Nom

kitten-@-set-colors - Définir les couleurs du terminal

Utilisation

kitten @ set-colors COULEUR_OU_FICHIER ...

Description

Définit les couleurs du terminal pour les fenêtres/onglets spécifiés (par défaut la fenêtre active). Vous pouvez soit spécifier le chemin vers un fichier de configuration (dans le même format que kitty.conf) pour lire les couleurs, soit spécifier des couleurs individuelles, par exemple::


kitten @ set-colors foreground=red background=white

Options

--all, -a [=no]
Par défaut, les couleurs ne sont modifiées que pour la fenêtre actuellement active. Cette option fera en sorte que les couleurs soient modifiées dans toutes les fenêtres.
--configured, -c [=no]
Modifie aussi les couleurs configurées (c'est-à-dire les couleurs que kitty utilisera pour les nouvelles fenêtres ou après une réinitialisation).
--reset [=no]
Restaure toutes les couleurs aux valeurs qu'elles avaient au démarrage de kitty. Notez que si vous spécifiez cette option, tous les arguments de couleur sont ignorés et --configured et --all sont implicites.
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id correspondent à partir du plus grand numéro d'id vers le bas, en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant à zéro et en comptant dans le sens horaire (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'id de fenêtre de la fenêtre actuelle est disponible en tant que la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, zéro étant la fenêtre actuellement active, un étant la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active soit la dernière session active quand aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier soit le nom de la variable d'environnement soit un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var fait correspondre les variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme avec le champ env.

Le champ state fait correspondre l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est faite correspondre. La valeur focused_os_window fait correspondre toutes les fenêtres dans la fenêtre OS actuellement focalisée. La valeur self fait correspondre la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent fait correspondre la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est un overlay.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste de fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l' expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du plus grand numéro d'id vers le bas, en particulier, -1 est l'onglet/fenêtre créé le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet pour cette fenêtre est utilisé.

Vous pouvez aussi utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le n-ième onglet dans la fenêtre OS actuellement active. Le numéro recent fait correspondre les onglets récemment actifs dans la fenêtre OS actuellement active, zéro étant l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session fait correspondre les onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active soit la dernière session active quand aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier soit le nom de la variable d'environnement soit un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont faits correspondre. De même, var fait correspondre les onglets contenant n'importe quelle fenêtre avec la variable utilisateur spécifiée.

Le champ state fait correspondre l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre OS parent. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont délivrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est fait correspondre. La valeur focused_os_window fait correspondre tous les onglets dans la fenêtre OS actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste d'onglets.

--help, -h [=no]
Affiche l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance de kitty à contrôler. Correspond à l'adresse donnée à l'instance de kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle pour ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la connexion à kitty. Cela fera que kitty demandera à l'utilisateur l'autorisation d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est pré-configuré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces en fin de ligne sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie la présence du fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password> [=if-availabl
e]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation ou non du mot de passe fourni. Si elle est définie à « always » et qu'aucun mot de passe n'est fourni, un mot de passe vide est utilisé.
