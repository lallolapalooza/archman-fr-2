DESCRIPTION L'appel

sys
tème

kexec_load() charge un nouveau noyau qui pourra être exécuté ultérieurement

par

reboot(2). L'argument flags est un masque de bits qui contrôle le fonctionnement de l'appel. Les valeurs suivantes peuvent être

spécifiées dans

flags : KEXEC_ON_CRASH (depuis Linux 2.6.13) Exécuter automatiquement le nouveau noyau en cas de crash système. Ce « crash kernel » (noyau de secours) est chargé dans une zone de mémoire réservée qui est déterminée

au démarrage à l'aide du
paramètre de ligne de commande du noyau crashkernel. L'emplacement de cette mémoire réservée est exporté vers l'espace utilisateur
via le
fichier /proc/iomem, dans une entrée étiquetée « Crash kernel ». Une application en espace utilisateur peut analyser ce fichier et préparer une liste de segments (voir ci-dessous) qui spécifient cette mémoire réservée comme destination. Si ce drapeau est spécifié, le noyau vérifie que les segments cibles spécifiés dans segments se trouvent dans la région réservée. KEXEC_PRESERVE_CONTEXT (depuis Linux 2.6.27) Préserver l'état matériel et logiciel du système avant d'exécuter le nouveau noyau. Cela peut être utilisé pour la mise en veille du système. Ce drapeau n'est disponible que si le noyau a été
configuré avec
CONFIG_KEXEC_JUMP, et n'est efficace que
si
nr_segments est supérieur à 0. Les bits de poids fort (correspondant au masque 0xffff0000) de flags contiennent l'architecture du noyau à
exécuter. Spécifiez (OU
logique) la constante

KEXEC_ARCH_DEFAULT pour utiliser l'architecture actuelle, ou l'une des constantes d'architecture suivantes KEXEC_ARCH_386, KEXEC_ARCH_68K, KEXEC_ARCH_X86_64, KEXEC_ARCH_PPC, KEXEC_ARCH_PPC64, KEXEC_ARCH_IA_64, KEXEC_ARCH_ARM, KEXEC_ARCH_S390, KEXEC_ARCH_SH, KEXEC_ARCH_MIPS, et KEXEC_ARCH_MIPS_LE. L'architecture doit être exécutable sur le CPU du système. L'argument entry est l'adresse d'entrée physique dans l'image du noyau.

L'argument

nr_segments est le nombre de segments pointés par le pointeur segments ; le noyau impose une limite (arbitraire) de 16 segments. L'argument segments est un tableau de structures kexec_segment qui définissent la disposition du noyau : struct kexec_segment { void *buf; /* Buffer en espace utilisateur */ size_t bufsz; /* Taille du buffer en espace utilisateur */ void *mem; /* Adresse physique du noyau */ size_t memsz; /* Longueur de l'adresse physique */ }; L'image du noyau définie

par 


segments est copiée depuis
le

processus appelant vers le noyau, soit en mémoire normale, soit en mémoire réservée (si KEXEC_ON_CRASH est défini). Le noyau effectue d'abord diverses vérifications de cohérence sur les informations passées dans segments. Si ces vérifications réussissent, le noyau copie les données des segments vers la mémoire du noyau. Chaque segment spécifié dans segments est copié comme suit

:
•
buf et bufsz identifient une région mémoire dans l'espace d'adressage virtuel de l'appelant qui est la source de la copie. La valeur dans bufsz ne peut pas dépasser la valeur dans le champ memsz
. •
mem
et
memsz spécifient une plage d'adresses physiques qui est la cible de la copie. Les valeurs spécifiées dans les deux champs doivent être des multiples de la taille de page du système. •
bufsz octets sont
copiés du buffer source vers le buffer cible du noyau. Si
bufsz est inférieur à memsz, les octets excédentaires dans le buffer du noyau sont mis à zéro. Dans le cas d'un kexec norma
l (c'est-à-dire
si le drapeau

KEXEC_ON_CRASH n'est pas défini), les données des segments sont chargées dans n'importe quelle mémoire disponible et sont déplacées vers la destination finale au moment du redémarrage kexec (par exemple, lorsque la commande kexec(8) est exécutée avec l'option -e)

.

Dans le cas du kexec sur panic (c'est-à-dire si le drapeau KEXEC_ON_CRASH est défini), les données des segments sont chargées en mémoire réservée au moment de l'appel, et, après un crash, le mécanisme kexec passe simplement le contrôle à ce

noyau.

L'appel système kexec_load() n'est disponible que si le noyau a été configuré avec CONFIG_KEXEC

.

kexec_file_load(

L'appel système kexec_file_load() est similaire à kexec_load(), mais il prend un ensemble d'arguments différent. Il lit le noyau à charger depuis le fichier référencé par le descripteur de fichier kernel_fd, et l'initrd (disque RAM initial) à charger depuis le fichier référencé par le descripteur de fichier initrd_fd. L'argument cmdline est un pointeur vers un buffer contenant la ligne de commande pour le nouveau noyau. L'argument cmdline_len spécifie la taille du buffer. Le dernier octet du buffer doit être un octet nul ('\0')

.
