Nom

kitten-@-set-spacing - Définir les espacements et les marges des fenêtres

Utilisation

kitten @ set-spacing MARGIN_OR_PADDING ...

Description

Définit les espacements et les marges pour les fenêtres spécifiées (par défaut, la fenêtre active). Par exemple : margin=20 ou padding-left=10 ou margin-h=30. La forme abrégée définit toutes les valeurs, les variantes *-h et *-v définissent les valeurs horizontales et verticales. La valeur spéciale default réinitialise à l'utilisation de la valeur par défaut. Si vous spécifiez un onglet plutôt qu'une fenêtre, toutes les fenêtres de cet onglet sont affectées.

Options

--all, -a [=no]
Par défaut, les paramètres ne sont modifiés que pour la fenêtre active. Cette option permet de modifier les espacements et les marges dans toutes les fenêtres.
--configured, -c [=no]
Modifie également les espacements et marges configurés (c'est-à-dire les paramètres que kitty utilisera pour les nouvelles fenêtres).
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent à partir du nombre d'id le plus élevé, en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui rapporté par la commande kitten @ ls).

L'identifiant de la fenêtre de la fenêtre actuelle est disponible via la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actif, zéro étant la fenêtre actuellement active, un la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres créées dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session et . pour correspondre à la session actuellement active et ~ pour correspondre soit à la session active, soit à la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme pour le champ env.

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements du clavier sont livrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est prise en compte. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre OS actuellement focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre située sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste de fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du nombre d'id/window_id le plus élevé, en particulier, -1 est l'onglet/la fenêtre créée le plus récemment.

Lors de l'utilisation de title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour correspondre à l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour correspondre au nième onglet dans la fenêtre OS actuellement active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre OS actuellement active, zéro étant l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets créés dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session et . pour correspondre à la session actuellement active et ~ pour correspondre soit à la session active, soit à la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var met en correspondance les onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre OS parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets de la fenêtre OS actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste d'onglets.

--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas trouvée non plus, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela demandera à kitty la permission à l'utilisateur d'effectuer l'action spécifiée, à moins que le mot de passe n'ait été accepté auparavant ou qu'il ne soit préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'exécution dans tous les cas.
