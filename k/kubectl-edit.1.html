NOM

kubectl edit - Modifier une ressource sur le serveur

SYNTAXE

kubectl edit [OPTIONS]

DESCRIPTION

Modifie une ressource depuis l'éditeur par défaut.

La commande edit permet de modifier directement toute ressource API que vous pouvez récupérer via les outils en ligne de commande. Elle ouvrira l'éditeur défini par vos variables d'environnement KUBE_EDITOR, ou EDITOR, ou se rabattra sur 'vi' pour Linux ou 'notepad' pour Windows. Lors de la tentative d'ouverture de l'éditeur, elle tentera d'abord d'utiliser le shell défini dans la variable d'environnement 'SHELL'. Si elle n'est pas définie, le shell par défaut sera utilisé, qui est '/bin/bash' pour Linux ou 'cmd' pour Windows.

Vous pouvez modifier plusieurs objets, bien que les modifications soient appliquées une par une. La commande accepte des noms de fichiers ainsi que des arguments en ligne de commande, bien que les fichiers que vous pointez doivent être des versions précédemment sauvegardées des ressources.

La modification est effectuée avec la version API utilisée pour récupérer la ressource. Pour modifier en utilisant une version API spécifique, qualifiez entièrement la ressource, la version et le groupe.

Le format par défaut est YAML. Pour modifier en JSON, spécifiez "-o json".

L'option --windows-line-endings peut être utilisée pour forcer les fins de ligne Windows, sinon la valeur par défaut de votre système d'exploitation sera utilisée.

En cas d'erreur lors de la mise à jour, un fichier temporaire sera créé sur le disque contenant vos modifications non appliquées. L'erreur la plus courante lors de la mise à jour d'une ressource est qu'un autre éditeur modifie la ressource sur le serveur. Lorsque cela se produit, vous devrez appliquer vos modifications à la version la plus récente de la ressource, ou mettre à jour votre copie temporaire sauvegardée pour inclure la dernière version de la ressource.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--field-manager="kubectl-edit" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers à utiliser pour modifier la ressource

-k, --kustomize="" Traiter le répertoire kustomization. Cette option ne peut pas être utilisée avec -f ou -R.

-o, --output="" Format de sortie. Un parmi: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--output-patch=false Afficher le patch si la ressource est modifiée.

--record=false Enregistrer la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, par défaut à la mise à jour de la valeur de l'annotation existante seulement si une existe déjà.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename récursivement. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--save-config=false Si vrai, la configuration de l'objet actuel sera sauvegardée dans son annotation. Sinon, l'annotation restera inchangée. Cette option est utile lorsque vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserver les managedFields lors de l'affichage des objets au format JSON ou YAML.

--subresource="" Si spécifié, edit opérera sur la sous-ressource de l'objet demandé.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un des: strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si invalide. Elle effectuera une validation côté serveur si ServerSideFieldValidation est activé sur l'api-server, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

--windows-line-endings=false Par défaut, utilise la fin de ligne native à votre plateforme.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, cette option peut être répétée pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la porte de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie aucune temporisation des requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Modifier le service nommé 'registry'
  kubectl edit svc/registry
  # Utiliser un éditeur alternatif
  KUBE_EDITOR="nano" kubectl edit svc/registry
  # Modifier le job 'myjob' en JSON en utilisant le format API v1
  kubectl edit job.v1.batch/myjob -o json
  # Modifier le déploiement 'mydeployment' en YAML et sauvegarder la configuration modifiée dans son annotation
  kubectl edit deployment/mydeployment -o yaml --save-config
  # Modifier la sous-ressource 'status' pour le déploiement 'mydeployment'
  kubectl edit deployment mydeployment --subresource='status'
