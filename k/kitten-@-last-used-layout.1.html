Nom

kitten-@-last-used-layout - Changer pour la dernière disposition utilisée

Utilisation

kitten @ last-used-layout

Description

Changer pour la dernière disposition de fenêtre utilisée dans les onglets spécifiés (ou l'onglet actif si aucun n'est spécifié).

Options

--all, -a [=non]
Changer la disposition dans tous les onglets.
--no-response [=non]
Ne pas attendre de réponse de kitty. Cela signifie que même si aucun onglet correspondant n'est trouvé, la commande se terminera avec un code de succès.
--match, -m
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des éléments suivants : id, index, titre, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du plus grand numéro d'id, en particulier, -1 est l'onglet/la fenêtre le(la) plus récemment créé(e).

Lors de l'utilisation de title ou id, une correspondance d'onglet est d'abord recherchée, et si aucune n'est trouvée, une correspondance de fenêtre est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre de l'OS active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre de l'OS active, zéro étant l'onglet actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session fait correspondre les onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session active actuelle et ~ pour faire correspondre soit la session active actuelle, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var fait correspondre les onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state fait correspondre l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre parente de l'OS. Il n'y a qu'un seul onglet focusé et c'est l'onglet auquel les événements clavier sont délivrés. Si aucun onglet n'est focusé, le dernier onglet focusé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets dans la fenêtre de l'OS actuellement focusée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--help, -h [=non]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse de l'instance kitty à contrôler. Correspond à l'adresse fournie à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la communication avec kitty. Cela demandera à kitty la permission de l'utilisateur pour effectuer l'action spécifiée, à moins que le mot de passe n'ait été accepté auparavant ou ne soit préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs en fin de ligne sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, il vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, il vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=si-disponible]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation systématique ou jamais du mot de passe fourni. Si défini sur always et aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
