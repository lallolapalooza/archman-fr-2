Nom

kitten-@-set-window-title - Définir le titre de la fenêtre

Utilisation

kitten @ set-window-title [TITRE ...]

Description

Définit le titre des fenêtres spécifiées. Si vous utilisez l'option --match, le titre sera défini pour toutes les fenêtres correspondantes. Par défaut, seule la fenêtre dans laquelle la commande est exécutée est affectée. Si vous ne spécifiez pas de titre, le dernier titre défini par le processus enfant s'exécutant dans la fenêtre sera utilisé.

Options

--temporary [=no]
Par défaut, le titre sera modifié de manière permanente et les programmes exécutés dans la fenêtre ne pourront plus le modifier. Si vous souhaitez permettre à d'autres programmes de le modifier par la suite, utilisez cette option.
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id correspondent à partir du nombre d'id le plus élevé, en particulier, -1 est la fenêtre la plus récemment créée.

Le champ num fait référence à la position de la fenêtre dans l'onglet courant, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'identifiant de fenêtre de la fenêtre courante est disponible via la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, zéro étant la fenêtre actuellement active, un étant la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var fait correspondre les variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme avec le champ env.

Le champ state fait correspondre l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre active (focused) et c'est la fenêtre à laquelle les événements du clavier sont livrés. Si aucune fenêtre n'est active (focused), la dernière fenêtre active (focused) est mise en correspondance. La valeur focused_os_window met en correspondance toutes les fenêtres dans la fenêtre du système d'exploitation actuellement active (focused). La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre située sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si celle-ci n'est pas trouvée non plus, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela amènera kitty à demander à l'utilisateur la permission d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou s'il est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password as always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire à partir du descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation ou non du mot de passe fourni. S'il est défini sur always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
