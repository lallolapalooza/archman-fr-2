DESCRIPTION

Ce programme est utilisé pour contrôler le mécanisme de gestion des clés de diverses manières à l'aide d'une variété de sous-commandes.

IDENTIFIANTS DE CLÉ

Les identifiants de clé passés à ou renvoyés par keyctl sont, en général, des entiers positifs. Il existe cependant certaines valeurs spéciales avec des significations spéciales qui peuvent être passées comme arguments :

Pas de clé : 0
Chaîne de clés du thread : @t ou -1
Chaque thread peut avoir sa propre chaîne de clés. Celle-ci est recherchée en premier, avant toutes les autres. La chaîne de clés du thread est remplacée par (v)fork, exec et clone.
Chaîne de clés du processus : @p ou -2
Chaque processus (groupe de threads) peut avoir sa propre chaîne de clés. Celle-ci est partagée entre tous les membres d'un groupe et sera recherchée après la chaîne de clés du thread. La chaîne de clés du processus est remplacée par (v)fork et exec.
Chaîne de clés de session : @s ou -3
Chaque processus souscrit à une chaîne de clés de session qui est héritée par (v)fork, exec et clone. Celle-ci est recherchée après la chaîne de clés du processus. Les chaînes de clés de session peuvent être nommées et une chaîne de clés existante peut être jointe à la place de la chaîne de clés de session actuelle d'un processus.
Chaîne de clés spécifique à l'utilisateur : @u ou -4
Cette chaîne de clés est partagée entre tous les processus appartenant à un utilisateur particulier. Elle n'est pas recherchée directement, mais est normalement liée depuis la chaîne de clés de session.
Chaîne de clés de session par défaut de l'utilisateur : @us ou -5
C'est la chaîne de clés de session par défaut pour un utilisateur particulier. Les processus de connexion qui basculent vers un utilisateur particulier se lieront à cette session jusqu'à ce qu'une autre session soit définie.
Chaîne de clés spécifique au groupe : @g ou -6
C'est un espace réservé pour une chaîne de clés spécifique au groupe, mais elle n'est pas encore implémentée dans le noyau.
Clé d'autorisation request_key présumée : @a ou -7
Ceci sélectionne la clé d'autorisation fournie à l'aide de la fonction d'aide request_key() pour lui permettre d'accéder aux chaînes de clés de l'appelant et d'instancier la clé cible.
Chaîne de clés par nom : %:<nom>
Une chaîne de clés nommée. Elle sera recherchée dans les chaînes de clés du processus et dans /proc/keys.
Clé par nom : %<type>:<nom>
Une clé nommée du type donné. Elle sera recherchée dans les chaînes de clés du processus et dans /proc/keys.

SYNTAXE DES COMMANDES

Toute contraction non ambiguë d'un nom de commande peut être utilisée à la place du nom de commande complet. Cette fonctionnalité ne doit pas être utilisée dans les scripts car de nouvelles commandes pourraient être ajoutées à l'avenir, provoquant ainsi une ambiguïté.

Afficher le numéro de version du paquet

keyctl --version

Cette commande imprime le numéro de version du paquet et la date de compilation, puis se termine :

$ keyctl --version
keyctl from keyutils-1.5.3 (Built 2011-08-24)

Interroger les capacités du sous-système

keyctl supports
keyctl supports --raw
keyctl supports <cap>

Cette commande peut lister les capacités disponibles :

$ keyctl supports
have_capabilities=0
have_persistent_keyrings=1
have_dh_compute=1
have_public_key=1

produire une sortie brute hexadécimale de la liste des capacités :

$ keyctl supports --raw
ff0f

ou interroger une capacité spécifique :

$ keyctl supports pkey
echo $?
0

qui se termine avec 0 si la capacité est supportée, 1 si elle ne l'est pas et 3 si le nom n'est pas reconnu. Les capacités supportées sont :

capabilities
Le noyau supporte les requêtes de capacités. Sinon, les autres capacités seront interrogées au mieux par libkeyutils.
persistent_keyrings
Le noyau supporte les chaînes de clés persistantes.
dh_compute
Le noyau supporte les opérations de calcul Diffie-Hellman.
public

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

_clé
Le noyau prend en charge les opérations sur les clés publiques.
big_key_type
Le noyau prend en charge le type de clé big_key.
key_invalidate
Le noyau prend en charge l'opération de clé invalidate.
restrict_keyring
Le noyau prend en charge l'opération restrict_keyring.
move_key
Le noyau prend en charge l'opération de clé move.
ns_keyring_name
Les noms de porte-clés sont séparés en fonction de l'espace de noms d'utilisateur dans lequel les porte-clés sont créés.
ns_key_tag
Les clés peuvent être étiquetées avec des étiquettes d'espace de noms, ce qui permet à des clés de même type et description, mais d'espaces de noms différents, de coexister dans un même porte-clés. L'étiquetage est effectué automatiquement en fonction du type de clé.

Afficher l'ID réel d'une clé ou d'un porte-clés

keyctl id [<clé>]

Cette commande recherche l'ID réel d'une clé ou d'un porte-clés à partir de l'identifiant fourni, qui est généralement un ID symbolique tel que « @s » indiquant le porte-clés de session, mais qui peut aussi être un ID numérique ou une notation « %type:desc ». Si un porte-clés spécial est spécifié et n'a pas encore été créé, une erreur sera renvoyée plutôt que de provoquer la création de ce porte-clés.

Afficher les porte-clés du processus

keyctl show [-x] [<porte-clés>]

Par défaut, cette commande affiche récursivement les porte-clés auxquels un processus est abonné ainsi que les clés et porte-clés qu'ils contiennent. Si un porte-clés est spécifié, alors c'est ce porte-clés qui sera affiché. Si -x est spécifié, les ID des porte-clés seront affichés en hexadécimal au lieu de décimal.

Ajouter une clé à un porte-clés

keyctl add [-x] <type> <desc> <données> <porte-clés>
keyctl padd [-x] <type> <desc> <porte-clés>

Cette commande crée une clé du type et de la description spécifiés ; l'instancie avec les données fournies et l'attache au porte-clés spécifié. Elle affiche ensuite l'ID de la nouvelle clé sur la sortie standard :

$ keyctl add user mykey stuff @u
26

La variante padd de la commande lit les données depuis l'entrée standard au lieu de les prendre depuis la ligne de commande :


$ echo -n stuff | keyctl padd user mykey @u 26

Si -x est spécifié, les données sont décodées en hexadécimal, les espaces étant ignorés.

Demander une clé

keyctl request <type> <desc> [<porte-clés-destination>]
keyctl request2 <type> <desc> <info> [<porte-clés-destination>]
keyctl prequest2 <type> <desc> [<porte-clés-destination>]

Ces trois commandes demandent la recherche d'une clé du type et de la description donnés. Les porte-clés du processus seront recherchés, et si une correspondance est trouvée, l'ID de la clé correspondante sera affiché sur la sortie standard ; et si un porte-clés de destination est spécifié, la clé sera également ajoutée à ce porte-clés.

S'il n'y a pas de clé, la première commande renverra simplement l'erreur ENOKEY et échouera. Les deuxième et troisième commandes créeront une clé partielle avec le type et la description, et appelleront /sbin/request-key avec cette clé et les informations supplémentaires fournies. Cela tentera alors d'instancier la clé d'une manière ou d'une autre, de sorte qu'une clé valide soit obtenue.

La troisième commande est semblable à la deuxième, sauf que les informations d'appel sont lues depuis l'entrée standard au lieu d'être passées sur la ligne de commande.

Si une clé valide est obtenue, l'ID sera affiché et la clé sera attachée comme si la recherche initiale avait réussi.

Si aucune clé valide n'a été obtenue, une clé négative temporaire sera attachée au porte-clés de destination si celui-ci est spécifié, et l'erreur « Requested key not available » sera renvoyée.

$ keyctl request2 user debug:hello wibble
23
$ echo -n wibble | keyctl prequest2 user debug:hello
23
$ keyctl request user debug:hello
23

Mettre à jour une clé

keyctl update [-x] <clé> <données>
keyctl pupdate [-x] <clé>

Cette commande remplace les données attachées à une clé par un nouvel ensemble de données. Si le type de clé ne prend pas en charge la mise à jour, l'erreur « Operation not supported » sera renvoyée.

$ keyctl update 23 zebra

La variante pupdate de la commande lit les données depuis l'entrée standard au lieu de les prendre depuis la ligne de commande :

$ echo -n zebra | keyctl pupdate 23
$ echo 616263313233 | keyctl pupdate -x 23

Si -x est spécifié, les données sont décodées en hexadécimal, les espaces étant ignorés.

Créer un porte-clés

keyctl newring <nom> <porte-clés>

Cette commande crée un nouveau porte-clés du nom spécifié et l'attache au porte-clés spécifié. L'ID du nouveau porte-clés sera affiché sur la sortie standard en cas de succès.

$ keyctl newring squelch @us
27

Révoquer une clé

keyctl revoke <clé>

Cette commande marque une clé comme étant révoquée. Toute opération ultérieure sur cette clé (à part le fait de la détacher) renverra l'erreur « Key has been revoked ».

$ keyctl revoke 26
$ keyctl describe 26
keyctl_describe: Key has been revoked

Vider un porte-clés

keyctl clear <porte-clés>

Cette commande détache toutes les clés attachées au porte-clés spécifié. L'erreur « Not a directory » sera renvoyée si la clé spécifiée n'est pas un porte-clés.

$ keyctl clear 27

Lier une clé à un porte-clés

keyctl link <clé> <porte-clés>

Cette commande crée un lien de la clé vers le porte-clés s'il y a suffisamment de capacité pour le faire. L'erreur « Not a directory » sera renvoyée si la destination n'est pas un porte-clés. L'erreur « Permission denied » sera renvoyée si la clé n'a pas la permission de liaison ou si le porte-clés n'a pas la permission d'écriture. L'erreur « File table overflow » sera renvoyée si le porte-clés est plein. L'erreur « Resource deadlock avoided » sera renvoyée si une tentative a été faite d'introduire un lien récursif.

$ keyctl link 23 27
$ keyctl link 27 27
keyctl_link: Resource deadlock avoided

Détacher une clé d'un porte-clés ou de l'arbre du porte-clés de session

keyctl unlink <clé> [<porte-clés>]

Si le porte-clés est spécifié, cette commande supprime un lien vers la clé depuis le porte-clés. L'erreur « Not a directory » sera renvoyée si la destination n'est pas un porte-clés. L'erreur « Permission denied » sera renvoyée si le porte-clés n'a pas la permission d'écriture. L'erreur « No such file or directory » sera renvoyée si la clé n'est pas liée par le porte-clés.

Si le porte-clés n'est pas spécifié, cette commande effectue une recherche en profondeur de l'arbre du porte-clés de session et supprime tous les liens vers la clé nominée qu'elle trouve (et qu'elle a le droit de supprimer). Elle affiche le nombre de détachements réussis avant de se terminer.

$ keyctl unlink 23 27

Déplacer une clé entre porte-clés.

keyctl move [-f] <clé> <porte-clés-source> <porte-clés-destination>

Cette commande déplace une clé d'un porte-clés à un autre, combinant de manière atomique « keyctl unlink <clé> <porte-clés-source> » et « keyctl link <clé> <porte-clés-destination> ».

Si l'option « -f » est présente, toute clé correspondante sera déplacée de « porte-clés-destination » ; si elle n'est pas présente, la commande échouera avec le message d'erreur « File exists » si la clé déplacerait autrement une autre clé de « porte-clés-destination ».

$ keyctl move 23 27 29
$ keyctl move -f 71 @u @s

Rechercher dans un porte-clés

keyctl search <porte-clés> <type> <desc> [<porte-clés-destination>]

Cette commande recherche de manière non récursive dans un porte-clés une clé d'un type et d'une description particuliers. Si elle est trouvée, l'ID de la clé sera affiché sur la sortie standard et la clé sera attachée au porte-clés de destination s'il est présent. L'erreur « Requested key not available » sera renvoyée si la clé n'est pas trouvée.

$ keyctl search @us user debug:hello
23
$ keyctl search @us user debug:bye
keyctl_search: Requested key not available

Restreindre un porte-clés

keyctl restrict_keyring <porte-clés> [<type> [<restriction>]]

Cette commande limite la liaison des clés au porte-clés donné en utilisant un schéma de restriction fourni. Le schéma est associé à un type de clé donné, avec des détails supplémentaires fournis dans la chaîne d'option de restriction. Les options contiennent généralement un nom de restriction éventuellement suivi d'identifiants de clés ou d'autres données pertinentes pour la restriction. Si aucun schéma de restriction n'est fourni, le porte-clés rejettera tous les liens.

$ keyctl restrict_keyring $1 asymmetric builtin_trusted

Lire une clé

keyctl read <clé>
keyctl pipe <clé>
keyctl print <clé>

Ces commandes lisent la charge utile d'une clé. "read" l'affiche sur stdout sous forme de dump hexadécimal, "pipe" écrit les données brutes sur stdout et "print" les écrit directement sur stdout si elles sont entièrement imprimables, ou sous forme de dump hexadécimal précédé de ":hex:" sinon.

Si le type de clé ne prend pas en charge la lecture de la charge utile, l'erreur « Opération non prise en charge » sera retournée.

$ keyctl read 26
1 byte de données dans la clé :
62
$ keyctl print 26
b
$ keyctl pipe 26
$

Lister un trousseau

keyctl list <trousseau>
keyctl rlist <trousseau>

Ces commandes listent le contenu d'une clé sous forme de trousseau. "list" affiche le contenu de manière formatée et "rlist" produit simplement une liste d'ID de clés séparés par des espaces.

Aucune vérification n'est effectuée pour confirmer que le trousseau spécifié est bien un trousseau.

$ keyctl list @us
2 clés dans le trousseau :
       22: vrwsl----------  4043    -1 keyring: _uid.4043
       23: vrwsl----------  4043  4043 user: debug:hello
$ keyctl rlist @us
22 23

Décrire une clé

keyctl describe <trousseau>
keyctl rdescribe <trousseau> [séparateur]

Ces commandes récupèrent la description d'un trousseau. "describe" affiche la description de manière formatée de la même façon que la commande "list" ; "rdescribe" affiche les données brutes retournées par le noyau.

$ keyctl describe @us
       -5: vrwsl----------  4043    -1 keyring: _uid_ses.4043
$ keyctl rdescribe @us
keyring;4043;-1;3f1f0000;_uid_ses.4043

La chaîne brute est « <type>;<uid>;<gid>;<perms>;<description> », où uid et gid sont les ID utilisateur et groupe au format décimal, perms est le masque de permissions en hexadécimal, type et description sont les chaînes du nom de type et de la description (aucune des deux ne contiendra de points-virgules).

Modifier les contrôles d'accès d'une clé

keyctl chown <clé> <uid>
keyctl chgrp <clé> <gid>

Ces deux commandes modifient le UID et le GID associés à l'évaluation du masque de permissions d'une clé. Le UID détermine également le quota dont la clé est déduite.

La commande chown n'est actuellement pas prise en charge ; la tenter vaudra au mieux l'erreur « Opération non prise en charge ».

Pour les utilisateurs non superutilisateur, le GID ne peut être défini que sur le GID du processus ou sur un GID figurant dans la liste des groupes du processus. Le superutilisateur peut définir n'importe quel GID de son choix.

$ sudo keyctl chown 27 0
keyctl_chown: Opération non prise en charge
$ sudo keyctl chgrp 27 0

Définir le masque de permissions d'une clé

keyctl setperm <clé> <masque>

Cette commande modifie le masque de contrôle des permissions d'une clé. Le masque peut être spécifié comme un nombre hexadécimal s'il commence par « 0x », un nombre octal s'il commence par « 0 » ou un nombre décimal sinon.

Les nombres hexadécimaux sont une combinaison de :

Possesseur  UID       GID       Autres     Permission accordée
========  ========  ========  ========  ==================
01000000  00010000  00000100  00000001  Voir
02000000  00020000  00000200  00000002  Lire
04000000  00040000  00000400  00000004  Écrire
08000000  00080000  00000800  00000008  Rechercher
10000000  00100000  00001000  00000010  Lier
20000000  00200000  00002000  00000020  Définir un attribut
3f000000  003f0000  00003f00  0000003f  Tout

Voir permet de visualiser le type, la description et les autres paramètres d'une clé.

Lire permet de lire la charge utile (ou la liste du trousseau) si c'est pris en charge par le type.

Écrire permet de modifier ou de mettre à jour la charge utile (ou la liste du trousseau).

Rechercher sur une clé permet de la trouver lorsqu'un trousseau auquel elle est liée est recherché.

Lier permet de lier une clé à un trousseau.

Définir un attribut permet de modifier le propriétaire, l'appartenance au groupe, le masque de permissions et le délai d'expiration d'une clé.

$ keyctl setperm 27 0x1f1f1f00

Démarrer une nouvelle session avec des trousseaux neufs

keyctl session
keyctl session - [<prog> <arg1> <arg2> ...]
keyctl session <nom> [<prog> <arg1> <arg2> ...]

Ces commandes rejoignent ou créent un nouveau trousseau puis lancent un shell ou un autre programme avec ce trousseau comme clé de session.

La variante sans arguments crée simplement un trousseau de session anonyme et l'attache comme trousseau de session ; elle exécute ensuite $SHELL.

La variante avec un tiret à la place d'un nom crée un trousseau de session anonyme et l'attache comme trousseau de session ; elle exécute ensuite la commande fournie, ou $SHELL si aucune n'est fournie.

La variante avec un nom fourni crée ou rejoint le trousseau nommé et l'attache comme trousseau de session ; elle exécute ensuite la commande fournie, ou $SHELL si aucune n'est fournie.

$ keyctl rdescribe @s
keyring;4043;-1;3f1f0000;_uid_ses.4043
$ keyctl session
Trousseau de session rejoint : 28
$ keyctl rdescribe @s
keyring;4043;4043;3f1f0000;_ses.24082
$ keyctl session -
Trousseau de session rejoint : 29
$ keyctl rdescribe @s
keyring;4043;4043;3f1f0000;_ses.24139
$ keyctl session - keyctl rdescribe @s
Trousseau de session rejoint : 30
keyring;4043;4043;3f1f0000;_ses.24185
$ keyctl session fish
Trousseau de session rejoint : 34
$ keyctl rdescribe @s
keyring;4043;4043;3f1f0000;fish
$ keyctl session fish keyctl rdesc @s
Trousseau de session rejoint : 35
keyring;4043;4043;3f1f0000;fish

Instancier une clé

keyctl instantiate [-x] <clé> <données> <trousseau>
keyctl pinstantiate [-x] <clé> <trousseau>
keyctl negate <clé> <délai> <trousseau>
keyctl reject <clé> <délai> <erreur> <trousseau>

Ces commandes sont utilisées pour attacher des données à une clé partiellement configurée (telle que créée par le noyau et passée à /sbin/request-key). « instantiate » marque une clé comme valide et attache les données comme charge utile. « negate » et « reject » marquent une clé comme invalide et définissent un délai d'expiration pour qu'elle disparaisse au bout d'un moment. Cela empêche de nombreuses requêtes rapides successives de ralentir excessivement le système lorsqu'elles échouent toutes, car toutes les requêtes suivantes échoueront alors avec l'erreur « Clé demandée introuvable » (si négée) ou l'erreur spécifiée (si rejetée) jusqu'à l'expiration de la clé négative.

L'argument d'erreur de reject peut être soit un numéro d'erreur UNIX, soit l'un de «rejected», «expired» ou «revoked».

La clé nouvellement instanciée sera attachée au trousseau spécifié.

Ces commandes ne peuvent être exécutées que depuis le programme lancé par request-key - une clé d'autorisation spéciale est créée par le noyau et attachée au trousseau de session de request-key. Cette clé spéciale est révoquée une fois que la clé à laquelle elle fait référence a été instanciée d'une manière ou d'une autre.

$ keyctl instantiate $1 "Debug $3" $4
$ keyctl negate $1 30 $4
$ keyctl reject $1 30 64 $4

La pinstantiate de la commande lit les données depuis stdin plutôt que de les prendre depuis la ligne de commande :

$ echo -n "Debug $3" | keyctl pinstantiate $1 $4

Si -x est spécifié, les données sont décodées en hexadécimal avec les espaces ignorés :

$ echo 01 02 03 04 | keyctl pinstantiate -x $1 $4

Définir le délai d'expiration d'une clé

keyctl timeout <clé> <délai>

Cette commande est utilisée pour définir le délai d'expiration d'une clé, ou effacer un délai existant si la valeur spécifiée est zéro. Le délai est donné en nombre de secondes dans le futur.

$ keyctl timeout $1 45

Récupérer le contexte de sécurité d'une clé

keyctl security <clé>

Cette commande est utilisée pour récupérer le contexte de sécurité LSM d'une clé. L'étiquette est affichée sur stdout.

$ keyctl security @s
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023

Donner au processus parent un nouveau trousseau de session

keyctl new_session [<nom>]

Cette commande est utilisée pour donner au processus appelant (typiquement un shell) un nouveau trousseau de session, en abandonnant son ancien trousseau de session. Si un nom est donné, le trousseau reçoit ce nom, sinon il recevra un nom de « _ses » et ne pourra pas être rejoint manuellement.

$  keyctl session foo
Trousseau de session rejoint : 723488146
$  keyctl show
Trousseau de session
       -3 --alswrv      0     0  keyring: foo
$  keyctl new_session
490511412
$  keyctl show
Trousseau de session
       -3 --alswrv      0     0  keyring: _ses

Notez que cela affecte le parent du processus qui appelle l'appel système, et ne peut donc affecter que les processus ayant des informations d'identification correspondantes. De plus, le changement ne prend effet que lorsque le processus parent effectue sa prochaine transition de l'espace noyau vers l'espace utilisateur - typiquement lorsque l'appel système wait() se termine.

Supprimer les clés inactives de l'arbre du trousseau de session

keyctl reap

Cette commande effectue une recherche en profondeur dans l'arbre du trousseau de session de l'appelant et tente de délier toute clé qu'elle trouve inaccessible en raison de l'expiration, de la révocation, du rejet ou de la négation. Elle ne tente pas de supprimer les clés actives qui sont simplement indisponibles en raison d'un manque de permission accordée.

Une clé désignée comme pouvant être supprimée ne sera supprimée d'un porte-clés que si l'appelant dispose de la permission d'écriture sur ce porte-clés, et seuls les porte-clés qui accordent la permission de recherche à l'appelant seront recherchés.

La commande imprime le nombre de clés supprimées avant de se terminer. Si l'indicateur -v est passé, les clés supprimées sont listées au fur et à mesure de leur suppression, ainsi que le succès ou l'échec de la suppression.

Supprimer les clés correspondantes de l'arbre des porte-clés de session

keyctl purge <type>
keyctl purge [-i] [-p] <type> <desc>
keyctl purge -s <type> <desc>

Ces commandes effectuent une recherche en profondeur pour trouver les clés correspondantes dans l'arbre des porte-clés de session de l'appelant et tentent de les supprimer. Le nombre de clés supprimées avec succès est imprimé à la fin.

Les porte-clés doivent accorder les permissions de lecture et de visualisation à l'appelant pour être recherchés, et les clés à supprimer doivent également accorder la permission de visualisation. Les clés ne peuvent être supprimées que des porte-clés qui accordent la permission d'écriture.

La première variante purge toutes les clés du type spécifié.

La deuxième variante purge toutes les clés du type spécifié qui correspondent également à la description donnée littéralement. L'indicateur -i permet une correspondance insensible à la casse et l'indicateur -p permet une correspondance de préfixe.

La troisième variante purge toutes les clés du type spécifié et correspondant à la description en utilisant le comparateur de type de clé du noyau pour faire correspondre la description. Cela permet au type de clé de correspondre à une clé avec diverses descriptions.

Obtenir le porte-clés persistant

keyctl get_persistent <keyring> [<uid>]

Cette commande obtient le porte-clés persistant pour l'UID actuel ou pour l'UID spécifié et l'attache au porte-clés désigné. L'ID du porte-clés persistant sera imprimé sur stdout.

Le noyau créera le porte-clés s'il n'existe pas et, chaque fois que cette commande sera appelée, réinitialisera le délai d'expiration du porte-clés à la valeur située dans :

/proc/sys/kernel/keys/persistent_keyring_expiry

(par défaut trois jours). Si le délai d'expiration est atteint, le porte-clés persistant sera supprimé et tout ce qu'il épingle pourra alors être collecté comme garbage.

Si un UID autre que les UID réels ou effectifs du processus est spécifié, une erreur sera retournée si le processus ne possède pas la capacité CAP_SETUID.

Calculer un secret partagé ou une clé publique Diffie-Hellman

keyctl dh_compute <private> <prime> <base>

Cette commande calcule soit un secret partagé Diffie-Hellman, soit la clé publique correspondant à la clé privée fournie en utilisant les charges utiles de trois clés. Le calcul est :

base ^ private (mod prime)

Les trois entrées doivent être des clés utilisateur avec permission de lecture. Si la clé de base fournie contient la valeur du générateur partagé, la clé publique sera calculée. Si la clé de base fournie contient la valeur de la clé publique distante, le secret partagé sera calculé.

Le résultat est imprimé sur stdout sous forme de dump hexadécimal.

$ keyctl dh_compute $1 $2 $3
8 octets de données dans le résultat :
00010203 04050607

Calculer un secret partagé Diffie-Hellman et dériver du matériel clé

keyctl dh_compute_kdf <private> <prime> <base> <output_length> <hash_type>

Cette commande calcule un secret partagé Diffie-Hellman et dérive du matériel clé à partir du secret partagé en utilisant une fonction de dérivation de clé (KDF). Le secret partagé est dérivé comme décrit ci-dessus et est entré dans le KDF en utilisant le type de hachage spécifié. Le type de hachage doit pointer vers un nom de hachage connu de l'API cryptographique du noyau.

L'opération dérive du matériel clé de la longueur spécifiée par l'appelant.

L'opération est conforme aux spécifications de SP800-56A.

Le résultat est imprimé sur stdout sous forme de dump hexadécimal.

Calculer un secret partagé Diffie-Hellman et appliquer un KDF avec une autre entrée

keyctl dh_compute_kdf_oi [-x] <private> <prime> <base> <output_length> <hash_type>

Cette commande est identique à la commande dh_compute_kdf pour générer un secret partagé Diffie-Hellman suivi d'une opération de dérivation de clé. Cette commande permet à l'appelant de fournir les autres données d'entrée (données OI) conformes à SP800-56A via stdin.

Si -x est donné, les données passées à stdin sont décodées en hexadécimal en ignorant les espaces blancs.

Effectuer des opérations de clé publique avec une clé asymétrique

keyctl pkey_query <key> <pass> [k=v]*
keyctl pkey_encrypt <key> <pass> <datafile> [k=v]* > <encfile>
keyctl pkey_decrypt <key> <pass> <encfile> [k=v]* > <datafile>
keyctl pkey_sign <key> <pass> <datafile> [k=v]* > <sigfile>
keyctl pkey_verify <key> <pass> <datafile> <sigfile> [k=v]*

Ces commandes interrogent une clé asymétrique, chiffrent des données avec celle-ci, déchiffrent les données chiffrées, génèrent une signature sur certaines données et vérifient cette signature. Pour le chiffrement, le déchiffrement et la signature, les données résultantes sont écrites sur stdout ; la vérification lit les fichiers de données et de signature et les compare.

[!] NOTEz que les données ont une capacité très limitée, avec pas plus de bits que la taille de la clé. Pour les signatures, l'appelant est censé digérer les données réelles et passer le résultat du digest dans le fichier de données. Le nom du digest doit être spécifié à la fin de la ligne de commande sous forme de "hash=<nom>".

L'ID key indique la clé à utiliser ; pass est un espace réservé pour une future fourniture de mot de passe et doit être "0" pour le moment ; datafile sont les données non chiffrées à chiffrer, signer ou dont la signature doit être vérifiée ; encfile est un fichier contenant des données chiffrées ; et sigfile est un fichier contenant une signature.

Une liste de paramètres sous forme "key[=val]" peut être incluse à la fin de la ligne de commande. Ceux-ci spécifient des choses comme l'algorithme de digest utilisé ("hash=<nom>") ou le format d'encodage ("enc=<type>").

k=`keyctl padd asymmetric "" @s <key.pkcs8.der`
keyctl pkey_query $k 0 enc=pkcs1 hash=sha256
keyctl pkey_encrypt $k 0 foo.hash enc=pkcs1 >foo.enc
keyctl pkey_decrypt $k 0 foo.enc enc=pkcs1 >foo.hash
keyctl pkey_sign $k 0 foo.hash enc=pkcs1 hash=sha256 >foo.sig
keyctl pkey_verify $k 0 foo.hash foo.sig enc=pkcs1 hash=sha256

Voir asymmetric-key(7) pour plus d'informations.

Notifications de changement

keyctl watch [-f<filtres>] <key>
keyctl watch_session [-f <filtres>] [-n <nom>] \
<notifylog> <gclog> <fd> <prog> [<arg1> <arg2> ...] keyctl watch_add <fd> <key>
keyctl watch_rm <fd> <key>

La commande watch surveille une clé unique, imprime des notifications sur stdout jusqu'à ce que la clé soit détruite. Des filtres peuvent être utilisés pour réduire les événements qui seront livrés. La chaîne filter est une série de lettres, chacune activant un sous-type d'événement particulier :

i - La clé a été instanciée
p - La clé a été mise à jour
l - Un lien a été ajouté à un porte-clés
n - Un lien a été retiré d'un porte-clés
c - Un porte-clés a été vidé
r - Une clé a été révoquée
v - Une clé a été invalidée
s - Les attributs d'une clé ont été modifiés

La sortie de la commande ressemble à ceci :

<keyid> <event> [<aux>]

Où keyid est le sujet principal de la notification, event est l'événement et aux est la clé secondaire s'il y en a une (comme un lien où la clé principale est le porte-clés et la clé secondaire est la clé qui y est liée). Par exemple :

255913279 link 340681059
255913279 clr

Une notification supplémentaire est générée lorsqu'une clé surveillée est récupérée par le garbage collector, par exemple :

255913279 gc

La commande watch_session crée un nouveau porte-clés de session, nommé name s'il est donné, le surveille pour les notifications et exécute le programme prog avec celui-ci. Le programme reçoit les arguments spécifiés.

Un second processus est déclenché pour surveiller les notifications. La sortie de celui-ci est dirigée vers les fichiers notifylog pour la plupart des notifications et gclog pour les notifications de suppression de clé (qui sont asynchrones et peuvent être différées).

Le périphérique watch_queue(7) est exporté au programme attaché au descripteur de fichier numéro fd. Ceci peut être passé par les deux autres commandes.

La commande watch_add ajoute une surveillance sur key à la watch_queue attachée à fd telle qu'exportée par watch_session et la commande watch_rm la supprime. Une watch_queue peut gérer plusieurs clés et même des sources qui ne sont pas des clés.

ERREURS

Il existe un certain nombre d'erreurs courantes renvoyées par ce programme :

"Pas un répertoire" - une clé n'était pas un porte-clés.

"Clé demandée non trouvée" - la clé recherchée n'est pas disponible.

"Clé révoquée" - une clé révoquée a été accédée.

"Clé expirée" - une clé expirée a été accédée.

"Permission refusée" - la permission a été refusée par une combinaison UID/GID/masque.
