NAME

knockd - serveur de *port-knock*

SYNOPSIS

knockd [options]

DESCRIPTION

knockd est un serveur de port-knock. Il écoute tout le trafic sur une interface Ethernet (ou PPP), à la recherche de séquences spéciales de "knocks" de ports. Un client effectue ces knocks en envoyant un paquet TCP (ou UDP) à un port sur le serveur. Ce port n'a pas besoin d'être ouvert -- puisque knockd écoute au niveau de la couche liaison, il voit tout le trafic même s'il est destiné à un port fermé. Lorsque le serveur détecte une séquence spécifique de knocks, il exécute une commande définie dans son fichier de configuration. Cela peut être utilisé pour ouvrir des trous dans un pare-feu pour un accès rapide.

OPTIONS DE LIGNE DE COMMANDE

-i, --interface <int>
Spécifie une interface sur laquelle écouter. Par défaut, c'est eth0.
-d, --daemon
Se détacher du terminal. Ceci est généralement souhaité pour un fonctionnement normal de type serveur.
-c, --config <fichier>
Spécifie un emplacement alternatif pour le fichier de configuration. Par défaut, c'est /etc/knockd.conf.
-D, --debug
Affiche les messages de débogage.
-l, --lookup
Recherche les noms DNS pour les entrées de log. Cela peut présenter un risque de sécurité ! Voir la section NOTES DE SÉCURITÉ.
-4, --only-ip-v4
Ignore les paquets IPv6 et ne traite que les paquets IPv4.
-v, --verbose
Affiche des messages d'état détaillés.
-V, --version
Affiche la version.
-h, --help
Aide sur la syntaxe.

CONFIGURATION

knockd lit tous les ensembles de knocks/événements à partir d'un fichier de configuration. Chaque knock/événement commence par un marqueur de titre, sous la forme [nom], où nom est le nom de l'événement qui apparaîtra dans le log. Un marqueur spécial, [options], est utilisé pour définir les options globales.

Exemple #1:

Cet exemple utilise deux knocks. Le premier autorise le knocker à accéder au port 22 (SSH), et le second ferme le port lorsque le knocker a terminé. Comme vous pouvez le voir, cela peut être utile si vous utilisez un pare-feu très restrictif (politique DENY) et que vous souhaitez y accéder discrètement. 
[options]
	logfile = /var/log/knockd.log
[openSSH]
	sequence    = 7000,8000,9000
	seq_timeout = 10
	tcpflags    = syn
	command     = /usr/sbin/iptables -A INPUT -s %IP% --dport 22 -j ACCEPT
[closeSSH]
	sequence    = 9000,8000,7000
	seq_timeout = 10
	tcpflags    = syn
	command     = /usr/sbin/iptables -D INPUT -s %IP% --dport 22 -j ACCEPT

Exemple #2:

Cet exemple utilise un seul knock pour contrôler l'accès au port 22 (SSH). Après avoir reçu un knock réussi, le démon exécute la commande start_command, attend le temps spécifié dans cmd_timeout, puis exécute la commande stop_command. Ceci est utile pour fermer automatiquement la porte derrière le knocker. La séquence de knock utilise à la fois les ports UDP et TCP. 
[options]
	logfile = /var/log/knockd.log
[opencloseSSH]
	sequence      = 2222:udp,3333:tcp,4444:udp
	seq_timeout   = 15
	tcpflags      = syn,ack
	start_command = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --syn -j ACCEPT
	cmd_timeout   = 5
	stop_command  = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --syn -j ACCEPT

Exemple #3:

Cet exemple n'utilise pas une séquence de knock unique et fixe pour déclencher un événement, mais un ensemble de séquences provenant d'un fichier de séquences (séquences à usage unique), spécifié par la directive one_time_sequences. Après chaque tentative de knock réussie, la séquence utilisée sera invalidée et la séquence suivante du fichier de séquences devra être utilisée pour une tentative de knock réussie. Cela empêche un attaquant de faire une attaque par rejeu après avoir découvert une séquence (par exemple, en reniflant le réseau). 
[options]
	logfile = /var/log/knockd.log
[opencloseSMTP]
	one_time_sequences = /etc/knockd/smtp_sequences
	seq_timeout        = 15
	tcpflags           = fin,!ack
	start_command      = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	cmd_timeout        = 5
	stop_command       = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT

Exemple #4:

Exemple pour supporter IPv4 et IPv6. Vous pouvez fournir une commande dédiée pour chacun des deux protocoles. 
[options]
	logfile = /var/log/knockd.log
[opencloseSMTP]
	one_time_sequences = /etc/knockd/smtp_sequences
	seq_timeout        = 15
	tcpflags           = fin,!ack
	start_command      = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	start_command_6    = /usr/sbin/ip6tables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	cmd_timeout        = 5
	stop_command       = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	stop_command_6     = /usr/sbin/ip6tables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT

CONFIGURATION: DIRECTIVES GLOBALES

UseSyslog
Journalise les messages d'action via syslog(). Cela insérera des entrées dans votre fichier /var/log/messages ou équivalent.
LogFile = /chemin/vers/fichier
Journalise les actions directement dans un fichier, généralement /var/log/knockd.log.
PidFile = /chemin/vers/fichier
Fichier PID à utiliser en mode démon, par défaut : /var/run/knockd.pid.
Interface = <nom_interface>
Interface réseau sur laquelle écouter. Seul son nom doit être donné, pas le chemin vers le périphérique (par exemple, "eth0" et non "/dev/eth0"). Par défaut : eth0.

CONFIGURATION: DIRECTIVES KNOCK/ÉVÉNEMENT

Sequence = <port1>[:<tcp|udp>],<port2>[:<tcp|udp>][,<port3>[:<tcp|udp>] ...]
Spécifie la séquence de ports dans le knock spécial. Si un port incorrect avec les mêmes drapeaux est reçu, le knock est rejeté. Vous pouvez optionnellement définir le protocole à utiliser par port (par défaut TCP).
One_Time_Sequences = /chemin/vers/fichier_sequences_usage_unique
Fichier contenant les séquences à usage unique à utiliser. Au lieu d'utiliser une séquence fixe, knockd lira la séquence à utiliser à partir de ce fichier. Après chaque tentative de knock réussie, la séquence utilisée sera désactivée en écrivant un caractère '#' à la première position de la ligne contenant la séquence utilisée. Cette séquence utilisée sera alors remplacée par la séquence valide suivante du fichier.

Comme le premier caractère est remplacé par un '#', il est recommandé de laisser un espace au début de chaque ligne. Sinon, le premier chiffre de votre séquence de knock sera écrasé par un '#' après son utilisation.

Chaque ligne du fichier de séquences à usage unique contient exactement une séquence et a le même format que celui de la directive Sequence. Les lignes commençant par un caractère '#' seront ignorées.

Note : Ne modifiez pas le fichier pendant que knockd est en cours d'exécution !

Seq_Timeout = <délai>
Temps d'attente pour la complétion d'une séquence en secondes. Si le temps est écoulé avant que le knock ne soit terminé, il est rejeté.

  • TCPFlags = <flags>
    • Spécifie les drapeaux TCP qui doivent être présents dans le paquet pour que le knock soit reconnu. Ceci est utile pour tester les connexions TCP, et peut être utilisé pour forcer un client à recommencer. L'utilisation de "TCPFlags = syn" est utile si vous testez sur une connexion SSH, car le trafic SSH interférera généralement avec (et donc invalidera) le knock.

    Séparez plusieurs drapeaux par des virgules (par exemple, TCPFlags = syn,ack,urg). Les drapeaux peuvent être explicitement exclus par un "!" (par exemple, TCPFlags = syn,!ack).

    Target = <adresse-ip>
    Utilise l'adresse IP spécifiée au lieu de l'adresse déterminée pour l' Interface lors de la mise en correspondance de la Sequence. Ceci est utile si knockd s'exécute sur un routeur et que vous souhaitez faire quelque chose en réponse à une tentative de connexion réelle à un hôte routé - par exemple, invoquer etherwake pour envoyer un paquet WOL à l'hôte.
    Start_Command = <commande>
    Spécifie la commande à exécuter lorsqu'un client effectue le port-knock correct avec IPv4. Toutes les occurrences de %IP% seront remplacées par l'adresse IP du frappeur. La directive Command est un alias pour Start_Command.
    Start_Command_6 = <commande>
    Spécifie la commande à exécuter lorsqu'un client effectue le port-knock correct avec IPv6. Toutes les occurrences de %IP% seront remplacées par l'adresse IP du frappeur. La directive Command_6 est un alias pour Start_Command_6. Si elle n'est pas présente, elle se rabattra automatiquement sur la même valeur Start_Command IPv4. Vous pouvez utiliser une valeur vide pour forcer à ne rien faire.
    Cmd_Timeout = <délai>
    Temps à attendre (en secondes) entre Start_Command et Stop_Command. Cette directive est facultative, seulement requise si Stop_Command est utilisée.
    Stop_Command = <commande>
    Spécifie la commande à exécuter lorsque Cmd_Timeout secondes se sont écoulées depuis l'exécution de Start_Command. Toutes les occurrences de %IP% seront remplacées par l'adresse IP du frappeur. Cette directive est facultative.
    Stop_Command_6 = <commande>
    Spécifie la commande à exécuter lorsque Cmd_Timeout secondes se sont écoulées depuis l'exécution de Start_Command_6. Toutes les occurrences de %IP% seront remplacées par l'adresse IP du frappeur. Cette directive est facultative. Si elle n'est pas présente, elle se rabattra automatiquement sur la même valeur Stop_Command IPv4. Vous pouvez utiliser une valeur vide pour forcer à ne rien faire.

    NOTES DE SÉCURITÉ

    L'utilisation de l'option de ligne de commande -l ou --lookup pour résoudre les noms DNS pour les entrées de journal peut présenter un risque de sécurité ! Un attaquant peut découvrir le premier port d'une séquence s'il peut surveiller le trafic DNS de l'hôte exécutant knockd. De plus, un hôte censé être furtif (par exemple, abandonnant les paquets vers des ports TCP fermés au lieu de répondre avec un paquet ACK+RST) peut se trahir en résolvant un nom DNS si un attaquant parvient à atteindre le premier port (inconnu) d'une séquence.

    VOIR AUSSI

    knock est le client port-knock accompagnant, bien que telnet ou netcat puissent être utilisés pour des knocks TCP simples à la place. Pour des knocks plus avancés, voir hping, sendip ou packit.
