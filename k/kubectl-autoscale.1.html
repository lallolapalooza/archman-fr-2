NOM

kubectl autoscale - Met à l'échelle automatiquement un déploiement, un replica set, un stateful set ou un contrôleur de réplication

SYNTAXE

kubectl autoscale [OPTIONS]

DESCRIPTION

Crée un autoscaler qui choisit et définit automatiquement le nombre de pods exécutés dans un cluster Kubernetes. La commande tentera d'utiliser d'abord l'API autoscaling/v2, en cas d'erreur, elle se rabattra sur l'API autoscaling/v1.

Recherche un déploiement, un replica set, un stateful set ou un contrôleur de réplication par son nom et crée un autoscaler qui utilise la ressource donnée comme référence. Un autoscaler peut augmenter ou diminuer automatiquement le nombre de pods déployés dans le système selon les besoins.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--cpu="" Utilisation cible du CPU sur tous les pods. Lorsqu'elle est spécifiée en pourcentage (par exemple, "70%" pour 70% du CPU demandé), elle ciblera une utilisation moyenne. Lorsqu'elle est spécifiée comme une quantité (par exemple, "500m" pour 500 milliCPU), elle ciblera une valeur moyenne. La valeur sans unité est traitée comme une quantité avec milliCPU comme unité (par exemple, "500" est "500m").

--cpu-percent=-1 L'utilisation moyenne cible du CPU (représentée en pourcentage du CPU demandé) sur tous les pods. Si elle n'est pas spécifiée ou est négative, une politique d'autoscaling par défaut sera utilisée.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est client, affiche uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-autoscale" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource à mettre à l'échelle automatiquement.

-k, --kustomize="" Traite le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--max=-1 La limite supérieure pour le nombre de pods pouvant être définis par l'autoscaler. Obligatoire.

--memory="" Utilisation cible de la mémoire sur tous les pods. Lorsqu'elle est spécifiée en pourcentage (par exemple, "60%" pour 60% de la mémoire demandée), elle ciblera une utilisation moyenne. Lorsqu'elle est spécifiée comme une quantité (par exemple, "200Mi" pour 200 MiB, "1Gi" pour 1 GiB), elle ciblera une valeur moyenne. La valeur sans unité est traitée comme une quantité avec des mébibytes comme unité (par exemple, "200" est "200Mi").

--min=-1 La limite inférieure pour le nombre de pods pouvant être définis par l'autoscaler. Si elle n'est pas spécifiée ou est négative, le serveur appliquera une valeur par défaut.

--name="" Le nom du nouvel objet créé. S'il n'est pas spécifié, le nom de la ressource d'entrée sera utilisé.

-o, --output="" Format de sortie. L'un des suivants : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, il met à jour la valeur d'annotation existante uniquement si elle existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--save-config=false Si vrai, la configuration de l'objet actuel sera enregistrée dans son annotation. Sinon, l'annotation restera inchangée. Ce drapeau est utile lorsque vous souhaitez effectuer une application kubectl sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin d'accès au fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles Go [ http://golang.org/pkg/text/template/#pkg-overview ].

OPTIONS HÉRITÉES DES COMMANDES PARENT

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin d'accès à un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin d'accès à un fichier de certificat client pour TLS

--client-key="" Chemin d'accès à un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin d'accès au fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin d'accès au fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la variable d'environnement KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. L'un des suivants (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée pendant laquelle attendre avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie qu'il n'y a pas de délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer pour le serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Mettre à l'échelle automatiquement un déploiement "foo", avec le nombre de pods entre 2 et 10, aucune utilisation cible du CPU spécifiée donc une politique d'autoscaling par défaut sera utilisée
  kubectl autoscale deployment foo --min=2 --max=10
  # Mettre à l'échelle automatiquement un contrôleur de réplication "foo", avec le nombre de pods entre 1 et 5, utilisation cible du CPU à 80%
  kubectl autoscale rc foo --max=5 --cpu=80%
  # Mettre à l'échelle automatiquement un déploiement "bar", avec le nombre de pods entre 3 et 6, CPU moyen cible de 500m et mémoire de 200Mi
  kubectl autoscale deployment bar --min=3 --max=6 --cpu=500m --memory=200Mi
  # Mettre à l'échelle automatiquement un déploiement "bar", avec le nombre de pods entre 2 et 8, utilisation du CPU cible de 60% et utilisation de la mémoire cible de 70%
  kubectl autoscale deployment bar --min=3 --max=6 --cpu=60% --memory=70%
