NOM

kube-proxy -

SYNOPSIS

kube-proxy [OPTIONS]

DESCRIPTION

Le proxy réseau Kubernetes s'exécute sur chaque nœud. Il reflète les services tels que définis dans l'API Kubernetes sur chaque nœud et peut effectuer un simple transfert de flux TCP, UDP et SCTP, ou un transfert TCP, UDP et SCTP en round robin sur un ensemble de backends. Les IPs et ports de cluster des services sont actuellement trouvés via des variables d'environnement compatibles avec Docker-links spécifiant les ports ouverts par le proxy de service. Il existe un module complémentaire optionnel qui fournit une DNS de cluster pour ces IPs de cluster. L'utilisateur doit créer un service avec l'API apiserver pour configurer le proxy.

OPTIONS

--allow_dynamic_housekeeping=true Indique si l'intervalle de maintenance doit être dynamique

--application_metrics_count_limit=100 Nombre maximal de métriques d'application à stocker (par conteneur)

--bind-address=0.0.0.0 Remplace l'idée que kube-proxy se fait de l'adresse IP principale de son nœud. Notez que le nom est un artefact historique et que kube-proxy ne lie en fait aucun socket à cette IP. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--bind-address-hard-fail=false Si vrai, kube-proxy traitera l'échec de liaison à un port comme une erreur fatale et quittera.

--boot_id_file="/proc/sys/kernel/random/boot_id" Liste séparée par des virgules de fichiers à vérifier pour le boot-id. Utilise le premier fichier existant.

--cleanup=false Si vrai, nettoie les règles iptables et ipvs et quitte.

--cluster-cidr="" La plage CIDR des pods dans le cluster. (Pour les clusters double pile, cela peut être une paire de plages CIDR double pile séparées par des virgules.). Lorsque --detect-local-mode est défini sur ClusterCIDR, kube-proxy considérera le trafic comme local si son adresse IP source se trouve dans cette plage. (Sinon, il n'est pas utilisé.) Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--config="" Le chemin d'accès au fichier de configuration.

--config-sync-period=15m0s À quelle fréquence la configuration de l'apiserver est rafraîchie. Doit être supérieur à 0.

--conntrack-max-per-core=32768 Nombre maximal de connexions NAT à suivre par cœur de processeur (0 pour laisser la limite telle quelle et ignorer conntrack-min).

--conntrack-min=131072 Nombre minimal d'entrées conntrack à allouer, quelle que soit conntrack-max-per-core (définir conntrack-max-per-core=0 pour laisser la limite telle quelle).

--conntrack-tcp-be-liberal=false Active le mode libéral pour le suivi des paquets TCP en définissant nf_conntrack_tcp_be_liberal sur 1

--conntrack-tcp-timeout-close-wait=1h0m0s Délai d'attente NAT pour les connexions TCP en état CLOSE_WAIT

--conntrack-tcp-timeout-established=24h0m0s Délai d'attente inactif pour les connexions TCP établies (0 pour laisser tel quel)

--conntrack-udp-timeout=0s Délai d'attente inactif pour les connexions UDP NON RÉPONDUES (0 pour laisser tel quel)

--conntrack-udp-timeout-stream=0s Délai d'attente inactif pour les connexions UDP ASSURÉES (0 pour laisser tel quel)

--crio_client_timeout=0s Délai d'attente du client CRI-O. Par défaut, aucun délai d'attente.

--detect-local-mode= Mode à utiliser pour détecter le trafic local. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--disable_root_cgroup_stats=false Désactive la collecte des statistiques du Cgroup racine.

--docker_only=false Rapporte uniquement les conteneurs docker en plus des statistiques racine.

--enable_load_reader=false Indique si le lecteur de charge CPU doit être activé.

--event_storage_age_limit="default=0" Durée maximale de stockage des événements (par type). La valeur est une liste de paires clé=valeur séparées par des virgules, où les clés sont des types d'événements (par exemple : creation, oom) ou "default" et la valeur est une durée. La valeur par défaut s'applique à tous les types d'événements non spécifiés.

--event_storage_event_limit="default=0" Nombre maximal d'événements à stocker (par type). La valeur est une liste de paires clé=valeur séparées par des virgules, où les clés sont des types d'événements (par exemple : creation, oom) ou "default" et la valeur est un entier. La valeur par défaut s'applique à tous les types d'événements non spécifiés.

--global_housekeeping_interval=1m0s Intervalle entre les opérations de maintenance globales.

--healthz-bind-address=0.0.0.0:10256 L'adresse IP et le port sur lesquels le serveur de vérification d'état doit écouter, par défaut "0.0.0.0:10256". Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--healthz-port=10256 Le port sur lequel le serveur de vérification d'état doit se lier. Utilisez 0 pour désactiver.

--hostname-override="" Si différent de vide, sera utilisé comme nom du nœud sur lequel kube-proxy s'exécute. S'il n'est pas défini, le nom du nœud est supposé être le même que le nom d'hôte du nœud.

--housekeeping_interval=10s Intervalle entre les opérations de maintenance des conteneurs.

--init-only=false Si vrai, effectue les étapes d'initialisation qui doivent être faites avec des privilèges root complets, puis se termine. Après cela, vous pouvez exécuter kube-proxy à nouveau avec uniquement la capacité CAP_NET_ADMIN.

--iptables-localhost-nodeports=true Si faux, kube-proxy désactivera le comportement hérité permettant d'accéder aux services NodePort via localhost. (S'applique uniquement au mode iptables et IPv4 ; les NodePorts localhost ne sont jamais autorisés avec d'autres modes de proxy ou avec IPv6.)

--iptables-masquerade-bit=14 Si vous utilisez le mode de proxy iptables ou ipvs, le bit de l'espace fwmark à marquer pour les paquets nécessitant SNAT. Doit être compris dans la plage [0, 31].

--iptables-min-sync-period=1s La période minimale entre les synchronisations des règles iptables (par exemple, '5s', '1m', '2h22m'). Une valeur de 0 signifie que chaque changement de Service ou d'EndpointSlice entraînera une synchronisation iptables immédiate.

--iptables-sync-period=30s Un intervalle (par exemple, '5s', '1m', '2h22m') indiquant la fréquence à laquelle diverses opérations de synchronisation et de nettoyage sont effectuées. Doit être supérieur à 0.

--ipvs-exclude-cidrs=[] Une liste séparée par des virgules de CIDRs que le proxifier ipvs ne doit pas toucher lors du nettoyage des règles IPVS.

--ipvs-min-sync-period=1s La période minimale entre les synchronisations des règles IPVS (par exemple, '5s', '1m', '2h22m'). Une valeur de 0 signifie que chaque changement de Service ou d'EndpointSlice entraînera une synchronisation IPVS immédiate.

--ipvs-scheduler="" Le type de planificateur ipvs lorsque le mode de proxy est ipvs.

--ipvs-strict-arp=false Active l'ARP strict en définissant arp_ignore sur 1 et arp_announce sur 2.

--ipvs-sync-period=30s Un intervalle (par exemple, '5s', '1m', '2h22m') indiquant la fréquence à laquelle diverses opérations de synchronisation et de nettoyage sont effectuées. Doit être supérieur à 0.

--ipvs-tcp-timeout=0s Le délai d'attente pour les connexions TCP IPVS inactives, 0 pour laisser tel quel. (par exemple, '5s', '1m', '2h22m').

--ipvs-tcpfin-timeout=0s Le délai d'attente pour les connexions TCP IPVS après réception d'un paquet FIN, 0 pour laisser tel quel. (par exemple, '5s', '1m', '2h22m').

--ipvs-udp-timeout=0s Le délai d'attente pour les paquets UDP IPVS, 0 pour laisser tel quel. (par exemple, '5s', '1m', '2h22m').

--kube-api-burst=10 Rafales à utiliser lors des communications avec l'apiserver kubernetes.

--kube-api-content-type="application/vnd.kubernetes.protobuf" Type de contenu des requêtes envoyées à l'apiserver.

--kube-api-qps=5 QPS à utiliser lors des communications avec l'apiserver kubernetes.

--kubeconfig="" Chemin vers le fichier kubeconfig contenant les informations d'autorisation (l'emplacement du maître peut être remplacé par le paramètre master).

--log-flush-frequency=5s Nombre maximum de secondes entre les vidages de logs.

--log-text-info-buffer-size=0 [Alpha] En format texte avec flux de sortie divisé, les messages d'information peuvent être mis en tampon pendant un certain temps pour augmenter les performances. La valeur par défaut de zéro octet désactive la mise en tampon. La taille peut être spécifiée en octets (512), multiples de 1000 (1K), multiples de 1024 (2Ki), ou puissances de ceux-ci (3M, 4G, 5Mi, 6Gi). Activez la porte d'accès aux fonctionnalités LoggingAlphaOptions pour l'utiliser.

--log-text-split-stream=false [Alpha] En format texte, écrire les messages d'erreur sur stderr et les messages d'information sur stdout. Par défaut, un seul flux est écrit sur stdout. Activez la porte d'accès aux fonctionnalités LoggingAlphaOptions pour l'utiliser.

--log_cadvisor_usage=false Indique s'il faut enregistrer l'utilisation du conteneur cAdvisor.

--logging-format="text" Définit le format des logs. Formats autorisés : "text".

--machine_id_file="/etc/machine-id,/var/lib/dbus/machine-id" Liste séparée par des virgules de fichiers à vérifier pour machine-id. Utilise le premier qui existe.

--masquerade-all=false SNAT tout le trafic envoyé via les adresses IP de cluster des Services. Ceci peut être requis avec certains plugins CNI. Uniquement supporté sous Linux.

--master="" L'adresse du serveur API Kubernetes (remplace toute valeur dans kubeconfig).

--max_housekeeping_interval=1m0s Le plus grand intervalle autorisé entre les opérations de maintenance des conteneurs.

--metrics-bind-address=127.0.0.1:10249 L'adresse IP et le port sur lesquels le serveur de métriques doit écouter, par défaut "127.0.0.1:10249". (Définir sur "0.0.0.0:10249" / "[::]:10249" pour écouter sur toutes les interfaces.) Définir vide pour désactiver. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--metrics-port=10249 Le port sur lequel le serveur de métriques doit se lier. Utilisez 0 pour désactiver.

--nodeport-addresses=[] Une liste de plages CIDR contenant des adresses IP de nœud valides, ou alternativement, la chaîne unique 'primary'. Si défini sur une liste de CIDR, les connexions aux services NodePort ne seront acceptées que sur les adresses IP de nœud dans l'une des plages indiquées. Si défini sur 'primary', les services NodePort ne seront acceptés que sur l'adresse IP principale du nœud (ou les adresses IP principales) selon l'objet Node. S'il n'est pas défini, les connexions NodePort seront acceptées sur toutes les adresses IP locales. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--oom-score-adj=-999 La valeur oom-score-adj pour le processus kube-proxy. Les valeurs doivent être comprises dans la plage [-1000, 1000]. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--pod-bridge-interface="" Un nom d'interface de pont. Lorsque --detect-local-mode est défini sur BridgeInterface, kube-proxy considérera le trafic comme local s'il provient de ce pont.

--pod-interface-name-prefix="" Un préfixe de nom d'interface. Lorsque --detect-local-mode est défini sur InterfaceNamePrefix, kube-proxy considérera le trafic comme local s'il provient d'une interface dont le nom commence par ce préfixe.

--profiling=false Si vrai, active le profilage via l'interface web sur le gestionnaire /debug/pprof. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--proxy-mode= Quel mode de proxy utiliser : sous Linux, il peut s'agir de 'iptables' (par défaut), 'ipvs' ou 'nftables'. Sous Windows, la seule valeur prise en charge est 'kernelspace'. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--referenced_reset_interval=0 Intervalle de réinitialisation pour les octets référencés (métrique container_referenced_bytes), nombre de cycles de mesure après lesquels les octets référencés sont effacés, s'il est défini sur 0, les octets référencés ne sont jamais effacés (défaut : 0)

>--show-hidden-metrics-for-version="" La version précédente pour laquelle vous souhaitez afficher les métriques masquées. Seule la version mineure précédente est pertinente, d'autres valeurs ne seront pas autorisées. Le format est ., par exemple : '1.16'. Le but de ce format est de s'assurer que vous avez l'opportunité de remarquer si la prochaine version masque des métriques supplémentaires, plutôt que d'être surpris lorsqu'elles sont définitivement supprimées dans la version suivante. Ce paramètre est ignoré si un fichier de configuration est spécifié par --config.

--storage_driver_buffer_duration=1m0s Les écritures dans le pilote de stockage seront mises en mémoire tampon pendant cette durée, et validées dans les backends non mémoire en tant que transaction unique.

--storage_driver_db="cadvisor" nom de la base de données

--storage_driver_host="localhost:8086" hôte:port de la base de données

--storage_driver_password="root" mot de passe de la base de données

--storage_driver_secure=false utiliser une connexion sécurisée avec la base de données

--storage_driver_table="stats" nom de la table

--storage_driver_user="root" nom d'utilisateur de la base de données

--update_machine_info_interval=5m0s Intervalle entre les mises à jour des informations de la machine.

-v, --v=0 nombre pour la verbosité du niveau de journalisation

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--vmodule= liste de paramètres séparés par des virgules de type motif=N pour la journalisation filtrée par fichier (ne fonctionne qu'avec le format de journalisation texte)

--write-config-to="" Si défini, écrit les valeurs de configuration par défaut dans ce fichier et quitte.
