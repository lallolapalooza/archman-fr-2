Nom

kitten-edit-in-kitty - Éditer un fichier dans une fenêtre d'aperçu kitty

Usage

kitten edit-in-kitty [options] fichier-a-editer

Description

Édite le fichier spécifié dans une fenêtre d'aperçu kitty. Fonctionne également via SSH.

Pour les instructions d'utilisation, voir : https://sw.kovidgoyal.net/kitty/shell-integration/#edit-file

Options

--title, --window-title
Le titre à définir pour la nouvelle fenêtre. Par défaut, le titre est contrôlé par le processus enfant. La valeur spéciale current copiera le titre de la fenêtre source (--source-window).
--tab-title
Le titre de l'onglet lors du lancement dans un nouvel onglet. Par défaut, le titre de la fenêtre active dans l'onglet est utilisé comme titre d'onglet. La valeur spéciale current copiera le titre de l'onglet contenant la fenêtre source (--source-window).
--type [=window]
Où lancer le processus enfant :

window
Une nouvelle fenêtre kitty dans l'onglet actuel

tab
Un nouvel onglet dans la fenêtre système actuelle. Non disponible lorsque la commande de lancement <launch> est utilisée dans les sessions de démarrage.

os-window
Une nouvelle fenêtre système. Non disponible lorsque la commande de lancement <launch> est utilisée dans les sessions de démarrage.

overlay
Une fenêtre d'aperçu couvrant la fenêtre kitty active actuelle

overlay-main
Une fenêtre d'aperçu couvrant la fenêtre kitty active actuelle. Contrairement à une fenêtre d'aperçu simple, cette fenêtre est considérée comme une fenêtre principale, ce qui signifie qu'elle est utilisée comme fenêtre active pour obtenir le répertoire de travail actuel, le texte d'entrée pour les kittens, les commandes de lancement, etc. Utile si cet aperçu est destiné à fonctionner longtemps comme une fenêtre principale.

background
Le processus sera exécuté en arrière-plan, sans fenêtre kitty. Notez que si --allow-remote-control est spécifié, la variable d'environnement KITTY_LISTEN_ON sera définie sur un descripteur de fichier de paire de sockets dédié que le processus peut utiliser pour le contrôle à distance.

clipboard, primary
Ces deux options sont destinées à fonctionner avec --stdin-source pour copier des données dans le presse-papiers système ou la sélection primaire.

os-panel
Similaire à os-window, sauf qu'il crée la nouvelle fenêtre système comme un panneau de bureau. Ne fonctionne que sur les plateformes qui le supportent, comme les compositeurs Wayland qui supportent le protocole de shell de couche. Utilisez l'option --os-panel pour configurer le panneau.

Choix : window, background, clipboard, os-panel, os-window, overlay, overlay-main, primary, tab

--dont-take-focus, --keep-focus [=no]
Garder le focus sur la fenêtre actuellement active au lieu de basculer vers la nouvelle fenêtre ouverte.
--cwd
Le répertoire de travail pour l'enfant nouvellement lancé. Utilisez la valeur spéciale current pour utiliser le répertoire de travail de la fenêtre source (--source-window). La valeur spéciale last_reported utilise le dernier répertoire de travail signalé par le shell (nécessite l'intégration du shell pour fonctionner). La valeur spéciale oldest fonctionne comme current mais utilise le répertoire de travail du processus de premier plan le plus ancien associé à la fenêtre active actuelle plutôt que le processus de premier plan le plus récent. Enfin, la valeur spéciale root fait référence au processus qui a été initialement démarré lors de la création de la fenêtre.

Lors de l'ouverture dans le même répertoire de travail que la fenêtre actuelle, si cela amène la nouvelle fenêtre à se connecter à un hôte distant, vous pouvez utiliser le drapeau --hold-after-ssh pour empêcher la nouvelle fenêtre de se fermer lorsque la connexion est terminée.

--env
Variables d'environnement à définir dans le processus enfant. Peut être spécifié plusieurs fois pour définir différentes variables d'environnement. Syntaxe : nom=valeur. Utiliser nom= définira une chaîne vide et nom supprimera la variable d'environnement.
--var
Variables utilisateur à définir dans la fenêtre créée. Peut être spécifié plusieurs fois pour définir différentes variables utilisateur. Syntaxe : nom=valeur. Utiliser nom= définira une chaîne vide.
--hold [=no]
Garder la fenêtre ouverte même après la sortie de la commande exécutée, à une invite de shell. Le shell sera exécuté après la sortie de la commande lancée.
--location [=default]
Où placer la nouvelle fenêtre lorsqu'elle est ajoutée à un onglet contenant déjà des fenêtres. after et before placent la nouvelle fenêtre avant ou après la fenêtre active. neighbor est un synonyme de after. S'applique également à la création d'un nouvel onglet, où la valeur after placera le nouvel onglet à côté de l'onglet actuel au lieu de la fin. Les valeurs vsplit, hsplit et split ne sont utilisées que par la mise en page des divisions et contrôlent si la nouvelle fenêtre est placée dans une division verticale, horizontale ou automatique avec la fenêtre active actuelle. Par défaut, la fenêtre est placée d'une manière dépendante de la mise en page, généralement après la fenêtre active actuelle. Voir --next-to pour utiliser une fenêtre autre que la fenêtre active actuelle.

Choix : default, after, before, first, hsplit, last, neighbor, split, vsplit

--next-to
Une expression de correspondance pour sélectionner la fenêtre à côté de laquelle la nouvelle fenêtre est créée. Voir search_syntax pour la syntaxe de spécification des fenêtres. Si non spécifié, utilise la fenêtre active par défaut. Lorsqu'il est utilisé via le contrôle à distance et qu'un onglet cible est spécifié, cette option est ignorée à moins que la fenêtre correspondante ne se trouve dans l'onglet spécifié. Lors de l'utilisation de --type of tab, l'onglet sera créé dans la fenêtre système contenant la fenêtre correspondante.
--os-window-class
Définit la propriété WM_CLASS sur X11 et la propriété application id sur Wayland pour la nouvelle fenêtre système créée lors de l'utilisation de --type. Par défaut, utilise ce qui est utilisé par le processus kitty parent, qui à son tour utilise kitty par défaut.
--os-window-name
Définit la propriété WM_NAME sur X11 pour la nouvelle fenêtre système créée lors de l'utilisation de --type. Par défaut, utilise --os-window-class.
--os-window-title
Définit le titre de la nouvelle fenêtre système. Ce titre remplacera tous les titres définis par les programmes s'exécutant dans kitty. La valeur spéciale current copiera le titre de la fenêtre système contenant la fenêtre source (--source-window).
--os-window-state [=normal]
L'état initial de la nouvelle fenêtre système.

Choix : normal, fullscreen, maximized, minimized

--logo
Chemin d'accès à une image PNG à utiliser comme logo pour la nouvelle fenêtre. Voir window_logo_path. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty.
--logo-position
La position du logo de la fenêtre. N'a d'effet que si --logo est spécifié. Voir window_logo_position.
--logo-alpha [=-1]
Le niveau de transparence du logo de la fenêtre dans l'arrière-plan. N'a d'effet que si --logo est spécifié. Voir window_logo_alpha.
--color
Change les couleurs de la nouvelle fenêtre lancée. Vous pouvez soit spécifier un chemin vers un fichier .conf avec la même syntaxe que kitty.conf pour lire les couleurs, soit les spécifier individuellement, par exemple :


--color background=white --color foreground=red

--spacing
Définit la marge et le remplissage pour le nouveau c

kitty — 1

Name

kitten-edit-in-kitty — Edit a file in kitty

Usage

kitten edit-in-kitty [options]

Description

The edit-in-kitty kitten lets you edit files using kitty's built-in editor. It is useful for editing configuration files or any other file that you want to edit within kitty itself.

Options

--allow-remote-control, -A
Allow the action to be run remotely. See Remote control for details.
--listen-on-socket, -L socket
Listen on the specified Unix socket for remote control commands. This option implies --allow-remote-control.
--directory, -d directory
Change to the specified directory before running the command. The default is the current working directory.
--confirm-os-window-close [=yes|no]
When a window is closed by the OS (e.g. by killing the process in it), whether to ask for confirmation before closing the OS window. Defaults to yes.
--title title
Set the window title to the specified value. This can be specified multiple times. The last value specified is the one that is used.
--layout layout
Set the layout to the specified value. This can be specified multiple times. The last value specified is the one that is used.
--map map
Assign a keyboard shortcut to a specific action. See Keyboard shortcuts for details. This can be specified multiple times.
--map-to-си си
Same as --map, but for character sequences. This can be specified multiple times.
--unmap си
Remove the specified keyboard shortcut. This can be specified multiple times.
--cwd directory
Set the current working directory for the new window. This is useful for launching programs in a specific directory. This can be specified multiple times. The last value specified is the one that is used.
--copy-cwd =yes|no
If set to yes, the new window's current working directory is copied from the current window. Defaults to yes.
--keep-new-window-alive [=yes|no]
When set to yes, the new window will not be closed automatically when the program running in it exits. Defaults to no.
--window-border width
Set the width of the window border. For example: --window-border=2. This option is ignored for overlay windows.
--window-padding width
Set the padding around the window. For example: --window-padding=10. This can be specified multiple times, e.g. --window-padding=10,10 or --window-padding=10,5,10,5. The shorthand form sets all values, the *-h and *-v variants set horizontal and vertical values. Can be specified multiple times. Note that this is ignored for overlay windows as these use the settings from the base window.
--margin width
Set the margin around the window. For example: margin=20 or padding-left=10 or margin-h=30. The shorthand form sets all values, the *-h and *-v variants set horizontal and vertical values. Can be specified multiple times. Note that this is ignored for overlay windows as these use the settings from the base window.
--hold-after-ssh [=no]
When using --cwd=current or similar from a window that is running the ssh kitten, the new window will run a local shell after disconnecting from the remote host, when this option is specified.
--max-file-size [=8]
The maximum allowed size (in MB) of files to edit. Since the file data has to be base64 encoded and transmitted over the tty device, overly large files will not perform well.
--help, -h [=no]
Show help for this command
