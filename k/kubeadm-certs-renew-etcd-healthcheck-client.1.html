NOM

kubeadm certs renew etcd-healthcheck-client - Renouveler le certificat pour les sondes de vivacité afin de vérifier la santé d'etcd

SYNTAXE

kubeadm certs renew etcd-healthcheck-client [OPTIONS]

DESCRIPTION

Renouveler le certificat pour les sondes de vivacité afin de vérifier la santé d'etcd.

Les renouvellements s'exécutent sans condition, quelle que soit la date d'expiration du certificat ; les attributs supplémentaires tels que les SANs seront basés sur le fichier/certificats existants, il n'est pas nécessaire de les fournir à nouveau.

Le renouvellement tente par défaut d'utiliser l'autorité de certification dans le PKI local géré par kubeadm ; en alternative, il est possible d'utiliser l'API de certification K8s pour le renouvellement de certificat, ou en dernier recours, de générer une demande CSR.

Après le renouvellement, afin de rendre les changements effectifs, il est nécessaire de redémarrer les composants du plan de contrôle et éventuellement de redistribuer le certificat renouvelé si le fichier est utilisé ailleurs.

OPTIONS

--cert-dir="/etc/kubernetes/pki" Le chemin où enregistrer les certificats

--config="" Chemin vers un fichier de configuration kubeadm.

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si l'indicateur n'est pas défini, un ensemble d'emplacements standard peut être recherché pour un fichier kubeconfig existant.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine du hôte 'réel'. Cela amènera kubeadm à utiliser le chemin fourni comme chroot.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée
