NOM

kubeadm join phase control-plane-prepare all - Préparer la machine pour servir un plan de contrôle

SYNTAXE

kubeadm join phase control-plane-prepare all [OPTIONS]

DESCRIPTION

Préparer la machine pour servir un plan de contrôle

OPTIONS

--apiserver-advertise-address="" Si le nœud doit héberger une nouvelle instance de plan de contrôle, l'adresse IP que le serveur d'API annoncera à l'écoute. Si non défini, l'interface réseau par défaut sera utilisée.

--apiserver-bind-port=6443 Si le nœud doit héberger une nouvelle instance de plan de contrôle, le port sur lequel le serveur d'API se liera.

--certificate-key="" Utiliser cette clé pour décrypter les secrets de certificat téléchargés par init. La clé de certificat est une chaîne hexadécimale qui représente une clé AES de 32 octets.

--config="" Chemin d'accès à un fichier de configuration kubeadm.

--control-plane=false Créer une nouvelle instance de plan de contrôle sur ce nœud

--discovery-file="" Pour la découverte basée sur des fichiers, un fichier ou une URL à partir duquel charger les informations du cluster.

--discovery-token="" Pour la découverte basée sur des jetons, le jeton utilisé pour valider les informations du cluster récupérées du serveur API.

--discovery-token-ca-cert-hash=[] Pour la découverte basée sur des jetons, valider que la clé publique de l'autorité de certification racine correspond à ce hash (format : ":").

--discovery-token-unsafe-skip-ca-verification=false Pour la découverte basée sur des jetons, autoriser la jonction sans épinglage de `--discovery-token-ca-cert-hash`.

--dry-run=false Ne pas appliquer de modifications ; afficher seulement ce qui serait fait.

--node-name="" Spécifier le nom du nœud.

--patches="" Chemin d'accès à un répertoire contenant des fichiers nommés "target[suffix][+patchtype].extension". Par exemple, "kube-apiserver0+merge.yaml" ou juste "etcd.json". "target" peut être l'un de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" peut être l'un de "strategic", "merge" ou "json" et correspond aux formats de patch pris en charge par kubectl. Le "patchtype" par défaut est "strategic". "extension" doit être soit "json" soit "yaml". "suffix" est une chaîne facultative qui peut être utilisée pour déterminer quels patchs sont appliqués en premier par ordre alphanumérique.

--tls-bootstrap-token="" Spécifier le jeton utilisé pour s'authentifier temporairement auprès du plan de contrôle Kubernetes lors de la jonction du nœud.

--token="" Utiliser ce jeton pour `discovery-token` et `tls-bootstrap-token` lorsque ces valeurs ne sont pas fournies.

OPTIONS HÉRITÉES DES COMMANDES PARENT

--rootfs="" Le chemin d'accès au 'vrai' système de fichiers racine de l'hôte. Cela forcera kubeadm à utiliser un chroot dans le chemin fourni.

--version=false `--version`, `--version=raw` affichent les informations de version et quittent ; `--version=vX.Y.Z...` définit la version rapportée
