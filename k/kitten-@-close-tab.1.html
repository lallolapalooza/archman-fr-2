Nom

kitten-@-close-tab - Ferme les onglets spécifiés

Usage

kitten @ close-tab

Description

Ferme un ensemble arbitraire d'onglets. L'option --match peut être utilisée pour spécifier des ensembles complexes d'onglets à fermer. Par exemple, pour fermer tous les onglets non focalisés dans la fenêtre OS actuellement focalisée, utilisez ::


kitten @ close-tab --match "not state:focused and state:parent_focused"

Options

--match, -m
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un de : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du plus grand nombre d'id vers le bas, en particulier, -1 est l'onglet/la fenêtre le(la) plus récemment créé(e).

Lors de l'utilisation de title ou id, une correspondance d'onglet est d'abord recherchée, et si aucune n'est trouvée, une correspondance de fenêtre est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre OS active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre OS active, zéro étant l'onglet actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session fait correspondre les onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session active et ~ pour faire correspondre soit la session active, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var fait correspondre les onglets contenant n'importe quelle fenêtre avec les variables utilisateur spécifiées.

Le champ state fait correspondre l'état de l'onglet. Les états supportés sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre OS parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont envoyés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets dans la fenêtre OS focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--no-response [=no]
N'attendez pas de réponse indiquant le succès de l'action. Notez que l'utilisation de cette option signifie que vous ne serez pas informé des échecs.
--self [=no]
Ferme l'onglet de la fenêtre dans laquelle cette commande est exécutée, plutôt que l'onglet actif.
--ignore-no-match [=no]
Ne renvoie pas d'erreur si aucun onglet ne correspond pour être fermé.
--help, -h [=no]
Affiche l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas trouvée non plus, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela amènera kitty à demander la permission à l'utilisateur pour effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs en fin de ligne sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun fichier --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation systématique ou jamais du mot de passe fourni. Si elle est définie sur always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
