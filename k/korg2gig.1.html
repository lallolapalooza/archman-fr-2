NOM

korg2gig - Convertit des fichiers sonores de KORG au format GigaStudio.

SYNTAXE

korg2gig [-v] [-f] [--interpret-names] FICHIER1 [ FICHIER2 ... ] NOUVEAUFICHIER

DESCRIPTION

Cet outil prend une liste de fichiers sonores KORG, utilisés avec les claviers synthétiseurs KORG comme Trinity, Triton, OASYS, M3 ou Kronos, et les convertit en un fichier Gigasampler/GigaStudio (.gig). Tous les fichiers KORG d'entrée sont fusionnés en un seul fichier de sortie (.gig).

Pour chaque fichier KORG "multi-sample" (.KMP), un instrument GigaStudio séparé sera créé dans le fichier de sortie (.gig). Les fichiers KORG Sample (.KSF) référencés par de tels fichiers multi-sample (.KMP) sont automatiquement détectés, chargés et écrits dans le fichier de sortie (.gig) également. Les assignations d'échantillons aux régions de clavier, les boucles d'échantillons et d'autres informations mineures d'articulation sont également converties. Mais notez que le format multi-sample (.KMP) est très primitif. Il ne sauve PAS les informations détaillées d'articulation de votre clavier KORG comme les enveloppes, les réglages LFO et de filtre. Ces informations sont stockées dans un fichier de programme (.PCG) séparé.

Malheureusement, il n'y a pas encore de support pour les fichiers programme/combinaisons/banque (.PCG) de KORG. Regardez l'option  --interpret-names pour une solution de contournement. En raison de ce manque de support pour les fichiers .PCG, vous devrez toujours ajuster les paramètres d'articulation dans le fichier de sortie (.gig) par la suite avec un éditeur d'instruments comme gigedit(1).

Si vous passez explicitement des fichiers KORG Sample (.KSF) également, et qu'ils ne sont référencés par aucun fichier "multi-sample" (.KMP) que vous auriez passé, alors ces échantillons orphelins sont ajoutés au fichier de sortie (.gig) dans un groupe d'échantillons séparé appelé "Non référencé". De cette façon, vous pouvez facilement distinguer les échantillons dans le fichier de sortie (.gig) qui sont réellement utilisés par l'un des instruments, et les échantillons qui ne sont pas encore utilisés.

NOTE : Cet outil peut nécessiter beaucoup de RAM pour le moment. Il allouera approximativement autant de RAM que la taille attendue du fichier .gig de sortie. Assurez-vous donc d'avoir suffisamment de RAM libre et/ou d'espace d'échange, sinon cet outil pourrait planter s'il ne parvient pas à allouer l'espace RAM requis.

OPTIONS

 FICHIER1 [ FICHIER2 ... ]
Une liste de fichiers sonores KORG d'entrée (.KMP ou .KSF). Vous devez fournir au moins un fichier KORG. Les fichiers KORG Sample (.KSF) référencés dans les fichiers "multi-sample" (.KMP) sont automatiquement détectés et chargés. Donc, dans la plupart des cas, vous passerez simplement des fichiers .KMP comme arguments de fichier d'entrée.
 NOUVEAUFICHIER
Fichier de sortie au format Gigasampler/GigaStudio (.gig). Si ce fichier de sortie existe déjà, korg2gig s'arrêtera avec un message d'erreur à moins que vous ne spécifiiez également  -f comme argument.
 -v
affiche la version et quitte
 -f
Écrase le fichier de sortie s'il existe déjà.
 --interpret-names
Essaye de deviner les paires d'échantillons gauche/droite et les divisions de vélocité. C'est une solution de contournement pour le fait qu'il n'y a pas de support pour lire les fichiers KORG .PCG. Si vous avez nommé manuellement les multi-samples (fichiers .KMP) sur votre clavier selon un schéma comme "PIANO 003-120 -R", il interprétera les deux indices comme a) une plage de division de vélocité (dans cet exemple de vélocité 3 à 120) et b) une paire d'échantillons stéréo (dans ce cas, le multi-sample contient le canal droit). Bien sûr, vous pouvez également omettre un ou les deux indices si vous ne voulez pas de division de vélocité ou de paire d'échantillons stéréo pour certains instruments ou régions.
