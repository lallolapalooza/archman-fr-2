NOM

kubectl create secret generic - Créer un secret à partir d'un fichier local, d'un répertoire ou d'une valeur littérale

SYNTAXE

kubectl create secret generic [OPTIONS]

DESCRIPTION

Crée un secret basé sur un fichier, un répertoire ou une valeur littérale spécifiée.

Un seul secret peut regrouper une ou plusieurs paires clé/valeur.

Lors de la création d'un secret basé sur un fichier, la clé sera par défaut le nom de base du fichier, et la valeur sera le contenu du fichier. Si le nom de base est une clé invalide ou si vous souhaitez en choisir une autre, vous pouvez spécifier une clé alternative.

Lors de la création d'un secret basé sur un répertoire, chaque fichier dont le nom de base est une clé valide dans le répertoire sera regroupé dans le secret. Toutes les entrées du répertoire, à l'exception des fichiers ordinaires, sont ignorées (par exemple, sous-répertoires, liens symboliques, périphériques, tuyaux, etc.).

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de mappe est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--append-hash=false Ajoute un hash du secret à son nom.

--dry-run="none" Doit être "none", "server" ou "client". Si stratégie client, imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--from-env-file=[] Spécifie le chemin d'un fichier à lire pour obtenir des lignes de paires clé=valeur afin de créer un secret.

--from-file=[] Les fichiers de clés peuvent être spécifiés en utilisant leur chemin de fichier, auquel cas un nom par défaut leur sera donné, ou optionnellement avec un nom et un chemin de fichier, auquel cas le nom donné sera utilisé. La spécification d'un répertoire itérera chaque fichier nommé dans le répertoire qui est une clé de secret valide.

--from-literal=[] Spécifie une clé et une valeur littérale à insérer dans le secret (par exemple, ma_clé=valeur_spéciale)

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si vrai, la configuration de l'objet actuel sera sauvegardée dans son annotation. Sinon, l'annotation restera inchangée. Ce drapeau est utile lorsque vous souhaitez effectuer une application kubectl sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets aux formats JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est golang templates [http://golang.org/pkg/text/template/#pkg-overview].

--type="" Le type de secret à créer

--validate="strict" Doit être l'un des suivants : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le api-server, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation côté serveur des champs est activée sur le serveur API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectueront aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

OPTIONS HERITEES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression de réponse pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la porte d'accès aux fonctionnalités KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Créer un nouveau secret nommé my-secret avec des clés pour chaque fichier du dossier bar
  kubectl create secret generic my-secret --from-file=path/to/bar
  # Créer un nouveau secret nommé my-secret avec des clés spécifiées au lieu des noms sur disque
  kubectl create secret generic my-secret --from-file=ssh-privatekey=path/to/id_rsa --from-file=ssh-publickey=path/to/id_rsa.pub
  # Créer un nouveau secret nommé my-secret avec key1=supersecret et key2=topsecret
  kubectl create secret generic my-secret --from-literal=key1=supersecret --from-literal=key2=topsecret
  # Créer un nouveau secret nommé my-secret en utilisant une combinaison d'un fichier et d'une valeur littérale
  kubectl create secret generic my-secret --from-file=ssh-privatekey=path/to/id_rsa --from-literal=passphrase=topsecret
  # Créer un nouveau secret nommé my-secret à partir de fichiers d'environnement
  kubectl create secret generic my-secret --from-env-file=path/to/foo.env --from-env-file=path/to/bar.env
