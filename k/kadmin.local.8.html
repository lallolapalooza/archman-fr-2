NOM

kadmin - Programme d'administration de la base de données Kerberos V5

SYNOPSIS

kadmin [-O|-N] [-r realm] [-p principal] [-q query] [[-c cache_name]|[-k [-t keytab]]|-n] [-w password] [-s admin_server[:port]] [command args...]

kadmin.local [-r realm] [-p principal] [-q query] [-d dbname] [-e enc:salt ...] [-m] [-x db_args] [command args...]

DESCRIPTION

kadmin et kadmin.local sont des interfaces en ligne de commande pour le système d'administration Kerberos V5. Ils fournissent des fonctionnalités presque identiques ; la différence est que kadmin.local accède directement à la base de données du KDC, tandis que kadmin effectue des opérations en utilisant kadmind(8). Sauf indication contraire explicite, cette page manuelle utilisera « kadmin » pour désigner les deux versions. kadmin permet la maintenance des principaux Kerberos, des politiques de mot de passe et des tables de clés de service (keytabs).

Le client kadmin distant utilise Kerberos pour s'authentifier auprès de kadmind en utilisant le principal de service kadmin/admin ou kadmin/ADMINHOST (où ADMINHOST est le nom d'hôte pleinement qualifié du serveur d'administration). Si le cache d'identifiants contient un ticket pour l'un de ces principaux, et que l'option -c credentials_cache est spécifiée, ce ticket est utilisé pour s'authentifier auprès de kadmind. Sinon, les options -p et -k sont utilisées pour spécifier le nom du principal Kerberos du client utilisé pour s'authentifier. Une fois que kadmin a déterminé le nom du principal, il demande un ticket de service au KDC et utilise ce ticket de service pour s'authentifier auprès de kadmind.

Puisque kadmin.local accède directement à la base de données du KDC, il doit généralement être exécuté directement sur le KDC primaire avec des permissions suffisantes pour lire la base de données du KDC. Si la base de données du KDC utilise le module de base de données LDAP, kadmin.local peut être exécuté sur n'importe quel hôte pouvant accéder au serveur LDAP.

OPTIONS

-r realm
Utiliser realm comme realm de base de données par défaut.
-p principal
Utiliser principal pour s'authentifier. Sinon, kadmin ajoutera /admin au nom du principal principal du ccache par défaut, à la valeur de la variable d'environnement USER , ou au nom d'utilisateur obtenu avec getpwuid, par ordre de préférence.
-k
Utiliser un keytab pour déchiffrer la réponse du KDC au lieu de demander un mot de passe. Dans ce cas, le principal par défaut sera host/hostname. S'il n'y a pas de keytab spécifié avec l'option -t , alors le keytab par défaut sera utilisé.
-t keytab
Utiliser keytab pour déchiffrer la réponse du KDC. Cela ne peut être utilisé qu'avec l'option -k .
-n
Demande un traitement anonyme. Deux types de principaux anonymes sont supportés. Pour un Kerberos entièrement anonyme, configurez PKINIT sur le KDC et configurez pkinit_anchors dans le krb5.conf(5) du client. Utilisez ensuite l'option -n avec un principal de la forme @REALM (un nom de principal vide suivi du signe arobase et d'un nom de realm). Si le KDC le permet, un ticket anonyme sera retourné. Une deuxième forme de tickets anonymes est supportée ; ces tickets exposant le realm cachent l'identité du client mais pas le realm du client. Pour ce mode, utilisez kinit -n avec un nom de principal normal. Si le KDC le supporte, le principal (mais pas le realm) sera remplacé par le principal anonyme. Depuis la version 1.8, le KDC MIT Kerberos ne supporte que le fonctionnement entièrement anonyme.
-c credentials_cache
Utiliser credentials_cache comme cache d'identifiants. Le cache doit contenir un ticket de service pour le service kadmin/admin ou kadmin/ADMINHOST (où ADMINHOST est le nom d'hôte pleinement qualifié du serveur d'administration) ; il peut être obtenu avec le programme kinit(1). Si cette option n'est pas spécifiée, kadmin demande un nouveau ticket de service au KDC et le stocke dans son propre ccache temporaire.
-w password
Utiliser password au lieu d'en demander un. Utilisez cette option avec prudence, car elle peut exposer le mot de passe à d'autres utilisateurs du système via la liste de processus.
-q query
Effectuer la requête spécifiée puis quitter.
-d dbname
Spécifie le nom de la base de données du KDC. Cette option ne s'applique pas au module de base de données LDAP.
-s admin_server[:port]
Spécifie le serveur d'administration que kadmin doit contacter.
-m
Si vous utilisez kadmin.local, demander le mot de passe maître de la base de données au lieu de le lire depuis un fichier de stockage.
-e "enc:salt ..."
Définit la liste de keysalt à utiliser pour toute nouvelle clé créée. Voir Keysalt_lists dans kdc.conf(5) pour une liste de valeurs possibles.
-O
Forcer l'utilisation de l'ancien type d'authentification AUTH_GSSAPI.
-N
Empêcher le repli sur le type d'authentification AUTH_GSSAPI.
-x db_args
Spécifie les arguments spécifiques à la base de données. Voir la section suivante pour les options supportées.

À partir de la version 1.14, si des arguments de ligne de commande restent après les options, ils seront traités comme une seule requête à exécuter. Ce mode de fonctionnement est destiné aux scripts et se comporte différemment du mode interactif à plusieurs égards :

  • Les arguments de requête sont divisés par le shell, pas par kadmin.
  • Les messages informatifs et d'avertissement sont supprimés. Les messages d'erreur et la sortie de la requête (par exemple pour get_principal) seront toujours affichés.
  • Les invites de confirmation sont désactivées (comme si -force avait été donné). Les demandes de mot de passe seront toujours émises si nécessaire.
  • Le code de sortie sera non nul si la requête échoue.

L'option -q n'a pas ces différences de comportement ; la requête sera traitée comme si elle avait été saisie de manière interactive. L'option -q ne peut pas être utilisée en combinaison avec une requête dans les arguments restants.

OPTIONS DE BASE DE DONNÉES

Les options de base de données peuvent être utilisées pour remplacer les valeurs par défaut spécifiques à la base de données. Les options supportées pour le module DB2 sont :

-x dbname=*filename*
Spécifie le nom de fichier de base de la base de données DB2.
-x lockiter
Faire en sorte que les opérations d'itération maintiennent le verrou pendant toute la durée de l'opération, plutôt que de libérer temporairement le verrou lors du traitement de chaque principal. C'est le comportement par défaut, mais cette option existe pour permettre de remplacer une configuration [dbmodules] en ligne de commande. Introduite pour la première fois dans la version 1.13.
-x unlockiter
Faire en sorte que les opérations d'itération déverrouillent la base de données pour chaque principal, au lieu de maintenir le verrou pendant toute la durée de l'opération. Introduite pour la première fois dans la version 1.13.

Les options supportées pour le module LDAP sont :

-x host=ldapuri
Spécifie le serveur LDAP auquel se connecter par une URI LDAP.
-x binddn=bind_dn
Spécifie le DN utilisé pour se lier au serveur LDAP.
-x bindpwd=password
Spécifie le mot de passe ou le secret SASL utilisé pour se lier au serveur LDAP. L'utilisation de cette option peut exposer le mot de passe à d'autres utilisateurs du système via la liste de processus ; pour éviter cela, stockez plutôt le mot de passe en utilisant la commande stashsrvpw de kdb5_ldap_util(8).
-x sasl_mech=mécanisme
Spécifie le mécanisme SASL utilisé pour se lier au serveur LDAP. Le DN de liaison est ignoré si un mécanisme SASL est utilisé. Nouveauté dans la version 1.13.
-x sasl_authcid=nom
Spécifie le nom d'authentification utilisé lors de la liaison au serveur LDAP avec un mécanisme SASL, si le mécanisme en requiert un. Nouveauté dans la version 1.13.
-x sasl_authzid=nom
Spécifie le nom d'autorisation utilisé lors de la liaison au serveur LDAP avec un mécanisme SASL. Nouveauté dans la version 1.13.
-x sasl_realm=domaine
Spécifie le domaine utilisé lors de la liaison au serveur LDAP avec un mécanisme SASL, si le mécanisme en utilise un. Nouveauté dans la version 1.13.
-x debug=niveau
Définit le niveau de débogage de la bibliothèque client OpenLDAP. niveau est un entier interprété par la bibliothèque. Les messages de débogage sont imprimés sur la sortie d'erreur standard. Nouveauté dans la version 1.12.

COMMANDES

Lors de l'utilisation du client distant, les commandes disponibles peuvent être restreintes en fonction des privilèges spécifiés dans le fichier kadm5.acl(5) sur le serveur d'administration.

add_principal

add_principal [options] nouveau_principal

Crée le principal nouveau_principal, en demandant deux fois un mot de passe. Si aucune politique de mot de passe n'est spécifiée avec l'option -policy, et que la politique nommée default est attribuée au principal s'il existe. Cependant, la création d'une politique nommée default n'attribuera pas automatiquement cette politique aux principaux existants précédemment. Cette attribution de politique peut être supprimée avec l'option -clearpolicy.

Cette commande nécessite le privilège add.

Alias : addprinc, ank

Options :

-expire date_expiration
(chaîne getdate) La date d'expiration du principal.
-pwexpire date_expiration_mdp
(chaîne getdate) La date d'expiration du mot de passe.
-maxlife duree_max
(durée ou chaîne getdate) La durée de vie maximale du ticket pour le principal.
-maxrenewlife duree_renouvellement_max
(durée ou chaîne getdate) La durée de vie maximale renouvelable des tickets pour le principal.
-kvno no_version_cle
Le numéro de version de clé initial.
-policy politique
La politique de mot de passe utilisée par ce principal. Si non spécifiée, la politique default est utilisée si elle existe (sauf si -clearpolicy est spécifié).
-clearpolicy
Empêche toute politique d'être attribuée lorsque -policy n'est pas spécifié.
{-|+}allow_postdated
-allow_postdated interdit à ce principal d'obtenir des tickets postdatés. +allow_postdated efface ce drapeau.
{-|+}allow_forwardable
-allow_forwardable interdit à ce principal d'obtenir des tickets transférables. +allow_forwardable efface ce drapeau.
{-|+}allow_renewable
-allow_renewable interdit à ce principal d'obtenir des tickets renouvelables. +allow_renewable efface ce drapeau.
{-|+}allow_proxiable
-allow_proxiable interdit à ce principal d'obtenir des tickets utilisables comme proxy. +allow_proxiable efface ce drapeau.
{-|+}allow_dup_skey
-allow_dup_skey désactive l'authentification utilisateur à utilisateur pour ce principal en interdisant aux autres d'obtenir un ticket de service chiffré avec la clé de session TGT de ce principal. +allow_dup_skey efface ce drapeau.
{-|+}requires_preauth
+requires_preauth exige que ce principal se préauthentifie avant d'être autorisé à utiliser kinit. -requires_preauth efface ce drapeau. Lorsque +requires_preauth est défini sur un principal de service, le KDC n'émettra des tickets de service pour ce principal de service que si l'authentification initiale du client a été effectuée à l'aide de la pré-authentification.
{-|+}requires_hwauth
+requires_hwauth exige que ce principal se préauthentifie à l'aide d'un appareil matériel avant d'être autorisé à utiliser kinit. -requires_hwauth efface ce drapeau. Lorsque +requires_hwauth est défini sur un principal de service, le KDC n'émettra des tickets de service pour ce principal de service que si l'authentification initiale du client a été effectuée à l'aide d'un appareil matériel pour la pré-authentification.
{-|+}ok_as_delegate
+ok_as_delegate définit le drapeau okay as delegate sur les tickets émis avec ce principal en tant que service. Les clients peuvent utiliser ce drapeau comme une indication que les informations d'identification doivent être déléguées lors de l'authentification auprès du service. -ok_as_delegate efface ce drapeau.
{-|+}allow_svr
-allow_svr interdit l'émission de tickets de service pour ce principal. Dans les versions 1.17 et ultérieures, les tickets de service utilisateur à utilisateur sont toujours autorisés sauf si le drapeau -allow_dup_skey est également défini. +allow_svr efface ce drapeau.
{-|+}allow_tgs_req
-allow_tgs_req spécifie qu'une requête Ticket-Granting Service (TGS) pour un ticket de service pour ce principal n'est pas autorisée. +allow_tgs_req efface ce drapeau.
{-|+}allow_tix
-allow_tix interdit l'émission de tout ticket pour ce principal. +allow_tix efface ce drapeau.
{-|+}needchange
+needchange force un changement de mot de passe lors de la prochaine authentification initiale auprès de ce principal. -needchange efface ce drapeau.
{-|+}password_changing_service
+password_changing_service marque ce principal comme étant un principal de service de changement de mot de passe.
{-|+}ok_to_auth_as_delegate
+ok_to_auth_as_delegate autorise ce principal à acquérir des tickets transférables à lui-même de la part d'utilisateurs arbitraires, pour une utilisation avec la délégation contrainte.
{-|+}no_auth_data_required
+no_auth_data_required empêche l'ajout de données PAC ou AD-SIGNEDPATH aux tickets de service pour le principal.
{-|+}lockdown_keys
+lockdown_keys empêche les clés de ce principal de quitter le KDC via kadmind. Les opérations chpass et extract sont refusées pour un principal avec cet attribut. L'opération chrand est autorisée, mais ne renverra pas les nouvelles clés. Les opérations delete et rename sont également refusées si cet attribut est défini, afin d'empêcher un administrateur malveillant de remplacer des principaux comme krbtgt/* ou kadmin/* par de nouveaux principaux sans l'attribut. Cet attribut peut être défini via le protocole réseau, mais ne peut être supprimé qu'en utilisant kadmin.local.
-randkey
Définit la clé du principal sur une valeur aléatoire.
-nokey
Crée le principal sans clé. Nouveauté dans la version 1.12.
-pw mot_de_passe
Définit le mot de passe du principal sur la chaîne spécifiée et ne demande pas de mot de passe. Note : l'utilisation de cette option dans un script shell peut exposer le mot de passe à d'autres utilisateurs du système via la liste des processus.
-e chiffrement:sel,...
Utilise la liste de clésalt spécifiée pour définir les clés du principal. Voir Keysalt_lists dans kdc.conf(5) pour une liste de valeurs possibles.
-x args_db_principal
Indique les options spécifiques à la base de données. Les options pour le module de base de données LDAP sont :
-x dn=dn
Spécifie l'objet LDAP qui contiendra le principal Kerberos en cours de création.
-x linkdn=dn
Spécifie l'objet LDAP auquel le nouvel objet principal Kerberos sera lié.
-x containerdn=dn_conteneur
Spécifie l'objet conteneur sous lequel le principal Kerberos doit être créé.
-x tktpolicy=politique
Associe une politique de ticket au principal Kerberos.

NOTE :

  • Les options containerdn et linkdn ne peuvent pas être spécifiées avec l'option dn.
  • Si les options dn ou containerdn ne sont pas spécifiées lors de l'ajout du principal, les principaux sont créés sous le conteneur de principaux configuré dans le domaine ou sous le conteneur du domaine.
  • dn et containerdn doivent se situer dans les sous-arbres ou le conteneur de principaux configuré dans le domaine.

Exemple :

kadmin: addprinc jennifer
Aucune politique spécifiée pour "jennifer@ATHENA.MIT.EDU";
utilisation de la politique par défaut (aucune).
Entrez le mot de passe pour le principal jennifer@ATHENA.MIT.EDU :
Entrez à nouveau le mot de passe pour le principal jennifer@ATHENA.MIT.EDU :
Principal "jennifer@ATHENA.MIT.EDU" créé.

NAME

kadmin - Kerberos 5 administration program

SYNOPSIS

kadmin [-l] [-r realm] [-p principal] [-n] [-m] [-k] [-q] [-T stashfile]

DESCRIPTION

kadmin is a command-line interface to the Kerberos administration server, kadmind(8). It allows principals with appropriate privileges to manage Kerberos principals, policies, and realms.

When kadmin is invoked, it attempts to contact the Kerberos administration server in the default realm. If it cannot contact the server, it will indicate an error and exit. If the server is running, kadmin will prompt for a password for the specified principal, or the current principal if none is specified.

The principal used for administration is typically kadmin/admin or kadmin/changepw for the realm. The default principal is the current Kerberos principal if the -n option is used. The -m option uses the principal name as the password.

The -k option disables the use of Kerberos tickets for authentication and instead uses the stash file specified by -T or the default stash file (usually /etc/krb5.keytab).

The -q option causes kadmin to execute the single command specified and then exit.

The -l option runs kadmin in local mode, connecting directly to the KDC database without going through the kadmind server. This is useful for performing database maintenance or when the KDC is running on the same host and you have administrative access to the KDC's database files.

OPTIONS

-l
Run in local mode, directly accessing the KDC database.
realm
Specify the realm to administer. If not specified, the default realm is used.
principal
Specify the administrative principal to log in as. Defaults to kadmin/admin in the specified realm.
-n
Do not prompt for a password. Use the current Kerberos ticket.
-m
Use the principal name as the password. Use with caution.
-k
Use the keytab file for authentication instead of a password.
-q
Execute a single command and exit.
stashfile
Specify the keytab file to use when the -k option is specified. Defaults to /etc/krb5.keytab.

DATABASE OPTIONS

When running in local mode (with -l), the following options may be used to specify the database file or type:

database_name
Specify the name of the KDC database file. Defaults to /var/kerberos/krb5kdc/principal.
realm_name
Specify the realm name associated with the database. Defaults to the default realm.
db_type
Specify the type of the KDC database (e.g., Berkeley DB, LDAP). Defaults to the type configured in kdc.conf.

COMMANDS

The following commands are available within the kadmin interactive shell:

add_principal

add_principal [options] principal

Adds a new principal to the Kerberos database. Options include:

principal
The name of the principal to add (e.g., user/admin).
-pw password
Specify the password for the new principal. If not specified, the user will be prompted for it.
-maxlife lifetime
(duration string) Sets the maximum lifetime for tickets issued to this principal. Defaults to the realm's maximum ticket life.
-minlife lifetime
(duration string) Sets the minimum lifetime for tickets issued to this principal. Defaults to the realm's minimum ticket life.
-maxrenewlife lifetime
(duration string) Sets the maximum renewable lifetime for tickets issued to this principal. Defaults to the realm's maximum renewable ticket life.
-policy policyname
Assigns the specified password policy to the principal.
-attributes +|-attribute,...
Sets or unsets principal attributes. Valid attributes include max_renewable, user_princ, ok_as_delegate, password_changing_required, requires_preauth, supported_enctypes.
-kvno kvno
Sets the key version number for the principal.
-keytype keytype,...
Specifies the key types to be generated for the principal. Defaults to all supported key types.
-enddate date
(date string) Sets the expiration date for the principal.
-max_skey_life lifetime
(duration string) Sets the maximum lifetime for service tickets issued to this principal. Defaults to the realm's maximum service ticket life.

Example:

kadmin: add_principal -maxlife "10 days" user/admin
Password for user/admin@REALM:
kadmin:

add_policy

add_policy [options] policy

Adds a new password policy named policy to the Kerberos database. Options include:

-maxlife lifetime
(duration or getdate string) Sets the maximum password lifetime. A value of 0 means indefinite.
-minlife lifetime
(duration or getdate string) Sets the minimum time that must pass before a password can be changed. A value of 0 means no minimum time.
-minlength length
(integer) Sets the minimum password length. Defaults to 0.
-minclasses count
(integer) Sets the minimum number of character classes required in the password. Character classes are typically lowercase letters, uppercase letters, digits, and punctuation. Defaults to 0.
-minkeyrmse count
(integer) Sets the minimum number of keys to be kept for a principal. Defaults to 0.
-maxkeys count
(integer) Sets the maximum number of keys to be kept for a principal. Defaults to 0.
-kthist count
(integer) Sets the number of historical keys to be kept for a principal. Defaults to 0.
-failurecountinterval failuretime
(duration or getdate string) Sets the allowable time between authentication failures. If an authentication failure happens after failuretime has elapsed since the previous failure, the number of authentication failures is reset to 1. A failuretime value of 0 (the default) means forever.
-lockoutduration lockouttime
(duration or getdate string) Sets the duration for which the principal is locked from authenticating if too many authentication failures occur without the specified failure count interval elapsing. A duration of 0 (the default) means the principal remains locked out until it is administratively unlocked with modprinc -unlock.
-allowedkeysalts
Specifies the key/salt tuples supported for long-term keys when setting or changing a principal's password/keys. See Keysalt_lists in kdc.conf(5) for a list of the accepted values, but note that key/salt tuples must be separated with commas (',') only. To clear the allowed key/salt policy use a value of '-'.

Example:

kadmin: add_policy -maxlife "2 days" -minlength 5 guests
kadmin:

ktadd

ktadd [options] principal
ktadd [options] -glob princ-exp

Adds a principal, or all principals matching princ-exp, to a keytab file. Each principal's keys are randomized in the process. The rules for princ-exp are described in the list_principals command.

This command requires the inquire and changepw privileges. With the -glob form, it also requires the list privilege.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-e enc:salt,...
Uses the specified keysalt list for setting the new keys of the principal. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-q
Display less verbose information.
-norandkey
Do not randomize the keys. The keys and their version numbers stay unchanged. This option cannot be specified in combination with the -e option.

An entry for each of the principal's unique encryption types is added, ignoring multiple keys with the same encryption type but different salt types.

Alias: xst

Example:

kadmin: ktadd -k /tmp/foo-new-keytab host/foo.mit.edu
Entry for principal host/foo.mit.edu@ATHENA.MIT.EDU with kvno 3,
     encryption type aes256-cts-hmac-sha1-96 added to keytab
     FILE:/tmp/foo-new-keytab
kadmin:

ktremove

ktremove [options] principal [kvno | all | old]

Removes entries for the specified principal from a keytab. Requires no permissions, since this does not require database access.

If the string "all" is specified, all entries for that principal are removed; if the string "old" is specified, all entries for that principal except those with the highest kvno are removed. Otherwise, the value specified is parsed as an integer, and all entries whose kvno match that integer are removed.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-q
Display less verbose information.

Alias: ktrem

Example:

kadmin: ktremove kadmin/admin all
Entry for principal kadmin/admin with kvno 3 removed from keytab
     FILE:/etc/krb5.keytab
kadmin:
