Paquet: krb5

Licences: custom

KVNO(1) MIT Kerberos KVNO(1)

NOM

kvno - afficher les numéros de version de clé des principaux Kerberos

SYNTAXE

kvno [-c ccache] [-e etype] [-k keytab] [-q] [-u | -S sname] [-P] [--cached-only] [--no-store] [--out-cache cache] [[{-F cert_file | {-I | -U} for_user} [-P]] | --u2u ccache] service1 service2 ...

DESCRIPTION

kvno acquiert un ticket de service pour les principaux Kerberos spécifiés et affiche les numéros de version de clé de chacun.

OPTIONS

-c ccache
Spécifie le nom d'un cache d'informations d'identification à utiliser (si ce n'est pas celui par défaut)
-e etype
Spécifie le type d'ennumération qui sera demandé pour la clé de session de tous les services nommés sur la ligne de commande. Ceci est utile dans certaines situations de compatibilité ascendante.
-k keytab
Déchiffre les tickets acquis en utilisant keytab pour confirmer leur validité.
-q
Supprime l'affichage en cas de succès. Si un ticket de service ne peut être obtenu, un message d'erreur sera toujours affiché et kvno se terminera avec un statut non nul.
-u
Utilise le type de nom inconnu dans les noms de principaux de service demandés. Cette option ne peut pas être utilisée avec -S.
-P
Spécifie que les arguments service1 service2 ... doivent être traités comme des services pour lesquels des informations d'identification doivent être acquises en utilisant la délégation contrainte. Cette option n'est valide que lorsqu'elle est utilisée conjointement avec la transition de protocole.
-S sname
Spécifie que les arguments service1 service2 ... sont interprétés comme des noms d'hôtes, et que les principaux de service doivent être construits à partir de ces noms d'hôtes et du nom de service sname. Les noms d'hôtes de service seront canonisés conformément aux règles habituelles de construction des principaux de service.
-I for_user
Spécifie que la transition de protocole (S4U2Self) doit être utilisée pour acquérir un ticket au nom de for_user. Si la délégation contrainte n'est pas demandée, le nom du service doit correspondre au principal client du cache d'informations d'identification.
-U for_user
Identique à -I, mais traite for_user comme un nom d'entreprise.
-F cert_file
Spécifie que la transition de protocole doit être utilisée, identifiant le principal client avec le certificat X.509 dans cert_file. Le fichier de certificat doit être au format PEM.
--cached-only
Ne récupérer que les informations d'identification déjà présentes dans le cache, pas du KDC. (Ajouté dans la version 1.19.)
--no-store
Ne pas stocker les informations d'identification récupérées dans le cache. Si --out-cache est également spécifié, les informations d'identification seront quand même stockées dans le cache d'informations d'identification de sortie. (Ajouté dans la version 1.19.)
--out-cache ccache
Initialise ccache et y stocke toutes les informations d'identification récupérées. Ne pas stocker les informations d'identification acquises dans le cache d'entrée. (Ajouté dans la version 1.19.)
--u2u ccache
Demande un ticket utilisateur-à-utilisateur. ccache doit contenir un ticket krbtgt local pour le principal serveur. Le numéro de version rapporté sera généralement de 0, car le ticket résultant n'est pas chiffré avec la clé à long terme du serveur.

ENVIRONNEMENT

Voir kerberos(7) pour une description des variables d'environnement Kerberos.

FICHIERS
