NOM

kubectl create secret docker-registry - Créer un secret pour l'utilisation avec un registre Docker

SYNTAXE

kubectl create secret docker-registry [OPTIONS]

DESCRIPTION

Crée un nouveau secret pour l'utilisation avec les registres Docker.

    Les secrets Dockercfg sont utilisés pour s'authentifier auprès des registres Docker.
    Lorsque vous utilisez la ligne de commande Docker pour pousser des images, vous pouvez vous authentifier auprès d'un registre donné en exécutant :
    '$ docker login DOCKER_REGISTRY_SERVER --username=DOCKER_USER --password=DOCKER_PASSWORD --email=DOCKER_EMAIL'.

Cela produit un fichier ~/.dockercfg qui est utilisé par les commandes 'docker push' et 'docker pull' ultérieures pour s'authentifier auprès du registre. L'adresse e-mail est facultative.

    Lors de la création d'applications, vous pourriez avoir un registre Docker nécessitant une authentification. Afin que
    les nœuds puissent tirer des images en votre nom, ils doivent avoir les identifiants. Vous pouvez fournir ces informations
    en créant un secret dockercfg et en le rattachant à votre compte de service.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignorez toutes les erreurs dans les modèles lorsqu'un champ ou une clé de mappe est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--append-hash=false Ajoute un hachage du secret à son nom.

--docker-email="" E-mail pour le registre Docker

--docker-password="" Mot de passe pour l'authentification au registre Docker

--docker-server="https://index.docker.io/v1/" Emplacement du serveur pour le registre Docker

--docker-username="" Nom d'utilisateur pour l'authentification au registre Docker

--dry-run="none" Doit être "none", "server", ou "client". Si stratégie client, imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--from-file=[] Les clés de fichiers peuvent être spécifiées par leur chemin de fichier, auquel cas un nom par défaut, .dockerconfigjson, leur sera donné, ou optionnellement avec un nom et un chemin de fichier, auquel cas le nom donné sera utilisé. Spécifier un répertoire itérera chaque fichier nommé dans le répertoire qui est une clé de secret valide. Pour cette commande, la clé doit toujours être .dockerconfigjson.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si vrai, la configuration de l'objet actuel sera sauvegardée dans son annotation. Sinon, l'annotation sera inchangée. Ce drapeau est utile lorsque vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format de modèle est les modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un des : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le serveur d'API, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur d'API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

OPTIONS HERITEES DES COMMANDES PARENT

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur ordinaire ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la porteuse de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la porteuse KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas appliquer de délai d'attente aux requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Si vous n'avez pas encore de fichier .dockercfg, créez directement un secret dockercfg
  kubectl create secret docker-registry my-secret --docker-server=DOCKER_REGISTRY_SERVER --docker-username=DOCKER_USER --docker-password=DOCKER_PASSWORD --docker-email=DOCKER_EMAIL
  # Crée un nouveau secret nommé my-secret à partir de ~/.docker/config.json
  kubectl create secret docker-registry my-secret --from-file=path/to/.docker/config.json
