syslog(2) Manuel des appels système syslog(2)

NOM

syslog, klogctl - lire et/ou effacer le tampon circulaire des messages du noyau ; définir le niveau de journalisation de la console

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_syslog, int type, char *bufp, int size);
/* L'interface glibc */
#include <sys/klog.h>
int klogctl(int type, char *bufp, int size);

DESCRIPTION

Note : Vous recherchez probablement la fonction de la bibliothèque C syslog(), qui communique avec syslogd(8) ; voir syslog(3) pour les détails.

Cette page décrit l'appel système syslog() du noyau, qui est utilisé pour contrôler le tampon printk() du noyau ; la fonction wrapper de glibc pour l'appel système s'appelle klogctl().

Le tampon de journalisation du noyau

Le noyau possède un tampon circulaire de taille LOG_BUF_LEN dans lequel les messages fournis en arguments à la fonction noyau printk() sont stockés (indépendamment de leur niveau de journalisation). Dans les noyaux anciens, LOG_BUF_LEN valait 4096 ; à partir de Linux 1.3.54, il valait 8192 ; à partir de Linux 2.1.113, il valait 16384 ; depuis Linux 2.4.23/2.6, la valeur est une option de configuration du noyau (CONFIG_LOG_BUF_SHIFT, valeur par défaut dépendant de l'architecture). Depuis Linux 2.6.6, la taille peut être interrogée avec le type de commande 10 (voir ci-dessous).

Commandes

L'argument type détermine l'action effectuée par cette fonction. La liste ci-dessous spécifie les valeurs pour type. Les noms symboliques sont définis dans le code source du noyau, mais ne sont pas exportés à l'espace utilisateur ; vous devrez soit utiliser les nombres, soit définir les noms vous-même.

SYSLOG_ACTION_CLOSE (0)
Fermer le journal. Actuellement un NOP (No Operation).
SYSLOG_ACTION_OPEN (1)
Ouvrir le journal. Actuellement un NOP.
SYSLOG_ACTION_READ (2)
Lire depuis le journal. L'appel attend jusqu'à ce que le tampon de journalisation du noyau ne soit plus vide, puis lit au maximum len octets dans le tampon pointé par bufp. L'appel retourne le nombre d'octets lus. Les octets lus du journal disparaissent du tampon de journalisation : l'information ne peut être lue qu'une seule fois. C'est la fonction exécutée par le noyau lorsqu'un programme utilisateur lit /proc/kmsg.
SYSLOG_ACTION_READ_ALL (3)
Lire tous les messages restants dans le tampon circulaire, en les plaçant dans le tampon pointé par bufp. L'appel lit les len derniers octets du tampon de journalisation (de manière non destructive), mais ne lira pas plus que ce qui a été écrit dans le tampon depuis la dernière commande "effacer le tampon circulaire" (voir la commande 5 ci-dessous). L'appel retourne le nombre d'octets lus.
SYSLOG_ACTION_READ_CLEAR (4)
Lire et effacer tous les messages restants dans le tampon circulaire. L'appel fait précisément la même chose que pour un type de 3, mais exécute également la commande "effacer le tampon circulaire".
SYSLOG_ACTION_CLEAR (5)
L'appel exécute uniquement la commande "effacer le tampon circulaire". Les arguments bufp et size sont ignorés.
Cette commande n'efface pas réellement le tampon circulaire. Plutôt, elle définit une variable de comptabilité du noyau qui détermine les résultats retournés par les commandes 3 (SYSLOG_ACTION_READ_ALL) et 4 (SYSLOG_ACTION_READ_CLEAR). Cette commande n'a aucun effet sur les commandes 2 (SYSLOG_ACTION_READ) et 9 (SYSLOG_ACTION_SIZE_UNREAD).
SYSLOG_ACTION_CONSOLE_OFF (6)
La commande sauvegarde la valeur actuelle de console_loglevel puis définit console_loglevel à minimum_console_loglevel, de sorte qu'aucun message ne soit imprimé sur la console. Avant Linux 2.6.32, la commande définissait simplement console_loglevel à minimum_console_loglevel. Voir la discussion sur /proc/sys/kernel/printk, ci-dessous.
Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_CONSOLE_ON (7)
Si une commande SYSLOG_ACTION_CONSOLE_OFF précédente a été exécutée, cette commande restaure console_loglevel à la valeur qui avait été sauvegardée par cette commande. Avant Linux 2.6.32, cette commande définissait simplement console_loglevel à default_console_loglevel. Voir la discussion sur /proc/sys/kernel/printk, ci-dessous.
Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_CONSOLE_LEVEL (8)
L'appel définit console_loglevel à la valeur donnée dans size, qui doit être un entier compris entre 1 et 8 (inclus). Le noyau impose silencieusement une valeur minimale de minimum_console_loglevel pour size. Voir la section niveau de journalisation pour plus de détails. L'argument bufp est ignoré.
SYSLOG_ACTION_SIZE_UNREAD (9) (depuis Linux 2.4.10)
L'appel retourne le nombre d'octets actuellement disponibles à lire depuis le tampon de journalisation du noyau via la commande 2 (SYSLOG_ACTION_READ). Les arguments bufp et size sont ignorés.
SYSLOG_ACTION_SIZE_BUFFER (10) (depuis Linux 2.6.6)
Cette commande retourne la taille totale du tampon de journalisation du noyau. Les arguments bufp et size sont ignorés.

Toutes les commandes sauf 3 et 10 nécessitent des privilèges. Dans les noyaux Linux avant Linux 2.6.37, les types de commandes 3 et 10 sont autorisés pour les processus non privilégiés ; depuis Linux 2.6.37, ces commandes ne sont autorisées pour les processus non privilégiés que si /proc/sys/kernel/dmesg_restrict a la valeur 0. Avant Linux 2.6.37, "privilégié" signifie que l'appelant possède la capacité CAP_SYS_ADMIN. Depuis Linux 2.6.37, "privilégié" signifie que l'appelant possède soit la capacité CAP_SYS_ADMIN (maintenant dépréciée à cet effet), soit la (nouvelle) capacité CAP_SYSLOG.

/proc/sys/kernel/printk

/proc/sys/kernel/printk est un fichier inscriptible contenant quatre valeurs entières qui influencent le comportement de printk() du noyau lors de l'impression ou de la journalisation des messages d'erreur. Les quatre valeurs sont :

console_loglevel
Seuls les messages ayant un niveau de journalisation inférieur à cette valeur seront imprimés sur la console. La valeur par défaut de ce champ est DEFAULT_CONSOLE_LOGLEVEL (7), mais elle est définie à 4 si la ligne de commande du noyau contient le mot "quiet", à 10 si la ligne de commande du noyau contient le mot "debug", et à 15 en cas de défaut du noyau (les valeurs 10 et 15 sont simplement absurdes et équivalentes à 8). La valeur de console_loglevel peut être définie (à une valeur comprise entre 1 et 8) par un appel syslog() avec un type de 8.
default_message_loglevel
Cette valeur sera utilisée comme niveau de journalisation pour les messages printk() qui n'ont pas de niveau explicite. Jusqu'à et y compris Linux 2.6.38, la valeur par défaut codée en dur pour ce champ était 4 (KERN_WARNING) ; depuis Linux 2.6.39, la valeur par défaut est définie par l'option de configuration du noyau CONFIG_DEFAULT_MESSAGE_LOGLEVEL, qui vaut par défaut 4.
minimum_co
Cette valeur est le niveau de journalisation le plus bas autorisé pour la console. Les appels système utilisant la commande 6 (SYSLOG_ACTION_CONSOLE_OFF) ou la commande 8 (SYSLOG_ACTION_CONSOLE_LEVEL) ne peuvent pas définir le niveau de journalisation de la console à une valeur inférieure à minimum_console_loglevel. La valeur par défaut est définie par MINIMUM_CONSOLE_LOGLEVEL (par défaut 1). Elle est définie à 0 si le mot "quiet" ou "debug" apparaît sur la ligne de commande du noyau.
default_console_loglevel
La valeur à laquelle console_loglevel est rétablie par la commande 7 (SYSLOG_ACTION_CONSOLE_ON) lorsqu'une commande 6 précédente a été exécutée. La valeur par défaut est définie par DEFAULT_CONSOLE_LOGLEVEL (par défaut 7).

Les niveaux de journalisation sont des entiers de 0 à 8. Les niveaux plus bas indiquent des messages plus urgents. La signification des niveaux est définie dans printk() et est la suivante :

KERN_EMERG (0)
Système inutilisable.
KERN_ALERT (1)
Action requise immédiatement.
KERN_CRIT (2)
Conditions critiques.
KERN_ERR (3)
Messages d'erreur.
KERN_WARNING (4)
Avertissements.
KERN_NOTICE (5)
Notifications normales mais significatives.
KERN_INFO (6)
Messages informatifs.
KERN_DEBUG (7)
Messages de débogage.

Ces valeurs sont définies dans <linux/kern_levels.h>. Notez que KERN_DEBUG est 7, et le niveau 8 est réservé pour une utilisation interne.

Le comportement du noyau concernant les messages est le suivant :

  • Tous les messages du noyau, indépendamment de leur niveau, sont stockés dans le tampon circulaire du noyau.
  • Les messages sont imprimés sur la console si leur niveau est inférieur à console_loglevel.
  • Les messages sont envoyés aux démons de journalisation (tels que syslogd(8)) s'ils ont un niveau inférieur ou égal à default_message_loglevel.

La lecture du fichier /proc/kmsg est une autre façon d'accéder aux messages du noyau. La lecture de ce fichier est équivalente à l'utilisation de la commande 2 (SYSLOG_ACTION_READ) du système d'appels syslog().

ERREURS

En cas de succès, klogctl() retourne une valeur non négative (un nombre d'octets lus, ou zéro). En cas d'échec, il retourne -1 et définit errno en conséquence.

Les erreurs courantes sont notamment :

EINVAL
Type d'action invalide.
EFAULT
bufp pointe hors de l'espace d'adressage accessible.
EPERM
L'opération nécessite des privilèges et l'appelant ne les a pas.
EACCES
L'opération nécessite des privilèges et l'appelant ne les a pas.

CONFORMITÉS

Cet appel système est spécifique à Linux.

klogctl(3) - Pages de manuel Linux

NOM

klogctl - Accéder au tampon de journalisation du noyau

BIBLIOTHEQUE

API C standard (libc), Utilisation avec l'option -lncurses (ne doit pas être liée explicitement).

SYNTAXE

#include <sys/klog.h>

int klogctl(int type, char *buf, int len);

DESCRIPTION

La fonction klogctl() fournit une interface pour le mécanisme de journalisation du noyau Linux. Les différentes fonctionnalités sont sélectionnées par le paramètre type.

Contrôle du niveau de journalisation

Les valeurs suivantes de type contrôlent le niveau de journalisation du noyau pour la console :

type=2 (KLOG_READ_ALL)
Lit le tampon de journalisation du noyau. Le message le plus ancien est lu en premier. Le nombre d'octets lus est renvoyé.
type=3 (KLOG_READ_ALL_CLEAR)
Lit le tampon de journalisation du noyau et le vide ensuite. Le nombre d'octets lus est renvoyé.
type=4 (KLOG_CLEAR)
Vide le tampon de journalisation du noyau.
type=7 (KLOG_GET_LOGLEVEL)
Lit le niveau de journalisation actuel de la console.
type=8 (KLOG_SET_LOGLEVEL)
Définit le niveau de journalisation de la console. Le paramètre level doit être dans la plage 1 à 8.

Paramètres globaux de niveau de journalisation

Il existe deux paramètres globaux qui affectent le comportement de la journalisation du noyau :

console_loglevel
La valeur dans ce champ est la valeur minimale à laquelle console_loglevel peut être définie.
default_console_loglevel
C'est la valeur par défaut pour console_loglevel.

Le niveau de journalisation

Chaque message printk() a son propre niveau de journalisation. Si le niveau de journalisation n'est pas explicitement spécifié dans le message, il est par défaut default_message_loglevel. La signification conventionnelle du niveau de journalisation est la suivante :

Constante du noyau Valeur du niveau Signification
KERN_EMERG 0 Système inutilisable
KERN_ALERT 1 Action immédiate requise
KERN_CRIT 2 Conditions critiques
KERN_ERR 3 Conditions d'erreur
KERN_WARNING 4 Conditions d'avertissement
KERN_NOTICE 5 Condition normale mais significative
KERN_INFO 6 Informationnel
KERN_DEBUG 7 Messages de niveau débogage

La routine printk() du noyau affichera un message sur la console uniquement si son niveau de journalisation est inférieur à la valeur de console_loglevel.

VALEUR DE RETOUR

Pour type égal à 2, 3 ou 4, un appel réussi à syslog() renvoie le nombre d'octets lus. Pour type 9, syslog() renvoie le nombre d'octets actuellement disponibles à la lecture sur le tampon de journalisation du noyau. Pour type 10, syslog() renvoie la taille totale du tampon de journalisation du noyau. Pour d'autres valeurs de type, 0 est renvoyé en cas de succès.

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
Arguments incorrects (par exemple, type incorrect ; ou pour type 2, 3 ou 4, buf est NULL, ou size est inférieur à zéro ; ou pour type 8, le level est hors de la plage de 1 à 8).
ENOSYS
Cet appel système syslog() n'est pas disponible, car le noyau a été compilé avec l'option de configuration du noyau CONFIG_PRINTK désactivée.
EPERM
Une tentative a été faite pour modifier console_loglevel ou effacer le tampon circulaire de messages du noyau par un processus sans privilèges suffisants (plus précisément : sans la capacité CAP_SYS_ADMIN ou CAP_SYSLOG).
ERESTARTSYS
L'appel système a été interrompu par un signal ; rien n'a été lu. (Ceci ne peut être vu que lors d'un traçage.)

NORMES

Linux.

HISTORIQUE

Dès le début, les gens ont noté qu'il est regrettable qu'un appel système et une routine de bibliothèque du même nom soient des entités totalement différentes.

VOIR AUSSI
