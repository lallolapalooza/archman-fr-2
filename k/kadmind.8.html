NOM

kadmind - Serveur d'administration KADM5

SYNTAXE

kadmind [-x db_args] [-r realm] [-m] [-nofork] [-proponly] [-port port-numéro] [-P fichier-pid] [-p chemin-kdb5_util] [-K chemin-kprop] [-k port-kprop] [-F fichier-dump]

DESCRIPTION

kadmind démarre le serveur d'administration Kerberos. kadmind s'exécute généralement sur le serveur Kerberos principal, qui stocke la base de données KDC. Si la base de données KDC utilise le module LDAP, le serveur d'administration et le serveur KDC n'ont pas besoin de s'exécuter sur la même machine. kadmind accepte les requêtes distantes des programmes tels que kadmin(1) et kpasswd(1) pour administrer les informations de ces bases de données.

kadmind nécessite que plusieurs fichiers de configuration soient configurés pour fonctionner :

kdc.conf(5)
Le fichier de configuration KDC contient des informations de configuration pour les serveurs KDC et d'administration. kadmind utilise les paramètres de ce fichier pour localiser la base de données Kerberos, et est également affecté par les variables acl_file, dict_file, kadmind_port, et les paramètres liés à iprop.
kadm5.acl(5)
La liste de contrôle d'accès (ACL) de kadmind indique quels principaux sont autorisés à effectuer des actions d'administration. Le chemin d'accès au fichier ACL peut être spécifié avec la variable acl_file de kdc.conf(5) ; par défaut, c'est /var/lib/krb5kdc/kadm5.acl.

Une fois que le serveur commence à s'exécuter, il se met en arrière-plan et se détache de son terminal de contrôle.

kadmind peut être configuré pour la propagation incrémentale de la base de données. La propagation incrémentale permet aux serveurs KDC répliqués de recevoir les mises à jour de principaux et de politiques de manière incrémentale au lieu de recevoir des dumps complets de la base de données. Cette fonctionnalité peut être activée dans le fichier kdc.conf(5) avec l'option iprop_enable. La propagation incrémentale nécessite le principal kiprop/NOM_HOTE_PRINCIPAL_KDC\@REALM (où NOM_HOTE_PRINCIPAL_KDC est le nom d'hôte canonique du KDC principal, et REALM le nom du realm). Dans la version 1.13, ce principal est automatiquement créé et enregistré dans la base de données.

OPTIONS

-r realm
spécifie le realm que kadmind servira ; s'il n'est pas spécifié, le realm par défaut de l'hôte est utilisé.
-m
demande que le mot de passe de la base de données maître soit récupéré depuis le clavier (avant que le serveur ne se mette en arrière-plan, s'il n'est pas invoqué avec l'option -nofork) plutôt que depuis un fichier sur disque.
-nofork
demande au serveur de rester au premier plan et de rester associé au terminal.
-proponly
demande au serveur de n'écouter et de ne répondre qu'aux requêtes de sondage de propagation incrémentale Kerberos des répliques. Cette option peut être utilisée pour configurer une topologie de propagation hiérarchique où un KDC répliqué fournit des mises à jour incrémentales à d'autres répliques Kerberos.
-port port-numéro
spécifie le port sur lequel le serveur d'administration écoute les connexions. Le port par défaut est déterminé par la variable de configuration kadmind_port dans kdc.conf(5).
-P fichier-pid
spécifie le fichier dans lequel le PID du processus kadmind doit être écrit après son démarrage. Ce fichier peut être utilisé pour déterminer si kadmind est toujours en cours d'exécution et pour permettre aux scripts d'initialisation d'arrêter le processus correct.
-p chemin-kdb5_util
spécifie le chemin de la commande kdb5_util à utiliser lors du dump de la KDB en réponse aux requêtes de synchronisation complète lorsque iprop est activé.
-K chemin-kprop
spécifie le chemin de la commande kprop à utiliser pour envoyer des dumps complets aux répliques en réponse aux requêtes de synchronisation complète.
-k port-kprop
spécifie le port par lequel le processus kprop lancé par kadmind se connecte au kpropd répliqué, afin de transférer le fichier de dump lors d'une requête de synchronisation complète iprop.
-F fichier-dump
spécifie le chemin du fichier à utiliser pour le dump de la KDB en réponse aux requêtes de synchronisation complète lorsque iprop est activé.
-x db_args
spécifie les arguments spécifiques à la base de données. Voir les Options de base de données dans kadmin(1) pour les arguments pris en charge.

ENVIRONNEMENT

Voir kerberos(7) pour une description des variables d'environnement Kerberos.
