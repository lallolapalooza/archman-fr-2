Nom

kitten-transfer - Transférer facilement des fichiers via le périphérique TTY

Aperçu

Ajouté dans la version 0.30.0.

Transférer des fichiers vers et depuis des ordinateurs distants via le périphérique TTY lui-même. Cela signifie que le transfert de fichiers fonctionne à travers des sessions SSH imbriquées, des liaisons série, etc. Partout où vous disposez d'un périphérique terminal, vous pouvez transférer des fichiers.

Ce kitten prend en charge le transfert d'arbres de répertoires entiers, en préservant les liens symboliques et les liens physiques, les permissions de fichiers, les dates, etc. Il prend même en charge le protocole rsync https://en.wikipedia.org/wiki/Rsync pour transférer uniquement les modifications de grands fichiers.

Voir aussi :

Voir le kitten Fichiers distants <>

Utilisation de base

Connectez-vous simplement à un ordinateur distant via le ssh kitten <> et exécutez ce kitten (que le ssh kitten rend automatiquement disponible pour vous sur l'ordinateur distant). Quelques exemples illustratifs suivent. Pour copier un fichier depuis un ordinateur distant :

<ordinateur local>  $ kitten ssh my-remote-computer
<ordinateur distant> $ kitten transfer some-file /chemin/sur/ordinateur/local

Cela copiera some-file depuis l'ordinateur sur lequel vous vous êtes connecté par SSH vers votre ordinateur local à /chemin/sur/ordinateur/local. kitty vous demandera une confirmation avant d'autoriser le transfert, afin que le protocole de transfert de fichiers ne puisse pas être abusé pour lire/écrire des fichiers sur votre ordinateur.

Pour copier un fichier de votre ordinateur local vers l'ordinateur distant :

<ordinateur local>  $ kitten ssh my-remote-computer
<ordinateur distant> $ kitten transfer --direction=upload /chemin/sur/ordinateur/local fichier-distant

Pour des exemples d'utilisation plus détaillés, voir la section interface en ligne de commande ci-dessous.

Remarque :

Si vous ne souhaitez pas utiliser le ssh kitten, vous pouvez installer le binaire du kitten sur la machine distante vous-même, il s'agit d'un binaire autonome, compilé statiquement, disponible sur la page des versions de kitty https://github.com/kovidgoyal/kitty/releases. Ou vous pouvez écrire votre propre script/programme pour utiliser le protocole de transfert de fichiers sous-jacent <>.

Éviter l'invite de confirmation

Normalement, lorsque vous démarrez un transfert de fichiers, kitty vous demandera une confirmation. Cela permet de s'assurer que des programmes hostiles s'exécutant sur une machine distante ne peuvent pas lire/écrire des fichiers sur votre ordinateur sans votre permission. Si la machine distante est de confiance, vous pouvez désactiver l'invite de confirmation en :

1.
Définissant l'option file_transfer_confirmation_bypass <#opt-kitty.file_transfer_confirmation_bypass> sur un mot de passe.
2.
Lors de l'invocation du kitten, utilisez --permissions-bypass pour fournir le mot de passe que vous avez défini à l'étape un.

Avertissement :

Utiliser un mot de passe pour contourner la confirmation signifie que tout logiciel s'exécutant sur la machine distante pourrait potentiellement apprendre ce mot de passe et l'utiliser pour obtenir un accès complet à votre ordinateur.

Transferts delta

Ce kitten a la capacité d'utiliser le protocole rsync https://en.wikipedia.org/wiki/Rsync pour ne transférer que les différences entre les fichiers. Pour l'activer, utilisez l'option --transmit-deltas . Notez que cela sera en réalité plus lent lors du transfert de petits fichiers ou sur un réseau très rapide, en raison du surcoût des allers-retours, donc utilisez-le avec précaution.

Code source du transfert

Le code source de ce kitten est disponible sur GitHub https://github.com/kovidgoyal/kitty/tree/master/kittens/transfer.

Interface en ligne de commande

kitten transfer [options] fichiers_ou_répertoires_source chemin_de_destination

Transférer des fichiers via le périphérique TTY. Peut être utilisé pour envoyer des fichiers entre n'importe quels deux ordinateurs à condition qu'il existe une connexion TTY entre eux, comme via SSH. Prend en charge la copie de fichiers, de répertoires (récursivement), de liens symboliques et de liens physiques. Peut même utiliser un protocole similaire à rsync pour copier uniquement les modifications entre les fichiers. Lors de la copie de plusieurs fichiers, utilisez l'option --confirm-paths pour voir exactement ce qui sera copié. La façon la plus simple d'utiliser ce kitten est de d'abord se connecter à l'ordinateur distant avec le ssh kitten :

$ kitten ssh my-remote-computer

Ensuite, sur l'ordinateur distant, exécutez le kitten transfer pour effectuer votre copie. Pour copier un fichier de l'ordinateur distant vers l'ordinateur local, exécutez :

$ kitten transfer fichier-distant /chemin/vers/fichier-local

Cela copiera fichier-distant depuis l'ordinateur distant vers /chemin/vers/fichier-local sur l'ordinateur local.

De même, pour copier un fichier de l'ordinateur local vers l'ordinateur distant, exécutez :

$ kitten transfer --direction=upload /chemin/vers/fichier-local fichier-distant

Cela copiera /chemin/vers/fichier-local depuis l'ordinateur local vers fichier-distant sur l'ordinateur distant.

Plusieurs fichiers peuvent être copiés :

$ kitten transfer fichier1 fichier2 /chemin/vers/rép/

Cela placera fichier1 et fichier2 dans le répertoire /chemin/vers/rép/ sur l'ordinateur local.

Les répertoires peuvent également être copiés, récursivement :

$ kitten transfer rép1 /chemin/vers/rép/

Cela placera rép1 et tout son contenu dans /chemin/vers/rép/ sur l'ordinateur local.

Notez que lors de la copie de plusieurs fichiers ou répertoires, la destination doit être un répertoire existant sur l'ordinateur de réception. Les chemins de fichiers relatifs sont résolus par rapport au répertoire courant sur l'ordinateur exécutant le kitten et au répertoire personnel sur l'autre ordinateur. Il est conseillé d'utiliser le --confirm-paths indicateur de ligne de commande pour vérifier que le kitten copiera les fichiers que vous attendez.

Options

--direction <DIRECTION>, -d <DIRECTION>
Envoyer ou recevoir des fichiers. send ou download copier les fichiers de l'ordinateur sur lequel le kitten s'exécute (généralement l'ordinateur distant) vers l'ordinateur local. receive ou upload copier les fichiers de l'ordinateur local vers l'ordinateur distant. Par défaut : download Choix : download, receive, send, upload
--mode <MODE>, -m <MODE>
Comment interpréter les arguments de la ligne de commande. En mode mirror tous les arguments sont supposés être des fichiers/répertoires sur l'ordinateur émetteur et ils sont répliqués sur l'ordinateur de réception. Les fichiers sous le répertoire HOME sont copiés vers le répertoire HOME sur l'ordinateur de réception même si le répertoire HOME est différent. En mode normal le dernier argument est supposé être un chemin de destination sur l'ordinateur de réception. Le dernier argument doit être un répertoire existant sauf s'il s'agit de la copie d'un seul fichier. S'il s'agit d'un répertoire, il doit se terminer par une barre oblique finale. Par défaut : normal Choix : mirror, normal
--compress <COMPRESS>
Compresser ou non les données envoyées. Par défaut, la compression est activée en fonction du type de fichier envoyé. Pour les fichiers reconnus comme déjà compressés, la compression est désactivée car elle ne fait que gaspiller des cycles CPU. Par défaut : auto Choix : always, auto, never
kitten-transfer(1)

NOM

kitten-transfer — transférer des fichiers via kitty

SYNOPSSIS

kitten transfer [-p PERMISSIONS_BYPASS] [-c[=no]] [-x[=no]] source destination

DESCRIPTION

L'outil kitten transfer est utilisé pour transférer des fichiers entre des sessions kitty, par exemple, entre votre ordinateur local et un serveur distant auquel vous vous connectez via kitty. Il tire parti du protocole de transfert de fichiers intégré à kitty.

Les arguments source et destination peuvent être des chemins locaux ou des chemins distants. Les chemins distants sont spécifiés dans le format user@host:/path/to/file.

OPTIONS

--permissions-bypass PERMISSIONS_BYPASS, -p PERMISSIONS_BYPASS
Le mot de passe à utiliser pour ignorer la fenêtre contextuelle de confirmation de transfert dans kitty. Doit correspondre au mot de passe défini pour l'option file_transfer_confirmation_bypass <#opt-kitty.file_transfer_confirmation_bypass> dans kitty.conf. Notez que les espaces blancs de début et de fin sont supprimés du mot de passe. Un mot de passe commençant par les caractères ., / ou ~ est supposé être un nom de fichier à partir duquel lire le mot de passe. Une valeur de - signifie lire le mot de passe depuis STDIN. Un mot de passe qui est purement un nombre inférieur à 256 est supposé être le numéro d'un descripteur de fichier à partir duquel lire le mot de passe réel.
--confirm-paths [=no], -c [=no]
Avant de transférer réellement les fichiers, afficher une correspondance des noms de fichiers locaux aux noms de fichiers distants et demander une confirmation.
--transmit-deltas [=no], -x [=no]
Si un fichier côté réception existe déjà, utiliser l'algorithme rsync pour le mettre à jour afin qu'il corresponde au fichier côté envoi, économisant potentiellement beaucoup de bande passante et reprenant automatiquement les transferts partiels. Notez que cela dégradera les performances sur les liaisons rapides ou avec des fichiers de petite taille, donc à utiliser avec précaution.
