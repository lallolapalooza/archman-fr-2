kubeadm-init-phase-control-plane-all(1)

Paquet: kubeadm

Licences: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOM

kubeadm init phase control-plane all - Génère tous les fichiers de manifeste de Pod statiques

SYNTAXE

kubeadm init phase control-plane all [OPTIONS]

DESCRIPTION

Génère tous les fichiers de manifeste de Pod statiques

OPTIONS

--apiserver-advertise-address="" L'adresse IP sur laquelle l'API Server annoncera son écoute. Si non défini, l'interface réseau par défaut sera utilisée.

--apiserver-bind-port=6443 Port sur lequel l'API Server se liera.

--apiserver-extra-args= Un ensemble d'arguments supplémentaires à passer à l'API Server ou pour remplacer ceux par défaut sous la forme =

--cert-dir="/etc/kubernetes/pki" Le chemin où enregistrer et stocker les certificats.

--config="" Chemin vers un fichier de configuration kubeadm.

--control-plane-endpoint="" Spécifie une adresse IP stable ou un nom DNS pour le plan de contrôle.

--controller-manager-extra-args= Un ensemble d'arguments supplémentaires à passer au Gestionnaire de Contrôle ou pour remplacer ceux par défaut sous la forme =

--dry-run=false N'applique aucun changement ; affiche seulement ce qui serait fait.

--feature-gates="" Un ensemble de paires clé=valeur décrivant les portes de fonctionnalités pour diverses fonctionnalités. Les options sont : ControlPlaneKubeletLocalMode=true|false (BETA - par défaut=true) NodeLocalCRISocket=true|false (BETA - par défaut=true) PublicKeysECDSA=true|false (OBSOLÈTE - par défaut=false) RootlessControlPlane=true|false (ALPHA - par défaut=false) WaitForAllControlPlaneComponents=true|false (par défaut=true)

--image-repository="registry.k8s.io" Choisit un registre de conteneurs pour télécharger les images du plan de contrôle.

--kubernetes-version="stable-1" Choisit une version spécifique de Kubernetes pour le plan de contrôle.

--patches="" Chemin vers un répertoire contenant des fichiers nommés "cible[suffixe][+type_patch].extension". Par exemple, "kube-apiserver0+merge.yaml" ou juste "etcd.json". "Cible" peut être l'un de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "type_patch" peut être l'un de "strategic", "merge" ou "json" et ils correspondent aux formats de patch supportés par kubectl. Le "type_patch" par défaut est "strategic". "extension" doit être soit "json" soit "yaml". "Suffixe" est une chaîne optionnelle qui peut être utilisée pour déterminer quels patchs sont appliqués en premier par ordre alphabétique.

--pod-network-cidr="" Spécifie la plage d'adresses IP pour le réseau des pods. Si défini, le plan de contrôle attribuera automatiquement des CIDR pour chaque nœud.

--scheduler-extra-args= Un ensemble d'arguments supplémentaires à passer au Planificateur ou pour remplacer ceux par défaut sous la forme =

--service-cidr="10.96.0.0/12" Utilise une plage alternative d'adresses IP pour les VIP de service.

OPTIONS HERITEES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à utiliser chroot sur le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

EXEMPLE

  # Génère tous les fichiers de manifeste de Pod statiques pour les composants du plan de contrôle,
  # équivalent fonctionnel à ce qui est généré par kubeadm init.
  kubeadm init phase control-plane all
  # Génère tous les fichiers de manifeste de Pod statiques en utilisant les options lues à partir d'un fichier de configuration.
  kubeadm init phase control-plane all --config config.yaml
