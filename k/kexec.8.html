NOM

kexec - démarrer directement sur un nouveau noyau

SYNTAXE

/sbin/kexec [-v (--version)] [-f (--force)] [-x (--no-ifdown)] [-y (--no-sync)] [-l (--load)] [-p (--load-panic)] [-u (--unload)] [-e (--exec)] [-t (--type)] [--mem-min=addr] [--mem-max=addr]

DESCRIPTION

kexec est un appel système qui permet de charger et de démarrer sur un autre noyau depuis le noyau actuellement en cours d'exécution. kexec réalise la fonction du chargeur de démarrage depuis l'intérieur du noyau. La principale différence entre un démarrage système standard et un démarrage kexec est que l'initialisation matérielle normalement effectuée par le BIOS ou le firmware (selon l'architecture) n'est pas réalisée lors d'un démarrage kexec. Cela a pour effet de réduire le temps nécessaire à un redémarrage.

Assurez-vous d'avoir sélectionné CONFIG_KEXEC=y lors de la configuration du noyau. L'option CONFIG_KEXEC active l'appel système kexec.

UTILISATION

Utiliser kexec consiste à

(1) charger le noyau sur lequel redémarrer en mémoire, et
(2) réellement redémarrer sur le noyau pré-chargé.

Pour charger un noyau, la syntaxe est la suivante :

kexec -l image-noyau --append=options-ligne-commande --initrd=image-initrd

où image-noyau est le fichier du noyau que vous avez l'intention de démarrer lors du redémarrage.

Insérez les paramètres de ligne de commande qui doivent être passés au nouveau noyau dans options-ligne-commande. Passer le contenu exact de /proc/cmdline dans options-ligne-commande est le moyen le plus sûr de s'assurer que les valeurs correctes sont passées au noyau en cours de redémarrage.

L'optionnel image-initrd est l'image initrd à utiliser pendant le démarrage.

Il est également possible d'appeler kexec sans paramètre d'option. Dans ce cas, kexec charge le noyau spécifié puis appelle shutdown(8). Si les scripts de fermeture de votre distribution Linux prennent en charge le redémarrage basé sur kexec, ils appellent alors kexec -e juste avant de réellement redémarrer la machine. Ainsi, la machine effectue une fermeture propre incluant tous les scripts de fermeture.

EXEMPLE

Par exemple, si l'image du noyau sur laquelle vous voulez redémarrer est /boot/vmlinux, le contenu de /proc/cmdline est root=/dev/hda1, et le chemin vers l'initrd est /boot/initrd, alors vous utiliseriez la commande suivante pour charger le noyau :

kexec -l /boot/vmlinux --append=root=/dev/hda1 --initrd=/boot/initrd

Après le chargement de ce noyau, en supposant que l'espace utilisateur prenne en charge le redémarrage basé sur kexec, il peut être démarré, avec une fermeture propre, en utilisant la commande :

reboot

Alternativement, il peut également être démarré, sans appeler shutdown(8), avec la commande :

kexec -e

OPTIONS

-d (--debug)
Active les messages de débogage.
-S (--status)
Retourne 1 si le type (par défaut crash) est chargé, 0 sinon. Peut être utilisé en conjonction avec -l ou -p pour basculer le type. Notez que cette option remplace les autres options et qu'elle ne chargera ni ne déchargera le noyau.
-e (--exec)
Exécute le noyau actuellement chargé. Notez qu'il redémarrera sur le noyau chargé sans appeler shutdown(8).
-f (--force)
Force un appel kexec immédiat, sans appeler shutdown(8) (contrairement à l'action par défaut sans paramètre). Cette option effectue les mêmes actions que l'exécution de -l et -e en un seul appel.
-h (--help)
Ouvre un fichier d'aide pour kexec.
--hotplug
Configure les segments kexec afin que le noyau puisse les mettre à jour en toute sécurité lors d'événements d'ajout/suppression à chaud de CPU/mémoire. Si cette option est activée, le noyau effectue des mises à jour internes des segments kexec lors des événements d'ajout/suppression à chaud de CPU/mémoire, évitant ainsi la nécessité de recharger le noyau kdump.
-i (--no-checks)
Redémarrage rapide, pas de vérification d'intégrité de la mémoire.
-l (--load) noyau
Charge le noyau spécifié dans le noyau actuel.
-p (--load-panic)
Charge le nouveau noyau pour une utilisation en cas de panique.
-t (--type=type)
Spécifie que le nouveau noyau est de ce type.
-s (--kexec-file-syscall)
Spécifie que le nouvel appel système KEXEC_FILE_LOAD doit être utilisé exclusivement. Ignoré sur XEN.
-c (--kexec-syscall)
Spécifie que l'ancien appel système KEXEC_LOAD doit être utilisé exclusivement.
-a (--kexec-syscall-auto)
Essaie d'abord le nouvel appel système KEXEC_FILE_LOAD et, lorsqu'il n'est pas pris en charge ou que le noyau ne comprend pas l'image fournie, revient à l'ancienne interface KEXEC_LOAD.

Il n'y a pas une seule interface qui fonctionne toujours, c'est donc par défaut.

KEXEC_FILE_LOAD est requis sur les systèmes qui utilisent le démarrage sécurisé verrouillé pour vérifier la signature du noyau. KEXEC_LOAD peut également être désactivé dans la configuration du noyau.

KEXEC_LOAD est requis pour certains formats d'images de noyau et sur les architectures qui n'implémentent pas KEXEC_FILE_LOAD.

-u (--unload)
Décharge le noyau kexec cible actuel. Si un noyau de capture est en cours de déchargement, spécifiez -p avec -u.
-v (--version)
Retourne le numéro de version de l'utilitaire installé.
-x (--no-ifdown)
Arrête le noyau en cours d'exécution, mais restaure l'interface lors du rechargement.
-y (--no-sync)
Arrête le noyau en cours d'exécution, mais ignore la synchronisation des systèmes de fichiers.
--mem-min=addr
Spécifie l'adresse mémoire la plus basse addr où charger le code.
--mem-max=addr
Spécifie l'adresse mémoire la plus haute addr où charger le code.
--entry=addr
Spécifie l'adresse de saut de retour. (0 signifie qu'il n'y a pas de saut de retour ou de préservation du contexte)
--load-preserve-context
Charge le nouveau noyau et préserve le contexte du noyau actuel pendant kexec.
--load-jump-back-helper
Charge une image d'aide pour sauter vers le noyau d'origine.
--reuseinitrd
Réutilise l'initrd du premier démarrage.
--print-ckr-size
Affiche la taille de la région du noyau de vidage (crash kernel), si disponible.

kexec(8)                                                               kexec(8)

NOM

kexec - Exécute un noyau Linux depuis un noyau Linux en cours d'exécution.

SYNOPIS

kexec [-b|--load] [-e|--exec] [-fh|--load-fh] [-t|--unload] [-p|--prepare] [-k|--kexec-file-syscall] [-s|--kexec-syscall] [-i|--init-image] [--load-syscall] [--unload-syscall] [-v|--version] [-h|--help] [-a|--append-cmdline] [--command-line=string] [--reuse-cmdline] [--initrd=file] [--ramdisk=file] [--module=mod arg1 arg2 ...] [--real-mode] [--devicetreeblob=file] [--dtb=file] [--console-serial] [--console-vga] [--elf32-core-headers] [--elf64-core-headers] [--reset-vga] [--serial=port] [--serial-baud=baud_rate] [--dt-no-old-root] kernel_image [initrd_image] [command_line_arguments]

DESCRIPTION

L'outil kexec charge une nouvelle image noyau Linux dans la mémoire et peut l'exécuter, remplaçant le noyau actuel sans redémarrage matériel.

Cela peut être utilisé pour démarrer un noyau différent, pour redémarrer dans un noyau de débogage en cas de plantage, ou pour mettre à jour le noyau sans redémarrer la machine.

Lorsque kexec est utilisé avec l'option --load, il copie l'image du noyau dans la mémoire. Si l'option --exec est également spécifiée, il exécute ensuite le noyau chargé. Sinon, une fois le noyau chargé, il peut être exécuté plus tard en appelant kexec avec l'option --exec seulement.

L'option --prepare charge l'image du noyau en mémoire mais ne l'exécute pas. Cette option est utilisée par le programme crash pour démarrer un noyau de récupération dans le cas d'un crash système.

L'option --kexec-file-syscall est utilisée pour charger un noyau via le système d'appels kexec_file. Ceci est le nouveau mécanisme préféré pour le chargement de noyaux.

Les options --kexec-syscall et --load-syscall sont des mécanismes plus anciens pour le chargement de noyaux.

L'option --unload retire une image noyau précédemment chargée.

USAGE

Les options varient en fonction du type de fichier noyau utilisé. Les types de fichiers noyau pris en charge sont : raw, bzImage, elf, multiboot, multiboot2.

EXEMPLE

Pour charger et exécuter un noyau Linux appelé vmlinuz avec une ligne de commande noyau spécifique et un initrd appelé initrd.img:

kexec -l -c "root=/dev/sda1 ro" vmlinuz -initrd initrd.img

Pour exécuter le noyau précédemment chargé:

kexec -e

OPTIONS

-l, --load
Charge l'image du noyau en mémoire. Requiert l'argument du nom de fichier du noyau. Peut être utilisé avec --exec. Ne peut pas être utilisé avec --load-fh, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-e, --exec
Exécute l'image noyau précédemment chargée. Ne peut pas être utilisé avec --load, --load-fh, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-fh, --load-fh
Charge l'image noyau en utilisant le mécanisme de transfert de fichiers. Requiert l'argument du nom de fichier du noyau. Ne peut pas être utilisé avec --load, --exec, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-t, --unload
Décharge l'image noyau précédemment chargée. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-p, --prepare
Prépare le noyau pour un redémarrage en cas de crash. Exécute la commande crash(8) avec le noyau chargé. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-k, --kexec-file-syscall
Charge l'image noyau en utilisant le système d'appels kexec_file. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-syscall ou --load-syscall.
-s, --kexec-syscall
Charge l'image noyau en utilisant le système d'appels kexec. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-file-syscall ou --load-syscall.
--load-syscall
Charge l'image noyau en utilisant le système d'appels kexec_load. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-file-syscall ou --kexec-syscall.
--unload-syscall
Décharge l'image noyau en utilisant le système d'appels kexec_unload. Ne peut pas être utilisé avec --load, --exec, --load-fh, --kexec-file-syscall, --kexec-syscall ou --load-syscall.
-v, --version
Affiche la version de kexec et quitte.
-h, --help
Affiche un message d'aide et quitte.
-a, --append-cmdline
Ajoute string à la ligne de commande du noyau. Peut être utilisé plusieurs fois.
--command-line=string
Définit la ligne de commande du noyau à string.
--reuse-cmdline
Utilise la ligne de commande du système en cours d'exécution. Lorsqu'un noyau de panic est chargé, il supprime automatiquement le paramètre crashkernel. Le paramètre BOOT_IMAGE est également supprimé.
--initrd=file
Utilise file comme ramdisk initial du noyau.
--ramdisk=file
Utilise file comme ramdisk initial du noyau.
--module=mod arg1 arg2 ...
Charge le module mod avec les arguments de ligne de commande arg1 arg2 .... Ce paramètre peut être spécifié plusieurs fois.
--real-mode
Utilise le point d'entrée en mode réel.
--devicetreeblob=file
Spécifie le fichier blob de l'arbre de périphériques. Non applicable lors de l'utilisation de --kexec-file-syscall.
--dtb=file
Spécifie le fichier blob de l'arbre de périphériques. Non applicable lors de l'utilisation de --kexec-file-syscall.
--console-serial
Active la console série.
--console-vga
Active la console VGA.
--elf32-core-headers
Prépare les en-têtes de base au format ELF32.
--elf64-core-headers
Prépare les en-têtes de base au format ELF64.
--reset-vga
Tente de réinitialiser un périphérique VGA standard.
--serial=port
Spécifie le port série pour la sortie de débogage.
--serial-baud=baud_rate
Spécifie le débit en bauds du port série.
--dt-no-old-root
Ne réutilise pas l'ancien paramètre root=<device> du noyau lors de la création de l'arbre de périphériques aplati.
