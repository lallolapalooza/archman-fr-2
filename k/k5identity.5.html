NOM

k5identity - règles de sélection du principal client Kerberos V5

DESCRIPTION

Le fichier .k5identity, qui se trouve dans le répertoire personnel de l'utilisateur, contient une liste de règles pour sélectionner un principal client basé sur le serveur accédé. Ces règles sont utilisées pour choisir un cache d'identifiants au sein de la collection de caches lorsque cela est possible.

Les lignes vides et les lignes commençant par # sont ignorées. Chaque ligne a la forme suivante :

principal champ=valeur ...

Si le principal du serveur correspond à toutes les contraintes de champ, alors le principal est choisi comme principal client. Les champs suivants sont reconnus :

realm
Si le realm du principal du serveur est connu, il est comparé à valeur, qui peut être un motif utilisant des caractères génériques du shell. Pour les principaux de serveur basés sur l'hôte, le realm ne sera généralement connu que s'il existe une section domain_realm dans krb5.conf(5) avec un mappage pour le nom d'hôte.
service
Si le principal du serveur est un principal basé sur l'hôte, son composant de service est comparé à valeur, qui peut être un motif utilisant des caractères génériques du shell.
host
Si le principal du serveur est un principal basé sur l'hôte, son composant de nom d'hôte est converti en minuscules et comparé à valeur, qui peut être un motif utilisant des caractères génériques du shell.

Si le principal du serveur correspond aux contraintes de plusieurs lignes dans le fichier .k5identity, le principal de la première ligne correspondante est utilisé. Si aucune ligne ne correspond, les identifiants seront sélectionnés par un autre moyen, tel que l'heuristique du realm ou le cache principal actuel.

EXEMPLE

L'exemple de fichier .k5identity suivant sélectionne le principal client alice@KRBTEST.COM si le principal du serveur est dans ce realm, le principal alice/root@EXAMPLE.COM si l'hôte du serveur est dans un sous-domaine de serveurs, et le principal alice/mail@EXAMPLE.COM lors de l'accès au service IMAP sur mail.example.com :

alice@KRBTEST.COM       realm=KRBTEST.COM
alice/root@EXAMPLE.COM  host=*.servers.example.com
alice/mail@EXAMPLE.COM  host=mail.example.com service=imap
