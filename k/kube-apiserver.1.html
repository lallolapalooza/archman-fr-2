NOM

kube-apiserver -

SYNTAXE

kube-apiserver [OPTIONS]

DESCRIPTION

Le serveur API Kubernetes valide et configure les données pour les objets d'API qui incluent des pods, des services, des contrôleurs de réplication et d'autres. Le serveur API dessert les opérations REST et fournit l'interface vers l'état partagé du cluster à travers lequel tous les autres composants interagissent.

OPTIONS

--admission-control=[] L'admission est divisée en deux phases. Dans la première phase, seuls les plugins d'admission mutateurs s'exécutent. Dans la seconde phase, seuls les plugins d'admission valideurs s'exécutent. Les noms dans la liste ci-dessous peuvent représenter un plugin validateur, un plugin mutateur, ou les deux. L'ordre des plugins tel qu'il est passé à cette option n'a pas d'importance. Liste délimitée par des virgules de : AlwaysAdmit, AlwaysDeny, AlwaysPullImages, CertificateApproval, CertificateSigning, CertificateSubjectRestriction, ClusterTrustBundleAttest, DefaultIngressClass, DefaultStorageClass, DefaultTolerationSeconds, DenyServiceExternalIPs, EventRateLimit, ExtendedResourceToleration, ImagePolicyWebhook, LimitPodHardAntiAffinityTopology, LimitRanger, MutatingAdmissionPolicy, MutatingAdmissionWebhook, NamespaceAutoProvision, NamespaceExists, NamespaceLifecycle, NodeRestriction, OwnerReferencesPermissionEnforcement, PersistentVolumeClaimResize, PodNodeSelector, PodSecurity, PodTolerationRestriction, PodTopologyLabels, Priority, ResourceQuota, RuntimeClass, ServiceAccount, StorageObjectInUseProtection, TaintNodesByCondition, ValidatingAdmissionPolicy, ValidatingAdmissionWebhook.

--admission-control-config-file="" Fichier contenant la configuration du contrôle d'admission.

--advertise-address= L'adresse IP sur laquelle l'apiserver sera annoncé aux membres du cluster. Cette adresse doit être accessible par le reste du cluster. Si elle est vide, --bind-address sera utilisé. Si --bind-address n'est pas spécifié, l'interface par défaut de l'hôte sera utilisée.

--aggregator-reject-forwarding-redirect=true L'agrégateur rejette le renvoi de la réponse de redirection vers le client.

--allow-metric-labels=[] Le mappage de l'étiquette métrique à la liste d'autorisation de valeurs pour cette étiquette. Le format de la clé est ,. Le format de la valeur est ,... par exemple metric1,label1='v1,v2,v3', metric1,label2='v1,v2,v3' metric2,label1='v1,v2,v3'.

--allow-metric-labels-manifest="" Le chemin d'accès au fichier manifeste contenant le mappage de la liste d'autorisation. Le format du fichier est identique à celui de l'option --allow-metric-labels. Notez que l'option --allow-metric-labels remplacera le fichier manifeste.

--allow-privileged=false Si vrai, autorise les conteneurs privilégiés. [défaut=false]

--anonymous-auth=true Active les requêtes anonymes vers le port sécurisé du serveur API. Les requêtes qui ne sont pas rejetées par une autre méthode d'authentification sont traitées comme des requêtes anonymes. Les requêtes anonymes ont un nom d'utilisateur system:anonymous et un nom de groupe system:unauthenticated.

--api-audiences=[] Identifiants de l'API. L'authentificateur de jeton de compte de service validera que les jetons utilisés contre l'API sont liés à au moins une de ces audiences. Si l'option --service-account-issuer est configurée et que cette option ne l'est pas, cette option par défaut est une liste à un seul élément contenant l'URL de l'émetteur.

--apiserver-count=1 Le nombre d'apiservers en cours d'exécution dans le cluster, doit être un nombre positif. (Utilisé lorsque --endpoint-reconciler-type=master-count est activé.)

--audit-log-batch-buffer-size=10000 La taille du tampon pour stocker les événements avant le traitement par lots et l'écriture. Uniquement utilisé en mode lot.

--audit-log-batch-max-size=1 La taille maximale d'un lot. Uniquement utilisé en mode lot.

--audit-log-batch-max-wait=0s Le temps d'attente avant d'écrire de force le lot qui n'a pas atteint la taille maximale. Uniquement utilisé en mode lot.

--audit-log-batch-throttle-burst=0 Nombre maximal de requêtes envoyées en même temps si ThrottleQPS n'a pas été utilisé auparavant. Uniquement utilisé en mode lot.

--audit-log-batch-throttle-enable=false Indique si le limitation par lots est activée. Uniquement utilisé en mode lot.

--audit-log-batch-throttle-qps=0 Nombre moyen maximal de lots par seconde. Uniquement utilisé en mode lot.

--audit-log-compress=false Si défini, les fichiers journaux rotatifs seront compressés à l'aide de gzip.

--audit-log-format="json" Format des audits enregistrés. "legacy" indique un format texte sur une seule ligne pour chaque événement. "json" indique un format json structuré. Formats connus : legacy,json.

--audit-log-maxage=0 Le nombre maximum de jours de rétention des anciens fichiers journaux d'audit basé sur l'horodatage encodé dans leur nom.

--audit-log-maxbackup=0 Le nombre maximum d'anciens fichiers journaux d'audit à conserver. Définir une valeur de 0 signifie qu'il n'y a aucune restriction sur le nombre de fichiers.

--audit-log-maxsize=0 La taille maximale en mégaoctets du fichier journal d'audit avant qu'il ne soit roté.

--audit-log-mode="blocking" Stratégie d'envoi des événements d'audit. Blocking indique que l'envoi des événements doit bloquer les réponses du serveur. Batch fait en sorte que le backend mette en mémoire tampon et écrive les événements de manière asynchrone. Modes connus : batch,blocking,blocking-strict.

--audit-log-path="" Si défini, toutes les requêtes arrivant à l'apiserver seront enregistrées dans ce fichier. '-' signifie la sortie standard.

--audit-log-truncate-enabled=false Indique si la troncature des événements et des lots est activée.

--audit-log-truncate-max-batch-size=10485760 Taille maximale du lot envoyé au backend sous-jacent. La taille sérialisée réelle peut être de plusieurs centaines d'octets supérieure. Si un lot dépasse cette limite, il est divisé en plusieurs lots de taille plus petite.

--audit-log-truncate-max-event-size=102400 Taille maximale de l'événement d'audit envoyé au backend sous-jacent. Si la taille d'un événement est supérieure à ce nombre, la première requête et la réponse sont supprimées, et si cela ne réduit pas suffisamment la taille, l'événement est rejeté.

--audit-log-version="audit.k8s.io/v1" Groupe et version API utilisés pour sérialiser les événements d'audit écrits dans le journal.

--audit-policy-file="" Chemin d'accès au fichier qui définit la configuration de la politique d'audit.

--audit-webhook-batch-buffer-size=10000 La taille du tampon pour stocker les événements avant le traitement par lots et l'écriture. Uniquement utilisé en mode lot.

--audit-webhook-batch-initial-backoff=10s Le temps d'attente avant de réessayer la première requête échouée.

--audit-webhook-batch-max-size=400 La taille maximale d'un lot. Uniquement utilisé en mode lot.

--audit-webhook-batch-max-wait=30s Le temps d'attente avant d'écrire de force le lot qui n'a pas atteint la taille maximale. Uniquement utilisé en mode lot.

--audit-webhook-batch-throttle-burst=15 Nombre maximal de requêtes envoyées en même temps si ThrottleQPS n'a pas été utilisé auparavant. Uniquement utilisé en mode lot.

--audit-webhook-batch-throttle-enable=true Indique si le limitation par lots est activée. Uniquement utilisé en mode lot.

--audit-webhook-batch-throttle-qps=10 Nombre moyen maximal de lots par seconde. Uniquement utilisé en mode lot.

--audit-webhook-config-file="" Chemin d'accès à un fichier formaté kubeconfig qui définit la configuration du webhook d'audit.

--audit-webhook-initial-backoff=10s Le temps d'attente avant de réessayer la première requête échouée.

--audit-webhook-mode="batch" Stratégie d'envoi des événements d'audit. Blocking indique que l'envoi des événements doit bloquer les réponses du serveur. Batch fait en sorte que le backend mette en mémoire tampon et écrive les événements de manière asynchrone. Modes connus : batch,blocking,blocking-strict.

--audit-webhook-truncate-enabled=false Indique si la troncature des événements et des lots est activée.

--audit-webhook-truncate-max-batch-size=10485760 Taille maximale du lot envoyé au backend sous-jacent. La taille sérialisée réelle peut être de plusieurs centaines d'octets supérieure. Si un lot dépasse cette limite, il est divisé en plusieurs lots de taille plus petite.

--audit-webhook-truncate-max-event-size=102400 Taille maximale de l'événement d'audit envoyé au backend sous-jacent. Si la taille d'un événement est supérieure à ce nombre, la première requête et la réponse sont supprimées, et si cela ne réduit pas suffisamment la taille, l'événement est rejeté.

--audit-webhook-version="audit.k8s.io/v1" Groupe et version API utilisés pour sérialiser les événements d'audit.

NAME

kube-apiserver - The Kubernetes API server

SYNOPSIS

kube-apiserver [OPTIONS]

DESCRIPTION

The Kubernetes API server (kube-apiserver) is the front end for the Kubernetes control plane. It exposes the Kubernetes API.

The API server is the component of the Kubernetes control plane that exposes the Kubernetes API. We recommend that you interact with the API server only through client libraries, controllers, and dashboards, rather than directly interacting with the API server.

A cluster has one or more instances of the API server running behind a load balancer, to accommodate cluster scale and high availability.

--watch-cache-sizes=[] Watch cache size settings for some resources (pods, nodes, etc.), comma separated. The individual setting format: resource[.group]#size, where resource is lowercase plural (no version), group is omitted for resources of apiVersion v1 (the legacy core API) and included for others, and size is a number. This option is only meaningful for resources built into the apiserver, not ones defined by CRDs or aggregated from external servers, and is only consulted if the watch-cache is enabled. The only meaningful size setting to supply here is zero, which means to disable watch caching for the associated resource; all non-zero values are equivalent and mean to not disable watch caching for that resource
