NOM

kubectl scale - Définir une nouvelle taille pour un déploiement, un ensemble de réplicas ou un contrôleur de réplication

SYNOPSIS

kubectl scale [OPTIONS]

DESCRIPTION

Définit une nouvelle taille pour un déploiement, un ensemble de réplicas, un contrôleur de réplication ou un ensemble d'état.

Scale permet également aux utilisateurs de spécifier une ou plusieurs préconditions pour l'action de mise à l'échelle.

Si --current-replicas ou --resource-version est spécifié, il est validé avant que la mise à l'échelle ne soit tentée, et il est garanti que la précondition est remplie lorsque la mise à l'échelle est envoyée au serveur.

OPTIONS

--all=false Sélectionne toutes les ressources dans l'espace de noms des types de ressources spécifiés

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de mappage est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--current-replicas=-1 Condition préalable pour la taille actuelle. Nécessite que la taille actuelle de la ressource corresponde à cette valeur pour pouvoir mettre à l'échelle. -1 (par défaut) pour aucune condition.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est client, imprime seulement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource pour laquelle définir une nouvelle taille

-k, --kustomize="" Traite le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini à false, n'enregistre pas la commande. Si défini à true, enregistre la commande. Si non défini, met à jour la valeur de l'annotation existante seulement si elle existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--replicas=0 Le nouveau nombre souhaité de réplicas. Requis.

--resource-version="" Condition préalable pour la version de la ressource. Nécessite que la version actuelle de la ressource corresponde à cette valeur pour pouvoir mettre à l'échelle.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'. (par ex. -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=0s La durée d'attente avant d'abandonner une opération de mise à l'échelle, zéro signifie ne pas attendre. Toutes les autres valeurs doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h).

OPTIONS HERITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version affichée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Mettre à l'échelle un ensemble de réplicas nommé 'foo' à 3
  kubectl scale --replicas=3 rs/foo
  # Mettre à l'échelle une ressource identifiée par le type et le nom spécifiés dans "foo.yaml" à 3
  kubectl scale --replicas=3 -f foo.yaml
  # Si la taille actuelle du déploiement nommé mysql est de 2, mettre à l'échelle mysql à 3
  kubectl scale --current-replicas=2 --replicas=3 deployment/mysql
  # Mettre à l'échelle plusieurs contrôleurs de réplication
  kubectl scale --replicas=5 rc/example1 rc/example2 rc/example3
  # Mettre à l'échelle l'ensemble d'état nommé 'web' à 3
  kubectl scale --replicas=3 statefulset/web

NAME

kubectl-scale - Set the number of replicas for a resource.

SYNOPSIS

Scale a resource to N instances.

kubectl scale [--resource-names="RESOURCE_NAME,REPLICA_SET_NAME"] --replicas=REPLICAS (<replication-controller">|<deployment">|<replica-set">|<stateful-set">) [-l <selector>] [options]

DESCRIPTION

The scale sub-command allows you to adjust the number of replicas for a given resource. This command is useful for manually scaling applications up or down, or for setting an initial number of replicas for a new deployment.

You can specify the resource you want to scale using its name or a label selector.

The command supports scaling the following resource types:

  • ReplicationController
  • Deployment
  • ReplicaSet
  • StatefulSet

OPTIONS

--replicas=REPLICAS

The desired number of replicas. This is a required flag.

--resource-names=RESOURCE_NAME,REPLICA_SET_NAME

Comma-separated list of resource names to scale. If not specified, the command will attempt to scale resources matching the provided selector.

-l, --selector <selector>

Selector (label query) to filter on, supports '=', '==', and '!='.(e.g. -l key1=value1,key2=value2). Matching resources will be scaled.

OPTIONS INHERITED FROM PARENT COMMANDS

--all-namespaces

If present, scale of all namespaces will be considered. Otherwise only the current namespace resource will be considered.

--allow-missing-template-keys

If true, ignore any errors in templates when a field or map key is missing. By default it fails.

--context

The name of the kubeconfig context to use

--kubeconfig

Path to the kubeconfig file. Required if you are not running inside a cluster. Defaults to $HOME/.kube/config

--match-expressions

A spec selection expression: each expression spec is a comma-separated list of required values or ranges for a label.

--match-labels

A spec selection expression between label key and label values.

-n, --namespace

If present, the namespace scope for this CLI request

--password

Password for basic authentication to the API server

--request-timeout='0s'

The length of time to wait before giving up on a single server request. Non-zero requests should be a duration in seconds with optional fraction (e.g. 30s, 0.5s) or a unit like B, G, M, K (e.g. 200 B, 1 GiB); some units are memory (B, M, G) and some are duration (s, m, h).

--server

The address and port for the Kubernetes API server

--tls-server-name

Server name for certificate verification

--token

Bearer token for authentication to the API server

--user

Name of the dashboard user account to use for this CLI request

--username

Username for basic authentication to the API server

--version

Print version information and quit

EXAMPLE

Scale a deployment named 'my-deployment' to 5 replicas:

kubectl scale --replicas=5 deployment/my-deployment

Scale a replication controller named 'my-rc' to 3 replicas:

kubectl scale --replicas=3 replicationcontroller/my-rc

Scale a replica set named 'my-rs' to 2 replicas:

kubectl scale --replicas=2 replicaset/my-rs

Scale a stateful set named 'my-sts' to 4 replicas:

kubectl scale --replicas=4 statefulset/my-sts

Scale all deployments with the label 'app=myapp' to 3 replicas:

kubectl scale --replicas=3 deployment --selector=app=myapp

Scale deployments named 'frontend' and 'backend' to 2 replicas:

kubectl scale --replicas=2 --resource-names=frontend,backend deployment
