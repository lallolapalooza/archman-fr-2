Nom

kitten-@-ls - Lister les onglets/fenêtres

Utilisation

kitten @ ls

Description

Liste les fenêtres. La liste est retournée sous forme d'arbre JSON. Le niveau supérieur est une liste de fenêtres kitty du système d'exploitation. Chaque fenêtre OS a un id et une liste d'onglets. Chaque onglet a son propre id, un titre et une liste de fenêtres. Chaque fenêtre a un id, un titre, le répertoire de travail courant, l'id du processus (PID), la ligne de commande et l'environnement du processus en cours d'exécution dans la fenêtre. De plus, lorsque la commande est exécutée à l'intérieur d'une fenêtre kitty, cette fenêtre peut être identifiée par le paramètre is_self.

Vous pouvez utiliser ces critères pour sélectionner des fenêtres/onglets pour les autres commandes.

Vous pouvez limiter les fenêtres/onglets dans la sortie en utilisant les options --match et --match-tab.

Options

--all-env-vars [=non]
Afficher toutes les variables d'environnement dans la sortie, pas seulement celles qui diffèrent.
--self [=non]
Ne lister que la fenêtre dans laquelle cette commande est exécutée.
--output-format [=json]
Sortie au format JSON ou format de session kitty

Choix : json, session

--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un de : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all fait correspondre toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id correspondent à partir du nombre d'id le plus élevé vers le bas, en particulier, -1 est la fenêtre la plus récemment créée.

Le champ num fait référence à la position de la fenêtre dans l'onglet courant, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'id de fenêtre de la fenêtre courante est disponible via la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actif, zéro étant la fenêtre active, un la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session, . pour faire correspondre la session active courante et ~ pour faire correspondre soit la session active courante, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme pour le champ env.

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée (focused) et c'est la fenêtre à laquelle les événements du clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est mise en correspondance. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre OS focalisée courante. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre située sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste de fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un de : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all fait correspondre tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du nombre d'id le plus élevé vers le bas, en particulier, -1 est l'onglet/la fenêtre créé le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le nombre d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre OS active courante. Le nombre recent correspond aux onglets récemment actifs dans la fenêtre OS active courante, zéro étant l'onglet actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session, . pour faire correspondre la session active courante et ~ pour faire correspondre soit la session active courante, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant n'importe quelle fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre OS parente. Il n'y a qu'un seul onglet focalisé (focused) et c'est l'onglet auquel les événements du clavier sont délivrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets de la fenêtre OS focalisée courante.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste d'onglets.

--help, -h [=non]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse de l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela demandera à kitty la permission à l'utilisateur d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs à la fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWO
