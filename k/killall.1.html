DESCRIPTIO

N

killall envoie un signal à tous les processus exécutant l'une des commandes spécifiées. Si aucun nom de signal n'est spécifié, SIGTERM est

envoyé.

Les signaux peuvent être spécifiés soit par nom (par ex. -HUP ou -SIGHUP), soit par numéro (par ex. -1), soit par l'option -s

.

Si le nom de commande n'est pas une expression rationnelle (option -r) et contient une barre oblique (/), les processus exécutant ce fichier particulier seront sélectionnés pour être tués, indépendamment de leur

nom.

killall renvoie un code de retour nul si au moins un processus a été tué pour chaque commande listée, ou si aucune commande n'a été listée et si au moins un processus correspond aux critères de recherche -u et -Z. killall renvoie un code non nul dans le cas

contraire.

Un processus killall ne se tue jamais lui-même (mais peut tuer d'autres processus

    killall(1)

    NAME

    killall - kill processes by name

    SYNOPSIS

    killall [-Z] [-eiqvwlsW] [-o graceperiod] [-p pidfile] [-u user] [-z zone] name...

    DESCRIPTION

    killall sends a signal to processes specified by their name. It is not the same as kill, which requires a process ID. The program killall will read the entire list of processes, and for each process it decides whether the process should be killed or not.

    By default, killall sends the SIGTERM signal. This signal can be caught, so that processes can shut down gracefully. If a process doesn't shut down, killall can be used to send the SIGKILL signal.

    When using killall, care must be taken. The name matching is done on the command line, not on the process name shown by ps. This means that running killall for a program which has arguments will kill all processes that have the name of the program in their command line. For example, killall vim will kill all processes where the command line contains "vim", which might be more than you wanted.

    There are some programs that have the same name, but are different. For example, sleep is a program, and sleep is also a shell builtin. On some systems, killall sends the signal to the shell builtin, and not to the program.

    OPTIONS

    -Z

    Allow killing processes that have an SELinux security context. Normally, killall will not kill processes that have an SELinux context. This option allows you to kill them.

    -e

    killall must match exactly the name given. This is useful in case the command line of a process is longer than the name of the command.

    -i

    Interactive mode. Ask the user for confirmation before killing each process.

    -q

    Quiet mode. If no processes are killed, do not return a non-zero exit code. This is useful if you want to kill a process that may or may not be running.

    -v

    Verbosity. Report whether the signals were successfully sent.

    -w

    Wait for processes to die. killall will wait for the killed processes to die. It will check once per second to see if the killed processes are still running. This is useful if you want to kill a process and then replace it with a new one. The default timeout is 60 seconds.

    -l

    List all signals.

    -s signal

    Send signal instead of SIGTERM. Signal may be given by name or by number.

    -o graceperiod

    Grace period. Specify the maximum amount of time (in seconds) to wait for processes to die. The default is 60 seconds. This option is only effective when used with the -w option.

    -p pidfile

    Pidfile. Specify a file containing the PIDs of processes to kill. This is useful when you want to kill a process that is started by another process, and you want to ensure that you kill only the intended process.

    -u user

    User. Send signal to processes owned by specified user only.

    -z zone

    Zone. Send signal to processes within specified zone only.

    -W

    Wait for processes to die. Same as -w, but with a timeout of 10 seconds.

    FILES

    /proc

    The process filesystem.

    KNOWN BUGS

    The name matching is done on the command line, not on the process name shown by ps. This means that running killall for a program which has arguments will kill all processes that have the name of the program in their command line.

    There are some programs that have the same name, but are different. For example, sleep is a program, and sleep is also a shell builtin. On some systems, killall sends the signal to the shell builtin, and not to the program.

    kill(1), pkill(1), skill(1)
