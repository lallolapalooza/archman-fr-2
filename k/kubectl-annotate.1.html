NOM

kubectl annotate - Mettre à jour les annotations d'une ressource

SYNTAXE

kubectl annotate [OPTIONS]

DESCRIPTION

Mettre à jour les annotations d'une ou plusieurs ressources.

Tous les objets Kubernetes prennent en charge la possibilité de stocker des données supplémentaires avec l'objet sous forme d'annotations. Les annotations sont des paires clé/valeur qui peuvent être plus grandes que les étiquettes et inclure des valeurs de chaîne arbitraires telles que du JSON structuré. Les outils et les extensions système peuvent utiliser des annotations pour stocker leurs propres données.

Tenter de définir une annotation qui existe déjà échouera à moins que --overwrite ne soit défini. Si --resource-version est spécifié et ne correspond pas à la version de ressource actuelle sur le serveur, la commande échouera.

Utilisez "kubectl api-resources" pour obtenir une liste complète des ressources prises en charge.

OPTIONS

--all=false Sélectionner toutes les ressources, dans l'espace de noms des types de ressources spécifiés.

-A, --all-namespaces=false Si vrai, vérifier l'action spécifiée dans tous les espaces de noms.

--allow-missing-template-keys=true Si vrai, ignorer toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est client, n'imprimer que l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumettre une requête côté serveur sans persister la ressource.

--field-manager="kubectl-annotate" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--field-selector="" Sélecteur (requête de champ) pour filtrer, prend en charge '=', '==', et '!='.(par exemple --field-selector key1=value1,key2=value2). Le serveur ne prend en charge qu'un nombre limité de requêtes de champ par type.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource pour mettre à jour l'annotation

-k, --kustomize="" Traiter le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--list=false Si vrai, afficher les annotations pour une ressource donnée.

--local=false Si vrai, l'annotation ne contactera PAS l'api-server mais s'exécutera localement.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=false Si vrai, autoriser la réécriture des annotations, sinon rejeter les mises à jour d'annotations qui écrasent les annotations existantes.

--record=false Enregistrer la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, par défaut à la mise à jour de la valeur d'annotation existante uniquement si une existe déjà.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--resource-version="" Si non vide, la mise à jour de l'annotation ne réussira que si c'est la resource-version actuelle de l'objet. Valide uniquement lors de la spécification d'une seule ressource.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'. (par exemple -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--show-managed-fields=false Si vrai, conserver les champs gérés lors de l'impression d'objets aux formats JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est un modèle golang [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS INHERITÉE DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas chronométrer les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et sortir avec un code de sortie non nul

EXEMPLE

  # Mettre à jour le pod 'foo' avec l'annotation 'description' et la valeur 'mon frontend'
  # Si la même annotation est définie plusieurs fois, seule la dernière valeur sera appliquée
  kubectl annotate pods foo description='mon frontend'
  # Mettre à jour un pod identifié par type et nom dans "pod.json"
  kubectl annotate -f pod.json description='mon frontend'
  # Mettre à jour le pod 'foo' avec l'annotation 'description' et la valeur 'mon frontend tournant nginx', en écrasant toute valeur existante
  kubectl annotate --overwrite pods foo description='mon frontend tournant nginx'
  # Mettre à jour tous les pods de l'espace de noms
  kubectl annotate pods --all description='mon frontend tournant nginx'
  # Mettre à jour le pod 'foo' uniquement si la ressource est inchangée par rapport à la version 1
  kubectl annotate pods foo description='mon frontend tournant nginx' --resource-version=1
  # Mettre à jour le pod 'foo' en supprimant une annotation nommée 'description' si elle existe
  # Ne nécessite pas le drapeau --overwrite
  kubectl annotate pods foo description-

NOM

kubectl - Outil de ligne de commande pour interagir avec les clusters Kubernetes.

SYNTAXE

kubectl [COMMAND] [TYPE] [NAME | -l label | -f filename] [options]

DESCRIPTION

kubectl permet de déployer des applications, d'inspecter et de gérer des ressources, ainsi que d'afficher des logs.

Il est couramment utilisé pour les opérations suivantes :

  • Créer, mettre à jour et supprimer des ressources Kubernetes.
  • Inspecter l'état des ressources et des nœuds du cluster.
  • Afficher les logs des conteneurs.
  • Exécuter des commandes dans les conteneurs.
  • Gérer les configurations et les secrets.

De nombreuses commandes peuvent être générées automatiquement depuis la documentation.
