NOM

kubeadm init phase addon all - Installer tous les modules complémentaires

SYNTAXE

kubeadm init phase addon all [OPTIONS]

DESCRIPTION

Installer tous les modules complémentaires

OPTIONS

--apiserver-advertise-address="" L'adresse IP sur laquelle l'API Server annoncera son écoute. Si elle n'est pas définie, l'interface réseau par défaut sera utilisée.

--apiserver-bind-port=6443 Port sur lequel l'API Server se connectera.

--config="" Chemin vers un fichier de configuration kubeadm.

--control-plane-endpoint="" Spécifier une adresse IP ou un nom DNS stable pour le plan de contrôle.

--dry-run=false Ne pas appliquer de changements ; afficher seulement ce qui serait fait.

--feature-gates="" Un ensemble de paires clé=valeur décrivant les portails de fonctionnalités pour diverses fonctions. Les options sont : ControlPlaneKubeletLocalMode=true|false (BETA - par défaut=true) NodeLocalCRISocket=true|false (BETA - par défaut=true) PublicKeysECDSA=true|false (OBSOLÈTE - par défaut=false) RootlessControlPlane=true|false (ALPHA - par défaut=false) WaitForAllControlPlaneComponents=true|false (par défaut=true)

--image-repository="registry.k8s.io" Choisir un registre de conteneurs pour télécharger les images du plan de contrôle.

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si l'option n'est pas définie, un ensemble d'emplacements standard peut être recherché pour un fichier kubeconfig existant.

--kubernetes-version="stable-1" Choisir une version Kubernetes spécifique pour le plan de contrôle.

--pod-network-cidr="" Spécifier la plage d'adresses IP pour le réseau des pods. Si elle est définie, le plan de contrôle attribuera automatiquement des CIDR pour chaque nœud.

--service-cidr="10.96.0.0/12" Utiliser une plage alternative d'adresses IP pour les VIP de service.

--service-dns-domain="cluster.local" Utiliser un domaine alternatif pour les services, par exemple "myorg.internal".

OPTIONS HERITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à utiliser chroot dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée.
