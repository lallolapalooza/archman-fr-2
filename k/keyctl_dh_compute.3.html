keyctl_dh_compute(3)

Paquet: keyutils

Licences: GPL2, LGPL2.1

KEYCTL_DH_COMPUTE(3) Appels de gestion de clés Linux KEYCTL_DH_COMPUTE(3)

NOM

keyctl_dh_compute - Calculer une clé publique ou un secret partagé Diffie-Hellman
keyctl_dh_compute_kdf - Dériver une clé à partir d'un secret partagé Diffie-Hellman

SYNTAXE

#include <keyutils.h>

long keyctl_dh_compute(key_serial_t private, key_serial_t prime,
key_serial_t base, char *buffer, size_t buflen);

long keyctl_dh_compute_alloc(key_serial_t private,
key_serial_t prime, key_serial_t base, void **_buffer);

long keyctl_dh_compute_kdf(key_serial_t private, key_serial_t prime,
key_serial_t base, char *hashname, char *otherinfo,
size_t otherinfolen, char *buffer, size_t buflen);

DESCRIPTION

keyctl_dh_compute() calcule une clé publique ou un secret partagé Diffie-Hellman. Ce calcul est :

base ^ private ( mod prime )

Lorsque base est une clé contenant la valeur du générateur partagé, la clé publique distante est calculée. Lorsque base est une clé contenant la clé publique distante, le secret partagé est calculé.

base, private et prime doivent tous faire référence à des clés de type user contenant les paramètres du calcul. Chacune de ces clés doit accorder à l'appelant la permission de lecture pour pouvoir être utilisée.

buffer et buflen spécifient le tampon dans lequel le résultat calculé sera placé. buflen peut être zéro, auquel cas le tampon n'est pas utilisé et la longueur minimale du tampon nécessaire est récupérée.

keyctl_dh_compute_alloc() est similaire à keyctl_dh_compute() sauf qu'elle alloue un tampon suffisamment grand pour contenir les données de charge utile et place les données dedans. En cas de succès, un pointeur vers le tampon est placé dans *_buffer. L'appelant doit libérer le tampon.

keyctl_dh_compute_kdf() dérive une clé d'un secret partagé Diffie-Hellman selon le protocole spécifié dans SP800-56A. Le calcul Diffie-Hellman est basé sur les mêmes primitives que celles discutées pour keyctl_dh_compute().

Pour implémenter le protocole de SP800-56A, base est une clé contenant la clé publique distante pour calculer le secret partagé Diffie-Hellman. Ce secret partagé est post-traité avec une fonction de dérivation de clé.

Le hashname spécifie le nom de l'API cryptographique du noyau Linux pour un hash qui sera utilisé pour la fonction de dérivation de clé, tel que sha256. Le hashname doit être une chaîne terminée par NULL. Voir /proc/crypto pour les hashes disponibles sur le système.

Conformément à la spécification de SP800-56A section 5.8.1.2, le paramètre otherinfo peut être fourni. Le format du champ OtherInfo est défini par l'appelant. L'appelant peut également spécifier NULL comme argument valide lorsqu'aucune donnée OtherInfo ne doit être traitée. La longueur du paramètre otherinfo est spécifiée avec otherinfolen et est limitée à une longueur maximale par le noyau.

Le KDF retourne le nombre d'octets demandé spécifié avec le paramètre genlen ou buflen en fonction de la fonction appelée.

buffer et buflen spécifient le tampon dans lequel le résultat calculé sera placé.

VALEUR DE RETOUR

En cas de succès, keyctl_dh_compute() retourne la quantité de données placée dans le tampon lorsque buflen est non nul. Lorsque buflen est zéro, la longueur minimale du tampon nécessaire pour contenir les données est retournée.

En cas de succès, keyctl_dh_compute_alloc() retourne la quantité de données dans le tampon.

En cas d'erreur, les deux fonctions définissent errno à un code approprié et retournent la valeur -1.

ERREURS

ENOKEY
Une des clés spécifiées est invalide ou non lisible.
EINVAL
Le pointeur du tampon est invalide ou buflen est trop petit.
EOPNOTSUPP
Une des clés n'était pas une clé utilisateur valide.
EMSGSIZE
Lors de l'utilisation de keyctl_dh_compute_kdf(), la taille de otherinfolen ou buflen est trop grande.

LIAISON

Ceci est une fonction de bibliothèque que l'on peut trouver dans libkeyutils. Lors de la liaison, -lkeyutils doit être spécifié au lieur.
