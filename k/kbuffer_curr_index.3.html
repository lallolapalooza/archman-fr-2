NAME

kbuffer_read_event, kbuffer_next_event, kbuffer_missed_events, kbuffer_event_size, kbuffer_curr_size, kbuffer_curr_offset, kbuffer_curr_index, kbuffer_read_buffer - Fonctions pour parcourir le sous-tampon kbuffer.

SYNOPSIS

#include <kbuffer.h>
void *kbuffer_read_event(struct kbuffer *kbuf, unsigned long long *ts);
void *kbuffer_next_event(struct kbuffer *kbuf, unsigned long long *ts);
void *kbuffer_read_at_offset(struct kbuffer *kbuf, int offset, unsigned long long *ts);
int kbuffer_missed_events(struct kbuffer *kbuf);
int kbuffer_event_size(struct kbuffer *kbuf);
int kbuffer_curr_size(struct kbuffer *kbuf);
int kbuffer_curr_offset(struct kbuffer *kbuf);
int kbuffer_curr_index(struct kbuffer *kbuf);
int kbuffer_read_buffer(struct kbuffer *kbuf, void *buffer, int len);

DESCRIPTION

La fonction kbuffer_read_event() lit l'événement suivant dans le descripteur kbuf et si ts n'est pas NULL, y placera son horodatage. Cela ne modifie pas le descripteur kbuf, et appeler cette fonction plusieurs fois retournera le même résultat.

La fonction kbuffer_next_event() retournera l'événement suivant dans le descripteur kbuf. Elle définira également ts à l'horodatage de l'événement retourné. NULL est retourné s'il n'y a plus d'événements et que ts sera indéfini. Notez que si cette fonction est appelée directement après un kbuffer_load_subbuffer(), elle donnera probablement un résultat inattendu, car elle retournera le deuxième événement et non le premier. Généralement, cette fonction est seulement utilisée pour passer à l'événement suivant et savoir s'il y a d'autres événements à lire, et kbuffer_read_event() est toujours appelée en premier.

La fonction kbuffer_read_at_offset() retourne l'événement situé à un offset donné depuis le début du sous-tampon. Cet offset peut être récupéré par kbuffer_curr_offset(). Si ts pointe vers un unsigned long long, il sera alors défini à l'horodatage de l'événement à l'offset donné.

Si le sous-tampon a manqué des événements avant lui, alors kbuffer_missed_events() retournera une valeur non nulle. Si elle retourne -1, cela signifie qu'il y a eu des événements manqués, mais que le nombre exact d'événements manqués est inconnu. Si elle retourne un nombre positif, alors le nombre d'événements manqués est la valeur de retour.

La fonction kbuffer_event_size() retourne la taille de la partie données de l'événement actuel (celui qui serait retourné par kbuffer_read_event().

La fonction kbuffer_curr_size() retourne la taille totale de l'enregistrement de l'événement actuel (celui qui serait retourné par kbuffer_read_event(). La différence ici est que la valeur de retour inclut la taille des métadonnées de l'enregistrement de l'événement qui ne font pas partie de ce qui est retourné par kbuffer_read_event().

La fonction kbuffer_curr_offset() retourne l'offset depuis le début du sous-tampon où les métadonnées de l'enregistrement de l'événement actuel commencent. Le premier événement ne sera pas à l'offset zéro. Cet offset peut être utilisé pour récupérer l'événement avec kbuffer_read_at_offset().

La fonction kbuffer_curr_index() retourne l'index depuis le début de la partie données du sous-tampon où se trouvent les métadonnées de l'événement actuel. Le premier événement sera probablement zéro, mais il peut ne pas l'être s'il y a un horodatage qui lui est attaché.

La fonction kbuffer_read_buffer() remplira le buffer donné à partir du kbuf de la même manière que le noyau effectuerait un appel système de lecture. C'est-à-dire que si la longueur len est inférieure à la taille du sous-tampon, ou si l'index actuel du kbuffer est non nul, elle commencera à copier à partir de l'événement actuel du kbuf et créera le buffer comme un nouveau sous-tampon (avec un horodatage et un en-tête de commit) avec l'événement trouvé et incluant tous les événements suivants qui peuvent tenir dans len. Le len doit inclure la taille de l'en-tête du sous-tampon ainsi que les événements à inclure. C'est-à-dire que len est la taille allouée de buffer qui peut être remplie. Le retour de cette fonction est l'index de fin du dernier événement ajouté. S'il n'y a plus d'événements, zéro est retourné, et si le tampon ne peut copier aucun événement car len était trop petit, -1 est retourné.

VALEUR DE RETOUR

kbuffer_read_event() retourne l'événement auquel le descripteur kbuf est actuellement positionné, ou NULL si le dernier événement a été dépassé (par kbuffer_next_event()).

kbuffer_next_event() retourne l'événement suivant après l'événement actuel ou NULL s'il n'y a plus d'événements.

kbuffer_read_at_offset() retourne l'événement à un offset donné depuis le début du sous-tampon stocké dans kbuf, ou NULL s'il n'existe aucun événement. Notez que offset n'a besoin d'être qu'un offset qui tombe sur l'enregistrement, ou est à son début. Il n'a pas besoin d'être exactement au début de l'enregistrement.

kbuffer_missed_events() retourne 0 s'il n'y a pas eu d'événements manqués avant le chargement du sous-tampon. Retourne -1 s'il y a eu un nombre inconnu d'événements manqués, ou si le nombre d'événements manqués est connu, ce nombre sera retourné.

kbuffer_event_size() retourne la taille de la charge utile de données de l'événement actuel de kbuf.

kbuffer_curr_size() retourne la taille totale de l'enregistrement de l'événement actuel de kbuf. Cela inclut la taille des métadonnées pour cet enregistrement.

kbuf_curr_offset() retourne l'offset de l'enregistrement actuel depuis le début du sous-tampon kbuf.

kbuf_curr_index() retourne l'index de l'enregistrement actuel depuis le début de la section de données kbuf.

kbuf_read_buffer() retourne l'index de fin du dernier événement qui a été rempli dans buffer. S'il n'y a plus d'événements à copier depuis start, alors 0 est retourné. Si len n'est pas assez grand pour contenir des événements, alors -1 est retourné.

DESCRIPTION

These functions provide an interface to read and navigate through trace event data stored in a kernel buffer (kbuf).

kbuffer_curr_index()
Returns the current index of the event being pointed to within the buffer.
kbuffer_curr_offset()
Returns the current offset of the event being pointed to within the buffer.
kbuffer_curr_size()
Returns the size of the current event record.
kbuffer_event_size()
Returns the size of the event data itself, excluding metadata.
kbuffer_next_event()
Advances the buffer pointer to the next event and returns a pointer to the event data. If `ts` is not NULL, it will be populated with the timestamp of the event. Returns NULL if there are no more events.
kbuffer_read_at_offset()
Reads an event from the specified `offset` within the buffer. If `ts` is not NULL, it will be populated with the timestamp of the event. Returns a pointer to the event data, or NULL if the offset is invalid or an error occurs.

RETURN VALUE

Refer to the descriptions of individual functions above.

EXAMPLE

The following example demonstrates how to iterate through events in a kbuffer, print their details, and then reread a specific event by its offset.

#include <stdio.h>
#include <stdlib.h>
#include <traceevent/kbuffer.h>

int main(void) {
    struct kbuffer *kbuf;
    void *event;
    int ts;
    int record_size, size, index, offset;
    int save_offset = 0;
    int i = 0;

    // Assume kbuf is initialized and populated with data elsewhere
    // For demonstration purposes, let's pretend we have a kbuf
    // In a real scenario, you would get kbuf from trace event library functions
    kbuf = calloc(1, sizeof(struct kbuffer)); // Placeholder, needs proper initialization

    // Simulate reading events
    do {
        event = kbuffer_next_event(kbuf, &ts);
        if (event) {
            record_size = kbuffer_curr_size(kbuf);
            offset = kbuffer_curr_offset(kbuf);
            index = kbuffer_curr_index(kbuf);
            size = kbuffer_event_size(kbuf);

            // Save the offset of the 20th event (or earlier if fewer events)
            if (i == 19) {
                save_offset = offset;
            }

            printf(" event %3d ts:%lld\trecord_size:%d size:%d\tindex:%d offset:%d\n",
                   i++, ts, record_size, size, index, offset);
        }
    } while (event);

    if (!event) {
        printf("Finished sub buffer\n");
    }

    // Reread the saved event if an offset was stored
    if (save_offset > 0) {
        event = kbuffer_read_at_offset(kbuf, save_offset, &ts);
        if (!event) {
            fprintf(stderr, "Funny, can't find event at offset %d\n", save_offset);
            exit(-1);
        }
        record_size = kbuffer_curr_size(kbuf);
        offset = kbuffer_curr_offset(kbuf);
        index = kbuffer_curr_index(kbuf);
        size = kbuffer_event_size(kbuf);
        printf("\n saved event ts:%lld\trecord_size:%d size:%d\tindex:%d offset:%d\n\n",
               ts, record_size, size, index, offset);
    }

    kbuffer_free(kbuf); // Placeholder, needs proper deallocation
    return 0;
}
