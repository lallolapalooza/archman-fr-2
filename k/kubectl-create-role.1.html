kubectl-create-role(1)

Paquet: kubectl

Licences: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOM

kubectl create role - Créer un rôle avec une seule règle

SYNOPIS

kubectl create role [OPTIONS]

DESCRIPTION

Crée un rôle avec une seule règle.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de mappe est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est "client", imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est "server", soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--resource=[] Ressource à laquelle la règle s'applique

--resource-name=[] Ressource dans la liste blanche à laquelle la règle s'applique, répéter ce drapeau pour plusieurs éléments

--save-config=false Si vrai, la configuration de l'objet courant sera sauvegardée dans son annotation. Sinon, l'annotation restera inchangée. Ce drapeau est utile lorsque vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un des : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur l'api-server, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

--verb=[] Verbe qui s'applique aux ressources contenues dans la règle

OPTIONS INHERITées DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la feature gate KUBECTL_KUBERC=false ou en désactivant la feature KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée du namespace pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas dépasser le temps imparti pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification (Bearer token) pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et sortir avec un code de sortie non nul

EXEMPLE

  # Créer un rôle nommé "pod-reader" qui permet à l'utilisateur d'effectuer des opérations "get", "watch" et "list" sur les pods
  kubectl create role pod-reader --verb=get --verb=list --verb=watch --resource=pods
  # Créer un rôle nommé "pod-reader" avec ResourceName spécifié
  kubectl create role pod-reader --verb=get --resource=pods --resource-name=readablepod --resource-name=anotherpod
  # Créer un rôle nommé "foo" avec API Group spécifié
  kubectl create role foo --verb=get,list,watch --resource=rs.apps
  # Créer un rôle nommé "foo" avec Sous-Ressource spécifiée
  kubectl create role foo --verb=get,list,watch --resource=pods,pods/status
