keyctl_instantiate(3)

Paquet: keyutils

Licences: GPL2, LGPL2.1

KEYCTL_INSTANTIATE(3) Appels de gestion de clés Linux KEYCTL_INSTANTIATE(3)

NOM

keyctl_assume_authority, keyctl_instantiate, keyctl_instantiate_iov, keyctl_reject, keyctl_negate - fonctions d'instanciation de clé

SYNTAXE

#include <keyutils.h>

long keyctl_assume_authority(key_serial_t key);

long keyctl_instantiate(key_serial_t key, const void *payload,
size_t plen, key_serial_t keyring);

long keyctl_instantiate_iov(key_serial_t key,
const struct iovec *payload_iov, unsigned ioc,
key_serial_t keyring);

long keyctl_negate(key_serial_t key, unsigned timeout,
key_serial_t keyring);

long keyctl_reject(key_serial_t key, unsigned timeout,
unsigned error, key_serial_t keyring);

DESCRIPTION

keyctl_assume_authority() prend l'autorité pour que le thread appelant puisse traiter et instancier la key non instanciée spécifiée.

Le thread appelant doit posséder la clé d'autorisation appropriée résidente dans l'un de ses porte-clés pour que cela réussisse, et cette autorisation ne doit pas avoir été révoquée.

La clé autorisant est allouée par request_key() lorsqu'elle a besoin d'invoquer l'espace utilisateur pour générer une clé pour le processus demandeur. Celle-ci est ensuite attachée à l'un des porte-clés du processus d'espace utilisateur auquel est confiée la tâche d'instanciation de la clé :

demandeur -> request_key() -> instanciateur

L'appel de cette fonction modifie la manière dont request_key() fonctionne lorsqu'il est appelé par la suite par le thread appelant (instanciateur) ; une fois l'autorité prise, les porte-clés du processus initial sont ajoutés au chemin de recherche, en utilisant l'UID, le GID, les groupes et le contexte de sécurité du processus initial.

Si un thread a plusieurs instanciations à traiter, il peut appeler cette fonction pour changer la clé d'autorisation actuellement en vigueur. La fourniture d'une clé zéro désassumera l'autorité actuellement assumée.

NOTE ! Il s'agit d'un réglage par thread et non par processus, de sorte qu'un processus multithread peut être utilisé pour instancier plusieurs clés simultanément.

keyctl_instantiate() instancie la charge utile d'une clé non instanciée à partir des données spécifiées. payload et plen spécifient les données pour la nouvelle charge utile. payload peut être NULL et plen peut être zéro si le type de clé le permet. Le type de clé peut rejeter les données si elles sont dans le mauvais format ou d'une manière invalide.

keyctl_instantiate_iov() est similaire, mais les données sont passées dans un tableau de structures iovec au lieu d'un tampon plat. payload_iov pointe vers la base du tableau et ioc indique le nombre d'éléments. payload_iov peut être NULL ou ioc peut être zéro pour indiquer qu'aucune donnée n'est fournie.

keyctl_reject() marque une clé comme étant instanciée négativement et définit son minuteur d'expiration. timeout spécifie la durée de vie de la clé en secondes. error spécifie l'erreur à retourner lorsqu'une recherche rencontre la clé (il s'agit généralement de EKEYREJECTED, EKEYREVOKED ou EKEYEXPIRED). Notez que keyctl_reject() se rabat sur keyctl_negate() si le noyau ne le prend pas en charge.

keyctl_negate() est identique à keyctl_reject() avec un code d'erreur de ENOKEY.

Seule une clé pour laquelle l'autorité a été assumée peut être instanciée ou instanciée négativement, et une fois instanciée, la clé d'autorisation sera révoquée et le processus demandeur pourra reprendre.

Le keyring de destination, s'il est fourni, est supposé appartenir au demandeur initial, et non au processus instanciateur. Par conséquent, les identifiants spéciaux de keyring font référence aux porte-clés du processus demandeur, et non à ceux de l'appelant, et l'UID, etc. du demandeur seront utilisés pour y accéder.

Le porte-clés de destination peut être zéro si aucun lien supplémentaire n'est souhaité.

Le demandeur, et non l'appelant, doit avoir l'autorisation d'écriture sur la destination pour qu'un lien y soit créé.

VALEUR REGROUPÉE

En cas de succès, keyctl_instantiate() retourne 0. En cas d'erreur, la valeur -1 sera retournée et errno aura été défini à une erreur appropriée.

ERREURS

ENOKEY
La clé ou le keyring spécifié est invalide.
EKEYEXPIRED
Le keyring spécifié a expiré.
EKEYREVOKED
La clé ou le keyring spécifié a été révoqué, ou l'autorisation a été révoquée.
EINVAL
Les données de la charge utile étaient invalides.
ENOMEM
Mémoire insuffisante pour stocker la nouvelle charge utile ou pour étendre le keyring de destination.
EDQUOT
Le quota de clé de l'utilisateur de la clé serait dépassé en augmentant la taille de la clé pour accueillir la nouvelle charge utile, ou le quota de clé de l'utilisateur du keyring serait dépassé en étendant le keyring de destination.
EACCES
La clé existe, mais n'est pas écrivable par le demandeur.

LIEN

Ceci est une fonction de bibliothèque qui se trouve dans libkeyutils. Lors de la liaison, -lkeyutils doit être spécifié au lieur.
