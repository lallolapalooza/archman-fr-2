NOM

kubectl taint - Mettre à jour les contaminations (taints) sur un ou plusieurs nœuds

SYNTAXE

kubectl taint [OPTIONS]

DESCRIPTION

Mettre à jour les contaminations (taints) sur un ou plusieurs nœuds.

  • Une contamination se compose d'une clé, d'une valeur et d'un effet. En tant qu'argument ici, elle est exprimée sous la forme clé=valeur:effet.
  • La clé doit commencer par une lettre ou un chiffre, et peut contenir des lettres, des chiffres, des traits d'union, des points et des underscores, jusqu'à 253 caractères.
  • Optionnellement, la clé peut commencer par un préfixe de sous-domaine DNS et un seul '/', comme exemple.com/mon-app.
  • La valeur est optionnelle. Si elle est fournie, elle doit commencer par une lettre ou un chiffre, et peut contenir des lettres, des chiffres, des traits d'union, des points et des underscores, jusqu'à 63 caractères.
  • L'effet doit être NoSchedule, PreferNoSchedule ou NoExecute.
  • Actuellement, la contamination ne peut s'appliquer qu'à un nœud.

OPTIONS

--all=false Sélectionner tous les nœuds du cluster

--allow-missing-template-keys=true Si vrai, ignorer toutes les erreurs dans les modèles lorsqu'un champ ou une clé de map est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est client, afficher uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumettre une requête côté serveur sans persister la ressource.

--field-manager="kubectl-taint" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=false Si vrai, permettre la réécriture des contaminations, sinon rejeter les mises à jour de contaminations qui écrasent des contaminations existantes.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, supporte '=', '==', '!=', 'in', 'notin'. (ex: -l clé1=valeur1,clé2=valeur2,clé3 in (valeur3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--show-managed-fields=false Si vrai, conserver les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un des suivants : strict (ou true), warn, ignore (ou false). "true" ou "strict" utiliseront un schéma pour valider l'entrée et échouer la requête si elle est invalide. Cela effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le serveur d'API, mais se rabattra sur une validation côté client moins fiable s'il ne l'est pas. "warn" avertira sur les champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur d'API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectueront aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

EXEMPLE

  # Mettre à jour le nœud 'foo' avec une contamination ayant la clé 'dedicated', la valeur 'special-user' et l'effet 'NoSchedule'
  # Si une contamination avec cette clé et cet effet existe déjà, sa valeur est remplacée comme spécifié
  kubectl taint nodes foo dedicated=special-user:NoSchedule
  # Supprimer du nœud 'foo' la contamination ayant la clé 'dedicated' et l'effet 'NoSchedule' si elle existe
  kubectl taint nodes foo dedicated:NoSchedule-
  # Supprimer du nœud 'foo' toutes les contaminations ayant la clé 'dedicated'
  kubectl taint nodes foo dedicated-
  # Ajouter une contamination avec la clé 'dedicated' sur les nœuds ayant l'étiquette myLabel=X
  kubectl taint node -l myLabel=X  dedicated=foo:PreferNoSchedule
  # Ajouter au nœud 'foo' une contamination avec la clé 'bar' et sans valeur
  kubectl taint nodes foo bar:NoSchedule

NOM

kubectl-taint - Supprimer ou ajouter destaints aux nœuds.

SYNTAXE

kubectl taint node (NODE_NAME ... NODE_SELECTOR | -l extended=key=value[,extended=key=value ...]) KEY[=VALUE]

DESCRIPTION

La commande taint permet de supprimer ou d'ajouter destaints aux nœuds. Un taint est une propriété d'un nœud qui, combinée à une tolérance, empêche les pods d'être planifiés sur ce nœud.

La commandetaint prend en entrée une liste de nœuds et un ou plusieurstaints.

Un taint est défini par une paire clef-valeur et un effet. Les effets possibles sont :

  • NoExecute : Les pods qui ne tolèrent pas ce taint ne pourront pas s'être planifiés sur ce nœud et seront terminés s'ils sont déjà en cours d'exécution.
  • PreferNoExecute : Le système essaiera d'éviter de planifier des pods qui ne tolèrent pas ce taint sur ce nœud.
  • NoSchedule : Les pods qui ne tolèrent pas ce taint ne pourront pas s'être planifiés sur ce nœud.

Pour ajouter un taint, vous devez spécifier la clef et la valeur du taint, ainsi que l'effet. Par exemple : 

kubectl taint nodes mynode key=value:NoSchedule

Pour supprimer un taint, vous devez spécifier la clef du taint et l'effet. La valeur n'est pas nécessaire. Par exemple : 

kubectl taint nodes mynode key:NoSchedule-

OPTIONS

-l, --selector string
Selector de nœuds pour s'appliquer aux nœuds correspondants.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--all, --selector string
Sélectionne tous les nœuds.
--allow-missing-template-keys=true
Si le réglage est défini sur true, les erreurs liées aux clés de modèle manquantes seront ignorées. Sinon, les erreurs liées aux clés de modèle manquantes provoqueront une erreur.
--context string
Le nom du contexte à utiliser dans le fichier kubeconfig.
--dry-run=strategy
Indique si les opérations doivent être simulées. Les valeurs valides sont "none". "server", et "client".
--field-manager string
Nom du gestionnaire de champs pour le retour à l'état précédent.
--kubeconfig string
Chemin d'accès au fichier kubeconfig.
--match-expressions stringArray
Un ensemble d'étiquettes qui doivent correspondre aux nœuds.
--match-labels stringArray
Une liste d'étiquettes à faire correspondre.
--record
Enregistrer cette opération dans la révision de l'objet, le cas échéant.
--save-config
Si la simulation est activée, enregistrez les configurations modifiées dans des fichiers locaux au lieu de les imprimer sur la sortie standard.
--show-managed-fields
Si la simulation est activée, affichez les champs gérés.
--trifluoromethyl string
Spécifie le fichier de configuration du noyau.
--validate=image
Indique si les opérations doivent être validées. Les valeurs valides sont "none". "strict".

EXEMPLE

Ajouter un taint `special-scheduler=true:NoSchedule` au nœud `my-node`: 

kubectl taint nodes my-node special-scheduler=true:NoSchedule

Supprimer le taint `special-scheduler=true:NoSchedule` du nœud `my-node`: 

kubectl taint nodes my-node special-scheduler:NoSchedule-

Ajouter un taint `key=value:NoExecute` à tous les nœuds : 

kubectl taint nodes -l all key=value:NoExecute
