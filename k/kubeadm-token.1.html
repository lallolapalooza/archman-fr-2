NOM

kubeadm token - Gérer les jetons d'amorçage

SYNTAXE

kubeadm token [OPTIONS]

DESCRIPTION

Cette commande gère les jetons d'amorçage. Elle est facultative et nécessaire uniquement pour des cas d'utilisation avancés.

En bref, les jetons d'amorçage sont utilisés pour établir une confiance bidirectionnelle entre un client et un serveur. Un jeton d'amorçage peut être utilisé lorsqu'un client (par exemple, un nœud sur le point de rejoindre le cluster) a besoin de faire confiance au serveur auquel il parle. Ensuite, un jeton d'amorçage avec l'utilisation "signature" peut être utilisé. Les jetons d'amorçage peuvent également servir à autoriser une authentification de courte durée auprès du serveur API (le jeton sert de moyen pour le serveur API de faire confiance au client), par exemple pour effectuer l'amorçage TLS.

Qu'est-ce qu'un jeton d'amorçage plus précisément ?
- C'est un Secret dans l'espace de noms kube-system de type "bootstrap.kubernetes.io/token".
- Un jeton d'amorçage doit être de la forme "[a-z0-9]{6}.[a-z0-9]{16}". La première partie est l'identifiant public du jeton,
tandis que la seconde est le jeton Secret et elle doit être gardée privée en toutes circonstances !
- Le nom du Secret doit être nommé "bootstrap-token-(token-id)".

Vous pouvez en savoir plus sur les jetons d'amorçage ici :
https://kubernetes.io/docs/admin/bootstrap-tokens/

OPTIONS

--dry-run=false Activer ou non le mode simulation

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si le drapeau n'est pas défini, un ensemble d'emplacements standard peut être recherché pour trouver un fichier kubeconfig existant.

OPTIONS INHERITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à utiliser chroot sur le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée
