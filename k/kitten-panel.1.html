Nom

kitten-panel - Utiliser un programme en ligne de commande pour dessiner un panneau accéléré par GPU sur votre bureau

Vue d'ensemble

Dessiner le fond d'écran du bureau ou des docks et panneaux en utilisant des programmes de terminal arbitraires. Par exemple, faire de btop https://github.com/aristocratos/btop ou cava https://github.com/karlstav/cava/ votre fond d'écran.

C'est utile pour afficher des informations d'état ou des notifications sur votre bureau en utilisant des programmes de terminal plutôt que des boîtes à outils GUI.

La capture d'écran sur le côté montre quelques utilisations du « panel kitten » pour dessiner divers composants du bureau tels que l'arrière-plan, une fenêtre de terminal flottante à accès rapide et un panneau de dock affichant des informations système (Linux uniquement).

Ajouté dans la version 0.42.0 : Prise en charge de macOS, voir la matrice de compatibilité pour les détails. et X11 (arrière-plan et superposition).

Ajouté dans la version 0.34.0 : Prise en charge de Wayland. Voir ci-dessous pour quels compositeurs Wayland fonctionnent.

Utiliser ce kitten est simple, par exemple :

kitten panel sh -c 'printf "\n\n\nHello, world."; sleep 5s'

Cela affichera Hello, world. en haut de votre écran pendant cinq secondes. Ici, le programme de terminal que nous exécutons est sh avec un script pour imprimer Hello, world!. Vous pouvez rendre le programme de terminal aussi complexe que vous le souhaitez, comme démontré dans les captures d'écran.

Si vous êtes sous Wayland ou macOS, vous pouvez, par exemple, exécuter :

kitten panel --edge=background htop

pour afficher htop comme fond d'écran de votre bureau. N'oubliez pas que cela fonctionne dans tout sauf GNOME et aussi, dans sway, vous devez désactiver le fond d'écran car sway le rend par-dessus la surface du panneau kitten.

Il existe des projets qui utilisent cette fonctionnalité pour implémenter des panneaux et des composants de bureau généralisés :

  • kitty panel https://github.com/5hubham5ingh/kitty-panel
  • pawbar https://github.com/codelif/pawbar

Contrôle des panneaux via la commande à distance

Vous pouvez contrôler les panneaux via la fonctionnalité de commande à distance de kitty <>. Créez un panneau avec la commande à distance activée :

kitten panel -o allow_remote_control=socket-only --lines=2 \
    --listen-on=unix:/tmp/panel kitten run-shell

Vous pouvez maintenant contrôler ce panneau via la commande à distance, par exemple pour l'afficher/le masquer, utilisez :

kitten @ --to=unix:/tmp/panel resize-os-window --action=toggle-visibility

Pour déplacer le panneau en bas de l'écran et augmenter sa hauteur :

kitten @ --to=unix:/tmp/panel resize-os-window --action=os-panel \
    --incremental edge=bottom lines=4

Pour créer un nouveau panneau exécutant le programme top, dans la même instance (comme la création d'une nouvelle fenêtre OS) :

kitten @ --to=unix:/tmp/panel launch --type=os-panel --os-panel edge=top \
    --os-panel lines=8 top

Code source du panneau

Le code source de ce kitten est disponible sur GitHub https://github.com/kovidgoyal/kitty/tree/master/kittens/panel.

Interface en ligne de commande

kitty +kitten panel [options] [cmdline-to-run ...]

Utiliser un programme en ligne de commande pour dessiner un panneau accéléré par GPU sur votre bureau

Options

--lines <LIGNES>
Le nombre de lignes affichées dans le panneau. Ignoré pour les panneaux de fond, centrés et verticaux. S'il a le suffixe px, il définit la hauteur du panneau en pixels au lieu de lignes. Défaut : 1
--columns <COLONNES>
Le nombre de colonnes affichées dans le panneau. Ignoré pour les panneaux de fond, centrés et horizontaux. S'il a le suffixe px, il définit la largeur du panneau en pixels au lieu de colonnes. Défaut : 1
--margin-top <MARGE_HAUT>
Définit la marge supérieure du panneau, en pixels. N'a aucun effet pour les panneaux du bord inférieur. Ne fonctionne que sur macOS et les compositeurs Wayland qui prennent en charge le protocole shell de couche wlr. Défaut : 0
--margin-left <MARGE_GAUCHE>
Définit la marge gauche du panneau, en pixels. N'a aucun effet pour les panneaux du bord droit. Ne fonctionne que sur macOS et les compositeurs Wayland qui prennent en charge le protocole shell de couche wlr. Défaut : 0
--margin-bottom <MARGE_BAS>
Définit la marge inférieure du panneau, en pixels. N'a aucun effet pour les panneaux du bord supérieur. Ne fonctionne que sur macOS et les compositeurs Wayland qui prennent en charge le protocole shell de couche wlr. Défaut : 0
--margin-right <MARGE_DROITE>
Définit la marge droite du panneau, en pixels. N'a aucun effet pour les panneaux du bord gauche. Ne fonctionne que sur macOS et les compositeurs Wayland qui prennent en charge le protocole shell de couche wlr. Défaut : 0
--edge <BORD>
Quel bord de l'écran placer le panneau. Notez que certains gestionnaires de fenêtres (comme i3) ne prennent pas en charge le placement de fenêtres ancrées sur les bords gauche et droit. La valeur background signifie faire du panneau le « fond d'écran ». Notez que lors de l'utilisation de sway, si vous définissez un fond d'écran dans votre configuration sway, il couvrira le fond dessiné à l'aide de ce kitten. De plus, il y a trois autres valeurs : center, center-sized et none. La valeur center ancre le panneau à tous les côtés et couvre tout l'affichage (sur macOS, la partie de l'affichage non couverte par la barre de titre et le dock). Le panneau peut être réduit et placé en utilisant les paramètres de marge. La valeur none ancre le panneau dans le coin supérieur gauche et doit être placé en utilisant les paramètres de marge. Sa taille est définie par --lines et --columns. La valeur center-sized est comme none sauf que le panneau est centré au lieu d'être dans le coin supérieur gauche et les marges n'ont aucun effet. Défaut : top Choix : background, bottom, center, center-sized, left, none, right, top
--layer <COUCHE>
Sur un compositeur Wayland qui prend en charge le protocole shell de couche wlr, spécifie la couche sur laquelle le panneau doit être dessiné. Ce paramètre est ignoré et défini sur background si --edge est défini sur background. Sur macOS, mappe ces éléments aux niveaux de fenêtre NSWindow appropriés. Défaut : bottom Choix : background, bottom, overlay, top
--config <CONFIG>, -c <CONFIG>
Chemin vers le fichier de configuration à utiliser pour kitty lors du dessin du panneau.
--override <OVERRIDE>, -o <OVERRIDE>
défaut= Remplace les options de configuration kitty individuelles, peut être spécifié plusieurs fois. Syntaxe : nom=valeur. Par exemple : kitty +kitten panel -o font_size=20
--output-name <NOM_SORTIE>
Le panneau ne peut être affiché que sur un seul moniteur (sortie) à la fois. Cela permet de spécifier quelle sortie est utilisée, par nom. Si non spécifié, le compositeur choisira automatiquement une sortie, généralement la dernière sortie avec laquelle l'utilisateur a interagi ou le moniteur principal. Utilisez la valeur spéciale list pour obtenir une liste des sorties disponibles. Utilisez listjson pour une sortie encodée en JSON. Notez que sur Wayland, la sortie ne peut être définie qu'au moment de la création du panneau, elle ne peut pas être modifiée après la création, et il n'y a aucun moyen d'afficher un seul panneau sur toutes les sorties. Veuillez vous plaindre aux développeurs Wayland à ce sujet.
--app-id <CLS>, --class <CLS>
Sur Wayland, définit l'espace de noms de la surface de la couche de présentation. Sur X11, définit la partie classe de la propriété de fenêtre WM_CLASS. Par défaut : kitty-panel
--name <NOM>, --os-window-tag <NOM>
Sur X11, définit la partie nom de la propriété WM_CLASS sur X11. Si non spécifié, utilise la valeur de kitty --class <#cmdoption-kitty-app-id> sur X11.
--focus-policy <POLITIQUE_FOCUS>
Sur un compositeur Wayland qui prend en charge le protocole wlr layer shell, spécifiez la politique de focus pour l'interactivité clavier avec le panneau. Veuillez vous référer à la documentation du protocole wlr layer shell pour plus de détails. Notez que différents compositeurs Wayland se comportent très différemment avec exclusive, vos résultats peuvent varier. Sur macOS, exclusive et on-demand sont actuellement identiques. Par défaut : not-allowed Choix : exclusive, not-allowed, on-demand
--hide-on-focus-loss [=no]
Masque automatiquement la fenêtre du panneau lorsqu'elle perd le focus. L'utilisation de cette option forcera --focus-policy à on-demand. Notez que sur Wayland, selon le compositeur, cela peut résulter en une fenêtre qui ne devient jamais visible.
--grab-keyboard [=no]
Capture le clavier. Cela signifie que les raccourcis globaux définis dans l'OS seront plutôt transmis à kitty. Utile si vous souhaitez créer une fenêtre modale de l'OS. Son bon fonctionnement dépend de l'OS/gestionnaire de fenêtres/environnement de bureau. Sur Wayland, cela ne fonctionne que si le compositeur implémente le protocole d'inhibition des raccourcis clavier https://wayland.app/protocols/keyboard-shortcuts-inhibit-unstable-v1. Sur macOS, Apple n'autorise pas les applications à capturer le clavier sans permissions spéciales, donc cela ne fonctionne pas.
--exclusive-zone <ZONE_EXCLUSIVE>
Sur un compositeur Wayland qui prend en charge le protocole wlr layer shell, demande une zone exclusive donnée pour le panneau. Veuillez vous référer à la documentation du protocole wlr layer shell pour plus de détails sur la signification d'exclusive et sa valeur. Si --edge est défini sur autre chose que center ou none, ce drapeau n'aura aucun effet à moins que le drapeau --override-exclusive-zone ne soit également défini. Si --edge est défini sur background, cette option n'a aucun effet. Ignoré sur X11 et macOS. Par défaut : -1
--override-exclusive-zone [=no]
Sur un compositeur Wayland qui prend en charge le protocole wlr layer shell, remplace la zone exclusive par défaut. Cela n'a d'effet que si --edge est défini sur top, left, bottom ou right. Ignoré sur X11 et macOS. Par défaut : no
--single-instance [=no], -1 [=no]
Si spécifié, une seule instance du panneau sera exécutée. Les nouvelles invocations créeront plutôt une nouvelle fenêtre de niveau supérieur dans l'instance de panneau existante. Par défaut : no
--instance-group <GROUPE_INSTANCES>
défaut= Utilisé en combinaison avec l'option --single-instance. Toutes les invocations de panneau avec le même --instance-group entraîneront la création de nouveaux panneaux dans la première instance de panneau de ce groupe.
--wait-for-single-instance-window-close [=no]
Normalement, lors de l'utilisation de kitty --single-instance <#cmdoption-kitty-single-instance>, kitty ouvrira une nouvelle fenêtre dans une instance existante et se fermera immédiatement. Avec cette option, il ne se fermera pas tant que la nouvelle fenêtre ouverte ne sera pas fermée. Notez que si aucune instance précédente n'est trouvée, kitty attendra de toute façon, indépendamment de cette option.
--listen-on <ECOUTER_SUR>
Écoute sur l'adresse de socket spécifiée pour les messages de contrôle. Par exemple, kitty --listen-on <#cmdoption-kitty-listen-on>=unix:/tmp/mykitty ou kitty --listen-on <#cmdoption-kitty-listen-on>=tcp:localhost:12345. Sur les systèmes Linux, vous pouvez également utiliser des sockets UNIX abstraits, non associés à un fichier, comme ceci : kitty --listen-on <#cmdoption-kitty-listen-on>=unix:@mykitty. Les variables d'environnement sont développées et les chemins relatifs sont résolus par rapport au répertoire temporaire. Pour contrôler kitty, vous pouvez lui envoyer des commandes avec kitten @ en utilisant l'option kitten @ --to <#cmdoption-kitten-to> pour spécifier cette adresse. Notez que si vous exécutez kitten @ dans une fenêtre kitty, il n'est pas nécessaire de spécifier l'option kitten @ --to <#cmdoption-kitten-to> car elle sera automatiquement lue depuis l'environnement. Notez que ceci sera ignoré à moins que allow_remote_control <#opt-kitty.allow_remote_control> ne soit défini sur : yes, socket ou socket-only. Ceci peut également être spécifié dans kitty.conf.
--toggle-visibility [=no]
Lorsqu'il est défini et utilisé avec --single-instance, basculera la visibilité du panneau existant au lieu d'en créer un nouveau. Par défaut : no
--move-to-active-monitor [=no]
Lorsqu'il est défini et utilisé avec --toggle-visibility pour afficher un panneau existant, le panneau est déplacé vers le moniteur actif (généralement le moniteur sur lequel se trouve la souris). Cela ne fonctionne que si le système d'exploitation sous-jacent le prend en charge. Il est actuellement pris en charge sur macOS uniquement. Par défaut : false
--start-as-hidden [=no]
Démarre en mode caché, utile avec --toggle-visibility. Par défaut : no
--detach [=no]
Se détache du terminal de contrôle, le cas échéant, s'exécute dans un processus enfant indépendant, le processus parent se termine immédiatement. Par défaut : no
--detached-log <LOG_DETACHE>
défaut= Chemin vers un fichier journal pour stocker STDOUT/STDERR lors de l'utilisation de --detach
--debug-rendering [=no]
Pour un usage de débogage interne.
--debug-input [=no]
Pour un usage de débogage interne.

Comment les captures d'écran ont été générées

Les statistiques système en arrière-plan ont été créées à l'aide de :

kitten panel --edge=background -o background_opacity=0.2 -o background=black btop

Cela crée une fenêtre d'arrière-plan kitty et exécute en son sein le programme btop https://github.com/aristocratos/btop pour afficher les statistiques.

La fenêtre d'accès rapide flottante a été créée en exécutant :

kitten quick-access-terminal kitten run-shell \
   zsh -c 'printf "\e]66;s=4;Quick access kitty in Hyprland\a\n\n\n\nAlso uses kitty to draw desktop background\n"'

Cela démarre la fenêtre d'accès rapide et exécute en son sein kitten run-shell, qui à son tour exécute d'abord zsh pour afficher le message, puis démarre le shell de connexion de l'utilisateur.

Le panneau de dock Linux était :

wm bar

Ceci est un programme personnalisé que j'ai écrit pour mon usage personnel. Il utilise l'infrastructure kitten de kitty pour implémenter la barre en quelques centaines de lignes de code https://github.com/kovidgoyal/wm/blob/master/bar/main.go. Ceci a été conçu pour mon usage personnel uniquement, mais il existe des projets publics implémentant des panneaux à usage général utilisant kitty.
