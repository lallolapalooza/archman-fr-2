KIBITZ(1) Manuel des commandes générales KIBITZ(1)

NOM

kibitz - permet à deux personnes d'interagir avec un seul shell

SYNOPSIS

kibitz [ kibitz-args ] user [ program program-args... ]
kibitz [ kibitz-args ] user@host [ program program-args... ]

INTRODUCTION

kibitz permet à deux (ou plus) personnes d'interagir avec un shell (ou n'importe quel programme arbitraire). Les utilisations incluent :

•
Un utilisateur novice peut demander de l'aide à un utilisateur expert. En utilisant kibitz, l' expert peut voir ce que fait l'utilisateur et donner des conseils ou montrer comment faire correctement.
•
En lançant kibitz puis en démarrant un éditeur plein écran, les gens peuvent avoir une conversation, tout en conservant la possibilité de faire défiler vers l'arrière, d'enregistrer la conversation entière, ou même de la modifier pendant qu'elle se déroule.
•
Les gens peuvent collaborer sur des jeux, l'édition de documents ou d'autres tâches coopératives où chaque personne a des forces et des faiblesses qui se complètent mutuellement.

UTILISATION

Pour démarrer kibitz, user1 lance kibitz avec en argument le utilisateur avec lequel kibitzer. Par exemple :

kibitz user2

kibitz démarre un nouveau shell (ou un autre programme, s'il est indiqué sur la ligne de commande), tout en invitant user2 à lancer kibitz. Si user2 lance kibitz comme indiqué, les frappes des deux utilisateurs deviennent l'entrée du shell. De même, les deux utilisateurs reçoivent la sortie du shell.

Pour terminer kibitz il suffit de terminer le shell lui-même. Par exemple, si l'un des utilisateurs tape ^D (et que le shell accepte cela comme EOF), le shell se termine suivi de kibitz.

Normalement, tous les caractères sont transmis sans interprétation. Cependant, si le caractère d'échappement (décrit lorsque kibitz démarre) est émis, l'utilisateur peut parler directement à l'interpréteur kibitz . N'importe quelle commande ou Tcl(3) peut être donnée. De plus, le contrôle des travaux peut être utilisé dans l'interpréteur, pour, par exemple, suspendre ou redémarrer kibitz.

Divers processus peuvent produire divers effets. Par exemple, vous pouvez émuler une session bidirectionnelle write(1) avec la commande :

kibitz user2 sleep 1000000

ARGUMENTS

kibitz prend des arguments, ceux-ci doivent également être séparés par des espaces.

L'option -noproc exécute kibitz sans processus en dessous. Les caractères sont transmis à l'autre kibitz. C'est particulièrement utile pour connecter plusieurs processus interactifs ensemble. Dans ce mode, les caractères ne sont pas renvoyés au frappeur.

-noescape désactive le caractère d'échappement.

-escape char définit le caractère d'échappement. Le caractère d'échappement par défaut est ^].

-silent désactive les messages informatifs décrivant ce que kibitz fait pour initier une connexion.

-tty ttyname définit le tty auquel l'invitation doit être envoyée.

Si vous démarrez kibitz vers user2 sur un ordinateur distant, kibitz effectue un rlogin vers l'ordinateur distant avec votre nom d'utilisateur actuel. L'option -proxy username fait que rlogin utilise username pour la connexion distante (par exemple si votre compte sur l'ordinateur distant a un nom d'utilisateur différent). Si l'option -proxy n'est pas donnée, kibitz essaie de déterminer votre nom d'utilisateur actuel en (dans cet ordre) inspectant les variables d'environnement USER et LOGNAME, puis en utilisant les commandes whoami et logname.

Les arguments -noescape et -escape peuvent également être donnés par user2 lorsqu'il est invité à lancer kibitz.

PLUS DE DEUX UTILISATEURS

L'implémentation actuelle de kibitz ne comprend explicitement que deux utilisateurs, cependant, il est néanmoins possible d'avoir un kibitz à trois (ou plus) , en kibitzant un autre kibitz. Par exemple, la commande suivante exécute kibitz avec l'utilisateur actuel, user2 et user3 :

% kibitz user2 kibitz user3

Des utilisateurs supplémentaires peuvent être ajoutés en ajoutant simplement plus de commandes "kibitz user".

Le script xkibitz est similaire à kibitz mais prend en charge la possibilité d'ajouter des utilisateurs supplémentaires (et de les retirer) dynamiquement.

AVERTISSEMENTS

kibitz suppose que le 2ème utilisateur a le même type de terminal et la même taille que le 1er utilisateur. Si cette hypothèse est incorrecte, les programmes graphiques peuvent s'afficher de manière étrange.

kibitz gère la graphique par caractères, mais ne peut pas gérer la graphique bitmap. Ainsi,

% xterm -e kibitz    fonctionnera
% kibitz xterm       ne fonctionnera pas
Cependant, vous pouvez obtenir l'effet de la dernière commande en utilisant xkibitz (voir VOIR AUSSI ci-dessous). kibitz utilise les mêmes permissions que celles utilisées par rlogin, rsh, etc. Ainsi, vous ne pouvez kibitz que vers des utilisateurs sur des hôtes pour lesquels vous pouvez rlogin. De même, kibitz demandera un mot de passe sur l'hôte distant si rlogin le faisait.

Si vous kibitz vers des utilisateurs sur des hôtes distants, kibitz doit distinguer votre invite d'autres choses qui peuvent la précéder pendant la connexion. (Idéalement, la fin de l'invite est préférée mais toute partie devrait suffire.) Si vous avez une invite inhabituelle, définissez la variable d'environnement EXPECT_PROMPT avec une expression régulière de style egrep(1). Les crochets doivent être précédés d'un antislash dans les plages, et de trois antislashes pour des crochets littéraux. L'expression régulière de l'invite par défaut est "($|%|#) ".

kibitz nécessite le programme kibitz sur les deux hôtes. kibitz nécessite expect(1).

Par comparaison, le script xkibitz utilise le mécanisme d'autorisation X pour la communication inter-hôtes, il n'a donc pas besoin de se connecter, de reconnaître votre invite, ou de nécessiter kibitz sur l'hôte distant. Il a cependant besoin de la permission d'accéder aux autres serveurs X.

BOGUES

Une version précoce de tmpfs de Sun avait un bogue qui faisait kibitz planter. Si kibitz rapporte "error flushing ...: Is a directory", demandez à Sun le patch #100174.

Si votre Expect n'est pas compilé avec la prise en charge multi-processus (c'est-à-dire que vous n'avez pas de select ou poll fonctionnel), vous ne pourrez pas exécuter kibitz.

ENVIRONNEMENT

La variable d'environnement SHELL est utilisée pour déterminer le shell à démarrer, si aucun autre programme n'est donné sur la ligne de commande.

Si la variable d'environnement EXPECT_PROMPT existe, elle est prise comme une expression régulière qui correspond à la fin de votre invite de connexion (mais qui ne se produit pas autrement pendant la connexion). Voir aussi AVERTISSEMENTS ci-dessus.

Si les variables d'environnement USER ou LOGNAME sont définies, elles sont utilisées pour déterminer le nom d'utilisateur actuel pour un kibitz vers un ordinateur distant. Voir la description de l'option -proxy dans ARGUMENTS ci-dessus.
