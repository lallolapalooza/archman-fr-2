NOM

kamene - Outil interactif de manipulation de paquets

SYNTAXE

kamene [options]

DESCRIPTION

Cette page de manuel documente brièvement l'outil kamene.

kamene est un puissant outil interactif de manipulation de paquets, générateur de paquets, scanner réseau, outil de découverte réseau, renifleur de paquets, etc. Il peut remplacer, pour l'instant, hping, des parties de nmap, arpspoof, arp-sk, arping, tcpdump, tshark, p0f, ...

kamene utilise l'interpréteur python comme tableau de commande. Cela signifie que vous pouvez utiliser directement le langage python (assigner des variables, utiliser des boucles, définir des fonctions, etc.) Si vous donnez un fichier comme paramètre lorsque vous exécutez kamene, votre session (variables, fonctions, instances, ...) sera sauvegardée à la sortie de l'interpréteur, et restaurée la prochaine fois que vous lancerez kamene.

L'idée est simple. Ces types d'outils font deux choses : envoyer des paquets et recevoir des réponses. C'est ce que fait kamene : vous définissez un ensemble de paquets, il les envoie, reçoit les réponses, fait correspondre les requêtes avec les réponses et renvoie une liste de couples (requête, réponse) et une liste de paquets non correspondants. Cela présente le grand avantage sur des outils comme nmap ou hping qu'une réponse n'est pas réduite à (ouvert/fermé/filtré), mais est le paquet entier.

Au-dessus de cela, des fonctions de plus haut niveau peuvent être construites, par exemple une qui fait des traceroutes et ne renvoie que le TTL de départ de la requête et l'IP source de la réponse. Une qui scanne un réseau entier et renvoie la liste des machines qui répondent. Une qui fait un scan de ports et renvoie un rapport LaTeX.

OPTIONS

Les options de kamene sont :

-h
affiche l'aide
-d
augmente la verbosité des logs. Peut être utilisé plusieurs fois.
-s FICHIER
utilise FICHIER pour sauvegarder/charger les valeurs de session (variables, fonctions, instances, ...)
-p FICHIER_PREDEMARRAGE
utilise FICHIER_PREDEMARRAGE à la place de $HOME/.kamene_prestart.py comme fichier de pré-démarrage
-P
n'exécute pas le fichier de pré-démarrage
-c FICHIER_DEMARRAGE
utilise FICHIER_DEMARRAGE à la place de $HOME/.kamene_startup.py comme fichier de démarrage
-C
n'exécute pas le fichier de démarrage

COMMANDES

Seules les commandes essentielles pour débuter sont listées ici pour le moment.

ls()
liste les couches de protocoles supportées. Si une couche de protocole est donnée en paramètre, liste ses champs et types de champs.
lsc()
liste quelques commandes utilisateur. Si une commande est donnée en paramètre, sa documentation est affichée.
conf
cet objet contient la configuration.

FICHIERS

$HOME/.kamene_prestart.py Ce fichier est exécuté avant que le cœur de kamene ne soit chargé. Seul l'objet conf est disponible. Ce fichier peut être utilisé pour manipuler la liste conf.load_layers pour choisir quelles couches seront chargées :

conf.load_layers.remove("bluetooth")
conf.load_layers.append("new_layer")

$HOME/.kamene_startup.py Ce fichier est exécuté après le chargement de kamene. Il peut être utilisé pour configurer certains des comportements de kamene :

conf.prog.pdfreader="xpdf"
split_layers(UDP,DNS)

EXEMPLES

Des exemples plus détaillés sont disponibles sur https://phaethon.github.io/kamene/ Lancez simplement kamene et essayez les commandes suivantes dans l'interpréteur.

Reniflage et décodage de paquets (avec un filtre bpf ou une sortie type ethereal) :

a=sniff(filter="tcp port 110")
a=sniff(prn = lambda x: x.display)

Réémission de paquets reniflés :

a=sniff(filter="tcp port 110")
sendp(a)

Réémission de paquets d'un fichier pcap :

sendp(rdpcap("file.cap"))

Traceroute TCP manuel :

sr(IP(dst="www.google.com", ttl=(1,30))/TCP(seq=RandInt(), sport=RandShort(), dport=dport)

Scan de protocoles :

sr(IP(dst="172.16.1.28", proto=(1,254)))

Ping ARP :

srp(Ether(dst="ff:ff:ff:ff:ff:ff")/ARP(pdst="172.16.1.1/24"))

Scan ACK :

sr(IP(dst="172.16.1.28")/TCP(dport=(1,1024), flags="A"))

Empoisonnement de cache ARP :

sendp(Ether(dst=tmac)/ARP(op="who-has", psrc=victim, pdst=target))

Rapports :

report_ports("192.168.2.34", (20,30))

BOGUES

Ne renvoie pas la bonne IP source pour les routes utilisant des alias d'interface.

Peut manquer des paquets sous forte charge.

La sauvegarde de session est limitée par la capacité de Python à sérialiser les objets. Par conséquent, les fonctions lambda et les générateurs ne peuvent pas être sauvegardés, ce qui réduit considérablement l'utilité de cette fonctionnalité.

Les filtres BPF ne fonctionnent pas sur les interfaces point à point.
