NOM

kerberos - Aperçu de l'utilisation de Kerberos

DESCRIPTION

Le système Kerberos authentifie les utilisateurs individuels dans un environnement réseau. Après vous être authentifié auprès de Kerberos, vous pouvez utiliser les programmes prenant en charge Kerberos sans avoir à présenter de mots de passe ou de certificats à ces programmes.

Si vous recevez la réponse suivante de kinit(1) :

kinit: Client not found in Kerberos database while getting initial credentials

vous n'avez pas été enregistré en tant qu'utilisateur Kerberos. Consultez votre administrateur système.

Un nom Kerberos contient généralement trois parties. La première est le primaire, qui est généralement le nom d'un utilisateur ou d'un service. La deuxième est l' instance, qui, dans le cas d'un utilisateur, est généralement nulle. Certains utilisateurs peuvent toutefois avoir des instances privilégiées, telles que root ou admin. Dans le cas d'un service, l'instance est le nom qualifié complet de la machine sur laquelle il s'exécute ; c'est-à-dire qu'il peut y avoir un service ssh s'exécutant sur la machine ABC (ssh/ABC@REALM), qui est différent du service ssh s'exécutant sur la machine XYZ (ssh/XYZ@REALM). La troisième partie d'un nom Kerberos est le royaume. Le royaume correspond au service Kerberos fournissant l'authentification pour le principal. Les royaumes sont conventionnellement en majuscules et correspondent souvent à la fin des noms d'hôtes dans le royaume (par exemple, host01.example.com pourrait se trouver dans le royaume EXAMPLE.COM).

Lorsque vous écrivez un nom Kerberos, le nom du principal est séparé de l'instance (si elle n'est pas nulle) par une barre oblique, et le royaume (s'il ne s'agit pas du royaume local) suit, précédé d'un signe « @ ». Voici des exemples de noms Kerberos valides :

david
jennifer/admin
joeuser@BLEEP.COM
cbrown/root@FUBAR.ORG

Lorsque vous vous authentifiez avec Kerberos, vous obtenez un premier ticketKerberos. (Un ticket Kerberos est un message de protocole chiffré qui fournit l'authentification.) Kerberos utilise ce ticket pour les utilitaires réseau tels que ssh. Les transactions de tickets sont effectuées de manière transparente, vous n'avez donc pas à vous soucier de leur gestion.

Notez cependant que les tickets expirent. Les administrateurs peuvent configurer des tickets plus privilégiés, tels que ceux avec un service ou une instance root ou admin, pour qu'ils expirent en quelques minutes, tandis que les tickets portant des privilèges plus ordinaires peuvent être valables plusieurs heures ou un jour. Si votre session de connexion dépasse la limite de temps, vous devrez vous ré-authentifier auprès de Kerberos pour obtenir de nouveaux tickets en utilisant la commande kinit(1).

Certains tickets sont renouvelables au-delà de leur durée de vie initiale. Cela signifie que kinit -R peut étendre leur durée de vie sans que vous deviez vous ré-authentifier.

Si vous souhaitez supprimer vos tickets locaux, utilisez la commande kdestroy(1).

Les tickets Kerberos peuvent être transférés. Afin de transférer des tickets, vous devez demander des tickets transférables lorsque vous utilisez kinit. Une fois que vous avez des tickets transférables, la plupart des programmes Kerberos disposent d'une option en ligne de commande pour les transférer vers l'hôte distant. Cela peut être utile pour, par exemple, exécuter kinit sur votre machine locale puis vous connecter en ssh à une autre machine pour travailler. Notez que cela ne devrait pas être fait sur des machines non fiables, car elles auront alors vos tickets.

VARIABLES D'ENVIRONNEMENT

Plusieurs variables d'environnement affectent le fonctionnement des programmes prenant en charge Kerberos. Celles-ci incluent :

KRB5CCNAME
Nom par défaut du fichier de cache d'identifiants, sous la forme TYPE:résidu. Le type de cache par défaut peut déterminer la disponibilité d'une collection de caches. FILE n'est pas un type de collection ; KEYRING, DIR, et KCM le sont.

S'il n'est pas défini, la valeur de default_ccache_name à partir des fichiers de configuration (voir KRB5_CONFIG) sera utilisée. Si cela n'est pas non plus défini, le type par défaut est FILE, et le résidu est le chemin /tmp/krb5cc_*uid*, où uid est l' identifiant utilisateur décimal de l'utilisateur.

KRB5_KTNAME
Spécifie l'emplacement du fichier keytab par défaut, sous la forme TYPE:résidu. Si aucun type n'est présent, le type FILE est supposé et le résidu est le chemin du fichier keytab. Si non défini, FILE:/etc/krb5.keytab sera utilisé.
KRB5_CONFIG
Spécifie l'emplacement du fichier de configuration de Kerberos. La valeur par défaut est /etc/krb5.conf. Plusieurs noms de fichiers peuvent être spécifiés, séparés par deux-points ; tous les fichiers présents seront lus.
KRB5_KDC_PROFILE
Spécifie l'emplacement du fichier de configuration du KDC, qui contient des directives de configuration supplémentaires pour le démon du Key Distribution Center et les programmes associés. La valeur par défaut est /var/lib/krb5kdc/kdc.conf.
KRB5RCACHENAME
(Nouveau dans la version 1.18) Spécifie l'emplacement du cache de rejeu par défaut, sous la forme type:résidu. Le type file2 avec un résidu de chemin spécifie un fichier de cache de rejeu au format version-2 à l'emplacement spécifié. Le type none (le résidu est ignoré) désactive le cache de rejeu. Le type dfl (le résidu est ignoré) indique la valeur par défaut, qui utilise un cache de rejeu file2 dans un répertoire temporaire. La valeur par défaut est dfl:.
KRB5RCACHETYPE
Spécifie le type du cache de rejeu par défaut, si KRB5RCACHENAME n'est pas spécifié. Aucun résidu ne peut être spécifié, donc none et dfl sont les seuls types utiles.
KRB5RCACHEDIR
Spécifie le répertoire utilisé par le type de cache de rejeu dfl. La valeur par défaut est celle de la variable d'environnement TMPDIR , ou /var/tmp si TMPDIR n'est pas définie.
KRB5_TRACE
Spécifie un nom de fichier dans lequel écrire la sortie du journal de traçage. Les journaux de traçage peuvent aider à éclairer les décisions prises en interne par les bibliothèques Kerberos. Par exemple, env KRB5_TRACE=/dev/stderr kinit enverrait les informations de traçage pour kinit(1) vers /dev/stderr. Par défaut, aucune sortie de journal de traçage n'est écrite nulle part.
KRB5_CLIENT_KTNAME
Nom du fichier keytab client par défaut. Si non défini, FILE:/var/lib/krb5/user/%{euid}/client.keytab sera utilisé).
KPROP_PORT
Port kprop(8) à utiliser. Par défaut 754.
GSS_MECH_CONFIG
Spécifie un nom de fichier contenant la configuration du module de mécanisme GSSAPI. La valeur par défaut est de lire /etc/gss/mech et les fichiers avec un suffixe .conf dans le répertoire /etc/gss/mech.d.

La plupart des variables d'environnement sont désactivées pour certains programmes, tels que les programmes système de connexion et les programmes setuid, qui sont conçus pour être sécurisés lorsqu'ils sont exécutés dans un environnement de processus non fiable.
