NOM

kubeadm token create - Créer des jetons d'amorçage sur le serveur

SYNTAXE

kubeadm token create [OPTIONS]

DESCRIPTION

Cette commande créera un jeton d'amorçage pour vous. Vous pouvez spécifier les utilisations pour ce jeton, la "durée de vie" et une description facultative conviviale.

Le [jeton] est le jeton réel à écrire. Il doit s'agir d'un jeton aléatoire généré de manière sécurisée de la forme "[a-z0-9]{6}.[a-z0-9]{16}". Si aucun [jeton] n'est fourni, kubeadm en générera un aléatoirement.

OPTIONS

--certificate-key="" Lorsqu'il est utilisé avec '--print-join-command', affiche le drapeau complet 'kubeadm join' nécessaire pour rejoindre le cluster en tant que plan de contrôle. Pour créer une nouvelle clé de certificat, vous devez utiliser 'kubeadm init phase upload-certs --upload-certs'.

--config="" Chemin d'accès à un fichier de configuration kubeadm.

--description="" Une description conviviale de la manière dont ce jeton est utilisé.

--groups=[system:bootstrappers:kubeadm:default-node-token] Groupes supplémentaires pour lesquels ce jeton s'authentifiera lors de son utilisation pour l'authentification. Doit correspondre à "\Asystem:bootstrappers:[a-z0-9:-]{0,255}[a-z0-9]\z"

--print-join-command=false Au lieu d'afficher uniquement le jeton, affiche le drapeau complet 'kubeadm join' nécessaire pour rejoindre le cluster en utilisant le jeton.

--ttl=24h0m0s La durée avant que le jeton ne soit automatiquement supprimé (par exemple, 1s, 2m, 3h). S'il est défini sur '0', le jeton n'expirera jamais.

--usages=[signing,authentication] Décrit les moyens par lesquels ce jeton peut être utilisé. Vous pouvez passer --usages plusieurs fois ou fournir une liste d'options séparées par des virgules. Options valides : [signing,authentication]

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--dry-run=false Si le mode simulation doit être activé ou non

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si le drapeau n'est pas défini, un ensemble d'emplacements standards peut être recherché pour trouver un fichier kubeconfig existant.

--rootfs="" Le chemin d'accès au système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à chrooter dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée
