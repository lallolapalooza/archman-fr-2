DESCRIPTIO

N

kadmin et kadmin.local sont des interfaces en ligne de commande pour le système d'administration Kerberos V5. Ils fournissent des fonctionnalités presque identiques ; la différence est que kadmin.local accède directement à la base de données du KDC, tandis que kadmin effectue les opérations en utilisant kadmind(8). Sauf indication contraire explicite, cette page man utilisera « kadmin » pour désigner les deux versions. kadmin permet la maintenance des principaux Kerberos, des politiques de mot de passe et des tables de clés de service (keytabs)

.

Le client kadmin distant utilise Kerberos pour s'authentifier auprès de kadmind en utilisant le principal de service kadmin/admin ou kadmin/ADMINHOST (où ADMINHOST est le nom d'hôte pleinement qualifié du serveur d'administration). Si le cache d'identifiants contient un ticket pour l'un de ces principaux, et que l'option -c credentials_cache est spécifiée, ce ticket est utilisé pour s'authentifier auprès de kadmind. Sinon, les options -p et -k sont utilisées pour spécifier le nom du principal Kerberos du client utilisé pour s'authentifier. Une fois que kadmin a déterminé le nom du principal, il demande un ticket de service au KDC et utilise ce ticket de service pour s'authentifier auprès de

kadmind.

Puisque kadmin.local accède directement à la base de données du KDC, il doit généralement être exécuté directement sur le K

DC primaire avec des permissions suffisantes pour lire la base de données du KDC. Si la base de données du KDC utilise
le module de base de données LDAP, kadmin.local peut être exécuté sur n'importe quel hôte pouvant accéder au serveur LDAP.

COMMANDES

Lors de l'utilisation du client distant, les commandes disponibles peuvent être restreintes en fonction des privilèges spécifiés dans le fichier kadm5.acl(5) sur le serveur d'administration.

add_principal

add_principal [options] nouveau_principal

Crée le principal nouveau_principal, en demandant deux fois un mot de passe. Si aucune politique de mot de passe n'est spécifiée avec l'option -policy, et si la politique nommée default est assignée au principal, elle lui sera appliquée s'il existe. Cependant, la création d'une politique nommée default n'assignera pas automatiquement cette politique aux principaux existants. Cette assignation de politique peut être supprimée avec l'option -clearpolicy.

Cette commande nécessite le privilège add.

Alias : addprinc, ank

Options :

-expire date_expiration
(chaîne getdate) La date d'expiration du principal.
-pwexpire date_exp_mot_de_passe
(chaîne getdate) La date d'expiration du mot de passe.
-maxlife durée_max_ticket
(durée ou chaîne getdate) La durée de vie maximale du ticket pour le principal.
-maxrenewlife durée_max_renouvellement
(durée ou chaîne getdate) La durée de vie maximale de renouvellement des tickets pour le principal.
-kvno num_version_clé
Le numéro de version de clé initial.
-policy politique
La politique de mot de passe utilisée par ce principal. Si non spécifiée, la politique default est utilisée si elle existe (sauf si -clearpolicy est spécifié).
-clearpolicy
Empêche l'assignation d'une politique lorsque -policy n'est pas spécifié.
{-|+}allow_postdated
-allow_postdated interdit à ce principal d'obtenir des tickets postdatés. +allow_postdated efface ce drapeau.
{-|+}allow_forwardable
-allow_forwardable interdit à ce principal d'obtenir des tickets transférables. +allow_forwardable efface ce drapeau.
{-|+}allow_renewable
-allow_renewable interdit à ce principal d'obtenir des tickets renouvelables. +allow_renewable efface ce drapeau.
{-|+}allow_proxiable
-allow_proxiable interdit à ce principal d'obtenir des tickets proxifiables. +allow_proxiable efface ce drapeau.
{-|+}allow_dup_skey
-allow_dup_skey désactive l'authentification utilisateur à utilisateur pour ce principal en interdisant à d'autres d'obtenir un ticket de service chiffré avec la clé de session TGT de ce principal. +allow_dup_skey efface ce drapeau.
{-|+}requires_preauth
+requires_preauth oblige ce principal à effectuer une pré-authentification avant d'être autorisé à utiliser kinit. -requires_preauth efface ce drapeau. Lorsque +requires_preauth est défini sur un principal de service, le KDC n'émettra des tickets de service pour ce principal que si l'authentification initiale du client a été effectuée à l'aide de la pré-authentification.
{-|+}requires_hwauth
+requires_hwauth oblige ce principal à se pré-authentifier à l'aide d'un périphérique matériel avant d'être autorisé à utiliser kinit. -requires_hwauth efface ce drapeau. Lorsque +requires_hwauth est défini sur un principal de service, le KDC n'émettra des tickets de service pour ce principal que si l'authentification initiale du client a été effectuée à l'aide d'un périphérique matériel pour la pré-authentification.
{-|+}ok_as_delegate
+ok_as_delegate définit le drapeau autorisé à déléguer sur les tickets émis avec ce principal en tant que service. Les clients peuvent utiliser ce drapeau comme indication que les informations d'identification devraient être déléguées lors de l'authentification au service. -ok_as_delegate efface ce drapeau.
{-|+}allow_svr
-allow_svr interdit l'émission de tickets de service pour ce principal. Dans les versions 1.17 et ultérieures, les tickets de service utilisateur à utilisateur sont toujours autorisés, sauf si le drapeau -allow_dup_skey est également défini. +allow_svr efface ce drapeau.
{-|+}allow_tgs_req
-allow_tgs_req spécifie qu'une demande de Ticket-Granting Service (TGS) pour un ticket de service pour ce principal n'est pas autorisée. +allow_tgs_req efface ce drapeau.
{-|+}allow_tix
-allow_tix interdit l'émission de tout ticket pour ce principal. +allow_tix efface ce drapeau.
{-|+}needchange
+needchange force un changement de mot de passe lors de la prochaine authentification initiale auprès de ce principal. -needchange efface ce drapeau.
{-|+}password_changing_service
+password_changing_service marque ce principal comme étant un principal de service de changement de mot de passe.
{-|+}ok_to_auth_as_delegate
+ok_to_auth_as_delegate permet à ce principal d'acquérir des tickets transférables à lui-même auprès d'utilisateurs arbitraires, à utiliser avec la délégation restreinte.
{-|+}no_auth_data_required
+no_auth_data_required empêche l'ajout de données PAC ou AD-SIGNEDPATH aux tickets de service pour le principal.
{-|+}lockdown_keys
+lockdown_keys empêche les clés de ce principal de quitter le KDC via kadmind. Les opérations chpass et extract sont refusées pour un principal ayant cet attribut. L'opération chrand est autorisée, mais ne retournera pas les nouvelles clés. Les opérations delete et rename sont également refusées si cet attribut est défini, afin d'empêcher un administrateur malveillant de remplacer des principaux comme krbtgt/* ou kadmin/* par de nouveaux principaux sans cet attribut. Cet attribut peut être défini via le protocole réseau, mais ne peut être supprimé qu'en utilisant kadmin.local.
-randkey
Définit la clé du principal à une valeur aléatoire.
-nokey
Crée le principal sans clé. Nouveauté depuis la version 1.12.
-pw mot_de_passe
Définit le mot de passe du principal à la chaîne spécifiée et ne demande pas de mot de passe. Remarque : l'utilisation de cette option dans un script shell peut exposer le mot de passe à d'autres utilisateurs du système via la liste des processus.
-e chiffrement:sel,...
Utilise la liste de clésalt spécifiée pour définir les clés du principal. Voir Keysalt_lists dans kdc.conf(5) pour une liste de valeurs possibles.
-x args_principal_bd
Indique des options spécifiques à la base de données. Les options pour le module de base de données LDAP sont :
-x dn=dn
Spécifie l'objet LDAP qui contiendra le principal Kerberos en cours de création.
-x linkdn=dn
Spécifie l'objet LDAP auquel pointera l'objet principal Kerberos nouvellement créé.
-x containerdn=dn_conteneur
Spécifie l'objet conteneur sous lequel le principal Kerberos doit être créé.
-x tktpolicy=politique
Associe une politique de ticket au principal Kerberos.

NOTE :

  • Les options containerdn et linkdn ne peuvent pas être spécifiées avec l'option dn.
  • Si les options dn ou containerdn ne sont pas spécifiées lors de l'ajout du principal, les principaux sont créés sous le conteneur de principaux configuré dans le realm ou le conteneur du realm.
  • dn et containerdn doivent se trouver dans les sous-arbres ou le conteneur de principaux configurés dans le realm.

par défaut, aucune politique.
Entrez le mot de passe du principal jennifer@ATHENA.MIT.EDU :
Réentrez le mot de passe du principal jennifer@ATHENA.MIT.EDU :

Spécifie un indicateur d'authentification qui est requis pour s'authentifier auprès du principal en tant que service. Plusieurs indicateurs peuvent être spécifiés, séparés par des espaces ; dans ce cas, n'importe lequel des indicateurs spécifiés sera accepté. (Nouveau dans la version 1.14.)

Spécifie une expression de correspondance qui définit les attributs de certificat requis pour le certificat client utilisé par le principal lors de l'authentification PKINIT. add_policy

add_policy [options] politique

Ajoute une politique de mot de passe nommée politique à la base de données.

Cette commande nécessite le privilège add.

Alias : addpol

Les options suivantes sont disponibles :

-maxlife durée
(durée ou chaîne getdate) Définit la durée de vie maximale d'un mot de passe.
-minlife durée
(durée ou chaîne getdate) Définit la durée de vie minimale d'un mot de passe.
-minlength longueur
Définit la longueur minimale d'un mot de passe.
-minclasses nombre
Définit le nombre minimum de classes de caractères requis dans un mot de passe. Les cinq classes de caractères sont les minuscules, les majuscules, les chiffres, la ponctuation et les espaces/caractères non imprimables.
-history nombre
Définit le nombre de clés passées conservées pour un principal. Cette option n'est pas prise en charge par le module de base de données KDC LDAP.
-maxfailure maxnombre
Définit le nombre d'échecs d'authentification avant que le principal ne soit verrouillé. Les échecs d'authentification ne sont suivis que pour les principaux qui nécessitent une pré-authentification. Le compteur de tentatives échouées est réinitialisé à 0 après une tentative d'authentification réussie. Une valeur de maxnombre de 0 (par défaut) désactive le verrouillage.
-failurecountinterval temps_echec
(durée ou chaîne getdate) Définit le temps allowable entre les échecs d'authentification. Si un échec d'authentification se produit après l'expiration de temps_echec depuis le dernier échec, le nombre d'échecs d'authentification est réinitialisé à 1. Une valeur de temps_echec de 0 (par défaut) signifie pour toujours.
-lockoutduration temps_verrouillage
(durée ou chaîne getdate) Définit la durée pendant laquelle le principal est verrouillé de l'authentification si trop d'échecs d'authentification se produisent sans que l'intervalle de comptage d'échecs spécifié n'ait expiré. Une durée de 0 (par défaut) signifie que le principal reste verrouillé jusqu'à ce qu'il soit déverrouillé administrativement avec modprinc -unlock.
-allowedkeysalts
Spécifie les tuples clé/sel pris en charge pour les clés à long terme lors de la définition ou de la modification du mot de passe/des clés d'un principal. Voir Keysalt_lists dans kdc.conf(5) pour une liste des valeurs acceptées, mais notez que les tuples clé/sel doivent être séparés par des virgules (',') uniquement. Pour effacer la politique de clé/sel autorisée, utilisez une valeur de '-'.

Exemple:

kadmin: add_policy -maxlife "2 jours" -minlength 5 invités
kadmin:

modify_policy

modify_policy [options] politique

Modifie la politique de mot de passe nommée politique. Les options sont telles que décrites pour add_policy.

Cette commande nécessite le privilège modify.

Alias : modpol

delete_policy

delete_policy [-force] politique

Supprime la politique de mot de passe nommée politique. Demande une confirmation avant la suppression. La commande échouera si la politique est utilisée par des principaux.

Cette commande nécessite le privilège delete.

Alias : delpol

Exemple:

kadmin: del_policy invités
Êtes-vous sûr de vouloir supprimer la politique "invités" ?
(oui/non) : oui
kadmin:

get_policy

get_policy [ -terse ] politique

Affiche les valeurs de la politique de mot de passe nommée politique. Avec le drapeau -terse, les champs sont affichés sous forme de chaînes de caractères entourées de guillemets et séparées par des tabulations.

Cette commande nécessite le privilège inquire.

Alias : getpol

Exemples:

kadmin: get_policy admin
Politique : admin
Durée de vie maximale du mot de passe : 180 jours 00:00:00
Durée de vie minimale du mot de passe : 00:00:00
Longueur minimale du mot de passe : 6
Nombre minimum de classes de caractères de mot de passe : 2
Nombre de clés anciennes conservées : 5
Nombre de références : 17
kadmin: get_policy -terse admin
admin     15552000  0    6    2    5    17
kadmin:

Le "Nombre de références" est le nombre de principaux utilisant cette politique. Avec le module de base de données KDC LDAP, le champ du nombre de références n'a pas de sens.

list_policies

list_policies [expression]

Récupère tous les noms de politiques ou certains d'entre eux. expression est une expression de type glob de shell qui peut contenir les caractères joker ?, *, et []. Tous les noms de politiques correspondant à l'expression sont imprimés. Si aucune expression n'est fournie, tous les noms de politiques existants sont imprimés.

Cette commande nécessite le privilège list.

Alias : listpols, get_policies, getpols.

Exemples:

kadmin:  listpols
test-pol
dict-only
once-a-min
test-pol-nopw
kadmin:  listpols t*
test-pol
test-pol-nopw
kadmin:

ktadd

ktadd [options] principal
ktadd [options] -glob expression_principal

Ajoute un principal, ou tous les principaux correspondant à expression_principal, à un fichier keytab. Les clés de chaque principal sont randomisées pendant le processus. Les règles pour expression_principal sont décrites dans la commande list_principals.

Cette commande nécessite les privilèges inquire et changepw. Avec la forme -glob, elle nécessite également le privilège list.

Les options sont:

-k[eytab] keytab
Utilise keytab comme fichier keytab. Sinon, le keytab par défaut est utilisé.
-e enc:salt,...
Utilise la liste spécifiée de clés/sels pour définir les nouvelles clés du principal. Voir Keysalt_lists dans kdc.conf(5) pour une liste des valeurs possibles.
-q
Affiche moins d'informations.
-norandkey
Ne pas randomiser les clés. Les clés et leurs numéros de version restent inchangés. Cette option ne peut pas être spécifiée en combinaison avec l'option -e.

Une entrée pour chacun des types de chiffrement uniques du principal est ajoutée, en ignorant les clés multiples avec le même type de chiffrement mais des sels différents.

Alias : xst

Exemple:

kadmin: ktadd -k /tmp/foo-new-keytab host/foo.mit.edu
Entrée pour le principal host/foo.mit.edu@ATHENA.MIT.EDU avec kvno 3,
     type de chiffrement aes256-cts-hmac-sha1-96 ajoutée au fichier keytab
     FILE:/tmp/foo-new-keytab
kadmin:

ktremove

ktremove [options] principal [kvno | all | old]

Supprime les entrées du principal spécifié d'un fichier keytab. Ne nécessite aucune permission, car cela ne nécessite pas d'accès à la base de données.

Si la chaîne "all" est spécifiée, toutes les entrées de ce principal sont supprimées ; si la chaîne "old" est spécifiée, toutes les entrées de ce principal sauf celles avec le kvno le plus élevé sont supprimées. Sinon, la valeur spécifiée est analysée comme un entier, et toutes les entrées dont le kvno correspond à cet entier sont supprimées.

Les options sont:

-k[eytab] keytab
Utilise keytab comme fichier keytab. Sinon, le keytab par défaut est utilisé.
-q
Affiche moins d'informations.

Alias : ktrem

Exemple:

kadmin: ktremove kadmin/admin all
Entrée pour le principal kadmin/admin avec kvno 3 supprimée du fichier keytab
     FILE:/etc/krb5.keytab
kadmin:

lock

Verrouille la base de données de manière exclusive. À utiliser avec une extrême prudence ! Cette commande ne fonctionne qu'avec le module de base de données DB2 KDC.

unlock

Libère le verrouillage exclusif de la base de données.

list_requests
