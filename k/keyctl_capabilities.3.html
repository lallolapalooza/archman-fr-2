KEYCTL_CAPABILITIES(3) Appels de gestion de clés Linux KEYCTL_CAPABILITIES(3)

NOM

keyctl_capabilities - interroger les capacités du sous-système

SYNTAXE

#include <keyutils.h>

long keyctl_capabilities(unsigned char *buffer, size_t buflen);

DESCRIPTION

keyctl_capabilities() interroge le sous-système des keyrings dans le noyau pour poser des questions sur ses capacités et remplit le tableau dans le tampon avec des bits qui indiquent la présence ou l'absence de fonctionnalités spécifiques dans le sous-système des keyrings.

La fonction retourne la quantité de données disponibles pour le noyau, indépendamment de la quantité d'espace tampon disponible. Si le tampon est plus court que les données, une copie tronquée sera faite ; si le tampon est plus grand que les données, l'espace excédentaire sera effacé.

Si cette opération n'est pas disponible dans le noyau, la bibliothèque keyutils l'émulera au mieux et le bit de capacité indiquant si l'opération du noyau est disponible sera effacé.

Dans buffer[0], les capacités suivantes existent :

KEYCTL_CAPS0_CAPABILITIES
Ceci est défini si le noyau supporte cette opération et effacé sinon. Si c'est effacé, le reste des drapeaux est émulé.
KEYCTL_CAPS0_PERSISTENT_KEYRINGS
Ceci est défini si le noyau supporte les keyrings persistants et effacé sinon. Voir keyctl_get_persistent(3).
KEYCTL_CAPS0_DIFFIE_HELLMAN
Ceci est défini si le noyau supporte le calcul de Diffie-Hellman et effacé sinon. Voir keyctl_dh_compute(3).
KEYCTL_CAPS0_PUBLIC_KEY
Ceci est défini si le noyau supporte les opérations de clé publique et effacé sinon. Voir keyctl_pkey_query(3).
KEYCTL_CAPS0_BIG_KEY
Ceci est défini si le noyau supporte le type de clé big_key et effacé sinon.
KEYCTL_CAPS0_INVALIDATE
Ceci est défini si le noyau supporte l'invalidation de clé et effacé sinon. Voir keyctl_invalidate(3).
KEYCTL_CAPS0_RESTRICT_KEYRING
Ceci est défini si le noyau supporte les restrictions sur les keyrings et effacé sinon. Voir keyctl_restrict_keyring(3).
KEYCTL_CAPS0_MOVE
Ceci est défini si le noyau supporte l'opération de déplacement de clé et effacé sinon. Voir keyctl_move(3).

Dans buffer[1], les capacités suivantes existent :

KEYCTL_CAPS1_NS_KEYRING_NAME
Ceci est défini si les noms de keyring sont séparés selon l'espace de noms (user-namespace) dans lequel un keyring est créé.
KEYCTL_CAPS1_NS_KEY_TAG
Ceci est défini si une clé ou un keyring peut être marqué avec un espace de noms, permettant ainsi à plusieurs clés du même type et description, mais avec des étiquettes d'espace de noms différentes, de coexister dans le même keyring. L'étiquetage peut être automatique en fonction du type de clé. Seul l'étiquetage d'espace de noms réseau est actuellement utilisé.

VALEUR DE RETOUR

En cas de succès, keyctl_capabilities() retourne la taille des données disponibles, indépendamment de la taille du tampon. En cas d'erreur, la valeur -1 sera retournée et errno aura été défini avec une erreur appropriée.

ERREURS

EFAULT
Le tampon ne peut pas être écrit.

LIAISON

Il s'agit d'une fonction de bibliothèque qui peut être trouvée dans libkeyutils. Lors de la liaison, -lkeyutils doit être spécifié au lieur.

VOIR AUSSI
