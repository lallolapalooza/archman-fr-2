NOM

kubeone-migrate-to-ccm-csi - Migrer un cluster actif du fournisseur cloud intégré vers le gestionnaire de contrôleur cloud (CCM) externe et le plugin CSI

SYNTAXE

kubeone migrate to-ccm-csi [flags]

DESCRIPTION

Suite à la dépréciation du fournisseur cloud intégré (http://kep.k8s.io/2395), cette commande aide à migrer les clusters existants du fournisseur cloud intégré vers le gestionnaire de contrôleur cloud (CCM) externe et le plugin CSI.

Remarque : si votre cluster a été créé avec .cloudProvider.external activé, la migration CCM/CSI n'est pas nécessaire car le cluster utilise déjà un CCM externe.

La migration est actuellement disponible pour OpenStack et vSphere. D'autres fournisseurs seront ajoutés dans les futures versions de KubeOne.

La migration se déroule en deux phases :

•
Phase 1 : déployer le CCM externe et le plugin CSI, tout en laissant le fournisseur intégré activé. Le serveur API Kubernetes et le kube-controller-manager sont configurés pour :
  • utiliser les contrôleurs intégrés dans le CCM externe au lieu du fournisseur cloud intégré pour toutes les opérations liées au cloud
  • rediriger toutes les opérations liées aux volumes vers le plugin CSI. Les nœuds de travail existants continueront d'utiliser le fournisseur intégré (c'est pourquoi il est toujours laissé activé), par conséquent, tous les nœuds de travail gérés par machine-controller doivent être redéployés après la fin de la phase 1.
•
Phase 2 : compléter la migration CCM/CSI en désactivant complètement le fournisseur intégré. Pour déclencher la phase 2, les utilisateurs doivent exécuter la commande « kubeone migrate to-ccm-csi » avec le drapeau « --complete ». Cela doit être fait après le déploiement de tous les nœuds de travail gérés par machine-controller.

Assurez-vous de vous familiariser avec les exigences de migration CCM/CSI en consultant le document suivant : https://docs.kubermatic.com/kubeone/v1.10/guides/ccm-csi-migration/

OPTIONS

-y, --auto-approve[=false] approuver automatiquement le plan

--complete[=false] compléter la migration ccm/csi

-h, --help[=false] aide pour to-ccm-csi

OPTIONS HÉRITÉES DES COMMANDES PARENTES

-c, --credentials="" Fichier pour extraire les informations d'identification et les secrets

-d, --debug[=false] sortie de débogage avec trace de la pile

-l, --log-format="text" format pour la journalisation

-m, --manifest="./kubeone.yaml" Chemin vers la configuration KubeOne

-t, --tfjson="" Source pour la sortie terraform en JSON - à lire depuis stdin. Si le chemin est un fichier, le contenu sera utilisé. Si le chemin est un dictionnaire, terraform output -json est exécuté dans ce chemin

-v, --verbose[=false] sortie détaillée
