KAK(1) Manuel des commandes générales KAK(1)

NOM

kak — un éditeur de code inspiré de vim, orienté sélection

SYNOPIS

kak [-d] [-n] [-ro] [-c id_session | -s id_session] [-ui type_interface] [-e commande] [-E commande] [+ligne[:colonne] | +:] [fichier ...]

kak -f touches [-q] [-i suffixe] [fichier ...]

kak -p id_session

kak -l

kak -clear

kak -version

kak -help

DESCRIPTION

Kakoune est un éditeur de code fortement inspiré de vim(1) et vi(1). À ce titre, la plupart de ses commandes sont similaires à celles de vi(1), partageant son modèle «les frappes au clavier comme langage d'édition de texte».

Kakoune fonctionne en deux modes, normal et insertion. En mode insertion, les touches sont directement insérées dans le tampon courant. En mode normal, les touches sont utilisées pour manipuler la sélection courante et entrer en mode insertion.

Kakoune met fortement l'accent sur l'interactivité. La plupart des commandes fournissent des résultats immédiats et incrémentiels, tout en restant compétitives en termes de nombre de frappes avec vim.

Kakoune travaille sur des sélections, qui sont des intervalles de caractères orientés et inclusifs. Les sélections ont une ancre et un curseur. La plupart des commandes les déplacent tous les deux, sauf lors de l'extension d'une sélection, où le caractère d'ancrage reste fixe et le curseur se déplace.

Les options sont les suivantes :

-help
Affiche un message d'aide et quitte.
-version
Affiche la version de Kakoune et quitte.
-n
Ne charge pas le kakrc système. (souvent, /usr/share/kak/kakrc)
-l
Liste les sessions existantes.
-d
S'exécute en tant que session sans tête (requiert -s).
-e commande
Exécute la commande après la phase d'initialisation du client.
-E commande
Exécute la commande après la phase d'initialisation du serveur.
-f touches
Exécute Kakoune en mode 'filtre', comme sed(1). Pour l'entrée standard et chaque fichier nommé dans la ligne de commande, tout le tampon est sélectionné (comme avec %) puis les touches sont exécutées. La version filtrée de l'entrée standard est écrite sur la sortie standard. Tous les fichiers mentionnés dans la ligne de commande sont modifiés sur place, mais si -i est fourni, Kakoune crée une sauvegarde de la version originale.
-i suffixe
Sauvegarde les fichiers sur lesquels un filtre est appliqué, en utilisant le suffixe donné.
-q
Lorsqu'en mode 'filtre', ne pas afficher d'erreurs.
-p id_session
Envoie les commandes écrites sur l'entrée standard à la session id_session.
-c id_session
Se connecte à la session donnée id_session.
-s id_session
Définit le nom de la session courante à id_session.
-ui type
Sélectionne le type d'interface utilisateur, qui peut être terminal, dummy, ou json.
-clear
Supprime les sessions qui ont été terminées dans un état incorrect (par exemple, après un crash).
-ro
Commence en mode lecture seule, tous les tampons ouverts ne seront pas écrits sur le disque.
+ligne[:colonne] | +:
Spécifie une ligne et une colonne cibles pour le premier fichier. Lorsque le signe plus est suivi uniquement d'un deux-points, le curseur est envoyé à la dernière ligne du fichier.
fichier ...
Un ou plusieurs fichiers à éditer.

ENVIRONNEMENT

KAKOUNE_POSIX_SHELL
Remplace le shell POSIX utilisé pour l'expansion %sh{...}, qui est /bin/sh (sh(1)) s'il n'est pas défini.
KAKOUNE_CONFIG_DIR
Remplace l'emplacement du répertoire contenant la configuration utilisateur de Kakoune. S'il n'est pas défini, $XDG_CONFIG_HOME/kak est utilisé.
KAKOUNE_RUNTIME
Remplace l'emplacement du répertoire contenant les fichiers de support de Kakoune. S'il n'est pas défini, l'emplacement est déterminé à partir de l'emplacement du binaire de Kakoune.
XDG_CONFIG_HOME
Chemin vers le répertoire de configuration de l'utilisateur. S'il n'est pas défini, $HOME/.config est utilisé.
XDG_RUNTIME_DIR
Chemin vers les sockets de la session de l'utilisateur. S'il n'est pas défini, $TMPDIR/kakoune est utilisé.

FICHIERS

Dans les chemins documentés ci-dessous, <rtdir> fait référence au répertoire d'exécution, dont la valeur est déterminée par rapport au chemin du binaire de kak si $KAKOUNE_RUNTIME n'est pas défini : <rtdir> = <chemin_vers_binaire_kak>/../share/kak.

Si kak n'est pas démarré avec le commutateur -n, il chargera d'abord <rtdir>/kakrc, qui chargera à son tour les fichiers supplémentaires suivants :

  • Si le répertoire de configuration de l'utilisateur $KAKOUNE_CONF

NAME

kak — modal text editor

SYNOPSIS

kak [-d—-v—-l—-s session—-c session—-t file—-f file—-e cmd—-a cmd—-p] [files...]

DESCRIPTION

Kakoune is a modal text editor, inspired by the design of Vim. It is known for its two-step editing process (selection then action), multiple selection, and vertical alignment.

The kak command launches an instance of the Kakoune editor. It can be used to edit one or more files. If no files are specified, an empty buffer will be created.

-d
Launch a new Kakoune session in the background. This is useful for starting a server that subsequent clients can connect to.
-v
Print the version of Kakoune and exit.
-l
List available sessions and exit.
-s session
Connect to an existing session named session. If no session by that name exists, a new one is created.
-c session
Connect to an existing session named session. If no session by that name exists, print an error message and exit.
-t file
On startup, execute the command file in the new session. This is typically used to restore a previous editing session.
-f file
On startup, execute the contents of the file file as Kakoune script commands.
-e cmd
On startup, execute the Kakoune script command cmd.
-a cmd
On startup, append the Kakoune script command cmd to the list of commands to be executed.
-p
Read commands from standard input and execute them.

If multiple files are specified, they will be opened in separate buffers.

ENVIRONMENT

Kakoune looks for configuration files and scripts in the following locations, in order:

  1. $KAKOUNE_CONFIG_DIR/autoload/*.kak, if the directory exists, recursively load every *.kak file in it, and its sub-directories.
  2. If it does not exist, fall back to the system-wide autoload directory in <rtdir>/autoload, and recursively load all files in a similar way.
  3. <rtdir>/kakrc.local, if it exists; this is a user-defined system-wide configuration.
  4. $KAKOUNE_CONFIG_DIR/kakrc, if it exists; this is the user configuration.

Consequently, if the $KAKOUNE_CONFIG_DIR/autoload directory exists, only scripts stored within that directory will be loaded — the built-in *.kak files will not be.

Users who still want the built-in scripts to be loaded along their own can create a symbolic link to <rtdir>/autoload (or to individual scripts in it) in their user-configuration directory:

ln -s <rtdir>/autoload ${XDG_CONFIG_HOME:-$HOME/.config} /kak/autoload

EXAMPLES

Edit a file:
kak /path/to/file
Edit multiple files (multiple buffers will be created):
kak ./file1.txt /path/to/file2.c
Prepend a modeline that sets the tabstop to multiple files:
kak -f "ggO// kak: tabstop=8<esc>" *.c

SEE ALSO

For the complete on-line documentation, use the :doc command after starting kak.

NOM

kak — éditeur de texte modal

SYNOPIS

kak [-d—-v—-l—-s session—-c session—-t fichier—-f fichier—-e cmd—-a cmd—-p] [fichiers...]

DESCRIPTION

Kakoune est un éditeur de texte modal, inspiré par la conception de Vim. Il est connu pour son processus d'édition en deux étapes (sélection puis action), sa sélection multiple et son alignement vertical.

La commande kak lance une instance de l'éditeur Kakoune. Elle peut être utilisée pour éditer un ou plusieurs fichiers. Si aucun fichier n'est spécifié, un tampon vide sera créé.

-d
Lance une nouvelle session Kakoune en arrière-plan. Ceci est utile pour démarrer un serveur auquel les clients ultérieurs pourront se connecter.
-v
Affiche la version de Kakoune et quitte.
-l
Liste les sessions disponibles et quitte.
-s session
Se connecte à une session existante nommée session. Si aucune session de ce nom n'existe, une nouvelle est créée.
-c session
Se connecte à une session existante nommée session. Si aucune session de ce nom n'existe, affiche un message d'erreur et quitte.
-t fichier
Au démarrage, exécute la commande fichier dans la nouvelle session. Ceci est typiquement utilisé pour restaurer une session d'édition précédente.
-f fichier
Au démarrage, exécute le contenu du fichier fichier comme commandes de script Kakoune.
-e cmd
Au démarrage, exécute la commande de script Kakoune cmd.
-a cmd
Au démarrage, ajoute la commande de script Kakoune cmd à la liste des commandes à exécuter.
-p
Lit les commandes depuis l'entrée standard et les exécute.

Si plusieurs fichiers sont spécifiés, ils seront ouverts dans des tampons séparés.

ENVIRONNEMENT

Kakoune recherche les fichiers de configuration et les scripts dans les emplacements suivants, dans l'ordre :

  1. $KAKOUNE_CONFIG_DIR/autoload/*.kak, si le répertoire existe, charge récursivement chaque fichier *.kak qui s'y trouve, ainsi que ses sous-répertoires.
  2. S'il n'existe pas, il se rabat sur le répertoire d'autoload système dans <rtdir>/autoload, et charge récursivement tous les fichiers de manière similaire.
  3. <rtdir>/kakrc.local, s'il existe ; il s'agit d'une configuration système globale définie par l'utilisateur.
  4. $KAKOUNE_CONFIG_DIR/kakrc, s'il existe ; il s'agit de la configuration utilisateur.

Par conséquent, si le répertoire $KAKOUNE_CONFIG_DIR/autoload existe, seuls les scripts stockés dans ce répertoire seront chargés — les fichiers *.kak intégrés ne le seront pas.

Les utilisateurs qui souhaitent toujours que les scripts intégrés soient chargés avec les leurs peuvent créer un lien symbolique vers <rtdir>/autoload (ou vers des fichiers individuels qu'il contient) dans leur répertoire de configuration utilisateur :

ln -s <rtdir>/autoload ${XDG_CONFIG_HOME:-$HOME/.config} /kak/autoload

EXEMPLES

Éditer un fichier :
kak /chemin/vers/fichier
Éditer plusieurs fichiers (des tampons multiples seront créés) :
kak ./fichier1.txt /chemin/vers/fichier2.c
Ajouter au début une ligne de modèle qui définit la largeur de tabulation pour plusieurs fichiers :
kak -f "ggO// kak: tabstop=8<esc>" *.c

VOIR AUSSI

Pour la documentation complète en ligne, utilisez la commande :doc après avoir lancé kak.
