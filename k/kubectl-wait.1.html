NOM

kubectl wait - Expérimental : Attend une condition spécifique sur une ou plusieurs ressources

SYNTAXE

kubectl wait [OPTIONS]

DESCRIPTION

Expérimental : Attend une condition spécifique sur une ou plusieurs ressources.

La commande prend plusieurs ressources et attend jusqu'à ce que la condition spécifiée soit vue dans le champ Status de chaque ressource donnée.

Alternativement, la commande peut attendre que l'ensemble donné de ressources soit créé ou supprimé en fournissant le mot-clé "create" ou "delete" comme valeur au drapeau --for.

Un message de succès sera imprimé sur la sortie standard, indiquant quand la condition spécifiée a été remplie. Vous pouvez utiliser l'option -o pour changer la destination de la sortie.

OPTIONS

--all=false Sélectionne toutes les ressources dans l'espace de noms des types de ressources spécifiés

-A, --all-namespaces=false Si présent, liste les objets demandés à travers tous les espaces de noms. L'espace de noms du contexte actuel est ignoré même s'il est spécifié avec --namespace.

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--field-selector="" Sélecteur (requête de champ) pour filtrer, prend en charge '=', '==', et '!='. (ex. --field-selector key1=value1,key2=value2). Le serveur ne prend en charge qu'un nombre limité de requêtes de champ par type.

-f, --filename=[] identifiant la ressource.

--for="" La condition à attendre : [create|delete|condition=nom-condition[=valeur-condition]|jsonpath='{Expression JSONPath}'=[valeur JSONPath]]. La valeur de condition par défaut est true. Les valeurs de condition sont comparées après la mise en casse simple Unicode, qui est une forme plus générale d'insensibilité à la casse.

--local=false Si vrai, l'annotation ne contactera PAS le serveur d'API mais s'exécutera localement.

-o, --output="" Format de sortie. L'un des suivants : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

-R, --recursive=true Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', et '!='. (ex. -l key1=value1,key2=value2)

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lors de -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=30s La durée pendant laquelle attendre avant d'abandonner. Zéro signifie vérifier une seule fois et ne pas attendre, négatif signifie attendre une semaine.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression de réponse pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant le signalement de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. L'un des suivants (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée pendant laquelle attendre avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas dépasser les délais des requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Attend que le pod "busybox1" contienne la condition de statut de type "Ready"
  kubectl wait --for=condition=Ready pod/busybox1
  # La valeur par défaut de la condition de statut est true ; vous pouvez attendre d'autres cibles après un délimiteur égal (comparé après la mise en casse simple Unicode, qui est une forme plus générale d'insensibilité à la casse)
  kubectl wait --for=condition=Ready=false pod/busybox1
  # Attend que le pod "busybox1" ait une phase de statut "Running"
  kubectl wait --for=jsonpath='{.status.phase}'=Running pod/busybox1
  # Attend que le pod "busybox1" soit prêt
  kubectl wait --for='jsonpath={.status.conditions[?(@.type=="Ready")].status}=True' pod/busybox1
  # Attend que le service "loadbalancer" ait une entrée (ingress)
  kubectl wait --for=jsonpath='{.status.loadBalancer.ingress}' service/loadbalancer
  # Attend que le secret "busybox1" soit créé, avec un délai d'attente de 30s
  kubectl create secret generic busybox1
  kubectl wait --for=create secret/busybox1 --timeout=30s
  # Attend que le pod "busybox1" soit supprimé, avec un délai d'attente de 60s, après avoir émis la commande "delete"
  kubectl delete pod/busybox1
  kubectl wait --for=delete pod/busybox1 --timeout=60s
