NOM

kubeadm join phase control-plane-prepare control-plane - Générer les manifestes des nouveaux composants du plan de contrôle

SYNTAXE

kubeadm join phase control-plane-prepare control-plane [OPTIONS]

DESCRIPTION

Générer les manifestes des nouveaux composants du plan de contrôle.

OPTIONS

--apiserver-advertise-address="" Si le nœud doit héberger une nouvelle instance du plan de contrôle, l'adresse IP sur laquelle l'API Server annoncera qu'il écoute. Si elle n'est pas définie, l'interface réseau par défaut sera utilisée.

--apiserver-bind-port=6443 Si le nœud doit héberger une nouvelle instance du plan de contrôle, le port sur lequel l'API Server doit se lier.

--config="" Chemin vers un fichier de configuration kubeadm.

--control-plane=false Créer une nouvelle instance du plan de contrôle sur ce nœud.

--dry-run=false Ne pas appliquer de changements ; afficher uniquement ce qui serait fait.

--patches="" Chemin vers un répertoire contenant des fichiers nommés "target[suffix][+patchtype].extension". Par exemple, "kube-apiserver0+merge.yaml" ou simplement "etcd.json". "target" peut être l'un des éléments suivants : "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" peut être l'un des éléments suivants : "strategic", "merge" ou "json" et correspond aux formats de patch pris en charge par kubectl. Le "patchtype" par défaut est "strategic". "extension" doit être soit "json" soit "yaml". "suffix" est une chaîne optionnelle qui peut être utilisée pour déterminer quels patchs sont appliqués en premier par ordre alphabétique.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela obligera kubeadm à chrooter dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée.
