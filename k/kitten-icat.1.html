Nom

kitten-icat - Afficher des images dans le terminal

Aperçu

Afficher des images dans le terminal

Le kitten icat peut être utilisé pour afficher des images arbitraires dans le terminal kitty. L'utiliser est aussi simple que :

kitten icat image.jpeg

Il prend en charge tous les types d'images pris en charge par ImageMagick https://www.imagemagick.org. Il fonctionne même via SSH. Pour plus de détails, voir le protocole graphique de kitty <>.

Vous voudrez peut-être créer un alias dans vos fichiers de configuration shell :

alias icat="kitten icat"

Ensuite, vous pouvez simplement utiliser icat image.png pour visualiser des images.

Note :

ImageMagick https://www.imagemagick.org doit être installé pour la gamme complète de types d'images. Sans lui, seuls les formats PNG/JPG/GIF/BMP/TIFF/WEBP sont pris en charge.

Note :

Le protocole d'affichage d'images de kitty peut ne pas fonctionner lorsqu'il est utilisé à l'intérieur d'un multiplexeur de terminal tel que screen ou tmux, selon que le multiplexeur a ajouté ou non la prise en charge.

Le kitten icat possède divers arguments de ligne de commande pour lui permettre d'être utilisé depuis l'intérieur d'autres programmes pour afficher des images. En particulier, --place, --detect-support et --print-window-size.

Si vous essayez d'intégrer icat dans un programme complexe comme un gestionnaire de fichiers ou un éditeur, il y a quelques points à garder à l'esprit. icat fonctionne normalement en communiquant via le périphérique TTY, il écrit et lit depuis le TTY. Il est donc impératif que pendant son exécution, le programme hôte n'effectue aucune E/S TTY. Toute pression sur une touche ou toute autre entrée de l'utilisateur sur le périphérique TTY sera ignorée. Si vous souhaitez plutôt l'utiliser uniquement comme backend pour générer les codes d'échappement pour l'affichage d'images, vous devez lui passer des options pour lui indiquer les dimensions de la fenêtre, où placer l'image dans la fenêtre et le mode de transfert à utiliser. Si vous faites cela, il n'essaiera pas de communiquer du tout avec le périphérique TTY. Les options requises sont : --use-window-size, --place et --transfer-mode, --stdin=no. Par exemple, pour démontrer l'utilisation sans accès au TTY :

zsh -c 'setsid kitten icat --stdin=no --use-window-size $COLUMNS,$LINES,3000,2000 --transfer-mode=file myimage.png'

Ici, setsid garantit qu'icat n'a pas accès au périphérique TTY. Les valeurs 3000 et 2000 sont arbitraires. Ce sont la largeur et la hauteur de la fenêtre en pixels, pour lesquelles un accès au TTY est nécessaire.

Pour être vraiment robuste, vous devriez envisager d'écrire une prise en charge appropriée du protocole graphique de kitty <> dans le programme à la place. De nos jours, de nombreuses bibliothèques le prennent en charge.

Code source de icat

Le code source de ce kitten est disponible sur GitHub https://github.com/kovidgoyal/kitty/tree/master/kittens/icat.

Interface en ligne de commande

kitten icat [options] fichier-image-ou-url-ou-répertoire ...

Un utilitaire semblable à cat pour afficher des images dans le terminal. Vous pouvez spécifier plusieurs fichiers image et/ou répertoires. Les répertoires sont parcourus récursivement à la recherche de fichiers image. Si STDIN n'est pas un terminal, les données de l'image en seront également lues. Vous pouvez également spécifier des URL HTTP(S) ou FTP qui seront automatiquement téléchargées et affichées.

Options

--align <ALIGNEMENT>
Alignement horizontal de l'image affichée. Par défaut : center Choix : center, left, right
--place <POSITION>
Choisissez où afficher l'image à l'écran. L'image sera mise à l'échelle pour s'adapter au rectangle spécifié. La syntaxe pour spécifier les rectangles est <largeur>x<hauteur>@<gauche>x<haut>. Toutes les mesures sont en cellules (c'est-à-dire positions du curseur) avec l'origine (0, 0) dans le coin supérieur gauche de l'écran. Notez que l'option --align alignera horizontalement l'image à l'intérieur de ce rectangle. Par défaut, l'image est centrée horizontalement dans le rectangle. L'utilisation de place placera le curseur dans le coin supérieur gauche de l'image, au lieu de sur la ligne après l'image.
--scale-up [=no]
Lorsqu'utilisé en combinaison avec --place, il fera en sorte que les images plus petites que la zone spécifiée soient mises à l'échelle pour utiliser autant de la zone spécifiée que possible.
--background <ARRIÈRE-PLAN>
Spécifiez une couleur d'arrière-plan, ce qui entraînera la composition des images transparentes sur la couleur spécifiée. Par défaut : none
--mirror <MIROIR>
Miroir l'image sur un axe horizontal ou vertical, ou les deux. Par défaut : none Choix : both, horizontal, none, vertical
--clear [=no]
Supprime toutes les images actuellement affichées à l'écran. Notez que cela ne peut pas fonctionner avec des multiplexeurs de terminal tels que tmux, car seul le multiplexeur peut connaître la position de l'écran.
--transfer-mode <MODE_TRANSFERT>
Quel mécanisme utiliser pour transférer des images vers le terminal. La valeur par défaut est la détection automatique. file signifie utiliser un fichier temporaire, memory signifie utiliser la mémoire partagée, stream signifie envoyer les données via des codes d'échappement de terminal. Notez que si vous utilisez les modes de transfert file ou memory et que vous vous connectez via une session distante, l'affichage des images ne fonctionnera pas. Par défaut : detect Choix : detect, file, memory, stream
--detect-support [=no]
Détecte la prise en charge de l'affichage d'images dans le terminal. Si ce n'est pas pris en charge, se terminera avec le code de sortie 1, sinon se terminera avec le code 0 et affichera le mode de transfert pris en charge sur stderr, qui peut être utilisé avec l'option --transfer-mode.
--detection-timeout <TEMPS_DETECTION>
Le temps (en secondes) à attendre une réponse du terminal lors de la détection de la prise en charge de l'affichage d'images. Par défaut : 10
--use-window-size <TAILLE_FENETRE>
Au lieu de demander la taille de la fenêtre au terminal, utilisez la taille spécifiée, qui doit être au format : largeur_en_cellules,hauteur_en_cellules,largeur_en_pixels,hauteur_en_pixels
--print-window-size [=no]
Affiche la taille de la fenêtre sous la forme <largeur>x<hauteur> (en pixels) et quitte. C'est une méthode pratique pour interroger la taille de la fenêtre si vous utilisez kitten icat à partir d'un langage de script incapable d'effectuer des appels termios.
--stdin <STDIN>
Lire les données de l'image depuis STDIN. Par défaut, cela se fait automatiquement lorsque STDIN n'est pas un terminal, mais vous pouvez l'activer ou le désactiver explicitement si nécessaire. Par défaut : detect Choix : detect, no, yes
--silent [=no]
Non utilisé, présent pour des raisons de compatibilité héritée.

Source code for icat

icat is part of the kitty terminal emulator. Its source code can be found in the kitty repository.

Command line interface

The following options are available:

--engine <ENGINE>
Le moteur utilisé pour le décodage et le traitement des images. La valeur par défaut est d'utiliser le moteur le plus approprié. Le moteur builtin utilise les bibliothèques d'imagerie natives de Go. Le moteur magick utilise ImageMagick, ce qui nécessite son installation sur le système. Par défaut : auto Choix : auto, builtin, magick
--z-index <Z_INDEX>, -z <Z_INDEX>
Z-index de l'image. Lorsque négatif, le texte sera affiché par-dessus l'image. Utiliser un double trait d'union pour les valeurs inférieures au seuil de dessin des images sous les couleurs de fond des cellules. Par exemple, --1 est évalué comme -1 073 741 825. Par défaut : 0
--loop <LOOP>, -l <LOOP>
Nombre de fois où les animations doivent être répétées. Les valeurs négatives répètent indéfiniment. Zéro signifie que seule la première image de l'animation est affichée. Sinon, l'animation est répétée le nombre de fois spécifié. Par défaut : -1
--hold [=no]
Attendre une pression de touche avant de quitter après l'affichage des images.
--unicode-placeholder [=no]
Utiliser la méthode de l'espace réservé Unicode pour afficher les images. Utile pour afficher des images à partir de programmes de terminal plein écran qui ne comprennent pas le protocole graphique de kitty, tels que les multiplexeurs ou les éditeurs. Voir les espaces réservés Unicode <#graphics-unicode-placeholders> pour plus de détails. Notez que lors de l'utilisation de cette méthode, les images placées (avec --place) qui ne rentrent pas à l'écran seront renvoyées au bord de l'écran au lieu d'être tronquées. Ce renvoi est par ligne et par conséquent l'image semblera entrelacée avec des lignes vides.
--passthrough <PASSTHROUGH>
Indique s'il faut entourer les commandes graphiques de séquences d'échappement qui leur permettent de passer à travers des programmes comme tmux. La valeur par défaut est de détecter lorsqu'on exécute à l'intérieur de tmux et d'utiliser automatiquement les codes d'échappement de passage de tmux. Notez que lorsque cette option est activée, elle implique également --unicode-placeholder. Par défaut : detect Choix : detect, none, tmux
--image-id <IMAGE_ID>
L'identifiant du protocole graphique à utiliser pour l'image créée. Normalement, un identifiant aléatoire est créé si nécessaire. Cette option permet de contrôler l'identifiant. Lorsque plusieurs images sont envoyées, des identifiants séquentiels à partir de l'identifiant spécifié sont utilisés. Les identifiants valides vont de 1 à 4 294 967 295. Les nombres en dehors de cette plage sont automatiquement enveloppés. Par défaut : 0
--no-trailing-newline [=no], -n [=no]
Par défaut, le curseur est déplacé à la ligne suivante après l'affichage d'une image. Cette option l'empêche. Ne doit pas être utilisé lors de la visualisation de plusieurs images. N'a pas non plus d'effet lorsque l'option --place est utilisée.
