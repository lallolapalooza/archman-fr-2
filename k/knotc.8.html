NAME

knotc - utilitaire de contrôle de Knot DNS

SYNOPSIS

knotc [option_config] [options] [action]

DESCRIPTION

Ce programme contrôle un processus knotd en cours d'exécution à l'aide d'un socket.

Si une action est spécifiée, elle est effectuée et knotc se termine. Sinon, le programme est exécuté en mode interactif.

Options de configuration

-c, --config fichier
Utiliser un fichier de configuration textuel (par défaut /etc/knot/knot.conf).
-C, --confdb répertoire
Utiliser un répertoire de base de données de configuration binaire (par défaut /var/lib/knot/confdb). La base de données de configuration par défaut, si elle existe, a une préférence par rapport au fichier de configuration par défaut.

Options

-m, --max-conf-size MiB
Définir la taille maximale de la base de données de configuration (par défaut 500 MiB, maximum 10000 MiB).
-s, --socket chemin
Utiliser un chemin de socket UNIX de contrôle (par défaut /run/knot/knot.sock).
-t, --timeout secondes
Utiliser un délai d'attente de contrôle en secondes. Régler à 0 pour l'infini (par défaut 60). Les opérations du socket de contrôle sont également soumises au paramètre timeout défini côté serveur dans la section de configuration du serveur de contrôle.
-b, --blocking
Les commandes de déclenchement d'événements de zone attendent que l'événement soit terminé. Le délai d'attente de contrôle est défini à l'infini s'il n'est pas forcé par une spécification explicite de délai.
-e, --extended
Afficher la sortie étendue (même les éléments vides dans le statut de la zone).
-f, --force
Opération forcée. Remplace certaines vérifications.
-x, --mono
Ne pas générer de sortie colorisée.
-X, --color
Forcer la sortie colorisée dans la sortie étendue ou vers un tube.
-v, --verbose
Activer la sortie de débogage.
-h, --help
Afficher l'aide du programme.
-V, --version
Afficher la version du programme. L'option -VV fait afficher au programme le résumé de la configuration de compilation.

Actions

status [détail]
Vérifier si le serveur est en cours d'exécution. Les détails sont version pour la version du serveur en cours d'exécution, workers pour le nombre de threads de travail, configure pour le résumé de la configuration, ou cert-key pour le pin de la clé publique du certificat actuellement utilisé.
stop
Arrêter le serveur s'il est en cours d'exécution.
reload
Recharger la configuration du serveur et les fichiers de zone modifiés, et rouvrir les fichiers journaux s'ils sont configurés. Toutes les transactions de zone ouvertes seront annulées !
stats [module[.compteur]]
Afficher le(s) compteur(s) statistique(s) global(aux). Pour afficher également les compteurs avec une valeur de 0, utilisez l'option force.
zone-check [zone...]
Tester si le serveur peut charger la zone. Des vérifications sémantiques sont effectuées si elles sont activées dans la configuration. En cas d'appel avec l'option force, une erreur est retournée lorsqu'un avertissement de vérification sémantique apparaît. (*)
zone-status [zone...] [filtre]
Afficher le statut de la zone. Les filtres sont +role, +serial, +transaction, +events, +freeze, et +catalog. Les paramètres de zone vides sont omis, sauf si l'option --extended est utilisée. Un tiret unique dans la sortie représente une valeur non définie. La colorisation automatique peut être annulée en utilisant les options --mono et --color.

Le code couleur est : vert - la zone agit en tant que maître / rouge - la zone agit en tant que secondaire, police en gras (mise en évidence) - la zone est active / normal - la zone est vide, souligné - la zone est un membre de catalogue interprété.

zone-reload [zone...]
Déclencher un rechargement de la zone depuis un disque sans vérifier son heure de modification. Pour une zone secondaire, l'événement de rafraîchissement du serveur primaire est planifié ; pour une zone primaire, l'événement NOTIFY vers le(s) serveur(s) secondaire(s) est planifié. Une transaction de zone ouverte sera annulée ! En cas d'appel avec l'option force, les modules de zone seront également rechargés, mais le mode bloquant peut ne pas fonctionner de manière fiable. (#)
zone-refresh [zone...]
Déclencher une vérification du numéro de série de la zone sur le serveur primaire de la zone. Si le serveur primaire a une zone plus récente, un transfert est planifié. Cette commande est valide pour les zones secondaires. (#)
zone-retransfer [zone...]
Déclencher un transfert de zone depuis le serveur primaire de la zone. Le serveur ne vérifie pas le numéro de série de la zone du serveur primaire. Cette commande est valide pour les zones secondaires. (#)
zone-notify [zone...]
Déclencher un message NOTIFY vers tous les serveurs distants configurés. Cela peut être utile dans les cas où les NOTIFY précédents ont été perdus ou lorsque les serveurs secondaires étaient hors ligne. (#)
zone-flush [zone...] [+outdir répertoire]
Déclencher une purge du journal de zone vers le fichier de zone configuré. Si la synchronisation du fichier de zone est désactivée, l'option force doit être utilisée. Si un répertoire de sortie est spécifié, la zone actuelle est immédiatement vidée (en mode bloquant) dans un fichier de zone dans le répertoire spécifié. Voir Notes ci-dessous concernant les permissions du répertoire. (#)
zone-backup [zone...] +backupdir répertoire [filtre...]
Déclencher une sauvegarde des données et métadonnées de la zone dans un répertoire spécifié. Les filtres disponibles sont +zonefile, +journal, +timers, +kaspdb, +keysonly, +catalog, +quic, et leurs contreparties négatives +nozonefile, +nojournal, +notimers, +nokaspdb, +nokeysonly, +nocatalog, et +noquic. Avec ces filtres définis, le contenu de la zone, le journal de la zone, les timers liés à la zone, les données liées à la zone dans la base de données KASP ainsi que les clés (ou les clés sans la base de données KASP), le catalogue de la zone, et la clé et le certificat QUIC du serveur, respectivement, sont sauvegardés ou omis de la sauvegarde. Par défaut, les filtres +zonefile, +timers, +kaspdb, +catalog, +quic, +nojournal, et +nokeysonly sont définis pour la sauvegarde. Les mêmes valeurs par défaut sont définies pour la restauration, avec la seule différence de +noquic. La définition d'un filtre pour un élément ne modifie pas les paramètres par défaut pour les autres éléments. La seule exception est +keysonly, qui désactive tous les autres filtres par défaut, mais ils peuvent toujours être activés explicitement. Si la purge de la zone est désactivée, le fichier de zone d'origine est sauvegardé au lieu d'écrire le contenu de la zone dans un fichier. Lors de la sauvegarde d'une zone de catalogue, il est recommandé d'éviter les modifications en cours en utilisant zone-freeze. L'option force permet d'écraser un répertoire de sauvegarde déjà existant. Voir Notes ci-dessous concernant les permissions du répertoire. (#)
zone-restore [zone...] +backupdir répertoire [filtre...]
Déclencher une restauration des données et métadonnées de la zone à partir d'un répertoire de sauvegarde spécifié. Les filtres optionnels sont équivalents aux mêmes filtres de zone-backup. La restauration à partir de sauvegardes créées par des versions de Knot DNS antérieures à la 3.1 est possible avec l'option force.
catalog-add zone +zonefile fichier [+serial numéro] [+url URL] [+key clé] [+key-file fichier] [+predef-tags étiquettes] [+tags étiquettes]
Ajouter une zone au catalogue. Les balises peuvent être spécifiées avec l'option +tags ou +predef-tags. Les balises prédéfinies sont is-secondary, is-primary, is-cached, et is-empty. Par défaut, il n'y a aucune balise.
catalog-remove zone...
Supprimer une zone du catalogue.
catalog-update zone [+zonefile fichier] [+serial numéro] [+url URL] [+key clé] [+key-file fichier] [+predef-tags étiquettes] [+tags étiquettes]
Mettre à jour une zone du catalogue.
catalog-list [zone...] [filtre]
Afficher les zones du catalogue. Les filtres sont +tags, +serial, +zonefile, +url, +key, et +key-file.
zone-freeze [zone...]
Verrouiller la zone contre les modifications. Les modifications au journal de la zone seront mises en attente jusqu'à ce que la commande zone-unfreeze soit appelée.
zone-unfreeze [zone...]
Libérer la zone pour les modifications.
control port [address]
Lister les points de terminaison de contrôle et les paramètres de connectivité.
log-reopen
Rouvrir les fichiers journaux. Utile après la rotation des journaux.
conf-get module [paramètre]
Afficher la valeur d'un paramètre de configuration. Si le paramètre n'est pas spécifié, le module entier est affiché.
conf-set module.paramètre=valeur
Définir un paramètre de configuration. Notez que les modifications apportées de cette manière ne sont pas persistantes et seront perdues lors du redémarrage du serveur.
conf-commit
Appliquer les modifications apportées avec conf-set et les rendre persistantes.
conf-diff
Afficher les différences entre la configuration actuellement chargée et celle sur disque.
zone-add zone +zonefile fichier [+serial numéro]
Ajouter une nouvelle zone. La zone doit exister dans le fichier de configuration. L'option +serial est obligatoire pour les zones primaires si vous n'utilisez pas de fichier journal.
zone-remove zone...
Supprimer une zone.
zone-disable zone...
Désactiver une zone.
zone-enable zone...
Activer une zone.
zone-rkey [zone...]
Afficher les clés de pré-partage des zones secondaires.
dnskey-list [zone...]
Afficher les clés DNSSEC (DNSKEY) pour les zones spécifiées.
dnskey-generate zone alg [type]
Générer une nouvelle clé DNSSEC (Key Signing Key - KSK, ou Zone Signing Key - ZSK) pour une zone spécifiée avec un algorithme spécifié.
dnskey-delete zone id
Supprimer une clé DNSSEC (par son ID) pour une zone spécifiée.
dnskey-rollover zone id [+force]
Déclencher le rollover d'une clé DNSSEC spécifiée pour une zone.
kasp-list [zone...]
Lister la base de données KASP (Key and Signature Propagation) pour les zones spécifiées.
kasp-db-load zone [+force]
Charger la base de données KASP pour une zone spécifiée.
kasp-db-dump zone [+force]
Vider la base de données KASP pour une zone spécifiée.
kasp-db-remove zone...
Supprimer la base de données KASP pour les zones spécifiées.
tsig-key-list
Lister les clés TSIG configurées.
tsig-key-add nom secret alg
Ajouter une nouvelle clé TSIG.
tsig-key-remove nom
Supprimer une clé TSIG par son nom.
acl-list
Lister les listes de contrôle d'accès (ACL) configurées.
acl-add nom addrs...
Ajouter une nouvelle ACL.
acl-remove nom
Supprimer une ACL par son nom.
acl-update nom addrs...
Mettre à jour une ACL existante.
network-list
Lister les interfaces réseau et leurs adresses IP.
zone-rebuild [zone...]
Reconstruire la zone à partir du journal. Utile si le fichier de zone est corrompu. (#)
zone-notify-send zone serial
Envoyer manuellement un message NOTIFY pour la zone spécifiée avec le numéro de série donné. Les serveurs secondaires qui sont configurés pour recevoir des NOTIFY seront informés. (#)
zone-soa-edit zone [+serial numéro] [+email email] [+nsname nom_serveur]
Modifier les champs SOA de la zone spécifiée. Le champ +serial est obligatoire pour les zones primaires si le fichier journal n'est pas utilisé. Les modifications sont appliquées uniquement après un redémarrage du serveur ou une commande reload.
zone-update-policy [zone...]
Mettre à jour la politique de mise à jour des zones spécifiées. Utile après des modifications dans les paramètres de mise à jour DNS.

NOTES

Les commandes marquées d'un astérisque (*) ou d'un dièse (#) peuvent modifier l'état du serveur ou des zones. L'utilisation de la commande --force peut être nécessaire pour certaines opérations.

Les actions de sauvegarde et de restauration nécessitent que le répertoire spécifié par +backupdir soit accessible en écriture par l'utilisateur exécutant knotc. Si la synchronisation des fichiers de zone est désactivée, vous devrez utiliser l'option --force lors de l'exécution de zone-flush ou zone-backup pour garantir que les modifications sont écrites dans le fichier de zone.

EXIT STATUS

La commande knotc renvoie 0 en cas de succès, et une valeur supérieure à 0 en cas d'erreur.

knotc(8) - Arch Linux

NAME

knotc(8) — KNOT DNS record manipulation tool

SYNOPSIS

knotc [options] command [arguments]

DESCRIPTION

The knotc utility is used for zone data manipulation and configuration management of the KNOT DNS server.

It can be used to load zones, edit zone data, and manage the server configuration.

OPTIONS

The following options are available:

-c, --config=FILE
Use specified configuration file.
-d, --dns-conf=FILE
Use specified DNS configuration file.
-p, --pidfile=FILE
Use specified PID file.
-s, --socket=FILE
Use specified control socket.
-h, --help
Show help message.
-V, --version
Show version.

COMMANDS

The following commands are available:

conf-begin
Begin configuration transaction.
conf-commit
Commit configuration transaction.
conf-rollback
Rollback configuration transaction.
conf-read [KEY]
Read configuration value(s).
conf-set KEY=VALUE
Set configuration value.
zone-list
List all configured zones.
zone-load [ZONE]
Load zone(s).
zone-reconf [ZONE]
Reconfigure zone(s).
zone-reload [ZONE]
Reload zone(s).
zone-read [ZONE] [RRTYPE]
Read zone data.
zone-delete [ZONE]
Delete zone(s).
zone-tmpl-list
List all configured zone templates.
zone-tmpl-add NAME OPTIONS
Add zone template.
zone-tmpl-delete NAME
Delete zone template.
zone-tmpl-set NAME OPTIONS
Set zone template options.
zone-tmpl-get NAME
Get zone template options.
log-level [LEVEL]
Get or set log level.
log-get
Get current log settings.
shutdown
Shutdown the server.
restart
Restart the server.

EXIT VALUES

The exit status is 0 on success, and non-zero otherwise.

EXAMPLES

Get the primary servers for the example.com zone

$ knotc conf-read 'zone[example.com].master'

Add example.org zone with a zonefile location

$ knotc conf-begin
$ knotc conf-set 'zone[example.org]'
$ knotc conf-set 'zone[example.org].file' '/var/zones/example.org.zone'
$ knotc conf-commit

Get the SOA record for each configured zone

$ knotc zone-read -- @ SOA

SEE ALSO

knotd(8), knot.conf(5), editrc(5).
