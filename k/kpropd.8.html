NOM

kpropd - serveur de mise à jour KDC de réplique Kerberos V5

SYNTAXE

kpropd [-r domaine] [-A serveur_admin] [-a fichier_acl] [-f fichier_dump_replique] [-F base_donnees_principal] [-p programme_kdb5_util] [-P port] [--pid-file=fichier_pid] [-D] [-d] [-s fichier_keytab]

DESCRIPTION

La commande kpropd s'exécute sur le serveur KDC de réplique. Elle écoute les demandes de mise à jour effectuées par le programme kprop(8). Si la propagation incrémentielle est activée, elle demande périodiquement des mises à jour incrémentielles au KDC primaire.

Lorsque la réplique reçoit une demande kprop du primaire, kpropd accepte la base de données KDC déversée et la place dans un fichier, puis exécute kdb5_util(8) pour charger la base de données déversée dans la base de données active utilisée par krb5kdc(8). Cela permet au serveur Kerberos primaire d'utiliser kprop(8) pour propager sa base de données aux serveurs de réplique. Après un téléchargement réussi du fichier de base de données KDC, le serveur Kerberos de réplique disposera d'une base de données KDC à jour.

Là où la propagation incrémentielle n'est pas utilisée, kpropd est couramment invoqué par inetd(8) en tant que service nowait. Ceci est fait en ajoutant une ligne au fichier /etc/inetd.conf qui ressemble à ceci :

 kprop  stream  tcp  nowait  root  /usr/local/sbin/kpropd  kpropd

kpropd peut également s'exécuter en tant que démon autonome, se détachant et attendant les connexions sur le port 754 (ou le port spécifié avec l'option -P si elle est donnée). Le mode autonome est requis pour la propagation incrémentielle. À partir de la version 1.11, kpropd détecte automatiquement s'il a été exécuté depuis inetd et s'exécute en mode autonome s'il ne l'est pas. Avant la version 1.11, l'option -S était requise pour exécuter kpropd en mode autonome ; cette option est maintenant acceptée pour des raisons de compatibilité ascendante mais ne fait rien.

La propagation incrémentielle peut être activée avec la variable iprop_enable dans kdc.conf(5). Si la propagation incrémentielle est activée, la réplique interroge périodiquement le KDC primaire pour obtenir les mises à jour, à un intervalle déterminé par la variable iprop_replica_poll. Si la réplique reçoit des mises à jour, kpropd met à jour son fichier journal avec toutes les mises à jour du primaire. kproplog(8) peut être utilisé pour afficher un résumé du journal des entrées de mise à jour sur le KDC de réplique. Si la propagation incrémentielle est activée, le principal kiprop/nom_hote_replique@DOMAINE (où nom_hote_replique est le nom de l'hôte KDC de réplique et DOMAINE est le nom du domaine Kerberos) doit être présent dans le fichier keytab de la réplique.

kproplog(8) peut être utilisé pour forcer la réplication complète lorsque iprop est activé.

OPTIONS

-r domaine
Spécifie le domaine du serveur primaire.
-A serveur_admin
Spécifie le serveur à contacter pour les mises à jour incrémentielles ; par défaut, le serveur d'administration primaire est contacté.
-f fichier
Spécifie le nom du fichier où la base de données des principaux déversée doit être stockée ; par défaut, le fichier de base de données déversé est /var/lib/krb5kdc/from_master.
-F kerberos_db
Chemin d'accès au fichier de base de données Kerberos, si ce n'est pas celui par défaut.
-p
Permet à l'utilisateur de spécifier le chemin d'accès au programme kdb5_util(8) ; par défaut, le chemin utilisé est /usr/bin/kdb5_util.
-D
Dans ce mode, kpropd ne se détachera pas du travail en cours et ne s'exécutera pas en arrière-plan. Il s'exécutera au premier plan.
-d
Active le mode de débogage. kpropd affichera des messages de débogage pendant la propagation de la base de données et s'exécutera au premier plan (implique -D).
-P
Permet un numéro de port alternatif pour que kpropd écoute. Ceci n'est utile qu'en combinaison avec l'option -S.
-a fichier_acl
Permet à l'utilisateur de spécifier le chemin d'accès au fichier kpropd.acl ; par défaut, le chemin utilisé est /var/lib/krb5kdc/kpropd.acl.
--pid-file=fichier_pid
En mode autonome, écrit l'identifiant du processus du démon dans fichier_pid.
-s fichier_keytab
Chemin d'accès à un keytab à utiliser pour acquérir les identifiants de l'accepteur.
-x db_args
Arguments spécifiques à la base de données. Voir Options de base de données dans kadmin(1) pour les arguments pris en charge.

FICHIERS

kpropd.acl
Fichier d'accès pour kpropd ; l'emplacement par défaut est /usr/local/var/krb5kdc/kpropd.acl. Chaque entrée est une ligne contenant le principal d'un hôte à partir duquel la machine locale autorisera la propagation de la base de données Kerberos via kprop(8).

ENVIRONNEMENT

Voir kerberos(7) pour une description des variables d'environnement Kerberos.
