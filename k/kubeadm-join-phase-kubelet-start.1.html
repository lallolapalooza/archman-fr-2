NOM

kubeadm join phase kubelet-start - Écrit les paramètres du kubelet, les certificats et redémarre le kubelet

SYNTAXE

kubeadm join phase kubelet-start [OPTIONS]

DESCRIPTION

Écrit un fichier avec KubeletConfiguration et un fichier d'environnement avec les paramètres spécifiques du nœud pour le kubelet, puis redémarre le kubelet.

OPTIONS

--config="" Chemin vers un fichier de configuration kubeadm.

--cri-socket="" Chemin vers la socket CRI pour se connecter. Si vide, kubeadm essaiera de détecter automatiquement cette valeur ; utilisez cette option uniquement si vous avez plusieurs CRI installés ou si vous avez une socket CRI non standard.

--discovery-file="" Pour la découverte basée sur des fichiers, un fichier ou une URL à partir desquels charger les informations du cluster.

--discovery-token="" Pour la découverte basée sur des jetons, le jeton utilisé pour valider les informations du cluster récupérées du serveur API.

--discovery-token-ca-cert-hash=[] Pour la découverte basée sur des jetons, valide que la clé publique racine du CA correspond à ce hachage (format : « : »).

--discovery-token-unsafe-skip-ca-verification=false Pour la découverte basée sur des jetons, autorise la jonction sans épinglage de --discovery-token-ca-cert-hash.

--dry-run=false N'appliquez aucune modification ; affichez seulement ce qui serait fait.

--node-name="" Spécifiez le nom du nœud.

--patches="" Chemin vers un répertoire contenant des fichiers nommés « target[suffix][+patchtype].extension ». Par exemple, « kube-apiserver0+merge.yaml » ou juste « etcd.json ». « target » peut être l'un des éléments suivants : « kube-apiserver », « kube-controller-manager », « kube-scheduler », « etcd », « kubeletconfiguration », « corednsdeployment ». « patchtype » peut être l'un des éléments suivants : « strategic », « merge » ou « json » et ils correspondent aux formats de patch pris en charge par kubectl. Le « patchtype » par défaut est « strategic ». « extension » doit être soit « json » soit « yaml ». « suffix » est une chaîne optionnelle qui peut être utilisée pour déterminer quels patchs sont appliqués en premier par ordre alphanumérique.

--tls-bootstrap-token="" Spécifiez le jeton utilisé pour s'authentifier temporairement auprès du plan de contrôle Kubernetes lors de la jonction du nœud.

--token="" Utilisez ce jeton pour le discovery-token et le tls-bootstrap-token lorsque ces valeurs ne sont pas fournies.

OPTIONS INHERITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à utiliser chroot dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée
