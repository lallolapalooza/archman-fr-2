NOM

kubectl create configmap - Créer une configmap à partir d'un fichier local, d'un répertoire ou d'une valeur littérale

SYNOPSIS

kubectl create configmap [OPTIONS]

DESCRIPTION

Crée une configmap basée sur un fichier, un répertoire ou une valeur littérale spécifiée.

Une seule configmap peut regrouper une ou plusieurs paires clé/valeur.

Lors de la création d'une configmap basée sur un fichier, la clé sera par défaut le nom de base du fichier et la valeur le contenu du fichier. Si le nom de base n'est pas une clé valide, vous pouvez spécifier une clé alternative.

Lors de la création d'une configmap basée sur un répertoire, chaque fichier dont le nom de base est une clé valide dans le répertoire sera inclus dans la configmap. Toutes les entrées de répertoire autres que les fichiers réguliers sont ignorées (par exemple, sous-répertoires, liens symboliques, périphériques, tubes, etc.).

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--append-hash=false Ajoute un hash de la configmap à son nom.

--dry-run="none" Doit être "none", "server", ou "client". Si stratégie client, imprime seulement l'objet qui serait envoyé, sans l'envoyer. Si stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--from-env-file=[] Spécifie le chemin d'un fichier pour lire des lignes de paires clé=valeur afin de créer une configmap.

--from-file=[] La clé du fichier peut être spécifiée en utilisant son chemin, auquel cas le nom de base du fichier sera utilisé comme clé de configmap, ou éventuellement avec une clé et un chemin de fichier, auquel cas la clé donnée sera utilisée. La spécification d'un répertoire itérera chaque fichier nommé dans le répertoire dont le nom de base est une clé de configmap valide.

--from-literal=[] Spécifie une clé et une valeur littérale à insérer dans la configmap (par exemple, mykey=somevalue)

-o, --output="" Format de sortie. L'un de : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si vrai, la configuration de l'objet actuel sera sauvegardée dans son annotation. Sinon, l'annotation restera inchangée. Ce drapeau est utile lorsque vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un de : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si elle est invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le api-server, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectueront aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

OPTIONS HÉRITÉES DES COMMANDESPARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié quant à sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. L'un de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie pas de délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Créer une nouvelle configmap nommée my-config basée sur le dossier bar
  kubectl create configmap my-config --from-file=chemin/vers/bar
  # Créer une nouvelle configmap nommée my-config avec des clés spécifiées au lieu des noms de base de fichiers sur disque
  kubectl create configmap my-config --from-file=cle1=/chemin/vers/bar/fichier1.txt --from-file=cle2=/chemin/vers/bar/fichier2.txt
  # Créer une nouvelle configmap nommée my-config avec clé1=config1 et clé2=config2
  kubectl create configmap my-config --from-literal=cle1=config1 --from-literal=cle2=config2
  # Créer une nouvelle configmap nommée my-config à partir du fichier
  kubectl create configmap my-config --from-file=chemin/vers/bar
  # Créer une nouvelle configmap nommée my-config à partir d'un fichier .env
  kubectl create configmap my-config --from-env-file=chemin/vers/foo.env --from-env-file=chemin/vers/bar.env
