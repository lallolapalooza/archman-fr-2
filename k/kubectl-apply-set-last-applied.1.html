kubectl-apply-set-last-applied(1)

Eric Paris Jan 2015

NOM

kubectl apply set-last-applied - Définit l'annotation last-applied-configuration sur un objet en direct pour correspondre au contenu d'un fichier

SYNTAXE

kubectl apply set-last-applied [OPTIONS]

DESCRIPTION

Définit la dernière annotation last-applied-configuration en la faisant correspondre au contenu d'un fichier. Cela a pour effet de mettre à jour la dernière configuration appliquée comme si 'kubectl apply -f ' avait été exécuté, sans mettre à jour aucune autre partie de l'objet.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant(e) dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--create-annotation=false Crée les annotations 'last-applied-configuration' si l'objet actuel n'en a pas.

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est 'client', imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est 'server', soumet une requête côté serveur sans persister la ressource.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers contenant les annotations last-applied-configuration.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle utilise les modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce flag peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut.

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification.

--client-certificate="" Chemin vers un fichier de certificat client pour TLS.

--client-key="" Chemin vers un fichier de clé client pour TLS.

--cluster="" Nom du cluster kubeconfig à utiliser.

--context="" Nom du contexte kubeconfig à utiliser.

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur.

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant KUBECTL_KUBERC=false feature gate ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client.

-n, --namespace="" Si présent, le scope du namespace pour cette requête CLI.

--password="" Mot de passe pour l'authentification basique auprès du serveur API.

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex).

--profile-output="profile.pprof" Nom du fichier où écrire le profil.

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie qu'il n'y a pas de délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes.

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton d'authentification (Bearer token) auprès du serveur API.

--user="" Nom de l'utilisateur kubeconfig à utiliser.

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée.

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul.

EXEMPLE

  # Définir la last-applied-configuration d'une ressource pour correspondre au contenu d'un fichier
  kubectl apply set-last-applied -f deploy.yaml
  # Exécuter set-last-applied sur chaque fichier de configuration dans un répertoire
  kubectl apply set-last-applied -f path/
  # Définir la last-applied-configuration d'une ressource pour correspondre au contenu d'un fichier ; l'annotation sera créée si elle n'existe pas déjà
  kubectl apply set-last-applied -f deploy.yaml --create-annotation=true
