DESCRIPTION
Ces fonctionscréent undescripteur kbuffer qui
peut être
utilisé pour

analyse

r

les sous-tampons bruts du tampon circulaire de traçage du noyau Linux. Le tampon circulaire se trouve dans le répertoire tracefs et peut être récupéré par tracefs_instance_get_file(3) à per_cpu/cpuX/trace_pipe_raw où X est remplacé par le numéro de CPU correspondant du tampon circulaire spécifié. Le tampon circulaire à l'intérieur du noyau est divisé par CPU, de sorte que le tampon circulaire brut doit également être récupéré par CPU. La fonction kbuffer_alloc()

créera

un descripteur qui peut être utilisé pour gérer un sous-tampon lu par le tampon circulaire. Le paramètre size indique la taille de mot pour le tampon donné (notez que cela fonctionne pour la lecture de données brutes provenant de machines autres que celle qui appelle cette fonction). Le paramètre endian indique l'endianness de la machine. Si endian

est

défini à KBUFFER_ENDIAN_SAME_AS_HOST, l'endianness sera définie sur la même que celle de l'hôte, ce qui est utile lorsque l'application lit les données du tampon circulaire directement depuis la même machine sur laquelle elle

s'exécute.

Si size est défini à KBUFFER_LSIZE_SAME_AS_HOST, si la taille de mot est 8, le descripteur kbuffer sera défini sur une taille longue de 8. Mais si la taille est 4, alors il effectuera un appel uname(2), et si le champ machine contient la chaîne "64", il sera défini sur une taille longue de 8 octets et non 4. Cela est dû au fait que la taille longue du tampon circulaire dépend du noyau et non de

l'espace

u tilisateur. La fonction kbuffer_dup() dupliquera une structure kbuffer existante en en allouant une nouvelle. Elle aura toutes les propriétés du kbuf passé, y compris le pointage vers le même sous-tampon qui a été chargé dans le kbuf. Elle doit être libérée avec kbuffer_

free()

. La fonction kbuffer_free() libérera les ressources créées par kbuffer_alloc

(). La

f onction kbuffer_load_subbuffer() prend un subbuffer qui est un bloc de données brut du fichier tracefs trace_pipe_raw. Le tampon circulaire de traçage de Linux est divisé en sous-tampons. Chaque sous-tampon est un segment de données autonome qui contient toutes les informations nécessaires pour extraire les événements individuels et les horodatages. C'est ce sous-tampons

que

kbuffer utilise pour parcourir les événements. La fonction kbuffer_subbuffer_size() renvoie l'emplacement de la fin du dernier événement sur le sous-tampon.

Elle

ne renvoie pas la taille du sous-tampon lui-même. La fonction kbuffer_refresh() doit être utilisée si des écritures supplémentaires ont été effectuées sur le kbuffer chargé, où la taille du kbuffer doit être actualisée pour pouvoir lire les

nouveaux

événements qui ont été écrits depuis le dernier appel à kbuffer_load_subbuffer(). Notez qu'aucune barrière mémoire n'est implémentée avec cette fonction

et

que toute synchronisation avec l'écrivain est de la responsabilité de l'application. La fonction kbuffer_start_of_data(

)

The renvoie le décalage où le chargement réel des données du sous-tampon commence. La fonction kbuffer_subbuffer() renvoie le pointeur vers le sous-tampon actuellement chargé. C'est-à-
