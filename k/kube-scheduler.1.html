NOM

kube-scheduler -

SYNTAXE

kube-scheduler [OPTIONS]

DESCRIPTION

Le planificateur Kubernetes est un processus de plan de contrôle qui attribue des Pods à des Nœuds. Le planificateur détermine quels Nœuds sont des emplacements valides pour chaque Pod dans la file d'attente de planification, conformément aux contraintes et aux ressources disponibles. Le planificateur classe ensuite chaque Nœud valide et lie le Pod à un Nœud approprié. Plusieurs planificateurs différents peuvent être utilisés au sein d'un cluster ; kube-scheduler est l'implémentation de référence. Voir planification ⟨https://kubernetes.io/docs/concepts/scheduling-eviction/⟩ pour plus d'informations sur la planification et le composant kube-scheduler.

--allow-metric-labels-manifest="" Le chemin d'accès au fichier manifeste contenant la liste d'autorisation. Le format du fichier est identique à celui du drapeau --allow-metric-labels. Notez que le drapeau --allow-metric-labels remplacera le fichier manifeste.

--emulated-version=[] Les versions que différents composants émulant leurs capacités (API, fonctionnalités, ...) de. -h, --help=false Aide pour kube-scheduler

--http2-max-streams-per-connection=0 La limite que le serveur impose aux clients pour le nombre maximum de flux dans une connexion HTTP/2. Zéro signifie utiliser la valeur par défaut de golang.

--kube-api-burst=100 DEPRECATED : rafale à utiliser lors des communications avec le apiserver Kubernetes. Ce paramètre est ignoré si un fichier de configuration est spécifié dans --config.

--kube-api-content-type="application/vnd.kubernetes.protobuf" DEPRECATED : type de contenu des requêtes envoyées au apiserver. Ce paramètre est ignoré si un fichier de configuration est spécifié dans --config.

--kube-api-qps=50 DEPRECATED : QPS à utiliser lors des communications avec le apiserver Kubernetes. Ce paramètre est ignoré si un fichier de configuration est spécifié dans --config.

--kubeconfig="" DEPRECATED : chemin vers le fichier kubeconfig avec les informations d'autorisation et d'emplacement du master. Ce paramètre est ignoré si un fichier de configuration est spécifié dans --config.

--leader-elect=true Démarre un client d'élection de leader et acquiert la direction avant d'exécuter la boucle principale. Activez ceci lors de l'exécution de composants répliqués pour une haute disponibilité.

--leader-elect-lease-duration=15s La durée pendant laquelle les candidats non-leaders attendront après avoir observé un renouvellement de direction avant de tenter d'acquérir la direction d'un emplacement de leader dirigé mais non renouvelé. Ceci est effectivement la durée maximale pendant laquelle un leader peut être arrêté avant d'être remplacé par un autre candidat. Ceci n'est applicable que si l'élection de leader est activée.

--leader-elect-renew-deadline=10s L'intervalle entre les tentatives du maître actuel de renouveler un emplacement de direction avant qu'il ne cesse de diriger. Ceci doit être inférieur à la durée du bail. Ceci n'est applicable que si l'élection de leader est activée.

--leader-elect-resource-lock="leases" Le type d'objet ressource utilisé pour le verrouillage lors de l'élection de leader. Les options prises en charge sont 'leases'.

--leader-elect-resource-name="kube-scheduler" Le nom de l'objet ressource utilisé pour le verrouillage lors de l'élection de leader.

--leader-elect-resource-namespace="kube-system" Le namespace de l'objet ressource utilisé pour le verrouillage lors de l'élection de leader.

--leader-elect-retry-period=2s La durée pendant laquelle les clients doivent attendre entre les tentatives d'acquisition et de renouvellement de la direction. Ceci n'est applicable que si l'élection de leader est activée.

--log-flush-frequency=5s Nombre maximum de secondes entre les vidages de logs

--log-text-info-buffer-size=0 [Alpha] En format texte avec flux de sortie séparés, les messages d'information peuvent être mis en mémoire tampon pendant un certain temps pour augmenter les performances. La valeur par défaut de zéro octet désactive la mise en mémoire tampon. La taille peut être spécifiée en nombre d'octets (512), en multiples de 1000 (1K), en multiples de 1024 (2Ki) ou en puissances de ceux-ci (3M, 4G, 5Mi, 6Gi). Activez le portail de fonctionnalités LoggingAlphaOptions pour l'utiliser.

--log-text-split-stream=false [Alpha] En format texte, écrire les messages d'erreur sur stderr et les messages d'information sur stdout. La valeur par défaut est d'écrire un seul flux sur stdout. Activez le portail de fonctionnalités LoggingAlphaOptions pour l'utiliser.

--logging-format="text" Définit le format des logs. Formats autorisés : "text".

--master="" L'adresse du serveur API Kubernetes (remplace toute valeur dans kubeconfig)

--permit-address-sharing=false Si vrai, SO_REUSEADDR sera utilisé lors de la liaison du port. Cela permet de lier simultanément des IP génériques comme 0.0.0.0 et des IP spécifiques, et évite d'attendre que le noyau libère les sockets en état TIME_WAIT. [par défaut=false]

--permit-port-sharing=false Si vrai, SO_REUSEPORT sera utilisé lors de la liaison du port, ce qui permet à plus d'une instance de se lier à la même adresse et au même port. [par défaut=false]

--pod-max-in-unschedulable-pods-duration=5m0s DEPRECATED : le temps maximum qu'un pod peut rester dans unschedulablePods. Si un pod reste dans unschedulablePods plus longtemps que cette valeur, le pod sera déplacé de unschedulablePods vers backoffQ ou activeQ. Ce drapeau est déprécié et sera supprimé dans une future version.

--profiling=true DEPRECATED : active le profilage via l'interface web host:port/debug/pprof/. Ce paramètre est ignoré si un fichier de configuration est spécifié dans --config.

--requestheader-allowed-names=[] Liste des noms communs de certificats clients autorisés à fournir des noms d'utilisateur dans les en-têtes spécifiés par --requestheader-username-headers. Si vide, tout certificat client validé par les autorités dans --requestheader-client-ca-file est autorisé.

--requestheader-client-ca-file="" Bundle de certificats racine à utiliser pour vérifier les certificats clients sur les requêtes entrantes avant de faire confiance aux noms d'utilisateur dans les en-têtes spécifiés par --requestheader-username-headers. ATTENTION : ne vous fiez généralement pas à l'autorisation déjà effectuée pour les requêtes entrantes.

--requestheader-extra-headers-prefix=[x-remote-extra-] Liste des préfixes d'en-tête de requête à inspecter. X-Remote-Extra- est suggéré.

--requestheader-group-headers=[x-remote-group] Liste des en-têtes de requête à inspecter pour les groupes. X-Remote-Group est suggéré.

--requestheader-uid-headers=[] Liste des en-têtes de requête à inspecter pour les UID. X-Remote-Uid est suggéré. Nécessite que la fonctionnalité RemoteRequestHeaderUID soit activée.

--requestheader-username-headers=[x-remote-user] Liste des en-têtes de requête à inspecter pour les noms d'utilisateur. X-Remote-User est courant.

--secure-port=10259 Le port sur lequel servir HTTPS avec authentification et autorisation. Si 0, ne pas servir HTTPS du tout.

--show-hidden-metrics-for-version="" La version précédente pour laquelle vous souhaitez afficher les métriques masquées. Seule la version mineure précédente a un sens, les autres valeurs ne seront pas autorisées. Le format est ., par exemple : '1.16'. Le but de ce format est de s'assurer que vous avez la possibilité de remarquer si la prochaine version masque des métriques supplémentaires, plutôt que d'être surpris lorsqu'elles sont définitivement supprimées dans la version suivante.

--tls-cert-file="" Fichier contenant le certificat x509 par défaut pour HTTPS. (Certificat CA, le cas échéant, concaténé après le certificat serveur). Si le service HTTPS est activé, et que --tls-cert-file et --tls-private-key-file ne sont pas fournis, un certificat et une clé auto-signés sont générés pour l'adresse publique et enregistrés dans le répertoire spécifié par --cert-dir.

--tls-cipher-suites

=[] Liste de suites de chiffrement séparées par des virgules pour le serveur. Si omis, les suites de chiffrement Go par défaut seront utilisées. Valeurs préférées : TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256. Valeurs non sécurisées : TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, TLS_ECDHE_RSA_WITH_3DES_EDE_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_RSA_WITH_RC4_128_SHA, TLS_RSA_WITH_3DES_EDE_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA256, TLS_RSA_WITH_AES_128_GCM_SHA256, TLS_RSA_WITH_AES_256_CBC_SHA, TLS_RSA_WITH_AES_256_GCM_SHA384, TLS_RSA_WITH_RC4_128_SHA.

--tls-min-version="" Version TLS minimale supportée. Valeurs possibles : VersionTLS10, VersionTLS11, VersionTLS12, VersionTLS13

--tls-private-key-file="" Fichier contenant la clé privée x509 par défaut correspondant au --tls-cert-file.

--tls-sni-cert-key=[] Une paire de chemins de fichiers de certificat x509 et de clé privée, éventuellement suffixés par une liste de modèles de domaine qui sont des noms de domaine entièrement qualifiés, éventuellement avec des segments de wildcard préfixés. Les modèles de domaine autorisent également les adresses IP, mais les adresses IP ne doivent être utilisées que si l'apiserver a une visibilité sur l'adresse IP demandée par un client. Si aucun modèle de domaine n'est fourni, les noms du certificat sont extraits. Les correspondances sans wildcard l'emportent sur les correspondances avec wildcard, les modèles de domaine explicites l'emportent sur les noms extraits. Pour plusieurs paires clé/certificat, utilisez --tls-sni-cert-key plusieurs fois. Exemples : "example.crt,example.key" ou "foo.crt,foo.key:*.foo.com,foo.com".

-v, --v=0 nombre pour le niveau de verbosité du journal

--write-config-to="" Si défini, écrit les valeurs de configuration dans ce fichier et quitte.
