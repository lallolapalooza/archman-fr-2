KILL(1) Commandes utilisateur KILL(1)

NOM

kill - terminer un processus

SYNTAXE

kill [-signal|-s signal|-p] [-q valeur] [-a] [--timeout millisecondes signal] [--] pid|nom...

kill -l [nombre|0xsigmask] | -L

kill -d pid

DESCRIPTION

La commande kill envoie le signal spécifié aux processus ou groupes de processus spécifiés.

Si aucun signal n'est spécifié, le signal TERM est envoyé. L'action par défaut pour ce signal est de terminer le processus. Ce signal doit être utilisé de préférence au signal KILL (numéro 9), car un processus peut installer un gestionnaire pour le signal TERM afin d'effectuer des étapes de nettoyage avant de se terminer de manière ordonnée. Si un processus ne se termine pas après l'envoi d'un signal TERM, le signal KILL peut alors être utilisé ; sachez que ce dernier signal ne peut pas être intercepté et ne donne donc pas au processus cible l'opportunité d'effectuer un quelconque nettoyage avant de se terminer.

La plupart des shells modernes ont une commande kill intégrée, avec une utilisation assez similaire à celle de la commande décrite ici. Les options --all, --pid et --queue, ainsi que la possibilité de spécifier des processus par nom de commande, sont des extensions locales.

Si signal est 0, alors aucun signal réel n'est envoyé, mais la vérification des erreurs est toujours effectuée.

ARGUMENTS

La liste des processus à signaler peut être un mélange de noms et de PID.

pid

Chaque pid peut être exprimé de l'une des manières suivantes :

n

où n est supérieur à 0. Le processus avec le PID n est signalé.

0

Tous les processus du groupe de processus courant sont signalés.

-1

Tous les processus avec un PID supérieur à 1 sont signalés.

-n

où n est supérieur à 1. Tous les processus du groupe de processus n sont signalés. Lorsqu'un argument de la forme '-n' est donné, et qu'il est censé désigner un groupe de processus, soit un signal doit être spécifié en premier, soit l'argument doit être précédé de l'option '--', sinon il sera pris comme signal à envoyer.

nom

Tous les processus invoqués en utilisant ce nom seront signalés.

OPTIONS

-s, --signal signal

Le signal à envoyer. Il peut être donné sous forme de nom ou de numéro.

-l, --list [nombre|0xsigmask]

Affiche une liste de noms de signaux, convertit le numéro de signal donné en nom, ou convertit le masque de signal donné en noms. Les signaux peuvent être trouvés dans /usr/include/linux/signal.h. 
$ ps s $$
  UID     PID          PENDING          BLOCKED          IGNORED           CAUGHT STAT TTY        TIME COMMAND
 1000 1608069 0000000000000000 0000000000000002 0000000000384000 0000000008013003 Ss   pts/44     0:02 zsh
$ kill -l 0x0000000000384000
TERM
TSTP
TTIN
TTOU

-L, --table

Similaire à -l, mais affiche les noms de signaux et leurs numéros correspondants.

-a, --all

Ne limite pas la conversion nom de commande vers PID aux processus ayant le même UID que le processus actuel.

-p, --pid

Affiche seulement le PID (identifiant de processus) des processus nommés, n'envoie aucun signal.

-r, --require-handler

N'envoie pas le signal s'il n'est pas intercepté en espace utilisateur par le processus signalé.

--verbose

Affiche les PID qui seront signalés avec kill, ainsi que le signal.

-q, --queue valeur

Envoie le signal en utilisant sigqueue(3) plutôt que kill(2). L'argument valeur est un entier qui est envoyé avec le signal. Si le processus récepteur a installé un gestionnaire pour ce signal en utilisant le drapeau SA_SIGINFO de sigaction(2), alors il peut obtenir ces données via le champ si_sigval de la structure siginfo_t.

--timeout millisecondes signal

Envoie un signal défini de la manière habituelle à un processus, suivi d'un signal supplémentaire après un délai spécifié. L'option --timeout fait que kill attend une période définie en millisecondes avant d'envoyer un signal de suivi signal au processus. Cette fonctionnalité est implémentée en utilisant la fonctionnalité de descripteur de fichier PID du noyau Linux afin de garantir que le signal de suivi soit envoyé au même processus ou ne soit pas envoyé si le processus n'existe plus.

Notez que le système d'exploitation peut réutiliser les PID et qu'implémenter une fonctionnalité équivalente dans un shell en utilisant kill et sleep serait sujet à des conditions de concurrence où le signal de suivi pourrait être envoyé à un processus différent qui aurait utilisé un PID recyclé.

L'option --timeout peut être spécifiée plusieurs fois : les signaux sont envoyés séquentiellement avec les délais spécifiés. L'option --timeout peut être combinée avec l'option --queue.

Par exemple, la commande suivante envoie séquentiellement les signaux QUIT, TERM et KILL et attend 1000 millisecondes entre l'envoi des signaux :

kill --verbose --timeout 1000 TERM --timeout 1000 KILL \
        --signal QUIT 12345

-d, --show-process-state pid

Décode les champs liés aux signaux dans /proc/pid/status. 
$ kill -d $$
Blocked: INT
Ignored: TERM TSTP TTIN TTOU
Caught: HUP INT PIPE ALRM CHLD WINCH

STATUT DE SORTIE

kill a les valeurs de statut de sortie suivantes :

0

succès

1

échec

64

succès partiel (lorsque plus d'un processus est spécifié)

NOTES

Bien qu'il soit possible de spécifier le TID (identifiant de thread, voir gettid(2)) de l'un des threads d'un processus multithreadé comme argument de kill, le signal est néanmoins dirigé vers le processus (c'est-à-dire l'ensemble du groupe de threads). En d'autres termes, il n'est pas possible d'envoyer un signal à un thread explicitement sélectionné dans un processus multithreadé. Le signal sera délivré à un thread arbitrairement sélectionné dans le processus cible qui ne bloque pas le signal. Pour plus de détails, voir signal(7) et la description de CLONE_THREAD dans clone(2).

Divers shells fournissent une commande kill intégrée qui est préférée par rapport à l'exécutable kill(1) décrit dans cette page de manuel. Le moyen le plus simple de s'assurer que vous exécutez la commande décrite dans cette page est d'utiliser le chemin complet lors de l'appel de la commande, par exemple : /bin/kill --version
