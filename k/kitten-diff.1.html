Nom

kitten-diff - Diff, côte à côte et avec coloration syntaxique, de fichiers et d'images

Un outil de diff rapide, côte à côte, avec coloration syntaxique et images

Fonctionnalités majeures

  • Affiche les diffs côte à côte dans le terminal kitty
  • Applique la coloration syntaxique aux diffs affichés, de manière asynchrone, pour une vitesse maximale
  • Affiche des images ainsi que des diffs de texte, même via SSH
  • Effectue des diffs récursifs de répertoires
Capture d'écran, montrant un exemple de diff (images non prises en charge)

Installation

Installez simplement kitty <#quickstart>.

Utilisation

Dans le terminal kitty, exécutez :

kitten diff fichier1 fichier2

pour voir le diff entre fichier1 et fichier2.

Créez un alias dans le fichier de démarrage de votre shell pour raccourcir la commande, par exemple :

alias d="kitten diff"

Maintenant, il vous suffit de faire :

d fichier1 fichier2

pour comparer deux fichiers.

Vous pouvez également passer des répertoires au lieu de fichiers pour voir le diff récursif du contenu des répertoires.

Intégration avec git

Ajoutez ce qui suit dans ~/.gitconfig :

[diff]
    tool = kitty
    guitool = kitty.gui
[difftool]
    prompt = false
    trustExitCode = true
[difftool "kitty"]
    cmd = kitten diff $LOCAL $REMOTE
[difftool "kitty.gui"]
    cmd = kitten diff $LOCAL $REMOTE

Maintenant, pour utiliser kitty-diff afin de visualiser les diffs git, vous pouvez simplement faire :

git difftool --no-symlinks --dir-diff

Encore une fois, créer un alias pour cette commande est utile.

Pourquoi cela ne fonctionne-t-il que dans kitty ?

Le kitten diff utilise diverses fonctionnalités spécifiques à kitty <>, telles que le protocole graphique de kitty <>, le protocole de clavier étendu <>, etc. Il tire également parti de l'infrastructure des programmes de terminal que j'ai créée pour tous les autres kittens de kitty afin de réduire la quantité de code nécessaire (l'implémentation complète fait moins de 3000 lignes de code).

Et fondamentalement, c'est uniquement pour kitty parce que je l'ai écrit pour moi-même, et il est très peu probable que j'utilise d'autres terminaux :)

Configuration

Vous pouvez configurer les couleurs utilisées, les raccourcis clavier, l'implémentation du diff, les lignes de contexte par défaut, etc. en créant un fichier diff.conf dans votre dossier de configuration kitty <#confloc>. Voir ci-dessous pour les directives de configuration prises en charge.

Diff

syntax_aliases
syntax_aliases pyj:py pyi:py recipe:py

Alias d'extension de fichier pour la coloration syntaxique. Par exemple, pour colorer syntaxiquement fichier.xyz comme fichier.abc, utilisez un réglage de xyz:abc. Les alias multiples doivent être séparés par des espaces.

num_context_lines
num_context_lines 3

Le nombre de lignes de contexte à afficher autour de chaque changement.

diff_cmd
diff_cmd auto

La commande de diff à utiliser. Doit contenir le placeholder _CONTEXT_ qui sera remplacé par le nombre de lignes de contexte. Quelques valeurs spéciales sont autorisées : auto choisira automatiquement une implémentation de diff disponible. builtin utilisera l'algorithme de diff ancré de la bibliothèque standard Go. git utilisera la commande git pour effectuer le diff. diff utilisera la commande diff pour effectuer le diff.

replace_tab_by
replace_tab_by \x20\x20\x20\x20

La chaîne à utiliser pour remplacer les tabulations. Par défaut, quatre espaces sont utilisés.

ignore_name

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Un modèle glob qui est mis en correspondance uniquement avec le nom de fichier des fichiers et des répertoires. Les fichiers et répertoires correspondants sont ignorés lors du parcours du système de fichiers pour rechercher des fichiers à comparer. Peut être spécifié plusieurs fois pour utiliser plusieurs modèles. Par exemple :

ignore_name .git
ignore_name *~
ignore_name *.pyc

theme_couleur
theme_couleur auto

Indique si les couleurs claires ou sombres doivent être utilisées. La valeur par défaut de auto signifie qu'il faut suivre le schéma de couleurs du terminal parent. Notez que les couleurs réelles utilisées pour les schémas sombres sont définies par les paramètres dark_* ci-dessous et les paramètres sans préfixe sont utilisés pour les couleurs claires.

style_pygments
style_pygments default

Le schéma de couleurs pygments à utiliser pour la coloration syntaxique. Voir les styles intégrés de pygments sur https://pygments.org/styles/ pour une liste des schémas. Code source pour diff

Le code source de ce kitten est disponible sur GitHub https://github.com/kovidgoyal/kitty/tree/master/kittens/diff.

Interface en ligne de commande

kitten diff [options] fichier_ou_repertoire_gauche fichier_ou_repertoire_droit

Affiche une comparaison côte à côte des fichiers/répertoires spécifiés. Vous pouvez également utiliser ssh:nom_hote:chemin_fichier_distant pour comparer des fichiers distants.

Options

--context <CONTEXT>
Nombre de lignes de contexte à afficher entre les changements. Les valeurs négatives utilisent le nombre défini dans diff.conf. Par défaut : -1
--config <CONFIG>
Spécifie un chemin vers le(s) fichier(s) de configuration à utiliser. Tous les fichiers de configuration sont fusionnés avec le fichier intégré diff.conf, remplaçant les valeurs intégrées. Cette option peut être spécifiée plusieurs fois pour lire plusieurs fichiers de configuration en séquence, qui sont fusionnés. Utilisez la valeur spéciale NONE pour ne charger aucun fichier de configuration.

Si cette option n'est pas spécifiée, les fichiers de configuration sont recherchés dans l'ordre : $XDG_CONFIG_HOME/kitty/diff.conf, ~/.config/kitty/diff.conf, $XDG_CONFIG_DIRS/kitty/diff.conf. Le premier qui existe est utilisé comme fichier de configuration.

Si la variable d'environnement KITTY_CONFIG_DIRECTORY <#envvar-KITTY_CONFIG_DIRECTORY> est spécifiée, ce répertoire est toujours utilisé et la recherche ci-dessus n'a pas lieu.

Si /etc/xdg/kitty/diff.conf existe, il est fusionné avant (c'est-à-dire avec une priorité plus faible) que tout fichier de configuration utilisateur. Il peut être utilisé pour spécifier des valeurs par défaut à l'échelle du système pour tous les utilisateurs. Vous pouvez utiliser soit - soit /dev/stdin pour lire la configuration depuis STDIN.

--override <OVERRIDE>, -o <OVERRIDE>
Remplace des options de configuration individuelles, peut être spécifié plusieurs fois. Syntaxe : nom=valeur. Par exemple : -o background=gray
