NOM

kubectl auth can-i - Vérifier si une action est autorisée

SYNOPIS

kubectl auth can-i [OPTIONS]

DESCRIPTION

Vérifier si une action est autorisée.

VERBE est un verbe logique de l'API Kubernetes comme 'get', 'list', 'watch', 'delete', etc. TYPE est une ressource Kubernetes. Les raccourcis et les groupes seront résolus. NONRESOURCEURL est une URL partielle qui commence par "/". NOM est le nom d'une ressource Kubernetes particulière. Cette commande s'associe bien à l'usurpation d'identité. Voir le drapeau global --as.

OPTIONS

-A, --all-namespaces=false Si vrai, vérifiez l'action spécifiée dans tous les espaces de noms.

--list=false Si vrai, imprime toutes les actions autorisées.

--no-headers=false Si vrai, imprime les actions autorisées sans en-têtes

-q, --quiet=false Si vrai, supprime la sortie et renvoie uniquement le code de sortie.

--subresource="" Sous-ressource telle que pod/log ou deployment/scale

OPTIONS HERITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression de réponse pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la porte d'entrée de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer pour le serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Vérifier si je peux créer des pods dans n'importe quel espace de noms
  kubectl auth can-i create pods --all-namespaces
  # Vérifier si je peux lister des déploiements dans mon espace de noms actuel
  kubectl auth can-i list deployments.apps
  # Vérifier si le compte de service "foo" de l'espace de noms "dev" peut lister les pods dans l'espace de noms "prod"
  # Vous devez être autorisé à utiliser l'usurpation d'identité pour l'option globale "--as"
  kubectl auth can-i list pods --as=system:serviceaccount:dev:foo -n prod
  # Vérifier si je peux tout faire dans mon espace de noms actuel ("*" signifie tout)
  kubectl auth can-i '*' '*'
  # Vérifier si je peux obtenir le job nommé "bar" dans l'espace de noms "foo"
  kubectl auth can-i list jobs.batch/bar -n foo
  # Vérifier si je peux lire les logs des pods
  kubectl auth can-i get pods --subresource=log
  # Vérifier si je peux accéder à l'URL /logs/
  kubectl auth can-i get /logs/
  # Vérifier si je peux approuver certificates.k8s.io
  kubectl auth can-i approve certificates.k8s.io
  # Lister toutes les actions autorisées dans l'espace de noms "foo"
  kubectl auth can-i --list --namespace=foo
