NOM

kubeadm certs renew etcd-server - Renouveler le certificat pour servir etcd

SYNTAXE

kubeadm certs renew etcd-server [OPTIONS]

DESCRIPTION

Renouveler le certificat pour servir etcd.

Les renouvellements s'exécutent sans condition, quelle que soit la date d'expiration du certificat ; les attributs supplémentaires tels que les SAN seront basés sur le fichier/les certificats existants, il n'est pas nécessaire de les fournir à nouveau.

Le renouvellement essaie par défaut d'utiliser l'autorité de certification dans la PKI locale gérée par kubeadm ; alternativement, il est possible d'utiliser l'API de certificat K8s pour le renouvellement de certificat, ou en dernier recours, de générer une demande de CSR.

Après le renouvellement, pour que les changements prennent effet, il est nécessaire de redémarrer les composants du plan de contrôle et éventuellement de redistribuer le certificat renouvelé si le fichier est utilisé ailleurs.

OPTIONS

--cert-dir="/etc/kubernetes/pki" Le chemin où enregistrer les certificats

--config="" Chemin vers un fichier de configuration kubeadm.

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si l'indicateur n'est pas défini, un ensemble d'emplacements standard peut être recherché pour trouver un fichier kubeconfig existant.

OPTIONS INHERITÉS DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela amènera kubeadm à chrooter dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée
