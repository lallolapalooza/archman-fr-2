NOM

kubeadm init - Exécutez cette commande afin de configurer le plan de contrôle Kubernetes

SYNTAXE

kubeadm init [OPTIONS]

DESCRIPTION

Exécutez cette commande afin de configurer le plan de contrôle Kubernetes

La commande « init » exécute les phases suivantes :

preflight                     Exécute les vérifications préalables
certs                         Génération des certificats
  /ca                           Génère la CA Kubernetes auto-signée pour provisionner les identités des autres composants Kubernetes
  /apiserver                    Génère le certificat pour servir l'API Kubernetes
  /apiserver-kubelet-client     Génère le certificat pour que le serveur d'API se connecte au kubelet
  /front-proxy-ca               Génère la CA auto-signée pour provisionner les identités du proxy frontal
  /front-proxy-client           Génère le certificat pour le client du proxy frontal
  /etcd-ca                      Génère la CA auto-signée pour provisionner les identités d'etcd
  /etcd-server                  Génère le certificat pour servir etcd
  /etcd-peer                    Génère le certificat pour que les nœuds etcd communiquent entre eux
  /etcd-healthcheck-client      Génère le certificat pour les sondes de vivacité afin de vérifier la santé d'etcd
  /apiserver-etcd-client        Génère le certificat que l'apiserver utilise pour accéder à etcd
  /sa                           Génère une clé privée pour la signature des jetons de service d'aéroport ainsi que sa clé publique
kubeconfig                    Génère tous les fichiers kubeconfig nécessaires pour établir le plan de contrôle et le fichier kubeconfig administrateur
  /admin                        Génère un fichier kubeconfig pour l'administrateur et pour kubeadm lui-même
  /super-admin                  Génère un fichier kubeconfig pour le super-administrateur
  /kubelet                      Génère un fichier kubeconfig pour le kubelet à utiliser *uniquement* à des fins de démarrage du cluster
  /controller-manager           Génère un fichier kubeconfig pour le gestionnaire de contrôleurs
  /scheduler                    Génère un fichier kubeconfig pour le planificateur
etcd                          Génère un fichier manifeste de Pod statique pour etcd local
  /local                        Génère le fichier manifeste de Pod statique pour une instance etcd locale à un seul nœud
control-plane                 Génère tous les fichiers manifestes de Pod statiques nécessaires pour établir le plan de contrôle
  /apiserver                    Génère le manifeste du Pod statique kube-apiserver
  /controller-manager           Génère le manifeste du Pod statique kube-controller-manager
  /scheduler                    Génère le manifeste du Pod statique kube-scheduler
kubelet-start                 Écrit les paramètres kubelet et démarre (redémarre) le kubelet
wait-control-plane            Attend le démarrage du plan de contrôle
upload-config                 Charge la configuration kubeadm et kubelet vers un ConfigMap
  /kubeadm                      Charge la configuration du cluster kubeadm vers un ConfigMap
  /kubelet                      Charge la configuration du composant kubelet vers un ConfigMap
upload-certs                  Charge les certificats vers kubeadm-certs
mark-control-plane            Marque un nœud comme plan de contrôle
bootstrap-token               Génère des jetons de démarrage utilisés pour joindre un nœud à un cluster
kubelet-finalize              Met à jour les paramètres pertinents pour le kubelet après le démarrage TLS
  /enable-client-cert-rotation  Active la rotation des certificats client kubelet
addon                         Installe les extensions requises pour passer les tests de conformité
  /coredns                      Installe l'extension CoreDNS dans un cluster Kubernetes
  /kube-proxy                   Installe l'extension kube-proxy dans un cluster Kubernetes
show-join-command             Affiche la commande de jointure pour le nœud du plan de contrôle et les nœuds de travail

OPTIONS

--apiserver-advertise-address="" L'adresse IP sur laquelle l'API Server annoncera son écoute. Si non défini, l'interface réseau par défaut sera utilisée.

--apiserver-bind-port=6443 Port sur lequel l'API Server doit s'associer.

--apiserver-cert-extra-sans=[] Noms Alternatifs de Sujet (SANs) supplémentaires optionnels à utiliser pour le certificat de service de l'API Server. Peuvent être des adresses IP et des noms DNS.

--cert-dir="/etc/kubernetes/pki" Le chemin où sauvegarder et stocker les certificats.

--certificate-key="" Clé utilisée pour chiffrer les certificats du plan de contrôle dans le Secret kubeadm-certs. La clé de certificat est une chaîne encodée en hexadécimal qui représente une clé AES de 32 octets.

--config="" Chemin vers un fichier de configuration kubeadm.

--control-plane-endpoint="" Spécifie une adresse IP stable ou un nom DNS pour le plan de contrôle.

--cri-socket="" Chemin vers la socket CRI pour se connecter. Si vide, kubeadm tentera de détecter automatiquement cette valeur ; utilisez cette option seulement si vous avez plus d'une CRI installée ou si vous avez une socket CRI non standard.

--dry-run=false N'applique aucun changement ; affiche seulement ce qui serait fait.

--feature-gates="" Un ensemble de paires clé=valeur décrivant les portes de fonctionnalités pour diverses fonctionnalités. Les options sont : ControlPlaneKubeletLocalMode=true|false (BETA - par défaut=true) NodeLocalCRISocket=true|false (BETA - par défaut=true) PublicKeysECDSA=true|false (OBSOLÈTE - par défaut=false) RootlessControlPlane=true|false (ALPHA - par défaut=false) WaitForAllControlPlaneComponents=true|false (par défaut=true)

--ignore-preflight-errors=[] Une liste de vérifications dont les erreurs seront affichées sous forme d'avertissements. Exemple : 'IsPrivilegedUser,Swap'. La valeur 'all' ignore les erreurs de toutes les vérifications.

--image-repository="registry.k8s.io" Choisir un registre de conteneurs pour télécharger les images du plan de contrôle

--kubernetes-version="stable-1" Choisir une version spécifique de Kubernetes pour le plan de contrôle.

--node-name="" Spécifie le nom du nœud.

--patches="" Chemin vers un répertoire contenant des fichiers nommés "target[suffix][+patchtype].extension". Par exemple, "kube-apiserver0+merge.yaml" ou juste "etcd.json". "target" peut être l'un de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" peut être l'un de "strategic", "merge" ou "json" et ils correspondent aux formats de patch pris en charge par kubectl. Le "patchtype" par défaut est "strategic". "extension" doit être soit "json" soit "yaml". "suffix" est une chaîne optionnelle qui peut être utilisée pour déterminer quels patches sont appliqués en premier par ordre alphabétique.

--pod-network-cidr="" Spécifie la plage d'adresses IP pour le réseau des pods. Si défini, le plan de contrôle allouera automatiquement des CIDR pour chaque nœud.

--service-cidr="10.96.0.0/12" Utilise une plage alternative d'adresses IP pour les VIP de service.

--service-dns-domain="cluster.local" Utilise un domaine alternatif pour les services, par exemple "myorg.internal".

--skip-certificate-key-print=false N'affiche pas la clé utilisée pour chiffrer les certificats du plan de contrôle.

--skip-phases=[] Liste des phases à sauter

--skip-token-print=false Saute l'affichage du jeton de démarrage par défaut généré par 'kubeadm init'.

--token="" Le jeton à utiliser pour établir une confiance bidirectionnelle entre les nœuds et les nœuds du plan de contrôle. Le format est [a-z0-9]{6}.[a-z0-9]{16} - par exemple abcdef.0123456789abcdef

--token-ttl=24h0m0s La durée avant que le jeton ne soit automatiquement supprimé (par exemple, 1s, 2m, 3h). S'il est défini sur '0', le jeton n'expirera jamais

--upload-certs=false Charge les certificats du plan de contrôle vers le Secret kubeadm-certs.

OPTIONS INCLUES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le 'vrai' système de fichiers racine de l'hôte. Cela forcera kubeadm à utiliser un chroot vers le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version affichée
