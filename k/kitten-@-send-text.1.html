Nom

kitten-@-send-text - Envoie du texte arbitraire vers les fenêtres spécifiées

Utilisation

kitten @ send-text [TEXTE À ENVOYER]

Description

Envoie du texte arbitraire vers les fenêtres spécifiées. Le texte suit les règles d'échappement de Python. Vous pouvez donc utiliser des séquences d'échappement comme '\e' pour envoyer des codes de contrôle et '\u21fa' pour envoyer des caractères Unicode. N'oubliez pas d'utiliser des guillemets simples, sinon la barre oblique inverse est interprétée comme un caractère d'échappement du shell. Si vous utilisez l'option --match, le texte sera envoyé à toutes les fenêtres correspondantes. Par défaut, le texte n'est envoyé qu'à la fenêtre active actuellement. Notez que les erreurs ne sont pas signalées, pour des raisons techniques, de sorte que send-text réussit toujours, même si aucun texte n'a été envoyé à aucune fenêtre.

Options

--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance ont la forme : champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent à partir du numéro d'id le plus élevé vers le bas ; en particulier, -1 correspond à la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant à zéro et en comptant dans le sens horaire (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'identifiant de fenêtre de la fenêtre actuelle est disponible en tant que la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, où zéro est la fenêtre actuellement active, un est la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres créées dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session et . pour correspondre à la session actuellement active et ~ pour correspondre soit à la session actuellement active, soit à la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier soit uniquement le nom de la variable d'environnement, soit un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var fait correspondre les variables utilisateur définies sur la fenêtre. Vous pouvez spécifier un nom ou un nom et une valeur comme avec le champ env.

Le champ state fait correspondre l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est correspondue. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre système actuellement focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est un superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance ont la forme : champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id le plus élevé vers le bas ; en particulier, -1 correspond à l'onglet/fenêtre créé le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le n-ième onglet dans la fenêtre système actuellement active. Le numéro recent fait correspondre les onglets récemment actifs dans la fenêtre système actuellement active, où zéro est l'onglet actuellement actif, un est l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets créés dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session et . pour correspondre à la session actuellement active et ~ pour correspondre soit à la session actuellement active, soit à la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier soit uniquement le nom de la variable d'environnement, soit un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont correspondus. De même, var correspond aux onglets contenant n'importe quelle fenêtre avec la variable utilisateur spécifiée.

Le champ state fait correspondre l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre système parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont délivrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est correspondu. La valeur focused_os_window correspond à tous les onglets de la fenêtre système actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--all [=no]
Faire correspondre toutes les fenêtres.
--exclude-active [=no]
Ne pas envoyer de texte à la fenêtre active, même si elle fait partie des fenêtres correspondantes.
--stdin [=no]
Lire le texte à envoyer depuis stdin. Notez que dans ce cas, le texte est envoyé tel quel, et non interprété pour les séquences d'échappement. Si stdin est un terminal, vous pouvez appuyer sur Ctrl+D pour terminer la lecture.
--from-file
Chemin vers un fichier dont vous souhaitez envoyer le contenu. Notez que dans ce cas, le contenu du fichier est envoyé tel quel, et non interprété pour les séquences d'échappement.
--bracketed-paste [=disable]
Lors de l'envoi de texte à une fenêtre, envelopper le texte dans des codes d'échappement de collage entre crochets. Par défaut, cela n'est pas fait. La valeur auto signifie que le collage entre crochets ne sera utilisé que si le programme s'exécutant dans la fenêtre a activé le mode de collage entre crochets.

Choix : disable, auto, enable

--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse de l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la connexion à kitty. Cela amènera kitty à demander à l'utilisateur l'autorisation d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces de fin sont ignorés. Les chemins relatifs sont résolus depuis le répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie la présence du fichier rc-pass dans le répertoire de configuration de
kitty.
