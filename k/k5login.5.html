NOM

k5login - Fichier de contrôle d'accès Kerberos V5 pour l'accès aux hôtes

DESCRIPTION

Le fichier .k5login, qui réside dans le répertoire personnel d'un utilisateur, contient une liste des principaux Kerberos. Toute personne possédant des tickets valides pour un principal dans le fichier est autorisée à accéder à l'hôte avec l'UID de l'utilisateur dans le répertoire personnel duquel se trouve le fichier. Une utilisation courante est de placer un fichier .k5login dans le répertoire personnel de root, accordant ainsi aux administrateurs système un accès distant root à l'hôte via Kerberos.

EXEMPLES

Supposons que l'utilisateur alice ait un fichier .k5login dans son répertoire personnel contenant uniquement la ligne suivante :

bob@FOOBAR.ORG

Cela permettrait à bob d'utiliser des applications réseau Kerberos, telles que ssh(1), pour accéder au compte d'alice, en utilisant les tickets Kerberos de bob. Dans une configuration par défaut (avec k5login_authoritative défini sur true dans krb5.conf(5)), ce fichier .k5login ne permettrait pas à alice d'utiliser ces applications réseau pour accéder à son compte, car elle n'y est pas listée ! Sans fichier .k5login, ou avec k5login_authoritative défini sur false, une règle par défaut autoriserait le principal alice dans le domaine par défaut de la machine à accéder au compte alice.

Supposons en outre qu'alice soit administratrice système. Alice et les autres administrateurs système auraient leurs principaux dans le fichier .k5login de root sur chaque hôte :

alice@BLEEP.COM
joeadmin/root@BLEEP.COM

Cela permettrait à l'un ou l'autre des administrateurs système de se connecter à ces hôtes en utilisant leurs tickets Kerberos au lieu d'avoir à taper le mot de passe root. Notez que parce que bob conserve les tickets Kerberos pour son propre principal, bob@FOOBAR.ORG, il n'aurait aucun des privilèges qui nécessitent les tickets d'alice, tels que l'accès root à l'un des hôtes du site, ou la possibilité de changer le mot de passe d'alice.
