Nom

kitten-@-disable-ligatures - Contrôler le rendu des ligatures

Utilisation

kitten @ disable-ligatures STRATÉGIE

Description

Contrôle le rendu des ligatures pour les fenêtres/onglets spécifiés (par défaut, la fenêtre active). La STRATÉGIE peut être l'une des suivantes : jamais, toujours, curseur.

Options

--all, -a [=no]
Par défaut, les ligatures ne sont affectées que dans la fenêtre active. Cette option provoquera la modification des ligatures dans toutes les fenêtres.
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, titre, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'id de la fenêtre active est disponible sous la forme de la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actif, zéro étant la fenêtre actuellement active, un la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : gauche, droite, haut ou bas.

Le champ session correspond aux fenêtres créées dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session, . pour correspondre à la session active actuelle et ~ pour correspondre soit à la session active actuelle, soit à la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme avec le champ env .

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont livrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est utilisée. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre OS actuellement focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre située sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, titre, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id/window_id le plus élevé vers le bas, en particulier, -1 est l'onglet/la fenêtre créé(e) le plus récemment.

Lors de l'utilisation de titre ou d'id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre OS active actuelle. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre OS active actuelle, zéro étant l'onglet actif actuel, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets créés dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session, . pour correspondre à la session active actuelle et ~ pour correspondre soit à la session active actuelle, soit à la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets actifs dans leur fenêtre OS parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est utilisé. La valeur focused_os_window correspond à tous les onglets de la fenêtre OS actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si elle n'est pas spécifiée, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela amènera kitty à demander à l'utilisateur la permission d'effectuer l'action spécifiée, à moins que le mot de passe n'ait été accepté auparavant ou ne soit préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs finaux sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty envoie généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation ou non du mot de passe fourni. S'il est défini sur always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never

Name

kitten --enable-ligatures -@-disable-ligatures - enable/disable font ligatures

Usage

kitten --enable-ligatures [OPTIONS] [args...] kitten -@-disable-ligatures [OPTIONS] [args...]

Description

Font ligatures are typographic ligatures that are commonly used in programming fonts. They are, in essence, a way to combine multiple characters into a single glyph for better readability.

When using the kitty terminal emulator, ligatures are enabled by default and can be toggled on/off using the kitten --enable-ligatures and kitten -@-disable-ligatures commands, respectively. These commands should be run from within a running kitty session.

Options

These commands do not accept any arguments.
