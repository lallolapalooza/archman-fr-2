NOM

kubectl describe - Afficher les détails d'une ressource spécifique ou d'un groupe de ressources

SYNTAXE

kubectl describe [OPTIONS]

DESCRIPTION

Affiche les détails d'une ressource spécifique ou d'un groupe de ressources.

Imprime une description détaillée des ressources sélectionnées, y compris les ressources associées telles que les événements ou les contrôleurs. Vous pouvez sélectionner un seul objet par son nom, tous les objets de ce type, fournir un préfixe de nom ou un sélecteur d'étiquettes. Par exemple :

    $ kubectl describe TYPE PREFIXE_NOM

vérifiera d'abord une correspondance exacte sur TYPE et PREFIXE_NOM. Si aucune ressource de ce type n'existe, il affichera les détails de chaque ressource dont le nom commence par PREFIXE_NOM.

Utilisez "kubectl api-resources" pour obtenir une liste complète des ressources prises en charge.

OPTIONS

-A, --all-namespaces=false Si présent, liste l'objet (ou les objets) demandé(s) dans tous les espaces de noms. L'espace de noms du contexte actuel est ignoré même s'il est spécifié avec --namespace.

--chunk-size=500 Retourne les listes volumineuses par morceaux plutôt qu'en une seule fois. Passez 0 pour désactiver. Cette option est en version bêta et peut changer à l'avenir.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers contenant la ressource à décrire

-k, --kustomize="" Traite le répertoire kustomize. Cette option ne peut pas être utilisée avec -f ou -R.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquettes) pour filtrer, supporte '=', '==', '!=', 'in', 'notin'.(par exemple : -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--show-events=true Si vrai, affiche les événements liés à l'objet décrit.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, cette option peut être répétée pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une requête serveur unique. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie pas de délai d'attente pour les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat du serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification (Bearer token) pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Décrire un nœud
  kubectl describe nodes kubernetes-node-emt8.c.myproject.internal
  # Décrire un pod
  kubectl describe pods/nginx
  # Décrire un pod identifié par type et nom dans "pod.json"
  kubectl describe -f pod.json
  # Décrire tous les pods
  kubectl describe pods
  # Décrire les pods par étiquette name=myLabel
  kubectl describe pods -l name=myLabel
  # Décrire tous les pods gérés par le contrôleur de réplication 'frontend'
  # (les pods créés par rc obtiennent le nom du rc comme préfixe dans le nom du pod)
  kubectl describe pods frontend
