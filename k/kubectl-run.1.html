NOM

kubectl run - Exécute une image particulière sur le cluster

SYNOPSIS

kubectl run [OPTIONS]

DESCRIPTION

Crée et exécute une image particulière dans un pod.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de mappe est manquant dans le modèle. Ne s'applique qu'aux formats de sortie golang et jsonpath.

--annotations=[] Annotations à appliquer au pod.

--attach=false Si vrai, attend que le Pod démarre, puis s'y attache comme si 'kubectl attach ...' avait été appelé. Par défaut faux, sauf si '-i/--stdin' est défini, auquel cas la valeur par défaut est vraie. Avec '--restart=Never', le code de sortie du processus du conteneur est renvoyé.

--cascade="background" Doit être "background", "orphan" ou "foreground". Sélectionne la stratégie de cascade de suppression pour les dépendants (par exemple, les Pods créés par un ReplicationController). Par défaut, background.

--command=false Si vrai et des arguments supplémentaires sont présents, utilisez-les comme champ 'command' dans le conteneur, plutôt que le champ 'args' qui est la valeur par défaut.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est client, affiche uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

--env=[] Variables d'environnement à définir dans le conteneur.

--expose=false Si vrai, crée un service ClusterIP associé au pod. Nécessite --port.

--field-manager="kubectl-run" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] à utiliser pour remplacer la ressource.

--force=false Si vrai, supprime immédiatement les ressources de l'API et contourne la suppression gracieuse. Notez que la suppression immédiate de certaines ressources peut entraîner une incohérence ou une perte de données et nécessite une confirmation.

--grace-period=-1 Période de temps en secondes accordée à la ressource pour se terminer gracieusement. Ignoré si négatif. Défini à 1 pour un arrêt immédiat. Ne peut être défini à 0 que lorsque --force est vrai (suppression forcée).

--image="" L'image que le conteneur doit exécuter.

--image-pull-policy="" La politique de récupération d'image pour le conteneur. Si laissée vide, cette valeur ne sera pas spécifiée par le client et sera gérée par le serveur.

-k, --kustomize="" Traite un répertoire kustomize. Ce drapeau ne peut pas être utilisé avec -f ou -R.

-l, --labels="" Étiquettes séparées par des virgules à appliquer au pod. Annulera les valeurs précédentes.

--leave-stdin-open=false Si le pod est démarré en mode interactif ou avec stdin, laisse stdin ouvert après la première attache. Par défaut, stdin sera fermé après la première attache. (Ce qui est appelé 'attache' fait référence à l'action d'attacher le processus à stdin/stdout/stderr d'un conteneur, typiquement via `kubectl attach` ou des options similaires).

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--override-type="merge" La méthode utilisée pour remplacer l'objet généré : json, merge ou strategic.

--overrides="" Un remplacement JSON intégré pour l'objet généré. Si non vide, il est utilisé pour remplacer l'objet généré. Nécessite que l'objet fournisse un champ apiVersion valide.

--pod-running-timeout=1m0s La durée (par exemple, 5s, 2m ou 3h, supérieure à zéro) à attendre avant qu'au moins un pod ne soit en exécution

--port="" Le port exposé par ce conteneur.

--privileged=false Si vrai, exécute le conteneur en mode privilégié.

-q, --quiet=false Si vrai, supprime les messages de demande.

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur faux, n'enregistre pas la commande. Si défini sur vrai, enregistre la commande. Si non défini, par défaut met à jour la valeur d'annotation existante uniquement si elle existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes connexes organisés dans le même répertoire.

--restart="Always" La politique de redémarrage pour ce Pod. Valeurs légales [Always, OnFailure, Never].

--rm=false Si vrai, supprime le pod après sa sortie. Valide uniquement lors de l'attachement au conteneur, par exemple avec '--attach' ou avec '-i/--stdin'.

--save-config=false Si vrai, la configuration de l'objet actuel sera enregistrée dans son annotation. Sinon, l'annotation ne sera pas modifiée. Ce drapeau est utile lorsque vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets aux formats JSON ou YAML.

-i, --stdin=false Garde stdin ouvert sur le conteneur dans le pod, même si rien n'est attaché.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=0s La durée à attendre avant d'abandonner une suppression, zéro signifie déterminer un délai d'attente à partir de la taille de l'objet

-t, --tty=false Alloue un TTY pour le conteneur dans le pod.

--wait=false Si vrai, attend que les ressources aient disparu avant de retourner. Ceci attend les finaliseurs.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant le portail de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée à attendre avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas imposer de délai d'attente aux requêtes.

-s, --server="" L'adresse et le port du serveur d'API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user=&qu

NAME

kubectl-run — Run a particular image on a particular host

SYNOPSIS

kubectl run [OPTIONS]

DESCRIPTION

Run a particular image on a particular host.

This command is used to create a pod on the current Kubernetes cluster. The pod will be created with the specified image and command-line arguments.

The command supports various options to configure the pod, including environment variables, labels, port mappings, and restart policies.

OPTIONS

--add-cpu-limits=<value>
Add cpu limits to the container. Values are in cpu, cores.
--allow-missing-template-keys=true
If true, ignore any errors in templates when a field or map key is missing in the template. Other errors will still be raised.
--attach=false
Attach to the specified pod.stdout in streaming, true if empty, false otherwise
--atomic=false
If true, show all errors before returning an error, including from the command itself.
--build-from-file=[]
Use a file to build an image
--cascade=true
Must be "background", "foreground", or "orphan".
--chart-dir="[chart directory]"
--chart-url="[chart url]"
--chart="[chart name]"
--check-api-versions=false
If true, then will check for compatibility of API versions between the client and server
--cluster=
The name of the Kubernetes cluster to use
--command=false
Use the specified command and arguments. This is a shorthand for passing --command to the container.
--create-namespace=false
If set, create the namespace if it does not exist.
--default-container=
Default container name if unspecified.
--dry-run=none
Must be "none", "server", or "client". If client strategy, the API objects printed will be valid but not sent to the server. If server strategy, a live object is returned, but no more than one command at a time can be converted to the dry-run mode.
--env=[]
Specifies environment variables to set in the container. Use--env="name=value". Repeat option for multiple env variables.
--expose=false
If true, create and configure service to expose the pod, and return the pod IP
--force=false
If set to true, will override the existing object
--grace-period=-1
Period of time in seconds given to the pod to terminate gracefully. Ignored if negative. Set to 0 to force deletion.
--heap-check=false
Check heap for memory leaks
--image-pull-policy=
Specify a policy for image pulling. Valid values are "Always", "Never", "IfNotPresent"
--include-uninitialized=false
If true, include uninitialized objects for the resource.
--insecure-skip-tls-verify=false
If true, the server's certificate will not be checked for validity. This should only be used occasionally for testing or in a private network where the server's identity is not a concern.
--kubeconfig=
Path to the kubeconfig file to use for CLI requests.
--labels=[]
Labels to apply to the pod. Use --labels=key=value. Repeat option for multiple labels.
--namespace=
If present, the namespace scope of this CLI request
--no-headers=false
When printing table headers, skip the headers
--port=
Port to expose on the pod. E.g. "80", "443"
--profile="[cpu|mem]"
Usage profile (e.g. cpu or mem) to capture. Defaults to cpu.
--record=false
Record current instance value in the event annotation.
--recursive=false
Process the request recursively.
--restart=Always
Specify a restart policy for the container. Valid values are "Always", "OnFailure", "Never"
--server-print=true
Allow server-side printing of logs. Uses the same format as "kubectl logs --server-print" if set.
--server-timeout=0s
The duration after which the server will auto-terminate during a debug session. If unset, debug sessions will stay alive until manually terminated.
--show-managed-fields=false
If true, keep and show all managed fields in the output.
--show-status=false
If true, try to show status information of the resource, unless it is uninitialized.
--template=
Template string or path to template file for rendering output.
--validate=true
Should the resource be validated before submitting it.
--version=false
Print version information and quit; or specify the version (e.g. v1.2.3) of the other objects to use.
--warnings-as-errors=false
Treat warnings received from the server as errors and exit with a non-zero exit code

OPTIONS INHERITED FROM PARENT COMMANDS

--add-cpu-limits, --add-cpu-requests, --alias, --cache-dir, --caller, --certificate-authority, --client-certificate, --client-key, --cluster, --context, --default-container, --disable-compression, --insecure-skip-tls-verify, --kubeconfig, --match-server-version, --namespace, --request-timeout, --tls-server-name, --user, --username, --version, --warnings-as-errors

EXAMPLE

  # Start a nginx pod
  kubectl run nginx --image=nginx
  # Start a hazelcast pod and let the container expose port 5701
  kubectl run hazelcast --image=hazelcast/hazelcast --port=5701
  # Start a hazelcast pod and set environment variables "DNS_DOMAIN=cluster" and "POD_NAMESPACE=default" in the container
  kubectl run hazelcast --image=hazelcast/hazelcast --env="DNS_DOMAIN=cluster" --env="POD_NAMESPACE=default"
  # Start a hazelcast pod and set labels "app=hazelcast" and "env=prod" in the container
  kubectl run hazelcast --image=hazelcast/hazelcast --labels="app=hazelcast,env=prod"
  # Dry run; print the corresponding API objects without creating them
  kubectl run nginx --image=nginx --dry-run=client
  # Start a nginx pod, but overload the spec with a partial set of values parsed from JSON
  kubectl run nginx --image=nginx --overrides='{ "apiVersion": "v1", "spec": { ... } }'
  # Start a busybox pod and keep it in the foreground, don't restart it if it exits
  kubectl run -i -t busybox --image=busybox --restart=Never
  # Start the nginx pod using the default command, but use custom arguments (arg1 .. argN) for that command
  kubectl run nginx --image=nginx -- <arg1> <arg2> ... <argN>
  # Start the nginx pod using a different command and custom arguments
  kubectl run nginx --image=nginx --command -- <cmd> <arg1> ... <argN>
