Nom

kitten-@-send-key - Envoie des pressions de touches arbitraires aux fenêtres spécifiées

Utilisation

kitten @ send-key [TOUCHE(S) À ENVOYER ...]

Description

Envoie des pressions de touches arbitraires aux fenêtres spécifiées. Toutes les touches spécifiées sont envoyées d'abord comme événements de pression puis comme événements de relâchement dans l'ordre inverse. Les touches sont envoyées aux programmes exécutés dans les fenêtres. Elles ne sont envoyées que si le mode clavier actuel du programme prend en charge la touche particulière. Par exemple : send-key ctrl+a ctrl+b. Notez que les erreurs ne sont pas signalées, pour des raisons techniques, send-key réussit donc toujours, même si aucune touche n'a été envoyée à aucune fenêtre.

Options

--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui dans lequel les fenêtres sont signalées par la commande kitten @ ls).

L'identifiant de fenêtre de la fenêtre actuelle est disponible sous la forme de la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actif actuel, zéro étant la fenêtre active actuelle, un la fenêtre précédemment active, etc.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session active actuelle et ~ pour faire correspondre soit la session active actuelle, soit la dernière session active lorsqu'aucune session n'est active.

En utilisant le champ env pour faire correspondre les variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme avec le champ env.

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée, et c'est la fenêtre à laquelle les événements clavier sont livrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est mise en correspondance. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre OS focalisée actuelle. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id/window_id le plus élevé vers le bas, en particulier, -1 est l'onglet/la fenêtre créé(e) le plus récemment.

Lorsque vous utilisez title ou id, on recherche d'abord un onglet correspondant, et s'il n'est pas trouvé, on recherche une fenêtre correspondante, et on utilise l'onglet de cette fenêtre.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le n-ième onglet dans la fenêtre OS active actuelle. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre OS active actuelle, zéro étant l'onglet actif actuel, un l'onglet précédemment actif, etc.

Le champ session correspond aux onglets créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session active actuelle et ~ pour faire correspondre soit la session active actuelle, soit la dernière session active lorsqu'aucune session n'est active.

En utilisant le champ env pour faire correspondre les variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre OS parente. Il n'y a qu'un seul onglet focalisé, et c'est l'onglet auquel les événements clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets de la fenêtre OS focalisée actuelle.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--all [=no]
Faire correspondre toutes les fenêtres.
--exclude-active [=no]
Ne pas envoyer de texte à la fenêtre active, même si c'est l'une des fenêtres correspondantes.
--help, -h [=no]
Afficher l'aide de cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si elle n'est pas spécifiée, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la contact de kitty. Cela demandera à kitty la permission de l'utilisateur d'effectuer l'action spécifiée, sauf si le mot de passe a déjà été accepté ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire à partir du descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, il vérifie le fichier rc-pass dans le répertoire de configuration kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, il vérifie la variable d'environnement KITTY_RC_PASSWORD.

kitten-@-send-key.1 -- Terminal multiplexer for the kitten framework

NAME

kitten-@-send-key.1 - Terminal multiplexer for the kitten framework

SYNOPSIS

kitten-@send-key

DESCRIPTION

This command is used to send key presses to a running kitten instance. It's part of the kitten framework and allows for programmatic interaction with terminal sessions.

When the kitten command is provided, the blank password is used.

OPTIONS

Choices: if-available, always, never
