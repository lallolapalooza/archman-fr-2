Nom

kitten-@-action - Exécute l'action mappée spécifiée

Utilisation

kitten @ action ACTION [ARGS POUR ACTION...]

Description

Exécute l'action mappée spécifiée. Pour une liste de toutes les actions mappables disponibles, voir actions. Tous les arguments pour ACTION devraient suivre l'action. Notez que l'analyse des arguments dépend de l'action, donc pour de meilleurs résultats, spécifiez tous les arguments comme une seule chaîne de caractères sur la ligne de commande dans le même format que vous utiliseriez pour cette action dans kitty.conf.

Options

--self [=non]
Exécute l'action sur la fenêtre où cette commande est exécutée au lieu de la fenêtre active.
--no-response [=non]
N'attendez pas une réponse indiquant le succès de l'action. Notez qu'en utilisant cette option, vous ne serez pas informé des échecs.
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont du type : champ:requête. Où champ peut être l'un des éléments suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id correspondent en partant du plus grand nombre d'id vers le bas, en particulier, -1 est la fenêtre la plus récemment créée.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant à zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui rapporté par la commande kitten @ ls).

L'id de la fenêtre de la fenêtre actuelle est disponible via la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, zéro étant la fenêtre actuellement active, un étant la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour correspondre aux fenêtres qui n'ont pas été créées dans une session et . pour correspondre à la session actuellement active et ~ pour correspondre soit à la session actuellement active, soit à la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier le nom ou le nom et la valeur comme avec le champ env.

Le champ state correspond à l'état de la fenêtre. Les états supportés sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est mise en correspondance. La valeur focused_os_window correspond à toutes les fenêtres dans la fenêtre du système d'exploitation focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre située sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--help, -h [=non]
Affiche l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le réglage listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors du contact avec kitty. Cela demandera à kitty la permission de l'utilisateur pour effectuer l'action spécifiée, à moins que le mot de passe n'ait été accepté auparavant ou qu'il ne soit préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire à partir du descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=si-disponible]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation ou non de manière permanente du mot de passe fourni. Si défini sur always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
