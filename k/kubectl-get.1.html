NOM

kubectl get - Afficher une ou plusieurs ressources

SYNTAXE

kubectl get [OPTIONS]

DESCRIPTION

Affiche une ou plusieurs ressources.

Imprime un tableau des informations les plus importantes sur les ressources spécifiées. Vous pouvez filtrer la liste en utilisant un sélecteur d'étiquettes et l'indicateur --selector. Si le type de ressource désiré est dans un espace de noms, vous ne verrez que les résultats dans l'espace de noms actuel si vous n'en spécifiez aucun.

En spécifiant la sortie comme 'template' et en fournissant un modèle Go comme valeur de l'indicateur --template, vous pouvez filtrer les attributs des ressources récupérées.

Utilisez "kubectl api-resources" pour une liste complète des ressources prises en charge.

OPTIONS

-A, --all-namespaces=false Si présent, répertorie les objets demandés dans tous les espaces de noms. L'espace de noms du contexte actuel est ignoré même s'il est spécifié avec --namespace.

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de mappage est manquant dans le modèle. Ne s'applique qu'aux formats de sortie golang et jsonpath.

--chunk-size=500 Retourne les grandes listes par blocs plutôt que tout en une fois. Passez 0 pour désactiver. Cet indicateur est bêta et peut changer à l'avenir.

--field-selector="" Sélecteur (requête de champ) pour filtrer, prend en charge '=', '==', et '!='.(par exemple, --field-selector clé1=valeur1,clé2=valeur2). Le serveur ne prend en charge qu'un nombre limité de requêtes de champs par type.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource à obtenir du serveur.

--ignore-not-found=false Si défini sur vrai, supprime l'erreur NotFound pour les objets spécifiques qui n'existent pas. L'utilisation de cet indicateur avec des commandes qui interrogent des collections de ressources n'a aucun effet lorsque aucune ressource n'est trouvée.

-k, --kustomize="" Traite le répertoire kustomization. Cet indicateur ne peut pas être utilisé avec -f ou -R.

-L, --label-columns=[] Accepte une liste séparée par des virgules d'étiquettes qui seront présentées sous forme de colonnes. Les noms sont sensibles à la casse. Vous pouvez également utiliser plusieurs options d'indicateur comme -L etiquette1 -L etiquette2...

--no-headers=false Lors de l'utilisation du format de sortie par défaut ou en colonnes personnalisées, n'imprime pas les en-têtes (imprime les en-têtes par défaut).

-o, --output="" Format de sortie. L'un des suivants : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file, custom-columns, custom-columns-file, wide). Voir les colonnes personnalisées [https://kubernetes.io/docs/reference/kubectl/#custom-columns], modèle golang [http://golang.org/pkg/text/template/#pkg-overview] et modèle jsonpath [https://kubernetes.io/docs/reference/kubectl/jsonpath/].

--output-watch-events=false Sortie des événements de surveillance lorsque --watch ou --watch-only est utilisé. Les objets existants sont affichés comme événements AJOUTÉS initiaux.

--raw="" URI brute à demander au serveur. Utilise le transport spécifié par le fichier kubeconfig.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'.(par exemple, -l clé1=valeur1,clé2=valeur2,clé3 in (valeur3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--server-print=true Si vrai, demande au serveur de renvoyer la sortie de tableau appropriée. Prend en charge les API d'extension et les CRD.

--show-kind=false Si présent, affiche le type de ressource pour l'objet demandé.

--show-labels=false Lors de l'impression, affiche toutes les étiquettes comme dernière colonne (masque la colonne d'étiquettes par défaut)

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets aux formats JSON ou YAML.

--sort-by="" Si non vide, trie les types de liste en utilisant cette spécification de champ. La spécification de champ est exprimée sous forme d'expression JSONPath (par exemple, '{.metadata.name}'). Le champ de la ressource API spécifié par cette expression JSONPath doit être un entier ou une chaîne.

--subresource="" Si spécifié, obtient la sous-ressource de l'objet demandé.

--template="" Chaîne de modèle ou chemin d'accès au fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

-w, --watch=false Après avoir listé/obtenu l'objet demandé, surveille les changements.

--watch-only=false Surveille les changements des objets demandés, sans les lister/obtenir au préalable.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, cet indicateur peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin d'accès à un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin d'accès à un fichier de certificat client pour TLS

--client-key="" Chemin d'accès à un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin d'accès au fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin d'accès au fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant KUBECTL_KUBERC=false ou en désactivant la passerelle de fonctionnalités KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. L'un des suivants (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification d'accès (Bearer) auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version affichée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Lister tous les pods au format de sortie ps
  kubectl get pods
  # Lister tous les pods au format de sortie ps avec plus d'informations (comme le nom du nœud)
  kubectl get pods -o wide

NOM

kubectl-get - afficher une ou plusieurs ressources

SYNOPSIS

kubectl get (TYPE | TYPE/NAME | TYPE.apiVersion | NAME) [-o=output-format]

kubectl get (TYPE1.apiVersion,TYPE2.apiVersion,...
–output=output-format)

kubectl get
–filename=FILENAME
–recursive
–output=output-format

kubectl get
–kustomize=KUSTOMIZATION_DIR
–output=output-format

kubectl get
--all-namespaces | --namespace=namespace

kubectl get
--selector=SELECTION_SET

kubectl get
--field-selector=FIELD_SELECTOR

kubectl get
--subresource=SUBRESOURCE

kubectl get
--template=TEMPLATE

kubectl get
--output-column=COLUMN_DESCRIPTOR

DESCRIPTION

Obtenez des informations sur une ou plusieurs ressources.

Les types de ressources pris en charge incluent:

  api-resources(7),
  kubectl-api-resources(1),
  kubectl-cluster-info(1),
  kubectl-config(1),
  kubectl-describe(1),
  kubectl-exec(1),
  kubectl-explain(1),
  kubectl-expose(1),
  kubectl-logs(1),
  kubectl-port-forward(1),
  kubectl-proxy(1),
  kubectl-run(1),
  kubectl-top(1),
  kubectl(1).

OPTIONS

-A, --all-namespaces
Si spécifié, le nom des ressources sera imprimé avec leur namespace.
--allow-missing-template-keys
Si spécifié, le rendu des modèles échouera si une clé de modèle manque. Par défaut, la clé manquante sera imprimée.
--chunk-size=INT
Retourne les listes de morceaux de cette taille dans la réponse paginée. Par défaut : 500.
--field-selector=FIELD_SELECTOR
Filtre les ressources en fonction de la valeur de leurs champs. Voir https://kubernetes.io/docs/concepts/overview/working-with-objects/field-selectors/
--filename, -f <filename>
Nom de fichier, répertoire ou URL identifiant un ensemble de ressources.
--ignore-not-found
Si spécifié, les messages d'erreur pour les ressources non trouvées seront supprimés.
--kustomize <kustomization-dir>
Spécifiez un répertoire contenant un kustomization.yaml pour obtenir des ressources.
--label-columns <comma-separated-list>
Colonne personnalisée pour les champs nommés par des étiquettes. Les colonnes seront triées par nom.
--no-headers
Lors de l'impression avec un format de sortie comme le tableau, n'imprimez pas les en-têtes de colonne.
--output, -o <output-format>
Format de sortie de la commande. Exemples : json, yaml, wide, name, custom-columns, jsonpath-template.
--output-column <column-definition>
Il s'agit d'une définition de colonne personnalisée qui utilise un chemin de gabarit pour extraire de la valeur. Exemple: <column-name>:.<json-path-expr> . Les colonnes seront triées par nom.
--recursive
Recursively prosesse les sous-répertoires des répertoires spécifiés dans -f.
--selector <string>
Utilisez des sélecteurs d'étiquettes pour filtrer les ressources. Le format est <key>=<value>.
--selector-version <string>
Filtre les ressources par leur version de l'API.
--server-print
Si elle est définie, la sortie sera formatée par le serveur. Ne fonctionne qu'avec les formats de sortie supportés par le serveur.
--show-kind
Si elle est définie, inclura la colonne Kind dans la sortie.
--show-labels
En plus des colonnes par défaut, affiche les étiquettes comme colonnes supplémentaires.
--subresource <string>
Spécifiez le sous-répertoire de la ressource à récupérer. Les sous-répertoires valides sont « status » et « scale ».
--template <template>
Spécifiez un modèle de sortie go. Voir https://golang.org/pkg/text/template/ pour la syntaxe du modèle.
--all-namespaces
Si spécifié, le nom des ressources sera imprimé avec leur namespace.
--namespace <string>
Si spécifié, affichez des ressources du namespace spécifié.

OPTIONS INHERITED FROM PARENT COMMANDS

--alsologto, --atomic-error-counter, --atomic-error-counter-dir, --cache-dir, --certificate-authority, --client-certificate, --client-key, --cluster, --context, --default-namespace, --disable-compression, --insecure-skip-tls-verify, --kubeconfig, --log-backtrace-at, --log-dir, --log-file, --log-file-max-size, --log-flush-frequency, --log-json, --log-level, --log-output, --log-stacktrace-at, --logtostderr, --match-server-version, --namespace, --request-timeout, --skip-headers, --stderrthreshold, --tls-server-name, --token, --user.

EXAMPLE

  # Afficher un unique contrôleur de réplication dans le format de sortie ps
  kubectl get replicationcontroller web
  # Lister les déploiements au format de sortie JSON, dans la version "v1" du groupe d'API "apps"
  kubectl get deployments.v1.apps -o json
  # Lister un unique pod au format de sortie JSON
  kubectl get -o json pod web-pod-13je7
  # Lister un pod identifié par le type et le nom spécifiés dans "pod.yaml" au format de sortie JSON
  kubectl get -f pod.yaml -o json
  # Lister des ressources à partir d'un répertoire avec kustomization.yaml - par ex. dir/kustomization.yaml
  kubectl get -k dir/
  # Retourner uniquement la valeur de la phase du pod spécifié
  kubectl get -o template pod/web-pod-13je7 --template={{.status.phase}}
  # Lister les informations sur les ressources dans des colonnes personnalisées
  kubectl get pod test-pod -o custom-columns=CONTAINER:.spec.containers[0].name,IMAGE:.spec.containers[0].image
  # Lister tous les contrôleurs de réplication et tous les services ensemble dans le format de sortie ps
  kubectl get rc,services
  # Lister une ou plusieurs ressources par leur type et leurs noms
  kubectl get rc/web service/frontend pods/web-pod-13je7
  # Lister le sous-répertoire 'status' pour un unique pod
  kubectl get pod web-pod-13je7 --subresource status
  # Lister tous les déploiements dans le namespace 'backend'
  kubectl get deployments.apps --namespace backend
  # Lister tous les pods existant dans tous les namespaces
  kubectl get pods --all-namespaces
