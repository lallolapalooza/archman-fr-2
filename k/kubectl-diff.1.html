kubectl-diff(1)

Paquet: kubectl

Licences: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOM

kubectl diff - Diff la version active contre une version qui serait appliquée

SYNTAXE

kubectl diff [OPTIONS]

DESCRIPTION

Différencie les configurations spécifiées par nom de fichier ou par l'entrée standard entre la configuration en ligne actuelle et la configuration telle qu'elle serait si elle était appliquée.

La sortie est toujours au format YAML.

La variable d'environnement KUBECTL_EXTERNAL_DIFF peut être utilisée pour sélectionner votre propre commande de comparaison. Les utilisateurs peuvent utiliser des commandes externes avec des paramètres, par exemple : KUBECTL_EXTERNAL_DIFF="colordiff -N -u"

Par défaut, la commande "diff" disponible dans votre chemin sera exécutée avec les options "-u" (différentiel unifié) et "-N" (traiter les fichiers absents comme vides).

Statut de sortie : 0 Aucune différence n'a été trouvée. 1 Des différences ont été trouvées. >1 Kubectl ou diff a échoué avec une erreur.

Note : KUBECTL_EXTERNAL_DIFF, s'il est utilisé, est censé suivre cette convention.

OPTIONS

--concurrency=1 Nombre d'objets à traiter en parallèle lors de la comparaison avec la version active. Un nombre plus élevé = plus rapide, mais plus de mémoire, d'E/S et de CPU sur cette période plus courte.

--field-manager="kubectl-client-side-apply" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers contenant la configuration à comparer

--force-conflicts=false Si vrai, l'application côté serveur forcera les modifications en cas de conflits.

-k, --kustomize="" Traite le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--prune=false Inclut les ressources qui seraient supprimées par le nettoyage. Peut être utilisé avec -l et par défaut affiche toutes les ressources qui seraient nettoyées.

--prune-allowlist=[] Remplace la liste d'autorisation par défaut pour --prune

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, supporte '=', '==', '!=', 'in', 'notin'. (par exemple, -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--server-side=false Si vrai, l'application s'exécute sur le serveur au lieu du client.

--show-managed-fields=false Si vrai, inclut les champs gérés dans la comparaison.

OPTIONS HERITEES DES COMMANDES PARENT

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié quant à sa validité. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la porte d'accès aux fonctionnalités KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, l'espace de noms de portée pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas dépasser le délai d'attente des requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul.

EXEMPLE

  # Diff les ressources incluses dans pod.json
  kubectl diff -f pod.json
  # Diff le fichier lu depuis l'entrée standard
  cat service.yaml | kubectl diff -f -
