kexec_load(2) Manuel des appels système kexec_load(2)

NOM

kexec_load, kexec_file_load - charge un nouveau noyau pour exécution ultérieure

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/kexec.h>      /* Définition des constantes KEXEC_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_kexec_load, unsigned long entry,
             unsigned long nr_segments,
             struct kexec_segment segments[nr_segments],
             unsigned long flags);
long syscall(SYS_kexec_file_load, int kernel_fd, int initrd_fd,
             unsigned long cmdline_len, const char cmdline[cmdline_len],
             unsigned long flags);

Note : glibc ne fournit pas de fonctions d'encapsulation pour ces appels système, rendant nécessaire l'utilisation de syscall(2).

DESCRIPTION

L'appel système kexec_load() charge un nouveau noyau qui peut être exécuté ultérieurement par reboot(2).

L'argument flags est un masque de bits qui contrôle le fonctionnement de l'appel. Les valeurs suivantes peuvent être spécifiées dans flags :

KEXEC_ON_CRASH (depuis Linux 2.6.13)
Exécute automatiquement le nouveau noyau en cas de crash du système. Ce "noyau de crash" est chargé dans une zone de mémoire réservée, déterminée au démarrage à l'aide du paramètre de ligne de commande du noyau crashkernel. L'emplacement de cette mémoire réservée est exporté vers l'espace utilisateur via le fichier /proc/iomem, dans une entrée intitulée "Crash kernel". Une application en espace utilisateur peut analyser ce fichier et préparer une liste de segments (voir ci-dessous) qui spécifient cette mémoire réservée comme destination. Si ce drapeau est spécifié, le noyau vérifie que les segments cibles spécifiés dans segments tombent dans la région réservée.
KEXEC_PRESERVE_CONTEXT (depuis Linux 2.6.27)
Préserve les états matériels et logiciels du système avant d'exécuter le nouveau noyau. Ceci peut être utilisé pour la mise en veille prolongée du système. Ce drapeau n'est disponible que si le noyau a été configuré avec CONFIG_KEXEC_JUMP, et n'est effectif que si nr_segments est supérieur à 0.

Les bits de poids fort (correspondant au masque 0xffff0000) de flags contiennent l'architecture du noyau à exécuter. Spécifiez (OU) la constante KEXEC_ARCH_DEFAULT pour utiliser l'architecture actuelle, ou l'une des constantes d'architecture suivantes : KEXEC_ARCH_386, KEXEC_ARCH_68K, KEXEC_ARCH_X86_64, KEXEC_ARCH_PPC, KEXEC_ARCH_PPC64, KEXEC_ARCH_IA_64, KEXEC_ARCH_ARM, KEXEC_ARCH_S390, KEXEC_ARCH_SH, KEXEC_ARCH_MIPS, et KEXEC_ARCH_MIPS_LE. L'architecture doit être exécutable sur le CPU du système.

L'argument entry est l'adresse d'entrée physique dans l'image du noyau. L'argument nr_segments est le nombre de segments pointés par le pointeur segments ; le noyau impose une limite (arbitraire) de 16 segments. L'argument segments est un tableau de structures kexec_segment qui définissent la disposition du noyau :


struct kexec_segment {
    void   *buf;        /* Tampon en espace utilisateur */
    size_t  bufsz;      /* Longueur du tampon en espace utilisateur */
    void   *mem;        /* Adresse physique du noyau */
    size_t  memsz;      /* Longueur de l'adresse mémoire */
};

L'image du noyau définie par segments est copiée depuis le processus appelant vers le noyau, soit dans la mémoire normale, soit dans la mémoire réservée (si KEXEC_ON_CRASH est défini). Le noyau effectue d'abord diverses vérifications de cohérence sur les informations transmises dans segments. Si ces vérifications réussissent, le noyau copie les données des segments dans la mémoire du noyau. Chaque segment spécifié dans segments est copié comme suit :

•
buf et bufsz identifient une région mémoire dans l'espace d'adressage virtuel de l'appelant, qui est la source de la copie. La valeur de bufsz ne peut pas dépasser la valeur du champ memsz.
•
mem et memsz spécifient une plage d'adresses physiques qui est la cible de la copie. Les valeurs spécifiées dans les deux champs doivent être des multiples de la taille de page du système.
•
bufsz octets sont copiés du tampon source vers le tampon du noyau cible. Si bufsz est inférieur à memsz, les octets excédentaires dans le tampon du noyau sont mis à zéro.

En cas de kexec normal (c'est-à-dire, si le drapeau KEXEC_ON_CRASH n'est pas défini), les données du segment sont chargées dans n'importe quelle mémoire disponible et sont déplacées vers la destination finale au moment du redémarrage kexec (par exemple, lorsque la commande kexec(8) est exécutée avec l'option -e).

En cas de kexec en cas de panne (c'est-à-dire, si le drapeau KEXEC_ON_CRASH est défini), les données du segment sont chargées dans la mémoire réservée au moment de l'appel, et, après une panne, le mécanisme kexec passe simplement le contrôle à ce noyau.

L'appel système kexec_load() n'est disponible que si le noyau a été configuré avec CONFIG_KEXEC.

kexec_file_load()

L'appel système kexec_file_load() est similaire à kexec_load(), mais il prend un ensemble d'arguments différent. Il lit le noyau à charger depuis le fichier référencé par le descripteur de fichier kernel_fd, et l'initrd (disque RAM initial) à charger depuis le fichier référencé par le descripteur de fichier initrd_fd. L'argument cmdline est un pointeur vers un tampon contenant la ligne de commande pour le nouveau noyau. L'argument cmdline_len spécifie la taille du tampon. Le dernier octet du tampon doit être un octet nul ('\0').

L'argument flags est un masque de bits qui modifie le comportement de l'appel. Les valeurs suivantes peuvent être spécifiées dans flags :

KEXEC_FILE_UNLOAD
Décharge le noyau actuellement chargé.
KEXEC_FILE_ON_CRASH
Charge le nouveau noyau dans la région mémoire réservée pour le noyau de crash (comme pour KEXEC_ON_CRASH). Ce noyau est démarré si le noyau en cours d'exécution plante.
KEXEC_FILE_NO_INITRAMFS
Le chargement de l'initrd/initramfs est facultatif. Spécifiez ce drapeau si aucun initramfs n'est chargé. Si ce drapeau est défini, la valeur passée dans initrd_fd est ignorée.

L'appel système kexec_file_load() a été ajouté pour fournir un support aux systèmes où le chargement "kexec" doit être limité aux noyaux signés. Cet appel système n'est disponible que si le noyau a été configuré avec CONFIG_KEXEC_FILE.

VALEUR DE RETOUR

En cas de succès, ces appels système retournent 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EADDRNOTAVAIL
Le drapeau KEXEC_ON_CRASH a été spécifié, mais la région spécifiée par les champs mem et memsz de l'une des entrées de segments se trouve en dehors de la plage de mémoire réservée pour le noyau de crash.
EADDRNOTAVAIL
La valeur d'un champ mem ou memsz dans l'une des entrées de segments n'est pas un multiple de la taille de page du système.
EBADF
kernel_fd ou initrd_fd n'est pas un descripteur de fichier valide.
EBUSY
Un autre noyau de crash est déjà en cours de chargement ou un noyau de crash est déjà utilisé.
EINVAL
flags est invalide.
EINVAL
La valeur d'un champ bufsz dans l'une des entrées de segmen

kexec_file_load(2) — Pages man Linux

NOM

kexec_file_load — charger un nouveau noyau Linux depuis le système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc), y compris dans les interfaces de programmation de syscall(2).

SYNOPSIS

cc fichier.c -lutil -o programme

#include <linux/kexec.h>

long kexec_file_load(int kernel_fd, int initrd_fd,
                     unsigned long cmdline_len, const char *cmdline,
                     unsigned long flags);

DESCRIPTION

La fonction kexec_file_load() permet de charger un nouveau noyau Linux qui sera exécuté en utilisant kexec(8). Le nouveau noyau est chargé à partir d'un descripteur de fichier (kernel_fd) qui fait référence à un fichier noyau, et éventuellement un fichier initrd à partir du descripteur de fichier initrd_fd. Le paramètre cmdline spécifie la ligne de commande du noyau, sa longueur étant spécifiée par cmdline_len. Le paramètre flags peut être utilisé pour spécifier différentes options.

Cette interface est une version améliorée de kexec_load(2). Elle permet de charger le noyau et l'initrd directement à partir de fichiers. Elle prend en charge le chargement de plusieurs segments du noyau. La structure struct kexec_segment est définie dans <linux/kexec.h> et permet de spécifier des adresses de chargement et des tailles pour différents segments du noyau.

Le paramètre flags peut inclure les valeurs suivantes :

KEXEC_FILE_UNLOAD
Décharge tout noyau précédemment chargé.
KEXEC_FILE_LOAD
Charge le nouveau noyau.
KEXEC_FILE_ON_CRASH
Indique que le noyau est destiné à être chargé en cas de crash du système.

Les descripteurs de fichiers kernel_fd et initrd_fd doivent faire référence à des fichiers ouverts en lecture. Le fichier noyau doit être un exécutable valide et chargeable par le chargeur de noyau du système. Le fichier initrd est un fichier image ramdisk qui sera mis à disposition du nouveau noyau.

Le paramètre cmdline est une chaîne de caractères contenant la ligne de commande du nouveau noyau. Elle doit être terminée par un caractère nul ('\0').

Le nombre de segments du noyau est spécifié par le champ nr_segments dans la structure struct kexec_file_info qui est passée implicitement via les descripteurs de fichiers ou par d'autres moyens selon l'implémentation. La valeur maximale est définie par KEXEC_SEGMENT_MAX.

VALEUR RENVOYÉE

En cas de succès, kexec_file_load() renvoie 0. En cas d'erreur, elle renvoie un nombre négatif représentant le numéro d'erreur.

ERREURS

EBADF
Un des descripteurs de fichiers (kernel_fd ou initrd_fd) n'est pas valide.
EINVAL
Le paramètre flags contient des bits non reconnus.
EINVAL
La taille des données des segments spécifiés dans les structures kexec_segment excède la valeur du champ memsz correspondant.
EINVAL
nr_segments excède KEXEC_SEGMENT_MAX (16).
EINVAL
Deux ou plusieurs des buffers cibles du noyau se chevauchent.
EINVAL
La valeur dans cmdline[cmdline_len-1] n'est pas '\0'.
EINVAL
Le fichier référencé par kernel_fd ou initrd_fd est vide (longueur zéro).
ENOEXEC
kernel_fd ne fait pas référence à un fichier ouvert, ou le noyau ne peut pas charger ce fichier. Actuellement, le fichier doit être un bzImage et contenir un noyau x86 qui peut être chargé au-dessus de 4 Gio de mémoire (voir le fichier source du noyau Documentation/x86/boot.txt).
ENOMEM
Impossible d'allouer de la mémoire.
EPERM
L'appelant ne possède pas la capacité CAP_SYS_BOOT.

NORMES

Linux.

HISTORIQUE

Linux 2.6.13.
kexec_file_load()
Linux 3.17.

VOIR AUSSI
