NOM

kubectl create clusterrole - Créer un rôle de cluster

SYNTAXE

kubectl create clusterrole [OPTIONS]

DESCRIPTION

Crée un rôle de cluster.

OPTIONS

--aggregation-rule= Un sélecteur d'étiquettes d'agrégation pour combiner les ClusterRoles.

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de mappage est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server" ou "client". Si stratégie client, imprime seulement l'objet qui serait envoyé, sans l'envoyer. Si stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--non-resource-url=[] Une URL partielle à laquelle l'utilisateur devrait avoir accès.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--resource=[] Ressource à laquelle la règle s'applique

--resource-name=[] Ressource dans la liste blanche à laquelle la règle s'applique, répétez ce drapeau pour plusieurs éléments

--save-config=false Si vrai, la configuration de l'objet actuel sera enregistrée dans son annotation. Sinon, l'annotation restera inchangée. Ce drapeau est utile si vous souhaitez effectuer kubectl apply sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conservez les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être un parmi : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le serveur d'API, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur d'API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

--verb=[] Verbe qui s'applique aux ressources contenues dans la règle

OPTIONS HÉRITÉES DE COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas de délai d'attente pour les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version affichée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Crée un rôle de cluster nommé "pod-reader" qui permet à l'utilisateur d'effectuer des opérations "get", "watch" et "list" sur les pods
  kubectl create clusterrole pod-reader --verb=get,list,watch --resource=pods
  # Crée un rôle de cluster nommé "pod-reader" avec ResourceName spécifié
  kubectl create clusterrole pod-reader --verb=get --resource=pods --resource-name=readablepod --resource-name=anotherpod
  # Crée un rôle de cluster nommé "foo" avec API Group spécifié
  kubectl create clusterrole foo --verb=get,list,watch --resource=rs.apps
  # Crée un rôle de cluster nommé "foo" avec SubResource spécifié
  kubectl create clusterrole foo --verb=get,list,watch --resource=pods,pods/status
  # Crée un rôle de cluster nommé "foo" avec NonResourceURL spécifié
  kubectl create clusterrole "foo" --verb=get --non-resource-url=/logs/*
  # Crée un rôle de cluster nommé "monitoring" avec AggregationRule spécifié
  kubectl create clusterrole monitoring --aggregation-rule="rbac.example.com/aggregate-to-monitoring=true"

NOM

kubectl-create-clusterrole - Créer un ClusterRole.

SYNTAXE

kubectl create clusterrole NOM --verb=VERBS --resource=RESOURCES [flags]

DESCRIPTION

Ceci est une commande de haut niveau pour créer une ressource ClusterRole.

Un ClusterRole lie les permissions à un ensemble de ressources. Ces permissions peuvent s'appliquer à des ressources au niveau du cluster (comme les nœuds) ou à des ressources au niveau du namespace. Si un ClusterRole utilise des permissions sur des ressources au niveau du namespace, ces permissions peuvent être appliquées à tous les namespaces, ou à un sous-ensemble de namespaces si vous utilisez un RoleBinding.

Voici quelques exemples de la façon dont un ClusterRole peut être utilisé:

  • Il peut définir des permissions pour un utilisateur qui ne sont pas liées à un namespace spécifique, comme la gestion des nœuds.
  • Il peut définir des permissions pour un utilisateur dans tous les namespaces, comme la lecture de tous les pods dans tous les namespaces.
  • Il peut définir des permissions pour un contrôleur qui doit accéder aux ressources dans plusieurs namespaces.

Utilisez des rôles pour définir des permissions spécifiques à un namespace.

Vous pouvez créer un ClusterRole en utilisant soit le sous-commande kubectl create clusterrole avec les flags appropriés, soit en créant un fichier YAML ou JSON et en le soumettant à l'API. Voici un exemple de fichier YAML qui crée un ClusterRole:

apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: secret-reader
rules:
- apiGroups: [""] # "" indique le groupe d'API core
  resources: ["secrets"]
  verbs: ["get", "watch", "list"]

OPTIONS

--allow-missing-template-keys=true Allow missing keys that are going to be substituted in templates. --dry-run=false Server side dry run

--from string Explicitly use data from the ClusterRole named <clusterrole-name> to create the new ClusterRole.

--from-file='': To skip the ড্রাই-run, use --dry-run=false. To not mutate the existing clusterrole, use --dry-run=server. This flag can be passed multiple times to add multiple files.

--output='': Output format. One of: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-file).

--record=false Record current kubectl command in the resource annotation.

--resource='': Resource names that the ClusterRole can access. Example: deployments,pods.

--save-config=false If true, the configuration of de-registered resources will be saved in its annotation. Otherwise, the annotation will be removed.

--template='': Template string or path to template file that uses go template format, to create a new resource by merging with the associative resources that are created after calling the subcommands. (e.g. kubectl create clusterrole --template="{{.name}} {{.names}}\")

--verb='': Verb names that are allowed for the associated resources. Example: get,list,watch.

--windows-fields=[] Fields to be set to Windows; must be present in the template, and must have values for each object. A comma-separated list of fields.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--add-dir-header=false If true, add a directory header to the files sourced from the command line.

--allow-empty-dir=false If true, allow creating an empty directory for a resource.

--as string Username to impersonate for the operation. User is then checked for permissions in Kubernetes based on the impersonated username.

--as-group=[] Group to impersonate for the operation, this field is deprecated, the 'subgroups' field is in alpha and is controlled by the GroupVersionResourceInCRD feature gate.

--cache-dir="/home/user/.kube/cache" Default cache directory.

--certificate-authority="" Path to a cert file for the certificate authority.

--client-certificate="" Path to a client certificate file for TLS.

--client-key="" Path to a client key file for TLS.

--cluster="" The name of the kubeconfig context to use.

--context="" The name of the kubeconfig context to use.

--disable-compression=false If true, opt-out of default compression for all applicable requests to the API server.

--insecure-skip-tls-verify=false If true, the server's certificate will not be checked for validity. This is dangerous and recommended against. Use with caution.

--kubeconfig="" Path to the kubeconfig file to use for CLI requests.

--match-server-version=false Require server version to match client version.

--request-timeout="0" The length of time to wait before giving up on a single API server request. Non-zero requests should be thiểued with the context's configured timeout. If flag is not set, the timeout is equivalent to the server's timeout.

--tls-server-name="" Server name to use for server certificate validation. If not specified, the hostname used to contact the server is used.

--token="" Bearer token for authentication to the API server.

--user="" The name of the kubeconfig user to use.

--username="" Username for basic authentication to the API server.

EXEMPLE

# Créer un ClusterRole qui permet de lister et obtenir des secrets dans tous les namespaces.

kubectl create clusterrole secret-reader --verb=get,list,watch --resource=secrets
