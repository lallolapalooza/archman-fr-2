INTRODUCTIO

N

Kid3 est une application pour éditer les étiquettes ID3v1 et ID3v2 dans les fichiers MP3 de manière efficace. Ces étiquettes peuvent être éditées par la plupart des lecteurs MP3, mais pas de manière très confortable et efficace. De plus, les étiquettes dans les fichiers Ogg/Vorbis, Opus, DSF, FLAC, MPC, APE, MP4/AAC, MP2, Speex, TrueAudio, WavPack, WMA, WAV, AIFF et les modules de tracker (MOD, S3M, IT, XM) sont également prises en

charge.

Kid3 ne récupère ni ne code les fichiers MP3, mais il est conçu pour éditer les étiquettes ID3 de tous les fichiers d'un album de manière efficace, c'est-à-dire avec le moins de clics de souris et de frappes de touches possible. Là où la plupart des autres programmes peuvent éditer soit les étiquettes ID3v1 soit les étiquettes ID3v2, Kid3 a un contrôle complet sur les deux versions, peut convertir les étiquettes entre les deux formats et a accès à toutes les étiquettes ID3v2. Les étiquettes de plusieurs fichiers peuvent être définies à la même valeur, par exemple l'artiste, l'album, l'année et le genre de tous les fichiers d'un album ont généralement les mêmes valeurs et peuvent être définis ensemble. Si l'information pour les étiquettes est contenue dans le nom de fichier, les étiquettes peuvent être automatiquement définies à partir du nom de fichier. Il est également possible de définir le nom de fichier selon les étiquettes trouvées dans le fichier dans des formats

arbitraires.

La tâche d'édition est en outre facilitée par le remplacement automatique de caractères ou de sous-chaînes, par exemple pour supprimer les caractères illégaux des noms de fichiers. Le contrôle automatique des majuscules et des minuscules facilite l'utilisation d'un schéma de nommage cohérent dans toutes les

étiquettes.

Les informations d'étiquette pour des albums complets peuvent être prises depuis gnudb.org[1], MusicBrainz[2], Discogs[3], Amazon[4] ou d'autres sources de listes de titres. Le format d'import est librement configurable par des expressions

rationnelles.

d'utilisation

Cette section décrit une session typique avec Kid3. Supposons que nous ayons un dossier contenant des fichiers MP3 avec les titres de l'album "Let's Tag" du groupe "One Hit Wonder". Le dossier est nommé au format "artiste - album", dans notre cas One Hit Wonder - Let's Tag. Le dossier contient les titres au format "titre de la piste.mp3", ce qui est utile car les noms de fichiers sont courts (important lors de l'utilisation de lecteurs MP3 mobiles avec de petits écrans) et dans le bon ordre lorsqu'ils sont triés alphabétiquement (important lors de l'utilisation de lecteurs MP3 matériels qui lisent les titres dans l'ordre alphabétique ou dans l'ordre dans lequel ils sont gravés sur CD et cet ordre est alphabétique lors de l'utilisation de mkisofs). De plus, les informations sur l'artiste et l'album sont déjà dans le nom du dossier et n'ont pas besoin d'être répétées dans le nom de fichier. Mais revenons à notre exemple, le contenu du dossier ressemble à ceci

:

01 Intro.

mp3

02 We Only Got This One.

mp3

03 Outro.

mp3

Ces fichiers n'ont pas encore d'étiquettes et nous voulons les générer à l'aide de Kid3. Nous utilisons l'élément de menu Fichier → Ouvrir (ou le bouton de la barre d'outils) et sélectionnons l'un des fichiers de ce dossier. Tous les fichiers seront affichés dans la liste de fichiers. Paresseux comme nous sommes, nous voulons utiliser les informations des noms de dossier et de fic

hier pour générer les étiquettes. Par conséquent, nous sélectionnons tous les fichiers, puis cliquons sur le bouton To: Tag 1 dans la section Fichier. Cela définira les valeurs de titre, d'artiste, d'album et de piste dans tous les fichiers. Pour définir les valeurs d'année et de genre de tous les fichiers, nous gardons tous les fichiers sélectionnés et saisissons "2002" pour la D
ate et sélectionnons "Pop" dans la liste Genre. Pour définir uniquement ces deux valeurs, leurs cases à cocher sont automatiquement cochées et toutes les autres cases à cocher restent décochées. Maintenant, nous changeons la sélection en ne sélectionnant que le premier fichier et nous voyons que toutes les étiquettes contiennent les valeurs correctes. Les étiquettes des autres
fichiers peuvent également être vérifiées en les sélectionnant un par un. Lorsque nous sommes satisfaits des étiquettes, nous utilisons l'élément de menu Fichier → Enregistrer (ou le bouton de la barre d'outils). Sélectionner l'élément de menu Fichier → Créer une liste de lecture (ou le bouton de la barre d'outils) générera un fichier One Hit Wonder - Let's Tag.m3u dans le dossier.

Liste des fichiers

La liste des fichiers contient les noms de tous les fichiers du dossier ouvert qui correspondent au filtre de nom de fichier sélectionné (typiquement *.mp3 *.ogg *.opus *.dsf *.flac *.mpc *.aac *.m4a *.m4b *.m4p *.mp4 *.mp2 *.spx *.tta *.wv *.wma *.wav *.aiff *.ape). Un ou plusieurs fichiers peuvent être sélectionnés. Pour ne sélectionner aucun fichier, cliquez dans la zone vide après les entrées de la liste. La sélection détermine les fichiers qui sont affectés par les opérations disponibles à l'aide des boutons décrits ci-dessous.

Outre le nom, d'autres colonnes (taille, type, date de modification) avec les détails des fichiers peuvent être affichées. Les colonnes peuvent être masquées en décochant leur nom dans le menu contextuel de l'en-tête de colonne. L'ordre des colonnes peut être modifié par glisser-déposer. L'ordre de tri peut être basculé en cliquant sur l'en-tête de colonne.

Les valeurs des balises standard peuvent également être affichées et modifiées dans les colonnes de la liste des fichiers.

À gauche des noms, une icône peut être affichée : un disque pour indiquer que le fichier a été modifié ou des informations sur les balises présentes (V1, V2, V1V2 ou AUCUNE BALISE ; aucune icône n'est affichée si le fichier n'a pas encore été lu).

Les dossiers sont affichés avec une icône de dossier. Si un dossier est ouvert, ses fichiers sont affichés dans une arborescence hiérarchique. En sélectionnant des fichiers de sous-dossiers, des opérations peuvent être exécutées sur des fichiers de différents dossiers, ce qui est utile si la collection de musique est organisée avec un dossier par artiste contenant des dossiers pour les albums de cet artiste.

Cliquer sur le bouton droit de la souris dans la liste des fichiers ouvre un menu contextuel avec les commandes suivantes :

•Tout développer : Développe toutes les arborescences de dossiers (uniquement l'arborescence actuelle si la touche Maj est enfoncée)
•Tout réduire : Réduit toutes les arborescences de dossiers
•Renommer : Change le nom d'un fichier
•Déplacer vers la corbeille : Déplace un fichier vers la corbeille
•Lire : Lit un fichier, voir Lecture. Si le fichier sélectionné est une liste de lecture, les fichiers de la liste de lecture seront lus.
•Modifier : Modifier une liste de lecture, voir Modifier la liste de lecture.
•Les entrées suivantes sont des commandes utilisateur, qui peuvent être définies dans l'onglet Actions utilisateur de Configurer Kid3. La lecture au double-clic peut également y être activée.

Lorsque Sélectionner le fichier lors de la lecture est activé, la piste en cours de lecture est automatiquement sélectionnée dans la liste des fichiers.

Modifier la liste de lecture

Une liste de lecture peut être créée vide ou contenir les pistes d'un dossier, voir Créer une liste de lecture. Le fichier de liste de lecture ainsi créé peut être modifié par double-clic ou en utilisant Modifier depuis le menu contextuel de la liste des fichiers. Une boîte de dialogue avec les entrées de la liste de lecture s'affiche. Il est possible d'ouvrir plusieurs listes de lecture simultanément.

De nouvelles entrées peuvent être ajoutées par glisser-déposer depuis la liste des fichiers, un gestionnaire de fichiers ou une autre liste de lecture. Si une entrée est glissée depuis une autre liste de lecture, elle sera déplacée ou copiée selon le système. Pour invoquer l'autre opération, respectivement, la touche Maj, Ctrl ou Alt (pour copier au lieu de déplacer sur macOS®) doit être enfoncée. Le réordonnancement des entrées au sein de la liste de lecture est également possible par glisser-déposer. Alternativement, les entrées peuvent être déplacées à l'aide des raccourcis clavier Ctrl+Maj+Haut et Ctrl+Maj+Bas (sur macOS®, la touche Commande doit être enfoncée au lieu de Ctrl). Une entrée peut être supprimée à l'aide de la touche Suppr.

Veuillez noter ce qui suit : pour faire glisser des entrées de la liste des fichiers, elles doivent être maintenues sur le côté gauche (près des icônes), le même geste sur le côté droit effectuera une sélection multiple, une telle action est ainsi toujours facilement possible.

Lorsqu'une liste de lecture a été modifiée, les modifications peuvent être enregistrées à l'aide de Enregistrer ou annulées à l'aide de Annuler. Lorsque la fenêtre est fermée, une invite de confirmation est affichée s'il y a des modifications non enregistrées.

Les pistes sélectionnées dans une liste de lecture seront automatiquement sélectionnées dans la liste des fichiers, permettant ainsi de modifier leurs balises.

Pour exécuter des actions sur une liste de lecture, son fichier doit être sélectionné dans la liste des fichiers. Modifier depuis le menu contextuel mènera à la boîte de dialogue décrite dans cette section, et Lire lancera le lecteur multimédia avec les pistes de la liste de lecture. Les actions utilisateur peuvent agir sur les listes de lecture, par exemple Exporter le dossier de la liste de lecture, qui copie les fichiers d'une liste de lecture dans un dossier.

Liste des dossiers

La liste des dossiers contient les noms des dossiers dans le dossier ouvert, ainsi que le dossier actuel (.) et le dossier parent (..). Elle permet de changer rapidement de dossier sans utiliser la commande Ouvrir ou le glisser-déposer.

La visibilité, l'ordre et le tri des colonnes peuvent être configurés comme décrit dans la section concernant la liste des fichiers.

Fichier

Affiche des informations sur l'encodage (MP3, Ogg, Opus, DSF, FLAC, MPC, APE, MP2, MP4, AAC, Speex, TrueAudio, WavPack, WMA, WAV, AIFF), le débit binaire, le taux d'échantillonnage, les canaux et la durée du fichier.

La ligne de texte Nom contient le nom du fichier (si un seul fichier est sélectionné). Si ce nom est modifié, le fichier sera renommé lorsque la commande Enregistrer sera utilisée.

La boîte combinée et la ligne de texte Format contiennent le format à utiliser lorsque le nom du fichier est généré à partir de la première ou de la seconde balise. Le nom du fichier peut contenir des caractères arbitraires, même une partie de dossier séparée du nom de fichier par une barre oblique, mais ce dossier doit déjà exister pour que le renommage réussisse. Les codes spéciaux suivants sont utilisés pour insérer les valeurs des balises dans le nom du fichier :

•%s %{title} Titre (Chanson)
•%a %{artist} Artiste
•%l %{album} Album
•%c %{comment} Commentaire
•%y %{year} Année
•%t %{track} Piste (par exemple 01)
•%t %{track.n} Piste avec une largeur de champ n (par exemple 001 pour %{track.3})
•%T %{tracknumber} Piste (sans zéros initiaux, par exemple 1)
•%g %{genre} Genre
•%{ignore} Ignoré lors de la génération des balises à partir du nom de fichier

Les codes de format ne sont pas limités aux exemples ci-dessus. Tout nom de trame peut être utilisé, par exemple des noms de trames unifiés comme %{albumartist}, %{discnumber.1}, %{bpm} ou des noms spécifiques au format comme %{popm}.

Il est possible de préfixer et de suffixer des chaînes à la remplacement d'un code de format en les ajoutant entre guillemets doubles à l'intérieur des accolades d'un code de format. Ces chaînes ne seront insérées dans la chaîne résultante que si le code de format produit une valeur non vide. Par exemple, si le nom du fichier doit contenir à la fois le titre et le sous-titre, on pourrait utiliser %{title} [%{subtitle}] dans la chaîne de format. Mais cela produirait une chaîne se terminant par [] s'il n'y a pas de trame de sous-titre pour un fichier. Afin d'omettre les crochets s'il n'y a pas de sous-titre, il faut utiliser %{title}%{" ["subtitle"]"} à la place. Cela omettra les crochets, l'espace initial et le sous-titre s'il n'y en a pas.

La liste des formats disponibles peut être modifiée dans la boîte de dialogue qui apparaît en cliquant sur le bouton Nom de fichier à partir de la balise dans l'onglet Fichier des paramètres.

Une deuxième boîte combinée Format (avec une flèche vers le bas) est utilisée pour générer les balises à partir du nom de fichier. Si le format du nom de fichier ne correspond pas à ce modèle, quelques autres formats couramment utilisés sont essayés.

Certains formats de nom de fichier couramment utilisés sont déjà disponibles dans la boîte combinée, mais il est également possible de taper un format spécial dans la ligne de texte.

La liste des formats disponibles peut être modifiée dans la boîte de dialogue qui apparaît en cliquant sur le bouton Balise à partir du nom de fichier dans l'onglet Fichier des paramètres.

En interne, une expression régulière est construite à partir des codes de format. Si des expressions régulières avancées sont requises, le format pour générer les balises à partir des noms de fichiers peut être donné comme une expression régulière complète avec des captures précédées des codes de format, par exemple pour extraire les numéros de piste sans suppression des zéros initiaux, un format tel que "/%{track}(\d+) %{title}(.*)" pourrait être utilisé.

TAG EDITING

The tag editor provides quick access to all commonly used tags. It is available in two modes:

  • Single file: All controls are filled with the values from the current file.
  • Multiple files: All controls show common values if they are identical in all selected files. Otherwise, the controls are empty and unchecked.

The selection of files is done in the file list. The buttons next to the file names allow to select a file, to add new files or to remove existing files from the list. The values of the selected files are displayed in the tag editor. If you change the selection of files, the values are updated.

The following sections describe the function of the controls in the tag editor. In the multiple files mode, all controls for which no value is displayed will be empty after the current file is saved. If you want to write a value to all selected files, you can edit the value and check the appropriate check box. The values will be set for all selected files when the selection is changed and can be saved using the Save command.

Check boxes are provided to control the write operation for each tag field. If a check box is checked, the corresponding value will be written to all selected files. If it is unchecked, the value will not be changed. In the multiple files mode, if a value is identical in all selected files, it is displayed and the check box is checked. If the values differ, the value is empty and the check box is unchecked. If a value has to be set for all selected files, it can be edited and the check box has to be set. The values will be set for all selected files when the selection is changed and can be saved using the Save command.

The check boxes also control the operation of most commands affecting the tags, such as copy, paste and transfer between tags 1 and 2. To make it easier to use with multiple files where all check boxes are unchecked, these commands behave in the same way when all check boxes are checked and when all check boxes are unchecked.

From Tag 2: The tag 1 fields are set from the corresponding values in tag 2. If a single file is selected, the GUI controls are filled with the values from tag 2. If multiple files are selected, the tags of the files are directly set.

Copy: The copy buffer is filled with the Tag 1 values. Only values with checked check box will be used in subsequent Paste commands.

Paste: Pastes the values from the copy buffer into the GUI controls.

Remove: This will set all GUI controls to their empty values which results in removing all values. The saved file will then contain no tag 1.

In all other controls, the empty values as described above are displayed. All check boxes are unchecked to avoid unwanted changes. Tag 2

The GUI controls function in the same way as described for the Tag 1 section, but the size of the strings is not limited.

For the tag 2 Genre you can also use your own names besides the genres listed in the combo box, just type the name into the line edit.

The tag 2 cannot only contain the same values as the tag 1, the format is built in a flexible way from several frames which are themselves composed of several fields. The tag 2 table shows all the frames which are available in the selected file.

Edit: This will open a window which allows one to edit all fields of the selected frame. If multiple files are selected, the edited fields are applied to all selected files which contain such a frame.

Add: A requester to select the frame type will appear and a frame of the selected type can be edited and added to the file. This works also to add a frame to multiple selected files.

Delete: Deletes the selected frame in the selected files.

Drag album artwork here is shown if the file does not contain embedded cover art. A picture can be added using drag and drop from a browser or file manager and will be displayed here. Picture frames can be edited or added by double clicking on this control.

Tag 3

Some files can have more than two tags, and a third tag section is visible. The following file types can have such a Tag 3 section:

•MP3 files can have an ID3v1.1 tag, an ID3v2 (2.3.0 or 2.4.0) tag and in the third section an APE tag. Such APE tags are used for replay gain information. In the Tag 3 section, this information is visible, and the APE tag can be removed with the Remove button.
•The RIFF INFO chunk of WAV files is available in the Tag 3 section because the Tag 1 section is dedicated to ID3v1.1 tags and handles their restrictions. The Tag 2 is still used for ID3v2.4.0 tags, which are also supported for WAV files, but RIFF INFO chunks seem to be supported better.
•FLAC files normally use a Vorbis comment for their meta data. However, there are FLAC files which have ID3v1 and ID3v2 tags, which can be found in the Tag 1 and Tag 3 sections. ID3 tags in FLAC files are only supported by TagLib, therefore the OggFlacMetadata plugin has to be disabled in the Plugins tab of the settings.

The GUI controls work in the same way as in the Tag 2 section.

Synchronized Lyrics and Event Timing Codes

For information synchronized with the audio data, a specific editor is available. These frames are supported for ID3v2.3.0 and ID3v2.4.0 tags. To add such a frame, the specific frame name has to be selected in the list which appears when the Add button is clicked - Synchronized Lyrics or Event Timing Codes, respectively. The editor is the same for both types, for the event timing codes, only a predefined set of events is available whereas for the synchronized lyrics, text has to be entered. In the following, editing synchronized lyrics is explained.

A file having an ID3v2 tag is selected, the lyrics editor is entered using Add and selecting Synchronized Lyrics. For an existing Synchronized Lyrics frame, it is selected and Edit is clicked. The player is automatically opened with the current file so that the file can be played and paused to synchronize lyrics.

The settings at the top of the SYLT editor normally do not have to be changed. If the lyrics contains characters which are not present in the Latin 1 character set, changing the text encoding to UTF16 (or UTF8 for ID3v2.4.0) is advisable. For English lyrics and maximum compatibility, ISO-8859-1 should be used.

The Lyrics section has five buttons at the top. Add will add a new time event in the table. The time is taken from the position of the player, thus adding an entry while playing the track will add a line for the currently played position. The events in the table have to be chronologically ordered, therefore the row will be inserted accordingly. Entries with an invalid time are treated specially: If the currently selected row has an invalid time, its time stamp will be replaced by the current time instead of adding a new row. If the current time is not invalid, the first row with an invalid time will be used if present. This behavior should facilitate adding time stamps if the lyrics text is already in the table but the time stamps are missing (which is the case when importing unsynchronized lyrics). Note that the invalid time is represented as 00:00.00, i.e. the same as the time at the absolute beginning of the track, which is not invalid. To make a time invalid, press the Delete key, or use Clear from the context menu. New rows inserted using Insert row from the context menu or created when importing unsynchronized lyrics with From Clipboard or Import also contain invalid time stamps. Rows in the table can be deleted by clicking the Delete button or using Delete rows from the context menu.

Synchronized lyrics can be imported from a file using Import. The expected format is simple or enhanced LRC. If the selected file does not contain a square bracket in the first line, it is supposed to be a simple text file with unsynchronized lyrics. The lines from such a file are then imported having invalid time stamps. The time information can be added using the Add button or by manual entry. It is also possible to import lyrics via copy-paste using From Clipboard. Synchronized lyrics can be written to LRC files using Export. Note that only entries with valid time stamps will be exported and that the entries will be sorted by time. Entries with invalid time won't be stored in the SYLT frame either, so make sure to include all timing information before leaving the dialog.

The ID3 specification[5] suggests a time stamp for each syllable. However most players only support the granularity of a line or sentence. To support both use cases, Kid3 follows the same conventions as SYLT Editor[6]. Text which is entered into the table is assumed to start a new line unless it starts with a space or a hyphen. Exceptions to this rule are possible by starting a line with an underscore ('_') to force continuation or a hash mark ('#') to force a new line. These escape characters are not stored inside the SYLT frame. Inside the SYLT frame, new lines start with a line feed character (hex 0A) whereas continuations do not. When reading SYLT frames, Kid3 checks if the first entry starts with a line feed. If this is not the case, it is assumed that all entries are new lines and that no syllable continuations are used.

While the track is played, the row associated with the current playing position is highlighted, so that the correctness of the synchronization information can be verified. If an offset has to be added to one or more time stamps, this can be accomplished with the Add offset context menu. Negative values can be used to reduce the time. Using Seek to position in the context menu, it is possible to set the playing position to the time of the selected row.

Recommended procedure to add new synchronized lyrics

•Get the unsynchronized lyrics, e.g. using Lyrics → Embed Lyrics from the file list context menu.
•Copy the unsynchronized lyrics to the clipboard, just go to the Lyrics row in the frame table and press Ctrl+C.
•Add a synchronized lyrics frame (Add..., Synchronized Lyrics, OK), click From Clipboard.
•Now all lines from the unsynchronized lyrics are in the table, all time stamps are invalid (0:0:0.00). You can delete empty entries beforehand.
•Start playing the song by clicking the play button ► in the play toolbar at the bottom of the main window.
•When the next lyrics line with invalid timestamp comes, click Add or press Alt+A, the timestamp will be updated.
•Continue like this until all timestamps are set. If you missed something, stop playback and clear the timestamps using the Delete key or by selecting them and using Clear from the context menu. To restart playback from a given timestamp, use Seek to position from the context menu.

Chapters in MP4 Files

MP4 audiobooks typically have a .m4b extension and are rather large because they contain all chapters in a single file. To navigate in such files, they can contain chapter marks, which can be edited in Kid3 in a pseudo "Chapters" frame using the same editor which is used for synchronized lyrics. Note, however, that this feature is only available with the Mp4v2Metadata plugin, so make sure that it is activated and above the TaglibMetadata plugin in the Plugins tab of the settings if you have to edit MP4 chapters.

The chapter information in MP3 audiobooks is stored in multiple "Chapter" (CHAP) frames which are referenced by a "Table of Contents" (CTOC) frame, and these frames have embedded subframes. To edit this information in a single place, a pseudo "Chapters" frame can also be used for ID3v2 tags. Its contents are used to create the real chapter, table of contents and embedded frames: The Description is used as the table of contents title, the Text column contains the chapter titles, and the corresponding Time value will be the chapter start time and the end time of the preceeding chapter. The end time of last chapter is determined by the Time of the last row if its Text is empty.

L'importation à partir d'un serveur freedb.org est possible en utilisant une boîte de dialogue qui apparaît lorsque "From Server: gnudb.org" est sélectionné. L'artiste et le nom de l'album à rechercher peuvent être saisis dans les deux champs supérieurs, les albums qui correspondent à la requête seront affichés lorsque "Find" est cliqué et que les résultats de www.gnudb.org[7] sont reçus. L'importation des données de piste pour un album se fait en double-cliquant sur l'album dans la liste. Le serveur freedb.org à partir duquel importer peut être sélectionné ainsi que le chemin CGI. Les données importées sont affichées dans le tableau de prévisualisation de la boîte de dialogue d'importation. Lorsque vous êtes satisfait des pistes affichées, elles peuvent être importées en terminant la boîte de dialogue d'importation avec OK.

Si vous avez déjà un résultat de recherche ouvert dans le navigateur Web, vous pouvez entrer l'URL dans le premier champ de recherche. Le résultat apparaîtra alors dans la liste des albums et pourra être directement importé dans Kid3.

Une adresse e-mail enregistrée auprès de gnudb.org[8] peut être saisie dans le champ Token.

Une recherche sur le serveur Discogs peut être effectuée en utilisant Discogs. Comme dans la boîte de dialogue gnudb.org, vous pouvez entrer l'artiste et l'album, puis choisir parmi une liste de sorties. Un Token peut être entré pour utiliser l'API RESTful de Discogs au lieu de leur interface Web, qui est souvent modifiée, ce qui peut casser le parseur d'importation. Vous devez créer un compte sur Discogs[9], puis générer un token sur leur site Web (Paramètres/Développeurs, Générer un nouveau token). N'oubliez pas de sauvegarder les paramètres après avoir entré le token afin de l'utiliser également pour les requêtes ultérieures. Si "Standard Tags" est coché, les informations standard sont importées, par exemple l'artiste, l'album et le titre. Si "Additional Tags" est coché, plus d'informations sont importées si disponibles, par exemple les interprètes, les arrangeurs ou l'éditeur. Si "Cover Art" est coché, la pochette sera téléchargée si disponible.

Une recherche sur Amazon peut être effectuée en utilisant Amazon. Comme dans la boîte de dialogue gnudb.org, vous pouvez entrer l'artiste et l'album, puis choisir parmi une liste de sorties. Si "Additional Tags" est coché, plus d'informations sont importées si disponibles, par exemple les interprètes, les arrangeurs ou l'éditeur. Si "Cover Art" est coché, la pochette sera téléchargée si disponible.

Vous pouvez rechercher de la même manière dans la base de données de sorties de MusicBrainz en utilisant "From MusicBrainz Release". Le flux de travail est le même que celui décrit pour "From gnudb.org".

L'importation à partir d'un serveur MusicBrainz est possible en utilisant la boîte de dialogue qui apparaît lorsque "From MusicBrainz Fingerprint" est sélectionné. Le serveur peut être sélectionné comme dans la boîte de dialogue d'importation freedb. Ci-dessous se trouve un tableau affichant les données de piste importées. La colonne de droite montre l'état de la requête MusicBrainz, qui commence par "Pending" (En attente) lorsque la boîte de dialogue est ouverte. Ensuite, l'empreinte digitale est recherchée et si elle ne donne aucun résultat, une autre recherche utilisant les tags dans le fichier est tentée. Ainsi, il peut être utile pour une requête MusicBrainz réussie de stocker des informations connues (par exemple, l'artiste et l'album) dans les tags avant l'importation. Si un résultat a été trouvé, la recherche se termine à l'état "Recognized" (Reconnu), sinon rien n'a été trouvé ou plusieurs résultats ambigus et l'un d'eux doit être sélectionné par l'utilisateur. OK et Apply utilisent les données importées, Cancel ferme la boîte de dialogue. La fermeture peut prendre un certain temps car toute la machinerie MusicBrainz doit être arrêtée.

Pour l'importation de données textuelles, "From File/Clipboard" ouvre une sous-boîte de dialogue, où plusieurs formats d'importation préconfigurés sont disponibles. Les deux premiers, "CSV unquoted" et "CSV quoted", peuvent être utilisés pour importer des données qui ont été exportées par la boîte de dialogue Export. Les données CSV peuvent être modifiées avec une feuille de calcul et doivent être écrites en utilisant des tabulations comme délimiteurs. L'importation devrait alors être possible en utilisant "CSV quoted", qui est plus flexible que "CSV unquoted". Cependant, ses champs ne peuvent pas contenir de guillemets doubles. Si vous exportez uniquement depuis Kid3 et importez plus tard, "CSV unquoted" peut être utilisé comme un format simple à cet effet. Notez qu'il existe également des commandes "Export CSV" et "Import CSV" dans le menu contextuel de la liste des fichiers, qui utilisent des scripts pour exporter et importer des données CSV de manière plus complète, puissante et flexible.

Le format suivant, "freedb HTML text", peut être utilisé pour copier des informations à partir d'une page HTML de freedb.org[10]. Recherchez un album dans freedb et si les informations souhaitées sont affichées dans le navigateur Web, copiez le contenu dans le presse-papiers. Cliquez ensuite sur le bouton "From Clipboard" et les pistes importées seront affichées dans le tableau de prévisualisation en haut de la boîte de dialogue. Si vous êtes satisfait des données importées, terminez la boîte de dialogue avec OK, ce qui insérera les données dans les tags du dossier actuel. La destination (Tag 1, Tag 2 ou Tag 1 et Tag 2) peut être sélectionnée avec une boîte combinée. Les fichiers du dossier actuel doivent être dans le bon ordre de piste pour que leurs tags soient assignés. C'est le cas s'ils sont numérotés.

Le format d'importation préconfiguré suivant, "freedb HTML source", peut être utilisé si les données sont disponibles sous forme de document HTML. L'importation est possible en utilisant le bouton "From File", qui ouvre un sélecteur de fichier, ou en copiant son contenu à partir d'un éditeur, puis en important à partir du presse-papiers. Ce format peut être utile pour l'importation hors ligne, bien que le document HTML puisse également être ouvert dans un navigateur, puis importé dans le premier format via le presse-papiers.

D'autres formats préconfigurés, par exemple "Track Title Time", sont disponibles. Un format personnalisé vide peut être créé avec "Add" pour être défini par l'utilisateur. Deux lignes sous le nom du format peuvent être définies avec une expression régulière pour capturer les champs du texte d'importation. La première expression régulière sera analysée une fois par document pour collecter des données par album telles que l'artiste, l'album, l'année et le genre. La deuxième ligne est essayée de correspondre du début du document à la fin pour obtenir les données de piste, généralement le numéro et le titre. Les expressions régulières incluent toutes les fonctionnalités offertes par Qt(TM), qui est la plupart de ce que Perl propose. Les constructions de parenthèses "(..)" créent des tampons de capture pour les champs à importer et sont précédées de codes spécifiques à Kid3 pour spécifier quel champ capturer. Les codes sont les mêmes que ceux utilisés pour le format de nom de fichier, en plus des codes listés ci-dessous, tout nom de trame est possible :

•%s %{title} Titre (Chanson)
•%a %{artist} Artiste
•%l %{album} Album
•%c %{comment} Commentaire
•%y %{year} Année
•%t %{track} Piste
•%g %{genre} Genre
•%d %{duration} Durée

Par exemple, une expression régulière de piste (deuxième ligne) pour importer à partir d'une playlist .m3u pourrait être "<code>%{track}(\d+)\s+%{title}(\S[^\r\n]*)\.mp3[\r\n]</code>". Tous les formats peuvent être modifiés en éditant les expressions régulières et le nom, puis en cliquant sur "Save Settings". Ils seront stockés dans le fichier kid3rc dans le dossier de configuration. Ce fichier peut être modifié directement pour avoir plus de formats d'importation ou il peut être supprimé pour revenir aux formats par défaut. Les formats peuvent être supprimés en utilisant "Remove".

Accuracy (Précision) affiche une estimation de la qualité de la correspondance entre les informations importées et les pistes données. Elle utilise les durées des pistes ou les noms de fichiers pour calculer le niveau de similarité en pourcentage. Cover Art affiche l'URL de l'image de la pochette de l'album qui sera téléchargée.

Pour vérifier si les pistes importées correspondent à l'ensemble actuel de fichiers, la durée des pistes importées peut être comparée à la durée des fichiers. Cette option peut être activée avec la case à cocher "Check maximum allowable time difference (sec):" (Vérifier la différence de temps maximale autorisée (sec) :) et la différence de temps maximale tolérée peut être définie en secondes. Si une discordance de longueur est détectée, la longueur sera affichée avec un fond rouge dans le tableau de prévisualisation.

Si les fichiers sont ordonnés différemment des pistes importées, leurs pistes assignées devront être modifiées. Cette tâche peut être facilitée en utilisant l'option "Match with" (Correspondre avec) avec les boutons "Length" (Longueur), "Track" (Piste) et "Title" (Titre), qui réordonneront les pistes selon le champ correspondant. Pour corriger manuellement les assignations, une piste peut être glissée avec le bouton gauche de la souris en maintenant la touche Ctrl enfoncée, puis déposée à son nouvel emplacement.

S'il y a plus de pistes importées que de fichiers, par exemple si le dossier actuel ne contient que le deuxième disque d'un album double, mais que les pistes des deux disques sont importées, il est possible de supprimer les pistes du premier disque en les sélectionnant en cliquant sur l'étiquette de ligne de la première piste, puis en cliquant sur l'étiquette de ligne de la dernière piste du premier disque tout en maintenant la touche Maj enfoncée, et enfin en supprimant les pistes en appuyant sur la touche Suppr.

Lorsque la boîte de dialogue d'importation est ouverte, elle contient le contenu actuel des tags. Le type de tag (Tag 1, Tag 2, Tag 1 et Tag 2) peut être sélectionné à l'aide de la boîte combinée "Destination". Le bouton situé à droite de cette boîte combinée peut être utilisé pour rétablir le contenu des tags. Les cases à cocher dans la première colonne du tableau peuvent être utilisées pour sélectionner les pistes qui sont importées. Cela peut être utile si un dossier contient les pistes des deux CD d'un double CD et que seules les pistes du deuxième CD doivent être importées.

Pour identifier les pistes qui sont importées, il est possible d'afficher les noms de fichiers ou les chemins complets des fichiers en utilisant le menu contextuel de l'en-tête du tableau. Les valeurs dans le tableau d'importation peuvent être modifiées. Le bouton "revert" (rétablir) à droite de la boîte combinée "Destination" peut être utilisé pour restaurer le contenu des tags, ce qui peut également être utile après avoir changé la "Destination".

Le Dialogue d'exportation est utilisé pour stocker des données à partir des étiquettes dans un fichier ou le presse-papiers. L'éditeur en haut affiche un aperçu des données à exporter. Les paramètres de format sont similaires à ceux du dialogue d'importation : le champ le plus haut contient le titre (par exemple, « CSV non quoté »), suivi de l'en-tête, qui sera généré au début du fichier. L'ensemble fonctionne comme le format du nom de fichier, et les mêmes codes sont utilisés ainsi que quelques codes supplémentaires. Non seulement les codes listés ci-dessous, mais tous les noms de cadres d'étiquettes peuvent être utilisés.

•%s %{title} Titre (Chanson)
•%a %{artist} Artiste
•%l %{album} Album
•%c %{comment} Commentaire
•%y %{year} Année
•%t %{track} Piste (par exemple, 01)
•%t %{track.n} Piste avec une largeur de champ n (par exemple, 001 pour %{track.3})

Every folder

A playlist is created in every folder which contains listed files, and each playlist contains the files of that folder.

Web Links

The Web Links page allows you to define custom web links that can be used to search for information about the current song or album. These links can be opened directly from Kid3, for example to download lyrics or cover art.

You can define new web links by clicking the "Add" button. For each web link, you can specify a name, a URL, and a command. The URL can contain placeholders that will be replaced with the corresponding information from the current song or album. The following placeholders are available:

%artist
The artist of the current song.
%album
The album of the current song.
%title
The title of the current song.
%track
The track number of the current song.
%year
The year of the current song.
%genre
The genre of the current song.
%comment
The comment of the current song.
%url
The URL of the current song.
%u
URL-encodes the following placeholder. For example, %u{artist} will URL-encode the artist information.

The command can be used to specify how the web link should be opened. For example, you can use the command "%{browser}" to open the web link in your default web browser.

Here are some examples of how to use the web links feature:

To search for lyrics on LyricWiki, you can define a web link with the following URL:

%{browser} http://lyricwiki.org/%u{artist}:%u{title}

This will open your default web browser and navigate to the LyricWiki page for the current song's lyrics. The "%u" before "artist" and "title" ensures that these values are properly URL-encoded.

To search for album cover art on Google Images, you can define a web link with the following URL:

%{browser} http://images.google.com/images?q=%u{artist}%20%u{album}

This will open your default web browser and search for images related to the current song's artist and album on Google Images. The "%20" represents a space character in the URL.

You can also add album cover art to tag 2 by using the web links feature to search for images on Google or Amazon. Once you have found an image, you can add it to the tag using drag and drop or by using the "Add" button and selecting "Picture frame". Picture frames are supported for ID3v2, MP4, FLAC, Ogg, and ASF tags.

You can add and delete entries in the web links table using the context menu.

Plugins

On the Plugins page, you can enable or disable available plugins. Plugins are divided into two sections:

Metadata Plugins & Priority list
This section contains plugins that support audio file formats. The order of plugins in this list is important, as they are tried from top to bottom. If multiple plugins support a specific format, the file will be opened with the first plugin in the list that supports it. The TaglibMetadata plugin supports most formats. If it's at the top of the list, it will handle most files. To use a different plugin for a specific format, ensure it is placed above TaglibMetadata in the list.
Details about the metadata plugins and reasons for using them over TagLib are provided below:
  • Id3libMetadata: Uses id3lib[15] for ID3v1.1 and ID3v2.3 tags in MP3, MP2, and AAC files. Supports more frame types than TagLib.
  • OggFlacMetadata: Uses libogg[16], libvorbis, libvorbisfile[17] for Ogg files, and libFLAC++ and libFLAC[18] for FLAC files. These are the official libraries for these formats.
  • TaglibMetadata: Uses TagLib[19], which supports a wide range of audio file formats compatible with Kid3.
  • Mp4v2Metadata: Originally used mp4v2[20] by Kid3 to support M4A files. Useful if encountering issues with TagLib's M4A support.
Available Plugins
This section lists the remaining plugins. Their order does not matter, but they can be enabled or disabled using checkboxes.
  • AmazonImport: Used for the "Import from Amazon..." function.
  • DiscogsImport: Used for the "Import from Discogs..." function.
  • FreedbImport: Used for the "Import from gnudb.org..." function.
  • MusicBrainzImport: Used for the "Import from MusicBrainz Release..." function.
  • AcoustidImport: Used for the "Import from MusicBrainz Fingerprint..." function, which relies on the Chromaprint[21] and libav[22] libraries.

Disabled plugins are not loaded, which helps optimize resource usage and startup time. Changes made on this page take effect only after restarting Kid3.

KID3-CLI

Commands

kid3-cli provides a command-line interface for Kid3. If a folder path is provided, that folder is opened. If one or more file paths are given, their common folder is opened, and the files are selected. Subsequent commands will operate on this selection. Commands are specified using the -c option. When multiple commands are provided, they are executed in the order they appear. If files are modified by commands, they are saved at the end. If no command options are given, kid3-cli starts in interactive mode, where commands can be entered and will affect the current selection. The following sections detail all available commands.

Help

help [COMMAND-NAME]

Displays help on the parameters of COMMAND-NAME, or on all commands if no command name is specified.

Timeout

timeout [ | default | off | TIME ]

Overrides the default command timeout. CLI commands abort after a command-specific timeout expires. This timeout is 10 seconds for ls and albumart, 60 seconds for autoimport and filter, and 3 seconds for all other commands. If a large number of files needs processing, these timeouts might be too strict. Consequently, the timeout for all commands can be set to TIME ms, switched off entirely, or left at its default value.

Quit application

exit [force]

Exits the application. If there are unsaved modified files, the force parameter is required.

Change folder

cd [FOLDER]

If no FOLDER is provided, changes to the home folder. If a folder is given, it changes into that folder. If one or more file paths are provided, it changes to their common folder and selects the files.

Print the filename of the current folder

pwd

Prints the filename of the current working folder.

Folder list

ls

Lists the contents of the current folder. This corresponds to the file list in the Kid3 GUI. Five characters preceding the filenames indicate the file's status:

•> File is selected.
•* File is modified.
•1 File has a tag 1, otherwise '-' is displayed.
•2 File has a tag 2, otherwise '-' is displayed.
•3 File has a tag 3, otherwise '-' is displayed.
kid3-cli> ls
  1-- 01 Intro.mp3
> 12- 02 We Only Got This One.mp3
 *1-- 03 Outro.mp3

In this example, all files have a tag 1. The second file also has a tag 2 and is selected. The third file is modified.

save

To select all files, enter select all; to deselect all files, enter select none. To traverse files in the current folder, start with select first, then move forward using select next or backward using select previous. Specific files can be added to the current selection by providing their filenames. Wildcards are supported, so select *.mp3 will select all MP3 files in the current folder.

Une application pour les spécifications de champs est le cas où vous souhaitez un cadre TXXX personnalisé avec la description « rating » au lieu d'un cadre Popularimeter standard (ceci semble être utilisé par certains plugins). kid3-cli> set rating ""

kid3-cli> set rating 5

Le nom de cadre pseudo « ratingstars » peut être utilisé pour définir la valeur du cadre « rating » à la valeur spécifique au format correspondant au nombre d'étoiles (0 à 5). Le nom de cadre « rating » peut être utilisé pour définir la valeur interne.

Définir « ratingstars » sur plusieurs fichiers ayant des formats de balises différents ne fonctionnera pas car le cadre avec la valeur mappée à partir du nombre d'étoiles est créé pour le premier fichier puis utilisé pour tous les fichiers. Exemples

Définir le titre contenant une apostrophe. Les commandes passées à kid3-cli avec -c doivent être entre guillemets si elles ne se composent pas d'un seul mot. Si une telle commande a elle-même un argument contenant des espaces, cet argument doit également être mis entre guillemets. Dans les shells UNIX®, des guillemets simples ou doubles peuvent être utilisés, mais sur l'invite de commande Windows, il est important que les guillemets extérieurs soient faits avec des guillemets doubles et à l'intérieur de ces guillemets, des guillemets simples sont utilisés. Si le texte à l'intérieur des guillemets simples contient une apostrophe, elle doit être échappée à l'aide d'un caractère backslash, comme le montre l'exemple suivant :

kid3-cli -c "set title 'I\'ll be there for you'" /chemin/vers/dossier

Définir la pochette d'album dans tous les fichiers d'un dossier en utilisant la fonction d'importation par lots :

kid3-cli -c "autoimport 'Cover Art'" /chemin/vers/dossier

Supprimer les cadres de commentaires et appliquer le format de tag dans les deux tags de tous les fichiers MP3 d'un dossier :

kid3-cli -c "set comment '' 1" -c "set comment '' 2" \
-c "tagformat 1" -c "tagformat 2" /chemin/vers/dossier/*.mp3

Importer automatiquement le tag 2, synchroniser vers le tag 1, définir les noms de fichiers à partir du tag 2 et enfin créer une playlist :

kid3-cli -c autoimport -c "syncto 1" -c fromtag -c playlist \
  /chemin/vers/dossier/*.mp3

Pour tous les fichiers avec un tag ID3v2.4.0, convertir en ID3v2.3.0 et supprimer le cadre d'arrangeur :

kid3-cli -c "filter 'ID3v2.4.0 Tag'" -c "select all" -c to23 \
  -c "set arranger ''" /chemin/vers/dossier

Ce script Python utilise kid3-cli pour générer des images sonores iTunes Sound Check (iTunNORM) à partir des informations de gain de reproduction.

#!/usr/bin/env python3
# Générer iTunes Sound Check à partir de ReplayGain.
import os, sys, subprocess
def rg2sc(dirpath):
  for root, dirs, files in os.walk(dirpath):
    for name in files:
      if name.endswith(('.mp3', '.m4a', '.aiff', '.aif')):
        fn = os.path.join(root, name)
        rg = subprocess.check_output([
          'kid3-cli', '-c', 'get "replaygain_track_gain"',
           fn]).strip()
        if rg.endswith(b' dB'):
          rg = rg[:-3]
        try:
          rg = float(rg)
        except ValueError:
          print('La valeur %s de %s n\'est pas un flottant' % (rg, fn))
          continue
        sc = (' ' + ('%08X' % int((10 ** (-rg / 10)) * 1000) )) * 10
        subprocess.call([
          'kid3-cli', '-c', 'set iTunNORM "%s"' % sc, fn])
if __name__ == '__main__':
  rg2sc(sys.argv[1])

Format JSON

Afin de faciliter l'analyse des résultats de kid3-cli, il est possible d'obtenir la sortie au format JSON. Lorsque la requête est au format JSON, la réponse sera également en JSON. Un format compact de la requête donnera également une représentation compacte de la réponse. Si la requête contient un champ "id", elle est supposée être une requête JSON-RPC et la réponse contiendra un champ "jsonrpc" et l'"id" de la requête. Le format de la requête utilise les mêmes commandes que le CLI standard, le champ "method" contient la commande et les paramètres (le cas échéant) sont donnés dans la liste "params". La réponse contient un objet "result", qui peut également être nul si la commande kid3-cli correspondante ne renvoie aucun résultat. En cas d'erreur, un objet "error" est retourné avec les champs "code" et "message" tels qu'utilisés dans JSON-RPC.

kid3-cli> {"method":"set","params":["artist","Un Artiste"]}
{"result":null}
kid3-cli> {"method":"get","params":["artist",2]}
{"result":"Un Artiste"}
kid3-cli> {"method": "get", "params": ["artist"]}
{
    "result": "Un Artiste"
}
kid3-cli> {"jsonrpc":"2.0","id":"123","method":"get","params":["artist"]}
{"id":"123","jsonrpc":"2.0","result":"Un Artiste"}

Comment obtenir Kid3

Kid3 est disponible sur https://kid3.kde.org.

Prérequis

Kid3 nécessite Qt(TM)[25]. KDE[26] est recommandé mais pas obligatoire, car Kid3 peut également être compilé comme une application Qt(TM). Kid3 peut être compilé pour les systèmes où ces bibliothèques sont disponibles, par exemple pour GNU/Linux®, Windows® et macOS®. Pour taguer les fichiers Ogg/Vorbis, libogg[16], libvorbis et libvorbisfile[17] sont requis, pour les fichiers FLAC libFLAC++ et libFLAC[18]. id3lib[15] est utilisé pour les fichiers MP3. Ces quatre formats sont également pris en charge par TagLib[19], qui peut également gérer les fichiers Opus, MPC, APE, MP2, Speex, TrueAudio, WavPack, WMA, WAV, AIFF et les modules de tracker. Pour importer à partir d'empreintes acoustiques, Chromaprint[21] et libav[22] sont utilisés.

Kid3 est disponible pour la plupart des distributions Linux®, Windows® et macOS®. Des liens peuvent être trouvés sur https://kid3.kde.org.

Compilation et Installation

Vous pouvez compiler Kid3 avec ou sans KDE. Sans KDE, Kid3 est une simple application Qt(TM) et manque de certaines fonctionnalités de configuration et de session.

Pour une version KDE, allez dans le dossier principal et tapez

% cmake .
% make
% make install

Pour compiler pour différentes versions de Qt(TM) ou KDE, définissez les options cmake correspondantes.

Si toutes les bibliothèques ne sont pas présentes, Kid3 est compilé avec une fonctionnalité réduite. Vous devriez donc veiller à avoir tous les paquets de développement souhaités installés. D'un autre côté, les options cmake contrôlent quelles bibliothèques sont compilées. Par défaut, il s'agit de -DWITH_TAGLIB:BOOL=ON -DWITH_MP4V2:BOOL=OFF -DWITH_ID3LIB:BOOL=ON -DWITH_CHROMAPRINT:BOOL=ON -DWITH_VORBIS:BOOL=ON -DWITH_FLAC:BOOL=ON . Ces options peuvent être désactivées en utilisant OFF.

Pour construire Kid3 comme une application Qt(TM) sans KDE, utilisez l'option cmake -DWITH_APPS=Qt. Pour construire une application KDE et une application Qt(TM), définissez -DWITH_APPS="Qt;KDE".

Pour utiliser une installation Qt(TM) spécifique, définissez -DQT_QMAKE_EXECUTABLE=/chemin/vers/qmake.

La génération de paquets RPM est prise en charge par le fichier kid3.spec, pour les paquets Debian®, exécutez build.sh deb.

L'application Qt(TM) peut également être compilée pour Windows® et macOS®. Le script build.sh peut être utilisé pour télécharger et compiler toutes les bibliothèques requises et créer un paquet Kid3.

Configuration

Avec KDE, les paramètres sont stockés dans .config/kid3rc, l'état de l'application dans .local/share/kid3/kid3staterc. En tant qu'application Qt(TM), ce fichier se trouve dans .config/Kid3/Kid3.conf. Sous Windows®, la configuration est stockée dans le registre. Sous macOS® dans un fichier plist.

La variable d'environnement KID3_CONFIG_FILE peut être utilisée pour définir le chemin du fichier de configuration.

Exemples QML

Les scripts QML peuvent être appelés via le menu contextuel de la liste de fichiers et peuvent être définis dans l'onglet Actions utilisateur des paramètres. Les scripts qui y sont définis peuvent servir d'exemples pour programmer des scripts personnalisés. QML utilise JavaScript, voici l'obligatoire "Hello World" :

import Kid3 1.0
Kid3Script {
  onRun: {
    console.log("Hello world, folder is", app.dirName)
    Qt.quit()
  }
}

Si ce script est enregistré sous /chemin/vers/Example.qml, la commande utilisateur peut être définie comme @qml /chemin/vers/Example.qml avec le nom Test QML et Sortie cochée. Il peut ensuite être lancé en utilisant l'élément Test QML dans le menu contextuel de la liste de fichiers, et la sortie sera visible dans la fenêtre.

Malheureusement, le lancement des scripts QML en utilisant qml (par exemple, qml -apptype widget -I /usr/lib/kid3/plugins/imports /chemin/vers/Example.qml) est défectueux dans les versions récentes de Qt. Mais kid3-cli offre une alternative pour exécuter un script QML depuis la ligne de commande en utilisant sa commande execute.

kid3-cli -c "execute @qml /chemin/vers/Example.qml"

Pour lister les titres dans les balises 2 de tous les fichiers du dossier courant, le script suivant pourrait être utilisé :

import Kid3 1.0
Kid3Script {
  onRun: {
    app.firstFile()
    do {
      if (app.selectionInfo.tag(Frame.Tag_2).tagFormat) {
        console.log(app.getFrame(tagv2, "title"))
      }
    } while (app.nextFile())
  }
}

Si le dossier contient de nombreux fichiers, un tel script pourrait bloquer l'interface utilisateur pendant un certain temps. Pour les opérations longues, il devrait donc y avoir une pause de temps en temps. L'implémentation alternative ci-dessous a le travail pour un seul fichier déplacé dans une fonction. Cette fonction s'invoque elle-même avec un délai de 1 ms à la fin, étant donné que d'autres fichiers doivent être traités. Cela garantira que l'interface graphique reste réactive pendant l'exécution du script.

import Kid3 1.0
Kid3Script {
  onRun: {
    function doWork() {
      if (app.selectionInfo.tag(Frame.Tag_2).tagFormat) {
        console.log(app.getFrame(tagv2, "title"))
      }
      if (!app.nextFile()) {
        Qt.quit()
      } else {
        setTimeout(doWork, 1)
      }
    }
    app.firstFile()
    doWork()
  }
}

En utilisant app.firstFile() avec app.nextFile(), tous les fichiers du dossier courant seront traités. Si seuls les fichiers sélectionnés doivent être affectés, utilisez firstFile() et nextFile() à la place, ce sont des fonctions pratiques du composant Kid3Script. L'exemple suivant est un script qui copie uniquement les trames du numéro de disque et de copyright du fichier sélectionné.

import Kid3 1.1
Kid3Script {
  onRun: {
    function doWork() {
      if (app.selectionInfo.tag(Frame.Tag_2).tagFormat) {
        app.setFrame(tagv2, "*.selected", false)
        app.setFrame(tagv2, "discnumber.selected", true)
        app.setFrame(tagv2, "copyright.selected", true)
        app.copyTags(tagv2)
      }
      if (!nextFile()) {
        Qt.quit()
      } else {
        setTimeout(doWork, 1)
      }
    }
    firstFile()
    doWork()
  }
}
