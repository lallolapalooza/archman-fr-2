NOM

kubectl label - Mettre à jour les étiquettes d'une ressource

SYNOPSIS

kubectl label [OPTIONS]

DESCRIPTION

Mettre à jour les étiquettes d'une ressource.

  • Une clé d'étiquette et sa valeur doivent commencer par une lettre ou un chiffre, et peuvent contenir des lettres, des chiffres, des tirets, des points et des tirets bas, jusqu'à 63 caractères chacune.
  • Optionnellement, la clé peut commencer par un préfixe de sous-domaine DNS et un seul '/', comme example.com/my-app.
  • Si --overwrite est vrai, alors les étiquettes existantes peuvent être écrasées, sinon tenter d'écraser une étiquette entraînera une erreur.
  • Si --resource-version est spécifié, alors les mises à jour utiliseront cette version de ressource, sinon la resource-version existante sera utilisée.

OPTIONS

--all=false Sélectionner toutes les ressources, dans le namespace des types de ressources spécifiés

-A, --all-namespaces=false Si vrai, vérifier l'action spécifiée dans tous les namespaces.

--allow-missing-template-keys=true Si vrai, ignorer toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est absent dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server", ou "client". Si stratégie client, imprimer uniquement l'objet qui serait envoyé, sans l'envoyer. Si stratégie serveur, soumettre une requête côté serveur sans persister la ressource.

--field-manager="kubectl-label" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--field-selector="" Sélecteur (requête de champ) pour filtrer, prend en charge '=', '==', et '!='.(par ex. --field-selector cle1=valeur1,cle2=valeur2). Le serveur ne prend en charge qu'un nombre limité de requêtes de champ par type.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource dont les étiquettes doivent être mises à jour

-k, --kustomize="" Traiter le répertoire kustomize. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--list=false Si vrai, afficher les étiquettes d'une ressource donnée.

--local=false Si vrai, l'étiquette ne contactera PAS le serveur API mais s'exécutera localement.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=false Si vrai, autoriser l'écrasement des étiquettes, sinon rejeter les mises à jour d'étiquettes qui écrasent les étiquettes existantes.

--record=false Enregistrer la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur faux, n'enregistrez pas la commande. Si défini sur vrai, enregistrez la commande. Si non défini, par défaut, mettez à jour la valeur de l'annotation existante uniquement si une existe déjà.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--resource-version="" Si non vide, la mise à jour des étiquettes ne réussira que si c'est la version actuelle de la ressource pour l'objet. Valide uniquement lors de la spécification d'une seule ressource.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'.(par ex. -l cle1=valeur1,cle2=valeur2,cle3 in (valeur3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--show-managed-fields=false Si vrai, conserver les managedFields lors de l'impression des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS INHERITÉS DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la feature gate KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée du namespace pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une requête serveur unique. Les valeurs non nulles doivent contenir une unité de temps correspondante (par ex. 1s, 2m, 3h). Une valeur zéro signifie qu'il n'y a pas de délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Mettre à jour le pod 'foo' avec l'étiquette 'unhealthy' et la valeur 'true'
  kubectl label pods foo unhealthy=true
  # Mettre à jour le pod 'foo' avec l'étiquette 'status' et la valeur 'unhealthy', en écrasant toute valeur existante
  kubectl label --overwrite pods foo status=unhealthy
  # Mettre à jour tous les pods dans le namespace
  kubectl label pods --all status=unhealthy
  # Mettre à jour un pod identifié par le type et le nom dans "pod.json"
  kubectl label -f pod.json status=unhealthy
  # Mettre à jour le pod 'foo' uniquement si la ressource est inchangée par rapport à la version 1
  kubectl label pods foo status=unhealthy --resource-version=1
  # Mettre à jour le pod 'foo' en supprimant une étiquette nommée 'bar' si elle existe
  # Ne nécessite pas le drapeau --overwrite
  kubectl label pods foo bar-
