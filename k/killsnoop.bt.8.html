NOM

killsnoop.bt - Trace les signaux émis par l'appel système kill(), tkill(), tgkill(). Utilise bpftrace/eBPF.

SYNTAXE

killsnoop.bt

DESCRIPTION

killsnoop trace les appels système kill(), tkill(), tgkill() pour afficher les signaux envoyés via cette méthode. Ceci peut être utile pour dépanner des applications défaillantes où un mécanisme inconnu envoie des signaux.

Cela fonctionne en traçant les points de trace des appels système kill(), tkill(), tgkill().

Comme il utilise BPF, seul l'utilisateur root peut utiliser cet outil.

EXIGENCES

CONFIG_BPF et bpftrace.

EXEMPLES

Trace tous les appels système kill(), tkill(), tgkill():
# killsnoop.bt

CHAMPS

TEMPS
Heure de l'appel kill.
PID
ID du processus source
COMM
Nom du processus source
SIG
Numéro du signal. Voir signal(7).
TPID
ID du processus cible
RES
Résultat. 0 == succès, une valeur négative (du code d'erreur) en cas d'échec.

SURCHARGE

Ceci trace la fonction kill du noyau et affiche la sortie pour chaque événement. Comme le taux de ces événements est généralement faible (< 100/s), la surcharge est également négligeable. Si une application appelle kill()|tkill()|tgkill() à un taux très élevé pour une raison quelconque, testez et comprenez la surcharge avant utilisation.

SOURCE

Ceci provient de bpftrace.

https://github.com/bpftrace/bpftrace

Consultez également la distribution bpftrace pour un fichier compagnon _examples.txt contenant des exemples d'utilisation, de sortie et des commentaires pour cet outil.

Il s'agit d'une version bpftrace de l'outil bcc du même nom. L'outil bcc peut offrir plus d'options et de personnalisations.

https://github.com/iovisor/bcc
