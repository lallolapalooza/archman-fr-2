NOM

kubectl debug - Créer des sessions de débogage pour le dépannage des workloads et des nœuds

SYNOPSIS

kubectl debug [OPTIONS]

DESCRIPTION

Déboguer les ressources du cluster à l'aide de conteneurs de débogage interactifs.

'debug' automatise les tâches de débogage courantes pour les objets du cluster identifiés par leur ressource et leur nom. Les Pods seront utilisés par défaut si aucune ressource n'est spécifiée.

L'action effectuée par 'debug' varie en fonction de la ressource spécifiée. Les actions prises en charge incluent :

  • Workload : Créer une copie d'un pod existant avec certains attributs modifiés, par exemple en changeant le tag de l'image pour une nouvelle version.
  • Workload : Ajouter un conteneur éphémère à un pod déjà en cours d'exécution, par exemple pour ajouter des utilitaires de débogage sans redémarrer le pod.
  • Node : Créer un nouveau pod qui s'exécute dans les espaces de noms hôtes du nœud et peut accéder au système de fichiers du nœud.

Note : Lorsqu'un utilisateur non-root est configuré pour l'ensemble du Pod cible, certaines capacités accordées par le profil de débogage peuvent ne pas fonctionner.

OPTIONS

--arguments-only=false Si spécifié, tout ce qui suit -- sera passé au nouveau conteneur comme Args au lieu de Command.

--attach=false Si vrai, attendre que le conteneur démarre et s'exécute, puis s'y attacher comme si 'kubectl attach ...' avait été appelé. Par défaut faux, sauf si '-i/--stdin' est défini, auquel cas la valeur par défaut est vraie.

-c, --container="" Nom du conteneur à utiliser pour le conteneur de débogage.

--copy-to="" Créer une copie du Pod cible avec ce nom.

--custom="" Chemin vers un fichier JSON ou YAML contenant une spécification de conteneur partielle pour personnaliser les profils de débogage intégrés.

--env=[] Variables d'environnement à définir dans le conteneur.

-f, --filename=[] Identifier la ressource à déboguer

--image="" Image du conteneur à utiliser pour le conteneur de débogage.

--image-pull-policy="" La politique de récupération de l'image pour le conteneur. Si laissé vide, cette valeur ne sera pas spécifiée par le client et sera laissée au soin du serveur.

--keep-annotations=false Si vrai, conserver les annotations du pod d'origine. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--keep-init-containers=true Exécuter les conteneurs d'initialisation pour le pod. Par défaut vrai. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--keep-labels=false Si vrai, conserver les étiquettes du pod d'origine. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--keep-liveness=false Si vrai, conserver les sondes de vivacité du pod d'origine. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--keep-readiness=false Si vrai, conserver les sondes de disponibilité du pod d'origine. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--keep-startup=false Si vrai, conserver les sondes de démarrage du pod d'origine. (Ce drapeau ne fonctionne qu'avec '--copy-to')

--profile="legacy" Les options sont "legacy", "general", "baseline", "netadmin", "restricted" ou "sysadmin".

-q, --quiet=false Si vrai, supprimer les messages informatifs.

--replace=false Lorsqu'il est utilisé avec '--copy-to', supprimer le Pod d'origine.

--same-node=false Lorsqu'il est utilisé avec '--copy-to', planifier la copie du Pod cible sur le même nœud.

--set-image=[] Lorsqu'il est utilisé avec '--copy-to', une liste de paires nom=image pour modifier les images des conteneurs, similaire à la façon dont fonctionne 'kubectl set image'.

--share-processes=true Lorsqu'il est utilisé avec '--copy-to', activer le partage d'espace de noms de processus dans la copie.

-i, --stdin=false Garder stdin ouvert sur les conteneurs du pod, même si rien n'est attaché.

--target="" Lors de l'utilisation d'un conteneur éphémère, cibler les processus dans ce nom de conteneur.

-t, --tty=false Allouer un TTY pour le conteneur de débogage.

OPTIONS HERITEES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la porte de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée d'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie qu'il n'y a pas de délai d'attente pour les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Porteur pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Créer une session de débogage interactive dans le pod mypod et s'y attacher immédiatement.
  kubectl debug mypod -it --image=busybox
  # Créer une session de débogage interactive pour le pod dans le fichier pod.yaml et s'y attacher immédiatement.
  # (nécessite que la fonctionnalité EphemeralContainers soit activée dans le cluster)
  kubectl debug -f pod.yaml -it --image=busybox
  # Créer un conteneur de débogage nommé debugger en utilisant une image de débogage automatisée personnalisée.
  kubectl debug --image=myproj/debug-tools -c debugger mypod
  # Créer une copie de mypod en ajoutant un conteneur de débogage et s'y attacher
  kubectl debug mypod -it --image=busybox --copy-to=my-debugger
  # Créer une copie de mypod en changeant la commande de mycontainer
  kubectl debug mypod -it --copy-to=my-debugger --container=mycontainer -- sh
  # Créer une copie de mypod en changeant toutes les images de conteneur en busybox
  kubectl debug mypod --copy-to=my-debugger --set-image=*=busybox
  # Créer une copie de mypod en ajoutant un conteneur de débogage et en changeant les images des conteneurs
  kubectl debug mypod -it --copy-to=my-debugger --image=debian --set-image=app=app:debug,sidecar=sidecar:debug
  # Créer une session de débogage interactive sur un nœud et s'y attacher immédiatement.
  # Le conteneur s'exécutera dans les espaces de noms hôtes et le système de fichiers de l'hôte sera monté sur /host
  kubectl debug node/mynode -it --image=busybox

NAME

kubectl ― interagit avec un cluster Kubernetes.

SYNOPSIS

kubectl [OPTIONS] COMMAND [ARG...]

kubectl [OPTIONS] COMMAND --help

DESCRIPTION

L'outil de ligne de commande kubectl permet d'exécuter des commandes sur des clusters Kubernetes. Il utilise l'API Kubernetes pour interagir avec le cluster.

Utilisez kubectl pour déployer des applications, inspecter et gérer les ressources, et afficher les journaux.

OPTIONS

Les options courantes incluent :

--cache-dir string
Répertoire pour stocker le cache des informations de discovery. Par défaut, utilise le cache de répertoire de l'état du système de fichiers.
--certificate-authority string
Chemin d'accès au fichier de certificat CA pour se connecter au cluster.
--client-certificate string
Chemin d'accès au fichier de certificat client pour se connecter au cluster.
--client-key string
Chemin d'accès à la clé privée du client pour se connecter au cluster.
-c, --context string
Nom du contexte Kubernetes à utiliser.
--default-namespace string
Espace de noms par défaut à utiliser pour les commandes s'il n'est pas spécifié.
--insecure-skip-tls-verify
Si true, ne vérifie pas la validité du certificat du serveur. Ne pas utiliser pour les environnements de production.
-h, --help
Aide pour kubectl.
--kubeconfig string
Chemin d'accès au fichier kubeconfig. Par défaut, utilise le chemin défini par la variable d'environnement KUBECONFIG ou le fichier par défaut ~/.kube/config.
--match-server-version
Si true, exige que la version du serveur corresponde à la version du client. Utiliser le flag --server-version pour spécifier la version du serveur.
--namespace, -n string
Si défini, le contexte actuel est ignoré ; l'espace de noms donné est utilisé.
--request-timeout duration
Délai d'attente pour les requêtes API REST. L'unité de temps est la seconde et peut avoir des suffixes 's' (seconde), 'm' (minute), 'h' (heure).
--server-print
Si true, affiche les objets renvoyés par le serveur. Par défaut, ce comportement est activé.
--server-print-output
Si true, affiche la sortie du serveur pour les commandes qui le prennent en charge.
--server-version
Version du serveur à utiliser.
--tls-server-name string
Nom du serveur pour la vérification du certificat TLS.
--token string
Jeton d'authentification de l'utilisateur.
-v, --verbose int
Niveau de verbosité du logging, de 0 à 10.

OPTIONS INHERITED FROM PARENT COMMANDS

Les options suivantes sont héritées des commandes parentes :

--as string
Nom d'utilisateur à impersonifier.
--as-group strings
Groupes à impersonifier, le cas échéant.

Répertoire pour stocker le cache des informations de discovery.
--certificate-authority string

--client-certificate string
Chemin d'accès au fichier de certificat client pour se connecter au cluster.
--client-key string
Chemin d'accès à la clé privée du client pour se connecter au cluster.
--context string
Nom du contexte Kubernetes à utiliser.
--disable-compression
Si true, désactive la compression des requêtes HTTP.
--insecure-skip-tls-verify
Si true, ne vérifie pas la validité du certificat du serveur.
--kubeconfig string
Chemin d'accès au fichier kubeconfig.
--match-server-version
Si true, exige que la version du serveur corresponde à la version du client.
--request-timeout duration
Délai d'attente pour les requêtes API REST.
--server-print
Si true, affiche les objets renvoyés par le serveur.
--server-print-output
Si true, affiche la sortie du serveur pour les commandes qui le prennent en charge.
--server-version
Version du serveur à utiliser.
--tls-server-name string
Nom du serveur pour la vérification du certificat TLS.
--token string
Jeton d'authentification de l'utilisateur.
--user string
Nom d'utilisateur à utiliser.
--username string
Nom d'utilisateur à utiliser.

EXAMPLE

Pour afficher la liste de tous les pods dans l'espace de noms actuel :

  kubectl get pods

Pour créer une ressource à partir d'un fichier :

  kubectl create -f myapp.yaml

Pour supprimer une ressource :

  kubectl delete pod my-pod
