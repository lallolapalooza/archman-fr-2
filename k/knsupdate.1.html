NOM

knsupdate - utilitaire de mise à jour DNS dynamique

SYNTAXE

knsupdate [-v] [options] [nom_fichier]

knsupdate [-q] [options_quic] [options] [nom_fichier]

DESCRIPTION

Cet utilitaire envoie des messages de mise à jour DNS dynamique à un serveur DNS. Le contenu de la mise à jour est lu à partir d'un fichier (si le paramètre nom_fichier est fourni) ou depuis l'entrée standard.

Le format des mises à jour est textuel et composé de commandes. Chaque commande est placée sur une ligne séparée de l'entrée. Les lignes commençant par un point-virgule sont des commentaires et ne sont pas traitées.

Paramètres

nom_fichier
Chemin vers le fichier contenant les commandes knsupdate.

Options

-T, --tcp
Utilise une connexion TCP. (-v peut être utilisé pour la compatibilité avec nsupdate).
-S, --tls
Utilise une connexion TLS.
-Q, --quic
Utilise une connexion QUIC.
-p, --port nombre
Définit le port à utiliser pour les connexions au serveur (s'il n'est pas explicitement spécifié dans la mise à jour). Le port par défaut est 53 pour UDP/TCP ou 853 pour QUIC.
-r, --retry compte
Le nombre de tentatives pour les requêtes UDP. La valeur par défaut est 3.
-t, --timeout secondes
Le délai d'attente total (pour toutes les tentatives de mise à jour UDP) de la requête de mise à jour en secondes. La valeur par défaut est 12. S'il est défini à zéro, le délai d'attente est infini.
-y, --tsig [alg:]nom:clé
Utilise la clé TSIG avec le nom nom pour authentifier la requête. La partie alg spécifie l'algorithme (par défaut, hmac-sha256) et clé spécifie le secret partagé encodé en Base64.
-k, --tsigfile chemin
Utilise la clé TSIG stockée dans un fichier nom_fichier_clé pour authentifier la requête. Le fichier doit contenir la clé dans le même format que celui accepté par l'option -y.
-d, --debug
Active les messages de débogage.
-h, --help
Affiche l'aide du programme.
-V, --version
Affiche la version du programme. L'option -VV permet au programme d'afficher le résumé de la configuration à la compilation.

Options QUIC/TLS

-H, --hostname chaîne
Active la validation du nom d'hôte du serveur distant.
-P, --pin base64
Utilise le profil de confidentialité par clé épinglée hors bande (RFC 7858#section-4.2). La broche doit être un hachage SHA-256 encodé en Base64 du SubjectPublicKeyInfo X.509. Peut être spécifié plusieurs fois.
-A, --ca [chemin]
Active la validation du certificat. Les certificats de l'autorité de certification sont chargés à partir du fichier PEM spécifié (par défaut, le stockage des certificats système est utilisé si aucun argument n'est fourni). Peut être spécifié plusieurs fois.
-E, --certfile chemin
Chemin vers un fichier de certificat client.
-K, --keyfile chemin
Chemin vers un fichier de clé client.
-s, --sni chaîne
Utilise le Server Name Indication spécifié.

Commandes

server nom [port]
Spécifie un serveur récepteur du message de mise à jour dynamique. Le paramètre nom peut être un nom d'hôte ou une adresse IP. Si le port n'est pas spécifié, le port par défaut est utilisé. La valeur du port par défaut peut être contrôlée à l'aide de l'option de programme -p.
local adresse [port]
Spécifie l'adresse et le port sortants. Si aucun local n'est spécifié, l'adresse et le port sont définis automatiquement par le système. Le numéro de port par défaut est 0.
zone nom
Spécifie que toutes les mises à jour sont effectuées dans la zone nom. Le nom de zone n'a pas de valeur par défaut et doit être défini explicitement.
origin nom
Spécifie le suffixe de nom de domaine complet qui est ajouté aux propriétaires non-fqdn dans les commandes de mise à jour. La valeur par défaut est le label terminal (.).
class nom
Définit nom comme la classe par défaut pour toutes les mises à jour. Si non utilisé, la classe par défaut est IN.
ttl valeur
Définit valeur comme le TTL (en secondes) par défaut. Si non utilisé, la valeur par défaut est 3600.
key [alg:]nom clé
Spécifie la clé TSIG nommée nom pour authentifier la requête. Un algorithme alg optionnel peut être spécifié. Cette commande a le même effet que l'option de programme -y.
[prereq] nxdomain nom
Ajoute une précondition pour un enregistrement inexistant appartenant à nom.
[prereq] yxdomain nom
Ajoute une précondition pour un enregistrement existant appartenant à nom.
[prereq] nxrrset nom [classe] type
Ajoute une précondition pour un enregistrement inexistant de type appartenant à nom. La classe Internet est attendue.
[prereq] yxrrset nom [classe] type [données]
Ajoute une précondition pour un enregistrement existant de type appartenant à nom avec données optionnelles. La classe Internet est attendue.
[update] add nom [ttl] [classe] type données
Ajoute une requête pour ajouter un nouvel enregistrement de ressource dans la zone. Veuillez noter que si le nom n'est pas un nom de domaine complet, le nom d'origine actuel lui est ajouté.
[update] del[ete] nom [ttl] [classe] [type] [données]
Ajoute une requête pour supprimer tous les enregistrements de ressource (ou correspondant à la classe, type ou données) de la zone. Il y a la même exigence pour le paramètre nom que dans la commande update add. L'élément ttl est ignoré.
show
Affiche le contenu actuel du message de mise à jour.
send
Envoie le message de mise à jour actuel et nettoie la liste des mises à jour.
answer
Affiche la dernière réponse du serveur.
debug
Active le débogage. Cette commande a la même signification que l'option de programme -d.
exit
Termine le programme.

NOTES

Les options -k et -y ne peuvent pas être utilisées simultanément.

Ni les formats de fichiers de clé de tsig-keygen(8) ni de dnssec-keygen(1) ne sont pris en charge. Utilisez keymgr(8) pour construire une chaîne pour -y ou pour le fichier passé à -k.

La devinette du nom de zone/serveur n'est pas prise en charge si le nom de zone/serveur n'est pas spécifié.

Une ligne vide n'envoie pas la mise à jour.

Mode interactif

L'utilitaire fournit un mode interactif avec des fonctionnalités de base d'édition de ligne, de complétion de commande et d'historique des commandes.

Le comportement du mode interactif peut être personnalisé dans ~/.editrc. Se référer à editrc(5) pour plus de détails.

L'historique des commandes est sauvegardé dans ~/.knsupdate_history.

VALEURS DE SORTIE

Un statut de sortie de 0 signifie une opération réussie. Tout autre statut de sortie indique une erreur.

EXEMPLES

1.
Envoyer une mise à jour de la zone example.com au serveur 192.168.1.1. La mise à jour contient deux nouveaux enregistrements :
$ knsupdate
knsupdate> server 192.168.1.1
knsupdate> zone example.com.
knsupdate> origin example.com.
knsupdate> ttl 3600
knsupdate> add test1.example.com. 7200 A 192.168.2.2
knsupdate> add test2 TXT "hello"
knsupdate> show
knsupdate> send
knsupdate> answer
knsupdate> exit
