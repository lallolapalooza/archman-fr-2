NOM

kubeadm certs renew apiserver-etcd-client - Renouveler le certificat que l'apiserver utilise pour accéder à etcd

SYNTAXE

kubeadm certs renew apiserver-etcd-client [OPTIONS]

DESCRIPTION

Renouveler le certificat que l'apiserver utilise pour accéder à etcd.

Les renouvellements s'exécutent sans condition, quelle que soit la date d'expiration du certificat ; les attributs supplémentaires tels que les SAN seront basés sur le fichier/les certificats existants, il n'est pas nécessaire de les réapprovisionner.

Le renouvellement tente par défaut d'utiliser l'autorité de certification dans la PKI locale gérée par kubeadm ; en alternative, il est possible d'utiliser l'API de certificats de K8s pour le renouvellement de certificat, ou en dernier recours, de générer une demande de CSR.

Après le renouvellement, pour rendre les modifications effectives, il est nécessaire de redémarrer les composants du control-plane et éventuellement de redistribuer le certificat renouvelé si le fichier est utilisé ailleurs.

OPTIONS

--cert-dir="/etc/kubernetes/pki" Le chemin où sauvegarder les certificats

--config="" Chemin vers un fichier de configuration kubeadm.

--kubeconfig="/etc/kubernetes/admin.conf" Le fichier kubeconfig à utiliser lors de la communication avec le cluster. Si l'option n'est pas définie, un ensemble d'emplacements standard peut être recherché pour un fichier kubeconfig existant.

OPTIONS INHERITÉES DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine de l'hôte 'réel'. Cela amènera kubeadm à chroot dans le chemin fourni.

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée
