Nom

kitty - Le terminal rapide et riche en fonctionnalités

kitty [options] [programme-à-exécuter ...]

Exécute le terminal kitty. Vous pouvez également spécifier le programme à exécuter dans kitty comme des arguments normaux après les options. Par exemple : kitty --hold sh -c "echo hello, world"

Pour une documentation complète sur kitty, veuillez consulter : https://sw.kovidgoyal.net/kitty/

Options

--app-id <CLS>, --class <CLS>
Sous Wayland, définit l'ID de l'application. Sous X11, définit la partie classe de la propriété WM_CLASS de la fenêtre. Défaut : kitty
--name <NOM>, --os-window-tag <NOM>
Sous Wayland, définit la balise de fenêtre, lorsqu'elle est spécifiée. Sous X11, définit la partie nom de la propriété WM_CLASS, lorsqu'elle n'est pas définie, utilise par défaut la valeur de kitty --class.
--title <TITRE>, -T <TITRE>
Définit le titre de la fenêtre du système d'exploitation. Cela remplacera tout titre défini par le programme exécuté dans kitty, fixant ainsi de manière permanente le titre de la fenêtre du système d'exploitation. Utilisez donc cette option uniquement si vous exécutez un programme qui ne définit pas de titres.
--config <CONFIG>, -c <CONFIG>
Spécifie un chemin vers les fichiers de configuration à utiliser. Tous les fichiers de configuration sont fusionnés sur le kitty.conf intégré, remplaçant les valeurs intégrées. Cette option peut être spécifiée plusieurs fois pour lire plusieurs fichiers de configuration en séquence, qui sont ensuite fusionnés. Utilisez la valeur spéciale NONE pour ne charger aucun fichier de configuration.

Si cette option n'est pas spécifiée, les fichiers de configuration sont recherchés dans l'ordre : $XDG_CONFIG_HOME/kitty/kitty.conf, ~/.config/kitty/kitty.conf, $XDG_CONFIG_DIRS/kitty/kitty.conf. Le premier qui existe est utilisé comme fichier de configuration.

Si la variable d'environnement KITTY_CONFIG_DIRECTORY <#envvar-KITTY_CONFIG_DIRECTORY> est spécifiée, ce répertoire est toujours utilisé et la recherche ci-dessus n'a pas lieu.

Si /etc/xdg/kitty/kitty.conf existe, il est fusionné avant (c'est-à-dire avec une priorité inférieure) tous les fichiers de configuration utilisateur. Il peut être utilisé pour spécifier des valeurs par défaut à l'échelle du système pour tous les utilisateurs. Vous pouvez utiliser soit - soit /dev/stdin pour lire la configuration depuis STDIN.

--override <OVERRIDE>, -o <OVERRIDE>
Remplace des options de configuration individuelles, peut être spécifié plusieurs fois. Syntaxe : nom=valeur. Par exemple : kitty -o font_size=20
--directory <RÉPERTOIRE>, --working-directory <RÉPERTOIRE>, -d <RÉPERTOIRE>
Changer pour le répertoire spécifié lors du lancement. Défaut : .
--detach [=no]
Détacher du terminal de contrôle, le cas échéant. Sur macOS, utilisez open -a kitty.app -n à la place.
--detached-log <DETACHED_LOG>
Chemin vers un fichier journal pour stocker STDOUT/STDERR lors de l'utilisation de --detach
--session <SESSION>
Chemin vers un fichier contenant la session de démarrage (onglets, fenêtres, disposition, programmes). Utilisez - pour lire depuis STDIN. Voir Sessions <#sessions> pour les détails et un exemple. Les variables d'environnement dans le nom du fichier sont développées, les chemins relatifs sont résolus par rapport au répertoire de configuration de kitty. La valeur spéciale none signifie qu'aucune session ne sera utilisée, même si l'option startup_session <#opt-kitty.startup_session> a été spécifiée dans kitty.conf. Notez que l'utilisation de cette option signifie que les arguments de ligne de commande spécifiant un programme à exécuter sont ignorés.
--hold [=no]
Rester ouvert, à une invite de shell, après la sortie du processus enfant. Notez que cela n'affecte que la première fenêtre. Vous pouvez quitter soit en utilisant le raccourci de fermeture de fenêtre, soit en exécutant la commande exit.
--single-instance [=no], -1 [=no]
Si spécifié, une seule instance de kitty s'exécutera. Les invocations nouvelles créeront une nouvelle fenêtre de niveau supérieur dans l'instance kitty existante. Cela permet à kitty de partager un cache de sprites unique sur le GPU et réduit également le temps de démarrage. Vous pouvez également avoir des groupes séparés d'instances kitty en utilisant l'option kitty --instance-group.
--instance-group <INSTANCE_GROUP>
Utilisé en combinaison avec l'option kitty --single-instance. Toutes les invocations de kitty avec le même kitty --instance-group créeront de nouvelles fenêtres dans la première instance kitty de ce groupe.
--wait-for-single-instance-window-close [=no]
Normalement, lorsque vous utilisez kitty --single-instance, kitty ouvrira une nouvelle fenêtre dans une instance existante et se quittera immédiatement. Avec cette option, il ne se quittera pas tant que la fenêtre nouvellement ouverte n'est pas fermée. Notez que si aucune instance précédente n'est trouvée, kitty attendra de toute façon, indépendamment de cette option.
--listen-on <LISTEN_ON>
Écouter sur l'adresse du socket spécifiée pour les messages de contrôle. Par exemple, kitty --listen-on=unix:/tmp/mykitty ou kitty --listen-on=tcp:localhost:12345. Sur les systèmes Linux, vous pouvez également utiliser des sockets UNIX abstraits, non associés à un fichier, comme ceci : kitty --listen-on=unix:@mykitty. Les variables d'environnement sont développées et les chemins relatifs sont résolus par rapport au répertoire temporaire. Pour contrôler kitty, vous pouvez lui envoyer des commandes avec kitten @ en utilisant l'option kitten @ --to <#cmdoption-kitten-to> pour spécifier cette adresse. Notez que si vous exécutez kitten @ à l'intérieur d'une fenêtre kitty, il n'est pas nécessaire de spécifier l'option kitten @ --to <#cmdoption-kitten-to>, car elle sera automatiquement lue depuis l'environnement. Notez que cela sera ignoré à moins que allow_remote_control <#opt-kitty.allow_remote_control> ne soit défini sur l'une des valeurs suivantes : yes, socket ou socket-only. Cela peut également être spécifié dans kitty.conf. Pour démarrer en mode sans tête, sans fenêtre réelle, utilisez kitty --start-as=hidden.
--start-as <START_AS>
Contrôler la manière dont la fenêtre kitty initiale est créée. Défaut : normal Choix : fullscreen, hidden, maximized, minimized, normal
--position <POSITION>
La position, par exemple 10x20, à l'écran où placer la première fenêtre OS de kitty. Cela peut fonctionner ou non en fonction des politiques de l'environnement de bureau/gestionnaire de fenêtres. Cela ne fonctionne jamais sous Wayland. Voir également remember_window_position <#opt-kitty.remember_window_position> pour que kitty essaie automatiquement de restaurer la position précédente de la fenêtre.
--grab-keyboard [=no]
Capturer le clavier. Cela signifie que les raccourcis globaux définis dans le système d'exploitation seront transmis à kitty à la place. Utile si vous souhaitez créer une fenêtre modale du système d'exploitation. L'efficacité de cette option dépend du système d'exploitation/gestionnaire de fenêtres/environnement de bureau. Sous Wayland, cela ne fonctionne que si le compositeur implémente le protocole inhibit-keyboard-shortcuts https://wayland.app/protocols/keyboard-shortcuts-inhibit-unstable-v1se pas les applications à saisir le
clavier sans autorisations spé
ciales, cela ne fonctionne donc pas.

Onglets et

fenêtres

kitty est capable d'exécuter plusieurs programmes organisés en onglets et fenêtres. Le niveau supérieur d'organisation est la fenêtre OS <#term-os_window>. Chaque fenêtre OS est composée d'un ou plusieurs onglets <#term-tab>. Chaque onglet est composé d'une ou plusieurs fenêtres kitty <#term-window>. Les fenêtres kitty peuvent être disposées selon plusieurs mises en page différentes <#term-layout>, comme les fenêtres sont organisées dans un gestionnaire de fenêtres en pavage. Nom


kitty — Raccourcis clavier






Options


Les raccourcis clavier de kitty sont définis dans le fichier
    kitty.conf. Les raccourcis clavier sont mappés en utilisant la
    directive map. La syntaxe est la suivante :






map  






où est la combinaison de touches et est l'action
    à exécuter. Les modificateurs sont ctrl, shift,
    alt et super (la touche
    Windows/Cmd). Les noms des touches sont générés en ajoutant un +
    entre les modificateurs et le nom de la touche. Par exemple, ctrl+shift+t.


Voici quelques exemples :






# Ouvrir un nouvel onglet
map ctrl+shift+t new_tab
# Fermer l'onglet actuel
map ctrl+shift+w close_tab
# Redémarrer la fenêtre actuelle
map ctrl+shift+r start_kernel
# Basculer le mode plein écran
map ctrl+shift+f toggle_fullscreen










Onglets et
    fenêtres


Vous pouvez définir des raccourcis pour naviguer entre les onglets
    et les fenêtres :






# Basculer vers le prochain onglet
map ctrl+tab next_tab
# Basculer vers l'onglet précédent
map ctrl+shift+tab prev_tab
# Basculer vers l'onglet n (0-indexé)
map ctrl+f{0..9} goto_tab {0..9}
# Basculer vers le prochain onglet avec du contenu
map alt+right neighboring_tab right
map alt+left neighboring_tab left






Vous pouvez également définir des raccourcis pour naviguer entre les
    fenêtres, qui sont des vues séparées à l'intérieur d'un onglet. Sur un onglet, vous
    pouvez avoir plusieurs fenêtres disposées en grille.






map left neighboring_window left
map right neighboring_window right
map up neighboring_window up
map down neighboring_window down
map shift+left move_window right
map ctrl+down neighboring_window down
map shift+down move_window up
...






Vous pouvez également définir un raccourci pour passer à la fenêtre
    précédemment active :






map ctrl+p nth_window -1






nth_window <#action-nth_window> se concentrera sur la
    nième fenêtre pour les nombres positifs (en commençant par zéro) et sur les fenêtres
    précédemment actives pour les nombres négatifs.


Pour passer à la nième fenêtre du système d'exploitation, vous pouvez
    définir nth_os_window <#action-nth_os_window>. Seuls les nombres positifs
    sont acceptés, en commençant par un.


Vous pouvez définir des raccourcis pour détacher la fenêtre actuelle
    et la déplacer vers un autre onglet ou une autre fenêtre du système d'exploitation :






# déplace la fenêtre dans une nouvelle fenêtre du système d'exploitation
map ctrl+f2 detach_window
# déplace la fenêtre dans un nouvel onglet
map ctrl+f3 detach_window new-tab
# déplace la fenêtre dans l'onglet précédemment actif
map ctrl+f3 detach_window tab-prev
# déplace la fenêtre dans l'onglet à gauche de l'onglet actif
map ctrl+f3 detach_window tab-left
# déplace la fenêtre dans un nouvel onglet créé à gauche de l'onglet actif
map ctrl+f3 detach_window new-tab-left
# demande dans quel onglet déplacer la fenêtre
map ctrl+f4 detach_window ask






De même, vous pouvez détacher l'onglet actuel avec :






# déplace l'onglet dans une nouvelle fenêtre du système d'exploitation
map ctrl+f2 detach_tab
# demande dans quelle fenêtre du système d'exploitation déplacer l'onglet
map ctrl+f4 detach_tab ask






Enfin, vous pouvez définir un raccourci pour fermer toutes les
    fenêtres d'un onglet autre que la fenêtre active actuelle :






map f9 close_other_windows_in_tab
