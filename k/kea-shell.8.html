NOM

kea-shell - Client texte pour le processus Agent de Contrôle

SYNOPIS

kea-shell [-h] [-v] [--host] [--port] [--path] [--ca] [--cert] [--key] [--auth-user] [--auth-password] [--auth-password-file] [--timeout] [--service] [commande]

DESCRIPTION

Le programme kea-shell fournit un client REST pour les serveurs Kea kea-dhcp4, kea-dhcp6 et kea-dhcp-ddns. Auparavant, il était destiné au démon Agent de Contrôle (CA), qui est obsolète. Il prend des commandes en tant que paramètre de ligne de commande qui sont envoyées au serveur Kea avec un encapsulage JSON approprié. Des arguments optionnels peuvent être spécifiés sur l'entrée standard. La requête est envoyée via HTTP et une réponse est récupérée et affichée sur la sortie standard. L'authentification HTTP de base et HTTPS, c'est-à-dire le transport TLS, sont prises en charge.

ARGUMENTS

Les arguments sont les suivants :

-h
Affiche l'aide concernant les paramètres de la ligne de commande.
-v
Affiche la version de Kea.
--host
Spécifie l'hôte auquel se connecter. Le serveur Kea doit être en cours d'exécution sur l'hôte spécifié. S'il n'est pas spécifié, 127.0.0.1 est utilisé.
--port
Spécifie le port TCP auquel se connecter. Le serveur doit écouter sur le port spécifié. S'il n'est pas spécifié, 8000 est utilisé.
--path
Spécifie le chemin dans l'URL auquel se connecter. S'il n'est pas spécifié, un chemin vide est utilisé. Comme les serveurs Kea écoutent sur le chemin vide, ce paramètre est utile uniquement avec un proxy inverse.
--ca
Spécifie le nom du fichier ou du répertoire de l'Autorité de Certification. S'il n'est pas spécifié, HTTPS n'est pas utilisé.
--cert
Spécifie le nom du fichier du certificat de clé publique de l'entité finale de l'utilisateur. S'il est spécifié, le nom du fichier de la clé de l'utilisateur doit également être spécifié.
--key
Spécifie le nom du fichier de la clé de l'utilisateur. S'il est spécifié, le nom du fichier du certificat de l'utilisateur doit également être spécifié. Les fichiers de clé chiffrés ne sont pas pris en charge.
--auth-user
Spécifie l'identifiant utilisateur pour l'authentification HTTP de base. S'il n'est pas spécifié, ou s'il est spécifié comme chaîne vide, l'authentification n'est pas utilisée.
--auth-password
Spécifie le mot de passe pour l'authentification HTTP de base. S'il n'est pas spécifié mais que l'identifiant utilisateur l'est, un mot de passe vide est utilisé. S'il est utilisé conjointement avec --auth-password-file, il est ignoré.
--auth-password-file
Spécifie un fichier texte dont la première ligne contient le mot de passe à utiliser pour l'authentification HTTP de base. Ce drapeau a priorité sur le drapeau --auth-password.
--timeout
Spécifie le délai d'attente de la connexion, en secondes. La valeur par défaut est 10.
--service
(Obsolète) Les serveurs Kea kea-dhcp4, kea-dhcp6 et kea-dhcp-ddns ignorent cet argument. Il était destiné à la communication avec le démon obsolète Agent de Contrôle. S'il est utilisé avec la version Kea < 2.7.2 : spécifie le service qui est la cible d'une commande. S'il n'est pas spécifié, l'Agent de Contrôle lui-même est ciblé. Peut être utilisé plusieurs fois pour spécifier plusieurs cibles.
commande
Spécifie la commande à envoyer au serveur. S'il n'est pas spécifié, list-commands est utilisé.

DOCUMENTATION

Kea est livré avec un manuel de référence complet pour l'administrateur Kea qui couvre tous les aspects de l'exécution du logiciel Kea - compilation, installation, configuration, exemples de configuration, et bien plus encore. Kea propose également un manuel des messages Kea, qui liste tous les messages possibles que Kea peut afficher avec une brève description pour chacun d'eux. Ces deux documents sont disponibles dans différents formats (.txt, .html, .pdf) avec la distribution Kea. La documentation Kea est disponible sur https://kea.readthedocs.io.

Le code source de Kea est documenté dans le Guide du développeur Kea, disponible sur https://reports.kea.isc.org/dev_guide/.

Le site web du projet Kea est disponible sur https://kea.isc.org.

LISTES DE DIFFUSION ET SUPPORT

Il existe deux listes de diffusion publiques disponibles pour le projet Kea. kea-users (kea-users at lists.isc.org) est destinée aux utilisateurs de Kea, tandis que kea-dev (kea-dev at lists.isc.org) est destinée aux développeurs de Kea, aux contributeurs potentiels et à d'autres utilisateurs avancés. Les deux listes sont disponibles sur https://lists.isc.org. La communauté fournit un support au mieux de ses capacités sur ces deux listes.

ISC fournit un support professionnel pour les services Kea. Voir https://www.isc.org/kea/ pour plus de détails.

HISTORIQUE

Le programme kea-shell a été codé pour la première fois en mars 2017 par Tomek Mrugalski.
