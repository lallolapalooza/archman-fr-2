KEYCTL_PKEY_SIGN(3) Signatures de clés publiques Linux KEYCTL_PKEY_SIGN(3)

NOM

keyctl_pkey_sign, keyctl_pkey_verify - Générer et vérifier des signatures

SYNOPSIS

#include <keyutils.h>

long keyctl_pkey_sign(key_serial_t key, const char *info,
                      const void *data, size_t data_len,
                      void *sig, size_t sig_len);

long keyctl_pkey_verify(key_serial_t key, const char *info,
                        const void *data, size_t data_len,
                        const void *sig, size_t sig_len);

DESCRIPTION

keyctl_pkey_sign() demande au noyau d'utiliser les données cryptographiques attachées à une clé pour générer une signature détachée pour un bloc de données. Notez que cela peut impliquer d'appeler le matériel cryptographique.

keyctl_pkey_verify() demande au noyau d'utiliser la clé pour générer une vérification de la signature par rapport au même bloc de données. Cela peut également impliquer d'appeler le matériel cryptographique.

L'appelant doit avoir la permission search sur une clé pour pouvoir effectuer l'une ou l'autre opération.

Lors de l'appel de la fonction, key indique la clé qui fournira le matériel cryptographique et info pointe vers une chaîne de paramètres de type "key[=value]", séparés par des espaces ou des tabulations, qui indiquent des éléments tels que les formes d'encodage et les mots de passe pour déverrouiller la clé ; voir asymmetric-key(7) pour plus d'informations.

data et datalen indiquent l'adresse et la taille du tampon de données à signer, et sig et siglen indiquent l'adresse et la taille du tampon de signature. La fonction de signature extrait les données du tampon de données, génère une signature à partir de celles-ci et place le résultat dans le tampon de signature. La fonction de vérification extrait également des données du tampon de données, puis déchiffre la signature et compare le résultat.

Notez que le tampon de données est strictement limité en capacité, incapable généralement de contenir plus de bits que la taille de la clé. L'appelant est censé avoir prétraité les données réelles et passera donc la sortie du hachage à cette fonction. Le nom du hachage utilisé doit être passé dans le cadre de la chaîne info sous la forme hash=<nom> pour être utilisé dans la construction des métadonnées de signature.

keyctl_pkey_query(2) peut être appelé pour savoir quelle taille doivent avoir les tampons et quelle est la taille maximale des données pour un encodage de signature spécifique.

Notez que toutes les clés de type asymétrique ne supporteront pas ces opérations ; de plus, les opérations disponibles peuvent dépendre des composants du matériel de clé disponibles : typiquement, le chiffrement ne nécessite que la clé publique, mais le déchiffrement nécessite également la clé privée. Les opérations prises en charge sur une clé particulière peuvent également être déterminées à l'aide de la fonction de requête.

VALEUR DE RETOUR

En cas de succès, keyctl_pkey_sign() retourne la quantité de données écrites dans le tampon de signature. keyctl_pkey_verify() retournera 0 dans ce cas car elle n'écrit pas dans l'espace utilisateur.

En cas d'erreur, la valeur -1 sera retournée et errno aura été défini à une erreur appropriée.

ERREURS

ENOKEY
La clé spécifiée est invalide.
EKEYEXPIRED
La clé spécifiée a expiré.
EKEYREVOKED
La clé spécifiée a été révoquée.
EACCES
La clé existe, mais n'est pas consultable par le processus appelant.
EINVAL, EBADMSG, EOVERFLOW
Une partie du matériel de clé ou des données de signature est corrompue.
EKEYREJECTED
La vérification de la signature a échoué.
ENOPKG
Une installation nécessaire pour compléter l'opération demandée n'est pas disponible. Il s'agit très probablement d'un algorithme de hachage ou de chiffrement demandé ou requis.
EFAULT
Mauvaise adresse.

LIAISON

Ceci est une fonction de bibliothèque qui peut être trouvée dans libkeyutils. Lors de la liaison, -lkeyutils doit être spécifié au lieur.
