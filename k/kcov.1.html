KCOV(1) Manuel des commandes générales KCOV(1)

NOM

kcov - Analyse de couverture de code pour programmes compilés et scripts Python

SYNTAXE

kcov [options] répertoire-sortie fichier-entrée [args-pour-exécutable...]

kcov --merge répertoire-sortie <chemin-vers-couverture> [chemin-vers-plus-de-couverture...]

DESCRIPTION

Cette page de manuel documente brièvement la commande kcov. kcov est un testeur de couverture de code pour les binaires ELF, les scripts Python et les scripts shell. Il permet de collecter des informations de couverture de code à partir d'exécutables sans directives de compilateur spéciales, et produit en continu des sorties pour les applications de longue durée.

Voir la page GitHub, https://github.com/SimonKagstrom/kcov, pour plus de documentation.

OPTIONS

-p, --pid=PID
Tracer le PID au lieu d'exécuter l'exécutable (le passage de l'exécutable est facultatif dans ce cas). Dans ce mode, la collecte de couverture pour les bibliothèques partagées ne fonctionnera pas.
-l, --limits=bas,haut
Définir les limites pour la couverture basse/haute (par défaut: 25,75).
--include-path=P1[,P2...]
Liste séparée par des virgules des chemins à inclure dans le rapport.
--exclude-path=P1[,P2...]
Liste séparée par des virgules des chemins à exclure du rapport.
--include-pattern=P1[,P2...]
Liste séparée par des virgules des motifs de chemins à inclure dans le rapport.
--exclude-pattern=P1[,P2...]
Liste séparée par des virgules des motifs de chemins à exclure du rapport.
--exclude-line=P1[,P2...]
Liste séparée par des virgules des motifs de lignes à exclure (marquer comme ne faisant pas partie du code)
--exclude-region=DEBUT:FIN[,DEBUT1:FIN1...]
Liste séparée par des virgules des régions de motifs de lignes à exclure (marquer comme ne faisant pas partie du code). La région commence par DEBUT et se termine par FIN.
--clean
Ne pas accumuler les données de plusieurs exécutions.
--collect-only
Collecter uniquement les données de couverture, ne pas générer de sortie HTML/Cobertura.
--dump-summary
Sauvegarder un bref résumé de la couverture sur stdout après l'exécution
--report-only
Générer uniquement le rapport HTML/Cobertura, ne pas collecter les données.
--merge
Fusionner le résultat de plusieurs exécutions de kcov. Au lieu d'un programme à tester, les chemins de sortie des exécutions précédentes doivent être donnés sur la ligne de commande, ou via un wildcard (*)
--coveralls-id=id
Téléverser les données sur coveralls.io en utilisant le jeton secret du dépôt ou l'ID du travail du service Travis CI id. L'ID est pris comme un jeton de dépôt s'il est plus long ou égal à 32 caractères.
--strip-path=chemin
S'il n'est pas défini, le chemin commun maximal sera supprimé.

OPTIONS RARES

--path-strip-level=N
Nombre de niveaux de chemin à afficher pour les chemins communs (par défaut: 2).
--skip-solibs
Sauter la collecte de couverture pour les bibliothèques partagées (améliore les performances)
--verify
Vérifier que les points d'arrêt sont configurés aux limites d'instructions. Cela ralentira considérablement l'exécution, mais peut détecter des problèmes où le compilateur génère des données DWARF incorrectes.
--exit-first-process
sortir lorsque le premier processus se termine, c'est-à-dire respecter le comportement des démons. Le comportement par défaut est de revenir à la console lorsque le dernier processus se termine.
--cobertura-only
Générer uniquement la sortie cobertura, sous forme de cov.xml, dans le répertoire de sortie. L'utilisation prévue est par exemple pour les gouttières de couverture de vscode, où le répertoire de sortie peut ensuite être pointé vers un endroit du répertoire du projet pour obtenir une couverture avec peu de ramifications.
--python-parser=ANALYSEUR
Définir l'analyseur Python à utiliser pour les programmes Python (par défaut est python). Peut être utilisé pour exécuter avec Python 3 sur des systèmes où Python 2 est le défaut.
--bash-parser=ANALYSEUR
Définir l'analyseur bash à utiliser pour les scripts shell (par défaut est /bin/bash).
--bash-method=METHODE
Utiliser la méthode de collecte METHODE pour les scripts bash. La méthode peut être soit PS4, pour l'utilisation de la variable d'environnement PS4, soit DEBUG pour l'utilisation du piège DEBUG.
--bash-handle-sh-invocation
Gérer les invocations de scripts /bin/sh en utilisant une bibliothèque LD_PRELOADée qui remplace execve (c'est-à-dire /bin/sh est exécuté comme /bin/bash). Ne fonctionne pas bien sur certains systèmes, donc par défaut, cela n'est pas utilisé.
--bash-dont-parse-binary-dir
Kcov analyse le répertoire du binaire pour d'autres scripts et les ajoute au rapport. Si vous ne voulez pas de ce comportement, cette option le désactive.
--bash-parse-files-in-dir=P1[,P2...]
Analyser les répertoires pour les scripts bash.
--bash-tracefd-closeexec
Forcer les enfants à ne pas être tracés en configurant le descripteur de trace comme non clonable avec LD_PRELOAD. Buggy sur certains systèmes.
--replace-src-path=P1:P2
Remplacer le chemin du fichier source P1 par P2, s'il est trouvé.
--system-record
Effectuer une instrumentation complète du système sur un sysroot, en générant des binaires modifiés qui collectent des données de couverture. Voir doc/full-system-instrumentation.md pour plus d'informations sur l'instrumentation complète du système.
--system-report
Produire une sortie de couverture pour une exécution de couverture complète du système.
--debug=niveau
Définir le niveau de débogage, 0...31 (en tant que masque). Par défaut, 0 pour aucune sortie de débogage.
--output-interval=MS
Définir l'intervalle d'écriture de la sortie en millisecondes. Par défaut, 5000.
--configure=CLÉ=VALEUR
Configurer des paires clé/valeur d'options internes. Voir --help --uncommon-options pour les options de configuration possibles.
--patchelf=CMD
Pour le mode système, définir la commande patchelf (patchelf par défaut).

EXEMPLES

Vérifier la couverture pour ./frodo et générer une sortie HTML dans /tmp/kcov et une sortie cobertura dans /tmp/kcov/frodo/cobertura.xml

kcov /tmp/kcov ./frodo

Vérifier la couverture pour ./frodo mais n'inclure que les fichiers source dont le nom contient la chaîne src/frodo

kcov --include-pattern=src/frodo /tmp/kcov ./frodo

Idem que ci-dessus mais séparer la collecte et le rapport (peut-être sur deux ordinateurs différents)

kcov --collect-only /tmp/kcov ./frodo

kcov --report-only --include-pattern=src/frodo /tmp/kcov ./frodo

SORTIE HTML

La sortie HTML montre les lignes de code source exécutées et non exécutées. Certaines lignes peuvent correspondre à plusieurs points d'instrumentation, par exemple pour les fonctions inline (où chaque mise en ligne de celles-ci générera une instrumentation distincte.

on point). Ceci est indiqué dans la colonne de gauche comme 1/3, par exemple, ce qui signifie que l'un des trois points d'instrumentation a été exécuté.

Un lien de sortie spécial est [merged], qui affiche l'union de tous les programmes couverts. Ceci peut être utile, par exemple, lorsque vous avez des tests unitaires dans plusieurs binaires qui partagent un sous-ensemble de fichiers source.

SORTIE COBERTURA

Kcov génère également des données au format XML Cobertura, ce qui permet d'intégrer la sortie de kcov dans Jenkins (voir https://cobertura.github.io/cobertura/ et https://www.jenkins.io/).

La sortie Cobertura est placée dans un fichier nommé out-path/exec-filename/cobertura.xml.

SORTIE JSON

Kcov génère un fichier JSON très générique qui inclut le pourcentage global de couverture pour une seule commande et le nombre de lignes instrumentées et couvertes. Il inclut également un résumé de chaque fichier source avec un pourcentage et des décomptes de lignes. Ceci permet une intégration facile avec GitlabCI (voir https://docs.gitlab.com/ce/user/project/pipelines/settings.html).

La sortie JSON est placée dans un fichier nommé out-path/exec-filename/coverage.json.
