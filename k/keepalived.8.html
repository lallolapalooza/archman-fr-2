NOM

keepalived - service d'équilibrage de charge et de haute disponibilité

SYNTAXE

keepalived [-f|--use-file=FICHIER] [-P|--vrrp] [-C|--check] [-B|--no_bfd] [--all] [-l|--log-console] [-D|--log-detail] [-S|--log-facility={0-7|local{0-7}|user|daemon}] [-g|--log-file=FICHIER] [--flush-log-file] [-G|--no-syslog] [-X|--release-vips] [-V|--dont-release-vrrp] [-I|--dont-release-ipvs] [-R|--dont-respawn] [-n|--dont-fork] [-d|--dump-conf] [-p|--pid=FICHIER] [-r|--vrrp_pid=FICHIER] [-T|--genhash] [-c|--checkers_pid=FICHIER] [-a|--address-monitoring] [-b|--bfd_pid=FICHIER] [-s|--namespace=NOM] [-e|--all-config] [-i|--config-id id] [-x|--snmp] [-A|--snmp-agent-socket=FICHIER] [-u|--umask=NOMBRE] [-m|--core-dump] [-M|--core-dump-pattern[=PATTERN]] [--signum=SIGFUNC] [-t|--config-test[=FICHIER]] [--perf[={all|run|end}]] [--debug[=debug-options]] [--no-mem-check] [--ignore-sigint] [-v|--version] [-h|--help]

DESCRIPTION

Keepalived fournit des fonctionnalités simples et robustes pour l'équilibrage de charge et la haute disponibilité. Le cadre d'équilibrage de charge repose sur le module noyau Linux Virtual Server (IPVS), bien connu et largement utilisé, qui fournit un équilibrage de charge de niveau 4. Keepalived implémente un ensemble de vérificateurs pour maintenir et gérer dynamiquement et de manière adaptative un pool de serveurs équilibrés en fonction de leur état de santé. Keepalived implémente également les protocoles VRRPv2 et VRRPv3 pour atteindre la haute disponibilité avec basculement du directeur.

OPTIONS

-f, --use-file=FICHIER
Utilise le fichier de configuration spécifié. Le fichier de configuration par défaut est "/etc/keepalived/keepalived.conf".
-P, --vrrp
Exécute uniquement le sous-système VRRP. Ceci est utile pour les configurations qui n'utilisent pas l'équilibreur de charge IPVS.
-C, --check
Exécute uniquement le sous-système de vérification de l'état (healthcheck). Ceci est utile pour les configurations qui utilisent l'équilibreur de charge IPVS avec un seul directeur sans basculement.
-B, --no_bfd
Ne pas exécuter le sous-système BFD.
--all
Exécute tous les sous-systèmes, même s'ils n'ont pas de configuration.
-l, --log-console
Enregistre les messages dans la console locale. Le comportement par défaut est d'enregistrer les messages dans syslog.
-D, --log-detail
Messages de journalisation détaillés.
-S, --log-facility={0-7|local{0-7}|user|daemon}
Définit la facilité syslog sur LOG_LOCAL[0-7], LOG_USER ou LOG_DAEMON. La facilité syslog par défaut est LOG_DAEMON.
-g, --log-file=FICHIER
Écrit les entrées de journal dans FICHIER. Le texte _vrrp, _healthcheckers, et _bfd sera inséré avant le dernier '.' dans FICHIER pour la sortie des journaux de ces processus.
--flush-log-file
Si l'option -g est utilisée, le flux du fichier journal sera vidé après chaque écriture.
-G, --no-syslog
Ne pas écrire les entrées de journal dans syslog. Ceci peut être utile si le taux d'écriture des entrées de journal est suffisamment élevé pour que syslog limite le débit, et que l'option -g est utilisée à la place.
-X, --release-vips
Supprime les VIP lors de la transition de signal.
-V, --dont-release-vrrp
Ne pas supprimer les VIP et VROUTEs VRRP à l'arrêt du démon. Le comportement par défaut est de supprimer toutes les VIP et VROUTEs à la sortie de keepalived.
-I, --dont-release-ipvs
Ne pas supprimer la topologie IPVS à l'arrêt du démon. Le comportement par défaut est de supprimer toutes les entrées de la table des serveurs virtuels IPVS à la sortie de keepalived.
-R, --dont-respawn
Ne pas relancer les processus fils. Le comportement par défaut est de redémarrer les processus VRRP et checker si l'un d'eux se termine.
-n, --dont-fork
Ne pas forker le processus démon. Cette option fera fonctionner keepalived au premier plan.
-d, --dump-conf
Affiche les données de configuration.
-p, --pid=FICHIER
Utilise le fichier pid spécifié pour le processus parent keepalived. Le fichier pid par défaut pour keepalived est "/run/keepalived.pid", sauf si un espace de noms réseau est utilisé. Voir ESPACES DE NOMS ci-dessous pour plus de détails.
-r, --vrrp_pid=FICHIER
Utilise le fichier pid spécifié pour le processus fils VRRP. Le fichier pid par défaut pour le processus fils VRRP est "/run/keepalived_vrrp.pid", sauf si un espace de noms réseau est utilisé.
-T, --genhash
Passe en mode utilitaire genhash. Les versions précédentes de keepalived étaient livrées avec un utilitaire genhash dédié. genhash fait maintenant partie du code principal. Nous maintenons la compatibilité avec l'option de ligne de commande de l'ancien utilitaire genhash. Pour plus d'informations, veuillez vous référer à la page de manuel de genhash(1).
-c, --checkers_pid=FICHIER
Utilise le fichier pid spécifié pour le processus fils checkers. Le fichier pid par défaut pour le processus fils checker est "/run/keepalived_checkers.pid" sauf si un espace de noms réseau est utilisé.
-a, --address-monitoring
Journalise toutes les additions/suppressions d'adresses signalées par netlink.
-b, --bfd_pid=FICHIER
Utilise le fichier pid spécifié pour le processus fils BFD. Le fichier pid par défaut pour le processus fils BFD est "/run/keepalived_bfd.pid" sauf si un espace de noms réseau est utilisé.
-s, --namespace=NOM
Exécute keepalived dans l'espace de noms réseau NOM. Voir ESPACES DE NOMS ci-dessous pour plus de détails.
-e, --all-config
Ne pas charger si un fichier de configuration est manquant ou ne peut être lu.
-i, --config-id ID
Utilise l'identifiant de configuration ID, pour la configuration conditionnelle (par défaut, le nom d'hôte sans le nom de domaine).
-x, --snmp
Active le sous-système SNMP.
-A, --snmp-agent-socket=FICHIER
Utilise le socket spécifié pour la connexion à l'agent maître SNMP.
-u, --umask=NOMBRE
Le umask spécifié de la manière numérique habituelle - voir man umask(2)
-m, --core-dump
Ignore les limites dures et douces de RLIMIT_CORE pour permettre à keepalived de produire un vidage de cœur en cas de segment fault ou d'autre échec. Ceci est surtout utile si keepalived a été compilé avec 'make debug'. Les vidages de cœur seront créés dans /, sauf si keepalived est exécuté avec l'option --dont-fork, auquel cas ils seront créés dans le répertoire à partir duquel keepalived a été exécuté, ou ils seront créés dans le répertoire d'un fichier de configuration si l'échec se produit lors de la lecture du fichier.
-M, --core-dump-pattern[=PATTERN]
Définit l'option --core-dump, et met également à jour /proc/sys/kernel/core_pattern vers le modèle spécifié, ou 'core' si aucun n'est spécifié. Pourvu que le processus parent ne se termine pas anormalement, il restaurera /proc/sys/kernel/core_pattern à sa valeur d'origine à la sortie.

Note: Ceci affectera également tout autre processus produisant un vidage de cœur pendant que keepalived est en cours d'exécution.

--signum=PATTERN
Retourne le numéro de signal à utiliser pour STOP, RELOAD, DATA, STATS,

STATS_CLEAR, JSON et TDATA. Par exemple, pour arrêter keepalived en cours d'exécution, exécutez : 
kill -s $(keepalived --signum=STOP) $(cat /run/keepalived.pid)
-t, --config-test[=FICHIER]
Keepalived vérifiera le fichier de configuration et quittera avec un code de sortie non nul en cas d'erreurs de configuration, sinon il quittera avec le code de sortie 0 (voir Code de sortie ci-dessous pour plus de détails).

Plutôt que d'écrire dans syslog, il écrira des messages de diagnostic sur stderr, sauf si un fichier est spécifié, auquel cas il écrira dans ce fichier.

--perf[={all|run|end}]
Enregistre les données de performance pour le processus vrrp. Les données seront écrites dans /perf_vrrp.data. Les données enregistrées sont destinées à être utilisées avec l'outil perf.
--no-mem-check
Désactive les vérifications de mémoire telles que malloc() si elles ont été compilées dans keepalived.
--ignore-sigint
Désactive la gestion de SIGINT (qui arrête par défaut keepalived). Ceci est nécessaire pour exécuter keepalived sous GDB.
--debug[=options-debug]]
Active les options de débogage si elles ont été compilées dans keepalived. options-debug est composé d'une séquence de chaînes de caractères de la forme Ulll.
La lettre majuscule spécifie l'option de débogage, et les lettres minuscules spécifient pour quels processus l'option doit être activée.
Si une option de débogage n'est suivie d'aucune lettre minuscule, l'option de débogage est activée pour tous les processus.
Les caractères permettant d'identifier les processus sont :
Chr Processus
p Processus parent
b Processus BFD
c Processus de vérification
v Processus VRRP

Les caractères utilisés pour identifier les options de débogage sont :

Chr Option de débogage
D Dump du thread epoll
E Débogage epoll
F Débogage des descripteurs de fichiers VRRP
N Timers Netlink
P Timestamp réseau
X Timers Regex
M Débogage des alertes par e-mail
T Débogage des timers
S Débogage TSM
R Débogage Regex
B Débogage de la connexion SMTP
U Diagnostics de checksum
O Débogage du processus de suivi
A Débogage du processus de suivi avec détails supplémentaires
C Débogage du parser (configuration)
H Débogage du checker
Z Débogage des erreurs d'allocation/libération de mémoire
G Débogage de recvmsg() VRRP
J Journalisation des données reçues par recvmsg() VRRP
V Débogage de scripts
K Dump des mots-clés

Exemple : --debug=DvEcvNR

-v, --version
Affiche la version et quitte.
-h, --help
Affiche ce message d'aide et quitte.

Code de sortie :

0
si OK
1
si impossible d'allouer de la mémoire
2
si impossible d'initialiser les sous-systèmes
3
si exécuté avec --config-test et la configuration ne peut pas être exécutée
4
si exécuté avec --config-test et il y a des erreurs de configuration mais keepalived fonctionnera après modification de la configuration
5
si exécuté avec --config-test et la sécurité des scripts n'a pas été activée mais des scripts sont configurés.

ESPACES DE NOMS

keepalived peut être exécuté dans un espace de noms réseau (voir keepalived.conf(5) pour les détails de configuration). Lorsqu'il est exécuté dans un espace de noms réseau, un espace de noms de montage local est également créé, et /run/keepalived/keepalived_NamespaceName est monté sur /run/keepalived. Par défaut, les fichiers pid avec les noms par défaut habituels sont alors créés dans /run/keepalived du point de vue d'un processus dans l'espace de noms de montage, et ils seront visibles dans /run/keepalived/keepalived_NamespaceName pour un processus s'exécutant dans l'espace de noms de montage par défaut.

SIGNALS

keepalived réagit à un ensemble de signaux. Vous pouvez envoyer un signal au processus parent keepalived en utilisant la commande suivante :

kill -SIGNAL $(cat /run/keepalived.pid)

ou mieux :

kill -s $(keepalived --signum=SIGFUNC) $(cat /run/keepalived.pid)

Notez que si la première option est utilisée, -SIGNAL doit être remplacé par le signal réel que vous essayez d'envoyer, par exemple HUP. Cela devient alors :

kill -HUP $(cat /run/keepalived.pid)

Les signaux autres que ceux pour STOP, RELOAD, DATA et STATS peuvent changer en fonction du noyau, ainsi que de la fonctionnalité incluse dans la version de keepalived, en fonction des options de compilation utilisées.

HUP ou SIGFUNC=RELOAD
Cela provoque la fermeture par keepalived de toutes les interfaces, le rechargement de sa configuration et le démarrage avec la nouvelle configuration.
Remarque : Si une virtual_ipaddress, virtual_route ou virtual_rule est déplacée d'une instance VRRP à une autre, deux rechargements seront nécessaires, le premier pour supprimer l'adresse ip virtuelle/route/règle, et le second rechargement pour l'ajouter à l'instance VRRP sur laquelle elle est maintenant configurée. Ne pas le faire peut entraîner la non-configuration de l'adresse ip/route/règle sur la nouvelle instance si les anciennes et nouvelles instances sont en état master. Cela fonctionnera généralement avec un seul rechargement, cependant, si l'une des instances VRRP n'est pas en état MASTER ou si l'instance VRRP à laquelle l'adresse ip/route/règle est ajoutée est plus loin dans le fichier de configuration d'origine que l'instance dont elle est supprimée. Remarque2 : Si une configuration s'exécute avec SNMP activé, puis qu'un rechargement est effectué avec une configuration qui ne permet pas SNMP, il n'est pas possible de réactiver SNMP par la suite. La raison n'est actuellement pas comprise.
TERM, INT ou SIGFUNC=STOP
keepalived s'arrêtera.
USR1 ou SIGFUNC=DATA
Écrit les données de configuration dans /tmp/keepalived.data ou le fichier configuré par state_dump_file
USR2 ou SIGFUNC=STATS
Écrit les informations de statistiques dans /tmp/keepalived.stats ou le fichier configuré par stats_dump_file
SIGFUNC=STATS_CLEAR
Écrit les informations de statistiques dans /tmp/keepalived.stats ou le fichier configuré par stats_dump_file et efface les compteurs de statistiques
SIGFUNC=JSON
Écrit les données de configuration au format JSON dans /tmp/keepalived.json ou le fichier configuré par json_dump_file
SIGFUNC=TDATA
Cela provoque l'écriture par keepalived de l'état actuel de ses threads internes dans le journal.

UTILISER KEEPALIVED AVEC FIREWALLD

Si vous utilisez un pare-feu (voir firewalld(8)) vous devez autoriser le trafic du protocole VRRP à travers le pare-feu. Par exemple, si cette instance de keepalived(8) a un nœud pair sur l'adresse IPv4 192.168.0.1 :

# firewall-cmd \
    --add-rich-rule="rule family='ipv4' \
                     source address='192.168.0.1' \
                     protocol value='vrrp' accept" --permanent
# firewall-cmd --reload
