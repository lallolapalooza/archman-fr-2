NOM

kubeadm init phase control-plane scheduler - Génère le manifeste du Pod statique kube-scheduler

SYNOPIS

kubeadm init phase control-plane scheduler [OPTIONS]

DESCRIPTION

Génère le manifeste du Pod statique kube-scheduler

OPTIONS

--cert-dir="/etc/kubernetes/pki" Le chemin où sauvegarder et stocker les certificats.

--config="" Chemin vers un fichier de configuration kubeadm.

--dry-run=false Ne pas appliquer de changements ; simplement afficher ce qui serait fait.

--image-repository="registry.k8s.io" Choisir un registre de conteneurs pour tirer les images du plan de contrôle.

--kubernetes-version="stable-1" Choisir une version spécifique de Kubernetes pour le plan de contrôle.

--patches="" Chemin vers un répertoire contenant des fichiers nommés "target[suffix][+patchtype].extension". Par exemple, "kube-apiserver0+merge.yaml" ou simplement "etcd.json". "target" peut être l'un de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" peut être l'un de "strategic", "merge" ou "json" et ils correspondent aux formats de patch supportés par kubectl. Le "patchtype" par défaut est "strategic". "extension" doit être soit "json" soit "yaml". "suffix" est une chaîne optionnelle qui peut être utilisée pour déterminer quels patchs sont appliqués en premier par ordre alphabétique.

--scheduler-extra-args= Un ensemble d'arguments supplémentaires à passer au Scheduler ou pour outrepasser ceux par défaut sous la forme =

OPTIONS INHERITÉE DES COMMANDES PARENTES

--rootfs="" Le chemin vers le système de fichiers racine 'réel' de l'hôte. Cela forcera kubeadm à faire un chroot dans le chemin fourni.

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée
