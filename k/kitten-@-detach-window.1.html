Nom

kitten-@-detach-window - Détacher les fenêtres spécifiées et les placer dans un onglet différent/nouveau

Utilisation

kitten @ detach-window

Description

Détache les fenêtres spécifiées et les déplace soit dans un nouvel onglet, soit dans une nouvelle fenêtre du système d'exploitation, soit les ajoute à l'onglet spécifié. Utilisez la valeur spéciale new pour --target-tab pour les déplacer vers un nouvel onglet. Si aucun onglet cible n'est spécifié, les fenêtres sont déplacées vers une nouvelle fenêtre du système d'exploitation.

Options

--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression rationnelle, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all fait correspondre toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression rationnelle. Les valeurs négatives pour id font correspondre à partir du numéro d'id le plus élevé vers le bas ; en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet courant, en commençant à zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même que l'ordre dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'identifiant de fenêtre de la fenêtre courante est disponible en tant que la variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, zéro étant la fenêtre actuellement active, un étant la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session fait correspondre les fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var fait correspondre les variables utilisateur définies sur la fenêtre. Vous pouvez spécifier un nom ou un nom et une valeur comme avec le champ env.

Le champ state fait correspondre l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est faite correspondre. La valeur focused_os_window fait correspondre toutes les fenêtres de la fenêtre du système d'exploitation actuellement focalisée. La valeur self fait correspondre la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent fait correspondre la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est un superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste de fenêtres.

--target-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression rationnelle, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all fait correspondre tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l' expression est interprétée comme un nombre, et non comme une expression rationnelle. Les valeurs négatives pour id/window_id font correspondre à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est l'onglet/fenêtre créé le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le n-ième onglet dans la fenêtre du système d'exploitation actuellement active. Le numéro recent fait correspondre les onglets récemment actifs dans la fenêtre du système d'exploitation actuellement active, zéro étant l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session fait correspondre les onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont faits correspondre. De même, var fait correspondre les onglets contenant n'importe quelle fenêtre avec la variable utilisateur spécifiée.

Le champ state fait correspondre l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre du système d'exploitation parent. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont délivrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est fait correspondre. La valeur focused_os_window fait correspondre tous les onglets de la fenêtre du système d'exploitation actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste de onglets. Utilisez la valeur spéciale new pour vous déplacer vers un nouvel onglet.

--self [=no]
Détache la fenêtre dans laquelle cette commande est exécutée, plutôt que la fenêtre active.
--stay-in-tab [=no]
Garde le focus sur une fenêtre dans l'onglet actuellement focalisé après le déplacement des fenêtres spécifiées.
--help, -h [=no]
Affiche l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance de kitty à contrôler. Correspond à l'adresse donnée à l'instance de kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la connexion à kitty. Cela fera demander à kitty la permission à l'utilisateur d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie la présence du fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement simplement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer kitty à toujours ou jamais utiliser le mot de passe fourni. Si défini à always et si aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choi kitten @ detach-window(1)

Name

kitten @ detach-window - détacher une fenêtre du bureau kitty

Usage

kitten @ detach-window [-w WID]

Description

Détache la fenêtre actuelle du bureau kitty. La fenêtre détachée peut être déplacée, redimensionnée et gérée indépendamment.

Options

-w WID, --window WID
Identifiant de la fenêtre à détacher. Si omis, la fenêtre actuelle est utilisée.

Options globales

--config PATH
Spécifie le fichier de configuration à utiliser.
--debug
Active la sortie de débogage.
--hold
Ne pas quitter après l'exécution de la commande.
--input-source-encoding ENCODING
Spécifie le codage des entrées stdin.
--no-response
Ne pas répondre aux requêtes de l'OS.
--session SESSION
Utilise la session spécifiée.
--single-instance
S'assure que seule une seule instance de kitty est en cours d'exécution.
--title TITLE
Définit le titre de la fenêtre.
--version
Affiche la version et quitte.

Exemples

Détacher la fenêtre actuelle :

kitten @ detach-window

Détacher la fenêtre avec l'ID 1234 :

kitten @ detach-window -w 1234

Voir aussi

kitten(1), kitten @ new-window(1), kitten @ split-window(1)

Compatibilité

Le comportement de cette commande peut varier en fonction des options de configuration dans kitty.conf(5), notamment les options focus_follows_mouse et mouse_bindings.

L'option cursor_blinking_global_option dans kitty.conf(5) contrôle si le curseur clignote. Les valeurs possibles sont : if-available, always, never.
