Nom

kitten-@-set-tab-color - Changer la couleur des onglets spécifiés dans la barre d'onglets

Usage

kitten @ set-tab-color COULEURS

Description

Changer la couleur des onglets spécifiés dans la barre d'onglets

Les couleurs de premier plan et d'arrière-plan, actives et inactives, peuvent être remplacées en utilisant cette commande. La syntaxe pour spécifier les couleurs est : active_fg=couleur active_bg=couleur inactive_fg=couleur inactive_bg=couleur. Où couleur peut être soit un nom de couleur, soit une valeur de la forme #rrggbb, soit le mot-clé AUCUNE pour revenir à l'utilisation des couleurs par défaut.

Options

--match, -m
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des : id, index, titre, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est l'onglet/la fenêtre créé(e) le plus récemment.

Lorsque vous utilisez title ou id, une correspondance d'onglet est d'abord recherchée, et si elle n'est pas trouvée, une correspondance de fenêtre est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre du système d'exploitation active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre du système d'exploitation active, zéro étant l'onglet actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session active actuelle et ~ pour faire correspondre soit la session active actuelle, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre parente du système d'exploitation. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements du clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets de la fenêtre du système d'exploitation actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--self [=no]
Fermez l'onglet dans lequel cette commande est exécutée, plutôt que l'onglet actif.
--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse de l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si elle n'est pas spécifiée, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la contact de kitty. Cela incitera kitty à demander à l'utilisateur la permission d'effectuer l'action spécifiée, sauf si le mot de passe a déjà été accepté ou s'il est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme toujours.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs de fin sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, il vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, il vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation systématique ou jamais du mot de passe fourni. S'il est défini sur always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
