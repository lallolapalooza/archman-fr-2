NOM

kubectl set resources - Mettre à jour les requêtes/limites de ressources sur les objets avec des modèles de pods

SYNTAXE

kubectl set resources [OPTIONS]

DESCRIPTION

Spécifiez les exigences en ressources informatiques (CPU, mémoire) pour toute ressource qui définit un modèle de pod. Si un pod est planifié avec succès, il se voit garantir la quantité de ressource demandée, mais peut dépasser ses limites spécifiées.

Pour chaque ressource informatique, si une limite est spécifiée et qu'une requête est omise, la requête prendra par défaut la valeur de la limite.

Ressources possibles incluant (insensible à la casse) : Utilisez "kubectl api-resources" pour une liste complète des ressources supportées.

OPTIONS

--all=false Sélectionne toutes les ressources, dans l'espace de noms des types de ressources spécifiés

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est absent(e) du modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

-c, --containers="*" Les noms des conteneurs dans les modèles de pods sélectionnés à modifier, tous les conteneurs sont sélectionnés par défaut - peut utiliser des caractères génériques

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est "client", affiche uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est "server", soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-set" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource à obtenir d'un serveur.

-k, --kustomize="" Traite le répertoire kustomize. Cette option ne peut pas être utilisée avec -f ou -R.

--limits="" Les requêtes de ressources pour ce conteneur. Par exemple, 'cpu=100m,memory=256Mi'. Notez que les composants côté serveur peuvent attribuer des requêtes en fonction de la configuration du serveur, telles que les limites de plage.

--local=false Si vrai, set resources NE contactera PAS le serveur API mais s'exécutera localement.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur faux, n'enregistre pas la commande. Si défini sur vrai, enregistre la commande. Si non défini, par défaut, met à jour la valeur d'annotation existante uniquement si une existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--requests="" Les requêtes de ressources pour ce conteneur. Par exemple, 'cpu=100m,memory=256Mi'. Notez que les composants côté serveur peuvent attribuer des requêtes en fonction de la configuration du serveur, telles que les limites de plage.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'. (par exemple, -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'affichage des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est les modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS HÉRITÉES DES COMMANDES PARENT

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur ordinaire ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, cette option peut être répétée pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant le gate de fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Définir les limites de CPU du conteneur nginx du déploiement à "200m" et la mémoire à "512Mi"
  kubectl set resources deployment nginx -c=nginx --limits=cpu=200m,memory=512Mi
  # Définir la requête et les limites de ressources pour tous les conteneurs dans nginx
  kubectl set resources deployment nginx --limits=cpu=200m,memory=512Mi --requests=cpu=100m,memory=256Mi
  # Supprimer les requêtes de ressources pour les ressources sur les conteneurs dans nginx
  kubectl set resources deployment nginx --limits=cpu=0,memory=0 --requests=cpu=0,memory=0
  # Afficher le résultat (au format yaml) de la mise à jour des limites du conteneur nginx à partir d'un fichier local, sans contacter le serveur
  kubectl set resources -f path/to/file.yaml --limits=cpu=200m,memory=512Mi --local -o yaml
