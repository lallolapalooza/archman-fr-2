NOM

kubectl port-forward - Transfère un ou plusieurs ports locaux vers un pod

SYNOPSIS

kubectl port-forward [OPTIONS]

DESCRIPTION

Transfère un ou plusieurs ports locaux vers un pod.

Utilisez le type/nom de ressource comme deployment/mondéploiement pour sélectionner un pod. Le type de ressource est par défaut 'pod' s'il est omis.

S'il y a plusieurs pods correspondant aux critères, un pod sera sélectionné automatiquement. La session de transfert se termine lorsque le pod sélectionné se termine, et une nouvelle exécution de la commande est nécessaire pour reprendre le transfert.

OPTIONS

--address=[localhost] Adresses sur lesquelles écouter (séparées par des virgules). N'accepte que les adresses IP ou localhost comme valeur. Lorsque localhost est fourni, kubectl tentera de se lier à la fois à 127.0.0.1 et à ::1 et échouera si aucune de ces adresses n'est disponible pour la liaison.

--pod-running-timeout=1m0s Durée (comme 5s, 2m, ou 3h, supérieure à zéro) pendant laquelle attendre qu'au moins un pod soit en cours d'exécution.

OPTIONS HÉRÉDITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la feature gate KUBECTL_KUBERC=false ou en désactivant la feature KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile="none" Nom du profil à capturer. L'un des éléments suivants (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie que les requêtes ne sont pas limitées dans le temps.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton d'authentification Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Écouter sur les ports 5000 et 6000 localement, transférant les données vers/depuis les ports 5000 et 6000 dans le pod
  kubectl port-forward pod/monpod 5000 6000
  # Écouter sur les ports 5000 et 6000 localement, transférant les données vers/depuis les ports 5000 et 6000 dans un pod sélectionné par le déploiement
  kubectl port-forward deployment/mondéploiement 5000 6000
  # Écouter sur le port 8443 localement, transférant vers le targetPort du port nommé "https" du service dans un pod sélectionné par le service
  kubectl port-forward service/monservice 8443:https
  # Écouter sur le port 8888 localement, transférant vers 5000 dans le pod
  kubectl port-forward pod/monpod 8888:5000
  # Écouter sur tous les adresses sur le port 8888, transférant vers 5000 dans le pod
  kubectl port-forward --address 0.0.0.0 pod/monpod 8888:5000
  # Écouter sur localhost et une IP sélectionnée sur le port 8888, transférant vers 5000 dans le pod
  kubectl port-forward --address localhost,10.19.21.23 pod/monpod 8888:5000
  # Écouter sur un port aléatoire localement, transférant vers 5000 dans le pod
  kubectl port-forward pod/monpod :5000
