NOM

kubectl patch - Mettre à jour les champs d'une ressource

SYNTAXE

kubectl patch [OPTIONS]

DESCRIPTION

Met à jour les champs d'une ressource en utilisant un patch de fusion stratégique, un patch de fusion JSON, ou un patch JSON.

Les formats JSON et YAML sont acceptés.

Note : Le patch de fusion stratégique n'est pas pris en charge pour les ressources personnalisées.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de mappe est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server", ou "client". En stratégie client, imprime uniquement l'objet qui serait envoyé, sans l'envoyer. En stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-patch" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource à mettre à jour

-k, --kustomize="" Traite le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--local=false Si vrai, le patch opérera sur le contenu du fichier, et non sur la ressource côté serveur.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

-p, --patch="" Le patch à appliquer au fichier JSON de la ressource.

--patch-file="" Un fichier contenant un patch à appliquer à la ressource.

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, met à jour par défaut la valeur d'annotation existante uniquement si elle existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression d'objets au format JSON ou YAML.

--subresource="" Si spécifié, le patch opérera sur la sous-ressource de l'objet demandé.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui de golang [http://golang.org/pkg/text/template/#pkg-overview].

--type="strategic" Le type de patch fourni ; un parmi [json merge strategic]

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée du namespace pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une requête serveur individuelle. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas temporiser les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Mettre à jour partiellement un nœud en utilisant un patch de fusion stratégique, en spécifiant le patch en JSON
  kubectl patch node k8s-node-1 -p '{"spec":{"unschedulable":true}}'
  # Mettre à jour partiellement un nœud en utilisant un patch de fusion stratégique, en spécifiant le patch en YAML
  kubectl patch node k8s-node-1 -p $'spec:\n unschedulable: true'
  # Mettre à jour partiellement un nœud identifié par le type et le nom spécifiés dans "node.json" en utilisant un patch de fusion stratégique
  kubectl patch -f node.json -p '{"spec":{"unschedulable":true}}'
  # Mettre à jour l'image d'un conteneur ; spec.containers[*].name est requis car c'est une clé de fusion
  kubectl patch pod valid-pod -p '{"spec":{"containers":[{"name":"kubernetes-serve-hostname","image":"new image"}]}}'
  # Mettre à jour l'image d'un conteneur en utilisant un patch JSON avec des tableaux positionnels
  kubectl patch pod valid-pod --type='json' -p='[{"op": "replace", "path": "/spec/containers/0/image", "value":"new image"}]'
  # Mettre à jour les réplicas d'un déploiement via la sous-ressource 'scale' en utilisant un patch de fusion
  kubectl patch deployment nginx-deployment --subresource='scale' --type='merge' -p '{"spec":{"replicas":2}}'
