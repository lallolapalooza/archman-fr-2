NOM

kresd - résolveur DNSSEC complet avec cache Knot Resolver 5.7.5.

SYNTAXE

kresd [-a|--addr addr[@port]] [-t|--tls addr[@port]] [-S|--fd fd] [-T|--tlsfd fd] [-c|--config config] [-n|--noninteractive] [-q|--quiet] [-v|--verbose] [-V|--version] [-h|--help] [rundir]

DESCRIPTION

Knot Resolver est un résolveur complet avec cache et DNSSEC activé.

Mode de fonctionnement par défaut : lorsqu'il reçoit une requête DNS, il interroge itérativement les serveurs de noms faisant autorité en commençant par la zone racine (.) et en terminant par les serveurs de noms faisant autorité pour le nom interrogé. Le DNSSEC automatique signifie la vérification de l'intégrité des réponses faisant autorité en suivant les clés et les signatures à partir de la racine. L'ancre de confiance racine est automatiquement démarrée à partir de l'IANA, ou vous pouvez fournir un fichier avec des ancres de confiance racine (même format que le fichier de clés racine d'Unbound ou BIND9).

Le démon met également en cache les réponses intermédiaires dans le cache, qui utilise par défaut la base de données mappée en mémoire LMDB. Cela présente un avantage significatif par rapport aux caches en mémoire, car le processus peut être arrêté et redémarré sans perte d'entrées de cache. Dans un scénario multi-utilisateurs, un cache partagé peut poser un problème de confidentialité/sécurité ; avec kresd, chaque utilisateur peut avoir un cache de résolveur dans son répertoire privé et l'utiliser de manière similaire à un trousseau.

Pour utiliser un kresd local en cours d'exécution pour la résolution, placez

nameserver 127.0.0.1

dans resolv.conf(5) et démarrez kresd.

Le démon peut également être configuré comme un simple transmetteur en utilisant des politiques de requêtes. Cela nécessite l'utilisation d'un fichier de configuration. Veuillez vous référer à la documentation pour les options du fichier de configuration. Elle est disponible sur https://knot-resolver.readthedocs.io ou dans la documentation du paquet (disponible sous le nom knot-resolver-doc dans la plupart des distributions).

Les options de ligne de commande disponibles sont :

-a addr[@port], --addr=<addr[@port]>
Écouter sur la paire d'adresses (et de ports) donnée. Si aucun port n'est spécifié, 53 est utilisé par défaut. L'option peut être passée plusieurs fois pour écouter sur plusieurs adresses.
-t addr[@port], --tls=<addr[@port]>
Écouter en utilisant TLS sur la paire d'adresses (et de ports) donnée. Si aucun port n'est spécifié, 853 est utilisé par défaut. L'option peut être passée plusieurs fois pour écouter sur plusieurs adresses.
-S fd, --fd=<fd>
Écouter sur les descripteurs de fichiers (fd) donnés, passés par le superviseur. L'option peut être passée plusieurs fois pour écouter sur plusieurs descripteurs de fichiers.
-T fd, --tlsfd=<fd>
Écouter en utilisant TLS sur les descripteurs de fichiers (fd) donnés, passés par le superviseur. L'option peut être passée plusieurs fois pour écouter sur plusieurs descripteurs de fichiers.
-c config, --config=<config>
Définir le fichier de configuration avec les paramètres que kresd doit lire au lieu de lire le fichier à l'emplacement par défaut (config).
-f N, --forks=<N>
Cette option est dépréciée depuis la version 5.0.0 !

Avec cette option, le démon est démarré en mode non interactif et crée à la place une socket UNIX dans rundir à laquelle l'opérateur peut se connecter pour une session interactive. Un nombre supérieur à 1 crée N démons fils, tous les fils se lieront aux mêmes adresses et le noyau équilibrera la charge entre eux sous Linux avec la prise en charge de SO_REUSEPORT.

Si vous souhaitez que plusieurs processus simultanés soient supervisés de cette manière, ils doivent être supervisés indépendamment (voir kresd.systemd(7)).

-n, --noninteractive
Le démon s'abstiendra d'entrer dans la boucle lecture-évaluation-impression pour stdin+stdout.
-q, --quiet
Le démon s'abstiendra d'afficher l'invite de commande.
-v, --verbose
Augmenter la journalisation au niveau de débogage.
-h
Afficher l'aide des options courtes de la ligne de commande.
-V
Afficher la version.
