NOM

kubectl events - Lister les événements

SYNTAXE

kubectl events [OPTIONS]

DESCRIPTION

Affiche les événements.

Imprime un tableau des informations les plus importantes sur les événements. Vous pouvez demander les événements pour un espace de noms, pour tous les espaces de noms, ou filtrés pour ne garder que ceux qui concernent une ressource spécifiée.

OPTIONS

-A, --all-namespaces=false Si présent, liste les objets demandés dans tous les espaces de noms. L'espace de noms du contexte actuel est ignoré même s'il est spécifié avec --namespace.

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. Ne s'applique qu'aux formats de sortie golang et jsonpath.

--chunk-size=500 Retourne les listes volumineuses par morceaux plutôt que d'un seul coup. Passez 0 pour désactiver. Ce drapeau est en bêta et peut changer à l'avenir.

--for="" Filtre les événements pour ne garder que ceux qui concernent la ressource spécifiée.

--no-headers=false Lors de l'utilisation du format de sortie par défaut, n'imprime pas les en-têtes.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets aux formats JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier de modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format de modèle est celui de golang templates [http://golang.org/pkg/text/template/#pkg-overview].

--types=[] Affiche uniquement les événements des types donnés.

-w, --watch=false Après avoir listé les événements demandés, surveille les nouveaux événements.

OPTIONS HÉRITÉES DES COMMANDES PARENT

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la feature gate KUBECTL_KUBERC=false ou en désactivant la feature KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas attendre la fin des requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Lister les événements récents dans l'espace de noms par défaut
  kubectl events
  # Lister les événements récents dans tous les espaces de noms
  kubectl events --all-namespaces
  # Lister les événements récents pour le pod spécifié, puis attendre d'autres événements et les lister au fur et à mesure
  kubectl events --for pod/web-pod-13je7 --watch
  # Lister les événements récents au format YAML
  kubectl events -oyaml
  # Lister uniquement les événements récents de type 'Warning' ou 'Normal'
  kubectl events --types=Warning,Normal
