NOM

kubectl set env - Met à jour les variables d'environnement dans un template de pod

SYNTAXE

kubectl set env [OPTIONS]

DESCRIPTION

Met à jour les variables d'environnement dans un template de pod.

Liste les définitions de variables d'environnement dans un ou plusieurs pods, templates de pod. Ajoute, met à jour ou supprime les définitions de variables d'environnement de conteneurs dans un ou plusieurs templates de pod (au sein de contrôleurs de réplication ou de configurations de déploiement). Affiche ou modifie les définitions de variables d'environnement sur tous les conteneurs des pods ou templates de pod spécifiés, ou seulement ceux qui correspondent à un joker.

Si "--env -" est passé, les variables d'environnement peuvent être lues depuis STDIN en utilisant la syntaxe standard d'env.

Les ressources possibles incluent (insensible à la casse) :

    pod (po), replicationcontroller (rc), deployment (deploy), daemonset (ds), statefulset (sts), cronjob (cj), replicaset (rs)

OPTIONS

--all=false Si vrai, sélectionne toutes les ressources dans le namespace des types de ressources spécifiés

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les templates lorsqu'un champ ou une clé de map est manquant dans le template. S'applique uniquement aux formats de sortie golang et jsonpath.

-c, --containers="*" Les noms des conteneurs dans les templates de pod sélectionnés à modifier - peut utiliser des jokers

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est client, affiche seulement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

-e, --env=[] Spécifie une paire clé-valeur pour une variable d'environnement à définir dans chaque conteneur.

--field-manager="kubectl-set" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire, ou URL vers des fichiers de la ressource pour mettre à jour l'env

--from="" Nom d'une ressource à partir de laquelle injecter des variables d'environnement

--keys=[] Liste de clés séparées par des virgules à importer depuis la ressource spécifiée

-k, --kustomize="" Traite le répertoire kustomize. Cette option ne peut pas être utilisée avec -f ou -R.

--list=false Si vrai, affiche l'environnement et les changements sous le format standard. Cette option sera supprimée lorsque nous aurons kubectl view env.

--local=false Si vrai, set env ne contactera PAS le serveur d'API mais fonctionnera localement.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=true Si vrai, autorise l'écrasement de l'environnement, sinon rejette les mises à jour qui écrasent l'environnement existant.

--prefix="" Préfixe à ajouter aux noms de variables

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename récursivement. Utile lorsque vous souhaitez gérer des manifestes liés organisés au sein du même répertoire.

--resolve=false Si vrai, affiche les références de secret ou de configmap lors de la liste des variables

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, supporte '=', '==', '!=', 'in', 'notin'.(par ex. -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'affichage des objets au format JSON ou YAML.

--template="" Chaîne de template ou chemin vers un fichier de template à utiliser lorsque -o=go-template, -o=go-template-file. Le format du template est golang templates [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS INHERITÉS DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, cette option peut être répétée pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant la variable d'environnement KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exige que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée du namespace pour cette requête CLI

--password="" Mot de passe pour l'authentification basique auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie qu'il n'y a pas de timeout pour les requêtes.

-s, --server="" Adresse et port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton d'authentification Bearer pour le serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification basique auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Met à jour le déploiement 'registry' avec une nouvelle variable d'environnement
  kubectl set env deployment/registry STORAGE_DIR=/local
  # Liste les variables d'environnement définies sur le déploiement 'sample-build'
  kubectl set env deployment/sample-build --list
  # Liste les variables d'environnement définies sur tous les pods
  kubectl set env pods --all --list
  # Affiche le déploiement modifié en YAML, et ne modifie pas l'objet sur le serveur
  kubectl set env deployment/sample-build STORAGE_DIR=/data -o yaml
  # Met à jour tous les conteneurs de tous les contrôleurs de réplication du projet pour avoir ENV=prod
  kubectl set env rc --all ENV=prod
  # Importe l'environnement depuis un secret
  kubectl set env --from=secret/mysecret deployment/myapp
  # Importe l'environnement depuis une configmap avec un préfixe
  kubectl set env --from=configmap/myconfigmap --prefix=MYSQL_ deployment/myapp
  # Importe des clés spécifiques depuis une configmap
  kubectl set env --keys=my-example-key --from=configmap/myconfigmap deployment/myapp
  # Supprime la variable d'environnement ENV du conteneur 'c1' dans toutes les configurations de déploiement
  kubectl set env deployments --all --containers="c1" ENV-
  # Supprime la variable d'environnement ENV d'une définition de déploiement sur disque et
  # met à jour la configuration du déploiement sur le serveur
  kubectl set env -f deploy.json ENV-
  # Définit une partie de l'environnement shell local dans une configuration de déploiement sur le serveur
  env | grep RAILS_ | kubectl set env -e - deployment/registry
