Nom

kitten-@-select-window - Sélectionner visuellement une fenêtre dans l'onglet spécifié

Utilisation

kitten @ select-window

Description

Affiche l'identifiant de la fenêtre sélectionnée. D'autres commandes peuvent ensuite être chaînées pour l'utiliser.

Options

--correspondre, -m
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, titre, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, pas comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du nombre d'identifiant le plus élevé vers le bas, en particulier, -1 est l'onglet/fenêtre créé le plus récemment.

Lors de l'utilisation de title ou id, une correspondance d'onglet est d'abord recherchée, et si elle n'est pas trouvée, une correspondance de fenêtre est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'identifiant ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre du système d'exploitation actuellement active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre du système d'exploitation actuellement active, zéro étant l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant toute fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant toute fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre parente du système d'exploitation. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est mis en correspondance. La valeur focused_os_window correspond à tous les onglets de la fenêtre du système d'exploitation actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste d'onglets.

--delai-reponse [=60]
Le temps en secondes à attendre que l'utilisateur sélectionne une fenêtre.
--soi-meme [=non]
Sélectionner la fenêtre de l'onglet contenant la fenêtre dans laquelle cette commande est exécutée, au lieu de l'onglet actif.
--titre
Un titre qui sera affiché à l'utilisateur pour décrire l'objectif de cette sélection.
--exclure-actif [=non]
Exclure la fenêtre actuellement active de la liste des fenêtres à choisir.
--reactiver-onglet-precedent [=non]
Lorsque la sélection est terminée, l'onglet de la même fenêtre système qui était actif avant la sélection sera réactivé. La dernière fenêtre système activée sera également recentrée.
--aide, -h [=non]
Afficher l'aide pour cette commande

Options globales

--vers
Une adresse pour l'instance kitty à contrôler. Correspond à l'adresse donnée à l'instance kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si elle n'est pas spécifiée, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--mot-de-passe
Un mot de passe à utiliser lors de la communication avec kitty. Cela amènera kitty à demander à l'utilisateur la permission d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou s'il est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --utiliser-mot-de-passe comme toujours.
--fichier-mot-de-passe [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces blancs finaux sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire à partir du descripteur de fichier num. Utilisé si aucun --mot-de-passe n'est fourni. Par défaut, vérifie le fichier rc-pass dans le répertoire de configuration de kitty.
--env-mot-de-passe [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --fichier-mot-de-passe n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--utiliser-mot-de-passe [=si-disponible]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation toujours ou jamais du mot de passe fourni. S'il est défini sur toujours et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : si-disponible, toujours, jamais
