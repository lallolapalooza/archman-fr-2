Nom

kitten-@-set-background-opacity - Définir l'opacité de l'arrière-plan

Utilisation

kitten @ set-background-opacity OPACITÉ

Description

Définit l'opacité de l'arrière-plan pour les fenêtres spécifiées. Cela ne fonctionnera que si vous avez activé dynamic_background_opacity dans kitty.conf. L'opacité de l'arrière-plan affecte toutes les fenêtres kitty dans une même fenêtre du système d'exploitation. Par exemple::


kitten @ set-background-opacity 0.5

Options

--all, -a [=no]
Par défaut, l'opacité de l'arrière-plan n'est modifiée que pour la fenêtre du système d'exploitation actuellement active. Cette option permettra de modifier l'opacité de l'arrière-plan dans toutes les fenêtres.
--toggle [=no]
Lorsqu'elle est spécifiée, l'opacité de l'arrière-plan des fenêtres du système d'exploitation correspondantes sera réinitialisée à la valeur par défaut si elle est actuellement égale à la valeur spécifiée, sinon elle sera définie à la valeur spécifiée.
--match, -m
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent du plus grand numéro d'id vers le bas ; en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant à zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls).

L'identifiant de fenêtre de la fenêtre actuelle est disponible en tant que variable d'environnement KITTY_WINDOW_ID.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, où zéro est la fenêtre actuellement active, un est la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier un nom ou un nom et une valeur comme avec le champ env.

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont livrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est faite correspondre. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre du système d'exploitation actuellement focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est un superposition.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des fenêtres.

--match-tab, -t
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent du plus grand numéro d'id vers le bas ; en particulier, -1 est l'onglet/fenêtre créé le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'identifiant ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre du système d'exploitation actuellement active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre du système d'exploitation actuellement active, où zéro est l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant n'importe quelle fenêtre avec les variables d'environnement spécifiées sont faits correspondre. De même, var fait correspondre les onglets contenant n'importe quelle fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre du système d'exploitation parent. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont livrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est fait correspondre. La valeur focused_os_window correspond à tous les onglets de la fenêtre du système d'exploitation actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance de kitty à contrôler. Correspond à l'adresse donnée à l'instance de kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si elle n'est pas spécifiée, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si elle n'est pas non plus trouvée, les messages sont envoyés au terminal de contrôle de ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la connexion à kitty. Cela amènera kitty à demander à l'utilisateur l'autorisation d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces en fin de ligne sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie la présence du fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement la commande de contrôle à distance sans mot de passe. Cet
option
peut être utilisé pour forcer l'utilisation ou non du mot de passe fourni. S'il est défini sur "always" et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
