NOM

kxdpgun - Outil d'étalonnage DNS basé sur XDP

SYNTAXE

kxdpgun [options] -i fichier cible

DESCRIPTION

Générateur puissant de trafic DNS, envoyant et recevant des paquets via XDP.

Les requêtes sont générées selon un fichier textuel qui est lu séquentiellement en boucle jusqu'à ce qu'une durée configurée soit écoulée. L'ordre des requêtes n'est pas garanti. Les réponses sont reçues (sauf si désactivé) et comptées, mais pas vérifiées par rapport aux requêtes.

Le nombre de threads parallèles est auto-détecté en fonction du nombre de files d'attente configurées pour l'interface réseau.

Paramètres

fichier
Chemin vers le fichier de requêtes. Voir la description ci-dessous pour le format du fichier.
cible
Soit le nom de domaine, l'adresse IPv4 ou IPv6 d'une cible distante.

Options

-t, --duration secondes
Durée de génération du trafic, spécifiée sous forme d'un nombre décimal en secondes (par défaut 5.0).
-T, --tcp[=mode_debug]
Envoyer des requêtes sur TCP. Voir la liste des modes de débogage optionnels ci-dessous.
-U, --quic[=mode_debug]
Envoyer des requêtes sur QUIC. Voir la liste des modes de débogage optionnels ci-dessous.
-Q, --qps requêtes
Nombre de requêtes par seconde (approximativement) à envoyer (par défaut 1000). Le programme n'est pas optimisé pour les basses vitesses où il peut perdre des paquets de communication. La vitesse minimale recommandée est de 2 paquets par thread (file d'attente Rx/Tx).
-b, --batch taille
Envoyer plus de requêtes par lot. Améliore le QPS mais peut affecter la perte de paquets de la contrepartie (par défaut 10 pour UDP et 1 pour TCP/QUIC).
-r, --drop
Ignorer les réponses entrantes. Améliore le QPS, mais désactive les statistiques de réponse.
-p, --port numéro
Port de destination distant (par défaut 53 pour UDP/TCP, 853 pour QUIC).
-F, --affinity spec_cpu
Affinité CPU pour tous les threads spécifiée au format [<cpu_start>][s<cpu_step>], où <cpu_start> est l'ID CPU pour le premier thread et <cpu_step> est l'incrément d'ID CPU pour le thread suivant (par défaut 0s1).
-i, --infile fichier
Chemin vers un fichier contenant des modèles de requêtes.
-B, --binary
Spécifier que le fichier d'entrée est au format binaire. Ce format est similaire au format de message TCP DNS. Le fichier contient des enregistrements formatés comme une longueur de 2 octets (ordre réseau) suivie d'un message au format filaire DNS.
-I, --interface interface
Interface réseau pour la communication sortante. Ceci peut être utile dans des situations où les interfaces sont regroupées, par exemple.
-l, --local IP_locale[/préfixe]
Remplacer l'adresse IP source auto-détectée. Si une plage d'adresses est spécifiée à la place, diverses IP de la plage seront utilisées uniformément pour différentes requêtes (plage d'adresses non supportée en mode QUIC).
-L, --mac-local
Remplacer l'adresse MAC locale auto-détectée.
-R, --mac-remote
Remplacer l'adresse MAC distante auto-détectée.
-v, --vlan id
Ajouter un en-tête VLAN 802.1Q avec l'ID donné. Le délestage VLAN doit être désactivé.
-e, --edns-size taille
Taille du paquet UDP EDNS, plage 512-4096 (par défaut 1232). Notez que sur XDP, le MTU maximum supporté est de 1790.
-m, --mode mode
Définir le mode XDP. Les valeurs supportées sont :
  • auto (par défaut) – le mode XDP est sélectionné automatiquement pour obtenir les meilleures performances, ce qui signifie que le support natif du pilote est préféré au générique, et le zero-copy est utilisé si disponible.
  • copy – le mode de copie du socket XDP est forcé même si le zero-copy est disponible. Cela peut résoudre divers problèmes de pilote, mais au détriment des performances.
  • generic – l'implémentation générique XDP est forcée même si l'implémentation native est disponible. Ce mode ne nécessite pas le support du pilote ni du matériel, mais offre les pires performances.
-G, --qlog chemin
Générer des fichiers qlog dans le répertoire spécifié par chemin. Le répertoire doit exister.

Cette option est ignorée si ce n'est pas en mode QUIC. L'usage recommandé est avec --quic=R ou avec un QPS bas. Sinon, trop de fichiers sont générés.

-j, --json
Afficher les statistiques formatées en json.
-S, --stats-period période
Rapporter automatiquement les statistiques toutes les période millisecondes.

Ces rapports ne contiennent que les métriques collectées pendant la période donnée.

-h, --help
Afficher l'aide du programme.
-V, --version
Afficher la version du programme. L'option -VV fait afficher au programme le résumé de la configuration à la compilation.

Format du fichier de requêtes

Chaque ligne décrit une requête sous la forme :

nom_requête type_requête [flags]

Où nom_requête est un nom de domaine à interroger, type_requête est un nom de type d'enregistrement, et flags est un caractère unique :

E Envoyer la requête avec EDNS.

D Demander DNSSEC (EDNS + flag DO).

Modes de débogage TCP/QUIC

0
Effectuer une poignée de main complète pour toutes les connexions (QUIC seulement).
1
Envoyer seulement SYN (Initial) et recevoir SYN-ACK (Handshake).
2
Effectuer la poignée de main TCP/QUIC et n'envoyer rien, permettre la fermeture initiée par le correspondant.
3
Effectuer la poignée de main TCP/QUIC et ne plus réagir.
5
Envoyer une requête incomplète (N-1 octets) et ne plus réagir.
7
Envoyer la requête et ne pas accuser réception de la réponse ou de quoi que ce soit d'autre.
8
Ne pas fermer la connexion et ignorer la fermeture par le correspondant.
9
Fonctionner normalement sauf pour ne pas accuser réception du FIN+ACK final (TCP seulement).
R
Au lieu d'ouvrir une connexion pour chaque requête, réutiliser les connexions.

Signaux

L'envoi du signal USR1 à un processus en cours d'exécution déclenche un vidage des statistiques actuelles sur la sortie standard. En combinaison avec -S peut entraîner un timing d'impression erratique.

NOTES

Le noyau Linux 4.18+ est requis.

L'utilitaire doit être exécuté en tant que root ou avec ces capacités : CAP_NET_RAW, CAP_NET_ADMIN, CAP_SYS_ADMIN, CAP_IPC_LOCK et CAP_SYS_RESOURCE (Linux < 5.11).

L'utilitaire alloue des ports UDP/TCP source dans la plage 2000-65535.

En raison de la structure multi-thread du programme, il existe de légères discrépances dans la période de temps pendant laquelle

ich sont collectées pour tout thread donné. Les impressions de statistiques l'ignorent et sont donc très légèrement inexactes. La marge d'erreur diminue proportionnellement au volume de données et à la période sur laquelle elles sont collectées.

VALEURS DE SORTIE

Un code de sortie de 0 signifie une opération réussie. Tout autre code de sortie indique une erreur.

EXEMPLES

Fichier de requêtes créé manuellement :

abc6.example.com. AAAA
nxdomain.example.com. A
notzone. A
a.example.com. NS E
ab.example.com. A D
abcd.example.com. DS D

Fichier de requêtes généré à partir d'un fichier de zone (format Knot DNS) :

cat ZONE_FILE | awk "{print \$1,\$3}" | grep -E "(NS|DS|A|AAAA|PTR|MX|SOA)$" | sort -u -R > queries.txt

Utilisation basique :

# kxdpgun -i ~/queries.txt 2001:DB8::1

Utilisation d'UDP avec une taille de lot accrue :

# kxdpgun -t 20 -Q 1000000 -i ~/queries.txt -b 20 -p 8853 192.0.2.1

Utilisation de TCP :

# kxdpgun -t 20 -Q 100000 -i ~/queries.txt -T -p 8853 192.0.2.1
