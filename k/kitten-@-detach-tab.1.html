Nom

kitten-@-detach-tab - Détacher les onglets spécifiés et les placer dans une fenêtre d'OS différente/nouvelle

Utilisation

kitten @ detach-tab

Description

Détache les onglets spécifiés et les déplace soit dans une nouvelle fenêtre d'OS, soit les ajoute à la fenêtre d'OS contenant l'onglet spécifié par --target-tab

Options

--match, -m
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id le plus élevé vers le bas ; en particulier, -1 est l'onglet/fenêtre créé le plus récemment.

Lors de l'utilisation de title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro d'index est utilisé pour faire correspondre le nième onglet dans la fenêtre d'OS actuellement active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre d'OS actuellement active, zéro étant l'onglet actuellement actif, un l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lors de l'utilisation du champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier soit uniquement le nom de la variable d'environnement, soit un nom et une valeur, par exemple env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont correspondus. De même, var correspond aux onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre d'OS parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont transmis. Si aucun onglet n'est focalisé, le dernier onglet focalisé est correspondu. La valeur focused_os_window correspond à tous les onglets dans la fenêtre d'OS actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls pour obtenir une liste des onglets.

--self [=no]
Détacher l'onglet dans lequel cette commande est exécutée, plutôt que l'onglet actif.
--help, -h [=no]
Afficher l'aide pour cette commande

Options globales

--to
Une adresse pour l'instance de kitty à contrôler. Correspond à l'adresse donnée à l'instance de kitty via l'option --listen-on ou le paramètre listen_on dans kitty.conf. Si non spécifié, la variable d'environnement KITTY_LISTEN_ON est vérifiée. Si celle-ci n'est pas non plus trouvée, les messages sont envoyés au terminal contrôleur pour ce processus, c'est-à-dire qu'ils ne fonctionneront que si ce processus est exécuté dans une fenêtre kitty.
--password
Un mot de passe à utiliser lors de la connexion à kitty. Cela fera demander à kitty la permission à l'utilisateur d'effectuer l'action spécifiée, sauf si le mot de passe a été accepté auparavant ou est préconfiguré dans kitty.conf. Pour utiliser un mot de passe vide, spécifiez --use-password comme always.
--password-file [=rc-pass]
Un fichier à partir duquel lire le mot de passe. Les espaces en fin de ligne sont ignorés. Les chemins relatifs sont résolus à partir du répertoire de configuration de kitty. Utilisez - pour lire depuis STDIN. Utilisez fd:num pour lire depuis le descripteur de fichier num. Utilisé si aucun --password n'est fourni. Par défaut, vérifie la présence du fichier rc-pass dans le répertoire de configuration de kitty.
--password-env [=KITTY_RC_PASSWORD]
Le nom d'une variable d'environnement à partir de laquelle lire le mot de passe. Utilisé si aucun --password-file n'est fourni. Par défaut, vérifie la variable d'environnement KITTY_RC_PASSWORD.
--use-password [=if-available]
Si aucun mot de passe n'est disponible, kitty enverra généralement simplement la commande de contrôle à distance sans mot de passe. Cette option peut être utilisée pour forcer l'utilisation ou non du mot de passe fourni. Si défini à always et qu'aucun mot de passe n'est fourni, le mot de passe vide est utilisé.

Choix : if-available, always, never
