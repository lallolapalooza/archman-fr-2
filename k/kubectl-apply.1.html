NOM

kubectl apply - Appliquer une configuration à une ressource par nom de fichier ou par entrée standard

SYNTAXE

kubectl apply [OPTIONS]

DESCRIPTION

Appliquer une configuration à une ressource par nom de fichier ou par entrée standard. Le nom de la ressource doit être spécifié. Cette ressource sera créée si elle n'existe pas déjà. Pour utiliser 'apply', créez toujours la ressource initialement avec 'apply' ou 'create --save-config'.

Les formats JSON et YAML sont acceptés.

Avertissement Alpha : la fonctionnalité --prune n'est pas encore complète. Ne pas utiliser à moins d'être conscient de l'état actuel. Voir https://issues.k8s.io/34274.

OPTIONS

--all=false Sélectionner toutes les ressources dans l'espace de noms des types de ressources spécifiés.

--allow-missing-template-keys=true Si vrai, ignorer toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--cascade="background" Doit être "background", "orphan" ou "foreground". Sélectionne la stratégie de suppression en cascade pour les dépendants (par exemple, les Pods créés par un ReplicationController). Par défaut, "background".

--dry-run="none" Doit être "none", "server" ou "client". En stratégie client, affiche seulement l'objet qui serait envoyé, sans l'envoyer. En stratégie serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-client-side-apply" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Les fichiers qui contiennent les configurations à appliquer.

--force=false Si vrai, supprime immédiatement les ressources de l'API et ignore la suppression progressive. Notez que la suppression immédiate de certaines ressources peut entraîner une incohérence ou une perte de données et nécessite une confirmation.

--force-conflicts=false Si vrai, l'application côté serveur forcera les modifications en cas de conflits.

--grace-period=-1 Période de temps en secondes accordée à la ressource pour se terminer proprement. Ignoré si négatif. Défini sur 1 pour un arrêt immédiat. Ne peut être défini sur 0 que si --force est vrai (suppression forcée).

-k, --kustomize="" Traiter un répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--openapi-patch=true Si vrai, utilise openapi pour calculer la différence lorsque openapi est présent et que la ressource peut être trouvée dans la spécification openapi. Sinon, revient aux types intégrés.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=true Résoudre automatiquement les conflits entre la configuration modifiée et la configuration active en utilisant les valeurs de la configuration modifiée.

--prune=false Supprimer automatiquement les objets de ressources qui n'apparaissent pas dans les configurations et qui sont créés par apply ou create --save-config. Doit être utilisé avec -l ou --all.

--prune-allowlist=[] Remplacer la liste d'autorisation par défaut pour --prune.

--record=false Enregistrer la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur faux, n'enregistre pas la commande. Si défini sur vrai, enregistre la commande. Si non défini, par défaut, met à jour la valeur de l'annotation existante uniquement si une existe déjà.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename récursivement. Utile lorsque vous souhaitez gérer des manifestes connexes organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, supporte '=', '==', '!=', 'in', 'notin'. (par exemple, -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--server-side=false Si vrai, apply s'exécute sur le serveur au lieu du client.

--show-managed-fields=false Si vrai, conserve les champs gérés lors de l'impression des objets au format JSON ou YAML.

--subresource="" Si spécifié, apply opérera sur la sous-ressource de l'objet demandé. Autorisé uniquement lors de l'utilisation de --server-side.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est golang templates [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=0s La durée pendant laquelle attendre avant d'abandonner une suppression, zéro signifie déterminer un délai en fonction de la taille de l'objet.

--validate="strict" Doit être l'un des suivants : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si elle est invalide. Il effectuera une validation côté serveur si ServerSideFieldValidation est activé sur le serveur d'API, mais reviendra à une validation côté client moins fiable sinon. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si la validation des champs côté serveur est activée sur le serveur d'API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

--wait=false Si vrai, attendez que les ressources aient disparu avant de revenir. Cela attend les finaliseurs.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut.

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification.

--client-certificate="" Chemin vers un fichier de certificat client pour TLS.

--client-key="" Chemin vers un fichier de clé client pour TLS.

--cluster="" Nom du cluster kubeconfig à utiliser.

--context="" Nom du contexte kubeconfig à utiliser.

--disable-compression=false Si vrai, désactive la compression des réponses pour toutes les requêtes vers le serveur.

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant le portail de fonctionnalités KUBECTL_KUBERC=false ou en désactivant le portail KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client.

-n, --namespace="" Si présent, l'espace de noms pour cette requête CLI.

--password="" Mot de passe pour l'authentification de base auprès du serveur API.

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex).

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil.

--request-timeout="0" La durée pendant laquelle attendre avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas dépasser le temps des requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes.

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton d'authentification d'accès (bearer token) pour le serveur API.

--user="" Nom de l'utilisateur kubeconfig à utiliser.

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API.

--version=false --version, --version=raw affiche la version i

EXEMPLE

  # Appliquer la configuration dans pod.json à un pod
  kubectl apply -f ./pod.json
  # Appliquer les ressources à partir d'un répertoire contenant kustomization.yaml - par exemple, dir/kustomization.yaml
  kubectl apply -k dir/
  # Appliquer le JSON passé à stdin à un pod
  cat pod.json | kubectl apply -f -
  # Appliquer la configuration de tous les fichiers se terminant par '.json'
  kubectl apply -f '*.json'
  # Note : --prune est encore en Alpha
  # Appliquer la configuration dans manifest.yaml qui correspond à l'étiquette app=nginx et supprimer toutes les autres ressources qui ne sont pas dans le fichier et correspondent à l'étiquette app=nginx
  kubectl apply --prune -f manifest.yaml -l app=nginx
  # Appliquer la configuration dans manifest.yaml et supprimer toutes les autres ConfigMaps qui ne sont pas dans le fichier
  kubectl apply --prune -f manifest.yaml --all --prune-allowlist=core/v1/ConfigMap
