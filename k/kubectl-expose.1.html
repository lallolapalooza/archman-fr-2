NOM

kubectl expose - Exposer un contrôleur de réplication, un service, un déploiement ou un pod sous forme d'un nouveau service Kubernetes

SYNTAXE

kubectl expose [OPTIONS]

DESCRIPTION

Expose une ressource sous forme d'un nouveau service Kubernetes.

Recherche un déploiement, un service, un ensemble de répliques, un contrôleur de réplication ou un pod par son nom et utilise le sélecteur de cette ressource comme sélecteur pour un nouveau service sur le port spécifié. Un déploiement ou un ensemble de répliques ne sera exposé en tant que service que si son sélecteur est convertible en un sélecteur pris en charge par le service, c'est-à-dire lorsque le sélecteur contient uniquement le composant matchLabels. Notez que si aucun port n'est spécifié via --port et que la ressource exposée a plusieurs ports, tous seront réutilisés par le nouveau service. De même, si aucun libellé n'est spécifié, le nouveau service réutilisera les libellés de la ressource qu'il expose.

Ressources possibles incluent (insensible à la casse) :

pod (po), service (svc), replicationcontroller (rc), deployment (deploy), replicaset (rs)

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toute erreur dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--cluster-ip="" IP de cluster à attribuer au service. Laisser vide pour auto-allouer, ou définir sur 'None' pour créer un service headless.

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est client, imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

--external-ip="" Adresse IP externe supplémentaire (non gérée par Kubernetes) à accepter pour le service. Si cette IP est routée vers un nœud, le service peut être accédé par cette IP en plus de son IP de service générée.

--field-manager="kubectl-expose" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource pour exposer un service.

-k, --kustomize="" Traiter le répertoire kustomization. Ce drapeau ne peut pas être utilisé avec -f ou -R.

-l, --labels="" Libellés à appliquer au service créé par cet appel.

--load-balancer-ip="" IP à attribuer au LoadBalancer. Si vide, une IP éphémère sera créée et utilisée (spécifique au fournisseur de cloud).

--name="" Le nom de l'objet nouvellement créé.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--override-type="merge" La méthode utilisée pour remplacer l'objet généré : json, merge, ou strategic.

--overrides="" Une substitution JSON en ligne pour l'objet généré. Si ce n'est pas vide, elle est utilisée pour remplacer l'objet généré. Nécessite que l'objet fournisse un champ apiVersion valide.

--port="" Le port sur lequel le service doit servir. Copié de la ressource exposée, si non spécifié.

--protocol="" Le protocole réseau pour le service à créer. Par défaut, c'est 'TCP'.

--record=false Enregistrer la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, la valeur par défaut est de mettre à jour la valeur de l'annotation existante uniquement si elle existe déjà.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename récursivement. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

--save-config=false Si vrai, la configuration de l'objet actuel sera enregistrée dans son annotation. Sinon, l'annotation ne sera pas modifiée. Ce drapeau est utile lorsque vous souhaitez effectuer une application kubectl sur cet objet à l'avenir.

--selector="" Un sélecteur d'étiquettes à utiliser pour ce service. Seules les exigences de sélecteur basées sur l'égalité sont prises en charge. Si vide (par défaut), déduit le sélecteur du contrôleur de réplication ou de l'ensemble de répliques).

--session-affinity="" Si non vide, définit l'affinité de session pour le service comme ceci ; valeurs valides : 'None', 'ClientIP'

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'impression des objets au format JSON ou YAML.

--target-port="" Nom ou numéro du port du conteneur vers lequel le service doit diriger le trafic. Optionnel.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--type="" Type pour ce service : ClusterIP, NodePort, LoadBalancer, ou ExternalName. Par défaut, c'est 'ClusterIP'.

OPTIONS HERITEES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression de réponse pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la fonctionnalité KUBECTL_KUBERC=false ou en désactivant la fonctionnalité KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier où écrire le profil

--request-timeout="0" La durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas limiter les requêtes dans le temps.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

NOM

kubectl-expose

SYNTAXE

kubectl expose (-f <filename> | --filename <filename>) [--port=<port>] [--target-port=<port>] [--name=<name>] [--type=<type>] [--protocol=<protocol>] kubectl expose (-f <filename> | --filename <filename>) ... --list [--all-containers] kubectl expose (-f <filename> | --filename <filename>) ... --output [--all-containers] kubectl expose (pod | service | rc | replicationcontroller | rs | replicaset | deployment | dp | daemonset | ds | statefulset | sts | job | cronjob | nging.io/v1beta1/Ingress | api.object.group/version/kind) (<name> | --all) (-f <filename> | --filename <filename>) [--selector <selector>] [--port=<port>] [--target-port=<port>] [--name=<name>] [--type=<type>] [--protocol=<protocol>] [--dry-run=<value>]

DESCRIPTION

Crée un service qui expose une application.

Les ressources peuvent être désignées par nom ou par le biais d'un fichier.

Par défaut, les services sont de type ClusterIP.

Une ressource peut être soit un fichier contenant une définition de ressource Kubernetes, soit un objet existant tel qu'un pod, un contrôleur de réplication, un replica set, un déploiement, etc.

OPTIONS

--all
Sélectionner toutes les ressources du type spécifié.
--all-containers
Si exposé à partir d'un fichier, exporter tous les conteneurs du pod.
-f, --filename <filename>
Nom(s) du ou des fichier(s) contenant des définitions de ressources.
-l, --selector <selector>
Seulement les ressources correspondant au sélecteur spécifié seront exposées. Le sélecteur est une liste de paires clé=valeur séparées par des virgules.
-o, --output <value>
Format de la sortie. Les valeurs possibles sont : text, yaml, json. Le défaut est text.
--port=<port>
Port sur lequel le service écoutera. Doit être un nombre entier compris entre 1 et 65535.
--protocol=<protocol>
Protocole à utiliser pour le service : TCP (par défaut) ou UDP.
--target-port=<port>
Port sur lequel les conteneurs de la ressource écouteront. Si ce n'est pas spécifié, la valeur de `--port` sera utilisée. Peut être un nombre ou un nom de port.
--type=<type>
Type de service. Les valeurs possibles sont : ClusterIP, NodePort, LoadBalancer.
--dry-run=<value>
Lorsque spécifié avec 'client', le serveur ne validera pas la requête, mais retournera une réponse ressemblant à ce qui se passerait si la requête était valide. Les serveurs n'effectueront aucune action et les objets retournés ne seront pas persistants. Quand spécifié avec 'server', le serveur effectuera la validation de la requête, mais ne créera pas d'objets et retournera une réponse ressemblant à ce qui se passerait si la requête était valide. Les valeurs possibles sont : none, client, server.
--list
Si spécifié, la sortie sera une liste de ressources exposées.

EXEMPLE

  # Crée un service pour un contrôleur de réplication identifié par le type et le nom spécifiés dans "nginx-controller.yaml", qui écoute sur le port 80 et se connecte aux conteneurs sur le port 8000
  kubectl expose -f nginx-controller.yaml --port=80 --target-port=8000
  # Crée un service pour un pod nommé valid-pod, qui écoute sur le port 444 avec le nom "frontend"
  kubectl expose pod valid-pod --port=444 --name=frontend
  # Crée un deuxième service basé sur le service ci-dessus, exposant le port du conteneur 8443 comme port 443 avec le nom "nginx-https"
  kubectl expose service nginx --port=443 --target-port=8443 --name=nginx-https
  # Crée un service pour une application de streaming répliquée sur le port 4100 équilibrant le trafic UDP et nommé 'video-stream'.
  kubectl expose rc streamer --port=4100 --protocol=UDP --name=video-stream
  # Crée un service pour un nginx répliqué en utilisant un replica set, qui écoute sur le port 80 et se connecte aux conteneurs sur le port 8000
  kubectl expose rs nginx --port=80 --target-port=8000
  # Crée un service pour un déploiement nginx, qui écoute sur le port 80 et se connecte aux conteneurs sur le port 8000
  kubectl expose deployment nginx --port=80 --target-port=8000
