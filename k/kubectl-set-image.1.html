NOM

kubectl set image - Met à jour l'image d'un modèle de pod

SYNTAXE

kubectl set image [OPTIONS]

DESCRIPTION

Met à jour les images de conteneur existantes des ressources.

Les ressources possibles incluent (insensible à la casse) :

    pod (po), replicationcontroller (rc), deployment (deploy), daemonset (ds), statefulset (sts), cronjob (cj), replicaset (rs)

OPTIONS

--all=false Sélectionne toutes les ressources, dans l'espace de noms des types de ressources spécifiés

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de carte est manquant dans le modèle. S'applique uniquement aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est client, imprime uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

--field-manager="kubectl-set" Nom du gestionnaire utilisé pour suivre la propriété des champs.

-f, --filename=[] Nom de fichier, répertoire ou URL vers des fichiers identifiant la ressource à obtenir d'un serveur.

-k, --kustomize="" Traite le répertoire kustomize. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--local=false Si vrai, set image ne contactera PAS le serveur d'API mais s'exécutera localement.

-o, --output="" Format de sortie. Un parmi : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Enregistre la commande kubectl actuelle dans l'annotation de la ressource. Si défini sur false, n'enregistre pas la commande. Si défini sur true, enregistre la commande. Si non défini, la valeur par défaut est de mettre à jour la valeur d'annotation existante uniquement si elle existe déjà.

-R, --recursive=false Traite le répertoire utilisé dans -f, --filename de manière récursive. Utile lorsque vous souhaitez gérer des manifestes liés organisés dans le même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'.(par exemple, -l key1=value1,key2=value2,key3 in (value3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquette spécifiées.

--show-managed-fields=false Si vrai, conserve les managedFields lors de l'affichage des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque -o=go-template, -o=go-template-file. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

OPTIONS INHERITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un espace de noms.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Le nom du cluster kubeconfig à utiliser

--context="" Le nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression de réponse pour toutes les requêtes au serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié pour sa validité. Cela rendra vos connexions HTTPS non sécurisées.

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Cela peut être désactivé en exportant la feature gate KUBECTL_KUBERC=false ou en désactivant la feature KUBERC=off.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, l'espace de noms pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. Un parmi (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" La durée pendant laquelle attendre avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé.

--token="" Jeton Bearer pour l'authentification auprès du serveur API

--user="" Le nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw imprime les informations de version et quitte ; --version=vX.Y.Z... définit la version rapportée

--warnings-as-errors=false Traite les avertissements reçus du serveur comme des erreurs et quitte avec un code de sortie non nul

EXEMPLE

  # Définir l'image du conteneur nginx d'un déploiement à 'nginx:1.9.1', et l'image du conteneur busybox à 'busybox'
  kubectl set image deployment/nginx busybox=busybox nginx=nginx:1.9.1
  # Mettre à jour l'image du conteneur nginx de tous les déploiements et rc à 'nginx:1.9.1'
  kubectl set image deployments,rc nginx=nginx:1.9.1 --all
  # Mettre à jour l'image de tous les conteneurs du daemonset abc à 'nginx:1.9.1'
  kubectl set image daemonset abc *=nginx:1.9.1
  # Imprimer le résultat (au format yaml) de la mise à jour de l'image du conteneur nginx à partir d'un fichier local, sans contacter le serveur
  kubectl set image -f path/to/file.yaml nginx=nginx:1.9.1 --local -o yaml

NOM

kubectl-set-image - Mettre à jour l'image des conteneurs dans les ressources.

SYNTAXE

kubectl set image (<resource>/<name> | -f FILENAME) (<container_name>=<image> | -c <container_name> <image>) [--recursive=true] [OPTIONS]

DESCRIPTION

Mettre à jour l'image d'un ou plusieurs conteneurs dans une ressource spécifiée. Les ressources valides incluent : deployments, statefulsets, daemonsets, replicationcontrollers, et pods.

Vous pouvez spécifier le nom de la ressource et le nouveau nom de l'image. Par exemple, pour mettre à jour l'image du conteneur app dans le deployment my-dep vers myrepo/myimage:v2, utilisez :

kubectl set image deployment/my-dep app=myrepo/myimage:v2

Si vous ne spécifiez pas de nom de conteneur, l'image de tous les conteneurs de la ressource sera mise à jour.

kubectl set image deployment my-dep myrepo/myimage:v2

Vous pouvez également spécifier plusieurs conteneurs et plusieurs ressources dans une seule commande.

Vous pouvez spécifier des ressources à modifier en utilisant le drapeau -f pour lire la définition de la ressource depuis un fichier.

OPTIONS

-c <container-name>, --container=<container-name>
Nom du ou des conteneurs dont l'image doit être mise à jour.
--all-containers
Mettre à jour l'image de tous les conteneurs.
--dry-run=strategy
Si défini, exécuter la commande sans effectuer de changements réels.
-f, --filename=[]
Nom(s) de fichier(s) contenant la définition de la ressource.
--local=false
Si vrai, le serveur ne sera pas contacté pour valider le schéma.
-o, --output=""
Format de sortie de la commande. Les formats valides sont : json, yaml, wide, name, template, templatefile, go-template, go-template-file, jsonpath, jsonpath-file.
--output-version=""
Version de l'objet de sortie.
--record=false
Enregistrer cette commande dans la vue de l'historique de l'objet.
--recursive=true
S'il faut rechercher récursivement dans les sous-répertoires les ressources lors de l'utilisation de -f.
--save-config=false
Si vrai, enregistrer la configuration mise à jour dans l'annotation de l'objet.
--selector=""
Sélecteur d'étiquette pour filtrer les ressources en fonction des étiquettes.
--template=""
Modèle go template pour le formatage de la sortie.
--validate=true
Valider la configuration avant de l'envoyer au serveur.
--windows-fields=[]
Quand on travaille avec des champs de type Windows, ils sont automatiquement convertis en Unix. Ce paramètre permet de les laisser tels quels.

EXEMPLE

Mettre à jour l'image du déploiement my-deploy, conteneur nginx, vers nginx:1.17.

kubectl set image deployment/my-deploy nginx=nginx:1.17

Mettre à jour l'image du conteneur myapp dans le StatefulSet my-sts vers my-registry/my-app:v2.

kubectl set image statefulset/my-sts myapp=my-registry/my-app:v2

Mettre à jour l'image de tous les conteneurs dans le DaemonSet my-daemon vers my-daemon:v1.1.

kubectl set image daemonset/my-daemon --all-containers=true my-daemon=my-daemon:v1.1

Mettre à jour l'image du pod my-pod, conteneur main, vers my-app:latest.

kubectl set image pod/my-pod main=my-app:latest

Mettre à jour l'image du déploiement my-deployment, conteneur app, vers my-app:v2, en enregistrant l'opération pour les futures comparaisons.

kubectl set image deployment my-deployment -c app=my-app:v2 --record

DIAGNOSTICS

Les erreurs sont généralement signalées sous forme de messages explicites sur la sortie d'erreur standard.
