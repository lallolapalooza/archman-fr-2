Le tampon circulaire se trouve dans le répertoire tracefs et peut être récupéré par tracefs_instance_get_file(3) à per_cpu/cpuX/trace_pipe_raw où X est remplacé par le numéro de CPU du tampon circulaire spécifié. Le tampon circulaire à l'intérieur du noyau est divisé par CPU, de sorte que le tampon circulaire brut doit également être récupéré par CPU. La fonction kbuffer_alloc() créera un descripteur

qui

peut être utilisé pour gérer un sous-tampon lu par le tampon circulaire. Le paramètre size indique la taille de mot pour le tampon donné (notez que cela fonctionne en lisant des données brutes provenant d'autres machines que celle qui appelle cette fonction). Le paramètre endian indique l'endianness de la machine. Si endian est défini à KBUFFER_ENDIAN_SAME_AS_HOST

,

If l'endianness sera définie sur la même que celle de l'hôte, ce qui est utile lorsque l'application lit les données du tampon circulaire directement depuis la même machine sur laquelle elle s'exécute. Si size est défini

à

K BUFFER_LSIZE_SAME_AS_HOST, si la taille de mot est 8, le descripteur kbuffer sera défini sur une taille longue de 8. Mais si la taille est 4, alors il effectuera un appel uname(2) et si le champ machine contient la chaîne "64", il sera défini sur une taille longue de 8 octets et non de 4. Cela est dû au fait que la taille longue du tampon circulaire dépend du noyau et non de l'espace utilisateur.

La

fonction kbuffer_dup() dupliquera une structure kbuffer existante avec une nouvelle structure allouée. Elle aura toutes les propriétés du kbuf passé, y compris le pointage vers le même sous-tampon qui a été chargé dans le kbuf. Elle doit être libérée avec kbuffer_free() . La fonc
