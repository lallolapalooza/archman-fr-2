NOM

kubectl delete - Supprimer des ressources par noms de fichiers, stdin, ressources et noms, ou par ressources et sélecteur d'étiquettes

SYNOPIS

kubectl delete [OPTIONS]

DESCRIPTION

Supprimer des ressources par noms de fichiers, stdin, ressources et noms, ou par ressources et sélecteur d'étiquettes.

Les formats JSON et YAML sont acceptés. Un seul type d'argument peut être spécifié : noms de fichiers, ressources et noms, ou ressources et sélecteur d'étiquettes.

Certaines ressources, comme les pods, prennent en charge la suppression gracieuse. Ces ressources définissent une période par défaut avant d'être forcées de se terminer (la période de grâce), mais vous pouvez remplacer cette valeur avec le drapeau --grace-period, ou passer --now pour définir une période de grâce de 1. Étant donné que ces ressources représentent souvent des entités dans le cluster, la suppression peut ne pas être immédiatement acquittée. Si le nœud hébergeant un pod est en panne ou ne peut pas atteindre le serveur API, la terminaison peut prendre beaucoup plus de temps que la période de grâce. Pour forcer la suppression d'une ressource, vous devez spécifier le drapeau --force. Note : seule une sous-partie des ressources prend en charge la suppression gracieuse. En l'absence de prise en charge, le drapeau --grace-period est ignoré.

IMPORTANT : Forcer la suppression des pods n'attend pas de confirmation que les processus du pod ont été terminés, ce qui peut laisser ces processus en cours d'exécution jusqu'à ce que le nœud détecte la suppression et termine la suppression gracieuse. Si vos processus utilisent un stockage partagé ou communiquent avec une API distante et dépendent du nom du pod pour s'identifier, forcer la suppression de ces pods peut entraîner l'exécution de plusieurs processus sur différentes machines utilisant la même identification, ce qui peut conduire à une corruption ou une incohérence des données. Forcez la suppression des pods uniquement lorsque vous êtes sûr que le pod est terminé, ou si votre application peut tolérer plusieurs copies du même pod en cours d'exécution simultanément. De plus, si vous forcez la suppression des pods, le planificateur peut placer de nouveaux pods sur ces nœuds avant que le nœud n'ait libéré ces ressources, ce qui entraîne l'éviction immédiate de ces pods.

Notez que la commande de suppression NE FAIT PAS de vérifications de version de ressource, donc si quelqu'un soumet une mise à jour à une ressource au moment où vous soumettez une suppression, leur mise à jour sera perdue avec le reste de la ressource.

Après la suppression d'une définition de ressource personnalisée (CustomResourceDefinition), l'invalidation du cache de découverte peut prendre jusqu'à 6 heures. Si vous ne souhaitez pas attendre, vous pouvez exécuter "kubectl api-resources" pour actualiser le cache de découverte.

OPTIONS

--all=false Supprimer toutes les ressources, dans l'espace de noms des types de ressources spécifiés.

-A, --all-namespaces=false Si présent, lister les objets demandés à travers tous les espaces de noms. L'espace de noms du contexte actuel est ignoré même s'il est spécifié avec --namespace.

--cascade="background" Doit être "background", "orphan", ou "foreground". Sélectionne la stratégie de suppression en cascade pour les dépendants (par exemple, les Pods créés par un ReplicationController). Par défaut, c'est background.

--dry-run="none" Doit être "none", "server", ou "client". Si la stratégie est client, affiche uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet une requête côté serveur sans persister la ressource.

--field-selector="" Sélecteur (requête de champ) pour filtrer, prend en charge '=', '==', et '!='. (par exemple, --field-selector clé1=valeur1,clé2=valeur2). Le serveur ne prend en charge qu'un nombre limité de requêtes de champs par type.

-f, --filename=[] contenant la ressource à supprimer.

--force=false Si vrai, supprime immédiatement les ressources de l'API et ignore la suppression gracieuse. Notez que la suppression immédiate de certaines ressources peut entraîner une incohérence ou une perte de données et nécessite une confirmation.

--grace-period=-1 Période en secondes accordée à la ressource pour se terminer gracieusement. Ignoré si négatif. Défini à 1 pour un arrêt immédiat. Ne peut être défini à 0 que lorsque --force est vrai (suppression forcée).

--ignore-not-found=false Traiter "ressource non trouvée" comme une suppression réussie. Par défaut, "true" lorsque --all est spécifié.

-i, --interactive=false Si vrai, supprimer la ressource uniquement lorsque l'utilisateur confirme.

-k, --kustomize="" Traiter un répertoire kustomize. Ce drapeau ne peut pas être utilisé avec -f ou -R.

--now=false Si vrai, les ressources sont signalées pour un arrêt immédiat (équivalent à --grace-period=1).

-o, --output="" Mode de sortie. Utiliser "-o name" pour une sortie plus courte (ressource/nom).

--raw="" URI brute à DELETE vers le serveur. Utilise le transport spécifié par le fichier kubeconfig.

-R, --recursive=false Traiter le répertoire utilisé dans -f, --filename récursivement. Utile lorsque vous souhaitez gérer des manifestes liés organisés au sein du même répertoire.

-l, --selector="" Sélecteur (requête d'étiquette) pour filtrer, prend en charge '=', '==', '!=', 'in', 'notin'. (par exemple, -l clé1=valeur1,clé2=valeur2,clé3 in (valeur3)). Les objets correspondants doivent satisfaire toutes les contraintes d'étiquettes spécifiées.

--timeout=0s La durée d'attente avant d'abandonner une suppression, zéro signifie déterminer un délai à partir de la taille de l'objet

--wait=true Si vrai, attendre que les ressources aient disparu avant de retourner. Ceci attend les finaliseurs.

-n, --namespace="" Si présent, la portée de l'espace de noms pour cette requête CLI

-s, --server="" L'adresse et le port du serveur API Kubernetes

EXEMPLE

  # Supprimer un pod en utilisant le type et le nom spécifiés dans pod.json
  kubectl delete -f ./pod.json
  # Supprimer des ressources d'un répertoire contenant kustomization.yaml - par exemple dir/kustomization.yaml
  kubectl delete -k dir
  # Supprimer des ressources de tous les fichiers se terminant par '.json'
  kubectl delete -f '*.json'
  # Supprimer un pod basé sur le type et le nom dans le JSON passé à stdin
  cat pod.json | kubectl delete -f -
  # Supprimer les pods et services portant les mêmes noms "baz" et "foo"
  kubectl delete pod,service baz foo
  # Supprimer les pods et services avec le label name=myLabel
  kubectl delete pods,services -l name=myLabel
  # Supprimer un pod avec un délai minimal
  kubectl delete pod foo --now
  # Supprimer de force un pod sur un nœud mort
  kubectl delete pod foo --force
  # Supprimer tous les pods
  kubectl delete pods --all
  # Supprimer tous les pods uniquement si l'utilisateur confirme la suppression
  kubectl delete pods --all --interactive
