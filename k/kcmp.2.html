kcmp(2) Manuel des appels système kcmp(2)

NOM

kcmp - comparer deux processus pour déterminer s'ils partagent une ressource du noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/kcmp.h>       /* Définition des constantes KCMP_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_kcmp, pid_t pid1, pid_t pid2, int type,
            unsigned long idx1, unsigned long idx2);

Note : glibc ne fournit pas d'enveloppe pour kcmp(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

L'appel système kcmp() peut être utilisé pour vérifier si les deux processus identifiés par pid1 et pid2 partagent une ressource du noyau telle que la mémoire virtuelle, les descripteurs de fichiers, etc.

La permission d'employer kcmp() est régie par des vérifications de mode d'accès ptrace PTRACE_MODE_READ_REALCREDS sur pid1 et pid2 ; voir ptrace(2).

L'argument type spécifie quelle ressource doit être comparée dans les deux processus. Il a l'une des valeurs suivantes :

KCMP_FILE
Vérifier si un descripteur de fichier idx1 dans le processus pid1 fait référence à la même description de fichier ouverte (voir open(2)) que le descripteur de fichier idx2 dans le processus pid2. L'existence de deux descripteurs de fichiers faisant référence à la même description de fichier ouverte peut résulter de dup(2) (et similaires) fork(2), ou du passage de descripteurs de fichiers via un socket de domaine (voir unix(7)).
KCMP_FILES
Vérifier si les processus partagent le même ensemble de descripteurs de fichiers ouverts. Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_FILES dans clone(2).
KCMP_FS
Vérifier si les processus partagent les mêmes informations de système de fichiers (c'est-à-dire, masque de création de mode de fichier, répertoire de travail et racine du système de fichiers). Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_FS dans clone(2).
KCMP_IO
Vérifier si les processus partagent le contexte d'E/S. Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_IO dans clone(2).
KCMP_SIGHAND
Vérifier si les processus partagent la même table de dispositions de signaux. Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_SIGHAND dans clone(2).
KCMP_SYSVSEM
Vérifier si les processus partagent la même liste d'opérations d'annulation des sémaphores System V. Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_SYSVSEM dans clone(2).
KCMP_VM
Vérifier si les processus partagent le même espace d'adressage. Les arguments idx1 et idx2 sont ignorés. Voir la discussion du drapeau CLONE_VM dans clone(2).
KCMP_EPOLL_TFD (depuis Linux 4.13)
Vérifier si le descripteur de fichier idx1 du processus pid1 est présent dans l'instance epoll(7) décrite par idx2 du processus pid2. L'argument idx2 est un pointeur vers une structure où le fichier cible est décrit. Cette structure a la forme :


struct kcmp_epoll_slot {
    __u32 efd;
    __u32 tfd;
    __u64 toff;
};

Dans cette structure, efd est un descripteur de fichier epoll renvoyé par epoll_create(2), tfd est un numéro de descripteur de fichier cible, et toff est un décalage de fichier cible compté à partir de zéro. Plusieurs cibles différentes peuvent être enregistrées avec le même numéro de descripteur de fichier et la définition d'un décalage spécifique aide à examiner chacune d'elles.

Notez que kcmp() n'est pas protégé contre les faux positifs qui peuvent survenir si les processus sont actuellement en cours d'exécution. Il faut arrêter les processus en envoyant SIGSTOP (voir signal(7)) avant l'inspection avec cet appel système pour obtenir des résultats significatifs.

VALEUR DE RETOUR

La valeur de retour d'un appel réussi à kcmp() est simplement le résultat de la comparaison arithmétique des pointeurs du noyau (lorsque le noyau compare des ressources, il utilise leurs adresses mémoire).

La façon la plus simple d'expliquer est de considérer un exemple. Supposons que v1 et v2 soient les adresses des ressources appropriées, alors la valeur de retour est l'un des éléments suivants :

0
v1 est égal à v2 ; en d'autres termes, les deux processus partagent la ressource.
1
v1 est inférieur à v2.
2
v1 est supérieur à v2.
3
v1 n'est pas égal à v2, mais des informations d'ordre ne sont pas disponibles.

En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

kcmp() a été conçu pour renvoyer des valeurs adaptées au tri. Ceci est particulièrement utile si l'on doit comparer un grand nombre de descripteurs de fichiers.

ERREURS

EBADF
type est KCMP_FILE et fd1 ou fd2 n'est pas un descripteur de fichier ouvert.
EFAULT
L'emplacement epoll adressé par idx2 est en dehors de l'espace d'adressage de l'utilisateur.
EINVAL
type est invalide.
ENOENT
Le fichier cible n'est pas présent dans l'instance epoll(7).
EPERM
Permissions insuffisantes pour inspecter les ressources du processus. La capacité CAP_SYS_PTRACE est requise pour inspecter les processus qui ne vous appartiennent pas. D'autres limitations de ptrace peuvent également s'appliquer, comme CONFIG_SECURITY_YAMA, qui, lorsque /proc/sys/kernel/yama/ptrace_scope est 2, limite kcmp() aux processus enfants ; voir ptrace(2).
ESRCH
Le processus pid1 ou pid2 n'existe pas.

NORMES

Linux.

HISTORIQUE

Linux 3.5.

Avant Linux 5.12, cet appel système n'était disponible que si le noyau était configuré avec CONFIG_CHECKPOINT_RESTORE, car le but initial de cet appel système était pour la fonctionnalité de sauvegarde/restauration dans l'espace utilisateur (CRIU). (L'alternative à cet appel système aurait été d'exposer des informations de processus appropriées via le système de fichiers proc(5) ; cela a été jugé inapproprié pour des raisons de sécurité.) Depuis Linux 5.12, cet appel système est également disponible si le noyau est configuré avec CONFIG_KCMP.

NOTES

Voir clone(2) pour quelques informations générales sur les ressources partagées mentionnées sur cette page.

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <linux/kcmp.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/syscall.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
static int
kcmp(pid_t pid1, pid_t pid2, int type,
     unsigned long idx1, unsigned long idx2)
{
    return syscall(SYS_kcmp, pid1, pid2, type, idx1, idx2);
}
static void
test_kcmp(char *msg, pid_t pid1, pid_t pid2, int fd_a, int fd_b)
{
    printf("\t%s\n", msg);
    printf("\t\tkcmp(%jd, %jd, KCMP_FILE, %d, %d) ==> %s\n",
           (intmax_t) pid1, (intmax_t) pid2, fd_a, fd_b,
           (kcmp(pid1, pid2, KCMP_FILE, fd_a, fd_b) == 0) ?
                        "same" : "different");
}
int
main(void)
{
    int                fd1, fd2, fd3;
    static const char  pathname[] = "/tmp/kcmp.test";
    fd1 = open(pathname, O_CREAT | O_RDWR, 0600);
    if (fd1 == -1)
        err(EXIT_FAILURE, "open");
    printf("Parent PID is %jd\n", (intmax_t) getpid());
    printf("Parent opened file on FD %d\n\n", fd1);
    switch (fork()) {
    case -1:
        err(EXIT_FAILURE, "fork");
    case 0:
        printf("PID of child of fork() is %jd\n", (intmax_t) getpid());
        test_kcmp("Compare duplicate FDs from different processes:",
                  getpid(), getppid(), fd1, fd1);
        fd2 = open(pathname, O_CREAT | O_RDWR, 0600);
        if (fd2 == -1)
            err(EXIT_FAILURE, "open");
        printf("Child opened file on FD %d\n", fd2);
        test_kcmp("Compare FDs from distinct open()s in same process:",
                  getpid(), getpid(), fd1, fd2);
        fd3 = dup(fd1);
        if (fd3 == -1)
            err(EXIT_FAILURE, "dup");
        printf("Child duplicated FD %d to create FD %d\n", fd1, fd3);
        test_kcmp("Compare duplicated FDs in same process:",
                  getpid(), getpid(), fd1, fd3);
        break;
    default:
        wait(NULL);
    }
    exit(EXIT_SUCCESS)
;
}
