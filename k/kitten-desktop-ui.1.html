Nom

kitten-desktop-ui - Documentation du kitten

Vue d'ensemble

Ajouté dans la version 0.43.0.

Les utilisateurs avancés des terminaux sous Linux apprécient souvent l'utilisation de gestionnaires de fenêtres minimalistes plutôt que des environnements de bureau complets. Ce kitten permet de fournir des éléments de l'environnement de bureau qui font défaut dans de telles configurations, et ce en utilisant des composants d'interface utilisateur rapides et centrés sur le clavier. Certaines de ses fonctionnalités sont :

  • Remplace les boîtes de dialogue Ouvrir/Enregistrer de fichiers typiques des programmes graphiques par le kitten choose-files <> rapide et centré sur le clavier, exécuté dans une superposition de kitty semi-transparente.
  • Permet une gestion simple des modes clair/sombre du bureau en ligne de commande.

Comment installer

Note :

Ce kitten repose sur le kitten panel <> en arrière-plan pour fournir les composants de l'interface utilisateur. Consultez la documentation <#panel-compat> de ce kitten pour savoir si votre gestionnaire de fenêtres est compatible avec.

Exécutez d'abord :

kitten desktop-ui enable-portal

Ensuite, définissez les deux variables d'environnement suivantes, pour l'ensemble du système, c'est-à-dire dans /etc/environment ou l'équivalent pour votre distribution :

QT_QPA_PLATFORMTHEME=xdgdesktopportal
GTK_USE_PORTAL=1

Enfin, redémarrez. Désormais, lorsque vous ouvrirez une boîte de dialogue de fichier dans la plupart des applications graphiques, celle-ci devrait ouvrir le kitten choose-files <> au lieu d'une boîte de dialogue d'ouverture de fichier normale. Vous pouvez changer le mode clair/sombre actuel de votre bureau en exécutant :

kitten desktop-ui set-color-scheme dark
kitten desktop-ui set-color-scheme light

Vérifiez la valeur actuelle en utilisant :

dbus-send --session --print-reply --dest=org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop org.freedesktop.portal.Settings.Read string:org.freedesktop.appearance string:color-scheme

Comment ça marche

Les environnements de bureau Linux modernes disposent de ce que l'on appelle des portails https://flatpak.github.io/xdg-desktop-portal/docs/index.html qui ont été inventés pour les applications sandboxées et qui fournissent diverses fonctionnalités à ces applications via DBUS, y compris les boîtes de dialogue d'ouverture de fichiers, les paramètres courants du bureau, etc. Ce kitten fonctionne en implémentant un backend pour certains de ces services.

Les applications graphiques normales peuvent alors être informées d'utiliser ces services, nous permettant ainsi de remplacer des parties de l'expérience de bureau au besoin.

Il existe plusieurs implémentations concurrentes des backends. Chaque environnement de bureau comme KDE ou GNOME a son propre backend et de nombreux gestionnaires de fenêtres fournissent également des implémentations pour certains backends. La découverte de services et la configuration du backend à utiliser se font via le programme xdg-desktop-portal, généralement trouvé à /usr/lib/xdg-desktop-portal.

Il peut être configuré par des fichiers dans ~/.local/share/xdg-desktop-portal. Voir la page de manuel portals.conf https://man.archlinux.org/man/portals.conf.5. La commande kitten desktop-ui enable-portal s'occupe automatiquement de la configuration pour vous. Si vous souhaitez personnaliser exactement quels services utiliser avec ce kitten, exécutez la commande puis modifiez le fichier conf que la commande indique avoir patché.

Dépannage

Assurez-vous d'abord que DBUS est capable de démarrer automatiquement le kitten lorsqu'il est nécessaire. Si le kitten n'est pas déjà en cours d'exécution, essayez la commande suivante :

dbus-send --session --print-reply --dest=org.freedesktop.impl.portal.desktop.kitty \
    /net/kovidgoyal/kitty/portal org.freedesktop.DBus.Properties.GetAll \
    string:net.kovidgoyal.kitty.settings

Si DBUS est capable de démarrer le kitten ou s'il est déjà en cours d'exécution, il affichera la propriété de version, sinon il échouera avec une erreur. En cas d'échec, vérifiez le fichier ~/.local/share/dbus-1/services/org.freedesktop.impl.portal.desktop.kitty.service qui aurait dû être créé par la commande enable-portal. Sa clé Exec doit pointer vers le chemin complet de l'exécutable du kitten.

Ensuite, vérifiez que le système de portails XDG utilise bien ce kitten pour son backend de configuration. Exécutez :

dbus-send --session --print-reply --dest=org.freedesktop.portal.Desktop \
    /org/freedesktop/portal/desktop org.freedesktop.portal.Settings.Read \
    string:net.kovidgoyal.kitty string:status

Si cela renvoie une réponse, le kitten est utilisé comme prévu. S'il renvoie une erreur "not found", un autre backend est utilisé pour les paramètres.

Lisez la page de manuel portals.conf et exécutez :

/usr/lib/xdg-desktop-portal -r v

cela affichera beaucoup d'informations de débogage, qui devraient vous indiquer quel backend est choisi pour quel service. Lisez attentivement les informations de débogage pour déterminer pourquoi le kitten n'est pas sélectionné.

Si certaines applications graphiques n'utilisent pas le kitten choose-files pour leurs boîtes de dialogue de sélection de fichiers, assurez-vous que les variables d'environnement mentionnées ci-dessus sont définies. Vous pouvez également essayer d'exécuter l'application graphique avec elles explicitement définies, comme suit :

QT_QPA_PLATFORMTHEME=xdgdesktopportal GTK_USE_PORTAL=1 mon-app-graphique

Notez que toutes les applications n'utilisent pas les portails. Ainsi, si une application particulière ne parvient pas à utiliser le portail mais que d'autres fonctionnent, signalez le problème aux développeurs de cette application.
