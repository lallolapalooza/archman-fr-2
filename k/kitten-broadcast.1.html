Nom

kitten-broadcast - Diffuse du texte tapé vers les fenêtres kitty

Aperçu

Tapez du texte dans toutes les fenêtres kitty simultanément

Le kitten broadcast peut être utilisé pour taper du texte simultanément dans toutes les fenêtres kitty <#term-window> (ou un sous-ensemble selon le désir).

Pour l'utiliser, créez simplement un mappage dans kitty.conf tel que :

map f1 launch --allow-remote-control kitty +kitten broadcast

Ensuite, appuyez sur la touche F1 et tout ce que vous taperez dans la nouvelle fenêtre sera envoyé à toutes les fenêtres kitty.

Vous pouvez utiliser les options décrites ci-dessous pour contrôler quelles fenêtres sont sélectionnées.

Par exemple, pour diffuser uniquement vers d'autres fenêtres dans l'onglet actuel :

map f1 launch --allow-remote-control kitty +kitten broadcast --match-tab state:focused

Code source de broadcast

Le code source de ce kitten est disponible sur GitHub https://github.com/kovidgoyal/kitty/tree/master/kittens/broadcast.

Interface en ligne de commande

kitty +kitten broadcast [options] [texte initial à envoyer ...]

Diffuse le texte tapé vers les fenêtres kitty. Par défaut, le texte est envoyé à toutes les fenêtres, sauf si l'une des options de correspondance est spécifiée.

Options

--hide-input-toggle <MASQUER_ENTREE>
Touche à presser pour activer/désactiver le masquage de l'entrée dans la fenêtre de diffusion elle-même. Utile lors de la saisie d'un mot de passe, cela empêche le mot de passe d'être visible à l'écran. Par défaut : Ctrl+Alt+Esc
--end-session <TERMINER_SESSION>
Touche à presser pour terminer la session de diffusion. Par défaut : Ctrl+Esc
--match <CORRESPONDANCE>, -m <CORRESPONDANCE>
La fenêtre à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où le champ peut être l'un des suivants : id, title, pid, cwd, cmdline, num, env, var, state, neighbor, session et recent. la requête est l'expression à faire correspondre. Les expressions peuvent être un nombre ou une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens <#search-syntax>.

La valeur spéciale all correspond à toutes les fenêtres.

Pour les champs numériques : id, pid, num et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id correspondent à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est la fenêtre créée le plus récemment.

Le champ num fait référence à la position de la fenêtre dans l'onglet actuel, en commençant par zéro et en comptant dans le sens des aiguilles d'une montre (c'est le même ordre que celui dans lequel les fenêtres sont rapportées par la commande kitten @ ls <#at-ls>).

L'id de fenêtre de la fenêtre actuelle est disponible sous la variable d'environnement KITTY_WINDOW_ID <#envvar-KITTY_WINDOW_ID>.

Le champ recent fait référence aux fenêtres récemment actives dans l'onglet actuellement actif, zéro étant la fenêtre actuellement active, un étant la fenêtre précédemment active, et ainsi de suite.

Le champ neighbor fait référence à un voisin de la fenêtre active dans la direction spécifiée, qui peut être : left, right, top ou bottom.

Le champ session correspond aux fenêtres qui ont été créées dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2.

De même, le champ var correspond aux variables utilisateur définies sur la fenêtre. Vous pouvez spécifier un nom ou un nom et une valeur, comme avec le champ env.

Le champ state correspond à l'état de la fenêtre. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused, focused_os_window, self, overlay_parent. Les fenêtres actives sont les fenêtres qui sont actives dans leur onglet parent. Il n'y a qu'une seule fenêtre focalisée et c'est la fenêtre à laquelle les événements clavier sont délivrés. Si aucune fenêtre n'est focalisée, la dernière fenêtre focalisée est utilisée. La valeur focused_os_window correspond à toutes les fenêtres de la fenêtre système actuellement focalisée. La valeur self correspond à la fenêtre dans laquelle la commande de contrôle à distance est exécutée. La valeur overlay_parent correspond à la fenêtre qui se trouve sous la fenêtre self, lorsque la fenêtre self est une superposition.

Notez que vous pouvez utiliser la commande kitten @ ls <#at-ls> pour obtenir une liste de fenêtres.

--match-tab <CORRESPONDANCE_TAB>, -t <CORRESPONDANCE_TAB>
L'onglet à faire correspondre. Les spécifications de correspondance sont de la forme : champ:requête. Où le champ peut être l'un des suivants : id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session et recent. la requête est l'expression à faire correspondre. Les expressions peuvent être soit un nombre, soit une expression régulière, et peuvent être combinées à l'aide d'opérateurs booléens <#search-syntax>.

La valeur spéciale all correspond à tous les onglets.

Pour les champs numériques : id, index, window_id, pid et recent, l'expression est interprétée comme un nombre, et non comme une expression régulière. Les valeurs négatives pour id/window_id correspondent à partir du numéro d'id le plus élevé vers le bas, en particulier, -1 est l'onglet/la fenêtre créée le plus récemment.

Lorsque vous utilisez title ou id, un onglet correspondant est d'abord recherché, et s'il n'est pas trouvé, une fenêtre correspondante est recherchée, et l'onglet de cette fenêtre est utilisé.

Vous pouvez également utiliser window_id et window_title pour faire correspondre l'onglet qui contient la fenêtre avec l'id ou le titre spécifié.

Le numéro index est utilisé pour faire correspondre le nième onglet dans la fenêtre système actuellement active. Le numéro recent correspond aux onglets récemment actifs dans la fenêtre système actuellement active, zéro étant l'onglet actuellement actif, un étant l'onglet précédemment actif, et ainsi de suite.

Le champ session correspond aux onglets qui ont été créés dans la session spécifiée. Utilisez l'expression ^$ pour faire correspondre les fenêtres qui n'ont pas été créées dans une session et . pour faire correspondre la session actuellement active et ~ pour faire correspondre soit la session actuellement active, soit la dernière session active lorsqu'aucune session n'est active.

Lorsque vous utilisez le champ env pour faire correspondre des variables d'environnement, vous pouvez spécifier uniquement le nom de la variable d'environnement ou un nom et une valeur, par exemple, env:MY_ENV_VAR=2. Les onglets contenant une fenêtre avec les variables d'environnement spécifiées sont mis en correspondance. De même, var correspond aux onglets contenant une fenêtre avec la variable utilisateur spécifiée.

Le champ state correspond à l'état de l'onglet. Les états pris en charge sont : active, focused, needs_attention, parent_active, parent_focused et focused_os_window. Les onglets actifs sont les onglets qui sont actifs dans leur fenêtre système parente. Il n'y a qu'un seul onglet focalisé et c'est l'onglet auquel les événements clavier sont délivrés. Si aucun onglet n'est focalisé, le dernier onglet focalisé est utilisé. La valeur focused_os_window correspond à tous les onglets de la fenêtre système actuellement focalisée.

Notez que vous pouvez utiliser la commande kitten @ ls <#at-ls> pour obtenir une liste d'onglets.
