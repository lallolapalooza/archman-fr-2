NOM

kubelet -

SYNTAXE

kubelet [OPTIONS]

DESCRIPTION

Le kubelet est l'agent de nœud principal qui s'exécute sur chaque nœud. Il peut enregistrer le nœud auprès de l'apiserver en utilisant l'une des méthodes suivantes : le nom d'hôte ; un drapeau pour remplacer le nom d'hôte ; ou une logique spécifique pour un fournisseur cloud.

Le kubelet travaille en termes de PodSpec. Un PodSpec est un objet YAML ou JSON qui décrit un pod. Le kubelet prend un ensemble de PodSpecs qui sont fournis par divers mécanismes (principalement via l'apiserver) et s'assure que les conteneurs décrits dans ces PodSpecs sont en cours d'exécution et sains. Le kubelet ne gère pas les conteneurs qui n'ont pas été créés par Kubernetes.

Outre un PodSpec provenant de l'apiserver, il existe deux façons de fournir un manifeste de conteneur au Kubelet.

Fichier : chemin passé sous forme de drapeau sur la ligne de commande. Les fichiers sous ce chemin seront surveillés périodiquement pour des mises à jour. La période de surveillance est de 20 secondes par défaut et est configurable via un drapeau.

Point d'accès HTTP : point d'accès HTTP passé en tant que paramètre sur la ligne de commande. Ce point d'accès est vérifié toutes les 20 secondes (également configurable avec un drapeau).

OPTIONS

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version affichée
