kubectl-create-deployment(1)

Paquet: kubectl

Licences: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOM

kubectl create deployment - Crée un déploiement avec le nom spécifié

SYNOPIS

kubectl create deployment [OPTIONS]

DESCRIPTION

Crée un déploiement avec le nom spécifié.

OPTIONS

--allow-missing-template-keys=true Si vrai, ignore toutes les erreurs dans les modèles lorsqu'un champ ou une clé de map est manquant dans le modèle. Ne s'applique qu'aux formats de sortie golang et jsonpath.

--dry-run="none" Doit être "none", "server" ou "client". Si la stratégie est client, affiche uniquement l'objet qui serait envoyé, sans l'envoyer. Si la stratégie est serveur, soumet la requête côté serveur sans persister la ressource.

--field-manager="kubectl-create" Nom du gestionnaire utilisé pour suivre la propriété des champs.

--image=[] Noms d'images à exécuter. Un déploiement peut avoir plusieurs images définies pour un pod multi-conteneurs.

-o, --output="" Format de sortie. L'un des suivants : (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--port=-1 Le containerPort que ce déploiement expose.

-r, --replicas=1 Nombre de répliques à créer. La valeur par défaut est 1.

--save-config=false Si vrai, la configuration de l'objet actuel sera enregistrée dans son annotation. Sinon, l'annotation ne sera pas modifiée. Ce drapeau est utile lorsque vous souhaitez effectuer un `kubectl apply` sur cet objet à l'avenir.

--show-managed-fields=false Si vrai, conserve les `managedFields` lors de l'affichage des objets au format JSON ou YAML.

--template="" Chaîne de modèle ou chemin vers un fichier modèle à utiliser lorsque `-o=go-template`, `-o=go-template-file`. Le format du modèle est celui des modèles golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Doit être l'un des suivants : strict (ou true), warn, ignore (ou false). "true" ou "strict" utilisera un schéma pour valider l'entrée et échouera la requête si elle est invalide. Il effectuera une validation côté serveur si `ServerSideFieldValidation` est activée sur le serveur API, mais se rabattra sur une validation côté client moins fiable si ce n'est pas le cas. "warn" avertira des champs inconnus ou dupliqués sans bloquer la requête si `ServerSideFieldValidation` est activée sur le serveur API, et se comportera comme "ignore" sinon. "false" ou "ignore" n'effectuera aucune validation de schéma, supprimant silencieusement tous les champs inconnus ou dupliqués.

OPTIONS HÉRITÉES DES COMMANDES PARENTES

--as="" Nom d'utilisateur à usurper pour l'opération. L'utilisateur peut être un utilisateur régulier ou un compte de service dans un namespace.

--as-group=[] Groupe à usurper pour l'opération, ce drapeau peut être répété pour spécifier plusieurs groupes.

--as-uid="" UID à usurper pour l'opération.

--cache-dir="/home/username/.kube/cache" Répertoire de cache par défaut

--certificate-authority="" Chemin vers un fichier de certificat pour l'autorité de certification

--client-certificate="" Chemin vers un fichier de certificat client pour TLS

--client-key="" Chemin vers un fichier de clé client pour TLS

--cluster="" Nom du cluster kubeconfig à utiliser

--context="" Nom du contexte kubeconfig à utiliser

--disable-compression=false Si vrai, désactiver la compression des réponses pour toutes les requêtes vers le serveur

--insecure-skip-tls-verify=false Si vrai, le certificat du serveur ne sera pas vérifié quant à sa validité. Cela rendra vos connexions HTTPS non sécurisées

--kubeconfig="" Chemin vers le fichier kubeconfig à utiliser pour les requêtes CLI.

--kuberc="" Chemin vers le fichier kuberc à utiliser pour les préférences. Ceci peut être désactivé en exportant `KUBECTL_KUBERC=false` gate de fonctionnalité ou en désactivant la fonctionnalité `KUBERC=off`.

--match-server-version=false Exiger que la version du serveur corresponde à la version du client

-n, --namespace="" Si présent, le scope du namespace pour cette requête CLI

--password="" Mot de passe pour l'authentification de base auprès du serveur API

--profile="none" Nom du profil à capturer. L'un des suivants (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nom du fichier dans lequel écrire le profil

--request-timeout="0" Durée d'attente avant d'abandonner une seule requête serveur. Les valeurs non nulles doivent contenir une unité de temps correspondante (par exemple, 1s, 2m, 3h). Une valeur de zéro signifie ne pas expirer les requêtes.

-s, --server="" L'adresse et le port du serveur API Kubernetes

--tls-server-name="" Nom du serveur à utiliser pour la validation du certificat serveur. S'il n'est pas fourni, le nom d'hôte utilisé pour contacter le serveur est utilisé

--token="" Jeton porteur pour l'authentification auprès du serveur API

--user="" Nom de l'utilisateur kubeconfig à utiliser

--username="" Nom d'utilisateur pour l'authentification de base auprès du serveur API

--version=false --version, --version=raw affiche les informations de version et quitte ; --version=vX.Y.Z... définit la version signalée

--warnings-as-errors=false Traiter les avertissements reçus du serveur comme des erreurs et quitter avec un code de sortie non nul

EXEMPLE

  # Crée un déploiement nommé my-dep qui exécute l'image busybox
  kubectl create deployment my-dep --image=busybox
  # Crée un déploiement avec une commande
  kubectl create deployment my-dep --image=busybox -- date
  # Crée un déploiement nommé my-dep qui exécute l'image nginx avec 3 répliques
  kubectl create deployment my-dep --image=nginx --replicas=3
  # Crée un déploiement nommé my-dep qui exécute l'image busybox et expose le port 5701
  kubectl create deployment my-dep --image=busybox --port=5701
  # Crée un déploiement nommé my-dep qui exécute plusieurs conteneurs
  kubectl create deployment my-dep --image=busybox:latest --image=ubuntu:latest --image=nginx
