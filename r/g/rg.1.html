RG(1) Commandes utilisateur RG(1)

NOM

rg - recherche récursivement dans le répertoire courant les lignes correspondant à un motif

SYNTAXE

rg [OPTIONS] MOTIF [CHEMIN...]

rg [OPTIONS] -e MOTIF... [CHEMIN...]

rg [OPTIONS] -f FICHIERMOTIF... [CHEMIN...]

rg [OPTIONS] --files [CHEMIN...]

rg [OPTIONS] --type-list

commande | rg [OPTIONS] MOTIF

rg [OPTIONS] --help

rg [OPTIONS] --version

DESCRIPTION

ripgrep (rg) recherche récursivement dans le répertoire courant un motif regex. Par défaut, ripgrep respecte votre .gitignore et ignore automatiquement les fichiers/répertoires cachés et les fichiers binaires.

Le moteur regex par défaut de ripgrep utilise des automates finis et garantit une recherche en temps linéaire. Pour cette raison, des fonctionnalités telles que les références arrière et le look-around arbitraire ne sont pas prises en charge. Cependant, si ripgrep est compilé avec PCRE2, l'option -P/--pcre2 peut être utilisée pour activer les références arrière et le look-around.

ripgrep prend en charge les fichiers de configuration. Définissez RIPGREP_CONFIG_PATH sur un fichier de configuration. Le fichier peut spécifier un argument shell par ligne. Les lignes commençant par # sont ignorées. Pour plus de détails, voir FICHIERS DE CONFIGURATION ci-dessous.

ripgrep détectera automatiquement si l'entrée standard est un fichier lisible et recherchera dans l'entrée standard un motif regex, par exemple ls | rg foo. Dans certains environnements, l'entrée standard peut exister alors qu'elle ne le devrait pas. Pour désactiver la détection de l'entrée standard, on peut explicitement spécifier le répertoire à rechercher, par exemple rg foo ./.

Comme d'autres outils tels que ls, ripgrep modifiera sa sortie en fonction de si la sortie standard est connectée à un tty. Par défaut, lors de l'affichage d'un tty, ripgrep activera les couleurs, les numéros de ligne et un format d'en-tête qui liste chaque chemin de fichier correspondant une fois au lieu d'une fois par ligne correspondante.

Astuce : pour désactiver tout filtrage intelligent et faire en sorte que ripgrep se comporte un peu plus comme grep classique, utilisez rg -uuu.

SYNTAXE REGEX

ripgrep utilise le moteur regex de Rust par défaut, qui documente sa syntaxe : https://docs.rs/regex/1.*/regex/#syntax

ripgrep utilise des expressions régulières orientées octets, qui disposent d'une documentation supplémentaire : https://docs.rs/regex/1.*/regex/bytes/index.html#syntax

À première approximation, ripgrep utilise des regex de type Perl sans look-around ni références arrière. Cela les rend très similaires aux expressions régulières « étendues » (ERE) prises en charge par *egrep*, mais avec quelques fonctionnalités supplémentaires comme les classes de caractères Unicode.

Si vous utilisez ripgrep avec l'option -P/--pcre2, veuillez consulter https://www.pcre.org ou les pages man de PCRE2 pour la documentation sur la syntaxe prise en charge.

ARGUMENTS POSITIONNELS

MOTIF
Une expression régulière utilisée pour la recherche. Pour faire correspondre un motif commençant par un trait d'union, utilisez l'option -e/--regexp.
CHEMIN
Un fichier ou un répertoire à rechercher. Les répertoires sont recherchés récursivement. Les chemins de fichiers spécifiés explicitement sur la ligne de commande remplacent les règles de glob et d'ignorance.

OPTIONS

Cette section documente tous les drapeaux que ripgrep accepte. Les drapeaux sont regroupés en catégories ci-dessous selon leur fonction.

Notez que de nombreuses options peuvent être activées et désactivées. Dans certains cas, ces drapeaux ne sont pas listés explicitement ci-dessous. Par exemple, le drapeau --column (listé ci-dessous) active les numéros de colonne dans la sortie de ripgrep, mais le drapeau --no-column (non listé ci-dessous) les désactive. L'inverse peut également exister. Par exemple, le drapeau --no-ignore (listé ci-dessous) désactive la logique gitignore de ripgrep, mais le drapeau --ignore (non listé ci-dessous) l'active. Ces drapeaux sont utiles pour remplacer un fichier de configuration ripgrep (ou un alias) en ligne de commande. La documentation de chaque drapeau indique si un drapeau inversé existe. Dans tous les cas, le dernier drapeau spécifié a priorité.

OPTIONS D'ENTRÉE

-e MOTIF, --regexp=MOTIF

Un motif à rechercher. Cette option peut être fournie plusieurs fois, où tous les motifs donnés sont recherchés, en plus de tous les motifs fournis par -f/--file. Les lignes correspondant à au moins un des motifs fournis sont imprimées. Ce drapeau peut également être utilisé lors de la recherche de motifs commençant par un trait d'union.

Par exemple, pour rechercher le littéral -foo :

    rg -e -foo

Vous pouvez également utiliser le délimiteur spécial -- pour indiquer qu'aucun autre drapeau ne sera fourni. Notamment, ce qui suit est équivalent à ce qui précède :

    rg -- -foo

Lorsque -f/--file ou -e/--regexp est utilisé, ripgrep traite tous les arguments positionnels comme des fichiers ou des répertoires à rechercher.

-f FICHIERMOTIF, --file=FICHIERMOTIF

Recherche les motifs à partir du fichier donné, avec un motif par ligne. Lorsque ce drapeau est utilisé plusieurs fois ou en combinaison avec le drapeau -e/--regexp, tous les motifs fournis sont recherchés. Les lignes de motif vides correspondent à toutes les lignes d'entrée, et le saut de ligne n'est pas compté comme faisant partie du motif.

Une ligne est imprimée si et seulement si elle correspond à au moins un des motifs.

Lorsque FICHIERMOTIF est -, l'entrée standard sera lue pour les motifs.

Lorsque -f/--file ou -e/--regexp est utilisé, ripgrep traite tous les arguments positionnels comme des fichiers ou des répertoires à rechercher.

--pre=COMMANDE

Pour chaque CHEMIN d'entrée, ce drapeau oblige ripgrep à rechercher la sortie standard de COMMANDE CHEMIN au lieu du contenu de CHEMIN. Cette option attend que le programme COMMANDE soit un chemin ou qu'il soit disponible dans votre PATH. Soit une chaîne vide COMMANDE, soit le drapeau --no-pre désactivera ce comportement.
AVERTISSEMENT
Lorsque ce drapeau est défini, ripgrep lancera inconditionnellement un processus pour chaque fichier recherché. Par conséquent, cela peut entraîner une pénalité de performance inutile si vous n'avez pas autrement besoin de la flexibilité offerte par ce drapeau. Une atténuation possible est d'utiliser le drapeau --pre-glob pour limiter les fichiers sur lesquels un préprocesseur est exécuté.

Un préprocesseur n'est pas exécuté lorsque ripgrep recherche l'entrée standard.

Lors de la recherche sur des ensembles de fichiers qui peuvent nécessiter un ou plusieurs préprocesseurs, COMMANDE doit être un programme wrapper qui classe d'abord le CHEMIN en fonction des numéros magiques/du contenu ou du nom du CHEMIN, puis se dispatche vers un préprocesseur approprié. Chaque COMMANDE a également son entrée standard connectée au CHEMIN pour plus de commodité.

Par exemple, un script shell pour COMMANDE pourrait ressembler à ceci :

    case "$1" in
    *.pdf)
        exec pdftotext "$1" -
        ;;
    *)
        case $(file "$1") in
        *Zstandard*)
            exec pzstd -cdq
            ;;
        *)
            exec cat
            ;;
        esac
        ;;
    esac

Le script ci-dessus utilise pdftotext pour convertir un fichier PDF en texte brut. Pour tous les autres fichiers, le script utilise l'utilitaire file pour identifier le type de fichier en fonction de son contenu. S'il s'agit d'un fichier compressé au format Zstandard, alors pzstd est utilisé pour décompresser le contenu vers la sortie standard.

Ceci remplace le drapeau -z/--search-zip.

--pre-glob=GLOB

Ce drapeau fonctionne en conjonction avec le drapeau --pre. À savoir, lorsque un ou plusieurs drapeaux --pre-glob sont donnés, seuls les fichiers qui correspondent aux ensembles de globs donnés seront transmis à la commande spécifiée par le drapeau --pre. Tous les fichiers non correspondants seront recherchés sans utiliser la commande de préprocesseur.

Ce drapeau est utile lors de la recherche de nombreux fichiers avec le drapeau --pre. À savoir, il offre la possibilité d'éviter la surcharge de processus pour les fichiers qui n'ont pas besoin de préprocesseur.

    #!/bin/sh
    pdftotext "$1" -

il est alors possible d'utiliser --pre pre-pdftotext --pre-glob '*.pdf' pour que ripgrep n'exécute la commande pre-pdftotext que sur les fichiers avec une extension .pdf.

Plusieurs indicateurs --pre-glob peuvent être utilisés. Les règles de globbing correspondent aux globes gitignore. Précédez un globe d'un ! pour l'exclure.

Cet indicateur n'a aucun effet si l'indicateur --pre n'est pas utilisé.

-z, --search-zip

Cet indicateur indique à ripgrep de rechercher dans les fichiers compressés. Actuellement, les fichiers gzip, bzip2, xz, LZ4, LZMA, Brotli et Zstd sont pris en charge. Cette option s'attend à ce que les binaires de décompression (tels que gzip) soient disponibles dans votre PATH. Si les binaires requis ne sont pas trouvés, ripgrep n'émettra pas de messages d'erreur par défaut. Utilisez l'indicateur --debug pour plus d'informations.

Notez que cet indicateur ne fait pas rechercher à ripgrep les formats d'archive comme des arbres de répertoires. Il ne fait que détecter les fichiers compressés puis les décompresser avant de rechercher leur contenu, comme il le ferait pour tout autre fichier.

Ceci remplace l'indicateur --pre.

Cet indicateur peut être désactivé avec --no-search-zip.

OPTIONS DE RECHERCHE

-s, --case-sensitive

Exécute la recherche en tenant compte de la casse. C'est le mode par défaut.

C'est une option globale qui s'applique à tous les motifs fournis à ripgrep. Les motifs individuels peuvent toujours être mis en correspondance sans tenir compte de la casse en utilisant des indicateurs d'expression régulière en ligne. Par exemple, (?i)abc correspondra à abc sans tenir compte de la casse, même lorsque cet indicateur est utilisé.

Cet indicateur remplace les indicateurs -i/--ignore-case et -S/--smart-case.

--crlf

Lorsqu'il est activé, ripgrep traitera CRLF (\r\n) comme un terminateur de ligne au lieu de simplement \n.

Principalement, cela permet aux assertions d'ancrage de ligne ^ et $ dans les motifs d'expression régulière de traiter CRLF, CR ou LF comme des terminateurs de ligne au lieu de simplement LF. Notez qu'ils ne correspondront jamais entre un CR et un LF. CRLF est traité comme un seul terminateur de ligne.

Lors de l'utilisation du moteur d'expression régulière par défaut, le support CRLF peut également être activé à l'intérieur du motif avec l'indicateur R. Par exemple, (?R:$) correspondra juste avant CR ou LF, mais jamais entre CR et LF.

Cet indicateur remplace --null-data.

Cet indicateur peut être désactivé avec --no-crlf.

--dfa-size-limit=NUM+SUFFIX?

La limite supérieure de la taille du DFA d'expression régulière. La limite par défaut est généreuse pour n'importe quel motif unique ou pour de nombreux motifs de petite taille. Ceci ne devrait être modifié que pour des entrées d'expression régulière très volumineuses où le moteur d'expression régulière (plus lent) de secours pourrait autrement être utilisé si la limite est atteinte.

Le format d'entrée accepte les suffixes de K, M ou G qui correspondent respectivement aux kilo-octets, méga-octets et giga-octets. Si aucun suffixe n'est fourni, l'entrée est traitée comme des octets.

-E ENCODING, --encoding=ENCODING

Spécifie l'encodage du texte que ripgrep utilisera sur tous les fichiers recherchés. La valeur par défaut est auto, ce qui amène ripgrep à effectuer une détection automatique de l'encodage au mieux pour chaque fichier. La détection automatique dans ce cas ne s'applique qu'aux fichiers qui commencent par une marque d'ordre des octets (BOM) UTF-8 ou UTF-16. Aucune autre détection automatique n'est effectuée. On peut également spécifier none qui désactivera alors complètement la détection de BOM et recherchera toujours les octets bruts, y compris une BOM si elle est présente, quel que soit son encodage.

D'autres valeurs prises en charge peuvent être trouvées dans la liste des étiquettes ici : https://encoding.spec.whatwg.org/#concept-encoding-get.

Pour plus de détails sur l'encodage et la manière dont ripgrep le gère, voir GUIDE.md.

La détection d'encodage utilisée par ripgrep peut être rétablie en mode automatique via l'indicateur --no-encoding.

--engine=ENGINE

Spécifie quel moteur d'expression régulière utiliser. Lorsque vous choisissez un moteur d'expression régulière, ce choix s'applique à chaque expression régulière fournie à ripgrep (par exemple, via plusieurs indicateurs -e/--regexp ou -f/--file).

Les valeurs acceptées sont default, pcre2, ou auto.

La valeur par défaut est default, qui est généralement le plus rapide et devrait convenir à la plupart des cas d'utilisation. Le moteur pcre2 est généralement utile lorsque vous souhaitez utiliser des fonctionnalités telles que les lookarounds ou les références arrière. auto choisira dynamiquement entre les moteurs d'expression régulière pris en charge en fonction des fonctionnalités utilisées dans un motif, au mieux.

Notez que le moteur pcre2 est une fonctionnalité optionnelle de ripgrep. Si PCRE2 n'était pas inclus dans votre build de ripgrep, alors l'utilisation de cet indicateur entraînera l'affichage d'un message d'erreur par ripgrep et sa sortie.

Ceci remplace les utilisations précédentes des indicateurs -P/--pcre2 et --auto-hybrid-regex.

-F, --fixed-strings

Traite tous les motifs comme des littéraux plutôt que comme des expressions régulières. Lorsque cet indicateur est utilisé, les caractères spéciaux méta d'expression régulière tels que .(){}*+ n'ont pas besoin d'être échappés.

Cet indicateur peut être désactivé avec --no-fixed-strings.

-i, --ignore-case

Lorsque cet indicateur est fourni, tous les motifs seront recherchés sans tenir compte de la casse. Les règles d'insensibilité à la casse utilisées par le moteur d'expression régulière par défaut de ripgrep sont conformes aux règles de mise en correspondance des cas "simples" de Unicode.

C'est une option globale qui s'applique à tous les motifs fournis à ripgrep. Les motifs individuels peuvent toujours être mis en correspondance en tenant compte de la casse en utilisant des indicateurs d'expression régulière en ligne. Par exemple, (?-i)abc correspondra à abc en tenant compte de la casse, même lorsque cet indicateur est utilisé.

Cet indicateur remplace -s/--case-sensitive et -S/--smart-case.

-v, --invert-match

Cet indicateur inverse la mise en correspondance. C'est-à-dire, au lieu d'afficher les lignes qui correspondent, ripgrep affichera les lignes qui ne correspondent pas.

Notez que cela inverse uniquement la mise en correspondance ligne par ligne. Par exemple, combiner cet indicateur avec -l/--files-with-matches émettra les fichiers qui contiennent des lignes ne correspondant pas aux motifs donnés. Ce n'est pas la même chose que, par exemple, --files-without-match, qui émettra les fichiers qui ne contiennent aucune ligne correspondante.

Cet indicateur peut être désactivé avec --no-invert-match.

-x, --line-regexp

Lorsqu'il est activé, ripgrep ne montrera que les correspondances entourées de limites de ligne. Ceci est équivalent à entourer chaque motif de ^ et $. En d'autres termes, cela n'affiche que les lignes où la ligne entière participe à une correspondance.

Ceci remplace l'indicateur -w/--word-regexp.

-m NUM, --max-count=NUM

Limite le nombre de lignes correspondantes par fichier recherché à NUM.

Lorsque -U/--multiline est utilisé, une seule correspondance qui s'étend sur plusieurs lignes n'est comptée qu'une fois pour les besoins de cette limite. Les correspondances multiples sur une seule ligne ne sont comptées qu'une fois, comme elles le seraient en mode non multiligne.

Lorsqu'il est combiné avec -A/--after-context ou -C/--context, il est possible que plus de correspondances que le maximum soient affichées si les lignes contextuelles contiennent une correspondance.

Notez que 0 est une valeur légale mais peu susceptible d'être utile. Lorsqu'elle est utilisée, ripgrep ne recherchera rien.

--mmap

Lorsqu'il est activé, ripgrep recherchera en utilisant des memory maps lorsque cela est possible. Ceci est activé par défaut lorsque ripgrep pense que ce sera plus rapide.

La recherche par memory map ne peut pas être utilisée dans toutes les circonstances. Par exemple, lors de la recherche de fichiers virtuels ou de flux comme stdin. Dans de tels cas, les memory maps ne seront pas utilisées même lorsque cet indicateur est activé.

Notez que ripgrep peut s'arrêter de manière inattendue lorsque des memory maps sont utilisées s'il recherche un fichier qui est simultanément tronqué. Les utilisateurs peuvent se soustraire à cette possibilité en désactivant les memory maps.

Cet indicateur peut être désactivé avec --no-mmap.

-U, --multiline

Cet indicateur active la recherche sur plusieurs lignes.

Lorsque le mode multiligne est activé, ripgrep lèvera la restriction selon laquelle une correspondance ne peut pas inclure un terminateur de ligne. Par exemple, lorsque le mode multiligne n'est pas activé (par défaut), alors l'expression régulière \p{any} correspondra à n'importe quel point de code Unicode autre que \n. De même, l'expression régulière \n est explicitement interdite, et si vous essayez de l'utiliser, ripgrep renverra une erreur. Cependant, lorsque le mode multiligne est activé, \p{any} correspondra à n'importe quel point de code Unicode, y compris \n, et les expressions régulières comme \n sont permises.

Une mise en garde importante est que le mode multiligne ne modifie pas les sémantiques de correspondance de .. À savoir, dans la plupart des moteurs d'expression régulière, un . correspondra par défaut à tout caractère sauf \n, et c'est également le cas dans ripgrep. Afin de faire correspondre . à \n, vous devez activer l'indicateur "dot all" à l'intérieur de l'expression régulière. Par exemple, (?s). et (?s:.) ont les mêmes sémantiques, où . correspondra à n'importe quel caractère, y compris \n. Alternativement, l'indicateur --multiline-dotall peut être passé pour faire du comportement "dot all" le comportement par défaut. Cet indicateur ne s'applique que lorsque la recherche multiligne est activée.

Il n'y a aucune limite au nombre de lignes qu'une seule correspondance peut couvrir.

AVERTISSEMENT : En raison de la manière dont le moteur d'expression régulière sous-jacent fonctionne, les recherches multilignes peuvent être plus lentes que les recherches normales orientées ligne, et elles peuvent également utiliser plus de mémoire. En particulier, lorsque le mode multiligne est activé, ripgrep exige que chaque fichier qu'il recherche soit disposé de manière contiguë en mémoire (soit en le lisant dans le tas, soit en le mappant en mémoire). Les choses qui ne peuvent pas être mappées en mémoire (comme stdin) seront consommées jusqu'à la fin de fichier avant que la recherche puisse commencer. En général, ripgrep ne fera ces choses que lorsque cela est nécessaire. Spécifiquement, si l'indicateur -U/--multiline est fourni mais que l'expression régulière ne contient pas de motifs qui correspondraient aux caractères \n, alors ripgrep évitera automatiquement de lire chaque fichier en mémoire avant de le rechercher. Néanmoins, si vous ne vous souciez que des correspondances couvrant au plus une ligne, il est toujours préférable de désactiver le mode multiligne.

Ceci remplace l'indicateur --stop-on-nonmatch.

Cet indicateur peut être désactivé avec --no-multiline.

--multiline-dotall

Cet indicateur active le mode "dot all" dans tous les motifs d'expression régulière. Cela fait que . correspond aux terminateurs de ligne lorsque la recherche multiligne est activée. Ceci flag n'a aucun effet si la recherche multiligne n'est pas activée avec le drapeau -U/--multiline.

Normalement, un . correspondra à n'importe quel caractère, à l'exception des terminateurs de ligne. Bien que ce comportement ne soit généralement pas pertinent pour la recherche orientée ligne (car les correspondances ne peuvent s'étendre que sur une seule ligne), il peut être utile lors de la recherche avec le drapeau -U/--multiline. Par défaut, le mode multiligne s'exécute sans le mode "point all" activé.

Ce drapeau est généralement destiné à être utilisé dans un alias ou dans votre fichier de configuration ripgrep si vous préférez la sémantique "point all" par défaut. Notez que, que ce drapeau soit utilisé ou non, la sémantique "point all" peut toujours être contrôlée via des drapeaux en ligne dans le motif regex lui-même, par exemple, (?s:.) active toujours "point all" tandis que (?-s:.) désactive toujours "point all". De plus, vous pouvez utiliser des classes de caractères comme \p{any} pour faire correspondre n'importe quel point de code Unicode, que le mode "point all" soit activé ou non.

Ce drapeau peut être désactivé avec --no-multiline-dotall.

--no-unicode

Ce drapeau désactive le mode Unicode pour tous les motifs donnés à ripgrep.

Par défaut, ripgrep active le "mode Unicode" dans toutes ses expressions régulières. Cela a un certain nombre de conséquences :

  • . ne correspondra qu'aux valeurs scalaires Unicode valides encodées en UTF-8.
  • Les classes comme \w, \s, \d sont toutes conscientes de l'Unicode et beaucoup plus grandes que leurs versions ASCII uniquement.
  • La recherche insensible à la casse utilisera le repliement de casse Unicode.
  • Un grand nombre de classes comme \p{Emoji} sont disponibles. (Bien que l'ensemble spécifique de classes disponibles varie en fonction du moteur regex. En général, le moteur regex par défaut dispose de plus de classes.)
  • Les limites de mots (\b et \B) utilisent la définition Unicode d'un caractère de mot.

Dans certains cas, il peut être souhaitable de désactiver ces options. Ce drapeau fera exactement cela. Par exemple, le mode Unicode peut parfois avoir un impact négatif sur les performances, en particulier lorsque des éléments comme \w sont utilisés fréquemment (y compris via des répétitions bornées comme \w{100}) alors que seule leur interprétation ASCII est nécessaire.

Ce drapeau peut être désactivé avec --unicode.

--null-data

L'activation de ce drapeau amène ripgrep à utiliser NUL comme terminateur de ligne au lieu de la valeur par défaut \n.

Ceci est utile lorsque vous recherchez de gros fichiers binaires qui auraient autrement des lignes très longues si \n était utilisé comme terminateur de ligne. En particulier, ripgrep exige qu'au minimum, chaque ligne tienne en mémoire. L'utilisation de NUL à la place peut être une solution utile pour maintenir les exigences de mémoire faibles et éviter les conditions de "out of memory" (OOM).

Ceci est également utile pour traiter des données délimitées par NUL, telles que celles émises lors de l'utilisation du drapeau -0/--null de ripgrep ou du drapeau --print0 de find.

L'utilisation de ce drapeau implique -a/--text. Il remplace également --crlf.

-P, --pcre2

Lorsque ce drapeau est présent, ripgrep utilisera le moteur regex PCRE2 au lieu de son moteur regex par défaut.

Ceci est généralement utile lorsque vous souhaitez utiliser des fonctionnalités telles que le look-around ou les références arrière.

L'utilisation de ce drapeau équivaut à passer --engine=pcre2. Les utilisateurs peuvent plutôt choisir d'utiliser --engine=auto pour demander à ripgrep de sélectionner automatiquement le bon moteur regex en fonction des motifs donnés. Ce drapeau et le drapeau --engine se remplacent mutuellement.

Notez que PCRE2 est une fonctionnalité optionnelle de ripgrep. Si PCRE2 n'a pas été inclus dans votre compilation de ripgrep, alors l'utilisation de ce drapeau entraînera l'affichage d'un message d'erreur par ripgrep et sa sortie. PCRE2 peut également avoir une expérience utilisateur moins bonne dans certains cas, car il dispose de moins d'API d'introspection que le moteur regex par défaut de ripgrep. Par exemple, si vous utilisez un \n dans une regex PCRE2 sans le drapeau -U/--multiline, ripgrep échouera silencieusement à trouver une correspondance au lieu de signaler immédiatement une erreur (comme il le fait avec le moteur regex par défaut).

Ce drapeau peut être désactivé avec --no-pcre2.

--regex-size-limit=NOMBRE+SUFFIXE?

La limite de taille de la regex compilée, où la regex compilée correspond généralement à un seul objet en mémoire qui peut faire correspondre tous les motifs fournis à ripgrep. La limite par défaut est suffisamment généreuse pour que la plupart des motifs raisonnables (ou même un petit nombre d'entre eux) rentrent.

Il est utile de changer cela lorsque vous souhaitez explicitement laisser ripgrep passer potentiellement beaucoup plus de temps et/ou de mémoire à construire un matcher regex.

Le format d'entrée accepte les suffixes K, M ou G qui correspondent respectivement aux kilooctets, mégaoctets et gigaoctets. Si aucun suffixe n'est fourni, l'entrée est traitée comme des octets.

-S, --smart-case

Ce drapeau indique à ripgrep de rechercher de manière insensible à la casse si le motif est entièrement en minuscules. Sinon, ripgrep recherchera de manière sensible à la casse.

Un motif est considéré comme entièrement en minuscules si les deux règles suivantes sont remplies :

  • Premièrement, le motif contient au moins un caractère littéral. Par exemple, a\w contient un littéral (a) mais \w seul n'en contient pas.
  • Deuxièmement, parmi les littéraux du motif, aucun d'entre eux n'est considéré comme une majuscule selon Unicode. Par exemple, foo\pL n'a pas de littéraux en majuscules mais Foo\pL en a.

Ceci remplace les drapeaux -s/--case-sensitive et -i/--ignore-case.

--stop-on-nonmatch

L'activation de cette option amène ripgrep à cesser de lire un fichier une fois qu'il rencontre une ligne non correspondante après avoir rencontré une ligne correspondante. Ceci est utile s'il est attendu que toutes les correspondances dans un fichier donné se trouvent sur des lignes séquentielles, par exemple en raison du tri des lignes.

Ceci remplace le drapeau -U/--multiline.

-a, --text

Ce drapeau indique à ripgrep de rechercher les fichiers binaires comme s'ils étaient du texte. Lorsque ce drapeau est présent, la détection des fichiers binaires par ripgrep est désactivée. Cela signifie que lorsqu'un fichier binaire est recherché, son contenu peut être imprimé s'il y a une correspondance. Cela peut provoquer l'impression de codes d'échappement qui modifient le comportement de votre terminal.

Lorsque la détection des fichiers binaires est activée, elle est imparfaite. En général, elle utilise une heuristique simple. Si un octet NUL est rencontré pendant la recherche, le fichier est considéré comme binaire et la recherche s'arrête (sauf si ce drapeau est présent). Alternativement, si le drapeau --binary est utilisé, ripgrep ne s'arrêtera que lorsqu'il verra un octet NUL après avoir vu une correspondance (ou s'il a recherché l'intégralité du fichier).

Ce drapeau remplace le drapeau --binary.

Ce drapeau peut être désactivé avec --no-text.

-j NOMBRE, --threads=NOMBRE

Ce drapeau définit le nombre approximatif de threads à utiliser. Une valeur de 0 (qui est la valeur par défaut) amène ripgrep à choisir le nombre de threads en utilisant des heuristiques.

-w, --word-regexp

Lorsqu'il est activé, ripgrep n'affichera que les correspondances entourées de limites de mots. Ceci est équivalent à entourer chaque motif de \b{moitié-début} et \b{moitié-fin}.

Ceci remplace le drapeau -x/--line-regexp.

--auto-hybrid-regex

OBSOLÈTE. Utilisez --engine à la place.

Lorsque ce drapeau est utilisé, ripgrep choisira dynamiquement parmi les moteurs regex pris en charge en fonction des fonctionnalités utilisées dans un motif. Lorsque ripgrep choisit un moteur regex, il applique ce choix pour chaque regex fournie à ripgrep (par exemple, via plusieurs drapeaux -e/--regexp ou -f/--file).

À titre d'exemple du comportement de ce drapeau, ripgrep tentera d'utiliser son moteur regex basé sur des automates finis par défaut chaque fois que le motif pourra être compilé avec succès avec ce moteur regex. Si PCRE2 est activé et si le motif donné n'a pas pu être compilé avec le moteur regex par défaut, alors PCRE2 sera automatiquement utilisé pour la recherche. Si PCRE2 n'est pas disponible, alors ce drapeau n'a aucun effet car il n'y a qu'un seul moteur regex parmi lequel choisir.

À l'avenir, ripgrep pourra ajuster ses heuristiques pour décider quel moteur regex utiliser. En général, les heuristiques seront limitées à une analyse statique des motifs, et non à un comportement d'exécution spécifique observé lors de la recherche de fichiers.

Le principal inconvénient de l'utilisation de ce drapeau est qu'il n'est pas toujours évident quel moteur regex ripgrep utilise, et par conséquent, la sémantique de correspondance ou le profil de performance de ripgrep peuvent subtilement et de manière inattendue changer. Cependant, dans de nombreux cas, tous les moteurs regex conviendront sur ce qui constitue une correspondance et il peut être agréable de prendre en charge de manière transparente des fonctionnalités regex plus avancées comme le look-around et les références arrière sans avoir besoin de les activer explicitement.

Ce drapeau peut être désactivé avec --no-auto-hybrid-regex.

--no-pcre2-unicode

OBSOLÈTE. Utilisez --no-unicode à la place.

Notez que le mode Unicode est activé par défaut.

Ce drapeau peut être désactivé avec --pcre2-unicode.

OPTIONS DE FILTRAGE

--binary

L'activation de ce drapeau amène ripgrep à rechercher les fichiers binaires. Par défaut, ripgrep tente d'ignorer automatiquement les fichiers binaires afin d'améliorer la pertinence des résultats et d'accélérer la recherche.

Les fichiers binaires sont détectés de manière heuristique en fonction de la présence ou non d'un octet NUL. Par défaut (sans ce drapeau activé), une fois qu'un octet NUL est rencontré, ripgrep arrête de rechercher dans le fichier. Habituellement, les octets NUL se trouvent au début de la plupart des fichiers binaires. Si un octet NUL apparaît après une correspondance, ripgrep n'affichera pas la correspondance, arrêtera de rechercher dans ce fichier et émettra un avertissement indiquant que certaines correspondances sont supprimées.

En revanche, lorsque ce drapeau est fourni, ripgrep continue de rechercher dans un fichier même si un octet NUL est trouvé. En particulier, si un octet NUL est trouvé, ripgrep continue de rechercher jusqu'à ce qu'une correspondance soit trouvée ou que la fin du fichier soit atteinte, selon la première éventualité. Si une correspondance est trouvée, ripgrep s'arrête et affiche un avertissement indiquant que la recherche s'est arrêtée prématurément.

Si vous souhaitez que ripgrep recherche un fichier sans aucun traitement spécial des octets NUL (et potentiellement imprimer des données binaires sur la sortie standard), vous devriez utiliser le drapeau -a/--text.

Le drapeau --binary est un drapeau pour contrôler le mécanisme de filtrage automatique de ripgrep. En tant que tel, il n'a pas besoin d'être utilisé lors de la recherche explicite d'un fichier ou lors de la recherche de l'entrée standard. C'est-à-dire qu'il n'est applicable que lors de la recherche récursive d'un répertoire.

Lorsque -u/--unrestricted

-b, --binary

This flag enables searching binary files. By default, ripgrep skips binary files. This flag can be used to search them.

If the -b/--binary flag is provided for a third time, then this flag is automatically enabled.

This flag overrides the -a/--text flag.

This flag can be disabled with --no-binary.

-L, --follow

This flag instructs ripgrep to follow symbolic links while traversing directories. This behavior is disabled by default. Note that ripgrep will check for symbolic link loops and report errors if it finds one. ripgrep will also report errors for broken links. To suppress error messages, use the --no-messages flag.

This flag can be disabled with --no-follow.

-g GLOB, --glob=GLOB

Include or exclude files and directories for searching that match the given glob. This always overrides any other ignore logic. Multiple glob flags may be used. Globbing rules match .gitignore globs. Precede a glob with a ! to exclude it. If multiple globs match a file or directory, the glob given later in the command line takes precedence.

As an extension, globs support specifying alternatives: -g 'ab{c,d}*' is equivalent to -g abc -g abd. Empty alternatives like -g 'ab{,c}' are not currently supported. Note that this syntax extension is also currently enabled in gitignore files, even though this syntax isn't supported by git itself. ripgrep may disable this syntax extension in gitignore files, but it will always remain available via the -g/--glob flag.

When this flag is set, every file and directory is applied to it to test for a match. For example, if you only want to search in a particular directory foo, then -g foo is incorrect because foo/bar does not match the glob foo. Instead, you should use -g 'foo/**'.

--glob-case-insensitive

Process all glob patterns given with the -g/--glob flag case insensitively. This effectively treats -g/--glob as --iglob.

This flag can be disabled with --no-glob-case-insensitive.

-., --hidden

Search hidden files and directories. By default, hidden files and directories are skipped. Note that if a hidden file or a directory is whitelisted in an ignore file, then it will be searched even if this flag isn't provided. Similarly if a hidden file or directory is given explicitly as an argument to ripgrep.

A file or directory is considered hidden if its base name starts with a dot character (.). On operating systems which support a "hidden" file attribute, like Windows, files with this attribute are also considered hidden.

Note that -./--hidden will include files and folders like .git regardless of --no-ignore-vcs. To exclude such paths when using -./--hidden, you must explicitly ignore them using another flag or ignore file.

This flag can be disabled with --no-hidden.

--iglob=GLOB

Include or exclude files and directories for searching that match the given glob. This always overrides any other ignore logic. Multiple glob flags may be used. Globbing rules match .gitignore globs. Precede a glob with a ! to exclude it. If multiple globs match a file or directory, the glob given later in the command line takes precedence. Globs used via this flag are matched case insensitively.

--ignore-file=PATH

Specifies a path to one or more gitignore formatted rules files. These patterns are applied after the patterns found in .gitignore, .rgignore and .ignore are applied and are matched relative to the current working directory. That is, files specified via this flag have lower precedence than files automatically found in the directory tree. Multiple additional ignore files can be specified by using this flag repeatedly. When specifying multiple ignore files, earlier files have lower precedence than later files.

If you are looking for a way to include or exclude files and directories directly on the command line, then use -g/--glob instead.

--ignore-file-case-insensitive

Process ignore files (.gitignore, .ignore, etc.) case insensitively. Note that this comes with a performance penalty and is most useful on case insensitive file systems (such as Windows).

This flag can be disabled with --no-ignore-file-case-insensitive.

-d NUM, --max-depth=NUM

This flag limits the depth of directory traversal to NUM levels beyond the paths given. A value of 0 only searches the explicitly given paths themselves.

For example, rg --max-depth 0 dir/ is a no-op because dir/ will not be descended into. rg --max-depth 1 dir/ will search only the direct children of dir.

An alternative spelling for this flag is --maxdepth.

--max-filesize=NUM+SUFFIX?

Ignore files larger than NUM in size. This does not apply to directories.

The input format accepts suffixes of K, M or G which correspond to kilobytes, megabytes and gigabytes, respectively. If no suffix is provided the input is treated as bytes.

Examples: --max-filesize 50K or --max-filesize 80M.

--no-ignore

When set, ignore files such as .gitignore, .ignore and .rgignore will not be respected. This implies --no-ignore-dot, --no-ignore-exclude, --no-ignore-global, --no-ignore-parent and --no-ignore-vcs.

This does not imply --no-ignore-files, since --ignore-file is specified explicitly as a command line argument.

When given only once, the -u/--unrestricted flag is identical in behavior to this flag and can be considered an alias. However, subsequent -u/--unrestricted flags have additional effects.

This flag can be disabled with --ignore.

--no-ignore-dot

Don't respect filter rules from .ignore or .rgignore files.

This does not impact whether ripgrep will ignore files and directories whose names begin with a dot. For that, see the -./--hidden flag. This flag also does not impact whether filter rules from .gitignore files are respected.

This flag can be disabled with --ignore-dot.

--no-ignore-exclude

Don't respect filter rules from files that are manually configured for the repository. For example, this includes git's .git/info/exclude.

This flag can be disabled with --ignore-exclude.

--no-ignore-files

When set, any --ignore-file flags, even ones that come after this flag, are ignored.

This flag can be disabled with --ignore-files.

--no-ignore-global

Don't respect filter rules from ignore files that come from "global" sources such as git's core.excludesFile configuration option (which defaults to $HOME/.config/git/ignore).

This flag can be disabled with --ignore-global.

--no-ignore-parent

When this flag is set, filter rules from ignore files found in parent directories are not respected. By default, ripgrep will ascend the parent directories of the current working directory to look for any applicable ignore files that should be applied. In some cases this may not be desirable.

This flag can be disabled with --ignore-parent.

--no-ignore-vcs

When given, filter rules from source control ignore files (e.g., .gitignore) are not respected. By default, ripgrep respects git's ignore rules for automatic filtering. In some cases, it may not be desirable to respect the source control's ignore rules and instead only respect rules in .ignore or .rgignore.

Note that this flag does not directly affect the filtering of source control files or folders that start with a dot (.), like .git. These are affected by -./--hidden and its related flags instead.

This flag implies --no-ignore-parent for source control ignore files as well.

This flag can be disabled with --ignore-vcs.

--no-require-git

When this flag is given, source control ignore files such as .gitignore are respected even if no git repository is present.

By default, ripgrep will only respect filter rules from source control ignore files when ripgrep detects that the search is executed inside a source control repository. For example, when a .git directory is observed.

This flag relaxes the default restriction. For example, it might be useful when the contents of a git repository are stored or copied somewhere, but where the repository state is absent.

This flag can be disabled with --require-git.

--one-file-system

When enabled, ripgrep will not cross file system boundaries relative to where the search started from.

Note that this applies to each path argument given to ripgrep. For example, in the command

    rg --one-file-system /foo/bar /quux/baz

ripgrep will search both /foo/bar and /quux/baz even if they are on different file systems, but will not cross a file system boundary when traversing each path's directory tree.

This is similar to find's -xdev or -mount flag.

This flag can be disabled with --no-one-file-system.

-t TYPE, --type=TYPE

This flag limits ripgrep to searching files matching TYPE. Multiple -t/--type flags may be provided.

This flag supports the special value all, which will behave as if -t/--type was provided for every file type supported by ripgrep (including any custom file types). The end result is that --type=all causes ripgrep to search in "whitelist" mode, where it will only search files it recognizes via its type definitions.

Note that this flag has lower precedence than both the -g/--glob flag and any rules found in ignore files.

To see the list of available file types, use the --type-list flag.

-T TYPE, --type-not=TYPE

Do not search files matching TYPE. Multiple -T/--type-not flags may be provided. Use the --ty
pe-list indicateur pour lister tous les types disponibles.

Cet indicateur prend en charge la valeur spéciale all, qui se comportera comme si -T/--type-not avait été fourni pour chaque type de fichier pris en charge par ripgrep (y compris les types de fichiers personnalisés). Le résultat final est que --type-not=all fait que ripgrep recherche en mode "liste noire", où il ne recherchera que les fichiers non reconnus par ses définitions de type.

Pour voir la liste des types de fichiers disponibles, utilisez l'indicateur --type-list.

--type-add=TYPESPEC

Cet indicateur ajoute une nouvelle glob pour un type de fichier particulier. Une seule glob peut être ajoutée à la fois. Plusieurs indicateurs --type-add peuvent être fournis. Sauf si --type-clear est utilisé, les globs sont ajoutées à toutes les globs existantes définies à l'intérieur de ripgrep.

Notez que cela doit être passé à chaque invocation de ripgrep. Les paramètres de type ne sont pas persistants. Voir FICHIERS DE CONFIGURATION pour une solution de contournement.

Exemple :

    rg --type-add 'foo:*.foo' -tfoo MOTIF

Cet indicateur peut également être utilisé pour inclure des règles d'autres types avec la directive d'inclusion spéciale. La directive d'inclusion permet de spécifier un ou plusieurs autres noms de types (séparés par une virgule) qui ont été définis et leurs règles seront automatiquement importées dans le type spécifié. Par exemple, pour créer un type appelé src qui correspond aux fichiers C++, Python et Markdown, on peut utiliser :

    --type-add 'src:include:cpp,py,md'

Des règles glob supplémentaires peuvent toujours être ajoutées au type src en utilisant cet indicateur à nouveau :

    --type-add 'src:include:cpp,py,md' --type-add 'src:*.foo'

Notez que les noms de types doivent uniquement contenir des lettres ou des chiffres Unicode. Les caractères de ponctuation ne sont pas autorisés.

--type-clear=TYPE

Efface les globs de types de fichiers précédemment définies pour TYPE. Cela efface toutes les globs précédemment définies pour le TYPE, mais des globs peuvent être ajoutées après cet indicateur.

Notez que cela doit être passé à chaque invocation de ripgrep. Les paramètres de type ne sont pas persistants. Voir FICHIERS DE CONFIGURATION pour une solution de contournement.

-u, --unrestricted

Cet indicateur réduit le niveau de filtrage "intelligent". Des utilisations répétées (jusqu'à 3) réduisent encore plus le filtrage. Lorsqu'il est répété trois fois, ripgrep recherchera dans chaque fichier d'une arborescence de répertoires.

Un seul indicateur -u/--unrestricted équivaut à --no-ignore. Deux indicateurs -u/--unrestricted équivalent à --no-ignore -./--hidden. Trois indicateurs -u/--unrestricted équivalent à --no-ignore -./--hidden --binary.

Le seul filtrage que ripgrep effectue encore lorsque -uuu est donné est de sauter les liens symboliques et d'éviter d'afficher les correspondances des fichiers binaires. Les liens symboliques peuvent être suivis via l'indicateur -L/--follow, et les fichiers binaires peuvent être traités comme des fichiers texte via l'indicateur -a/--text.

OPTIONS DE SORTIE

-A NUM, --after-context=NUM

Affiche NUM lignes après chaque correspondance.

Cela remplace l'indicateur --passthru et remplace partiellement l'indicateur -C/--context.

-B NUM, --before-context=NUM

Affiche NUM lignes avant chaque correspondance.

Cela remplace l'indicateur --passthru et remplace partiellement l'indicateur -C/--context.

--block-buffered

Lorsqu'il est activé, ripgrep utilisera la mise en mémoire tampon par bloc. C'est-à-dire, chaque fois qu'une ligne correspondante est trouvée, elle sera écrite dans un tampon en mémoire et ne sera pas écrite sur la sortie standard tant que le tampon n'aura pas atteint une certaine taille. C'est le comportement par défaut lorsque la sortie standard de ripgrep est redirigée vers un pipeline ou un fichier. Lorsque la sortie standard de ripgrep est connectée à un tty, la mise en mémoire tampon par ligne sera utilisée par défaut. Forcer la mise en mémoire tampon par bloc peut être utile lors du déchargement d'une grande quantité de contenu vers un tty.

Cela remplace l'indicateur --line-buffered.

Cet indicateur peut être désactivé avec --no-block-buffered.

-b, --byte-offset

Affiche le décalage en octets (base 0) dans le fichier d'entrée avant chaque ligne de sortie. Si -o/--only-matching est spécifié, affiche le décalage du texte correspondant lui-même.

Si ripgrep effectue un transcodage, le décalage en octets est en termes de résultat du transcodage et non des données d'origine. Ceci s'applique de manière similaire à d'autres transformations des données, telles que la décompression ou un filtre --pre.

Cet indicateur peut être désactivé avec --no-byte-offset.

--color=QUAND

Cet indicateur contrôle quand utiliser les couleurs. Le réglage par défaut est auto, ce qui signifie que ripgrep essaiera de deviner quand utiliser les couleurs. Par exemple, si ripgrep écrit sur un tty, il utilisera les couleurs, mais si la sortie est redirigée vers un fichier ou un tuyau, il supprimera la sortie couleur.

ripgrep supprimera la sortie couleur par défaut dans d'autres circonstances également. Celles-ci incluent, sans s'y limiter :

  • Lorsque la variable d'environnement TERM n'est pas définie ou est définie sur dumb.
  • Lorsque la variable d'environnement NO_COLOR est définie (quelle que soit sa valeur).
  • Lorsque des indicateurs qui impliquent qu'il n'y a pas d'utilisation pour les couleurs sont fournis. Par exemple, --vimgrep et --json.

Les valeurs possibles pour cet indicateur sont :

jamais
Les couleurs ne seront jamais utilisées.
auto
Par défaut. ripgrep essaie d'être intelligent.
toujours
Les couleurs seront toujours utilisées, quelle que soit la destination de la sortie.
ansi
Comme 'toujours', mais émet des séquences d'échappement ANSI (même dans une console Windows).

Cet indicateur contrôle également l'émission des hyperliens. Par exemple, lorsqu'un format d'hyperlien est spécifié, les hyperliens ne seront pas utilisés lorsque la couleur est supprimée. Si l'on souhaite émettre des hyperliens mais pas de couleurs, il faut utiliser l'indicateur --colors pour définir manuellement tous les styles de couleur sur none :

    --colors 'path:none' \
    --colors 'line:none' \
    --colors 'column:none' \
    --colors 'match:none' \
    --colors 'highlight:none'

--colors=SPEC_COULEUR

Cet indicateur spécifie les paramètres de couleur à utiliser dans la sortie. Cet indicateur peut être fourni plusieurs fois. Les paramètres sont appliqués itérativement. Les étiquettes de couleur préexistantes sont limitées à l'un des huit choix : red, blue, green, cyan, magenta, yellow, white et black. Les styles sont limités à nobold, bold, nointense, intense, nounderline, underline, noitalic ou italic.

Le format de l'indicateur est {type}:{attribut}:{valeur}. type doit être l'un de path, line, column, highlight ou match. attribut peut être fg, bg ou style. valeur est soit une couleur (pour fg et bg) soit un style de texte. Un format spécial, {type}:none, effacera tous les paramètres de couleur pour type.

Par exemple, la commande suivante changera la couleur de correspondance en magenta et la couleur de fond des numéros de ligne en jaune :

    rg --colors 'match:fg:magenta' --colors 'line:bg:yellow'

Autre exemple, la commande suivante "mettra en surbrillance" le texte non correspondant dans les lignes correspondantes :

    rg --colors 'highlight:bg:yellow' --colors 'highlight:fg:black'

Le type de couleur "highlight" est particulièrement utile pour contraster les lignes correspondantes avec le contexte environnant affiché par les indicateurs -B/--before-context, -A/--after-context, -C/--context ou --passthru.

Des couleurs étendues peuvent être utilisées pour valeur lorsque le tty prend en charge les séquences de couleurs ANSI. Celles-ci sont spécifiées comme x (couleur 256) ou x,x,x (truecolor 24 bits) où x est un nombre compris entre 0 et 255 inclus. x peut être donné comme un nombre décimal normal ou un nombre hexadécimal, préfixé par 0x.

Par exemple, la commande suivante changera la couleur de fond de correspondance à celle représentée par la valeur RVB (0, 128, 255) :

    rg --colors 'match:bg:0,128,255'

ou, de manière équivalente,

    rg --colors 'match:bg:0x0,0x80,0xFF'

Notez que les styles intense et nointense n'auront aucun effet lorsqu'ils sont utilisés avec ces codes de couleur étendus.

--column

Affiche les numéros de colonne (base 1). Cela n'affiche que les numéros de colonne pour la première correspondance sur chaque ligne. Cela n'essaie pas de tenir compte de l'Unicode. Un octet est égal à une colonne. Cela implique -n/--line-number.

Lorsque -o/--only-matching est utilisé, les numéros de colonne affichés correspondent au début de chaque correspondance.

Cet indicateur peut être désactivé avec --no-column.

-C NUM, --context=NUM

Affiche NUM lignes avant et après chaque correspondance. Ceci équivaut à fournir à la fois les indicateurs -B/--before-context et -A/--after-context avec la même valeur.

Cela remplace l'indicateur --passthru. Les indicateurs -A/--after-context et -B/--before-context remplacent tous deux partiellement cet indicateur, quel que soit l'ordre. Par exemple, -A2 -C1 équivaut à -A2 -B1.

--context-separator=SEPARATEUR

La chaîne utilisée pour séparer les lignes de contexte non contiguës dans la sortie. Ceci n'est utilisé que lorsqu'un des indicateurs de contexte est utilisé (c'est-à-dire, -A/--after-context, -B/--before-context ou -C/--context). Des séquences d'échappement comme \x7F ou \t peuvent être utilisées. La valeur par défaut est --.

Lorsque le séparateur de contexte est défini sur une chaîne vide, un saut de ligne est toujours inséré. Pour désactiver complètement les séparateurs de contexte, utilisez l'indicateur --no-context-separator.

--field-context-separator=SEPARATEUR

Définit le séparateur de contexte de champ. Ce séparateur est uniquement utilisé lors de l'affichage des lignes de contexte. Il est utilisé pour délimiter les chemins de fichiers, les numéros de ligne, les colonnes et la ligne de contexte elle-même. Le séparateur peut être n'importe quel nombre d'octets, y compris zéro. Des séquences d'échappement comme \x7F ou \t peuvent être utilisées.

Le caractère - est la valeur par défaut.

--field-match-separator=SEPARATEUR

Définit le séparateur de correspondance de champ. Ce séparateur est uniquement utilisé lors de l'affichage des lignes correspondantes. Il est utilisé pour délimiter les chemins de fichiers, les numéros de ligne, les col
Ensembles et la ligne correspondante elle-même. Le séparateur peut être n'importe quel nombre d'octets, y compris zéro. Les séquences d'échappement comme \x7F ou \t peuvent être utilisées.

Le caractère : est la valeur par défaut.

--heading

Ce drapeau imprime le chemin du fichier au-dessus des groupes de correspondances de chaque fichier au lieu d'imprimer le chemin du fichier comme préfixe pour chaque ligne correspondante.

C'est le mode par défaut lors de l'impression vers un tty.

Lorsque stdout n'est pas un tty, ripgrep utilisera par défaut le format standard de type grep. On peut forcer ce format dans les environnements Unix en redirigeant la sortie de ripgrep vers cat. Par exemple, rg foo | cat.

Ce drapeau peut être désactivé avec --no-heading.

-h, --help

Ce drapeau imprime la sortie d'aide pour ripgrep.

Contrairement à la plupart des autres drapeaux, le comportement du drapeau court, -h, et du drapeau long, --help, est différent. Le drapeau court affichera une aide condensée tandis que le drapeau long affichera une aide détaillée. L'aide détaillée contient la documentation complète, tandis que l'aide condensée n'affichera qu'une seule ligne pour chaque drapeau.

--hostname-bin=COMMANDE

Ce drapeau contrôle comment ripgrep détermine le nom d'hôte de ce système. La valeur du drapeau doit correspondre à un exécutable (soit un chemin, soit quelque chose qui peut être trouvé via la variable d'environnement PATH de votre système). Lorsqu'il est défini, ripgrep exécutera cet exécutable, sans arguments, et traitera sa sortie (avec les espaces blancs de début et de fin supprimés) comme le nom d'hôte de votre système.

Lorsqu'il n'est pas défini (par défaut, ou la chaîne vide), ripgrep essaiera de détecter automatiquement le nom d'hôte de votre système. Sur Unix, cela correspond à l'appel de gethostname. Sur Windows, cela correspond à l'appel de GetComputerNameExW pour récupérer le "nom d'hôte DNS physique" du système.

ripgrep utilise le nom d'hôte de votre système pour produire des hyperliens.

--hyperlink-format=FORMAT

Définit le format des hyperliens à utiliser lors de l'impression des résultats. Les hyperliens rendent certains éléments de la sortie de ripgrep, tels que les chemins de fichiers, cliquables. Cela ne fonctionne généralement que dans les émulateurs de terminaux qui prennent en charge les hyperliens OSC-8. Par exemple, le format file://{host}{path} émettra un hyperlien RFC 8089. Pour voir le format utilisé par ripgrep, passez le drapeau --debug.

Alternativement, une chaîne de format peut correspondre à l'un des alias suivants : default, none, cursor, file, grep+, kitty, macvim, textmate, vscode, vscode-insiders, vscodium. L'alias sera remplacé par une chaîne de format destinée à fonctionner pour l'application correspondante.

Les variables suivantes sont disponibles dans la chaîne de format :

{path}
Obligatoire. Ceci est remplacé par un chemin vers un fichier correspondant. Le chemin est garanti d'être absolu et encodé en pourcentage de manière à pouvoir être placé dans une URI. Notez qu'un chemin est garanti de commencer par un /.
{host}
Optionnel. Ceci est remplacé par le nom d'hôte de votre système. Sur Unix, cela correspond à l'appel de gethostname. Sur Windows, cela correspond à l'appel de GetComputerNameExW pour récupérer le "nom d'hôte DNS physique" du système. Alternativement, si --hostname-bin a été fourni, le nom d'hôte retourné par la sortie de ce programme sera retourné. Si aucun nom d'hôte n'a pu être trouvé, cette variable est remplacée par une chaîne vide.
{line}
Optionnel. Si approprié, ceci est remplacé par le numéro de ligne d'une correspondance. S'il n'y a pas de numéro de ligne disponible (par exemple, si --no-line-number a été donné), alors il est automatiquement remplacé par la valeur 1.
{column}
Optionnel, mais nécessite la présence de {line}. Si approprié, ceci est remplacé par le numéro de colonne d'une correspondance. S'il n'y a pas de numéro de colonne disponible (par exemple, si --no-column a été donné), alors il est automatiquement remplacé par la valeur 1.
{wslprefix}
Optionnel. C'est une valeur spéciale qui est définie sur wsl$/WSL_DISTRO_NAME, où WSL_DISTRO_NAME correspond à la valeur de la variable d'environnement équivalente. Si le système n'est pas Unix ou si la variable d'environnement WSL_DISTRO_NAME n'est pas définie, alors ceci est remplacé par une chaîne vide.

Une chaîne de format peut être vide. Une chaîne de format vide équivaut à l'alias none. Dans ce cas, les hyperliens seront désactivés.

Actuellement, ripgrep n'active pas les hyperliens par défaut. Les utilisateurs doivent y souscrire. Si vous n'êtes pas sûr du format à utiliser, essayez default.

Comme les couleurs, lorsque ripgrep détecte que stdout n'est pas connecté à un tty, les hyperliens sont automatiquement désactivés, quelle que soit la valeur de ce drapeau. Les utilisateurs peuvent passer --color=always pour forcer l'émission d'hyperliens.

Notez que les hyperliens ne sont écrits que lorsqu'un chemin est également présent dans la sortie et que les couleurs sont activées. Pour écrire des hyperliens sans couleurs, vous devrez configurer ripgrep pour ne rien coloriser sans désactiver complètement tous les codes d'échappement ANSI :

    --colors 'path:none' \
    --colors 'line:none' \
    --colors 'column:none' \
    --colors 'match:none'

ripgrep fonctionne ainsi car il traite le drapeau --color comme un proxy pour déterminer si les codes d'échappement ANSI doivent être utilisés ou non. Cela signifie que les variables d'environnement comme NO_COLOR=1 et TERM=dumb désactivent non seulement les couleurs, mais aussi les hyperliens. De même, les couleurs et les hyperliens sont désactivés lorsque ripgrep n'écrit pas vers un tty. (À moins que l'on ne force la question en réglant --color=always.)

Si vous recherchez directement un fichier, par exemple :

    rg foo chemin/vers/fichier

alors les hyperliens ne seront pas émis car le chemin donné n'apparaît pas dans la sortie. Pour faire apparaître le chemin, et donc aussi un hyperlien, utilisez le drapeau -H/--with-filename.

Pour plus d'informations sur les hyperliens dans les émulateurs de terminaux, voir : https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda

--include-zero

Lorsqu'il est utilisé avec -c/--count ou --count-matches, cela amène ripgrep à imprimer le nombre de correspondances pour chaque fichier même s'il y avait zéro correspondance. Ceci est désactivé par défaut mais peut être activé pour que ripgrep se comporte davantage comme grep.

Ce drapeau peut être désactivé avec --no-include-zero.

--line-buffered

Lorsqu'il est activé, ripgrep utilisera toujours la mise en mémoire tampon par ligne. C'est-à-dire que chaque fois qu'une ligne correspondante est trouvée, elle sera immédiatement vidée vers stdout. C'est le comportement par défaut lorsque le stdout de ripgrep est connecté à un tty, mais sinon, ripgrep utilisera la mise en mémoire tampon par bloc, qui est généralement plus rapide. Ce drapeau force ripgrep à utiliser la mise en mémoire tampon par ligne même s'il utiliserait autrement la mise en mémoire tampon par bloc. C'est généralement utile dans les pipelines shell, par exemple : 
    tail -f something.log | rg foo --line-buffered | rg bar

Ceci remplace le drapeau --block-buffered.

Ce drapeau peut être désactivé avec --no-line-buffered.

-n, --line-number

Afficher les numéros de ligne (commençant à 1).

Ceci est activé par défaut lorsque stdout est connecté à un tty.

Ce drapeau peut être désactivé par -N/--no-line-number.

-N, --no-line-number

Supprimer les numéros de ligne.

Les numéros de ligne sont désactivés par défaut lorsque stdout n'est pas connecté à un tty.

Les numéros de ligne peuvent être activés de force par -n/--line-number.

-M NUM, --max-columns=NUM

Lorsqu'il est spécifié, ripgrep omettra les lignes plus longues que cette limite en octets. Au lieu d'imprimer les lignes longues, seul le nombre de correspondances dans cette ligne est imprimé.

Lorsque ce drapeau est omis ou défini sur 0, il n'a aucun effet.

--max-columns-preview

Imprime un aperçu des lignes dépassant la limite de colonnes configurée.

Lorsque le drapeau -M/--max-columns est utilisé, ripgrep remplacera par défaut complètement toute ligne trop longue par un message indiquant qu'une ligne correspondante a été supprimée. Lorsque ce drapeau est combiné avec -M/--max-columns, un aperçu de la ligne (correspondant à la limite de taille) est affiché à la place, où la partie de la ligne dépassant la limite n'est pas montrée.

Si le drapeau -M/--max-columns n'est pas défini, alors ceci n'a aucun effet.

Ce drapeau peut être désactivé avec --no-max-columns-preview.

-0, --null

Chaque fois qu'un chemin de fichier est imprimé, suivez-le d'un octet NUL. Cela inclut l'impression des chemins de fichiers avant les correspondances, et lors de l'impression d'une liste de fichiers correspondants comme avec -c/--count, -l/--files-with-matches et --files. Cette option est utile pour une utilisation avec xargs.

-o, --only-matching

Imprime uniquement les parties correspondantes (non vides) d'une ligne correspondante, avec chaque partie sur une ligne de sortie distincte.

--path-separator=SEPARATEUR

Définit le séparateur de chemin à utiliser lors de l'impression des chemins de fichiers. Par défaut, c'est le séparateur de chemin de votre plateforme, qui est / sur Unix et \ sur Windows. Ce drapeau est destiné à remplacer la valeur par défaut lorsque l'environnement l'exige (par exemple, cygwin). Un séparateur de chemin est limité à un seul octet.

Définir ce drapeau sur une chaîne vide le rétablit à son comportement par défaut. C'est-à-dire que le séparateur de chemin est automatiquement choisi en fonction de l'environnement.

--passthru

Imprime les lignes correspondantes et non correspondantes.

Une autre façon d'obtenir un effet similaire est de modifier votre motif pour correspondre à la chaîne vide. Par exemple, si vous recherchez avec rg foo, alors utiliser rg '^|foo' à la place émettra chaque ligne dans chaque fichier recherché, mais seules les occurrences de foo seront mises en surbrillance. Ce drapeau active le même comportement sans avoir besoin de modifier le motif.

Une orthographe alternative pour ce drapeau est --passthrough.

Ceci remplace les drapeaux -C/--context, -A/--after-context et -B/--before-context.

-p, --pretty

Ceci est un alias de commodité pour --color=always --heading --line-number. Ce drapeau est utile lorsque vous souhaitez toujours une sortie jolie, même si vous redirigez ripgrep vers un autre programme ou fichier. Par exemple : rg -p foo | less -R.

-q, --quiet

Ne rien imprimer sur stdout. Si une correspondance est trouvée dans un fichier, ripgrep s'arrêtera de chercher. Ceci est utile
lorsque ripgrep est utilisé uniquement pour son code de sortie (qui sera un code d'erreur si aucune correspondance n'est trouvée).

Lorsque --files est utilisé, ripgrep arrête de trouver des fichiers après avoir trouvé le premier fichier qui ne correspond à aucune règle d'ignorance.

-r REMPLACEMENT, --replace=REMPLACEMENT

Remplace chaque correspondance par le texte fourni lors de l'impression des résultats. Ni ce drapeau ni aucun autre drapeau de ripgrep ne modifiera vos fichiers.

Les indices de groupe de capture (par exemple, $5) et les noms (par exemple, $foo) sont pris en charge dans la chaîne de remplacement. Les indices de groupe de capture sont numérotés en fonction de la position de la parenthèse ouvrante du groupe, où le groupe le plus à gauche est $1. Le groupe spécial $0 correspond à la correspondance entière.

Le nom d'un groupe est formé en prenant la chaîne la plus longue de lettres, chiffres et underscores (c'est-à-dire [_0-9A-Za-z]) après le $. Par exemple, $1a sera remplacé par le groupe nommé 1a, et non par le groupe à l'indice 1. Si le nom du groupe contient des caractères qui ne sont pas des lettres, des chiffres ou des underscores, ou si vous souhaitez immédiatement suivre le groupe avec une autre chaîne, le nom doit être placé entre accolades. Par exemple, ${1}a prendra le contenu du groupe à l'indice 1 et ajoutera a à la fin.

Si un indice ou un nom ne fait pas référence à un groupe de capture valide, il sera remplacé par une chaîne vide.

Dans les shells comme Bash et zsh, vous devriez entourer le motif entre guillemets simples au lieu de guillemets doubles. Sinon, les indices de groupe de capture seront remplacés par des variables shell étendues qui seront très probablement vides.

Pour écrire un $ littéral, utilisez $$.

Notez que le remplacement remplace par défaut chaque correspondance, et non la ligne entière. Pour remplacer la ligne entière, vous devez faire correspondre la ligne entière.

Ce drapeau peut être utilisé avec le drapeau -o/--only-matching.

--sort=TRI PAR

Ce drapeau active le tri des résultats par ordre croissant. Les valeurs possibles pour ce drapeau sont :
none
(Défaut) Ne pas trier les résultats. Le plus rapide. Peut être multi-threadé.
path
Trier par chemin de fichier. Toujours mono-threadé. L'ordre est déterminé en triant les fichiers dans chaque entrée de répertoire lors du parcours. Cela signifie que, étant donné les fichiers a/b et a+, ce dernier sera trié après le premier même si + serait normalement trié avant /.
modified
Trier par l'heure de dernière modification d'un fichier. Toujours mono-threadé.
accessed
Trier par l'heure du dernier accès à un fichier. Toujours mono-threadé.
created
Trier par l'heure de création d'un fichier. Toujours mono-threadé.

Si le critère de tri choisi (manuellement ou par défaut) n'est pas disponible sur votre système (par exemple, l'heure de création n'est pas disponible sur les systèmes de fichiers ext4), ripgrep tentera de le détecter, d'afficher une erreur et de quitter sans effectuer de recherche.

Pour trier les résultats en ordre inverse ou décroissant, utilisez le drapeau --sortr. De plus, ce drapeau remplace --sortr.

Notez que le tri des résultats force actuellement ripgrep à abandonner le parallélisme et à s'exécuter en un seul thread.

--sortr=TRI PAR

Ce drapeau active le tri des résultats par ordre décroissant. Les valeurs possibles pour ce drapeau sont :
none
(Défaut) Ne pas trier les résultats. Le plus rapide. Peut être multi-threadé.
path
Trier par chemin de fichier. Toujours mono-threadé. L'ordre est déterminé en triant les fichiers dans chaque entrée de répertoire lors du parcours. Cela signifie que, étant donné les fichiers a/b et a+, ce dernier sera trié avant le premier même si + serait normalement trié après / lors d'un tri lexicographique inversé.
modified
Trier par l'heure de dernière modification d'un fichier. Toujours mono-threadé.
accessed
Trier par l'heure du dernier accès à un fichier. Toujours mono-threadé.
created
Trier par l'heure de création d'un fichier. Toujours mono-threadé.

Si le critère de tri choisi (manuellement ou par défaut) n'est pas disponible sur votre système (par exemple, l'heure de création n'est pas disponible sur les systèmes de fichiers ext4), ripgrep tentera de le détecter, d'afficher une erreur et de quitter sans effectuer de recherche.

Pour trier les résultats par ordre croissant, utilisez le drapeau --sort. De plus, ce drapeau remplace --sort.

Notez que le tri des résultats force actuellement ripgrep à abandonner le parallélisme et à s'exécuter en un seul thread.

--trim

Lorsqu'il est activé, tous les espaces blancs ASCII au début de chaque ligne imprimée seront supprimés.

Ce drapeau peut être désactivé avec --no-trim.

--vimgrep

Ce drapeau demande à ripgrep d'imprimer les résultats avec chaque correspondance sur sa propre ligne, y compris les numéros de ligne et les numéros de colonne.

Avec cette option, une ligne contenant plus d'une correspondance sera imprimée en entier, plusieurs fois. Pour cette raison, la quantité totale de sortie résultant de ce drapeau peut être quadratique par rapport à la taille de l'entrée. Par exemple, si le motif correspond à chaque octet d'un fichier d'entrée, alors chaque ligne sera répétée pour chaque octet correspondant. Pour cette raison, les utilisateurs ne devraient utiliser ce drapeau que lorsqu'il n'y a pas d'autre choix. Les intégrations d'éditeurs devraient préférer une autre méthode pour lire les résultats de ripgrep, par exemple via le drapeau --json. Une alternative pour éviter une consommation de mémoire exorbitante est de forcer ripgrep en mode mono-thread avec le drapeau -j/--threads. Notez cependant que cela n'affectera pas la taille totale de la sortie, seulement la mémoire du tas que ripgrep utilisera.

-H, --with-filename

Ce drapeau demande à ripgrep d'imprimer le chemin du fichier pour chaque ligne correspondante. C'est le comportement par défaut lorsque plusieurs fichiers sont recherchés. Si --heading est activé (par défaut lors de l'impression vers un tty), le chemin du fichier sera affiché au-dessus des groupes de correspondances de chaque fichier ; sinon, le nom du fichier sera affiché comme préfixe pour chaque ligne correspondante.

Ce drapeau remplace -I/--no-filename.

-I, --no-filename

Ce drapeau demande à ripgrep de ne jamais imprimer le chemin du fichier avec chaque ligne correspondante. C'est le comportement par défaut lorsque ripgrep est explicitement instruit de rechercher un seul fichier ou stdin.

Ce drapeau remplace -H/--with-filename.

--sort-files

OBSOLÈTE. Utilisez --sort=path à la place.

Ce drapeau demande à ripgrep de trier les résultats de recherche par chemin de fichier lexicographiquement par ordre croissant. Notez que cela désactive actuellement tout parallélisme et exécute la recherche en un seul thread.

Ce drapeau remplace --sort et --sortr.

Ce drapeau peut être désactivé avec --no-sort-files.

-c, --count

Ce drapeau supprime la sortie normale et affiche le nombre de lignes qui correspondent aux motifs donnés pour chaque fichier recherché. Chaque fichier contenant une correspondance a son chemin et son nombre imprimés sur chaque ligne. Notez que, à moins que -U/--multiline ne soit activé et que le(s) motif(s) donné(s) ne puisse(nt) correspondre sur plusieurs lignes, ceci indique le nombre de lignes qui correspondent et non le nombre total de correspondances. Lorsque le mode multiligne est activé et que le(s) motif(s) donné(s) peut (peuvent) correspondre sur plusieurs lignes, -c/--count est équivalent à --count-matches.

Si un seul fichier est donné à ripgrep, alors seul le compte est imprimé s'il y a une correspondance. Le drapeau -H/--with-filename peut être utilisé pour forcer l'impression du chemin du fichier dans ce cas. Si vous avez besoin qu'un compte soit imprimé, qu'il y ait une correspondance ou non, utilisez --include-zero.

Notez qu'il est possible que ce drapeau ait des résultats incohérents avec la sortie de -l/--files-with-matches. Notamment, par défaut, ripgrep essaie d'éviter de rechercher des fichiers contenant des données binaires. Avec ce drapeau, ripgrep doit rechercher l'intégralité du contenu des fichiers, ce qui peut inclure des données binaires. Mais avec -l/--files-with-matches, ripgrep peut s'arrêter dès qu'une correspondance est observée, ce qui peut survenir bien avant toute donnée binaire. Pour éviter cette incohérence sans désactiver la détection binaire, utilisez le drapeau --binary.

Ceci remplace le drapeau --count-matches. Notez que lorsque -c/--count est combiné avec -o/--only-matching, ripgrep se comporte comme si --count-matches était donné.

--count-matches

Ce drapeau supprime la sortie normale et affiche le nombre de correspondances individuelles des motifs donnés pour chaque fichier recherché. Chaque fichier contenant des correspondances a son chemin et son nombre de correspondances imprimés sur chaque ligne. Notez que ceci indique le nombre total de correspondances individuelles et non le nombre de lignes qui correspondent.

Si un seul fichier est donné à ripgrep, alors seul le compte est imprimé s'il y a une correspondance. Le drapeau -H/--with-filename peut être utilisé pour forcer l'impression du chemin du fichier dans ce cas.

Ceci remplace le drapeau -c/--count. Notez que lorsque -c/--count est combiné avec -o/--only-matching, ripgrep se comporte comme si --count-matches était donné.

-l, --files-with-matches

Imprimer uniquement les chemins contenant au moins une correspondance et supprimer le contenu des correspondances.

Notez qu'il est possible que ce drapeau ait des résultats incohérents avec la sortie de -c/--count. Notamment, par défaut, ripgrep essaie d'éviter de rechercher des fichiers contenant des données binaires. Avec ce drapeau, ripgrep peut arrêter la recherche avant que les données binaires ne soient observées. Mais avec -c/--count, ripgrep doit rechercher l'intégralité du contenu pour déterminer le nombre de correspondances, ce qui signifie qu'il peut rencontrer des données binaires qui le font ignorer la recherche de ce fichier. Pour éviter cette incohérence sans désactiver la détection binaire, utilisez le drapeau --binary.

Ceci remplace --files-without-match.

--files-without-match

Imprimer les chemins qui ne contiennent aucune correspondance et supprimer le contenu des correspondances.

Ceci remplace -l/--files-with-matches.

Chacun des types de filtrage peut être configuré via des indicateurs de ligne de commande :

  • Il existe plusieurs indicateurs commençant par --no-ignore qui permettent de contrôler quelles règles d'ignorance sont respectées. --no-ignore seul les désactivera toutes.
  • -./--hidden forcera ripgrep à rechercher dans les fichiers et répertoires cachés.
  • --binary forcera ripgrep à rechercher dans les fichiers binaires.
  • -L/--follow forcera ripgrep à suivre les liens symboliques.

En tant que raccourci spécial, l'indicateur -u peut être spécifié jusqu'à trois fois. Chaque fois supplémentaire diminue progressivement le filtrage :

  • -u équivaut à --no-ignore.
  • -uu équivaut à --no-ignore --hidden.
  • -uuu équivaut à --no-ignore --hidden --binary.

En particulier, rg -uuu devrait rechercher le même contenu exact que grep -r.

FICHIERS DE CONFIGURATION

ripgrep prend en charge la lecture de fichiers de configuration qui modifient le comportement par défaut de ripgrep. Le format du fichier de configuration est de style "rc" et est très simple. Il est défini par deux règles :

1.
Chaque ligne est un argument de shell, après suppression des espaces blancs.
2.
Les lignes commençant par # (éventuellement précédées d'une quantité quelconque d'espaces blancs) sont ignorées.

ripgrep recherchera un seul fichier de configuration si et seulement si la variable d'environnement RIPGREP_CONFIG_PATH est définie et non vide. ripgrep analysera les arguments de ce fichier au démarrage et se comportera comme si les arguments de ce fichier étaient ajoutés avant tout argument explicite donné à ripgrep sur la ligne de commande. Notez cependant que la commande rg que vous exécutez doit toujours contenir au moins un motif sur la ligne de commande, même si le fichier de configuration utilise l'indicateur -e/--regexp.

Par exemple, si votre fichier ripgreprc contenait une seule ligne :

    --smart-case

alors la commande suivante

    RIPGREP_CONFIG_PATH=wherever/.ripgreprc rg foo

se comporterait de manière identique à la commande suivante :

    rg --smart-case foo

Un autre exemple est l'ajout de types, comme ceci :

    --type-add
    web:*.{html,css,js}*

Ce qui précède se comporterait de manière identique à la commande suivante :

    rg --type-add 'web:*.{html,css,js}*' foo

Il en va de même pour l'utilisation de globs. Ceci :

    --glob=!.git

ou ceci :

    --glob
    !.git

se comporterait de manière identique à la commande suivante :

    rg --glob '!.git' foo

Le point essentiel est que chaque argument de shell doit être sur sa propre ligne. Ainsi, par exemple, un fichier de configuration contenant

    -j 4

ne fait probablement pas ce que vous avez l'intention. Au lieu de cela, vous voulez

    -j
    4

ou

    -j4

ripgrep fournit également un indicateur, --no-config, qui, lorsqu'il est présent, supprimera toute prise en charge des configurations. Cela inclut toute prise en charge future du chargement automatique des fichiers de configuration à partir de chemins prédéterminés.

Les conflits entre les fichiers de configuration et les arguments explicites sont gérés exactement comme les conflits dans la même invocation de commande. C'est-à-dire, en supposant que votre fichier de configuration ne contienne que --smart-case, alors cette commande :

    RIPGREP_CONFIG_PATH=wherever/.ripgreprc rg foo --case-sensitive

est exactement équivalente à

    rg --smart-case foo --case-sensitive

auquel cas, l'indicateur --case-sensitive remplacerait l'indicateur --smart-case.

COMPLETION SHELL

Les fichiers de complétion shell sont inclus dans le tarball de publication pour Bash, Fish, Zsh et PowerShell.

Pour bash, déplacez rg.bash vers $XDG_CONFIG_HOME/bash_completion ou /etc/bash_completion.d/.

Pour fish, déplacez rg.fish vers $HOME/.config/fish/completions.

Pour zsh, déplacez _rg vers l'un de vos répertoires $fpath.

CAVEATS

ripgrep peut s'arrêter de manière inattendue en utilisant les paramètres par défaut s'il recherche un fichier qui est simultanément tronqué. Ce comportement peut être évité en passant l'indicateur --no-mmap qui désactivera de force l'utilisation des mappages mémoire dans tous les cas.

ripgrep peut utiliser une grande quantité de mémoire en fonction de quelques facteurs. Premièrement, si ripgrep utilise le parallélisme pour la recherche (par défaut), alors la sortie complète pour chaque fichier individuel est mise en tampon en mémoire afin d'éviter l'entrelacement des correspondances dans la sortie. Pour éviter cela, vous pouvez désactiver le parallélisme avec l'indicateur -j1. Deuxièmement, ripgrep a toujours besoin d'avoir au moins une seule ligne en mémoire pour exécuter une recherche. Un fichier avec une ligne très longue peut donc entraîner l'utilisation d'une grande quantité de mémoire par ripgrep. Généralement, cela ne se produit que lors de la recherche de données binaires avec l'indicateur -a/--text activé. (Lorsque l'indicateur -a/--text n'est pas activé, ripgrep remplacera tous les octets NUL par des terminateurs de ligne, ce qui empêche généralement une utilisation excessive de la mémoire.) Troisièmement, lorsque ripgrep recherche un grand fichier à l'aide d'un mappage mémoire, le processus signalera probablement son utilisation de mémoire résidente comme étant la taille du fichier. Cependant, cela ne signifie pas que ripgrep a réellement besoin d'utiliser autant de mémoire de tas ; le système d'exploitation s'en chargera généralement.
