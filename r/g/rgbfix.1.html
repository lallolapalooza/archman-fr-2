RGBFIX(1) Manuel des commandes générales RGBFIX(1)

NOM

rgbfix — Utilitaire et correcteur de somme de contrôle pour en-tête Game Boy

SYNTAXE

rgbfix [-hjOsVvw] [-C | -c] [-f spéc_fix] [-i id_jeu] [-k str_licence] [-L fichier_logo] [-l id_licence] [-m type_mbc] [-n version_rom] [-o fichier_sortie] [-p valeur_remplissage] [-r taille_ram] [-t str_titre] [-W avertissement] [fichier ...]

DESCRIPTION

Le programme rgbfix modifie les en-têtes des images ROM Game Boy, généralement générées par rgblink(1), bien qu'il fonctionne avec n'importe quelle ROM Game Boy. Il effectue également d'autres opérations de correction, telles que le remplissage. rgbfix ne modifie que les champs pour lesquels des valeurs sont spécifiées. Il est conseillé aux développeurs de remplir ces champs avec des octets 0x00 dans leur code source avant d'exécuter rgbfix, et d'avoir déjà renseigné les champs qu'ils ne spécifient pas en utilisant rgbfix.

Le fichier d'entrée asmfile peut être un chemin vers un fichier, ou - pour lire depuis l'entrée standard.

Notez que les options peuvent être abrégées tant que l'abréviation est sans ambiguïté : --color-o est --color-only, mais --color est invalide car il pourrait aussi être --color-compatible. Les options placées plus loin dans la ligne de commande remplacent celles définies précédemment. Les options acceptées sont les suivantes :

-C, --color-only
Définit le drapeau Game Boy Color uniquement (0x143) à 0xC0. Ceci remplace -c s'il a été défini précédemment.
-c, --color-compatible
Définit le drapeau compatible Game Boy Color : (0x143) à 0x80. Ceci remplace -c s'il a été défini précédemment.
-f spéc_fix, --fix-spec spéc_fix
Corrige certaines valeurs d'en-tête que le Game Boy vérifie pour leur exactitude. Alternativement, corrompt intentionnellement ces valeurs en écrivant leur inverse binaire. spéc_fix est une chaîne contenant n'importe quelle combinaison des caractères suivants :
l
Corrige le logo Nintendo (0x104–0x133).
L
Corrompt le logo Nintendo.
h
Corrige la somme de contrôle de l'en-tête (0x14D).
H
Corrompt la somme de contrôle de l'en-tête.
g
Corrige la somme de contrôle globale (0x14E–0x14F).
G
Corrompt la somme de contrôle globale.
-h, --help
Affiche le texte d'aide du programme et quitte.
-i id_jeu, --game-id id_jeu
Définit la chaîne d'identifiant du jeu (0x13F–0x142) à une chaîne donnée. Si elle est plus longue que 4 caractères, elle sera tronquée.
-j, --non-japanese
Définit le drapeau de région non japonaise (0x14A) à 0x01.
-k str_licence, --new-licensee str_licence
Définit la chaîne du nouveau licencié (0x144–0x145) à une chaîne donnée. Si elle est plus longue que 2 caractères, elle sera tronquée.
-L fichier_logo, --logo fichier_logo
Spécifie un fichier logo à utiliser à la place du logo officiel Nintendo. Le fichier doit contenir 48 octets de données de tuile 1bpp ; l'image source devrait mesurer 48 pixels de large et 8 pixels de haut.
-l id_licence, --old-licensee id_licence
Définit le code ancien licencié (0x14B) à une valeur donnée de 0 à 0xFF. Cette valeur est obsolète et doit être définie à 0x33 pour tout nouveau logiciel.
-m type_mbc, --mbc-type type_mbc
Définit le type de MBC (0x147) à une valeur donnée de 0 à 0xFF.

Cette valeur peut également être un nom de MBC. La liste des noms acceptés peut être obtenue en passant ‘help’ ou ‘list’ comme argument. N'importe quelle quantité d'espaces (espaces et tabulations) est autorisée autour des signes plus, et l'ordre des "composants" est libre, tant que le nom du MBC est en premier. Il y a des considérations spéciales pour le mapper TPP1 ; voir la section TPP1 ci-dessous.

-n version_rom, --rom-version version_rom
Définit la version de la ROM (0x14C) à une valeur donnée de 0 à 0xFF.
-O, --overwrite
Alias pour -Wno-overwrite.
-o fichier_sortie, --output fichier_sortie
Écrit l'image ROM modifiée dans le fichier donné, ou '-' pour écrire sur la sortie standard. Si non spécifié, les fichiers d'entrée sont modifiés en place, ou écrits sur la sortie standard s'ils sont lus depuis l'entrée standard.
-p valeur_remplissage, --pad-value valeur_remplissage
Remplit l'image ROM à une taille valide avec une valeur de remplissage donnée de 0 à 255 (0xFF). rgbfix choisira automatiquement une taille parmi 32 Kio, 64 Kio, 128 Kio, ..., 8192 Kio. L'octet de taille de la cartouche (0x148) sera modifié pour refléter cette nouvelle taille. La valeur de remplissage recommandée est 0xFF, pour accélérer l'écriture de la ROM sur les puces flash, et pour éviter les "nop slides" dans la VRAM.
-r taille_ram, --ram-size taille_ram
Définit la taille de la RAM (0x149) à une valeur donnée de 0 à 0xFF.
-s, --sgb-compatible
Définit le drapeau SGB (0x146) à 0x03. Ce drapeau sera ignoré par le SGB sauf si le code ancien licencié (--l) est 0x33 !
-t titre, --title titre
Définit la chaîne du titre du jeu (0x134–0x143) à une chaîne donnée. Si elle est plus longue que 16 caractères, elle sera tronquée.
-v, --version
Affiche les informations de version et quitte.
-V
Alias pour --version.
-w, --warn-single-file
Émet un avertissement si le programme est appelé sur un seul fichier, car cela peut être une erreur si le fichier n'est pas destiné à être modifié en place.
-W avertissement, --warning avertissement
Désactive l'avertissement spécifié. L'option -Wno-overwrite désactive l'avertissement concernant l'écrasement de fichiers.

EXEMPLES

Corriger un fichier ROM nommé game.gb, le remplir avec 0xFF, le rendre compatible GBC, définir son ID de jeu à "GAME", et écrire le résultat dans game_fixed.gb :

rgbfix -p 0xFF -c -i GAME -o game_fixed.gb game.gb

Traduire le logo, la somme de contrôle et la somme de contrôle globale d'un fichier ROM nommé foo.gb et écrire le résultat dans bar.gb :

rgbfix -f lhg -o bar.gb foo.gb

TPP1

Le mapper TPP1 est utilisé par les jeux Super Game Boy 2 et Game Boy Color de T&C. Le format de type_mbc pour TPP1 est ‘TPP1 + slots [chip]’.

slots est le nombre d'emplacements de carte, qui doit être une puissance de deux. chip est le type de puce, qui peut être NAND, NOR, ou MaskROM. Si chip est omis, NAND sera utilisé.

Par exemple, pour spécifier TPP1 avec 32 emplacements et une puce NAND, vous utiliseriez :

-m "TPP1 + 32 NAND"

Ou pour spécifier TPP1 avec 16 emplacements et une puce MaskROM :

-m "TPP1 + 16 MaskROM"

Équivalent à -f lhg.
-W warning, --warning warning

-w

DIAGNOSTICS

Les avertissements sont des messages diagnostiques qui indiquent un comportement potentiellement erroné qui ne compromet pas nécessairement le processus de correction de l'en-tête. Les options suivantes modifient la manière dont les avertissements sont traités.

-Werror
Transforme tous les avertissements en erreurs. Ceci peut être nié avec -Wno-error pour empêcher la transformation de tous les avertissements en erreurs.
-Werror=
Transforme l'avertissement spécifié ou le méta-avertissement en erreur. Le nom d'un avertissement est ajouté (exemple : -Werror=overwrite), et cet avertissement est implicitement activé et transformé en erreur. Ceci peut être nié avec -Wno-error= pour empêcher la transformation d'un avertissement spécifié en erreur, même si -Werror est actif.

Les avertissements suivants sont des méta-avertissements, qui activent une collection d'autres avertissements. Si un avertissement spécifique est basculé via un drapeau méta et un drapeau spécifique, celui qui est le plus spécifique prend la priorité. La position sur la ligne de commande sert de critère de départage, le dernier prenant effet.

-Wall
Active les avertissements qui sont susceptibles d'indiquer une erreur ou un comportement indésirable, et qui peuvent être facilement corrigés.
-Weverything
Active littéralement tous les avertissements.

Les avertissements suivants sont de véritables drapeaux d'avertissement ; avec chaque description, le drapeau d'avertissement correspondant est inclus. Notez que chacun de ces drapeaux a également une négation (par exemple, -Wtruncation active l'avertissement que -Wno-truncation désactive ; et -Wall active chaque avertissement que -Wno-all désactive). Seul le drapeau non-défaut est listé ici. En ignorant le préfixe « no- », les entrées sont listées par ordre alphabétique.

-Wno-mbc
Avertit en cas d'incohérences ou de mises en garde concernant le type MBC spécifié.
-Wno-overwrite
Avertit en cas d'écrasement de différents octets non nuls dans l'en-tête.
-Wno-sgb
Avertit lorsque le drapeau SGB (-s) est en conflit avec l'ancien code de licence (-l).
-Wno-truncation
Avertit lors de la troncature de valeurs pour les faire tenir dans l'espace disponible.

EXAMPLES

La plupart des valeurs dans l'en-tête ROM n'ont pas d'importance pour la console réelle, et la plupart sont rarement utiles de toute façon. Les exigences minimales pour un programme fonctionnel sont la somme de contrôle de l'en-tête, le logo Nintendo, et (si nécessaire) les drapeaux CGB/SGB. Il est conseillé de rembourrer l'image à une taille valide également (« valide » signifiant une puissance de 2, multipliée par 32 KiB).

Ce qui suit créera un jeu Game Boy simple, non-couleur, sans vérifier la taille valide :

$ rgbfix -v foo.gb

Ce qui suit créera un jeu compatible SGB et couleur avec le titre « foobar », et le rembourrera à une taille valide. (Le Game Boy lui-même n'utilise pas le titre, mais certains émulateurs ou gestionnaires de ROM le font.)

$ rgbfix -vcs -l 0x33 -p 255 -t foobar baz.gb

Ce qui suit dupliquera l'en-tête du jeu « Survival Kids », sans la somme de contrôle globale :

$ rgbfix -cjsv -k A4 -l 0x33 -m 0x1B -p 0xFF -r 3 -t SURVIVALKIDAVKE SurvivalKids.gbc

TPP1

TPP1 est un mapper de homebrew conçu comme un sur-ensemble fonctionnel des MBC traditionnels courants, permettant des tailles de ROM et de RAM plus importantes combinées à d'autres fonctionnalités matérielles. Sa spécification, ainsi que d'autres ressources, peuvent être trouvées en ligne sur https://github.com/aaaaaa123456789/tpp1.

Nom MBC

Le nom du MBC pour TPP1 est plus complexe que pour les mappers standards. Il doit être suivi du numéro de révision, sous la forme « major.minor », où « major » et « minor » sont des entiers décimaux de 8 bits. Il peut y avoir n'importe quelle quantité d'espaces ou de soulignements entre « TPP1 » et le numéro de révision. rgbfix ne prend en charge que les révisions 1.x, et rejettera tout le reste.

Comme pour les autres mappers, le nom peut être suivi d'une liste de fonctionnalités optionnelles séparées par « + » ; cependant, « RAM » ne doit pas être spécifié, car le mapper TPP1 demande implicitement de la RAM si une taille de RAM non nulle est spécifiée. Par conséquent, rgbfix ignorera la fonctionnalité « RAM » sur un mapper TPP1.

Considérations spéciales

TPP1 écrase l'octet à l'adresse 0x14A, indiquant généralement la destination régionale (voir -j), avec l'un de ses trois octets d'identification. Par conséquent, rgbfix avertira et ignorera -j s'il est utilisé en combinaison avec TPP1.
