RGBLINK(1) Manuel des commandes générales RGBLINK(1)

NOM

rgblink — Éditeur de liens pour Game Boy

SYNTAXE

rgblink [-dhMtVvwx] [-l script_editeur_lien] [-m fichier_carte] [-n fichier_symboles] [-O fichier_superposition] [-o fichier_sortie] [-p valeur_remplissage] [-S spec] [-W avertissement] fichier ...

DESCRIPTION

Le programme rgblink édite les fichiers objets RGB, généralement créés par rgbasm(1), en un seul fichier ROM Game Boy. Le format du fichier objet est documenté dans rgbds(5).

Les sections ROM0 sont placées dans les 16 premiers KiB de la ROM de sortie, et les sections ROMX sont placées dans n'importe quel « banc » de 16 KiB à l'exception du premier. Si votre ROM ne fait que 32 KiB, vous pouvez utiliser l'option -t pour modifier cela.

De même, les sections WRAM0 sont placées dans les 4 premiers KiB de WRAM (« banc 0 »), et les sections WRAMX sont placées dans n'importe quel banc des 4 derniers KiB. Si votre ROM n'utilise pas de WRAM bancarisée, vous pouvez utiliser l'option -w pour modifier cela.

De plus, si votre ROM est conçue pour une Game Boy monochrome, vous pouvez vous assurer de ne pas utiliser de section incompatible en utilisant l'option -d, qui active implicitement -w mais interdit également l'utilisation de VRAM bancarisée.

Le fichier d'entrée asmfile peut être un chemin vers un fichier, ou - pour lire depuis l'entrée standard.

Notez que les options peuvent être abrégées tant que l'abréviation est sans ambiguïté : --verb est --verbose, mais --ver est invalide car il pourrait aussi s'agir de --version. Les arguments sont les suivants :

-d, --dmg
Active le mode DMG. Interdit l'utilisation de sections qui n'existent pas sur un DMG, comme la banque 1 de VRAM. Cette option active automatiquement -w.
-h, --help
Affiche le texte d'aide du programme et quitte.
-l script_editeur_lien, --linkerscript script_editeur_lien
Spécifie un fichier de script d'éditeur de liens qui indique à l'éditeur de liens comment les sections doivent être placées dans la ROM. Les attributs assignés dans le script d'éditeur de liens doivent être cohérents avec ceux assignés dans le code. Voir rgblink(5) pour plus d'informations sur le format du script d'éditeur de liens.
-M, --no-sym-in-map
Si spécifié, le fichier carte n'affichera pas les symboles, uniquement les sections.
-m fichier_carte, --map fichier_carte
Écrit un fichier carte dans le nom de fichier donné, listant comment les sections et les symboles ont été assignés.
-n fichier_symboles, --sym fichier_symboles
Écrit un fichier symboles dans le nom de fichier donné, listant toutes les étiquettes visibles et les constantes numériques exportées. Les étiquettes affichent leur banque et leur adresse, les constantes numériques affichent leur valeur, suivant cette spécification. Plusieurs programmes externes peuvent utiliser ces informations, par exemple pour aider au débogage des ROMs.
-O fichier_superposition, --overlay fichier_superposition
Si spécifié, les sections seront superposées « par-dessus » l'image ROM fichier_superposition : les espaces vides entre les sections seront remplis par les octets correspondants de fichier_superposition. Ceci est utile pour patcher une ROM existante. Notez que toutes les sections doivent être fixes (banque forcée et adresse !).
-o fichier_sortie, --output fichier_sortie
Écrit l'image ROM dans le fichier donné.
-p valeur_remplissage, --pad valeur_remplissage
Lors de l'insertion d'un remplissage entre les sections, utilise cette valeur pour le remplissage. La valeur par défaut est 0.
-S spec, --scramble spec
Active un algorithme de « brouillage » différent pour placer les sections. Voir la section Algorithme de brouillage ci-dessous pour une explication et une description de spec.
-t, --tiny
Augmente la taille de la section ROM0 de 16 KiB à l'intégralité des 32 KiB attribués à la ROM. Les sections ROMX qui sont fixes à une banque autre que 1 deviennent des erreurs, les autres sections ROMX sont traitées comme ROM0. Utile pour les ROMs qui tiennent en 32 KiB.
-V, --version
Affiche la version du programme et quitte.
-v, --verbose
Verbeux : active l'affichage d'informations supplémentaires sur la sortie d'erreur standard.
-W avertissement, --warning avertissement
Définit le drapeau d'avertissement avertissement. Un message d'avertissement sera affiché si avertissement est un drapeau d'avertissement inconnu. Voir la section DIAGNOSTICS pour une liste des avertissements.
-w, --wramx
Augmente la taille de la section WRAM0 de 4 KiB à l'intégralité des 8 KiB attribués à la WRAM. Les sections WRAMX qui sont fixes à une banque autre que 1 deviennent des erreurs, les autres sections WRAMX sont traitées comme WRAM0.
-x, --nopad
Désactive le remplissage de la fin du fichier final. Cette option active automatiquement -t. Vous pouvez l'utiliser pour créer des fichiers binaires qui ne sont pas une ROM. Lors de la création d'une ROM, notez que ne pas utiliser cette option ne remplace pas l'option -p de rgbfix(1) !

Algorithme de brouillage

L'algorithme de placement de section par défaut essaie de minimiser le nombre de banques utilisées ; le « brouillage » place plutôt les sections dans un ensemble donné de banques, en essayant de minimiser le nombre de sections partageant une banque donnée. Ceci est utile pour détecter des hypothèses incorrectes concernant les banques, comme s'attendre à ce que deux sections différentes aboutissent dans la même banque (ce qui n'est pas garanti à moins que les deux ne se voient attribuer manuellement le même numéro de banque).

Une spécification de brouillage est une liste de spécifications de régions séparées par des virgules. Une virgule finale est autorisée, ainsi que des espaces blancs entre toutes les spécifications et leurs composants. Chaque spécification de région a la forme suivante :

région[=taille]
région doit être l'une des suivantes (insensible à la casse), tandis que taille doit être un entier décimal positif compris entre 1 et la valeur maximale correspondante. Certaines régions permettent d'omettre la taille, auquel cas elle prend sa valeur maximale par défaut.
Nom de la région Taille max Taille facultative
romx 65535 Non
rgblink(1) — man pages

NAME

rgblink

— the RGBDS linker

SYNOPSIS

rgblink [-o outfile] [-n mapfile] [-p fill] [-d] [-w] [--map=mapfile] [--output=outfile] [--fill=fill] [--data] [--warn-zero-fill] [--help] [--version] [infile ...]

DESCRIPTION

The rgblink utility is the linker for the RGBDS Game Boy assembler suite. It takes one or more input files, which are usually object files produced by rgbasm(1), and links them together into a single ROM image.

The following options are available:

-o outfile
Specifies the name of the output file. If this is omitted, the output will be written to a.out.
-n mapfile
--map=mapfile
Specifies the name of the map file. This file contains information about where each section was placed in the final ROM. If omitted, no map file will be produced.
-p fill
--fill=fill
Specifies the byte value to use when filling unused portions of the ROM image. The default is 0.
-d
--data
Causes sections that would normally be placed in ROM (e.g. ROMX, VRAM, WRAMX) to be placed in the data section instead. This is useful for testing Game Boy ROMs under emulators, as it allows memory regions that would normally be read-only to be modified.
-w
--warn-zero-fill
Causes rgblink to warn if any sections are filled with 0. This can be useful for detecting unintentional gaps in the ROM image. Note that this option implies -w. It is silently ignored if -d is passed.

The default behavior is to scramble sections, meaning that they will be placed in different memory banks each time the ROM is linked. This can help to prevent certain types of bugs that are related to memory layout.

The following sections can be scrambled:

Table 1. Scrambled Sections
Section Max Size Scrambled by default?
sram 255 No
wramx 7 Yes

A size of 0 disables scrambling for that region.

For example, ‘romx=64,wramx=4’ will scramble ROMX sections among ROM banks 1 to 64, WRAMX sections among RAM banks 1 to 4, and will not scramble SRAM sections.

Later region specs override earlier ones; for example, ‘romx=42, Romx=0’ disables scrambling for romx.

wramx scrambling is silently ignored if -w is passed (including if implied by -d), as WRAMX sections will be treated as WRAM0.

DIAGNOSTICS

Warnings are diagnostic messages that indicate possibly erroneous behavior that does not necessarily compromise the linking process. The following options alter the way warnings are processed.

-Werror
Make all warnings into errors. This can be negated as -Wno-error to prevent turning all warnings into errors.
-Werror=
Make the specified warning or meta warning into an error. A warning's name is appended (example: -Werror=assert), and this warning is implicitly enabled and turned into an error. This can be negated as -Wno-error= to prevent turning a specified warning into an error, even if -Werror is in effect.

The following warnings are “meta” warnings, that enable a collection of other warnings. If a specific warning is toggled via a meta flag and a specific one, the more specific one takes priority. The position on the command-line acts as a tie breaker, the last one taking effect.

-Wall
This enables warnings that are likely to indicate an error or undesired behavior, and that can easily be fixed.
-Weverything
Enables literally every warning.

The following warnings are actual warning flags; with each description, the corresponding warning flag is included. Note that each of these flag also has a negation (for example, -Wobsolete enables the warning that -Wno-obsolete disables; and -Wall enables every warning that -Wno-all disables). Only the non-default flag is listed here. Ignoring the “no-” prefix, entries are listed alphabetically.

-Wno-assert
Warn when WARN-type assertions fail. (See “Aborting the assembly process” in rgbasm(5) for ASSERT).
-Wdiv
Warn when dividing the smallest negative integer (-2**31) by -1, which yields itself due to integer overflow. This warning is enabled by -Wall.
-Wno-obsolete
Warn when obsolete features are encountered, which have been deprecated and may later be removed.
-Wshift
Warn when shifting right a negative value. Use a division by 2**N instead. This warning is enabled by -Wall.
-Wshift-amount
Warn when a shift's operand is negative or greater than 32. This warning is enabled by -Wall.
-Wno-truncation
Warn when an implicit truncation (for example, db to an 8-bit value) loses some bits. This occurs when an N-bit value is 2**N or greater, or less than -2**N.

EXAMPLES

All you need for a basic ROM is an object file, which can be made into a ROM image like so:

$ rgblink -o bar.gb foo.o

The resulting bar.gb will not have correct checksums (unless you put them in the assembly source). You should use rgbfix(1) to fix these so that the program will actually run in a Game Boy:

$ rgbfix -v bar.gb

Here is a more complete example:

$ rgblink -o bin/game.gb -n bin/game.sym -p 0xFF obj/title.o obj/engine.o
