NOM

rgr - Un remplaçant interactif pour ripgrep qui facilite la recherche et le remplacement dans des fichiers en ligne de commande.

DESCRIPTION

Pour utiliser cet outil, vous devez d'abord avoir installé rg (alias : ripgrep). Voir : https://github.com/BurntSushi/ripgrep/#installation.

UTILISATION

Utilisation normale

Au démarrage, tous les arguments de la ligne de commande sont transmis à rg (en ajoutant --json et --no-config). La sortie JSON est ensuite analysée, et vous êtes présenté avec une interface terminal (décrite ci-dessous).

Notez que comme nous utilisons le drapeau --json, un certain nombre de drapeaux de rg ne sont pas disponibles. Voir rgr --help pour une liste des drapeaux pris en charge qui seront transmis à ripgrep.

Groupes de capture

Vous pouvez utiliser des groupes de capture lors de l'utilisation de rgr, par exemple rgr «foo (\w+)». Lors de leur utilisation, les correspondances peuvent être utilisées lors du remplacement en se référant à elles par leur nom $nom ou leur index $1. Cette syntaxe est héritée de la crate regex, voir : https://docs.rs/regex/1.8.4/regex/struct.Captures.html#method.expand

Un seul motif peut être passé à la fois lorsque des groupes de capture sont utilisés (c'est-à-dire que plusieurs drapeaux -e <pat> ne sont pas autorisés).

Lecture des résultats à partir d'un fichier

Cet outil prend également en charge la lecture des résultats à partir d'un fichier JSON, dans l'optique du cas d'utilisation suivant :

•L'utilisateur exécute "rg --json <args> > rg-results.json"
•Maintenant, cet outil peut être exécuté avec ces résultats via "RGR_JSON_FILE=./rg-results.json rgr"

INTERFACE

Pour voir une liste des raccourcis clavier, appuyez sur ? en mode SELECT. Il existe plusieurs modes différents :

SELECT

•Ce mode est le premier mode présenté après le démarrage de rgr.
•Dans ce mode, une liste de correspondances est présentée, et elles peuvent être activées ou désactivées.
•Désactiver une correspondance signifie que la correspondance elle-même ne sera pas remplacée.

REPLACE

•Dans ce mode, l'utilisateur tape le texte de remplacement désiré et les correspondances sont mises à jour en temps réel.
•Notez qu'il ne s'agit que d'une démonstration, aucune modification n'est écrite sur le disque.
•Les octets non UTF-8 dans les correspondances sont affichés avec le caractère de remplacement UTF-8 dans ce mode.
•Appuyer sur Ctrl+S entraînera le remplacement de toutes les correspondances sélectionnées par le texte saisi.

CONFIRM

•Invite l'utilisateur à confirmer avant d'écrire les remplacements sur le disque.
•Les remplacements sont écrits sur le disque, et toutes les tentatives sont faites pour utiliser le bon encodage de fichier. (voir ENCODAGE DE FICHIER.)
•Notez que rgr ne remplacera pas une tranche d'octets différente de celle que rg a rapportée dans sa sortie. (voir ENCODAGE DE FICHIER.)

HELP

•Ce mode fournit des informations sur rgr et ses raccourcis clavier.

CARACTÈRES DE CONTRÔLE

L'utilisateur peut modifier la façon dont les caractères de contrôle sont rendus dans l'interface en appuyant sur Ctrl+V. Les différents modes sont :

•C : afficher les caractères de contrôle courants
•c : afficher les caractères de contrôle courants (une ligne)
•A : afficher tous les caractères de contrôle
•a : afficher tous les caractères de contrôle (une ligne)
•H : afficher les caractères de contrôle courants comme des espaces, et supprimer les autres (cachés)

ENCODAGE DE FICHIER

La gestion de l'encodage des fichiers se fait en deux endroits : le mode SELECT et lors de l'écriture des remplacements sur le disque.

Dans le mode SELECT, les octets non UTF-8 sont affichés avec le caractère de remplacement UTF-8. Cela se produit car les fichiers eux-mêmes n'ont pas encore été lus (les informations proviennent directement de ripgrep) et donc l'encodage du fichier est inconnu.

Lors du remplacement, l'encodage est géré de la manière suivante :

•Si un BOM (Byte Order Mark) est trouvé, alors cet encodage est utilisé, sinon
•Si un encodage a été passé à ripgrep, alors cet encodage est utilisé, sinon
•La bibliothèque chardet ( https://github.com/thuleqaid/rust-chardet) est utilisée pour détecter l'encodage
•Si cela échoue, alors UTF8 est supposé

Notez que rgr ne remplacera jamais une correspondance qu'il n'attend pas. Si, lors du remplacement d'une correspondance, les octets à remplacer ne correspondent pas à ceux trouvés par ripgrep, alors l'outil échouera et le fichier ne sera pas écrit. (Les erreurs seront signalées sur STDERR.)
