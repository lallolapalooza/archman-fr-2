RGBDS(5) Formats de fichiers RGBDS(5)

NOM

rgbds — documentation du format de fichier objet

DESCRIPTION

Ceci est la description des fichiers objets utilisés par rgbasm(1) et rgblink(1). Veuillez noter que la spécification n'est pas encore stable. RGBDS est toujours en développement actif, et certaines nouvelles fonctionnalités nécessitent l'ajout d'informations supplémentaires au fichier objet, ou la modification de certains champs, ce qui brise la compatibilité avec les anciennes versions.

STRUCTURE DU FICHIER

Les types suivants sont utilisés :

LONG est un entier de 32 bits stocké au format little-endian. BYTE est un entier de 8 bits. STRING est une chaîne de BYTE terminée par 0. Les crochets après un type (par exemple LONG[n]) indiquent n éléments consécutifs (ici, des LONG). Tous les éléments sont contigus, sans aucun remplissage — cela signifie également qu'ils peuvent ne pas être alignés dans le fichier !

REPT n indique que les champs entre le REPT et le ENDR correspondant sont répétés n fois.

Tous les IDs font référence à des objets au sein du fichier ; par exemple, l'ID de symbole $0001 fait référence au deuxième symbole défini dans le tableau des ce fichier objet. La seule exception concerne les nœuds d'informations de fichier source (Informations de fichier source), dont les IDs sont inversés, c'est-à-dire que l'ID de nœud source $0000 fait référence au dernier nœud du tableau, pas au premier. Les références à d'autres fichiers objets sont faites par des importations (symboles), par nom (sections), etc. — mais jamais par ID.

Symboles

REPT NumberOfSymbols
STRING Name
Le nom du symbole.
LONG SectionID
L'identifiant de la section à laquelle le symbole appartient. Si le symbole n'appartient à aucune section, cette valeur est -1.
LONG Type
Le type de symbole. Les bits inférieurs indiquent la portée, les bits supérieurs la catégorie. Les valeurs possibles sont :
BYTE 0
Symbole local globalement défini. Doit avoir un type section et une valeur valides.
BYTE 1
Symbole local à la section. Doit avoir un type section et une valeur valides.
BYTE 2
Symbole externe, non défini. Doit avoir un type section invalide (cela devrait être -1, bien que le code ne le vérifie pas) et une valeur invalide (-1).
La signification des types dépend des bits supérieurs. Les bits 0–2 indiquent la portée :
Valeur Signification
0 Local
1 Global
2 Weak
Les bits 3–7 indiquent la catégorie du symbole :
Valeur Signification
0 Symbole de code
1 Symbole de données
2 Symbole de section
3 Symbole de fichier
4 Symbole d'assertion
5 Symbole de 32 bits
Si le champ contient -1, ce champ contient -1.
LONG Valeur
La valeur du symbole. Si le symbole appartient à une section, il s'agit de l'offset dans la section du symbole.
ENDC

Sections

REPT NumberOfSections
STRING Nom
Le nom de la section.
LONG NodeID
Contexte dans lequel la section a été définie.
LONG LineNo
Numéro de ligne dans le contexte où la section a été définie.
LONG Taille
La taille de la section, en octets.
BYTE Type
Les bits 0–2 indiquent le type de la section :
Valeur Signification
0 WRAM0
1 VRAM
2 ROMX
3 ROM0
4 HRAM
5 WRAMX
6 SRAM
7 OAM

Le bit 7 activé signifie que la section est une « union » (voir « Sections unifiées » dans rgbasm(5)). Le bit 6 activé signifie que la section est un « fragment » (voir « Fragments de section » dans rgbasm(5)). Ces deux bits sont mutuellement exclusifs.

LONG Adresse
Adresse à laquelle cette section doit être placée. Celle-ci doit être valide pour le Type de la section (tel qu'affecté par des flags comme -t ou -d dans rgblink(1)), ou -1 pour indiquer que l'éditeur de liens doit décider automatiquement (la section est « flottante »).
LONG Banque
Identifiant de la banque dans laquelle cette section doit être placée. Celle-ci doit être valide pour le Type de la section (avec les mêmes mises en garde que pour l'Adresse), ou -1 pour indiquer que l'éditeur de liens doit décider automatiquement.
BYTE Alignement
Combien de bits de l'adresse de la section doivent être égaux à l'AlignOfs, en commençant par le bit de poids faible.
LONG AlignOfs
Décalage d'alignement. Doit être strictement inférieur à ‘1 << Alignement’.
IF Type = 2 || Type = 3
Si la section est de type ROM, elle contient des données.
BYTE Données[Taille]
Les données brutes de la section. Les octets qui doivent être patchés doivent être présents, même si leur contenu sera écrasé.
LONG NumberOfPatches
Combien de patchs doivent être appliqués aux Données de cette section.
REPT NumberOfPatches
LONG NodeID
Contexte dans lequel le patch a été défini.
LONG LineNo
Numéro de ligne dans le contexte où le patch a été défini.
LONG Offset
Offset dans les Données de la section où le patch doit être appliqué. Ne doit pas être supérieur à la Taille de la section moins la taille du patch (voir Type ci-dessous).
LONG PCSectionID
ID de la section dans laquelle se trouve le PC. (C'est généralement la même section dans laquelle le patch est appliqué, sauf pour les blocs ‘LOAD’, voir « Code RAM » dans rgbasm(5).)
LONG PCOffset
Offset du symbole PC dans la section désignée par PCSectionID. On s'attend à ce que le PC pointe vers le premier octet de l'instruction pour les opérandes d'instruction (c'est-à-dire que ‘jp @’ doit être une boucle infinie), et vers le premier octet du patch sinon (‘db’, ‘dw’, ‘dl’).
BYTE Type
Valeur Signification
0 Patch d'un seul octet
1 Patch de deux octets little-endian
2 Patch de quatre octets little-endian
3 Patch ‘jr’ d'un seul octet ; la valeur du patch sera soustraite de PC + 2 (c'est-à-dire que ‘jr @’ doit être la boucle infinie ‘18 FE’).
LONG RPNSize
Taille de l'RPNExpr ci-dessous.
BYTE RPNExpr[RPNSize]
La valeur du patch, encodée comme une expression RPN (voir Expressions RPN).

Expressions RPN

Les expressions dans le fichier objet sont stockées en RPN, ou « notation polonaise inverse », qui est une notation permettant de calculer des expressions arbitraires avec une simple pile. Par exemple, l'expression « 2 5 - » poussera d'abord la valeur « 2 » sur la pile, puis « 5 ». L'opérateur « - » dépile deux arguments de la pile, les soustrait, puis repousse le résultat (« 3 ») sur la pile. Une expression RPN bien formée n'essaie jamais de dépiler d'une pile vide et laisse exactement une valeur dans celle-ci à la fin.

RGBDS encode les expressions RPN sous forme d'un tableau de BYTEs. Le premier octet encode soit un opérateur, soit une valeur littérale, qui consomme plus de BYTEs après lui :

Valeur Signification
$00 Opérateur d'addition (« + »)
$01 Opérateur de soustraction (« - »)
$02 Opérateur de multiplication (« * »)
$03 Opérateur de division (« / »)
$04 Opérateur modulo (« % »)
$05 Négation ( « - » unaire)
$06 Opérateur d'exponentiation (« ** »)
$10 Opérateur OU binaire (« | »)
$11 Opérateur ET binaire (« & »)
$12 Opérateur XOR binaire (« ^ »)
$13 Opérateur de complément binaire (unary « ~ »)
$21 Opérateur ET logique (« && »)
$22 Opérateur OU logique (« || »)
$23 Opérateur de complément logique (unary « ! »)
$30 Opérateur d'égalité (« == »)
$31 Opérateur de non-égalité (« != »)
$32 Opérateur supérieur à (« > »)
$33 Opérateur inférieur à (« < »)
$34 Opérateur supérieur ou égal (« >= »)
$35 Opérateur inférieur ou égal (« <= »)
$40 Opérateur de décalage à gauche (« << »)
$41 Opérateur de décalage à droite arithmétique/signé (« >> »)
$42 Opérateur de décalage à droite logique/non signé (« >>> »)
$50 BANK(symbole) ; suivi de l'ID LONG du symbole.
$51 BANK(section) ; suivi du nom STRING de la section.
$52 BANK() du PC (c'est-à-dire « BANK(@) »).
$53 SIZEOF(section) ; suivi du nom STRING de la section.
$54 STARTOF(section) ; suivi du nom STRING de la section.
$55 SIZEOF(typetsection) ; suivi de la valeur BYTE du typetsection (voir les valeurs de Type dans Sections).
$56 STARTOF(typetsection) ; suivi de la valeur BYTE du typetsection (voir les valeurs de Type dans Sections).
$60 Vérification « ldh ». Vérifie si la valeur est un opérande « ldh » valide (voir « Instructions de chargement » dans gbz80(7)), c'est-à-dire qu'elle est comprise entre $00 et $FF, ou entre $FF00 et $FFFF, les deux inclus. La valeur est ensuite combinée avec $00FF ( « & $FF »).
$61 Vérification « rst ». Vérifie si la valeur est un vecteur « rst » valide (voir « Vecteurs RST » dans gbz80(7)), c'est-à-dire l'un des $00, $08, $10, $18, $20, $28, $30 ou $38. La valeur est ensuite combinée avec $C7 ( « | $C7 »).
$62 Vérification « bit/res/set » ; suivi du masque BYTE de l'instruction. Vérifie si la valeur est un indice de bit valide (voir par exemple « BIT u3, r8 » dans gbz80(7)), c'est-à-dire de 0 à 7. La valeur est ensuite combinée avec le masque de l'instruction.
$80 Littéral entier ; suivi de l'entier LONG.
$70 Octet HIGH.
$71 Octet LOW.
$72
BITWIDTH valeur. $73 TZCOUNT valeur. $81 Une valeur de symbole ; suivie de l'LONG ID du symbole.
