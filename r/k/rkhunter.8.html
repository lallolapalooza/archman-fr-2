NOM

rkhunter - RootKit Hunter

SYNTAXE

rkhunter {--check | --unlock | --update | --versioncheck |
--propupd [{nom_fichier | répertoire | nom_paquet},...] |
--list [tests | {lang | langues} | rootkits | perl |
propfiles] |
--config-check | --version | --help} [options]

DESCRIPTION

rkhunter est un script shell qui effectue diverses vérifications sur le système local pour tenter de détecter des rootkits et des malwares connus. Il effectue également des vérifications pour voir si des commandes ont été modifiées, si les fichiers de démarrage du système ont été modifiés, et diverses vérifications des interfaces réseau, y compris les applications en écoute.

rkhunter a été écrit pour être aussi générique que possible, et devrait donc fonctionner sur la plupart des systèmes Linux et UNIX. Il est fourni avec des scripts de support pour le cas où certaines commandes seraient manquantes sur le système, et certains de ces scripts sont écrits en perl. rkhunter nécessite la présence de certaines commandes pour pouvoir s'exécuter. De plus, certains tests nécessitent des commandes spécifiques, mais si elles ne sont pas présentes, le test sera ignoré. rkhunter doit être exécuté sous un shell de type Bourne, typiquement bash ou ksh. rkhunter peut être exécuté via une tâche cron ou depuis la ligne de commande.

OPTIONS DE COMMANDE

Si aucune option de commande n'est donnée, alors --help est supposé. rkhunter retournera un code de sortie non nul si une erreur ou un avertissement se produit.

-c, --check
Cette option de commande indique à rkhunter d'effectuer diverses vérifications sur le système local. Le résultat de chaque test sera affiché sur stdout. Si quelque chose de suspect est trouvé, un avertissement sera affiché. Un fichier journal des tests et des résultats sera automatiquement créé.

Il est suggéré d'exécuter cette option de commande régulièrement pour s'assurer que le système n'a pas été compromis.

--unlock
Cette option de commande déverrouille (supprime) simplement le fichier de verrouillage. Si cette option est utilisée seule, aucun fichier journal n'est créé.
--update
Cette option de commande amène rkhunter à vérifier s'il existe une version plus récente de ses fichiers de données textuelles. Un navigateur web en ligne de commande, par exemple wget ou lynx, doit être présent sur le système lors de l'utilisation de cette option.

Il est suggéré d'exécuter cette option de commande régulièrement pour s'assurer que les fichiers de données sont tenus à jour.

Si cette option est utilisée via cron, il est recommandé d'utiliser également l'option --nocolors.

Un code de sortie de zéro pour cette option de commande signifie qu'aucune mise à jour n'était disponible. Un code de sortie de un signifie qu'une erreur de téléchargement s'est produite, et un code de deux signifie qu'aucune erreur ne s'est produite mais que des mises à jour étaient disponibles et ont été installées.

--propupd [{nom_fichier | répertoire | nom_paquet},...]
L'une des vérifications effectuées par rkhunter consiste à comparer les propriétés de divers fichiers actuels de diverses commandes, avec celles qu'il a précédemment stockées. Cette option de commande amène rkhunter à mettre à jour son fichier de données des valeurs stockées avec les valeurs actuelles.

Si l'option nom_fichier est utilisée, elle doit être soit un chemin d'accès complet, soit un nom de fichier simple (par exemple, 'awk'). Lorsqu'elle est utilisée, seule l'entrée dans la base de données des propriétés de fichier pour ce fichier sera mise à jour. Si l'option répertoire est utilisée, seules les fichiers listés dans la base de données qui se trouvent dans le répertoire donné seront mis à jour. De même, si l'option nom_paquet est utilisée, seules les fichiers de la base de données qui font partie du paquet spécifié seront mis à jour. Le nom du paquet doit être la partie de base du nom, aucun numéro de version ne doit être inclus - par exemple, 'coreutils'. Les noms de paquets ne seront, bien sûr, stockés dans la base de données des propriétés de fichier que si un gestionnaire de paquets est utilisé. Si un nom de paquet est identique à un nom de fichier - par exemple, 'file' pourrait faire référence à la commande 'file' ou au paquet RPM 'file' (qui contient la commande 'file') - le nom du paquet sera utilisé. Si aucune option spécifique n'est donnée, l'ensemble de la base de données est mise à jour.

ATTENTION : Il incombe à l'utilisateur de s'assurer que les fichiers sur le système sont authentiques et proviennent d'une source fiable. rkhunter ne peut que signaler si un fichier a changé, mais pas ce qui a causé le changement. Par conséquent, si un fichier a changé, et que l'option de commande --propupd est utilisée, rkhunter supposera que le fichier est authentique.

--versioncheck
Cette option de commande amène rkhunter à vérifier s'il existe une version plus récente du programme. Un navigateur web en ligne de commande doit être présent sur le système lors de l'utilisation de cette option.

Si cette option est utilisée via cron, il est recommandé d'utiliser également l'option --nocolors.

Un code de sortie de zéro pour cette option de commande signifie qu'aucune nouvelle version n'était disponible. Un code de sortie de un signifie qu'une erreur s'est produite lors du téléchargement du numéro de dernière version, et un code de deux signifie qu'aucune erreur ne s'est produite mais qu'une nouvelle version est disponible.

--list [tests | {lang | langues} | rootkits | perl | propfiles]
Cette option de commande listera certaines des capacités prises en charge par le programme, puis se terminera. L'option tests liste les noms de tests actuellement disponibles (voir le fichier README pour plus de détails sur les noms de tests). L'option langues liste les langues actuellement disponibles, et l'option rootkits liste les rootkits recherchés par rkhunter. L'option perl liste le statut d'installation de la commande perl et des modules perl qui peuvent être utilisés par certains tests. Notez qu'il n'est pas *requis* d'installer ces modules. Cependant, si rkhunter est forcé d'utiliser perl pour exécuter un test, le module doit être présent. L'option propfiles listera les noms de fichiers utilisés pour générer la base de données des propriétés de fichiers. Si aucune option spécifique n'est donnée, toutes les listes, à l'exception de la base de données des propriétés de fichiers, sont affichées.
-C, --config-check
Cette option de commande amène rkhunter à vérifier ses fichiers de configuration, puis à se terminer. Le programme effectuera ses vérifications de configuration normales comme spécifié par les options enable et disable sur la ligne de commande et dans les fichiers de configuration. C'est-à-dire que seules les options de configuration pour les tests qui s'exécuteraient normalement seront vérifiées. Pour vérifier toutes les options configurées, utilisez les options --enable all --disable none sur la ligne de commande. De plus, le programme vérifiera s'il y a des options de configuration non reconnues. Si des problèmes de configuration sont trouvés, ils seront affichés et le code de retour sera défini sur 1.

Il est suggéré d'utiliser cette option chaque fois que le(s) fichier(s) de configuration ont été modifiés.

-V, --version
Cette option de commande amène rkhunter à afficher son numéro de version, puis à se terminer.
-h, --help

Cette option de commande affiche le menu d'aide, puis se termine.

OPTIONS

rkhunter utilise un fichier de configuration, nommé rkhunter.conf, pour bon nombre de ses options de configuration. Il peut également utiliser un fichier de configuration local, nommé rkhunter.conf.local, et un répertoire nommé rkhunter.d s'il est présent. Le fichier de configuration local, ainsi que le répertoire local, doivent se trouver dans le même répertoire que le fichier de configuration principal. L'installateur ne crée ni le fichier local ni le répertoire, mais l'un, ou les deux, peuvent être créés par l'utilisateur si nécessaire. Si un répertoire est utilisé, alors à l'intérieur du répertoire tout fichier se terminant par .conf sera traité

Créé en tant que fichier de configuration local.

Certaines options peuvent également être spécifiées sur la ligne de commande et remplaceront les options équivalentes du fichier de configuration. Les options du fichier de configuration sont bien documentées dans le fichier de configuration principal lui-même. Les options suivantes sont celles de la ligne de commande. Les valeurs par défaut mentionnées ici sont les valeurs par défaut du programme, sauf indication contraire explicite comme étant la valeur par défaut du fichier de configuration.

--appendlog
Par défaut, un nouveau fichier journal est créé lorsque rkhunter s'exécute, et le fichier journal précédent est renommé en ajoutant .old à son nom. Cette option indique à rkhunter d'ajouter au fichier journal existant. Si le fichier journal n'existe pas, il sera créé.
--bindir <répertoire>...
Cette option modifie les répertoires dans lesquels rkhunter recherche les différentes commandes dont il a besoin (c'est-à-dire son PATH). La valeur par défaut est le PATH racine et une liste interne de certains répertoires de commandes courants. Par défaut, un répertoire spécifié sera ajouté à la liste par défaut. Cependant, si le nom du répertoire commence par le caractère '+', il sera ajouté au début de la liste (c'est-à-dire qu'il sera placé au début de la liste).
--cs2, --color-set2
Par défaut, rkhunter affiche les résultats de ses tests en couleur. Les couleurs utilisées sont le vert pour les tests réussis, le rouge pour les tests échoués (avertissements) et le jaune pour les tests ignorés. Ces couleurs sont visibles lorsqu'un arrière-plan noir est utilisé, mais difficiles à voir sur un fond blanc. Cette option indique à rkhunter d'utiliser un ensemble de couleurs différent, plus adapté à un fond blanc.
--configfile <fichier>
Le processus d'installation indiquera automatiquement à rkhunter où se trouve son fichier de configuration. Cependant, si nécessaire, cette option peut être utilisée pour spécifier un chemin différent.

Si un fichier de configuration local ou un répertoire local doit être utilisé, il doit résider dans le même répertoire que le fichier de configuration spécifié par cette option.

--cronjob
Ceci est similaire à l'option de commande --check, mais elle désactive plusieurs options interactives. Lorsque cette option est utilisée, --check, --nocolors et --skip-keypress sont supposées. Par défaut, aucune sortie n'est envoyée à stdout, donc l'option --report-warnings-only peut être utile avec cette option.
--dbdir <répertoire>
Le processus d'installation configurera automatiquement où les fichiers de données sont stockés pour rkhunter. Cependant, si nécessaire, cette option peut être utilisée pour spécifier un répertoire différent. Le répertoire peut être en lecture seule, après l'installation, à condition que ni les options --update ni --propupd ne soient spécifiées, et que l'option --versioncheck ne soit pas spécifiée si ROTATE_MIRRORS est défini sur 1 dans le fichier de configuration.
--debug
Ceci est une option spéciale principalement pour les développeurs. Elle ne produit aucune sortie sur stdout. La journalisation normale continuera comme par défaut ou comme spécifié par l'option --logfile, et la sortie de débogage sera dans un nom de fichier généré aléatoirement qui commence par /tmp/rkhunter-debug.
--disable <test>[,<test>...]
Cette option indique à rkhunter de ne pas exécuter les tests spécifiés. Lisez le fichier README pour plus d'informations sur les noms de tests. Par défaut, aucun test n'est désactivé.
--display-logfile
Cette option affichera le fichier journal à l'écran une fois que rkhunter aura terminé.
--enable <test>[,<test>...]
Cette option indique à rkhunter de n'exécuter que les tests spécifiés. Si un seul nom de test, autre que all, est donné, alors l'option --skip-keypress est supposée. Lisez le fichier README pour plus d'informations sur les noms de tests. Par défaut, tous les tests sont activés. Tous les noms de tests sont listés ci-dessous sous TESTS.
--hash {MD5 | SHA1 | SHA224 | SHA256 | SHA384 | SHA512 |
NONE | <commande>}
La vérification des propriétés de fichier et l'option de commande --propupd utiliseront une fonction de hachage pour déterminer la valeur de hachage actuelle d'un fichier. Cette option indique à rkhunter quelle fonction de hachage utiliser. Les options MD5 et SHA rechercheront la commande pertinente et, si elle n'est pas trouvée, un script de support perl sera utilisé pour voir si un module perl prenant en charge la fonction a été installé. Alternativement, une commande spécifique peut être spécifiée. Une valeur de NONE peut être utilisée pour indiquer que les valeurs de hachage ne doivent pas être obtenues ou utilisées dans le cadre de la vérification des propriétés de fichier. La valeur par défaut est SHA256.

Les systèmes utilisant le pré-liage doivent utiliser MD5, SHA1 ou NONE.

--lang, --language <langue>
Cette option spécifie la langue à utiliser pour les tests et les résultats affichés. Les langues actuellement prises en charge peuvent être vues avec l'option de commande --list. La valeur par défaut est en (anglais). Si un message à afficher ne peut être trouvé dans le fichier de langue, la version anglaise sera utilisée. Par conséquent, le fichier de langue anglaise doit toujours être présent. L'option de commande --update mettra à jour les fichiers de langue lorsque de nouvelles versions seront disponibles.
-l, --logfile [fichier]
Par défaut, rkhunter écrira un fichier journal. L'emplacement par défaut du fichier est /var/log/rkhunter.log. Cependant, cet emplacement peut être modifié en utilisant cette option. Si /dev/null est spécifié comme fichier journal, aucun fichier journal ne sera écrit. Si aucun fichier spécifique n'est donné, la valeur par défaut sera utilisée. Par défaut, rkhunter créera un nouveau fichier journal chaque fois qu'il s'exécutera. Tout fichier journal précédemment existant est déplacé et a .old ajouté à son nom.
--noappend-log
Cette option ramène rkhunter à son comportement par défaut de création d'un nouveau fichier journal plutôt que de l'ajouter.
--nocf

Cette option n'est valide que lorsque l'option de ligne de commande --disable est utilisée. Lorsque l'option --disable est utilisée, par défaut, l'option du fichier de configuration pour désactiver les tests est également utilisée pour déterminer quels tests exécuter. Si seule l'option --disable doit être utilisée pour déterminer quels tests exécuter, alors --nocf doit être donné.
--nocolors
Cette option empêche l'affichage du résultat de chaque test dans une couleur spécifique. La couleur par défaut, généralement l'inverse de la couleur de fond, sera utilisée (typiquement juste le noir et blanc).
--nolog
Cette option indique à rkhunter de ne rien écrire dans un fichier journal.
--nomow, --no-mail-on-warning
Le fichier de configuration a une option qui envoie un simple message électronique à un utilisateur si rkhunter détecte des avertissements lors des vérifications du système. Cette option de ligne de commande remplace l'option du fichier de configuration et empêche l'envoi d'un message électronique. La valeur par défaut du fichier de configuration est de ne pas envoyer de message par courrier électronique.
--ns, --nosummary
Lorsque l'option de commande --check est utilisée, un bref résumé des résultats est affiché à la fin par défaut. Cette option empêche l'affichage du résumé.
--novl, --no-verbose-logging
Pendant certains tests, rkhunter enregistre beaucoup d'informations. L'utilisation de cette option réduit la quantité de journalisation et peut donc améliorer les performances de rkhunter. Cependant, le fichier journal contiendra moins d'informations en cas d'avertissements. Par défaut, la journalisation détaillée est activée.
--pkgmgr {RPM | DPKG | BSD | BSDng | SOLARIS | NONE}
Cette option est utilisée lors de la vérification des propriétés de fichier ou lorsque l'option de commande --propupd est donnée. Elle indique à rkhunter que les valeurs actuelles des propriétés de fichier doivent être obtenues auprès du gestionnaire de paquets concerné. Voir le fichier README pour plus de détails sur cette option. La valeur par défaut est NONE, ce qui signifie de ne pas utiliser de gestionnaire de paquets.
-q, --quiet
Cette option indique à rkhunter de ne pas afficher de sortie. Elle peut être utile lorsque seul le code de sortie doit être vérifié. D'autres options peuvent être utilisées avec celle-ci pour forcer l'affichage uniquement d'éléments spécifiques.
--rwo, --report-warnings-only
Cette option ne fait afficher que les messages d'avertissement. Cela peut être utile lorsque rkhunter est exécuté via cron. D'autres options peuvent être utilisées pour forcer l'affichage d'autres informations.
--sk, --skip-keypress
Lorsque l'option de commande --check est utilisée, après certaines sections de tests, l'utilisateur sera invité à appuyer sur la touche Entrée pour continuer. Cette option désactive cette fonctionnalité, et rkhunter s'exécutera jusqu'à ce que tous les tests soient terminés.

Si cette option n'a pas été donnée, et que l'utilisateur est invité à appuyer sur la touche Entrée, un seul caractère 's', en majuscule ou en minuscule, peut être donné suivi de la touche Entrée. rkhunter continuera alors les tests sans demander à nouveau à l'utilisateur (comme si cette option avait été donnée).

--summary
Cette option affichera le résumé des résultats des tests. C'est le comportement par défaut.
--syslog [facility.priority]
Lorsque l'option de commande --check est utilisée, cette option enregistrera les heures de début et de fin dans syslog. Par défaut, rien n'est enregistré dans syslog, mais si l'option est utilisée, le niveau par défaut est authpriv.notice.
rkhunter(8)

NAME

rkhunter – RootKit Hunter

SYNOPSIS

rkhunter [‑update | ‑update|‑propupd|‑check|‑clean] [‑hash|‑entropy|‑unhide|‑disable|‑enable] [test ...]

test is one of the tests listed in the TESTS section.

rkhunter [‑? | ‑help]

rkhunter [‑version]

DESCRIPTION

RootKit Hunter (rkhunter) is an utility that scans for rootkits, backdoors and local exploits. Rkhunter does this by performing various checks on the local system. These checks include:

  • Checking for suspicious file properties (e.g. file attributes, permissions and timestamps).
  • Checking for the presence of known rootkits.
  • Checking for suspicious running processes and loaded kernel modules.
  • Checking for default web server configuration files.
  • Checking for suspicious network configurations.
  • Checking for the presence of text strings in the kernel and boot code.
  • Checking for modifications to commonly modified files.
  • Checking for the presence of malware.

The output of the tests is logged to /var/log/rkhunter.log.

COMMAND OPTIONS

The command options are described below.

-c, --check
Perform a system scan for rootkits. The results of the scan are logged to /var/log/rkhunter.log.
-h, --hash
Generate MD5 hashes for specified files. If no files are specified then the hashes for the files in the rootkit_files.txt database will be generated.
-l, --list
List the available tests or options.
-p, --propupd
Update the properties database. This command should be run after a system has been installed or updated.
-u, --update
Update the rkhunter data files. These are the files that rkhunter uses to determine if a system is infected.
-V, --version
Display the version of rkhunter.

OPTIONS

The following options can be used with the above commands.

-a, --append-log
Append the output to the log file. The default is to overwrite the log file.
-c2, --color-set2
Use the second colour set for displaying the output. This colour set is intended for use when X Window is in use.
-d, --disable
Disable tests or options. The test or option to be disabled is specified in the configuration file, or on the command line.
-e, --enable
Enable tests or options. The test or option to be enabled is specified in the configuration file, or on the command line.
-f, --config-file

Use the specified configuration file. The default configuration file is.

/etc/rkhunter.conf

The configuration file can contain the following options:

append_log
Append the output to the log file. The default is to overwrite the log file.
color_set
Use the specified colour set for displaying the output. The default colour set is 1.
csleep
Wait the specified number of seconds between the checks. The default is to not wait.
dbdir
The directory where the rkhunter database files are stored. The default is /var/lib/rkhunter/db.
disable_rkhunter_log
If set to 1 then logging to the rkhunter log file will be disabled. The default is 0.
dgoogle
Disable the Google search tests. The default is to enable them.
dportopen
Disable the portknocking test. The default is to enable it.
disable_syslog
If set to 1 then logging to syslog will be disabled. The default is 0.
hash_list_enabled
If set to 1 then the hash comparison tests will be enabled. The default is 1.
hmax
Maximum number of hash files to compare. The default is 256.
hidden_dir
List of directories to be searched for hidden files. The default is /root/.
hidden_file
List of hidden files to be searched for. The default is.
high_frequency_rootkit_scan
If set to 1 then the high frequency rootkit scan will be enabled. The default is 0.
history_file
The file used to store the command history. The default is /var/log/rkhunter.history.
iptables_check
If set to 1 then the iptables rules will be checked. The default is 1.
lang
The language to use for the messages. The default is en.
logprefix
Prefix for the log file. The default is empty.
logtarget
The target for the log file. The default is FILE.
mail_allow
List of email addresses to send the results to. The default is empty.
mail_on_warning
If set to 1 then an email will be sent when a warning is generated. The default is 0.
mail_r=
List of email addresses to send the results to. The default is empty.
mail_summary
If set to 1 then a summary email will be sent. The default is 0.
max_module_size
Maximum size of a kernel module. The default is 1000000.
rhosts
If set to 1 then the rhosts files will be checked. The default is 1.
rootkit_files
List of files to be checked for rootkits. The default is /etc/rkhunter.dat.
runtimes
Wait the specified number of seconds between the tests. The default is to not wait.
scan_binary
If set to 1 then the binary files will be scanned. The default is 1.
scan_file
List of files to be scanned. The default is empty.
scan_hidden
If set to 1 then hidden files and directories will be scanned. The default is 1.
suspscan
If set to 1 then the suspicious scan will be enabled. The default is 1.
suspscan_max
Maximum number of suspicious files to scan. The default is 100.
tmpdir
The directory where temporary files are created. The default is /tmp.
use_ssh
If set to 1 then SSH will be used to connect to remote hosts. The default is 0.
version_check
If set to 1 then the version check will be enabled. The default is 1.
webrootkit
List of directories to be checked for web rootkits. The default is /var/www.
webrootkit_files
List of files to be checked for web rootkits. The default is /etc/rkhunter.web.

The configuration file is read when rkhunter is run. Any options specified on the command line will override the options in the configuration file.

--tmpdir <directory>
The installation process will automatically configure where temporary files are to be created. However, if necessary, this option can be used to specify a different directory. The directory must not be a symbolic link, and must be secure (root access only).
--vl, --verbose-logging
This option tells rkhunter that when it runs some tests, it should log as much information as possible. This can be useful when trying to diagnose why a warning has occurred, but it obviously also takes more time. The default is to use verbose logging.
-x, --autox
When this option is used, rkhunter will try and detect if the X Window system is in use. If it is in use, then the second color set will automatically be used (see the --color-set2 option). This allows rkhunter to be run on, for example, a server console (where X is not present, so the default color set should be used), and on a users terminal (where X is in use, so the second color set should be used). In both cases rkhunter will use the correct color set. The configuration file default is to try and detect X.
-X, --no-autox
This option prevents rkhunter from automatically detecting if the X Window system is being used. See the --autox option.
