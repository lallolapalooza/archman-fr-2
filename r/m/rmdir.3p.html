RMDIR(3P) Manuel du programmeur POSIX RMDIR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

rmdir — supprimer un répertoire

SYNTAXE

#include <unistd.h>
int rmdir(const char *path);

DESCRIPTION

La fonction rmdir() supprime un répertoire dont le nom est fourni par path. Le répertoire n'est supprimé que s'il est vide.

Si le répertoire est le répertoire racine ou le répertoire de travail courant de tout processus, il est indéterminé si la fonction réussit, ou si elle échoue et définit errno sur [EBUSY].

Si path désigne un lien symbolique, rmdir() échoue et définit errno sur [ENOTDIR].

Si l'argument path fait référence à un chemin dont le dernier composant est soit point (dot) soit double point (dot-dot), rmdir() échoue.

Si le compte de liens du répertoire devient 0 et qu'aucun processus n'a le répertoire ouvert, l'espace occupé par le répertoire est libéré et le répertoire n'est plus accessible. Si un ou plusieurs processus ont le répertoire ouvert lorsque le dernier lien est supprimé, les entrées point et double point, si elles sont présentes, sont supprimées avant le retour de rmdir() et aucune nouvelle entrée ne peut être créée dans le répertoire, mais le répertoire n'est pas supprimé tant que toutes les références au répertoire ne sont pas fermées.

Si le répertoire n'est pas un répertoire vide, rmdir() échoue et définit errno sur [EEXIST] ou [ENOTEMPTY].

En cas de succès, rmdir() marque pour mise à jour les horodatages de dernière modification des données et de dernier changement d'état du fichier du répertoire parent.

VALEUR EN RETOUR

En cas de succès, la fonction rmdir() retourne 0. Sinon, -1 est retourné, et errno est défini pour indiquer l'erreur. Si -1 est retourné, le répertoire nommé n'est pas modifié.

ERREURS

La fonction rmdir() échoue si :

EACCES
La permission de recherche est refusée sur un composant du préfixe du chemin, ou la permission d'écriture est refusée sur le répertoire parent du répertoire à supprimer.
EBUSY
Le répertoire à supprimer est actuellement utilisé par le système ou un processus et l'implémentation considère cela comme une erreur.
[EEXIST] ou [ENOTEMPTY]

L'argument path désigne un répertoire qui n'est pas vide, ou il existe des liens physiques vers le répertoire autres que point ou une entrée unique dans double point.
EINVAL
L'argument path contient un dernier composant qui est un point.
EIO
Une erreur d'E/S physique s'est produite.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un composant d'un nom de fichier est supérieure à {NAME_MAX}.
ENOENT
Un composant de path ne désigne pas un fichier existant, ou l'argument path désigne un répertoire inexistant ou pointe vers une chaîne vide.
ENOTDIR
Un composant de path désigne un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
[EPERM] ou [EACCES]

Le drapeau S_ISVTX est défini sur le répertoire contenant le fichier référencé par l'argument path et le processus ne satisfait pas aux critères spécifiés dans le volume Bases de Définitions de POSIX.1‐2017, Section 4.3, Protection des Répertoires.
EROFS
L'entrée de répertoire à supprimer réside sur un système de fichiers en lecture seule.

La fonction rmdir() peut échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un nom de chemin dépasse {PATH_MAX}, ou la résolution du nom d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.

EXEMPLES

Suppression d'un Répertoire

L'exemple suivant montre comment supprimer un répertoire nommé /home/cnd/mod1.

#include <unistd.h>
int status;
...
status = rmdir("/home/cnd/mod1");

UTILISATION PAR L’APPLICATION

Aucune.

RATIONNEL

La fonction rmdir() et la fonction rename() proviennent de 4.2 BSD, et elles utilisaient [ENOTEMPTY] pour la condition où le répertoire à supprimer n'existe pas ou new existe déjà. Lorsque la norme /usr/group de 1984 a été publiée, elle contenait [EEXIST] à la place. Lorsque ces fonctions ont été adoptées dans System V, la norme /usr/group de 1984 a été utilisée comme référence. Par conséquent, plusieurs applications et implémentations existantes prennent en charge/utilisent les deux formes, et aucun accord n'a pu être trouvé sur l'une ou l'autre valeur. Toutes les implémentations sont tenues de fournir à la fois [EEXIST] et [ENOTEMPTY] dans <errno.h> avec des valeurs distinctes, de sorte que les applications puissent utiliser les deux valeurs dans les instructions case du langage C.

La signification de la suppression de pathname/dot n'est pas claire, car le nom du fichier (répertoire) dans le répertoire parent à supprimer n'est pas clair, en particulier en présence de plusieurs liens vers un répertoire.

La norme POSIX.1‐1990 était muette quant au comportement de rmdir() lorsqu'il existe plusieurs liens physiques vers le répertoire à supprimer. L'exigence de définir errno sur [EEXIST] ou [ENOTEMPTY] clarifie le comportement dans ce cas.

Si le répertoire de travail courant du processus est supprimé, cela devrait être une erreur autorisée.

Presque toutes les implémentations existantes détectent [ENOTEMPTY] ou le cas de double point. Le texte de la Section 2.3, Numéros d'Erreur sur le retour de l'une des erreurs possibles permet à ce comportement de continuer. L'erreur [ELOOP] peut être retournée si plus de {SYMLOOP_MAX} liens symboliques sont rencontrés lors de la résolution de l'argument path.
