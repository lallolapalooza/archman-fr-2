rmid(1) Outils d'invocation de méthode distante (RMI) rmid(1)

NOM

rmid - Lance le démon du système d'activation qui permet d'enregistrer et d'activer des objets dans une Machine Virtuelle Java (JVM).

SYNTAXE

rmid [options]
options
Les options en ligne de commande. Voir Options.

DESCRIPTION

La commande rmid lance le démon du système d'activation. Le démon du système d'activation doit être démarré avant que les objets activables puissent être enregistrés auprès du système d'activation ou activés dans une JVM. Pour plus de détails sur la façon d'écrire des programmes utilisant des objets activables, consultez le tutoriel Utilisation de l'activation à l'adresse http://docs.oracle.com/javase/8/docs/technotes/guides/rmi/activation/overview.html

Démarrez le démon en exécutant la commande rmid et en spécifiant un fichier de politique de sécurité, comme suit :

rmid -J-Djava.security.policy=rmid.policy

Lorsque vous exécutez l'implémentation d'Oracle de la commande rmid, par défaut, vous devez spécifier un fichier de politique de sécurité afin que la commande rmid puisse vérifier si les informations de chaque ActivationGroupDesc sont autorisées à être utilisées pour démarrer une JVM pour un groupe d'activation. Plus précisément, la commande et les options spécifiées par CommandEnvironment et toutes les propriétés passées à un constructeur ActivationGroupDesc doivent maintenant être explicitement autorisées dans le fichier de politique de sécurité pour la commande rmid. La valeur de la propriété sun.rmi.activation.execPolicy dicte la politique que la commande rmid utilise pour déterminer si les informations d'un ActivationGroupDesc peuvent être utilisées pour démarrer une JVM pour un groupe d'activation. Pour plus d'informations, voir la description de l'option -J-Dsun.rmi.activation.execPolicy=policy.

L'exécution de la commande rmid lance l'Activator et un registre interne sur le port par défaut 1098 et lie un ActivationSystem au nom java.rmi.activation.ActivationSystem dans ce registre interne.

Pour spécifier un port alternatif pour le registre, vous devez spécifier l'option -port lors de l'exécution de la commande rmid. Par exemple, la commande suivante démarre le démon du système d'activation et un registre sur le port par défaut du registre, 1099.

rmid -J-Djava.security.policy=rmid.policy -port 1099

Une alternative au démarrage de rmid depuis la ligne de commande est de configurer inetd (Oracle Solaris) ou xinetd (Linux) pour démarrer rmid à la demande.

Lorsque RMID démarre, il tente d'obtenir un canal hérité (hérité de inetd/xinetd) en appelant la méthode System.inheritedChannel. Si le canal hérité est nul ou n'est pas une instance de java.nio.channels.ServerSocketChannel, alors RMID suppose qu'il n'a pas été démarré par inetd/xinetd, et il démarre comme décrit précédemment.

Si le canal hérité est une instance de ServerSocketChannel, alors RMID utilise le java.net.ServerSocket obtenu à partir du ServerSocketChannel comme socket serveur qui accepte les requêtes pour les objets distants qu'il exporte : le registre dans lequel java.rmi.activation.ActivationSystem est lié et l'objet distant java.rmi.activation.Activator. Dans ce mode, RMID se comporte de la même manière que lorsqu'il est démarré depuis la ligne de commande, sauf dans les cas suivants :

•
La sortie imprimée sur System.err est redirigée vers un fichier. Ce fichier est situé dans le répertoire spécifié par la propriété système java.io.tmpdir (typiquement /var/tmp ou /tmp) avec le préfixe rmid-err et le suffixe tmp.
•
L'option -port n'est pas autorisée. Si cette option est spécifiée, RMID se termine avec un message d'erreur.
•
L'option -log est requise. Si cette option n'est pas spécifiée, RMID se termine avec un message d'erreur.

Consultez les pages de manuel de inetd (Oracle Solaris) ou xinetd (Linux) pour savoir comment configurer les services à démarrer à la demande.

OPTIONS

-Coption

Spécifie une option passée comme argument en ligne de commande à chaque processus enfant (groupe d'activation) de la commande rmid lorsque ce processus est créé. Par exemple, vous pouvez passer une propriété à chaque machine virtuelle lancée par le démon du système d'activation : 
rmid -C-Dsome.property=value

Cette capacité à passer des arguments en ligne de commande aux processus enfants peut être utile pour le débogage. Par exemple, la commande suivante active la journalisation des appels serveur dans toutes les JVM enfants.

rmid -C-Djava.rmi.server.logCalls=true
-Joption

Spécifie une option passée à l'interpréteur Java exécutant RMID. Par exemple, pour spécifier que la commande rmid utilise un fichier de politique nommé rmid.policy, l'option -J peut être utilisée pour définir la propriété java.security.policy sur la ligne de commande rmid, par exemple : 
rmid -J-Djava.security.policy-rmid.policy
-J-Dsun.rmi.activation.execPolicy=policy

Spécifie la politique que RMID emploie pour vérifier les commandes et les options de ligne de commande utilisées pour démarrer la JVM dans laquelle un groupe d'activation s'exécute. Veuillez noter que cette option existe uniquement dans l'implémentation d'Oracle du démon d'activation Java RMI. Si cette propriété n'est pas spécifiée sur la ligne de commande, le résultat est le même que si -J-Dsun.rmi.activation.execPolicy=default avait été spécifié. Les valeurs possibles de policy peuvent être default, policyClassName, ou none.
•
default

La valeur default ou non spécifiée execPolicy permet à la commande rmid d'exécuter des commandes avec des options de ligne de commande spécifiques uniquement lorsque la commande rmid a reçu l'autorisation d'exécuter ces commandes et options dans le fichier de politique de sécurité que la commande rmid utilise. Seule l'implémentation par défaut du groupe d'activation peut être utilisée avec la politique d'exécution par défaut.

La commande rmid démarre une JVM pour un groupe d'activation avec les informations du descripteur de groupe d'activation enregistré du groupe, un ActivationGroupDesc. Le descripteur de groupe spécifie un ActivationGroupDesc.CommandEnvironment optionnel qui comprend la commande à exécuter pour démarrer le groupe d'activation et toutes les options de ligne de commande à ajouter à la ligne de commande. Par défaut, la commande rmid utilise la commande java trouvée dans java.home. Le descripteur de groupe contient également des remplacements de propriétés qui sont ajoutés à la ligne de commande sous forme d'options définies comme : -D<propriété>=<valeur>. La permission com.sun.rmi.rmid.ExecPermission accorde à la commande rmid la permission d'exécuter une commande spécifiée dans le CommandEnvironment du descripteur de groupe pour démarrer un groupe d'activation. La permission com.sun.rmi.rmid.ExecOptionPermission permet à la commande rmid d'utiliser les options de ligne de commande, spécifiées comme remplacements de propriétés dans le descripteur de groupe ou comme options dans le CommandEnvironment lors du démarrage du groupe d'activation. Lors de l'octroi à la commande rmid de la permission d'exécuter diverses commandes et options, les permissions ExecPermission et ExecOptionPermission doivent être accordées à toutes les sources de code.

ExecPermission

La classe ExecPermission représente la permission pour la commande rmid d'exécuter une commande spécifique pour démarrer un groupe d'activation.

Syntaxe : Le nom d'une ExecPermission est le nom du chemin d'une commande pour laquelle la commande rmid est autorisée à exécuter. Un nom de chemin se terminant par une barre oblique (/) et un astérisque (*) indique que tous les fichiers contenus dans ce répertoire

où / est le caractère séparateur de fichier, File.separatorChar. Un nom de chemin qui se termine par une barre oblique (/) et un signe moins (-) indique tous les fichiers et sous-répertoires contenus dans ce répertoire (récursivement). Un nom de chemin constitué du jeton spécial <<TOUS FICHIERS>> correspond à n'importe quel fichier.

Un nom de chemin constitué d'un astérisque (*) indique tous les fichiers du répertoire courant. Un nom de chemin constitué d'un signe moins (-) indique tous les fichiers du répertoire courant et (récursivement) tous les fichiers et sous-répertoires contenus dans le répertoire courant.

ExecOptionPermission

La classe ExecOptionPermission représente la permission pour la commande rmid d'utiliser une option de ligne de commande spécifique lors du démarrage d'un groupe d'activation. Le nom d'une ExecOptionPermission est la valeur d'une option de ligne de commande.

Syntaxe : Les options prennent en charge un schéma de caractères joker limité. Un astérisque signifie une correspondance joker, et il peut apparaître comme le nom de l'option lui-même (correspond à n'importe quelle option), ou un astérisque (*) peut apparaître à la fin du nom de l'option uniquement lorsque l'astérisque (*) suit un point (.) ou un signe égal (=).

Par exemple : * ou -Dmydir.* ou -Da.b.c=* sont valides, mais *mydir ou -Da*b ou ab* ne le sont pas.

Fichier de stratégie pour rmid

Lorsque vous accordez à la commande rmid la permission d'exécuter diverses commandes et options, les permissions ExecPermission et ExecOptionPermission doivent être accordées à toutes les sources de code (universellement). Il est sûr d'accorder ces permissions universellement car seule la commande rmid vérifie ces permissions.

Un exemple de fichier de stratégie qui accorde diverses permissions d'exécution à la commande rmid est le suivant :

grant {
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/java/jdk1.7.0/solaris/bin/java";
    permission com.sun.rmi.rmid.ExecPermission
        "/files/apps/rmidcmds/*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.policy=/files/policies/group.policy";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Djava.security.debug=*";
    permission com.sun.rmi.rmid.ExecOptionPermission
        "-Dsun.rmi.*";
};

La première permission accordée permet à la commande rmid d'exécuter la version 1.7.0 de la commande java, spécifiée par son chemin explicite. Par défaut, la version de la commande java trouvée dans java.home est utilisée (la même que celle utilisée par la commande rmid), et il n'est pas nécessaire de la spécifier dans le fichier de stratégie. La deuxième permission permet à la commande rmid d'exécuter n'importe quelle commande dans le répertoire /files/apps/rmidcmds.

La troisième permission accordée, une ExecOptionPermission, permet à la commande rmid de démarrer un groupe d'activation qui définit le fichier de stratégie de sécurité comme étant /files/policies/group.policy. La permission suivante permet que la propriété java.security.debug soit utilisée par un groupe d'activation. La dernière permission permet que toute propriété de la hiérarchie de noms de propriétés sun.rmi soit utilisée par les groupes d'activation.

Pour démarrer la commande rmid avec un fichier de stratégie, la propriété java.security.policy doit être spécifiée sur la ligne de commande de rmid, par exemple :

rmid -J-Djava.security.policy=rmid.policy.

•
<nomClassePolitique>

Si le comportement par défaut n'est pas assez flexible, alors un administrateur peut fournir, lors du démarrage de la commande rmid, le nom d'une classe dont la méthode checkExecCommand est exécutée pour vérifier les commandes à exécuter par la commande rmid.

Le nomClassePolitique spécifie une classe publique avec un constructeur public sans argument et une implémentation de la méthode checkExecCommand suivante :

 public void checkExecCommand(ActivationGroupDesc desc, String[] command)
        throws SecurityException;

Avant de démarrer un groupe d'activation, la commande rmid appelle la méthode checkExecCommand de la politique et lui transmet le descripteur du groupe d'activation et un tableau contenant la commande complète pour démarrer le groupe d'activation. Si checkExecCommand lève une SecurityException, alors la commande rmid ne démarre pas le groupe d'activation et une ActivationException est levée à l'appelant tentant d'activer l'objet.

•
none

Si la valeur de la propriété sun.rmi.activation.execPolicy est none, alors la commande rmid n'effectue aucune validation des commandes pour démarrer les groupes d'activation.

-log dir

Spécifie le nom du répertoire que le démon du système d'activation utilise pour écrire sa base de données et les informations associées. Le répertoire de journalisation par défaut consiste à créer un journal, dans le répertoire où la commande rmid a été exécutée.
-port port

Spécifie le port utilisé par le registre. Le démon du système d'activation lie le ActivationSystem, avec le nom java.rmi.activation.ActivationSystem, dans ce registre. L' ActivationSystem sur la machine locale peut être obtenu en utilisant l'appel de méthode Naming.lookup suivant : 
import java.rmi.*; 
    import java.rmi.activation.*;
    ActivationSystem system; system = (ActivationSystem)
    Naming.lookup("//:port/java.rmi.activation.ActivationSystem");
-stop

Arrête l'invocation courante de la commande rmid pour un port spécifié par l'option -port. Si aucun port n'est spécifié, cette option arrête l'invocation de rmid en cours d'exécution sur le port 1098.

VARIABLES D'ENVIRONNEMENT

CLASSPATH
Utilisé pour fournir au système un chemin vers les classes définies par l'utilisateur. Les répertoires sont séparés par des deux-points, par exemple : .:/usr/local/java/classes.
