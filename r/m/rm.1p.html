PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

rm — supprimer des entrées de répertoire

SYNTAXE

rm [-iRr] fichier...
rm -f [-iRr] [fichier...]

DESCRIPTION

L'utilitaire rm supprime l'entrée de répertoire spécifiée par chaque argument fichier.

Si l'un des fichiers dot (.) ou dot-dot (..) est spécifié comme partie nom de base d'un opérande (c'est-à-dire le composant de chemin final) ou si un opérande aboutit au répertoire racine, rm écrit un message de diagnostic sur la sortie d'erreur standard et ne fait rien de plus avec de tels opérandes.

Pour chaque fichier, les étapes suivantes sont effectuées :

1.
Si le fichier n'existe pas :
a.
Si l'option -f n'est pas spécifiée, rm écrit un message de diagnostic sur la sortie d'erreur standard.
b.
Passe aux fichiers restants.
2.
Si le fichier est de type répertoire, les étapes suivantes sont effectuées :
a.
Si ni l'option -R ni l'option -r n'est spécifiée, rm écrit un message de diagnostic sur la sortie d'erreur standard, ne fait rien de plus avec le fichier et passe aux fichiers restants.
b.
Si le fichier est un répertoire vide, rm peut passer à l'étape 2d. Si l'option -f n'est pas spécifiée, et soit les permissions du fichier ne permettent pas l'écriture et l'entrée standard est un terminal, soit l'option -i est spécifiée, rm écrit une invite sur la sortie d'erreur standard et lit une ligne depuis l'entrée standard. Si la réponse n'est pas affirmative, rm ne fait rien de plus avec le fichier courant et passe aux fichiers restants.
c.
Pour chaque entrée contenue dans le fichier, autre que dot ou dot-dot, les quatre étapes listées ici (1 à 4) sont effectuées avec l'entrée comme si c'était un opérande fichier. L'utilitaire rm ne traverse pas les répertoires en suivant les liens symboliques vers d'autres parties de la hiérarchie, mais supprime les liens eux-mêmes.
d.
Si l'option -i est spécifiée, rm écrit une invite sur la sortie d'erreur standard et lit une ligne depuis l'entrée standard. Si la réponse n'est pas affirmative, rm ne fait rien de plus avec le fichier courant et passe aux fichiers restants.
3.
Si le fichier n'est pas de type répertoire, que l'option -f n'est pas spécifiée, et soit les permissions du fichier ne permettent pas l'écriture et l'entrée standard est un terminal, soit l'option -i est spécifiée, rm écrit une invite sur la sortie d'erreur standard et lit une ligne depuis l'entrée standard. Si la réponse n'est pas affirmative, rm ne fait rien de plus avec le fichier courant et passe aux fichiers restants.
4.
Si le fichier courant est un répertoire, rm effectue des actions équivalentes à la fonction rmdir() définie dans le volume Interfaces système de POSIX.1‐2017, appelée avec un chemin du fichier courant utilisé comme argument path. Si le fichier courant n'est pas un répertoire, rm effectue des actions équivalentes à la fonction unlink() définie dans le volume Interfaces système de POSIX.1‐2017, appelée avec un chemin du fichier courant utilisé comme argument path.

Si cela échoue pour une raison quelconque, rm écrit un message de diagnostic sur la sortie d'erreur standard, ne fait rien de plus avec le fichier courant et passe aux fichiers restants.

L'utilitaire rm est capable de descendre à des profondeurs arbitraires dans une hiérarchie de fichiers, et ne doit pas échouer en raison de limitations de longueur de chemin (sauf si un opérande spécifié par l'utilisateur dépasse les limitations du système).

OPTIONS

L'utilitaire rm doit être conforme aux directives de syntaxe utilitaire du volume Définitions de base de POSIX.1‐2017, Section 12.2.

Les options suivantes doivent être prises en charge :

-f
Ne demande pas de confirmation. Ne produit pas de messages de diagnostic et ne modifie pas le code de sortie en cas d'absence d'opérandes de fichier, ou en cas d'opérandes qui n'existent pas. Toute occurrence précédente de l'option -i est ignorée.
-i
Demande une confirmation comme décrit précédemment. Toute occurrence précédente de l'option -f est ignorée.
-R
Supprime les hiérarchies de fichiers. Voir la DESCRIPTION.
-r
Équivalent à -R.

OPERANDES

L'opérande suivant doit être pris en charge :

fichier
Un nom de chemin d'une entrée de répertoire à supprimer.

ENTRÉE STANDARD

L'entrée standard est utilisée pour lire une ligne de réponse à chaque invite spécifiée dans la section SORTIE STANDARD. Sinon, l'entrée standard n'est pas utilisée.

FICHIERS ENTRÉE

Aucun.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de rm :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour le comportement des plages, des classes d'équivalence et des éléments de collation multicaractères utilisés dans l'expression régulière étendue définie pour le mot-clé yesexpr de la catégorie LC_MESSAGES.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments) et le comportement des classes de caractères dans les expressions régulières utilisées dans l'expression régulière étendue définie pour le mot-clé yesexpr de la catégorie LC_MESSAGES.
LC_MESSAGES

Détermine la locale utilisée pour traiter les réponses affirmatives, et la locale utilisée pour affecter le format et le contenu des messages de diagnostic et des invites écrites sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

NAME

rm

remove files or directories

SYNOPSIS

rm [ -f | -i ] file ...

rm -r | -R | --preserve-root [ -f | -i ] file ...

DESCRIPTION

The rm utility shall remove the entries for one or more files from the file system. The default action is to remove the files pointed to by each file argument.

If the rm utility is invoked for a regular file, the file shall be removed unless it is write-protected.

If the file pointed to by a file argument is a symbolic link, the symbolic link itself shall be removed, not the file to which it refers. This is a consequence of the dependence on the unlink() functionality.

If a file is a write-once, read-only file, it shall be removed. (See also unlink(2) and remove(3)).

If a file argument does not exist, the command shall not report an error, nor modify the exit status to reflect an error, unless the -f option is specified.

If a file argument is a directory, the behavior is implementation-defined unless the -r or -R options are specified.

The -r and -R options shall cause the rm utility to remove the contents of directories recursively.

The --preserve-root option shall be supported and shall be the default behavior. This option shall cause the rm utility to refuse to attempt to operate on / unless the -f option is specified.

If the -r or -R option is specified, and the user attempts to remove the directory /, the rm utility shall fail with an error message unless the -f option is specified.

If the rm utility would remove a file for which the user does not have write permission, or a directory for which the user does not have write and search permissions, the rm utility shall prompt the user for confirmation before removing the file unless the -f option is specified. The prompt shall be written to standard error. The response shall be read from standard input.

The -i option shall cause rm to prompt for confirmation before attempting to remove each file, regardless of its permissions. The prompt shall be written to standard error. The response shall be read from standard input.

If a non-affirmative response is received from the user, the file shall not be removed, and the rm utility shall continue with the next file. If an affirmative response is received, the file shall be removed.

If the standard input is not a terminal, and the -i option is used, rm shall not prompt for confirmation and shall behave as if the user had responded affirmatively.

OPTIONS

The following options shall be supported:

-f, --force
Force deletion. Override file permissions. Ignore nonexistent files and arguments, never prompt.
-i, --interactive
Prompt before every removal.
-r, -R, --recursive
Remove directories and their contents recursively.
--preserve-root
Do not remove /. This is the default.

OPERANDS

The following operands shall be supported:

file
A pathname of a file or directory to be removed.

STDIN

The standard input shall be used for prompts from the -i option or when write permission is denied.

INPUT FILES

None.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of rm:

COLUMNS
Determine the locale's number of columns used for displaying output. See locale(7).
LANG
Provide a default locale for the interpretation of the locale's data (formatting messages and data related to the locale's specific information). See locale(7).
LC_ALL
Equivalent to setting both LANG and LC_* variables at the same time.
LC_COLLATE
Determine the order in which sequences of comparable characters are treated when sorting the output of commands which might produce sorted output. See locale(7).
LC_CTYPE
Determine the interpretation of bytes of information and which characters are valid as part of a character and which is the first byte of a multi-byte sequence. See locale(7).
LC_MESSAGES
Determine the locale that should be used for writing diagnostic and informative messages. See locale(7).
NLSPATH
Determine the search path for message catalog files. See locale(7).

Default.

STDERR

>0

The following sections are informative.

APPLICATION USAGE

The rm utility is forbidden to remove the names dot and dot-dot in order to avoid the consequences of inadvertently doing something like:

rm -r .*

Some implementations do not permit the removal of the last link to an executable binary file that is being executed; see the [EBUSY] error in the unlink() function defined in the System Interfaces volume of POSIX.1‐2017. Thus, the rm utility can fail to remove such files.

The -i option causes rm to prompt and read the standard input even if the standard input is not a terminal, but in the absence of -i the mode prompting is not done when the standard input is not a terminal.

EXAMPLES

1.
The following command:
rm a.out core

removes the directory entries: a.out and core.

2.
The following command:
rm -Rf junk

removes the directory junk and all its contents, without prompting.

RATIONALE

For absolute clarity, paragraphs (2b) and (3) in the DESCRIPTION of rm describing the behavior when prompting for confirmation, should be interpreted in the following manner:

if ((NOT f_option) AND
    ((not_writable AND input_is_terminal) OR i_option))

The exact format of the interactive prompts is unspecified. Only the general nature of the contents of prompts are specified because implementations may desire more descriptive prompts than those used on historical implementations. Therefore, an application not using the -f option, or using the -i option, relies on the system to provide the most suitable dialog directly with the user, based on the behavior specified.

The -r option is historical practice on all known systems. The synonym -R option is provided for consistency with the other utilities in this volume of POSIX.1‐2017 that provide options requesting recursive descent through the file hierarchy.

The behavior of the -f option in historical versions of rm is inconsistent. In general, along with ``forcing'' the unlink without prompting for permission, it always causes diagnostic messages to be suppressed and the exit status to be unmodified for nonexistent operands and files that cannot be unlinked. In some versions, however, the -f option suppresses usage messages and system errors as well. Suppressing such messages is not a service to either shell scripts or users.

It is less clear that error messages regarding files that cannot be unlinked (removed) should be suppressed. Although this is historical practice, this volume of POSIX.1‐2017 does not permit the -f option to suppress such messages.

When given the -r and -i options, historical versions of rm prompt the user twice for each directory, once before removing its contents and once before actually attempting to delete the directory entry that names it. This allows the user to ``prune'' the file hierarchy walk. Historical versions of rm were inconsistent in that some did not do the former prompt for directories named on the command line and others had obscure prompting behavior when the -i option was specified and the permissions of the file did not permit writing. The POSIX Shell and Utilities rm differs little from historic practice, but does require that prompts be consistent. Historical versions of rm were also inconsistent in that prompts were done to both standard output and standard error. This volume of POSIX.1‐2017 requires that prompts be done to standard error, for consistency with cp and mv, and to allow historical extensions to rm that provide an option to list deleted files on standard output.

The rm utility is required to descend to arbitrary depths so that any file hierarchy may be deleted. This means, for example, that the rm utility cannot run out of file descriptors during its descent (that is, if the number of file descriptors is limited, rm cannot be implemented in the historical fashion where one file descriptor is used per directory level). Also, rm is not permitted to fail because of path length restrictions, unless an operand specified by the user is longer than {PATH_MAX}.

The rm utility removes symbolic links themselves, not the files they refer to, as a consequence of the dependence on the unlink() functionality, per the DESCRIPTION. When removing hierarchies with -r or -R, the prohibition on following symbolic links has to be made explicit.
