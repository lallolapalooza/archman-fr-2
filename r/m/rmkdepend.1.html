RMKDEPEND(1) Manuel des commandes générales RMKDEPEND(1)

NOM

rmkdepend - crée les dépendances dans les makefiles (Version ROOT)

SYNTAXE

rmkdepend [ -Dnom=déf ] [ -Dnom ] [ -Irépertoiresource ] [ -Yrépertoiresource ] [ -a ] [ -fmakefile ] [ -osuffixeobjet ] [ -ppréfixesourceobjet ] [ -schaîne ] [ -wlargeur ] [ -v ] [ -m ] [ -- autresoptions -- ] fichier-source [ -tnomfichiercible ] ...

DESCRIPTION

Le programme rmkdepend lit chaque fichier-source en séquence et l'analyse comme un préprocesseur C, traitant toutes les directives #include, #define, #undef, #ifdef, #ifndef, #endif, #if, #elif et #else pour pouvoir déterminer correctement quelles directives #include seraient utilisées lors d'une compilation. Les directives #include peuvent référencer des fichiers ayant d'autres directives #include, et une analyse aura lieu également dans ces fichiers.

Chaque fichier qu'un fichier-source inclut, directement ou indirectement, est ce que rmkdepend appelle une dépendance. Ces dépendances sont ensuite écrites dans un makefile de telle sorte que make(1) sache quels fichiers objets doivent être recompilés lorsqu'une dépendance a changé.

Par défaut, rmkdepend place sa sortie dans le fichier nommé makefile s'il existe, sinon Makefile. Un makefile alternatif peut être spécifié avec l'option -f. Il recherche d'abord dans le makefile la ligne


# DO NOT DELETE THIS LINE -- make depend depends on it.

ou une ligne fournie avec l'option -s, comme délimiteur pour la sortie des dépendances. S'il la trouve, il supprime tout ce qui suit jusqu'à la fin du makefile et insère la sortie après cette ligne. S'il ne la trouve pas, le programme ajoute la chaîne à la fin du makefile et place la sortie après celle-ci. Pour chaque fichier-source apparaissant sur la ligne de commande, rmkdepend insère des lignes dans le makefile de la forme


fichier-source.o: fichier...

Où fichier-source.o est le nom de la ligne de commande avec son suffixe remplacé par «.o», et fichier est une dépendance trouvée dans une directive #include lors de l'analyse de fichier-source ou d'un des fichiers qu'il incluait.

NOTE

L'application rmkdepend est basée sur makedepend(1) du Consortium X, mais légèrement modifiée pour s'adapter aux besoins du système ROOT. Cette page de manuel man(1) est plus ou moins identique à la page de manuel de makedepend(1), à l'exception de cet avis, et des sections VOIR AUSSI et AUTEURS.

EXEMPLE

Normalement, rmkdepend sera utilisé dans une cible de makefile de sorte qu'en tapant «make depend» les dépendances soient mises à jour pour le makefile. Par exemple,

    SRCS = fichier1.c fichier2.c ...
    CFLAGS = -O -DHACK -I../foobar -xyz
    depend:
            rmkdepend -- $(CFLAGS) -- $(SRCS)

OPTIONS

Le programme ignorera toute option qu'il ne comprend pas afin que vous puissiez utiliser les mêmes arguments que pour cc(1).

-Dnom=déf ou -Dnom
Définir. Ceci place une définition pour nom dans la table des symboles de rmkdepend. Sans =déf le symbole est défini comme «1».
-Irépertoiresource
Répertoire source. Cette option indique à rmkdepend de préfixer répertoiresource à sa liste de répertoires à rechercher lorsqu'il rencontre une directive #include. Par défaut, rmkdepend ne recherche que les répertoires sources standards (généralement /usr/include et potentiellement un répertoire dépendant du compilateur).
-Yrépertoiresource
Remplace tous les répertoires sources standards par le seul répertoire source spécifié; vous pouvez omettre répertoiresource pour simplement empêcher la recherche dans les répertoires sources standards.
-a
Ajoute les dépendances à la fin du fichier au lieu de les remplacer.
-fmakefile
Nom de fichier. Ceci vous permet de spécifier un makefile alternatif dans lequel rmkdepend peut placer sa sortie. Spécifier «-» comme nom de fichier (c'est-à-dire -f-) envoie la sortie vers la sortie standard au lieu de modifier un fichier existant.
-osuffixeobjet
Suffixe de fichier objet. Certains systèmes peuvent avoir des fichiers objets dont le suffixe est autre que «.o». Cette option vous permet de spécifier un autre suffixe, comme «.b» avec -o.b ou «:obj» avec -o:obj et ainsi de suite.
-ppréfixesourceobjet
Préfixe de fichier objet. Le préfixe est ajouté avant le nom du fichier objet. Ceci est généralement utilisé pour désigner un répertoire différent pour le fichier objet. Le défaut est la chaîne vide.
-schaîne
Chaîne de délimiteur de départ. Cette option permet de spécifier une chaîne différente que rmkdepend doit rechercher dans le makefile.
-wlargeur
Largeur de ligne. Normalement, rmkdepend s'assure que chaque ligne de sortie qu'il écrit ne dépasse pas 78 caractères pour des raisons de lisibilité. Cette option permet de changer cette largeur.
-v
Fonctionnement verbeux. Cette option fait en sorte que rmkdepend émette la liste des fichiers inclus par chaque fichier d'entrée sur la sortie standard.
-m
Avertir des inclusions multiples. Cette option fait en sorte que rmkdepend produise un avertissement si un fichier d'entrée inclut un autre fichier plus d'une fois. Dans les versions précédentes de rmkdepend, c'était le comportement par défaut ; le comportement par défaut a été modifié pour mieux correspondre au comportement du compilateur C, qui ne considère pas l'inclusion multiple comme une erreur. Cette option est fournie pour la compatibilité ascendante, et pour aider au débogage des problèmes liés aux inclusions multiples.
-- options --
Si rmkdepend rencontre un double trait d'union (--) dans la liste des arguments, alors tout argument non reconnu qui suit sera ignoré silencieusement ; un second double trait d'union termine ce traitement spécial. De cette façon, rmkdepend peut être amené à ignorer sans risque des arguments de compilateur ésotériques qui pourraient normalement se trouver dans une macro make CFLAGS (voir la section EXEMPLE ci-dessus). Toutes les options que rmkdepend reconnaît et qui apparaissent entre la paire de doubles traits d'union sont traitées normalement.
-tnomfichiercible
Nom de fichier. Ceci vous permet de spécifier un nom de fichier cible alternatif à utiliser pour le fichier précédent. Par exemple si vous appelez


rmkdepend -sobj -pbuild fichier.cxx -tbibliotheque.so

au lieu d'insérer la ligne


build/fichier.obj: ...

rmkdepend insérera :


bibliotheque.so: ...

ALGORITHME

L'approche utilisée dans ce programme lui permet de s'exécuter un ordre de grandeur plus rapidement que tout autre «générateur de dépendances» que j'ai jamais vu. Au cœur de cette performance se trouvent deux hypothèses : que tous les fichiers compilés par un même makefile seront compilés avec des options -I et -D à peu près identiques ; et que la plupart des fichiers d'un même répertoire incluront en grande partie les mêmes fichiers.

Compte tenu de ces hypothèses, rmkdepend s'attend à être appelé une fois pour chaque makefile, avec tous les fichiers sources maintenus par le makefile apparaissant sur la ligne de commande. Il analyse chaque fichier source et fichier d'inclusion exactement une fois, en maintenant une table des symboles interne pour chacun. Ainsi, le premier fichier sur la ligne de commande prendra un temps proportionnel au temps qu'un préprocesseur C normal met. Mais

sur les fichiers subséquents, s'il rencontre un fichier d'inclusion qu'il a déjà analysé, il ne l'analyse pas à nouveau.

Par exemple, imaginez que vous compiliez deux fichiers, file1.c et file2.c, ils incluent chacun le fichier d'en-tête header.h, et le fichier header.h inclut à son tour les fichiers def1.h et def2.h. Lorsque vous exécutez la commande


rmkdepend file1.c file2.c

rmkdepend analysera file1.c et par conséquent, header.h puis def1.h et def2.h. Il décidera alors que les dépendances pour ce fichier sont


file1.o: header.h def1.h def2.h

Mais lorsque le programme analyse file2.c et découvre qu'il inclut également header.h, il n'analyse pas le fichier, mais ajoute simplement header.h, def1.h et def2.h à la liste des dépendances pour file2.o.

BOGUES

rmkdepend analyse, mais n'évalue pas actuellement, l'expression du préprocesseur SVR4 #predicate(token-list) ; de telles expressions sont simplement supposées vraies. Cela peut entraîner l'évaluation de directives #include incorrectes.

Imaginez que vous analysez deux fichiers, disons file1.c et file2.c, chacun incluant le fichier def.h. La liste des fichiers que def.h inclut peut être réellement différente lorsque def.h est inclus par file1.c que lorsqu'il est inclus par file2.c. Mais une fois que rmkdepend arrive à une liste de dépendances pour un fichier, elle est coulée dans le béton.
