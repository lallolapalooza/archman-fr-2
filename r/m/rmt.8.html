NOM

rmt - serveur de bande magnétique à distance

SYNTAXE

rmt

DESCRIPTION

Rmt fournit un accès à distance aux fichiers et périphériques pour tar(1), cpio(1), et utilitaires de sauvegarde similaires. Il est normalement appelé en exécutant rsh(1) ou ssh(1) sur la machine distante, éventuellement en utilisant un nom d'utilisateur différent si un est fourni.

Le programme appelant communique avec rmt en envoyant des requêtes sur son entrée standard et en lisant les réponses depuis la sortie standard. Une requête consiste en une lettre de requête suivie d'un argument (si requis) et d'un caractère de nouvelle ligne. Des données supplémentaires, le cas échéant, sont envoyées après la nouvelle ligne. En cas de succès, rmt renvoie


Anombre\n

où nombre est une représentation ASCII d'un code de retour décimal. Des données supplémentaires sont renvoyées après cette ligne. En cas d'erreur, la réponse suivante est renvoyée:


Eerrno\nmessage-erreur\n

où errno est l'un des codes d'erreur système, comme décrit dans errno(3), et message-erreur est une description lisible par l'homme en une ligne de l'erreur, telle qu'affichée par perror(3).

Les commandes disponibles et les réponses possibles sont discutées en détail dans la section suivante.

COMMANDES

Opériphérique\nflags\n
Ouvre le périphérique avec les flags donnés. Si un périphérique avait déjà été ouvert, il est fermé avant l'ouverture du nouveau.

Arguments

périphérique
Le nom du périphérique à ouvrir.
flags
Flags pour open(2) : un nombre décimal, ou toute constante O_* valide de fcntl.h (le O_ initial peut être omis), ou un ou (utilisant |) de plusieurs de ces constantes, par exemple : 
576
64|512
CREAT|TRUNC
De plus, une forme combinée est également autorisée, c'est-à-dire un mode décimal suivi de sa représentation symbolique. Dans ce cas, la représentation symbolique est privilégiée.

Réponse

A0\n en cas de succès.

Extensions

La version BSD n'autorise qu'un nombre décimal comme flags.
C[périphérique]\n
Ferme le périphérique actuellement ouvert.
Arguments

Tous les arguments sont ignorés silencieusement.
Réponse

A0\n en cas de succès.
Lwhence\noffset\n
Effectue un lseek(2) sur le périphérique actuellement ouvert avec les paramètres spécifiés.
Arguments
whence
Où mesurer le décalage à partir. Les valeurs valides sont : 
0, SET, SEEK_SET	déplacer depuis le début du fichier
1, CUR, SEEK_CUR	déplacer depuis l'emplacement actuel
2, END, SEEK_END	déplacer depuis la fin du fichier
Réponse

Aoffset\n en cas de succès. L'offset est le nouveau décalage dans le fichier.
Extensions
La version BSD n'autorise que 0, 1, 2 comme whence.
Rcompte\n

Lit compte octets de données depuis le périphérique actuel.
Arguments
compte
Nombre d'octets à lire.
Réponse

En cas de succès :


Anbrelu\n

suivi de nbrelu octets de données lus depuis le périphérique.

Wcompte\n
Écrit des données sur le périphérique actuel. La commande est suivie de compte octets de données d'entrée.
Arguments
compte
Nombre d'octets à écrire.
Réponse

En cas de succès : Anbreécrit\n, où nbreécrit est le nombre d'octets réellement écrits.
Iopcode\ncompte\n
Effectue une commande ioctl(2) MTIOCOP avec les paramètres spécifiés.
Arguments
opcode
Code d'opération MTIOCOP.
compte
mt_count.
Réponse

En cas de succès : A0\n.
S\n
Renvoie l'état du périphérique actuellement ouvert, tel qu'obtenu via un appel ioctl(2) MTIOCGET.
Arguments

Aucun
Réponse

En cas de succès : Acompte\n suivi de compte octets de données.

VOIR AUSSI

tar(1).

BOGUES

L'utilisation de cet utilitaire comme outil d'accès aux fichiers à distance général est déconseillée.

SIGNALEMENT DE BOGUES

Signalez les bogues à <bug-tar@gnu.org>.

HISTORIQUE

La commande rmt est apparue dans 4.2BSD. Le rmt GNU est écrit à partir de zéro, en utilisant la spécification BSD.
