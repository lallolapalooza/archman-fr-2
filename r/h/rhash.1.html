NOM

rhash - calculer/vérifier les sommes de contrôle CRC32, MD5, SHA1, GOST, TTH, BTIH ou autres sommes de contrôle de messages.

SYNTAXE

rhash [ option ]... [ fichier ]...

DESCRIPTION

RHash (Recursive Hasher) calcule et vérifie divers sommes de contrôle et sommes de contrôle de messages de fichiers. Les algorithmes de hachage pris en charge incluent CRC32, CRC32C, MD4, MD5, SHA1, SHA256, SHA512, SHA3, Tiger, DC++ TTH, BTIH, AICH, ED2K, GOST R 34.11-*, RIPEMD-160, HAS-160, BLAKE2s/BLAKE2b, BLAKE3, EDON-R 256/512, Whirlpool, Snefru-128/256.

Le programme peut créer et vérifier des liens Magnet et des liens ed2k:// edonkey, voir les options --magnet et --ed2k-link.

Un paramètre de chaîne de tiret `-' est interprété comme le flux d'entrée standard (stdin).

Par défaut, rhash imprime les sommes au format SFV avec uniquement la somme de contrôle CRC32. Le format peut être modifié par les options --bsd, --magnet, --simple, --printf, --template. Pour afficher toutes les sommes, utilisez l'option `-a'.

OPTIONS DE MODE PROGRAMME

Le mode par défaut consiste à imprimer les sommes de contrôle pour tous les fichiers et arborescences de répertoires spécifiés en ligne de commande. Le mode peut être modifié par les options suivantes.

-c, --check
Vérifier les fichiers de sommes de contrôle spécifiés en ligne de commande. RHash peut vérifier les fichiers de sommes de contrôle aux formats SFV et BSD, les fichiers au format MD5 et SHA1, et les fichiers texte contenant des liens magnet ou ed2k (un lien par ligne). Les lignes vides et les lignes commençant par `;` ou `#` sont ignorées.

RHash peut vérifier les fichiers de sommes de contrôle générés sans les options de formatage --printf et --template.

Si l'algorithme de hachage n'est pas spécifié par les options de ligne de commande, RHash tente de détecter l'algorithme à partir de l'extension du fichier de sommes de contrôle. Si la détection échoue, toutes les fonctions de hachage de la même longueur de hachage sont calculées, ce qui ralentit considérablement la vérification des fichiers. Pour accélérer la vérification, dans ce cas, spécifiez explicitement l'algorithme de hachage en ligne de commande.

-u, --update=<fichier-somme>
Mettre à jour le fichier de sommes de contrôle spécifié en calculant les sommes de contrôle des messages pour les fichiers listés dans les arguments de la commande qui n'y sont pas présents. Les nouvelles sommes de contrôle sont ajoutées dans le format spécifié par les options de formatage.

Avec --recursive, met à jour le fichier de sommes de contrôle en utilisant les fichiers de toutes les arborescences de répertoires. Avec --check, vérifie les sommes de contrôle existantes avant la mise à jour.

--missing=<fichier-somme>
Lister les fichiers du fichier de sommes de contrôle qui sont manquants ou inaccessibles dans le système de fichiers.
--unverified=<fichier-somme>
Lister les fichiers en ligne de commande manquants dans le fichier de sommes de contrôle donné (fichiers non vérifiés). Avec --recursive, vérifie toutes les arborescences de répertoires pour les fichiers non vérifiés.
-k, --check-embedded
Vérifier les fichiers par la somme crc32 intégrée dans leur nom.
--torrent
Créer un fichier torrent pour chaque fichier traité.
-h, --help
Aide : afficher l'écran d'aide et quitter.
-V, --version
Version : afficher la version et quitter.
-B, --benchmark
Exécuter un benchmark pour l'algorithme de hachage sélectionné(s).

Spécifie quelles fonctions de hachage doivent être calculées à l'aide de la bibliothèque OpenSSL. La <liste> est une liste d'algos de hachage séparés par des virgules, mais seuls ceux pris en charge par openssl sont autorisés : md4, md5, sha1, sha2*, ripemd160 et whirlpool.

Inverse les octets dans la sortie hexadécimale des fonctions de hachage GOST. L'octet le plus significatif de la somme de contrôle du message sera imprimé en premier. L'ordre par défaut est l'octet le moins significatif en premier.

Active le mode batch torrent (implique le mode torrent). Calcule le batch-torrent pour les fichiers spécifiés en ligne de commande et enregistre le fichier torrent dans le chemin du fichier. L'option -r <répertoire> peut être utile dans ce mode.
--bt-private

Ajoute une URL d'annonce de tracker aux fichiers torrent créés. Plusieurs URL peuvent être passées en spécifiant l'option plusieurs fois. Cette option ne modifie pas la somme de contrôle BTIH.
--benchmark-raw
Passe le format de sortie du benchmark en texte lisible par machine, délimité par des tabulations, avec le nom de la fonction de hachage, la vitesse, les cycles d'horloge CPU par octet. Cette option ne fonctionne que si l'option --benchmark a été spécifiée.
--no-detect-by-ext
Ne détecte pas la fonction de hachage par l'extension du fichier de hachage, en mode --check.

Désactive l'échappement des caractères dans les chemins de fichiers. L'option peut être spécifiée dans les modes par défaut, vérification ou mise à jour.
-- (double trait d'union)
Marque la fin des options de la ligne de commande. Tous les paramètres suivant le double trait d'union sont interprétés comme des fichiers ou des répertoires. Il est généralement utilisé pour traiter des noms de fichiers commençant par un trait d'union `-'. Alternativement, vous pouvez spécifier './' ou un chemin complet avant de tels fichiers, de sorte qu'ils ne ressemblent plus à des options.

OPTIONS DE FORMAT DE SORTIE

--sfv
Imprime les sommes de contrôle du message au format de sortie SFV (Simple File Verification) (par défaut). Mais contrairement aux fichiers SFV courants, non seulement CRC32, mais toutes les sommes de contrôle spécifiées par les options peuvent être imprimées.
-g, --magnet
Imprime les sommes de contrôle du message formatées en liens magnet.
--bsd
Utilise le format de sortie BSD. Chaque somme de contrôle du message est imprimée sur une ligne séparée après le nom de la fonction de hachage et le chemin du fichier, entre parenthèses.
--simple
Utilise le format de sortie simple. Chaque ligne sera constituée du nom du fichier et des sommes de contrôle spécifiées par les options.
--one-hash
Imprime une somme de contrôle du message par ligne sans informations de fichier supplémentaires.
-L, --ed2k-link
Imprime le lien eDonkey contenant le nom du fichier, la taille du fichier, les sommes de contrôle ED2K et AICH.
--hex
Imprime les sommes de contrôle du message au format hexadécimal.
--base32
Imprime les sommes de contrôle du message au format Base32.
-b, --base64
Imprime les sommes de contrôle du message au format Base64.
--uppercase
Imprime les sommes de contrôle du message en majuscules.
--lowercase
Imprime les sommes de contrôle du message en minuscules.
--template=<fichier>
Lit un modèle de type printf depuis le <fichier> donné. Voir l'option --printf.

FICHIER DE CONFIGURATION

RHash recherche un fichier de configuration à $XDG_CONFIG_HOME/rhash/rhashrc, $HOME/.config/rhash/rhashrc, $XDG_CONFIG_DIRS/rhash/rhashrc, $HOME/.rhashrc et /etc.

Le fichier de configuration se compose de lignes formatées comme suit :

variable = valeur

où la variable peut être le nom de n'importe quelle option de ligne de commande, comme magnet, printf, percents, etc. Une variable booléenne peut être définie sur vrai avec la valeur `on', `yes' ou `true', toute autre valeur met la variable à faux.

Les lignes vides et les lignes commençant par `#` ou `;` sont ignorées.

Exemple de fichier de configuration :

# Ceci est une ligne de commentaire
percents = on
crc-accept = .sfv,.md5,.sha1,.sha256,.sha512,.tth,.magnet

NAME

rhash - Calculer et vérifier des sommes de contrôle cryptographiques

SYNTAXE

rhash [OPTIONS] [FILE]...
rhash -c [OPTIONS] CHECKFILE...

DESCRIPTION

rhash est un utilitaire de ligne de commande pour calculer et vérifier des sommes de contrôle cryptographiques (hachages) de fichiers. Il prend en charge plusieurs algorithmes de hachage, notamment MD5, SHA1, SHA256, SHA512, etc.

OPTIONS DE MODE DE PROGRAMME

-c, --check
Lit les sommes de contrôle et les noms de fichiers à partir de CHECKFILE et vérifie les sommes de contrôle. Si CHECKFILE est défini sur -, les entrées sont lues à partir de l'entrée standard. La syntaxe de chaque ligne de CHECKFILE est la suivante : HASH ALGORITHME FICHIER. Par exemple : 
e10adc3949ba59abbe56e057f20f883e  motdepasse.txt
ou 
-- -- check -c [OPTIONS] CHECKFILE...
Le format MD5 (motdepasse.txt) = e10adc3949ba59abbe56e057f20f883e est également pris en charge.
--list
Liste les algorithmes de hachage pris en charge et leurs propriétés.

OPTIONS D'ALGORITHMES DE HACHAGE

Par défaut, rhash calcule le hachage MD5. Pour utiliser un autre algorithme, spécifiez l'une des options suivantes :

-p, --per-file
Calcule un hachage pour chaque fichier spécifié. Ceci est le comportement par défaut lorsque plusieurs fichiers sont fournis.
-m, --md5
Calcule le hachage MD5.
-s, --sha1
Calcule le hachage SHA1.
-2, --sha256
Calcule le hachage SHA256.
-5, --sha512
Calcule le hachage SHA512.
-a, --crc32
Calcule le hachage CRC32.
-H, --tiger
Calcule le hachage Tiger.
-B, --blake2b
Calcule le hachage BLAKE2b.
-S, --snefru
Calcule le hachage Snefru.
-T, --tkm
Calcule le hachage TKM.
--all
Calcule tous les hachages pris en charge.

OPTIONS DIVERSES

-v, --verbose
Mode verbeux. Affiche des informations supplémentaires sur le processus.
-q, --quiet
Mode silencieux. N'affiche que les erreurs.
-b, --binary
Lit et écrit les données en mode binaire.
-z, --zero
Traite les fichiers vides comme des fichiers contenant une chaîne de caractères nuls.
-F, --force
Forcer la vérification des fichiers même s'ils ne sont pas trouvés.

OPTIONS DE FORMAT DE SORTIE

-f, --format FORMAT
Spécifie le format de sortie. Les formats disponibles sont :
  • default : format par défaut de rhash.
  • crc32 : format CRC32.
  • md5 : format MD5.
  • sha1 : format SHA1.
  • sha256 : format SHA256.
  • sha512 : format SHA512.
  • tiger : format Tiger.
  • blake2b : format BLAKE2b.
  • snefru : format Snefru.
  • tkm : format TKM.
  • json : format JSON.
  • xml : format XML.
  • base32 : format Base32.
  • base64 : format Base64.
--hex
Affiche le hachage sous forme hexadécimale (par défaut).
--base64
Affiche le hachage en Base64.
--base32
Affiche le hachage en Base32.
--uppercase
Affiche le hachage en majuscules.

FICHIER DE CONFIGURATION

rhash peut lire les options de ligne de commande à partir d'un fichier de configuration. Le fichier de configuration par défaut est ~/.config/rhash/rhash.conf. Les options peuvent être spécifiées une par ligne, précédées d'un tiret. Les lignes commençant par # sont ignorées.
