NOM

rnews - Injecter des articles individuels et des lots UUCP

SYNTAXE

rnews [-abdNUv] [-h hôte] [-P port] [-rS serveur] [fichier]

DESCRIPTION

rnews injecte soit des articles individuels, soit des lots d'articles de style UUCP dans un serveur de news local ou distant. Il soumet les articles via IHAVE et convient à l'injection d'articles reçus d'autres sources ; les publications locales devraient généralement utiliser inews(1) à la place. Il est également utilisé pour traiter les messages mis en file d'attente créés par, par exemple, nnrpd pendant que innd n'est pas disponible.

Si des informations d'identification d'authentification sont présentes pour le serveur distant dans le fichier passwd.nntp situé dans pathetc, alors rnews les utilisera pour s'authentifier.

Le message est lu à partir de fichier s'il est donné, des fichiers mis en file d'attente (avec le drapeau -U) ou de l'entrée standard si aucun fichier n'est donné. Les articles sont envoyés au serveur spécifié dans les options de ligne de commande -r ou -S s'ils sont donnés, sinon au serveur défini via nnrpdposthost dans inn.conf, sinon au serveur local à 127.0.0.1, et enfin au serveur défini via server dans inn.conf.

Lorsqu'ils sont envoyés via UUCP, les articles Usenet sont typiquement regroupés en un seul lot pour réduire la surcharge UUCP. Les lots peuvent également être compressés pour réduire le temps de communication. Si l'entrée de rnews ne commence pas par les caractères "#!", elle est considérée comme un article de news unique ; sinon, la première ligne de l'entrée est interprétée comme une commande de lot.

Si la commande de lot est :

#! rnews <nombre>

alors les <nombre> octets suivants (à partir de la ligne suivante) sont lus comme un article de news. Après le traitement de cet article, la ligne suivante est à nouveau traitée comme une commande de lot.

Si la commande est :

#! cunbatch

alors le reste de l'entrée est passé à "gzip -d" pour la décompresser, puis la sortie décompressée résultante est relue comme si c'était l'entrée originale de rnews. Un lot compressé devrait donc commencer par cette ligne et contenir un lot d'articles séparés par des lignes "#! rnews" puis compressé avec compress(1). (Les lots compressés avec gzip(1) devraient plutôt utiliser "gunbatch" comme commande de lot ; INN utilise simplement gzip plutôt que compress car il peut gérer la compression de style compress mais est plus largement disponible, en raison d'anciens problèmes de brevet, que compress.)

Sinon, si la commande est un autre mot et que le drapeau -a n'est pas donné, rnews essaiera d'exécuter un programme portant ce nom, en le recherchant dans le répertoire pathbin/rnews.libexec. Le reste du lot sera transmis à l'entrée standard de ce programme, et la sortie standard du programme sera traitée comme si c'était l'entrée originale de rnews. INN est livré avec trois processeurs de lot standard :

bunbatch
Il invoque bzip2 et doit être utilisé pour les lots compressés avec bzip2.
c7unbatch
Il annule un codage ASCII pour récupérer le flux binaire compressé original, puis le décompresse comme expliqué ci-dessus.
gunbatch
Il invoque gzip et doit être utilisé pour les lots compressés avec gzip.

OPTIONS

-a
Par défaut, rnews recherche des décompresseurs supplémentaires dans le sous-répertoire rnews.libexec de pathbin (tel que défini dans inn.conf). Si -a est donné, aucun processeur de lot supplémentaire ne sera utilisé ; seuls "rnews" et "cunbatch" seront reconnus comme commandes de lot valides.
-b
Par défaut, rnews enregistrera et supprimera tous les articles qui sont rejetés par le serveur ou qui ne peuvent pas être analysés par rnews pour une raison quelconque (comme un champ d'en-tête manquant). Si -b est donné, les articles rejetés seront également sauvegardés dans le sous-répertoire bad de pathincoming (tel que défini dans inn.conf).
-d
Si -d est donné, rnews enregistrera via syslog l'ID du message et le corps du champ d'en-tête Path de chaque article rejeté comme un doublon par le serveur.
-h hôte
Si -h est donné, rnews enregistrera l'ID du message et hôte via syslog pour chaque article qu'il propose au serveur. Ceci est utilisé conjointement avec un flux UUCP pour obtenir un enregistrement des messages reçus via ce flux. Cela sera également fait si la variable d'environnement UU_MACHINE est définie, mais ne sera fait que si hôte n'est pas une chaîne vide. (Vous pouvez donc désactiver l'enregistrement même si UU_MACHINE sera défini en passant le drapeau "-h ''" à rnews.)
-N
Normalement, si la décompression du lot d'entrée échoue, il est remis en file d'attente dans pathincoming pour une autre tentative plus tard. Si le drapeau -N est donné, aucune remise en file d'attente ne sera faite et rnews sortira avec le statut 9 si la décompression échoue.
-P port
Utiliser port comme port du serveur auquel se connecter plutôt que nnrpdpostport (tel que défini dans inn.conf). Notez que cette valeur n'est utilisée que si rnews ne se connecte pas au serveur local (en d'autres termes, lorsque -r ou -S est donné ou que nnrpdposthost est défini).
-r serveur, -S serveur
-r et -S sont synonymes. Si l'un d'eux est donné, les articles seront envoyés à serveur au lieu d'utiliser le serveur local, en remplaçant également le réglage de nnrpdposthost dans inn.conf.
-U
Si le serveur n'est pas disponible, rnews et nnrpd mettront en file d'attente les publications dans de nouveaux fichiers dans le répertoire pathincoming (tel que spécifié dans inn.conf). Lorsque rnews est invoqué avec l'option -U, il analyse ce répertoire et traite tous les messages mis en file d'attente trouvés dont les noms de fichiers ne commencent pas par ".", en essayant de les renvoyer au serveur. Il est conseillé d'exécuter ceci périodiquement via cron pour récupérer les articles mis en file d'attente en raison d'indisponibilité temporaire du serveur.
-v
Activer le mode verbeux, avec plus de traces, notamment en enregistrant la raison pour laquelle les articles sont rejetés par le serveur.

BOGUES

rnews ne peut pas traiter les articles qui contiennent des caractères nuls intégrés. (Le reste d'INN ne le peut pas non plus pour le moment.)
