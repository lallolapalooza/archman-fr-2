RNGD(8) Manuel de l'administrateur système RNGD(8)

NOM

rngd - Vérifie et alimente le périphérique aléatoire du noyau en données aléatoires provenant d'un périphérique matériel.

SYNTAXE

rngd [-b, --background] [-f, --foreground] [-d, --debug] [-l, --list] [-x, --exclude] [-n, --include] [-O, --option] [-i, --ignorefail] [-o, --random-device=fichier] [-p, --pid-file=fichier] [-r, --rng-device=fichier] [-s, --random-step=nnn] [-t, --test] [-W, --fill-watermark=nnn] [-R, --force-reseed=nnn] [-u, --use-slow-sources] [-D, --drop-privileges=utilisateur:groupe] [-q, --quiet] [-?, --help] [-v, --version]

DESCRIPTION

Ce démon alimente le pool d'entropie du périphérique aléatoire du noyau avec des données provenant d'un générateur de nombres aléatoires, après avoir vérifié que les données sont effectivement aléatoires.

Les options -f ou --foreground peuvent être utilisées pour indiquer à rngd de ne pas se lancer en arrière-plan au démarrage. Ceci est généralement utilisé pour le débogage. Les options -b ou --background, qui lancent un fork et placent rngd en arrière-plan automatiquement, sont celles par défaut.

Les options -r ou --rng-device peuvent être utilisées pour sélectionner une source d'entrée alternative, en plus de celle par défaut /dev/hwrng. Les options -o ou --random-device peuvent être utilisées pour sélectionner un périphérique de sortie d'entropie alternatif, en plus de celui par défaut /dev/random. Notez que ce périphérique doit supporter l'API d'ioctl /dev/random du noyau Linux.

OPTIONS

-b, --background
Devient un démon (par défaut)
-f, --foreground
Ne pas faire de fork et rester en premier plan
-d, --debug
Activer les messages de débogage
-l, --list
Lister les index et les noms des sources d'entropie disponibles. Le code de retour lors du listage des sources est 0 si au moins une source d'entropie a été trouvée et initialisée, 1 sinon.
-x, --exclude
Désactiver les sources d'entropie basées sur l'index ou le nom court rapporté par l'option --list
-n, --include
Activer les sources d'entropie basées sur l'index ou le nom court rapporté par l'option --list
-O, --option
Fournir des options de configuration spécifiques à des sources d'entropie individuelles, au format --option [index|nom_court]:clé:valeur. Voir la section Sources d'entropie ci-dessous pour les indices et les options spécifiques aux sources. Notez que spécifier -O [<index>|<nom_court>] affichera les options disponibles pour cet index sur la console.
-p fichier, --pid-file=fichier
Fichier utilisé pour enregistrer le PID du démon, et pour l'exclusion multiple (par défaut : /var/run/rngd.pid)
-i, --ignorefail
Ignorer les échecs FIPS répétés
-o fichier, --random-device=fichier
Périphérique du noyau utilisé pour la sortie des nombres aléatoires (par défaut : /dev/random)
-r fichier, --rng-device=fichier
Périphérique du noyau utilisé pour l'entrée des nombres aléatoires (par défaut : /dev/hwrng)
-s nnn, --random-step=nnn
Nombre d'octets écrits dans le périphérique aléatoire à la fois (par défaut : 64)
-t, --test
Entrer en mode test. Dans ce mode (qui implique -f), toute l'entropie générée est écartée et rngd signale la quantité d'entropie générée chaque seconde.
-e nnn, --entropy-count=nnn
Nombre de bits considérés comme aléatoires lors de l'ajout d'entropie. 1<=e<=8 (par défaut : 8)
-W n, --fill-watermark=nnn
Une fois que nous commençons à le faire, alimenter le périphérique aléatoire en entropie jusqu'à ce qu'au moins fill-watermark bits d'entropie soient disponibles dans son pool d'entropie. Par défaut, cette valeur est définie à 75% de la taille du pool d'entropie ou 2048 bits si la taille du pool d'entropie n'a pas pu être déterminée. Définir cette valeur trop haut fera que rngd dominera le contenu du pool d'entropie. Des valeurs basses nuiront aux performances du système pendant les pénuries d'entropie. Ne pas définir fill-watermark au-dessus de la taille du pool d'entropie (généralement 256 bits). Une valeur de 0 pour cette option ne définira aucune marque.
-R n, --force-reseed=nnn
Pour les noyaux plus récents qui supportent les pools d'entropie non bloquants, il est toujours bénéfique d'ajouter périodiquement de l'entropie fraîche comme événement de réensemencement. --force-reseed définit le nombre de secondes entre les ajouts d'entropie fraîche au pool d'entropie du noyau. Par défaut, 5 minutes.
-u, --use-slow-sources
Les sources d'entropie nist, jitter et pkcs11 sont considérées comme lentes pour fournir de l'entropie. Par défaut, leurs données ne sont utilisées qu'après que toutes les autres sources aient échoué à fournir de l'entropie valide 100 fois. Avec cette option, rngd essaie toujours de collecter de l'entropie de ces sources également.
-D, --drop-privileges=utilisateur:groupe
Abandonner les privilèges à un utilisateur et un groupe spécifiés après l'initialisation. Un utilisateur et un groupe peuvent être spécifiés sous forme de nom ou d'identifiant numérique et doivent être séparés par un deux-points. Un utilisateur et un groupe doivent exister. Par défaut, aucun abandon de privilèges n'est effectué.
-q, --quiet
Supprimer tous les messages
-?, --help
Donner un bref résumé de toutes les options du programme
-v, --version
Afficher la version du programme

SOURCES D'ENTROPIE

Rngd est composé de plusieurs sources d'entropie, dont les données sont agrégées et introduites dans le pool d'entropie du noyau. Notez que toutes les sources d'entropie ne sont pas disponibles sur tous les systèmes, et si une source d'entropie est activée pour un système sur lequel elle n'est pas appropriée (ou possible) à utiliser, elle peut échouer à l'initialisation. L'échec d'une seule source d'entropie au démarrage n'est pas fatal à rngd. Une seule source d'entropie est nécessaire pour que rngd fonctionne. Les sources d'entropie suivantes sont actuellement définies dans rngd :

RNG matériel (hwrng)
Le RNG matériel est une source d'entropie générique qui tire l'entropie d'un rng matériel connecté par défaut à /dev/hwrng.
TPM (tpm)
Entropie tirée du périphérique TPM intégré. Notez que cette source d'entropie est obsolète et sera bientôt supprimée, car les périphériques TPM plus récents exportent l'entropie via /dev/hwrng, qui est collectée par la source hwrng ci-dessus.
RDRAND/RDSEED (rdrand)
Entropie tirée des instructions RDRAND et RDSEED (x86 uniquement)
Options

use_aes - sélectionne si rdrand est utilisé pour ensemencer un cprng afin de produire de l'entropie, ou si toute l'entropie est tirée directement de l'instruction rdrand (par défaut 0)

DARN (darn)
Entropie tirée de l'instruction DARN (ppc64 uniquement)
Options

use_aes - sélectionne si l'instruction power darn est utilisée pour remplir directement le pool d'entropie, ou si elle est utilisée comme graine périodique pour un cprng basé sur aes (par défaut 1)

RNDR (rndr)
Entropie tirée de l'instruction RNDR (aarch64 uniquement)
Options

use_aes - sélectionne si l'instruction arm rndr est utilisée pour remplir directement le pool d'entropie, ou si elle est utilisée comme graine périodique pour un cprng basé sur aes (par défaut

rngd(8) — Man pages

NAME

rngd — random number generator daemon

SYNOPSIS

rngd [OPTION...]

DESCRIPTION

The rngd daemon gathers random data from a specified entropy source and makes it available to the kernel's random number generator.

The daemon can be configured to use one or more entropy sources. If multiple sources are specified, they will be used in the order they appear on the command line.

Entropy sources available:

/dev/rng
Entropy from the kernel's random number generator.
/dev/random
Entropy from the kernel's random number generator.
/dev/urandom
Entropy from the kernel's random number generator.

OPTIONS

The following options are supported by the rngd daemon:

-f, --foreground
Run the daemon in the foreground. This is useful for debugging.
-p, --pidfile
Specify the path to the PID file. The default is /run/rngd.pid.
-s, --rng-device
Specify the path to the random number generator device. The default is /dev/urandom.
-o, --entropy-source
Specify the path to the entropy source. This option can be specified multiple times to use multiple entropy sources.
-n, --no-daemon
Do not fork into the background. This is equivalent to --foreground.
-d, --debug
Enable debugging output. This is equivalent to --foreground.
-v, --verbose
Enable verbose output. This is equivalent to --foreground.
-h, --help
Print a help message and exit.
-V
Print version information and exit.

ENTROPY SOURCES

INTELRDRAND (rdrand)
Entropy gathered from the Intel Hardware Random Number Generator (RDRAND) instruction.
HWRNG (hwrng)
Entropy gathered from the generic Linux Kernel hardware random number generator interface (CONFIG_HW_RANDOM).
EDGERNG (edgerng)
Entropy gathered from the Edge-RNG device.
UIO_RAND (uio_rand)
Entropy gathered from a user-space driver that exposes a hardware random number generator via the uio interface.
Options

device - Specify the device path for the entropy source.

PLUGIN (plugin)
Entropy gathered from a dynamically loaded plugin. The plugin must implement the rngd entropy source interface.
Options

path - Specify the path to the plugin library.

symbol - Specify the symbol name of the entropy source function within the plugin library.

USERSPACE (userspace)
Entropy gathered from a userspace daemon that provides entropy via standard input. The userspace daemon is expected to produce random data and write it to standard output. rngd will read from standard input.
Options

path - Specify the path to the userspace daemon executable.

cmdline - Specify the command line arguments for the userspace daemon.

max_bytes - Specify the maximum number of bytes to read from the userspace daemon. If not specified, there is no limit.

max_period - Specify the maximum period in seconds to wait for new entropy. If not specified, there is no limit.

min_pool - Specify the minimum number of bytes to accumulate in the entropy pool before starting to feed the kernel. Defaults to 4.

low_mark - Specify the low watermark for the entropy pool. When the pool size drops below this mark, rngd will attempt to refill it. Defaults to 4.

high_mark - Specify the high watermark for the entropy pool. When the pool size reaches this mark, rngd will stop refilling it until it drops below the low mark. Defaults to 32.

fill_timeout - Specify the timeout in seconds to wait for entropy data from the userspace daemon. Defaults to 60.

fallback - If this option is specified, rngd will fall back to the default entropy source if the userspace daemon fails to provide entropy within the specified timeout. Defaults to false.

tsp - If this option is specified, rngd will timestamp the entropy data before feeding it to the kernel. This may be useful for debugging or performance analysis. Defaults to false.

NIST Entropy Beacon (nist)
Entropy gathered from the NIST network entropy beacon. Note that this entropy source is disabled by default as it should never be used for cryptographic purposes, or any use case in which random data should be known only by a single entity.
Qrypt Entropy Beacon (qrypt)
Entropy gathered from the qrypt entropy beacon. Note this beacon provides entropy to remote clients over a TLS connection. As such this source should not be used for cryptographic operations unless the security of the network can be guaranteed against man in the middle and other network based attacks.
Options

tokenfile - Specify the file containing the access token to the Qrypt beacon

delay - Specify the maximum delay (in seconds) that the source will wait when there are temporary conditions preventing entropy retrieval before trying to fetch entropy again. The default maximum delay is eight hours, exponentially counting up from one second upwards, in powers of two.

JITTER (jitter)
Entropy gathered by measuring timing variance of operations on the local cpu
Options

thread_count - Set the number of threads that the jitter entropy source will spawn

buffer_size - Set the size of the buffer cache that each thread maintains

refill_thresh - Set the low watermark for the cache that triggers its corresponding thread to start refill operations

retry_count - If all entropy buffers are empty, retry this many times before giving up. Note that jitterentropy can take several seconds to refill a buffer, and so retries after a delay may be preferable to repeatedly spining on an empty buffer (default 1)

retry_delay - between each retry for retry_count above, sleep for this many seconds. May also be the special value -1, representing adaptive sleep, where each retry delay will be half the recorded execution time of the last entropy gathering round (default -1)

force_soft_timer - on platforms with a hardware timer that is too coarse to sample jitter, we can instead use a software based timer loop. Detection and use of this mechanism is automatic, but this can be useful for testing purposes

PKCS11 (pkcs11)
Entropy gathered via the opensc openssl engine, which can extract entropy from various smart card readers. Install a package for your distribution containing pkcs11 endpoint library to gather smartcard entropy. This is opensc for Fedora, opensc-pkcs11 for Debian/Ubuntu or another package containing opensc-pkcs11.so.
Options

engine_path - Set the patch for the pkcs11 engine DSO to load

chunk_size - Some pkcs11 engines have restrictions on how much data can be requested at a time, this option allows for the request to be subdivided into smaller chunks to be satisfied

RTLSDR (rtlsdr)
Entropy gathered via the rtl software defined radio library, which can gather entropy using various usb software defined radios listening to random radio static
Options

devid - When multiple devices are available the integer index of the device to use

freq_min - The minimum frequence range to scan in

freq_max - The maximum frequency range to scan in

sample_min - The minimum sample rate of the radio

sample_max - The maximum sample rate of the radio

Named pipe (namedpipe)
Reads entropy from a named pipe (aka FIFO). Another program, for example a driver reading and preparing data from an external hardware RNG, is expected to feed entropy into this named pipe. Should the named pipe be closed, rngd will try to reopen it.
Options

path - Path of the named pipe. Required.

timeout - Maximum time in seconds rngd waits until a full FIPS test buffer of entropy can be read. Defaults to 5.
