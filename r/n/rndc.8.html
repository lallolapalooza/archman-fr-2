NOM

rndc - utilitaire de contrôle du serveur de noms

SYNOPSIS

rndc [-b adresse-source] [-c fichier-config] [-k fichier-clé] [-s serveur] [-p port] [-q] [-r] [-V] [-y clé-serveur] [[-4] | [-6]] {commande}

DESCRIPTION

rndc contrôle le fonctionnement d'un serveur de noms. Si rndc est appelé sans options ou arguments en ligne de commande, il affiche un bref résumé des commandes supportées et des options disponibles ainsi que leurs arguments.

rndc communique avec le serveur de noms via une connexion TCP, envoyant des commandes authentifiées par des signatures numériques. Dans les versions actuelles de rndc et named <#std-iscman-named>, les seuls algorithmes d'authentification supportés sont HMAC-MD5 (pour la compatibilité), HMAC-SHA1, HMAC-SHA224, HMAC-SHA256 (par défaut), HMAC-SHA384, et HMAC-SHA512. Ils utilisent un secret partagé à chaque extrémité de la connexion, ce qui fournit une authentification de type TSIG pour la requête de commande et la réponse du serveur de noms. Toutes les commandes envoyées sur le canal doivent être signées par une clé-serveur connue du serveur.

rndc lit un fichier de configuration pour déterminer comment contacter le serveur de noms et décider quel algorithme et quelle clé utiliser.

OPTIONS

-4
Cette option indique l'utilisation d'IPv4 uniquement.
-6
Cette option indique l'utilisation d'IPv6 uniquement.
-b adresse-source
Cette option spécifie adresse-source comme adresse source pour la connexion au serveur. Plusieurs instances sont permises, pour permettre la définition des adresses sources IPv4 et IPv6.
-c fichier-config
Cette option spécifie fichier-config comme fichier de configuration au lieu du fichier par défaut, /etc/rndc.conf.
-k fichier-clé
Cette option spécifie fichier-clé comme fichier de clé au lieu du fichier par défaut, /etc/rndc.key. La clé dans /etc/rndc.key est utilisée pour authentifier les commandes envoyées au serveur si le fichier-config n'existe pas.
-s serveur
serveur est le nom ou l'adresse du serveur qui correspond à une déclaration de serveur dans le fichier de configuration pour rndc. Si aucun serveur n'est fourni en ligne de commande, l'hôte nommé par la clause default-server dans la déclaration d'options du fichier de configuration rndc est utilisé.
-p port
Cette option demande à BIND 9 d'envoyer les commandes au port TCP port au lieu de son port de canal de contrôle par défaut, 953.
-q
Cette option active le mode silencieux, où le texte des messages renvoyés par le serveur n'est pas affiché sauf en cas d'erreur.
-r
Cette option demande à rndc d'afficher le code de résultat renvoyé par named <#std-iscman-named> après l'exécution de la commande demandée (par exemple, ISC_R_SUCCESS, ISC_R_FAILURE, etc.).
-t délai
Cette option définit la période d'expiration du délai d'inactivité pour rndc à délai secondes. La valeur par défaut est de 60 secondes, et la valeur maximale configurable est de 86400 secondes (1 jour). Si elle est définie à 0, il n'y a pas de délai d'expiration.
-V
Cette option active la journalisation détaillée.
-y clé-serveur
Cette option indique l'utilisation de la clé clé-serveur du fichier de configuration. Pour que la validation des messages de contrôle réussisse, clé-serveur doit être connue par named <#std-iscman-named> avec le même algorithme et la même chaîne secrète. Si aucun clé-serveur n'est spécifié, rndc recherche d'abord une clause clé dans la déclaration de serveur du serveur utilisé, ou si aucune déclaration de serveur n'est présente pour cet hôte, alors dans la clause clé par défaut de la déclaration d'options. Notez que le fichier de configuration contient des secrets partagés qui sont utilisés pour envoyer des commandes de contrôle authentifiées aux serveurs de noms, et ne doit donc pas avoir un accès général en lecture ou en écriture.

COMMANDES

Une liste des commandes supportées par rndc peut être consultée en exécutant rndc sans arguments.

Les commandes actuellement supportées sont :

addzone zone [classe [vue]] configuration
Cette commande ajoute une zone pendant que le serveur est en cours d'exécution. Cette commande nécessite que l'option allow-new-zones soit définie à yes. La chaîne de configuration spécifiée en ligne de commande est le texte de configuration de zone qui serait normalement placé dans named.conf <#std-iscman-named.conf>.

La configuration est sauvegardée dans un fichier appelé nomvue.nzf (ou, si named <#std-iscman-named> est compilé avec liblmdb, un fichier de base de données LMDB appelé nomvue.nzd). nomvue est le nom de la vue, à moins que le nom de la vue ne contienne des caractères incompatibles avec une utilisation comme nom de fichier, auquel cas un hachage cryptographique du nom de la vue est utilisé à la place. Lorsque named <#std-iscman-named> est redémarré, le fichier est chargé dans la configuration de la vue afin que les zones ajoutées puissent persister après un redémarrage.

Cette commande addzone d'exemple ajoute la zone example.com à la vue par défaut :

rndc addzone example.com '{ type primary; file "example.com.db"; };'

(Notez les accolades autour et le point-virgule après le texte de configuration de la zone.)

Voir aussi rndc delzone et rndc modzone.

delzone [-clean] zone [classe [vue]]
Cette commande supprime une zone pendant que le serveur est en cours d'exécution.

Si l'argument -clean est spécifié, le fichier maître de la zone (et le fichier journal, le cas échéant) sont supprimés en même temps que la zone. Sans l'option -clean, les fichiers de zone doivent être supprimés manuellement. (Si la zone est de type secondary ou stub, les fichiers à supprimer sont signalés dans la sortie de la commande rndc delzone.)

Si la zone a été initialement ajoutée via rndc addzone, elle est alors supprimée de manière permanente. Cependant, si elle a été initialement configurée dans named.conf <#std-iscman-named.conf>, cette configuration originale reste en place ; lorsque le serveur est redémarré ou reconfiguré, la zone est recréée. Pour la supprimer de manière permanente, elle doit également être supprimée de named.conf <#std-iscman-named.conf>.

Voir aussi rndc addzone et rndc modzone.

dnssec (-status | -step | -rollover -key id [-alg algorithme] [-quand temps] | -checkds [-key id [-alg algorithme]] [-quand temps] publié | retiré)) zone [classe [vue]]
Cette commande vous permet d'interagir avec la "dnssec-policy" d'une zone donnée.

rndc dnssec -status affiche l'état de signature DNSSEC pour la zone spécifiée.

rndc dnssec -step envoie un signal à une instance de named <#std-iscman-named> pour une zone configurée avec dnssec-policy en mode manuel, lui disant de continuer avec les opérations qui avaient été précédemment bloquées mais consignées. Cela donne à l'opérateur humain une chance d'examiner les messages du journal, de comprendre ce qui va se passer ensuite et ensuite, en utilisant rndc dnssec -step, d'informer named <#std-iscman-named> de passer à l'étape suivante.

rndc dnssec -roll

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

over permet de planifier le transfert de clés pour une clé spécifique (en remplaçant la durée de vie d'origine de la clé).

rndc dnssec -checkds informe named <#std-iscman-named> que le DS pour la clé de signature de clé d'une zone spécifiée a été confirmé comme étant publié ou retiré de la zone parente. Ceci est nécessaire pour compléter un transfert de KSK. Les arguments -key id et -alg algorithm peuvent être utilisés pour spécifier une KSK particulière, si nécessaire ; s'il n'y a qu'une seule clé agissant comme KSK pour la zone, ces arguments peuvent être omis. L'heure de publication ou de retrait du DS est définie à l'heure actuelle par défaut, mais peut être remplacée par une heure spécifique avec l'argument -when time, où time est exprimé en notation YYYYMMDDHHMMSS.

dnstap (-reopen | -roll [number])
Cette commande ferme et rouvre les fichiers de sortie DNSTAP.

rndc dnstap -reopen permet au fichier de sortie d'être renommé extérieurement, afin que named <#std-iscman-named> puisse le tronquer et le rouvrir.

rndc dnstap -roll provoque le roulement automatique du fichier de sortie, similaire aux fichiers journaux. Le fichier de sortie le plus récent se voit ajouter ".0" à son nom ; le fichier de sortie précédent le plus récent est déplacé vers ".1", et ainsi de suite. Si number est spécifié, le nombre de fichiers journaux de sauvegarde est limité à ce nombre.

dumpdb [-all | -cache | -zones | -adb | -bad | -expired | -fail] [view ...]
Cette commande vide les caches du serveur (par défaut) et/ou les zones dans le fichier de vidage pour les vues spécifiées. Si aucune vue n'est spécifiée, toutes les vues sont vidées. (Voir l'option dump-file dans le Manuel de référence de l'administrateur BIND 9.)
fetchlimit [view]
Cette commande vide une liste de serveurs qui sont actuellement limités en débit en raison des paramètres fetches-per-server, et une liste de noms de domaines qui sont actuellement limités en débit en raison des paramètres fetches-per-zone.
flush
Cette commande vide le cache du serveur.
flushname name [view]
Cette commande vide le nom donné du cache DNS de la vue et, le cas échéant, de la base de données d'adresses des serveurs de noms, du cache des mauvais serveurs et du cache SERVFAIL de la vue.
flushtree name [view]
Cette commande vide le nom donné, et tous ses sous-domaines, du cache DNS, de la base de données d'adresses, du cache des mauvais serveurs et du cache SERVFAIL de la vue.
freeze [zone [class [view]]]
Cette commande suspend les mises à jour d'une zone dynamique. Si aucune zone n'est spécifiée, toutes les zones sont suspendues. Cela permet d'apporter des modifications manuelles à une zone normalement mise à jour par des mises à jour dynamiques, et entraîne la synchronisation des modifications du fichier journal dans le fichier maître. Toutes les tentatives de mise à jour dynamique sont refusées pendant que la zone est gelée.

Voir aussi rndc thaw.

halt [-p]
Cette commande arrête le serveur immédiatement. Les modifications récentes apportées par mise à jour dynamique ou IXFR ne sont pas enregistrées dans les fichiers maîtres, mais sont rétablies à partir des fichiers journaux lors du redémarrage du serveur. Si -p est spécifié, l'ID du processus de named <#std-iscman-named> est renvoyé. Cela permet à un processus externe de déterminer quand named <#std-iscman-named> a terminé son arrêt.

Voir aussi rndc stop.

skr -import file zone [class [view]]
Cette commande permet d'importer un fichier SKR pour la zone spécifiée, afin de prendre en charge la signature hors ligne de KSK.
loadkeys [zone [class [view]]]
Cette commande récupère toutes les clés DNSSEC pour la zone donnée du répertoire des clés. Si elles sont dans leur période de publication, elles sont fusionnées dans l'ensemble d'enregistrements RR DNSKEY de la zone. Contrairement à rndc sign, cependant, la zone n'est pas immédiatement resignée par les nouvelles clés, mais est autorisée à se resigner de manière incrémentielle au fil du temps.

Cette commande nécessite que la zone soit configurée avec une dnssec-policy, et exige également que la zone soit configurée pour autoriser le DNS dynamique. (Voir "Politiques de mise à jour dynamique" dans le Manuel de référence de l'administrateur pour plus de détails.)

managed-keys (status | refresh | sync | destroy) [class [view]]
Cette commande inspecte et contrôle la base de données "managed-keys" qui gère la maintenance des ancres de confiance DNSSEC de RFC 5011 https://datatracker.ietf.org/doc/html/rfc5011.html. Si une vue est spécifiée, ces commandes s'appliquent à cette vue ; sinon, elles s'appliquent à toutes les vues.
  • Lorsqu'elle est exécutée avec le mot-clé status, elle affiche l'état actuel de la base de données managed-keys.
  • Lorsqu'elle est exécutée avec le mot-clé refresh, elle force l'envoi d'une requête de rafraîchissement immédiate pour toutes les clés gérées, mettant à jour la base de données managed-keys si de nouvelles clés sont trouvées, sans attendre l'intervalle de rafraîchissement normal.
  • Lorsqu'elle est exécutée avec le mot-clé sync, elle force un vidage immédiat de la base de données managed-keys sur disque (dans le fichier managed-keys.bind ou (viewname.mkeys). Cela synchronise la base de données avec son fichier journal, de sorte que le contenu actuel de la base de données puisse être inspecté visuellement.
  • Lorsqu'elle est exécutée avec le mot-clé destroy, la base de données managed-keys est arrêtée et supprimée, et toute la maintenance des clés est terminée. Cette commande ne doit être utilisée qu'avec une extrême prudence.

    Les clés existantes qui sont déjà approuvées ne sont pas supprimées de la mémoire ; la validation DNSSEC peut continuer après l'utilisation de cette commande. Cependant, les opérations de maintenance des clés cessent jusqu'au redémarrage ou à la reconfiguration de named <#std-iscman-named>, et tous les états de maintenance des clés existants sont supprimés.

    Exécuter rndc reconfig ou redémarrer named <#std-iscman-named> immédiatement après cette commande entraîne la réinitialisation de la maintenance des clés à partir de zéro, comme si le serveur était démarré pour la première fois. Ceci est principalement destiné aux tests, mais peut également être utilisé, par exemple, pour accélérer l'acquisition de nouvelles clés en cas de rollover d'ancre de confiance, ou comme une réparation forcée pour les problèmes de maintenance des clés.

memprof [(on | off | dump)]
Cette commande contrôle le profilage de la mémoire. Pour avoir un effet, named <#std-iscman-named> doit être compilé avec jemalloc, la bibliothèque doit avoir le support de profilage activé et être exécuté avec la configuration de l'allocateur prof:true. (soit via MALLOC_CONF, soit via /etc/malloc.conf)

L'option prof_active:false est recommandée pour garantir que la surcharge de profilage n'affecte pas named <#std-iscman-named> lorsqu'elle n'est pas nécessaire.

Les options on et off démarrent et arrêtent respectivement le profilage de la mémoire jemalloc. Lorsqu'elle est exécutée avec l'option dump, named <#std-iscman-named> déversera le profil dans le répertoire de travail. Le nom sera choisi automatiquement par jemalloc.

modzone zone [class [view]] configuration
Cette commande modifie la configuration d'une zone pendant que le serveur est en cours d'exécution. Cette commande nécessite que l'option allow-new-zones soit définie sur yes. Comme avec addzone, la chaîne de configuration spécifiée sur la ligne de commande est le texte de configuration de zone qui serait normalement placé dans named.conf <#std-iscman-named.conf>.

Si la zone a été initialement ajoutée via rndc addzone, les modifications de configuration sont enregistrées de manière permanente et restent en vigueur après le redémarrage ou la reconfiguration du serveur. Cependant, si elle a été initialement configurée dans named.conf <#std-iscman-named.conf>, alors la configuration d'origine reste en place ; lorsque le serveur est redémarré ou reconfiguré, la zone revient à sa configuration d'origine. Pour rendre les modifications permanentes, elles doivent également être modifiées dans named.conf <#std-iscman-named.conf>.

Voir aussi rndc addzone et rndc delzone.

notify zone [class [view]]
Cette commande renvoie les messages NOTIFY pour la zone.
notrace
Cette commande définit le niveau de débogage du serveur à 0.

Voir aussi rndc trace.

nta [(-class class | -dump | -force | -remove | -lifetime duration)] domain [view]
Cette commande définit une ancre de confiance négative DNSSEC (NTA) pour domain, avec une durée de vie de duration. La durée de vie par défaut est configurée dans named.conf <#std-iscman-named.conf> via l'option nta-lifetime, et vaut par défaut une heure. La durée de vie ne peut pas dépasser une semaine.

Une ancre de confiance négative désactive sélectivement la validation DNSSEC pour les zones dont on sait qu'elles échouent en raison d'une mauvaise configuration plutôt que d'une attaque. Lorsque les données à valider sont au niveau ou en dessous d'une NTA active (et au-dessus de toute autre ancre de confiance configurée), named <#std-iscman-named> interrompt le processus de validation DNSSEC et traite les données comme non sécurisées plutôt que comme invalides. Cela continue jusqu'à ce que la durée de vie de la NTA soit écoulée.

Commandes de l'utilitaire rndc

Les commandes disponibles dans rndc sont les suivantes :

addzone zone [class [view]]
Ajoute une nouvelle zone à la configuration active du serveur.

Si la zone est configurée avec une politique de signature DNSSEC, cette politique est utilisée pour générer les signatures de la zone nouvellement ajoutée. Dans le cas contraire, si la zone doit être signée, une politique de signature par défaut est utilisée.

Voir aussi rndc delzone, rndc loadkeys, rndc modzone, et rndc signing.

ban <ip-address> [<ip-address>...]
Cette commande intercepte les requêtes DNS provenant des adresses IP spécifiées. Les réponses sont renvoyées avec une réponse SERVFAIL. L'interception est annulée automatiquement après une période de temps spécifiée dans l'option response-check-interval du fichier de configuration named.conf <#std-iscman-named.conf>. Pour annuler manuellement l'interception, utilisez la commande unban.
delzone zone [class [view]]
Supprime une zone de la configuration active du serveur.

Voir aussi rndc addzone, rndc loadkeys, rndc modzone, et rndc signing.

dumpdb [-d | -d view]
Écrit le contenu de la base de données de cache du serveur dans des fichiers sur le disque. Les fichiers sont nommés named_dump.db et named_stats.txt. Le premier contient la base de données de cache, et le second contient des statistiques sur l'utilisation de la mémoire.

Si l'option -d est spécifiée, elle écrit les données pour une seule vue donnée. Sinon, elle écrit les données pour toutes les vues.

flush
Supprime toutes les entrées du cache du serveur.
flushname name [view]
Supprime toutes les entrées relatives à une seule chaîne de caractères du cache du serveur. Si le serveur est configuré pour plusieurs vues, le nom est recherché dans la vue spécifiée ou dans toutes les vues si aucune vue n'est spécifiée.

Voir aussi rndc flushtree.

flushtree name [view]
Supprime toutes les entrées relatives à une seule chaîne de caractères et à tous ses descendants du cache du serveur. Si le serveur est configuré pour plusieurs vues, le nom est recherché dans la vue spécifiée ou dans toutes les vues si aucune vue n'est spécifiée.

Voir aussi rndc flushname.

ha
Cette commande imprime la liste des serveurs de secours et les statistiques de leurs transferts de zone. Voir aussi les options allow-transfer et also-notify dans named.conf <#std-iscman-named.conf>.
http
Cette commande envoie une requête HTTP à l'interface de contrôle HTTP du serveur named. L'URL de la requête est spécifiée dans l'argument de la commande. Les résultats sont renvoyés sur la sortie standard.

Voir aussi la directive controls dans named.conf <#std-iscman-named.conf>.

ip-address
Cette commande imprime la liste des adresses IP que le serveur named utilise pour écouter les requêtes DNS, ainsi que les ports sur lesquels il écoute.
key-load
Force le serveur named à recharger toutes les clés DNSSEC qui ont été modifiées. Ceci est utile lorsque les clés sont automatiquement générées ou mises à jour.

Voir aussi rndc signing et rndc loadkeys.

loadkeys
Cette commande recharge toutes les clés ZSK (Zone Signing Key) et KSK (Key Signing Key) pour les zones signées par le serveur. La commande ne fonctionne que si les clés sont stockées dans des fichiers distincts de la zone elle-même.

Voir aussi rndc sign.

logging
Redémarre le système de journalisation du serveur. Ceci est utile pour changer le niveau de détail des journaux ou pour rediriger les journaux vers d'autres destinations.

Voir aussi la section logging de named.conf <#std-iscman-named.conf>.

managed-keys [stop | start]
Cette commande permet d'arrêter ou de démarrer la mise à jour automatique des clés DNSSEC pour les zones signées. Lorsque cette fonctionnalité est activée, le serveur met à jour automatiquement les clés des zones signées.

Voir aussi la commande rndc secroots.

modzone zone [class [view]]
Modifie la configuration d'une zone existante. Ceci peut inclure des changements tels que le type de zone, les serveurs autoritaires, ou les directives de signature DNSSEC.

Voir aussi rndc addzone, rndc delzone, et rndc signing.

nta [-d view] [-f name] [-l lifetime] [-r name] [-c class] [-f]
Cette commande gère les Notified Trusted Authorities (NTA) pour une vue donnée. Les NTA sont utilisées pour indiquer au serveur named qu'il doit faire confiance aux données DNSSEC d'une zone particulière. Les NTA pour une vue sont enregistrées dans un fichier nommé name.nta, où name est le nom de la vue ; si elle contient des caractères incompatibles avec une utilisation comme nom de fichier, un hachage cryptographique est généré à partir du nom de la vue.

Une NTA existante peut être supprimée en utilisant l'option -remove.

La durée de vie d'une NTA peut être spécifiée avec l'option -lifetime. Les suffixes de style TTL peuvent être utilisés pour spécifier la durée de vie en secondes, minutes ou heures. Si la NTA spécifiée existe déjà, sa durée de vie est mise à jour avec la nouvelle valeur. Définir lifetime à zéro équivaut à -remove.

Si -dump est utilisé, tous les autres arguments sont ignorés et une liste des NTA existantes est imprimée. Notez que cela peut inclure des NTA qui ont expiré mais qui n'ont pas encore été nettoyées.

Normalement, named <#std-iscman-named> teste périodiquement pour voir si les données sous une NTA peuvent maintenant être validées (voir l'option nta-recheck dans le Manuel de référence de l'administrateur pour plus de détails). Si les données peuvent être validées, alors la NTA est considérée comme n'étant plus nécessaire et est autorisée à expirer anticipativement. Le paramètre -force surcharge ce comportement et force une NTA à persister pendant toute sa durée de vie, quel que soit le fait que les données auraient pu être validées si la NTA n'était pas présente.

La classe de vue peut être spécifiée avec -class. La classe par défaut est IN, qui est la seule classe pour laquelle DNSSEC est actuellement pris en charge.

Toutes ces options peuvent être raccourcies, c'est-à-dire en -l, -r, -d, -f, et -c.

Les options non reconnues sont traitées comme des erreurs. Pour faire référence à un nom de domaine ou de vue commençant par un trait d'union, utilisez un double trait d'union (--) sur la ligne de commande pour indiquer la fin des options.

querylog [(on | off)]
Cette commande active ou désactive la journalisation des requêtes. Par compatibilité ascendante, cette commande peut également être utilisée sans argument pour activer et désactiver la journalisation des requêtes.

La journalisation des requêtes peut également être activée en dirigeant explicitement la catégorie queries vers un channel dans la section logging de named.conf <#std-iscman-named.conf>, ou en spécifiant querylog yes; dans la section options de named.conf <#std-iscman-named.conf>.

reconfig
Cette commande recharge le fichier de configuration et charge de nouvelles zones, mais ne recharge pas les fichiers de zone existants même s'ils ont été modifiés. Ceci est plus rapide qu'un rndc reload complet lorsqu'il y a un grand nombre de zones, car cela évite d'avoir à examiner les dates de modification des fichiers de zone.
recursing
Cette commande imprime la liste des requêtes sur lesquelles named <#std-iscman-named> est actuellement en cours de récursion, et la liste des domaines auxquels des requêtes itératives sont actuellement envoyées.

La première liste comprend tous les clients uniques qui attendent que la récursion se termine, y compris la requête qui attend une réponse et l'horodatage (secondes depuis l'époque Unix) du moment où named a commencé le traitement de cette requête client.

La deuxième liste comprend les domaines pour lesquels des recherches actives (ou récemment actives) sont en cours. Elle indique le nombre de recherches actives pour chaque domaine et le nombre de requêtes qui ont été passées (autorisées) ou abandonnées (débordées) à la suite de la limite fetches-per-zone. (Remarque : ces compteurs ne sont pas cumulatifs dans le temps ; chaque fois que le nombre de recherches actives pour un domaine tombe à zéro, le compteur pour ce domaine est supprimé, et la prochaine fois qu'une recherche est envoyée à ce domaine, elle est recréée avec les compteurs mis à zéro).

refresh zone [class [view]]
Cette commande planifie la maintenance de la zone pour la zone donnée.
reload
Cette commande recharge le fichier de configuration et les zones.
zone [class [view]]

Si une zone est spécifiée, cette commande recharge uniquement la zone donnée. Si aucune zone n'est spécifiée, le rechargement se fait de manière asynchrone.

reset-stats <counter-name ...>
Cette commande réinitialise les compteurs de statistiques demandés.

Au moins un nom de compteur doit être fourni. Actuellement, les compteurs suivants sont pris en charge : recursive-high-water, tcp-high-water.

responselog [on | off]
Cette commande active ou désactive la journalisation des réponses. Par compatibilité ascendante, cette commande peut également être utilisée sans argument pour activer et désactiver la journalisation des réponses.

Contrairement à la journalisation des requêtes, la journalisation des réponses ne peut pas être activée en dirigeant explicitement la catégorie responses vers un channel dans la section logging de named.conf <#std-iscman-named.conf>, mais elle peut toujours être activée en spécifiant responselog yes; dans la section options de named.conf <#std-iscman-named.conf>.

retransfer [-force] zone [class [view]]
Cette commande retransfère la zone secondaire donnée depuis le serveur primaire.

Si la zone est configurée pour utiliser inline-signing, la version signée de la zone est supprimée ; une fois le retransfert de la version non signée terminé, la version signée est régénérée avec de nouvelles signatures. Avec l'argument optionnel -force fourni s'il y a un transfert de zone en cours, celui-ci sera interrompu avant qu'un nouveau transfert de zone ne soit planifié.

scan
Cette commande analyse la liste des interfaces réseau disponibles pour détecter les changements, sans effectuer un rndc reconfig complet ni attendre le minuteur interface-interval.
secroots [-] [view ...]
Cette commande imprime les racines de sécurité (c'est-à-dire les ancres de confiance configurées via trust-anchors, ou les instructions managed-keys ou trusted-keys [les deux obsolètes], ou dnssec-validation auto) et les ancres de confiance négatives pour les vues spécifiées. Si aucune vue n'est spécifiée, toutes les vues sont imprimées. Les racines de sécurité indiquent si elles sont configurées comme clés de confiance, clés gérées ou clés gérées en cours d'initialisation (clés gérées qui n'ont pas encore été mises à jour par une requête de rafraîchissement de clé réussie).

Si le premier argument est -, alors la sortie est renvoyée via le canal de réponse de rndc et imprimée sur la sortie standard. Sinon, elle est écrite dans le fichier de vidage des secroots, qui par défaut est named.secroots, mais peut être remplacé via l'option secroots-file dans named.conf <#std-iscman-named.conf>.

Voir aussi rndc managed-keys.

serve-stale (on | off | reset | status) [class [view]]
Cette commande active, désactive, réinitialise ou rapporte le statut actuel de la fourniture de réponses obsolètes tel que configuré dans named.conf <#std-iscman-named.conf>.

Si la fourniture de réponses obsolètes est désactivée par rndc-serve-stale off, alors elle reste désactivée même si named <#std-iscman-named> est rechargé ou reconfiguré. rndc serve-stale reset restaure le réglage tel que configuré dans named.conf <#std-iscman-named.conf>.

rndc serve-stale status rapporte si la mise en cache et la fourniture de réponses obsolètes sont actuellement activées ou désactivées. Il rapporte également les valeurs de stale-answer-ttl et max-stale-ttl.

showzone zone [class [view]]
Si le serveur est configuré avec allow-new-zones défini sur yes, alors cette commande imprime la configuration d'une zone en cours d'exécution.

Voir aussi rndc addzone, rndc modzone. et rndc delzone.

sign zone [class [view]]
Cette commande récupère toutes les clés DNSSEC pour la zone donnée à partir du répertoire des clés (voir l'option key-directory dans le Manuel de référence de l'administrateur BIND 9). Si elles sont dans leur période de publication, elles sont fusionnées dans l'ensemble d'enregistrements RRKEY DNS de la zone. Si l'ensemble d'enregistrements RRKEY DNS est modifié, alors la zone est automatiquement resignée avec le nouvel ensemble de clés.

Cette commande nécessite que la zone soit configurée avec une dnssec-policy, et nécessite également que la zone soit configurée pour permettre le DNS dynamique. (Voir « Politiques de mise à jour dynamique » dans le Manuel de référence de l'administrateur pour plus de détails.)

Voir aussi rndc loadkeys.

signing [(-list | -clear keyid/algorithm | -clear all | -nsec3param (parameters | none) | -serial value) zone [class [view]]
Cette commande liste, modifie ou supprime les enregistrements d'état de signature DNSSEC pour la zone spécifiée. Le statut des opérations DNSSEC en cours, telles que la signature ou la génération de chaînes NSEC3, est stocké dans la zone sous la forme d'enregistrements de ressources DNS de type sig-signing-type. rndc signing -list convertit ces enregistrements en une forme lisible par l'homme, indiquant quelles clés signent actuellement ou ont terminé de signer la zone, et quelles chaînes NSEC3 sont en cours de création ou de suppression.

rndc(8) — Manuel BIND 9

NAME

rndc — Contrôle à distance du démon BIND 9

SYNOPSIS

rndc [ [-c config-file] ] [ [-k key-file] ] [ [-s server] ] [ [-p port] ] [ [-d] ] command [ command-options ]

DESCRIPTION

Le programme rndc est un outil pour contrôler le démon named depuis une machine distante, sans avoir à utiliser sendmail ou des techniques similaires. Il fonctionne en envoyant des commandes au démon named via le protocole DNS.

Seules les commandes qui sont autorisées dans le fichier rndc.conf sont exécutées. Le fichier rndc.conf spécifie les clés partagées et les adresses IP autorisées à envoyer des commandes.

Les arguments optionnels -c, -k, -s, -p et -d sont décrits dans la page de manuel rndc.conf(5).

COMMANDS

account
Envoie des informations de compte au fichier de statistiques.
addzone zone [class [view]]
Ajoute une zone au serveur.
delzone zone [class [view]]
Supprime une zone du serveur.
dumpdb [-clean]
Envoie le contenu de la base de données des zones au fichier de vidage.
freeze [zone [class [view]]]
Gèle une zone dynamique. Aucune mise à jour ne sera autorisée tant que la zone n'est pas décongelée. Si aucune zone n'est spécifiée, toutes les zones dynamiques sont gelées.
getkey zone [class [view]]
Demande une clé DNSSEC pour une zone donnée.
getviewkey [view ...]
Demande une clé DNSSEC pour une vue donnée.
halt
Arrête le serveur, en s'assurant que toutes les modifications récentes apportées par des mises à jour dynamiques ou des IXFR sont d'abord sauvegardées dans les fichiers maîtres des zones mises à jour.
loadkeys [zone [class [view]]]
Charge les clés DNSSEC pour une zone donnée. Si aucune zone n'est spécifiée, toutes les zones sont chargées.
loadviewkeys [view ...]
Charge les clés DNSSEC pour une vue donnée.
lock zone [class [view]]
Verrouille une zone dynamique. Aucune mise à jour ne sera autorisée tant que la zone n'est pas déverrouillée. Si aucune zone n'est spécifiée, toutes les zones dynamiques sont verrouillées.
message
Envoie un message au fichier de journalisation du serveur.
mirrors
Envoie les informations sur les zones miroir au fichier de statistiques.
movezone zone [class [view]] destination-view
Déplace une zone d'une vue à une autre.
newsync zone [class [view]]
Force une zone secondaire à vérifier si de nouvelles mises à jour sont disponibles.
nxdomain name [class [view]]
Crée une fausse réponse NXDOMAIN pour un nom donné. Utile pour tester.
pool
Affiche des informations sur les pools d'adresses utilisés par le serveur.
print name [class [view]]
Imprime les enregistrements DNS pour un nom donné. Utile pour tester.
reconfig
Demande au serveur de recharger son fichier de configuration.
refresh zone [class [view]]
Force une zone secondaire à demander une actualisation de sa source maître.
reload zone [class [view]]
Recharge une zone spécifiée. Si aucune zone n'est spécifiée, toutes les zones sont rechargées.
rendername name [class [view]]
Affiche le nom d'une zone dans un format lisible.
reopen
Rouvre les fichiers de journalisation. Utile pour des tests.
retransfer zone [class [view]]
Force une zone secondaire à transférer la zone entière depuis sa source maître.
signzone zone [class [view]] [-isalive deadline] [-dnssecpropagate boolean] [-key keyname] [-Nbits bits]
Signe une zone avec DNSSEC. Le paramètre zone est obligatoire. Les paramètres optionnels class et view peuvent être spécifiés.

Le paramètre -isalive spécifie un délai en secondes avant que la signature ne soit terminée. Si le délai est atteint sans que la signature ne soit terminée, rndc retournera une erreur. Ceci est utile pour s'assurer que la signature est terminée avant de continuer.

Le paramètre -dnssecpropagate active ou désactive la propagation DNSSEC des enregistrements de clés. Par défaut, elle est activée.

Le paramètre -key spécifie le nom de la clé à utiliser pour signer la zone. Si aucune clé n'est spécifiée, la clé par défaut sera utilisée.

Le paramètre -Nbits spécifie le nombre de bits à utiliser pour le hachage NSEC3. La valeur par défaut est 160 bits.

signing zone [class [view]] -nsec3param hash algorithm flags iterations salt
Définit les paramètres NSEC3 pour une zone. C'est le seul mécanisme pris en charge pour utiliser NSEC3 avec des zones inline-signing. Les paramètres sont spécifiés dans le même format qu'un enregistrement ressource NSEC3PARAM : algorithme de hachage, indicateurs, itérations et sel, dans cet ordre.

Actuellement, la seule valeur définie pour l'algorithme de hachage est 1, représentant SHA-1. Les indicateurs peuvent être définis à 0 ou 1, selon que le bit de désactivation (opt-out) dans la chaîne NSEC3 doit être défini. Les itérations définissent le nombre de fois supplémentaires où l'algorithme est appliqué lors de la génération d'un hachage NSEC3. Le sel est une chaîne de données exprimée en hexadécimal, un trait d'union (-) si aucun sel ne doit être utilisé, ou le mot-clé auto, qui fait que named <#std-iscman-named> génère un sel aléatoire de 64 bits.

La seule configuration recommandée est rndc signing -nsec3param 1 0 0 - zone, c'est-à-dire pas de sel, pas d'itérations supplémentaires, pas de désactivation.

Attention :

N'utilisez pas d'itérations, de sel ou de désactivation supplémentaires à moins que toutes leurs implications ne soient pleinement comprises. Un nombre élevé d'itérations entraîne des problèmes d'interopérabilité et expose les serveurs à des attaques par déni de service (DoS) épuisant le processeur.

rndc signing -nsec3param none supprime une chaîne NSEC3 existante et la remplace par NSEC.

rndc signing -serial value définit le numéro de série de la zone à value. Si la valeur ferait que le numéro de série recule, elle est rejetée. L'utilisation principale de ce paramètre est de définir le numéro de série sur les zones signées en ligne.

stats
Cette commande écrit les statistiques du serveur dans le fichier de statistiques. (Voir l'option statistics-file dans le Manuel de l'administrateur BIND 9.)
status
Cette commande affiche le statut du serveur. Notez que le nombre de zones inclut la zone interne bind/CH et la zone de référence par défaut ./IN, s'il n'y a pas de zone racine explicite configurée.
stop -p
Cette commande arrête le serveur, en s'assurant que toutes les modifications récentes apportées par mise à jour dynamique ou IXFR sont d'abord sauvegardées dans les fichiers maîtres des zones mises à jour. Si -p est spécifié, l'ID du processus de named <#std-iscman-named> est retourné. Cela permet à un processus externe de déterminer quand named <#std-iscman-named> a fini de s'arrêter.

Voir aussi rndc halt.

sync -clean [zone [class [view]]]
Cette commande synchronise les modifications du fichier journal pour une zone dynamique vers le fichier maître. Si l'option « -clean » est spécifiée, le fichier journal est également supprimé. Si aucune zone n'est spécifiée, toutes les zones sont synchronisées.
tcp-timeouts [initial idle keepalive advertised]
Lorsqu'elle est appelée sans arguments, cette commande affiche les valeurs actuelles des options tcp-initial-timeout, tcp-idle-timeout, tcp-keepalive-timeout et tcp-advertised-timeout. Lorsqu'elle est appelée avec des arguments, ces valeurs sont mises à jour. Cela permet à un administrateur d'effectuer des ajustements rapides en cas d'attaque par déni de service (DoS). Voir les descriptions de ces options dans le Manuel de l'administrateur BIND 9 pour plus de détails sur leur utilisation.
thaw [zone [class [view]]]
Cette commande active les mises à jour d'une zone dynamique gelée. Si aucune zone n'est spécifiée, toutes les zones gelées sont activées. Cela provoque le rechargement de la zone par le serveur depuis le disque, et réactive les mises à jour dynamiques après la fin du chargement. Après qu'une zone a été décongelée, les mises à jour dynamiques ne sont plus refusées. Si la zone a changé et que l'option ixfr-from-differences est utilisée, le fichier journal est mis à jour pour refléter les changements dans la zone. Sinon, si la zone a changé, tout fichier journal existant est supprimé. Si aucune zone n'est spécifiée, le rechargement se fait de manière asynchrone.

Voir aussi rndc freeze.

trace [level]
Si aucun niveau n'est spécifié, cette commande incrémente le niveau de débogage du serveur d'une unité.
level
Si spécifié, cette commande définit le niveau de débogage du serveur à la valeur fournie.

Voir aussi rndc notrace.

validation (on | off | status) [view ...]
Cette commande active, désactive ou vérifie le statut actuel de la validation DNSSEC. Par défaut, la validation est activée.

Le cache est vidé lorsque la validation est activée ou désactivée pour éviter d'utiliser des données qui pourraient différer entre les états.

zonestatus zone [class [view]]
Cette commande affiche le statut actuel de la zone donnée, y compris le nom du fichier maître et les éventuels fichiers inclus dont elle a été chargée, sa date de chargement la plus récente, son numéro de série actuel, le nombre de nœuds, si la zone prend en charge les mises à jour dynamiques, si la zone est signée DNSSEC, si elle utilise la gestion automatique des clés DNSSEC ou la signature en ligne, et les heures de rafraîchissement ou d'expiration prévues pour la zone.

Voir aussi rndc showzone.

Les commandes rndc qui spécifient des noms de zone, tels que reload, retransfer, ou zonestatus, peuvent être ambiguës lorsqu'elles sont appliquées à des zones de type redirect. Les zones de redirection sont toujours appelées ., et peuvent être confondues avec des zones de type hint ou avec des copies secondaires de la zone racine. Pour spécifier une zone de redirection, utilisez le nom de zone spécial -redirect, sans point final. (Avec un point final, cela spécifierait une zone nommée "-redirect".)

LIMITATIONS

Il n'y a actuellement aucun moyen de fournir le secret partagé pour une server_key sans utiliser le fichier de configuration.

Plusieurs messages d'erreur pourraient être plus clairs.
