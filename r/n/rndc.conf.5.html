NOM

rndc.conf - fichier de configuration de rndc

SYNOPSIS

rndc.conf

DESCRIPTION

rndc.conf est le fichier de configuration de rndc <#std-iscman-rndc>, l'utilitaire de contrôle du serveur de noms BIND 9. Ce fichier a une structure et une syntaxe similaires à named.conf <#std-iscman-named.conf>. Les instructions sont entourées d'accolades et se terminent par un point-virgule. Les clauses dans les instructions sont également terminées par un point-virgule. Les styles de commentaires habituels sont supportés :

Style C : /* */

Style C++ : // jusqu'à la fin de la ligne

Style Unix : # jusqu'à la fin de la ligne

rndc.conf est beaucoup plus simple que named.conf <#std-iscman-named.conf>. Le fichier utilise trois instructions : une instruction options, une instruction server et une instruction key.

L'instruction options contient cinq clauses. La clause default-server est suivie du nom ou de l'adresse d'un serveur de noms. Cet hôte est utilisé lorsqu'aucun serveur de noms n'est donné en argument à rndc <#std-iscman-rndc>. La clause default-key est suivie du nom d'une clé, identifiée par une instruction key. Si aucun keyid n'est fourni sur la ligne de commande rndc, et qu'aucune clause key n'est trouvée dans une instruction server correspondante, cette clé par défaut est utilisée pour authentifier les commandes et les réponses du serveur. La clause default-port est suivie du port auquel se connecter sur le serveur de noms distant. Si aucune option port n'est fournie sur la ligne de commande rndc, et qu'aucune clause port n'est trouvée dans une instruction server correspondante, ce port par défaut est utilisé pour la connexion. Les clauses default-source-address et default-source-address-v6 peuvent être utilisées pour définir les adresses source IPv4 et IPv6 respectivement.

Après le mot-clé server, l'instruction server inclut une chaîne qui est le nom d'hôte ou l'adresse d'un serveur de noms. L'instruction a trois clauses possibles : key, port et addresses. Le nom de la clé doit correspondre au nom d'une instruction key dans le fichier. Le numéro de port spécifie le port de connexion. Si une clause addresses est fournie, ces adresses sont utilisées à la place du nom du serveur. Chaque adresse peut avoir un port optionnel. Si une source-address ou source-address-v6 est fournie, elle est utilisée pour spécifier l'adresse source IPv4 et IPv6 respectivement.

L'instruction key commence par une chaîne identifiante, le nom de la clé. L'instruction a deux clauses. algorithm identifie l'algorithme d'authentification que rndc <#std-iscman-rndc> doit utiliser ; actuellement, seuls HMAC-MD5 (pour la compatibilité), HMAC-SHA1, HMAC-SHA224, HMAC-SHA256 (par défaut), HMAC-SHA384 et HMAC-SHA512 sont pris en charge. Ceci est suivi d'une clause secret qui contient l'encodage base-64 de la clé d'authentification de l'algorithme. La chaîne base-64 est entourée de guillemets doubles.

Il existe deux façons courantes de générer la chaîne base-64 pour le secret. Le programme BIND 9 rndc-confgen <#std-iscman-rndc-confgen> peut être utilisé pour générer une clé aléatoire, ou le programme mmencode, également connu sous le nom de mimencode, peut être utilisé pour générer une chaîne base-64 à partir d'une entrée connue. mmencode n'est pas livré avec BIND 9 mais est disponible sur de nombreux systèmes. Voir la section Exemple pour des lignes de commande types pour chacun.

EXEMPLE

options {
  default-server  localhost;
  default-key     samplekey;
};
server localhost {
  key             samplekey;
};
server testserver {
  key     testkey;
  addresses   { localhost port 5353; };
};
key samplekey {
  algorithm       hmac-sha256;
  secret          "6FMfj43Osz4lyb24OIe2iGEz9lf1llJO+lz";
};
key testkey {
  algorithm   hmac-sha256;
  secret      "R3HI8P6BKw9ZwXwN3VZKuQ==";
};

Dans l'exemple ci-dessus, rndc <#std-iscman-rndc> utilise par défaut le serveur à localhost (127.0.0.1) et la clé appelée "samplekey". Les commandes au serveur localhost utilisent la clé "samplekey", qui doit également être définie dans le fichier de configuration du serveur avec le même nom et le même secret. L'instruction key indique que "samplekey" utilise l'algorithme HMAC-SHA256 et sa clause secret contient l'encodage base-64 du secret HMAC-SHA256 entouré de guillemets doubles.

Si rndc -s testserver <#cmdoption-rndc-s> est utilisé, alors rndc <#std-iscman-rndc> se connecte au serveur sur localhost port 5353 en utilisant la clé "testkey".

Pour générer un secret aléatoire avec rndc-confgen <#std-iscman-rndc-confgen> :

rndc-confgen <#std-iscman-rndc-confgen>

Un fichier rndc.conf complet, incluant la clé générée aléatoirement, est écrit sur la sortie standard. Des instructions key et controls commentées pour named.conf <#std-iscman-named.conf> sont également imprimées.

Pour générer un secret base-64 avec mmencode :

echo "known plaintext for a secret" | mmencode

CONFIGURATION DU SERVEUR DE NOMS

Le serveur de noms doit être configuré pour accepter les connexions rndc et pour reconnaître la clé spécifiée dans le fichier rndc.conf, en utilisant l'instruction controls dans named.conf <#std-iscman-named.conf>. Voir les sections sur l'instruction controls dans le Manuel de Référence de l'Administrateur BIND 9 pour plus de détails.
