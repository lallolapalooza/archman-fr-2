NOM

rubytest - test ruby via l'API rubytest

DESCRIPTION

La commande rubytest est une interface en ligne de commande pour exécuter des tests pour les frameworks de test basés sur RubyTest.

APERÇU

L'outil en ligne de commande rubytest suit bon nombre des conventions usuelles, ce qui rend son utilisation assez simple. L'option -h/--help est disponible pour détailler toutes ses options. Voici un exemple d'utilisation basique.

$ rubytest -Ilib test/*_test.rb

Ceci ajouterait lib au $LOAD_PATH de Ruby puis chargerait tous les fichiers de test correspondant au glob test/*_test.rb.

Lorsque vous exécutez des tests, vous devez vous assurer de charger votre framework de test ou l'adaptateur Ruby Test de votre framework. Ceci est généralement fait via un script d'aide dans les fichiers de test, mais peut également être fait via des options en ligne de commande, par exemple.

$ rubytest -r lemon -r ae test/test_*.rb

Bien sûr, il peut devenir fastidieux de taper une commande aussi longue à plusieurs reprises. Cela peut être résolu via un fichier de configuration. Pour l'utiliser, ajoutez un fichier etc/test.rb à un projet et ajoutez-y des entrées Test.run (un alias pour Test.configure).

Test.run do |r|
  r.loadpath ´lib´
  r.test_files << ´test/*_test.rb´
end
Test.run ´coverage´ do |r|
  r.loadpath ´lib´
  r.test_files << ´test/*_test.rb´
  r.before do
    require ´simplecov´
    Simplecov.setup do |s|
      s.filter ´test/´
      s.command_name File.basename($0)
      s.coverage_dir ´log/coverage´
    end
    # pour assurer une couverture correcte
    require ´myapp´
  end
end

Maintenant, lorsque rubytest est utilisé, la première configuration s'appliquera. Pour utiliser la configuration ´coverage´, utilisez l'option -p/--profile.

$ rubytest -p coverage

De cette manière, un projet peut avoir n'importe quel nombre de configurations de test différentes, et il est facile de choisir entre elles.

Notez que l'exemple ci-dessus aurait pu utiliser Test.configure au lieu de Test.run. Ils font la même chose. Mais n'utilisez pas Test.run! car cela provoquerait l'exécution immédiate des tests.

Le fichier de configuration peut être dans le répertoire config au lieu de etc, ce qui est bien pour les projets Rails. Mais si vous préférez un fichier à la racine du projet, alors soit Testfile, soit .test peuvent également être utilisés. Tous ces emplacements sont pris en charge simplement parce qu'aucune convention de configuration n'a pris une emprise solide dans la communauté Ruby. Cependant, nous recommandons vivement d'utiliser etc/test.rb. En fin de compte, cela semble être la meilleure convention globale.

UTILISATION

rubytest [options] [fichiers ...]

OPTIONS

  • -p --profile <NOM> Utilise le profil de configuration.
  • -f --format <NOM> Format du rapport.
  • y --tapy Raccourci pour -f tapy.
  • -j --tapj Raccourci pour -f tapj.
  • -t --tag <TAG> Sélectionne les tests par tag.
  • -u --unit <TAG> Sélectionne les tests par unité logicielle.
  • -m --match <TEXTE> Sélectionne les tests par description.
  • -A --autopath Ajoute automatiquement des chemins à $LOAD_PATH.
  • -I --loadpath <CHEMIN> Ajoute le chemin donné à $LOAD_PATH.
  • -C --chdir <DIR> Change de répertoire avant d'exécuter les tests.
  • -R --chroot Change pour le répertoire racine du projet avant d'exécuter les tests.
  • -r --require <FICHIER> Requiert le fichier.
  • -c --config <FICHIER> Utilise un fichier de configuration alternatif.
  • -V --verbose Fournit des détails supplémentaires dans les rapports.
  • --[no-]ansi Active/désactive les couleurs ANSI.
  • --debug Active le mode débogage.
  • --about Affiche des informations sur rubytest.
  • --version Affiche la version de rubytest.
  • -h --help Affiche ce message d'aide.
