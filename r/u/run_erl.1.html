NOM

run_erl - Rediriger les flux d'entrée et de sortie Erlang sur les systèmes Unix

DESCRIPTION

Le programme run_erl est spécifique aux systèmes Unix. Ce programme redirige les flux d'entrée et de sortie standard afin que toutes les sorties puissent être enregistrées. Il permet également au programme to_erl de se connecter à la console Erlang, rendant possible la surveillance et le débogage à distance d'un système embarqué.

Pour plus d'informations sur l'utilisation, consultez le Guide de l'utilisateur des systèmes embarqués dans la Documentation système.

run_erl [-daemon] dir_tube/ dir_log "commande_exec arg1 arg2 ..."

Arguments :

-daemon

Cette option est fortement recommandée. Elle permet à run_erl de s'exécuter en arrière-plan, complètement détaché de tout terminal de contrôle, et la commande retourne immédiatement à l'appelant. Sans cette option, run_erl doit être démarré en utilisant plusieurs astuces dans le shell pour le détacher complètement du terminal utilisé lors de son lancement. L'option doit être le premier argument de run_erl sur la ligne de commande.

dir_tube

Le tube nommé, généralement /tmp/. Il doit être suffixé par un / (slash), c'est-à-dire /tmp/epipes/, et non /tmp/epipes.

dir_log

Les fichiers journaux, c'est-à-dire :
•Un fichier journal, run_erl.log, qui enregistre la progression et les avertissements du programme run_erl lui-même.
•Jusqu'à cinq fichiers journaux d'au maximum 100 Ko chacun contenant le contenu des flux standard depuis et vers la commande. (Le nombre de journaux et les tailles peuvent être modifiés par des variables d'environnement, voir la section Variables d'environnement ci-dessous.)

Lorsque les journaux sont pleins, run_erl supprime et réutilise le fichier journal le plus ancien.

"commande_exec arg1 arg2 ..."

Une chaîne de caractères séparée par des espaces spécifiant le programme à exécuter. Le deuxième champ est typiquement un nom de commande tel que erl.

Notes concernant les fichiers journaux

Pendant son exécution, run_erl envoie toutes les sorties, sans interprétation, dans un fichier journal. Le fichier est nommé erlang.log.N, où N est un entier. Lorsque le journal est "plein" (taille de journal par défaut de 100 Ko), run_erl commence à enregistrer dans le fichier erlang.log.(N+1), jusqu'à ce que N atteigne un certain nombre (par défaut 5), après quoi N recommence à 1 et les fichiers les plus anciens commencent à être écrasés.

Si aucune sortie ne provient du shell Erlang, mais que la machine Erlang semble toujours être active, un message "ALIVE" est écrit dans le journal ; il s'agit d'un horodatage et il est écrit, par défaut, après 15 minutes d'inactivité. De plus, si la sortie d'Erlang est enregistrée, mais que plus de 5 minutes (par défaut) se sont écoulées depuis la dernière fois que nous avons reçu quelque chose d'Erlang, un horodatage est écrit dans le journal. Les messages "ALIVE" ressemblent à ceci :

===== ALIVE <chaîne_date-heure>

Les autres horodatages ressemblent à ceci :

===== <chaîne_date-heure>

chaîne_date-heure est la date et l'heure d'écriture du message, par défaut en heure locale (peut être changée en UTC si nécessaire). Elle est formatée avec la fonction ANSI-C strftime en utilisant la chaîne de format %a %b %e %T %Z %Y, qui produit des messages comme ===== ALIVE Jeu Mai 15 10:13:36 MEST 2003 ; cela peut être modifié, voir la section suivante.

Variables d'environnement

Les variables d'environnement suivantes sont reconnues par run_erl et modifient le comportement de journalisation. Pour plus d'informations, voir la section précédente.

RUN_ERL_LOG_ALIVE_MINUTES

Temps d'attente avant d'écrire un message "ALIVE" dans le journal (en minutes). Par défaut 15, minimum 1.

RUN_ERL_LOG_ACTIVITY_MINUTES

Temps d'inactivité d'Erlang avant que la sortie ne soit précédée d'un horodatage. Par défaut RUN_ERL_LOG_ALIVE_MINUTES divisé par 3, minimum 1.

RUN_ERL_LOG_ALIVE_FORMAT

Spécifie une autre chaîne de format à utiliser dans l'appel de bibliothèque C strftime. C'est-à-dire, spécifier ceci à "%e-%b-%Y, %T %Z" donne des messages de journal avec des horodatages comme 15-Mai-2003, 10:23:04 MET. Pour plus d'informations, voir la documentation de la fonction de bibliothèque C strftime. Par défaut "%a %b %e %T %Z %Y".

RUN_ERL_LOG_ALIVE_IN_UTC

Si défini à autre chose que 0, toutes les heures affichées par run_erl seront en UTC (GMT, CET, MET, sans heure d'été), plutôt qu'en heure locale. Cela n'affecte pas les données provenant d'Erlang, seulement les journaux générés directement par run_erl. L'application SASL peut être modifiée en conséquence en définissant la variable d'application Erlang utc_log à true.

RUN_ERL_LOG_GENERATIONS

Contrôle le nombre de fichiers journaux écrits avant que les anciens fichiers ne soient réutilisés. Par défaut 5, minimum 2, maximum 1000.

Notez que, pour indiquer le fichier le plus récent, run_erl supprimera le fichier journal le plus ancien pour maintenir un "trou" dans la séquence des fichiers. Par exemple, si les fichiers journaux #1, #2, #4 et #5 existent, cela signifie que #2 est le plus récent et #4 le plus ancien. Vous obtiendrez donc au plus un fichier journal de moins que la valeur définie par RUN_ERL_LOG_GENERATIONS.

RUN_ERL_LOG_MAXSIZE

La taille, en octets, d'un fichier journal avant de passer à un nouveau fichier journal. Par défaut 100000, minimum 1000, maximum environ 2^30.

RUN_ERL_DISABLE_FLOWCNTRL

Si défini, désactive le contrôle de flux d'entrée et de sortie pour le pty ouvert par run_erl. Utile si vous souhaitez éliminer tout risque de bloquer accidentellement le contrôle de flux en utilisant Ctrl-S (au lieu de Ctrl-D pour se détacher), ce qui peut entraîner le blocage de l'ensemble du processus Beam, et dans le cas d'une exécution de heart en tant que superviseur, même le processus heart sera bloqué lors de l'écriture du message de journal dans le terminal, laissant le processus heart incapable de faire son travail.
