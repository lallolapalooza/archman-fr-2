NOM

run0 - Élever les privilèges

SYNTAXE

run0 [OPTIONS...] [COMMANDE...]

DESCRIPTION

run0 peut être utilisé pour acquérir temporairement et interactivement des privilèges élevés ou différents. Il remplit un rôle similaire à sudo(8), mais fonctionne différemment sur certains points clés :

•Aucun privilège d'exécution ou contexte de sécurité n'est hérité de l'appelant vers les commandes invoquées, car elles sont lancées à partir d'un service frais et isolé lancé par le gestionnaire de services.
•L'authentification se fait via polkit[1], isolant ainsi l'invite d'authentification du terminal (si possible).
•Un pseudo-terminal indépendant est alloué pour la commande invoquée, détachant son cycle de vie et l'isolant pour des raisons de sécurité.
•Aucune fonctionnalité de bit d'accès de fichier SetUID/SetGID n'est utilisée pour l'implémentation.

Dans l'ensemble, cela devrait fournir une alternative plus sûre et plus robuste au mécanisme sudo, en particulier dans les environnements système où le support SetUID/SetGID n'est pas disponible (par exemple, en définissant la variable NoNewPrivileges= dans systemd-system.conf(5)).

Toute session invoquée via run0 s'exécutera via la pile PAM "systemd-run0".

Notez que run0 est implémenté comme une invocation alternative multi-appel de systemd-run(1). C'est-à-dire que run0 est un lien symbolique vers le fichier exécutable systemd-run, et il se comporte comme run0 s'il est invoqué via le lien symbolique, sinon il se comporte comme systemd-run.

OPTIONS

Les options suivantes sont comprises :

--unit=

Utilise ce nom d'unité au lieu d'un nom généré automatiquement.

Ajouté dans la version 256.

--property=

Définit une propriété de l'unité de service qui est créée. Cette option prend une affectation dans le même format que la commande set-property de systemctl(1).

Ajouté dans la version 256.

--description=

Fournit une description pour l'unité de service qui est invoquée. Si elle n'est pas spécifiée, la commande elle-même sera utilisée comme description. Voir Description= dans systemd.unit(5).

Ajouté dans la version 256.

--slice=

Fait de la nouvelle unité .service partie de la tranche spécifiée, au lieu de user.slice.

Ajouté dans la version 256.

--slice-inherit

Fait de la nouvelle unité .service partie de la tranche dans laquelle run0 lui-même a été invoqué. Cette option peut être combinée avec --slice=, auquel cas la tranche spécifiée via --slice= est placée dans la tranche où la commande run0 est invoquée.

Exemple : considérez que run0 est invoqué dans la tranche foo.slice, et que l'argument --slice= est bar. L'unité sera alors placée sous foo-bar.slice.

Ajouté dans la version 256.

--user=, -u, --group=, -g

Commute vers l'utilisateur/groupe spécifié. Si non spécifié, par défaut "root", sauf si --area= est utilisé (voir ci-dessous), auquel cas il prend par défaut l'utilisateur appelant.

Ajouté dans la version 256.

--nice=

Exécute la session invoquée avec le niveau de priorité spécifié.

Ajouté dans la version 256.

--chdir=, -D

Exécute la session invoquée avec le répertoire de travail spécifié. Si non spécifié, par défaut le répertoire de travail actuel du client si on bascule vers l'utilisateur root, ou le répertoire personnel de l'utilisateur cible sinon.

Ajouté dans la version 256.

--via-shell

Invoque le shell de connexion de l'utilisateur cible et exécute la commande spécifiée (le cas échéant) via celui-ci.

Ajouté dans la version 258.

-i

Raccourci pour --via-shell --chdir='~'.

Ajouté dans la version 258.

--setenv=NOM[=VALEUR]

Exécute la session invoquée avec la variable d'environnement spécifiée définie. Ce paramètre peut être utilisé plusieurs fois pour définir plusieurs variables. Lorsque "=" et VALEUR sont omis, la valeur de la variable du même nom dans l'environnement appelant sera utilisée.

Ajouté dans la version 256.

--background=COULEUR

Change la couleur d'arrière-plan du terminal vers la couleur ANSI spécifiée tant que la session dure. Si non spécifié, l'arrière-plan sera teinté d'une tonalité rougeâtre lors de l'opération en tant que root, et d'une tonalité jaunâtre lors de l'opération sous un autre UID, pour rappeler les privilèges modifiés. La couleur spécifiée doit être une couleur d'arrière-plan SGR ANSI X3.64, c'est-à-dire des chaînes telles que "40", "41", ..., "47", "48;2;...", "48;5;...". Voir Code d'échappement ANSI (Wikipedia)[2] pour les détails. Définir sur une chaîne vide pour désactiver.

Exemple : "--background=44" pour un arrière-plan bleu.

Ajouté dans la version 256.

--pty, --pty-late, --pipe

Demande l'allocation d'un pseudo TTY pour la session run0 (dans le cas de --pty ou --pty-late), ou demande la transmission directe des descripteurs de fichiers STDIN, STDOUT et STDERR de l'appelant (dans le cas de --pipe). --pty-late est très similaire à --pty mais commence le traitement TTY uniquement une fois le démarrage de l'unité terminé, laissant l'entrée aux agents de mot de passe/polkit jusqu'à ce moment. Si aucun de ces commutateurs n'est spécifié, ou si à la fois --pipe et l'un de --pty/--pty-late sont spécifiés, le mode sera choisi automatiquement : si l'entrée standard, la sortie standard et la sortie d'erreur standard sont tous connectés à un TTY, alors un pseudo TTY est alloué (en mode --pty-late sauf si --no-ask-password est spécifié, auquel cas --pty est sélectionné), sinon les descripteurs de fichiers pertinents sont transmis directement.

--pty et --pipe ont été ajoutés dans la v257.

--pty-late a été ajouté dans la v258.

--shell-prompt-prefix=CHAINE

Définit une chaîne de préfixe pour l'invite de shell. Cela contrôle finalement la variable d'environnement $SHELL_PROMPT_PREFIX pour le programme invoqué, qui est généralement importée dans l'invite du shell. Par défaut – si les emojis sont pris en charge – un emoji de super-héros est affiché (🦸). Cette valeur par défaut peut également être modifiée (ou désactivée) en passant la variable d'environnement $SYSTEMD_RUN_SHELL_PROMPT_PREFIX à run0, voir ci-dessous. Définir sur une chaîne vide pour désactiver le préfixe de l'invite de shell.

Ajouté dans la version 257.

--lightweight=BOOLEEN

Contrôle s'il faut activer le gestionnaire de services par utilisateur pour l'utilisateur cible. Par défaut, si l'utilisateur cible est "root" ou un utilisateur système, le gestionnaire de services par utilisateur n'est pas activé suite à l'invocation de run0, sinon il l'est.

Cela contrôle finalement la variable d'environnement $XDG_SESSION_CLASS que pam_systemd(8) respecte.

Ajouté dans la version 258.

--area=ZONE

Contrôle la "zone" du compte cible à laquelle se connecter. Les zones sont des répertoires personnels secondaires au sein du répertoire personnel principal de l'utilisateur cible, c'est-à-dire se connecter à la zone "foobar" d'un compte se traduit par $HOME étant défini sur ~/Areas/foobar lors de la connexion.

Si cette option est utilisée, l'utilisateur par défaut vers lequel transitionner change de root à l'utilisateur appelant (mais --user= est prioritaire, voir ci-dessus). Autrement dit, spécifier une zone sans utilisateur est un mécanisme pour créer une nouvelle session de l'utilisateur appelant, mais avec une zone différente.

Cela contrôle finalement la variable d'environnement $XDG_AREA que pam_systemd(8) respecte.

Pour plus de détails sur le concept de zone, voir pam_systemd_home(8).

Ajouté dans la version 258.

--machine=

Exécute l'opération dans un conteneur local. Spécifiez un nom de conteneur auquel se connecter.

Ajouté dans la version 256.

--no-ask-password

Ne pas interroger

NOM

run0 - Exécuter un programme avec des privilèges élevés, en tant qu'un autre utilisateur

SYNTAXIS

run0 [OPTIONS...] [COMMAND] [ARG...]

run0 [OPTIONS...] --user=USER [COMMAND] [ARG...]

run0 [OPTIONS...] --machine=MACHINE [COMMAND] [ARG...]

DESCRIPTION

Utilisez run0 pour exécuter un programme en tant qu'un autre utilisateur. Ceci est utile pour les opérations administratives qui nécessitent des privilèges élevés ou pour tester des programmes dans un environnement différent. Par défaut, run0 s'exécute en tant qu'utilisateur root s'il est lancé par un utilisateur non privilégié.

run0 est destiné à être utilisé comme alternative à des outils comme sudo ou su.

Le programme lancé est géré comme un service systemd. La session de ce programme sera configurée avec les mêmes paramètres et politiques que ceux utilisés pour les services systemd standards. Par exemple, des contrôles de sécurité via Polkit peuvent être appliqués.

Par défaut, run0 s'exécutera en tant qu'utilisateur root. Pour s'exécuter en tant qu'un autre utilisateur, utilisez l'option --user=. Si vous spécifiez --machine=, run0 s'exécutera dans le contexte de cet utilisateur sur la machine distante.

Des variables d'environnement spécifiques peuvent être définies pour le programme lancé à l'aide de l'option --setenv=.

Si vous ne spécifiez pas de commande, un shell interactif sera lancé. Le shell par défaut est celui défini dans l'environnement de l'utilisateur lançant la commande, ou /bin/sh si vous utilisez l'option --machine=.

Notez que, contrairement à sudo, run0 lance toujours les shells avec les sémantiques de shell de connexion, indépendamment de l'option -i.

OPTIONS

Les options suivantes sont comprises :

-h, --help
Affiche un court message d'aide et quitte.
--version
Affiche une courte chaîne de version et quitte.

Tous les arguments de ligne de commande après le premier argument qui n'est pas une option font partie de la ligne de commande du processus lancé. Si aucune ligne de commande n'est spécifiée, un shell interactif est invoqué. Le shell à invoquer peut être contrôlé via --via-shell - lorsqu'il est spécifié, le shell de l'utilisateur cible est utilisé - ou --setenv=SHELL=.... Par défaut, le shell de l'utilisateur d'origine est exécuté si l'on opère localement, ou /bin/sh lors de l'opération avec --machine=.

Notez que contrairement à sudo, run0 lance toujours des shells avec des sémantiques de shell de connexion, indépendamment de -i.

ÉTAT DE SORTIE

En cas de succès, 0 est retourné. Si run0 n'a pas réussi à démarrer la session ou si la commande spécifiée échoue, une valeur de retour non nulle sera retournée.

VARIABLES D'ENVIRONNEMENT

Comme avec systemd-run, la session héritera de l'environnement système du gestionnaire de services. En outre, les variables d'environnement suivantes seront définies :

$TERM

Copié depuis le $TERM de l'appelant. Peut être remplacé avec --setenv=.

Ajouté dans la version 256.

$SUDO_USER

Défini avec le nom d'utilisateur de l'utilisateur d'origine.

Ajouté dans la version 256.

$SUDO_UID

Défini avec l'identifiant numérique UNIX de l'utilisateur d'origine.

Ajouté dans la version 256.

$SUDO_GID

Défini avec l'identifiant numérique UNIX primaire de la session d'origine.

Ajouté dans la version 256.

$SHELL_PROMPT_PREFIX

Par défaut, défini avec l'emoji super-héros (si supporté), mais peut être remplacé par la variable d'environnement $SYSTEMD_RUN_SHELL_PROMPT_PREFIX (voir ci-dessous), ou le commutateur --shell-prompt-prefix= (voir ci-dessus).

Ajouté dans la version 257.

Les variables suivantes peuvent être passées à run0 :

$SYSTEMD_RUN_SHELL_PROMPT_PREFIX

Si défini, remplace le préfixe de prompt de shell par défaut que run0 définit pour le shell invoqué (l'emoji super-héros). Définir sur une chaîne vide pour désactiver le préfixe de prompt de shell.

Ajouté dans la version 257.
