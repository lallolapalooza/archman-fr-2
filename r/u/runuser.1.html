RUNUSER(1) Commandes utilisateur RUNUSER(1)

NOM

runuser - exécute une commande avec un ID utilisateur et groupe substitué

SYNTAXE

runuser [options] -u utilisateur [[--] commande [argument...]]

runuser [options] [-] [utilisateur [argument...]]

DESCRIPTION

runuser peut être utilisé pour exécuter des commandes avec un ID utilisateur et groupe substitué. Si l'option -u n'est pas donnée, runuser revient à la sémantique compatible avec su et un shell est exécuté. La différence entre les commandes runuser et su est que runuser ne demande pas de mot de passe (car il peut être exécuté par l'utilisateur root uniquement) et utilise une configuration PAM différente. La commande runuser n'a pas besoin d'être installée avec les permissions set-user-ID.

Si la session PAM n'est pas requise, la solution recommandée est d'utiliser la commande setpriv(1).

Lorsqu'elle est appelée sans arguments, runuser exécute par défaut un shell interactif en tant que root.

Pour des raisons de compatibilité ascendante, runuser ne change pas le répertoire courant par défaut et définit uniquement les variables d'environnement HOME et SHELL (plus USER et LOGNAME si l'utilisateur cible n'est pas root). Cette version de runuser utilise PAM pour la gestion de session.

Notez que runuser utilise dans tous les cas PAM (pam_getenvlist()) pour effectuer la modification finale de l'environnement. Les options en ligne de commande telles que --login et --preserve-environment affectent l'environnement avant qu'il ne soit modifié par PAM.

Depuis la version 2.38, runuser réinitialise les limites de ressources du processus RLIMIT_NICE, RLIMIT_RTPRIO, RLIMIT_FSIZE, RLIMIT_AS et RLIMIT_NOFILE.

OPTIONS

-c, --command=commande

Passe commande au shell avec l'option -c.

-f, --fast

Passe -f au shell, ce qui peut être utile ou non, selon le shell.

-g, --group=groupe

Le groupe principal à utiliser. Cette option n'est autorisée que pour l'utilisateur root.

-G, --supp-group=groupe

Spécifie un groupe supplémentaire. Cette option n'est disponible que pour l'utilisateur root. Le premier groupe supplémentaire spécifié est également utilisé comme groupe principal si l'option --group n'est pas spécifiée.

-, -l, --login

Démarre le shell comme un shell de connexion avec un environnement similaire à une connexion réelle :
•efface toutes les variables d'environnement sauf TERM et celles spécifiées par --whitelist-environment
•initialise les variables d'environnement HOME, SHELL, USER, LOGNAME et PATH
•change vers le répertoire personnel de l'utilisateur cible
•définit argv[0] du shell à '-' afin de faire du shell un shell de connexion

-m, -p, --preserve-environment

Préserve l'environnement entier, c'est-à-dire ne définit pas HOME, SHELL, USER ou LOGNAME. L'option est ignorée si l'option --login est spécifiée.

-P, --pty

Crée un pseudo-terminal pour la session. Le terminal indépendant offre une meilleure sécurité car l'utilisateur ne partage pas de terminal avec la session d'origine. Cela peut être utilisé pour éviter l'injection de commandes via l'ioctl TIOCSTI et d'autres attaques de sécurité contre les descripteurs de fichiers de terminal. La session entière peut également être déplacée en arrière-plan (par exemple, runuser --pty -u utilisateur -- commande &). Si le pseudo-terminal est activé, runuser agit comme un proxy entre les sessions (synchronisation stdin et stdout).

Cette fonctionnalité est principalement conçue pour les sessions interactives. Si l'entrée standard n'est pas un terminal, mais par exemple un pipe (par exemple, echo "date" | runuser --pty -u utilisateur), alors le drapeau ECHO pour le pseudo-terminal est désactivé pour éviter une sortie désordonnée.

-s, --shell=shell

Exécute le shell spécifié au lieu du shell par défaut. Le shell à exécuter est sélectionné selon les règles suivantes, par ordre de priorité :
•le shell spécifié avec --shell
•le shell spécifié dans la variable d'environnement SHELL si l'option --preserve-environment est utilisée
•le shell listé dans l'entrée passwd de l'utilisateur cible
•/bin/sh

Si l'utilisateur cible a un shell restreint (c'est-à-dire non listé dans /etc/shells), alors les options --shell et les variables d'environnement SHELL sont ignorées sauf si l'utilisateur appelant est root.

--session-command=commande

Identique à -c, mais ne crée pas de nouvelle session. (Déconseillé.)

-T, --no-pty

Ne crée pas de pseudo-terminal, l'opposé de --pty et -P. Notez que l'exécution sans pseudo-terminal présente un risque de sécurité lié à l'escalade de privilèges via l'injection de commandes ioctl TIOCSTI/TIOCLINUX.

-u, --user=utilisateur

Exécute commande avec l'ID utilisateur effectif et l'ID groupe de l'utilisateur nommé utilisateur.

-w, --whitelist-environment=liste

Ne réinitialise pas les variables d'environnement spécifiées dans la liste séparée par des virgules lors de l'effacement de l'environnement pour --login. La liste blanche est ignorée pour les variables d'environnement HOME, SHELL, USER, LOGNAME et PATH.

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

FICHIERS DE CONFIGURATION

runuser lit les fichiers de configuration /etc/default/runuser et /etc/login.defs. Les éléments de configuration suivants sont pertinents pour runuser :

ENV_PATH (string)

Définit la variable d'environnement PATH pour un utilisateur normal. La valeur par défaut est /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (string), ENV_SUPATH (string)

Définit la variable d'environnement PATH pour root. ENV_SUPATH a la priorité. La valeur par défaut est /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

ALWAYS_SET_PATH (booléen)

Si défini sur yes et que --login et --preserve-environment n'ont pas été spécifiés, runuser initialise PATH.

La variable d'environnement PATH peut être différente sur les systèmes où /bin et /sbin sont fusionnés dans /usr ; cette variable est également affectée par l'option de ligne de commande --login et le paramètre système PAM (par exemple, pam_env(8)).

STATUT DE SORTIE

runuser retourne normalement le statut de sortie de la commande qu'il a exécutée. Si la commande a été tuée par un signal, runuser retourne le numéro du signal plus 128.

Statuts de sortie générés par runuser lui-même :

1

Erreur générique avant l'exécution de la commande demandée

126

La commande demandée n'a pas pu être exécutée

127

La commande demandée n'a pas été trouvée
