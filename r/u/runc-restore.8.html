NOM

runc-restore - restaurer un conteneur à partir d'un point de contrôle précédent

SYNTAXE

runc restore [option ...] id-conteneur

DESCRIPTION

Restaure l'instance du conteneur à partir d'un runc checkpoint précédemment effectué.

OPTIONS

--console-socket chemin
Chemin vers un socket AF_UNIX qui recevra un descripteur de fichier faisant référence à l'extrémité maître du pseudoterminal de la console. Voir docs/terminals ⟨https://github.com/opencontainers/runc/blob/master/docs/terminals.md⟩.
--image-path chemin
Définit le chemin pour obtenir les fichiers image de criu à restaurer.
--work-path chemin
Définit le chemin pour sauvegarder les fichiers de travail et les journaux de criu. Par défaut, le répertoire des fichiers image est réutilisé.
--tcp-established
Autorise le point de contrôle/restauration des connexions TCP établies. Voir l'option --tcp-establised de criu ⟨https://criu.org/CLI/opt/--tcp-established⟩.
--ext-unix-sk
Autorise le point de contrôle/restauration des sockets Unix externes. Voir l'option --ext-unix-sk de criu ⟨https://criu.org/CLI/opt/--ext-unix-sk⟩.
--shell-job
Autorise le point de contrôle/restauration des jobs shell.
--file-locks
Autorise le point de contrôle/restauration des verrous de fichiers. Voir l'option --file-locks de criu ⟨https://criu.org/CLI/opt/--file-locks⟩.
--manage-cgroups-mode soft|full|strict|ignore.
Mode cgroups. Par défaut, soft. Voir l'option --manage-cgroups de criu ⟨https://criu.org/CLI/opt/--manage-cgroups⟩.

En particulier, pour restaurer le conteneur dans un cgroup différent, --manage-cgroups-mode ignore doit être utilisé lors du checkpoint et de la restore, et l'_id-conteneur (ou la propriété cgroupsPath dans la configuration OCI, si définie) doit être modifié.

--bundle|-b chemin
Chemin vers la racine du répertoire du bundle. Par défaut, le répertoire courant.
--detach|-d
Se détacher du processus du conteneur.
--pid-file chemin
Spécifie le fichier dans lequel écrire le PID du processus initial du conteneur.
--no-subreaper
Désactive l'utilisation du sous-processus de supervision (subreaper) utilisé pour récupérer les processus reparentés.
--no-pivot
N'utilise pas pivot root pour enfermer le processus dans le rootfs. Ceci ne devrait pas être utilisé sauf dans des circonstances exceptionnelles, et peut être dangereux du point de vue de la sécurité.
--empty-ns namespace
Crée un namespace, mais ne restaure pas ses propriétés. Voir l'option --empty-ns de criu ⟨https://criu.org/CLI/opt/--empty-ns⟩.
--auto-dedup
Active la déduplication automatique des images mémoire. Voir l'option --auto-dedup de criu ⟨https://criu.org/CLI/opt/--auto-dedup⟩.
--lazy-pages
Utilise le mécanisme de migration paresseuse (lazy migration). Ceci nécessite un démon criu lazy-pages en cours d'exécution. Voir l'option --lazy-pages de criu ⟨https://criu.org/CLI/opt/--lazy-pages⟩.
--lsm-profile type:label
Spécifie un profil LSM à utiliser lors de la restauration. Ici, type peut être apparmor ou selinux, et label est une étiquette LSM valide. Par exemple, --lsm-profile "selinux:system_u:system_r:container_t:s0:c82,c137". Par défaut, le profil LSM du point de contrôle est utilisé lors de la restauration.
--lsm-mount-context contexte
Spécifie un contexte de montage LSM à utiliser lors de la restauration. Seuls les montages avec un contexte existant verront leur contexte remplacé. Avec cette option, il est possible de modifier les options de montage SELinux. Au lieu de monter avec le contexte du point de contrôle, le contexte spécifié sera utilisé. Par exemple, --lsm-mount-context "system_u:object_r:container_file_t:s0:c82,c137".

VOIR AUSSI

criu(8), runc-checkpoint(8), runc(8).
