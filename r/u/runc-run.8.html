NOM

runc-run - créer et démarrer un conteneur

SYNTAXE

runc run [option ...] container-id

DESCRIPTION

La commande run crée une instance d'un conteneur à partir d'un bundle, et le démarre. Vous pouvez considérer run comme un raccourci pour create suivi de start.

OPTIONS

--bundle|-b chemin
Chemin vers la racine du répertoire du bundle. Par défaut, c'est le répertoire courant.
--console-socket chemin
Chemin vers un socket AF_UNIX qui recevra un descripteur de fichier référençant l'extrémité maître du pseudo-terminal de la console. Voir docs/terminals ⟨https://github.com/opencontainers/runc/blob/master/docs/terminals.md⟩.
--detach|-d
Détacher du processus du conteneur.
--pid-file chemin
Spécifier le fichier dans lequel écrire le PID du processus initial du conteneur.
--no-subreaper
Désactiver l'utilisation du sous-processus de supervision (subreaper) utilisé pour récupérer les processus réparentés.
--no-pivot
Ne pas utiliser `pivot root` pour isoler le processus dans le rootfs. Ceci ne doit pas être utilisé sauf dans des circonstances exceptionnelles et peut être dangereux du point de vue de la sécurité.
--no-new-keyring
Ne pas créer de nouveau keyring de session pour le conteneur. Cela fera hériter au conteneur la clé de session des processus appelants.
--preserve-fds N
Transmettre N descripteurs de fichiers supplémentaires au conteneur (stdio + $LISTEN_FDS + N au total). La valeur par défaut est 0.
--keep
Conserver le répertoire d'état et le cgroup du conteneur. Ceci peut être utile si un utilisateur souhaite vérifier l'état (par exemple, des contrôleurs cgroup) après la sortie du conteneur. Si cette option est utilisée, un runc delete manuel est nécessaire par la suite pour nettoyer les artefacts du conteneur sorti.
