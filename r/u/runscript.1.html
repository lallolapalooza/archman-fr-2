NOM

runscript - interpréteur de scripts pour minicom

SYNTAXE

runscript nom_script [fichier_log [rep_accueil]]

DESCRIPTION

runscript est un interpréteur de scripts simple qui peut être appelé depuis le programme de communication minicom pour automatiser des tâches telles que la connexion à un système Unix ou à votre BBS préféré.

APPEL

Le programme attend le nom d'un script et, éventuellement, un nom de fichier et le répertoire personnel de l'utilisateur comme arguments. Il s'attend à ce que ses entrées et sorties soient connectées à "l'extrémité distante", le système auquel vous vous connectez. Tous les messages de runscript destinés à l'écran local sont dirigés vers la sortie stderr. Tout cela est pris en charge automatiquement si vous l'exécutez depuis minicom. Les paramètres fichier_log et rep_accueil sont uniquement utilisés pour indiquer à la commande log le nom du fichier journal et où l'écrire. Si le nom du répertoire personnel est omis, runscript utilise le répertoire trouvé dans la variable d'environnement $HOME. Si le nom du fichier journal est également omis, les commandes de log sont ignorées.

MOTS-CLÉS

Runscript reconnaît les commandes suivantes :

expect   send     goto     gosub    return   !<   !
exit     print    set      inc      dec      if   timeout
verbose  sleep    break    call     log

APERÇU DES MOTS-CLÉS

send <chaîne>
<chaîne> est envoyée au modem. Elle est suivie d'un '\r'. <chaîne> peut être :
- du texte ordinaire, par ex. 'send bonjour'
- du texte entre guillemets, par ex. 'send "bonjour le monde"'

Dans <chaîne>, les séquences suivantes sont reconnues :

\n - nouvelle ligne
\r - retour chariot
\a - sonnerie
\b - retour arrière
\c - n'envoie pas le '\r' par défaut.
\f - saut de page
\^ - le caractère ^
\o - envoie le caractère o (o est un nombre octal)

Les caractères de contrôle peuvent être utilisés dans la chaîne avec le préfixe ^ (^A à ^Z, ^[, ^ ^], ^^ et ^_). Si vous avez besoin d'envoyer le caractère ^, vous devez le préfixer avec le caractère d'échappement \.
Les caractères octaux sont soit à quatre chiffres, soit délimités par un caractère non-chiffre, par ex. le caractère nul peut être envoyé avec \0000 et 'send 1234' équivaut à 'send \0061234'.
Aussi $(variable_environnement) peut être utilisé, par exemple $(TERM). Minicom transmet trois variables d'environnement spéciales : $(LOGIN), qui est le nom d'utilisateur, $(PASS), qui est le mot de passe, tels que définis dans l'entrée appropriée de l'annuaire de numérotation, et $(TERMLIN) qui est le nombre de lignes de terminal réelles sur votre écran (c'est-à-dire, en excluant la ligne de statut).

print <chaîne>
Affiche <chaîne> sur l'écran local. Par défaut, suivi de '\r\n'. Voir la description de 'send' ci-dessus.
étiquette:
Déclare une étiquette (du nom 'étiquette') à utiliser avec goto ou gosub.
goto <étiquette>
Saute à un autre endroit dans le programme.
gosub <étiquette>
Saute à un autre endroit dans le programme. Lorsque l'instruction 'return' est rencontrée, le contrôle revient à l'instruction après le gosub. Les Gosub peuvent être imbriqués.
return
Retourne d'un gosub.
! <commande>
Lance un shell pour vous dans lequel 'commande' est exécutée. Au retour, la variable '$?' est définie sur le code de sortie de cette commande, vous pouvez donc la tester ensuite avec 'if'.
!< <commande>
Lance un shell pour vous dans lequel 'commande' est exécutée. La sortie stdout de l'exécution de la commande sera envoyée au modem. Au retour, la variable '$?' est définie sur le code de sortie de cette commande, vous pouvez donc la tester ensuite avec 'if'.
exit [valeur]
Sort de "runscript" avec un code de sortie optionnel. (défaut 1)
set <variable> <valeur>
Définit la valeur de <variable> (qui est une seule lettre de a à z) à la <valeur>. Si <variable> n'existe pas, elle sera créée. <valeur> peut être une valeur entière ou une autre variable.
inc <variable>
Incrémente la valeur de <variable> de un.
dec <variable>
Décrémente la valeur de <variable> de un.
if <valeur> <opérateur> <valeur> <instruction>
Exécution conditionnelle de <instruction>. <opérateur> peut être <, >, != ou =. Par ex., 'if a > 3 goto étiquette_sortie'.
timeout <valeur>
Définit le timeout global. Par défaut, 'runscript' se terminera après 120 secondes. Ceci peut être changé avec cette commande. Attention : cette commande agit différemment dans une instruction 'expect', mais nous y reviendrons plus tard.
verbose <on|off>
Par défaut, c'est 'on'. Cela signifie que tout ce qui est lu du modem par 'runscript' est affiché à l'écran. C'est pour que vous puissiez voir ce que 'runscript' fait.
sleep <valeur>
Suspend l'exécution pendant <valeur> secondes.
expect
  expect {
    motif  [instruction]
    motif  [instruction]
    [timeout <valeur> [instruction] ]
    ....
  }
La commande la plus importante de toutes. Expect continue de lire depuis l'entrée jusqu'à ce qu'il lise un motif qui correspond à l'un des motifs spécifiés. Si expect rencontre une instruction optionnelle après ce motif, il l'exécutera. Sinon, l'action par défaut est simplement de sortir de l'expect. 'motif' est une chaîne, tout comme dans 'send' (voir ci-dessus). Normalement, expect expira au bout de 60 secondes et se terminera simplement, mais cela peut être changé avec la commande timeout.
break
Sort d'une instruction 'expect'. Ceci est normalement utile uniquement comme argument pour 'timeout' dans un expect, car l'action par défaut de timeout est de sortir immédiatement.
call <nom_script>
Transfère le contrôle vers un autre fichier de script. Lorsque ce fichier de script se termine sans erreur, le script original continue.
log <texte>
Écrit du texte dans le fichier journal.

NOTES

Si vous voulez que votre script quitte minicom (par exemple, lorsque vous utilisez minicom pour composer votre FAI, puis démarrez une session PPP ou SLIP depuis un script), essayez la commande "! killall -9 minicom" comme dernière commande du script. L'option -9 devrait empêcher minicom de raccrocher la ligne et de réinitialiser le modem avant de quitter.
Eh bien, je ne pense pas que ce soit suffisamment d'informations pour faire de vous un 'programmeur' expérimenté en 'runscript', mais avec les exemples, il ne devrait pas être trop difficile d'écrire des fichiers de script utiles. Les choses seront plus faciles si vous avez de l'expérience en BASIC. Le code source de minicom est fourni avec deux scripts d'exemple, scriptdemo et unixlogin. Surtout le dernier est une bonne base sur laquelle construire vos propres scripts.

NAME

minicom - a serial communication program

SYNOPSIS

minicom [-a] [-c screen] [-d device] [-e] [-g] [-h] [-i program] [-k] [-l logfile] [-m] [-p protocol] [-s] [-t termtype] [-U] [-w] [-X] [-Z] [-x level]

DESCRIPTION

Minicom is a simple-to-use, function-key driven serial communication program for the Unix-like operating system. Minicom is a replacement for the xmodem program. It is well suited for the beginner, but also contains many features for the experienced user.

Minicom is a menu-driven program which includes the ability to script the communication session. The program can be configured for different serial ports and communication parameters.

INVOCATION

When minicom is started without any options, it attempts to open the default serial port (/dev/ttyS0) and waits for you to connect to the modem. If you have a different serial port, you should specify it with the -d option.

The following options are available:

-a
Auto-login. When minicom connects to the serial port, it sends the login name to the remote host. This is useful if you have to log in frequently.
-c screen
Sets the screen size to screen. This can be either the number of rows or the number of rows and columns (e.g. 24 or 24x80).
-d device
Opens the serial port specified by device. If this option is not specified, minicom tries to open the default serial port.
-e
Disable the display of remote terminal output. This is useful when you are using minicom as a terminal emulator to connect to a remote host.
-g
When minicom starts, it also displays the screen content. This is useful for debugging.
-h
Display a help message and exit.
-i program
Sets the initial program to be executed. This program is executed after the serial port is opened.
-k
Disable the display of local echo. This is useful when you are connecting to a remote host that echoes characters.
-l logfile
Sets the log file to logfile. If this option is not specified, minicom uses the default log file.
-m
Enable the display of messages. This is useful for debugging.
-p protocol
Sets the initial transfer protocol to protocol. The available protocols are: ascii, xmodem, ymodem, zmodem.
-s
Start minicom in script mode. This is useful for transferring files.
-t termtype
Sets the terminal type to termtype. This is useful for applications that require a specific terminal type.
-U
Enable UTF-8 encoding. This is useful for displaying characters that are not in the ASCII character set.
-w
Wrap lines. When this option is enabled, long lines are wrapped to the next line. This is useful for displaying files that are wider than the screen.
-X
Disable X Window System support. This is useful when running minicom in a text-only environment.
-Z
Disable the display of the status line. This is useful for maximizing the screen space.
-x level
Set the debugging level to level. Higher values mean more debugging output.

KEYWORDS

serial communication, terminal emulator, modem

OVERVIEW OF KEYWORDS

This section is intentionally left blank.

NOTES

The default serial port is /dev/ttyS0. The default log file is /var/log/minicom.log. The default screen size is 24x80.

screen(1), picocom(1), minicom(1)
