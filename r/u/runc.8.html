NOM

runc - Client d'exécution de l'Open Container Initiative

SYNOPSIS

runc [option-globale ...] commande [option-commande ...] [argument ...]

DESCRIPTION

runc est un client en ligne de commande pour exécuter des applications packagées selon le format de l'Open Container Initiative (OCI) et est une implémentation conforme de la spécification de l'Open Container Initiative.

runc s'intègre bien avec les superviseurs de processus existants pour fournir un environnement d'exécution de conteneurs de production pour les applications. Il peut être utilisé avec vos outils de surveillance de processus existants et le conteneur sera lancé comme enfant direct du superviseur de processus.

Les conteneurs sont configurés à l'aide de bundles. Un bundle pour un conteneur est un répertoire qui inclut un fichier de spécification nommé config.json et un système de fichiers racine. Le système de fichiers racine contient le contenu du conteneur.

Pour exécuter une nouvelle instance d'un conteneur :

# runc run [ -b bundle ] identifiant-conteneur

Où identifiant-conteneur est le nom que vous donnez à l'instance du conteneur que vous démarrez. Le nom que vous fournissez pour l'instance du conteneur doit être unique sur votre hôte.

Fournir le répertoire du bundle à l'aide de -b est facultatif. La valeur par défaut pour bundle est le répertoire courant.

COMMANDES

checkpoint
Checkpoint un conteneur en cours d'exécution. Voir runc-checkpoint(8).
create
Crée un conteneur. Voir runc-create(8).
delete
Supprime toutes les ressources détenues par le conteneur; souvent utilisé avec des conteneurs détachés. Voir runc-delete(8).
events
Affiche les événements du conteneur, tels que les notifications OOM, les statistiques CPU, mémoire, E/S et réseau. Voir runc-events(8).
exec
Exécute un nouveau processus à l'intérieur du conteneur. Voir runc-exec(8).
kill
Envoie un signal spécifié au processus d'initialisation du conteneur. Voir runc-kill(8).
list
Liste les conteneurs démarrés par runc avec le --root donné. Voir runc-list(8).
pause
Suspend tous les processus à l'intérieur du conteneur. Voir runc-pause(8).
ps
Affiche les processus en cours d'exécution à l'intérieur du conteneur. Voir runc-ps(8).
restore
Restaure un conteneur à partir d'un checkpoint précédent. Voir runc-restore(8).
resume
Reprend tous les processus qui ont été précédemment mis en pause. Voir runc-resume(8).
run
Crée et démarre un conteneur. Voir runc-run(8).
spec
Crée un nouveau fichier de spécification (config.json). Voir runc-spec(8).
start
Démarre un conteneur précédemment créé par runc create. Voir runc-start(8).
state
Affiche l'état du conteneur. Voir runc-state(8).
update
Met à jour les contraintes de ressources du conteneur. Voir runc-update(8).
help, h
Affiche une liste des commandes ou l'aide pour une commande particulière.

OPTIONS GÉNÉRALES

Ces options peuvent être utilisées avec n'importe quelle commande et doivent précéder la commande.

--debug
Active la journalisation de débogage.
--log chemin
Définit la destination du journal à chemin. Par défaut, le journal est envoyé sur stderr.
--log-format text|json
Définit le format du journal (par défaut text).
--root chemin
Définit le répertoire racine pour stocker l'état des conteneurs. Le chemin doit être situé sur tmpfs. Par défaut, c'est /run/runc, ou $XDG_RUNTIME_DIR/runc pour les conteneurs sans privilèges.
--systemd-cgroup
Active le support des cgroups systemd. Si cette option est définie, le spécification du conteneur (config.json) doit avoir la valeur cgroupsPath sous la forme slice:prefix:name (par exemple system.slice:runc:434234).
--rootless true|false|auto
Active ou désactive le mode sans privilèges (rootless). La valeur par défaut est auto, ce qui signifie que le mode sans privilèges est détecté automatiquement.
--help|-h
Affiche l'aide.
--version|-v
Affiche la version.
