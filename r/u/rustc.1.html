RUSTC(1) Commandes utilisateur RUSTC(1)

NOM

rustc - Le compilateur Rust

SYNTAXE

rustc [OPTIONS] ENTREE

DESCRIPTION

Ce programme est un compilateur pour le langage Rust, disponible sur https://www.rust-lang.org.

OPTIONS

-h, --help
Afficher le message d'aide.
--cfg SPEC
Configurer l'environnement de compilation.
-L [TYPE=]CHEMIN
Ajouter un répertoire au chemin de recherche des bibliothèques. Le TYPE optionnel peut être l'un des suivants :
dependance
chercher uniquement les dépendances transitives ici
crate
chercher uniquement les directives `extern crate` locales ici
native
chercher uniquement les bibliothèques natives ici
framework
chercher uniquement les frameworks OSX ici
tous
chercher n'importe quoi ici (par défaut)
-l [TYPE=]NOM
Lier le(s) crate(s) généré(s) à la bibliothèque spécifiée NOM. Le TYPE optionnel peut être l'un de static, dylib, ou framework. S'il est omis, dylib est supposé.
--crate-type [bin|lib|rlib|dylib|cdylib|staticlib|proc-macro]
Liste séparée par des virgules des types de crates que le compilateur doit émettre.
--crate-name NOM
Spécifier le nom du crate en cours de construction.
--emit [asm|llvm-bc|llvm-ir|obj|metadata|link|dep-info|mir][=CHEMIN]
Configurer la sortie que rustc produira. Chaque émission peut également avoir un CHEMIN de sortie explicite spécifié pour ce type d'émission particulier. Ce chemin a la priorité sur l'option -o.
--print [crate-name|file-names|sysroot|target-libdir|cfg|target-list|target-cpus|target-features|relocation-models|code-models|tls-models|target-spec-json|native-static-libs|stack-protector-strategies|link-args]
Liste séparée par des virgules des informations du compilateur à afficher sur stdout.
-g
Équivalent à -C debuginfo=2.
-O
Équivalent à -C opt-level=2.
-o NOMFICHIER
Écrire la sortie dans NOMFICHIER. Ignoré si plusieurs sorties --emit sont spécifiées sans chemin explicite autrement.
--out-dir DIR
Écrire la sortie dans un nom de fichier choisi par le compilateur dans DIR. Ignoré si -o est spécifié. Par défaut, le répertoire courant.
--explain OPT
Fournir une explication détaillée d'un message d'erreur.
--test
Construire un cadre de test (test harness).
--target TARGET
Triple cible pour lequel le code est compilé. Cette option est par défaut le triple cible de l'hôte. Le triple cible a le format général <arch><sub>-<vendor>-<sys>-<abi>, où :
<arch>
x86, arm, thumb, mips, etc.
<sub>
par exemple sur ARM : v5, v6m, v7a, v7m, etc.
<vendor>
pc, apple, nvidia, ibm, etc.
<sys>
none, linux, win32, darwin, cuda, etc.
<abi>
eabi, gnu, android, macho, elf, etc.
-W help
Afficher les options de 'lint' et leurs paramètres par défaut.
-W OPT, --warn OPT
Définir les avertissements de lint.
-A OPT, --allow OPT
Autoriser un lint.
-D OPT, --deny OPT
Refuser un lint.
-F OPT, --forbid OPT
Interdire un lint.
-C FLAG[=VAL], --codegen FLAG[=VAL]
Définir un indicateur lié à la génération de code à la valeur spécifiée. Utiliser -C help pour afficher les indicateurs disponibles. Voir OPTIONS DE CODEGEN ci-dessous.
-V, --version
Afficher les informations de version et quitter.
-v, --verbose
Utiliser une sortie verbeuse.
--remap-path-prefix de=à
Réécrire les préfixes de chemin source dans toutes les sorties, y compris les diagnostics du compilateur, les informations de débogage, les expansions de macro, etc. Le paramètre de=à est analysé de droite à gauche, donc de peut contenir '=', mais à ne le peut pas.

Ceci est utile pour normaliser les produits de construction, par exemple en supprimant le répertoire courant des noms de fichiers émis dans les fichiers objets. Le remplacement est purement textuel, sans tenir compte de la syntaxe des chemins du système actuel. Par exemple --remap-path-prefix foo=bar correspondra à foo/lib.rs mais pas à ./foo/lib.rs.

--extern NOM=CHEMIN
Spécifier l'emplacement d'une bibliothèque Rust externe. Ceux-ci doivent correspondre aux déclarations extern dans le code source du crate.
--sysroot CHEMIN
Remplacer la racine système.
-Z FLAG
Définir des options instables / permanemment instables. Utiliser -Z help pour afficher les options disponibles.
--color auto|always|never
Configurer la coloration de la sortie :
auto
colorer, si la sortie va vers un tty (par défaut) ;
always
toujours colorer la sortie ;
never
ne jamais colorer la sortie.

OPTIONS DE CODEGEN

linker=/chemin/vers/cc
Chemin vers l'utilitaire d'édition de liens à utiliser lors de l'édition de liens de bibliothèques, d'exécutables et d'objets.
link-args='-flag1 -flag2'
Une liste d'arguments supplémentaires séparés par des espaces à passer à l'éditeur de liens lorsque celui-ci est invoqué.
lto
Effectuer des optimisations LLVM au moment de l'édition de liens (link-time optimizations).
target-cpu=help
Sélectionne un processeur cible. Si la valeur est 'help', une liste des CPU disponibles est affichée.
target-feature='+feature1,-feature2'
Une liste de fonctionnalités séparées par des virgules à activer ou désactiver pour la cible. Un '+' précédent active une fonctionnalité tandis qu'un '-' précédent la désactive. Les fonctionnalités disponibles peuvent être découvertes via llc -mcpu=help.
passes=val
Une liste de passes LLVM supplémentaires séparées par des espaces à exécuter. Une valeur de 'list' entraînera l'affichage par rustc de tous les passes connus et sa sortie. Les passes spécifiés sont ajoutés à la fin du gestionnaire de passes normal.
llvm-args='-arg1 -arg2'
Une liste d'arguments séparés par des espaces à passer à LLVM.
rustc(1) — rustc man page

NAME

rustc ‐ le compilateur Rust

SYNOPSIS

rustc [OPTIONS] [RUST_FILES...]

DESCRIPTION

rustc est le compilateur Rust. Il prend des fichiers source Rust et produit des exécutables, des bibliothèques ou d'autres formats de sortie.

Il existe deux types principaux de "crates" que rustc peut produire :

  • binaries : Des exécutables qui peuvent être lancé.
  • libraries : Des bibliothèques qui peuvent être lié à d'autres crates.

Un crate binaire est le format de sortie par défaut. Pour produire une bibliothèque, utilisez l’option --crate-type.

OPTIONS

La plupart de ces options ne sont pas utilisées directement mais via l'outil de construction cargo.

crate-type=vals
Spécifiez le type de crate à produire. Les valeurs possibles sont :
bin
Compilation en un exécutable binaire.
lib
Compilation en une bibliothèque statique (lib.rlib).
rlib
Compilation en une bibliothèque dynamique (lib.so, lib.dylib, dll.so).
dylib
Compilation en une bibliothèque dynamique (lib.so, lib.dylib, dll.so).
cdylib
Compilation en une bibliothèque dynamique C (pour être lié par d’autres langages).
staticlib
Compilation en une bibliothèque statique (lib.a).
proc-macro
Compilation en une bibliothèque de macros de processus.
La valeur par défaut est `bin` si aucune autre n’est spécifiée. Ces valeurs peuvent être séparées par des virgules.
emit=val
Spécifie ce qui doit être produit. Les valeurs possibles sont :
asm
Produit du code assembleur.
bc
Produit du bytecode LLVM (`.bc`).
obj
Produit un fichier objet (`.o`).
bytecode
Produit du bytecode LLVM.
llvm-ir
Produit du LLVM IR.
metadata
Produit uniquement les métadonnées du crate.
La valeur par défaut est `obj`.
cfg=spec
Active des attributs de compilation conditionnelle.
codegen=val
Spécifie le backend de génération de code. Les valeurs possibles sont :
rustc-codegen-gcc-}{(\d+)}
Utilise le backend GCC.
rustc-codegen-llvm
Utilise le backend LLVM (défaut).
debug
Active les informations de débogage (correspond à -g sur GCC).
debuginfo=val
Contrôle le niveau d'émission des informations de débogage :
0
Aucune information de débogage.
1
Tableaux de lignes uniquement (pour les traces de pile et les points d’arrêt).
2
Informations de débogage complètes avec les variables et les informations de type.
extern<ident>=path
Ajoute un chemin de recherche pour les bibliothèques externes.
extern-cfg=spec
Ajoute une configuration externe qui peut être utilisée dans les attributs de compilation conditionnelle.
extra-filename=val
Données supplémentaires à inclure dans chaque nom de fichier de sortie.
force
Force la compilation même si les fichiers de sortie existent.
link=mode
Spécifie le mode de liaison. Les valeurs possibles sont :
dylib
Liaison dynamique.
static
Liaison statique.
link-arg=arg
Ajoute un argument à passer à l'éditeur de liens.
metadata=val
Métadonnées à utiliser pour le "mangling" des noms de symboles.
no-prepopulate-passes
Supprime le pré-remplissage du gestionnaire de passes LLVM exécuté sur le module.
no-vectorize-loops
Supprime l'exécution du passage LLVM de vectorisation de boucles, quel que soit le niveau d'optimisation.
no-vectorize-slp
Supprime l'exécution du passage LLVM de vectorisation SLP, quel que soit le niveau d'optimisation.
no-integrated-as
Force l'utilisation d'un assembleur externe plutôt que celui intégré à LLVM.
no-redzone
Désactive l'utilisation de la zone rouge.
no-stack-check
Désactive les vérifications d'épuisement de la pile (un risque pour la sécurité de la mémoire !).
opt-level=VAL
Optimise avec les niveaux possibles 0-3, s (optimiser pour la taille), ou z (pour une taille minimale).
prefer-dynamic
Préfère la liaison dynamique à la liaison statique.
codegen-units=n
Divise le crate en n unités pour optimiser en parallèle.
out-dir=dir
Spécifie le répertoire de sortie pour les artefacts de compilation.
print=val
Imprime des informations sur le processus de compilation. Les valeurs possibles incluent :
file-names
Imprime les noms de fichiers générés.
sysroot
Imprime le chemin du sysroot.
target-cpus
Imprime les CPU cibles.
target-features
Imprime les fonctionnalités cibles.
codegen=val
Spécifie le backend de génération de code.
remark=val
Imprime des remarques pour ces passes d'optimisation (séparées par des espaces, ou "all").
relocation-model=[pic,static,dynamic-no-pic]
Le modèle de relocalisation à utiliser. (Par défaut : pic)
rpath
Si spécifié, la valeur rpath pour les bibliothèques dynamiques sera définie dans la sortie de la bibliothèque dynamique ou de l'exécutable.
save-temps
Si spécifié, le compilateur conservera davantage de fichiers (.bc, .o, .no-opt.bc) générés tout au long de la compilation dans le répertoire de sortie.
soft-float
Génère des appels de bibliothèque flottante logicielle au lieu d'instructions matérielles.
sysroot=path
Chemin vers le sysroot de Rust.
target=target-triple
Spécifie la cible pour laquelle compiler (par exemple, x86_64-unknown-linux-gnu).

ENVIRONMENT

Certaines de ces options n'affectent que les programmes de test (générés via rustc --test) ; d'autres affectent tous les programmes qui se lient à la bibliothèque standard Rust.

RUST_TEST_THREADS
Le framework de test Rust exécute les tests en parallèle. Cette variable définit le nombre maximum de threads utilisés à cette fin. Ce réglage est écrasé par l'option --test-threads.
RUST_TEST_NOCAPTURE
Si définie à une valeur autre que "0", un synonyme de l'indicateur --nocapture.
RUST_MIN_STACK
Définit la taille minimale de la pile pour les nouveaux threads.
RUST_BACKTRACE
Si définie à une valeur différente de "0", produit une trace de pile dans la sortie d'un programme qui panique.

EXAMPLES

Pour compiler un exécutable à partir d'un fichier source avec une fonction main :
$ rustc -o hello hello.rs

Pour compiler une bibliothèque à partir d'un fichier source :
$ rustc --crate-type=lib hello-lib.rs

Pour compiler l'un ou l'autre avec un fichier de crate (.rs) :
$ rustc hello.rs

Pour compiler un exécutable avec des informations de débogage :
$ rustc -g -o hello hello.rs
