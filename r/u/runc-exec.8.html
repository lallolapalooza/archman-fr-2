NOM

runc-exec - exécuter un nouveau processus dans le conteneur

SYNTAXE

runc exec [option ...] id-conteneur [--] commande [arg ...]

runc exec [option ...] -p process.json id-conteneur

OPTIONS

--console-socket chemin
Chemin vers un socket AF_UNIX qui recevra un descripteur de fichier faisant référence à l'extrémité maître du pseudoterminal de la console. Voir docs/terminals ⟨https://github.com/opencontainers/runc/blob/master/docs/terminals.md⟩.
--cwd chemin
Se déplacer dans chemin dans le conteneur avant d'exécuter la commande.
--env|-e nom=valeur
Définir une variable d'environnement nom à valeur. Peut être spécifié plusieurs fois.
--tty|-t
Allouer un pseudo-TTY.
--user|-u uid[:gid]
Exécuter la commande en tant qu'utilisateur (et, facultativement, groupe) spécifié par uid (et gid).
--additional-gids|-g gid
Ajouter des IDs de groupe supplémentaires. Peut être spécifié plusieurs fois.
--process|-p process.json
Au lieu de spécifier tous les paramètres d'exécution directement sur la ligne de commande, les obtenir d'un fichier process.json, un fichier JSON contenant la spécification du processus telle que définie par la spécification du runtime OCI ⟨https://github.com/opencontainers/runtime-spec/blob/master/config.md#process⟩.
--detach|-d
Se détacher du processus du conteneur.
--pid-file chemin
Spécifier le fichier dans lequel écrire le PID du processus du conteneur.
--process-label label
Définir le label de processus asm pour le processus, couramment utilisé avec selinux(7).
--apparmor profil
Définir le profil apparmor(7) pour le processus.
--no-new-privs
Définir la valeur "pas de nouveaux privilèges" pour le processus.
--cap cap
Ajouter une capacité à l'ensemble des capacités limitées pour le processus. Peut être spécifié plusieurs fois.
--preserve-fds N
Passer N descripteurs de fichiers supplémentaires au conteneur (stdio + $LISTEN_FDS + N au total). La valeur par défaut est 0.
--ignore-paused
Permettre l'exécution dans un conteneur en pause. Par défaut, si un conteneur est en pause, runc exec retourne une erreur ; cette option peut être utilisée pour la contourner. Un conteneur en pause doit être repris pour que l'exécution s'achève.
--cgroup chemin | contrôleur[,contrôleur...]:chemin
Exécuter un processus dans un sous-cgroup. Si le cgroup spécifié n'existe pas, une erreur est retournée. La valeur par défaut est un chemin vide, ce qui signifie qu'il faut utiliser le cgroup de niveau supérieur du conteneur.

Pour cgroup v1 uniquement, un contrôleur particulier (ou plusieurs contrôleurs séparés par des virgules) peut être spécifié, et l'option peut être utilisée plusieurs fois pour définir différents chemins pour différents contrôleurs.

Note pour cgroup v2, dans le cas où le processus ne peut pas rejoindre le cgroup de niveau supérieur, runc exec essaie de rejoindre le cgroup de l'init du conteneur. Ce fallback peut être désactivé en utilisant --cgroup /.

STATUT DE SORTIE

Se termine avec le statut de commande (sauf si -d est utilisé), ou 255 en cas d'erreur.

EXEMPLES

Si le conteneur peut exécuter la commande ps(1), la commande suivante affichera une liste des processus en cours d'exécution dans le conteneur :

# runc exec <id-conteneur> ps
