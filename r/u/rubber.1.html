RUBBER(1) Manuel des commandes générales RUBBER(1)

NOM

rubber - un système de construction pour documents LaTeX

SYNTAXE

rubber [options] sources ...
rubber-pipe [options]

DESCRIPTION

Rubber est un wrapper pour LaTeX et les programmes compagnons. Son but est, étant donné une source LaTeX à traiter, de la compiler suffisamment de fois pour résoudre toutes les références, en exécutant éventuellement des programmes satellites tels que BibTeX, makeindex, Metapost, etc. pour produire les fichiers de données appropriés.

La commande rubber construit complètement les documents spécifiés. Les fichiers source peuvent être soit des sources LaTeX (auquel cas le suffixe .tex peut être omis), soit des documents dans un format que Rubber sait traduire en LaTeX. Si une compilation échoue, l'ensemble du processus s'arrête, y compris la compilation des documents suivants sur la ligne de commande, et rubber retourne un code de sortie non nul.

La commande rubber-pipe fait de même pour un seul document, mais elle lit la source LaTeX depuis l'entrée standard et envoie le document compilé sur la sortie standard.

Certaines informations ne peuvent pas être extraites des sources LaTeX. C'est le cas, par exemple, des chemins de recherche (qui peuvent être spécifiés dans des variables d'environnement comme TEXINPUTS), ou du style à utiliser avec Makeindex. Pour résoudre ce problème, on peut ajouter des informations pour Rubber dans les commentaires des sources LaTeX, voir la section DIRECTIVES.

OPTIONS

Les options sont utilisées soit pour choisir l'action à effectuer, soit pour configurer le processus de construction. Elles sont pour la plupart identiques dans rubber et rubber-pipe. Les options sont analysées en utilisant les conventions de GNU Getopt.

-b, --bzip2
Compresse le document final (au format bzip2). Ceci est équivalent à dire -o bzip2 après toutes les autres options.
--clean
Supprime tous les fichiers produits par la compilation, au lieu de construire le document. Cette option n'existe que dans rubber. Elle s'applique à la compilation telle qu'elle serait effectuée avec les autres options de la ligne de commande, c'est-à-dire que dire "rubber --clean foo" ne supprimera pas foo.ps, tandis que dire "rubber --ps --clean foo" le fera.
-c, --command <commande>
Exécute la commande (ou directive) spécifiée avant d'analyser les fichiers d'entrée. Voir la section DIRECTIVES pour plus de détails.
-e, --epilogue <commande>
Exécute la commande (ou directive) spécifiée après d'analyser les fichiers d'entrée. Voir la section DIRECTIVES pour plus de détails.
-f, --force
Force au moins une compilation de la source. Cela peut être utile, par exemple, si une dépendance inhabituelle a été modifiée (par exemple, un paquet dans un répertoire système). Cette option est sans objet dans rubber-pipe.
-z, --gzip
Compresse le document final (au format gzip). Ceci est équivalent à dire -o gz après toutes les autres options.
-h, --help
Affiche la liste de toutes les options disponibles et quitte proprement.
--inplace
Se déplace dans le répertoire des fichiers source avant la compilation, de sorte que les résultats de la compilation soient au même endroit que leurs sources.
--into <répertoire>
Se déplace dans le répertoire spécifié avant la compilation, de sorte que tous les fichiers soient produits là et non dans le répertoire courant.
--jobname <nom>
Spécifie un nom de travail différent du nom de fichier de base. Cela change le nom des fichiers de sortie et ne s'applique qu'à la première cible.
-k, --keep
Cette option n'est utilisée que dans rubber-pipe. Avec cette option, les fichiers temporaires ne seront pas supprimés après la compilation du document et l'envoi des résultats sur la sortie standard. Le document temporaire est nommé rubtmpX.tex, où X est un nombre tel qu'aucun fichier de ce nom n'existe initialement.
-n, --maxerr <num>
Définit le nombre maximum d'erreurs affichées. Par défaut, jusqu'à 10 erreurs sont signalées, dire -n -1 affiche toutes les erreurs.
-m, --module <module>[:<args>]
Utilise le module spécifié en plus des paquets du document. Des arguments peuvent être passés au paquet en les ajoutant après un deux-points, ils correspondent aux options du paquet en LaTeX. Le module est chargé avant l'analyse des sources du document.
--only <sources>
Compile le document partiellement, en incluant uniquement les sources spécifiées. Cela fonctionne en insérant un appel à \includeonly sur la ligne de commande. L'argument est une liste de noms de fichiers séparés par des virgules.
-o, --post <module>[:<args>]
Utilise le module spécifié comme post-processeur. Ceci est similaire aux options -m sauf que le module est chargé après l'analyse du document.
-d, --pdf
Produit une sortie PDF. Lorsque cette option vient après --ps (par exemple sous la forme -pd), c'est un synonyme de -o ps2pdf, sinon elle agit comme -m pdftex, afin d'utiliser pdfLaTeX au lieu de LaTeX.
-p, --ps
Traite le DVI produit par le processus via dvips(1) pour produire un document PostScript. Cette option est un synonyme de -o dvips, elle ne peut pas venir après --pdf.
-q, --quiet
Diminue le niveau de verbosité. C'est l'inverse de -v.
-r, --read <fichier>
Lit des directives supplémentaires à partir du fichier spécifié (voir également la directive "read").
-S, --src-specials
Active la génération de spéciaux source si le compilateur le supporte. Ceci est équivalent à définir la variable src-specials à yes.
-s, --short
Affiche les messages d'erreur de LaTeX sous une forme compacte (une erreur par ligne).
-I, --texpath <répertoire>
Ajoute le répertoire spécifié au chemin de recherche de TeX.
--synctex
Active le support SyncTeX dans l'exécution LaTeX.
--unsafe
Permet au document d'invoquer des programmes externes arbitraires. Ceci est potentiellement dangereux, n'utilisez cette option que pour des documents provenant d'une source fiable.
-v, --verbose
Augmente le niveau de verbosité. Les niveaux entre 0 et 4 existent, le niveau par défaut est 1 pour rubber et 0 pour rubber-pipe. Attention, dire -vvv fait parler beaucoup Rubber.
--version
Affiche le numéro de version et quitte proprement.
-W, --warn <type>
Signale les informations du type donné s'il n'y a pas eu d'erreur pendant la compilation. Les types disponibles sont : boxes (boîtes trop pleines et pas assez pleines), refs (références non définies ou multiples), misc (autres avertissements) et all pour signaler tous les avertissements.

MODULES

L'action de Rubber est influencée par les modules. Les modules s'occupent des fonctionnalités particulières des paquets et des programmes externes.

Paquets

Pour chaque paquet qu'un document utilise, Rubber recherche un module du même nom pour effectuer les tâches que ce paquet peut nécessiter en dehors de la compilation par LaTeX. Les modules peuvent être ajoutés

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ded aux dépendances fournies par défaut pour inclure de nouvelles fonctionnalités (c'est le but du système de modules). Les modules standard sont les suivants :

asymptote
Traite les fichiers .asy générés par le package LaTeX, puis déclenche une recompilation.
beamer
Ce module gère les fichiers supplémentaires de Beamer de la même manière que les autres tables des matières.
bibtex, biblatex
Prend en charge le traitement de la bibliographie du document avec BibTeX lorsque nécessaire. Ce module est chargé automatiquement si le document contient la macro \bibliography (voir également dans DIRECTIVES pour les options).
combine
Le package combine est utilisé pour rassembler plusieurs documents LaTeX en un seul, et ce module gère les dépendances dans ce cas.
epsfig
Ce module gère l'inclusion de graphiques pour les documents qui utilisent l'ancienne macro \psfig. C'est en fait une interface pour le module graphics, voir ce dernier pour les détails.
glossaries
Exécute makeglossaries et recompiles lorsque le fichier .glo change.
graphics, graphicx
Ces modules identifient les graphiques inclus dans le document et les considèrent comme des dépendances pour la compilation. Ils utilisent également des règles standard pour construire ces fichiers avec des programmes externes. Voir la documentation info pour les détails.
hyperref
Gère les fichiers supplémentaires que ce package produit dans certains cas.
index, makeidx, nomencl
Traite les index et les nomenclatures du document avec makeindex(1) si nécessaire (voir la section DIRECTIVES pour les options).
ltxtable
Ajoute des dépendances pour les fichiers insérés via le package LaTeX ltxtable.
minitoc, minitoc-hyper
Lors du nettoyage, supprime les fichiers supplémentaires produits pour créer des tables des matières partielles.
moreverb, verbatim
Ajoute les fichiers inclus avec \verbatiminput et les macros similaires à la liste des dépendances.
multibib
Gère les bibliographies supplémentaires que ce package crée, et supprime les fichiers supplémentaires lors du nettoyage.
xr
Ajoute les fichiers .aux supplémentaires utilisés pour les références externes à la liste des dépendances, de sorte que la recompilation soit automatique lorsque les documents référencés sont modifiés.

Pré-traitement

Les modules suivants sont fournis pour utiliser des programmes qui génèrent une source LaTeX à partir d'un autre format de fichier :

cweb
Le but de ce module est d'exécuter cweave(1) si nécessaire avant le processus de compilation pour produire la source LaTeX. Ce module est chargé automatiquement si le fichier spécifié sur la ligne de commande a .w comme suffixe.
lhs2TeX
Ce module utilise le préprocesseur lhs2TeX pour générer la source LaTeX à partir d'un programme Literate Haskell. Il est déclenché automatiquement si le nom du fichier d'entrée se termine par .lhs.

Post-traitement

Les modules suivants sont fournis pour prendre en charge différents types de post-traitements. Notez que l'ordre est important lors de l'utilisation de ces modules : si vous souhaitez utiliser une chaîne de traitement comme

foo.tex -> foo.dvi -> foo.ps -> foo.pdf -> foo.pdf.gz
vous devez charger les modules dvips, ps2pdf et gz dans cet ordre, par exemple en utilisant la ligne de commande
rubber -p -o ps2pdf -z foo.tex
bzip2
Produit une version du fichier final compressée avec bzip2(1).
dvipdfm
Exécute dvipdfm(1) à la fin de la compilation pour produire un document PDF.
dvips
Exécute dvips(1) à la fin de la compilation pour produire un document PostScript. Ce module est également chargé par l'option de ligne de commande --ps.
expand
Produit une source LaTeX développée en remplaçant les macros \input par les fichiers inclus, les macros de bibliographie par la bibliographie produite par bibtex(1), et les classes et packages locaux par leur source. Si le fichier principal est foo.tex, alors le fichier développé sera nommé foo-final.tex. Voir la documentation info pour les détails.
gz
Produit une version du fichier final compressée avec gzip(1).
ps2pdf
En supposant que la compilation produit un document PostScript (par exemple en utilisant le module dvips), convertit ce document en PDF en utilisant ps2pdf(1).

Choix du compilateur

Les modules suivants sont utilisés pour changer le compilateur LaTeX :

aleph
Utilise le compilateur Aleph au lieu de TeX, c'est-à-dire qu'il compile le document en utilisant lamed(1) au lieu de latex.
omega
Utilise le compilateur Omega au lieu de TeX, c'est-à-dire qu'il compile le document en utilisant lambda(1) au lieu de latex. Si le module dvips est également utilisé, il utilisera odvips(1) pour traduire le fichier DVI. Notez que ce module est déclenché automatiquement lorsque le document utilise le package omega.
pdftex
Indique à Rubber d'utiliser pdflatex(1) au lieu de latex(1) pour compiler le document. Par défaut, cela produit un fichier PDF au lieu d'un DVI, mais lors du chargement du module avec l'option dvi (par exemple en disant -m pdftex:dvi) le document est compilé en DVI en utilisant pdflatex. Ce module est également chargé par l'option de ligne de commande --pdf.
vtex
Indique à Rubber d'utiliser le compilateur VTeX. Par défaut, cela utilise vlatex comme compilateur pour produire une sortie PDF. Avec l'option ps (par exemple en disant "rubber -m vtex:ps foo.tex") le compilateur utilisé est vlatexp et le résultat est un fichier PostScript.
xelatex
Indique à Rubber d'utiliser xelatex(1) au lieu de latex.

DIRECTIVES

Le comportement automatique de Rubber est basé sur la recherche de macros dans les sources LaTeX. Lorsque cela n'est pas suffisant, des directives peuvent être ajoutées dans les commentaires des sources. Une directive est une ligne comme

% rubber: cmd args
La ligne doit commencer par un "%", puis toute séquence de signes "%" et d'espaces, puis le texte "rubber:" suivi d'espaces et d'un nom de commande, éventuellement suivi d'espaces et d'arguments.

Directives générales

alias <name1> <name2>
Faire semblant que la macro LaTeX name1 est équivalente à name2. Cela peut être utile lors de la définition de wrappers autour de macros prises en charge.
clean <file>
Indique que le fichier spécifié doit être supprimé lors du nettoyage à l'aide de --clean.
depend <file>
Considérer le fichier spécifié comme une dépendance, de sorte que son heure de modification soit vérifiée.
make <file> [<options>]
Déclarer que le fichier spécifié doit être généré. Les options peuvent spécifier la manière dont il doit être produit, les options disponibles sont from <file> pour spécifier la source et with <rule> pour spécifier la règle de conversion. Par exemple, dire "make foo.pdf from foo.eps" indique que foo.pdf doit être produit à partir de foo.eps, avec toute règle de conversion qui peut le faire. Voir la documentation info pour les détails sur la conversion de fichiers.
module <module> [<options>]
Charge le module spécifié, éventuellement avec des options. Ceci est équivalent à l'option de ligne de commande --module.
onchange <file> <command>
Exécute la commande shell spécifiée après la compilation si le contenu du fichier spécifié a changé. Le nom du fichier se termine au premier espace.
path <directory>
Ajoute le répertoire spécifié au chemin de recherche pour TeX (et Rubber). Le nom du répertoire est tout ce qui suit les espaces après "path".
produce <file>
Déclare que l'exécution de LaTeX créera ou mettra à jour le(s) fichier(s) spécifié(s).
read <file>
Lit le fichier de directives spécifié. Le fichier doit contenir une directive par ligne. Les lignes vides et les lignes commençant par "%" sont ignorées.
rules <file>
Charge les règles de construction à partir du fichier spécifié. Ces règles sont utilisées pour savoir comment construire les fichiers déclarés avec la directive make.

Directives BibTeX

Les directives suivantes sont spécifiques au traitement de la bibliographie.

bibliography <file>
Indique que le fichier spécifié est utilisé pour construire la bibliographie. Si le fichier n'a pas d'extension, l'extension .bib est supposée. Cette directive est obligatoire si le module bibtex ou biblatex est utilisé et qu'il n'est pas possible de déterminer le nom du fichier de bibliographie à partir du document.
bibtex <option>
Applique l'option spécifiée à l'exécution de BibTeX. Les options courantes sont -min et -max.

Directives d'index

Les directives suivantes sont spécifiques au traitement des index.

index <option>
Applique l'option spécifiée à l'exécution de makeindex. Les options courantes sont -l pour un index par colonnes et -r pour un index inversé.
indexing <file>
Indique que le fichier spécifié est utilisé pour construire l'index. Si le fichier n'a pas d'extension, l'extension .idx est supposée. Cette directive est obligatoire si le module index est utilisé et qu'il n'est pas possible de déterminer le nom du fichier d'index à partir du document.
makeindex <option>
Applique l'option spécifiée à l'exécution de makeindex. Ceci est un synonyme de la directive index.
nomenclature <option>
Applique l'option spécifiée à l'exécution de makeindex pour la nomenclature. Ceci est équivalent à utiliser la directive index avec l'option -n.
nomencl <option>
Applique l'option spécifiée à l'exécution de makeindex pour la nomenclature. Ceci est équivalent à utiliser la directive index avec l'option -n.

Directives spécifiques au compilateur

pdftex <option>
Applique l'option spécifiée à l'exécution de pdflatex. Ceci est utile pour passer des options spécifiques à pdflatex qui ne sont pas gérées par Rubber.
gt;
Lire des règles de conversion supplémentaires à partir du fichier spécifié. Le format de ce fichier est le même que celui de rules.ini, voir la documentation info pour plus de détails.
set <nom> <valeur>
Définir la valeur d'une variable sous forme de chaîne de caractères. Pour plus de détails sur les variables existantes et leur signification, voir la documentation info.
setlist <nom> <valeurs>
Définir la valeur d'une variable comme une liste de chaînes de caractères (séparées par des espaces). Pour plus de détails sur les variables existantes et leur signification, voir la documentation info.
shell_escape
Marquer le document comme nécessitant des programmes externes (shell-escape ou write18). Rubber n'active réellement cela que lorsqu'il est appelé avec l'option --unsafe.
synctex
Activer le support SyncTeX dans l'exécution LaTeX.
watch <fichier>
Surveiller le fichier spécifié pour les changements. Si le contenu de ce fichier a changé après une compilation, une autre compilation est déclenchée. Ceci est utile dans le cas des tables des matières, par exemple.

Directives spécifiques aux modules

Si une commande a la forme foo.bar, elle est considérée comme une commande bar pour le module foo. Si ce module n'est pas enregistré lorsque la directive est trouvée, alors la commande est silencieusement ignorée. Pour les modules standard, les directives sont les suivantes :

biblatex.path <répertoire>
Ajoute le répertoire spécifié au chemin de recherche des bases de données BibTeX (.bib fichiers).
bibtex.crossrefs <nombre>
Définit le nombre minimum de crossref requis pour l'inclusion automatique de l'entrée référencée dans la liste des citations. Ceci définit l'option -min-crossrefs lors de l'appel de bibtex(1).
bibtex.path <répertoire>
Ajoute le répertoire spécifié au chemin de recherche des bases de données BibTeX (.bib fichiers).
bibtex.stylepath <répertoire>
Ajoute le répertoire spécifié au chemin de recherche des styles BibTeX (.bst fichiers).
bibtex.tool <commande>
Utilise un outil de bibliographie différent au lieu de BibTeX.
dvipdfm.options <options>
Passe les commutateurs de ligne de commande spécifiés à dvipdfm.
dvips.options <options>
Passe les commutateurs de ligne de commande spécifiés à dvips.
index.tool (index) <nom>
Spécifie quel outil doit être utilisé pour traiter l'index. Les outils actuellement supportés sont makeindex(1) (choix par défaut) et xindy(1). L'argument index est optionnel, il peut être utilisé pour spécifier la liste des index auxquels la commande s'applique. Lorsqu'il est présent, il doit être entre parenthèses ; la liste est séparée par des virgules. Lorsque l'argument n'est pas présent, la commande s'applique à tous les index.
index.language (index) <langue>
Sélectionne la langue utilisée pour le tri de l'index. Ceci ne s'applique que lors de l'utilisation de xindy(1) comme outil d'indexation. L'argument optionnel a la même sémantique que ci-dessus.
index.modules (index) <module>...
Spécifie quels modules utiliser lors du traitement d'un index avec xindy(1). L'argument optionnel a la même sémantique que ci-dessus.
index.order (index) <options>
Modifie les options de tri pour les index. Les arguments sont des mots (séparés par des espaces) parmi standard, german et letter. Ceci ne s'applique que lors de l'utilisation de makeindex(1). L' argument optionnel a la même sémantique que ci-dessus.
index.path (index) <répertoire>
Ajoute le répertoire spécifié au chemin de recherche des styles d'index (.ist fichiers). L'argument optionnel a la même sémantique que ci-dessus.
index.style (index) <style>
Spécifie le style d'index à utiliser. L'argument optionnel a la même sémantique que ci-dessus.
makeidx.language, .modules, .order, .path, .style, .tool
Ces directives sont les mêmes que pour le module index, sauf qu'elles n'acceptent pas d'argument optionnel.
multibib.crossrefs, .path, .stylepath, .tool
Ces directives sont les mêmes que pour le module bibtex mais elles s'appliquent aux bibliographies gérées par le package multibib. Elles prennent un premier argument optionnel, avec la même convention que pour les directives du module index, qui peut être utilisé pour spécifier la liste des bibliographies auxquelles la commande s'applique.
