NOM

runc-spec - créer un nouveau fichier de spécification

SYNTAXE

runc spec [option ...]

DESCRIPTION

La commande spec crée le nouveau fichier de spécification nommé config.json pour le bundle.

La spécification générée n'est qu'un fichier de départ. La modification de la spécification est nécessaire pour obtenir les résultats souhaités. Par exemple, la spécification nouvellement générée inclut un paramètre args qui est initialement défini pour appeler la commande sh lors du démarrage du conteneur. L'appel de sh peut fonctionner pour un conteneur ubuntu ou busybox, mais ne fonctionnera pas pour les conteneurs qui n'incluent pas le binaire sh.

OPTIONS

--bundle|-b chemin
Définit chemin sur la racine du répertoire du bundle.
--rootless
Génère une configuration pour un conteneur sans privilèges root. Notez que cette option est entièrement différente de l'option globale --rootless.

EXEMPLES

Pour exécuter un simple conteneur "hello-world", il faut définir le paramètre args dans la spécification pour appeler hello. Cela peut être fait en utilisant sed(1), jq(1), ou un éditeur de texte.

Les commandes suivantes vont :
- créer un bundle pour hello-world ;
- changer la commande à exécuter dans un conteneur en /hello en utilisant jq(1) ;
- exécuter la commande hello dans un nouveau conteneur hello-world nommé container1.

mkdir hello
cd hello
docker pull hello-world
docker export $(docker create hello-world) > hello-world.tar
mkdir rootfs
tar -C rootfs -xf hello-world.tar
runc spec
jq '.process.args |= ["/hello"]' < config.json > new.json
mv -f new.json config.json
runc run container1

Dans la commande run ci-dessus, container1 est le nom de l'instance du conteneur que vous démarrez. Le nom que vous fournissez pour l'instance du conteneur doit être unique sur votre hôte.

Une alternative pour générer une configuration de spécification personnalisée est d'utiliser oci-runtime-tool ; sa sous-commande oci-runtime-tool generate a de nombreuses options qui peuvent être utilisées pour effectuer toutes les personnalisations souhaitées. Voir runtime-tools ⟨https://github.com/opencontainers/runtime-tools⟩ pour obtenir plus d'informations.

Lors du démarrage d'un conteneur via runc, ce dernier a généralement besoin de privilèges root. Si vous n'êtes pas déjà en cours d'exécution en tant que root, vous pouvez utiliser sudo(8), par exemple :

sudo runc start container1

Alternativement, vous pouvez démarrer un conteneur sans privilèges root, qui a la capacité de s'exécuter sans privilèges root. Pour que cela fonctionne, le fichier de spécification doit être ajusté en conséquence. Vous pouvez passer l'option --rootless à cette commande pour générer un fichier de spécification approprié sans privilèges root.
