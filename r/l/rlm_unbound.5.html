NOM

rlm_unbound - Module FreeRADIUS

DESCRIPTION

Chaque instance de rlm_unbound fournit un client DNS embarqué pour effectuer des recherches DNS. Chaque instance peut être configurée séparément pour interroger différentes horizons DNS, modifier les options DNSSEC, etc.

Le module est principalement destiné à être utilisé par d'autres modules via des API internes, et par conséquent, les instances doivent être initialisées avant les modules qui les utilisent. Chaque instance fournit également certaines fonctionnalités xlat pour une utilisation générale et pour le dépannage.

Chaque instance de rlm_unbound peut accepter les paramètres suivants :

filename
Ce fichier doit exister et pointer vers un fichier de configuration libunbound valide. Le défaut est ${raddbdir}/mods-config/unbound/default.conf.
timeout
Alors que libunbound fournit une API asynchrone pour un usage interne, l'utilisation de tout xlat est effectuée de manière synchrone du point de vue de unlang. Cette valeur limite le temps d'attente d'une requête pour que DNS réponde, après quoi le xlat échouera. Le défaut est 3000 millisecondes. Ce réglage est indépendant de toutes les valeurs de configuration de libunbound.
resolvconf
Chemin complet d'un fichier resolv.conf à partir duquel charger les détails du résolveur. Si ce n'est pas défini, libunbound interrogera les serveurs DNS racines.
hosts
Chemin complet d'un fichier hosts à charger. Cela fournit un mécanisme pour les substitutions locales de noms qui, autrement, ne résoudraient pas ou nécessiteraient des résultats différents de ceux qu'une résolution DNS fournirait.

Une instance nommée, par exemple, "dns" fournira les fonctionnalités xlat suivantes :

%{dns-a:<owner>}
Effectue une recherche A pour le nom de propriétaire, retournant une adresse IPv4 sous forme de chaîne. Seul le premier enregistrement A dans le RRSET sera retourné.
%{dns-aaaa:<owner>}
Effectue une recherche AAAA pour le nom de propriétaire, retournant une adresse IPv6 sous forme de chaîne. Seul le premier enregistrement AAAA dans le RRSET sera retourné.
%{dns-ptr:<owner>}
Effectue une recherche PTR pour le propriétaire.

MISE EN GARDE

La journalisation de rlm_unbound peut être problématique, surtout si plus d'une instance du module est utilisée. Ceci est dû à la nécessité de fonctionnalités supplémentaires dans le libunbound sous-jacent, qui, espérons-le, seront améliorées au fil du temps.

Il existe un risque qu'un serveur FreeRADIUS utilisant rlm_unbound ne se termine pas proprement (laissant des processus zombies, ne nettoyant pas d'autres modules, et bloquant après un SIGTERM jusqu'à ce qu'un SIGKILL soit envoyé) ou échoue aux vérifications valgrind lors de la terminaison lorsqu'il est exécuté avec -m. De même, ce problème dépendra des améliorations en amont avant qu'il ne puisse être résolu, et le comportement exact peut changer dans les versions intermédiaires jusqu'alors.

Le comportement de journalisation de rlm_unbound peut varier en fonction que FreeRADIUS est compilé avec le support des threads ou non.
