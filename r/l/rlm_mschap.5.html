rlm_mschap(5) Module FreeRADIUS rlm_mschap(5)

NOM

rlm_mschap - Module FreeRADIUS

DESCRIPTION

Le module rlm_mschap fournit le support d'authentification MS-CHAP et MS-CHAPv2.

Ce module valide un utilisateur avec une authentification MS-CHAP ou MS-CHAPv2. S'il est appelé dans la section Authorize, il recherchera les attributs MS-CHAP Challenge/Response dans la requête Access-Request et ajoutera un attribut Auth-Type défini sur MS-CHAP dans la liste des éléments de configuration, sauf si Auth-Type a déjà été défini.

Le module peut authentifier la session MS-CHAP via des mots de passe en texte clair (attribut User-Password), ou des mots de passe NT (attribut NT-Password). Le module ne peut pas effectuer d'authentification contre un domaine NT.

Le module applique également l'attribut SMB-Account-Ctrl. Voir la documentation Samba pour la signification du contrôle de compte SMB. Le module ne lit pas les fichiers de mots de passe Samba. Au lieu de cela, le module rlm_passwd peut être utilisé pour lire un fichier de mots de passe Samba et fournir un attribut NT-Password que ce module peut utiliser.

Les principaux éléments de configuration à connaître sont :

authtype
C'est la chaîne utilisée pour définir le type d'authentification. Normalement, elle devrait être laissée à la valeur par défaut de MS-CHAP.
use_mppe
Sauf si cette option est définie sur 'no', FreeRADIUS ajoutera MS-CHAP-MPPE-Keys pour MS-CHAPv1 et MS-MPPE-Recv-Key/MS-MPPE-Send-Key pour MS-CHAPv2. La valeur par défaut est 'yes'.
require_encryption
Si MPPE est activé, la définition de cet attribut sur 'yes' entraînera la définition de l'attribut MS-MPPE-Encryption-Policy pour exiger le chiffrement. La valeur par défaut est 'no'.
require_strong
Si MPPE est activé, la définition de cet attribut sur 'yes' entraînera la définition de l'attribut MS-MPPE-Encryption-Types pour exiger une clé de 128 bits. La valeur par défaut est 'no'.
with_ntdomain_hack
Les clients Windows envoient User-Name sous la forme "DOMAIN\User", mais envoient le challenge/response basé uniquement sur la partie User. La définition de cette valeur sur yes active une solution de contournement pour cette erreur. La valeur par défaut est 'no'.

CONFIGURATION

modules {
  ...
  mschap {
	authtype = MS-CHAP
	use_mppe = yes	
  }
  ...
}
 ...
authorize {
  ...
  mschap
  ...
}
 ...
authenticate {
  ...
  mschap
  ...
}
