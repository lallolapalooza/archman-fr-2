rlm_attr_filter(5) Module FreeRADIUS rlm_attr_filter(5)

NOM

rlm_attr_filter - Module FreeRADIUS

DESCRIPTION

Le module rlm_attr_filter sert à filtrer certains attributs et valeurs dans les paquets radius reçus (ou transmis). Il offre au serveur un cadre flexible pour filtrer les attributs que nous envoyons aux serveurs d'origine ou aux NAS, ou que nous recevons d'eux. Cela est utile, par exemple, dans une situation de connexion sortante externalisée, pour diverses décisions de politique, telles que la restriction d'un client à certaines plages de Idle-Timeout ou de Session-Timeout.

Les règles de filtrage sont normalement définies et appliquées par domaine (realm), où le domaine est tout ce qui est défini et mis en correspondance selon la configuration du module rlm_realm. Les règles de filtrage peuvent éventuellement être appliquées en utilisant un autre attribut, en modifiant la configuration key de ce module.

Dans les versions 2.0.1 et antérieures, la section "accounting" filtrait les Accounting-Request, même si elle était documentée comme filtrant la réponse. Ce problème a été corrigé dans la version 2.0.2 et les versions ultérieures. La section "preacct" peut maintenant être utilisée pour filtrer les paquets Accounting-Request. La section "accounting" filtre désormais les paquets Accounting-Response. Les administrateurs utilisant "attr_filter" dans la section "accounting" DEVRAIENT déplacer la référence à "attr_filter" de "accounting" à "preacct".

Le fichier qui définit les règles de filtrage d'attributs suit une syntaxe similaire au fichier users. Il y a cependant quelques différences :

    Aucun élément de vérification n'est autorisé, à l'exception du nom de la
clé.
    Il ne peut y avoir qu'une seule entrée DEFAULT.
Les règles pour chaque entrée sont analysées de haut en bas, et un
attribut doit passer *toutes* les règles qui le concernent pour passer
le filtre. L'ordre des règles est important.
Les opérateurs et leur objectif dans la définition des règles sont
les suivants :
=
CET OPÉRATEUR N'EST PAS AUTORISÉ. S'il est utilisé, un message d'avertissement
est affiché et il est traité comme ==
:=
Définir, cet attribut et sa valeur seront toujours placés dans les paires
A/V de sortie. Si l'attribut existe, il est écrasé.
==
Égal, la valeur doit correspondre exactement.
=*
Toujours Égal, autorise toutes les valeurs pour l'attribut spécifié.
!*
Jamais Égal, refuse toutes les valeurs pour l'attribut spécifié.
( Ceci est redondant, car toute paire A/V non explicitement autorisée
sera ignorée ).
!=
Pas Égal, la valeur ne doit pas correspondre.
>=
Supérieur ou Égal
<=
Inférieur ou Égal
>
Strictement Supérieur
<
Strictement Inférieur
Si les expressions régulières sont activées, les opérateurs suivants sont
également possibles. ( Les expressions régulières sont incluses par défaut
sauf si votre système ne les supporte pas, ce qui devrait être rare ).
Le champ valeur utilise la syntaxe standard des expressions régulières.
=~
Égalité d'Expression Régulière
!~
Inégalité d'Expression Régulière
Voir le fichier /etc/raddb/mods-config/attr_filter/ par défaut pour des
exemples de règles de classement et d'utilisation des différents opérateurs.

Les éléments de configuration sont :

file
Ceci spécifie l'emplacement du fichier utilisé pour charger les règles de filtrage. Ce fichier est utilisé pour filtrer la réponse de comptabilité, le paquet avant qu'il ne soit proxyé, la réponse proxy du serveur d'origine, ou notre réponse au NAS.
key
Généralement %{Realm} (par défaut). Peut aussi être %{User-Name}, ou un autre attribut présent dans la requête. Notez que le module se base toujours sur les attributs de la requête, et NON sur ceux de tout autre paquet.
relaxed
S'il est défini sur 'yes', les attributs qui ne correspondent à aucune règle de filtrage explicite seront également autorisés. Ce comportement peut être annulé pour un bloc de filtrage individuel en utilisant l'élément de vérification Relax-Filter. La valeur par défaut pour cet élément de configuration est 'no'.

SECTIONS

preacct
Filtre les paquets Accounting-Request.
accounting
Filtre les paquets Accounting-Response.
pre-proxy
Filtre les paquets Accounting-Request ou Access-Request avant leur proxy.
post-proxy
Filtre les réponses Accounting-Response, Access-Accept, Access-Reject, ou Access-Challenge provenant d'un serveur d'origine.
authorize
Filtre les paquets Access-Request.
post-auth
Filtre les paquets Access-Accept ou Access-Reject.
