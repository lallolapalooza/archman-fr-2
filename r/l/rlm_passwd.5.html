NOM

rlm_passwd - Module FreeRADIUS

DESCRIPTION

Le module rlm_passwd permet l'autorisation via des fichiers similaires en format à /etc/passwd.

Ce module vous permet de récupérer toute information de compte à partir de n'importe quel fichier au format similaire à passwd (/etc/passwd, /etc/group, smbpasswd, .htpasswd, etc.). Chaque champ du fichier peut être mappé à un attribut RADIUS, l'un des champs étant utilisé comme clé.

Le module lit le fichier lors de son initialisation et met en cache les données en mémoire. Cela le rend très rapide, même pour les fichiers contenant des milliers de lignes. Pour relire le fichier, le module devra être rechargé avec radmin(8), ou le serveur devra recevoir un SIGHUP, car les mises à jour dynamiques ne sont pas supportées.

CONFIGURATION

L'élément de configuration :

allow_multiple_keys
Si défini sur 'yes', et si plus d'un enregistrement dans le fichier correspond à la requête, alors les attributs de tous les enregistrements seront utilisés. Si défini sur 'no' (par défaut), le module affichera un avertissement concernant les enregistrements dupliqués.
delimiter = ":"
Le caractère utilisé comme délimiteur entre les champs. Le défaut est ":"
filename
Le chemin vers le fichier.
format
Le format des champs dans le fichier, donné comme une ligne d'exemple du fichier, avec le contenu des champs comme attributs RADIUS auxquels les champs sont mappés. Les champs sont séparés par le caractère ':' dans la configuration (peu importe ce qui est configuré pour l'option 'delimiter').
hash_size
La taille de la table de hachage. Une valeur plus grande signifie moins de probabilité de collision, donc les enregistrements seront trouvés plus rapidement, au détriment d'une utilisation accrue de la mémoire. Avoir un hash_size dans la plage de 30 à 100 % du nombre d'enregistrements du fichier passwd est raisonnable.
ignore_empty
Lorsque défini sur "yes", ce qui est le comportement par défaut, les champs vides dans l'entrée seront ignorés et l'attribut RADIUS ne sera pas ajouté. En définissant cette valeur sur "no", tous les attributs de la liste de format seront toujours ajoutés, même s'ils n'ont pas de valeur.
ignore_nislike
Si défini sur 'yes', alors tous les enregistrements du fichier commençant par le signe '+' seront ignorés. Le défaut est 'no'.

FORMAT

L'option format contrôle la manière dont les lignes sont lues depuis le fichier, et quels champs sont mappés à quels attributs RADIUS.

Le champ clé est le champ recherché dans le fichier. Il est normalement signifié par un '*' précédant le champ, qui indique que le champ n'a qu'une seule clé, comme le fichier /etc/passwd. Le champ clé peut être précédé de '*,', ce qui indique que le champ a plusieurs clés séparées par des virgules, comme lors de la recherche dans le fichier /etc/group.

Les autres champs signifient des attributs RADIUS. Par défaut, ils seront ajoutés en tant que liste d'attributs de contrôle.

Pour ajouter un attribut à la requête RADIUS (comme s'il avait été envoyé par le NAS), préfixez le nom de l'attribut dans la chaîne "format" avec le caractère '~'.

Pour ajouter un attribut à la réponse RADIUS (à renvoyer au NAS), préfixez le nom de l'attribut dans la chaîne "format" avec le caractère '='.

EXEMPLES

format = "*User-Name:Crypt-Password:"
Pour un fichier ressemblant à /etc/passwd. Le premier champ, User-Name, est la clé à rechercher dans le fichier. Lorsque l'enregistrement est trouvé, un attribut de contrôle, 'Crypt-Password', sera ajouté avec le contenu du second champ. (Notez que cela ne fonctionnera pas avec les mots de passe shadow.)
format = "My-Group:::*,User-Name"
Analyser un fichier similaire au fichier /etc/group. Une entrée correspond à une requête lorsque le nom dans un attribut User-Name existe dans la liste séparée par des virgules d'une ligne du fichier. Lorsqu'une entrée correspond, un attribut "My-Group" sera créé et ajouté aux éléments de contrôle de la requête. La valeur de cet attribut sera prise du premier champ de la ligne correspondante du fichier.
Les ":::" dans la chaîne de format signifient qu'il y a deux champs supplémentaires dans la ligne, entre le nom du groupe et la liste des noms d'utilisateur. Ces champs ne correspondent à aucun attribut RADIUS et sont donc ignorés.
Pour que cet exemple fonctionne en pratique, vous devrez ajouter l'attribut My-Group au fichier de dictionnaire. Voir dictionary(5) pour les détails sur la manière dont cela peut être fait.
format = "~My-Group:::*,User-Name"
Similaire à l'entrée précédente, sauf que l'attribut My-Group est ajouté à la requête, comme s'il avait été envoyé par le NAS.
