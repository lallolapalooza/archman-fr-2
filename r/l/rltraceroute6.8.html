TRACEROUTE6(8) Manuel de l'administrateur système TRACEROUTE6(8)

NOM

rltraceroute6 - Outil de traceroute IPv6

tcptraceroute6 - Outil de traceroute TCP/IPv6

SYNTAXE

traceroute6 [-AdEILlnrSU] [-f min_hop] [-g hop] [ -i iface] [-m max_hop] [-p port] [-q tentatives] [ -s source] [-t tclass] [-w delai] [-z delai_ms] < nom_hote/adresse> [longueur_paquet]

tcptraceroute6 [-AdEnrS] [-f min_hop] [-g hop] [ -i iface] [-l taille_paquet] [-m max_hop] [-p port] [ -q tentatives] [-s source] [-t tclass] [-w delai] [ -z delai_ms] < nom_hote/adresse> [port]

DESCRIPTION

rltraceroute6 est une implémentation de traceroute IPv6.

Il affiche la liste des sauts le long de la route réseau entre le système local et la destination spécifiée, en envoyant des paquets tout en incrémentant leur limite de sauts, jusqu'à ce que la destination finale soit atteinte.

Par défaut, rltraceroute6 envoie des paquets de sondage UDP vers la destination (c'est le comportement par défaut historique). Cependant, il peut également envoyer des paquets TCP, tout comme le fait tcptraceroute de Michael C. Toren sur les réseaux IPv4 ; tcptraceroute6 envoie des paquets TCP par défaut (et imite la syntaxe de la ligne de commande de tcptraceroute). Enfin, il peut également envoyer des paquets ICMPv6 Echo Request, comme certaines autres implémentations de traceroute (telles que celle de Microsoft Windows) ; tracert6 le fait par défaut.

Vous devez spécifier le nom ou l'adresse de l'hôte vers lequel la route réseau doit être déterminée. Un paramètre supplémentaire facultatif spécifie soit la longueur des paquets de sondage (pour les paquets UDP et ICMP), soit le numéro de port de destination/nom de service (pour les paquets TCP).

Notez que le port de destination TCP zéro est bien le port TCP numéroté 0 (qui ne peut pas être utilisé via l'interface de programmation TCP/IP de haut niveau habituelle).

OPTIONS

-A
Envoie des paquets de sondage TCP/ACK. C'est très efficace contre les pare-feux sans état (par exemple, les versions officielles du noyau Linux jusqu'à et y compris 2.4.31 et 2.6.14), et totalement inefficace contre ceux avec état. Notez que la sonde TCP/ACK ne permet pas de déterminer si le port TCP de destination est ouvert ou non.
-d
Active l'option de débogage de socket (SO_DEBUG). Sauf si vous déboguez le noyau, cela n'aura probablement aucun effet réel.
-E
Envoie des paquets de sondage TCP/SYN pour l'établissement ECN (conformément à la RFC 3168) plutôt que des paquets de sondage TCP/SYN sans établissement ECN. Cela n'a aucun effet sauf si l'option de ligne de commande -S est également spécifiée.
-F
Cette option est ignorée pour des raisons de compatibilité ascendante. Les paquets IPv6 ne sont jamais fragmentés en cours de route.
-f
Remplace la limite de sauts initiale des paquets IPv6 (par défaut : 1).
-g
Ajoute un segment de routage IPv6 dans un en-tête de routage IPv6. Cela permet le routage source lâche. Actuellement, seul l'en-tête de routage de "Type 0" est pris en charge.
-h
Affiche une aide et quitte.
-I (rltraceroute6 seulement)
Envoie des requêtes ICMPv6 Echo (comme ping6) comme paquets de sondage. C'est le défaut pour tracert6.
-i
N'envoie des paquets qu'à travers l'interface spécifiée. Voir aussi BUGS.
-I (rltraceroute6 seulement)
Envoie des paquets UDP-Lite (protocole 136) (avec une couverture complète de somme de contrôle) comme paquets de sondage au lieu de UDP normal (protocole 17).
-l (seulement rltraceroute6)
Affiche la limite de sauts des paquets reçus. Ceci est principalement utilisé pour détecter un routage asymétrique.
-l (seulement tcptraceroute6)
Spécifie la taille (en octets) des paquets envoyés.
-m
Remplace la limite de sauts maximale (nombre maximum de sauts). La valeur par défaut est de 30 sauts, ce qui devrait être suffisant sur l'Internet IPv6 pendant un certain temps.
-N
Essaie de résoudre l'adresse IPv6 de chaque saut en un nom d'hôte. C'est le comportement par défaut. Cette option est destinée à la compatibilité ascendante avec tcptraceroute(8).
-n
N'essaie pas de résoudre l'adresse IPv6 de chaque saut en un nom d'hôte. Cela peut considérablement accélérer le traceroute.
-p
Pour rltraceroute6, spécifie le numéro de port de destination de base (par défaut : 33434). rltraceroute6 suppose que les paquets vers ce port jusqu'à ce port plus la limite de sauts maximale ne sont utilisés par aucun programme sur la destination finale et qu'ils ne sont bloqués par aucun pare-feu. Le fait que cette hypothèse n'ait pas toujours été correcte a finalement conduit au développement de tcptraceroute IPv4 original par Michael Toren.

Pour tcptraceroute6, spécifie le numéro de port source (par défaut : auto). Notez que le numéro de port source zéro signifie réellement le numéro zéro, plutôt qu'un numéro de port qui serait attribué automatiquement, comme c'est le cas avec les logiciels habituels.

-q
Remplace le nombre de sondes envoyées à chaque saut (par défaut : 3).
-r
Ne route pas les paquets, c'est-à-dire n'envoie pas de paquets via une passerelle qui serait spécifiée par la table de routage. Voir aussi BUGS.
-S
Utilise des paquets de sondage TCP/SYN. C'est le comportement par défaut pour tcptraceroute6.
-s
Spécifie explicitement l'adresse source à utiliser pour les paquets de sondage.
-S
Utilise des paquets de sondage UDP. C'est le comportement par défaut pour rltraceroute6.
-t
Spécifie la classe de trafic (DSCP) pour les paquets de sondage. Voir aussi BUGS.
-U (seulement rltraceroute6)
Envoie des paquets de sondage UDP. C'est le comportement par défaut.
-V
Affiche la version du programme et la licence, puis quitte.
-w
Remplace le délai (en secondes) d'attente de réponse une fois qu'un paquet de sondage donné a été envoyé (par défaut : 5 secondes).
-x
Cette option est ignorée pour une migration transparente depuis traceroute IPv4. L'en-tête IPv6 n'a pas de champ de somme de contrôle.
-z
Spécifie un délai en millisecondes à attendre entre chaque sonde avec une limite de sauts identique. Cela peut être utile pour contourner la limitation de débit ICMPv6 sur certains hôtes.

DIAGNOSTICS

Si une réponse est reçue, le temps aller-retour est affiché. De plus, des symboles spécifiques dénotent certaines erreurs :

* Pas de réponse
Aucune réponse valide reçue avant le délai d'attente (voir l'option -w).
!N Aucune route vers la destination
Il n'y a pas d'entrée pour le réseau de destination dans la table de routage.
!A Communication avec la destination interdite administrativement
Un pare-feu a explicitement rejeté le trafic.
!S Au-delà de la portée de l'adresse source
La portée de l'adresse source est trop petite pour atteindre l'adresse de destination. Au moment de la rédaction, cela ne peut se produire que lors de l'utilisation d'une adresse source de lien local pour atteindre une destination de portée globale. (Note : certaines implémentations de traceroute IPv4 utilisent !S pour une erreur de routage source, ce qui est complètement différent)
!H Adresse inaccessible
L'adresse de l'hôte n'est pas accessible pour d'autres raisons, notamment une défaillance de la couche lien (par exemple, échec de découverte de voisin).
!P Type d'en-tête suivant non reconnu rencontré
La destination n'implémente pas le protocole de couche 4 utilisé. Vous devriez réessayer avec des requêtes ICMPv6 Echo (-I comma

rltraceroute6(8) — traceroute6

OPTIONS

-g

Route strict specified by the given list of IPv6 addresses. This option can be used multiple times. This option is equivalent to the RFC3094 ROUTING header. The address list MUST be supported by any IPv6 node.

DIAGNOSTICS

The -g option can be used to specify a strict routing header. The option requires a list of IPv6 addresses, and it's specified in RFC3094. This option MUST be supported by any IPv6 node.

SECURITY

rltraceroute6 doit être configuré avec le bit setuid root pour être utilisé par des utilisateurs non privilégiés. Il abandonnera ses privilèges root avant toute tentative d'envoi ou de réception de données du réseau afin de réduire l'impact potentiel d'une vulnérabilité de sécurité.

BUGS

Bien qu'utiles, les options -i et -r sont ignorées par le noyau Linux officiel au moment de la rédaction de cette page de manuel, et donc ne fonctionnent pas comme documenté.

Le support de l'option -t était cassé jusqu'à la version 2.6.18 du noyau Linux.

L'utilisation de l'en-tête de routage, avec l'option -g, déclenche un OOPS sur les versions du noyau Linux inférieures à 2.6.17.12.

La réception des paquets TCP/SYN-ACK ne fonctionne pas du tout sous FreeBSD. Cela limite sévèrement l'utilité de tcptraceroute6 sous FreeBSD.

La longueur du paquet prend en compte l'en-tête IPv6 et, le cas échéant, les en-têtes d'extension. Les versions de rltraceroute6 antérieures à 0.7.4 l'utilisaient comme longueur de charge utile IPv6, c'est-à-dire qu'elles n'incluaient pas les en-têtes de couche 3 dans le calcul. Le traceroute6 d'iputils sous Linux n'inclut même pas l'en-tête UDP. Dans l'ensemble, la sémantique de la longueur du paquet est très incohérente entre les implémentations de traceroute IPv6.
