rlm_sql(5) Module FreeRADIUS rlm_sql(5)

NOM

rlm_sql - Module FreeRADIUS

DESCRIPTION

Le module rlm_sql fournit une interface SQL pour récupérer des informations d'autorisation et stocker des informations de comptabilité. Il peut être utilisé en conjonction avec, ou à la place des modules fichiers et détail. Le module SQL possède des pilotes pour supporter les bases de données SQL suivantes :

     db2
     iodbc
     mysql
     oracle
     postgresql
     sybase
     unixodbc

En raison de la taille des variables de configuration, le module sql est généralement configuré dans un fichier séparé, qui est inclus dans le fichier radiusd.conf principal via une directive include.

Les éléments de configuration principaux à connaître sont :

driver
Cette variable spécifie le pilote à charger.
server
login
password
Ces variables spécifient le nom du serveur, le nom d'utilisateur et le mot de passe que le module utilisera pour se connecter à la base de données.
radius_db
Le nom de la base de données où les tables radius sont stockées.
acct_table1
acct_table2
Ces variables spécifient les noms des tables pour les enregistrements de comptabilité. acct_table1 spécifie la table où les enregistrements Start sont stockés. acct_table2 spécifie la table où les enregistrements Stop sont stockés. Dans la plupart des cas, il devrait s'agir de la même table.
postauth_table
Le nom de la table pour stocker les données post-authentification.
authcheck_table
authreply_table
Les tables où sont stockés les éléments de vérification (Check-Items) et les éléments de réponse (Reply-Items) individuels.
groupcheck_table
groupreply_table
Les tables où sont stockés les éléments de vérification (Check-Items) et les éléments de réponse (Reply-Items) de groupe.
usergroup_table
La table où sont stockées les relations entre le nom d'utilisateur et le groupe.
deletestalesessions
Cette option est réglée sur 'yes' ou 'no'. Si vous effectuez une vérification d'utilisation simultanée (Simultaneous-Use), et que cette option est réglée sur yes, les sessions périmées (définies comme des sessions pour lesquelles aucun enregistrement Stop n'a été reçu) seront effacées.
logfile
Cette option est utile pour déboguer les problèmes sql. Si logfile est défini, alors toutes les requêtes sql pour la section parente sont écrites dans le fichier spécifié. Ceci est utile pour le débogage et les insertions en masse.
num_sql_socks
Le nombre de connexions sql à établir avec la base de données.
connect_failure_retry_delay
Le nombre de secondes à attendre avant de tenter de se reconnecter à une connexion de base de données défaillante.
sql_user_name
Ceci est la définition de l'attribut SQL-User-Name. Il est défini une fois, de sorte que vous puissiez utiliser %{SQL-User-Name} dans les requêtes SQL, plutôt que la substitution imbriquée du nom d'utilisateur. Cela garantit que Username est analysé de manière cohérente pour toutes les requêtes SQL exécutées.
default_user_profile
Ceci est le nom du profil par défaut qui sera appliqué à tous les utilisateurs s'il est défini. Il n'est pas défini par défaut.
query_on_not_found
Cette option est réglée sur 'yes' ou 'no'. Si elle est réglée sur yes, alors le profil utilisateur par défaut est retourné si aucune correspondance spécifique n'a été trouvée pour l'utilisateur.
authorize_check_query
authorize_reply_query
Ces requêtes sont exécutées pendant la phase d'autorisation pour extraire les informations d'autorisation de l'utilisateur des tables ${authcheck_table} et ${authreply_table}.
authorize_group_check_query
authorize_group_reply_query
Ces requêtes sont exécutées pendant la phase d'autorisation pour extraire les informations d'autorisation de groupe des tables ${groupcheck_table} et ${groupreply_table}.
accounting_onoff_query
La requête à exécuter lors de la réception d'un paquet Accounting On ou Accounting Off.
accounting_update_query
accounting_update_query_alt
La requête à exécuter lors de la réception d'un paquet Accounting Update. Si la requête principale échoue, la requête alternative est exécutée.
accounting_start_query
accounting_start_query_alt
La requête à exécuter lors de la réception d'un paquet Accounting Start. Si la requête principale échoue, la requête alternative est exécutée.
accounting_stop_query
accounting_stop_query_alt
La requête à exécuter lors de la réception d'un paquet Accounting Stop. Si la requête principale échoue, la requête alternative est exécutée.
simul_count_query
La requête à exécuter pour retourner le nombre de sessions simultanées aux fins de limiter l'Utilisation Simultanée.
simul_verify_query
La requête pour retourner les informations détaillées nécessaires pour confirmer que toutes les sessions suspectées connectées sont valides et ne sont pas des sessions périmées.
group_membership_query
La requête à exécuter pour vérifier l'appartenance d'un utilisateur à un groupe.
postauth_query
La requête à exécuter pendant la phase post-authentification.

CONFIGURATION

En raison de la taille de la configuration de ce module, elle n'est pas incluse dans cette page de manuel. Veuillez consulter les fichiers de configuration fournis pour des exemples de requêtes et des détails de configuration.
