rlm_pap(5) Module FreeRADIUS rlm_pap(5)

NOM

rlm_pap - Module FreeRADIUS

DESCRIPTION

Le module rlm_pap authentifie les paquets RADIUS Access-Request contenant un attribut User-Password. Le module doit également être listé en dernier dans la section authorize, afin qu'il puisse définir l'attribut Auth-Type comme il convient.

Lorsqu'un paquet RADIUS contient un mot de passe en clair sous la forme d'un attribut User-Password, le module rlm_pap peut être utilisé pour l'authentification. Le module nécessite un mot de passe « connu et valide », qu'il utilise pour valider le mot de passe fourni dans le paquet RADIUS. Ce mot de passe « connu et valide » doit être fourni par un autre module (par ex. rlm_files, rlm_ldap, etc.), et est généralement extrait d'une base de données.

CONFIGURATION

Le seul élément de configuration est :

normalise
La valeur par défaut est « yes ». Cela signifie que le module essaiera de détecter automatiquement les mots de passe codés en hexadécimal ou en base64 et de les décoder en leur représentation binaire. Cependant, certains mots de passe en clair peuvent être convertis par erreur. La définition à « no » empêche cette conversion.

UTILISATION

Le module recherche l'attribut de contrôle Password-With-Header pour trouver le mot de passe « connu et valide ». La valeur de l'attribut comprend l'en-tête suivi immédiatement des données du mot de passe. L'en-tête est donné par le tableau suivant.

En-tête       Attribut           Description
------       ---------           -----------
{clear}      Cleartext-Password  Mots de passe en clair
{cleartext}  Cleartext-Password  Mots de passe en clair
{crypt}      Crypt-Password      Mots de passe chiffrés style Unix « crypt »
{md5}        MD5-Password        Mots de passe hachés MD5
{base64_md5} MD5-Password        Mots de passe hachés MD5
{smd5}       SMD5-Password       Mots de passe hachés MD5, avec un sel
{sha}        SHA-Password        Mots de passe hachés SHA1
             SHA1-Password       Mots de passe hachés SHA1
{ssha}       SSHA-Password       Mots de passe hachés SHA1, avec un sel
{sha2}       SHA2-Password       Mots de passe hachés SHA2
{sha224}     SHA2-Password       Mots de passe hachés SHA2
{sha256}     SHA2-Password       Mots de passe hachés SHA2
{sha384}     SHA2-Password       Mots de passe hachés SHA2
{sha512}     SHA2-Password       Mots de passe hachés SHA2
{ssha224}    SSHA2-224-Password  Mots de passe hachés SHA2, avec un sel
{ssha256}    SSHA2-256-Password  Mots de passe hachés SHA2, avec un sel
{ssha384}    SSHA2-384-Password  Mots de passe hachés SHA2, avec un sel
{ssha512}    SSHA2-512-Password  Mots de passe hachés SHA2, avec un sel
{nt}         NT-Password         Mots de passe hachés Windows NT
{nthash}     NT-Password         Mots de passe hachés Windows NT
{md4}        NT-Password         Mots de passe hachés Windows NT
{x-nthash}   NT-Password         Mots de passe hachés Windows NT
{ns-mta-md5} NS-MTA-MD5-Password Mots de passe hachés Netscape MTA MD5
{x- orcllmv} LM-Password         Mots de passe hachés Windows LANMAN
{X- orclntv} NT-Password         Mots de passe hachés Windows NT

Le module essaie d'être flexible lors du traitement des différents formats de mots de passe. Il gère automatiquement les données codées en Base64, les chaînes hexadécimales et les données binaires, et les convertit dans un format que le serveur peut utiliser.

S'il n'y a pas d'attribut Password-With-Header, le module recherche l'un des attributs Cleartext-Password, NT-Password, Crypt-Password, etc., comme indiqué dans le tableau ci-dessus. Ces attributs doivent contenir directement le mot de passe au format pertinent, sans le préfixe de l'en-tête.

Un seul attribut de contrôle doit être défini, sinon le comportement est indéfini quant à celui qui sera utilisé pour l'authentification.

NOTES

Il est important de comprendre la différence entre les attributs User-Password et Cleartext-Password. L'attribut Cleartext-Password est le mot de passe « connu et valide » de l'utilisateur. La simple fourniture de Cleartext-Password au serveur entraînera le fonctionnement de la plupart des méthodes d'authentification. L'attribut User-Password est le mot de passe tel que tapé par l'utilisateur sur sa machine privée. Les deux ne sont pas identiques et doivent être traités très différemment. Autrement dit, vous ne devriez généralement pas utiliser l'attribut User-Password nulle part dans la configuration RADIUS.
