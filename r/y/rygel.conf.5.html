RYGEL.CONF(5) Manuel de l'utilisateur Rygel RYGEL.CONF(5)

NOM

rygel.conf - Fichier de configuration de Rygel

SYNTAXE

$XDG_CONFIG_DIR/rygel.conf

/etc/rygel.conf

DESCRIPTION

rygel lit ses valeurs de configuration dans le fichier $XDG_CONFIG_DIR/rygel.conf ou dans un fichier donné sur la ligne de commande avec l'option --config. Si ce fichier n'existe pas, il utilise le fichier /etc/rygel.conf.

La plupart des options peuvent être remplacées par des arguments de ligne de commande ou des variables d'environnement. Voir rygel(1) pour plus de détails.

DIRECTIVES GÉNÉRALES

Les listes dans les fichiers de configuration sont séparées par un point-virgule (;). Les valeurs booléennes peuvent être true ou false.

ipv6

Réglez sur false pour désactiver la liaison aux adresses IPv6

interface=INTERFACE

Liste d'interfaces réseau, séparées par des points-virgules, sur lesquelles rygel doit écouter. Peut être une adresse IP, un nom d'interface ou, sous Linux, même l'ESSID d'un réseau sans fil.

port=PORT

Définissez le port d'écoute.

enable-transcoding

Réglez sur true pour activer le transcodage en général.

log-level=DOMAINE:NIVEAU[,DOMAINE:NIVEAU,...]

Liste de paires DOMAINE:NIVEAU, séparées par des virgules, permettant de définir le niveau de journalisation individuellement pour chaque domaine, où DOMAINE est soit "*", "rygel" soit le nom d'un plugin. Les niveaux de journalisation autorisés sont 1=erreur, 2=critique, 3=avertissement, 4=message/info, 5=débogage. Notez que sur les versions récentes de GLib (>= 2.36), il est nécessaire de définir la variable d'environnement G_MESSAGES_DEBUG à all pour obtenir une sortie de débogage.

plugin-path=CHEMIN

Définissez le chemin de recherche des plugins.

engine-path=CHEMIN

Définissez le chemin de recherche des moteurs.

media-engine=MOTEUR

Nom du module chargeable à utiliser comme backend pour le moteur multimédia.

allow-upload

Autoriser le téléchargement de fichiers multimédias via UPnP.

allow-deletion

Autoriser la suppression à distance de fichiers multimédias via UPnP.

video-upload-folder

Si allow-upload est true, utiliser ce dossier pour stocker les vidéos téléchargées. Par défaut, il s'agit de @VIDEOS@ qui correspond au répertoire par défaut pour les fichiers vidéo (généralement $HOME/Vidéos).

music-upload-folder

Si allow-upload est true, utiliser ce dossier pour stocker les musiques téléchargées. Par défaut, il s'agit de @MUSIC@ qui correspond au répertoire par défaut pour les fichiers musicaux (généralement $HOME/Musique).

picture-upload-folder

Si allow-upload est true, utiliser ce dossier pour stocker les images téléchargées. Par défaut, il s'agit de @PICTURES@ qui correspond au répertoire par défaut pour les fichiers image (généralement $HOME/Images).

force-downgrade-for

Liste, séparée par des points-virgules, des agents utilisateurs d'appareils (ou parties de ceux-ci) qui nécessitent une dégradation forcée à MediaServer:1 et/ou ContentDirectory:1.

Attention
N'utilisez ce paramètre que si vous savez ce que vous faites ou si on vous demande de le faire ; remplacer la valeur par défaut peut causer des incompatibilités. Si vous constatez que l'ajout de votre appareil ici permet son utilisation avec Rygel, veuillez ouvrir un rapport de bug IOP[1] afin que nous puissions l'inclure dans la configuration par défaut.

acl-fallback-policy

Il s'agit de la politique par défaut utilisée si aucun fournisseur de contrôle d'accès n'est trouvé sur D-Bus. Utilisez true pour autoriser l'accès à tous les pairs, false pour refuser tout accès. Si elle n'est pas spécifiée, la politique de repli par défaut est true.

strict-dlna

Désactivé par défaut. Utilisez true pour désactiver un ensemble de fonctionnalités qui améliorent la compatibilité avec de nombreux clients, mais enfreignent la conformité standard.

PARAMÈTRES BASE DE DONNÉES

Les paramètres de la section [Database] sont pour la bibliothèque de support de base de données.

debug

Réglez sur true pour afficher les instructions SQL utilisées.

PARAMÈTRES MOTEUR MULTIMÉDIA GSTREAMER

Les paramètres de la section [GstMediaEngine] sont spécifiques au moteur multimédia GStreamer, qui est le moteur multimédia par défaut. Voir le paramètre media-engine. Les options suivantes sont disponibles pour le moteur multimédia GStreamer[2].

transcoders

Une liste de transcoderurs actifs, séparée par des points-virgules. Cette option n'a aucun effet si enable-transcoding est réglé sur false. Les valeurs possibles sont : lpcm,mp3,mp2ts,aac,avc ou wmv. Sa valeur par défaut est lpcm;mp3;mp2ts;aac;wmv.

PARAMÈTRES SPÉCIFIQUES PLUGINS

Les sections des plugins sont délimitées par [NomDuPlugin] et peuvent contenir des options spécifiques à un plugin (voir ci-dessous) ainsi que les options communes suivantes :

title=TITRE

Titre de l'appareil implémenté par ce plugin. Il existe quelques variables qui seront remplacées par rygel. @REALNAME@ sera remplacé par le nom réel de l'utilisateur, @USERNAME@ par l'identifiant de connexion de l'utilisateur et @HOSTNAME@ par le nom de la machine sur laquelle rygel s'exécute.

enabled

Vous pouvez activer ou désactiver individuellement les plugins en les réglant sur true ou false.

energy-management

Réglez sur true si vous souhaitez que l'appareil UPnP contienne un service EnergyManagement. Notez que des configurations supplémentaires sont requises, voir les paramètres EnergyManagement.

diagnostics

Réglez sur true si vous souhaitez que l'appareil UPnP contienne un service BasicManagement:2 qui permet d'exécuter à distance des outils tels que ping, nslookup et traceroute.

server-name

Une chaîne de caractères qui sera envoyée en tant qu'en-tête "Server:" dans une réponse HTTP.

PARAMÈTRES ENERGYMANAGEMENT

Les paramètres des sections [EnergyManagement-NOMINTERFACE] spécifient les paramètres relatifs aux services EnergyManagement sur cette interface. Exemple : [EnergyManagement-eth0].

mode-on-suspend

Le NetworkInterfaceMode à utiliser lors de la mise en veille. Par défaut, il s'agit de "Unimplemented", d'autres valeurs valides sont "IP-up-Periodic”, "IP-down-no-Wake", "IP-down-with-WakeOn", "IP-down-with-WakeAuto", "IP-down-with-WakeOnAuto".

supported-transport

WakeSupportedTransport optionnel que le service doit annoncer. Les valeurs valides sont "UDP-Broadcast", "UDP-Unicast", "TCP-Unicast", "Other".

password

Mot de passe hexadécimal optionnel qui sera utilisé pour construire le WakeOnPattern.

PLUGIN TRACKER

Le plugin tracker utilise la base de données centralisée de métadonnées du projet tracker. Voir le site web du projet tracker[3] pour plus d'informations sur tracker.

share-pictures

Activer ou désactiver le partage de toutes les images dans la base de données Tracker.

share-videos

Activer ou désactiver le partage de toutes les vidéos dans la base de données Tracker.

share-music

Activer ou désactiver le partage de toute la musique dans la base de données Tracker.

PLUGIN MEDIAEXPORT

Le plugin MediaExport est une alternative à l'exportation multimédia basée sur tracker. Il extrait lui-même les métadonnées et les stocke dans une base de données SQLite[4] dans $XDG_CACHE_DIR/rygel/media-export.db sur les plateformes UNIX.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>

Note

Si les deux plugins, Tracker et MediaExport, sont activés, MediaExport se désactivera en faveur du plugin Tracker.

Plusieurs options sont prises en charge par ce plugin :

uris

Une liste d'URI à exposer via UPnP. Il peut s'agir de fichiers, de dossiers ou de tout ce qui est pris en charge par GVFS. Si elle est laissée vide, elle exporte par défaut les dossiers de musique, de vidéo et d'images de l'utilisateur tels que définis par la spécification des répertoires spéciaux des utilisateurs XDG. Ces répertoires par défaut peuvent être référencés par @MUSIC@, @PICTURES@ et @VIDEOS@. Les emplacements peuvent être saisis sous forme d'URI entièrement échappés ou de chemins normaux.

Note
Si vous entrez un chemin normal contenant des espaces, il n'est pas nécessaire de les échapper avec une barre oblique inverse ni de mettre la chaîne entre guillemets.

Note
Il est fortement déconseillé d'utiliser un dossier exporté comme cible pour les téléchargements lorsque extract-metadata est activé. Rygel ignorera très probablement les fichiers car leur extraction échouera.

Exemple 1. Valeurs possibles pour uris

uris=@MUSIC@;/home/user/My Pictures;file:///home/user/My%20Videos

extract-metadata

Mettez sur false si vous ne vous souciez pas de la durée ou de toute autre métadonnée comme l'artiste. Cela accélère considérablement l'analyse initiale des médias. Utilisez-le pour partager rapidement des fichiers via UPnP. Assurez-vous de définir un include-filter, sinon vous vous retrouverez avec de nombreux fichiers exposés que le client ne pourra de toute façon pas afficher.

monitor-changes

Mettez sur false si vous ne souhaitez pas que de nouveaux fichiers soient automatiquement détectés par rygel.

monitor-grace-timeout

Temps en secondes à attendre après la détection d'un nouveau fichier avant d'essayer d'en extraire les métadonnées. Utile si vous téléchargez dans un répertoire surveillé par rygel. Par défaut, 5 secondes.

virtual-folders

Mettez sur false si vous n'avez pas besoin de la hiérarchie de dossiers virtuels.

PLUGIN PLAYBIN

Le plugin Playbin implémente un lecteur multimédia (Digtal Media Renderer, DMR dans les termes DLNA). Ce plugin était connu sous le nom de GstRenderer.

Il est fortement recommandé de laisser le choix du puits à playbin. Si, toutefois, les choix par défaut ne vous conviennent pas, ils peuvent être reconfigurés comme suit :

audio-sink

Définition du puits audio à utiliser. Peut être un seul élément ou une définition de pipeline partielle dans la syntaxe de gst-launch

video-sink

Définition du puits vidéo à utiliser. Peut être un seul élément ou une définition de pipeline partielle dans la syntaxe de gst-launch

PLUGIN LIGHTMEDIASCANNER

Le plugin LightMediaScanner exporte le contenu du démon lightmediascanner[5]

Ce plugin n'a pas d'options spéciales.

PLUGIN GSTLAUNCH

Le plugin GstLaunch permet d'exposer des pipelines GStreamer en utilisant la même syntaxe que l'utilitaire gst-launch. Vous pouvez configurer plusieurs éléments dans ces plugins.

launch-items

Une liste d'identificateurs pour les pipelines à exposer.

identifier-title

Titre de l'appareil représenté par ce pipeline. Identifier est l'identificateur tel que défini dans launch-items

identifier-mime

Type MIME du pipeline.

identifier-launch

Définition du pipeline en syntaxe gst-launch. Pour quelques exemples sur l'écriture de pipelines, voir gst-launch(1).

identifier-dlnaprofile

Profil DLNA pour le flux.

Un exemple de configuration est disponible dans le fichier de configuration distribué /etc/rygel.conf.

EXTERNAL

Le plugin External est un consommateur de la spécification de l'interface DBus MediaServer2[6]. Cela permet aux programmes externes de partager leurs données via UPnP en implémentant cette spécification DBus. Le plugin détecte toute implémentation de cette interface sur le bus de session et expose les médias présentés via UPnP. Les implémenteurs connus de cette spécification sont gnome-dvb-daemon[7], Rhythmbox[8] et Grilo[9] via le projet grilo-ms2.

Vous pouvez désactiver toute la fonctionnalité en définissant enabled=false dans la section [External] du fichier de configuration.

Les pairs individuels peuvent être activés ou désactivés en créant des sections correspondant aux noms D-Bus du pair :

[org.gnome.UPnP.MediaServer2.Rhythmbox]
enabled=false

Ce plugin n'a pas d'options supplémentaires.

MPRIS

Le plugin MPRIS est un consommateur de la spécification de l'interface DBus MPRIS2[10]. L'implémentation est conforme à la version 2.0 de la norme.

rygel expose les lecteurs multimédias qui implémentent le côté fournisseur de cette spécification DBus en tant que lecteurs multimédias numériques DLNA (DMR) similaires au plugin Playbin. Cela signifie que vous pouvez facilement transformer votre lecteur multimédia en DMR en implémentant cette spécification DBus.

Les lecteurs qui implémentent cette spécification et qui sont connus pour fonctionner avec rygel sont Banshee[11], Rhythmbox[8] et Vidéos GNOME (anciennement Totem)[12]

Vous pouvez désactiver toute la fonctionnalité en définissant enabled=false dans la section [MRPIS] du fichier de configuration.

La configuration de ce plugin est spéciale. La configuration du plugin ne se fait pas sur le plugin mais plutôt par pair trouvé fournissant l'interface MPRIS2. Voir l'exemple suivant pour définir le titre de Banshee sur MPRIS :

[org.mpris.MediaPlayer2.banshee]
title=@REALNAME@'s Banshee on @HOSTNAME@

Ce plugin n'a pas d'options supplémentaires.
