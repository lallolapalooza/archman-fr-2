DESCRIPTION

Les fonctions svc_*() et clnt_*() décrites dans cette page sont l'ancienne interface TS-RPC de la bibliothèque XDR et RPC, et existent pour la compatibilité ascendante. La nouvelle interface est décrite dans les pages référencées par rpc(3).

Ces routines permettent aux programmes C de faire des appels de procédure sur d'autres machines à travers le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de dispatch pour effectuer le service demandé, puis renvoie une réponse. Finalement, l'appel de procédure retourne au client.

Les routines utilisées pour RPC sécurisé (authentification DES) sont décrites dans rpc_secure(3). RPC sécurisé ne peut être utilisé que si le chiffrement DES est disponible.

void
 
auth_destroy(AUTH *auth)

Une macro qui détruit les informations d'authentification associées à auth. La destruction implique généralement la désallocation de structures de données privées. L'utilisation de auth est indéfinie après l'appel de auth_destroy().

AUTH *
 
authnone_create()

Crée et retourne un handle d'authentification RPC qui passe des informations d'authentification non utilisables avec chaque appel de procédure distante. C'est l'authentification par défaut utilisée par RPC.

AUTH *
 
authunix_create(char *host, int uid, int gid, int len, int *aup_gids)

Crée et retourne un handle d'authentification RPC qui contient des informations d'authentification UNIX. L'argument host est le nom de la machine sur laquelle les informations ont été créées ; uid est l'identifiant utilisateur de l'utilisateur ; gid est l'identifiant du groupe actuel de l'utilisateur ; len et aup_gids se réfèrent à un tableau indexé des groupes auxquels l'utilisateur appartient. Il est facile d'usurper l'identité d'un utilisateur.

AUTH *
 
authunix_create_default()

Appelle authunix_create() avec les arguments appropriés.

int callrpc(char *host, u_long prognum, u_long versnum, u_long procnum, xdrproc_t inproc, void *in, xdrproc_t outproc, void *out);

Appelle la procédure distante associée à prognum, versnum, et procnum sur la machine host. L'argument in est l'adresse des arguments de la procédure, et out est l'adresse où placer les résultats ; inproc est utilisé pour encoder les arguments de la procédure, et outproc est utilisé pour décoder les résultats de la procédure. Cette routine retourne zéro en cas de succès, ou la valeur de enum clnt_stat convertie en entier en cas d'échec. La routine clnt_perrno() est utile pour traduire les statuts d'échec en messages.

Attention : appeler des procédures distantes avec cette routine utilise UDP/IP comme transport ; voir clntudp_create() pour les restrictions. Vous n'avez pas le contrôle des délais d'attente ou de l'authentification avec cette routine.

enum clnt_stat
 
clnt_broadcast(u_long prognum, u_long versnum, u_long procnum, xdrproc_t inproc, char *in, xdrproc_t outproc, char *out, bool_t (*eachresult)(caddr_t, struct sockaddr_in *));

Comme callrpc(), sauf que le message d'appel est diffusé à tous les réseaux de diffusion connectés localement. Chaque fois qu'elle reçoit une réponse, cette routine appelle eachresult(), dont la forme est :

bool_t eachresult(caddr_t out, struct sockaddr_in *addr)

où out est le même que out passé à clnt_broadcast - broadcast RPC call

NAME

clnt_broadcast - broadcast RPC call

SYNOPSIS

clnt_broadcast(unsigned long prog, unsigned long vers, unsigned long proc, xdrproc_t encod, char *args, xdrproc_t decod, char *result, int (*eachresult)(char *, struct sockaddr_in *), int seconds);

DESCRIPTION

The clnt_broadcast() routine makes an RPC call to all machines on the network. The call is to the remote procedure proc of program prog with version vers. The arguments are encoded by the XDR routine encod, and placed in args. The results are decoded by the XDR routine decod, and placed in result. The function eachresult is called for each result that is returned. If eachresult returns non-zero, the broadcast is terminated. The seconds argument specifies the time interval, in seconds, to wait for replies.

The clnt_broadcast() routine is similar to clnt_call(), except that the remote procedure's output is decoded there; addr points to the address of the machine that sent the results. If eachresult() returns zero, clnt_broadcast() waits for more replies; otherwise it returns with appropriate status.

Warning: broadcast sockets are limited in size to the maximum transfer unit of the data link. For ethernet, this value is 1500 bytes.

NAME

rpc_soc, xdr_rejected_reply, xdr_replymsg, xprt_register, xprt_unregister — socket-based RPC service routines

SYNOPSIS

bool_t
xdr_pmaplist(XDR *xdrs, struct pmaplist **rp);

DESCRIPTION

These routines are part of the libtirpc library, providing utilities for constructing RPC messages. They are intended to be used by developers who need finer control over RPC message construction than is offered by the standard RPC programming interfaces.

The xdr_pmaplist() routine is used to describe a list of port mappings, externally. This routine is useful for users who wish to generate these arguments without using the pmap_*() interface.

The xdr_rejected_reply() routine is used for describing RPC reply messages. This routine is useful for users who wish to generate RPC-style messages without using the RPC package.

The xdr_replymsg() routine is also used for describing RPC reply messages. This routine is useful for users who wish to generate RPC style messages without using the RPC package.

 

The xprt_register() routine is used to register RPC service transport handles with the RPC service package. After RPC service transport handles are created, they should register themselves with the RPC service package. This routine modifies the global variable svc_fds. Service implementors usually do not need this routine.

 

The xprt_unregister() routine is used to unregister RPC service transport handles from the RPC service package. Before an RPC service transport handle is destroyed, it should unregister itself with the RPC service package. This routine modifies the global variable svc_fds. Service implementors usually do not need this routine.

AVAILABILITY

These functions are part of libtirpc.
