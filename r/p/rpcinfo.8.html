RPCINFO(8) Manuel de l'administrateur système RPCINFO(8)

NOM

rpcinfo — rapporte les informations RPC

SYNTAXE

rpcinfo [-m | -s] [hôte]

rpcinfo -p [hôte]

rpcinfo -T transport hôte prognum [versnum]

rpcinfo -l [-T transport] hôte prognum versnum

rpcinfo [-n portnum] -u hôte prognum [versnum]

rpcinfo [-n portnum] [-t] hôte prognum [versnum]

rpcinfo -a serv_address -T transport prognum [versnum]

rpcinfo -b [-T transport] prognum versnum

rpcinfo -d [-T transport] prognum versnum

DESCRIPTION

rpcinfo effectue un appel RPC à un serveur RPC et rapporte ce qu'il trouve.

Dans la première syntaxe, rpcinfo liste tous les services RPC enregistrés auprès de rpcbind sur l'hôte. Si hôte n'est pas spécifié, l'hôte local est utilisé par défaut. Si -s est utilisé, les informations sont affichées dans un format concis.

Dans la deuxième syntaxe, rpcinfo liste tous les services RPC enregistrés auprès de rpcbind, version 2. Notez également que le format des informations est différent dans la première et la seconde syntaxe. Ceci est dû au fait que la seconde syntaxe utilise un ancien protocole pour collecter les informations affichées (version 2 du protocole rpcbind).

La troisième syntaxe effectue un appel RPC à la procédure 0 de prognum et versnum sur l'hôte spécifié et rapporte si une réponse a été reçue. transport est le transport qui doit être utilisé pour contacter le service donné. L'adresse distante du service est obtenue en effectuant un appel au rpcbind distant.

L'argument prognum est un nombre qui représente un numéro de programme RPC. Si un versnum est spécifié, rpcinfo tente d'appeler cette version du prognum spécifié. Sinon, rpcinfo tente de trouver tous les numéros de version enregistrés pour le prognum spécifié en appelant la version 0, qui est supposée ne pas exister ; si elle existe, rpcinfo tente d'obtenir ces informations en appelant plutôt un numéro de version extrêmement élevé, et tente d'appeler chaque version enregistrée. Remarque : le numéro de version est requis pour les options -b et -d.

OPTIONS

-T transport
Spécifie le transport sur lequel le service est requis. Si cette option n'est pas spécifiée, rpcinfo utilise le transport spécifié dans la variable d'environnement NETPATH, ou si celle-ci est vide ou non définie, le transport dans la base de données netconfig(5) est utilisé. Ceci est une option générique, et peut être utilisée en conjonction avec d'autres options comme montré dans la SYNTAXE.
-a serv_address
Utilise serv_address comme adresse (universelle) pour le service sur transport pour interroger la procédure 0 du prognum spécifié et rapporte si une réponse a été reçue. L'option -T est requise avec l'option -a.

Si versnum n'est pas spécifié, rpcinfo essaie d'interroger toutes les versions disponibles pour ce numéro de programme. Cette option évite les appels au rpcbind distant pour trouver l'adresse du service. L'adresse du service est spécifiée au format d'adresse universelle du transport donné.

-b
Effectue une diffusion RPC vers la procédure 0 du prognum et versnum spécifiés et rapporte tous les hôtes qui répondent. Si transport est spécifié, il diffuse sa requête uniquement sur le transport spécifié. Si la diffusion n'est pas supportée par un transport, un message d'erreur est affiché. L'utilisation de la diffusion doit être limitée en raison de son impact potentiel sur d'autres systèmes.
-d
Supprime l'enregistrement pour le service RPC du prognum et versnum spécifiés. Si transport est spécifié, désenregistre le service uniquement sur ce transport, sinon désenregistre le service sur tous les transports sur lesquels il était enregistré. Seul le propriétaire d'un service peut supprimer un enregistrement, à l'exception du super-utilisateur qui peut supprimer n'importe quel service.
-l
Affiche une liste des entrées avec un prognum et un versnum donnés sur l'hôte spécifié. Les entrées sont retournées pour tous les transports dans la même famille de protocoles que celle utilisée pour contacter le rpcbind distant.
-m
Affiche un tableau de statistiques des opérations de rpcbind sur l'hôte donné. Le tableau montre les statistiques pour chaque version de rpcbind (versions 2, 3 et 4), donnant le nombre de fois où chaque procédure a été demandée et traitée avec succès, le nombre et le type de requêtes d'appel distant qui ont été effectuées, et des informations sur les recherches d'adresses RPC qui ont été gérées. Ceci est utile pour surveiller les activités RPC sur hôte.
-n portnum
Utilise portnum comme numéro de port pour les options -t et -u au lieu du numéro de port fourni par rpcbind. L'utilisation de cette option évite un appel au rpcbind distant pour connaître l'adresse du service. Cette option est rendue obsolète par l'option -a.
-p
Sonde rpcbind sur l'hôte en utilisant la version 2 du protocole rpcbind, et affiche une liste de tous les programmes RPC enregistrés. Si hôte n'est pas spécifié, il est par défaut l'hôte local. Remarque : La version 2 du protocole rpcbind était auparavant connue sous le nom de protocole portmapper.
-s

-t
Effectue un appel RPC vers la procédure 0 de prognum sur la machine spécifiée hôte en utilisant TCP, et signale si une réponse a été reçue. Cette option est rendue obsolète par l'option -T comme montré dans le troisième synopsis.
-u
Effectue un appel RPC vers la procédure 0 de prognum sur la machine spécifiée hôte en utilisant UDP, et signale si une réponse a été reçue. Cette option est rendue obsolète par l'option -T comme montré dans le troisième synopsis.

EXEMPLES

Pour afficher tous les services RPC enregistrés sur la machine locale, utilisez :

example% rpcinfo

Pour afficher tous les services RPC enregistrés avec rpcbind sur la machine nommée klaxon, utilisez :

example% rpcinfo klaxon

Les informations affichées par les commandes ci-dessus peuvent être assez longues. Utilisez l'option -s pour afficher une liste plus concise :

example$ rpcinfo -s klaxon
programme version(s) netid(s) service propriétaire
100000 2,3,4 local,tcp,udp,tcp6,udp6 rpcbind super-utilisateur
100008 1 udp,tcp,udp6,tcp6 walld super-utilisateur
100002 2,1 udp,udp6 rusersd super-utilisateur
100001 2,3,4 udp,udp6 rstatd super-utilisateur
100012 1 udp,tcp sprayd super-utilisateur
100007 3 udp,tcp ypbind super-utilisateur

Pour afficher si le service RPC avec le numéro de programme prognum et la version versnum est enregistré sur la machine nommée klaxon pour le transport TCP, utilisez :

example% rpcinfo -T tcp klaxon prognum versnum

Pour afficher tous les services RPC enregistrés avec la version 2 du protocole rpcbind sur la machine locale, utilisez :

example% rpcinfo -p

Pour supprimer l'enregistrement de la version 1 du service walld (numéro de programme 100008) pour tous les transports, utilisez :

example# rpcinfo -d 100008 1

ou

example# rpcinfo -d walld 1
