SVCXPRT *
svc_tp_create(void (*dispatch)(struct svc_req *, SVCXPRT *), const rpcprog_t prognum, const rpcvers_t versnum, const struct netconfig *netconf);

DESCRIPTION

Ces routines font partie de la bibliothèque RPC qui permet aux programmes en langage C de faire des appels de procédure à des serveurs sur le réseau. Ces routines s'occupent de la création des descripteurs de service. Une fois le descripteur créé, le serveur peut être invoqué en appelant svc_run().

ROUTINES

Voir rpc(3) pour la définition de la structure de données SVCXPRT.

svc_control()
Une fonction pour modifier ou récupérer diverses informations sur un objet de service. L'argument req indique le type d'opération et info est un pointeur vers les informations. Les valeurs prises en charge pour req, leurs types d'arguments et ce qu'elles font sont :
SVCGET_VERSQUIET
Si une requête est reçue pour un numéro de programme servi par ce serveur, mais que le numéro de version est en dehors de la plage enregistrée auprès du serveur, une erreur RPC_PROGVERSMISMATCH sera normalement retournée. L'argument info doit être un pointeur vers un entier. En cas de succès de la requête SVCGET_VERSQUIET, *info contiendra un entier décrivant le comportement actuel du serveur : 0 indique un comportement normal du serveur (c'est-à-dire qu'une erreur RPC_PROGVERSMISMATCH sera retournée) ; 1 indique que la requête hors plage sera ignorée silencieusement.
SVCSET_VERSQUIET
Si une requête est reçue pour un numéro de programme servi par ce serveur, mais que le numéro de version est en dehors de la plage enregistrée auprès du serveur, une erreur RPC_PROGVERSMISMATCH sera normalement retournée. Il est parfois souhaitable de modifier ce comportement. L'argument info doit être un pointeur vers un entier qui est soit 0 (indiquant un comportement normal du serveur - une erreur RPC_PROGVERSMISMATCH sera retournée), soit 1 (indiquant que la requête hors plage doit être ignorée silencieusement).
svc_create()
La fonction svc_create() crée des descripteurs de serveur pour tous les transports appartenant à la classe nettype. L'argument nettype définit une classe de transports qui peuvent être utilisés pour une application particulière. Les transports sont essayés de gauche à droite dans la variable NETPATH ou de haut en bas dans la base de données netconfig. Si nettype est NULL, il prend par défaut "netpath".

La fonction svc_create() s'enregistre auprès du service rpcbind (voir rpcbind(8)). La fonction dispatch est appelée lorsqu'il y a un appel de procédure distante pour le prognum et le versnum donnés ; cela nécessite d'appeler svc_run() (voir svc_run() dans rpc_svc_reg(3)). Si svc_create() réussit, elle retourne le nombre de descripteurs de serveur qu'elle a créés, sinon elle retourne 0 et un message d'erreur est enregistré.

svc_destroy()
Une macro fonction qui détruit le descripteur de service RPC xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine.
svc_dg_create()
Cette routine crée un descripteur de service RPC sans connexion et retourne un pointeur vers celui-ci. Cette routine retourne NULL en cas d'échec et un message d'erreur est enregistré. Les arguments sendsz et recvsz sont des arguments utilisés pour spécifier la taille des tampons. S'ils sont à 0, des valeurs par défaut appropriées sont choisies. Le descripteur de fichier fildes doit être ouvert et lié. Le serveur n'est pas enregistré auprès de rpcbind(8).

Attention : comme les messages RPC basés sur la connexion ne peuvent contenir qu'une quantité limitée de données encodées, ce transport ne peut pas être utilisé pour les procédures qui acceptent de grands arguments ou retournent des résultats volumineux.

svc_fd_create()

svc_raw_create()
Cette routine crée un descripteur de service RPC et renvoie un pointeur vers celui-ci. Le transport est en réalité un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant doit résider dans le même espace d'adressage ; (voir clnt_raw_create() dans rpc_clnt_create(3)). Cette routine permet de simuler le RPC et d'acquérir les frais généraux RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau et du réseau. Cette routine renvoie NULL si elle échoue, et un message d'erreur est enregistré.

Note : svc_run() ne doit pas être appelée lorsque l'interface brute est utilisée.

svc_tli_create()
Cette routine crée un descripteur de serveur RPC, et renvoie un pointeur vers celui-ci. L'argument fildes est le descripteur de fichier sur lequel le service écoute. Si fildes est RPC_ANYFD, il ouvre un descripteur de fichier sur le transport spécifié par netconf. Si le descripteur de fichier est non lié et bindaddr n'est pas NULL, fildes est lié à l'adresse spécifiée par bindaddr, sinon fildes est lié à une adresse par défaut choisie par le transport.

Note : la structure t_bind provient de l'interface SysV TLI/XTI, que NetBSD n'utilise pas. La structure est définie dans <rpc/types.h> pour la compatibilité comme suit :

struct t_bind {
    struct netbuf addr;	/* adresse réseau, voir rpc(3) */
    unsigned int  qlen;	/* longueur de la file d'attente (pour listen(2)) */
};

Dans le cas où l'adresse par défaut est choisie, le nombre de requêtes de connexion en attente est défini à 8 pour les transports orientés connexion. L'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les arguments sendsz et recvsz ; des valeurs de 0 choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL si elle échoue, et un message d'erreur est enregistré. Le serveur n'est pas enregistré auprès du service rpcbind(8).

svc_tp_create()
La fonction svc_tp_create() crée un descripteur de serveur pour le réseau spécifié par netconf, et s'enregistre auprès du service rpcbind. La fonction dispatch est appelée lorsqu'il y a un appel de procédure distante pour le prognum et le versnum donnés ; cela nécessite l'appel de svc_run(). La fonction svc_tp_create() renvoie le descripteur de service en cas de succès, sinon un NULL est renvoyé et un message d'erreur est enregistré.
svc_vc_create()
Cette routine crée un service RPC orienté connexion et renvoie un pointeur vers celui-ci. Cette routine renvoie NULL si elle échoue, et un message d'erreur est enregistré. L'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les arguments sendsz et recvsz ; des valeurs de 0 choisissent des valeurs par défaut appropriées. Le descripteur de fichier fildes doit être ouvert et lié. Le serveur n'est pas enregistré auprès du service rpcbind(8).

DISPONIBILITÉ

Ces fonctions font partie de libtirpc.
