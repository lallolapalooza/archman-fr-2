DESCRIPTION

rpm est un puissant Gestionnaire de paquets, qui peut être utilisé pour construire, installer, interroger, vérifier, mettre à jour et supprimer des paquets logiciels individuels. Un paquet se compose d'une archive de fichiers et de métadonnées utilisées pour installer et supprimer les fichiers de l'archive. Les métadonnées incluent des scripts d'aide, des attributs de fichiers et des informations descriptives sur le paquet. Les paquets existent en deux variétés : les paquets binaires, utilisés pour encapsuler le logiciel à installer, et les paquets sources, contenant le code source et la recette nécessaire pour produire les paquets binaires.

L'un des modes de base suivants doit être sélectionné : Interrogation, Vérification, Installation/Mise à niveau/Rafraîchissement/Réinstallation, Désinstallation, Définir Propriétaires/Groupes, Afficher Querytags, et Afficher Configuration.

OPTIONS GÉNÉRALES

Ces options peuvent être utilisées dans tous les modes différents.

-?, --help
Affiche un message d'utilisation plus long que la normale.
--version
Affiche une seule ligne contenant le numéro de version de rpm utilisé.
--quiet
Affiche le moins d'informations possible - normalement seuls les messages d'erreur seront affichés.
-v, --verbose
Affiche des informations détaillées - normalement les messages de progression routiniers seront affichés.
-vv
Affiche beaucoup d'informations de débogage.
--rcfile LISTE_FICHIERS
Remplace la liste par défaut des fichiers de configuration à lire par LISTE_FICHIERS. Voir Configuration rpmrc pour les détails.
--load FICHIER
Charge un fichier de macro individuel.
--macros LISTE_FICHIERS
Remplace la liste des fichiers de macros à charger par LISTE_FICHIERS. Voir Configuration des macros pour les détails.
--pipe CMD
Passe la sortie de rpm à la commande CMD.
--dbpath RÉPERTOIRE
Utilise la base de données dans RÉPERTOIRE au lieu du chemin par défaut /var/lib/rpm.
--root RÉPERTOIRE
Utilise l'arborescence du système de fichiers racine à RÉPERTOIRE pour toutes les opérations. Notez que cela signifie que la base de données dans RÉPERTOIRE sera utilisée pour les vérifications de dépendances et que tout scriptlet (par ex. %post si installation, ou %prep si construction, d'un paquet) sera exécuté après un chroot(2) vers RÉPERTOIRE.

Notez que rpm suppose que l'environnement à l'intérieur de la racine est configuré par l'appelant, tels que les points de montage nécessaires à l'opération dans le répertoire racine.

-D, --define='MACRO EXPR'
Définit MACRO avec la valeur EXPR.
--undefine='MACRO'
Annule la définition de MACRO.
-E, --eval='EXPR'
Affiche l'expansion de macro de EXPR.

Plus d'options - moins souvent nécessaires - peuvent être trouvées sur la page de manuel rpm-misc(8).

La forme générale d'une commande d'installation rpm est

rpm {-i|--install} [install-options] PACKAGE_FILE ...

Ceci installe un nouveau paquet.

La forme générale d'une commande de mise à niveau rpm est

rpm {-U|--upgrade} [install-options] PACKAGE_FILE ...

Ceci met à niveau ou installe la version actuelle du paquet à une version plus récente. C'est identique à l'installation, sauf que toutes les autres versions du paquet sont supprimées après l'installation du nouveau paquet.

rpm {-F|--freshen} [install-options] PACKAGE_FILE ...

Ceci mettra à niveau les paquets, mais uniquement ceux pour lesquels une version antérieure est installée.

La forme générale d'une commande de réinstallation rpm est

rpm {--reinstall} [install-options] PACKAGE_FILE ...

Ceci réinstalle un paquet précédemment installé.

--allfiles
Installe ou met à niveau tous les fichiers missingok du paquet, qu'ils existent ou non.
--badreloc
Utilisé avec --relocate, permet des relocalisations sur tous les chemins de fichiers, pas seulement ceux dont les OLDPATH sont inclus dans les indices de relocalisation du paquet binaire.
--excludepath OLDPATH
N'installe pas les fichiers dont le nom commence par OLDPATH.
--excludeartifacts
N'installe aucun fichier marqué comme artefact, tels que les liens de type build-id.
--excludedocs
N'installe aucun fichier marqué comme documentation (ce qui inclut les pages man et les documents texinfo).
--force
Identique à l'utilisation de --replacepkgs, --replacefiles, et --oldpackage.
-h, --hash
Affiche 50 signes dièse pendant que l'archive du paquet est décompressée. Utiliser avec -v|--verbose pour un affichage plus agréable.
--ignoresize
Ne vérifie pas si les systèmes de fichiers montés disposent de suffisamment d'espace disque avant d'installer ce paquet.
--ignorearch
Permet l'installation ou la mise à niveau même si les architectures du paquet binaire et de l'hôte ne correspondent pas.
--ignoreos
Permet l'installation ou la mise à niveau même si les systèmes d'exploitation du paquet binaire et de l'hôte ne correspondent pas.
--includedocs
Installe les fichiers de documentation. C'est le comportement par défaut.
--justdb
Met à jour uniquement la base de données, pas le système de fichiers.
--nodb
Met à jour uniquement le système de fichiers, pas la base de données.
--nodigest
Ne vérifie pas les sommes de contrôle des paquets ou des en-têtes lors de la lecture.
--nomanifest
Ne traite pas les fichiers non-paquets comme des manifestes.
--nosignature
Ne vérifie pas les signatures des paquets ou des en-têtes lors de la lecture.
--nodeps
Ne fait pas de vérification de dépendances avant d'installer ou de mettre à niveau un paquet.
--nocaps
Ne définit pas les capacités de fichier.
--noorder
Ne réorganise pas les paquets pour une installation. La liste des paquets serait normalement réorganisée pour satisfaire les dépendances.
--noverify
Ne vérifie pas les fichiers du paquet avant l'installation.
--noplugins
Ne charge ni n'exécute les plugins.
--noscripts, --nopre, --nopost, --nopreun, --nopostun, --nopretrans, --noposttrans, --nopreuntrans, --nopostuntrans
N'exécute pas le scriptlet du même nom. L'option --noscripts est équivalente à

--nopre --nopost --nopreun --nopostun --nopretrans --noposttrans --nopreuntrans --nopostuntrans

et désactive l'exécution des scriptlets correspondants %pre, %post, %preun, %postun %pretrans, %posttrans, %preuntrans et %postuntrans.

--notriggers, --notriggerin, --notriggerun, --notriggerprein, --notriggerpostun
N'exécute aucun scriptlet de déclencheur du type nommé. L'option --notriggers est équivalente à

--notriggerprein --notriggerin --notriggerun --notriggerpostun

et désactive l'exécution des scriptlets correspondants %triggerprein, %triggerin, %triggerun et %triggerpostun.

--nosysusers
Ne crée pas d'utilisateurs système à partir des paquets
--oldpackage
Permet à une mise à niveau de remplacer un paquet plus récent par un plus ancien.
--percent
Affiche les pourcentages lors du dépaquetage des fichiers de l'archive du paquet. Ceci est destiné à rendre rpm facile à utiliser à partir d'autres outils.
--prefix NEWPATH
Pour les paquets binaires relocalisables, traduit tous les chemins de fichiers qui commencent par le préfixe d'installation dans les indices de relocalisation du paquet à NEWPATH.
--relocate OLDPATH=NEWPATH
Pour les paquets binaires relocalisables, traduit tous les chemins de fichiers qui commencent par OLDPATH dans les indices de relocalisation du paquet à NEWPATH. Cette option peut être utilisée plusieurs fois si plusieurs OLDPATH dans le paquet doivent être relocalisés.
--replacefiles
Installe les paquets même s'ils remplacent des fichiers d'autres paquets déjà installés.
--replacepkgs
Installe les paquets même si certains d'entre eux sont déjà installés sur ce système.
--test
N'installe pas le paquet, vérifie et signale simplement les conflits potentiels.

OPTIONS D'EFFACEMENT

La forme générale d'une commande d'effacement rpm est

rpm {-e|--erase} [--allmatches] [--justdb] [--nodeps] [--noscripts] [--notriggers] [--test] PACKAGE_NAME ...

Les options suivantes peuvent également être utilisées :

--allmatches
Supprime toutes les versions du paquet qui correspondent à PACKAGE_NAME. Normalement, une erreur est signalée si PACKAGE_NAME correspond à plusieurs paquets.
--justdb
Met à jour uniquement la base de données, pas le système de fichiers.
--nodeps
Ne vérifie pas les dépendances avant de désinstaller les paquets.
--noscripts, --nopreun, --nopostun
N'exécute pas le scriptlet du même nom. L'option --noscripts lors de l'effacement d'un paquet est équivalente à

--nopreun --nopostun

et désactive l'exécution des scriptlets correspondants %preun et %postun.

--notriggers, --notriggerun, --notriggerpostun
N'exécute aucun scriptlet de déclencheur du type nommé. L'option --notriggers est équivalente à

--notriggerun --notriggerpostun

et désactive l'exécution des scriptlets correspondants %triggerun et %triggerpostun.

--test
Ne désinstalle rien, effectue seulement les étapes nécessaires. Utile en conjonction avec l'option -vv pour le débogage.

OPTIONS DE RECHERCHE

La forme générale d'une commande de recherche rpm est

rpm {-q|--query} [select-options] [query-options]

Vous pouvez spécifier le format dans lequel les informations du paquet doivent être imprimées. Pour ce faire, utilisez l'option

--qf|--queryformat QUERYFMT

suivie de la chaîne de format QUERYFMT. Les formats de recherche sont des versions modifiées du formatage standard de printf(3). Le format est composé de chaînes statiques (qui peuvent inclure des échappements de caractères C standard pour les nouvelles lignes, les tabulations et autres caractères spéciaux (n'incluant pas \0)) et de formateurs de type printf(3). Comme rpm connaît déjà le type à imprimer, le spécificateur de type doit être omis, remplacé par le nom de la balise d'en-tête à imprimer, entouré de caractères {}. Les noms de balises ne sont pas sensibles à la casse, et la partie RPMTAG_ initiale du nom de balise peut également être omise.

Des formats de sortie alternatifs peuvent être demandés en ajoutant :typetag après la balise. Actuellement, les types suivants sont pris en charge :

:armor
Encapsule une clé publique dans un blindage ASCII.
:arraysize
Affiche le nombre d'éléments dans les balises de tableau.
:base64
Encode les données binaires en utilisant base64.
:date
Utilise le format strftime(3) "%c".
:jour
Utiliser le format strftime(3) « %a %b %d %Y ».
:flagsdep
Opérateur de comparaison des dépendances formaté.
:typedep
Type de dépendance formaté.
:expand
Effectuer l'expansion des macros.
:flagsfic
Drapeaux de fichier formatés.
:etatfic
État du fichier formaté.
:statverif
Statut de vérification du fichier formaté.
:hex
Format hexadécimal.
:octal
Format octal.
:humaniec
Nombre lisible par l'homme (selon IEC 80000). Le suffixe K = 1024, M = 1048576, ...
:humansi
Nombre lisible par l'homme (selon SI). Le suffixe K = 1000, M = 1000000, ...
:json
Encapsuler les données en JSON.
:perms
Permissions du fichier formatées.
:pgpsig
Afficher l'empreinte digitale et l'heure de la signature.
:shescape
Échapper les apostrophes pour une utilisation dans un script.
:string
Afficher le format de chaîne. (par défaut)
:tagname
Afficher le nom de la balise.
:tagnum
Afficher le numéro de la balise.
:triggertype
Afficher le suffixe du déclencheur.
:vflags
Drapeaux de vérification de fichier.
:xml
Encapsuler les données dans un marquage xml simple.

Par exemple, pour n'afficher que les noms des paquets interrogés, vous pourriez utiliser %{NOM} comme chaîne de format. Pour afficher le nom des paquets et les informations de distribution en deux colonnes, vous pourriez utiliser %-30{NOM}%{DISTRIBUTION}. rpm affichera une liste de toutes les balises qu'il connaît lorsqu'il est appelé avec l'argument --querytags.

Il existe trois sous-ensembles d'options pour les requêtes : sélection de paquet, sélection de fichier et sélection d'informations.

OPTIONS DE SÉLECTION DE PAQUET

NOM_DU_PAQUET
Interroge le paquet installé nommé NOM_DU_PAQUET. Pour spécifier le paquet plus précisément, le nom du paquet peut être suivi de la version ou de la version et de la publication, toutes deux séparées par un tiret, ou d'un nom d'architecture séparé par un point. Voir la sortie de rpm -qa ou rpm -qp FICHIER_PAQUET comme exemple.
-a, --all [SÉLECTEUR]
Interroge tous les paquets installés.

Un SÉLECTEUR optionnel sous la forme tag=motif peut être fourni pour affiner la sélection, par exemple name="b*" pour interroger les paquets dont le nom commence par "b".

--dupes
Lister les paquets dupliqués.
-f, --file FICHIER
Interroge le paquet possédant le FICHIER installé.
--filecaps
Lister les noms de fichiers avec les capacités POSIX1.e.
--fileclass
Lister les noms de fichiers avec leurs classes (classification libmagic).
--filecolor
Lister les noms de fichiers avec leurs couleurs (0 pour noarch, 1 pour 32 bits, 2 pour 64 bits).
--fileprovide
Lister les noms de fichiers avec leurs provide.
--filerequire
Lister les noms de fichiers avec leurs require.
-g, --group GROUPE
Interroge les paquets du groupe GROUPE.
--hdrid SHA1
Interroge le paquet contenant un identifiant d'en-tête donné, c'est-à-dire le condensat SHA1 de la région d'en-tête immuable.
-p, --package FICHIER_PAQUET
Interroge un paquet (non installé) FICHIER_PAQUET. Le FICHIER_PAQUET peut être spécifié comme une URL de style ftp ou http, auquel cas l'en-tête du paquet sera téléchargé et interrogé. Voir **OPTIONS FTP/HTTP** pour plus d'informations sur le support client ftp et http de rpm. L'argument (les arguments) FICHIER_PAQUET, s'il ne s'agit pas d'un paquet binaire, sera interprété comme un manifeste de paquet ASCII, sauf si l'option --nomanifest est utilisée. Dans les manifestes, les commentaires sont autorisés, commençant par un '#', et chaque ligne d'un fichier manifeste de paquet peut inclure des expressions glob séparées par des espaces blancs, y compris des URL, qui seront développées en chemins qui seront substitués à la place du manifeste de paquet en tant qu'arguments FICHIER_PAQUET supplémentaires à la requête.
--path CHEMIN
Interroge le ou les paquets possédant le CHEMIN, que le fichier soit installé ou non. Plusieurs paquets peuvent posséder un CHEMIN, mais le fichier n'est possédé que par le paquet installé en dernier.
--pkgid MD5
Interroge le paquet contenant un identifiant de paquet donné, c'est-à-dire le condensat MD5 du contenu combiné de l'en-tête et de la charge utile.
--querybynumber HDRNUM
Interroge directement la HDRNUMème entrée de la base de données ; ceci n'est utile que pour le débogage.
--specfile FICHIER_SPEC
Analyse et interroge FICHIER_SPEC comme s'il s'agissait d'un paquet. Bien que toutes les informations (par exemple, les listes de fichiers) ne soient pas disponibles, ce type de requête permet à rpm d'être utilisé pour extraire des informations des fichiers spec sans avoir à écrire un analyseur de specfile.
--tid TID
Interroge le ou les paquets ayant un identifiant de transaction TID donné. Un horodatage UNIX est actuellement utilisé comme identifiant de transaction. Tous les paquets installés ou effacés au cours d'une transaction unique ont un identifiant commun.
--triggeredby NOM_PAQUET
Interroge les paquets qui sont déclenchés par le ou les paquets NOM_PAQUET.
--whatobsoletes CAPACITÉ
Interroge tous les paquets qui obsolètent la CAPACITÉ pour un fonctionnement correct.
--whatprovides CAPACITÉ
Interroge tous les paquets qui fournissent la capacité CAPACITÉ.
--whatrequires CAPACITÉ
Interroge tous les paquets qui nécessitent la CAPACITÉ pour un fonctionnement correct.
--whatconflicts CAPACITÉ
Interroge tous les paquets qui entrent en conflit avec la CAPACITÉ.
--whatrecommends CAPACITÉ
Interroge tous les paquets qui recommandent la CAPACITÉ.
--whatsuggests CAPACITÉ
Interroge tous les paquets qui suggèrent la CAPACITÉ.
--whatsupplements CAPACITÉ
Interroge tous les paquets qui complètent la CAPACITÉ.
--whatenhances CAPACITÉ
Interroge tous les paquets qui améliorent la CAPACITÉ.

OPTIONS DE VÉRIFICATION

La forme générale d'une commande rpm de vérification est

rpm {-V|--verify} [select-options] [verify-options]

La vérification d'un paquet compare les informations sur les fichiers installés dans le paquet avec les informations sur les fichiers tirées des métadonnées du paquet stockées dans la base de données rpm. Entre autres choses, la vérification compare la taille, le digest, les permissions, le type, le propriétaire et le groupe de chaque fichier. Toute divergence est affichée. Les fichiers qui n'ont pas été installés à partir du paquet, par exemple, les fichiers de documentation exclus lors de l'installation en utilisant l'option "--excludedocs", seront silencieusement ignorés.

Les options de sélection de paquets et de fichiers sont les mêmes que pour la requête de paquet (y compris les fichiers manifeste de paquet comme arguments). Les autres options spécifiques au mode de vérification sont :

--nodeps
Ne pas vérifier les dépendances des paquets.
--nodigest
Ne pas vérifier les digests de paquet ou d'en-tête lors de la lecture.
--nofiles
Ne pas vérifier les attributs des fichiers du paquet.
--noscripts
Ne pas exécuter le scriptlet %verifyscript (s'il existe).
--nosignature
Ne pas vérifier les signatures de paquet ou d'en-tête lors de la lecture.
--nolinkto
--nofiledigest (anciennement --nomd5)
--nosize
--nomtime
--nomode
--nordev
Ne pas vérifier l'attribut de fichier correspondant.
--nouser
--nogroup
Ne pas vérifier la propriété utilisateur/groupe des fichiers. Notez que seules les bases de données locales passwd(5) et group(5) sont consultées.
--nocaps
Ne pas vérifier les capacités des fichiers.

Le format de la sortie est une chaîne de 9 caractères, un marqueur d'attribut possible :

**a** %**a**rtifact un fichier effet secondaire de construction (comme les liens buildid).
**c** %**c**onfig fichier de configuration.
**d** %**d**oc fichier de documentation.
**g** %**g**host fichier (c'est-à-dire que le contenu du fichier n'est pas inclus dans la charge utile du paquet).
**l** %**l**icense fichier de licence.
**m** %**m**issingok l'absence de fichier n'est pas un échec de vérification.
**n** %%config(**n**oreplace) (ne pas remplacer le fichier).

OPTIONS FTP/HTTP

rpm peut agir comme client FTP et/ou HTTP afin que les paquets puissent être interrogés ou installés depuis Internet. Les fichiers de paquet pour les opérations d'installation, de mise à niveau et de requête peuvent être spécifiés sous forme d'URL de type ftp ou http :

http://HOST[:PORT]/chemin/vers/paquet.rpm

ftp://[UTILISATEUR:MOTDEPASSE]@HOTE[:PORT]/chemin/vers/paquet.rpm

Si l'utilisateur et le mot de passe sont omis, le mode anonyme ftp est utilisé.

rpm autorise les options suivantes à être utilisées avec les URL ftp :

rpm autorise les options suivantes à être utilisées avec les URL http et ftp :

--httpproxy HOTE
L'hôte HOTE sera utilisé comme serveur proxy pour tous les transferts http et ftp. Cette option peut également être spécifiée en configurant la macro %_httpproxy.
--httpport PORT
Le numéro de port TCP PORT à utiliser pour la connexion http sur le serveur proxy http au lieu du port par défaut. Cette option peut également être spécifiée en configurant la macro %_httpport.

FICHIERS

Configuration rpmrc

Chaque fichier dans le chemin rpmrc séparé par des deux-points est lu séquentiellement par rpm pour obtenir des informations de configuration. Seul le premier fichier de la liste doit exister, et les tildes seront étendus à la valeur de $HOME. Le chemin rpmrc par défaut est le suivant :

/usr/lib/rpm/rpmrc:
/usr/lib/rpm/<vendor>/rpmrc:
/etc/rpmrc:
~/.config/rpm/rpmrc

Si la variable d'environnement XDG_CONFIG_HOME est définie, elle remplace ~/.config dans le chemin.

Dans les anciennes versions de rpm, le chemin du fichier rpmrc par utilisateur était ~/.rpmrc. Celui-ci est toujours traité s'il existe et si le nouveau répertoire de configuration n'existe pas.

Configuration des macros

Chaque fichier ou motif de glob(7) dans le chemin des macros séparé par des deux-points est lu séquentiellement par rpm pour les définitions de macros. Les tildes seront étendus à la valeur de la variable d'environnement HOME. Le chemin des macros par défaut est le suivant :

/usr/lib/rpm/macros:
/usr/lib/rpm/macros.d/macros.*:
/usr/lib/rpm/platform/%{_target}/macros:
/usr/lib/rpm/fileattrs/*.attr:
/usr/lib/rpm/<vendor>/macros:
/etc/rpm/macros.*:
/etc/rpm/macros:
/etc/rpm/%{_target}/macros:
~/.config/rpm/macros

Si la variable d'environnement XDG_CONFIG_HOME est définie, elle remplace ~/.config dans le chemin.

Dans les anciennes versions de rpm, le chemin des macros par utilisateur était ~/.rpmmacros. Celui-ci est toujours traité s'il existe et si le nouveau répertoire de configuration n'existe pas.
