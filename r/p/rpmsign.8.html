NOM

rpmsign - Signature de paquets RPM

SYNTAXE

SIGNER DES PAQUETS :

rpmsign --addsign|--resign [options-rpmsign] FICHIER_PAQUET ...

rpmsign --delsign FICHIER_PAQUET ...

rpmsign --delfilesign FICHIER_PAQUET ...

options-rpmsign

[--rpmv3] [--fskpath CLÉ] [--signfiles]

DESCRIPTION

Les deux options --addsign et --resign génèrent et insèrent de nouvelles signatures pour chaque paquet FICHIER_PAQUET fourni, remplaçant toute signature existante. Il existe deux options pour des raisons historiques, il n'y a actuellement aucune différence de comportement.

Pour créer une signature, rpmsign a besoin de vérifier la somme de contrôle du paquet. En conséquence, les paquets avec des sommes de contrôle MD5/SHA1 ne peuvent pas être signés en mode FIPS.

rpmsign --delsign FICHIER_PAQUET ...

Supprime toutes les signatures de chaque paquet FICHIER_PAQUET fourni.

rpmsign --delfilesign FICHIER_PAQUET ...

Supprime toutes les signatures de fichiers IMA et fsverity de chaque paquet FICHIER_PAQUET fourni.

OPTIONS DE SIGNATURE

--rpmv3
Force l'ajout de signatures d'en-tête/charge utile RPM V3. Celles-ci constituent un surcoût coûteux et redondant pour les paquets où un résumé de charge utile séparé existe (paquets construits avec rpm >= 4.14). Rpmsign détectera automatiquement la nécessité de signatures V3, mais cette option peut être utilisée pour forcer leur création si les paquets doivent être entièrement vérifiables par signature avec rpm < 4.14 ou pour d'autres raisons d'interopérabilité.
--fskpath CLÉ
Utilisé avec --signfiles, utilise la clé de signature de fichier CLÉ.
--certpath CERT
Utilisé avec --signverity, utilise le certificat de signature de fichier CERT.
--verityalgo ALG
Utilisé avec --signverity, pour spécifier l'algorithme de signature. sha256 et sha512 sont supportés, sha256 étant la valeur par défaut si cet argument n'est pas spécifié. Ceci peut aussi être spécifié avec la macro %_verity_algorithm.
--signfiles
Signe les fichiers du paquet. La macro %_binary_filedigest_algorithm doit être définie sur un algorithme supporté avant la construction du paquet. Les algorithmes supportés sont SHA1, SHA256, SHA384 et SHA512, représentés par 2, 8, 9 et 10 respectivement. La clé de signature de fichier (clé privée RSA) doit être définie avant la signature du paquet, elle peut être configurée sur la ligne de commande avec --fskpath ou la macro %_file_signing_key.
--signverity
Signe les fichiers du paquet avec des signatures fsverity. La clé de signature de fichier (clé privée RSA) et le certificat de signature doivent être définis avant la signature du paquet. La clé peut être configurée sur la ligne de commande avec --fskpath ou la macro %_file_signing_key, et le certificat peut être configuré sur la ligne de commande avec --certpath ou la macro %_file_signing_cert.

CONFIGURATION DES CLÉS DE SIGNATURE

Pour pouvoir signer des paquets, vous devez créer votre propre paire de clés publique et secrète (voir le manuel GnuPG). De plus, rpm(8) doit être configuré pour trouver GnuPG et les clés appropriées avec les macros suivantes :

%_gpg_name
Le nom de l'"utilisateur" dont la clé vous souhaitez utiliser pour signer vos paquets. Généralement, c'est la seule configuration nécessaire.
%_gpg_path
L'emplacement de votre trousseau de clés GnuPG si ce n'est pas le $GNUPGHOME par défaut.
%__gpg
Le chemin vers l'exécutable GnuPG. Normalement pré-configuré.

Par exemple, pour pouvoir utiliser GnuPG pour signer des paquets en tant qu'utilisateur "John Doe <jdoe@foo.com>" depuis les trousseaux de clés situés dans /etc/rpm/.gpg en utilisant l'exécutable /opt/bin/gpg, vous incluriez

%_gpg_path /etc/rpm/.gpg
%_gpg_name John Doe <jdoe@foo.com>
%__gpg /opt/bin/gpg

dans un fichier de configuration de macros, typiquement ~/.config/rpm/macros. Voir Configuration des macros dans rpm(8) pour plus de détails.
