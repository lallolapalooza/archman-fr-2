rpmatch(3) Manuel des fonctions de bibliothèque rpmatch(3)

NOM

rpmatch - déterminer si la réponse à une question est affirmative ou négative

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdlib.h>
int rpmatch(const char *response);
Exigences relatives aux macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

rpmatch():

    Depuis glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 et antérieur:
        _SVID_SOURCE

DESCRIPTION

rpmatch() gère une réponse utilisateur aux questions oui ou non, avec prise en charge de l'internationalisation.

response doit être une chaîne terminée par un caractère nul contenant une réponse fournie par l'utilisateur, éventuellement obtenue avec fgets(3) ou getline(3).

La préférence linguistique de l'utilisateur est prise en compte selon les variables d'environnement LANG, LC_MESSAGES et LC_ALL, si le programme a appelé setlocale(3) pour appliquer leurs modifications.

Indépendamment de la locale, les réponses correspondant à ^[Yy] sont toujours acceptées comme affirmatives, et celles correspondant à ^[Nn] sont toujours acceptées comme négatives.

VALEUR DE RETOUR

Après avoir examiné response, rpmatch() renvoie 0 pour une réponse négative reconnue ("non"), 1 pour une réponse positive reconnue ("oui"), et -1 lorsque la valeur de response n'est pas reconnue.

ERREURS

Une valeur de retour de -1 peut indiquer soit une entrée invalide, soit une autre erreur. Il est incorrect de vérifier uniquement si la valeur de retour est non nulle.

rpmatch() peut échouer pour l'une des raisons pour lesquelles regcomp(3) ou regexec(3) peuvent échouer ; l'erreur n'est pas disponible depuis errno ou ailleurs, mais indique un échec du moteur regex (mais ce cas est indiscernable de celui d'une valeur de response non reconnue).

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
rpmatch () Sécurité des threads MT-Safe locale

NORMES

Aucune.

HISTORIQUE

GNU, FreeBSD, AIX.

BOGUES

Le YESEXPR et le NOEXPR de certaines locales (y compris "C") n'inspectent que le premier caractère de la response. Cela peut signifier que "yno" et al. se résolvent en 1. C'est un effet secondaire historique malheureux qui devrait être corrigé avec une localisation appropriée, et ne devrait pas dissuader d'utiliser rpmatch() comme méthode appropriée pour distinguer les réponses binaires.

EXEMPLES

Le programme suivant affiche les résultats lorsque rpmatch() est appliqué à la chaîne donnée dans l'argument de ligne de commande du programme.

#define _DEFAULT_SOURCE
#include <locale.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    if (argc != 2 || strcmp(argv[1], "--help") == 0) {
        fprintf(stderr, "%s response\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    setlocale(LC_ALL, "");
    printf("rpmatch() renvoie : %d\n", rpmatch(argv[1]));
    exit(EXIT_SUCCESS);
}

VOIR AUSSI

fgets(3), getline(3), nl_langinfo(3), regcomp(3), setlocale(3)
