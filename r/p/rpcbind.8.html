NOM

rpcbind — traducteur d'adresses universelles en numéros de programmes RPC

SYNTAXE

rpcbind [-adfhilsvw]

DESCRIPTION

L'utilitaire rpcbind est un serveur qui convertit les numéros de programmes RPC en adresses universelles. Il doit être en cours d'exécution sur l'hôte pour pouvoir effectuer des appels RPC vers un serveur sur cette machine.

Lorsqu'un service RPC est démarré, il indique à rpcbind l'adresse à laquelle il écoute, ainsi que les numéros de programmes RPC qu'il est prêt à servir. Lorsqu'un client souhaite effectuer un appel RPC vers un numéro de programme donné, il contacte d'abord rpcbind sur la machine serveur pour déterminer l'adresse à laquelle les requêtes RPC doivent être envoyées.

L'utilitaire rpcbind doit être démarré avant tout autre service RPC. Normalement, les serveurs RPC standard sont démarrés par des moniteurs de ports, donc rpcbind doit être démarré avant que les moniteurs de ports ne soient invoqués.

Lorsque rpcbind est démarré, il vérifie que certains appels de traduction nom-adresse fonctionnent correctement. S'ils échouent, les bases de données de configuration réseau peuvent être corrompues. Comme les services RPC ne peuvent pas fonctionner correctement dans cette situation, rpcbind signale la condition et se termine.

L'utilitaire rpcbind ne peut être démarré que par le super-utilisateur.

OPTIONS

-a
En mode débogage (-d), provoque une interruption en cas d'erreur.
-d
Exécuter en mode débogage. Dans ce mode, rpcbind enregistre des informations supplémentaires pendant son fonctionnement et s'interrompt en cas de certaines erreurs si -a est également spécifié. Avec cette option, les vérifications de cohérence de la traduction nom-adresse sont affichées en détail.
-f
Ne pas créer de processus fils et devenir un processus d'arrière-plan.
-h
Spécifier les adresses IP spécifiques auxquelles se lier pour les requêtes UDP. Cette option peut être spécifiée plusieurs fois et permet de restreindre les interfaces auxquelles rpcbind répondra. Lors de la spécification d'adresses IP avec -h, rpcbind ajoutera automatiquement 127.0.0.1 et, si IPv6 est activé, ::1 à la liste. Si aucune option -h n'est spécifiée, rpcbind se liera à INADDR_ANY, ce qui peut entraîner des problèmes sur un hôte multi-homed car rpcbind renverra un paquet UDP provenant d'une adresse IP différente de celle à laquelle il a été envoyé. Notez que lorsque rpcbind est contrôlé via l'activation de socket de systemd, l'option -h est ignorée. Dans ce cas, vous devez modifier les définitions ListenStream et ListenDgram dans /usr/lib/systemd/system/rpcbind.socket à la place.
-i
Mode « non sécurisé ». Autoriser les appels à SET et UNSET depuis n'importe quel hôte. Normalement, rpcbind accepte ces requêtes uniquement depuis l'interface de bouclage pour des raisons de sécurité. Cette modification est nécessaire pour les programmes qui ont été compilés avec des versions antérieures de la bibliothèque rpc et qui n'effectuent pas ces requêtes via l'interface de bouclage.
-l
Activer la journalisation des connexions libwrap.
-s
Demander à rpcbind de changer pour l'utilisateur daemon dès que possible. Cela permet à rpcbind d'utiliser des ports non privilégiés pour les connexions sortantes, empêchant ainsi les clients non privilégiés d'utiliser rpcbind pour se connecter à des services depuis un port privilégié.
-v
Afficher la version de rpcbind et la configuration intégrée, puis quitter.
-w
Demander à rpcbind d'effectuer un démarrage « à chaud » en lisant un fichier d'état au démarrage de rpcbind. Le fichier d'état est créé lorsque rpcbind se termine.

FICHIERS

L'utilitaire rpcbind essaie de charger le fichier de configuration dans l'ordre suivant :

/etc/rpcbind.conf
/etc/default/rpcbind
/etc/sysconfig/rpcbind

NOTES

Tous les serveurs RPC doivent être redémarrés si rpcbind est redémarré.
