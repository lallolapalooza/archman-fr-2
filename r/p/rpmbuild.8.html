NOM

rpmbuild - Construire des paquets RPM

SYNTAXE

CONSTRUCTION DE PAQUETS

rpmbuild {-ba|-bb|-bp|-bf|-bc|-bi|-bl|-bs|-br|-bd} [options-rpmbuild] FICHIER-SPEC ...

rpmbuild {-ra|-rb|-rp|-rf|-rc|-ri|-rl|-rs|-rr|-rd} [options-rpmbuild] PAQUET-SOURCE ...

rpmbuild {-ta|-tb|-tp|-tf|-tc|-ti|-tl|-ts|-tr|-td} [options-rpmbuild] TARBALL ...

rpmbuild {--rebuild|--recompile} PAQUET-SOURCE ...

DIVERS

rpmbuild --showrc

options-rpmbuild

[--buildroot RÉPERTOIRE] [--clean] [--nobuild] [--rmsource] [--rmspec] [--short-circuit] [--build-in-place] [--noprep] [--noclean] [--nocheck] [--rpmfcdebug] [--target PLATEFORME] [--with OPTION] [--without OPTION]

DESCRIPTION

rpmbuild est utilisé pour construire des paquets logiciels binaires et sources. Un paquet consiste en une archive de fichiers et des métadonnées utilisées pour installer et désinstaller les fichiers de l'archive. Les métadonnées incluent des scripts d'aide, des attributs de fichiers et des informations descriptives sur le paquet. Les paquets existent en deux variétés : les paquets binaires, utilisés pour encapsuler le logiciel à installer, et les paquets sources, contenant le code source et la recette nécessaires à la production des paquets binaires.

L'un des modes de base suivants doit être sélectionné : Construire un paquet, Construire un paquet à partir d'une archive tar, Recompiler un paquet, Afficher la configuration.

OPTIONS GÉNÉRALES

Ces options peuvent être utilisées dans tous les différents modes.

-?, --help
Affiche un message d'utilisation plus long que la normale.
--version
Affiche une seule ligne contenant le numéro de version de rpm utilisé.
--quiet
Affiche le moins possible - normalement, seuls les messages d'erreur seront affichés.
-v
Affiche des informations détaillées - normalement, les messages de progression routinière seront affichés.
-vv
Affiche beaucoup d'informations de débogage peu claires.
--rpmfcdebug
Permet de déboguer la génération des dépendances.
--rcfile LISTE-FICHIERS
Remplace la liste par défaut des fichiers de configuration à lire par LISTE-FICHIERS. Voir Configuration rpmrc dans rpm(8) pour les détails.
--load FICHIER
Charge un fichier de macros individuel.
--macros LISTE-FICHIERS
Remplace la liste des fichiers de macros à charger par LISTE-FICHIERS. Voir Configuration des macros dans rpm(8) pour les détails.
--pipe COMMANDE
Passe la sortie de rpm à la commande COMMANDE.
--dbpath RÉPERTOIRE
Utilise la base de données dans RÉPERTOIRE au lieu du chemin par défaut /var/lib/rpm.
--root RÉPERTOIRE
Utilise l'arborescence du système de fichiers racine à RÉPERTOIRE pour toutes les opérations. Notez que cela signifie que la base de données dans RÉPERTOIRE sera utilisée pour les vérifications de dépendances et que tout scriptlet (par exemple, %post lors de l'installation, ou %prep lors de la construction d'un paquet) sera exécuté après un chroot(2) vers RÉPERTOIRE.
-D, --define='MACRO EXPR'
Définit MACRO avec la valeur EXPR.
--scm=SCM
Sélectionne le SCM à utiliser avec %autosetup, si aucun n'est défini dans le fichier spec. Notez que toutes les valeurs de SCM, par exemple patch (par défaut) et gendiff, git, ou quilt, ne fonctionnent pas de manière interchangeable avec toutes les autres corrections et options indiquées sur la ligne %autosetup, en particulier l'option -pN.

OPTIONS DE CONSTRUCTION

La forme générale d'une commande de construction rpm(8) est

rpmbuild {-bÉTAPE|-rÉTAPE|-tÉTAPE} [options-rpmbuild] FICHIER ...

L'argument utilisé est -b si un fichier spec est utilisé pour construire le paquet, -r si un paquet source doit être reconstruit et -t si rpmbuild doit rechercher à l'intérieur d'un fichier tar (éventuellement compressé) le fichier spec à utiliser.

Les paquets sont construits en plusieurs étapes. Les six premières correspondent aux sections suivantes d'un fichier spec : %prep, %generate_buildrequires, %build, %install, %check et %clean. Enfin, les paquets binaires et sources sont créés lors d'une étape d'assemblage.

Le caractère ÉTAPE spécifie l'étape à terminer (après avoir effectué toutes les étapes qui la précèdent), et est l'un des suivants :

-ba
Effectue une construction complète - exécute jusqu'à l'étape d'assemblage incluse. Dans la plupart des cas, c'est l'option à choisir.
-bb
Construit uniquement les paquets binaires - exécute jusqu'à l'étape d'assemblage incluse, mais sans créer le paquet source. En cas de succès, le répertoire de construction est supprimé (comme avec --clean).
-bp
Désarchive les sources et applique les correctifs - exécute uniquement l'étape %prep.
-bf
Configure les sources - exécute jusqu'à l'étape %conf incluse. Cela implique généralement l'équivalent d'un "./configure".
-bc
Compile les sources - exécute jusqu'à l'étape %build incluse. Cela implique généralement l'équivalent d'un "make".
-bi
Installe les binaires dans la racine de construction - exécute jusqu'à l'étape %check incluse. Cela implique généralement l'équivalent d'un "make install" et d'un "make check".
-bl
Effectue une "vérification de liste" - la section %files du fichier spec est développée par macro, et des vérifications sont effectuées pour s'assurer que chaque fichier existe.
-bs
Construit uniquement le paquet source - saute directement à l'étape d'assemblage, sans exécuter aucune des étapes précédentes ni créer de paquets binaires.
-br
Construit uniquement le paquet source, mais analyse et inclut également les dépendances de construction dynamiques - exécute jusqu'à l'étape %generate_buildrequires incluse, puis saute directement à l'étape d'assemblage, sans créer de paquets binaires. Cette commande peut être utilisée pour résoudre entièrement les dépendances de construction dynamiques. Voir la section DÉPENDANCES DE CONSTRUCTION DYNAMIQUES pour plus de détails.
-bd
Vérifie les dépendances de construction dynamiques et construit le paquet .buildreqs.nosrc.rpm s'il en manque. Ne construit rien d'autre.

NAME

rpmbuild - create RPMs from sources

SYNOPSIS

rpmbuild [OPTIONS] SPECFILE ...

DESCRIPTION

rpmbuild is used to build binary package files from a source package and a SPECFILE.

-b, --build STAGE
Build package for specified stage(s). STAGE can be a number or a letter corresponding to the build stages:
0
--all
Perform all build stages.
1
--clean
Remove the build tree after the packages are made.
2
--prep
Prepare the sources (unpack and patch).
3
--build
Compile the package.
4
--install
Install the package.
5
--test
Test the installed package.
6
--rpm
Build the binary RPM package.
For example, -bb will build the package and then build the binary RPM. -ba will build both binary and source RPMs.
--clean-build
Remove the build tree *before* starting the build.
--nobuild
Do not execute any build stages. Useful for testing out spec files.
--noprep
Do not execute %prep build stage even if present in spec.
--noclean
Do not execute %clean build stage even if present in spec.
--nocheck
Do not execute %check build stage even if present in spec.
--nodebuginfo
Do not generate debuginfo packages.
--nodeps
Do not verify build dependencies.
--rmsource
Remove the sources after the build (may also be used standalone, e.g. "rpmbuild --rmsource foo.spec").
--rmspec
Remove the spec file after the build (may also be used standalone, e.g. "rpmbuild --rmspec foo.spec").
--short-circuit
Skip straight to specified stage (i.e., skip all stages leading up to the specified stage). Only valid with -bc, -bi, and -bb. Useful for local testing only. Packages built this way will be marked with an unsatisfiable dependency to prevent their accidental use.
--build-in-place
Build from locally checked out sources in the current working directory. The build tree is set up as if %setup was used, but %builddir/*%buildsubdir* points back to the current working directory. %prep is skipped entirely.
--target PLATFORM
When building the package, interpret PLATFORM as arch-vendor-os and set the macros %_target, %_target_cpu, and %_target_os accordingly.
--with OPTION
Enable configure OPTION for build.
--without OPTION
Disable configure OPTION for build.

REBUILD AND RECOMPILE OPTIONS

There are two other ways to invoke building with rpm(8):

rpmbuild --rebuild|--recompile SOURCEPKG ...

When invoked this way, rpmbuild installs the named source package, and does a prep, compile and install. In addition, --rebuild builds a new binary package. When the build has completed, the build directory is removed (as in --clean) and the the sources and spec file for the package are removed.

These options are now superseded by the -r* options which allow much more fine control over what stages of the build to run.

DYNAMIC BUILD DEPENDENCIES

When the %generate_buildrequires stage runs and some of the newly generated BuildRequires are not satisfied, rpmbuild creates an intermediate source package ending in buildreqs.nosrc.rpm, which has the new BuildRequires, and exits with code 11. This package can then be used in place of the original source package to resolve and install the missing build dependencies in the usual way, such as with dnf-builddep(8).

Multiple layers of dynamic build dependencies may exist in a spec file; the presence of specific BuildRequires on the system may yield new BuildRequires next time a build is performed with the same source package. The easiest way to ensure that all dynamic build dependencies are satisfied is to run the -br option, install the new dependencies of the buildreqs.nosrc.rpm package and repeat the whole procedure until rpmbuild no longer exits with code 11.

If the -br command is coupled with --nodeps, exit code 11 is always returned and a buildreqs.nosrc.rpm package is always created.

SHOWRC

The command

rpmbuild --showrc

shows the values rpmbuild will use for all of the options are currently set in rpmrc and macros configuration file(s).
