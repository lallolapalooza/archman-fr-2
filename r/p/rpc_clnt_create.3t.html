DESCRIPTION

Les routines de bibliothèque RPC permettent aux programmes en langage C d'effectuer des appels de procédure sur d'autres machines sur le réseau. Un descripteur CLIENT est d'abord créé, puis le client appelle une procédure pour envoyer une requête au serveur. À la réception de la requête, le serveur appelle une routine de dispatch pour effectuer le service demandé, puis renvoie une réponse.

Routines

clnt_control()
Une macro de fonction pour modifier ou récupérer diverses informations sur un objet client. L'argument req indique le type d'opération, et info est un pointeur vers les informations. Pour les transports sans connexion et orientés connexion, les valeurs prises en charge de req et leurs types d'arguments ainsi que leur fonction sont :
CLSET_TIMEOUT struct timeval * définir le délai d'attente total
CLGET_TIMEOUT struct timeval * obtenir le délai d'attente total

Note : si vous définissez le délai d'attente en utilisant clnt_control(), l'argument de délai d'attente passé par clnt_call() est ignoré dans tous les appels ultérieurs.

Note : Si vous définissez la valeur du délai d'attente à 0, clnt_control() renvoie immédiatement une erreur (RPC_TIMEDOUT). Définissez l'argument de délai d'attente à 0 pour le traitement par lots des appels.

CLGET_SVC_ADDR struct netbuf * obtenir l'adresse du serveur
CLGET_FD int * obtenir le fd du descripteur
CLSET_FD_CLOSE void fermer le descripteur de fichier à la destruction
CLSET_FD_NCLOSE void ne pas fermer le descripteur de fichier à la destruction
CLGET_VERS u_int32_t * obtenir la version du programme RPC
CLSET_VERS u_int32_t * définir la version du programme RPC
CLGET_XID u_int32_t * obtenir le XID de l'appel précédent
CLSET_XID u_int32_t * définir le XID de l'appel suivant

Les opérations suivantes sont valides uniquement pour les transporteurs sans connexion :

CLSET_RETRY_TIMEOUT struct timeval * définir le délai de nouvelle tentative
CLGET_RETRY_TIMEOUT struct timeval * obtenir le délai de nouvelle tentative
CLSET_CONNECT int * utiliser connect(2)

Le délai de nouvelle tentative est le temps pendant lequel RPC attend une réponse du serveur avant de retransmettre la requête. La fonction clnt_control() renvoie TRUE en cas de succès et FALSE en cas d'échec.

clnt_create()
Routine générique de création de client pour le programme prognum et la version versnum. L'argument host identifie le nom de l'hôte distant où se trouve le serveur. L'argument nettype indique la classe de protocole de transport à utiliser. Les transporteurs sont essayés dans l'ordre de gauche à droite dans la variable d'environnement NETPATH ou dans l'ordre de haut en bas dans la base de données netconfig. La fonction clnt_create() essaie tous les transporteurs de la classe nettype disponibles à partir de la variable d'environnement NETPATH et de la base de données netconfig, et choisit le premier qui réussit. Un délai d'attente par défaut est défini et peut être modifié à l'aide de clnt_control(). Cette routine renvoie NULL si elle échoue. La routine clnt_pcreateerror() peut être utilisée pour imprimer la raison de l'échec.

Remarque : clnt_create() renvoie un handle client valide même si le numéro de version particulier fourni à clnt_create() n'est pas enregistré auprès du service rpcbind(8). Cette divergence sera découverte plus tard par un appel à clnt_call() (voir rpc_clnt_calls(3)).

clnt_create_timed()
Routine générique de création de client qui est similaire à clnt_create() mais qui possède également l'argument supplémentaire timeout qui spécifie la durée maximale autorisée pour chaque classe de transport essayée. À tous autres égards, l'appel à clnt_create_timed() se comporte exactement comme l'appel à clnt_create().
clnt_create_vers()
Routine générique de création de client qui est similaire à clnt_create() mais qui vérifie également la disponibilité de la version. L'argument host identifie le nom de l'hôte distant où se trouve le serveur. L'argument nettype indique la classe de protocoles de transport à utiliser. Si la routine réussit, elle renvoie un handle client créé pour la version la plus élevée entre vers_low et vers_high qui est prise en charge par le serveur. L'argument vers_outp est défini à cette valeur. C'est-à-dire qu'après un retour réussi, vers_low <= *vers_outp <= vers_high. Si aucune version entre vers_low et vers_high n'est prise en charge par le serveur, la routine échoue et renvoie NULL. Un délai d'attente par défaut est défini et peut être modifié à l'aide de clnt_control(). Cette routine renvoie NULL si elle échoue. La routine clnt_pcreateerror() peut être utilisée pour imprimer la raison de l'échec. Remarque : clnt_create() renvoie un handle client valide même si le numéro de version particulier fourni à clnt_create() n'est pas enregistré auprès du service rpcbind(8). Cette divergence sera découverte plus tard par un appel à clnt_call() (voir rpc_clnt_calls(3)). Cependant, clnt_create_vers() fait cela pour vous et ne renvoie un handle valide que si une version dans la plage fournie est prise en charge par le serveur.
clnt_create_vers_timed()
Routine générique de création de client qui est similaire à clnt_create_vers() mais qui possède également l'argument supplémentaire timeout qui spécifie la durée maximale autorisée pour chaque classe de transport essayée. À tous autres égards, l'appel à clnt_create_vers_timed() se comporte exactement comme l'appel à clnt_create_vers().
clnt_destroy()
Macro fonction qui détruit le handle RPC du client. La destruction implique généralement la désallocation des structures de données privées, y compris clnt lui-même. L'utilisation de clnt est indéfinie après l'appel à clnt_destroy(). Si la bibliothèque RPC a ouvert le descripteur de fichier associé, ou si CLSET_FD_CLOSE a été défini à l'aide de clnt_control(), le descripteur de fichier sera fermé. L'appelant doit appeler auth_destroy(clnt->cl_auth) (avant d'appeler clnt_destroy()) pour détruire la structure AUTH associée (voir rpc_clnt_auth(3)).
clnt_dg_create()
Cette routine crée un client RPC pour le programme distant prognum et la version versnum ; le client utilise un transport sans connexion. Le programme distant est situé à l'adresse svcaddr. L'argument fildes est un descripteur de fichier ouvert et lié. Cette routine renverra le message d'appel par intervalles de 15 secondes jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call() (voir clnt_call() dans rpc_clnt_calls(3)). Les périodes de délai de nouvelle tentative et de délai d'expiration total peuvent être modifiées à l'aide de clnt_control(). L'utilisateur peut définir la taille des tampons d'envoi et de réception avec les arguments sendsz et recvsz ; les valeurs 0 choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL si elle échoue.
clnt_pcreateerror()
Imprime un message sur l'erreur standard indiquant pourquoi un handle RPC client n'a pas pu être créé. Le message est précédé de la chaîne s et d'un deux-points, et suivi d'un saut de ligne.
clnt_spcreateerror()
Comme clnt_pcreateerror(), sauf qu'elle renvoie une chaîne au lieu d'imprimer sur l'erreur standard. Aucun saut de ligne n'est ajouté au message dans ce cas. Avertissement : renvoie un pointeur vers un tampon qui est écrasé à chaque appel.
clnt_raw_create()
Cette routine crée un handle client RPC pour le programme distant prognum et la version versnum. Le transport utilisé pour passer des messages au service est un tampon au sein de l'espace d'adressage du processus, donc le serveur RPC correspondant doit résider dans le même espace d'adressage ; (voir svc_raw_create() dans rpc_svc_create(3)). Cela permet de simuler RPC et de mesurer les surcoûts RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau ou du réseau. Cette routine renvoie NULL si elle échoue. La fonction clnt_raw_create() doit être appelée après svc_raw_create().
clnt_tli_create()
Cette routine crée un handle client RPC pour le programme distant prognum et la version versnum. Le programme distant est situé à l'adresse svcaddr. Si svcaddr est NULL et qu'il s'agit d'un transport orienté connexion, on suppose que le descripteur de fichier est connecté. Pour les transports sans connexion, si svcaddr est NULL, une erreur RPC_UNKNOWNADDR est définie. L'argument

NAME

clnt_create, clnt_pcreateerror, clnt_spcreateerror, clnt_tli_create, clnt_tp_create, clnt_tp_create_timed, clnt_vc_create — routines to create RPC clients

SYNOPSIS

#include <rpc/rpc.h>
CLIENT *
clnt_create(const char *host, u_long prognum, u_long versnum, const char *nettype);
CLIENT *
clnt_tli_create(const char *host, const char *netconf, const char *nettype, u_long prognum, u_long versnum);
CLIENT *
clnt_tp_create(const char *host, u_long prognum, u_long versnum, const char *netconf);
CLIENT *
clnt_tp_create_timed(const char *host, u_long prognum, u_long versnum, const char *netconf, struct timeval *timeout);
CLIENT *
clnt_vc_create(const char *host, const struct svc_addr *svcaddr, u_long prognum, u_long versnum, u_int flags, const struct netbuf *netconf);
CLIENT *
clnt_create_rdma(const char *host, u_long prognum, u_long versnum, const char *nettype, const struct rdma_addr *rdma_addr);
void
clnt_pcreateerror(const char *s);
void
clnt_spcreateerror(const char *s, char *buf, size_t len);

DESCRIPTION

These routines are used to create RPC client handles. These handles are used for all subsequent communication with an RPC service. An RPC client handle is a structure that holds information about the connection to the RPC service, including the transport protocol, timeouts, and authentication information. By default, all new client handles are created with authentication information set to AUTH_UNSPEC.

The routines differ in how they specify the transport and how they locate the RPC service.

Routines

clnt_create()
Creates an RPC client handle for the program prognum and version versnum on the remote host host. The transport protocol is specified by nettype. The routine consults the remote rpcbind service to determine the address of the remote service. If the creation fails, clnt_pcreateerror() can be used to print the reason for failure.
clnt_tli_create()
Creates an RPC client handle for the program prognum and version versnum on the remote host host. The transport is specified by netconf, which is a pointer to a netconfig structure. The nettype argument specifies the desired transport type (e.g., "udp", "tcp"). If netconf is NULL, the routine consults the remote rpcbind service to determine the address of the remote service. Otherwise, it uses the address specified in netconf. The routine returns NULL if it fails.
clnt_tp_create()
Like clnt_create() except that clnt_tp_create() tries only one transport specified through netconf. The clnt_tp_create() function creates a client handle for the program prognum, the version versnum, and for the transport specified by netconf. Default options are set, which can be changed using clnt_control() calls. The remote rpcbind service on the host host is consulted for the address of the remote service. This routine returns NULL if it fails. The clnt_pcreateerror() routine can be used to print the reason for failure.
clnt_tp_create_timed()
Like clnt_tp_create() except clnt_tp_create_timed() has the extra argument timeout which specifies the maximum time allowed for the creation attempt to succeed. In all other respects, the clnt_tp_create_timed() call behaves exactly like the clnt_tp_create() call.
clnt_vc_create()
This routine creates an RPC client for the remote program prognum and version versnum; the client uses a connection-oriented transport. The remote program is located at address svcaddr. The fildes argument is an open and bound file descriptor. The user may specify the size of the send and receive buffers with the sendsz and recvsz arguments; values of 0 choose suitable defaults. This routine returns NULL if it fails. The address svcaddr should not be NULL and should point to the actual address of the remote program. The clnt_vc_create() function does not consult the remote rpcbind service for this information.
struct rpc_createerr rpc_createerr;
A global variable whose value is set by any RPC client handle creation routine that fails. It is used by the routine clnt_pcreateerror() to print the reason for the failure.

AVAILABILITY

These functions are part of libtirpc.
