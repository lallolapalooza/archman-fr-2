NOM

rpcclient - outil pour exécuter des fonctions MS-RPC côté client

SYNTAXE

rpcclient [-c|--command=COMMANDES] [-I|--dest-ip=IP] [-p|--port=PORT] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=FICHIER_LOG_BASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDRE_RESOLUTION_NOMS] [-O|--socket-options=OPTIONS_SOCKET] [-m|--max-protocol=PROTOCOLE_MAX] [-n|--netbiosname=NOM_NETBIOS] [--netbios-scope=PORTEE] [-W|--workgroup=GROUPE_TRAVAIL] [--realm=DOMAINE] [-U|--user=[DOMAINE/]NOM_UTILISATEUR[%MOT_DE_PASSE]] [-N|--no-pass] [--password=CHAINE] [--pw-nt-hash] [-A|--authentication-file=FICHIER] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desire|requis|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] {CHAINE_LIAISON|HOTE}

DESCRIPTION

Cet outil fait partie de la suite samba(7).

rpcclient est un utilitaire initialement développé pour tester les fonctionnalités MS-RPC dans Samba lui-même. Il a subi plusieurs étapes de développement et de stabilisation. De nombreux administrateurs système ont maintenant écrit des scripts autour de cet outil pour gérer les clients Windows NT depuis leur station de travail UNIX.

OPTIONS

CHAINE_LIAISON|HOTE

Lors de la connexion à un service dcerpc, vous devez spécifier une chaîne de liaison.

Le format est :

TRANSPORT:hote[options]

où TRANSPORT est soit ncacn_np (pipes nommés) pour SMB, soit ncacn_ip_tcp pour DCERPC sur TCP/IP.

« hote » est une adresse IP ou un nom d'hôte ou un nom NetBIOS. Si la chaîne de liaison identifie le côté serveur d'un point d'extrémité, « hote » peut être une chaîne vide. Voir ci-dessous pour plus de détails.

« options » peut inclure un nom de pipe SMB si vous utilisez le transport ncacn_np ou un numéro de port TCP si vous utilisez le transport ncacn_ip_tcp, sinon ils seront déterminés automatiquement.

Exemples :

•ncacn_ip_tcp:samba.example.com[1024]
•ncacn_ip_tcp:samba.example.com[sign,seal,krb5]
•ncacn_ip_tcp:samba.example.com[sign,spnego]
•ncacn_np:samba.example.com
•ncacn_np:samba.example.com[samr]
•ncacn_np:samba.example.com[samr,sign,print]
•ncalrpc:/chemin/vers/socket/unix
•//SAMBA
Les transports pris en charge sont :
•ncacn_np - Connexion utilisant les pipes nommés
•ncacn_ip_tcp - Connexion via TCP/IP
•ncalrpc - Connexion via RPC local (sockets unix)
Les options prises en charge sont :
•sign - Utiliser le niveau d'intégrité d'authentification RPC
•seal - Activer le niveau d'authentification RPC de confidentialité (chiffrement)
•connect - Utiliser le niveau de connexion RPC (authentification, mais sans sign ou seal)
•packet - Utiliser le niveau d'authentification de paquet RPC
•spnego - Utiliser SPNEGO au lieu de l'authentification NTLMSSP
•ntlm - Utiliser NTLM brut au lieu de SPNEGO ou NTLMSSP
•krb5 - Utiliser Kerberos au lieu de l'authentification NTLMSSP
•schannel - Créer une connexion schannel
•smb1 - Utiliser SMB1 pour les pipes nommés
•smb2 - Utiliser SMB2/3 pour les pipes nommés
•validate - Activer le validateur NDR
•print - Activer le débogage des paquets
•padcheck - Vérifier les données de réponse pour des octets de remplissage non nuls
•bigendian - Utiliser le big-endian pour RPC
•ndr64 - Utiliser NDR64 pour RPC

-c|--command=<chaîne de commande>

Exécute les commandes séparées par des points-virgules (listées ci-dessous)

-I|--dest-ip IP

L'adresse IP est l'adresse du serveur à contacter. Elle doit être spécifiée en notation standard « a.b.c.d ».

Normalement, le client tenterait de localiser un serveur SMB/CIFS nommé en le recherchant via le mécanisme de résolution de noms NetBIOS décrit ci-dessus dans le paramètre ordre de résolution des noms. L'utilisation de ce paramètre forcera le client à supposer que le serveur se trouve sur la machine avec l'adresse IP spécifiée et le composant nom NetBIOS de la ressource à laquelle on se connecte sera ignoré.

Il n'y a pas de valeur par défaut pour ce paramètre. S'il n'est pas fourni, il sera déterminé automatiquement par le client comme décrit ci-dessus.

-p|--port port

Ce nombre est le numéro de port TCP qui sera utilisé lors des connexions au serveur. Le numéro de port TCP standard (bien connu) pour un serveur SMB/CIFS est 139, qui est la valeur par défaut.

-?|--help

Imprime un résumé des options de ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier allant de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus le détail sera consigné dans les fichiers journaux sur les activités du serveur. Au niveau 0, seules les erreurs critiques et les avertissements graves seront consignés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne ; il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journal, et ne doivent être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'ÉNORMES quantités de données de journal, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre remplacera le paramètre niveau de journal du fichier /etc/samba/smb.conf.

--debug-stdout

Redirige la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) « <nom> » à la valeur « <valeur> » depuis la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur contient un espace, encadrez l'intégralité de --option=nom=valeur entre guillemets.

-l|--log-basename=répertoire_journal

Nom du répertoire de base pour les fichiers journaux/de débogage. L'extension ".nomprog" sera ajoutée (par exemple, log.smbclient, log.smbd, etc.). Le fichier journal n'est jamais supprimé par le client.

--leak-report

Active le rapport de fuite talloc à la sortie.

--leak-report-full

Active le rapport complet de fuite talloc à la sortie.

-V|--version

Affiche le numéro de version du programme.

-R|--name-resolve=ORDRE_RESOLUTION_NOMS

Cette option est utilisée pour déterminer quels services de nommage et dans quel ordre résoudre les noms d'hôtes en adresses IP. L'option prend une chaîne d'options de résolution de noms séparées par des espaces. Il est préférable d'encadrer l'intégralité de --name-resolve=ORDRE_RESOLUTION_NOMS entre guillemets.

Les options sont : « lmhosts », « host », « wins » et « bcast ». Elles entraînent la résolution des noms comme suit :

•lmhosts : Recherche une adresse IP dans le fichier lmhosts de Samba. Si la ligne dans lmhosts n'a pas de type de nom attaché au nom NetBIOS (voir lmhosts(5) pour plus de détails), alors tout type de nom correspond pour la recherche.
•host : Effectue une résolution standard nom d'hôte vers adresse IP, en utilisant les fichiers /etc/hosts du système, NIS ou les recherches DNS. Cette méthode de résolution de noms dépend du système d'exploitation, par exemple sur IRIX ou Solaris, elle peut être contrôlée par le fichier /etc/
(fichier nsswitch.conf). Notez que cette méthode n'est utilisée que si le type de nom NetBIOS interrogé est le type de nom 0x20 (serveur), sinon il est ignoré.
•wins: Interroger un nom avec l'adresse IP listée dans le paramètre wins server. Si aucun serveur WINS n'a été spécifié, cette méthode sera ignorée.
•bcast: Diffuser sur chacune des interfaces locales connues listées dans le paramètre interfaces. C'est la méthode de résolution de noms la moins fiable car elle dépend du fait que l'hôte cible soit sur un sous-réseau connecté localement.
Si ce paramètre n'est pas défini, l'ordre de résolution des noms défini dans le paramètre (name resolve order) du fichier /etc/samba/smb.conf sera utilisé.

L'ordre par défaut est lmhosts, host, wins, bcast. Sans ce paramètre ou sans aucune entrée dans le paramètre name resolve order du fichier /etc/samba/smb.conf, les méthodes de résolution de noms seront tentées dans cet ordre.

-O|--socket-options=SOCKETOPTIONS

Options de socket TCP à définir sur le socket client. Voir le paramètre des options de socket dans la page de manuel /etc/samba/smb.conf pour la liste des options valides.

-m|--max-protocol=MAXPROTOCOL

La valeur du paramètre (une chaîne) est le niveau de protocole le plus élevé qui sera pris en charge par le client.

Notez que la spécification de ce paramètre ici remplacera le paramètre client max protocol dans le fichier /etc/samba/smb.conf.

-n|--netbiosname=NETBIOSNAME

Cette option permet de remplacer le nom NetBIOS que Samba utilise pour lui-même. Ceci est identique à la définition du paramètre netbios name dans le fichier /etc/samba/smb.conf. Cependant, un réglage en ligne de commande aura la priorité sur les réglages dans /etc/samba/smb.conf.

--netbios-scope=SCOPE

Ceci spécifie une portée NetBIOS que nmblookup utilisera pour communiquer lors de la génération de noms NetBIOS. Pour plus de détails sur l'utilisation des portées NetBIOS, voir rfc1001.txt et rfc1002.txt. Les portées NetBIOS sont *très* rarement utilisées, ne définissez ce paramètre que si vous êtes l'administrateur système en charge de tous les systèmes NetBIOS avec lesquels vous communiquez.

-W|--workgroup=WORKGROUP

Définit le domaine SMB du nom d'utilisateur. Ceci remplace le domaine par défaut qui est le domaine défini dans smb.conf. Si le domaine spécifié est le même que le nom NetBIOS du serveur, le client se connectera en utilisant le SAM local du serveur (par opposition au SAM du domaine).

Notez que la spécification de ce paramètre ici remplacera le paramètre workgroup dans le fichier /etc/samba/smb.conf.

-r|--realm=REALM

Définit le royaume pour le domaine.

Notez que la spécification de ce paramètre ici remplacera le paramètre realm dans le fichier /etc/samba/smb.conf.

-U|--user=[DOMAIN\]USERNAME[%PASSWORD]

Définit le nom d'utilisateur SMB ou le nom d'utilisateur et le mot de passe.

Si %PASSWORD n'est pas spécifié, l'utilisateur sera invité. Le client vérifiera d'abord la variable d'environnement USER (qui est également autorisée à contenir le mot de passe séparé par un %), puis la variable LOGNAME (qui n'est pas autorisée à contenir un mot de passe) et si l'un d'eux existe, la valeur sera utilisée. Si ces variables d'environnement ne sont pas trouvées, le nom d'utilisateur trouvé dans un cache d'identification Kerberos peut être utilisé.

Une troisième option consiste à utiliser un fichier d'identification contenant le mot de passe en clair du nom d'utilisateur et du mot de passe. Cette option est principalement fournie pour les scripts où l'administrateur ne souhaite pas passer les identifiants en ligne de commande ou via des variables d'environnement. Si cette méthode est utilisée, assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables. Voir le -A pour plus de détails.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou lorsque vous transmettez des valeurs fournies par l'utilisateur en ligne de commande. Par mesure de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Bien que Samba tente de supprimer le mot de passe du titre du processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une condition de concurrence.

-N|--no-pass

Si spécifié, ce paramètre supprime l'invite de mot de passe normale du client à l'utilisateur. Ceci est utile lors de l'accès à un service qui ne nécessite pas de mot de passe.

À moins qu'un mot de passe ne soit spécifié en ligne de commande ou que ce paramètre ne soit spécifié, le client demandera un mot de passe.

Si un mot de passe est spécifié en ligne de commande et que cette option est également définie, le mot de passe en ligne de commande sera silencieusement ignoré et aucun mot de passe ne sera utilisé.

--password

Spécifie le mot de passe en ligne de commande.

Soyez prudent lorsque vous incluez des mots de passe dans des scripts ou lorsque vous transmettez des valeurs fournies par l'utilisateur en ligne de commande. Par mesure de sécurité, il est préférable de laisser l'outil client Samba demander le mot de passe si nécessaire, ou d'obtenir le mot de passe une fois avec kinit.

Si --password n'est pas spécifié, l'outil vérifiera la variable d'environnement PASSWD, suivie de PASSWD_FD qui est censée contenir un numéro de descripteur de fichier (FD) ouvert.

Enfin, il vérifiera PASSWD_FILE (contenant un chemin de fichier à ouvrir). Le fichier ne doit contenir que le mot de passe. Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

Bien que Samba tente de supprimer le mot de passe du titre du processus (comme vu dans ps), cela se produit après le démarrage et est donc sujet à une condition de concurrence.

--pw-nt-hash

Le mot de passe fourni est le hachage NT.

-A|--authentication-file=filename

Cette option permet de spécifier un fichier à partir duquel lire le nom d'utilisateur et le mot de passe utilisés dans la connexion. Le format du fichier est le suivant : 
username = <value>
password = <value>
domain   = <value>

Assurez-vous que les permissions du fichier restreignent l'accès aux utilisateurs indésirables !

-P|--machine-pass

Utiliser le mot de passe du compte machine stocké.

--simple-bind-dn=DN

DN à utiliser pour une liaison simple.

--use-kerberos=desired|required|off

Ce paramètre détermine si les outils client Samba tenteront de s'authentifier via Kerberos. Pour l'authentification Kerberos, vous devez utiliser des noms DNS au lieu d'adresses IP lors de la connexion à un service. Par défaut, les outils client Samba tenteront d'utiliser le cache d'identification Kerberos par défaut (ccache). Si le ccache n'existe pas ou si l'option -U|--user a été spécifiée, les clients demanderont un mot de passe et obtiendront un ticket Kerberos (kinit) pour vous. Si vous souhaitez utiliser un cache d'identification Kerberos alternatif, utilisez l'option --use-krb5-ccache.

Notez que la spécification de ce paramètre ici remplacera le paramètre client use kerberos dans le fichier /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Spécifie l'emplacement du cache d'identification pour l'authentification Kerberos.

Ceci forcera --use-kerberos=required.

--use-winbind-ccache

Essayer d'utiliser le cache d'identification par winbind.

--client-protection=sign|encrypt|off

Définit la protection de connexion que l'outil client doit utiliser.

Notez que la spécification de ce paramètre ici remplacera le paramètre client protection dans le fichier /etc/samba/smb.conf.

Si vous avez besoin d'un contrôle plus granulaire, vous pouvez utiliser : --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

SPOOLSS

adddriver <arch> <config> [<version>]

Exécute un RPC AddPrinterDriver() pour installer les informations du pilote d'impression sur le serveur. Notez que les fichiers du pilote doivent déjà exister dans le répertoire renvoyé par getdriverdir. Les valeurs possibles pour arch sont les mêmes que celles de la commande getdriverdir. Le paramètre config est défini comme suit : 
Nom Long du Pilote:\
Nom du Fichier Pilote:\
Nom du Fichier Données:\
Nom du Fichier Configuration:\
Nom du Fichier Aide:\
Nom du Moniteur Langue:\
Type de Données par Défaut:\
Liste des Fichiers séparés par des virgules

Tout champ vide doit être saisi comme la chaîne "NULL".

Samba n'a pas besoin de prendre en charge le concept de moniteurs d'impression car ceux-ci s'appliquent uniquement aux imprimantes locales dont le pilote peut utiliser un lien bidirectionnel pour la communication. Ce champ doit être "NULL". Sur un serveur d'impression NT distant, le moniteur d'impression d'un pilote doit être installé avant d'ajouter le pilote, sinon le RPC échouera.

Le paramètre version vous permet de spécifier le numéro de version du pilote d'impression. S'il est omis, la version par défaut du pilote pour l'architecture spécifiée sera utilisée. Cette option peut être utilisée pour télécharger les pilotes d'impression Windows 2000 (version 3).

addprinter <nomimprimante> <nompartage> <nompilote> <port>

Ajoute une imprimante sur le serveur distant. Cette imprimante sera automatiquement partagée. Soyez conscient que le pilote d'impression doit déjà être installé sur le serveur (voir adddriver) et que le port doit être un nom de port valide (voir enumports.

deldriver <pilote>

Supprime le pilote d'impression spécifié pour toutes les architectures. Cela ne supprime pas les fichiers du pilote réels du serveur, seulement l'entrée de la liste des pilotes du serveur.

deldriverex <pilote> [architecture] [version] [indicateurs]

Supprime le pilote d'impression spécifié et éventuellement les fichiers associés au pilote. Vous pouvez limiter cette action à une architecture spécifique et à une version spécifique. Si aucune architecture n'est donnée, tous les fichiers du pilote de ce pilote seront supprimés. Les indicateurs correspondent aux valeurs numériques DPD_*, c'est-à-dire qu'une valeur de 3 demande (DPD_DELETE_UNUSED_FILES | DPD_DELETE_SPECIFIC_VERSION).

BOGUES

rpcclient est conçu comme un outil de test pour développeurs et peut ne pas être robuste dans certaines zones (comme l'analyse des arguments de ligne de commande). Il a été connu pour générer un vidage central lors d'échecs lorsque des paramètres invalides étaient passés à l'interpréteur.

ATTENTION ! Le protocole MSRPC

BUGS

Le code SMB RPC (MSRPC) a été développé à partir de l'examen des traces réseau. Aucune documentation n'est disponible auprès des créateurs originaux (Microsoft) sur le fonctionnement de MSRPC sur SMB, ni sur le fonctionnement des services MSRPC individuels. L'implémentation de ces services par Microsoft s'est avérée (et a été rapportée) être... un peu instable par endroits.

Le développement de l'implémentation de Samba est également un peu brut, et à mesure que de plus en plus de services sont compris, cela peut même entraîner des versions de smbd(8) et rpcclient(1) incompatibles pour certaines commandes ou certains services. De plus, les développeurs envoient des rapports à Microsoft, et les problèmes rencontrés ou signalés à Microsoft sont corrigés dans les Service Packs, ce qui peut entraîner des incompatibilités.
