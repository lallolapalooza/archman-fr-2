RPC_SVC_REG(3) Manuel des fonctions de bibliothèque RPC_SVC_REG(3)

NOM

rpc_svc_reg, rpc_reg, svc_reg, svc_unreg, svc_auth_reg, xprt_register, xprt_unregister — routines de bibliothèque pour l'enregistrement de serveurs

SYNTAXE

#include <rpc/rpc.h>

int
rpc_reg(rpcprog_t prognum, rpcvers_t versnum, rpcproc_t procnum, char *(*procname)(), xdrproc_t inproc, xdrproc_t outproc, char *nettype);

bool_t
svc_reg(SVCXPRT *xprt, const rpcprog_t prognum, const rpcvers_t versnum, void (*dispatch)(struct svc_req *, SVCXPRT *), const struct netconfig *netconf);

void
svc_unreg(const rpcprog_t prognum, const rpcvers_t versnum);

int
svc_auth_reg(int cred_flavor, enum auth_stat (*handler)(struct svc_req *, struct rpc_msg *));

void
xprt_register(SVCXPRT *xprt);

void
xprt_unregister(SVCXPRT *xprt);

DESCRIPTION

Ces routines font partie de la bibliothèque RPC qui permet aux serveurs RPC de s'enregistrer auprès de rpcbind (voir rpcbind(8)), et d'associer le numéro de programme et de version donné à la routine de distribution. Lorsque le serveur RPC reçoit une requête RPC, la bibliothèque appelle la routine de distribution avec les arguments appropriés.

Routines

Voir rpc(3) pour la définition de la structure de données SVCXPRT.

rpc_reg()
Enregistre le programme prognum, la procédure procname, et la version versnum auprès du paquet de services RPC. Si une requête arrive pour le programme prognum, la version versnum, et la procédure procnum, procname est appelée avec un pointeur vers ses arguments ; procname devrait retourner un pointeur vers son/ses résultat(s) statique(s) ; inproc est la fonction XDR utilisée pour décoder les arguments tandis que outproc est la fonction XDR utilisée pour encoder les résultats. Les procédures sont enregistrées sur tous les transports disponibles de la classe nettype. Voir rpc(3). Cette routine retourne 0 si l'enregistrement a réussi, -1 sinon.
svc_reg()
Associe prognum et versnum à la procédure de distribution du service, dispatch. Si netconf est NULL, le service n'est pas enregistré auprès du service rpcbind(8). Si netconf n'est pas nul, alors un mappage du triplet [prognum, versnum, netconf->nc_netid] à xprt->xp_ltaddr est établi avec le service rpcbind local.

La routine svc_reg() retourne 1 si elle réussit, et 0 sinon.

svc_unreg()
Supprime du service rpcbind, tous les mappages du triplet [prognum, versnum, tous-les-transports] à l'adresse réseau et tous les mappages au sein du paquet de services RPC du double [prognum, versnum] aux routines de distribution.
svc_auth_reg()
Enregistre la routine d'authentification du service handler auprès du mécanisme de distribution afin qu'elle puisse être invoquée pour authentifier les requêtes RPC reçues avec le type d'authentification cred_flavor. Cette interface permet aux développeurs d'ajouter de nouveaux types d'authentification à leurs applications RPC sans avoir à modifier les bibliothèques. Les implémenteurs de services n'ont généralement pas besoin de cette routine.

L'application de service typique appellerait svc_auth_reg() après avoir enregistré le service et avant d'appeler svc_run(). Lorsque nécessaire pour traiter un identifiant RPC de type cred_flavor, la procédure handler sera appelée avec deux arguments, struct svc_req *rqst et struct rpc_msg *msg, et est censée retourner une valeur valide de type enum auth_stat. Il n'y a aucune disposition pour modifier ou supprimer un gestionnaire d'authentification une fois enregistré.

La routine svc_auth_reg() retourne 0 si l'enregistrement est réussi, 1 si cred_flavor a déjà un gestionnaire d'authentification enregistré pour lui, et -1 sinon.

xprt_register()
Après la création du descripteur de transport de service RPC xprt, il est enregistré auprès du paquet de services RPC. Cette routine modifie la variable globale svc_fdset (voir rpc_svc_calls(3)). Les implémenteurs de services n'ont généralement pas besoin de cette routine.
xprt_unregister()
Avant qu'un descripteur de transport de service RPC xprt ne soit détruit, il se désenregistre auprès du paquet de services RPC. Cette routine modifie la variable globale svc_fdset (voir rpc_svc_calls(3)). Les implémenteurs de services n'ont généralement pas besoin de cette routine.

DISPONIBILITÉ
