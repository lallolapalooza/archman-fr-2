RWARRAY(3am) Modules d'extension GNU Awk RWARRAY(3am)

NOM

writea, reada, writeall, readall - écrire et lire des tableaux gawk depuis/vers des fichiers

SYNTAXE

@load "rwarray"

ret = writea(fichier, tableau)
ret = reada(fichier, tableau)
ret = writeall(fichier)
ret = readall(fichier)

DESCRIPTION

L'extension rwarray ajoute des fonctions nommées writea(), reada(), writeall() et readall(), comme suit.

writea()
Cette fonction prend un argument chaîne de caractères, qui est le nom du fichier vers lequel décharger le tableau, et le tableau lui-même comme deuxième argument. writea() comprend les tableaux multidimensionnels. Elle retourne un en cas de succès, ou zéro en cas d'échec.
reada()
est l'inverse de writea() ; elle lit le fichier nommé comme premier argument, remplissant le tableau nommé comme deuxième argument. Elle efface d'abord le tableau. Ici aussi, la valeur de retour est un en cas de succès et zéro en cas d'échec.
writeall()
Cette fonction prend un argument chaîne de caractères, qui est le nom du fichier vers lequel décharger l'état de toutes les variables. Appeler cette fonction est complètement équivalent à appeler writea() avec le deuxième argument égal à SYMTAB. Elle retourne un en cas de succès, ou zéro en cas d'échec.
readall()
Cette fonction prend un argument chaîne de caractères, qui est le nom du fichier à partir duquel lire le contenu de diverses variables globales. Pour chaque variable dans le fichier, les données sont chargées à moins que la variable n'existe déjà. Si la variable existe déjà, les données de cette variable dans le fichier sont ignorées. Elle retourne un en cas de succès, ou zéro en cas d'échec.

NOTES

Le tableau créé par reada() est identique à celui écrit par writea() en ce sens que les contenus sont les mêmes. Cependant, en raison de problèmes d'implémentation, l'ordre de parcours du tableau du tableau recréé sera probablement différent de celui du tableau d'origine. Comme l'ordre de parcours des tableaux en AWK est par défaut indéfini, ce n'est pas (techniquement) un problème. Si vous avez besoin de garantir un ordre de parcours particulier, utilisez les fonctionnalités de tri de tableaux de gawk pour ce faire.

Le fichier contient des données binaires. Toutes les valeurs entières sont écrites en ordre réseau (network byte order). Cependant, les valeurs à virgule flottante de double précision sont écrites sous forme de données binaires natives. Ainsi, les tableaux ne contenant que des données chaînes peuvent théoriquement être déchargés sur des systèmes avec un ordre d'octets et restaurés sur des systèmes avec un ordre différent, mais cela n'a pas été essayé.

EXEMPLE

@load "rwarray"
...
ret = writea("arraydump.bin", array)
...
ret = reada("arraydump.bin", array)
...
ret = writeall("globalstate.bin")
...
ret = readall("globalstate.bin")
