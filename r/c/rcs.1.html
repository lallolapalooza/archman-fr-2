NOM

rcs - modifier les attributs des fichiers RCS

SYNTAXE

rcs options fichier ...

DESCRIPTION

rcs crée de nouveaux fichiers RCS ou modifie les attributs de ceux existants. Un fichier RCS contient plusieurs révisions de texte, une liste d'accès, un journal des modifications, un texte descriptif et certains attributs de contrôle. Pour que rcs fonctionne, le nom de connexion de l'appelant doit figurer dans la liste d'accès, sauf si la liste d'accès est vide, si l'appelant est le propriétaire du fichier ou le superutilisateur, ou si l'option -i est présente.

Les noms de fichiers correspondant à un suffixe RCS désignent des fichiers RCS ; tous les autres désignent des fichiers de travail. Les noms sont associés comme expliqué dans ci(1). Les numéros de révision utilisent la syntaxe décrite dans ci(1).

OPTIONS

-i
Crée et initialise un nouveau fichier RCS, mais ne dépose aucune révision. Si le nom du fichier RCS n'a pas de composante de répertoire, essaie de le placer d'abord dans le sous-répertoire ./RCS, puis dans le répertoire courant. Si le fichier RCS existe déjà, affiche un message d'erreur.
-anoms_connexion
Ajoute les noms de connexion apparaissant dans la liste séparée par des virgules noms_connexion à la liste d'accès du fichier RCS.
-Aancien_fichier
Ajoute la liste d'accès de ancien_fichier à la liste d'accès du fichier RCS.
-e[noms_connexion]
Supprime les noms de connexion apparaissant dans la liste séparée par des virgules noms_connexion de la liste d'accès du fichier RCS. Si noms_connexion est omis, supprime toute la liste d'accès.
-b[rev]
Définit la branche par défaut à rev. Si rev est omis, la branche par défaut est réinitialisée à la branche (dynamiquement) la plus haute sur le tronc.
-cchaîne
Définit le leader de commentaire à chaîne. Un premier ci, ou un rcs -i sans -c, devine le leader de commentaire à partir du suffixe du nom du fichier de travail.

Cette option est obsolète, car RCS utilise normalement le préfixe de la ligne $Log$ précédente lors de l'insertion des lignes de journalisation lors de l'extraction (voir co(1)). Cependant, les anciennes versions de RCS utilisent le leader de commentaire au lieu du préfixe de la ligne $Log$. Par conséquent, si vous prévoyez d'accéder à un fichier avec des versions anciennes et nouvelles de RCS, assurez-vous que son leader de commentaire correspond à son préfixe de ligne $Log$.

-ksubst
Définit la substitution de mots-clés par défaut à subst. L'effet de la substitution de mots-clés est décrit dans co(1). Donner une option -k explicite à co, rcsdiff, et rcsmerge annule cette valeur par défaut. Attention à rcs -kv, car -kv est incompatible avec co -l. Utilisez rcs -kkv pour restaurer la substitution de mots-clés par défaut normale.
-l[rev]
Verrouille la révision avec le numéro rev. Si une branche est donnée, verrouille la dernière révision sur cette branche. Si rev est omis, verrouille la dernière révision sur la branche par défaut. Le verrouillage empêche les modifications qui se chevauchent. Si quelqu'un d'autre détient déjà le verrou, le verrou est brisé comme avec rcs -u (voir ci-dessous).
-u[rev]
Déverrouille la révision avec le numéro rev. Si une branche est donnée, déverrouille la dernière révision sur cette branche. Si rev est omis, supprime le dernier verrou détenu par l'appelant. Normalement, seul le verrouilleur d'une révision peut la déverrouiller. Le déverrouillage d'une révision par quelqu'un d'autre brise le verrou. Si RCS a été configuré avec --with-mailer, alors cela provoque l'envoi d'un message électronique au verrouilleur d'origine. Le message contient un commentaire sollicité de la part de celui qui a brisé le verrou. Le commentaire est terminé par la fin du fichier ou par une ligne contenant uniquement ..
-L
Définit le verrouillage à strict. Le verrouillage strict signifie que le propriétaire d'un fichier RCS n'est pas exempté du verrouillage pour l'enregistrement (checkin). Cette option doit être utilisée pour les fichiers partagés.
-U
Définit le verrouillage à non-strict. Le verrouillage non-strict signifie que le propriétaire d'un fichier n'a pas besoin de verrouiller une révision pour l'enregistrement (checkin). Cette option ne doit pas être utilisée pour les fichiers partagés. Le verrouillage par défaut est-il strict est déterminé par votre administrateur système, mais il est normalement strict.
-mrev:[msg]
Remplace le message de journalisation de la révision rev par msg. Si msg est omis, il prend par défaut "*** message de journalisation vide ***".
-M
N'envoie pas d'e-mail lors de la rupture du verrou de quelqu'un d'autre. Cette option n'est pas destinée à une utilisation occasionnelle ; elle est destinée aux programmes qui avertissent les utilisateurs par d'autres moyens et qui appellent rcs -u uniquement comme opération de bas niveau pour briser le verrou.
-nnom[:[rev]]
Associe le nom symbolique nom à la branche ou à la révision rev. Supprime le nom symbolique si : et rev sont tous deux omis ; sinon, affiche un message d'erreur si nom est déjà associé à un autre numéro. Si rev est symbolique, il est développé avant l'association. Une rev constituée d'un numéro de branche suivi d'un point (.) représente la dernière révision actuelle dans la branche. Un deux-points (:) avec une rev vide représente la dernière révision actuelle sur la branche par défaut, normalement le tronc. Par exemple, rcs -nnom: RCS/* associe nom à la dernière révision actuelle de tous les fichiers RCS nommés ; cela contraste avec rcs -nnom:$ RCS/* qui associe nom aux numéros de révision extraits des chaînes de mots-clés dans les fichiers de travail correspondants.
-Nnom[:[rev]]
Agit comme -n, sauf qu'il annule toute affectation précédente de nom.
-oplage
Supprime ("date au rebut") les révisions données par plage. Une plage constituée d'un seul numéro de révision désigne cette révision. Une plage constituée d'un numéro de branche désigne la dernière révision sur cette branche. Une plage de la forme rev1:rev2 désigne les révisions rev1 à rev2 sur la même branche, :rev désigne depuis le début de la branche contenant rev jusqu'à et y compris rev, et rev: désigne depuis la révision rev jusqu'à la fin de la branche contenant rev. Aucune des révisions datées au rebut ne peut avoir de branches ou de verrous.
-q
Exécute silencieusement ; n'affiche pas de diagnostics.
-I
Exécute interactivement, même si l'entrée standard n'est pas un terminal.
-sétat[:rev]
Définit l'attribut d'état de la révision rev à état. Si rev est un numéro de branche, suppose la dernière révision sur cette branche. Si rev est omis, suppose la dernière révision sur la branche par défaut. N'importe quel identifiant est acceptable pour état. Un ensemble utile d'états est Exp (pour expérimental), Stab (pour stable), et Rel (pour libéré). Par défaut, ci(1) définit l'état d'une révision à Exp.
-t[fichier]
Écrit le texte descriptif du contenu du fichier nommé dans le fichier RCS, en supprimant le texte existant. Le nom de fichier ne peut pas commencer par -. Si fichier est omis, obtient le texte de l'entrée standard, terminé par la fin du fichier ou par une ligne contenant uniquement .. Demande le texte si une interaction est possible ; voir -I. Avec -i, le texte descriptif est obtenu même si -t n'est pas donné.
-t-chaîne
Écrit le texte descriptif de la chaîne dans le fichier RCS, en supprimant le texte existant.
-T
Préserve l'heure de modification sur le fichier RCS sauf si une révision est supprimée. Cette option peut supprimer une recompilation extensive causée par un changement de l'heure de modification.

Ces options sont utilisées pour initialiser et manipuler des fichiers RCS. Le reste de la commande rcs est utilisé pour changer les attributs des fichiers RCS. Si une option est spécifiée, une ou plusieurs valeurs peuvent être utilisées pour spécifier ce que vous voulez changer.

EXEMPLES

Pour créer un nouveau fichier RCS appelé `test.c.RCS` avec un accès autorisé pour `john` et `jane`:

rcs -i -a"john,jane" test.c

Pour verrouiller la dernière révision du fichier `test.c`:

rcs -l test.c

Pour déverrouiller la dernière révision du fichier `test.c`:

rcs -u test.c

VOIR AUSSI

ci(1), co(1), ident(1), rcs(1), rcsdiff(1), rcsmerge(1)

make(1) de certaines copies du fichier de travail sur le fichier RCS. Utilisez cette option avec prudence ; elle peut supprimer la recompilation même lorsqu'elle est nécessaire, c'est-à-dire lorsqu'une modification du fichier RCS entraînerait une modification des chaînes de mots-clés dans le fichier de travail.
-V
Affiche le numéro de version de RCS.
-Vn
Émule la version n de RCS. Voir co(1) pour les détails.
-xsuffixes
Utilise suffixes pour caractériser les fichiers RCS. Voir ci(1) pour les détails.
-zfuseau
Utilise fuseau comme fuseau horaire par défaut. Cette option n'a aucun effet ; elle est présente pour la compatibilité avec d'autres commandes RCS.

Au moins une option explicite doit être donnée, afin d'assurer la compatibilité avec les extensions futures prévues pour la commande rcs.

COMPATIBILITÉ

L'option -brev génère un fichier RCS qui ne peut pas être analysé par les versions 3 ou antérieures de RCS.

Les options -ksubst (sauf -kkv) génèrent un fichier RCS qui ne peut pas être analysé par les versions 4 ou antérieures de RCS.

Utilisez rcs -Vn pour rendre un fichier RCS acceptable pour la version n de RCS en supprimant les informations qui pourraient confondre la version n.

La version 5.5 de RCS et les versions antérieures ne supportent pas l'option -x, et exigent un suffixe ,v pour les noms de fichiers RCS.

FICHIERS

rcs accède aux fichiers de manière similaire à ci(1), sauf qu'il utilise l'utilisateur effectif pour tous les accès, qu'il n'écrit pas le fichier de travail ni son répertoire, et qu'il ne lit même pas le fichier de travail à moins qu'un numéro de révision de $ ne soit spécifié.

ENVIRONNEMENT

RCSINIT
Options ajoutées avant la liste des arguments, séparées par des espaces. Une barre oblique inverse échappe les espaces à l'intérieur d'une option. Les options RCSINIT sont ajoutées avant les listes d'arguments de la plupart des commandes RCS. Les options RCSINIT utiles incluent -q, -V, -x, et -z.
RCS_MEM_LIMIT
Normalement, pour la rapidité, les commandes mémorisent ou copient en mémoire le fichier RCS si sa taille est inférieure à la limite-mémoire, qui par défaut est « illimitée ». Sinon (ou si les méthodes rapides initialement tentées échouent), les commandes reviennent aux routines d'entrée/sortie standard. Vous pouvez ajuster la limite de mémoire en définissant RCS_MEM_LIMIT à une valeur numérique lim (mesurée en kilooctets). Une valeur vide est ignorée silencieusement. En tant qu'effet secondaire, la spécification de RCS_MEM_LIMIT empêche le recours aux routines plus lentes.
TMPDIR
Nom du répertoire temporaire. S'il n'est pas défini, les variables d'environnement TMP et TEMP sont inspectées à la place et la première valeur trouvée est prise ; si aucune d'elles n'est définie, un défaut dépendant de l'hôte est utilisé, généralement /tmp.

DIAGNOSTICS

Le nom du fichier RCS et les révisions obsolètes sont écrits sur la sortie de diagnostic. Le statut de sortie est zéro si et seulement si toutes les opérations ont réussi.

BOGUES

Une catastrophe (par exemple, un crash système) peut amener RCS à laisser un fichier sémaphore qui fait que les invocations ultérieures de RCS affirment que le fichier RCS est en cours d'utilisation. Pour résoudre ce problème, supprimez le fichier sémaphore. Le nom d'un fichier sémaphore commence généralement par , ou se termine par _.

Le séparateur pour les plages de révisions dans l'option -o était auparavant - au lieu de :, mais cela crée une confusion lorsque les noms symboliques contiennent des -. Pour des raisons de compatibilité ascendante, rcs -o supporte toujours l'ancien séparateur -, mais il émet un avertissement concernant cette utilisation obsolète.

Les noms symboliques n'ont pas besoin de faire référence à des révisions ou des branches existantes. Par exemple, l'option -o ne supprime pas les noms symboliques pour les révisions obsolètes ; vous devez utiliser -n pour supprimer les noms.
