NOM

rrdgraph_data - préparation des données pour le graphique rrdtool

SYNTAXE

DEF:<vname>=<rrdfile>:<ds-name>:<CF>[:step=<step>][:start=<time>][:end=<time>][:reduce=<CF>][:daemon=<address>]

VDEF:vname=expression RPN

CDEF:vname=expression RPN

DESCRIPTION

Ces trois instructions extraient des valeurs de données des fichiers RRD, en les modifiant éventuellement (pensez, par exemple, à une conversion d'octets en bits). Si vous le souhaitez, vous pouvez également définir des variables contenant des informations utiles telles que le maximum, le minimum, etc. Deux des instructions utilisent un langage appelé RPN, qui est décrit dans sa propre page de manuel.

Les noms de variables (vname) doivent être composés de chaînes caractères des types suivants "A-Z, a-z, 0-9, _, -" et avoir une longueur maximale de 255 caractères.

Lors du choix des noms de variables, assurez-vous de ne pas choisir un nom déjà utilisé par un opérateur RPN. Il est plus sûr d'utiliser des noms en minuscules ou en casse mixte pour les variables, car les opérateurs seront toujours en majuscules.

DEF

DEF:<vname>=<rrdfile>:<ds-name>:<CF>[:step=<step>][:start=<time>][:end=<time>][:reduce=<CF>][:daemon=<address>]

Cette commande récupère les données d'un fichier RRD. Le nom virtuel vname peut ensuite être utilisé dans le reste du script. Par défaut, un RRA contenant les données consolidées correctes à une résolution appropriée sera choisi. La résolution peut être remplacée par l'option --step. La résolution peut être à nouveau remplacée en spécifiant la taille du pas. La période de temps de ces données est identique à celle du graphique par défaut, vous pouvez la remplacer en spécifiant start et end. N'oubliez pas d'échapper les deux-points dans la spécification de l'heure !

Si la résolution des données est supérieure à la résolution du graphique, les données seront davantage consolidées. Cela peut aboutir à un graphique couvrant un temps légèrement supérieur à celui demandé. Idéalement, chaque point du graphique devrait correspondre à un CDP d'un RRA. Par exemple, si votre RRD a un RRA avec une résolution de 1800 secondes par CDP, vous devriez créer une image avec une largeur de 400 et une période de temps de 400*1800 secondes (utilisez des heures de début et de fin appropriées, telles que "--start end-8days8hours").

Si une consolidation est nécessaire, le CF du RRA spécifié dans le DEF lui-même sera utilisé pour réduire la densité des données. Ce comportement peut être modifié en utilisant ":reduce=<CF>". Ce paramètre facultatif spécifie le CF à utiliser pendant la phase de réduction des données.

Il est possible de demander des sources de données uniques à un RRDCacheD spécifique, voir rrdcached, en utilisant le paramètre ":daemon=<address>". La valeur donnée à ce paramètre suit la même syntaxe que les autres moyens de spécifier l'adresse du démon de cache. Elle est décrite en détail dans rrdcached. Attention cependant, les deux-points (dans les adresses IPv6 et comme séparateur de port, par exemple) doivent être échappés à l'aide d'une barre oblique inverse.

Exemple :

DEF:ds0=router.rrd:ds0:AVERAGE
DEF:ds0weekly=router.rrd:ds0:AVERAGE:step=7200
DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=end-1h
DEF:ds0weekly=router.rrd:ds0:AVERAGE:start=11\:00:end=start+1h
DEF:ds0weekly=router.rrd:ds0:AVERAGE:daemon=collect1.example.com

VDEF

VDEF:vname=expression RPN

Cette commande retourne une valeur et/ou une heure selon les instructions RPN utilisées. Le vname résultant aura, en fonction des fonctions utilisées, une valeur et un composant temporel. Lorsque vous utilisez ce vname dans une autre expression RPN, vous insérez effectivement sa valeur comme si vous aviez mis un nombre à cet endroit. La variable peut également être utilisée dans les divers éléments de graphique et d'impression.

Exemple : "VDEF:avg=mydata,AVERAGE"

Notez qu'actuellement, seules les fonctions d'agrégation fonctionnent dans les expressions RPN VDEF. Les correctifs pour changer cela sont les bienvenus.

CDEF

CDEF:vname=expression RPN

Cette commande crée un nouvel ensemble de points de données (en mémoire uniquement, pas dans le fichier RRD) à partir d'une ou plusieurs autres séries de données. Les instructions RPN sont utilisées pour évaluer une fonction mathématique sur chaque point de données. Le vname résultant peut ensuite être utilisé plus loin dans le script, comme s'il avait été généré par une instruction DEF.

Exemple : "CDEF:mydatabits=mydata,8,*"

À propos de CDEF versus VDEF

À un certain moment du traitement, RRDtool a rassemblé un tableau de taux prêts à être affichés.

CDEF travaille sur un tel tableau. Par exemple, CDEF:new=ds0,8,* multiplierait chacun des membres du tableau par huit (transformant probablement des octets en bits). Le résultat est un tableau contenant les nouvelles valeurs.

VDEF travaille également sur un tel tableau, mais d'une manière différente. Par exemple, VDEF:max=ds0,MAXIMUM parcourrait chacun des membres du tableau et stockerait la valeur maximale.

Quand utilisez-vous VDEF au lieu de CDEF et vice-versa ?

Utilisez CDEF pour transformer vos données avant de les graphiquer. Dans l'exemple ci-dessus, nous utiliserions un CDEF pour transformer les octets en bits avant de graphiquer les bits.

Vous utilisez un VDEF si vous voulez que max(1,5,3,2,4) retourne cinq, ce qui serait affiché dans la légende du graphique (pour répondre à la question : quelle était la valeur maximale pendant la période du graphique).

Si vous souhaitez appliquer des opérations « complexes » au résultat d'un VDEF, vous devez à nouveau utiliser un CDEF, car les VDEF ressemblent seulement à des expressions RPN, ils ne le sont pas vraiment.

VOIR AUSSI

rrdgraph donne un aperçu du fonctionnement de rrdtool graph. rrdgraph_data décrit DEF, CDEF et VDEF en détail. rrdgraph_rpn décrit le langage RPN utilisé dans les instructions ?DEF. rrdgraph_graph décrit toutes les fonctions de graphique et d'impression.

Assurez-vous de lire rrdgraph_examples pour des astuces et des conseils.

    rrdgraph_data(1)

    NOM

    rrdgraph_data — Définition des fonctions de données pour RRDtool

    SYNOPSIS

    Vous pouvez utiliser les définitions de données RRD dans vos scripts pour traiter les données de base de données RRD avant de les tracer. Les définitions de données sont spécifiées avec l'option --imginfo de la commande rrdgraph ou via le paramètre --drawoption dans les fichiers de configuration de rrdtool.

    DESCRIPTION

    Les définitions de données RRD sont un moyen puissant de manipuler les données de base de données RRD avant de les tracer. Elles vous permettent d'effectuer des calculs, de transformer des données et de créer de nouvelles séries de données à partir de sources existantes.

    OPTIONS

    Aucune option spécifique n'est applicable à cette section. Les définitions de données sont intégrées aux commandes.

    VDEF

    VDEF:nom=source:fonction[:paramètres]

    VDEF spécifie une fonction de définition de valeur qui calcule une seule valeur à partir d'une série de données. Par exemple, vous pouvez calculer la moyenne, la valeur maximale, la valeur minimale, la somme, etc. d'une série de données sur une période donnée.

    Exemple : VDEF:avg_temp=temperature:AVERAGE calcule la température moyenne.

    CDEF

    CDEF:nom=source:fonction[:paramètres]

    CDEF spécifie une fonction de définition de calcul qui crée une nouvelle série de données à partir d'une ou plusieurs séries de données existantes. Vous pouvez effectuer diverses opérations arithmétiques, logiques et des transformations sur les données.

    Exemple : CDEF:temp_celsius=temperature:SCALE,32,-,* convertit la température de Fahrenheit en Celsius.

    À propos de CDEF versus VDEF

    La principale différence entre CDEF et VDEF réside dans ce qu'ils produisent :

    • CDEF crée une nouvelle série de données. Cela signifie que le résultat de CDEF est une séquence de valeurs qui peut être tracée, agrégée ou utilisée comme entrée pour d'autres définitions de données.
    • VDEF calcule et renvoie une valeur unique. Cette valeur peut être utilisée pour annoter un graphique, pour définir une limite, ou pour être affichée comme une statistique.

    En bref, CDEF est utilisé pour la transformation et la manipulation de données au niveau de la série, tandis que VDEF est utilisé pour l'agrégation et le calcul de statistiques sur une série de données.
