NOM

rrdgraph_examples - Exemples pour rrdtool graph

SYNOPSIS

rrdtool graph /home/httpd/html/test.png --imgformat PNG

suivi par l'un des exemples ci-dessous

DESCRIPTION

Pour votre commodité, certaines commandes sont expliquées ici à l'aide d'exemples détaillés. Elles ne sont pas toujours prêtes à être copiées-collées car les commentaires sont mélangés aux exemples.

EXEMPLES

Données avec multiples résolutions

--end now --start end-120000s --width 400
DEF:ds0a=/home/rrdtool/data/router1.rrd:ds0:AVERAGE
DEF:ds0b=/home/rrdtool/data/router1.rrd:ds0:AVERAGE:step=1800
DEF:ds0c=/home/rrdtool/data/router1.rrd:ds0:AVERAGE:step=7200
LINE1:ds0a#0000FF:"résolution par défaut\l"
LINE1:ds0b#00CCFF:"résolution 1800 secondes par intervalle\l"
LINE1:ds0c#FF00FF:"résolution 7200 secondes par intervalle\l"

Section de légende joliment formatée

DEF:ds0=/home/rrdtool/data/router1.rrd:ds0:AVERAGE
DEF:ds1=/home/rrdtool/data/router1.rrd:ds1:AVERAGE
VDEF:ds0max=ds0,MAXIMUM
VDEF:ds0avg=ds0,AVERAGE
VDEF:ds0min=ds0,MINIMUM
VDEF:ds0pct=ds0,95,PERCENT
VDEF:ds1max=ds1,MAXIMUM
VDEF:ds1avg=ds1,AVERAGE
VDEF:ds1min=ds1,MINIMUM
VDEF:ds1pct=ds1,95,PERCENT

Note : la consolidation a lieu ici.

CDEF:ds0bits=ds0,8,*
CDEF:ds1bits=ds1,8,*

Note : 10 espaces pour déplacer le texte vers la droite

COMMENT:"          "

Note : les titres de colonnes doivent être aussi larges que les colonnes

COMMENT:"Maximum    "
COMMENT:"Moyenne    "
COMMENT:"Minimum    "
COMMENT:"95ème percentile\l"
AREA:ds0bits#00C000:"Entrant "
GPRINT:ds0max:"%6.2lf %Sbps"
GPRINT:ds0avg:"%6.2lf %Sbps"
GPRINT:ds0min:"%6.2lf %Sbps"
GPRINT:ds0pct:"%6.2lf %Sbps\l"
LINE1:ds1bits#0000FF:"Sortant"
GPRINT:ds1max:"%6.2lf %Sbps"
GPRINT:ds1avg:"%6.2lf %Sbps"
GPRINT:ds1min:"%6.2lf %Sbps"
GPRINT:ds1pct:"%6.2lf %Sbps\l"

Décaler une ligne sur l'axe y

Selon vos besoins, vous pouvez le faire de deux manières :

  • Décalez les données, puis tracez ceci 
    DEF:mydata=my.rrd:ds:AVERAGE

    Note : cela influencera également toute autre commande qui utilise "data"

    CDEF:data=mydata,100,+
LINE1:data#FF0000:"Données avec décalage"
  • Tracez les données originales, avec un décalage 
    DEF:mydata=my.rrd:ds:AVERAGE

    Note : pas de couleur dans la première ligne, donc elle n'est pas visible

    LINE1:100

    Note : la deuxième ligne est empilée sur la première

    LINE1:mydata#FF0000:"Données avec décalage":STACK

Dessiner des lignes pointillées

Fonctionne également pour HRULE et VRULE

  • style par défaut : - - - - - 
    LINE1:data#FF0000:"ligne pointillée":dashes
  • style plus fantaisiste avec décalage : - - --- - --- - 
    LINE1:data#FF0000:"une autre ligne pointillée":dashes=15,5,5,10:dash-offset=10

Plages horaires

Quatre dernières semaines : --start end-4w --end 00:00
Janvier 2001 :    --start 20010101 --end start+31d
Janvier 2001 :    --start 20010101 --end 20010201
Dernière heure :       --start end-1h
Dernières 24 heures :   <rien du tout>
Hier :          --end 00:00

Visualiser la semaine actuelle et la semaine précédente ensemble

--end now --start end-1w
DEF:thisweek=router.rrd:ds0:AVERAGE
DEF:lastweek=router.rrd:ds0:AVERAGE:end=now-1w:start=end-1w

Déplacez les données d'une semaine (604800 secondes)

SHIFT:lastweek:604800
[ plus du reste de la configuration VDEF et CDEF habituelle si vous le souhaitez ]
AREA:lastweek#0000FF:Semaine\ dernière
LINE1:thisweek#FF0000:Semaine\ dernière

Détection de comportement aberrant

Si les fonctions spécialisées RRA existent pour la détection de comportements aberrants, elles peuvent être utilisées pour générer le graphique d'une série temporelle avec des bandes de confiance et des échecs.

rrdtool graph example.png \
       DEF:obs=monitor.rrd:ifOutOctets:AVERAGE \
       DEF:pred=monitor.rrd:ifOutOctets:HWPREDICT \
       DEF:dev=monitor.rrd:ifOutOctets:DEVPREDICT \
       DEF:fail=monitor.rrd:ifOutOctets:FAILURES \
       TICK:fail#ffffa0:1.0:"Échecs\: Octets sortants moyens" \
       CDEF:scaledobs=obs,8,* \
       CDEF:upper=pred,dev,2,*,+ \
       CDEF:lower=pred,dev,2,*,- \
       CDEF:scaledupper=upper,8,* \
       CDEF:scaledlower=lower,8,* \
       LINE2:scaledobs#0000ff:"Octets sortants moyens" \
       LINE1:scaledupper#ff0000:"Borne de confiance supérieure : Octets sortants moyens" \
       LINE1:scaledlower#ff0000:"Borne de confiance inférieure : Octets sortants moyens"

Cet exemple génère un graphique de la série de données en bleu (LINE2 avec la source de données virtuelle scaledobs), des bornes de confiance en rouge (sources de données virtuelles scaledupper et scaledlower), et des échecs potentiels (c'est-à-dire un comportement potentiellement aberrant) marqués par des lignes verticales jaunes (la source de données fail).

Les données brutes proviennent d'un RRA AVERAGE, la résolution la plus fine de la série temporelle observée (un point de données consolidé par point de données primaire). Les valeurs prédites (ou lissées) sont stockées dans le RRA HWPREDICT. Les valeurs de déviations prédites (pensez écart type) sont stockées dans le RRA DEVPREDICT. Enfin, le RRA FAILURES contient des indicateurs, avec 1 indiquant un échec potentiel.

Toutes les données sont redimensionnées en bits (au lieu d'Octets) en multipliant par 8. Les bornes de confiance sont calculées par un décalage de 2 déviations à la fois au-dessus et en dessous des valeurs prédites (les CDEF upper et lower). Les lignes verticales indiquant les échecs potentiels sont tracées via l'élément graphique TICK, qui convertit les valeurs non nulles d'un RRA en marques de graduation. Ici, un argument de fraction d'axe de 1.0 signifie que les marques de graduation s'étendent sur tout l'axe y, devenant ainsi des lignes verticales sur le graphique.

Le choix de 2 déviations (un facteur d'échelle) correspond à la valeur par défaut utilisée en interne par le RRA FAILURES. Si la valeur interne est modifiée (voir rrdtune), cette commande graphique doit être modifiée pour être cohérente.

Une note sur la réduction des données :

La commande graph de rrdtool est conçue pour tracer des données à une résolution temporelle spécifiée, quelle que soit la résolution réelle des données dans le fichier RRD. Cela peut poser problème pour les fonctions de consolidation spécialisées qui maintiennent une relation un-à-un entre les points de données primaires et les points de données consolidés. Si un graphique insiste pour visualiser le contenu de ces RRAs à une échelle temporelle plus grossière, la commande graph tente de faire quelque chose d'intelligent, mais les bandes de confiance et les échecs n'ont plus le même sens et peuvent être trompeurs.

VOIR AUSSI

rrdgraph donne un aperçu du fonctionnement de rrdtool graph. rrdgraph_data décrit DEF,CDEF et VDEF en détail. rrdgraph_rpn décrit le langage RPN utilisé dans les instructions xDEF. rrdgraph_graph décrit toutes les fonctions de graphique et d'impression.
