RRDUPDATE(1) rrdtool RRDUPDATE(1)

NOM

rrdupdate - Stocker un nouvel ensemble de valeurs dans le RRD

SYNTAXE

rrdtool {update | updatev} nom_fichier [--template|-t nom-ds[:nom-ds]...] [--skip-past-updates|-s] [--daemon|-d adresse] [--] N:valeur[:valeur]... horodatage:valeur[:valeur]... horodatage-at@valeur[:valeur]...

DESCRIPTION

La fonction update alimente une RRD avec de nouvelles valeurs de données. Les données sont alignées dans le temps (interpolées) conformément aux propriétés de la RRD dans laquelle les données sont écrites.

updatev
Cette version alternative de update prend les mêmes arguments et exécute la même fonction. Le v signifie verbeux, ce qui décrit la sortie retournée. updatev retourne une liste de tous les points de données consolidés (CDP) écrits sur le disque suite à l'appel de update. Les valeurs sont indexées par l'horodatage (time_t), le RRA (fonction de consolidation et PDP par CDP), et la source de données (nom). Notez qu'en fonction des arguments de l'appel actuel et précédent de update, la liste peut ne contenir aucune entrée ou un grand nombre d'entrées.

Étant donné que updatev nécessite un accès direct au disque, l'option --daemon ne peut pas être utilisée avec cette commande.

nom_fichier
Le nom de la RRD que vous souhaitez mettre à jour.
--locking|-L try|block|none
Verrouille le fichier RRD dans le mode spécifié : try échoue si le fichier est verrouillé par un autre processus, block attend que le verrou soit libéré, et none ignore le verrouillage. La valeur par défaut est lue à partir de la variable d'environnement $RRD_LOCKING et se rabat sur try si une telle variable n'existe pas.
--template|-t nom-ds[:nom-ds]...
Par défaut, la fonction update attend ses données d'entrée dans l'ordre où les sources de données sont définies dans la RRD, excluant toute source de données COMPUTE (c'est-à-dire si la troisième source de données DST est COMPUTE, la troisième valeur d'entrée sera mappée à la quatrième source de données dans la RRD, et ainsi de suite). Ce n'est pas très résistant aux erreurs, car vous pourriez envoyer des données incorrectes à une RRD.

L'option template vous permet de spécifier quelles sources de données vous allez mettre à jour et dans quel ordre. Si les sources de données spécifiées dans le template ne sont pas disponibles dans le fichier RRD, le processus de mise à jour s'arrêtera avec un message d'erreur.

Bien qu'il semble possible avec l'option template de mettre à jour les sources de données de manière asynchrone, RRDtool attribue implicitement la valeur *UNKNOWN* aux sources de données non-COMPUTE absentes du template.

Ne spécifiez pas de valeur pour une DST COMPUTE dans la fonction update. Si cela est fait accidentellement (et cela ne peut être fait qu'en utilisant l'option template), RRDtool ignorera la valeur spécifiée pour la DST COMPUTE.

Le démon de mise en cache rrdcached ne peut pas encore être utilisé avec les templates.

--skip-past-updates|-s
Lors de la mise à jour d'un fichier rrd avec des données antérieures à la dernière mise à jour déjà appliquée, rrdtool émettra un message d'erreur et s'arrêtera. Cette option demande à rrdtool d'ignorer silencieusement ces données. Elle peut être utile lors de la relecture de données anciennes dans un fichier rrd et lorsque vous n'êtes pas sûr du nombre de mises à jour déjà appliquées.
--daemon|-d adresse
Si spécifié, RRDtool tentera de se connecter au démon de mise en cache rrdcached à l'adresse adresse. Si la connexion est établie avec succès, les valeurs seront envoyées au démon au lieu d'accéder directement aux fichiers. Si la connexion ne peut pas être établie, il se rabattra sur l'accès direct aux fichiers. Bien que pratique, cela peut causer des problèmes silencieusement, veuillez donc lire l'avertissement dans les exemples.

Pour une liste des formats acceptés, voir l'option -l dans le manuel de rrdcached.

{N | horodatage}:valeur[:valeur]...
Les données utilisées pour mettre à jour la RRD ont été acquises à un certain moment. Ce moment peut être défini en secondes depuis le 1970-01-01 ou en utilisant la lettre 'N', auquel cas l'heure de mise à jour sera définie comme l'heure actuelle. Les valeurs temporelles négatives sont soustraites de l'heure actuelle. Une SPÉCIFICATION DE TEMPS AU STYLE AT (voir la documentation de rrdfetch) peut également être utilisée en délimitant la fin de la spécification temporelle par le caractère '@' au lieu d'un ':'. Obtenir le timing précis à la seconde près est particulièrement important lorsque vous travaillez avec des sources de données de type COUNTER, DERIVE, DCOUNTER, DDERIVE ou ABSOLUTE.

Lorsque vous utilisez des valeurs temporelles négatives, les options et les données doivent être séparées par deux tirets (--), sinon la valeur temporelle serait analysée comme une option. Voir ci-dessous pour un exemple.

Les éléments restants de l'argument sont les mises à jour DS. L'ordre de cette liste est le même que l'ordre dans lequel les sources de données ont été définies dans le RRA. S'il n'y a pas de données pour une certaine source de données, la lettre U (par exemple, N:0.1:U:1) peut être spécifiée.

Le format de la valeur acquise à partir de la source de données dépend du type de source de données choisi. Normalement, ce sera numérique, mais les modules d'acquisition de données peuvent imposer leur propre analyse de ce paramètre tant que le deux-points (:) reste le séparateur de valeur de la source de données.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour modifier le comportement de "rrdtool update" :

RRDCACHED_ADDRESS
Si cette variable d'environnement est définie, elle aura le même effet que la spécification de l'option "--daemon" sur la ligne de commande. Si les deux sont présentes, l'argument de la ligne de commande a la priorité.
RRDCACHED_STRIPPATH
Si cette variable d'environnement est définie, elle supprimera la chaîne de caractères de début du nom de fichier avant d'envoyer le nom de fichier à rrdcached. Ceci est principalement destiné à permettre à rrdcached de fonctionner avec des outils comme xymon et cacti sans avoir à modifier ces outils.
RRD_LOCKING
Si cette variable d'environnement est définie, le fichier RRD sera verrouillé dans le mode spécifié : try échoue si le fichier est verrouillé par un autre processus, block attend que le verrou soit libéré, et none ignore le verrouillage.

Cette variable peut être remplacée par l'option de ligne de commande --locking.

EXEMPLES

  • "rrdtool update demo1.rrd N:3.44:3.15:U:23"

    Met à jour le fichier de base de données demo1.rrd avec 3 valeurs connues et une valeur *UNKNOWN*. Utilise l'heure actuelle comme heure de mise à jour.

  • "rrdtool update demo2.rrd 887457267:U 887457521:22 887457903:2.7"

    Met à jour le fichier de base de données demo2.rrd qui attend des données d'une seule source de données, trois fois. D'abord avec une valeur *UNKNOWN*, puis avec deux lectures régulières. L'intervalle de mise à jour semble être d'environ 300 secondes.

  • "rrdtool update demo3.rrd -- -5:21 N:42"

    Met à jour le fichier de base de données demo3.rrd deux fois, en utilisant cinq secondes dans le passé et l'heure actuelle comme heures de mise à jour.

rrdupdate(1) — Arch Linux

NAME

rrdupdate - update RRD database files.

SYNOPSIS

rrdupdate daemon [-f file] [-d directory] [-r] [-R host:port:password] [-p pidfile] [-w directory]

rrdupdate -f file [-d directory] [-r] [-R host:port:password] [-p pidfile] [-w directory]

rrdupdate -d directory [-r] [-R host:port:password] [-p pidfile] [-w directory]

DESCRIPTION

The rrdupdate utility is used to update RRD database files.

This utility is designed to be run periodically by cron. It is capable of updating one or more RRD files, possibly on a remote server, using the RRDp protocol. The rrdupdate utility can also fetch data from remote servers and store it locally in RRD files.

The primary purpose of rrdupdate is to poll data sources and update RRD files. This includes fetching data from remote servers and consolidating it into local RRD files.

The rrdupdate utility is often used in conjunction with a daemon that runs in the background and listens for update requests. If the daemon is available, it will handle the update requests. If the daemon is not available, rrdupdate will attempt to update the RRD files directly.

  • daemon: Specifies the daemon to connect to. If this is omitted, rrdupdate will attempt to update the RRD files directly.

  • -f file: Specifies the RRD file to update. This option can be specified multiple times to update multiple files.

  • -d directory: Specifies the directory to search for RRD files. This option can be specified multiple times to search multiple directories.

  • -r: Recursively search subdirectories for RRD files.

  • -R host:port:password: Specifies the remote host, port, and password to use for updating RRD files on a remote server. This option can be specified multiple times to update multiple remote servers.

  • -p pidfile: Specifies the PID file to use for the daemon.

  • -w directory: Specifies the working directory for the daemon.

When updating RRD files, rrdupdate will look for a configuration file named .rrdupdate.conf in the current directory. This file can contain options that will be passed to rrdupdate.

If a file is specified with a relative path, the file is looked up relative to the working directory. If the daemon is available, the file relative to the working directory of the daemon is used. If the daemon is not available, the file relative to the current working directory of the invoking process is used. This may update two different files depending on whether the daemon could be reached or not. Don't do relative paths, kids!

ENVIRONMENT VARIABLES

None.

EXAMPLES

Update a single RRD file:

  • rrdupdate -f /var/lib/rrd/mydb.rrd

Update all RRD files in a directory:

  • rrdupdate -d /var/lib/rrd/

Update RRD files on a remote server:

  • rrdupdate -R remote.server.com:8080:secretpassword -f /var/lib/rrd/mydb.rrd
