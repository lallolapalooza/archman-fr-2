NOM

rrdxport - Exporter des données au format XML basées sur les données d'un ou plusieurs RRD

SYNTAXE

rrdtool xport [-s|--start secondes] [-e|--end secondes] [-m|--maxrows lignes] [--step valeur] [--json] [-t|--showtime] [--enumds] [--daemon|-d adresse] [DEF:vname=rrd:ds-name:CF] [CDEF:vname=expression-rpn] [XPORT:vname[:légende]]

DESCRIPTION

Le but principal de la fonction xport est d'écrire une représentation au format XML des données stockées dans un ou plusieurs RRD. Il peut également extraire des rapports numériques.

Si aucune instruction XPORT n'est trouvée, il n'y aura pas de sortie.

-s|--start secondes (défaut : fin-1jour)
L'heure à laquelle la plage exportée doit commencer. Le temps en secondes depuis l'époque (1er janvier 1970) est requis. Les nombres négatifs sont relatifs à l'heure actuelle. Par défaut, une journée de données sera imprimée. Voir aussi « SPÉCIFICATION DE TEMPS STYLE-AT » dans rrdfetch pour une explication détaillée sur la façon de spécifier le temps.

Voir « FORMAT DE SORTIE » ci-dessous pour les détails sur la façon dont cela affecte la sortie.

-e|--end secondes (défaut : maintenant)
L'heure à laquelle la plage exportée doit se terminer. Temps en secondes depuis l'époque. Voir aussi « SPÉCIFICATION DE TEMPS STYLE-AT » dans rrdfetch pour une explication détaillée sur la façon de spécifier le temps.

Voir « FORMAT DE SORTIE » ci-dessous pour les détails sur la façon dont cela affecte la sortie.

-m|--maxrows lignes (défaut : 400 lignes)
Ceci fonctionne comme le paramètre -w|--width de rrdgraph. En fait, c'est exactement la même chose, mais le paramètre a été renommé pour décrire son objectif dans ce module. Voir la documentation de rrdgraph pour les détails.
--step valeur (défaut : automatique)
Voir la documentation de rrdgraph.
--daemon|-d adresse
Adresse du démon rrdcached. Si spécifié, une commande "flush" est envoyée au serveur avant de lire les fichiers RRD. Cela permet à rrdtool de retourner des données fraîches même si le démon est configuré pour mettre en cache les valeurs pendant longtemps. Pour une liste des formats acceptés, voir l'option -l dans le manuel de rrdcached. 
rrdtool xport --daemon unix:/var/run/rrdcached.sock ...
-t|--showtime
Inclure l'heure dans chaque ligne de données.
--json
Produire une sortie au format json (au lieu de xml)
--enumds
Le xml généré doit contenir les valeurs des données dans des balises énumérées. 
<v0>valeur</v0><v1>valeur</v1>
DEF:vname=rrd:ds-name:CF
Voir la documentation de rrdgraph.
CDEF:vname=expression-rpn
Voir la documentation de rrdgraph.
XPORT:vname[:légende]
Au moins une instruction XPORT doit être présente. Les valeurs référencées par vname sont imprimées. Ajoutez éventuellement une légende.

FORMAT DE SORTIE

La sortie est encapsulée dans un élément xport et contient deux blocs. Le premier bloc est encapsulé par un élément meta et contient des métadonnées. Le second bloc est encapsulé par un élément data et contient les lignes de données.

Supposons que la commande xport ressemble à ceci :

rrdtool xport \
        --start now-1h --end now \
        DEF:xx=host-inout.lo.rrd:output:AVERAGE \
        DEF:yy=host-inout.lo.rrd:input:AVERAGE \
        CDEF:aa=xx,yy,+,8,* \
        XPORT:xx:"octets sortants" \
        XPORT:aa:"bits entrants et sortants"

La section de métadonnées résultante est (les valeurs dépendront des caractéristiques du RRD) :

<meta>
  <start>1020611700</start>
  <step>300</step>
  <end>1020615600</end>
  <rows>14</rows>
  <columns>2</columns>
  <legend>
    <entry>octets sortants</entry>
    <entry>bits entrants et sortants</entry>
  </legend>
</meta>

La section de données résultante est :

  <row><t>1020612000</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>
  <row><t>1020612300</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>

Toutes les statistiques dans la sortie utiliseront le même pas. Le premier échantillon sera le premier échantillon commençant immédiatement après --start. Le dernier échantillon sera celui se terminant à ou immédiatement après --end.

Chaque échantillon a un horodatage et une ou plusieurs valeurs. Les horodatages associés à une valeur dans RRDtool représentent TOUJOURS le moment où l'échantillon a été pris. Puisque toute valeur que vous échantillonnez représentera une sorte d'état passé que votre appareil d'échantillonnage a recueilli, l'horodatage sera toujours à la fin de la période d'échantillonnage.

RRDtool ne stocke pas les échantillons réels, mais effectue un rééchantillonnage interne des valeurs qui lui sont présentées. Néanmoins, lorsqu'une valeur de donnée est présentée avec un seul horodatage, cet horodatage se trouve à la fin de la période que la valeur représente. Notez que l'horodatage lui-même est extérieur à la période pour laquelle l'échantillon est valide. Pour plus de détails à ce sujet, voir l'explication du calcul PDP.

Le temps de début d'une période pour un échantillon avec un horodatage est donc en fait de "horodatage - pas" inclus à "horodatage" exclus.

La première ligne de la sortie de l'échantillon :

<row><t>1020611700</t><v>3.4000000000e+00</v><v>5.4400000000e+01</v></row>

signifie donc que les valeurs pour l'intervalle 1020611400 à 1020611699 étaient de 3.4 et 54.4 pour les "octets sortants" et "bits entrants et sortants" respectivement, car la valeur a été prise à 1020611700.

EXEMPLE 1

rrdtool xport \
        DEF:out=if1-inouts.rrd:outoctets:AVERAGE \
        XPORT:out:"octets sortants"

EXEMPLE 2

rrdtool xport \
        DEF:out1=if1-inouts.rrd:outoctets:AVERAGE \
        DEF:out2=if2-inouts.rrd:outoctets:AVERAGE \
        CDEF:sum=out1,out2,+ \
        XPORT:out1:"octets sortants if1" \
        XPORT:out2:"octets sortants if2" \
        XPORT:sum:"somme sortante"

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour modifier le comportement de "rrdtool xport" :

RRDCACHED_ADDRESS
Si cette variable d'environnement est définie, elle aura le même effet que l'option "--daemon" spécifiée sur la ligne de commande. Si les deux sont présents, l'argument de la ligne de commande est prioritaire.
