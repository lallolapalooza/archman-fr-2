rrsync(1) Commandes utilisateur rrsync(1)

NOM

rrsync - script pour configurer des utilisateurs rsync restreints via des connexions ssh

SYNOPSIS

rrsync [-ro|-wo] [-munge] [-no-del] [-no-lock] [-no-overwrite]  DIR

Le seul argument non optionnel spécifie le DIR restreint à utiliser. Il peut être relatif au répertoire personnel de l'utilisateur ou un chemin absolu.

La version en ligne de cette page de manuel (qui inclut des liens croisés entre les sujets) est disponible sur https://download.samba.org/pub/rsync/rrsync.1.

DESCRIPTION

La connexion ssh d'un utilisateur peut être restreinte pour ne permettre que l'exécution d'un transfert rsync de deux manières simples :

o
forcer l'exécution du script rrsync
o
forcer l'exécution d'une commande rsync daemon sur ssh.

Ces deux configurations utilisent une fonctionnalité de ssh qui permet de forcer l'exécution d'une commande au lieu d'un shell interactif. Cependant, si le shell personnel de l'utilisateur est bash, veuillez consulter PROBLÈME DE SÉCURITÉ BASH pour un problème potentiel.

Pour utiliser le script rrsync, modifiez le fichier ~/.ssh/authorized_keys de l'utilisateur et ajoutez un préfixe comme l'un des suivants (suivi d'un espace) devant chaque ligne de clé ssh qui doit être restreinte :

command="rrsync DIR"
command="rrsync -ro DIR"
command="rrsync -munge -no-del DIR"

Assurez-vous ensuite que le script rrsync possède les restrictions d'options souhaitées. Vous voudrez peut-être copier le script dans un répertoire bin local avec un nom unique si vous souhaitez avoir plusieurs configurations. Une ou plusieurs options rrsync peuvent être spécifiées avant le DIR si vous souhaitez restreindre davantage le transfert.

Pour utiliser une configuration rsync daemon, modifiez le fichier ~/.ssh/authorized_keys de l'utilisateur et ajoutez un préfixe comme l'un des suivants (suivi d'un espace) devant chaque ligne de clé ssh qui doit être restreinte :

command="rsync --server --daemon ."
command="rsync --server --daemon --config=/CHEMIN/VERS/rsyncd.conf ."

Assurez-vous ensuite que le fichier rsyncd.conf est créé avec un ou plusieurs noms de module avec le chemin et les restrictions d'options appropriés. Si l'option --config de rsync est omise, elle utilise par défaut ~/rsyncd.conf. Voir la page de manuel rsyncd.conf(5) pour les détails sur la configuration d'un rsync daemon.

Lors de l'utilisation de rrsync, il ne peut y avoir qu'un seul répertoire restreint par clé autorisée. Une configuration daemon, en revanche, autorise plusieurs noms de module dans le fichier de configuration, chacun avec son propre paramètre de chemin.

Le reste de cette page de manuel est consacré à l'utilisation du script rrsync.

OPTIONS

-ro
Autoriser uniquement la lecture depuis le DIR. Implique -no-del et -no-lock.
-wo
Autoriser uniquement l'écriture dans le DIR.
-munge
Activer --munge-links de rsync côté serveur.
-no-del
Désactiver les options --delete* et --remove* de rsync.
-no-lock
Éviter la vérification du verrouillage d'exécution unique (par utilisateur). Utile avec -munge.
-no-overwrite
Forcer --ignore-existing côté serveur. Empêche la réécriture des fichiers existants lorsque le serveur est le récepteur.
-help, -h
Afficher ce message d'aide et quitter.

RESTRICTIONS DE SÉCURITÉ

Le script rrsync valide les arguments de chemin qu'il reçoit pour tenter de les restreindre à rester dans le DIR spécifié.

Le script rrsync rejette l'option --copy-links de rsync (par défaut) afin qu'une copie ne puisse pas déréférencer un lien symbolique dans le DIR pour atteindre un fichier en dehors du DIR.

Le script rrsync rejette l'option --protect-args (-s) de rsync car elle permettrait d'envoyer des options au serveur qui ne peuvent pas être vérifiées par le script. Si vous souhaitez prendre en charge --protect-args, utilisez une configuration daemon sur ssh.

Le script rrsync accepte seulement un sous-ensemble des options de rsync que le véritable rsync utilise lors de l'exécution de la commande serveur. Quelques options supplémentaires de commodité sont également incluses pour l'aider à interagir avec BackupPC et à accepter certains remplacements pratiques par l'utilisateur.

Le script (ou une copie de celui-ci) peut être modifié manuellement si vous souhaitez personnaliser la gestion des options.

PROBLÈME DE SÉCURITÉ BASH

Si vos utilisateurs ont bash comme shell personnel, bash peut essayer d'être trop serviable et de s'assurer que les fichiers bashrc personnels de l'utilisateur sont exécutés avant d'exécuter la commande forcée. Cela peut être un problème si l'utilisateur peut d'une manière ou d'une autre mettre à jour ses fichiers bashrc personnels, peut-être via la copie restreinte, un répertoire personnel partagé, ou quelque chose de similaire.

Une façon simple d'éviter le problème est de passer l'utilisateur à un shell plus simple, comme dash. Lors du choix du nouveau shell personnel, assurez-vous de ne pas choisir bash déguisé, car il n'est pas clair s'il évite le problème de sécurité.

Une autre solution potentielle est de s'assurer que le répertoire personnel de l'utilisateur n'est pas un montage partagé et qu'il n'a aucun moyen de copier des fichiers en dehors de ses répertoires restreints. Cela peut nécessiter que vous forciez l'activation du « symlink munging » côté serveur.

Une future version d'openssh pourrait modifier la gestion des commandes forcées pour éviter d'utiliser le shell personnel de l'utilisateur.

EXEMPLES

Le fichier ~/.ssh/authorized_keys pourrait contenir des lignes comme celle-ci :

command="rrsync client/logs" ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIEAzG...
command="rrsync -ro results" ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIEAmk...

FICHIERS

NOM

rrsync - copie de sauvegarde incrémentielle améliorée

SYNOPIS

rrsync [OPTION...] SOURCE... DEST

DESCRIPTION

rrsync est un script shell qui synchronise les fichiers de SOURCE vers DEST en utilisant rsync.

rrsync essaie de détecter si rsync est utilisé pour la sauvegarde et, si c'est le cas, il utilise des options appropriées pour optimiser la synchronisation et éviter les problèmes potentiels.

Les options par défaut sont :

  • --archive-mode=push
  • --hard-links
  • --recursive
  • --perms
  • --owner
  • --group
  • --times
  • --verbose
  • --delete
  • --compress

Ces options peuvent être remplacées par les options spécifiées dans la ligne de commande.

OPTIONS

-h, --help
Affiche l'aide et quitte.
-V, --version
Affiche les informations de version et quitte.
-v, --verbose
Augmente la verbosité. Peut être spécifié plusieurs fois.
-d, --delete
Supprime les fichiers dans la destination qui n'existent plus dans la source.
-c, --compress
Compresse les données pendant le transfert.

RESTRICTIONS DE SÉCURITÉ

rrsync utilise rsync pour effectuer la copie. Les restrictions de sécurité s'appliquent à rsync. Il est recommandé de lire attentivement la page de manuel de rsync pour comprendre les implications de sécurité.

En particulier, l'option --delete peut entraîner la perte de données si elle est utilisée de manière incorrecte.

PROBLÈME DE SÉCURITÉ BASH

Ce script utilise des fonctionnalités de Bash qui peuvent être vulnérables si le script n'est pas exécuté dans un environnement sécurisé. Par exemple, l'expansion de la commande et l'utilisation de variables non validées peuvent entraîner des problèmes de sécurité.

Il est fortement recommandé de ne pas exécuter ce script avec des privilèges root, sauf si vous comprenez parfaitement les risques.

EXEMPLES

Sauvegarde du répertoire personnel vers un disque externe :

rrsync -d --compress /home/utilisateur /media/disque_externe/backup

FICHIERS

Aucun fichier spécifique n'est géré par rrsync au-delà de la source et de la destination.

VOIR AUSSI
