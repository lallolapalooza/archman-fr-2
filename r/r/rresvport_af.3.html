rcmd(3) Manuel des fonctions de bibliothèque rcmd(3)

NOM

rcmd, rresvport, iruserok, ruserok, rcmd_af, rresvport_af, iruserok_af, ruserok_af - routines pour retourner un flux vers une commande distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <netdb.h>    /* Ou <unistd.h> sur certains systèmes */
int rcmd(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p);
int rresvport(int *port);
int iruserok(uint32_t raddr, int superuser,
            const char *ruser, const char *luser);

            const char *ruser, const char *luser);
int rcmd_af(char **restrict ahost, unsigned short inport,
            const char *restrict locuser,
            const char *restrict remuser,
            const char *restrict cmd, int *restrict fd2p,
            sa_family_t af);
int rresvport_af(int *port, sa_family_t af);
int iruserok_af(const void *restrict raddr, int superuser,
            const char *restrict ruser, const char *restrict luser,
            sa_family_t af);
int ruserok_af(const char *rhost, int superuser,
            const char *ruser, const char *luser,

DESCRIPTION

La fonction rcmd() est utilisée par le superutilisateur pour exécuter une commande sur une machine distante en utilisant un schéma d'authentification basé sur des numéros de ports privilégiés. La fonction rresvport() renvoie un descripteur de fichier vers un socket avec une adresse dans l'espace des ports privilégiés. Les fonctions iruserok() et ruserok() sont utilisées par les serveurs pour authentifier les clients demandant un service avec rcmd(). Les quatre fonctions sont utilisées par le serveur rshd(8) (entre autres).

rcmd()

La fonction rcmd() recherche l'hôte *ahost en utilisant gethostbyname(3), retournant -1 si l'hôte n'existe pas. Sinon, *ahost est défini au nom standard de l'hôte et une connexion est établie vers un serveur résidant au port Internet bien connu inport.

Si la connexion réussit, un descripteur de socket dans le domaine Internet de type SOCK_STREAM est retourné à l'appelant, et donné à la commande distante comme stdin et stdout. Si fd2p est non nul, alors un canal auxiliaire vers un processus de contrôle sera configuré, et un descripteur de fichier pour celui-ci sera placé dans *fd2p. Le processus de contrôle retournera les sorties diagnostiques de la commande (unité 2) sur ce canal, et acceptera également des octets sur ce canal comme étant des numéros de signaux UNIX, à transmettre au groupe de processus de la commande. Si fd2p est 0, alors le stderr (unité 2 de la commande distante) sera rendu identique à stdout et aucune disposition n'est prise pour envoyer des signaux arbitraires au processus distant, bien que vous puissiez être en mesure d'attirer son attention en utilisant des données hors bande.

Le protocole est décrit en détail dans rshd(8).

rresvport()

La fonction rresvport() est utilisée pour obtenir un socket avec un port privilégié qui lui est lié. Ce socket est approprié pour être utilisé par rcmd() et plusieurs autres fonctions. Les ports privilégiés sont ceux dans la plage 0 à 1023. Seul un processus privilégié (sous Linux, un processus ayant la capacité CAP_NET_BIND_SERVICE dans l'espace de noms utilisateur régissant son espace de noms réseau) est autorisé à se lier à un port privilégié. Dans l'implémentation glibc, cette fonction restreint sa recherche aux ports de 512 à 1023. L'argument port est en valeur-résultat : la valeur qu'il fournit à l'appel est utilisée comme point de départ pour une recherche circulaire de la plage de ports ; lors du retour (réussi), il contient le numéro de port qui a été lié.

iruserok() et ruserok()

Les fonctions iruserok() et ruserok() prennent l'adresse IP ou le nom de l'hôte distant, respectivement, deux noms d'utilisateur et un indicateur indiquant si le nom de l'utilisateur local est celui du superutilisateur. Ensuite, si l'utilisateur n'est *pas* le superutilisateur, elle vérifie le fichier /etc/hosts.equiv. Si cette recherche n'est pas effectuée ou échoue, le fichier .rhosts dans le répertoire personnel de l'utilisateur local est vérifié pour voir si la demande de service est autorisée.

Si ce fichier n'existe pas, n'est pas un fichier régulier, est détenu par quelqu'un d'autre que l'utilisateur ou le superutilisateur, est modifiable par quiconque d'autre que le propriétaire, ou est lié de manière rigide quelque part, la vérification échoue automatiquement. Zéro est retourné si le nom de la machine est listé dans le fichier hosts.equiv, ou si le nom d'hôte et le nom d'utilisateur distant sont trouvés dans le fichier .rhosts ; sinon, iruserok() et ruserok() retournent -1. Si le domaine local (tel qu'obtenu par gethostname(2)) est le même que le domaine distant, seul le nom de la machine doit être spécifié.

Si l'adresse IP de l'hôte distant est connue, iruserok() doit être préférée à ruserok(), car elle ne nécessite pas de faire confiance au serveur DNS pour le domaine de l'hôte distant.

Variantes *_af()

Toutes les fonctions décrites ci-dessus fonctionnent avec des sockets IPv4 (AF_INET). Les variantes "_af" prennent un argument supplémentaire qui permet de spécifier la famille d'adresses du socket. Pour ces fonctions, l'argument af peut être spécifié comme AF_INET ou AF_INET6. De plus, rcmd_af() prend en charge l'utilisation de AF_UNSPEC.

VALEUR DE RETOUR

La fonction rcmd() retourne un descripteur de socket valide en cas de succès. Elle retourne -1 en cas d'erreur et affiche un message diagnostique sur la sortie d'erreur standard.

La fonction rresvport() retourne un descripteur de socket valide et lié en cas de succès. En cas d'échec, elle retourne -1 et définit errno pour indiquer l'erreur. Le code d'erreur EAGAIN est surchargé pour signifier : "Tous les ports réseau sont utilisés".

Pour des informations sur le retour de ruserok() et iruserok(), voir ci-dessus.

ruserok_af(3) - pages de manuel Linux

NOM

iruserok, iruserok_af, ruserok, ruserok_af - vérifier si un utilisateur distant est autorisé à se connecter

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXIS

C'est un peu délicat, car ces fonctions ne sont pas disponibles sur tous les systèmes, et les en-têtes peuvent ne pas les déclarer.

#include <sys/socket.h>
#include <netinet/in.h>>

int iruserok(unsigned int rport, int superuser, uid_t ruid, uid_t ruser);
int iruserok_af(int domain, unsigned int rport, int superuser, uid_t ruid, uid_t ruser);
int ruserok(const char *rhostname, int superuser, const char *ruser, const char *luser);
int ruserok_af(int domain, const char *rhostname, int superuser, const char *ruser, const char *luser);

DESCRIPTION

Ces fonctions sont utilisées par les démons de services réseau tels que rlogind(8) et rexecd(8) pour vérifier si un utilisateur distant est autorisé à se connecter ou à exécuter une commande.

La fonction ruserok(3) vérifie les informations d'authentification de l'utilisateur distant dans le fichier hosts.equiv(5) et dans le fichier ~/.rhosts de l'utilisateur local.

Si le paramètre superuser est vrai (non nul), les vérifications sont effectuées pour un processus exécuté en tant que superutilisateur. Le comportement exact dépend des options de compilation de la bibliothèque.

La fonction ruserok(3) utilise les informations d'adresse IP pour trouver le nom d'hôte de l'utilisateur distant. Si ces informations ne sont pas disponibles, la vérification échoue.

Les fonctions iruserok(3) et iruserok_af(3) sont des versions plus récentes qui prennent des adresses IP numériques et effectuent leurs propres recherches d'adresses. La fonction iruserok_af(3) prend également en compte le domaine d'adresse du socket.

Les paramètres ruid et ruser sont les ID utilisateur et les noms d'utilisateur distants. Les paramètres luser est le nom d'utilisateur local.

Les fonctions iruserok(3) et iruserok_af(3) sont préférées car elles évitent une recherche DNS potentiellement coûteuse pour le nom d'hôte distant.

VALEUR RENVOYÉE

Les fonctions renvoient 1 en cas de succès, 0 en cas d'échec.

ATTRIBUTS

Pour obtenir des informations sur les attributs de cette fonction, consultez les sections « ATTRIBUTES » du attr(7).

NORMES

Ces fonctions ne sont pas standardisées et leur disponibilité varie selon les systèmes.

HISTORIQUE

iruserok(), iruserok_af()
glibc 2.2.

Solaris, 4.2BSD. Les variantes « _af » sont des ajouts plus récents et ne sont pas présentes sur autant de systèmes.

BOGUES

Les fonctions iruserok(3) et iruserok_af(3) ne sont déclarées dans les en-têtes glibc que depuis glibc 2.12.

VOIR AUSSI

rlogin(1), rsh(1), rexec(3), rexecd(8), rlogind(8), rshd(8)
