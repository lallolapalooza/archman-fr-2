NOM

rrdthreads - Provisions pour lier la bibliothèque RRD à utiliser dans des programmes multi-threadés

SYNOPIS

L'utilisation de librrd dans des programmes multi-threadés nécessite quelques précautions supplémentaires, car la bibliothèque RRD dans sa forme originale n'était pas du tout thread-safe. Ce document décrit les exigences et les pièges pour utiliser la version multi-threadée de librrd dans vos propres programmes. Il donne également des indications pour le futur développement de RRD afin de maintenir la bibliothèque thread-safe.

Actuellement, seules certaines opérations RRD sont implémentées de manière thread-safe. Elles se terminent toutes par le suffixe habituel ""_r"".

DESCRIPTION

Afin d'utiliser librrd dans des programmes multi-threadés, vous devez :

  • Lier avec librrd_th au lieu de librrd (utilisez "-lrrd_th" lors de la liaison)
  • Utiliser les fonctions ""_r"" au lieu des fonctions API normales
  • Ne pas utiliser de spécifications de temps de style at. L'analyse de telles spécifications de temps n'est absolument pas thread-safe.
  • Ne jamais utiliser de fonctions autres que *"_r" à moins qu'il ne soit explicitement documenté que la fonction est thread-safe.
  • Chaque thread DOIT appeler "rrd_get_context()" avant son premier appel à une fonction "librrd_th" afin de configurer les données spécifiques au thread. Ce n'est pas strictement requis, mais c'est le seul moyen de tester si l'allocation mémoire peut être réalisée par cette fonction. Sinon, le programme peut planter avec un SIGSEGV dans une situation de manque de mémoire.
  • Toujours appeler "rrd_error_clear()" avant tout appel à la bibliothèque. Sinon, l'appel pourrait échouer en raison d'une erreur antérieure.

NOTES POUR LES CONTRIBUTEURS RRD

Certaines précautions doivent être suivies lors du développement de RRD à partir de maintenant :

•
Utiliser uniquement des fonctions thread-safe dans le code de la bibliothèque. De nombreuses fonctions libc couramment utilisées ne sont pas thread-safe. Faites attention dans les situations suivantes ou lorsque vous utilisez les fonctions de bibliothèque suivantes :
  • Les appels directs à "strerror()" doivent être évités : utilisez plutôt "rrd_strerror()", il fournit un message d'erreur par thread.
  • Les familles de fonctions "getpw*", "getgr*", "gethost*" (et d'autres fonctions "get*") ne sont pas thread-safe : utilisez les variantes *"_r"
  • Fonctions temporelles : "asctime", "ctime", "gmtime", "localtime" : utilisez les variantes *"_r"
  • "strtok" : utilisez "strtok_r"
  • "tmpnam" : utilisez "tmpnam_r"
  • Beaucoup d'autres (consultez la documentation)
  • Un fichier d'en-tête nommé rrd_is_thread_safe.h est fourni, qui fonctionne avec le préprocesseur C GNU pour "empoisonner" certaines des fonctions non thread-safe les plus courantes en utilisant la directive "#pragma GCC poison". Il suffit d'inclure cet en-tête dans les fichiers source que vous souhaitez conserver thread-safe.
  • Ne pas introduire de variables globales !

    Si vous devez absolument utiliser une variable globale, vous pouvez ajouter un nouveau champ à la structure "rrd_context" et modifier rrd_error.c, rrd_thread_safe.c et rrd_non_thread_safe.c

  • Ne pas utiliser "getopt" ou "getopt_long" dans les fonctions *"_r" (ni directement ni indirectement).

    "getopt" utilise des variables globales et se comporte mal dans une application multi-threadée lorsqu'elle est appelée simultanément. Fournissez plutôt une fonction *_r prenant toutes les options en paramètres de fonction. Vous pouvez fournir des arguments argc et **argv pour les listes d'arguments de longueur variable. Voir "rrd_update_r" comme exemple.

  • Ne pas utiliser la fonction "rrd_parsetime" !

    Elle utilise beaucoup de variables globales. Vous pouvez l'utiliser dans des fonctions non conçues pour être thread-safe, comme dans les fonctions enveloppant la version "_r" d'une opération (par exemple, "rrd_create", mais pas dans "rrd_create_r")

FONCTIONS THREAD-SAFE ACTUELLEMENT IMPLÉMENTÉES

Actuellement, il existe des variantes thread-safe de "rrd_update", "rrd_create", "rrd_dump", "rrd_info", "rrd_last" et "rrd_fetch".
