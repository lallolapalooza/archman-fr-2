NOM

rrdgraph - Fonctions de graphe pour Round Robin Database

SYNTAXE

rrdtool graph|graphv nom_fichier [option ...] [définition de données ...] [calcul de données ...] [définition de variable ...] [élément de graphe ...] [élément d'impression ...]

DESCRIPTION

La fonction graph de RRDtool est utilisée pour présenter les données d'une RRD à un spectateur humain. Son objectif principal est de créer une représentation graphique agréable, mais elle peut également générer un rapport numérique.

VUE D'ENSEMBLE

rrdtool graph a besoin de données pour fonctionner, vous devez donc utiliser une ou plusieurs déclarations de définition de données pour collecter ces données. Vous n'êtes pas limité à une seule base de données, il est tout à fait légal de collecter des données de deux bases de données ou plus (une par déclaration, cependant).

Si vous souhaitez afficher des moyennes, des maxima, des percentiles, etc., il est préférable de les collecter maintenant en utilisant la déclaration de définition de variable. Actuellement, cela ne fait aucune différence, mais dans une future version de RRDtool, vous pourriez vouloir collecter ces valeurs avant la consolidation.

Les données récupérées de la RRA sont ensuite consolidées de sorte qu'il y ait exactement un point de données par pixel dans le graphe. Si vous n'y prenez pas garde vous-même, RRDtool étendra la plage légèrement si nécessaire. Notez que, dans ce cas, le premier et/ou le dernier pixel pourraient très bien devenir inconnus !

Parfois, les données ne sont pas exactement dans le format que vous aimeriez afficher. Par exemple, vous pourriez collecter des octets par seconde, mais vouloir afficher des bits par seconde. C'est pour cela que la commande de calcul de données est conçue. Après avoir consolidé les données, une copie est faite et cette copie est modifiée à l'aide d'un ensemble de commandes RPN assez puissantes.

Lorsque vous avez terminé la récupération et le traitement des données, il est temps de les représenter graphiquement (ou de les imprimer). Cela termine la séquence rrdtool graph.

Utilisez graphv au lieu de graph pour obtenir des informations détaillées sur la géométrie et les données du graphe une fois qu'il est dessiné. Voir le bas du document pour plus d'informations.

OPTIONS

nom_fichier

Le nom et le chemin du graphe à générer. Il est recommandé de terminer par ".png", ".svg" ou ".eps", mais RRDtool ne l'impose pas.

nom_fichier peut être '"-"' pour envoyer l'image à "stdout". Dans ce cas, aucune autre sortie n'est générée.

Plage temporelle

[-s|--start temps] [-e|--end temps] [-S|--step secondes]

Le début et la fin de la série temporelle que vous souhaitez afficher, et de quelle RRA proviennent les données. Les valeurs par défaut sont : il y a 1 jour jusqu'à maintenant, avec la meilleure résolution possible. Start et end peuvent être spécifiés dans plusieurs formats, voir "SPÉCIFICATION DE TEMPS STYLE AT" dans rrdfetch et rrdgraph_examples. Par défaut, rrdtool graph calcule la largeur d'un pixel dans le domaine temporel et essaie d'obtenir des données d'une RRA avec cette résolution. Avec l'option step, vous pouvez modifier ce comportement. Si vous voulez que rrdtool graph obtienne des données à une résolution horaire de la RRD, définissez step à 3600. Note : un pas inférieur à un pixel sera silencieusement ignoré.

Pour les --imgformats non-image, voir "FORMAT DE SORTIE" dans rrdxport pour les détails sur la manière dont cela affecte la sortie.

Étiquettes

[-t|--title chaîne]

Une chaîne horizontale placée en haut du graphe, qui peut être séparée en plusieurs lignes en utilisant <br/> ou \n

[-v|--vertical-label chaîne]

Une chaîne verticale placée sur le côté gauche du graphe.

Taille

[-w|--width pixels] [-h|--height pixels] [-j|--only-graph] [-D|--full-size-mode]

Par défaut, la largeur et la hauteur de la zone de dessin (la partie contenant les données réelles et autres). Par défaut : 400 pixels par 100 pixels.

Si vous spécifiez l'option --full-size-mode, la largeur et la hauteur spécifient les dimensions finales de l'image de sortie et la zone de dessin est automatiquement redimensionnée pour s'adapter.

Si vous spécifiez l'option --only-graph et définissez la hauteur < 32 pixels, vous obtiendrez une image de graphe minuscule (vignette) à utiliser comme icône dans un aperçu, par exemple. Toutes les étiquettes seront retirées du graphe.

Limites

[-u|--upper-limit valeur] [-l|--lower-limit valeur] [-r|--rigid] [--allow-shrink]

Par défaut, le graphe est mis à l'échelle automatique afin d'ajuster l'axe des Y à la plage des données. Vous pouvez modifier ce comportement en définissant explicitement les limites. L'axe des Y affiché s'étendra alors au moins de lower-limit à upper-limit. La mise à l'échelle automatique permettra toujours d'étirer ces limites, sauf si l'option rigid est définie. allow-shrink modifie le comportement de rigid en autorisant la mise à l'échelle automatique vers le bas ; le graphe ne dépassera pas les limites spécifiées par l'utilisateur.

[-A|--alt-autoscale]

Parfois, l'algorithme par défaut pour sélectionner l'échelle de l'axe des Y n'est pas satisfaisant. Normalement, l'échelle est sélectionnée parmi un ensemble prédéfini de plages et cela échoue lamentablement lorsque vous devez représenter graphiquement quelque chose comme "260 + 0.001 * sin(x)". Cette option calcule le minimum et le maximum de l'axe des Y à partir des valeurs minimales et maximales réelles des données. Notre exemple afficherait légèrement moins de "260-0.001" à légèrement plus de "260+0.001" (cette fonctionnalité a été contribuée par Sasha Mikheev).

[-J|--alt-autoscale-min]

Alors que "--alt-autoscale" modifiera les valeurs maximales ET minimales absolues, cette option n'affectera que la valeur minimale. La valeur maximale, si elle n'est pas définie sur la ligne de commande, sera 0. Cette option peut être utile lors de la représentation graphique du trafic d'un routeur lorsque la ligne WAN utilise la compression, et donc le débit peut être supérieur à la vitesse de la ligne WAN.

[-M|--alt-autoscale-max]

Alors que "--alt-autoscale" modifiera les valeurs maximales ET minimales absolues, cette option n'affectera que la valeur maximale. La valeur minimale, si elle n'est pas définie sur la ligne de commande, sera 0. Cette option peut être utile lors de la représentation graphique du trafic d'un routeur lorsque la ligne WAN utilise la compression, et donc le débit peut être supérieur à la vitesse de la ligne WAN.

[-N|--no-gridfit]

Afin d'éviter les effets de flou d'anticrénelage, RRDtool accroche les points à la résolution des pixels de l'appareil, ce qui donne une apparence plus nette. Si cela ne vous convient pas, vous pouvez utiliser ce commutateur pour désactiver ce comportement.

L'ajustement de la grille est désactivé par défaut pour les sorties PDF, EPS, SVG.

Axe X

[-x|--x-grid GTM:GST:MTM:MST:LTM:LST:LPR:LFM]

[-x|--x-grid none]

L'étiquette de l'axe X est assez complexe à configurer. Si vous n'avez pas de besoins très spéciaux, il est probablement préférable de vous fier à la configuration automatique pour bien faire les choses. Vous pouvez spécifier la chaîne "none" pour supprimer complètement la grille et les étiquettes.

La grille est définie en spécifiant une certaine durée en temps dans les positions ?TM. Vous pouvez choisir parmi "SECOND", "MINUTE", "HOUR", "DAY", "WEEK", "MONTH" ou "YEAR". Ensuite, vous définissez combien de celles-ci doivent passer entre chaque ligne ou étiquette. Ceci

pair (?TM:?ST) doit être spécifiée pour la grille de base (G??), la grille majeure (M??) et les étiquettes (L??). Pour les étiquettes, vous devez également définir une précision dans LPR et une chaîne de format strftime dans LFM. LPR définit où chaque étiquette sera placée. S'il est zéro, l'étiquette sera placée juste sous la ligne correspondante (utile pour les heures, les dates, etc.). Si vous spécifiez un nombre de secondes ici, l'étiquette sera centrée sur cet intervalle (utile pour lundi, janvier, etc.).

--x-grid MINUTE:10:HOUR:1:HOUR:4:0:%X

Ceci place des lignes de grille toutes les 10 minutes, des lignes de grille majeures toutes les heures et des étiquettes toutes les 4 heures. Les étiquettes sont placées sous les lignes de grille majeures car elles spécifient exactement cette heure.

--x-grid HOUR:8:DAY:1:DAY:1:86400:%A

Ceci place des lignes de grille toutes les 8 heures, des lignes de grille majeures et des étiquettes chaque jour. Les étiquettes sont placées exactement entre deux lignes de grille majeures car elles spécifient le jour complet et pas seulement minuit.

[--week-fmt chaîne de format strftime]

Par défaut, rrdtool utilise "Week %V" pour afficher le numéro de la semaine. Avec cette option, vous pouvez définir votre propre format, sans écraser complètement le format de l'axe x.

Axe Y

[-y|--y-grid pas de grille:facteur d'étiquette]

[-y|--y-grid none]

Les lignes de grille de l'axe Y apparaissent à chaque intervalle de pas de grille. Les étiquettes sont placées toutes les facteur d'étiquette lignes. Vous pouvez spécifier "-y none" pour supprimer complètement la grille et les étiquettes. La valeur par défaut pour cette option est de sélectionner automatiquement des valeurs raisonnables.

Si vous avez défini --y-grid sur 'none', non seulement les étiquettes sont supprimées, mais aussi l'espace réservé aux étiquettes est supprimé. Vous pouvez toujours ajouter de l'espace manuellement si vous utilisez la commande --units-length pour réserver explicitement de l'espace.

[--left-axis-formatter nom du formateur]

Spécifie quel formateur utiliser pour afficher les valeurs de l'axe.

numeric
Par défaut, les valeurs sont exprimées en quantités numériques.
timestamp
Les valeurs sont interprétées comme des timestamps Unix (nombre de secondes depuis le 1970-01-01 00:00:00 UTC) et exprimées à l'aide du format strftime (par défaut '%Y-%m-%d %H:%M:%S'). Voir aussi --units-length et --left-axis-format.
duration
Les valeurs sont interprétées comme des durées en millisecondes. Le formatage suit les règles de valstrfduration qualifié PRINT/GPRINT. Voir rrdgraph_graph.

[--left-axis-format chaîne de format]

Par défaut, le format des étiquettes de l'axe est déterminé automatiquement. Si vous souhaitez le faire vous-même, utilisez cette option avec les mêmes arguments %lf que vous connaissez des commandes PRINT et GPRINT, ou d'autres si vous utilisez un formateur différent.

[-Y|--alt-y-grid]

Place la grille Y dynamiquement en fonction de la plage Y du graphique. L'algorithme garantit que vous avez toujours une grille, qu'il y a suffisamment mais pas trop de lignes de grille, et que la grille est métrique. C'est-à-dire que les lignes de grille sont placées tous les 1, 2, 5 ou 10 unités. Ce paramètre garantira également que suffisamment de décimales sont affichées même si votre graphique va de 69.998 à 70.001. (contribué par Sasha Mikheev).

[-o|--logarithmic]

Mise à l'échelle logarithmique de l'axe Y.

[-X|--units-exponent valeur]

Ceci définit la mise à l'échelle 10**exponentielle des valeurs de l'axe Y. Normalement, les valeurs seront mises à l'échelle selon les unités appropriées (k, M, etc.). Cependant, vous pourriez souhaiter afficher les unités toujours en k (Kilo, 10e3) même si les données sont dans la plage M (Méga, 10e6), par exemple. La valeur doit être un entier multiple de 3 compris entre -18 et 18 inclusivement. C'est l'exposant des unités que vous souhaitez utiliser. Par exemple, utilisez 3 pour afficher les valeurs de l'axe Y en k (Kilo, 10e3, milliers), utilisez -6 pour afficher les valeurs de l'axe Y en u (Micro, 10e-6, millionièmes). Utilisez une valeur de 0 pour empêcher toute mise à l'échelle des valeurs de l'axe Y.

Cette option est très efficace pour dérouter la fonction d'auto-mise à l'échelle et le peintre de grille par défaut de RRDtool. Si RRDtool détecte qu'il ne parvient pas à étiqueter le graphique dans les circonstances données, il passera en mode --alt-y-grid plus robuste.

[-L|--units-length valeur]

Combien de chiffres RRDtool doit-il supposer que les étiquettes de l'axe Y ont ? Vous devrez peut-être utiliser cette option pour faire suffisamment de place une fois que vous commencerez à modifier l'étiquetage de l'axe Y.

[--units=si]

Avec cette option, les valeurs de l'axe Y sur les graphiques logarithmiques seront mises à l'échelle selon les unités appropriées (k, M, etc.) au lieu d'utiliser la notation exponentielle. Notez que pour les graphiques linéaires, la notation SI est utilisée par défaut.

Axe Y Droit

[--right-axis échelle:décalage] [--right-axis-label étiquette]

Un second axe sera dessiné à droite du graphique. Il est lié à l'axe gauche via les paramètres d'échelle et de décalage. Vous pouvez également définir une étiquette pour l'axe droit.

[--right-axis-formatter nom du formateur]

Spécifie quel formateur utiliser pour afficher les valeurs de l'axe.

numeric
Par défaut, les valeurs sont exprimées en quantités numériques.
timestamp
Les valeurs sont interprétées comme des timestamps Unix (nombre de secondes depuis le 1970-01-01 00:00:00 UTC) et exprimées à l'aide du format strftime (par défaut '%Y-%m-%d %H:%M:%S'). Voir aussi --units-length et --right-axis-format.
duration
Les valeurs sont interprétées comme des durées en millisecondes. Le formatage suit les règles de valstrfduration qualifié PRINT/GPRINT. Voir rrdgraph_graph.

[--right-axis-format chaîne de format]

Par défaut, le format des étiquettes de l'axe est déterminé automatiquement. Si vous souhaitez le faire vous-même, utilisez cette option avec les mêmes arguments %lf que vous connaissez des commandes PRINT et GPRINT, ou d'autres si vous utilisez un formateur différent.

Légende

[-g|--no-legend]

Supprime la génération de la légende ; affiche uniquement le graphique.

[-F|--force-rules-legend]

Force la génération des légendes HRULE et VRULE même si ces HRULE ou VRULE ne seront pas dessinées car hors des limites du graphique (imite le comportement des versions antérieures à 1.0.42).

[--legend-position=(north|south|west|east)]

Place la légende du côté donné du graphique. Par défaut, c'est south. En position ouest ou est, il est nécessaire d'ajouter des sauts de ligne manuellement.

[--legend-direction=(topdown|bottomup|bottomup2)]

Place les éléments de la légende dans l'ordre vertical donné. Par défaut, c'est topdown. En utilisant bottomup, les éléments de la légende apparaissent dans le même ordre vertical qu'une pile de lignes ou de zones. En utilisant bottomup2, les lignes COMMENT de début et de fin seront conservées dans l'ordre, ce qui peut être utile pour les générateurs qui les utilisent pour les en-têtes de table, etc.

Divers

[-z|--lazy]

Génère le graphique uniquement si le graphique actuel est obsolète ou inexistant. Notez que tous les calculs seront effectués indépendamment, de sorte que la sortie de PRINT et graphv sera complète quoi qu'il arrive. Notez que le comportement de lazy à cet égard a connu plusieurs changements au fil du temps. La seule chose sur laquelle vous pouvez vraiment compter avant RRDtool 1.3.7 est que lazy ne générera pas le graphique lorsqu'il est déjà là et à jour, et qu'il affichera également la taille du graphique.

[-d|--daemon adresse]

Adresse du démon rrdcached. Si spécifié, une commande "flush" est envoyée au serveur avant de lire les fichiers RRD. Cela permet au graphique de contenir des données fraîches même si le démon est configuré pour mettre en cache les valeurs pendant longtemps. Pour une liste des formats acceptés, voir l'option -l dans le manuel de rrdcached.

rrdtool graph [...] --daemon unix:/var/run/rrdcached.sock [...]

[-f|--imginfo printfstr]

Après la création de l'image, la fonction graph utilise printf avec cette chaîne de format pour créer une sortie similaire à la fonction PRINT, seulement la fonction printf est fournie avec les paramètres nom de fichier, taille x et taille y. Afin de générer une balise IMG appropriée pour inclure le graphique dans une page web, la ligne de commande ressemblerait à ceci :

--imginfo '<IMG SRC="/img/%s" WIDTH="%lu" HEIGHT="%lu" ALT="Demo">'

[-c|--color TAGCOULEUR#rrggbb[aa]]

Remplace les couleurs par défaut des éléments standard du graphique. Le TAGCOULEUR est l'un des suivants : "BACK" arrière-plan, "CANVAS" pour l'arrière-plan du graphique réel, "SHADEA" pour la bordure gauche et supérieure, "SHADEB" pour la bordure droite et inférieure, "GRID", "MGRID" pour la grille majeure, "FONT" pour la couleur de la police, "AXIS" pour l'axe du graphique, "FRAME" pour la ligne autour des spots de couleur, et enfin "ARROW" pour la pointe de flèche pointant vers le haut et vers l'avant. Chaque couleur est composée de trois nombres hexadécimaux spécifiant son composant de couleur RVB (00 est désactivé, FF est maximum) de rouge, vert et bleu. Facultativement, vous pouvez ajouter un autre nombre hexadécimal spécifiant la transparence (FF est solide). Vous pouvez définir cette option plusieurs fois pour modifier plusieurs valeurs par défaut.

Une flèche verte est créée par : "--color ARROW#00FF00"

[--grid-dash on:off]

Par défaut, la grille est dessinée selon un motif 1 activé, 1 désactivé. Avec cette option, vous pouvez le définir vous-même.

--grid-dash 1:3    pour une grille en pointillés
--grid-dash 1:0    pour des lignes de grille ininterrompues

[--border largeur]

Largeur en pixels pour la bordure 3D dessinée autour de l'image

OPTIONS

[--border width:color]

Sets the border width and color. Setting width to 0 disables the border. See "SHADEA" and "SHADEB" above for setting the border color.

[--dynamic-labels]

Pick the shape of the color marker next to the label according to the element drawn on the graph.

[-m|--zoom factor]

Zoom the graphics by the given amount. The factor must be > 0

[-n|--font FONTTAG:size[:font]]

This lets you customize which font to use for the various text elements on the RRD graphs. "DEFAULT" sets the default value for all elements, "TITLE" for the title, "AXIS" for the axis labels, "UNIT" for the vertical unit label, "LEGEND" for the graph legend, "WATERMARK" for the watermark on the edge of the graph.

Use Times for the title: "--font TITLE:13:Times"

Note that you need to quote the argument to --font if the font-name contains whitespace: --font "TITLE:13:Some Font"

If you do not give a font string you can modify just the size of the default font: "--font TITLE:13:".

If you specify the size 0 then you can modify just the font without touching the size. This is especially useful for altering the default font without resetting the default fontsizes: "--font DEFAULT:0:Courier".

RRDtool comes with a preset default font. You can set the environment variable "RRD_DEFAULT_FONT" if you want to change this.

RRDtool uses Pango for its font handling. This means that you can use the full Pango syntax when selecting your font:

The font name has the form "[FAMILY-LIST] [STYLE-OPTIONS] [SIZE]", where FAMILY-LIST is a comma separated list of families optionally terminated by a comma, STYLE_OPTIONS is a whitespace separated list of words where each WORD describes one of style, variant, weight, stretch, or gravity, and SIZE is a decimal number (size in points) or optionally followed by the unit modifier "px" for absolute size. Any one of the options may be absent.

[-R|--font-render-mode {normal,light,mono}]

There are 3 font render modes:

normal: Full Hinting and Anti-aliasing (default)

light: Slight Hinting and Anti-aliasing

mono: Full Hinting and NO Anti-aliasing

[-B|--font-smoothing-threshold size]

(this gets ignored in 1.3 for now!)

This specifies the largest font size which will be rendered bitmapped, that is, without any font smoothing. By default, no text is rendered bitmapped.

[-P|--pango-markup]

All text in RRDtool is rendered using Pango. With the --pango-markup option, all text will be processed by pango markup. This allows one to embed some simple html like markup tags using

<span key="value">text</span>

Apart from the verbose syntax, there are also the following short tags available.

b     Bold
big   Makes font relatively larger, equivalent to <span size="larger">
i     Italic
s     Strikethrough
sub   Subscript
sup   Superscript
small Makes font relatively smaller, equivalent to <span size="smaller">
tt    Monospace font
u     Underline

More details on http://developer.gnome.org/pango/stable/PangoMarkupFormat.html.

[-G|--graph-render-mode {normal,mono}]

There are 2 render modes:

normal: Graphs are fully Anti-aliased (default)

mono: No Anti-aliasing

[-E|--slope-mode]

RRDtool graphs are composed of stair case curves by default. This is in line with the way RRDtool calculates its data. Some people favor a more 'organic' look for their graphs even though it is not all that true.

[-a|--imgformat PNG|SVG|EPS|PDF|XML|XMLENUM|JSON|JSONTIME|CSV|TSV|SSV]

Image format for the generated graph. For the vector formats you can choose among the standard Postscript fonts Courier-Bold, Courier-BoldOblique, Courier-Oblique, Courier, Helvetica-Bold, Helvetica-BoldOblique, Helvetica-Oblique, Helvetica, Symbol, Times-Bold, Times-BoldItalic, Times-Italic, Times-Roman, and ZapfDingbats.

For Export type you can define XML, XMLENUM (enumerates the value tags <v0>,<v1>,<v2>,...), JSON, JSONTIME (adds a timestamp to each data row), CSV (=comma separated values), TSV (=tab separated values), SSV (=semicolon separated values), (for comma/tab/semicolon separated values the time format by default is in the form of unix time. to change it to something else use: --x-grid MINUTE:10:HOUR:1:HOUR:4:0:"%Y-%m-%d %H:%M:%S")

For non-image --imgformats see "OUTPUT FORMAT" in rrdxport for details on the output.

[-i|--interlaced]

(this gets ignored in 1.3 for now!)

If images are interlaced they become visible on browsers more quickly.

[-T|--tabwidth value]

By default the tab-width is 40 pixels, use this option to change it.

[-b|--base value]

If you are graphing memory (and NOT network traffic) this switch should be set to 1024 so that one Kb is 1024 byte. For traffic measurement, 1 kb/s is 1000 b/s.

[-W|--watermark string]

Adds the given string as a watermark, horizontally centered, at the bottom of the graph.

[-Z|--use-nan-for-all-missing-data]

If one DS is missing, either because the RRD is not available or because it does not contain the requested DS name, just assume that we got empty values instead of raising a fatal error.

[--add-jsontime]

Adds xport data in JSONTIME format, giving both graph image data and data point values in one call to graphv command.

[--utc]

Force the timezone to be UTC. Equivalent to doing TZ=UTC rrdtool graph .... This is useful to calculate daily average ranging from midnight to midnight rather than say the last 24 hours.

Data and variables

DEF:vname=rrdfile:ds-name:CF[:step=step][:start=time][:end=time]

CDEF:vname=RPN expression

VDEF:vname=RPN expression

You need at least one DEF and one LINE, AREA, GPRINT, PRINT statement to generate anything useful.

See rrdgraph_data and rrdgraph_rpn for the exact format.

NOTE: Graph and print elements

You need at least one graph element to generate an image and/or at least one print statement to generate a report. See rrdgraph_graph for the exact format.

graphv

Calling RRDtool with the graphv option will return information in the RRDtool info format. On the command line this means that all output will be in key=value format. When used from the Perl and Ruby bindings a hash pointer will be returned from the call.

When the filename '-' is given, the contents of the graph itself will also be returned through this interface (hash key 'image'). On the command line the output will look like this:

print[0] = "0.020833"
print[1] = "0.0440833"
graph_left = 51
graph_top = 22
graph_width = 400
graph_height = 100
graph_start = 1232908800
graph_end = 1232914200
image_width = 481
image_height = 154
value_min = 0.0000000000e+00
value_max = 4.0000000000e-02
image = BLOB_SIZE:8196
[... 8196 bytes of image data ...]

There is more information returned than in the standard interface. Especially the 'graph_*' keys are new. They help applications that want to know what is where on the graph.

ENVIRONMENT VARIABLES

The following environment variables may be used to change the behavior of "rrdtool graph":

RRDCACHED_ADDRESS
If this environment variable is set it will have the same effect as specifying the "--daemon" option on the command line. If both are present, the command line argument takes precedence.
RRD_DEFAULT_FONT
RRDtool comes with a preset default font. You can set the environment variable RRD_DEFAULT_FONT if you want to change this.
