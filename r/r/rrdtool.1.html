RRDTOOL(1) rrdtool RRDTOOL(1)

NOM

rrdtool - Outil de base de données Round Robin

SYNTAXE

rrdtool - [répertoire_travail]| fonction

DESCRIPTION

APERÇU

Il est assez facile de collecter des informations d'état de toutes sortes de choses, allant de la température de votre bureau au nombre d'octets qui sont passés par l'interface FDDI de votre routeur. Mais il n'est pas si trivial de stocker ces données de manière efficace et systématique. C'est là que RRDtool s'avère utile. Il vous permet d'*enregistrer et d'analyser* les données que vous collectez à partir de toutes sortes de sources de données (DS). La partie analyse de données de RRDtool repose sur la capacité à générer rapidement des représentations graphiques des valeurs de données collectées sur une période de temps définissable.

Dans cette page de manuel, vous trouverez des informations générales sur la conception et la fonctionnalité de l'outil Round Robin Database (RRDtool). Pour une description plus détaillée de l'utilisation des fonctions individuelles de RRDtool, consultez la page de manuel correspondante.

Pour une introduction à l'utilisation de RRDtool, assurez-vous de consulter le rrdtutorial.

FONCTIONS

Bien que les pages de manuel parlent d'options en ligne de commande que vous devez définir pour faire fonctionner RRDtool, il est important de noter que RRDtool peut être contrôlé à distance via un ensemble de tubes. Cela permet d'économiser un temps de démarrage considérable lorsque vous prévoyez de faire faire beaucoup de choses rapidement à RRDtool. Consultez la section sur le "CONTRÔLE À DISTANCE" plus bas. Il existe également un certain nombre de liaisons linguistiques pour RRDtool qui vous permettent de l'utiliser directement depuis Perl, Python, Tcl, PHP, etc.

create
Configurer une nouvelle base de données Round Robin (RRD). Voir rrdcreate.
update
Stocker de nouvelles valeurs de données dans une RRD. Voir rrdupdate.
updatev
Équivalent opérationnel de update sauf pour la sortie. Voir rrdupdate.
graph
Créer un graphique à partir de données stockées dans une ou plusieurs RRD. En plus de générer des graphiques, les données peuvent également être extraites vers stdout. Voir rrdgraph.
graphv
Créer un graphique à partir de données stockées dans une ou plusieurs RRD. Identique à graph, mais les métadonnées sont imprimées avant le graphique. Voir rrdgraph.
dump
Exporter le contenu d'une RRD en texte brut ASCII. En combinaison avec restore, vous pouvez l'utiliser pour déplacer une RRD d'une architecture informatique à une autre. Voir rrddump.
restore
Restaurer une RRD au format XML dans une RRD binaire. Voir rrdrestore.
fetch
Obtenir des données pour une période donnée à partir d'une RRD. La fonction graph utilise fetch pour récupérer ses données d'une RRD. Voir rrdfetch.
tune
Modifier la configuration et la structure d'une RRD. Voir rrdtune.
first
Trouver la première heure de mise à jour d'une RRD. Voir rrdfirst.
last
Trouver la dernière heure de mise à jour d'une RRD. Voir rrdlast.
lastupdate
Trouver la dernière heure de mise à jour d'une RRD. Elle renvoie également la valeur stockée pour chaque donnée lors de la dernière mise à jour. Voir rrdlastupdate.
info
Obtenir des informations sur une RRD. Voir rrdinfo.
resize
Modifier la taille des RRA individuels. C'est dangereux ! Voir rrdresize.
xport
Exporter les données récupérées d'une ou plusieurs RRD. Voir rrdxport.
flushcached
Vider les valeurs d'un fichier RRD spécifique de la mémoire. Voir rrdflushcached.
list
Lister les répertoires et les bases de données rrd à distance. Voir rrdlist.

COMMENT FONCTIONNE RRDTOOL ?

Acquisition des données
Lors de la surveillance de l'état d'un système, il est pratique d'avoir les données disponibles à un intervalle de temps constant. Malheureusement, vous ne pourrez peut-être pas toujours récupérer les données exactement au moment où vous le souhaitez. Par conséquent, RRDtool vous permet de mettre à jour le fichier journal à tout moment. Il interpolera automatiquement la valeur de la source de données (DS) au dernier créneau horaire officiel (intervalle) et écrira cette valeur interpolée dans le journal. La valeur originale que vous avez fournie est également stockée et prise en compte lors de l'interpolation de la prochaine entrée du journal.
Consolidation
Vous pouvez enregistrer des données à un intervalle de 1 minute, mais vous pourriez également être intéressé par le développement des données sur la dernière année. Vous pourriez le faire en stockant simplement les données à des intervalles de 1 minute pendant toute l'année. Bien que cela prenne un espace disque considérable, cela prendrait également beaucoup de temps pour analyser les données lorsque vous voudriez créer un graphique couvrant toute l'année. RRDtool offre une solution à ce problème grâce à sa fonctionnalité de consolidation de données. Lors de la configuration d'une base de données Round Robin (RRD), vous pouvez définir l'intervalle auquel cette consolidation doit avoir lieu, et quelle fonction de consolidation (CF) (moyenne, minimum, maximum, dernière) doit être utilisée pour construire les valeurs consolidées (voir rrdcreate). Vous pouvez définir autant de configurations de consolidation différentes que vous le souhaitez au sein d'une seule RRD. Elles seront toutes maintenues à la volée lors du chargement de nouvelles données dans la RRD.
Archives Round Robin
Les valeurs de données d'une même configuration de consolidation sont stockées dans des Archives Round Robin (RRA). C'est une manière très efficace de stocker des données pendant une certaine période, tout en utilisant une quantité d'espace de stockage connue et constante.

Cela fonctionne comme suit : Si vous souhaitez stocker 1 000 valeurs à un intervalle de 5 minutes, RRDtool allouera de l'espace pour 1 000 valeurs de données et une zone d'en-tête. Dans l'en-tête, il stockera un pointeur indiquant quels emplacements (valeurs) dans la zone de stockage ont été écrits en dernier. Les nouvelles valeurs sont écrites dans l'Archive Round Robin de manière, vous l'avez deviné, round robin. Cela limite automatiquement l'historique aux 1 000 dernières valeurs (dans notre exemple). Étant donné que vous pouvez définir plusieurs RRA au sein d'une seule RRD, vous pouvez en configurer une autre, pour stocker 750 valeurs de données à un intervalle de 2 heures, par exemple, et ainsi conserver un journal pendant les deux derniers mois à une résolution plus faible.

L'utilisation des RRA garantit que la RRD ne croît pas au fil du temps et que les anciennes données sont automatiquement éliminées. En utilisant la fonction de consolidation, vous pouvez toujours conserver les données pendant très longtemps, tout en réduisant progressivement la résolution des données le long de l'axe temporel.

L'utilisation de différentes fonctions de consolidation (CF) vous permet de stocker exactement le type d'informations qui vous intéresse réellement : le trafic maximal par minute sur le réseau local, la température minimale de votre cave à vin, ... etc.

Données inconnues
Comme mentionné précédemment, la RRD stocke les données à un intervalle constant. Il peut arriver qu'aucune nouvelle donnée ne soit disponible lorsqu'une valeur doit être écrite dans la RRD. L'acquisition de données peut être impossible pour une raison ou une autre. Avec RRDtool, vous pouvez gérer ces situations en stockant une valeur *UNKNOWN* dans la base de données. La valeur '*UNKNOWN*' est supportée par toutes les fonctions de l'outil. Lors de la consolidation d'un ensemble de données, la quantité de valeurs de données *UNKNOWN* est comptabilisée et lorsqu'une nouvelle valeur consolidée est prête à être écrite dans son Archive Round Robin (RRA), une vérification de validité est effectuée pour s'assurer que le pourcentage de valeurs inconnues dans le point de données n'est pas supérieur à un niveau configurable. Sinon, une valeur *UNKNOWN* sera écrite dans le RRA.

rrdtool(1)

NAME

rrdtool — Round Robin Database tool

SYNOPSIS

rrdtool [command] [options]

DESCRIPTION

RRDtool is a system for storing and displaying time-series data. The data is stored in round-robin databases (RRDBs). RRDBs have a fixed size, so, when the database is full, new data overwrites the oldest data. This is especially useful for network monitoring or any application where data is generated continuously.

The following commands are available:

create
Creates a new Round Robin Database file. See rrdcreate(1) for more details.
update
Adds new data to an RRD file. See rrdupdate(1) for more details.
info
Returns information about an RRD file.
fetch
Fetches data from an RRD file. See rrdfetch(1) for more details.
last
Returns the latest data from an RRD file. See rrdlast(1) for more details.
lastupdate
Returns the latest update times for each data source in an RRD file.
first
Returns the time of the first valid data point in an RRD file.
dump
Dumps the contents of an RRD file in a text format. See rrddump(1) for more details.
restore
Restores an RRD file from a dump file.
graph
Generates an image (graph) from RRD data. See rrdgraph(1) for more details.
tune
Tune an existing RRD file. See rrdtune(1) for more details.
xport
Exports data from an RRD file in a standard format. See rrdxport(1) for more details.
flushcached
Flushes the data held by rrdcached. See rrdflushcached(1) for more details.
resize
Resizes an RRD file. See rrdresize(1) for more details.

Aberrant Behavior Detection

RRDtool provides the building blocks for near real-time aberrant behavior detection. These components include:

  • An algorithm for predicting the value of a time series one time step into the future.
  • A measure of deviation between predicted and observed values.
  • A mechanism to decide if and when an observed value or sequence of observed values is too deviant from the predicted value(s).

Here is a brief explanation of these components:

The Holt-Winters time series forecasting algorithm is an on-line (or incremental) algorithm that adaptively predicts future observations in a time series. Its forecast is the sum of three components: a baseline (or intercept), a linear trend over time (or slope), and a seasonal coefficient (a periodic effect, such as a daily cycle). There is one seasonal coefficient for each time point in the period (cycle). After a value is observed, each of these components is updated via exponential smoothing. This means that the algorithm "learns" from past values and uses them to predict the future. The rate of adaptation is governed by 3 parameters, alpha (intercept), beta (slope), and gamma (seasonal). The prediction can also be viewed as a smoothed value for the time series.

The measure of deviation is a seasonal weighted absolute deviation. The term seasonal means deviation is measured separately for each time point in the seasonal cycle. As with Holt-Winters forecasting, deviation is predicted using the measure computed from past values (but only at that point in the seasonal cycle). After the value is observed, the algorithm learns from the observed value via exponential smoothing. Confidence bands for the observed time series are generated by scaling the sequence of predicted deviation values (we usually think of the sequence as a continuous line rather than a set of discrete points).

Aberrant behavior (a potential failure) is reported whenever the number of times the observed value violates the confidence bands meets or exceeds a specified threshold within a specified temporal window (e.g. 5 violations during the past 45 minutes with a value observed every 5 minutes).

This functionality is embedded in a set of related RRAs. In particular, a FAILURES RRA logs potential failures. With these data you could, for example, use a front-end application to RRDtool to initiate real-time alerts.

For a detailed description on how to set this up, see rrdcreate(1).

REMOTE CONTROL

When you start RRDtool with the command line option '-' it waits for input via standard input (STDIN). With this feature you can improve performance by attaching RRDtool to another process (MRTG is one example) through a set of pipes. Over these pipes RRDtool accepts the same arguments as on the command line and some special commands like cd, mkdir, pwd, ls and quit. For detailed help on the server commands type:

rrdtool help cd

When a command is completed, RRDtool will print the string '"OK"', followed by timing information of the form u:usertime s:systemtimer:runtime. The usertime and systemtime values are the running totals of seconds since RRDtool was started. runtime is the total amount of seconds that RRDtool has been running. If an error occurs, a line of the form '"ERROR:" Description of error' will be printed instead. RRDtool will not abort, unless something really serious happens. If a workdir is specified and the UID is 0, RRDtool will do a chroot to that workdir. If the UID is not 0, RRDtool only changes the current directory to workdir.

RRD Server

If you want to create a RRD-Server, you must choose a TCP/IP Service number and add them to /etc/services like this:

rrdsrv      13900/tcp                       # RRD server

Attention: the TCP port 13900 isn't officially registered for rrdsrv. You can use any unused port in your services file, but the server and the client system must use the same port, of course.

With this configuration you can add RRDtool as meta-server to /etc/inetd.conf. For example:

rrdsrv stream tcp nowait root /opt/rrd/bin/rrdtool rrdtool - /var/rrd

Don't forget to create the database directory /var/rrd and reinitialize your inetd.

If all was setup correctly, you can access the server with Perl sockets, tools like netcat, or in a quick interactive test by using 'telnet localhost rrdsrv'.

NOTE: that there is no authentication with this feature! Do not setup such a port unless you are sure what you are doing.

ENVIRONMENT VARIABLES

The following environment variables may be used to change the behavior of most of the utilities.

RRD_LOCKING
If this environment variable is set, the RRD file is locked in the given mode:
  • try fails, when the file is locked by another process. This is the default.
  • block waits until the lock is released.
  • none skips locking at all. Caller has to ensure a proper locking which should be compatible with "fcntl(fd, F_SETLK, ...)".

Some utilities have command line options (--locking) which override this variable.

RRDCACHED, THE CACHING DAEMON

For very big setups, updating thousands of RRD files often becomes a serious IO problem. If you run into such problems, you might want to take a look at rrdcached, a caching daemon for RRDtool which may help you lessen the stress on your disks.
