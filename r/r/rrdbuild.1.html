NOM

rrdbuild - Instructions pour compiler RRDtool

APERÇU

Si vous avez téléchargé le code source de RRDtool, vous devez le compiler. Ce document vous donnera des informations sur la manière de procéder.

RRDtool dépend des services de bibliothèques tierces. Certaines de ces bibliothèques peuvent déjà être installées sur votre système. Vous devez compiler des copies des autres avant de pouvoir compiler RRDtool.

Ce document vous expliquera toutes les étapes nécessaires pour commencer.

Ces instructions supposent que vous utilisez un shell bash. Si vous utilisez csh/tcsh, vous pouvez soit taper bash pour passer à bash pour la compilation, soit, si vous savez ce que vous faites, remplacer les instructions d'exportation par setenv.

Nous supposons en outre que vos copies de tar et make sont en fait GNU tar et GNU make respectivement. Il se pourrait qu'ils soient installés sous le nom gtar et gmake sur votre système.

COMPILATION OPTIMISTE

Avant de commencer à compiler RRDtool, vous devez décider deux choses :

1.
Dans quel répertoire vous souhaitez compiler le logiciel.
2.
Où vous souhaitez installer le logiciel.

Une fois que vous avez décidé, sauvegardez les deux emplacements dans des variables d'environnement.

BUILD_DIR=/tmp/rrdbuild
INSTALL_DIR=/opt/rrdtool-1.9.0

Si votre /tmp est monté avec l'option noexec (ce que fait apparemment RHEL), vous devez choisir un autre répertoire !

Assurez-vous maintenant que BUILD_DIR existe et allez-y :

mkdir -p $BUILD_DIR
cd $BUILD_DIR

Supposons d'abord que vous avez déjà toutes les bibliothèques nécessaires préinstallées.

wget https://github.com/oetiker/rrdtool-1.x/releases/download/v1.8.0/rrdtool-1.9.0.tar.gz
gunzip -c rrdtool-1.9.0.tar.gz | tar xf -
cd rrdtool-1.9.0
./configure --prefix=$INSTALL_DIR && make && make install

Ok, c'était très optimiste. Cet essai se terminera probablement par le fait que configure se plaindra de plusieurs bibliothèques manquantes.

INSTALLATION DES DÉPENDANCES

Si votre système d'exploitation vous permet d'installer des paquets supplémentaires à partir d'un dépôt logiciel, vous pourriez vous en sortir en installant les paquets manquants. Lorsque les paquets sont installés, exécutez à nouveau configure et essayez de compiler à nouveau. Vous trouverez ci-dessous quelques indications pour préparer votre système d'exploitation à la compilation de RRDtool.

Des ajouts à cette liste sont les bienvenus. En général, RRDtool devrait fonctionner avec les dernières versions des bibliothèques. Les versions listées ici sont juste celles qui étaient à jour lors de mes tests.

OpenSolaris 2008.05

Ajoutez simplement un compilateur et le paquet de développement gnome :

pkg install sunstudioexpress
pkg install SUNWgnome-common-devel

Il y a un problème avec cairo.pc sur OpenSolaris. Il suggère que xrender est requis pour la compilation avec cairo. Ce n'est pas vrai et c'est aussi mauvais car OpenSolaris n'inclut pas de fichier xrender.pc. Utilisez Perl pour résoudre ce problème :

perl -i~ -p -e 's/(Requires.*?)\s*xrender.*/$1/' /usr/lib/pkgconfig/cairo.pc

Assurez-vous que le système de compilation de RRDtool trouve votre nouveau compilateur

export PATH=/opt/SunStudioExpress/bin

Debian / Ubuntu

Utilisez apt-get pour vous assurer d'avoir tout ce qui est nécessaire. Un certain nombre de paquets seront ajoutés via les dépendances.

apt-get install autoconf autopoint build-essential dc
apt-get install groff-base libtool libpango1.0-dev libxml2-dev
apt-get install python3-dev python3-setuptools

Gentoo

Sous Gentoo, installer RRDtool est très simple, il suffit d'emerge rrdtool. Toutes les dépendances seront gérées automatiquement par le système portage. La seule chose à laquelle vous devriez faire attention sont les flags USE, qui vous permettent d'affiner les fonctionnalités avec lesquelles RRDtool sera compilé. Actuellement, les flags USE suivants sont disponibles :

doc    - installe la documentation .html et .txt
         dans /usr/share/doc/rrdtool-1.x.xx/
perl   - compile et installe les bindings du langage perl
python - compile et installe les bindings du langage python
ruby   - compile et installe les bindings du langage ruby
tcl    - compile et installe les bindings du langage tcl
rrdcgi - compile et installe rrdcgi

Après avoir décidé quels flags USE vous avez besoin, définissez-les soit dans make.conf, soit dans /etc/portage/package.use et exécutez finalement :

# emerge -va rrdtool

Consultez le manuel de Gentoo pour plus de détails sur la gestion des flags USE : http://www.gentoo.org/doc/en/handbook/handbook-x86.xml?part=2

COMPILATION DES DÉPENDANCES

Mais encore une fois, cela aurait pu être trop optimiste, et vous devez en fait compiler vos propres copies de certaines des bibliothèques requises. Des éléments comme libpng et zlib sont assez standards, vous les aurez donc probablement déjà sur votre système. Freetype, Fontinst, Cairo, Pango peuvent être installés, mais il est possible qu'ils soient assez anciens et ne répondent donc pas à nos attentes, vous pourriez donc vouloir compiler leurs dernières versions.

Conseils généraux de compilation pour AIX

Si vous travaillez avec AIX, vous constaterez peut-être que l'option --disable-shared peut causer des problèmes. Dans ce cas, vous devrez peut-être installer les bibliothèques partagées dans le PREFIX de RRDtool et utiliser --disable-static à la place.

Une autre indication pour faire fonctionner RRDtool sur AIX est d'utiliser le compilateur IBM XL C :

export CC=/usr/vac/bin/cc
export PERLCC=$CC

(De meilleures instructions pour AIX sont bienvenues !)

Instructions de compilation

Certaines bibliothèques veulent savoir où se trouvent d'autres bibliothèques. Pour que cela fonctionne, définissez la variable d'environnement suivante

export PKG_CONFIG_PATH=${INSTALL_DIR}/lib/pkgconfig
export PATH=$INSTALL_DIR/bin:$PATH

Ce qui précède repose sur la présence du programme pkgconfig. Vous trouverez ci-dessous des instructions sur la manière de compiler pkgconfig.

Étant donné que nous compilons des bibliothèques dynamiquement, elles doivent savoir où se trouver mutuellement. Ceci est fait en définissant un LDFLAGS approprié. Malheureusement, la syntaxe diffère encore d'un système à l'autre :

Solaris
export LDFLAGS=-R${INSTALL_DIR}/lib

si vous utilisez le compilateur Sun Studio/Forte, vous voudrez peut-être aussi définir

CFLAGS="-xO3 -xcode=pic13"   (SPARC)
CFLAGS="-xO3 -Kpic"          (x86)
Linux
export LDFLAGS="-Wl,--rpath -Wl,${INSTALL_DIR}/lib"
HPUX
export LDFLAGS="+b${INSTALL_DIR}/lib"
AIX
export LDFLAGS="-Wl,-blibpath:${INSTALL_DIR}/lib"

Si vous avez GNU make installé et qu'il n'est pas appelé 'make', alors faites

export MAKE=gmake
export GNUMAKE=gmake

sinon faites simplement

export MAKE=make

Compilation de pkgconfig

Comme mentionné ci-dessus, sans pkgconfig, l'ensemble du processus de compilation sera une source de douleur et de souffrance, assurez-vous donc d'en avoir une copie sur votre système. S'il n'est pas disponible nativement, voici comment le compiler.

wget http://pkgconfig.freedesktop.org/releases/pkg-config-0.23.tar.gz
gunzip -c pkg-config-0.23.tar.gz | tar xf -
cd pkg-config-0.23
./configure --prefix=$INSTALL_DIR CFLAGS="-O3 -fPIC"
$MAKE
$MAKE install

Après avoir installé pkgconfig dans un répertoire personnalisé, la définition de la variable d'environnement correspondante sera utile.

export PKG_CONFIG=$INSTALL_DIR/bin/pkg-config

Compilation de zlib

Il y a de très fortes chances que vous l'ayez déjà sur votre système ...

cd $BUILD_DIR
wget https://oss.oetiker.ch/rrdtool/pub/libs/zlib-1.2.3.tar.gz
gunzip -c zlib-1.2.3.tar.gz | tar xf -
cd zlib-1.2.3
./configure --prefix=$INSTALL_DIR CFLAGS="-O3 -fPIC" --shared
$MAKE
$MAKE install

Construction de fontconfig

Notez que fontconfig possède un fichier de configuration d'exécution dans INSTALL_DIR/etc que vous voudrez peut-être ajuster afin que fontconfig trouve les polices sur votre système. Exécutez le programme fc-cache pour construire le cache fontconfig après avoir modifié le fichier de configuration.

cd $BUILD_DIR
wget https://oss.oetiker.ch/rrdtool/pub/libs/fontconfig-2.4.2.tar.gz
gunzip -c fontconfig-2.4.2.tar.gz   | tar xf -
cd fontconfig-2.4.2
./configure --prefix=$INSTALL_DIR CFLAGS="-O3 -fPIC" --with-freetype-config=$INSTALL_DIR/bin/freetype-config
$MAKE
$MAKE install

Construction de Pixman

cd $BUILD_DIR

Construction de Cairo

cd $BUILD_DIR
wget https://oss.oetiker.ch/rrdtool/pub/libs/cairo-1.6.4.tar.gz
gunzip -c cairo-1.6.4.tar.gz   | tar xf -
cd cairo-1.6.4
./configure --prefix=$INSTALL_DIR \
   --enable-xlib=no \
   --enable-xlib-render=no \
   --enable-win32=no \
   CFLAGS="-O3 -fPIC"
$MAKE
$MAKE install

Lors de la construction sur Solaris, vous voudrez peut-être faire

./configure --prefix=$INSTALL_DIR \
   --enable-xlib=no \
   --enable-xlib-render=no \
   --enable-win32=no \
   CFLAGS="-O3 -fPIC -D_POSIX_PTHREAD_SEMANTICS"

Construction de rrdtool (deuxième tentative)

Toutes les bibliothèques dépendantes sont maintenant construites et vous pouvez réessayer. Cette fois, vous indiquez à configure où il doit chercher les bibliothèques et les fichiers d'inclusion. Ceci est fait via des variables d'environnement. Selon le shell que vous utilisez, la syntaxe pour définir les variables d'environnement est différente.

Et enfin, essayez de construire à nouveau. Nous désactivons les bindings python et tcl car il semble qu'un bon nombre de personnes aient des configurations python et tcl mal configurées qui empêcheraient RRDtool de se construire s'ils étaient inclus dans leur état actuel.

cd $BUILD_DIR/rrdtool-1.9.0
./configure --prefix=$INSTALL_DIR --disable-tcl --disable-python
$MAKE clean
$MAKE
$MAKE install

ASTUCE SOLARIS : si vous voulez construire le module Perl pour le Perl natif (celui livré avec Solaris), vous aurez besoin du compilateur Sun Forte installé sur votre machine ou vous devrez ajuster manuellement bindings/perl-shared/Makefile pendant la construction !

Allez maintenant dans $INSTALL_DIR/share/rrdtool/examples/ et exécutez-les pour voir si votre construction a réussi.
