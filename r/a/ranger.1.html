ranger - gestionnaire de fichiers visuel

SYNOPIS

ranger [--version] [--help] [--debug] [--clean] [--cachedir=répertoire] [--confdir=répertoire] [--datadir=répertoire] [--copy-config=quoi] [--choosefile=cible] [--choosefiles=cible] [--choosedir=cible] [--selectfile=chemin_fichier] [--show-only-dirs] [--list-unused-keys] [--list-tagged-files=étiquette] [--profile] [--cmd=commande] [chemin ...]

DESCRIPTION

ranger est un gestionnaire de fichiers en console avec des raccourcis clavier VI.

RESSOURCES

Ce manuel contient des instructions sur l'utilisation et la configuration de ranger.

Dans ranger, vous pouvez appuyer sur ? pour une liste de raccourcis clavier, de commandes ou de paramètres.

Le README contient les instructions d'installation.

Le fichier HACKING.md contient des lignes directrices pour la modification du code.

Le répertoire doc/configs contient des fichiers de configuration. Ils sont généralement installés dans /usr/share/doc/ranger/config et peuvent être obtenus avec l'option --copy-config de ranger.

Le répertoire examples contient des implémentations de référence pour les plugins de ranger, des exemples de fichiers de configuration et certains programmes pour intégrer ranger avec d'autres logiciels. Ils sont généralement installés dans /usr/share/doc/ranger/examples.

La page de manuel de rifle(1) décrit les fonctions de l'ouvreur de fichiers

La section LIENS de cette page de manuel contient d'autres ressources.

ARGUMENTS POSITIONNELS

chemin ...
Chaque chemin sera ouvert dans un onglet et si le chemin est un fichier, il sera sélectionné. Omettre ceci est équivalent à fournir le répertoire courant.

OPTIONS

-d, --debug
Active le mode debug : chaque fois qu'une erreur se produit, ranger s'arrête et affiche une trace complète. Le comportement par défaut est de simplement afficher le nom de l'exception dans la barre d'état/log et d'essayer de continuer à fonctionner.
-c, --clean
Active le mode propre : ranger n'accédera ni ne créera de fichiers de configuration, et ne laissera aucune trace sur votre système. Ceci est utile lorsque votre configuration est cassée, lorsque vous voulez éviter le désordre, etc.
--cachedir=dir
Change le répertoire cache de ranger de $XDG_CACHE_HOME ou ~/.cache/ranger à "dir".
-r dir, --confdir=dir
Change le répertoire de configuration de ranger de $XDG_CONFIG_HOME ou ~/.config/ranger à "dir".
--datadir=dir
Change le répertoire de données de ranger de $XDG_DATA_HOME ou ~/.local/share/ranger à "dir".
--copy-config=fichier
Crée des copies des fichiers de configuration par défaut dans votre répertoire de configuration local. Les fichiers existants ne seront pas écrasés. Valeurs possibles : all, commands, commands_full, rc, rifle, scope.

Note : vous voudrez peut-être désactiver le chargement des fichiers de configuration globaux en exportant RANGER_LOAD_DEFAULT_RC=FALSE dans votre environnement. Voir aussi : FICHIERS, ENVIRONNEMENT

--copy-config=commands copiera uniquement un petit fichier de configuration d'exemple avec un exemple minutieusement commenté. Il est recommandé de garder ce fichier bien organisé pour éviter d'avoir des commandes obsolètes lors des mises à jour de ranger. Le fichier commands.py complet par défaut peut être copié avec --copy-config=commands_full, mais ce fichier sera ignoré par ranger et servira uniquement de référence pour créer vos propres commandes.

--choosefile=fichier_cible
Permet de choisir un fichier avec ranger. Ceci modifie le comportement de sorte que lorsque vous ouvrez un fichier, ranger se ferme et écrit le chemin absolu de ce fichier dans fichier_cible.
--choosefiles=fichier_cible
Permet de choisir plusieurs fichiers avec ranger. Ceci modifie le comportement de sorte que lorsque vous ouvrez un fichier, ranger se ferme et écrit les chemins absolus de tous les fichiers sélectionnés dans fichier_cible, en ajoutant une nouvelle ligne après chaque nom de fichier.
--choosedir=fichier_cible
Permet de choisir un répertoire avec ranger. Lorsque vous quittez ranger, il écrira le dernier répertoire visité dans fichier_cible.
--selectfile=fichier_cible
Ouvre ranger avec fichier_cible sélectionné. Ceci est une option héritée, remplacée par le comportement des ARGUMENTS POSITIONNELS.
--show-only-dirs
Affiche uniquement les répertoires. Peut être utilisé en conjonction avec --choosedir=fichier_cible.
--list-unused-keys
Liste les touches courantes qui ne sont liées à aucune action dans le contexte "browser". Cette liste n'est pas exhaustive, vous pouvez lier n'importe quelle touche prise en charge par curses : utilisez le code de touche retourné par "getch()".
--list-tagged-files=étiquette
Liste tous les fichiers qui sont étiquetés avec l'étiquette donnée. Note : Les étiquettes sont des caractères uniques. L'étiquette par défaut est "*"
--profile
Affiche des statistiques d'utilisation du CPU à la sortie.
--cmd=commande
Exécute la commande après que la configuration a été lue. Utilisez cette option plusieurs fois pour exécuter plusieurs commandes.
--version
Affiche la version et quitte.
-h, --help
Affiche une liste d'options et quitte.

CONCEPTS

Cette partie explique comment certaines parties de ranger fonctionnent et comment elles peuvent être utilisées efficacement.

ÉTIQUETTES

Les étiquettes sont des caractères uniques qui sont affichés à gauche d'un nom de fichier. Vous pouvez utiliser les étiquettes comme vous le souhaitez. Appuyez sur "t" pour activer/désactiver les étiquettes et sur "ut" pour supprimer toutes les étiquettes de la sélection. L'étiquette par défaut est un astérisque ("*"), mais vous pouvez utiliser n'importe quelle étiquette en tapant "<nom_étiquette>.

PRÉVISUALISATIONS

Par défaut, seuls les fichiers texte sont prévisualisés, mais vous pouvez activer des scripts de prévisualisation externes en définissant les options "use_preview_script" et "preview_files" sur vrai.

Ce script par défaut est %rangerdir/data/scope.sh. Il contient plus de documentation et des appels à de nombreux programmes externes pour générer des prévisualisations. Ils sont automatiquement utilisés lorsqu'ils sont disponibles mais sont entièrement facultatifs.

  • "python-bidi" (package Python) pour afficher correctement les noms de fichiers de droite à gauche (hébreu, arabe)
Pour des prévisualisations de fichiers améliorées (avec scope.sh) :
  • "img2txt" (de "caca-utils") pour les prévisualisations d'images en art ASCII
  • "w3mimgdisplay", "ueberzug", "mpv",

    Indépendamment du script d'aperçu, il existe une fonctionnalité pour prévisualiser les images en les dessinant directement dans le terminal. Pour activer cette fonctionnalité, définissez l'option "preview_images" sur true et activez l'un des modes d'aperçu d'images :

    iTerm2

    Cela ne fonctionne qu'avec iTerm2 compilé avec le support de l'aperçu d'images, mais fonctionne via ssh.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur iterm2.

    Cette fonctionnalité repose sur les dimensions de la police du terminal. Par défaut, une largeur de 8 et une hauteur de 11 sont utilisées. Pour utiliser d'autres valeurs, définissez les options "iterm2_font_width" et "iterm2_font_height" aux valeurs souhaitées.

    kitty

    Cela ne fonctionne qu'avec Kitty. Nécessite PIL (ou Pillow) pour fonctionner. Permet les aperçus d'images à distance, par exemple dans une session ssh.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur kitty.

    terminology

    Cela ne fonctionne qu'avec terminology. Il peut rendre les graphiques vectoriels, mais fonctionne uniquement localement.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur terminology.

    ueberzug

    Ueberzug est un utilitaire en ligne de commande qui dessine des images sur les terminaux en utilisant des fenêtres enfants. Il nécessite PIL (ou Pillow) et repose sur X11. Cela le rend compatible (de manière limitée, c'est-à-dire que les divisions tmux ne sont pas prises en charge) avec de nombreux terminaux et tmux, mais pas avec la console Linux ou Wayland.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur ueberzug.

    urxvt

    Cela ne fonctionne qu'avec urxvt compilé avec le support pixbuf. Ne fonctionne pas via ssh.

    Essentiellement, ce mode définit temporairement une image comme arrière-plan du terminal, elle écrasera donc tout arrière-plan d'image précédemment défini.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur urxvt.

    urxvt-full

    Identique à urxvt mais utilise non seulement le panneau d'aperçu mais aussi toute la fenêtre du terminal.

    Pour activer cette fonctionnalité, définissez l'option "preview_images_method" sur urxvt-full.

    w3m

    Cela ne fonctionne pas via ssh, nécessite certains terminaux (testé sur "xterm" et "urxvt") et est incompatible avec tmux, bien qu'il fonctionne avec screen.

    Pour activer cette fonctionnalité, installez le programme "w3m" et définissez l'option "preview_images_method" sur w3m.

    Lors de l'utilisation d'un terminal avec une bordure non nulle qui n'est pas automatiquement détectée, l'aperçu w3m sera mal aligné. Utilisez l'option "w3m_offset" pour ajuster manuellement le décalage de l'image. Cette valeur doit être identique à la valeur de la bordure du terminal.

    SÉLECTION

    La sélection est définie comme "Tous les fichiers marqués S'IL Y EN A, sinon le fichier courant." Soyez conscient de cela lors de l'utilisation de la commande :delete, qui supprime tous les fichiers de la sélection.

    Vous pouvez marquer des fichiers en appuyant sur <Espace>, v, etc. Un symbole Mrk jaune en bas à droite indique qu'il y a des fichiers marqués dans ce répertoire.

    MACROS

    Les macros peuvent être utilisées dans les commandes pour abréger des choses.

    %f   le fichier mis en surbrillance
%d   le chemin du répertoire courant
%s   les fichiers sélectionnés dans le répertoire courant
%t   tous les fichiers étiquetés dans le répertoire courant
%c   les chemins complets des fichiers copiés/coupés actuellement
%p   les chemins complets des fichiers sélectionnés

    Les macros %f, %d, %p, et %s ont également des variantes majuscules, %F, %D, %P, et %S, qui font référence à l'onglet suivant. Pour faire référence à des onglets spécifiques, ajoutez un nombre entre les deux. (%7s = sélection du septième onglet.)

    %c est la seule macro qui sort du répertoire courant. Vous pouvez donc "abuser" de la fonction de copie à d'autres fins, comme comparer deux fichiers qui se trouvent dans des répertoires différents :

    Copiez le fichier A (tapez yy), déplacez-vous vers le fichier B, puis tapez
@diff %c %f

    Les macros pour les chemins de fichiers sont généralement échappées par le shell afin qu'elles puissent être utilisées dans la commande "shell".

    Lors du mappage de touches, vous pouvez utiliser le placeholder <any>, la touche entrée à cette position peut être utilisée via les macros %any et %any_path. (Lors de l'utilisation de plusieurs placeholders <any>, vous pouvez indexer les macros : %any0, %any_path0, %any1, %any_path1...) La macro %any sera remplacée par la touche pressée à la position du placeholder <any>. La macro %any_path sera remplacée par le chemin du signet mappé à la touche pressée à la position du placeholder <any>. Par exemple, cette macro peut être utilisée pour afficher la touche qui a été pressée après "c" :

    map c<any> echo %any

    %any est utilisé dans la configuration de ranger pour créer une liaison de touche pour ajouter un signet. c<set_bookmark> crée un signet pour le répertoire courant et la touche pour le signet est le premier argument fourni. Dans ce cas, la touche pressée après "m" :

    map m<any> set_bookmark %any

    La macro %any_path peut être utilisée pour afficher le chemin du signet qui est défini sur la touche pressée après "c" :

    map c<any> echo %any_path

    Un exemple pratique de l'utilisation de %any_path est le collage de fichiers coupés/copiés vers un répertoire marqué :

    map p'<any> paste dest=%any_path

    La macro %rangerdir s'étend au répertoire de la bibliothèque python de ranger, vous pouvez l'utiliser pour quelque chose comme cette commande :
    alias show_commands shell less %rangerdir/config/commands.py

    %confdir s'étend au répertoire spécifié par --confdir.

    %datadir s'étend au répertoire spécifié par --datadir.

    La macro %space s'étend à un caractère espace. Vous pouvez l'utiliser pour ajouter des espaces à la fin d'une commande si nécessaire, tout en empêchant les éditeurs de supprimer automatiquement les espaces de fin de ligne.

    Pour écrire un littéral %, vous devez l'échapper en écrivant %%.

    Notez que les macros sont développées deux fois lorsqu'elles sont chaînées. Par exemple, pour insérer un caractère espace dans une commande chaînée, vous écririez %%space :
    chain command1; command2%%space

    MARQUEURS

    Tapez m<clé> pour marquer le répertoire courant. Vous pouvez y revenir en tapant `<clé>. <clé> peut être n'importe quelle lettre ou chiffre. Contrairement à vim, les marqueurs minuscules et majuscules sont persistants.

    Chaque fois que vous accédez à un marqueur, le marqueur spécial à la clé ` sera défini sur le dernier répertoire. Ainsi, taper "``" vous ramène à l'endroit où vous étiez auparavant.

    Les marqueurs sont sélectionnables lors de la tabulation dans la commande :cd.

    Remarque : Les marqueurs ' (apostrophe) et ` (backtick) sont identiques.

    RIFLE

    Rifle est l'ouvreur de fichiers de ranger. Il peut être utilisé comme un programme autonome ou un module python. Il est situé à $repo/ranger/ext/rifle.py. Contrairement à d'autres ouvreurs de fichiers plus simples, rifle peut trouver automatiquement les programmes installés, il peut donc être utilisé efficacement dès le départ sur une variété de systèmes.

    Il est configuré dans rifle.conf via une liste de conditions et de commandes. Pour chaque ligne, les conditions sont vérifiées et si elles sont remplies, la commande respective est prise en considération. Par défaut, seule la première règle correspondante est utilisée. Dans ranger, vous pouvez lister et choisir les règles en tapant "r" ou simplement en tapant "<numéro de règle><entrée>". Si vous utilisez rifle de manière autonome, vous pouvez lister toutes les règles avec la commande &quo

    t;-l" option et choisissez une règle avec "-p <nombre>".

    Les règles, ainsi que d'autres documentations, se trouvent dans $repo/ranger/config/rifle.conf.

    FLAGS

    Les drapeaux vous permettent de modifier le comportement du processus lancé. Ils sont utilisés dans les commandes ":open_with" (touche "r") et ":shell" (touche "!").

    f   Fork the process, i.e. run in background. Please use this flag
    instead of calling "disown" or "nohup", to avoid killing the
    background command when pressing Ctrl+C in ranger. (Exécuter le processus en arrière-plan. Veuillez utiliser ce drapeau
    au lieu d'appeler "disown" ou "nohup", afin d'éviter de tuer la
    commande en arrière-plan lorsque vous appuyez sur Ctrl+C dans ranger.)
c   Run the current file only, instead of the selection (Exécuter uniquement le fichier actuel, au lieu de la sélection)
r   Run application with root privilege (requires sudo) (Exécuter l'application avec les privilèges root (nécessite sudo))
t   Run application in a new terminal window (Exécuter l'application dans une nouvelle fenêtre de terminal)

    Il existe quelques drapeaux supplémentaires qui ne peuvent actuellement être utilisés que dans la commande "shell" : (par exemple ":shell -w df")

    p   Redirect output to the pager (Rediriger la sortie vers le pager)
s   Silent mode.  Output will be discarded. (Mode silencieux. La sortie sera ignorée.)
w   Wait for an Enter-press when the process is done (Attendre une pression sur Entrée lorsque le processus est terminé)

    Par défaut, tous les drapeaux sont désactivés, sauf indication contraire dans les raccourcis clavier de rc.conf ou les règles de rifle.conf. Vous pouvez spécifier autant de drapeaux que vous le souhaitez. Un drapeau majuscule annule son effet : "ffcccFsf" est équivalent à "cs".

    Le nom du programme de terminal pour le drapeau "t" est extrait de la variable d'environnement $TERMCMD. S'il n'existe pas, il essaie de l'extraire de $TERM, utilise "x-terminal-emulator" comme solution de repli, puis "xterm" si cela échoue.

    Exemples : ":open_with c" ouvrira le fichier sur lequel vous pointez actuellement, même si vous avez sélectionné d'autres fichiers. ":shell -w df" exécutera "df" et attendra que vous appuyiez sur Entrée avant de revenir à ranger.

    PLUGINS

    Le système de plugins de ranger est constitué de fichiers python situés dans ~/.config/ranger/plugins/ et qui sont importés par ordre alphabétique au démarrage de ranger. Un plugin modifie le comportement de ranger en écrasant ou en étendant une fonction utilisée par ranger. Cela vous permet de modifier pratiquement toutes les parties de ranger, mais il n'y a aucune garantie que les choses continueront à fonctionner dans les versions futures à mesure que le code source évolue.

    Ajouter de nouvelles commandes via un plugin est aussi simple que de les spécifier comme vous le feriez dans commands.py.

    Il existe des hooks (points d'accroche) spécialement conçus pour être utilisés dans les plugins. Ce sont des fonctions qui commencent par hook_ et que l'on trouve dans tout le code.

    grep 'def hook_' -r /path/to/rangers/source

    Essayez également :

    pydoc ranger.api

    Notez que vous ne devriez PAS simplement écraser une fonction à moins de savoir ce que vous faites. Au lieu de cela, sauvegardez la fonction existante et appelez-la depuis votre nouvelle fonction. Ainsi, plusieurs plugins peuvent utiliser le même hook. Il existe plusieurs exemples de plugins dans le répertoire /usr/share/doc/ranger/examples/, y compris un plugin "hello-world" qui décrit cette procédure.

    BINDINGS CLAVIER

    Les raccourcis clavier sont définis dans le fichier %rangerdir/config/rc.conf. Consultez ce fichier pour obtenir la liste de tous les raccourcis clavier. Vous pouvez le copier dans votre répertoire de configuration local avec l'option --copy-config=rc.

    De nombreux raccourcis clavier acceptent un argument numérique supplémentaire. Tapez 5j pour descendre de 5 lignes, 2l pour ouvrir un fichier en mode 2, 10<Espace> pour marquer 10 fichiers.

    Cette liste contient les raccourcis les plus utiles :

    BINDINGS PRINCIPAUX

    h, j, k, l
    Se déplacer vers la gauche, le bas, le haut ou la droite
    ^D ou J, ^U ou K
    Se déplacer d'une demi-page vers le bas, vers le haut
    H, L
    Revenir en arrière et avancer dans l'historique
    gg
    Aller en haut
    G
    Aller en bas
    [, ]
    Se déplacer vers le haut et vers le bas dans le répertoire parent.
    ^R
    Tout recharger
    F
    Basculer le réglage freeze_files. Lorsqu'il est actif (indiqué par un message FROZEN cyan dans la barre d'état), les répertoires et les fichiers ne seront pas chargés, améliorant les performances lorsque tous les fichiers dont vous avez besoin sont déjà chargés. Cela n'affecte pas les aperçus de fichiers, qui peuvent être basculés avec zI. Essayez également de désactiver l'aperçu des répertoires avec zP.
    ^L
    Redessiner l'écran
    i
    Inspecter le fichier actuel dans une fenêtre plus grande.
    E
    Éditer le fichier actuel dans $VISUAL sinon $EDITOR sinon "vim"
    S
    Ouvrir un shell dans le répertoire actuel
    ?
    Ouvre cette page man
    W
    Ouvre la fenêtre de journal où vous pouvez consulter les messages qui apparaissent en bas.
    w
    Ouvre la fenêtre des tâches où vous pouvez visualiser et modifier les processus en arrière-plan qui s'exécutent actuellement dans ranger. Là, vous pouvez taper "dd" pour abandonner un processus et "J" ou "K" pour changer la priorité d'un processus. Un seul processus s'exécute à la fois.
    ^C
    Arrêter le processus en arrière-plan actuellement en cours, lancé par ranger, comme la copie de fichiers, le chargement de répertoires ou les aperçus de fichiers.
    <octal>=, +<qui><quoi>, -<qui><quoi>
    Changer les permissions de la sélection. Par exemple, "777=" est équivalent à "chmod 777 %s", "+ar" fait "chmod a+r %s", "-ow" fait "chmod o-w %s" etc.
    yy
    Copier (yank) la sélection, comme appuyer sur Ctrl+C dans les programmes GUI modernes. (Vous pouvez également taper "ya" pour ajouter des fichiers au tampon de copie, "yr" pour les supprimer à nouveau, ou "yt" pour basculer.)
    dd
    Couper la sélection, comme appuyer sur Ctrl+X dans les programmes GUI modernes. (Il existe également des raccourcis "da", "dr" et "dt" équivalents à "ya", "yr" et "yt".)
    pp
    Coller les fichiers qui ont été précédemment copiés ou coupés, comme appuyer sur Ctrl+V dans les programmes GUI modernes.

    Les conflits seront renommés en ajoutant un '\_' (et un compteur si nécessaire), résultant en "file.ext_", "file.ext_0", etc. Si vous préférez "file_.ext", vous pouvez utiliser la commande "paste_ext".

    po
    Coller les fichiers copiés/coupés, en écrasant les fichiers existants.
    pP, pO
    Comme pp et po, mais met l'opération en file d'attente pour qu'elle soit exécutée après toute autre opération. Rappel : tapez "w" pour ouvrir la fenêtre des tâches.
    pl, pL
    Créer des liens symboliques (absolus ou relatifs) vers les fichiers copiés
    phl
    Créer des liens physiques vers les fichiers copiés
    pht
    Dupliquer l'arborescence du sous-répertoire du répertoire copié, puis créer des liens physiques pour chaque fichier contenu dans la nouvelle arborescence.
    mX
    Créer un marque-page nommé X
    `X
    Aller au marque-page nommé X
    n
    Trouver le fichier suivant. Par défaut, cela vous amène au fichier le plus récent du répertoire, mais si vous recherchez quelque chose en utilisant les touches /, cm, ct, ..., cela vous amène à la prochaine entrée trouvée.
    N
    Trouver le fichier précédent.
    oX
    Changer la méthode de tri (comme dans mutt)
    zX
    Changer les paramètres. Voir la section des paramètres pour une liste des paramètres et de leurs raccourcis.
    u?
    Touche d'annulation universelle. Selon la touche sur laquelle vous appuyez après "u", elle restaure les onglets fermés (uq), supprime les étiquettes (ut), efface le tampon de copie/coupe (ud), démarre le mode visuel inversé (uV) ou efface la sélection (uv).
    f
    Naviguer rapidement en entrant une partie du nom du fichier.
    Espace
    Marquer un fichier.
    v
    Basculer le statut de marque de tous les fichiers
    V
    Démarre le mode visuel, qui sélectionne tous les fichiers entre le point de départ et le curseur jusqu'à ce que vous appuyiez sur ESC. Pour désélectionner les fichiers de la même manière, utilisez "uV".
    /
    Rechercher des fichiers dans le répertoire actuel.
    :
    Ouvrir la console.
    !
    Ouvrir la console avec le contenu "shell " pour que vous puissiez rapidement exécuter des commandes
    @
    Ouvrir la console avec le contenu "shell %s", plaçant le curseur avant le " %s" pour que vous puissiez rapidement exécuter des commandes avec la sélection actuelle comme argument.
    r
    Ouvrir la console avec le contenu "open with " pour que vous puissiez décider quel programme utiliser pour ouvrir la sélection de fichiers actuelle.
    cd
    Ouvrir la console avec le contenu "cd "
    ^P
    Ouvrir la console avec la commande la plus récente.
    Alt-N
    Ouvrir un onglet. N doit être un nombre de 0 à 9. Si l'onglet n'existe pas encore, il sera créé.
    Alt-l, Alt-r
    Décaler un onglet vers la gauche, respectivement vers la droite.
    gn, ^N
    Créer un nouvel onglet.
    gt, gT
    Aller à l'onglet suivant ou précédent. Vous pouvez également utiliser TAB et SHIFT+TAB à la place.
    /dd>
    gc, ^W
    Ferme l'onglet actuel. Le dernier onglet ne peut pas être fermé de cette manière.
    M
    Une chaîne de touches qui vous permet de changer rapidement le mode de ligne de tous les fichiers du répertoire courant. Pour une solution plus permanente, utilisez la commande "default_linemode" dans votre rc.conf.
    .d
    Applique le filtre de type "directory".
    .f
    Applique le filtre de type "file".
    .l
    Applique le filtre de type "symlink".
    .m
    Applique un nouveau filtre de type MIME.
    .n
    Applique un nouveau filtre de nom de fichier.
    .#
    Applique un nouveau filtre de hachage.
    ."
    Applique un nouveau filtre de duplication.
    .
    Applique un nouveau filtre unique.
    .|
    Combine les deux filtres les plus hauts de la pile de filtres dans la relation "OR", au lieu de la relation "AND" utilisée implicitement.
    .&
    Combine explicitement les deux filtres les plus hauts dans la relation "AND". Généralement pas nécessaire car les filtres sont implicitement dans cette relation, mais peut être utile dans des scénarios plus compliqués.
    .!
    Négation du filtre le plus haut.
    .r
    Fait pivoter la pile de filtres de N éléments. Où N est fourni comme préfixe numérique comme le count de vim et vaut par défaut 1, c'est-à-dire déplace l'élément le plus haut au bas de la pile.
    .c
    Efface la pile de filtres.
    .*
    Décompose le combinator de filtre le plus haut (par exemple, ".!", ".|").
    .p
    Retire le filtre le plus haut de la pile de filtres.
    ..
    Affiche l'état actuel de la pile de filtres.

    Il existe des commandes supplémentaires qui sont directement traduites en fonctions python, une pour chaque méthode de la classe ranger.core.actions.Actions. Elles ne sont pas documentées ici, car elles sont principalement destinées aux liaisons de touches, et non à être tapées par un utilisateur. Lisez le code source si vous êtes intéressé par celles-ci.

    Voici les commandes publiques incluant leurs descriptions :

    alias [nouvelle_commande] [ancienne_commande]
    Copie l'ancienne_commande comme nouvelle_commande.
    bulkrename
    Cette commande ouvre une liste de fichiers sélectionnés dans un éditeur externe. Après avoir édité et sauvegardé le fichier, elle générera un script shell qui effectuera le renommage en masse selon les modifications que vous avez apportées dans le fichier.

    Ce script shell est ouvert dans un éditeur pour que vous puissiez le vérifier. Une fois que vous l'aurez fermé, il sera exécuté.

    cd [chemin]
    La commande cd change de répertoire. Si le chemin est un fichier, elle sélectionne ce fichier. La commande ":cd -" est équivalente à taper ``.
    chain commande1[; commande2[; commande3...]]
    Combine plusieurs commandes en une seule, séparées par des points-virgules.
    chmod nombre_octal
    Définit les permissions de la sélection au nombre octal.

    Le nombre octal est compris entre 000 et 777. Les chiffres spécifient les permissions pour l'utilisateur, le groupe et les autres. Un 1 permet l'exécution, un 2 permet l'écriture, un 4 permet la lecture. Additionnez ces nombres pour les combiner. Ainsi, un 7 permet tout.

    Des liaisons de touches sous la forme [-+]<qui><quoi> et <octal>= existent également. Par exemple, +ar permet la lecture pour tout le monde, -ow interdit aux autres d'écrire et 777= permet tout.

    Voir aussi : man 1 chmod

    console [-pN] commande
    Ouvre la console avec la commande déjà tapée. Le curseur est placé à N.
    copymap touche nouvelle_touche [nouvelle_touche2 ...]
    copycmap touche nouvelle_touche [nouvelle_touche2 ...]
    copypmap touche nouvelle_touche [nouvelle_touche2 ...]
    copytmap touche nouvelle_touche [nouvelle_touche2 ...]
    Copie la liaison de touche touche vers nouvelle_touche dans le contexte "navigateur". C'est une copie profonde, donc si vous modifiez la nouvelle liaison (ou des parties de celle-ci) plus tard, l'ancienne ne sera pas modifiée. Par exemple, copymap j down fera que la séquence de touches "down" déplacera le curseur d'un élément vers le bas.

    Pour copier les liaisons de touches de la console, du pager ou de la vue des tâches, utilisez respectivement "copycmap", "copypmap" ou "copytmap".

    default_linemode [chemin=regexp | tag=tags] nom_mode_ligne
    Définit le mode de ligne par défaut. Voir la commande linemode.

    Exemples :

    Définir le mode de ligne par défaut global sur "permissions" :
    :default_linemode permissions

    Définir le mode de ligne par défaut sur "permissions" pour tous les fichiers étiquetés "p" ou "P" :
    :default_linemode tag=pP permissions

    Définir le mode de ligne par défaut pour tous les fichiers dans ~/books/ sur "metatitle" :
    :default_linemode path=/home/.*?/books/.* metatitle

    delete
    Détruit tous les fichiers de la sélection avec un coup de pied circulaire. ranger demandera une confirmation si vous tentez de supprimer plusieurs fichiers (marqués) ou des répertoires non vides. Ceci peut être modifié en changeant le paramètre "confirm_on_delete".
    echo texte
    Affiche le texte dans la barre d'état.
    edit [nom_fichier]
    Modifie le fichier courant ou le fichier dans l'argument.
    eval [-q] code_python
    Évalue le code python. `fm' est une référence à l'instance de FM. Pour afficher du texte, utilisez la fonction `p'. Le résultat est affiché à l'écran sauf si vous utilisez l'option "-q".

    Exemples :
    :eval fm
    :eval len(fm.tabs)
    :eval p("Bonjour le monde !")

    Affiche uniquement les fichiers qui contiennent la chaine dans leur nom de base. Lancer cette commande sans paramètre réinitialise le filtre.

:filter_stack add and

    and

    scout [-flags...] [--] pattern
    Commande multifonction pour rechercher, voyager et filtrer des fichiers.

    Indicateurs :
    -a Ouvre automatiquement un fichier en cas de correspondance non ambiguë
    -e Ouvre le fichier sélectionné en appuyant sur Entrée
    -f Filtre les fichiers qui correspondent au modèle de recherche courant
    -g Interprète le modèle comme un modèle glob
    -i Ignore la casse des lettres des fichiers
    -k Garde la console ouverte lors du changement de répertoire avec la commande
    -l Saut de lettres ; par exemple, permet à "rdme" de correspondre au fichier "readme"
    -m Marque les fichiers correspondants après avoir appuyé sur Entrée
    -M Démarque les fichiers correspondants après avoir appuyé sur Entrée
    -p Filtre permanent : masque les fichiers non correspondants après avoir appuyé sur Entrée
    -r Interprète le modèle comme un modèle d'expression régulière
    -s Cas intelligent ; comme -i sauf si le modèle contient des lettres majuscules
    -t Applique le filtre et le modèle de recherche pendant que vous tapez
    -v Inverse la correspondance

    Plusieurs indicateurs peuvent être combinés. Par exemple, ":scout -gpt" créerait une commande de type :filter en utilisant le globbing.

    set option valeur
    Attribue une nouvelle valeur à une option. Les options valides sont listées dans la section des paramètres. Utilisez la complétion par tabulation pour obtenir la valeur actuelle d'une option, bien que cela ne fonctionne pas pour les fonctions et les expressions régulières. Les valeurs valides sont : 
    type de réglage | exemples de valeurs
---------------+----------------------------
bool           | true, false
integer        | 1, 23, 1337
string         | foo, hello world
list           | 1,2,3,4
none           | none
    setintag tags option valeur
    Attribue une nouvelle valeur à une option, mais localement pour les répertoires qui sont marqués avec tag. Cela signifie que cette option ne prend effet que lors de la visite de ce répertoire.

    Par exemple, pour changer l'ordre de tri dans votre répertoire de téléchargements, marquez-le avec la balise v en tapant "v, puis utilisez cette commande :

    setlocal [path=chemin] option valeur
    Attribue une nouvelle valeur à une option, mais localement pour le répertoire donné par chemin. Cela signifie que cette option ne prend effet que lors de la visite de ce répertoire. Si aucun chemin n'est donné, utilise le répertoire courant.

    chemin peut être entouré d'apostrophes ou de guillemets pour éviter un découpage indésirable. path='~/dl dl$' ou path="~/dl dl$"

    FICHIERS

    ranger lit plusieurs fichiers de configuration qui sont situés dans $HOME/.config/ranger ou $XDG_CONFIG_HOME/ranger si $XDG_CONFIG_HOME est défini. Vous pouvez utiliser l'option --copy-config pour obtenir les fichiers de configuration par défaut. Les fichiers contiennent une documentation supplémentaire.

    rc.conf, commands.py et colorschemes n'ont pas besoin d'être copiés entièrement car ils s'ajouteront seulement aux fichiers de configuration par défaut, sauf s'ils sont explicitement remplacés. Cela peut entraîner des situations déroutantes, par exemple lorsqu'une touche est mappée malgré la suppression de la ligne correspondante dans la copie utilisateur du fichier de configuration. Ce comportement peut être désactivé avec une variable d'environnement (voir aussi : ENVIRONNEMENT). Note : Tous les autres fichiers de configuration ne lisent qu'une seule source ; c'est-à-dire par défaut OU utilisateur, pas les deux. rc.conf et commands.py sont également lus à partir de /etc/ranger s'ils existent pour la configuration système, la configuration utilisateur remplace la configuration système qui remplace la configuration par défaut.

    Lorsque vous lancez ranger avec l'option --clean, il n'accédera ni ne créera aucun de ces fichiers.

    rc.conf
    Contient une liste de commandes qui sont exécutées au démarrage. Principalement, les raccourcis clavier et les paramètres y sont définis.
    commands.py
    Un module python qui définit des commandes utilisables dans la console de ranger en tapant ":" ou dans le fichier rc.conf. Notez que vous pouvez définir des commandes de la même manière dans les plugins.
    commands_full.py
    Ce fichier est copié par --copy-config=commands_full et sert de référence pour les commandes personnalisées. Il est entièrement ignoré par ranger.
    rifle.conf
    C'est le fichier de configuration du lanceur de fichiers intégré appelé "rifle".
    scope.sh
    C'est un script qui gère les aperçus de fichiers. Lorsque les options use_preview_script et preview_files sont définies, le programme spécifié dans l'option preview_script est exécuté et sa sortie et/ou son code de sortie déterminent la réaction de ranger.
    colorschemes/
    Les thèmes de couleurs peuvent être placés ici.
    plugins/
    Les plugins peuvent être placés ici.

    STOCKAGE

    bookmarks
    Ce fichier contient une liste de favoris. La syntaxe est /^(.):(.*)$/. Le premier caractère est la touche du favori et le reste après le deux-points est le chemin vers le fichier. Dans ranger, les favoris peuvent être définis en tapant m<touche>, accédés en tapant '<touche>' et supprimés en tapant um<touche>.
    copy_buffer
    Lors de l'exécution de la commande :save_copy_buffer, les chemins de tous les fichiers actuellement copiés sont enregistrés dans ce fichier. Vous pouvez plus tard exécuter :load_copy_buffer pour copier les mêmes fichiers à nouveau, les passer à une autre instance de ranger ou les traiter dans un script.
    history
    Contient une liste des commandes qui ont été tapées précédemment.
    tagged
    Contient une liste de fichiers étiquetés. La syntaxe est /^(.:)?(.*)$/ où la première lettre est le nom optionnel de l'étiquette et le reste après le deux-points optionnel est le chemin vers le fichier. Dans ranger, les étiquettes peuvent être définies en appuyant sur t et supprimées avec T. Pour assigner une étiquette nommée, tapez "<nom_etiquette>.

    ENVIRONNEMENT

    Ces variables d'environnement ont un effet sur ranger :

    RANGER_LEVEL
    ranger définit cette variable d'environnement à "1" ou l'incrémente si elle existe déjà. Les programmes externes peuvent déterminer s'ils ont été lancés depuis ranger en vérifiant cette variable.
    RANGER_LOAD_DEFAULT_RC
    Si cette variable est définie à FALSE, ranger ne chargera pas le rc.conf par défaut. Cela peut faire gagner du temps si vous avez copié tout le rc.conf dans ~/.config/ranger/ et que vous n'avez pas du tout besoin de celui par défaut.
    VISUAL
    Définit l'éditeur à utiliser pour la touche "E". Se rabat sur EDITOR si non défini ou vide.
    EDITOR
    Définit l'éditeur à utiliser pour la touche "E" si VISUAL est non défini ou vide. Par défaut "vim".
    SHELL
    Définit le shell que ranger va utiliser avec la commande :shell et la touche "S". Par défaut "/bin/sh".
    TERMCMD
    Définit la commande de l'émulateur de terminal que ranger va utiliser avec la commande :terminal et le drapeau d'exécution "t". Par défaut "xterm".
    BAT_STYLE
    Spécifie le thème à utiliser pour la coloration syntaxique lorsque bat est installé, à moins que highlight ne soit également installé. Trouvez les valeurs possibles en exécutant "bat --list-themes".
    PYGMENTIZE_STYLE
    Spécifie le thème à utiliser pour la coloration syntaxique lorsque pygmentize est installé, à moins que highlight ne soit également installé. Trouvez les valeurs possibles en exécutant :
    python -c 'import pygments.styles; [print(stl) for stl in
    pygments.styles.get_all_styles()]'
    HIGHLIGHT_STYLE
    Spécifie le thème à utiliser pour la coloration syntaxique lorsque highlight est installé. Trouvez les valeurs possibles en exécutant "highlight --list-themes".
    HIGHLIGHT_TABWIDTH
    Spécifie le nombre d'espaces à utiliser pour remplacer les tabulations dans les fichiers highlightés.
    HIGHLIGHT_OPTIONS
    highlight utilisera les options de ligne de commande spécifiées dans cette variable. Une option "--style=" spécifiée ici remplacera "HIGHLIGHT_STYLE". De même, "--replace-tabs=" remplacera "HIGHLIGHT_TABWIDTH".
    OPENSCAD_COLORSCHEME
    Spécifie le schéma de couleurs utilisé par openscad lors de l'aperçu des modèles 3D. Lisez la page man de openscad pour les schémas de couleurs. Ranger utilisera par défaut Tomorrow Night.
    OPENSCAD_IMGSIZE
    Spécifie la résolution interne que openscad utilisera pour le rendu des modèles 3D. L'image sera réduite pour s'adapter au panneau d'aperçu. Cette résolution sera par défaut "1000,1000" si aucune valeur n'est définie.
    XDG_CONFIG_HOME
    Spécifie le di
    $HOME/.config.
    PYTHONOPTIMIZE
    Cette variable détermine le niveau d'optimisation de python.

    Utiliser PYTHONOPTIMIZE=1 (comme python -O) supprimera les instructions d'assertion de python. Vous gagnerez en efficacité au prix de la perte d'informations de débogage.

    Utiliser PYTHONOPTIMIZE=2 (comme python -OO) supprimera supplémentairement toutes les docstrings. L'utilisation de cette option désactivera la touche <F1> sur les commandes.

    W3MIMGDISPLAY_PATH
    En modifiant cette variable, vous pouvez changer le chemin du fichier exécutable pour les aperçus d'images. Par défaut, il est défini sur /usr/lib/w3m/w3mimgdisplay.
