NOM

rabbitmq-streams — Outils de gestion des flux RabbitMQ

SYNTAXE

rabbitmq-streams [-q] [-s] [-l] [-n nœud] [-t délai] commande [options_commande]

DESCRIPTION

rabbitmq-streams est un outil en ligne de commande qui fournit des commandes pour gérer les flux, par exemple, ajouter ou supprimer des répliques de flux. Voir la vue d'ensemble des flux RabbitMQ.

OPTIONS

-n nœud
Le nœud par défaut est "rabbit@nom-hote-cible", où nom-hote-cible est la machine locale. Sur une machine nommée "myserver.example.com", le nom du nœud sera généralement "rabbit@myserver" (sauf si RABBITMQ_NODENAME a été remplacé). La sortie de "hostname -s" est généralement le suffixe correct à utiliser après le signe "@". Voir rabbitmq-server(8) pour les détails de configuration d'un nœud RabbitMQ.
-q, --quiet
Le mode de sortie silencieux est sélectionné. Les messages d'information sont réduits lorsque le mode silencieux est actif.
-s, --silent
Le mode de sortie très silencieux est sélectionné. Les messages d'information sont réduits et les en-têtes de table sont supprimés lorsque le mode très silencieux est actif.
-t délai, --timeout délai
Délai d'opération en secondes. Toutes les commandes ne prennent pas en charge les délais. Le délai par défaut est infini.
-l, --longnames
Doit être spécifié lorsque le cluster est configuré pour utiliser des noms de nœuds longs (FQDN). Pour en savoir plus, consultez le guide de clustering RabbitMQ
--erlang-cookie cookie
Secret partagé à utiliser pour s'authentifier auprès du nœud cible. Préférez utiliser un fichier local ou la variable d'environnement RABBITMQ_ERLANG_COOKIE plutôt que de spécifier cette option sur la ligne de commande. Pour en savoir plus, consultez le guide des outils CLI RabbitMQ

COMMANDES

help

Affiche l'aide générale et les commandes prises en charge par rabbitmq-streams.

Réplication

add_replica filet nœud --vhost hôte-virtuel

Ajoute une réplique de flux sur le nœud donné.

Exemple :

rabbitmq-streams add_replica --vhost "un-hote-virtuel" "une-filet" "rabbit@nouveau-noeud"
delete_replica filet nœud --vhost hôte-virtuel

Supprime une réplique de flux sur le nœud donné.

Exemple :

rabbitmq-streams delete_replica --vhost "un-hote-virtuel" "une-filet" "rabbit@noeud-retire"

Surveillance, observabilité et vérifications de l’état

stream_status flux --vhost hôte-virtuel

Affiche le statut d'un flux.

Exemple :

rabbitmq-streams stream_status --vhost "un-hote-virtuel" "un-flux"
restart_stream flux --vhost hôte-virtuel ---preferred-leader-node nœud

Redémarre un flux, y compris toutes ses répliques. L'indicateur optionnel de nœud préféré indique à la commande d'essayer de placer le leader sur un nœud spécifique lors du redémarrage.

Exemple :

rabbitmq-streams restart_stream --vhost "un-hote-virtuel" "un-flux" --preferred-leader-node "noeud"

Plugin Stream

activate_stream_consumer --stream flux --reference référence [--vhost hote-virtuel]

Déclenche un rééquilibrage pour activer un consommateur dans un groupe de consommateurs actifs unique.

Exemple :

rabbitmq-streams activate_stream_consumer --stream flux --reference app-1
list_stream_connections [objetinfo_connexion ...]

Retourne les statistiques de connexion du protocole de flux.

Le paramètre objetinfo_connexion est utilisé pour indiquer quels éléments d'information de connexion doivent être inclus dans les résultats. L'ordre des colonnes dans les résultats correspondra à l'ordre des paramètres. objetinfo_connexion peut prendre n'importe quelle valeur de la liste suivante :

auth_mechanism
Mécanisme d'authentification SASL utilisé, tel que "PLAIN".
client_properties
Propriétés informatives transmises par le client lors de l'établissement de la connexion.
conn_name
Nom lisible de la connexion.
connected_at
Date et heure d'établissement de cette connexion, sous forme d'horodatage.
connection_state
État de la connexion ; l'une des valeurs suivantes :
  • running
  • blocked
frame_max
Taille maximale des trames (en octets).
heartbeat
Intervalle de battement de cœur négocié, en secondes.
host
Nom d'hôte du serveur obtenu par DNS inversé, ou son adresse IP si le DNS inversé a échoué ou a été désactivé.
peer_cert_issuer
L'émetteur du certificat SSL du pair, au format RFC4514.
peer_cert_subject
Le sujet du certificat SSL du pair, au format RFC4514.
peer_cert_validity
La période pendant laquelle le certificat SSL du pair est valide.
peer_host
Le nom d'hôte du pair obtenu par DNS inversé, ou son adresse IP si le DNS inversé a échoué ou n'était pas activé.
peer_port
Le port du pair.
port
Le port du serveur.
ssl
Booléen indiquant si la connexion est sécurisée avec SSL.
ssl_cipher
Algorithme de chiffrement SSL (par exemple, "aes_256_cbc").
ssl_hash
Fonction de hachage SSL (par exemple, "sha").
ssl_key_exchange
Algorithme d'échange de clés SSL (par exemple, "rsa").
ssl_protocol
Protocole SSL (par exemple, "tlsv1").
subscriptions
Nombre d'abonnements (consommateurs) sur la connexion.
user
Nom d'utilisateur associé à la connexion.
vhost
Nom de l'hôte virtuel avec les caractères non ASCII échappés comme en C.

Si aucun connectioninfoitem n'est spécifié, seul conn_name est affiché.

Par exemple, cette commande affiche le nom de la connexion et l'utilisateur pour chaque connexion :

rabbitmq-streams list_stream_connections conn_name user
list_stream_consumers [-p vhost] [consumerinfoitem ...]

Retourne les consommateurs attachés à un flux.

Le paramètre consumerinfoitem est utilisé pour indiquer quels éléments d'information sur les consommateurs inclure dans les résultats. L'ordre des colonnes dans les résultats correspondra à l'ordre des paramètres. consumerinfoitem peut prendre n'importe quelle valeur de la liste suivante :

active
Booléen indiquant si le consommateur est actif ou non.
activity_status
Statut d'activité du consommateur ; l'une des valeurs suivantes :
  • up
  • single_active
  • waiting
connection_pid
ID du processus Erlang associé à la connexion du consommateur.
credits
Crédits disponibles pour le consommateur.
messages_consumed
Nombre de messages consommés par le consommateur.
offset
L'offset (position dans le flux) où se trouve le consommateur.
offset_lag
La différence entre le dernier offset stocké et le dernier offset distribué pour le consommateur.
properties
Les propriétés de l'abonnement du consommateur.
stream
Le flux auquel le consommateur est attaché.
subscription_id
L'ID du consommateur dans le contexte de la connexion.

Si aucun consumerinfoitem n'est spécifié, connection_pid, subscription_id, stream, messages_consumed, offset, offset_lag, credits, active, activity_status, et properties sont affichés.

Par exemple, cette commande affiche le PID de la connexion, l'ID de l'abonnement et le flux pour chaque consommateur :

rabbitmq-streams list_stream_consumers connection_pid subscription_id stream
list_stream_publishers [-p vhost] [publisherinfoitem ...]

Retourne les éditeurs enregistrés.

Le paramètre publisherinfoitem est utilisé pour indiquer quels éléments d'information sur les éditeurs inclure dans les résultats. L'ordre des colonnes dans les résultats correspondra à l'ordre des paramètres. publisherinfoitem peut prendre n'importe quelle valeur de la liste suivante :

connection_pid
ID du processus Erlang associé à la connexion du consommateur.
messages_confirmed
Le nombre de messages confirmés pour l'éditeur.
messages_errored
Le nombre de messages en erreur pour l'éditeur.
messages_published
Le nombre total de messages publiés par l'éditeur.
publisher_id
L'ID de l'éditeur dans le contexte de la connexion.
reference
La référence de déduplication de l'éditeur.
stream
Le flux auquel l'éditeur publie.

Si aucun publisherinfoitem n'est spécifié, connection_pid, publisher_id, stream, reference, messages_published, messages_confirmed, et messages_errored sont affichés.

Par exemple, cette commande affiche le PID de la connexion, l'ID de l'éditeur et le flux pour chaque producteur :

rabbitmq-streams list_stream_publishers connection_pid publisher_id stream
add_super_stream super-stream [--vhost vhost] [--partitions partitions] [--binding-keys binding-keys] [--max-length-bytes max-length-bytes] [--max-age max-age] [--stream-max-segment-size-bytes stream-max-segment-size-bytes] [--leader-locator leader-locator] [--initial-cluster-size initial-cluster-size]
super-stream
Le nom du super flux à créer.
vhost
Le nom de l'hôte virtuel dans lequel créer le super flux.
partitions
Le nombre de partitions que le super flux aura.
binding-keys
Liste des clés de liaison séparées par des virgules.
max-length-bytes
La taille maximale des flux de partition, exemples de valeurs : 20gb, 500mb.
max-age
L'âge maximal des segments de flux de partition, en utilisant le format ISO 8601 pour la durée, par exemple PT10M30S pour 10 minutes 30 secondes, P5DT8H pour 5 jours 8 heures.
stream-max-segment-size-bytes
La taille maximale des segments de flux de partition, exemples de valeurs : 500mb, 1gb.
leader-locator
Stratégie de localisation du leader pour les flux de partition. Les valeurs possibles sont :
  • client-local
  • balanced
La valeur par défaut est balanced
initial-cluster-size
La taille initiale du cluster des flux de partition.

Crée un super flux.

delete_super_stream super-stream [--vhost vhost]

Supprime un super flux.

super-stream
Le nom du super flux à supprimer.
vhost
L'hôte virtuel du super flux.
list_stream_consumer_groups [-p vhost] [groupinfoitem ...]

Liste les groupes de consommateurs uniques actifs de flux pour un hôte virtuel.

Le paramètre groupinfoitem est utilisé pour indiquer quels éléments d'information de groupe inclure dans les résultats. L'ordre des colonnes dans les résultats correspondra à l'ordre des paramètres. groupinfoitem peut prendre n'importe quelle valeur de la liste suivante :

consumers
Nombre de consommateurs dans le groupe.
partition_index
L'index de partition du flux si le flux fait partie d'un super flux, -1 s'il n'en fait pas partie.
reference
La référence (nom) du groupe.
stream
Le flux auquel les consommateurs sont attachés.

Si aucun groupinfoitem n'est spécifié, alors stream, reference, partition_index, et consumers sont affichés.

Par exemple, cette commande affiche le flux, la référence et le nombre de consommateurs pour chaque groupe :

rabbitmq-streams list_stream_consumer_groups stream reference consumers
list_stream_group_consumers --stream stream --reference reference [--vhost vhost] [consumerinfoitem ...]

Liste les consommateurs d'un groupe de consommateurs de flux dans un vhost.

stream
Le flux auquel les consommateurs sont attachés.
reference
La référence du groupe (nom).
vhost
Le hôte virtuel du flux.

Le paramètre consumerinfoitem est utilisé pour indiquer quels éléments d'information du consommateur inclure dans les résultats. L'ordre des colonnes dans les résultats correspondra à l'ordre des paramètres. consumerinfoitem peut prendre n'importe quelle valeur de la liste qui suit :

connection_name
Nom lisible de la connexion du consommateur.
state
État du consommateur ; l'un des éléments suivants :
  • active
  • inactive
subscription_id
L'ID du consommateur dans le champ d'application de la connexion.

Si aucun consumerinfoitem n'est spécifié, alors subscription_id, connection_name et state sont affichés.

Par exemple, cette commande affiche le nom de la connexion et l'état de chaque consommateur attaché au flux stream-1 et appartenant au groupe stream-1 :

rabbitmq-streams list_stream_group_consumers --stream stream-1 --reference stream-1 connection_name state
list_stream_tracking stream [--all | --offset | --writer] [--vhost vhost]

Liste les informations de suivi d'un flux.

stream
Le nom du flux.

Les informations de suivi peuvent être filtrées par leur type en utilisant l'une des options mutuellement exclusives suivantes :

--all
Liste les informations de suivi de décalage et de déduplication des rédacteurs.
--offset
Liste uniquement les informations de suivi de décalage.
--writer
Liste uniquement les informations de suivi de déduplication des rédacteurs.

Exemple :

rabbitmq-streams list_stream_tracking stream-1 --offset
reset_offset --stream stream --reference reference [--vhost vhost]

Réinitialise le décalage stocké pour un nom de consommateur sur un flux.

Exemple :

rabbitmq-streams reset_offset --stream stream --reference app-1
