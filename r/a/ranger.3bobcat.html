Paquet: libbobcat

FBB::Ranger(3bobcat) itérateurs de boucle for FBB::Ranger(3bobcat)

NOM

FBB::Ranger - généralise les plages pour les boucles for basées sur des plages

SYNTAXE

#include <bobcat/ranger>

DESCRIPTION

La classe de modèle Ranger définit des plages qui peuvent être utilisées avec des boucles for basées sur des plages. La boucle for basée sur une plage standard nécessite pour sa spécification de plage un tableau ou une plage d'itérateurs comme celle offerte par, par exemple, les conteneurs (via leurs membres begin et end). Les plages définies par une paire de pointeurs, ou par une sous-plage définie par des expressions d'itérateurs ne peuvent pas actuellement être utilisées en combinaison avec des boucles for basées sur des plages.

Ranger étend l'applicabilité des boucles for basées sur des plages en transformant des paires de pointeurs, un pointeur initial et un nombre de pointeurs, ou une paire d'itérateurs en une plage utilisable par les boucles for basées sur des plages.

Ranger est une classe de modèle nécessitant un paramètre de type de modèle : Iterator, un type d'itérateur ou de pointeur qui atteint les données lorsqu'il est déréférencé.

Les utilisateurs de Ranger n'ont pas à spécifier le type de modèle de Ranger. Le modèle de fonction ranger retourne l'objet Ranger approprié.

ESPACE DE NOMS

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de noms FBB.

FONCTION LIBRE

Lors de l'utilisation des fonctions libres suivantes, toute (sous-)plage d'itérateurs ou de pointeurs peut être utilisée. Avec des itérateurs, des sous-plages d' itérateurs inversés peuvent également être spécifiées. La section EXEMPLE ci-dessous illustre l'utilisation des modèles de fonction ranger.

o
Ranger<Iterator> ranger(Iterator &&begin, Iterator &&end):
ce modèle de fonction retourne un objet Ranger pour la (sous-)plage définie par deux (itérateurs inversés) ;
o
Ranger<Iterator> ranger(Iterator &&begin, size_t count):
ce modèle de fonction retourne un objet Ranger pour la (sous-)plage définie par la plage d'itérateurs (inversés) begin et begin + count ;
o
Ranger<Data *> ranger(Data *begin, Data *end):
ce modèle de fonction retourne un objet Ranger pour la (sous-)plage définie par les deux pointeurs begin et end ;
o
Ranger<Data *> ranger(Data *begin, size_t count):
ce modèle de fonction retourne un objet Ranger pour la (sous-)plage définie par les deux pointeurs begin et begin + count.

CONSTRUCTEURS

Ci-dessous, Iterator fait référence au paramètre de type de la classe de modèle Ranger. Bien que nommé 'Iterator', il peut aussi s'agir d'un pointeur vers un certain type de données (par ex. std::string *).

o
Ranger(Iterator const &begin, Iterator const &end):
Un objet Ranger peut être passé comme spécificateur de plage dans une boucle for basée sur une plage. Tous les éléments définis par la plage seront ensuite parcourus par la boucle for basée sur une plage.

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) sont disponibles.

FONCTIONS MEMBRES

o
Iterator const &begin() const:
retourne (une copie de) l'itérateur begin passé au constructeur de Ranger. Notez que si Iterator était un type pointeur (comme int *) les données vers lesquelles l'itérateur retourné par begin() peut être modifié, car le type de retour du membre (en utilisant int * pour Iterator) devient int * const &, donc une référence à un pointeur constant vers un int. Ceci est parfaitement acceptable : si les données elles-mêmes doivent être immuables, alors le type de données doit être défini comme int const, ce qui est automatiquement le cas lors du passage de données int const *. Voir la section EXEMPLE pour une illustration.
o
Iterator const &end() const:
retourne (une copie de) l'itérateur end passé au constructeur de Ranger. Si des itérateurs inversés sont passés au constructeur de Ranger, alors les membres begin et end retournent des itérateurs inversés. Étant donné que l'utilisation prévue des objets Ranger est de définir une plage pour les boucles for basées sur des plages, des membres comme rbegin et rend peuvent être omis de Ranger.

EXEMPLE

#include <vector>
#include <iostream>
#include <bobcat/ranger>
using namespace std;
using namespace FBB;
int main()
{
    vector<int> iv {1, 2, 3, 4, 5};
                                    // afficher et modifier une sous-plage
    for(auto &el: ranger(iv.rbegin() + 1, iv.rend() - 1))
        cout << el++ << ’ ’;
    cout << ’\n’;
                                    // afficher une plage inversée
    for(auto &el: ranger(iv.rbegin() + 1, iv.rend() - 1))
        cout << el << ’ ’;
    cout << ’\n’;
                                    // même chose : afficher en utilisant un compte
    for(auto &el: ranger(iv.rbegin() + 1, 3))
        cout << el << ’ ’;
    cout << ’\n’;
    int intArray[] = {1, 2, 3, 4, 5};
                                    // afficher et modifier les éléments
                                    // dans une plage basée sur des pointeurs
    for(auto &el: ranger(intArray + 1, intArray + 3))
        cout << el++ << ’ ’;
    cout << ’\n’;
                                    // données maintenant modifiées
    for(auto &el: ranger(intArray + 1, intArray + 3))
        cout << el << ’ ’;
    cout << ’\n’;
                                    // utiliser un compte plutôt qu'un
                                    // pointeur de fin
    for(auto &el: ranger(intArray + 1, 3))
        cout << el << ’ ’;
    cout << ’\n’;
    int const constInts[] = {1, 2, 3, 4, 5};
                                    // les données ne peuvent pas être modifiées
    for(auto &el: ranger(constInts + 1, constInts + 3))
        cout << el << ’ ’;
    cout << ’\n’;
}
