NOM

rabbitmq-service.bat — outil de gestion du service RabbitMQ sous Windows

SYNOPIS

rabbitmq-service.bat [commande]

DESCRIPTION

RabbitMQ est un courtier de messagerie open source multi-protocoles.

L'exécution de rabbitmq-service.bat permet d'exécuter le courtier RabbitMQ en tant que service dans les environnements Windows®. Le service du courtier RabbitMQ peut être démarré et arrêté en utilisant le panneau des services Windows®.

Par défaut, le service s'exécutera dans le contexte d'authentification du compte système local. Il est donc nécessaire de synchroniser les cookies Erlang entre le compte système local (typiquement C:\Windows\.erlang.cookie) et le compte qui sera utilisé pour exécuter rabbitmqctl(8).

COMMANDES

help
Affiche les informations d'utilisation.
install
Installe le service. Le service ne sera pas démarré. Les invocations ultérieures mettront à jour les paramètres du service si des variables d'environnement pertinentes ont été modifiées.
remove
Supprime le service. Si le service est en cours d'exécution, il sera automatiquement arrêté avant d'être supprimé. Aucun fichier ne sera supprimé en conséquence et rabbitmq-server(8) restera opérationnel.
start
Démarre le service. Le service doit avoir été correctement installé au préalable.
stop
Arrête le service. Le service doit être en cours d'exécution pour que cette commande ait un effet.
disable
Désactive le service. Ceci est équivalent à définir le type de démarrage sur Disabled en utilisant le panneau de contrôle des services.
enable
Active le service. Ceci est équivalent à définir le type de démarrage sur Automatic en utilisant le panneau de contrôle des services.

ENVIRONNEMENT

RABBITMQ_SERVICENAME
Par défaut, RabbitMQ.
RABBITMQ_BASE
Note : Windows uniquement. Par défaut, le répertoire des données d'application de l'utilisateur actuel. C'est l'emplacement des répertoires de journaux et de base de données.
RABBITMQ_NODENAME
Par défaut, "rabbit@" suivi du nom d'hôte calculé. Peut être utilisé pour exécuter plusieurs nœuds sur le même hôte. Chaque nœud d'un cluster doit avoir un RABBITMQ_NODENAME unique. Pour en savoir plus, consultez le guide de clustering RabbitMQ.
RABBITMQ_NODE_IP_ADDRESS
Par défaut, RabbitMQ se connectera à toutes les interfaces IPv6 et IPv4 disponibles. Cette variable limite le nœud à une seule interface réseau ou famille d'adresses. Pour en savoir plus, consultez le guide réseau RabbitMQ.
RABBITMQ_NODE_PORT
Port AMQP 0-9-1 et AMQP 1.0. Par défaut, 5672. Pour en savoir plus, consultez le guide réseau RabbitMQ.
ERLANG_SERVICE_MANAGER_PATH
Par défaut, C:\Program Files\erl{version}\erts-{version}\bin (ou C:\Program Files (x86)\erl{version}\erts-{version}\bin pour les environnements 64 bits). Ceci est l'emplacement d'installation du gestionnaire de services Erlang.
RABBITMQ_CONSOLE_LOG
Définissez cette variable sur new ou reuse pour que la sortie de la console du serveur soit redirigée vers un fichier nommé SERVICENAME.debug dans le répertoire des données d'application de l'utilisateur qui a installé le service. Sous Vista, ce sera C:\Users\AppData\username\SERVICENAME. Sous les versions précédentes de Windows, ce sera C:\Documents and Settings\username\Application Data\SERVICENAME. Si RABBITMQ_CONSOLE_LOG est défini sur new, un nouveau fichier sera créé chaque fois que le service démarre. Si RABBITMQ_CONSOLE_LOG est défini sur reuse, le fichier sera écrasé à chaque démarrage du service. Le comportement par défaut lorsque RABBITMQ_CONSOLE_LOG n'est pas défini ou est défini sur une valeur autre que new ou reuse est d'ignorer la sortie du serveur.
