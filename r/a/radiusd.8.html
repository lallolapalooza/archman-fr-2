NOM

radiusd - Serveur d'authentification, d'autorisation et de comptabilité

SYNTAXE

radiusd [-C] [-d répertoire_config] [-D répertoire_dictionnaire] [-f] [-h] [-i adresse_ip] [-l fichier_log] [-m] [-n nom] [-p port] [-P] [-s] [-t] [-v] [-x] [-X]

DESCRIPTION

FreeRADIUS est un serveur RADIUS haute performance et hautement configurable. Il prend en charge de nombreux backends de base de données tels que les fichiers texte brut, SQL, LDAP, Perl, Python, etc. Il prend également en charge de nombreux protocoles d'authentification tels que PAP, CHAP, MS-CHAP(v2), Digest HTTP et EAP (EAP-MD5, EAP-TLS, PEAP, EAP-TTLS, EAP-SIM, etc.).

Il prend également en charge complètement le protocole Cisco de requête VLAN (VMPS) et DHCP.

Veuillez lire la section DÉBOGAGE ci-dessous. Elle contient des instructions pour configurer rapidement le serveur pour votre système local.

OPTIONS

Les options de ligne de commande suivantes sont acceptées par le serveur :

-C
Vérifie la configuration et quitte immédiatement. S'il y a un problème à la lecture de la configuration, le serveur se terminera avec un code d'état non nul. Si la configuration semble acceptable, le serveur se terminera avec un code d'état nul.

Notez qu'il y a des limitations à cette vérification. En raison des complexités impliquées dans le démarrage presque d'un serveur RADIUS, ces vérifications sont nécessairement incomplètes. Le serveur peut retourner un code d'état nul lorsqu'il est exécuté avec -C, mais peut toujours se terminer avec une erreur lorsqu'il est exécuté normalement.

Voir la sortie de radiusd -XC pour une liste informative des modules dont la configuration correcte est vérifiée, et des modules qui sont ignorés, et donc pas vérifiés.

-d répertoire_config
Par défaut, /etc/raddb. Radiusd cherche ici ses fichiers de configuration tels que le fichier dictionary et le fichier users.
-D répertoire_dictionnaire
Définit le répertoire principal des dictionnaires. Par défaut, /usr/share/freeradius.
-f
Ne pas forker, rester en cours d'exécution comme processus de premier plan.
-h
Afficher l'aide d'utilisation.
-i adresse_ip
Définit quelle adresse IP le serveur utilise pour envoyer et recevoir des paquets.

Si cette option de ligne de commande est donnée, alors l'entrée "bind_address" et toutes les entrées "listen{}" dans radiusd.conf sont ignorées.

Cette option DOIT être utilisée en conjonction avec "-p".

-l fichier_log
Par défaut, ${logdir}/radius.log. Radiusd écrit ses informations de journalisation dans ce fichier. Si fichier_log est la chaîne "stdout", la journalisation sera écrite sur stdout.
-m
À SIGINT ou SIGQUIT, quitter proprement au lieu de immédiatement. Ceci est surtout utile lorsque vous exécutez le serveur avec "valgrind".
-n nom
Lire raddb/nom.conf au lieu de raddb/radiusd.conf.
-p port
Définit quel port est utilisé pour recevoir les paquets d'authentification. Les paquets de comptabilité sont reçus sur "port + 1".

Lorsque cette option de ligne de commande est donnée, toutes les sections "listen" dans radiusd.conf sont ignorées.

Cette option DOIT être utilisée en conjonction avec "-i".

-P
Toujours écrire le PID, même avec -f.
-s
Exécuter en mode "serveur unique". Le serveur s'exécute normalement avec plusieurs threads et/ou processus, ce qui peut réduire son temps de réponse aux requêtes. Cependant, certains systèmes ont des problèmes avec le multithreading, donc l'exécution en mode "serveur unique" peut aider à résoudre ces problèmes. En mode serveur unique, le serveur ne se mettra pas non plus en "démon" (auto-background).
-t
Ne pas créer de threads.
-v
Afficher les informations sur la version du serveur et quitter.
-X
Mode débogage. Équivalent à "-sfxx -l stdout". Lorsque vous essayez de comprendre comment le serveur fonctionne, exécutez-le TOUJOURS avec "radiusd -X". Pour les serveurs de production, utilisez "raddebug"
-x
Mode de débogage plus fin. Dans ce mode, le serveur affichera des détails de chaque requête sur sa sortie stdout. Vous pouvez spécifier cette option plusieurs fois (-x -x ou -xx) pour obtenir une sortie plus détaillée.

DÉBOGAGE

La configuration par défaut est réglée pour fonctionner dans les circonstances les plus larges possibles. Elle nécessite des modifications minimales pour votre système.

Cependant, vos besoins peuvent être complexes et nécessiter des modifications importantes de la configuration du serveur. Apporter des modifications aléatoires est une méthode garantie d'échec. Au lieu de cela, nous RECOMMANDONS FORTEMENT de suivre les étapes suivantes :

1) Exécutez toujours le serveur en mode débogage ( radiusd -X ) après avoir apporté une modification de configuration. Nous ne pouvons pas assez insister là-dessus. Si vous n'exécutez pas le serveur en mode débogage, vous ne pourrez pas voir ce qu'il fait, et vous ne pourrez pas corriger les problèmes.

Si vous posez des questions sur la liste de diffusion, la première réponse sera de vous dire "exécutez le serveur en mode débogage". S'il vous plaît, suivez ces instructions.

2) Modifiez le moins possible les fichiers de configuration par défaut. Le serveur contient une décennie d'expérience avec les protocoles, les bases de données et différents systèmes. Sa configuration par défaut est conçue pour fonctionner presque partout, et pour faire presque tout ce dont vous avez besoin.

3) Lorsque vous apportez une petite modification, testez-la avant de modifier quoi que ce soit d'autre. Si la modification fonctionne, enregistrez une copie de la configuration, et apportez une autre modification. Si la modification ne fonctionne pas, déboguez-la et essayez de comprendre pourquoi elle ne fonctionne pas.

Si vous commencez par apporter de grandes modifications à la configuration du serveur, il ne fonctionnera jamais, et vous ne pourrez jamais déboguer le problème.

4) Si vous avez besoin d'ajouter une connexion à une base de données FOO (par exemple, LDAP ou SQL), alors :


a) Éditez raddb/modules/foo
Ce fichier contient la configuration par défaut pour le module. Il contient des commentaires décrivant ce qui peut être configuré, et ce que ces entrées de configuration signifient.
b) Éditez raddb/sites-available/default
Ce fichier contient la politique par défaut pour le serveur. Par exemple, "activer l'authentification CHAP, MS-CHAP et EAP". Recherchez dans ce fichier toutes les références à votre module "foo". Lisez les commentaires et supprimez le dièse (#) initial des lignes faisant référence au module. Cela active le module.
c) Éditez raddb/sites-available/inner-tunnel
Ce fichier contient la politique par défaut pour la partie "tunnelisée" de certaines méthodes EAP. Effectuez le même type d'éditions que ci-dessus, pour le fichier "default".. Si vous n'utilisez pas EAP (802.1X), alors cette étape peut être ignorée.
d) Démarrez le serveur en mode débogage ( radiusd -X ), et commencez les tests.

5) Posez des questions sur la liste de diffusion (freeradius-users@lists.freeradius.org). Lorsque vous posez des questions, incluez la sortie du mode débogage ( radiusd -X ). Ces informations permettront aux gens de vous aider. Si vous ne l'incluez pas, la première réponse à votre message sera "poster la sortie du mode débogage".

Posez vos questions le plus tôt possible. Si vous ne parvenez pas à résoudre un problème en une journée, posez une question sur la liste de diffusion. La plupart des questions ont déjà été vues et peuvent être répondues rapidement.

ARRIÈRE-PLAN

RADIUS est un protocole utilisé entre un serveur d'accès, typiquement un appareil connecté à plusieurs modems ou lignes RNIS, et un serveur radius. Lorsqu'un utilisateur se connecte au serveur d'accès, il lui est demandé un nom d'utilisateur et un mot de passe. Ces informations sont ensuite envoyées au serveur radius. Le serveur d'accès envoie également des enregistrements de connexion et de déconnexion au serveur radius afin que la comptabilité puisse être effectuée. Ces enregistrements sont conservés séparément pour chaque serveur de terminaux dans un fichier appelé detail, et dans le fichier journal compatible wtmp /var/log/radwtmp.

CONFIGURATION

Radiusd utilise un certain nombre de fichiers de configuration. Chaque fichier a sa propre page de manuel décrivant le format du fichier. Ces fichiers sont :

radiusd.conf
Le fichier de configuration principal, qui définit les éléments contrôlés par l'administrateur.
dictionary
Ce fichier est généralement statique. Il définit tous les attributs RADIUS possibles utilisés dans les autres fichiers de configuration. Vous n'avez pas besoin de le modifier. Il inclut d'autres fichiers de dictionnaire dans le même répertoire.
hints
Définit certains indices pour le serveur radius en fonction du nom de connexion de l'utilisateur ou d'autres attributs envoyés par le serveur d'accès. Il permet également de mapper les noms d'utilisateur (par exemple, Pusername -> username). Cela fournit la fonctionnalité que le serveur Livingston 2.0 a en tant que support "Prefix" et "Suffix" dans le fichier users, mais est plus général. Bien sûr, la manière de faire de Livingston est également prise en charge, et vous pouvez même utiliser les deux en même temps (dans certaines limites).
huntgroups
Définit les groupes de recherche que vous avez, et permet de restreindre l'accès à certains groupes de recherche à certains (groupes d')utilisateurs.
users
C'est ici que les utilisateurs sont définis. Dans une configuration typique, ce fichier contient principalement des entrées DEFAULT pour traiter les différents types de connexions, basées sur les indices du fichier hints. L'authentification est ensuite basée sur le contenu du fichier UNIX /etc/passwd. Cependant, il est également possible de définir tous les utilisateurs, et leurs mots de passe, dans ce fichier.
