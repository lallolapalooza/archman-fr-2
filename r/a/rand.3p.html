RAND(3P) Manuel du programmeur POSIX RAND(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

rand, rand_r, srand — générateur de nombres pseudo-aléatoires

SYNTAXE

#include <stdlib.h>
int rand(void);
int rand_r(unsigned int *seed);
void srand(unsigned int seed);

DESCRIPTION

Pour rand() et srand() : Les fonctionnalités décrites sur cette page de référence sont alignées avec la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1-2017 renvoie à la norme ISO C.

La fonction rand() calcule une séquence d'entiers pseudo-aléatoires dans l'intervalle [0,{RAND_MAX}] avec une période d'au moins 2³².

La fonction rand() n'a pas besoin d'être thread-safe.

La fonction rand_r() calcule une séquence d'entiers pseudo-aléatoires dans l'intervalle [0,{RAND_MAX}]. (La valeur de la macro {RAND_MAX} doit être d'au moins 32767.)

Si rand_r() est appelée avec la même valeur initiale pour l'objet pointé par seed et que cet objet n'est pas modifié entre les retours successifs et les appels à rand_r(), la même séquence sera générée.

La fonction srand() utilise l'argument comme amorce (seed) pour une nouvelle séquence de nombres pseudo-aléatoires à retourner par les appels ultérieurs à rand(). Si srand() est ensuite appelée avec la même valeur d'amorce, la séquence de nombres pseudo-aléatoires sera répétée. Si rand() est appelée avant tout appel à srand(), la même séquence sera générée que lors du premier appel à srand() avec une valeur d'amorce de 1.

L'implémentation doit se comporter comme si aucune fonction définie dans ce volume de POSIX.1-2017 n'appelait rand() ou srand().

VALEUR DE RETOUR

La fonction rand() retourne le prochain nombre pseudo-aléatoire de la séquence.

La fonction rand_r() retourne un entier pseudo-aléatoire.

La fonction srand() ne retourne aucune valeur.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Génération d'une séquence de nombres pseudo-aléatoires

L'exemple suivant montre comment générer une séquence de nombres pseudo-aléatoires.

#include <stdio.h>
#include <stdlib.h>
...
    long count, i;
    char *keystr;
    int elementlen, len;
    char c;
...
/* Initialiser le générateur de nombres aléatoires. */
    srand(1);
    /* Créer des clés en utilisant uniquement des caractères minuscules */
    len = 0;
    for (i=0; i<count; i++) {
        while (len < elementlen) {
            c = (char) (rand() % 128);
            if (islower(c))
                keystr[len++] = c;
        }
        keystr[len] = '\0';
        printf("%s Element%0*ld\n", keystr, elementlen, i);
        len = 0;
    }

Génération de la même séquence sur différentes machines

Le code suivant définit une paire de fonctions qui pourraient être incorporées dans des applications souhaitant garantir que la même séquence de nombres est générée sur différentes machines.

static unsigned long next = 1;
int myrand(void)  /* On suppose que RAND_MAX est 32767. */
{
    next = next * 1103515245 + 12345;
    return((unsigned)(next/65536) % 32768);
}
void mysrand(unsigned int seed)
{
    next = seed;
}

UTILISATION PAR APPLICATION

Les fonctions drand48() et random() fournissent des générateurs de nombres pseudo-aléatoires beaucoup plus élaborés.

Les limitations sur la quantité d'état qui peut être conservée entre un appel de fonction et un autre signifient que la fonction rand_r() ne peut jamais être implémentée d'une manière qui satisfasse toutes les exigences d'un générateur de nombres pseudo-aléatoires.

Ces fonctions devraient être évitées chaque fois que des exigences non triviales (y compris la sécurité) doivent être satisfaites.

RATIONALE

Les fonctions rand() et srand() de la norme ISO C permettent des flux pseudo-aléatoires par processus partagés par tous les threads. Ces deux fonctions n'ont pas besoin de changer, mais il doit y avoir une exclusion mutuelle qui empêche l'interférence entre deux threads accédant simultanément au générateur de nombres aléatoires.

Concernant rand(), il existe deux comportements différents qui peuvent être souhaités dans un programme multithreadé :

1.
Une seule séquence de nombres pseudo-aléatoires par processus partagée par tous les threads qui appellent rand().
2.
Une séquence différente de nombres pseudo-aléatoires pour chaque thread qui appelle rand().

Ceci est fourni par la fonction thread-safe modifiée, en fonction de si la valeur d'amorce est globale au processus entier ou locale à chaque thread.

Cela ne résout pas les lacunes connues des implémentations de la fonction rand(), qui ont été abordées en maintenant plus d'état. En effet, cela spécifie de nouvelles formes thread-safe d'une fonction déficiente.

DIRECTIONS FUTURES

La fonction rand_r() pourrait être supprimée dans une future version.
