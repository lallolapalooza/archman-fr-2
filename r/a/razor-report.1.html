NOM

« razor-report » - Agent de rapport Razor

SYNTAXE

razor-report [options]  fichier contenant le mail au format rfc822
$ cat mail | razor-report
$ razor-report ./mail 
$ razor-report -d ./mail

DESCRIPTION

« razor-report » est l'Agent de rapport Razor utilisé pour signaler les messages de spam à un serveur de nomination Razor. « razor-report » devrait généralement être appelé depuis un MUA (Mail User Agent), bien qu'il n'y ait aucune restriction pour l'invoquer depuis la ligne de commande. « razor-report » est un filtre, ce qui signifie que les messages de spam doivent lui être transmis via un pipe. Par défaut, « razor-report » se met en arrière-plan et se détache du terminal de contrôle au démarrage.

Si « razor-report » reçoit plus d'un mail, il les rapportera chacun contre la base de données. Veuillez utiliser cela avec précaution, nous ne voulons pas que la base de données soit remplie de mails incorrectement identifiés comme spam. « razor-report » prend en charge les fichiers au format mbox contenant 1 ou plusieurs mails, ainsi que les fichiers contenant un seul mail RFC 822 (non-mbox). Plus d'un fichier peut être présent sur la ligne de commande, il peut s'agir de fichiers non-mbox ou mbox dans n'importe quel ordre.

Cependant, plus d'un mail non-mbox ne peut pas être lu depuis stdin. « razor-report » et razor-revoke(1) nécessitent une authentification utilisateur pour fonctionner, voir razor-admin(1). Cela permet au serveur de nomination Razor de suivre le nombre de messages qu'un utilisateur rapporte et révoque. Plus un utilisateur rapporte et/ou révoque correctement des messages, plus il gagne en confiance. De même, lorsque des messages sont incorrectement rapportés ou révoqués, la confiance de cet utilisateur diminue. Les utilisateurs ayant une grande confiance auront le plus d'impact sur le Catalogue Razor.

UTILISATION

« razor-report » accepte les arguments suivants :

"-h"
Affiche un message d'utilisation et quitte.
"-v"
Affiche le numéro de version et quitte.
"-d | --verbose"
Affiche des informations de débogage sur la sortie standard.
"-debuglevel=n | -dl=n"
Définit le niveau de débogage à 'n'. La valeur par défaut est 3 sans l'option « -d », et 9 avec.
"-whitelist=fichier"
Spécifie le fichier à utiliser pour la liste blanche. Remplace l'option 'whitelist' dans « razor-agent.conf ».
"-s"
Simule une vérification. Fait tout sauf communiquer avec le serveur.
"-conf=nom_de_fichier"
Spécifie un fichier de configuration alternatif. S'il n'est pas spécifié, il est calculé, voir la page de manuel de razor-agents(1) pour les détails. Voir la page de manuel de razor-agent.conf(5) pour les diverses options de configuration. Le fichier par défaut est « <razorhome>/razor-agent.conf ».
"-home=répertoire"
Spécifie le répertoire razorhome. C'est là que se trouvent le fichier de configuration, les journaux, les identités et les fichiers serveur. S'il n'est pas spécifié, il est calculé, voir la page de manuel de razor-agents(1) pour les détails.
"-logfile=fichier"
Spécifie le fichier où écrire les journaux au lieu de celui du fichier de configuration. Le fichier par défaut est « <razorhome>/razor-agent.log ».
"-ident=nom_de_fichier"
Spécifie un fichier d'identité à utiliser pour l'authentification avec les serveurs Razor. S'il n'est pas spécifié, « <razorhome>/identity-<utilisateur> » est utilisé.
"-rs=razor.server.com"
Utilise ce serveur de nomination Razor au lieu de lire « servers.nomination.lst ».
"-H"
Calcule et affiche la signature du contenu du mail et quitte. Si « -e=entier » n'est pas spécifié, tous les moteurs pris en charge seront utilisés.
"-S=chaîne"
Accepte une liste de signatures pré-calculées (avec « -H ») sur la ligne de commande, au lieu d'en calculer une à partir du contenu du mail. Les signatures peuvent être soumises en hexadécimal ou en base64, mais le base64 est préféré. Nécessite « -e=entier ». Utilisation :

razor-report -e 1 -S a8a3d545adb73f9733675571ffeaf10cba87745b

"-e=entier"
Spécifie le moteur utilisé pour créer les signatures. Doit être 1, 2, 3 ou 4 dans cette version. Le moteur 1, ou « -e=1 », est utilisé pour les signatures Razor 1.x. Utilisé uniquement avec « -S=chaîne » ou « -H ».
"-ep4=chaîne"
Chaîne utilisée par le moteur 4 lors du calcul des signatures. Publiée par les serveurs de nomination Razor et mise à jour très fréquemment. Utilisé uniquement avec « -e=4 ».
"-i=nom_de_fichier"
Utilise l'identité du nom de fichier au lieu de lire <razorhome>/identity. Les serveurs Razor calculent la confiance pour chaque identité unique. Les agents Razor déterminent l'identité par un processus en 2 étapes. Premièrement, vérifie si l'identité est spécifiée via la ligne de commande (-i=fichier). Si elle n'y est pas, recherche le fichier d'identité dans <razorhome>. Si <razorhome> n'a pas de fichier d'identité, l'authentification échouera - vous ne pouvez ni rapporter ni révoquer. Voir razor-agents.conf(5) pour plus d'informations sur <razorhome>. ---à corriger----
"-a"
Authentification uniquement. Si authentifié, quitte avec 0 ; sinon, quitte avec 1.
"-f"
Reste au premier plan, ne se détache pas et ne tourne pas en arrière-plan.

INTÉGRATION AVEC MUTT

Ajoutez la ligne suivante à « mutt.conf »

macro index S "|/usr/bin/razor-report"

Ensuite, appuyez sur S sur le message spam dans « mutt » pour le signaler avec « razor-report ». Puisque « razor-report » se délègue, le contrôle reviendra immédiatement.
