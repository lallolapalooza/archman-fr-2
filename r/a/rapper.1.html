rapper(1) Manuel des commandes générales rapper(1)

NOM

rapper - Utilitaire de Raptor pour l'analyse et la sérialisation RDF

SYNTAXE

rapper [OPTIONS] URI-ENTREE [URI-BASE-ENTREE]

EXEMPLE

rapper -o ntriples http://planetrdf.com/guide/rss.rdf
rapper -i rss-tag-soup -o rss-1.0 pile-de-rss.xml http://example.org/base/
rapper --count http://example.org/index.rdf

DESCRIPTION

L'utilitaire rapper permet l'analyse de contenu RDF par la boîte à outils d'analyse RDF Raptor, en émettant les résultats sous forme de triplets RDF dans un choix de syntaxes. L'URI-ENTREE peut être un nom de fichier, '-' pour l'entrée standard ou, si Raptor est compilé avec une bibliothèque de récupération WWW, une URI générale. L'argument optionnel URI-BASE-ENTREE est utilisé comme URI de base de l'analyseur de document s'il est présent, sinon il prend par défaut la valeur de l'URI-ENTREE. La valeur '-' signifie qu'il n'y a pas d'URI de base.

OPTIONS

rapper utilise la syntaxe habituelle des lignes de commande GNU, avec des options longues commençant par deux tirets (`-') si elles sont prises en charge par la fonction getopt_long. Sinon, seules les options courtes sont disponibles.

-h, --help
Affiche un résumé des options.
-i, --input FORMAT
Définit le FORMAT d'entrée sur l'un des formats suivants : 'rdfxml' (RDF/XML, par défaut), 'ntriples' (N-Triples, voir ci-dessous), 'turtle' (Turtle, voir ci-dessous) ou 'rss-tag-soup' (RSS Tag Soup). L'analyseur RSS Tag Soup peut transformer les nombreux formats RSS XML, Atom 0.3 et Atom 1.0 en triplets RDF.
La liste des analyseurs dépend de la manière dont libraptor(3) a été compilé. La liste des analyseurs pris en charge est donnée dans le résumé d'aide fourni par -h.
-I, --input-uri URI
Définit l'URI de base de l'entrée/analyseur ou utilise la valeur '-' pour aucune base. La valeur par défaut est la valeur de l'argument URI-ENTREE.
-o, --output FORMAT
Définit le FORMAT de sortie sur 'ntriples' (N-Triples, par défaut), 'rdfxml' (RDF/XML), 'rdfxml-abbrev' (RDF/XML avec abréviations) ou 'rss-1.0' (RSS 1.0, également une syntaxe RDF/XML).
La liste des sérialiseurs dépend de la manière dont libraptor(3) a été compilé. La liste des sérialiseurs pris en charge est donnée dans le résumé d'aide fourni par -h.
-O, --output-uri URI
Définit l'URI de base de la sortie/du sérialiseur ou utilise la valeur '-' pour aucune base. La valeur par défaut est l'URI de base d'entrée, soit définie par l'argument URI-BASE-ENTREE, soit via l'option -I, --input-uri URI
-c, --count
Compte uniquement les triplets et ne produit aucune autre sortie.
-e, --ignore-errors
Ignore les erreurs, ne produit pas les messages et essaie de continuer l'analyse.
-f, --feature FONCTIONNALITE[=VALEUR]
Définit une fonctionnalité de l'analyseur ou du sérialiseur FONCTIONNALITE à une valeur, ou à 1 si VALEUR est omis. Utilisez -f help pour obtenir la liste des fonctionnalités valides pour les analyseurs et les sérialiseurs.
Si la forme -f 'xmlns:prefix="uri"' est utilisée, le préfixe et l'URI de l'espace de noms donnés seront définis pour la sérialisation. La syntaxe correspond à XML dans la mesure où le préfixe et/ou l'URI peuvent être omis.
-g, --guess
Devine l'analyseur à utiliser à partir de l'URI source plutôt que d'utiliser le FORMAT -i.
-q, --quiet
Aucun message d'information supplémentaire.
-r, --replace-newlines
Remplace les nouvelles lignes dans les littéraux multilignes par des espaces.
--show-graphs
Affiche les noms de graphes (URIs) tels qu'ils sont rencontrés dans l'entrée. Cela n'a de sens que pour les analyseurs qui prennent en charge les noms de graphes, comme l'analyseur TRiG.
--show-namespaces
Affiche les espaces de noms tels qu'ils sont rencontrés dans l'entrée.
-t, --trace
Affiche les URIs récupérées lors de l'analyse. Particulièrement utile pour surveiller ce que font les analyseurs guess et GRDDL.
-w, --ignore-warnings
Ignore les avertissements, ne produit pas les messages.
-v, --version
Affiche la version de raptor et quitte.

EXEMPLES

rapper -q -i ntriples -o rdfxml -f 'xmlns:rss="http://purl.org/rss/1.0/"' -f 'xmlns:ex="http://example.org/"' tests/test.nt
rapper -q -o rdfxml -f 'xmlns:rdfs="http://www.w3.org/2000/01/rdf-schema#"' tests/rdf-schema.rdf 'http://www.w3.org/2000/01/rdf-schema#'

CHANGEMENTS

2.0.0

Suppression de l'option -a qui ne faisait rien.

Suppression de l'option -m de rapper, mais elle n'a jamais été documentée ici.

Suppression de l'option -n qui était cachée depuis longtemps.

Suppression de l'option -s qui était équivalente à -f scanForRDF

1.4.16

Ajout de -I/--input-uri et -O/--output-uri pour définir séparément les URIs de base d'entrée et de sortie (analyseur et sérialiseur).

1.4.15

Ajout de -t/--trace pour effectuer des traces d'URI.

1.4.5

Mise à jour pour ajouter le sérialiseur rdfxml-abbrev

1.4.3

Mise à jour des analyseurs et sérialiseurs potentiels et description de -f pour définir les espaces de noms.

1.3.0

Ajout de -f pour les fonctionnalités.
Ajout de -g pour deviner l'analyseur à utiliser.

1.1.0

Suppression de -a, --assume car rdf:RDF est maintenant toujours facultatif.
