NOM

radiusd.conf - fichier de configuration du serveur FreeRADIUS

DESCRIPTION

Le fichier radiusd.conf réside dans le répertoire de la base de données radius, par défaut /etc/raddb. Il définit la configuration globale du serveur RADIUS FreeRADIUS.

CONTENU

Il existe un grand nombre de paramètres de configuration pour le serveur. La plupart sont documentés dans le fichier lui-même sous forme de commentaires. Cette page ne documente que le format du fichier. Veuillez lire le fichier radiusd.conf lui-même pour plus d'informations.

L'analyseur de fichiers de configuration est indépendant de la configuration du serveur. Cela signifie que vous pouvez mettre presque n'importe quoi dans le fichier de configuration. Tant qu'il est correctement formaté, le serveur démarrera.

Lorsque le serveur analyse le fichier de configuration, il ne recherche que les configurations qu'il comprend. Les éléments de configuration supplémentaires sont ignorés. Cette « fonctionnalité » peut être (ab)utilisée de manières intéressantes.

FORMAT DU FICHIER

Le format du fichier est basé sur les lignes, comme de nombreux autres fichiers de configuration Unix. Chaque entrée dans le fichier doit être placée sur sa propre ligne, bien que les continuations soient prises en charge.

Le fichier se compose d'éléments de configuration (paires variable = valeur), de sections et de commentaires.

Variables
Les variables peuvent être définies via : 
nom = valeur

Les chaînes simples et entre guillemets sont autorisées :

	string1 = "bonjour le monde"
	string2 = 'bonjour maman'
Sections
Une section commence par un nom de section, suivi sur la même ligne d'une accolade ouvrante '{'. Les sections peuvent contenir d'autres sections, des commentaires ou des variables. Les sections peuvent être imbriquées à n'importe quelle profondeur, limitée uniquement par la mémoire disponible. Une section se termine par une accolade fermante '}', sur une ligne à elle seule. 
	section {
		...
	}

Les sections peuvent parfois avoir un deuxième nom suivant le premier. Les situations où cela est légal dépendent du contexte. Voir les exemples et les commentaires dans le fichier radiusd.conf pour plus d'informations.

	section foo {
		...
	}
Commentaires
Toute ligne commençant par un (#) est considérée comme un commentaire et est ignorée. Les commentaires peuvent apparaître après des définitions de variable ou de section. 
	# commentaire
	foo = bar # définit la variable 'foo' avec la valeur 'bar'
	section {	# début de la section
	...
	}		# fin de la section
Continuations
Les longues lignes peuvent être réparties par des continuations, en utilisant '\' comme dernier caractère de la ligne. Par exemple, l'entrée suivante : 
	foo = "machin \
	truc \
	chose"

définira la valeur de la variable "foo" à "machin truc chose". Tout CR ou LF n'est pas transformé en espace, mais tout autre espace blanc est préservé dans la valeur finale.

RÉFÉRENCES

La valeur d'une variable peut faire référence à une autre variable. Ces références sont évaluées lors du chargement du fichier de configuration, ce qui signifie qu'il n'y a pas de coût d'exécution associé. Cette fonctionnalité est particulièrement utile pour transformer de longs textes répétitifs en textes courts.

Les variables sont référencées par ${nom_variable}, comme dans les exemples suivants.

	foo = bar       # définit la variable 'foo' avec la valeur 'bar'
	qui = ${foo}    # définit la variable 'qui' avec la valeur de la variable 'foo'
	mon = "${foo} un" # définit la variable 'mon' à "bar un"

Si la variable existe dans une section ou une sous-section, elle peut être référencée comme ${section.subsection.variable}. Les références avant l'heure ne sont pas autorisées. Les références relatives sont autorisées, en faisant précéder le nom d'un ou plusieurs points.

blogs = ${.foo}

Définira la variable blogs à la valeur de la variable foo, de la section actuelle.

blogs = ${..foo}

Définira la variable blogs à la valeur de la variable foo, de la section qui contient la section actuelle.

blogs = ${modules.detail.filename}

Définira la variable blogs à la valeur de la variable filename, du module detail, qui se trouve dans la section modules du fichier de configuration.

Les propriétés des sections parentes anonymes peuvent également être référencées, actuellement name et instance sont prises en charge.

modules {
	example foo {
		file = ${.:name}
	}
}

Définira la variable file au nom de la section parente (example).

modules {
	example foo {
		file = ${.:instance}
	}
}

Définira la variable file au nom d'instance de la section parente (foo).

modules {
	example foo {
		file = ${..:name}
	}
}

Définira la variable file au nom de la section parente de la section parente (modules).
