NOM

rabbitmq-diagnostics — Outils de diagnostic, de surveillance et de vérification de l'état de RabbitMQ

SYNTAXE

rabbitmq-diagnostics [-q] [-s] [-l] [-n nœud] [-t délai] commande [options_commande]

DESCRIPTION

rabbitmq-diagnostics est un outil en ligne de commande qui fournit des commandes utilisées pour le diagnostic, la surveillance et les vérifications d'état des nœuds RabbitMQ. Consultez les guides de documentation RabbitMQ pour en savoir plus sur le diagnostic, la surveillance et les vérifications d'état de RabbitMQ.

rabbitmq-diagnostics permet à l'opérateur d'inspecter l'état du nœud et du cluster. Un certain nombre de vérifications d'état sont disponibles pour être utilisées de manière interactive et par les outils de surveillance.

Par défaut, s'il n'est pas possible de se connecter au nœud cible et de s'authentifier auprès de celui-ci (par exemple, s'il est arrêté), l'opération échouera. Pour en savoir plus, consultez le guide de surveillance de RabbitMQ

OPTIONS

-n nœud
Le nœud par défaut est "rabbit@nom_hote_cible", où nom_hote_cible est l'hôte local. Sur un hôte nommé "myserver.example.com", le nom du nœud sera généralement "rabbit@myserver" (sauf si RABBITMQ_NODENAME a été redéfini). La sortie de "hostname -s" est généralement le suffixe correct à utiliser après le signe "@". Voir rabbitmq-server(8) pour les détails de configuration d'un nœud RabbitMQ.
-q, --quiet
Mode de sortie silencieux sélectionné. Les messages d'information sont réduits en mode silencieux.
-s, --silent
Mode de sortie muet sélectionné. Les messages d'information sont réduits et les en-têtes de table sont supprimés en mode muet.
-t délai, --timeout délai
Délai d'opération en secondes. Toutes les commandes ne prennent pas en charge les délais. Par défaut, c'est infini.
-l, --longnames
Doit être spécifié lorsque le cluster est configuré pour utiliser des noms de nœuds longs (FQDN). Pour en savoir plus, consultez le guide du clustering RabbitMQ
--erlang-cookie cookie
Secret partagé à utiliser pour s'authentifier auprès du nœud cible. Préférez utiliser un fichier local ou la variable d'environnement RABBITMQ_ERLANG_COOKIE plutôt que de spécifier cette option sur la ligne de commande. Pour en savoir plus, consultez le guide des outils CLI RabbitMQ

COMMANDES

La plupart des commandes fournies par rabbitmq-diagnostics inspectent l'état du nœud et du cluster ou effectuent des vérifications d'état.

Les commandes qui listent les entités de topologie (par exemple, les files d'attente) utilisent la tabulation comme délimiteur de colonne. Ces commandes et leurs arguments sont délégués à rabbitmqctl(8).

Certaines commandes ( list_queues, list_exchanges, list_bindings et list_consumers) acceptent un paramètre facultatif vhost.

Les commandes list_queues, list_exchanges et list_bindings acceptent un paramètre d'hôte virtuel facultatif pour lequel afficher les résultats. La valeur par défaut est "/".

Surveillance, observabilité et vérifications d'état

alarms

Liste les alarmes de ressources, le cas échéant, dans le cluster.

Voir guide des alarmes de ressources RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics alarms
certificates

Affiche les certificats du nœud pour chaque écouteur sur le nœud cible configuré pour utiliser TLS.

Exemple :

rabbitmq-diagnostics certificates
check_alarms

Vérification de l'état qui échoue (retourne un code non nul) s'il y a des alarmes actives sur l'un des nœuds du cluster.

Voir le guide des alarmes de ressources RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics check_alarms
check_certificate_expiration [--unit time_unit] [--within seconds]

Vérifie la date d'expiration des certificats pour chaque écouteur sur le nœud cible configuré pour utiliser TLS. Les unités de temps prises en charge sont :

  • jours
  • semaines
  • mois
  • années

Exemple :

rabbitmq-diagnostics check_certificate_expiration --unit semaines --within 6
check_local_alarms

Vérification de l'état qui échoue (retourne un code non nul) s'il y a des alarmes actives sur le nœud cible.

Voir le guide des alarmes de ressources RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics check_local_alarms
check_port_connectivity

Vérification de l'état qui échoue (retourne un code non nul) si des ports d'écoute sur le nœud cible ne parviennent pas à accepter une nouvelle connexion TCP ouverte par rabbitmq-diagnostics

La vérification valide uniquement si une nouvelle connexion TCP est acceptée. Elle n'effectue pas de handshake de protocole de messagerie ni d'authentification.

Voir le guide réseau RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics check_port_connectivity
check_port_listener port

Vérification de l'état qui échoue (retourne un code non nul) si le nœud cible n'écoute pas sur le port spécifié (aucun écouteur n'utilise ce port).

Voir le guide réseau RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics check_port_listener 5672
check_protocol_listener protocol

Vérification de l'état qui échoue (retourne un code non nul) si le nœud cible n'a pas d'écouteur pour le protocole spécifié.

Voir le guide réseau RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics check_protocol_listener mqtt
check_running

Vérification de l'état qui échoue (retourne un code non nul) si l'application RabbitMQ n'est pas en cours d'exécution sur le nœud cible.

Si rabbitmqctl(8) a été utilisé pour arrêter l'application, cette vérification échouera.

Exemple :

rabbitmq-diagnostics check_running
check_virtual_hosts

Vérification de l'état qui vérifie si tous les vhosts sont en cours d'exécution sur le nœud cible

Exemple :

rabbitmq-diagnostics check_virtual_hosts --timeout 60
cipher_suites

Liste les suites de chiffrement activées par défaut. Pour lister toutes les suites de chiffrement disponibles, ajoutez l'argument --all.

Exemple :

rabbitmq-diagnostics cipher_suites --format openssl --all
command_line_arguments

Affiche les arguments de ligne de commande et les drapeaux du nœud cible tels que rapportés par l'environnement d'exécution.

Exemple :

rabbitmq-diagnostics command_line_arguments -n rabbit@hostname
consume_event_stream [--duration seconds | -d seconds] [--pattern pattern] [--timeout milliseconds]

Diffuse les événements internes d'un nœud en cours d'exécution. La sortie est compatible avec jq.

Exemple :

rabbitmq-diagnostics consume_event_stream -n rabbit@hostname --duration 20 --pattern queue_.*
discover_peers

Exécute une découverte de pairs sur le nœud cible et affiche les nœuds découverts, le cas échéant.

Voir le guide de formation de cluster RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics discover_peers --timeout 60
environment
Voir environment dans rabbitmqctl(8)
erlang_cookie_hash

Produit une valeur hachée du secret partagé utilisé par le nœud cible pour authentifier les outils CLI et les pairs. La valeur peut être comparée au hachage trouvé dans les messages d'erreur des outils CLI.

Voir le guide de clustering RabbitMQ pour en savoir plus.

Exemple :

rabbitmq-diagnostics erlang_cookie_hash -q
erlang_version

Rapporte la version Erlang/OTP du nœud cible.

Exemple :

rabbitmq-diagnostics erlang_version -q
is_booting

Indique si l'application RabbitMQ est en cours de démarrage (pas encore démarrée/en cours d'exécution ou arrêtée) sur le nœud cible.

Exemple :

rabbitmq-diagnostics is_booting
is_running

Indique si l'application RabbitMQ est complètement démarrée et en cours d'exécution (c'est-à-dire non arrêtée) sur le nœud cible.

Exemple :

rabbitmq-diagnostics is_running

listeners

Liste les écouteurs (sockets liés) sur ce nœud. Utilisez ceci pour inspecter les protocoles et les ports sur lesquels le nœud écoute pour les connexions clients, outils CLI et pairs.

Voir le guide Réseau de RabbitMQ pour en savoir plus.

Exemple:

rabbitmq-diagnostics listeners
log_tail [--number nombre | -N nombre [--timeout millisecondes]

Affiche les N dernières lignes du journal sur le nœud.

Exemple:

rabbitmq-diagnostics log_tail --number 100
]
 
log_tail_stream [--duration secondes | -d secondes] [--timeout millisecondes]

Diffuse les journaux d'un nœud en cours d'exécution pendant une période donnée.

Exemple:

rabbitmq-diagnostics log_tail_stream --duration 60
maybe_stuck

Échantillonne périodiquement les traces de pile de tous les processus Erlang ("threads légers") sur le nœud. Signale les processus pour lesquels les échantillons de trace de pile sont identiques.

Des échantillons identiques peuvent indiquer que le processus ne progresse pas, mais ce n'est pas nécessairement une indication de problème.

Exemple:

rabbitmq-diagnostics maybe_stuck -q
memory_breakdown [--unit unité_mémoire]

Affiche l'utilisation de la mémoire du nœud par catégorie. Les unités de mémoire prises en charge sont:

  • octets
  • mégaoctets
  • gigaoctets
  • téraoctets

Voir le guide Utilisation de la mémoire de RabbitMQ pour en savoir plus.

Exemple:

rabbitmq-diagnostics memory_breakdown --unit gigaoctets
observer [--interval secondes]

Démarre une interface observateur CLI sur le nœud cible.

Exemple:

rabbitmq-diagnostics observer --interval 10
ping

Vérification de base de l'état. Réussit si le nœud cible (runtime) est en cours d'exécution et que rabbitmq-diagnostics peut s'authentifier auprès de lui avec succès.

report

Voir report dans rabbitmqctl(8)

runtime_thread_stats [--sample-interval intervalle]

Effectue un échantillonnage de l'activité des threads d'exécution (noyau) pendant intervalle secondes et le rapporte.

Pour que cette commande fonctionne, Erlang/OTP sur le nœud cible doit être compilé avec le support de la comptabilité des microétats et avoir le package runtime_tools disponible.

Exemple:

rabbitmq-diagnostics runtime_thread_stats --sample-interval 15
schema_info [--no_table_headers] [colonne ...] [--timeout millisecondes]

Voir schema_info dans rabbitmqctl(8)

server_version

Rapporte la version du nœud cible.

Exemple:

rabbitmq-diagnostics server_version -q
status

Voir status dans rabbitmqctl(8)

tls_versions

Liste toutes les versions TLS prises en charge par le runtime sur le nœud cible. Notez que RabbitMQ peut être configuré pour n'accepter qu'un sous-ensemble de ces versions, par exemple, SSLv3 est désactivé par défaut.

Voir le guide TLS de RabbitMQ pour en savoir plus.

Exemple:

rabbitmq-diagnostics tls_versions -q
