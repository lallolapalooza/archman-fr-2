radrelay.conf(5) Fichier de configuration FreeRADIUS radrelay.conf(5)

NOM

radrelay.conf - fichier de configuration pour la personnalité "radrelay" du serveur FreeRADIUS

DESCRIPTION

Le fichier radrelay.conf réside dans le répertoire de la base de données radius, par défaut /etc/raddb. Il définit la configuration globale du serveur FreeRADIUS, lorsque le serveur fonctionne en tant que "radrelay".

FORMAT DU FICHIER

Pour une description détaillée du format du fichier, voir "man radiusd.conf". Les entrées de configuration sont très similaires pour radrelay.conf, avec quelques différences comme indiqué ici.

RÉPLICATION POUR SAUVEGARDES

De nombreux sites exécutent plusieurs serveurs radius ; au moins un serveur principal et un serveur de secours. Lorsque le serveur principal tombe en panne, la plupart des NAS le détectent et basculent sur le serveur de secours.

Cela entraînera l'envoi de vos paquets de comptabilisation vers le serveur de secours - et certains NAS ne basculent même pas vers le serveur principal lorsqu'il est de nouveau opérationnel.

Le résultat est que les enregistrements de comptabilisation sont manquants, et/ou que l'administrateur doit faire des contorsions pour combiner les différents fichiers de détails de plusieurs serveurs. Cela signifie également que la base de données de sessions ("radutmp", utilisée pour radwho et la détection d'utilisation simultanée) se désynchronise.

radrelay résout ce problème en "relaisant" les paquets d'un serveur à un autre, de sorte qu'ils aient tous deux le même ensemble de données de comptabilisation.

MISE EN TAMPON POUR LES SERVEURS À FORTE CHARGE

Si le serveur RADIUS reçoit soudainement de nombreux paquets de comptabilisation, il se peut qu'il n'ait pas suffisamment de puissance CPU pour les traiter tous en temps voulu. Ce problème est particulièrement marquant lorsque les paquets de comptabilisation sont dirigés vers une base de données backend.

De même, vous pourriez avoir une base de données qui suit les sessions "en direct" et une autre qui suit les données de comptabilisation historiques. Dans ce cas, l'accès à la première base de données est rapide, car elle est petite. L'accès à la seconde base de données peut être plus lent, car elle peut contenir plusieurs gigaoctets de données. De plus, il est important d'écrire dans la première base de données en temps voulu, tandis que les données peuvent être écrites dans la seconde base de données avec un délai de quelques minutes, sans aucun dommage.

RELAIS DES PAQUETS DE COMPTABILISATION

Le fichier radrelay.conf contrôle la personnalité "radrelay" du serveur, qui peut effectuer les deux fonctions ci-dessus en même temps.

UTILISATION

Tout d'abord, vous devriez configurer le serveur radius principal pour enregistrer dans un fichier de détail supplémentaire et unique. Cela peut être fait en ajoutant une instance supplémentaire du module detail à radiusd.conf :

Par exemple :

	detail radrelay-detail {
		filename = ${radacctdir}/radrelay/detail
		permissions = 0600
		dir_permissions = 0755
		locking = yes
	}
	...
	accounting {
		...
		radrelay-detail
		...
	}

Cette configuration entraînera l'enregistrement des paquets de comptabilisation dans le fichier ${radacctdir}/radrelay/detail. Ce fichier ne doit pas être géré par les scripts de rotation de journaux standards, car le programme radrelay le lira et le gérera.

EXEMPLE RADRELAY.CONF

Voir le fichier radrelay.conf pour des instructions détaillées sur les entrées de configuration, leur signification et leur utilisation.

Pour que la partie "radrelay" du serveur lise le fichier de détail ci-dessus, configurez radrelay.conf avec la section suivante :

	listen {
		type = detail
		filename = ${radacctdir}/radrelay/detail
		max_outstanding = 100
		identity = radrelay
	}

Le serveur lira les paquets de comptabilisation à partir du fichier de détail et les traitera comme s'il les avait reçus du NAS. Par conséquent, vous devriez configurer la section "accounting" de radrelay.conf pour écrire les enregistrements de comptabilisation dans un module "sql" ou pour les proxifier vers un autre serveur RADIUS.

Ensuite, démarrez le serveur via la commande suivante :

$ radiusd -n radrelay

Le serveur devrait démarrer, lire le fichier de détail et traiter les paquets de comptabilisation à partir de celui-ci.

NOTES

Le fichier radiusd.conf n'est pas du tout lu lorsque le serveur fonctionne en tant que radrelay. Veuillez modifier radrelay.conf.
