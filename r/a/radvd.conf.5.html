RADVD.CONF(5) RADVD.CONF(5)

NOM

radvd.conf - fichier de configuration du démon d'annonces de routeur radvd

DESCRIPTION

Ce fichier décrit les informations incluses dans l'annonce de routeur (RA) d'une interface spécifique.

Le fichier contient une ou plusieurs définitions d'interface de la forme :

interface nom {
	liste d'options spécifiques à l'interface
	liste de définitions de préfixes
	liste de clients (adresses IPv6) à annoncer
	liste de définitions de routes
	liste de définitions RDNSS
	liste de définitions DNSSL
	liste de définitions ABRO
	liste de définitions NAT64 pref64
	liste de préfixes à ignorer automatiquement
	liste d'adresses sources RA acceptables
};

Toutes les options possibles spécifiques à l'interface sont détaillées ci-dessous. Chaque option doit être terminée par un point-virgule. Les options ne sont pas sensibles à la casse.

Les définitions de préfixes sont de la forme :

prefix préfixe/longueur {
	liste d'options spécifiques au préfixe
};

Le préfixe peut être un préfixe réseau ou l'adresse de l'interface. L'adresse de l'interface doit être utilisée lors de l'utilisation des extensions Mobile IPv6.

Le préfixe spécial « ::/64 » est également supporté sur les systèmes qui implémentent getifaddrs() (sur d'autres systèmes, l'activation de la configuration échoue et radvd se termine). Lorsqu'il est configuré, radvd sélectionne tous les préfixes non locaux du lien attribués à l'interface et commence à les annoncer (sauf s'ils sont ignorés avec autoignoreprefixes). Ceci peut être applicable dans des scénarios non-6to4 où le préfixe amont peut changer. Cette option est incompatible avec l'option Base6to4Interface. L'option AdvRouterAddr est toujours activée lorsque cette configuration est utilisée.

Toutes les options possibles spécifiques au préfixe sont décrites ci-dessous. Chaque option doit être terminée par un point-virgule.

Les valeurs décimales ne sont autorisées que pour MinDelayBetweenRAs, MaxRtrAdvInterval et MinRtrAdvInterval. Les valeurs décimales ne doivent être utilisées que lors de l'utilisation des extensions Mobile IPv6.

Les définitions de routes sont de la forme :

route préfixe/longueur {
	liste d'options spécifiques à la route
};

Le préfixe d'une définition de route doit être un préfixe réseau ; il peut être utilisé pour annoncer des routes plus spécifiques aux hôtes.

Les définitions RDNSS (serveur DNS récursif) sont de la forme :

RDNSS ip [ip] [ip] {
	liste d'options spécifiques à RDNSS
};

Chaque bloc de définition RDNSS a une longueur maximale de 2040 octets incluant l'en-tête, ce qui permet d'accueillir jusqu'à 127 adresses.

Si la longueur est dépassée, radvd enregistrera une erreur non fatale au lieu d'envoyer l'option.

Les définitions DNSSL (liste de recherche DNS) sont de la forme :

DNSSL suffixe [suffixe] [suffixe] [...] {
	liste d'options spécifiques à DNSSL
};

Chaque bloc de définition DNSSL a une longueur maximale de 2040 octets incluant l'en-tête, appliqué après que les suffixes soient encodés selon la RFC1035, section 3.1.

Si la longueur est dépassée, radvd enregistrera une erreur non fatale au lieu d'envoyer l'option.

Par défaut, radvd enverra des annonces de route multicast afin que chaque nœud sur le lien puisse les utiliser. La liste des clients (adresse IPv6) à annoncer et à partir desquels accepter les sollicitations de route peut être configurée. Si cela est fait, radvd n'enverra pas de messages aux adresses multicast mais uniquement aux adresses unicast configurées. Les sollicitations provenant d'autres adresses sont refusées sauf si UnrestrictedUnicast est activé. Ceci est similaire à UnicastOnly mais inclut les messages périodiques et la configuration d'accès client entrant. Voir la section exemples pour un cas d'utilisation.

Les définitions sont de la forme :

clients {
        liste d'adresses IPv6
};

Les clients peuvent être précédés de « ! » pour les ignorer complètement et ne jamais leur envoyer d'annonces.

Par défaut, radvd utilisera la première adresse locale du lien pour l'interface comme adresse source pour les annonces de route. Cela peut être écrasé en définissant manuellement la liste des adresses sources acceptables. Si cela est fait, radvd utilisera uniquement la première adresse de l'interface qui est présente dans les adresses sources configurées. Cette fonctionnalité ne usurpera PAS l'adresse source, mais peut être utile en combinaison avec VRRP ou d'autres fonctionnalités qui gèrent un MAC virtuel/de basculement.

AdvRASrcAddress {
        liste d'adresses IPv6
};

Les définitions ABRO (Authoritative Border Router Option) sont de la forme :

abro adresse-IPv6 {
        liste d'options spécifiques à abro
};

NAT64 pref64 (le préfixe NAT64 inclus dans les annonces de routeur) :

nat64prefix préfixe/longueur {
	liste d'options spécifiques au préfixe NAT64
};

La valeur de longueur ne peut être que /32, /40, /48, /56, /64, ou /96.

Lors de l'utilisation du préfixe spécial « ::/64 », cette option forme une liste d'ignorés pour les préfixes qui ne doivent pas être générés et annoncés automatiquement. N'a aucun effet sur toute autre définition de préfixe.

Les définitions sont de la forme :

autoignoreprefixes {
        liste de préfixes IPv6
};

OPTIONS SPÉCIFIQUES À L'INTERFACE

IgnoreIfMissing on|off

Un indicateur indiquant si l'interface doit être ignorée ou non si elle n'existe pas au démarrage.

Ceci est utile pour les interfaces dynamiques qui ne sont pas actives lorsque radvd démarre ou qui sont désactivées et réactivées dynamiquement pendant que radvd s'exécute.

Les versions actuelles de radvd tentent automatiquement de réactiver les interfaces.

L'activation de IgnoreIfMissing permet également d'étouffer certains avertissements dans les messages de log relatifs aux interfaces manquantes.

Par défaut : on

AdvSendAdvert on|off

Un indicateur indiquant si le routeur envoie des annonces de routeur périodiques et répond aux sollicitations de routeur.

Cette option n'a plus besoin d'être spécifiée en premier, mais elle doit être on pour activer l'annonce sur cette interface.

Par défaut : off

UnicastOnly on|off

Indique que le type de lien de l'interface ne prend en charge que l'unicast. Cela empêchera l'envoi d'annonces non sollicitées et provoquera l'envoi d'annonces sollicitées en unicast au nœud sollicitant. Cette option est nécessaire pour les liens multiples non diffusés, tels que ISATAP.

Par défaut : off

UnrestrictedUnicast on|off

Un indicateur indiquant si l'on doit répondre ou non aux sollicitations de routeur lorsqu'il existe une liste de clients configurée.

Cela permet d'envoyer des annonces non sollicitées régulières à certains clients sans ignorer les sollicitations de routeur provenant de clients inconnus.

Par défaut : off

AdvRASolicitedUnicast on|off

Indique que les sollicitations de routeur seront répondues avec des annonces de routeur unicast, comme recommandé par la RFC7772. Les grands réseaux avec une forte concentration d'appareils mobiles pourraient subir une décharge de la batterie, lorsque les messages d'annonce de routeur sollicités sont transmis en multicast.

Ceci correspond à l'option Cisco IOS ipv6 nd ra solicited unicast

Par défaut : on

MaxRtrAdvInterval secondes

Le temps maximum autorisé entre l'envoi d'annonces de routeur multicast non sollicitées depuis l'interface, en secondes.

Doit être au moins 4 secondes et au plus 1800 secondes.

Minimum lors de l'utilisation des extensions Mobile IPv6 : 0.07.

Pour les valeurs inférieures à 0.2 secondes, 0.02 secondes sont ajoutées pour tenir compte des granularités de planification spécifiées dans la RFC3775.

Par défaut : 600 secondes

MinRtrAdvInterval secondes

Le temps minimum autorisé entre l'envoi d'annonces de routeur multicast non sollicitées depuis l'interface, en secondes.

Doit être au moins 3 secondes et au plus 0.75 * MaxRtrAdvInterval.

Par défaut : 3 secondes

AdvDefaultLifetime secondes

La durée de vie par défaut des informations de routeur. Cette valeur est utilisée pour les informations de routeur annoncées par le routeur. Elle est utilisée par les hôtes pour déterminer pendant combien de temps ils peuvent utiliser les informations de route par défaut fournies dans l'annonce.

Doit être supérieure à MinRtrAdvInterval.

Par défaut : 1800 secondes

AdvHomeAgentInfo on|off

Un indicateur pour activer ou désactiver la publication des informations du Home Agent. Si activé, radvd annonceira une option Home Agent avec les champs de priorité et de durée de vie définis par AdvHomeAgentPriority et AdvHomeAgentLifetime.

Par défaut : off

AdvHomeAgentPriority priorité

La priorité du Home Agent pour l'annonce Mobile IPv6. La valeur doit être comprise entre -2147483648 et 2147483647.

Par défaut : 0

AdvHomeAgentLifetime secondes

La durée de vie du Home Agent pour l'annonce Mobile IPv6. La valeur doit être comprise entre 0 et 1800. Si elle est définie sur 0, cela indique que le routeur n'est pas un Home Agent.

Par défaut : 1800

AdvOtherConf on|off

Un indicateur indiquant si les hôtes doivent obtenir des informations de configuration (comme les serveurs DNS) auprès d'une autre source.

Par défaut : off

AdvManagedFlag on|off

Un indicateur indiquant si les hôtes doivent obtenir leurs adresses IPv6 auprès d'un serveur DHCPv6.

Par défaut : off

AdvRdnssOption on|off

Un indicateur indiquant si l'option RDNSS doit être incluse dans les annonces de routeur.

Par défaut : off

AdvDNSSLCacheTimeout msec

La période de validité du cache des enregistrements DNSSL, en millisecondes. La valeur doit être comprise entre 0 et 4294967295. Si elle est définie sur 0, cela désactive la publicité DNSSL.

Par défaut : 0

AdvDNSSLOption on|off

Un indicateur indiquant si l'option DNSSL doit être incluse dans les annonces de routeur.

Par défaut : off

AdvRouteInfo on|off

Un indicateur indiquant si les informations de route doivent être incluses dans les annonces de routeur.

Par défaut : off

AdvLinkMTU mtu

La valeur MTU du lien. Doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvReachableTime msec

Le temps de réception des paquets, en millisecondes. Doit être compris entre 0 et 4294967295.

Par défaut : 30000

AdvRetransTimer msec

Le temps de retransmission des paquets, en millisecondes. Doit être compris entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvCurHopLimit limit

La limite de sauts actuelle pour les paquets originaires de l'interface. Doit être comprise entre 0 et 255.

Par défaut : 64

AdvRouterAddr on|off

Un indicateur indiquant si l'adresse de l'interface doit être annoncée comme adresse de routeur. Si off, l'adresse de l'interface n'est pas annoncée.

Par défaut : on

AdvSourceSpecific on|off

Un indicateur indiquant si l'adresse source IPv6 de l'annonce doit être annoncée comme une adresse source spécifique. Si elle est activée, le routeur annonce une option RA Source-Specific Address Configuration. Sinon, le routeur annonce une option RA Prefix Information.

Par défaut : off

AdvV6Address on|off

Un indicateur indiquant si l'adresse IPv6 de l'interface doit être annoncée comme une adresse source spécifique. Si elle est activée, le routeur annonce une option RA Source-Specific Address Configuration.

Par défaut : off

AdvRouterSelection on|off

Indique si le routeur doit participer à la sélection de routeur (RFC7772). Si activé, le routeur utilisera une durée de vie de 0 pour les informations de préfixe qui ne sont pas destinées à la configuration d'adresses et annoncera une priorité plus faible pour lui-même.

Par défaut : off

MaxIntervalBetweenNeighborSolicitations secondes

La période maximale entre deux sollicitations de voisin, en secondes. Cette valeur est utilisée pour la gestion de la charge et la prévention des attaques par déni de service.

Par défaut : 1000

Base6to4Interface interface

La spécification d'une interface pour le mécanisme 6to4. Ceci est utilisé pour obtenir automatiquement une adresse IPv6 6to4.

Aucune valeur par défaut.

Remote6to4Address adresse

L'adresse IPv4 du routeur 6to4 distant. Ceci est utilisé lorsque l'interface spécifiée par Base6to4Interface n'est pas configurée avec une adresse IPv4 publique.

Aucune valeur par défaut.

AdvRouterAddrLifetime secondes

La durée de vie de l'adresse du routeur annoncée. Cette valeur est utilisée pour les annonces RA lorsque l'option AdvRouterAddr est activée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvPreferredLifetime secondes

La durée de vie préférée de l'adresse de l'interface. Cette valeur est utilisée lorsque l'option AdvRouterAddr est activée et que l'adresse de l'interface est annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

PREFIX SPECIFIC OPTIONS

AdvOnLink on|off

Un indicateur indiquant si le préfixe doit être annoncé comme étant sur le lien.

Par défaut : on

AdvAutonomous on|off

Un indicateur indiquant si le préfixe doit être annoncé comme étant autonome (c'est-à-dire qu'il peut être utilisé pour la configuration automatique des adresses).

Par défaut : on

AdvRouterAddr on|off

Un indicateur indiquant si le préfixe doit être annoncé comme une adresse de routeur. Si off, le préfixe n'est pas annoncé comme une adresse de routeur.

Par défaut : off

AdvRouterAddrLifetime secondes

La durée de vie de l'adresse de routeur annoncée pour ce préfixe. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvPreferredLifetime secondes

La durée de vie préférée de ce préfixe. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvValidLifetime secondes

La durée de vie valide de ce préfixe. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvRouterSelection on|off

Un indicateur indiquant si ce préfixe doit être utilisé pour la sélection de routeur. Si activé, le routeur annonce ce préfixe avec une durée de vie de 0 pour les informations de préfixe qui ne sont pas destinées à la configuration d'adresses.

Par défaut : off

ROUTE SPECIFIC OPTIONS

AdvRouteLifetime secondes

La durée de vie de la route annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

AdvRoutePreference préférence

La préférence de la route annoncée. Les valeurs possibles sont high, medium, et low.

Par défaut : medium

RDNSS SPECIFIC OPTIONS

AdvRDNSSLifetime secondes

La durée de vie du serveur DNS récursif annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

DNSSL SPECIFIC OPTIONS

AdvDNSSLifetime secondes

La durée de vie de la liste de recherche DNS annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

NAT64 PREFIX SPECIFIC OPTIONS

AdvNAT64Lifetime secondes

La durée de vie du préfixe NAT64 annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

ABRO SPECIFIC OPTIONS

AdvABROLifetime secondes

La durée de vie de l'option ABRO annoncée. La valeur doit être comprise entre 0 et 4294967295.

Par défaut : 0 (c'est-à-dire que l'option n'est pas annoncée)

EXAMPLES

Un exemple simple de fichier radvd.conf:

interface eth0 {
	AdvSendAdvert "on"
	MinRtrAdvInterval 3
	MaxRtrAdvInterval 10
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
};

Un exemple avec des options supplémentaires:

interface eth0 {
	AdvSendAdvert "on"
	MaxRtrAdvInterval 600
	MinRtrAdvInterval 200
	AdvOtherConf "on"
	AdvManagedFlag "off"
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
		AdvPreferredLifetime 604800
		AdvValidLifetime 2592000
	}
	RDNSS 2001:db8:3:3::1 {
		AdvRDNSSLifetime 10800
	}
	DNSSL example.com {
		AdvDNSSLifetime 10800
	}
};

Un exemple utilisant l'option clients pour envoyer des annonces unicast uniquement aux clients spécifiés:

interface eth0 {
	AdvSendAdvert "on"
	clients {
		2001:db8:1:1::1
		2001:db8:1:1::2
	}
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
};

Un exemple utilisant l'option clients avec UnrestrictedUnicast pour autoriser les sollicitations de routeur inconnues:

interface eth0 {
	AdvSendAdvert "on"
	UnrestrictedUnicast "on"
	clients {
		!2001:db8:1:1::1
		2001:db8:1:1::2
	}
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
};

Un exemple utilisant AdvRASrcAddress pour spécifier l'adresse source des annonces RA:

interface eth0 {
	AdvSendAdvert "on"
	AdvRASrcAddress {
		2001:db8:ffff:ffff::1
	}
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
};

Un exemple avec la définition de 6to4:

interface eth0 {
	AdvSendAdvert "on"
	Base6to4Interface "eth0"
	Remote6to4Address "192.0.2.1"
	prefix 2001:db8:1:1::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
};

Un exemple utilisant le préfixe spécial "::/64" pour découvrir automatiquement les préfixes de l'interface:

interface eth0 {
	AdvSendAdvert "on"
	prefix ::/64 {
		AdvOnLink "on"
		AdvAutonomous "on"
	}
	autoignoreprefixes {
		2001:db8:0:0::/56
	}
};

MinDelayBetweenRAs secondes

Le temps minimum autorisé entre l'envoi de publicités de routeur multicast depuis l'interface, en secondes.

Ceci s'applique aux publicités de routeur multicast sollicitées. Ceci est défini comme la constante de protocole MIN_DELAY_BETWEEN_RAS dans la RFC4861. MIPv6 redéfinit ce paramètre pour avoir un minimum de 0,03 seconde.

Minimum lors de l'utilisation des extensions Mobile IPv6 : 0,03.

Défaut : 3

AdvManagedFlag on|off

Lorsqu'il est activé, les hôtes utilisent le protocole administré (étatistate) pour l'autoconfiguration d'adresses en plus de toutes les adresses autoconfigurées à l'aide de l'autoconfiguration d'adresses sans état. L'utilisation de ce drapeau est décrite dans la RFC 4862.

Défaut : off

AdvOtherConfigFlag on|off

Lorsqu'il est activé, les hôtes utilisent le protocole administré (étatistate) pour l'autoconfiguration d'autres informations (non d'adresses). L'utilisation de ce drapeau est décrite dans la RFC 4862.

Défaut : off

AdvLinkMTU entier

L'option MTU est utilisée dans les messages de publicité de routeur pour s'assurer que tous les nœuds sur un lien utilisent la même valeur MTU dans les cas où la MTU du lien n'est pas bien connue.

Si spécifié (c'est-à-dire différent de 0), ne doit pas être inférieur à 1280 et ne doit pas être supérieur à la MTU maximale autorisée pour ce lien (par exemple, Ethernet a une MTU maximale de 1500. Voir RFC 4864).

Défaut : 0

AdvReachableTime millisecondes

Le temps, en millisecondes, pendant lequel un nœud suppose qu'un voisin est joignable après avoir reçu une confirmation de joignabilité. Utilisé par l'algorithme de détection de non-joignabilité des voisins (voir section 7.3 de la RFC 4861). Une valeur de zéro signifie non spécifiée (par ce routeur).

Ne doit pas être supérieur à 3 600 000 millisecondes (1 heure).

Défaut : 0

AdvRetransTimer millisecondes

Le temps, en millisecondes, entre les messages de sollicitation de voisin retransmis. Utilisé par la résolution d'adresses et l'algorithme de détection de non-joignabilité des voisins (voir sections 7.2 et 7.3 de la RFC 4861). Une valeur de zéro signifie non spécifiée (par ce routeur).

Défaut : 0

AdvCurHopLimit entier

La valeur par défaut qui doit être placée dans le champ Limite de saut de l'en-tête IP pour les paquets IP sortants (unicast). La valeur doit être définie sur le diamètre actuel de l'Internet. La valeur zéro signifie non spécifiée (par ce routeur).

Défaut : 64

AdvDefaultLifetime secondes

La durée de vie associée au routeur par défaut en unités de secondes. La valeur maximale correspond à 18,2 heures. Une durée de vie de 0 indique que le routeur n'est pas un routeur par défaut et ne doit pas apparaître dans la liste des routeurs par défaut. La durée de vie du routeur ne s'applique qu'à l'utilité du routeur en tant que routeur par défaut ; elle ne s'applique pas aux informations contenues dans d'autres champs ou options de message. Les options qui nécessitent des limites de temps pour leurs informations incluent leurs propres champs de durée de vie.

Doit être zéro ou compris entre MaxRtrAdvInterval et 9000 secondes.

Défaut : 3 * MaxRtrAdvInterval (Minimum 1 seconde).

AdvDefaultPreference low|medium|high

La préférence associée au routeur par défaut, comme « low », « medium » ou « high ».

Défaut : medium

AdvSourceLLAddress on|off

Lorsqu'il est activé, l'adresse de lien local de l'interface sortante est incluse dans la publicité RA.

Défaut : on

RemoveAdvOnExit on|off

Lors de l'arrêt, envoyez une dernière publicité avec une durée de vie du routeur nulle. Cela devrait faire en sorte que le routeur et les routes soient immédiatement supprimés de la table de routage des nœuds de réception. Cela pourrait devoir être désactivé (« off ») dans une configuration vrrp ou carp.

Défaut : on

AdvHomeAgentFlag on|off

Lorsqu'il est activé, indique que le routeur émetteur est capable de servir d'agent domestique Mobile IPv6. Lorsqu'il est activé, les limites minimales spécifiées par Mobile IPv6 sont utilisées pour MinRtrAdvInterval et MaxRtrAdvInterval.

Défaut : off

AdvHomeAgentInfo on|off

Lorsqu'il est activé, l'option d'information de l'agent domestique (spécifiée par Mobile IPv6) est incluse dans les publicités de routeur. AdvHomeAgentFlag doit également être activé lors de l'utilisation de cette option.

Défaut : off

HomeAgentLifetime secondes

La durée en secondes (par rapport au moment où le paquet est envoyé) pendant laquelle le routeur propose des services d'agent domestique Mobile IPv6. Une valeur de 0 ne doit pas être utilisée. La durée de vie maximale est de 65520 secondes (18,2 heures). Cette option est ignorée si AdvHomeAgentInfo n'est pas activé.

Si HomeAgentLifetime et HomeAgentPreference sont tous deux réglés sur leurs valeurs par défaut, l'option d'information de l'agent domestique ne sera pas envoyée.

Défaut : AdvDefaultLifetime

HomeAgentPreference entier

La préférence pour l'agent domestique envoyant cette publicité de routeur. Les valeurs supérieures à 0 indiquent un agent domestique plus préférable, les valeurs inférieures à 0 indiquent un agent domestique moins préférable. Cette option est ignorée si AdvHomeAgentInfo n'est pas activé.

Si HomeAgentLifetime et HomeAgentPreference sont tous deux réglés sur leurs valeurs par défaut, l'option d'information de l'agent domestique ne sera pas envoyée.

Défaut : 0

AdvMobRtrSupportFlag on|off

Lorsqu'il est activé, l'agent domestique signale qu'il prend en charge les enregistrements de routeur mobile (spécifiés par NEMO Basic). AdvHomeAgentInfo doit également être activé lors de l'utilisation de cette option.

Défaut : off

AdvIntervalOpt on|off

Lorsqu'il est activé, l'option Intervalle de publicité (spécifiée par Mobile IPv6) est incluse dans les publicités de routeur. Lorsqu'il est activé, les limites minimales spécifiées par Mobile IPv6 sont utilisées pour MinRtrAdvInterval et MaxRtrAdvInterval.

L'intervalle de publicité est basé sur le paramètre MaxRtrAdvInterval configuré, sauf lorsque celui-ci est inférieur à 200 ms. Dans ce cas, l'intervalle annoncé est (MaxRtrAdvInterval + 20 ms).

Défaut : off

AdvCaptivePortalAPI "URL"

Lorsqu'il est activé, annonce l'URL de l'API du portail captif RFC8908.

Voir RFC8952 Architecture du portail captif, RFC8910 Identification du portail captif dans DHCP et les publicités de routeur (RA) et RFC8908 API du portail captif pour plus d'informations.

OPTIONS SPÉCIFIQUES AU PRÉFIXE

AdvOnLink on|off

Cette option spécifie si le préfixe annoncé doit être marqué comme étant sur le lien. Si cette option est activée, le préfixe sera considéré comme étant sur le lien.

Par défaut : on

AdvAutonomous on|off

Cette option spécifie si le préfixe annoncé doit être marqué comme étant autonome. Si cette option est activée, les hôtes peuvent utiliser ce préfixe pour générer leurs propres adresses IPv6 sans avoir besoin d'un serveur DHCPv6.

Par défaut : on

AdvRouterAddr on|off

Cette option spécifie si l'adresse du routeur doit être annoncée. Si cette option est activée, l'adresse du routeur sera incluse dans les annonces de routeur (RA).

Par défaut : off

AdvLinkMTU octets

Cette option définit la taille maximale du paquet qui peut être transmise sur le lien. Cette valeur est incluse dans les annonces de routeur (RA).

Par défaut : 1500

AdvReachableTime millisecondes

Cette option définit le temps pendant lequel une adresse est considérée comme atteignable après avoir reçu un paquet de la part de l'hôte. Cette valeur est incluse dans les annonces de routeur (RA).

Par défaut : 30000 millisecondes (30 secondes)

AdvRetransTimer millisecondes

Cette option définit le temps d'attente avant de retransmettre un paquet non acquitté. Cette valeur est incluse dans les annonces de routeur (RA).

Par défaut : 0 millisecondes (désactivé)

AdvCurHopLimit octets

Cette option définit la limite de sauts par défaut pour les paquets envoyés à partir du routeur. Cette valeur est incluse dans les annonces de routeur (RA).

Par défaut : 64

AdvValidLifetime secondes | infinity

La durée de validité du préfixe en secondes. La valeur symbolique infinity représente l'infini (c'est-à-dire une valeur de tous les bits à 1 (0xffffffff)). Voir RFC 4862.

Note : La valeur par défaut suggérée par la RFC 4861 est significativement plus longue : 7 jours.

Par défaut : 14400 secondes (4 heures)

AdvPreferredLifetime secondes | infinity

La durée pendant laquelle le préfixe est considéré comme préféré. La valeur symbolique infinity représente l'infini (c'est-à-dire une valeur de tous les bits à 1 (0xffffffff)). Voir RFC 4862.

Note : La valeur par défaut suggérée par la RFC 4861 est significativement plus longue : 7 jours.

Par défaut : 14400 secondes (4 heures)

DeprecatePrefix on|off

Lors de l'arrêt, cette option amène `radvd` à déprécier le préfixe en l'annonçant dans le RA d'arrêt de `radvd` avec une durée de vie préférée de zéro et une durée de vie valide légèrement supérieure à 2 heures. Cela encouragera les nœuds finaux utilisant ce préfixe à déprécier immédiatement toutes les adresses associées. Notez que cette option ne doit être utilisée que lorsqu'un seul routeur annonce le préfixe sur le lien, sinon les nœuds finaux déprécieront les adresses associées malgré la validité continue du préfixe pour une utilisation préférée.

Voir RFC 4862, section 5.5.3., « Router Advertisement Processing », partie (e).

Par défaut : off

DecrementLifetimes on|off

Cette option amène `radvd` à décrémenter les valeurs des durées de vie préférées et valides pour le préfixe au fil du temps. Les durées de vie sont décrémentées du nombre de secondes écoulées depuis le dernier RA. Si `radvd` reçoit un signal SIGUSR1, il réinitialisera les valeurs des durées de vie préférées et valides aux valeurs initiales utilisées par `radvd` lors de son démarrage. Si `radvd` ne reçoit jamais de signal SIGUSR1, il continuera à décrémenter les durées de vie jusqu'à ce que la durée de vie préférée atteigne zéro. Après un dernier RA avec une durée de vie préférée de zéro, `radvd` cessera d'annoncer le préfixe. Si un signal SIGUSR1 provoque alors la réinitialisation des durées de vie, le préfixe réapparaîtra dans les RA.

Cette option est destinée à être utilisée en conjonction avec un client DHCPv6 qui utilise l'option Identity Association for Prefix Delegation (IA_PD) pour acquérir un préfixe d'un Routeur Délégant pour un Routeur Demandeur. Dans ce scénario, les préfixes à partir desquels le préfixe délégué est annoncé par `radvd` vieilliraient parallèlement et au même rythme que le préfixe délégué, et expireraient à peu près au même moment, si la durée de vie du préfixe délégué n'est pas étendue.

Voir RFC 3633, « IPv6 Prefix Options for Dynamic Host Configuration Protocol (DHCP) version 6 ».

Par défaut : off

Base6Interface nom

Si cette option est spécifiée, ce préfixe sera combiné avec l'adresse IPv6 de l'interface spécifiée par nom. La longueur du préfixe résultant sera de 64.

Base6to4Interface nom

Si cette option est spécifiée, ce préfixe sera combiné avec l'adresse IPv4 de l'interface nom pour produire un préfixe 6to4 valide. Les 16 premiers bits de ce préfixe seront remplacés par 2002 et les 32 bits suivants de ce préfixe seront remplacés par l'adresse IPv4 attribuée à l'interface nom au moment de la configuration. Les 80 bits restants du préfixe (y compris l'ID SLA) seront annoncés comme spécifié dans le fichier de configuration. Voir la section suivante pour un exemple.

Si l'interface nom n'est pas disponible au moment de la configuration, un avertissement sera écrit dans le journal et ce préfixe sera désactivé jusqu'à ce que `radvd` soit reconfiguré.

Cette option permet aux systèmes dotés d'adresses IPv4 dynamiques de mettre à jour leurs préfixes 6to4 annoncés simplement en redémarrant `radvd` ou en envoyant un signal SIGHUP pour que `radvd` se reconfigure.

Notez que les préfixes 6to4 dérivés d'adresses IPv4 attribuées dynamiquement doivent être annoncés avec une durée de vie significativement plus courte (voir les options AdvValidLifetime et AdvPreferredLifetime).

Pour plus d'informations sur 6to4, voir RFC 3056.

Par défaut : 6to4 n'est pas utilisé

AdvValidLifetime secondes

La durée en secondes (par rapport au moment où le paquet est envoyé) pendant laquelle le préfixe est valide pour déterminer l'existence de NAT64. Si la valeur n'est pas un multiple de 8, la validité est arrondie au multiple de 8 supérieur. Le maximum est de 65528 secondes.

EXEMPLES

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
        };
};

Cela indique que le démon d'annonce de routeur doit annoncer (AdvSendAdvert on;) le préfixe 2001:db8:0:1:: d'une longueur de 64 sur l'interface eth0. De plus, le préfixe sera marqué comme autonome (AdvAutonomous on;) et sur le lien (AdvOnLink on;). Toutes les autres options restent sur leurs valeurs par défaut.

Pour prendre en charge la détection de déplacement des Nœuds Mobiles IPv6, l'adresse de l'interface doit être utilisée à la place du préfixe réseau :

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::4/64
        {
                AdvOnLink on;
                AdvAutonomous on;
                AdvRouterAddr on;
        };
};

Pour le support 6to4, incluez l'option Base6to4Interface dans chaque section de préfixe. Lors de l'utilisation d'une adresse IPv4 dynamique, définissez des durées de vie de préfixe courtes pour éviter que les hôtes ne conservent des préfixes inaccessibles après l'attribution d'une nouvelle adresse IPv4. Lors de l'annonce sur une interface dynamique (par exemple, Bluetooth), ignorez l'interface si elle n'est pas encore active.

interface bnep0
{
        IgnoreIfMissing on;
        AdvSendAdvert on;
        # Annoncer au moins toutes les 30 secondes
        MaxRtrAdvInterval 30;
        prefix 0:0:0:5678::/64
        {
                AdvOnLink on;
                AdvAutonomous on;
                Base6to4Interface ppp0;
                # Durées de vie très courtes pour les adresses dynamiques
                AdvValidLifetime 300;
                AdvPreferredLifetime 120;
        };
};

Étant donné que 6to4 est activé, le préfixe sera annoncé comme 2002:WWXX:YYZZ:5678::/64, où WW.XX.YY.ZZ est l'adresse IPv4 de ppp0 au moment de la configuration. (Les adresses IPv6 sont écrites en hexadécimal tandis que les adresses IPv4 sont écrites en décimal, donc l'adresse IPv4 WW.XX.YY.ZZ dans le préfixe 6to4 sera représentée en hexadécimal.)

Dans ce cas spécifique, les scripts de configuration peuvent envoyer un signal HUP à `radvd` lors de la montée de bnep0.

NAME

radvd.conf

configuration file for radvd

DESCRIPTION

The radvd daemon listens to router advertisements (RA) on IPv6 enabled network interfaces. The configuration file describes the network interfaces on which the daemon should operate and what parameters to use for the router advertisements.

The configuration file consists of a sequence of interface definitions. An interface definition starts with the keyword interface, followed by the interface name and a block enclosed in curly braces.

The interface definition can contain the following options:

AdvSendAdvert
A boolean value. If set to on, radvd will send router advertisements on this interface. If set to off, it will not. The default is off.
AdvManaged
A boolean value. If set to on, clients will use stateful autoconfiguration (DHCPv6) to obtain their IPv6 address. The default is off.
AdvOther
A boolean value. If set to on, clients will use stateful autoconfiguration (DHCPv6) to obtain other configuration information (e.g. DNS servers).
AdvHomeAgent
A boolean value. If set to on, clients will use this router as a home agent for mobile IPv6.
AdvLinkMTU
A integer value. It specifies the Link MTU to be advertised in RA.
AdvCurHopLimit
A integer value. It specifies the current hop limit to be advertised.
AdvDefaultLifetime
A integer value. It specifies the default lifetime for router advertisements. This value is used for the router lifetime field in the RA.
AdvReachableTime
AdvRetransTimer
Integer values (in milliseconds) that are advertised in the RA. They are used by clients to calculate the reachable time and retransmission timer.
AdvSourceLLAddress
A boolean value. If set to on, the source link-layer address will be included in the RA.
max_RTR_solicitations
A integer value. It specifies the maximum number of router solicitations that a host sends before giving up.
max_RA_solicitations
A integer value. It specifies the maximum number of router advertisements that a host sends before giving up.
AdvInterval
A integer value. It specifies the interval between successive router advertisements. If this value is 0, then the router will only send periodic router advertisements if it has received a router solicitation. Otherwise, it will send periodic router advertisements with the specified interval.
AdvDefaultPreference
A string value. It specifies the default router preference. Valid values are "high", "medium", and "low".
AdvRouteInfo
A boolean value. If set to on, radvd will advertise route information. The default is off.
AdvLinkMTU
A boolean value. If set to on, radvd will include the link MTU in the RA. The default is off.
AdvManagedFlag
A boolean value. If set to on, the Managed Address Configuration flag will be set in the RA. The default is off.
AdvOtherFlag
A boolean value. If set to on, the Other Configuration flag will be set in the RA. The default is off.
AdvAutonomousFlag
A boolean value. If set to on, the Autonomous Address Configuration flag will be set in the RA. The default is off.
AdvRouterAddrFlag
A boolean value. If set to on, the Router Address flag will be set in the RA. The default is off.
AdvOnLinkFlag
A boolean value. If set to on, the On-Link flag will be set in the RA. The default is off.
AdvAutonomous
A boolean value. If set to on, the Autonomous flag will be set in the RA for this prefix. The default is off.
AdvRouterAddr
A boolean value. If set to on, the Router Address flag will be set in the RA for this prefix. The default is off.
AdvValidLifetime
A integer value. It specifies the valid lifetime for this prefix. The default is 2592000 seconds (30 days).
AdvPreferredLifetime
A integer value. It specifies the preferred lifetime for this prefix. The default is 604800 seconds (7 days).
AdvRouterAddr
A boolean value. If set to on, the Router Address flag will be set in the RA. The default is off.
clients
A list of client IPv6 addresses. If specified, radvd will only send router advertisements to these clients. If not specified, radvd will send router advertisements to all clients. This option is useful for testing purposes.
clients_max_timeout
A integer value. It specifies the maximum timeout for client solicitations. If this value is reached, radvd will stop sending router advertisements to this client.
unspec_solicitation
A boolean value. If set to on, radvd will send router advertisements in response to unspecified solicitations. The default is off.
ipv6only
A boolean value. If set to on, radvd will only consider IPv6 addresses for this interface. The default is off.
disable_RA6
A boolean value. If set to on, radvd will not send any RA messages on this interface. The default is off.

interface eth0
{
        AdvSendAdvert on;
        prefix 2001:db8:0:1::/64

                AdvOnLink on;
                AdvAutonomous on;

};
