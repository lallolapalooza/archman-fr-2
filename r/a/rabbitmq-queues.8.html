NOM

rabbitmq-queues — Outils de gestion des files d'attente RabbitMQ

SYNTAXE

rabbitmq-queues [-q] [-s] [-l] [-n nœud] [-t délai] commande [options_commande]

DESCRIPTION

rabbitmq-queues est un outil en ligne de commande qui fournit des commandes utilisées pour gérer les files d'attente, par exemple, pour augmenter, réduire ou rééquilibrer les répliques des types de files d'attente répliquées. Consultez le guide des files d'attente quorum de RabbitMQ et le guide général des files d'attente RabbitMQ pour en savoir plus sur les types de files d'attente dans RabbitMQ.

OPTIONS

-n nœud
Le nœud par défaut est "rabbit@nom_hote_cible", où nom_hote_cible est l'hôte local. Sur un hôte nommé "myserver.example.com", le nom du nœud sera généralement "rabbit@myserver" (sauf si RABBITMQ_NODENAME a été remplacé). La sortie de "hostname -s" est généralement le suffixe correct à utiliser après le signe "@". Voir rabbitmq-server(8) pour plus de détails sur la configuration d'un nœud RabbitMQ.
-q, --quiet
Le mode de sortie silencieuse est sélectionné. Les messages informationnels sont réduits en mode silencieux.
-s, --silent
Le mode de sortie muette est sélectionné. Les messages informationnels sont réduits et les en-têtes de tableau sont supprimés en mode muet.
-t délai, --timeout délai
Délai d'opération en secondes. Toutes les commandes ne prennent pas en charge les délais. Par défaut, c'est infini.
-l, --longnames
Doit être spécifié lorsque le cluster est configuré pour utiliser des noms de nœuds longs (FQDN). Pour en savoir plus, consultez le guide de clustering RabbitMQ
--erlang-cookie cookie
Secret partagé à utiliser pour s'authentifier auprès du nœud cible. Préférez l'utilisation d'un fichier local ou de la variable d'environnement RABBITMQ_ERLANG_COOKIE plutôt que de spécifier cette option sur la ligne de commande. Pour en savoir plus, consultez le guide des outils CLI RabbitMQ

COMMANDES

help

Affiche l'aide générale et les commandes prises en charge par rabbitmq-queues.

Cluster

grow nœud sélecteur --vhost-pattern modèle --queue-pattern modèle --errors-only

Ajoute une nouvelle réplique sur le nœud donné pour toutes les files d'attente quorum correspondantes ou la moitié d'entre elles.

Les valeurs sélecteur prises en charge sont :

all
Sélectionne toutes les files d'attente quorum
even
Sélectionne les files d'attente quorum avec un nombre pair de répliques

Exemple :

rabbitmq-queues grow "rabbit@nouveauhote" "all" --vhost-pattern "vhost-un" --queue-pattern ".*"
rebalance type --vhost-pattern modèle --queue-pattern modèle

Rééquilibrage des répliques leaders des files d'attente sur les nœuds du cluster.

Les valeurs type prises en charge sont :

all
Tous types de files d'attente
quorum
Uniquement les files d'attente quorum
classic
Uniquement les files d'attente classiques
stream
Uniquement les flux (streams)

Exemple :

rabbitmq-queues rebalance "all" --vhost-pattern "vhost-un" --queue-pattern ".*"
shrink nœud

Réduit les clusters de files d'attente quorum en supprimant les membres (répliques) sur le nœud donné.

Exemple :

rabbitmq-queues shrink "rabbit@nœud-a-supprimer"

Réplication

add_member file nœud --vhost espace-virtuel

Ajoute un membre de file d'attente quorum (réplique) sur le nœud donné.

Exemple :

rabbitmq-queues add_member --vhost "vhost-un" "file-une" "rabbit@nouveau-nœud"
delete_member file nœud --vhost espace-virtuel

Supprime un membre de file d'attente quorum (réplique) sur le nœud donné.

Exemple :

rabbitmq-queues delete_member --vhost "vhost-un" "file-une" "rabbit@nœud-a-supprimer"

Files d'attente

quorum_status file --vhost espace-virtuel

Affiche le statut quorum d'une file d'attente quorum.

Exemple :

rabbitmq-queues quorum_status --vhost "vhost-un" "file-une"
peek file position --vhost espace-virtuel --timeout

Affiche les détails d'un message à la position donnée dans la file d'attente. Cette commande n'est actuellement prise en charge que par les files d'attente quorum.

Exemple :

rabbitmq-queues peek --vhost "vhost-un" "file-une" "1"
check_if_cluster_has_classic_queue_mirroring_policy

Vérification de santé qui se termine avec un code non nul s'il existe des politiques dans le cluster qui activent

NAME

rabbitmq-queues - RabbitMQ queue management operations

SYNOPSIS

rabbitmq-queues [complex commands]

rabbitmq-queues [simple commands]

DESCRIPTION

The rabbitmq-queues command can be used to perform queue-related operations.

OPTIONS

The command supports various options, including:

-q, --quiet
Suppresses all output except for errors.
-s, --silent
Suppresses all output, including errors.
-f, --force
Forces the operation to proceed, even if warnings are issued.
-v, --verbose
Increases the verbosity of the output.
-h, --help
Displays help information and exits.

COMMANDS

check_all_queues_mirroring_health

Checks the mirroring health of all queues in the cluster. Exits with a non-zero status code if any queue has mirroring issues.

Example:

rabbitmq-queues check_all_queues_mirroring_health
check_classic_queue_mirroring_status

Checks the status of classic queue mirroring. Classic queue mirroring has been deprecated since 2021 and was completely removed in the RabbitMQ 4.0 development cycle.

Example:

rabbitmq-queues check_classic_queue_mirroring_status
check_if_cluster_has_classic_queue_mirroring_policy

Checks if the cluster has any classic queue mirroring policies enabled. Classic queue mirroring has been deprecated since 2021 and was completely removed in the RabbitMQ 4.0 development cycle.

Example:

rabbitmq-queues check_if_cluster_has_classic_queue_mirroring_policy
check_if_node_is_quorum_critical

Health check that exits with a non-zero code if there are queues with minimum online quorum (queues that would lose their quorum if the target node is shut down).

Example:

rabbitmq-queues check_if_node_is_quorum_critical
