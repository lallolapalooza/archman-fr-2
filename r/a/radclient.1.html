RADCLIENT(1) Démon FreeRADIUS RADCLIENT(1)

NOM

radclient - envoyer des paquets à un serveur RADIUS, afficher la réponse

SYNTAXE

radclient [-4] [-6] [-b] [-c nombre] [-d répertoire_raddb] [-D répertoire_dictionnaires] [-f fichier] [-F] [-h] [-i id] [-n nb_requêtes_par_seconde] [-p nb_requêtes_en_parallèle] [-q] [-r nb_réessais] [-s] [-S fichier_secret_partagé] [-t délai] [-v] [-x] serveur {acct|auth|status|coa|disconnect|auto} secret

DESCRIPTION

radclient est un programme client radius. Il peut envoyer des paquets radius arbitraires à un serveur radius, puis affiche la réponse. Il peut être utilisé pour tester les modifications que vous avez apportées à la configuration du serveur radius, ou pour vérifier si un serveur radius est en marche.

radclient lit les paires attribut/valeur radius depuis son entrée standard, ou depuis un fichier spécifié sur la ligne de commande. Il encode ensuite ces paires attribut/valeur en utilisant le dictionnaire, et les envoie au serveur distant.

Les attributs User-Password et CHAP-Password sont automatiquement chiffrés avant que le paquet ne soit envoyé au serveur.

OPTIONS

-4
Utiliser IPv4 (par défaut)
-6
Utiliser IPv6
-b
Appliquer les vérifications Blast RADIUS. Toutes les réponses à un paquet Access-Request doivent contenir un Message-Authenticator comme premier attribut.

Pour la compatibilité avec les anciens serveurs, ce drapeau n'est pas activé par défaut. Cependant, radclient vérifie toujours la signature Blast RADIUS et rejette les paquets qui correspondent à l'attaque.

-c nombre
Envoyer chaque paquet nombre fois.
-d répertoire_raddb
Le répertoire qui contient le fichier de dictionnaire utilisateur. Par défaut /etc/raddb.
-D répertoire_dictionnaires
Le répertoire qui contient le fichier de dictionnaire principal. Par défaut /usr/share/freeradius.
-f fichier[:fichier]
Fichier à partir duquel lire les paires attribut/valeur. Si non spécifié, elles sont lues depuis stdin. Cette option peut être spécifiée plusieurs fois, dans ce cas les paquets sont envoyés dans l'ordre par fichier, et dans chaque fichier, du premier paquet au dernier. Une ligne vide sépare les paquets logiques dans un fichier. Si une paire de fichiers séparés par un deux-points est spécifiée, le second fichier sera utilisé pour filtrer les réponses aux requêtes du premier. Le nombre de requêtes et de filtres doit être le même. Un résumé des résultats de filtrage sera affiché si -s est passé.
-F
Afficher le nom du fichier, le numéro du paquet et le code de réponse.
-h
Afficher les informations d'aide sur l'utilisation.
-i id
Utiliser id comme Id de requête RADIUS.
-n nb_requêtes_par_seconde
Essayer d'envoyer nb_requêtes_par_seconde, espacées uniformément. Cette option permet de ralentir la cadence à laquelle radclient envoie les requêtes. Lorsque -n n'est pas utilisé, le comportement par défaut est d'envoyer les paquets aussi vite que possible, sans délais entre les paquets.

En raison des limitations de radclient, cette option n'envoie pas précisément le nombre de paquets par seconde demandé.

-p nb_requêtes_en_parallèle
Envoyer nb_requêtes_en_parallèle, sans attendre de réponse pour chacune. Par défaut, radclient envoie la première requête qu'il a lue, attend la réponse, et une fois la réponse reçue, envoie la seconde requête de sa liste. Cette option permet d'envoyer de nombreuses requêtes simultanément. Une fois que nb_requêtes_en_parallèle ont été envoyées, radclient attend l'arrivée de toutes les réponses (ou l'expiration des requêtes) avant d'envoyer d'autres paquets.

Cette option permet de découvrir la charge maximale acceptée par un serveur RADIUS.

-P proto
Utiliser le protocole de transport proto ("tcp" ou "udp"). Uniquement disponible si FreeRADIUS est compilé avec le support du transport TCP.
-q
Passer en mode silencieux et n'afficher rien.
-r nb_réessais
Essayer d'envoyer chaque paquet nb_réessais fois, avant d'abandonner. La valeur par défaut est 10.
-s
Afficher des résumés des paquets envoyés et reçus.
-S fichier_secret_partagé
Plutôt que de lire le secret partagé depuis la ligne de commande (où il peut être vu par d'autres sur le système local), le lire à la place depuis fichier_secret_partagé.
-t délai
Attendre délai secondes avant de décider que le NAS n'a pas répondu à une requête, et de réenvoyer le paquet. Le délai par défaut est de 3.
-v
Afficher les informations de version.
-x
Afficher les informations de débogage.
serveur[:port]
Le nom d'hôte ou l'adresse IP du serveur distant. Optionnellement, un port UDP peut être spécifié. Si aucun port UDP n'est spécifié, il est recherché dans /etc/services. Le nom de service recherché est radacct pour les paquets de comptabilité, et radius pour toutes les autres requêtes. Si un service n'est pas trouvé dans /etc/services, 1813 et 1812 sont utilisés respectivement. Pour les paquets coa et disconnect, le port 3799 est utilisé.

Si un nom d'hôte est spécifié, alors radclient effectuera une recherche DNS, et utilisera l'enregistrement A pour trouver l'adresse IP du serveur RADIUS. S'il n'y a pas d'enregistrement A, alors radclient recherchera un enregistrement AAAA. S'il n'y a pas d'enregistrement AAAA, une erreur sera produite.

Les adresses IPv6 peuvent être spécifiées en les entourant de crochets. Par exemple, [2002:c000:0201:0:0:0:0:0], ou avec un port, [2002:c000:0201:0:0:0:0:0]:18120.

Les attributs RADIUS lus par radclient peuvent contenir l'attribut spécial Packet-Dst-IP-Address. Si cet attribut existe, alors cette adresse IP est celle où le paquet est envoyé, et le serveur spécifié sur la ligne de commande est ignoré.

Si la liste des attributs RADIUS contient toujours l'attribut Packet-Dst-IP-Address, alors le paramètre serveur peut être donné comme -.

Les attributs RADIUS lus par radclient peuvent contenir l'attribut spécial Packet-Dst-Port. Si cet attribut existe, alors ce port UDP est celui où le paquet est envoyé, et le :port spécifié sur la ligne de commande est ignoré.

acct | auth | status | coa | disconnect | auto
Utiliser auth pour envoyer un paquet d'authentification (Access-Request), acct pour envoyer un paquet de comptabilité (Accounting-Request), status pour envoyer un paquet de statut (Status-Server), ou coa pour envoyer un CoA-Request, ou disconnect pour envoyer une demande de déconnexion. Au lieu de ces valeurs, vous pouvez également utiliser un code décimal ici. Par exemple, le code 12 correspond également à Status-Server.

Les attributs RADIUS lus par radclient peuvent contenir l'attribut spécial Packet-Type. Si cet attribut existe, alors ce type de paquet est envoyé, et le type spécifié sur la ligne de commande est ignoré.

Si la liste des attributs RADIUS contient toujours l'attribut Packet-Type, alors le paramètre type peut être donné comme auto.

secret
Le secret partagé pour ce client. Il doit également être défini côté serveur radius, pour l'adresse IP depuis laquelle vous envoyez les paquets radius.

EXEMPLE

Une session d'échantillon interrogeant le serveur distant pour Status-Server (tous les serveurs ne prennent pas en charge cela, mais FreeRADIUS a un support configurable pour cela).

$ echo "Message-Authenticator = 0x00" | radclient 192.0.2.42 status s3cr3t
Envoi d'une requête au serveur 192.0.2.42, port 1812.
radrecv: Paquet reçu de l'hôte 192.0.2.42 code=2, id=140, longueur=54
    Reply-Message = "FreeRADIUS en ligne depuis 21 jours, 02:05"
