RAGEL(1) Compilateur de machines à états Ragel RAGEL(1)

NOM

ragel - compile les langages réguliers en machines à états exécutables

SYNOPSIS

ragel [options] fichier

DESCRIPTION

Ragel compile des machines à états finis exécutables à partir de langages réguliers. Ragel peut générer du code C, C++, Objective-C, D, Go ou Java. Les machines à états Ragel peuvent non seulement reconnaître des séquences d'octets comme le font les machines d'expressions régulières, mais peuvent également exécuter du code à des points arbitraires de la reconnaissance d'un langage régulier. Le code utilisateur est intégré à l'aide d'opérateurs en ligne qui ne perturbent pas la syntaxe du langage régulier.

Le langage central se compose des opérateurs d'expressions régulières standard, tels que l'union, la concaténation et l'étoile de Kleene, accompagnés d'opérateurs d'intégration d'actions. Ragel fournit également des opérateurs qui vous permettent de contrôler tout non-déterminisme que vous créez, de construire des analyseurs en utilisant le paradigme de la correspondance la plus longue et de construire des machines à états en utilisant le modèle de diagramme d'état. Il est également possible d'influencer l'exécution d'une machine à états depuis une action embarquée en sautant ou en appelant d'autres parties de la machine et en retraitant l'entrée.

Ragel offre une interface très flexible au langage hôte qui tente de placer des restrictions minimales sur la façon dont le code généré est utilisé et intégré dans l'application. Le code généré n'a pas de dépendances.

OPTIONS

-h, -H, -?, --help
Affiche l'aide et quitte.
-v
Affiche les informations de version et quitte.
-o fichier
Écrit la sortie dans le fichier. Si -o n'est pas donné, un nom de fichier par défaut est choisi en remplaçant l'extension du fichier d'entrée. Pour les fichiers source se terminant par .rh, le suffixe .h est utilisé. Pour tous les autres fichiers source, un suffixe basé sur le langage de sortie est utilisé (.c, .cpp, .m, etc.). Si -o n'est pas donné pour la sortie Graphviz, le fichier dot généré est écrit sur la sortie standard.
-s
Affiche quelques statistiques sur l'erreur standard.
--error-format=gnu
Affiche les messages d'erreur en utilisant le format "fichier:ligne:colonne:" (par défaut)
--error-format=msvc
Affiche les messages d'erreur en utilisant le format "fichier(ligne,colonne):"
-d
Ne supprime pas les actions dupliquées des listes d'actions.
-I dir
Ajoute dir à la liste des répertoires à rechercher pour les fichiers inclus et importés.
-n
Ne réalise pas la minimisation des états.
-m
Réalise la minimisation une seule fois, à la fin de la compilation de la machine à états.
-l
Minimise après presque chaque opération. Les listes d'opérations similaires comme les unions sont minimisées une fois à la fin. C'est l'option de minimisation par défaut.
-e
Minimise après chaque opération.
-x
Compile les machines à états et émet une représentation XML des données hôtes et des machines.
-V
Génère un fichier dot pour Graphviz.
-p
Affiche les caractères imprimables sur les étiquettes.
-S <spec>
Spécification FSM à sortir.
-M <machine>
Définition/instanciation de machine à sortir.
-C
Le langage hôte est C, C++, Obj-C ou Obj-C++. C'est l'option de langage hôte par défaut.
-D
Le langage hôte est D.
-J
Le langage hôte est Java.
-Z
Le langage hôte est Go.
-R
Le langage hôte est Ruby.
-L
Inhibe l'écriture des directives #line.
-T0
(C/D/Java/Ruby/C#/Go) Génère une FSM pilotée par table. C'est le style de code par défaut. La FSM pilotée par table représente la machine à états sous forme de données statiques. Il existe des tables d'états, de transitions, d'indices et d'actions. L'état actuel est stocké dans une variable. L'exécution est une boucle qui, étant donné l'état actuel et le caractère actuel à traiter, recherche la transition à prendre à l'aide d'une recherche binaire, exécute les actions et passe à l'état cible. En général, la FSM pilotée par table produit un binaire plus petit et nécessite une compilation plus simple du langage hôte, mais se traduit par un code d'exécution plus lent. La FSM pilotée par table convient à toute FSM.
-T1
(C/D/Ruby/C#/Go) Génère une FSM pilotée par table plus rapide en développant les listes d'actions dans le code d'exécution des actions.
-F0
(C/D/Ruby/C#/Go) Génère une FSM pilotée par table plate. Les transitions sont représentées sous forme de tableau indexé par le caractère alphabétique actuel. Cela élimine le besoin d'une recherche binaire pour localiser les transitions et produit un code plus rapide, mais ce n'est adapté qu'aux petits alphabets.
-F1
(C/D/Ruby/C#/Go) Génère une FSM pilotée par table plate plus rapide en développant les listes d'actions dans le code d'exécution des actions.
-G0
(C/D/C#/Go) Génère une FSM pilotée par goto. La FSM pilotée par goto représente la machine à états sous forme d'une série d'instructions goto. Pendant que vous êtes dans la machine, l'état actuel est stocké par le pointeur d'instruction du processeur. L'exécution est une fonction plate où le contrôle est passé d'un état à l'autre à l'aide de gotos. En général, la FSM goto produit un code plus rapide mais résulte en un binaire plus grand et une compilation plus coûteuse du langage hôte.
-G1
(C/D/C#/Go) Génère une FSM pilotée par goto plus rapide en développant les listes d'actions dans le code d'exécution des actions.
-G2
(C/D/Go) Génère une FSM pilotée par goto vraiment rapide en intégrant les listes d'actions dans le code de contrôle de la machine à états.
-P<N>
(C/D) FSM pilotée par goto très rapide avec split N-way.

ENTRÉE RAGEL

NOTE : Ceci est une description très brève de l'entrée Ragel. Ragel est décrit plus en détail dans le guide de l'utilisateur disponible sur la page d'accueil (voir ci-dessous).

Ragel passe normalement les fichiers d'entrée directement à la sortie. Lorsqu'il rencontre une spécification de FSM contenant des instanciations de machine, il s'arrête pour générer la machine à états. S'il y a des instructions d'écriture (telles que "write exec"), ragel émet le code correspondant. Il peut y avoir n'importe quel nombre de spécifications de FSM dans un fichier d'entrée. Une spécification de FSM multi-lignes commence par '%%{' et se termine par '}%%'. Une spécification de FSM sur une seule ligne commence par %% et se termine au premier retour à la ligne.

MACHINES DE BASE

Les machines de base sont les opérandes de base des expressions de langage régulier.

'hello'
Concat littérale. Produit une concaténation des caractères de la chaîne. Prend en charge les séquences d'échappement avec '\'. Le résultat aura un état de départ et une transition vers un nouvel état pour chaque caractère de la chaîne. Le dernier état de la séquence sera rendu final. Pour rendre la chaîne insensible à la casse, ajoutez un 'i' à la chaîne, comme dans 'cmd'i.
"hello"
Identique à la version avec apostrophe.
[hello]
Ou littéral. Produit une union de caractères. Prend en charge les plages de caractères avec '-', nie le sens de l'union avec un '^' initial et les séquences d'échappement avec '\'. Le résultat aura deux états avec une transition entre eux pour chaque caractère ou plage.

NOTE : '', "", et [] produisent des FSM nuls. Les machines nulles ont un état qui est à la fois un état de départ et un état final et correspondent à la chaîne de longueur zéro. Une machine nulle peut être créée avec la machine intégrée null.

entier
Crée une machine à deux états avec une seule transition sur le nombre entier donné.
hex
Crée une machine à deux états avec une seule transition sur le nombre hexadécimal donné.
/simple_regex/
Une expression régulière simple. Prend en charge la notation '.', '*' et '[]', les plages de caractères avec '-', la négation du sens d'une expression OU avec un '^' initial et les séquences d'échappement avec '\'. Prend également en charge un drapeau final : i. Utilisez-le pour produire une expression régulière insensible à la casse, comme dans /GET/i.
lit .. lit
Spécifie une plage. Les bornes supérieure et inférieure autorisées sont des littéraux de concaténation de longueur un et des machines numériques. Par exemple, 0x10..0x20, 0..63 et 'a'..'z' sont des plages valides.
nom_variable
Fait référence à la définition de machine attribuée au nom de variable donné.
machine_intégrée
Il existe plusieurs machines intégrées disponibles. Ce sont toutes des machines à deux états pour faire correspondre des classes de caractères courantes. Ce sont :
any
N'importe quel caractère de l'alphabet.
ascii
Caractères ASCII 0..127.
extend
Caractères étendus ASCII. Il s'agit de la plage -128..127 pour les alphabets signés et de la plage 0..255 pour les alphabets non signés.
alpha
Caractères alphabétiques /[A-Za-z]/.
digit
Chiffres /[0-9]/.
alnum
Alpha numériques /[0-9A-Za-z]/.
lower
Caractères minuscules /[a-z]/.
upper
Caractères majuscules /[A-Z]/.
xdigit
Chiffres hexadécimaux /[0-9A-Fa-f]/.
cntrl
Caractères de contrôle 0..31.
graph
Caractères graphiques /[!-~]/.
print
Caractères imprimables /[ -~]/.
punct
Ponctuation. Caractères graphiques qui ne sont pas alphanumériques /[!-/:-@\[-`{-~]/.
space
Espace blanc /[\t\v\f\n\r ]/.
null
Chaîne de longueur zéro. Équivalent à '', "" et [].
empty
Ensemble vide. Ne correspond à rien.

REFERENCE BRIEVE DES OPERATEURS

Les opérateurs sont regroupés par priorité, le groupe 1 étant la plus basse et le groupe 6 la plus haute.

GROUPE 1 :

expr , expr
Joignez les machines ensemble sans dessiner de transitions, en définissant un état de départ ou des états finaux. L'état de départ doit être explicitement spécifié avec le libellé "start". Les états finaux peuvent être spécifiés avec des transitions epsilon vers l'état "final" implicitement créé.

GROUPE 2 :

expr | expr
Produit une machine qui correspond à n'importe quelle chaîne de la machine un ou de la machine deux.
expr & expr
Produit une machine qui correspond à n'importe quelle chaîne qui se trouve à la fois dans la machine un et dans la machine deux.
expr - expr
Produit une machine qui correspond à n'importe quelle chaîne qui se trouve dans la machine un mais pas dans la machine deux.
expr -- expr
Soustraction forte. Correspond à toute chaîne de la machine un qui n'a aucune chaîne de la machine deux comme sous-chaîne.

GROUPE 3 :

expr . expr
Produit une machine qui correspond à toutes les chaînes de la machine un suivies de toutes les chaînes de la machine deux.
expr :> expr
Concaténation avec garde d'entrée : termine la machine un à l'entrée de la machine deux.
expr :>> expr
Concaténation avec garde de fin : termine la machine un lorsque la machine deux se termine.
expr <: expr
Concaténation avec garde gauche : donne une priorité plus élevée à la machine un.

NOTE : La concaténation est l'opérateur par défaut. Deux machines côte à côte sans opérateur entre elles résultent en une opération de concaténation.

GROUPE 4 :

label: expr
Attache un libellé à une expression. Les libellés peuvent être utilisés par des transitions epsilon et des instructions fgoto et fcall dans les actions. Notez également que la référence à une définition de machine provoque la création implicite d'un libellé du même nom.

GROUPE 5 :

expr -> label
Dessine une transition epsilon vers l'état défini par le libellé. Le libellé doit être un nom dans la portée actuelle. Les transitions epsilon sont résolues lors de l'évaluation des opérateurs virgule et à la racine de l'arbre d'expression de l'affectation/instanciation de machine.

GROUPE 6 : Actions

Une action peut être un nom prédéfini avec une instruction d'action ou peut être spécifiée directement avec '{' et '}' dans l'expression.

expr > action
Intègre l'action dans les transitions de départ.
expr @ action
Intègre l'action dans les transitions qui mènent à un état final.
expr $ action
Intègre l'action dans toutes les transitions. N'inclut pas les transitions sortantes en attente.
expr % action
Intègre l'action dans les transitions sortantes en attente depuis les états finaux.

GROUPE 6 : Actions EOF

Lorsque la routine de fin d'une machine est appelée, les actions EOF de l'état actuel sont exécutées.

expr >/ action
Intègre une action EOF dans l'état de départ.
expr </ action
Intègre une action EOF dans tous les états sauf l'état de départ.
expr $/ action
Intègre une action EOF dans tous les états.
expr %/ action
Intègre une action EOF dans les états finaux.
expr @/ action
Intègre une action EOF dans tous les états qui ne sont pas finaux.
expr <>/ action
Intègre une action EOF dans tous les états qui ne sont ni l'état de départ ni l'état final (états intermédiaires).

GROUPE 6 : Actions d'erreur globales

Les actions d'erreur globales sont stockées dans les états jusqu'à ce que la machine d'état finale soit entièrement construite. Elles sont ensuite transférées aux transitions d'erreur, donnant l'effet d'une action par défaut.

expr >! action
Intègre une action d'erreur globale dans l'état de départ.
expr <! action
Intègre une action d'erreur globale dans tous les états sauf l'état de départ.
expr $! action
Intègre une action d'erreur globale dans tous les états.
expr %! action
Intègre une action d'erreur globale dans les états finaux.
expr @! action
Intègre une action d'erreur globale dans tous les états qui ne sont pas finaux.
expr <>! action
Intègre une action d'erreur globale dans tous les états qui ne sont ni l'état de départ ni l'état final (états intermédiaires).

GROUPE 6: Actions d'erreur locales

Les actions d'erreur locales sont stockées dans des états jusqu'à ce que la machine nommée soit entièrement construite. Elles sont ensuite transférées aux transitions d'erreur, donnant l'effet d'une action par défaut pour une partie de la machine totale. Notez que le nom peut être omis, auquel cas l'action sera transférée aux actions d'erreur lors de la construction de la machine actuelle.

expr >^ action
Intègre une action d'erreur locale dans l'état de départ.
expr <^ action
Intègre une action d'erreur locale dans tous les états sauf l'état de départ.
expr $^ action
Intègre une action d'erreur locale dans tous les états.
expr %^ action
Intègre une action d'erreur locale dans les états finaux.
expr @^ action
Intègre une action d'erreur locale dans tous les états qui ne sont pas finaux.
expr <>^ action
Intègre une action d'erreur locale dans tous les états qui ne sont ni l'état de départ ni l'état final (états intermédiaires).

GROUPE 6 : Actions vers état

Les actions vers état sont stockées dans les états et exécutées chaque fois que la machine entre dans un état. Cela inclut les transitions régulières et les transferts de contrôle tels que fgoto. Notez que la définition de l'état courant depuis l'extérieur de la machine (par exemple, lors de l'initialisation) ne compte pas comme une transition vers un état.

expr >~ action
Intègre une action vers état dans l'état de départ.
expr <~ action
Intègre une action vers état dans tous les états sauf l'état de départ.
expr $~ action
Intègre une action vers état dans tous les états.
expr %~ action
Intègre une action vers état dans les états finaux.
expr @~ action
Intègre une action vers état dans tous les états qui ne sont pas finaux.
expr <>~ action
Intègre une action vers état dans tous les états qui ne sont ni l'état de départ ni l'état final (états intermédiaires).

GROUPE 6 : Actions depuis état

Les actions depuis état sont exécutées chaque fois qu'un état effectue une transition sur un caractère. Cela inclut la transition d'erreur et une transition vers soi-même.

expr >* action
Intègre une action depuis état dans l'état de départ.
expr <* action
Intègre une action depuis état dans tous les états sauf l'état de départ.
expr $* action
Intègre une action depuis état dans tous les états.
expr %* action
Intègre une action depuis état dans les états finaux.
expr @* action
Intègre une action depuis état dans tous les états qui ne sont pas finaux.
expr <>* action
Intègre une action depuis état dans tous les états qui ne sont ni l'état de départ ni l'état final (états intermédiaires).

GROUPE 6 : Assignation de priorité

Les priorités sont assignées aux noms dans les transitions. Seules les priorités sur le même nom sont autorisées à interagir. Dans la première forme de priorités, le nom est par défaut le nom de la définition de machine dans laquelle la priorité est assignée. Les transitions n'ont pas de priorités par défaut.

expr > int
Assigne la priorité entière dans toutes les transitions sortant de l'état de départ.
expr @ int
Assigne la priorité entière dans toutes les transitions qui mènent à un état final.
expr $ int
Assigne la priorité entière dans toutes les transitions existantes.
expr % int
Assigne la priorité entière dans toutes les transitions sortantes en attente.

Une deuxième forme d'assignation de priorité permet au programmeur de spécifier le nom auquel la priorité est assignée, permettant aux interactions de traverser les limites de définition de la machine.

expr > (name,int)
Assigne la priorité entière au nom dans toutes les transitions sortant de l'état de départ.
expr @ (name, int)
Assigne la priorité entière au nom dans toutes les transitions qui mènent à un état final.
expr $ (name, int)
Assigne la priorité entière au nom dans toutes les transitions existantes.
expr % (name, int)
Assigne la priorité entière au nom dans toutes les transitions sortantes en attente.

GROUPE 7 :

expr *
Produit l'étoile de Kleene d'une machine. Correspond à zéro ou plusieurs répétitions de la machine.
expr **
Étoile de Kleene à correspondance la plus longue. Cette version de l'étoile de Kleene privilégie le maintien dans la machine plutôt que le retour au début. Cet opérateur est équivalent à ( ( expr ) $0 %1 )*.
expr ?
Produit une machine qui accepte la machine donnée ou la chaîne nulle. Cet opérateur est équivalent à ( expr | '' ).
expr +
Produit la machine concaténée avec son étoile de Kleene. Correspond à une ou plusieurs répétitions de la machine. Cet opérateur est équivalent à ( expr . expr* ).
expr {n}
Produit une machine qui correspond exactement à n répétitions de expr.
expr {,n}
Produit une machine qui correspond de zéro à n répétitions de expr.
expr {n,}
Produit une machine qui correspond à n répétitions ou plus de expr.
expr {n,m}
Produit une machine qui correspond à n à m répétitions de expr.

GROUPE 8 :

! expr
Produit une machine qui correspond à toute chaîne qui n'est pas correspondante à la machine donnée. Cet opérateur est équivalent à ( *extend - expr ).
^ expr
Négation au niveau du caractère. Correspond à tout caractère unique qui n'est pas correspondant à la machine à caractère unique expr.

GROUPE 9 :

( expr )
Force la précédence sur les opérateurs.

VALEURS DISPONIBLES DANS LES BLOCS DE CODE

fc
Le caractère courant. Équivalent à *p.
fpc
Un pointeur vers le caractère courant. Équivalent à p.
fcurs
Une valeur entière représentant l'état courant.
ftargs
Une valeur entière représentant l'état cible.
fentry(<label>)
Une valeur entière représentant le point d'entrée <label>.

INSTRUCTIONS DISPONIBLES DANS LES BLOCS DE CODE

fhold;
Ne pas avancer sur le caractère courant. Équivalent à --p;.
fexec <expr>;
Définit le caractère courant à autre chose. Équivalent à p = (<expr>)-1;
fgoto <label>;
Sauter vers la machine définie par <label>.
fgoto *<expr>;
Sauter vers le point d'entrée donné par <expr>. L'expression doit évaluer à une valeur entière représentant un état.
fnext <label>;
Définit le prochain état comme étant le point d'entrée défini par <label>. L'instruction fnext ne saute pas immédiatement vers l'état spécifié. Tout code d'action suivant l'instruction est exécuté.
fnext *<expr>;
Définit le prochain état comme étant le point d'entrée donné par <expr>. L'expression doit évaluer à une valeur entière représentant un état.
fcall <label>;
Appelle la machine définie par <label>. Le prochain fret sautera vers la cible de la transition sur laquelle l'action est invoquée.
fcall *<expr>;
Appelle le point d'entrée donné par <expr>. Le prochain fret sautera vers la cible de la transition sur laquelle l'action est invoquée.
fret;
Retourner à l'état cible de la transition sur laquelle le dernier fcall a été effectué.
fbreak;
Sauvegarde l'état courant et sort immédiatement de la machine.
