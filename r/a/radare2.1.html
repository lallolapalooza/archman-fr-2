RADARE2(1) Manuel des commandes générales RADARE2(1)

NOM

radare2 — Éditeur hexadécimal, désassembleur et débogueur en ligne de commande avancé

SYNTAXE

radare2 [-a arch] [-b bits] [-B baddr] [-c cmd] [-e k=v] [-i fichier] [-I prefile] [-k kernel] [-m addr] [-p projet] [-P patch] [-r rarun2] [-R rr2rule] [-s addr] [-012AdDjwntLquvVxX] -|--|=|fichier

DESCRIPTION

radare2 est un éditeur hexadécimal en ligne de commande.

"r2" est le nom d'alias du programme radare2.

Cette page de manuel n'est pas encore mise à jour. N'hésitez pas à contribuer.

Les options sont :

--
Ouvre radare2 sur un fichier vide
-
Équivalent de 'r2 malloc://512'
-0
Imprime \x00 après l'initialisation et après chaque commande exécutée
-1
Redirige stderr vers stdout
-2
Ferme stderr avant de démarrer RCore
-a arch
Force asm.arch (x86, ppc, arm, mips, bf, java, ...)
-A
Exécute la commande 'aaa' avant l'invite ou le patch pour analyser tout le code référencé. Utiliser -AA pour exécuter aaaa.
-b bits
Force asm.bits (16, 32, 64)
-B baddr
Spécifie l'adresse de base à utiliser lors du chargement d'un nouveau binaire. Voir 'e?bin.baddr'.
-c cmd
Exécute la commande donnée avant de présenter l'invite.
-d
Démarre en mode débogueur
-D dbg.backend
Active le mode débogage. Définit cfg.debug=true
-e k=v
Définit la variable d'évaluation de configuration clé=valeur. Par exemple -e scr.color=false. Lorsque -e est passé après -j, il définira la source du script à exécuter au lieu de définir des variables d'évaluation.
-f
Taille de bloc = taille du fichier
-j
Exécute un script QJS si un argument est passé ou entre dans le shell qjs si aucun fichier n'est spécifié. Vous pouvez évaluer des expressions en passant le drapeau -e après -j.
-i fichier
Exécute le fichier script. Après le chargement du fichier.
-I fichier
Exécute le fichier script. Avant le chargement du fichier.
-k kernel
Sélectionne le noyau (asm.os) pour la résolution des appels système.
-l plugfile
Charge le fichier plugin donné.
-L
Liste les plugins IO chargés.
-LL
Liste les plugins core chargés.
-m addr
mappe le fichier à l'adresse donnée.
-M
Désactive le dénommage.
-n
N'effectue aucune analyse (r_bin). Charge simplement le fichier brut.
-nn
Charge uniquement les structures rbin (elf, mach0, ...).
-N
Ne charge pas les paramètres utilisateur/projets depuis ~/.radare2rc, ~/.config/radare2/radare2rc et les scripts dans le répertoire .../radare2rc.d/.
-NN
Identique à -N mais désactive également le chargement automatique des plugins au démarrage.
-q
Mode silencieux (pas d'invite) et quitte après l'exécution des commandes spécifiées avec -i ou -c.
-qq
Quitte avant d'afficher l'invite. Juste après l'évaluation de tous les arguments -e, -c et -i.
-Q
Identique à q, mais quitte sans libérer RCore, cela produit des fuites en sortie, mais économise quelques précieuses millisecondes pour exécuter la suite de tests en mode rapide.
-p prj
Définit le fichier projet.
-P fichier
Applique le fichier rapatch et quitte (voir doc/rapatch.md pour plus de détails).
-r rarun2
Spécifie le profil rarun2 dbg.profile à utiliser lors du lancement d'un programme pour le débogage.
-R directive-rarun2
Spécifie des directives rarun2 personnalisées sans avoir à créer un profil rarun2.
-s addr
Commence la recherche à cette adresse.
-S
Active le mode sandbox (identique à -e cfg.sandbox=true).
-t
Obtient les informations du binaire et analyse le binaire dans un thread d'arrière-plan.
-T
Évite de calculer les hachages de fichiers.
-u
Définit bin.filter=false pour charger les informations rbin sans filtrer les noms.
-v
Affiche les informations de version et quitte (Utiliser -qv pour obtenir juste le numéro de version).
-V
Affiche les versions des bibliothèques de radare2 (affiche le format JSON si -j est utilisé).
-w
Ouvre en mode écriture.
-h
Affiche le message d'aide.
-H
Affiche l'aide sur les fichiers et l'environnement.
-x
Ouvre le fichier mappé sans permissions d'exécution.
-X
Identique à -e bin.usextr=false, n'utilise pas les plugins d'extraction, utile pour dyldcache.

SHELL

Tapez '?' pour obtenir de l'aide.

VISUAL

Pour entrer en mode visuel, utilisez la commande 'V'. Ensuite, appuyez sur '?' pour obtenir de l'aide.

DEBUGGER

Dans r2, les commandes de débogage sont implémentées sous la commande 'd'. Tapez 'd?' pour obtenir de l'aide.

NAME

radare2 – a portable reverse engineering framework

SYNOPSIS

radare2 [-AadLlmv] [--batch] [-c cmd] [-e k=v] [-f file] [-i file] [-k kernel] [-n] [-p port] [-q] [-r file] [-s file] [-t pid] [-u] [-w] [-R file] [-- args...]

DESCRIPTION

Radare2 is a complete framework for reverse engineering. It aims to provide a set of tools to help the user to perform reverse engineering tasks, from malware analysis to vulnerability research and application security.

Radare2 is a command-line driven tool. It supports a wide variety of file formats, code languages, architectures and operating systems.

The main executable radare2 can be invoked with several options. After initialization, it drops into its own shell, where further commands can be issued.

Some of the basic commands include:

  • o or open: open a file.
  • i: show information about the opened file.
  • s: seek to a specific address.
  • p: print information (e.g. hex dump, disassembly, strings).
  • e: set or get configuration variables.
  • w: write data to the file.
  • q: quit radare2.

SHELL

Once radare2 is started, it enters in a shell mode where you can issue commands. The command syntax is generally: cmd [arg0] [arg1] .... Some commands may accept more arguments or have their own specific syntax. The command history and auto-completion are available.

You can run shell commands by prefixing them with the exclamation mark !. For example, !ls.

VISUAL

Radare2 offers a visual mode that can be entered using the V command. This mode provides multiple panels for viewing disassembly, hex dump, registers, etc. The navigation and commands are similar to the command-line mode, but enhanced for interactive use. Use q to quit visual mode.

DEBUGGER

Radare2 includes a debugger that supports various operating systems and architectures. You can attach to a running process using -p or -t, or launch a new process in debug mode. Debugger commands are prefixed with d (e.g. dcr to read registers, dc to continue execution).

ENVIRONMENT

The behavior of radare2 can be influenced by several environment variables:

  • R2_ARGS: run radare2 with defined arguments in environment and ignore cli ones
  • R2_IGNVER: load plugins ignoring the specified version. (be careful)
  • R2_DEBUG: if defined, show error messages and crash signal
  • R2_DEBUG_ASSERT=1: set a breakpoint when hitting an assert
  • R2_MAGICPATH: /Users/pancake/.local/share/radare2/share/radare2/4.5.0-git/magic
  • R2_NOPLUGINS: do not load r2 shared plugins
  • R2_RCFILE: ~/.radare2rc (user preferences, batch script)
  • R2_RDATAHOME: /usr/local FILE: path to the current working file.
