NOM

"razor-revoke" - Agent de révocation Razor

SYNOPSIS

razor-revoke [options]  fichier avec le courrier au format rfc822
$ cat courrier | razor-revoke
$ razor-revoke ./courrier 
$ razor-revoke -d ./courrier

DESCRIPTION

"razor-revoke" est l'agent de révocation Razor, utilisé pour signaler des messages comme N'ÉTANT PAS du spam à un serveur de nomination Razor. Par exemple, il peut être invoqué si une vérification a incorrectement marqué un message comme spam ou après qu'un message ait été incorrectement signalé comme spam. "razor-revoke" doit généralement être appelé depuis un MUA, bien qu'il n'y ait pas de restrictions pour l'invoquer depuis la ligne de commande. "razor-revoke" est un filtre, ce qui signifie que les messages de spam doivent lui être transmis via un tube. Par défaut, "razor-revoke" se met en arrière-plan et se détache du terminal de contrôle au démarrage.

Si "razor-revoke" reçoit plusieurs courriels, il révoquera chacun d'eux par rapport à la base de données. Veuillez utiliser ceci avec prudence, nous ne voulons pas que la base de données contienne des informations inexactes. "razor-revoke" prend en charge les fichiers au format mbox avec 1 ou plusieurs courriels, ainsi que les fichiers contenant un seul courriel RFC 822 (non-mbox). Plus d'un fichier peut être présent sur la ligne de commande, il peut s'agir d'un non-mbox ou d'un mbox dans n'importe quel ordre. Cependant, plus d'un courriel non-mbox ne peut pas être lu depuis stdin.

Tant razor-report(1) que "razor-revoke" nécessitent une authentification utilisateur pour fonctionner, voir razor-admin(1). Cela permet au serveur de nomination Razor de suivre le nombre de messages qu'un utilisateur signale et révoque. Plus un utilisateur signale et/ou révoque correctement de messages, plus il gagne en confiance. De même, lorsque des messages sont signalés ou révoqués de manière incorrecte, la confiance de cet utilisateur diminue. Les utilisateurs ayant une grande confiance auront le plus d'influence sur la base de données Razor.

Notez que même après une révocation réussie, un courriel peut toujours être considéré comme spam dans le Catalogue Razor. Par exemple, cela peut se produire si des utilisateurs plus fiables considèrent le courriel comme spam plutôt que comme non spam.

UTILISATION

"razor-revoke" prend les arguments suivants :

"-h"
Affiche un message d'utilisation et quitte.
"-v"
Affiche le numéro de version et quitte.
"-d | --verbose"
Affiche des informations de débogage.
"-debuglevel=n | -dl=n"
Définit le niveau de débogage sur 'n'. La valeur par défaut est 3 sans l'option "-d", et 9 avec.
"-whitelist=fichier"
Spécifie le fichier à utiliser pour la liste blanche. Annule l'option 'whitelist' dans "razor-agent.conf".
"-s"
Simule une vérification. Fait tout sauf communiquer avec le serveur.
"-conf=nom_fichier"
Spécifie un fichier de configuration alternatif. S'il n'est pas spécifié, il est calculé, voir la page de manuel de razor-agents(1) pour les détails. Voir la page de manuel de razor-agent.conf(5) pour les différentes options de configuration. Le défaut est "<razorhome>/razor-agent.conf".
"-home=dossier"
Spécifie le répertoire razorhome. C'est là que résident le fichier de configuration, les journaux, les identités et les fichiers serveur. S'il n'est pas spécifié, il est calculé, voir la page de manuel de razor-agents(1) pour les détails.
"-logfile=nom_fichier"
Spécifie le fichier dans lequel enregistrer au lieu de ce qui se trouve dans le fichier de configuration. Le défaut est "<razorhome>/razor-agent.log".
"-ident=nom_fichier"
Spécifie un fichier d'identité à utiliser pour l'authentification auprès des serveurs Razor. S'il n'est pas spécifié, "<razorhome>/identity-<utilisateur>" est utilisé.
"-rs=razor.server.com"
Utilise ce serveur de nomination Razor au lieu de lire "servers.nomination.lst".
"-M | --mbox"
Accepte un nom de boîte aux lettres sur la ligne de commande et révoque chaque courriel de la boîte aux lettres par rapport à la base de données. S'il est au premier plan, "-f", "razor-revoke" affichera le numéro de chaque courriel accepté par le serveur du Catalogue. 
C<razor-revoke -f -M ~/Mail/incorrectly-marked-spam>
"-i=nom_fichier"
Utilise l'identité du fichier spécifié au lieu de lire <razorhome>/identity.
"-a"
Authentification uniquement. Si authentifié, quitte avec 0 ; sinon, quitte avec 1.
"-f"
Reste au premier plan, ne se détache pas et ne s'exécute pas en arrière-plan.

INTÉGRATION AVEC MUTT

Ajoutez la ligne suivante à "mutt.conf"

macro index R "|/usr/bin/razor-revoke"

Ensuite, appuyez sur R sur le message de spam dans "mutt" pour le signaler avec "razor-revoke". Comme "razor-revoke" crée un fork, le contrôle reviendra immédiatement.
