raw(7) Manuel d'informations diverses raw(7)

NOM

raw - Sockets bruts IPv4 sous Linux

SYNTAXE

#include <sys/socket.h>
#include <netinet/in.h>
raw_socket = socket(AF_INET, SOCK_RAW, int protocol);

DESCRIPTION

Les sockets bruts permettent d'implémenter de nouveaux protocoles IPv4 dans l'espace utilisateur. Un socket brut reçoit ou envoie le datagramme brut sans inclure les en-têtes de niveau liaison.

La couche IPv4 génère un en-tête IP lors de l'envoi d'un paquet, sauf si l'option de socket IP_HDRINCL est activée sur le socket. Lorsqu'elle est activée, le paquet doit contenir un en-tête IP. Pour la réception, l'en-tête IP est toujours inclus dans le paquet.

Afin de créer un socket brut, un processus doit posséder la capacité CAP_NET_RAW dans l'espace de noms utilisateur qui gouverne son espace de noms réseau.

Tous les paquets ou erreurs correspondant au numéro de protocol spécifié pour le socket brut sont transmis à ce socket. Pour une liste des protocoles autorisés, consultez la liste des numéros de protocole attribués par l'IANA sur http://www.iana.org/assignments/protocol-numbers/ et getprotobyname(3).

Un protocole de IPPROTO_RAW implique que IP_HDRINCL est activé et permet d'envoyer tout protocole IP spécifié dans l'en-tête passé. La réception de tous les protocoles IP via IPPROTO_RAW n'est pas possible en utilisant des sockets bruts.

Champs d'en-tête IP modifiés lors de l'envoi par IP_HDRINCL
Somme de contrôle IP Toujours remplie
Adresse source Remplie si zéro
Identifiant du paquet Rempli si zéro
Longueur totale Toujours remplie

Si IP_HDRINCL est spécifié et que l'en-tête IP a une adresse de destination non nulle, alors l'adresse de destination du socket est utilisée pour acheminer le paquet. Lorsque MSG_DONTROUTE est spécifié, l'adresse de destination doit faire référence à une interface locale, sinon une recherche dans la table de routage est effectuée mais les routes passant par une passerelle sont ignorées.

Si IP_HDRINCL n'est pas défini, alors les options d'en-tête IP peuvent être définies sur des sockets bruts avec setsockopt(2) ; voir ip(7) pour plus d'informations.

Depuis Linux 2.2, tous les champs et options d'en-tête IP peuvent être définis à l'aide des options de socket IP. Cela signifie que les sockets bruts ne sont généralement nécessaires que pour les nouveaux protocoles ou les protocoles sans interface utilisateur (comme ICMP).

Lorsqu'un paquet est reçu, il est transmis à tous les sockets bruts qui ont été liés à son protocole avant d'être transmis à d'autres gestionnaires de protocole (par exemple, les modules de protocole du noyau).

Format d'adresse

Pour envoyer et recevoir des datagrammes (sendto(2), recvfrom(2), et similaires), les sockets bruts utilisent la structure d'adresse standard sockaddr_in définie dans ip(7). Le champ sin_port pourrait être utilisé pour spécifier le numéro de protocole IP, mais il est ignoré pour l'envoi sous Linux 2.2 et versions ultérieures, et doit toujours être défini à 0 (voir BUGS). Pour les paquets entrants, sin_port est défini à zéro.

Options de socket

Les options de socket brut peuvent être définies avec setsockopt(2) et lues avec getsockopt(2) en passant l'indicateur de famille IPPROTO_RAW.

ICMP_FILTER
Active un filtre spécial pour les sockets bruts liés au protocole IPPROTO_ICMP. La valeur a un bit défini pour chaque type de message ICMP qui doit être filtré. Par défaut, aucun message ICMP n'est filtré.

De plus, toutes les options de socket IPPROTO_IP de ip(7) valides pour les sockets datagramme sont prises en charge.

Gestion des erreurs

Les erreurs provenant du réseau ne sont transmises à l'utilisateur que lorsque le socket est connecté ou que le drapeau IP_RECVERR est activé. Pour les sockets connectés, seuls EMSGSIZE et EPROTO sont transmis pour des raisons de compatibilité. Avec IP_RECVERR, toutes les erreurs réseau sont enregistrées dans la file d'attente des erreurs.

ERREURS

EACCES
L'utilisateur a tenté d'envoyer à une adresse de diffusion sans avoir le drapeau de diffusion défini sur le socket.
EFAULT
Une adresse mémoire invalide a été fournie.
EINVAL
Argument invalide.
EMSGSIZE
Paquet trop volumineux. Soit la découverte de MTU par chemin est activée (l'option de socket IP_MTU_DISCOVER), soit la taille du paquet dépasse la taille maximale autorisée pour un paquet IPv4 de 64 Ko.
EOPNOTSUPP
Un drapeau invalide a été passé à un appel de socket (comme MSG_OOB).
EPERM
L'utilisateur n'a pas la permission d'ouvrir des sockets bruts. Seuls les processus avec un identifiant utilisateur effectif de 0 ou l'attribut CAP_NET_RAW peuvent le faire.
EPROTO
Une erreur ICMP est arrivée signalant un problème de paramètre.

VERSIONS

IP_RECVERR et ICMP_FILTER sont nouveaux dans Linux 2.2. Ce sont des extensions Linux et ne doivent pas être utilisées dans des programmes portables.

Linux 2.0 a activé une compatibilité bug à bug avec BSD dans le code des sockets bruts lorsque l'option de socket SO_BSDCOMPAT était définie ; depuis Linux 2.2, cette option n'a plus cet effet.

NOTES

Par défaut, les sockets bruts effectuent la découverte de la MTU (Maximum Transmission Unit) par chemin. Cela signifie que le noyau gardera une trace de la MTU vers une adresse IP cible spécifique et renverra EMSGSIZE lorsqu'un paquet brut dépasse cette limite lors d'une écriture. Dans ce cas, l'application doit réduire la taille du paquet. La découverte de MTU par chemin peut également être désactivée en utilisant l'option de socket IP_MTU_DISCOVER ou le fichier /proc/sys/net/ipv4/ip_no_pmtu_disc ; voir ip(7) pour plus de détails. Lorsqu'elle est désactivée, les sockets bruts fragmenteront les paquets sortants qui dépassent la MTU de l'interface. Cependant, il n'est pas recommandé de la désactiver pour des raisons de performance et de fiabilité.

Un socket brut peut être lié à une adresse locale spécifique en utilisant l'appel bind(2). S'il n'est pas lié, tous les paquets avec le protocole IP spécifié sont reçus. De plus, un socket brut peut être lié à un périphérique réseau spécifique en utilisant SO_BINDTODEVICE ; voir socket(7).

Un socket IPPROTO_RAW est uniquement pour l'envoi. Si vous souhaitez réellement recevoir tous les paquets IP, utilisez un socket packet(7) avec le protocole ETH_P_IP. Notez que les sockets de paquet ne réassemblent pas les fragments IP, contrairement aux sockets bruts.

Si vous souhaitez recevoir tous les paquets ICMP pour un socket datagramme, il est souvent préférable d'utiliser IP_RECVERR sur ce socket particulier ; voir ip(7).

Les sockets bruts peuvent exploiter tous les protocoles IP sous Linux, y compris des protocoles comme ICMP ou TCP qui ont un module de protocole dans le noyau. Dans ce cas, les paquets sont transmis à la fois au module du noyau et au(x) socket(s) brut(s). Cela ne doit pas être pris en compte dans les programmes portables ; de nombreuses autres implémentations de sockets BSD ont des limitations à cet égard.

Raw sockets are generally rather unportable and should be avoided in programs intended to be portable.

Sending on raw sockets should take the IP protocol from sin_port; this ability was lost in Linux 2.2. The workaround is to use IP_HDRINCL.

BUGS

Transparent proxy extensions are not described.

When the IP_HDRINCL option is set, datagrams will not be fragmented and are limited to the interface MTU.

Setting the IP protocol for sending in sin_port got lost in Linux 2.2. The protocol that the socket was bound to or that was specified in the initial socket(2) call is always used.
