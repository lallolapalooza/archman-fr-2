NOM

windres - manipuler les ressources Windows

SYNTAXE

windres [options] [fichier-entrée] [fichier-sortie]

DESCRIPTION

windres lit les ressources d'un fichier d'entrée et les copie dans un fichier de sortie. Chaque fichier peut être dans l'un des trois formats suivants :

"rc"
Un format texte lu par le Resource Compiler.
"res"
Un format binaire généré par le Resource Compiler.
"coff"
Un objet ou exécutable COFF.

La description exacte de ces différents formats est disponible dans la documentation de Microsoft.

Lorsque windres convertit du format "rc" au format "res", il agit comme le Resource Compiler de Windows. Lorsque windres convertit du format "res" au format "coff", il agit comme le programme "CVTRES" de Windows.

Lorsque windres génère un fichier "rc", la sortie est similaire mais pas identique au format attendu pour l'entrée. Lorsqu'un fichier "rc" d'entrée fait référence à un nom de fichier externe, un fichier "rc" de sortie inclura plutôt le contenu du fichier.

Si le format d'entrée ou de sortie n'est pas spécifié, windres devinera en fonction du nom du fichier, ou, pour le fichier d'entrée, du contenu du fichier. Un fichier avec une extension .rc sera traité comme un fichier "rc", un fichier avec une extension .res sera traité comme un fichier "res", et un fichier avec une extension .o ou .exe sera traité comme un fichier "coff".

Si aucun fichier de sortie n'est spécifié, windres affichera les ressources au format "rc" sur la sortie standard.

L'utilisation normale consiste à écrire un fichier "rc", à utiliser windres pour le convertir en un fichier objet COFF, puis à lier le fichier COFF à votre application. Cela rendra les ressources décrites dans le fichier "rc" disponibles pour Windows.

OPTIONS

-i nomfichier
--input nomfichier
Le nom du fichier d'entrée. Si cette option n'est pas utilisée, alors windres utilisera le premier argument non-option comme nom de fichier d'entrée. S'il n'y a pas d'arguments non-options, alors windres lira depuis l'entrée standard. windres ne peut pas lire un fichier COFF depuis l'entrée standard.
-o nomfichier
--output nomfichier
Le nom du fichier de sortie. Si cette option n'est pas utilisée, alors windres utilisera le premier argument non-option, après ceux utilisés pour le nom du fichier d'entrée, comme nom de fichier de sortie. S'il n'y a pas d'argument non-option, alors windres écrira sur la sortie standard. windres ne peut pas écrire un fichier COFF sur la sortie standard. Notez que pour la compatibilité avec rc, l'option -fo est également acceptée, mais son utilisation n'est pas recommandée.
-J format
--input-format format
Le format d'entrée à lire. format peut être res, rc, ou coff. Si aucun format d'entrée n'est spécifié, windres devinera, comme décrit ci-dessus.
-O format
--output-format format
Le format de sortie à générer. format peut être res, rc, ou coff. Si aucun format de sortie n'est spécifié, windres devinera, comme décrit ci-dessus.
-F cible
--target cible
Spécifie le format BFD à utiliser pour un fichier COFF en entrée ou en sortie. Ceci est un nom de cible BFD ; vous pouvez utiliser l'option --help pour voir une liste des cibles supportées. Normalement, windres utilisera le format par défaut, qui est le premier listé par l'option --help.
--preprocessor programme
Lorsque windres lit un fichier "rc", il le passe d'abord par le préprocesseur C. Cette option peut être utilisée pour spécifier le préprocesseur à utiliser. Le préprocesseur par défaut est "gcc".
--preprocessor-arg option
Lorsque windres lit un fichier "rc", il le passe d'abord par le préprocesseur C. Cette option peut être utilisée pour spécifier du texte supplémentaire à passer au préprocesseur sur sa ligne de commande. Cette option peut être utilisée plusieurs fois pour ajouter plusieurs options à la ligne de commande du préprocesseur. Si l'option --preprocessor n'a pas été spécifiée, un ensemble d'arguments par défaut pour le préprocesseur sera utilisé, avec toutes les options --preprocessor-arg placées après eux sur la ligne de commande. Ces arguments par défaut sont "-E", "-xc-header" et "-DRC_INVOKED".
-I répertoire
--include-dir répertoire
Spécifie un répertoire d'inclusion à utiliser lors de la lecture d'un fichier "rc". windres passera ceci au préprocesseur comme une option -I. windres cherchera également dans ce répertoire lors de la recherche de fichiers nommés dans le fichier "rc". Si l'argument passé à cette commande correspond à l'un des formats supportés (comme décrit dans l'option -J), il émettra un avertissement de dépréciation, et se comportera exactement comme l'option -J. Les nouveaux programmes ne devraient pas utiliser ce comportement. Si un répertoire correspond à un format, préfixez-le simplement avec ./ pour désactiver la compatibilité arrière.
-D cible
--define sym[=val]
Spécifie une option -D à passer au préprocesseur lors de la lecture d'un fichier "rc".
-U cible
--undefine sym
Spécifie une option -U à passer au préprocesseur lors de la lecture d'un fichier "rc".
-r
Ignoré pour la compatibilité avec rc.
-v
Active le mode verbeux. Cela vous indique quel est le préprocesseur si vous n'en avez pas spécifié un.
-c val
--codepage val
Spécifie la page de codes par défaut à utiliser lors de la lecture d'un fichier "rc". val doit être un code hexadécimal précédé de 0x ou un code décimal de page de codes. La plage valide va de zéro à 0xffff, mais la validité de la page de codes dépend de l'hôte et de la configuration.
-l val
--language val
Spécifie la langue par défaut à utiliser lors de la lecture d'un fichier "rc". val doit être un code de langue hexadécimal. Les huit bits de poids faible représentent la langue, et les huit bits de poids fort le sous-langage.
--use-temp-file
Utilise un fichier temporaire au lieu d'utiliser popen pour lire la sortie du préprocesseur. Utilisez cette option si l'implémentation de popen est boguée sur l'hôte (par exemple, certaines versions non anglaises de Windows 95 et Windows 98 ar

NAME

windres — compilateur de ressources du format Windows

SYNOPSIS

windres [-i input_file] [-o output_file] [-J coff_file] [-T coff_file] [-P template_file] [-W coff_file] [-F [pe|pe-64]] [-v] [-V] [--help] [--version] [--no-use-temp-file] [--use-temp-file]

DESCRIPTION

windres est un utilitaire qui permet de compiler des fichiers de ressources du format Windows en un format binaire qui peut être intégré dans un exécutable. Il peut lire des fichiers de ressources dans différents formats, y compris le format texte standard utilisé par les compilateurs du format C et le format binaire du format RC. Il peut ensuite générer des fichiers binaires dans différents formats, notamment le format PE (Portable Executable) utilisé par Windows.

OPTIONS

-i input_file
Spécifie le fichier d'entrée contenant les ressources. Si ce n'est pas spécifié, windres lira à partir de l'entrée standard.
-o output_file
Spécifie le fichier de sortie. Si ce n'est pas spécifié, windres écrira dans la sortie standard.
-J coff_file
Spécifie un fichier COFF d'où importer des ressources. La ressource sera ajoutée à la table des ressources.
-T coff_file
Spécifie un fichier COFF d'où importer des ressources. La ressource sera ajoutée à la table des ressources.
-P template_file
Spécifie un fichier modèle à utiliser pour le format de sortie.
-W coff_file
Spécifie un fichier COFF d'où importer des ressources. La ressource sera ajoutée à la table des ressources.
-F [ pe | pe-64 ]
Spécifie le format de sortie. pe pour le format PE 32 bits, et pe-64 pour le format PE 64 bits.
-v
Affiche les informations de version de windres.
--no-use-temp-file
Utilise popen, pas un fichier temporaire, pour lire la sortie du préprocesseur. C'est le comportement par défaut.
--use-temp-file
Utilise un fichier temporaire pour lire la sortie du préprocesseur. Ceci peut être utile si la sortie de popen est redirigée vers la console, ce qui est connu pour causer des problèmes avec certains interpréteurs de commandes.
-h
--help
Affiche un résumé de l'utilisation.
-V
--version
Affiche le numéro de version de windres.
--yydebug
Si windres est compilé avec "YYDEBUG" défini comme 1, cela activera le débogage de l'analyseur.
@file
Lit les options de la ligne de commande depuis le fichier file. Les options lues sont insérées à la place de l'option @file originale. Si file n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière soit de guillemets simples soit de guillemets doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure d'un antislash. Le file peut lui-même contenir d'autres options @file ; de telles options seront traitées récursivement.
