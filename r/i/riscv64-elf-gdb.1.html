NOM

gdb - Le débogueur GNU

SYNTAXE

gdb [OPTIONS] [programme|programme PID|programme core]

DESCRIPTION

Le but d'un débogueur comme GDB est de vous permettre de voir ce qui se passe "à l'intérieur" d'un autre programme pendant son exécution -- ou ce que faisait un autre programme au moment où il a planté.

GDB peut effectuer quatre types d'actions principales (plus d'autres actions en soutien) pour vous aider à détecter les bugs en action :

  • Démarrer votre programme, en spécifiant tout ce qui pourrait affecter son comportement.
  • Faire s'arrêter votre programme sous certaines conditions spécifiées.
  • Examiner ce qui s'est passé, lorsque votre programme s'est arrêté.
  • Modifier des choses dans votre programme, afin que vous puissiez expérimenter en corrigeant les effets d'un bug et passer à l'apprentissage d'un autre.

Vous pouvez utiliser GDB pour déboguer des programmes écrits en C, C++, Fortran et Modula-2.

GDB est appelé avec la commande shell "gdb". Une fois démarré, il lit les commandes du terminal jusqu'à ce que vous lui demandiez de quitter avec la commande GDB "quit" ou "exit". Vous pouvez obtenir de l'aide en ligne depuis GDB lui-même en utilisant la commande "help".

Vous pouvez exécuter "gdb" sans arguments ni options ; mais la façon la plus courante de démarrer GDB est avec un ou deux arguments, spécifiant un fichier exécutable comme argument :

gdb programme

Vous pouvez aussi démarrer avec un fichier exécutable et un fichier core spécifiés :

gdb programme core

Vous pouvez,Alternatively, spécifier un identifiant de processus comme second argument ou utiliser l'option "-p", si vous souhaitez déboguer un processus en cours d'exécution :

gdb programme 1234
gdb -p 1234

attachera GDB au processus 1234. Avec l'option -p vous pouvez omettre le nom de fichier du programme.

Voici quelques-unes des commandes GDB les plus fréquemment utilisées :

break [fichier:][fonction|ligne]
Définir un point d'arrêt à fonction ou ligne (dans fichier).
run [liste_args]
Démarrer votre programme (avec liste_args, si spécifié).
bt
Backtrace (trace arrière) : afficher la pile du programme.
print expr
Afficher la valeur d'une expression.
c
Continuer l'exécution de votre programme (après un arrêt, par ex. à un point d'arrêt).
next
Exécuter la ligne de programme suivante (après un arrêt) ; passez par-dessus les appels de fonction dans la ligne.
edit [fichier:]fonction
Regarder la ligne du programme à l'endroit où il est actuellement arrêté.
list [fichier:]fonction
Afficher le texte du programme à proximité de l'endroit où il est actuellement arrêté.
step
Exécuter la ligne de programme suivante (après un arrêt) ; entrez dans les appels de fonction dans la ligne.
help [nom]
Afficher des informations sur la commande GDB nom, ou des informations générales sur l'utilisation de GDB.
quit
exit
Quitter GDB.

Pour plus de détails sur GDB, consultez Using GDB: A Guide to the GNU Source-Level Debugger, par Richard M. Stallman et Roland H. Pesch. Le même texte est disponible en ligne sous l'entrée "gdb" du programme "info".

OPTIONS

Tous les arguments autres que les options spécifient un fichier exécutable et un fichier core (ou un identifiant de processus) ; c'est-à-dire que le premier argument rencontré sans indicateur d'option est équivalent à une option --se, et le second, le cas échéant, est équivalent à une option -c s'il s'agit du nom d'un fichier. Beaucoup d'options ont des formes longues et abrégées ; les deux sont affichées ici. Les formes longues sont également reconnues si vous les tronquez, tant qu'assez de l'option est présente pour être non ambiguë.

Les formes abrégées sont affichées ici avec - et les formes longues avec -- pour refléter la manière dont elles sont affichées dans --help. Cependant, GDB reconnaît toutes les conventions suivantes pour la plupart des options :

"--option=valeur"
"--option valeur"
"-option=valeur"
"-option valeur"
"--o=valeur"
"--o valeur"
"-o=valeur"
"-o valeur"

Toutes les options et tous les arguments de ligne de commande que vous donnez sont traités séquentiellement. L'ordre est important lorsque l'option -x est utilisée.

--help
-h
Lister toutes les options, avec de brèves explications.
--symbols=fichier
-s fichier
Lire la table des symboles depuis fichier.
--write
Activer l'écriture dans les fichiers exécutables et core.
--exec=fichier
-e fichier
Utiliser fichier comme fichier exécutable à lancer le cas échéant, et pour examiner les données pures en conjonction avec un dump core.
--se=fichier
Lire la table des symboles depuis fichier et l'utiliser comme fichier exécutable.
--core=fichier
-c fichier
Utiliser fichier comme un dump core à examiner.
--command=fichier
-x fichier
Exécuter les commandes GDB depuis fichier.
--eval-command=commande
-ex commande
Exécuter la commande GDB donnée.
--init-eval-command=commande
-iex
Exécuter la commande GDB avant de charger l'inférieur.
--directory=répertoire
-d répertoire
Ajouter répertoire au chemin de recherche des fichiers source.
--nh
Ne pas exécuter les commandes de ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, ou ~/.gdbearlyinit.
--nx
-n
Ne pas exécuter les commandes depuis un quelconque fichier d'initialisation .gdbinit ou .gdbearlyinit.
--quiet
--silent
-q
"Silencieux". Ne pas afficher les messages d'introduction et de copyright. Ces messages sont également supprimés en mode batch.
--batch
Exécuter en mode batch. Quitter avec le statut 0 après avoir traité tous les fichiers de commandes spécifiés avec -x (et .gdbinit, si non inhibé). Quitter avec un statut non nul si une erreur se produit lors de l'exécution des commandes GDB dans les fichiers de commandes.

gdb(1) - Arch manual pages

NAME

gdb — The GNU Project Debugger

SYNOPSIS

gdb [-help] [-nx] [-batch [-quiet]] [--batch-silent] [--args prog [arglist]] [--pid=pid] [--tui] [--readnow] [--readnever] [--return-child-result] [--configuration] [--version] [--cd=directory] [--data-directory=directory] [-D] [--fullname] [-f] [-b baudrate] [-l timeout] [--tty=device] [file[core]] [-se symfile] [-ex cmd] [-x cmdfile] [-i=inferior_type]

DESCRIPTION

GDB, the GNU Source-Level Debugger, allows you to see what is going on inside another program while it executes or what another program was doing at the time it crashed. You can think of GDB as three things:

A source code debugger: you can look at your program's source code, and use a debugger to locate and fix errors in its source code.

An interpreter for the commands of the GDB command language: this is a powerful language that you can use to control GDB, automate debugging tasks, and more.

A process control program: GDB can start new processes, or attach to an existing process and make it behave under the control of GDB.

GDB is also a sophisticated testing and exploration tool.

The debugger is useful for debugging C, C++, Objective-C, GNU Modula-2, Fortran, Ada and other languages.

You can use GDB to debug programs that have already been compiled and run, or you can use GDB to help you debug programs that you are still writing.

For example, you can use GDB to:

  • Start your program, specifying anything that might affect its behavior.
  • Make your program stop on specified conditions.
  • Examine what happened when your program stopped.
  • Change things in your program, so you can experiment with correcting the effects of one bug and go on to learn about another.

OPTIONS

-help
Print a description of the command-line options and exit.
-nx
--batch
Run GDB in batch mode. GDB will exit after processing all the commands from the script file specified by the -x option. If the -x option is not specified, GDB will exit after processing commands given on the command line with -ex. This mode is useful for preliminary debugging of a new program, or for running a specific diagnostic test suite. In batch mode, neither the initial nor the final GDB quiet explanations are printed. This is the default behaviour.

When running in batch mode, GDB exits early if it encounters an error. This may be undesirable if you are attempting to perform multiple debugging actions on another computer; in order to make this more useful, the message

Program exited normally.

(which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode.

--batch-silent
Run in batch mode, just like --batch, but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than --silent and would be useless for an interactive session.

This is particularly useful when using targets that give Loading section messages, for example.

Note that targets that give their output via GDB, as opposed to writing directly to "stdout", will also be made silent.

--args prog [arglist]
Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: 
gdb ./a.out -q

It would start GDB with -q, not printing the introductory message. On the other hand, using:

gdb --args ./a.out -q

starts GDB with the introductory message, and passes the option to the inferior.

--pid=pid
Attach GDB to an already running program, with the PID pid.
--tui
Open the terminal user interface.
--readnow
Read all symbols from the given symfile on the first access.
--readnever
Do not read symbol files.
--return-child-result
GDB's exit code will be the same as the child's exit code.
--configuration
Print details about GDB configuration and then exit.
--version
Print version information and then exit.
--cd=directory
Run GDB using directory as its working directory, instead of the current directory.
--data-directory=directory
-D
Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files.
--fullname
-f
Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame.
-b baudrate
Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging.
-l timeout
Set timeout, in seconds, for remote debugging.
--tty=device
Run using device for your program's standard input and output.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
