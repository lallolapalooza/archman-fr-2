ADDR2LINE(1) Outils de développement GNU ADDR2LINE(1)

NOM

addr2line - convertir des adresses ou un symbole+décalage en noms de fichiers et numéros de ligne

SYNTAXE

addr2line [-a|--addresses]
[-b nom_bfd|--target=nom_bfd]
[-C|--demangle[=style]]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-e nom_fichier|--exe=nom_fichier]
[-f|--functions] [-s|--basename]
[-i|--inlines]
[-p|--pretty-print]
[-j|--section=nom]
[-H|--help] [-V|--version]
[adresse adresse ...]

DESCRIPTION

addr2line traduit des adresses ou un symbole+décalage en noms de fichiers et numéros de ligne. Étant donné une adresse ou un symbole+décalage dans un exécutable ou un décalage dans une section d'un objet déplaçable, il utilise les informations de débogage pour déterminer quel nom de fichier et quel numéro de ligne lui sont associés.

L'exécutable ou l'objet déplaçable à utiliser est spécifié avec l'option -e. Par défaut, il s'agit du fichier a.out. La section de l'objet déplaçable à utiliser est spécifiée avec l'option -j.

addr2line a deux modes de fonctionnement.

Dans le premier, des adresses hexadécimales ou un symbole+décalage sont spécifiés sur la ligne de commande, et addr2line affiche le nom du fichier et le numéro de ligne pour chaque adresse.

Dans le second, addr2line lit des adresses hexadécimales ou un symbole+décalage depuis l'entrée standard et imprime le nom du fichier et le numéro de ligne pour chaque adresse sur la sortie standard. Dans ce mode, addr2line peut être utilisé dans un pipe pour convertir des adresses choisies dynamiquement.

Le format de la sortie est NOM_FICHIER:NUMERO_LIGNE. Par défaut, chaque adresse d'entrée génère une ligne de sortie.

Deux options peuvent générer des lignes supplémentaires avant chaque ligne NOM_FICHIER:NUMERO_LIGNE (dans cet ordre).

Si l'option -a est utilisée, alors une ligne avec l'adresse d'entrée est affichée.

Si l'option -f est utilisée, alors une ligne avec le NOM_FONCTION est affichée. C'est le nom de la fonction contenant l'adresse.

Une option peut générer des lignes supplémentaires après la ligne NOM_FICHIER:NUMERO_LIGNE.

Si l'option -i est utilisée et que le code à l'adresse donnée est présent là à cause d'une inlining par le compilateur, alors des lignes supplémentaires sont affichées ensuite. Une ou deux lignes supplémentaires (si l'option -f est utilisée) sont affichées pour chaque fonction inlinée.

Alternativement, si l'option -p est utilisée, alors chaque adresse d'entrée génère une seule longue ligne de sortie contenant l'adresse, le nom de la fonction, le nom du fichier et le numéro de ligne. Si l'option -i a également été utilisée, alors les fonctions inlinées seront affichées de la même manière, mais sur des lignes séparées, et préfixées par le texte (inlined by).

Si le nom du fichier ou le nom de la fonction ne peuvent pas être déterminés, addr2line imprimera deux points d'interrogation à leur place. Si le numéro de ligne ne peut pas être déterminé, addr2line imprimera 0.

Lorsque un symbole+décalage est utilisé, +décalage est optionnel, sauf lorsque le symbole est ambigu avec un nombre hexadécimal. Les symboles résolus peuvent être manglés ou non manglés, sauf que les symboles non manglés avec + ne sont pas autorisés.

OPTIONS

Les formes longues et courtes des options, montrées ici comme alternatives, sont équivalentes.

-a
--addresses
Affiche l'adresse avant les informations sur le nom de la fonction, le fichier et le numéro de ligne. L'adresse est imprimée avec un préfixe 0x pour l'identifier facilement.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objets est nom_bfd.
-C
--demangle[=style]
Décoder (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de "mangling". L'argument optionnel de style de "demangling" peut être utilisé pour choisir un style de "demangling" approprié pour votre compilateur.
-e nom_fichier
--exe=nom_fichier
Spécifie le nom de l'exécutable pour lequel les adresses doivent être traduites. Le fichier par défaut est a.out.
-f
--functions
Affiche les noms de fonctions ainsi que les informations sur le fichier et le numéro de ligne.
-s
--basenames
Affiche uniquement la base de chaque nom de fichier.
-i
--inlines
Si l'adresse appartient à une fonction qui a été inlinée, les informations sources pour tous les scopes englobants jusqu'à la première fonction non inlinée seront également imprimées. Par exemple, si "main" inlines "callee1" qui inlines "callee2", et que l'adresse provient de "callee2", les informations sources pour "callee1" et "main" seront également imprimées.
-j
--section
Lit les décalages par rapport à la section spécifiée au lieu des adresses absolues.
-p
--pretty-print
Rend la sortie plus conviviale : chaque emplacement est imprimé sur une ligne. Si l'option -i est spécifiée, les lignes pour tous les scopes englobants sont préfixées par (inlined by).
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du "demangling" des chaînes. Étant donné que les formats de "mangling" de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une erreur de segmentation. La limite tente d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour "demangler" des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

Notez que cette option n'est effective que si l'option -C ou --demangle a été activée.

@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure avec une barre oblique inverse. Le fichier peut lui-même contenir des options supplémentaires @fichier ; toutes ces options seront traitées de manière récursive.

cessed récursivement.
