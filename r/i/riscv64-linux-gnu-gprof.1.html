NOM

gprof - affiche les données de profil du graphe d'appels

DESCRIPTION

"gprof" produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré au profil de chaque appelant. Les données de profil proviennent du fichier de profil du graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc", et "f77". L'option -pg lie également les versions des routines de bibliothèque qui sont compilées pour le profilage. "Gprof" lit le fichier objet donné (le défaut est "a.out") et établit la relation entre sa table de symboles et le profil du graphe d'appels de gmon.out. Si plusieurs fichiers de profil sont spécifiés, la sortie de "gprof" affiche la somme des informations de profil des fichiers de profil donnés.

"Gprof" calcule le temps passé dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels dans un cycle sont faits pour partager le temps du cycle.

Plusieurs formes de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment la plupart des cycles, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a également une estimation du temps passé dans les sous-routines de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonction qui consomment beaucoup de temps.

La liste annotée de la source est une copie du code source du programme, étiquetée avec le nombre de fois où chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient quel format de sortie parmi plusieurs "gprof" doit produire.

Beaucoup de ces options prennent un symspec optionnel pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec des symspecs différents, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options surcharge le comportement par défaut (-p -q), qui affiche un profil plat et une analyse du graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--annotated-source[=symspec]"
L'option -A demande à "gprof" d'afficher la source annotée. Si symspec est spécifié, n'affichez la sortie que pour les symboles correspondants.
"-b"
"--brief"
Si l'option -b est donnée, "gprof" n'affiche pas les textes explicatifs verbeux qui essaient d'expliquer la signification de tous les champs dans les tableaux. Ceci est utile si vous avez l'intention d'imprimer la sortie, ou si vous êtes fatigué de voir les textes explicatifs.
"-B"
L'option -B demande à "gprof" d'afficher l'analyse du graphe d'appels.
"-C[symspec]"
"--exec-counts[=symspec]"
L'option -C demande à "gprof" d'afficher un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, n'affichez le décompte que pour les symboles correspondants.

Si le fichier de données de profil contient des enregistrements de comptage de blocs de base, la spécification de l'option -l, avec -C, demandera le comptage et l'affichage des comptes d'exécution de blocs de base.

"-i"
"--file-info"
L'option -i demande à "gprof" d'afficher des informations récapitulatives sur le(s) fichier(s) de données de profil et de quitter. Le nombre d'enregistrements d'histogramme, de graphe d'appels et de comptage de blocs de base est affiché.
"-I dossiers"
"--directory-path=dossiers"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers source. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Principalement utilisé pour la sortie de source annotée.
"-J[symspec]"
"--no-annotated-source[=symspec]"
L'option -J demande à "gprof" de ne pas afficher la source annotée. Si symspec est spécifié, "gprof" affiche la source annotée, mais exclut les symboles correspondants.
"-L"
"--print-path"
Normalement, les noms de fichiers source sont affichés avec le composant de chemin supprimé. L'option -L demande à "gprof" d'afficher le chemin d'accès complet des noms de fichiers source, qui est déterminé à partir des informations de débogage symbolique dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--flat-profile[=symspec]"
L'option -p demande à "gprof" d'afficher un profil plat. Si symspec est spécifié, n'affichez le profil plat que pour les symboles correspondants.
"-P[symspec]"
"--no-flat-profile[=symspec]"
L'option -P demande à "gprof" de supprimer l'affichage du profil plat. Si symspec est spécifié, "gprof" affiche un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graph[=symspec]"
L'option -q demande à "gprof" d'afficher l'analyse du graphe d'appels. Si symspec est spécifié, n'affichez le graphe d'appels que pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--no-graph[=symspec]"
L'option -Q demande à "gprof" de supprimer l'affichage du graphe d'appels. Si symspec est spécifié, "gprof" affiche un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--table-length=num"
L'option -t demande à afficher les num lignes sources les plus actives dans chaque fichier source lorsque l'annotation de source est activée. La valeur par défaut est 10.
"-y"
"--separate-files"
Cette option n'affecte que la sortie de source annotée. Normalement, "gprof" affiche les fichiers source annotés sur la sortie standard. Si cette option est spécifiée, la source annotée pour un fichier nommé chemin/nom_fichier est générée dans le fichier nom_fichier-ann. Si le système de fichiers sous-jacent tronquait nom_fichier-ann de manière à écraser le nom_fichier d'origine, "gprof" génère alors la source annotée dans le fichier nom_fichier.ann (si le nom de fichier d'origine a une extension, cette extension est remplacée par .ann).
"-Z[symspec]"
"--no-exec-counts[=symspec]"
L'option -Z demande à

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

"gprof" ne pas imprimer un décompte des fonctions et du nombre de fois où chacune a été appelée. Si symspec est spécifié, imprimer le décompte, mais exclure les symboles correspondants.
"-r"
"--function-ordering"
L'option --function-ordering demande à "gprof" d'imprimer un ordre de fonctions suggéré pour le programme, basé sur les données de profilage. Cette option suggère un ordre qui pourrait améliorer le comportement de pagination, de tlb et de cache pour le programme sur les systèmes qui prennent en charge l'ordre arbitraire des fonctions dans un exécutable.

Les détails exacts sur la manière de forcer le lieur à placer les fonctions dans un ordre particulier dépendent du système et sortent du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering demande à "gprof" d'imprimer une suggestion d'ordre de ligne de lien .o pour le programme, basée sur les données de profilage. Cette option suggère un ordre qui pourrait améliorer le comportement de pagination, de tlb et de cache pour le programme sur les systèmes qui ne prennent pas en charge l'ordre arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin d'accès à un fichier qui fournit les correspondances entre les noms de fonctions et les fichiers objets. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec "nm" de GNU, tapez une commande comme "nm --extern-only --defined-only -v --print-file-name nom_programme".

"-T"
"--traditional"
L'option -T demande à "gprof" d'imprimer sa sortie dans le style « traditionnel » BSD.
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, utilisé uniquement lors de l'impression de l'index des fonctions en bas du graphe d'appels.
"-x"
"--all-lines"
Cette option affecte uniquement la sortie annotée du code source. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire au -a de "tcov".
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démangled lors de l'impression de la sortie. Par défaut, les symboles sont démangled. L'option "--no-demangle" peut être utilisée pour désactiver le démangling. Différents compilateurs ont différents styles de mangling. L'argument optionnel du style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.

Options d'Analyse

"-a"
"--no-static"
L'option -a demande à "gprof" de supprimer l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globaux et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels depuis/vers elles, etc., seront tous attribués à la fonction qui a été chargée directement avant elle dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c demande que le graphe d'appels du programme soit augmenté par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonctions dans le code machine binaire. Comme les enregistrements normaux du graphe d'appels ne sont générés que lorsque les fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels à des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais uniquement si des entrées de table de symboles sont présentes pour elles. Les appels aux routines de bibliothèques dynamiques ne sont généralement pas trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des comptes d'appels de 0.
"-D"
"--ignore-non-functions"
L'option -D demande à "gprof" d'ignorer les symboles qui ne sont pas reconnus comme des fonctions. Cette option donnera des données de profilage plus précises sur les systèmes où elle est prise en charge (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appels tous les arcs allant des symboles correspondant à from à ceux correspondant à to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les succès de l'histogramme sont imputés à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par d'anciennes versions du compilateur "gcc". Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera également combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où un programme passe son temps dans une grande fonction, il augmente également considérablement le temps d'exécution de "gprof" et amplifie les inexactitudes statistiques.

"--inline-file-names"
Cette option demande à "gprof" d'imprimer le fichier source après chaque symbole, à la fois dans le profil plat et dans le graphe d'appels. Le chemin complet du fichier est imprimé si utilisé avec l'option -L.
"-m num"
"--min-count=num"
Cette option affecte uniquement la sortie des comptes d'exécution. Les symboles exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n demande à "gprof", dans son analyse de graphe d'appels, de ne propager les temps que pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n demande à "gprof", dans son analyse de graphe d'appels, de ne pas propager les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S demande à "gprof" de lire un fichier de table de symboles externe, tel que /proc/kallsyms, plutôt que de lire la table de symboles à partir du fichier objet donné (par défaut, "a.out"). Ceci est utile pour profiler les modules du noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z, "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et pour lesquelles aucun temps n'a été passé. Ceci est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options Diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, active tout le débogage.
"-h"
"--help"
L'option -h affiche l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profilage. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic, et prof (pas encore pris en charge).
"-s"
"--sum"
L'option -s demande à "gprof" de résumer les informations contenues dans les fichiers de données de profilage qu'il a lus, et d'écrire un fichier de données de profilage appelé gmon.sum, qui contient toutes les informations des fichiers de données de profilage que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter à nouveau "gprof" sans -s pour analyser les données cumulatives dans le fichier gmon.sum.

"-v"
"--version"
Le drapeau -v demande à "gprof" d'afficher le numéro de version actuel, puis de quitter.

Options Dépréciées

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer les informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme un enfant des fonctions qui l'appellent, mais son numéro d'index sera affiché comme [non imprimé]. Plus d'une option -e peuvent être données ; un seul function_name peut être indiqué avec chaque option -e.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e", mais le temps passé dans la fonction (et les enfants qui n'ont été appelés par personne d'autre) ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appels. Plus d'une option -E peuvent être données ; un seul function_name peut être indiqué avec chaque option -E.

NAME

gprof — display profiling information

SYNOPSIS

gprof [prog [sourcename ...]]

gprof [-abcdZBFiv M m r T Y] [-b N] [-e E] [-f F] [-p P] [-S s] [-u U] [-W w] [-l L] [-n N] [-o O] [-x X] [-@ '@'] [-c C] [-d D] [-h H] [-k K] [-j J] [-g G] [-q Q]

gprof -V

DESCRIPTION

The gprof utility is a 386bsd™-compatible execution profiler. It uses the facilities described in profil(2) and monitor(3) to produce a call graph analysis of the program execution profile.

The gprof utility requires that the profiled program be compiled with the -pg flag.

The output of gprof is based on the program's execution profile, which is written to the file "gmon.out" by the profiled program. This file is binary and contains dynamic call graph and profile information.

The program gprof reads the symbol table and execution profile information from the specified program file (default "a.out"), sorts the information, and prints the analysis to standard output.

In order to get profile information, the profiled program must call exit(2) or return normally from the main routine for the profile information to be saved in the "gmon.out" file.

If prog is not specified, gprof uses "a.out". If one or more gprof will print annotated listing of each source file specified. If no gprof prints a flat profile listing.

OPTIONS

"-b"
Print less verbose output. This option suppresses the printing of the flat profile.
"-c"
Compute the call graph based on the call counts derived from the profiling data. This option is only effective when the program has been compiled with -pg.
"-e function_name"
Exclude "function_name" and its descendants from the call graph analysis. More than one "-e" option may be given.
"-E function_name"
Exclude "function_name" and its descendants from the call graph analysis, but include it in the flat profile. More than one "-E" option may be given.
"-F function_name"
Only use time spent in "function_name" and its descendants to compute the total time and percentages of time for the call graph. More than one "-F" option may be given.
"-f function_name"
Limit the call graph to "function_name" and its descendants. More than one "-f" option may be given.

FILES

"a.out"
The namelist and text space.
"gmon.out"
Dynamic call graph and profile.
"gmon.sum"
Summarized dynamic call graph and profile.

BUGS

The granularity of the sampling is shown, but remains statistical at best. We assume that the time for each execution of a function can be expressed by the total time for the function divided by the number of times the function is called. Thus the time propagated along the call graph arcs to the function's parents is directly proportional to the number of times that arc is traversed.

Parents that are not themselves profiled will have the time of their profiled children propagated to them, but they will appear to be spontaneously invoked in the call graph listing, and will not have their time propagated further. Similarly, signal catchers, even though profiled, will appear to be spontaneous (although for more obscure reasons). Any profiled children of signal catchers should have their times propagated properly, unless the signal catcher was invoked during the execution of the profiling routine, in which case all is lost.

The profiled program must call "exit"(2) or return normally for the profiling information to be saved in the "gmon.out" file.
