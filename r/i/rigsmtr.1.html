RIGSMTR(1) Utilitaires Hamlib RIGSMTR(1)

NOM

rigsmtr - mesure le S-Mètre en fonction de l'azimut avec Hamlib

SYNTAXE

rigsmtr [-hvV] [-m id] [-r périphérique] [-s débit] [-c id] [-C parm=val] [-M id] [-R périphérique] [-S débit] [-N parm=val] [pas_de_temps]

DESCRIPTION

rigsmtr utilise Hamlib pour contrôler une radio afin de mesurer la valeur du S-Mètre en fonction de l'azimut de l'antenne.

Il fait pivoter l'antenne du azimut minimum au azimut maximum. Chaque seconde, ou pas_de_temps si spécifié en secondes, il récupère la force du signal. L'azimut en degrés et le niveau S-Mètre correspondant en dB par rapport à S9 sont ensuite imprimés sur stdout.

Pour fonctionner correctement, rigsmtr nécessite une radio capable de mesurer le S-Mètre et un backend Hamlib capable de le récupérer, connecté à un rotateur supporté par Hamlib.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que de nombreuses bibliothèques backend manquent de prise en charge complète de la radio, les fonctions de base sont généralement bien prises en charge.

Veuillez signaler les bugs et fournir des commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (‘-’) nécessitent un ‘=’ entre l'option et tout argument.

Voici un résumé des options prises en charge.

-m, --model=id
Sélectionne le numéro du modèle de la radio.
Voir la liste des modèles (utiliser “rigctl -l”).
-r, --rig-file=périphérique
Utilise périphérique comme nom de fichier du port connecté à la radio.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
-s, --serial-speed=débit
Définit la vitesse série de la radio à débit bauds.
Utilise la vitesse série maximale des capacités du backend radio comme valeur par défaut.
-c, --civaddr=id
Utilise id comme adresse CI-V pour communiquer avec la radio.
Utile uniquement pour les radios Icom et certains Ten-Tec.
Note : L'id est en notation décimale, sauf s'il est préfixé par 0x, auquel cas il est hexadécimal.
-C, --set-conf=parm=val[,parm=val]
Définit un ou plusieurs paramètres de configuration de la radio, par exemple stop_bits=2.
Utilisez l'option -L de rigctl pour obtenir une liste des paramètres de configuration pour un numéro de modèle donné.
-M, --rot-model=id
Sélectionne le numéro du modèle du rotateur.
Voir la liste des modèles (utiliser “rotctl -l”).
-R, --rot-file=périphérique
Utilise périphérique comme nom de fichier du port connecté au rotateur.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
-S, --rot-serial-speed=débit
Définit la vitesse série du rotateur à débit bauds.
Utilise la vitesse série maximale des capacités du backend du rotateur comme valeur par défaut.
-N, --rot-set-conf=parm=val[,parm=val]
Définit un ou plusieurs paramètres de configuration du rotateur, par exemple stop_bits=2.
Utilisez l'option -L de rotctl pour obtenir une liste des paramètres de configuration pour un numéro de modèle donné.
-v, --verbose
Active le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rigsmtr et quitte.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. Cela se produit très probablement avec les options --set-conf et --rot-set-conf.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à envoyer sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques de backend radio et peut être demandé par les développeurs.

STATUT DE SORTIE

rigsmtr sort avec :

0
si toutes les opérations se sont déroulées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib ;
3
si la radio n'a pas les capacités requises.

EXEMPLE

Collecter les lectures du S-Mètre sur un TS-850 pendant qu'un rotateur EasycommII effectue une rotation complète de 360° et enregistrer les mesures dans le fichier csmtr (texte tapé affiché en gras) :


$ rigsmtr -m 2009 -r /dev/ttyS1 -M 202 > csmtr

Après l'achèvement, le fichier csmtr contient des lignes telles que :


0 -47
30 -40
60 -22
90 -3
120 10
150 1
180 -11
210 -24
240 -35
270 -42
300 -48
330 -51
360 -49

Les résultats peuvent être tracés avec gnuplot(1) :


$ gnuplot
set angles degrees
set polar
set grid polar 15.
unset border
unset param
set style data line
set rrange [-60:60]
set xrange [-60:60]
set yrange [-60:60]
plot csmtr
