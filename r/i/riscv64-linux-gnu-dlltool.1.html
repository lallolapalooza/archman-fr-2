DLLTOOL(1) Outils de développement GNU DLLTOOL(1)

NOM

dlltool - créer des fichiers nécessaires à la construction et à l'utilisation des DLL

SYNTAXE

dlltool [-d|--input-def nom-fichier-def]
[-b|--base-file nom-fichier-base]
[-e|--output-exp nom-fichier-exports]
[-z|--output-def nom-fichier-def]
[-l|--output-lib nom-fichier-bibliothèque]
[-y|--output-delaylib nom-fichier-bibliothèque]
[--export-all-symbols] [--no-export-all-symbols]
[--exclude-symbols liste]
[--no-default-excludes]
[-S|--as chemin-vers-l-assembleur] [-f|--as-flags options]
[-D|--dllname nom] [-m|--machine machine]
[-a|--add-indirect]
[-U|--add-underscore] [--add-stdcall-underscore]
[-k|--kill-at] [-A|--add-stdcall-alias]
[-p|--ext-prefix-alias préfixe]
[-x|--no-idata4] [-c|--no-idata5]
[--use-nul-prefixed-import-tables]
[-I|--identify nom-fichier-bibliothèque] [--identify-strict]
[-i|--interwork]
[-n|--nodelete] [-t|--temp-prefix préfixe]
[-v|--verbose]
[-h|--help] [-V|--version]
[--no-leading-underscore] [--leading-underscore]
[--deterministic-libraries] [--non-deterministic-libraries]
[fichier-objet ...]

DESCRIPTION

dlltool lit ses entrées, qui peuvent provenir des options -d et -b ainsi que des fichiers objets spécifiés sur la ligne de commande. Il traite ensuite ces entrées et, si l'option -e a été spécifiée, il crée un fichier d'exportations. Si l'option -l a été spécifiée, il crée un fichier bibliothèque et si l'option -z a été spécifiée, il crée un fichier def. N'importe laquelle ou toutes les options -e, -l et -z peuvent être présentes dans une seule invocation de dlltool.

Lors de la création d'une DLL, en plus du code source de la DLL, il est nécessaire de disposer de trois autres fichiers. dlltool peut aider à la création de ces fichiers.

Le premier fichier est un fichier .def qui spécifie quelles fonctions sont exportées par la DLL, quelles fonctions la DLL importe, etc. C'est un fichier texte qui peut être créé manuellement, ou dlltool peut être utilisé pour le créer en utilisant l'option -z. Dans ce cas, dlltool analysera les fichiers objets spécifiés sur sa ligne de commande à la recherche des fonctions qui ont été spécialement marquées comme étant exportées et y placera des entrées dans le fichier .def qu'il crée.

Afin de marquer une fonction comme étant exportée d'une DLL, elle doit avoir une entrée -export:<nom_de_la_fonction> dans la section .drectve du fichier objet. Cela peut être fait en C en utilisant l'opérateur asm() :

asm (".section .drectve");
asm (".ascii \"-export:ma_fonction\"");

int ma_fonction (void) { ... }

Le deuxième fichier nécessaire à la création d'une DLL est un fichier d'exportations. Ce fichier est lié avec les fichiers objets qui composent le corps de la DLL et il gère l'interface entre la DLL et le monde extérieur. C'est un fichier binaire et il peut être créé en donnant l'option -e à dlltool lors de la création ou de la lecture d'un fichier .def.

Le troisième fichier nécessaire à la création d'une DLL est le fichier bibliothèque avec lequel les programmes seront liés pour accéder aux fonctions de la DLL (une « bibliothèque d'importation »). Ce fichier peut être créé en donnant l'option -l à dlltool lors de la création ou de la lecture d'un fichier .def.

Si l'option -y est spécifiée, dlltool génère une bibliothèque d'importation retardée qui peut être utilisée à la place de la bibliothèque d'importation normale pour permettre à un programme de ne se connecter à la dll qu'au moment où une fonction importée est appelée pour la première fois. L'exécutable résultant devra être lié à la bibliothèque statique delayimp contenant __delayLoadHelper2(), qui à son tour importera LoadLibraryA et GetProcAddress de kernel32.

dlltool construit le fichier bibliothèque manuellement, mais il construit le fichier d'exportations en créant des fichiers temporaires contenant des instructions assembleur puis en les assemblant. L'option de ligne de commande -S peut être utilisée pour spécifier le chemin de l'assembleur que dlltool utilisera, et l'option -f peut être utilisée pour passer des indicateurs spécifiques à cet assembleur. L'option -n peut être utilisée pour empêcher dlltool de supprimer ces fichiers assembleur temporaires une fois terminé, et si -n est spécifié deux fois, cela empêchera dlltool de supprimer les fichiers objets temporaires qu'il a utilisés pour construire la bibliothèque.

Voici un exemple de création d'une DLL à partir d'un fichier source dll.c et également de création d'un programme (à partir d'un fichier objet appelé program.o) qui utilise cette DLL :

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool peut également être utilisé pour interroger une bibliothèque d'importation existante afin de déterminer le nom de la DLL à laquelle elle est associée. Voir la description de l'option -I ou --identify.

OPTIONS

Les options de ligne de commande ont les significations suivantes :

-d nom-fichier
--input-def nom-fichier
Spécifie le nom d'un fichier .def à lire et traiter.
-b nom-fichier
--base-file nom-fichier
Spécifie le nom d'un fichier de base à lire et traiter. Le contenu de ce fichier sera ajouté à la section de relocalisation dans le fichier d'exportations généré par dlltool.
-e nom-fichier
--output-exp nom-fichier
Spécifie le nom du fichier d'exportations à créer par dlltool.
-z nom-fichier
--output-def nom-fichier
Spécifie le nom du fichier .def à créer par dlltool.
-l nom-fichier
--output-lib nom-fichier
Spécifie le nom du fichier bibliothèque à créer par dlltool.
-y nom-fichier
--output-delaylib nom-fichier
Spécifie le nom du fichier bibliothèque d'importation retardée à créer par dlltool.
--deterministic-libraries
--non-deterministic-libraries
Lors de la création de bibliothèques de sortie en réponse aux options --output-lib ou --output-delaylib, utilisez soit la valeur zéro pour les horodatages, les identifiants utilisateur et les identifiants de groupe créés (--deterministic-libraries), soit les horodatages, identifiants utilisateur et de groupe réels (--non-deterministic-libraries).
--export-all-symbols
Traiter tous les symboles globaux et faibles définis trouvés dans les fichiers objets d'entrée comme des symboles à exporter. Il y a une petite liste de symboles qui ne sont pas exportés par défaut ; voir l'option --no-default-excludes. Vous pouvez ajouter à la liste des symboles à ne pas exporter en utilisant l'option --exclude-symbols.
--no-export-all-symbols
Exporter uniquement les symboles explicitement listés dans un fichier .def d'entrée ou dans les sections .drectve des fichiers objets d'entrée. C'est le comportement par défaut. Les sections .drectve sont créées par les attributs dllexport dans le code source.
--exclude-symbols liste
N'exporter pas les symboles de la liste. C'est une liste de noms de symboles séparés par des caractères virgule ou deux-points. Les noms de symboles ne doivent pas contenir de trait de soulignement initial. Ceci n'est pertinent que lorsque --export-all-symbols est utilisé.
--no-default-excludes
Ne pas utiliser la liste par défaut de symboles à exclure. Les symboles courants qui sont exclus par défaut incluent `__main', `_main', `_WinMainCRTStartup', `_pei386_runtime_relocator'.
-S chemin-vers-l-assembleur
--as chemin-vers-l-assembleur
Spécifie le chemin de l'assembleur à utiliser pour assembler les fichiers intermédiaires d'exportation.
-f options
--as-flags options
Spécifie les indicateurs à passer à l'assembleur.
-D nom
--dllname nom
Spécifie le nom de la DLL pour laquelle la bibliothèque d'importation est créée. Ceci est nécessaire lorsque l'on crée une bibliothèque d'importation à partir d'un fichier d'exportations, car le nom du fichier de sortie n'est pas nécessairement le nom de la DLL.
-m machine
--machine machine
Spécifie le type de machine pour lequel la bibliothèque d'importation est créée. Les types de machines valides sont `i386', `i486', `i586', `i686', `pentium', `pentiumpro', `pentium3', `pentium4', `amd64', `x86_64', `i8086', `i386sx', `i486sx', `i386sl', `i486sl', `x87', `x87sl', `mmx', `mmxemu', `amd64em', `powerpc', `powerpclinear', `powerpcoldטן', `rs6000', `alpha', `arm', `sh', `mips', `mips16', `mipsfpu', `mipsfpu16', `bigendian', `littleendian', `thumb', `wasm32', `riscv32', `riscv64'. La valeur par défaut est le type de machine du système hôte.
-a
--add-indirect
Ajoute des entrées de table de liaison indirecte pour chaque fonction importée. Ceci est utilisé pour construire des bibliothèques d'importation compatibles avec les anciennes versions de Windows.
-U
--add-underscore
Ajoute un trait de soulignement préfixant aux noms de symboles lors de la création de bibliothèques d'importation. Ceci est généralement utilisé pour les bibliothèques C standard.
--add-stdcall-underscore
Ajoute un trait de soulignement préfixant aux noms de symboles qui sont marqués pour l'appel stdcall. Ceci est nécessaire pour la compatibilité avec les anciennes versions de Windows.
-k
--kill-at
Supprime le caractère `@` des noms de symboles lorsque vous utilisez l'option --add-stdcall-underscore. Ceci est nécessaire pour les anciennes versions de Windows.
-A
--add-stdcall-alias
Ajoute un alias stdcall pour chaque fonction exportée. Ceci est nécessaire pour la compatibilité avec les anciennes versions de Windows.
-p préfixe
--ext-prefix-alias préfixe
Ajoute un alias avec le préfixe spécifié pour chaque fonction exportée. Ceci est utile pour créer des bibliothèques d'importation pour des DLL qui utilisent des conventions d'appel non standard.
-x
--no-idata4
N'inclut pas la section `idata4` dans le fichier d'exportations. Cette section est utilisée pour les importations retardées.
-c
--no-idata5
N'inclut pas la section `idata5` dans le fichier d'exportations. Cette section est utilisée pour les importations retardées.
--use-nul-prefixed-import-tables
Utilise des tables d'importation préfixées par `\0' pour les importations retardées. Ceci est nécessaire pour la compatibilité avec certaines anciennes versions de Windows.
-I nom-fichier-bibliothèque
--identify nom-fichier-bibliothèque
Interroge le fichier bibliothèque spécifié pour déterminer le nom de la DLL associée. Si l'option --identify-strict est également fournie, dlltool échouera si la bibliothèque ne peut pas être identifiée.
--identify-strict
Comme --identify, mais échoue si la bibliothèque ne peut pas être identifiée.
-i
--interwork
Active le mode interwork pour les architectures ARM. Ceci est nécessaire pour créer des bibliothèques d'importation pour du code mixte ARM/Thumb.
-n
--nodelete
Ne supprime pas les fichiers assembleur temporaires créés par dlltool. Si cette option est spécifiée deux fois, cela empêche également la suppression des fichiers objets temporaires utilisés pour construire la bibliothèque.
-t préfixe
--temp-prefix préfixe
Spécifie un préfixe pour les fichiers temporaires créés par dlltool. Ceci est utile pour éviter les conflits de noms de fichiers.
-v
--verbose
Active la sortie détaillée. Ceci est utile pour déboguer dlltool.
-h
--help
Affiche un message d'aide et quitte.
-V
--version
Affiche les informations de version et quitte.
--no-leading-underscore
Ne pas ajouter de trait de soulignement préfixant aux noms de symboles. Ceci est utilisé pour les conventions d'appel qui n'utilisent pas de trait de soulignement initial, comme `cdecl`.
--leading-underscore
Ajoute un trait de soulignement préfixant aux noms de symboles. Ceci est le comportement par défaut pour de nombreuses conventions d'appel C.

-a

Spécifie que lorsque dlltool crée le fichier d'exportations, il doit ajouter une section qui permet aux fonctions exportées d'être référencées sans utiliser la bibliothèque d'importation. Quoi que cela puisse bien signifier !

Spécifie si les symboles standard doivent être préfixés, ou non.
--add-stdcall-underscore
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit préfixer un underscore aux noms des fonctions stdcall exportées. Les noms de variables et les noms de fonctions non-stdcall ne sont pas modifiés. Cette option est utile lors de la création de bibliothèques d'importation compatibles GNU pour des DLL tierces qui ont été construites avec des outils MS-Windows.
-k
--kill-at
Spécifie que les suffixes @<nombre> doivent être omis des noms des fonctions stdcall qui seront importées de la DLL. Ceci est utile lors de la création d'une bibliothèque d'importation pour une DLL qui exporte des fonctions stdcall mais sans le suffixe de nom de symbole habituel @<nombre>.

Ceci ne modifie pas la dénomination des symboles fournis par la bibliothèque d'importation aux programmes qui y sont liés, mais uniquement les entrées dans la table d'importation (c'est-à-dire la section .idata).

-A
--add-stdcall-alias
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit ajouter des alias pour les symboles stdcall sans @ <nombre> en plus des symboles avec @ <nombre>.
-p
--ext-prefix-alias préfixe
Demande à dlltool de créer des alias externes pour toutes les importations de DLL avec le préfixe spécifié. Les alias sont créés pour les symboles externes et d'importation sans underscore en tête.
-x
--no-idata4
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques il doit omettre la section ".idata4". Ceci est pour la compatibilité avec certains systèmes d'exploitation.
--use-nul-prefixed-import-tables
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques il doit préfixer les sections ".idata4" et ".idata5" par un élément nul. Ceci émule la génération ancienne par gnu des bibliothèques d'importation de "dlltool". Par défaut, cette option est désactivée.
-c
--no-idata5
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques il doit omettre la section ".idata5". Ceci est pour la compatibilité avec certains systèmes d'exploitation.
-I nomfichier
--identify nomfichier
Spécifie que dlltool doit inspecter la bibliothèque d'importation indiquée par nomfichier et rapporter, sur "stdout", le(s) nom(s) de la (des) DLL associée(s). Ceci peut être effectué en plus de toute autre opération indiquée par les autres options et arguments. dlltool échoue si la bibliothèque d'importation n'existe pas ou n'est pas réellement une bibliothèque d'importation. Voir aussi --identify-strict.
--identify-strict
Modifie le comportement de l'option --identify, de sorte qu'une erreur soit signalée si nomfichier est associé à plus d'une DLL.
-i
--interwork
Spécifie que dlltool doit marquer les objets dans le fichier de bibliothèque et le fichier d'exportations qu'il produit comme supportant l'interworking entre le code ARM et Thumb.
-n
--nodelete
Fait en sorte que dlltool conserve les fichiers assembleur temporaires qu'il a utilisés pour créer le fichier d'exportations. Si cette option est répétée, dlltool conservera également les fichiers objet temporaires qu'il utilise pour créer le fichier de bibliothèquedans le fichier de bibliothèqu.
-t préfixe
--temp-prefix préfixe
Fait en sorte que dlltool utilise préfixe lors de la construction des noms des fichiers assembleur et objet temporaires. Par défaut, le préfixe des fichiers temporaires est généré à partir du pid.
-v
--verbose
Demande à dlltool de décrire ce qu'il fait.
-h
--help
Affiche une liste des options de ligne de commande, puis quitte.
-V
--version
Affiche le numéro de version de dlltool, puis quitte.
@fichier
Lit les options de ligne de commande à partir de fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière soit de guillemets simples, soit de guillemets doubles. Tout caractère (y compris un antislash) peut être inclus en préfixant le caractère à inclure par un antislash. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées récursivement.

    riscv64-linux-gnu-dlltool(1)

    NOM

    riscv64-linux-gnu-dlltool — Créer une table de fonctions importées pour des bibliothèques partagées.

    SYNTAXE

    riscv64-linux-gnu-dlltool [-.]option...

    DESCRIPTION

    dlltool est un utilitaire qui crée des fichiers objets qui peuvent être utilisés pour lier dans une bibliothèque partagée quand vous n'avez pas la bibliothèque elle-même. Il génère généralement un fichier qui contient une table de fonctions importées.

    dlltool peut être utilisé pour créer une table de fonctions importées, qui peut être utilisée en combinaison avec le compilateur pour lier dans une bibliothèque partagée. Cela est utile lorsque vous ne disposez pas de la bibliothèque partagée de l'objet que vous souhaitez lier.

    L'utilisation la plus courante de dlltool consiste à créer une table de fonctions importées pour une bibliothèque DLL Windows. dlltool peut également être utilisé pour créer une bibliothèque d'importation pour un exécutable PE ou une bibliothèque DLL qui a été construite pour le système d'exploitation Windows.

    Dans les environnements Unix, dlltool est utilisé pour créer des tables de fonctions importées pour des bibliothèques partagées. Ces tables sont utilisées par le chargeur dynamique pour trouver les fonctions dans les bibliothèques partagées.

    Pour plus d'informations, veuillez consulter la documentation de dlltool.

    OPTIONS

    dlltool prend en charge un certain nombre d'options qui vous permettent de contrôler le processus de création de la table de fonctions importées.

    Les options courantes incluent :

    • -u, --usage : Affiche un message d'aide et quitte.
    • -h, --help : Affiche le message d'aide et quitte.
    • -v, --version : Affiche les informations de version et quitte.
    • -d, --dll nom-dll : Spécifie le nom de la bibliothèque DLL pour laquelle créer la table de fonctions importées.
    • -m, --machine machine : Spécifie l'architecture machine de la bibliothèque DLL.
    • -a, --add-symbol nom-symbole : Ajoute un symbole à la table de fonctions importées.
    • -r, --output fichier-objet : Spécifie le nom du fichier objet de sortie.

    Pour une liste complète des options, veuillez consulter la page de manuel de dlltool.
