RINT(3P) Manuel du programmeur POSIX RINT(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

rint, rintf, rintl — arrondir à la valeur entière la plus proche

SYNTAXE

#include <math.h>
double rint(double x);
float rintf(float x);
long double rintl(long double x);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

Ces fonctions renvoient la valeur entière (représentée sous forme de double) la plus proche de x dans la direction du mode d'arrondi actuel. Le mode d'arrondi actuel est défini par l'implémentation.

Si le mode d'arrondi actuel arrondit vers l'infini négatif, alors rint() est équivalent à floor(). Si le mode d'arrondi actuel arrondit vers l'infini positif, alors rint() est équivalent à ceil(). Si le mode d'arrondi actuel arrondit vers zéro, alors rint() est équivalent à trunc(). Si le mode d'arrondi actuel arrondit vers le plus proche, alors rint() diffère de round() en ce que les cas intermédiaires sont arrondis vers le pair plutôt qu'en s'éloignant de zéro.

Ces fonctions ne diffèrent des fonctions nearbyint(), nearbyintf(), et nearbyintl() que par le fait qu'elles peuvent lever l'exception de virgule flottante inexacte si le résultat diffère de l'argument.

Une application souhaitant vérifier les situations d'erreur doit définir errno à zéro et appeler feclearexcept(FE_ALL_EXCEPT) avant d'appeler ces fonctions. Au retour, si errno est non nul ou si fetestexcept(FE_INVALID | FE_DIVBYZERO | FE_OVERFLOW | FE_UNDERFLOW) est non nul, une erreur s'est produite.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient l'entier (représenté sous forme de nombre à double précision) le plus proche de x dans la direction du mode d'arrondi actuel. Le résultat doit avoir le même signe que x.

Si x est NaN, un NaN est renvoyé.

Si x est ±0 ou ±Inf, x est renvoyé.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATION

La valeur entière renvoyée par ces fonctions n'a pas besoin d'être exprimable comme un intmax_t. La valeur de retour doit être vérifiée avant d'être assignée à un type entier afin d'éviter les résultats indéfinis d'un dépassement entier.
