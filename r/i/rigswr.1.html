NOM

rigswr - mesure le ROS en fonction de la fréquence.

SYNTAXE

rigswr [-hvV] [-m id] [-r périphérique] [-s débit] [-c id] [-C param=val] [-p périphérique] [-P type] freq_debut freq_fin [pas_freq]

DESCRIPTION

rigswr utilise Hamlib pour contrôler une radio afin de mesurer le ROS (Rapport d'Ondes Stationnaires) sur une plage de fréquences.

Il scanne les fréquences de freq_debut à freq_fin avec un incrément optionnel de pas_freq (pas par défaut : 100 kHz). Toutes les valeurs doivent être saisies sous forme d'entier en Hertz (cycles par seconde).

Note : rigswr suppose que freq_debut est inférieure ou égale à freq_fin. Si elle est supérieure, rigswr se terminera sans rien faire.

Pour chaque fréquence, il émet à 25% de la PUISSANCE totale pendant 0,5 seconde en mode CW et lit le ROS.

La fréquence et le ROS correspondant sont ensuite imprimés sur stdout.

Pour fonctionner correctement, rigswr nécessite une radio capable de mesurer le ROS et un backend Hamlib qui supporte la lecture du ROS à partir de la radio.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que de nombreuses bibliothèques backend manquent de support complet pour les radios, les fonctions de base sont généralement bien prises en charge.

Veuillez signaler les bugs et fournir des commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur immédiatement après ou séparée par un espace. Les options longues commençant par deux tirets (‘-’) nécessitent un ‘=’ entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --modele=id
Sélectionne le numéro du modèle de la radio.
Voir la liste des modèles (utiliser “rigctl -l”).
-r, --fichier-radio=périphérique
Utilise périphérique comme nom de fichier du port connecté à la radio.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les systèmes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
-s, --vitesse-serie=débit
Définit la vitesse série de la radio au débit débit.
Utilise la vitesse série maximale des capacités du backend radio comme valeur par défaut.
-c, --civaddr=id
Utilise id comme adresse CI-V pour communiquer avec la radio.
Utile uniquement pour les radios Icom et certains radios Ten-Tec.
Note : L'id est en notation décimale, sauf s'il est préfixé par 0x, auquel cas il est hexadécimal.
-C, --config-set=param=val[,param=val]
Définit un ou plusieurs paramètres de configuration de la radio, par exemple stop_bits=2.
Utilisez l'option -L de rigctl pour obtenir une liste des paramètres de configuration pour un numéro de modèle donné.
-p, --fichier-ptt=périphérique
Utilise périphérique comme nom de fichier du port Push-To-Talk en utilisant un fichier périphérique comme avec l'option -r ci-dessus.
Ceci n'est nécessaire que si la radio n'a pas de contrôle PTT CAT et nécessite un port périphérique séparé pour activer l'émetteur.
-P, --type-ptt=type
Utilise le type de périphérique Push-To-Talk.
Les types pris en charge sont RIG (CAT), DTR, RTS, PARALLEL, NONE.
-v, --verbeux
Active le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-h, --aide
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rigswr et quitte.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et renverront une erreur. Cela est le plus susceptible de se produire avec l'option --config-set.

DIAGNOSTICS

L'option -v, --verbeux permet différents niveaux de diagnostics à afficher sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques backend radio et peut être demandé par les développeurs.

STATUT DE SORTIE

rigswr se termine avec :

0
si toutes les opérations se sont déroulées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib ;
3
si la radio n'a pas les capacités requises.

EXEMPLE

Scanne les fréquences entre 14.000 MHz et 14.200 MHz avec un pas de 50 kHz sur un TS-850 et enregistre les mesures de ROS dans le fichier cswr (texte tapé en gras) :


$ rigswr -m 2009 -r /dev/ttyS1 14000000 14200000 50000 > cswr

Après l'achèvement, cswr contient les lignes suivantes :


14000000 1.50
14050000 1.31
14100000 1.22
14150000 1.07
14200000 1.07

Le résultat peut être tracé avec gnuplot(1) :


$ gnuplot
set data style linespoints
set grid
plot cswr

BUGS

Selon la configuration du manipulateur / QSK, les transmissions en mode CW peuvent ne pas être modulées, donnant ainsi potentiellement un résultat erroné. Veuillez signaler cette situation si elle se produit.
