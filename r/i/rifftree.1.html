NOM

rifftree - Affiche la structure arborescente RIFF d'un fichier RIFF arbitraire.

SYNTAXE

rifftree [OPTIONS] FICHIER

DESCRIPTION

Le format RIFF (Resource Interchange File Format) est un format de fichier binaire simple destiné aux structures de données arborescentes. De nombreux formats de fichiers propriétaires sont construits sur le format RIFF (par exemple, les formats de fichiers multimédias comme WAV, AVI, DLS, GIG). Les données dans un fichier RIFF sont encapsulées dans des « morceaux » (chunks). Il existe des morceaux de liste (conteneurs) qui peuvent être vus comme des nœuds dans l'arbre de données et peuvent donc avoir des enfants (c'est-à-dire pouvoir avoir des sous-morceaux) et il existe des morceaux de données normaux qui peuvent être vus comme des feuilles dans l'arbre de données et ne peuvent donc pas avoir d'enfants. Les morceaux réguliers (feuilles de l'arbre) contiennent les données réelles à stocker. Les morceaux de liste eux-mêmes (nœuds / conteneurs) ne contiennent aucune donnée en eux-mêmes.

Chaque morceau de liste et morceau normal possède un ID de 32 bits (non unique), qui est généralement un texte ASCII de quatre caractères lisible par l'homme, reflétant le but du morceau ou de la liste respective. Cette application affichera cet ID pour chaque morceau trouvé. L'avantage des ID de liste/morceaux lisibles par l'homme est que les fichiers basés sur cette pratique peuvent facilement être analysés manuellement avec un éditeur hexadécimal.

Un fichier RIFF normal commence toujours par un morceau de liste (soit avec l'ID de morceau « RIFF » soit « RIFX »), qui contient tous les autres morceaux. Il n'y a pas d'autres morceaux en dehors des limites de ce premier morceau dans un fichier RIFF normal. Vous pouvez cependant outrepasser cette attente avec les arguments décrits ci-dessous (voir l'argument « --flat »), afin de pouvoir ouvrir d'autres fichiers de type RIFF.

OPTIONS

 FICHIER
Nom du fichier basé sur RIFF.
 -v
Affiche la version et quitte.
 -s
Affiche la taille de chaque morceau RIFF.
 --flat
Le premier morceau du fichier n'est pas un morceau de liste (conteneur). Vous pourriez vouloir l'utiliser si le fichier n'est pas un « vrai » fichier RIFF. Un « vrai » fichier RIFF a toujours un morceau de liste RIFF (conteneur) comme tout premier morceau dans un fichier, et il s'attend à ce que tous les morceaux soient contenus dans ce premier morceau (liste/conteneur). Ainsi, dans un « vrai » fichier RIFF, il n'y aurait pas d'autres morceaux en dehors de la portée (c'est-à-dire après la fin) du premier morceau du fichier. De nombreux formats de fichiers primitifs cependant sont une séquence plate de morceaux de données ordinaires (pas des morceaux de liste/conteneur). Si vous utilisez cette option, vous devez également utiliser l'option --first-chunk-id.
 --first-chunk-id CKID
Actuellement utilisé uniquement en combinaison avec --flat. CKID doit être l'ID de morceau de 32 bits du tout premier morceau dans le fichier. Si le premier morceau du fichier n'a pas l'ID de morceau donné, cette application s'arrêtera. Cela garantit que le fichier est bien du format attendu. L'argument attendu ici doit être un texte ASCII lisible par l'homme de quatre caractères, car les ID de morceaux RIFF sont généralement des chaînes ASCII lisibles par l'homme.
 --big-endian
Le fichier est au format big-endian. Actuellement utilisé uniquement en combinaison avec --flat. Sans --flat, le type d'endianness sera automatiquement détecté. Si vous utilisez --flat et ne fournissez ni --big-endian ni --little-endian, alors le type d'endianness natif de votre machine sera utilisé par défaut.
 --little-endian
Le fichier est au format little-endian. Actuellement utilisé uniquement en combinaison avec --flat. Sans --flat, le type d'endianness sera automatiquement détecté. Si vous utilisez --flat et ne fournissez ni --big-endian ni --little-endian, alors le type d'endianness natif de votre machine sera utilisé par défaut.

EXEMPLES

Affiche la structure du fichier d'un fichier RIFF standard (dans l'exemple suivant, un fichier Gigasampler/GigaStudio) et affiche les tailles exactes de chaque morceau du fichier :

rifftree -s piano.gig

Fait de même pour un fichier son Korg Trinity/Triton/OASYS/Kronos (qui n'est pas un fichier RIFF standard, mais un fichier de type RIFF) :

rifftree -s --flat --first-chunk-id MSP1 --big-endian PIANO_000.KMP
