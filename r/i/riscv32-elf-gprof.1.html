NOM

gprof - afficher les données de profilage d'appel

SYNTAXE

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nom] ]
[ -I dossiers ] [ -d[num] ] [ -k de/à ]
[ -m nb-min ] [ -R fichier_carte ] [ -t longueur_tableau ]
[ --[no-]annotated-source[=nom] ]
[ --[no-]exec-counts[=nom] ]
[ --[no-]flat-profile[=nom] ] [ --[no-]graph[=nom] ]
[ --[no-]time=nom] [ --all-lines ] [ --brief ]
[ --debug[=niveau] ] [ --function-ordering ]
[ --file-ordering fichier_carte ] [ --directory-path=dossiers ]
[ --display-unused-functions ] [ --file-format=nom ]
[ --file-info ] [ --help ] [ --line ] [ --inline-file-names ]
[ --min-count=n ] [ --no-static ] [ --print-path ]
[ --separate-files ] [ --static-call-graph ] [ --sum ]
[ --table-length=longueur ] [ --traditional ] [ --version ]
[ --width=n ] [ --ignore-non-functions ]
[ --demangle[=STYLE] ] [ --no-demangle ]
[--external-symbol-table=nom]
[ fichier_image ] [ fichier_profil ... ]

DESCRIPTION

"gprof" produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré dans le profil de chaque appelant. Les données de profilage proviennent du fichier de profil de graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc" et "f77". L'option -pg lie également les versions des routines de bibliothèque qui sont compilées pour le profilage. "Gprof" lit le fichier objet donné (par défaut "a.out") et établit la relation entre sa table de symboles et le graphe d'appels du profil du fichier gmon.out. Si plusieurs fichiers de profil sont spécifiés, la sortie de "gprof" montre la somme des informations de profilage des fichiers de profil spécifiés.

"Gprof" calcule la quantité de temps passée dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels dans un cycle sont effectués pour partager le temps du cycle.

Plusieurs formes de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment le plus de temps, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a également une estimation du temps passé dans les sous-routines de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonctions qui consomment beaucoup de temps.

La liste de code source annoté est une copie du code source du programme, étiquetée avec le nombre de fois où chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient lequel des plusieurs formats de sortie "gprof" doit produire.

Beaucoup de ces options prennent un symspec optionnel pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec différents symspecs, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options remplace le comportement par défaut (-p -q), qui imprime un profil plat et une analyse du graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--annotated-source[=symspec]"
L'option -A fait en sorte que "gprof" imprime le code source annoté. Si symspec est spécifié, imprime la sortie uniquement pour les symboles correspondants.
"-b"
"--brief"
Si l'option -b est donnée, "gprof" n'imprime pas les blocs de texte verbeux qui essaient d'expliquer la signification de tous les champs dans les tableaux. C'est utile si vous avez l'intention d'imprimer la sortie, ou si vous en avez marre de voir les blocs de texte.
"-B"
L'option -B fait en sorte que "gprof" imprime l'analyse du graphe d'appels.
"-C[symspec]"
"--exec-counts[=symspec]"
L'option -C fait en sorte que "gprof" imprime un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, imprime le décompte uniquement pour les symboles correspondants.

Si le fichier de données de profilage contient des enregistrements de comptage de blocs de base, la spécification de l'option -l, ainsi que -C, fera en sorte que les comptages d'exécution de blocs de base soient décomptés et affichés.

"-i"
"--file-info"
L'option -i fait en sorte que "gprof" affiche des informations récapitulatives sur les fichiers de données de profilage et quitte ensuite. Le nombre d'enregistrements d'histogramme, de graphes d'appels et de blocs de base est affiché.
"-I dossiers"
"--directory-path=dossiers"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers sources. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Utilisé principalement pour la sortie de code source annoté.
"-J[symspec]"
"--no-annotated-source[=symspec]"
L'option -J fait en sorte que "gprof" n'imprime pas le code source annoté. Si symspec est spécifié, "gprof" imprime le code source annoté, mais exclut les symboles correspondants.
"-L"
"--print-path"
Normalement, les noms de fichiers sources sont imprimés avec le composant de chemin supprimé. L'option -L fait en sorte que "gprof" imprime le chemin d'accès complet des noms de fichiers sources, qui est déterminé à partir des informations de débogage symbolique dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--flat-profile[=symspec]"
L'option -p fait en sorte que "gprof" imprime un profil plat. Si symspec est spécifié, imprime le profil plat uniquement pour les symboles correspondants.
"-P[symspec]"
"--no-flat-profile[=symspec]"
L'option -P fait en sorte que "gprof" supprime l'impression d'un profil plat. Si symspec est spécifié, "gprof" imprime un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graph[=symspec]"
L'option -q fait en sorte que "gprof" imprime l'analyse du graphe d'appels. Si symspec est spécifié, imprime le graphe d'appels uniquement pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--no-graph[=symspec]"
L'option -Q fait en sorte que "gprof" supprime l'impression du graphe d'appels. Si symspec est spécifié, "gprof" imprime un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--table-length=num"
L'option -t fait en sorte que les num lignes sources les plus actives dans chaque fichier source soient listées lorsque l'annotation source est activée. La valeur par défaut est 10.
"-y"
"--separate-files"
Cette option n'affecte que la sortie de code source annoté. Normalement, "gprof" imprime les fichiers sources annotés sur la sortie standard. Si cette option est spécifiée, le code source annoté pour un fichier nommé chemin/nom_fichier est généré dans le fichier nom_fichier-ann. Si le système de fichiers sous-jacent tronquerait nom_fichier-ann de manière à écraser le fichier original nom_fichier, "gprof" génère alors le code source annoté dans le fichier nom_fichier.ann (si le nom de fichier original a une extension, cette extension est remplacée par .ann).
"-Z[symspec]"
"--no-exec-counts[=symspec]"
L'option -Z fait en sorte que

"gprof" pour ne pas imprimer un décompte des fonctions et du nombre de fois où chacune a été appelée. Si symspec est spécifié, imprime le décompte, mais exclut les symboles correspondants.
"-r"
"--function-ordering"
L'option --function-ordering demande à "gprof" d'imprimer une proposition d'ordonnancement des fonctions pour le programme, basée sur les données de profilage. Cette option suggère un ordonnancement qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui supportent un ordonnancement arbitraire des fonctions dans un exécutable.

Les détails exacts sur la manière de forcer l'éditeur de liens à placer les fonctions dans un ordre particulier dépendent du système et sortent du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering demande à "gprof" d'imprimer une proposition d'ordonnancement de ligne de liaison .o pour le programme, basée sur les données de profilage. Cette option suggère un ordonnancement qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui ne supportent pas un ordonnancement arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin d'accès à un fichier qui fournit des correspondances entre les noms de fonctions et les fichiers objets. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec GNU "nm", tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T demande à "gprof" d'imprimer sa sortie dans un style BSD "traditionnel".
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, cette option n'est utilisée que lors de l'impression de l'index des fonctions en bas du graphe d'appel.
"-x"
"--all-lines"
Cette option affecte uniquement la sortie annotée source. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à l'option -a de "tcov".
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démangled lors de l'impression de la sortie. Par défaut, les symboles sont démangled. L'option "--no-demangle" peut être utilisée pour désactiver le démangling. Différents compilateurs ont différents styles de mangling. L'argument facultatif de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a demande à "gprof" de supprimer l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globaux, et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels depuis/vers elles, etc., sera attribué à la fonction qui était chargée juste avant dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appel.
"-c"
"--static-call-graph"
L'option -c demande que le graphe d'appel du programme soit augmenté par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonction dans le code machine binaire. Étant donné que les enregistrements normaux du graphe d'appel ne sont générés que lorsque les fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels à des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais uniquement si des entrées de table de symboles sont présentes pour elles. Les appels aux routines de bibliothèques dynamiques ne sont généralement *pas* trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appel avec des comptes d'appels de 0.
"-D"
"--ignore-non-functions"
L'option -D demande à "gprof" d'ignorer les symboles dont on ne sait pas qu'ils sont des fonctions. Cette option fournira des données de profilage plus précises sur les systèmes où elle est prise en charge (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appel tous les arcs des symboles correspondant à from à ceux correspondant à to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les succès de l'histogramme sont attribués à des lignes de code source individuelles, au lieu des fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par d'anciennes versions du compilateur "gcc". Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera également combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où, dans une grande fonction, un programme passe son temps, il augmente aussi considérablement le temps d'exécution de "gprof", et amplifie les inexactitudes statistiques.

"--inline-file-names"
Cette option demande à "gprof" d'imprimer le fichier source après chaque symbole dans le profil plat et dans le graphe d'appel. Le chemin complet du fichier est imprimé si l'option est utilisée avec l'option -L.
"-m num"
"--min-count=num"
Cette option n'affecte que la sortie du compte d'exécution. Les symboles exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n demande à "gprof", dans son analyse du graphe d'appel, de ne propager les temps que pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -N demande à "gprof", dans son analyse du graphe d'appel, de ne pas propager les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S demande à "gprof" de lire un fichier de table de symboles externe, tel que /proc/kallsyms, au lieu de lire la table de symboles du fichier objet donné (par défaut, c'est "a.out"). Ceci est utile pour le profilage des modules du noyau.
"-z"
"--display-unused-functions"
Si vous utilisez l'option -z, "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et dans lesquelles aucun temps n'a été passé. Ceci est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, active tout le débogage.
"-h"
"--help"
L'option -h imprime l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profilage. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic, et prof (pas encore supporté).
"-s"
"--sum"
L'option -s demande à "gprof" de résumer les informations contenues dans les fichiers de données de profilage qu'il a lus, et d'écrire un fichier de données de profilage appelé gmon.sum, qui contient toutes les informations des fichiers de données de profilage que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter "gprof" à nouveau sans -s pour analyser les données cumulées dans le fichier gmon.sum.

"-v"
"--version"
L'option -v demande à "gprof" d'imprimer le numéro de version actuel, puis de quitter.

Options dépréciées

Ces options ont été remplacées par des versions plus récentes utilisant des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer les informations concernant la fonction function_name (et ses enfants...) dans le graphe d'appel. La fonction sera toujours listée comme un enfant des fonctions qui l'appellent, mais son numéro d'index sera affiché comme [pas imprimé]. Plus d'une option -e peut être donnée ; un seul function_name peut être indiqué avec chaque option -e.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e", mais le temps passé dans la fonction (et ses enfants qui n'ont été appelés par personne d'autre) ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appel. Plus d'une option -E peut être donnée ; un seul function_name peut être indiqué avec chaque option -E.
"-f function_name"
L'option -f function demande à "gprof" pour limiter le graphe d'appel à la fonction nom_fonction et à ses enfants (et leurs enfants...). Plusieurs options -f peuvent être données ; un seul nom_fonction peut être indiqué avec chaque option -f.
"-F nom_fonction"
L'option -F fonction fonctionne comme l'option "-f", mais seul le temps passé dans la fonction et ses enfants (et leurs enfants...) sera utilisé pour déterminer le temps total et les pourcentages de temps pour le graphe d'appel. Plusieurs options -F peuvent être données ; un seul nom_fonction peut être indiqué avec chaque option -F. L'option -F annule l'option -E.

FICHIERS

"a.out"
la liste des noms et l'espace texte.
"gmon.out"
graphe d'appel dynamique et profil.
"gmon.sum"
graphe d'appel dynamique résumé et profil.

BOGUES

La granularité de l'échantillonnage est montrée, mais reste au mieux statistique. Nous supposons que le temps de chaque exécution d'une fonction peut être exprimé par le temps total de la fonction divisé par le nombre de fois où la fonction est appelée. Ainsi, le temps propagé le long des arcs du graphe d'appel vers les parents de la fonction est directement proportionnel au nombre de fois où cet arc est traversé.

Les parents qui ne sont pas eux-mêmes profilés auront le temps de leurs enfants profilés propagé vers eux, mais ils apparaîtront comme étant invoqués spontanément dans la liste du graphe d'appel, et leur temps ne sera pas propagé plus loin. De même, les attrapeurs de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Tous les enfants profilés des attrapeurs de signaux devraient avoir leur temps propagé correctement, à moins que l'attrapeur de signal n'ait été invoqué pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou retourner normalement pour que les informations de profilage soient sauvegardées dans le fichier gmon.out.
