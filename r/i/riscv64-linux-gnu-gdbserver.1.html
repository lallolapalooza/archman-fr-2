GDBSERVER(1) Outils de développement GNU GDBSERVER(1)

NOM

gdbserver - Serveur distant pour le débogueur GNU

SYNOPSIS

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPTION

gdbserver est un programme qui permet d'exécuter GDB sur une machine différente de celle qui exécute le programme en cours de débogage.

Utilisation (côté serveur (cible)) :

Premièrement, vous devez disposer d'une copie du programme que vous souhaitez déboguer sur le système cible. Le programme peut être dépouillé pour économiser de l'espace si nécessaire, car gdbserver ne se soucie pas des symboles. Toute la gestion des symboles est prise en charge par le GDB exécuté sur le système hôte.

Pour utiliser le serveur, connectez-vous au système cible et exécutez le programme gdbserver. Vous devez lui indiquer (a) comment communiquer avec GDB, (b) le nom de votre programme et (c) ses arguments. La syntaxe générale est :

cible> gdbserver <comm> <programme> [<args> ...]

Par exemple, en utilisant un port série, vous pourriez dire :

cible> gdbserver /dev/com1 emacs foo.txt

Ceci indique à gdbserver de déboguer emacs avec l'argument foo.txt, et de communiquer avec GDB via /dev/com1. gdbserver attend maintenant patiemment que le GDB hôte communique avec lui.

Pour utiliser une connexion TCP, vous pourriez dire :

cible> gdbserver hôte:2345 emacs foo.txt

Ceci dit à peu près la même chose que l'exemple précédent, sauf que nous allons communiquer avec le GDB "hôte" via TCP. L'argument "hôte:2345" signifie que nous attendons une connexion TCP depuis "hôte" vers le port TCP local 2345. (Actuellement, la partie "hôte" est ignorée.) Vous pouvez choisir n'importe quel numéro de port qui ne conflit pas avec les ports TCP existants sur le système cible. Le même numéro de port doit être utilisé dans la commande "target remote" du GDB hôte, qui sera décrite prochainement. Notez que si vous choisissez un numéro de port qui entre en conflit avec un autre service, gdbserver affichera un message d'erreur et se terminera.

gdbserver peut également s'attacher à des programmes en cours d'exécution. Ceci est réalisé via l'argument --attach. La syntaxe est :

cible> gdbserver --attach <comm> <pid>

pid est l'identifiant du processus d'un processus en cours d'exécution. Il n'est pas nécessaire d'indiquer à gdbserver le binaire du processus en cours d'exécution.

Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ni d'identifiant de processus auquel s'attacher, utilisez l'option de ligne de commande --multi. Dans ce cas, vous devriez vous connecter en utilisant "target extended-remote" pour démarrer le programme que vous souhaitez déboguer.

cible> gdbserver --multi <comm>

Utilisation (côté hôte) :

Vous avez besoin d'une copie non dépouillée du programme cible sur votre système hôte, car GDB doit examiner ses tables de symboles et autres. Lancez GDB comme d'habitude, avec le programme cible comme premier argument. (Vous pourriez avoir besoin d'utiliser l'option --baud si la ligne série ne fonctionne pas à 9600 bauds.) C'est "gdb PROGRAMME-CIBLE", ou "gdb --baud BAUD PROGRAMME-CIBLE". Après cela, la seule nouvelle commande que vous devez connaître est "target remote" (ou "target extended-remote"). Son argument est soit un nom de périphérique (généralement un port série, comme /dev/ttyb), soit un descripteur "HÔTE:PORT". Par exemple :

(gdb) target remote /dev/ttyb

communique avec le serveur via la ligne série /dev/ttyb, et :

(gdb) target remote cible:2345

communique via une connexion TCP vers le port 2345 sur l'hôte `cible', où vous avez précédemment lancé gdbserver avec le même numéro de port. Notez que pour les connexions TCP, vous devez lancer gdbserver avant d'utiliser la commande `target remote', sinon vous pourriez obtenir une erreur comme `Connection refused'.

gdbserver peut également déboguer plusieurs inférieurs simultanément, comme décrit dans le manuel GDB au nœud "Inferiors Connections and Programs" -- commande shell "info -f gdb -n 'Inferiors Connections and Programs'". Dans ce cas, utilisez la variante de commande GDB "extended-remote" :

(gdb) target extended-remote cible:2345

L'option --multi de gdbserver peut ou peut ne pas être utilisée dans ce cas.

OPTIONS

Il existe trois modes d'invocation différents pour gdbserver :

  • Déboguer un programme spécifique dont le nom est spécifié : 
    gdbserver <comm> <prog> [<args>...]

    Le paramètre comm spécifie comment le serveur doit communiquer avec GDB ; il s'agit soit d'un nom de périphérique (pour utiliser une ligne série), soit d'un numéro de port TCP (":1234"), soit de "-" ou "stdio" pour utiliser l'entrée/sortie standard de "gdbserver". Spécifiez le nom du programme à déboguer dans prog. Les arguments restants seront passés au programme tels quels. Lorsque le programme se termine, GDB fermera la connexion et "gdbserver" se terminera.

  • Déboguer un programme spécifique en spécifiant l'identifiant du processus d'un programme en cours d'exécution : 
    gdbserver --attach <comm> <pid>

    Le paramètre comm est décrit ci-dessus. Fournissez l'identifiant du processus d'un programme en cours d'exécution dans pid ; GDB fera le reste. Comme pour le mode précédent, lorsque le processus pid se termine, GDB fermera la connexion et "gdbserver" se terminera.

  • Mode multi-processus -- déboguer plus d'un programme/processus : 
    gdbserver --multi <comm>

    Dans ce mode, GDB peut indiquer à gdbserver quelle(s) commande(s) exécuter. Contrairement aux 2 autres modes, GDB ne fermera pas la connexion lorsqu'un processus débogué se termine, vous pouvez donc déboguer plusieurs processus dans la même session.

Dans chacun des modes, vous pouvez spécifier les options suivantes :

--help
Liste toutes les options, avec de brèves explications.
--version
Cette option fait en sorte que gdbserver affiche son numéro de version et se termine.
--attach
gdbserver s'attachera à un programme en cours d'exécution. La syntaxe est : 
cible> gdbserver --attach <comm> <pid>

pid est l'identifiant du processus d'un processus en cours d'exécution. Il n'est pas nécessaire d'indiquer à gdbserver le binaire du processus en cours d'exécution.

--multi
Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ou d'identifiant de processus auquel s'attacher, utilisez cette option de ligne de commande. Ensuite, vous pouvez vous connecter en utilisant "target extended-remote" et démarrer le programme que vous souhaitez déboguer. La syntaxe est : 
cible> gdbserver --multi <comm>
--debug[=option1,option2,...]
Demande à "gdbserver" d'afficher des informations de statut supplémentaires sur le processus de débogage. Cette option est destinée au développement de "gdbserver" et aux rapports de bugs aux développeurs.

Chaque option est le nom d'un composant pour lequel le débogage doit être activé. La liste des options possibles est all, threads, event-loop, remote. L'option spéciale all active tous les composants. La liste des options est traitée de gauche à droite, et une option peut être précédée du caractère "-" pour désactiver la sortie pour ce composant, vous pourriez donc écrire :

cible> gdbserver --debug=all,-event-loop

pour activer la sortie de débogage pour tous les composants, sauf event-loop. Si aucune option n'est passée à --debug, alors cela est traité comme équivalent à --debu

NAME

gdbserver — GDB Remote Serial Protocol server

SYNOPSIS

gdbserver [--multi] [--debug-file=filename] [--debug-format=option1[,option2,...]] [--wrapper wrapper [args...]] [--once] [host:port] [program [args...]]

DESCRIPTION

gdbserver is a program that allows you to debug programs running on a remote machine. It communicates with the GDB debugger using the GDB Remote Serial Protocol.

The host and port arguments specify the address and port on which gdbserver will listen for incoming connections from GDB. If host is omitted, gdbserver will listen on all available network interfaces.

The program argument is the executable to be debugged. If specified, gdbserver will launch this program and debug it. If omitted, gdbserver will wait for GDB to attach to a running process.

The args following program are the command-line arguments passed to the program being debugged.

OPTIONS

--multi
Enable multi-threaded debugging. In this mode, gdbserver allows GDB to debug multiple threads within the same process. Without this option, gdbserver typically handles only one thread at a time, or may not properly support multi-threaded applications. This option may change in future releases of "gdbserver".
--debug-file=filename
Instruct "gdbserver" to send any debug output to the given filename. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-format=option1[,option2,...]
Instruct "gdbserver" to include extra information in each line of debugging output.
--wrapper
Specify a wrapper to launch programs for debugging. The option should be followed by the name of the wrapper, then any command-line arguments to pass to the wrapper, then "--" indicating the end of the wrapper arguments.
--once
By default, gdbserver keeps the listening TCP port open, so that additional connections are possible. However, if you start "gdbserver" with the --once option, it will stop listening for any further connection attempts after connecting to the first GDB session.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.

Using GDB: A Guide to the GNU Source-Level Debugger, Richard M. Stallman and Roland H. Pesch, July 1991.

NOM

gdbserver — serveur du protocole série GDB à distance

SYNOPSIS

gdbserver [--multi] [--debug-file=nom_fichier] [--debug-format=option1[,option2,...]] [--wrapper wrapper [args...]] [--once] [hote:port] [programme [args...]]

DESCRIPTION

gdbserver est un programme qui permet de déboguer des programmes en cours d'exécution sur une machine distante. Il communique avec le débogueur GDB en utilisant le protocole série GDB à distance.

Les arguments hote et port spécifient l'adresse et le port sur lesquels gdbserver écoutera les connexions entrantes de GDB. Si hote est omis, gdbserver écoutera sur toutes les interfaces réseau disponibles.

L'argument programme est l'exécutable à déboguer. S'il est spécifié, gdbserver lancera ce programme et le débogera. S'il est omis, gdbserver attendra que GDB s'attache à un processus en cours d'exécution.

Les args suivant programme sont les arguments de ligne de commande passés au programme en cours de débogage.

OPTIONS

--multi
Active le débogage multi-thread. Dans ce mode, gdbserver permet à GDB de déboguer plusieurs threads au sein du même processus. Sans cette option, gdbserver ne gère généralement qu'un seul thread à la fois, ou peut ne pas prendre en charge correctement les applications multi-thread. Cette option pourrait changer dans les futures versions de "gdbserver".
--debug-file=nom_fichier
Demande à "gdbserver" d'envoyer toute sortie de débogage vers le nom_fichier donné. Cette option est destinée au développement de "gdbserver" et aux rapports de bug destinés aux développeurs.
--debug-format=option1[,option2,...]
Demande à "gdbserver" d'inclure des informations supplémentaires dans chaque ligne de sortie de débogage.
--wrapper
Spécifie un wrapper pour lancer les programmes à déboguer. L'option doit être suivie du nom du wrapper, puis de tous les arguments de ligne de commande à passer au wrapper, puis de "--" indiquant la fin des arguments du wrapper.
--once
Par défaut, gdbserver maintient le port TCP d'écoute ouvert, de sorte que des connexions supplémentaires soient possibles. Cependant, si vous démarrez "gdbserver" avec l'option --once, il cessera d'écouter toute tentative de connexion ultérieure après s'être connecté à la première session GDB.

VOIR AUSSI

La documentation complète de GDB est maintenue sous forme de manuel Texinfo. Si les programmes "info" et "gdb" ainsi que la documentation Texinfo de GDB sont correctement installés sur votre site, la commande

info gdb

devrait vous donner accès au manuel complet.
