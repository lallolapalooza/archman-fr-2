NOM

readelf - afficher des informations sur les fichiers ELF

SYNTAXE

readelf [-a|--all]
[-h|--file-header]
[-l|--program-headers|--segments]
[-S|--section-headers|--sections]
[-g|--section-groups]
[-t|--section-details]
[-e|--headers]
[-s|--syms|--symbols]
[--dyn-syms|--lto-syms]
[--sym-base=[0|8|10|16]]
[--demangle=style|--no-demangle]
[--quiet]
[--recurse-limit|--no-recurse-limit]
[-U method|--unicode=method]
[-X|--extra-sym-info|--no-extra-sym-info]
[-n|--notes]
[-r|--relocs]
[-u|--unwind]
[-d|--dynamic]
[-V|--version-info]
[-A|--arch-specific]
[-D|--use-dynamic]
[-L|--lint|--enable-checks]
[-x <nombre ou nom>|--hex-dump=<nombre ou nom>]
[-p <nombre ou nom>|--string-dump=<nombre ou nom>]
[-R <nombre ou nom>|--relocated-dump=<nombre ou nom>]
[-z|--decompress]
[-c|--archive-index]
[-w[lLiaprmfFsoORtUuTgAck]|
--debug-dump[=rawline,=decodedline,=info,=abbrev,=pubnames,=aranges,=macro,=frames,=frames-interp,=str,=str-offsets,=loc,=Ranges,=pubtypes,=trace_info,=trace_abbrev,=trace_aranges,=gdb_index,=addr,=cu_index,=links]]
[-wK|--debug-dump=follow-links]
[-wN|--debug-dump=no-follow-links]
[-wD|--debug-dump=use-debuginfod]
[-wE|--debug-dump=do-not-use-debuginfod]
[-P|--process-links]
[--dwarf-depth=n]
[--dwarf-start=n]
[--ctf=section]
[--ctf-parent=section]
[--ctf-symbols=section]
[--ctf-strings=section]
[--sframe=section]
[-I|--histogram]
[-v|--version]
[-W|--wide]
[-T|--silent-truncation]
[-H|--help]
fichier_elf...

DESCRIPTION

readelf affiche des informations sur un ou plusieurs fichiers objets au format ELF. Les options contrôlent quelles informations spécifiques afficher.

fichier_elf... sont les fichiers objets à examiner. Les fichiers ELF 32 bits et 64 bits sont supportés, ainsi que les archives contenant des fichiers ELF.

Ce programme remplit une fonction similaire à objdump mais il va plus dans le détail et il est indépendant de la bibliothèque BFD, donc si il y a un bug dans BFD, readelf n'en sera pas affecté.

OPTIONS

Les formes longues et courtes des options, montrées ici comme alternatives, sont équivalentes. Au moins une option autre que -v ou -H doit être donnée.

-a
--all
Équivalent à spécifier --file-header, --program-headers, --sections, --symbols, --relocs, --dynamic, --notes, --version-info, --arch-specific, --unwind, --section-groups et --histogram.

Note - cette option n'active pas --use-dynamic elle-même, donc si cette option n'est pas présente sur la ligne de commande, les symboles dynamiques et les relocations dynamiques ne seront pas affichés.

-h
--file-header
Affiche les informations contenues dans l'en-tête ELF au début du fichier.
-l
--program-headers
--segments
Affiche les informations contenues dans les en-têtes de segment du fichier, s'il en a.
--quiet
Supprime le diagnostic "pas de symboles".
-S
--sections
--section-headers
Affiche les informations contenues dans les en-têtes de section du fichier, s'il en a.
-g
--section-groups
Affiche les informations contenues dans les groupes de sections du fichier, s'il en a.
-t
--section-details
Affiche les informations détaillées sur les sections. Implique -S.
-s
--symbols
--syms
Affiche les entrées dans la table des symboles du fichier, s'il en a une. Si un symbole a des informations de version associées, elles sont également affichées. La chaîne de version est affichée comme un suffixe au nom du symbole, précédé d'un caractère @. Par exemple foo@VER_1. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées vers le symbole, elle est affichée comme un suffixe précédé de deux caractères @. Par exemple foo@@VER_2.
--dyn-syms
Affiche les entrées dans la table des symboles dynamiques du fichier, s'il en a une. Le format de sortie est le même que le format utilisé par l'option --syms.
--lto-syms
Affiche le contenu des tables de symboles LTO dans le fichier.
--sym-base=[0|8|10|16]
Force le champ de taille de la table des symboles à utiliser la base donnée. Toutes les options non reconnues seront traitées comme 0. --sym-base=0 représente le comportement par défaut et hérité. Il affichera les tailles en décimal pour les nombres inférieurs à 100000. Pour les tailles supérieures ou égales à 100000, la notation hexadécimale sera utilisée avec un préfixe 0x. --sym-base=8 donnera les tailles de symboles en octal. --sym-base=10 donnera toujours les tailles de symboles en décimal. --sym-base=16 donnera toujours les tailles de symboles en hexadécimal avec un préfixe 0x.
-C
--demangle[=style]
Décode (démangle) les noms de symboles bas niveau en noms de niveau utilisateur. Cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. Le style de dé-mangling optionnel peut être utilisé pour choisir un style de dé-mangling approprié pour votre compilateur.
--no-demangle
Ne décode pas les noms de symboles bas niveau. C'est le comportement par défaut.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du dé-mangling des chaînes. Comme les formats de mangling des noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une erreur de mémoire. La limite essaie d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour dé-mangler des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-U [d|i|l|e|x|h]
--unicode=[défaut|invalide|locale|escape|hex|highlight]
Contrôle l'affichage des caractères non-ASCII dans les noms d'identifiants. Le mode par défaut (--unicode=locale ou --unicode=défaut) consiste à les traiter comme des caractères multi-octets et à les afficher dans la locale actuelle. Toutes les autres versions de cette option traitent les octets comme des valeurs encodées en UTF-8 et tentent de les interpréter. S'ils ne peuvent pas être interprétés ou si l'option --unicode=invalide est utilisée, ils sont affichés sous forme d'une séquence d'octets hexadécimaux, entourés d'accolades.

L'utilisation de l'option --unicode=escape affichera les caractères sous forme de séquences d'échappement unicode (\uxxxx). L'utilisation de l'option --unicode=hex affichera les caractères sous forme de séquences d'octets hexadécimaux entourées d'accolades.

L'utilisation de l'option --unicode=highlight affichera les caractères sous forme de séquences d'échappement unicode, mais les mettra également en surbrillance en rouge, en supposant que la coloration est prise en charge par le périphérique de sortie. La coloration est destinée à attirer l'attention sur la présence de séquences unicode lorsqu'elles ne sont pas attendues.

-X
--extra-sym-info
Lors de l'affichage des détails des symboles, inclure des informations supplémentaires non présentées normalement. Actuellement, cela ajoute simplement le nom de la section référencée par le champ d'index du symbole, s'il y en a un. À l'avenir, plus d'informations pourraient être affichées lorsque cette option est activée.

L'activation de cette option active également l'option --wide, du moins lors de l'affichage des informations de symbole.

--no-extra-sym-info
Désactive l'effet de l'option --extra-sym-info. C'est le comportement par défaut.
-e
--headers
Affiche tous les en-têtes du fichier. Équivalent à -h -l -S.
-n
--notes
Affiche le contenu des segments et/ou sections NOTE, s'il y en a.
-r
--relocs
Affiche le contenu de la section de relocalisation du fichier, s'il en possède une.
-u
--unwind
Affiche le contenu de la section de déroulement du fichier, s'il en possède une. Seules les sections de déroulement pour les fichiers ELF IA64, ainsi que les tables de déroulement ARM (« .ARM.exidx » / « .ARM.extab ») sont actuellement prises en charge. Si la prise en charge n'est pas encore implémentée pour votre architecture, vous pouvez essayer d'afficher le contenu de la section .eh_frames en utilisant les options --debug-dump=frames ou --debug-dump=frames-interp.
-d
--dynamic
Affiche le contenu de la section dynamique du fichier, s'il en possède une.
-V
--version-info
Affiche le contenu des sections de version dans le fichier, s'il en existe.
-A
--arch-specific
Affiche les informations spécifiques à l'architecture dans le fichier, s'il y en a.
-D
--use-dynamic
Lors de l'affichage des symboles, cette option fait utiliser par readelf les tables de hachage de symboles dans la section dynamique du fichier, plutôt que les sections de table de symboles.

Lors de l'affichage des relocalisations, cette option fait afficher par readelf les relocalisations dynamiques plutôt que les relocalisations statiques.

-L
--lint
--enable-checks
Affiche des messages d'avertissement concernant d'éventuels problèmes avec le(s) fichier(s) examiné(s). S'il est utilisé seul, tout le contenu du ou des fichiers sera examiné. S'il est utilisé avec l'une des options de vidage, les messages d'avertissement ne seront produits que pour les éléments affichés.
-x <numéro ou nom>
--hex-dump=<numéro ou nom>
Affiche le contenu de la section indiquée sous forme d'octets hexadécimaux. Un numéro identifie une section particulière par son index dans la table des sections ; toute autre chaîne identifie toutes les sections portant ce nom dans le fichier objet.
-R <numéro ou nom>
--relocated-dump=<numéro ou nom>
Affiche le contenu de la section indiquée sous forme d'octets hexadécimaux. Un numéro identifie une section particulière par son index dans la table des sections ; toute autre chaîne identifie toutes les sections portant ce nom dans le fichier objet. Le contenu de la section sera relocalisé avant d'être affiché.
-p <numéro ou nom>
--string-dump=<numéro ou nom>
Affiche le contenu de la section indiquée sous forme de chaînes imprimables. Un numéro identifie une section particulière par son index dans la table des sections ; toute autre chaîne identifie toutes les sections portant ce nom dans le fichier objet.
-z
--decompress
Demande que les sections vidées par les options x, R ou p soient décompressées avant d'être affichées. Si les sections ne sont pas compressées, elles sont affichées telles quelles.
-c
--archive-index
Affiche les informations d'index de symboles du fichier contenues dans la partie en-tête des archives binaires. Remplit la même fonction que la commande t de ar, mais sans utiliser la bibliothèque BFD.
-w[lLiaprmfFsOoRtUuTgAckK]
--debug-dump[=rawline,=decodedline,=info,=abbrev,=pubnames,=aranges,=macro,=frames,=frames-interp,=str,=str-offsets,=loc,=Ranges,=pubtypes,=trace_info,=trace_abbrev,=trace_aranges,=gdb_index,=addr,=cu_index,=links,=follow-links]
Affiche le contenu des sections de débogage DWARF dans le fichier, s'il y en a. Les sections de débogage compressées sont automatiquement décompressées (temporairement) avant d'être affichées. Si une ou plusieurs des lettres ou mots optionnels suivent l'interrupteur, seuls ces types de données seront vidés. Les lettres et les mots se réfèrent aux informations suivantes :
"a"
"=abbrev"
Affiche le contenu de la section .debug_abbrev.
"A"
"=addr"
Affiche le contenu de la section .debug_addr.
"c"
"=cu_index"
Affiche le contenu des sections .debug_cu_index et/ou .debug_tu_index.
"f"
"=frames"
Affiche le contenu brut d'une section .debug_frame.
"F"
"=frames-interp"
Affiche le contenu interprété d'une section .debug_frame.
"g"
"=gdb_index"
Affiche le contenu des sections .gdb_index et/ou .debug_names.
"i"
"=info"
Affiche le contenu de la section .debug_info. Notez que la sortie de cette option peut également être restreinte par l'utilisation des options --dwarf-depth et --dwarf-start.
"k"
"=links"
Affiche le contenu des sections .gnu_debuglink, .gnu_debugaltlink et .debug_sup, s'il y en a. Affiche également tous les liens vers des fichiers objets de débogage séparés (dwo), s'ils sont spécifiés par les attributs DW_AT_GNU_dwo_name ou DW_AT_dwo_name dans la section .debug_info.
"K"
"=follow-links"
Affiche le contenu des sections de débogage sélectionnées qui se trouvent dans des fichiers d'informations de débogage séparés et liés. Cela peut entraîner l'affichage de plusieurs versions de la même section de débogage si elle existe dans plus d'un fichier.

De plus, lors de l'affichage des attributs DWARF, si une forme est trouvée qui référence le fichier d'informations de débogage séparé, le contenu référencé sera également affiché.

Notez que dans certaines distributions, cette option est activée par défaut. Elle peut être désactivée via l'option de débogage N. Le comportement par défaut peut être choisi lors de la configuration de binutils via les options --enable-follow-debug-links=yes ou --enable-follow-debug-links=no. Si celles-ci ne sont pas utilisées, le comportement par défaut est d'activer le suivi des liens de débogage.

Notez que si la prise en charge du protocole debuginfod a été activée lors de la construction des binutils, cette option inclura également une tentative de contacter les serveurs debuginfod mentionnés dans la variable d'environnement DEBUGINFOD_URLS. Cela pourrait prendre du temps à résoudre. Ce comportement peut être désactivé via l'option de débogage =do-not-use-debuginfod.

"N"
"=no-follow-links"
Désactive le suivi des liens vers des fichiers d'informations de débogage séparés.
"D"
"=use-debuginfod"
Active le contact avec les serveurs debuginfod s'il est nécessaire de suivre les liens de débogage. C'est le comportement par défaut.
"E"
"=do-not-use-debuginfod"
Désactive le contact avec les serveurs debuginfod lorsqu'il est nécessaire de suivre les liens de débogage.
"l"
"=rawline"
Affiche le contenu de la section .debug_line dans un format brut.
"L"
"=decodedline"
Affiche le contenu interprété de la section .debug_line.
"m"
"=macro"
Affiche le contenu des sections .debug_macro et/ou .debug_macinfo.
"o"
"=loc"
Affiche le contenu des sections .debug_loc et/ou .debug_loclists.
"O"
"=str-offsets"
Affiche le contenu de la section .debug_str_offsets.
"p"
"=pubnames"
Affiche le contenu des sections .debug_pubnames et/ou .debug_gnu_pubnames.
"r"
"=aranges"
Affiche le contenu de la section .debug_aranges.
"R"
"=Ranges"
Affiche le contenu des sections .debug_ranges et/ou .debug_rnglists.
"s"
"=str"
Affiche le contenu des sections .debug_str, .debug_line_str et/ou .debug_str_offsets.
"t"
"=pubtype"
Affiche le contenu des sections .debug_pubtypes et/ou .debug_gnu_pubtypes.
"T"
"=trace_aranges"
Affiche le contenu de la section .trace_aranges.
"u"
"=trace_abbrev"
Affiche le contenu de la section .trace_abbrev.
"U"
"=trace_info"
Affiche le contenu de la section .trace_info.

Note : l'affichage du contenu des sections .debug_static_funcs, .debug_static_vars et debug_weaknames n'est pas pris en charge actuellement.

--dwarf-depth=n
Limite l'extraction de la section ".debug_info" à n enfants. Ceci n'est utile qu'avec --debug-dump=info. Par défaut, tous les DIEs sont imprimés ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIEs à un niveau égal ou supérieur à n ne seront pas imprimés. L'intervalle pour n est basé sur zéro.

--dwarf-start=n
Imprime seulement les DIEs en commençant par le DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si elle est spécifiée, cette option supprimera l'impression de toutes les informations d'en-tête et de tous les DIEs avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront imprimés.

Ceci peut être utilisé conjointement avec --dwarf-depth.

-P
--process-links
Affiche le contenu des sections non-debug trouvées dans des fichiers debuginfo séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -wK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
--ctf[=section]
Affiche le contenu de la section CTF spécifiée. Les sections CTF contiennent elles-mêmes de nombreuses sous-sections, toutes affichées dans l'ordre.

Par défaut, affiche le nom de la section nommée .ctf, qui est le nom émis par ld.

--ctf-parent=member
Si la section CTF contient des types définis de manière ambiguë, elle constarra d'une archive de nombreux dictionnaires CTF, tous héritant d'un dictionnaire contenant des types non ambigus. Ce membre est nommé par défaut .ctf, comme la section qui le contient, mais il est possible de changer ce nom en utilisant la fonction "ctf_link_set_memb_name_changer" au moment de la liaison. Lors de l'examen d'archives CTF créées par un éditeur de liens utilisant le changeur de nom pour renommer le membre de l'archive parente, --ctf-parent peut être utilisé pour spécifier le nom utilisé pour le parent.
--ctf-symbols=section
--ctf-strings=section
Spécifie le nom d'une autre section à partir de laquelle le fichier CTF peut hériter de chaînes et de symboles. Par défaut, les tables ".symtab" et sa table de chaînes liée sont utilisées.

Si --ctf-symbols ou --ctf-strings est spécifié, l'autre doit également être spécifié.

-I
--histogram
Affiche un histogramme des longueurs des listes de compartiments lors de l'affichage du contenu des tables de symboles.
-v
--version
Affiche le numéro de version de readelf.
-W
--wide
Ne coupe pas les lignes de sortie pour les faire tenir dans 80 colonnes. Par défaut, readelf coupe les lignes d'en-tête de section et de listing de segment pour les fichiers ELF 64 bits, afin qu'elles tiennent dans 80 colonnes. Cette option fait que readelf imprime chaque en-tête de section ou chaque segment sur une seule ligne, ce qui est beaucoup plus lisible sur les terminaux plus larges que 80 colonnes.
-T
--silent-truncation
Normalement, lorsque readelf affiche un nom de symbole et qu'il doit tronquer le nom pour qu'il tienne dans un affichage de 80 colonnes, il ajoute un suffixe de "[...]" au nom. Cette option de ligne de commande désactive ce comportement, permettant d'afficher 5 caractères supplémentaires du nom et restaurant le comportement précédent de readelf (avant la version 2.35).
-H
--help
Affiche les options de ligne de commande comprises par readelf.
@file
Lit les options de ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en précédant le caractère à inclure d'une barre oblique inverse. Le file peut lui-même contenir des options @file supplémentaires ; de telles options seront traitées récursivement.
