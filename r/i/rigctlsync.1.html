NOM

rigctlsync - synchroniser un émetteur-récepteur avec SDR# (ou un autre émetteur-récepteur)

SYNTAXE

rigctlsync [-hlLuV] [-m id] [-r périphérique] [-R périphérique] [-s débit] [-S débit] [-c id] [-C param=val] [-B] [-v[-Z]]

DESCRIPTION

Permet de synchroniser la fréquence d'un émetteur-récepteur avec SDR#. Optimal lorsqu'utilisé avec rigctld, FlRig ou une radio multiport.

Veuillez signaler les bugs et fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui acceptent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux traits (“-”) nécessitent un “=” entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --model=id
Sélectionne le numéro du modèle de la radio.
Voir la liste des modèles (utilisez “rigctlsync -l”).
Note : rigctlsync (ou un logiciel tiers utilisant l'API C) utilisera le modèle de radio 2 pour NET rigctl (communication avec rigctld).
-r, --rig-file=périphérique
Utilise périphérique comme nom de fichier du port connecté à la radio.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les saveurs BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
La chaîne spéciale “uh-rig” peut être donnée pour activer le support des périphériques micro-ham.
-R, --rig-file2=périphérique
Utilise périphérique comme nom de fichier de l'un des ports COM virtuels -- votre programme se connectera à l'autre port COM de la paire virtuelle.
-s, --serial-speed=débit
Définit la vitesse série sur le débit.
Utilise la vitesse série maximale des capacités du backend radio (définie par -m ci-dessus) comme défaut.
-S, --serial-speed2=débit
Définit la vitesse série sur le débit pour le port COM virtuel (voir -R).
Utilise la vitesse série maximale des capacités du backend radio (définie par -m ci-dessus) comme défaut.
-c, --civaddr=id
Utilise id comme adresse CI-V pour communiquer avec la radio.
Utile uniquement pour les radios Icom et certains Ten-Tec.
Note : L'id est en notation décimale, sauf s'il est préfixé par 0x, auquel cas il est hexadécimal.
-L, --show-conf
Liste tous les paramètres de configuration pour la radio définie avec -m ci-dessus.
-C, --set-conf=param=val[,param=val]
Définit un ou plusieurs paramètres de configuration de la radio, par ex. stop_bits=2.
Utilisez l'option -L ci-dessus pour obtenir une liste des paramètres de configuration d'un numéro de modèle donné.
-u, --dump-caps
Affiche les capacités de la radio définie avec -m ci-dessus et quitte.
-l, --list
Liste tous les numéros de modèles définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être parcourue en utilisant Maj-PagePréc/Maj-PageSuiv, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou la fenêtre cmd sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple “rigctl -l | more”.
-n, --no-restore-ai
rigctl restaure l'état de l'information automatique (AI) sur la radio contrôlée.
Si ce n'est pas souhaité, par exemple si vous utilisez rigctl pour activer ou désactiver le mode AI, passez cette option.
-B, --mapa2b
Mappe set_freq sur VFOA vers VFOB au lieu de cela. Cela permet d'utiliser un skimmer CW avec la radio en mode split et cliquer sur une fréquence dans le skimmer CW définira VFOB à la fréquence de transmission.
-v, --verbose
Définit le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Z, --debug-time-stamps
Active les horodatages pour les messages de débogage.
À utiliser uniquement en combinaison avec l'option -v car elle ne génère aucune sortie seule.
-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rigctl et quitte.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. Cela se produit le plus souvent avec les options --set-conf et --show-conf.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à afficher sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques de backends radio et peut être demandé par les développeurs.

ÉTAT DE SORTIE

rigctlsync se termine avec :

0
si toutes les opérations se sont terminées normalement ;
1
s'il y a eu une option de ligne de commande ou un argument invalide ;
2
si une erreur a été retournée par Hamlib.

EXEMPLE

Démarrer rigctlsync avec FLRig comme modèle Hamlib


$ rigctlsync -m 4 -M 9 -R 192.168.1.1:4532

Le schéma suivant montre le flux de communication qui permet à N1MM Logger+ de communiquer avec une radio connectée à Flrig :


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM
