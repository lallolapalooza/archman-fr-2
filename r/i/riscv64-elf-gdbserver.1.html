GDBSERVER(1) Outils de développement GNU GDBSERVER(1)

NOM

gdbserver - Serveur distant pour le débogueur GNU

SYNTAXE

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPTION

gdbserver est un programme qui permet d'exécuter GDB sur une machine différente de celle qui exécute le programme en cours de débogage.

Utilisation (côté serveur (cible)) :

Tout d'abord, vous devez avoir une copie du programme que vous souhaitez déboguer sur le système cible. Le programme peut être dépouillé pour économiser de l'espace si nécessaire, car gdbserver ne se soucie pas des symboles. Toute la gestion des symboles est prise en charge par GDB exécuté sur le système hôte.

Pour utiliser le serveur, connectez-vous au système cible et exécutez le programme gdbserver. Vous devez lui indiquer (a) comment communiquer avec GDB, (b) le nom de votre programme et (c) ses arguments. La syntaxe générale est :

cible> gdbserver <comm> <programme> [<args> ...]

Par exemple, en utilisant un port série, vous pourriez dire :

cible> gdbserver /dev/com1 emacs foo.txt

Cela indique à gdbserver de déboguer emacs avec l'argument foo.txt, et de communiquer avec GDB via /dev/com1. gdbserver attend maintenant patiemment que GDB hôte communique avec lui.

Pour utiliser une connexion TCP, vous pourriez dire :

cible> gdbserver hôte:2345 emacs foo.txt

Cela dit à peu près la même chose que l'exemple précédent, sauf que nous allons communiquer avec le GDB de "hôte" via TCP. L'argument "hôte:2345" signifie que nous nous attendons à voir une connexion TCP de "hôte" sur le port TCP local 2345. (Actuellement, la partie "hôte" est ignorée.) Vous pouvez choisir n'importe quel numéro de port qui n'entre pas en conflit avec d'autres ports TCP existants sur le système cible. Le même numéro de port doit être utilisé dans la commande "target remote" de GDB hôte, qui sera décrite plus loin. Notez que si vous choisissez un numéro de port qui entre en conflit avec un autre service, gdbserver affichera un message d'erreur et quittera.

gdbserver peut également s'attacher à des programmes en cours d'exécution. Ceci est réalisé via l'argument --attach. La syntaxe est :

cible> gdbserver --attach <comm> <pid>

pid est l'identifiant de processus d'un processus en cours d'exécution. Il n'est pas nécessaire de pointer gdbserver vers un exécutable pour le processus en cours.

Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ni d'ID de processus à attacher, utilisez l'option de ligne de commande --multi. Dans ce cas, vous devriez vous connecter en utilisant "target extended-remote" pour démarrer le programme que vous souhaitez déboguer.

cible> gdbserver --multi <comm>

Utilisation (côté hôte) :

Vous avez besoin d'une copie non dépouillée du programme cible sur votre système hôte, car GDB doit examiner ses tables de symboles et autres. Démarrez GDB comme vous le feriez normalement, avec le programme cible comme premier argument. (Vous pourriez avoir besoin d'utiliser l'option --baud si la ligne série fonctionne à autre chose que 9600 bauds.) C'est "gdb PROGRAMME-CIBLE", ou "gdb --baud BAUD PROGRAMME-CIBLE". Après cela, la seule nouvelle commande dont vous avez besoin est "target remote" (ou "target extended-remote"). Son argument est soit un nom de périphérique (généralement un périphérique série, comme /dev/ttyb), soit un descripteur "HÔTE:PORT". Par exemple :

(gdb) target remote /dev/ttyb

communique avec le serveur via la ligne série /dev/ttyb, et :

(gdb) target remote l-cible:2345

communique via une connexion TCP au port 2345 sur l'hôte `l-cible', où vous aviez précédemment démarré gdbserver avec le même numéro de port. Notez que pour les connexions TCP, vous devez démarrer gdbserver avant d'utiliser la commande `target remote', sinon vous pourriez obtenir une erreur du type `Connection refused'.

gdbserver peut également déboguer plusieurs inférieurs à la fois, décrits dans le manuel GDB dans le nœud "Connexions et Programmes des Inférieurs" -- commande shell "info -f gdb -n 'Connexions et Programmes des Inférieurs'". Dans ce cas, utilisez la variante de commande GDB "extended-remote" :

(gdb) target extended-remote l-cible:2345

L'option --multi de gdbserver peut ou peut ne pas être utilisée dans ce cas.

OPTIONS

Il existe trois modes différents pour invoquer gdbserver :

  • Déboguer un programme spécifique spécifié par son nom : 
    gdbserver <comm> <prog> [<args>...]

    Le paramètre comm spécifie comment le serveur doit communiquer avec GDB ; il s'agit soit d'un nom de périphérique (pour utiliser une ligne série), d'un numéro de port TCP (":1234"), soit de "-" ou "stdio" pour utiliser l'entrée/sortie standard de "gdbserver". Spécifiez le nom du programme à déboguer dans prog. Tous les arguments restants seront passés au programme tels quels. Lorsque le programme se termine, GDB fermera la connexion, et "gdbserver" se terminera.

  • Déboguer un programme spécifique en spécifiant l'ID de processus d'un programme en cours d'exécution : 
    gdbserver --attach <comm> <pid>

    Le paramètre comm est décrit ci-dessus. Fournissez l'identifiant de processus d'un programme en cours d'exécution dans pid ; GDB fera le reste. Comme pour le mode précédent, lorsque le processus pid se termine, GDB fermera la connexion, et "gdbserver" se terminera.

  • Mode multi-processus -- déboguer plus d'un programme/processus : 
    gdbserver --multi <comm>

    Dans ce mode, GDB peut indiquer à gdbserver quelles commandes exécuter. Contrairement aux 2 autres modes, GDB ne fermera pas la connexion lorsqu'un processus débogué se terminera, vous pouvez donc déboguer plusieurs processus dans la même session.

Dans chacun des modes, vous pouvez spécifier ces options :

--help
Liste toutes les options, avec de brèves explications.
--version
Cette option provoque l'affichage du numéro de version de gdbserver et sa sortie.
--attach
gdbserver s'attachera à un programme en cours d'exécution. La syntaxe est : 
cible> gdbserver --attach <comm> <pid>

pid est l'identifiant de processus d'un programme en cours d'exécution. Il n'est pas nécessaire de pointer gdbserver vers un exécutable pour le programme en cours.

--multi
Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ni d'ID de processus à attacher, utilisez cette option de ligne de commande. Vous pouvez ensuite vous connecter en utilisant "target extended-remote" et démarrer le programme que vous souhaitez déboguer. La syntaxe est : 
cible> gdbserver --multi <comm>
--debug[=option1,option2,...]
Indique à "gdbserver" d'afficher des informations de statut supplémentaires sur le processus de débogage. Cette option est destinée au développement de "gdbserver" et aux rapports de bugs aux développeurs.

Chaque option est le nom d'un composant pour lequel le débogage doit être activé. La liste des options possibles est all, threads, event-loop, remote. L'option spéciale all active tous les composants. La liste des options est traitée de gauche à droite, et une option peut être précédée du caractère "-" pour désactiver la sortie pour ce composant, vous pourriez donc écrire :

cible> gdbserver --debug=all,-event-loop

pour activer la sortie de débogage pour tous les composants sauf event-loop. Si aucune option n'est passée à --debug, alors cela est traité comme équivalent à --debug=thre

gdbserver(1) — archlinux

NAME

gdbserver ― a remote debugging program.

SYNOPSIS

gdbserver [ --authority ] [ --debug-file filename ] [ --debug-format option1[,option2... ] ] [ --once ] [ --wrapper wrapper-name ] [--] host:port program [ arg... ]
gdbserver [ --authority ] [ --debug-file filename ] [ --debug-format option1[,option2... ] ] [ --once ] [ --wrapper wrapper-name ] [ --attach ] host:port pid

DESCRIPTION

The gdbserver program is a small program that runs on the remote machine and allows you to debug programs there using the GNU Debugger (gdb) running on your local machine.

gdbserver supports debugging programs that are executed via fork or exec system calls. The process being debugged must be launched by gdbserver, or attached to by gdbserver.

The gdbserver program requires a stub to be running on the remote machine. This stub is what talks to the target processor and performs operations such as reading and writing registers and memory.

The gdbserver program talks to the GDB client using TCP. The gdbserver program listens on a specified port, and the GDB client connects to that port.

The remote debugging session can be started in two ways:

  • The gdbserver program starts the program to be debugged. The program is specified as the last arguments to gdbserver. This is the most common way to start a remote debugging session.

  • The gdbserver program attaches to an already running program. The process ID of the program to be attached to is specified as the last argument to gdbserver.

Note that gdbserver does not support debugging programs that use fork or exec in the same way as gdb does. For debugging programs that use fork or exec, you should use the gdbserver --wrapper option, or the gdbserver --attach option, or start the program under gdbserver in a shell.

OPTIONS

--authority
This option allows gdbserver to listen on a different network interface than the default. It is intended for use on systems with multiple network interfaces, and it is not recommended for general use.
--debug-file=filename
Instruct gdbserver to send any debug output to the given filename. This option is intended for gdbserver development and for bug reports to the developers.
--debug-format=option1[,option2,...]
Instruct gdbserver to include extra information in each line of debugging output.
--wrapper
Specify a wrapper to launch programs for debugging. The option should be followed by the name of the wrapper, then any command-line arguments to pass to the wrapper, then -- indicating the end of the wrapper arguments.
--once
By default, gdbserver keeps the listening TCP port open, so that additional connections are possible. However, if you start gdbserver with the --once option, it will stop listening for any further connection attempts after connecting to the first GDB session.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.

Using GDB: A Guide to the GNU Source-Level Debugger, Richard M. Stallman and Roland H. Pesch, July 1991.

NOM

gdbserver ― un programme de débogage à distance.

SYNTAXE

gdbserver [ --authority ] [ --debug-file nom_de_fichier ] [ --debug-format option1[,option2... ] ] [ --once ] [ --wrapper nom_du_wrapper ] [--] hôte:port programme [ arg... ]
gdbserver [ --authority ] [ --debug-file nom_de_fichier ] [ --debug-format option1[,option2... ] ] [ --once ] [ --wrapper nom_du_wrapper ] [ --attach ] hôte:port pid

DESCRIPTION

Le programme gdbserver est un petit programme qui s'exécute sur la machine distante et vous permet de déboguer des programmes là-bas en utilisant le débogueur GNU (gdb) s'exécutant sur votre machine locale.

gdbserver supporte le débogage des programmes qui sont exécutés via les appels système fork ou exec. Le processus débogué doit être lancé par gdbserver, ou être attaché par gdbserver.

Le programme gdbserver nécessite un stub (une petite partie de code) s'exécutant sur la machine distante. Ce stub est ce qui communique avec le processeur cible et effectue des opérations telles que la lecture et l'écriture des registres et de la mémoire.

Le programme gdbserver communique avec le client GDB en utilisant TCP. Le programme gdbserver écoute sur un port spécifié, et le client GDB se connecte à ce port.

La session de débogage à distance peut être démarrée de deux manières :

  • Le programme gdbserver démarre le programme à déboguer. Le programme est spécifié comme derniers arguments de gdbserver. C'est la façon la plus courante de démarrer une session de débogage à distance.

  • Le programme gdbserver s'attache à un programme déjà en cours d'exécution. L'identifiant du processus (PID) du programme à attacher est spécifié comme dernier argument de gdbserver.

Notez que gdbserver ne supporte pas le débogage des programmes qui utilisent fork ou exec de la même manière que gdb. Pour déboguer des programmes qui utilisent fork ou exec, vous devriez utiliser l'option gdbserver --wrapper, ou l'option gdbserver --attach, ou lancer le programme sous gdbserver dans un shell.

OPTIONS

--authority
Cette option permet à gdbserver d'écouter sur une interface réseau différente de celle par défaut. Elle est destinée à être utilisée sur des systèmes avec plusieurs interfaces réseau, et n'est pas recommandée pour une utilisation générale.
--debug-file=nom_de_fichier
Instruire gdbserver d'envoyer toute sortie de débogage vers le nom_de_fichier donné. Cette option est destinée au développement de gdbserver et pour les rapports de bugs aux développeurs.
--debug-format=option1[,option2,...]
Instruire gdbserver d'inclure des informations supplémentaires dans chaque ligne de sortie de débogage.
--wrapper
Spécifier un wrapper pour lancer des programmes pour le débogage. L'option doit être suivie du nom du wrapper, puis de tous les arguments en ligne de commande à passer au wrapper, puis de -- indiquant la fin des arguments du wrapper.
--once
Par défaut, gdbserver laisse le port TCP d'écoute ouvert, de sorte que des connexions supplémentaires soient possibles. Cependant, si vous démarrez gdbserver avec l'option --once, il arrêtera d'écouter toute tentative de connexion ultérieure après s'être connecté à la première session GDB.

VOIR AUSSI

La documentation complète de GDB est maintenue sous forme de manuel Texinfo. Si les programmes "info" et "gdb" ainsi que la documentation Texinfo de GDB sont correctement installés sur votre site, la commande

info gdb

devrait vous donner accès au manuel complet.
