DESCRIPTION

GNU as est en réalité une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les formats de fichiers objet, la plupart des directives d'assembleur (souvent appelées pseudo-ops) et la syntaxe de l'assembleur.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour être utilisée par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte que as assemble correctement tout ce que les autres assembleurs pour la même machine assembleraient. Toutes les exceptions sont documentées explicitement. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage d'assemblage 680x0.

Chaque fois que vous exécutez as, il assemble un seul programme source. Le programme source est composé d'un ou plusieurs fichiers. (L'entrée standard est également un fichier.)

Vous donnez à as une ligne de commande qui comporte zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du nom de fichier de gauche vers la droite). Un argument de ligne de commande (dans n'importe quelle position) qui n'a pas de signification spéciale est considéré comme un nom de fichier d'entrée.

Si vous ne donnez aucun nom de fichier à as, il tente de lire un fichier d'entrée depuis l'entrée standard de as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler.

Utilisez -- si vous devez explicitement nommer le fichier d'entrée standard dans votre ligne de commande.

Si la source est vide, as produit un petit fichier objet vide.

as peut écrire des avertissements et des messages d'erreur dans le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas se produire lorsqu'un compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour que as puisse continuer à assembler un programme défectueux ; les erreurs signalent un problème grave qui interrompt l'assemblage.

Si vous invoquez as via le compilateur C GNU, vous pouvez utiliser l'option -Wa pour passer des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple:

gcc -c -g -O -Wa,-alh,-L file.c

Cela passe deux options à l'assembleur : -alh (générer une liste dans la sortie standard avec le code source de haut niveau et l'assembleur) et -L (conserver les symboles locaux dans la table des symboles).

Généralement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote de compilation GNU avec l'option -v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.)

OPTIONS

@file
Lire les options de ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas ou ne peut pas être lu, l'option sera traitée littéralement et non supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espace peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le file peut lui-même contenir d'autres options @file ; toutes ces options seront traitées récursivement.

-a[cdghilmns]
Activer les listages, de diverses manières:
-ac
omettre les conditionnels faux
-ad
omettre les directives de débogage
-ag
omettre les lignes de code assembleur
inclure des informations générales, telles que la version et les options passées
-ah
inclure le code source de haut niveau
-al
inclure l'assembleur
-ali
inclure l'assembleur avec ginsn
-am
inclure les expansions de macros
-an
omettre le traitement des formes
-as
inclure les symboles
=fichier
définir le nom du fichier de liste

Vous pouvez combiner ces options ; par exemple, utilisez -aln pour une liste d'assembleur sans traitement des formes. L'option =fichier, si elle est utilisée, doit être la dernière. En soi, -a est équivalent à -ahls.

--alternate
Commencer en mode macro alternatif.
--compress-debug-sections
Compresser les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens linkers et utilitaires de fichiers objet. Notez que si la compression rendait une section donnée *plus grande*, elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent la compression des sections de débogage DWARF. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format obsolète zlib-gnu. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Notez que si la compression rendait une section *plus grande*, elle n'est ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement la valeur par défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour outrepasser ce comportement.
-D
Activer le débogage dans les backends spécifiques à la cible, si supporté. Sinon, ignoré. Même si ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrer les informations de débogage les décrivant comme dans nouveau à la place.
--defsym sym=valeur
Définir le symbole sym à la valeur valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un préfixe 0x indique une valeur hexadécimale, et un préfixe 0 indique une valeur octale. La valeur du symbole peut être remplacée dans un fichier source via l'utilisation d'une pseudo-instruction ".set".
--dump-config
Affiche la configuration de l'assembleur puis se termine.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". La valeur par défaut peut être contrôlée par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour supporter plusieurs configurations cibles différentes, cette option peut être utilisée pour sélectionner la forme désirée.
-f
"rapide"---sauter le prétraitement des espaces et des commentaires (supposer que la source est une sortie de compilateur).
-g
--gen-debug
Générer des informations de débogage pour chaque ligne source de l'assembleur en utilisant le format de débogage préféré par la cible. Cela signifie actuellement soit STABS, ECOFF ou DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et ".debug_line" n'est émise que lorsque le fichier assembleur n'en génère pas une lui-même.
--gstabs
Générer des informations de débogage stabs pour chaque ligne de l'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer.
--gstabs+
Générer des informations de débogage stabs pour chaque ligne de l'assembleur, avec des extensions GNU que seul gdb peut probablement gérer, et qui pourraient faire planter ou refuser de lire votre programme à d'autres débogueurs. Cela peut aider au débogage du code assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Générer des informations de débogage DWARF2 pour chaque ligne de l'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer. Notez que cette option n'est supportée que par certaines cibles, pas toutes.
--gdwarf-3
Cette option est la même que l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 3 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-4
Cette option est la même que l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 4 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-5
Cette option est la même que l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 5 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, créez une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code appelée .text.func aura ses informations de ligne de débogage placées dans une section appelée .debug_line.text.func. Si la section de code s'appelle simplement .text, alors la section de ligne de débogage s'appellera toujours simplement .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'information communes DWARF (CIE) est produite. Lorsque ce drapeau n'est pas spécifié, la valeur par défaut est la version 1, bien que certaines cibles puissent modifier cette valeur par défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attribut GNU Build s'il n'y en a pas dans les sources d'entrée. La valeur par défaut peut être contrôlée par l'option de configuration --enable-generate-build-notes.
--gsframe
--gsframe
Crée une section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Supporté pour la compatibilité de ligne de commande avec d'autres assembleurs.
--help
Affiche un résumé des options de ligne de commande et quitte.
--target-help
Affiche un résumé de toutes les options spécifiques à la cible et quitte.
--info
Ne pas supprimer les messages d'information.
--no-info
Supprimer les messages d'information.
-I rep
Ajoute le répertoire rep à la liste de recherche pour les directives ".include".
-J
Ne pas avertir en cas de dépassement signé.
-K
Émettre des avertissements lorsque les tables de différence sont modifiées pour des déplacements longs.
-L

Cette option spécifie la syntaxe de l'instruction lors du traitement des instructions. Les directives ".att_syntax" et ".intel_syntax" auront la priorité.

Cette option spécifie que les registres ne nécessitent pas de préfixe %. Les directives ".att_syntax" et ".intel_syntax" auront la priorité.
-madd-bnd-prefix
Cette option force l'assembleur à ajouter le préfixe BND à tous les sauts, même si un tel préfixe n'était pas explicitement spécifié dans le code source.
-mno-shared
Sur cible ELF, l'assembleur optimise normalement les décalages non-PLT vers des cibles de branchement globales définies et non-faibles avec la visibilité par défaut. L'option -mshared indique à l'assembleur de générer du code qui peut aller dans une bibliothèque partagée où toutes les cibles de branchement globales non-faibles avec visibilité par défaut peuvent être préemptées. Le code résultant est légèrement plus volumineux. Cette option n'affecte que la gestion des instructions de branchement.
-mbig-obj
Sur cible PE/COFF, cette option force l'utilisation du format de fichier objet volumineux, qui permet plus de 32768 sections.
-momit-lock-prefix=no
-momit-lock-prefix=yes
Ces options contrôlent comment l'assembleur doit encoder le préfixe lock. Cette option est destinée à contourner les processeurs qui échouent avec le préfixe lock. Cette option ne peut être utilisée en toute sécurité qu'avec des ordinateurs monocœur, monothread. -momit-lock-prefix=yes omettra tous les préfixes lock. -momit-lock-prefix=no encodera le préfixe lock comme d'habitude, ce qui est la valeur par défaut.
-mfence-as-lock-add=no
-mfence-as-lock-add=yes
Ces options contrôlent comment l'assembleur doit encoder lfence, mfence et sfence. -mfence-as-lock-add=yes encodera lfence, mfence et sfence comme lock addl $0x0, (%rsp) en mode 64 bits et lock addl $0x0, (%esp) en mode 32 bits. -mfence-as-lock-add=no encodera lfence, mfence et sfence comme d'habitude, ce qui est la valeur par défaut.
-mrelax-relocations=no
-mrelax-relocations=yes
Ces options contrôlent si l'assembleur doit générer des décalages de relaxation (R_386_GOT32X en mode 32 bits, ou R_X86_64_GOTPCRELX et R_X86_64_REX_GOTPCRELX en mode 64 bits). -mrelax-relocations=yes générera des décalages de relaxation. -mrelax-relocations=no ne générera pas de décalages de relaxation. La valeur par défaut peut être contrôlée par l'option de configuration --enable-x86-relax-relocations.
-mtls-check=no
-mtls-check=yes
Ces options contrôlent si l'assembleur vérifie les décalages TLS (Thread-Local Storage). -mtls-check=yes vérifiera les décalages TLS. -mtls-check=no ne vérifiera pas les décalages TLS. La valeur par défaut peut être contrôlée par l'option de configuration --enable-x86-tls-check.
-malign-branch-boundary=NUM
Cette option contrôle comment l'assembleur doit aligner les sauts avec des préfixes de segment ou des NOPs. NUM doit être une puissance de 2. Il doit être 0 ou au moins 16. Les sauts seront alignés sur une frontière de NUM octets. -malign-branch-boundary=0, qui est la valeur par défaut, n'aligne pas les sauts.
-malign-branch=TYPE[+TYPE...]
Cette option spécifie les types de sauts à aligner. TYPE est une combinaison de jcc (aligne les sauts conditionnels), fused (aligne les sauts conditionnels fusionnés), jmp (aligne les sauts inconditionnels), call (aligne les appels), ret (aligne les retours), indirect (aligne les sauts et appels indirects). La valeur par défaut est -malign-branch=jcc+fused+jmp.
-malign-branch-prefix-size=NUM
Cette option spécifie le nombre maximum de préfixes sur une instruction pour aligner les sauts. NUM doit être compris entre 0 et 5. La valeur par défaut de NUM est 5.
-mbranches-within-32B-boundaries
Cette option aligne les sauts conditionnels, les sauts conditionnels fusionnés et les sauts inconditionnels sur une frontière de 32 octets avec jusqu'à 5 préfixes de segment sur une instruction. Elle est équivalente à -malign-branch-boundary=32 -malign-branch=jcc+fused+jmp -malign-branch-prefix-size=5. La valeur par défaut n'aligne pas les sauts.
-mlfence-after-load=no
-mlfence-after-load=yes
Ces options contrôlent si l'assembleur doit générer un lfence après les instructions de chargement. -mlfence-after-load=yes générera un lfence. -mlfence-after-load=no ne générera pas de lfence, ce qui est la valeur par défaut.
-mlfence-before-indirect-branch=none
-mlfence-before-indirect-branch=all
-mlfence-before-indirect-branch=register
-mlfence-before-indirect-branch=memory
Ces options contrôlent si l'assembleur doit générer un lfence avant les instructions de branchement indirect proche. -mlfence-before-indirect-branch=all générera un lfence avant un branchement indirect proche via registre et émettra un avertissement avant un branchement indirect proche via mémoire. Il définit également implicitement -mlfence-before-ret=shl lorsqu'il n'y a pas d'option explicite -mlfence-before-ret=. -mlfence-before-indirect-branch=register générera un lfence avant un branchement indirect proche via registre. -mlfence-before-indirect-branch=memory émettra un avertissement avant un branchement indirect proche via mémoire. -mlfence-before-indirect-branch=none ne générera pas de lfence ni n'émettra d'avertissement, ce qui est la valeur par défaut. Notez que lfence ne sera pas généré avant un branchement indirect proche via registre avec -mlfence-after-load=yes car lfence sera généré après le chargement du registre cible du branchement.
-mlfence-before-ret=none
-mlfence-before-ret=shl
-mlfence-before-ret=or
-mlfence-before-ret=yes
-mlfence-before-ret=not
Ces options contrôlent si l'assembleur doit générer un lfence avant un retour. -mlfence-before-ret=or générera une instruction `or` avec lfence. -mlfence-before-ret=shl/yes générera une instruction `shl` avec lfence. -mlfence-before-ret=not générera une instruction `not` avec lfence. -mlfence-before-ret=none ne générera pas de lfence, ce qui est la valeur par défaut.

-mintel64
Cette option spécifie que l'assembleur doit accepter uniquement les jeux d'instructions AMD64 ou Intel64 en mode 64 bits. La valeur par défaut est d'accepter les jeux d'instructions courants, Intel64 uniquement et AMD64.
-O0 | -O | -O1 | -O2 | -Os
Optimise l'encodage des instructions avec une taille d'instruction plus petite. -O et -O1 encodent les instructions de chargement de registre 64 bits avec un immédiat 64 bits comme des instructions de chargement de registre 32 bits avec des immédiats 31 bits ou 32 bits, encodent 64
- instructions de nettoyage de registres 16 bits avec instructions de nettoyage de registres 32 bits, coder les instructions de nettoyage de registres vectoriels VEX/EVEX 256 bits/512 bits avec les instructions de nettoyage de registres vectoriels VEX 128 bits, coder les instructions de chargement/stockage de registres vectoriels EVEX 128 bits/256 bits avec les instructions de chargement/stockage de registres vectoriels VEX, et coder les instructions logiques entières vectorielles EVEX 128 bits/256 bits avec les instructions logiques entières vectorielles VEX 128 bits/256 bits.

-O2 inclut l'optimisation -O1 plus le codage des instructions de nettoyage de registres vectoriels EVEX 256 bits/512 bits avec les instructions de nettoyage de registres vectoriels EVEX 128 bits. En mode 64 bits, les instructions codées VEX avec des opérandes source commutatives auront également leurs opérandes source échangés si cela permet d'utiliser la forme de préfixe VEX à 2 octets au lieu de celle à 3 octets. Certaines formes de AND ainsi que OR avec le même opérande (registre) spécifié deux fois seront également modifiées en TEST.

-Os inclut l'optimisation -O2 plus le codage des tests de registres 16 bits, 32 bits et 64 bits avec un immédiat comme test de registre 8 bits avec un immédiat. -O0 désactive cette optimisation.

La valeur par défaut est --trampolines.
--abi-windowed | --abi-call0
Choisit la balise ABI écrite dans la section ".xtensa.info". La balise ABI indique l'ABI du code d'assemblage. Un avertissement est émis par l'éditeur de liens lors d'une tentative de lier des fichiers objets avec des balises ABI incohérentes. L'ABI par défaut est choisie par la configuration du noyau Xtensa.

Les options suivantes sont disponibles lorsque as est configuré pour un processeur Z80.

@chapter Fonctionnalités spécifiques au Z80

Options de ligne de commande

-march=CPU[-EXT...][+EXT...]
Cette option spécifie le processeur cible. L'assembleur émettra un message d'erreur si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur le processeur cible. Les noms de processeurs suivants sont reconnus : "z80", "z180", "ez80", "gbz80", "z80n", "r800". En plus de l'ensemble d'instructions de base, l'assembleur peut être informé d'accepter certaines extensions mnémoniques. Par exemple, "-march=z180+sli+infc" étend le z180 avec les instructions SLI et IN F,(C). Les extensions suivantes sont actuellement prises en charge : "full" (toutes les instructions connues), "adl" (mode CPU ADL par défaut, eZ80 uniquement), "sli" (instruction connue sous le nom de SLI, SLL ou SL1), "xyhl" (instructions avec les moitiés des registres d'index : IXL, IXH, IYL, IYH), "xdcb" (instructions comme RotOp (II+d),R et BitOp n,(II+d),R), "infc" (instruction IN F,(C) ou IN (C)), "outc0" (instruction OUT (C),0). Notez que plutôt que d'étendre un jeu d'instructions de base, les mnémoniques d'extension commençant par "-" révoquent la fonctionnalité respective : "-march=z80-full+xyhl" supprime d'abord toutes les extensions par défaut et ajoute uniquement la prise en charge des moitiés de registres d'index.

Si cette option n'est pas spécifiée, alors "-march=z80+xyhl+infc" est supposée.

-local-prefix=prefix
Marque toutes les étiquettes avec le préfixe spécifié comme locales. Mais une telle étiquette peut être marquée comme globale explicitement dans le code. Cette option ne modifie pas le préfixe d'étiquette locale par défaut ".L", elle en ajoute juste un nouveau.
-colonless
Accepte les étiquettes sans deux-points. Tous les symboles au début d'une ligne sont traités comme des étiquettes.
-sdcc
Accepte le code d'assembleur produit par SDCC.
-fp-s=FORMAT
Format des nombres à virgule flottante simple précision. Par défaut : ieee754 (32 bits).
-fp-d=FORMAT
Format des nombres à virgule flottante double précision. Par défaut : ieee754 (64 bits).
