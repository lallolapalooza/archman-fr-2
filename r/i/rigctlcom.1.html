RIGCTLCOM(1) Utilitaires Hamlib RIGCTLCOM(1)

NOM

rigctlcom - Port COM en passthru comme émulateur TS-2000 vers votre radio

SYNTAXE

rigctlcom [-hlLuV] [-m id] [-r périphérique] [-R périphérique] [-p périphérique] [-d périphérique] [-P type] [-D type] [-s débit] [-S débit] [-c id] [-C param=val] [-B] [-v[-Z]]

DESCRIPTION

Permet aux programmes qui peuvent se connecter au TS-2000 via le port COM d'utiliser des radios Hamlib ou FLRig. Plusieurs programmes peuvent se connecter à la radio via FLRig ou rigctld.

Les ports série/COM virtuels doivent être configurés au préalable à l'aide de socat(1) ou d'un outil similaire sur les systèmes POSIX (BSD, Linux, OS/X). Sur Microsoft Windows, les utilitaires disponibles sont com0com, Free Virtual Serial Ports, ou VPSD.

Veuillez signaler les bugs et fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (‘-’) nécessitent un ‘=’ entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --model=id
Sélectionne le numéro du modèle de la radio.
Voir la liste des modèles (utilisez “rigctlcom -l”).
Note : rigctlcom (ou un logiciel tiers utilisant l'API C) utilisera le modèle de radio 2 pour NET rigctl (communication avec rigctld).
-r, --rig-file=périphérique
Utilise périphérique comme nom de fichier du port connecté à la radio.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
La chaîne spéciale “uh-rig” peut être fournie pour activer le support des périphériques micro-ham.
-R, --rig-file2=périphérique
Utilise périphérique comme nom de fichier de l'un des ports COM virtuels -- votre programme se connectera à l'autre port COM de la paire virtuelle.
Les ports série virtuels sur les systèmes POSIX peuvent être créés avec socat(1) :

$ socat -d -d pty,raw,echo=0 pty,raw,echo=0

Voir cette réponse Stackoverflow pour l'utilisation de socat.
Sur Microsoft Windows, les utilitaires disponibles sont com0com, Free Virtual Serial Ports ou VPSD (voir la section DESCRIPTION ci-dessus pour les liens WWW).
-p, --ptt-file=périphérique
Utilise périphérique comme nom de fichier du périphérique Push-To-Talk en utilisant un fichier périphérique comme décrit ci-dessus.
-d, --dcd-file=périphérique
Utilise périphérique comme nom de fichier du périphérique Data Carrier Detect en utilisant un fichier périphérique comme décrit ci-dessus.
-P, --ptt-type=type
Utilise le type de périphérique Push-To-Talk.
Les types pris en charge sont ‘RIG’ (commande CAT), ‘DTR’, ‘RTS’, ‘PARALLEL’, ‘NONE’, remplaçant le type PTT défini dans le backend de la radio.
Certains effets secondaires de cette commande sont que lorsque le type est défini sur DTR, l'état PTT lu provient du frontend Hamlib, et non de la radio. Lorsqu'il est défini sur NONE, l'état PTT ne peut être ni lu ni défini, même si le backend de la radio prend en charge la lecture/définition de l'état PTT à partir de la radio.
-D, --dcd-type=type
Utilise le type de périphérique Data Carrier Detect.
Les types pris en charge sont ‘RIG’ (commande CAT), ‘DSR’, ‘CTS’, ‘CD’, ‘PARALLEL’, ‘NONE’.
-s, --serial-speed=débit
Définit la vitesse série sur le débit.
Utilise la vitesse série maximale des capacités du backend de la radio (définie par -m ci-dessus) par défaut.
-S, --serial-speed2=débit
Définit la vitesse série sur le débit pour le port COM virtuel (voir -R).
Utilise la vitesse série maximale des capacités du backend de la radio (définie par -m ci-dessus) par défaut.
-c, --civaddr=id
Utilise id comme adresse CI-V pour communiquer avec la radio.
Utile uniquement pour les radios Icom et certains Ten-Tec.
Note : L'id est en notation décimale, sauf s'il est précédé de 0x, auquel cas il est hexadécimal.
-L, --show-conf
Liste tous les paramètres de configuration de la radio définie avec -m ci-dessus.
-C, --set-conf=param=val[,param=val]
Définit le(s) paramètre(s) de configuration de la radio, par exemple stop_bits=2.
Utilisez l'option -L ci-dessus pour obtenir la liste des paramètres de configuration d'un numéro de modèle donné.
-u, --dump-caps
Affiche les capacités de la radio définie avec -m ci-dessus et quitte.
-l, --list
Liste tous les numéros de modèles définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être parcourue en faisant défiler vers le haut/bas avec Maj-PagePréc/Maj-PageSuiv, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou de la fenêtre cmd sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple “rigctl -l | more”.
-n, --no-restore-ai
rigctl restaure l'état de l'information automatique (AI) sur la radio contrôlée.
Si cela n'est pas souhaité, par exemple si vous utilisez rigctl pour activer ou désactiver le mode AI, passez cette option.
-B, --mapa2b
Mappe set_freq sur VFOA vers VFOB au lieu de cela. Cela permet d'utiliser un skimmer CW avec la radio en mode split et cliquer sur une fréquence dans le skimmer CW définira VFOB sur la fréquence de transmission.
-v, --verbose
Active le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Z, --debug-time-stamps
Active les horodatages pour les messages de débogage.
À utiliser uniquement en combinaison avec l'option -v, car elle ne génère aucune sortie par elle-même.

DIAGNOSTICS

Les messages de diagnostic sont envoyés aux flux de sortie standard et d'erreur.

Le niveau de débogage peut être contrôlé en passant une ou plusieurs fois l'option -v. Par défaut, aucun niveau de débogage n'est défini.

Lorsque le niveau de débogage est supérieur à 0, les messages débogage sont envoyés au flux d'erreur standard.

   0        Pas de débogage.
   1        Erreurs d'initialisation et de configuration.
   2        Messages de niveau supérieur, y compris les erreurs.
   3        Informations de niveau inférieur, y compris les avertissements.
   4        Messages détaillés, y compris les appels aux fonctions de Hamlib.
   5        Messages très détaillés, y compris les détails des données transmises/reçues.
   6        Messages de débogage des trames de données de la radio.

rigctlcom(1) - Hamlib

NOM

rigctlcom - utilitaire de communication pour rigctl

SYNTAXIS

rigctlcom [options]

DESCRIPTION

Cet utilitaire est un pont entre le serveur de communications de Hamlib, rigctld, et un autre programme, typiquement un autre logiciel de radiocommunication qui ne peut pas utiliser directement Hamlib. Il écoute sur un port réseau, généralement le port 4572 par défaut, et fait le relais des commandes entre les clients connectés et le serveur rigctld, qui lui-même contrôle le transceiver.

Il permet donc à des logiciels comme N1MM Logger+ de contrôler un transceiver via rigctld et un backend Hamlib spécifique, même si ces logiciels ne disposent pas de leur propre support natif de Hamlib.

OPTIONS

-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rigctl et quitte.

Note: Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. Cela est plus susceptible de se produire avec les options --set-conf et --show-conf.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à afficher sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques de backend radio et peut être demandé par les développeurs.

STATUT DE SORTIE

rigctlcom se termine avec :

0
si toutes les opérations se sont terminées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib.

EXEMPLE

Démarrez rigctlcom avec FLRig comme modèle Hamlib et les ports série virtuels COM9/COM10, par exemple, N1MM Logger+ se connectant à COM10 et utilisant l'émulateur TS-2000 connecté à COM9 (suppose que le pipe de port série/COM virtuel a été créé avec l'utilitaire approprié comme décrit ci-dessus) :


$ rigctlcom -m 4 -R COM9 -S 115200

Le diagramme suivant montre le flux de communication qui permet à N1MM Logger+ de communiquer avec une radio connectée à Flrig :


Flrig -><- rigctlcom -> COM9 <- virt_port_pipe -> COM10 <- N1MM
