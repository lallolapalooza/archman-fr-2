DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objets. Les options contrôlent quelles informations spécifiques afficher. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent juste que leur programme compile et fonctionne.

fichier_objet... sont les fichiers objets à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objets membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes. Au moins une option de la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-headers
Si l'un des fichiers fichier_objet est une archive, affiche les informations d'en-tête de l'archive (dans un format similaire à ls -l). En plus des informations que vous pourriez lister avec ar tv, objdump -a montre le format du fichier objet de chaque membre de l'archive.
--adjust-vma=décalage
Lors de l'affichage des informations, ajoute d'abord décalage à toutes les adresses des sections. Ceci est utile si les adresses des sections ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise de sections à des adresses spécifiques lorsqu'on utilise un format qui ne peut pas représenter les adresses de section, comme a.out.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objets est nom_bfd. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche des informations sommaires des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer l'underscore initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
--recursion-limit
--no-recursion-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Les formats de mangling de noms permettant un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, provoquant un défaut de mémoire. La limite tente d'éviter cela en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Cela tente d'analyser les informations de format de débogage STABS stockées dans le fichier et de les imprimer en utilisant une syntaxe de type C. Si aucun débogage STABS n'a été trouvé, cette option revient à l'option -W pour imprimer toute information DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques de l'assembleur pour les instructions machine du fichier d'entrée. Cette option désassemble uniquement les sections censées contenir des instructions. Si l'argument optionnel symbole est donné, alors affiche les mnémoniques de l'assembleur à partir de symbole. Si symbole est un nom de fonction, la désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lors de la rencontre du symbole suivant. S'il n'y a pas de correspondance pour symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

-D
--disassemble-all

désassemble le contenu de toutes les sections non vides non-bss, pas seulement celles censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est activée, objdump suppose que tous les symboles présents dans une section de code se trouvent à la limite entre les instructions et refusera de désassembler au-delà d'une telle limite. Lorsque l'option -D est activée, cependant, cette supposition est supprimée. Cela signifie que la sortie de -d et -D peut différer si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur a également pour effet de forcer le désassembleur à décoder des morceaux de données trouvés dans les sections de code comme s'il s'agissait d'instructions.

Notez que si l'option --dwarf=follow-links est activée, les tables de symboles des fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

--no-addresses
Lors du désassemblage, n'affiche pas les adresses sur chaque ligne ni pour les symboles et les décalages de relocalisation. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, affiche l'adresse complète sur chaque ligne. C'est l'ancien format de désassemblage.
-EB
-EL
--endian={big|little}
Spécifie l'endianness des fichiers objet. Cela n'affecte que le désassemblage. Cela peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas les informations d'endianness, tels que les enregistrements S.
-f
--file-headers
Affiche des informations récapitulatives de l'en-tête général de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage de sections, chaque fois qu'un symbole est affiché, affiche également l'offset dans le fichier de la région de données qui est sur le point d'être vidée. Si des zéros sont ignorés, alors lorsque le désassemblage reprend, informe l'utilisateur du nombre de zéros ignorés et de l'offset dans le fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du vidage de sections, affiche l'offset dans le fichier de l'emplacement à partir duquel le vidage commence.
--file-start-context
Spécifie que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, le contexte est étendu au début du fichier.
-h
--section-headers
--headers
Affiche des informations récapitulatives des en-têtes de section du fichier objet.

Les segments de fichiers peuvent être relocalisés à des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata ou -Tbss de ld. Cependant, certains formats de fichiers objet, tels que a.out, ne stockent pas l'adresse de départ des segments de fichiers. Dans ces situations, bien que ld relocalise correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section de fichier ne peut pas afficher les adresses correctes. Au lieu de cela, il affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que dans certains cas, une section peut avoir à la fois les attributs READONLY et NOREAD définis. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump rapportera les deux car le réglage exact des bits de drapeau pourrait être important.

-H
--help
Affiche un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant toutes les architectures et formats d'objets disponibles pour être spécifiés avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non de débogage trouvées dans des fichiers d'informations de débogage séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom de fichier et les numéros de ligne source correspondant au code objet ou aux relocs affichés. Utile uniquement avec -d, -D ou -r.
-m machine
--architecture=machine
Spécifie l'architecture à utiliser lors du désassemblage des fichiers objet. Cela peut être utile lors du désassemblage de fichiers objet qui ne décrivent pas les informations d'architecture, tels que les enregistrements S. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par un deux-points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Cela peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il restreint le désassemblage aux seules instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information d'architecture, mais que l'on souhaite également désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Transmet des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plus d'une option de désassembleur, plusieurs options -M peuvent être utilisées ou regroupées dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'affichage des instructions DSP, spfp sélectionne l'affichage des instructions FP de précision simple FPX, dpfp sélectionne l'affichage des instructions FP de précision double FPX, quarkse_em sélectionne l'affichage des instructions spéciales QuarkSE-EM, fpuda sélectionne l'affichage des instructions d'assistance de précision double, fpus sélectionne l'affichage des instructions FP de précision simple FPU, tandis que fpud sélectionne l'affichage des instructions FP de précision double FPU. De plus, on peut choisir d'afficher tous les immédiats en hexadécimal en utilisant hex. Par défaut, les immédiats courts sont affichés en utilisant la représentation décimale, tandis que les valeurs immédiates longues sont affichées en hexadécimal.

cpu=... permet d'imposer un ISA particulier lors du désassemblage des instructions, remplaçant la valeur de -m ou ce qui se trouve dans le fichier ELF. Cela peut être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur les données de l'en-tête ELF privé pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois - seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option -mcpu=... de l'assembleur.

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner quel jeu de noms de registres est utilisé lors du désassemblage. Spécifier -M reg-names-std (par défaut) sélectionnera les noms de registres tels qu'utilisés dans la documentation de l'ensemble d'instructions d'ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. Spécifier -M reg-names-apcs sélectionnera le jeu de noms utilisé par le standard d'appel de procédure ARM, tandis que spécifier -M reg-names-raw utilisera simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de dénomination des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de dénomination du standard d'appel de procédure ARM/Thumb. (Soit avec les noms de registres normaux, soit avec les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Cela peut être utile lorsque l'on tente de désassembler du code Thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées comme l'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instructions doivent être générées comme commentaires dans le désassemblage en utilisant -M notes.

Pour x86, certaines des options dupliquent les fonctions du commutateur -m, mais permettent un contrôle plus fin.

"i386"

"intel"
"att"
Sélectionne entre le mode syntaxe Intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre l'ISA AMD64 et l'ISA Intel64.

"suffix"
Lorsque le mode AT&T est actif et aussi pour un ensemble limité d'instructions en mode Intel, demande au désassembleur d'afficher un suffixe mnémonique même lorsque le suffixe peut être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument -M raw sélectionne le désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont pris en charge. Ce sont : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle, et future. 32 et 64 modifient la sélection de CPU par défaut ou précédente, désactivant et activant respectivement les instructions 64 bits. En outre, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des capacités à une sélection de CPU précédente ou ultérieure. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations différentes ou des arguments différents, vous pourriez ne pas voir le désassemblage attendu. Si vous désassemblez sans spécifier de CPU, une valeur par défaut sera choisie à partir des informations extraites par BFD des en-têtes des fichiers objet, mais le résultat pourrait à nouveau ne pas être celui attendu.

Pour MIPS, cette option contrôle l'affichage des noms de mnémoniques d'instructions et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées :

"no-aliases"
Affiche le mnémonique d'instruction 'brut' au lieu d'un mnémonique d'instruction pseudo. C'est-à-dire, affiche 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassemble les instructions MSA.
"virt"
Désassemble les instructions ASE de virtualisation.
"xpa"
Désassemble les instructions eXtended Physical Address (XPA) ASE.
"gpr-names=ABI"
Affiche les noms des registres GPR (registres à usage général) appropriés pour l'ABI spécifié. Par défaut, les noms des GPR sont sélectionnés en fonction de l'ABI du binaire désassemblé.
"fpr-names=ABI"
Affiche les noms des registres FPR (registres flottants) appropriés pour l'ABI spécifié. Par défaut, les numéros des FPR sont affichés plutôt que les noms.
"cp0-names=ARCH"
Affiche les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"hwr-names=ARCH"
Affiche les noms des HWR (registres matériels, utilisés par l'instruction "rdhwr") appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des HWR sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"reg-names=ABI"
Affiche les noms des GPR et FPR appropriés pour l'ABI sélectionné.
"reg-names=ARCH"
Affiche les noms des registres spécifiques au CPU (noms des registres CP0 et HWR) appropriés pour le CPU ou l'architecture sélectionné.

Pour l'une des options listées ci-dessus, ABI ou ARCH peuvent être spécifiés comme numeric pour afficher des nombres plutôt que des noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier des adresses d'entrée de fonction avec -M entry:0xf00ba. Vous pouvez l'utiliser plusieurs fois pour désassembler correctement des fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme des dumps ROM). Dans ces cas, le masque d'entrée de fonction serait autrement décodé comme des instructions VAX, ce qui conduirait probablement au mauvais désassemblage du reste de la fonction.

Affiche les informations spécifiques au format du fichier objet. Les informations exactes affichées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est affichée.

--private=options
Affiche les informations spécifiques au format du fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (les listes d'options sont affichées avec l'aide).

-r
--reloc
Affiche les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.
-R
--dynamic-reloc
Affiche les entrées de relocalisation dynamiques du fichier. Ceci n'est pertinent que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.
-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non BSS sont affichées. Par défaut, toute section compressée sera affichée dans sa forme compressée. Afin de voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source intercalé avec le désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Typiquement, txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut de "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifie prefix à ajouter aux chemins absolus lorsqu'il est utilisé avec -S.
--prefix-strip=level
Indique combien de noms de répertoire initiaux doivent être retirés des chemins absolus codés en dur. Il n'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, affiche l'instruction en hexadécimal ainsi qu'en forme symbolique. C'est le comportement par défaut sauf lorsque --prefix-addresses est utilisé.
--no-show-raw-insn
Lors du désassemblage d'instructions, n'affiche pas les octets de l'instruction. C'est le comportement par défaut lorsque --prefix-addresses est utilisé.
--insn-width=width
Affiche width octets sur une seule ligne lors du désassemblage d'instructions.
--visualize-jumps[=color|=extended-color|=off]
Visualise les sauts qui restent à l'intérieur d'une fonction en dessinant des art ASCII entre l'adresse de début et l'adresse cible. L'argument optionnel =color ajoute de la couleur à la sortie en utilisant des couleurs de terminal simples. Alternativement, l'argument =extended-color ajoutera de la couleur en utilisant des couleurs 8 bits, mais celles-ci pourraient ne pas fonctionner sur tous les terminaux.

S'il est nécessaire de désactiver l'option visualize-jumps après qu'elle ait été précédemment activée, utilisez visualize-jumps=off.

--disassembler-color=extened|extended-color|extened-colour
Active ou désactive l'utilisation de la coloration syntaxique dans la sortie de désassemblage. La valeur par défaut

OPTION DE DÉBOGAGE

1 mai 2023

L'argument default applique une coloration par défaut au comportement de désassemblage.

L'argument auto applique une coloration si le comportement de désassemblage est configuré via une option de configuration.

Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et en fonction du terminal utilisé, la sortie colorée peut ne pas être réellement lisible.

L'argument on ajoute des couleurs à l'aide de couleurs de terminal simples.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

--dwarf[=rawline,=decodedline,=info,=abbrev,=pubnames,=aranges,=macro,=frames,=frames-interp,=str,=str-offsets,=loc,=Ranges,=pubtypes,=trace_info,=trace_abbrev,=trace_aranges,=gdb_index,=addr,=cu_index,=links,=follow-links]

Affiche le contenu de la section .debug_info. Remarque : la sortie de cette option peut également être limitée par l'utilisation des options --dwarf-depth et --dwarf-start.
"k"

Affiche le contenu des sections .gnu_debuglink, .gnu_debugaltlink et .debug_sup, si l'une d'entre elles est présente. Affiche également les liens vers des fichiers d'objets de débogage séparés (dwo), s'ils sont spécifiés par les attributs DW_AT_GNU_dwo_name ou DW_AT_dwo_name dans la section .debug_info.

"=follow-links"
Affiche le contenu des sections de débogage sélectionnées qui se trouvent dans des fichiers d'informations de débogage séparés et liés. Cela peut entraîner l'affichage de plusieurs versions de la même section de débogage si elle existe dans plus d'un fichier.

De plus, lors de l'affichage des attributs DWARF, si un formulaire est trouvé qui référence le fichier d'informations de débogage séparé, le contenu référencé sera également affiché.

Remarque : dans certaines distributions, cette option est activée par défaut. Elle peut être désactivée via l'option de débogage N. Le comportement par défaut peut être choisi lors de la configuration de binutils via les options --enable-follow-debug-links=yes ou --enable-follow-debug-links=no. Si celles-ci ne sont pas utilisées, le comportement par défaut est d'activer le suivi des liens de débogage.

Remarque : si la prise en charge du protocole debuginfod a été activée lors de la compilation des binutils, cette option inclura également une tentative de contact avec les serveurs debuginfod mentionnés dans la variable d'environnement DEBUGINFOD_URLS. Cela peut prendre du temps à résoudre. Ce comportement peut être désactivé via l'option de débogage =do-not-use-debuginfod.

--dwarf-depth=n
Limite le déchargement de la section ".debug_info" à n enfants. Ceci n'est utile qu'avec --debug-dump=info. La valeur par défaut est d'imprimer tous les DIE ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIE au niveau n ou plus profonds ne seront pas imprimés. La plage pour n est basée sur zéro.

--dwarf-start=n
Imprime uniquement les DIE commençant par le DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si cette option est spécifiée, elle supprimera l'impression de toute information d'en-tête et de tous les DIE avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront imprimés.

Ceci peut être utilisé conjointement avec --dwarf-depth.

--dwarf-check
Active des vérifications supplémentaires de la cohérence des informations Dwarf.
--ctf[=section]
Affiche le contenu de la section CTF spécifiée. Les sections CTF elles-mêmes contiennent de nombreuses sous-sections, qui sont toutes affichées dans l'ordre.

Par défaut, affiche le nom de la section nommée .ctf, qui est le nom émis par ld.

--ctf-parent=member
Si la section CTF contient des types définis de manière ambiguë, elle contiendra une archive de nombreux dictionnaires CTF, héritant tous d'un dictionnaire contenant des types non ambigus. Ce membre est nommé par défaut .ctf, comme la section qu'il contient, mais il est possible de changer ce nom en utilisant la fonction "ctf_link_set_memb_name_changer" au moment de l'édition des liens. Lors de l'examen d'archives CTF créées par un éditeur de liens qui utilise le changeur de nom pour renommer le membre d'archive parent, --ctf-parent peut être utilisé pour spécifier le nom utilisé pour le parent.
--sframe[=section]
Affiche le contenu de la section SFrame spécifiée.

Par défaut, affiche le nom de la section nommée .sframe, qui est le nom émis par ld.

-G
--stabs
Affiche le contenu complet de toutes les sections demandées. Affiche le contenu des sections .stab, .stab.index et .stab.excl d'un fichier ELF. Ceci n'est utile que sur les systèmes (tels que Solaris 2.0) où les entrées de table de symboles de débogage ".stab" sont transportées dans une section ELF. Dans la plupart des autres formats de fichiers, les entrées de table de symboles de débogage sont entrelacées avec les symboles de liaison et sont visibles dans la sortie --syms.
--start-address=address
Commence l'affichage des données à l'adresse spécifiée. Cela affecte la sortie des options -d, -r et -s.
--stop-address=address
Arrête l'affichage des données à l'adresse spécifiée. Cela affecte la sortie des options -d, -r et -s.
-t
--syms
Imprime les entrées de la table des symboles du fichier. Ceci est similaire aux informations fournies par le programme nm, bien que le format d'affichage soit différent. Le format de la sortie dépend du format du fichier déchargé, mais il existe deux types principaux. L'un ressemble à ceci : 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

où le nombre entre crochets est le numéro du

 l'entrée dans la table des symboles, le numéro sec est le numéro de section, la valeur fl sont les bits de drapeau du symbole, le numéro ty est le type du symbole, le numéro scl est la classe de stockage du symbole et la valeur nx est le nombre d'entrées auxiliaires associées au symbole. Les deux derniers champs sont la valeur du symbole et son nom.

L'autre format de sortie courant, généralement observé avec les fichiers basés sur ELF, ressemble à ceci :

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Ici, le premier nombre est la valeur du symbole (parfois appelée son adresse). Le champ suivant est en fait un ensemble de caractères et d'espaces indiquant les bits de drapeau qui sont définis pour le symbole. Ces caractères sont décrits ci-dessous. Vient ensuite la section à laquelle le symbole est associé ou *ABS* si la section est absolue (c'est-à-dire non liée à une section), ou *UND* si la section est référencée dans le fichier en cours de vidage, mais non définie là.

Après le nom de la section vient un autre champ, un nombre, qui pour les symboles communs est l'alignement et pour les autres symboles est la taille. Enfin, le nom du symbole est affiché.

Les caractères de drapeau sont divisés en 7 groupes comme suit :

"l"
"g"
"u"
"!"
Le symbole est local (l), global (g), global unique (u), ni global ni local (un espace) ou à la fois global et local (!). Un symbole peut être ni local ni global pour diverses raisons, par exemple, parce qu'il est utilisé pour le débogage, mais c'est probablement une indication d'un bug s'il est jamais à la fois local et global. Les symboles globaux uniques sont une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, le lieur dynamique s'assurera qu'il n'y a qu'un seul symbole de ce nom et type utilisé dans tout le processus.
"w"
Le symbole est faible (w) ou fort (un espace).
"C"
Le symbole dénote un constructeur (C) ou un symbole ordinaire (un espace).
"W"
Le symbole est un avertissement (W) ou un symbole normal (un espace). Le nom d'un symbole d'avertissement est un message à afficher si le symbole qui suit le symbole d'avertissement est jamais référencé.
"I"
"i"
Le symbole est une référence indirecte à un autre symbole (I), une fonction à évaluer pendant le traitement des relocations (i) ou un symbole normal (un espace).
"d"
"D"
Le symbole est un symbole de débogage (d) ou un symbole dynamique (D) ou un symbole normal (un espace).
"F"
"f"
"O"
Le symbole est le nom d'une fonction (F) ou d'un fichier (f) ou d'un objet (O) ou simplement d'un symbole normal (un espace).
-T
--dynamic-syms
Affiche les entrées de la table des symboles dynamiques du fichier. Ceci n'est significatif que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Ceci est similaire aux informations fournies par le programme nm lorsqu'il reçoit l'option -D (--dynamic).

Le format de sortie est similaire à celui produit par l'option --syms, à l'exception d'un champ supplémentaire inséré avant le nom du symbole, donnant les informations de version associées au symbole. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées au symbole, elle est affichée telle quelle, sinon elle est placée entre parenthèses.

--special-syms
Lors de l'affichage des symboles, inclure ceux que la cible considère comme spéciaux d'une manière ou d'une autre et qui n'intéresseraient normalement pas l'utilisateur.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multibytes encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), aucun traitement spécial ne leur est appliqué. L'option --unicode=locale affiche la séquence dans la locale actuelle, qui peut ou non les prendre en charge. Les options --unicode=hex et --unicode=invalid les affichent sous forme de séquences d'octets hexadécimaux entourées d'accolades ou de crochets.

L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en évidence en rouge (si pris en charge par le périphérique de sortie). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

-V
--version
Affiche le numéro de version de objdump et quitte.
-x
--all-headers
Affiche toutes les informations d'en-tête disponibles, y compris la table des symboles et les entrées de relocalisation. L'utilisation de -x équivaut à spécifier tous les -a -f -h -p -r -t.
-w
--wide
Formate certaines lignes pour les périphériques de sortie ayant plus de 80 colonnes. Ne tronque pas non plus les noms de symboles lorsqu'ils sont affichés.
-z
--disassemble-zeroes
Normalement, la sortie de désassemblage ignore les blocs de zéros. Cette option demande au désassembleur de désassembler ces blocs, comme tout autre donnée.
-Z
--decompress
L'option -Z est destinée à être utilisée conjointement avec l'option -s. Elle demande à objdump de décompresser toutes les sections compressées avant d'afficher leur contenu.
@file
Lit les options de ligne de commande à partir de file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure d'un antislash. Le file peut lui-même contenir d'autres options @file ; ces options seront traitées récursivement.
