DESCRIPTION

GNU as is really a family of assemblers. If you use (or have used) the GNU assembler on one architecture, you should find a fairly similar environment when you use it on another architecture. Each version has much in common with the others, including object file formats, most assembler directives (often called pseudo-ops) and assembler syntax.

as is primarily intended to assemble the output of the GNU C compiler "gcc" for use by the linker "ld". Nevertheless, we've tried to make as assemble correctly everything that other assemblers for the same machine would assemble. Any exceptions are documented explicitly. This doesn't mean as always uses the same syntax as another assembler for the same architecture; for example, we know of several incompatible versions of 680x0 assembly language syntax.

Each time you run as it assembles exactly one source program. The source program is made up of one or more files. (The standard input is also a file.)

You give as a command line that has zero or more input file names. The input files are read (from left file name to right). A command-line argument (in any position) that has no special meaning is taken to be an input file name.

If you give as no file names it attempts to read one input file from the as standard input, which is normally your terminal. You may have to type ctl-D to tell as there is no more program to assemble.

Use -- if you need to explicitly name the standard input file in your command line.

If the source is empty, as produces a small, empty object file.

as may write warnings and error messages to the standard error file (usually your terminal). This should not happen when a compiler runs as automatically. Warnings report an assumption made so that as could keep assembling a flawed program; errors report a grave problem that stops the assembly.

If you are invoking as via the GNU C compiler, you can use the -Wa option to pass arguments through to the assembler. The assembler arguments must be separated from each other (and the -Wa) by commas. For example:

gcc -c -g -O -Wa,-alh,-L file.c

This passes two options to the assembler: -alh (emit a listing to standard output with high-level and assembly source) and -L (retain local symbols in the symbol table).

Usually you do not need to use this -Wa mechanism, since many compiler command-line options are automatically passed to the assembler by the compiler. (You can call the GNU compiler driver with the -v option to see precisely what options it passes to each compilation pass, including the assembler.)

OPTIONS

@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.

-a[cdghilmns]
Turn on listings, in any of a variety of ways:
-ac
omit false conditionals
-ad
omit debugging directives
-ag
include general information, like as version and options passed
-ah
include high-level source code

The options can be combined. For example, -a is equivalent to -agh. The default for all these options is off.

DESCRIPTION

GNU as is really a family of assemblers. If you use (or have used) the GNU assembler on one architecture, you should find a fairly similar environment when you use it on another architecture. Each version has much in common with the others, including object file formats, most assembler directives (often called pseudo-ops) and assembler syntax.

as is primarily intended to assemble the output of the GNU C compiler "gcc" for use by the linker "ld". Nevertheless, we've tried to make as assemble correctly everything that other assemblers for the same machine would assemble. Any exceptions are documented explicitly. This doesn't mean as always uses the same syntax as another assembler for the same architecture; for example, we know of several incompatible versions of 680x0 assembly language syntax.

Each time you run as it assembles exactly one source program. The source program is made up of one or more files. (The standard input is also a file.)

You give as a command line that has zero or more input file names. The input files are read (from left file name to right). A command-line argument (in any position) that has no special meaning is taken to be an input file name.

If you give as no file names it attempts to read one input file from the as standard input, which is normally your terminal. You may have to type ctl-D to tell as there is no more program to assemble.

Use -- if you need to explicitly name the standard input file in your command line.

If the source is empty, as produces a small, empty object file.

as may write warnings and error messages to the standard error file (usually your terminal). This should not happen when a compiler runs as automatically. Warnings report an assumption made so that as could keep assembling a flawed program; errors report a grave problem that stops the assembly.

If you are invoking as via the GNU C compiler, you can use the -Wa option to pass arguments through to the assembler. The assembler arguments must be separated from each other (and the -Wa) by commas. For example:

gcc -c -g -O -Wa,-alh,-L file.c

This passes two options to the assembler: -alh (emit a listing to standard output with high-level and assembly source) and -L (retain local symbols in the symbol table).

Usually you do not need to use this -Wa mechanism, since many compiler command-line options are automatically passed to the assembler by the compiler. (You can call the GNU compiler driver with the -v option to see precisely what options it passes to each compilation pass, including the assembler.)

OPTIONS

@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backlash) may be included by prefixing the character to be included with a backlash. The file may itself contain additional @file options; any such options will be processed recursively.

-a[cdghilmns]
Turn on listings, in any of a variety of ways:
-ac
omit false conditionals
-ad
omit debugging directives
-ag
include general information, like as version and options passed
-ah
include high-level source code

The options can be combined. For example, -a is equivalent to -agh. The default for all these options is off.

The listing file is written to standard error, or, if the -o option is used to name an output file, then the listing file is written to standard output. Use -al to produce an assembly listing file, writing it to standard output.

-A
This is an assembler directive, not an option. It is recognized by GAS, but not by as. It is recognized and ignored by as. It is also recognized and ignored by gas.
-b
Output in binary format, not object file format.
-c
Do not discard section information from object files.
-d
Output in COFF format, not object file format.
-e
Set the entry point address to symbol.
-f
Output in the default format for the target.
-g
Output in a.out format, not object file format.
-h
Output in H8/300 format, not object file format.
-i
Output in IEEE format, not object file format.
-k
Output in Omron format, not object file format.
-l
Output in elf32-little, elf32-big, elf64-little, elf64-big, elfxx-little, or elfxx-big format, not object file format.
-m
A machine-dependent option. This is the most commonly used option. The available options depend on the target machine.

Sélectionne l'ISA de base, comme spécifié par ISA. Par exemple, -march=rv32ima. Si cette option et les attributs d'architecture ne sont pas définis, l'assembleur vérifiera le réglage de configuration par défaut --with-arch=ISA.
-misa-spec=ISAspec
Sélectionne la version de la spécification ISA par défaut. Si la version de l'ISA n'est pas définie par -march, alors l'assembleur aide à définir la version selon la spécification choisie par défaut. Si cette option n'est pas définie, l'assembleur vérifiera le réglage de configuration par défaut --with-isa-spec=ISAspec.

-mabi=ABI
Sélectionne l'ABI, qui peut être "ilp32" ou "lp64", éventuellement suivi de "f", "d" ou "q" pour indiquer la convention d'appel en virgule flottante simple précision, double précision ou quadruple précision, ou aucune ou "e" pour indiquer la convention d'appel en virgule flottante logicielle ("e" indique une ABI RVE en virgule flottante logicielle).
-mrelax

-mno-relax

-march-attr
Génère le contenu par défaut pour la section d'attributs riscv elf si les directives .attribute ne sont pas définies. Cette section est utilisée pour enregistrer les informations dont un lieur ou un chargeur d'exécution a besoin pour vérifier la compatibilité. Ces informations incluent la chaîne ISA, l'exigence d'alignement de la pile, les accès mémoire non alignés et la version majeure, mineure et de révision de la spécification privilégiée.
-mno-arch-attr

-mcsr-check
Active la vérification des CSR pour les CSR dépendant de l'ISA et les CSR en lecture seule. Les CSR dépendant de l'ISA ne sont valides que lorsque l'ISA spécifique est définie. Les CSR en lecture seule ne peuvent pas être écrits par les instructions CSR.
-mno-csr-check
N'effectue pas de vérification des CSR.

--text-section-literals | --no-text-section-literals
Contrôle le traitement des pools de littéraux. Le défaut est --no-text-section-literals, qui place les littéraux dans des sections séparées du fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --text-section-literals, les littéraux sont entrelacés dans la section de texte afin de les maintenir aussi proches que possible de leurs références. Cela peut être nécessaire pour de grands fichiers d'assemblage, où les littéraux seraient autrement hors de portée des instructions "L32R" dans la section de texte. Les littéraux sont groupés en pools suite aux directives ".literal_position" ou précédant les instructions "ENTRY". Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément.
--auto-litpools | --no-auto-litpools
Contrôle le traitement des pools de littéraux. Le défaut est --no-auto-litpools, qui en l'absence de --text-section-literals place les littéraux dans des sections séparées du fichier de sortie. Cela permet de placer le pool de littéraux dans une RAM/ROM de données. Avec --auto-litpools, les littéraux sont entrelacés dans la section de texte afin de les maintenir aussi proches que possible de leurs références, les directives explicites ".literal_position" ne sont pas requises. Cela peut être nécessaire pour des fonctions très grandes, où un seul pool de littéraux au début de la fonction peut ne pas être accessible par les instructions "L32R" à la fin. Ces options n'affectent que les littéraux référencés via des instructions "L32R" relatives au PC ; les littéraux pour les instructions "L32R" en mode absolu sont traités séparément. Lorsqu'ils sont utilisés conjointement avec --text-section-literals, --auto-litpools prend la priorité.
--absolute-literals | --no-absolute-literals
Indique à l'assembleur si les instructions "L32R" utilisent l'adressage absolu ou relatif au PC. Si le processeur inclut l'option d'adressage absolu, le défaut est d'utiliser des relocations "L32R" absolues. Sinon, seules les relocations "L32R" relatives au PC peuvent être utilisées.
--target-align | --no-target-align
Active ou désactive l'alignement automatique pour réduire les pénalités de branchement au détriment d'une certaine taille de code. Cette optimisation est activée par défaut. Notez que l'assembleur alignera toujours les instructions telles que "LOOP" qui ont des exigences d'alignement fixes.
--longcalls | --no-longcalls
Active ou désactive la transformation des instructions d'appel pour permettre des appels sur une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles d'appel peuvent potentiellement être hors de portée. Elle peut dégrader la taille du code et les performances, mais l'éditeur de liens peut généralement optimiser le surcoût inutile lorsqu'un appel se retrouve dans la portée. La valeur par défaut est --no-longcalls.
--transform | --no-transform
Active ou désactive toutes les transformations d'instructions Xtensa par l'assembleur, y compris la relaxation et l'optimisation. La valeur par défaut est --transform ; --no-transform ne doit être utilisé que dans les rares cas où les instructions doivent être exactement telles que spécifiées dans le code source de l'assemblage. L'utilisation de --no-transform entraîne des erreurs pour les opérandes d'instructions hors de portée.
--rename-section oldname=newname
Renomme la section oldname en newname. Cette option peut être utilisée plusieurs fois pour renommer plusieurs sections.
--trampolines | --no-trampolines
Active ou désactive la transformation des instructions de saut pour permettre des sauts sur une plus grande plage d'adresses. Cette option doit être utilisée lorsque les cibles de saut peuvent potentiellement être hors de portée. En l'absence de tels sauts, cette option n'affecte pas la taille du code ni les performances. La valeur par défaut est --trampolines.
--abi-windowed | --abi-call0
Choisit la balise ABI écrite dans la section ".xtensa.info". La balise ABI indique l'ABI du code d'assemblage. Un avertissement est émis par l'éditeur de liens en cas de tentative de lier des fichiers objet avec des balises ABI incohérentes. L'ABI par défaut est choisi par la configuration du cœur Xtensa.

@chapter Fonctionnalités dépendantes de Z80

Options de ligne de commande

-march=CPU[-EXT...][+EXT...]
Cette option spécifie le processeur cible. L'assembleur émettra un message d'erreur si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur le processeur cible. Les noms de processeurs suivants sont reconnus : "z80", "z180", "ez80", "gbz80", "z80n", "r800". En plus de l'ensemble d'instructions de base, l'assembleur peut être configuré pour accepter certaines extensions mnémoniques. Par exemple, "-march=z180+sli+infc" étend z180 avec les instructions SLI et IN F,(C). Les extensions suivantes sont actuellement prises en charge : "full" (toutes les instructions connues), "adl" (mode CPU ADL par défaut, eZ80 uniquement), "sli" (instruction connue sous le nom de SLI, SLL ou SL1), "xyhl" (instructions avec les moitiés des registres d'index : IXL, IXH, IYL, IYH), "xdcb" (instructions comme RotOp (II+d),R et BitOp n,(II+d),R), "infc" (instruction IN F,(C) ou IN (C)), "outc0" (instruction OUT (C),0). Notez qu'au lieu d'étendre un ensemble d'instructions de base, les mnémoniques d'extension commençant par "-" révoquent la fonctionnalité respective : "-march=z80-full+xyhl" supprime d'abord toutes les extensions par défaut et n'ajoute que la prise en charge des moitiés de registres d'index.

Si cette option n'est pas spécifiée, "-march=z80+xyhl+infc" est supposée.

-local-prefix=prefix
Marque toutes les étiquettes avec le préfixe spécifié comme locales. Cependant, de telles étiquettes peuvent être marquées comme globales explicitement dans le code. Cette option ne modifie pas le préfixe d'étiquette locale par défaut ".L", elle en ajoute simplement un nouveau.
-colonless
Accepte les étiquettes sans deux-points. Tous les symboles en début de ligne sont traités comme des étiquettes.
-sdcc
Accepte le code d'assemblage produit par SDCC.
-fp-s=FORMAT
Format des nombres à virgule flottante de précision simple. Par défaut : ieee754 (32 bits).
-fp-d=FORMAT
Format des nombres à virgule flottante de précision double. Par défaut : ieee754 (64 bits).
