Paquet: riscv32-elf-binutils

Licences: GPL

C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - Démangle les symboles C++ et Java

SYNTAXE

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|-R|--no-recurse-limit|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java permettent la surcharge de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction accepte des paramètres de types différents. Afin de pouvoir distinguer ces fonctions aux noms similaires, C++ et Java les codent en noms d'assembleur de bas niveau qui identifient de manière unique chaque version différente. Ce processus est connu sous le nom de mangling (ou brouillage). Le programme c++filt effectue le mappage inverse : il décode (démangle) les noms de bas niveau en noms de niveau utilisateur afin qu'ils puissent être lus.

Chaque mot alphanumérique (composé de lettres, chiffres, underscores, dollars ou points) vu dans l'entrée est un nom potentiellement brouillé. Si le nom est décodé en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot original est affiché. De cette manière, vous pouvez passer un fichier source d'assembleur complet, contenant des noms brouillés, à travers c++filt et voir le même fichier source contenant des noms démêlés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles depuis l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés être uniquement des noms brouillés et aucune vérification n'est effectuée pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et démêlera le nom en "f()", alors que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom brouillé qui le rend invalide). Cette commande cependant fonctionnera :

echo _Z1fv, | c++filt -n

et affichera "f(),", c'est-à-dire le nom démêlé suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, il est attendu qu'ils puissent faire partie d'un fichier source d'assembleur où il peut y avoir des caractères supplémentaires, superflus, après un nom brouillé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ placent un underscore devant chaque nom. Par exemple, le nom C "foo" obtient le nom de bas niveau "_foo". Cette option supprime l'underscore initial. Que c++filt supprime ou non l'underscore par défaut dépend de la cible.
-n
--no-strip-underscore
Ne pas supprimer l'underscore initial.
-p
--no-params
Lors du démêlage du nom d'une fonction, ne pas afficher les types des paramètres de la fonction.
-t
--types
Tenter de démêler les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types brouillés ne sont normalement utilisés qu'en interne par le compilateur, et ils peuvent être confondus avec des noms non brouillés. Par exemple, une fonction appelée "a" traitée comme un nom de type brouillé serait démêlée en "signed char".
-i
--no-verbose
Ne pas inclure les détails d'implémentation (s'il y en a) dans la sortie démêlée.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démêlage des chaînes. Étant donné que les formats de brouillage de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démêler des noms réellement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes de brouillage, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (méthode par défaut)
"gnu"
celle utilisée par le compilateur C++ GNU (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le C++ Annotated Reference Manual
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur Java GNU (gcj)
"gnat"
celle utilisée par le compilateur Ada GNU (GNAT).
--help
Affiche un résumé des options de c++filt et quitte.
--version
Affiche le numéro de version de c++filt et quitte.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier originale. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toute option de ce type sera traitée récursivement.

NOTES DE BAS DE PAGE

1.
MS-DOS n'autorise pas les caractères "+" dans les noms de fichiers, donc sur MS-DOS ce programme est nommé CXXFILT.
