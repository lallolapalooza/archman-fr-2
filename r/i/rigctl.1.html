NOM

rigctl - contrôle les émetteurs-récepteurs et récepteurs radio

SYNTAXE

rigctl [-hiIlLnouV] [-m id] [-r périphérique] [-p périphérique] [-d périphérique] [-P type] [-D type] [-s débit] [-c id] [-t char] [-C parm=val] -Y [-v[-Z]] [commande|-]

DESCRIPTION

Contrôle les émetteurs-récepteurs et récepteurs radio. rigctl accepte des commandes depuis la ligne de commande ainsi qu'en mode interactif si aucune commande n'est fournie en ligne de commande.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que de nombreuses bibliothèques backend manquent de support complet pour les appareils, les fonctions de base sont généralement bien prises en charge.

Merci de signaler les bugs et de fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui acceptent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (‘-’) nécessitent un ‘=’ entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --model=id
Sélectionne le numéro du modèle de la radio. Par défaut, la radio factice (dummy rig).
Voir la liste des modèles (utilisez “rigctl -l”).
Note : rigctl (ou un logiciel tiers utilisant l'API C) utilisera le modèle de radio 2 pour NET rigctl (communication avec rigctld).
-r, --rig-file=périphérique
Utilise périphérique comme nom de fichier du port connecté à la radio.
Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
Peut être une adresse réseau:port, par exemple 127.0.0.1:12345
La chaîne spéciale “uh-rig” peut être utilisée pour activer la prise en charge des périphériques micro-ham.
-p, --ptt-file=périphérique
Utilise périphérique comme nom de fichier du périphérique Push-To-Talk (PTT) en utilisant un fichier périphérique comme décrit ci-dessus.
-d, --dcd-file=périphérique
Utilise périphérique comme nom de fichier du périphérique Data Carrier Detect (DCD) en utilisant un fichier périphérique comme décrit ci-dessus.
-P, --ptt-type=type
Utilise le type de périphérique Push-To-Talk.
Les types pris en charge sont ‘RIG’ (commande CAT), ‘DTR’, ‘RTS’, ‘PARALLEL’, ‘CM108’, ‘GPIO’, ‘GPION’, ‘NONE’, remplaçant le type PTT défini dans le backend de la radio.
Certains effets secondaires de cette commande sont que lorsque le type est défini sur DTR, l'état PTT lu provient du frontend Hamlib, et non lu depuis la radio. Lorsqu'il est défini sur NONE, l'état PTT ne peut être ni lu ni défini même si le backend de la radio prend en charge la lecture/définition du statut PTT depuis la radio.
-D, --dcd-type=type
Utilise le type de périphérique Data Carrier Detect.
Les types pris en charge sont ‘RIG’ (commande CAT), ‘DSR’, ‘CTS’, ‘CD’, ‘PARALLEL’, ‘CM108’, ‘GPIO’, ‘GPION’, ‘NONE’.
-s, --serial-speed=débit
Définit la vitesse série à débit bits par seconde.
Utilise la vitesse série maximale des capacités du backend de la radio (définie par -m ci-dessus) comme valeur par défaut.
-c, --civaddr=id
Utilise id comme adresse CI-V pour communiquer avec la radio.
Uniquement utile pour les radios Icom et certains Ten-Tec.
Note : L'id est en notation décimale, sauf s'il est préfixé par 0x, auquel cas il est hexadécimal.
-t, --send-cmd-term=char
Change le caractère de terminaison char pour le protocole texte lors de l'utilisation de la commande send_cmd.
La valeur par défaut est ASCII CR (‘0x0D’). Les caractères non imprimables ASCII peuvent être donnés sous forme de leur numéro ASCII en format hexadécimal préfixé par “0x”. Vous pouvez passer une chaîne vide pour n'avoir aucun caractère de terminaison. La chaîne “-1” indique à rigctl de passer au protocole binaire. Voir la commande send_cmd pour plus d'explications.
Par exemple, pour spécifier un terminateur de commande pour les commandes texte style Kenwood, passez “-t ';'” à rigctl. Voir EXEMPLE ci-dessous.
-L, --show-conf
Liste tous les paramètres de configuration pour la radio définie avec -m ci-dessus. S'arrête si aucun -r n'est donné. Notez que le périphérique factice n'a pas de paramètres série.
-C, --set-conf=parm=val[,parm=val]
Définit un ou plusieurs paramètres de configuration. Certains paramètres courants sont : 
async:True active le transfert de données asynchrone pour les backends qui le supportent. Ceci permet l'utilisation des données transceive et spectre.
auto_power_on:True permet d'allumer les radios compatibles à l'ouverture.
auto_power_off:True permet d'éteindre les radios compatibles à la fermeture.
auto_disable_screensaver:True permet de désactiver le protecteur d'écran des radios compatibles à l'ouverture.
dcd_type:Surcharge du type d'interface Data Carrier Detect (ou squelch).
dcd_pathname:Nom du chemin vers le fichier périphérique du Data Carrier Detect (ou squelch).
disable_yaesu_bandselect:True désactive la sélection automatique de bande lors d'un changement de bande pour les radios Yaesu.
dtr_state:ON allume DTR, OFF l'éteint, Unset le désactive.
lo_freq:Fréquence à ajouter à la fréquence VFO pour l'utilisation avec un transverter.
post_write_delay:Délai en ms entre chaque commande envoyée.
ptt_share:True active le partage du port PTT avec d'autres applications.
ptt_type:Surcharge du type d'interface Push-To-Talk.
ptt_pathname:Nom du chemin vers le fichier périphérique du Push-To-Talk.
ptt_bitnum:Numéro du bit GPIO du Push-To-Talk.
retry:Nombre maximum de tentatives.
rts_state:ON allume RTS, OFF l'éteint, Unset le désactive.
twiddle_timeout:Pour les opérations satellites lorsque VFOB est manipulé, mettra en pause les commandes VFOB jusqu'à la fin du délai imparti.
twiddle_rit:Supprime get_freq sur VFOB pour les satellites réglés avec RIT.
timeout:Délai en ms.
write_delay:Délai en ms entre chaque octet envoyé.
tuner_control_pathname:Nom du chemin vers un script/programme pour contrôler un tuner avec 1 argument de 0/1 pour Tuner Off/On.

Utilisez l'option -L ci-dessus pour obtenir la liste des paramètres de configuration pour un numéro de modèle donné.
-u, --dump-caps
Affiche les capacités pour la radio définie avec -m ci-dessus et quitte.
-l, --list
Liste tous les numéros de modèles définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être remontée en utilisant Maj-PagePréc/Maj-PageSuiv, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou la fenêtre de commande sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple “rigctl -l | more”.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-o, --vfo
Active le mode VFO.
Un argument VFO supplémentaire sera requis avant chaque commande appropriée (sauf set_vfo). Sinon, ‘currVFO’ est utilisé lorsque cette option n'est pas définie et qu'un argument VFO supplémentaire n'est pas utilisé.
-n, --no-restore-ai
À la sortie, rigctl restaure l'état de l'information automatique (AI) sur le poste contrôlé.
Si cela n'est pas souhaité, par exemple si vous utilisez rigctl pour activer ou désactiver le mode AI, passez cette option.
-i, --read-history
Lit l'historique des commandes et arguments précédemment enregistrés à partir d'un fichier (par défaut $HOME/.rigctl_history) pour la session en cours.
Disponible lorsque rigctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note: Pour lire un fichier d'historique stocké dans un autre répertoire, définissez la variable d'environnement RIGCTL_HIST_DIR, par exemple “RIGCTL_HIST_DIR=~/tmp rigctl -i”. Lorsque RIGCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-I, --save-history
Écrit l'historique des commandes et arguments de la session en cours (et des sessions précédentes, si l'option -i est donnée) dans un fichier (par défaut $HOME/.rigctl_history) à la fin de la session en cours.
Les commandes complètes avec leurs arguments sont enregistrées sur une seule ligne pour être rappelées et utilisées ou modifiées. Disponible lorsque rigctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note: Pour écrire un fichier d'historique dans un autre répertoire, définissez la variable d'environnement RIGCTL_HIST_DIR, par exemple “RIGCTL_HIST_DIR=~/tmp rigctl -IRq. Lorsque RIGCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-v, --verbose
Définit le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Y,--ignore-err
Ignore les erreurs d'ouverture du poste
-Z, --debug-time-stamps
Active les horodatages pour les messages de débogage.
À utiliser uniquement en combinaison avec l'option -v, car elle ne génère aucune sortie par elle-même.
-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rigctl et quitte.
-!, --cookie
Définit le cookie à utiliser pour la sécurité d'accès à distance
-#, --skip_init
Ignore la plupart des initialisations au démarrage.
-
Arrête le traitement des options et lit les commandes depuis l'entrée standard.
Voir Standard Input ci-dessous.

Note: Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. Cela se produira très probablement avec les options --set-conf et --show-conf.

Veuillez noter que le backend du poste à contrôler, ou le poste lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un code d'erreur Hamlib.

COMMANDES

Les commandes peuvent être entrées soit comme un seul caractère, soit comme un nom de commande long. Les commandes ne sont pas préfixées par un tiret comme le sont les options. Elles peuvent être tapées en mode interactif ou fournies comme argument(s) en mode ligne de commande. En mode interactif, les commandes et leurs arguments peuvent être entrés sur une seule ligne :


M LSB 2400

Étant donné que la plupart des opérations Hamlib ont une méthode set et une méthode get, une seule lettre majuscule sera utilisée pour les méthodes set, tandis que la lettre minuscule correspondante fera référence à la méthode get. Chaque opération a également un nom long ; en mode interactif, préfixez un antislash, ‘\’, pour entrer un nom de commande entièrement en minuscules.

Exemple : Utilisez “\dump_caps” pour voir quelles capacités ce poste et ce backend supportent.

Note: Le backend du poste à contrôler, ou le poste lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un message d'erreur Hamlib.

Standard Input

En alternative à l'entrée de commande interactive READLINE ou à une seule commande par exécution, rigctl propose une option spéciale où un simple tiret (‘-’) peut être utilisé pour lire les commandes depuis l'entrée standard (stdin). Les commandes doivent être séparées par des espaces, de manière similaire aux commandes données sur la ligne de commande. Des commentaires peuvent être ajoutés en utilisant le caractère ‘#’, tout texte jusqu'à la fin de la ligne courante, y compris le caractère ‘#’, est ignoré.

Un exemple simple (le texte tapé est en gras) :


$ cat <<.EOF. >cmds.txt
> # Fichier de commandes
> v f m	# interroger le poste
> V VFOB F 14200000 M CW 500	# configurer le poste
> v f m	# interroger le poste
> .EOF.
$ rigctl -m1 - <cmds.txt
v VFOA
f 145000000
m FM
15000
V VFOB
F 14200000
M CW 500
v VFOB
f 14200000
m CW
500
$

Commandes rigctl

Un résumé des commandes est inclus ci-dessous (Dans le cas des commandes set, la chaîne italisée entre guillemets est remplacée par la valeur dans la description. Dans le cas des commandes get, la chaîne italisée entre guillemets est le nom clé de la valeur retournée) :

Q|q, exit rigctl
Quitte rigctl en mode interactif.
Lorsque rigctl contrôle directement le poste, il ferme le backend du poste et le port. Lorsque rigctl est connecté à rigctld (modèle de radio 2), la connexion TCP/IP à rigctld est fermée et rigctld reste en cours d'exécution, disponible pour une autre connexion réseau TCP/IP.
F, set_freq 'Fréquence'
Définit la 'Fréquence', en Hz.
La fréquence peut être une valeur flottante ou entière.
f, get_freq
Récupère la 'Fréquence', en Hz.
Retourne une valeur entière et le VFO que hamlib considère comme actif. Notez que certains postes (par ex. tous les Icoms) ne peuvent pas suivre le VFO actuel, donc hamlib peut se désynchroniser du poste si l'utilisateur appuie sur des boutons du poste comme le VFO.
M, set_mode 'Mode' 'Bande passante'
Définit le 'Mode' et la 'Bande passante'.
Le mode est un jeton : ‘USB’, ‘LSB’, ‘CW’, ‘CWR’, ‘RTTY’, ‘RTTYR’, ‘AM’, ‘FM’, ‘WFM’, ‘AMS’, ‘PKTLSB’, ‘PKTUSB’, ‘PKTFM’, ‘ECSSUSB’, ‘ECSSLSB’, ‘FA’, ‘SAM’, ‘SAL’, ‘SAH’, ‘DSB’.
La bande passante est en Hz sous forme d'entier, -1 pour aucun changement, ou ‘0’ pour la valeur par défaut du backend du poste. L'IC7300 peut utiliser 1, 2, 3 pour sélectionner le filtre à utiliser
Note: Passer un ‘?’ (requête) comme premier argument au lieu d'un jeton de Mode retournera une liste de Modes supportés par le backend du poste, séparés par des espaces. Utilisez ceci pour déterminer les Modes supportés d'un backend de poste donné.
m, get_mode
Récupère le 'Mode' et la 'Bande passante'.
Retourne le Mode sous forme de jeton et la Bande passante en Hz comme dans set_mode ci-dessus.
V, set_vfo 'VFO'
Définit le 'VFO'.
Le VFO est un jeton : ‘VFOA’, ‘VFOB’, ‘VFOC’, ‘currVFO’, ‘VFO’, ‘MEM’, ‘Main’, ‘Sub’, ‘TX’, ‘RX’, ‘MainA’, ‘MainB’, ‘MainC’, ‘SubA’, ‘SubB’ ‘SubC’.
En mode VFO (voir l'option --vfo ci-dessus), un seul paramètre VFO est requis :

$ rigctl -m 2029 -r /dev/rig -o
Rig command: V
VFO: VFOB
Rig command:

v, get_vfo
Récupère le 'VFO' actuel.
Retourne le VFO sous forme de jeton comme dans set_vfo ci-dessus.
J, set_rit 'RIT'
Définit le 'RIT'.
Le RIT est en Hz et peut être + ou -. Une valeur de ‘0’ réinitialise le RIT (Receiver Incremental Tuning) pour correspondre à la fréquence VFO.
Note: Le RIT doit être activé ou désactivé explicitement avec la commande set_func. Cela permet de définir le décalage RIT indépendamment de son activation et permet au RIT de rester actif tout en définissant le décalage à ‘0’.
j, get_rit
Récupère le 'RIT' en Hz.
La valeur retournée est un entier.
Z, set_xit 'XIT'
Définit le 'XIT'.
Le XIT est en Hz et peut être + ou -. Une valeur de ‘0’ réinitialise le XIT (Transmitter Incremental Tuning) pour correspondre à la fréquence VFO.
Note: Le XIT doit être activé ou désactivé explicitement avec la commande set_func. Cela permet de définir le décalage XIT indépendamment de son activation et permet au XIT de rester act

Y, set_ant 'Antenna' 'Option'
Définir 'Antenne' et 'Option'.
Le nombre est le numéro d'antenne basé sur 1 (‘1’, ‘2’, ‘3’, ...).
L'option dépend du transceiver. Pour les Icom, elle définit probablement les antennes Tx & Rx comme dans l'IC-7851. Consultez votre manuel pour les valeurs d'option spécifiques au transceiver. La plupart des transceivers ne se soucient pas de l'option.
Pour l'IC-7851, le FTDX3000 (et peut-être d'autres) cela signifie ceci :

1 = TX/RX = ANT1  FTDX3000=ANT1/ANT3
2 = TX/RX = ANT2  FTDX3000=ANT2/ANT3
3 = TX/RX = ANT3  FTDX3000=ANT3
4 = TX/RX = ANT1/ANT4
5 = TX/RX = ANT2/ANT4
6 = TX/RX = ANT3/ANT4

> 0 est le numéro d'antenne basé sur 1 (‘1’, ‘2’, ‘3’, ...).

NOM

rigctl — Interface de contrôle de radio amateur

SYNTAXE

rigctl [OPTIONS...] [COMMAND ARGUMENTS...]

DESCRIPTION

rigctl est un programme d'interface pour contrôler un équipement radio amateur via la bibliothèque Hamlib. Hamlib fournit une API uniforme pour contrôler divers équipements radio, quelle que soit la marque ou le modèle. Hamlib est implémenté en C et est utilisé par de nombreuses applications de radio amateur.

Il peut être utilisé en mode interactif (par défaut) ou en mode non interactif, où les commandes sont lues depuis l'entrée standard et traitées séquentiellement.

Le programme rigctl est également disponible en tant que démon réseau, rigctld(1), qui peut être interrogé par un programme client distant.

Le modèle radio peut être spécifié via l'option -m ou --model. L'appareil de communication, par exemple un port série, peut être spécifié avec l'option -r ou --rig-hamming. Pour une liste complète des modèles et des appareils, veuillez consulter la documentation de Hamlib.

L'utilisation des options -v, --verbose, et -d, --debug permet d'ajuster le niveau de verbosité des diagnostics de sortie.

OPTIONS

Les options suivantes sont disponibles :

-m MODEL, --model=MODEL
Sélectionne le modèle de l'équipement radio à utiliser. Si un équipement radio est sélectionné, sa description et son modèle sont affichés. La valeur spéciale 0 désigne l'équipement de démo, le modèle 1 l'équipement générique et le modèle 2 le « NET rigctl ». Pour le modèle 2, le nom d'hôte et le port TCP sont spécifiés avec l'option -r ou --rig-hamming.
-r DEVICE, --rig-hamming=DEVICE
Spécifie l'appareil de communication pour le contrôle de l'équipement radio. Il s'agit généralement d'un port série (par ex. /dev/ttyS0, /dev/ttyUSB0, COM1). Si l'option --model est définie sur 2, DEVICE doit être dans le format hostname:port (par ex. localhost:4532).
-s SPEED, --speed=SPEED
Définit la vitesse de transmission (baud rate) du port série. Les valeurs courantes sont 9600, 4800, etc. L'option ne s'applique que si l'équipement radio est connecté via un port série.
-t TIMEOUT, --toilet-timeout=TIMEOUT
Définit le délai d'attente (timeout) en secondes pour les commandes. Utile pour les équipements qui ne répondent pas immédiatement ou qui ne répondent pas du tout. Le comportement par défaut dépend du modèle d'équipement et de l'implémentation Hamlib.
-C SETTING, --set-conf=SETTING
Permet de définir des paramètres de configuration spécifiques au modèle d'équipement radio. La syntaxe est SETTING=VALEUR. Par exemple, pour définir le nombre de bits d'arrêt à 2 pour un port série, utilisez -C stop_bits=2.
-v, --verbose
Augmente le niveau de verbosité. Peut être spécifié plusieurs fois pour augmenter le niveau (par ex. -vv pour un niveau plus élevé). Cela affecte les diagnostics envoyés à stderr.
-d MASK, --debug=MASK
Définit un masque de débogage pour l'implémentation Hamlib. Permet de déboguer des parties spécifiques de la bibliothèque. Le masque est une valeur entière où chaque bit active un niveau de débogage différent.
-h, --help
Affiche un message d'aide et quitte.
-V, --version
Affiche des informations sur la version de Hamlib et quitte.
-i FILE, --read-history=FILE
Lit l'historique des commandes à partir du fichier spécifié.
-I FILE, --save-history=FILE
Écrit l'historique des commandes dans le fichier spécifié.

COMMANDES

Lorsque rigctl est exécuté en mode interactif, il accepte les commandes suivantes :

send_raw HEX-STRING
Envoie une chaîne d'octets bruts à l'équipement radio. La chaîne est une suite de valeurs hexadécimales séparées par des points-virgules. Par exemple : send_raw 0xFE;0xFE;0x94;0x03;0xFD
client_version 'String'
Le client peut envoyer sa version à rigctld et recevoir un retour d'information sur la compatibilité, l'obsolescence et les alternatives.
hamlib_version
Retourne la version de Hamlib avec la date/heure au format ISO8601.
test
Exécute des routines de test. En cours de développement.
set_gpio 'GPIO#'
Définit les GPIO1, GPIO2, GPIO3, GPIO4 sur le port PTT GPIO. Peut aussi utiliser 1,2,3,4.
get_gpio 'GPIO#'
Lit les GPIO1, GPIO2, GPIO3, GPIO4 sur le port PTT GPIO. Peut aussi utiliser 1,2,3,4.
skip_init
Ignore l'initialisation de l'équipement radio — utile lors de l'exécution de commandes avec rigctl pour accélérer les choses.
freq_skip 'skip'
Lorsque skip!=0, ignore le réglage de la fréquence sur le VFO TX en mode RX et sur le VFO RX en mode TX — à utiliser avec gpredict et les équipements qui n'ont pas de VFO CIBLE.

READLINE

Si les fichiers de développement de la bibliothèque Readline sont trouvés lors de la configuration, rigctl sera construit conditionnellement avec le support de Readline pour la saisie des commandes et des arguments. Les raccourcis clavier de Readline sont par défaut ceux décrits dans le manuel Readline. rigctl définit le nom « rigctl », qui peut être utilisé dans les constructions d'initialisation conditionnelles dans le fichier d'initialisation Readline (par défaut $HOME/.inputrc) pour des liaisons de touches personnalisées uniques à rigctl.

L'historique des commandes est disponible avec le support de Readline comme décrit dans le manuel Readline History. Les chaînes de commandes et d'arguments sont stockées en tant que lignes uniques, même lorsque les arguments sont demandés individuellement. Les commandes et les arguments ne sont pas validés et sont stockés tels qu'ils sont saisis, les valeurs étant séparées par un seul espace.

Normalement, l'historique de session n'est pas sauvegardé. Cependant, l'utilisation des options -i/ --read-history ou -I/ --save-history lors du démarrage de rigctl entraînera la lecture de tout historique précédemment sauvegardé et/ou l'écriture de l'historique de la session en cours et de toute session précédente (en supposant que les options -i et -I soient données ensemble) à la fermeture de rigctl. Chaque option est mutuellement exclusive, c'est-à-dire que chacune peut être donnée séparément ou en combinaison. Ceci est utile pour sauvegarder un ensemble de commandes, puis les lire plus tard, mais sans écrire l'historique modifié, pour un ensemble cohérent de commandes de test en mode interactif, par exemple.

L'historique est stocké par défaut dans $HOME/.rigctl_history, bien que le répertoire de destination puisse être modifié en définissant la variable d'environnement RIGCTL_HIST_DIR. Lorsque RIGCTL_HIST_DIR n'est pas définie, la valeur de la variable d'environnement HOME est utilisée à la place. Seul le répertoire de destination peut être modifié à l'heure actuelle.

Si le support de Readline n'est pas trouvé lors de la configuration, le gestionnaire de commandes interne d'origine est utilisé. Readline n'est pas utilisé pour les commandes rigctl saisies sur la ligne de commande, que le support de Readline soit intégré ou non.

Note : Le support de Readline n'est pas inclus dans les builds binaires MS Windows 32 ou 64 bits fournis par le projet Hamlib. L'exécution de rigctl sous MS Windows dans le shell « cmd » fournit un historique des commandes de session, mais il n'est pas sauvegardé sur disque entre les sessions.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à envoyer à stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques backend radio et peut être demandé par les développeurs.

EXIT STATUS

rigctl se termine avec :

0
si toutes les opérations se sont terminées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib.

EXAMPLES

Démarrer rigctl pour un Yaesu FT-920 utilisant un adaptateur série USB sous Linux en mode interactif :


$ rigctl -m 1014 -r /dev/ttyUSB1

Démarrer rigctl pour un Yaesu FT-920 utilisant COM1 sous MS Windows tout en générant une sortie TRACE vers stderr :


> rigctl -m 1014 -r COM1 -vvvvv

Démarrer rigctl pour un Yaesu FT-920 utilisant un adaptateur série USB tout en définissant le débit en bauds et les bits d'arrêt :


$ rigctl -m 1014 -r /dev/ttyUSB1 -s 4800 -C stop_bits=2

Démarrer rigctl pour un Elecraft K3 utilisant un adaptateur série USB tout en spécifiant un terminateur de commande pour la commande w :


$ rigctl -m 2029 -r /dev/ttyUSB0 -t';'

Se connecter à un rigctld en cours d'exécution avec le modèle radio 2 (« NET rigctl ») sur l'hôte local et en spécifiant le port TCP, en réglant la fréquence et le mode :


$ rigctl -m 2 -r localhost:4532 F 7253500 M LSB 0
