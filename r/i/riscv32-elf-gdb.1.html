GDB(1) Outils de développement GNU GDB(1)

NOM

gdb - Le débogueur GNU

SYNTAXE

gdb [OPTIONS] [prog|prog procID|prog core]

DESCRIPTION

Le but d'un débogueur comme GDB est de vous permettre de voir ce qui se passe "à l'intérieur" d'un autre programme pendant son exécution -- ou ce qu'un autre programme faisait au moment où il a crashé.

GDB peut faire quatre types d'actions principales (plus d'autres actions pour les supporter) pour vous aider à attraper les bugs en flagrant délit :

  • Démarrer votre programme, en spécifiant tout ce qui pourrait affecter son comportement.
  • Faire s'arrêter votre programme dans des conditions spécifiées.
  • Examiner ce qui s'est passé, lorsque votre programme s'est arrêté.
  • Changer des éléments dans votre programme, afin que vous puissiez expérimenter la correction des effets d'un bug et continuer pour en découvrir un autre.

Vous pouvez utiliser GDB pour déboguer des programmes écrits en C, C++, Fortran et Modula-2.

GDB est invoqué avec la commande shell "gdb". Une fois démarré, il lit les commandes du terminal jusqu'à ce que vous lui disiez de sortir avec la commande GDB "quit" ou "exit". Vous pouvez obtenir de l'aide en ligne depuis GDB lui-même en utilisant la commande "help".

Vous pouvez exécuter "gdb" sans arguments ni options ; mais la manière la plus courante de démarrer GDB est avec un ou deux arguments, spécifiant un programme exécutable comme argument :

gdb programme

Vous pouvez aussi démarrer avec un programme exécutable et un fichier core spécifiés :

gdb programme core

Vous pouvez, alternativement, spécifier un ID de processus comme deuxième argument ou utiliser l'option "-p", si vous voulez déboguer un processus en cours d'exécution :

gdb programme 1234
gdb -p 1234

attacherait GDB au processus 1234. Avec l'option -p vous pouvez omettre le nom de fichier programme.

Voici quelques-unes des commandes GDB les plus fréquemment nécessaires :

break [fichier:][fonction|ligne]
Pose un point d'arrêt à fonction ou ligne (dans fichier).
run [liste_args]
Démarre votre programme (avec liste_args, si spécifiée).
bt
Backtrace : affiche la pile du programme.
print expr
Affiche la valeur d'une expression.
c
Continue l'exécution de votre programme (après un arrêt, par ex. à un point d'arrêt).
next
Exécute la ligne de programme suivante (après un arrêt) ; passe *par-dessus* les appels de fonction dans la ligne.
edit [fichier:]fonction
examine la ligne du programme où il est actuellement arrêté.
list [fichier:]fonction
écrit le texte du programme dans le voisinage de l'endroit où il est actuellement arrêté.
step
Exécute la ligne de programme suivante (après un arrêt) ; passe *dans* les appels de fonction dans la ligne.
help [nom]
Affiche des informations sur la commande GDB nom, ou des informations générales sur l'utilisation de GDB.
quit
exit
Quitte GDB.

Pour plus de détails sur GDB, voir Using GDB: A Guide to the GNU Source-Level Debugger, par Richard M. Stallman et Roland H. Pesch. Le même texte est disponible en ligne sous l'entrée "gdb" du programme "info".

OPTIONS

Tous les arguments autres que les options spécifient un fichier exécutable et un fichier core (ou un ID de processus) ; c'est-à-dire que le premier argument rencontré sans drapeau d'option associé est équivalent à une option --se, et le second, s'il y en a un, est équivalent à une option -c s'il s'agit du nom d'un fichier. De nombreuses options ont des formes longues et abrégées ; les deux sont montrées ici. Les formes longues sont également reconnues si vous les tronquez, tant que suffisamment de l'option est présente pour être non ambiguë.

Les formes abrégées sont montrées ici avec - et les formes longues avec -- pour refléter la façon dont elles sont présentées dans --help. Cependant, GDB reconnaît toutes les conventions suivantes pour la plupart des options :

"--option=valeur"
"--option valeur"
"-option=valeur"
"-option valeur"
"--o=valeur"
"--o valeur"
"-o=valeur"
"-o valeur"

Toutes les options et tous les arguments de ligne de commande que vous donnez sont traités dans l'ordre séquentiel. L'ordre a une importance lorsque l'option -x est utilisée.

--help
-h
Liste toutes les options avec de brèves explications.
--symbols=fichier
-s fichier
Lit la table des symboles depuis fichier.
--write
Active l'écriture dans les fichiers exécutables et les fichiers core.
--exec=fichier
-e fichier
Utilise fichier comme fichier exécutable à lancer le cas échéant, et pour examiner des données pures en conjonction avec un dump core.
--se=fichier
Lit la table des symboles depuis fichier et l'utilise comme fichier exécutable.
--core=fichier
-c fichier
Utilise fichier comme un dump core à examiner.
--command=fichier
-x fichier
Exécute les commandes GDB depuis fichier.
--eval-command=commande
-ex commande
Exécute la commande GDB donnée.
--init-eval-command=commande
-iex
Exécute la commande GDB avant de charger l'inférieur.
--directory=répertoire
-d répertoire
Ajoute répertoire au chemin de recherche des fichiers sources.
--nh
N'exécute pas les commandes de ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, ou ~/.gdbearlyinit.
--nx
-n
N'exécute aucune commande des fichiers d'initialisation .gdbinit ou .gdbearlyinit.
--quiet
--silent
-q
"Silencieux". N'affiche pas les messages d'introduction et de copyright. Ces messages sont également supprimés en mode batch.
--batch
Exécute en mode batch. Se termine avec le statut 0 après avoir traité tous les fichiers de commandes spécifiés avec -x (et .gdbinit, si non inhibé). Se termine avec un statut non nul si une erreur survient lors de l'exécution des commandes GDB dans les fichiers de commandes.

riscv32-elf-gdb(1) — Arch Linux

NAME

riscv32-elf-gdb 15.2-1 — The GNU Project Debugger

SYNOPSIS

gdb [-nx] [--args] [--batch] [--batch-silent] [--cd=directory] [--configuration] [--data-directory=directory] [-d directory] [-e] [--exec-file=file] [-F file] [-f] [-h|--help] [--pid=pid] [-q|--quiet] [--readnow] [--readnever] [--return-child-result] [-se=file] [-tui] [--tty=device] [--version] [--verbose] [program [initial-arguments...]] [program-file [arguments...]] [[--] file ...]

DESCRIPTION

The GNU Project Debugger, GDB, allows you to see what is going on inside another program while it executes or what another program was doing at the time it crashed. You can use GDB to start your program, tell it when to stop, and examine what has happened, when it has stopped. You can change variables that are running in your program and you can even run your program again, modified by the new values you have found.

The command you use to start GDB is always gdb. You can give GDB the name of the program you want to debug, and optional arguments to that program.

If you start GDB without specifying a program name, GDB will start, and you can then use the file command to load a program into GDB, and the run command to run it.

GDB can be used to debug programs that are already running. GDB can also be used to debug core dumps. In this case, GDB can show you the state of the process when the core dump occurred.

OPTIONS

--batch
Run in batch mode. GDB exits after performing all file and other startup operations. This mode is useful for invoking GDB from scripts.

In batch mode, GDB does not require a running program. It is useful for downloading and running a program on another computer; in order to make this more useful, the message

Program exited normally.

(which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode.

--batch-silent
Run in batch mode, just like --batch, but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than --silent and would be useless for an interactive session.

This is particularly useful when using targets that give Loading section messages, for example.

Note that targets that give their output via GDB, as opposed to writing directly to "stdout", will also be made silent.

--args prog [arglist]
Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: 
gdb ./a.out -q

It would start GDB with -q, not printing the introductory message. On the other hand, using:

gdb --args ./a.out -q

starts GDB with the introductory message, and passes the option to the inferior.

--pid=pid
Attach GDB to an already running program, with the PID pid.
--tui
Open the terminal user interface.
--readnow
Read all symbols from the given symfile on the first access.
--readnever
Do not read symbol files.
--return-child-result
GDB's exit code will be the same as the child's exit code.
--configuration
Print details about GDB configuration and then exit.
--version
Print version information and then exit.
--cd=directory
Run GDB using directory as its working directory, instead of the current directory.
--data-directory=directory
-D
Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files.
--fullname
-f
Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame.
-b baudrate
Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging.
-l timeout
Set timeout, in seconds, for remote debugging.
--tty=device
Run using device for your program's standard input and output.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
