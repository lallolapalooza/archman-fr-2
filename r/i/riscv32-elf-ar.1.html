riscv32-elf-ar(1)

Paquet: riscv32-elf-binutils

AR(1) Outils de développement GNU AR(1)

NOM

ar - créer, modifier et extraire des archives

SYNOPIS

ar [-X32_64] [-]p[mod] [--plugin nom] [--target nom_bfd] [--output rép] [--record-libdeps déps_lib] [--thin] [pos_rel] [compte] archive [membre...]

DESCRIPTION

Le programme GNU ar crée, modifie et extrait des fichiers à partir d'archives. Une archive est un seul fichier contenant une collection d'autres fichiers dans une structure qui permet de récupérer les fichiers individuels d'origine (appelés membres de l'archive).

Le contenu, le mode (permissions), l'horodatage, le propriétaire et le groupe des fichiers d'origine sont préservés dans l'archive et peuvent être restaurés lors de l'extraction.

GNU ar peut gérer des archives dont les membres ont des noms de n'importe quelle longueur ; cependant, selon la configuration de ar sur votre système, une limite sur la longueur des noms de membres peut être imposée pour assurer la compatibilité avec les formats d'archives gérés par d'autres outils. Si elle existe, la limite est souvent de 15 caractères (typique des formats liés à a.out) ou 16 caractères (typique des formats liés à coff).

ar est considéré comme un utilitaire binaire car les archives de ce type sont le plus souvent utilisées comme bibliothèques contenant des sous-routines couramment nécessaires. Comme les bibliothèques dépendent souvent d'autres bibliothèques, ar peut également enregistrer les dépendances d'une bibliothèque lorsque l'option --record-libdeps est spécifiée.

ar crée un index des symboles définis dans les modules d'objet déplaçables dans l'archive lorsque vous spécifiez le modificateur s. Une fois créé, cet index est mis à jour dans l'archive chaque fois que ar apporte une modification à son contenu (sauf pour l'opération de mise à jour q).

Une archive avec un tel index accélère la liaison à la bibliothèque et permet aux routines de la bibliothèque de s'appeler mutuellement sans tenir compte de leur placement dans l'archive.

Vous pouvez utiliser nm -s ou nm --print-armap pour lister cette table d'index. Si une archive n'a pas de table, une autre forme de ar appelée ranlib peut être utilisée pour ajouter uniquement la table.

GNU ar peut optionnellement créer une archive fine (thin), qui contient un index de symboles et des références aux copies originales des fichiers membres de l'archive. Ceci est utile pour construire des bibliothèques à utiliser dans un arbre de construction local, où les objets déplaçables sont censés rester disponibles, et copier le contenu de chaque objet ne ferait que perdre du temps et de l'espace.

Une archive peut être fine ou normale. Elle ne peut pas être les deux en même temps. Une fois qu'une archive est créée, son format ne peut pas être modifié sans d'abord la supprimer puis en créer une nouvelle à sa place.

Les archives fines sont également aplaties, de sorte que l'ajout d'une archive fine à une autre archive fine ne l'imbrique pas, comme cela se produirait avec une archive normale. Au lieu de cela, les éléments de la première archive sont ajoutés individuellement à la seconde archive.

Les chemins vers les éléments de l'archive sont stockés relativement à l'archive elle-même.

GNU ar est conçu pour être compatible avec deux installations différentes. Vous pouvez contrôler son activité à l'aide d'options de ligne de commande, comme les différentes variétés de ar sur les systèmes Unix ; ou, si vous spécifiez l'unique option de ligne de commande -M, vous pouvez le contrôler avec un script fourni via l'entrée standard, comme le programme "librarian" de MRI.

OPTIONS

GNU ar vous permet de mélanger le code d'opération p et les indicateurs modificateurs mod dans n'importe quel ordre, au sein du premier argument de ligne de commande.

Si vous le souhaitez, vous pouvez commencer le premier argument de ligne de commande par un tiret.

La lettre clé p spécifie l'opération à exécuter ; elle peut être l'une des suivantes, mais vous ne devez en spécifier qu'une seule :

d
Supprime des modules de l'archive. Spécifiez les noms des modules à supprimer comme membre... ; l'archive reste inchangée si vous ne spécifiez aucun fichier à supprimer.

Si vous spécifiez le modificateur v, ar liste chaque module lors de sa suppression.

m
Utilisez cette opération pour déplacer des membres dans une archive.

L'ordre des membres dans une archive peut avoir une incidence sur la manière dont les programmes sont liés à l'aide de la bibliothèque, si un symbole est défini dans plusieurs membres.

Si aucun modificateur n'est utilisé avec "m", les membres que vous nommez dans les arguments membre sont déplacés à la fin de l'archive ; vous pouvez utiliser les modificateurs a, b ou i pour les déplacer à un endroit spécifié à la place.

p
Affiche les membres spécifiés de l'archive, sur la sortie standard. Si le modificateur v est spécifié, affiche le nom du membre avant de copier son contenu sur la sortie standard.

Si vous ne spécifiez aucun argument membre, tous les fichiers de l'archive sont affichés.

q
Ajout rapide ; Historiquement, ajoute les fichiers membre... à la fin de archive, sans vérifier les remplacements.

Les modificateurs a, b et i n'affectent pas cette opération ; les nouveaux membres sont toujours placés à la fin de l'archive.

Le modificateur v fait que ar liste chaque fichier lorsqu'il est ajouté.

Étant donné que le but de cette opération est la rapidité, les implémentations de ar ont la possibilité de ne pas mettre à jour la table des symboles de l'archive si elle existe. Trop de systèmes différents supposent cependant que les tables des symboles sont toujours à jour, c'est pourquoi GNU ar reconstruira la table même avec un ajout rapide.

Note - GNU ar traite la commande qs comme un synonyme de r - remplaçant les fichiers déjà existants dans l'archive et en ajoutant de nouveaux à la fin.

r
Insère les fichiers membre... dans archive (avec remplacement). Cette opération diffère de q en ce que tous les membres précédemment existants sont supprimés si leurs noms correspondent à ceux ajoutés.

Si l'un des fichiers nommés dans membre... n'existe pas, ar affiche un message d'erreur et laisse intacts les membres existants de l'archive correspondant à ce nom.

Par défaut, les nouveaux membres sont ajoutés à la fin du fichier ; mais vous pouvez utiliser l'un des modificateurs a, b ou i pour demander un placement relatif à un membre existant.

Le modificateur v utilisé avec cette opération génère une ligne de sortie pour chaque fichier inséré, ainsi que l'une des lettres a ou r pour indiquer si le fichier a été ajouté (aucun ancien membre supprimé) ou remplacé.

s
Ajoute un index à l'archive, ou le met à jour s'il existe déjà. Notez que cette commande est une exception à la règle selon laquelle il ne peut y avoir qu'une seule lettre de commande, car il est possible de l'utiliser comme commande ou comme modificateur. Dans les deux cas, elle fait la même chose.
t
Affiche un tableau listant le contenu de archive, ou celui des fichiers listés dans membre... qui sont présents dans l'archive. Normalement, seul le nom du membre est affiché, mais si le modificateur O est spécifié, alors le décalage correspondant du membre est également affiché. Enfin, afin de voir les modes (permissions), l'horodatage, le propriétaire, le groupe et la taille, le modificateur v doit être inclus.

Si vous ne spécifiez pas de membre, tous les fichiers de l'archive sont listés.

S'il y a plus d'un fichier portant le même nom (par exemple, fie) dans une archive (par exemple b.a), ar t b.a fie ne liste que la première occurrence ; pour toutes les voir, vous devez demander une liste complète --- dans notre exemple, ar t b.a.

x
Extrait les membres (nommés membre) de l'archive. Vous pouvez utiliser le modificateur v avec cette opération, pour demander à ar de lister chaque nom lors de son extraction.

Si vous ne spécifiez pas de membre, tous les fichiers de l'archive sont extraits.

Les fichiers ne peuvent pas être extraits d'une archive fine, et il existe des restrictions sur l'extraction à partir d'archives créées avec P : les chemins ne doivent pas être absolus.

, peut ne pas contenir "..", et tous les sous-répertoires dans les chemins doivent exister. Si vous souhaitez éviter ces restrictions, utilisez l'option --output pour spécifier un répertoire de sortie.

Un certain nombre de modificateurs (mod) peuvent suivre immédiatement la lettre de clé p, pour spécifier des variations sur le comportement d'une opération :

a
Ajouter de nouveaux fichiers après un membre existant de l'archive. Si vous utilisez le modificateur a, le nom d'un membre d'archive existant doit être présent comme argument relpos, avant la spécification de l'archive.
b
Ajouter de nouveaux fichiers avant un membre existant de l'archive. Si vous utilisez le modificateur b, le nom d'un membre d'archive existant doit être présent comme argument relpos, avant la spécification de l'archive. (identique à i).
c
Créer l'archive. L'archive spécifiée est toujours créée si elle n'existait pas, lorsque vous demandez une mise à jour. Mais un avertissement est émis à moins que vous ne spécifiiez à l'avance que vous vous attendez à la créer, en utilisant ce modificateur.
D
Opérer en mode déterministe. Lors de l'ajout de fichiers et que l'index de l'archive utilise zéro pour les UID, GID, horodatages, et utilise des modes de fichier cohérents pour tous les fichiers. Lorsque cette option est utilisée, si ar est utilisé avec des options identiques et des fichiers d'entrée identiques, plusieurs exécutions créeront des fichiers de sortie identiques indépendamment des propriétaires, groupes, modes de fichier ou heures de modification des fichiers d'entrée.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec le modificateur U, ci-dessous.

f
Tronquer les noms dans l'archive. GNU ar autorisera normalement les noms de fichiers de toute longueur. Cela le fera créer des archives qui ne sont pas compatibles avec le programme ar natif sur certains systèmes. Si cela pose un problème, le modificateur f peut être utilisé pour tronquer les noms de fichiers lors de leur insertion dans l'archive.
i
Insérer de nouveaux fichiers avant un membre existant de l'archive. Si vous utilisez le modificateur i, le nom d'un membre d'archive existant doit être présent comme argument relpos, avant la spécification de l'archive. (identique à b).
l
Spécifier les dépendances de cette bibliothèque. Les dépendances doivent suivre immédiatement ce caractère d'option, doivent utiliser la même syntaxe que la ligne de commande de l'éditeur de liens, et doivent être spécifiées dans un seul argument. C'est-à-dire, si plusieurs éléments sont nécessaires, ils doivent être mis entre guillemets pour former un seul argument de ligne de commande. Par exemple L "-L/usr/local/lib -lmydep1 -lmydep2"
N
Utilise le paramètre count. Ceci est utilisé s'il y a plusieurs entrées dans l'archive avec le même nom. Extraire ou supprimer l'instance count du nom donné de l'archive.
o
Préserver les dates originales des membres lors de leur extraction. Si vous ne spécifiez pas ce modificateur, les fichiers extraits de l'archive seront estampillés avec l'heure d'extraction.
O
Afficher les décalages des membres à l'intérieur de l'archive. Utiliser conjointement avec l'option t.
P
Utiliser le nom de chemin complet lors de la correspondance ou du stockage des noms dans l'archive. Les archives créées avec des noms de chemin complets ne sont pas conformes à POSIX, et donc peuvent ne pas fonctionner avec des outils autres que les outils GNU à jour. La modification de telles archives avec GNU ar sans utiliser P supprimera les noms de chemin complets sauf si l'archive est une archive légère (thin archive). Notez que P peut être utile lors de l'ajout de fichiers à une archive légère, car r sans P ignore le chemin lors du choix de l'élément à remplacer. Ainsi 
ar rcST archive.a subdir/file1 subdir/file2 file1

remplacera le premier "subdir/file1" par "file1" du répertoire courant. L'ajout de P empêchera ce remplacement.

s
Écrire un index de fichiers objets dans l'archive, ou mettre à jour un index existant, même si aucune autre modification n'est apportée à l'archive. Vous pouvez utiliser ce drapeau de modificateur avec n'importe quelle opération, ou seul. Exécuter ar s sur une archive est équivalent à exécuter ranlib dessus.
S
Ne pas générer de table des symboles d'archive. Cela peut accélérer la construction d'une grande bibliothèque en plusieurs étapes. L'archive résultante ne peut pas être utilisée avec l'éditeur de liens. Pour construire une table des symboles, vous devez omettre le modificateur S lors de la dernière exécution de ar, ou vous devez exécuter ranlib sur l'archive.
T
Alias déprécié pour --thin. T n'est pas recommandé car dans de nombreuses implémentations de ar, T a une signification différente, comme spécifié par X/Open System Interface.
u
Normalement, ar r... insère tous les fichiers listés dans l'archive. Si vous souhaitez insérer uniquement les fichiers listés qui sont plus récents que les membres existants portant les mêmes noms, utilisez ce modificateur. Le modificateur u n'est autorisé que pour l'opération r (remplacer). En particulier, la combinaison qu n'est pas autorisée, car la vérification des horodatages perdrait tout avantage de vitesse de l'opération q.

Note : si une archive a été créée de manière déterministe, par exemple via l'utilisation du modificateur D, alors le remplacement se produira toujours et le modificateur u sera inefficace.

U
Ne pas opérer en mode déterministe. C'est l'inverse du modificateur D, ci-dessus : les fichiers ajoutés et l'index de l'archive recevront leurs valeurs réelles d'UID, GID, horodatage et mode de fichier.

C'est le défaut, sauf si binutils a été configuré avec --enable-deterministic-archives.

v
Ce modificateur demande la version verbeuse d'une opération. De nombreuses opérations affichent des informations supplémentaires, telles que les noms de fichiers traités, lorsque le modificateur v est ajouté.
V
Ce modificateur affiche le numéro de version de ar.

Le programme ar prend également en charge certaines options de ligne de commande qui ne sont ni des modificateurs ni des actions, mais qui modifient son comportement de manière spécifique :

--help
Affiche la liste des options de ligne de commande prises en charge par ar, puis quitte.
--version
Affiche les informations de version de ar, puis quitte.
-X32_64
ar ignore une option initiale épelée -X32_64, pour la compatibilité avec AIX. Le comportement produit par cette option est le défaut pour GNU ar. ar ne prend pas en charge les autres options -X ; en particulier, il ne prend pas en charge -X32 qui est le défaut pour AIX ar.
--plugin name
Le commutateur de ligne de commande optionnel --plugin name fait charger par ar le plugin appelé name, qui ajoute la prise en charge de formats de fichiers supplémentaires, y compris les fichiers objets avec des informations d'optimisation au moment de l'édition des liens.

Cette option n'est disponible que si la chaîne d'outils a été compilée avec la prise en charge des plugins activée.

Si --plugin n'est pas fourni, mais que la prise en charge des plugins a été activée, alors ar itère sur les fichiers dans ${libdir}/bfd-plugins par ordre alphabétique et le premier plugin qui revendique l'objet en question est utilisé.

Veuillez noter que ce répertoire de recherche de plugins n'est *pas* celui utilisé par l'option -plugin de ld. Pour que ar utilise le plugin de l'éditeur de liens, il doit être copié dans le répertoire ${libdir}/bfd-plugins. Pour les compilations basées sur GCC, le plugin de l'éditeur de liens s'appelle liblto_plugin.so.0.0.0. Pour les compilations basées sur Clang, il s'appelle LLVMgold.so. Le plugin GCC est toujours rétrocompatible avec les versions antérieures, il suffit donc de copier le plus récent.

--target target
Le commutateur de ligne de commande optionnel --target bfdname spécifie que les membres de l'archive sont dans un format de code objet différent du format par défaut de votre système. Voir
--output dirname
L'option --output peut être utilisée pour spécifier un chemin vers un répertoire dans lequel les membres de l'archive doivent être extraits. Si cette option n'est pas spécifiée, le répertoire courant sera utilisé.

Note : bien que la présence de cette option implique une opération d'extraction x, cette option doit toujours être incluse dans la ligne de commande.

--record-libdeps libdeps
L'option --record-libdeps est identique au modificateur l, gérée simplement sous forme longue.
--thin
Fait de l'archive spécifiée une archive légère (thin archive). Si elle existe déjà et est une archive régulière, les membres existants doivent être présents dans le même répertoire que l'archive.
@file
Lire les options de ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le file peut lui-même contenir d'autres options @file ; toutes ces options seront traitées récursivement.
