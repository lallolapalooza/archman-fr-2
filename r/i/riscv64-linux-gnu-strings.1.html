STRINGS(1) Outils de développement GNU STRINGS(1)

NOM

strings - affiche les séquences de caractères imprimables dans les fichiers

SYNTAXE

strings [-afovV] [-longueur-min]
[-n longueur-min] [--bytes=longueur-min]
[-t base] [--radix=base]
[-e encodage] [--encoding=encodage]
[-U méthode] [--unicode=méthode]
[-] [--all] [--print-file-name]
[-T nom-bfd] [--target=nom-bfd]
[-w] [--include-all-whitespace]
[-s] [--output-separator chaîne-séparateur]
[--help] [--version] fichier...

DESCRIPTION

Pour chaque fichier donné, GNU strings affiche les séquences de caractères imprimables qui ont une longueur d'au moins 4 caractères (ou le nombre spécifié avec les options ci-dessous) et qui sont suivies par un caractère non imprimable.

Selon la configuration du programme strings, il affichera par défaut toutes les séquences imprimables qu'il peut trouver dans chaque fichier, ou seulement celles qui se trouvent dans les sections de données initialisées et chargées. Si le type de fichier n'est pas reconnaissable, ou si strings lit depuis stdin, il affichera toujours toutes les séquences imprimables qu'il peut trouver.

Par souci de compatibilité ascendante, tout fichier qui apparaît après une option de ligne de commande comme juste - sera également analysé en entier, quelle que soit la présence de l'option -d.

strings est principalement utile pour déterminer le contenu des fichiers non textuels.

OPTIONS

-a
--all
-
Analyse tout le fichier, indépendamment des sections qu'il contient ou si ces sections sont chargées ou initialisées. Normalement, c'est le comportement par défaut, mais strings peut être configuré pour que -d soit le défaut à la place.

L'option - dépend de sa position et force strings à analyser entièrement tout fichier mentionné après le - sur la ligne de commande, même si l'option -d a été spécifiée.

-d
--data
N'affiche que les chaînes provenant des sections de données initialisées et chargées dans le fichier. Cela peut réduire la quantité de "bruit" dans la sortie, mais expose également le programme strings aux éventuelles failles de sécurité présentes dans la bibliothèque BFD utilisée pour analyser et charger les sections. Strings peut être configuré pour que cette option soit le comportement par défaut. Dans ce cas, l'option -a peut être utilisée pour éviter d'utiliser la bibliothèque BFD et afficher plutôt toutes les chaînes trouvées dans le fichier.
-f
--print-file-name
Affiche le nom du fichier avant chaque chaîne.
--help
Affiche un résumé de l'utilisation du programme sur la sortie standard et quitte.
-longueur-min
-n longueur-min
--bytes=longueur-min
Affiche les séquences de caractères affichables qui ont une longueur d'au moins longueur-min caractères. Si non spécifié, une longueur minimum par défaut de 4 est utilisée. La distinction entre caractères affichables et non affichables dépend du réglage des options -e et -U. Les séquences sont toujours terminées par des caractères de contrôle comme la nouvelle ligne et le retour chariot, mais pas par la tabulation.
-o
Comme -t o. Certaines autres versions de strings font que -o agit comme -t d à la place. Comme nous ne pouvons pas être compatibles avec les deux, nous en avons simplement choisi une.
-t base
--radix=base
Affiche le décalage dans le fichier avant chaque chaîne. L'argument d'un seul caractère spécifie la base du décalage : o pour octal, x pour hexadécimal, ou d pour décimal.
-e encodage
--encoding=encodage
Sélectionne l'encodage de caractères des chaînes à rechercher. Les valeurs possibles pour encodage sont : s = caractères d'un octet en 7 bits (par défaut), S = caractères d'un octet en 8 bits, b = 16 bits big-endian, l = 16 bits little-endian, B = 32 bits big-endian, L = 32 bits little-endian. Utile pour trouver des chaînes de caractères larges. (l et b s'appliquent, par exemple, aux encodages Unicode UTF-16/UCS-2).
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multi-octets encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), aucun traitement spécial n'est appliqué, et on s'en remet au réglage de l'option --encoding. Les autres valeurs de cette option activent automatiquement --encoding=S.

L'option --unicode=invalid les traite comme des caractères non graphiques et donc non valides dans une chaîne. Toutes les autres options les traitent comme des caractères de chaîne valides.

L'option --unicode=locale les affiche dans la locale actuelle, qui peut ou non prendre en charge l'encodage UTF-8. L'option --unicode=hex les affiche sous forme de séquences d'octets hexadécimaux entourées de caractères <>. L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en évidence en rouge (si le périphérique de sortie le supporte). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

-T nom-bfd
--target=nom-bfd
Spécifie un format de code objet différent du format par défaut de votre système.
-v
-V
--version
Affiche le numéro de version du programme sur la sortie standard et quitte.
-w
--include-all-whitespace
Par défaut, les caractères tabulation et espace sont inclus dans les chaînes affichées, mais les autres caractères d'espacement, tels que les nouvelles lignes et les retours chariot, ne le sont pas. L'option -w modifie ce comportement pour que tous les caractères d'espacement soient considérés comme faisant partie d'une chaîne.
-s
--output-separator
Par défaut, les chaînes de sortie sont délimitées par une nouvelle ligne. Cette option vous permet de fournir n'importe quelle chaîne à utiliser comme séparateur d'enregistrements de sortie. Utile avec --include-all-whitespace où les chaînes peuvent contenir des nouvelles lignes en interne.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure par un antislash. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.
