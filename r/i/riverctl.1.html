RIVERCTL(1) Manuel des commandes générales RIVERCTL(1)

NOM

riverctl - interface en ligne de commande pour contrôler river

SYNOPSIS

riverctl [options] commande [arguments spécifiques à la commande]

DESCRIPTION

riverctl est un utilitaire en ligne de commande utilisé pour contrôler et configurer river via le protocole Wayland.

OPTIONS

-h

Affiche un message d'aide et quitte.

-version

Affiche le numéro de version et quitte.

TERMINOLOGIE

Ce manuel utilise des termes qui peuvent sembler déroutants pour certains, provenant principalement de leur utilisation dans d'autres projets Wayland.

Le compositeur, le serveur d'affichage, le serveur Wayland, etc. sont des façons de désigner river lui-même.

Une vue (ou toplevel) est ce que la plupart appellent une fenêtre.

Un output est un synonyme d'un écran ou d'un moniteur.

Les tags sont la façon dont river divise les vues d'un output en groupes (pas nécessairement disjoints), une analogie aux espaces de travail.

COMMANDES

ACTIONS

close

Ferme la vue focalisée.

exit

Quitte le compositeur, terminant la session Wayland.

focus-output next|previous|up|right|down|left|nom

Focalise l'output suivant ou précédent, l'output le plus proche dans n'importe quelle direction ou un output par son nom.

focus-view [-skip-floating] next|previous|up|down|left|right

Focalise la vue suivante ou précédente dans la pile ou la vue la plus proche dans n'importe quelle direction.
•
-skip-floating : Ignore les vues flottantes, ne focalise que celles en mosaïque.

move up|down|left|right delta

Déplace la vue focalisée dans la direction spécifiée de delta pixels logiques. La vue sera mise en mode flottant.

resize horizontal|vertical delta

Redimensionne la vue focalisée le long de l'axe donné de delta pixels logiques. La vue sera mise en mode flottant.

snap up|down|left|right

Ancre la vue focalisée sur le bord de l'écran spécifié. La vue sera mise en mode flottant.

send-to-output [-current-tags] next|previous|up|right|down|left|nom

Envoie la vue focalisée vers l'output suivant ou précédent, l'output le plus proche dans n'importe quelle direction ou vers un output par son nom.
•
-current-tags : Assigne les tags actuellement focalisés de l'output de destination à la vue.

spawn commande_shell

Exécute commande_shell en utilisant `/bin/sh -c commande_shell`. Notez que spawn ne prend qu'un seul argument. Pour lancer une commande prenant plusieurs arguments, il est recommandé d'encapsuler la commande entre guillemets.

swap next|previous|up|down|left|right

Échange la vue focalisée avec la vue non flottante suivante ou précédente dans la pile ou la vue non flottante la plus proche dans n'importe quelle direction.

toggle-float

Bascule l'état flottant de la vue focalisée.

toggle-fullscreen

Bascule l'état plein écran de la vue focalisée.

zoom

Remonte la vue focalisée au sommet de la pile de disposition. Si la vue du sommet de la pile est déjà focalisée, remonte la deuxième vue.

default-layout espace_nom

Définit l'espace de noms de disposition à utiliser par défaut pour tous les outputs.

output-layout espace_nom

Définit l'espace de noms de disposition de l'output actuellement focalisé, remplaçant la valeur définie avec default-layout le cas échéant.

send-layout-cmd espace_nom commande

Envoie la commande au générateur de disposition sur l'output actuellement focalisé avec l'espace de noms donné, le cas échéant. Les commandes comprises par un générateur de disposition dépendent de ce générateur. Pour rivertile, consultez la documentation de la page de manuel rivertile(1).

GESTION DES TAGS

Les tags sont similaires aux espaces de travail mais plus flexibles. Vous pouvez assigner plusieurs tags à des vues et focaliser plusieurs tags simultanément. Des champs de bits sont utilisés pour décrire des ensembles de tags lors de l'interaction avec river. Ainsi, les commandes suivantes prennent un nombre normal en base 10 comme argument, mais leur sémantique est mieux comprise en binaire. Le nombre binaire 000000001 représente un ensemble ne contenant que le tag 1, tandis que 100001101 représente un ensemble contenant les tags 1, 3, 4 et 9.

Lorsqu'une vue est lancée, elle se voit attribuer les tags actuellement focalisés de l'output.

Au moins un tag doit toujours être focalisé et chaque vue doit être assignée à au moins un tag. Les opérations qui violeraient l'une ou l'autre de ces exigences sont ignorées par river.

set-focused-tags tags

Affiche les vues avec les tags correspondant aux bits définis de tags sur l'output actuellement focalisé.

set-view-tags tags

Assigne à la vue actuellement focalisée les tags correspondant aux bits définis de tags.

toggle-focused-tags tags

Bascule la visibilité des vues avec les tags correspondant aux bits définis de tags sur l'output actuellement focalisé.

toggle-view-tags tags

Bascule les tags de la vue actuellement focalisée correspondant aux bits définis de tags.

spawn-tagmask masque_tags

Définit un masque_tags pour filtrer les tags assignés aux nouvelles vues lancées. Ce masque sera appliqué aux tags des nouvelles vues avec un ET bit à bit. Si, par exemple, les tags 000011111 sont focalisés et que le masque de lancement masque_tags est 111110001, une nouvelle vue se verra attribuer les tags 000010001. Si aucun tag ne reste après le filtrage, le masque_tags est ignoré.

focus-previous-tags

Définit les tags à leur valeur précédente sur l'output actuellement focalisé, permettant de passer d'une configuration de tags à une autre.

send-to-previous-tags

Assigne à la vue actuellement focalisée les tags précédents de l'output actuellement focalisé.

MAPPINGS

Les mappings sont modaux dans river. Chaque mapping est associé à un mode et n'est actif que pendant ce mode. Il existe deux modes spéciaux : « normal » et « verrouillé ». Le mode normal est le mode initial au démarrage. Le mode verrouillé est automatiquement activé lorsque la session est verrouillée (par exemple, en raison d'un verrouilleur d'écran). Il ne peut être entré ou quitté manuellement.

Les modificateurs suivants sont disponibles pour une utilisation dans les mappings :

  • Shift
  • Control
  • Mod1 (Alt)
  • Mod3
  • Mod4 (Super)
  • Mod5
  • None

Alt et Super sont des alias pour Mod1 et Mod4 respectivement. None permet de créer un mapping sans modificateurs.

Les touches sont spécifiées par leur nom de XKB keysym. Consultez /usr/include/xkbcommon/xkbcommon-keysyms.h pour la liste complète.

Les boutons de la souris sont spécifiés par les noms de code d'événement d'entrée Linux. Les valeurs les plus couramment utilisées sont :

  • BTN_LEFT - bouton gauche de la souris
  • BTN_RIGHT - bouton droit de la souris
  • BTN_MIDDLE - bouton du milieu de la souris

Une liste complète peut être trouvée dans /usr/include/linux/input-event-codes.h

declare-mode nom

Crée un nouveau mode appelé nom.

enter-mode nom

Passe au mode donné s'il existe.

RÈGLES

Les règles font correspondre l'app-id et le titre des vues à un modèle glob. Un glob est une chaîne qui peut éventuellement avoir un * au début et/ou à la fin. Un * dans un glob correspond à zéro ou plusieurs caractères arbitraires dans l'app-id ou le titre.

Par exemple, abc correspond à a*, *a*, *b*, *c, abc, et *, mais ne correspond pas à *a, b*, *b, c*, ou ab. Notez que * correspond à tout, tandis que ** et la chaîne vide sont invalides.

rule-add [-app-id glob|-title glob] action [arguments]

Ajoute une règle qui applique une action aux vues dont l'app-id et le titre correspondent aux glob respectifs. Omettre -app-id ou -title est équivalent à passer -app-id * ou -title *. Certaines actions nécessitent un ou plusieurs arguments.

Les types d'action pris en charge sont :

  • float : Rend la vue flottante. S'applique uniquement aux nouvelles vues.
  • no-float : Ne rend pas la vue flottante. S'applique uniquement aux nouvelles vues.
  • ssd : Utilise les décorations côté serveur pour la vue. S'applique aux nouvelles vues et aux vues existantes.
  • csd : Utilise les décorations côté client pour la vue. S'applique aux nouvelles vues et aux vues existantes.
  • tags : Définit les étiquettes initiales de la vue. Nécessite les étiquettes comme argument. S'applique uniquement aux nouvelles vues.
  • output : Définit la sortie initiale de la vue. Nécessite la sortie comme argument. S'applique uniquement aux nouvelles vues. La sortie peut être spécifiée soit par le nom du connecteur (tel que HDMI-A-1 ou DP-2), soit par un identifiant sous la forme FABRICANT MODÈLE NUMÉRO_DE_SÉRIE, par exemple pour une sortie avec fabricant : HP Inc., modèle : HP 22w, et numéro de série : CNC93720WF, l'identifiant serait : HP Inc. HP 22w CNC93720WF. Si le fabricant, le modèle ou le numéro de série est inconnu, le mot "Unknown" (Inconnu) est utilisé à la place.
  • position : Définit la position initiale de la vue, en la contraignant aux limites de la sortie. Nécessite les coordonnées x et y de la vue comme arguments, qui doivent tous deux être non négatifs. S'applique uniquement aux nouvelles vues.
  • dimensions : Définit les dimensions initiales de la vue, en les contraignant aux contraintes de la vue. Nécessite la largeur et la hauteur de la vue comme arguments, qui doivent toutes deux être non négatives. S'applique uniquement aux nouvelles vues.
  • fullscreen : Rend la vue plein écran. S'applique uniquement aux nouvelles vues.
  • no-fullscreen : Ne rend pas la vue plein écran. S'applique uniquement aux nouvelles vues.
  • tearing : Permet à la vue de se déchirer lorsqu'elle est en plein écran, quelle que soit la préférence de la vue. S'applique aux nouvelles vues et aux vues existantes.
  • no-tearing : Désactive le déchirement pour la vue, quelle que soit la préférence de la vue. S'applique aux nouvelles vues et aux vues existantes.

Les règles float et no-float sont ajoutées à la même liste, ce qui signifie qu'ajouter une règle no-float avec les mêmes arguments qu'une règle float la remplacera. Il en va de même pour les règles ssd et csd, fullscreen et no-fullscreen, tearing et no-tearing.

Si plusieurs règles d'une liste correspondent à une vue donnée, la règle la plus spécifique sera appliquée. Par exemple, avec les règles suivantes :

app-id  title  action
foo     bar    ssd
foo     *      csd
*       bar    csd
*       baz    ssd
une vue avec l'app-id 'foo' et le titre 'bar' obtiendra le ssd malgré la correspondance avec deux règles csd, car la première règle est la plus spécifique. De plus, une vue avec l'app-id 'foo' et le titre 'baz' obtiendra le csd malgré la correspondance avec la dernière règle de la liste, car la spécificité de l'app-id prime sur la spécificité du titre.

Si une vue n'est correspondue par aucune règle, river respectera les souhaits csd/ssd du client et pourra démarrer la vue en mode flottant en fonction d'heuristiques simples destinées à attraper les vues de type popup.

Si une vue est lancée en plein écran ou n'est pas flottante, les règles position et dimensions n'auront aucun effet. Une vue doit être mise en correspondance par une règle float pour qu'elles prennent effet.

rule-del [-app-id glob|-title glob] action

Supprime une règle créée à l'aide de rule-add avec les arguments donnés.

list-rules float|ssd|tags|position|dimensions|fullscreen

Affiche la liste de règles spécifiée. La sortie est ordonnée du plus spécifique au moins spécifique, le même ordre dans lequel les vues sont vérifiées lors de la recherche d'une correspondance. Seule la première règle correspondante dans la liste a un effet sur une vue donnée.

CONFIGURATION

default-attach-mode top|bottom|above|below|after <N>

Définit le mode d'attachement qui sera utilisé par toutes les sorties par défaut.

Valeurs possibles :

  • top : Prépare la vue nouvellement créée en haut de la pile.
  • bottom : Ajoute la vue nouvellement créée en bas de la pile.
  • above : Insère la vue nouvellement créée au-dessus de la vue actuellement focalisée.
  • below : Insère la vue nouvellement créée en dessous de la vue actuellement focalisée.
  • after <N> : Insère la vue nouvellement créée après N vues dans la pile.

Notez que la commande obsolète attach-mode est aliasée à default-attach-mode pour des raisons de compatibilité descendante.

output-attach-mode top|bottom|above|below|after <N>

Définit le mode d'attachement de la sortie actuellement focalisée, écrasant la valeur de default-attach-mode s'il y en a une.

allow-tearing enabled|disabled

Permet aux vues en plein écran de se déchirer si elles le demandent. Voir aussi la règle tearing pour forcer l'activation du déchirement pour des vues spécifiques.

background-color 0xRRGGBB|0xRRGGBBAA

Définit la couleur de fond.

border-color-focused 0xRRGGBB|0xRRGGBBAA

Définit la couleur de la bordure des vues focalisées.

border-color-unfocused 0xRRGGBB|0xRRGGBBAA

Définit la couleur de la bordure des vues non focalisées.

border-color-urgent 0xRRGGBB|0xRRGGBBAA

Définit la couleur de la bordure des vues urgentes.

border-width pixels

Définit la largeur de la bordure à pixels.

COMMANDS

set-focused-cursor-follows-mouse enabled|disabled|normal

Controls how the cursor focuses views.
  • disabled: Cursor position does not affect focus. This is the default.
  • normal: Moving the cursor over a view will focus that view. Moving the cursor within a view will not re-focus that view if focus has moved elsewhere.
  • always: Moving the cursor will always focus whatever view is under the cursor.

If the view to be focused is on an output that does not have focus, focus is switched to that output.

hide-cursor timeout timeout

Hide the cursor if it wasn't moved in the last timeout milliseconds until it is moved again. The default value is 0, which disables automatically hiding the cursor. Show the cursor again on any movement.

hide-cursor when-typing enabled|disabled

Hide the cursor when pressing any non-modifier key. Show the cursor again on any movement.

set-cursor-warp disabled|on-output-change|on-focus-change

Set the cursor warp mode. There are two available modes:
  • disabled: Cursor will not be warped. This is the default.
  • on-output-change: When a different output is focused, the cursor will be warped to its center.
  • on-focus-change: When a different view/output is focused, the cursor will be warped to its center.

set-repeat rate delay

Set the keyboard repeat rate to rate key repeats per second and repeat delay to delay milliseconds. The default is a rate of 25 repeats per second and a delay of 600ms.

xcursor-theme theme_name [size]

Set the xcursor theme to theme_name and optionally set the size. The theme of the default seat determines the default for Xwayland and is made available through the XCURSOR_THEME and XCURSOR_SIZE environment variables.

CONFIGURATION DES ENTRÉES

list-inputs

Liste tous les périphériques d'entrée.

list-input-configs

Liste toutes les configurations d'entrée.

keyboard-layout [-rules rules] [-model model] [-variant variant] [-options options] layout

Définit la disposition XKB pour tous les claviers. Les paramètres par défaut de libxkbcommon sont utilisés pour tout ce qui n'est pas spécifié. Notez que layout peut être une liste de dispositions séparées par des virgules (par exemple, "us,de") qui peuvent être permutées à l'aide de diverses combinaisons de touches configurées via l'argument options (par exemple, -options "grp:ctrl_space_toggle"). Voir xkeyboard-config(7) pour les valeurs possibles et plus d'informations.

keyboard-layout-file path

Définit la disposition XKB pour tous les claviers à partir d'un fichier de configuration de clavier XKB situé au chemin fourni. La documentation du format de fichier de configuration de clavier XKB se trouve à l'URL suivante : https://xkbcommon.org/doc/current/keymap-text-format-v1.html

La commande input peut être utilisée pour créer une règle de configuration pour un périphérique d'entrée identifié par son nom. Le nom d'un périphérique d'entrée se compose de son type, de son identifiant vendeur décimal, de son identifiant produit décimal et enfin de son nom autoproclamé, séparés par -. Des modèles de correspondance simples sont pris en charge, voir la section des règles pour plus d'informations sur les modèles.

Une liste de toutes les propriétés de périphérique pouvant être configurées se trouve ci-dessous. Notez cependant que tous les périphériques d'entrée ne prennent pas en charge toutes les propriétés.

input name events enabled|disabled|disabled-on-external-mouse

Configure si les événements des périphériques d'entrée seront utilisés par river.

input name accel-profile none|flat|adaptive

Définit le profil d'accélération du pointeur du périphérique d'entrée.

input name pointer-accel factor

Définit le facteur d'accélération du pointeur du périphérique d'entrée. Nécessite un flottant entre -1.0 et 1.0.

input name click-method none|button-areas|clickfinger

Définit la méthode de clic du périphérique d'entrée.

input name drag enabled|disabled

Active ou désactive la fonctionnalité de glisser-déposer (tap-and-drag) du périphérique d'entrée.

input name drag-lock enabled|disabled

Active ou désactive la fonctionnalité de verrouillage du glisser-déposer (drag lock) du périphérique d'entrée.

input name disable-while-typing enabled|disabled

Active ou désactive la fonctionnalité de désactivation pendant la frappe (disable-while-typing) du périphérique d'entrée.

input name disable-while-trackpointing enabled|disabled

Active ou désactive la fonctionnalité de désactivation pendant le trackpointing (disable-while-trackpointing) du périphérique d'entrée.

input name middle-emulation enabled|disabled

Active ou désactive la fonctionnalité d'émulation du clic du milieu (middle click emulation) du périphérique d'entrée.

input name natural-scroll enabled|disabled

Active ou désactive la fonctionnalité de défilement naturel (natural scroll) du périphérique d'entrée. Si elle est active, la direction du défilement est inversée.

input name scroll-factor factor

Définit le facteur de défilement du périphérique d'entrée. Accepte une valeur positive supérieure à 0. Par exemple, un factor de 0.5 ralentira le défilement de moitié tandis qu'un factor de 3 l'accélérera 3 fois.

input name left-handed enabled|disabled

Active ou désactive le mode gaucher (left handed) du périphérique d'entrée.

input name tap enabled|disabled

Active ou désactive la fonctionnalité de tapotement (tap) du périphérique d'entrée.

input name tap-button-map left-right-middle|left-middle-right

Configure le mappage des boutons pour le tapotement.
  • left-right-middle : un tapotement à 1 doigt équivaut à un clic gauche, un tapotement à 2 doigts à un clic droit, un tapotement à 3 doigts à un clic milieu.
  • left-middle-right : un tapotement à 1 doigt équivaut à un clic gauche, un tapotement à 2 doigts à un clic milieu, un tapotement à 3 doigts à un clic droit.

input name scroll-method none|two-finger|edge|button

Définit la méthode de défilement du périphérique d'entrée.
  • none : pas de défilement
  • two-finger : défilement en glissant avec deux doigts simultanément
  • edge : défilement en glissant le long du bord
  • button : défilement avec le mouvement du pointeur tout en maintenant un bouton enfoncé

input name scroll-button button

Définit le bouton de défilement d'un périphérique d'entrée. button est le nom d'un code d'événement d'entrée Linux.

input name scroll-button-lock enabled|disabled

Active ou désactive la fonctionnalité de verrouillage du bouton de défilement (scroll button lock) du périphérique d'entrée. Si elle est active, le bouton n'a pas besoin d'être maintenu enfoncé. Une pression le fait considérer comme enfoncé, et une seconde pression le relâche.

input name map-to-output output|disabled

Mappe l'entrée vers une sortie donnée. Ceci est valide même si la sortie n'est pas actuellement active et entraînera le mappage du périphérique une fois qu'il sera connecté.

EXEMPLES

Lier Super+Retour en mode normal pour lancer un terminal foot(1):

riverctl map normal Mod4 Return spawn 'foot --app-id=foobar'

Lier Super+Shift+J pour échanger la vue focalisée avec la vue visible suivante :

riverctl map normal Mod4+Shift J swap next
