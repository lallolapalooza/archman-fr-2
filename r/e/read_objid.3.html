DESCRIPTION

Les fonctions traitant des modules MIB se répartissent en quatre groupes : celles qui gèrent l'initialisation et l'arrêt, celles qui lisent et analysent les fichiers MIB, celles qui recherchent dans l'arbre MIB, et les routines de sortie.

Initialisation et arrêt

add_mibdir est utilisée pour ajouter le répertoire spécifié au chemin des emplacements qui sont recherchés pour trouver les fichiers contenant des modules MIB. Notez que cela ne charge pas réellement les modules MIB situés dans ce répertoire, mais constitue simplement une étape d'initialisation pour les rendre disponibles à netsnmp_read_module. Cette fonction renvoie le nombre de fichiers trouvés dans le répertoire, ou -1 en cas d'erreur. Elle doit être appelée avant d'invoquer netsnmp_init_mib.

netsnmp_init_mib configure le chemin de recherche des répertoires MIB (en utilisant add_mibdir), met en place le cadre MIB interne, puis charge les modules MIB appropriés (en utilisant netsnmp_read_module et read_mib). Voir la section VARIABLES D'ENVIRONNEMENT pour plus de détails.
Elle doit être appelée avant toute autre routine qui manipule ou accède à l'arbre MIB (mais après tout appel supplémentaire à add_mibdir).

shutdown_mib effacera les informations qui ont été collectées par netsnmp_read_module, add_mibdir et add_module_replacement. Il est fortement recommandé de ne pas invoquer shutdown_mib pendant que des sessions SNMP sont activement gérées.

Lecture et analyse des MIB

netsnmp_read_module prend le nom d'un module MIB (qui n'a pas besoin d'être identique au nom du fichier qui contient le module), le localise dans la liste configurée des répertoires MIB, et charge les définitions du module dans l'arbre MIB actif. Elle charge également tous les modules MIB listés dans la clause IMPORTS de ce module.

read_mib est similaire, mais prend le nom du fichier contenant le module MIB. Notez que ce fichier n'a pas besoin d'être situé dans la liste de recherche des répertoires MIB (bien que les modules listés dans la clause IMPORTS le soient).

read_all_mibs lira tous les modules MIB trouvés dans la liste de recherche des répertoires MIB.

En général, l'analyseur est silencieux quant aux bizarreries qu'il rencontre dans les fichiers MIB. Pour obtenir des avertissements, appelez snmp_set_mib_warnings avec un level de 1 (ou 2 pour encore plus d'avertissements).

add_module_replacement peut être utilisé pour permettre aux nouveaux modules MIB d'en remplacer d'anciens, sans avoir à modifier les clauses IMPORTS des autres modules. Il prend les noms des anciens et des nouveaux modules, ainsi qu'une indication des portions de l'ancien module qui sont affectées.

tag len charge le nouveau module lorsque :
NULL 0 toujours (l'ancien module est un sous-ensemble strict
du nouveau)
nom 0 pour la balise donnée uniquement
nom non-0 pour tout identifiant avec ce préfixe
Il peut également être utilisé pour gérer les erreurs dans les identificateurs de module utilisés dans les clauses IMPORTS MIB (comme faire référence à RFC1213 au lieu de RFC1213-MIB).

Recherche dans l'arbre MIB

read_objid prend une chaîne contenant une version textuelle d'un identifiant d'objet (sous forme numérique ou descripteur), et la transforme en la liste correspondante de sous-identifiants. Ceci est retourné dans le paramètre output, avec le nombre de sous-identifiants retourné via out_len. Lors de l'appel, out_len doit contenir la longueur maximale du tableau output. Si plusieurs identifiants d'objet sont traités, cette longueur doit être réinitialisée avant chaque appel. Cette fonction renvoie 1 si elle réussit à analyser la chaîne, et 0 sinon.

snmp_parse_oid est similaire, mais renvoie un pointeur vers le tampon OID analysé (ou NULL).

get_module_node prend un descripteur et le nom d'un module, et renvoie la liste OID correspondante, de la même manière que read_objid ci-dessus.
Si le nom du module est spécifié comme "ANY", cette routine suppose que le descripteur donné est unique dans l'arbre, et renverra l'entrée correspondante. Si cette hypothèse est invalide, le comportement quant à la variable retournée dépend de l'implémentation.

Sortie

print_mib imprimera une représentation de l'arbre MIB actif actuellement sur le pointeur FILE spécifié.

print_objid prendra un identifiant d'objet (tel que retourné par read_objid, snmp_parse_oid ou get_module_node), et imprimera la forme textuelle de cet OID sur la sortie standard.

fprint_objid fait la même chose, mais imprime sur le pointeur FILE spécifié par le paramètre initial.

snprint_objid imprime les mêmes informations dans le tampon pointé par buf, qui a une longueur de len. Elle renvoie le nombre de caractères imprimés, ou -1 si le tampon n'était pas assez grand. Dans ce dernier cas, buf contiendra généralement une version tronquée des informations (mais ce comportement n'est pas garanti).

print_description, fprint_description, et snprint_description prennent un identifiant d'objet similaire et impriment une version de la définition MIB pour cet objet, avec l'OID complet. L'argument width contrôle la disposition de l'OID.

Par défaut, l'analyseur ne sauvegarde pas les descriptions car elles peuvent être énormes. Afin de pouvoir les imprimer, il est nécessaire d'invo

ke snmp_set_save_descriptions(1) avant d'appeler init_mib (ou similaire).

VARIABLES ENVIRONNEMENTALES

La principale utilisation des variables d'environnement concernant ces appels d'API est de configurer les modules MIB qui doivent être chargés et où ils sont situés.

MIBDIRS
Une liste de répertoires séparés par des deux-points où chercher les modules MIB.
Par défaut : /usr/share/snmp/mibs
Utilisé par init_mib, netsnmp_read_module, read_all_mibs et (implicitement) par read_mib.
MIBS
Une liste de modules MIB séparés par des deux-points à charger.
La liste par défaut des modules dépendra de la façon dont le logiciel Net-SNMP a été compilé à l'origine, mais c'est généralement :
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
Si la valeur de la variable d'environnement MIBS commence par un caractère '+', alors ces modules MIB seront ajoutés à la liste par défaut. Sinon, ces modules (plus ceux dont ils font une IMPORT) seront chargés *à la place* de la liste par défaut.
Si la variable d'environnement MIBS a la valeur ALL, alors read_all_mibs sera appelée pour charger la collection complète de tous les modules MIB disponibles.
Utilisé par init_mib uniquement.
MIBFILES
Une liste de fichiers séparés par des deux-points à charger.
Par défaut : (aucun)
Utilisé par init_mib uniquement.
