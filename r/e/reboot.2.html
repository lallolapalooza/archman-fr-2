reboot(2) Manuel des appels système reboot(2)

NOM

reboot - redémarrer ou activer/désactiver Ctrl-Alt-Suppr

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

/* Depuis Linux 2.1.30 il existe des noms symboliques LINUX_REBOOT_*
   pour les constantes et un quatrième argument à l'appel : */
#include <linux/reboot.h>  /* Définition des constantes LINUX_REBOOT_* */
#include <sys/syscall.h>   /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_reboot, int magic, int magic2, int op, void *arg);
/* Sous glibc et la plupart des libc alternatives (y compris uclibc, dietlibc,
   musl et quelques autres), certains des constantes impliquées ont des noms
   symboliques RB_*, et l'appel bibliothèque est une enveloppe à 1 argument
   autour de l'appel système : */
#include <sys/reboot.h>    /* Définition des constantes RB_* */
#include <unistd.h>
int reboot(int op);

DESCRIPTION

L'appel reboot() redémarre le système, ou active/désactive la combinaison de touches de redémarrage (abréviée CAD, puisque la valeur par défaut est Ctrl-Alt-Suppr; elle peut être changée en utilisant loadkeys(1)).

Cet appel système échoue (avec l'erreur EINVAL) à moins que magic n'ait la valeur LINUX_REBOOT_MAGIC1 (c'est-à-dire 0xfee1dead) et magic2 la valeur LINUX_REBOOT_MAGIC2 (c'est-à-dire 0x28121969). Cependant, depuis Linux 2.1.17, LINUX_REBOOT_MAGIC2A (c'est-à-dire 0x05121996) et depuis Linux 2.1.97, LINUX_REBOOT_MAGIC2B (c'est-à-dire 0x16041998) et depuis Linux 2.5.71, LINUX_REBOOT_MAGIC2C (c'est-à-dire 0x20112000) sont aussi autorisés comme valeurs pour magic2. (Les valeurs hexadécimales de ces constantes ont un sens.)

L'argument op peut avoir les valeurs suivantes :

LINUX_REBOOT_CMD_CAD_OFF
(RB_DISABLE_CAD, 0). CAD est désactivé. Cela signifie que la touche CAD enverra un signal SIGINT à init (processus 1), lequel pourra alors décider d'une action appropriée (peut-être : tuer tous les processus, synchroniser, redémarrer).
LINUX_REBOOT_CMD_CAD_ON
(RB_ENABLE_CAD, 0x89abcdef). CAD est activé. Cela signifie que la touche CAD provoquera immédiatement l'action associée à LINUX_REBOOT_CMD_RESTART.
LINUX_REBOOT_CMD_HALT
(RB_HALT_SYSTEM, 0xcdef0123 ; depuis Linux 1.1.76). Le message "System halted." est affiché, et le système est arrêté. Le contrôle est rendu au moniteur ROM, s'il y en a un. Si non précédé d'une commande sync(2), des données seront perdues.
LINUX_REBOOT_CMD_KEXEC
(RB_KEXEC, 0x45584543, depuis Linux 2.6.13). Exécute un noyau qui a été préalablement chargé avec kexec_load(2). Cette option n'est disponible que si le noyau a été configuré avec CONFIG_KEXEC.
LINUX_REBOOT_CMD_POWER_OFF
(RB_POWER_OFF, 0x4321fedc ; depuis Linux 2.1.30). Le message "Power down." est affiché, le système est arrêté, et toute alimentation est retirée du système, si possible. Si non précédé d'une commande sync(2), des données seront perdues.
LINUX_REBOOT_CMD_RESTART
(RB_AUTOBOOT, 0x1234567). Le message "Restarting system." est affiché, et un redémarrage par défaut est effectué immédiatement. Si non précédé d'une commande sync(2), des données seront perdues.
LINUX_REBOOT_CMD_RESTART2
(0xa1b2c3d4 ; depuis Linux 2.1.30). Le message "Restarting system with command '%s'" est affiché, et un redémarrage (utilisant la chaîne de commande donnée dans arg) est effectué immédiatement. Si non précédé d'une commande sync(2), des données seront perdues.
LINUX_REBOOT_CMD_SW_SUSPEND
(RB_SW_SUSPEND, 0xd000fce1 ; depuis Linux 2.5.18). Le système est suspendu (mis en veille prolongée) sur disque. Cette option n'est disponible que si le noyau a été configuré avec CONFIG_HIBERNATION.

Seul le superutilisateur peut appeler reboot().

L'effet précis des actions ci-dessus dépend de l'architecture. Pour l'architecture i386, l'argument supplémentaire n'a pas d'effet pour le moment (2.1.122), mais le type de redémarrage peut être déterminé par des arguments de ligne de commande du noyau ("reboot=...") pour être soit chaud, soit froid, et soit dur, soit via le BIOS.

Comportement à l'intérieur des espaces de noms PID

Depuis Linux 3.4, si reboot() est appelé depuis un espace de noms PID autre que l'espace de noms PID initial avec l'une des valeurs op listées ci-dessous, il effectue un "redémarrage" de cet espace de noms : le processus "init" de l'espace de noms PID est immédiatement terminé, avec les effets décrits dans pid_namespaces(7).

Les valeurs qui peuvent être fournies dans op lors de l'appel de reboot() dans ce cas sont les suivantes :

LINUX_REBOOT_CMD_RESTART
LINUX_REBOOT_CMD_RESTART2
Le processus "init" est terminé, et wait(2) dans le processus parent signale que l'enfant a été tué avec le signal SIGHUP.
LINUX_REBOOT_CMD_POWER_OFF
LINUX_REBOOT_CMD_HALT
Le processus "init" est terminé, et wait(2) dans le processus parent signale que l'enfant a été tué avec le signal SIGINT.

Pour les autres valeurs de op, reboot() renvoie -1 et errno est mis à EINVAL.

VALEUR DE RETOUR

Pour les valeurs de op qui arrêtent ou redémarrent le système, un appel réussi à reboot() ne retourne pas. Pour les autres valeurs de op, zéro est renvoyé en cas de succès. Dans tous les cas, -1 est renvoyé en cas d'échec, et errno est configuré pour indiquer l'erreur.

ERREURS

EFAULT
Problème lors de la récupération de données de l'espace utilisateur sous LINUX_REBOOT_CMD_RESTART2.
EINVAL
Nombres magiques ou op invalides.
EPERM
Le processus appelant n'a pas les privilèges suffisants pour appeler reboot ; l'appelant doit posséder la capacité CAP_SYS_BOOT dans son espace de noms utilisateur.

NORMES

Linux.

VOIR AUSSI

systemctl(1), systemd(1), kexec_load(2), sync(2), bootparam(7), capabilities(7), ctrlaltdel(8)
