READ(1P) Manuel du programmeur POSIX READ(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

read — lire depuis l'entrée standard dans des variables shell

SYNTAXE

read [-r] var...

DESCRIPTION

L'utilitaire read lira une seule ligne logique depuis l'entrée standard dans une ou plusieurs variables shell.

Par défaut, sauf si l'option -r est spécifiée, le <backslash> agira comme un caractère d'échappement. Un <backslash> non échappé préservera la valeur littérale du caractère suivant, à l'exception du <newline>. Si un <newline> suit le <backslash>, l'utilitaire read interprétera cela comme une continuation de ligne. Le <backslash> et le <newline> seront supprimés avant de diviser l'entrée en champs. Tous les autres caractères <backslash> non échappés seront supprimés après la division de l'entrée en champs.

Si l'entrée standard est un périphérique terminal et que le shell invocateur est interactif, read affichera une invite pour une ligne de continuation lorsqu'il lira une ligne d'entrée se terminant par un <backslash> <newline>, sauf si l'option -r est spécifiée.

Le <newline> de terminaison (le cas échéant) sera supprimé de l'entrée et les résultats seront divisés en champs comme pour le shell lors des résultats de l'expansion des paramètres (voir Section 2.6.5, Division en champs) ; le premier champ sera affecté à la première variable var, le second champ à la seconde variable var, et ainsi de suite. S'il y a moins de champs qu'il n'y a d'opérandes var, les var restantes seront définies comme des chaînes vides. S'il y a moins de var que de champs, la dernière var sera définie à une valeur comprenant les éléments suivants :

*
Le champ qui correspond à la dernière var dans la séquence d'affectation normale décrite ci-dessus
*
Le ou les délimiteurs qui suivent le champ correspondant à la dernière var
*
Les champs restants et leurs délimiteurs, avec les espaces blancs IFS en fin de chaîne ignorés

Le réglage des variables spécifiées par les opérandes var affectera l'environnement d'exécution du shell courant ; voir Section 2.12, Environnement d'exécution du shell. Si elle est appelée dans un sous-shell ou un environnement d'exécution d'utilitaire séparé, tel qu'un des éléments suivants :

(read foo)
nohup read ...
find . -exec read ... \;

elle n'affectera pas les variables shell dans l'environnement de l'appelant.

OPTIONS

L'utilitaire read sera conforme aux Définitions de Base du volume de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

L'option suivante est prise en charge :

-r
Ne pas traiter le caractère <backslash> de manière spéciale. Considérer chaque <backslash> comme faisant partie de la ligne d'entrée.

OPERANDES

L'opérande suivant sera pris en charge :

var
Le nom d'une variable shell existante ou non.

ENTRÉE STANDARD

L'entrée standard sera un fichier texte.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de read :

IFS
Détermine les séparateurs de champs internes utilisés pour délimiter les champs ; voir Section 2.5.3, Variables Shell.
LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de Base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par rapport à multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PS2
Fournit la chaîne d'invite qu'un shell interactif écrira sur la sortie standard lorsqu'une ligne se terminant par un <backslash> <newline> est lue et que l'option -r n'a pas été spécifiée.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Non utilisé.

ERREUR STANDARD

La sortie standard sera utilisée pour les messages de diagnostic et les invites pour la continuation de l'entrée.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
La fin du fichier a été détectée ou une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION APPLICATIVE

L'option -r est incluse pour permettre à read d'englober le but de l'utilitaire line, qui n'est pas inclus dans POSIX.1‐2008.

EXEMPLES

La commande suivante :

while read -r xx yy
do
    printf "%s %s\n$yy$xx"
done < fichier_entree

imprime un fichier en déplaçant le premier champ de chaque ligne vers la fin de la ligne.

RATIONALE

L'utilitaire read était historiquement une commande intégrée du shell. Il a été séparé en son propre utilitaire pour bénéficier de la description plus riche de la fonctionnalité introduite par ce volume de POSIX.1‐2017.

Puisque read affecte l'environnement d'exécution du shell courant, il est généralement fourni comme une commande intégrée régulière du shell. S'il est appelé dans un sous-shell ou un environnement d'exécution d'utilitaire séparé, tel qu'un des éléments suivants :

(read foo)
nohup read ...
find . -exec read ... \;

il n'affecte pas les variables shell dans l'environnement de l'appelant.

RATIONALE

L'omission des lignes de continuation lors de l'utilisation de l'option -r peut entraîner une fin de fichier d'entrée qui ne se termine pas par un <newline>. Cela se produit si la dernière ligne du fichier d'entrée se termine par un <backslash> suivi d'un <newline>. C'est pour cette raison que ``si elle existe'' est utilisé dans ``La <newline> de terminaison (si elle existe) doit être supprimée de l'entrée'' dans la description. Il ne s'agit pas d'une relaxation de l'exigence que l'entrée standard soit un fichier texte.
