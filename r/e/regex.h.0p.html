regex.h(0P) Manuel du programmeur POSIX regex.h(0P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

regex.h — types de correspondance d'expressions régulières

SYNOPIS

#include <regex.h>

DESCRIPTION

L'en-tête <regex.h> définira les structures et les constantes symboliques utilisées par les fonctions regcomp(), regexec(), regerror() et regfree().

L'en-tête <regex.h> définira le type de structure regex_t, qui inclura au moins le membre suivant :

size_t    re_nsub    Nombre d'expressions secondaires entre parenthèses.

L'en-tête <regex.h> définira le type size_t tel que décrit dans <sys/types.h>.

L'en-tête <regex.h> définira le type regoff_t comme un type entier signé capable de contenir la plus grande valeur pouvant être stockée dans un type ptrdiff_t ou un type ssize_t.

L'en-tête <regex.h> définira le type de structure regmatch_t, qui inclura au moins les membres suivants :

regoff_t    rm_so    Décalage en octets depuis le début de la chaîne
                     jusqu'au début de la sous-chaîne.
regoff_t    rm_eo    Décalage en octets depuis le début de la chaîne jusqu'au
                     premier caractère après la fin de la sous-chaîne.

L'en-tête <regex.h> définira les constantes symboliques suivantes pour le paramètre cflags de la fonction regcomp() :

REG_EXTENDED
Utiliser les expressions régulières étendues.
REG_ICASE
Ignorer la casse lors de la correspondance.
REG_NOSUB
Rapporter seulement le succès ou l'échec dans regexec().
REG_NEWLINE
Modifier le traitement des sauts de ligne (<newline>).

L'en-tête <regex.h> définira les constantes symboliques suivantes pour le paramètre eflags de la fonction regexec() :

REG_NOTBOL
Le caractère circonflexe ('^'), lorsqu'il est pris comme caractère spécial, ne correspond pas au début de string.
REG_NOTEOL
Le signe dollar ('$'), lorsqu'il est pris comme caractère spécial, ne correspond pas à la fin de string.

L'en-tête <regex.h> définira les constantes symboliques suivantes comme valeurs de retour d'erreur :

REG_NOMATCH
regexec() n'a pas trouvé de correspondance.
REG_BADPAT
Expression régulière invalide.
REG_ECOLLATE
Élément de tri invalide référencé.
REG_ECTYPE
Type de classe de caractères invalide référencé.
REG_EESCAPE
Caractère antislash (\) final dans le motif.
REG_ESUBREG
Numéro dans \chiffre invalide ou en erreur.
REG_EBRACK
Déséquilibre "[]".
REG_EPAREN
Déséquilibre "\(\)" ou "()".
REG_EBRACE
Déséquilibre "\{\}".
REG_BADBR
Contenu de "\{\}" invalide : pas un nombre, nombre trop grand, plus de deux nombres, premier plus grand que le second.
REG_ERANGE
Point de terminaison invalide dans l'expression de plage.
REG_ESPACE
Manque de mémoire.
REG_BADRPT
'?', '*' ou '+' non précédé d'une expression régulière valide.

Les éléments suivants seront déclarés comme fonctions et pourront également être définis comme macros. Des prototypes de fonctions seront fournis.

int    regcomp(regex_t *restrict, const char *restrict, int);
size_t regerror(int, const regex_t *restrict, char *restrict, size_t);
int    regexec(const regex_t *restrict, const char *restrict, size_t,
           regmatch_t [restrict], int);
void   regfree(regex_t *);

L'implémentation peut définir des macros ou constantes supplémentaires utilisant des noms commençant par REG_.
