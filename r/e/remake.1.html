REMAKE(1) Commandes utilisateur REMAKE(1)

NOM

remake - utilitaire GNU make pour maintenir des groupes de programmes

SYNTAXE

remake [OPTION]... [CIBLE]...

DESCRIPTION

L'utilitaire remake déterminera automatiquement quelles pièces d'un grand programme doivent être recompilées et émettra les commandes pour les recompiler. Le manuel décrit l'implémentation GNU de make dont remake est dérivé, qui a été écrite par Richard Stallman et Roland McGrath, et est actuellement maintenue par Paul Smith. Des extensions de rapport d'erreurs, de débogueur et de profilage ont été écrites par Rocky Bernstein. Nos exemples montrent des programmes C, car ils sont très courants, mais vous pouvez utiliser remake avec n'importe quel langage de programmation dont le compilateur peut être exécuté avec une commande shell. En fait, remake ou make ne sont pas limités aux programmes. Vous pouvez l'utiliser pour décrire toute tâche où certains fichiers doivent être mis à jour automatiquement à partir d'autres lorsque ces derniers changent.

Pour vous préparer à utiliser remake, vous devez écrire un fichier appelé makefile qui décrit les relations entre les fichiers de votre programme et les commandes pour mettre à jour chaque fichier. Dans un programme, généralement le fichier exécutable est mis à jour à partir des fichiers objets, qui sont eux-mêmes créés en compilant les fichiers source.

Une fois qu'un makefile approprié existe, chaque fois que vous modifiez certains fichiers source, cette simple commande shell :

remake

suffit à effectuer toutes les recompilations nécessaires. Le programme remake utilise la description du makefile et les heures de dernière modification des fichiers pour décider lesquels doivent être mis à jour. Pour chacun de ces fichiers, il émet les commandes enregistrées dans le makefile.

remake exécute les commandes dans le makefile pour mettre à jour un ou plusieurs noms cibles, où nom est typiquement un programme. Si aucune option -f n'est présente, remake recherchera les makefiles GNUmakefile, makefile, et Makefile, dans cet ordre.

Normalement, vous devriez nommer votre makefile soit makefile, soit Makefile. (Nous recommandons Makefile car il apparaît bien en évidence au début d'une liste de répertoires, juste à côté d'autres fichiers importants tels que README.) Le premier nom vérifié, GNUmakefile, n'est pas recommandé pour la plupart des makefiles. Vous devriez utiliser ce nom si vous avez un makefile spécifique à remake de GNU, et qui ne sera pas compris par les autres versions de remake. Si makefile est '-', l'entrée standard sera lue.

remake met à jour une cible si elle dépend de fichiers prérequis qui ont été modifiés depuis la dernière modification de la cible, ou si la cible n'existe pas.

OPTIONS

Ci-dessous, nous donnons les options spécifiques à remake. Pour les autres options, veuillez vous référer à la documentation GNU Make.

-c, --search-parent
si un Makefile ou une cible de but n'est pas trouvé dans le répertoire courant, remake recherchera dans le répertoire parent un Makefile. En trouvant un répertoire parent le plus proche avec un Makefile, remake définira son répertoire de travail courant au répertoire où le Makefile a été trouvé.

À cet égard, l'option courte '-c' est comme '-C' sauf qu'aucun répertoire n'a besoin d'être spécifié.

-!, --post-mortem
Entrer dans le débogueur en cas d'erreur. C'est la même chose que les options : --debugger --debugger-stop=error
-P, --profile [=TYPE]
Active la sortie de profilage de temps et de dépendances en utilisant le TYPE spécifié pour le formatage. TYPE peut être callgrind ou json. S'il est omis, il prend par défaut callgrind. Les fichiers générés avec callgrind peuvent être analysés avec kcachegrind, callgrind_annotate, ou gprof2dot. Les fichiers générés avec json ont le format spécifié dans le manuel info.
--profile-directory=[CHEMIN]
Spécifie le CHEMIN où les fichiers de profilage doivent être écrits. Il doit exister avant d'exécuter make. Il est supposé être un chemin relatif au répertoire initial où make est appelé, sauf s'il commence par un ~ ou un /.
--targets
Affiche une liste des cibles nommées explicitement trouvées dans les makefiles lus.
--tasks
Affiche une liste des cibles nommées explicitement trouvées dans les makefiles lus qui ont des commentaires descriptifs. Un commentaire descriptif est ajouté en plaçant un seul commentaire avant la cible qui commence par '#:'.
-x, --trace [=FLAGS]
Définit les indicateurs de trace. Si les FLAGS sont omis, alors le comportement est le même que si --trace=normal était spécifié. FLAGS peut être read pour tracer les Makefiles lus, noshell qui est comme normal mais le traçage shell est désactivé, ou full pour un traçage maximal.
-X, --debugger [=TYPE]
Entrer dans le débogueur avec. Si le TYPE est omis, alors le comportement est le même que si --debugger=normal était spécifié. TYPE peut être goal pour tous les tracés des Makefiles lus, preread qui s'arrête avant que des Makefiles ne soient lus, goal qui s'arrête après la construction de la cible de but, normal qui est le même que de ne donner aucune option, preaction qui est comme normal mais le traçage shell est désactivé, full pour un traçage maximal. C'est la même chose que de donner toutes les options sauf "normal", fatal pour entrer dans le débogueur en cas d'erreur fatale, error pour entrer dans le débogueur en cas d'erreur.

VOIR AUSSI

La documentation complète de remake est maintenue sous forme de manuel Texinfo. Si les programmes info et remake sont correctement installés sur votre site, la commande

info remake

devrait vous donner accès au manuel de remake.

BOGUES

Comme il est dérivé de GNU Make, il a la plupart de ses bogues.

Voir le chapitre « Problèmes et bogues » dans Le manuel GNU Make.

Pour les bogues spécifiques à remake, voir https://github.com/rocky/remake/issues/.

AUTEURS

Le GNU make dont remake est dérivé, a été écrit par Richard Stallman et Roland McGrath, et est actuellement maintenu par Paul Smith.

Cependant, remake est le fruit de l'imagination de Rocky Bernstein. L'aide d'autres personnes a été, et est toujours, grandement appréciée. Michael Lord Welles a cependant trouvé le nom, remake.
