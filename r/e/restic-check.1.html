NOM

restic-check - Vérifie le dépôt à la recherche d'erreurs

SYNTAXE

restic check [options]

DESCRIPTION

La commande « check » teste le dépôt à la recherche d'erreurs et rapporte toutes les erreurs trouvées. Elle peut également être utilisée pour charger toutes les données et simuler ainsi une restauration.

Par défaut, la commande « check » chargera toujours toutes les données directement depuis le dépôt et n'utilisera pas de cache local.

CODE DE SORTIE

Le code de sortie est 0 si la commande a réussi. Le code de sortie est 1 s'il y a eu une erreur. Le code de sortie est 10 si le dépôt n'existe pas. Le code de sortie est 11 si le dépôt est déjà verrouillé. Le code de sortie est 12 si le mot de passe est incorrect.

OPTIONS

-h, --help[=false] aide pour check

--read-data[=false] lit tous les blobs de données

--read-data-subset="" lit un sous-ensemble de paquets de données, spécifié comme « n/t » pour une partie spécifique, ou soit « x% » soit « x.y% » soit une taille en octets avec les suffixes k/K, m/M, g/G, t/T pour un sous-ensemble aléatoire

--with-cache[=false] utilise le cache existant, ne lit que les données non mises en cache depuis le dépôt

OPTIONS HÉRITÉES DES COMMANDES PARENT

--cacert=[] fichier à partir duquel charger les certificats racine (défaut : utiliser les certificats système ou $RESTIC_CACERT)

--cache-dir="" définit le répertoire du cache. (défaut : utiliser le répertoire de cache par défaut du système)

--cleanup-cache[=false] supprime automatiquement les anciens répertoires de cache

--compression=auto mode de compression (uniquement disponible pour le format de dépôt version 2), l'un des (auto|off|max) (défaut : $RESTIC_COMPRESSION)

--http-user-agent="" définit un agent utilisateur http pour les requêtes http sortantes

--insecure-no-password[=false] utilise un mot de passe vide pour le dépôt, doit être passé à chaque commande restic (non sécurisé)

--insecure-tls[=false] ignore la vérification du certificat TLS lors de la connexion au dépôt (non sécurisé)

--json[=false] définit le mode de sortie sur JSON pour les commandes qui le prennent en charge

--key-hint="" ID de clé de la clé à essayer de déchiffrer en premier (défaut : $RESTIC_KEY_HINT)

--limit-download=0 limite les téléchargements à un débit maximal en KiB/s. (défaut : illimité)

--limit-upload=0 limite les téléversements à un débit maximal en KiB/s. (défaut : illimité)

--no-cache[=false] n'utilise pas de cache local

--no-extra-verify[=false] ignore la vérification supplémentaire des données avant le téléversement (voir la documentation)

--no-lock[=false] ne verrouille pas le dépôt, cela autorise certaines opérations sur les dépôts en lecture seule

-o, --option=[] définit une option étendue (clé=valeur, peut être spécifié plusieurs fois)

--pack-size=0 définit la taille cible des paquets en MiB, les fichiers de paquets créés peuvent être plus grands (défaut : $RESTIC_PACK_SIZE)

--password-command="" commande shell pour obtenir le mot de passe du dépôt (défaut : $RESTIC_PASSWORD_COMMAND)

-p, --password-file="" fichier à partir duquel lire le mot de passe du dépôt (défaut : $RESTIC_PASSWORD_FILE)

-q, --quiet[=false] ne pas afficher de rapport de progression complet

-r, --repo="" dépôt vers lequel sauvegarder ou à partir duquel restaurer (défaut : $RESTIC_REPOSITORY)

--repository-file="" fichier à partir duquel lire l'emplacement du dépôt (défaut : $RESTIC_REPOSITORY_FILE)

--retry-lock=0s réessayer de verrouiller le dépôt s'il est déjà verrouillé, prend une valeur comme 5m ou 2h (défaut : pas de réessais)

--stuck-request-timeout=5m0s durée après laquelle les requêtes bloquées seront réessayées

--tls-client-cert="" chemin vers un fichier contenant le certificat client TLS et la clé privée encodés en PEM (défaut : $RESTIC_TLS_CLIENT_CERT)

-v, --verbose[=0] être verbeux (spécifiez plusieurs fois ou un niveau avec --verbose=n``, niveau/fois maximum est 2)
