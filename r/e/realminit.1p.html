REALMINIT(1) Documentation Perl fournie par l'utilisateur REALMINIT(1)

NOM

realminit - Crée de nouveaux enregistrements de domaine pour un fichier de domaines DNSSEC-Tools.

SYNTAXE

realminit [options] <domaine1> ... <domaineN>

DESCRIPTION

realminit crée de nouvelles entrées de domaine pour un fichier realms. dtrealms gère plusieurs environnements de basculement DNSSEC-Tools distincts fonctionnant simultanément. Chaque environnement de basculement, appelé domaine, est défini dans un fichier realms. dtrealms utilise ce fichier pour déterminer comment exécuter l'environnement de basculement. Ceci est utile pour des choses telles que la gestion de très grandes collections de zones, la ségrégation des zones clients et les tests logiciels.

Les entrées de domaine nouvellement générées sont écrites sur la sortie standard, sauf si l'option -out est spécifiée.

Un fichier realms contient un certain nombre d'entrées, une pour chaque domaine géré. Une entrée de domaine a ce format :

domaine "exemple"
    state          "actif"
    configdir      "/usr/realms/configs/exemple"
    statedir       "/usr/realms/states/exemple"
    realmsdir      "/usr/realms/realms-files/exemple"
    rollrec        "exemple.rrf"
    administrator  "bob@cat.example.com"
    display        "1"
    manager        "rollerd"
    args           "-display -loglevel phase"

Plusieurs entrées de domaine peuvent être créées avec une seule exécution de realminit. À l'exception du champ de nom de l'entrée, les entrées seront exactement les mêmes, sauf si le métacaractère '=' est utilisé dans les options de la ligne de commande. Si les valeurs des options configdir, statedir, realmdir, rollrec, administrator, args ou user contiennent un '=', il sera remplacé par le nom du domaine lors de la construction de l'entrée. Voir la section EXEMPLES pour des exemples de la manière dont les options sont utilisées par realminit.

OPTIONS

realminit peut recevoir les options suivantes :

-actif
Ceci indique que dtrealms doit démarrer le domaine lors du démarrage de dtrealms. Les domaines sont actifs par défaut.
-administrator
Ceci est l'adresse e-mail de l'administrateur du domaine.
-args
Ceci est un ensemble d'arguments de ligne de commande passés au gestionnaire de basculement du domaine lors du démarrage du domaine.
-configdir
Ceci est le répertoire de configuration du domaine. Il contiendra des fichiers tels que le fichier de configuration DNSSEC-Tools pour ce domaine.
-display
Ceci indique si le domaine doit être inclus dans la sortie grandvizier.
-inactif
Ceci indique que dtrealms ne doit pas démarrer le domaine lors du démarrage de dtrealms.
-manager
Ceci est le gestionnaire de basculement pour le domaine. rollerd est le gestionnaire de basculement par défaut, mais d'autres gestionnaires peuvent être utilisés.
-out fichier-sortie
Les nouvelles entrées de domaine seront ajoutées à fichier-sortie. Le fichier sera créé s'il n'existe pas.

Si cette option n'est pas donnée, les nouvelles entrées de rollrec seront écrites sur la sortie standard.

-realmdir
Ceci est le répertoire de données du domaine. Ce répertoire est censé contenir le fichier rollrec, les fichiers de zone, les fichiers keyrec et les fichiers de clé pour les zones de ce domaine.
-rollrec
Ceci est le chemin d'accès au fichier rollrec du domaine. Il est utilisé pour contrôler les actions de basculement pour le domaine. S'il ne s'agit pas d'un chemin absolu, il sera supposé être relatif au champ realmdir.
-statedir
Ceci est le répertoire d'état du domaine. Il contiendra des fichiers tels que le fichier de verrouillage rollrec de ce domaine et le socket de communication rollerd. Si le statedir n'est pas défini pour un domaine, alors le configdir du domaine est utilisé pour cette valeur.
-user
Ceci est l'utilisateur sous lequel le domaine est exécuté. (Ceci n'est pas encore implémenté dans dtrealms.)
-help
Affiche un message d'utilisation.
-Version
Affiche les informations de version pour realminit et DNSSEC-Tools.

EXEMPLES

Les options suivantes devraient clarifier comment realminit traite les options et les nouveaux domaines. L'Exemple 1 montrera l'enregistrement de domaine complet. Par souci de brièveté, les exemples restants ne montreront que les champs pertinents pour cet exemple. D'autres exemples utiliseront également des formes abrégées des noms d'options.

Exemple 1. Un domaine, avec -statedir

Cet exemple montre le domaine généré en fournissant à realminit un seul domaine.

$ realminit -actif -configdir /realms/confs/exemple -statedir /realms/states/exemple -realmdir /realms/realms/exemple -rollrec exemple.rrf -admin bob@cat.example.com -args "-loglevel phase -logfile logger" exemple
domaine       "exemple"
    state           "actif"
    configdir       "/realms/confs/exemple"
    statedir        "/realms/states/exemple"
    realmdir        "/realms/realms/exemple"
    rollrec         "exemple.rrf"
    administrator   "bob@cat.example.com"
    display         "1"
    manager         "rollerd"
    args            "-loglevel phase -logfile logger"

Exemple 2. Un domaine, sans -statedir

Cet exemple montre le domaine généré en fournissant à realminit un seul domaine.

$ realminit -actif -configdir /realms/confs/exemple -realmdir /realms/realms/exemple -rollrec exemple.rrf -admin bob@cat.example.com -args "-loglevel phase -logfile logger" exemple
domaine       "exemple"
    state           "actif"
    configdir       "/realms/confs/exemple"
    statedir        "/realms/confs/exemple"
    ...

Exemple 3. Deux domaines, sans métacaractères

Cet exemple montre les domaines générés en fournissant à realminit deux domaines, sans utiliser le métacaractère spécial "=".

$ realminit -configdir /realms/confs/exemple -statedir /realms/states/exemple -realmdir /realms/realms/exemple -rollrec exemple.rrf -admin bob@cat.example.com exemple test
domaine       "exemple"
    configdir       "/realms/confs/exemple"
    statedir        "/realms/states/exemple"
    realmdir        "/realms/realms/exemple"
    rollrec         "exemple.rrf"
    administrator   "bob@cat.example.com"
    ...
domaine       "test"
    configdir       "/realms/confs/exemple"
    statedir        "/realms/states/exemple"
    realmdir        "/realms/realms/exemple"
    rollrec         "exemple.rrf"
    administrator   "bob@cat.example.com"
    ...

Exemple 4. Deux domaines, avec métacaractères

Cet exemple montre les domaines générés en fournissant à realminit deux domaines, et qui utilise le métacaractère spécial "=".

$ realminit -configdir /realms/confs/= -statedir /realms/states/= -realmdir /realms/realms/= -rollrec =.rrf -admin bob@cat.=.com exemple test
domaine       "exemple"
    configdir       "/realms/confs/exemple"
    statedir        "/realms/states/exemple"
    realmdir        "/realms/realms/exemple"
    rollrec         "exemple.rrf"
    administrator   "bob@cat.example.com"
    ...
domaine       "test"
    configdir       "/realms/confs/test"
    statedir        "/realms/states/test"
    realmdir        "/realms/realms/test"
    rollrec         "test.rrf"
    administrator   "bob@cat.test.com"
    ...

realminit#

1p, DNSSEC-Tools

NAME

realminit — initializes a realm record directory

SYNOPSIS

realminit [options] realm

DESCRIPTION

The realminit command creates the directory structure and necessary initial files for a realm as defined in the realm configuration file.

A realm configuration file is a text file that contains a series of records. The first record must be the realm record, which starts with the keyword realm and contains the realm's name. The realm record may contain the following parameters:

configdir
The directory in which the realm's configuration files are stored. This is where zone files and other configuration will be kept.
statedir
The directory in which realm state files are stored. This includes things like current keys and key information.
realmdir
The directory in which the realm's realm record is stored. This is where the actual realm record file will be located.
rollrec
The filename for the rollover records. This is where rollover plans and status are recorded.
administrator
The email address of the administrator for this realm. This should be in standard email address format.

Any subsequent records in the realm configuration file must be administrator records, which start with the keyword administrator and contain the email address of a realm administrator.

The realminit command will take the information from the realm configuration file and create the directories specified by configdir, statedir, and realmdir. It will also create the realm record file specified by rollrec in the directory specified by realmdir.

By default, realminit looks for the realm configuration file in the directory specified by the DNSSEC_TOOLS_REALM_CONFIG_DIR environment variable, or if that is not set, in /realm.conf

OPTIONS

There are currently no options for realminit.

EXAMPLES

The following is an example of a realm configuration file:

realm       "example.com" {
    configdir       "/realms/confs/example.com"
    statedir        "/realms/states/example.com"
    realmdir        "/realms/realms/example.com"
    rollrec         "example.com.rrf"
    administrator   "bob@cat.example.com"
    administrator   "alice@dog.example.com"
}
administrator   "root@localhost"

realm       "test.net" {
    configdir       "/realms/confs/test.net"
    statedir        "/realms/states/test.net"
    realmdir        "/realms/realms/test.net"
    rollrec         "test.net.rrf"
    administrator   "alice@cat.test.net.com"
}

If the above is saved as realm.conf in a directory where realminit can find it, then running:

realminit example.com

will create the directories:

/realms/confs/example.com
/realms/states/example.com
/realms/realms/example.com

and the file:

/realms/realms/example.com/example.com.rrf

with the contents:

example.com.rrf
    administrator   "bob@cat.example.com"
    administrator   "alice@dog.example.com"
    administrator   "root@localhost"
    ...
realm       "test.net"
    configdir       "/realms/confs/test.net"
    statedir        "/realms/states/test.net"
    realmdir        "/realms/realms/test.net"
    rollrec         "test.net.rrf"
    administrator   "alice@cat.test.net.com"
    ...
