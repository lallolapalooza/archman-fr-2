REBUILD-DETECTOR(7) Manuel des commandes générales REBUILD-DETECTOR(7)

NOM

rebuild-detector

Cet outil vous aide à trouver les paquets Arch Linux qui ont été compilés contre des versions plus anciennes de dépendances et qui doivent donc être recompilés pour fonctionner correctement.

Vérifications supportées :

  • ldd : Un exécutable est lié à une bibliothèque partagée inexistante
  • python : Un paquet a été compilé contre une ancienne version de Python
  • perl : Un paquet a été compilé contre une ancienne version de Perl
  • ruby : Un paquet a été compilé contre une ancienne version de Ruby
  • haskell : Un paquet a été compilé contre une ancienne version de Haskell

INSTALLATION

pacman -S rebuild-detector

UTILISATION

Exécutez checkrebuild pour voir quels paquets nécessitent une recompilation. Si aucune sortie n'apparaît, cela signifie qu'il n'y a rien à recompiler.

Utilisez le mode verbeux checkrebuild -v pour obtenir un peu plus d'informations sur la raison pour laquelle ces paquets sont signalés.

Par défaut, seuls les paquets des dépôts locaux (file://) sont vérifiés. Si vous souhaitez inclure des dépôts supplémentaires, utilisez l'indicateur -i comme suit : checkrebuild -i repo1 -i repo2

QUE FAIRE SI UN PAQUET EST SIGNALÉ ?

Premièrement, exécutez checkrebuild -v pour voir exactement pourquoi le paquet est signalé.

Si un paquet manque d'un fichier .so, cela signifie que le binaire est lié à une bibliothèque qui n'est pas présente sur votre ordinateur. Cela peut se produire pour deux raisons :

  • Vous manquez une dépendance
  • Le binaire est lié à une ancienne version de la dépendance installée

Le premier cas ne peut pas être résolu en recompilant le paquet. Parfois, il peut être résolu en installant une dépendance manquante, mais surtout si un binaire a été compilé par quelqu'un d'autre (typique pour les paquets -bin) il n'y a rien que vous puissiez faire.

Le second cas se produit lorsqu'un paquet n'était pas signalé par le passé, mais est soudainement signalé après une mise à jour. Dans ce cas, checkrebuild -v pourrait indiquer que la bibliothèque manquante est par exemple *-7.so mais vous avez actuellement *-8.so installé sur votre ordinateur. C'est le cas pour lequel rebuild-detector a été conçu : recompiler le paquet signalé et l'erreur devrait disparaître.

Si vous ne parvenez pas à corriger le paquet, la seule chose que vous pouvez faire est de l'ignorer complètement, c'est-à-dire d'exécuter la prochaine fois checkrebuild | grep -v paquet-cassé.

HOOK PACMAN

Un hook pacman est également inclus dans la distribution. Pour des raisons de performance, la vérification ldd n'est exécutée que sur les dépendances directes des paquets qui sont mis à jour dans cette transaction pacman.

Ceci peut être reproduit manuellement en passant la liste de ces paquets sur stdin, par exemple printf &#39;pkg1\npkg2&#39; | checkrebuild. N'oubliez pas que cette fonctionnalité est destinée à détecter les paquets qui sont cassés par la mise à jour de pkg1 et pkg2. Dans ce cas, ldd ne vérifiera pas les binaires de pkg1 et pkg2 eux-mêmes, mais plutôt les binaires de tous les paquets qui dépendent directement de pkg1 ou pkg2.
