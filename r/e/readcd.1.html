READCD(1) COMMANDES UTILISATEUR de Schily READCD(1)

NOM

readcd - lire ou écrire des Compact Discs ou des médias associés

SYNTAXE

readcd [ dev=périphérique ][ options ]

DESCRIPTION

Readcd est utilisé pour lire ou écrire des Compact Discs.

Nommage des périphériques

La plupart des utilisateurs n'ont pas à se soucier du nommage des périphériques. Si aucune option dev= n'a été spécifiée, readcd implémente le support auto target et trouve automatiquement le lecteur s'il n'y a qu'un seul type de lecteur CD-ROM disponible dans le système. S'il existe plusieurs types de lecteurs CD-ROM dans le système, une liste de noms de périphériques possibles peut être récupérée avec readcd -scanbus ou à partir de l'exemple de cible de la sortie de readcd dev=help, puis le paramètre dev= peut être défini en fonction de la liste des périphériques.

Le paramètre périphérique de l'option dev= expliquée ci-dessous fait référence à la notation standard SCSI CAM pour scsibus/target/lun de l'enregistreur CD/DVD/BluRay. Si un fichier /etc/default/cdrecord existe, le paramètre de l'option dev= peut également être une étiquette de nom de lecteur dans ledit fichier (voir la section FICHIERS).

OPTIONS

Si aucune option autre que l'option dev= n'a été spécifiée, readcd passe en mode interactif. Sélectionnez une fonction principale, puis suivez les instructions.

Options informatives

-help
affiche les informations de version de readcd sur la sortie standard.
-version
Affiche les informations de version et quitte.
-v
Incrémente le niveau de verbosité générale de un. Ceci est utilisé par exemple pour afficher la progression du processus.

Options fonctionnelles de Readcd

-clone
Effectue une lecture en clone. Lit le CD avec toutes les données de sous-canal et un TOC complet. Les données complètes du TOC seront placées dans un fichier portant un nom similaire à celui de l'option f= mais avec le suffixe .toc ajouté.

Notez que la lecture en mode clone entraîne l'absence de correction d'erreurs au niveau du sous-canal. Même dans le canal de données principal, il y a moins de correction d'erreurs qu'avec d'autres modes de lecture. Cela entraîne une légère dégradation de la qualité. Évitez de copier des CD audio en mode clone pour cette raison.

-c2scan
Analyse l'intégralité du CD ou la plage spécifiée par sectors=plage pour les erreurs C2. Les erreurs C2 sont des erreurs qui sont incorrigibles après la deuxième étape du système de correction Reed Solomon 24/28 + 28/32 au niveau audio (taille de secteur de 2352 octets). Si un CD audio présente des erreurs C2, une interpolation est nécessaire pour masquer les erreurs. Si un CD de données présente des erreurs C2, celles-ci sont dans la plupart des cas corrigées par le code ECC/EDC qui crée 2352 octets à partir de 2048 octets de données. Le code ECC/EDC devrait être capable de corriger environ 100 octets d'erreur C2 par secteur.

Si vous trouvez des erreurs C2, vous voudrez peut-être réduire la vitesse en utilisant l'option speed= car les erreurs C2 peuvent résulter d'un déséquilibre dynamique du support.

-cxscan
Analyse l'intégralité du CD ou la plage spécifiée par sectors=plage pour les erreurs C1/C2/CU. En mode non verbeux, seul un résumé est affiché. Avec -v, une ligne pour chaque seconde sans erreur est affichée. Avec -vv, une ligne pour chaque seconde est affichée. Cette méthode d'analyse ne fonctionne qu'avec quelques lecteurs.
-edc-corr
Dans ce mode, readcd lit les secteurs de données du CD en mode audio non corrigé, puis essaie de corriger les données à l'aide de la bibliothèque de décodage ECC/EDC de Heiko Eissfeldt. Comme cette bibliothèque implémente une boucle sur deux couches de correction d'erreurs, readcd peut être capable de corriger plus de données que le firmware du lecteur CD-ROM.

Cette option est actuellement expérimentale et applicable uniquement aux CD et ne prend actuellement en charge que les secteurs CD-ROM bruts de 2048 octets.

f=fichier
Spécifie le nom du fichier où la sortie doit être écrite ou à partir duquel l'entrée doit être prise. Utiliser '-' comme nom de fichier amènera readcd à utiliser stdout resp. stdin.
-factor
Affiche les valeurs de vitesse pour meshpoints=# comme facteur basé sur la vitesse simple du support actuel. Ceci ne fonctionne que si readcd est capable de déterminer le type de support actuel.
-fulltoc
Récupère un TOC complet du disque actuel et l'affiche en hexadécimal.
meshpoints=#
Affiche la vitesse de lecture à # emplacements. Le but de cette option est de créer une liste de valeurs de vitesse de lecture adaptées par exemple à gnuplot. Les valeurs de vitesse sont calculées en supposant que 1000 octets constituent un kilooctet, comme documenté dans la norme SCSI. Les données de sortie créées à cet effet sont écrites sur stdout.
-nocorr
Passe le lecteur dans un mode où il ignore les erreurs de lecture dans les secteurs de données résultant d'erreurs ECC/EDC incorrigibles avant la lecture. Si readcd se termine, le mode de récupération d'erreurs du lecteur est restauré à l'ancien mode mémorisé.
-noerror
N'arrête pas si la vérification d'erreurs de haut niveau dans readcd a trouvé une erreur incorrigible dans le flux de données.
-notrunc
Ne tronque pas le fichier de sortie lors de son ouverture.
-overhead
Mesure le temps de surcharge des commandes SCSI. Ceci est fait en exécutant plusieurs commandes 1000 fois et en affichant le temps total utilisé. Si vous divisez les temps affichés par 1000, vous obtenez le temps de surcharge moyen pour une seule commande.
-pi8scan
Analyse l'intégralité du DVD ou la plage spécifiée par sectors=plage pour les erreurs pisum8. En mode non verbeux, seul un résumé est affiché. Avec -v, une ligne pour chaque bloc de 8 * 32 ko sans erreur est affichée. Avec -vv, une ligne pour chaque bloc de 8 * 32 ko est affichée. Cette méthode d'analyse ne fonctionne qu'avec quelques lecteurs.
-pifscan
Analyse l'intégralité du DVD ou la plage spécifiée par sectors=plage pour les erreurs pif. En mode non verbeux, seul un résumé est affiché. Avec -v, une ligne pour chaque bloc de 32 ko sans erreur est affichée. Avec -vv, une ligne pour chaque bloc de 32 ko est affichée. Cette méthode d'analyse ne fonctionne qu'avec quelques lecteurs.
-plot
Cette option modifie le comportement pour -cxscan, -pi8scan et -pifscan. La sortie est mieux adaptée pour gnuplot.
retries=#
Définit le nombre de tentatives pour les nouvelles tentatives de haut niveau dans readcd à #. La valeur par défaut est de 128 tentatives, ce qui peut être excessif si vous souhaitez lire un CD avec de nombreux secteurs illisibles.
sectors=plage
Spécifie une plage de secteurs à lire. La plage est spécifiée par le numéro de secteur de départ, un signe moins et le numéro de secteur de fin. Le secteur de fin n'est pas inclus dans la liste, donc sectors=0-0 ne lira rien et peut être utilisé pour vérifier la présence d'un CD dans le lecteur.
speed=#
Définit le facteur de vitesse du processus de lecture ou d'écriture à #. # est un entier, représentant un multiple de la vitesse audio. C'est environ 150 Ko/s pour un CD-ROM et environ 172 Ko/s pour un CD Audio. Si aucune option speed n'est présente, readcd utilisera la vitesse maximale. Seuls les lecteurs conformes MMC bénéficieront de cette option. La vitesse des lecteurs non MMC n'est pas modifiée.

DVD.

-w
Passe en mode écriture. L'écriture n'est possible que sur les supports DVD-RAM. Pour d'autres supports, utilisez plutôt cdrecord. Notez que cdrecord prend également en charge l'écriture sur les supports DVD-RAM.

Si cette option n'est pas présente, readcd lit depuis le périphérique spécifié.

Options SCSI

dev=cible
Définit la cible SCSI pour l'enregistreur CD/DVD/BluRay, voir les notes ci-dessus. Une spécification typique de périphérique cible est dev=1,6,0. Si un nom de fichier doit être fourni avec la spécification numérique de la cible, le nom de fichier dépend de l'implémentation. Le nom de fichier correct dans ce cas se trouve dans les manuels spécifiques au système d'exploitation cible. Sur un système FreeBSD sans support CAM, vous devez utiliser le périphérique de contrôle (par ex. /dev/rcd0.ctl). Une spécification de périphérique correcte dans ce cas peut être dev=/dev/rcd0.ctl:@.

Adressage SCSI général
Le périphérique cible de l'option dev= fait référence à la notation standard SCSI CAM pour scsibus/target/lun de l'enregistreur CD/DVD/BluRay. La communication sur SunOS se fait avec le pilote général SCSI scg. D'autres systèmes d'exploitation utilisent une simulation de bibliothèque de ce pilote. La syntaxe possible est : dev= scsibus,target,lun ou dev= target,lun. Dans ce dernier cas, l'enregistreur CD/DVD/BluRay doit être connecté au bus SCSI par défaut de la machine. Scsibus, target et lun sont des nombres entiers. Certains systèmes d'exploitation ou implémentations de transport SCSI peuvent exiger de spécifier un nom de fichier en plus. Dans ce cas, la syntaxe correcte pour le périphérique est : dev= nom_peripherique:scsibus,target,lun ou dev= nom_peripherique:target,lun. Si le nom du nœud de périphérique spécifié sur un tel système fait référence à un seul périphérique SCSI, un raccourci sous la forme dev= nom_peripherique:@ ou dev= nom_peripherique:@,lun peut être utilisé à la place de dev= nom_peripherique:scsibus,target,lun.

Adressage SCSI distant
Pour accéder aux périphériques SCSI distants, vous devez préfixer le nom du périphérique SCSI par un indicateur de périphérique distant. L'indicateur de périphérique distant est soit REMOTE:utilisateur@hôte: soit REMOTE:hôte: Un nom de périphérique SCSI distant valide peut être : REMOTE:utilisateur@hôte: pour permettre le balayage du bus SCSI distant ou REMOTE:utilisateur@hôte:1,0,0 pour accéder au périphérique SCSI sur hôte connecté au bus SCSI n° 1, cible 0, lun 0. Pour permettre l'accès distant à un hôte spécifique, le programme rscsi(1) doit être présent et configuré sur l'hôte.

Transports SCSI alternatifs
Cdrecord est entièrement basé sur les commandes SCSI, mais ce n'est pas un problème car tous les graveurs CD/DVD/BluRay jamais fabriqués utilisent des commandes SCSI pour la communication. Même les lecteurs ATAPI ne sont que des lecteurs SCSI qui utilisent intrinsèquement l'interface de paquets ATA comme couche de transport de commande SCSI intégrée au transport IDE (ATA). Vous devrez peut-être spécifier une couche de transport alternative sur la ligne de commande si votre système d'exploitation n'implémente pas un sous-système de pilote noyau entièrement intégré qui permet d'accéder à tout lecteur utilisant des commandes SCSI via une interface utilisateur unique.

Pour accéder aux périphériques SCSI via des couches de transport alternatives, vous devez préfixer le nom du périphérique SCSI par un indicateur de couche de transport. L'indicateur de couche de transport peut être quelque chose comme USCSI: ou ATAPI:. Pour obtenir une liste des couches de transport prises en charge pour votre plateforme, utilisez dev= HELP :

Contexte de portabilité
Pour rendre readcd portable sur toutes les plateformes UNIX, la syntaxe dev= nom_peripherique:scsibus,target,lun est préférée car elle cache les connaissances spécifiques au système d'exploitation sur les noms de périphériques à l'utilisateur. Un système d'exploitation spécifique peut ne pas nécessairement prendre en charge un moyen de spécifier un nom de fichier de périphérique réel ni un moyen de spécifier scsibus,target,lun.

Scsibus 0 est le bus SCSI par défaut sur la machine. Observez les messages de démarrage pour plus d'informations ou consultez /var/adm/messages pour plus d'informations sur la configuration SCSI de votre machine. Si vous avez des difficultés à déterminer quelles valeurs pour scsibus,target,lun doivent être utilisées, essayez l'option -scanbus de readcd décrite ci-dessous.

Utilisation de noms logiques pour les périphériques
Si aucune option dev n'est présente, readcd essaiera d'obtenir le périphérique de l'environnement CDR_DEVICE.

Si un fichier /etc/default/cdrecord existe, et si l'argument de l'option dev= ou l'environnement CDR_DEVICE ne contient pas les caractères ',', '/', '@' ou ':', il est interprété comme un nom d'étiquette de périphérique défini dans le fichier /etc/default/cdrecord (voir la section FICHIERS).

Mode Cible Automatique
Si aucune option dev= et aucun environnement CDR_DEVICE n'est présent, ou s'il ne contient qu'un spécificateur de transport mais pas de notation d'adresse, readcd essaie de scanner l'espace d'adresses SCSI pour les lecteurs CD-ROM. S'il n'en trouve qu'un seul, celui-ci est utilisé par défaut.

debug=#, -d
Définit la valeur de débogage divers à # (avec debug=#) ou incrémente le niveau de débogage divers de un (avec -d). Si vous spécifiez -dd, cela équivaut à debug=2. Cela peut aider à trouver des problèmes lors de l'ouverture d'un pilote pour libscg, ainsi qu'avec les tailles et types de secteurs. L'utilisation de -debug ralentit le processus et peut être la cause d'un sous-dépassement de tampon.
kdebug=#, kd=#
Indique au pilote scg de modifier la valeur de débogage du noyau pendant l'exécution des commandes SCSI.
-scanbus
Balaye tous les périphériques SCSI sur tous les bus SCSI et affiche les chaînes d'interrogation. Cette option peut être utilisée pour trouver l'adresse SCSI des périphériques sur un système. Les nombres affichés comme étiquettes sont calculés par : bus * 100 + target
scgopts=liste
Une liste d'options SCSI séparées par des virgules, gérées par libscg. Les options implémentées peuvent être mises à jour indépendamment des applications. Actuellement, une option : ignore-resid est prise en charge pour contourner un bug du noyau Linux.
-silent, -s
Ne pas afficher de rapport de statut pour les commandes SCSI échouées.
timeout=#
Définit la valeur de timeout par défaut des commandes SCSI à # secondes. Le timeout par défaut des commandes SCSI est le timeout minimum utilisé pour l'envoi des commandes SCSI. Si une commande SCSI échoue en raison d'un timeout, vous pouvez essayer d'augmenter le timeout par défaut des commandes SCSI au-dessus de la valeur de timeout de la commande échouée. Si la commande s'exécute correctement avec un timeout de commande augmenté, veuillez signaler la meilleure valeur de timeout et la commande correspondante à l'auteur du programme. Si aucune option timeout n'est présente, un timeout par défaut de 40 secondes est utilisé.
ts=#
Définit la taille maximale de transfert pour une seule commande SCSI à #. La syntaxe de l'option ts= est la même que pour cdrecord fs=# ou sdd bs=#.

Si aucune option ts= n'a été spécifiée, readcd utilise par défaut une taille de transfert de 256 Ko. Si libscg reçoit des valeurs inférieures du système d'exploitation, la valeur est réduite à la valeur maximale possible avec le système d'exploitation actuel. Parfois, il peut être utile de réduire davantage la taille de transfert ou de l'augmenter, mais notez qu'il peut falloir beaucoup de temps pour trouver une meilleure valeur en expérimentant avec l'option ts=.

-V
Incrémente le niveau de verbosité concernant le transport des commandes SCSI de un. Cela aide à déboguer les problèmes survenant pendant le processus, dans le graveur de CD. Si vous obtenez des messages d'erreur incompréhensibles, vous devriez utiliser ce drapeau pour obtenir une sortie plus détaillée. -VV affichera en plus le contenu du tampon de données. L'utilisation de -V ou -VV ralentit le processus.

EXEMPLES

Pour tous les exemples ci-dessous, il sera supposé que le lecteur est connecté au bus SCSI principal de la machine. L'ID cible SCSI est réglé sur 2.

Pour lire le média complet depuis un CD-ROM et écrire les données dans le fichier cdimage.raw :


readcd dev=2,0 f=cdimage.raw

Pour lire les secteurs de la plage 150 ... 10000 d'un CD-ROM et écrire les données dans le fichier cdimage.raw :


readcd dev=2,0 sectors=150-10000 f=cdimage.raw

Pour écrire les données du fichier cdimage.raw (par ex. une image de système de fichiers de mkisofs) sur un DVD-RAM, appelez :


readcd dev=2,0 -w f=cdimage.raw

ENVIRONNEMENT

RSH
Si l'environnement RSH est présent, la connexion distante ne sera pas créée via rcmd(3) mais en appelant le programme pointé par RSH. Utilisez par ex. RSH=/usr/bin/ssh pour créer une connexion shell sécurisée.

Notez que cela force cdrecord à créer un tube vers le programme rsh(1) et empêche cdrecord d'accéder directement au socket réseau vers le serveur distant. Cela rend impossible la configuration des paramètres de performance et ralentit la connexion par rapport à une connexion rcmd(3) initiée par root.

RSCSI
Si l'environnement RSCSI est présent, le serveur SCSI distant ne sera pas le programme /opt/schily/sbin/rscsi mais le programme pointé par RSCSI. Notez que le nom du programme serveur SCSI distant sera ignoré si vous vous connectez avec un compte créé avec un programme serveur SCSI distant comme shell de connexion.

STATUT DE SORTIE

Les codes de sortie suivants sont utilisés :

0
Aucune erreur n'est apparue.
-1
Une erreur spécifique est apparue. Il peut s'agir d'une erreur d'utilisation causée par une ligne de commande illégale ou d'une autre erreur avec un message d'erreur spécifique au problème de readcd.
-2
Une erreur non spécifiée est apparue lors de la communication avec le lecteur. Voir le message d'erreur SCSI pour plus d'informations. La section DIAGNOSTICS ci-dessous contient une explication sur la façon de lire les messages d'erreur SCSI.

Notez que les anciens systèmes d'exploitation et les anciens shells peuvent ne pas prendre en charge la gamme complète des 32 bits du code de sortie et masquer la valeur avec 0xFF. Cela se traduit par des codes de sortie tronqués dans la plage 0..255 où -1 est mappé à 255.

NOTES

Si vous ne souhaitez pas autoriser les utilisateurs à devenir root sur votre système, readcd peut être installé en toute sécurité en tant que suid root. Cela permet à tous les utilisateurs ou à un groupe d'utilisateurs sans privilèges root d'utiliser readcd. Dans ce cas, Readcd n'autorisera l'accès qu'aux lecteurs de type CD-ROM. Pour donner à tous les utilisateurs l'accès à readcd, tapez :

chown root /usr/local/bin/readcd
chmod 4711 /usr/local/bin/readcd

Pour donner à un groupe restreint d'utilisateurs l'accès à readcd, tapez :

chown root /usr/local/bin/readcd
chgrp cdburners /usr/local/bin/readcd
chmod 4710 /usr/local/bin/readcd

et ajoutez un groupe cdburners sur votre système.

Ne donnez jamais de permissions d'écriture aux utilisateurs non root pour les périphériques /dev/scg? à moins que vous ne permettiez à quiconque de lire/écrire/formater tous vos disques.

Vous ne devriez pas connecter d'anciens lecteurs qui ne prennent pas en charge la déconnexion/reconnexion au bus SCSI connecté au graveur CD ou au disque source.

Lors de l'utilisation de readcd avec le pilote générique SCSI sous Linux. Vous devez noter que readcd utilise une couche qui tente d'émuler la fonctionnalité du pilote scg au-dessus des lecteurs du système d'exploitation local. Malheureusement, le pilote sg sous Linux présente plusieurs défauts :

•
Il ne peut pas détecter si une commande SCSI n'a pas pu être envoyée du tout.
•
Il ne peut pas obtenir l'octet de statut SCSI. Readcd ne peut donc pas signaler les commandes SCSI défaillantes dans certaines situations.
•
Il ne peut pas obtenir le nombre réel de transfert DMA. Readcd ne peut pas vous dire s'il y a un compte résiduel DMA.
•
Il ne peut pas obtenir le nombre d'octets valides dans les données de détection automatique. Readcd ne peut pas vous dire si le périphérique ne transfère aucune donnée de détection.
•
Il récupère trop peu de données lors de la détection automatique des requêtes (CCS/SCSI-2/SCSI-3 nécessite >= 18).

DIAGNOSTICS

Un message d'erreur typique pour une commande SCSI ressemble à ceci :

readcd: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0
Sense flags: Blk 0 (not valid)
cmd finished after 0.002s timeout 40s
La première ligne donne des informations sur le transport de la commande. Le texte après les deux-points donne le message d'erreur pour l'appel système du point de vue du noyau. Il s'agit généralement de : I/O error, sauf si d'autres problèmes surviennent. Les mots suivants contiennent une brève description de la commande SCSI qui échoue. Le reste de la ligne indique s'il y a eu des problèmes pour le transport de la commande sur le bus SCSI. fatal error signifie qu'il n'a pas été possible de transporter la commande (par exemple, aucun périphérique présent à l'adresse SCSI demandée).

La deuxième ligne affiche le bloc de descripteur de commande SCSI pour la commande échouée.

La troisième ligne donne des informations sur le code d'état SCSI renvoyé par la commande, si le transport de la commande réussit. Il s'agit d'informations d'erreur provenant du périphérique SCSI.

La quatrième ligne est un vidage hexadécimal des informations de détection automatique des requêtes pour la commande.

La cinquième ligne est le message d'erreur pour la clé de détection si elle est disponible, suivie du numéro de segment qui n'est valide que si la commande était une commande de copie. Si le message d'erreur n'est pas directement lié à la commande actuelle, le texte deferred error est ajouté.

La sixième ligne est le message d'erreur pour le code de détection et le qualificateur de détection si disponibles. Si le type de périphérique est connu, les données de détection sont décodées à partir de tables dans scsierrs.c. Le texte est suivi de la valeur d'erreur pour une unité remplaçable sur le terrain.

La septième ligne affiche le numéro de bloc lié à la commande échouée et le texte pour plusieurs indicateurs d'erreur. Le numéro de bloc peut ne pas être valide.

La huitième ligne indique le délai d'attente défini pour cette commande et le temps qu'il a réellement fallu pour que la commande se termine.

STABILITE DE L'INTERFACE

Les interfaces fournies par readcd sont conçues pour une stabilité à long terme. Comme readcd dépend des interfaces fournies par le système d'exploitation sous-jacent, la stabilité des interfaces proposées par readcd dépend de la stabilité des interfaces du système d'exploitation. Des interfaces modifiées dans le système d'exploitation peuvent nécessiter des interfaces modifiées dans readcd.
