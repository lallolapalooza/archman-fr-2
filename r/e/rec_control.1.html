REC_CONTROL(1) PowerDNS Recursor REC_CONTROL(1)

NOM

rec_control - Outil en ligne de commande pour contrôler un Recursor en cours d'exécution

SYNTAXE

rec_control [OPTION]... COMMANDE [OPTION-COMMANDE]...

DESCRIPTION

rec_control permet à l'opérateur d'interroger et de contrôler une instance en cours d'exécution du PowerDNS Recursor.

rec_control communique avec le recursor via le 'controlsocket'. Qui est généralement situé dans /var/run . Les options --socket-dir ou --config-dir et --config-name contrôlent à quel processus rec_control se connecte.

EXEMPLES

Pour vérifier si le Recursor est actif, exécutez :

# rec_control ping

Pour arrêter le recursor manuellement, exécutez :

# rec_control quit

Pour vider les caches sur disque, exécutez :

# rec_control dump-cache /tmp/le-cache

REMARQUE :

Avant la version 4.5.0, pour chaque commande qui écrit dans un fichier, pdns_recursor ouvrait le fichier pour y écrire. À partir de la version 4.5.0, les fichiers sont ouverts par la commande rec_control elle-même, en utilisant les identifiants et le répertoire de travail actuel de l'utilisateur exécutant rec_control. Un simple trait d'union - peut être utilisé comme nom de fichier pour écrire les données dans le flux de sortie standard.

OPTIONS

--help
fournit ce message d'aide.
--config-dir=<chemin>
Répertoire où se trouve recursor.conf.
--config-name=<nom>
Nom de la configuration virtuelle.
--socket-dir=<chemin>
Où se trouvera le controlsocket, veuillez utiliser --config-dir à la place.
--socket-pid=<pid>
Lors de l'exécution en mode SMP, pid de pdns_recursor à contrôler.
--timeout=<num>
Nombre de secondes à attendre la réponse du PowerDNS Recursor distant.
--version
Affiche le numéro de version de ce programme. Notez que la commande version affiche la version du recursor en cours d'exécution.

COMMANDES

add-dont-throttle-names NOM [NOM...]
Ajoute des noms pour les domaines de serveurs de noms qui ne peuvent pas être étranglés.
add-dont-throttle-netmasks MASQUE_RESEAU [MASQUE_RESEAU...]
Ajoute des masques réseau pour les serveurs de noms qui ne peuvent pas être étranglés.
add-nta DOMAINE [RAISON]
Ajoute une ancre de confiance négative pour DOMAINE, éventuellement suffixée par RAISON.
add-ta DOMAINE ENREGISTREMENT_DS
Ajoute une ancre de confiance pour DOMAINE avec les données de l'enregistrement DS ENREGISTREMENT_DS. Ceci ajoute la nouvelle ancre de confiance à l'ensemble existant d'ancres de confiance pour DOMAINE.
current-queries
Affiche les requêtes actuellement actives.
clear-dont-throttle-names NOM [NOM...]
Supprime les noms qui ne sont pas autorisés à être étranglés. Si NOM est *, supprime tout.
clear-dont-throttle-netmasks MASQUE_RESEAU [MASQUE_RESEAU...]
Supprime les masques réseau qui ne sont pas autorisés à être étranglés. Si MASQUE_RESEAU est *, supprime tout.
clear-nta DOMAINE...
Supprime l'ancre de confiance négative pour un ou plusieurs DOMAINEs. Définissez le domaine à * pour supprimer toutes les NTA.
clear-ta [DOMAINE]...
Supprime l'ancre de confiance pour un ou plusieurs DOMAINEs. Notez que la suppression de l'ancre de confiance racine n'est pas possible.
dump-cache NOM_FICHIER [TYPE...]
Vide les caches dans NOM_FICHIER. Ce fichier ne doit pas exister auparavant, PowerDNS refusera de l'écraser. Pendant le vidage, le recursor pourrait ne pas répondre aux questions.

Si aucun TYPE n'est spécifié, le cache des enregistrements, le cache négatif, le cache des paquets et le cache NSEC agressif sont vidés. Pour sélectionner des caches spécifiques, spécifiez un ou plusieurs TYPE*s, séparés par des espaces. La valeur de *TYPE peut être r, n, p ou a.

dump-dot-probe-map NOM_FICHIER
Vide le contenu de la carte de sondage DoT dans le NOM_FICHIER mentionné.
dump-edns NOM_FICHIER
Vide l'état EDNS dans le nom de fichier mentionné. Ce fichier ne doit pas exister au préalable, PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions.
dump-failedservers NOM_FICHIER
Vide le contenu de la carte des serveurs défaillants dans le NOM_FICHIER mentionné. Ce fichier ne doit pas exister au préalable, sinon PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions.
dump-non-resolving NOM_FICHIER
Vide le contenu de la carte des noms de serveurs de noms qui n'ont pas pu être résolus en une adresse. Ce fichier ne doit pas exister au préalable, sinon PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions.
dump-nsspeeds NOM_FICHIER
Vide les statistiques de vitesse des serveurs de noms dans le NOM_FICHIER mentionné. Ce fichier ne doit pas exister au préalable, PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions. Les statistiques sont conservées par thread, et les vidages se retrouvent dans le même fichier.
dump-rpz
Vide le contenu de la zone RPZ nommée ZONE NOM dans le NOM_FICHIER mentionné. Ce fichier ne doit pas exister au préalable, sinon PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions. Pour plus de détails sur la dénomination des RPZ, consultez https://docs.powerdns.com/recursor/lua-config/rpz.html#policyname.
dump-saved-parent-ns-sets NOM_FICHIER
Vide les entrées de la carte contenant les ensembles NS parents sauvegardés qui ont été utilisés avec succès lors de la résolution. Le nombre total d'entrées est également imprimé dans l'en-tête. Une entrée est sauvegardée si le recursor constate que l'ensemble parent inclut des noms qui ne sont pas dans l'ensemble enfant. Ceci est une indication d'un domaine mal configuré.
dump-throttlemap NOM_FICHIER
Vide le contenu de la carte d'étranglement dans le NOM_FICHIER mentionné. Ce fichier ne doit pas exister au préalable, sinon PowerDNS refusera de l'écraser. Pendant le vidage, le recursor ne répondra pas aux questions.
get STATISTIQUE [STATISTIQUE]...
Récupère une statistique. Pour les éléments qui peuvent être interrogés, consultez https://docs.powerdns.com/recursor/metrics.html.
get-all
Récupère toutes les statistiques connues.
get-dont-throttle-names
Obtient la liste des noms qui ne sont pas autorisés à être étranglés.
get-dont-throttle-netmasks
Obtient la liste des masques réseau qui ne sont pas autorisés à être étranglés.

COMMANDS

block domain-name
Block queries for domain-name. The domain name must end with a dot. This command does not trigger a cache invalidation. If the domain name is already cached, it will continue to return answers from cache until the TTL expires. This means that for a domain name to be blocked, it must not be cached.
connect HOST
Connect to a running pdns_recursor instance. This command will drop the connection if the server is not accepting connections, or not configured to accept them. The default for this is localhost on port 53.
disconnect
Disconnect from the running pdns_recursor instance.
get-audit-log
Get the audit log. This log contains all commands that have been issued to the recursor. This log is not allowed to be throttled.
get-ntas
Obtenir la liste des Ancrages de Confiance Négatifs actuellement configurés.
get-tas
Obtenir la liste des Ancrages de Confiance actuellement configurés.
get-parameter CLÉ [CLÉ]...
Récupère le(s) paramètre(s) de configuration spécifié(s).
get-proxymapping-stats
Obtenir la liste des sous-réseaux mappés par proxy et les compteurs associés.
get-qtypelist
Récupère les statistiques QType. Les requêtes provenant du cache ne sont pas encore comptabilisées.
get-remotelogger-stats
Récupère les statistiques du journal distant, par type et adresse.
hash-password [FACTEUR-DE-TRAVAIL]
Demande un mot de passe puis renvoie la version hachée et salée, à utiliser comme mot de passe du serveur web ou comme clé API. Cette commande ne contacte pas le récurseur mais effectue le hachage à l'intérieur de rec_control. Un facteur de travail scrypt optionnel peut être spécifié, sous forme de puissance de deux. Le défaut est 1024.
help
Affiche une liste des commandes prises en charge comprises par le pdns_recursor en cours d'exécution.
list-dnssec-algos
Liste les algorithmes DNSSEC pris en charge (et potentiellement désactivés).
ping
Vérifie si le serveur est actif.
quit
Demande l'arrêt du récurseur, quittant le processus tout en laissant le système d'exploitation nettoyer les ressources.
quit-nicely
Demande un arrêt propre du récurseur. Cette méthode permet à tous les threads de terminer leur travail en cours et libère les ressources avant de quitter. C'est la méthode préférée pour arrêter le récurseur.
reload-acls
Recharge les ACLs.
reload-lua-script [NOM FICHIER]
(Re)charge le script Lua NOM FICHIER. Si NOM FICHIER est vide, tente de recharger le script actuellement chargé. Cela remplace le script actuellement chargé.
reload-lua-config [NOM FICHIER]
(Re)charge la configuration Lua NOM FICHIER. Si NOM FICHIER est vide, tente de recharger le fichier actuellement chargé. Notez que NOM FICHIER sera entièrement exécuté, tous les paramètres modifiés à l'exécution qui ne sont pas modifiés dans ce fichier resteront actifs. Les effets du rechargement n'ont pas toujours lieu immédiatement, car certains sous-systèmes rechargent et remplacent la configuration de manière asynchrone. Si des paramètres YAML sont utilisés, cette commande rechargera les parties des paramètres YAML modifiables à l'exécution.
reload-yaml
Recharge les parties des paramètres YAML modifiables à l'exécution.
reload-zones
Recharge les zones faisant autorité et les zones de transfert. Conserve la configuration actuelle en cas d'erreurs.
set-carbon-server CARBONE SERVEUR [CARBONE NOMNOTRE]
Définit le paramètre carbon-server à CARBONE SERVEUR. Si CARBONE NOMNOTRE n'est pas vide, définit également le paramètre carbon-ourname à CARBONE NOMNOTRE.
set-dnssec-log-bogus PARAMÈTRE
Définit le paramètre dnssec-log-bogus à PARAMÈTRE. Mettez à on ou yes pour journaliser les échecs de validation DNSSEC et à no ou off pour désactiver la journalisation de ces échecs.
set-ecs-minimum-ttl NB
Définit ecs-minimum-ttl-override à NB.
set-max-aggr-nsec-cache-size NB
Change le nombre maximum d'entrées dans le cache NSEC agressif. Si le cache est désactivé en réglant sa taille à 0 dans la configuration, la taille du cache ne peut pas être définie par cette commande. Définir la taille à 0 par cette commande conserve le cache, mais le rend largement inefficace car il est vidé périodiquement.
set-max-cache-entries NB
Change le nombre maximum d'entrées dans le cache DNS. Si réduit, la taille du cache commencera à diminuer jusqu'à ce nombre dans le cadre du processus normal de purge du cache, ce qui peut prendre un certain temps.
set-max-packetcache-entries NB
Change le nombre maximum d'entrées dans le cache de paquets. Si réduit, la taille du cache commencera à diminuer jusqu'à ce nombre dans le cadre du processus normal de purge du cache, ce qui peut prendre un certain temps.
set-minimum-ttl NB
Définit minimum-ttl-override à NB.
set-event-trace-enabled NB
Définit la journalisation des messages de trace d'événements, 0 = désactivé, 1 = protobuf, 2 = fichier journal, 3 = protobuf et fichier journal.
show-yaml [FICHIER]
Affiche la représentation Yaml de la configuration à l'ancienne.
top-queries
Affiche les 20 requêtes principales. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-pub-queries
Affiche les 20 requêtes principales regroupées par liste de suffixes publics. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-largeanswer-remotes
Affiche les 20 hôtes distants principaux générant de grandes réponses. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-remotes
Affiche les 20 hôtes distants les plus actifs. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-servfail-queries
Affiche les 20 requêtes principales provoquant des réponses servfail. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-bogus-queries
Affiche les 20 requêtes principales provoquant des réponses erronées. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-pub-servfail-queries
Affiche les 20 requêtes principales provoquant des réponses servfail regroupées par liste de suffixes publics. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-pub-bogus-queries
Affiche les 20 requêtes principales provoquant des réponses erronées regroupées par liste de suffixes publics. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-servfail-remotes
Affiche les 20 hôtes distants les plus actifs provoquant des réponses servfail. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-bogus-remotes
Affiche les 20 hôtes distants les plus actifs provoquant des réponses erronées. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
top-timeouts
Affiche les 20 destinations de timeouts descendants les plus actives. Les statistiques portent sur les 'stats-ringbuffer-entries' dernières requêtes.
trace-regex REGEX FICHIER
Émet une trace de résolution pour les requêtes correspondantes. Aucun argument ne désactive le traçage. Avant la version 4.9.0, il n'y avait pas d'argument FICHIER, les traces étaient toujours écrites dans le journal. À partir de la version 4.9.0, les informations de trace sont écrites dans le fichier spécifié, qui peut être - pour le flux standard.

Les requêtes correspondant à cette expression régulière généreront des sorties de traçage volumineuses. Sachez que les correspondances du cache de paquets ne généreront toujours pas de traçage. Pour désactiver l'expression régulière, passez trace-regex sans nouvelle expression régulière.

L'expression régulière est mise en correspondance avec les requêtes de domaine se terminant par un point. Par exemple, l'expression régulière 'powerdns.com$' ne correspondra pas à une requête pour 'www.powerdns.com', car la correspondance tentée sera avec 'www.powerdns.com.'.

De plus, comme il s'agit d'une expression régulière, pour correspondre exclusivement aux requêtes pour 'www.powerdns.com', il faut échapper les points : '^www\.powerdns\.com\.$'. Notez que les guillemets simples empêchent toute interprétation supplémentaire des barres obliques inverses par le shell.

Plusieurs correspondances peuvent être chaînées avec l'opérateur |. Par exemple, pour correspondre à toutes les requêtes pour des noms de domaine néerlandais (.nl) et allemands (.de), utilisez : '\.nl\.$|\.de\.$'.

unload-lua-script
Décharge le script Lua s'il y en avait un chargé.
version
Rapporte la version du Recursor en cours d'exécution.
wipe-cache DOMAINE [DOMAINE] [...]
Efface les entrées pour DOMAINE (correspondance exacte du nom) du cache. Ceci est utile si, par exemple, un serveur important a une nouvelle adresse IP, mais que le TTL n'a pas encore expiré. Plusieurs noms de domaine peuvent être passés. DOMAINE peut être suffixé par un $ pour supprimer tout l'arbre du cache. C'est-à-dire que powerdns.com$ supprimera toutes les entrées mises en cache sous et incluant le nom powerdns.com.

Note : cette commande efface également le cache négatif.

Attention : ne vous contentez pas d'effacer "www.somedomain.com", ses enregistrements NS ou sa cible CNAME peuvent toujours être indésirables, alors effacez "somedomain.com" également.

wipe-cache-typed qtype DOMAINE [DOMAINE] [...]
Identique à wipe-cache, mais efface uniquement les enregistrements du type qtype.
