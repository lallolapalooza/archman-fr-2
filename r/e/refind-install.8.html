NOM

refind-install - Installer rEFInd sur la partition système EFI (ESP) et créer une entrée NVRAM

SYNOPSIS

refind-install [--notesp | --usedefault fichier-périphérique | --root point-de-montage | --ownhfs fichier-périphérique ] [--keepname] [--nodrivers | --alldrivers] [--shim nom-fichier-shim] [--localkeys] [--encryptkeys] [--yes]

DESCRIPTION

Pour être utile, le gestionnaire de démarrage rEFInd doit être installé sur la partition système EFI (ESP) de l'ordinateur ou sur un autre emplacement accessible par EFI. Dans la plupart des cas, une entrée NVRAM décrivant l'emplacement de rEFInd doit également être créée. Ces étapes peuvent être effectuées manuellement ; cependant, la commande refind-install fournit un moyen automatisé d'effectuer ces tâches sous Linux et OS X. Le comportement exact et les options varient en fonction du système d'exploitation.

Voici quelques détails qui peuvent affecter le fonctionnement du script :

*
Si vous exécutez le script en tant qu'utilisateur ordinaire, il tente d'acquérir les privilèges root en utilisant la commande sudo. Cela fonctionne sur Mac OS X et certaines installations Linux (comme sous Ubuntu ou si vous vous êtes ajouté à la liste des utilisateurs sudo), mais sur certaines installations Linux, cela échouera. Sur de tels systèmes, vous devez exécuter refind-install en tant que root.
*
Sous OS X, vous pouvez exécuter le script avec une souris en ouvrant une session Terminal, puis en faisant glisser le fichier refind-install dans la fenêtre Terminal. Vous devrez appuyer sur la touche Retour ou Entrée pour exécuter le script.
*
Si vous utilisez la fonctionnalité de chiffrement de disque entier (WDE) de OS X 10.7 ou la fonctionnalité de volumes logiques dans OS X 10.10, vous devez installer rEFInd sur l'ESP ou sur une partition HFS+ séparée. Par défaut, depuis rEFInd 0.8.4, l'installation se fait sur l'ESP. Si vous préférez utiliser un volume HFS+ séparé, l'option --ownhfs fichier-périphérique pour refind-install est requise.
*
Si vous n'utilisez pas WDE ou des volumes logiques, vous pouvez installer rEFInd sur la partition racine (/) d'OS X en utilisant l'option --notesp de refind-install. L'utilisation de cette option est recommandée lors de la mise à niveau depuis une installation rEFInd fonctionnelle à cet emplacement.
*
Si vous remplacez rEFIt par rEFInd sur un Mac, il est possible que refind-install vous avertisse de la présence d'un programme appelé /Library/StartupItems/rEFItBlesser et vous demande si vous souhaitez le supprimer. Ce programme est conçu pour maintenir rEFIt comme gestionnaire de démarrage en le re-bénédictant automatiquement si le gestionnaire de démarrage par défaut change. Ceci est évidemment indésirable si vous installez rEFInd comme gestionnaire de démarrage principal, il est donc généralement préférable de supprimer ce programme. Si vous préférez garder vos options ouvertes, vous pouvez répondre N lorsque refind-install demande si vous voulez supprimer rEFItBlesser, et copier-le manuellement ailleurs à la place. Si par la suite vous décidez de revenir à l'utilisation de rEFIt comme gestionnaire de démarrage principal, vous pourrez restaurer rEFItBlesser à sa place.
*
Si vous avez l'intention de démarrer des systèmes basés sur le BIOS sur un PC basé sur UEFI, vous devez modifier la ligne scanfor du fichier refind.conf pour activer les recherches pertinentes. Ceci n'est cependant pas nécessaire sur les Mac ; en raison de la popularité des doubles démarrages avec Windows sur les Mac, les recherches BIOS/héritées sont activées par défaut sur les Mac.
*
Sous Linux, refind-install vérifie le type de système de fichiers du répertoire /boot et, si un pilote de système de fichiers correspondant est disponible, l'installe. Notez que le "répertoire /boot" peut se trouver sur une partition séparée ou faire partie de votre système de fichiers racine (/), auquel cas le pilote de votre système de fichiers racine est installé. Cette fonctionnalité ne fonctionnera probablement pas correctement depuis un système d'urgence, bien qu'elle puisse fonctionner si vous avez une partition /boot séparée et si vous montez cette partition à /boot dans votre système d'urgence, et l'ESP à /boot/efi.
*
Sous OS X, refind-install vérifie vos tables de partitions à la recherche de signes d'une installation Linux. Si un tel signe est trouvé, le script installe le pilote de système de fichiers EFI pour le système de fichiers ext4 de Linux. Cela permettra à rEFInd de lire votre noyau Linux s'il se trouve sur un système de fichiers ext2, ext3 ou ext4. Notez que certaines configurations nécessiteront un fichier /boot/refind_linux.conf, qui ne peut être généré de manière fiable que sous Linux. (Le script mkrlconf fourni avec rEFInd s'acquittera de cette tâche une fois que vous aurez démarré Linux.) En attendant, vous pouvez lancer GRUB depuis rEFInd ou appuyer deux fois sur F2 ou Insert après avoir mis en surbrillance l'option Linux dans rEFInd. Cela vous permettra d'entrer une spécification root=/dev/quelquechose, où /dev/quelquechose est l'identifiant de périphérique de votre système de fichiers racine (/) Linux.
*
Si vous exécutez refind-install sous Linux et si /boot/refind_linux.conf n'existe pas déjà, refind-install crée ce fichier et le peuple avec quelques entrées d'exemple. Si /boot se trouve sur une partition FAT (ou HFS+ sur un Mac), ou s'il se trouve sur une partition ext2fs, ext3fs, ext4fs, ReiserFS, Btrfs, ou HFS+ et que vous installez un pilote approprié, rEFInd détectera votre noyau et le démarrera probablement correctement. Certains systèmes nécessiteront cependant des ajustements manuels de refind_linux.conf, par exemple pour ajouter dolvm aux options de démarrage sur les systèmes Gentoo qui utilisent LVM.
*
Si vous passez l'option --shim au script (avec un nom de fichier pour un binaire Shim), le script se configure pour une configuration de démarrage sécurisé via Shim. Par défaut, cela entraîne le renommage du binaire rEFInd en grubx64.efi. Les versions récentes de Shim prennent en charge le passage du nom du programme suivant à Shim via un paramètre. Si vous souhaitez utiliser cette fonctionnalité, vous pouvez passer l'option --keepname à refind-install.

Après avoir exécuté refind-install, vous devriez parcourir la sortie du script pour vous assurer que tout semble correct. refind-install affiche des messages d'erreur lorsqu'il rencontre des problèmes, par exemple si l'ESP est montée en lecture seule ou si vous manquez d'espace disque. Vous devrez peut-être corriger ces problèmes manuellement et relancer le script. Dans certains cas, vous devrez peut-être recourir à une installation manuelle, ce qui vous donnera un meilleur contrôle sur les détails tels que la partition à utiliser pour l'installation.

OPTIONS

--notesp
Cette option, valide uniquement sous OS X, indique à refind-install d'installer rEFInd sur la partition racine d'OS X plutôt que sur l'ESP. Ce comportement était le défaut dans rEFInd 0.8.3 et versions antérieures, vous voudrez donc peut-être l'utiliser lors de la mise à niveau d'installations de cette version, sauf si vous avez utilisé --esp (qui est maintenant le comportement par défaut, bien que l'option --esp n'existe plus) ou --ownhfs. Vous voudrez peut-être également utiliser --notesp pour de nouvelles installations si vous êtes sûr de ne pas utiliser le chiffrement de disque entier ou des volumes logiques.
--usedefault fichier-périphérique
Vous pouvez installer rEFInd sur un disque en utilisant le nom de fichier par défaut/de secours EFI/BOOT/bootx64.efi (ainsi que EFI/BOOT/bootia32.efi et EFI/BOOT/bootaa64.efi, si les builds IA-32 et ARM64 sont disponibles) en utilisant cette option. Le fichier-périphérique doit être une ESP non montée, ou au moins une partition FAT, comme dans --usedefault /dev/sdc1. Les entrées NVRAM de votre ordinateur ne seront pas modifiées lors de l'installation de cette manière. L'intention est de pouvoir créer une clé USB amorçable ou d'installer rEFInd sur un ordinateur qui a tendance à "oublier" ses paramètres NVRAM avec cette option. Cette option est mutuellement exclusive avec --notesp et --root.
--ownhfs fichier-périphérique
Cette option ne doit être utilisée que sous OS X. Elle est utilisée pour installer rEFInd sur un volume HFS+ autre qu'un volume de démarrage Mac standard. Le résultat devrait être que rEFInd apparaîtra dans le propre gestionnaire de démarrage du Mac. Plus important encore, les opérations de mise en veille prolongée (suspend-to-RAM) peuvent fonctionner correctement. Notez que cette option nécessite un volume HFS+ qui n'est pas actuellement un volume de démarrage OS X. Il peut s'agir d'un volume de données ou d'une partition rEFInd dédiée. L'ESP pourrait également fonctionner, si elle est convertie pour utiliser HFS+ ; cependant, HFS+ est un système de fichiers non standard pour une ESP, et n'est donc pas recommandé.
--root point-de-montage
Cette option est destinée à aider à installer rEFInd depuis une "li
ve CD" ou d'un autre système d'urgence. Pour l'utiliser, vous devez monter votre installation régulière dans /point-de-montage, y compris votre répertoire /boot (s'il est séparé) dans /point-de-montage/boot et (sous Linux) votre ESP à cet endroit ou dans /point-de-montage/boot/efi. Le script refind-install installe ensuite rEFInd à l'emplacement approprié -- sous Linux, /point-de-montage/boot/EFI/refind ou /point-de-montage/boot/efi/EFI/refind, selon l'endroit où vous avez monté votre ESP. Sous OS X, cette option n'est utile qu'en conjonction avec --notesp, auquel cas rEFInd s'installera dans /point-de-montage/EFI/refind. Le script ajoute également une entrée à votre NVRAM pour rEFInd à cet emplacement. Vous ne pouvez pas utiliser cette option avec --usedefault. Notez que cette option n'est pas nécessaire lors d'une installation en double amorçage Linux/OS X ; installez simplement normalement sous OS X.
--nodrivers
Normalement, refind-install tente d'installer le pilote nécessaire pour lire /boot sous Linux. Cette tentative ne fonctionne que si vous utilisez ext2fs, ext3fs, ext4fs, ReiserFS ou Btrfs sur la partition concernée. Si vous souhaitez renoncer à cette installation de pilote, utilisez l'option --nodrivers. Cette option est implicite lorsque vous utilisez --usedefault.
--alldrivers
Lorsque vous spécifiez cette option, refind-install copie tous les fichiers de pilotes pour votre architecture. Vous pourriez vouloir supprimer les fichiers de pilotes inutilisés après avoir utilisé cette option. Notez que certains ordinateurs se bloquent ou ne fonctionnent pas avec certains pilotes si vous utilisez cette option, utilisez-la donc avec prudence.
--shim nom-fichier-shim ou --preloader nom-fichier-preloader
Si vous passez cette option à refind-install, le script copiera le fichier du programme shim spécifié dans le répertoire cible, copiera le fichier MokManager.efi depuis le répertoire du programme shim dans le répertoire cible, copiera la version 64 bits de rEFInd sous le nom grubx64.efi, et enregistrera shim auprès du firmware. (Si vous spécifiez également --usedefault, l'enregistrement NVRAM est ignoré. Si vous utilisez également --keepname, le renommage en grubx64.efi est ignoré.) Lorsque le fichier cible est identifié comme PreLoader, à peu près la même chose se produit, mais refind-install copie HashTool.efi au lieu de MokManager.efi et copie rEFInd sous le nom loader.efi au lieu de grubx64.efi. L'intention est de simplifier l'installation de rEFInd sur un ordinateur qui utilise le démarrage sécurisé ; lorsqu'il est ainsi configuré, rEFInd démarrera en mode de démarrage sécurisé, avec une mise en garde : la première fois que vous démarrez, MokManager/HashTool se lancera, et vous devrez l'utiliser pour localiser et installer une clé publique ou enregistrer rEFInd comme application de confiance. Le fichier de clé publique rEFInd se trouvera dans le sous-répertoire keys du répertoire rEFInd sous le nom refind.cer.
--localkeys
Cette option indique à refind-install de générer une nouvelle clé de propriétaire de machine (MOK), de la stocker dans /etc/refind.d/keys sous le nom refind_local.*, et de resigner tous les binaires 64 bits de rEFInd avec cette clé avant de les installer. C'est la méthode préférable pour installer rEFInd en mode de démarrage sécurisé, car cela signifie que vos binaires seront signés localement plutôt qu'avec ma propre clé, qui est utilisée pour signer les binaires de nombreux autres utilisateurs ; cependant, cette méthode nécessite que les binaires openssl et sbsign soient installés. Le premier est facilement disponible dans les dépôts de la plupart des distributions, mais le second ne l'est pas, donc cette option n'est pas la valeur par défaut.
--encryptkeys
Normalement, si vous utilisez l'option --localkeys, refind-install stocke les fichiers de clé locaux sur votre disque dur sous forme non chiffrée. Ainsi, si votre ordinateur est compromis, l'intrus pourrait utiliser votre propre clé pour signer un chargeur de démarrage modifié, annulant les avantages du démarrage sécurisé. Si vous utilisez cette option, alors la clé privée est stockée sous une forme chiffrée, sécurisée par un mot de passe de chiffrement. Vous devrez entrer ce mot de passe avant que la clé puisse être utilisée pour signer un quelconque binaire, réduisant ainsi le risque qu'un intrus puisse détourner votre processus de démarrage. C'est évidemment une option très souhaitable, mais le revers de la médaille est que vous devez vous souvenir du mot de passe et le saisir chaque fois que vous mettez à jour rEFInd ou tout autre programme signé avec votre clé privée. Cela rend également impossible une mise à jour complètement automatisée de rEFInd.
--keepname
Cette option n'est utile qu'en conjonction avec --shim. Elle indique à refind-install de conserver le nom de fichier régulier de rEFInd (typiquement refind_x64.efi) lorsqu'il est utilisé avec shim, au lieu de renommer le binaire en grubx64.efi. Ce changement réduit le risque de confusion en raison de problèmes de nom de fichier ; cependant, cette fonctionnalité nécessite que shim soit lancé avec un paramètre de ligne de commande qui pointe vers le binaire rEFInd sous son vrai nom. Les versions de shim antérieures à 0.7 ne prennent pas correctement en charge cette fonctionnalité. (La version 0.4 la prend en charge mais avec une interprétation boguée de la spécification du chargeur suivant.) Si vos variables NVRAM deviennent corrompues ou sont oubliées, cette fonctionnalité peut rendre le lancement de rEFInd plus difficile. Cette option est incompatible avec --usedefault et n'est pas disponible lors de l'exécution sous OS X ou sans l'option --shim. Si le script découvre une installation rEFInd existante sous EFI/BOOT ou EFI/Microsoft/Boot et aucune autre installation rEFInd lors de l'utilisation de cette option, il s'arrêtera.
--yes
Cette option fait que le script assume une réponse OUI à chaque invite oui/non qui peut être générée dans certaines conditions, par exemple si vous spécifiez --shim mais que refind-install ne détecte aucune preuve d'une installation de démarrage sécurisé. Cette option est principalement destinée à être utilisée par des scripts, comme ceux qui pourraient être utilisés dans le cadre d'une installation via un paquet RPM ou Debian.
