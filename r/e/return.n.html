return(n) Commandes intégrées Tcl return(n)

NOM

return - Retour d'une procédure, ou définition du code de retour d'un script

SYNTAXE

return ?résultat?

return ?-code code? ?résultat?

return ?option valeur ...? ?résultat?

DESCRIPTION

Dans son utilisation la plus simple, la commande return est utilisée sans options dans le corps d'une procédure pour retourner immédiatement le contrôle à l'appelant de la procédure. Si un argument résultat est fourni, sa valeur devient le résultat de la procédure renvoyé à l'appelant. Si résultat n'est pas spécifié, une chaîne vide sera retournée à l'appelant comme résultat de la procédure.

La commande return remplit une fonction similaire dans les fichiers de script évalués par la commande source. Lorsque source évalue le contenu d'un fichier comme un script, une invocation de la commande return entraînera l'arrêt immédiat de l'évaluation du script, et la valeur résultat (ou une chaîne vide) sera retournée comme résultat de la commande source.

CODES DE RETOUR EXCEPTIONNELS

En plus du résultat d'une procédure, le code de retour d'une procédure peut également être défini par return grâce à l'utilisation de l'option -code. Dans le cas habituel où l'option -code n'est pas spécifiée, la procédure retournera normalement. Cependant, l'option -code peut être utilisée pour générer un retour exceptionnel de la procédure. Code peut prendre l'une des valeurs suivantes :

ok (ou 0)
Retour normal : identique à l'omission de l'option. Le code de retour de la procédure est 0 (TCL_OK).
error (ou 1)
Retour d'erreur : le code de retour de la procédure est 1 (TCL_ERROR). La commande de procédure se comporte dans son contexte d'appel comme si elle était la commande error résultat. Voir ci-dessous pour les options supplémentaires.
return (ou 2)
Le code de retour de la procédure est 2 (TCL_RETURN). La commande de procédure se comporte dans son contexte d'appel comme si elle était la commande return (sans arguments).
break (ou 3)
Le code de retour de la procédure est 3 (TCL_BREAK). La commande de procédure se comporte dans son contexte d'appel comme si elle était la commande break.
continue (ou 4)
Le code de retour de la procédure est 4 (TCL_CONTINUE). La commande de procédure se comporte dans son contexte d'appel comme si elle était la commande continue.
valeur
Valeur doit être un entier ; elle sera retournée comme code de retour pour la procédure actuelle.

Lorsqu'une procédure souhaite signaler qu'elle a reçu des arguments invalides de son appelant, elle peut utiliser return -code error avec résultat défini sur un message d'erreur approprié. Sinon, l'utilisation de l'option return -code est principalement limitée aux procédures qui implémentent une nouvelle structure de contrôle.

La commande return -code agit de manière similaire dans les fichiers de script évalués par la commande source. Lors de l'évaluation du contenu d'un fichier comme script par source, une invocation de la commande return -code code donnera à source le code de retour code.

OPTIONS DE RETOUR

En plus d'un résultat et d'un code de retour, l'évaluation d'une commande en Tcl produit également un dictionnaire d'options de retour. En usage général, toutes les paires option valeur données comme arguments à return deviennent des entrées dans le dictionnaire d'options de retour, et toutes les valeurs sont acceptables sauf indication contraire ci-dessous. La commande catch peut être utilisée pour capturer toutes ces informations — le code de retour, le résultat et le dictionnaire d'options de retour — qui découlent de l'évaluation d'un script.

Comme documenté ci-dessus, l'entrée -code dans le dictionnaire d'options de retour reçoit un traitement spécial par Tcl. Il existe d'autres options de retour également reconnues et traitées spécialement par Tcl. Ce sont :

-errorcode liste
L'option -errorcode ne reçoit un traitement spécial que lorsque la valeur de l'option -code est TCL_ERROR. Alors, la valeur liste est destinée à être une information supplémentaire sur l'erreur, présentée sous forme de liste Tcl pour un traitement ultérieur par les programmes. Si aucune option -errorcode n'est fournie à return lorsque l'option -code error est fournie, Tcl définira la valeur de l'entrée -errorcode dans le dictionnaire d'options de retour à la valeur par défaut de NONE. L'option de retour -errorcode sera également stockée dans la variable globale errorCode.
-errorinfo info
L'option -errorinfo ne reçoit un traitement spécial que lorsque la valeur de l'option -code est TCL_ERROR. Alors, info est la trace de pile initiale, destinée à fournir à un lecteur humain des informations supplémentaires sur le contexte dans lequel l'erreur s'est produite. La trace de pile sera également stockée dans la variable globale errorInfo. Si aucune option -errorinfo n'est fournie à return lorsque l'option -code error est fournie, Tcl fournira sa propre valeur de trace de pile initiale dans l'entrée pour -errorinfo. La trace de pile initiale de Tcl n'inclura que l'appel à la procédure, et le déroulement de la pile ajoutera des informations sur les niveaux de pile supérieurs, mais il n'y aura aucune information sur le contexte de l'erreur au sein de la procédure. Typiquement, la valeur info est fournie à partir de la valeur de -errorinfo dans un dictionnaire d'options de retour capturé par la commande catch (ou à partir de la copie de ces informations stockée dans la variable globale errorInfo).
-errorstack liste
L'option -errorstack ne reçoit un traitement spécial que lorsque la valeur de l'option -code est TCL_ERROR. Alors, liste est la pile d'erreurs initiale, enregistrant les valeurs d'arguments réels passées à chaque niveau de proc. La pile d'erreurs sera également accessible via info errorstack. Si aucune option -errorstack n'est fournie à return lorsque l'option -code error est fournie, Tcl fournira sa propre pile d'erreurs initiale dans l'entrée pour -errorstack. La pile d'erreurs initiale de Tcl n'inclura que l'appel à la procédure, et le déroulement de la pile ajoutera des informations sur les niveaux de pile supérieurs, mais il n'y aura aucune information sur le contexte de l'erreur au sein de la procédure. Typiquement, la valeur liste est fournie à partir de la valeur de -errorstack dans un dictionnaire d'options de retour capturé par la commande catch (ou à partir de la copie de ces informations provenant de info errorstack).
-level niveau
Les options -level et -code travaillent ensemble pour définir le code de retour à renvoyer par l'une des commandes actuellement en cours d'évaluation. La valeur niveau doit être un entier non négatif représentant un nombre de niveaux sur la pile d'appels. Elle définit le nombre de niveaux ascendants sur la pile où le code de retour d'une commande actuellement en cours d'évaluation doit être code. Si aucune option -level n'est fournie, la valeur par défaut de niveau est 1, de sorte que return définisse le code de retour que la procédure actuelle retourne à son appelant, 1 niveau plus haut sur la pile d'appels. Le mécanisme par lequel ces options fonctionnent est décrit plus en détail ci-dessous.
-options options
La valeur options doit être un dictionnaire valide. Les entrées de ce dictionnaire sont traitées comme des paires option valeur supplémentaires pour la commande return.

MÉCANISMES DE GESTION DU CODE DE RETOUR

Les codes de retour sont utilisés en Tcl pour contrôler le flux du programme. Un script Tcl est une séquence de commandes Tcl. Tant que l'évaluation de chaque commande retourne un code de retour de TCL_OK, l'évaluation continue vers la commande suivante.

return(n) — Tcl

NAME

return

set return value for procedure or script

SYNOPSIS

return ?arg ?arg ...?
return ?-code code? ?-level i? ?value?

DESCRIPTION

The return command is used to terminate the execution of the current script, procedure, or sourced file, and to return a value or status code.

If return is invoked with no arguments, and it is not inside a procedure, it causes the script evaluation to stop. The return code of the script evaluation will be TCL_OK, and the return value will be an empty string.

If return is invoked with arguments, those arguments are concatenated together, separated by spaces, to form the return value of the current script evaluation. The return code of the script evaluation will be TCL_OK.

If return is invoked inside a procedure, it causes the procedure to return. The procedure's return value is formed by concatenating the arguments to return, separated by spaces. If return is invoked with no arguments, the procedure returns an empty string.

The return command also supports options that allow for more detailed control over the return status.

EXCEPTIONAL RETURN CODES

In addition to the normal return code TCL_OK, Tcl commands can return other exceptional return codes. These include TCL_ERROR, TCL_RETURN, TCL_BREAK, TCL_CONTINUE, and TCL_ABORT. When a command evaluation results in an exceptional return code, the normal sequential evaluation of the script is interrupted. The exceptional return code becomes the return code of the entire script, and any remaining commands in the script are not evaluated.

This mechanism is used to implement control flow commands like break, continue, and return, as well as to propagate errors.

RETURN OPTIONS

The return command supports the following options:

-code code
Specifies the return code for the command. The code can be:
  • A Tcl value (e.g., an integer like 0 or 1, or a string like "error"). If the value is not one of the special codes below, it is treated as TCL_OK if it evaluates to an integer 0, or TCL_ERROR otherwise.
  • TCL_OK
  • TCL_ERROR
  • TCL_RETURN
  • TCL_BREAK
  • TCL_CONTINUE
  • TCL_ABORT
    • -level i
    Specifies the call stack level relative to which the return should be handled. A value of 0 means the current level. A value of 1 (the default) means the caller's level. Higher values mean further up the call stack. This is primarily used by procedures and sourced scripts to control how returns propagate.
    -options dict
    A dictionary containing options to be used for the return. The keys of the dictionary are option names (e.g., "-code", "-level"), and the values are the corresponding option values. This allows for passing multiple return options at once.

    If no arguments are given after the options, the return value is an empty string.

    If one argument is given after the options, it becomes the return value.

    If multiple arguments are given after the options, they are concatenated, separated by spaces, to form the return value.

    RETURN CODE HANDLING MECHANISMS

    When a command is evaluated within a Tcl script, its return code is checked. Any exceptional return code (non-TCL_OK) returned by a command evaluation causes the flow on to the next command to be interrupted. Script evaluation ceases, and the exceptional return code from the command becomes the return code of the full script evaluation. This is the mechanism by which errors during script evaluation cause an interruption and unwinding of the call stack. It is also the mechanism by which commands like break, continue, and return cause script evaluation to terminate without evaluating all commands in sequence.

    Some of Tcl's built-in commands evaluate scripts as part of their functioning. These commands can make use of exceptional return codes to enable special features. For example, the built-in Tcl commands that provide loops — such as while, for, and foreach — evaluate a script that is the body of the loop. If evaluation of the loop body returns the return code of TCL_BREAK or TCL_CONTINUE, the loop command can react in such a way as to give the break and continue commands their documented interpretation in loops.

    Procedure invocation also involves evaluation of a script, the body of the procedure. Procedure invocation provides special treatment when evaluation of the procedure body returns the return code TCL_RETURN. In that circumstance, the -level entry in the return options dictionary is decremented. If after decrementing, the value of the -level entry is 0, then the value of the -code entry becomes the return code of the procedure. If after decrementing, the value of the -level entry is greater than zero, then the return code of the procedure is TCL_RETURN. If the procedure invocation occurred during the evaluation of the body of another procedure, the process will repeat itself up the call stack, decrementing the value of the -level entry at each level, so that the code will be the return code of the current command level levels up the call stack. The source command performs the same handling of the TCL_RETURN return code, which explains the similarity of return invocation during a source to return invocation within a procedure.

    The return code of the return command itself triggers this special handling by procedure invocation. If return is provided the option -level 0, then the return code of the return command itself will be the value code of the -code option (or TCL_OK by default). Any other value for the -level option (including the default value of 1) will cause the return code of the return command itself to be TCL_RETURN, triggering a return from the enclosing procedure.

    EXAMPLES

    First, a simple example of using return to return from a procedure, interrupting the procedure body.

    proc printOneLine {} {
    puts "line 1"    ;# This line will be printed.
    return
    puts "line 2"    ;# This line will not be printed.
}

    Next, an example of using return to set the value returned by the procedure.

    proc returnX {} {return X}
puts [returnX]    ;# prints "X"

    Next, a more complete example, using return -code error to report invalid arguments.

    proc factorial {n} {
    if {![string is integer $n] || ($n < 0)} {
        return -code error \
                "expected non-negative integer,\
                but got \"$n\""
    }
    if {$n < 2} {
        return 1
    }
    set m [expr {$n - 1}]
    set code [catch {factorial $m} factor]
    if {$code != 0} {
        return -code $code $factor
    }
    set product [expr {$n * $factor}]
    if {$product < 0} {
        return -code error \
                "overflow computing factorial of $n"
    }
    return $product
}

    Next, a procedure replacement for break.

    proc myBreak {} {
    return -code break
}

    With the -level 0 option, return itself can serve as a replacement for break, with the help of interp alias.

    interp alias {} Break {} return -level 0 -code break

    An example of using catch and return -options to re-raise a caught error:

    proc doSomething {} {
    set resource [allocate]
    catch {
        # Long script of operations
        # that might raise an error
    } result options
    deallocate $resource
    return -options $options $result
}

    Finally an example of advanced use of the return options to create a procedure replacement for return itself:

    proc myReturn {args} {
    set result ""
    if {[llength $args] % 2} {
        set result [lindex $args end]
        set args [lrange $args 0 end-1]
    }
    set options [dict merge {-level 1} $args]
    dict incr options -level
    return -options $options $result
}
