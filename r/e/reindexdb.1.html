reindexdb(1)

Paquet: postgresql-libs

Licences: PostgreSQL

REINDEXDB(1) Documentation PostgreSQL 18.1 REINDEXDB(1)

NOM

reindexdb - réindexe une base de données PostgreSQL

SYNTAXE

reindexdb [option-connexion...] [option...] [ -S | --schema schéma ]... [ -t | --table table ]... [ -i | --index index ]... [ -s | --system ] [nomdb | -a | --all]

DESCRIPTION

reindexdb est un utilitaire pour reconstruire les index d'une base de données PostgreSQL.

reindexdb est un wrapper autour de la commande SQL REINDEX. Il n'y a pas de différence effective entre la réindexation des bases de données via cet utilitaire et via d'autres méthodes d'accès au serveur.

OPTIONS

reindexdb accepte les arguments de ligne de commande suivants :

-a
--all

Réindexe toutes les bases de données.

--concurrently

Utilise l'option CONCURRENTLY. Voir REINDEX(7), où toutes les mises en garde de cette option sont expliquées en détail.

[-d] nomdb
[--dbname=]nomdb

Spécifie le nom de la base de données à réindexer, lorsque -a/--all n'est pas utilisé. Si ce n'est pas spécifié, le nom de la base de données est lu à partir de la variable d'environnement PGDATABASE. Si celle-ci n'est pas définie, le nom d'utilisateur spécifié pour la connexion est utilisé. Le nomdb peut être une chaîne de connexion. Si c'est le cas, les paramètres de la chaîne de connexion outrepasseront toute option de ligne de commande contradictoire.

-e
--echo

Affiche les commandes que reindexdb génère et envoie au serveur.

-i index
--index=index

Recrée uniquement l'index index. Plusieurs index peuvent être recréés en écrivant plusieurs options -i.

-j njob
--jobs=njob

Exécute les commandes de réindexation en parallèle en exécutant njob commandes simultanément. Cette option peut réduire le temps de traitement mais augmente également la charge sur le serveur de base de données.

reindexdb ouvrira njob connexions à la base de données, alors assurez-vous que votre paramètre max_connections est suffisamment élevé pour accueillir toutes les connexions.

Notez que cette option est incompatible avec l'option --system.

-q
--quiet

N'affiche pas les messages de progression.

-s
--system

Réindexe uniquement les catalogues système de la base de données.

-S schéma
--schema=schéma

Réindexe uniquement le schéma. Plusieurs schémas peuvent être réindexés en écrivant plusieurs options -S.

-t table
--table=table

Réindexe uniquement la table. Plusieurs tables peuvent être réindexées en écrivant plusieurs options -t.

--tablespace=tablespace

Spécifie l'espace de tables où les index sont reconstruits. (Ce nom est traité comme un identifiant entre guillemets doubles.)

-v
--verbose

Affiche des informations détaillées pendant le traitement.

-V
--version

Affiche la version de reindexdb et quitte.

-?
--help

Affiche l'aide sur les arguments de ligne de commande de reindexdb et quitte.

reindexdb accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-h hôte
--host=hôte

Spécifie le nom d'hôte de la machine sur laquelle le serveur est en cours d'exécution. Si la valeur commence par une barre oblique, elle est utilisée comme répertoire pour le socket Unix.

-p port
--port=port

Spécifie le port TCP ou l'extension du fichier de socket Unix local sur lequel le serveur écoute les connexions.

-U nomutilisateur
--username=nomutilisateur

Nom d'utilisateur pour se connecter.

-w
--no-password

N'émet jamais d'invite de mot de passe. Si le serveur requiert l'authentification par mot de passe et qu'aucun mot de passe n'est disponible par d'autres moyens tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les travaux par lots et les scripts où aucun utilisateur n'est présent pour entrer un mot de passe.

-W
--password

Force reindexdb à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car reindexdb demandera automatiquement un mot de passe si le serveur exige une authentification par mot de passe. Cependant, reindexdb gaspillera une tentative de connexion pour découvrir que le serveur veut un mot de passe. Dans certains cas, il vaut la peine de taper -W pour éviter la tentative de connexion supplémentaire.

--maintenance-db=nomdb

Lorsque -a/--all est utilisé, se connecte à cette base de données pour collecter la liste des bases de données à réindexer. Si non spécifié, la base de données postgres sera utilisée, ou si celle-ci n'existe pas, template1 sera utilisée. Cela peut être une chaîne de connexion. Si c'est le cas, les paramètres de la chaîne de connexion outrepasseront toute option de ligne de commande contradictoire. De plus, les paramètres de la chaîne de connexion autres que le nom de la base de données elle-même seront réutilisés lors de la connexion à d'autres bases de données.

ENVIRONNEMENT

PGDATABASE
PGHOST
PGPORT
PGUSER

Paramètres de connexion par défaut

PG_COLOR

Spécifie si la couleur doit être utilisée dans les messages diagnostiques. Les valeurs possibles sont always, auto et never.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15).

DIAGNOSTICS

En cas de difficulté, voir REINDEX(7) et psql(1) pour les discussions sur les problèmes potentiels et les messages d'erreur. Le serveur de base de données doit être en cours d'exécution sur l'hôte cible. De plus, tous les paramètres de connexion par défaut et les variables d'environnement utilisés par la bibliothèque frontale libpq s'appliqueront.

EXEMPLES

Pour réindexer la base de données test :

$ reindexdb test

Pour réindexer la table foo et l'index bar dans une base de données nommée abcd :

$ reindexdb --table=foo --index=bar abcd

reindexdb(1)

NOM

reindexdb - reconstruire les index d'une base de données PostgreSQL

SYNOPSIS

reindexdb [OPTION]... [--user=]USER [--host=]HOST [--port=]PORT [--dbname=]DBNAME

DESCRIPTION

reindexdb reconstruit les index d'une base de données PostgreSQL. Il peut également reconstruire des tables individuelles, toutes les tables d'une base de données ou toutes les bases de données d'un serveur. Si un index est corrompu, reindexdb peut être utilisé pour le reconstruire. Si les performances des requêtes se dégradent, reindexdb peut être utilisé pour reconstruire tous les index afin de les optimiser.

reindexdb est un script shell qui utilise le programme psql pour exécuter les commandes nécessaires.

OPTIONS

-a, --all-databases
Reconstruit les index dans toutes les bases de données. S'il est omis, seules les bases de données spécifiées sont traitées.
-d DBNAME, --dbname=DBNAME
Spécifie le nom de la base de données à traiter. Par défaut, il utilise la valeur de la variable d'environnement PGDATABASE, ou le nom d'utilisateur.
-e, --echo
Affiche les commandes SQL envoyées au serveur.
-f, --force
Ne demande pas de confirmation avant la reconstruction.
-h HOST, --host=HOST
Spécifie le nom d'hôte du serveur sur lequel la base de données est exécutée. Par défaut, il utilise la valeur de la variable d'environnement PGHOST, ou le socket de domaine Unix local.
-i INDEX, --index=INDEX
Reconstruit uniquement l'index spécifié. Les index sont spécifiés par leur nom. Si plusieurs index sont spécifiés, ils sont tous reconstruits.
-n, --no-security-warnings
Ne produit pas d'avertissements sur la sécurité (par exemple, en cas d'utilisation de mots de passe en clair).
-o [NO]OIDS
Reconstruit les index pour les tables qui ont des OID, ou ne reconstruit pas les index pour les tables qui ont des OID. Par défaut, les OID sont utilisés.
-p PORT, --port=PORT
Spécifie le port TCP de l'ordinateur sur lequel le serveur PostgreSQL écoute. Par défaut, il utilise la valeur de la variable d'environnement PGPORT, ou le port par défaut du compilateur.
-q, --quiet
Ne renvoie pas de messages, sauf en cas d'erreur.
-s SCHEMA, --schema=SCHEMA
Reconstruit uniquement les index du schéma spécifié. S'il est omis, tous les schémas sont traités.
-t TABLE, --table=TABLE
Reconstruit tous les index de la table spécifiée. S'il est omis, toutes les tables sont traitées.
-U USERNAME, --username=USERNAME
Spécifie le nom d'utilisateur à utiliser pour la connexion. Par défaut, il utilise le nom d'utilisateur actuel.
-v, --verbose
Spécifie le mode verbeux. Affiche des informations détaillées sur les actions effectuées.
-V, --version
Affiche la version du programme et quitte.
-?, --help
Affiche l'aide sur l'utilisation de reindexdb et quitte.

ENVIRONNEMENT

reindexdb utilise les variables d'environnement courantes de libpq, telles que PGHOST, PGPORT, PGDATABASE et PGPASSWORD.

DIAGNOSTICS

En cas d'erreur, reindexdb renvoie un code de sortie non nul.

EXEMPLES

Pour reconstruire tous les index de la base de données mydatabase:

reindexdb mydatabase

Pour reconstruire l'index myindex dans la table mytable de la base de données mydatabase:

reindexdb --index myindex --table mytable mydatabase

Pour reconstruire tous les index de toutes les bases de données sur un serveur distant:

reindexdb --all-databases --host=db.example.com

psql(1), REINDEX
