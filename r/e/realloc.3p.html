REALLOC(3P) Manuel du programmeur POSIX REALLOC(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

realloc — réallocateur de mémoire

SYNOPIS

#include <stdlib.h>
void *realloc(void *ptr, size_t size);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 renvoie à la norme ISO C.

La fonction realloc() doit désallouer l'ancien objet pointé par ptr et retourner un pointeur vers un nouvel objet ayant la taille spécifiée par size. Le contenu du nouvel objet doit être le même que celui de l'ancien objet avant la désallocation, jusqu'à la moindre des tailles nouvelle et ancienne. Les octets du nouvel objet au-delà de la taille de l'ancien objet ont des valeurs indéterminées. Si la taille de l'espace demandé est zéro, le comportement est défini par l'implémentation : soit un pointeur nul est retourné, soit le comportement est tel que si la taille était une valeur non nulle, sauf que le comportement est indéfini si le pointeur retourné est utilisé pour accéder à un objet. Si l'espace ne peut pas être alloué, l'objet reste inchangé.

Si ptr est un pointeur nul, realloc() est équivalent à malloc() pour la taille spécifiée.

Si ptr ne correspond pas à un pointeur retourné précédemment par calloc(), malloc() ou realloc(), ou si l'espace a été précédemment désalloué par un appel à free() ou realloc(), le comportement est indéfini.

L'ordre et la contiguïté du stockage alloué par des appels successifs à realloc() ne sont pas spécifiés. Le pointeur retourné si l'allocation réussit doit être suffisamment aligné pour pouvoir être assigné à un pointeur de n'importe quel type d'objet, puis utilisé pour accéder à un tel objet dans l'espace alloué (jusqu'à ce que l'espace soit explicitement libéré ou réalloué). Chaque allocation de ce type doit retourner un pointeur vers un objet distinct de tout autre objet. Le pointeur retourné doit pointer vers le début (adresse d'octet la plus basse) de l'espace alloué. Si l'espace ne peut pas être alloué, un pointeur nul doit être retourné.

VALEUR DE RETOUR

En cas d'achèvement réussi, realloc() retourne un pointeur vers l'espace alloué (potentiellement déplacé). Si size est 0, soit :

*
Un pointeur nul est retourné et, si ptr n'est pas un pointeur nul, errno est défini à une valeur définie par l'implémentation.
*
Un pointeur vers l'espace alloué est retourné et l'objet mémoire pointé par ptr est libéré. L'application doit s'assurer que le pointeur n'est pas utilisé pour accéder à un objet.

S'il n'y a pas assez de mémoire disponible, realloc() retourne un pointeur nul et définit errno à [ENOMEM]. Si realloc() retourne un pointeur nul et que errno a été défini à [ENOMEM], la mémoire référencée par ptr ne doit pas être modifiée.

ERREURS

La fonction realloc() échoue si :

ENOMEM
Mémoire insuffisante disponible.

EXEMPLES

Aucun.

USAGE APPLICATION

La description de realloc() a été modifiée par rapport aux versions précédentes de cette norme pour s'aligner sur la norme ISO/IEC 9899:1999. Les versions précédentes permettaient explicitement un appel à realloc(p, 0) pour libérer l'espace pointé par p et retourner un pointeur nul. Bien que ce comportement puisse être interprété comme étant autorisé par cette version de la norme, le comité du langage C a indiqué que cette interprétation est incorrecte. Les applications doivent supposer que si realloc() retourne un pointeur nul, l'espace pointé par p n'a pas été libéré. Comme cela pourrait entraîner des doubles libérations, les implémentations devraient également définir errno si un pointeur nul indique réellement un échec, et les applications ne devraient libérer l'espace que si errno a été modifié.

RATIONALE

Aucun.

ORIENTATIONS FUTURES

Cette norme renvoie à la norme ISO C. Bien que cette norme contienne actuellement un langage qui pourrait permettre à realloc(p, 0), où p n'est pas un pointeur nul, de libérer p tout en retournant un pointeur nul, le comité responsable de cette norme envisage de clarifier le langage pour interdire explicitement cette alternative.
