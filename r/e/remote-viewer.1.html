NOM

remote-viewer - un client de bureau distant simple

SYNTAXE

remote-viewer [OPTIONS] -- [URI]

DESCRIPTION

remote-viewer est un client d'affichage distant simple. Les protocoles pris en charge sont SPICE et VNC.

Lancer remote-viewer sans URI ouvrira une boîte de dialogue simple avec une zone de saisie et une liste des URI précédemment accédés avec succès.

L'URI peut également pointer vers un fichier de paramètres de connexion, voir la section FICHIER DE CONNEXION pour une description du format.

Si l'URI est '-', alors remote-viewer lira l'entrée standard comme un fichier de paramètres de connexion et tentera de s'y connecter en utilisant celui-ci.

Dans certaines circonstances, le visualiseur peut avoir besoin de capturer le pointeur de la souris. La séquence de touches par défaut pour libérer la capture est "Ctrl_L"+"Alt_L", cependant, cela peut être remplacé en utilisant l'argument "--hotkeys" décrit ci-dessous.

OPTIONS

Les options suivantes sont acceptées lors de l'exécution de "remote-viewer" :

-h, --help
Affiche un résumé de l'aide de la ligne de commande
-V, --version
Affiche le numéro de version du programme
-v, --verbose
Affiche des informations sur la connexion
-z PCT, --zoom=PCT
Niveau de zoom de la fenêtre d'affichage en pourcentage. Plage 10-400.
-f, --full-screen
Démarre avec les fenêtres maximisées en plein écran.

Si pris en charge, l'affichage distant sera reconfiguré pour correspondre à la configuration des moniteurs du client physique, en activant ou désactivant des moniteurs supplémentaires si nécessaire. Ceci est actuellement implémenté uniquement par le backend Spice et peut être désactivé par l'argument "--auto-resize".

Pour spécifier quels moniteurs clients sont utilisés en mode plein écran, voir la section CONFIGURATION ci-dessous.

--auto-resize <toujours|jamais>
Contrôle s'il est autorisé de tenter de redimensionner le frame-buffer distant pour qu'il corresponde à la taille de la fenêtre locale. Ceci est actuellement activé par défaut, mais notez que tous les serveurs ne prennent pas en charge cette fonctionnalité.
-t TITRE, --title TITRE
Définit le titre de la fenêtre sur TITRE
-s, --shared
Permet une session partagée avec plusieurs clients
--cursor auto|local
Contrôle la manière dont le curseur de la souris est rendu. "auto" est le comportement par défaut, qui respectera le comportement demandé par le serveur distant. Cela peut impliquer que le serveur rende le curseur dans le frame-buffer, ou qu'il envoie les détails du curseur au client pour qu'il le rende. "local" remplace ce défaut pour demander que le curseur du bureau local soit toujours rendu, quel que soit ce que demande le serveur. Ce dernier est rarement nécessaire, mais peut être utilisé si le serveur a une mauvaise configuration qui entraîne la disparition de son propre curseur.
--debug
Affiche les informations de débogage
-H HOTKEYS, --hotkeys HOTKEYS
Définit les raccourcis clavier globaux. Par défaut, les raccourcis clavier ne fonctionnent que lorsque le widget d'affichage invité n'a pas le focus. Toutes les actions spécifiées dans HOTKEYS seront efficaces même lorsque le widget d'affichage invité a le focus d'entrée. Le format de HOTKEYS est <action1>=<clé1>[+<clé2>][,<action2>=<clé3>[+<clé4>]]. Les noms de touches ne sont pas sensibles à la casse. Les actions valides sont : toggle-fullscreen, release-cursor, zoom-in, zoom-out, zoom-reset, secure-attention, usb-device-reset, smartcard-insert et smartcard-remove. L'action "secure-attention" envoie une séquence d'attention sécurisée (Ctrl+Alt+Suppr) à l'invité. Exemples : 
--hotkeys=toggle-fullscreen=shift+f11,release-cursor=shift+f12
--hotkeys=release-cursor=ctrl+alt

Notez que les raccourcis pour lesquels aucune liaison n'est donnée sont désactivés. Bien que les raccourcis spécifiés ici soient gérés par le client, il est toujours possible d'envoyer ces combinaisons de touches à l'invité via un élément de menu.

-K, --keymap
Remappe et/ou bloque les frappes de touches fournies à l'hôte. Tous les identifiants de touches sont sensibles à la casse et suivent la convention de nommage telle que définie dans gdkkeysyms.h sans le préfixe GDK_KEY_.

Lancer l'application avec --debug affichera les symboles de frappe de touches de la manière suivante :
"Key pressed was keycode='0x63', gdk_keyname='c'"
"Key pressed was keycode='0xffeb', gdk_keyname='Super_L'"

Le format pour fournir une table de correspondance des touches est : <srcKeySym1>=[<destKeySym1>][+<destKeySym2][,<srckeySym2>=[<destKeySym1]

Pour bloquer une frappe de touche, attribuez simplement un paramètre vide à srcKeySym.

Exemple :
--keymap=Super_L=,Alt_L=,1=Shift_L+F1,2=Shift_L+F2

Ceci bloquera les frappes Super_L (généralement la touche Windows) et Alt_L, et remappera la touche 1 vers Shift F1, 2 vers Shift F2.

-k, --kiosk
Démarre en mode kiosque. Dans ce mode, l'application démarrera en plein écran avec une interface utilisateur minimale. Elle empêchera l'utilisateur de quitter ou d'effectuer toute interaction en dehors de l'utilisation de la session de bureau à distance.

Notez qu'il ne peut pas offrir une solution sécurisée complète par lui-même. Votre système de kiosque doit avoir une configuration et des paramètres de sécurité supplémentaires pour verrouiller le système d'exploitation. En particulier, vous devez configurer ou désactiver le gestionnaire de fenêtres, limiter les capacités de la session, utiliser un mécanisme de redémarrage/watchdog, désactiver le changement de VT, etc.

--kiosk-quit <jamais|à_la_déconnexion>
Par défaut, lorsque le mode kiosque est activé, virt-viewer reste ouvert lorsque la connexion au serveur distant est terminée. En définissant l'option kiosk-quit sur la valeur "on-disconnect", virt-viewer se fermera à la place.

RACCOURCI CLAVIER

Une combinaison de raccourcis clavier est décrite par une série de chaînes de touches séparées par '+' qui doivent être enfoncées simultanément pour activer l'action associée.

Elle doit être composée de modificateurs (shift, ctrl ou alt) et d'une touche non-modificatrice. Par exemple, "shift+f11".

FICHIER DE CONNEXION

Le fichier de connexion remote-viewer est au format de fichier INI, avec un groupe obligatoire [virt-viewer] et une clé "type".

Exemple

Ouvrir un fichier contenant le contenu suivant lancera remote-viewer en mode plein écran et se connectera à l'hôte "betsiboka" en utilisant le protocole SPICE :

[virt-viewer]
type=spice
host=betsiboka
port=5900
fullscreen=1

Liste des clés

"version" (chaîne)
Si le numéro de version de remote-viewer n'est pas supérieur ou égal à la version requise, une erreur est générée avec la version attendue.

Le format de version accepté est une liste d'entiers séparés par des '.'. Il peut être suivi d'un trait '-' et d'un numéro de build supplémentaire avec le même format.

La comparaison des versions se fait en comparant chaque entier de la liste un par un. Si un des composants n'est pas un nombre, la comparaison des versions échouera et considérera que les 2 versions sont identiques.

"versions" (liste osid:version)
Ceci est une liste de couples osid:version séparés par ';'. osid est une chaîne de caractères arbitraire, version est un numéro de version dans le même format que dans le champ 'version'. Un couple donné indique que les builds de remote-viewer correspondant à l' 'osid' donné (fedora22, debian7, ...) doivent être au moins de la version 'version'. Par souci de cohérence, il est recommandé d'utiliser les shortids d'OS de libosinfo comme osid.
"newer-version-url" (chaîne)
Si spécifié, ce champ

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

eld est une URL qui sera affichée à l'utilisateur lorsqu'une vérification de version échoue.
"type" (chaîne, obligatoire)
Le type de session, soit "spice", "vnc" ou "ovirt".
"unix-path" (chaîne)
Le serveur auquel se connecter, en utilisant un chemin de socket Unix. (pris en charge avec spice, depuis la version 8.0)

Cette option est incompatible avec "host", "port" et "tls-port".

"host" (chaîne)
L'hôte du serveur auquel se connecter.
"port" (entier)
Le port du serveur auquel se connecter.
"tls-port" (entier)
Le port TLS/SSL du serveur auquel se connecter.
"username" (chaîne)
Le nom d'utilisateur pour l'authentification de la session.
"password" (chaîne)
Le mot de passe pour l'authentification de la session.
"disable-channels" (liste de chaînes)
La liste des canaux de session à désactiver.

Les canaux SPICE actuels sont : main, display, inputs, cursor, playback, record, smartcard, usbredir.

"tls-ciphers" (chaîne)
Définit la liste des chiffrements à utiliser pour la connexion sécurisée, au format textuel de la liste de chiffrements OpenSSL. (voir ciphers(1))
"title" (chaîne)
Chaîne à présenter dans le titre de la fenêtre.
"fullscreen" (booléen)
Ouvre les fenêtres du client en plein écran.
"ca" (chaîne)
Certificat d'autorité de certification au format PEM (utilisant "\n" pour séparer les lignes). Il sera utilisé pour vérifier le certificat SSL utilisé pour les sessions SPICE TLS.
"host-subject" (chaîne)
Vérifie que le sujet du certificat correspond au sujet donné.
"toggle-fullscreen" (raccourci clavier chaîne)
Raccourci clavier pour passer en mode plein écran et en sortir. (voir HOTKEY pour la description de la chaîne attendue)
"release-cursor" (raccourci clavier chaîne)
Raccourci clavier pour libérer la capture du curseur. (voir HOTKEY pour la description de la chaîne attendue)
"zoom-in" (raccourci clavier chaîne)
Raccourci clavier pour zoomer et agrandir la taille de la fenêtre client. (voir HOTKEY pour la description de la chaîne attendue)
"zoom-out" (raccourci clavier chaîne)
Raccourci clavier pour dézoomer et réduire la taille de la fenêtre client. (voir HOTKEY pour la description de la chaîne attendue)
"zoom-reset" (raccourci clavier chaîne)
Raccourci clavier pour réinitialiser le zoom et la taille de la fenêtre client. (voir HOTKEY pour la description de la chaîne attendue)
"smartcard-insert" (raccourci clavier chaîne)
Raccourci clavier pour insérer une carte à puce émulée. (voir HOTKEY pour la description de la chaîne attendue)
"smartcard-remove" (raccourci clavier chaîne)
Raccourci clavier pour retirer une carte à puce émulée. (voir HOTKEY pour la description de la chaîne attendue)
"color-depth" (entier)
Définit la profondeur de couleur de l'affichage invité (16 ou 32).
"disable-effects" (liste de chaînes)
Une liste d'effets de bureau à désactiver dans l'invité distant.

Les effets qui peuvent être désactivés avec SPICE sont : wallpaper, font-smooth, animation ou all.

"enable-smartcard" (booléen)
Défini à 1 pour activer la redirection de carte à puce côté client.
"enable-usbredir" (booléen)
Défini à 1 pour activer la redirection de périphérique USB côté client.
"enable-usb-autoshare" (booléen)
Défini à 1 pour activer le partage automatique des périphériques USB côté client.
"usb-filter" (chaîne)
Définit une chaîne spécifiant un filtre à utiliser pour déterminer quels périphériques USB doivent être connectés automatiquement lors de leur branchement, un filtre se compose d'une ou plusieurs règles. Où chaque règle a la forme :

"class,vendor,product,version,allow"

Utilisez -1 pour class/vendor/product/version pour accepter n'importe quelle valeur.

Et les règles elles-mêmes sont concaténées comme suit :

"rule1|rule2|rule3"

"secure-channels" (liste de chaînes)
La liste des canaux de session à sécuriser.

Les canaux SPICE actuels sont : main, display, inputs, cursor, playback, record, smartcard, usbredir.

"delete-this-file" (booléen)
Défini à 1 pour que le client supprime ce fichier de connexion (s'il ne peut pas le faire, il échouera silencieusement)
"proxy" (chaîne)
Une URL de proxy pour tunneliser la connexion.

Au moment de la rédaction de cette documentation, la seule méthode de proxy prise en charge avec Spice est HTTP CONNECT.

Par exemple, pour tunneliser la connexion via le proxy HTTP foobar sur le port 8080, utilisez la valeur "http://foobar:8080".

Prise en charge d'oVirt

Le fichier de connexion peut également contenir des options spécifiques à oVirt lorsque la prise en charge d'oVirt est compilée. Ces options sont utilisées pour interagir avec l'API REST d'oVirt. Ceci est actuellement utilisé uniquement pour afficher un menu permettant de changer l'image CD utilisée par la machine virtuelle depuis l'interface utilisateur de remote-viewer. Ces options se trouvent dans un groupe optionnel [ovirt].

"host" (chaîne, obligatoire)
L'instance oVirt à laquelle se connecter. Ceci correspond au nom d'hôte auquel on se connecterait pour accéder au portail utilisateur ou administrateur d'oVirt.
"vm-guid" (chaîne, obligatoire)
GUID de la machine virtuelle oVirt à laquelle se connecter.
"jsessionid" (chaîne)
Valeur à définir pour le cookie 'jsessionid'. Avec oVirt 3.6, définir ce cookie d'authentification à une valeur valide permettra d'interagir avec l'API REST d'oVirt sans demander d'identifiants.
"sso-token" (chaîne)
Valeur à définir pour l'en-tête 'Authorization'. Avec oVirt 4.0 ou plus récent, définir cet en-tête d'authentification à une valeur valide permettra d'interagir avec l'API REST d'oVirt sans demander d'identifiants.
"ca" (chaîne)
Certificat d'autorité de certification au format PEM (utilisant "\n" pour séparer les lignes). Il sera utilisé pour valider le certificat utilisé pour la session HTTPS de l'API REST oVirt que remote-viewer établira.

CONFIGURATION

Un petit nombre d'options de configuration peuvent être contrôlées en éditant le fichier de paramètres situé dans le répertoire de configuration de l'utilisateur :

<USER-CONFIG-DIR>/virt-viewer/settings

Ce fichier est un fichier texte au format INI, avec les options de l'application dans le groupe [virt-viewer] et les options par invité dans un groupe identifié par l'UUID de l'invité. Les options de l'application ne doivent pas être modifiées manuellement. Il existe également un groupe spécial [fallback] qui spécifie les options pour tous les invités qui n'ont pas de groupe explicite.

Pour chaque invité, la configuration initiale du moniteur en plein écran peut être spécifiée en utilisant la clé monitor-mapping. Cette configuration ne prend effet que lorsque l'option -f/--full-screen est spécifiée.

La valeur de cette clé est une liste de correspondances entre un affichage invité et un moniteur client. Chaque correspondance est séparée par un point-virgule, et les correspondances ont le format <ID-AFFICHAGE-INVITÉ>:<ID-MONITEUR-CLIENT>.

Par exemple, pour mapper les affichages invités 1 et 2 aux moniteurs clients 2 et 3 pour l'invité avec un UUID de e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2, utilisez :

[e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2]
monitor-mapping=1:2;2:3

Le monitor-mapping doit contenir les identifiants de tous les affichages de 1 au dernier identifiant d'affichage souhaité, par exemple "monitor-mapping=3:3" est invalide car les correspondances pour les affichages 1 et 2 ne sont pas spécifiées.

La clé de configuration share-clipboard contient une valeur booléenne. Si c'est "true", alors le presse-papiers est partagé avec les invités si le partage de presse-papiers est pris en charge par le protocole utilisé.

EXEMPLES

Pour se connecter au serveur SPICE sur l'hôte "makai" avec le port 5900

remote-viewer spice://makai:5900

Pour se connecter au serveur VNC sur l'hôte "tsingy" avec le port 5900

remote-viewer vnc://tsingy:5900

Pour se connecter à une machine virtuelle nommée "toliara" sur un serveur oVirt à l'adresse example.org

remote-viewer ovirt://[username@]example.org/toliara
