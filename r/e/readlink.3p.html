READLINK(3P) Manuel du programmeur POSIX READLINK(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

readlink, readlinkat — lire le contenu d'un lien symbolique

SYNTAXE

#include <unistd.h>
ssize_t readlink(const char *restrict path, char *restrict buf,
    size_t bufsize);
#include <fcntl.h>
ssize_t readlinkat(int fd, const char *restrict path,
    char *restrict buf, size_t bufsize);

DESCRIPTION

La fonction readlink() place le contenu du lien symbolique référencé par path dans le tampon buf qui a une taille de bufsize. Si le nombre d'octets du lien symbolique est inférieur à bufsize, le contenu du reste de buf est indéterminé. Si l'argument buf n'est pas assez grand pour contenir le contenu du lien, les bufsize premiers octets seront placés dans buf.

Si la valeur de bufsize est supérieure à {SSIZE_MAX}, le résultat est défini par l'implémentation.

En cas de succès, readlink() marque pour mise à jour l'horodatage du dernier accès aux données du lien symbolique.

La fonction readlinkat() est équivalente à la fonction readlink(), sauf dans le cas où path spécifie un chemin relatif. Dans ce cas, le lien symbolique dont le contenu est lu est relatif au répertoire associé au descripteur de fichier fd au lieu du répertoire de travail courant. Si le mode d'accès du descripteur de fichier ouvert n'est pas O_SEARCH, la fonction vérifie si les recherches de répertoire sont autorisées en utilisant les permissions actuelles du répertoire sous-jacent au descripteur de fichier. Si le mode d'accès est O_SEARCH, la fonction n'effectue pas cette vérification.

Si readlinkat() reçoit la valeur spéciale AT_FDCWD dans le paramètre fd, le répertoire de travail courant est utilisé et le comportement est identique à un appel à readlink().

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent le nombre d'octets placés dans le tampon. Sinon, ces fonctions retournent une valeur de -1, laissent le tampon inchangé et définissent errno pour indiquer l'erreur.

ERREURS

Ces fonctions échouent si :

EACCES
La permission de recherche est refusée pour un composant du préfixe du chemin de path.
EINVAL
L'argument path nomme un fichier qui n'est pas un lien symbolique.
EIO
Une erreur d'E/S s'est produite lors de la lecture du système de fichiers.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un composant d'un nom de fichier est supérieure à {NAME_MAX}.
ENOENT
Un composant de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOTDIR
Un composant du préfixe du chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou l'argument path contient au moins un caractère non-<slash> et se termine par un ou plusieurs <slash> finaux et le dernier composant du nom de fichier nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.

La fonction readlinkat() échoue si :

EACCES
Le mode d'accès du descripteur de fichier ouvert associé à fd n'est pas O_SEARCH et les permissions du répertoire sous-jacent à fd n'autorisent pas les recherches de répertoire.
EBADF
L'argument path ne spécifie pas un chemin absolu et l'argument fd n'est ni AT_FDCWD ni un descripteur de fichier valide ouvert en lecture ou en recherche.
ENOTDIR
L'argument path n'est pas un chemin absolu et fd est un descripteur de fichier associé à un fichier non-répertoire.

Ces fonctions peuvent échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path.
ENAMETOOLONG

La longueur d'un nom de fichier dépasse {PATH_MAX}, ou la résolution du chemin d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.

Les sections suivantes sont informatives.

EXEMPLES

Lecture du nom d'un lien symbolique

L'exemple suivant montre comment lire le nom d'un lien symbolique nommé /modules/pass1.

#include <unistd.h>
char buf[1024];
ssize_t len;
...
if ((len = readlink("/modules/pass1", buf, sizeof(buf)-1)) != -1)
    buf[len] = '\0';

UTILISATION PAR L'APPLICATION

Les applications conformes ne doivent pas supposer que le contenu retourné du lien symbolique est terminé par un caractère nul.

RATIONNEL

Le type associé à bufsiz est un size_t afin d'être cohérent avec le standard ISO C et la définition de read(). Le comportement spécifié pour readlink() lorsque bufsiz est zéro représente la pratique historique. Pour ce cas, les développeurs du standard ont envisagé un changement où readlink() retournerait le nombre d'octets non nuls contenus dans le lien symbolique avec le tampon buf restant inchangé ; cependant, puisque la valeur du membre st_size de la structure stat peut être utilisée pour déterminer la taille du tampon nécessaire pour contenir le contenu du lien symbolique tel que retourné par readlink(), cette proposition a été rejetée et la pratique historique conservée.

Le but de la fonction readlinkat() est de lire le contenu des liens symboliques dans des répertoires autres que le répertoire de travail courant, sans exposition aux conditions de concurrence (race conditions). N'importe quelle partie du chemin d'un fichier pourrait être modifiée en parallèle à un appel à readlink(), résultant en un comportement indéterminé. En ouvrant un descripteur de fichier pour le répertoire cible et en utilisant la fonction readlinkat(), il est garanti que le lien symbolique lu est situé par rapport au répertoire souhaité.
