readlink(2) Manuel des appels système readlink(2)

NOM

readlink, readlinkat - lire la valeur d'un lien symbolique

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
ssize_t readlink(size_t bufsiz;
                 const char *restrict path,
                 char buf[restrict bufsiz], size_t bufsiz);
#include <fcntl.h>            /* Définition des constantes AT_* */
#include <unistd.h>
ssize_t readlinkat(size_t bufsiz;
                 int dirfd, const char *restrict path,
                 char buf[restrict bufsiz], size_t bufsiz);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

readlink():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

readlinkat():

    Depuis glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10:
        _ATFILE_SOURCE

DESCRIPTION

readlink() place le contenu du lien symbolique path dans le tampon buf, dont la taille est bufsiz. readlink() n'ajoute pas de caractère nul de fin à buf. Il tronquera (silencieusement) le contenu (à une longueur de bufsiz caractères), si le tampon est trop petit pour contenir tout le contenu.

readlinkat()

L'appel système readlinkat() fonctionne exactement de la même manière que readlink(), sauf pour les différences décrites ici.

Si path est relatif, il est interprété par rapport au répertoire référencé par le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme le fait readlink() pour un nom de chemin relatif).

Si path est relatif et dirfd a la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail actuel du processus appelant (comme readlink()).

Si path est absolu, alors dirfd est ignoré.

Depuis Linux 2.6.39, path peut être une chaîne vide, dans ce cas l'appel opère sur le lien symbolique référencé par dirfd (qui devrait avoir été obtenu en utilisant open(2) avec les flags O_PATH et O_NOFOLLOW).

Voir openat(2) pour une explication de la nécessité de readlinkat().

VALEUR DE RETOUR

En cas de succès, ces appels retournent le nombre d'octets placés dans buf. (Si la valeur retournée est égale à bufsiz, alors un troncature a pu se produire.) En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
La permission de recherche est refusée pour un composant du préfixe du nom de chemin. (Voir aussi path_resolution(7).)
EBADF
(readlinkat()) path est relatif mais dirfd n'est ni AT_FDCWD ni un descripteur de fichier valide.
EFAULT
buf s'étend en dehors de l'espace d'adressage alloué au processus.
EINVAL
bufsiz n'est pas positif.
EINVAL
Le fichier nommé (c'est-à-dire le dernier composant du nom de fichier de path) n'est pas un lien symbolique.
EIO
Une erreur d'E/S s'est produite lors de la lecture du système de fichiers.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la traduction du nom de chemin.
ENAMETOOLONG
Un nom de chemin, ou un composant d'un nom de chemin, était trop long.
ENOENT
Le fichier nommé n'existe pas.
ENOMEM
Pas assez de mémoire noyau était disponible.
ENOTDIR
Un composant du préfixe du nom de chemin n'est pas un répertoire.
ENOTDIR
(readlinkat()) path est relatif et dirfd est un descripteur de fichier faisant référence à un fichier autre qu'un répertoire.

NORMES

POSIX.1-2024.

HISTORIQUE

readlink()
4.4BSD (apparut pour la première fois dans 4.2BSD), POSIX.1-2001, POSIX.1-2008.
readlinkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

Jusqu'à et y compris glibc 2.4, le type de retour de readlink() était déclaré comme int. Désormais, le type de retour est déclaré comme ssize_t, comme (nouvellement) requis dans POSIX.1-2001.

glibc

Sur les anciens noyaux où readlinkat() n'est pas disponible, la fonction d'encapsulation glibc se rabat sur l'utilisation de readlink(). Lorsque path est relatif, glibc construit un nom de chemin basé sur le lien symbolique dans /proc/self/fd qui correspond à l'argument dirfd.

NOTES

L'utilisation d'un tampon de taille statique peut ne pas fournir une place suffisante pour le contenu du lien symbolique. La taille requise pour le tampon peut être obtenue à partir de la valeur stat.st_size renvoyée par un appel à lstat(2) sur le lien. Cependant, le nombre d'octets écrits par readlink() et readlinkat() doit être vérifié pour s'assurer que la taille du lien symbolique n'a pas augmenté entre les appels. L'allocation dynamique du tampon pour readlink() et readlinkat() résout également un problème de portabilité courant lors de l'utilisation de PATH_MAX pour la taille du tampon, car cette constante n'est pas garantie d'être définie par POSIX si le système n'a pas une telle limite.

EXEMPLES

Le programme suivant alloue dynamiquement le tampon nécessaire à readlink() à partir des informations fournies par lstat(2), en se rabattant sur un tampon de taille PATH_MAX dans les cas où lstat(2) renvoie une taille de zéro.

#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char         *buf;
    ssize_t      nbytes, bufsiz;
    struct stat  sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    /* Ajouter un à la taille du lien, afin que nous puissions déterminer si
       le tampon retourné par readlink() a été tronqué.  */
    bufsiz = sb.st_size + 1;
    /* Certains liens symboliques magiques sous (par exemple) /proc et /sys
       rapportent 'st_size' à zéro. Dans ce cas, prendre PATH_MAX comme
       une estimation "suffisamment bonne".  */
    if (sb.st_size == 0)
        bufsiz = PATH_MAX;
    buf = malloc(bufsiz);
    if (buf == NULL) {
        perror("malloc");
        exit(EXIT_FAILURE);
    }
    nbytes = readlink(argv[1], buf, bufsiz);
    if (nbytes == -1) {
        perror("readlink");
        exit(EXIT_FAILURE);
    }
    /* Afficher seulement 'nbytes' de 'buf', car il ne contient pas de terminating
       byte nul ('\0').  */
    printf("'%s' pointe vers '%.*s'\n", argv[1], (int) nbytes, buf);
    /* Si la valeur de retour était égale à la taille du tampon, alors
       la cible du lien était plus grande que prévu (peut-être parce que le
     */
    if (nbytes == bufsiz) {
        fprintf(stderr, "Warning: buffer was truncated\n");
    }
    exit(EXIT_SUCCESS);
}
