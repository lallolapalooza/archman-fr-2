DESCRIPTION

Note : Cette page est incomplète (diverses fonctions de résolveur fournies par glibc ne sont pas décrites) et probablement obsolète.

Les fonctions décrites ci-dessous interrogent les serveurs de noms de domaine Internet et interprètent leurs réponses.

L'API se compose d'un ensemble de fonctions plus modernes et réentrantes et d'un ensemble plus ancien de fonctions non réentrantes qui ont été remplacées. Les interfaces traditionnelles du résolveur telles que res_init() et res_query() utilisent un état statique (global) stocké dans la structure _res, rendant ces fonctions non thread-safe. BIND 8.2 a introduit un ensemble de nouvelles interfaces res_ninit(), res_nquery(), etc., qui prennent un res_state comme premier argument, vous pouvez donc utiliser un état de résolveur par thread.

Les fonctions res_ninit() et res_init() lisent les fichiers de configuration (voir resolv.conf(5)) pour obtenir le nom de domaine par défaut et le(s) adresse(s) du serveur de noms. Si aucun serveur n'est spécifié, le système local est essayé. Si aucun domaine n'est spécifié, celui associé au système local est utilisé. Il peut être outrepassé par la variable d'environnement LOCALDOMAIN. res_ninit() ou res_init() est normalement exécuté par le premier appel à l'une des autres fonctions. Chaque appel à res_ninit() nécessite un appel correspondant à res_nclose() pour libérer la mémoire allouée par res_ninit() et les appels ultérieurs à res_nquery().

Les fonctions res_nquery() et res_query() interrogent le serveur de noms pour le nom de domaine entièrement qualifié name du type et de la class spécifiés. La réponse est laissée dans le tampon answer de longueur anslen fourni par l'appelant.

Les fonctions res_nsearch() et res_search() effectuent une requête et attendent la réponse comme res_nquery() et res_query(), mais en plus elles implémentent les règles de défaut et de recherche contrôlées par RES_DEFNAMES et RES_DNSRCH (voir la description des options de _res ci-dessous).

Les fonctions res_nquerydomain() et res_querydomain() effectuent une requête en utilisant res_nquery()/res_query() sur la concaténation de name et domain.

Les fonctions suivantes sont des routines de bas niveau utilisées par res_nquery()/res_query().

Les fonctions res_nmkquery() et res_mkquery() construisent un message de requête dans buf de longueur buflen pour le nom de domaine dname. Le type de requête op est l'un des suivants (typiquement QUERY) :

QUERY
Requête standard.
IQUERY
Requête inverse. Cette option a été supprimée dans glibc 2.26, car elle n'est plus prise en charge par les serveurs DNS depuis très longtemps.
NS_NOTIFY_OP
Notifier le secondaire d'un changement de SOA (Start of Authority).

newrr n'est actuellement pas utilisé.

La fonction res_nsend() et res_send() envoie une requête préformatée donnée dans msg de longueur msglen et retourne la réponse dans answer qui a la longueur anslen. Elles appelleront res_ninit()/res_init() si elles n'ont pas déjà été appelées.

La fonction dn_comp() compresse le nom de domaine exp_dn et le stocke dans le tampon comp_dn de longueur length. La compression utilise un tableau de pointeurs dnptrs vers des noms précédemment compressés dans le message courant. Le premier pointeur pointe vers le début du message et la liste se termine par NULL. La limite du tableau est spécifiée par lastdnptr. Si dnptr est NULL, les noms de domaine ne sont pas compressés. Si lastdnptr est NULL, la liste des labels n'est pas mise à jour.

OPTIONS

Les routines du résolveur utilisent des informations de configuration et d'état contenues dans une structure __res_state (passée comme argument statep, ou dans la variable globale _res, dans le cas des fonctions non réentrantes plus anciennes). Le seul champ de cette structure qui est normalement manipulé par l'utilisateur est le champ options. Ce champ peut contenir le "OU" binaire des options suivantes :

RES_INIT
Vrai si res_ninit() ou res_init() a été appelé.
RES_DEBUG
Afficher les messages de débogage. Cette option n'est disponible que si glibc a été compilé avec le débogage activé, ce qui n'est pas le cas par défaut.
RES_AAONLY (non implémenté ; obsolète dans glibc 2.25)
Accepter uniquement les réponses faisant autorité. res_send() continue jusqu'à ce qu'il trouve une réponse faisant autorité ou qu'il retourne une erreur. Cette option était présente mais non implémentée jusqu'à glibc 2.24 ; depuis glibc 2.25, elle est obsolète et son utilisation produit un avertissement.
RES_USEVC
Utiliser des connexions TCP pour les requêtes plutôt que des datagrammes UDP.
RES_PRIMARY (non implémenté ; obsolète dans glibc 2.25)
Interroger uniquement le serveur de noms de domaine principal. Cette option était présente mais non implémentée jusqu'à glibc 2.24 ; depuis glibc 2.25, elle est obsolète et son utilisation produit un avertissement.
RES_IGNTC
Ignorer les erreurs de troncature. Ne pas réessayer avec TCP.
RES_RECURSE
Définir le bit de récursion désirée dans les requêtes. La récursion est effectuée par le serveur de noms de domaine, pas par res_send(). [Activé par défaut].
RES_DEFNAMES
Si défini, res_search() ajoutera le nom de domaine par défaut aux noms composés d'un seul composant, c'est-à-dire ceux qui ne contiennent pas de point. [Activé par défaut].
RES_STAYOPEN
Utilisé avec RES_USEVC pour maintenir la connexion TCP ouverte entre les requêtes.
RES_DNSRCH
Si défini, res_search() recherchera les noms d'hôte dans le domaine courant et dans les domaines parents. Cette option est utilisée par gethostbyname(3). [Activé par défaut].
RES_INSECURE1
Accepter une réponse provenant d'un serveur incorrect. Ceci peut être utilisé pour détecter des dangers potentiels pour la sécurité, mais vous devez compiler glibc avec le débogage activé et utiliser l'option RES_DEBUG (à des fins de débogage uniquement).
RES_INSECURE2
Accepter une réponse contenant une requête incorrecte. Ceci peut être utilisé pour détecter des dangers potentiels pour la sécurité, mais vous devez compiler glibc avec le débogage activé et utiliser l'option RES_DEBUG (à des fins de débogage uniquement).
RES_NOALIASES
Désactiver l'utilisation de la variable d'environnement HOSTALIASES.
RES_USE_INET6
Essayer une requête AAAA avant une requête A dans la fonction gethostbyname(3), et mapper les réponses IPv4 sous forme "tunnelisée" IPv6 si aucun enregistrement AAAA n'est trouvé mais qu'un ensemble d'enregistrements A existe. Depuis glibc 2.25, cette option est obsolète et son utilisation produit un avertissement ; les applications devraient utiliser getaddrinfo(3), plutôt que gethostbyname(3).
RES_ROTATE
Permet une sélection en mode round-robin des serveurs de noms parmi ceux listés. Cela a pour effet de répartir la charge des requêtes entre tous les serveurs listés, plutôt que d'avoir tous les clients qui essaient le premier serveur listé à chaque fois.
RES_NOCHECKNAME (non implémenté ; obsolète dans glibc 2.25)
Désactiver la vérification moderne de BIND des noms d'hôte et des noms de courrier entrants pour les caractères invalides tels que le trait de soulignement (_), les caractères non ASCII ou les caractères de contrôle. Cette option était présente jusqu'à glibc 2.24 ; depuis glibc 2.25, elle est obsolète et son utilisation produit un avertissement.
RES_KEEPTSIG (non implémenté ; obsolète dans glibc 2.25)
Ne pas supprimer les enregistrements TSIG. Cette option était présente mais non implémentée jusqu'à glibc 2.24 ; depuis glibc 2.25, elle est obsolète et son utilisation produit un avertissement.
RES_BLAST (non implémenté ; obsolète dans glibc 2.25)
Envoyer chaque requête simultanément et récursivement à tous les serveurs. Cette option était présente mais non implémentée jusqu'à glibc 2.24 ; depuis glibc 2.25, elle est obsolète et son utilisation produit un avertissement.
RES_USEBSTRING (glibc 2.3.4 à glibc 2.24)
Effectuer les recherches IPv6 inverses en utilisant le format de libellé binaire décrit dans la RFC 2673 ; si cette option n'est pas définie (ce qui est le cas par défaut), le format nibble est utilisé. Cette option a été supprimée dans glibc 2.25, car elle reposait sur une extension DNS incompatible avec les versions précédentes qui n'a jamais été déployée sur Internet.
RES_NOIP6DOTINT (glibc 2.24 et versions antérieures)
Utiliser la zone ip6.arpa dans la recherche inverse IPv6 au lieu de ip6.int, qui est obsolète depuis glibc 2.3.4. Cette option est présente jusqu'à glibc 2.24 inclus, où elle est activée par défaut. Dans glibc 2.25, cette option a été supprimée.
RES_USE_EDNS0 (depuis glibc 2.6)
Active la prise en charge des extensions DNS (EDNS0) décrites dans la RFC 2671.
RES_SNGLKUP (depuis glibc 2.10)
Par défaut, glibc effectue des recherches IPv4 et IPv6 en parallèle depuis glibc 2.9. Certains serveurs DNS d'appareils ne peuvent pas gérer correctement ces requêtes et provoquent l'expiration des demandes. Cette option désactive ce comportement et fait en sorte que glibc effectue les requêtes IPv6 et IPv4 séquentiellement (au détriment d'un certain ralentissement du processus de résolution).
RES_SNGLKUPREOP
Lorsque l'option RES_SNGLKUP est activée, ouvre un nouveau socket pour chaque requête.
RES_USE_DNSSEC
Utiliser DNSSEC avec le bit OK dans l'enregistrement OPT. Cette option implique RES_USE_EDNS0.
RES_NOTLDQUERY
Ne pas rechercher le nom non qualifié comme domaine de premier niveau (TLD).
RES_DEFAULT
Option par défaut qui implique : RES_RECURSE, RES_DEFNAMES, RES_DNSRCH et RES_NOIP6DOTINT.

VALEUR DE RETOUR

Les fonctions res_ninit() et res_init() retournent 0 en cas de succès, ou -1 si une erreur se produit.

Les fonctions res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), res_querydomain(), res_nmkquery(), res_mkquery(), res_nsend(), et res_send() retournent la longueur de la réponse, ou -1 si une erreur se produit.

Les fonctions dn_comp() et dn_expand() retournent la longueur du nom compressé, ou -1 si une erreur se produit.

En cas de retour d'erreur de res_nquery(), res_query(), res_nsearch(), res_search(), res_nquerydomain(), ou res_querydomain(), la variable globale h_errno (voir gethostbyname(3)) peut être consultée pour déterminer l'erreur.
