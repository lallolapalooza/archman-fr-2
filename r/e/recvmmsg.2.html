recvmmsg(2) Manuel des appels système recvmmsg(2)

NOM

recvmmsg - recevoir plusieurs messages sur une socket

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <sys/socket.h>
int recvmmsg(unsigned int n;
             int sockfd, struct mmsghdr msgvec[n], unsigned int n,
             int flags, struct timespec *timeout);

DESCRIPTION

L'appel système recvmmsg() est une extension de recvmsg(2) qui permet à l'appelant de recevoir plusieurs messages d'une socket en un seul appel système. (Cela offre des avantages en termes de performance pour certaines applications.) Une extension supplémentaire par rapport à recvmsg(2) est le support d'un délai d'attente pour l'opération de réception.

L'argument sockfd est le descripteur de fichier de la socket à partir de laquelle recevoir des données.

L'argument msgvec est un pointeur vers un tableau de structures mmsghdr. La taille de ce tableau est spécifiée par n.

La structure mmsghdr est définie dans <sys/socket.h> comme suit :


struct mmsghdr {
    struct msghdr msg_hdr;  /* En-tête du message */
    unsigned int  msg_len;  /* Nombre d'octets reçus pour l'en-tête */
};

Le champ msg_hdr est une structure msghdr, comme décrit dans recvmsg(2). Le champ msg_len est le nombre d'octets retournés pour le message dans l'entrée. Ce champ a la même valeur que la valeur de retour d'un appel unique à recvmsg(2) sur l'en-tête.

L'argument flags contient des drapeaux combinés par OU. Les drapeaux sont les mêmes que ceux documentés pour recvmsg(2), avec l'ajout suivant :

MSG_WAITFORONE (depuis Linux 2.6.34)
Active MSG_DONTWAIT après la réception du premier message.

L'argument timeout pointe vers une struct timespec (voir clock_gettime(2)) définissant un délai d'attente (secondes plus nanosecondes) pour l'opération de réception (mais voir BUGS !). (Cet intervalle sera arrondi à la granularité de l'horloge système, et les retards de planification du noyau signifient que l'intervalle de blocage peut déborder d'un petit montant.) Si timeout est NULL, l'opération bloque indéfiniment.

Un appel bloquant à recvmmsg() bloque jusqu'à ce que n messages aient été reçus ou jusqu'à ce que le délai d'attente expire. Un appel non bloquant lit autant de messages que disponibles (jusqu'à la limite spécifiée par n) et retourne immédiatement.

Au retour de recvmmsg(), les éléments successifs de msgvec sont mis à jour pour contenir des informations sur chaque message reçu : msg_len contient la taille du message reçu ; les sous-champs de msg_hdr sont mis à jour comme décrit dans recvmsg(2). La valeur de retour de l'appel indique le nombre d'éléments de msgvec qui ont été mis à jour.

VALEUR DE RETOUR

En cas de succès, recvmmsg() retourne le nombre de messages reçus dans msgvec ; en cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

Les erreurs sont celles de recvmsg(2). De plus, l'erreur suivante peut survenir :

EINVAL
timeout est invalide.

Voir aussi BUGS.

NORMES

Linux.

HISTORIQUE

Linux 2.6.33, glibc 2.12.

BUGS

L'argument timeout ne fonctionne pas comme prévu. Le délai d'attente est vérifié uniquement après la réception de chaque datagramme, de sorte que si jusqu'à n-1 datagrammes sont reçus avant que le délai d'attente n'expire, mais qu'aucun autre datagramme n'est reçu, l'appel bloquera indéfiniment.

Si une erreur survient après qu'au moins un message a été reçu, l'appel réussit et retourne le nombre de messages reçus. Le code d'erreur est censé être retourné lors d'un appel ultérieur à recvmmsg(). Dans l'implémentation actuelle, cependant, le code d'erreur peut être écrasé entre-temps par un événement réseau non lié sur une socket, par exemple un paquet ICMP entrant.

EXEMPLES

Le programme suivant utilise recvmmsg() pour recevoir plusieurs messages sur une socket et les stocke dans plusieurs tampons. L'appel retourne si tous les tampons sont remplis ou si le délai d'attente spécifié a expiré.

L'extrait suivant génère périodiquement des datagrammes UDP contenant un nombre aléatoire :


$ while true; do echo $RANDOM > /dev/udp/127.0.0.1/1234;
      sleep 0.25; done

Ces datagrammes sont lus par l'application exemple, ce qui peut donner la sortie suivante :


$ ./a.out
5 messages received
1 11782
2 11345
3 304
4 13514
5 28421

Source du programme

#define _GNU_SOURCE
#include <arpa/inet.h>
#include <netinet/in.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <time.h>
int
main(void)
{
#define VLEN 10
#define BUFSIZE 200
#define TIMEOUT 1
    int                 sockfd, retval;
    char                bufs[VLEN][BUFSIZE+1];
    struct iovec        iovecs[VLEN];
    struct mmsghdr      msgs[VLEN];
    struct timespec     timeout;
    struct sockaddr_in  addr;
    sockfd = socket(AF_INET, SOCK_DGRAM, 0);
    if (sockfd == -1) {
        perror("socket()");
        exit(EXIT_FAILURE);
    }
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
    addr.sin_port = htons(1234);
    if (bind(sockfd, (struct sockaddr *) &addr, sizeof(addr)) == -1) {
        perror("bind()");
        exit(EXIT_FAILURE);
    }
    memset(msgs, 0, sizeof(msgs));
    for (size_t i = 0; i < VLEN; i++) {
        iovecs[i].iov_base         = bufs[i];
        iovecs[i].iov_len          = BUFSIZE;
        msgs[i].msg_hdr.msg_iov    = &iovecs[i];
        msgs[i].msg_hdr.msg_iovlen = 1;
    }
    timeout.tv_sec = TIMEOUT;
    timeout.tv_nsec = 0;
    retval = recvmmsg(sockfd, msgs, VLEN, 0, &timeout);
    if (retval == -1) {
        perror("recvmmsg()");
        exit(EXIT_FAILURE);
    }
    printf("%d messages received\n",retval);
    for (size_t i = 0; i < retval; i++) {
        bufs[i][msgs[i].msg_len] = 0;
        printf("%zu %s", i+1, bufs[i]);
    }
    exit(EXIT_SUCCESS);
}
