RESOLVECTL(1) resolvectl RESOLVECTL(1)

NOM

resolvectl, resolvconf - Résoudre des noms de domaine, des adresses IPV4 et IPv6, des enregistrements de ressources DNS et des services ; inspecter et reconfigurer le résolveur DNS

SYNTAXE

resolvectl [OPTIONS...] {COMMANDE} [NOM...]

DESCRIPTION

resolvectl peut être utilisé pour résoudre des noms de domaine, des adresses IPv4 et IPv6, des enregistrements de ressources DNS et des services avec le service de résolution systemd-resolved.service(8). Par défaut, la liste spécifiée de paramètres sera résolue en tant que noms d'hôte, récupérant leurs adresses IPv4 et IPv6. Si les paramètres spécifiés sont formatés comme des adresses IPv4 ou IPv6, l'opération inverse est effectuée et un nom d'hôte est récupéré pour les adresses spécifiées.

La sortie du programme contient des informations sur le protocole utilisé pour la recherche et sur quelle interface réseau les données ont été découvertes. Elle contient également des informations sur la possibilité d'authentifier les informations. Toutes les données pour lesquelles la validation locale DNSSEC réussit sont considérées comme authentifiées. De plus, toutes les données provenant de sources locales fiables sont également signalées comme authentifiées, y compris la résolution du nom d'hôte local, le nom d'hôte « localhost » ou toutes les données de /etc/hosts.

COMMANDES

query NOM_HOTE|ADRESSE...

Résout les noms de domaine, ainsi que les adresses IPv4 et IPv6. Lorsqu'il est utilisé conjointement avec --type= ou --class= (voir ci-dessous), résout les enregistrements de ressources DNS de bas niveau.

Si un nom de domaine à étiquette unique est spécifié, il est recherché conformément aux domaines de recherche configurés — sauf si --search=no ou --type=/--class= sont spécifiés, qui désactivent tous deux cette logique.

Si un nom de domaine international est spécifié, il est automatiquement traduit conformément aux règles IDNA lors de la résolution via DNS classique — mais pas pour les recherches via MulticastDNS ou LLMNR. Si --type=/--class= est utilisé, la traduction IDNA est désactivée et les noms de domaine sont traités tels quels.

Si combiné avec --json= (uniquement pris en charge en combinaison avec --type=) affichera les données de l'enregistrement de ressource dans un objet JSON.

Ajouté dans la version 239.

service [[NOM] TYPE] DOMAINE

Résout les services RFC 6763 DNS-SD[1] et RFC 2782 SRV[2], en fonction de la liste de paramètres spécifiée. Si trois paramètres sont passés, le premier est supposé être le nom de service DNS-SD, le second le type de service SRV, et le troisième le domaine dans lequel rechercher. Dans ce cas, une recherche complète de type DNS-SD des enregistrements SRV et TXT est effectuée. Si seulement deux paramètres sont spécifiés, le premier est supposé être le type de service SRV et le second le domaine dans lequel rechercher. Dans ce cas, aucun enregistrement de ressource TXT n'est demandé. Enfin, si un seul paramètre est spécifié, il est supposé être un nom de domaine, qui est déjà préfixé par un type SRV, et une recherche SRV est effectuée (pas de TXT).

Ajouté dans la version 239.

openpgp EMAIL@DOMAINE...

Interroge les clés PGP stockées sous forme d'enregistrements de ressources OPENPGPKEY, voir RFC 7929[3]. Les adresses e-mail spécifiées sont converties en nom de domaine DNS correspondant, et toutes les clés OPENPGPKEY sont affichées.

Ajouté dans la version 239.

tlsa [FAMILLE] DOMAINE[:PORT]...

Interroge les clés publiques TLS stockées sous forme d'enregistrements de ressources TLSA, voir RFC 6698[4]. Une requête sera effectuée pour chacun des noms spécifiés, préfixés par le port et la famille ("_port._famille.domaine"). Le numéro de port peut être spécifié après un deux-points (":"), sinon 443 sera utilisé par défaut. La famille peut être spécifiée comme premier argument, sinon tcp sera utilisé.

Ajouté dans la version 239.

status [LIEN...]

Affiche les paramètres DNS globaux et par lien actuellement en vigueur. Si aucune commande n'est spécifiée, c'est la commande par défaut implicite.

Ajouté dans la version 239.

statistics

Affiche des statistiques générales du résolveur, y compris des informations sur l'activation et la disponibilité de DNSSEC, ainsi que des statistiques de résolution et de validation.

Ajouté dans la version 239.

reset-statistics

Réinitialise les compteurs de statistiques affichés dans statistics à zéro. Cette opération nécessite des privilèges root.

Ajouté dans la version 239.

flush-caches

Vide tous les caches d'enregistrements de ressources DNS que le service maintient localement. Ceci est essentiellement équivalent à envoyer le signal SIGUSR2 au service systemd-resolved.

Ajouté dans la version 239.

reset-server-features

Vide toutes les informations de niveau de fonctionnalité que le résolveur a apprises sur des serveurs spécifiques, et garantit que la logique de sonder les fonctionnalités des serveurs est redémarrée depuis le début avec la prochaine requête de résolution. Ceci est essentiellement équivalent à envoyer le signal SIGRTMIN+1 au service systemd-resolved.

Ajouté dans la version 239.

dns [LIEN [SERVEUR...]], domain [LIEN [DOMAINE...]], default-route [LIEN [BOOL...]], llmnr [LIEN [MODE]], mdns [LIEN [MODE]], dnssec [LIEN [MODE]], dnsovertls [LIEN [MODE]], nta [LIEN [DOMAINE...]]

Obtenir/définir la configuration DNS par interface. Ces commandes peuvent être utilisées pour configurer divers paramètres DNS pour les interfaces réseau. Ces commandes peuvent être utilisées pour informer systemd-resolved ou systemd-networkd de la configuration DNS par interface déterminée par des moyens externes. La commande dns attend des spécifications d'adresses IPv4 ou IPv6 de serveurs DNS à utiliser. Chaque adresse peut éventuellement prendre un numéro de port séparé par ":", un nom ou un index d'interface réseau séparé par "%", et un Server Name Indication (SNI) séparé par "#". Lorsque l'adresse IPv6 est spécifiée avec un numéro de port, l'adresse doit être entre crochets. C'est-à-dire, les formats complets acceptables sont "111.222.333.444:9953%ifname#example.com" pour IPv4 et "[1111:2222::3333]:9953%ifname#example.com" pour IPv6. La commande domain attend des domaines DNS valides, éventuellement préfixés par "~", et configure un domaine de recherche ou de routage par interface. La commande default-route attend un paramètre booléen et configure si le lien peut être utilisé comme route par défaut pour les recherches DNS, c'est-à-dire s'il convient aux recherches sur des domaines pour lesquels aucun autre lien n'est explicitement configuré. Les commandes llmnr, mdns, dnssec et dnsovertls peuvent être utilisées pour configurer les paramètres LLMNR, MulticastDNS, DNSSEC et DNSOverTLS par interface. Enfin, la commande nta peut être utilisée pour configurer des domaines NTA DNSSEC supplémentaires par interface.

Les commandes dns, domain et nta peuvent prendre une seule chaîne vide comme argument pour effacer leurs listes de valeurs respectives.

Pour plus de détails sur ces paramètres, leurs valeurs possibles et leur effet, voir les paramètres correspondants dans systemd.network(5).

Ajouté dans la version 239.

revert LIEN

Annule la configuration DNS par interface. Si la configuration DNS est annulée, tous les paramètres DNS par interface sont réinitialisés à leurs valeurs par défaut, annulant tous les effets de dns, domain, default-route, llmnr, mdns, dnssec, dnsovertls, nta. Notez que lorsqu'une interface réseau disparaît, toute la configuration est perdue automatiquement, une annulation explicite n'est pas nécessaire dans ce cas.

Ajouté dans la version 239.

monitor

Affiche un flux continu des requêtes de résolution des clients locaux et leurs réponses. Chaque fois qu'une requête locale est terminée, la clé de recherche d'enregistrement DNS et les enregistrements de ressources sont affichés. Notez que cela affiche uniquement les requêtes émises localement et n'est pas immédiatement lié aux requêtes DNS soumises aux serveurs DNS configurés ou aux zones LLMNR ou MulticastDNS, car les recherches peuvent être répondues à partir du cache local, ou peuvent entraîner plusieurs transactions DNS (par exemple pour valider les informations DNSSEC). Si des chaînes de redirection CNAME/CNAME sont suivies, une requête distincte sera affichée pour chaque élément de la chaîne. Utilisez --json= pour activer la sortie JSON.

Ajouté dans la version 252.

    OPTIONS

    -4, -6

    Par défaut, lors de la résolution d'un nom d'hôte, les adresses IPv4 et IPv6 sont acquises. En spécifiant -4, seules les adresses IPv4 sont demandées, en spécifiant -6, seules les adresses IPv6 sont demandées.

    Ajouté dans la version 239.

    -i INTERFACE, --interface=INTERFACE

    Spécifie l'interface réseau sur laquelle exécuter la requête. Ceci peut être spécifié comme un index d'interface numérique ou comme une chaîne de nom d'interface réseau (par exemple, "en0"). Notez que cette option n'a aucun effet si la configuration DNS au niveau du système (telle que configurée dans /etc/resolv.conf ou /etc/systemd/resolved.conf) remplace la configuration par lien.

    Ajouté dans la version 239.

    -p PROTOCOLE, --protocol=PROTOCOLE

    Spécifie le protocole réseau pour la requête. Peut être l'un des suivants : "dns" (c'est-à-dire DNS unicast classique), "llmnr" (Link-Local Multicast Name Resolution[5]), "llmnr-ipv4", "llmnr-ipv6" (LLMNR via les protocoles IP sous-jacents indiqués), "mdns" (Multicast DNS[6]), "mdns-ipv4", "mdns-ipv6" (MDNS via les protocoles IP sous-jacents indiqués). Par défaut, la recherche est effectuée via tous les protocoles adaptés à la recherche. Si utilisé, limite l'ensemble des protocoles qui peuvent être utilisés. Utiliser cette option plusieurs fois pour activer la résolution via plusieurs protocoles en même temps. Le réglage "llmnr" est identique à la spécification de ce commutateur une fois avec "llmnr-ipv4" et une fois via "llmnr-ipv6". Notez que cette option ne force pas le service à résoudre l'opération avec le protocole spécifié, car cela pourrait nécessiter une interface réseau et une configuration appropriées. La valeur spéciale "help" peut être utilisée pour lister les valeurs connues.

    Ajouté dans la version 239.

    -t TYPE, --type=TYPE, -c CLASSE, --class=CLASSE

    Lorsqu'il est utilisé en conjonction avec la commande query, spécifie le type d'enregistrement de ressource DNS (par exemple, A, AAAA, MX, ...) et la classe (par exemple, IN, ANY, ...) à rechercher. Si ces options sont utilisées, un ensemble d'enregistrements de ressources DNS correspondant à la classe et au type spécifiés est demandé. La classe par défaut est IN si seul un type est spécifié. La valeur spéciale "help" peut être utilisée pour lister les valeurs connues.

    Sans ces options, resolvectl query fournit une résolution de nom de domaine vers adresse et d'adresse vers nom de domaine de haut niveau. Avec ces options, elle fournit une résolution d'enregistrement de ressource DNS de bas niveau. La logique des domaines de recherche est automatiquement désactivée lorsque ces options sont utilisées, c'est-à-dire que les noms de domaine spécifiés doivent être des noms de domaine entièrement qualifiés. De plus, la traduction interne des noms de domaine IDNA est également désactivée, c'est-à-dire que les noms de domaine internationaux doivent être spécifiés en notation "xn--...", sauf si une recherche dans MulticastDNS/LLMNR est souhaitée, auquel cas les caractères UTF-8 doivent être utilisés.

    Ajouté dans la version 239.

    --service-address=BOOL

    Prend un paramètre booléen. Si vrai (par défaut), lors d'une recherche de service avec --service, les noms d'hôtes contenus dans les enregistrements de ressource SRV sont également résolus.

    Ajouté dans la version 239.

    --service-txt=BOOL

    Prend un paramètre booléen. Si vrai (par défaut), lors d'une recherche de service DNS-SD avec --service, l'enregistrement de métadonnées de service TXT est également résolu.

    Ajouté dans la version 239.

    --cname=BOOL

    Prend un paramètre booléen. Si vrai (par défaut), les redirections CNAME ou DNAME DNS sont suivies. Sinon, si un enregistrement CNAME ou DNAME est rencontré pendant la résolution, une erreur est retournée.

    Ajouté dans la version 239.

    --validate=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), la validation DNSSEC est appliquée comme d'habitude — à condition qu'elle soit activée pour le réseau et pour systemd-resolved.service dans son ensemble. Si faux, la validation DNSSEC est désactivée pour la requête spécifique, indépendamment de savoir si elle est activée pour le réseau ou dans le service. Notez que le réglage de cette option sur vrai ne force pas la validation DNSSEC sur les systèmes/réseaux où DNSSEC est désactivé. Cette option est uniquement adaptée pour désactiver la validation là où elle est autrement activée, pas pour activer la validation là où elle est autrement désactivée.

    Ajouté dans la version 248.

    --synthesize=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), certains domaines sélectionnés sont résolus sur le système local, parmi eux "localhost", "_gateway", "_outbound", "_localdnsstub" et "_localdnsproxy" ou les entrées de /etc/hosts. Si faux, ces domaines ne sont pas résolus localement, et échouent (dans le cas de "localhost", "_gateway" ou "_outbound" et similaires) ou vont sur le réseau via des recherches DNS/mDNS/LLMNR régulières (dans le cas des entrées /etc/hosts).

    Ajouté dans la version 248.

    --cache=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), les recherches utilisent le cache local des enregistrements de ressources DNS. Si faux, les recherches sont acheminées vers le réseau au lieu de cela, indépendamment du fait qu'elles soient déjà disponibles dans le cache local.

    Ajouté dans la version 248.

    --zone=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), les recherches sont répondues à partir des enregistrements de ressources LLMNR ou mDNS enregistrés localement, s'ils sont définis. Si faux, les enregistrements LLMNR/mDNS enregistrés localement ne sont pas pris en compte pour la requête de recherche.

    Ajouté dans la version 248.

    --trust-anchor=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), les recherches pour DS et DNSKEY sont répondues à partir des points d'ancrage de confiance DNSSEC locaux si possible. Si faux, le magasin de confiance local n'est pas pris en compte pour la requête de recherche.

    Ajouté dans la version 248.

    --network=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), les recherches sont répondues via des requêtes réseau DNS, LLMNR ou mDNS si elles ne peuvent pas être synthétisées localement, ou être répondues à partir du cache local, de la zone ou des points d'ancrage de confiance (voir ci-dessus). Si faux, la requête n'est pas répondue par le réseau et échouera donc si aucune des sources indiquées ne peut y répondre.

    Ajouté dans la version 248.

    --search=BOOL

    Prend un paramètre booléen. Si vrai (par défaut), tous les noms d'hôtes à étiquette unique spécifiés seront recherchés dans les domaines configurés dans la liste des domaines de recherche, si elle n'est pas vide. Sinon, la logique des domaines de recherche est désactivée. Notez que cette option n'a aucun effet si --type= est utilisé (voir ci-dessus), auquel cas la logique des domaines de recherche est sans condition désactivée.

    Ajouté dans la version 239.

    --raw[=payload|packet]

    Affiche les enregistrements de réponse sous forme de données binaires. S'il n'y a pas d'argument ou si l'argument est "payload", la charge utile des données de l'enregistrement de ressource est exportée, c'est-à-dire non pas le "RDATA" entier, mais seulement le contenu principal. Si l'argument est "packet", l'enregistrement de ressource entier est affiché en format filaire, préfixé par la longueur spécifiée comme un entier 64 bits little-endian. Ce format permet d'afficher plusieurs enregistrements et de les analyser sans ambiguïté.

    Notez que "payload" n'est pris en charge que pour un petit sous-ensemble des types d'enregistrements de ressources : SSHFP, TLSA, OPENPGPKEY où cela affiche uniquement le matériel de clé ; et A, AAAA où cela affiche les données d'adresse.

    Ajouté dans la version 239.

    --legend=BOOL

    Prend un paramètre booléen. Si vrai (par défaut), les en-têtes de colonne et les méta-informations sur la réponse à la requête sont affichés. Sinon, cette sortie est supprimée.

    Ajouté dans la version 239.

    --stale-data=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai (par défaut), les recherches sont répondues avec des données obsolètes (enregistrements de ressources expirés) si possible. Si faux, les données obsolètes ne sont pas prises en compte pour la requête de recherche.

    Ajouté dans la version 254.

    --relax-single-label=BOOL

    Prend un paramètre booléen ; utilisé en conjonction avec query. Si vrai, les règles concernant le routage des noms à étiquette unique sont assouplies. Par défaut, faux. Par défaut, les recherches de noms à étiquette unique sont supposées faire référence à des hôtes locaux à résoudre via une résolution locale telle que LLMNR ou via la qualification de domaine de recherche et ne sont pas acheminées vers les serveurs en amont. Si cette option est activée, ces règles sont désactivées et les requêtes sont quand même acheminées en amont. Voir également l'option ResolveUnicastSingleLabel= dans resolved.conf(5) qui fournit une option au niveau du système qui contrôle ce comportement.

    Ajouté dans la version 256.

    --no-ask-password

    Ne pas interroger l'utilisateur pour l'authentification pour les opérations privilégiées.

    --json=MODE

    Affiche la sortie formatée en JSON. Attend l'une des valeurs suivantes : "short" (pour la sortie la plus courte possible sans espaces blancs ou sauts de ligne redondants), "pretty" (pour une version jolie du même, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

    -j

    Équivalent à --json=pretty si exécuté sur un terminal, et à --json=short sinon.

    --no-pager

    Ne pas rediriger la sortie vers un paginateur.

    -h, --help

    Affiche un court message d'aide et quitte.

    --version

    Affiche une courte chaîne de version et quitte.

    COMPATIBILITÉ AVEC RESOLVCONF(8)

    resolvectl est un binaire multi-appels. Lorsqu'il est invoqué sous le nom « resolvconf » (généralement obtenu au moyen d'un lien symbolique de ce nom vers le binaire resolvectl), il est exécuté dans un mode de compatibilité limité avec resolvconf(8). Il accepte principalement les mêmes arguments et transmet toutes les données à systemd-resolved.service(8), de manière similaire à la façon dont les commandes dns et domain fonctionnent. Notez que systemd-resolved.service est le seul backend pris en charge, ce qui diffère des autres implémentations de cette commande.

    Le fichier /etc/resolv.conf ne sera mis à jour avec les serveurs ajoutés via cette commande que si /etc/resolv.conf est un lien symbolique vers /run/systemd/resolve/resolv.conf, et non un fichier statique. Voir la discussion sur la gestion de /etc/resolv.conf dans systemd-resolved.service(8).

    Toutes les opérations prises en charge par d'autres implémentations ne le sont pas nativement. Spécifiquement :

    -a

    Enregistre les données de configuration DNS par interface auprès de systemd-resolved. Attend un nom d'interface réseau comme seul argument de ligne de commande. Lit les données de configuration DNS compatibles avec resolv.conf(5) depuis son entrée standard. Les champs pertinents sont « nameserver » et « domain »/« search ». Cette commande est en grande partie identique à l'invocation de resolvectl avec une combinaison des commandes dns et domain.

    Ajouté dans la version 239.

    -d

    Désenregistre les données de configuration DNS par interface auprès de systemd-resolved. Cette commande est en grande partie identique à l'invocation de resolvectl revert.

    Ajouté dans la version 239.

    -f

    Lorsque spécifié, -a et -d ne se plaindront pas des interfaces réseau manquantes et n'exécuteront silencieusement aucune opération dans ce cas.

    Ajouté dans la version 239.

    -x

    Ce commutateur pour une opération « exclusive » n'est que partiellement pris en charge. Il est mappé à un domaine de recherche configuré supplémentaire de « ~. » — c'est-à-dire qu'il garantit que le trafic DNS est de préférence acheminé vers les serveurs DNS sur cette interface, sauf s'il existe d'autres domaines plus spécifiques configurés sur d'autres interfaces.

    Ajouté dans la version 239.

    -p

    Lorsqu'il est spécifié, l'interface ne sera pas utilisée comme route par défaut. Voir aussi systemd-resolved.service(8) concernant la route par défaut.

    Ajouté dans la version 257.

    -m

    Le commutateur n'est pas pris en charge et est ignoré silencieusement.

    Ajouté dans la version 239.

    -u, -I, -i, -l, -R, -r, -v, -V, --enable-updates, --disable-updates, --are-updates-enabled

    Ces commutateurs ne sont pas pris en charge et la commande échouera si elle est utilisée.

    Ajouté dans la version 239.

    Voir resolvconf(8) pour les détails sur ces options de ligne de commande.

    EXEMPLES

    Exemple 1. Récupérer les adresses du domaine « www.0pointer.net » (enregistrements de ressources A et AAAA)

    $ resolvectl query www.0pointer.net
www.0pointer.net: 2a01:238:43ed:c300:10c3:bcf3:3266:da74
                  85.214.157.71
-- Information acquise via le protocole DNS en 611.6ms.
-- Données authentifiées : non

    Exemple 2. Récupérer le domaine de l'adresse IP « 85.214.157.71 » (enregistrement de ressource PTR)

    $ resolvectl query 85.214.157.71
85.214.157.71: gardel.0pointer.net
-- Information acquise via le protocole DNS en 1.2997s.
-- Données authentifiées : non

    Exemple 3. Récupérer l'enregistrement MX du domaine « yahoo.com »

    $ resolvectl --legend=no -t MX query yahoo.com
yahoo.com. IN MX    1 mta7.am0.yahoodns.net
yahoo.com. IN MX    1 mta6.am0.yahoodns.net
yahoo.com. IN MX    1 mta5.am0.yahoodns.net

    Exemple 4. Résoudre un service SRV

    $ resolvectl service _xmpp-server._tcp gmail.com
_xmpp-server._tcp/gmail.com: alt1.xmpp-server.l.google.com:5269 [priorité=20, poids=0]
                             173.194.210.125
                             alt4.xmpp-server.l.google.com:5269 [priorité=20, poids=0]
                             173.194.65.125
                             ...

    Exemple 5. Récupérer une clé PGP (enregistrement de ressource OPENPGP)

    $ resolvectl openpgp zbyszek@fedoraproject.org
d08ee310438ca124a6149ea5cc21b6313b390dce485576eff96f8722._openpgpkey.fedoraproject.org. IN OPENPGPKEY
        mQINBFBHPMsBEACeInGYJCb+7TurKfb6wGyTottCDtiSJB310i37/6ZYoeIay/5soJjlMyf
        MFQ9T2XNT/0LM6gTa0MpC1st9LnzYTMsT6tzRly1D1UbVI6xw0g0vE5y2Cjk3xUwAynCsSs
        ...

    Exemple 6. Récupérer une clé TLS (enregistrement de ressource TLSA)

    $ resolvectl tlsa tcp fedoraproject.org:443
_443._tcp.fedoraproject.org IN TLSA 0 0 1 19400be5b7a31fb733917700789d2f0a2471c0c9d506c0e504c06c16d7cb17c0
        -- Usage du certificat : Contrainte CA
        -- Sélecteur : Certificat complet
        -- Type de correspondance : SHA-256

    « tcp » et « :443 » sont facultatifs et peuvent être omis.
