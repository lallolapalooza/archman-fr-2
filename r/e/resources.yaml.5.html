NOM

resources.yaml - Fichier de configuration Slurm pour les Ressources Hiérarchiques (HRES).

DESCRIPTION

resources.yaml est un fichier de configuration au format YAML qui définit les Ressources Hiérarchiques (HRES). Le fichier doit être situé dans le même répertoire que slurm.conf. Tout texte suivant un "#" dans ce fichier est traité comme un commentaire jusqu'à la fin de la ligne.

Plus de détails sont disponibles sur la page Planification des Ressources Hiérarchiques (HRES) : https://slurm.schedmd.com/hres.html

PARAMÈTRES

Chaque définition de Ressources Hiérarchiques est un objet YAML contenant les attributs suivants :

ressource
Le nom unique de la ressource. Ce nom sera utilisé pour l'identifier par slurmctld. Ce doit être le premier attribut de l'objet.
mode
Le mode de planification pour la ressource. Doit être l'un des suivants :
MODE_1
Des ressources suffisantes sont requises sur une seule couche qui chevauche les nœuds alloués du travail.
MODE_2
Des ressources suffisantes doivent être disponibles sur toutes les couches qui chevauchent les nœuds alloués du travail.
MODE_3
Les ressources sont allouées par nœud. Le planificateur calcule la consommation totale à partir de la couche la plus granulaire et l'additionne aux couches successivement supérieures, garantissant que le compte n'est pas dépassé à quelque couche que ce soit. Ce mode est conçu pour les ressources consommables comme l'énergie et peut être mappé à une topologie de bloc à l'aide du paramètre topology.
topologie
(Optionnel) Spécifie le nom d'une définition topology/block à mapper à cette ressource. Ce paramètre n'est valide que pour les ressources de MODE_3. Les couches HRes doivent avoir la même disposition que la topologie de bloc spécifiée. Cela permet au planificateur d'optimiser simultanément les allocations HRes et de topologie de bloc.
variables
(Optionnel) Une liste de paires nom/valeur qui mappent des chaînes de caractères arbitraires à des comptes de ressources définis administrativement. Les utilisateurs peuvent alors utiliser ces chaînes dans les soumissions de travaux (par exemple, --resources=power:full_node) au lieu d'une valeur numérique. Chaque entrée de la liste contient :
nom
L'alias de chaîne pour la valeur (par exemple, "full_node").
valeur
Le compte de ressources numérique (par exemple, 1000).
couches
Une liste de couches qui définissent la hiérarchie des ressources. Chaque couche est un objet YAML contenant :
noeuds
Une liste de noms de nœuds ou d'expressions d'hôtes faisant partie de cette couche.
compte
Le nombre total de ressources disponibles dans cette couche spécifique.
base
(Optionnel) Une liste de paires nom/valeur décrivant la consommation de ressources (statique) non liée au travail dans cette couche. Ceci est particulièrement pertinent pour le MODE_3. Chaque entrée contient :
nom
Le nom du consommateur de ressources statique (par exemple, "stockage", "network1").
valeur
Le compte de ressources numérique utilisé par ce consommateur.

EXEMPLE

---
- resource: flat
  mode: MODE_2
  layers:
    - nodes:			# niveau le plus élevé
        - "node[01-32]"
      count: 24
    - nodes:			# niveaux intermédiaires
        - "node[01-16]"
      count: 16
    - nodes:
        - "node[17-32]"
      count: 16
    - nodes:			# niveaux les plus bas
        - "node[01-08]"
      count: 12
    - nodes:
        - "node[09-16]"
      count: 12
    - nodes:
        - "node[17-24]"
      count: 12
    - nodes:
        - "node[25-32]"
      count: 12
- resource: natural
  mode: MODE_1
  layers:
    - nodes:			# niveau le plus élevé
        - "node[01-32]"
      count: 50
    - nodes:			# niveaux les plus bas
        - "node[01-16]"
      count: 100
    - nodes:
        - "node[17-32]"
      count: 100
- resource: power
  mode: MODE_3
  topology: blok1
  variables:
    - name: full_node
      value: 1000
    - name: full_gpu_node
      value: 2000
  layers:
    - nodes:
        - "node[01-32]"
      count: 130000
      base:
        - name: acUnit1
          value: 10000
        - name: acUnit2
          value: 8000
    - nodes:
        - "node[01-16]"
      count: 60000
      base:
        - name: network1
          value: 3000
    - nodes:
        - "node[17-32]"
      count: 80000
      base:
        - name: network2
          value: 2000
    - nodes:
        - "node[01-08]"
      count: 40000
      base:
        - name: storage
          value: 5000
    - nodes:
        - "node[09-16]"
      count: 40000
    - nodes:
        - "node[17-24]"
      count: 40000
    - nodes:
        - "node[25-32]"
      count: 40000
