remap_file_pages(2) Manuel des appels système remap_file_pages(2)

NOM

remap_file_pages - créer un mappage de fichier non linéaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <sys/mman.h>
[[deprecated]] int remap_file_pages(size_t size;
                                    void addr[size], size_t size,
                                    int prot, size_t pgoff, int flags);

DESCRIPTION

Note : cet appel système a été marqué comme obsolète à partir de Linux 3.16. Dans Linux 4.0, l'implémentation a été remplacée par une émulation plus lente au sein du noyau. Les quelques applications qui utilisent cet appel système devraient envisager de migrer vers des alternatives. Ce changement a été apporté car le code du noyau pour cet appel système était complexe, et il est considéré comme peu utilisé, voire complètement inutilisé. Bien qu'il ait eu quelques cas d'utilisation dans des applications de bases de données sur les systèmes 32 bits, ces cas d'utilisation n'existent pas sur les systèmes 64 bits.

L'appel système remap_file_pages() est utilisé pour créer un mappage non linéaire, c'est-à-dire un mappage dans lequel les pages du fichier sont mappées dans un ordre non séquentiel en mémoire. L'avantage d'utiliser remap_file_pages() par rapport à des appels répétés à mmap(2) est que la première approche ne nécessite pas au noyau de créer des structures de données VMA (Virtual Memory Area) supplémentaires.

Pour créer un mappage non linéaire, nous effectuons les étapes suivantes :

1.
Utiliser mmap(2) pour créer un mappage (qui est initialement linéaire). Ce mappage doit être créé avec le drapeau MAP_SHARED.
2.
Utiliser un ou plusieurs appels à remap_file_pages() pour réorganiser la correspondance entre les pages du mappage et les pages du fichier. Il est possible de mapper la même page d'un fichier dans plusieurs emplacements de la région mappée.

Les arguments pgoff et size spécifient la région du fichier qui doit être réorganisée dans le mappage : pgoff est un décalage de fichier en unités de la taille de page système ; size est la longueur de la région en octets.

L'argument addr remplit deux objectifs. Premièrement, il identifie le mappage dont nous voulons réorganiser les pages. Ainsi, addr doit être une adresse qui tombe dans une région précédemment mappée par un appel à mmap(2). Deuxièmement, addr spécifie l'adresse à laquelle les pages du fichier identifiées par pgoff et size seront placées.

Les valeurs spécifiées dans addr et size doivent être des multiples de la taille de page système. Si elles ne le sont pas, le noyau arrondit les deux valeurs vers le bas au multiple le plus proche de la taille de page.

L'argument prot doit être spécifié comme 0.

L'argument flags a la même signification que pour mmap(2), mais tous les drapeaux autres que MAP_NONBLOCK sont ignorés.

VALEUR DE RETOUR

En cas de succès, remap_file_pages() retourne 0. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
addr ne fait pas référence à un mappage valide créé avec le drapeau MAP_SHARED.
EINVAL
addr, size, prot, ou pgoff est invalide.

NORMES

Linux.

HISTORIQUE

Linux 2.5.46, glibc 2.3.3.

NOTES

Depuis Linux 2.6.23, remap_file_pages() crée des mappages non linéaires uniquement sur les systèmes de fichiers en mémoire tels que tmpfs(5), hugetlbfs ou ramfs. Sur les systèmes de fichiers avec une sauvegarde, remap_file_pages() n'est pas beaucoup plus efficace que d'utiliser mmap(2) pour ajuster quelles parties du fichier sont mappées à quelles adresses.
