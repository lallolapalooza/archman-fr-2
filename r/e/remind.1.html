NOM

remind - un service de rappels sophistiqué

SYNTAXE

remind [options] fichier [date] [*rép] [heure]

DESCRIPTION

Remind lit le fichier fourni et exécute les commandes qu'il contient. Ces commandes sont utilisées pour émettre des rappels et des alarmes. Chaque rappel ou alarme peut consister en un message envoyé à la sortie standard, ou un programme à exécuter.

Si fichier est spécifié comme un simple trait d'union '-', alors Remind prend son entrée depuis l'entrée standard. Dans ce cas, si Remind a été compilé avec la bibliothèque GNU Readline, il utilisera Readline pour vous fournir une interface interactive d'édition de ligne.

Si fichier se trouve être un répertoire plutôt qu'un fichier ordinaire, alors Remind lit tous les fichiers (mais pas les sous-répertoires !) dans ce répertoire qui correspondent au motif "*.rem". Les fichiers sont lus par ordre trié ; l'ordre de tri peut dépendre de votre locale, mais devrait correspondre à l'ordre de tri utilisé par le shell pour développer "*.rem".

Remind lit ses fichiers en commençant par le début jusqu'à la fin, ou jusqu'à ce qu'il rencontre une ligne dont le seul contenu est "__EOF__" (sans les guillemets.) Tout ce qui suit le marqueur __EOF__ est complètement ignoré.

MODES DE FONCTIONNEMENT

Remind a quatre modes de fonctionnement principaux :

Mode Agenda
Le mode Agenda est le mode par défaut. Dans ce mode, Remind affiche les rappels du jour sur la sortie standard et se termine. Il peut créer un processus en arrière-plan pour afficher les rappels mis en file d'attente pour plus tard dans la journée.
Mode Calendrier
Dans ce mode, Remind génère un calendrier soit en le dessinant dans le terminal, soit en envoyant des données dans un format lisible par machine à un programme backend qui dessine réellement le calendrier.
Mode Démon
C'est un mode de fonctionnement spécial dans lequel Remind est appelé par un frontal et fonctionne comme un démon, acceptant les requêtes du frontal et renvoyant des messages au frontal. TkRemind utilise Remind en mode démon.
Mode Purge
Dans ce mode, Remind ne produit aucune sortie, mais crée de nouvelles versions de ses fichiers d'entrée avec tous les rappels expirés commentés.

OPTIONS

Remind possède une multitude d'options. Si vous débutez avec le programme, ignorez-les pour l'instant et passez à la section "FICHIERS DE RAPPELS".

-n
L'option -n fait que Remind affiche la prochaine occurrence de chaque rappel dans un format de calendrier simple. Vous pouvez trier cela par date en redirigeant la sortie via sort(1). Notez que l'option -n fait que toute option -g est ignorée et active également implicitement l'option -o.
-j[n]
Exécute Remind en mode "purge" pour supprimer les rappels expirés. Voir la section MODE PURGE pour plus de détails.
-r
L'option -r désactive les directives RUN et la fonction shell().
-c[indicateurs]n
L'option -c fait que Remind produit un calendrier qui est envoyé à la sortie standard. Si vous fournissez un nombre n, alors un calendrier sera généré pour n mois, en commençant par le mois courant. Par défaut, un calendrier pour le mois courant uniquement est produit. Cette option active implicitement l'option -o.

Vous pouvez précéder n (s'il existe) d'un ensemble d'indicateurs. Les indicateurs sont les suivants :

'+'
provoque la production d'un calendrier pour n semaines.
'a'
fait que Remind affiche les rappels sur le calendrier le jour où ils se produisent réellement ainsi que les jours précédents spécifiés par le delta du rappel. Cela fait également que Remind inclut du texte en dehors des séquences %"...%" qui seraient autrement supprimées (bien que les marqueurs %" eux-mêmes soient supprimés.)
'l'
fait que Remind utilise des caractères de dessin de ligne VT100 pour dessiner le calendrier. Les caractères sont codés en dur et ne fonctionneront que sur les terminaux qui émulent l'ensemble de caractères de dessin de ligne VT00.
'u'
est similaire à 'l', mais fait que Remind utilise des caractères de dessin de ligne UNICODE pour dessiner le calendrier. Les caractères sont codés en dur et ne fonctionneront que sur les terminaux configurés en encodage de caractères UTF-8. Cet indicateur active également l'utilisation de la marque UNICODE "gauche-à-droite" qui peut corriger les problèmes de formatage avec les langues de droite à gauche dans l'affichage du calendrier.
'c'
fait que Remind utilise des séquences d'échappement VT100 pour approximer les rappels SPECIAL COLOR. Notez que cet indicateur est conservé pour des raisons de compatibilité ascendante ; vous devriez utiliser l'option de ligne de commande -@[n][,m][,b] à la place.

Dans une locale UTF-8, Remind utilisera des "marques gauche-à-droite" lors de la création d'un calendrier avec l'option -c. Certains terminaux ne gèrent pas cela correctement et rendent le rendu du calendrier incorrect ; voir la documentation de $SuppressLRM dans la section "VARIABLES SYSTÈME" pour une solution.

-@[n][,m][,b]
Indique à Remind d'approximer les rappels SPECIAL COLOR et SHADE en utilisant des séquences d'échappement VT100. L'approximation est (par nécessité) très grossière, car le VT100 n'a que huit séquences de couleur différentes, chacune avec une luminosité (0 ou 1). Un composant de couleur supérieur à 64 est considéré comme "allumé", et si l'un des trois composants de couleur est supérieur à 128, la couleur est considérée comme "brillante".

Si vous fournissez les paramètres numériques optionnels, ils ont les significations suivantes : n=0 indique à Remind d'utiliser les 16 couleurs VT100 standard. n=1 indique d'utiliser une palette étendue de 256 couleurs supportée par de nombreux émulateurs de terminal comme xterm. Et n=2 indique d'utiliser des séquences d'échappement qui supportent les couleurs vraies 24 bits, également supportées par de nombreux émulateurs de terminal comme xterm.

Si le paramètre optionnel m est fourni après une virgule, alors m=0 indique à Remind que l'arrière-plan du terminal est sombre, et Remind éclaircira les couleurs sombres pour les rendre visibles. Si m=1, alors Remind suppose que l'arrière-plan du terminal est clair et il assombrira les couleurs vives pour les rendre visibles. Si m est spécifié comme 2, alors Remind n'effectue aucun ajustement, et certains rappels peuvent être difficiles ou impossibles à voir si la couleur est trop proche de la couleur d'arrière-plan du terminal. Si vous fournissez la lettre t au lieu d'un nombre, alors Remind tente de deviner la couleur d'arrière-plan du terminal, même si la sortie standard n'est pas un terminal.

Au démarrage, si la sortie standard est un terminal, Remind tente de déterminer si l'arrière-plan du terminal est sombre ou clair en envoyant une séquence d'échappement spéciale pour déterminer la couleur d'arrière-plan. Le paramètre m peut outrepasser cette vérification (ou la forcer si m est donné comme t.)

Si le paramètre optionnel b est fourni après une virgule, alors b=0 indique à Remind d'ignorer les rappels SPECIAL SHADE (par défaut) et b=1 indique à Remind de respecter les rappels SPECIAL SHADE en émettant des codes d'échappement VT100 pour colorer l'arrière-plan de la cellule du calendrier. Notez que SHADE ne fonctionne pas bien sauf si vous utilisez la palette étendue de 256 couleurs (n=1) ou les couleurs vraies 24 bits (n=2). Notez que pour les cellules de calendrier qui sont ombrées, le mécanisme de limitation décrit précédemment pour m=0 ou m=1 est ignoré ; on suppose que si vous définissez à la fois la couleur de premier plan d'un rappel et la couleur d'arrière-plan d'une cellule, alors vous savez ce que vous faites.

-wcol[,pad[,esp]]]
L'option -w spécifie la largeur de sortie, le remplissage et l'espacement de la sortie formatée du calendrier. Col spécifie le nombre de colonnes sur le périphérique de sortie. Si col n'est pas spécifié, ou est spécifié comme

0, par défaut, il utilise le plus grand de 71 ou de la largeur réelle de votre terminal, ou 80 si la sortie standard n'est pas un terminal. Si col est spécifié par la lettre t, alors Remind tente d'obtenir la largeur du périphérique de terminal /dev/tty. Ceci est utile, par exemple, si vous redirigez la sortie du calendrier vers less ; même si la sortie standard est un tube, vous voulez que le calendrier soit correctement dimensionné pour votre fenêtre de terminal : 
        remind -c -wt .reminders | less

Notez que la valeur de col est également utilisée pour définir la variable système $FormWidth, qui est initialisée à col - 8. Voir "VARIABLES SYSTÈME" pour les détails.

Pad spécifie combien de lignes utiliser pour "rembourrer" les cases de calendrier vides. La valeur par défaut est 5. Si vous avez de nombreux rappels certains jours qui rendent votre calendrier trop grand pour tenir sur une page, vous pouvez essayer de réduire pad pour rendre les cases vides plus petites. Spc spécifie combien de lignes vides laisser entre le numéro du jour et la première entrée du rappel. La valeur par défaut est 1.

N'importe lequel de col, pad ou spc peut être omis, à condition que vous fournissiez le nombre correct de virgules. N'utilisez pas d'espaces dans l'option.

-s[a]n
L'option -s est très similaire à l'option -c, sauf que le calendrier de sortie n'est pas formaté. Il est répertorié dans un format "simple" qui peut être utilisé comme entrée pour des programmes de dessin de calendrier plus sophistiqués. Si n commence par "+", il est interprété comme un nombre de semaines. Cette option active également implicitement l'option -o.

Si vous suivez immédiatement le s avec la lettre a, alors Remind affiche les rappels sur le calendrier le jour où ils se produisent réellement ainsi que les jours précédents spécifiés par le delta du rappel.

-p[a][p][p][q][+]n
L'option -p est très similaire à l'option -s, sauf que la sortie contient des informations supplémentaires à utiliser par un backend tel que le programme Rem2PS, qui crée un calendrier PostScript, et divers autres programmes backend. Si n commence par "+", il spécifie un nombre de semaines plutôt qu'un nombre de mois, et les backends sont censés produire des calendriers hebdomadaires. Notez que tous les backends ne prennent pas en charge les calendriers hebdomadaires ; actuellement, seuls rem2pdf et rem2html le font. La spécification d'un calendrier hebdomadaire active implicitement le format d'échange JSON pur, similaire à -ppp.

Le format de la sortie -p est décrit dans la page de manuel rem2ps(1). Si vous suivez immédiatement le p avec la lettre a, alors Remind affiche les rappels sur le calendrier le jour où ils se produisent réellement ainsi que les jours précédents spécifiés par le delta du rappel. Si vous suivez le p avec un autre p, alors Remind utilise un format plus complet basé sur JSON plutôt que le format "calendrier simple". Ce format est également documenté dans la page de manuel rem2ps(1). Enfin, si vous utilisez trois p, comme dans -ppp, alors Remind utilise un format JSON pur, à nouveau documenté dans rem2ps(1). Si vous incluez une lettre q avec cette option, le filtre de substitution habituel du mode calendrier est désactivé et les séquences %"...%" sont conservées dans la sortie.

Notez que pour passer des chaînes INFO à un backend, vous devez utiliser -pp ou -ppp. Le format -p plus simple n'est pas capable de transmettre les chaînes INFO au backend.

Les options -p, -pp et -ppp activent implicitement l'option -o.

Notez que les options -pp ou -ppp activent également l'option -l.

-l
Si vous utilisez l'option -l conjointement avec l'option -p, alors Remind génère des informations supplémentaires pour les programmes backend tels que rem2ps. Ces informations supplémentaires permettent aux programmes backend de corréler un rappel avec le fichier source et le numéro de ligne qui l'ont produit.
-m
L'option -m fait en sorte que les options -c ou -p produisent un calendrier dont la première colonne est le lundi plutôt que le dimanche. (Ceci est conforme à la norme internationale.)
-v
L'option -v rend la sortie de Remind légèrement plus verbeuse. Actuellement, cela fait que Remind échoppe une ligne incorrecte en cas d'erreur, et affiche un message de sécurité si un script teste la variable système $RunOff.
-o
L'option -o fait que Remind ignore toutes les directives ONCE. Notez que ONCE est également ignoré si l'une des options -c, -n, -p ou -s est utilisée, si un facteur de répétition *n est utilisé, ou si une date autre que la date du jour est spécifiée sur la ligne de commande.
-t
L'option -t fait que Remind déclenche tous les rappels non expirés, quel que soit le delta fourni pour chaque rappel.
-tn
Si vous fournissez un nombre n après l'option -t, alors Remind fait semblant que chaque commande REM a un delta de ++n, quel que soit le delta existant.
-tz
Si vous fournissez la lettre z après l'option -t, alors Remind définit les deltas de toutes les instructions REM à zéro, quelle que soit la valeur fournie dans l'instruction REM elle-même. En effet, cela désactive tous les deltas de la forme +n et ++n.
-tt[n]
L'option -tt fait que Remind suppose un delta par défaut de n minutes pour tous les rappels chronométrés. Si -tt est donné sans n, un delta par défaut de 5 minutes est utilisé.
-h
L'option -h ("hush...") supprime certains messages d'avertissement et d'information. En particulier, si aucun rappel n'est déclenché, ce mode ne produit aucune sortie.
-a
L'option -a fait que Remind ne déclenche pas immédiatement les rappels chronométrés qui se déclenchent le jour même. Elle fait également en sorte que Remind ne place pas les rappels chronométrés dans un calendrier. Si vous fournissez deux options -a ou plus, alors Remind déclenchera les rappels chronométrés qui sont dans le futur, mais ne déclenchera pas les rappels chronométrés dont l'heure est passée. (Indépendamment du nombre d'options -a que vous fournissez, Remind n'inclura pas les rappels chronométrés dans le calendrier si au moins une option -a est utilisée.)
-q
L'option -q fait que Remind ne met pas en file d'attente les rappels chronométrés pour une exécution ultérieure.
-f
L'option -f fait que Remind reste au premier plan lors du traitement des rappels mis en file d'attente, au lieu de créer un processus d'arrière-plan pour les gérer.
-e
L'option -e redirige les messages d'erreur (normalement envoyés vers le flux d'erreur standard) vers le flux de sortie standard.
-dcaractères
L'option -d active certains modes de débogage. Les caractères spécifient les modes à activer :
e
Écho de toutes les lignes d'entrée
x
Trace de toute l'évaluation d'expressions
t
Affichage de tous les calculs de dates de déclenchement
v
Vidage de la table des variables après exécution du script de rappel
l
Écho des lignes lors de l'affichage des messages d'erreur
f
Trace de la lecture des fichiers de rappel
s
Trace de l'analyse syntaxique des expressions et affiche l'arbre des nœuds d'expression interne. Ceci est peu susceptible d'être utile à moins que vous ne travailliez sur le moteur d'évaluation d'expressions de Remind.
h
Vidage des statistiques de table de hachage à la sortie.
u
Lorsque Remind se termine, affiche une liste des variables qui ont été définies (SET), mais qui n'ont pas été utilisées par la suite.

Notez que le drapeau de débogage u peut produire des avertissements non pertinents. Par exemple, cette séquence de commandes :

        DEBUG +u
        SET a 1
        IFTRIG Wed
                MSG a = [a]
        ENDIF

émettra un avertissement indiquant que a est inutilisé, sauf si elle est exécutée un mercredi.

n
Affiche des informations de débogage sur la raison pour laquelle Remind considère une expression comme "non constante"
q
Génère une commande TRANSLATE chaque fois que la fonction intégrée _() est appelée ou que la séquence de substitution %(...) est rencontrée.
-g[a|d[a|d[a|d[a|d]]]]
Normalement, les rappels sont émis dans l'ordre dans lequel ils sont rencontrés dans le script de rappel. L'option -g fait que Remind trie les rappels par date et heure avant de les émettre. Les caractères optionnels a et d spécifient l'ordre de tri (ascendant ou descendant) pour les champs de date, d'heure et de priorité. Voir la section "TRI DES RAPPELS" pour plus d'informations.

Notez que -g est ignoré si vous utilisez l'option -n.

-b[n]
Définit le format de l'heure pour les sorties de calendrier et de calendrier simple. N peut varier de 0 à 2, avec 0 par défaut. Une valeur de 0 fait que les heures sont insérées au format 12 heures (am/pm). 1 fait que les heures sont insérées au format 24 heures, et 2 empêche l'insertion automatique des heures dans la sortie du calendrier.
-x[n]
Définit la limite d'itération pour la clause SATISFY d'une commande REM. La valeur par défaut est 1000.
-kcmd
Au lieu de simplement imprimer les rappels de type MSG, cela les fait passer à la commande spécifique cm
d. Vous devez utiliser '%s' là où vous souhaitez que le corps apparaisse, et vous pourriez avoir besoin d'encadrer cette option entre guillemets. Notez que tous les caractères shell dans le corps du rappel sont échappés avec une barre oblique inverse, et le corps entier du rappel est passé comme un seul argument. Notez que cette option annule l'option -r et la commande RUN OFF.
Par exemple, supposez que vous ayez un programme X Window appelé xmessage qui affiche une fenêtre et ses arguments d'invocation. Vous pourriez utiliser : 
remind '-kxmessage %s &' ...

pour que tous vos rappels de type MSG soient traités à l'aide de xmessage.

Un avertissement : il est très facile de lancer des dizaines de processus xmessage avec la technique ci-dessus. Soyez donc très prudent. Parce que tous les caractères shell et d'espacement sont échappés, le programme que vous exécutez avec l'option -k doit être préparé à gérer le message entier comme un seul argument.

Si vous faites suivre l'option -k par un deux-points, la commande est appliquée uniquement aux rappels programmés mis en file d'attente. Les rappels normaux sont traités comme d'habitude. Dans l'exemple ci-dessus, si vous souhaitez que les rappels normaux soient simplement affichés comme d'habitude, mais que les rappels mis en file d'attente soient envoyés à notify-send, vous pourriez utiliser :

remind '-k:notify-send %s &' ...

Vous utilisez à la fois -kcmd1 et -k:cmd2 pour utiliser des commandes différentes pour les rappels mis en file d'attente et ceux qui ne le sont pas.

-z[n] Exécute Remind en mode "démon". Si n
est fourni, il spécifie la fréquence (en minutes) à laquelle Remind doit se réveiller pour vérifier si le script de rappel a été modifié. N vaut 1 par défaut, et peut aller de 1 à 60. Notez que l'utilisation de l'option -z active également l'option -f.
Si Remind est compilé sur un système qui supporte inotify(7), alors si le script de rappel fourni en ligne de commande est en fait un répertoire, Remind vérifie en outre si tous les fichiers de ce répertoire ont été modifiés depuis le démarrage.

Si vous fournissez l'option -zj, Remind s'exécute dans un mode spécial appelé mode serveur. Ceci est documenté dans la page man de tkremind ; voir tkremind(1). L'ancienne option de mode serveur -z0 fonctionne toujours, mais est dépréciée ; elle utilise une méthode ad hoc pour communiquer avec le client plutôt que d'utiliser JSON pour communiquer avec le client.

-unom
Exécute Remind avec l'uid et le gid de l'utilisateur spécifié par nom. L'option modifie l'uid et le gid comme décrit, et définit les variables d'environnement HOME, SHELL et USER vers le répertoire personnel, le shell et le nom d'utilisateur, respectivement, de l'utilisateur spécifié. LOGNAME est également défini sur le nom d'utilisateur spécifié. Cette option est destinée à être utilisée dans des scripts shell qui envoient des rappels par courrier à tous les utilisateurs. Notez qu'à partir de Remind 3.00.17, l'utilisation de -u implique -r -- la directive RUN et les fonctions shell() sont désactivées. Cependant, si vous préfixez nom avec un signe +, alors RUN et shell() ne sont pas désactivés. C'est-à-dire que -uquelquechose passe à l'utilisateur quelquechose et désactive RUN, tandis que -u+quelquechose passe à l'utilisateur quelquechose mais laisse RUN activé.
Les utilisateurs non root peuvent également utiliser l'option -u. Cependant, dans ce cas, elle ne modifie que les variables d'environnement comme décrit ci-dessus. Elle ne modifie pas l'uid ou le gid effectif.
-+nomutilisateur
Fait en sorte que Remind fasse confiance aux fichiers appartenant à l'utilisateur nomutilisateur. Normalement, si Remind lit un fichier que vous ne possédez pas, il désactive RUN et la fonction shell(). Cette option fait en sorte qu'il fasse également confiance aux fichiers appartenant à nomutilisateur. Vous pouvez fournir plusieurs options -+ pour faire confiance à plusieurs utilisateurs, jusqu'à une limite de 20 utilisateurs de confiance.
-y
Fait en sorte que Remind synthétise une étiquette pour tout rappel qui ne possède pas de clause TAG.
-ivar=expr
Définit la valeur de la variable var spécifiée sur expr, et préserve var. Expr peut être n'importe quelle expression Remind valide. Voir la section "INITIALISATION DES VARIABLES SUR LA LIGNE DE COMMANDE" pour plus de détails. Si vous omettez la partie =expr, alors var est initialisée à 0. En d'autres termes, -ivar est exactement la même chose que -ivar=0.
-ifonction(args)=définition
Vous permet de définir une fonction en ligne de commande.

Si vous fournissez une date en ligne de commande, elle doit se composer de jour mois année, où jour est le jour du mois, mois est au moins les trois premières lettres du nom anglais du mois, et année est une année (toutes les 4 chiffres) de 1990 à environ 2075. Vous pouvez omettre le jour, qui vaut alors 1 par défaut.

Si vous fournissez une date en ligne de commande, alors Remind l'utilise, plutôt que la date système réelle, comme sa notion de "aujourd'hui". Cela vous permet de créer des calendriers pour les mois à venir, ou de tester comment vos rappels se déclencheront à l'avenir. De même, vous pouvez fournir une heure pour définir la notion de "maintenant" de Remind à une heure particulière. Fournir une heure en ligne de commande active également implicitement l'option -q et désactive l'option -z. L'heure peut être spécifiée au format 24 heures (par exemple, 13:20) ou au format courant "AM/PM" (1:20pm).

Si vous préférez spécifier la date de manière plus concise, vous pouvez la fournir au format AAAA-MM-JJ ou AAAA/MM/JJ. Vous pouvez même fournir une date et une heure en ligne de commande comme un seul argument : AAAA-MM-JJ@HH:MM.

De plus, vous pouvez fournir un paramètre répéter, qui a la forme *rep. Cela fait exécuter Remind rep fois, avec la date incrémentée à chaque itération. Vous devrez peut-être encadrer le paramètre entre guillemets pour éviter l'expansion par le shell. Voir la sous-section "Exécution Répétée" dans la section "MODE CALENDRIER" pour plus d'informations.

OPTIONS LONGUES

Remind supporte les options longues suivantes, qui sont sensibles à la casse :

--version
L'option --version fait afficher par Remind son numéro de version sur la sortie standard, puis quitte.
--hide-completed-todos
En mode Calendrier, Remind affiche normalement tous les TODOs. Si vous fournissez cette option, il n'affichera pas les TODOs qui ont été marqués comme terminés.
--only-todos
N'émet que les rappels de type TODO.
--only-events
N'émet pas les rappels de type TODO.
--json
En mode Agenda, génère une sortie JSON au lieu de la sortie normale en mode texte. --json désactive également le tri (l'option -g) et la mise en file d'attente (l'option -q). Voir la section "SORTIE JSON DU MODE AGENDA" pour plus de détails. L'option --json est ignorée en mode Calendrier. Notez qu'en mode JSON, la sortie de tout rappel de type RUN qui apparaîtrait normalement sur la sortie standard est redirigée vers la sortie d'erreur standard à la place ; ceci afin que les rappels de type RUN ne perturbent pas la sortie et ne produisent pas de JSON invalide sur la sortie standard.
--print-errs
L'option --print-errs fait afficher par Remind tous les messages d'erreur possibles sur la sortie standard, puis quitte. Les messages sont affichés dans un format adapté au premier argument d'une commande TRANSLATE. Si vous traduisez les messages d'erreur, alors Remind utilisera les versions traduites lors de l'affichage des messages d'erreur et d'avertissement. Voir également TRANSLATE GENERATE dans la section "LA TABLE DE TRADUCTION".

Notez que si un message non traduit contient des séquences de formatage de style printf comme "%s" ou "%d", alors le message traduit doit contenir les mêmes séquences dans le même ordre, sinon Remind l'ignorera et utilisera le message original non traduit.

--print-config-cmd
Cette option fait afficher par Remind la commande ./configure exacte qui a été utilisée lors de la compilation de Remind. Vous pouvez l'utiliser pour construire une nouvelle version de Remind en utilisant la même configuration qu'une version existante en exécutant :
        eval `remind --print-config-cmd`

depuis le répertoire source de niveau supérieur de Remind. (Cependant, il est plus sûr d'exécuter simplement remind --print-config-cmd puis de taper la commande une fois que vous avez vérifié qu'elle semble correcte.)

--print-tokens
L'option --print-tokens fait afficher par Remind les jetons utilisés par l'analyseur, les noms des fonctions intégrées et les noms des variables système sur la sortie standard, puis quitte. Cette sortie est conçue pour faciliter la création d'un fichier de coloration syntaxique pour divers éditeurs de texte. La sortie peut être modifiée à la main ou par un script pour créer un fichier de coloration syntaxique avec une relative facilité.
--max-execution-time=n
Limite le temps d'exécution total (mesuré par l'horloge murale) à n secondes. Ceci est utile si Remind est invoqué sur des fichiers potentiellement non fiables qui pourraient tenter d'utiliser beaucoup de ressources. Notez que la limite n est approximative et Remind pourrait s'exécuter une ou deux secondes de plus avant d'être arrêté. Si n est spécifié comme zéro, alors aucune limite n'est appliquée, comme si l'option n'avait pas été utilisée du tout.

Si une limite est appliquée, elle ne s'applique qu'à l'exécution au premier plan de Remind. Si Remind termine le traitement du script puis commence à gérer les rappels mis en file d'attente, la limite de temps est réinitialisée à aucune limite.

--max-expr-complexity=n
Limite la complexité totale de l'évaluation d'expressions pour une ligne donnée dans un script à n nœuds. En gros, chaque appel de fonction, opérateur, constante, référence de variable, etc. correspond à un nœud d'expression. Par défaut, la limite est fixée à 10000000 (dix millions). Vous pouvez explicitement la régler à
o zéro si vous ne souhaitez aucune limite. La limite par défaut de dix millions ne devrait jamais être déclenchée par un script Remind sensible, cependant, et nous ne recommandons pas de changer la limite.
--test
L'option longue --test est réservée à l'utilisation par les tests d'acceptation exécutés par "make test". N'utilisez pas cette option en production.
--flush
L'option longue --flush rend les flux de sortie standard et d'erreur standard de Remind non mis en mémoire tampon. Elle est principalement utilisée pour les tests et ne devrait probablement pas être utilisée en production.

FICHIERS DE RAPPEL

Remind utilise des scripts pour contrôler son fonctionnement. Vous pouvez utiliser n'importe quel éditeur de texte capable de créer des fichiers texte brut pour créer un script Remind. Les commandes à l'intérieur d'un script peuvent aller du très simple et presque immédiatement compréhensible :

        REM Mar 31 MSG Journée Internationale de Visibilité Transgenre

au baroque et obscur :

        REM [date(cetteannée, 1, 1) + 180] ++5 OMIT \
        sam dim AVANT MSG [ord(cetteannée-1980)] paiement dû %b!

Un fichier de rappel se compose de commandes, avec une commande par ligne. Plusieurs lignes peuvent être prolongées en utilisant le caractère backslash, comme dans l'exemple ci-dessus. Dans ce cas, toutes les lignes concaténées sont traitées comme une seule ligne par Remind. Notez que si une erreur se produit, Remind signale le numéro de ligne de la dernière ligne d'une ligne prolongée.

Remind ignore les lignes vides et les lignes commençant par les caractères '#' ou ';'. Vous pouvez utiliser le point-virgule comme caractère de commentaire si vous souhaitez faire passer un script Remind par le préprocesseur C, qui interprète le caractère '#' comme le début d'une directive de préprocesseur.

Notez que Remind traite les continuations de ligne avant tout le reste. Par exemple :

# Ceci est un commentaire \
Cette ligne fait partie du commentaire en raison de la continuation de ligne \
et ainsi de suite.
REM MSG Cette ligne n'est pas ignorée (pas de \ ci-dessus)

Remind n'est pas sensible à la casse ; vous pouvez généralement utiliser n'importe quel mélange de majuscules ou de minuscules pour les commandes, les paramètres, les options d'invocation, etc.

LA COMMANDE REM

La commande la plus puissante dans un script Remind est la commande REM. Cette commande est responsable de l'émission des rappels. Sa syntaxe est :

REM [ONCE] [spéc_date] [retard] [delta] [répétition] [TODO] [MAX-EN_RETARD n] [TERMINE_JUSQU'À date_complète] [PRIORITÉ prio] [OMIT | AVANT | APRÈS] [OMIT liste_omit] [AJOUTOMIT] [PASDEFILE] [OMITFUNC fonction_omit] [À heure [tdelta] [trepétition]] [SCHED fonction_sched] [ALERTE fonction_alerte] [JUSQU'À date_expiration | SOUS dernière_date] [SCANDEPUI date_scan | DEPUIS date_début] [DURÉE durée] [TAG tag] [TZ fuseau_horaire] [INFO "chaîne_info"] MSG | MSF | RUN | CAL | SATISFY | SPÉCIAL spécial | PS | PSFILE corps

Les parties de la commande REM peuvent être spécifiées dans n'importe quel ordre, sauf que le corps doit venir immédiatement après le mot-clé MSG, RUN, CAL, PS, PSFILE ou SATISFY. La portion de la commande REM avant la clause MSG, MSF RUN, CAL ou SATISFY est appelée un déclencheur.

Dans les versions antérieures de Remind, le jeton REM était facultatif à condition que le reste de la commande ne puisse pas être confondu avec une autre commande Remind. Cependant, cette utilisation est dépréciée et provoquera maintenant un avertissement. Toutes vos lignes de rappel doivent commencer par la commande REM.

MSG, MSF, RUN, CAL, SPÉCIAL, PS et PSFILE

Ces mots-clés indiquent le type du rappel. (SATISFY est plus compliqué et sera expliqué plus tard.) Un rappel de type MSG imprime normalement un message sur la sortie standard, après avoir fait passer le corps à travers un filtre de substitution spécial, décrit dans la section "LE FILTRE DE SUBSTITUTION." Cependant, si vous avez utilisé l'option de ligne de commande -k, les rappels de type MSG sont transmis au programme approprié. Notez que les options -c, -s, -p et -n désactivent l'option -k.

Les versions antérieures de Remind vous permettaient d'omettre le type de rappel, auquel cas il était par défaut MSG. Cependant, cette utilisation est dépréciée et provoquera un avertissement. Quelque chose comme :

REM 6 Janvier Anniversaire de Dianne

affichera l'avertissement "Type REM manquant ; MSG supposé"

Le mot-clé MSF est presque identique au mot-clé MSG, sauf que le rappel est formaté pour s'adapter à un format de type paragraphe. Trois variables système contrôlent le formatage des rappels de type MSF - ce sont $FirstIndent, $SubsIndent et $FormWidth. Elles sont discutées dans la section "VARIABLES SYSTÈME." Le mot-clé MSF provoque la modification de l'espacement de votre rappel - les espaces supplémentaires sont supprimés et deux espaces sont placés après les points et autres caractères, tels que spécifiés par les variables système $EndSent et $EndSentIg. Notez que si le corps du rappel inclut des caractères de nouvelle ligne (placés là avec la séquence %_), les nouvelles lignes sont traitées comme le début de nouveaux paragraphes, et l'indentation $FirstIndent est utilisée pour la ligne suivante. Vous pouvez utiliser deux nouvelles lignes consécutives pour émettre des paragraphes espacés à partir d'un seul corps de rappel.

Un rappel de type RUN fait également passer le corps par le filtre de substitution, puis exécute le résultat comme une commande système. Un rappel de type CAL est utilisé uniquement pour placer des entrées dans le calendrier produit lorsque Remind est exécuté avec les options -c, -s ou -p.

Un rappel de type PS ou PSFILE est utilisé pour transmettre directement du code PostScript à l'imprimante lors de la production de calendriers PostScript. Cela peut être utilisé pour ombrer certaines entrées de calendrier (voir la fonction psshade()), inclure des graphiques dans le calendrier, ou presque tout autre usage auquel vous pouvez penser. Vous ne devriez pas utiliser ces types de rappels à moins d'être un programmeur PostScript expert. Les rappels PS et PSFILE sont ignorés à moins que Remind ne soit exécuté avec l'option -p. Voir la section "Plus sur PostScript" pour plus de détails.

Un rappel de type SPÉCIAL est utilisé pour passer des informations "hors bande" de Remind à un backend de production de calendrier. Il doit être suivi d'un mot indiquant le type de données spéciales transmises. Le type d'un rappel spécial dépend du backend. Pour le backend Rem2PS, SPÉCIAL PostScript est équivalent à un rappel de type PS, et SPÉCIAL PSFile est équivalent à un rappel de type PSFILE. Le corps d'un rappel SPÉCIAL dépend évidemment du backend. Un backend doit ignorer un SPÉCIAL qu'il ne reconnaît pas.

SPÉCIFICATIONS DE DATE

Une spéc_date se compose de zéro à quatre parties. Ces parties sont le jour (jour du mois), le mois (nom du mois), l'année et le jour_semaine. Mois et jour_semaine sont les noms anglais des mois et des jours de la semaine. Au moins les trois premiers caractères doivent être utilisés. Les exemples suivants illustrent les diverses parties d'une spéc_date :

jour:
1, 22, 31, 14, 3
mois:
JANVIER, fév, Mars, AvR, mai, Août
année:
1990, 1993, 2030. L'année peut varier de 1990 à 2075.
jour_semaine:
Lundi, mar, Mer, JEU, Vendredi, samedi, dimAnchE

Notez qu'il peut y avoir plusieurs composants jour_semaine séparés par des espaces dans une spéc_date.

INTERPRÉTATION DES SPÉCIFICATIONS DE DATE

Les exemples suivants montrent comment les spécifications de date sont interprétées.

1. Spécification de date nulle - le rappel est déclenché chaque jour. La date de déclenchement pour une exécution spécifique est simplement la date système actuelle. Par exemple :

        REM MSG Ceci est déclenché à chaque fois que Remind s'exécute

2. Seulement le jour présent. Le rappel est déclenché le jour spécifié de chaque mois. La date de déclenchement pour une exécution particulière est le jour le plus proche de ce type de la date système actuelle. Par exemple :

REM 1 MSG Premier de chaque mois.
REM 31 MSG 31 de chaque mois qui a 31 jours.

3. Seulement le mois présent. Le rappel est déclenché chaque jour du mois spécifié. Exemple :

REM Fév MSG Chaque jour en février

4. Le jour et le mois présents. Exemples :

REM 6 Jan MSG Chaque 6 janvier
REM Fév 29 MSG Chaque 29 février

5. Seulement l'année présente. Exemple :

REM 1991 MSG Chaque jour en 1991

6. L'année et le jour présents. Exemples :

REM 1 1990 MSG 1er de chaque mois en 1990
REM 1992 23 MSG 23 de chaque mois en 1992

7. L'année et le mois présents. Exemples :

REM Fév 1991 MSG Chaque jour en fév 1991
REM 1992 Septembre MSG Chaque jour en sept 1992

8. L'année, le mois et le jour présents. Exemples :

REM 8 Jan 1991 MSG 8 janvier 1991.
REM 1992 Mars 9 MSG 9 mars 1992.

9. Seulement le jour_semaine. Exemples :

REM Sam MSG Chaque samedi
REM Lun Mar Mer Jeu Ven MSG Chaque jour de semaine
REM Lundi Mercredi MSG Chaque lundi et mercredi

10. Le jour_semaine et le jour présents. Exemples :

REM Sam 1 MSG Premier samedi de chaque mois
REM Lun Mar Mer Jeu Ven 15 \
	MSG 1er jour de semaine le ou après le 15 de chaque mois

11. Le jour_semaine et le mois présents. Exemples :

REM Lun Mars MSG Chaque lundi en mars
REM Lun Mar Mer Jeu Ven Fév MSG Chaque jour de semaine en février

12. Le jour_semaine, le mois et le jour présents. Exemples :

REM Lun 1 Mars MSG Premier lundi en mars
REM Sam Dim 15 Juillet MSG Premier sam ou dim le ou après le 15 juillet

13. Le jour_semaine et l'année présents. Exemple :

REM Sam Dim 1991 MSG Chaque samedi et dimanche en 1991

14. Le jour_semaine, le jour et l'année présents. Exemples :

REM Lun 15 1990 MSG 1er lun après le 15 de chaque mois en 1990
REM Lun Mar Mer Jeu Ven 1 1990 \
	MSG 1er jour de semaine de chaque mois en 1990

15. Le jour_semaine, le mois et l'année présents. Exemple :

REM Lun Mer 1991 Fév MSG
Chaque lundi et mercredi de février 1991. 16. *jour de la semaine, jour, mois* et *année* présents. Exemple : REM Lun Mar Mer Jeu Ven 28 oct 1990 \ MSG 1er jour ouvrable à partir du 28 octobre 1990. Notez que lorsque *jour de la semaine* et *jour* sont tous deux spécifiés, **Remind** choisit la première date à partir du *jour* spécifié qui satisfait également la contrainte de *jour de la semaine*. Il le fait en choisissant la première date à partir du *jour* spécifié qui est listée dans la liste des *jours de la semaine*. Ainsi, un rappel comme : REM Lun Mar 28 oct 1990 MSG Salut ne serait émis que le lundi 29 octobre 1990. Il ne serait pas émis le mardi 30 octobre 1990, car le 29 est la première date satisfaisant les contraintes de *jour de la semaine*. **SPÉCIFICATIONS DE DATE RACCOURCIES** En plus d'écrire le jour, le mois et l'année séparément, vous pouvez spécifier YYYY-MM-DD ou YYYY/MM/DD. Par exemple, les instructions suivantes sont équivalentes : REM 5 juin 2010 MSG Cool ! REM 2010-06-05 MSG Cool ! Vous pouvez également spécifier une date et une heure sous la forme YYYY-MM-DD@HH:MM. Ces instructions sont équivalentes : REM 19 déc 2010 À 16:45 MSG Salut REM 2010-12-19@16:45 MSG Salut Il y a une subtilité avec les spécifications de date raccourcies : les instructions suivantes ne sont *pas* équivalentes : REM 19 déc 2010 À 16:45 +60 MSG Salut REM 2010-12-19@16:45 +60 MSG Salut Dans la deuxième instruction, le « +60 » est un *delta* qui s'applique à la date plutôt qu'un *tdelta* qui s'applique à l'heure. Nous recommandons d'utiliser explicitement le mot-clé AT avec les rappels basés sur l'heure. **L'ALGORITHME DE REMIND** **Remind** utilise l'algorithme suivant pour calculer une date de déclenchement : à partir de la date actuelle, il examine chaque jour, un par un, jusqu'à ce qu'il trouve une date qui satisfait la spécification de date, ou qu'il prouve par lui-même qu'une telle date n'existe pas. (En réalité, **Remind** se comporte *comme s'il* utilisait cet algorithme ; ce serait beaucoup trop lent en pratique. En interne, **Remind** utilise des techniques beaucoup plus rapides pour calculer une date de déclenchement.) Voir DÉTAILS SUR LE CALCUL DES DÉCLENCHEURS pour plus d'informations. **SCANNING ARRIÈRE** Parfois, il est nécessaire de spécifier une date comme étant une quantité de temps donnée avant une autre date. Par exemple, le dernier lundi d'un mois donné est calculé comme le premier lundi du mois suivant, moins 7 jours. La spécification *back* dans le rappel est utilisée dans ce cas : REM Lun 1 -7 MSG Dernier lundi de chaque mois. Un *back* est spécifié avec un ou deux tirets suivis d'un entier. Cela amène **Remind** à se déplacer « en arrière » par rapport à ce qui serait normalement la date de déclenchement. La différence entre --7 et -7 sera expliquée lorsque le mot-clé **OMIT** sera décrit. **AVERTISSEMENT PRÉVENTIF** Pour certains rappels, il est approprié de recevoir un avertissement préalable de l'événement. Par exemple, vous pourriez souhaiter être rappelé de l'anniversaire de quelqu'un plusieurs jours à l'avance. La partie *delta* de la commande **REM** y parvient. Elle est spécifiée par un ou deux signes « + » suivis d'un nombre *n*. Encore une fois, la différence entre les formes « + » et « ++ » sera expliquée sous le mot-clé **OMIT**. **Remind** déclenchera le rappel à la date de déclenchement calculée, ainsi que chacun des *n* jours précédant l'événement. Voici quelques exemples : REM 6 jan +5 MSG Rappelez-moi de l'anniversaire 5 jours à l'avance. L'exemple ci-dessus serait déclenché chaque 6 janvier, ainsi que les 1er au 5 janvier. **RAPPELS PÉRIODIQUES** Nous avons déjà vu certains mécanismes intégrés pour certains types de rappels périodiques. Par exemple, un événement se produisant chaque mercredi pourrait être spécifié comme : REM Mer MSG Événement ! Cependant, les événements qui ne se répètent pas quotidiennement, hebdomadairement, mensuellement ou annuellement nécessitent une autre approche. Le composant *repeat* de la commande **REM** répond à ce besoin. Pour l'utiliser, vous devez spécifier complètement une date (année, mois et jour, et éventuellement jour de la semaine) ; c'est la date de début de la période de répétition. Le composant *repeat* est un astérisque suivi d'un nombre spécifiant la période de répétition en jours. Par exemple, supposons que vous soyez payé chaque deuxième mercredi, et que votre dernière paie ait été le mercredi 28 octobre 1992. Vous pouvez utiliser : REM 28 oct 1992 *14 MSG Paie Cela émet le rappel tous les 14 jours, à partir du 28 oct 1992. Vous pouvez utiliser *delta* et *back* avec *repeat*. Notez, cependant, que le *back* est utilisé uniquement pour calculer la date de début ; par la suite, le rappel se répète avec la période spécifiée. De même, si vous spécifiez un jour de la semaine, il est utilisé uniquement pour calculer la date de début, et n'affecte pas la période de répétition. **SCANFROM et FROM** Les mots-clés **SCANFROM** et **FROM** sont réservés aux programmeurs **Remind** avancés et seront expliqués dans la section « DÉTAILS SUR LE CALCUL DES DÉCLENCHEURS » vers la fin de ce manuel. Notez que **SCANFROM** n'est disponible que dans les versions de **Remind** 03.00.04 et ultérieures. **FROM** n'est disponible qu'à partir de 03.01.00 et versions ultérieures. **PRIORITÉ** Le mot-clé **PRIORITY** doit être suivi d'un nombre de 0 à 9999. Il est utilisé en mode calendrier et lors du tri des rappels. Si deux rappels ont la même date et heure de déclenchement, ils sont triés par priorité. Si le mot-clé **PRIORITY** n'est pas fourni, une priorité par défaut de 5000 est utilisée. (Cette valeur par défaut peut être modifiée en ajustant la variable système **$DefaultPrio**. Voir la section « VARIABLES SYSTÈME » pour plus d'informations.) **DATES D'EXPIRATION** Certains rappels doivent être émis périodiquement pendant un certain temps, puis expirer. Par exemple, supposez que vous ayez un cours tous les vendredis, et que votre dernier cours soit le 11 décembre 1992. Vous pouvez utiliser : REM Ven JUSQU'AU 11 déc 1992 MSG Cours aujourd'hui. Un autre exemple : supposez que vous ayez un devoir de juré du 30 novembre 1992 au 4 décembre 1992. Le rappel suivant émettra le message chaque jour de votre devoir de juré, ainsi que 2 jours avant : REM 1992-11-30 *1 +2 JUSQU'AU 1992-12-04 MSG Devoir de juré Notez que la répétition de *1 est nécessaire ; sans elle, le rappel ne serait émis que le 30 novembre (et les deux jours précédents). Comme cas particulier, vous pouvez utiliser le mot-clé **THROUGH** à la place de *1 et **UNTIL**. Les deux commandes **REM** suivantes sont équivalentes : REM 1992-11-30 *1 +2 JUSQU'AU 1992-12-04 MSG Devoir de juré REM 1992-11-30 +2 À TRAVERS 1992-12-04 MSG Devoir de juré Si vous avez une date d'expiration via l'utilisation de **THROUGH** ou **UNTIL**, alors **Remind** ne déclenchera *jamais* le rappel après la date d'expiration. Par exemple, si vous avez ceci : OMIT 2021-01-08 REM 2021-01-01 À TRAVERS 2021-01-08 APRÈS MSG Test le rappel ne sera pas déclenché le 2021-01-08, ni le 2021-01-09 ; même si le mot-clé AFTER déplacerait normalement le rappel du 8 au 9, la date d'expiration du 2021-01-08 la supplante. **LE MOT-CLÉ ONCE** Parfois, il est nécessaire de s'assurer que les rappels ne sont exécutés qu'une seule fois par jour. Par exemple, comparez les deux rappels suivants : REM Ven EXEC do_backup REM Ven UNE SEULE FOIS EXEC do_backup Le premier sera exécuté chaque fois que vous invoquerez **Remind** un vendredi, tandis que le second ne sera exécuté que la première fois que vous invoquerez **Remind** un vendredi donné. Si vous exécutez **Remind** depuis votre script .login, par exemple, et que vous vous connectez plusieurs fois par jour, le programme *do_backup* du premier rappel sera exécuté à chaque connexion. Si, cependant, vous utilisez le mot-clé **ONCE** dans le rappel, **Remind** vérifie la date du dernier accès au script de rappel. Si elle est identique à la date actuelle, **Remind** suppose qu'il a déjà été exécuté et n'émettra pas les rappels contenant le mot-clé **ONCE**. Notez que si vous visualisez ou modifiez votre script de rappel, la date du dernier accès sera mise à jour, et le mot-clé **ONCE** ne fonctionnera pas correctement. Vous pouvez corriger cela en définissant un fichier d'horodatage pour que **Remind** suive la date de dernière exécution ; voir la documentation de **$OnceFile** dans la section **VARIABLES SYSTÈME**. Si vous utilisez l'entrée standard comme fichier d'entrée **Remind**, alors vous *devez* utiliser **$OnceFile** pour que le mot-clé **ONCE** fonctionne correctement. Si vous démarrez **Remind** avec l'option **-o**, alors le mot-clé **ONCE** sera ignoré et tout **$OnceFile** sera ignoré. **OMISSION LOCALE DE JOURS DE LA SEMAINE** La partie **OMIT** de la commande **REM** est utilisée pour « omettre » certains jours lors du comptage du *delta* ou du *back*. Elle est spécifiée à l'aide du mot-clé **OMIT** suivi d'une liste de jours de la semaine. Son action est mieux illustrée par des exemples : REM 1 +1 OMET Sam Dim MSG Événement important Ce rappel est normalement déclenché le premier de chaque mois, ainsi que le jour qui le précède. Cependant, si le premier du mois tombe un dimanche ou un lundi, le rappel est déclenché à partir du vendredi précédent. C'est parce que le *delta* de +1 ne compte pas le samedi ou le dimanche lorsqu'il compte à rebours à partir de la date de déclenchement pour déterminer quel avertissement préalable donner. Comparez cela avec l'utilisation de « ++1 » dans la commande ci-dessus. Dans ce cas, le rappel est déclenché le premier de chaque mois, ainsi que le jour qui le précède. Les jours omis sont comptés. REM 1 -1 OMET Sam Dim MSG Dernier jour ouvrable du mois Encore une fois, dans l'exemple ci-dessus, le *back* de -1 fait normalement que la date de déclenchement est le dernier jour du mois. Cependant, en raison de la clause **OMIT**, si le premier du mois tombe un dimanche ou un lundi, la date de déclenchement est ramenée au vendredi. (Si vous avez omis des jours fériés globalement, le rappel sera également ramené avant eux. Voir « La commande OMIT » pour plus de détails.) Par comparaison, si nous avions utilisé « --1 », le rappel serait déclenché le dernier jour du mois, quelle que soit la clause **OMIT**. Si vous omettez localement des jours de la semaine mais avez également des jours de la semaine omis globalement, alors la liste des jours de la semaine omis est l'union des deux. Considérons cet exemple : OMIT Sam Dim REM 15 OMET Ven Sam MSG Quoi qu'il en soit Dans la commande REM, la liste effective des jours de la semaine omis sera vendredi, samedi et dimanche. **OMISSIONS LOCALES CALCULÉES** La phrase **OMITFUNC** de la commande **REM** vous permet de fournir une fonction qui détermine si une date doit être omise ou non. Notez que **OMITFUNC** doit recevoir uniquement le nom d'une fonction définie par l'utilisateur ; il ne peut pas prendre une expression arbitraire ou le nom d'une fonction intégrée. La fonction reçoit un seul paramètre de type **DATE**, et doit retourner un entier non nul si la date est consont considérés comme « omis » et 0 sinon. Voici un exemple :

        FSET _third(x) (day(x) % 3) || \
                       (wkdaynum(x) == 0) || \
                       (wkdaynum(x) == 6)
        REM OMITFUNC _third AFTER MSG Jour ouvrable divisible par 3

Dans l'exemple ci-dessus, le rappel est déclenché tous les lundis au vendredis dont le numéro du jour du mois est divisible par trois. Voici comment cela fonctionne :

o
La partie OMITFUNC _third fait que tous les jours pour lesquels _third(x) retourne une valeur non nulle sont considérés comme « omis ». Cela fait que tous les jours dont le numéro du jour du mois n'est pas un multiple de trois sont omis. Notez que _third retourne également une valeur non nulle si le jour de la semaine est un dimanche ou un samedi.
o
Le mot-clé AFTER fait que le rappel est déplacé après un bloc de jours omis.

La combinaison de OMITFUNC et du mot-clé AFTER fait que le rappel est émis tous les jours dont le numéro du jour du mois est divisible par trois, mais pas les samedis ou les dimanches.

Notez que si vous utilisez OMITFUNC, un OMIT local est *ignoré*, tout comme *tous les OMITs globaux*. Si vous souhaitez omettre des jours de la semaine spécifiques, votre fonction d'omission devra les tester spécifiquement. Si vous souhaitez prendre en compte le contexte OMIT global, votre fonction d'omission devra le tester explicitement (en utilisant la fonction isomitted()).

Notez qu'une OMITFUNC incorrecte pourrait faire que tous les jours soient considérés comme omis. Pour cette raison, lorsque Remind recherche parmi les jours omis, il termine la recherche après la limite d'itération SATISFY (option de ligne de commande -x).

AJOUT DE DATES DE DÉCLENCHEMENT AU CONTEXTE D'OMISSION

Si le mot-clé ADDOMIT apparaît dans une commande REM, la date de déclenchement (si elle peut être calculée) est automatiquement ajoutée à la liste des OMITs globaux.

La commande :

        REM ... quel qu'il soit ... ADDOMIT MSG Foo

est identique en comportement à la séquence :

        REM ... quel qu'il soit ... SATISFY 1
        IF trigvalid()
            OMIT [trigdate()] MSG Foo
        ENDIF

RAPPELS TEMPORISÉS

Les rappels temporisés sont ceux qui ont un mot-clé AT suivi d'une *heure* et éventuellement de *tdelta* et *trepeat*. L'*heure* peut être spécifiée au format 24 heures, où 0h00 représente minuit, 12h00 représente midi, et 23h59 représente une minute avant minuit. Alternativement, elle peut être spécifiée au format courant « AM/PM » ; dans ce cas, l'heure doit être comprise entre 1 et 12. 12h00 du matin représente minuit, 12h00 de l'après-midi représente midi, et 23h59 représente une minute avant minuit. Les parties « am » et « pm » ne sont pas sensibles à la casse et le « m » est optionnel.

Vous pouvez utiliser un deux-points ou un point pour séparer les heures des minutes. C'est-à-dire que 13h39 et 13.39 sont équivalents.

Remind traite les rappels temporisés de manière spéciale. Si la date de déclenchement d'un rappel temporisé est la même que la date du système actuel, le rappel est mis en file d'attente pour une activation ultérieure. Lorsque Remind a fini de traiter le fichier de rappels, il se met en arrière-plan et active les rappels temporisés lorsque l'heure du système atteint l'heure spécifiée. Notez que si vous utilisez le modificateur NOQUEUE dans la commande REM, cette mise en file d'attente et l'activation en arrière-plan ne sont *pas* effectuées. NOQUEUE est utile si vous souhaitez associer une heure à un rappel (par exemple, dans le calendrier) mais que vous ne souhaitez pas qu'un rappel popup se produise à l'heure spécifiée.

Si la date de déclenchement n'est *pas* la même que la date du système, le rappel n'est pas mis en file d'attente.

Par exemple, le rappel suivant, déclenché chaque jour ouvrable, affichera un message vous disant de partir à 17h00 :

REM Lun Mar Mer Jeu Ven AT 17:00 MSG Il est temps de partir !

Le rappel suivant sera déclenché les jeudis et vendredis, mais ne sera mis en file d'attente que les vendredis :

REM Ven ++1 AT 13:00 MSG Déjeuner à 13h le vendredi.

Le *tdelta* et le *trepeat* ont la même forme qu'un *repeat* et un *delta*, mais sont spécifiés en minutes. Par exemple, ce rappel sera déclenché à 12h00 ainsi que 45 minutes avant :

REM AT 12:00 +45 MSG Exemple

Ce qui suit sera émis à partir de 10h45, toutes les demi-heures jusqu'à 11h45, puis à nouveau à midi.

REM AT 12:00 +75 *30 MSG Exemple2

Le « +75 » signifie que le rappel est émis à partir de 75 minutes avant midi ; en d'autres termes, à 10h45. Le *30 spécifie que le rappel est ensuite à émettre toutes les 30 minutes. Notez que le rappel est toujours émis à l'heure spécifiée, même si le *tdelta* n'est pas un multiple du *trepeat*. L'exemple ci-dessus est donc émis à 10h45, 11h15, 11h45 et 12h00. Notez que dans la spécification de l'heure, il n'y a pas de distinction entre les formes « + » et « ++ » de *tdelta*.

Normalement, Remind émettra les rappels temporisés lors du traitement du script de rappel, en plus de les mettre en file d'attente pour plus tard. Si vous ne souhaitez pas que Remind émette les rappels lors du traitement du script, mais seulement les mette en file d'attente pour plus tard, utilisez l'option de ligne de commande -a. Si vous ne souhaitez pas que les rappels soient mis en file d'attente pour plus tard, utilisez l'option de ligne de commande -q.

Normalement, Remind crée un processus d'arrière-plan pour gérer les rappels mis en file d'attente. Si vous souhaitez que Remind reste au premier plan, utilisez l'option de ligne de commande -f. Ceci est utile, par exemple, dans les scripts .xinitrc, où vous pouvez utiliser la commande :

remind -fa mesrappels &

Ceci garantit que lorsque vous quittez X-Windows, le processus Remind est tué.

AVERTISSEMENT CONCERNANT LES RAPPELS TEMPORISÉS

Note : Si vous utilisez des fonctions ou des variables définies par l'utilisateur (décrites plus loin) dans le corps des rappels temporisés, alors lorsque les rappels temporisés sont activés, les variables et fonctions ont les définitions qui étaient en vigueur à la fin du script de rappel. Ces définitions peuvent ne pas être nécessairement celles qui étaient en vigueur au moment où le rappel a été mis en file d'attente. De plus, le contexte OMIT est celui qui était en vigueur à la fin du script de rappel, ce qui peut ne pas être nécessairement le même qu'au moment où la commande REM a été traitée pour la première fois.

LES MOTS-CLÉS SCHED ET WARN

Le mot-clé SCHED permet un contrôle plus précis sur le déclenchement des rappels temporisés, et le mot-clé WARN permet un contrôle précis sur le déclenchement anticipé de tous les types de rappels. Cependant, la discussion doit être reportée jusqu'à après l'explication des expressions et des fonctions définies par l'utilisateur. Voir la sous-section « PLANIFICATION PRÉCISE » plus loin.

TAG, INFO ET DURATION

Le mot-clé TAG vous permet de « taguer » certains rappels. Cette fonctionnalité est utilisée par certains backends ou systèmes construits autour de Remind, tels que TkRemind. Ces backends ont des règles spécifiques concernant les tags ; consultez leur documentation pour plus de détails.

Le mot-clé TAG est suivi d'un tag composé de 48 caractères maximum. Vous pouvez avoir autant de clauses TAG que vous le souhaitez dans une instruction REM donnée. Un tag peut contenir n'importe quel caractère à l'exception des espaces et des virgules.

Si vous fournissez l'option -y à Remind, tout rappel qui ne possède pas de TAG en aura un synthétisé. Le tag synthétisé consiste en les caractères « __syn__ » suivis de la représentation hexadécimale de la somme MD5 de la ligne de commande REM. Cela vous permet de donner un identifiant plus ou moins unique à chaque commande REM distincte.

Le mot-clé INFO est similaire à TAG mais est destiné à transmettre des métadonnées sur un événement, telles que son emplacement. Les backends auront leurs propres règles concernant les *info_string* qu'ils reconnaissent, et devront ignorer les *info_string* qu'ils ne reconnaissent pas. Notez que INFO doit être suivi d'une chaîne entre guillemets ; vous pouvez inclure des nouvelles lignes dans la chaîne en les fournissant comme « \n ».

Une chaîne INFO doit *être* de la forme « Header: Value ». L'en-tête peut être composé de n'importe quel caractère imprimable, mais ne peut pas contenir d'espaces. La valeur peut être composée de n'importe quel caractère que vous aimez. L'espace ne peut pas apparaître avant le deux-points, mais peut y apparaître après ; cet espace n'est pas considéré comme faisant partie de la valeur. S'il y a plus d'une chaîne INFO pour un rappel donné, il ne peut y avoir de doublons d'en-têtes. La casse est ignorée lors de la détermination si un en-tête est un doublon d'un en-tête existant.

Par exemple, un backend hypothétique pourrait vous permettre de définir l'emplacement et la description d'un rappel comme ceci :

        REM 26 fév 2025 INFO "Emplacement : Salle de réunion #2" \
                        INFO "Description : Examiner les dernières demandes de tirage" \
                        MSG Réunion d'ingénierie

Le mot-clé DURATION n'a de sens que pour les rappels temporisés ; il spécifie la durée d'un événement. Par exemple, si vous avez une réunion de 90 minutes commençant à 13h00, vous pourriez utiliser l'une des options suivantes :

        REM 5 mars 2021 AT 13:00 DURATION 1:30 MSG Réunion
        REM 5 mars 2021 AT 13:00 DURATION 90 MSG Réunion
        REM 5 mars 2021 AT 13:00pm DURATION 1:30 MSG Réunion
        REM 5 mars 2021 AT 13:00pm DURATION 90 MSG Réunion

Pour les rappels de longue durée, il est pratique d'utiliser des expressions pour simplifier l'écriture de DURATION. Par exemple, si vous êtes absent du 20 février 2023 au 23 février 2023 (soit 4 jours au total), vous pourriez écrire :

        REM 20 fév AT 00:00 DURATION [4*24]:00 MSG absent
        REM 20 fév AT 00:00 DURATION [4*24*60] MSG absent

Notez que la *durée* est spécifiée soit comme *heures*:*minutes*, soit simplement comme *minutes* spécifiées par un *entier*.

Si vous spécifiez une durée de 00:00 ou 0, Remind se comporte exactement comme si aucune DURATION n'avait été présente. Bien que les durées spécifiées comme *heures*:*minutes* ressemblent superficiellement à une heure de la journée, ce n'est pas le cas ; le composant *heures* n'est pas limité à la plage 00-23.

SUCRE SYNTAXIQUE POUR REM

La commande REM a du sucre syntaxique pour vous permettre d'exprimer des rappels courants. Les paires de rappels suivantes sont équivalentes :

        REM Premier lundi avril MSG Foo
        REM Lun 1 avril        MSG Foo
        REM Deuxième lundi mai  MSG Bar
        REM Lun 8 mai          MSG Bar
        REM Troisième lundi MSG Troisième lundi de chaque mois
        REM Lun 15 MSG Troisième lundi de chaque mois
        REM Quatrième dimanche juin 2025 MSG Quatrième dimanche de juin 2025
        REM Dim 22 juin 2025 MSG Quatrième dimanche de juin 2025
        REM Dernier lundi MSG Dernier lundi de chaque mois
        REM Lun 1 --7 MSG Dernier lundi de chaque mois
        REM Dernier lundi avril MSG Dernier lundi de chaque avril
        REM Lun 1 mai --7 MSG  Dernier lundi de chaque avril
        REM Dernier lundi décembre 2025 MSG Dernier lundi de dé
c 2025 REM Lundi 1 jan 2026 --7 MSG Dernier lundi de déc. 2025

Notez que Last ajuste effectivement le mois et l'année, si nécessaire, pour que le rappel se déclenche à la bonne date.

Le mot-clé IN est complètement ignoré, vous pouvez donc écrire (par exemple) :

        REM Second Monday in May MSG foo
        REM Last Monday in December 2025 MSG Bar

Une forme alternative de back facilite l'écriture des rappels. Les groupes de rappels suivants sont équivalents :

        REM ~~1 MSG Dernier jour de chaque mois
        REM Lastday MSG Dernier jour de chaque mois
        REM 1 --1 MSG Dernier jour de chaque mois
        REM May ~~1 MSG Dernier jour de mai
        REM Lastday May MSG Dernier jour de mai
        REM 1 June --1 MSG Dernier jour de mai
        REM Dec 2025 ~~1 MSG Dernier jour de décembre 2025
        REM Lastday Dec 2025 MSG Dernier jour de décembre 2025
        REM 1 Jan 2026 --1 MSG Dernier jour de décembre 2025
        REM Apr ~1 OMIT SAT SUN MSG Dernier jour ouvrable d'avril
        REM Lastworkday April OMIT SAT SUN MSG Dernier jour ouvrable d'avril
        REM 1 May -1 OMIT SAT SUN MSG Dernier jour ouvrable d'avril
        REM Apr ~~7 MSG Septième jour avant la fin d'avril
        REM 1 May --7 MSG Septième jour avant la fin d'avril
        REM Apr ~2 OMIT SAT SUN MSG Deuxième jour ouvrable avant la fin d'avril
        REM 1 May -2 OMIT SAT SUN MSG Deuxième jour ouvrable avant la fin d'avril

Comme nous le voyons, "Lastday" équivaut à ~~1 et "Lastworkday" à ~1.

Notez que les mots-clés First/Second/Third/Fourth/Last et la forme ~ et ~~ de back impliquent une valeur pour le jour du mois ; en tant que tels, ils ne peuvent pas être combinés avec un jour. De plus, First/Second/Third/Fourth/Last doivent avoir au moins un nom de jour de la semaine. Les exemples suivants sont illégaux :

        REM First Monday 3 June MSG Huh?
        REM April 3 ~~1 MSG What?
        REM Second June MSG Where's the weekday???

LE FILTRE DE SUBSTITUTION

Avant d'être traité, le corps d'une commande REM est passé à travers un filtre de substitution. Le filtre recherche les séquences "%x" (où "x" est une lettre et certains autres caractères) et effectue les substitutions comme indiqué ci-dessous. (Toutes les dates se réfèrent à la date de déclenchement du rappel.)

%a
est remplacé par "le jour_semaine, jour mois, année"
Par exemple, considérez le rappel :

REM 18 Oct 1990 +4 MSG Meeting with Bob %a.

Le 16 octobre 1990, il afficherait "Meeting with Bob le jeudi 18 octobre 1990."

Le 17 octobre 1990, il afficherait "Meeting with Bob demain."

Le 18 octobre 1990, il afficherait "Meeting with Bob aujourd'hui."

%b
est remplacé par "dans diff jour(s)" où diff est le nombre réel de jours entre la date actuelle et la date de déclenchement. (Les OMITs n'ont aucun effet.)
Par exemple, considérez :

REM 18 Oct 1990 +4 MSG Meeting with Bob %b.

Le 16 octobre 1990, il afficherait "Meeting with Bob dans 2 jours."

Le 17 octobre 1990, il afficherait "Meeting with Bob demain."

Le 18 octobre 1990, il afficherait "Meeting with Bob aujourd'hui."

%c
est remplacé par "le jour_semaine"
Exemple : REM 18 Oct 1990 +4 MSG Meeting with Bob %c.

Le 16 octobre 1990, il afficherait "Meeting with Bob le jeudi."

Le 17 octobre 1990, il afficherait "Meeting with Bob demain."

Le 18 octobre 1990, il afficherait "Meeting with Bob aujourd'hui."

%d
est remplacé par "jour", le jour du mois.
%e
est remplacé par "le jj-mm-aaaa"
%f
est remplacé par "le mm-jj-aaaa"
%g
est remplacé par "le jour_semaine, jour mois"
%h
est remplacé par "le jj-mm"
%i
est remplacé par "le mm-jj"
%j
est remplacé par "le jour_semaine, mois jour-ème, année" Cette forme ajoute les caractères "er", "nd", "rd" ou "ème" au jour du mois, selon le cas.
%k
est remplacé par "le jour_semaine, mois jour-ème"
%l
est remplacé par "le aaaa-mm-jj"
%m
est remplacé par "mois", le nom du mois.
%n
est remplacé par le numéro (1 à 12) du mois.
%o
est remplacé par " (aujourd'hui)" si et seulement si la date système actuelle est la même que la date utilisée par Remind comme date actuelle. Rappelez-vous que vous pouvez spécifier une date pour Remind sur la ligne de commande. Cette substitution n'est généralement pas utile dans une commande REM, mais est utile dans une commande BANNER. (Voir "La Commande BANNER".")
%p
est remplacé par "s" si la différence entre la date actuelle et la date de déclenchement n'est pas 1. Vous pouvez l'utiliser pour construire des rappels comme :
REM 1 Jan +4 MSG %x day%p to go before New Year!
%q
est remplacé par "'s" si la différence entre la date de déclenchement et la date actuelle est de 1. Sinon, il est remplacé par "s'". Ceci peut être utilisé comme suit :
REM 1 Jan +4 MSG New Year in %x day%q time!
%r
est remplacé par le jour du mois (01 à 31) avec un zéro initial si nécessaire pour obtenir deux chiffres.
%s
est remplacé par "er", "nd", "rd" ou "ème" en fonction du jour du mois.
%t
est remplacé par le numéro du mois (01 à 12) complété à deux chiffres avec un zéro initial.
%u
est remplacé par "le jour_semaine, jour-ème mois, année" Ceci est similaire à %a sauf que "er", "nd", "rd" ou "ème" est ajouté au jour selon le cas.
%v
est remplacé par "le jour_semaine, jour-ème mois"
%w
est remplacé par "jour_semaine", le nom du jour de la semaine.
%x
est remplacé par la différence entre la date actuelle et la date de déclenchement. La différence est définie comme le nombre réel de jours entre ces deux dates ; les OMITs ne sont pas comptés. (Une soustraction stricte de dates est effectuée.)
%y
est remplacé par "année", l'année de la date de déclenchement.
%z
est remplacé par "aa", les deux derniers chiffres de l'année.
%(any_text)
est remplacé par la recherche de any_text dans la table de traduction. C'est l'équivalent de [_("any_text")] mais plus pratique à taper.
%<any_text>
est remplacé par la valeur INFO associée à l'en-tête any_text ou la chaîne vide si aucune valeur INFO de ce type n'existe. C'est l'équivalent de [triginfo("any_text")] mais plus pratique à taper.
%_
(pourcentage-underscore) est remplacé par un saut de ligne. Vous pouvez l'utiliser pour obtenir des rappels sur plusieurs lignes. Notez que les backends de calendrier varient dans leur gestion des rappels sur plusieurs lignes :
o
L'exécution de remind -c conserve les sauts de ligne dans la sortie du calendrier du terminal.
o
rem2pdf conserve les sauts de ligne si remind est appelé avec l'option -pp ou -ppp.
o
rem2html conserve les sauts de ligne si remind est appelé avec l'option -pp.
o
tkremind conserve les sauts de ligne.
o
rem2ps convertit les sauts de ligne en espaces. Mais rem2ps est déprécié ; utilisez rem2pdf à la place.
o
Les formats "calendrier simple" (c'est-à-dire, les options -s, -n et -p de remind) convertissent les sauts de ligne en espaces.

Tous les backends de calendrier réduisent les espaces multiples à un seul espace et les sauts de ligne multiples à un seul saut de ligne.

%1
est remplacé par "maintenant", "dans m minutes", "il y a m minutes", "dans h heures", "il y a h heures", "dans h heures et m minutes" ou "il y a h heures et m minutes", selon le cas pour un rappel chronométré. Notez que sauf si vous spécifiez l'option -a, les rappels chronométrés se déclencheront comme des rappels normaux, et donc un rappel chronométré qui s'est produit plus tôt dans la journée peut se déclencher. Cela explique le besoin des formes "...ago".
%2
est remplacé par "à hh:mmam" ou "..pm" selon l'heure AT du rappel.
%3
est remplacé par "à hh:mm" au format 24 heures.
%4
est remplacé par "mm" où mm est le nombre de minutes entre "maintenant" et l'heure spécifiée par AT. Si l'heure AT est antérieure à l'heure actuelle, le résultat est négatif.
%5
est remplacé par "ma" où ma est la valeur absolue du nombre produit par %4.
%6
est remplacé par "ago" (il y a) ou "from now" (dans), en fonction de la relation entre l'heure AT et l'heure actuelle.
%7
est remplacé par le nombre d'heures entre l'heure AT et l'heure actuelle. Il est toujours non négatif.
%8
est remplacé par le nombre de minutes entre l'heure AT et l'heure actuelle, après que les heures (%7) aient été soustraites. C'est un nombre compris entre 0 et 59.
%9
est remplacé par "s" si la valeur produite par %8 n'est pas 1.
%0
est remplacé par "s" si la valeur produite par %7 n'est pas 1.
%!
est remplacé par "is" (est) si la date et l'heure actuelles sont avant la date de déclenchement et l'heure AT, ou "was" (était)
si c'est après. La séquence %! peut être utilisée dans un rappel non programmé, auquel cas seules les dates sont comparées.
%?
est remplacé par « sont » si la date et l'heure actuelles sont antérieures à la date et l'heure de déclenchement, ou « étaient » si elles sont postérieures. La séquence %? peut être utilisée dans un rappel non programmé, auquel cas seules les dates sont comparées.
%@
est similaire à %2 mais affiche l'heure actuelle.
%#
est similaire à %3 mais affiche l'heure actuelle.
%:
est remplacé par « (fait) » pour un rappel TODO dont la date de déclenchement est égale ou postérieure à sa date de FIN-COMPLETE. Il est remplacé par la chaîne vide dans toute autre situation. Notez que, comme Remind n'affiche pas les rappels TODO terminés en mode Agenda, cette séquence d'échappement est vraiment utile uniquement en mode Calendrier.
%"
(pourcent-guillemet double) est supprimé. Cette séquence n'est pas utilisée par le filtre de substitution, mais elle est utilisée pour indiquer à Remind quel texte inclure dans une entrée de calendrier lorsque l'option -c, -s ou -p est choisie. Voir « MODE CALENDRIER ».

Notes :

o
Remind imprime normalement une ligne vide après chaque rappel ; si le dernier caractère du corps est « % », la ligne vide ne sera pas imprimée. Vous pouvez supprimer globalement les lignes vides supplémentaires en définissant $AddBlankLines sur 0.
o
Les substitutions a, b, c, e, f, g, h, i, j, k, l, u et v sont toutes remplacées par « aujourd'hui » si la date actuelle est égale à la date de déclenchement, ou par « demain » si la date de déclenchement est un jour après la date actuelle. Ainsi, elles ne sont pas identiques aux substitutions construites à partir des séquences plus simples %w, %y, etc.
o
Les substitutions a, c, e, f, g, h, i, j, k, l, u, v, 2 et 3 peuvent être précédées d'un astérisque (par exemple, %*c) ce qui fait que le mot « à » ou « le » qui serait normalement inclus dans la sortie est omis.
o
Les substitutions ! et ? peuvent être précédées d'un astérisque (%*! ou %*?), auquel cas la comparaison est effectuée entre la date de déclenchement et realtoday() au lieu de today().
o
Toute substitution traitant de l'heure (0 à 9) produit des résultats indéfinis si elle est utilisée dans un rappel qui n'a pas de mot-clé AT. De plus, si un rappel a un delta et peut être déclenché plusieurs jours, les substitutions d'heure ignorent la date. Ainsi, la substitution %1 peut indiquer qu'une réunion est dans 15 minutes, par exemple, même si elle n'est que dans 2 jours, car un delta a déclenché le rappel. Il est recommandé d'utiliser les substitutions d'heure uniquement dans les rappels programmés sans delta et conçus pour être mis en file d'attente pour une activation programmée.
o
Les lettres majuscules peuvent être utilisées dans la séquence de substitution, auquel cas le premier caractère de la chaîne substituée est capitalisé (s'il s'agit normalement d'une lettre minuscule).
o
Tous les autres caractères suivant un signe « % » sont simplement copiés. En particulier, pour obtenir un signe « % », utilisez « %% » dans le corps. Pour commencer le corps d'un rappel par un espace, utilisez « % » car Remind recherche normalement le premier caractère non blanc après un jeton MSG, CAL ou RUN.

ÉVÉNEMENTS ET TODO

La commande REM est normalement utilisée pour créer un ÉVÉNEMENT. C'est quelque chose qui se produit à un moment donné, éventuellement récurrent, et qui se produit quelle que soit l'action que vous entreprenez. Les événements incluent des choses comme les anniversaires, les fêtes, les réunions, etc... pratiquement tout ce qui se produit selon un calendrier particulier. Une fois que la date d'un événement est passée, Remind ne vous rappellera plus cet événement.

Un TODO est différent ; c'est une tâche que vous devez accomplir avant une date ou une date et heure spécifiques. Si vous ne marquez pas explicitement un TODO comme terminé, Remind continuera à vous le rappeler, même après la date d'échéance..

Pour marquer un REM comme un TODO, incluez simplement le mot-clé TODO. Par exemple :

    REM TODO 15 août 2025 ++5 MSG Acheter nourriture pour chat %b.

En mode Agenda, Remind commencera à vous avertir le 10 août 2025 que vous devez acheter de la nourriture pour chat dans 5 jours, puis 4 jours, etc...

Cependant, le 16 août 2025, Remind dira « Achetez la nourriture pour chat hier. » et continuera à vous rappeler votre besoin d'acheter de la nourriture pour chat jusqu'à la fin des temps, ou jusqu'à ce que vous marquiez le TODO comme terminé.

MARQUAGE DES TODOS COMME FAITS

Il existe deux façons de marquer un TODO comme terminé. Si le TODO n'est pas récurrent, le moyen le plus simple est simplement de supprimer le désignateur TODO de la commande REM (ou même de le supprimer complètement). La première option conserve le rappel dans le calendrier tandis que la seconde le supprime complètement.

Si un TODO est récurrent, utilisez la clause COMPLETE-THROUGH pour marquer quelles récurrences ont été complétées. Par exemple :

    REM TODO 30 avril ++15 COMPLETE-THROUGH 2025-04-30 MSG Déclarer impôts

Les impôts canadiens doivent être déclarés chaque 30 avril. La commande ci-dessus vous rappellera de payer vos impôts en 2026. Si vous ne mettez pas à jour la date COMPLETE-THROUGH, alors après le 30 avril 2026, Remind continuera à vous rappeler jusqu'à la fin des temps que vos impôts étaient dus le 30 avril 2026. Pour indiquer que vous les avez payés, mettez simplement à jour la date COMPLETE-THROUGH à 2026-04-30 et alors Remind commencera à vous rappeler vos impôts de 2027 (en commençant 15 jours avant la date d'échéance).

Il est erroné de spécifier COMPLETE-THROUGH sans spécifier également TODO.

LIMITATION DES RAPPELS CONCERNANT LES TODOS EN RETARD

Bien que Remind soit heureux de continuer à vous rappeler les TODOs en retard pendant des centaines d'années, pour certaines choses cela peut être inutile. Si vous voulez que Remind cesse de vous harceler à propos d'un TODO en retard après un certain nombre de jours, utilisez la clause MAX-OVERDUE n. Dans ce cas, Remind arrête de vous rappeler un TODO qui est en retard de plus de n jours. Voici un exemple.

    REM TODO 2025-08-13 ++5 MAX-OVERDUE 5 MSG Tâche : %b.

Remind commence à vous rappeler la tâche le 2025-08-08, en raison de la valeur arrière ++5. Il continue à vous rappeler la tâche après la date d'échéance. Cependant, la dernière fois qu'il vous le rappellera sera le 2025-08-18, en raison de la clause MAX-OVERDUE. À partir du 2025-08-19, Remind ne vous rappellera plus la tâche car c'est probablement inutile - elle a dépassé la période MAX-OVERDUE.

PLUS DE DÉTAILS SUR LES TODOS

Les TODOs sont traités spécialement uniquement en mode Agenda. En mode Calendrier, ils apparaissent dans le calendrier exactement comme un événement normal.

Les TODOs sont implémentés en interne en utilisant la date COMPLETE-THROUGH plus un jour comme point de départ pour l'algorithme de balayage de date de Remind. Si vous avez un TODO récurrent sans clause COMPLETE-THROUGH, alors Remind commence à scanner depuis le début des temps, ce que nous savons tous être le 1er janvier 1990. Considérez cette commande :

    REM TODO Mer +7 MSG Sortir les poubelles %a (%b)

Exécuter cette commande en mode Agenda le 2025-08-13 donne le résultat suivant :

    Sortir les poubelles le mercredi 3 janvier 1990 (il y a 13006 jours)

Remind est très persistant pour vous rappeler les tâches ! Si vous sortez les poubelles et les marquez comme terminées :

    REM TODO Mer +7 COMPLETE-THROUGH 2025-08-13 MSG Sortir les poubelles %a (%b)

alors vous obtenez ceci :

    Sortir les poubelles le mercredi 20 août 2025 (dans 7 jours)

Vous pouvez utiliser FROM et UNTIL pour limiter l'intervalle de récurrence des tâches comme vous le pouvez avec les événements. Par exemple, si vous gardez des animaux pour le mois d'août et que vous devez arroser les plantes tous les mercredis :

    REM TODO Mer +7 FROM 2025-08-06 UNTIL 2025-08-27 MSG Plantes %b.

Exécuter cette commande le 13 août donne : « Plantes il y a 7 jours. » car vous n'avez pas dit à Remind que vous avez terminé le premier arrosage. Si vous terminez vos tâches et ajoutez une date COMPLETE-THROUGH de 2025-08-27, alors Remind ne vous rappellera jamais cette tâche à l'avenir.

En mode Purge, Remind ne purgera pas les TODOs sauf s'ils ont été marqués comme terminés. Dans le cas d'un TODO récurrent, Remind ne le purgera pas tant que la dernière occurrence n'aura pas été marquée comme terminée.

LA COMMANDE OMIT

En plus d'être un mot-clé dans la commande REM, OMIT est une commande à part entière. Sa syntaxe est :

OMIT jour_de_la_semaine [jour_de_la_semaine...]

ou :

OMIT [jour] mois [année]

ou :

OMIT [jour1] mois1 [année1] THROUGH [jour2] mois2 [année2]

La commande OMIT est utilisée pour omettre « globalement » certains jours (généralement les jours fériés). Ces jours globalement omis sont ignorés par les formes « - » et « + » de back et delta, mais pas par les formes « -- » et « ++ ». Quelques exemples :

    OMIT Samedi Dimanche
    OMIT 1 Jan
    OMIT 7 Sep 1992
    OMIT 15 Jan THROUGH 14 Fev
    OMIT Mai     # Équivalent à OMIT Mai 1 THROUGH Mai 31
    OMIT 25 Déc THROUGH 4 Jan
    OMIT 2023-05-03 THROUGH 2023-05-12
    OMIT Juin THROUGH Juillet  # Équivalent à OMIT Juin 1 THROUGH Juil 31

Le premier exemple omet chaque samedi et dimanche. C'est utile pour les rappels qui ne devraient pas se déclencher le week-end.

Le deuxième exemple spécifie un jour férié qui tombe à la même date chaque année - le jour de l'An.

Le troisième exemple spécifie un jour férié qui change chaque année - le jour de la Fête du Travail. Pour ces types de jours fériés, vous devez créer une commande OMIT pour chaque année. (Plus tard, dans la description des expressions et de certaines des fonctionnalités plus avancées de Remind, vous verrez comment automatiser cela pour certains cas.)

Comme pour la commande REM, vous pouvez utiliser des spécificateurs abrégés pour les dates ; les suivants sont équivalents :

OMIT 7 Sep 1992
OMIT 1992-09-07

Pour plus de commodité, vous pouvez utiliser un mot-clé delta et MSG ou RUN dans la commande OMIT. Les séquences suivantes sont équivalentes :

OMIT 1 Jan
REM 1 Jan +4 MSG Le jour de l'an est %b!
et
OMIT 1 Jan +4 MSG Le jour de l'an est %b!

Le mot-clé THROUGH vous permet d'OMIT une plage de jours de manière pratique. Par exemple, les séquences suivantes sont équivalentes :

OMIT 3 Jan 2011
OMIT 4 Jan 2011
OMIT 5 Jan 2011
et
OMIT 3 Jan 2011 THROUGH 5 Jan 2011

Notez que Remind a une limite intégrée au nombre d'OMIT complets. Si vous omettez une plage de N jours entièrement spécifiés (c'est-à-dire avec l'année incluse), alors N OMIT complets sont utilisés. Essayer d'omettre une plage très large peut entraîner l'erreur « Trop d'OMIT complets »

Vous pouvez faire en sorte qu'un OMIT THROUGH serve également de commande REM tant que les deux dates sont entièrement spécifiées

OMIT 6 Sep 2010 THROUGH 10 Sep 2010 MSG Vacances

Si vous utilisez une clause THROUGH, l'année doit être fournie avant et après le THROUGH, ou elle doit être manquante avant et après le THROUGH. Les exemples suivants sont valides :

    OMIT 25 Dec THROUGH 6 Jan
    OMIT 25 Dec 2024 THROUGH 6 Jan 2025

Mais les exemples suivants ne le sont pas :

    OMIT 25 Dec THROUGH 6 Jan 2025
    OMIT 25 Dec 2024 THROUGH 6 Jan

Vous pouvez déboguer vos OMIT globaux avec la commande suivante :
	OMIT DUMP

La commande OMIT DUMP imprime les omits globaux actuels sur la sortie standard.

LES MOTS-CLÉS BEFORE, AFTER ET SKIP

Normalement, les jours qui sont omis, que ce soit par une commande globale OMIT ou par les mots-clés locaux OMIT ou OMITFUNC dans une instruction REM, n'affectent que le comptage du -back ou du +delta. Par exemple, supposez que vous avez une réunion tous les mercredis. Supposez également que vous avez indiqué le 11 novembre comme jour férié :

OMIT 11 Nov +4 MSG Jour du Souvenir
REM Mer +1 MSG Réunion de code %b.

La séquence ci-dessus émettra un rappel concernant une réunion le 11 novembre 1992, qui est un mercredi. C'est probablement incorrect. Il existe trois options :

BEFORE
Ce mot-clé déplace le rappel avant les jours omis. Ainsi, dans l'exemple ci-dessus, l'utilisation de BEFORE provoquerait le déclenchement du rappel de réunion le mardi 10 novembre 1992.
AFTER
Ce mot-clé déplace le rappel après les jours omis. Dans l'exemple ci-dessus, le rappel de réunion serait déclenché le jeudi 12 novembre 1992.
SKIP
Ce mot-clé provoque l'omission complète du rappel les jours omis. Ainsi, dans l'exemple ci-dessus, le rappel ne serait pas déclenché le 11 novembre 1992. Cependant, il serait déclenché comme d'habitude le mercredi suivant, le 18 novembre 1992.

Les mots-clés BEFORE et AFTER déplacent la date de déclenchement d'un rappel avant ou après un bloc de jours omis, respectivement. Supposez que vous effectuez normalement une sauvegarde le premier jour du mois. Cependant, si le premier jour du mois est un week-end ou un jour férié, vous effectuez la sauvegarde le premier jour ouvrable suivant le week-end ou le jour férié. Vous pourriez utiliser :

REM 1 OMIT Sat Sun AFTER RUN do_backup

Examinons comment la date de déclenchement est calculée. Le 1 spécifie le premier jour du mois. Le mot-clé local OMIT provoque le déplacement du rappel AFTER pour passer les week-ends. Enfin, le mot-clé AFTER continuera de déplacer le rappel jusqu'à ce qu'il ait passé tous les jours fériés spécifiés par des commandes OMIT globales.

SUPPORT DE FUSEAU HORAIRE

La commande REM prend en charge un mot-clé optionnel TZ, qui doit être suivi du nom du fuseau horaire sensible à la casse dans lequel la commande doit être interprétée. Notez que si vous utilisez le mot-clé TZ, vous devez également utiliser une clause AT. Voici quelques exemples :

    REM Wednesday AT 14:00 TZ America/Toronto MSG 14h00 heure de l'Est (%2).
    REM Wednesday AT 23:59 TZ America/Los_Angeles SATISFY [$Td == 13] MSG Foo %b %2.

Dans une clause SATISFY et une fonction OMITFUNC, toutes les fonctions de déclenchement et la date de déclenchement sont interprétées dans le fuseau horaire spécifié dans la commande REM. En dehors de la commande REM, cependant, les fonctions de déclenchement sont ajustées au fuseau horaire local. Si le fuseau horaire local est UTC et que nous fournissons à Remind le fichier suivant le 2025-09-04 UTC :

    SET $AddBlankLines 0
    BANNER %
    REM Wednesday AT 14:00 TZ America/Toronto MSG 14h00 heure de l'Est (%2).
    set a $T
    set b $Tt
    REM MSG a = [a], b = [b]
    REM Wednesday AT 23:59 TZ America/Los_Angeles SATISFY [$Td == 13] MSG Foo %b %2.
    set c $T
    set d $Tt
    REM MSG c = [c], d = [d]

Alors la sortie est la suivante :

    a = 2025-09-10, b = 18:00
    c = 2026-05-14, d = 06:59

C'est parce que la date de déclenchement de la première (mercredi 2025-09-10 à 14:00 heure de l'Est) est le 2025-09-10 à 18:00 UTC. Dans le second cas, le mercredi 13 mai 2026 est la date de déclenchement SATISFIED, qui est ajustée au jeudi 14 mai 2026 à 06:59 UTC en raison de l'ajustement du fuseau horaire.

Si vous utilisez un nom de fuseau horaire invalide après le mot-clé TZ, les résultats ne sont pas définis. Malheureusement, Remind ne peut pas diagnostiquer cette erreur car la fonction tzset() de la bibliothèque C n'a pas de retour d'erreur.

Dans un rappel avec le mot-clé TZ, les dates OMIT sont évaluées dans le fuseau horaire spécifié. Voici un exemple : Supposons que le fuseau horaire local soit America/Toronto et que vous ayez ce script :

    # Un vendredi
    OMIT 2025-09-05
    # Un samedi
    OMIT 2025-09-13
    REM Saturday AT 01:00 TZ Europe/Amsterdam SKIP MSG Early Sat AM

Le 2025-09-05 dans le fuseau horaire America/Toronto, le rappel se déclenchera bien. Même si le 2025-09-05 a été omis, le mot-clé SKIP évalue la date dans le fuseau horaire Europe/Amsterdam, et le 2025-09-06 (date de déclenchement) n'est pas omis.

Inversement, le 2025-09-12 dans le fuseau horaire America/Toronto, le rappel ne se déclenchera pas. Même si le 2025-09-12 n'est pas omis, le 2025-09-13 l'est, et c'est la date de déclenchement dans le fuseau horaire Europe/Amsterdam.

LES COMMANDES DO, INCLUDE ET SYSINCLUDE

Remind vous permet d'inclure d'autres fichiers dans votre script de rappel, similaire à la directive #include du préprocesseur C. Par exemple, vous pourriez organiser différents rappels dans différents fichiers comme ceci :

        INCLUDE holidays.rem
        INCLUDE birthdays.rem
        INCLUDE "quote files with spaces.rem"

Les fichiers INCLUDE peuvent être imbriqués jusqu'à une profondeur de 8. Comme indiqué ci-dessus, si un nom de fichier contient des espaces (déconseillé !), vous pouvez utiliser des guillemets doubles autour du nom de fichier.

Si vous spécifiez un nom de fichier de « - » dans la commande INCLUDE, Remind commencera à lire depuis l'entrée standard.

Si vous spécifiez un répertoire comme argument pour INCLUDE, alors Remind traitera tous les fichiers (mais pas les sous-répertoires !) de ce répertoire qui correspondent au modèle shell « *.rem ». Les fichiers sont traités dans l'ordre trié ; l'ordre de tri correspond à celui utilisé par le shell lorsqu'il développe « *.rem ».

Notez que le fichier spécifié par une commande INCLUDE est interprété par rapport au répertoire de travail actuel du processus Remind. Si vous souhaitez inclure un fichier par rapport au répertoire contenant le fichier en cours de traitement, utilisez plutôt DO. Par exemple, si le fichier actuel est /home/user/.reminders/foo.rem et que le répertoire de travail de Remind est /home/user, alors :

    # Lire /home/user/.reminders/bar.rem
    DO bar.rem
    # Lire /usr/share/bar.rem - chemin absolu
    DO /usr/share/bar.rem
    # Lire /home/user/bar.rem
    INCLUDE bar.rem
    # Lire /usr/share/bar.rem - chemin absolu
    INCLUDE /usr/share/bar.rem

On pourrait argumenter que la commande INCLUDE aurait dû fonctionner comme DO dès le départ, mais la modifier aurait rompu la compatibilité ascendante, d'où l'introduction de DO.

Notez que si le fichier de rappels actuellement traité a été spécifié comme un lien symbolique vers un fichier qui ne se trouve pas dans le même répertoire que le lien symbolique lui-même, DO échouera. Remind ne résout pas le chemin réel des liens symboliques, vous devriez donc éviter d'utiliser des liens symboliques vers des fichiers.

La commande SYSINCLUDE est similaire à DO, mais elle recherche les noms de chemin relatifs sous le répertoire système contenant les scripts de rappel standard. Pour cette installation de Remind, le répertoire système est « /usr/share/remind ».

LA COMMANDE RETURN

La commande RETURN fait en sorte que Remind ignore le contenu restant du fichier actuellement traité. Elle peut être utilisée comme un moyen rapide de « sortir » d'un fichier inclus (bien qu'elle fonctionne également au niveau supérieur).

Voici un exemple d'utilisation de RETURN :

        IF already_done
            RETURN
        ENDIF
        set already_done 1
        preserve already_done
        # Effectuer un traitement coûteux ici

LA COMMANDE RUN

Si vous incluez d'autres fichiers dans votre script de rappel, vous ne pourrez peut-être pas toujours faire entièrement confiance au contenu de ces autres fichiers. Par exemple, ils peuvent contenir des rappels de type RUN qui pourraient être utilisés pour accéder à vos fichiers ou effectuer des actions indésirables. La commande RUN peut restreindre cela : si vous incluez la commande RUN OFF dans votre script de rappel principal, tout rappel ou expression qui exécuterait normalement une commande système sera désactivé. RUN ON réactivera l'exécution des commandes système. Notez que la commande RUN ON ne peut être utilisée que dans votre script de rappel principal ; elle ne fonctionnera pas dans les fichiers accessibles par la commande INCLUDE. Ceci afin de vous protéger contre quelqu'un plaçant une commande RUN ON dans un fichier inclus. Cependant, la commande RUN OFF peut être utilisée au niveau supérieur ou dans un fichier inclus.

Si vous exécutez Remind avec l'option de ligne de commande -r, les rappels de type RUN et la fonction shell() seront désactivés, quelle que soit la commande RUN dans le script de rappel. Cependant, toute commande fournie avec l'option -k sera toujours exécutée.

De plus, Remind contient quelques autres fonctionnalités de sécurité. Il ne lira pas un fichier qui est inscriptible par le groupe ou par tout le monde. Il ne sera pas exécuté set-uid. S'il lit un fichier qui ne vous appartient pas, il désactivera RUN a

nd the fonction shell(). Et s'il est exécuté en tant que root, il ne lira que les fichiers appartenant à root.

Notez que si Remind lit l'entrée standard, il n'essaie pas de vérifier la propriété de l'entrée standard, même si elle provient d'un fichier, et donc ne désactive pas RUN et shell() dans cette situation.

LA COMMANDE EXPR

Remind vous permet de désactiver complètement l'évaluation des expressions. Cela pourrait être utile si vous exécutez Remind sur un fichier quelque peu non fiable qui ne devrait pas contenir d'expressions. Pour désactiver l'évaluation des expressions, utilisez :

        EXPR OFF

Si Remind rencontre une expression alors que EXPR OFF est en vigueur, il renvoie une erreur

Pour réactiver l'évaluation des expressions, utilisez :

        EXPR ON

Comme pour RUN ON, EXPR ON ne peut être utilisé que dans le script de niveau supérieur, pas dans un fichier inclus.

LA COMMANDE INCLUDECMD

Remind vous permet d'exécuter une commande shell et d'évaluer la sortie de cette commande comme s'il s'agissait d'un fichier inclus. Par exemple, vous pourriez avoir des scripts qui extraient des rappels d'une base de données et les impriment sur stdout sous forme de commandes REM. Voici un exemple :

INCLUDECMD extract_reminders_for dfs

Nous supposons que la commande "extract_reminders_for" extrait les rappels d'une base de données centrale pour l'utilisateur nommé. Une autre utilisation de INCLUDECMD est si vous avez vos rappels stockés dans un fichier dans un format non-Remind ; vous pouvez écrire une commande qui les transforme au format Remind et ensuite Remind peut "inclure" le fichier avec une commande INCLUDECMD appropriée.

Notez que si RUN est désactivé, alors INCLUDECMD échouera avec le message d'erreur "RUN disabled"

INCLUDECMD transmet le reste de la ligne à popen(3), ce qui signifie que la commande est exécutée par le shell. En tant que tel, les métacaractères du shell peuvent nécessiter une échappement ou le guillemet des arguments, selon ce que vous essayez de faire. Remind lui-même n'effectue aucune modification de la ligne de commande (à part le mécanisme normal de collage d'expressions [expr]).

Si la commande passée à INCLUDECMD commence par un point d'exclamation "!", alors Remind désactive RUN pour la sortie de la commande. Si vous exécutez une commande dont vous n'êtes pas tout à fait sûr de la sortie, vous devriez la préfixer par "!" afin que toutes les commandes RUN qu'elle émet échouent.

Une commande INCLUDECMD compte dans la profondeur de imbrication INCLUDE. Pour une exécution donnée de Remind, une commande INCLUDECMD donnée n'est exécutée qu'une seule fois et les résultats sont mis en cache. Par exemple, si vous générez un calendrier, chaque commande INCLUDECMD unique sera exécutée une seule fois, pas une fois pour chaque jour du calendrier produit. "Unicité" est déterminée en examinant la commande qui sera passée au shell, donc si (par exemple) votre INCLUDECMD utilise le collage d'expressions qui aboutit à des différences en fonction de la valeur de today(), alors chaque version unique de la commande sera exécutée une fois.

Si un fichier de rappel donné contient plus d'une INCLUDECMD identique, seule la première sera effectivement exécutée. Toutes les commandes identiques ultérieures utiliseront la sortie mise en cache de la première.

LA COMMANDE BANNER

Lorsque Remind émet un rappel pour la première fois, il affiche un message comme celui-ci :

Rappels pour Vendredi, 30 Octobre 1992 (aujourd'hui) :

(La bannière n'est pas affichée si l'une des options de production de calendrier est utilisée, ou si l'option -k est utilisée.)

La commande BANNER vous permet de changer le format. Elle doit apparaître avant toute commande REM. Le format est :

BANNER format

Le format est similaire au corps d'une commande REM. Il est passé par le filtre de substitution, avec un déclencheur implicite de la date système actuelle. Ainsi, la bannière par défaut est équivalente à :

BANNER Rappels pour %w, %d%s %m, %y%o :

Vous pouvez désactiver complètement la bannière avec BANNER %. Ou vous pouvez créer une bannière personnalisée :

BANNER Salut - voici vos rappels pour %y-%t-%r :

CONTROLE DU CONEXTE OMIT

Parfois, il est nécessaire de modifier temporairement les OMITs globaux qui sont en vigueur pour quelques rappels. Trois commandes le permettent :

PUSH-OMIT-CONTEXT
Cette commande enregistre les OMITs globaux actuels sur une pile interne.
CLEAR-OMIT-CONTEXT
Cette commande efface tous les OMITs globaux, vous offrant une "ardoise vierge".
POP-OMIT-CONTEXT
Cette commande restaure les OMITs globaux qui ont été sauvegardés par le plus récent PUSH-OMIT-CONTEXT.

Par exemple, supposons que vous ayez un bloc de rappels qui nécessitent un contexte OMIT clair, et qu'ils introduisent également des OMITs globaux indésirables qui pourraient interférer avec des rappels ultérieurs. Vous pourriez utiliser le fragment suivant :

PUSH-OMIT-CONTEXT	# Sauvegarde du contexte actuel
CLEAR-OMIT-CONTEXT	# Nettoyage de l'ardoise
# Bloc de rappels ici
POP-OMIT-CONTEXT	# Restauration du contexte omit sauvegardé

EXPRESSIONS

Dans certains contextes, décrits plus loin, Remind acceptera des expressions pour évaluation. Les expressions Remind ressemblent aux expressions C, mais opèrent sur différents types d'objets.

TYPES DE DONNÉES

Les expressions Remind opèrent sur cinq types d'objets :

INT
Le type de données INT comprend les entiers représentables dans un mot machine. Le type de données INT correspond au type C "int".
STRING
Le type de données STRING comprend les chaînes de caractères. Il est assez comparable à un tableau de caractères C, mais ressemble plus au type chaîne en BASIC.

Remind s'attend normalement à s'exécuter dans un environnement UTF-8. Dans cet environnement, il y a une différence entre les octets et les caractères car en UTF-8, un caractère peut être représenté par une séquence de plusieurs octets. Par exemple, dans un environnement UTF-8, la chaîne "🙂" contient un caractère mais quatre octets. Et la chaîne "één" contient trois caractères mais cinq octets.

Remind dispose d'un ensemble de fonctions qui fonctionnent sur les octets, à savoir index, strlen et substr. Celles-ci ne sont pas sûres à utiliser sur des chaînes multi-octets ; utilisez à la place mbindex, mbstrlen et mbsubstr. Si vous savez à coup sûr qu'une chaîne ne contient que des caractères mono-octet, alors les versions orientées octets peuvent être utilisées et sont plus rapides que les versions multi-octets.

Certains systèmes anciens ou embarqués peuvent ne pas disposer des fonctions de bibliothèque C nécessaires pour traiter les chaînes multi-octets. Dans ce cas, toutes les fonctions mbxxx renvoient une erreur.

TIME
Le type de données TIME est utilisé à deux fins différentes : pour représenter une heure de la journée avec une précision d'une minute ou pour représenter une durée avec une précision d'une minute. Le contexte où un TIME est utilisé détermine s'il est interprété comme une heure de la journée ou une durée.

Dans les contextes où un TIME représente une heure de la journée, il peut varier de 00:00 à 23:59 et est stocké en interne sous forme d'un entier de 0 à 1439 représentant le nombre de minutes depuis minuit.

Dans les contextes où un TIME représente une durée, il n'y a pas de limite supérieure au composant heure (au-delà de celle imposée par la restriction qu'une durée exprimée en minutes doit tenir dans le type entier signé de votre architecture CPU.) En interne, une durée est stockée comme un nombre entier de minutes.

DATE
Le type de données DATE comprend les dates (postérieures au 1er janvier 1990.) En interne, les objets DATE sont stockés comme le nombre de jours depuis le 1er janvier 1990.
DATETIME
Le type de données DATETIME comprend une date et une heure ensemble. En interne, les objets DATETIME sont stockés comme le nombre de minutes depuis minuit, le 1er janvier 1990. Vous pouvez considérer un objet DATETIME comme la combinaison des parties DATE et TIME.

CONSTANTES

Les exemples suivants illustrent les constantes dans les expressions Remind :

Constantes INT
12, 36, -10, 0, 1209, 0x1F, 0xfe00 (les deux dernières démontrent l'utilisation de constantes hexadécimales)
Constantes STRING
"Bonjour", "Ceci est un test", "\nBonjour\tMonde", ""
Notez que la chaîne vide est représentée par "". Remind prend en charge les séquences d'échappement "\a", "\b", "\f", "\n", "\r", "\t" et "\v" qui ont les mêmes significations que leurs homologues en C. Il prend également en charge "\xAB" où A et B sont des chiffres hexadécimaux ; cela fonctionne comme en C. Le "\x" doit être suivi d'un ou deux chiffres hex ; la séquence d'échappement "\x00" n'est pas autorisée.

Pour inclure un guillemet dans une chaîne, utilisez "\"". Tout autre caractère précédé d'une barre oblique inverse est inséré dans la chaîne tel quel, mais la barre oblique inverse elle-même est supprimée. Pour inclure une barre oblique inverse dans une chaîne, utilisez "\\".

Constantes TIME
12:33, 0:01, 14:15, 16:42, 12.16, 13.00, 1.11, 4:30PM, 12:20am
Notez que les constantes TIME peuvent être écrites en format 24 heures ou en format courant "AM/PM". Si vous utilisez le format "AM/PM", alors l'heure peut varier de 1 à 12. Un point ou un deux-points peut être utilisé pour séparer les minutes des heures. Cependant, Remind affichera de manière cohérente les heures au format 24 heures en utilisant un seul caractère séparateur. (Le caractère séparateur de sortie est choisi au moment de la compilation.)

Si le TIME est utilisé là où Remind attend une heure de la journée (par exemple, dans une clause AT), alors il peut être écrit au format 24 heures (allant de 00:00 à 23:59) ou au format 12 heures (allant de 12:00am à 11:59pm). Si TIME est utilisé là où Remind attend une durée, il ne doit pas avoir de suffixe am ou pm et l'heure peut être aussi grande que vous le souhaitez, tant que le nombre total de minutes dans la durée tient dans une variable entière signée.

Pour plus de commodité, une constante TIME peut être entourée d'apostrophes pour correspondre aux constantes DATE et DATETIME, mais ces apostrophes sont facultatives. C'est-à-dire que 12:56 et '12:56' représentent la même constante TIME.

Constantes DATE
Les constantes DATE sont exprimées comme 'yyyy/mm/dd' ou 'yyyy-mm-dd', et les apostrophes doivent être fournies. Cela distingue les constantes de date de la division ou de la soustraction d'entiers. Exemples :
'1993/02/22', '1992-12-25', '1999/01/01'

Notez que les valeurs DATE sont affichées sans les apostrophes. Bien que '-' ou '/' soient acceptés comme séparateur de date à l'entrée, lors de l'affichage des dates, un seul sera utilisé. Le choix d'utiliser '-' ou '/' est fait au moment de la compilation. Notez également que les versions de Remind antérieures à 03.00.01 ne supportaient pas les constantes de date. Dans ces versions, vous devez créer des dates en utilisant la fonction date(). De plus, les versions antérieures à 03.00.02 ne supportaient pas le séparateur de date '-'.

Constantes DATETIME
Les constantes DATETIME sont exprimées de manière similaire aux constantes DATE avec l'ajout d'une partie "@HH:MM", suivie éventuellement de "am" ou "pm". Par exemple :
'2008-04-05@23:11', '1999/02/03@14:06', '2001-04-07@08:30', '2020-01-01@3:20pm'

Les valeurs DATETIME sont affichées sans les apostrophes. Les notes concernant les caractères séparateurs de date et d'heure pour les constantes DATE et TIME s'appliquent également aux constantes DATETIME.

VALEURS ZÉRO ET VRAI/FAUX

Tous les types ont une valeur zéro associée, qui est traitée comme faux par la commande IF, la fonction IIF et les opérateurs logiques. Les valeurs zéro sont :

INT - 0

DATE - '1990-01-01'

TIME - 00:00

DATETIME - '1990-01-01@00:00'

STRING - "" (la chaîne vide)

Toute valeur autre que la valeur zéro est traitée comme vrai.

OPÉRATEURS

Remind possède les opérateurs suivants. Les opérateurs sur la même ligne ont la même priorité, tandis que les opérateurs sur les lignes inférieures ont une priorité inférieure à ceux des lignes supérieures. Les opérateurs correspondent approximativement aux opérateurs C.

!  -            (négation logique unaire et négation arithmétique)
*  /  %         (multiplication, division, modulo)
+  -            (addition/concaténation, soustraction)
<  <=  >  >=    (comparaisons)
==  !=          (tests d'égalité et d'inégalité)
&&              (ET logique)
||              (OU logique)

DESCRIPTION DES OPÉRATEURS

!
Négation logique. Peut être appliqué à n'importe quel type. Si l'opérande est non nul, retourne 0. Sinon, retourne 1.
-
Moins unaire. Peut être appliqué à un INT. Retourne l'opposé de l'opérande.
*
Multiplication. Retourne le produit de deux INTs. Alternativement, si un argument est une STRING et l'autre un INT, retourne une STRING constituée du nombre de répétitions de la STRING d'origine indiqué par l'INT. Dans ce cas, l'argument INT ne peut pas être négatif.
/
Division entière. Retourne le quotient de deux INTs, en ignorant le reste.
%
Modulo. Retourne le reste de la division d'un INT par un autre.
+
A plusieurs usages. Ce sont :
INT + INT - retourne la somme de deux INTs.

INT + TIME ou TIME + INT - retourne une TIME obtenue en ajoutant INT minutes à la TIME d'origine. Le résultat sera toujours compris entre 00:00 et 23:59.

TIME + TIME traite le second paramètre TIME comme une durée, le convertit en un nombre entier de minutes après minuit, puis effectue l'addition comme avec TIME + INT.

INT + DATE ou DATE + INT - retourne une DATE obtenue en ajoutant INT jours à la DATE d'origine.

INT + DATETIME ou DATETIME + INT - retourne une DATETIME obtenue en ajoutant INT minutes à la DATETIME d'origine.

DATETIME + TIME ou TIME + DATETIME traite le paramètre TIME comme une durée, le convertit en un nombre entier de minutes après minuit, puis effectue l'addition comme avec DATETIME + INT.

STRING + STRING - retourne une STRING qui est la concaténation des deux STRINGs d'origine.

STRING + quoi que ce soit ou quoi que ce soit + STRING - convertit l'argument non-STRING en une STRING, puis effectue la concaténation. Voir la fonction coerce().

-
A plusieurs usages. Ce sont :
INT - INT - retourne la différence de deux INTs.

DATE - DATE - retourne (en tant qu'INT) la différence en jours entre deux DATEs.

TIME - TIME - retourne (en tant qu'INT) la différence en minutes entre deux TIMEs.

DATETIME - DATETIME - retourne (en tant qu'INT) la différence en minutes entre deux DATETIMEs.

DATE - INT - retourne une DATE qui est INT jours plus tôt que la DATE d'origine.

TIME - INT - retourne une TIME qui est INT minutes plus tôt que la TIME d'origine.

DATETIME - INT - retourne une DATETIME qui est INT minutes plus tôt que la DATETIME d'origine.

DATETIME - TIME - convertit la TIME en un INT puis effectue la soustraction comme ci-dessus.

<, <=, >, et >=
Ce sont les opérateurs de comparaison. Ils peuvent prendre des opérandes de n'importe quel type, mais les deux opérandes doivent être du même type. Les opérateurs de comparaison retournent 1 si la comparaison est vraie, ou 0 si elle est fausse. Notez que la comparaison de chaînes se fait selon l'ordre lexical des caractères sur votre système, et que la casse est distincte pour ces opérateurs.
==, !=
== teste l'égalité, retournant 1 si ses opérandes sont égaux, et 0 s'ils ne le sont pas. != teste l'inégalité.
Si les opérandes ne sont pas du même type, == retourne 0 et != retourne 1. Encore une fois, les comparaisons de chaînes sont sensibles à la casse.
&&
C'est l'opérateur ET logique. Retourne le second opérande si les deux opérandes sont non nuls. Sinon, retourne l'opérande qui est zéro. Les opérandes peuvent être de n'importe quel type et "zéro" est interprété comme approprié pour le type de chaque opérande.
||
C'est l'opérateur OU logique. Il retourne le premier opérande non nul ; si les deux opérandes sont nuls, il retourne le second opérande. Les opérandes peuvent être de n'importe quel type et "zéro" est interprété comme approprié pour le type de chaque opérande.

NOTES

Si le résultat d'une opération d'addition, de soustraction ou de multiplication ne peut pas tenir dans un type "int" de C, Remind génère une erreur "Nombre trop élevé". Contrairement à C, les opérations entières ne donneront pas simplement une mauvaise réponse en cas de dépassement.

Les opérateurs de même priorité sont toujours évalués de gauche à droite, sauf indication contraire des parenthèses. Ceci est important, car l'opérateur "+" amélioré n'est pas nécessairement associatif. Par exemple :

1 + 2 + "string" + 3 + 4  donne "3string34"
1 + (2 + "string") + (3 + 4)  donne "12string7"
12:59 + 1 + "test"  donne "13:00test"
12:59 + (1 + "test")  donne "12:591test"

Les opérateurs logiques sont des opérateurs à évaluation paresseuse (short-circuit), comme en C. Cela signifie que si le premier opérande de || est vrai, alors le second opérande n'est pas évalué. De même, si le premier opérande de && est faux, alors le second opérande n'est pas évalué.

VARIABLES

Remind vous permet d'affecter des valeurs à des variables. La commande SET est utilisée comme suit :

SET var expr

Var est le nom d'une variable. Il doit commencer par une lettre ou un underscore, et ne contenir que des lettres, des chiffres et des underscores. Seuls les 64 premiers caractères d'un nom de variable sont significatifs. Les noms de variables ne sont pas sensibles à la casse ; ainsi, "Afoo" et "afOo" désignent la même variable. Exemples :

SET a 10 + (9*8)
SET b "Ceci est un test"
SET mydir getenv("HOME")
SET time 12:15
SET date today()

Notez que les variables elles-mêmes n'ont pas de type. Elles prennent le type de tout ce qui y est stocké.

Les variables définies avec SET ou sur la ligne de commande avec -ivar=expr ont une portée globale.

Pour supprimer une variable, utilisez la commande UNSET :

UNSET var [var...]

Par exemple, pour supprimer toutes les variables déclarées ci-dessus, utilisez :

UNSET a b mydir time date

VARIABLES SYSTÈME

En plus des variables utilisateur régulières, Remind dispose de plusieurs "variables système" utilisées pour interroger ou contrôler l'état de fonctionnement de Remind. Les variables système sont disponibles à partir de la version 03.00.07 de Remind.

Toutes les variables système commencent par un signe dollar '$'. Elles peuvent être utilisées dans les commandes SET et les expressions, tout comme les variables régulières. Toutes les variables système contiennent toujours des valeurs d'un type spécifié. De plus, certaines variables système ne peuvent pas être modifiées, et vous ne pouvez pas créer de nouvelles variables système. Les variables système peuvent être initialisées sur la ligne de commande avec l'option -i, mais vous devrez peut-être les mettre entre guillemets pour éviter que le shell n'interprète le signe dollar. Les noms des variables système ne sont pas sensibles à la casse.

Les variables système suivantes sont définies. Celles marquées "lecture seule" ne peuvent pas être modifiées avec la commande SET. Toutes les variables système contiennent des valeurs de type INT, sauf indication contraire.

$AjouterLignesVides
Si défini sur 1 (par défaut), Remind imprime normalement une ligne vide après la bannière et chaque rappel. (Ceci peut être supprimé en terminant le rappel ou la bannière par un seul signe de pourcentage.) Si $AjouterLignesVides est défini sur 0, alors Remind n'imprime pas la ligne vide. Dans ce cas, terminer un rappel par % n'a aucun effet. Si vous souhaitez une ligne vide après un rappel, terminez-le par %_ pour insérer un saut de ligne.
$CalcUTC
Si 1 (par défaut), alors Remind utilise les fonctions de la bibliothèque C pour calculer le nombre de minutes entre l'heure locale et le Temps Universel Coordonné. Cela affecte les calculs astronomiques (sunrise() par exemple.) Si 0, alors vous devez fournir le nombre de minutes entre l'heure locale et le Temps Universel Coordonné dans la variable système $MinsFromUTC.
$CalMode (lecture seule)
Si non nul, alors l'option -c a été fournie sur la ligne de commande.
$CalType (lecture seule, type STRING)
Si les options de ligne de commande -c, -s ou -p ont été utilisées, alors cette variable a la valeur "mensuel". Si -c+, -s+ ou -p+ ont été utilisés, alors "hebdomadaire". Sinon, "aucun".
$Daemon (lecture seule)
Si le "mode daemon" -z a été invoqué, contient le nombre de minutes entre les réveils. Si vous n'êtes pas en mode daemon, contient 0. En mode serveur (soit -z0 soit -zj), contient -1.
$DateSep (type STRING)
Cette variable ne peut être définie que sur "/" ou "-". Elle contient le caractère utilisé pour séparer les parties d'une date lorsque Remind imprime une valeur DATE ou DATETIME.
$DedupeReminders
Si cette variable est définie sur 1, alors Remind supprimera les rappels dupliqués. Un rappel donné est considéré comme un doublon d'un précédent s'il a la date de déclenchement, l'heure de déclenchement et le corps exactement identiques. Par défaut, cette variable est définie sur 0 et Remind ne supprime pas les rappels dupliqués.

À titre d'exemple, considérons le fichier de rappels suivant :

        SET $DedupeReminders 1
        REM Mercredi MSG Phooey
        REM 20 MSG Phooey

Le mercredi 20 novembre 2024, un seul rappel "Phooey" sera émis. En décembre 2024, "Phooey" sera émis chaque mercredi ainsi que le vendredi 20 décembre 2024.

Si vous définissez $DedupeReminders sur 0, alors Remind ne suit même pas les rappels pour détecter les doublons. Considérons l'exemple suivant :

        SET $DedupeReminders 0
        REM Mercredi MSG Hello
        SET $DedupeReminders 1
        REM Mercredi MSG Hello

Chaque mercredi, Remind émettra deux rappels "Hello". Parce que $DedupeReminders était à 0 lors de la première émission de "Hello", il ne sera pas suivi pour d'éventuels doublons.

Les doublons sont détectés après que toutes les expansions et substitutions de variables aient été effectuées. Considérons ce qui suit :

        SET $DedupeReminders 1
        set a "foo"
        REM MSG [a]
        set a "bar"
        REM MSG [a]
        set a "foo"
        REM MSG [a]

Le premier REM se déclenchera et affichera "foo". Le deuxième se déclenchera et affichera "bar". Le troisième ne se déclenchera pas car c'est un doublon du premier "foo".

$DefaultColor (type STRING)
Cette variable peut être définie sur une chaîne de caractères ayant la forme de trois nombres séparés par des espaces. Chaque nombre doit être un entier de 0 à 255, ou les trois nombres doivent être -1. La valeur par défaut de $DefaultColor est "-1 -1 -1", ce qui supprime la coloration par défaut des rappels de type MSG. Si vous définissez $DefaultColor sur toute autre valeur, alors tous les rappels de type MSG, MSF et CAL sont effectivement convertis en rappels SPECIAL COLOR dont la valeur de couleur est spécifiée par $DefaultColor.

Contrairement aux autres variables système, la valeur de $DefaultColor n'est pas conservée entre les itérations du calendrier ; elle est plutôt réinitialisée à "-1 -1 -1" au début de chaque itération.

$DefaultPrio
La priorité par défaut attribuée aux rappels sans clause PRIORITY. Vous pouvez la définir selon vos besoins pour ajuster les priorités de blocs de rappels sans avoir à taper les priorités pour des rappels individuels. Au démarrage, $DefaultPrio est défini sur 5000 ; il peut varier de 0 à 9999.
$DefaultDelta
Vous pouvez définir cette variable sur un nombre de 0 à 10000. Si elle est définie sur un nombre non nul, alors Remind déclenche toute instruction REM qui ne comporte pas de delta comme si elle avait un delta de ++$DefaultDelta. Par défaut, $DefaultDelta est zéro.
$DefaultTDelta
Le delta de temps par défaut utilisé si aucun +N n'est donné dans une clause AT. Ceci est normalement 0, mais peut être défini avec l'option -tt ou explicitement défini dans votre script. Si $DefaultDelta est non nul, vous pouvez utiliser un delta explicite de +0 dans une clause AT pour contrecarrer le delta par défaut.
$DeltaOverride (lecture seule)
Si non nul, correspond à l'argument n donné à une option de ligne de commande -tn.
$DontFork (lecture seule)
Si non nul, alors l'option -c a été fournie sur la ligne de commande.
$DontTrigAts (lecture seule)
Le nombre de fois que l'option -a a été fournie sur la ligne de commande.
$DontQueue (lecture seule)
Si non nul, alors l'option -q a été fournie sur la ligne de commande.
$EndSent (type STRING)
Contient une liste de caractères qui terminent une phrase. Le mot-clé MSF insère deux espaces après ces caractères. Initialement, $EndSent est défini sur ".!?" (point, point d'exclamation et point d'interrogation.)
$EndSentIg (type STRING)
Contient une liste de caractères qui doivent être ignorés lorsque MSF décide s'il faut ou non placer deux espaces après une phrase. Initialement, est défini sur "'>)]}"+CHAR(34) (apostrophe, supérieur, parenthèse fermante, crochet fermant, accolade fermante et guillemet double.)
Par exemple, les valeurs par défaut fonctionnent comme suit : 
MSF Il a dit, "Hein ! (Deux espaces suivront ceci.)"  Ouais.

car la parenthèse finale et le guillemet sont ignorés (aux fins de l'espacement) lorsqu'ils suivent un point.

$ExpressionTimeLimit
Si défini sur une valeur non nulle n, alors toute expression qui prend plus de n secondes à évaluer sera interrompue et une erreur sera retournée. Ceci afin d'empêcher des expressions malveillantes de créer un déni de service. Dans un fichier inclus, $ExpressionTimeLimit ne peut qu'être réduit par rapport à sa valeur actuelle. Dans le fichier de niveau supérieur, il peut être défini sur n'importe quelle valeur, y compris zéro pour désactiver la limite de temps.
$FirstIndent
Le nombre d'espaces dont la première ligne d'un rappel de type MSF doit être indentée. La valeur par défaut est 0.
$FoldYear
Les fonctions standard de la bibliothèque Unix peuvent avoir des difficultés à traiter les dates postérieures à 2037. Si cette variable est définie sur 1, alors les calculs UTC "replient" les années postérieures à 2037 avant d'utiliser les fonctions de la bibliothèque Unix. Par exemple, pour savoir si l'heure d'été est en vigueur en juin 2077, l'année est "repliée" sur 2027, car les deux années commencent un vendredi et aucune des deux n'est une année bissextile. Les règles relatives à l'heure d'été sont donc présumées identiques pour les deux années, et les fonctions de la bibliothèque Unix peuvent gérer 2027. Par défaut, cette variable est à 0. Définissez-la sur 1 si les fonctions de soleil ou d'UTC se comportent mal pour les années supérieures à 2037. Voir aussi la section "MACHINES AVEC UN TYPE TIME_T DE 32 BITS"
$FormWidth
La largeur maximale de chaque ligne de texte pour le formatage des rappels de type MSF. Par défaut, c'est la largeur du terminal en colonnes, moins 8, mais plafonnée à un minimum de 20 et un maximum de 500. Si la sortie standard n'est pas un terminal, la valeur par défaut est 72. Si un rappel de type MSF contient un mot trop long pour tenir dans cette largeur, il ne sera pas tronqué - la limite de largeur sera ignorée.
$HideCompletedTodos (lecture seule)
Si non nul, alors l'option --hide-completed-todos a été fournie sur la ligne de commande.
$HushMode (lecture seule)
Si non nul, alors l'option -h a été fournie sur la ligne de commande.
$IgnoreOnce (lecture seule)
Si non nul, alors l'option -o a été fournie sur la ligne de commande, ou activée implicitement pour une autre raison. Dans ce cas, les directives ONCE seront ignorées.
$InfDelta (lecture seule)
Si non nul, alors l'option -t a été fournie sur la ligne de commande, sans argument n.
$IntMax (lecture seule)
Le plus grand INT représentable. Sur une machine avec des entiers signés de 32 bits utilisant une représentation en complément à deux, ce sera 2147483647.
$IntMin (lecture seule)
Le plus petit INT représentable. Sur une machine avec des entiers signés de 32 bits utilisant une représentation en complément à deux, ce sera -2147483648.
$Latitude (type STRING)
La latitude de votre emplacement, exprimée sous forme de chaîne de caractères représentant un nombre à virgule flottante. Parce que Remind n'a pas de type à virgule flottante natif, nous devons l'exprimer sous forme de chaîne. $Latitude peut varier de "-90.0" à "90.0", les nombres positifs représentant des points au nord de l'équateur et les nombres négatifs représentant le sud. Notez que, quelle que soit votre locale, $Latitude est toujours interprétée dans la locale "C" et, par conséquent, le point décimal doit être un point (".").
$Longitude (type STRING)
La longitude de votre emplacement, exprimée sous forme de chaîne de caractères représentant un nombre à virgule flottante. Parce que Remind n'a pas de type à virgule flottante natif, nous devons l'exprimer sous forme de chaîne. $Longitude peut varier de "-180.0" à "180.0", les nombres positifs représentant des points à l'est du méridien de Greenwich et les nombres négatifs représentant l'ouest. Notez que, quelle que soit votre locale, $Longitude est toujours interprétée dans la locale "C" et, par conséquent, le point décimal doit être un point (".").

Par exemple, les coordonnées de la Statue de la Liberté à New York sont approximativement définies par :

    SET $Latitude   "40.68933"
    SET $Longitude "-74.04454"
$LatDeg, $LatMin, $LatSec (OBSOLÈTE)
Ces éléments spécifient la latitude de votre emplacement. $LatDeg peut varier de -90 à 90, et les autres de -59 à 59. Les latitudes nord sont positives ; les latitudes sud sont négatives. Pour les latitudes sud, les trois composantes doivent être négatives. Ces trois variables sont obsolètes ; vous devriez utiliser $Latitude à la place.
$Location (type STRING)
Ceci est une chaîne spécifiant le nom de votre emplacement. C'est généralement le nom de votre ville ou village. Il peut être défini comme vous le souhaitez, mais une bonne pratique suggère de le garder cohérent avec les variables système de latitude et de longitude.
$LongDeg, $LongMin, $LongSec (OBSOLÈTE)
Ceux-ci spécifient la longitude de votre emplacement. $LongDeg peut varier de -180 à 180. Les longitudes occidentales sont positives ; les orientales sont négatives. Notez que les trois composantes doivent avoir le même signe : toutes positives pour les longitudes occidentales et toutes négatives pour les longitudes orientales. Notez que pour des raisons historiques, le signe de la longitude est différent de la convention habituelle ! Si vous trouvez la longitude de votre emplacement à partir d'un moteur de recherche, vous devrez très probablement inverser le signe pour qu'il fonctionne correctement avec Remind. Ces trois variables sont obsolètes ; vous devriez utiliser $Longitude à la place. Notez également que $Longitude utilise la convention standard de négatif pour les longitudes occidentales et positif pour les orientales.

Les informations de latitude et de longitude sont requises pour les fonctions sunrise() et sunset(). Des valeurs par défaut peuvent être compilées dans Remind, ou vous pouvez SET les valeurs correctes au début de vos scripts de rappel.

Notez que la définition de l'un quelconque de $LongDec, $LongMin et $LongSec met à jour $Longitude en conséquence, et la définition de $Longitude met à jour $LongDeg, $LongMin et $LongSec. Des règles similaires s'appliquent à $Latitude, $LatDeg, $LatMin et $LatSec.

$JSONMode (en lecture seule)
Si non nul, alors l'option de ligne de commande --json a été fournie.
$MaxLateMinutes
Cette variable contrôle la réaction de Remind à la suspension puis au réveil d'un ordinateur. Normalement, si un rappel programmé est mis en file d'attente puis que l'ordinateur est suspendu, puis que l'ordinateur est réveillé *après* l'heure de déclenchement du rappel programmé, Remind déclenchera le minuteur de toute façon, malgré le fait que l'heure de déclenchement soit déjà passée.

Si vous définissez $MaxLateMinutes à un entier non nul compris entre 1 et 1440, alors Remind ne déclenchera *pas* un rappel programmé dont l'heure de déclenchement est plus ancienne que $MaxLateMinutes minutes.

Notez que Remind utilise la valeur de $MaxLateMinutes qui est en vigueur lorsqu'il a fini de lire le fichier de rappels et se met en arrière-plan. Généralement, vous devriez définir $MaxLateMinutes une fois près du début du fichier et ne pas la modifier par la suite.

$MaxSatIter
Le nombre maximum d'itérations pour la clause SATISFY (décrite plus loin.) Doit être au moins 10.
$MaxStringLen
Une limite sur la plus longue chaîne que Remind vous autorisera à créer. La valeur par défaut est 65535. Si vous définissez $MaxStringLen à 0 ou -1, alors remind vous permettra de créer des chaînes de longueur arbitraire, du moins jusqu'à ce qu'il manque de mémoire. Nous ne recommandons pas de définir $MaxStringLen à 0 ou -1 car il est très facile d'écrire du code qui attaque Remind dans ce cas.
$MinsFromUTC
Le nombre de minutes entre le Temps Universel Coordonné et l'heure locale. Si $CalcUTC est non nul, cela est calculé au démarrage de Remind. Sinon, vous devez le définir explicitement. Si $CalcUTC est nul, alors $MinsFromUTC est utilisé dans les calculs astronomiques. Vous devez l'ajuster vous-même pour l'heure d'été. De plus, si vous souhaitez initialiser $MinsFromUTC en utilisant l'option de ligne de commande -i, vous devez également définir $CalcUTC à 0 avec l'option -i.
$NextMode (en lecture seule)
Si non nul, alors l'option -n a été fournie sur la ligne de commande.
$MaxFullOmits (en lecture seule)
Le nombre maximum d'OMITs complets autorisés (une constante compilée.)
$MaxPartialOmits (en lecture seule)
Le nombre maximum d'OMITs partiels autorisés (une constante compilée.)
$NumFullOmits (en lecture seule)
Le nombre d'OMITs complets dans le contexte OMIT actuel.
$NumPartialOmits (en lecture seule)
Le nombre d'OMITs partiels dans le contexte OMIT actuel.
$NumQueued (en lecture seule)
Contient le nombre de rappels mis en file d'attente jusqu'à présent pour un déclenchement programmé en arrière-plan.
$NumTrig (en lecture seule)
Contient le nombre de rappels déclenchés pour la date actuelle. Une utilisation de cette variable est la suivante : Supposons que vous souhaitiez ombrer la case d'un calendrier PostScript chaque fois qu'une fête est déclenchée. Vous pourriez sauvegarder la valeur de $NumTrig dans une variable régulière avant d'exécuter un bloc de rappels de fêtes. Si la valeur de $NumTrig après le bloc de fêtes est supérieure à la valeur sauvegardée, alors au moins une fête a été déclenchée, et vous pouvez exécuter la commande pour ombrer la case du calendrier. (Voir la section "Mode Calendrier".)
Notez que $NumTrig est affecté *uniquement* par les commandes REM ; les déclenchements dans les commandes IFTRIG ne l'affectent pas.
$OnceFile (type STRING)
Si vous définissez cette variable à une chaîne non vide, alors au lieu d'utiliser la date d'accès au fichier pour déterminer si un rappel de type ONCE doit être exécuté ou non, Remind maintiendra un horodatage dans le fichier $OnceFile. Ceci est plus fiable que d'utiliser la date d'accès au fichier de rappels.

Si $OnceFile n'existe pas, il sera créé la première fois qu'un mot-clé ONCE est traité. Le fichier doit être accessible en écriture par l'utilisateur actuel. Si vous essayez de définir $OnceFile *après* qu'un rappel ONCE ait déjà été traité, Remind affichera un avertissement et ignorera la tentative de définir $OnceFile.

$ParseUntriggered
Un indicateur indiquant si Remind doit analyser complètement les instructions REM qui ne sont pas déclenchées. 0 (par défaut) signifie les ignorer lors de l'analyse, et 1 signifie les analyser.
Par exemple, si nous avons l'instruction REM suivante : 
            REM 2020-01-01 MSG ["bad_expression" / 2]

Alors si $ParseUntriggered est défini à 1, Remind analysera complètement la ligne et affichera une erreur de "Type mismatch" même si le rappel n'est pas déclenché. Cependant, si $ParseUntriggered est défini à 0, la valeur par défaut, alors Remind n'affichera pas l'erreur sauf le 2020-01-01, lorsque le rappel est déclenché.

Garder $ParseUntriggered à 0 peut légèrement améliorer les performances, au risque de ne pas détecter les erreurs tant qu'un rappel n'est pas déclenché. Nous recommandons de le laisser défini à 0.

$PrefixLineNo (en lecture seule)
Si non nul, alors l'option -l a été fournie sur la ligne de commande.
$PSCal (en lecture seule)
Si non nul, alors l'option -p a été fournie sur la ligne de commande.

$SortByDate (en lecture seule)

$SortByPrio (en lecture seule)

$SortByTime (en lecture seule)

    SET $SuppressLRM 1

SAUVEGARDER ET RESTITUER LES VARIABLES

Tout comme avec le contexte OMIT, vous pouvez sauvegarder et restaurer les valeurs des variables globales et de toutes les variables système (modifiables). Par exemple :

        SET a 1
        UNSET b
        # Sauvegarder les variables
        PUSH-VARS $DefaultColor $AddBlankLines a b
        SET $DefaultColor "255 0 0"
        SET $AddBlankLines 0
        SET a 3
        SET b 4
        REM MSG Hello
        # Restaurer toutes les variables que nous avions précédemment poussées
        POP-VARS
        # Maintenant, les modifications apportées à $DefaultColor et $AddBlankLines
        # ont été annulées. De plus, a est restauré à 1
        # et b est désactivé

Comme vous le voyez dans l'exemple, PUSH-VARS prend une liste de noms de variables globales et/ou de noms de variables système. Vous pouvez sauvegarder les valeurs de toutes les variables système *modifiables* et de toute variable globale. Vous pouvez même pousser des variables globales qui ne sont pas définies.

La commande POP-VARS restaure les valeurs de toutes les variables système et variables globales qui ont été poussées par la commande PUSH-VARS la plus récente. Si vous poussez une variable globale non définie, alors cette variable est désactivée par la commande POP-VARS.

FONCTIONS INTÉGRÉES

Remind dispose d'une pléthore de fonctions intégrées. La syntaxe d'un appel de fonction est identique à celle de C : le nom de la fonction, suivi d'une liste d'arguments séparés par des virgules entre parenthèses. Les noms de fonctions ne sont pas sensibles à la casse. Si une fonction ne prend aucun argument, elle doit être suivie de "()" dans l'appel de fonction. Sinon, Remind l'interprétera comme un nom de variable, et ne fonctionnera probablement pas correctement.

Dans les descriptions ci-dessous, des formes abrégées sont utilisées pour indiquer les types acceptables pour les arguments. Les caractères "i", "s", "d", "t" et "q" désignent les arguments INT, STRING, DATE, TIME et DATETIME, respectivement. Si un argument peut être d'un seul des plusieurs types, les caractères sont concaténés. Par exemple, "di_arg" désigne un argument qui peut être une DATE ou un INT. "x_arg" désigne un argument qui peut être de n'importe quel type. Le type de l'argument est suivi d'un tiret bas et d'un identifiant nommant l'argument.

Les fonctions intégrées sont :

_(s_message)
Retourne l'entrée de la table de traduction pour message. S'il n'y a pas d'entrée de table de traduction correspondante, retourne message tel quel. Par exemple, considérez cette séquence :
        TRANSLATE "Goodbye" "Tot ziens"
        SET a _("Goodbye")

Après que ces deux lignes aient été exécutées, la variable a sera définie sur "Tot ziens". Voir la section LA TABLE DE TRADUCTION pour plus d'informations.

Dans le corps d'un rappel, la séquence de substitution %(texte) est (presque) l'équivalent de [_("texte")]. Par conséquent, les rappels suivants sont presque équivalents :

        REM MSG %(Goodbye)
        REM MSG [_("Goodbye")]

La seule différence est que si _("Goodbye") contient un signe %, alors ce résultat sera traité par le filtre de substitution, alors que dans le premier rappel, il ne le sera pas. C'est parce que la deuxième commande REM effectue un collage d'expression suivi d'une passe du filtre de substitution, tandis que la première effectue la traduction dans le cadre du filtre de substitution (et ne fait pas de seconde passe du filtre de substitution).

abs(i_num)
Retourne la valeur absolue de num.
access(s_file, si_mode)
Teste les permissions d'accès pour le fichier file. Mode peut être une chaîne, contenant un mélange des caractères "rwx" pour les tests de permission de lecture, écriture et exécution. Alternativement, mode peut être un nombre comme décrit dans l'appel système UNIX access(2). La fonction retourne 0 si le fichier peut être accédé avec le mode spécifié, et -1 sinon.
adawn([dq_date])
Retourne l'heure de l'aube "astronomique" à la date spécifiée date. Si date est omise, elle vaut par défaut today(). Si un objet datetime est fourni, seule la composante date est utilisée.
adusk([dq_date])
Retourne l'heure du crépuscule "astronomique" à la date spécifiée date. Si date est omise, elle vaut par défaut today().
ampm(tq_time [,s_am [,s_pm [,i_lz]]])
Retourne une STRING qui est le résultat de la conversion de time (qui est soit un objet TIME, soit un objet DATETIME) au format "AM/PM". Les arguments optionnels am et pm sont les chaînes à ajouter dans le cas AM et PM respectivement ; ils valent par défaut "AM" et "PM". L'argument optionnel lz spécifie si l'heure doit être complétée par un zéro initial pour faire deux chiffres. Si lz est zéro, alors un zéro initial n'est pas ajouté ; sinon, l'heure est complétée à deux chiffres avec un zéro initial. Si non fourni, lz vaut par défaut zéro.

La fonction respecte les variables système $DateSep, $TimeSep et $DateTimeSep lors du formatage de sa sortie. Voici quelques exemples de sa sortie :

        ampm(0:22)                 retourne "12:22AM"
        ampm(17:45, "am", "pm")    retourne "5:45pm"
        ampm(17:45, "am", "pm", 1) retourne "05:45pm"
        ampm('2020-03-14@21:34')   retourne "2020-03-14@9:34PM"
ansicolor(i_red, i_green, i_blue [,i_bg [,i_clamp]])
Retourne une STRING contenant une séquence d'échappement ANSI pour changer la couleur du texte du terminal. Les paramètres red, green et blue sont des entiers de 0 à 255 spécifiant la valeur de la composante de couleur respective. À titre de cas spécial, les trois valeurs peuvent être -1, auquel cas la séquence ANSI "ESC[0m" est retournée, ce qui réinitialise tous les attributs de texte à la normale.

La chaîne retournée par ansicolor dépend du mode couleur dans lequel Remind est exécuté, comme spécifié par l'option -@. Si le mode couleur n'est pas activé, alors ansicolor retourne toujours la chaîne vide. Sinon, elle retourne la séquence d'échappement qui approxime le mieux la couleur selon le mode couleur -@.

L'argument optionnel bg est soit 0, soit 1. Si 0 (la valeur par défaut), alors la couleur de premier plan est définie. Si 1, alors la couleur d'arrière-plan est définie. Notez que la définition de la couleur d'arrière-plan ne fonctionne qu'en mode 256 couleurs ou couleur réelle.

L'argument optionnel clamp est soit 0, soit 1. Si 0 (la valeur par défaut), alors les couleurs ne sont pas ajustées en fonction de la couleur d'arrière-plan du terminal. Si 1, alors Remind tente d'ajuster les couleurs sombres ou vives afin qu'elles aient suffisamment de contraste pour être visibles dans le terminal.

Les trois premiers arguments peuvent alternativement être spécifiés comme une chaîne composée de trois nombres séparés par des espaces, comme dans cet exemple : "128 128 0"

À titre de cas spécial, ansicolor("") est équivalent à ansicolor(-1,-1,-1) et retourne la séquence ANSI pour réinitialiser tous les attributs de texte à la normale.

Notez que l'insertion de séquences de couleurs ANSI en mode calendrier *produira des résultats incorrects*. C'est pourquoi nous recommandons de définir des fonctions comme celles ci-dessous qui retournent la chaîne vide en mode calendrier :

        IF $CalMode
            FSET fg(r,g,b) ""
            FSET bg(r,g,b) ""
        ELSE
            FSET fg(r,g,b) ansicolor(r,g,b)
            FSET bg(r,g,b) ansicolor(r,g,b,1)
        ENDIF
        REM [fg(255,0,0)][bg(64,64,64)]Rouge sur Gris[fg(-1,-1,-1)] en mode agenda
        REM COULEUR SPÉCIALE 0 255 0 Vert en mode agenda et calendrier

Si vous utilisez la fonction ansicolor, n'oubliez pas de réinitialiser la couleur à la normale avec ansicolor(-1,-1,-1) ou les rappels suivants continueront d'être colorés.

args(s_fname)
Retourne le nombre d'arguments attendus par la fonction définie par l'utilisateur fname, ou -1 si aucune fonction définie par l'utilisateur de ce nom n'existe. Notez que cette fonction examine uniquement les fonctions définies par l'utilisateur, pas les fonctions intégrées. Son utilisation principale est de déterminer si une fonction définie par l'utilisateur particulière a été définie précédemment ou non. La fonction args() n'est disponible que dans les versions de Remind à partir de 03.00.04.
asc(s_string)
Retourne un INT qui est le code ASCII du premier octet de la chaîne string. À titre de cas spécial, asc("") retourne 0. Pour les chaînes UTF-8, cela retournera l'octet UTF-8 avec lequel la chaîne commence, ce qui n'est probablement pas très utile.
codepoint(s_string)
Retourne un INT qt est le point de code du premier caractère de string, en traitant correctement les caractères multi-octets. À titre de cas spécial, codepoint("") renvoie 0.
baseyr()
Renvoie l'« année de base » qui a été compilée dans Remind (normalement 1990.) Toutes les dates sont stockées en interne comme le nombre de jours depuis le 1er janvier de baseyr().
catch(x_arg1, x_arg2)
Évalue arg1 et si aucune erreur ne se produit, renvoie la valeur résultante. Si une erreur se produit pendant l'évaluation de arg1, évalue et renvoie arg2. Notez que catch() ne peut intercepter que des erreurs d'évaluation d'exécution. Il ne peut pas intercepter des erreurs de syntaxe.

Voici quelques exemples :

catch(4/2, 33)  => 2, car 4/2 s'évalue sans erreur
catch(4/0, 33)  => 33, car 4/0 donne une erreur de division par zéro
catch(2, 1/0)   => 2, et le deuxième argument n'est pas évalué
catch(4/0, 1/0) provoque une erreur de division par zéro

Notez dans le dernier exemple que catch ne vous protège pas des erreurs d'évaluation de arg2.

catcherr()
Renvoie une chaîne représentant le message d'erreur de la fonction catch() la plus récemment évaluée dont le premier argument a généré une erreur. Notez que le message d'erreur est toujours en anglais même si Remind a été localisé ; cela vous permet de tester de manière fiable la valeur renvoyée. Voici quelques exemples :
    # Aucune invocation de "catch" encore : définit a sur "Ok"
    set a catcherr()
    # Définit b sur "oops" et a sur "Division by zero"
    set b catch(1/0, "oops")
    set a catcherr()
    # Définit b sur 1 et a sur "Division by zero". L'erreur de catch
    # n'est jamais effacée par un catch() sans erreur
    set b catch(4-3, "not-evaluated")
    set a catcherr()
char(i_i1 [,i_i2...])
Cette fonction peut prendre un nombre quelconque d'arguments INT. Elle renvoie une STRING composée des octets spécifiés par les arguments. Il est facile de créer des séquences UTF-8 invalides ; char ne vérifie pas cela. Notez qu'aucun des arguments ne peut être 0, sauf s'il n'y a qu'un seul argument. À titre de cas spécial, char(0) renvoie "".
mbchar(i_i1 [,i_i2...])
Cette fonction peut prendre un nombre quelconque d'arguments INT. Elle renvoie une STRING composée des caractères spécifiés par les arguments. Tout point de code peut être fourni et une chaîne de caractères multi-octets correcte sera renvoyée. Notez qu'aucun des arguments ne peut être 0, sauf s'il n'y a qu'un seul argument. À titre de cas spécial, mbchar(0) renvoie "". De plus, aucun argument ne peut être un nombre négatif.
choose(i_index, x_arg1 [,x_arg2...])
Choose doit prendre au moins deux arguments, dont le premier est un INT. Si index est n, alors le nème argument suivant est renvoyé. Si index est inférieur à 1, alors arg1 est renvoyé. Si index est supérieur au nombre d'arguments suivants, alors le dernier argument est renvoyé. Exemples :
choose(0, "foo", 1:13, 1000) renvoie "foo"
choose(1, "foo", 1:13, 1000) renvoie "foo"
choose(2, "foo", 1:13, 1000) renvoie 1:13
choose(3, "foo", 1:13, 1000) renvoie 1000
choose(4, "foo", 1:13, 1000) renvoie 1000

Notez que seuls le premier argument et le résultat choisi sont évalués. Tous les arguments non choisis ne seront pas évalués.

coerce(s_type, x_arg)
Cette fonction convertit arg dans le type spécifié, si une telle conversion est possible. Type doit être l'un des "INT", "STRING", "DATE", "TIME" ou "DATETIME" (insensible à la casse). Les règles de conversion sont les suivantes :

Si arg est déjà du type spécifié, il est renvoyé tel quel.

Si type est "STRING", alors arg est converti en une chaîne composée de sa représentation imprimée.

Si type est "DATE", alors un INT arg est converti en l'interprétant comme le nombre de jours depuis le 1er janvier baseyr(). Une STRING arg est convertie en tentant de la lire comme si c'était une date imprimée. Un DATETIME est converti en une date en supprimant le composant temporel. Un TIME arg ne peut pas être converti en une date.

Si type est "TIME", alors un INT arg est converti en l'interprétant comme le nombre de minutes depuis minuit. Une STRING arg est convertie en tentant de la lire comme si c'était une heure imprimée. Un DATETIME est converti en une heure en supprimant le composant date. Une DATE arg ne peut pas être convertie en une heure.

Si type est "DATETIME", alors un INT arg est converti en l'interprétant comme le nombre de minutes depuis minuit, le 1er janvier baseyr(). Une STRING est convertie en tentant de la lire comme si c'était une date-heure imprimée. D'autres types ne peuvent pas être convertis en date-heure.

Si type est "INT", alors les arguments DATE, TIME et DATETIME sont convertis en utilisant l'inverse des procédures décrites ci-dessus. Une STRING arg est convertie en l'analysant comme un entier.

columns([s_arg])
Si appelée sans arguments, columns() se comporte comme suit : Si la sortie standard est un TTY, renvoie la largeur du terminal en colonnes. Si la sortie standard n'est pas un TTY, tente d'ouvrir "/dev/tty" pour obtenir la taille du terminal. Si cela échoue, renvoie -1.

Si appelée avec un seul argument chaîne, columns(str) renvoie le nombre de colonnes que str occupera si elle est imprimée dans un terminal. Les séquences de changement de couleur ANSI occupent zéro colonne, tandis que certains caractères Unicode occupent deux colonnes. columns(str) prend tout cela en compte. Notez que si Remind a été compilé sans prise en charge Unicode, columns(str) renvoie une erreur de discordance de type.

Le résultat de columns(str) peut être inférieur, égal ou supérieur au résultat de mbstrlen(str). En effet, certains caractères Unicode sont des caractères dits de combinaison qui ajoutent un à la longueur du caractère, mais n'occupent aucune colonne par eux-mêmes. Et d'autres caractères Unicode sont des caractères double-largeur qui ajoutent un à la longueur du caractère, mais deux au nombre de colonnes d'affichage.

const(x_arg)
Évalue arg et le renvoie, mais s'assure également que le résultat est marqué comme "constant". Utiliser avec prudence ; une mauvaise utilisation pourrait entraîner la suppression de rappels indésirables en mode Purge. Voir également la section « EXPRESSIONS NON CONSTANTES »
current()
Renvoie la date et l'heure actuelles sous forme d'objet DATETIME. Il peut s'agir de la date et de l'heure réelles, ou de la date et de l'heure fournies en ligne de commande.
date(i_y, si_m, i_d)
La fonction date() renvoie un objet DATE avec les composantes année, mois et jour spécifiées par y, m et d. Le mois peut être spécifié comme un entier de 1 à 12, ou une chaîne qui est le nom d'un mois.
datepart(dq_datetime)
Renvoie un objet DATE représentant la partie date de datetime.
datetime(args)
La fonction datetime() peut prendre entre deux et cinq arguments. Elle renvoie toujours une DATETIME générée à partir de ses arguments.

Si vous fournissez deux arguments, le premier doit être une DATE et le second une HEURE.

Si vous fournissez trois arguments, le premier doit être une DATE et le second et le troisième doivent être des INTs. Le second et le troisième arguments sont interprétés comme heures et minutes et convertis en une HEURE.

Si vous fournissez quatre arguments, ils sont interprétés comme année, mois, jour et heure. Année et jour doivent être des INTs. Mois peut être un INT de 0 à 12 ou une chaîne nommant un mois. Heure doit être une HEURE.

Enfin, si vous fournissez cinq arguments, ils doivent tous être des INTs et sont interprétés comme année, mois, jour, heure et minute. (En fait, mois peut aussi être une chaîne qui est le nom d'un mois.)

dawn([dq_date])
Renvoie l'heure de l'« aube civile » à la date spécifiée date. Si date est omis, utilise la valeur par défaut de today(). Si un objet datetime est fourni, seule la composante date est utilisée.
day(dq_date)
Cette fonction prend une DATE ou une DATETIME comme argument, et renvoie un INT qui est la composante jour-du-mois de date.
daysinmon(si_m, i_y) ou daysinmon(dq_date)
Renvoie le nombre de jours du mois m (1-12) de l'année y. Le premier argument peut être un entier de 1 à 12, ou une chaîne qui est le nom d'un mois. S'il reçoit un seul argument DATE ou DATETIME, renvoie le nombre de jours du mois contenant l'argument.
defined(s_var)
Renvoie 1 si la variable nommée par var est définie, ou 0 si elle ne l'est pas.

multitrig(s_trig1 [,s_trig2, [... s_trigN]])
multitrig évalue chaque chaîne comme un déclencheur, similaire à evaltrig, et renvoie la date de déclenchement la plus ancienne qui est le jour même ou après today(). multitrig est similaire à trig mais présente la différence suivante :

trig renvoie la première date de déclenchement qui aurait été déclenchée aujourd'hui, tandis que multitrig renvoie la date de déclenchement la plus ancienne après aujourd'hui, indépendamment du fait qu'elle aurait déclenché aujourd'hui.

Si aucun déclencheur ne peut être calculé après today(), alors multitrig renvoie 1990-01-01.

Considérez les exemples suivants, en supposant qu'aujourd'hui est le dimanche 24 mars 2024 :

   # Renvoie 1990-01-01 car aucun des deux ne se déclencherait aujourd'hui
   SET a trig("Mon", "Wed")
   # Renvoie 2024-03-25 car c'est la date de déclenchement la plus ancienne
   SET a multitrig("Mon", "Wed")
   # Renvoie 2024-03-27 car c'est la première qui se déclencherait aujourd'hui
   SET a trig("Wed +3", "Mon +3")
   # Renvoie 2024-03-25 car c'est la date de déclenchement la plus ancienne
   SET a multitrig("Wed +3", "Mon +3")
   # Renvoie 1990-01-01 car tous les déclencheurs ont expiré
   SET a multitrig("2000", "2022", "1998", "2023")

En général, multitrig fonctionne mieux avec l'algorithme Remind que trig et devrait être utilisé la plupart du temps. Par exemple, ce rappel est émis à la fin de chaque trimestre :

        REM [multitrig("Mar 31", "Jun 30", "Sep 30", "Dec 31")] +7 MSG \
        %"End of [ord($Tm/3)] quarter%" is %b.

Si vous souhaitez le dernier jour ouvrable de chaque trimestre, vous pouvez utiliser :

        PUSH-OMIT-CONTEXT
        OMIT Sat Sun
        REM [multitrig("Mar ~1", "Jun ~1", "Sep ~1", "Dec ~1")] +7 MSG \
        %"Last working day of [ord($Tm/3)] quarter%" is %b.
        POP-OMIT-CONTEXT

Notez que contrairement à evaltrig, multitrig renvoie toujours une DATE et jamais un DATETIME. Inclure une clause AT dans un déclencheur su

appliqué à multitrig entraînera une erreur.

nonomitted(dq_start, dq_end [, i_step] [,s_wkday...])
Cette fonction retourne le nombre de jours non omis entre start et end. Si start n'est pas omis, il est compté. end n'est jamais compté.

Notez que si end est antérieur à start, les arguments sont effectivement échangés, donc le comptage commence toujours à partir de la date la plus ancienne.

Si le troisième argument de nonomitted est un INT, il doit être supérieur à zéro et est considéré comme le pas selon lequel nonomitted compte. Par exemple, l'expression suivante :

        nonomitted('2023-07-01', '2023-07-29', 7)

retourne le nombre de samedis non omis du 2023-07-01 jusqu'au 2023-07-29 (inclus). (Le 2023-07-01 et le 2023-07-29 sont tous deux des samedis.)

Si aucun argument de pas n'est fourni, un pas de 1 est utilisé.

En plus d'utiliser le contexte OMIT global, vous pouvez fournir des arguments supplémentaires qui sont des noms de jours de la semaine à omettre. Cependant, dans une commande REM, toute clause locale OMITFUNC n'est pas prise en compte par cette fonction.

Par exemple, la ligne suivante définit a à 11 (en supposant aucun OMIT global) :

set a nonomitted('2007-08-01', '2007-08-16', "Sat", "Sun")

car le jeudi 16 août 2007 est le 11ème jour ouvrable (sans compter les samedis et dimanches) après le mercredi 1er août 2007.

nonomitted a diverses utilisations. Par exemple, de nombreuses écoles fonctionnent sur un cycle de six jours et le numéro du jour n'est pas incrémenté les jours fériés. Supposons que l'année scolaire commence par le Jour 1 le 4 septembre 2007. Le rappel suivant étiquètera les numéros de jour dans un calendrier :

   IF today() >= '2007-09-04'
       set daynum nonomitted('2007-09-04', today(), "Sat", "Sun")
       REM OMIT SAT SUN SKIP CAL Day [(daynum % 6) + 1]
   ENDIF

Évidemment, la réponse que vous obtenez de nonomitted dépend du contexte OMIT global. Si vous utilisez des OMITs mobiles, vous pourriez obtenir des résultats incohérents.

Voici une utilisation plus complexe de nonomitted. Ma collecte des déchets suit deux cycles entrelacés de 14 jours : un vendredi, les déchets et le recyclage du papier ("Boîte Noire") sont collectés. Le vendredi suivant, les déchets et le recyclage du plastique ("Boîte Bleue") sont collectés. Si l'un des jours du lundi au vendredi est férié, la collecte est retardée jusqu'au samedi. Voici une façon d'encoder ces règles :

   fset _garbhol(x) wkdaynum(x) == 5 && nonomitted(x-4, x+1) < 5
   REM 12 novembre 1999 *14 AFTER OMITFUNC _garbhol MSG Black Box
   REM 19 novembre 1999 *14 AFTER OMITFUNC _garbhol MSG Blue Box

Voici comment cela fonctionne : la fonction définie par l'utilisateur _garbhol(x) retourne 1 si et seulement si (1) x est un vendredi et (2) il y a au moins un jour OMIT ted du lundi précédent jusqu'au vendredi inclus.

La première instruction REM configure le cycle de la boîte noire de 14 jours. Le mot-clé AFTER reporte la collecte au samedi si _garbhol retourne 1. La seconde instruction REM configure le cycle de la boîte bleue avec un ajustement similaire effectué par AFTER en conjonction avec _garbhol.

Si notesize est donné, il spécifie la taille de la police à utiliser pour l'annotation, en unités PostScript (1/72 pouce.) Si notesize n'est pas donné, il prend par défaut la taille utilisée pour les entrées du calendrier. REM [moondate(0)] PS [psmoon(0, -1, moontime(0)+"")]

Notez comment l'heure est convertie en chaîne de caractères par concaténation de la chaîne nulle.

Cette fonction est l'inverse de nonomitted. Elle ajoute amt (qui peut être négatif) blocs de step jours à start, sans compter les jours omis. Si step n'est pas fourni, il est supposé être 1. Notez que seul chaque stepème jour est testé pour voir s'il est omis. Les arguments optionnels wkday sont des noms de jours de semaine supplémentaires à omettre.

Considérez cet exemple :

OMIT 14 May 2009
SET a slide('2009-05-13', 5, "Sat", "Sun")

Dans ce cas, a est défini à 2009-05-21. C'est parce que nous avançons de 5 jours, sans inclure le jeudi 14 mai ni les samedi et dimanche 16 et 17 mai. Vous pouvez aussi reculer, donc :

SET a slide('2009-05-21', -5, "Sat", "Sun")

Considérez maintenant cet exemple :

        OMIT 14 May 2009
        SET a slide('2009-05-07', 2, 7)

Cela définit a à '2009-05-28' car nous sautons deux semaines, sans compter une semaine où le jour sur lequel nous atterrissons est omis. Comparez avec ceci :

Elles nécessitent que la latitude et la longitude soient spécifiées en définissant les variables système appropriées. (Voir "Variables système".) trig(s_1 [, s_2, ...])
Pour chaque argument chaîne s_n, trig évalue s_n comme s'il s'agissait d'une spécification de déclencheur REM ou IFTRIG. Si le déclencheur se déclenche aujourd'hui, alors la date du déclencheur est retournée et aucun autre déclencheur n'est évalué. Si aucun des déclencheurs ne se déclenche aujourd'hui, alors la date zéro 1990-01-01 est retournée.
trig a également une forme sans argument ; elle retourne la date de déclenchement de la fonction trig la plus récente qui a retourné une date de déclenchement non nulle.

trig peut être utilisé pour créer des versions plus sophistiquées de IFTRIG. Par exemple, si vous avez des réunions tous les lundis en juin et juillet, et que vous souhaitez des avertissements 3 jours à l'avance, vous pourriez utiliser :

    REM [trig("Mon Jun +3", "Mon July +3")] +3 MSG Réunion %b

NOTE : Nous devons répéter le delta +3 en dehors de la fonction trig pour que l'avertissement anticipé fonctionne correctement. C'est parce que trig retourne une date constante (la date du déclencheur) et que la commande REM ne connaît pas les détails des arguments de trig.

Notez que parce que Remind a des opérateurs logiques d'évaluation courte, quelque chose comme :

    SET a trig("Mon +7") || trig("Fri +7")

définirait la valeur de trig() à la date du lundi suivant. Parce que trig("Mon +7") retourne toujours vrai, l'opérateur OU logique n'évalue pas trig("Fri +7") qui ne définit donc pas trig().

Note Importante : Parce que trig() retourne toujours une date absolue, il ne fonctionnera *pas* correctement avec une clause SATISFY. Considérez ce rappel :

    REM [trig("Mar", "Apr")] SATISFY [$Td == 15] MSG 15 Mar ou April

Si nous exécutons Remind le 5 mars 2022, nous pourrions nous attendre à ce que la date du déclencheur soit calculée comme le 15 mars 2022... mais ce n'est pas ce qui se passe. Au lieu de cela, la fonction trig est évaluée en premier, et elle retourne 2022-03-05. Donc, en ce qui concerne Remind, l'instruction REM devient :

    REM 2022-03-05 SATISFY [$Td == 15] MSG 15 Mar ou April

et l'expression SATISFY n'est jamais vraie. Donc : *Ne mélangez pas* *trig()* *et SATISFY*.

MACHINES AVEC UN TYPE TIME_T DE 32 BITS

En interne, la bibliothèque C standard représente les temps sous forme d'un type time_t. Il s'agit d'un type entier signé qui compte les secondes depuis minuit, le 1er janvier 1970 UTC. Si le type time_t n'a qu'une taille de 32 bits, la bibliothèque C ne peut pas représenter les temps après le 19 janvier 2038 à 03:14:07 UTC.

Pour contourner cette limitation, Remind "pliera" les années supérieures à 2037 vers une année plus petite qui commence le même jour et a le même nombre de jours. Il en résulte une année qui a très probablement les mêmes règles d'heure d'été que l'année d'origine, à moins que les règles n'aient changé entre-temps (auquel cas le changement de règle n'aurait même pas pu être représenté sur une machine 32 bits, donc c'est sans importance).

Remind effectue ensuite des conversions UTC vers local ou local vers UTC avec l'année pliée, puis la corrige après conversion. Cela devrait donner des résultats corrects pour les fonctions astronomiques et les conversions entre heure locale et UTC, à condition que les règles d'heure d'été n'aient pas changé entre l'année pliée et l'année d'origine.

Notez que la variable système $FoldYear n'est plus aussi utile ; Remind plie toujours les années si c'est nécessaire sur un système 32 bits. Vous pouvez définir $FoldYear à 1 pour forcer Remind à plier les années même sur un système 64 bits, mais cela n'est utile que pour les tests et non pour la production.

ÉVÉNEMENTS SUR PLUSIEURS JOURS

Si vous spécifiez une heure de début avec AT et une durée avec DURATION, vous pouvez créer des événements qui s'étendent sur plusieurs jours. Considérez ces deux instructions REM :

    REM 1991-02-13 AT 16:00 DURATION 72:00 MSG Événement de 72 heures
    REM 1991-02-13 THROUGH 1991-02-16 AT 16:00 MSG Quatre événements

La première instruction crée un unique événement qui commence le 13 février 1991 à 16h00 et se termine le 16 février 1991 à 16h00.

La seconde instruction crée quatre événements distincts qui commencent à 16h00 les 13, 14, 15 et 16 février 1991 et ont une durée indéfinie.

Remind gère les événements sur plusieurs jours de manière spéciale. Ce sont les règles :

Le premier jour d'un événement sur plusieurs jours, trigdatetime() retournera la date et l'heure de début de l'événement, et trigduration() retournera la DURATION d'origine.

Chaque jour suivant d'un événement sur plusieurs jours, trigdatetime() retournera minuit le jour en question, et trigduration() retournera la durée restante. Considérez cet exemple :

    #!/bin/sh
    remind - 12 feb 1991 '*6' <<'EOF'
    BANNER %
    REM 1991-02-13 AT 16:00 DURATION 72:00 SATISFY 1
    set a trigdatetime()
    set b trigduration()
    set c trigeventstart()
    set d trigeventduration()
    MSG now=[today()] dt=[a] dur=[b] estart=[c] edur=[d]%
    EOF

La sortie est :

now=1991-02-12 dt=1991-02-13@16:00 dur=72:00 estart=1991-02-13@16:00 edur=72:00
now=1991-02-13 dt=1991-02-13@16:00 dur=72:00 estart=1991-02-13@16:00 edur=72:00
now=1991-02-14 dt=1991-02-14@00:00 dur=64:00 estart=1991-02-13@16:00 edur=72:00
now=1991-02-15 dt=1991-02-15@00:00 dur=40:00 estart=1991-02-13@16:00 edur=72:00
now=1991-02-16 dt=1991-02-16@00:00 dur=16:00 estart=1991-02-13@16:00 edur=72:00
now=1991-02-17 dt=1991-02-13@16:00 dur=72:00 estart=-1 edur=-1

Comme vous pouvez le voir, les fonctions trigdatetime() et trigduration() retournent l'heure de début et la durée de la portion restante d'un événement sur plusieurs jours, tandis que trigeventstart et trigeventduration retournent toujours l'heure de début et la durée d'origine de l'événement sur plusieurs jours. Notez également que la valeur de retour pour les rappels expirés n'est pas fiable ; le fait que trigeventstart et trigeventduration retournent -1 dans ce cas est un artefact d'implémentation.

ÉVÉNEMENTS QUI SE CHEVAUCHENT

Un événement sur plusieurs jours peut avoir la possibilité de "se chevaucher". Lorsque cela se produit, Remind préfère l'événement le plus tardif (une seule copie d'un événement est jamais déclenchée pour une date donnée). Considérez cet exemple :

   #!/bin/sh
   remind - '*5' 10 Feb 1991 <<'EOF'
   BANNER %
   REM MON at 0:00 DURATION 192:0 MSG [today()] [trigeventstart()] [trigduration()]%
   EOF

La sortie est :

   1991-02-10 1991-02-04@00:00 48:00
   1991-02-11 1991-02-11@00:00 192:00
   1991-02-12 1991-02-11@00:00 168:00
   1991-02-13 1991-02-11@00:00 144:00
   1991-02-14 1991-02-11@00:00 120:00

Bien que l'événement du 04-02-1991 ait encore 24 heures restantes le 11-02-1991, la nouvelle occurrence du 11-02-1991 prend la priorité et est celle qui est déclenchée.

Je ne recommande pas de construire des événements sur plusieurs jours qui se chevauchent.

COLLAGE D'EXPRESSIONS

Une caractéristique extrêmement puissante de Remind est sa capacité de macro, ou "collage d'expressions".

Dans presque toutes les situations où Remind n'attend pas une expression, vous pouvez "coller" une expression. Pour ce faire, entourez l'expression de crochets. Par exemple :

REM [mydate] MSG foo

Cela évalue l'expression "mydate", où "mydate" est vraisemblablement une variable pré-calculée, puis "colle" le résultat dans la ligne de commande pour que le parseur la traite.

Si vous voulez un caractère littéral "[" pour une raison quelconque, utilisez simplement "[[". Par exemple :

        REM MSG Voici [[crochets carrés!

Une description formelle de ceci est : Lorsque Remind rencontre une expression "collée", il évalue l'expression, et coercit le résultat en une CHAÎNE. Il substitue ensuite la chaîne à l'expression collée, et continue l'analyse. Notez, cependant, que les expressions ne sont évaluées qu'une seule fois, pas récursivement. Ainsi, écrire :

["[a+b]"]

amène Remind à lire le jeton "[a+b]". Il n'interprète pas cela comme une expression collée. En fait, la seule façon d'obtenir un crochet gauche littéral dans un rappel est d'utiliser ["["].

Vous pouvez utiliser le collage d'expressions presque partout. Cependant, il existe quelques exceptions :

o
Si Remind attend une expression, comme dans la commande SET, ou la commande IF, vous ne devriez pas inclure de crochets. Par exemple, utilisez :
SET a 4+5
et non : 
SET a [4+5]
o
Vous ne pouvez pas utiliser le collage d'expressions pour le premier jeton d'une ligne. Par exemple, ce qui suit ne fonctionnera pas :
["SET"] a 1

Cette restriction est due au fait que Remind doit pouvoir déterminer sans ambiguïté le premier jeton d'une ligne pour les commandes de contrôle de flux (qui seront discutées plus tard).

En fait, si Remind ne peut pas déterminer le premier jeton sur une ligne, il suppose qu'il s'agit d'une commande REM. Si le collage d'expressions est utilisé, Remind suppose qu'il s'agit d'une commande REM. Ainsi, les trois commandes suivantes sont équivalentes :

REM 12 Nov 1993 AT 13:05 MSG BOO!
12 Nov 1993 AT 13:05 MSG BOO!
[12] ["Nov " + 1993] AT [12:05+60] MSG BOO!
o
Vous ne pouvez pas utiliser le collage d'expressions pour déterminer le type (MSG, CAL, etc.) d'une commande REM. Vous pouvez coller des expressions avant et après les mots-clés MSG, etc., mais pas faire quelque chose comme ceci :
        REM ["12 nov 1993 À 13:05 " + "MSG" + " BOO!"]

Cependant, comme échappatoire, la séquence SPECIAL type signifie la même chose que juste type où type est l'un des MSG, MSF, RUN, CAL, PS et PSFILE. Cela vous permet de faire quelque chose comme ceci :

        SET type "MSG"
        REM 12 nov 2024 SPECIAL [type] Bonjour

Vous pouvez l'utiliser pour contrôler les types de vos rappels en fonction des variables que vous définissez, de la manière dont Remind est appelé, etc.

PIÈGES COMMUNES AVEC LE COLLAGE D'EXPRESSIONS

N'oubliez pas que des espaces supplémentaires ne sont pas insérés lorsqu'une expression est collée. Ainsi, quelque chose comme :

REM[expression]MSG[expression]

échouera probablement.

Si vous utilisez une expression pour calculer un delta ou un retard, assurez-vous que le résultat est un nombre positif. Quelque chose comme :

REM +[mondelta] 12 nov 1993 MSG foo

échouera si mondelta s'avère être négatif.

COMMANDES DE CONTRÔLE DE FLUX

Remind dispose de commandes qui contrôlent le flux d'un script de rappel. Normalement, les scripts de rappel sont traités séquentiellement. Cependant, les commandes IF et associées vous permettent de traiter des fichiers conditionnellement, et de sauter des sections que vous ne voulez pas interpréter.

LA COMMANDE IF

La commande IF a la forme suivante :

IF expression
	commande-t
	commande-t...
ELSE
	commande-f
	commande-f...
ENDIF

Notez que les commandes sont présentées en retrait pour plus de clarté. De plus, la partie ELSE peut être omise. Les commandes IF peuvent être imbriquées jusqu'à une profondeur de 64, à travers tous les niveaux de INCLUDE.

Si l' expression est évaluée à un INT non nul, une DATE qui n'est pas le 1990-01-01, une TIME qui n'est pas 00:00, une DATETIME qui n'est pas 1990-01-01@00:00, ou une STRING non nulle, alors la partie IF est considérée comme vraie, et les commandes-t sont exécutées. Si l' expression est évaluée à zéro ou nulle, alors les commandes-f (si la partie ELSE est présente) sont exécutées.

Exemples :

IF defined("vouloir_fetes")
	INCLUDE /usr/share/remind/jours_feries
ENDIF
IF aujourdhui() > '1992/2/10'
	set rater_rdv "Vous l'avez manqué !"
ELSE
	set rater_rdv "Encore le temps..."
ENDIF

LA COMMANDE IFTTRIG

La commande IFTRIG est similaire à une commande IF, sauf qu'elle calcule un déclencheur (comme dans la commande REM), et est évaluée comme vraie si une commande REM correspondante se déclencherait. Exemples :

IFTRIG 1 Nov
	; Exécuté le 1er Nov
ELSE
	; Exécuté sauf le 1er Nov
ENDIF
IFTRIG 1 -1 OMET Sam Dim +4
	; Exécuté le dernier jour ouvrable du mois,
	; et les 4 jours ouvrables qui le précèdent
ELSE
	; Exécuté sauf ces jours-là
ENDIF

Notez que la commande IFTRIG calcule une date de déclenchement, qui peut être récupérée avec la fonction trigdate(). Vous pouvez utiliser tous les composants de déclenchement normaux, tels que UNTIL, delta, etc. dans la commande IFTRIG. Cependant, vous ne pouvez pas utiliser un spécificateur de type tel que CAL, MSG ou SATISFY ; tenter de le faire génère une erreur d'analyse.

FONCTIONS DÉFINIES PAR L'UTILISATEUR

En plus des fonctions intégrées, Remind vous permet de définir vos propres fonctions. La commande FSET fait cela pour vous :

FSET nom_fonction(args) expression

Nom_fonction est le nom de la fonction et suit la convention de nommage des variables. Args est une liste d'arguments séparés par des virgules, et expression est une expression. L' expression n'est pas évaluée au moment où la fonction est définie ; elle est plutôt évaluée à chaque fois que la fonction est appelée. Args peut être vide, auquel cas vous définissez une fonction ne prenant aucun paramètre. Voici quelques exemples :

FSET double(x) 2*x
FSET anneediff(date1, date2) annee(date1) - annee(date2)
FSET depuis(x) ord($Ty - x)

La dernière fonction est utile dans les rappels d'anniversaire. Par exemple :

REM 1 Nov +12 MSG L'anniversaire de Dean [depuis(1984)] est le %b.

Dean est né en 1984. L'exemple ci-dessus, le 1er novembre 1992, imprimerait :

Le 8ème anniversaire de Dean est aujourd'hui.

De même, la fonction est utile dans les rappels d'anniversaire. Par exemple :

        REM 4 juin MSG [depuis(1989)] anniversaire du massacre de la place Tiananmen

Remarques :

o
Si vous accédez à une variable dans l' expression qui ne se trouve pas dans la liste des arguments, la valeur globale (le cas échéant) est utilisée.
o
Les noms de fonctions et de paramètres sont significatifs sur 64 caractères.
o
La fonction value() accède toujours à la valeur globale d'une variable, même si elle porte le même nom qu'un argument. Par exemple :
fset fonction(x) value("x")
set x 1
set y fonction(5)

La séquence ci-dessus définit y à 1, qui est la valeur globale de x.

o
Les fonctions définies par l'utilisateur peuvent appeler d'autres fonctions, y compris d'autres fonctions définies par l'utilisateur. Les appels récursifs sont autorisés, mais ils doivent se terminer (par exemple, en utilisant un opérateur de court-circuit ou une fonction qui rompt la récursion) ou une erreur résultera après un certain nombre maximum d'appels récursifs (par défaut, 1000).
o
Si une fonction définie par l'utilisateur porte le même nom qu'une fonction intégrée, elle est ignorée et la fonction intégrée est utilisée. Pour éviter les conflits avec les futures versions de Remind (qui pourraient définir plus de fonctions intégrées), vous pourriez vouloir nommer toutes les fonctions définies par l'utilisateur en commençant par un tiret bas.
o
Si une fonction définie par l'utilisateur est définie dans un contexte où RUN est désactivé, alors chaque fois que cette fonction est appelée, RUN sera désactivé pendant son évaluation, même si elle est appelée à partir d'un contexte où RUN est activé.

Pour supprimer une fonction définie par l'utilisateur, utilisez FUNSET. Cela prend une liste de fonctions définies par l'utilisateur séparées par des espaces à supprimer. Par exemple, après la commande :

        FUNSET ma_fonction1 autre_fonction fonction_trois

il est garanti qu'aucune fonction définie par l'utilisateur nommée ma_fonction1, autre_fonction ou fonction_trois n'existera. Remind ne génère pas d'erreur si vous essayez de FUNSET une fonction définie par l'utilisateur inexistante ; il ne fait simplement rien dans ce cas.

Vous pouvez renommer une fonction définie par l'utilisateur avec FRENAME. Cela prend deux noms : un ancien nom et un nouveau nom. Considérez cette commande :

        FRENAME fonction_a fonction_b

Si fonction_a n'existe pas, la commande annule la définition de fonction_b si elle est définie. Cependant, si fonction_a existe, alors elle est renommée en fonction_b, et fonction_a n'est plus définie. Si fonction_b a été définie avant la commande FRENAME, alors cette ancienne définition est perdue.

Si l'un des arguments de la commande FRENAME est le nom d'une fonction intégrée, la commande échoue avec un message d'erreur et ne fait rien.

Si vous définissez une fonction définie par l'utilisateur, puis la redéfinissez plus tard, Remind émettra un avertissement. Si vous ne souhaitez pas cet avertissement, utilisez FUNSET pour supprimer la définition existante avant de redéfinir la fonction. Alternativement, vous pouvez utiliser un jeton « - » avant le nom de la fonction pour supprimer les avertissements « fonction redéfinie », comme dans l'exemple suivant :

        FSET - f(x) 2*x
        # Vous devez avoir un espace avant et après le "-"
        # Cela ne fonctionnera PAS :
        # FSET -f(x) 2*x

pour définir une fonction et supprimer tout avertissement de « fonction redéfinie ».

SAUVEGARDER ET RESTITUER LES FONCTIONS

Parfois, il est utile de redéfinir une fonction pour un bloc spécifique de rappels, mais de restaurer sa définition d'origine à la fin de ce bloc. Tout comme avec les variables, les fonctions peuvent être empilées et dépilées d'une pile interne. Voici un exemple :

        PUSH-FUNCS msgprefix
        FSET msgprefix(x) "Mon nouveau préfixe : "
        INCLUDE block_de_rappels.rem
        POP-FUNCS

Le fichier block_de_rappels.rem serait exécuté avec la fonction msgprefix définie ci-dessus. Après le POP-FUNCS, msgprefix serait restauré à sa définition précédente s'il en avait une, ou simplement annulé s'il n'était pas précédemment défini.

La commande PUSH-FUNCS prend une liste de noms de fonctions séparés par des espaces. Toutes les fonctions définies par l'utilisateur nommées seront sauvegardées dans une pile interne. Vous pouvez même empiler des noms qui ne sont définis comme aucune fonction.

Après qu'un nom de fonction a été empilé, Remind n'émettra pas d'avertissement si vous le redéfinissez, car on suppose que le but de l'empiler en premier lieu est de le redéfinir.

La commande POP-FUNCS restaure les définitions de toutes les fonctions définies par l'utilisateur dans la commande PUSH-FUNCS correspondante. Si des fonctions indéfinies ont été empilées, alors POP-FUNCS rend à nouveau ces fonctions indéfinies. Voici un autre exemple :

        FUNSET a
        FSET b(x) 2*x
        REM MSG [b(3)]   # Sortie 6
        PUSH-FUNCS a b
        FSET a(x) 22*x
        FSET b(x) 3*x
        REM MSG [a(3)] [b(3)] # Sortie 66 9
        POP-FUNCS
        REM MSG [a(3)]   # Fonction indéfinie "a"
        REM MSG [b(3)]   # Sortie 6

PLANIFICATION PRÉCISE

Le mot-clé WARN permet un contrôle précis des avertissements avancés d'une manière plus flexible que le mécanisme delta. Il doit être suivi du nom d'une fonction définie par l'utilisateur, fonction_alerte.

Si une fonction_alerte est fournie, elle doit accepter un argument de type INT. Remind ignore tout delta et appelle plutôt fonction_alerte successivement avec les arguments 1, 2, 3, ...

La valeur de retour n de fonction_alerte est interprétée comme suit :

o
Si n est positif, alors le rappel est déclenché exactement n jours avant sa date de déclenchement.
s="permalink" href="#o~27">o
Si n est négatif, alors il est déclenché n jours avant sa date de déclenchement, sans compter les jours OMITted.

Par exemple, supposons que vous souhaitiez être averti de la fête nationale américaine 5, 3 et 1 jour à l'avance. Vous pourriez utiliser ceci:

FSET _wfun(x) choose(x, 5, 3, 1, 0)
REM 4 July WARN _wfun MSG American Independence Day is %b.

NOTES

1
Si une erreur se produit lors de l'évaluation de warn_function, alors Remind arrête de l'appeler et émet simplement le rappel à sa date de déclenchement.
2
Si les valeurs absolues des valeurs de retour de warn_function ne sont pas décroissantes de manière monotone, Remind arrête de l'appeler et émet le rappel à sa date de déclenchement.
3
Warn_function devrait (par souci de style) retourner 0 comme valeur finale de sa séquence de valeurs de retour. Cependant, un rappel sera toujours déclenché à sa date de déclenchement, indépendamment de ce que fait warn_function.

Similairement à WARN, le mot-clé SCHED permet un contrôle précis de la planification des rappels chronométrés. Il doit être suivi du nom d'une fonction définie par l'utilisateur, sched_function.

Si une fonction de planification est fournie, elle doit prendre un argument de type INT. Plutôt que d'utiliser l'heure AT, le délai temporel delta et la répétition temporelle repeat, Remind appelle la fonction de planification pour déterminer quand déclencher le rappel. La première fois que le rappel est mis en file d'attente, la fonction de planification est appelée avec un argument de 1. Chaque fois que le rappel est déclenché, il est replanifié en appelant à nouveau la fonction de planification. À chaque appel, l'argument est incrémenté d'un.

La valeur de retour de la fonction de planification doit être un INT ou un TIME. Si la valeur de retour est un TIME, alors le rappel est replanifié pour se déclencher à ce moment-là. S'il s'agit d'un entier positif n, alors le rappel est replanifié pour se déclencher à l'heure de déclenchement précédente plus n minutes. Enfin, s'il s'agit d'un entier négatif ou de zéro, alors le rappel est replanifié pour se déclencher n minutes avant l'heure AT. Notez qu'il doit y avoir une clause AT pour que la clause SCHED ait un effet.

Voici un exemple:

FSET _sfun(x) choose(x, -60, 30, 15, 10, 3, 1, 1, 1, 1, 0)
REM AT 13:00 SCHED _sfun MSG foo

Le rappel serait d'abord déclenché 60 minutes avant 13h00, soit à 12h00. Il serait ensuite déclenché 30 minutes plus tard, à 12h30. Puis, il serait déclenché à 12h45, 12h55, 12h58, 12h59, 13h00, 13h01 et 13h02.

NOTES

1
Si une erreur se produit lors de l'évaluation de sched_func, alors Remind revient à l'utilisation de l'heure AT et des valeurs delta et repeat, et n'appelle plus jamais sched_func.
2
Si le traitement de sched_func donne une heure antérieure à l'heure système actuelle, elle est appelée à plusieurs reprises avec un argument croissant jusqu'à ce qu'elle donne une valeur supérieure ou égale à l'heure actuelle. Cependant, si la séquence de valeurs calculées pendant la répétition n'est pas strictement croissante, alors Remind revient au comportement par défaut et n'appelle plus jamais sched_func.
3
Il est tout à fait possible en utilisant sched_func de continuer à déclencher un rappel même après l'heure AT. Cependant, il n'est pas possible de reprogrammer un rappel après minuit - aucun franchissement des limites de jour n'est autorisé. De plus, il est tout à fait possible de ne pas déclencher un rappel à l'heure AT lorsque vous utilisez une fonction de planification. Cependant, si votre fonction de planification est terminée (pour les raisons 1 et 2) avant l'heure AT du rappel, elle sera déclenchée à l'heure AT, car le traitement normal prend le relais.
4
Vos fonctions de planification devraient (par souci de style) retourner 0 lorsqu'aucune planification supplémentaire n'est requise. Voir l'exemple.
5
Toutes les fonctions de planification sont évaluées après que l'intégralité du script Remind a été lue. Ainsi, les définitions de fonctions qui sont en vigueur à la fin du script sont utilisées.

LA CLAUSE SATISFY

La forme de REM qui utilise SATISFY est la suivante:

REM trigger SATISFY expr

Voici comment cela fonctionne: Remind calcule d'abord une date de déclenchement, de manière normale. Ensuite, il définit trigdate() à la date de déclenchement calculée. Il évalue alors expr. Si le résultat n'est pas la chaîne nulle ou zéro, le traitement se termine. Sinon, Remind calcule la prochaine date de déclenchement et re-teste expr. Cette itération continue jusqu'à ce que expr évalue à non-zéro ou non-nul, ou jusqu'à ce que la limite d'itération spécifiée avec l'option de ligne de commande -x soit atteinte.

Si expr n'est pas satisfaite, alors trigvalid() est mis à 0 et le message d'erreur "Can't compute trigger" est émis. Sinon, trigvalid() est mis à 1.

Ceci est vraiment utile uniquement si expr implique un appel à trigdate() ou des fonctions ou variables système associées; sinon, expr ne changera pas pendant que Remind itère. En fait, si expr n'est pas une constante et n'appelle pas trigdate() ou des fonctions ou variables système associées, alors Remind émettra un avertissement.

Un exemple de l'utilité de SATISFY: Supposons que vous souhaitiez être averti de chaque vendredi 13. Votre première tentative pourrait être:

# WRONG!
REM Fri 13 +2 MSG Friday the 13th is %b.

Mais cela ne fonctionnera pas. Ce rappel se déclenche le premier vendredi du mois ou après le 13 de chaque mois. La manière de le faire est avec une séquence plus compliquée:

REM 13 SATISFY wkdaynum(trigdate()) == 5
IF trigvalid()
	REM [trigdate()] +2 MSG \
	Friday the 13th is %b.
ENDIF

Vous pouvez écrire l'instruction REM un peu plus concisément:

REM 13 SATISFY $Tw == 5

Voyons comment cela fonctionne. La clause SATISFY itère à travers tous les 13 des mois successifs, jusqu'à ce qu'une date de déclenchement soit trouvée dont le jour de la semaine est le vendredi (== 5). Si une date valide a été trouvée, nous utilisons la date de déclenchement calculée pour configurer le rappel suivant.

Nous aurions également pu écrire:

REM Fri SATISFY day(trigdate()) == 13

mais cela entraînerait plus d'itérations, puisque les "vendredis" se produisent plus souvent que les "13 du mois."

Voici un autre exemple: Supposons que vous vouliez être rappelé de quelque chose le 15 janvier, avril, juillet et octobre. Vous pourriez faire quatre rappels séparés, ou vous pourriez utiliser:

        REM 15 SATISFY [isany($Tm, 1, 4, 7, 10)] MSG 15th Reminder!

Cette technique consistant à utiliser une commande REM pour calculer une date de déclenchement à utiliser par une autre commande est très puissante. Par exemple, supposons que vous vouliez OMETTRE le jour du travail, qui est le premier lundi de septembre. Vous pourriez utiliser:

# Note: SATISFY 1 est un idiome pour "ne rien faire"
REM Mon 1 Sept SATISFY 1
OMIT [trigdate()]

ATTENTION: Ceci omet seulement le prochain jour du travail, pas tous les jours du travail à venir. Cela pourrait entraîner des résultats étranges, car le contexte OMIT peut changer en fonction de la date actuelle. Par exemple, si vous utilisez la commande suivante après les commandes ci-dessus:

REM Mon AFTER msg hello

le résultat ne sera pas celui attendu. Considérez la production d'un calendrier pour septembre 1992. Le jour du travail était le lundi 7 septembre 1992. Cependant, lorsque Remind arrive au calcul du déclenchement pour le mardi 8 septembre 1992, la commande OMIT omettra maintenant le jour du travail pour 1993, et la commande "Mon AFTER" ne sera pas déclenchée. (Mais voir la description de SCANFROM dans la section "DÉTAILS SUR LE CALCUL DES DÉCLENCHEMENTS.")

Il est probablement préférable de ne pas calculer les dates de déclenchement OMIT à moins que vous ne gardiez ces pièges à l'esprit.

Pour les versions de Remind à partir de 03.00.07, vous pouvez inclure une clause MSG, RUN, etc. dans une clause SATISFY comme suit:

REM trigger_stuff SATISFY [expr] MSG body

Notez que pour ce cas uniquement, expr après SATISFY doit être entouré de crochets. Il doit venir après tous les autres composants du déclenchement, et immédiatement avant le mot-clé MSG, RUN, etc. Si expr ne peut pas être satisfaite, alors le rappel n'est pas déclenché.

Ainsi, l'exemple "vendredi 13" peut être exprimé plus compactement comme suit:

REM 13 +2 SATISFY [$Tw == 5] MSG Friday the 13th is %b.

Et vous pouvez déclencher un rappel les lundis, mercredis et jeudis tombant les jours impairs du mois avec ce qui suit:

REM Mon Wed Thu SATISFY [$Td %2 ] MSG Here it is!!!

Notez que SATISFY et OMITFUNC peuvent souvent être utilisés pour résoudre le même problème, bien que de différentes manières. Parfois, un SATISFY est plus clair et parfois un OMITFUNC; expérimentez et utilisez ce qui semble le plus clair.

DÉCLENCHEMENTS-POTENTIELLEMENT-INCOMPUTABLES

Occasionnellement, vous souhaiterez peut-être supprimer les avertissements "Can't compute trigger" pour les rappels pour lesquels une date de déclenchement ne peut pas être calculée. Par exemple, le rappel suivant est déclenché un lundi qui n'est pas un jour férié si le mardi suivant est un jour férié:

        REM Mon SKIP SATISFY [isomitted($T+1)] MSG Work between holidays

Cependant, s'il n'y a pas de lundis après la date d'aujourd'hui qui satisfont la condition, Remind affichera l'erreur "Can't compute trigger". Pour la supprimer, utilisez le mot-clé MAYBE-UNCOMPUTABLE:

        REM MAYBE-UNCOMPUTABLE Mon SKIP SATISFY [isomitted($T+1)] MSG Work between holidays

Il est presque jamais approprié d'utiliser MAYBE-UNCOMPUTABLE, mais il est fourni pour ces rares occasions où il a du sens. Si vous utilisez MAYBE-UNCOMPUTABLE à l'intérieur de la fonction evaltrig(), alors les déclencheurs non déclenchables retournent -1. Par exemple:

        SET a evaltrig("MAYBE-UNCOMPUTABLE Mon SKIP OMIT Mon")

définira a à -1.

LA COMMANDE DUMPVARS

La commande DUMPVARS affiche les valeurs des variables en mémoire. Son format est :

La commande ERRMSG a le format suivant :

Le corps est passé à travers le filtre de substitution (avec une date de déclenchement implicite de today()) et imprimé sur le flux de sortie d'erreur. Exemple :

IF ! defined("critical_var")
	ERRMSG Vous devez fournir une valeur pour "critical_var"
	EXIT
ENDIF

LA COMMANDE EXIT

L'exemple ci-dessus montre également l'utilisation de la commande EXIT. Cela provoque une sortie inconditionnelle du traitement du script. Tous les rappels programmés mis en file d'attente sont supprimés. Si vous êtes en mode calendrier (décrit ci-dessous), le traitement du calendrier est abandonné.

Si vous fournissez une expression de type INT après la commande EXIT, elle est retournée au programme appelant en tant que code de sortie. Sinon, un code de sortie de 99 est retourné.

Cette commande consiste simplement en le mot FLUSH sur une ligne seule. La commande vide les flux de sortie standard et d'erreur standard utilisés par Remind. Ce n'est pas très utile pour la plupart des gens, mais peut être utile si vous exécutez Remind comme sous-processus d'un autre programme et que vous souhaitez utiliser des tubes pour la communication.

MODE AGENDA SORTIE JSON

Si vous fournissez l'argument --json, Remind génère une sortie JSON au lieu de la sortie texte normale. La sortie JSON consiste en un seul tableau JSON de zéro ou plusieurs objets. Il existe trois types possibles d'objets dans le tableau :

banner
L'objet banner, s'il est présent, sera le premier objet du tableau. Il y aura au plus un objet banner. Il contient une seule clé, banner, dont la valeur est la bannière que Remind imprimerait normalement en Mode Agenda.
noreminders
L'objet noreminders, s'il est présent, sera le dernier objet du tableau. Il y aura au plus un objet noreminders. Il contient une seule clé, noreminders, dont la valeur est la phrase "Pas de rappels.", éventuellement localisée dans une autre langue.
event
Tous les autres objets du tableau sont des objets event. Ce sont des objets JSON qui contiennent toutes les clés décrites dans la section "ENTRÉES DE CALENDRIER" de la page man rem2ps(1). Cependant, les clés calendar_body, plain_body et raw_body ne seront pas présentes.

La sortie JSON peut être utilisée par une interface pour afficher une jolie liste de rappels en Mode Agenda. La fonctionnalité "afficher les rappels d'aujourd'hui" de tkremind utilise la sortie JSON.

MODE CALENDRIER

Si vous fournissez l'option de ligne de commande -c, -s ou -p, alors Remind s'exécute en "mode calendrier". Dans ce mode, Remind interprète le script de manière répétée, effectuant une itération complète du fichier pour chaque jour du calendrier. Les rappels qui se déclenchent sont enregistrés dans des tampons internes, puis insérés dans le calendrier aux endroits appropriés.

Si vous fournissez également l'option -a, alors Remind n'inclura pas les rappels chronométrés dans le calendrier.

L'option -p est utilisée conjointement avec le programme Rem2PS pour produire un calendrier au format PostScript. Par exemple, la commande suivante enverra du code PostScript à la sortie standard :

remind -p .reminders | rem2ps

Vous pouvez imprimer un calendrier PostScript en le redirigeant vers la commande lpr.

Si vous avez un script de rappel appelé ".reminders" et que vous exécutez cette commande :

remind -c .reminders jan 1993

alors Remind exécute le script 31 fois, une fois pour chaque jour de janvier. Chaque fois qu'il exécute le script, il incrémente la valeur de today(). Tous les rappels dont la date de déclenchement correspond à today() sont entrés dans le calendrier.

Les rappels de type MSG et CAL, par défaut, ont leur corps entier inséré dans le calendrier. Les rappels de type RUN ne sont normalement pas insérés dans le calendrier. Cependant, si vous entourez une partie du corps de la séquence %"...%", seule cette partie est insérée. Par exemple, considérez ce qui suit :

REM 6 Jan MSG %"L'anniversaire de Dianne%" est %b

En mode agenda, Remind imprimerait "L'anniversaire de Dianne est aujourd'hui" le 6 janvier. Cependant, en mode calendrier, seul le texte "L'anniversaire de Dianne" est inséré dans la case du 6 janvier.

Si vous utilisez explicitement la séquence %"...%" dans un rappel de type RUN, alors le texte entre les délimiteurs est inséré dans le calendrier. Si vous utilisez la séquence %"%" dans un rappel de type MSG ou CAL, aucune entrée de calendrier n'est produite pour ce rappel.

PRÉSERVATION DES VARIABLES

Étant donné que Remind itère sur le script pour chaque jour du calendrier, les opérations lentes peuvent réduire considérablement la vitesse de production d'un calendrier.

Par exemple, supposons que vous définissiez les variables "me" et "hostname" comme suit :

SET me shell("whoami")
SET hostname shell("hostname")

Normalement, Remind efface toutes les variables entre les itérations en mode calendrier. Cependant, si certaines variables sont lentes à calculer et ne changeront pas entre les itérations, vous pouvez "préserver" leurs valeurs avec la commande PRESERVE. De plus, comme les définitions de fonctions sont préservées entre les itérations du calendrier, il n'est pas nécessaire de les redéfinir à chaque itération. Ainsi, vous pourriez utiliser la séquence suivante :

IF ! defined("initialized")
	set initialized 1
	set me shell("whoami")
	set hostname shell("hostname")
	fset func(x) complex_expr
	preserve initialized me hostname
ENDIF

L'opération est la suivante : lors de la première itération du script, "initialized" n'est pas défini. Par conséquent, les commandes entre IF et ENDIF sont exécutées. La commande PRESERVE garantit que les valeurs de initialized, me et hostname sont préservées pour les itérations suivantes. Lors de l'itération suivante, les commandes sont ignorées, car initialized est resté défini. Ainsi, les opérations coûteuses en temps qui ne dépendent pas de la valeur de today() ne sont effectuées qu'une seule fois.

La plupart des variables système (celles dont le nom commence par '$') sont automatiquement préservées entre les itérations du calendrier.

Notez que pour des raisons d'efficacité, Remind met en cache le script de rappel (et tous les fichiers INCLUDEd) en mémoire lors de la production d'un calendrier.

Les rappels chronométrés sont triés et placés dans le calendrier par ordre chronologique. Ceux-ci sont suivis par les rappels non chronométrés. Remind place automatiquement l'heure des rappels chronométrés dans le calendrier selon l'option de ligne de commande -b. Les rappels en mode calendrier sont triés comme si l'option -g avait été utilisée ; vous pouvez modifier l'ordre de tri en mode calendrier en utilisant explicitement l'option -g pour spécifier un ordre différent de celui par défaut.

EXÉCUTION RÉPÉTÉE

Si vous fournissez un paramètre repeat sur la ligne de commande et que vous n'utilisez pas les options -c, -p ou -s, Remind fonctionne de manière similaire au mode calendrier. Il exécute le script de rappel de manière répétée, en incrémentant today() à chaque itération. Les mêmes règles concernant la préservation des variables et des définitions de fonctions s'appliquent. Notez que l'utilisation de repeat sur la ligne de commande active également l'option -q et désactive toute option -z. Par exemple, si vous voulez voir comment Remind se comportera pendant la semaine prochaine, vous pouvez taper :

remind .reminders '*7'

Si vous voulez imprimer les dates des 1000 prochains jours, utilisez :

(echo 'banner %'; echo 'msg [today()]%') | remind - '*1000'

INITIALISATION DES VARIABLES SUR LA LIGNE DE COMMANDE

L'option -i est utilisée pour initialiser des variables sur la ligne de commande de Remind. Le format est -ivar=expr, où expr est une expression valide. Notez que vous devrez peut-être utiliser des guillemets ou des échappements pour empêcher le shell d'interpréter les caractères spéciaux dans expr. Vous pouvez avoir autant d'options -i que vous le souhaitez sur la ligne de commande, et elles sont traitées dans l'ordre. Ainsi, si une variable est définie dans une option -i, elle peut être référencée par les options -i suivantes.

Notez que si vous fournissez une date sur la ligne de commande, elle n'est pas analysée tant que toutes les options n'ont pas été traitées. Ainsi, si vous utilisez today() dans l'une des expressions -i, elle retournera la même valeur que realtoday() et non la date fournie sur la ligne de commande.

Toutes les variables définies sur la ligne de commande sont préservées comme avec la commande PRESERVE.

Vous ne devez pas avoir d'espaces entre l'option -i et le signe égal ; sinon, des noms de variables étranges seront créés qui ne pourront être accessibles qu'avec les fonctions value() ou defined().

Vous pouvez également définir une fonction sur la ligne de commande en utilisant :

-ifunc(args)=definition

Assurez-vous de protéger les caractères spéciaux de l'interprétation par le shell.

EN SAVOIR PLUS SUR POSTSCRIPT

Les rappels PS et PSFILE passent directement du code PostScript à t

PostScript

Les rappels de type PS et PSFILE sont similaires aux rappels de type REM, mais au lieu d'imprimer du texte, ils insèrent du code PostScript dans la sortie de l'imprimante. Ils diffèrent en ce que le rappel de type PS transmet son corps directement à la sortie PostScript (après traitement par le filtre de substitution), tandis que le corps du rappel de type PSFILE doit simplement consister en un nom de fichier. Le programme Rem2PS ouvrira le fichier nommé dans le rappel de type PSFILE et inclura son contenu dans la sortie PostScript.

Les rappels de type PostScript pour une journée donnée sont inclus dans la sortie PostScript dans l'ordre de priorité trié. Notez que l'ordre des commandes PostScript a un impact *majeur* sur l'apparence des calendriers. Par exemple, un code PostScript pour ombrer une boîte de calendrier obliterateda un code pour dessiner un symbole de lune si le code du symbole de lune est placé dans le calendrier en premier. Pour cette raison, vous ne devez pas fournir de priorités aux rappels de type PS ou PSFILE; vous devez plutôt vous assurer qu'ils apparaissent dans le script de rappel dans le bon ordre. Le code PostScript doit dessiner les objets en partant de l'arrière-plan vers le premier plan, de sorte que les objets du premier plan recouvrent correctement ceux de l'arrière-plan. Si vous priorisez ces rappels et exécutez le script en utilisant l'ordre de tri décroissant pour les priorités, la sortie PostScript ne fonctionnera pas.

Tout le code PostScript pour une date donnée est encapsulé dans une paire save-restore. Cependant, si plusieurs rappels de type PostScript sont déclenchés pour une seule journée, chaque section de PostScript n'est pas encapsulée dans une paire save-restore - au lieu de cela, l'intégralité du corps du PostScript inclus est encapsulée.

Les rappels de type PostScript sont exécutés par l'imprimante PostScript avant toute entrée de calendrier normale. Ainsi, les entrées de calendrier normales recouvriront les rappels de type PostScript, vous permettant de créer des arrière-plans ombrés ou graphiques pour des jours particuliers.

Avant d'exécuter votre code PostScript, l'origine du système de coordonnées PostScript est positionnée au coin inférieur gauche de la "boîte" du calendrier représentant today(). Cet emplacement est exactement au milieu de l'intersection des lignes noires inférieure et gauche délimitant la boîte - vous devrez peut-être tenir compte de l'épaisseur de ces lignes lors du calcul des positions.

Plusieurs variables PostScript sont disponibles pour le code PostScript que vous fournissez. Toutes les variables de distance et de taille sont en unités PostScript (1/72 pouce). Les variables sont :

LineWidth
La largeur des lignes de grille noires formant le calendrier.
Border
La bordure entre le centre des lignes de grille et l'espace utilisé pour imprimer les entrées du calendrier. Cette bordure est normalement un espace vide.
BoxWidth et BoxHeight
La largeur et la hauteur de la boîte du calendrier, de centre à centre des lignes de grille noires.
InBoxHeight
La hauteur du centre de la ligne de grille noire inférieure au sommet de la zone d'entrée du calendrier normale. L'espace à partir d'ici jusqu'au sommet de la boîte est utilisé uniquement pour dessiner le numéro du jour.
/DayFont, /EntryFont, /SmallFont, /TitleFont et /HeadFont
Les polices utilisées pour dessiner les numéros de jour, les entrées du calendrier, les petits calendriers, le titre du calendrier (mois, année) et les en-têtes des jours de la semaine, respectivement.
DaySize, EntrySize, TitleSize et HeadSize
Les tailles des polices ci-dessus. (La taille de la police du petit calendrier n'est *pas* définie ici.) Par exemple, si vous vouliez imprimer la date hébraïque à côté du numéro de jour normal dans le calendrier, utilisez :
REM PS Border BoxHeight Border sub DaySize sub moveto \
   /DayFont findfont DaySize scalefont setfont \
   ([hebday(today())] [hebmon(today())]) show
Notez comment /DayFont et DaySize sont utilisés.

Notez que si vous fournissez du code PostScript, il est possible de produire des fichiers PostScript invalides. Testez toujours votre PostScript soigneusement avec un visualiseur PostScript avant de l'envoyer à l'imprimante. Vous ne devez utiliser aucun commentaire de structuration de document dans votre code PostScript.

MODE DAEMON

Si vous utilisez l'option de ligne de commande -z, Remind s'exécute en "mode daemon". Dans ce mode, aucun rappel "normal" n'est émis. Au lieu de cela, seuls les rappels chronométrés sont collectés et mis en file d'attente, puis émis chaque fois qu'ils atteignent leur heure de déclenchement.

De plus, Remind se réveille toutes les quelques minutes pour vérifier la date de modification du script de rappel (le nom de fichier fourni sur la ligne de commande). Si Remind détecte que le script a changé, il s'exécute à nouveau en mode daemon et interprète le script modifié. Si Remind a été compilé avec le support de inotify(7), alors si le script de rappel sur la ligne de commande est réellement un répertoire, Remind s'exécute également s'il détecte un changement dans les fichiers du répertoire.

En mode daemon, Remind relit également le script de rappel lorsqu'il détecte que la date du système a changé.

En mode daemon, Remind se comporte comme si l'option -f avait été utilisée, donc pour s'exécuter en mode daemon en arrière-plan, utilisez :

remind -z .reminders &

Si vous utilisez sh ou bash, vous devrez peut-être utiliser la commande "nohup" pour vous assurer que le daemon n'est pas tué lorsque vous vous déconnectez.

MODE PURGE

Si vous fournissez l'option de ligne de commande -j, Remind s'exécute en *mode purge*. Dans ce mode, il essaie de purger les rappels expirés de vos fichiers de rappels.

En mode purge, Remind lit votre fichier de rappel et crée un nouveau fichier en ajoutant ".purged" au nom du fichier d'origine. Notez que Remind ne modifie *jamais* votre fichier d'origine ; il crée toujours un nouveau fichier .purged.

Si vous invoquez Remind contre un répertoire au lieu d'un fichier, un fichier .purged est créé pour chaque fichier *.rem dans le répertoire.

Normalement, Remind ne crée pas de fichiers .purged pour les fichiers INCLUS. Cependant, si vous fournissez un argument numérique après -j, alors Remind créera des fichiers .purged pour le niveau spécifié d'INCLUDE. Par exemple, si vous invoquez Remind avec l'argument -j2, des fichiers .purged seront créés pour le fichier (ou répertoire) spécifié sur la ligne de commande, tous les fichiers inclus par eux, et tous les fichiers inclus par ces fichiers. Cependant, les fichiers .purged ne seront pas créés pour les fichiers INCLUDE de troisième niveau ou plus.

Déterminer quels rappels ont expiré est extrêmement délicat. Remind fait de son mieux, mais vous devriez toujours comparer le fichier .purged au fichier d'origine et fusionner manuellement les modifications.

Remind annote le fichier .purged comme suit :

Un rappel expiré est précédé de : #!P: Expired:

Dans les situations où Remind ne peut pas déterminer de manière fiable que quelque chose a expiré, vous pouvez voir les commentaires suivants insérés avant la ligne problématique :

   #!P: Cannot purge SATISFY-type reminders
   #!P: The next IF evaluated false...
   #!P: REM statements in IF block not checked for purging.
   #!P: The previous IF evaluated true.
   #!P: REM statements in ELSE block not checked for purging
   #!P: The next IFTRIG did not trigger.
   #!P: REM statements in IFTRIG block not checked for purging.
   #!P: Next line has expired, but contains expression...  please verify
   #!P: Next line may have expired, but contains non-constant expression
   #!P: or a relative SCANFROM clause
   #!P! Could not parse next line: Some-Error-Message-Here
   #!P! Problem calculating trigger date

Remind annote toujours les fichiers .purged avec des lignes commençant par "#!P". Si de telles lignes sont rencontrées dans le fichier *d'origine*, elles ne sont pas copiées dans le fichier .purged.

Si vous utilisez le drapeau "Hush" -h en conjonction avec le drapeau "Purge" -j, alors Remind ne crée *aucun* des commentaires diagnostiques listés ci-dessus. Au lieu de cela, la seule modification qu'il apporte au fichier .purged est de marquer les rappels expirés avec "#!P: Expired".

EXPRESSIONS NON CONSTANTES

En mode Purge, Remind ne marquera pas un énoncé REM comme expiré si sa spécification de déclenchement contient une expression non constante. Une expression non constante est définie comme une expression dont la valeur peut différer d'une exécution à l'autre, généralement parce qu'elle dépend de la date actuelle, mais aussi si elle dépend de quelque chose de l'environnement (comme la sortie de la fonction shell()).

L'utilisation de l'un des éléments suivants dans une expression amène Remind à la considérer comme non constante :

o
Une variable globale à laquelle a été assigné le résultat d'une expression non constante, ou qui a reçu une valeur dans un *contexte non constant* (qui sera décrit plus tard).
o
Une variable système
o
Certaines fonctions intégrées qui dépendent de la date actuelle (par exemple, today()) ou de l'environnement (par exemple, shell()).

De plus, aux fins de l'expiration sûre des rappels en mode Purge, Remind considère les éléments suivants comme non constants :

o
L'utilisation d'une OMITFUNC
o
L'utilisation d'une SCANFROM relative

Chaque fois qu'une variable se voit assigner une valeur, Remind suit si l'expression dont la valeur lui a été assignée est constante ou non constante. De plus, les variables qui sont assignées dans un contexte non constant sont toujours supposées être non constantes. Un contexte non constant est le code dans la portée d'une instruction IF où l'expression IF est non constante.

Voici quelques exemples qui devraient clarifier les choses :

        SET d '2025-06-01'        # d est constant
        REM [d] MSG Hello!        # éligible à la purge
        SET d today() - 3         # d est non constant
        REM [d] MSG Hello!        # non éligible à la purge
        IF wkdaynum(today()) == 3
            set d '2025-06-01'    # d est non constant
        ELSE
            set d '2026-01-01'    # d est non constant
        ENDIF
        SET d '2025-06-01'        # d est constant
        IF today() > today() + 3  # Cette branche n'est jamais prise, mais...
            SET d '2029-01-01'    # d est toujours marqué non constant
        ENDIF
        # Bien qu'ici d soit toujours '2025-06-01', il est marqué
        # non constant car pour Remind, c

VARIABLES

Les variables sont des chaînes de caractères qui peuvent contenir des valeurs calculées. Vous pouvez utiliser des variables pour stocker des valeurs temporaires ou pour rendre votre script plus lisible.

Les variables sont définies à l'aide de l'instruction SET. Par exemple, pour définir une variable nommée myvar à la valeur « hello »:

    SET myvar = "hello"

Les variables peuvent être utilisées dans votre script en les précédant du signe dollar ($). Par exemple, pour afficher la valeur de myvar:

    MSG $myvar

Les variables peuvent également être utilisées dans des expressions. Par exemple, pour ajouter la valeur de myvar à 10:

    SET count = $myvar + 10

Les variables sont considérées comme non constantes si elles sont définies dans le corps d'une instruction IF qui dépend de la date d'aujourd'hui. Par exemple:

    IF today() == 1993-01-01
        SET var = "This is only set on Jan 1st"

Dans ce cas, le corps de l'IF *pourrait* avoir été exécuté en fonction de la date d'aujourd'hui.

Notez que dans la portée IF...ENDIF, toutes les affectations sont non constantes car le flux de code dépend de la date d'aujourd'hui, qui peut changer lors des prochaines exécutions de Remind. Si vous voulez forcer une variable à être traitée comme constante, quoi qu'il arrive, utilisez la commande suivante juste avant d'utiliser la variable:

    SET var const(var)

Les variables initialisées sur la ligne de commande avec le drapeau -i sont *toujours* considérées comme non constantes.

Si vous avez un rappel expiré que vous ne voulez pour aucune raison jamais purger, utilisez simplement la fonction intégrée nonconst quelque part dans le déclencheur. Par exemple:

    REM 1992-01-01 MSG Ceci sera purgé après le 1er janvier 1992
    REM [nonconst('1992-01-01')] MSG Ceci ne sera jamais purgé
    REM Wed UNTIL 1993-12-31 MSG Ceci sera purgé après 1993
    REM Wed UNTIL [nonconst('1993-12-31')] MSG Jamais purgé

Le drapeau de débogage n imprime un message sur la sortie d'erreur standard chaque fois que Remind décide qu'une expression est non constante. Cela peut produire une grande quantité de sortie. Donc, si vous voulez savoir pourquoi Remind considère une expression spécifique comme non constante, il est préférable d'utiliser DEBUG +n avant et DEBUG -n après pour limiter la quantité de sortie.

TRI DES RAPPELS

L'option -g fait en sorte que Remind trie les rappels par date de déclenchement, heure et priorité avant de les émettre. Notez que les rappels sont toujours calculés dans l'ordre où ils apparaissent dans le script. Cependant, plutôt que d'être émis immédiatement, ils sont sauvegardés dans un tampon interne. Lorsque Remind a fini de traiter le script, il émet les rappels sauvegardés dans l'ordre trié. L'option -g peut être suivie de jusqu'à quatre caractères qui doivent tous être « a » ou « d ». Le premier caractère spécifie l'ordre de tri par date de déclenchement (ascendant ou descendant), le second spécifie l'ordre de tri par heure de déclenchement et le troisième spécifie l'ordre de tri par priorité. Si le quatrième caractère est « d », les rappels non datés sont triés avant les rappels datés. Par défaut, tous les champs sont triés par ordre ascendant et les rappels non datés sont triés après les rappels datés.

En ordre ascendant, les rappels les plus imminents sont émis en premier. L'ordre descendant est l'inverse. Les rappels sont toujours triés par date de déclenchement, et les rappels ayant la même date de déclenchement sont ensuite triés par heure de déclenchement. Si deux rappels ont la même date et la même heure, la priorité est utilisée pour départager. Les rappels ayant la même date, heure et priorité sont émis dans l'ordre où ils ont été rencontrés.

Vous pouvez définir une fonction utilisateur appelée SORTBANNER qui prend un argument de type DATE. En mode tri, la séquence suivante se produit:

Si Remind constate que le prochain rappel à émettre a une date de déclenchement différente du précédent (ou s'il s'agit du premier à émettre), alors SORTBANNER est appelé avec la date de déclenchement comme argument. Le résultat est converti en chaîne de caractères et passé à travers le filtre de substitution avec la date de déclenchement appropriée. Le résultat est ensuite affiché.

Voici un exemple - considérez le fragment suivant:

# Désactiver la bannière normale
BANNER %
REM 11 March 1993 ++1 MSG Pas si important
REM 17 March 1993 ++7 MSG Loin dans le futur
REM 10 March 1993 MSG Rappel important
REM 11 March 1993 ++1 MSG Pas si important - B
FSET sortbanner(x) iif(x == today(), \
	"***** CHOSES À FAIRE AUJOURD'HUI *****", \
	"----- Choses à faire %b -----")

L'exécution de ce script avec l'option -gaa le 10 mars 1993 produit la sortie suivante:

***** CHOSES À FAIRE AUJOURD'HUI *****
Rappel important
----- Choses à faire demain -----
Pas si important
Pas si important - B
----- Choses à faire dans 7 jours -----
Loin dans le futur

Vous pouvez utiliser la fonction intégrée args() pour déterminer si SORTBANNER a été défini ou non. (Cela pourrait être utilisé, par exemple, pour fournir une définition par défaut pour SORTBANNER dans un fichier système inclus à la fin du fichier de l'utilisateur.) Voici un exemple:

# Créer une fonction sortbanner par défaut si elle n'a pas déjà été
# définie
if args("sortbanner") != 1
	fset sortbanner(x) "--- Choses à faire %b ---"
endif

MSGPREFIX() ET MSGSUFFIX()

Vous pouvez définir deux fonctions dans votre script appelées msgprefix() et msgsuffix(). Elles doivent chacune accepter un argument, un nombre de 0 à 9999.

En mode agenda, pour les rappels de type MSG et MSF, la séquence suivante se produit lorsque Remind déclenche un rappel:

o
Si msgprefix() est défini, il est évalué avec la priorité du rappel comme argument. Le résultat est affiché. Il n'est *pas* passé à travers le filtre de substitution.
o
Le corps du rappel est affiché.
o
Si msgsuffix() est défini, il est évalué avec la priorité du rappel comme argument. Le résultat est affiché. Il n'est *pas* passé à travers le filtre de substitution.

Voici un exemple : La définition suivante fait que les rappels de priorité 0 sont précédés de « URGENT : », et les rappels de priorité 6000 sont précédés de « (pas important) ».

fset msgprefix(x) iif(x==0, "URGENT: ", \
     x==6000, "(pas important) ", "")

En mode Calendrier (avec les options -c, -s ou -p), une paire de fonctions analogues nommées calprefix() et calsuffix() peut être définie. Elles fonctionnent avec tous les rappels qui produisent une entrée dans le calendrier (c'est-à-dire les rappels de type CAL et éventuellement RUN, ainsi que les rappels de type MSG).

NOTES

Normalement, le corps d'un rappel est suivi d'un retour chariot. Ainsi, les résultats de msgsuffix() apparaîtront sur la ligne suivante. Si vous ne voulez pas cela, assurez-vous que la sortie de msgsuffix commence par un retour arrière. Cela place le suffixe *avant* plutôt qu'après le retour chariot. (Le caractère de retour arrière lui-même est supprimé.) Voici un exemple:

        FSET msgsuffix(x) char(8) + " - suffixe sur la même ligne"

Si Remind a des problèmes pour évaluer msgprefix(), msgsuffix() ou sortbanner(), vous verrez beaucoup de messages d'erreur. Pour un exemple de cela, définissez ce qui suit:

fset msgprefix(x) x/0

PRISE EN CHARGE AU MOMENT DE LA COMPILATION POUR D'AUTRES LANGUES

Remind prenait en charge la localisation au moment de la compilation pour d'autres langues, mais ce n'est plus le cas. Toute la localisation se fait désormais au moment de l'exécution.

PRISE EN CHARGE AU MOMENT DE L'EXÉCUTION POUR D'AUTRES LANGUES

Remind prend en charge au moment de l'exécution d'autres langues, et la prise en charge au moment de la compilation a été supprimée au profit de la prise en charge au moment de l'exécution.

Un certain nombre de variables système vous permettent de traduire diverses phrases dans d'autres langues. Ces variables système sont:

$Lundi, $Mardi, $Mercredi, $Jeudi, $Vendredi, $Samedi, $Dimanche
Définissez chacune de ces variables système sur une chaîne représentant le nom du jour correspondant dans votre langue. Les chaînes doivent être des chaînes UTF-8 valides.
$Janvier, $Février, $Mars, $Avril, $Mai, $Juin, $Juillet, $Août, $Septembre, $Octobre, $Novembre, $Décembre
Définissez chacune de ces variables système sur une chaîne représentant le nom du mois correspondant dans votre langue. Les chaînes doivent être des chaînes UTF-8 valides.
$Ago, $Am, $And, $At, $Hour, $Is, $Minute, $Now, $On, $Pm, $Today, $Tomorrow, $Was
Définissez chacune de ces variables système sur la traduction du mot anglais correspondant dans votre langue. Notez que $Am et $Pm doivent être les traductions de « AM » et « PM » (indicateurs de temps du matin et de l'après-midi) respectivement.
$Hplu, $Mplu
Définissez-les sur le suffixe à ajouter au mot « heure » et « minute » pour les mettre au pluriel. En français, les deux seraient définis sur « s » pour « heures » et « minutes », bien que cela ne soit pas toujours nécessaire grammaticalement. Ce paramètre est principalement pour l'anglais.
$Fromnow
Définissez-le sur la traduction de la phrase anglaise « from now ».

Notez que si vous définissez l'une des variables système liées à la langue, elles doivent être définies dans une section de votre script qui est toujours évaluée. Si vous les définissez à l'intérieur d'une instruction IF, par exemple, les résultats sont imprévisibles.

Notez également que le backend Rem2PS ne prend pas en charge toute la gamme de caractères UTF-8. Les backends TkRemind, rem2html et rem2pdf prennent tous en charge la gamme complète UTF-8.

MODIFICATION AU MOMENT DE L'EXÉCUTION DU FILTRE DE SUBSTITUTION

Les variables système mentionnées dans la section précédente ne suffisent généralement pas à traduire correctement la sortie de Remind dans une autre langue. Certaines langues ont des règles compliquées pour les heures AM/PM et d'autres ont des règles complexes pour la mise au pluriel des mots. Remind vous permet donc de définir un certain nombre de fonctions qui modifient le comportement du filtre de substitution au moment de l'exécution. Les fonctions sont:

subst_ampm(h)
Cette fonction reçoit un seul entier, à savoir une heure de 0 à 23. Elle doit renvoyer une chaîne indiquant « AM » ou « PM », ou même des gradations plus fines dans certaines langues.
subst_ordinal(d)
Cette fonction reçoit un seul entier, à savoir un jour du mois de 1 à 31. Elle doit renvoyer une chaîne qui sera ajoutée au numéro du jour pour en faire un nombre ordinal. En français, par exemple, la fonction pourrait renvoyer « er », « nd », « ième » ou « e » selon d.
subst_N(alt, date, heure)
Il s'agit en fait d'une *famille* de fonctions, où N est une lettre ou un chiffre. Cette fonction *remplace complètement* la séquence de substitution « %N ». Les trois arguments sont un entier alt qui, s'il est différent de zéro, indique que la séquence de substitution alternative « %*N » a été rencontrée ; date qui est la date de déclenchement du r
eminder et time qui est l'heure du déclenchement.
subst_Nx(alt, date, time)
Encore une fois, il s'agit d'une famille de fonctions. Elle est similaire à la famille subst_N, sauf qu'elle n'est appelée que si date est à deux jours ou plus de today(). Ceci est utile si vous ne voulez pas annuler la sortie "aujourd'hui" ou "demain" pour la plupart des séquences de substitution.

Voici un exemple de la façon dont vous pourriez personnaliser votre filtre de substitution. Supposons que vous vouliez changer la séquence "%b" pour qu'elle substitue "après-demain" pour un événement qui se produit dans deux jours. Vous pourriez faire ceci :

    FSET subst_bx(a,d,t) iif(d==today()+2, "après-demain", \
                             "dans " + (d-today()) + " jours")
    REM [today()+3] ++3 MSG L'événement 1 est %b%
    REM [today()+2] ++3 MSG L'événement 2 est %b%
    REM [today()+1] ++3 MSG L'événement 3 est %b%
    REM [today()]   ++3 MSG L'événement 4 est %b%

Le résultat de ce script est :

    L'événement 1 est dans 3 jours
    L'événement 2 est après-demain
    L'événement 3 est demain
    L'événement 4 est aujourd'hui

Notez comment la formulation de l'événement 2 a été changée par rapport à la normale "dans 2 jours", et notez aussi que les événements "demain" et "aujourd'hui" ont utilisé la substitution normale --- subst_bx n'est pas appelée pour les jours de déclenchement d'aujourd'hui ou de demain.

À titre spécial, si une fonction subst_Nx ou subst_N renvoie l'entier zéro, alors le mécanisme de substitution normal est utilisé. Par conséquent, l'exemple précédent aurait pu être écrit plus simplement comme ceci :

    FSET subst_bx(a,d,t) iif(d==today()+2, "après-demain", 0)

Vous pouvez remplacer les séquences de substitution qui ne sont pas alphanumériques comme suit :

Remplacez %: par subst_colon

Remplacez %! par subst_bang

Remplacez %? par subst_question

Remplacez %@ par subst_at

Remplacez %# par subst_hash

Vous pouvez définir vos propres séquences de substitution en plus de celles intégrées comme suit : Si vous définissez une fonction nommée subst_name(alt, date, time), alors la séquence %{name} appelle la fonction avec alt défini à 0 et date et time à la date et à l'heure du déclenchement, respectivement. La séquence %{name} est remplacée par ce que la fonction renvoie. La séquence %*{name} est similaire, mais appelle la fonction avec alt défini à 1.

Si vous utilisez une séquence %{name} et que la fonction subst_name n'est pas définie ou renvoie une erreur, alors %{name} est remplacée par une chaîne vide.

Notez que lorsque Remind invoque une fonction de rappel pour une séquence de substitution, RUN sera désactivé.

LA TABLE DE TRADUCTION

Pour faciliter la localisation des fichiers de rappels, Remind maintient une table de traductions. C'est simplement une table de recherche qui associe une chaîne (la chaîne d'origine) à une nouvelle chaîne (la chaîne traduite). Lorsque Remind commence son exécution, la table de traductions est vide.

Pour ajouter un message à la table de traductions, utilisez la commande TRANSLATE (qui peut être abrégée en TRANS). La commande TRANSLATE doit être suivie de deux chaînes entre guillemets, séparées l'une de l'autre et de la commande par des espaces blancs. Par exemple, un fichier en langue néerlandaise pourrait contenir quelque chose comme ceci :

        TRANSLATE "New Moon" "Nieuwe maan"
        TRANSLATE "First Quarter" "Eerste kwartier"
        TRANSLATE "Full Moon" "Volle maan"
        TRANSLATE "Last Quarter" "Laatste kwartier"

Pour utiliser réellement la table de traductions, utilisez la fonction intégrée _, comme suit :

        REM NOQUEUE [moondatetime(0)] MSG [_("New Moon")] (%2)
        REM NOQUEUE [moondatetime(1)] MSG [_("First Quarter")] (%2)
        REM NOQUEUE [moondatetime(2)] MSG [_("Full Moon")] (%2)
        REM NOQUEUE [moondatetime(3)] MSG [_("Last Quarter")] (%2)

En utilisant judicieusement TRANSLATE et _, vous pouvez rendre vos fichiers de rappels faciles à traduire.

TRANSLATE a quatre formes supplémentaires : Si elle est suivie d'une seule chaîne entre guillemets au lieu de deux, alors Remind supprime l'entrée de la table de traductions pour cette chaîne. Si elle est suivie du mot-clé DUMP, alors Remind déverse toutes les entrées de la table de traductions sur la sortie standard. Et si elle est suivie de CLEAR, alors Remind supprime toutes les entrées de la table de traductions.

La quatrième forme, TRANSLATE GENERATE, déverse toutes les chaînes qui peuvent être localisées (sous forme d'une série de commandes TRANSLATE) sur la sortie standard. Les chaînes déjà localisées sont affichées avec leur localisation ; les chaînes non localisées sont affichées comme suit :

        TRANSLATE "non traduit" ""

Si vous voulez ajouter une nouvelle langue, vous pouvez obtenir un fichier de traduction squelette en exécutant :
        echo "TRANSLATE GENERATE" | remind -h - > /tmp/skeleton.rem

Si vous avez un fichier de langue existant auquel il manque certaines traductions, vous pouvez le mettre à jour en exécutant :

        (echo INCLUDE mylang.rem; echo TRANSLATE GENERATE) | \
            remind -h - > /tmp/mylang-update.rem

et en éditant ensuite mylang-update.rem pour ajouter les traductions manquantes.

Si vous avez des scripts de rappel qui utilisent la fonction intégrée _() ou la séquence de substitution %(...), vous pouvez générer une liste des commandes TRANSLATE nécessaires en exécutant :

        remind -q -n -dq myscript.rem 2>&1 | grep ^TRANSLATE | sort | uniq

Notez que si vous SET diverses variables système liées à la traduction telles que $Monday, $December, $Ago, etc, alors Remind crée également automatiquement une entrée correspondante dans la table de traduction. Ceci est fait pour toutes les variables système liées à la traduction, à l'exception de $Hplu et $Mplu.

L'inverse s'applique également ; la création d'une table de traduction pour "December" définit automatiquement $December. Et si vous invoquez TRANSLATE CLEAR, alors toutes les variables système liées à la traduction sont également définies à leurs valeurs par défaut.

La table de traduction contient toujours une entrée spéciale LANGID dont la valeur par défaut est en. Les traducteurs sont encouragés à ajouter une entrée LANGID dans leurs fichiers de langue ; la valeur doit être le code de langue ISO 639 à deux caractères.

Par exemple, si vous écrivez un fichier de traduction pour la langue néerlandaise, ajoutez cette ligne :

        TRANSLATE "LANGID" "nl"

Les scripts peuvent utiliser _("LANGID") pour interroger la langue de traduction en vigueur.

La fonction _() utilise la procédure suivante pour obtenir la traduction d'une chaîne :

1
Recherche d'une correspondance exacte. Si trouvée, renvoie.
2
Si la chaîne d'origine contenait une lettre majuscule, recherche de l'équivalent tout en minuscules. Si trouvé, met la première lettre du résultat en majuscule et renvoie.
3
Si la chaîne d'origine commençait par une lettre minuscule, recherche d'un équivalent dont la première lettre est majuscule et le reste en minuscules. Si trouvé, met la première lettre du résultat en minuscule et renvoie.
4
Aucune traduction n'a été trouvée. Renvoie la chaîne d'origine.

LE CALENDRIER HÉBRAÏQUE

Remind prend en charge le calendrier hébraïque, qui est un calendrier luni-solaire. Cela vous permet de créer des rappels pour les fêtes juives, les jahrzeits (anniversaires de décès) et les smachot (occasions joyeuses).

L'ANNÉE HÉBRAÏQUE

L'année hébraïque compte 12 mois, alternant entre 30 et 29 jours. Les mois sont : Tishri, Heshvan, Kislev, Tevet, Shvat, Adar, Nisan, Iyar, Sivan, Tamuz, Av et Elul. À l'époque biblique, l'année commençait en Nisan, mais Roch Hachana (le Nouvel An juif) est maintenant célébré les 1er et 2 Tishri.

Dans un cycle de 19 ans, il y a 7 années bissextiles, étant les années 3, 6, 8, 11, 14, 17 et 19 du cycle. Lors d'une année bissextile, un mois supplémentaire de 30 jours est ajouté avant Adar. Les deux Adars sont appelés Adar A et Adar B.

Pour des raisons religieuses, l'année ne peut pas commencer un dimanche, un mercredi ou un vendredi. Pour compenser cela, un jour est retiré de Kislev ou ajouté à Heshvan. Ainsi, une année régulière peut avoir de 353 à 355 jours, et une année bissextile de 383 à 385.

Lorsque Kislev ou Heshvan est court, il est appelé chaser, ou manquant. Lorsqu'il est long, il est appelé shalem, ou plein.

La date juive change au coucher du soleil. Cependant, Remind changera la date à minuit, pas au coucher du soleil. Donc, pendant la période entre le coucher du soleil et minuit, Remind sera un jour plus tôt que la date juive réelle. Cela ne devrait pas poser beaucoup de problèmes en pratique.

Les calculs pour le calendrier juif étaient basés sur le programme "hdate" écrit par Amos Shapir de l'Université Hébraïque de Jérusalem, Israël. Il a également fourni l'explication précédente du calendrier.

FONCTIONS DE DATE HÉBRAÏQUE

hebday(d_date)
Retourne le jour du mois hébraïque correspondant au paramètre date. Par exemple, le 12 avril 1993 correspond au 21 Nisan 5753. Ainsi, hebday('1993/04/12') renvoie 21.
hebmon(d_date)
Retourne le nom du mois hébraïque correspondant à date. Par exemple, hebmon('1993/04/12') renvoie "Nisan".
hebyear(d_d
Retourne l'année hébraïque correspondant à date. Par exemple, hebyear('1993/04/12') renvoie 5753.
ate)">hebyear(d_date)
Retourne l'année hébraïque correspondant à date. Par exemple, hebyear('1993/04/12') renvoie 5753.
hebdate(i_day, s_hebmon [,id_yrstart [,i_jahr [,i_aflag]]])
La fonction hebdate() est la plus complexe des fonctions de support hébraïque. Elle peut accepter de 2 à 5 arguments. Elle renvoie une DATE correspondant à la date hébraïque.
Le paramètre day peut varier de 1 à 30 et spécifie le jour du mois hébraïque. Le paramètre hebmon est une chaîne de caractères qui doit nommer l'un des mois hébraïques spécifiés ci-dessus. Notez que le mois doit être orthographié en toutes lettres et utiliser la translittération anglaise indiquée précédemment. Vous pouvez également spécifier "Adar A" et "Adar B". Les noms des mois ne sont pas sensibles à la casse.

Le paramètre yrstart peut être soit une DATE, soit un INT. S'il s'agit d'une DATE, alors hebdate() recherche la première date hébraïque égale ou postérieure à cette date. Par exemple :

hebdate(15, "Nisan", '1990/01/01')

renvoie 1990/03/30, car c'est la première occurrence du 15 Nisan à partir du 1er janvier 1990.

Si yrstart est un INT, il est interprété comme une année hébraïque. Ainsi :

hebdate(22, "Kislev", 5756)

renvoie 1995/12/15, car cette date correspond au 22 Kislev, 5756. Notez qu'aucune des fonctions de date hébraïque ne fonctionnera avec des dates en dehors de la plage normale de dates de Remind.

Si yrstart n'est pas fourni, il prend par défaut la valeur de today().

Le paramètre jahr modifie le comportement de hebdate() comme suit :

Si jahr est 0 (par défaut), alors hebdate() continue à chercher jusqu'à ce qu'il trouve une date qui satisfait exactement les autres paramètres. Par exemple :

hebdate(30, "Adar A", 1993/01/01)

renvoie 1995/03/02, correspondant au 30 Adar A, 5755, car c'est la prochaine occurrence du 30 Adar A après le 1er janvier 1993. Ce comportement est approprié pour Pourim Katan, qui n'apparaît que les années bissextiles.

Si jahr est 1, alors la date est modifiée comme suit :

o
Le 30 Heshvan est converti en 1 Kislev les années où Heshvan est chaser.
o
Le 30 Kislev est converti en 1 Tevet les années où Kislev est chaser.
o
Le 30 Adar A est converti en 1 Nisan les années non bissextiles.
o
Les autres dates du Adar A sont reportées au jour correspondant dans Adar les années non bissextiles.

Ce comportement est approprié pour les smachot (occasions joyeuses) et pour certains jahrzeits - voir "JAHRZEITS".

Si jahr est 2, alors la date est modifiée comme suit :

o
Le 30 Kislev et le 30 Heshvan sont convertis en 29 Kislev et 29 Heshvan, respectivement, si le mois est chaser.
o
Le 30 Adar A est converti en 30 Shvat les années non bissextiles.
o
Les autres dates du Adar A sont reportées au jour correspondant dans Adar les années non bissextiles.

Si jahr n'est ni 0, ni 1, ni 2, il est interprété comme une année hébraïque, et le comportement est calculé comme décrit dans la section suivante, "JAHRZEITS".

Le paramètre aflag modifie le comportement de la fonction pour les dates du Adar pendant les années bissextiles. Le paramètre aflag est uniquement utilisé si yrstart est de type DATE.

Le paramètre aflag n'affecte les calculs de date que si hebmon est spécifié comme "Adar". Les années bissextiles, l'algorithme suivant est suivi :

o
Si aflag est 0, alors la date est déclenchée dans Adar B. C'est la valeur par défaut.
o
Si aflag est 1, alors la date est déclenchée dans Adar A. Cela peut être approprié pour les jahrzeits dans la tradition ashkénaze ; consultez un rabbin.
o
Si aflag est 2, alors la date est déclenchée à la fois dans Adar A et Adar B d'une année bissextile. Certains Ashkénazes observent le jahrzeit dans Adar A et Adar B.

JAHRZEITS

Un jahrzeit est une commémoration annuelle du décès de quelqu'un. Il a lieu normalement à l'anniversaire du décès, mais peut être retardé si l'enterrement est retardé - consultez un rabbin pour plus d'informations.

De plus, comme certains mois changent de longueur, il n'est pas évident quel jour est l'anniversaire d'un décès. Les règles suivantes sont utilisées :

o
Si le décès a eu lieu le 30 Heshvan, et que Heshvan l'année suivant le décès est chaser, alors le jahrzeit est observé le 29 Heshvan les années où Heshvan est chaser. Sinon, le jahrzeit est observé le 1 Kislev lorsque Heshvan est chaser.
o
Si le décès a eu lieu le 30 Kislev, et que Kislev l'année suivant le décès est chaser, alors le jahrzeit est observé le 29 Kislev les années où Kislev est chaser. Sinon, le jahrzeit est observé le 1 Tevet lorsque Kislev est chaser.
o
Si le décès a eu lieu du 1er au 29 Adar A, il est observé du 1er au 29 Adar les années non bissextiles.
o
Si le décès a eu lieu le 30 Adar A, il est observé le 30 Shvat une année non bissextile.

Spécifier une année hébraïque pour le paramètre jahr permet de sélectionner le comportement correct pour un décès survenu cette année-là. Vous devrez peut-être également spécifier aflag, selon votre tradition.

Les informations sur les jahrzeits ont été fournies par Frank Yellin, qui a cité "The Comprehensive Hebrew Calendar" par Arthur Spier, et "Calendrical Calculations" par E. M. Reingold et Nachum Dershowitz.

RAPPELS EXTRA-BANDES

Le mot-clé SPECIAL est utilisé pour transmettre des informations "extra-bandes" aux backends de Remind, tels que tkremind ou Rem2PS. Ils sont utilisés uniquement lors du transfert de données à partir d'une ligne remind -p. (Notez que le spécial COLOR est une exception ; il fonctionne de manière similaire à MSG lorsque l'option -p n'est pas fournie.)

Les différents SPECIALs reconnus sont spécifiques à chaque backend ; cependant, il existe quatre SPECIALs que tous les backends devraient tenter de supporter. Ils sont actuellement pris en charge par Rem2PS, tkremind et rem2html.

Le spécial SHADE remplace la fonction psshade(). Utilisez-le comme suit :

REM Sat Sun SPECIAL SHADE 128
REM Mon SPECIAL SHADE 255 0 0

Le mot-clé SHADE est suivi d'un ou trois nombres, de 0 à 255. Si un seul nombre est fourni, il est interprété comme une valeur de niveaux de gris, du noir (0) au blanc (255). S'il y a trois nombres, ils sont interprétés comme des composantes RVB, du minimum (0) au maximum (255). L'exemple ci-dessus colore les week-ends en gris assez foncé et rend les lundis en rouge saturé. (Ces coloriages apparaissent dans les calendriers produits par Rem2PS, tkremind et rem2html.)

Le spécial MOON remplace la fonction psmoon(). Utilisez-le comme suit :

REM [moondate(0)] SPECIAL MOON 0
REM [moondate(1)] SPECIAL MOON 1
REM [moondate(2)] SPECIAL MOON 2
REM [moondate(3)] SPECIAL MOON 3

Ces commandes dessinent de petites lunes sur les différents calendriers. La syntaxe complète du spécial MOON est la suivante :

... SPECIAL MOON phase moonsize fontsize msg

Phase est un nombre de 0 à 3, 0 représentant une nouvelle lune, 1 le premier quartier, 2 une pleine lune et 3 le dernier quartier.

moonsize est le diamètre en unités PostScript de la lune à dessiner. S'il est omis ou fourni comme -1, le backend choisit une taille appropriée.

fontsize est la taille de la police en unités PostScript du msg.

Msg est un texte supplémentaire placé près du glyphe de la lune.

Notez que seul le backend Rem2PS prend en charge moonsize et fontsize ; les autres backends utilisent des tailles fixes.

Le spécial COLOR vous permet de placer des rappels colorés dans le calendrier. Utilisez-le comme suit :

REM ... SPECIAL COLOR 255 0 0 This is a bright red reminder
REM ... SPECIAL COLOR 0 128 0 This is a dark green reminder

Vous pouvez écrire COLOR soit à l'américaine ("COLOR"), soit à l'anglaise ("COLOUR"). Ce manuel utilisera la manière américaine.

Immédiatement après COLOR doivent se trouver trois nombres décimaux compris entre 0 et 255 spécifiant respectivement les intensités de rouge, de vert et de bleu. Le reste de la ligne est le texte à afficher dans le calendrier.

Le spécial COLOR est "doublement spécial", car en mode agenda, remind traite un spécial COLOR comme un rappel de type MSG. De plus, si vous invoquez Remind avec -@[n], il approxime les rappels SPECIAL COLOR sur votre terminal.

Voir également la documentation de la variable système $DefaultColor dans la section "VARIABLES SYSTÈME".

Le spécial WEEK vous permet de placer des annotations telles que le numéro de semaine dans le calendrier. Par exemple, cela numéroterait chaque lundi avec le numéro de semaine ISO 8601. Le numéro de semaine est affiché sous la forme : "(Wn)" dans cet exemple, mais vous pouvez mettre le texte de votre choix après le mot-clé WEEK.

REM Monday SPECIAL WEEK (W[weekno()])

EXEMPLES DE NIFTY

Cette section est un échantillon de ce que vous pouvez faire avec Remind.

REM 5 fév 1991 À 14:00 +45 *30 \
RUN mail -s "Réunion à %2" $LOGNAME </dev/null &

Le 5 février 1991, ce rappel vous enverra des rappels de réunion à 14h00 à 13h15, 13h45 et 14h00. L'objet du courriel sera "Réunion à 14h00" et le corps du message sera vide.

REM À 17:00 RUN echo "17h00 - RENTRE CHEZ VOUS !" | xless -g +0+0 &

Ce rappel fera apparaître une fenêtre xless chaque jour à 17h00. La fenêtre xless contiendra la ligne "17h00 - RENTRE CHEZ VOUS !"

REM À 23:59 RUN (sleep 120; remind -a [filename()]) &

Ce rappel s'exécutera une minute avant minuit. Il lancera un nouveau processus Remind une minute après minuit. Cela vous permet d'avoir un service de rappel continu afin que vous puissiez travailler toute la nuit et recevoir quand même des rappels chronométrés tôt le matin. Notez que cette astuce n'est plus nécessaire, à condition que vous exécutiez Remind en mode démon.

remind -c12 /dev/null Jan 1993

Cette invocation de Remind lui fera imprimer un calendrier pour 1993, avec toutes les entrées laissées vides.

REM CAL [trigdate()-date(year(trigdate()), 1, 1)+1]

Cet exemple insère une entrée dans chaque case d'un calendrier indiquant le numéro (1-365 ou 366) du jour de l'année.

REM Mar 2 Nov SATISFY (year(trigdate())%4) == 0
IF trigvalid()
	REM [trigdate()] ++5 MSG \
	Élection présidentielle américaine !!
ENDIF

Cet exemple vous avertit 5 jours avant chaque élection présidentielle américaine. La première commande REM calcule le premier mardi après le premier lundi de novembre. (Ceci est équivalent au premier mardi le ou après le 2 novembre.) La clause SATISFY garantit que la date de déclenchement n'est émise que les années d'élection, qui sont des multiples de 4. La seconde commande REM émet réellement le rappel.

DÉTAILS SUR LE CALCUL DES TRIGGERS

Voici une description *conceptuelle* de la façon dont les triggers sont calculés. Notez que Remind utilise en réalité une procédure beaucoup plus efficace, mais les résultats sont les mêmes que si la procédure conceptuelle avait été suivie.

Remind part de la date actuelle (c'est-à-dire la valeur de today()) et balaie vers l'avant, examinant chaque jour un par un jusqu'à ce qu'il trouve une date qui satisfait le trigger, ou qu'il puisse prouver qu'aucune telle date (à partir de la date actuelle ou après) n'existe.

Si Remind exécute un rappel de type SATISFY, il évalue l'expression avec trigdate() défini sur la date trouvée ci-dessus. Si l'expression s'évalue à zéro ou à une chaîne nulle, Remind poursuit la procédure de balayage décrite ci-dessus, en commençant par le jour suivant le trigger trouvé ci-dessus.

La clause SCANFROM (ayant une syntaxe similaire à UNTIL) peut modifier la stratégie de recherche utilisée. Dans ce cas, Remind commence la procédure de balayage à scan_date, qui est la date spécifiée dans la clause SCANFROM. Par exemple:

REM Lun 1 SCANFROM 17 jan 1992 MSG Foo

L'exemple ci-dessus aura toujours une date de trigger du lundi 3 février 1992. C'est parce que Remind commence à balayer à partir du 17 janvier 1992 et arrête de balayer dès qu'il atteint une date qui satisfait "Lun 1".

L'utilisation principale de SCANFROM se situe dans des situations où vous souhaitez calculer les positions des jours fériés flottants. Considérez l'exemple de la Fête du Travail montré plus tôt. La Fête du Travail est le premier lundi de septembre. Elle peut se déplacer sur une période de 7 jours. Considérez la séquence suivante:

REM Lun 1 sept SCANFROM [today()-7] ADDOMIT MSG Fête du Travail
REM Lun APRÈS MSG Bonjour

La clause SCANFROM garantit que Remind commence le balayage 7 jours avant la date actuelle. Cela garantit que la Fête du Travail pour l'année en cours continuera à être déclenchée jusqu'à 7 jours après sa survenance. Cela vous permet d'utiliser en toute sécurité le mot-clé APRÈS comme indiqué.

À titre spécial, vous pouvez simplement utiliser un nombre négatif après SCANFROM; un nombre négatif -N est interprété comme N jours avant aujourd'hui. Ainsi, l'exemple précédent pourrait également être écrit comme suit:

REM Lun 1 sept SCANFROM -7 ADDOMIT MSG Fête du Travail
REM Lun APRÈS MSG Bonjour

Un SCANFROM qui spécifie une date complète est appelé un SCANFROM *absolu* et un SCANFROM qui spécifie un nombre négatif est appelé un SCANFROM *relatif*.

En général, utilisez SCANFROM comme montré pour les OMIT mobiles en toute sécurité. Le montant par lequel vous devriez balayer en arrière (7 jours dans l'exemple ci-dessus) dépend du nombre de jours consécutifs possibles OMIT qui peuvent survenir, et de la plage du jour férié mobile. Généralement, une valeur de 7 est sûre.

La clause FROM fonctionne presque comme le contrepoint de UNTIL. Elle empêche le rappel de se déclencher avant la date FROM. Par exemple, le rappel suivant:

REM Lun Jeu FROM 23 juil 2007 UNTIL 2 août 2007 MSG Test

se déclenchera les lundis et jeudis entre le 23 juillet 2007 et le 2 août 2007 inclus.

FROM est en réalité juste du sucre syntaxique; vous pourriez implémenter le rappel ci-dessus comme suit:

	REM Lun Jeu SCANFROM [max(today(), '2007-07-23')] \
            UNTIL 2 août 2007 MSG Test

mais c'est beaucoup moins lisible. En interne, Remind traite FROM exactement comme illustré à l'aide de SCANFROM. Pour cette raison, vous ne pouvez pas utiliser à la fois FROM et SCANFROM.

Notez que si vous utilisez une commande REM pour calculer une date de déclenchement, effectuez des calculs de date (addition ou soustraction, par exemple) puis utilisez la date modifiée dans une commande REM subséquente, les résultats *peuvent ne pas être ceux que vous aviez prévus*. C'est parce que vous avez contourné le mécanisme de balayage normal. Vous devriez essayer d'écrire des commandes REM qui calculent des dates de déclenchement qui peuvent être utilisées sans modification dans les commandes REM subséquentes. Le fichier "defs.rem" qui accompagne la distribution de Remind contient des exemples.

DÉTAILS SUR TRIGVALID()

La fonction trigvalid() renvoie 1 si Remind a pu trouver une date de déclenchement pour la commande REM ou IFTRIG précédente. Plus précisément, elle renvoie 1 si Remind trouve une date *pas avant la date de début du balayage* qui satisfait le trigger. De plus, il y a un cas spécial où trigvalid() renvoie 1 et trigdate() renvoie un résultat significatif:

Si la commande REM ou IFTRIG ne contenait pas de clause UNTIL ou SATISFY, et contenait tous les composants *jour*, *mois* et *année*, alors Remind calculera correctement une date de déclenchement, même si elle se trouve être antérieure au début du balayage. Notez que ce comportement n'est pas vrai pour les versions de Remind antérieures à 03.00.01.

FICHIERS

L'emplacement traditionnel de votre fichier ou répertoire de rappels est:

        $HOME/.reminders

où $HOME est votre répertoire personnel.

Remind est livré avec des fichiers préinstallés pour les jours fériés et les packs de langues. Ceux-ci sont situés dans le répertoire suivant:

        /usr/share/remind/

Ne codez pas en dur le répertoire ci-dessus dans vos fichiers de rappels. Utilisez plutôt la valeur de la variable système $SysInclude.

DESCRIPTION

remind is a utility to remind you of things. It is a complex and powerful program which can be used to generate reminders in a variety of formats, including plain text, PostScript, and HTML. It can also be used to manage to-do lists, schedule events, and even send email reminders.

MODES OF OPERATION

remind has several modes of operation, which are determined by the options passed to the program. These modes include:

  • Reminder Mode: Displays reminders for the current day or a specified date.
  • Agenda Mode: Displays a list of upcoming events and to-dos in a chronological order.
  • Calendar Mode: Generates a calendar view for a specified month or year.
  • Daemon Mode: Runs in the background, periodically checking for reminders and notifying the user.
  • Purge Mode: Removes old or completed to-dos from the reminder files.

LONG OPTIONS

remind also supports long options, which are specified with a double dash (--). For example, --help is equivalent to -h.

REMINDER FILES

remind uses text files to store reminders and to-dos. The default reminder file is ~/.reminders. You can specify a different file using the -f option.

Reminder files can contain a variety of directives, including:

  • REMEMBER: Specifies a reminder to be displayed on a certain date.
  • TODO: Specifies a to-do item with a due date.
  • EVENT: Specifies an event with a start and end date.
  • INCLUDE: Includes another reminder file.
  • EXPR: Evaluates a mathematical expression.
  • RUN: Executes a command.

See the remind man page for a complete list of directives and their syntax.

THE REM COMMAND

The REM command is used to specify a reminder. It takes the form:

REM YYYYMMDD [HHMM] message

For example:

REM 20231225 Call mom

This will display "Call mom" on December 25, 2023.

SYNTACTIC SUGAR FOR REM

remind provides several shortcuts for specifying common reminders. For example:

  • NEXT TUESDAY remind me to buy milk
  • IN 3 WEEKS call the dentist
  • ON JULY 4TH have a barbecue

THE SUBSTITUTION FILTER

The substitution filter allows you to modify the output of reminders. It uses a set of predefined functions and variables to perform text manipulations.

EVENTS AND TODOS

remind distinguishes between events and to-dos. Events are scheduled occurrences, while to-dos are tasks that need to be completed.

MARKING TODOS AS DONE

To-dos can be marked as done by adding a DONE tag to the to-do item.

LIMITING REMINDERS ABOUT OVERDUE TODOS

You can limit the number of reminders about overdue to-dos using the -s option.

MORE DETAILS ABOUT TODOS

remind allows you to associate additional details with to-dos, such as priority, estimated time, and subtasks.

THE OMIT COMMAND

The OMIT command is used to suppress certain reminders or to-dos based on specified criteria.

TIMEZONE SUPPORT

remind supports timezone conversions, allowing you to specify reminders in different timezones using the -z option.

THE DO, INCLUDE AND SYSINCLUDE COMMANDS

These commands are used to execute other commands, include other reminder files, or include system-wide reminder files.

THE RETURN COMMAND

The RETURN command is used within user-defined functions to return a value.

THE RUN COMMAND

The RUN command executes an external command. It can be used to automate tasks or integrate with other programs.

THE EXPR COMMAND

The EXPR command evaluates a mathematical or logical expression. It can be used for calculations or conditional logic within reminder files.

THE INCLUDECMD COMMAND

Similar to INCLUDE, but executes the specified file as a command and includes its output.

THE BANNER COMMAND

The BANNER command specifies text to be displayed at the beginning of each reminder output.

CONTROLLING THE OMIT CONTEXT

The OMIT command's behavior can be controlled by setting the context in which it operates.

EXPRESSIONS

remind supports a wide range of expressions, including arithmetic operations, comparisons, and date/time functions.

SYSTEM VARIABLES

SAVING AND RESTORING VARIABLES
