readdir(3) Manuel des fonctions de bibliothèque readdir(3)

NOM

readdir - lire un répertoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <dirent.h>
struct dirent *readdir(DIR *dirp);

DESCRIPTION

La fonction readdir() retourne un pointeur vers une structure dirent représentant l'entrée de répertoire suivante dans le flux de répertoire pointé par dirp. Elle retourne NULL lorsqu'elle atteint la fin du flux de répertoire ou si une erreur s'est produite.

Dans l'implémentation glibc, la structure dirent est définie comme suit :


struct dirent {
    ino_t          d_ino;       /* Numéro d'inode */
    off_t          d_off;       /* Pas un offset ; voir ci-dessous */
    unsigned short d_reclen;    /* Longueur de cet enregistrement */
    unsigned char  d_type;      /* Type de fichier ; non supporté
                                   par tous les types de systèmes de fichiers */
    char           d_name[256]; /* Nom de fichier terminé par null */
};

Les seuls champs de la structure dirent qui sont imposés par POSIX.1 sont d_name et d_ino. Les autres champs ne sont pas standardisés et ne sont pas présents sur tous les systèmes ; voir VERSIONS.

Les champs de la structure dirent sont les suivants :

d_ino
C'est le numéro d'inode du fichier.
d_off
La valeur retournée dans d_off est la même que celle qui serait retournée par un appel à telldir(3) à la position actuelle dans le flux de répertoire. Soyez conscient que malgré son type et son nom, le champ d_off est rarement un offset de répertoire sur les systèmes de fichiers modernes. Les applications doivent traiter ce champ comme une valeur opaque, sans faire d'hypothèses sur son contenu ; voir aussi telldir(3).
d_reclen
C'est la taille (en octets) de l'enregistrement retourné. Cela peut ne pas correspondre à la taille de la structure montrée ci-dessus ; voir VERSIONS.
d_type
Ce champ contient une valeur indiquant le type de fichier, ce qui permet d'éviter la dépense d'un appel à lstat(2) si des actions ultérieures dépendent du type de fichier.
Lorsque le macro de fonctionnalité approprié est défini (_DEFAULT_SOURCE depuis glibc 2.19, ou _BSD_SOURCE sur glibc 2.19 et antérieurs), glibc définit les constantes macro suivantes pour la valeur retournée dans d_type :
DT_BLK
Ceci est un périphérique de bloc.
DT_CHR
Ceci est un périphérique de caractère.
DT_DIR
Ceci est un répertoire.
DT_FIFO
Ceci est un tube nommé (FIFO).
DT_LNK
Ceci est un lien symbolique.
DT_REG
Ceci est un fichier régulier.
DT_SOCK
Ceci est un socket de domaine UNIX.
DT_UNKNOWN
Le type de fichier n'a pas pu être déterminé.
Actuellement, seuls certains systèmes de fichiers (parmi eux : Btrfs, ext2, ext3 et ext4) ont un support complet pour retourner le type de fichier dans d_type. Toutes les applications doivent gérer correctement un retour de DT_UNKNOWN.
d_name
Ce champ contient le nom de fichier terminé par null ; voir VERSIONS.

Les données retournées par readdir() peuvent être écrasées par des appels ultérieurs à readdir() pour le même flux de répertoire.

VALEUR DE RETOUR

En cas de succès, readdir() retourne un pointeur vers une structure dirent. (Cette structure peut être allouée statiquement ; n'essayez pas de la free(3).)

Si la fin du flux de répertoire est atteinte, NULL est retourné et errno n'est pas modifié. Si une erreur se produit, NULL est retourné et errno est défini pour indiquer l'erreur. Pour distinguer la fin du flux d'une erreur, initialisez errno à zéro avant d'appeler readdir() puis vérifiez la valeur de errno si NULL est retourné.

ERREURS

EBADF
Descripteur de flux de répertoire dirp invalide.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
readdir () Thread safety MT-Unsafe race:dirstream

Dans la spécification POSIX.1 actuelle (POSIX.1-2008), readdir() n'est pas obligée d'être thread-safe. Cependant, dans les implémentations modernes (y compris l'implémentation glibc), les appels concurrents à readdir() qui spécifient différents flux de répertoire sont thread-safe. Dans les cas où plusieurs threads doivent lire à partir du même flux de répertoire, utiliser readdir() avec une synchronisation externe est toujours préférable à l'utilisation de la fonction dépréciée readdir_r(3). On s'attend à ce qu'une version future de POSIX.1 exige que readdir() soit thread-safe lorsqu'il est utilisé concurremment sur différents flux de répertoire.

VERSIONS

Seuls les champs d_name et (en tant qu'extension XSI) d_ino sont spécifiés dans POSIX.1. Outre Linux, le champ d_type n'est disponible principalement que sur les systèmes BSD. Les champs restants sont disponibles sur de nombreux systèmes, mais pas tous. Sous glibc, les programmes peuvent vérifier la disponibilité des champs non définis dans POSIX.1 en testant si les macros _DIRENT_HAVE_D_NAMLEN, _DIRENT_HAVE_D_RECLEN, _DIRENT_HAVE_D_OFF ou _DIRENT_HAVE_D_TYPE sont définis.

Le champ d_name

La définition de la structure dirent montrée ci-dessus est tirée des en-têtes glibc, et montre le champ d_name avec une taille fixe.

Attention : les applications doivent éviter toute dépendance vis-à-vis de la taille du champ d_name. POSIX le définit comme char d_name[], un tableau de caractères de taille non spécifiée, avec au plus NAME_MAX caractères précédant le caractère nul de terminaison ('\0').

POSIX.1 note explicitement que ce champ ne doit pas être utilisé comme lvalue. La norme note également que l'utilisation de sizeof(d_name) est incorrecte ; utilisez plutôt strlen(d_name). (Sur certains systèmes, ce champ est défini comme char d_name[1] !) Par implication, l'utilisation de sizeof(struct dirent) pour capturer la taille de l'enregistrement, y compris la taille de d_name, est également incorrecte.

Notez que bien que l'appel


fpathconf(fd, _PC_NAME_MAX)

retourne la valeur 255 pour la plupart des systèmes de fichiers, sur certains systèmes de fichiers (par exemple, CIFS, serveurs SMB Windows), le nom de fichier terminé par null qui est (correctement) retourné dans d_name peut réellement dépasser cette taille. Dans de tels cas, le champ d_reclen contiendra une valeur qui dépasse la taille de la structure dirent glibc montrée ci-dessus.

NORMES

POSIX.1-2008.

HISTORIQUE

La fonction readdir() est apparue dans la version 3 Xerox AT&T UNIX.

BOGUES

Le champ d_type n'est pas fiable sur tous les systèmes de fichiers ; par exemple, il n'est pas implémenté sur le système de fichiers NFS.

NOTES

Un flux de répertoire est ouvert à l'aide de opendir(3).

L'ordre dans lequel les noms de fichiers sont lus par des appels successifs à readdir() dépend de l'implémentation du système de fichiers ; il est peu probable que les noms soient triés d'une quelconque manière.
