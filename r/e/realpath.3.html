realpath(3) Manuel des fonctions de bibliothèque realpath(3)

NOM

realpath - renvoie le chemin absolu canonisé

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <limits.h>
#include <stdlib.h>
char *realpath(const char *restrict path,
               char *restrict resolved_path);
Exigences relatives aux macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

realpath() :

    _XOPEN_SOURCE >= 500
        || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE

DESCRIPTION

realpath() développe tous les liens symboliques et résout les références à /./, /../ et les caractères '/' supplémentaires dans la chaîne terminée par un caractère nul nommée par path pour produire un chemin absolu canonisé. Le chemin résultant est stocké sous forme de chaîne terminée par un caractère nul, jusqu'à un maximum de PATH_MAX octets, dans le tampon pointé par resolved_path. Le chemin résultant n'aura pas de composant de lien symbolique, /./ ou /../.

Si resolved_path est spécifié comme NULL, alors realpath() utilise malloc(3) pour allouer un tampon pouvant contenir jusqu'à PATH_MAX octets pour stocker le chemin résolu, et renvoie un pointeur vers ce tampon. L'appelant doit désallouer ce tampon en utilisant free(3).

VALEUR DE RETOUR

En l'absence d'erreur, realpath() renvoie un pointeur vers resolved_path.

Sinon, il renvoie NULL, le contenu du tableau resolved_path est indéfini, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
L'autorisation de lecture ou de recherche a été refusée pour une composante du préfixe du chemin.
EINVAL
path est NULL. (Avant glibc 2.3, cette erreur est également renvoyée si resolved_path est NULL.)
EIO
Une erreur d'E/S s'est produite lors de la lecture du système de fichiers.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la traduction du nom de chemin.
ENAMETOOLONG
Une composante d'un nom de chemin a dépassé NAME_MAX caractères, ou un nom de chemin entier a dépassé PATH_MAX caractères.
ENOENT
Le fichier nommé n'existe pas.
ENOMEM
Manque de mémoire.
ENOTDIR
Une composante du préfixe du chemin n'est pas un répertoire.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
realpath () Sécurité des threads MT-Safe

VERSIONS

Extensions GNU

Si l'appel échoue avec EACCES ou ENOENT et que resolved_path n'est pas NULL, alors le préfixe de path qui n'est pas lisible ou qui n'existe pas est renvoyé dans resolved_path.

NORMES

POSIX.1-2008.

HISTORIQUE

4.4BSD, POSIX.1-2001, Solaris.

POSIX.1-2001 indique que le comportement si resolved_path est NULL est défini par l'implémentation. POSIX.1-2008 spécifie le comportement décrit dans cette page.

Dans 4.4BSD et Solaris, la limite de longueur du nom de chemin est MAXPATHLEN (trouvée dans <sys/param.h>). SUSv2 prescrit PATH_MAX et NAME_MAX, tels que trouvés dans <limits.h> ou fournis par la fonction pathconf(3). Un fragment de source typique serait


#ifdef PATH_MAX
  path_max = PATH_MAX;
#else
  path_max = pathconf(path, _PC_PATH_MAX);
  if (path_max <= 0)
    path_max = 4096;
#endif

(Mais voir la section BUGS.)

BUGS

La version de la norme POSIX.1-2001 de cette fonction est défectueuse par conception, car il est impossible de déterminer une taille appropriée pour le tampon de sortie, resolved_path. Selon POSIX.1-2001, un tampon de taille PATH_MAX suffit, mais PATH_MAX n'a pas besoin d'être une constante définie, et peut devoir être obtenu en utilisant pathconf(3). Et demander à pathconf(3) n'aide pas vraiment, car d'une part POSIX avertit que le résultat de pathconf(3) peut être énorme et inadapté à l'allocation de mémoire, et d'autre part pathconf(3) peut renvoyer -1 pour signifier que PATH_MAX n'est pas borné. La fonctionnalité resolved_path == NULL, non standardisée dans POSIX.1-2001, mais standardisée dans POSIX.1-2008, permet d'éviter ce problème de conception.

VOIR AUSSI

realpath(1), readlink(2), canonicalize_file_name(3), getcwd(3), pathconf(3), sysconf(3)

real.path(3) - Manuel Linux (français)

NOM

real.path - renvoie le nom canonique d'un chemin d'accès

SYNOPSIS

#include <stdlib.h>

char *realpath(const char *path, char *resolved_path);

DESCRIPTION

La fonction realpath() convertit un nom de chemin d'accès path en un nom de chemin d'accès canonique absolu. Elle supprime les composants . et .., résout les liens symboliques, et supprime les composants de répertoire redondants (par exemple, //).

Si resolved_path n'est pas NULL, il doit pointer vers un buffer d'au moins PATH_MAX octets. Le chemin d'accès canonique résultant sera copié dans ce buffer.

Si resolved_path est NULL, realpath() alloue de la mémoire pour le chemin d'accès canonique résultant à l'aide de malloc(3). Le pointeur vers cette mémoire est renvoyé. L'appelant est responsable de libérer cette mémoire avec free(3).

Les chemins d'accès sont traités comme étant absolus, même s'ils commencent par un /.

VALEUR DE RETOUR

En cas de succès, realpath() renvoie un pointeur vers resolved_path (s'il n'est pas NULL) ou vers la mémoire allouée (s'il est NULL).

En cas d'erreur, realpath() renvoie NULL et errno est défini pour indiquer l'erreur.

ERREURS

  • EACCES : Le programme n'a pas les permissions nécessaires pour lire un composant du chemin d'accès.
  • ENOENT : Un composant du chemin d'accès n'existe pas.
  • ENOTDIR : Un composant du chemin d'accès n'est pas un répertoire.
  • ELOOP : Trop de liens symboliques ont été rencontrés lors de la résolution du chemin d'accès.
  • ENOMEM : Mémoire insuffisante pour allouer le chemin d'accès résolu (si resolved_path est NULL).

VOIR AUSSI

readlink(2), malloc(3), pathmax(5)

BUGS

La fonction realpath() peut être sujette à des conditions de concurrence (race conditions) si le système de fichiers est modifié pendant son exécution. Il est recommandé de faire attention lors de l'utilisation de cette fonction dans des environnements multithreadés.

Voir VOIR AUSSI.
