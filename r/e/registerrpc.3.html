rpc(3) Manuel des fonctions de bibliothèque rpc(3)

NOM

rpc - routines de bibliothèque pour les appels de procédure distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE ET DESCRIPTION

Ces routines permettent aux programmes C de faire des appels de procédure sur d'autres machines à travers le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de distribution pour effectuer le service demandé, puis renvoie une réponse. Finalement, l'appel de procédure retourne au client.

Pour utiliser ces routines, inclure le fichier d'en-tête <rpc/rpc.h>.

Les prototypes ci-dessous utilisent les types suivants :

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Voir les fichiers d'en-tête pour les déclarations des types AUTH, CLIENT, SVCXPRT et XDR.

void auth_destroy(AUTH *auth);
Une macro qui détruit les informations d'authentification associées à auth. La destruction implique généralement la désallocation de structures de données privées. L'utilisation de auth est indéfinie après avoir appelé auth_destroy().
AUTH *authnone_create(void);
Crée et renvoie un descripteur d'authentification RPC qui transmet des informations d'authentification non utilisables à chaque appel de procédure distante. C'est l'authentification par défaut utilisée par RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crée et renvoie un descripteur d'authentification RPC qui contient des informations d'authentification. Le paramètre host est le nom de la machine sur laquelle les informations ont été créées ; uid est l'identifiant utilisateur de l'utilisateur ; gid est l'identifiant de groupe actuel de l'utilisateur ; n et aup_gids font référence à un tableau compté des groupes auxquels l'utilisateur appartient. Il est facile d'usurper l'identité d'un utilisateur.
AUTH *authunix_create_default(void);
Appelle authunix_create() avec les paramètres appropriés.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Appelle la procédure distante associée à prognum, versnum et procnum sur la machine host. Le paramètre in est l'adresse du ou des arguments de la procédure, et out est l'adresse où placer le ou les résultats ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure. Cette routine renvoie zéro en cas de succès, ou la valeur de enum clnt_stat convertie en entier en cas d'échec. La routine clnt_perrno() est utile pour traduire les statuts d'échec en messages.
Attention : l'appel de procédures distantes avec cette routine utilise UDP/IP comme transport ; voir clntudp_create() pour les restrictions. Vous n'avez pas le contrôle des délais d'attente ou de l'authentification avec cette routine.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similaire à callrpc(), sauf que le message d'appel est diffusé sur tous les réseaux de diffusion locaux connectés. Chaque fois qu'elle reçoit une réponse, cette routine appelle eachresult(), dont la forme est :

eachresult(char *out, struct sockaddr_in *addr);

où out est le même que out passé à clnt_broadcast(), sauf que la sortie de la procédure distante y est décodée ; addr pointe vers l'adresse de la machine qui a envoyé les résultats. Si eachresult() renvoie zéro, clnt_broadcast() attend d'autres réponses ; sinon, elle retourne avec le statut approprié.
Attention : les sockets de diffusion sont limitées en taille au maximum de l'unité de transfert de la liaison de données. Pour ethernet, cette valeur est de 1500 octets.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Une macro qui appelle la procédure distante procnum associée au descripteur client, clnt, qui est obtenu avec une routine de création de client RPC telle que clnt_create(). Le paramètre in est l'adresse du ou des arguments de la procédure, et out est l'adresse où placer le ou les résultats ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure ; tout est le temps autorisé pour le retour des résultats.
clnt_destroy(CLIENT *clnt);
Une macro qui détruit le descripteur RPC du client. La destruction implique généralement la désallocation de structures de données privées, y compris clnt lui-même. L'utilisation de clnt est indéfinie après avoir appelé clnt_destroy(). Si la bibliothèque RPC a ouvert le socket associé, elle le fermera également. Sinon, le socket reste ouvert.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Routine générique de création de client. host identifie le nom de l'hôte distant où se trouve le serveur. proto indique quel type de protocole de transport utiliser. Les valeurs actuellement prises en charge pour ce champ sont « udp » et « tcp ». Des délais d'attente par défaut sont définis, mais peuvent être modifiés en utilisant clnt_control().
Attention : l'utilisation de UDP présente des inconvénients. Comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Kbytes de données encodées, ce transport ne peut pas être utilisé pour des procédures qui prennent de gros arguments ou retournent d'énormes résultats.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Une macro utilisée pour changer ou récupérer diverses informations concernant un objet client. req indique le type d'opération, et info est un pointeur vers les informations. Pour UDP et TCP, les valeurs prises en charge pour req et leurs types d'arguments ainsi que leurs fonctions sont :

CLSET_TIMEOUT  struct timeval // définir le délai d'attente total
CLGET_TIMEOUT  struct timeval // obtenir le délai d'attente total

Remarque : si vous définissez le délai d'attente en utilisant clnt_control(), le paramètre de délai d'attente passé à clnt_call() sera ignoré dans tous les appels futurs.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtenir l'adresse du serveur

Les opérations suivantes sont valides pour UDP uniquement :

CLSET_RETRY_TIMEOUT  struct timeval // définir le délai de nouvelle tentative
CLGET_RETRY_TIMEOUT  struct timeval // obtenir le délai de nouvelle tentative

Le délai de nouvelle tentative est le temps pendant lequel « UDP RPC » attend la réponse du serveur avant de retransmettre la requête.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Une macro qui libère toutes les données allouées par le système RPC/XDR lors du décodage des résultats d'un appel RPC. Le paramètre out est l'adresse des résultats, et outproc est la routine XDR décrivant les résultats. Cette routine renvoie un si les résultats ont été libérés avec succès, et zéro sinon.
void clnt_geterr(CLIENT *clnt, struct rpc_err
*errp);
Une macro qui copie la structure d'erreur du handle du client vers la structure à l'adresse errp.
void clnt_pcreateerror(const char *s);
Imprime un message sur la sortie d'erreur standard indiquant pourquoi un handle RPC client n'a pas pu être créé. Le message est précédé de la chaîne s et d'un deux-points. Utilisé lorsqu'un appel à clnt_create(), clntraw_create(), clnttcp_create(), ou clntudp_create() échoue.
void clnt_perrno(enum clnt_stat stat);
Imprime un message sur la sortie d'erreur standard correspondant à la condition indiquée par stat. Utilisé après callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué ; clnt est le handle utilisé pour effectuer l'appel. Le message est précédé de la chaîne s et d'un deux-points. Utilisé après clnt_call().
char *clnt_spcreateerror(const char *s);
Identique à clnt_pcreateerror(), sauf qu'il renvoie une chaîne de caractères au lieu d'imprimer sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
char *clnt_sperrno(enum clnt_stat stat);
Prend les mêmes arguments que clnt_perrno(), mais au lieu d'envoyer un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué, renvoie un pointeur vers une chaîne de caractères contenant le message. La chaîne se termine par un RETOUR À LA LIGNE.
clnt_sperrno() est utilisé à la place de clnt_perrno() si le programme n'a pas de sortie d'erreur standard (ce qui est probable pour un programme s'exécutant en tant que serveur) ou si le programmeur ne souhaite pas que le message soit affiché avec printf(3), ou si un format de message différent de celui pris en charge par clnt_perrno() doit être utilisé. Remarque : contrairement à clnt_sperror() et clnt_spcreateerror(), clnt_sperrno() renvoie un pointeur vers des données statiques, mais le résultat ne sera pas écrasé à chaque appel.
char *clnt_sperror(CLIENT *rpch, const char *s);
Identique à clnt_perror(), sauf que (comme clnt_sperrno()) il renvoie une chaîne de caractères au lieu d'imprimer sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Cette routine crée un client RPC factice pour le programme distant prognum, version versnum. Le transport utilisé pour passer les messages au service est en fait un tampon dans l'espace d'adressage du processus, de sorte que le serveur RPC correspondant doit résider dans le même espace d'adressage ; voir svcraw_create(). Cela permet de simuler le RPC et d'acquérir les surcoûts RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau. Cette routine renvoie NULL en cas d'échec.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; s'il s'agit de RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Comme le RPC basé sur TCP utilise des E/S mises en tampon, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; des valeurs de zéro choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL en cas d'échec.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; s'il s'agit de RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call().
Attention : comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Ko de données encodées, ce transport ne peut pas être utilisé pour les procédures qui prennent de grands arguments ou retournent d'énormes résultats.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; s'il s'agit de RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call().
Cela permet à l'utilisateur de spécifier la taille maximale du paquet pour l'envoi et la réception des messages RPC basés sur UDP.
void get_myaddress(struct sockaddr_in *addr);
Place l'adresse IP de la machine dans *addr, sans consulter les routines de bibliothèque qui traitent /etc/hosts. Le numéro de port est toujours défini sur htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Une interface utilisateur pour le service portmap, qui renvoie une liste des mappages actuels de programmes RPC à ports sur l'hôte situé à l'adresse IP *addr. Cette routine peut renvoyer NULL. La commande rpcinfo -p utilise cette routine.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Une interface utilisateur pour le service portmap, qui renvoie le numéro de port sur lequel attend un service qui prend en charge le numéro de programme prognum, la version versnum, et parle le protocole de transport associé à protocol. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Une valeur de retour de zéro signifie que le mappage n'existe pas ou que le système RPC n'a pas réussi à contacter le service portmap distant. Dans ce dernier cas, la variable globale rpc_createerr contient l'état RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Une interface utilisateur pour le service portmap, qui demande au portmap sur l'hôte à l'adresse IP *addr de faire un appel RPC en votre nom vers une procédure sur cet hôte. Le paramètre *portp sera modifié pour indiquer le numéro de port du programme si la procédure réussit. La définition des autres paramètres est discutée dans callrpc() et clnt_call(). Cette procédure doit être utilisée pour un “ping” et rien d'autre. Voir aussi clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Une interface utilisateur pour le service portmap, qui établit un mappage entre le triplet [prognum,versnum,protocol] et port sur le service portmap de la machine. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Cette routine renvoie un si elle réussit, zéro sinon. Automatiquement fait par svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Une interface utilisateur pour le service portmap, qui détruit tous les mappages entre le triplet [prognum,versnum,*] et les ports sur le service portmap de la machine. Cette routine renvoie un si elle réussit, zéro sinon.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Enregistre la procédure procname auprès du package de services RPC. Si une requête arrive pour le programme prognum, la version versnum, et la procédure procnum, procname est appelé avec un pointeur vers ses paramètres ; procname doit renvoyer un pointeur vers ses résultats statiques ; inproc est utilisé pour décoder les paramètres tandis que outproc est utilisé pour encoder les résultats. Cette routine renvoie zéro si l'enregistrement a réussi, -1 sinon.
Attention : les procédures distantes enregistrées sous cette forme sont accessibles via le transport UDP/IP
port ; voir svcudp_create() pour les restrictions. 
struct rpc_createerr rpc_createerr;
Une variable globale dont la valeur est définie par toute routine de création de client RPC qui ne réussit pas. Utilisez la routine clnt_pcreateerror() pour imprimer la raison.
void svc_destroy(SVCXPRT *xprt);
Une macro qui détruit le handle de transport du service RPC, xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine.
fd_set svc_fdset;
Une variable globale reflétant le masque de bits des descripteurs de fichiers en lecture du côté service RPC ; elle est appropriée comme paramètre pour l'appel système select(2). Ceci n'intéresse que si un implémenteur de service effectue son propre traitement d'événements asynchrones, au lieu d'appeler svc_run(). Cette variable est en lecture seule (ne pas passer son adresse à select(2) !), et elle peut changer après les appels à svc_getreqset() ou à toute routine de création.
int svc_fds;
Similaire à svc_fdset, mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui libère toute donnée allouée par le système RPC/XDR lors du décodage des arguments d'une procédure de service à l'aide de svc_getargs(). Cette routine retourne 1 si les résultats ont été libérés avec succès, et zéro sinon.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui décode les arguments d'une requête RPC associée au handle de transport du service RPC, xprt. Le paramètre in est l'adresse où les arguments seront placés ; inproc est la routine XDR utilisée pour décoder les arguments. Cette routine retourne un si le décodage réussit, et zéro sinon.
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
La manière approuvée d'obtenir l'adresse réseau de l'appelant d'une procédure associée au handle de transport du service RPC, xprt.
void svc_getreqset(fd_set *rdfds);
Cette routine n'intéresse que si un implémenteur de service n'appelle pas svc_run(), mais implémente à la place un traitement d'événements asynchrones personnalisé. Elle est appelée lorsque l'appel système select(2) a déterminé qu'une requête RPC est arrivée sur un ou plusieurs sockets RPC ; rdfds est le masque de bits des descripteurs de fichiers en lecture résultant. La routine retourne lorsque tous les sockets associés à la valeur de rdfds ont été traités.
void svc_getreq(int rdfds);
Similaire à svc_getreqset(), mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Associe prognum et versnum à la procédure de dispatch du service, dispatch. Si protocol est zéro, le service n'est pas enregistré auprès du service portmap. Si protocol est non nul, alors un mappage du triplet [prognum,versnum,protocol] vers xprt->xp_port est établi avec le service portmap local (généralement protocol est zéro, IPPROTO_UDP ou IPPROTO_TCP). La procédure dispatch a la forme suivante :

dispatch(struct svc_req *request, SVCXPRT *xprt);

La routine svc_register() retourne un si elle réussit, et zéro sinon.
void svc_run(void);
Cette routine ne retourne jamais. Elle attend l'arrivée des requêtes RPC et appelle la procédure de service appropriée en utilisant svc_getreq() lorsqu'une requête arrive. Cette procédure attend généralement qu'un appel système select(2) retourne.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Appelée par la routine de dispatch d'un service RPC pour envoyer les résultats d'un appel de procédure distante. Le paramètre xprt est le handle de transport associé à la requête ; outproc est la routine XDR utilisée pour encoder les résultats ; et out est l'adresse des résultats. Cette routine retourne un si elle réussit, zéro sinon.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Supprime tous les mappages du double [prognum,versnum] vers les routines de dispatch, et du triplet [prognum,versnum,*] vers le numéro de port.
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
Appelée par une routine de dispatch de service qui refuse d'exécuter un appel de procédure distante en raison d'une erreur d'authentification.
void svcerr_decode(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui ne parvient pas à décoder ses paramètres. Voir aussi svc_getargs().
void svcerr_noproc(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui n'implémente pas la procédure numérotée que l'appelant demande.
void svcerr_noprog(SVCXPRT *xprt);
Appelée lorsque le programme désiré n'est pas enregistré auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.
void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);
Appelée lorsque la version désiée d'un programme n'est pas enregistrée auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.
void svcerr_systemerr(SVCXPRT *xprt);
Appelée par une routine de dispatch de service lorsqu'elle détecte une erreur système non couverte par un protocole particulier. Par exemple, si un service ne peut plus allouer de stockage, il peut appeler cette routine.
void svcerr_weakauth(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui refuse d'exécuter un appel de procédure distante en raison de paramètres d'authentification insuffisants. La routine appelle svcerr_auth(xprt, AUTH_TOOWEAK).
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crée un service sur un descripteur de fichier ouvert. Typiquement, ce descripteur de fichier est un socket connecté pour un protocole de flux tel que TCP. sendsize et recvsize indiquent les tailles des tampons d'envoi et de réception. S'ils sont zéro, une valeur par défaut raisonnable est choisie.
SVCXPRT *svcraw_create(void);
Cette routine crée un transport de service RPC factice, auquel elle retourne un pointeur. Le transport est en réalité un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant doit résider dans le même espace d'adressage ; voir clntraw_create(). Cette routine permet de simuler le RPC et d'acquérir les surcoûts du RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau. Cette routine retourne NULL si elle échoue.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Cette routine crée un transport de service RPC basé sur TCP/IP, auquel elle retourne un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port TCP local, alors cette routine le lie à un port arbitraire. À la fin, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine retourne NULL si elle échoue. Comme le RPC basé sur TCP utilise des E/S mises en tampon, les utilisateurs peuvent spécifier la taille des tampons ; des valeurs de zéro choisissent des défauts appropriés.
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);
Cette routine crée un transport de service RPC basé sur UDP/IP, auquel elle retourne un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port UDP local, alors cette routine le lie à un port arbitraire. À la fin, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine retourne NULL si elle échoue.
Cela permet à l'utilisateur de spécifier la taille maximale du paquet pour l'envoi et la réception de messages RPC basés sur UDP.
SVCXPRT *svcudp_create(int sock);
Cet appel est équivalent à svcudp_bufcreate(sock,SZ,SZ) pour une taille par défaut SZ.
