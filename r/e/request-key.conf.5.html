REQUEST-KEY.CONF(5) Utilitaires de gestion de clés Linux REQUEST-KEY.CONF(5)

NOM

request-key.conf - Fichier de configuration du gestionnaire d'instanciation

DESCRIPTION

Ces fichiers sont utilisés par le programme /sbin/request-key pour déterminer quel programme exécuter afin d'instancier une clé.

request-key recherche la meilleure correspondance, en lisant tous les fichiers suivants :

/etc/request-key.d/*.conf
/etc/request-key.conf

S'il ne trouve aucune correspondance, il renverra une erreur et le noyau annulera automatiquement la clé.

La meilleure correspondance est définie comme la ligne avec les sauts de caractères joker les plus courts, classant les colonnes dans l'ordre de gauche à droite. Si deux lignes ont des sauts de longueur égale, la première lue est celle qui est prise.

Dans les fichiers, toute ligne vide ou ligne commençant par un dièse '#' est considérée comme un commentaire et ignorée.

Toutes les autres lignes sont supposées être des lignes de commande avec un certain nombre de champs séparés par des espaces blancs :

<op> <type> <description> <informations-d'appel> <prog> <arg1> <arg2> ...

Les quatre premiers champs sont utilisés pour faire correspondre les paramètres passés à request-key par le noyau. op est le type d'opération ; actuellement, la seule opération prise en charge est « create ».

type, description et callout-info correspondent aux trois paramètres passés à keyctl request2 ou à l'appel système request_key(). Chacun d'eux peut contenir un seul astérisque '*' comme caractère joker n'importe où dans la chaîne.

Si une correspondance est effectuée, le programme spécifié par <prog> sera exécuté. Il doit avoir un nom de chemin complet. argv[0] sera défini à partir de la partie du nom du programme qui suit le dernier caractère slash '/'.

Si le nom du programme est précédé d'une barre verticale '|', alors le programme sera bifurqué et exécuté attaché à trois tuyaux. Les informations d'appel lui seront transmises via son entrée standard (stdin) et les données de charge utile prévues seront récupérées de sa sortie standard (stdout). Tout ce qui est envoyé à la sortie d'erreur (stderr) sera enregistré dans syslog. Si le programme se termine avec 0, alors /sbin/request-key tentera d'instancier la clé avec les données lues depuis stdout. S'il échoue de toute autre manière, alors request-key tentera d'exécuter la commande d'opération « negate » appropriée.

Les arguments du programme peuvent être substitués par diverses macros. Seule la substitution complète des arguments est prise en charge - les substitutions de macros ne peuvent pas être intégrées. Toutes les macros commencent par un caractère pourcentage '%'. Un argument commençant par deux caractères pourcentage verra l'un d'eux supprimé.

Les macros suivantes sont prises en charge :

%o Type d'opération
%k ID de la clé
%t Type de clé
%d Description de la clé
%c Informations d'appel
%u UID de la clé
%g GID de la clé
%T Keyring du thread demandeur
%P Keyring du processus demandeur
%S Keyring de session du demandeur

Il existe également une autre substitution de macro qui permet l'interpolation du contenu d'une clé :

%{ <type> : <description> }

Cela effectue une recherche d'une clé du type et de la description donnés sur les keyrings du demandeur, et si elle est trouvée, substitue le contenu à la macro. Si elle n'est pas trouvée, une erreur sera enregistrée et la clé en cours de construction sera annulée.

EXEMPLE

Un fichier de base sera installé dans /etc. Il contiendra deux lignes de débogage qui peuvent être utilisées pour tester l'installation :

create user debug:* negate /bin/keyctl negate %k 30 %S
create user debug:loop:* * |/bin/cat
create user debug:* * /usr/share/keyutils/request-key-debug.sh %k %d %c %S
negate * * * /bin/keyctl negate %k 30 %S

Ceci est configuré de telle sorte que quelque chose comme :

keyctl request2 user debug:xxxx negate

créera une clé définie par l'utilisateur négative, quelque chose comme :

keyctl request2 user debug:yyyy spoon

créera une clé définie par l'utilisateur instanciée avec « Debug spoon » comme charge utile, et quelque chose comme :

keyctl request2 user debug:loop:zzzz abcdefghijkl

créera une clé définie par l'utilisateur instanciée avec les informations d'appel comme charge utile.
