rebuilderd(1) Manuel des commandes générales rebuilderd(1)

NOM

rebuilderd - Vérification indépendante des paquets binaires (démon)

SYNTAXE

rebuilderd [-v] [-c /etc/rebuilderd.conf]

DESCRIPTION

Le démon rebuilderd assure le suivi de l'état de tous les paquets, de la file de travaux et attribue les reconstructions aux instances de rebuilderd-worker.

AUTHENTIFICATION

Il existe deux routes publiques permettant à quiconque d'exécuter rebuildctl pkgs ls et rebuildctl queue ls. Tout le reste nécessite une authentification. rebuilderd va vérifier plusieurs emplacements dans cet ordre :

  • ~/.config/rebuilderd.conf
  • /etc/rebuilderd.conf
  • /var/lib/rebuilderd/auth-cookie
  • ~/.local/share/rebuilderd-auth-cookie

Les chemins se terminant par .conf sont analysés comme des fichiers de configuration et nous recherchons une section comme celle-ci :

[auth]
cookie = "Mettez votre secret ici"

Avec les chemins se terminant par auth-cookie, nous prenons le contenu tel quel. Si nous ne trouvons pas de valeur préconfigurée, nous en générons une et l'écrirons dans /var/lib/rebuilderd/auth-cookie.

AUTHENTIFICATION DU TRAVAILLEUR

Il existe deux façons d'authentifier les travailleurs. Si vous travaillez avec un nombre fixe de travailleurs, vous pouvez autoriser leurs clés dans une liste :

[worker]
authorized_workers = ["clef1", "clef2"]

NOTE : Les clés ne sont actuellement pas contestées et le travailleur n'a pas à prouver la propriété de la clé privée. Cela changera dans les versions futures.

Vous pouvez également utiliser un secret partagé qui vous permet de joindre dynamiquement de nouveaux travailleurs. Ceci est particulièrement utile dans les configurations cloud. Un secret peut être généré avec `pwgen -1s 32` :

[worker]
signup_secret = "Mettez votre secret ici"

Si les deux ne sont pas configurés, les travailleurs devront fournir les informations d'identification d'administrateur décrites dans la section précédente.

VOIR AUSSI

rebuilderd.conf(5), rebuildctl(1), rebuilderd-worker(1).
