Nom

readtags - Trouver des entrées de fichier de tags correspondant à des noms spécifiés

SYNOPSIS

readtags -h | --help
readtags (-H | --help-expression) (filtre|trieur|formateur)
readtags -v | --version
readtags [OPTION]... ACTION

DESCRIPTION

Le programme readtags filtre, trie et affiche les entrées de tags dans un fichier de tags. Le filtrage de base s'effectue à l'aide d'actions, par lesquelles vous pouvez lister tous les tags réguliers, les pseudo-tags ou les tags réguliers correspondant à des noms spécifiques. Ensuite, un filtrage, un tri et un formatage supplémentaires peuvent être effectués à l'aide de post-processeurs, à savoir des expressions de filtre, des expressions de tri et des expressions de formatage.

ACTIONS

-l, --list
Lister les tags réguliers.
[-] NOM
Lister les tags réguliers correspondant à NOM. "-" comme NOM indique que les arguments suivants sont des NOMS même s'ils commencent par -.
-D, --list-pseudo-tags
Lister les pseudo-tags. Vous pouvez utiliser cette option avec l'option -Q pour extraire des pseudo-tags spécifiés.

OPTIONS

Contrôle du comportement de lecture des tags

Le comportement de lecture des tags peut être contrôlé à l'aide de ces options :

-t FICHIERTAGE, --tag-file FICHIERTAGE
Utiliser le fichier de tags spécifié (par défaut : "tags"). Donner "-" comme FICHIERTAGE indique la lecture du contenu du fichier de tags depuis l'entrée standard. "-" peut simplifier la ligne de commande. Cependant, cela ne signifie pas une efficacité accrue ; readtags stocke les données dans un fichier temporaire et lit ce fichier pour exécuter l'ACTION.
-s[0|1|2], --override-sort-detection METHODE
Remplacer la détection de tri du fichier de tags. MÉTHODE : unsorted|sorted|foldcase

L'action NOM effectuera une recherche binaire sur les fichiers de tags triés (y compris "foldcase"), ce qui est beaucoup plus rapide que sur les fichiers de tags non triés.

Contrôle du comportement de l'action NOM

Le comportement de l'action NOM peut être contrôlé à l'aide de ces options :

-i, --icase-match
Effectuer une correspondance insensible à la casse dans l'action NOM.
-p, --prefix-match
Effectuer une correspondance de préfixe dans l'action NOM.

Contrôle de la sortie

Par défaut, la sortie de readtags ne contient que les champs nom, entrée et motif. La sortie peut être ajustée à l'aide de ces options :

-A, --absolute-input
Faire la même chose que l'option -C mais en utilisant uniquement le format de chemin absolu.
-C, --canonicalize-input
Résoudre '..' et '.' dans les champs d'entrée des tags réguliers. Ceci produit une représentation unique du chemin d'entrée. Cette option ne fonctionne qu'avec les fichiers de tags ayant le pseudo-tag !_TAG_PROC_CWD.

NOTE : L'implémentation actuelle n'accepte que les pseudo-tags !_TAG_PROC_CWD commençant par / ; un nom de répertoire Windows commençant par une lettre de lecteur comme C:\QuelquePart n'est pas acceptable.

-d, --debug
Activer la sortie de débogage.
-E, --escape-output
Échapper les caractères comme les tabulations dans la sortie, comme décrit dans tags(5).
-e, --extension-fields
Inclure les champs d'extension dans la sortie.
-n, --line-number
Inclure également le champ numéro de ligne lorsque l'option -e est donnée.
-P, --with-pseudo-tags
Lister les pseudo-tags comme si l'option -D était spécifiée, mais continuer le traitement sans quitter. Même si vous spécifiez les options -Q et -P ensemble, -Q n'affecte que les tags réguliers ; il n'affecte pas les pseudo-tags.

Concernant l'option -E : certains caractères sont échappés dans un fichier de tags, pour le rendre lisible par machine. Par exemple, pour s'assurer qu'aucun caractère de tabulation n'apparaît dans les champs autres que le champ motif. Par défaut, readtags les traduit pour les rendre lisibles par l'homme, mais lors de l'utilisation de la sortie de readtags dans un script ou un outil client, l'option -E doit être utilisée. Voir ctags-client-tools(7) pour plus de discussions à ce sujet.

Concernant l'affichage des champs d'entrée ({tagfile} dans tags(5)) avec l'option -E : readtags affiche toujours le champ d'entrée littéralement (tel qu'il est dans le fichier de tags), et lorsque ctags écrit le fichier de tags, les règles d'échappement ne sont appliquées que lorsque le pseudo-tag TAG_OUTPUT_MODE a pour valeur "u-ctags" et que TAG_OUTPUT_FILESEP a pour valeur "slash" pour leurs champs d'entrée, comme expliqué dans ctags-client-tools(7).

Filtrage, tri et formatage

Un filtrage, un tri et un formatage supplémentaires sur les tags listés par les actions sont effectués à l'aide de :

-Q EXP, --filter EXP
Filtrer les tags listés par ACTION avec EXP avant l'affichage.
-S EXP, --sorter EXP
Trier les tags listés par ACTION avec EXP avant l'affichage.
-F EXP, --formatter EXP
Formater les tags listés par ACTION avec EXP lors de l'affichage.

Ceux-ci sont discutés dans la section EXPRESSION.

Exemples

•
Lister tous les tags dans "/chemin/vers/tags" :
$ readtags -t /chemin/vers/tags -l
•
Lister tous les tags dans "tags" commençant par "ma_methode" :
$ readtags -p - ma_methode
•
Lister tous les tags correspondant à "ma_methode", sans tenir compte de la casse :
$ readtags -i - ma_methode
•
Lister tous les tags commençant par "mavaleur", et afficher tous les champs (c'est-à-dire toute la ligne) :
$ readtags -p -ne - mavaleur

EXPRESSION

Des expressions de style Scheme sont utilisées pour les options -Q, -S et -F. Pour ceux qui ne connaissent pas Scheme ou Lisp, retenez simplement :

  • Un appel de fonction est enveloppé dans une paire de parenthèses. Le premier élément est le nom de la fonction/opérateur, les autres sont les arguments.
  • Les appels de fonction peuvent être imbriqués.
  • Les valeurs manquantes et le booléen faux sont représentés par #f. #t et toutes les autres valeurs sont considérées comme vraies.

Ainsi, (+ 1 (+ 2 3)) signifie additionner 2 et 3 d'abord, puis ajouter le résultat à 1. (and "chaîne" 1 #t) signifie un ET logique sur "chaîne", 1 et #t, et le résultat est vrai car il n'y a pas de #f.

Filtrage

Les entrées de tags qui font que l'expression de filtre produit une valeur vraie sont affichées par readtags.

Le

Les opérateurs de base pour le filtrage sont eq?, prefix?, suffix?, substr? et #/PATTERN/. Les champs communs au langage peuvent être accédés à l'aide de variables commençant par $, par exemple, $language représente le champ langue. Par exemple :

•
Lister toutes les balises commençant par « myfunc » dans les fichiers de code Python :
$ readtags -p -Q '(eq? $language "Python")' - myfunc

Les opérateurs downcase ou upcase peuvent être utilisés pour effectuer une correspondance insensible à la casse :

•
Lister toutes les balises contenant « my », insensible à la casse :
$ readtags -Q '(substr? (downcase $name) "my")' -l

Nous avons des opérateurs logiques comme and, or et not. La valeur d'un champ manquant est #f, nous pouvons donc traiter les champs manquants :

•
Lister toutes les balises contenant « impl » dans les fichiers de code Python, mais autoriser le champ language: à être manquant :
$ readtags -Q '(and (substr? $name "impl")\
                    (or (not $language)\
                        (eq? $language "Python")))' -l

#/PATTERN/ est pour le cas où les prédicats de chaîne (prefix?, suffix? et substr?) ne suffisent pas. Vous pouvez utiliser « Posix extended regular expression » comme PATTERN.

•
Lister toutes les balises héritant de la classe « A » :
$ readtags -Q '(#/(^|,) ?A(,|$)/ $inherits)' -l

Ici, $inherits est une liste de classes séparées par des virgules comme « A,B,C », « P, A, Q », ou simplement « A ». Notez que ce filtre fonctionne dans les deux situations où il y a un espace après chaque virgule ou non.

La correspondance insensible à la casse peut être effectuée par #/PATTERN/i :

•
Lister toutes les balises héritant de la classe « A » ou « a » :
$ readtags -Q '(#/(^|,) ?A(,|$)/i $inherits)' -l

Pour inclure « / » dans un modèle, préfixez \ au « / ».

REMARQUE : Le modèle d'expression régulière ci-dessus pour inspecter les héritages n'est qu'un exemple pour montrer comment utiliser l'expression #/PATTERN/. Les générateurs de fichiers de balises n'ont pas de consensus sur le format de inherits:, par exemple, s'il doit y avoir un espace après une virgule. Même les analyseurs dans ctags n'ont pas de consensus. Remarquer le format du champ inherits: de langages spécifiques est nécessaire pour de telles requêtes.

Les expressions #/PATTERN/ et #/PATTERN/i sont pour une utilisation interactive. Readtags propose également un alias string->regexp, donc #/PATTERN/ est égal à (string->regexp "PATTERN"), et #/PATTERN/i est égal à (string->regexp "PATTERN" :case-fold #t). string->regexp n'a pas besoin de préfixer \ pour inclure « / » dans un modèle. string->regexp peut simplifier la construction d'une expression par un outil client. Voir aussi ctags-client-tools(7) pour la construction d'expressions dans votre outil.

Considérons maintenant les champs manquants. Le fichier de balises peut avoir des entrées de balises qui n'ont pas le champ inherits:. Dans ce cas, $inherits est #f, et la correspondance d'expression régulière provoque une erreur, car les opérateurs de chaîne ne fonctionnent que pour les chaînes. Pour éviter ce problème :

•
Lister en toute sécurité toutes les balises héritant de la classe « A » :
$ readtags -Q '(and $inherits (#/(^|,) ?A(,|$)/ $inherits))' -l

Cela garantit que $inherits n'est pas manquant d'abord, puis le fait correspondre par regexp.

Parfois, vous voulez conserver les balises où le champ est manquant. Par exemple, vous voulez exclure les balises de référence, qui sont marquées par le champ extras:, puis vous voulez conserver les balises qui n'ont pas le champ extras: puisqu'elles ne sont pas non plus des balises de référence. Voici comment faire :

•
Lister toutes les balises sauf les balises de référence :
$ readtags -Q '(or (not $extras) (#/(^|,) ?reference(,|$)/ $extras))' -l

Notez que (not $extras) produit #t lorsque $extras est manquant, donc toute l'expression or produit #t.

La combinaison de ctags -o - et readtags -t - est pratique pour inspecter un fichier source tant que le fichier source est suffisamment court.

•
Lister toutes les fonctions larges (> 100 lignes) dans un fichier :
$ ctags -o - --fields=+neKz input.c \
  | ./readtags -t - -en \
               -Q '(and (eq? $kind "function") $end $line (> (- $end $line) 100))' \
               -l
•
Lister toutes les balises incluant la ligne 80 dans un fichier :
$ ctags -o - --fields=+neKz input.c \
  | readtags -t - -ne \
             -Q '(and $line
                      (or (eq? $line 80)
                          (and $end (< $line 80) (< 80 $end))))' \
    -l

Exécutez « readtags -H filter » pour connaître toutes les fonctions et variables valides.

Tri

Lors du tri, l'expression de tri est évaluée sur deux entrées de balise pour décider laquelle doit être triée avant l'autre, jusqu'à ce que l'ordre de toutes les entrées de balise soit décidé.

Dans une expression de tri, $ et & sont utilisés pour accéder aux champs des deux entrées de balise, et appelons-les entrée $ et entrée &. L'expression de tri doit avoir une valeur de -1, 0 ou 1. La valeur -1 signifie que l'entrée $ doit être placée avant l'entrée &, 1 signifie le contraire, et 0 rend leur ordre dans la sortie incertain.

L'opérateur principal de tri est <>. Il est utilisé pour comparer deux chaînes ou deux nombres (les nombres sont pour les champs line: ou end:). Dans (<> a b), si a < b, le résultat est -1 ; a > b produit 1, et a = b produit 0. Les chaînes sont comparées en utilisant la fonction strcmp, voir strcmp(3).

Par exemple, trier par noms, et faire apparaître les plus courts ou les plus petits alphabétiquement avant les autres :

$ readtags -S '(<> $name &name)' -l

Cela lit « Si le nom de la balise dans l'entrée $ est plus petit, il passe avant l'entrée & ».

L'opérateur <or> est utilisé pour chaîner plusieurs expressions jusqu'à ce qu'une renvoie -1 ou 1. Par exemple, trier par noms de fichiers d'entrée, puis par numéros de ligne si elles sont dans le même fichier :

$ readtags -S '(<or> (<> $input &input) (<> $line &line))' -l

L'opérateur *- est utilisé pour inverser le résultat de la comparaison. c'est-à-dire que (*- (<> a b)) est identique à (<> b a).

Les expressions de filtre peuvent être utilisées dans les expressions de tri. La technique consiste à utiliser if pour produire des entiers qui peuvent être comparés en fonction du filtre, comme :

(<> (if filter-expr-on-$-entry -1 1)
    (if filter-expr-on-&-entry -1 1))

Ainsi, si l'entrée $ satisfait le filtre, tandis que l'entrée & ne le fait pas, c'est équivalent à (<> -1 1), qui produit -1.

Par exemple, nous voulons placer les balises avec le type « file » en dessous des autres balises, alors le tri ressemblerait à ceci :

(<> (if (eq? $kind "file") 1 -1)
    (if (eq? &kind "file") 1 -1))

Une lecture rapide nous dit : Si l'entrée $ a le type « file » et que l'entrée & ne l'a pas, le tri devient (<> 1 -1), qui produit 1, donc l'entrée $ est placée sous l'entrée &, exactement ce que nous voulons.

Formatage

Une expression de formatage définit comment readtags imprime les entrées de balise.

Une expression de formatage peut produire une chaîne, un booléen, un entier ou une liste. Readtags imprime la chaîne produite, et l'entier tel quel. Readtags n'imprime rien pour #f, et une nouvelle ligne pour #t.

Une liste peut contenir n'importe quel nombre de chaînes, de booléens, d'entiers et/ou de listes. Readtags imprime les éléments d'une liste séquentiellement et récursivement.

Tous les opérateurs de filtrage sont également disponibles dans les expressions de formatage. En plus des opérateurs, list est disponible dans les expressions de formatage. Comme son nom l'indique, list sert à créer une liste. list crée une liste contenant les arguments passés à l'opérateur. Par exemple, l'expression suivante crée une liste contenant 1, #f et "hello" :

(list 1 #f "hello")

NOTE : Contrairement au vrai Lisp, les constructions de guillemet inverse ne sont pas disponibles.

Pour montrer quelques exemples, le fichier de balises suivant (output.tags) est supposé comme entrée pour readtags :

M    input.c 4;"     macro   file:
N    input.c 3;"     macro   file:
bar  input.c 11;"    f       typeref:typename:void   file:   signature:(char ** argv,int * r)
foo  input.c 6;"     f       typeref:typename:int    file:   signature:(int v)
main input.c 16;"    f       typeref:typename:int    signature:(int argc,char ** argv)

Un exemple pour imprimer uniquement les noms de fonctions :

$ readtags -t output.tags -Q '(eq? $kind "function")' -F '(list $name #t)' -l
bar
foo
main

Faire la même chose uniquement avec une expression de formatage :

$ readtags -t output.tags -F '(if (eq? $kind "function") (list $name #t) #f)' -l
bar
foo
main

Name


readtags - read information from a tags file






Synopsis


readtags‐options ‐expression






Description


The readtags command
    reads tag entries from a tags file, evaluates the given expression for each
    tag entry, and prints the result of the expression to standard output.


The expressions are written in an extension of Lisp.






Actions


The following actions are available in expressions:




begin


Evaluates all arguments in order. Returns the value of the last argument.


begin0

Evaluates all arguments in order. Returns the value of the first argument.


print


Prints the value of the argument to standard output. Returns the value of the argument.


set

Sets the given variable. Returns the value of the argument.








Options




-l


Prints tag entries one per line.


-Q expression


Evaluates the given expression for each tag entry.








Expression


An expression is a list of items, or a single item. An item can be
    a symbol, a number, a string, or a list.


The following symbols are available in expressions:




$name


The name of the tag entry.


$file

The file name of the tag entry.


$address

The address of the tag entry.


$kind

The kind of the tag entry.


$line

The line number of the tag entry.


$language

The language of the tag entry.


$role

The role of the tag entry.


$pattern

The pattern of the tag entry.


$full-trigger

The full trigger of the tag entry.


$tag-trigger

The tag trigger of the tag entry.


$field-count

The number of fields in the tag entry.


$field

The fields of the tag entry.


(prefix? prefix string)


Returns #t if string starts with prefix, and #f otherwise.


(suffix? suffix string)


Returns #t if string ends with suffix, and #f otherwise.


(contains? substring string)


Returns #t if string contains substring, and #f otherwise.


(eq arg1 arg2)


Returns #t if arg1 and arg2 are equal, and #f otherwise.


(neq arg1 arg2)


Returns #t if arg1 and arg2 are not equal, and #f otherwise.


(lt arg1 arg2)


Returns #t if arg1 is less than arg2, and #f otherwise.


(gt arg1 arg2)


Returns #t if arg1 is greater than arg2, and #f otherwise.


(le arg1 arg2)


Returns #t if arg1 is less than or equal to arg2, and #f otherwise.


(ge arg1 arg2)


Returns #t if arg1 is greater than or equal to arg2, and #f otherwise.


(and arg1 arg2)


Returns #t if both arg1 and arg2 are true, and #f otherwise.


(or arg1 arg2)


Returns #t if either arg1 or arg2 is true, and #f otherwise.


(not arg)


Returns #t if arg is false, and #f otherwise.


(if cond then else)


If cond is true, evaluates and returns then, otherwise evaluates and
    returns else.


(quote arg)


Returns arg without evaluating it.


(begin arg1 ... argN)


Evaluates all arguments in order. Returns the value of the last argument.


(begin0 arg1 ... argN)


Evaluates all arguments in order. Returns the value of the first argument.


(set var value)


Sets the variable var to value. Returns value.


(print arg)


Prints the value of arg to standard output. Returns the value of arg.

#include <stddef.h>

int main(int argc, char ** argv);








Inspecting   the Behavior of Expressions


The print operator can be used to print the value of an
    expression. For example:






$ readtags -Q '(print $name)' -l






prints the name of each tag entry before it. Since the return
    value of print is not #f, all the tag entries are printed. We could
    control this using the begin or begin0 operator. begin
    returns the value of its last argument, and begin0 returns the value
    of its first argument. For example:






$ readtags -Q '(begin0 #f (print (prefix? "ctags" "ct")))' -l






prints a bunch of "#t" (depending on how many lines are
    in the tags file), and the actual tag entries are not printed.
