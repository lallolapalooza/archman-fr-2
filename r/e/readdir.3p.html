READDIR(3P) Manuel du programmeur POSIX READDIR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

readdir, readdir_r — lire un répertoire

SYNOPIS

#include <dirent.h>
struct dirent *readdir(DIR *dirp);
int readdir_r(DIR *restrict dirp, struct dirent *restrict entry,
    struct dirent **restrict result);

DESCRIPTION

Le type DIR, défini dans l'en-tête <dirent.h>, représente un flux de répertoire, qui est une séquence ordonnée de toutes les entrées de répertoire dans un répertoire particulier. Les entrées de répertoire représentent des fichiers ; les fichiers peuvent être supprimés d'un répertoire ou ajoutés à un répertoire de manière asynchrone à l'opération de readdir().

La fonction readdir() renvoie un pointeur vers une structure représentant l'entrée de répertoire à la position actuelle dans le flux de répertoire spécifié par l'argument dirp, et positionne le flux de répertoire à l'entrée suivante. Elle renvoie un pointeur nul lorsqu'elle atteint la fin du flux de répertoire. La structure dirent définie dans l'en-tête <dirent.h> décrit une entrée de répertoire. La valeur du membre d_ino de la structure est définie sur le numéro de série du fichier nommé par le membre d_name. Si le membre d_name nomme un lien symbolique, la valeur du membre d_ino est définie sur le numéro de série du lien symbolique lui-même.

La fonction readdir() ne doit pas renvoyer d'entrées de répertoire contenant des noms vides. Si des entrées pour point (.) ou point-point (..) existent, une entrée sera renvoyée pour le point et une entrée sera renvoyée pour le point-point ; sinon, elles ne seront pas renvoyées.

L'application ne doit pas modifier la structure vers laquelle pointe la valeur de retour de readdir(), ni les zones de stockage pointées par des pointeurs dans la structure. Le pointeur retourné, et les pointeurs dans la structure, peuvent être invalidés ou la structure ou les zones de stockage peuvent être écrasés par un appel ultérieur à readdir() sur le même flux de répertoire. Ils ne seront pas affectés par un appel à readdir() sur un flux de répertoire différent. Le pointeur retourné, et les pointeurs dans la structure, peuvent également être invalidés si le thread appelant est terminé.

Si un fichier est supprimé ou ajouté au répertoire après le dernier appel à opendir() ou rewinddir(), il est indéterminé si un appel ultérieur à readdir() renverra une entrée pour ce fichier.

La fonction readdir() peut mettre en mémoire tampon plusieurs entrées de répertoire par opération de lecture réelle ; readdir() marquera pour mise à jour l'horodatage de dernier accès aux données du répertoire chaque fois que le répertoire est effectivement lu.

Après un appel à fork(), soit le parent, soit l'enfant (mais pas les deux) peuvent continuer à traiter le flux de répertoire en utilisant readdir(), rewinddir(), ou seekdir(). Si les deux processus, parent et enfant, utilisent ces fonctions, le résultat est indéfini.

La fonction readdir() n'est pas nécessairement thread-safe.

Les applications souhaitant vérifier les situations d'erreur doivent définir errno à 0 avant d'appeler readdir(). Si errno est défini à une valeur non nulle au retour, une erreur s'est produite.

La fonction readdir_r() initialise la structure dirent référencée par entry pour représenter l'entrée de répertoire à la position actuelle dans le flux de répertoire référencé par dirp, stocke un pointeur vers cette structure à l'emplacement référencé par result, et positionne le flux de répertoire à l'entrée suivante.

Le stockage pointé par entry doit être suffisamment grand pour un dirent avec un tableau de membres char d_name contenant au moins {NAME_MAX}+1 éléments.

Lors d'un retour réussi, le pointeur retourné à *result aura la même valeur que l'argument entry. Lors de l'atteinte de la fin du flux de répertoire, ce pointeur aura la valeur NULL.

La fonction readdir_r() ne doit pas renvoyer d'entrées de répertoire contenant des noms vides.

Si un fichier est supprimé ou ajouté au répertoire après le dernier appel à opendir() ou rewinddir(), il est indéterminé si un appel ultérieur à readdir_r() renverra une entrée pour ce fichier.

La fonction readdir_r() peut mettre en mémoire tampon plusieurs entrées de répertoire par opération de lecture réelle ; readdir_r() marquera pour mise à jour l'horodatage de dernier accès aux données du répertoire chaque fois que le répertoire est effectivement lu.

VALEUR DE RETOUR

En cas de succès, readdir() renvoie un pointeur vers un objet de type struct dirent. Lorsqu'une erreur est rencontrée, un pointeur nul est renvoyé et errno est défini pour indiquer l'erreur. Lorsque la fin du répertoire est rencontrée, un pointeur nul est renvoyé et errno n'est pas modifié.

En cas de succès, la fonction readdir_r() renvoie zéro ; sinon, un numéro d'erreur est renvoyé pour indiquer l'erreur.

ERREURS

Ces fonctions échouent si :

EOVERFLOW
Une des valeurs dans la structure à renvoyer ne peut pas être représentée correctement.

Ces fonctions peuvent échouer si :

EBADF
L'argument dirp ne fait pas référence à un flux de répertoire ouvert.
ENOENT
La position actuelle du flux de répertoire est invalide.

EXEMPLES

L'exemple de programme suivant recherche dans le répertoire courant chacun des arguments fournis sur la ligne de commande.

#include <dirent.h>
#include <errno.h>
#include <stdio.h>
#include <string.h>
static void lookup(const char *arg)
{
    DIR *dirp;
    struct dirent *dp;
    if ((dirp = opendir(".")) == NULL) {
        perror("impossible d'ouvrir '.'");
        return;
    }
    do {
        errno = 0;
        if ((dp = readdir(dirp)) != NULL) {
            if (strcmp(dp->d_name, arg) != 0)
                continue;
            (void) printf("trouvé %s\n", arg);
            (void) closedir(dirp);
                return;
        }
    } while (dp != NULL);
    if (errno != 0)
        perror("erreur de lecture du répertoire");
    else
        (void) printf("échec de la recherche de %s\n", arg);
    (void) closedir(dirp);
    return;
}
int main(int argc, char *argv[])
{
    int i;
    for (i = 1; i < argc; i++)
        lookup(argv[i]);
    return (0);
}

USAGE APPLICATIF

La fonction readdir() doit être utilisée en conjonction avec opendir(), closedir(), et rewinddir() pour examiner le contenu du répertoire.

La fonction readdir_r() est thread-safe et renverra les valeurs dans un tampon fourni par l'utilisateur au lieu d'utiliser potentiellement une zone de données statique qui pourrait être écrasée par chaque appel.

RATIONALE

La valeur retournée par readdir() ne fait que représenter une entrée de répertoire. Aucune équivalence ne doit être déduite.

Les implémentations historiques de readdir() obtiennent plusieurs entrées de répertoire sur une seule opération de lecture, ce qui permet aux opérations readdir() ultérieures d'opérer à partir des informations mises en mémoire tampon. Toute formulation exigeant que chaque opération readdir() réussie marque l'horodatage de dernier accès aux données du répertoire pour mise à jour interdirait de telles implémentations historiques orientées performance.

Lors du retour d'une entrée de répertoire pour la racine d'un système de fichiers monté, certaines implémentations historiques de readdir() renvoyaient le numéro de série du fichier du point de montage sous-jacent, plutôt que celui de la racine du système de fichiers monté. Étant donné que readdir() retourne NULL lorsqu'il détecte une erreur et lorsque la fin du répertoire est atteinte, une application qui a besoin de faire la différence doit définir errno à zéro avant l'appel et le vérifier si NULL est retourné. Comme la fonction ne doit pas modifier errno dans le second cas et doit lui affecter une valeur non nulle dans le premier cas, un errno nul après un appel retournant NULL indique la fin du répertoire ; sinon, une erreur.

Des routines pour traiter ce problème plus directement ont été proposées :

int derror (dirp)
DIR *dirp;
void clearderr (dirp)
DIR *dirp;

La première indiquerait si une erreur s'était produite et la seconde effacerait l'indication d'erreur. La méthode plus simple impliquant errno a été adoptée à la place, en exigeant que readdir() ne modifie pas errno lorsque la fin du répertoire est rencontrée.

Une erreur ou un signal indiquant qu'un répertoire a changé pendant qu'il était ouvert a été envisagé mais rejeté.

La version thread-safe de la fonction de lecture de répertoire retourne les valeurs dans un tampon fourni par l'utilisateur au lieu d'utiliser éventuellement une zone de données statique qui pourrait être écrasée à chaque appel. Soit la constante de compilation {NAME_MAX}, soit l'option correspondante pathconf() peut être utilisée pour déterminer la taille maximale des noms de chemins retournés.
