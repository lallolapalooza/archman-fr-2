NOM

refind-mkdefault - Définir rEFInd comme option de démarrage EFI par défaut

SYNTAXE

refind-mkdefault [ -L|--label <nom> ]

DESCRIPTION

Le démarrage EFI repose normalement sur des entrées de gestionnaire de démarrage stockées dans la NVRAM, qui décrivent les emplacements des programmes de démarrage EFI et l'ordre dans lequel le firmware tentera de les lancer. Sous Linux, ces entrées peuvent être créées, supprimées et manipulées avec l'utilitaire efibootmgr.

De nombreux systèmes d'exploitation et paquets Linux supposent qu'ils doivent contrôler le processus de démarrage, créant ainsi des entrées de démarrage NVRAM pour eux-mêmes et plaçant ces entrées en premier dans l'ordre de démarrage. Si vous avez l'intention que rEFInd contrôle le processus de démarrage, de tels changements sont cependant indésirables et nécessitent des ajustements via efibootmgr. Ces ajustements sont ennuyeux à faire et peuvent être intimidants pour les non-experts.

Le script refind-mkdefault simplifie les choses : exécuter ce script sans option définit rEFInd comme programme de démarrage par défaut. Les détails de ce que fait le script dépendent de l'état actuel de la liste d'ordre de démarrage et des entrées de démarrage existantes :

*
Si une entrée rEFInd existe déjà dans l'ordre de démarrage et est déjà en première position, aucun changement n'est apporté.
*
Si une entrée rEFInd existe déjà dans l'ordre de démarrage mais n'est pas en première position, cette entrée est déplacée à la première position dans l'ordre de démarrage.
*
Si plusieurs entrées rEFInd existent dans l'ordre de démarrage, refind-mkdefault déplace celle qui apparaît le plus tôt au début de la liste d'ordre de démarrage.
*
Si aucune entrée rEFInd n'existe dans l'ordre de démarrage mais qu'une entrée de démarrage rEFInd peut être trouvée dans la liste des entrées Boot####, elle est ajoutée à l'ordre de démarrage et placée au début de la liste.
*
Si plusieurs entrées de démarrage rEFInd existent mais qu'aucune n'est dans l'ordre de démarrage, toutes les entrées sont ajoutées à l'ordre de démarrage, mais laquelle est la première n'est pas contrôlée.

Une entrée rEFInd est définie comme celle qui contient la chaîne refind (insensible à la casse). Cette chaîne peut exister dans la description ou dans le nom de fichier. La chaîne utilisée pour définir l'entrée rEFInd peut être modifiée via l'option --label (-L).

L'intention est que refind-mkdefault puisse être appelé après avoir démarré via GRUB ou un autre moyen pour restaurer rEFInd comme programme de démarrage par défaut. Il peut également être placé dans un script de démarrage et/ou d'arrêt pour restaurer automatiquement rEFInd à sa position par défaut. Comme il ne réécrit pas l'ordre de démarrage si rEFInd est listé comme première entrée de démarrage, cette pratique devrait présenter peu de risques.

OPTIONS

-L | --label <nom>
Au lieu de rechercher la chaîne refind dans la sortie d'efibootmgr comme moyen d'identifier rEFInd, recherche la chaîne nom.

VALEURS DE RETOUR

refind-mkdefault retourne les valeurs suivantes :

0
Le script s'est terminé avec succès, ce qui peut signifier soit qu'aucun changement n'était nécessaire, soit que l'appel à efibootmgr a renvoyé un code de succès.
1
Les variables d'ordre de démarrage EFI sont disponibles et une entrée rEFInd a été trouvée, mais l'appel à efibootmgr a renvoyé un code d'échec.
2
Les entrées de démarrage EFI ne sont pas disponibles. Cette condition est souvent une indication d'un EFI défectueux ou d'un contenu NVRAM gravement endommagé.
3
Aucune entrée rEFInd n'a pu être trouvée dans la liste des options de démarrage, et donc aucun changement n'a été apporté à la liste d'ordre de démarrage.
4
Le script n'a pas pu s'exécuter en raison de problèmes liés au système d'exploitation -- le système d'exploitation n'était pas Linux, l'utilitaire efibootmgr n'était pas disponible, ou le script n'a pas été exécuté en tant que root.

LIMITATIONS

*
refind-mkdefault ne fonctionne pas lorsqu'il est démarré en mode BIOS (y compris via un module de support de compatibilité, ou CSM, sur un ordinateur basé sur EFI). De même, il ne fonctionne pas si efibootmgr n'est pas installé ou ne fonctionne pas pour une raison quelconque.
*
Le script utilise un algorithme très simple pour déterminer ce qu'il faut déplacer au début de la liste d'ordre de démarrage. Cet algorithme peut échouer si le système a des entrées de démarrage rEFInd redondantes ou non fonctionnelles, ou si ces entrées ne sont pas nommées de manière attendue. Un nettoyage des entrées de démarrage via une utilisation manuelle de efibootmgr peut être nécessaire dans de tels cas.
