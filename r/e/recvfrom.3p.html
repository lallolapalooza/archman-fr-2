RECVFROM(3P) Manuel du programmeur POSIX RECVFROM(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

recvfrom — recevoir un message d'un socket

SYNTAXE

#include <sys/socket.h>
ssize_t recvfrom(int socket, void *restrict buffer, size_t length,
    int flags, struct sockaddr *restrict address,
    socklen_t *restrict address_len);

DESCRIPTION

La fonction recvfrom() reçoit un message d'un socket en mode connecté ou non connecté. Elle est normalement utilisée avec des sockets en mode non connecté car elle permet à l'application de récupérer l'adresse source des données reçues.

La fonction recvfrom() prend les arguments suivants :

socket
Spécifie le descripteur de fichier du socket.
buffer
Pointe vers le tampon où le message doit être stocké.
length
Spécifie la longueur en octets du tampon pointé par l'argument buffer.
flags
Spécifie le type de réception du message. Les valeurs de cet argument sont formées en combinant logiquement zéro ou plusieurs des valeurs suivantes :
MSG_PEEK
Jette un œil à un message entrant. Les données sont traitées comme non lues et la prochaine fonction recvfrom() ou similaire retournera toujours ces données.
MSG_OOB
Demande des données hors bande. La signification et la sémantique des données hors bande sont spécifiques au protocole.
MSG_WAITALL
Sur les sockets SOCK_STREAM, cela demande que la fonction bloque jusqu'à ce que la totalité des données puisse être retournée. La fonction peut retourner une quantité de données inférieure si le socket est un socket basé sur des messages, si un signal est intercepté, si la connexion est terminée, si MSG_PEEK a été spécifié, ou si une erreur est en attente pour le socket.
address
Un pointeur nul, ou pointe vers une structure sockaddr dans laquelle l'adresse de l'expéditeur doit être stockée. La longueur et le format de l'adresse dépendent de la famille d'adresses du socket.
address_len
Soit un pointeur nul, si address est un pointeur nul, soit un pointeur vers un objet socklen_t qui, à l'entrée, spécifie la longueur de la structure sockaddr fournie, et à la sortie spécifie la longueur de l'adresse stockée.

La fonction recvfrom() retourne la longueur du message écrit dans le tampon pointé par l'argument buffer. Pour les sockets basés sur des messages, tels que SOCK_RAW, SOCK_DGRAM et SOCK_SEQPACKET, le message entier est lu en une seule opération. Si un message est trop long pour tenir dans le tampon fourni, et que MSG_PEEK n'est pas défini dans l'argument flags, les octets excédentaires sont rejetés. Pour les sockets basés sur des flux, tels que SOCK_STREAM, les frontières des messages sont ignorées. Dans ce cas, les données sont retournées à l'utilisateur dès qu'elles deviennent disponibles, et aucune donnée n'est rejetée.

Si l'indicateur MSG_WAITALL n'est pas défini, les données sont retournées uniquement jusqu'à la fin du premier message.

Tous les protocoles ne fournissent pas l'adresse source des messages. Si l'argument address n'est pas nul et que le protocole fournit l'adresse source des messages, l'adresse source du message reçu est stockée dans la structure sockaddr pointée par l'argument address, et la longueur de cette adresse est stockée dans l'objet pointé par l'argument address_len.

Si la longueur réelle de l'adresse est supérieure à la longueur de la structure sockaddr fournie, l'adresse stockée est tronquée.

Si l'argument address n'est pas nul et que le protocole ne fournit pas l'adresse source des messages, la valeur stockée dans l'objet pointé par address est indéterminée.

Si aucun message n'est disponible au niveau du socket et que O_NONBLOCK n'est pas défini sur le descripteur de fichier du socket, recvfrom() se bloque jusqu'à l'arrivée d'un message. Si aucun message n'est disponible au niveau du socket et que O_NONBLOCK est défini sur le descripteur de fichier du socket, recvfrom() échoue et définit errno à [EAGAIN] ou [EWOULDBLOCK].

VALEUR DE RETOUR

En cas de succès, recvfrom() retourne la longueur du message en octets. Si aucun message n'est disponible à recevoir et que le pair a effectué une fermeture ordonnée, recvfrom() retourne 0. Sinon, la fonction retourne -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction recvfrom() échoue si :

EAGAIN ou EWOULDBLOCK

Le descripteur de fichier du socket est marqué O_NONBLOCK et aucune donnée n'attend d'être reçue ; ou MSG_OOB est défini et aucune donnée hors bande n'est disponible et soit le descripteur de fichier du socket est marqué O_NONBLOCK, soit le socket ne supporte pas le blocage pour attendre des données hors bande.
EBADF
L'argument socket n'est pas un descripteur de fichier valide.
ECONNRESET
Une connexion a été fermée de force par un pair.
EINTR
Un signal a interrompu recvfrom() avant que des données ne soient disponibles.
EINVAL
L'indicateur MSG_OOB est défini et aucune donnée hors bande n'est disponible.
ENOTCONN
Une réception est tentée sur un socket en mode connecté qui n'est pas connecté.
ENOTSOCK
L'argument socket ne fait pas référence à un socket.
EOPNOTSUPP
Les indicateurs spécifiés ne sont pas pris en charge pour ce type de socket.
ETIMEDOUT
La connexion a expiré pendant l'établissement de la connexion, ou en raison d'une transmission expirée sur une connexion active.

La fonction recvfrom() peut échouer si :

EIO
Une erreur d'E/S s'est produite lors de la lecture ou de l'écriture dans le système de fichiers.
ENOBUFS
Des ressources insuffisantes étaient disponibles dans le système pour effectuer l'opération.
ENOMEM
Une mémoire insuffisante était disponible pour répondre à la demande.

This page is a manual page for POSIX.1-2017.

NAME

recvfrom — receive a message from a socket

SYNOPSIS

#include <sys/socket.h>

ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
    struct sockaddr *src_addr, socklen_t *addrlen);

DESCRIPTION

The recvfrom() function shall retrieve a message from a connection-mode or connectionless-mode socket.

The sockfd argument specifies the file descriptor of the socket from which to receive.

The buf argument points to the buffer where the message will be stored.

The len argument specifies the length in bytes of the buffer pointed to by buf.

The flags argument specify socket options that affect the way a call is made. See recv(2) .

If src_addr is not a null pointer, the kernel-side address of the sender shall be placed in the buffer pointed to by src_addr. The value pointed to by addrlen prior to the call shall specify the size of the buffer pointed to by src_addr. On return, the value pointed to by addrlen shall be set to the actual length of the address. If the src_addr argument is not a null pointer and the actual length of the address is greater than the value pointed to by addrlen, the value pointed to by addrlen is still updated, but the contents of the buffer are not necessarily the complete address.

If the socket is connection-mode, src_addr and addrlen are ignored.

RETURN VALUE

Upon successful completion, recvfrom() shall return the number of bytes received, or 0 if an orderly peer-shutdown has been received.

Upon failure, recvfrom() shall return -1 and set errno to indicate the error.

ERRORS

The recvfrom() function shall fail if:

EBADF
The sockfd argument is not a valid file descriptor.
ECONNRESET
Connection reset by peer.
EINTR
The call was interrupted by a signal prior to any data being received.
EINVAL
The socket is not in a listening state, and recvfrom() was invoked.
ENOTCONN
The socket is not connected, and it was not bound to an address.
ENOTSOCK
The sockfd argument does not refer to a socket.
EWOULDBLOCK
The socket is marked non-blocking and no messages are available to be received.

The recvfrom() function may fail if:

EFAULT
buf or src_addr points to an invalid address.
EMSGSIZE
The message is too long to fit in the supplied buffer.
ENOMEM
Insufficient memory is available.
ENOBUFS
No buffer space is available for the incoming data.
ETIMEDOUT
Connection timed out during connection establishment.
