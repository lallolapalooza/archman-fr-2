REALPATH(3P) Manuel du programmeur POSIX REALPATH(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

realpath — résout un nom de chemin

SYNTAXE

#include <stdlib.h>
char *realpath(const char *restrict file_name,
    char *restrict resolved_name);

DESCRIPTION

La fonction realpath() dérive, à partir du nom de chemin pointé par file_name, un nom de chemin absolu qui résout au même entrée de répertoire, dont la résolution n'implique pas '.', '..', ou des liens symboliques. Si resolved_name est un pointeur nul, le nom de chemin généré sera stocké sous forme de chaîne terminée par un caractère nul dans un tampon alloué comme par un appel à malloc(). Sinon, si {PATH_MAX} est défini comme une constante dans l'en-tête <limits.h>, alors le nom de chemin généré sera stocké sous forme de chaîne terminée par un caractère nul, jusqu'à un maximum de {PATH_MAX} octets, dans le tampon pointé par resolved_name.

Si resolved_name n'est pas un pointeur nul et que {PATH_MAX} n'est pas défini comme une constante dans l'en-tête <limits.h>, le comportement est indéfini.

VALEUR DE RETOUR

En cas de succès, realpath() renvoie un pointeur vers le tampon contenant le nom résolu. Sinon, realpath() renvoie un pointeur nul et définit errno pour indiquer l'erreur.

Si l'argument resolved_name est un pointeur nul, le pointeur renvoyé par realpath() peut être passé à free().

Si l'argument resolved_name n'est pas un pointeur nul et que la fonction realpath() échoue, le contenu du tampon pointé par resolved_name est indéfini.

ERREURS

La fonction realpath() échouera si :

EACCES
La permission de recherche a été refusée pour un composant du préfixe du chemin de file_name.
EINVAL
L'argument file_name est un pointeur nul.
EIO
Une erreur s'est produite lors de la lecture du système de fichiers.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument file_name.
ENAMETOOLONG

La longueur d'un composant d'un nom de chemin est supérieure à {NAME_MAX}.
ENOENT
Un composant de file_name ne nomme pas un fichier existant ou file_name pointe vers une chaîne vide.
ENOTDIR
Un composant du préfixe du chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou l'argument file_name contient au moins un caractère autre que <slash> et se termine par un ou plusieurs <slash> finaux et le dernier composant du nom de chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.

La fonction realpath() peut échouer si :

EACCES
L'argument file_name ne commence pas par un <slash> et aucun des liens symboliques (le cas échéant) traités lors de la résolution du nom de chemin de file_name n'avait un contenu commençant par un <slash>, et soit la permission de recherche a été refusée pour le répertoire courant, soit la permission de lecture ou de recherche a été refusée pour un répertoire au-dessus du répertoire courant dans la hiérarchie des fichiers.
ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument file_name.
ENAMETOOLONG

La longueur d'un nom de chemin dépasse {PATH_MAX}, ou la résolution du nom de chemin d'un lien symbolique produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.
ENOMEM
Un espace de stockage suffisant n'est pas disponible.

Les sections suivantes sont informatives.

EXEMPLES

Génération d'un Nom de Chemin Absolu

L'exemple suivant génère un nom de chemin absolu pour le fichier identifié par l'argument symlinkpath. Le nom de chemin généré est stocké dans le tampon pointé par actualpath.

#include <stdlib.h>
...
char *symlinkpath = "/tmp/symlink/file";
char *actualpath;
actualpath = realpath(symlinkpath, NULL);
if (actualpath != NULL)
{
    ... utiliser actualpath ...
    free(actualpath);
}
else
{
    ... gérer l'erreur ...
}

UTILISATION PAR APPLICATION

Pour les fonctions qui allouent de la mémoire comme par malloc(), l'application doit libérer cette mémoire lorsqu'elle n'est plus nécessaire par un appel à free(). Pour realpath(), il s'agit de la valeur de retour.

RATIONALE

Étant donné que realpath() n'a pas d'argument de length, si {PATH_MAX} n'est pas défini comme une constante dans <limits.h>, les applications n'ont aucun moyen de déterminer la taille du tampon qu'elles doivent allouer pour qu'il soit sûr de le passer à realpath(). Une valeur {PATH_MAX} obtenue à partir d'un appel antérieur à pathconf() est obsolète au moment où realpath() est appelé. Par conséquent, la seule façon fiable d'utiliser realpath() lorsque {PATH_MAX} n'est pas défini dans <limits.h> est de passer un pointeur nul pour resolved_name afin que realpath() alloue un tampon de la taille nécessaire.
