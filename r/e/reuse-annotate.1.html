NOM

reuse-annotate - Ajoute des informations REUSE dans les fichiers

SYNTAXE

reuse annotate [options] [fichier ...]

DESCRIPTION

reuse-annotate ajoute des informations REUSE dans les en-têtes des fichiers. Ceci est utile en particulier dans les scénarios où vous souhaitez ajouter un détenteur de droits d'auteur ou une licence à un grand nombre de fichiers sans avoir à éditer manuellement l'en-tête de chaque fichier.

Attention :

Soyez prudent lors de l'utilisation de annotate dans des processus automatisés. Bien que rien ne vous empêche de l'utiliser dans votre script de publication, vous devez vous assurer que les informations qu'il ajoute reflètent réellement la réalité. Il est préférable de vérifier cela manuellement.

L'en-tête REUSE est placé tout en haut du fichier, à l'exception de certains en-têtes existants tels que les shebangs (#!) ou les déclarations XML (<?xml version="1.0"?>). Si un en-tête différent contenant des informations de droit d'auteur ou de licence existe déjà dans le fichier — en haut ou ailleurs — cet en-tête est remplacé en place par les informations REUSE fournies.

L'outil tente de détecter automatiquement le style de commentaire à utiliser à partir de l'extension de fichier, et utilise ce style de commentaire.

Normalement, l'outil utilise un style de commentaire sur une seule ligne lorsqu'il est disponible (par exemple, // est utilisé au lieu de /* ... */ pour les styles de commentaires C++). Si aucun style de commentaire sur une seule ligne n'est disponible, un style multiligne est utilisé.

OPTIONS OBLIGATOIRES

Au moins une des options suivantes est requise. Elles contiennent les informations que l'outil ajoutera aux fichiers. Vous pouvez répéter ces options.

-c, --copyright DROITDAUTEUR
Un détenteur de droits d'auteur. Cela ne contient pas l'année ni le préfixe de droit d'auteur. Voir --year et --copyright-prefix pour l'année et le préfixe.
-l, --license LICENCE
Un identifiant de licence SPDX.
--contributor CONTRIBUTEUR
Le nom d'un contributeur. Le contributeur sera ajouté via l'étiquette SPDX-FileContributor:.

AUTRES OPTIONS

-y, --year ANNEE
Définit l'année de la ou des notices de droit d'auteur. Si elle n'est pas définie, l'année par défaut est l'année en cours. La valeur peut être une plage (complexe), telle que '2017-2019', ou '2017, 2019-2022, 2024-Présent'.
-s, --style STYLE
Remplace le mécanisme de détection du style de commentaire pour forcer un style de commentaire sur les fichiers. Ceci est utile lorsqu'une extension de fichier n'est pas reconnue, ou lorsqu'une extension de fichier est associée à un style de commentaire avec lequel vous n'êtes pas d'accord.
--copyright-prefix PREFIXE
Le préfixe à utiliser dans la notice de droit d'auteur. Si non défini, spdx est utilisé comme préfixe. Les préfixes de droit d'auteur disponibles sont :
spdx:               SPDX-FileCopyrightText: <année> <auteur>
spdx-c:             SPDX-FileCopyrightText: (C) <année> <auteur>
spdx-symbol:        SPDX-FileCopyrightText: © <année> <auteur>
spdx-string:        SPDX-FileCopyrightText: Copyright <année> <auteur>
spdx-string-c:      SPDX-FileCopyrightText: Copyright (C) <année> <auteur>
spdx-string-symbol: SPDX-FileCopyrightText: Copyright © <année> <auteur>
string:             Copyright <année> <auteur>
string-c:           Copyright (C) <année> <auteur>
string-symbol:      Copyright © <année> <auteur>
symbol:             © <année> <auteur>
-t, --template MODELE
Le modèle à utiliser pour l'en-tête de commentaire. Le nom du modèle correspond au nom du modèle dans .reuse/templates/, sans le suffixe .jinja2 ou .commented.jinja2.
--exclude-year
Ne pas inclure l'année dans la notice de droit d'auteur.
--merge-copyrights
Si deux (ou plusieurs) notices de droit d'auteur sont identiques sauf pour leurs années, les afficher sur une seule ligne avec les années combinées.
--single-line
Forcer l'outil à utiliser un style de commentaire sur une seule ligne. Pour C, ce serait //.
--multi-line
Forcer l'outil à utiliser un style de commentaire multiligne. Pour C, ce serait /* ... */.
-r, --recursive
Annoter tous les fichiers récursivement sous le chemin spécifié.
--no-replace
Au lieu de remplacer le premier en-tête du fichier contenant des informations de droit d'auteur et de licence, le conserver et créer un nouvel en-tête en haut.
--force-dot-license
Toujours écrire un fichier .license au lieu d'essayer d'écrire dans le fichier lui-même.
--fallback-dot-license
Au lieu d'avorter lorsqu'une extension de fichier n'a pas de style de commentaire associé, créer un fichier .license pour ces fichiers.
--skip-unrecognised
Au lieu d'avorter lorsqu'une extension de fichier n'a pas de style de commentaire associé, ignorer ces fichiers.
--help
Afficher l'aide et quitter.

MODELES

Lorsque l'outil ajoute un en-tête à un fichier, il liste normalement d'abord toutes les notices de droit d'auteur par ordre alphabétique, puis tous les contributeurs, ensuite ajoute une ligne vide, et enfin liste toutes les Expressions de Licence SPDX par ordre alphabétique. Il est possible de changer ce comportement et d'utiliser un type d'en-tête personnalisé contenant du texte supplémentaire. Ceci est fait via des modèles Jinja2.

Le modèle par défaut est :

{% for copyright_line in copyright_lines %}
{{ copyright_line }}
{% endfor %}
{% for contributor_line in contributor_lines %}
SPDX-FileContributor: {{ contributor_line }}
{% endfor %}
{% for expression in spdx_expressions %}
SPDX-License-Identifier: {{ expression }}
{% endfor %}

Les modèles sont automatiquement commentés par l'outil, en fonction du style de commentaire détecté ou spécifié.

Vous pouvez créer vos propres modèles Jinja2 et les placer dans .reuse/templates/. Vous devez suffixer votre modèle avec .jinja2.

Dans le modèle, vous avez accès aux variables suivantes :

  • copyright_lines --- une liste de notices de droit d'auteur (chaîne).
  • contributor_lines --- une liste de contributeurs (chaîne).
  • spdx_expressions --- une liste d'Expressions de Licence SPDX (chaîne).

À l'avenir, d'autres variables pourront être ajoutées.

Dans certains cas, vous pourriez vouloir faire un formatage personnalisé des commentaires. Dans ces cas, vous pouvez pré-formater votre en-tête comme un commentaire. Lorsque vous le faites, suffixez votre modèle avec .commented.jinja2.

Un exemple de modèle personnalisé avec commentaires manuels est :

# (C) {{ year }} {{ copyright }}
#
# Ce fichier est sous licence {{ spdx_expression }}
# Il est considéré comme domaine public si vous le souhaitez.
#
# Code par {{ contributor }}

NAME

reuse-annotate

annotate files with license and copyright information

SYNOPSIS

reuse annotate [-h|--help] [-v|--verbose] [-q|--quiet] [--config=path] [--no-global-config] [--copyright=name] [--license=expression] [--ignore-file=glob] [--skip-unrecognized] [file...]

DESCRIPTION

This command adds a license header to the given files. This command is used to add license and copyright information to files that do not yet have it. This command does not modify files that already have license information. The license information is checked using the reuse tool.

MANDATORY OPTIONS

The following options are mandatory:

--copyright=name
Set the copyright holder name. This can be a person or an organization.
--license=expression
Set the SPDX license expression. This can be a single license (e.g. MIT) or a combination of licenses (e.g. MIT OR Apache-2.0).

OTHER OPTIONS

-h, --help
Show help message and exit.
-v, --verbose
Enable verbose output. When this option is used, reuse will print more information about what it is doing.
-q, --quiet
Enable quiet output. When this option is used, reuse will print less information about what it is doing.
--config=path
Use a specific configuration file. If this option is not used, reuse will look for a configuration file in the current directory and its parent directories.
--no-global-config
Do not load global configuration files. This option can be used to ensure that reuse is using only the configuration files specified with --config.
--ignore-file=glob
Ignore files that match the given glob pattern. This option can be used multiple times to ignore multiple files.
--skip-unrecognized
Skip files that are not recognized by reuse. This option can be used to avoid errors when dealing with files that reuse does not know how to handle.

TEMPLATES

{% endfor %}

 * version.

 *
 * You should have received a copy of the GNU General Public License along with
 * this program. If not, see <https://www.gnu.org/licenses/>.
{% endif %}
 */

EXAMPLES

The basic usage is reuse annotate --copyright="Jane Doe" --license=MIT my_file.py. This will add the following header to the file (assuming that the current year is 2019):

# SPDX-FileCopyrightText: 2019 Jane Doe
#
# SPDX-License-Identifier: MIT

Author

Free Software Foundation Europe

Copyright
