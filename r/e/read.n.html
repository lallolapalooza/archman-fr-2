read(n) Commandes intégrées Tcl read(n)

NOM

read - Lire depuis un canal

SYNOPSIS

read ?-nonewline? canalId

read canalId numCaractères

DESCRIPTION

Dans la première forme, la commande read lit toutes les données du canalId jusqu'à la fin du fichier. Si le commutateur -nonewline est spécifié, le dernier caractère du fichier est ignoré s'il s'agit d'une nouvelle ligne. Dans la seconde forme, l'argument supplémentaire spécifie combien de caractères lire. Exactement ce nombre de caractères sera lu et retourné, à moins qu'il n'y ait moins de numCaractères restants dans le fichier ; dans ce cas, tous les caractères restants sont retournés. Si le canal est configuré pour utiliser un encodage multi-octets, le nombre de caractères lus peut ne pas être le même que le nombre d'octets lus.

CanalId doit être un identifiant d'un canal ouvert tel que le canal d'entrée standard Tcl (stdin), la valeur de retour d'une invocation de open ou socket, ou le résultat d'une commande de création de canal fournie par une extension Tcl. Le canal doit avoir été ouvert en lecture.

Si canalId est en mode non bloquant, la commande peut ne pas lire autant de caractères que demandé : une fois que toute l'entrée disponible a été lue, la commande retournera les données disponibles plutôt que de bloquer pour plus d'entrée. Si le canal est configuré pour utiliser un encodage multi-octets, il peut y avoir des octets restants dans les tampons internes qui ne forment pas un caractère complet. Ces octets ne seront pas retournés tant qu'un caractère complet n'est pas disponible ou que la fin du fichier n'est pas atteinte. Le commutateur -nonewline est ignoré si la commande retourne avant d'atteindre la fin du fichier.

Read traduit les séquences de fin de ligne dans l'entrée en caractères de nouvelle ligne selon l'option -translation pour le canal. Voir l'entrée de manuel fconfigure pour une discussion sur les manières dont fconfigure modifiera l'entrée.

UTILISATION AVEC LES PORTS SÉRIE

Pour la plupart des applications, un canal connecté à un port série devrait être configuré pour être non bloquant : fconfigure canalId -blocking 0. Alors read se comporte largement comme décrit ci-dessus. Il faut faire attention lors de l'utilisation de read sur des ports série bloquants :

read canalId numCaractères
Dans cette forme, read bloque jusqu'à ce que numCaractères aient été reçus du port série.
read canalId
Dans cette forme, read bloque jusqu'à la réception du caractère de fin de fichier, voir fconfigure -eofchar. S'il n'y a pas de caractère de fin de fichier configuré pour le canal, alors read bloquera indéfiniment.

EXEMPLE

Cet exemple de code lit un fichier en une seule fois et le divise en une liste, chaque ligne du fichier correspondant à un élément de la liste :

set fl [open /proc/meminfo]
set data [read $fl]
close $fl
set lines [split $data \n]
