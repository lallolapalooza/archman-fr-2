READONLY(1P) Manuel du programmeur POSIX READONLY(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

readonly — définir l'attribut lecture seule pour les variables

SYNTAXE

readonly nom[=mot]...
readonly -p

DESCRIPTION

Les variables dont les noms sont spécifiés recevront l'attribut readonly. Les valeurs des variables ayant l'attribut readonly ne peuvent pas être modifiées par des affectations ultérieures, et ces variables ne peuvent pas être supprimées par l'utilitaire unset. Si le nom d'une variable est suivi de =mot, alors la valeur de cette variable sera définie sur mot.

L'utilitaire intégré spécial readonly prendra en charge le volume Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

Lorsque -p est spécifié, readonly écrit dans la sortie standard les noms et les valeurs de toutes les variables en lecture seule, selon le format suivant :

"readonly %s=%s\n", <nom>, <valeur>

si nom est défini, et

"readonly %s\n", <nom>

si nom est indéfini.

Le shell formatera la sortie, y compris l'utilisation correcte des guillemets, de manière à ce qu'elle soit appropriée pour être réinjectée dans le shell sous forme de commandes qui obtiennent les mêmes résultats de définition de valeur et d'attribut readonly dans un environnement d'exécution de shell où :

1.
Les variables ayant des valeurs au moment où elles ont été affichées n'auront pas l'attribut readonly défini.
2.
Les variables qui étaient indéfinies au moment où elles ont été affichées n'auront pas de valeur au moment où la sortie sauvegardée sera réinjectée dans le shell.

Lorsqu'aucun argument n'est fourni, les résultats ne sont pas spécifiés.

EXEMPLES

RATIONNEL

Certains shells historiques conservent l'attribut readonly entre des invocations séparées. Ce volume de POSIX.1‐2017 autorise ce comportement, mais ne l'exige pas.

L'option -p permet un accès portable aux valeurs qui peuvent être sauvegardées puis restaurées ultérieurement à l'aide, par exemple, d'un script point. Voir également le RATIONNEL de export pour une description des cas de sortie sans argument et avec l'option -p, ainsi qu'un exemple connexe.

Les fonctions en lecture seule ont été envisagées, mais elles ont été omises car elles ne correspondent pas à la pratique historique ou ne sont pas particulièrement utiles. De plus, les fonctions ne doivent pas être en lecture seule entre les invocations afin d'empêcher le « spoofing » (le « spoofing » est le terme désignant la pratique de création d'un programme qui se comporte comme un utilitaire bien connu dans le but de subvertir l'intention réelle de l'utilisateur) de scripts shell administratifs ou sensibles à la sécurité (ou conscients de la sécurité).
