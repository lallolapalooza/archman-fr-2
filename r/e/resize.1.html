RESIZE(1) Système X Window RESIZE(1)

NOM

resize - définit les variables d'environnement et les paramètres du terminal à la taille actuelle de la fenêtre xterm

SYNTAXE

resize [ -v | -u | -c ] [ -s [ ligne colonne ] ]

DESCRIPTION

Resize imprime une commande shell pour définir les variables d'environnement appropriées afin d'indiquer la taille actuelle de la fenêtre xterm depuis laquelle la commande est exécutée.

Resize détermine la commande par plusieurs étapes :

  • tout d'abord, il trouve le nom du programme shell de l'utilisateur. Il utilise la variable SHELL si elle est définie, sinon il utilise les données de l'utilisateur du fichier /etc/passwd.
  • ensuite, il décide s'il faut utiliser la syntaxe du shell Bourne ou la syntaxe du C-shell. Il utilise une table intégrée de shells connus, qui peut être outrepassée par les options -u et -c.
  • ensuite, resize demande au système d'exploitation les paramètres du terminal. C'est la même information qui peut être manipulée avec stty.
  • ensuite, resize demande au terminal sa taille en caractères. Selon que l'option « -s » est donnée ou non, resize utilise une séquence d'échappement différente pour demander cette information.
  • à ce stade, resize tente de mettre à jour les paramètres du terminal pour refléter la taille de la fenêtre du terminal en pixels :
  • si l'option -s est utilisée, resize demande alors au terminal sa taille en pixels.
  • sinon, resize demande au système d'exploitation les informations et les met à jour après s'être assuré que les dimensions de la fenêtre sont un multiple de la hauteur et de la largeur des caractères.
  • dans les deux cas, la mise à jour des paramètres du terminal est effectuée à l'aide d'un appel système différent de celui utilisé pour stty.
  • ensuite, resize met à jour les paramètres du terminal pour refléter les valeurs modifiées telles que sa taille en lignes ou en colonnes. Cela affecte les valeurs affichées par stty.
  • enfin, resize génère des commandes shell pour définir les variables d'environnement, et les écrit sur la sortie standard.

OPTIONS

Les options suivantes peuvent être utilisées avec resize :

-c
Cette option indique que des commandes C-shell doivent être générées, même si le shell actuel de l'utilisateur ne semble pas utiliser la syntaxe C-shell.
-s [lignes colonnes]
Cette option indique que les séquences d'échappement de la console Sun seront utilisées à la place des codes d'échappement xterm de style VT100. Si lignes et colonnes sont données, resize demandera à xterm de se redimensionner en utilisant ces valeurs.
Les deux séquences d'échappement utilisées pour cette option (la première pour obtenir la taille de la fenêtre et la seconde pour la modifier) sont soumises au paramètre de ressource allowWindowOps de xterm. Le gestionnaire de fenêtres peut également choisir de refuser la modification.
La séquence d'échappement de style VT100 utilisée pour déterminer la taille de l'écran fonctionne toujours pour les terminaux compatibles VT100. Les VT100 n'ont aucun moyen correspondant de modifier la taille de l'écran.
-u
Cette option indique que des commandes Bourne-shell doivent être générées, même si le shell actuel de l'utilisateur ne semble pas utiliser la syntaxe Bourne-shell.
-v
Cela provoque l'affichage par resize d'un numéro de version sur la sortie standard, puis sa sortie.

Notez que les séquences d'échappement de la console Sun sont reconnues par xterm de XFree86 et par dtterm. Le programme resize peut être installé sous le nom sunsize, ce qui le fait supposer l'option -s.

Les arguments lignes et colonnes doivent apparaître en dernier ; bien qu'ils soient normalement associés à l'option -s, ils sont analysés séparément.

ENVIRONNEMENT

SHELL
Sauf outrepassé par l'option -c, resize détermine le shell actuel de l'utilisateur en
  • vérifiant d'abord si $SHELL est défini, et en l'utilisant,
  • sinon, resize recherche dans le fichier de mots de passe (/etc/passwd).
En général, les variantes de Bourne-shell (y compris ksh) ne modifient pas $SHELL, il est donc possible que resize soit confus si l'on exécute resize à partir d'un Bourne shell lancé depuis un C-shell.
Après avoir déterminé le shell de l'utilisateur, resize compare le nom du shell à une table de noms de shells connus. S'il ne trouve pas le nom dans sa table, resize utilisera la syntaxe C-shell pour les commandes générées afin de définir les variables d'environnement.
TERM
La commande shell générée par resize définit ceci à « xterm » si ce n'est pas déjà fait.
TERMCAP
La commande shell générée par resize définit cette variable sur les systèmes utilisant termcap, par exemple lorsque resize est lié à la bibliothèque termcap plutôt qu'à une bibliothèque terminfo. Cette dernière ne fournit pas le texte complet d'une entrée termcap.
COLUMNS, LINES
La commande shell générée par resize définit ces variables sur les systèmes utilisant terminfo. De nombreuses applications (y compris la bibliothèque curses) utilisent ces variables lorsqu'elles sont définies pour outrepasser la taille de leur écran.

FICHIERS

/etc/termcap
pour l'entrée termcap de base à modifier.
~/.cshrc
alias utilisateur pour la commande.

EXEMPLES

Pour que la sortie de resize prenne effet, resize doit soit être évalué dans le cadre de la ligne de commande (généralement fait avec un alias ou une fonction shell), soit être redirigé vers un fichier qui peut ensuite être lu. Depuis le C-shell (généralement connu sous le nom de /bin/csh), l'alias suivant pourrait être défini dans le fichier .cshrc de l'utilisateur :


% alias rs 'set noglob; eval `resize`'

Après avoir redimensionné la fenêtre, l'utilisateur taperait :


% rs

Les utilisateurs de versions du Bourne shell (généralement connu sous le nom de /bin/sh) qui n'ont pas de fonctions de commande devront envoyer la sortie vers un fichier temporaire, puis la relire avec la commande « . » :


$ resize > /tmp/out
$ . /tmp/out
