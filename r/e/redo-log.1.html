REDO-LOG(1) Commandes utilisateur REDO-LOG(1)

NOM

redo-log - affiche les messages de journalisation des compilations précédentes

SYNTAXE

redo-log [options...] [cibles...]

DESCRIPTION

Lorsque redo s'exécute, il capture la sortie d'erreur standard (stderr) de l'activité de compilation pour chaque cible, et la sauvegarde pour une utilisation ultérieure. Lorsqu'une cible est recompilée, les nouveaux journaux remplacent les anciens journaux pour cette cible. redo-log imprime la sortie du journal pour n'importe quel ensemble de cibles.

OPTIONS

-r, --recursive
si les cibles demandées entraînent la compilation de dépendances, afficher récursivement les journaux de ces dépendances également. (Et si ces dépendances compilent d'autres dépendances, afficher également ces journaux, et ainsi de suite.)
-u, --unchanged
afficher les messages même pour les dépendances qui n'ont pas changé (n'ont pas eu besoin d'être recompilées). Pour ce faire, nous affichons les journaux de la *dernière* compilation de chaque dépendance affectée. Habituellement, cela est utilisé avec -r.
-f, --follow
si une compilation est en cours pour l'une des cibles demandées ou leurs dépendances, suivre les journaux (comme tail -f) jusqu'à la fin de la compilation.
--no-details
afficher *uniquement* les messages de redo lui-même, pas les autres messages produits par les scripts de compilation. Généralement, cela vous donne une liste des cibles qui ont été compilées, mais pas les journaux détaillés, les avertissements ou les erreurs.
--no-status
ne pas afficher la ligne d'état de la compilation en cours en bas de l'écran. (Sauf si cette option est spécifiée, la ligne d'état sera activée si vous utilisez --follow, si stderr est un terminal.) Si stderr n'est *pas* un terminal, vous pouvez forcer l'activation de la ligne d'état en utilisant --status.
--no-pretty
afficher les lignes de journal redo "brutes" (événements @@REDO) plutôt que d'utiliser un format lisible par l'homme. La valeur par défaut est --pretty.
--no-color
lorsque vous utilisez --pretty et que vous écrivez dans un terminal, coloriser la sortie pour que les résultats ressortent plus clairement. Si vous n'écrivez pas dans un terminal, vous pouvez utiliser --color pour forcer une sortie colorisée.
--debug-locks
afficher les messages concernant l'acquisition, la libération et l'attente des verrous. Comme redo peut être hautement parallélisé, une instance peut finir par attendre qu'une cible soit compilée par une autre instance avant de pouvoir continuer. Si vous suspectez que cela cause des problèmes, utilisez cette option pour voir quelle instance attend et quand.
--debug-pids
ajouter l'identifiant de processus de l'instance redo particulière à chaque message de sortie. Cela permet de déterminer plus facilement quelle sous-instance de redo fait quoi.
