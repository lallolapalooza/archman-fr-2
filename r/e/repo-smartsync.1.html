repo-smartsync(1)

Paquet: repo

Licences: Apache-2.0

REPO(1) Manuel de repo REPO(1)

NOM

repo - repo smartsync - page de manuel pour repo smartsync

SYNTAXE

repo smartsync [<projet>...]

DESCRIPTION

Résumé

Met à jour l'arbre de travail vers la dernière révision stable connue

OPTIONS

-h, --help
affiche ce message d'aide et quitte
-j JOBS, --jobs=JOBS
nombre de jobs à exécuter en parallèle (défaut : basé sur le nombre de cœurs CPU)
--jobs-network=JOBS
nombre de jobs réseau à exécuter en parallèle (défaut : --jobs ou 1). Ignoré si --interleaved est défini
--jobs-checkout=JOBS
nombre de jobs de checkout locaux à exécuter en parallèle (défaut : --jobs ou 8). Ignoré si --interleaved est défini
-f, --force-broken
option obsolète (sera supprimée à l'avenir)
--fail-fast
arrête la synchronisation après la première erreur rencontrée
--force-sync
remplace un répertoire git existant s'il doit pointer vers un autre répertoire d'objets. ATTENTION : cela peut entraîner une perte de données
--force-checkout
force le checkout même s'il entraîne le rejet des modifications non validées. ATTENTION : cela peut entraîner une perte de données
--force-remove-dirty
supprime de force les projets avec des modifications non validées s'ils n'existent plus dans le manifeste. ATTENTION : cela peut entraîner une perte de données
--rebase
rebase les commits locaux indépendamment de s'ils sont publiés
-l, --local-only
met à jour uniquement l'arbre de travail, sans récupération (fetch)
--no-manifest-update, --nmu
utilise le checkout du manifeste existant tel quel. (ne met pas à jour vers la dernière révision)
--interleaved
récupère et checkout les projets en parallèle (expérimental)
-n, --network-only
récupère uniquement, ne met pas à jour l'arbre de travail
-d, --detach
détache les projets vers la révision du manifeste
-c, --current-branch
récupère uniquement la branche actuelle du serveur
--no-current-branch
récupère toutes les branches du serveur
-m NOM.xml, --manifest-name=NOM.xml
manifeste temporaire à utiliser pour cette synchronisation
--clone-bundle
active l'utilisation de /clone.bundle sur HTTP/HTTPS
--no-clone-bundle
désactive l'utilisation de /clone.bundle sur HTTP/HTTPS
-u NOM_SERVEUR_MANIFESTE, --manifest-server-username=NOM_SERVEUR_MANIFESTE
nom d'utilisateur pour s'authentifier auprès du serveur de manifeste
-p MOT_DE_PASSE_SERVEUR_MANIFESTE, --manifest-server-password=MOT_DE_PASSE_SERVEUR_MANIFESTE
mot de passe pour s'authentifier auprès du serveur de manifeste
--fetch-submodules
récupère les sous-modules du serveur
--use-superproject
utilise le superprojet du manifeste pour synchroniser les projets ; implique -c
--no-use-superproject
désactive l'utilisation des superprojets de manifeste
--tags
récupère les tags
--no-tags
ne récupère pas les tags (défaut)
--optimized-fetch
ne récupère les projets fixés à sha1 que si la révision n'existe pas localement
--retry-fetches=RETRIES_FETCHES
nombre de tentatives pour récupérer en cas d'erreurs transitoires
--prune
supprime les refs qui n'existent plus sur le distant (défaut)
--no-prune
ne supprime pas les refs qui n'existent plus sur le distant
--auto-gc
exécute le garbage collection sur tous les projets synchronisés
--no-auto-gc
n'exécute pas le garbage collection sur aucun projet (défaut)

Options de journalisation :

-v, --verbose
affiche toutes les sorties
-q, --quiet
affiche uniquement les erreurs

Options multi-manifeste :

--outer-manifest
opère en commençant par le manifeste le plus externe
--no-outer-manifest
n'opère pas sur les manifestes externes
--this-manifest-only
opère uniquement sur ce manifeste (sous-manifeste)
--no-this-manifest-only, --all-manifests
opère sur ce manifeste et ses sous-manifestes

Options de version de repo :

--no-repo-verify
ne vérifie pas le code source de repo

Exécutez `repo help smartsync` pour voir le manuel détaillé.

DÉTAILS

La commande 'repo smartsync' est un raccourci pour sync -s.

juin 2025 repo smartsync
