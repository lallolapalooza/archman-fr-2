RECOLL.CONF(5) Manuel des formats de fichier RECOLL.CONF(5)

NOM

recoll.conf - fichier de configuration personnel principal pour Recoll

DESCRIPTION

Ce fichier définit la configuration de l'index pour le système de recherche plein texte Recoll.

Le fichier de configuration au niveau système est normalement situé dans /usr/[local]/share/recoll/examples. Tout paramètre défini dans le fichier commun peut être remplacé en le définissant dans le fichier de configuration d'index spécifique, par défaut : $HOME/.recoll/recoll.conf

Toutes les commandes recoll accepteront une option -c ou utiliseront la variable d'environnement $RECOLL_CONFDIR pour spécifier un répertoire de configuration d'index non par défaut.

Un court extrait du fichier pourrait ressembler à ceci :

# Liste d'espaces séparés des répertoires à indexer.
topdirs =  ~/docs /usr/share/doc
[~/some-directory-with-utf8-txt-files]
defaultcharset = utf-8

Il existe trois types de lignes :

  • Commentaire ou ligne vide.
  • Affectation de paramètre.
  • Définition de section.

Les lignes vides ou les lignes commençant par # sont ignorées.

Les lignes d'affectation sont de la forme 'nom = valeur'. Dans la description suivante, elles ont également un type, qui est principalement indicatif. Les deux moins évidents sont 'fn' : chemin de fichier, et 'dfn' : chemin de répertoire.

Les lignes de section permettent de redéfinir un paramètre pour un sous-arbre de répertoire. Certains des paramètres utilisés pour l'indexation sont recherchés hiérarchiquement du plus spécifique au moins spécifique. Tous les paramètres ne peuvent pas être redéfinis de manière significative, cela est spécifié pour chacun dans la section suivante.

Le caractère tilde (~) est développé dans les noms de fichiers pour représenter le répertoire personnel de l'utilisateur.

Certaines valeurs de type 'chaîne' sont des listes, ce qui est seulement indiqué par leur description. Dans ce cas, les espaces blancs sont utilisés pour la séparation, et les éléments avec des espaces intégrés peuvent être cités avec des guillemets doubles.

OPTIONS

topdirs = chaîne
Liste d'espaces séparés de fichiers ou de répertoires à indexer récursivement. Vous pouvez utiliser des liens symboliques dans la liste, ils seront suivis, indépendamment de la valeur de la variable followLinks. La valeur par défaut est ~ : indexe récursivement $HOME.
monitordirs = chaîne
Liste d'espaces séparés de fichiers ou de répertoires à surveiller pour les mises à jour. Lors de l'exécution de l'indexeur en temps réel, cela permet de surveiller seulement un sous-ensemble de la zone entière indexée. Les éléments doivent être inclus dans l'arbre défini par les membres de 'topdirs'.
skippedNames = chaîne
Noms de fichiers et de répertoires qui doivent être ignorés. Liste d'espaces séparés de motifs génériques (simples, pas des chemins, ne doivent pas contenir de

Consultez la configuration par défaut pour la valeur initiale, certaines entrées peuvent ne pas convenir à votre situation. Le moyen le plus simple de la voir est via le panneau "paramètres locaux" de la configuration de l'index de l'interface graphique.

La liste dans la configuration par défaut n'exclut pas les répertoires cachés (noms commençant par un point), ce qui signifie qu'elle peut indexer pas mal de choses que vous ne voulez pas. D'un autre côté, les agents de messagerie comme Thunderbird stockent généralement les messages dans des répertoires cachés, et vous voulez probablement que cela soit indexé. Une solution possible est d'avoir ".*" dans "skippedNames", et d'ajouter des éléments comme "~/.thunderbird" "~/.evolution" à "topdirs".

Même les noms de fichiers ne sont pas indexés pour les motifs de cette liste, voir la variable "noContentSuffixes" pour une approche alternative qui indexe les noms de fichiers. Peut être redéfini pour tout sous-répertoire.

skippedNames- = chaîne
Liste de motifs de noms à supprimer de la liste par défaut de skippedNames. Permet de modifier la liste dans la configuration locale sans la copier.
skippedNames+ = chaîne
Liste de motifs de noms à ajouter à la liste par défaut de skippedNames. Permet de modifier la liste dans la configuration locale sans la copier.
onlyNames = chaîne
Motifs de filtre de noms de fichiers réguliers. Ceci est normalement vide. S'il est défini, seuls les noms de fichiers ne figurant pas dans skippedNames et correspondant à l'un des motifs seront considérés pour l'indexation. Peut être redéfini par sous-répertoire. Ne s'applique pas aux répertoires.
noContentSuffixes = chaîne
Liste des fins de noms (pas nécessairement des suffixes séparés par des points) pour lesquelles nous n'essayons pas d'identifier le type MIME, et nous ne décompressons ni n'indexons le contenu. Seuls les noms seront indexés. Ceci complète la liste maintenant obsolète recoll_noindex du fichier mimemap, qui disparaîtra dans une future version (le passage de mimemap à recoll.conf permet de modifier la liste via l'interface graphique). Ceci est différent de skippedNames car il s'agit uniquement de correspondances de fins de noms (pas de motifs génériques), et le nom du fichier lui-même est indexé normalement. Ceci peut être redéfini pour les sous-répertoires.
noContentSuffixes- = chaîne
Liste des fins de noms à supprimer de la liste par défaut de noContentSuffixes.
noContentSuffixes+ = chaîne
Liste des fins de noms à ajouter à la liste par défaut de noContentSuffixes.
skippedPaths = chaîne
Chemins absolus que nous ne devrions pas parcourir. Liste d'espaces de expressions génériques pour les chemins absolus du système de fichiers (pour les fichiers ou les répertoires). La variable doit être définie au niveau supérieur du fichier de configuration, pas dans une sous-section.

Toute valeur dans la liste doit être textuellement cohérente avec les valeurs dans topdirs, aucune tentative n'est faite pour résoudre les liens symboliques. En pratique, si, comme c'est fréquemment le cas, /home est un lien vers /usr/home, vos topdirs par défaut auront une seule entrée "~" qui sera traduite en "/home/votrenomlogin". Dans ce cas, toute entrée skippedPaths devrait commencer par "/home/votrenomlogin" *pas* par "/usr/home/votrenomlogin".

Les répertoires d'index et de configuration seront automatiquement ajoutés à la liste.

Les expressions sont mises en correspondance en utilisant "fnmatch(3)" avec le drapeau FNM_PATHNAME défini par défaut. Cela signifie que les caractères "/" doivent être mis en correspondance explicitement. Vous pouvez définir "skippedPathsFnmPathname" à 0 pour désactiver l'utilisation de FNM_PATHNAME (ce qui signifie que "/*/dir3" correspondra à "/dir1/dir2/dir3").

La valeur par défaut contient le point de montage habituel pour les médias amovibles pour vous rappeler que c'est dans la plupart des cas une mauvaise idée d'avoir Recoll travaillant sur ceux-ci. L'ajout explicite de "/media/xxx" à la variable "topdirs" annulera cela.

skippedPathsFnmPathname = bool
Défini à 0 pour ignorer l'utilisation de FNM_PATHNAME pour la mise en correspondance des chemins ignorés.
nowalkfn = chaîne
Nom de fichier qui provoquera l'ignorance de son répertoire parent. Tout répertoire contenant un fichier avec ce nom sera ignoré comme s'il faisait partie de la liste skippedPaths. Ex: .recoll-noindex
daemSkippedPaths = chaîne
Équivalent de skippedPaths spécifique à l'indexation en temps réel. Cela permet d'avoir des parties de l'arbre qui sont initialement indexées mais non surveillées. Si daemSkippedPaths n'est pas défini, le démon utilise skippedPaths.
followLinks = bool
Suivre les liens symboliques pendant l'indexation. Par défaut, les liens symboliques sont ignorés pour éviter l'indexation multiple de fichiers liés. Aucun effort n'est fait pour éviter les doublons lorsque cette option est définie à vrai. Cette option peut être définie individuellement pour chacun des membres de "topdirs" en utilisant des sections. Elle ne peut pas être modifiée en dessous du niveau "topdirs". Les liens dans la liste "topdirs" elle-même sont toujours suivis.
indexedmimetypes = chaîne
Liste restrictive des types MIME indexés. Normalement non définie (auquel cas tous les types pris en charge

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Les types sont indexés). S'il est défini, seuls les types de la liste auront leur contenu indexé. Les noms seront indexés de toute façon si indexallfilenames est défini (par défaut). Les noms de types MIME doivent être tirés du fichier mimemap (les valeurs peuvent différer de la sortie xdg-mime ou file -i dans certains cas). Peut être redéfini pour les sous-arborescences.
excludedmimetypes = chaîne
Liste des types MIME exclus. Permet d'exclure certains types de l'indexation. Les noms de types MIME doivent être tirés du fichier mimemap (les valeurs peuvent être différentes des sorties xdg-mime ou file -i dans certains cas). Peut être redéfini pour les sous-arborescences.
nomd5types = chaîne
Types MIME pour lesquels nous ne calculons pas de hachage md5. Les sommes de contrôle md5 sont utilisées uniquement pour dédupliquer les résultats, et peuvent être très coûteuses à calculer sur des fichiers multimédias ou d'autres gros fichiers. Cette liste permet de désactiver le calcul md5 pour les types sélectionnés. Elle est globale (pas de redéfinition pour les sous-arborescences). Actuellement, elle n'a d'effet que pour les gestionnaires externes (exec et execm). Les types de fichiers peuvent être spécifiés en listant soit des types MIME (par exemple, audio/mpeg) soit des noms de gestionnaires (par exemple, rclaudio.py).
compressedfilemaxkbs = entier
Limite de taille pour les fichiers compressés. Nous devons les décompresser dans un répertoire temporaire pour identification, ce qui peut être coûteux dans certains cas. Limitez le gaspillage. Une valeur négative signifie aucune limite. 0 ne traite aucun fichier compressé. Par défaut : 100 Mo.
textfilemaxmbs = entier
Limite de taille pour les fichiers texte. Principalement pour ignorer les journaux énormes. Également utilisé pour la taille maximale du corps des messages de courrier électronique. Par défaut : 20 Mo. Utilisez une valeur de -1 pour désactiver.
textfilepagekbs = entier
Taille de page pour les fichiers texte. Si cette option est définie, les fichiers text/plain seront divisés en documents d'environ cette taille. Cela réduira l'utilisation de la mémoire lors de l'indexation et aidera au chargement des données dans la fenêtre de prévisualisation lors de la recherche. Particulièrement utile avec de très gros fichiers, tels que les journaux d'application ou système. Voir également textfilemaxmbs et compressedfilemaxkbs.
textunknownasplain = booléen
Traiter les fichiers text/xxx inconnus comme text/plain Permet d'indexer divers fichiers texte identifiés comme text/quelquechose par "file" ou "xdg-mime" sans avoir à définir explicitement des entrées de configuration pour eux. Cela fonctionne bien pour l'indexation (cela entraînera également le traitement de nombreux fichiers inutiles), mais les documents indexés de cette manière seront ouverts par le visualiseur de bureau, même si text/plain possède un éditeur spécifique.
indexallfilenames = booléen
Indexer les noms de fichiers des fichiers non traités. Indexer les noms des fichiers dont le contenu n'est pas indexé en raison d'un type MIME exclu ou non pris en charge.
usesystemfilecommand = booléen
Utiliser un mécanisme système en dernier recours pour deviner un type MIME. Selon la plateforme et la version, une configuration à la compilation décidera s'il exécute réellement une commande ou utilise libmagic. Cette identification de dernier recours (si celle basée sur l'extension a échoué) est généralement utile, mais entraînera l'indexation de nombreux fichiers "texte" sans extension et erronés. Voir également "systemfilecommand".
systemfilecommand = chaîne
Commande à utiliser pour deviner le type MIME si les méthodes internes échouent. Ceci est ignoré sous Windows ou avec Recoll 1.38+ s'il est compilé avec libmagic activé (par défaut). Sinon, cela devrait être un équivalent de "file -i". Le chemin du fichier sera ajouté en dernier paramètre à la ligne de commande. "xdg-mime" fonctionne mieux que la commande traditionnelle "file", et est maintenant configuré par défaut (avec un mécanisme de repli intégré pour "file").
processwebqueue = booléen
Détermine si nous traitons la file d'attente Web. La file d'attente est un répertoire où les plugins du navigateur Web de Recoll créent des copies des pages visitées.
membermaxkbs = entier
Limite de taille pour les membres d'archive. Ceci est passé aux gestionnaires MIME dans l'environnement sous le nom RECOLL_FILTER_MAXMEMBERKB.
indexStripChars = booléen
Détermine si nous stockons la casse des caractères et les diacritiques dans l'index. Si nous le faisons, les recherches sensibles à la casse et aux diacritiques peuvent être effectuées, mais l'index sera plus volumineux, et certaines bizarreries marginales peuvent parfois survenir. Le comportement par défaut est un index dépouillé. Lors de l'utilisation de plusieurs index pour une recherche, ce paramètre doit être défini de manière identique pour tous. La modification de la valeur implique une réinitialisation de l'index.
indexStoreDocText = booléen
Détermine si nous stockons le contenu textuel des documents dans l'index. Le stockage du texte permet d'en extraire des extraits au moment de la recherche, au lieu de les construire à partir des données de position dans l'index.

Les formats d'index Xapian plus récents ont rendu notre utilisation de la liste de positions inacceptablement lente dans certains cas. Le dernier format d'index Xapian avec des performances correctes pour l'ancienne méthode est Chert, qui est par défaut pour la version 1.2, toujours pris en charge mais pas par défaut dans la version 1.4 et sera supprimé dans la version 1.6.

Le texte du document stocké est traduit de son format d'origine vers du texte brut UTF-8, mais n'est pas dépouillé des majuscules, des diacritiques ou des signes de ponctuation. Son stockage augmente la taille de l'index de 10 à 20 % en général, mais permet également des extraits plus agréables, il peut donc être utile de l'activer même s'il n'est pas strictement nécessaire pour les performances si vous pouvez vous permettre l'espace.

La variable n'a d'effet que lors de la création d'un index, c'est-à-dire que le répertoire xapiandb ne doit pas encore exister. Son effet exact dépend de la version de Xapian.

Pour Xapian 1.4, si la variable est définie sur 0, nous utilisions le format Chert et ne stockions pas le texte. Si la variable était 1, Glass était utilisé, et le texte stocké. Nous ne faisons plus cela : le stockage du texte s'est avéré être la meilleure option, et la suppression de cette possibilité simplifie le code.

Ainsi, le format d'index pour un nouvel index est toujours celui par défaut, mais la variable contrôle toujours si le texte est stocké ou non, et la méthode de génération de résumé. Avec Xapian 1.4 et supérieur, et la variable définie sur 0, la génération de résumé peut être très lente, mais ce réglage peut toujours être utile pour économiser de l'espace si vous n'utilisez pas du tout la génération de résumé, en utilisant le réglage approprié dans l'interface graphique, et/ou en évitant l'API Python ou les options recollq qui le déclencheraient.

nonumbers = booléen
Détermine si des termes seront générés pour les nombres. Par exemple, "123", "1.5e6", 192.168.1.4, ne seraient pas indexés si nonumbers est défini ("value123" le serait toujours). Les nombres sont souvent très intéressants à rechercher, et cela ne devrait probablement pas être défini, sauf dans des situations spéciales, c'est-à-dire pour des documents scientifiques contenant d'énormes quantités de nombres, où la définition de nonumbers réduira la taille de l'index. Ceci ne peut être défini que pour un index entier, pas pour une sous-arborescence.
notermpositions = booléen
Ne pas stocker les positions des termes. Les positions des termes permettent les recherches de phrases et de proximité, mais rendent l'index beaucoup plus volumineux. Dans certaines circonstances spéciales, vous pourriez vouloir vous en passer.
dehyphenate = booléen
Détermine si nous indexons "coworker" également lorsque l'entrée est "co-worker". Ceci est nouveau dans la version 1.22, et activé par défaut. Définir la variable sur off permet de restaurer le comportement précédent.
indexedpunctuation = chaîne
Chaîne de caractères de ponctuation UTF-8 à indexer comme mots. Les termes résultants seront alors recherchables et, par exemple, en définissant le paramètre sur "%€" (sans les guillemets), vous pourriez rechercher séparément "100%" ou "100€". Notez que "100%" ou "100 %" seraient indexés de la même manière, les caractères étant leurs propres séparateurs de mots.
backslashasletter = booléen
Traiter le backslash comme une lettre normale. Cela peut être utile pour les personnes souhaitant indexer des commandes TeX telles quelles, mais n'a pas beaucoup d'utilité générale.
underscoreasletter = booléen
Traiter le tiret bas comme une lettre normale. Cela est utile dans de nombreux cas, au point qu'on se demande s'il ne devrait pas être la valeur par défaut.
maxtermlength = entier
Longueur maximale d'un terme en caractères Unicode. Les mots plus longs que cela seront rejetés. La valeur par défaut est 40 et était auparavant codée en dur, mais elle peut désormais être ajustée. Vous pourriez avoir besoin d'une réinitialisation de l'index si vous modifiez la valeur.
maxdbdatarecordkbs = entier
Taille binaire maximale d'un enregistrement de données de document Xapian. L'enregistrement de données contient les métadonnées de document "stockées". Une taille très importante indique généralement une erreur d'analyse du document. Xapian a une limite stricte d'environ 100 Mo pour cela.
maxdbstoredtextmbs = entier
Taille binaire maximale du texte stocké d'un document. Xapian a une limite stricte d'environ 100 Mo pour la valeur compressée, mais notre limite est avant compression, il peut donc y avoir une certaine marge.
nocjk = booléen
Détermine si la segmentation spécifique des caractères/mots d'Asie de l'Est (chinois, coréen, japonais) est désactivée. Cela économisera une petite quantité de CPU si vous n'avez pas de documents CJK. Si votre base de documents contient un tel texte mais que vous n'êtes pas intéressé par sa recherche, la définition de nocjk peut permettre d'économiser un temps et un espace considérables.
cjkngramlen = entier
Cela vous permet d'ajuster la taille des n-grammes utilisés pour indexer le texte CJK. La valeur par défaut de 2 est probablement appropriée dans
dans la plupart des cas. Une valeur de 3 permettrait plus de précision et d'efficacité sur les mots longs, mais l'index sera approximativement deux fois plus grand.
hangultagger = chaîne
Analyseur externe pour le coréen Hangul. Ceci permet d'utiliser un processeur spécifique à la langue pour extraire des termes du texte coréen, au lieu du générateur de termes n-grammes générique. Voir https://www.recoll.org/pages/recoll-korean.html pour les instructions.
chinesetagger = chaîne
Analyseur externe pour le chinois. Ceci permet d'utiliser l'analyseur Jieba spécifique à la langue pour extraire des termes significatifs du texte chinois, au lieu du générateur de termes n-grammes générique. Voir https://www.recoll.org/pages/recoll-chinese.html pour les instructions.
indexstemminglanguages = chaîne
Langues pour lesquelles créer des données d'expansion de stemmisation. Les noms des stemmers peuvent être trouvés en exécutant « recollindex -l », ou ceci peut également être défini à partir d'une liste dans l'interface graphique. Les valeurs sont des noms de langue complets, par exemple, english, french...
defaultcharset = chaîne
Jeu de caractères par défaut. Ceci est utilisé pour les fichiers qui ne contiennent pas de définition de jeu de caractères (par exemple : text/plain). Les valeurs trouvées à l'intérieur des fichiers, par exemple une balise « charset » dans les documents HTML, le remplaceront. S'il n'est pas défini, le jeu de caractères par défaut est celui défini par l'environnement NLS ($LC_ALL, $LC_CTYPE, $LANG), ou à défaut iso-8859-1 (en fait cp-1252). Si pour une raison quelconque vous souhaitez un défaut général qui ne correspond pas à votre LANG et n'est pas 8859-1, utilisez cette variable. Ceci peut être redéfini pour tout sous-répertoire.
unac_except_trans = chaîne
Une liste de caractères, encodés en UTF-8, qui doivent être traités spécialement lors de la conversion du texte en minuscules sans accent. Par exemple, en suédois, la lettre a avec tréma a une pleine citoyenneté alphabétique et ne devrait pas être transformée en a. Chaque élément de la liste séparée par des espaces a le caractère spécial comme premier élément et la traduction qui suit. Le traitement des versions minuscules et majuscules d'un caractère doit être spécifié, car l'appartenance à la liste désactivera le traitement standard des accents et des majuscules. La valeur est globale et affecte à la fois l'indexation et la requête. Nous convertissons également quelques caractères Unicode confus (guillemets, traits d'union) en leur équivalent ASCII pour éviter des échecs de recherche « invisibles ».

Exemples : Suédois : unac_except_trans = ää Ää öö Öö üü Üü ßss œoe Œoe æae Æae ﬀff ﬁfi ﬂfl åå Åå ’' ❜' ʼ' ‐- unac_except_trans = ää Ää öö Öö üü Üü ßss œoe Œoe æae Æae ﬀff ﬁfi ﬂfl ’' ❜' ʼ' ‐- un accent allemand ß unac_except_trans = ßss œoe Œoe æae Æae ﬀff ﬁfi ﬂfl ’' ❜' ʼ' ‐- ne sont pas effectués par unac, mais il est peu probable que quelqu'un tape les formes composées dans une recherche. unac_except_trans = ßss œoe Œoe æae Æae ﬀff ﬁfi ﬂfl ’' ❜' ʼ' ‐-

maildefcharset = chaîne
Remplace le jeu de caractères par défaut pour les messages électroniques qui n'en spécifient pas. Ceci est principalement utile pour les dumps de readpst (libpst), qui sont en utf-8 mais ne le disent pas.
localfields = chaîne
Définit des champs sur tous les fichiers (généralement d'une zone fs spécifique). La syntaxe est la suivante : nom = valeur ; attr1 = val1 ; [...] la valeur est vide, donc cela nécessite un point-virgule initial. Ceci est utile, par exemple, pour définir le champ rclaptg pour la sélection d'applications dans mimeview.
testmodifusemtime = booléen
Utilise mtime au lieu de ctime pour tester si un fichier a été modifié. Le temps est utilisé en plus de la taille, qui est toujours utilisée. Définir ceci peut réduire la réindexation sur les systèmes où les attributs étendus sont utilisés (par une autre application), mais pas indexés, car la modification des attributs étendus n'affecte que ctime. Notes : - Ceci peut empêcher la détection de modifications dans certains cas limites de renommage de fichiers (la cible devrait avoir la même taille et mtime). - Vous devriez probablement aussi définir noxattrfields à 1 dans ce cas, sauf si vous préférez toujours effectuer l'indexation des xattr, par exemple si le modèle de mise à jour de fichier local le rend utile (car en général, il y a un risque que les mises à jour d'attributs étendus pures sans modification de fichier passent inaperçues). Effectuez une réinitialisation complète de l'index après avoir modifié ceci.
noxattrfields = booléen
Désactive la conversion des attributs étendus en champs de métadonnées. Ceci doit probablement être défini si testmodifusemtime est défini.
metadatacmds = chaîne
Définit les commandes pour collecter des métadonnées externes, par exemple les tags tmsu. Il peut y avoir plusieurs entrées, séparées par des points-virgules, chacune définissant dans quel nom de champ les données vont et la commande à utiliser. N'oubliez pas le point-virgule initial. Tous les noms de champs doivent être différents. Vous pouvez utiliser des alias dans le fichier « field » si nécessaire. Comme astuce pas très jolie concédée par souci de commodité, tout nom de champ commençant par « rclmulti » sera interprété comme une indication que la commande renvoie plusieurs valeurs de champ dans un blob de texte formaté comme un fichier de configuration recoll (« nom_de_champ = valeur_de_champ » lignes). Le nom rclmultixx sera ignoré, et les noms de champs et valeurs seront analysés à partir des données. Exemple : metadatacmds = ; tags = tmsu tags %f; rclmulti1 = cmdOutputsConf %f
cachedir = dfn
Répertoire principal pour les données Recoll. Les répertoires de données Recoll sont normalement situés par rapport au répertoire de configuration (par exemple, ~/.recoll/xapiandb, ~/.recoll/mboxcache). Si « cachedir » est défini, les répertoires sont stockés sous la valeur spécifiée à la place (par exemple, si cachedir est ~/.cache/recoll, dbdir serait par défaut ~/.cache/recoll/xapiandb). Ceci affecte dbdir, webcachedir, mboxcachedir, aspellDicDir, qui peuvent toujours être spécifiés individuellement pour remplacer cachedir. Notez que si vous avez plusieurs configurations, chacune doit avoir un cachedir différent, il n'y a pas de calcul automatique d'un sous-chemin sous cachedir.
maxfsoccuppc = int
Occupation maximale du système de fichiers au-delà de laquelle nous arrêtons l'indexation. La valeur est un pourcentage, correspondant à ce que la colonne « Capacity » de la sortie df montre. idxflushmb = int
Seuil (en mégaoctets de nouvelles données) auquel nous vidons l'index de la mémoire vers le disque. La définition de cette option permet de contrôler l'utilisation de la mémoire par le processus d'indexation. Une valeur de 0 signifie pas de vidage explicite, ce qui laisse Xapian gérer lui-même, c'est-à-dire qu'il vide tous les $XAPIAN_FLUSH_THRESHOLD documents créés, modifiés ou supprimés : comme l'utilisation de la mémoire dépend de la taille moyenne des documents, et pas seulement du nombre de documents, l'approche Xapian n'est pas très utile, et vous devriez laisser Recoll gérer les vidages. La valeur compilée est 0. La valeur par défaut configurée (dans ce fichier) est maintenant de 50 Mo, et devrait convenir dans de nombreux cas. Vous pouvez la régler aussi bas que 10 pour économiser de la mémoire, mais si vous recherchez une vitesse maximale, vous pourriez vouloir expérimenter avec des valeurs comprises entre 20 et 200. D'après mon expérience, les valeurs au-delà de celles-ci sont toujours contre-productives. Si vous trouvez le contraire, merci de me laisser un message.

Espace mémoire virtuelle maximum pour les processus de filtre (setrlimit(RLIMIT_AS)), en mégaoctets. Notez que cela inclut toutes les bibliothèques mappées (il n'y a pas de moyen fiable sous Linux pour limiter uniquement l'espace de données), nous devons donc être un peu généreux ici. Toute valeur supérieure à 2000 sera ignorée sur les machines 32 bits. La valeur par défaut élevée est nécessaire en raison des gestionnaires basés sur Java (pdftk) qui nécessitent beaucoup de VM (dont la majeure partie est du texte), en particulier pdftk lorsqu'il est exécuté à partir de Python rclpdf.py. Vous pouvez utiliser une valeur beaucoup plus faible si vous n'avez pas besoin de Java.
thrQSizes = string
Profondités des files d'attente de tâches pour chaque étape et contrôle de la configuration du threading. Il existe trois files d'attente internes dans les étapes du pipeline d'indexation (extraction des données du fichier, génération des termes, mise à jour de l'index). Ce paramètre définit les profondeurs de file d'attente pour chaque étape (trois valeurs entières). En pratique, des files d'attente profondes n'ont pas montré d'augmentation des performances. La première valeur est également utilisée pour contrôler la configuration automatique du threading ou la désactivation du multithreading. Si la profondeur de la première file d'attente est définie sur 0, Recoll configurera les profondeurs de file d'attente et le nombre de threads en fonction du nombre de CPU détectés. Les valeurs choisies arbitrairement sont les suivantes (profondeur, nombre de threads). 1 CPU -> pas de threading. Moins de 4 CPU : (2, 2) (2, 2) (2, 1). Moins de 6 : (2, 4), (2, 2), (2, 1). Sinon (2, 5), (2, 3), (2, 1). Si la profondeur de la première file d'attente est définie sur -1, le multithreading sera entièrement désactivé. Les deuxième et troisième valeurs sont ignorées dans ces deux cas.
thrTCounts = string
Nombre de threads utilisés pour chaque étape d'indexation. Si la première entrée de thrQSizes n'est pas 0 ou -1, ces trois valeurs définissent le nombre de threads utilisés pour chaque étape (extraction des données du fichier, génération de termes, mise à jour de l'index). Il n'est pas logique d'utiliser une valeur autre que 1 pour la dernière étape car la mise à jour de l'index Xapian est nécessairement mono-thread (et protégée par un mutex).
thrTmpDbCnt = int
Nombre d'index temporaires utilisés lors de l'indexation incrémentielle ou complète. S'il n'est pas défini sur zéro, cela définit le nombre d'index temporaires que nous utilisons pendant l'indexation. Ces index temporaires sont fusionnés dans l'index principal à la fin de l'opération. L'utilisation de plusieurs index et d'une fusion finale peut améliorer considérablement les performances d'indexation lorsque les mises à jour mono-thread de l'index Xapian deviennent un goulot d'étranglement. L'utilité dépend du type d'entrée et du CPU. Voir le manuel pour plus de détails.

Suspendre l'indexation en temps réel lorsque le système fonctionne sur batterie. L'indexeur attendra un retour sur secteur et se réexécutera lorsque cela se produira.

NAME

recoll.conf

– recoll indexing configuration file

DESCRIPTION

The user manual for recoll can be found at https://www.recoll.org/manual. This manual page only describes the configuration variables.

Configuration variables can be set in the user's ~/.config/recoll/recoll.conf file, or in the system-wide /etc/recoll/recoll.conf. If the variable is defined in both, the user's value takes precedence. Variables can be defined multiple times. In that case, the last definition counts.

Variables can also be set from the command line, using the -c option for recollindex. This is mostly useful for testing.

Some variables can be defined in subdirectories. For example, if you set shellexec for the ~/Documents/Work directory, it will only apply to files within that directory and its subdirectories.

The variables are:

OPTIONS

fields = string
This is a comma-separated list of metadata field names. These fields will be extracted and stored by recoll. Some common fields are author, title, subject, comments, keywords, abstract. The list of all possible fields can be found in the documentation, or by using the recoll -m command. The default value is empty. Adding fields here allows you to search within these metadata fields later using the md: query syntax.
fieldsconf = string
Space-separated list of external commands to process selected metadata fields. The command must be executable. It will be called with the qualified field name and the field value as arguments. The command should print the new value to standard output. It can also print nothing to erase the field value. This can be used to clean up or transform metadata before it is stored. For example, to remove all HTML tags from the abstract field: fieldsconf = abstract:html2text. You need to have the external command (e.g., html2text) installed and in your PATH.
fieldsconfpath = string
Path for external commands used in fieldsconf. If not set, the commands will be searched in the user's PATH. This can be useful if the external commands are not in the standard PATH.
fieldsconfdconf = string
Directory containing external commands for fieldsconf. This is an alternative to fieldsconfpath. The commands in this directory will be added to the search path.
pdftextExtractionMethod = string
Specify the PDF text extraction method. Possible values are:
  • pdfminer (default): Uses the pdfminer.six Python library. Requires installation: pip install pdfminer.six.
  • pdftotext: Uses the pdftotext external command (from the poppler-utils package).
  • textonly: Extracts only text, no images or complex formatting.

This setting can be specified for subdirectories.

pdfocrconfig = string
Specify the OCR configuration for PDF files. This is a comma-separated list of options. Possible options are:
  • ocr: Enable OCR for PDF files.
  • forceocr: Force OCR even if the PDF already contains text.
  • langs=LANGS: Specify the language(s) for OCR (e.g., langs=eng+fra).
  • psm=PSM: Page Segmentation Mode for Tesseract OCR.
  • oem=OEM: OCR Engine Mode for Tesseract OCR.

Example: pdfocrconfig = ocr,langs=eng,psm=6

This setting can be specified for subdirectories.

pdfmetadatamapping = string
Map PDF metadata fields to Recoll fields. The format is a comma-separated list of mappings, where each mapping is PDF_FIELD=RECOLL_FIELD. For example: pdfmetadatamapping = Creator=author,Producer=tool. This allows you to extract specific PDF metadata into Recoll fields for searching.
pdfextrametafix = fn
Define name of XMP field editing script. This defines the name of a script to be loaded for editing XMP field values. The script should define a "MetaFixer" class with a metafix() method which will be called with the qualified tag name and value of each selected field, for editing or erasing. A new instance is created for each document, so that the object can keep state for, e.g. eliminating duplicate values.
zipUseSkippedNames = bool
Use skippedNames inside Zip archives. Fetched directly by the rclzip.py handler. Skip the patterns defined by skippedNames inside Zip archives. Can be redefined for subdirectories. See https://www.recoll.org/faqsandhowtos/FilteringOutZipArchiveMembers.html
zipSkippedNames = string
Space-separated list of wildcard expressions for names that should be ignored inside zip archives. This is used directly by the zip handler. If zipUseSkippedNames is not set, zipSkippedNames defines the patterns to be skipped inside archives. If zipUseSkippedNames is set, the two lists are concatenated and used. Can be redefined for subdirectories. See https://www.recoll.org/faqsandhowtos/FilteringOutZipArchiveMembers.html
zipMetaEncoding = string
File path encoding. Needs Python 3.11+. Set to "detect" for using chardet. This is useful for non-standard zip files where the metadata is neither UTF-8 (indicated by a file flag), nor CP437 (default). The parameter can be set for specific subtrees. You need to install the Python3 "chardet" package if the value is set to "detect".
orgmodesubdocs = bool
Index org-mode level 1 sections as separate sub-documents This is the default. If set to false, org-mode files will be indexed as plain text
mhmboxquirks = string
Enable thunderbird/mozilla-seamonkey mbox format quirks Set this for the directory(ies) where the email mbox files are stored.
imgocr = bool
Tell the non-default Python image handler to run OCR. See the PDF section for PDF OCR. The image OCR also needs mimeconf changes. See the manual. imgocr can be defined for subdirectories.
ocrprogs = string
OCR modules to try. The top OCR script will try to load the corresponding modules in order and use the first which reports being capable of performing OCR on the input file. Modules for tesseract (tesseract) and ABBYY FineReader (abbyy) are present in the standard distribution. For compatibility with the previous version, if this is not defined at all, the default value is "tesseract". Use an explicit empty value if needed. A value of "abbyy tesseract" will try everything.
ocrcachedir = dfn
Location for caching OCR data. The default if this is empty or undefined is to store the cached OCR data under $RECOLL_CONFDIR/ocrcache.
tesseractlang = string
Language to assume for tesseract OCR. Important for improving the OCR accuracy. This can also be set through the contents of a file in the currently processed directory. See the rclocrtesseract.py script. Example values: eng, fra... See the tesseract documentation.
tesseractcmd = fn
Path for the tesseract command. Do not quote. This is mostly useful on Windows, or for specifying a non-default tesseract command. E.g. on Windows. tesseractcmd = C:/ProgramFiles(x86)/Tesseract-OCR/tesseract.exe
abbyylang = string
Language to assume for abbyy OCR. Important for improving the OCR accuracy. This can also be set through the contents of a file in the currently processed directory. See the rclocrabbyy.py script. Typical values: English, French... See the ABBYY documentation.
abbyyocrcmd = fn
Path for the abbyy command The ABBY directory is usually not in the path, so you should set this.
speechtotext = string
Activate speech to text conversion The only possible value at the moment is "whisper" for using the OpenAI whisper program.
sttmodel = string
Name of the whisper model
sttdevice = string
Name of the device to be used by for whisper
