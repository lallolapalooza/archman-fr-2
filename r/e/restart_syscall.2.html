restart_syscall(2) Manuel des appels système restart_syscall(2)

NOM

restart_syscall - redémarrer un appel système après interruption par un signal d'arrêt

SYNTAXE

long restart_syscall(void);

Note : Il n'y a pas d'enveloppe (wrapper) glibc pour cet appel système ; voir NOTES.

DESCRIPTION

L'appel système restart_syscall() est utilisé pour redémarrer certains appels système après qu'un processus arrêté par un signal (par exemple, SIGSTOP ou SIGTSTP) est ultérieurement repris après avoir reçu un signal SIGCONT. Cet appel système est conçu pour un usage interne par le noyau uniquement.

restart_syscall() est utilisé pour redémarrer uniquement les appels système qui, lors de leur redémarrage, doivent ajuster leurs paramètres temporels—à savoir poll(2) (depuis Linux 2.6.24), nanosleep(2) (depuis Linux 2.6), clock_nanosleep(2) (depuis Linux 2.6), et futex(2), lorsqu'il est utilisé avec les opérations FUTEX_WAIT (depuis Linux 2.6.22) et FUTEX_WAIT_BITSET (depuis Linux 2.6.31). restart_syscall() redémarre l'appel système interrompu avec un argument de temps qui est correctement ajusté pour prendre en compte le temps déjà écoulé (y compris le temps pendant lequel le processus était arrêté par un signal). Sans le mécanisme restart_syscall(), le redémarrage de ces appels système ne déduirait pas correctement le temps déjà écoulé lorsque le processus reprend son exécution.

VALEUR DE RETOUR

La valeur de retour de restart_syscall() est la valeur de retour de l'appel système qui est en cours de redémarrage.

ERREURS

errno est défini conformément aux erreurs de l'appel système qui est redémarré par restart_syscall().

NORMES

Linux.

HISTORIQUE

Linux 2.6.

NOTES

Il n'y a pas d'enveloppe glibc pour cet appel système, car il est destiné à être utilisé uniquement par le noyau et ne devrait jamais être appelé par les applications.

Le noyau utilise restart_syscall() pour s'assurer que lorsqu'un appel système est redémarré après qu'un processus a été arrêté par un signal et ensuite repris par SIGCONT, le temps pendant lequel le processus était arrêté est déduit de l'intervalle de temporisation spécifié dans l'appel système d'origine. Dans le cas des appels système qui prennent un argument de temporisation et redémarrent automatiquement après un signal d'arrêt plus SIGCONT, mais qui n'ont pas le mécanisme restart_syscall() intégré, alors, après que le processus a repris son exécution, le temps pendant lequel le processus était arrêté n'est *pas* déduit de la valeur de temporisation. Des exemples notables d'appels système qui souffrent de ce problème sont ppoll(2), select(2), et pselect(2).

Depuis l'espace utilisateur, le fonctionnement de restart_syscall() est largement invisible : pour le processus qui a effectué l'appel système qui est redémarré, il semble que cet appel système se soit exécuté et ait renvoyé un résultat normalement.

VOIR AUSSI

sigaction(2), sigreturn(2), signal(7)
