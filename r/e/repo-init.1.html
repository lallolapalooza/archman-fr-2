NOM

repo - repo init - page de manuel pour repo init

SYNOPSIS

repo init [options] [url_du_manifeste]

DESCRIPTION

Résumé

Initialise un checkout client repo dans le répertoire courant

OPTIONS

-h, --help
affiche cette aide et quitte

Options de journalisation :

-v, --verbose
affiche toute la sortie
-q, --quiet
affiche uniquement les erreurs

Options de manifeste :

-u URL, --manifest-url=URL
emplacement du dépôt de manifeste
-b REVISION, --manifest-branch=REVISION
branche ou révision du manifeste (utiliser HEAD pour la valeur par défaut)
--manifest-upstream-branch=BRANCH
lorsqu'un commit est fourni à --manifest-branch, c'est le nom de la référence git dans laquelle le commit peut être trouvé
-m NOM.xml, --manifest-name=NOM.xml
fichier manifeste initial
-g GROUPE, --groups=GROUPE
restreint les projets du manifeste à ceux avec les groupes spécifiés [défaut|tous|G1,G2,G3|G4,-G5,-G6]
-p PLATEFORME, --platform=PLATEFORME
restreint les projets du manifeste à ceux avec un groupe de plateforme spécifié [auto|tous|aucun|linux|darwin|...]
--submodules
synchronise tous les sous-modules associés au dépôt de manifeste
--standalone-manifest
télécharge le manifeste comme un fichier statique plutôt que de créer un checkout git du dépôt de manifeste
--manifest-depth=PROFONDEUR
crée un clone superficiel du dépôt de manifeste avec la profondeur donnée (0 pour un clone complet) ; voir git clone (défaut : 0)

Options de checkout de manifeste (uniquement) :

-c, --current-branch
récupère uniquement la branche de manifeste actuelle du serveur (par défaut)
--no-current-branch
récupère toutes les branches de manifeste du serveur
--tags
récupère les tags dans le manifeste
--no-tags
ne récupère pas les tags dans le manifeste

Modes de checkout :

--mirror
crée une réplique des dépôts distants plutôt qu'un répertoire de travail client
--archive
checkout une archive au lieu d'un dépôt git pour chaque projet. Voir git archive.
--worktree
utilise git-worktree pour gérer les projets

Optimisations de checkout de projet :

--reference=DIR
emplacement du répertoire miroir
--dissociate
dissocie des miroirs de référence après le clone
--depth=PROFONDEUR
crée un clone superficiel avec la profondeur donnée ; voir git clone
--partial-clone
effectue un clone partiel (https://gitscm.com/docs/gitrepositorylayout#_code_partialclone_code)
--no-partial-clone
désactive l'utilisation du clone partiel (https://gitscm.com/docs/gitrepositorylayout#_code_partialclone_code)
--partial-clone-exclude=EXCLUSION_CLONE_PARTIEL
exclut les projets spécifiés (noms de projets séparés par des virgules) du clone partiel (https://gitscm.com/docs/gitrepositorylayout#_code_partialclone_code)
--clone-filter=FILTRE_CLONE
filtre à utiliser avec --partial-clone [défaut : blob:none]
--use-superproject
utilise le super-projet de manifeste pour synchroniser les projets ; implique -c
--no-use-superproject
désactive l'utilisation des super-projets de manifeste
--clone-bundle
active l'utilisation de /clone.bundle sur HTTP/HTTPS (par défaut si ce n'est pas --partial-clone)
--no-clone-bundle
désactive l'utilisation de /clone.bundle sur HTTP/HTTPS (par défaut si --partial-clone)
--git-lfs
active le support Git LFS
--no-git-lfs
désactive le support Git LFS

Options de version de repo :

--repo-url=URL
emplacement du dépôt repo ($REPO_URL)
--repo-rev=REV
branche ou révision repo ($REPO_REV)
--no-repo-verify
ne pas vérifier le code source de repo

Autres options :

--config-name
demande toujours le nom/e-mail

Multi-manifeste :

--outer-manifest
opère en partant du manifeste le plus externe
--no-outer-manifest
n'opère pas sur les manifestes externes
--this-manifest-only
opère uniquement sur ce manifeste (sous-manifeste)
--no-this-manifest-only, --all-manifests
opère sur ce manifeste et ses sous-manifestes

Exécutez `repo help init` pour afficher le manuel détaillé.

DÉTAILS

La commande 'repo init' est exécutée une fois pour installer et initialiser repo. Le code source de repo le plus récent et la collection de manifestes sont téléchargés depuis le serveur et sont installés dans le répertoire .repo/ dans le répertoire de travail courant.

Lors de la création d'un nouveau checkout, l'URL du manifeste est la seule configuration requise. Elle peut être spécifiée en utilisant l'option --manifest-url, ou comme premier argument optionnel.

L'argument optionnel -b peut être utilisé pour sélectionner la branche du manifeste à checkout et utiliser. Si aucune branche n'est spécifiée, la branche par défaut du distant est utilisée. Ceci est équivalent à utiliser -b HEAD.

L'argument optionnel --manifest-upstream-branch peut être utilisé lorsqu'un commit est fourni à --manifest-branch (ou -b), pour spécifier le nom

repo-init(1) — repo — Arch Linux

NAME

repo-init — Initialize a repo client in a working directory.

SYNOPSIS

repo init [-q] [-u URL] [-m MANIFEST] [-b BRANCH] [--depth DEPTH] [--standalone-manifest] [--reference REPO-PATH] [--dissociate] [--no-clone-bundle] [--groups=GROUPS] [--repo-url=URL] [--repo-branch=BRANCH] [--repo-commit=COMMIT] [--main-repo-repo-url=URL] [--main-repo-repo-branch=BRANCH] [--main-repo-repo-commit=COMMIT]

DESCRIPTION

The repo client is initialized in the current working directory. A .repo directory will be created to store the metadata for the repo client. This metadata includes the manifest file, which describes the set of Git repositories needed to implement the project.

OPTIONS

The following options are available:

-q
Quiet mode. Suppresses non-error messages.
-u URL
Remote repository URL. This is the URL of the Git repository that contains the manifest file. By default, this is https://android.googlesource.com/platform/manifest.
-m MANIFEST
Manifest file. This is the name of the manifest file within the repository specified by -u. The default manifest file is default.xml.
-b BRANCH
Manifest branch. This is the name of the branch within the repository specified by -u that contains the manifest file. If not specified, the default branch (usually master) will be used.
--depth DEPTH
Create a shallow clone with a history depth of DEPTH. This reduces the amount of data downloaded from the server, but limits the available Git history. Not all Git operations may work correctly with shallow clones.
--standalone-manifest
Download the manifest directly as a static file rather than setting up a Git checkout of the manifest repository. This is useful for build servers or other environments where the manifest doesn't need to be updated frequently. The manifest will not be re-downloaded during subsequent `repo init` and `repo sync` calls.
--reference REPO-PATH
Local reference repository. This option points to a directory that has the content of a --mirror sync. The working directory will use as much data as possible from the local reference directory when fetching from the server, which can significantly speed up syncs by reducing network traffic.
--dissociate
Borrow objects from the directory specified with --reference only to reduce network transfer, and stop borrowing from them after the first clone is made by making necessary local copies of borrowed objects.
--no-clone-bundle
Disable the use of $URL/clone.bundle to bootstrap a new Git repository from a resumeable bundle file. This may be necessary if there are issues with the local HTTP client or proxy configuration.
--groups=GROUPS
Comma-separated list of manifest group names to sync. If not specified, all groups are synced. This allows for selective syncing of projects based on the groups defined in the manifest.
--repo-url=URL
URL of the repository containing the repo tool itself. Used when initializing a repo client in a different location than the current directory.
--repo-branch=BRANCH
Branch of the repository containing the repo tool. Used in conjunction with --repo-url.
--repo-commit=COMMIT
Specific commit of the repository containing the repo tool. Used in conjunction with --repo-url.
--main-repo-repo-url=URL
URL of the manifest repository. This is an alternative to the -u option.
--main-repo-repo-branch=BRANCH
Branch of the manifest repository. This is an alternative to the -b option.
--main-repo-repo-commit=COMMIT
Specific commit of the manifest repository. This is an alternative to specifying a branch and is useful for checking out a specific version of the manifest.

DETAILS

The -m argument can be used to specify an alternate manifest to be used. If no manifest is specified, the manifest default.xml will be used.

If the --standalone-manifest argument is set, the manifest will be downloaded directly from the specified --manifest-url as a static file (rather than setting up a manifest git checkout). With --standalone-manifest, the manifest will be fully static and will not be re-downloaded during subsesquent repo init and repo sync calls.

The --reference option can be used to point to a directory that has the content of a --mirror sync. This will make the working directory use as much data as possible from the local reference directory when fetching from the server. This will make the sync go a lot faster by reducing data traffic on the network.

The --dissociate option can be used to borrow the objects from the directory specified with the --reference option only to reduce network transfer, and stop borrowing from them after a first clone is made by making necessary local copies of borrowed objects.

The --no-clone-bundle option disables any attempt to use $URL/clone.bundle to bootstrap a new Git repository from a resumeable bundle file on a content delivery network. This may be necessary if there are problems with the local Python HTTP client or proxy configuration, but the Git binary works.

Switching Manifest Branches

To switch to another manifest branch, repo init -b otherbranch may be used in an existing client. However, as this only updates the manifest, a subsequent repo sync (or repo sync -d) is necessary to update the working directory files.
