rebuilderd.conf(5) Manuel des formats de fichiers rebuilderd.conf(5)

NOM

rebuilderd.conf - Fichiers de configuration de rebuilderd et rebuildctl

SYNTAXE

/etc/rebuilderd.conf

~/.config/rebuilderd.conf

DESCRIPTION

Ce fichier contient la configuration pour rebuilderd et rebuildctl.

OPTIONS

[http]

bind_addr=

L'adresse à laquelle se lier. Il s'agit de 127.0.0.1:8484 par défaut.

real_ip_header=

Si vous utilisez un proxy inverse, utilisez cet en-tête au lieu de l'adresse IP de connexion réelle. Assurez-vous que le proxy inverse dispose de filtres pour éviter les problèmes d'usurpation. Il n'y a pas de valeur par défaut, mais il est recommandé d'utiliser "X-Real-IP".

endpoint=

Définir un point d'extrémité par défaut pour rebuildctl. Ceci est particulièrement utile pour le minuteur de synchronisation. Par défaut, il s'agit de http://127.0.0.1:8484.

[auth]

cookie=

Un cookie aléatoire pour authentifier les administrateurs. Si cette valeur n'est pas définie, rebuilderd en générera un lui-même et l'écrira dans /var/lib/rebuilderd/auth-cookie. Vous n'avez besoin de le configurer que si vous souhaitez administrer à distance.

https://rebuilder.example.com__">[endpoints."https://rebuilder.example.com"]

cookie=

Cette section est généralement configurée uniquement dans ~/.config/rebuilderd.conf. Elle permet de définir des cookies pour des instances rebuilderd alternatives avec -H. La valeur passée par -H doit correspondre exactement à l'en-tête de section, assurez-vous qu'il n'y a pas de barres obliques finales.

[worker]

authorized_workers=

Liste blanche de la clé publique des instances rebuilderd-worker. Voir la section d'authentification dans rebuilderd(1) pour plus de détails.

signup_secret=

Configurez un secret partagé qu'un rebuilderd-worker doit fournir pour être autorisé à se joindre. Voir la section d'authentification dans rebuilderd(1) pour plus de détails.

[schedule]

retry_delay_base=

Configurez le délai pour réessayer automatiquement les reconstructions échouées en heures. La valeur par défaut est 24h, cette base est multipliée par le nombre de reconstructions, de sorte que la première tentative se produirait après 24h, la deuxième tentative se produirait 48h après la première tentative et la troisième tentative se produirait 72h après la deuxième tentative. Il n'y a pas de limite supérieure aux tentatives, si vous ne pouvez pas vous permettre des tentatives fréquentes, il est recommandé de régler cette valeur sur une valeur élevée comme 168 (1 semaine) ou plus. Les reconstructions réussies ne sont pas retentées.

EXEMPLE

## Configuration pour le démon http
#[http]
## L'adresse à laquelle se lier. Il s'agit de 127.0.0.1:8484 par défaut.
#bind_addr = "0.0.0.0:8484"
## Si vous utilisez un proxy inverse, utilisez cet en-tête au lieu de l'adresse IP réelle de la connexion.
## Assurez-vous que le proxy inverse dispose de filtres pour éviter les problèmes d'usurpation.
#real_ip_header = "X-Real-IP"
## Définir un point d'extrémité par défaut pour rebuildctl. Ceci est particulièrement utile pour le minuteur de synchronisation.
#endpoint = "http://127.0.0.1:8484"
## Un cookie aléatoire pour l'administration est généré au démarrage et écrit dans /var/lib/rebuilderd/auth-cookie
## Vous pouvez le définir sur une valeur fixe ici. Utilisez `pwgen -1s 32` pour en générer un.
## rebuildctl recherche ce cookie dans ~/.config/rebuilderd.conf, /etc/rebuilderd.conf et
## /var/lib/rebuilderd/auth-cookie dans cet ordre.
#[auth]
#cookie = "INSECURE"
## Le cookie d'authentification ci-dessus n'est utilisé que pour le point d'extrémité par défaut.
## Vous pouvez utiliser différents points d'extrémité avec `rebuildctl -H https://rebuilder.example.com status`,
## Dans ce cas, vous devez configurer une section ci-dessous si vous souhaitez joindre un cookie.
#[endpoints."https://rebuilder.example.com"]
#cookie = "INSECURE"
## IMPORTANT : en production, assurez-vous que soit `authorized_workers`, soit `signup_secret` est configuré.
#[worker]
## Si nous avons un ensemble fixe de travailleurs, nous pouvons autoriser leurs clés ici.
#authorized_workers = ["key1", "key2"]
## Si nous voulons générer dynamiquement de nouveaux travailleurs, nous pouvons configurer un secret d'inscription ci-dessous.
## Utilisez `pwgen -1s 32` pour en générer un.
#signup_secret = "INSECURE"
#[schedule]
## Configurez le délai pour réessayer automatiquement les reconstructions échouées en heures. La
## valeur par défaut est de 24h, cette base est multipliée par le nombre de reconstructions, de sorte que la première
## tentative se produise après 24h, la deuxième tentative après 48h après la première tentative et la troisième
## tentative après 72h après la deuxième tentative. Il n'y a pas de limite supérieure aux tentatives, si vous ne
## pouvez pas vous permettre des tentatives fréquentes, il est recommandé de définir cette valeur sur une valeur
## élevée comme 168 (1 semaine) ou plus. Les reconstructions réussies ne sont pas retentées.
#retry_delay_base = 24
