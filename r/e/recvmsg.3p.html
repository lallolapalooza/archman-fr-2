RECVMSG(3P) Manuel du programmeur POSIX RECVMSG(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

recvmsg — recevoir un message d'une socket

SYNOPSIS

#include <sys/socket.h>
ssize_t recvmsg(int socket, struct msghdr *message, int flags);

DESCRIPTION

La fonction recvmsg() reçoit un message d'une socket en mode connexion ou en mode sans connexion. Elle est normalement utilisée avec des sockets en mode sans connexion car elle permet à l'application de récupérer l'adresse source des données reçues.

La fonction recvmsg() prend les arguments suivants :

socket
Spécifie le descripteur de fichier de la socket.
message
Pointe vers une structure msghdr, contenant à la fois le tampon pour stocker l'adresse source et les tampons pour le message entrant. La longueur et le format de l'adresse dépendent de la famille d'adresses de la socket. Le membre msg_flags est ignoré en entrée, mais peut contenir des valeurs significatives en sortie.
flags
Spécifie le type de réception du message. Les valeurs de cet argument sont formées en combinant logiquement zéro ou plus des valeurs suivantes :
MSG_OOB
Demande des données hors bande (out-of-band). La signification et la sémantique des données hors bande sont spécifiques au protocole.
MSG_PEEK
Permet de jeter un coup d'œil au message entrant.
MSG_WAITALL
Sur les sockets SOCK_STREAM, demande à la fonction de bloquer jusqu'à ce que la quantité totale de données puisse être retournée. La fonction peut retourner une quantité plus petite de données si la socket est une socket basée sur les messages, si un signal est intercepté, si la connexion est terminée, si MSG_PEEK a été spécifié, ou si une erreur est en attente pour la socket.

La fonction recvmsg() reçoit des messages de sockets non connectées ou connectées et retourne la longueur du message.

La fonction recvmsg() retourne la longueur totale du message. Pour les sockets basées sur les messages, telles que SOCK_DGRAM et SOCK_SEQPACKET, le message entier doit être lu en une seule opération. Si un message est trop long pour tenir dans les tampons fournis, et que MSG_PEEK n'est pas défini dans l'argument flags, les octets excédentaires seront supprimés, et MSG_TRUNC sera défini dans le membre msg_flags de la structure msghdr. Pour les sockets de flux, telles que SOCK_STREAM, les frontières des messages sont ignorées. Dans ce cas, les données sont retournées à l'utilisateur dès qu'elles deviennent disponibles, et aucune donnée n'est supprimée.

Si le drapeau MSG_WAITALL n'est pas défini, les données ne seront retournées qu'à la fin du premier message.

Si aucun message n'est disponible sur la socket et que O_NONBLOCK n'est pas défini sur le descripteur de fichier de la socket, recvmsg() bloquera jusqu'à l'arrivée d'un message. Si aucun message n'est disponible sur la socket et que O_NONBLOCK est défini sur le descripteur de fichier de la socket, la fonction recvmsg() échouera et définira errno sur [EAGAIN] ou [EWOULDBLOCK].

Dans la structure msghdr, le membre msg_name peut être un pointeur nul si l'adresse source n'est pas requise. Sinon, si la socket n'est pas connectée, le membre msg_name pointe vers une structure sockaddr dans laquelle l'adresse source doit être stockée, et le membre msg_namelen en entrée spécifie la longueur de la structure sockaddr fournie et en sortie spécifie la longueur de l'adresse stockée. Si la longueur réelle de l'adresse est supérieure à la longueur de la structure sockaddr fournie, l'adresse stockée sera tronquée. Si la socket est connectée, les membres msg_name et msg_namelen seront ignorés. Les champs msg_iov et msg_iovlen sont utilisés pour spécifier où les données reçues doivent être stockées. Le membre msg_iov pointe vers un tableau de structures iovec ; le membre msg_iovlen doit être défini à la dimension de ce tableau. Dans chaque structure iovec, le champ iov_base spécifie une zone de stockage et le champ iov_len donne sa taille en octets. Chaque zone de stockage indiquée par msg_iov est remplie de données reçues tour à tour jusqu'à ce que toutes les données reçues soient stockées ou que toutes les zones aient été remplies.

En cas de succès, le membre msg_flags de l'en-tête du message sera le OU logique inclusif de tous les drapeaux suivants qui indiquent des conditions détectées pour le message reçu :

MSG_EOR
Fin d'enregistrement reçue (si supporté par le protocole).
MSG_OOB
Données hors bande reçues.
MSG_TRUNC
Données normales tronquées.
MSG_CTRUNC
Données de contrôle tronquées.

VALEUR DE RETOUR

En cas de succès, recvmsg() retourne la longueur du message en octets. Si aucun message n'est disponible à recevoir et que le pair a effectué une fermeture ordonnée, recvmsg() retourne 0. Sinon, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

La fonction recvmsg() échouera si :

EAGAIN ou EWOULDBLOCK

Le descripteur de fichier de la socket est marqué O_NONBLOCK et aucune donnée n'attend d'être reçue ; ou le drapeau MSG_OOB est défini et aucune donnée hors bande n'est disponible et soit le descripteur de fichier de la socket est marqué O_NONBLOCK, soit la socket ne supporte pas le blocage pour attendre des données hors bande.
EBADF
L'argument socket n'est pas un descripteur de fichier valide ouvert.
ECONNRESET
Une connexion a été forcée à se fermer par un pair.
EINTR
Cette fonction a été interrompue par un signal avant que des données ne soient disponibles.
EINVAL
La somme des valeurs iov_len dépasse un ssize_t, ou le drapeau MSG_OOB est défini et aucune donnée hors bande n'est disponible.
EMSGSIZE
Le membre msg_iovlen de la structure msghdr pointée par message est inférieur ou égal à 0, ou est supérieur à {IOV_MAX}.
ENOTCONN
Une tentative de réception est effectuée sur une socket en mode connexion qui n'est pas connectée.
ENOTSOCK
L'argument socket ne fait pas référence à une socket.
EOPNOTSUPP
Les drapeaux spécifiés ne sont pas supportés pour ce type de socket.
ETIMEDOUT
La connexion a expiré pendant l'établissement de la connexion, ou en raison d'une temporisation de transmission sur une connexion active.

La fonction recvmsg() peut échouer si :

EIO
Une erreur d'E/S s'est produite lors de la lecture ou de l'écriture du système de fichiers.
ENOBUFS
Des ressources insuffisantes étaient disponibles dans le système pour effectuer l'opération.
ENOMEM
Une mémoire insuffisante était disponible pour répondre à la demande.

USAGE PAR L'APPLICATION

PROLOG

This page is a manual page for the Linux operating system. It describes the behavior of the recvmsg() system call and is intended for use with the Linux C library.

NAME

recvmsg, recv

receive a message from a socket

SYNOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <sys/uio.h>

ssize_t recvmsg(int sockfd, struct msghdr *msg, int flags);
ssize_t recv(int sockfd, void *buf, size_t len, int flags);

DESCRIPTION

The recvmsg() function is a general interface for receiving messages from a socket. The recv() function is a simpler interface for receiving data from a connected socket.

The recvmsg() function uses a structure pointed to by msg to receive data and associated information. The msghdr structure is defined as follows:

struct msghdr {
    void         *msg_name;    /* optional address to report */
    socklen_t     msg_namelen; /* size of address to store */
    struct iovec *msg_iov;     /* scatter/gather array of buffers */
    int           msg_iovlen;  /* number of buffers in msg_iov */
    void         *msg_control; /* ancillary data buffer */
    socklen_t     msg_controllen;/* buffer length */
    int           msg_flags;   /* flags on received message */
};

The members of the msghdr structure have the following meanings:

msg_name
This member specifies the address of the peer socket. This is only relevant for connectionless sockets (e.g., UDP) where the sender address is not implicitly known. The argument msg_name points to a buffer large enough to hold the socket address structure (e.g., struct sockaddr). The argument msg_namelen is a value-result argument, which on input specifies the size of the buffer pointed to by msg_name, and on return contains the actual length of the peer address. If msg_name or msg_namelen are NULL or zero respectively, the sender address is not returned.
msg_iov
This member points to an array of iovec structures, each specifying a buffer in which to store incoming data. The iovec structure is defined as:
struct iovec {
    void  *iov_base; /* Pointer to data */
    size_t iov_len;  /* Length of data */
};

This feature, known as scatter/gather I/O, allows incoming data to be placed into multiple buffers. The kernel attempts to fill the buffers in the order specified by the msg_iov array. The msg_iovlen member specifies the number of structures in the msg_iov array.

msg_control
This member points to a buffer that can be used for ancillary data. Ancillary data is protocol-specific control information associated with the message, such as packet information or socket credentials. The kernel will place any available ancillary data into this buffer. The argument msg_controllen is a value-result argument, which on input specifies the size of the buffer pointed to by msg_control, and on return contains the actual size of the ancillary data returned. If msg_control is NULL or msg_controllen is zero, no ancillary data is returned.
msg_flags
This member is used to specify flags affecting the behavior of recvmsg() (see below) and to return flags associated with the received message. On input, it should be set to zero. On return, it contains flags describing the received message. The following flags can be returned:
MSG_CTRUNC
An ancillary data buffer overflow occurred and some ancillary data was discarded.
MSG_DONTWAIT
See MSG_DONTWAIT under DESCRIPTION below.
MSG_ERRQUEUE
Receive error information from the socket error queue. This flag should only be used when receiving from a protocol that generates protocol errors (e.g., IP, ICMP).
MSG_PEEK
See MSG_PEEK under DESCRIPTION below.
MSG_TRUNC
The message was longer than the buffer size available for data. Some data was discarded.
MSG_WAITALL
See MSG_WAITALL under DESCRIPTION below.

The recv() function is equivalent to calling recvmsg() with msg->msg_name, msg->msg_namelen, msg->msg_iov, msg->msg_iovlen, and msg->msg_control all set to NULL or zero, and msg_flags set to 0, and using a single buffer pointed to by buf with length len.

The recvmsg() function receives a message from the socket referred to by the file descriptor sockfd. The message is retrieved from the socket and stored in the buffers specified by msg. If the message is longer than the space available, the excess data is discarded unless MSG_PEEK is specified (see below).

If the socket is a datagram socket (UDP, etc.), recvmsg() can receive a single message. If the message is longer than the specified buffers, the excess data is discarded unless MSG_PEEK is specified. If the socket is a stream socket (TCP, etc.), recvmsg() can receive any number of bytes up to the size of the buffers provided. The recvmsg() call normally blocks until a message is received.

The flags argument can be used to modify the behavior of recvmsg(). The following flags are supported:

MSG_CMSG_CLOEXEC
(Since Linux 3.6) If this flag is set, the close-on-exec flag is set for the file descriptor of the socket if it is created as part of processing this message. This is relevant only for Unix domain sockets and for specific socket types like raw sockets where ancillary data might contain file descriptors.
MSG_DONTBLOCK
Same as MSG_NONBLOCK. Do not wait for data. If data is not available, the call returns -1 and sets errno to EAGAIN.
MSG_DONTWAIT
Do not wait for data. This is a nonblocking option. If data is not available, the call returns -1 and sets errno to EAGAIN.
MSG_ERRQUEUE
Receive error information from the socket error queue. This flag should only be used when receiving from a protocol that generates protocol errors (e.g., IP, ICMP).
MSG_OOB
Process out-of-band data. The use of this flag depends on the socket type and protocol. For stream sockets, it retrieves the out-of-band data. For datagram sockets, it retrieves a control message that indicates an out-of-band condition.
MSG_PEEK
Leave the data in the socket buffer after reading it. This means that the next read operation on the socket will retrieve the same data again. This flag is useful for inspecting incoming data without consuming it.
MSG_TRUNC
Return the real length of the datagram, even if it is longer than the buffer supplied. If the datagram is longer than the buffer, MSG_TRUNC is set in the returned msg_flags, and the datagram is truncated to fit the buffer. If MSG_PEEK is also specified, the message is not removed from the input queue.
MSG_WAITALL
Wait for the entire message to be received. If the socket is a stream socket, this flag causes recvmsg() to block until all of the requested data has been received, or until an error occurs. If the socket is a datagram socket, this flag has no effect.

RETURN VALUE

On success, recvmsg() and recv() return the number of bytes received, or 0 if an end-of-file has been reached. If an error occurs, -1 is returned, and errno is set to indicate the error.

ERRORS

The recvmsg() and recv() functions can fail for the following reasons:

EBADF
The argument sockfd is not a valid file descriptor.
ECONNRESET
A connection reset by peer.
EFAULT
Bad address. Either the message structure, the iovec structure, or the buffers are not valid addresses.
EINTR
A signal was caught before any data was available.
EINVAL
Invalid argument. For example, msg_iovlen is negative or too large, or msg_iov or msg_name point to invalid memory.
ENOTCONN
The socket is not connected.
ENOTSOCK
The file descriptor sockfd does not refer to a socket.
EOPNOTSUPP
The operation is not supported on the socket.
ENOBUFS
No buffer space available.
EAGAIN
The socket is marked nonblocking and no data is available.
ETIMEDOUT
Connection timed out.

EXAMPLES

The following example demonstrates receiving a message using recvmsg() with a single buffer:

struct msghdr msg;
struct iovec iov[1];
char buf[1024];
ssize_t n;

memset(&msg, 0, sizeof(msg));
iov[0].iov_base = buf;
iov[0].iov_len = sizeof(buf);
msg.msg_iov = iov;
msg.msg_iovlen = 1;

n = recvmsg(sockfd, &msg, 0);
if (n < 0) {
    perror("recvmsg");
    exit(EXIT_FAILURE);
}
printf("Received %zd bytes\n", n);

The following example demonstrates receiving a message using recv():

char buf[1024];
ssize_t n;

n = recv(sockfd, buf, sizeof(buf), 0);
if (n < 0) {
    perror("recv");
    exit(EXIT_FAILURE);
}
printf("Received %zd bytes\n", n);

APPLICATION USAGE

The select() and poll() functions can be used to determine when data is available to be received.
