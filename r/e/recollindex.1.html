RECOLLINDEX(1) Manuel des commandes générales RECOLLINDEX(1)

NOM

recollindex - commande d'indexation pour le système de recherche plein texte Recoll

SYNTAXE

recollindex -h
recollindex [ -z|-Z ] [ -k ] [ --nopurge ] [ -P ] [ --diagsfile <chemin_diag> ]
recollindex -m [ -w <secs>] [ -D ] [ -O ] [ -x ] [ -C ] [ -n|-k ]
recollindex -i [ -Z -k -f -P ] [<chemin [chemin ...]>]
recollindex -r [ -Z -K -e -f ] [ -p motif ] <chemin_rep>
recollindex -e [<chemin [chemin ...]>]
recollindex -l|-S|-E
recollindex -s <langue>
recollindex --webcache-compact
recollindex --webcache-burst <rep_dest>
recollindex --notindexed [chemin [chemin ...]]

DESCRIPTION

Crée ou met à jour un index Recoll.

Il existe plusieurs modes de fonctionnement. Tous les modes prennent en charge une option optionnelle -c <rep_cfg> pour spécifier le nom du répertoire de configuration, remplaçant la valeur par défaut ou $RECOLL_CONFDIR (ou $HOME/.recoll par défaut).

Le mode normal indexera l'ensemble de fichiers décrit dans la configuration. Cela mettra à jour incrémentalement l'index avec les fichiers qui ont changé depuis la dernière exécution. Si l'option -z est fournie, l'index sera effacé avant de commencer. Si l'option -Z est fournie, l'index ne sera pas réinitialisé, mais tous les fichiers seront considérés comme nécessitant une réindexation (réinitialisation sur place).

recollindex ne traite pas à nouveau les fichiers qui ont échoué à l'indexation précédemment (par exemple, en raison d'un programme auxiliaire manquant). Si l'option -k est fournie, recollindex essaiera à nouveau de traiter tous les fichiers échoués. Veuillez noter que recollindex peut également décider de réessayer les fichiers échoués si le script de vérification auxiliaire défini par la variable de configuration "checkneedretryindexscript" indique que cela doit se produire.

L'option --nopurge désactivera l'effacement normal des documents supprimés de l'index. Ceci peut être utile dans des cas spéciaux (lorsqu'on sait qu'une partie de l'ensemble de documents est temporairement inaccessible).

L'option -P forcera le passage de purge. Ceci est utile uniquement si le paramètre idxnoautopurge est défini dans le fichier de configuration.

Si l'option --diagsfile est fournie, le chemin donné en paramètre sera tronqué et les diagnostics d'indexation y seront écrits. Chaque ligne du fichier contiendra un type de diagnostic (raison pour laquelle le fichier n'est pas indexé), le chemin du fichier, et un élément d'information supplémentaire possible, qui peut être le type MIME ou le chemin interne de l'archive selon le problème. Les types de diagnostic suivants sont actuellement définis :

Skipped : le chemin correspond à un élément de skippedPaths ou skippedNames.
NoContentSuffix : le suffixe du nom de fichier se trouve dans la liste noContentSuffixes.
MissingHelper : un programme auxiliaire est manquant.
Error : erreur générale (voir le log).
NoHandler: aucun gestionnaire n'est défini pour le type MIME.
ExcludedMime : le type MIME fait partie de la liste excludedmimetypes.
NotIncludedMime : la liste onlymimetypes n'est pas vide et le type MIME n'en fait pas partie.

L'option -R permet de spécifier un fichier temporaire pour écrire les messages d'erreur en cas d'échec de l'indexation. Les mêmes messages vont vers stderr, et l'option est surtout utile pour l'interface graphique, pour afficher une fenêtre d'erreur.

Si l'option -m est fournie, recollindex est démarré pour une surveillance en temps réel, en utilisant le package de surveillance du système de fichiers pour lequel il a été configuré (inotify sous Linux, gamin sous xBSD, fsevents sous MacOS et ReadDirectoryChanges sous Windows). Le programme se détachera normalement du terminal de contrôle et deviendra un démon. Si l'option -D est fournie, il restera au premier plan. L'option -w <secondes> peut être utilisée pour spécifier que le programme doit dormir pendant le temps spécifié avant que l'indexation ne commence. La valeur par défaut est 60. Le démon surveille normalement la session X11 et se termine lorsqu'elle est réinitialisée. Ceci peut être désactivé avec l'option -x  . Vous pouvez utiliser l'option -n pour sauter le passage incrémentiel initial qui est normalement effectué avant que la surveillance ne commence. Une fois la surveillance démarrée, le démon surveille la configuration et redémarre à partir de zéro si un changement est effectué. Vous pouvez désactiver cela avec l'option -C  . L'option -O maintient également le processus au premier plan et en plus, le processus se terminera si son processus parent disparaît.

recollindex -i indexera des fichiers individuels dans l'index. L'expansion des radicaux et les bases de données aspell ne seront pas mises à jour. Les variables de configuration skippedPaths et skippedNames seront utilisées, de sorte que certains fichiers peuvent être ignorés. Vous pouvez indiquer à recollindex d'ignorer skippedPaths et skippedNames en définissant l'option -f. Ceci permet une sélection de fichiers entièrement personnalisée pour un sous-arbre donné, pour lequel vous ajouteriez le répertoire racine à skippedPaths, et utiliseriez tout outil personnalisé pour générer la liste des fichiers (par ex. un outil d'un système de contrôle de code source). Lorsqu'il est exécuté de cette manière, l'indexeur n'effectue normalement pas le passage de purge des fichiers supprimés, car il ne peut pas être sûr d'avoir vu tous les fichiers existants. Vous pouvez forcer un passage de purge avec -P.

recollindex -e effacera les données de fichiers individuels de l'index. Les bases de données d'expansion des radicaux ne seront pas mises à jour.

Les options -i et -e peuvent être combinées. Cela effectuera d'abord la purge, puis l'indexation.

Avec les options -i ou -e , si aucun nom de fichier n'est donné sur la ligne de commande, ils seront lus depuis stdin, de sorte que vous pourriez par exemple exécuter :

find /chemin/vers/rep -print | recollindex -e -i

pour forcer la réindexation d'une arborescence de répertoires (qui doit exister dans la zone du système de fichiers définie par topdirs dans recoll.conf). Vous pourriez accomplir presque la même chose avec

find /chemin/vers/rep -print | recollindex -Z -i

Cette dernière méthode effectuera cependant un travail moins approfondi de purge des sous-documents obsolètes.

recollindex -r fonctionne principalement comme -i , mais le paramètre est un seul répertoire, qui sera mis à jour récursivement. Cela ne fait généralement rien de plus que find rep_racine | recollindex -i mais peut être plus pratique à utiliser lorsqu'il est démarré depuis un autre programme. Cela retente les fichiers échoués par défaut, utilisez l'option -K pour changer. Une ou plusieurs options -p peuvent être utilisées pour définir des motifs de sélection de type shell (par ex. : *.pdf).

recollindex -l listera les noms des stemmers de langue disponibles.

recollindex -s construira la base de données d'expansion des radicaux pour une langue donnée, qui peut ou non faire partie de la liste dans le fichier de configuration. Si la langue ne fait pas partie de la configuration, la base de données d'expansion des radicaux sera supprimée à la fin de la prochaine exécution d'indexation normale. Vous pouvez obtenir la liste des noms de stemmers à partir de la commande recollindex -l. Notez que c'est principalement pour un usage expérimental, la manière normale d'ajouter une langue de stemming est de la définir dans la configuration, soit en modifiant "recoll.conf", soit en utilisant la boîte de dialogue de configuration d'indexation de l'interface graphique.
Au moment de la rédaction, les langues suivantes sont reconnues (parmi celles de Xapian's stem.h) :

  • danish
  • dutch
  • english Martin Porter's 2002 revision of his stemmer
  • english_lovins Lovin's stemmer
  • english_porter Porter's stemmer as described in his 1980 paper
  • finnish
  • french
  • german
  • italian
  • norwegian
  • portuguese
  • russian
  • spanish
  • swedish

recollindex -S reconstruira l'index phonétique/orthographique. Cette fonctionnalité utilise le paquet aspell, qui doit être installé sur le système.

recollindex -E vérifiera l'existence du fichier de configuration pour topdirs et d'autres chemins pertinents (pour aider à attraper les fautes de frappe).

recollindex --webcache-compact récupérera l'espace perdu par les instances de pages effacées dans le cache Web. Il peut temporairement nécessiter l'utilisation du double de l'espace disque utilisé par le cache Web.

recollindex --webcache-burst <rep_dest> extraira toutes les entrées du cache Web vers des fichiers créés dans <rep_dest>. Chaque entrée de cache est extraite en deux fichiers, pour les données et les métadonnées.

Interruption de la commande : l'indexation pouvant prendre un certain temps, la commande peut être interrompue en envoyant un signal d'interruption (Ctrl-C, SIGINT) ou de terminaison (SIGTERM). Un certain temps peut s'écouler avant que le processus ne se termine, car il doit correctement vider et fermer l'index. Cela peut également être fait depuis l'interface graphique de recoll (entrée de menu : Fichier/Arrêter_l'indexation). Après une telle interruption, l'index sera quelque peu incohérent car certaines opérations normalement effectuées à la fin du passage d'indexation auront été sautées (par exemple, les bases de données de racinisation et d'orthographe seront inexistantes ou obsolètes). Il suffit de redémarrer l'indexation ultérieurement pour rétablir la cohérence. L'indexation reprendra au point d'interruption (l'arborescence complète des fichiers sera parcourue, mais les fichiers qui ont été indexés jusqu'à l'interruption et pour lesquels l'index est toujours à jour n'auront pas besoin d'être réindexés).
