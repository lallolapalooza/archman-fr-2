NOM

repo-add - utilitaire de maintenance de base de données de dépôts

SYNTAXE

repo-add [options] <chemin-vers-db> <paquet> [<paquet> ...]

repo-remove [options] <chemin-vers-db> <nom-paquet> [<nom-paquet> ...]

DESCRIPTION

repo-add et repo-remove sont deux scripts pour aider à construire une base de données de paquets pour les paquets construits avec makepkg(8) et installés avec pacman(8).

repo-add mettra à jour une base de données de paquets en lisant un fichier de paquet construit. Plusieurs paquets à ajouter peuvent être spécifiés sur la ligne de commande.

Si un fichier “.sig” correspondant est trouvé à côté d'un fichier de paquet, la signature sera automatiquement intégrée dans la base de données.

repo-remove mettra à jour une base de données de paquets en supprimant le nom de paquet spécifié sur la ligne de commande. Plusieurs paquets à supprimer peuvent être spécifiés sur la ligne de commande.

Une base de données de paquets est un fichier tar, optionnellement compressé. Les extensions valides sont “.db” suivies d'une extension d'archive “.tar”, “.tar.gz”, “.tar.bz2”, “.tar.xz”, ou “.tar.Z”. Le fichier n'a pas besoin d'exister, mais tous les répertoires parents doivent exister.

OPTIONS COMMUNES

-q, --quiet

Force ce programme à rester silencieux et à s'exécuter sans bruit, sauf pour les messages d'avertissement et d'erreur.

-s, --sign

Génère un fichier de signature PGP à l'aide de GnuPG. Ceci exécutera gpg --detach-sign sur la base de données générée pour créer un fichier de signature détaché, en utilisant l'agent GPG s'il est disponible. Le fichier de signature sera le nom de fichier complet de la base de données avec l'extension “.sig”.

-k, --key <clé>

Spécifie une clé à utiliser lors de la signature des paquets. Peut également être spécifiée via la variable d'environnement GPGKEY. Si elle n'est spécifiée dans aucun de ces emplacements, la clé par défaut de l'anneau de clés sera utilisée.

-v, --verify

Vérifie la signature PGP de la base de données avant de mettre à jour la base de données. Si la signature est invalide, une erreur est produite et la mise à jour ne progresse pas.

--nocolor

Supprime la couleur de la sortie de repo-add et repo-remove.

OPTIONS REPO-ADD

-n, --new

Ajoute uniquement les paquets qui ne sont pas déjà dans la base de données. Des avertissements seront affichés lors de la détection de paquets existants, mais ils ne seront pas re-ajoutés.

-R, --remove

Supprime les anciens fichiers de paquets du disque lors de la mise à jour de leur entrée dans la base de données.

--include-sigs

Inclut les signatures PGP des paquets dans la base de données du dépôt (si disponibles).

EXEMPLE

repo-add foo.db.tar.xz <paquet1> [<paquet2> ...]

Ceci crée deux bases de données distinctes ; une base de données plus petite “foo.db.tar.xz” utilisée par pacman et une base de données plus grande contenant les listes de fichiers de paquets “foo.files.tar.xz” pour être utilisée par d'autres utilitaires. Bien que pacman puisse utiliser la base de données plus grande (si renommée avec une extension db.tar*), il n'y a actuellement aucun avantage supplémentaire pour un téléchargement plus important.

BOGUES

Des bogues ? Vous plaisantez ; il n'y a pas de bogues dans ce logiciel. Mais si nous nous trompons, veuillez les signaler au traqueur de problèmes à l'adresse https://gitlab.archlinux.org/pacman/pacman/-/issues avec des informations spécifiques telles que votre ligne de commande, la nature du bogue, et même la base de données de paquets si cela peut aider.
