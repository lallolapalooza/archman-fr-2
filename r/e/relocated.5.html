RELOCATED(5) Formats de fichiers RELOCATED(5)

NOM

relocated - Format de la table relocated de Postfix

SYNTAXE

postmap /etc/postfix/relocated

DESCRIPTION


La table optionnelle relocated(5) fournit les informations utilisées dans les messages de rebond "l'utilisateur a déménagé vers nouvel_emplacement".

Normalement, la table relocated(5) est spécifiée comme un fichier texte servant d'entrée à la commande postmap(1). Le résultat, un fichier indexé au format dbm ou db, est utilisé pour une recherche rapide par le système de messagerie. Exécutez la commande "postmap /etc/postfix/relocated" pour reconstruire un fichier indexé après avoir modifié la table relocated correspondante.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, la table peut être fournie sous forme de table d'expressions régulières où les motifs sont donnés comme des expressions régulières, ou les recherches peuvent être dirigées vers un serveur basé sur TCP. Dans ces cas, les recherches sont effectuées d'une manière légèrement différente, comme décrit ci-dessous sous "TABLES D'EXPRESSIONS RÉGULIÈRES" ou "TABLES BASÉES SUR TCP".

Les recherches dans la table ne sont pas sensibles à la casse.

PLIAGE DE CASSE

La chaîne de recherche est mise en minuscules avant la recherche dans la base de données. Depuis Postfix 2.3, la chaîne de recherche n'est pas mise en minuscules avec des types de bases de données tels que regexp: ou pcre: dont les champs de recherche peuvent correspondre aux majuscules et aux minuscules.

FORMAT DE LA TABLE

Le format d'entrée pour la commande postmap(1) est le suivant :

  • Une entrée a l'une des formes suivantes : 
         motif      nouvel_emplacement

    Où nouvel_emplacement spécifie des informations de contact telles qu'une adresse e-mail, ou peut-être une adresse postale ou un numéro de téléphone.

  • Les lignes vides et les lignes contenant uniquement des espaces sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
  • Une ligne logique commence par du texte non-espace. Une ligne qui commence par un espace continue une ligne logique.

ORDRE DE RECHERCHE DE LA TABLE

Avec les recherches dans des fichiers indexés tels que DB ou DBM, ou dans des tables réseau telles que NIS, LDAP ou SQL, les motifs sont essayés dans l'ordre indiqué ci-dessous :

utilisateur@domaine
Correspond à utilisateur@domaine. Cette forme a la priorité sur toutes les autres formes.
utilisateur
Correspond à utilisateur@site lorsque site est $myorigin, lorsque site est listé dans $mydestination, ou lorsque site est listé dans $inet_interfaces ou $proxy_interfaces.
@domaine
Correspond à d'autres adresses dans domaine. Cette forme a la plus basse priorité.

EXTENSION D'ADRESSE

Lorsqu'une partie locale d'adresse e-mail contient le délimiteur de destinataire optionnel (par exemple, utilisateur+foo@domaine), l'ordre de recherche devient : utilisateur+foo@domaine, utilisateur@domaine, utilisateur+foo, utilisateur, et @domaine.

TABLES D'EXPRESSIONS RÉGULIÈRES

Cette section décrit comment les recherches dans la table changent lorsque la table est fournie sous forme d'expressions régulières ou lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description de la syntaxe des tables de recherche d'expressions régulières, voir regexp_table(5) ou pcre_table(5). Pour une description du protocole de recherche client/serveur TCP, voir tcp_table(5). Cette fonctionnalité est disponible depuis Postfix 2.5.

Chaque motif est une expression régulière appliquée à l'adresse entière recherchée. Ainsi, les adresses e-mail utilisateur@domaine ne sont pas décomposées en leurs parties constitutives utilisateur et @domaine, pas plus que utilisateur+foo n'est décomposé en utilisateur et foo.

Les motifs sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un motif soit trouvé qui corresponde à la chaîne de recherche.

Les résultats sont identiques à ceux des recherches dans des fichiers indexés, avec la fonctionnalité supplémentaire que les sous-chaînes entre parenthèses du motif peuvent être interpolées comme $1, $2 et ainsi de suite.

TABLES BASÉES SUR TCP

Cette section décrit comment les recherches dans la table changent lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description du protocole de recherche client/serveur TCP, voir tcp_table(5). Cette fonctionnalité est disponible depuis Postfix 2.5.

Chaque opération de recherche utilise l'adresse entière une seule fois. Ainsi, les adresses e-mail utilisateur@domaine ne sont pas décomposées en leurs parties constitutives utilisateur et @domaine, pas plus que utilisateur+foo n'est décomposé en utilisateur et foo.

Les résultats sont identiques à ceux des recherches dans des fichiers indexés.

BOGUES


Le format de la table ne comprend pas les conventions de mise entre guillemets.

PARAMÈTRES DE CONFIGURATION

Les paramètres main.cf suivants sont particulièrement pertinents. Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

relocated_maps (vide)
Tables de recherche optionnelles avec les nouvelles informations de contact pour les utilisateurs ou domaines qui n'existent plus.

Autres paramètres d'intérêt :

inet_interfaces (all)
Les adresses d'interface réseau locales sur lesquelles ce système de messagerie reçoit des e-mails.
mydestination ($myhostname, localhost.$mydomain, localhost)
La liste des domaines qui sont livrés via le transport de livraison de courrier $local_transport.
myorigin ($myhostname)
Le nom de domaine d'où semble provenir le courrier posté localement, et vers lequel le courrier posté localement est livré.
proxy_interfaces (vide)
Les adresses d'interface réseau distantes sur lesquelles ce système de messagerie reçoit des e-mails par le biais d'un proxy ou d'une unité de traduction d'adresses réseau.
