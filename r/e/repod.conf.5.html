SYNOPIS

$XDG_CONFIG_HOME/repod/repod.conf

$XDG_CONFIG_HOME/repod/repod.conf.d/

/etc/repod.conf

/etc/repod.conf.d/

DESCRIPTION

Un fichier de configuration basé sur TOML [1], qui peut être fourni dans un emplacement de configuration par défaut et/ou des emplacements de fichiers de configuration de remplacement. Les fichiers de configuration de remplacement sont lus et fusionnés par ordre alphabétique et ont une priorité plus élevée que l'emplacement du fichier de configuration par défaut.

Les fichiers de configuration fournis dans les emplacements système (c.-à-d. /etc/repod.conf et /etc/repod.conf.d/) ne sont utilisés que pour l'utilisation de repod à l'échelle du système, tandis que les configurations fournies dans les emplacements par utilisateur (c.-à-d. $XDG_CONFIG_HOME/repod/repod.conf et $XDG_CONFIG_HOME/repod/repod.conf.d/) ne sont utilisées que pour l'utilisation de repod par utilisateur.

Si aucun fichier de configuration n'est fourni, les valeurs par défaut sont supposées (voir VALEURS PAR DÉFAUT).

OPTIONS GLOBALES

Les options globales fournissent les valeurs par défaut pour tout dépôt qui ne les définit pas. Pour toute option indéfinie, les valeurs par défaut sont supposées (voir OPTIONS PAR DÉFAUT).

architecture =

Un paramètre de chaîne définissant l'architecture CPU utilisée pour tout dépôt qui ne la définit pas. Les valeurs comprises sont

"aarch64", "any", "arm", "armv6h", "armv7h", "i486", "i686", "pentium4", "riscv32", "riscv64", "x86_64", "x86_64_v2", "x86_64_v3", "x86_64_v4"

archiving =

Une table ou une valeur booléenne facultative, qui définit les options d'archivage utilisées pour tout dépôt qui ne les définit pas explicitement. Lorsqu'elle n'est pas définie ou définie sur true, les options d'archivage par défaut sont créées. Si elle est définie sur false, l'archivage est désactivé par défaut, mais peut toujours être défini par dépôt. Lorsqu'elle est définie comme une table, l'option doit définir les paires clé-valeur suivantes :

packages =
Le nom du répertoire d'archives de paquets (voir RÉPERTOIRES PAR DÉFAUT pour les valeurs par défaut), sous lequel des structures de répertoires et des fichiers pour l'archivage des paquets et des fichiers de signature sont créés. Ce répertoire doit être absolu.
sources =
Le nom du répertoire d'archives sources (voir RÉPERTOIRES PAR DÉFAUT pour les valeurs par défaut), sous lequel des structures de répertoires et des fichiers pour l'archivage des tarballs sources sont créés. Ce répertoire doit être absolu.

build_requirements_exist =

Une valeur booléenne facultative, qui définit si les exigences de construction des paquets ajoutés doivent exister dans l'archive (si configuré), dans l'une des couches de stabilité du dépôt cible ou dans l'ensemble des paquets en cours d'ajout. Lorsqu'elle n'est pas définie, la valeur sera définie sur la valeur par défaut (voir OPTIONS PAR DÉFAUT). Lorsqu'elle est définie sur false, les exigences de construction des paquets ajoutés ne sont pas vérifiées, lorsqu'elle est définie sur true, elles sont vérifiées. Ce paramètre peut toujours être remplacé par dépôt.

database_compression =

Un paramètre de chaîne définissant la compression de la base de données utilisée pour tout dépôt qui ne la définit pas. Les valeurs comprises sont

"", "bz2", "gz", "xz", "zst"

management_repo

Une table fournissant la configuration du dépôt de gestion pour tout dépôt qui n'en définit pas explicitement un. Comme chaque dépôt de paquets binaires configuré est représenté par une structure de sous-répertoires dans le dépôt de gestion, plusieurs dépôts peuvent partager le même management_repo.

directory =
Le nom du dépôt de gestion dans le répertoire de base du dépôt de gestion (voir RÉPERTOIRES PAR DÉFAUT), sous lequel les répertoires par dépôt de paquets binaires sont créés. Si la chaîne représente un répertoire absolu, elle est utilisée directement et le répertoire de base par défaut est ignoré.
json_dumps =
Un entier, définissant l'option pour la méthode dumps() [2] d'orjson. Par défaut :
1057

url =

Une chaîne d'URL facultative, pour le dépôt en amont du dépôt de gestion (actuellement non utilisée)

package_pool =

Un paramètre de chaîne définissant un répertoire qui sert de pool de paquets pour tout dépôt qui ne le définit pas.

package_verification =

Une chaîne facultative définissant l'implémentation de la vérification de la signature des paquets pour tous les dépôts. Si une implémentation de vérification de signature est sélectionnée, les paquets ajoutés au dépôt doivent être signés. Les valeurs comprises sont

"pacman-key"

source_pool =

Un paramètre de chaîne définissant un répertoire qui sert de pool de tarballs sources pour tout dépôt qui ne le définit pas.

PARAMÈTRES DE SYNCHRONISATION DE BASE DE DONNÉES

Les paramètres de synchronisation des bases de données offrent un contrôle sur la manière dont les données des bases de données de synchronisation des dépôts sont exportées. Les paires clé-valeur ci-dessous sont configurées sous une table globale syncdb_settings. Pour toute option indéfinie, les valeurs par défaut sont supposées (voir OPTIONS PAR DÉFAUT).

desc_version =

Un entier définissant la version desc utilisée lors de l'exportation du dépôt de gestion vers une base de données de synchronisation de dépôts. Les valeurs comprises sont

2, 1

files_version =

Un entier définissant la version des fichiers utilisée lors de l'exportation du dépôt de gestion vers une base de données de synchronisation de dépôts. Les valeurs comprises sont

1

OPTIONS DE DÉPÔT

Les options de dépôt sont utilisées pour configurer un dépôt spécifique. Si les options facultatives ne sont pas définies, les options globales (voir OPTIONS GLOBALES) ou les valeurs par défaut (voir OPTIONS PAR DÉFAUT) sont supposées.

NOTE : Les répertoires résolus pour les dépôts doivent être globalement uniques. Les seules exceptions à cette règle sont package_pool, source_pool, archiving.packages et archiving.sources.

architecture =

Une chaîne facultative définissant l'architecture CPU. Les valeurs comprises sont

"aarch64", "any", "arm", "armv6h", "armv7h", "i486", "i686", "pentium4", "riscv32", "riscv64", "x86_64", "x86_64_v2", "x86_64_v3", "x86_64_v4"

archiving =

Une table en ligne ou une valeur booléenne facultative, qui définit les options d'archivage. Lorsqu'elle n'est pas définie ou définie sur true, les options d'archivage globales sont utilisées. Si elle est définie sur false, l'archivage est désactivé.

NOTE : Lorsque les dépôts sont utilisés ensemble, ils doivent utiliser les mêmes options d'archivage.

Lorsqu'elle est définie comme une table en ligne, l'option doit définir les paires clé-valeur suivantes :

packages =
Le nom du

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

répertoire d'archivage des paquets (voir RÉPERTOIRES PAR DÉFAUT pour les valeurs par défaut), en dessous duquel des structures de répertoires et des fichiers pour l'archivage des paquets et des fichiers de signature sont créés. Ce répertoire doit être absolu.
sources =
Le nom du répertoire d'archivage des sources (voir RÉPERTOIRES PAR DÉFAUT pour les valeurs par défaut), en dessous duquel des structures de répertoires et des fichiers pour l'archivage des tarballs sources sont créés. Ce répertoire doit être absolu.

build_requirements_exist =

Une valeur booléenne facultative, qui définit si les exigences de compilation des paquets ajoutés doivent exister dans l'archive (si configuré), dans l'une des couches de stabilité du dépôt cible ou dans l'ensemble des paquets en cours d'ajout. Lorsqu'elle n'est pas définie, la valeur sera définie selon la valeur définie globalement. Lorsqu'elle est définie sur false, les exigences de compilation des paquets ajoutés ne sont pas vérifiées, lorsqu'elle est définie sur true, elles le sont.

database_compression =

Un réglage de chaîne de caractères facultatif pour la compression de base de données utilisée pour le dépôt. Les valeurs comprises sont

"", "bz2", "gz", "xz", "zst"

group =

Un entier positif facultatif, qui définit le groupe auquel un dépôt appartient.

NOTE: Lorsque les dépôts sont regroupés, les noms pkgbase et package doivent être uniques parmi eux (c'est-à-dire que le même paquet ne peut pas exister simultanément dans deux dépôts - ceci est différent du même paquet existant dans différentes couches de stabilité du même dépôt !). De plus, les dépôts doivent utiliser le même dépôt de gestion (qui réside sous le répertoire de base du dépôt de gestion), le même répertoire de base du dépôt de paquets, le même répertoire de base du pool de paquets et le même répertoire de base du pool de sources !

management_repo =

Une table en ligne facultative fournissant la configuration du dépôt de gestion du dépôt. Si elle est fournie, elle a priorité sur un management_repo défini globalement. Comme chaque dépôt configuré est représenté par une structure de sous-répertoires dans le dépôt de gestion, plusieurs dépôts peuvent partager le même management_repo.

directory =
Le nom du dépôt de gestion dans le répertoire de base du dépôt de gestion (voir RÉPERTOIRES PAR DÉFAUT), sous lequel des répertoires par dépôt de paquets binaires sont créés. Si la chaîne dénote un répertoire absolu, elle est utilisée directement et le répertoire de base par défaut est ignoré.
json_dumps =
Un entier, définissant l'option pour la méthode dumps() d'orjson (voir https://github.com/ijl/orjson#option). Par défaut :
1057

url =

Une chaîne URL facultative, pour le dépôt amont du dépôt de gestion (actuellement non utilisée)

package_url_validation =

Une table en ligne facultative fournissant la configuration pour la validation des URLs sources. Les URLs sources sont des liens, qui peuvent être fournis par pkgbase en utilisant repod-file et servent de référence aux fichiers sources (par exemple PKGBUILD) pour chaque paquet.

urls =
Une liste de chaînes URL, par rapport auxquelles les URLs sources fournies à repod-file doivent être validées.
tls_required =
Une valeur booléenne, définissant si les URLs dans la liste urls et toute URL source fournie à repod-file doivent utiliser TLS ou non.

name =

Une chaîne de caractères définissant le nom du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets stables du dépôt sont stockées.

NOTE: La combinaison name et architecture **doit être unique** parmi tous les dépôts.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

debug =

Une chaîne de caractères facultative définissant le nom de débogage du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets de débogage stables du dépôt sont stockées.

NOTE: Lors de l'utilisation de cette option et de l'utilisation également des options staging ou testing, les options staging_debug et testing_debug (respectivement) doivent également être définies.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

package_pool =

Une chaîne de caractères facultative définissant un répertoire qui sert de pool de paquets pour le dépôt.

NOTE: Si les dépôts déplacent des paquets entre eux, ils doivent utiliser le même package_pool.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du pool de paquets par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

source_pool =

Une chaîne de caractères facultative définissant un répertoire qui sert de pool de tarballs sources pour le dépôt.

NOTE: Si les dépôts déplacent des paquets entre eux, ils doivent utiliser le même source_pool.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du pool de sources par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

staging =

Une chaîne de caractères facultative définissant le nom de staging du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets de staging du dépôt sont stockées.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

staging_debug =

Une chaîne de caractères facultative définissant le nom de débogage de staging du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets de débogage de staging du dépôt sont stockées.

NOTE: Les options staging et debug doivent être définies lors de l'utilisation de cette option. De même, si debug et staging sont configurés pour un dépôt, cette option doit également être configurée.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

testing =

Une chaîne de caractères facultative définissant le nom de test du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets de test du dépôt sont stockées.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.

testing_debug =

Une chaîne de caractères facultative définissant le nom de débogage de test du dépôt. Elle est utilisée pour construire l'emplacement sous lequel les données de paquets de débogage de test du dépôt sont stockées.

NOTE: Les options testing et debug doivent être définies lors de l'utilisation de cette option. De même, si debug et testing sont configurés pour un dépôt, cette option doit également être configurée.

Si la chaîne dénote un répertoire relatif, elle est utilisée sous le répertoire de base du dépôt de paquets et le répertoire de base du dépôt de gestion par défaut (voir RÉPERTOIRES PAR DÉFAUT).

Si la chaîne dénote un répertoire absolu, elle est utilisée directement et les répertoires de base par défaut sont ignorés.
