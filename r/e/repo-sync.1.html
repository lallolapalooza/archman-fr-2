SYNTAXE

repo sync [<projet>...]

DESCRIPTION

Résumé

Mettre à jour l'arbre de travail vers la dernière révision

OPTIONS

-h, --help
afficher ce message d'aide et quitter
-j JOBS, --jobs=JOBS
nombre de tâches à exécuter en parallèle (défaut : basé sur le nombre de cœurs de CPU)
--jobs-network=JOBS
nombre de tâches réseau à exécuter en parallèle (défaut à --jobs ou 1). Ignoré lorsque --interleaved est défini
--jobs-checkout=JOBS
nombre de tâches de clonage local à exécuter en parallèle (défaut à --jobs ou 8). Ignoré lorsque --interleaved est défini
-f, --force-broken
option obsolète (sera supprimée à l'avenir)
--fail-fast
arrêter la synchronisation après la première erreur rencontrée
--force-sync
écraser un répertoire git existant s'il doit pointer vers un répertoire d'objets différent. ATTENTION : cela peut entraîner une perte de données
--force-checkout
forcer le clonage même si cela entraîne le rejet de modifications non validées. ATTENTION : cela peut entraîner une perte de données
--force-remove-dirty
forcer la suppression de projets avec des modifications non validées si les projets n'existent plus dans le manifeste. ATTENTION : cela peut entraîner une perte de données
--rebase
rebaser les commits locaux, qu'ils soient publiés ou non
-l, --local-only
mettre à jour uniquement l'arbre de travail, ne pas récupérer
--no-manifest-update, --nmu
utiliser le clonage de manifeste existant tel quel. (ne pas mettre à jour vers la dernière révision)
--interleaved
récupérer et cloner les projets en parallèle (expérimental)
-n, --network-only
récupérer uniquement, ne pas mettre à jour l'arbre de travail
-d, --detach
détacher les projets à la révision du manifeste
-c, --current-branch
récupérer uniquement la branche actuelle du serveur
--no-current-branch
récupérer toutes les branches du serveur
-m NOM.xml, --manifest-name=NOM.xml
manifeste temporaire à utiliser pour cette synchronisation
--clone-bundle
activer l'utilisation de /clone.bundle sur HTTP/HTTPS
--no-clone-bundle
désactiver l'utilisation de /clone.bundle sur HTTP/HTTPS
-u NOM_UTILISATEUR_SERVEUR_MANIFESTE, --manifest-server-username=NOM_UTILISATEUR_SERVEUR_MANIFESTE
nom d'utilisateur pour s'authentifier auprès du serveur de manifeste
-p MOT_DE_PASSE_SERVEUR_MANIFESTE, --manifest-server-password=MOT_DE_PASSE_SERVEUR_MANIFESTE
mot de passe pour s'authentifier auprès du serveur de manifeste
--fetch-submodules
récupérer les sous-modules du serveur
--use-superproject
utiliser le super-projet du manifeste pour synchroniser les projets ; implique -c
--no-use-superproject
désactiver l'utilisation des super-projets du manifeste
--tags
récupérer les tags
--no-tags
ne pas récupérer les tags (par défaut)
--optimized-fetch
récupérer uniquement les projets fixés à sha1 si la révision n'existe pas localement
--retry-fetches=RETRY_FETCHES
nombre de tentatives de récupération en cas d'erreurs transitoires
--prune
supprimer les références qui n'existent plus sur le distant (par défaut)
--no-prune
ne pas supprimer les références qui n'existent plus sur le distant
--auto-gc
exécuter le garbage collection sur tous les projets synchronisés
--no-auto-gc
ne pas exécuter le garbage collection sur aucun projet (par défaut)
-s, --smart-sync
synchronisation intelligente en utilisant le manifeste du dernier build connu comme étant bon
-t TAG_INTELLIGENT, --smart-tag=TAG_INTELLIGENT
synchronisation intelligente en utilisant le manifeste d'un tag connu

Options de journalisation :

-v, --verbose
afficher toute la sortie
-q, --quiet
afficher uniquement les erreurs

Options multi-manifeste :

--outer-manifest
opérer en partant du manifeste extérieur
--no-outer-manifest
ne pas opérer sur les manifestes extérieurs
--this-manifest-only
opérer uniquement sur ce manifeste (sous-manifeste)
--no-this-manifest-only, --all-manifests
opérer sur ce manifeste et ses sous-manifestes

Options de version de repo :

--no-repo-verify
ne pas vérifier le code source de repo

Exécutez `repo help sync` pour afficher le manuel détaillé.

DÉTAILS

La commande 'repo sync' synchronise les répertoires de projets locaux avec les dépôts distants spécifiés dans le manifeste. Si un projet local n'existe pas encore, elle clonera un nouveau répertoire local à partir du dépôt distant et configurera les branches de suivi comme spécifié dans le manifeste. Si le projet local existe déjà, 'repo sync' mettra à jour les branches distantes et rebasera les nouveaux changements locaux par-dessus les nouveaux changements distants.

'repo sync' synchronisera tous les projets listés à la ligne de commande. Les projets peuvent être spécifiés soit par leur nom, soit par un chemin relatif ou absolu vers le répertoire local du projet. Si aucun projet n'est spécifié, 'repo sync' synchronisera tous les projets listés dans le manifeste.

L'option -d/--detach peut être utilisée pour ramener les projets spécifiés à la révision du manifeste. Cette option est particulièrement utile si le projet est actuellement sur une branche de sujet, mais que la révision du manifeste est temporairement nécessaire.

L'option -s/--smart-sync peut être utilisée pour se synchroniser avec un build connu comme étant bon, tel que spécifié par l'élément manifest-server dans le manifeste actuel. L'option -t/--smart-tag est similaire et permet de spécifier un tag/une étiquette personnalisé(e).

Les options -u/--manifest-server-username et -p/--manifest-server-password peuvent être utilisées pour spécifier un nom d'utilisateur et un mot de passe afin de s'authentifier auprès du serveur de manifeste lors de l'utilisation de l'option -s ou -t.

Si -u et -p ne sont pas spécifiés lors de l'utilisation de l'option -s ou -t, 'repo sync' tentera de lire les informations d'identification d'authentification pour le serveur de manifeste depuis le fichier .netrc de l'utilisateur.

'repo sync' n'utilisera pas les informations d'identification d'authentification de -u/-p ou de .netrc i

repo-sync(1) - Arch manual pages

repo sync

Sync projects from a manifest

SYNOPSIS

repo sync [OPTIONS] [PROJECT...]
repo sync -h | --help

DESCRIPTION

This command downloads the specified projects from their remote Git repositories and checks out the specified revision. If no projects are specified, all projects in the manifest are downloaded.

The command operates on a set of projects. Each project is identified by its path name relative to the top of the working directory. Projects can be specified on the command line to sync only those projects. When the list of projects is empty, all projects are synced.

The remote Git repositories are specified in the manifest file used to initialize the repository. If the manifest file contains multiple remote repositories, the command will try each remote in order until the project is found.

OPTIONS

-c, --current-branch
Only fetch objects that are on the branch specified by a project's revision. This is used to avoid fetching objects on all branches, and save bandwidth. Not compatible with Fetching submodules.
-d, --default-branch
If a project is not on its default branch, check out the manifest's default branch. This is useful when you only care about the default branch.
-f, --force-sync
Overwrite existing git directories if they have previously been linked to a different object directory. WARNING: This may cause data to be lost since refs may be removed when overwriting.
-F, --fail-fast
Halt syncing as soon as possible when the first project fails to sync.
-h, --help
Show this help message and exit.
-j N
Use up to N parallel threads to sync projects.
-m, --mirror
Create a mirror of the Git repository. This is useful for creating a local mirror of the remote repository.
-n, --network-only
Do not check out any files into the working directory. Only fetch objects and update the Git index. This is useful for running repo sync in a CI environment where only the Git objects are needed.
--no-clone-bundle
Disables any attempt to use $URL/clone.bundle to bootstrap a new Git repository from a resumeable bundle file on a content delivery network. This may be necessary if there are problems with the local Python HTTP client or proxy configuration, but the Git binary works.
--no-tags
Do not fetch tags.
--optimize-fetch
Only fetch projects that are fixed to a sha1 revision if the sha1 revision does not already exist locally.
--prune
Remove any refs that no longer exist on the remote.
-u, --upload-archive
Create an upload archive.
-p, --prune-tags
Remove any tags that no longer exist on the remote.
-g, --groups
Fetch projects that are members of the specified groups.
--force-checkout
Force git to switch revs even if the index or the working tree differs from HEAD, and if there are untracked files. WARNING: This may cause data to be lost since uncommitted changes may be removed.
--force-remove-dirty
Remove previously used projects with uncommitted changes. WARNING: This may cause data to be lost since uncommitted changes may be removed with projects that no longer exist in the manifest.
--fetch-submodules
Fetch Git submodules of a project from server.
--auto-gc
Trigger garbage collection on all projects. By default, repo does not run garbage collection.

DETAILS

If the manifest server specified in the manifest file already includes credentials.

By default, all projects will be synced. The --fail-fast option can be used to halt syncing as soon as possible when the first project fails to sync.

The --force-sync option can be used to overwrite existing git directories if they have previously been linked to a different object directory. WARNING: This may cause data to be lost since refs may be removed when overwriting.

The --force-checkout option can be used to force git to switch revs even if the index or the working tree differs from HEAD, and if there are untracked files. WARNING: This may cause data to be lost since uncommitted changes may be removed.

The --force-remove-dirty option can be used to remove previously used projects with uncommitted changes. WARNING: This may cause data to be lost since uncommitted changes may be removed with projects that no longer exist in the manifest.

The --no-clone-bundle option disables any attempt to use $URL/clone.bundle to bootstrap a new Git repository from a resumeable bundle file on a content delivery network. This may be necessary if there are problems with the local Python HTTP client or proxy configuration, but the Git binary works.

The --fetch-submodules option enables fetching Git submodules of a project from server.

The -c/--current-branch option can be used to only fetch objects that are on the branch specified by a project's revision.

The --optimized-fetch option can be used to only fetch projects that are fixed to a sha1 revision if the sha1 revision does not already exist locally.

The --prune option can be used to remove any refs that no longer exist on the remote.

The --auto-gc option can be used to trigger garbage collection on all projects. By default, repo does not run garbage collection.

SSH Connections

If at least one project remote URL uses an SSH connection (ssh://, git+ssh://, or user@host:path syntax) repo will automatically enable the SSH ControlMaster option when connecting to that host. This feature permits other projects in the same 'repo sync' session to reuse the same SSH tunnel, saving connection setup overheads.

To disable this behavior on UNIX platforms, set the GIT_SSH environment variable to 'ssh'. For example:

export GIT_SSH=ssh repo sync

Compatibility

This feature is automatically disabled on Windows, due to the lack of UNIX domain socket support.

This feature is not compatible with url.insteadof rewrites in the user's ~/.gitconfig. 'repo sync' is currently not able to perform the rewrite early enough to establish the ControlMaster tunnel.

If the remote SSH daemon is Gerrit Code Review, version 2.0.10 or later is required to fix a server side protocol bug.
