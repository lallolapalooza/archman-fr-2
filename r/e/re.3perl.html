re(3perl) Guide de référence du programmeur Perl re(3perl)

NOM

re — Pragma Perl pour modifier le comportement des expressions régulières

SYNOPSIS

use re 'taint';
($x) = ($^X =~ /^(.*)$/s);     # $x est "tainted" ici
$pat = '(?{ $foo = 1 })';
use re 'eval';
/foo${pat}bar/;                # ne échouera pas (quand pas sous le commutateur -T
                               # switch)
{
    no re 'taint';             # par défaut
    ($x) = ($^X =~ /^(.*)$/s); # $x n'est pas "tainted" ici
    no re 'eval';              # par défaut
    /foo${pat}bar/;            # interdit (avec ou sans commutateur -T)
}
use re 'strict';               # Émet des avertissements pour plus de conditions
use re '/ix';
"FOO" =~ / foo /; # /ix implicite
no re '/x';
"FOO" =~ /foo/; # seulement /i implicite
use re 'debug';                # affiche des informations de débogage pendant
/^(.*)$/s;                     # la compilation et l'exécution
use re 'debugcolor';           # identique à 'debug', mais avec une sortie colorée
...
use re qw(Debug All);          # Identique à "use re 'debug'", mais vous
                               # pouvez utiliser "Debug" avec des choses autres
                               # que 'All'
use re qw(Debug More);         # 'All' plus la sortie de plus de détails
no re qw(Debug ALL);           # Active (presque) tout le débogage re
                               # dans cette portée
use re qw(is_regexp regexp_pattern); # importe des fonctions utilitaires
my ($pat,$mods)=regexp_pattern(qr/foo/i);
if (is_regexp($obj)) {
    print "Got regexp: ",
        scalar regexp_pattern($obj); # juste comme perl le convertirait en chaîne
}                                    # mais sans tracas avec des re encapsulés.

(Nous utilisons $^X dans ces exemples car il est "tainted" par défaut.)

DESCRIPTION

mode 'taint'

Lorsque "use re 'taint'" est en vigueur, et qu'une chaîne "tainted" est la cible d'une expression régulière, les mémoires de l'expression régulière (ou les valeurs renvoyées par l'opérateur m// en contexte de liste) sont "tainted". Cette fonctionnalité est utile lorsque les opérations d'expression régulière sur des données "tainted" ne sont pas destinées à extraire des sous-chaînes sûres, mais à effectuer d'autres transformations.

mode 'eval'

Lorsque "use re 'eval'" est en vigueur, une expression régulière est autorisée à contenir des assertions de largeur nulle "(?{ ... })" et des sous-expressions postposées "(??{ ... })" qui sont dérivées de l'interpolation de variables, plutôt que d'apparaître littéralement dans l'expression régulière. Ceci est normalement interdit, car c'est un risque potentiel pour la sécurité. Notez que ce pragma est ignoré lorsque l'expression régulière est obtenue à partir de données "tainted", c'est-à-dire que l'évaluation est toujours interdite avec des expressions régulières "tainted". Voir "(?{ code })" dans perlre et "(??{ code })" dans perlre.

Aux fins de ce pragma, l'interpolation d'expressions régulières précompilées (c'est-à-dire le résultat de "qr//") n'est pas considérée comme une interpolation de variable. Ainsi :

/foo${pat}bar/

est autorisé si $pat est une expression régulière précompilée, même si $pat contient des assertions "(?{ ... })" ou des sous-expressions "(??{ ... })".

mode 'strict'

Notez qu'il s'agit d'une fonctionnalité expérimentale qui pourrait être modifiée ou supprimée dans une future version de Perl.

Lorsque "use re 'strict'" est en vigueur, des vérifications plus strictes sont appliquées qu'autrement lors de la compilation des motifs d'expressions régulières. Celles-ci peuvent provoquer plus d'avertissements que d'habitude, et rendre plus de choses fatales au lieu d'être simplement des avertissements. Le but est de trouver et de signaler au moment de la compilation certaines choses qui peuvent être légales, mais qui ont une probabilité raisonnable de ne pas correspondre à l'intention réelle du programmeur. Cela active automatiquement la catégorie d'avertissements "regexp" (si elle n'est pas déjà activée) dans sa portée.

À titre d'exemple de quelque chose qui est détecté sous 'strict', mais pas autrement, on trouve le motif

qr/\xABC/

Le construct "\x" sans accolades doit être suivi de exactement deux chiffres hexadécimaux ; celui-ci est suivi de trois. Ceci est actuellement évalué comme équivalent à

qr/\x{AB}C/

c'est-à-dire le caractère dont la valeur du point de code est 0xAB, suivi de la lettre "C". Mais comme "C" est un chiffre hexadécimal, il y a une chance raisonnable que l'intention ait été

qr/\x{ABC}/

c'est-à-dire le caractère unique à 0xABC. Sous 'strict', il est interdit de ne pas suivre "\x" de exactement deux chiffres hexadécimaux. Lorsque l'on n'est pas sous 'strict', un avertissement est généré s'il n'y a qu'un seul chiffre hexadécimal, et aucun avertissement n'est émis s'il y en a plus de deux.

Il est prévu que ce que fait exactement 'strict' évoluera au fil du temps à mesure que nous acquérons de l'expérience avec lui. Cela signifie que les programmes qui se compilent sous celui-ci dans le Perl actuel pourraient ne pas se compiler, ou avoir plus ou moins d'avertissements, dans les Perl futurs. Il n'y a aucune promesse de rétrocompatibilité à cet égard. De plus, il existe déjà des propositions pour une syntaxe alternative pour l'activer. Pour ces raisons, son utilisation déclenchera un avertissement de la classe "experimental::re_strict", sauf si cette catégorie est désactivée.

Notez que si un motif compilé dans le mode 'strict' est recompilé, par exemple en l'interpolant dans un autre motif, en dehors du mode 'strict', il n'est pas revérifié pour la stricte. C'est parce que s'il fonctionne sous strict, il doit fonctionner sous non-strict.

mode '/flags'

Lorsque "use re '/flags'a', 'aa', 'd', 'i', 'l', 'm', 'n', 'p', 's', 'u', 'x', et/ou 'xx'.

"no re '/flags"use re '/flagsPar exemple, si vous voulez que toutes vos expressions régulières aient les flags /msxx par défaut, mettez simplement

use re '/msxx';

en haut de votre code.

L'ensemble de caractères "/adul" des flags s'annulent mutuellement. Donc, dans cet exemple,

use re "/u";
"ss" =~ /\xdf/;
use re "/d";
"ss" =~ /\xdf/;

le second "use re" effectue un "no re '/u'" implicite.

De même,

use re "/xx";   # Double-x
...
use re "/x";    # Simple x à partir d'ici
...

L'activation de l'un des flags de jeu de caractères avec "use re" a priorité sur le pragma "locale" et la "feature" 'unicode_strings', pour les expressions régulières. La désactivation de l'un de ces flags lorsqu'il est actif rétablit le comportement spécifié par les autres pragmata en vigueur. Par exemple :

use feature "unicode_strings";
no re "/u"; # ne fait rien
use re "/l";
no re "/l"; # revient au comportement unicode_strings

Les flags par défaut sont appliqués partout où un motif est compilé, à l'exception du flag "/x", qui n'est pas appliqué aux motifs compilés à partir d'arguments de chaîne pour "split". Ainsi `use re "/x";` n'affecte pas le comportement de "split " "" mais affecte le comportement de "split / /".

mode 'debug'

Lorsque "use re 'debug'" est en vigueur, perl émet des messages de débogage lors de la compilation et de l'utilisation des expressions régulières. La sortie est la même que celle obtenue en exécutant un Perl compilé avec l'option "-DDEBUGGING".

mode 'debugcolor'

Identique à "use re 'debug'", mais avec une sortie colorée.

mode 'all'

Utiliser "use re 'all'" (ou "use re 'debug'") émet des messages de débogage pour toutes les expressions régulières.

mode 'more'

Utiliser "use re 'more'" (ou "use re 'debug'" puis "use re 'more'") émet plus de détails sur le débogage des expressions régulières.

Vérification de la compilation des expressions régulières

Les commandes "use re qw(is_regexp regexp_pattern)" et "no re qw(is_regexp regexp_pattern)" importent (ou suppriment) les fonctions utilitaires is_regexp et regexp_pattern.

is_regexp($thing) renvoie vrai si $thing est une référence d'expression régulière.

regexp_pattern($thing) renvoie la chaîne représentant le motif de l'expression régulière de $thing, ou undef si ce n'est pas une expression régulière.

Ces fonctions sont utiles si vous avez des objets qui pourraient contenir des expressions régulières et que vous voulez savoir si c'est le cas et récupérer le motif.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Interpréteur perl ed avec l'option -Dr. Elle peut être assez volumineuse en fonction de la complexité de la correspondance. L'utilisation de "debugcolor" au lieu de "debug" active une forme de sortie qui peut être utilisée pour obtenir un affichage coloré sur les terminaux qui comprennent les séquences de couleurs termcap. Définissez $ENV{PERL_RE_TC} sur une liste séparée par des virgules de propriétés "termcap" à utiliser pour la mise en évidence des chaînes on/off, avant le point on/off. Voir "Debugging Regular Expressions" dans perldebug pour des informations supplémentaires.

NOTEZ que le format exact du mode "debug" n'est PAS considéré comme une API officiellement prise en charge par Perl. Il est destiné uniquement au débogage et peut être modifié par l'équipe de développement du noyau sans préavis ni obsolescence dans aucune version de Perl, majeure ou mineure. Toute documentation de la sortie est purement indicative.

À partir de 5.9.5, la directive "use re 'debug'" et ses équivalents sont délimités lexicalement, comme le sont les autres directives. Cependant, ils ont des effets à la fois au moment de la compilation et à l'exécution.

Voir "Pragmatic Modules" dans perlmodlib.

'Debug' mode

De même, "use re 'Debug'" produit une sortie de débogage, la différence étant qu'elle permet un réglage fin de la sortie de débogage qui sera émise. Les options sont divisées en trois groupes : celles liées à la compilation, celles liées à l'exécution et celles liées à des fins spéciales.

NOTEZ que les options fournies sous le mode "Debug" et le format exact de la sortie qu'elles créent ne sont PAS considérés comme une API officiellement prise en charge par Perl. Il est destiné uniquement au débogage et peut être modifié par l'équipe de développement du noyau sans préavis ni obsolescence dans aucune version de Perl, majeure ou mineure. Toute documentation du format ou des options disponibles est uniquement à titre indicatif et est sujette à modification sans préavis.

Les options sont les suivantes :

Options relatives à la compilation
COMPILE
Active toutes les options de débogage relatives à la compilation, sauf les options supplémentaires.
PARSE
Active la sortie de débogage relative au processus d'analyse du motif.
OPTIMISE
Active la sortie relative à la phase d'optimisation de la compilation.
TRIEC
Informations détaillées sur la compilation des triés.
DUMP
Affiche le programme final après sa compilation et son optimisation.
FLAGS
Affiche les indicateurs associés au programme.
TEST
Affiche la sortie destinée à tester les internes du processus de compilation.
Options relatives à l'exécution
EXECUTE
Active toutes les options de débogage relatives à l'exécution, sauf les options supplémentaires.
MATCH
Active le débogage de la boucle de correspondance principale.
TRIEE
Débogage supplémentaire de la façon dont les triés s'exécutent.
INTUIT
Active le débogage des optimisations du point de départ.
Options de débogage supplémentaires
EXTRA
Active toutes les options de débogage "supplémentaires".
BUFFERS
Active le débogage du stockage des groupes de capture pendant la correspondance. Attention, cela peut potentiellement produire une sortie extrêmement volumineuse.
TRIEM
Active le débogage amélioré des triés. Améliore à la fois TRIEE et TRIEC.
STATE
Active le débogage des états dans le moteur.
STACK
Active le débogage de la pile de récursion dans le moteur. L'activation ou la désactivation de cette option fait automatiquement de même pour le débogage des états. La sortie de celle-ci peut être assez volumineuse.
GPOS
Active le débogage du modificateur \\G.
OPTIMISEM
Active le débogage amélioré de l'optimisation et les optimisations du point de départ. Probablement inutile sauf lors du débogage du moteur d'expressions régulières lui-même.
DUMP_PRE_OPTIMIZE
Active l'affichage du motif compilé avant la phase d'optimisation.
WILDCARD
Lorsque Perl rencontre un sous-motif joker, (voir "Wildcards in Property Values" dans perlunicode), il suspend la compilation du motif principal, compile le sous-motif, puis le fait correspondre à toutes les possibilités légales pour déterminer les points de code réels que le sous-motif correspond. Après cela, il les ajoute au motif principal et poursuit sa compilation.

Vous voudrez peut-être voir comment votre sous-motif est compilé, mais il est probablement moins utile de voir comment Perl le fait correspondre à toutes les possibilités légales, car cela est sous le contrôle de Perl, pas de vous. Par conséquent, les informations de débogage de la partie compilation sont spécifiées par les autres options, mais la sortie de débogage de la partie correspondance est normalement supprimée.

Vous pouvez utiliser l'option WILDCARD pour activer la sortie de débogage de cette correspondance de sous-motif. Attention ! Cela peut entraîner des sorties volumineuses, et il se peut que ce que Perl fait et pourquoi n'ait pas beaucoup de sens pour vous. Mais cela peut vous aider à comprendre pourquoi les choses ne se passent pas comme prévu.

Notez que cette option seule ne provoque aucune sortie d'informations de débogage. Ce qu'elle fait, c'est arrêter la suppression normale des informations de débogage liées à l'exécution pendant la partie correspondance de la compilation des jokers. Vous devez également spécifier quelles informations de débogage d'exécution vous souhaitez, par exemple en incluant également l'option EXECUTE.

Autres indicateurs utiles
Ce sont des raccourcis utiles pour économiser de la frappe.
ALL
Active toutes les options à la fois, sauf BUFFERS, WILDCARD et DUMP_PRE_OPTIMIZE. (Pour obtenir toutes les options sans exception, utilisez à la fois ALL et EXTRA, ou à partir de 5.30 sur un interpréteur perl activé par "-DDEBUGGING", utilisez les options de ligne de commande -Drv.)
All
Active DUMP et toutes les options d'exécution non supplémentaires. Équivalent à : 
use re 'debug';
MORE
More
Active les options activées par "All", plus STATE, TRIEC et TRIEM.

À partir de 5.9.5, la directive "use re 'debug'" et ses équivalents sont délimités lexicalement, comme le sont les autres directives. Cependant, ils ont des effets à la fois au moment de la compilation et à l'exécution.

Fonctions Exportables

Depuis perl 5.9.5, le module "re" contient un certain nombre de fonctions utilitaires qui peuvent être exportées facultativement dans l'espace de noms de l'appelant. Elles sont listées ci-dessous.

is_regexp($ref)
Retourne vrai si l'argument est une expression régulière compilée telle que retournée par "qr//", faux si ce n'est pas le cas.

Cette fonction ne sera pas confondue par le surcharge ou la bénédiction. En termes internes, elle extrait le pointeur d'expression régulière de la structure PERL_MAGIC_qr afin qu'elle ne puisse pas être trompée.

regexp_pattern($ref)
Si l'argument est une expression régulière compilée telle que retournée par "qr//", alors cette fonction retourne le motif.

En contexte de liste, elle retourne une liste à deux éléments, le premier élément contenant le motif et le second contenant les modificateurs utilisés lors de la compilation du motif.

my ($pat, $mods) = regexp_pattern($ref);

En contexte scalaire, elle retourne la même chose que perl lors de la transformation en chaîne d'un "qr//" brut avec le même motif à l'intérieur. Si l'argument n'est pas une référence compilée, alors cette routine retourne faux mais défini en contexte scalaire, et la liste vide en contexte de liste. Ainsi, le suivant

if (regexp_pattern($ref) eq '(?^i:foo)')

sera sans avertissement, quel que soit ce que $ref est réellement.

Comme "is_regexp", cette fonction ne sera pas confuse par le surcharge ou la bénédiction de l'objet.

regname($name,$all)
Retourne le contenu d'un tampon nommé de la dernière correspondance réussie. Si $all est vrai, alors retourne une référence de tableau contenant une entrée par tampon, sinon retourne le premier tampon défini.
regnames($all)
Retourne une liste de tous les tampons nommés définis dans la dernière correspondance réussie. Si $all est vrai, alors il retourne tous les noms définis, sinon il retourne uniquement les noms qui ont été impliqués dans la correspondance.
regnames_count()
Retourne le nombre de noms distincts définis dans le motif utilisé pour la dernière correspondance réussie.

Note : ce résultat est toujours le nombre réel de tampons nommés distincts définis, il peut ne pas correspondre à ce qui est retourné par regnames() et les routines associées lorsque ces routines n'ont pas été appelées avec le $al

l paramètre défini.

regmust($ref)
Si l'argument est une expression régulière compilée telle que retournée par "qr//", alors cette fonction retourne ce que l'optimiseur considère comme la chaîne fixe ancrée la plus longue et la chaîne fixe flottante la plus longue dans le motif.

Une chaîne fixe est définie comme étant une sous-chaîne qui doit apparaître pour que le motif corresponde. Une chaîne fixe ancrée est une chaîne fixe qui doit apparaître à un décalage particulier par rapport au début de la correspondance. Une chaîne fixe flottante est définie comme une chaîne fixe qui peut apparaître à n'importe quel point d'une plage de positions par rapport au début de la correspondance. Par exemple,

my $qr = qr/here .* there/x;
my ($anchored, $floating) = regmust($qr);
print "anchored:'$anchored'\nfloating:'$floating'\n";

résulte en

anchored:'here'
floating:'there'

Parce que "here" est avant ".*" dans le motif, sa position peut être déterminée exactement. Ce n'est pas vrai, cependant, pour "there" ; il peut apparaître à n'importe quel point après l'emplacement de la chaîne ancrée. Perl utilise les deux pour ses optimisations, préférant la plus longue, ou, si elles sont égales, la flottante.

NOTE : Ce n'est pas nécessairement la chaîne ancrée et flottante la plus longue qui soit définitive. Ce sera ce que l'optimiseur de la version de Perl que vous utilisez considère comme la plus longue. Si vous pensez que le résultat est erroné, veuillez le signaler via l'utilitaire perlbug.

optimization($ref)
Si l'argument est une expression régulière compilée telle que retournée par "qr//", alors cette fonction retourne une référence de hachage des informations d'optimisation découvertes au moment de la compilation, afin que nous puissions écrire des tests autour. Si un autre argument est donné, retourne "undef".

Le contenu du hachage est susceptible de changer de temps à autre à mesure que nous développons de nouvelles méthodes d'optimisation - aucune stabilité ne doit être présumée, pas même entre des versions mineures de perl.

Pour la version actuelle, le hachage aura le contenu suivant :

minlen
Un entier, le nombre minimum de caractères dans toute chaîne qui peut correspondre.
minlenret
Un entier, le nombre minimum de caractères qui peuvent se trouver dans $& après une correspondance. (Considérez par exemple " /ns(?=\d)/ ".)
gofs
Un entier, le nombre de caractères avant pos() pour commencer la correspondance.
noscan
Un booléen, "TRUE" pour indiquer que les sous-chaînes ancrées/flottantes trouvées ne doivent pas être utilisées. (À VÉRIFIER : apparemment, ceci est défini pour un motif ancré sans sous-chaîne flottante, mais jamais utilisé.)
isall
Un booléen, "TRUE" pour indiquer que les informations d'optimisation sont tout ce que contient l'expression régulière, et par conséquent, il n'est pas nécessaire d'entrer dans le moteur d'exécution regexp du tout.
anchor SBOL
Un booléen, "TRUE" si le motif est ancré au début de la chaîne.
anchor MBOL
Un booléen, "TRUE" si le motif est ancré à n'importe quel début de ligne dans la chaîne.
anchor GPOS
Un booléen, "TRUE" si le motif est ancré à la fin de la correspondance précédente.
skip
Un booléen, "TRUE" si la classe de départ peut correspondre uniquement au premier d'une série.
implicit
Un booléen, "TRUE" si un "/.*/" a été implicitement transformé en "/^.*/".
anchored/floating
Une chaîne d'octets représentant une sous-chaîne ancrée ou flottante respectivement que toute correspondance doit contenir, ou undef si aucune sous-chaîne de ce type n'a été trouvée, ou si la sous-chaîne nécessiterait utf8 pour être représentée.
anchored utf8/floating utf8
Une chaîne utf8 représentant une sous-chaîne ancrée ou flottante respectivement que toute correspondance doit contenir, ou undef si aucune sous-chaîne de ce type n'a été trouvée, ou si la sous-chaîne ne contient que des caractères ASCII 7 bits.
anchored min offset/floating min offset
Un entier, le premier décalage en caractères depuis un emplacement de correspondance auquel nous devrions rechercher la sous-chaîne correspondante.
anchored max offset/floating max offset
Un entier, le dernier décalage en caractères depuis un emplacement de correspondance auquel nous devrions rechercher la sous-chaîne correspondante.

Ignoré pour les ancrés, donc peut être 0 ou identique au minimum.

anchored end shift/floating end shift
À VERIFIER : je ne suis pas sûr de ce que c'est, quelque chose lié au lookbehind. regcomp.c dit :
Lorsque le motif final est compilé et que les données sont déplacées de la
structure scan_data_t vers la structure regexp, les informations
sur le lookbehind sont prises en compte, avec les informations qui auraient
été perdues précalculées dans le champ end_shift pour la
chaîne associée.
checking
Une chaîne constante, l'une de "anchored", "floating" ou "none" pour indiquer quelle sous-chaîne (le cas échéant) doit être vérifiée en premier.
stclass
Une représentation sous forme de chaîne d'une classe de caractères ("classe de départ") qui doit être le premier caractère de toute correspondance.

À FAIRE : expliquer les représentations.
