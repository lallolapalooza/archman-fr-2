recno(3) Manuel des fonctions de bibliothèque recno(3)

NOM

recno - méthode d'accès à la base de données de numéros d'enregistrement

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/types.h>
#include <db.h>

DESCRIPTION

Notez bien : cette page documente les interfaces fournies jusqu'à glibc 2.1. Depuis glibc 2.2, glibc ne fournit plus ces interfaces. Vous recherchez probablement les API fournies par la bibliothèque libdb.

La routine dbopen(3) est l'interface de la bibliothèque pour les fichiers de base de données. L'un des formats de fichiers pris en charge est les fichiers de numéros d'enregistrement. La structure de données du numéro d'enregistrement est soit des enregistrements de longueur variable, soit de longueur fixe, stockés dans un format de fichier plat, accessibles par le numéro d'enregistrement logique. L'existence du numéro d'enregistrement cinq implique l'existence des enregistrements un à quatre, et la suppression de l'enregistrement numéro un entraîne le renommage de l'enregistrement numéro cinq en enregistrement numéro quatre, ainsi que le déplacement d'un enregistrement du curseur, s'il est positionné après l'enregistrement numéro un.

La structure de données spécifique à la méthode d'accès recno fournie à dbopen(3) est définie dans le fichier d'inclusion <db.h> comme suit :


typedef struct {
    unsigned long flags;
    unsigned int  cachesize;
    unsigned int  psize;
    int           lorder;
    size_t        reclen;
    unsigned char bval;
    char         *bfname;
} RECNOINFO;

Les éléments de cette structure sont définis comme suit :

flags
La valeur du drapeau est spécifiée en combinant (par OU) les valeurs suivantes :
R_FIXEDLEN
Les enregistrements sont de longueur fixe, non délimités par des octets. L'élément de structure reclen spécifie la longueur de l'enregistrement, et l'élément de structure bval est utilisé comme caractère de remplissage. Tous les enregistrements insérés dans la base de données qui ont moins de reclen octets sont automatiquement remplis.
R_NOKEY
Dans l'interface spécifiée par dbopen(3), la récupération séquentielle des enregistrements remplit les structures de clé et de données de l'appelant. Si le drapeau R_NOKEY est spécifié, les routines de curseur ne sont pas tenues de remplir la structure de clé. Cela permet aux applications de récupérer des enregistrements à la fin des fichiers sans lire tous les enregistrements intermédiaires.
R_SNAPSHOT
Ce drapeau exige qu'un instantané du fichier soit pris lors de l'appel à dbopen(3), au lieu de permettre la lecture de tous enregistrements non modifiés du fichier d'origine.
cachesize
Une taille maximale suggérée, en octets, pour le cache mémoire. Cette valeur est uniquement indicative, et la méthode d'accès allouera plus de mémoire plutôt qu'elle n'échouera. Si cachesize est 0 (aucune taille n'est spécifiée), un cache par défaut est utilisé.
psize
La méthode d'accès recno stocke les copies en mémoire de ses enregistrements dans un arbre binaire. Cette valeur est la taille (en octets) des pages utilisées pour les nœuds de cet arbre. Si psize est 0 (aucune taille de page n'est spécifiée), une taille de page est choisie en fonction de la taille du bloc d'E/S du système de fichiers sous-jacent. Voir btree(3) pour plus d'informations.
lorder
L'ordre des octets pour les entiers dans les métadonnées stockées de la base de données. Le nombre doit représenter l'ordre sous forme d'entier ; par exemple, l'ordre big endian serait le nombre 4 321. Si lorder est 0 (aucun ordre n'est spécifié), l'ordre de l'hôte actuel est utilisé.
reclen
La longueur d'un enregistrement de longueur fixe.
bval
L'octet délimiteur à utiliser pour marquer la fin d'un enregistrement pour les enregistrements de longueur variable, et le caractère de remplissage pour les enregistrements de longueur fixe. Si aucune valeur n'est spécifiée, les sauts de ligne ("\n") sont utilisés pour marquer la fin des enregistrements de longueur variable et les enregistrements de longueur fixe sont remplis avec des espaces.
bfname
La méthode d'accès recno stocke les copies en mémoire de ses enregistrements dans un arbre binaire. Si bfname n'est pas NULL, il spécifie le nom du fichier d'arbre binaire, comme s'il était spécifié comme nom de fichier pour un dbopen(3) d'un fichier d'arbre binaire.

La partie données de la paire clé/données utilisée par la méthode d'accès recno est la même que celle des autres méthodes d'accès. La clé est différente. Le champ data de la clé doit être un pointeur vers un emplacement mémoire de type recno_t, tel que défini dans le fichier d'inclusion <db.h>. Ce type est normalement le type intégral non signé le plus grand disponible pour l'implémentation. Le champ size de la clé doit être la taille de ce type.

Étant donné qu'il ne peut y avoir de métadonnées associées aux fichiers sous-jacents de la méthode d'accès recno, toutes les modifications apportées aux valeurs par défaut (par exemple, longueur d'enregistrement fixe ou valeur du séparateur d'octets) doivent être explicitement spécifiées chaque fois que le fichier est ouvert.

Dans l'interface spécifiée par dbopen(3), l'utilisation de l'interface put pour créer un nouvel enregistrement entraînera la création de plusieurs enregistrements vides si le numéro d'enregistrement est supérieur de plus d'un au plus grand enregistrement actuellement dans la base de données.

ERREURS

Les routines de la méthode d'accès recno peuvent échouer et définir errno pour toutes les erreurs spécifiées pour la routine de bibliothèque dbopen(3) ou les suivantes :

EINVAL
Une tentative a été faite pour ajouter un enregistrement à une base de données de longueur fixe qui était trop grande pour tenir.

BOGUES

Seuls les ordres d'octets big et little endian sont pris en charge.

VOIR AUSSI
