readdir_r(3) Manuel des fonctions de bibliothèque readdir_r(3)

NOM

readdir_r - lire un répertoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <dirent.h>
[[deprecated]] int readdir_r(DIR *restrict dirp,
                             struct dirent *restrict entry,
                             struct dirent **restrict result);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

readdir_r() :

    _POSIX_C_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Cette fonction est obsolète ; utilisez readdir(3) à la place.

La fonction readdir_r() a été inventée comme version réentrante de readdir(3). Elle lit la prochaine entrée de répertoire à partir du flux de répertoire dirp, et la renvoie dans le tampon alloué par l'appelant pointé par entry. Pour les détails de la structure dirent, voir readdir(3).

Un pointeur vers le tampon renvoyé est placé dans *result ; si la fin du flux de répertoire a été rencontrée, alors NULL est plutôt renvoyé dans *result.

Il est recommandé que les applications utilisent readdir(3) plutôt que readdir_r(). De plus, depuis glibc 2.24, glibc déprécie readdir_r(). Les raisons sont les suivantes :

•
Sur les systèmes où NAME_MAX est indéfini, appeler readdir_r() peut être dangereux car l'interface ne permet pas à l'appelant de spécifier la longueur du tampon utilisé pour l'entrée de répertoire renvoyée.
•
Sur certains systèmes, readdir_r() ne peut pas lire les entrées de répertoire avec des noms très longs. Lorsque l'implémentation glibc rencontre un tel nom, readdir_r() échoue avec l'erreur ENAMETOOLONG après que la dernière entrée de répertoire a été lue. Sur certains autres systèmes, readdir_r() peut renvoyer un statut de succès, mais le champ d_name renvoyé peut ne pas être terminé par null ou peut être tronqué.
•
Dans la spécification POSIX.1 actuelle (POSIX.1-2008), readdir(3) n'est pas obligatoirement thread-safe. Cependant, dans les implémentations modernes (y compris l'implémentation glibc), les appels concurrents à readdir(3) qui spécifient des flux de répertoires différents sont thread-safe. Par conséquent, l'utilisation de readdir_r() est généralement inutile dans les programmes multithreadés. Dans les cas où plusieurs threads doivent lire à partir du même flux de répertoire, utiliser readdir(3) avec une synchronisation externe reste préférable à l'utilisation de readdir_r(), pour les raisons données dans les points ci-dessus.
•
Il est prévu qu'une future version de POSIX.1 rende readdir_r() obsolète, et exige que readdir(3) soit thread-safe lorsqu'il est utilisé simultanément sur différents flux de répertoires.

VALEUR DE RETOUR

La fonction readdir_r() renvoie 0 en cas de succès. En cas d'erreur, elle renvoie un numéro d'erreur positif (listé sous ERREURS). Si la fin du flux de répertoire est atteinte, readdir_r() renvoie 0, et renvoie NULL dans *result.

ERREURS

EBADF
Descripteur de flux de répertoire dirp invalide.
ENAMETOOLONG
Une entrée de répertoire dont le nom était trop long pour être lu a été rencontrée.
