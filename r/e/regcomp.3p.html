PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

regcomp, regerror, regexec, regfree — correspondance d'expressions régulières

SYNOPSIS

#include <regex.h>
int regcomp(regex_t *restrict preg, const char *restrict pattern,
    int cflags);
size_t regerror(int errcode, const regex_t *restrict preg,
    char *restrict errbuf, size_t errbuf_size);
int regexec(const regex_t *restrict preg, const char *restrict string,
    size_t nmatch, regmatch_t pmatch[restrict], int eflags);
void regfree(regex_t *preg);

DESCRIPTION

Ces fonctions interprètent les expressions régulières de base et étendues telles que décrites dans le volume Base Definitions de POSIX.1‐2017, Chapitre 9, Expressions régulières.

La structure regex_t est définie dans <regex.h> et contient au moins le membre suivant :

Type de membre Nom du membre Description
size_t re_nsub Nombre d'expressions régulières parenthésées.

La structure regmatch_t est définie dans <regex.h> et contient au moins les membres suivants :

Type de membre Nom du membre Description
regoff_t rm_so Décalage en octets depuis le début de string jusqu'au début de la sous-chaîne.
regoff_t rm_eo Décalage en octets depuis le début de la chaîne du premier caractère après la fin de la sous-chaîne.

La fonction regcomp() compile l'expression régulière contenue dans la chaîne pointée par l'argument pattern et place les résultats dans la structure pointée par preg. L'argument cflags est le OU inclusif par bits de zéro ou plusieurs des indicateurs suivants, qui sont définis dans l'en-tête <regex.h> :

REG_EXTENDED
Utiliser les Expressions Régulières Étendues.
REG_ICASE
Ignorer la casse lors de la correspondance (voir le volume Base Definitions de POSIX.1‐2017, Chapitre 9, Expressions régulières).
REG_NOSUB
Rapporter uniquement succès/échec dans regexec().
REG_NEWLINE
Modifier la gestion des caractères de saut de ligne (<newline>), comme décrit dans le texte.

Le type d'expression régulière par défaut pour pattern est une Expression Régulière de Base. L'application peut spécifier des Expressions Régulières Étendues en utilisant l'indicateur cflags REG_EXTENDED.

Si l'indicateur REG_NOSUB n'était pas défini dans cflags, alors regcomp() définira re_nsub au nombre d'expressions régulières parenthésées (délimitées par "\(\)" dans les expressions régulières de base ou "()" dans les expressions régulières étendues) trouvées dans pattern.

La fonction regexec() compare la chaîne terminée par un caractère nul spécifiée par string avec l'expression régulière compilée preg initialisée par un appel précédent à regcomp(). Si elle trouve une correspondance, regexec() renverra 0 ; sinon, elle renverra une valeur non nulle indiquant soit aucune correspondance, soit une erreur. L'argument eflags est le OU inclusif par bits de zéro ou plusieurs des indicateurs suivants, qui sont définis dans l'en-tête <regex.h> :

REG_NOTBOL
Le premier caractère de la chaîne pointée par string n'est pas le début de la ligne. Par conséquent, le caractère <circonflexe> ('^'), lorsqu'il est pris comme caractère spécial, ne correspondra pas au début de string.
REG_NOTEOL
Le dernier caractère de la chaîne pointée par string n'est pas la fin de la ligne. Par conséquent, le <signe dollar> ('$'), lorsqu'il est pris comme caractère spécial, ne correspondra pas à la fin de string.

Si nmatch est 0 ou si REG_NOSUB a été défini dans l'argument cflags de regcomp(), alors regexec() ignorera l'argument pmatch. Sinon, l'application s'assurera que l'argument pmatch pointe vers un tableau avec au moins nmatch éléments, et regexec() remplira les éléments de ce tableau avec les décalages des sous-chaînes de string qui correspondent aux expressions régulières parenthésées de pattern : pmatch[i].rm_so sera le décalage en octets du début et pmatch[i].rm_eo sera un supérieur au décalage en octets de la fin de la sous-chaîne i. (L'expression régulière i commence au ième caractère parenthésé correspondant, en comptant à partir de 1.) Les décalages dans pmatch[0] identifient la sous-chaîne qui correspond à l'expression régulière entière. Les éléments inutilisés de pmatch jusqu'à pmatch[nmatch-1] seront remplis avec -1. S'il y a plus de nmatch expressions régulières dans pattern (pattern lui-même compte comme une expression régulière), alors regexec() effectuera quand même la correspondance, mais n'enregistrera que les nmatch premières sous-chaînes.

Lors de la correspondance d'une expression régulière de base ou étendue, toute expression régulière parenthésée donnée de pattern peut participer à la correspondance de plusieurs sous-chaînes différentes de string, ou elle peut ne pas correspondre à une sous-chaîne même si le modèle dans son ensemble correspond. Les règles suivantes doivent être utilisées pour déterminer les sous-chaînes à rapporter dans pmatch lors de la correspondance d'expressions régulières :

1.
Si l'expression régulière i dans une expression régulière n'est pas contenue dans une autre expression régulière, et qu'elle a participé à la correspondance plusieurs fois, alors les décalages en octets dans pmatch[i] délimiteront la dernière correspondance de ce type.
2.
Si l'expression régulière i n'est pas contenue dans une autre expression régulière, et qu'elle n'a pas participé à une correspondance sinon réussie, les décalages en octets dans pmatch[i] seront -1. Une expression régulière ne participe pas à la correspondance quand :
'*' ou "\{\}" apparaît immédiatement après l'expression régulière dans une expression régulière de base, ou '*', '?', ou "{}" apparaît immédiatement après l'expression régulière dans une expression régulière étendue, et que l'expression régulière n'a pas correspondu (correspondance de 0 fois)

ou :

'|' est utilisé dans une expression régulière étendue pour sélectionner cette expression régulière ou une autre, et que l'autre expression régulière a correspondu.
3.
Si l'expression régulière i est contenue dans une autre expression régulière j, et que i n'est pas contenue dans une autre expression régulière contenue dans j, et qu'une correspondance de l'expression régulière j est rapportée dans pmatch[j], alors la correspondance ou la non-correspondance de l'expression régulière i rapportée dans pmatch[i] sera telle que décrite dans 1. et 2. ci-dessus, mais dans la sous-chaîne rapportée dans pmatch[j] plutôt que dans la chaîne entière. Les décalages dans pmatch[i] sont toujours relatifs au début de string.
4.
Si l'expression régulière i est contenue dans l'expression régulière j, et que les décalages en octets dans pmatch[j] sont -1, alors les pointeurs dans pmatch[i] seront également -1.
5.
Si l'expression régulière i a correspondu à une chaîne de longueur zéro, alors les deux décalages en octets dans pmatch[i] seront le décalage en octets du cara

Si, lors de l'appel de regexec(), la locale est différente de celle lors de la compilation de l'expression régulière, le résultat est indéfini.

Si REG_NEWLINE n'est pas défini dans cflags, alors un <saut de ligne> dans pattern ou string sera traité comme un caractère ordinaire. Si REG_NEWLINE est défini, alors <saut de ligne> sera traité comme un caractère ordinaire, sauf comme suit :

1.
Un <saut de ligne> dans string ne sera pas mis en correspondance par un <point> en dehors d'une expression entre crochets ou par une forme de liste non correspondante (voir le volume des Définitions de base de POSIX.1-2017, Chapitre 9, Expressions Régulières).
2.
Un <circonflexe> ('^') dans pattern, lorsqu'il est utilisé pour spécifier l'ancrage d'expression (voir le volume des Définitions de base de POSIX.1-2017, Section 9.3.8, Ancrage d'expressions BRE), correspondra à la chaîne de longueur nulle immédiatement après un <saut de ligne> dans string, quelle que soit la valeur de REG_NOTBOL.
3.
Un <signe dollar> ('$') dans pattern, lorsqu'il est utilisé pour spécifier l'ancrage d'expression, correspondra à la chaîne de longueur nulle immédiatement avant un <saut de ligne> dans string, quelle que soit la valeur de REG_NOTEOL.

La fonction regfree() libère toute mémoire allouée par regcomp() associée à preg.

Les constantes suivantes sont définies comme le sous-ensemble minimum des valeurs de retour d'erreur, bien que d'autres erreurs listées comme extensions d'implémentation dans <regex.h> soient possibles :

REG_BADBR
Contenu de "\{\}" invalide : pas un nombre, nombre trop grand, plus de deux nombres, premier plus grand que le second.
REG_BADPAT
Expression régulière invalide.
REG_BADRPT
'?', '*', ou '+' non précédé par une expression régulière valide.
REG_EBRACE
Déséquilibre de "\{\}".
REG_EBRACK
Déséquilibre de "[]".
REG_ECOLLATE
Élément de classement invalide référencé.
REG_ECTYPE
Type de classe de caractères invalide référencé.
REG_EESCAPE
Caractère <backslash> final dans le modèle.
REG_EPAREN
Déséquilibre de "\(\)" ou "()".
REG_ERANGE
Point de terminaison invalide dans une expression de plage.
REG_ESPACE
Manque de mémoire.
REG_ESUBREG
Nombre dans "\chiffre" invalide ou en erreur.
REG_NOMATCH
regexec() n'a pas réussi à trouver de correspondance.

Si plusieurs erreurs se produisent lors du traitement d'un appel de fonction, l'une des constantes possibles peut être retournée, car l'ordre de détection n'est pas spécifié.

La fonction regerror() fournit un mappage des codes d'erreur retournés par regcomp() et regexec() à des chaînes imprimables non spécifiées. Elle génère une chaîne correspondant à la valeur de l'argument errcode, et l'application doit s'assurer qu'il s'agit de la dernière valeur non nulle retournée par regcomp() ou regexec() avec la valeur donnée de preg. Si errcode n'est pas une telle valeur, le contenu de la chaîne générée n'est pas spécifié.

Si preg est un pointeur nul, mais que errcode est une valeur retournée par un appel précédent à regexec() ou regcomp(), regerror() génère toujours une chaîne d'erreur correspondant à la valeur de errcode, mais elle peut ne pas être aussi détaillée selon l'implémentation.

Si l'argument errbuf_size n'est pas 0, regerror() placerat la chaîne générée dans le tampon de taille errbuf_size octets pointé par errbuf. Si la chaîne (y compris le caractère nul de terminaison) ne rentre pas dans le tampon, regerror() tronquera la chaîne et terminera le résultat par un caractère nul.

Si errbuf_size est 0, regerror() ignorera l'argument errbuf et retournera la taille du tampon nécessaire pour contenir la chaîne générée.

Si l'argument preg de regexec() ou regfree() n'est pas une expression régulière compilée retournée par regcomp(), le résultat est indéfini. Un preg n'est plus considéré comme une expression régulière compilée après avoir été passé à regfree().

VALEUR DE RETOUR

En cas de succès, la fonction regcomp() retournera 0. Sinon, elle retournera une valeur entière indiquant une erreur, comme décrit dans <regex.h>, et le contenu de preg est indéfini. Si un code est retourné, son interprétation sera celle donnée dans <regex.h>.

Si regcomp() détecte une RE invalide, elle peut retourner REG_BADPAT, ou elle peut retourner l'un des codes d'erreur qui décrivent plus précisément l'erreur.

En cas de succès, la fonction regexec() retournera 0. Sinon, elle retournera REG_NOMATCH pour indiquer l'absence de correspondance.

En cas de succès, la fonction regerror() retournera le nombre d'octets nécessaires pour contenir la chaîne générée entière, y compris la terminaison nulle. Si la valeur de retour est supérieure à errbuf_size, la chaîne retournée dans le tampon pointé par errbuf a été tronquée.

La fonction regfree() ne retourne pas de valeur.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

#include <regex.h>
/*
 * Met en correspondance la chaîne avec l'expression régulière étendue dans
 * pattern, en traitant les erreurs comme une absence de correspondance.
 *
 * Retourne 1 pour une correspondance, 0 pour aucune correspondance.
 */
int
match(const char *string, char *pattern)
{
    int    status;
    regex_t    re;
    if (regcomp(&re, pattern, REG_EXTENDED|REG_NOSUB) != 0) {
        return(0);      /* Signaler l'erreur. */
    }
    status = regexec(&re, string, (size_t) 0, NULL, 0);
    regfree(&re);
    if (status != 0) {
        return(0);      /* Signaler l'erreur. */
    }
    return(1);
}

L'exemple suivant montre comment le drapeau REG_NOTBOL peut être utilisé avec regexec() pour trouver toutes les sous-chaînes d'une ligne qui correspondent à un modèle fourni par l'utilisateur. (Pour simplifier l'exemple, très peu de vérification d'erreurs est effectuée.)

(void) regcomp (&re, pattern, 0);
/* Cet appel à regexec() trouve la première correspondance sur la ligne. */
error = regexec (&re, &buffer[0], 1, &pm, 0);
while (error == 0) {  /* Tant que des correspondances sont trouvées. */
    /* Sous-chaîne trouvée entre pm.rm_so et pm.rm_eo. */
    /* Cet appel à regexec() trouve la correspondance suivante. */
    error = regexec (&re, buffer + pm.rm_eo, 1, &pm, REG_NOTBOL);
}

UTILISATION PAR L'APPLICATION

Une application pourrait utiliser :

regerror(code,preg,(char *)NULL,(size_t)0)

pour connaître la taille du tampon nécessaire pour la chaîne générée, allouer de la mémoire avec malloc() pour contenir la chaîne, puis appeler regerror() à nouveau pour obtenir la chaîne. Alternativement, elle pourrait allouer un tampon fixe et statique suffisamment grand pour contenir la plupart des chaînes, puis utiliser malloc() pour allouer un tampon plus grand si elle constate que celui-ci est trop petit.

Pour faire correspondre un modèle comme décrit dans le volume Shell et Utilitaires de POSIX.1-2017, Section 2.13, Notation de correspondance de modèle, utilisez la fonction fnmatch().

RATIONALE

La fonction regexec() doit remplir tous les éléments nmatch de pmatch, où nmatch et pmatch sont fournis par l'application, même si certains éléments de pmatch ne correspondent pas à des sous-expressions dans pattern. Le développeur d'application doit noter qu'il n'y a probablement aucune raison d'utiliser une valeur de nmatch supérieure à preg->re_nsub+1.

Le drapeau REG_NEWLINE prend en charge une utilisation des correspondances RE qui est nécessaire dans certaines applications comme les éditeurs de texte. Dans de telles applications, l'utilisateur fournit une RE demandant à l'application de trouver une ligne qui correspond à l'expression donnée. Un ancre dans une telle RE s'ancre au début ou à la fin de n'importe quelle ligne. Une telle application peut passer une séquence de lignes séparées par des <sauts de ligne> à regexec() sous forme d'une seule longue chaîne et spécifier REG_NEWLINE à regcomp() pour obtenir le comportement souhaité. L'application doit s'assurer qu'il n'y a pas de caractères <saut de ligne> explicites dans pattern si elle souhaite garantir que toute correspondance se situe entièrement à l'intérieur d'une seule ligne.

Le drapeau REG_NEWLINE affecte le comportement de regexec(), mais il se trouve dans le paramètre cflags de regcomp() pour permettre la flexibilité d'implémentation. Certaines implémentations voudront générer la même RE compilée dans regcomp() indépendamment du réglage de REG_NEWLINE et laisser regexec() gérer les ancres différemment en fonction du réglage du drapeau. D'autres implémentations généreront des RE compilées différentes en fonction de REG_NEWLINE.

Le drapeau REG_ICASE prend en charge les opérations effectuées par l'option -i de grep et les implémentations historiques de ex et vi. L'inclusion de ce drapeau facilitera l'écriture de code d'application qui fait la même chose que ces utilitaires.

Les sous-chaînes rapportées dans pmatch[] sont définies à l'aide d'offsets par rapport au début de la chaîne plutôt que par des pointeurs. Cela permet un accès sécurisé en type aux chaînes constantes et non constantes.

Le type regoff_t est utilisé pour les éléments de pmatch[] afin de garantir que l'application peut représenter de grands tableaux en mémoire (important pour une application conforme au volume Shell et Utilitaires de POSIX.1-2017).

regcomp(3p) — REGEX API

PROLOG

This page is a translation of the POSIX `regcomp`, `regexec`, `regfree`, and `regerror` specification. It is a manual page for the POSIX Programmer's API. It is not, and is not intended to be, a manual page for any particular operating system.

NAME

regcomp, regexec, regfree, regerror - regular expression matching API

SYNOPSIS

#include <regex.h>

int regcomp(regex_t *preg, const char *pattern, int cflags);
int regexec(const regex_t *preg, const char *string, size_t nmatch, regmatch_t pmatch[], int eflags);
void regfree(regex_t *preg);
size_t regerror(int errcode, const regex_t *preg, char *errbuf, size_t errbuf_size);

DESCRIPTION

These functions implement the POSIX Extended Regular Expression (ERE) and Basic Regular Expression (BRE) matching. The functionality is defined by the POSIX.1‐2008 standard, Section 9.4, Regular Expression Matching.

The regcomp() function compiles the regular expression in the string pointed to by pattern into the structure pointed to by preg. The cflags argument is the bitwise OR of zero or more of the following flags:

REG_BASIC
Use Basic Regular Expression syntax.
REG_EXTENDED
Use Extended Regular Expression syntax.
REG_NOSUB
Do not report substring matches. If this flag is set, the pmatch argument to regexec() is ignored.
REG_NEWLINE
The character '.', any bracket expression, and the ‘^’ and ‘$’ anchors match the newline character \n in addition to other characters. By default, \n only matches \n.
REG_ICASE
Ignore case distinctions in the pattern and the string.
REG_NOSUB
Do not report substring matches. If this flag is set, the pmatch argument to regexec() is ignored.
REG_BADPAT
If the expression contains an invalid BRE syntax.
REG_ESPACE
If insufficient memory was available to create the internal buffer needed to hold the compiled regular expression.
REG_ECOLLATE
If the collating element supplied is invalid.
REG_ECTYPE
If the character class supplied is invalid.
REG_EESCAPE
If the backslash notation is not recognized.
REG_EBRACK
If the square bracketed section is invalid.
REG_BADALT
If the alternation construct is invalid.
REG_COMP
If an invalid command was encountered in the regular expression.
REG_SYNTAX
If the regular expression syntax is invalid.

The regexec() function compares the compiled regular expression preg against the string. If nmatch is not zero and REG_NOSUB is not set in cflags when regcomp was called, the pmatch array is filled with the location of the matched substrings. pmatch[0] is the location of the entire match, and pmatch[i] for i > 0 is the location of the i-th subexpression. The number of available subexpressions is stored in preg->re_nsub. The structure of regmatch_t is:

re_start
Offset to the start of the matched substring.
re_end
Offset to the character immediately following the matched substring.

The eflags argument is the bitwise OR of zero or more of the following flags:

REG_NOTBOL
The beginning of the string is not considered to be the beginning of a line. By default, the ‘^’ anchor matches the beginning of the string.
REG_NOTEOL
The end of the string is not considered to be the end of a line. By default, the ‘$’ anchor matches the end of the string.

The regfree() function frees the memory allocated by regcomp().

The regerror() function returns a human-readable string describing the error code errcode into the buffer pointed to by errbuf with a maximum size of errbuf_size. If preg is not NULL, it is used to provide context for the error message. If errbuf_size is 0, regerror() will return the required size of the buffer without copying any data. If the error code is not recognized, an implementation-defined string is returned.

RETURN VALUE

regcomp() returns 0 on success, or an error code otherwise. The error code is one of the values listed for cflags above, or REG_ENOSYS if the implementation does not support the requested regular expression syntax.

regexec() returns 0 on a successful match, REG_NOMATCH if no match is found, or an error code otherwise. The error code is one of the values listed for cflags above, or REG_ENOSYS if the implementation does not support the requested regular expression syntax.

regerror() returns the number of characters that would be written to the buffer, including the terminating null byte.

ERRORS

regcomp() may fail and set one of the following error codes in preg->re_errno (accessible via regerror()):

REG_EBRACK
Invalid bracket expression.
REG_EBRACK
Invalid bracket expression.
REG_ECOLLATE
Invalid collating element.
REG_ECTYPE
Invalid character class.
REG_EESCAPE
Invalid escape sequence.
REG_EJUSTNS
Invalid repetition count.
REG_ENOENT
No matched substring.
REG_ENOSYS
Function not implemented.
REG_EPAREN
Mismatched parentheses.
REG_ESLASH
Trailing backslash.
REG_ESUBREG
Invalid substring reference.
REG_EUNKCHAR
Unknown character.
REG_ESPACE
Out of memory.
REG_SYNTAX
Invalid syntax.

regexec() may fail and set one of the following error codes in preg->re_errno (accessible via regerror()):

REG_BADPAT
Invalid regular expression.
REG_ESPACE
Out of memory.
REG_INVARG
Invalid argument.
REG_NOMATCH
No match found.

EXAMPLES

Compile a regular expression:

    regex_t regex;
    int reti = regcomp(&regex, "([a-z]+) ([0-9]+)", REG_EXTENDED);
    if (reti) {
        fprintf(stderr, "Could not compile regex\n");
        exit(EXIT_FAILURE);
    }

Execute a regular expression:

    regmatch_t match[3]; // 1 for whole match, 2 for subexpressions
    int reti = regexec(&regex, "hello 123", 3, match, 0);
    if (!reti) {
        printf("Match found.\n");
        // match[0] is the whole match "hello 123"
        // match[1] is the first subexpression "hello"
        // match[2] is the second subexpression "123"
    } else if (reti == REG_NOMATCH) {
        printf("No match found.\n");
    } else {
        fprintf(stderr, "Regex match failed: %d\n", reti);
    }

Free the compiled regular expression:

    regfree(&regex);

Get an error message:

    char errbuf[256];
    size_t errbuf_size = regerror(REG_BADPAT, NULL, errbuf, sizeof(errbuf));
    printf("Error message: %s\n", errbuf);

APPLICATION USAGE

Applications should always check the return value of regcomp() and regexec(). If an error occurs, the application can use regerror() to obtain a human-readable error message.

The regfree() function should be called to free any memory allocated by regcomp() when the compiled regular expression is no longer needed.

RATIONALE

The initial proposal for POSIX regular expressions was based on the functionality provided by the Bell System's `regexp` library. However, the POSIX standard aimed to provide a more robust and portable interface. Several design decisions were made to achieve this goal.

The standard developers rejected the inclusion of a regsub() function that would be used to do substitutions for a matched RE. While such a routine would be useful to some applications, its utility would be much more limited than the matching function described here. Both RE parsing and substitution are possible to implement without support other than that required by the ISO C standard, but matching is much more complex than substituting. The only difficult part of substitution, given the information supplied by regexec(), is finding the next character in a string when there can be multi-byte characters. That is a much larger issue, and one that needs a more general solution.

The errno variable has not been used for error returns to avoid filling the errno name space for this feature.

The interface is defined so that the matched substrings rm_sp and rm_ep are in a separate regmatch_t structure instead of in regex_t. This allows a single compiled RE to be used simultaneously in several contexts; in main() and a signal handler, perhaps, or in multiple threads of lightweight processes. (The preg argument to regexec() is declared with type const, so the implementation is not permitted to use the structure to store intermediate results.) It also allows an application to request an arbitrary number of substrings from an RE. The number of subexpressions in the RE is reported in re_nsub in preg. With this change to regexec(), consideration was given to dropping the REG_NOSUB flag since the user can now specify this with a zero nmatch argument to regexec(). However, keeping REG_NOSUB allows an implementation to use a different (perhaps more efficient) algorithm if it knows in regcomp() that no subexpressions need be reported. The implementation is only required to fill in pmatch if nmatch is not zero and if REG_NOSUB is not specified. Note that the size_t type, as defined in the ISO C standard, is unsigned, so the description of regexec() does not need to address negative values of nmatch.

REG_NOTBOL was added to allow an application to do repeated searches for the same pattern in a line. If the pattern contains a <circumflex> character that should match the beginning of a line, then the pattern should only match when matched against the beginning of the line. Without the REG_NOTBOL flag, the application could rewrite the expression for subsequent matches, but in the general case this would require parsing the expression. The need for REG_NOTEOL is not as clear; it was added for symmetry.

The addition of the regerror() function addresses the historical need for conforming application programs to have access to error information more than ``Function failed to compile/match your RE for unknown reasons''.

This interface provides for two different methods of dealing with error conditions. The specific error codes (REG_EBRACE, for example), defined in <regex.h>, allow an application to recover from an error if it is so able. Many applications, especially those that use patterns supplied by a user, will not try to deal with specific error cases, but will just use regerror() to obtain a human-readable error message to present to the user.

The regerror() function uses a scheme similar to confstr() to deal with the problem of allocating memory to hold the generated string. The scheme used by strerror() in the ISO C standard was considered unacceptable since it creates difficulties for multi-threaded applications.

The preg argument is provided to regerror() to allow an implementation to generate a more descriptive message than would be possible with errcode alone. An implementation might, for example, save the character offset of the offending character of the pattern in a field of preg, and then include that in the generated message string. The implementation may also ignore preg.

A REG_FILENAME flag was considered, but omitted. This flag caused regexec() to match patterns as described in the Shell and Utilities volume of POSIX.1‐2017, Section 2.13, Pattern Matching Notation instead of REs. This service is now provided by the fnmatch() function.

Notice that there is a difference in philosophy between the ISO POSIX‐2:1993 standard and POSIX.1‐2008 in how to handle a ``bad'' regular expression. The ISO POSIX‐2:1993 standard says that many bad constructs ``produce undefined results'', or that ``the interpretation is undefined''. POSIX.1‐2008, however, says that the interpretation of such REs is unspecified. The term ``undefined'' means that the action by the application is an error, of similar severity to passing a bad pointer to a function.

The regcomp() and regexec() functions are required to accept any null-terminated string as the pattern argument. If the meaning of the string is ``undefined'', the behavior of the function is ``unspecified''. POSIX.1‐2008 does not specify how the functions will interpret the pattern; they might return error codes, or they might do pattern matching in some completely unexpected way, but they should not do something like abort the process.
