repo-forall(1)

Paquet: repo

Licences: Apache-2.0

REPO(1) Manuel Repo REPO(1)

NOM

repo - repo forall - page de manuel pour repo forall

SYNTAXE

repo forall [<projet>...] -c <commande> [<arg>...]

DESCRIPTION

Résumé

Exécute une commande shell dans chaque projet.

repo forall -r str1 [str2] ... -c <commande> [<arg>...]

OPTIONS

-h, --help
afficher cette aide et quitter
-j JOBS, --jobs=JOBS
nombre de tâches à exécuter en parallèle (défaut : basé sur le nombre de cœurs CPU)
-r, --regex
exécuter la commande uniquement sur les projets correspondant à l'expression régulière ou au motif joker
-i, --inverse-regex
exécuter la commande uniquement sur les projets ne correspondant pas à l'expression régulière ou au motif joker
-g GROUPES, --groups=GROUPES
exécuter la commande uniquement sur les projets correspondant aux groupes spécifiés
-c, --command
commande (et arguments) à exécuter
-e, --abort-on-errors
abandonner si une commande se termine sans succès
--ignore-missing
ignorer silencieusement et ne pas sortir avec un code non nul en cas de non-trouvage de checkout
--interactive
forcer l'utilisation interactive

Options de journalisation :

-v, --verbose
afficher toutes les sorties
-q, --quiet
afficher uniquement les erreurs
-p
afficher les en-têtes de projet avant la sortie

Options multi-manifeste :

--outer-manifest
opérer à partir du manifeste le plus externe
--no-outer-manifest
ne pas opérer sur les manifestes externes
--this-manifest-only
opérer uniquement sur ce manifeste (sous-manifeste)
--no-this-manifest-only, --all-manifests
opérer sur ce manifeste et ses sous-manifestes

Exécutez `repo help forall` pour voir le manuel détaillé.

DÉTAILS

Exécute la même commande shell dans chaque projet.

L'option -r permet d'exécuter la commande uniquement sur les projets correspondant à une expression régulière ou à un motif joker.

Par défaut, les projets sont traités de manière non interactive en parallèle. Si vous souhaitez exécuter des commandes interactives, assurez-vous de passer --interactive pour forcer --jobs 1. Bien que l'ordre de traitement des projets ne soit pas garanti, l'ordre de la sortie des projets est stable.

Formatage de la sortie

L'option -p fait en sorte que 'repo forall' lie les pipes aux flux stdin, stdout et stderr de la commande, et redirige toute la sortie dans un flux continu qui est affiché dans une seule session de pagination. Les en-têtes de projet sont insérés avant que la sortie de chaque commande ne soit affichée. Si la commande ne produit aucune sortie dans un projet, aucun en-tête n'est affiché.

La convention de formatage utilisée par -p est très adaptée à certains types de recherche, par exemple `repo forall -p -c git log -SFoo` affichera tous les commits qui ajoutent ou suppriment des références à Foo.

L'option -v fait en sorte que 'repo forall' affiche les messages stderr si une commande produit une sortie uniquement sur stderr. Normalement, l'option -p fait en sorte que la sortie de la commande soit supprimée jusqu'à ce que la commande produise au moins un octet de sortie sur stdout.

Environnement

pwd est le répertoire de travail du projet. Si le client actuel est un client miroir, alors pwd est le dépôt Git.

REPO_PROJECT est défini sur le nom unique du projet.

REPO_PATH est le chemin relatif à la racine du client.

REPO_OUTERPATH est le chemin de la racine du sous-manifeste par rapport à la racine du client.

REPO_INNERPATH est le chemin relatif à la racine du sous-manifeste.

REPO_REMOTE est le nom du système distant du manifeste.

REPO_LREV est le nom de la révision du manifeste, traduit en une branche de suivi locale. Si vous avez besoin de passer la révision du manifeste à une commande git exécutée localement, utilisez REPO_LREV.

REPO_RREV est le nom de la révision du manifeste, tel qu'écrit dans le manifeste.

REPO_COUNT est le nombre total de projets en cours d'itération.

REPO_I est le compteur d'itération actuel (basé sur 1). Peut être utilisé en conjonction avec REPO_COUNT pour ajouter un simple indicateur de progression à votre commande.

REPO__* sont toutes variables d'environnement supplémentaires, spécifiées par l'élément "annotation" sous tout élément de projet. Cela peut être utile pour différencier les arbres en fonction de critères spécifiques à l'utilisateur, ou simplement pour annoter les détails de l'arbre.

Les arguments positionnels du shell ($1, $2, .., $#) sont définis par les arguments suivant <commande>.

Exemple : pour lister les projets :

repo forall -c 'echo $REPO_PROJECT'

Notez que $REPO_PROJECT est entre guillemets pour s'assurer qu'il est développé dans le contexte de l'exécution de <commande> au lieu d'être développé dans le shell appelant.

Sauf si -p est utilisé, stdin, stdout, stderr sont hérités du terminal et ne sont pas redirigés.

Si -e est utilisé, lorsqu'une commande se termine sans succès, 'repo forall' abandonnera sans itérer sur les projets restants.
