readahead(2) Manuel des appels système readahead(2)

NOM

readahead - initier la pré-lecture d'un fichier dans le cache de pages

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#define _FILE_OFFSET_BITS 64
#include <fcntl.h>
ssize_t readahead(int fd, off_t offset, size_t count);

DESCRIPTION

readahead() initie une pré-lecture sur un fichier afin que les lectures ultérieures de ce fichier soient satisfaites depuis le cache, et ne bloquent pas sur les entrées/sorties disque (en supposant que la pré-lecture a été initiée suffisamment tôt et que les autres activités sur le système n'ont pas entre-temps vidé les pages du cache).

L'argument fd est un descripteur de fichier identifiant le fichier à lire. L'argument offset spécifie le point de départ à partir duquel les données doivent être lues et count spécifie le nombre d'octets à lire. Les entrées/sorties sont effectuées par pages entières, de sorte que offset est effectivement arrondi à la limite de page inférieure et les octets sont lus jusqu'à la limite de page supérieure égale ou supérieure à (offset+count). readahead() ne lit pas au-delà de la fin du fichier. Le décalage du fichier de la description de fichier référencée par le descripteur de fichier fd reste inchangé.

VALEUR DE RETOUR

En cas de succès, readahead() renvoie 0 ; en cas d'échec, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide ou n'est pas ouvert en lecture.
EINVAL
fd ne fait pas référence à un type de fichier auquel readahead() peut être appliqué.

VERSIONS

Sur certaines architectures 32 bits, la signature de l'appelant pour cet appel système diffère, pour les raisons décrites dans syscall(2).

NORMES

Linux.

HISTORIQUE

Linux 2.4.13, glibc 2.3.

NOTES

_FILE_OFFSET_BITS doit être défini à 64 dans le code qui utilise un pointeur vers readahead, si le code est destiné à être portable vers les plateformes x86 et ARM 32 bits traditionnelles où la largeur de off_t est par défaut de 32 bits.

BOGUES

readahead() tente de planifier les lectures en arrière-plan et de retourner immédiatement. Cependant, il peut bloquer pendant qu'il lit les métadonnées du système de fichiers nécessaires pour localiser les blocs demandés. Cela se produit fréquemment avec ext[234] sur de gros fichiers utilisant des blocs indirects au lieu d'extents, donnant l'apparence que l'appel bloque jusqu'à ce que les données demandées aient été lues.

VOIR AUSSI

lseek(2), madvise(2), mmap(2), posix_fadvise(2), read(2)
