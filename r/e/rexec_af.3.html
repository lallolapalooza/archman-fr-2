rexec(3) Manuel des fonctions de bibliothèque rexec(3)

NOM

rexec, rexec_af - retourner un flux vers une commande distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <netdb.h>
[[deprecated]]
int rexec(char **restrict ahost, int inport,
          const char *restrict user, const char *restrict passwd,
          const char *restrict cmd, int *restrict fd2p);
[[deprecated]]
int rexec_af(char **restrict ahost, int inport,
          const char *restrict user, const char *restrict passwd,
          const char *restrict cmd, int *restrict fd2p,
          sa_family_t af);

rexec(), rexec_af():

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    Dans glibc jusqu'à et y compris 2.19 :
        _BSD_SOURCE

DESCRIPTION

Cette interface est obsolète et remplacée par rcmd(3).

La fonction rexec() recherche l'hôte *ahost en utilisant gethostbyname(3), et retourne -1 si l'hôte n'existe pas. Sinon, *ahost est défini sur le nom standard de l'hôte. Si un nom d'utilisateur et un mot de passe sont tous deux spécifiés, ils sont utilisés pour s'authentifier auprès de l'hôte étranger ; sinon, l'environnement puis le fichier .netrc dans le répertoire personnel de l'utilisateur sont recherchés pour obtenir les informations appropriées. Si tout cela échoue, l'utilisateur est invité à fournir les informations.

Le port inport spécifie quel port Internet DARPA bien connu utiliser pour la connexion ; l'appel getservbyname("exec", "tcp") (voir getservent(3)) retournera un pointeur vers une structure contenant le port nécessaire. Le protocole de connexion est décrit en détail dans rexecd(8).

Si la connexion réussit, un socket dans le domaine Internet de type SOCK_STREAM est retourné à l'appelant et fourni à la commande distante en tant que stdin et stdout. Si fd2p n'est pas nul, alors un canal auxiliaire vers un processus de contrôle sera mis en place, et un descripteur de fichier pour celui-ci sera placé dans *fd2p. Le processus de contrôle retournera les messages de diagnostic de la commande (unité 2) sur ce canal, et acceptera également des octets sur ce canal en tant que numéros de signaux UNIX, à transmettre au groupe de processus de la commande. Les informations de diagnostic retournées n'incluent pas l'échec d'autorisation distante, car la connexion secondaire est établie après vérification de l'autorisation. Si fd2p est 0, alors le stderr (unité 2 de la commande distante) sera identique au stdout et aucune disposition n'est prise pour envoyer des signaux arbitraires au processus distant, bien que vous puissiez être en mesure d'attirer son attention en utilisant des données hors bande.

rexec_af()

La fonction rexec() fonctionne sur IPv4 (AF_INET). En revanche, la fonction rexec_af() fournit un argument supplémentaire, af, qui permet à l'appelant de sélectionner le protocole. Cet argument peut être spécifié comme AF_INET, AF_INET6, ou AF_UNSPEC (pour permettre à l'implémentation de sélectionner le protocole).

HISTORIQUE

rexec()
4.2BSD, BSD, Solaris.

glibc 2.2.

BOGUES

La fonction rexec() envoie le mot de passe non chiffré sur le réseau.

Le service sous-jacent est considéré comme un gros problème de sécurité, et par conséquent, il n'est pas activé sur de nombreux sites ; voir rexecd(8) pour des explications.

VOIR AUSSI
