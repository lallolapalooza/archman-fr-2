RECOVER(6) Manuel des Jeux RECOVER(6)

NOM

recover - récupérer une partie de NetHack interrompue par un désastre

SYNTAXE

recover [ -d répertoire ] base1 base2 ...

DESCRIPTION

Occasionnellement, une partie de NetHack peut être interrompue par un désastre lorsque le jeu ou le système plante. Avant NetHack v3.1, ces parties étaient perdues car diverses informations comme l'inventaire du joueur n'étaient conservées qu'en mémoire. Désormais, toutes les informations pertinentes peuvent être écrites sur disque, permettant ainsi de récupérer ces parties au moment du dernier changement de niveau.

Les options base indiquent à recover quels fichiers traiter. Chaque option base spécifie la récupération d'une partie distincte.

L'option -d, qui doit être le premier argument s'il apparaît, fournit un répertoire qui est l'aire de jeu de NetHack. Elle remplace la valeur de NETHACKDIR, HACKDIR, ou le répertoire spécifié par l'administrateur du jeu lors de la compilation (généralement /usr/games/lib/nethackdir).

Pour que la récupération soit possible, nethack doit avoir été compilé avec l'option INSURANCE, et l'option d'exécution checkpoint doit également avoir été activée. NetHack écrit normalement les fichiers des niveaux au fur et à mesure que le joueur les quitte, de sorte qu'ils soient prêts pour les visites ultérieures. Lors de la mise en point de contrôle, NetHack écrit également le niveau entré et l'état actuel de la partie à chaque changement de niveau. Cela ralentit naturellement un peu les changements de niveau.

Les noms des fichiers de niveau sont de la forme base.nn, où nn est un numéro de suivi interne pour le niveau. Le fichier base.0 est utilisé pour l'identité de la partie, le verrouillage, et, lors de la mise en point de contrôle, pour l'état de la partie. Divers systèmes d'exploitation utilisent différentes stratégies pour construire le nom de base. Les micro-ordinateurs utilisent le nom du personnage, potentiellement tronqué et modifié pour être un nom de fichier légal sur ce système. Les systèmes multi-utilisateurs utilisent le nom du personnage (modifié) précédé d'un numéro d'utilisateur pour éviter les conflits, ou "xlock" si le nombre de joueurs simultanés est limité. Il peut être nécessaire de chercher dans l'aire de jeu pour trouver le nom de base correct de la partie interrompue. recover transformera ces fichiers de niveau en un fichier de sauvegarde portant le même nom que nethack utiliserait.

Étant donné que recover doit pouvoir lire et supprimer des fichiers de l'aire de jeu et créer des fichiers dans le répertoire de sauvegarde, il a des interactions intéressantes avec la sécurité du jeu. Donner aux joueurs ordinaires un accès à recover via setuid ou setgid équivaut à laisser l'aire de jeu inscriptible par tous, tant pour la triche que pour perturber les autres joueurs. Pour un système mono-utilisateur, cela ne change rien, bien sûr, c'est pourquoi certains ports pour micro-ordinateurs installent recover par défaut.

Pour un système multi-utilisateurs, l'administrateur du jeu peut vouloir organiser pour que tous les fichiers .0 de l'aire de jeu soient alimentés à recover au démarrage de la machine hôte, et gérer les plantages de jeu individuellement. Si la population d'utilisateurs est suffisamment digne de confiance, recover peut être installé avec les mêmes permissions que l'exécutable nethack. Dans les deux cas, recover est facilement compilable à partir du répertoire utilitaire de distribution.

NOTES

Comme nethack lui-même, recover écrasera les fichiers de sauvegarde existants du même nom. Les fichiers de sauvegarde créés par recover ne sont pas compressés ; ils peuvent être compressés par la suite si désiré, mais même un nethack utilisant la compression les trouvera sous leur forme non compressée.

VOIR AUSSI

nethack(6)

BOGUES

recover ne tente pas de vérifier si un nom de base spécifie une partie en cours. Si plusieurs machines partagent une aire de jeu, cela serait impossible à déterminer.

recover devrait être modifié pour utiliser le mécanisme de verrouillage de l'aire de jeu de nethack afin d'éviter les conflits.
