READLINE(3) Manuel des fonctions de bibliothèque READLINE(3)

NOM

readline - obtenir une ligne d'un utilisateur avec édition

SYNTAXE

#include <stdio.h>
#include <readline/readline.h>
#include <readline/history.h>
char *
readline (const char *prompt);

DROIT D'AUTEUR

Readline est Copyright (C) 1989-2025 Free Software Foundation, Inc.

DESCRIPTION

readline lit une ligne depuis le terminal et la retourne, en utilisant prompt comme invite. Si prompt est NULL ou une chaîne vide, readline n'affiche pas d'invite. La ligne retournée est allouée avec malloc(3) ; l'appelant doit la libérer lorsqu'il a terminé. La ligne retournée a la nouvelle ligne finale supprimée, donc seul le texte de la ligne reste. Comme il est possible d'entrer des caractères dans la ligne en les guillemetant pour désactiver toute fonction d'édition readline qu'ils pourraient normalement avoir, cette ligne peut inclure des nouvelles lignes embarquées et d'autres caractères spéciaux.

readline offre des capacités d'édition pendant que l'utilisateur saisit la ligne. Par défaut, les commandes d'édition de ligne sont similaires à celles d'emacs. Une interface d'édition de ligne de style vi est également disponible.

Cette page de manuel décrit uniquement l'utilisation la plus basique de readline. Beaucoup plus de fonctionnalités sont disponibles ; voir The GNU Readline Library et The GNU History Library pour des informations supplémentaires.

VALEUR DE RETOUR

readline retourne le texte de la ligne lue. Une ligne vide retourne la chaîne vide. Si EOF est rencontré lors de la lecture d'une ligne, et que la ligne est vide, readline retourne NULL. Si un EOF est lu avec une ligne non vide, il est traité comme une nouvelle ligne.

NOTATION

Cette section utilise des concepts d'édition de style Emacs et emploie sa notation pour les frappes de touches. Les touches de contrôle sont dénommées par C-touche, par exemple, C-n signifie Control-N. De même, les touches meta sont dénominées par M-touche, donc M-x signifie Meta-X. La touche Meta est souvent étiquetée « Alt » ou « Option ».

Sur les claviers sans touche Meta, M-x signifie ESC x, c'est-à-dire appuyez et relâchez la touche Échap, puis appuyez et relâchez la touche x, en séquence. Cela fait d'ESC le préfixe méta. La combinaison M-C-x signifie ESC Control-x : appuyez et relâchez la touche Échap, puis maintenez la touche Contrôle enfoncée tout en appuyant sur la touche x, puis relâchez les deux.

Sur certains claviers, le modificateur Meta produit des caractères avec le huitième bit (0200) défini. Vous pouvez utiliser la variable enable-meta-key pour contrôler si c'est le cas, si le clavier le permet. Sur beaucoup d'autres, le terminal ou l'émulateur de terminal convertit la touche métamorphe en une séquence de touches commençant par ESC comme décrit au paragraphe précédent.

Si votre touche Meta produit une séquence de touches avec le préfixe méta ESC, vous pouvez faire en sorte que les liaisons de touches M-touche que vous spécifiez (voir Liaisons de touches Readline ci-dessous) fassent la même chose en définissant la variable force-meta-prefix.

Les commandes Readline peuvent recevoir des arguments numériques, qui agissent normalement comme un compteur de répétition. Parfois, cependant, c'est le signe de l'argument qui est significatif. Passer un argument négatif à une commande qui agit dans le sens avant (par exemple, kill-line) fait agir cette commande dans le sens arrière. Les commandes dont le comportement avec des arguments dévie de ceci sont notées ci-dessous.

Le point est la position actuelle du curseur, et la marque fait référence à une position de curseur enregistrée. Le texte entre le point et la marque est appelé la région.

Lorsqu'une commande est décrite comme tuant du texte, le texte supprimé est sauvegardé pour une récupération future éventuelle (yankage). Le texte tué est sauvegardé dans un anneau de tuerie. Les tueries consécutives accumulent le texte supprimé en une seule unité, qui peut être récupérée en une seule fois. Les commandes qui ne tuent pas de texte séparent les fragments de texte sur l'anneau de tuerie.

FICHIER D'INITIALISATION

Readline est personnalisé en plaçant des commandes dans un fichier d'initialisation (le fichier inputrc). Le nom de ce fichier est tiré de la valeur de la variable d'environnement INPUTRC. Si cette variable n'est pas définie, la valeur par défaut est ~/.inputrc. Si ce fichier n'existe pas ou ne peut être lu, readline recherche /etc/inputrc. Lorsqu'un programme qui utilise la bibliothèque readline démarre, readline lit le fichier d'initialisation et définit les liaisons de touches et les variables qui s'y trouvent, avant de lire toute entrée utilisateur.

Il n'y a que quelques constructions de base autorisées dans le fichier inputrc. Les lignes vides sont ignorées. Les lignes commençant par un # sont des commentaires. Les lignes commençant par un $ indiquent des constructions conditionnelles. D'autres lignes dénotent des liaisons de touches et des paramètres de variables.

Les liaisons de touches par défaut dans ce document peuvent être modifiées en utilisant des commandes de liaison de touches dans le fichier inputrc. Les programmes qui utilisent cette bibliothèque peuvent ajouter leurs propres commandes et liaisons.

Par exemple, placer

M-Control-u: universal-argument

ou
C-Meta-u: universal-argument

dans le fichier inputrc ferait que M-C-u exécute la commande readline universal-argument.

Les liaisons de touches peuvent contenir les noms de caractères symboliques suivants : DEL, ESC, ESCAPE, LFD, NEWLINE, RET, RETURN, RUBOUT (une backspace destructrice), SPACE, SPC, et TAB.

En plus des noms de commandes, readline permet de lier des touches à une chaîne qui est insérée lorsque la touche est pressée (une macro). La différence entre une macro et une commande est qu'une macro est entourée de guillemets simples ou doubles.

Liaisons de touches

La syntaxe pour contrôler les liaisons de touches dans le fichier inputrc est simple. Tout ce qui est requis est le nom de la commande ou le texte d'une macro et une séquence de touches à laquelle elle doit être liée. La séquence de touches peut être spécifiée de l'une des deux manières suivantes : comme un nom de touche symbolique, éventuellement avec des préfixes Meta- ou Control-, ou comme une séquence de touches composée d'un ou plusieurs caractères entourés de guillemets doubles. La séquence de touches et le nom sont séparés par un deux-points. Il ne peut y avoir d'espace entre le nom et le deux-points.

Lorsqu'on utilise la forme nomtouche:nomfonction ou macro, nomtouche est le nom d'une touche épelé en anglais. Par exemple :

Control-u: universal-argument
Meta-Rubout: backward-kill-word
Control-o: "> output"

Dans l'exemple ci-dessus, C-u est lié à la fonction universal-argument, M-DEL est lié à la fonction backward-kill-word, et C-o est lié à l'exécution de la macro exprimée dans le membre de droite (c'est-à-dire, pour insérer le texte « > output » dans la ligne).

Dans la deuxième forme, "seqtouche":nomfonction ou macro, seqtouche diffère de nomtouche ci-dessus en ce que les chaînes dénotant une séquence de touches entière peuvent être spécifiées en plaçant la séquence entre guillemets doubles. Certains échappements de style GNU Emacs peuvent être utilisés, comme dans l'exemple suivant, mais aucun des noms de caractères symboliques n'est reconnu.

"\C-u": universal-argument
"\C-x\C-r": re-read-init-file
"\e[11~": "Function Key 1"

Dans cet exemple, C-u est à nouveau lié à la fonction universal-argument. C-x C-r est lié à la fonction re-read-init-file, et ESC [ 1 1 ~ est lié à l'insertion du texte « Function Key 1 ».

L'ensemble complet des séquences d'échappement de style GNU Emacs disponibles lors de la spécification des séquences de touches est

\C-
Un préfixe de contrôle.
\M-
Ajout du préfixe meta ou conversion du caractère suivant en caractère meta, comme décrit ci-dessous sous force-meta-prefix.
\e
Un caractère d'échappement.
\\
Antislash.
\"
Guillemet double littéral.
\'
Guillemet simple littéral.

LUA_READLINE_FUNCTIONS

In addition to the GNU Emacs style escape sequences, a second set of backslash escapes is available:

\a
alerte (sonnerie)
\b
retour arrière
\d
supprimer
\f
saut de page
\n
nouvelle ligne
\r
retour chariot
\t
tabulation horizontale
\v
tabulation verticale
\nnn
Le caractère huit bits dont la valeur est la valeur octale nnn (un à trois chiffres).
\xHH
Le caractère huit bits dont la valeur est la valeur hexadécimale HH (un ou deux chiffres hexadécimaux).

Lors de la saisie du texte d'une macro, des apostrophes ou des guillemets doivent être utilisés pour indiquer une définition de macro. Le texte non cité est supposé être un nom de fonction. Les échappements par antislash décrits ci-dessus sont développés dans le corps de la macro. L'antislash échappe tout autre caractère dans le texte de la macro, y compris “ et '.

Bash affichera ou modifiera les liaisons de touches readline actuelles avec la commande intégrée bind. Les options -o emacs ou -o vi de la commande intégrée set modifient le mode d'édition pendant l'utilisation interactive. D'autres programmes utilisant cette bibliothèque fournissent des mécanismes similaires. Un utilisateur peut toujours modifier le fichier inputrc et faire en sorte que readline le relise si un programme ne fournit aucun autre moyen d'intégrer de nouvelles liaisons.

Variables

Readline dispose de variables qui peuvent être utilisées pour personnaliser davantage son comportement. Une variable peut être définie dans le fichier inputrc avec une instruction de la forme

set nom-variable valeur

Sauf indication contraire, les variables readline peuvent prendre les valeurs On ou Off (sans tenir compte de la casse). Les noms de variables non reconnus sont ignorés. Lorsque readline lit la valeur d'une variable, les valeurs vides ou nulles, “on” (insensible à la casse) et “1” sont équivalents à On. Toutes les autres valeurs sont équivalentes à Off.

Les variables et leurs valeurs par défaut sont :

active-region-start-color
Une variable de chaîne qui contrôle la couleur du texte et de l'arrière-plan lors de l'affichage du texte dans la région active (voir la description de enable-active-region ci-dessous). Cette chaîne ne doit pas occuper d'espace caractère physique sur l'affichage, elle doit donc se composer uniquement de séquences d'échappement de terminal. Elle est envoyée au terminal avant d'afficher le texte dans la région active. Cette variable est réinitialisée à sa valeur par défaut chaque fois que le type de terminal change. La valeur par défaut est la chaîne qui met le terminal en mode standout, telle qu'obtenue à partir de la description terminfo du terminal. Une valeur d'exemple pourrait être “\e[01;33m”.
active-region-end-color
Une variable de chaîne qui “annule” les effets de active-region-start-color et restaure l'apparence d'affichage de terminal “normale” après l'affichage du texte dans la région active. Cette chaîne ne doit pas occuper d'espace caractère physique sur l'affichage, elle doit donc se composer uniquement de séquences d'échappement de terminal. Elle est envoyée au terminal après l'affichage du texte dans la région active. Cette variable est réinitialisée à sa valeur par défaut chaque fois que le type de terminal change. La valeur par défaut est la chaîne qui restaure le terminal du mode standout, telle qu'obtenue à partir de la description terminfo du terminal. Une valeur d'exemple pourrait être “\e[0m”.
bell-style (audible)
Contrôle ce qui se passe lorsque readline veut sonner la cloche du terminal. Si défini sur none, readline ne sonne jamais la cloche. Si défini sur visible, readline utilise une cloche visible si elle est disponible. Si défini sur audible, readline tente de faire sonner la cloche du terminal.
bind-tty-special-chars (On)
Si défini sur On, readline tente de lier les caractères de contrôle qui sont traités spécialement par le pilote de terminal du noyau à leurs équivalents readline. Ceux-ci remplacent les liaisons readline par défaut décrites ici. Tapez “stty -a” à une invite bash pour voir vos paramètres de terminal actuels, y compris les caractères de contrôle spéciaux (généralement cchars).
blink-matching-paren (Off)
Si défini sur On, readline tente de déplacer brièvement le curseur vers une parenthèse ouvrante lorsqu'une parenthèse fermante est insérée.
colored-completion-prefix (Off)
Si défini sur On, lors de la liste des complétions, readline affiche le préfixe commun de l'ensemble des complétions possibles en utilisant une couleur différente. Les définitions de couleur sont prises à partir de la valeur de la variable d'environnement LS_COLORS. S'il existe une définition de couleur dans $LS_COLORS pour le suffixe personnalisé “readline-colored-completion-prefix”, readline utilise cette couleur pour le préfixe commun au lieu de sa valeur par défaut.
colored-stats (Off)
Si défini sur On, readline affiche les complétions possibles en utilisant différentes couleurs pour indiquer leur type de fichier. Les définitions de couleur sont prises à partir de la valeur de la variable d'environnement LS_COLORS.
comment-begin (“#”)
La chaîne que la commande insert-comment de readline insère. Cette commande est liée à M-# en mode emacs et à # en mode commande vi.
completion-display-width (-1)
Le nombre de colonnes d'écran utilisées pour afficher les correspondances possibles lors de l'exécution de la complétion. La valeur est ignorée si elle est inférieure à 0 ou supérieure à la largeur de l'écran du terminal. Une valeur de 0 fait afficher les correspondances une par ligne. La valeur par défaut est -1.
completion-ignore-case (Off)
Si défini sur On, readline effectue la correspondance et la complétion des noms de fichiers sans tenir compte de la casse.
completion-map-case (Off)
Si défini sur On, et que completion-ignore-case est activé, readline traite les tirets (-) et les underscores (_) comme équivalents lors de la correspondance et de la complétion de noms de fichiers sans tenir compte de la casse.
completion-prefix-display-length (0)
La longueur maximale en caractères du préfixe commun d'une liste de complétions possibles qui est affichée sans modification. Lorsqu'elle est définie sur une valeur supérieure à zéro, readline remplace les préfixes communs plus longs que cette valeur par des points de suspension lors de l'affichage des complétions possibles. Si une complétion commence par un point, et que readline complète des noms de fichiers, il utilise trois points de suspension au lieu d'une ellipse.
completion-query-items (100)
Ceci détermine quand l'utilisateur est interrogé sur la visualisation du nombre de complétions possibles générées par la commande possible-completions. Il peut être défini sur n'importe quelle valeur entière supérieure ou égale à zéro. Si le nombre de complétions possibles est supérieur ou égal à la valeur de cette variable, readline demande si l'utilisateur souhaite les afficher ; sinon readline les liste simplement sur le terminal. Une valeur de zéro signifie que readline ne doit jamais demander ; les valeurs négatives sont traitées comme zéro.
convert-meta (On)
Si défini sur On, readline convertit les caractères qu'il lit et qui ont le huitième bit défini en une séquence de touches ASCII en effaçant le huitième bit et en le préfixant avec un caractère d'échappement (convertissant le caractère pour avoir le préfixe meta). La valeur par défaut est On, mais readline la définit sur Off si la locale contient des caractères dont les codages peuvent inclure des octets avec le huitième bit défini. Cette variable dépend de la catégorie de locale LC_CTYPE et peut changer si la locale change. Cette variable affecte également les liaisons de touches ; voir la description de force-meta-prefix ci-dessous.
disable-completion (Off)
Si défini sur On, readline inhibe la complétion de mots. Les caractères de complétion sont insérés dans la ligne comme s'ils avaient été mappés à self-insert.
echo-control-characters (On)
Lorsque défini sur On, sur les systèmes d'exploitation qui indiquent le supporter, readline affiche un caractère correspondant à un signal généré depuis le clavier.
editing-mode (emacs)
Contrôle si readline utilise un ensemble de liaisons de touches similaire à Emacs ou vi. editing-mode peut être défini sur emacs ou vi.
emacs-mode-string (@)
Si la variable show-mode-in-prompt est activée, cette chaîne est affichée juste avant la dernière ligne de l'invite principale lorsque le mode d'édition emacs est actif. La valeur est développée comme une liaison de touches, donc l'ensemble standard des préfixes meta et contrôle ainsi que les séquences d'échappement par antislash est disponible. Les échappements \1 et \2 débutent et terminent des séquences de caractères non imprimables, qui peuvent être utilisées pour intégrer une séquence de contrôle de terminal dans la chaîne de mode.
enable-active-region (On)
Lorsque cette variable est définie sur On, readline permet à certaines commandes de désigner la région comme active. Lorsque la région est active, readline met en surbrillance le texte de la région en utilisant la valeur de la variable active-region-start-color, qui par défaut est la chaîne qui active le mode standout du terminal. La région active affiche le texte inséré par les parenthèses.
-coller et tout texte correspondant trouvé par les recherches d'historique incrémentielles et non incrémentielles.
enable-bracketed-paste (On)
Lorsqu'il est défini sur On, readline configure le terminal pour insérer chaque collage dans le tampon d'édition comme une seule chaîne de caractères, au lieu de traiter chaque caractère comme s'il avait été lu depuis le clavier. Ceci est appelé mode de collage entre crochets ; cela empêche readline d'exécuter toute commande d'édition liée à des séquences de touches apparaissant dans le texte collé.
enable-keypad (Off)
Lorsqu'il est défini sur On, readline tente d'activer le pavé numérique de l'application lorsqu'il est appelé. Certains systèmes en ont besoin pour activer les touches fléchées.
enable-meta-key (On)
Lorsqu'il est défini sur On, readline tente d'activer toute touche de modification méta que le terminal prétend prendre en charge. Sur de nombreux terminaux, la touche Meta est utilisée pour envoyer des caractères sur huit bits ; cette variable vérifie la capacité du terminal qui indique que le terminal peut activer et désactiver un mode qui définit le huitième bit d'un caractère (0200) si la touche Meta est maintenue enfoncée lorsque le caractère est tapé (un caractère méta).
expand-tilde (Off)
S'il est défini sur On, readline effectue l'expansion du tilde lorsqu'il tente la complétion de mots.
force-meta-prefix (Off)
S'il est défini sur On, readline modifie son comportement lors de la liaison de séquences de touches contenant \M- ou Meta- (voir Liaisons de touches ci-dessus) en convertissant une séquence de touches de la forme \M-C ou Meta-C en la séquence de deux caractères ESC C (ajoutant le préfixe méta). Si force-meta-prefix est défini sur Off (par défaut), readline utilise la valeur de la variable convert-meta pour déterminer s'il faut effectuer cette conversion : si convert-meta est On, readline effectue la conversion décrite ci-dessus ; si elle est Off, readline convertit C en un caractère méta en définissant le huitième bit (0200).
history-preserve-point (Off)
S'il est défini sur On, le code d'historique tente de placer le point au même emplacement sur chaque ligne d'historique récupérée avec previous-history ou next-history.
history-size (non défini)
Définit le nombre maximum d'entrées d'historique enregistrées dans la liste d'historique. Si défini sur zéro, toutes les entrées d'historique existantes sont supprimées et aucune nouvelle entrée n'est enregistrée. Si défini sur une valeur inférieure à zéro, le nombre d'entrées d'historique n'est pas limité. Par défaut, le nombre d'entrées d'historique n'est pas limité. Définir history-size sur une valeur non numérique définira le nombre maximum d'entrées d'historique sur 500.
horizontal-scroll-mode (Off)
Définir cette variable sur On fait utiliser à readline une seule ligne pour l'affichage, en faisant défiler l'entrée horizontalement sur une seule ligne de l'écran lorsqu'elle devient plus longue que la largeur de l'écran, plutôt que de passer à une nouvelle ligne. Ce paramètre est automatiquement activé pour les terminaux de hauteur 1.
input-meta (Off)
S'il est défini sur On, readline active l'entrée sur huit bits (c'est-à-dire qu'il ne désactive pas le huitième bit des caractères qu'il lit), indépendamment de ce que le terminal prétend prendre en charge. La valeur par défaut est Off, mais readline la définit sur On si la locale contient des caractères dont les encodages peuvent inclure des octets avec le huitième bit défini. Cette variable dépend de la catégorie de locale LC_CTYPE, et sa valeur peut changer si la locale change. Le nom meta-flag est un synonyme de input-meta.
isearch-terminators (“C-[C-j”)
La chaîne de caractères qui doit terminer une recherche incrémentielle sans exécuter ensuite le caractère comme une commande. Si cette variable n'a pas reçu de valeur, les caractères ESC et C-j terminent une recherche incrémentielle.
keymap (emacs)
Définit la table des codes de touches (keymap) readline actuelle. L'ensemble des noms de tables de codes de touches valides est emacs, emacs-standard, emacs-meta, emacs-ctlx, vi, vi-command, et vi-insert. vi est équivalent à vi-command ; emacs est équivalent à emacs-standard. La valeur par défaut est emacs ; la valeur de editing-mode affecte également la table des codes de touches par défaut.
keyseq-timeout (500)
Spécifie la durée pendant laquelle readline attendra un caractère lors de la lecture d'une séquence de touches ambiguë (une qui peut former une séquence de touches complète en utilisant l'entrée lue jusqu'à présent, ou qui peut prendre une entrée supplémentaire pour compléter une séquence de touches plus longue). Si readline ne reçoit aucune entrée dans le délai imparti, il utilise la séquence de touches plus courte mais complète. La valeur est spécifiée en millisecondes, donc une valeur de 1000 signifie que readline attendra une seconde pour une entrée supplémentaire. Si cette variable est définie sur une valeur inférieure ou égale à zéro, ou sur une valeur non numérique, readline attendra qu'une autre touche soit pressée pour décider quelle séquence de touches compléter.
mark-directories (On)
S'il est défini sur On, un slash est ajouté aux noms de répertoires complétés.
mark-modified-lines (Off)
S'il est défini sur On, readline affiche les lignes d'historique qui ont été modifiées avec un astérisque précédent (*).
mark-symlinked-directories (Off)
S'il est défini sur On, les noms complétés qui sont des liens symboliques vers des répertoires auront un slash ajouté, sous réserve de la valeur de mark-directories.
match-hidden-files (On)
Cette variable, lorsqu'elle est définie sur On, force readline à faire correspondre les fichiers dont les noms commencent par un point (".") (fichiers cachés) lors de la complétion de noms de fichiers. Si elle est définie sur Off, l'utilisateur doit inclure le point (".") initial dans le nom de fichier à compléter.
menu-complete-display-prefix (Off)
S'il est défini sur On, la complétion par menu affiche le préfixe commun de la liste des complétions possibles (qui peut être vide) avant de parcourir la liste.
output-meta (Off)
S'il est défini sur On, readline affiche directement les caractères avec le huitième bit défini au lieu d'une séquence d'échappement avec préfixe méta. La valeur par défaut est Off, mais readline la définit sur On si la locale contient des caractères dont les encodages peuvent inclure des octets avec le huitième bit défini. Cette variable dépend de la catégorie de locale LC_CTYPE, et sa valeur peut changer si la locale change.
page-completions (On)
S'il est défini sur On, readline utilise un paginateur interne ressemblant à more(1) pour afficher un écran de complétions possibles à la fois.
prefer-visible-bell
Voir bell-style.
print-completions-horizontally (Off)
S'il est défini sur On, readline affiche les complétions avec des correspondances triées horizontalement par ordre alphabétique, plutôt que verticalement sur l'écran.
revert-all-at-newline (Off)
S'il est défini sur On, readline annulera toutes les modifications apportées aux lignes d'historique avant de revenir lors de l'exécution de accept-line. Par défaut, les lignes d'historique peuvent être modifiées et conserver des listes d'annulation individuelles entre les appels à readline().
search-ignore-case (Off)
S'il est défini sur On, readline effectue les recherches d'historique incrémentielles et non incrémentielles sans tenir compte de la casse.
show-all-if-ambiguous (Off)
Ceci modifie le comportement par défaut des fonctions de complétion. S'il est défini sur On, les mots qui ont plus d'une complétion possible provoquent l'affichage immédiat des correspondances au lieu de faire sonner la cloche.
show-all-if-unmodified (Off)
Ceci modifie le comportement par défaut des fonctions de complétion d'une manière similaire à show-all-if-ambiguous. S'il est défini sur On, les mots qui ont plus d'une complétion possible sans aucune complétion partielle possible (les complétions possibles ne partagent pas de préfixe commun) provoquent l'affichage immédiat des correspondances au lieu de faire sonner la cloche.
show-mode-in-prompt (Off)
S'il est défini sur On, ajoute une chaîne au début de l'invite indiquant le mode d'édition : emacs, vi commande, ou vi insertion. Les chaînes de mode sont modifiables par l'utilisateur (par exemple, emacs-mode-string).

S'il est défini sur On, cela modifie le comportement de complétion par défaut lors de l'insertion d'une seule correspondance dans la ligne. Il n'est actif que lors de l'exécution de la complétion au milieu d'un mot. S'il est activé, readline n'insère pas les caractères de la complétion qui correspondent aux caractères après le point dans le mot en cours de complétion, de sorte que les portions du mot suivant le curseur ne sont pas dupliquées.

Structures Conditionnelles

Readline implémente une facilité similaire dans l'esprit aux fonctionnalités de compilation conditionnelle du préprocesseur C, qui permet des liaisons de touches et des réglages de variables basés sur des tests. Quatre directives d'analyseur sont disponibles.

$if
La construction $if permet de faire des liaisons basées sur le mode d'édition, le terminal utilisé, ou l'application utilisant readline. Le texte du test, après tout opérateur de comparaison, s'étend jusqu'à la fin de la ligne ; sauf indication contraire, aucun caractère n'est requis pour l'isoler.
mode
La forme mode= de la directive $if est utilisée pour tester si readline est en mode emacs ou vi. Cela peut être utilisé conjointement avec la commande set keymap, par exemple, pour définir des liaisons dans les maps de touches emacs-standard et emacs-ctlx seulement si readline démarre en mode emacs.
term
La forme term= peut être utilisée pour inclure des liaisons de touches spécifiques au terminal, peut-être pour lier les séquences de touches générées par les touches de fonction du terminal. Le mot à droite du = est comparé à la fois au nom complet du terminal et à la partie du nom du terminal avant le premier -. Cela permet à xterm de correspondre à la fois à xterm et à xterm-256color, par exemple.
version
Le test version peut être utilisé pour effectuer des comparaisons avec des versions spécifiques de readline. La version se développe en la version actuelle de readline. L'ensemble des opérateurs de comparaison inclut =, (et ==), !=, <=, >=, < et >. Le numéro de version fourni à droite de l'opérateur se compose d'un numéro de version majeur, d'un point décimal optionnel et d'une version mineure optionnelle (par exemple, 7.1). Si la version mineure est omise, elle vaut par défaut 0. L'opérateur peut être séparé de la chaîne version et de l'argument du numéro de version par des espaces blancs.
application
La construction application est utilisée pour inclure des réglages spécifiques à l'application. Chaque programme utilisant la bibliothèque readline définit le nom de l'application, et un fichier d'initialisation peut tester une valeur particulière. Cela pourrait être utilisé pour lier des séquences de touches à des fonctions utiles pour un programme spécifique. Par exemple, la commande suivante ajoute une séquence de touches qui met entre guillemets le mot actuel ou précédent dans bash :
$if Bash
# Mettre entre guillemets le mot actuel ou précédent
"\C-xq": "\eb\"\ef\""
$endif
variable
La construction variable fournit des tests d'égalité simples pour les variables et valeurs de readline. Les opérateurs de comparaison autorisés sont =, == et !=. Le nom de la variable doit être séparé de l'opérateur de comparaison par des espaces blancs ; l'opérateur peut être séparé de la valeur à droite par des espaces blancs. Les variables de type chaîne et booléennes peuvent être testées. Les variables booléennes doivent être testées contre les valeurs on et off.
$else
Les commandes de cette branche de la directive $if sont exécutées si le test échoue.
$endif
Cette commande, comme vu dans l'exemple précédent, termine une commande $if.
$include
Cette directive prend un seul nom de fichier comme argument et lit les commandes et les liaisons de touches de ce fichier. Par exemple, la directive suivante lirait /etc/inputrc :
$include  /etc/inputrc

RECHERCHE

Readline fournit des commandes pour rechercher dans l'historique des commandes les lignes contenant une chaîne spécifiée. Il existe deux modes de recherche : incrémental et non incrémental.

Les recherches incrémentales commencent avant que l'utilisateur ait fini de taper la chaîne de recherche. À chaque caractère de la chaîne de recherche tapé, readline affiche la prochaine entrée de l'historique correspondant à la chaîne tapée jusqu'à présent. Une recherche incrémentale ne nécessite que le nombre de caractères nécessaires pour trouver l'entrée d'historique souhaitée. Lors de l'utilisation du mode d'édition emacs, tapez C-r pour rechercher en arrière dans l'historique une chaîne particulière. Taper C-s recherche en avant dans l'historique. Les caractères présents dans la valeur de la variable isearch-terminators sont utilisés pour terminer une recherche incrémentale. Si cette variable n'a pas reçu de valeur, ESC et C-j terminent une recherche incrémentale. C-g annule une recherche incrémentale et restaure la ligne d'origine. Lorsque la recherche est terminée, l'entrée d'historique contenant la chaîne de recherche devient la ligne courante.

Pour trouver d'autres entrées correspondantes dans la liste d'historique, tapez C-r ou C-s selon le cas. Cela recherche en arrière ou en avant dans l'historique la prochaine entrée correspondant à la chaîne de recherche tapée jusqu'à présent. Toute autre séquence de touches liée à une commande readline termine la recherche et exécute cette commande. Par exemple, un retour à la ligne termine la recherche et accepte la ligne, exécutant ainsi la commande de la liste d'historique. Une commande de déplacement terminera la recherche, fera de la dernière ligne trouvée la ligne courante, et commencera l'édition.

Readline mémorise la dernière chaîne de recherche incrémentale. Si deux C-r sont tapés sans aucun caractère intermédiaire définissant une nouvelle chaîne de recherche, readline utilise la chaîne de recherche mémorisée.

Les recherches non incrémentales lisent la chaîne de recherche entière avant de commencer à rechercher les entrées d'historique correspondantes. La chaîne de recherche peut être tapée par l'utilisateur ou faire partie du contenu de la ligne courante.

COMMANDES D'ÉDITION

Voici une liste des noms des commandes et des séquences de touches par défaut auxquelles elles sont liées. Les noms de commandes sans séquence de touches associée ne sont pas liés par défaut.

Dans les descriptions suivantes, point fait référence à la position actuelle du curseur, et marque fait référence à une position de curseur sauvegardée par la commande set-mark. Le texte entre le point et la marque est appelé la région. Readline a le concept d'une région active : lorsque la région est active, readline redessine en mettant en surbrillance la région en utilisant la valeur de la variable active-region-start-color. La variable enable-active-region active ou désactive cette fonctionnalité. Plusieurs commandes activent la région ; celles-ci sont notées ci-dessous.

Arguments Numériques

digit-argument (M-0, M-1, ..., M--)
Ajoute ce chiffre à l'argument déjà en cours de construction, ou commence un nouvel argument. M-- commence un argument négatif.
universal-argument
C'est une autre façon de spécifier un argument. Si cette commande est suivie par un ou plusieurs chiffres, éventuellement précédés d'un signe moins, ces chiffres définissent l'argument. Si la commande est suivie par des chiffres, l'exécution de universal-argument à nouveau termine l'argument numérique, mais n'a pas d'autre effet. Dans un cas spécial, si cette commande est immédiatement suivie par un caractère qui n'est ni un chiffre ni un signe moins, le compteur d'arguments pour la commande suivante est multiplié par quatre. Le compteur d'arguments est initialement à un, donc l'exécution de cette fonction une première fois rend le compteur d'arguments à quatre, une seconde fois à seize, et ainsi de suite.

Complétion

complete (TAB)
Tente d'effectuer une complétion sur le texte précédant le curseur. La complétion réelle effectuée est spécifique à l'application. Bash, par exemple, tente d'abord une complétion programmable, sinon traite le texte comme une variable (si le texte commence par $), un nom d'utilisateur (si le texte commence par ~), un nom d'hôte (si le texte commence par @), ou une commande (y compris les alias, fonctions et commandes internes) tour à tour. Si aucune de ces options ne produit de correspondance, elle se rabat sur la complétion de noms de fichiers. Gdb, d'autre part, permet la complétion de fonctions et variables du programme, et ne tente la complétion de noms de fichiers que dans certaines circonstances. La complétion par défaut de readline est la complétion de noms de fichiers.
possible-completions (M-?)
Liste les complétions possibles du texte précédant le curseur. Lors de l'affichage des complétions, readline définit le nombre de colonnes utilisées pour l'affichage à la valeur de completion-display-width, la valeur de la variable d'environnement COLUMNS, ou la largeur de l'écran, dans cet ordre.
insert-completions (M-*)
Insère toutes les complétions du texte précédant le curseur qui auraient été générées par possible-completions, séparées par un espace.
menu-complete
Similaire à complete, mais remplace le mot à compléter par une seule correspondance parmi la liste des complétions possibles. L'exécution répétée de menu-complete parcourt la liste des complétions possibles, en insérant chaque correspondance tour à tour. À la fin de la liste des complétions, menu-complete fait sonner la cloche (sous réserve du réglage de bell-style) et restaure le texte original. Un argument de n avance de n positions dans la liste des correspondances ; un argument négatif recule dans la liste. Cette commande est destinée à être liée à TAB, mais n'est pas liée par défaut.
menu-complete-backward
Identique à menu-complete, mais recule dans la liste des complétions possibles, comme si menu-complete avait reçu un argument négatif. Cette commande n'est pas liée par défaut.
export-completions
Effectue une complétion sur le mot précédant le curseur comme décrit ci-dessus et écrit la liste des complétions possibles dans le flux de sortie de readline en utilisant le format suivant, en écrivant les informations sur des lignes séparées :
  • le nombre de correspondances N ;
  • le mot en cours de complétion ;
  • S:E, où S et E sont les décalages de début et de fin du mot dans le tampon de ligne de readline ; puis
  • chaque correspondance, une par ligne
S'il n'y a pas de correspondance, la première ligne sera “0”, et cette commande n'imprime aucune sortie après S:E. S'il n'y a qu'une seule correspondance, elle imprime une seule ligne la contenant. S'il y a plus d'une correspondance, elle imprime le préfixe commun des correspondances, qui peut être vide, sur la première ligne après S:E, puis les correspondances sur les lignes suivantes. Dans ce cas, N inclura la première ligne avec le préfixe commun.
L'utilisateur ou l'application doit être capable de gérer la possibilité d'une ligne vide. L'intention est que l'utilisateur ou l'application lise N lignes après la ligne contenant S:E pour obtenir la liste des correspondances. Cette commande n'est pas liée par défaut.
delete-char-or-list
Supprime le caractère sous le curseur s'il n'est ni au début ni à la fin de la ligne (comme delete-char). À la fin de la ligne, il se comporte de manière identique à possible-completions. Cette commande n'est pas liée par défaut.

Macros Clavier

start-kbd-macro (C-x ()
Commence à enregistrer les caractères tapés dans la macro clavier courante.
end-kbd-macro (C-x ))
Arrête d'enregistrer les caractères tapés dans la macro clavier courante et stocke la définition.
call-last-kbd-macro (C-x e)
Réexécute la dernière macro clavier définie, en faisant apparaître les caractères de la macro comme s'ils étaient tapés au clavier.
print-last-kbd-macro ()
Imprime la dernière macro clavier définie dans un format adapté au fichier inputrc.

Divers

re-read-init-file (C-x C-r)
Relit le contenu du fichier inputrc et intègre les liaisons ou les affectations de variables qui y sont trouvées.
abort (C-g)
Interrompt la commande d'édition courante et fait sonner la cloche du terminal (sous réserve du réglage de bell-style).
do-lowercase-version (M-A, M-B, M-x, ...)
Si le caractère métacaráctère x est en majuscule, exécute la commande liée au caractère minuscule métacaráctère correspondant. Le comportement est indéfini si x est déjà en minuscule.
prefix-meta (ESC)
Ajoute le méta-caractère au caractère suivant tapé. ESC f est équivalent à Meta-f.
undo (C-_, C-x C-u)
Annulation incrémentielle, mémorisée séparément pour chaque ligne.
revert-line (M-r)
Annule toutes les modifications apportées à cette ligne. C'est comme exécuter la commande undo suffisamment de fois pour ramener la ligne à son état initial.
tilde-expand (M-~)
Effectue une expansion de tilde sur le mot courant.
set-mark (C-@, M-<space>)
Définit la marque à la position du curseur. Si un argument numérique est fourni, définit la marque à cette position.
exchange-point-and-mark (C-x C-x)
Échange le curseur et la marque. Définit la position courante du curseur à la position sauvegardée, puis définit la marque à l'ancienne position du curseur.
character-search (C-])
Lit un caractère et déplace le curseur à la prochaine occurrence de ce caractère. Un argument négatif recherche les occurrences précédentes.
character-search-backward (M-C-])
Lit un caractère et déplace le curseur à l'occurrence précédente de ce caractère. Un argument négatif recherche les occurrences suivantes.
skip-csi-sequence
Lit suffisamment de caractères pour consommer une séquence multi-touches telle que celles définies pour des touches comme Home et End. Les séquences CSI commencent par un indicateur de séquence de contrôle (CSI), généralement ESC [. Si cette séquence est liée à “\e[”, les touches produisant des séquences CSI n'ont aucun effet sauf si elles sont explicitement liées à une commande readline, au lieu d'insérer des caractères parasites dans le tampon d'édition. Cette commande n'est pas liée par défaut, mais est généralement liée à ESC [.
insert-comment (M-#)
Sans argument numérique, insère la valeur de la variable comment-begin de readline au début de la ligne courante. Si un argument numérique est fourni
, cette commande agit comme un interrupteur : si les caractères au début de la ligne ne correspondent pas à la valeur de comment-begin, insérer la valeur ; sinon, supprimer les caractères de comment-begin du début de la ligne. Dans les deux cas, la ligne est acceptée comme si une nouvelle ligne avait été tapée. La valeur par défaut de comment-begin fait de cette commande un commentaire shell pour la ligne actuelle. Si un argument numérique supprime le caractère de commentaire, la ligne sera exécutée par le shell.
dump-functions
Imprimer toutes les fonctions et leurs associations de touches dans le flux de sortie de readline. Si un argument numérique est fourni, la sortie est formatée de manière à pouvoir être incluse dans un fichier inputrc.
dump-variables
Imprimer toutes les variables configurables et leurs valeurs dans le flux de sortie de readline. Si un argument numérique est fourni, la sortie est formatée de manière à pouvoir être incluse dans un fichier inputrc.
dump-macros
Imprimer toutes les séquences de touches de readline associées à des macros et les chaînes qu'elles génèrent dans le flux de sortie de readline. Si un argument numérique est fourni, la sortie est formatée de manière à pouvoir être incluse dans un fichier inputrc.
execute-named-command (M-x)
Lire un nom de commande readline associable à partir de l'entrée et exécuter la fonction à laquelle il est associé, comme si la séquence de touches à laquelle il était associé était apparue dans l'entrée. Si cette fonction reçoit un argument numérique, elle transmet cet argument à la fonction qu'elle exécute.
emacs-editing-mode (C-e)
En mode commande vi, cela bascule readline en mode édition emacs.
vi-editing-mode (M-C-j)
En mode édition emacs, cela bascule en mode édition vi.

LIAISONS DE TOUCHES PAR DÉFAUT

Voici une liste des liaisons par défaut pour emacs et vi. Les caractères dont le huitième bit est défini sont écrits comme M-<caractère>, et sont appelés caractères métafiés. Les caractères ASCII imprimables non mentionnés dans la liste des liaisons standard d'emacs sont liés à la fonction self-insert, qui insère simplement le caractère donné dans la ligne d'entrée. En mode insertion vi, tous les caractères non mentionnés spécifiquement sont liés à self-insert. Les caractères attribués à la génération de signaux par stty(1) ou le pilote de terminal, tels que C-Z ou C-C, conservent leur fonction. Les caractères métafiés en majuscules et minuscules sont liés à la même fonction dans la table des touches méta du mode emacs. Les caractères restants ne sont pas liés, ce qui provoque la sonnerie de la cloche par readline (sous réserve du réglage de la variable bell-style).

SIGNALEMENTS DE BOGUES

Si vous trouvez un bogue dans readline, vous devriez le signaler. Mais d'abord, vous devriez vous assurer qu'il s'agit bien d'un bogue et qu'il apparaît dans la dernière version de la bibliothèque readline que vous possédez.

Une fois que vous avez déterminé qu'un bogue existe réellement, envoyez un rapport de bogue à bug-readline@gnu.org. Si vous avez un correctif, vous êtes également invité à l'envoyer ! Les suggestions et les rapports de bogues « philosophiques » peuvent être envoyés à bug-readline@gnu.org ou publiés sur le groupe de discussion Usenet gnu.bash.bug.

Les commentaires et les rapports de bogues concernant cette page de manuel doivent être adressés à chet.ramey@case.edu.
