NOM

repo - repo upload - page de manuel pour repo upload

SYNTAXE

repo upload [--re --cc] [<projet>]...

DESCRIPTION

Résumé

Télécharger les modifications pour revue de code

OPTIONS

-h, --help
afficher ce message d'aide et quitter
-j JOBS, --jobs=JOBS
nombre de jobs à exécuter en parallèle (par défaut : basé sur le nombre de cœurs de CPU)
-t, --topic-branch
définir le sujet sur le nom de la branche locale
--topic=TOPIC
définir le sujet pour la modification
--hashtag=HASHTAGS, --ht=HASHTAGS
ajouter des hashtags (délimités par des virgules) à la revue
--hashtag-branch, --htb
ajouter le nom de la branche locale comme hashtag
-l LABELS, --label=LABELS
ajouter une étiquette lors du téléchargement
--pd=PATCHSET_DESCRIPTION, --patchset-description=PATCHSET_DESCRIPTION
description du jeu de correctifs
--re=REVIEWERS, --reviewers=REVIEWERS
demander des revues à ces personnes
--cc=CC
envoyer également un e-mail à ces adresses e-mail
--br=BRANCH, --branch=BRANCH
branche (locale) à télécharger
-c, --current-branch
télécharger la branche git actuelle
--no-current-branch
télécharger toutes les branches git
--ne, --no-emails
ne pas envoyer d'e-mails lors du téléchargement
-p, --private
télécharger comme une modification privée (obsolète ; utiliser --wip)
-w, --wip
télécharger comme une modification en cours de développement
-r, --ready
marquer la modification comme prête (efface le réglage en cours de développement)
-o PUSH_OPTIONS, --push-option=PUSH_OPTIONS
options de poussée supplémentaires à transmettre
-D BRANCH, --destination=BRANCH, --dest=BRANCH
soumettre pour revue sur cette branche cible
-n, --dry-run
tout faire sauf télécharger réellement le CL
-y, --yes
répondre oui à toutes les invites sûres
--ignore-untracked-files
ignorer les fichiers non suivis dans la copie de travail
--no-ignore-untracked-files
demander toujours concernant les fichiers non suivis dans la copie de travail
--no-cert-checks
désactiver la vérification des certificats SSL (dangereux)

Options de journalisation :

-v, --verbose
afficher toute la sortie
-q, --quiet
n'afficher que les erreurs

Options multi-manifest :

--outer-manifest
opérer en partant du manifeste le plus externe
--no-outer-manifest
ne pas opérer sur les manifestes externes
--this-manifest-only
opérer uniquement sur ce manifeste (sub)
--no-this-manifest-only, --all-manifests
opérer sur ce manifeste et ses sous-manifestes

Hooks pre-upload :

--no-verify
Ne pas exécuter le hook pre-upload.
--verify
Exécuter le hook pre-upload sans demander confirmation.
--ignore-hooks
Ne pas abandonner si les hooks pre-upload échouent.

Exécutez `repo help upload` pour voir le manuel détaillé.

DÉTAILS

La commande 'repo upload' est utilisée pour envoyer des modifications au système Gerrit Code Review. Elle recherche les branches de sujet dans les projets locaux qui n'ont pas encore été publiées pour revue. Si plusieurs branches de sujet sont trouvées, 'repo upload' ouvre un éditeur pour permettre à l'utilisateur de sélectionner les branches à télécharger.

'repo upload' recherche les modifications téléchargeables dans tous les projets listés en ligne de commande. Les projets peuvent être spécifiés soit par leur nom, soit par un chemin relatif ou absolu vers le répertoire local du projet. Si aucun projet n'est spécifié, 'repo upload' recherchera les modifications téléchargeables dans tous les projets listés dans le manifeste.

Si les options --reviewers ou --cc sont passées, ces e-mails sont ajoutés à la liste respective des utilisateurs, et des e-mails sont envoyés aux nouveaux utilisateurs. Les utilisateurs passés comme --reviewers doivent déjà être enregistrés auprès du système de revue de code, sinon le téléchargement échouera.

Bien que la plupart des options Gerrit normales aient des options de ligne de commande dédiées, un accès direct aux options Gerrit est disponible via --push-options. Ceci est utile lorsque Gerrit a des fonctionnalités plus récentes que repo upload ne supporte pas encore, ou n'a pas l'intention de supporter. Voir la documentation des Options de Poussée pour plus de détails : https://gerrit-review.googlesource.com/Documentation/user-upload.html#push_options

Configuration

review.URL.autoupload:

Pour désactiver l'invite "Upload ... (y/N)?", vous pouvez définir une option de configuration Git globale ou par projet. Si review.URL.autoupload est défini sur "true", alors repo supposera que vous répondez toujours "y" à l'invite, et ne vous invitera plus. Si elle est définie sur "false", alors repo supposera que vous répondez toujours "n", et abandonnera.

review.URL.autoreviewer:

Pour ajouter automatiquement un utilisateur ou une liste de diffusion aux revues, vous pouvez définir une option Git globale ou par projet pour ce faire.

review.URL.autocopy:

Pour copier automatiquement un utilisateur ou une liste de diffusion sur toutes les revues téléchargées, vous pouvez définir une option Git globale ou par projet pour ce faire. Spécifiquement, review.URL.autocopy peut être défini sur une liste d'examinateurs séparés par des virgules que vous voulez toujours copier sur tous les téléchargements avec un argument --re non vide.

review.URL.username:

Remplace le nom d'utilisateur utilisé pour se connecter à Gerrit Code Review. Par défaut, la partie locale de l'adresse e-mail est utilisée.

L'URL doit correspondre à l'URL de revue listée dans le fichier XML du manifeste, ou dans le .git/config du projet. Par exemple :

[remote "origin"]
url = git://git.example.com/project.git review = http://review.example.com/
[review "http://review.example.com/"]
autoupload = true autocopy = johndoe@company.com,my-team-alias@company.com

review.URL.uploadtopic:

Pour ajouter une branche de sujet lors du téléchargement d'un commit, vous pouvez définir une option Git globale ou par projet pour ce faire. Si review.URL.uploadtopic est défini sur "true", alors repo supposera que vous voulez toujours l'équivalent de l'option -t de la commande repo. Si non défini ou défini sur "false", alors repo utilisera uniquement la ligne de commande o

NAME

repo upload — Téléverser des modifications sur une liste de branches

SYNOPSIS

repo upload [OPTION]... [BRANCH]...

DESCRIPTION

La commande repo upload téléverse des modifications sur une liste de branches. Elle peut être utilisée pour téléverser les modifications en attente de plusieurs branches à la fois. Par défaut, repo upload téléversera les modifications pour toutes les branches qui contiennent des modifications non validées.

La commande repo upload est une interface pour la commande git push. Elle est utilisée pour téléverser des modifications vers un dépôt distant.

La commande repo upload peut être utilisée pour téléverser des modifications à partir de plusieurs branches à la fois. Par défaut, repo upload téléversera les modifications pour toutes les branches qui contiennent des modifications non validées.

La commande repo upload est une interface pour la commande git push. Elle est utilisée pour téléverser des modifications vers un dépôt distant.

OPTIONS

-a, --all
Téléverser toutes les branches, y compris celles qui ne contiennent pas de modifications non validées.
-c, --current-branch
Téléverser uniquement la branche actuelle.
-n, --dry-run
Simuler le téléversement sans réellement envoyer les modifications.
-f, --force
Forcer le téléversement, même s'il y a des conflits.
-p, --push-tags
Inclure les tags lors du téléversement.
-r, --replace
Remplacer une branche existante sur le dépôt distant.
-s, --save-only
Ne sauvegarder que les modifications, sans les téléverser.
-t, --topic TOPIC
Téléverser les modifications sous forme de topic TOPIC.
-v, --verbose
Afficher plus d'informations lors du téléversement.
--force-tag [glob]
Forcer le téléversement de tags correspondant au motif glob. S'il n'y a pas de motif, tous les tags seront téléversés.

DETAILS

La commande repo upload utilise les options de configuration suivantes :

review.URL.uploadhashtags:

Pour ajouter des hashtags lors du téléversement d'un commit, vous pouvez définir une option Git par projet ou globale pour ce faire. La valeur de review.URL.uploadhashtags sera utilisée comme hashtags délimités par des virgules, comme l'option --hashtag.

review.URL.uploadlabels:

Pour ajouter des étiquettes lors du téléversement d'un commit, vous pouvez définir une option Git par projet ou globale pour ce faire. La valeur de review.URL.uploadlabels sera utilisée comme étiquettes délimitées par des virgules, comme l'option --label.

review.URL.uploadnotify:

Contrôler les notifications par e-mail lors du téléversement. https://gerrit-review.googlesource.com/Documentation/user-upload.html#notify

review.URL.uploadwarningthreshold:

Repo vous avertira si vous tentez de téléverser un grand nombre de commits dans une ou plusieurs branches. Par défaut, le seuil est de cinq commits. Cette option vous permet de remplacer le seuil d'avertissement par une valeur différente.
