REGEXP_TABLE(5) Manuel des formats de fichiers REGEXP_TABLE(5)

NOM

regexp_table - format des tables d'expressions régulières Postfix

SYNTAXE

postmap -q "chaîne" regexp:/etc/postfix/nomfichier
postmap -q - regexp:/etc/postfix/nomfichier <fichierentree

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses, le routage de courrier ou le contrôle d'accès. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de recherche peuvent être spécifiées sous forme d'expressions régulières POSIX. Dans ce cas, chaque entrée est comparée à une liste de motifs. Lorsqu'une correspondance est trouvée, le résultat correspondant est retourné et la recherche est terminée.

Pour savoir quels types de tables de recherche votre système Postfix prend en charge, utilisez la commande "postconf -m".

Pour tester les tables de recherche, utilisez la commande "postmap -q" comme décrit dans la SYNTAXE ci-dessus. Utilisez "postmap -hmq - <fichier" pour les motifs de header_checks(5), et "postmap -bmq - <fichier" pour les body_checks(5) (Postfix 2.6 et versions ultérieures).

COMPATIBILITÉ

Avec Postfix version 2.2 et antérieures, spécifiez "postmap -fq" pour interroger une table qui contient des motifs sensibles à la casse. Les motifs sont insensibles à la casse par défaut.

FORMAT DE TABLE

La forme générale d'une table d'expressions régulières Postfix est :

/motif/indicateurs résultat
Lorsque motif correspond à la chaîne d'entrée, utilisez la valeur résultat correspondante.
!/motif/indicateurs résultat
Lorsque motif ne correspond pas à la chaîne d'entrée, utilisez la valeur résultat correspondante.
si /motif/indicateurs
finsi
Si la chaîne d'entrée correspond à /motif/, alors faites correspondre cette chaîne d'entrée avec les motifs entre si et finsi. Les blocs si..finsi peuvent être imbriqués.

Note : n'ajoutez pas d'espace avant les motifs à l'intérieur de si..finsi.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

si !/motif/indicateurs
finsi
Si la chaîne d'entrée ne correspond pas à /motif/, alors faites correspondre cette chaîne d'entrée avec les motifs entre si et finsi. Les blocs si..finsi peuvent être imbriqués.

Note : n'ajoutez pas d'espace avant les motifs à l'intérieur de si..finsi.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

lignes vides et commentaires
Les lignes vides et les lignes composées uniquement d'espaces sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
texte multi-lignes
Une ligne logique commence par un caractère non-espace. Une ligne qui commence par un espace continue une ligne logique.

Chaque motif est une expression régulière POSIX délimitée par une paire de délimiteurs. La syntaxe des expressions régulières est documentée dans re_format(7) avec 4.4BSD, dans regex(5) avec Solaris, et dans regex(7) avec Linux. D'autres systèmes peuvent utiliser d'autres noms de documents.

Le délimiteur d'expression peut être n'importe quel caractère non alphanumérique, à l'exception des espaces et des caractères ayant une signification spéciale (traditionnellement, la barre oblique est utilisée). L'expression régulière peut contenir des espaces.

Par défaut, la correspondance est insensible à la casse et les sauts de ligne ne sont pas traités comme des caractères spéciaux. Le comportement est contrôlé par des indicateurs, qui sont activés/désactivés en ajoutant un ou plusieurs des caractères suivants après le motif :

i (défaut : activé)
Active/désactive l'indicateur de sensibilité à la casse. Par défaut, la correspondance est insensible à la casse.
m (défaut : désactivé)
Active/désactive l'indicateur de mode multi-lignes. Lorsque cet indicateur est activé, les métacaractères ^ et $ correspondent immédiatement après et immédiatement avant un caractère de saut de ligne, respectivement, en plus de correspondre au début et à la fin de la chaîne d'entrée.
x (défaut : activé)
Active/désactive l'indicateur de syntaxe d'expression étendue. Par défaut, la prise en charge de la syntaxe d'expression étendue est activée.

ORDRE DE RECHERCHE DE TABLE

Les motifs sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un motif soit trouvé qui corresponde à la chaîne d'entrée.

Chaque motif est appliqué à la chaîne d'entrée entière. Selon l'application, cette chaîne est un nom d'hôte client complet, une adresse IP client complète ou une adresse de messagerie complète. Ainsi, aucune recherche de domaine parent ou de réseau parent n'est effectuée, et les adresses de messagerie utilisateur@domaine ne sont pas décomposées en leurs parties utilisateur et domaine, ni utilisateur+foo décomposé en utilisateur et foo.

SUBSTITUTION DE TEXTE

La substitution de sous-chaînes (texte qui correspond aux motifs à l'intérieur de "()") de l'expression correspondante dans la chaîne de résultat est demandée avec $1, $2, etc. ; spécifiez $$ pour produire un caractère $ en sortie. Les macros dans la chaîne de résultat peuvent devoir être écrites comme ${n} ou $(n) si elles ne sont pas suivies d'un espace.

Note : étant donné que les motifs négatifs (ceux précédés de !) retournent un résultat lorsque l'expression ne correspond pas, les substitutions ne sont pas disponibles pour les motifs négatifs.

SPECIFICATION EN LIGNE

Le contenu d'une table peut être spécifié dans le nom de la table (Postfix 3.7 et versions ultérieures). La syntaxe de base est :

main.cf:
    parametre = .. regexp:{ { regle-1 }, { regle-2 } .. } ..
master.cf:
    .. -o { parametre = .. regexp:{ { regle-1 }, { regle-2 } .. } .. } ..

Postfix développe récursivement toutes les instances $nomparametre dans la valeur du paramètre ci-dessus, ignore les espaces après '{' et avant '}', et écrit chaque règle comme une ligne de texte dans un fichier en mémoire :

fichier en mémoire:
    regle-1
    regle-2
    ..

Postfix analyse le résultat comme s'il s'agissait d'un fichier dans /etc/postfix.

CAVEATS SPECIFICATION EN LIGNE

  • Évitez d'utiliser $nomparametre à l'intérieur d'une expression régulière en ligne : motif. Le motif aurait des correspondances inattendues lorsqu'il y a des métacaractères tels que '.' dans l'expansion de $nomparametre. Pour éviter les correspondances inattendues, utilisez une table pcre: et spécifiez \Q$nomparametre\E.
  • Lorsqu'une règle en ligne doit contenir $, spécifiez $$ pour empêcher Postfix d'essayer d'effectuer une expansion $nom lors de l'évaluation d'une valeur de paramètre. Pour vérifier une configuration en ligne, utilisez l'option "postconf -x" comme indiqué ci-dessous :
  • Lorsqu'un réglage "nomparametre = valeur" dans main.cf contient une table regexp: en ligne, utilisez la commande "postconf -x nomparametre". Vérifiez qu'il n'y a pas d'avertissements "paramètre non défini" et que la sortie a la syntaxe que l'on utiliserait dans un fichier Postfix regexp: non en ligne.
  • Lorsqu'une surcharge master.cf "-o { nomparametre = valeur }" contient une table regexp: en ligne, utilisez la commande "postconf -Px '*/*/nomparametre' ". Vérifiez qu'il n'y a pas d'avertissements "paramètre non défini" et que la sortie a la syntaxe que l'on utiliserait dans un fichier Postfix regexp: non en ligne.

EXEMPLE MAP ACCES SMTPD

# Interdire le routage spécifié par l'expéditeur. C'est indispensable si vous
# relayez du courrier pour d'autres domaines.
/[%!@].*[%!@]/       55
0 Rejeté par le routage spécifié par l'expéditeur # Le Postmaster est OK, de cette façon ils peuvent nous parler de la façon de résoudre # leur problème. /^postmaster@/ OK # Protégez vos exploders majordomo sortants if !/^owner-/ /^(.*)-outgoing@(.*)$/ 550 Utilisez ${1}@${2} à la place endif

EXEMPLE DE CARTE DE FILTRAGE D'EN-TÊTE

# C'était courant dans les spams autrefois.
/^Subject: make money fast/ REJECT
/^To: friend@public\.com/ REJECT

EXEMPLE DE CARTE DE FILTRAGE DE CORPS

# D'abord, on saute le texte encodé en base 64 pour économiser des cycles CPU.
~^[[:alnum:]+/]{60,}$~ OK
# Mettez vos propres motifs de corps ici.
