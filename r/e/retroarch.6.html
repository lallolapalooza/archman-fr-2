NOM

retroarch - Le frontend de référence pour l'API libretro.

SYNTAXE

retroarch [fichier(s) rom] [OPTIONS]...

DESCRIPTION

retroarch est le frontend de référence pour l'API libretro. libretro est une abstraction d'un système de jeu et peut être implémentée par n'importe quel frontend. L'API libretro est conçue pour les jeux, les émulateurs et le multimédia. retroarch se concentre sur l'exposition des fonctionnalités nécessaires au système de jeu via l'utilisation de la ligne de commande et de fichiers de configuration. Il dispose également d'une simple interface utilisateur intégrée.

EXEMPLE LIGNE DE COMMANDE

Charger du contenu, en utilisant un noyau libretro et un fichier de configuration spécifiques.
retroarch --config ~/.config/retroarch/retroarch.cfg --libretro /chemin/vers/noyau/libretro.so /chemin/vers/rom.rom --verbose
Aucune option de ligne de commande ne lancera RetroArch en mode menu.
retroarch
Lancer RetroArch en mode menu, avec journalisation détaillée.
retroarch --menu --verbose

Menu

Fait référence au système d'interface graphique intégré de RetroArch. Il est conçu pour être contrôlé uniquement avec une manette de jeu.

CONTROLES PAR DÉFAUT

Par défaut, seule l'entrée clavier est acceptée.

OPTIONS GÉNÉRALES

[fichier rom]
Si aucun chemin de fichier rom n'est défini sur la ligne de commande, retroarch essaiera de charger un noyau sans rom. Cela ne fonctionnera qu'avec certains noyaux libretro. retroarch utilise du contenu non compressé, mais peut décompresser du contenu au format .zip/deflate si le support est compilé. Les types de contenu pris en charge dépendent de l'implémentation libretro utilisée.
--aide, -h
Affiche le texte d'aide.
--menu
Démarre directement dans le menu en jeu si activé. Ne nécessite pas que le contenu ou l'implémentation libretro soient définis. Ceux-ci peuvent être chargés ultérieurement dans le menu. Si aucun argument n'est passé à retroarch, cela équivaut à appeler retroarch avec ceci comme seul argument.
--features
Affiche les fonctionnalités disponibles compilées dans RetroArch, puis quitte.
-L CHEMIN, --libretro CHEMIN
Chemin vers une implémentation libretro qui doit être utilisée. Cette option remplacera tout réglage dans un fichier de configuration. Cette option n'est disponible que si RetroArch est compilé avec le chargement dynamique de libretro.
--save CHEMIN, -s CHEMIN
Remplace le chemin utilisé pour la mémoire de sauvegarde (*.srm) (obsolète). Sans ce drapeau, le chemin de la mémoire de sauvegarde sera inféré du nom du fichier rom, et placé dans le même répertoire que le fichier rom avec l'extension remplacée par '.srm'. Si CHEMIN est un répertoire, RetroArch le traitera comme le répertoire des fichiers de sauvegarde, où le nom du fichier de sauvegarde sera inféré du nom du rom.
--savestate CHEMIN, -S CHEMIN
Remplace le chemin utilisé pour les états de sauvegarde (obsolète). Sans ce drapeau, le chemin de l'état de sauvegarde sera inféré du nom du fichier rom, et placé dans le même répertoire que le fichier rom avec l'extension remplacée par '.state'. Si CHEMIN est un répertoire, RetroArch le traitera comme le répertoire des états de sauvegarde, où le nom du fichier d'état sera inféré du nom du rom. Notez que les états de sauvegarde sont liés à l'implémentation libretro utilisée. L'utilisation d'un libretro différent pourrait invalider le fichier d'état de sauvegarde.
--fullscreen, -f
Lance toujours RetroArch en plein écran. Ignore les réglages du fichier de configuration.
--config CHEMIN, -c CHEMIN
Définit le chemin du fichier de configuration. retroarch utilisera ce chemin pour charger le fichier de configuration. S'il n'est pas défini, retroarch recherchera dans les chemins spécifiques à la plateforme pour tenter de trouver le fichier de configuration. /etc/retroarch.cfg (lorsqu'il est installé), ou retroarch.cfg dans l'archive source sert de fichier de configuration squelette. /etc/retroarch.cfg devrait servir uniquement de squelette de configuration.
Les systèmes de type Unix rechercheront d'abord dans $XDG_CONFIG_HOME/retroarch/retroarch.cfg. Si $XDG_CONFIG_HOME n'est pas défini, il sera supposé être $HOME/.config conformément à la spécification. Ensuite, il essaiera $HOME/.retroarch.cfg. Si les deux chemins échouent, RetroArch essaiera de créer un nouveau fichier de configuration par défaut dans $XDG_CONFIG_HOME/retroarch/retroarch.cfg (ou la valeur par défaut de $HOME/.config pour $XDG_CONFIG_HOME). Si tout échoue, les paramètres par défaut seront supposés. Si RetroArch crée un nouveau fichier de configuration par défaut, il tentera de charger le fichier squelette /etc/retroarch.cfg et l'utilisera comme base. Cela permet aux distributions de définir des chemins par défaut pour les noyaux libretro, et des choses similaires. Un fichier de configuration n'a pas besoin de définir toutes les options possibles, seulement celles qui doivent être remplacées.

Si config_save_on_exit = true est défini dans le fichier de configuration, RetroArch écrasera le fichier de configuration à la sortie. Les paramètres peuvent être modifiés depuis le menu. Si RetroArch écrase un fichier de configuration, le formatage, les commentaires, etc. seront perdus. Si RetroArch crée un fichier de configuration par défaut, il aura automatiquement config_save_on_exit défini.

Windows recherchera retroarch.cfg dans le même dossier où se trouve retroarch.exe. Un fichier de configuration par défaut sera également créé de la même manière que sur Unix.
--appendconfig CHEMIN
Ajoute un ensemble différent de fichiers de configuration au fichier de configuration chargé avec -c (ou par défaut). Plusieurs fichiers de configuration sont délimités par ','. Chaque fichier de configuration sera ajouté dans l'ordre où les paires clé-valeur du fichier de configuration suivant ont priorité sur les anciens.
--subsystem SOUS_SYSTEME
Utilise un sous-système du noyau libretro chargé. Plusieurs fichiers de contenu sont chargés comme plusieurs arguments. Si du contenu est sauté, utilisez un argument de ligne de commande vide (""). Le contenu doit être chargé dans un ordre qui dépend du sous-système particulier utilisé. Voir la sortie du journal détaillée pour savoir comment un sous-système particulier souhaite que le contenu soit chargé.
--nodevice PORT, -N PORT
Déconnecte un périphérique d'entrée du port numéro PORT. Les valeurs possibles pour PORT sont de 1 à 8. Cela peut être nécessaire pour que certains jeux étranges fonctionnent correctement. Si défini explicitement ici, remplace le fichier de configuration pour ce port.
--dualanalog PORT, -A PORT
Connecte une manette DualAnalog au port PORT. Les valeurs possibles sont de 1 à 8. Si défini explicitement ici, remplace le fichier de configuration pour ce port.
--device PORT:ID, -d PORT:ID
Connecte un périphérique d'entrée générique ID au port PORT. Les valeurs possibles pour le port sont de 1 à 8. Si défini explicitement ici, remplace le fichier de configuration pour ce port. ID est un nombre non signé correspondant au périphérique pour un noyau libretro.
--record CHEMIN, -r CHEMIN
Active l'enregistrement vidéo du gameplay dans CHEMIN. L'utilisation de l'extension .mkv est recommandée. Les codecs utilisés sont (FFV1 ou H264 RGB sans perte (x264))/FLAC, adaptés au traitement ultérieur du matériel.
--recordconfig CHEMIN
Définit le chemin vers un fichier de configuration à utiliser pendant l'enregistrement.
--size LARGEURxHAUTEUR
Permet de spécifier la largeur et la hauteur de sortie exactes de l'enregistrement. Cette option remplacera tous les réglages de configuration. L'entrée vidéo est mise à l'échelle avec un filtrage par points avant d'être encodée à la bonne taille.
--play-replay CHEMIN, -P CHEMIN

--record-replay CHEMIN, -R CHEMIN
Commence à enregistrer une vidéo au format .replay vers CHEMIN immédiatement après le démarrage.
--sram-mode MODE, -M MODE
MODE désigne comment gérer la SRAM. Le format du second paramètre est {no,}load-{no,}save. Ces deux valeurs booléennes indiquent si le chargement de la SRAM et la sauvegarde de la SRAM doivent avoir lieu. Notez que noload-save implique que la SRAM sera écrasée par de nouvelles données.
--verbose, -v
Active la journalisation détaillée.
--host, -H
Être l'hôte du netplay. Attend qu'un utilisateur se connecte. L'hôte assumerait toujours l'utilisateur 1.
--connect SERVEUR, -C SERVEUR
Se connecter à un hôte de netplay. Assumerait toujours l'utilisateur 2.
--frames FRAMES, -F FRAMES
Images de synchronisation à utiliser lors de l'utilisation du netplay. Plus d'images permettent une latence plus importante, mais nécessitent plus de puissance CPU. Définir FRAMES à 0 pour une synchronisation parfaite. 0 images ne convient que pour le réseau local (LAN). Par défaut à 0.
--port PORT
Port réseau utilisé pour le netplay. Par défaut, il s'agit de 55435. Cette option affecte à la fois TCP et UDP.
--spectate
Si le netplay est utilisé, il passera en mode spectateur. Le mode spectateur permet à un hôte de diffuser en direct la lecture du jeu à plusieurs clients. Essentiellement, les clients reçoivent un fichier de film de replay diffusé en direct. Les clients peuvent se connecter et se déconnecter à tout moment. Les clients ne peuvent donc pas interagir en tant qu'utilisateur 2. Pour que le mode spectateur fonctionne, l'hôte et les clients devront utiliser ce drapeau.
--command COMMANDE
Envoie une commande via UDP à une application RetroArch déjà en cours d'exécution, et quitte. La commande est formatée comme "COMMANDE;HOTE;PORT". HOTE et PORT sont tous deux optionnels. "COMMANDE;HOTE" définira le PORT sur le réglage par défaut de "network_cmd_port". Si seule "COMMANDE" est utilisée, HOTE et PORT seront supposés être "localhost" et "network_cmd_port" respectivement.

Les commandes disponibles sont listées si "COMMANDE" est invalide.

--nick NICK
Choisir un surnom à utiliser avec le netplay. Ceci est purement cosmétique et sert uniquement à aider les utilisateurs à s'identifier mutuellement.
--ups PATCH, -U PATCH
Tente d'appliquer un patch UPS à l'image de contenu actuelle. Aucun fichier n'est modifié. Si ce drapeau n'est pas spécifié, RetroArch recherchera un fichier .ups avec le même nom de base que le contenu spécifié.
--bps PATCH
Tente d'appliquer un patch BPS à l'image de contenu actuelle. Aucun fichier n'est modifié. Si ce drapeau n'est pas spécifié, RetroArch recherchera un fichier .bps avec le même nom de base que le contenu spécifié.
--ips PATCH
Tente d'appliquer un patch IPS à l'image de contenu actuelle. Aucun fichier n'est modifié. Si ce drapeau n'est pas spécifié, RetroArch recherchera un fichier .ips avec le même nom de base que le contenu spécifié. Notez que RetroArch ne peut effectuer aucun contrôle d'erreur si le patch a été appliqué avec succès en raison du fonctionnement de l'IPS.
--xdelta PATCH
Tente d'appliquer un patch Xdelta à l'image de contenu actuelle. Aucun fichier n'est modifié. Si ce drapeau n'est pas spécifié, RetroArch recherchera un fichier .xdelta avec le même nom de base que le contenu spécifié. Uniquement disponible si RetroArch a été compilé avec le support Xdelta.
--no-patch
Désactive tous les types de patchs de contenu.
-D, --detach
Détacher de la console actuelle. Ceci n'est actuellement pertinent que pour Microsoft Windows.

ENVIRONNEMENT

retroarch respecte les variables d'environnement suivantes :

LIBRETRO_DIRECTORY
Spécifie le répertoire où RetroArch recherche les fichiers de cœur et d'information, en remplaçant la valeur de l'option de fichier de configuration "libretro_directory".
LIBRETRO_ASSETS_DIRECTORY
Spécifie le répertoire où RetroArch recherche les ressources, en remplaçant la valeur de l'option de fichier de configuration "assets_directory".
LIBRETRO_AUTOCONFIG_DIRECTORY
Spécifie le répertoire où RetroArch recherche les fichiers d'auto-configuration de manette, en remplaçant la valeur de l'option de fichier de configuration "joypad_autoconfig_dir".
LIBRETRO_CHEATS_DIRECTORY
Spécifie le répertoire où RetroArch recherche les fichiers de triche, en remplaçant la valeur de l'option de fichier de configuration "cheat_database_path".
LIBRETRO_DATABASE_DIRECTORY
Spécifie le répertoire où RetroArch recherche les fichiers de base de données, en remplaçant la valeur de l'option de fichier de configuration "content_database_path".
LIBRETRO_SYSTEM_DIRECTORY
Spécifie le répertoire où RetroArch recherche les fichiers système, en remplaçant la valeur de l'option de fichier de configuration "system_directory".
LIBRETRO_VIDEO_FILTER_DIRECTORY
Spécifie le répertoire où RetroArch recherche les filtres vidéo, en remplaçant la valeur de l'option de fichier de configuration "video_filter_dir".
LIBRETRO_VIDEO_SHADER_DIRECTORY
Spécifie le répertoire où RetroArch recherche les shaders vidéo, en remplaçant la valeur de l'option de fichier de configuration "video_shader_dir". option.
