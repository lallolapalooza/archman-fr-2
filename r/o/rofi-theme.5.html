NOM

rofi-theme - Fichiers de format de thème Rofi

Démarrage avec les thèmes

La manière la plus simple de commencer à thématiser rofi est de modifier votre thème existant.

Les thèmes peuvent être modifiés/ajustés en ajoutant des éléments de thème à la fin du

fichier de configuration. L'emplacement par défaut de ce fichier est ~/.config/rofi/config.rasi, si le fichier n'existe pas, vous pouvez le créer.

Une configuration de base :

configuration {
  modes: [ combi ];
  combi-modes: [ window, drun, run ];
}
@theme "gruvbox-light"
/* Insérez les modifications du thème après ceci */

Par exemple, si nous voulons changer le texte **Type to filter** dans la boîte d'entrée, nous ajoutons ce qui suit :

entry {
    placeholder: "Tapez ici";
}

Dans la section ci-dessus, entry indique le widget, placeholder est la propriété que nous voulons modifier et nous la définissons à la chaîne "Tapez ici". Pour trouver les widgets couramment disponibles dans rofi, consultez la section 'Structure de base'.

Pour changer le curseur de la souris en pointeur, ajoutez :

entry {
    placeholder: "Tapez ici";
    cursor: pointer;
}

Pour la modification suivante, nous voulons ajouter l'icône après chaque élément textuel et augmenter la taille. D'abord, nous commençons par modifier le widget element :

element {
  orientation: horizontal;
  children: [ element-text, element-icon ];
  spacing: 5px;
}

Résultant du packing suivant :

┌─────────────────────────────────────────────────────────────────────┐ 
│ element                                                             │ 
│ ┌─────────────────────────────────────────────┐ ┌─────────────────┐ │ 
│ │element─text                                 │ │ element─icon    │ │ 
│ └─────────────────────────────────────────────┘ └─────────────────┘ │ 
└─────────────────────────────────────────────────────────────────────┘

Le widget element (conteneur) contient chaque entrée dans le listview, nous ajoutons les deux enfants prédéfinis dans l'ordre où nous voulons les afficher. Nous spécifions également la direction du empilement (orientation) et l'espacement entre les enfants (spacing). Nous spécifions l'espace entre les deux enfants en pixels absolus (px).

Pour augmenter la taille de l'icône, nous devons modifier le widget element-icon.

element-icon {
    size: 2.5em;
}

┌─────────────────────────────────────────────────────────────────────┐ 
│ element                                                             │ 
│ ┌─────────────────────────────────────────────┐ ┌─────────────────┐ │ 
│ │element─text                                 │ │    element      │ │ 
│ │                                             │ │       ─         │ │ 
│ │                                             │ │     icon        │ │ 
│ └─────────────────────────────────────────────┘ └─────────────────┘ │ 
└─────────────────────────────────────────────────────────────────────┘

Dans cet exemple, nous spécifions la taille dans l'unité em.

Maintenant, changeons la couleur du texte des widgets entry et element-text en rouge et l'arrière-plan en bleu.

entry, element-text {
  text-color: red;
  background-color: rgb(0,0,255);
}

Ici, nous utilisons deux méthodes différentes pour écrire la couleur : pour text-color nous avons utilisé une couleur nommée, pour background-color nous l'avons spécifiée en rgb. Nous spécifions également la propriété pour plusieurs widgets en passant une liste de noms de widgets séparés par des virgules.

Si vous voulez centrer le texte par rapport à l'icône, nous pouvons définir ceci :

element-text {
    vertical-align: 0.5;
}

┌─────────────────────────────────────────────────────────────────────┐ 
│ element                                                             │ 
│ ┌─────────────────────────────────────────────┐ ┌─────────────────┐ │ 
│ │element─text                                 │ │    element      │ │ 
│ │                                             │ │       ─         │ │ 
│ │                                             │ │     icon        │ │ 
│ └─────────────────────────────────────────────┘ └─────────────────┘ │ 
└─────────────────────────────────────────────────────────────────────┘

Dans cet exemple, nous utilisons une valeur de 0.5 pour représenter le milieu vertical.

Il existe deux ensembles de propriétés pour la disposition : layout et children. La propriété layout est utilisée pour disposer les enfants dans le widget conteneur. Par défaut, le conteneur est organisé de gauche à droite.

La propriété children est utilisée pour spécifier les widgets qui doivent être inclus dans le widget conteneur.

Par exemple, nous pouvons vouloir changer l'ordre des enfants, de sorte que l'icône vienne en premier.

element {
  children: [ element-icon, element-text ];
}

Pour obtenir le résultat suivant :

┌─────────────────────────────────────────────────────────────────────┐ 
│ element                                                             │ 
│ ┌─────────────────────────────────────────────┐ ┌─────────────────┐ │ 
│ │    element      │ │element─text                                 │ │ 
│ │       ─         │ │                                             │ │ 
│ │     icon        │ │                                             │ │ 
│ └─────────────────────────────────────────────┘ └─────────────────┘ │ 
└─────────────────────────────────────────────────────────────────────┘

Par défaut, rofi affiche le widget element-text avant le widget element-icon. En remplaçant la propriété children, nous pouvons facilement changer l'ordre.

La dernière modification que nous allons apporter est l'ajout d'une bordure autour de chaque élément.

element {
  border: 2px dash red;
}

Ceci ajoutera une bordure rouge de 2 pixels de style pointillé autour de chaque élément.

Le style de bordure peut être défini en utilisant les mots-clés suivants :

solid
Bordure pleine.
dashed
Bordure pointillée.
dotted
Bordure avec des points.

Il est également possible de modifier le remplissage de chaque élément.

element {
  padding: 5px;
}

Ceci ajoutera un espacement de 5 pixels à l'intérieur de chaque élément, entre le contenu et la bordure.

STRUCTURE DE BASE

Rofi utilise une structure imbriquée de widgets pour construire son interface utilisateur. Les widgets sont organisés de manière hiérarchique, chaque widget pouvant contenir d'autres widgets.

La structure de base est la suivante :

window
Le widget principal qui contient tous les autres widgets.
module
Un widget qui peut contenir d'autres widgets. Utilisé pour regrouper des éléments liés.
bar
Un widget qui affiche une barre horizontale ou verticale. Peut contenir d'autres widgets.
listview
Un widget qui affiche une liste d'éléments. Chaque élément est un widget element.
element
Un widget qui représente un élément individuel dans un listview.
element-icon
Un widget qui affiche une icône.
element-text
Un widget qui affiche du texte.
entry
Un widget qui permet la saisie de texte par l'utilisateur.

Les widgets peuvent être stylisés en utilisant diverses propriétés, telles que : background-color, text-color, padding, border, font, etc.

PROPRIÉTÉS

Les propriétés suivantes peuvent être utilisées pour styliser les widgets :

text-color
La couleur du texte.
background-color
La couleur de l'arrière-plan.
padding
L'espacement intérieur d'un widget.
margin
L'espacement extérieur d'un widget.
border
La bordure d'un widget (épaisseur, style, couleur).
font
La police de caractères utilisée pour le texte.
cursor
Le type de curseur de la souris à afficher.
placeholder
Le texte indicatif affiché dans un champ de saisie lorsque celui-ci est vide.
orientation
L'orientation d'un widget conteneur (horizontal ou vertical).
children
La liste des widgets enfants à inclure dans un widget conteneur.
spacing
L'espacement entre les widgets enfants.
vertical-align
L'alignement vertical du contenu d'un widget.
size
La taille d'un widget (par exemple, une icône).

Nous pouvons également personnaliser la couleur et la largeur du curseur, et choisir de le masquer lorsque la boîte de saisie est vide. Vous pourriez, par exemple, créer un curseur bloc cramoisi qui n'apparaît que lorsque du texte est saisi, comme ceci :

entry {
  cursor-color: rgb(220,20,60);
  cursor-width: 8px;
  hide-cursor-on-empty: true;
}

Par défaut, la cursor-color sera la même que la text-color. La cursor-width sera toujours de 2 pixels par défaut et hide-cursor-on-empty sera défini sur false.

Si vous souhaitez voir le thème complet, y compris les modifications, vous pouvez exécuter :

rofi -dump-theme

Chargement du thème par défaut

Par défaut, rofi charge le thème par défaut. Ce thème est toujours chargé. La configuration par défaut contient :

@theme "default"

Pour décharger le thème par défaut et charger un autre thème, ajoutez l'instruction @theme à votre fichier config.rasi.

Si vous avez un thème chargé via @theme ou utilisez le thème par défaut, vous pouvez le modifier en ajoutant des éléments de remplacement à la fin de votre fichier config.rasi.

Pour connaître la différence entre @import et @theme, consultez la section Gestion de plusieurs fichiers de cette page de manuel.

Pour voir le thème par défaut, exécutez la commande suivante :

rofi -no-config -dump-theme

Description

Le besoin d'un nouveau format de thème a été motivé par la façon dont rofi gérait les widgets. D'un dessin très statique de lignes et de texte à une forme structurée agréable d'empilement de widgets. Ce changement a permis de fournir un cadre de thème plus flexible. L'ancien format de thème et le fichier de configuration n'étaient pas assez flexibles pour exposer ces options de manière conviviale. Par conséquent, un nouveau format de fichier a été créé, remplaçant l'ancien.

Spécification du format

Encodage

L'encodage du fichier est UTF-8. Les deux sauts de ligne Unix (\n) et Windows (\r\n) sont supportés. Mais Unix est préféré.

Commentaires

Les commentaires de style C et C++ sont supportés.

•
Tout ce qui suit // et précède un saut de ligne est considéré comme un commentaire.
•
Tout ce qui se trouve entre /* et */ est un commentaire, ce commentaire peut s'étendre sur plusieurs lignes.

Les commentaires peuvent être imbriqués et les commentaires C peuvent être en ligne.

Ce qui suit est valide :

// Commentaire magique.
propriété: /* commentaire */ valeur;

Cependant, ceci ne l'est pas :

prop/*commentaire*/riété: valeur;

Espace blanc

Les espaces blancs et les sauts de ligne, comme les commentaires, sont ignorés par l'analyseur.

Ceci :

propriété: nom;

Est identique à :

     propriété             :
nom
;

Extension de fichier

L'extension de fichier préférée pour le nouveau format de thème est rasi. C'est une abréviation pour rofi advanced style information. Si un fichier de thème est divisé en plusieurs fichiers, les fichiers inclus peuvent avoir l'extension : rasinc.

Structure de base

Chaque élément a une section avec des propriétés définies. Les propriétés globales peuvent être définies dans la section * { }. Les noms des sous-sections commencent par un symbole dièse optionnel #.

Il est conseillé de définir la section des propriétés globales en haut du fichier pour rendre l'héritage des propriétés plus clair.

/* Section des propriétés globales */
* {
    // liste des propriétés
}
/* Section de thème de l'élément. */
{chemin_élément} {
    // liste des propriétés
}
{éléments... } {
    // liste des propriétés
}

S'il y a plusieurs sections du même nom, elles sont fusionnées. Les propriétés dupliquées sont écrasées et la dernière entrée analysée est conservée.

Section des propriétés globales

Un thème peut avoir une ou plusieurs sections de propriétés globales. S'il y en a plus d'une, elles seront fusionnées.

La section des propriétés globales désigne les valeurs par défaut pour chaque élément. Chaque propriété de cette section peut être référencée avec @{identificateur} (Voir section Propriétés)

Une section de propriétés globales est indiquée par un * comme chemin d'élément.

Section de thème d'élément

Un thème peut avoir plusieurs sections de thème d'élément.

Le chemin de l'élément peut être composé de plusieurs noms séparés par des espaces blancs ou des points. Chaque élément peut contenir n'importe quel nombre de lettres, de chiffres et de tirets -. Le premier élément du chemin de l'élément peut commencer facultativement par un # (pour des raisons historiques). Plusieurs éléments peuvent être spécifiés par une ,.

Ceci est un nom d'élément valide :

element normal.normal {
    background-color: bleu;
}
button {
    background-color: bleu;
}

Et est identique à :

element normal normal, button {
    background-color: bleu;
}

Chaque section hérite des propriétés globales. Les propriétés peuvent être explicitement héritées de leur parent avec le mot-clé inherit. Dans l'exemple suivant :

window {
 a: 1;
 b: 2;
 children: [ mainbox ];
}
mainbox {
    a: inherit;
    b: 4;
    c: 8;
}

L'élément mainbox aura l'ensemble de propriétés suivant (si mainbox est un enfant de window) :

a: 1;
b: 4;
c: 8;

Si plusieurs sections du même nom sont définies, elles sont fusionnées par l'analyseur. Si plusieurs propriétés du même nom sont définies dans une seule section, la dernière propriété rencontrée est utilisée.

Format des propriétés

Les propriétés d'une section consistent en :

{identificateur}: {valeur};

Les deux champs sont obligatoires pour une propriété.

L'identificateur nomme la propriété spécifiée. Les identificateurs peuvent être composés de n'importe quelle combinaison de chiffres, de lettres et de `-'. Ils ne doivent pas contenir d'espaces blancs. La structure de la valeur définit le type de la propriété. L'analyseur actuel ne définit ni n'impose un type particulier pour un identificateur donné. Lorsqu'elles sont utilisées, les valeurs de type incorrect qui ne peuvent pas être converties sont ignorées.

Le format de thème actuel prend en charge différents types :

•
une chaîne de caractères
•
un nombre entier
•
un nombre fractionnaire
•
une valeur booléenne
•
une couleur
•
une image
•
un style de texte
•
un style de ligne
•
une distance
•
un remplissage (padding)
•
une bordure
•
une position
•
une référence
•
une orientation
•
un curseur
•
une liste de mots-clés
•
un tableau de valeurs
•
une variable d'environnement

Héritage

Certains de ces types sont une combinaison d'autres types.

Chaîne de caractères

•
Format : (["'])[:print:]+\1

Les chaînes de caractères sont toujours entourées de guillemets doubles (") ou simples (', apostrophe). Entre les guillemets, il peut y avoir n'importe quel caractère imprimable.

Par exemple :

font: "Awasome 12"
quot;;

La chaîne doit être en UTF-8 valide, les caractères spéciaux peuvent être échappés :

text { content: "Ligne un\n\tLigne deux indentée 'Texte entre guillemets'"; }
text { content: 'Ligne un\n\tLigne deux indentée "Texte entre guillemets"'; }
text { content: "Ligne un\n\tLigne deux indentée \"Texte entre guillemets\""; }

Les caractères spéciaux suivants peuvent être échappés : \b, \f, \n, \r, \t, \v, \, " et ' (les guillemets doubles à l'intérieur de guillemets simples ou inversement n'ont pas besoin d'être échappés).

Entier

•
Format : [-+]?[:digit:]+

Un entier peut contenir n'importe quel nombre.

Exemples :

lines: 12;

Réel

•
Format : [-+]?[:digit:]+(\.[:digit:]+)?

Un réel est un entier avec une partie fractionnaire optionnelle.

Par exemple :

real: 3.4;

Les éléments suivants ne sont pas valides : .3, 3. ou la notation scientifique : 3.4e-3.

Booléen

•
Format : (true|false)

La valeur booléenne est soit true, soit false. Ceci est sensible à la casse.

Par exemple :

dynamic: false;

Image

rofi supporte un ensemble limité de formats d'image d'arrière-plan.

•
Format : url(“chemin vers l'image”);
•
Format : url(“chemin vers l'image”, scale); où scale est : none, both, width, height
•
Format : linear-gradient(couleur_de_fin, couleur1, couleur2, ...);
•
Format : linear-gradient(vers direction, couleur_de_fin, couleur1, couleur2, ...); où direction est : top,left,right,bottom.
•
Format : linear-gradient(angle, couleur_de_fin, couleur1, couleur2, ...); Angle en deg,rad,grad (comme utilisé pour les couleurs).

Où le chemin est une chaîne de caractères, et la couleur de fin est de type couleur.

•
Format : #{HEX}{4} (rgba)
•
Format : #{HEX}{6} (rrggbb)
•
Format : #{HEX}{8} (rrggbbaa)

Format : rgb[a]({ENTIER},{ENTIER},{ENTIER}[, {POURCENTAGE}])
•
Format : rgb[a]({ENTIER}%,{ENTIER}%,{ENTIER}%[, {POURCENTAGE}])
•
Format : hsl[a]( {ANGLE}, {POURCENTAGE}, {POURCENTAGE} [, {POURCENTAGE}])
•
Format : hwb[a]( {ANGLE}, {POURCENTAGE}, {POURCENTAGE} [, {POURCENTAGE}])
•
Format : cmyk( {POURCENTAGE}, {POURCENTAGE}, {POURCENTAGE}, {POURCENTAGE} [, {POURCENTAGE} ])

Format : {nom-couleur} [ / {POURCENTAGE} ]

Le format de l'espace blanc proposé dans CSS4 est également supporté.

Style de texte

•
Format : (bold|italic|underline|strikethrough|none)

Le style du texte indique comment le texte mis en surbrillance est mis en emphase. None indique qu'aucune emphase ne doit être appliquée.

•
bold : rend le texte plus épais que le texte environnant.
•
italic : met le texte mis en surbrillance dans un type d'écriture (incliné).
•
underline : place une ligne sous le texte.
•
strikethrough : place une ligne à travers le texte.

Les options suivantes sont disponibles à partir de pango 1.50.0 :

•
uppercase : Met le texte en majuscules.
•
lowercase : Met le texte en minuscules.

L'option suivante est désactivée car pango plante dessus s'il y a un redimensionnement ou un retour à la ligne. Elle sera réactivée une fois corrigée :

•
capitalize : Met la première lettre de chaque mot en majuscule.

Style de ligne

•
Format : (dash|solid)

Indique comment une ligne doit être dessinée. Elle supporte actuellement :

•
dash : une ligne discontinue, où l'espace est de la même largeur que le trait
•
solid : une ligne continue

Distance

•
Format : {Entier}px
•
Format : {Réel}em
•
Format : {Réel}ch
•
Format : {Réel}%
•
Format : {Réel}mm

Une distance peut être spécifiée en 3 unités différentes :

•
px : Pixels de l'écran.
•
em : Relative à la hauteur du texte.
•
ch : Relative à la largeur d'un seul chiffre.
•
mm : Taille réelle en millimètres (basée sur les dpi).
•
% : Pourcentage de la taille de l'écran.

Les distances utilisées dans la direction horizontale utilisent la largeur de l'écran. Les distances dans la direction verticale utilisent la hauteur de l'écran. Par exemple :

   padding: 10%;

Sur un écran full-HD (1920x1080), cela définit un remplissage de 192 pixels sur les côtés gauche et droit et 108 pixels en haut et en bas.

Calcul des tailles

Rofi supporte certaines opérations mathématiques pour le calcul des tailles. Pour cela, il utilise la syntaxe CSS :

width: calc( 100% - 37px );

width: calc( 20% min 512 );

Il supporte les opérations suivantes :

•
+ : Addition
•
- : Soustraction
•
/ : Division
•
\* : Multiplication
•
modulo : Modulo
•
min : Minimum entre la valeur de gauche et la valeur de droite ;
•
max : Maximum entre la valeur de gauche et la valeur de droite ;
•
floor : Arrondit la valeur de gauche à la baisse au multiple le plus proche de la valeur de droite
•
ceil : Arrondit la valeur de gauche à la hausse au multiple le plus proche de la valeur de droite
•
round : Arrondit la valeur de gauche au multiple le plus proche de la valeur de droite

Il utilise l'ordre de priorité de C.

Format : (center|east|north|west|south|north east|north west|south west|south east)

Visibilité

Il est possible de masquer les widgets :

inputbar {

Référence

•
Format : @{NOM DE LA PROPRIÉTÉ}

Une référence peut pointer vers une autre référence. Actuellement, le nombre maximum de redirections est de 20. Une propriété fait toujours référence à une autre propriété. Elle ne peut pas être utilisée pour une sous-partie de la propriété. Par exemple, ceci n'est pas valide :

highlight: bold @pink;

Mais ceci l'est :

* {
    myhigh: bold #FAA;
}
window {
    highlight: @myhigh;
}
•
Format : var( NOM DE LA PROPRIÉTÉ, DÉFAUT)

Une référence peut pointer vers une autre référence. Actuellement, le nombre maximum de redirections est de 20. Une propriété fait toujours référence à une autre propriété. Elle ne peut pas être utilisée pour une sous-partie de la propriété.

Exemple :

window {
    width: var( width, 30%);
}

Si la propriété width est définie globalement (*{}), cette valeur est utilisée ; si la propriété width n'est pas définie, la valeur par défaut est utilisée.

Orientation

•
Format : (horizontal|vertical)

Spécifie l'orientation du widget.

Curseur

•
Format : (default|pointer|text)

Spécifie le type de curseur de souris qui est défini lorsque le pointeur de la souris se trouve sur le widget.

Liste des mots-clés

•
Format : [ mot-clé, mot-clé ]

Une liste commence par un `[` et se termine par un `]'. Les entrées de la liste sont séparées par des virgules. Le mot-clé dans la liste fait référence à un nom de widget.

Liste des valeurs

•
Format : [ valeur, valeur, ... ]

Une liste commence par un `[` et se termine par un `]'. Les entrées de la liste sont séparées par des virgules.

Variable d'environnement

•
Format : ${:alnum:}

Ceci analysera la variable d'environnement comme valeur de propriété. (qui peut alors être de n'importe quel type ci-dessus). La variable d'environnement doit être une chaîne alphanumérique sans espaces blancs.

* {
    background-color: ${BG};
}
•
Format : env(ENVIRONNEMENT, défaut)

Ceci analysera la variable d'environnement comme valeur de propriété. (qui peut alors être de n'importe quel type ci-dessus). La variable d'environnement doit être une chaîne alphanumérique sans espaces blancs. Si la valeur d'environnement n'est pas trouvée, la valeur par défaut est utilisée.

window {
    width: env(WIDTH, 40%);
}

Si l'environnement WIDTH est défini, alors cette valeur est analysée, sinon la valeur par défaut (40%).

Hériter

•
Format : inherit

Hérite de la propriété de son widget parent.

mainbox {
    border-color: inherit;
}

Chemins des éléments

Les chemins d'éléments sont constitués de deux parties, la première partie fait référence au widget réel par son nom. Certains widgets ont un état supplémentaire.

Par exemple :

element selected {
}

Ici, element selected est le nom du widget, selected est l'état du widget.

La différence entre les points et les espaces est purement cosmétique. Ceux-ci sont tous identiques :

element .selected {
element.selected {
}
element selected {
}

mise en surbrillance du texte de la listview

Le widget element-text dans la listview est celui utilisé pour afficher le texte.   element-text {

textbox-custom {

}

Ceci est un widget d'icône. L'icône affichée peut être définie avec filename et la taille avec size. Si la propriété action est définie, il agit comme un bouton. action peut être défini sur un nom de raccourci clavier et exécute cette action. (voir rofi -show keys pour une liste).

icon-paste {

    filename: "gtk-paste";
    size: 24;

}

Tout comme CSS, rofi utilise le modèle de boîte pour chaque widget.

Explication des différentes parties :

•
Contenu - Le contenu du widget.
•
Rembourrage - Nettoie une zone autour du widget. Le rembourrage affiche la couleur de fond du widget.
•
Bordure - Une bordure qui entoure le rembourrage et le contenu. La bordure utilise la couleur de bordure du widget.
•
Marge - Nettoie une zone à l'extérieur de la bordure. La marge est transparente.

Le modèle de boîte nous permet d'ajouter une bordure autour des éléments et de définir un espace entre les éléments.

La taille de chaque marge, bordure et rembourrage peut être définie. Pour la bordure, un style de ligne et un rayon peuvent être définis.

Un espacement plus dynamique peut être obtenu en ajoutant des widgets factices, par exemple pour centrer un widget :

│  ┌───────────────┐  ┌────────┐  ┌───────────────┐  │
│  │ dummy         │  │ child  │  │ dummy         │  │
│  │ expand: true; │  │        │  │ expand: true; │  │
│  │               │  │        │  │               │  &#x
2502; │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ └───────────────┘ └────────┘ └───────────────┘ │ └────────────────────────────────────────────────────┘

Si les deux widgets factices sont configurés pour s'étendre, child sera centré. En fonction de l'indicateur expand de l'enfant, l'espace restant sera divisé équitablement entre le widget factice et l'enfant (expand activé), ou entre les deux widgets factices (expand désactivé).

Débogage

Pour obtenir des informations de débogage de l'analyseur, exécutez rofi comme suit :

G_MESSAGES_DEBUG=Parser rofi -show run

Les erreurs de syntaxe sont affichées dans une fenêtre pop-up et imprimées sur la ligne de commande avec la commande ci-dessus.

Pour voir les éléments interrogés pendant l'exécution, exécutez :

G_MESSAGES_DEBUG=Theme rofi -show run

Pour tester des modifications mineures, une partie du thème peut être passée sur la ligne de commande, par exemple pour le définir en plein écran :

rofi -theme-str 'window { fullscreen:true;}' -show run

Une autre syntaxe pour modifier les propriétés du thème est :

rofi -theme+window+fullscreen true -show run

Pour imprimer le thème actuel, exécutez :

rofi -dump-theme

Support médiatique

Des parties du thème peuvent être chargées conditionnellement, comme l'option CSS @media.

@media ( min-width: 120 ) {
}

Il prend en charge les clés suivantes comme contrainte :

•
min-width : charge lorsque la largeur est supérieure ou égale à la valeur.
•
max-width : charge lorsque la largeur est inférieure à la valeur.
•
min-height : charge lorsque la hauteur est supérieure ou égale à la valeur.
•
max-height : charge lorsque la hauteur est inférieure à la valeur.
•
min-aspect-ratio charge lorsque le rapport d'aspect est supérieur à la valeur.
•
max-aspect-ratio : charge lorsque le rapport d'aspect est inférieur à la valeur.
•
monitor-id : l'ID du moniteur, voir rofi -help pour les IDs.
•
enabled : option booléenne pour activer. Prend en charge la variable d'environnement ou DMENU pour détecter s'il s'agit du mode dmenu.

@media prend un nombre entier ou une fraction, pour un nombre entier px peut être ajouté.

@media ( min-width: 120 px ) {
}

@media ( enabled: env(DO_LIGHT, false )) {
}

@media ( enabled: DMENU) {
}

Contraintes conflictuelles

Il est possible de définir des contraintes conflictuelles dans le thème. Ces conflits ne sont pas explicitement signalés. L'exemple le plus courant est de forcer une taille de fenêtre spécifique, par exemple en activant le mode plein écran, en ayant un nombre de lignes défini dans la liste et en faisant en sorte que la liste s'étende à l'espace disponible. Il y a clairement un conflit dans ces 3 contraintes. Dans ce cas, la liste ne se limitera pas au nombre de lignes, mais essaiera de remplir l'espace disponible. Il appartient au concepteur du thème de s'assurer que le thème gère cela correctement.

Analyse des polices

Rofi utilise pango pour le rendu des polices. La police doit être spécifiée dans un format que pango comprend. C'est normalement le nom de la police suivi de la taille de la police. Par exemple :

mono 18

Ou

FontAwesome 22

D'après le manuel pango :

La chaîne doit avoir la forme

\[LISTE-FAMILLES] \[OPTIONS-STYLE] \[TAILLE] \[VARIATIONS]

où LISTE-FAMILLES est une liste de familles séparées par des virgules, éventuellement terminée par une virgule, OPTIONS-STYLE est une liste de mots séparés par des espaces où chaque mot décrit un style, une variante, un poids, une largeur ou une gravité, et TAILLE est un nombre décimal (taille en points) ou éventuellement suivi du modificateur d'unité « px » pour la taille absolue. VARIATIONS est une liste de spécifications de variations de police séparées par des virgules de la forme « axis=valeur » (le signe = est facultatif).

Les mots suivants sont compris comme des styles : « Normal », « Roman », « Oblique », « Italic ».

Les mots suivants sont compris comme des variantes : « Small-Caps », « All-Small-Caps », « Petite-Caps », « All-Petite-Caps », « Unicase », « Title-Caps ».

Les mots suivants sont compris comme des poids : « Thin », « Ultra-Light », « Extra-Light », « Light », « Semi-Light », « Demi-Light », « Book », « Regular », « Medium », « Semi-Bold », « Demi-Bold », « Bold », « Ultra-Bold », « Extra-Bold », « Heavy », « Black », « Ultra-Black », « Extra-Black ».

Les mots suivants sont compris comme des valeurs de largeur : « Ultra-Condensed », « Extra-Condensed », « Condensed », « Semi-Condensed », « Semi-Expanded », « Expanded », « Extra-Expanded », « Ultra-Expanded ».

Les mots suivants sont compris comme des valeurs de gravité : « Not-Rotated », « South », « Upside-Down », « North », « Rotated-Left », « East », « Rotated-Right », « West ».

N'importe laquelle des options peut être absente. Si LISTE-FAMILLES est absent, alors le champ family_name de la description de police résultante sera initialisé à NULL. Si OPTIONS-STYLE est absent, alors toutes les options de style seront définies sur les valeurs par défaut. Si TAILLE est absent, la taille dans la description de police résultante sera définie sur 0.

Un exemple typique :

« Cantarell Italic Light 15 `wght`=200 »

Gestion des icônes

Rofi prend en charge 3 méthodes pour spécifier une icône :

•
Nom de fichier
•
nom-icône, recherché via le thème d'icônes.
•
Chaîne de balisage. Elle rend une chaîne sous forme d'icône.

Pour les deux premières options, GdkPixbuf est utilisé pour ouvrir et rendre les icônes. Cela offre généralement un support pour la plupart des formats d'image requis. Pour l'option chaîne, il utilise Pango pour rendre la chaîne. La chaîne doit commencer par une balise <span, qui vous permet de définir la couleur et la police.

Chaîne de balisage :

echo -en "testing\0icon\x1f<span color='red'>⏻</span>" | ./rofi -dmenu

Obtenir les formats d'icônes pris en charge :

G_MESSAGES_DEBUG=Helpers.IconFetcher rofi

Cela utilise le framework de débogage et imprime une liste des extensions de fichiers image prises en charge.

Gestion des fichiers multiples

Le format de fichier rasi offre deux méthodes pour inclure d'autres fichiers. Cela peut être utilisé pour modifier des thèmes existants, ou avoir plusieurs variations sur un thème.

•
import : Importe et analyse un deuxième fichier.
•
theme : Ignore le thème, et charge le fichier comme un nouveau thème.

Syntaxe :

@import "myfile"
@theme "mytheme"

L'option de ligne de commande -theme est gérée de manière similaire à @theme.

Le fichier spécifié peut être soit un nom, un nom de fichier, un chemin complet.

Si un nom de fichier est fourni, il essaiera de le résoudre dans l'ordre suivant :

•
Si le chemin est absolu et que le fichier existe, il ouvrira le fichier. Cela inclut l'expansion de `~' ou `~user'
•
Sur un @import ou un @theme, il recherche dans le répertoire du fichier qui a tenté de l'inclure.
•
${XDG_CONFIG_HOME}/rofi/themes/
•
${XDG_CONFIG_HOME}/rofi/
•
${XDG_DATA_HOME}/rofi/themes/
•
${INSTALL PREFIX}/share/rofi/themes/

Un nom est résolu (s'il n'a pas d'extension valide) comme un nom de fichier en ajoutant l'extension .rasi et .rasinc. Il recherchera d'abord les fichiers avec .rasi, puis les fichiers avec .rasinc.

Si vous souhaitez faire une importation optionnelle, par exemple, aucune erreur lorsque le fichier n'existe pas, vous pouvez faire :

?import "myfile"

Cela génère toujours une erreur en cas d'erreur de syntaxe, mais n'interrompra pas l'analyse si le fichier n'existe pas.

NAME

rofi-theme

5 — rofi theme file format

Getting started with theming

It is recommended to start with an existing theme file. The default theme files are located in the /usr/share/rofi/themes directory.

Copy one of the existing themes and modify it.

$ cp /usr/share/rofi/themes/default.rasi ~/.config/rofi/themes/mytheme.rasi

Then start rofi with the new theme:

$ rofi -theme ~/.config/rofi/themes/mytheme.rasi

rofi will look for theme files in the default location, and user-defined locations. The default location is system-dependent. It is usually in /usr/share/rofi/themes/. User themes can be found in $XDG_CONFIG_HOME/rofi/themes/ (defaults to ~/.config/rofi/themes/).

Default theme loading

rofi loads a default theme file if none is specified using the -theme option. The theme is searched for in the following order:

  1. $XDG_CONFIG_HOME/rofi/themes/theme.rasi
  2. $HOME/.config/rofi/themes/theme.rasi
  3. ~/.config/rofi/themes/theme.rasi
  4. /usr/share/rofi/themes/theme.rasi

The theme name is usually theme.rasi. This can be changed with the -theme-str option. The theme is loaded using the rasi format.

Description

This file describes the rofi theme file format, which is based on the rasi (rule-based auto-suggestion inference) language. It allows users to customize the appearance of rofi.

Format specification

The theme file is a plain text file written in the rasi format. It consists of rules that define properties for different elements of the rofi interface.

Encoding

The theme file must be encoded in UTF-8.

Comments

Comments can be single-line, starting with //, or multi-line, enclosed in /* ... */.

White space

White space (spaces, tabs, newlines) is generally ignored, except within strings.

File extension

Theme files should have the extension .rasi.

Basic Structure

A theme file consists of a set of rules. Each rule has a selector and a block of declarations.

selector {
  property: value;
  property: value;
}

Selectors can target specific rofi elements or apply global properties.

Global properties section

The global properties section allows you to define properties that affect the entire rofi window. This section is usually at the beginning of the file.

* {
  /* Global properties */
  background-color: @background;
  text-color: @foreground;
}

Element theme section

Each element of the rofi interface can be themed individually. Examples include window, textbox, listview, etc.

window {
  width: 50%;
  height: 50%;
  background-color: @window-bg;
}

Properties Format

Properties are defined as name: value;. Values can be colors, dimensions, fonts, strings, booleans, etc.

  • Colors: #RRGGBB, #RRGGBBAA, rgba(r,g,b,a), or named colors (e.g., red). Variables can be defined using @variable-name.
  • Dimensions: 10px, 5em, 20%, 200 (pixels).
  • Fonts: "Font Name Size", e.g., "Sans 12".
  • Strings: Enclosed in double quotes ".
  • Booleans: true or false.

Elements paths

Some elements can be nested. Paths are used to select these elements. For example, window listview selects the listview within the window.

Widget properties

Specific properties for different widgets are available. For example, textbox widgets have properties like horizontal-align and vertical-align.

Listview widget

The listview widget has properties such as lines to control the number of visible lines.

listview {
  lines: 10;
}

Layout

Properties like orientation, padding, margin, and children-placement can be used to control the layout of elements.

Debugging

Use the -d -log-theme-errors option to log theme parsing errors.

Media support

rofi has experimental support for displaying images. You can use the image property for this. This requires rofi to be compiled with imlib2 support.

Conflicting constraints

When multiple rules apply to the same element and property, the most specific rule or the last defined rule (if specificity is equal) takes precedence. Inline properties defined with -theme-str override file-based themes.

Font Parsing

Fonts are parsed using Pango rules. You can specify font families, styles, and sizes.

Icon Handling

Icons can be specified using the icon-name property (for icon fonts like FontAwesome) or by providing a path to an image file.

Multiple file handling

rofi can load multiple theme files. The @theme directive can be used to include other theme files.

@theme "/path/to/another/theme.rasi"

Examples

See the default themes in /usr/share/rofi/themes/ for examples of how to style different elements.

An example of a simple theme:

/* ~/.config/rofi/themes/simple.rasi */
* {
  background-color: #2E3440;
  color: #ECEFF4;
  font: "JetBrains Mono 12";
}

window {
  width: 30%;
  height: 40%;
  border: 2px solid #88C0D0;
  background-color: #3B4252;
}

entry {
  placeholder: "Search...";
  padding: 10px;
}

listview {
  padding: 10px;
  lines: 5;
}

element selected {
  background-color: #5E81AC;
  color: #ECEFF4;
}
