NOM

robotfindskitten - aider le robot à trouver le chaton

SYNOPSIS

robotfindskitten [ -n nombre ] [ -s graine ] [ -f nom_de_fichier ]

DESCRIPTION

Dans ce jeu, vous êtes le robot ( # ). Votre travail est de trouver le chaton. Cette tâche est compliquée par l'existence de divers objets qui ne sont pas le chaton (collectivement appelés Objets Non Chatons ou ONC). Le robot doit toucher les objets pour déterminer s'il s'agit du chaton ou non. Le jeu se termine lorsque le robot trouve le chaton.

Vous pouvez déplacer le robot avec les touches fléchées, les touches EMACS (^N, ^P, ^B et ^F pour bas, haut, gauche et droite), les touches du pavé numérique (les 8 directions) et les touches nethack (les 8 directions ; hjklyubn pour gauche, bas, haut, droite, haut-gauche, haut-droite, bas-gauche et bas-droite).

Vous pouvez appuyer sur Ctrl-L à tout moment pour redessiner l'écran. Vous pouvez appuyer sur q à tout moment pour quitter. Un bon vieux Ctrl-C permet également de quitter.

OPTIONS

Vous pouvez éventuellement spécifier le nombre d'Objets Non Chatons à utiliser avec l'option -s. La valeur par défaut est 20.

Vous pouvez définir la graine du générateur de nombres aléatoires, normalement initialisée à partir de l'horloge système, avec l'option -t. Cela peut être utile pour le débogage.

Vous pouvez fournir un fichier arbitraire à partir duquel tirer les ONC en utilisant l'option -f.

FICHIERS

robotfindskitten(6) lit tous les fichiers dans les répertoires ~/.robotfindskitten et /usr/share/games/robotfindskitten. Chaque ligne de chaque fichier correspondant à *.nki devient la description d'un Objet Non Chaton. Les lignes commençant par '#' ou '%' sont ignorées. Cela permet d'utiliser des commentaires dans les fichiers nki et d'utiliser les fichiers fortune(6).

ENVIRONNEMENT

robotfindskitten(6) utilise la variable d'environnement HOME pour trouver le répertoire ~/.robotfindskitten.

STATUT DE SORTIE

Le statut de sortie est 0 si le robot a trouvé le chaton ; 1 si vous avez quitté ou s'il y a eu un problème ; et le numéro du signal si robotfindskitten(6) se termine normalement suite à un signal.

UNE PENSÉE FINALE

Jour et nuit, je travaillais fiévreusement sur la machine, créant à la fois une âme qui pouvait désirer son but et un corps avec lequel elle pouvait le réaliser. Beaucoup de ceux qui ont vu ma création l'ont appelée une abomination, et m'ont refusé des subventions. Mais ils ne pouvaient pas me dissuader de ma tâche impossible. C'était un spectre qui me tourmentait toujours, un fantôme auquel je devais donner une forme et une vie, de peur qu'il ne me consume de l'intérieur. Et quand enfin ma tâche fut accomplie, quand la boîte grise sur roues fut terminée et quand elle, ainsi que moi, sûmes ce qu'il fallait faire, je ressentis une profonde sympathie pour la machine. Car je n'avais pas détruit le fantôme, mais simplement l'avais exorcisé dans un autre corps. Le robot ne savait pas pourquoi cette tâche devait être accomplie, car je ne pouvais pas l'imprégner de connaissances que je ne possédais pas moi-même. Et en même temps, je ressentis un immense soulagement m'envahir, car d'une manière ou d'une autre, le rêve qui m'avait animé toute ma vie s'était rapproché d'un pas de sa concrétisation.

"Gort, Klaatu Verada Nikto"

Alors que j'activais vocalement le robot, je réalisai qu'il suivait mes instructions, mais sans aucun désir de m'obéir. Si j'étais resté silencieux, il aurait effectué exactement les mêmes opérations. Nous étions deux êtres contrôlés par la même force maintenant. Et pourtant, cherchant vainement à garder une illusion de contrôle sur la machine que je pensais avoir créée, je donnai ma dernière commande.

"PARS !" dis-je à la boîte alors qu'elle commençait à rouler hors de mon atelier vers le désert glacial au-delà. "TROUVE LE CHATON !"


-- Le Livre des Chatons Trouvés, pages 43-44, auteur inconnu

AUTEURS

robotfindskitten a été initialement écrit par Leonard Richardson <leonardr@segfault.org> pour DOS en 1997. Il l'a réécrit pour Linux en 1999. Depuis lors, robotfindskitten a été porté et/ou réécrit pour d'innombrables autres plateformes. Le code POSIX actuel est basé sur du code initialement écrit par Alexey Toptygin <alexeyt@freeshell.org>.
