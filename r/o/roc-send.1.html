NOM

roc-send - envoyer de l'audio en temps réel

SYNOPIS

roc-send OPTIONS

DESCRIPTION

Lit un flux audio depuis un périphérique audio ou un fichier et l'envoie à un récepteur distant.

Options

-h, --help
Affiche l'aide et quitte
-V, --version
Affiche la version et quitte
-v, --verbose
Augmente le niveau de verbosité (peut être utilisé plusieurs fois)
-L, --list-supported
liste les schémas et formats supportés
-i,--input=URI_IO
Fichier d'entrée ou URI du périphérique
--input-format=FORMAT_FICHIER
Force le format du fichier d'entrée
-s,--source=URI_POINT_EXTREMITE
Point de terminaison source distant
-r,--repair=URI_POINT_EXTREMITE
Point de terminaison de réparation distant
-c,--control=URI_POINT_EXTREMITE
Point de terminaison de contrôle distant
--reuseaddr
active SO_REUSEADDR lors de la liaison des sockets
--target-latency=CHAINE
Latence cible, unités de TEMPS
--io-latency=CHAINE
Latence cible d'enregistrement, unités de TEMPS
--latency-tolerance=CHAINE
Déviation maximale par rapport à la latence cible, unités de TEMPS
--nbsrc=INT
Nombre de paquets source dans un bloc FEC
--nbrpr=INT
Nombre de paquets de réparation dans un bloc FEC
--packet-len=CHAINE
Longueur du paquet sortant, unités de TEMPS
--frame-len=TEMPS
Durée des trames internes, unités de TEMPS
--max-packet-size=TAILLE
Taille maximale du paquet, en unités de TAILLE
--max-frame-size=TAILLE
Taille maximale de la trame interne, en unités de TAILLE
--rate=INT
Remplace le taux d'échantillonnage d'entrée, Hz
--latency-backend=ENUM
Quelle latence utiliser dans le réglage de latence (valeurs possibles="niq" défaut=`niq')
--latency-profile=ENUM
Profil de réglage de latence (valeurs possibles="responsive", "gradual", "intact" défaut=`intact')
--resampler-backend=ENUM
Backend ré-échantillonneur (valeurs possibles="default", "builtin", "speex", "speexdec" défaut=`default')
--resampler-profile=ENUM
Profil ré-échantillonneur (valeurs possibles="low", "medium", "high" défaut=`medium')
--interleaving
Active l'entrelacement des paquets (défaut=désactivé)
--profiling
Active le profilage interne (défaut=désactivé)
--color=ENUM
Définit le mode de journalisation colorée pour la sortie stderr (valeurs possibles="auto", "always", "never" défaut=`auto')

URI de Point de Terminaison

Les options --source, --repair, et --control définissent les points de terminaison réseau auxquels le trafic sera envoyé.

URI_POINT_EXTREMITE doit avoir la forme suivante :

protocole://hote[:port][/chemin][?requete]

Exemples :

  • rtsp://localhost:123/chemin?requete
  • rtp+rs8m://localhost:123
  • rtp://127.0.0.1:123
  • rtp://[::1]:123
  • rtcp://10.9.8.3:123

La liste des protocoles supportés peut être obtenue en utilisant l'option --list-supported.

Le champ hôte doit être soit un nom de domaine complet (FQDN), soit une adresse IPv4, soit une adresse IPv6 entre crochets.

Le champ port peut être omis si le protocole définit un port standard. Sinon, il est obligatoire.

Les champs chemin et requête ne sont autorisés que pour les protocoles qui les supportent, par exemple pour RTSP.

Si le FEC est activé, une paire de points de terminaison source et de réparation doit être fournie. Les deux points de terminaison doivent utiliser des protocoles compatibles, par exemple rtp+rs8m:// pour le point de terminaison source, et rs8m:// pour le point de terminaison de réparation. Si le FEC est désactivé, un seul point de terminaison source doit être fourni.

Protocoles source et de réparation supportés :

  • source rtp://, réparation none (RTP brut sans FEC)
  • source rtp+rs8m://, réparation rs8m:// (RTP avec Reed-Solomon FEC)
  • source rtp+ldpc://, réparation ldpc:// (RTP avec LDPC-Staircase FEC)

De plus, il est recommandé de fournir un point de terminaison de contrôle. Il est utilisé pour échanger des informations non média utilisées pour identifier une session, transporter des retours, etc. Si aucun point de terminaison de contrôle n'est fourni, la session fonctionne en mode de repli réduit, ce qui peut être moins robuste et ne pas supporter toutes les fonctionnalités.

Protocoles de contrôle supportés :

•
rtcp://

URI d'IO

L'option --input requiert un URI de périphérique ou de fichier dans l'une des formes suivantes :

  • TYPE_PERIPHERIQUE://NOM_PERIPHERIQUE -- périphérique audio
  • TYPE_PERIPHERIQUE://default -- périphérique audio par défaut pour le type de périphérique donné
  • file:///CHEMIN/ABSOLU -- chemin de fichier absolu
  • file://localhost/CHEMIN/ABSOLU -- chemin de fichier absolu (forme alternative; seul l'hôte "localhost" est supporté)
  • file:/CHEMIN/ABSOLU -- chemin de fichier absolu (forme alternative)
  • file:CHEMIN/RELATIF -- chemin de fichier relatif
  • file://- -- stdin
  • file:- -- stdin (forme alternative)

Exemples :

  • pulse://default
  • pulse://alsa_input.pci-0000_00_1f.3.analog-stereo
  • alsa://hw:1,0
  • file:///home/user/test.wav
  • file://localhost/home/user/test.wav
  • file:/home/user/test.wav
  • file:./test.wav
  • file:-

La liste des schémas et formats de fichiers supportés peut être obtenue en utilisant l'option --list-supported.

Si --input est omis, le pilote et le périphérique par défaut sont sélectionnés.

L'option --input-format peut être utilisée pour forcer le format du fichier d'entrée. S'il est omis, le format du fichier est auto-détecté. Cette option est toujours requise lorsque l'entrée est stdin.

Le composant chemin de l'URI fourni est *décodé en pourcentage*. Pour plus de commodité, des caractères non encodés sont également autorisés, à la condition que % soit toujours encodé en %25.

Par exemple, le fichier nommé /foo/bar%/[baz] peut être spécifié en utilisant l'un des URI suivants : file:///foo%2Fbar%25%2F%5Bbaz%5D et file:///foo/bar%25/[baz].

Slots multiplesLe réglage du système peut nécessiter de créer des slots multiples pour le traitement audio. Par exemple, pour capturer des flux de différents périphériques en même temps, il peut être nécessaire de spécifier le nom de l'appareil audio tel qu'il est identifié par le système, par exemple pulse://alsa_input.pci-0000_00_1f.3.analog-stereo.

Les sessions multiples peuvent être lancées en exécutant roc-send plusieurs fois avec des paramètres différents.

EXEMPLES

Envoyer le flux audio par défaut vers localhost sur le port 1234 :

roc-send -s rtp://localhost:1234

Envoyer le flux audio depuis le périphérique PulseAudio nommé "default" vers localhost sur le port 1234 avec FEC Reed-Solomon :

roc-send -i pulse://default -s rtp+rs8m://localhost:1234 -r rs8m://localhost:1235

Envoyer le flux audio depuis un fichier WAV vers localhost sur le port 1234 :

roc-send -i file:///home/user/audio.wav -s rtp://localhost:1234

Envoyer le flux audio depuis stdin vers localhost sur le port 1234 :

cat audio.wav | roc-send -i file:- -s rtp://localhost:1234

Envoyer le flux audio depuis le périphérique ALSA hw:1,0 vers localhost sur le port 1234 avec le protocole de contrôle RTCP :

roc-send -i alsa://hw:1,0 -s rtp://localhost:1234 -c rtcp://localhost:1236

Envoyer le flux audio depuis le périphérique ALSA hw:0,0 vers localhost sur le port 1234 avec une latence cible de 20ms et une tolérance de 5ms :

roc-send -i alsa://hw:0,0 --target-latency=20ms --latency-tolerance=5ms -s rtp://localhost:1234

Envoyer le flux audio depuis le périphérique ALSA hw:0,0 vers localhost sur le port 1234 avec 10 paquets source et 4 paquets de réparation par bloc FEC :

roc-send -i alsa://hw:0,0 --nbsrc=10 --nbrpr=4 -s rtp+rs8m://localhost:1234 -r rs8m://localhost:1235

Envoyer le flux audio depuis le périphérique ALSA hw:0,0 vers localhost sur le port 1234 avec des paquets de 10 ms et des trames de 5 ms :

roc-send -i alsa://hw:0,0 --packet-len=10ms --frame-len=5ms -s rtp://localhost:1234

Activer l'entrelacement des paquets et le profilage :

roc-send --interleaving --profiling -s rtp://localhost:1234

Forcer le format du fichier d'entrée à être WAV :

roc-send --input-format=wav -i file:input.dat -s rtp://localhost:1234

Désactiver la coloration de la sortie :

roc-send --color=never -s rtp://localhost:1234

roc-send(1) — Roc Toolkit 0.4

NAME

roc-send - Send audio stream

SYNOPSIS

roc-send [-c | --color[=auto|always|never]] [-h | --help] [-v | --verbose] [-V | --version] [--color=never] [-f | --force] [--color=always] [--color=auto] [-i | --input=INPUT] [--input-format=FORMAT] [--input-rate=RATE] [--input-channels=CHANNELS] [--input-samples=SAMPLES] [--input-latency=TIME] [--input-volume=VOLUME] [--input-mono] [--input-stereo] [-s | --source=ENDPOINT] [-r | --repair=ENDPOINT] [-c | --control=ENDPOINT] [-a | --audio=ENDPOINT] [--resampler-backend=BACKEND] [--resampler-profile=PROFILE] [--resampler-quality=QUALITY] [--resampler-latency=TIME] [--resampler-packet-len=TIME] [--resampler-len=FRAME_LEN] [--resampler-batch=BATCH_LEN] [--packet-len=TIME] [--frame-len=TIME] [--nbsrc=SIZE] [--nbrpr=SIZE] [--nbctl=SIZE] [--nbaud=SIZE] [--target-latency=TIME] [--latency-profile=PROFILE] [--io-latency=TIME] [--tx-interval=TIME] [--debug] [--faults] [--no-faults] [--reuseaddr]

DESCRIPTION

The roc-send command streams audio data from an input device to one or more remote endpoints. It supports various input sources such as files, ALSA, PulseAudio, and network sockets. It can also send audio to multiple destinations simultaneously by specifying multiple endpoints.

Each endpoint set can include source (RTP), repair (FEC), and control (RTCP) endpoints. They are specified using the -s, -r, and -c options respectively.

Multiple sets of endpoints can be specified to send media to multiple addresses.

Such endpoint sets are called slots. All slots should have the same set of endpoint types (source, repair, etc) and should use the same protocols for them.

SO_REUSEADDR

If --reuseaddr option is provided, SO_REUSEADDR socket option will be enabled for all sockets.

For TCP, it allows immediately reusing recently closed socket in TIME_WAIT state, which may be useful you want to be able to restart server quickly.

For UDP, it allows multiple processes to bind to the same address, which may be useful if you're using systemd socket activation.

Regardless of the option, SO_REUSEADDR is always disabled when binding to ephemeral port.

Time units

TIME should have one of the following forms:
123ns; 1.23us; 1.23ms; 1.23s; 1.23m; 1.23h;

Size units

SIZE should have one of the following forms:
123; 1.23K; 1.23M; 1.23G;

EXAMPLES

Endpoint examples

Send file to receiver with one bare RTP endpoint:

$ roc-send -vv -i file:./input.wav -s rtp://192.168.0.3:10001

Send file to receiver with IPv4 source, repair, and control endpoints:

$ roc-send -vv -i file:./input.wav -s rtp+rs8m://192.168.0.3:10001 \
    -r rs8m://192.168.0.3:10002 -c rtcp://192.168.0.3:10003

Send file to receiver with IPv6 source, repair, and control endpoints:

$ roc-send -vv -i file:./input.wav -s rtp+rs8m://[2001:db8::]:10001 \
    -r rs8m://[2001:db8::]:10002 -r rtcp://[2001:db8::]:10003

Send file to two receivers, each with three endpoints:

$ roc-send -vv \
    -i file:./input.wav \
    -s rtp+rs8m://192.168.0.3:10001 -r rs8m://192.168.0.3:10002 \
        -c rtcp://192.168.0.3:10003 \
    -s rtp+rs8m://198.214.0.7:10001 -r rs8m://198.214.0.7:10002 \
        -c rtcp://198.214.0.7:10003

I/O examples

Capture sound from the default device (omit -i):

$ roc-send -vv -s rtp://192.168.0.3:10001

Capture sound from the default ALSA device:

$ roc-send -vv -s rtp://192.168.0.3:10001 -i alsa://default

Capture sound from a specific PulseAudio device:

$ roc-send -vv -s rtp://192.168.0.3:10001 -i pulse://alsa_input.pci-0000_00_1f.3.analog-stereo

Send WAV file (guess format by extension):

$ roc-send -vv -s rtp://192.168.0.3:10001 -i file:./input.wav

Send WAV file (specify format manually):

$ roc-send -vv -s rtp://192.168.0.3:10001 -i file:./input.file --input-format wav

Send WAV from stdin:

$ roc-send -vv -s rtp://192.168.0.3:10001 -i file:- --input-format wav <./input.wav

Send WAV file (specify absolute path):

$ roc-send -vv -s rtp://192.168.0.3:10001 -i file:///home/user/input.wav

Tuning examples

Force a specific rate on the input device:

$ roc-send -vv -s rtp://192.168.0.3:10001 --rate=44100

Select the LDPC-Staircase FEC scheme and a larger block size:

$ roc-send -vv -i file:./input.wav -s rtp+ldpc://192.168.0.3:10001 \
    -r ldpc://192.168.0.3:10002 -c ldpc://192.168.0.3:10003 \
    --nbsrc=1000 --nbrpr=500

Select smaller packet length:

$ roc-send -vv -i file:./input.wav -s rtp+ldpc://192.168.0.3:10001 \
    --packet-len 2500us

Select lower I/O latency and frame length:

$ roc-send -vv -s rtp://192.168.0.3:10001 \
    --io-latency=20ms --frame-len 4ms

Manually specify resampling parameters:

$ roc-send -vv -s rtp://192.168.0.3:10001 \
    --resampler-backend=speex --resampler-profile=high

Perform latency tuning on sender instead of receiver:

$ roc-recv -vv -o pulse://default -s rtp+rs8m://0.0.0.0:10001 \
    -r rs8m://0.0.0.0:10002 -c rtcp://0.0.0.0:10003 \
    --latency-profile=intact --target-latency=200ms
$ roc-send -vv -i file:./input.wav -s rtp+rs8m://192.168.0.3:10001 \
    -r rs8m://192.168.0.3:10002 -c rtcp://192.168.0.3:10003 \
    --latency-profile=gradual --target-latency=200ms

ENVIRONMENT VARIABLES

The following environment variables are supported:

NO_COLOR
By default, terminal coloring is automatically detected. This environment variable can be set to a non-empty string to disable terminal coloring. It has lower precedence than --color option.
FORCE_COLOR
By default, terminal coloring is automatically detected. This environment variable can be set to a positive integer to enable/force terminal coloring. It has lower precedence than NO_COLOR variable and --color option.
