NOM

rofi-thumbnails - Système de miniatures Rofi

DESCRIPTION

rofi est désormais capable d'afficher des miniatures pour tous les types de fichiers pour lesquels un programme de génération de miniatures compatible XDG est présent sur le système.

Ceci est fait par défaut dans les modes filebrowser et recursivebrowser, si rofi est lancé avec l'argument -show-icons.

Dans un script utilisateur personnalisé ou en mode dmenu, il est possible de produire des icônes pour les entrées en utilisant les générateurs de miniatures XDG en ajoutant le préfixe thumbnail:// au nom de fichier spécifié après \0icon\x1f, par exemple :

echo -en "NomEntree\0icon\x1fthumbnail://chemin/vers/fichier\n" | rofi -dmenu -show-icons

Générateurs de miniatures XDG

Les générateurs de miniatures XDG sont des fichiers avec le suffixe “.thumbnailer” et une structure similaire aux fichiers “.desktop” pour le lancement des applications. Ils sont placés dans /usr/share/thumbnailers/ ou $HOME/.local/share/thumbnailers/, et contiennent une liste de mimetypes, pour lesquels il est possible de produire l'image miniature, et une chaîne de caractères avec la commande pour créer ladite image. L'exemple ci-dessous montre le contenu de librsvg.thumbnailer, un générateur de miniatures pour les fichiers svg utilisant librsvg :

[Thumbnailer Entry]
TryExec=/usr/bin/gdk-pixbuf-thumbnailer
Exec=/usr/bin/gdk-pixbuf-thumbnailer -s %s %u %o
MimeType=image/svg+xml;image/svg+xml-compressed;

Les images produites sont nommées d'après le md5sum des fichiers d'entrée et placées, en fonction de leur taille, dans les répertoires de miniatures XDG : $HOME/.cache/thumbnails/{normal,large,x-large,xx-large}. Elles sont ensuite chargées par rofi en tant qu'icônes d'entrée et peuvent également être utilisées par les gestionnaires de fichiers tels que Thunar, Caja ou KDE Dolphin pour afficher leurs miniatures. De plus, si une miniature pour un fichier est trouvée dans les répertoires de miniatures (produite précédemment par rofi ou un gestionnaire de fichiers), rofi la chargera au lieu d'appeler le générateur de miniatures.

Si un générateur de miniatures approprié pour un fichier donné n'est pas trouvé, rofi essaiera d'utiliser l'icône de mimetype correspondante du thème d'icônes.

Commande personnalisée pour créer des miniatures

Il est possible d'utiliser une commande personnalisée pour générer des miniatures pour des noms d'entrées génériques, par exemple un script qui télécharge une icône en fonction de son URL ou sélectionne différentes icônes en fonction de l'entrée. Cela peut être fait en fournissant l'argument -preview-cmd suivi d'une chaîne de caractères avec la commande à exécuter, en utilisant la syntaxe suivante :

rofi ... -preview-cmd 'chemin/vers/script_ou_cmd "{input}" "{output}" "{size}"'

rofi appellera le script ou la commande en substituant {input} par le nom de l'icône d'entrée (la chaîne après \0icon\x1fthumbnail://), {output} par le nom du fichier de sortie de la miniature et {size} par la taille de miniature demandée. Le script ou la commande est responsable de produire une image miniature (en respectant si possible la taille demandée) et de l'enregistrer dans le nom de fichier {output} spécifié.

Problèmes avec AppArmor

Dans les distributions Linux utilisant AppArmor (comme Ubuntu et Debian), les règles par défaut peuvent causer des problèmes avec la génération des miniatures. Si tel est le cas, AppArmor peut être désactivé en exécutant les commandes suivantes :

sudo systemctl stop apparmor
sudo systemctl disable apparmor

Alternativement, le profil AppArmor suivant peut être placé dans un fichier nommé /etc/apparmor.d/usr.bin.rofi

#vim:syntax=apparmor
# AppArmor policy for rofi
#include <tunables/global>
/usr/bin/rofi {
    #include <abstractions/base>
    # TCP/UDP network access for NFS
    network inet  stream,
    network inet6 stream,
    network inet  dgram,
    network inet6 dgram,
    /usr/bin/rofi mr,
    @{HOME}/ r,
    @{HOME}/** rw,
    owner @{HOME}/.cache/thumbnails/** rw,
}

puis exécutez

apparmor_parser  -r /etc/apparmor.d/usr.bin.rofi

pour recharger la règle. Ceci suppose que le binaire rofi se trouve dans /usr/bin, ce qui est le cas pour une installation standard du paquet.

rofi
