NOM

rollctl - Envoyer des commandes au démon de rollover DNSSEC-Tools

SYNTAXE

rollctl [options]

DESCRIPTION

La commande rollctl envoie des commandes au démon de rollover DNSSEC-Tools, rollerd. Une seule option peut être spécifiée sur la ligne de commande.

Dans la plupart des cas, rollerd enverra une réponse à rollctl. rollctl affichera un message de succès ou d'échec, le cas échéant.

Si rollctl est exécuté comme une commande empaquetée PAR, il utilisera sa propre copie locale du fichier dnssec-tools.conf. Ce fichier se trouvera dans le répertoire du paquet.

OPTIONS

Les options suivantes sont gérées par rollctl.

-display
Lance l'interface graphique de statut du rollover.
-dspub zone
Indique que le parent de zone a publié un nouvel enregistrement DS pour zone.

Plusieurs zones peuvent être spécifiées sur la ligne de commande. Par exemple, cette commande enverra la commande dspub à rollerd pour trois zones.

$ rollctl -dspub example1.com example2.com example3.com
-dspuball
Indique que des enregistrements DS ont été publiés pour toutes les zones en phase 5 du rollover KSK.
-group
Indique que la commande spécifiée doit s'appliquer à un groupe de zones au lieu d'une zone. Par conséquent, la zone spécifiée doit réellement être un groupe de zones. Cette option doit être utilisée conjointement avec une autre commande.

Cette option ne s'applique qu'aux commandes suivantes : -dspub, -rollksk, -rollzone, -rollzsk et -skipzone. Cette commande n'aura aucun effet si elle est donnée à d'autres commandes.

-halt [now]
Arrête proprement l'exécution de rollerd. Si le paramètre optionnel now est donné, alors rollerd sera arrêté immédiatement, plutôt que de lui permettre de terminer ses opérations actuellement mises en queue.
-logfile logfile
Définit le fichier de journalisation de rollerd sur logfile. Ce doit être un fichier de journalisation valide, ce qui signifie que si logfile existe déjà, il doit s'agir d'un fichier régulier. Les seules exceptions sont si logfile est /dev/stdout ou /dev/tty.
-loglevel loglevel
Définit le niveau de journalisation de rollerd sur loglevel. Ce doit être l'un des niveaux de journalisation valides définis dans rollmgr.pm(3).

Si un niveau de journalisation n'est pas spécifié, alors la liste des niveaux valides sera imprimée et rollctl se terminera. La liste est donnée sous forme textuelle et numérique.

-logtz logtz
Définit le fuseau horaire de journalisation de rollerd sur loglevel. Ce doit être gmt (pour le temps moyen de Greenwich) ou local (pour l'heure locale de l'hôte).
-mergerrfs rollrec0 ... rollrecN
Indique à rollerd de fusionner les fichiers rollrec spécifiés avec son fichier rollrec actif. Les noms des fichiers rollrec ne doivent pas contenir de deux-points.
-nodisplay
Arrête l'interface graphique de statut du rollover.
-phasemsg length
length est la longueur par défaut des messages de journalisation liés aux phases utilisés par rollerd. Les niveaux valides sont "long" et "short", avec "long" étant la valeur par défaut.

La longueur de message longue signifie qu'une description de phase sera incluse avec certains messages de journalisation. Par exemple, la forme longue d'un message sur la phase 3 du rollover ZSK ressemblera à ceci : "ZSK phase 3 (En attente de l'expiration des anciennes données de zone des caches)".

La longueur de message courte signifie qu'une description de phase ne sera pas incluse avec certains messages de journalisation. Par exemple, la forme courte d'un message sur la phase 3 du rollover ZSK ressemblera à ceci : "ZSK phase 3".

-rollall
Reprend le rollover pour toutes les zones du fichier rollrec actuel qui ont été suspendues. (Les zones "skip" sont suspendues.)
-rollallksks
Initie le rollover KSK pour toutes les zones définies dans le fichier rollrec actuel qui ne sont pas actuellement en rollover.
-rollallzsks
Initie le rollover ZSK pour toutes les zones définies dans le fichier rollrec actuel qui ne sont pas actuellement en rollover.
-rollksk zone
Initie le rollover KSK pour la zone nommée par zone.

Plusieurs zones peuvent être spécifiées sur la ligne de commande. Par exemple, cette commande enverra la commande rollksk à rollerd pour trois zones.

$ rollctl -rollksk example1.com example2.com example3.com
-rollrec rollrec_file
Définit le fichier rollrec à traiter par rollerd sur rollrec_file.
-rollzone zone
Reprend le rollover pour la zone suspendue nommée par zone.

Plusieurs zones peuvent être spécifiées sur la ligne de commande. Par exemple, cette commande enverra la commande rollzone à rollerd pour trois zones.

$ rollctl -rollzone example1.com example2.com example3.com
-rollzsk zone
Initie le rollover pour la zone nommée par zone.

Plusieurs zones peuvent être spécifiées sur la ligne de commande. Par exemple, cette commande enverra la commande rollzsk à rollerd pour trois zones.

$ rollctl -rollzsk example1.com example2.com example3.com
-runqueue
Réveille rollerd et lui fait exécuter sa file d'entrées rollrec.
-shutdown
Synonyme de -halt.
-signzone zone
Signe le fichier de zone de zone sans effectuer d'actions de rollover. La zone est signée avec les clés les plus récemment utilisées pour signer la zone. Aucune nouvelle clé ne sera générée.
-signzones [all | active]
Signe les fichiers de zone des zones gérées par rollerd, sans effectuer d'actions de rollover. Si l'option all est donnée, alors toutes les zones de rollerd seront signées. Si l'option active est donnée, alors seules les zones qui ne sont pas au stade skip seront signées. Les zones sont signées avec les clés les plus récemment utilisées pour signer chaque zone. Aucune nouvelle clé ne sera générée.
-skipall
Suspend le rollover pour toutes les zones du fichier rollrec actuel.
-skipzone zone
Suspend le rollover pour la zone nommée par zone.

Plusieurs zones peuvent être spécifiées sur la ligne de commande. Par exemple, cette commande enverra la commande skipzone à rollerd pour trois zones.

$ rollctl -skipzone example1.com example2.com example3.com
-sleeptime seconds
Définit le temps de veille de rollerd à seconds secondes. sleeptime doit être un entier au moins aussi grand que la valeur $MIN_SLEEP dans rollerd.
-splitrrf new-rrf zone0 ... zoneN
Indique à rollerd de déplacer un ensemble d'entrées rollrec du fichier rollrec actuel vers un nouveau fichier. Le nouveau fichier est nommé dans le paramètre new-rrf. Les entrées rollrec dont les noms correspondent à ceux de zone0 à zoneN

> les listes sont déplacées vers le nouveau fichier. Le nom du nouveau fichier rollrec et les noms de zone ne doivent pas contenir de deux-points.
-status
Demande à rollerd d'écrire plusieurs de ses paramètres opérationnels dans son fichier journal. Les paramètres sont également signalés à rollctl, qui les affiche à l'écran.
-zonegroup [groupe-zone]
Demande des informations sur les groupes de zones à rollerd. Si l'argument optionnel groupe-zone n'est pas fourni, rollerd renvoie une liste des groupes de zones définis et le nombre de zones dans chacun. Si un groupe-zone est spécifié, rollerd renvoie une liste des zones de ce groupe.

(Bien que ce terme utilise le mot "zone", il fait en réalité référence au nom des entrées rollrec. Pour une entrée rollrec donnée, le nom rollrec est généralement le même que le nom de la zone, mais ce n'est pas une obligation.)

-zonelog
Définit le niveau de journalisation pour la zone spécifiée. Le nouveau niveau de journalisation ne s'applique qu'à l'exécution actuelle de rollerd et n'est pas enregistré dans le fichier rollrec actif.

Les arguments de cette commande doivent être au format "zone:niveau-journalisation". Par exemple, cette commande envoie la commande zonelog à rollerd pour trois zones.

$ rollctl -zonelog example1.com:info example2.com:6 example3.com:err
-zonestatus
Demande à rollerd d'écrire le statut des zones du fichier rollrec actuel dans le fichier journal de rollerd. Le statut est également signalé à rollctl, qui l'affiche à l'écran. rollctl l'affiche sous forme de colonnes pour en améliorer la lisibilité. Les colonnes, dans l'ordre, sont : nom rollrec, nom de zone, état roll/skip, et phase de rollover.

Exemple :
anothersub anothersub.example.com skip KSK 1
example.com example.com roll KSK 1
site1.in.subzone.example.com subzone.example.com roll KSK 3
site1.subzone.example.com subzone.example.com roll KSK 3

-zsargs liste-arguments zones
Fournit des arguments supplémentaires pour zonesigner pour un ensemble donné de zones. Ces arguments remplacent les arguments du fichier de configuration par défaut de DNSSEC-Tools, du fichier de configuration de DNSSEC-Tools et des fichiers keyrec des zones.

La liste d'arguments de zonesigner est fournie dans liste-arguments. Compte tenu du traitement des arguments de rollctl, les nouveaux arguments pour zonesigner ne peuvent pas être spécifiés comme prévu. Au lieu de cela, les arguments doivent être fournis de la manière suivante. Le trait d'union initial doit être remplacé par un signe égal. Si l'option prend un argument, l'espace qui séparerait l'option de son argument doit également être remplacé par un signe égal. rollerd traduit ces arguments dans le format approprié pour zonesigner. Ces exemples devraient clarifier les modifications :

option zonesigner normale            options -zsargs
------------------------            ---------------
    -nokrfile                          =nokrfile
    -zskcount 5                        =zskcount=5

La liste zones est une liste de zones séparées par des espaces. Tous les nouveaux arguments zonesigner seront appliqués à toutes les zones listées.

L'argument "=clear" est spécial. rollerd le traduit en "-clear", qui n'est pas une option zonesigner normale. Au lieu de cela, rollerd reconnaît "-clear" comme un indicateur qu'il doit supprimer le champ zsargs des enregistrements rollrec pour les zones spécifiées.

Les utilisations suivantes de -zsargs sont valides :

# rollctl -zsargs =ksklength=2048 example.com
# rollctl -zsargs =ksklen=2048 =zsklen=2048 example.com test.com
-Version
Affiche les informations de version pour rollctl et le package DNSSEC-Tools.
-quiet
Empêche la sortie. Les sorties d'erreur et non d'erreur sont arrêtées.
-help
Affiche un message d'utilisation.

CODES DE SORTIE

rollctl peut renvoyer les codes de sortie suivants :

0 - Exécution réussie
1 - Erreur lors de l'envoi de la commande à rollerd.
2 - Argument manquant.
3 - Trop de commandes spécifiées.
200 - Rollerd ne fonctionne pas.
201 - Les vérifications du fichier de configuration ont échoué.

FUTUR

Les modifications suivantes pourront être apportées à l'avenir :

ordre d'exécution des commandes
Les commandes seront exécutées dans l'ordre où elles sont données sur la ligne de commande plutôt que par ordre alphabétique.
