Paquet: ruby-ronn-ng

RONN-FORMAT(7) Manuel Ronn RONN-FORMAT(7)

NOM

ronn-format - format d'auteur de manuel basé sur Markdown

SYNTAXE

nom(1) -- description courte en une phrase
=============================================
## SYNTAXE
`nom` [<optionnel>...] <indicateurs>
## DESCRIPTION
Un paragraphe normal. Il peut s'étendre sur plusieurs lignes et est terminé par deux
ou plusieurs fins de ligne -- tout comme Markdown.
Le balisage en ligne pour `code`, `entrée utilisateur`, et **fort** sont affichés
en gras ; <variable>, _emphase_, *emphase*, sont affichés en italique
(HTML) ou souligné (roff).
Les références de manuel comme sh(1), markdown(7), roff(7), etc. sont des hyperliens dans
la sortie HTML.
Lien vers des sections comme [NORMES][], [VOIR AUSSI][], ou [AVEC UN AUTRE TEXTE DE LIEN][#SEE-ALSO].
Listes de définition:
  * `-a`, `--argument`=[<valeur>]:
    Un ou plusieurs paragraphes décrivant l'argument.
  * Vous pouvez y mettre ce que vous *voulez*, vraiment :
    L'imbrication et l'espacement des paragraphes sont respectés.
Sections fréquemment utilisées:
## OPTIONS
## SYNTAXE
## ENVIRONNEMENT
## VALEURS DE RETOUR
## NORMES
## CONSIDÉRATIONS DE SÉCURITÉ
## BUGS
## HISTORIQUE
## AUTEUR
## COPYRIGHT
## VOIR AUSSI

DESCRIPTION

La commande ronn(1) convertit du texte dans un format simple en pages de manuel Unix. La syntaxe inclut toutes les fonctionnalités de formatage de Markdown, plus des conventions pour exprimer la structure et diverses notations présentes dans les pages de manuel Unix standard.

Toutes les fonctionnalités de composition roff(7) ne peuvent pas être exprimées en utilisant la syntaxe ronn.

TITRE DE PAGE MANUEL

Les pages de manuel ont un nom, une section et une description d'une ligne. Les fichiers doivent commencer par un titre de niveau un définissant ces attributs :

ls(1) -- lister le contenu du répertoire
================================

Indique que la page de manuel s'appelle ls dans la section de manuel 1 ("commandes utilisateur").

TITRES DE SECTION

Les titres de section de manuel sont exprimés avec des titres de niveau deux en markdown. Il existe deux syntaxes pour les titres de niveau deux.

Syntaxe avec préfixe hash :

## TEXTE DU TITRE

Syntaxe avec soulignement par tirets :

TEXTE DU TITRE
------------

Les titres de section doivent être entièrement en majuscules et ne peuvent pas contenir de balisage en ligne.

BALISAGE EN LIGNE

Les pages de manuel ont un ensemble limité de capacités de formatage de texte. Il y a essentiellement le gras et l'italique (souvent affiché en souligné). Ronn utilise les éléments suivants de markdown(7) pour y parvenir :

\`guillemets inversés\` (compatible markdown)
Code, indicateurs, commandes et choses ressemblant à des noms ; généralement affichés en gras. Tout texte inclus dans les guillemets inversés est affiché littéralement ; le balisage en ligne n'est pas traité. Sortie HTML : <code>.
**étoiles doubles** (compatible markdown)
Également affiché en gras. Contrairement aux guillemets inversés, le balisage en ligne est traité. Sortie HTML : <strong>.
<angles> (extension markdown non compatible)
Arguments spécifiés par l'utilisateur, variables ou entrée utilisateur. Généralement affiché en souligné dans la sortie roff. Sortie HTML : <var/>.
_tiret bas_ (compatible markdown)
Emphase. Peut être utilisé pour les valeurs d'option littérales. Généralement affiché en souligné dans la sortie roff. Sortie HTML : <em>.

Voici la section DESCRIPTION de grep(1) représentée en ronn :

`Grep` recherche dans le <FICHIER> nommé (ou l'entrée standard si
aucun fichier n'est nommé, ou si le nom de fichier `-` est donné) les lignes
contenant une correspondance avec le <MOTIF> donné. Par défaut, `grep`
affiche les lignes correspondantes.

LISTES DE DÉFINITION

La syntaxe des listes de définition est compatible avec la syntaxe des listes non ordonnées de markdown mais exige que la première ligne de chaque élément de liste soit terminée par un caractère deux-points ":". Le contenu de la première ligne est le terme ; les lignes suivantes peuvent être composées de plusieurs paragraphes, blocs de code, listes standard et listes de définition imbriquées.

Un exemple de liste de définition, tiré de la section DESCRIPTION de test(1) de BSD :

 Les primaires suivantes sont utilisées pour construire des expressions :
   * `-b` <fichier>:
     Vrai si <fichier> existe et est un fichier spécial de bloc.
   * `-c` <fichier>:
     Vrai si _fichier_ existe et est un fichier spécial de caractère.
   * `-d` <fichier>:
     Vrai si le fichier existe et est un répertoire.

LIENS

Toutes les fonctionnalités de liaison de markdown(7) sont prises en charge.

Les liens de style référence Markdown peuvent être utilisés pour lier des sections spécifiques par leur nom :

## SECTION 1
Voir la section suivante.
## SECTION 2
Voir [SECTION 1][] ou [pour le dire autrement][SECTION 1].

Le nom de l'ancre serait #SECTION-1 et #SECTION-2. Tous les caractères non-mot sont supprimés et les espaces sont remplacés par des tirets.

VOIR AUSSI
