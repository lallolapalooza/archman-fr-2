NOM

Débogage de rofi.

Lorsque vous signalez un problème de plantage ou de mauvais comportement de rofi. Il est utile d'effectuer quelques petits tests pour aider à cerner le problème.

Essayez d'abord de désactiver votre configuration personnalisée : -no-config

Ceci désactive l'analyse des fichiers de configuration. Ceci lance rofi en mode par défaut.

Si vous utilisez des plugins C personnalisés, vous pouvez les désactiver en utilisant : -no-plugins

Obtenir les informations pertinentes pour un problème

Veuillez mettre en pâte les sorties des commandes suivantes sur un site de pastebin :

rofi -help
rofi -dump-config
rofi -dump-theme
rofi -help nous fournit les fichiers de configuration analysés, la version exacte, la disposition des moniteurs et d'autres informations utiles.
Les sorties de rofi -dump-config et rofi -dump-theme nous donnent l'interprétation de rofi de votre configuration et de votre thème.

Veuillez vérifier les sorties pour les informations identifiables et les supprimer.

Traces de chronométrage

Pour obtenir une trace de chronométrage, activez le domaine de débogage Timings.

G_MESSAGES_DEBUG=Timings rofi -show drun

Cela affichera une trace avec des informations de chronométrage (utiles) aux points pertinents de l'exécution. Ceci aidera au débogage lorsque rofi est lent à démarrer.

Domaines de débogage

Pour déboguer davantage le plugin, vous pouvez obtenir une trace avec (beaucoup) d'informations de débogage. Cette sortie de débogage peut être activée pour plusieurs parties de rofi en utilisant le framework de débogage glib. Les domaines de débogage peuvent être activés en définissant la variable d'environnement G_MESSAGES_DEBUG. Au moment de la création de cette page, les domaines de débogage suivants existent :

•
all : Afficher les informations de débogage de tous les domaines.
•
X11Helper : Les fonctions d'aide X11.
•
View : Les fonctions de la fenêtre principale.
•
Widgets.Box : Le widget Box.
•
Modes.DMenu : Le mode dmenu.
•
Modes.Run : Le mode d'exécution.
•
Modes.DRun : Le mode d'exécution des fichiers de bureau.
•
Modes.Window : Le mode fenêtre.
•
Modes.Script : Le mode script.
•
Modes.Combi : Le mode script.
•
Modes.Ssh : Le mode ssh.
•
Rofi : L'application principale.
•
Timings : Obtenir la sortie de chronométrage.
•
Theme : Sortie de débogage du moteur de thème. (attention, beaucoup de sortie).
•
Widgets.Icon : Le widget Icon.
•
Widgets.Box : Le widget box.
•
Widgets.Container : Le widget conteneur.
•
Widgets.Window : Le widget fenêtre.
•
Helpers.IconFetcher : Informations sur la recherche d'icônes.

Pour la liste complète, voir man rofi.

Exemple : G_MESSAGES_DEBUG=Dialogs.DRun rofi -show drun Pour obtenir une sortie spécifique de la boîte de dialogue d'exécution des fichiers de bureau.

Créer une trace d'exécution

Assurez-vous d'abord de compiler rofi avec les symboles de débogage :

make CFLAGS="-O0 -g3" clean rofi

Obtenir une trace d'exécution à l'aide de GDB n'est pas très pratique. Car si rofi se bloque, il capture le clavier et la souris. Donc s'il plante dans GDB, vous êtes bloqué. La meilleure façon est d'activer le fichier core. (ulimit -c unlimited dans bash) puis de faire planter rofi. Vous pourrez alors charger le core dans GDB.

gdb rofi core

Tapez ensuite dans gdb :

thread apply all bt

La trace de sortie est utile lors du signalement de plantages.

Certaines distributions ont systemd-coredump, vous pouvez ainsi obtenir facilement une trace d'exécution via coredumpctl.
