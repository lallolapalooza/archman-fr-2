NOM

rofi script mode - Format Rofi pour mode scriptable.

DESCRIPTION

rofi supporte des modes qui utilisent des scripts simples en arrière-plan pour générer une liste et traiter le résultat des actions de l'utilisateur. Ceci fournit une interface simple pour créer des extensions simples à rofi.

UTILISATION

Pour spécifier un mode script, définissez un mode avec la syntaxe suivante : “{nom}:{exécutable}”

Par exemple :

rofi -show fb -modes "fb:file_browser.sh"

Le nom doit être unique.

API

Rofi appelle l'exécutable sans arguments au démarrage. Celui-ci doit générer une liste d'options, séparées par un retour à la ligne (\n) (Ceci peut être changé par le script). Si l'utilisateur sélectionne une option, rofi appelle l'exécutable avec le texte de cette option comme premier argument. Si le script ne retourne aucune entrée, rofi se quitte.

Un script simple serait :

#!/usr/bin/env bash
if [ x"$@" = x"quit" ]
then
    exit 0
fi
echo "reload"
echo "quit"

Ceci affiche deux entrées, reload et quit. Lorsque l'entrée quit est sélectionnée, rofi se ferme.

Environnement

Rofi définit la variable d'environnement suivante lors de l'exécution du script :

ROFI_RETV

Un nombre entier représentant l'état actuel :

•
0 : Appel initial du script.
•
1 : Entrée sélectionnée.
•
2 : Entrée personnalisée sélectionnée.
•
3 : Entrée supprimée.
•
10-28 : Raccourcis personnalisés 1-19 (doivent être explicitement activés par le script).

ROFI_INFO

Variable d'environnement définie lorsque l'entrée sélectionnée est définie avec la valeur de la propriété `info' de l'option de ligne, si elle est définie.

ROFI_DATA

Variable d'environnement définie lorsque le script définit l'option data dans l'en-tête.

Passage des options de mode

Des options supplémentaires, comme la définition de l'invite, peuvent être définies par le script. Les options supplémentaires sont des lignes qui commencent par un caractère NULL (\0) suivi d'une clé, d'un séparateur (\x1f) et d'une valeur.

Par exemple, pour définir l'invite :

    echo -en "\0prompt\x1fChanger l'invite\n"

Les options supplémentaires suivantes existent :

•
prompt : Met à jour le texte de l'invite.
•
message : Met à jour le texte du message.
•
markup-rows : Si `true', affiche le balisage dans la ligne.
•
urgent : Marque les lignes comme urgentes. (pour la syntaxe, voir l'option `urgent' en mode dmenu)
•
active : Marque les lignes comme actives. (pour la syntaxe, voir l'option `active' en mode dmenu)
•
delim : Définit le délimiteur pour les lignes suivantes. Par défaut, c'est `' et cette option doit se terminer par celui-ci. N'appelez cette option que lors du premier appel du script, elle est mémorisée pour les appels consécutifs.
•
no-custom : Si défini sur `true'; n'accepte que les entrées listées, ignore les entrées personnalisées.
•
use-hot-keys : Si défini sur `true', il active les raccourcis clavier personnalisés pour le script. Attention, cela casse le flux normal de rofi.
•
keep-selection : Si défini, la sélection n'est pas déplacée vers la première entrée, mais la position actuelle est maintenue. Le filtre est effacé.
•
keep-filter : Si défini, le filtre n'est pas effacé.
•
new-selection : Si keep-selection est défini, cela vous permet de remplacer l'entrée sélectionnée (position absolue).
•
data : Transmet des données à la prochaine exécution du script via ROFI_DATA.
•
theme : Petit extrait de thème pour, par exemple, changer la couleur de fond d'un widget.

La propriété theme ne peut pas changer l'interface pendant l'exécution, elle est seulement utilisable pour de petits changements, par exemple la couleur de fond, des widgets qui sont mis à jour pendant l'affichage comme la couleur de la ligne de la liste.

Analyse des options de ligne

Des options supplémentaires pour les lignes individuelles peuvent être définies. L'option supplémentaire peut être spécifiée en suivant la même syntaxe que l'option de mode, mais après l'entrée.

Par exemple :

    echo -en "aap\0icon\x1ffolder\n"

Les options suivantes sont supportées :

•
icon : Définit l'icône pour cette ligne.
•
display : Remplace la chaîne affichée. (La chaîne originale sera toujours utilisée pour le filtrage)
•
meta : Spécifie des termes de recherche invisibles utilisés pour le filtrage.
•
nonselectable : Si vrai, la ligne ne peut pas être activée.
•
permanent : Si vrai, la ligne s'affiche toujours, indépendamment du filtre.
•
info : Informations qui, lors de la sélection, sont placées dans la variable d'environnement ROFI_INFO. Cette entrée n'est pas recherchée pour le filtrage.
•
urgent : Définit le drapeau urgent sur l'entrée (vrai/faux)
•
active : Définit le drapeau actif sur l'entrée (vrai/faux)

Plusieurs entrées peuvent être passées en utilisant le séparateur \x1f.

    echo -en "aap\0icon\x1ffolder\x1finfo\x1ftest\n"

Exécution d'un programme externe

Si vous souhaitez lancer un programme externe depuis le script, vous devez vous assurer qu'il est lancé en arrière-plan. Sinon, rofi attendra sa sortie (pour l'afficher).

En bash, la meilleure façon de le faire est d'utiliser coproc.

 coproc ( myApp  > /dev/null  2>&1 )

Shell DASH

Si vous utilisez le shell dash pour votre script, soyez particulièrement attentif à la manière dont dash gère les valeurs échappées pour les séparateurs. Voir le problème #1201 sur github.

Emplacements des scripts

Pour spécifier un script, il y a les options suivantes :

•
Spécifiez un chemin absolu vers le script.
•
Le script est exécutable et situé dans votre $PATH

Les scripts situés aux emplacements suivants sont chargés au démarrage et peuvent être lancés directement en fonction du nom de fichier (sans extension) :

•
Le script se trouve dans $XDG_CONFIG_HOME/rofi/scripts/, ce qui est généralement ~/.config/rofi/scripts/.

Si vous avez un script `mymode.sh' dans ce dossier, vous pouvez l'ouvrir en utilisant :

rofi -show mymode

Voir la sortie de rofi -h pour une liste des scripts détectés.
