NOM

roc-recv - recevoir de l'audio en temps réel

SYNOPIS

roc-recv OPTIONS

DESCRIPTION

Reçoit des flux audio de senders distants et les écrit sur un périphérique audio ou dans un fichier.

Options

-h, --help
Affiche l'aide et quitte
-V, --version
Affiche la version et quitte
-v, --verbose
Augmente le niveau de verbosité (peut être utilisé plusieurs fois)
-L, --list-supported
liste les schémas et formats supportés
-o,--output=URI_IO
Fichier de sortie ou URI du périphérique
--output-format=FORMAT_FICHIER
Force le format du fichier de sortie
--backup=URI_IO
Fichier de sauvegarde ou URI du périphérique (si défini, utilisé lorsqu'il n'y a pas de sessions)
--backup-format=FORMAT_FICHIER
Force le format du fichier de sauvegarde
-s,--source=ENDPOINT_URI
Point de terminaison source local
-r,--repair=ENDPOINT_URI
Point de terminaison de réparation local
-c,--control=ENDPOINT_URI

URI du point de terminaison

Les options --source, --repair et --control définissent les points de terminaison réseau sur lesquels recevoir le trafic.

ENDPOINT_URI doit avoir le format suivant :

protocole://hôte[:port][/chemin][?requête]

Exemples :

  • rtsp://localhost:123/chemin?requête
  • rtp+rs8m://localhost:123
  • rtp://0.0.0.0:123
  • rtp://[::1]:123
  • rtcp://0.0.0.0:123

La liste des protocoles supportés peut être récupérée à l'aide de l'option --list-supported.

Le champ hôte doit être soit un FQDN (nom de domaine), soit une adresse IPv4, soit une adresse IPv6 entre crochets. Il peut être 0.0.0.0 (pour IPv4) ou [::] (pour IPv6) pour lier le point de terminaison à toutes les interfaces réseau.

Le champ port peut être omis si le protocole définit un port standard. Sinon, il est obligatoire. Il peut être défini à zéro pour lier le point de terminaison à un port éphémère choisi aléatoirement.

Les champs chemin et requête sont autorisés uniquement pour les protocoles qui les supportent, par exemple pour RTSP.

Si le FEC est activé sur l'émetteur, une paire de points de terminaison source et de réparation doit être fournie. Les deux points de terminaison doivent utiliser des protocoles compatibles, par exemple rtp+rs8m:// pour le point de terminaison source, et rs8m:// pour le point de terminaison de réparation. Si le FEC est désactivé, un seul point de terminaison source doit être fourni.

Protocoles source et de réparation supportés :

  • source rtp://, réparation none (RTP simple sans FEC)
  • source rtp+rs8m://, réparation rs8m:// (RTP avec FEC Reed-Solomon)
  • source rtp+ldpc://, réparation ldpc:// (RTP avec FEC LDPC-Staircase)

De plus, il est recommandé de fournir un point de terminaison de contrôle. Il est utilisé pour échanger des informations non médiatiques servant à identifier la session, porter les retours, etc. Si aucun point de terminaison de contrôle n'est fourni, la session fonctionne en mode de repli réduit, ce qui peut être moins robuste et ne pas supporter toutes les fonctionnalités.

Protocoles de contrôle supportés :

•
rtcp://

URI IO

Les options --output et --backup nécessitent un URI de périphérique ou de fichier dans l'un des formats suivants :

  • TYPE_APPAREIL://NOM_APPAREIL -- périphérique audio
  • TYPE_APPAREIL://default -- périphérique audio par défaut pour le type d'appareil donné
  • file:///CHEMIN/ABSOLU -- chemin de fichier absolu
  • file://localhost/CHEMIN/ABSOLU -- chemin de fichier absolu (forme alternative ; seul l'hôte "localhost" est supporté)
  • file:/CHEMIN/ABSOLU -- chemin de fichier absolu (forme alternative)
  • file:CHEMIN/RELATIF -- chemin de fichier relatif
  • file://- -- stdout
  • file:- -- stdout (forme alternative)

Exemples :

  • pulse://default
  • pulse://alsa_output.pci-0000_00_1f.3.analog-stereo
  • alsa://hw:1,0
  • file:///home/utilisateur/test.wav
  • file://localhost/home/utilisateur/test.wav
  • file:/home/utilisateur/test.wav
  • file:./test.wav
  • file:-

La liste des schémas et formats de fichiers supportés peut être récupérée à l'aide de l'option --list-supported.

Si --output est omis, le pilote et le périphérique par défaut sont sélectionnés

OPTIONS

The following options are available:

--backup [URI]
Define backup source. If --backup is omitted, no backup source is used.
--output-format FORMAT
--backup-format FORMAT
Can be used to force the output or backup file format. If the option is omitted, the file format is auto-detected. The option is always required when the output or backup is stdout or stdin.

The path component of the provided URI is percent-decoded. For convenience, unencoded characters are allowed as well, except that % should be always encoded as %25.

For example, the file named /foo/bar%/[baz] may be specified using either of the following URIs: file:///foo%2Fbar%25%2F%5Bbaz%5D and file:///foo/bar%25/[baz].

Multicast interface

If --miface option is present, it defines an IP address of the network interface on which to join the multicast group. If not present, no multicast group should be joined.

It's not possible to receive multicast traffic without joining a multicast group. The user should either provide multicast interface, or join the group manually using foreign tools.

MIFACE should be an IP address of the network interface on which to join the multicast group. It may be 0.0.0.0 (for IPv4) or :: (for IPv6) to join the multicast group on all available interfaces.

Multiple slots

Multiple sets of endpoints can be specified to retrieve media from multiple addresses.

Such endpoint sets are called slots. All slots should have the same set of endpoint types (source, repair, etc) and should use the same protocols for them. All slots should also have their own multicast interface option, if it's used.

SO_REUSEADDR

If --reuseaddr option is provided, SO_REUSEADDR socket option will be enabled for all sockets (by default it's enabled only for multicast sockets).

For TCP, it allows immediately reusing recently closed socket in TIME_WAIT state, which may be useful you want to be able to restart server quickly.

For UDP, it allows multiple processes to bind to the same address, which may be useful if you're using systemd socket activation.

Regardless of the option, SO_REUSEADDR is always disabled when binding to ephemeral port.

Backup audio

If --backup option is given, it defines input audio device or file which will be played when there are no connected sessions. If it's not given, silence is played instead.

Backup file is restarted from the beginning each time when the last session disconnect. The playback of of the backup file is automatically looped.

Time units

TIME should have one of the following forms:
123ns; 1.23us; 1.23ms; 1.23s; 1.23m; 1.23h;

Size units

SIZE should have one of the following forms:
123; 1.23K; 1.23M; 1.23G;

EXEMPLES

Exemples de points d'extrémité

Lier un point d'extrémité RTP nu sur toutes les interfaces IPv4 :

$ roc-recv -vv -s rtp://0.0.0.0:10001

Lier les points d'extrémité source, réparation et contrôle à toutes les interfaces IPv4 (mais pas IPv6) :

$ roc-recv -vv -s rtp+rs8m://0.0.0.0:10001 -r rs8m://0.0.0.0:10002 \
    -c rtcp://0.0.0.0:10003

Lier les points d'extrémité source, réparation et contrôle à toutes les interfaces IPv6 (mais pas IPv4) :

$ roc-recv -vv -s rtp+rs8m://[::]:10001 -r rs8m://[::]:10002 -c rtcp://[::]:10003

Lier les points d'extrémité source, réparation et contrôle à une interface réseau particulière :

$ roc-recv -vv -s rtp+rs8m://192.168.0.3:10001 -r rs8m://192.168.0.3:10002 \
    -c rtcp://192.168.0.3:10003

Lier les points d'extrémité à une adresse multicast particulière et rejoindre un groupe multicast sur une interface réseau particulière :

$ roc-recv -vv -s rtp+rs8m://225.1.2.3:10001 -r rs8m://225.1.2.3:10002 \
    -c rtcp://225.1.2.3:10003 \
    --miface 192.168.0.3

Lier deux ensembles de points d'extrémité source, réparation et contrôle (six points d'extrémité au total) :

$ roc-recv -vv \
    -s rtp+rs8m://192.168.0.3:10001 -r rs8m://192.168.0.3:10002 \
        -c rtcp://192.168.0.3:10003 \
    -s rtp+rs8m://198.214.0.7:10001 -r rs8m://198.214.0.7:10002 \
        -c rtcp://198.214.0.7:10003

Exemples d'entrées/sorties

Sortie vers le périphérique par défaut (omettre -o) :

$ roc-recv -vv -s rtp://0.0.0.0:10001

Sortie vers le périphérique ALSA par défaut :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o alsa://default

Sortie vers un périphérique PulseAudio spécifique :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o pulse://alsa_input.pci-0000_00_1f.3.analog-stereo

Sortie vers un fichier au format WAV (deviner le format par extension) :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:./output.wav

Sortie vers un fichier au format WAV (spécifier le format manuellement) :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:./output.file --output-format wav

Sortie vers stdout au format WAV :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:- --output-format wav >./output.wav

Sortie vers un fichier au format WAV (chemin absolu) :

$ roc-recv -vv -s rtp://0.0.0.0:10001 -o file:///home/user/output.wav

Spécifier un fichier de sauvegarde :

$ roc-recv -vv -s rtp://0.0.0.0:10001 --backup file:./backup.wav

Exemples de réglage

Forcer un débit spécifique sur le périphérique de sortie :

$ roc-recv -vv -s rtp://0.0.0.0:10001 --rate=44100

Sélectionner le schéma FEC LDPC-Staircase :

$ roc-recv -vv -s rtp+ldpc://0.0.0.0:10001 -r ldpc://0.0.0.0:10002 \
    -c rtcp://0.0.0.0:10003

Sélectionner une latence de session plus faible :

$ roc-recv -vv -s rtp://0.0.0.0:10001 --target-latency=50ms

Sélectionner une latence d'entrée/sortie et une longueur de trame plus faibles :

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --io-latency=20ms --frame-len 4ms

Spécifier manuellement les seuils et les délais d'attente :

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --target-latency=50ms --min-latency=40ms --max-latency 60ms \
    --no-play-timeout=200ms --choppy-play-timeout=500ms

Spécifier manuellement les paramètres de rééchantillonnage :

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --resampler-backend=speex --resampler-profile=high

Spécifier manuellement les paramètres de réglage de la latence :

$ roc-recv -vv -s rtp://0.0.0.0:10001 \
    --latency-backend=niq --latency-profile=gradual

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes sont prises en charge :

NO_COLOR
Par défaut, la coloration du terminal est automatiquement détectée. Cette variable d'environnement peut être définie sur une chaîne non vide pour désactiver la coloration du terminal. Elle a une priorité inférieure à l'option --color.
FORCE_COLOR
Par défaut, la coloration du terminal est automatiquement détectée. Cette variable d'environnement peut être définie sur un entier positif pour activer/forcer la coloration du terminal. Elle a une priorité inférieure à la variable NO_COLOR et à l'option --color.
