ROUTE(8) Manuel d'administration système Linux ROUTE(8)

NOM

route - afficher / manipuler la table de routage IP

SYNTAXE

route [-CFvnNee] [-A famille |-4|-6]

route
[-v] [-A famille |-4|-6] add [-net|-host] cible [netmask Nm] [gw Gw] [metric N] [mss M] [window W] [irtt I] [reject] [mod] [dyn] [reinstate] [[dev] If]
route
[-v] [-A famille |-4|-6] del [-net|-host] cible [gw Gw] [netmask Nm] [metric M] [[dev] If]
route
[-V] [--version] [-h] [--help]

DESCRIPTION

Route manipule les tables de routage IP du noyau. Son utilisation principale est de configurer des routes statiques vers des hôtes ou des réseaux spécifiques via une interface après sa configuration avec le programme ifconfig(8).

Lorsque les options add ou del sont utilisées, route modifie les tables de routage. Sans ces options, route affiche le contenu actuel des tables de routage.

OPTIONS

-A famille
utilise la famille d'adresses spécifiée (par ex. `inet'). Utilisez route --help pour une liste complète. Vous pouvez utiliser -6 comme alias pour --inet6 et -4 comme alias pour -A inet
-F
opère sur la table de routage FIB (Forwarding Information Base) du noyau. C'est le comportement par défaut.
-C
opère sur le cache de routage du noyau.
-v
sélectionne le mode verbeux.
-n
affiche les adresses numériques au lieu d'essayer de déterminer les noms d'hôtes symboliques. C'est utile si vous essayez de déterminer pourquoi la route vers votre serveur DNS a disparu.
-e
utilise le format de netstat(8) pour afficher la table de routage. -ee générera une ligne très longue avec tous les paramètres de la table de routage.
del
supprime une route.
add
ajoute une nouvelle route.
cible
le réseau ou l'hôte de destination. Vous pouvez fournir une adresse ou un nom de réseau ou d'hôte symbolique. Optionnellement, vous pouvez utiliser la notation /longueur_pref au lieu d'utiliser l'option netmask.
-net
la cible est un réseau.
-host
la cible est un hôte.
netmask NM
lors de l'ajout d'une route réseau, le masque de réseau à utiliser.
gw GW
achemine les paquets via une passerelle.
NOTE : La passerelle spécifiée doit être joignable au préalable. Cela signifie généralement que vous devez configurer une route statique vers la passerelle avant. Si vous spécifiez l'adresse d'une de vos interfaces locales, elle sera utilisée pour décider quelle interface doit être utilisée pour le routage des paquets. C'est une astuce de compatibilité BSD.
metric M
définit le champ métrique dans la table de routage (utilisé par les démons de routage) à M. Si cette option n'est pas spécifiée, la métrique pour la famille d'adresses inet6 (IPv6) est par défaut '1', pour inet (IPv4) elle est par défaut '0'. Vous devriez toujours spécifier une valeur métrique explicite pour ne pas dépendre de ces valeurs par défaut - elles diffèrent également de iproute2.
mss M
définit l'unité de transmission maximale (MTU) de la route à M octets. Notez que l'implémentation actuelle de la commande route ne permet pas l'option de définir la taille maximale de segment (MSS).
window W
définit la fenêtre TCP pour les connexions sur cette route à W octets. Ceci est généralement utilisé uniquement sur les réseaux AX.25 et avec des pilotes incapables de gérer des trames consécutives.
irtt I
définit le temps aller-retour initial (irtt) pour les connexions TCP sur cette route à I millisecondes (1-12000). Ceci est généralement utilisé uniquement sur les réseaux AX.25. Si omis, la valeur par défaut de 300 ms selon la RFC 1122 est utilisée.
reject
installe une route de blocage, qui forcera une recherche de route à échouer. Ceci est par exemple utilisé pour masquer des réseaux avant d'utiliser la route par défaut. Ceci n'est PAS pour le pare-feu.
mod, dyn, reinstate
installe une route dynamique ou modifiée. Ces indicateurs sont à des fins de diagnostic et sont généralement uniquement définis par les démons de routage.
dev If
force la route à être associée à l'interface spécifiée, car le noyau essaiera sinon de déterminer l'interface par lui-même (en vérifiant les routes déjà existantes et les spécifications d'interface, et où la route est ajoutée). Dans la plupart des réseaux normaux, vous n'en aurez pas besoin.

Si dev If est la dernière option sur la ligne de commande, le mot dev peut être omis, car c'est le comportement par défaut. Sinon, l'ordre des modificateurs de route (metric netmask gw dev) n'a pas d'importance.

EXEMPLES

route add -net 127.0.0.0 netmask 255.0.0.0 metric 1024 dev lo
ajoute l'entrée de boucle locale normale, en utilisant le masque de réseau 255.0.0.0 et associée à l'interface "lo" (en supposant que cette interface ait été correctement configurée auparavant avec ifconfig(8)).
route add -net 192.56.76.0 netmask 255.255.255.0 metric 1024 dev eth0
ajoute une route vers le réseau local 192.56.76.x via "eth0". Le mot "dev" peut être omis ici.
route del default
supprime la route par défaut actuelle, qui est étiquetée "default" ou 0.0.0.0 dans le champ destination de la table de routage actuelle.
route del -net 192.56.76.0 netmask 255.255.255.0
supprime la route. Comme le noyau de routage Linux utilise l'adressage sans classe, vous devez presque toujours spécifier le masque de réseau qui est le même que celui vu dans l'affichage 'route -n'.
route add default gw mango
ajoute une route par défaut (qui sera utilisée si aucune autre route ne correspond). Tous les paquets utilisant cette route seront acheminés via l'adresse d'un nœud nommé "mango". L'interface qui sera effectivement utilisée pour cette route dépendra de la manière dont nous pouvons atteindre "mango" - "mango" doit être sur une route directement accessible.
route add mango sl0
Ajoute la route vers l'hôte nommé "mango" via l'interface SLIP (en supposant que "mango" est l'hôte SLIP).
route add -net 192.57.66.0 netmask 255.255.255.0 gw mango
Cette commande ajoute le réseau "192.57.66.x" à acheminer via l'ancienne route vers l'interface SLIP.
route add -net 224.0.0.0 netmask 240.0.0.0 dev eth0
C'est une commande obscure documentée pour que les gens sachent comment la faire. Elle configure toutes les routes IP de classe D (multicast) pour passer par "eth0". C'est la ligne de configuration normale correcte avec un noyau multicast.

SORTIE

La sortie de la table de routage du noyau est organisée dans les colonnes suivantes

Destination
Le réseau de destination ou l'hôte de destination.
Passerelle
L'adresse de la passerelle ou '*' si aucune n'est définie.
Masque générique
Le masque de réseau pour le réseau de destination ; '255.255.255.255' pour une destination d'hôte et '0.0.0.0' pour la route par défaut.
Indicateurs
Les indicateurs possibles incluent
U (la route est active)
H (la cible est un hôte)
G (utiliser la passerelle)
R (rétablir la route pour le routage dynamique)
D (installé dynamiquement par un démon ou une redirection)
M (modifié par un démon de routage ou une redirection)
A (installé par addrconf)
C (entrée du cache)
! (route de rejet)
Métrique
La 'distance' vers la cible (généralement comptée en sauts).
Réf
Nombre de références à cette route. (Non utilisé dans le noyau Linux.)
Utilisation
Nombre d'accès à la route. Selon l'utilisation de -F et -C, il s'agira soit de ratés de cache de route (-F), soit de succès (-C).
Interface
L'interface sur laquelle les paquets pour cette route seront envoyés.
MSS
Taille maximale de segment par défaut pour les connexions TCP sur cette route.
Fenêtre
Taille de fenêtre par défaut pour les connexions TCP sur cette route.
irtt
RTT initial (temps de trajet aller-retour). Le noyau l'utilise pour estimer les meilleurs paramètres du protocole TCP sans attendre (potentiellement lente) réponses.
HH (en cache uniquement)
Le nombre d'entrées ARP et de routes mises en cache qui se réfèrent à l'en-tête matériel du cache pour la route mise en cache. Ce sera -1 si une adresse matérielle n'est pas nécessaire pour l'interface de la route mise en cache (par exemple, lo).
ARP (en cache uniquement)
Indique si l'adresse matérielle de la route mise en cache est à jour ou non.
