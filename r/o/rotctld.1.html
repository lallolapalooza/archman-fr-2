ROTCTLD(1) Utilitaires Hamlib ROTCTLD(1)

NOM

rotctld - démon de contrôle de rotator TCP

SYNTAXE

rotctld [-hlLuV] [-m id] [-r périphérique] [-s débit] [-T ADRESSE_IP] [-t nombre] [-C parm=val] [-v[-Z]]

DESCRIPTION

Le programme rotctld est un démon de contrôle de rotator qui gère les requêtes des clients via des sockets TCP. Cela permet à plusieurs programmes utilisateurs de partager un seul rotator (cela nécessite plus de développement). Plusieurs rotators peuvent être contrôlés sur différents ports TCP en utilisant plusieurs processus rotctld. La syntaxe des commandes est la même que celle de rotctl(1). On espère que rotctld sera particulièrement utile aux auteurs de clients utilisant des langages tels que Perl, Python, PHP, et autres.

rotctld communique avec un client via un socket TCP en utilisant des commandes textuelles partagées avec rotctl. Le protocole est simple, les commandes sont envoyées à rotctld sur une ligne et rotctld répond aux commandes « get » avec les valeurs demandées, une par ligne, en cas de succès, sinon, il répond avec une ligne « RPRT x », où « x » est un nombre négatif indiquant le code d'erreur. Les commandes qui ne retournent pas de valeurs répondent avec la ligne « RPRT x », où « x » est « 0 » en cas de succès, sinon c'est un nombre négatif indiquant le code d'erreur. Chaque ligne est terminée par un caractère de saut de ligne « \n » . Ce protocole est principalement destiné à être utilisé par le backend NET rotctl (modèle de rotator 2).

Un Protocole de réponse étendu distinct étend le comportement ci-dessus en écho la chaîne de commande reçue comme en-tête, toute valeur renvoyée sous forme de paire clé: valeur, et la chaîne « RPRT x » comme marqueur de fin de réponse qui inclut la valeur de succès ou d'échec de Hamlib. Voir la section PROTOCOLE pour les détails. Envisagez d'utiliser ce protocole pour les clients qui interagiront directement avec rotctld via un socket TCP.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que de nombreuses bibliothèques backend manquent de prise en charge complète des rotators, les fonctions de base sont généralement bien prises en charge.

Veuillez signaler les bugs et fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (« - ») nécessitent un « = » entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --modele=id
Sélectionne le numéro du modèle de rotator.
Voir la liste des modèles (utiliser « rotctld -l »).
Note : rotctl (ou un logiciel tiers utilisant l'API C) utilisera le modèle de rotator 2 pour NET rotctl (ce numéro de modèle n'est pas utilisé pour rotctld bien qu'il apparaisse dans la liste des modèles).
-r, --fichier-rot=périphérique
Utilise périphérique comme nom de fichier du port connecté au rotator.
Souvent un port série, mais pourrait être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les dérivés BSD et Mac OS/X ont leurs propres désignations. Consultez la documentation de votre système.
-s, --vitesse-serie=débit
Définit la vitesse série sur le débit débit.
Utilise le débit série maximal des capacités du backend du rotator comme valeur par défaut.
-T, --addr-ecoute=ADRESSE_IP
Utilise ADRESSE_IP comme adresse IP d'écoute.
La valeur par défaut est ANY.
rotctld peut être exécuté et connecté comme suit :
rotctld (se connecte à toutes les interfaces)
rotctl -m 2
rotctl -m 2 -r 127.0.0.1
rotctl -m 2 -r localhost
rotctl -m 2 -r 192.168.1.1 (adresse IP locale)
rotctl -m 2 -r ::1 (sous Linux rotctld n'écoute pas sur IPV6 par défaut)

rotctld -T 127.0.0.1 (se connecte uniquement à 127.0.0.1)
rotctl -m 2 (se connecte à toutes les interfaces)
rotctl -m 2 -r 127.0.0.1 (se connecte uniquement à 127.0.0.1)
-t, --port=nombre
Utilise nombre comme port d'écoute TCP.
La valeur par défaut est 4533.
Note : Comme le port par défaut de rotctld est 4533, il est conseillé d'utiliser des ports impairs pour rotctld, par exemple 4533, 4535, 4537, etc.
-L, --afficher-conf
Liste tous les paramètres de configuration du rotator défini avec -m ci-dessus.
-C, --definir-conf=parm=val[,parm=val]
Définit un ou plusieurs paramètres de configuration du rotator, par exemple stop_bits=2.
Utilisez l'option -L ci-dessus pour obtenir la liste des paramètres de configuration pour un numéro de modèle donné.
-u, --vider-etat
Vide l'état du rotator défini avec -m ci-dessus et quitte.
-u, --vider-capacites
Vide les capacités du rotator défini avec -m ci-dessus et quitte.
-l, --lister
Liste tous les numéros de modèles de rotator définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être parcourue en arrière en utilisant Maj-PagePrécédente/Maj-PageSuivante, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou la fenêtre cmd sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple « rotctl -l | more ».
-v, --verbeux
Active le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Z, --horodatages-debug
Active les horodatages pour les messages de débogage.
Utiliser uniquement en combinaison avec l'option -v car cela ne génère aucune sortie par lui-même.
-h, --aide
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rotctld et quitte.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. C'est le plus probable avec les options --definir-conf et --afficher-conf.

Soyez conscient que le backend pour le rotator à contrôler, ou le rotator lui-même peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un code d'erreur Hamlib.

COMMANDES

Les commandes peuvent être envoyées sur le socket TCP soit comme un seul caractère, soit comme un nom de commande long plus la ou les valeurs séparées par un espace sur une ligne terminée par « \n ». Voir PROTOCOLE.

Comme la plupart des opérations Hamlib ont une méthode set et une méthode get, une lettre majuscule sera utilisée pour les méthodes set tandis que la lettre minuscule correspondante fera référence à la méthode get. Chaque opération a également un nom long ; préfixez avec une barre oblique inverse, « \ », pour envoyer un nom de commande long.

Exemple (Perl) : « print $socket « \\dump_caps\n »; » pour voir ce que le backend du rotator peut faire (Note : En Perl et dans de nombreux autres langages, une « \ »

9; devront être échappés avec un caractère anti-slash précédant ‘\’ de sorte que, même si deux caractères anti-slash apparaissent dans le code, un seul sera transmis à rotctld. Ceci est un bug potentiel, attention !

Note : Le backend pour le rotateur à contrôler, ou le rotateur lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un message d'erreur Hamlib.

Voici un résumé des commandes supportées (Dans le cas des commandes set, la chaîne itérative entre guillemets est remplacée par la valeur dans la description. Dans le cas des commandes get, la chaîne itérative entre guillemets est le nom de clé de la valeur retournée.) :

P, set_pos 'Azimuth' 'Elevation'
Définit la position.
'Azimuth' et 'Elevation' sont des valeurs flottantes.
Par exemple (texte tapé affiché en gras) :

P 163.0 41.0

Note : Si le rotateur ne supporte pas la définition de l'élévation (la plupart ne le font pas), fournissez "0.0" pour 'Elevation'.
p, get_pos
Obtient la position.
'Azimuth' et 'Elevation' sont retournés en tant que valeurs flottantes double précision.
M, move 'Direction' 'Speed'
Déplace le rotateur dans une direction spécifique à la vitesse donnée.
'Direction' est un entier ou un mot-clé défini comme '2' = UP, '4' = DOWN, '8' = LEFT ou CCW, '16' = RIGHT ou CW, '32' = UP_LEFT ou UP_CCW, 'R64' = UP_RIGHT = UP_CW, '128' = DOWN_LEFT ou DOWN_CCW, '256' = DOWN_RIGHT ou DOWN_CW.
'Speed' est un entier compris entre 1 et 100. Utilisez -1 pour ne pas modifier la vitesse actuelle.
Note : Tous les backends qui implémentent la commande move n'utilisent pas la valeur Speed.
S, stop
Arrête le rotateur.
K, park
Met le rotateur en position de stationnement (park).
C, set_conf 'Token' 'Value'
Définit un paramètre de configuration.
'Token' est une chaîne de caractères ; voir l'option -C et la sortie -L.
'Value' est une chaîne de caractères de 20 caractères maximum.
R, reset 'Reset'
Réinitialise le rotateur.
'Reset' accepte une valeur entière de '1' pour "Reset All" (Réinitialiser tout).
_, get_info
Obtient des informations diverses sur le rotateur.
Retourne 'Info' "Nom du modèle".
dump_state
Retourne certaines informations d'état du backend du rotateur.
1, dump_caps
Ce n'est pas une vraie commande distante rot, elle ne fait que décharger les capacités, c'est-à-dire ce que le backend sait sur ce modèle et ce qu'il peut faire.
w, send_cmd 'Cmd'
Envoie une chaîne de commande brute au rotateur.
Un retour chariot ASCII est automatiquement ajouté à la fin de la commande pour les protocoles texte. Pour les protocoles binaires, entrez les valeurs hexadécimales sous la forme '\0xAA\0xBB'.

Commandes Locator

Ces commandes offrent des conversions de Degrés Minutes Secondes vers d'autres formats, des conversions de carrés de localisation Maidenhead et des conversions de distance et d'azimut.

L, lonlat2loc 'Longitude' 'Latitude' 'Loc Len'
Retourne le 'Locator' Maidenhead pour la 'Longitude' et la 'Latitude' données.
'Longitude' et 'Latitude' sont des valeurs flottantes.
'Loc Len' est la précision du carré retourné et doit être un entier pair compris entre 2 et 12.
Par exemple :

L -170.0 -85.0 12

retourne :

Locator: AA55AA00AA00

l, loc2lonlat 'Locator'
Retourne la 'Longitude' et la 'Latitude' en degrés décimaux au centre approximatif du carré de grille Maidenhead demandé.
'Locator' peut avoir une longueur de 2 à 12 caractères.
La longitude Ouest est exprimée comme une valeur négative.
La latitude Sud est exprimée comme une valeur négative.
Par exemple :

l AA55AA00AA00

retourne :

Longitude: -169.999983 Latitude: -84.999991

Note : Malgré l'utilisation de variables double précision en interne, une certaine erreur d'arrondi se produit.
D, dms2dec 'Degrees' 'Minutes' 'Seconds' 'S/W'
Retourne 'Dec Degrees', une valeur flottante signée.
'Degrees' et 'Minutes' sont des valeurs entières.
'Seconds' est une valeur flottante.
'S/W' est un indicateur avec '1' indiquant la latitude Sud ou la longitude Ouest et '0' la latitude Nord ou la longitude Est (l'indicateur est nécessaire car les ordinateurs ne reconnaissent pas un zéro signé bien que seule la valeur 'Degrees' soit typiquement signée en notation DMS).
d, dec2dms 'Dec Degrees'
Retourne 'Degrees' 'Minutes' 'Seconds' 'S/W'.
Les valeurs sont comme dans dms2dec ci-dessus.
E, dmmm2dec 'Degrees' 'Dec Minutes' 'S/W'
Retourne 'Dec Degrees', une valeur flottante signée.
'Degrees' est une valeur entière.
'Dec Minutes' est une valeur flottante.
'S/W' est un indicateur comme dans dms2dec ci-dessus.
e, dec2dmmm 'Dec Deg'
Retourne 'Degrees' 'Minutes' 'S/W'.
Les valeurs sont comme dans dmmm2dec ci-dessus.
B, qrb 'Lon 1' 'Lat 1' 'Lon 2' 'Lat 2'
Retourne 'Distance' et 'Azimuth'.
'Distance' est en km.
'Azimuth' est en degrés.
Les valeurs de Lon/Lat fournies sont des nombres flottants signés.
A, a_sp2a_lp 'Short Path Deg'
Retourne 'Long Path Deg'.
L'argument fourni et la valeur retournée sont des valeurs flottantes dans la plage de 0.00 à 360.00.
Note : Fournir une valeur négative retournera un message d'erreur.
a, d_sp2d_lp 'Short Path km'
Retourne 'Long Path km'.
L'argument fourni et la valeur retournée sont des valeurs flottantes.
pause 'Seconds'
Met en pause pendant le nombre entier de 'Seconds' donné avant d'envoyer la commande suivante au rotateur.

PROTOCOLE

Il existe deux protocoles utilisés par rotctld, le Protocole par Défaut et le Protocole à Réponses Étendues.

Le Protocole par Défaut est principalement destiné à la communication entre les fonctions de la bibliothèque Hamlib et rotctld ("NET rotctl", disponible en utilisant le modèle de rotateur '2').

Le Protocole à Réponses Étendues est destiné à être utilisé avec des scripts ou d'autres programmes interagissant directement avec rotctld car un retour d'information cohérent est fourni.

Protocole par Défaut

Le Protocole par Défaut est intentionnellement simple. Les commandes sont entrées sur une seule ligne avec les valeurs nécessaires. En pratique, des résultats fiables sont obtenus en terminant chaque chaîne de commande par un caractère de nouvelle ligne, '\n'.

Exemple de définition de position (code Perl) :


print $socket "P 135 10\n";

ou :


print $socket "\\set_pos 135 10\n";   # échappe le '\' initial

Une réponse sur une seule ligne sera envoyée en réponse aux commandes set, "RPRT x\n" où x est le code d'erreur Hamlib avec '0' indiquant le succès de la commande.

Les réponses des commandes get de rotctld sont des valeurs texte et correspondent aux mêmes jetons que ceux utilisés dans les commandes set. Chaque valeur est retournée sur sa propre ligne. En cas d'erreur, la chaîne "RPRT x\n" est retournée où x est le code d'erreur Hamlib.

Exemple de récupération de position (code Perl) :


print $socket "p\n";
"135"
"10"

La plupart des fonctions get retournent une à trois valeurs. Une exception notable est la commande dump_caps qui

ich retourne plusieurs lignes de paires clé:valeur.

Ce protocole est principalement utilisé par le backend « NET rotctl » (rotctl modèle 2) qui permet aux applications déjà écrites pour l'API C de Hamlib de bénéficier de rotctld sans avoir à réécrire le code de l'application. L'utilisateur d'une application peut sélectionner le modèle de rotateur 2 (« NET rotctl ») puis définir rot_pathname sur « localhost:4533 » ou un autre hôte:port réseau (défini par les options -T/-t, respectivement, ci-dessus).

Protocole de réponse étendu

Le protocole de réponse étendu ajoute plusieurs règles aux chaînes retournées par rotctld et ajoute une règle pour la syntaxe des commandes.

1. La commande reçue par rotctld est répétée avec son nom de commande long suivi de la ou des valeurs (le cas échéant) reçues du client, terminées par le séparateur de réponse spécifié, comme premier enregistrement de la réponse.

2. Le dernier enregistrement de chaque bloc est la chaîne « RPRT x\n » où x est la valeur de retour numérique de la fonction backend Hamlib qui a été appelée par la commande.

3. Tous les enregistrements constitués de valeurs de données retournées par le backend du rotateur sont précédés d'une chaîne immédiatement suivie d'un deux-points, puis d'un espace et de la valeur, terminés par le séparateur de réponse, par ex. « Azimuth: 90.000000\n » lorsque la commande était précédée de « + ».

4. Toutes les commandes reçues seront acquittées par rotctld avec les enregistrements des règles 1 et 2. Les enregistrements de la règle 3 ne sont retournés que lorsque des valeurs de données doivent être retournées au client.

Un exemple de réponse à une commande P envoyée depuis l'invite de commande shell (notez le « + » préfixé) :


$ echo "+P 90 45" | nc -w 1 localhost 4533
set_pos: 90 45
RPRT 0

Dans ce cas, le nom de commande long et les valeurs sont retournés sur la première ligne et la deuxième ligne contient le marqueur de fin de bloc et la valeur numérique de retour du backend du rotateur indiquant le succès.

Un exemple de réponse à une requête get_pos :


$ echo "+\get_pos" | nc -w 1 localhost 4533
get_pos:
Azimuth: 90.000000
Elevation: 45.000000
RPRT 0
Note : Le « \ » est toujours requis pour le nom de commande long, même avec le caractère ERP.

Dans ce cas, comme aucune valeur n'est passée à rotctld, la première ligne ne contient que le nom de commande long. La dernière ligne indique que la commande a été traitée avec succès par le backend du rotateur.

L'invocation du protocole de réponse étendu nécessite de préfixer une commande par un caractère de ponctuation. Comme montré dans les exemples ci-dessus, préfixer la commande par un « + » entraîne la séparation des réponses par un caractère de nouvelle ligne (« \n »). Tout autre caractère de ponctuation reconnu par la fonction C ispunct() à l'exception de « \ », « ? » ou « _ » fera de ce caractère le séparateur de réponse et la réponse entière sera sur une seule ligne.

Résumé des caractères séparateurs :

« + »
Chaque enregistrement de la réponse est suivi d'une nouvelle ligne (« \n »).
« ; », « | », ou « , »
Chaque enregistrement de la réponse est suivi du caractère donné, résultant en une réponse entière sur une seule ligne.
Ce sont des séparateurs d'enregistrements courants pour les représentations textuelles de données de tableur, etc.
« ? »
Réservé pour l'aide dans rotctl.
« _ »
Réservé pour la commande courte get_info
« # »
Réservé pour les commentaires lors de la lecture d'un script de fichier de commandes.
Note : D'autres caractères de ponctuation n'ont pas été testés ! Utilisez à vos propres risques.

Par exemple, l'invocation d'une requête get_pos avec un « ; » au début renvoie :


get_pos:;Azimuth: 90.000000;Elevation: 45.000000;RPRT 0

Ou, en utilisant le caractère pipe « | » renvoie :


get_pos:|Azimuth: 90.000000|Elevation: 45.000000|RPRT 0

Et une commande set_pos préfixée par un « | » renvoie :


set_pos: 135 22.5|RPRT 0

Un tel format permettra de lire une réponse comme un événement unique en utilisant un séparateur de réponse préféré. D'autres caractères de ponctuation n'ont pas été testés !

Toutes les commandes à l'exception de set_conf ont été testées avec le protocole de réponse étendu et le script Perl testrotctld.pl inclus.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à afficher sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir des informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques backend radio et peut être demandé par les développeurs.

EXEMPLES

Démarrer rotctld pour un rotateur Hy-Gain Ham IV avec la carte RotorEZ d'Idiom Press installée en utilisant un adaptateur USB vers série et en arrière-plan :


$ rotctld -m 401 -r /dev/ttyUSB1 &

Démarrer rotctld pour RotorEZ en utilisant COM2 sur Win32 :


> rotctl -m 401 -r COM2

Se connecter au rotctld déjà en cours d'exécution, et définir la position à 135,0 degrés d'azimut et 30,0 degrés d'élévation avec un temps de lecture de 1 seconde depuis l'invite de commande :


$ echo "\set_pos 135.0 30.0" | nc -w 1 localhost 4533

Se connecter à un rotctld en cours d'exécution avec rotctl sur l'hôte local :


$ rotctl -m 2

SÉCURITÉ

Aucune authentification ; NE LAISSEZ PAS ce port TCP ouvert à l'Internet. Veuillez demander si une sécurité plus forte est nécessaire ou envisager d'utiliser un tunnel SSH (ssh(1)).

Comme rotctld n'a pas besoin de plus de permissions que rotctl, il est conseillé de ne pas démarrer rotctld en tant que « root » ou un autre compte utilisateur système afin de limiter toute vulnérabilité.

BOGUES

Le démon ne se détache pas et ne se met pas en arrière-plan lui-même.

Aucune méthode pour quitter le démon, donc la commande kill(1) doit être utilisée pour le terminer.

Plusieurs clients utilisant le démon peuvent rencontrer des conflits avec le rotateur connecté.

Signalez les bogues à :
