ros-template - Modifier le modèle pour ros-init

Synopsis

•
ros template commande args...

Sous-commandes

init nom-du-modèle
Créer un nouveau modèle dans le répertoire projet-local.
deinit nom-du-modèle
Supprimer un modèle du répertoire projet-local.
list
Afficher la liste des fichiers et les états des fichiers type chmod rewrite dans les modèles.
checkout [nom-du-modèle]
Lorsqu'elle est invoquée sans nom-du-modèle, cette commande affiche les candidats pour les modèles actuels à opérer. Avec nom-du-modèle, cette commande choisit le nom comme modèle actuel.
add [nom-du-modèle] [fichiers ...]
Ajouter des fichiers au modèle actuel. Le premier paramètre peut être pris comme nom-du-modèle lorsque le modèle actuel est par défaut.
cat [nom-du-modèle] [fichiers ...]
Afficher le contenu du modèle actuel.
edit [nom-du-modèle] [fichiers ...]
Modifier le contenu des fichiers dans le modèle en utilisant /usr/bin/editor.
path [nom-du-modèle] [fichiers ...]
Afficher le chemin natif des fichiers dans le modèle.
rm [nom-du-modèle] [fichiers ...]
Supprimer un fichier du modèle actuel.
type [nom-du-modèle] [type] [fichiers ...]
Changer le type de fichier. Les choix actuels pour les types sont djula ou copy {{nom}} {{auteur}} {{email}} {{universal_time}} sont des variables disponibles dans le fichier modèle. Sans fichiers, change le type par défaut.
chmod [nom-du-modèle] [mode] [fichiers ...]
Changer les bits de mode du fichier à générer. spécifier le mode en format octal.
rewrite [nom-du-modèle] fichier règle-de-réécriture
Changer le nom du fichier en utilisant un modèle djula. Les variables {{nom}} {{auteur}} {{email}} {{universal_time}} sont disponibles pour la règle-de-réécriture.
export [nom-du-modèle] [répertoire]
Exporter les fichiers du modèle actuel dans le répertoire courant.
import [répertoire]
Importer un modèle du répertoire courant
help
Afficher l'aide de la sous-commande.

Description

La commande ros-template(1) gère les modèles de projets.

Créer un modèle

D'abord, la sous-commande init crée un modèle vide.

$ ros template init sample-template

Beaucoup de sous-commandes prennent un nom de modèle comme premier argument. Mais vous pouvez l'omettre avec la sous-commande checkout. Après ce qui suit, de telles sous-commandes seront appliquées à sample-template.

$ ros template checkout sample-template

Ensuite, la sous-commande add ajoute des fichiers locaux au modèle. Puis, la sous-commande list affiche des informations sur les fichiers du modèle.

$ echo "Hello {{ author }}!!" > sample.txt
$ ros template add sample.txt
$ ros template list
      copy  sample.txt

Le mot copy signifie une stratégie lors de l'application du modèle. Il y a les 2 stratégies suivantes.

•
copy copie simplement le fichier tel quel.
•
djula traite le contenu du fichier par le moteur de modèle, Djula (http://mmontone.github.io/djula/).
•
Les variables disponibles sont expliquées plus loin.

La sous-commande type la change. De plus, la stratégie par défaut (copy) peut être changée pour chaque modèle avec la sous-commande type sans noms de fichiers (Ex. ros template type djula).

$ ros template type djula sample.txt
$ ros template list
      djula sample.txt

sample.txt sera simplement sorti comme sample.txt par défaut. Mais vous pouvez le changer avec la sous-commande rewrite. Dans l'exemple suivant, il sera sorti comme sample_<nom du projet>.txt.

$ ros template rewrite sample.txt "sample-{{ name }}.txt"
$ ros template list
      djula sample.txt -> "sample-{{ name }}.txt"

Note : Les règles de réécriture sont toujours traitées par Djula, indépendamment de la stratégie du fichier.

Appliquer un modèle

ros-init(1) peut spécifier un modèle.

$ mkdir temp ; cd temp
$ ros init sample-template some-project
$ ls
sample-some-project.txt
$ cat sample-some-project.txt # En supposant que "author" est "alien"
Hello alien!!

Le nom du fichier et son contenu sont traités par Djula comme expliqué ci-dessus. Les variables suivantes peuvent être utilisées par défaut.

•
{{name}}: Le nom du projet spécifié dans ros-init(1)
•
{{author}}: Le nom de l'auteur extrait de la configuration Git ou de whoami
•
{{email}}: L'adresse e-mail extraite de la configuration Git ou créée en utilisant whoami et hostname
•
{{universal_time}}: L'heure universelle créée par la fonction get-universal-time

De plus, vous pouvez utiliser des variables originales comme suit.

$ echo "Hello {{ area }}!!" > sample.txt
$ ros template add sample.txt # Note : Cela écrase l'existant
$ mkdir temp ; cd temp
$ ros init sample-template roswell --area 51
$ cat sample-roswell.txt
Hello 51!!

Exporter et importer un modèle

Fondamentalement, ros-template(1) est conçu pour gérer interne les fichiers ajoutés.

Cependant, si vous souhaitez, par exemple, le gérer en utilisant Git dans un répertoire local ou installer des modèles distribués, vous pouvez utiliser les sous-commandes export et import.

D'abord, la sous-commande export exporte les fichiers ajoutés et un fichier de configuration roswell.init.<nom du modèle>.asd qui est créé et édité en interne.

$ ros template export dir
$ ls dir
roswell.init.sample-template.asd  sample.txt
$ cat dir/sample.txt
Hello {{ area }}!!

Ensuite, la sous-commande import les importe.

# Supposons que c'est une autre machine...
$ ros template list sample-template # rien n'est affiché 
$ ls downloaded
roswell.init.sample-template.asd  sample.txt
$ ros template import downloaded
$ ros template list sample-template
      djula sample.txt -> "sample-{{ name }}.txt"

Note : S'il existe un modèle portant le même nom, il sera écrasé.
