ROTCTL(1) Utilitaire Hamlib ROTCTL(1)

NOM

rotctl - contrôle les rotateurs d'antenne

SYNTAXE

rotctl [-hiIlLuV] [-m id] [-r périphérique] [-R périphérique2] [-s débit] [-t caractère] [-C param=val] [-o décalage_az] [-O décalage_el] [-v[-Z]] [commande|-]

DESCRIPTION

Contrôle les rotateurs d'antenne.

rotctl accepte des commandes depuis la ligne de commande ainsi qu'en mode interactif si aucune n'est fournie en ligne de commande.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que beaucoup de bibliothèques backend manquent de support complet des rotateurs, les fonctions de base sont généralement bien supportées.

Veuillez signaler les bugs et fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (‘-’) nécessitent un ‘=’ entre l'option et tout argument.

Voici un résumé des options supportées :

-m, --model=id
Sélectionne le numéro du modèle du rotateur.
Voir la liste des modèles (utiliser “rotctl -l”).
Note : rotctl (ou un logiciel tiers utilisant l'API C) utilisera le modèle de rotateur 2 pour NET rotctl (communication avec rotctld).
-r, --rot-file=périphérique
Utilise périphérique comme nom de fichier du port connecté au rotateur.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
-R, --rot-file2=périphérique
Utilise périphérique comme nom de fichier du port connecté au 2ème rotateur. par exemple, 2ème rotateur utilisé pour l'élévation.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les variantes BSD et Mac OS/X ont leurs propres désignations. Voir la documentation de votre système.
-s, --serial-speed=débit
Définit la vitesse série à débit bauds.
Utilise la vitesse série maximale des capacités du backend du rotateur comme valeur par défaut.
-t, --send-cmd-term=caractère
Change le caractère de terminaison pour le protocole texte lors de l'utilisation de la commande send_cmd.
La valeur par défaut est le caractère CR (‘0x0D’) ASCII. Les caractères non imprimables ASCII peuvent être donnés sous forme de leur numéro ASCII au format hexadécimal précédé de “0x”. Vous pouvez passer une chaîne vide pour aucun caractère de terminaison. La chaîne “-1” indique à rotctl de passer en protocole binaire. Voir la commande send_cmd pour plus d'explications.
Note : Le point-virgule (‘;’) est un terminateur courant pour les rotateurs qui acceptent des chaînes de caractères ASCII.
-o, --set-azoffset
Correction d'azimut en virgule flottante -- lors du réglage, la valeur est ajoutée ; lors de la lecture, la valeur est soustraite.
-O, --set-eloffset
Correction d'élévation en virgule flottante -- lors du réglage, la valeur est ajoutée ; lors de la lecture, la valeur est soustraite.
-L, --show-conf
Liste tous les paramètres de configuration du rotateur défini avec -m ci-dessus.
-C, --set-conf=param=val[,param=val]
Définit un ou plusieurs paramètres de configuration du rotateur, par exemple stop_bits=2.
Utilisez l'option -L ci-dessus pour obtenir la liste des paramètres de configuration pour un modèle donné.
-u, --dump-caps
Affiche les capacités du rotateur défini avec -m ci-dessus et quitte.
-l, --list
Liste tous les numéros de modèles de rotateurs définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être parcourue vers le haut/bas en utilisant Maj-Page haut/Maj-Page bas, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou la fenêtre cmd sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple “rotctl -l | more”.
-i, --read-history
Lit l'historique des commandes et arguments précédemment enregistré depuis un fichier (par défaut $HOME/.rotctl_history) pour la session actuelle.
Disponible lorsque rotctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note : Pour lire un fichier d'historique stocké dans un autre répertoire, définissez la variable d'environnement ROTCTL_HIST_DIR, par exemple “ROTCTL_HIST_DIR=$HOME/tmp rotctl -i”. Lorsque ROTCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-I, --save-history
Écrit l'historique des commandes et arguments de la session actuelle (et de toute session précédente, si l'option -i est également donnée) dans un fichier (par défaut $HOME/.rotctl_history) à la fin de la session actuelle.
Les commandes complètes avec leurs arguments sont enregistrées sur une seule ligne pour être rappelées et utilisées ou modifiées. Disponible lorsque rotctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note : Pour écrire un fichier d'historique dans un autre répertoire, définissez la variable d'environnement ROTCTL_HIST_DIR, par exemple “ROTCTL_HIST_DIR=$HOME/tmp rotctl -I”. Lorsque ROTCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-v, --verbose
Définit le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Z, --debug-time-stamps
Active les horodatages pour les messages de débogage.
À utiliser uniquement en combinaison avec l'option -v car elle ne génère aucune sortie seule.
-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de rotctl et quitte.
-
Arrête le traitement des options et lit les commandes depuis l'entrée standard.
Voir Entrée standard ci-dessous.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et retourneront une erreur. Cela se produira très probablement avec les options --set-conf et --show-conf.

Soyez conscient que le backend pour le rotateur à contrôler, ou le rotateur lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un code d'erreur Hamlib.

y peut être saisi en mode interactif ou fourni comme(s) argument(s) en mode ligne de commande. En mode interactif, les commandes et leurs arguments peuvent être saisis sur une seule ligne (texte saisi affiché en gras) :


P 123 45

Étant donné que la plupart des opérations Hamlib ont une méthode set et une méthode get, une lettre majuscule sera souvent utilisée pour une méthode set, tandis que la lettre minuscule correspondante fera référence à la méthode get. Chaque opération a également un nom long ; en mode interactif, préfixez une barre oblique inverse, « \ », pour entrer un nom de commande long.

Exemple : Utilisez « \get_info » en mode interactif pour afficher les informations du rotateur.

Note : Le backend du rotateur à contrôler, ou le rotateur lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un message d'erreur Hamlib.

Entrée Standard

Comme alternative à la saisie de commandes interactives READLINE ou à une seule commande pour chaque exécution, rotctl propose une option spéciale où un simple tiret (« - ») peut être utilisé pour lire les commandes depuis l'entrée standard (stdin). Les commandes doivent être séparées par des espaces blancs, comme les commandes données sur la ligne de commande. Des commentaires peuvent être ajoutés en utilisant le caractère « # », tout le texte jusqu'à la fin de la ligne courante, y compris le caractère « # », est ignoré.

Un exemple simple :


$ cat <<.EOF. >cmds.txt
> # Fichier de commandes
> set_pos 180.0 10.0	# rotation
> pause 30  # attente de la fin de l'action
> get_pos   # requête rotateur
>.EOF.
$ rotctl -m 1 - <cmds.txt
set_pos 180.0 10.0
pause 30
get_pos 180.000000
10.000000
$

Commandes Rotateur

Un résumé des commandes est inclus ci-dessous (Dans le cas des commandes set, la chaîne de caractères entre guillemets et en italique est remplacée par la valeur dans la description. Dans le cas des commandes get, la chaîne de caractères entre guillemets et en italique est le nom de la clé de la valeur retournée) :

Q|q, quitter rotctl
Quitte rotctl en mode interactif.
Lorsque rotctl contrôle directement le rotateur, il ferme le backend du rotateur et le port. Lorsque rotctl est connecté à rotctld (modèle de rotateur 2), la connexion TCP/IP à rotctld est fermée et rotctld reste en exécution, disponible pour une autre connexion réseau TCP/IP.
P, set_pos 'Azimut' 'Élévation'
Définit la position.
'Azimut' et 'Élévation' sont des valeurs flottantes.
L'azimut peut varier de -180 à 540 selon le rotateur, pour tenir compte des rotateurs orientés au sud et des capacités du rotateur.
L'élévation peut varier de -20 à 210 selon le rotateur.
Par exemple :

P 163.0 41.0

Note : Si le rotateur ne supporte pas la définition de l'élévation (la plupart ne le font pas), fournissez « 0.0 » pour 'Élévation'.
p, get_pos
Récupère la position.
'Azimut' et 'Élévation' sont retournés sous forme de valeurs flottantes de double précision.
M, move 'Direction' 'Vitesse'
Déplace le rotateur dans une direction spécifique à la vitesse donnée.
'Direction' est un entier ou un mot-clé défini comme « 2 » = HAUT, « 4 » = BAS, « 8 » = GAUCHE ou CCW, « 16 » = DROITE ou CW, « 32 » = HAUT_GAUCHE ou HAUT_CCW, « R64 » = HAUT_DROITE = HAUT_CW, « 128 » = BAS_GAUCHE ou BAS_CCW, « 256 » = BAS_DROITE ou BAS_CW
'Vitesse' est un entier compris entre 1 et 100. Utilisez -1 pour ne pas modifier la vitesse actuelle.
Note : Tous les backends qui implémentent la commande move n'utilisent pas la valeur Vitesse.
S, stop
Arrête le rotateur.
K, park
Stationne le rotateur.
C, set_conf 'Jeton' 'Valeur'
Définit un paramètre de configuration.
'Jeton' est une chaîne de caractères ; voir l'option -C et la sortie de -L.
'Valeur' est une chaîne de caractères de jusqu'à 20 caractères.
R, reset 'Réinitialisation'
Réinitialise le rotateur.
'Réinitialisation' accepte une valeur entière de « 1 » pour « Réinitialisation Complète ».
_, get_info
Récupère des informations diverses sur le rotateur.
Retourne actuellement 'Info' « Nom du modèle ».
dump_state
Retourne certaines informations d'état sur le backend du rotateur.
1, dump_caps
Ce n'est pas une vraie commande rot remote, elle affiche simplement les capacités, c'est-à-dire ce que le backend sait de ce modèle et ce qu'il peut faire.
w, send_cmd 'Cmd'
Envoie une chaîne de commande brute au rotateur.
CR ASCII (ou la valeur de --send-cmd-term, voir l'option -t) est ajouté automatiquement à la fin de la commande pour les protocoles texte. Pour les protocoles binaires, entrez les valeurs hexadécimales comme « \0xAA\0xBB ».

Commandes Localisateur

Ces commandes offrent des conversions de Degrés Minutes Secondes vers d'autres formats, des conversions de localisateur carré Maidenhead et des conversions de distance et d'azimut.

L, lonlat2loc 'Longitude' 'Latitude' 'Len Loc'
Retourne le 'Localisateur' Maidenhead pour la 'Longitude' et la 'Latitude' données.
Des valeurs flottantes sont fournies. La précision du carré retourné est contrôlée par 'Len Loc', qui doit être un entier pair compris entre 2 et 12.
Par exemple :

L -170.0 -85.0 12

retourne :

Locator: AA55AA00AA00

l, loc2lonlat 'Localisateur'
Retourne la 'Longitude' et la 'Latitude' en degrés décimaux au centre approximatif du carré de grille Maidenhead demandé.
'Localisateur' peut avoir une longueur de 2 à 12 caractères.
La longitude Ouest est exprimée sous forme de valeur négative.
La latitude Sud est exprimée sous forme de valeur négative.
Par exemple :

l AA55AA00AA00

retourne :

Longitude: -169.999983 Latitude: -84.999991

Note : Malgré l'utilisation de variables en double précision en interne, une certaine erreur d'arrondi se produit.
D, dms2dec 'Degrés' 'Minutes' 'Secondes' 'S/O'
Retourne 'Degrés Décimaux', une valeur flottante signée.
'Degrés' et 'Minutes' sont des valeurs entières.
'Secondes' est une valeur flottante.
'S/O' est un indicateur, « 1 » indiquant une latitude Sud ou une longitude Ouest, et « 0 » une latitude Nord ou une longitude Est (l'indicateur est nécessaire car les ordinateurs ne reconnaissent pas un zéro signé, même si seule la valeur 'Degrés' est typiquement signée en notation DMS).
d, dec2dms 'Degrés Décimaux'
Retourne 'Degrés' 'Minutes' 'Secondes' 'S/O'.
Les valeurs sont identiques à celles de dms2dec ci-dessus.
E, dmmm2dec 'Degrés' 'Minutes Décimales' 'S/O'
Retourne 'Degrés Décimaux', une valeur flottante signée.
'Degrés' est une valeur entière.
'Minutes Décimales' est une valeur flottante.
'S/O' est un indicateur comme dans dms2dec ci-dessus.
e, dec2dmmm 'Degrés Décimaux'
Retourne 'Degrés' 'Minutes' 'S/O'.
Les valeurs sont identiques à celles de dmmm2dec ci-dessus.
B, qrb 'Lon 1' 'Lat 1' 'Lon 2' 'Lat 2'
Retourne 'Distance' et 'Azimut'.
'Distance' est en km.
'Azimut' est en degrés.
Les valeurs de Lon/Lat fournies sont des nombres flottants signés.
A, a_sp2a_lp 'Degrés Chemin Court'
Retourne 'Degrés Chemin Long'.
L'argument fourni et la valeur retournée sont des valeurs flottantes dans la plage de 0.00 à 360.00.
Note : Fournir une valeur négative renverra un message d'erreur.
a, d_sp2d_lp 'km Chemin Court'
Retourne 'km Chemin Long'.
Les deux : argument fourni et valeur retournée sont des valeurs en virgule flottante.
pause 'Secondes'
Pause pendant le nombre entier spécifié de 'Secondes' avant d'envoyer la prochaine commande au rotateur.

READLINE

Si les fichiers de développement de la bibliothèque Readline sont trouvés lors de la configuration, rotctl sera construit conditionnellement avec le support Readline pour la saisie des commandes et des arguments. Les raccourcis clavier de la bibliothèque Readline sont ceux par défaut tels que décrits dans le manuel Readline. rotctl définit le nom « rotctl » qui peut être utilisé dans les constructions d'initialisation conditionnelle du fichier d'initialisation Readline ($HOME/.inputrc par défaut) pour des liaisons de touches personnalisées propres à rotctl.

L'historique des commandes est disponible avec le support Readline tel que décrit dans le manuel de l'historique Readline. Les chaînes de commandes et d'arguments sont stockées en une seule ligne, même lorsque les arguments sont demandés individuellement. Les commandes et les arguments ne sont pas validés et sont stockés tels qu'ils sont saisis, avec les valeurs séparées par un seul espace.

Normalement, l'historique de session n'est pas sauvegardé. Cependant, l'utilisation des options -i/--read-history ou -I/--save-history au démarrage de rotctl entraînera la lecture de tout historique précédemment sauvegardé et/ou l'écriture de l'historique de la session actuelle et de toute session précédente (en supposant que les options -i et -I soient données ensemble) à la fermeture de rotctl. Chaque option est mutuellement exclusive, c'est-à-dire qu'elles peuvent être données séparément ou en combinaison. Ceci est utile pour sauvegarder un ensemble de commandes, puis les lire plus tard, sans écrire l'historique modifié, pour un ensemble cohérent de commandes de test en mode interactif, par exemple.

L'historique est stocké dans $HOME/.rotctl_history par défaut, bien que le répertoire de destination puisse être modifié en définissant la variable d'environnement ROTCTL_HIST_DIR. Lorsque ROTCTL_HIST_DIR n'est pas défini, la valeur de la variable d'environnement HOME est utilisée à la place. Seul le répertoire de destination peut être modifié à l'heure actuelle.

Si le support Readline n'est pas trouvé lors de la configuration, le gestionnaire de commandes interne d'origine est utilisé. Readline n'est pas utilisé pour les commandes rotctl saisies sur la ligne de commande, que le support Readline soit intégré ou non.

Note : Le support Readline n'est pas inclus dans les versions binaires 32 ou 64 bits pour MS Windows fournies par le projet Hamlib. L'exécution de rotctl sous MS Windows dans le shell 'cmd' fournit un historique des commandes en ligne de session, mais il n'est pas sauvegardé sur disque entre les sessions.

DIAGNOSTICS

L'option -v, --verbose permet de choisir différents niveaux de diagnostics affichés sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de la radio, ce qui est très utile pour le développement de bibliothèques backend radio et peut être demandé par les développeurs.

STATUT DE SORTIE

rotctl se termine avec :

0
si toutes les opérations se sont déroulées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib.

EXEMPLES

Démarrer rotctl pour RotorEZ en utilisant le premier port série sous Linux :


$ rotctl -m 401 -r /dev/ttyS0

Démarrer rotctl pour RotorEZ en utilisant COM2 sous MS Windows :


> rotctl -m 401 -r COM2

Se connecter à un rotctld en cours d'exécution avec le modèle de rotateur 2 (« NET rotctl ») sur l'hôte local et spécifier le port TCP, et interroger la position :


$ rotctl -m 2 -r localhost:4533 t_pos
