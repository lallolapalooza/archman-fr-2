ROLLINIT(1) Documentation Perl fournie par l'utilisateur ROLLINIT(1)

NOM

rollinit - Crée de nouveaux enregistrements rollrec pour un fichier rollrec DNSSEC-Tools.

SYNOPSIS

rollinit [options] <nomzone1> ... <nomzoneN>

DESCRIPTION

rollinit crée de nouvelles entrées rollrec pour un fichier rollrec. Ce fichier rollrec sera utilisé par rollerd pour gérer le changement de clés pour les zones nommées.

Les entrées rollrec nouvellement générées sont écrites sur la sortie standard, sauf si l'option -out est spécifiée.

Une entrée rollrec a ce format :

roll "example.com"
    zonename        "example.com"
    zonefile        "example.com.signed"
    keyrec          "example.com.krf"
    zonegroup       "example-zones"
    kskphase        "0"
    zskphase        "0"
    administrator   "bob@bobhost.example.com"
    directory       "/var/dns/zones/example.com"
    loglevel        "phase"
    ksk_rolldate    " "
    ksk_rollsecs    "0"
    zsk_rolldate    " "
    zsk_rollsecs    "0"
    maxttl          "604800"
    display         "1"
    phasestart      "Mon Jan 9 16:00:00 2006"
    # enregistrements optionnels pour le changement RFC5011:
    istrustanchor   "no"
    holddowntime    "60D"

Les mots-clés roll et skip indiquent si rollerd doit traiter ou ignorer une entrée rollrec particulière. Les enregistrements roll sont créés par défaut ; les entrées skip sont créées si l'option -skip est spécifiée.

La ligne roll a un nom qui est utilisé pour la distinguer de toutes les autres entrées rollrec dans le fichier. Le champ zonename est défini avec le nom de la zone. Ces deux données sont souvent identiques, mais ce n'est pas obligatoire. rollinit les définira à la même valeur, sauf si l'option -rollrec est utilisée.

Les champs zonefile et keyrec sont définis en fonction des options de la ligne de commande et des arguments. La manière de générer les valeurs réelles des rollrec est un peu complexe et est décrite dans la section ZONEFILE et CHAMPS KEYREC ci-dessous.

Le champ zonegroup est utilisé pour associer un ensemble d' rollrec ensemble, de sorte qu'ils puissent être contrôlés par une seule commande rollctl -group. Plusieurs groupe de zones peuvent être spécifiés dans une liste séparée par des virgules. Les espaces en début et en fin seront supprimés, mais les espaces internes sont autorisés. Ce champ est optionnel et rollinit ne le définit que si l'option -zonegroup est spécifiée. (Bien que cela utilise le terme "zone", cela fait en réalité référence au nom des entrées rollrec.)

Le champ administrator est défini avec l'adresse e-mail de la personne (ou personne, si l'adresse est en fait une liste de diffusion) considérée comme la personne responsable de la zone.

Le champ directory est défini avec le répertoire qui contient les fichiers de la zone. Ces fichiers incluent le fichier de zone, le fichier de zone signé et le fichier keyrec.

Le champ loglevel est défini avec le niveau des messages de journal que rollerd doit produire pour cette zone. Le niveau de journal inclut les messages ayant une priorité supérieure au niveau spécifié, donc un niveau de "phase" inclura également les messages "err" et "fatal".

Les champs kskphase et zskphase indiquent la phase de changement pour les clés KSK et ZSK de la zone. La valeur 0 indique que la zone est en fonctionnement normal (pas de changement) pour ce type de clé. Une phase non nulle (1-7 pour les KSK ; 1-4 pour les ZSK) indique que la zone est en cours de changement de clés. Un seul de ces champs devrait être non nul à un moment donné. S'ils sont tous deux nuls, aucune opération de changement n'est en cours.

Les champs ksk_rolldate et ksk_rollsecs indiquent quand le changement de KSK a commencé. Si les valeurs sont un espace et zéro, respectivement, alors la zone n'est pas en cours de changement de KSK.

Les champs zsk_rolldate et zsk_rollsecs indiquent quand le changement de ZSK a commencé. Si les valeurs sont un espace et zéro, respectivement, alors la zone n'est pas en cours de changement de ZSK.

Le champ booléen display indique si blinkenlights doit afficher des informations sur cette zone.

Le champ maxttl contient la valeur TTL maximale du fichier de zone.

Les champs phasestart contiennent la date à laquelle la phase de changement actuelle a été entrée.

Les fichiers rollrec ont également le champ zsargs qui contient les options spécifiées par l'utilisateur pour zonesigner. Ce champ est défini lors de l'exécution de rollerd lorsque l'administrateur détermine que certains champs de zone doivent être modifiés. Ce n'est pas un champ rollrec initial et par conséquent il ne peut pas être spécifié par rollinit.

Le champ istrustanchor spécifie s'il faut changer les clés KSK d'une manière conforme à tout résolveur de validation distant utilisant la KSK comme point d'ancrage de confiance. S'il est défini sur "yes", alors 60 jours seront le temps d'attente minimum pendant la phase 3 du changement KSK pour s'assurer que les validateurs distants peuvent suivre correctement les étapes nécessaires, comme spécifié par le RFC5011. La durée par défaut de 60 jours peut être modifiée via le champ holddowntime.

INFO ROLLRECS

À partir de la version 1.15 de DNSSEC-Tools, chaque fichier rollrec devrait avoir un info rollrec. Cette entrée rollrec spéciale contient des informations sur le fichier rollrec lui-même et ne contient aucune information de zone. Son contenu ne doit pas être modifié par autre chose que les utilitaires DNSSEC-Tools.

ZONEFILE et CHAMPS KEYREC

Les champs zonefile et keyrec peuvent être fournis en utilisant les options -zonefile et -keyrec, ou des valeurs par défaut peuvent être utilisées.

Les valeurs par défaut utilisent le nom de la zone rollrec, tiré de la ligne de commande, comme base. .signed est ajouté au nom de la zone pour le fichier de zone ; .krf est ajouté au nom de la zone pour le fichier keyrec.

Si -zonefile ou -keyrec sont spécifiés, alors les valeurs des options sont utilisées de l'une des deux manières suivantes :

1. Un seul nom de zone est donné sur la ligne de commande.
Les valeurs des options pour -zonefile et/ou -keyrec sont utilisées pour les champs rollrec réels.
2. Plusieurs noms de zone sont donnés sur la ligne de commande.
Les valeurs des options pour -zonefile et/ou -keyrec sont utilisées comme modèles pour les champs rollrec réels. Les valeurs des options doivent contenir la chaîne =. Cette chaîne est remplacée par la zone dont le rollrec est en cours de création.

Voir la section EXEMPLES pour des exemples de la façon dont les options sont utilisées par rollinit.

OPTIONS

rollinit peut recevoir les options suivantes :

-rollrec nom-rollrec
Ceci spécifie le nom de l'enregistrement rollrec. Cette valeur peut contenir des espaces. Si cette option n'est pas spécifiée, elle sera définie à la même valeur que le champ zonename. Voir les sections ZONEFILE et CHAMPS KEYREC et EXEMPLES pour plus de détails.
-zonefile fichier-zone
Ceci spécifie la valeur du champ zonefile. Voir les sections ZONEFILE et CHAMPS KEYREC et EXEMPLES pour plus de détails.
-keyrec fichier-keyrec
Ceci spécifie la valeur du champ keyrec. Voir les sections ZONEFILE et CHAMPS KEYREC et EXEMPLES pour plus de détails.
-zg groupezone
-zonegroup groupezone
Ceci spécifie la valeur du champ zonegroup. Ce champ est optionnel.
-admin
Ceci spécifie la valeur du champ administrator. S'il n'est pas donné, un champ administrator ne sera pas inclus pour l'enregistrement.
-directory
Ceci spécifie la valeur du champ directory. S'il n'est pas donné, un champ directory ne sera pas inclus pour l'enregistrement.
-loglevel
Ceci spécifie la valeur du champ loglevel. S'il n'est pas donné, un champ loglevel ne sera pas inclus pour l'enregistrement.
-kskphase phase
Ceci spécifie la valeur du champ kskphase. S'il n'est pas donné, la valeur sera 0.
-zskphase phase
Ceci spécifie la valeur du champ zskphase. S'il n'est pas donné, la valeur sera 0.
-maxttl ttl
Ceci spécifie la valeur du champ maxttl. S'il n'est pas donné, la valeur sera 604800.
-display
Ceci spécifie la valeur du champ display. S'il n'est pas donné, la valeur sera 1.
-phasestart date
Ceci spécifie la valeur du champ phasestart. S'il n'est pas donné, la valeur sera la date et l'heure actuelles.
-istrustanchor
Ceci spécifie la valeur du champ istrustanchor. S'il n'est pas donné, la valeur sera "no".
-holddowntime duree
Ceci spécifie la valeur du champ holddowntime. S'il n'est pas donné, la valeur sera "60D".
-skip
Crée un enregistrement rollrec avec un mot-clé skip au lieu de roll.
-out fichier
Écrit la sortie dans le fichier spécifié plutôt que sur la sortie standard.
-help
Affiche un message d'aide et quitte.
-version
Affiche les informations de version et quitte.

EXEMPLES

Pour créer un enregistrement rollrec pour la zone « example.com »:

    $ rollinit example.com

Pour créer un enregistrement rollrec pour plusieurs zones:

    $ rollinit example.com blog.example.com www.example.com

Pour créer un enregistrement rollrec pour la zone « example.com » et spécifier le fichier de zone et le fichier keyrec:

    $ rollinit -zonefile "db.example.com" -keyrec "keys.example.com" example.com

Pour créer des enregistrements rollrec pour plusieurs zones, en utilisant des modèles pour les fichiers de zone et keyrec:

    $ rollinit -zonefile "=zone" -keyrec "=keys" example.com blog.example.com

Pour créer un enregistrement rollrec pour la zone « example.com » et la placer dans le groupe de zones « my-zones »:

    $ rollinit -zonegroup my-zones example.com

Pour créer un enregistrement rollrec à ignorer (skip):

    $ rollinit -skip example.com

Pour créer un enregistrement rollrec et le sauvegarder dans un fichier:

    $ rollinit -out zone.rollrec example.com

EXEMPLES

Les options suivantes devraient clarifier comment rollinit traite les options et les nouveaux rollrec. L'exemple 1 montrera l'enregistrement rollrec complet. Par souci de brièveté, les exemples restants ne montreront que les enregistrements zonefile et keyrec nouvellement créés.

Un info rollrec est montré dans le premier exemple. Par souci de place, il n'est pas inclus dans les exemples restants.

Exemple 1. Une zone, pas d'options

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, sans aucune option.

$ rollinit example.com
    skip    "info rollrec"
        version         "2"
    roll    "example.com"
        zonename        "example.com"
        zonefile        "example.com.signed"
        keyrec          "example.com.krf"
        kskphase        "0"
        zskphase        "0"
        ksk_rolldate    " "
        ksk_rollsecs    "0"
        zsk_rolldate    " "
        zsk_rollsecs    "0"
        maxttl          "0"
        display         "1"
        phasestart      "new"

Exemple 2. Une zone, option -zonefile

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec l'option -zonefile.

$ rollinit -zonefile signed-example example.com
    roll    "example.com"
        zonename        "example.com"
        zonefile        "signed-example"
        keyrec          "example.com.krf"

Exemple 3. Une zone, option -keyrec

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec l'option -keyrec.

$ rollinit -keyrec x-rrf example.com
    roll    "example.com"
        zonename        "example.com"
        zonefile        "example.com.signed"
        keyrec          "x-rrf"

Exemple 4. Une zone, options -zonefile et -keyrec

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec les options -zonefile et -keyrec.

$ rollinit -zonefile signed-example -keyrec example.rrf example.com
    roll    "example.com"
        zonename        "example.com"
        zonefile        "signed-example"
        keyrec          "example.rrf"

Exemple 5. Une zone, option -skip

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec les options -zonefile et -keyrec.

$ rollinit -skip example.com
    skip    "example.com"
        zonename        "example.com"
        zonefile        "example.com.signed"
        keyrec          "example.com.krf"

Exemple 6. Une zone, option -rollrec

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec l'option -rollrec.

$ rollinit -rollrec test example.com
    roll    "test"
        zonename        "example.com"
        zonefile        "example.com.signed"
        keyrec          "example.com.krf"

Exemple 7. Plusieurs zones, pas d'options

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, sans aucune option.

$ rollinit example1.com example2.com
    roll    "example1.com"
        zonename        "example1.com"
        zonefile        "example1.com.signed"
        keyrec          "example1.com.krf"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "example2.com.signed"
        keyrec          "example2.com.krf"

Exemple 8. Plusieurs zones, option -zonefile

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, avec l'option -zonefile.

$ rollinit -zonefile =-signed example1.com example2.com
    roll    "example1.com"
        zonename        "example1.com"
        zonefile        "example1.com-signed"
        keyrec          "example1.com.krf"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "example2.com-signed"
        keyrec          "example2.com.krf"

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, avec l'option -keyrec.

        zonename        "example1.com"
        zonefile        "example1.com.signed"
        keyrec          "zone-example1.com-keyrec"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "example2.com.signed"
        keyrec          "zone-example2.com-keyrec"

Exemple 10. Plusieurs zones, options -zonefile et -keyrec

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, avec les options -zonefile et -keyrec.

$ rollinit -zonefile Z-= -keyrec =.K example1.com example2.com
    roll    "example1.com"
        zonename        "example1.com"

        zonename        "example2.com"

Exemple 11. Une seule zone, options -zonefile et -keyrec avec template

Cet exemple montre le rollrec généré en donnant à rollinit une seule zone, avec les options -zonefile et -keyrec. Les options utilisent le template multi-zone =.

$ rollinit -zonefile Z-= -keyrec =.K example.com
    roll    "example.com"
        zonename        "example.com"
        zonefile        "Z-="
        keyrec          "=.K"

Ce n'est probablement pas ce qui est souhaité, car cela a pour résultat que les valeurs des champs zonefile et keyrec contiennent le signe =.

Exemple 12. Plusieurs zones, options -zonefile et -keyrec sans template

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, avec les options -zonefile et -keyrec. Les options n'utilisent pas le template multi-zone =.

$ rollinit -zonefile ex.zone -keyrec ex.krf example1.com example2.com
    roll    "example1.com"
        zonename        "example1.com"
        zonefile        "ex.zone"
        keyrec          "ex.krf"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "ex.zone"
        keyrec          "ex.krf"

Ce n'est peut-être pas ce qui est souhaité, car cela a pour résultat que les valeurs des champs zonefile et keyrec sont identiques pour chaque rollrec.

Exemple 13. Plusieurs zones, option -rollrec

Cet exemple montre les rollrec générés en donnant à rollinit plusieurs zones, avec l'option -rollrec. Les noms de rollrec incluent un espace.

$ rollinit -rollrec "= entry" example1.com example2.com

        zonename        "example1.com"
        zonefile        "example1.com.signed"
        keyrec          "example1.com.krf"
    roll    "example2.com entry"
        zonename        "example2.com"
        zonefile        "example2.com.signed"
        keyrec          "example2.com.krf"

rollinit(1p) — DNSSEC-Tools documentation

NAME

rollinit - Initialize a new zone record.

SYNOPSIS

rollinit [-h] [-V] [-a] [-c class] [-f format] [-g zonegroup] [-k keyrec] [-n zonename] [-o owner] [-z zonefile] [zone ...]

DESCRIPTION

rollinit is used to initialize a new zone record for use by the DNSSEC-Tools DNSSEC management software. It is primarily used to create new rollrec(5) files for the management of zones, and can optionally be used to initialize the corresponding keyrec(5) files for the zones as well.

The command will create a rollrec(5) file for each zone specified on the command line. If the -k option is given, it will create a keyrec(5) file for that zone as well.

The zones can be specified as domain names on the command line. If no zones are specified on the command line, rollinit will read zone names from standard input.

If the -a option is given, then rollinit will attempt to automatically generate the zone name from the zone file name. For example, if the zone file is named example.com.signed, then the zone name will be set to example.com.

The zonefile and keyrec names are derived from the zone name. By default, the zone file will be named zone.signed and the key record will be named zone.krf. The -z and -k options can be used to override these defaults.

By default, the zone class will be set to IN. The -c option can be used to specify a different class.

The zone group is used to group zones together for management purposes. The -g option can be used to specify a zone group. If no zone group is specified, then the zone will not be assigned to any zone group.

The -o option can be used to specify the owner of the zone. This is typically the organization or individual responsible for the zone.

INFO ROLLRECS

The rollrec(5) file contains information about a zone that is used by the DNSSEC-Tools management software. The file is a simple text file with key-value pairs. The following keys are supported:

zonename
The name of the zone.
zonefile
The name of the zone file.
keyrec
The name of the key record file.
zonegroup
The name of the zone group.
owner
The owner of the zone.
class
The class of the zone (e.g., IN, CH, HS).

ZONEFILE and KEYREC FIELDS

The zone file is a standard DNS zone file. The key record file is a text file that contains information about the keys used for the zone. The format of the key record file is as follows:

keyrec "keyname"
    zonename        "zonename"
    zonefile        "zonefile"
    keyrec          "keyrec"
    zonegroup       "zonegroup"
    owner           "owner"
    class           "class"

OPTIONS

-a
Automatically generate the zone name from the zone file name.
-c class
Set the zone class to class. Defaults to IN.
-f format
Set the output format to format. Supported formats are "text" and "xml".
-g zonegroup
Set the zone group to zonegroup.
-h
Display a help message and exit.
-k keyrec
Create a key record file named keyrec for the zone.
-n zonename
Set the zone name to zonename.
-o owner
Set the owner of the zone to owner.
-V
Display version information and exit.
-z zonefile
Set the zone file name to zonefile.

EXAMPLES

Example 14. Multiple zones, Single zonegroup

This example shows the rollrec generated by giving rollinit a single zonegroup for two zones.

$ rollinit -zg "example zones" example1.com example2.com
    roll    "example1.com"
        zonename        "example1.com"
        zonefile        "example1.com.signed"
        keyrec          "example1.com.krf"
        zonegroup       "example zones"
    roll    "example2.com"
        zonename        "example2.com"
        zonefile        "example2.com.signed"
        keyrec          "example2.com.krf"
        zonegroup       "example zones"

Example 15. One zone, Two zonegroups

This example shows the rollrec generated by giving rollinit a set of two zonegroups for a single zone.

$ rollinit -zg "customers, paid up" example.com
    roll    "example1.com"
        zonename        "example.com"
        zonefile        "example.com.signed"
        keyrec          "example.com.krf"
        zonegroup       "customers, paid up"
