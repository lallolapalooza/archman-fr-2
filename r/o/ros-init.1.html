ros-init - Crée un script roswell (éventuellement basé sur un modèle)

Synopsis

ros init [MODELE] NOM [ARGUMENTS...]]

MODELE
Spécifie le nom d'un modèle, par défaut le modèle default. Cependant, si MODELE n'est pas spécifié et que NOMFICHIER correspond à l'un des modèles stockés, alors il utilise automatiquement le modèle. Pour supprimer ce comportement, vous devriez explicitement spécifier MODELE comme default.

Ainsi, vous êtes averti lorsque vous utilisez cette commande à partir d'un script shell. Afin d'obtenir un comportement cohérent et désiré, il est conseillé de toujours spécifier explicitement le nom du modèle.

NOM
Spécifie le nom du fichier de sortie, ou “-” pour indiquer stdout. Lorsque MODELE est default, il ajoute automatiquement une extension de type de fichier “.ros”.

Description

Initialise un fichier roswell basé sur un modèle. Des modèles spécifiés par l'utilisateur peuvent être ajoutés par ros-template(1).

Le modèle par défaut ressemble à ceci :

#!/bin/sh
#|-*- mode:lisp -*-|#
#| <Mettez une description sur une ligne ici>
exec ros -Q -- $0 "$@"
|#
(progn ;;formes d'initialisation
  (ros:ensure-asdf)
  ;;#+quicklisp (ql:quickload '() :silent t)
  )
(defpackage :ros.script.test.3703600390
  (:use :cl))
(in-package :ros.script.test.3703600390)
(defun main (&rest argv)
  (declare (ignorable argv)))
;;; vim: set ft=lisp lisp:

Ceci est essentiellement un script shell qui invoque immédiatement Roswell par exec (voir sh(1)). Roswell charge le même script en entrée, saute les commentaires multilignes, lit le reste du fichier comme un programme Common Lisp, et enfin invoque une fonction main avec les arguments de la ligne de commande.
