rdfproc(1) Manuel des commandes générales rdfproc(1)

NOM

rdfproc - utilitaire de traitement RDF Redland

SYNTAXE

rdfproc [options] nom-magasin commande arg...

EXEMPLE

rdfproc test parse http://planetrdf.com/guide/rss.rdf
rdfproc test print
rdfproc test serialize ntriples

DESCRIPTION

L'utilitaire rdfproc permet l'analyse syntaxique, la requête, la manipulation et la sérialisation de contenu RDF en utilisant la bibliothèque RDF Redland. Le nom-magasin est un nom de magasin Redland, typiquement un identifiant court. Les arguments de commande varient et sont expliqués dans la section COMMANDES ci-dessous.

OPTIONS

rdfproc utilise la syntaxe habituelle des lignes de commande GNU, avec les options longues commençant par deux tirets (`-') si elles sont prises en charge par la fonction getopt_long. Sinon, seules les options courtes sont disponibles.

-h, --help
Affiche un résumé des options.
-c, --contexts
Utilise un magasin avec des contextes Redland.
-n, --new
Crée un nouveau magasin, en écrasant tout magasin existant.
-o, --output FORMAT
Définit le FORMAT de sortie pour les séquences de triplets, comme celles issues d'une recherche (commande find), vers un sérialiseur Redland. Utilisez -h ou -o help pour voir la liste complète des formats pris en charge.
-p, --password
Lit l'option de stockage 'password' depuis l'entrée standard. Terminé par un saut de ligne ('\n') ou la fin du fichier. Ceci équivaut à le définir en utilisant -t ou --storage-options mais ne nécessite pas d'exposer le mot de passe dans la liste des arguments.
-q, --quiet
Supprime les messages d'information (qui vont vers stderr)
-r, --results FORMAT
Définit le format de syntaxe des résultats de requête. Utilisez -h ou -r help pour voir la liste complète des formats de résultats de requête.
La liste exacte des formats dépend de ce avec quoi libraptor(3) a été compilé, mais elle est correctement indiquée dans le message d'utilisation avec -h.
-s, --storage TYPE
Définit le type de stockage Redland (par défaut 'hashes'). Si la variable d'environnement RDFPROC_STORAGE_TYPE est définie, le type de stockage donné ici la remplacera. Utilisez -h ou -s help pour voir la liste complète des formats de résultats de requête.
-t, --storage-options OPTIONS
Définit les options pour le stockage Redland, par défaut "hash-type='bdb',dir='.'" pour correspondre au stockage par défaut "hashes". Pour les types de stockage tels que 'mysql' qui nécessitent des options supplémentaires, ce serait typiquement quelque chose comme "host='nom_hote',database='nom_base',user='abc',password='mdp'". Si la variable d'environnement RDFPROC_STORAGE_OPTIONS est définie, les options de stockage données ici seront appliquées par la suite.
-v, --version
Affiche la version de Redland et quitte.
-V, --verbose
Affiche des messages d'information sur stderr.

COMMANDES

Là où un nœud est autorisé, comme NŒUD, SUJET, PRÉDICAT ou OBJET ci-dessous, des heuristiques simples sont utilisées pour deviner s'il s'agit d'identifiants de nœuds vides, d'URI ou de littéraux (pour ajouter une déclaration avec un littéral, utilisez add-typed). Si l'élément commence par _: alors il est supposé être un identifiant de nœud vide, sinon s'il correspond à quelque chose:// il est supposé être un URI, sinon c'est un littéral. Les littéraux ne sont autorisés que comme objets de déclarations et les nœuds vides ne sont pas autorisés comme prédicats.

add SUJET PRÉDICAT OBJET [CONॅTEXTE]
Ajoute le triplet donné au graphe, dans le contexte Redland optionnel si le nœud CONTEXTE est donné.
add-typed SUJET PRÉDICAT OBJET LANGUE-OBJET URI-OBJET [CONॅTEXTE]
Ajoute le triplet avec l'objet littéral typé à données au graphe, dans le contexte Redland optionnel si CONॅTEXTE est donné.
arc SUJET OBJET
arcs SUJET OBJET
Affiche un nœud/tous les nœuds qui correspondent aux triplets (SUJET, ?, OBJET)
arcs-in NŒUD
Affiche toutes les propriétés des triplets dont NŒUD est le sujet.
arcs-out NŒUD
Affiche toutes les propriétés des triplets dont NŒUD est l'objet.
contains SUJET PRÉDICAT OBJET
Vérifie si le triplet donné est dans le graphe.
contexts
Liste tous les contextes du graphe (si les contextes sont activés).
find SUJET|- PRÉDICAT|- OBJET|- [CONॅTEXTE]
Recherche les triplets correspondants à la déclaration donnée où - représente un blanc qui correspond à n'importe quel nœud. Si CONॅTEXTE est donné, ne recherche que les triplets dans ce nœud de contexte.
has-arc-in NŒUD ARC
Vérifie qu'il existe un triplet avec NŒUD comme sujet et ARC comme prédicat.
has-arc-out NŒUD ARC
Vérifie qu'il existe un triplet avec NŒUD comme objet et ARC comme prédicat.
parse URI|NOMFICHIER [SYNTAXE| [BASE URI]]
Analyse la syntaxe à l'URI dans le graphe en utilisant SYNTAXE qui peut être l'un des suivants : rdfxml (RDF/XML, par défaut), ntriples, turtle, rss-tag-soup (pour tous les RSS et Atom), grddl et guess pour utiliser les indices de contenu et les informations de protocole pour le déterminer. (Cette liste change plus rapidement que cette page de manuel) Si NOMFICHIER est un fichier existant, l'URI approprié sera généré pour celui-ci. Si l'analyse syntaxique renvoie des erreurs, le code de retour sera différent de 0.
parse-stream URI|NOMFICHIER [SYNTAXE [BASE URI [CONॅTEXTE]]
Analyse en flux la syntaxe à l'URI dans le graphe en utilisant SYNTAXE qui peut être l'un des suivants : rdfxml (RDF/XML, par défaut) ou ntriples. Si NOMFICHIER est un fichier existant, l'URI approprié sera généré pour celui-ci. Si l'URI optionnel du CONॅTEXTE est donné, les triplets sont ajoutés à ce contexte. Si l'analyse syntaxique renvoie des erreurs, le code de retour sera différent de 0.
print
Affiche les triplets du graphe dans un format simple montrant les nœuds de contexte si présents.
query NOM|- URI|- CHAÎNE-REQUÊTE
Exécute la requête CHAÎNE-REQUÊTE dans le langage NOM en retournant des liaisons de variables, un booléen ou un graphe RDF selon la requête. Le langage de requête peut être 'sparql' ou 'rdql'.
remove SUJET PRÉDICAT OBJET [CONॅTEXTE]
Supprime le triplet du graphe donné, dans le contexte Redland optionnel si CONॅTEXTE est donné.
remove-context CONॅTEXTE
Supprime tous les triplets du graphe associés au contexte Redland CONॅTEXTE.

NAME

rdfproc

command-line client for Redland RDF library

SYNOPSIS

rdfproc [-h|--help] [-v|--version] [-p|--pretty] [-e|--expressions] [-t|--storage-type TYPE] [-o|--storage-options OPTIONS] [-u|--uri URI] [-f|--file FILE] [-l|--listen PORT] [-c|--connect PORT] [-i|--input-syntax SYNTAX] [-a|--accept-syntax SYNTAX] [-s|--syntax SYNTAX] [-n|--name NAME] [--ntriples] [--pretty-xml] [--no-bullets] [--verbose] [--quiet] [--debug] [COMMAND]

EXAMPLE

Load a document into the default Sesame store:

 $ rdfproc -u http://example.com/doc.rdf

Print the graph in N-Triples format:

 $ rdfproc -s ntriples

Find triples with predicate http://example.com/pred and object:

 $ rdfproc sources http://example.com/pred <http://example.com/obj>

Find triples with subject and predicate:

 $ rdfproc targets <http://example.com/subj> http://example.com/pred

Load a document into a database store and serve it via HTTP:

 $ rdfproc -t "sqlite:mydb.db" -l 8080 -u http://example.com/doc.rdf

DESCRIPTION

The rdfproc command-line tool provides a way to load RDF data into a Redland RDF store, query it, and serialize it out to various RDF syntaxes.

It can operate in two main modes:

Interactive Mode:
If no file, URI or command is given, rdfproc starts an interactive interpreter that reads commands from standard input. This is useful for exploring RDF graphs.
Batch Mode:
If a file, URI or command is given on the command line, rdfproc processes the input, performs the action, and exits.

The tool supports multiple storage types (e.g., Memory, SQLite, PostgreSQL, Berkeley DB, TDB) and can read and write RDF in various syntaxes, including RDF/XML, N-Triples, Turtle, and RSS 1.0.

OPTIONS

The following options are available:

-h, --help
Show help message and exit.
-v, --version
Show version information and exit.
-p, --pretty
Use pretty-printing for output syntaxes that support it (e.g., RDF/XML, Turtle).
-e, --expressions
Parse and execute SPARQL expressions.
-t, --storage-type TYPE
Set the storage type. Can be memory, bdb, postgresql, mysql, tdb, sesame etc. Default is memory.
-o, --storage-options OPTIONS
Set storage-specific options. For example, for a database store, this could be connection details like user=... password=... host=... dbname=.... For file-based stores like bdb or tdb, this would be the path to the database directory.
-u, --uri URI
Load RDF from the given URI into the store. If multiple URIs are given, they are loaded sequentially.
-f, --file FILE
Load RDF from the given file into the store. If multiple files are given, they are loaded sequentially.
-l, --listen PORT
Listen on the specified port for incoming RDF data (e.g., via HTTP POST). Requires a storage to be specified.
-c, --connect PORT
Connect to a listener on the specified port to send RDF data.
-i, --input-syntax SYNTAX
Specify the syntax of the input data (e.g., rdfxml, ntriples, turtle). If not specified, rdfproc will try to guess the syntax from the file extension or content.
-a, --accept-syntax SYNTAX
Specify the acceptable output syntaxes for negotiation when fetching data from URIs.
-s, --syntax SYNTAX
Serialize the entire graph to the specified RDF syntax. If not specified, the default is RDF/XML.
-n, --name NAME
Set the name of the graph. Useful when working with named graphs.
--ntriples
Alias for -s ntriples.
--pretty-xml
Alias for -s rdfxml --pretty.
--verbose
Enable verbose output.
--quiet
Suppress output messages.
--debug
Enable debug output.

COMMANDS

The following commands can be used in interactive or batch mode:

clear
Clear all statements from the graph.
dump
Serialize the entire graph to standard output.
graphs
List all named graphs in the store.
load FILE | URI
Load RDF data from a file or URI into the store.
query SPARQL_QUERY
Execute a SPARQL query against the graph and print the results.
save FILE
Save the entire graph to a file.
sparql SPARQL_QUERY
Alias for query.
syntax [SYNTAX [URI [MIME-TYPE]]]]
Serializes the graph to a syntax with a particular ISYNTAX URI or Internet Media Type/MIME Type. The default is RDF/XML (NAME "rdfxml", MIME Type "application/rdf/xml") if none of the above are given. Other alternatives are "ntriples" (no MIME Type).
source PREDICATE OBJECT
sources PREDICATE OBJECT
Show one node/all nodes that match triples (?, PREDICATE, OBJECT)
target SUBJECT PREDICATE
targets SUBJECT PREDICATE
Show one node/all nodes that match triples (SUBJECT, PREDICATE, ?)

ENVIRONMENT

RDFPROC_STORAGE_OPTIONS can be set to provide storage options instead of using the option -t, --storage-options OPTIONS. When both are given, command options are applied last.

RDFPROC_STORAGE_TYPE can be set to provide a storage type instead of using the option -s, --storage TYPE. When both are given, the storage type from the command is used.

CONFORMING TO

RDF/XML Syntax (Revised), W3C Recommendation, http://www.w3.org/TR/rdf-syntax-grammar/

N-Triples, in RDF Test Cases, Jan Grant and Dave Beckett (eds.) W3C Recommendation, http://www.w3.org/TR/rdf-testcases/#ntriples

SEE ALSO

redland(3), libraptor(3), rapper(1)

NOM

rdfproc

client en ligne de commande pour la bibliothèque RDF Redland

SYNTAXE

rdfproc [-h|--help] [-v|--version] [-p|--pretty] [-e|--expressions] [-t|--storage-type TYPE] [-o|--storage-options OPTIONS] [-u|--uri URI] [-f|--file FILE] [-l|--listen PORT] [-c|--connect PORT] [-i|--input-syntax SYNTAX] [-a|--accept-syntax SYNTAX] [-s|--syntax SYNTAX] [-n|--name NAME] [--ntriples] [--pretty-xml] [--no-bullets] [--verbose] [--quiet] [--debug] [COMMANDE]

EXEMPLE

Charger un document dans le magasin Sesame par défaut :

 $ rdfproc -u http://example.com/doc.rdf

Afficher le graphe au format N-Triples :

 $ rdfproc -s ntriples

Trouver les triplets avec le prédicat http://example.com/pred et l'objet :

 $ rdfproc sources http://example.com/pred <http://example.com/obj>

Trouver les triplets avec le sujet et le prédicat :

 $ rdfproc targets <http://example.com/subj> http://example.com/pred

Charger un document dans un magasin de base de données et le servir via HTTP :

 $ rdfproc -t "sqlite:mydb.db" -l 8080 -u http://example.com/doc.rdf

DESCRIPTION

L'outil en ligne de commande rdfproc fournit un moyen de charger des données RDF dans un magasin RDF Redland, de les interroger et de les sérialiser dans divers formats RDF.

Il peut fonctionner dans deux modes principaux :

Mode Interactif :
Si aucun fichier, URI ou commande n'est donné, rdfproc démarre un interpréteur interactif qui lit les commandes depuis l'entrée standard. Ceci est utile pour explorer les graphes RDF.
Mode Batch :
Si un fichier, un URI ou une commande est donné sur la ligne de commande, rdfproc traite l'entrée, effectue l'action et se termine.

L'outil prend en charge plusieurs types de stockage (par exemple, Mémoire, SQLite, PostgreSQL, Berkeley DB, TDB) et peut lire et écrire du RDF dans divers formats, y compris RDF/XML, N-Triples, Turtle et RSS 1.0.

OPTIONS

Les options suivantes sont disponibles :

-h, --help
Afficher le message d'aide et quitter.
-v, --version
Afficher les informations de version et quitter.
-p, --pretty
Utiliser l'indentation pour les formats de sortie qui le prennent en charge (par exemple, RDF/XML, Turtle).
-e, --expressions
Analyser et exécuter des expressions SPARQL.
-t, --storage-type TYPE
Définir le type de stockage. Peut être memory, bdb, postgresql, mysql, tdb, sesame etc. La valeur par défaut est memory.
-o, --storage-options OPTIONS
Définir des options spécifiques au stockage. Par exemple, pour un magasin de base de données, cela pourrait être des détails de connexion tels que user=... password=... host=... dbname=.... Pour les magasins basés sur des fichiers comme bdb ou tdb, ce serait le chemin vers le répertoire de la base de données.
-u, --uri URI
Charger le RDF de l'URI donné dans le magasin. Si plusieurs URIs sont donnés, ils sont chargés séquentiellement.
-f, --file FILE
Charger le RDF du fichier donné dans le magasin. Si plusieurs fichiers sont donnés, ils sont chargés séquentiellement.
-l, --listen PORT
Écouter sur le port spécifié pour les données RDF entrantes (par exemple, via HTTP POST). Nécessite qu'un magasin soit spécifié.
-c, --connect PORT
Se connecter à un écouteur sur le port spécifié pour envoyer des données RDF.
-i, --input-syntax SYNTAX
Spécifier la syntaxe des données d'entrée (par exemple, rdfxml, ntriples, turtle). Si non spécifié, rdfproc essaiera de deviner la syntaxe à partir de l'extension du fichier ou du contenu.
-a, --accept-syntax SYNTAX
Spécifier les formats de sortie acceptables pour la négociation lors de la récupération de données depuis des URIs.
-s, --syntax SYNTAX
Sérialiser l'intégralité du graphe dans la syntaxe RDF spécifiée. Si non spécifié, la valeur par défaut est RDF/XML.
-n, --name NAME
Définir le nom du graphe. Utile lors du travail avec des graphes nommés.
--ntriples
Alias pour -s ntriples.
--pretty-xml
Alias pour -s rdfxml --pretty.
--verbose
Activer la sortie détaillée.
--quiet
Supprimer les messages de sortie.
--debug
Activer la sortie de débogage.

COMMANDES

Les commandes suivantes peuvent être utilisées en mode interactif ou batch :

clear
Supprimer toutes les instructions du graphe.
dump
Sérialiser l'intégralité du graphe vers la sortie standard.
graphs
Lister tous les graphes nommés dans le magasin.
load FICHIER | URI
Charger les données RDF d'un fichier ou d'un URI dans le magasin.
query SPARQL_QUERY
Exécuter une requête SPARQL sur le graphe et afficher les résultats.
save FICHIER
Sauvegarder l'intégralité du graphe dans un fichier.
sparql SPARQL_QUERY
Alias pour query.
syntax [SYNTAX [URI [MIME-TYPE]]]]
Sérialise le graphe vers une syntaxe avec un URI ISYNTAX particulier ou un Type Média Internet/Type MIME. Par défaut, il s'agit de RDF/XML (NOM "rdfxml", Type MIME "application/rdf/xml") si aucun des éléments ci-dessus n'est donné. D'autres alternatives sont "ntriples" (pas de Type MIME).
source PREDICAT OBJET
sources PREDICAT OBJET
Afficher un nœud/tous les nœuds qui correspondent aux triplets (?, PREDICAT, OBJET)
target SUJET PREDICAT
targets SUJET PREDICAT
Afficher un nœud/tous les nœuds qui correspondent aux triplets (SUJET, PREDICAT, ?)

ENVIRONNEMENT

RDFPROC_STORAGE_OPTIONS peut être défini pour fournir des options de stockage au lieu d'utiliser l'option -t, --storage-options OPTIONS. Lorsque les deux sont donnés, les options de la ligne de commande sont appliquées en dernier.

RDFPROC_STORAGE_TYPE peut être défini pour fournir un type de stockage au lieu d'utiliser l'option -s, --storage TYPE. Lorsque les deux sont donnés, le type de stockage de la ligne de commande est utilisé.
