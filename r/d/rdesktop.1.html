rdesktop(1) Manuel des commandes générales rdesktop(1)

NOM

rdesktop - client du protocole de bureau à distance

SYNTAXE

rdesktop [options] serveur[:port]

DESCRIPTION

rdesktop est un client pour le protocole de bureau à distance (RDP), utilisé dans un certain nombre de produits Microsoft. Il est connu pour fonctionner avec les versions serveur de Microsoft Windows allant de NT 4 terminal server à Windows Server 2012 R2.

OPTIONS

-u <nomutilisateur>
Nom d'utilisateur pour l'authentification sur le serveur.
-d <domaine>
Domaine pour l'authentification.
-s <shell>
Shell de démarrage pour l'utilisateur - lance une application spécifique au lieu d'Explorer. Si SeamlessRDP est activé, il s'agit de l'application qui est lancée en mode transparent.
-c <répertoire>
Le répertoire de travail initial pour l'utilisateur. Souvent utilisé en combinaison avec -s pour configurer un environnement de connexion fixe.
-p <motdepasse>
Le mot de passe pour s'authentifier. Notez que cela peut ne pas avoir d'effet si "Demander toujours le mot de passe" est activé sur le serveur. ATTENTION : si vous spécifiez un mot de passe dans la ligne de commande, il peut être visible par d'autres utilisateurs lorsqu'ils utilisent des outils comme ps. Utilisez -p - pour que rdesktop demande un mot de passe au démarrage (depuis l'entrée standard).
-n <nommachine>
Nom d'hôte du client. Normalement, rdesktop obtient automatiquement le nom d'hôte du client.
-k <mappeklavier>
Disposition du clavier à émuler. Cela nécessite qu'un fichier de mappage de touches correspondant soit installé. Les mappages de clavier standard fournis avec rdesktop suivent la convention de nommage RFC1766 : un code de langue suivi d'un code de pays si nécessaire - par exemple, en-us, en-gb, de, fr, sv, etc.

Le mappage de clavier par défaut dépend de la locale actuelle (variables d'environnement LC_* et LANG). Si la locale actuelle est inconnue, le mappage de clavier par défaut est en-us (un clavier anglais américain).

Les mappages de clavier sont des noms de fichiers, ce qui signifie qu'ils sont sensibles à la casse. Les mappages de clavier standard sont tous en minuscules.

Les mappages de clavier sont recherchés par rapport aux répertoires $HOME/.rdesktop/keymaps, KEYMAP_PATH (spécifié lors de la compilation) et $CWD/keymaps, dans cet ordre. L'argument keyboard-map peut également être un nom de fichier absolu.

La valeur spéciale `none' peut être utilisée à la place d'un mappage de clavier. Dans ce cas, rdesktop devinera les codes de scan à partir des codes de touches de l'événement X11 en utilisant une méthode de mappage interne. Cette méthode ne prend en charge que les touches alphanumériques de base et peut ne pas fonctionner correctement sur toutes les plateformes, son utilisation est donc déconseillée.

-g <géométrie>
Géométrie du bureau (LxH[@DPI][+X[+Y]]). Si la géométrie est le mot spécial "workarea", la géométrie sera récupérée de la propriété d'indice du gestionnaire de fenêtres étendu _NET_WORKAREA, de la fenêtre racine. La géométrie peut également être spécifiée en pourcentage de l'écran entier, par exemple, "-g 80%", "-g 80%x70%".

Si la géométrie spécifiée dépend de la taille de l'écran et que la taille de l'écran est modifiée, rdesktop se reconnectera automatiquement en utilisant la nouvelle taille d'écran. Cela nécessite que rdesktop ait été compilé avec le support de RandR.

Le paramètre DPI optionnel doit être spécifié si l'écran sur lequel rdesktop est affiché est trop éloigné de 96 DPI pour que les fenêtres non mises à l'échelle soient lisibles. Windows accepte actuellement des valeurs allant de 96 à 480.

Le placement décalé de la fenêtre est facultatif. Le point de départ est le coin supérieur gauche de l'écran. Le gestionnaire de fenêtres peut pousser dans la zone visible, si un panneau est couvert. Le schéma est "-g <valeur>+<décalageX>+<décalageY>", par exemple, "-g 30%+200+600".

-i
Utiliser le mot de passe comme code PIN de carte à puce. Si un certificat d'utilisateur valide est trouvé dans le lecteur de carte à puce, le mot de passe passé avec l'argument p est utilisé comme code PIN pour la carte à puce. Cette fonctionnalité nécessite également que la redirection de carte à puce soit utilisée via l'argument r scard.
-f
Activer le mode plein écran. Cela surcharge le gestionnaire de fenêtres et fait que la fenêtre rdesktop couvre entièrement l'écran actuel. Le mode plein écran peut être activé ou désactivé à tout moment en utilisant Ctrl-Alt-Entrée.
-b
Forcer le serveur à envoyer les mises à jour de l'écran sous forme de bitmaps plutôt que d'utiliser des opérations de dessin de plus haut niveau.
-t
Désactiver l'utilisation du contrôle à distance. Cela désactivera des fonctionnalités comme le partage de connexion transparent.
-A <seamlessrdpshell>
Activer SeamlessRDP en spécifiant le chemin d'accès au shell RDP transparent. Dans ce mode, rdesktop crée une fenêtre X11 pour chaque fenêtre côté serveur. Ce mode nécessite le composant côté serveur SeamlessRDP, disponible sur http://www.cendio.com/seamlessrdp/.

Lorsque vous utilisez cette option, vous devriez normalement spécifier un shell de démarrage qui lance l'application souhaitée via SeamlessRDP.

Exemple : rdesktop -A 'c:\seamlessrdp\seamlessrdpshell.exe' -s 'notepad' monwts.domaine.com

Toute invocation ultérieure de la ligne de commande ci-dessus utilisera la fonctionnalité de partage de connexion transparente qui lance un autre bloc-notes dans la connexion actuelle au serveur spécifié, puis se termine.

-V <versiontls>
Définir la version du Transport Level Security (également connu sous le nom de SSL) utilisée. Doit être l'une des valeurs suivantes : 1.0, 1.1, 1.2. Par défaut, toutes les versions sont prises en charge.
-B
Utiliser le BackingStore du Xserver au lieu de celui intégré dans rdesktop.
-e
Désactiver le chiffrement. Cette option n'est nécessaire (et ne fonctionnera) que si vous avez une version française de NT TSE.
-E
Désactiver le chiffrement du client vers le serveur. Cela envoie un paquet de connexion chiffré, mais tout ce qui suit est non chiffré (y compris les connexions interactives).
-m
Ne pas envoyer les événements de mouvement de souris. Cela économise de la bande passante, bien que certaines applications Windows puissent dépendre de la réception du mouvement de la souris.
-M
Utiliser le curseur X local hérité du gestionnaire de fenêtres au lieu du curseur serveur. Ceci est principalement utile avec -m, mais est également utile si le serveur envoie des curseurs de souris invalides.
-C
Utiliser une colormap privée. Cela améliorera la précision des couleurs sur un écran 8 bits, mais rdesktop apparaîtra en fausses couleurs lorsqu'il n'est pas focalisé.
-D
Masquer les décorations du gestionnaire de fenêtres, en utilisant les indices MWM.
-K
Ne pas remplacer les raccourcis clavier du gestionnaire de fenêtres. Par défaut, rdesktop tente de capturer toute l'entrée clavier lorsqu'il est focalisé.
-S <taillebouton>
Activer le mode application unique. Cette option peut être utilisée lors de l'exécution d'une application unique et maximisée (via -s). Lorsque le bouton de minimisation de l'application Windows est pressé, la fenêtre rdesktop est minimisée au lieu de l'application distante. Le bouton maximiser/restaurer est désactivé. Pour que cela fonctionne, vous devez spécifier la taille correcte du bouton, en pixels. Le mot spécial "standard" signifie 18 pixels.
-T <titre>
Définit le titre de la fenêtre. Le titre doit être spécifié à l'aide d'une chaîne UTF-8.
-N
Activer la synchronisation du verrouillage numérique entre le Xserver et la session RDP distante. Ceci est utile avec les applications qui vérifient l'état du verrouillage numérique, mais peut causer des problèmes avec certains Xservers comme Xvnc.
-X <idfenetre>
Intégrer la fenêtre rdesktop dans une autre fenêtre. L'idfenetre est attendu en décimal ou hexadécimal (précédé de 0x).
-a <bpp>
/a>
Définit la profondeur de couleur pour la connexion (8, 15, 16, 24 ou 32). Plus de 8 bpp ne sont pris en charge que lors de la connexion à Windows XP (jusqu'à 16 bpp) ou plus récent. Notez que la profondeur de couleur peut également être limitée par la configuration du serveur. La valeur par défaut est la profondeur de la fenêtre racine.
-z
Active la compression du flux de données RDP.
-x <experience>
Modifie le comportement par défaut des performances de bande passante pour RDP5. Par défaut, seul le thème est activé et toutes les autres options sont désactivées (correspondant au modem (56 Kbps)). Définir experience sur b[roadband] active les animations de menu et le glisser-déposer de fenêtre complète. Définir experience sur l[an] activera également le papier peint du bureau. Définir experience sur m[odem] désactive tout (y compris les thèmes). L'expérience peut également être un nombre hexadécimal contenant les indicateurs.
-P
Active la mise en cache des bitmaps sur le disque (mise en cache persistante des bitmaps). Ceci améliore généralement les performances (en particulier sur les connexions à faible bande passante) et réduit le trafic réseau au prix d'un démarrage légèrement plus long et d'une utilisation de l'espace disque. (10 Mo pour les couleurs 8 bits, 20 Mo pour les couleurs 15/16 bits, 30 Mo pour les couleurs 24 bits et 40 Mo pour les sessions 32 bits)
-r <périphérique>
Active la redirection du périphérique spécifié sur le client, de sorte qu'il apparaisse sur le serveur. Notez que les redirections autorisées peuvent être restreintes par la configuration du serveur.

Les périphériques suivants sont actuellement pris en charge :

-r comport:<portcom>=<périphérique>,...
Redirige les périphériques série de votre client vers le serveur. Notez que si vous devez modifier les paramètres du ou des périphériques série, faites-le avec un outil approprié avant de démarrer rdesktop. Dans la plupart des systèmes d'exploitation, vous utiliseriez stty. Le support bidirectionnel/lecture nécessite Windows XP ou plus récent. Dans Windows 2000, cela créera un port, mais ce ne sera pas transparent, la plupart des programmes shell ne fonctionneront pas avec.
-r disk:<nompartage>=<chemin>,...
Redirige un chemin vers le partage \\tsclient\<nompartage> sur le serveur (nécessite Windows XP ou plus récent). Le nom du partage est limité à 8 caractères.
-r lptport:<portlpt>=<périphérique>,...
Redirige les périphériques parallèles de votre client vers le serveur. Le support bidirectionnel/lecture nécessite Windows XP ou plus récent. Dans Windows 2000, cela créera un port, mais ce ne sera pas transparent, la plupart des programmes shell ne fonctionneront pas avec.
-r printer:<nomimprimante>[=<pilote>],...
Redirige une file d'attente d'impression sur le client vers le serveur. Le <nomimprimante> est le nom de la file d'attente dans votre système local. <pilote> est par défaut un pilote PS simple, sauf si vous en spécifiez un. Gardez à l'esprit que vous avez besoin d'une correspondance à 100% dans l'environnement serveur, sinon le pilote échouera. La première imprimante sur la ligne de commande sera définie comme votre imprimante par défaut.
-r sound:[local|off|remote]
Redirige le son généré sur le serveur vers le client. "remote" n'a d'effet que lorsque vous vous connectez à la console avec l'option -0. (Nécessite Windows XP ou plus récent).
-r lspci
Active le canal lspci, qui permet au serveur d'énumérer les périphériques PCI du client. Consultez le fichier lspci-channel.txt dans la documentation pour plus d'informations.
-r scard[:<NomCarteSC>=<NomAlias>[;<NomVendeur>][,...]]
Active la redirection d'une ou plusieurs cartes à puce. Vous pouvez fournir une liaison de nom statique entre GNU/Linux et Windows. Pour ce faire, vous pouvez utiliser des paramètres optionnels comme décrit : <NomCarteSC> - nom de l'appareil dans l'environnement GNU/Linux et UNIX, <NomAlias> - nom de l'appareil affiché dans l'environnement Windows <NomVendeur> - nom optionnel du vendeur de l'appareil. Pour une liste d'exemples, exécutez rdesktop sans paramètres.
-r clipboard:[off|PRIMARYCLIPBOARD|CLIPBOARD]
Active la redirection du presse-papiers. 'PRIMARYCLIPBOARD' examine à la fois PRIMARY et CLIPBOARD lors de l'envoi de données au serveur. 'CLIPBOARD' examine uniquement 'CLIPBOARD'.
-0
Se connecte à la console du serveur (nécessite Windows Server 2003 ou plus récent).
-4
Utilise la version RDP 4.
-5
Utilise la version RDP 5 (par défaut).
-v
Active la sortie verbeuse.

Options CredSSP et carte à puce

--sc-csp-name <nom>
Spécifie le CSP (Fournisseur de services de chiffrement) à utiliser côté Windows pour l'authentification par carte à puce. Le CSP est le pilote de votre carte à puce et il semble qu'il doive être spécifié pour l'authentification CredSSP. Pour NetID suédois, le nom CSP suivant est utilisé : "Net iD - CSP".
--sc-container-name <nom>
Spécifie le nom du conteneur, généralement c'est le nom d'utilisateur pour le conteneur par défaut et il semble qu'il doive être spécifié pour l'authentification CredSSP.
--sc-reader-name <nom>
Spécifie le nom du lecteur à utiliser pour éviter que le code PIN ne soit envoyé à la mauvaise carte s'il y a plusieurs lecteurs.
--sc-card-name <nom>
Spécifie le nom de la carte, par exemple : "Telia EID IP5a".
