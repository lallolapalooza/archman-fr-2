RDMA_GETADDRINFO(3) Manuel du programmeur Librdmacm RDMA_GETADDRINFO(3)

NOM

rdma_getaddrinfo - Fournit une traduction d'adresse indépendante du transport.

SYNTAXE

#include <rdma/rdma_cma.h>

int rdma_getaddrinfo (const char *node, const char *service, const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);

ARGUMENTS

node
Optionnel, nom, adresse IPv4 décimale-pointée ou adresse hexadécimale IPv6 à résoudre.
service
Nom de service ou numéro de port de l'adresse.
hints
Référence à une structure rdma_addrinfo contenant des indices sur le type de service supporté par l'appelant.
res
Un pointeur vers une liste chaînée de structures rdma_addrinfo contenant les informations de réponse.

DESCRIPTION

Résout l'adresse du nœud de destination et du service et retourne les informations nécessaires pour établir la communication. Fournit l'équivalent fonctionnel RDMA de getaddrinfo.

VALEUR DE RETOUR

Retourne 0 en cas de succès, ou -1 en cas d'erreur (errno sera défini pour indiquer la raison de l'échec), ou l'un des codes d'erreur non nuls suivants :

EAI_ADDRFAMILY
L'hôte réseau spécifié n'a aucune adresse réseau dans la famille d'adresses demandée.
EAI_AGAIN
Le serveur de noms a retourné une indication d'échec temporaire. Réessayez plus tard.
EAI_BADFLAGS
hints.ai_flags contient des drapeaux invalides.
EAI_FAIL
Le serveur de noms a retourné une indication d'échec permanent.
EAI_FAMILY
La famille d'adresses demandée n'est pas supportée.
EAI_MEMORY
Manque de mémoire.
EAI_NODATA
L'hôte réseau spécifié existe, mais n'a aucune adresse réseau définie.
EAI_NONAME
Le nœud ou le service n'est pas connu ; ou node et service sont tous deux NULL.
EAI_SERVICE
Le service demandé n'est pas disponible pour le type de QP demandé. Il peut être disponible via un autre type de QP.
EAI_QPTYPE
Le type de socket demandé n'est pas supporté. Cela pourrait se produire, par exemple, si hints.ai_qptype et hints.ai_port_space sont incohérents (par exemple, IBV_QPT_UD et RDMA_PS_TCP, respectivement).
EAI_SYSTEM
Autre erreur système, vérifiez errno pour les détails. La fonction gai_strerror() traduit ces codes d'erreur en une chaîne lisible par l'homme, adaptée à la déclaration d'erreurs.

NOTES

Soit node, soit service, soit hints doit être fourni. Si hints est fourni, l'opération sera contrôlée par hints.ai_flags. Si RAI_PASSIVE est spécifié, l'appel résoudra les informations d'adresse à utiliser du côté passif d'une connexion. Si node est fourni, rdma_getaddrinfo tentera de résoudre l'adresse RDMA, la route et les données de connexion du nœud donné. Le paramètre hints, s'il est fourni, peut être utilisé pour contrôler la sortie résultante comme indiqué ci-dessous. Si node n'est pas donné, rdma_getaddrinfo tentera de résoudre les informations d'adressage RDMA en se basant sur hints.ai_src_addr, hints.ai_dst_addr ou hints.ai_route.

rdma_addrinfo

ai_flags
Drapeaux d'indice qui contrôlent l'opération. Les drapeaux supportés sont :
RAI_PASSIVE
Indique que les résultats seront utilisés du côté passif/d'écoute d'une connexion.
RAI_NUMERICHOST
Si spécifié, alors le paramètre node, s'il est fourni, doit être une adresse numérique du réseau. Ce drapeau supprime toute résolution d'adresse longue.
RAI_NOROUTE
Si défini, ce drapeau supprime toute résolution de route longue.
RAI_FAMILY
Si défini, le réglage ai_family doit être utilisé comme indice d'entrée pour interpréter le paramètre node.
RAI_DNS
Indique que la résolution d'adresse doit utiliser DNS pour mapper les noms de nœud et de service aux adresses. Le drapeau est mutuellement exclusif avec RAI_SA. La résolution DNS est l'option par défaut.
RAI_SA
Indique que la résolution d'adresse doit interroger le SA Infiniband pour mapper les noms de nœud et de service aux adresses. Le drapeau est mutuellement exclusif avec RAI_DNS. La résolution SA ne s'applique qu'aux ports Infiniband. Les ports non-Infiniband seront ignorés.
ai_family
Famille d'adresses pour l'adresse source et destination. Les familles supportées sont : AF_INET, AF_INET6 et AF_IB.
ai_qp_type
Indique le type de QP RDMA utilisé pour la communication. Les types supportés sont : IBV_QPT_UD (datagramme non fiable) et IBV_QPT_RC (connecté fiable).
ai_port_space
Espace de port RDMA en cours d'utilisation. Les valeurs supportées sont : RDMA_PS_UDP, RDMA_PS_TCP et RDMA_PS_IB.
ai_src_len
La longueur de l'adresse source référencée par ai_src_addr. Ce sera 0 si une adresse source appropriée n'a pas pu être découverte pour une destination donnée.
ai_dst_len
La longueur de l'adresse destination référencée par ai_dst_addr. Ce sera 0 si le drapeau RAI_PASSIVE a été spécifié dans le cadre des hints.
ai_src_addr
Si fourni, l'adresse du périphérique RDMA local.
ai_dst_addr
Si fourni, l'adresse du périphérique RDMA destination.
ai_src_canonname
Le nom canonique pour la source.
ai_dst_canonname
Le nom canonique pour la destination.
ai_route_len
Taille du tampon d'informations de routage référencé par ai_route. Ce sera 0 si le transport sous-jacent ne nécessite pas de données de routage, ou si aucune n'a pu être résolue.
ai_route
Informations de routage pour les transports RDMA qui nécessitent des données de routage dans le cadre de l'établissement de la connexion. Le format des données de routage dépend du transport sous-jacent. Si des transports Infiniband sont utilisés, ai_route pointera vers un tableau de struct ibv_path_data en sortie, si des données de routage sont disponibles. Les chemins de routage peuvent être restreints en définissant les champs de données de routage souhaités en entrée de rdma_getaddrinfo. Pour Infiniband, hints.ai_route peut pointer vers un tableau de struct ibv_path_record ou struct ibv_path_data en entrée.
ai_connect_len
Taille des informations de connexion référencées par ai_connect. Ce sera 0 si le transport sous-jacent ne nécessite pas d'informations de connexion supplémentaires.
ai_connect
Données échangées dans le cadre du processus d'établissement de la connexion. Si fourni, les données ai_connect doivent être transférées en tant que données privées, avec toutes les données privées fournies par l'utilisateur qui les suivent.
ai_next
Pointeur vers la structure rdma_addrinfo suivante dans la liste. Sera NULL si

rdma_getaddrinfo(3)

NAME

rdma_getaddrinfo, rdma_freeaddrinfo, rdma_resolve_addrinfo, rdma_query_addrinfo - retrieve RDMA address information

SYNOPSIS

#include <rdma/rdma_verbs.h>
int rdma_getaddrinfo(const char *nodename, const char *servname,
    const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);
void rdma_freeaddrinfo(struct rdma_addrinfo *res);
int rdma_resolve_addrinfo(const char *nodename, const char *servname,
    const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);
int rdma_query_addrinfo(const char *nodename, const char *servname,
    const struct rdma_addrinfo *hints, struct rdma_addrinfo **res);

ARGUMENTS

nodename
A NULL terminated character string that specifies a network host name, or a string representation of an IP address. If NULL, then Internet addresses in the network address list that correspond to the specified service are returned.
servname
A NULL terminated character string that specifies a port number, or a service name. If NULL, then any address for the specified host name is returned.
hints
A pointer to a struct rdma_addrinfo that specifies criteria for selecting the returned address information. If NULL, then any address for the specified host name is returned.
res
A pointer to a pointer to a struct rdma_addrinfo that will be filled with the return address information. The caller is responsible for freeing this memory using rdma_freeaddrinfo.

DESCRIPTION

rdma_getaddrinfo, rdma_resolve_addrinfo and rdma_query_addrinfo are functions that retrieve address information for a specified host name and service name. The functions are similar to getaddrinfo(3) but are RDMA specific.

The struct rdma_addrinfo structure contains the following fields:

ai_flags
This parameter can be used to request additional options. The supported flags are:
RDMA_CLIENT_REQ_MATCH
This flag is used by the client to request that the server address it is looking for be matched by any available server address.
RDMA_CLIENT_REQ_PEER
This flag is used by the client to request that the server address it is looking for be matched by the specified peer address. The peer address is specified in the ai_src_addr field of the hints parameter.
RDMA_ITERATOR_NEXT
This flag is used to iterate through multiple possible address matches. The rdma_getaddrinfo function will return the first matching address. To retrieve the next matching address, the caller should set ai_flags to RDMA_ITERATOR_NEXT and call rdma_getaddrinfo again with the same parameters. The res parameter should point to the previously returned struct rdma_addrinfo.
RDMA_QUERY_PORT_SUPPORT
This flag is used to query for RDMA port support. The ai_port_space field of the hints parameter must be set to the desired port space.
ai_port_space
This parameter specifies the desired port space. The supported port spaces are:
RDMA_PS_UDP
UDP port space.
RDMA_PS_TCP
TCP port space.
RDMA_PS_IB
InfiniBand port space.
RDMA_PS_RNIC
RNIC port space.
ai_src_addr
This parameter specifies the source address to be used for the connection. If not NULL, then the source address is used to determine the RDMA device and port to be used for the connection.
ai_dst_addr
This parameter specifies the destination address to be used for the connection. If not NULL, then the destination address is used to determine the RDMA device and port to be used for the connection.
ai_verbs
This parameter specifies the struct ibv_context to be used for the connection. If not NULL, then the specified context is used to determine the RDMA device and port to be used for the connection.
ai_pd
This parameter specifies the struct ibv_pd to be used for the connection. If not NULL, then the specified protection domain is used to determine the RDMA device and port to be used for the connection.
ai_qp_type
This parameter specifies the desired queue pair type. The supported queue pair types are:
IBV_QPT_SMI
Send/Manage/indicate queue pair.
IBV_QPT_RC
Reliable Connected queue pair.
IBV_QPT_UC
Unreliable Connected queue pair.
IBV_QPT_UD
Unreliable Datagram queue pair.
ai_port_number
This parameter specifies the RDMA port number to be used for the connection.
ai_pkey_index
This parameter specifies the Partition Key (PKey) index to be used for the connection.

rdma_getaddrinfo is used to retrieve address information for a specified host name and service name. The function attempts to resolve the host name and service name to an RDMA address. If successful, the function returns a pointer to a linked list of struct rdma_addrinfo structures, each representing a possible connection endpoint. The caller is responsible for freeing the memory allocated for the returned structures using rdma_freeaddrinfo.

rdma_resolve_addrinfo is similar to rdma_getaddrinfo but it also attempts to resolve the RDMA route to the destination address. This function is useful when the caller needs to establish a connection to a remote RDMA device.

rdma_query_addrinfo is used to query for RDMA port support for a given host name and service name. The function returns a list of supported RDMA port spaces and queue pair types. This function is useful when the caller needs to determine the RDMA capabilities of a remote host.

rdma_freeaddrinfo frees the memory allocated by rdma_getaddrinfo, rdma_resolve_addrinfo or rdma_query_addrinfo.

RETURN VALUE

On success, these functions return 0. On failure, they return a negative error code.

NOTES

The rdma_getaddrinfo, rdma_resolve_addrinfo and rdma_query_addrinfo functions are thread-safe.

The rdma_freeaddrinfo function is not thread-safe.

The struct rdma_addrinfo structure is defined in the <rdma/rdma_verbs.h> header file.

rdma_addrinfo

The struct rdma_addrinfo is used to specify hints for address resolution and to return address information. It is defined as follows:

struct rdma_addrinfo {
    int                     ai_flags;       /* AI_... flags */
    int                     ai_port_space;  /* RDMA_PS_... */
    struct sockaddr         *ai_src_addr;   /* source address */
    struct sockaddr         *ai_dst_addr;   /* destination address */
    struct ibv_context      *ai_verbs;      /* RDMA context */
    struct ibv_pd           *ai_pd;         /* protection domain */
    enum ibv_qp_type        ai_qp_type;     /* queue pair type */
    int                     ai_port_number; /* RDMA port number */
    int                     ai_pkey_index;  /* Partition Key index */
    struct rdma_addrinfo    *ai_next;       /* next address info */
};

The ai_next field is used to link multiple struct rdma_addrinfo structures together in a linked list. When rdma_getaddrinfo returns a list of addresses, the ai_next field of each structure points to the next structure in the list. The last structure in the list has its ai_next field set to NULL.

If rdma_getaddrinfo returns multiple addresses, the caller can iterate through the list using the RDMA_ITERATOR_NEXT flag. The caller should set the ai_flags field to RDMA_ITERATOR_NEXT and call rdma_getaddrinfo again with the same parameters. The res parameter should point to the previously returned struct rdma_addrinfo.

If no structures exist, res will be set to NULL.
