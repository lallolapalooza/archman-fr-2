NOM

rdfind - trouve les fichiers dupliqués

SYNTAXE

rdfind [ options ] répertoire1 | fichier1 [ répertoire2 | fichier2 ] ...

DESCRIPTION

rdfind trouve les fichiers dupliqués à travers et/ou dans plusieurs répertoires. Il calcule la somme de contrôle uniquement si nécessaire. rdfind s'exécute en temps O(Nlog(N)) où N est le nombre de fichiers.

Si deux (ou plus) fichiers égaux sont trouvés, le programme décide lequel d'entre eux est l'original et les autres sont considérés comme des doublons. Ceci est fait en classant les fichiers les uns par rapport aux autres et en décidant lequel a le rang le plus élevé. Voir la section CLASSEMENT pour les détails.

Par défaut, aucune action n'est effectuée en dehors de la création d'un fichier avec les fichiers détectés et de l'affichage de l'espace potentiellement économisé.

Si vous avez besoin d'un meilleur contrôle sur le classement que ce qui est proposé, vous pouvez utiliser un préprocesseur qui trie les noms de fichiers dans l'ordre souhaité et ensuite exécuter le programme en utilisant xargs. Voir les exemples ci-dessous pour savoir comment utiliser find et xargs conjointement avec rdfind.

Pour inclure des fichiers ou des répertoires dont les noms commencent par -, utilisez rdfind ./- pour ne pas les confondre avec des options.

CLASSEMENT

Étant donné deux fichiers ou plus qui sont égaux, celui qui a le rang le plus élevé est sélectionné comme original et les autres sont des doublons. Les règles de classement sont données ci-dessous, où les règles sont exécutées depuis le début jusqu'à ce qu'un original ait été trouvé. Étant donné deux fichiers A et B qui ont une taille et un contenu égaux, le classement est le suivant :

Si A a été trouvé lors du balayage d'un argument d'entrée avant B, A a un rang plus élevé.

Si A a été trouvé à une profondeur de répertoire inférieure à B, A a un rang plus élevé (A est plus proche de la racine).

Si A et B sont trouvés lors du balayage du même argument d'entrée et partagent la même profondeur de répertoire, celui qui a le rang le plus élevé dépend si l'opération déterministe est activée. Ceci est activé par défaut, voir l'option -deterministic). Si activé, lequel a le rang le plus élevé n'est pas spécifié mais est déterministe. Si désactivé, celui qui a été signalé en premier par le système de fichiers a le rang le plus élevé.

OPTIONS

Options de recherche, etc :

-ignoreempty vrai|faux
Ignore les fichiers vides. Définir cela sur vrai (par défaut) est équivalent à -minsize 1, faux est équivalent à -minsize 0.
-minsize N
Ignore les fichiers de moins de N octets. La valeur par défaut est 1, ce qui signifie que les fichiers vides sont ignorés.
-maxsize N
Ignore les fichiers de N octets ou plus. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée.
-followsymlinks vrai|faux
Suit les liens symboliques. La valeur par défaut est faux.
-removeidentinode vrai|faux
Supprime les éléments trouvés qui ont le même inode et le même ID de périphérique. La valeur par défaut est vrai.
-checksum md5|sha1|sha256|sha512|xxh128
Quel type de somme de contrôle utiliser : md5, sha1, sha256, sha512 ou xxh128. La valeur par défaut est sha1 depuis la version 1.4.0. xxh128 est une somme de contrôle très rapide, mais pas de qualité cryptographique. Le support xxh est optionnel et nécessite que rdfind ait été configuré avec --with-xxhash. Dans le cas où xxh est utilisé mais qu'il n'y a pas de support, une erreur est retournée.
-buffersize N
Taille de bloc en octets lors du calcul de la somme de contrôle des fichiers, une taille plus petite ou plus grande peut améliorer les performances en fonction du système de fichiers et de l'algorithme de somme de contrôle. La valeur par défaut est 1 MiB, le maximum autorisé est 128 MiB (inclus).
-deterministic vrai|faux
Si défini (par défaut), trie les fichiers de rang égal dans un ordre indéterminé mais déterministe. Cela rend le comportement indépendant de l'ordre dans lequel les fichiers sont listés lors de l'interrogation du système de fichiers.

Options d'action :

-makesymlinks vrai|faux
Remplace les fichiers dupliqués par des liens symboliques. La valeur par défaut est faux.
-makehardlinks vrai|faux
Remplace les fichiers dupliqués par des liens physiques. La valeur par défaut est faux.
-makeresultsfile vrai|faux
Crée un fichier de résultats dans le répertoire courant. La valeur par défaut est vrai. Si le fichier existe, il est écrasé. Cela n'affecte pas la suppression des éléments. Voir -dryrun pour désactiver les suppressions.
-outputname nom
Nomme le fichier de résultats "nom" au lieu du nom par défaut results.txt.
-deleteduplicates vrai|faux
Supprime (désélectionne) les fichiers. La valeur par défaut est faux.

Options générales :

-sleep Xms
Attend X millisecondes entre la lecture de chaque fichier, pour réduire la charge. La valeur par défaut est 0 (pas d'attente). Notez que seules quelques valeurs sont actuellement prises en charge : 0, 1-5, 10, 25, 50, 100 millisecondes.
-n, -dryrun vrai|faux
Affiche ce qui aurait dû être fait, ne supprime ni ne crée de liens réellement. La valeur par défaut est faux.
-h, -help, --help
Affiche un bref message d'aide.
-v, -version, --version
Affiche le numéro de version.

EXEMPLES

Recherche de fichiers dupliqués dans le répertoire personnel et un répertoire de sauvegarde :
rdfind ~ /mnt/backup
Suppression des doublons dans un répertoire de sauvegarde :
rdfind -deleteduplicates vrai /mnt/backup
Recherche de fichiers dupliqués dans des répertoires nommés foo :
find . -type d -name foo -print0 |xargs -0 rdfind

FICHIERS

results.txt (le nom par défaut est results.txt et peut être modifié avec l'option outputname, voir ci-dessus) Le fichier de résultats results.txt contiendra une ligne par fichier dupliqué trouvé, ainsi qu'une ligne d'en-tête expliquant les colonnes. Un texte décrit pourquoi le fichier est considéré comme un doublon :

DUPTYPE_UNKNOWN une erreur interne

DUPTYPE_FIRST_OCCURRENCE le fichier considéré comme l'original.

DUPTYPE_WITHIN_SAME_TREE fichiers dans le même arbre (trouvés lors du traitement du répertoire dans le même argument d'entrée que l'original)

DUPTYPE_OUTSIDE_TREE le fichier est trouvé lors du traitement d'un argument d'entrée différent de celui de l'original.

DIAGNOSTICS

VALEURS DE RETOUR

0 en cas de succès, une valeur non nulle sinon.

BOGUES/FONCTIONNALITÉS

Lors de la spécification du même répertoire deux fois, il conserve le premier rencontré comme le plus important (original), et les autres comme doublons. Ce n'est peut-être pas ce que vous voulez.

Les liens symboliques créent des liens absolus. Ce n'est peut-être pas ce que vous voulez. Pour créer des liens relatifs à la place, vous pouvez utiliser la commande symlink (2), qui est capable de convertir des liens absolus en liens relatifs.

Les anciennes versions contenaient malheureusement une faute d'orthographe dans le mot occurrence. Ceci est maintenant corrigé.

ed (depuis la version 1.3), ce qui peut affecter les scripts utilisateur analysant le fichier de sortie écrit par rdfind.

CONSIDÉRATIONS DE SÉCURITÉ

Évitez de manipuler les répertoires pendant que rdfind les lit. rdfind est assez fragile dans ce cas. En particulier, lors de la suppression ou de la création de liens, rdfind peut être sujet à une attaque par lien symbolique. À utiliser avec précaution !
