RTMPGW(8) Manuel de l'administrateur système RTMPGW(8)

NOM

rtmpgw - passerelle de streaming multimédia RTMP

SYNTAXE

rtmpgw [-r url] [-n nomhote] [-c port] [-l protocole] [-S hote:port] [-a app] [-t tcUrl] [-p pageUrl] [-s swfUrl] [-f flashVer] [-u auth] [-C conndata] [-y playpath] [-v] [-d abonnement] [-e] [-k saut] [-A debut] [-B fin] [-b buffer] [-m delai] [-T cle] [-j JSON] [-w swfHash] [-x swfSize] [-W swfUrl] [-X swfAge] [-D adresse] [-g port] [-q] [-V] [-z]
rtmpgw -h

DESCRIPTION

rtmpgw est un serveur pour le streaming de contenu multimédia depuis RTMP vers HTTP.

rtmpgw écoute les requêtes HTTP qui spécifient les paramètres de flux RTMP, puis renvoie les données RTMP dans la réponse HTTP. La seule requête HTTP valide est « GET / » mais des options supplémentaires peuvent être fournies sous forme encodée dans l'URL. Les options spécifiées sur la ligne de commande seront utilisées par défaut, et pourront être remplacées par les options de la requête HTTP.

OPTIONS

Paramètres réseau

Ces options définissent comment se connecter au serveur multimédia.

--rtmp -r url
URL du serveur et du contenu multimédia.
--hote -n nomhote
Remplace le nom d'hôte dans l'URL RTMP.
--port -c port
Remplace le numéro de port dans l'URL RTMP.
--protocole -l nombre
Remplace le protocole dans l'URL RTMP. 
  0 = rtmp
  1 = rtmpt
  2 = rtmpe
  3 = rtmpte
  4 = rtmps
  5 = rtmpts
--socks -S hote:port
Utilise le proxy SOCKS4 spécifié.

Paramètres de connexion

Ces options définissent le contenu du paquet de requête RTMP Connect. Si les valeurs correctes ne sont pas fournies, le serveur multimédia rejettera la tentative de connexion.

--app -a app
Nom de l'application à laquelle se connecter sur le serveur RTMP. Remplace l'application dans l'URL RTMP. Parfois, l'analyseur d'URL de rtmpdump ne parvient pas à déterminer le nom de l'application automatiquement, il doit donc être spécifié explicitement à l'aide de cette option.
--tcUrl -t url
URL du flux cible. Par défaut, rtmp[e]://hote[:port]/app/playpath.
--pageUrl -p url
URL de la page Web sur laquelle le média était intégré. Par défaut, aucune valeur ne sera envoyée.
--swfUrl -s url
URL du lecteur SWF pour le média. Par défaut, aucune valeur ne sera envoyée.
--flashVer -f version
Version du plugin Flash utilisé pour exécuter le lecteur SWF. Par défaut, "LNX 10,0,32,18".
--auth -u chaîne
Une chaîne d'authentification à ajouter au message Connect. L'utilisation de cette option ajoutera une valeur booléenne TRUE puis la chaîne spécifiée. Cette option n'est utilisée que par certains serveurs spécifiques et est obsolète. L'option plus générale --conn devrait être utilisée à la place.
--conn -C type:donnée
Ajoute des données AMF arbitraires au message Connect. Le type doit être B pour Booléen, N pour Nombre, S pour Chaîne, O pour Objet, ou Z pour Nul. Pour les booléens, la donnée doit être 0 ou 1 pour FAUX ou VRAI, respectivement. De même, pour les objets, la donnée doit être 0 ou 1 pour terminer ou commencer un objet, respectivement. Les éléments de donnée dans les sous-objets peuvent être nommés, en préfixant le type avec 'N' et en spécifiant le nom avant la valeur, par exemple NB:monFlag:1. Cette option peut être utilisée plusieurs fois pour construire des séquences AMF arbitraires. Par exemple, 
  -C B:1 -C S:authMe -C O:1 -C NN:code:1.23 -C NS:flag:ok -C O:0

Paramètres de session

Ces options prennent effet après que la requête Connect ait réussi.

--playpath -y chemin
Remplace le playpath analysé à partir de l'URL RTMP. Parfois, l'analyseur d'URL de rtmpdump ne parvient pas à déterminer le bon playpath automatiquement, il doit donc être spécifié explicitement à l'aide de cette option.
--live -v
Spécifie que le média est un flux en direct. Aucune reprise ou recherche dans les flux en direct n'est possible.
--abonnement -d flux
Nom du flux en direct auquel s'abonner. Par défaut, playpath.
--debut -A num
Commencer à num secondes dans le flux. Non valide pour les flux en direct.
--fin -B num
Arrêter à num secondes dans le flux.
--buffer -b num
Définir le temps de buffer à num millisecondes. Par défaut, 20000.
--delai -m num
Mettre fin à la session après num secondes sans recevoir de données du serveur. Par défaut, 120.

Paramètres de sécurité

Ces options gèrent les demandes d'authentification supplémentaires du serveur.

--cle -T clé
Clé pour la réponse SecureToken, utilisée si le serveur exige une authentification SecureToken.
--json -j JSON
Jeton JSON utilisé par les anciens serveurs Justin.tv. Déclenche NetStream.Authenticate.UsherToken.
--swfhash -w chainehex
Hash SHA256 du fichier SWF décompressé. Cette option peut être nécessaire si le serveur utilise la vérification SWF, mais voir l'option --swfVfy ci-dessous. Le hash fait 32 octets et doit être fourni en hexadécimal. L'option --swfsize doit toujours être utilisée avec cette option.
--swfsize -x num
Taille du fichier SWF décompressé. Cette option peut être nécessaire si le serveur utilise la vérification SWF, mais voir l'option --swfVfy ci-dessous. L'option --swfhash doit toujours être utilisée avec cette option.
--swfVfy -W url
URL du lecteur SWF pour ce média. Cette option remplace les trois options --swfUrl, --swfhash, et --swfsize. Lorsque cette option est utilisée, le lecteur SWF est récupéré depuis l'URL spécifiée et le hash et la taille sont calculés automatiquement. De plus, les informations sont mises en cache dans un fichier .swfinfo dans le répertoire personnel de l'utilisateur, de sorte qu'elles n'ont pas besoin d'être récupérées et recalculées à chaque exécution de rtmpdump. Le fichier .swfinfo enregistre l'URL, l'heure de récupération, l'horodatage de modification du fichier SWF, sa taille et son hash. Par défaut, les informations mises en cache seront utilisées pendant 30 jours avant une nouvelle vérification.
--swfAge -X jours
Spécifie combien de jours utiliser les informations SWF mises en cache avant de vérifier à nouveau. Utiliser 0 pour toujours

rtmpgw(8) — RTMPDump v2.4

NAME

rtmpgw ― RTMP proxy

SYNOPSIS

rtmpgw

    [-r URL] [-R URL] [-y playpath] [-Y playpath]
    [-d debug] [-l log] [-u user] [-p password]
    [-C token] [-t timeout] [-T timeout]
    [-a app] [-A app] [-f flashver] [-F flashver]
    [-k swfhash] [-K swfhash] [-s swfurl] [-S swfurl]
    [-W swfurl] [-x swfhash] [-X swfhash]
    [-H swfurl] [-o swfurl] [-b bytes] [-B bytes]
    [-e rtmp-server-ip] [-E rtmp-server-ip]
    [-v vhost] [-V vhost]
    [--device | -D address] [--sport | -g port]
    [--quiet | -q] [--verbose | -V] [--debug | -z]
    [--help | -h]

DESCRIPTION

The rtmpgw utility is a RTMP proxy. It listens on an IP address and port specified by the user, and forwards all incoming connections to another RTMP server. It can be used to relay RTMP streams, or to allow clients to connect to RTMP servers behind a firewall.

When the SWFVerification directive is enabled in the configuration file, it is possible to check the SWF URL. Note that if the check shows that the SWF file has the same modification timestamp as before, it will not be retrieved again.

Miscellaneous

--device -D address
Adresse IP de l'écoute. La valeur par défaut est 0.0.0.0, c'est-à-dire n'importe quelle adresse IP.
--sport -g port
Port d'écoute. La valeur par défaut est 80.
--quiet -q
Supprime toute sortie de commande.
--verbose -V
Sortie de commande détaillée.
--debug -z
Sortie de niveau débogage. Extrêmement détaillée, y compris les dumps hexadécimaux de toutes les données de paquets.
--help -h
Affiche un résumé des options de commande.

EXAMPLES

La requête HTTP

GET /?r=rtmp:%2f%2fserver%2fmyapp&y=somefile HTTP/1.0

est équivalente à l'invocation de rtrmpdump(1)

rtmpdump -r rtmp://server/myapp -y somefile

Notez que seules les options courtes (lettre unique) sont prises en charge.

ENVIRONMENT

HOME
La valeur de $HOME est utilisée comme emplacement pour le fichier .swfinfo.

FILES

$HOME/.swfinfo
Cache des informations de vérification SWF
