RTLD-AUDIT(7) Manuel d'informations diverses RTLD-AUDIT(7)

NOM

rtld-audit - API d'audit pour le lieur dynamique

SYNTAXE

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <link.h>

DESCRIPTION

Le lieur dynamique GNU (lieur d'exécution) fournit une API d'audit qui permet à une application d'être informée lorsque divers événements de liaison dynamique se produisent. Cette API est très similaire à l'interface d'audit fournie par le lieur d'exécution Solaris. Les constantes et prototypes nécessaires sont définis en incluant <link.h>.

Pour utiliser cette interface, le programmeur crée une bibliothèque partagée qui implémente un ensemble standard de noms de fonctions. Toutes les fonctions n'ont pas besoin d'être implémentées : dans la plupart des cas, si le programmeur ne s'intéresse pas à une catégorie particulière d'événements d'audit, aucune implémentation n'a besoin d'être fournie pour la fonction d'audit correspondante.

Pour employer l'interface d'audit, la variable d'environnement LD_AUDIT doit être définie pour contenir une liste de bibliothèques partagées séparées par des deux-points, chacune pouvant implémenter (des parties de) l'API d'audit. Lorsqu'un événement auditable se produit, la fonction correspondante est appelée dans chaque bibliothèque, dans l'ordre où les bibliothèques sont listées.

la_version()

unsigned int la_version(unsigned int version);

C'est la seule fonction qui doit être définie par une bibliothèque d'audit : elle effectue la poignée de main initiale entre le lieur dynamique et la bibliothèque d'audit. Lors de l'appel de cette fonction, le lieur dynamique transmet, dans version, la version la plus élevée de l'interface d'audit que le lieur supporte.

Une implémentation typique de cette fonction renvoie simplement la constante LAV_CURRENT, qui indique la version de <link.h> qui a été utilisée pour construire le module d'audit. Si le lieur dynamique ne supporte pas cette version de l'interface d'audit, il refusera d'activer ce module d'audit. Si la fonction renvoie zéro, le lieur dynamique n'active pas non plus ce module d'audit.

Afin d'activer la compatibilité descendante avec les lieurs dynamiques plus anciens, un module d'audit peut examiner l'argument version et renvoyer une version antérieure à LAV_CURRENT, en supposant que le module puisse ajuster son implémentation pour correspondre aux exigences de la version précédente de l'interface d'audit. La fonction la_version ne doit pas renvoyer la valeur de version sans vérifications supplémentaires car elle pourrait correspondre à une interface qui ne correspond pas aux définitions de <link.h> utilisées pour construire le module d'audit.

la_objsearch()

char *la_objsearch(const char *name, uintptr_t *cookie,
                   unsigned int flag);

Le lieur dynamique invoque cette fonction pour informer la bibliothèque d'audit qu'il s'apprête à rechercher un objet partagé. L'argument name est le nom de fichier ou le chemin d'accès à rechercher. cookie identifie l'objet partagé qui a initié la recherche. flag est défini à l'une des valeurs suivantes :

LA_SER_ORIG
C'est le nom original recherché. Typiquement, ce nom provient d'une entrée ELF DT_NEEDED, ou est l'argument filename donné à dlopen(3).
LA_SER_LIBPATH
name a été créé en utilisant un répertoire spécifié dans LD_LIBRARY_PATH.
LA_SER_RUNPATH
name a été créé en utilisant un répertoire spécifié dans une liste ELF DT_RPATH ou DT_RUNPATH.
LA_SER_CONFIG
name a été trouvé via le cache ldconfig(8) (/etc/ld.so.cache).
LA_SER_DEFAULT
name a été trouvé en parcourant un des répertoires par défaut.
LA_SER_SECURE
name est spécifique à un objet sécurisé (non utilisé sous Linux).

Comme résultat de sa fonction, la_objsearch() renvoie le chemin d'accès que le lieur dynamique doit utiliser pour un traitement ultérieur. Si NULL est renvoyé, alors ce chemin est ignoré pour un traitement ultérieur. Si cette bibliothèque d'audit a simplement l'intention de surveiller les chemins de recherche, alors name devrait être renvoyé.

la_activity()

void la_activity( uintptr_t *cookie, unsigned int flag);

Le lieur dynamique appelle cette fonction pour informer la bibliothèque d'audit que des activités de mappe de liaison se produisent. cookie identifie l'objet en tête de la mappe de liaison. Lorsque le lieur dynamique appelle cette fonction, flag est défini à l'une des valeurs suivantes :

LA_ACT_ADD
De nouveaux objets sont ajoutés à la mappe de liaison.
LA_ACT_DELETE
Des objets sont retirés de la mappe de liaison.
LA_ACT_CONSISTENT
L'activité de la mappe de liaison est terminée : la mappe est de nouveau cohérente.

la_objopen()

unsigned int la_objopen(struct link_map *map, Lmid_t lmid,
                        uintptr_t *cookie);

Le lieur dynamique appelle cette fonction lorsqu'un nouvel objet partagé est chargé. L'argument map est un pointeur vers une structure de mappe de liaison qui décrit l'objet. Le champ lmid a l'une des valeurs suivantes :

LM_ID_BASE
La mappe de liaison fait partie de l'espace de noms initial.
LM_ID_NEWLM
La mappe de liaison fait partie d'un nouvel espace de noms demandé via dlmopen(3).

cookie est un pointeur vers un identifiant pour cet objet. L'identifiant est fourni lors d'appels ultérieurs aux fonctions de la bibliothèque d'audit afin d'identifier cet objet. Cet identifiant est initialisé pour pointer vers la structure de mappe de liaison de l'objet, mais la bibliothèque d'audit peut modifier l'identifiant pour une autre valeur qu'elle pourrait préférer utiliser pour identifier l'objet.

Comme valeur de retour, la_objopen() renvoie un masque de bits créé en combinant par OU zéro ou plusieurs des constantes suivantes, qui permettent à la bibliothèque d'audit de sélectionner les objets à surveiller par la_symbind*():

LA_FLG_BINDTO
Auditer les liaisons de symboles vers cet objet.
LA_FLG_BINDFROM
Auditer les liaisons de symboles depuis cet objet.

Une valeur de retour de 0 de la_objopen() indique qu'aucune liaison de symbole ne doit être auditée pour cet objet.

la_objclose()

unsigned int la_objclose(uintptr_t *cookie);

Le lieur dynamique invoque cette fonction après l'exécution de tout code de finalisation pour l'objet, avant que l'objet ne soit déchargé. L'argument cookie est l'identifiant obtenu lors d'une invocation précédente de la_objopen().

Dans l'implémentation actuelle, la valeur renvoyée par la_objclose() est ignorée.

la_preinit()

void la_preinit(uintptr_t *cookie);

Le lieur dynamique invoque cette fonction après que tous les objets partagés aient été chargés, avant que le contrôle ne soit passé à l'application (c'est-à-dire, avant l'appel de main()). Notez que main() peut encore plus tard charger dynamiquement des objets en utilisant dlopen(3).

ass='permalink' href='#la_symbind*()'>la_symbind*() 
uintptr_t la_symbind32(Elf32_Sym *sym, unsigned int ndx,
                       uintptr_t *refcook, uintptr_t *defcook,
                       unsigned int *flags, const char *symname);
uintptr_t la_symbind64(Elf64_Sym *sym, unsigned int ndx,
                       uintptr_t *refcook, uintptr_t *defcook,
                       unsigned int *flags, const char *symname);

Le chargeur dynamique invoque l'une de ces fonctions lorsqu'une liaison de symbole se produit entre deux objets partagés qui ont été marqués pour notification d'audit par la_objopen(). La fonction la_symbind32() est utilisée sur les plateformes 32 bits ; la fonction la_symbind64() est utilisée sur les plateformes 64 bits.

L'argument sym est un pointeur vers une structure qui fournit des informations sur le symbole en cours de liaison. La définition de la structure est indiquée dans <elf.h>. Parmi les champs de cette structure, st_value indique l'adresse à laquelle le symbole est lié.

L'argument ndx donne l'indice du symbole dans la table des symboles de l'objet partagé lié.

L'argument refcook identifie l'objet partagé qui effectue la référence du symbole ; il s'agit du même identifiant qui est fourni à la fonction la_objopen() qui a retourné LA_FLG_BINDFROM. L'argument defcook identifie l'objet partagé qui définit le symbole référencé ; il s'agit du même identifiant qui est fourni à la fonction la_objopen() qui a retourné LA_FLG_BINDTO.

L'argument symname pointe vers une chaîne contenant le nom du symbole.

L'argument flags est un masque de bits qui fournit des informations sur le symbole et peut être utilisé pour modifier l'audit ultérieur de cette entrée PLT (Procedure Linkage Table). Le chargeur dynamique peut fournir les valeurs de bits suivantes dans cet argument :

LA_SYMB_DLSYM
La liaison est le résultat d'un appel à dlsym(3).
LA_SYMB_ALTVALUE
Un appel précédent à la_symbind*() a retourné une valeur alternative pour ce symbole.

Par défaut, si la bibliothèque d'audit implémente les fonctions la_pltenter() et la_pltexit() (voir ci-dessous), alors ces fonctions sont invoquées, après la_symbind(), pour les entrées PLT, chaque fois que le symbole est référencé. Les drapeaux suivants peuvent être ORés dans *flags pour modifier ce comportement par défaut :

LA_SYMB_NOPLTENTER
Ne pas appeler la_pltenter() pour ce symbole.
LA_SYMB_NOPLTEXIT
Ne pas appeler la_pltexit() pour ce symbole.

La valeur de retour de la_symbind32() et la_symbind64() est l'adresse à laquelle le contrôle doit être transmis après le retour de la fonction. Si la bibliothèque d'audit se contente de surveiller les liaisons de symboles, elle doit retourner sym->st_value. Une valeur différente peut être retournée si la bibliothèque souhaite diriger le contrôle vers un emplacement alternatif.

la_pltenter()

Le nom précis et les types d'arguments de cette fonction dépendent de la plateforme matérielle. (La définition appropriée est fournie par <link.h>.) Voici la définition pour x86-32 :

Elf32_Addr la_i86_gnu_pltenter(Elf32_Sym *sym, unsigned int ndx,
                 uintptr_t *refcook, uintptr_t *defcook,
                 La_i86_regs *regs, unsigned int *flags,
                 const char *symname, long *framesizep);

Cette fonction est invoquée juste avant qu'une entrée PLT ne soit appelée, entre deux objets partagés qui ont été marqués pour notification de liaison.

Les arguments sym, ndx, refcook, defcook et symname sont les mêmes que pour la_symbind*().

L'argument regs pointe vers une structure (définie dans <link.h>) contenant les valeurs des registres à utiliser pour l'appel à cette entrée PLT.

L'argument flags pointe vers un masque de bits qui transmet des informations sur cette entrée PLT et peut être utilisé pour modifier l'audit ultérieur de celle-ci, comme pour la_symbind*().

L'argument framesizep pointe vers un tampon de type long int qui peut être utilisé pour définir explicitement la taille du cadre utilisée pour l'appel à cette entrée PLT. Si différentes invocations de la_pltenter() pour ce symbole retournent des valeurs différentes, la valeur maximale retournée est utilisée. La fonction la_pltexit() n'est appelée que si ce tampon est explicitement défini à une valeur appropriée.

La valeur de retour de la_pltenter() est la même que pour la_symbind*().

la_pltexit()

Le nom précis et les types d'arguments de cette fonction dépendent de la plateforme matérielle. (La définition appropriée est fournie par <link.h>.) Voici la définition pour x86-32 :

unsigned int la_i86_gnu_pltexit(Elf32_Sym *sym, unsigned int ndx,
                 uintptr_t *refcook, uintptr_t *defcook,
                 const La_i86_regs *inregs, La_i86_retval *outregs,
                 const char *symname);

Cette fonction est appelée lorsqu'une entrée PLT, établie entre deux objets partagés qui ont été marqués pour notification de liaison, retourne. La fonction est appelée juste avant que le contrôle ne retourne à l'appelant de l'entrée PLT.

Les arguments sym, ndx, refcook, defcook et symname sont les mêmes que pour la_symbind*().

L'argument inregs pointe vers une structure (définie dans <link.h>) contenant les valeurs des registres utilisés pour l'appel à cette entrée PLT. L'argument outregs pointe vers une structure (définie dans <link.h>) contenant les valeurs de retour pour l'appel à cette entrée PLT. Ces valeurs peuvent être modifiées par l'appelant, et les modifications seront visibles par l'appelant de l'entrée PLT.

Dans l'implémentation GNU actuelle, la valeur de retour de la_pltexit() est ignorée.

VERSIONS

Cette API est très similaire à l'API Solaris décrite dans le Guide des Linkers et Bibliothèques Solaris, dans le chapitre Interface d'audit du Linker d'exécution.

STANDARDS

Aucun.

NOTES

Notez les différences suivantes par rapport à l'API d'audit du chargeur dynamique de Solaris :

•
L'interface la_objfilter() de Solaris n'est pas prise en charge par l'implémentation GNU.
•
Les fonctions la_symbind32() et la_pltexit() de Solaris ne fournissent pas d'argument symname.
•
La fonction la_pltexit() de Solaris ne fournit pas les arguments inregs et outregs (mais fournit un argument retval avec la valeur de retour de la fonction).

BUGS

Dans les versions de glibc jusqu'à et y compris 2.9, la spécification de plusieurs bibliothèques d'audit dans LD_AUDIT entraîne un crash au moment de l'exécution. Ceci est apparemment corrigé dans glibc 2.10.

EXEMPLES

#include <link.h>
#include <stdio.h>
unsigned int
la_version(unsigned int version)
{
    printf("la_version(): version = %u; LAV_CURRENT = %u\n",
            version, LAV_CURRENT);
    return LAV_CURRENT;
}
char *
la_objsearch(const char *name, uintptr_t *cookie, unsigned int flag)
{
    printf("la_objsearch(): name = %s; cookie = %p", name, cookie);
    printf("; flag = %s\n",
            (flag == LA_SER_ORIG) ?    "LA_SER_ORIG" :
            (flag == LA_SER_LIBPATH) ? "LA_SER_LIBPATH" :
            (flag == LA_SER_RUNPATH) ? "LA_SER_RUNPATH" :
            (flag == LA_SER_DEFAULT) ? "LA_SER_DEFAULT" :
            (flag == LA_SER_CONFIG) ?  "LA_SER_CONFIG" :
            (flag == LA_SER_SECURE) ?  "LA_SER_SECURE" :
            "???");
    return name;
}
void
la_activity (uintptr_t *cookie, unsigned int flag)
{
    printf("la_activity(): cookie = %p; flag = %s\n", cookie,
            (flag == LA_ACT_CONSISTENT) ? "LA_ACT_CONSISTENT" :
            (flag == LA_ACT_ADD) ?        "LA_ACT_ADD" :
            (flag == LA_ACT_DELETE) ?     "LA_ACT_DELETE" :
            "???");
}
unsigned int
la_objopen(struct link_map *map, Lmid_t lmid, uintptr_t *cookie)
{
    printf("la_objopen(): loading \"%s\"; lmid = %s; cookie=%p\n",
            map->l_name,
            (lmid == LM_ID_BASE) ?  "LM_ID_BASE" :
            (lmid == LM_ID_NEWLM) ? "LM_ID_NEWLM" :
            "???",
            cookie);
    return LA_FLG_BINDTO | LA_FLG_BINDFROM;
}
unsigned int
la_objclose (uintptr_t *cookie)
{
    printf("la_objclose(): %p\n", cookie);
    return 0;
}
void
la_preinit(uintptr_t *cookie)
{
    printf("la_preinit(): %p\n", cookie);
}
uintptr_t
la_symbind32(Elf32_Sym *sym, unsigned int ndx, uintptr_t *refcook,
        uintptr_t *defcook, unsigned int *flags, const char *symname)
{
    printf("la_symbind32(): symname = %s; sym->st_value = %p\n",
            symname, sym->st_value);
    printf("        ndx = %u; flags = %#x", ndx, *flags);
    printf("; refcook = %p; defcook = %p\n", refcook, defcook);
    return sym->st_value;
}
uintptr_t
la_symbind64(Elf64_Sym *sym, unsigned int ndx, uintptr_t *refcook,
        uintptr_t *defcook, unsigned int *flags, const char *symname)
{
    printf("la_symbind64(): symname = %s; sym->st_value = %p\n",
            symname, sym->st_value);
    printf("        ndx = %u; flags = %#x", ndx, *flags);
    printf("; refcook = %p; defcook = %p\n", refcook, defcook);
    return sym->st_value;
}
Elf32_Addr
la_i86_gnu_pltenter(Elf32_Sym *sym, unsigned int ndx,
        uintptr_t *refcook, uintptr_t *defcook, La_i86_regs *regs,
        unsigned int *flags, const char *symname, long *framesizep)
{
    printf("la_i86_gnu_pltenter(): %s (%p)\n", symname, sym->st_value);
    return sym->st_value;
}
