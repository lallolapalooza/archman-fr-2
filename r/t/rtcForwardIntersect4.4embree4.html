NOM

rtcForwardIntersect4/8/16/Ex - transmet un paquet de rayons vers une nouvelle scène
  depuis un rappel de géométrie utilisateur

DESCRIPTION

Les fonctions rtcForwardIntersect4/8/16 et rtcForwardIntersect4/8/16Ex transmettent le parcours d'un paquet de rayons transformé (argument ray) dans une scène (argument scene) depuis un rappel de géométrie utilisateur. La fonction ne peut être appelée que depuis un rappel de géométrie utilisateur pour un parcours de rayon initié avec la fonction rtcIntersect4/8/16. La structure des arguments du rappel de l'invocation doit être passée à la transmission du rayon (argument args). Le rappel de géométrie utilisateur doit se terminer immédiatement après l'invocation de la fonction rtcForwardIntersect4/8/16/Ex.

Seuls les membres d'origine du rayon et de direction du rayon de l'argument rayon sont utilisés pour la transmission ; toutes les propriétés de rayon supplémentaires sont héritées de l'invocation initiale de parcours de rayon de rtcIntersect4/8/16.

L'implémentation de la fonction rtcForwardIntersect4/8/16 continue récursivement le parcours du rayon dans la scène spécifiée et empile l'ID d'instance fourni (argument instID) sur la pile des ID d'instance. Les informations de collision sont mises à jour dans la structure de collision du rayon passée à l'invocation originale de rtcIntersect4/8/16.

Cette fonction peut être utilisée pour implémenter l'instanciation définie par l'utilisateur en utilisant des géométries utilisateur, par exemple, en transformant le rayon d'une manière spéciale, et/ou en sélectionnant entre différentes scènes à instancier.

Pour les tableaux d'instances définis par l'utilisateur, la variante rtcForwardIntersect4/8/16Ex possède un argument supplémentaire instPrimID qui est empilé sur la pile des ID de primitive d'instance. Les ID de primitive d'instance identifient quelle instance d'un tableau d'instances a été touchée.

Lors de l'utilisation d'Embree sur le CPU, il est possible d'invoquer récursivement rtcIntersect4/8/16 directement depuis un rappel de géométrie utilisateur. Cependant, lorsque SYCL est utilisé, le traçage récursif de rayons n'est pas directement pris en charge, et la fonction rtcForwardIntersect4/8/16 doit être utilisée.

Pour rtcForwardIntersect4, le paquet de rayons doit être aligné sur 16 octets, pour rtcForwardIntersect8 l'alignement doit être de 32 octets, et pour rtcForwardIntersect16 l'alignement doit être de 64 octets.

STATUT DE SORTIE

Pour des raisons de performance, cette fonction n'effectue aucune vérification d'erreur, elle ne définit donc aucun indicateur d'erreur en cas d'échec.
