rtcSetGeometryPointQueryFunction(3) Embree Ray Tracing Kernels 3 rtcSetGeometryPointQueryFunction(3)

NOM

rtcSetGeometryPointQueryFunction - définit la fonction de rappel pour la requête de point d'une géométrie

SYNTAXE

#include <embree3/rtcore.h>
struct RTCPointQueryFunctionArguments
{
  // l'objet de requête (en espace monde) qui a été passé comme argument de rtcPointQuery.
  struct RTCPointQuery* query;
  // utilisé pour les données d'entrée/sortie utilisateur. Ne sera pas lu ni modifié en interne.
  void* userPtr;
  // ID de primitive et ID de géométrie de la primitive
  unsigned int  primID;        
  unsigned int  geomID;    
  // le contexte avec la pile de transformations et d'ID d'instance
  struct RTCPointQueryContext* context;
  // facteur d'échelle indiquant si la transformation d'instance actuelle
  // est une transformation de similarité.
  float similarityScale;
};
typedef bool (*RTCPointQueryFunction)(
  struct RTCPointQueryFunctionArguments* args
);
void rtcSetGeometryPointQueryFunction(
  RTCGeometry geometry,
  RTCPointQueryFunction queryFunc
);

DESCRIPTION

La fonction rtcSetGeometryPointQueryFunction enregistre une fonction de rappel de requête de point (argument queryFunc) pour la géométrie spécifiée (argument geometry).

Une seule fonction de rappel peut être enregistrée par géométrie et les invocations ultérieures écrasent la fonction de rappel précédemment définie. Passer NULL comme pointeur de fonction désactive la fonction de rappel enregistrée.

La fonction de rappel enregistrée est appelée par [rtcPointQuery] pour chaque primitive de la géométrie qui intersecte le domaine de requête de point correspondant. La fonction de rappel de type RTCPointQueryFunction reçoit un certain nombre d'arguments via la structure RTCPointQueryFunctionArguments. L'objet de requête est l'objet de requête de point d'origine passé à [rtcPointQuery], usrPtr est un pointeur arbitraire pour passer des entrées et stocker les résultats de la fonction de rappel. Les primID, geomID et context (voir [rtcInitPointQueryContext] pour les détails) peuvent être utilisés pour identifier les données de géométrie de la primitive.

Une RTCPointQueryFunction peut également être passée directement comme argument à [rtcPointQuery]. Dans ce cas, le rappel est appelé pour toutes les primitives de la scène qui intersectent le domaine de requête. Si une fonction de rappel est passée comme argument à [rtcPointQuery] et qu'une fonction de rappel (potentiellement différente) est définie pour une géométrie avec [rtcSetGeometryPointQueryFunction], les deux fonctions de rappel seront appelées et la fonction de rappel passée à [rtcPointQuery] sera appelée avant la fonction de rappel spécifique à la géométrie.

Si l'instanciation est utilisée, le paramètre simliarityScale indique si la transformation d'instance actuelle (élément supérieur de la pile dans le contexte) est une transformation de similarité ou non. Les transformations de similarité sont composées de translation, de rotation et de mise à l'échelle uniforme, et si une matrice M définit une transformation de similarité, il existe un facteur d'échelle D tel que pour tous les x,y : dist(Mx, My) = D * dist(x, y). Dans ce cas, le paramètre scalingFactor est ce facteur d'échelle D et sinon il est de 0. Une échelle de similarité valide (similarityScale > 0) permet de calculer des informations de distance dans l'espace d'instance et de mettre à l'échelle les distances dans l'espace monde (par exemple, pour mettre à jour le rayon de requête, voir ci-dessous) en divisant la distance de l'espace d'instance par l'échelle de similarité. Si la transformation d'instance actuelle n'est pas une transformation de similarité (similarityScale est 0), le calcul de distance doit être effectué dans l'espace monde pour garantir la correction. Dans ce cas, les transformations d'instance vers monde données avec le contexte doivent être utilisées pour transformer les données de la primitive dans l'espace monde. Sinon, l'emplacement de la requête peut être transformé dans l'espace d'instance, ce qui peut être plus efficace. S'il n'y a pas de transformation d'instance, l'échelle de similarité est de 1.

La fonction de rappel sera potentiellement appelée pour des primitives en dehors du domaine de requête pour deux raisons : Premièrement, le rappel est appelé pour toutes les primitives à l'intérieur d'un nœud feuille BVH car aucune donnée de géométrie des primitives n'est déterminée en interne et donc les primitives individuelles ne sont pas élaguées (seulement leurs boîtes englobantes agrégées). Deuxièmement, en cas d'utilisation de transformations non similaires, le domaine de requête ellipsoïdal résultant (en espace d'instance) est approximé par sa boîte englobante alignée sur les axes en interne, et donc les nœuds internes qui n'intersectent pas le domaine d'origine peuvent intersecter la boîte englobante approximative, ce qui entraîne des rappels inutiles. Dans tous les cas, les rappels sont conservateurs, c'est-à-dire que si une primitive se trouve dans le domaine de requête, un rappel sera appelé, mais l'inverse n'est pas nécessairement vrai.

Pour des raisons d'efficacité, le rayon de l'objet de requête peut être diminué (dans l'espace monde) à l'intérieur de la fonction de rappel pour améliorer l'élagage de la géométrie pendant le parcours du BVH. Si le rayon de la requête a été mis à jour, la fonction de rappel doit retourner vrai pour déclencher une mise à jour des informations de parcours internes. Augmenter le rayon ou modifier l'heure ou la position de la requête entraîne un comportement indéfini.

Dans la fonction de rappel, il est sûr d'appeler [rtcPointQuery] à nouveau, par exemple lors de l'implémentation manuelle de l'instanciation. Dans ce cas, la transformation d'instance doit être empilée dans le contexte. Embree calculera en interne les informations de requête de point dans l'espace d'instance en utilisant l'élément supérieur de la pile dans le contexte lorsque [rtcPointQuery] est appelé.

Pour une implémentation de référence d'un parcours de point le plus proche sur des maillages triangulaires utilisant l'instanciation et l'instanciation définie par l'utilisateur, voir le tutoriel [ClosestPoint].
