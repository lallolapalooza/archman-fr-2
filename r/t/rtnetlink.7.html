rtnetlink(7) Manuel d'informations diverses rtnetlink(7)

NOM

rtnetlink - Socket de routage Linux

SYNTAXE

#include <asm/types.h>
#include <linux/netlink.h>
#include <linux/rtnetlink.h>
#include <sys/socket.h>
rtnetlink_socket = socket(AF_NETLINK, int socket_type, NETLINK_ROUTE);

DESCRIPTION

Rtnetlink permet de lire et de modifier les tables de routage du noyau. Il est utilisé au sein du noyau pour communiquer entre différents sous-systèmes, bien que cette utilisation ne soit pas documentée ici, et pour la communication avec les programmes de l'espace utilisateur. Les routes réseau, les adresses IP, les paramètres de liaison, les configurations de voisins, les disciplines de mise en file d'attente, les classes de trafic et les classificateurs de paquets peuvent tous être contrôlés via les sockets NETLINK_ROUTE. Il est basé sur les messages netlink ; voir netlink(7) pour plus d'informations.

Attributs de routage

Certains messages rtnetlink ont des attributs optionnels après l'en-tête initial :


struct rtattr {
    unsigned short rta_len;    /* Longueur de l'option */
    unsigned short rta_type;   /* Type de l'option */
    /* Les données suivent */
};

Ces attributs doivent être manipulés en utilisant uniquement les macros RTA_* ou libnetlink, voir rtnetlink(3).

Messages

Rtnetlink comprend ces types de messages (en plus des messages netlink standard) :

RTM_NEWLINK
RTM_DELLINK
RTM_GETLINK
Créer, supprimer ou obtenir des informations sur une interface réseau spécifique. Ces messages contiennent une structure ifinfomsg suivie d'une série de structures rtattr.
struct ifinfomsg {
    unsigned char  ifi_family; /* AF_UNSPEC */
    unsigned short ifi_type;   /* Type de périphérique */
    int            ifi_index;  /* Index de l'interface */
    unsigned int   ifi_flags;  /* Indicateurs du périphérique */
    unsigned int   ifi_change; /* Masque de changement */
};
ifi_flags contient les indicateurs du périphérique, voir netdevice(7) ; ifi_index est l'index unique de l'interface (depuis Linux 3.7, il est possible de fournir une valeur non nulle avec le message RTM_NEWLINK, créant ainsi une liaison avec l'ifindex donné) ; ifi_change est réservé pour une utilisation future et doit toujours être défini à 0xFFFFFFFF.
Attributs de routage
rta_type Type de valeur Description
IFLA_UNSPEC - non spécifié
IFLA_ADDRESS adresse matérielle adresse L2 de l'interface
IFLA_BROADCAST adresse matérielle adresse de diffusion L2
IFLA_IFNAME chaîne asciiz Nom du périphérique
IFLA_MTU entier non signé MTU du périphérique
IFLA_LINK entier Type de liaison
IFLA_QDISC chaîne asciiz Discipline de mise en file d'attente
IFLA_STATS voir ci-dessous Statistiques de l'interface
IFLA_PERM_ADDRESS adresse matérielle adresse matérielle fournie par le périphérique (depuis Linux 5.5)
Le type de valeur pour IFLA_STATS est struct rtnl_link_stats (struct net_device_stats dans Linux 2.4 et antérieur).
RTM_NEWADDR
RTM_DELADDR
RTM_GETADDR
Ajouter, supprimer ou recevoir des informations sur une adresse IP associée à une interface. Dans Linux 2.2, une interface peut porter plusieurs adresses IP, ceci remplace le concept de périphérique alias dans Linux 2.0. Dans Linux 2.2, ces messages supportent les adresses IPv4 et IPv6. Ils contiennent une structure ifaddrmsg suivie éventuellement d'attributs de routage rtattr.
struct ifaddrmsg {
    unsigned char ifa_family;    /* Type d'adresse */
    unsigned char ifa_prefixlen; /* Longueur du préfixe de l'adresse */
    unsigned char ifa_flags;     /* Indicateurs d'adresse */
    unsigned char ifa_scope;     /* Portée de l'adresse */
    unsigned int  ifa_index;     /* Index de l'interface */
};
ifa_family est le type de famille d'adresses (actuellement AF_INET ou AF_INET6), ifa_prefixlen est la longueur du masque d'adresse de l'adresse si elle est définie pour la famille (comme pour IPv4), ifa_scope est la portée de l'adresse, ifa_index est l'index de l'interface à laquelle l'adresse est associée. ifa_flags est un mot d'indicateurs de IFA_F_SECONDARY pour une adresse secondaire (ancien périphérique alias), IFA_F_PERMANENT pour une adresse permanente définie par l'utilisateur et d'autres indicateurs non documentés.
Attributs
rta_type Type de valeur Description
IFA_UNSPEC - non spécifié
IFA_ADDRESS adresse de protocole brute adresse de l'interface
IFA_LOCAL adresse de protocole brute adresse locale
IFA_LABEL chaîne asciiz nom de l'interface
IFA_BROADCAST adresse de protocole brute adresse de diffusion
IFA_ANYCAST adresse de protocole brute adresse anycast
IFA_CACHEINFO struct ifa_cacheinfo Informations sur l'adresse 
struct ifa_cacheinfo {
    __u32 ifa_prefered; // Durée de vie préférée restante, en secondes
    __u32 ifa_valid;    // Durée de vie valide restante, en secondes
    __u32 cstamp;       // Horodatage de création, en centisecondes
    __u32 tstamp;       // Horodatage de mise à jour, en centisecondes
};
ifa_valid ne peut pas être zéro, et ifa_prefered ne peut pas être supérieur à ifa_valid. Une valeur de UINT32_MAX représente une durée de vie infinie.
RTM_NEWROUTE
RTM_DELROUTE
RTM_GETROUTE
Créer, supprimer ou recevoir des informations sur une route réseau. Ces messages contiennent une structure rtmsg avec une séquence optionnelle de structures rtattr suivant. Pour RTM_GETROUTE, définir rtm_dst_len et rtm_src_len à 0 signifie que vous obtenez toutes les entrées pour la table de routage spécifiée. Pour les autres champs, sauf rtm_table et rtm_protocol, 0 est un joker.
struct rtmsg {
    unsigned char rtm_family;   /* Famille d'adresses de la route */
    unsigned char rtm_dst_len;  /* Longueur de destination */
    unsigned char rtm_src_len;  /* Longueur de source */
    unsigned char rtm_tos;      /* Filtre TOS */
    unsigned char rtm_table;    /* ID de la table de routage ;
                                   voir RTA_TABLE ci-dessous */
    unsigned char rtm_protocol; /* Protocole de routage ; voir ci-dessous */
    unsigned char rtm_scope;    /* Voir ci-dessous */
    unsigned char rtm_type;     /* Voir ci-dessous */
    unsigned int  rtm_flags;
};

rtm_type Type de route
RTN_UNSPEC route inconnue
RTN_UNICAST une passerelle ou une route directe
RTN_LOCAL une route d'interface locale
RTN_BROADCAST une route de diffusion locale (envoyée en broadcast)
RTN_ANYCAST une route de diffusion locale (envoyée en unicast)
RTN_MULTICAST une route multicast
RTN_BLACKHOLE une route qui supprime les paquets
RTN_UNREACHABLE une destination inaccessible
RTN_PROHIBIT une route qui rejette les paquets
RTN_THROW continue la recherche de routage dans une autre table
RTN_NAT une règle de traduction d'adresses réseau
RTN_XRESOLVE se référer à un résolveur externe (non implémenté)
rtm_protocol Origine de la route
RTPROT_UNSPEC inconnu
RTPROT_REDIRECT par une redirection ICMP (actuellement non utilisé)
RTPROT_KERNEL par le noyau
RTPROT_BOOT au démarrage
RTPROT_STATIC par l'administrateur
Les valeurs supérieures à RTPROT_STATIC ne sont pas interprétées par le noyau, elles sont destinées à l'information de l'utilisateur. Elles peuvent être utilisées pour marquer la source d'une information de routage ou pour distinguer entre plusieurs démons de routage. Voir <linux/rtnetlink.h> pour les identifiants de démons de routage déjà attribués.
rtm_scope est la distance à la destination :
RT_SCOPE_UNIVERSE route globale
RT_SCOPE_SITE route intérieure dans le système autonome local
RT_SCOPE_LINK route sur ce lien
RT_SCOPE_HOST route sur l'hôte local
RT_SCOPE_NOWHERE la destination n'existe pas
Les valeurs comprises entre RT_SCOPE_UNIVERSE et RT_SCOPE_SITE sont disponibles pour l'utilisateur.
Les rtm_flags ont les significations suivantes :
RTM_F_NOTIFY si la route change, notifier l'utilisateur via rtnetlink
RTM_F_CLONED la route est clonée à partir d'une autre route
RTM_F_EQUALIZE un égaliseur multipath (pas encore implémenté)
rtm_table spécifie la table de routage
RT_TABLE_UNSPEC une table de routage non spécifiée
RT_TABLE_DEFAULT la table par défaut
RT_TABLE_MAIN la table principale
RT_TABLE_LOCAL la table locale
L'utilisateur peut attribuer des valeurs arbitraires entre RT_TABLE_UNSPEC et RT_TABLE_DEFAULT.

Les métriques verrouillées avec RTAX_LOCK ont la priorité sur les valeurs normalement utilisées par le noyau (calculées ou attribuées via sysctl ou setsockopt(2)). Par conséquent, certaines métriques, comme RTAX_RTO_MIN, n'ont aucun effet sauf si leur bit est défini dans RTAX_LOCK.
RTA_MULTIPATH contient plusieurs instances empaquetées de struct rtnexthop ainsi que des RTA imbriqués (RTA_GATEWAY) :

struct rtnexthop {
    unsigned short rtnh_len;     /* Longueur de la structure + longueur
                                    des RTAs */
    unsigned char  rtnh_flags;   /* Flags (voir
                                    linux/rtnetlink.h) */
    unsigned char  rtnh_hops;    /* Priorité de la prochaine route */
    int            rtnh_ifindex; /* Index de l'interface pour cette
                                    prochaine route */
}

Il existe un ensemble de macros RTNH_* similaires aux macros RTA_* et NLHDR_* utiles pour manipuler ces structures.
struct rtvia {
    unsigned short rtvia_family;
    unsigned char  rtvia_addr[0];
};

rtvia_addr est l'adresse, rtvia_family est son type de famille.
RTA_PREF peut contenir les valeurs ICMPV6_ROUTER_PREF_LOW, ICMPV6_ROUTER_PREF_MEDIUM et ICMPV6_ROUTER_PREF_HIGH définies dans <linux/icmpv6.h>.
RTA_ENCAP_TYPE peut contenir les valeurs LWTUNNEL_ENCAP_MPLS, LWTUNNEL_ENCAP_IP, LWTUNNEL_ENCAP_ILA ou LWTUNNEL_ENCAP_IP6 définies dans <linux/lwtunnel.h>.
Remplissez ces valeurs !
RTM_NEWNEIGH
RTM_DELNEIGH
RTM_GETNEIGH
Ajouter, supprimer ou recevoir des informations sur une entrée de table de voisins (par exemple, une entrée ARP). Le message contient une structure ndmsg.
struct ndmsg {
    unsigned char ndm_family;
    int           ndm_ifindex;  /* Interface index */
    __u16         ndm_state;    /* State */
    __u8          ndm_flags;    /* Flags */
    __u8          ndm_type;
};
struct nda_cacheinfo {
    __u32         ndm_confirmed;
    __u32         ndm_used;
    __u32         ndm_updated;
    __u32         ndm_refcnt;
};
ndm_state est un masque de bits des états suivants :
NUD_INCOMPLETE une entrée de cache en cours de résolution
NUD_REACHABLE une entrée de cache confirmée comme fonctionnelle
NUD_STALE une entrée de cache expirée
NUD_DELAY une entrée en attente d'un timer
NUD_PROBE une entrée de cache en cours de re-sonde
NUD_FAILED une entrée de cache invalide
NUD_NOARP un périphérique sans cache de destination
NUD_PERMANENT une entrée statique
Les ndm_flags valides sont :
NTF_PROXY une entrée proxy arp
NTF_ROUTER un routeur IPv6
La structure rtattr a les significations suivantes pour le champ rta_type :
NDA_UNSPEC type inconnu
NDA_DST une adresse de destination de la couche réseau du cache voisin
NDA_LLADDR une adresse de couche liaison du cache voisin
NDA_CACHEINFO statistiques du cache
Si le champ rta_type est NDA_CACHEINFO, alors une structure struct nda_cacheinfo suit.

RTM_GETRULE

struct tcmsg {
    unsigned char    tcm_family;
    int              tcm_ifindex;   /* interface index */
    __u32            tcm_handle;    /* Qdisc handle */
    __u32            tcm_parent;    /* Parent qdisc */
    __u32            tcm_info;
};
Attributs
rta_type Type de valeur Description
TCA_UNSPEC - non spécifié
TCA_KIND chaîne asciiz Nom de la discipline de mise en file d'attente
TCA_OPTIONS séquence d'octets Les options spécifiques à la discipline de mise en file d'attente suivent
TCA_STATS struct tc_stats Statistiques de la discipline de mise en file d'attente
TCA_XSTATS spécifique à la discipline de mise en file d'attente Statistiques spécifiques au module
TCA_RATE struct tc_estimator Limitation de débit
De plus, divers autres attributs spécifiques au module de discipline de mise en file d'attente sont autorisés. Pour plus d'informations, consultez les fichiers d'en-tête appropriés.
