sigprocmask(2) Manuel des appels système sigprocmask(2)

NOM

sigprocmask, rt_sigprocmask - examiner et modifier les signaux bloqués

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <signal.h>

/* Prototype de la fonction d'encapsulation glibc */
int sigprocmask(int how, const sigset_t *_Nullable restrict set,
                           sigset_t *_Nullable restrict oldset);
#include <signal.h>           /* Définition des constantes SIG_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
/* Prototype de l'appel système sous-jacent */
int syscall(SYS_rt_sigprocmask, int how,
                           const kernel_sigset_t *_Nullable set,
                           kernel_sigset_t *_Nullable oldset,
                           size_t sigsetsize);
/* Prototype de l'appel système hérité */
[[deprecated]] int syscall(SYS_sigprocmask, int how,
                           const old_kernel_sigset_t *_Nullable set,
                           old_kernel_sigset_t *_Nullable oldset);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

sigprocmask() :

    _POSIX_C_SOURCE

DESCRIPTION

sigprocmask() est utilisée pour récupérer et/ou modifier le masque de signaux du thread appelant. Le masque de signaux est l'ensemble des signaux dont la livraison est actuellement bloquée pour l'appelant (voir aussi signal(7) pour plus de détails).

Le comportement de l'appel dépend de la valeur de how, comme suit.

SIG_BLOCK
L'ensemble des signaux bloqués est l'union de l'ensemble actuel et de l'argument set.
SIG_UNBLOCK
Les signaux dans set sont retirés de l'ensemble actuel des signaux bloqués. Il est permis de tenter de débloquer un signal qui n'est pas bloqué.
SIG_SETMASK
L'ensemble des signaux bloqués est défini à l'argument set.

Si oldset n'est pas NULL, la valeur précédente du masque de signaux est stockée dans oldset.

Si set est NULL, alors le masque de signaux n'est pas modifié (c'est-à-dire que how est ignoré), mais la valeur actuelle du masque de signaux est néanmoins retournée dans oldset (s'il n'est pas NULL).

Un ensemble de fonctions pour modifier et inspecter des variables de type sigset_t ("ensembles de signaux") est décrit dans sigsetops(3).

L'utilisation de sigprocmask() n'est pas spécifiée dans un processus multithread ; voir pthread_sigmask(3).

VALEUR DE RETOUR

sigprocmask() retourne 0 en cas de succès. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
L'argument set ou oldset pointe en dehors de l'espace d'adressage alloué du processus.
EINVAL
Soit la valeur spécifiée dans how était invalide, soit le noyau ne prend pas en charge la taille passée dans sigsetsize.

VERSIONS

Différences Bibliothèque C/Noyau

La définition du noyau de sigset_t diffère en taille de celle utilisée par la bibliothèque C. Dans cette page de manuel, la première est appelée kernel_sigset_t (elle est néanmoins nommée sigset_t dans les sources du noyau).

La fonction d'encapsulation glibc pour sigprocmask() ignore silencieusement les tentatives de blocage des deux signaux temps réel utilisés en interne par l'implémentation de threads NPTL. Voir nptl(7) pour les détails.

L'appel système Linux d'origine était nommé sigprocmask(). Cependant, avec l'ajout des signaux temps réel sous Linux 2.2, le type sigset_t de taille fixe de 32 bits (appelé old_kernel_sigset_t dans cette page de manuel) pris en charge par cet appel système n'était plus adapté. Par conséquent, un nouvel appel système, rt_sigprocmask(), a été ajouté pour prendre en charge un type sigset_t élargi (appelé kernel_sigset_t dans cette page de manuel). Le nouvel appel système prend un quatrième argument, size_t sigsetsize, qui spécifie la taille en octets des ensembles de signaux dans set et oldset. Cet argument doit actuellement avoir une valeur fixe spécifique à l'architecture (égale à sizeof(kernel_sigset_t)).

La fonction d'encapsulation glibc sigprocmask() nous cache ces détails, appelant de manière transparente rt_sigprocmask() lorsque le noyau la fournit.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

NOTES

Il n'est pas possible de bloquer SIGKILL ou SIGSTOP. Les tentatives de le faire sont ignorées silencieusement.

Chacun des threads d'un processus a son propre masque de signaux.

Un enfant créé via fork(2) hérite d'une copie du masque de signaux de son parent ; le masque de signaux est préservé lors de execve(2).

Si SIGBUS, SIGFPE, SIGILL ou SIGSEGV sont générés alors qu'ils sont bloqués, le résultat est indéfini, à moins que le signal n'ait été généré par kill(2), sigqueue(3), ou raise(3).

Voir sigsetops(3) pour les détails sur la manipulation des ensembles de signaux.

Notez qu'il est permis (bien que peu utile) de spécifier set et oldset comme NULL.

VOIR AUSSI

kill(2), pause(2), sigaction(2), signal(2), sigpending(2), sigsuspend(2), pthread_sigmask(3), sigqueue(3), sigsetops(3), signal(7)
