rtcOccluded4/8/16(3) Embree Ray Tracing Kernels 4 rtcOccluded4/8/16(3)

NOM

rtcOccluded4/8/16 - trouve les collisions pour un paquet de rayons

SYNOPSIS

#include <embree4/rtcore.h>
void rtcOccluded4(
  const int* valid,
  RTCScene scene,
  struct RTCRay4* ray,
  struct RTCOccludedArguments* args = NULL
);
void rtcOccluded8(
  const int* valid,
  RTCScene scene,
  struct RTCRay8* ray,
  struct RTCOccludedArguments* args = NULL
);
void rtcOccluded16(
  const int* valid,
  RTCScene scene,
  struct RTCRay16* ray,
  struct RTCOccludedArguments* args = NULL
);

DESCRIPTION

Les fonctions rtcOccluded4/8/16 vérifient pour chaque rayon actif du paquet de rayons de taille 4, 8 ou 16 (argument ray) s'il existe une collision avec la scène (argument scene). La structure optionnelle d'arguments passée (argument args) peut être utilisée pour des cas d'utilisation avancés, voir la section [rtcInitOccludedArguments] pour plus de détails. Voir la section [rtcOccluded1] pour plus de détails et une description de la configuration et du traçage des rayons d'occlusion.

Un masque de validité de rayon doit être fourni (argument valid) qui stocke un entier 32 bits (-1 signifie valide et 0 invalide) par rayon dans le paquet. Seuls les rayons actifs sont traités, et les données de collision des rayons inactifs ne sont pas modifiées.

Pour rtcOccluded4, le paquet de rayons doit être aligné sur 16 octets, pour rtcOccluded8 l'alignement doit être de 32 octets, et pour rtcOccluded16 l'alignement doit être de 64 octets.

Les fonctions rtcOccluded4, rtcOccluded8 et rtcOccluded16 peuvent modifier la taille du paquet de rayons et l'ordre des rayons lors des rappels aux fonctions de filtre d'intersection ou aux rappels de géométrie utilisateur. Dans certaines conditions, l'application peut supposer que les paquets restent intacts, ce qui peut être déterminé en interrogeant les propriétés RTC_DEVICE_PROPERTY_NATIVE_RAY4_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY8_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY16_SUPPORTED via la fonction rtcGetDeviceProperty. Voir [rtcGetDeviceProperty] pour plus d'informations.

STATUT DE RETOUR

Pour des raisons de performance, cette fonction n'effectue aucune vérification d'erreur, et ne définit donc aucun drapeau d'erreur en cas d'échec.
