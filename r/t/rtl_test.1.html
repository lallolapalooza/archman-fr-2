NOM

rtl_test - un outil de référence pour les récepteurs DVB-T basés sur RTL2832

DESCRIPTION

Teste la plage de réglage et les fréquences d'échantillonnage fonctionnelles de votre appareil sur votre système. Utilise un récepteur DVB-T réaffecté comme radio définie par logiciel. Écrit pour et intégré au projet osmocom rtl-sdr.

De nombreux logiciels sont disponibles pour le RTL2832. La plupart des paquets de niveau utilisateur s'appuient sur la bibliothèque librtlsdr qui fait partie de la base de code rtl-sdr. Cette base de code contient à la fois la bibliothèque elle-même et un certain nombre d'outils en ligne de commande tels que rtl_test, rtl_sdr, rtl_tcp et rtl_fm. Ces outils en ligne de commande utilisent la bibliothèque pour tester l'existence d'appareils RTL2832 et pour effectuer des fonctions de transfert de données de base vers et depuis l'appareil.

Étant donné que la plupart des appareils RTL2832 sont connectés via USB, la bibliothèque librtlsdr dépend de la bibliothèque libusb pour communiquer avec l'appareil.

SYNTAXE

rtl_test [OPTIONS]

OPTIONS

-s fréquence_échantillon (par défaut : 2048000 Hz)
-d index_appareil (par défaut : 0)
-t active le test de référence du tuner Elonics E4000]
-p mesure l'erreur PPM
-b taille_bloc_sortie (par défaut : 16 * 16384)
-S force la sortie synchrone (par défaut : asynchrone)

EXEMPLES

Pour vérifier la plage de réglage possible (peut varier considérablement de quelques MHz selon l'appareil et la température), appelez

rtl_test -t
Pour vérifier la fréquence d'échantillonnage maximale possible sur votre machine, tapez (diminuez la fréquence jusqu'à ce qu'il n'y ait plus de perte d'échantillons) :

rtl_test -s 3.2e6

Une fréquence d'échantillonnage de 2.4e6 est connue pour fonctionner même sur des connexions tcp (voir rtl_tcp ci-dessus). Une fréquence d'échantillonnage de 2.88e6 peut fonctionner sans perte d'échantillons, mais cela peut dépendre de l'interface hôte de votre PC/ordinateur portable.
