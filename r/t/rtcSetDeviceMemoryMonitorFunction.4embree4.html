NAME

rtcSetDeviceMemoryMonitorFunction - enregistre une fonction de rappel pour suivre la consommation mémoire

SYNOPSIS

#include <embree4/rtcore.h>
typedef bool (*RTCMemoryMonitorFunction)(
  void* userPtr,
  ssize_t bytes,
  bool post
);
void rtcSetDeviceMemoryMonitorFunction(
  RTCDevice device,
  RTCMemoryMonitorFunction memoryMonitor,
  void* userPtr
);

DESCRIPTION

En utilisant l'appel rtcSetDeviceMemoryMonitorFunction, il est possible d'enregistrer une fonction de rappel (argument memoryMonitor) avec une charge utile (argument userPtr) pour un appareil (argument device), qui est appelée chaque fois que la mémoire interne est allouée ou désallouée par des objets de cet appareil. En utilisant ce mécanisme de rappel de moniteur mémoire, l'application peut suivre la consommation mémoire d'un appareil Embree, et éventuellement annuler les appels API qui consomment trop de mémoire.

Une seule fonction de rappel peut être enregistrée par appareil, et les invocations ultérieures écrasent la fonction de rappel précédemment définie. Passer NULL comme pointeur de fonction désactive la fonction de rappel enregistrée.

Une fois enregistrée, l'appareil Embree invoquera la fonction de rappel du moniteur mémoire avant ou après l'allocation ou la libération de blocs mémoire importants. La fonction de rappel reçoit la charge utile telle que spécifiée lors de l'enregistrement (argument userPtr), le nombre d'octets alloués ou libérés (argument bytes), et si le rappel est invoqué après que l'allocation ou la libération a eu lieu (argument post). La fonction de rappel peut être appelée depuis plusieurs threads simultanément.

L'application peut suivre l'utilisation actuelle de la mémoire de l'appareil Embree en accumulant atomiquement le paramètre d'entrée bytes fourni à la fonction de rappel. Ce paramètre sera >0 pour les allocations et <0 pour les désallocations.

Embree continuera son fonctionnement normalement lors du retour de true depuis la fonction de rappel. Si false est retourné, Embree annulera l'opération en cours avec le code d'erreur RTC_ERROR_OUT_OF_MEMORY. L'émission de plusieurs demandes d'annulation à partir de différents threads est autorisée. L'annulation ne se produira que lorsque le rappel a été appelé pour des allocations (bytes > 0), sinon la demande d'annulation sera ignorée.

Si un rappel pour annuler a été invoqué avant que l'allocation ne se produise (post == false), alors le paramètre bytes ne doit pas être accumulé, car l'allocation n'aura jamais lieu. Si le rappel pour annuler a été invoqué après que l'allocation ait eu lieu (post == true), alors le paramètre bytes doit être accumulé, car l'allocation a eu lieu correctement et une désallocation libérera plus tard ce bloc de données.

EXIT STATUS

En cas d'échec, un code d'erreur est défini et peut être interrogé à l'aide de rtcGetDeviceError.
