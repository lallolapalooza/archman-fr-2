NOM

rtl_433 - Récepteur et décodeur de données RF générique pour appareils de bande ISM utilisant RTL-SDR et SoapySDR.

DESCRIPTION

Cette page de manuel documente brièvement la commande rtl_433.

rtl_433 est un récepteur de données générique, principalement pour les bandes ISM de 433,92 MHz, 868 MHz (SRD), 315 MHz et 915 MHz. Il fonctionne avec RTL-SDR et/ou SoapySDR. Les clés USB DVB basées sur RTL2832 (utilisant RTL-SDR) et LimeSDR (échantillons d'ingénierie LimeSDR USB et LimeSDR mini gracieusement fournis par MyriadRf), PlutoSDR, HackRF One (utilisant les pilotes SoapySDR), ainsi que SoapyRemote sont activement testés et pris en charge.

SYNTAXE

rtl_433 [OPTION]... FICHIER...

OPTIONS

Un résumé des options est inclus ci-dessous. Des informations détaillées sur certaines options suivent.


Un fichier "rtl_433.conf" est recherché dans "./", XDG_CONFIG_HOME par ex. "$HOME/.config/rtl_433/",
SYSCONFDIR par ex. "/usr/local/etc/rtl_433/", puis les arguments de ligne de commande seront analysés dans l'ordre.

Options générales

[ -V ]
Affiche la chaîne de version et quitte
[ -v ]
Augmente la verbosité (peut être utilisé plusieurs fois).
-v : avis verbeux, -vv : informations verbeuses, -vvv : débogage, -vvvv : trace.
[ -c <chemin> ]
Lit les options de configuration à partir d'un fichier

Options de syntoniseur

[ -d <index du périphérique USB RTL-SDR> | :<numéro de série du périphérique USB RTL-SDR> | <requête du périphérique SoapySDR> | rtl_tcp | help ]
[-g <gain> | help] (défaut : auto)
[ -t <paramètres> ]
Applique une liste de paramètres clé=valeur au périphérique SDR
par ex. pour SoapySDR -t "antenna=A,bandwidth=4.5M,rfnotch_ctrl=false"
pour RTL-SDR utiliser "direct_samp[=1]", "offset_tune[=1]", "digital_agc[=1]", "biastee[=1]"
[ -f <fréquence> ]
Fréquence(s) de réception (défaut : 433920000 Hz)
[ -H <secondes> ]
Intervalle de saut pour l'interrogation de fréquences multiples (défaut : 600 secondes)
[ -p <erreur ppm> ]
Corrige l'erreur de fréquence du syntoniseur rtl-sdr (défaut : 0)
[ -s <taux d'échantillonnage> ]
Définit le taux d'échantillonnage (défaut : 250000 Hz)
[ -D restart | pause | quit | manual ]
Options de mode d'exécution du périphérique d'entrée.

Options de démodulateur

[ -R <périphérique> | help ]
N'active que le protocole de décodage du périphérique spécifié (peut être utilisé plusieurs fois)
Spécifiez un nombre négatif pour désactiver un protocole de décodage de périphérique (peut être utilisé plusieurs fois)
[ -X <spec> | help ]
Ajoute un décodeur à usage général (précéder de -R 0 pour désactiver tous les décodeurs)
[ -Y auto | classic | minmax ]
Mode du détecteur d'impulsions FSK.
[ -Y level=<niveau dB> ]
Niveau de détection manuel utilisé pour déterminer les impulsions (-1,0 à -30,0) (0=auto).
[ -Y minlevel=<niveau dB> ]
Niveau de détection minimum manuel utilisé pour déterminer les impulsions (-1,0 à -99,0).
[ -Y minsnr=<niveau dB> ]
SNR minimum pour déterminer les impulsions (1,0 à 99,0).
[ -Y autolevel ]
Définit minlevel automatiquement en fonction du bruit moyen estimé.
[ -Y squelch ]
Ignore les trames en dessous du niveau de bruit estimé pour réduire la charge CPU.
[ -Y ampest | magest ]
Choisit l'estimateur de niveau d'amplitude ou de magnitude.

Options d'analyse/débogage

[ -A ]
Analyseur d'impulsions. Active l'analyse d'impulsions et la tentative de décodage.
Désactivez tous les décodeurs avec -R 0 si vous souhaitez uniquement la sortie de l'analyseur.
[ -y <code> ]
Vérifie le décodage des données démodulées (par ex. "{25}fb2dd58") avec les périphériques activés

Options d'entrée/sortie de fichier

[ -S none | all | unknown | known ]
Sauvegarde automatique du signal. Crée un fichier par signal.
Remarque : Sauvegarde les échantillons bruts I/Q (pcm uint8, 2 canaux). Mode préféré pour générer des fichiers de test.
[ -r <nom de fichier> | help ]
Lit les données à partir d'un fichier d'entrée au lieu d'un récepteur
[ -w <nom de fichier> | help ]
Sauvegarde le flux de données dans un fichier de sortie (un '-' envoie les échantillons vers la sortie standard)
[ -W <nom de fichier> | help ]
Sauvegarde le flux de données dans un fichier de sortie, écrase le fichier existant

Options de sortie de données

[ -F log | kv | json | csv | mqtt | influx | syslog | trigger | null | help ]
Produit la sortie décodée dans le format donné.
Ajoute la sortie à un fichier avec :<nom de fichier> (par ex. -F csv:log.csv), la sortie standard par défaut.
Spécifie l'hôte/port pour syslog avec par ex. -F syslog:127.0.0.1:1514
[ -M time[:<options>] | protocol | level | noise[:<secs>] | stats | bits | help ]
Ajoute diverses métadonnées à chaque sortie.
[ -K FILE | PATH | <tag> | <key>=<tag> ]
Ajoute un jeton développé ou une étiquette fixe à chaque ligne de sortie.
[ -C native | si | customary ]
Convertit les unités dans la sortie décodée.
[ -n <valeur> ]
Spécifie le nombre d'échantillons à prendre (chaque échantillon est une paire I/Q)
[ -T <secondes> ]
Spécifie le nombre de secondes d'exécution, également 12:34 ou 1h23m45s
[ -E hop | quit ]
Saute/Arrête après avoir émis un ou plusieurs événements réussis
[ -h ]
Affiche cette aide d'utilisation et quitte
Utilisez -d, -g, -R, -X, -F, -M, -r, -w ou -W sans argument pour plus d'aide

Sélection du périphérique d'entrée

Le pilote de périphérique RTL-SDR est disponible.
[ -d <index du périphérique USB RTL-SDR> ]
(défaut : 0)
[ -d :<numéro de série du périphérique USB RTL-SDR (peut être défini avec rtl_eeprom -s)> ]
Pour définir le gain pour RTL-SDR, utilisez -g <gain> pour définir un gain global en dB.
Le pilote de périphérique SoapySDR est disponible.
[ -d "" ]
Ouvre le périphérique SoapySDR par défaut
[ -d driver=rtlsdr ]
Ouvre par ex. un périphérique SoapySDR spécifique
Pour définir le gain pour SoapySDR, utilisez -g ELEM=val,ELEM=val,... par ex. -g LNA=20,TIA=8,PGA=2 (pour LimeSDR).
[ -d rtl_tcp[:[//]host[:port] ]
(défaut : localhost:1234)
Spécifiez l'hôte/port de connexion avec par ex. -d rtl_tcp:127.0.0.1:1234

Option de gain

[ -g <gain> ]
(défaut : auto)
Pour RTL-SDR : gain en dB ("0" est auto).
Pour SoapySDR : gain en dB pour la distribution automatique ("" est auto), ou une chaîne d'éléments de gain.
Par ex. "LNA=20,TIA=8,PGA=2" pour LimeSDR.

Spécification du décodeur flexible

Utilisez -X <spec> pour ajouter un décodeur flexible à usage général.

<spec> est "clé=valeur[,clé=valeur...]" Les clés courantes sont :

name=<nom> (ou : n=<nom>)
modulation=

DESCRIPTION

rtl_433 is a command-line tool to decode radio protocols from many common, low-cost ISM band, and other radio devices.

This program is a client for the RTL-SDR API (librtlsdr) and other SDR hardware like SoapySDR.

The following sections describe the command line options.

OPTIONS

Device Selection Option

[ -d <device> ]
Use specified SDR device. List available devices with -l.

General Option

[ -h ]
Show help message.
[ -v ]
Increase verbosity.
[ -l ]
List available devices.
[ -C caps ]
Enable various capabilities.
List of capabilities:
  • all: enable all capabilities
  • buffer: enable buffer flushing
  • event: enable event mode (default)
  • file: enable file read mode (for input)
  • gain: enable automatic gain control (AGC)
  • gui: enable GUI features
  • json: enable JSON output
  • log: enable log output (default)
  • noise: enable noise reporting
  • raw: enable raw input data capture
  • repeat: enable repeating of decoded messages
  • stats: enable statistics output
  • syslog: enable syslog logging
  • tcp: enable TCP input/output
  • trace: enable trace output
  • trigger: enable trigger output
  • udp: enable UDP input/output
  • verbose: increase verbosity
  • version: show version information
  • window: enable GUI window handling

Tuning Option

[ -f freq ]
Tune to specified frequency in Hz.
[ -S rate ]
Set sample rate.
[ -g gain ]
Set gain.
[ -p ppm ]
Set tuner PFL.
[ -i ]
Invert IQ data.
[ -T times ]
Set tuner timing.

Protocol Option

[ -X <name>=<value>,... ]
Select and configure decoders.
Options can be specified multiple times, e.g.: -X n=foo -X m=OOK_MC_ZEROBIT.
A decoder is selected by its name (e.g. OOK_MC_ZEROBIT) or a descriptive name tag (e.g. n=doorbell).
Additional options can be specified as name=value pairs.
Supported options are:

  • modulation or m: selects the modulation type. Possible values are:

    • OOK_MC_ZEROBIT: Manchester Code with fixed leading zero bit
    • OOK_PCM: Non Return to Zero coding (Pulse Code)
    • OOK_RZ: Return to Zero coding (Pulse Code)
    • OOK_PPM: Pulse Position Modulation
    • OOK_PWM: Pulse Width Modulation
    • OOK_DMC: Differential Manchester Code
    • OOK_PIWM_RAW: Raw Pulse Interval and Width Modulation
    • OOK_PIWM_DC: Differential Pulse Interval and Width Modulation
    • OOK_MC_OSV1: Manchester Code for OSv1 devices
    • FSK_PCM: FSK Pulse Code Modulation
    • FSK_PWM: FSK Pulse Width Modulation
    • FSK_MC_ZEROBIT: Manchester Code with fixed leading zero bit

  • short or s: nominal modulation timings in us.

    • PCM/RZ short: Nominal width of pulse [us]
    • PPM short: Nominal width of '0' gap [us]
    • PWM short: Nominal width of '1' pulse [us]

  • long or l: nominal modulation timings in us.

    • PCM/RZ long: Nominal width of bit period [us]
    • PPM long: Nominal width of '1' gap [us]
    • PWM long: Nominal width of '0' pulse [us]

  • sync or y: nominal modulation timings in us.

    • sync: Nominal width of sync pulse [us] (optional)

  • reset or r: maximum modulation timings in us.

    • reset: Maximum gap size before End Of Message [us]

  • gap or g: maximum modulation timings in us.

    • gap: Maximum gap size before new row of bits [us]

  • tolerance or t: maximum modulation timings in us.

    • tolerance: Maximum pulse deviation [us] (optional).

  • priority: run decoder only as fallback.

  • bits: only match if at least one row has <n> bits.

  • rows: only match if there are <n> rows.

  • repeats: only match if some row is repeated <n> times.

    • use opt>=n to match at least <n> and opt<=n to match at most <n>.
  • invert: invert all bits.
  • reflect: reflect each byte (MSB first to MSB last).
  • decode_uart: UART 8n1 (10-to-8) decode.
  • decode_dm: Differential Manchester decode.

  • match: only match if the <bits> are found.

  • preamble: match and align at the <bits> preamble.

    • <bits> is a row spec of {<bit count>}<bits as hex number>
  • unique: suppress duplicate row output.
  • countonly: suppress detailed row output.

E.g. -X "n=doorbell,m=OOK_PWM,s=400,l=800,r=7000,g=1000,match={24}0xa9878c,repeats>=3"

Output format option

[ -F log|kv|json|csv|mqtt|influx|syslog|trigger|null ]
Produce decoded output in given format.
Without this option the default is LOG and KV output. Use -F null to remove the default.
Append output to file with :<filename> (e.g. -F csv:log.csv), defaults to stdout.
Specify MQTT server with e.g. -F mqtt://localhost:1883
Default user and password are read from MQTT_USERNAME and MQTT_PASSWORD env vars.
Add MQTT options with e.g. -F "mqtt://host:1883,opt=arg"
MQTT options are: user=foo, pass=bar, retain[=0|1], <format>[=topic]
Supported MQTT formats: (default is all)
  • events: posts JSON event data, default "<base>/events"
  • states: posts JSON state data, default "<base>/states"
  • devices: posts device and sensor info in nested topics, default "<base>/devices[/type][/model][/subtype][/channel][/id]"
A base topic can be set with base=<topic>, default is "rtl_433/HOSTNAME".
Any topic string overrides the base topic and will expand keys like [/model]
E.g. -F "mqtt://localhost:1883,user=USERNAME,pass=PASSWORD,retain=0,devices=rtl_433[/id]"
With MQTT each rtl_433 instance needs a distinct driver selection. The MQTT Client-ID is computed from the driver string.
If you use multiple RTL-SDR, perhaps set a serial and select by that (helps not to get the wrong antenna).
Specify InfluxDB 2.0 server with e.g. -F "influx://localhost:9999/api/v2/write?org=<org>&bucket=<bucket>,token=<authtoken>"
Specify InfluxDB 1.x server with e.g. -F "influx://localhost:8086/write?db=<db>&p=<password>&u=<user>"
  • Additional parameter -M time:unix:usec:utc for correct timestamps in InfluxDB recommended
Specify host/port for syslog with e.g. -F syslog:127.0.0.1:1514

Meta information option

[ -M time[:<options>]|protocol|level|noise[:<secs>]|stats|bits ]
Add various metadata to every output line.
Use "time" to add current date and time meta data (preset for live inputs).
Use "time:rel" to add sample position meta data (preset for read-file and stdin).
Use "time:unix" to show the seconds since unix epoch as time meta data. This is always UTC.
Use "time:iso" to show the time with ISO-8601 format (YYYY-MM-DD"T"hh:mm:ss).
Use "time:off" to remove time meta data.
Use "time:usec" to add microseconds to date time meta data.
Use "time:tz" to output time with timezone offset.
Use "time:utc" to output time in UTC.
(this may also be accomplished by invocation with TZ environment variable set).
"usec" and "utc" can be combined with other options, eg. "time:iso:utc" or "time:unix:usec".
Use "replay[:N]" to replay file inputs at (N-times) realtime.
Use "protocol" / "noprotocol" to output the decoder protocol number meta data.
Use "level" to add Modulation, Frequency, RSSI, SNR, and Noise meta data.
Use "noise[:<secs>]" to report estimated noise level at intervals (default: 10 seconds).
Use "stats[:[<level>][:<interval>]]" to report statistics (default: 600 seconds).
  • level 0: no report, 1: report successful devices, 2: report active devices, 3: report all
Use "bits" to add bit representation to code outputs (for debug).

Read file option

[ -r <filename> ]
Read data from input file instead of a receiver
Parameters are detected from the full path, file name, and extension.
A center frequency is detected as (fractional) number suffixed with 'M',
  • 'Hz', 'kHz', 'MHz', or 'GHz'.
A sample rate is detected as (fractional) number suffixed with 'k',
  • 'sps', 'ksps', 'Msps', or 'Gsps'.
File content and format are detected as parameters, possible options are:
  • 'cu8', 'cs16', 'cf32' ('IQ' implied), and 'am.s16'.
Parameters must be separated by non-alphanumeric chars and are case-insensitive.
Overrides can be prefixed, separated by colon (':')
E.g. default detection by extension: path/filename.am.s16
forced overrides: am:s16:path/filename.ext
Reading from pipes also support format options.
E.g reading complex 32-bit float: CU32:-

Write file option

[ -w <filename> ]
Save data stream to output file (a '-' dumps samples to stdout)
[ -W <filename> ]
Save data stream to output file, overwrite existing file
Parameters are detected from the full path, file name, and extension.
File content and format are detected as parameters, possible options are:
  • 'cu8', 'cs8', 'cs16', 'cf32' ('IQ' implied),
  • 'am.s16', 'am.f32', 'fm.s16', 'fm.f32',
  • 'i.f32', 'q.f32', 'logic.u8', 'ook', and 'vcd'.
Parameters must be separated by non-alphanumeric chars and are case-insensitive.
Overrides can be prefixed, separated by colon (':')
E.g. default detection by extension: path/filename.am.s16
forced overrides: am:s16:path/filename.ext
