rtcInitIntersectArguments(3) Embree Ray Tracing Kernels 4 rtcInitIntersectArguments(3)

NOM

rtcInitIntersectArguments - initialise la structure d'arguments d'intersection

SYNTAXE

#include <embree4/rtcore.h>
enum RTCRayQueryFlags
{
  RTC_RAY_QUERY_FLAG_NONE,
  RTC_RAY_QUERY_FLAG_INCOHERENT,
  RTC_RAY_QUERY_FLAG_COHERENT,
  RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER
};
struct RTCIntersectArguments
{
  enum RTCRayQueryFlags flags;
  enum RTCFeatureFlags feature_mask;
  struct RTCRayQueryContext* context;
  RTCFilterFunctionN filter;
  RTCIntersectFunctionN intersect;
#if RTC_MIN_WIDTH
  float minWidthDistanceFactor;
#endif
};
void rtcInitIntersectArguments(
  struct RTCIntersectArguments* args
);

DESCRIPTION

La fonction rtcInitIntersectArguments initialise la structure d'arguments optionnelle qui peut être passée aux fonctions rtcIntersect1/4/8/16 aux valeurs par défaut. La structure d'arguments doit être utilisée pour les fonctionnalités Embree plus avancées décrites ici.

Le membre flags peut être utilisé pour activer un mode de parcours spécial. L'utilisation du flag RTC_RAY_QUERY_FLAG_INCOHERENT utilise un algorithme de parcours optimisé pour les rayons incohérents (par défaut), tandis que RTC_RAY_QUERY_FLAG_COHERENT utilise un algorithme de parcours optimisé pour les rayons cohérents (par exemple, les rayons de caméra primaires).

Le membre feature_mask doit être utilisé dans SYCL pour activer uniquement les fonctionnalités de ray tracing requises pour rendre une scène donnée. Veuillez consulter la section [RTCFeatureFlags] pour une description plus détaillée.

Le membre context peut être utilisé pour passer un contexte d'intersection optionnel. Il est garanti que le pointeur vers le contexte passé à une requête de rayon est directement passé à toutes les fonctions de rappel. De cette manière, il est possible d'attacher des données arbitraires à la fin du contexte, telles qu'une charge utile par rayon. Veuillez noter que le pointeur de rayon n'est pas garanti d'être passé aux fonctions de rappel, donc la lecture de données supplémentaires à partir du pointeur de rayon passé aux rappels n'est pas possible. Voir la section [rtcInitRayQueryContext] pour plus de détails.

Le membre filter spécifie une fonction de filtre à appeler pour chaque intersection rencontrée. Le support de la fonction de filtre d'arguments doit être activé pour une scène en utilisant le flag de scène RTC_SCENE_FLAG_FILTER_FUNCTION_IN_ARGUMENTS. En cas d'instanciation, cette fonctionnalité doit également être activée pour chaque scène instanciée.

La fonction de filtre d'arguments est appelée pour chaque géométrie pour laquelle elle a été explicitement activée en utilisant la fonction rtcSetGeometryEnableFilterFunctionFromArguments. L'invocation de la fonction de filtre d'arguments peut également être forcée pour chaque géométrie en utilisant le flag de requête de rayon RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER. Cette fonction de filtre d'arguments est appelée comme deuxième étape de filtrage après l'invocation de la fonction de filtre par géométrie. Seuls les rayons ayant passé la première étape de filtrage sont valides dans cette deuxième étape de filtrage. Avoir une telle fonction de filtre par requête de rayon peut être utile pour implémenter des modifications du comportement de la requête, telles que la collecte de toutes les intersections ou l'accumulation des transparences.

Le membre intersect spécifie le rappel de géométrie utilisateur à appeler pour chaque géométrie utilisateur rencontrée lors du parcours. La géométrie utilisateur de rappel spécifiée de cette manière a la préférence sur celle spécifiée dans la géométrie.

La valeur minWidthDistanceFactor contrôle la taille cible des rayons des courbes lorsque la fonctionnalité de largeur minimale est activée. Veuillez consulter la fonction [rtcSetGeometryMaxRadiusScale] pour plus de détails sur la fonctionnalité de largeur minimale.

STATUT DE SORTIE

Aucun code d'erreur n'est défini par cette fonction.
