RTF2RTF(1) Manuel des commandes générales RTF2RTF(1)

NOM

rtf2rtf - programmes pour post-traiter le RTF brut généré par les fichiers de mappage

SYNTAXE

rtf2rtf [options] ..

DESCRIPTION

Cette page de manuel documente brièvement les commandes rtf2rtf. Elle a été écrite pour la distribution Debian GNU/Linux car le programme original n'a pas de page de manuel pour rtf2rtf.

rtf2rtf est un programme destiné à post-traiter le RTF brut généré par les fichiers de mappage.

Il est utilisé par d'autres programmes dans sgml-tools (v1), et normalement, l'utilisateur n'a pas besoin d'utiliser ce programme directement.

Ce qui suit est cité du README dans l'arborescence source.

(Début des citations)

Je ne suis pas fier de ce code. C'est un hack imposé à un hack, imbriqué dans un ou deux autres hacks. Il fonctionne plus ou moins bien pour mes besoins (générer des fichiers .RTF pour WinHelp pour mes documents), mais il pourrait certainement bénéficier d'une refonte/réécriture. Il a commencé comme une simple perturbation du filtre html2html, mais est rapidement devenu laid...

Je blâme sans vergogne le format RTF pour la majeure partie de la complexité ici -- le RTF n'est pas un _langage_ comme LaTeX ou ROFF -- c'est juste un format de fichier. Ainsi, nous ne pouvons pas compter sur RTF pour faire même des choses simples comme "insérer un saut de paragraphe ici seulement si le token précédent n'était pas aussi un saut de paragraphe". Comme le frontend SGML n'a pas de capacités de traitement conditionnel, plusieurs lignes vides dans SGML sont traduites en plusieurs sauts de paragraphe dans RTF. C'est pourquoi nous utilisons un filtre "lex" (rtf2rtf) pour post-traiter le RTF brut généré par les fichiers de mappage.

Encore une fois : j'offre ceci à la communauté Linuxdoc dans l'espoir qu'il sera utile à d'autres et que quelqu'un d'autre pourra aider à compléter les pièces manquantes. Quoi ? Pièces manquantes ? Oui, rappelez-vous que j'ai dit qu'il fonctionnait "assez bien pour mes besoins". Les fichiers de remplacement (généraux, mappage) ont commencé comme les fichiers de remplacement latex. Une grande partie d'entre eux sont toujours les fichiers de remplacement latex. Je n'ai converti que les parties qui sont effectivement utilisées par mes documents. Vos documents pourraient nécessiter une plus grande partie des fichiers à traduire en RTF.

Comme j'utilise ces mappages pour de la documentation réelle, j'ai l'intention de maintenir ce backend, alors envoyez-moi toutes les améliorations -- je coordonnerai avec Greg pour m'assurer qu'elles soient incluses dans la prochaine version officielle.

(Fin des citations)

Les programmes ne prennent pas en charge les options normales de ligne de commande.
