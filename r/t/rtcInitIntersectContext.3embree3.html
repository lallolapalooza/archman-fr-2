rtcInitIntersectContext(3) Embree Ray Tracing Kernels 3 rtcInitIntersectContext(3)

NOM

rtcInitIntersectContext - initialise le contexte d'intersection

SYNOPSIS

#include <embree3/rtcore.h>
enum RTCIntersectContextFlags
{
  RTC_INTERSECT_CONTEXT_FLAG_NONE,
  RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT,
  RTC_INTERSECT_CONTEXT_FLAG_COHERENT,
};
struct RTCIntersectContext
{
  enum RTCIntersectContextFlags flags;
  RTCFilterFunctionN filter;
  #if RTC_MAX_INSTANCE_LEVEL_COUNT > 1
    unsigned int instStackSize;
  #endif
  unsigned int instID[RTC_MAX_INSTANCE_LEVEL_COUNT];
  #if RTC_MIN_WIDTH
    float minWidthDistanceFactor;
  #endif
};
void rtcInitIntersectContext(
  struct RTCIntersectContext* context
);

DESCRIPTION

Un contexte d'intersection par rayon (type RTCIntersectContext) est pris en charge et peut être utilisé pour configurer les drapeaux d'intersection (membre flags), spécifier une fonction de rappel de filtrage (membre filter), spécifier la chaîne d'identifiants de l'instance courante (membres instID et instStackSize), et pour attacher des données arbitraires à la requête (par exemple, des données par rayon).

La fonction rtcInitIntersectContext initialise le contexte avec des valeurs par défaut et doit être appelée pour initialiser chaque contexte d'intersection. Cette fonction est intégrée (inlined), ce qui minimise la surcharge et permet des optimisations du compilateur.

Le drapeau du contexte d'intersection peut être utilisé pour affiner le comportement de l'algorithme de parcours. L'utilisation du drapeau RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT utilise un algorithme de parcours optimisé pour les rayons incohérents (par défaut), tandis que RTC_INTERSECT_CONTEXT_FLAG_COHERENT utilise un algorithme de parcours optimisé pour les rayons cohérents (par exemple, les rayons de caméra primaires).

Les meilleures performances pour les rayons primaires peuvent être obtenues en utilisant l'API de flux de rayons et en définissant le drapeau du contexte d'intersection à RTC_INTERSECT_CONTEXT_FLAG_COHERENT. Pour les rayons secondaires, il est généralement préférable d'utiliser le drapeau RTC_INTERSECT_CONTEXT_FLAG_INCOHERENT, à moins que les rayons ne soient également connus pour être très cohérents (par exemple, pour les rayons de transparence primaires).

Une fonction de filtrage peut être spécifiée dans le contexte. Cette fonction de filtrage est appelée comme deuxième étape de filtrage après que la fonction de filtrage d'intersection ou d'occlusion par géométrie soit appelée. Seuls les rayons ayant passé la première étape de filtrage sont valides dans cette deuxième étape de filtrage. Avoir une telle fonction de filtrage par requête peut être utile pour implémenter des modifications du comportement de la requête, comme la collecte de tous les succès ou l'accumulation de transparences. La prise en charge de la fonction de filtrage de contexte doit être activée pour une scène en utilisant le drapeau de scène RTC_SCENE_FLAG_CONTEXT_FILTER_FUNCTION. En cas d'instanciation, cette fonctionnalité doit également être activée pour chaque scène instanciée.

La valeur minWidthDistanceFactor contrôle la taille cible des rayons des courbes lorsque la fonctionnalité min-width est activée. Veuillez consulter la fonction [rtcSetGeometryMaxRadiusScale] pour plus de détails sur la fonctionnalité min-width.

Il est garanti que le pointeur vers le contexte d'intersection passé à une requête de rayon est directement passé aux fonctions de rappel enregistrées. De cette manière, il est possible d'attacher des données arbitraires à la fin du contexte d'intersection, telles qu'une charge utile par rayon.

Veuillez noter que le pointeur de rayon n'est pas garanti d'être passé aux fonctions de rappel, il n'est donc pas possible de lire des données supplémentaires à partir du pointeur de rayon passé aux rappels.

STATUT DE RÉTOR

Aucun code d'erreur n'est défini par cette fonction.
