rtcOccluded4/8/16(3) Embree Ray Tracing Kernels 3 rtcOccluded4/8/16(3)

NOM

rtcOccluded4/8/16 - trouve toute intersection pour un paquet de rayons

SYNTAXE

#include <embree3/rtcore.h>
void rtcOccluded4(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay4* ray
);
void rtcOccluded8(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay8* ray
);
void rtcOccluded16(
  const int* valid,
  RTCScene scene,
  struct RTCIntersectContext* context,
  struct RTCRay16* ray
);

DESCRIPTION

Les fonctions rtcOccluded4/8/16 vérifient pour chaque rayon actif du paquet de rayons de taille 4, 8 ou 16 (argument ray) s'il existe une intersection avec la scène (argument scene). Voir Section [rtcOccluded1] pour une description de la manière de configurer et de tracer des rayons d'occlusion.

Un masque de validité de rayon doit être fourni (argument valid) qui stocke un entier de 32 bits (-1 signifie valide et 0 invalide) par rayon dans le paquet. Seuls les rayons actifs sont traités, et les données d'intersection des rayons inactifs ne sont pas modifiées.

L'implémentation de ces fonctions garantit d'invoquer les fonctions de rappel avec toujours la même taille de paquet de rayons et le même ordre de rayons que spécifié initialement.

Pour rtcOccluded4, le paquet de rayons doit être aligné sur 16 octets, pour rtcOccluded8 l'alignement doit être de 32 octets, et pour rtcOccluded16 l'alignement doit être de 64 octets.

Les fonctions rtcOccluded4, rtcOccluded8 et rtcOccluded16 peuvent changer la taille du paquet de rayons et l'ordre des rayons lors des rappels aux fonctions de filtre d'intersection ou aux rappels de géométrie utilisateur. Dans certaines conditions, l'application peut supposer que les paquets restent intacts, ce qui peut être déterminé en interrogeant les propriétés RTC_DEVICE_PROPERTY_NATIVE_RAY4_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY8_SUPPORTED, RTC_DEVICE_PROPERTY_NATIVE_RAY16_SUPPORTED via la fonction rtcGetDeviceProperty. Voir [rtcGetDeviceProperty] pour plus d'informations.

STATUT DE SORTIE

Pour des raisons de performance, cette fonction n'effectue aucune vérification d'erreur et ne définira donc aucun indicateur d'erreur en cas d'échec.
