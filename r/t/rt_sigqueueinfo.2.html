rt_sigqueueinfo(2) Manuel des appels système rt_sigqueueinfo(2)

NOM

rt_sigqueueinfo, rt_tgsigqueueinfo - mettre en file d'attente un signal et des données

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/signal.h>     /* Définition des constantes SI_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_rt_sigqueueinfo, pid_t tgid,
            int sig, siginfo_t *info);
int syscall(SYS_rt_tgsigqueueinfo, pid_t tgid, pid_t tid,
            int sig, siginfo_t *info);

Note : Il n'y a pas de fonctions d'enveloppement glibc pour ces appels système ; voir NOTES.

DESCRIPTION

Les appels système rt_sigqueueinfo() et rt_tgsigqueueinfo() sont les interfaces de bas niveau utilisées pour envoyer un signal et des données à un processus ou un thread. Le récepteur du signal peut obtenir les données associées en établissant un gestionnaire de signaux avec le drapeau SA_SIGINFO de sigaction(2).

Ces appels système ne sont pas destinés à une utilisation directe par les applications ; ils sont fournis pour permettre l'implémentation de sigqueue(3) et pthread_sigqueue(3).

L'appel système rt_sigqueueinfo() envoie le signal sig au groupe de threads dont l'identifiant est tgid. (Le terme « groupe de threads » est synonyme de « processus », et tgid correspond à l'identifiant de processus UNIX traditionnel.) Le signal sera délivré à un membre arbitraire du groupe de threads (c'est-à-dire à l'un des threads qui ne bloque pas actuellement le signal).

L'argument info spécifie les données à accompagner le signal. Cet argument est un pointeur vers une structure de type siginfo_t, décrite dans sigaction(2) (et définie en incluant <sigaction.h>). L'appelant doit définir les champs suivants dans cette structure :

si_code
Il doit s'agir de l'un des codes SI_* du fichier source du noyau Linux include/asm-generic/siginfo.h. Si le signal est envoyé à un autre processus que l'appelant, les restrictions suivantes s'appliquent :
•
Le code ne peut pas être une valeur supérieure ou égale à zéro. En particulier, il ne peut pas être SI_USER, qui est utilisé par le noyau pour indiquer un signal envoyé par kill(2), ni SI_KERNEL, qui est utilisé pour indiquer un signal généré par le noyau.
•
Le code ne peut pas (depuis Linux 2.6.39) être SI_TKILL, qui est utilisé par le noyau pour indiquer un signal envoyé à l'aide de tgkill(2).
si_pid
Il doit être défini à un identifiant de processus, typiquement l'identifiant du processus expéditeur.
si_uid
Il doit être défini à un identifiant d'utilisateur, typiquement l'identifiant réel de l'utilisateur de l'expéditeur.
si_value
Ce champ contient les données utilisateur à accompagner le signal. Pour plus d'informations, voir la description du dernier argument (union sigval) de sigqueue(3).

En interne, le noyau définit le champ si_signo à la valeur spécifiée dans sig, de sorte que le récepteur du signal puisse également obtenir le numéro de signal via ce champ.

L'appel système rt_tgsigqueueinfo() est similaire à rt_sigqueueinfo(), mais envoie le signal et les données au thread unique spécifié par la combinaison de tgid, un identifiant de groupe de threads, et tid, un thread de ce groupe de threads.

VALEUR DE RETOUR

En cas de succès, ces appels système renvoient 0. En cas d'erreur, ils renvoient -1 et errno est défini pour indiquer l'erreur.

ERREURS

EAGAIN
La limite des signaux qui peuvent être mis en file d'attente a été atteinte. (Voir signal(7) pour plus d'informations.)
EINVAL
sig, tgid, ou tid était invalide.
EPERM
L'appelant n'a pas la permission d'envoyer le signal à la cible. Pour les permissions requises, voir kill(2).
EPERM
tgid spécifie un processus autre que l'appelant et info->si_code est invalide.
ESRCH
rt_sigqueueinfo() : Aucun groupe de threads correspondant à tgid n'a été trouvé.

rt_tgsigqueinfo() : Aucun thread correspondant à tgid et tid n'a été trouvé.

NORMES

Linux.

HISTORIQUE

rt_sigqueueinfo()
Linux 2.2.
rt_tgsigqueueinfo()
Linux 2.6.31.

NOTES

Comme ces appels système ne sont pas destinés à l'usage des applications, il n'y a pas de fonctions d'enveloppement glibc ; utilisez syscall(2) dans le cas improbable où vous voudriez les appeler directement.

Comme avec kill(2), le signal nul (0) peut être utilisé pour vérifier si le processus ou le thread spécifié existe.

VOIR AUSSI

kill(2), pidfd_send_signal(2), sigaction(2), sigprocmask(2), tgkill(2), pthread_sigqueue(3), sigqueue(3), signal(7)

NAME

rt_sigqueueinfo - send a signal to a process

SYNOPSIS

#include <signal.h>

int rt_sigqueueinfo(pid_t pid, int sig, siginfo_t *info);

DESCRIPTION

The rt_sigqueueinfo() system call sends the signal sig to the process pid. Unlike kill(2), this call allows the sender to specify the reason for the signal by passing a pointer to a siginfo_t structure in the info argument. If info is NULL, the signal is sent with a default siginfo_t structure, where si_signo is set to sig, si_code is set to SI_QUEUE, and si_pid is set to the PID of the sending process.

The siginfo_t structure is defined as follows:

typedef struct siginfo {
                    int      si_signo;    /* Signal number */
                    int      si_errno;    /* If non-zero, an error value associated with this signal */
                    int      si_code;     /* Signal code */
                    pid_t    si_pid;      /* Sending process ID */
                    uid_t    si_uid;      /* Real user ID of sending process */
                    void     *si_addr;    /* Address associated with signal (if any) */
                    int      si_status;   /* Exit value or signal number */
                    sigval_t si_value;    /* Signal value (pid, or other data) */
                    /* ... more fields ... */
                } siginfo_t;

The si_code field specifies the reason for the signal. Common values include:

  • SI_USER: Signal sent by kill(2).
  • SI_KERNEL: Signal generated by the kernel.
  • SI_QUEUE: Signal sent by rt_sigqueueinfo().
  • SI_TIMER: Signal sent by expiration of a timer set by timer_create(2).
  • SI_MESGQ: Signal notified by a message queue (mq_notify(3)).
  • SI_ASYNCIO: Signal sent by a completed asynchronous I/O operation.
  • SI_CHILD: Signal sent by a child process (waitid(2)).

The pid argument specifies the target process. If pid is 0, the signal is sent to all processes in the calling process's process group.

The sig argument specifies the signal to be sent. This must be a signal number for which the process has a signal handler or for which the signal disposition is not set to ignore.

The info argument is a pointer to a siginfo_t structure containing information about the signal being sent. The fields si_signo, si_code, and si_pid are set by the caller. Other fields may be set depending on the value of si_code.

RETURN VALUE

On success, rt_sigqueueinfo() returns 0. On error, it returns -1, and errno is set to indicate the error.

ERRORS

  • EAGAIN: No more processes can be created.
  • EINVAL: An invalid signal was specified.
  • EPERM: The sending process does not have permission to send the signal to the target process.
  • ESRCH: The target process or process group does not exist.

STANDARDS

This system call is part of the POSIX real-time extensions.

HISTORY

This system call was introduced in Linux kernel 2.2.

NOTES

This system call is a more powerful version of kill(2) because it allows the sender to provide more information about the signal being sent.

The siginfo_t structure is used by the signal handling mechanism to provide detailed information about the signal that has been received.

SEE ALSO

kill(2), sigaction(2), sigprocmask(2), sigsuspend(2), sigwaitinfo(2)

NOM

rt_sigqueueinfo - envoyer un signal à un processus

SYNTAXE

#include <signal.h>

int rt_sigqueueinfo(pid_t pid, int sig, siginfo_t *info);

DESCRIPTION

L'appel système rt_sigqueueinfo() envoie le signal sig au processus pid. Contrairement à kill(2), cet appel permet à l'expéditeur de spécifier la raison du signal en passant un pointeur vers une structure siginfo_t dans l'argument info. Si info est NULL, le signal est envoyé avec une structure siginfo_t par défaut, où si_signo est défini sur sig, si_code est défini sur SI_QUEUE, et si_pid est défini sur le PID du processus expéditeur.

La structure siginfo_t est définie comme suit :

typedef struct siginfo {
                    int      si_signo;    /* Numéro du signal */
                    int      si_errno;    /* Si non nul, une valeur d'erreur associée à ce signal */
                    int      si_code;     /* Code du signal */
                    pid_t    si_pid;      /* ID du processus expéditeur */
                    uid_t    si_uid;      /* ID utilisateur réel du processus expéditeur */
                    void     *si_addr;    /* Adresse associée au signal (si applicable) */
                    int      si_status;   /* Valeur de sortie ou numéro de signal */
                    sigval_t si_value;    /* Valeur du signal (pid, ou autres données) */
                    /* ... champs supplémentaires ... */
                } siginfo_t;

Le champ si_code spécifie la raison du signal. Les valeurs courantes incluent :

  • SI_USER : Signal envoyé par kill(2).
  • SI_KERNEL : Signal généré par le noyau.
  • SI_QUEUE : Signal envoyé par rt_sigqueueinfo().
  • SI_TIMER : Signal envoyé par l'expiration d'un timer défini par timer_create(2).
  • SI_MESGQ : Signal notifié par une file de messages (mq_notify(3)).
  • SI_ASYNCIO : Signal envoyé par une opération d'E/S asynchrone terminée.
  • SI_CHILD : Signal envoyé par un processus enfant (waitid(2)).

L'argument pid spécifie le processus cible. Si pid est 0, le signal est envoyé à tous les processus du groupe de processus du processus appelant.

L'argument sig spécifie le signal à envoyer. Il doit s'agir d'un numéro de signal pour lequel le processus a un gestionnaire de signaux ou dont la disposition de signal n'est pas définie sur ignorer.

L'argument info est un pointeur vers une structure siginfo_t contenant des informations sur le signal envoyé. Les champs si_signo, si_code, et si_pid sont définis par l'appelant. D'autres champs peuvent être définis en fonction de la valeur de si_code.

VALEUR DE RETOUR

En cas de succès, rt_sigqueueinfo() retourne 0. En cas d'erreur, il retourne -1, et errno est défini pour indiquer l'erreur.

ERREURS

  • EAGAIN : Aucun autre processus ne peut être créé.
  • EINVAL : Un signal invalide a été spécifié.
  • EPERM : Le processus expéditeur n'a pas la permission d'envoyer le signal au processus cible.
  • ESRCH : Le processus ou groupe de processus cible n'existe pas.

NORMES

Cet appel système fait partie des extensions temps réel POSIX.

HISTORIQUE

Cet appel système a été introduit dans le noyau Linux 2.2.

NOTES

Cet appel système est une version plus puissante de kill(2) car il permet à l'expéditeur de fournir plus d'informations sur le signal envoyé.

La structure siginfo_t est utilisée par le mécanisme de gestion des signaux pour fournir des informations détaillées sur le signal reçu.

VOIR AUSSI

kill(2), sigaction(2), sigprocmask(2), sigsuspend(2), sigwaitinfo(2)
