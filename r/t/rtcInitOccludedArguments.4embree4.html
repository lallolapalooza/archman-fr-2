rtcInitOccludedArguments(3) Embree Ray Tracing Kernels 4 rtcInitOccludedArguments(3)

NOM

rtcInitOccludedArguments - initialise la structure des arguments d'occlusion

SYNTAXE

#include <embree4/rtcore.h>
enum RTCRayQueryFlags
{
  RTC_RAY_QUERY_FLAG_NONE,
  RTC_RAY_QUERY_FLAG_INCOHERENT,
  RTC_RAY_QUERY_FLAG_COHERENT,
  RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER
};
struct RTCOccludedArguments
{
  enum RTCRayQueryFlags flags;
  enum RTCFeatureFlags feature_mask;
  struct RTCRayQueryContext* context;
  RTCFilterFunctionN filter;
  RTCOccludedFunctionN intersect;
#if RTC_MIN_WIDTH
  float minWidthDistanceFactor;
#endif
};
void rtcInitOccludedArguments(
  struct RTCOccludedArguments* args
);

DESCRIPTION

La fonction rtcInitOccludedArguments initialise la structure d'arguments optionnelle qui peut être passée aux fonctions rtcOccluded1/4/8/16 à leurs valeurs par défaut. La structure d'arguments doit être utilisée pour les fonctionnalités avancées d'Embree décrites ici.

Le membre flags peut être utilisé pour activer des modes de parcours spéciaux. L'utilisation de l'indicateur RTC_RAY_QUERY_FLAG_INCOHERENT utilise un algorithme de parcours optimisé pour les rayons incohérents (par défaut), tandis que RTC_RAY_QUERY_FLAG_COHERENT utilise un algorithme de parcours optimisé pour les rayons cohérents (par exemple, les rayons de caméra primaires).

Le membre feature_mask doit être utilisé en SYCL pour activer uniquement les fonctionnalités de lancer de rayons requises pour rendre une scène donnée. Veuillez consulter la section [RTCFeatureFlags] pour une description plus détaillée.

Le membre context peut être utilisé pour passer un contexte d'intersection optionnel. Il est garanti que le pointeur vers le contexte passé à une requête de rayon est directement passé à toutes les fonctions de rappel. Il est ainsi possible d'attacher des données arbitraires à la fin du contexte, comme une charge utile par rayon. Veuillez noter que le pointeur de rayon n'est pas garanti d'être passé aux fonctions de rappel, il n'est donc pas possible de lire des données supplémentaires à partir du pointeur de rayon passé aux rappels. Voir la section [rtcInitRayQueryContext] pour plus de détails.

Le membre filter spécifie une fonction de filtre à invoquer pour chaque intersection rencontrée. La prise en charge de la fonction de filtre d'arguments doit être activée pour une scène en utilisant l'indicateur de scène RTC_SCENE_FLAG_FILTER_FUNCTION_IN_ARGUMENTS. En cas d'instanciation, cette fonctionnalité doit également être activée pour chaque scène instanciée.

La fonction de filtre d'arguments est invoquée pour chaque géométrie pour laquelle elle a été explicitement activée à l'aide de la fonction rtcSetGeometryEnableFilterFunctionFromArguments. L'invocation de la fonction de filtre d'arguments peut également être forcée pour chaque géométrie en utilisant l'indicateur de requête de rayon RTC_RAY_QUERY_FLAG_INVOKE_ARGUMENT_FILTER. Cette fonction de filtre d'arguments est invoquée comme deuxième étape de filtrage après l'invocation de la fonction de filtre par géométrie. Seuls les rayons qui ont passé la première étape de filtrage sont valides dans cette deuxième étape de filtrage. Avoir une telle fonction de filtre par requête de rayon peut être utile pour implémenter des modifications du comportement de la requête, telles que la collecte de toutes les intersections ou l'accumulation de transparences.

Le membre intersect spécifie le rappel de géométrie utilisateur à invoquer pour chaque géométrie utilisateur rencontrée pendant le parcours. Le rappel de géométrie utilisateur spécifié de cette manière a la préférence sur celui spécifié à l'intérieur de la géométrie.

La valeur minWidthDistanceFactor contrôle la taille cible des rayons des courbes lorsque la fonctionnalité de largeur minimale est activée. Veuillez consulter la fonction [rtcSetGeometryMaxRadiusScale] pour plus de détails sur la fonctionnalité de largeur minimale.

CODE DE SORTIE

Aucun code d'erreur n'est défini par cette fonction.
