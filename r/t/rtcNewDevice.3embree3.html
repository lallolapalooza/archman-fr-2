rtcNewDevice(3) Embree Ray Tracing Kernels 3 rtcNewDevice(3)

NOM

rtcNewDevice - crée un nouveau périphérique

SYNTAXE

#include <embree3/rtcore.h>
RTCDevice rtcNewDevice(const char* config);

DESCRIPTION

Cette fonction crée un nouveau périphérique et renvoie un pointeur vers ce périphérique. L'objet périphérique est référencé, avec un compteur de références initial de 1. Le pointeur peut être libéré en utilisant l'appel API rtcReleaseDevice.

L'objet périphérique agit comme une fabrique de classes pour tous les autres types d'objets. Tous les objets créés à partir du périphérique (comme les scènes, les géométries, etc.) détiennent une référence vers le périphérique, par conséquent le périphérique ne sera pas détruit à moins que ces objets ne soient détruits en premier.

Les objets ne sont compatibles que s'ils appartiennent au même périphérique, par exemple, il n'est pas permis de créer une géométrie dans un périphérique et de l'attacher à une scène créée avec un périphérique différent.

Une chaîne de configuration (argument config) peut être passée à la construction du périphérique. Cette chaîne de configuration peut être NULL pour utiliser la configuration par défaut.

La configuration suivante est supportée :

•
threads=[int] : Spécifie un nombre de threads de construction à utiliser. Une valeur de 0 active tous les threads matériels détectés. Par défaut, tous les threads matériels sont utilisés.
•
user_threads=[int] : Définit le nombre de threads utilisateur qui peuvent être utilisés pour rejoindre et participer à un commit de scène avec rtcJoinCommitScene. Le système de tâches n'utilisera que threads-user_threads threads de travail, donc si l'application souhaite utiliser uniquement ses threads pour commiter des scènes, il suffit de définir threads égal à user_threads. Cette option n'a d'effet qu'avec le système de tâches Intel(R) Threading Building Blocks (TBB).
•
set_affinity=[0/1] : Lorsqu'il est activé, les threads de construction sont affichés sur les threads matériels. Cette option est désactivée par défaut sur les CPU standards, et activée par défaut sur les processeurs Xeon Phi.
•
start_threads=[0/1] : Lorsqu'il est activé, les threads de construction sont lancés à l'avance. Cela peut être utile pour les benchmarks afin d'exclure le temps de création des threads. Cette option est désactivée par défaut.
•
isa=[sse2,sse4.2,avx,avx2,avx512] : Utilise l'ISA spécifiée. Par défaut, l'ISA est sélectionnée automatiquement.
•
max_isa=[sse2,sse4.2,avx,avx2,avx512] : Configure la sélection automatique de l'ISA pour utiliser au maximum l'ISA spécifiée.
•
hugepages=[0/1] : Active ou désactive l'utilisation des pages géantes. Sous Linux, les pages géantes sont utilisées par défaut, mais sous Windows et macOS, elles sont désactivées par défaut.
•
enable_selockmemoryprivilege=[0/1] : Lorsqu'il est défini sur 1, cela active le privilège SeLockMemoryPrivilege requis pour utiliser les pages géantes sous Windows. Cette option n'a d'effet que sous Windows et est ignorée sur les autres plateformes. Voir la section [Support des pages géantes] pour plus de détails.
•
verbose=[0,1,2,3] : Définit le niveau de verbosité de la sortie. Lorsqu'il est défini sur 0, aucune sortie n'est imprimée par Embree, lorsqu'il est défini sur un niveau plus élevé, plus de sortie est imprimée. Par défaut, Embree n'imprime rien sur la console.
•
frequency_level=[simd128,simd256,simd512] : Spécifie le niveau de fréquence sur lequel l'application souhaite fonctionner, qui peut être :
a)
simd128 pour fonctionner à la fréquence la plus élevée
b)
simd256 pour fonctionner au niveau de fréquence AVX2 intensif
c)
simd512 pour fonctionner au niveau de fréquence AVX512 intensif. Lorsqu'un niveau de fréquence est spécifié, Embree évitera de faire des optimisations qui pourraient réduire le niveau de fréquence en dessous du niveau spécifié. Par exemple, si votre application n'utilise pas d'instructions AVX, définir “frequency_level=simd128” amènera certains CPU à fonctionner à la fréquence la plus élevée, ce qui pourrait entraîner des performances d'application plus élevées si vous faites beaucoup d'ombrage. Si votre application utilise intensément du code AVX, il est préférable de définir le niveau de fréquence sur simd256. Par défaut, Embree essaie d'éviter de réduire la fréquence du CPU en définissant le niveau simd256 uniquement lorsque le CPU n'a pas de réduction significative de fréquence.

Différentes options de configuration doivent être séparées par des virgules, par exemple :

rtcNewDevice("threads=1,isa=avx");

STATUT DE SORTIE

En cas de succès, renvoie un pointeur vers le périphérique créé. En cas d'échec, renvoie NULL en tant que périphérique et définit un code d'erreur par thread qui peut être interrogé en utilisant rtcGetDeviceError(NULL).

VOIR AUSSI

[rtcRetainDevice], [rtcReleaseDevice]
