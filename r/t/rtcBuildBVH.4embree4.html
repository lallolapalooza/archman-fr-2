NAME

rtcBuildBVH - construit un BVH

SYNOPSIS

#include <embree4/rtcore.h>
struct RTC_ALIGN(32) RTCBuildPrimitive
{
  float lower_x, lower_y, lower_z; 
  unsigned int geomID;
  float upper_x, upper_y, upper_z;
  unsigned int primID;
};
typedef void* (*RTCCreateNodeFunction) (
  RTCThreadLocalAllocator allocator,
  unsigned int childCount,
  void* userPtr
);
typedef void (*RTCSetNodeChildrenFunction) (
  void* nodePtr,
  void** children,
  unsigned int childCount,
  void* userPtr
);
typedef void (*RTCSetNodeBoundsFunction) (
  void* nodePtr,
  const struct RTCBounds** bounds,
  unsigned int childCount,
  void* userPtr
);
typedef void* (*RTCCreateLeafFunction) (
  RTCThreadLocalAllocator allocator,
  const struct RTCBuildPrimitive* primitives,
  size_t primitiveCount,
  void* userPtr
);
typedef void (*RTCSplitPrimitiveFunction) (
  const struct RTCBuildPrimitive* primitive,
  unsigned int dimension,
  float position,
  struct RTCBounds* leftBounds,
  struct RTCBounds* rightBounds,
  void* userPtr
);
typedef bool (*RTCProgressMonitorFunction)(
  void* userPtr, double n
);
enum RTCBuildFlags
{
  RTC_BUILD_FLAG_NONE,
  RTC_BUILD_FLAG_DYNAMIC
};
struct RTCBuildArguments
{
  size_t byteSize;
  enum RTCBuildQuality buildQuality;
  enum RTCBuildFlags buildFlags;
  unsigned int maxBranchingFactor;
  unsigned int maxDepth;
  unsigned int sahBlockSize;
  unsigned int minLeafSize;
  unsigned int maxLeafSize;
  float traversalCost;
  float intersectionCost;
  RTCBVH bvh;
  struct RTCBuildPrimitive* primitives;
  size_t primitiveCount;
  size_t primitiveArrayCapacity;
  RTCCreateNodeFunction createNode;
  RTCSetNodeChildrenFunction setNodeChildren;
  RTCSetNodeBoundsFunction setNodeBounds;
  RTCCreateLeafFunction createLeaf;
  RTCSplitPrimitiveFunction splitPrimitive;
  RTCProgressMonitorFunction buildProgress;
  void* userPtr;
};
struct RTCBuildArguments rtcDefaultBuildArguments();
void* rtcBuildBVH(
  const struct RTCBuildArguments* args
);

DESCRIPTION

La fonction rtcBuildBVH peut être utilisée pour construire un BVH dans un format défini par l'utilisateur sur des primitives arbitraires. Tous les arguments de la fonction sont fournis via la structure RTCBuildArguments. Le premier membre de cette structure doit être défini comme étant la taille de la structure en octets (membre bytesSize), ce qui permet des extensions futures de la structure. Il est recommandé d'initialiser la structure des arguments de construction en utilisant la fonction rtcDefaultBuildArguments.

La fonction rtcBuildBVH reçoit le BVH à construire (membre bvh), le tableau de primitives (membre primitives), la capacité de ce tableau (membre primitiveArrayCapacity), le nombre de primitives stockées dans le tableau (membre primitiveCount), des pointeurs de fonction de rappel et un pointeur défini par l'utilisateur (membre userPtr) qui est passé à toutes les fonctions de rappel lorsqu'elles sont invoquées. Le tableau de primitives peut être libéré par l'application après la construction du BVH. Toutes les fonctions de rappel sont généralement appelées depuis plusieurs threads, leur implémentation doit donc être thread-safe.

Quatre fonctions de rappel doivent être enregistrées, qui sont invoquées pendant la construction pour créer les nœuds BVH (membre createNode), pour définir les pointeurs vers tous les enfants (membre setNodeChildren), pour définir les boîtes englobantes de tous les enfants (membre setNodeBounds), et pour créer un nœud feuille (membre createLeaf).

Le pointeur de fonction pour la fonction de découpage de primitives (membre splitPrimitive) peut être NULL, cependant, dans ce cas, aucun découpage spatial en mode de haute qualité n'est possible. Le pointeur de fonction utilisé pour signaler la progression de la construction (membre buildProgress) est facultatif et peut également être NULL.

De plus, certains paramètres de construction sont transmis pour configurer la construction du BVH. En utilisant les paramètres de qualité de construction (membre buildQuality), on peut choisir entre une construction rapide de faible qualité, adaptée aux scènes dynamiques, et une construction de qualité standard pour les scènes statiques. On peut également spécifier le facteur de branchement maximal désiré du BVH (membre maxBranchingFactor), la profondeur maximale que le BVH devrait avoir (membre maxDepth), la taille de bloc pour l'heuristique SAH (membre sahBlockSize), la taille minimale et maximale des feuilles (membres minLeafSize et maxLeafSize), et les coûts estimés d'une étape de parcours et d'une intersection de primitive (membres traversalCost et intersectionCost). En activant les drapeaux de construction RTC_BUILD_FLAG_DYNAMIC (membre buildFlags), les performances de reconstruction pour les scènes dynamiques sont améliorées au détriment d'une utilisation mémoire plus importante.

Pour découper spatialement les primitives en mode de haute qualité, le constructeur a besoin d'espace supplémentaire à la fin du tableau de primitives de construction pour stocker les primitives découpées. La capacité totale du tableau de primitives de construction est passée via le membre primitiveArrayCapacity, et devrait être environ le double du nombre de primitives lors de l'utilisation de découpages spatiaux.

Les rappels RTCCreateNodeFunc et RTCCreateLeafFunc reçoivent un objet d'allocateur local au thread qui doit être utilisé pour l'allocation rapide des nœuds en utilisant la fonction rtcThreadLocalAlloc. Nous recommandons fortement d'utiliser ce mécanisme d'allocation, car les approches alternatives comme malloc standard peuvent être jusqu'à 10 fois plus lentes. L'allocateur passé aux rappels de création peut être utilisé uniquement à l'intérieur du thread courant. La mémoire allouée avec rtcThreadLocalAlloc est automatiquement libérée lorsque l'objet RTCBVH est supprimé. Si vous utilisez votre propre schéma d'allocation mémoire, vous devrez libérer la mémoire vous-même lorsque l'objet RTCBVH n'est plus utilisé.

Le rappel RTCCreateNodeFunc reçoit en outre le nombre d'enfants pour ce nœud, dans la plage de 2 à maxBranchingFactor (argument childCount).

La fonction de rappel RTCSetNodeChildFunc reçoit un pointeur vers le nœud en entrée (argument nodePtr), un tableau de pointeurs vers les enfants (argument childPtrs), et la taille de ce tableau (argument childCount).

La fonction de rappel RTCSetNodeBoundsFunc reçoit un pointeur vers le nœud en entrée (argument nodePtr), un tableau de pointeurs vers les boîtes englobantes des enfants (argument bounds), et la taille de ce tableau (argument childCount).

Le rappel RTCCreateLeafFunc reçoit en outre un tableau de primitives en entrée (argument primitives), et la taille de ce tableau (argument primitiveCount). Le rappel doit lire les membres geomID et primID des primitives passées pour construire la feuille.

Le rappel RTCSplitPrimitiveFunc est invoqué en mode de haute qualité pour découper une primitive (argument primitive) à la position spécifiée (argument position) et dimension (argument dimension). Le rappel doit retourner les boîtes des parties gauche et droite découpées de la primitive (arguments leftBounds et rightBounds).

La fonction de rappel RTCProgressMonitorFunction est appelée avec le taux d'achèvement estimé n dans la plage [0,1]. Retourner vrai depuis le rappel permet à la construction de continuer ; retourner faux annule la construction.

EXIT STATUS

En cas d'échec, un code d'erreur est défini qui peut être interrogé en utilisant rtcGetDeviceError.
