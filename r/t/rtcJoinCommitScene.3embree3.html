rtcJoinCommitScene(3) Embree Ray Tracing Kernels 3 rtcJoinCommitScene(3)

NOM

rtcJoinCommitScene - valide la scène à partir de plusieurs threads

SYNOPSIS

#include <embree3/rtcore.h>
void rtcJoinCommitScene(RTCScene scene);

DESCRIPTION

La fonction rtcJoinCommitScene valide toutes les modifications pour la scène spécifiée (argument scene). La validation de la scène déclenche interne la construction d'une structure d'accélération spatiale pour la scène. Les requêtes de rayons peuvent être effectuées après que les modifications de scène aient été correctement validées.

La fonction rtcJoinCommitScene peut être appelée à partir de plusieurs threads utilisateurs qui coopéreront tous à l'opération de construction. Tous les threads appelant cette fonction retourneront de rtcJoinCommitScene une fois la validation de la scène terminée. Tous les threads doivent appeler de manière cohérente rtcJoinCommitScene et non rtcCommitScene.

Contrairement à la fonction rtcCommitScene, la fonction rtcJoinCommitScene peut être appelée à partir de plusieurs threads utilisateurs, tandis que rtcCommitScene ne peut être appelée qu'à partir de plusieurs threads de travail TBB lorsqu'elle est utilisée simultanément. Pour des performances optimales, nous recommandons fortement d'utiliser TBB dans l'application avec la fonction rtcCommitScene et d'éviter d'utiliser la fonction rtcJoinCommitScene.

La fonctionnalité rtcJoinCommitScene permet une manière flexible de créer des hiérarchies de manière paresseuse pendant le rendu. Un thread atteignant une sous-scène d'une scène à deux niveaux qui n'a pas encore été construite peut générer la géométrie de la sous-scène et appeler rtcJoinCommitScene sur cette scène nouvellement générée. Pendant la construction, d'autres threads atteignant la scène qui n'a pas encore été construite peuvent rejoindre l'opération de construction en invoquant également rtcJoinCommitScene. Un thread qui appelle rtcJoinCommitScene après la fin de la construction retournera directement de l'appel rtcJoinCommitScene.

Plusieurs opérations de validation de scène sur différentes scènes peuvent s'exécuter simultanément, il est donc possible de valider de nombreuses petites scènes en parallèle, distribuant les validations à de nombreux threads.

Lors de l'utilisation d'Embree avec les Intel® Threading Building Blocks (ce qui est le défaut), les threads qui appellent rtcJoinCommitScene rejoindront l'opération de construction, mais d'autres threads de travail TBB pourraient également participer à la construction. Pour éviter la sur-allocation de threads, nous recommandons d'utiliser TBB également dans l'application. De plus, le mode de jointure ne fonctionne correctement qu'à partir de TBB v4.4 Update 1. Pour les versions TBB antérieures, les threads qui appellent rtcJoinCommitScene pour rejoindre une construction en cours déclencheront simplement la construction et attendront sa fin. De plus, les anciennes versions de TBB avec TBB_INTERFACE_VERSION_MAJOR < 8 ne prennent pas en charge rtcJoinCommitScene, et l'invocation de cette fonction entraînera une erreur.

Lors de l'utilisation d'Embree avec le système de tâches interne, seuls les threads qui appellent rtcJoinCommitScene effectueront l'opération de construction, et aucun thread de travail supplémentaire ne sera planifié.

Lors de l'utilisation d'Embree avec le Parallel Patterns Library (PPL), rtcJoinCommitScene n'est pas pris en charge et l'appel de cette fonction entraînera une erreur.

Pour détecter si rtcJoinCommitScene est pris en charge, utilisez la fonction rtcGetDeviceProperty.

STATUT DE SORTIE

En cas d'échec, un code d'erreur est défini qui peut être interrogé en utilisant rtcGetDeviceError.

VOIR AUSSI

[rtcCommitScene], [rtcGetDeviceProperty]
