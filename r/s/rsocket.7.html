RSOCKET(7) Manuel du programmeur Librdmacm RSOCKET(7)

NOM

rsocket - API de socket RDMA

SYNOPSIS

#include <rdma/rsocket.h>

DESCRIPTION

API et protocole de socket RDMA

NOTES

Rsockets est un protocole sur RDMA qui prend en charge une API au niveau du socket pour les applications. Les API Rsocket sont destinées à imiter le comportement des appels de socket correspondants, sauf indication contraire. Les fonctions Rsocket correspondent au nom et à la signature des appels de socket, à la différence près que tous les appels de fonction sont précédés d'un 'r'.

Les fonctions suivantes sont définies :

rsocket

rbind, rlisten, raccept, rconnect

rshutdown, rclose

rrecv, rrecvfrom, rrecvmsg, rread, rreadv

rsend, rsendto, rsendmsg, rwrite, rwritev

rpoll, rselect

rgetpeername, rgetsockname

rsetsockopt, rgetsockopt, rfcntl

Les fonctions prennent les mêmes paramètres que ceux utilisés pour les sockets. Les capacités et indicateurs suivants sont pris en charge à l'heure actuelle :

PF_INET, PF_INET6, SOCK_STREAM, SOCK_DGRAM

SOL_SOCKET - SO_ERROR, SO_KEEPALIVE (indicateur pris en charge, mais ignoré), SO_LINGER, SO_OOBINLINE, SO_RCVBUF, SO_REUSEADDR, SO_SNDBUF

IPPROTO_TCP - TCP_NODELAY, TCP_MAXSEG

IPPROTO_IPV6 - IPV6_V6ONLY

MSG_DONTWAIT, MSG_PEEK, O_NONBLOCK

Rockets fournit des extensions au-delà des routines de socket normales qui permettent le placement direct des données dans le tampon d'une application. C'est aussi ce qu'on appelle la prise en charge de la copie zéro (zero-copy), car les données sont envoyées et reçues directement, en contournant les copies dans les tampons contrôlés par le réseau. Les appels et options suivants prennent en charge le placement direct des données.

riomap, riounmap, riowrite

off_t riomap(int socket, void *buf, size_t len, int prot, int flags, off_t offset)
Riomap enregistre un tampon d'application auprès du matériel RDMA
associé à un rsocket. Le tampon est enregistré soit pour un accès local uniquement (PROT_NONE), soit pour un accès en écriture à distance (PROT_WRITE). Lorsqu'il est enregistré pour un accès à distance, le tampon est mappé à un décalage donné. Le décalage est soit fourni par l'utilisateur, soit, si l'utilisateur sélectionne -1 pour le décalage, rsockets en sélectionne un. Le pair distant peut accéder à un tampon iomappé directement en spécifiant le bon décalage. Le mappage n'est pas garanti d'être disponible avant que le pair distant n'ait reçu un transfert de données initié après la fin de riomap.

Pour activer l'utilisation des appels de mappage d'E/S à distance sur un rsocket, une application doit définir le nombre de mappages d'E/S disponibles pour le pair distant. Cela peut être fait en utilisant l'option rsetsockopt RDMA_IOMAPSIZE. Par défaut, un rsocket ne prend pas en charge les mappages d'E/S à distance. riounmap

int riounmap(int socket, void *buf, size_t len)
Riounmap supprime le mappage entre un tampon et un rsocket.

riowrite

size_t riowrite(int socket, const void *buf, size_t count, off_t offset, int flags)
Riowrite permet à une application de transférer des données sur un rsocket
directement dans un tampon mappé par E/S à distance. Le tampon distant est spécifié par un paramètre de décalage, qui correspond à un tampon mappé par E/S à distance. Du point de vue de l'expéditeur, riowrite se comporte de manière similaire à rwrite. Du point de vue du récepteur, les transferts riowrite sont silencieusement redirigés vers un tampon de données prédéterminé. Les données sont reçues automatiquement et le récepteur n'est pas informé du transfert. Cependant, les données iowrite sont toujours considérées comme faisant partie du flux de données, de sorte que les données iowrite seront écrites avant qu'un transfert ultérieur ne soit reçu. Un message envoyé immédiatement après l'initiation d'un iowrite peut être utilisé pour informer le récepteur de l'iowrite.

En plus des options de socket standard, rsockets prend en charge des options spécifiques aux périphériques et protocoles RDMA. Ces options sont accessibles via rsetsockopt en utilisant le niveau d'option SOL_RDMA.

RDMA_SQSIZE - Taille entière de la file d'attente d'envoi sous-jacente.
RDMA_RQSIZE - Taille entière de la file d'attente de réception sous-jacente.
RDMA_INLINE - Taille entière des données en ligne.
RDMA_IOMAPSIZE - Nombre entier de mappages d'E/S à distance pris en charge
RDMA_ROUTE - struct ibv_path_data de l'enregistrement de chemin pour la connexion.

Notez que les descripteurs de fichiers rsockets ne peuvent pas être transmis à des appels non-rsocket. Pour les applications qui doivent mélanger des descripteurs de fichiers rsocket avec des descripteurs de fichiers standard ou des fichiers ouverts, rpoll et rselect prennent en charge le sondage des rsocket et des descripteurs de fichiers normaux.

Les applications existantes peuvent utiliser les rsockets grâce à une bibliothèque de préchargement. Comme les rsockets implémentent un protocole de bout en bout, les deux côtés d'une connexion doivent utiliser des rsockets. La bibliothèque rdma_cm fournit une telle bibliothèque de préchargement, librspreload. Pour réduire la probabilité que la bibliothèque de préchargement intercepte des appels sans la connaissance explicite de l'utilisateur, la bibliothèque librspreload est installée dans le sous-répertoire %libdir%/rsocket.

La bibliothèque de préchargement peut être utilisée en définissant LD_PRELOAD lors de l'exécution. Notez que toutes les applications ne fonctionneront pas avec les rsockets. La prise en charge est limitée en fonction des options de socket utilisées par l'application. La prise en charge de fork() est limitée, mais disponible. Pour utiliser les rsockets avec la bibliothèque de préchargement pour les applications qui appellent fork, les utilisateurs doivent définir la variable d'environnement RDMAV_FORK_SAFE=1 des deux côtés client et serveur de la connexion. En général, fork est supportable pour les applications serveur qui acceptent une connexion, puis forquent un processus pour gérer la nouvelle connexion.

rsockets utilise des fichiers de configuration qui donnent à un administrateur le contrôle sur les paramètres par défaut utilisés par rsockets. Utilisez les fichiers sous /etc/rdma/rsocket comme suit :

mem_default - taille par défaut du(des) tampon(s) de réception

wmem_default - taille par défaut du(des) tampon(s) d'envoi

sqsize_default - taille par défaut de la file d'attente d'envoi

rqsize_default - taille par défaut de la file d'attente de réception

inline_default - taille par défaut des données en ligne

iomap_size - taille par défaut de la table de mappage d'E/S à distance

polling_time - nombre par défaut de microsecondes pour sonder les données avant d'attendre

wake_up_interval - nombre maximum de millisecondes à bloquer dans poll. Cette valeur est utilisée pour se prémunir contre d'éventuels blocages d'application dans rpoll().

Tous les fichiers de configuration doivent contenir une seule valeur entière. Les valeurs peuvent être définies en émettant une commande similaire à l'exemple suivant.

echo 1000000 > /etc/rdma/rsocket/mem_default

Si les fichiers de configuration ne sont pas disponibles, rsockets utilise des valeurs par défaut internes. Les applications peuvent remplacer les valeurs par défaut par programme via la routine rsetsockopt.
