NOM

rsnapshot - utilitaire d'instantanés de système de fichiers distant

SYNTAXE

rsnapshot [-vtxqVD] [-c fichier_cfg] [commande] [args]

DESCRIPTION

rsnapshot est un utilitaire d'instantanés de système de fichiers. Il peut prendre des instantanés incrémentiels de systèmes de fichiers locaux et distants pour un nombre quelconque de machines.

Les instantanés locaux du système de fichiers sont gérés avec rsync(1). Les connexions distantes sécurisées sont gérées avec rsync sur ssh(1), tandis que les connexions rsync anonymes utilisent simplement un serveur rsync. Les transferts distants et locaux dépendent de rsync.

rsnapshot économise beaucoup plus d'espace disque que ce que vous pourriez imaginer. La quantité d'espace requise correspond approximativement à la taille d'une sauvegarde complète, plus une copie de chaque fichier supplémentaire qui est modifié. rsnapshot utilise intensivement les liens physiques (hard links), donc si le fichier ne change pas, le snapshot suivant est simplement un lien physique vers le même fichier.

rsnapshot sera généralement appelé en tant que root par un job cron, ou une série de jobs cron. Il est cependant possible de l'exécuter en tant que n'importe quel utilisateur arbitraire avec un fichier de configuration alternatif.

Toutes les options importantes sont spécifiées dans un fichier de configuration, qui se trouve par défaut dans /etc/rsnapshot.conf. Un fichier alternatif peut être spécifié sur la ligne de commande. Il existe également des options supplémentaires qui peuvent être passées sur la ligne de commande.

Les options de la ligne de commande sont les suivantes :

-v verbeux, affiche les commandes shell exécutées

-t test, affiche les commandes shell qui seraient exécutées

-c chemin vers un fichier de configuration alternatif

-x un seul système de fichiers, ne traverse pas les partitions à l'intérieur de chaque point de sauvegarde

-q silencieux, supprime les avertissements non fatals

-V identique à -v, mais avec plus de détails

-D un flot continu d'informations de diagnostic

CONFIGURATION

/etc/rsnapshot.conf est le fichier de configuration par défaut. Tous les paramètres de ce fichier doivent être séparés par des tabulations. /etc/rsnapshot.conf.default peut être utilisé comme référence.

Il est recommandé de copier /etc/rsnapshot.conf.default dans /etc/rsnapshot.conf, puis de modifier /etc/rsnapshot.conf pour qu'il corresponde à vos besoins.

Les longues lignes peuvent être divisées sur plusieurs lignes. Les lignes de "continuation" doivent commencer par un espace ou une tabulation. Les lignes de continuation auront tous les espaces blancs au début et à la fin supprimés, puis seront concaténées avec une tabulation intercalée à la ligne précédente lors de l'analyse du fichier de configuration.

Voici une liste des paramètres autorisés :

config_version Version du fichier de configuration (obligatoire). Par défaut 1.2

snapshot_root Chemin du système de fichiers local pour sauvegarder tous les instantanés

include_conf Inclure un autre fichier dans la configuration à cet endroit.

Ceci est récursif, mais vous devrez peut-être faire attention aux chemins lors de la spécification du fichier à inclure. Nous vérifions si le fichier que vous avez spécifié est lisible, et afficherons une erreur s'il ne l'est pas. Nous recommandons d'utiliser un chemin complet. À titre de cas spécial, la valeur de include_conf peut être entourée de `backticks` auquel cas elle sera exécutée et ce qu'elle renverra sur STDOUT sera inclus dans la configuration. Notez que les métacaractères shell peuvent être interprétés.

no_create_root Si défini à 1, rsnapshot ne créera pas le répertoire snapshot_root

cmd_rsync Chemin complet vers "rsync" (obligatoire)

cmd_ssh Chemin complet vers "ssh" (facultatif)

cmd_cp Chemin complet vers "cp" (facultatif, mais doit être la version GNU)

Si vous utilisez Linux, vous devriez décommenter cmd_cp. Si vous utilisez une plateforme qui ne dispose pas de cp GNU, vous devriez laisser cmd_cp commenté.

Avec cp GNU, rsnapshot peut gérer les fichiers normaux et les fichiers spéciaux (comme les FIFOs, les sockets et les périphériques bloc/caractère) en une seule passe.

Si cmd_cp est désactivé, rsnapshot utilisera sa propre fonction intégrée, native_cp_al(), pour sauvegarder les fichiers et répertoires réguliers. Ceci sera suivi d'un appel séparé à rsync, pour transférer les fichiers spéciaux (en supposant qu'il y en ait).

cmd_rm Chemin complet vers "rm" (facultatif)

cmd_logger Chemin complet vers "logger" (facultatif, pour le support de syslog)

cmd_du Chemin complet vers "du" (facultatif, pour les rapports d'utilisation du disque)

cmd_rsnapshot_diff Chemin complet vers "rsnapshot-diff" (facultatif)

cmd_preexec

Chemin complet (plus les arguments éventuels) vers le script preexec (facultatif). Ce script sera exécuté immédiatement avant chaque opération de sauvegarde (mais pas les rotations). Si l'exécution échoue, rsnapshot s'arrêtera immédiatement.

cmd_postexec

Chemin complet (plus les arguments éventuels) vers le script postexec (facultatif). Ce script sera exécuté immédiatement après chaque opération de sauvegarde (mais pas les rotations). Si l'exécution échoue, rsnapshot s'arrêtera immédiatement.

linux_lvm_cmd_lvcreate

linux_lvm_cmd_lvremove

linux_lvm_cmd_mount

linux_lvm_cmd_umount

Chemins des commandes lvcreate, lvremove, mount et umount, pour une utilisation avec les LVM Linux. Vous pouvez également inclure des options pour les commandes. Les commandes lvcreate, lvremove, mount et umount sont nécessaires pour gérer les instantanés des volumes LVM et sont par ailleurs facultatives.

retain [nom] [nombre]

"nom" fait référence au nom de ce niveau de sauvegarde (par exemple, alpha, beta, aussi appelé 'intervalle'). "nombre" est le nombre d'instantanés pour ce type d'intervalle qui seront conservés. La valeur de "nom" sera la commande passée à rsnapshot pour effectuer ce type de sauvegarde.

Un alias obsolète pour 'retain' est 'interval'.

Exemple : retain alpha 6

[root@localhost]# rsnapshot alpha

Pour cet exemple, chaque fois que ceci est exécuté, ce qui suit se produira :

<snapshot_root>/alpha.5/ sera supprimé, s'il existe.

<snapshot_root>/alpha.{1,2,3,4} seront tous décalés de +1, s'ils existent.

<snapshot_root>/alpha.0/ sera copié vers <snapshot_root>/alpha.1/ en utilisant des liens physiques.

Chaque point de sauvegarde (expliqué ci-dessous) sera ensuite synchronisé avec les répertoires correspondants dans <snapshot_root>/alpha.0/

Les niveaux de sauvegarde doivent être spécifiés dans le fichier de configuration dans l'ordre, du plus fréquent au moins fréquent. La première entrée est celle qui sera synchronisée avec les points de sauvegarde. Les niveaux de sauvegarde suivants (par exemple, beta, gamma, etc.) effectuent simplement une rotation, chaque niveau de sauvegarde supérieur récupérant à partir du niveau inférieur pour son répertoire .0.

Exemple :

retain alpha 6

retain beta 7

retain gamma 4

beta.0/ sera déplacé de alpha.5/, et gamma.0/ sera déplacé de beta.6/

alpha.0/ sera synchronisé directement depuis le système de fichiers.

link_dest 1

Si votre version de rsync supporte --link-dest (2.5.7 ou plus récent), vous pouvez l'activer pour laisser rsync gérer certaines choses que cp GNU ou les sous-routines intégrées feraient autrement. L'activation de cette option fait que rsnapshot suit une branche de code légèrement plus compliquée, mais c'est la meilleure façon de prendre en charge les fichiers spéciaux sur les systèmes non-Linux.

sync_first 1

sync_first modifie le comportement de rsnapshot. Lorsque cette option est activée, tous les appels à rsnapshot avec différents niveaux de sauvegarde effectuent simplement une rotation des fichiers. Toutes les sauvegardes sont gérées en appelant rsnapshot avec l'argument "sync". Les fichiers synchronisés sont stockés dans un répertoire ".sync" sous le snapshot_root.

Cela permet une meilleure récupération dans le cas où rsnapshot serait interrompu au milieu d'une opération de synchronisation, car les étapes de synchronisation et de rotation sont séparées. Cela signifie également que vous pouvez facilement exécuter "rsnapshot sync" en ligne de commande sans craindre de forcer tous les autres répertoires à monter en niveau. Ce bénéfice a le coût d'un

plus d'espace disque que les instantanés. La valeur par défaut est 0 (désactivé).

verbose 2

Le niveau de détail des informations affichées lors de l'exécution du programme. Les valeurs autorisées vont de 1 à 5. La valeur par défaut est 2. 
1        Calme            Affiche uniquement les erreurs fatales
2        Défaut           Affiche les avertissements et les erreurs
3        Verbeux          Affiche les commandes shell équivalentes exécutées
4        Très Verbeux     Identique à verbeux, mais avec plus de détails
5        Débogage         Toutes sortes d'informations

loglevel 3

Ce nombre a la même signification que verbose ci-dessus, mais il détermine la quantité de données écrites dans le fichier journal, si un fichier journal est en cours d'écriture.

logfile /var/log/rsnapshot

Chemin d'accès complet au fichier journal de rsnapshot. S'il est défini, un fichier journal sera écrit, dont la quantité de données sera contrôlée par loglevel. S'il est commenté, aucun fichier journal ne sera écrit.

include [nom-de-fichier-modèle]

Ceci est passé directement à rsync en utilisant la directive --include. Ce paramètre peut être spécifié autant de fois que nécessaire, avec un modèle défini par ligne. Voir la page de manuel rsync(1) pour la syntaxe.

exclude [nom-de-fichier-modèle]

Ceci est passé directement à rsync en utilisant la directive --exclude. Ce paramètre peut être spécifié autant de fois que nécessaire, avec un modèle défini par ligne. Voir la page de manuel rsync(1) pour la syntaxe.

include_file /chemin/vers/fichier/include

Ceci est passé directement à rsync en utilisant la directive --include-from. Voir la page de manuel rsync(1) pour la syntaxe.

exclude_file /chemin/vers/fichier/exclude

Ceci est passé directement à rsync en utilisant la directive --exclude-from. Voir la page de manuel rsync(1) pour la syntaxe.

rsync_short_args -a

Liste des arguments courts à passer à rsync. S'ils ne sont pas spécifiés, "-a" est la valeur par défaut. Veuillez noter qu'ils doivent être tous regroupés. Par exemple, "-az" est valide, alors que "-a -z" ne l'est pas.

"-a" est le "mode archive" de rsync, qui lui indique de copier autant de métadonnées du système de fichiers que possible pour chaque fichier. Cela n'inclut *pas* spécifiquement les informations sur les liens physiques, car cela augmenterait considérablement l'utilisation de la mémoire de rsync et le ralentirait. Si vous avez besoin de préserver les liens physiques dans vos sauvegardes, ajoutez "H" à cette option.

rsync_long_args --delete --numeric-ids --relative --delete-excluded

Liste des arguments longs à passer à rsync. Les valeurs par défaut sont
--delete --numeric-ids --relative --delete-excluded Cela signifie que la structure de répertoires dans chaque destination de point de sauvegarde correspondra à celle de la source du point de sauvegarde.

Les guillemets sont autorisés dans rsync_long_args, par exemple "--rsync-path='sudo /usr/bin/rsync'". Vous pouvez utiliser des guillemets simples (') ou doubles ("), mais les guillemets imbriqués (y compris les guillemets imbriqués mixtes) ne sont pas autorisés. Une mise en guillemets similaire est également autorisée dans rsync_long_args par point de sauvegarde.

rsync_numtries 0

Nombre de tentatives supplémentaires pour exécuter rsync pour chaque source de sauvegarde donnée. Chaque fois que l'opération rsync pour une source se termine avec un code de sortie non nul, rsnapshot répétera cette opération jusqu'à ce que le nombre configuré de "rsync_numtries" soit atteint ou que rsync se termine avec succès. Par défaut, aucune tentative répétée n'est effectuée ("rsync_numtries 0").

rsync_wait_between_tries 0

Attendre entre les tentatives en secondes. Spécifiez la durée en secondes à attendre entre les nouvelles tentatives de l'opération rsync. Le nombre de nouvelles tentatives doit être défini dans rsync_numtries. Le temps d'attente par défaut est de 0 seconde.

ssh_args -p 22

Arguments à passer à ssh. S'ils ne sont pas spécifiés, la valeur par défaut est aucune.

du_args -csh

Arguments à passer à du. S'ils ne sont pas spécifiés, la valeur par défaut est -csh. GNU du supporte -csh, BSD du supporte -csk, Solaris du ne supporte pas du du tout. La version GNU est recommandée, car elle offre le plus de fonctionnalités.

lockfile /var/run/rsnapshot.pid

stop_on_stale_lockfile 0

Fichier de verrouillage à utiliser lorsque rsnapshot est exécuté. Cela empêche une seconde invocation d'écraser la première. S'il n'est pas spécifié, aucun fichier de verrouillage n'est utilisé. Assurez-vous d'utiliser un répertoire qui n'est pas accessible en écriture par tout le monde pour des raisons de sécurité. L'utilisation d'un fichier de verrouillage est fortement recommandée.

Si un fichier de verrouillage existe lorsque rsnapshot démarre, il essaiera de lire le fichier et s'arrêtera avec une erreur s'il ne peut pas. S'il *peut* lire le fichier, il vérifie s'il existe un processus avec le PID indiqué dans le fichier. S'il existe, rsnapshot s'arrête avec un message d'erreur. S'il n'y a pas de processus avec ce PID, alors nous supposons que le fichier de verrouillage est obsolète et nous l'ignorons *sauf si* stop_on_stale_lockfile est défini sur 1, auquel cas nous nous arrêtons.

stop_on_stale_lockfile vaut par défaut 0.

one_fs 1

Empêche rsync de franchir les partitions du système de fichiers. Définir cette valeur sur 1 active cette fonctionnalité. 0 la désactive. Ce paramètre est facultatif. La valeur par défaut est 0 (désactivé).

use_lazy_deletes 1

Modifie le comportement par défaut de rsnapshot et ne supprime pas initialement l'instantané le plus ancien. Au lieu de cela, il déplace ce répertoire vers _delete.[processid] et continue normalement. Une fois la sauvegarde terminée, le fichier de verrouillage sera supprimé avant que rsnapshot ne commence à supprimer le répertoire.

L'activation de cette option permet des captures d'instantanés plus rapides (car la suppression ne se fait pas en premier), et autorise le démarrage d'autres processus rsnapshot pendant que la suppression finale a lieu. Ce bénéfice se fait au détriment d'une utilisation accrue de l'espace disque. La valeur par défaut est 0 (désactivé).

Les détails sur son fonctionnement ont changé dans la version 1.3.1 de rsnapshot. Initialement, vous ne pouviez avoir qu'un seul répertoire .delete par niveau de sauvegarde. Désormais, vous pouvez en avoir plusieurs, donc si votre prochaine sauvegarde (par exemple) alpha démarre pendant que la précédente est encore en train d'effectuer une suppression différée, vous pourriez temporairement avoir des répertoires _delete supplémentaires.

linux_lvm_snapshotsize 2G

Taille des instantanés LVM (option lvcreate --size).

linux_lvm_snapshotname rsnapshot

Nom à utiliser lors de la création de l'instantané (ou des instantanés) de volume logique LVM (option lvcreate --name).

linux_lvm_vgpath /dev

Chemin d'accès aux groupes de volumes LVM.

linux_lvm_mountpath /mnt/lvm-snapshot

Point de montage à utiliser pour monter temporairement l'instantané (ou les instantanés).

backup /etc/ localhost/

backup root@example.com:/etc/ example.com/

backup rsync://example.com/path2/ example.com/

backup /var/ localhost/ one_fs=1

backup lvm://vg0/home/path2/ lvm-vg0/

backup_script /usr/local/bin/backup_pgsql.sh pgsql_backup/

Exemples :

backup /etc/ localhost/

Sauvegarde /etc/ vers <snapshot_root>/<retain>.0/localhost/etc/ en utilisant rsync sur le système de fichiers local

backup /usr/local/ localhost/

Sauvegarde /usr/local/ vers <snapshot_root>/<retain>.0/localhost/usr/local/ en utilisant rsync sur le système de fichiers local

backup root@example.com:/etc/ example.com/

Sauvegarde root@example.com:/etc/ vers <snapshot_root>/<retain>.0/example.com/etc/ en utilisant rsync via ssh

backup example.com:/etc/ example.com/

Même chose mais laisse ssh choisir le nom d'utilisateur distant (tel que spécifié dans ~/.ssh/config, sinon identique au nom d'utilisateur local)

backup root@example.com:/usr/local/ example.com/

Sauvegarde root@example.com:/usr/local/ vers <snapshot_root>/<retain>.0/example.com/usr/local/ en utilisant rsync via ssh

backup rsync://example.com/pub/ example.com/pub/

Sauvegarde rsync://example.com/pub/ vers <snapshot_root>/<retain>.0/example.com/pub/ en utilisant un serveur rsync anonyme. Veuillez noter que contrairement à la sauvegarde de chemins locaux et à l'utilisation de rsync via ssh, les serveurs rsync ont des "modules", qui sont des répertoires de premier niveau exportés. Par conséquent, le module doit également être spécifié dans le chemin de destination, comme indiqué dans l'exemple ci-dessus (le répertoire pub/ à la fin).

backup /var/ localhost/ one_fs=1

Ceci est identique aux autres exemples, mais remarquez la quatrième colonne. C'est ainsi que vous spécifiez des options par point de sauvegarde pour remplacer les paramètres globaux. Ce paramètre supplémentaire peut prendre plusieurs options, séparées par des virgules.

Il est plus utile lorsque vous spécifiez des exclusions rsync par sauvegarde, ainsi :

backup root@somehost:/ somehost +rsync_long_args=--exclude=/var/spool/

Notez le signe +. Cela indique à rsync_long_args d'*ajouter* à la liste des arguments à passer à rsync au lieu de remplacer la liste. Le signe + n'est pris en charge que pour rsync_long_args et rsync_short_args de rsnapshot.

backup lvm://vg0/home/path2/ lvm-vg0/

Sauvegarde le volume logique LVM appelé home, du groupe de volumes vg0, vers <snapshot_root>/<retain>.0/lvm-vg0/. Crée, monte, sauvegarde, démonte et supprime un instantané LVM pour chaque entrée lvm://.

backup_script /usr/local/bin/backup_database.sh db_backup/

Dans cet exemple, nous spécifions un script ou un programme à exécuter. Ce script doit simplement créer des fichiers et/ou des répertoires dans son répertoire de travail actuel. rsnapshot prendra alors cette sortie et la déplacera dans le répertoire spécifié dans la troisième colonne.

Veuillez noter que tout ce qui se trouve dans le répertoire de destination sera complètement supprimé et recréé. Pour cette raison, rsnapshot vous empêche de spécifier un répertoire de destination

pour un script de sauvegarde qui va écraser d'autres sauvegardes.

Donc, dans cet exemple, disons que le script backup_database.sh exécute simplement une commande comme :

#!/bin/sh
mysqldump -uusername mydatabase > mydatabase.sql
chmod u=r,go= mydatabase.sql        # r-------- (0400)

rsnapshot prendra le fichier "mydatabase.sql" généré et le déplacera dans le répertoire <snapshot_root>/<retain>.0/db_backup/. Lors des exécutions suivantes, rsnapshot vérifie les différences entre les fichiers créés et les fichiers précédents. Si le script de sauvegarde génère la même sortie lors de l'exécution suivante, les fichiers seront liés en dur aux précédents et aucun espace disque supplémentaire ne sera utilisé.

backup_exec ssh root@1.2.3.4 "du -sh /.offsite_backup" optional

backup_exec rsync -az /.snapshots/daily.0 root@1.2.3.4:/.offsite_backup/ required

backup_exec /bin/true/

backup_exec exécute simplement la commande listée. Le deuxième argument n'est pas obligatoire et vaut par défaut 'optional'. Il spécifie l'importance que la commande retourne 0. Les valeurs valides sont 'optional' et 'required'. Si la commande est spécifiée comme facultative, un statut de sortie non nul de la commande entraînera un message d'avertissement. Si la commande est spécifiée comme 'required', un statut de sortie non nul de la commande entraînera un message d'erreur et rsnapshot lui-même se terminera avec un statut de sortie non nul.

N'oubliez pas que les tabulations doivent séparer tous les éléments et qu'il doit y avoir une barre oblique finale à la fin de chaque répertoire.

Un symbole dièse (#) au début d'une ligne est traité comme un commentaire.

Mise en place (un exemple de fichier) :

# CECI EST UN COMMENTAIRE, N'OUBLIEZ PAS QUE LES TABULATIONS DOIVENT SEPARER TOUS LES ELEMENTS
config_version  1.2
snapshot_root   /.snapshots/
cmd_rsync           /usr/bin/rsync
cmd_ssh             /usr/bin/ssh
#cmd_cp             /bin/cp
cmd_rm              /bin/rm
cmd_logger          /usr/bin/logger
cmd_du              /usr/bin/du
linux_lvm_cmd_lvcreate        /sbin/lvcreate
linux_lvm_cmd_lvremove        /sbin/lvremove
linux_lvm_cmd_mount           /bin/mount
linux_lvm_cmd_umount          /bin/umount
linux_lvm_snapshotsize    2G
linux_lvm_snapshotname    rsnapshot
linux_lvm_vgpath          /dev
linux_lvm_mountpath       /mnt/lvm-snapshot
retain              alpha  6
retain              beta   7
retain              gamma  7
retain              delta 3
backup              /etc/                     localhost/
backup              /home/                    localhost/
backup_script       /usr/local/bin/backup_mysql.sh  mysql_backup/
backup              root@foo.com:/etc/        foo.com/
backup              root@foo.com:/home/       foo.com/
backup              root@mail.foo.com:/home/  mail.foo.com/
backup              rsync://example.com/pub/  example.com/pub/
backup              lvm://vg0/xen-home/       lvm-vg0/xen-home/
backup_exec         echo "sauvegarde terminée !"

UTILISATION

rsnapshot peut être utilisé par n'importe quel utilisateur, mais pour les sauvegardes système, vous voudrez probablement l'exécuter en tant que root.

Étant donné que les sauvegardes sont généralement négligées si une intervention humaine est requise, la méthode préférée est de l'exécuter à partir de cron.

Lorsque vous configurez vos sauvegardes pour la première fois, vous voudrez probablement également l'exécuter à partir de la ligne de commande une ou deux fois pour vous familiariser avec ce qu'il fait.

Voici un exemple d'entrée crontab, en supposant que les niveaux de sauvegarde alpha, beta, gamma et delta ont été définis dans /etc/rsnapshot.conf

0 */4 * * * /usr/local/bin/rsnapshot alpha

50 23 * * * /usr/local/bin/rsnapshot beta

40 23 * * 6 /usr/local/bin/rsnapshot gamma

30 23 1 * * /usr/local/bin/rsnapshot delta

Cet exemple fera ce qui suit :

6 sauvegardes alpha par jour (une toutes les 4 heures, à 0, 4, 8, 12, 16, 20)

1 sauvegarde beta par jour, à 23h50

1 sauvegarde gamma par semaine, à 23h40, le samedi (6ème jour de la semaine)

1 sauvegarde delta par mois, à 23h30 le 1er jour du mois

Il est généralement conseillé de planifier les niveaux de sauvegarde les plus importants pour qu'ils s'exécutent un peu avant les plus bas. Par exemple, dans le crontab ci-dessus, remarquez que "beta" s'exécute 10 minutes avant "alpha". La principale raison est que la rotation beta retirera le plus ancien alpha et en fera le plus récent beta (ce qui signifie que la prochaine rotation alpha n'aura pas besoin de supprimer le plus ancien alpha), ce qui est plus efficace. Une raison secondaire est qu'il est plus difficile de prédire combien de temps prendra le niveau de sauvegarde le plus bas, car il doit réellement effectuer un rsync de la source ainsi que la rotation que toutes les sauvegardes effectuent.

Si rsnapshot met plus de 10 minutes pour effectuer la rotation "beta" (ce qui inclut généralement la suppression de la plus ancienne sauvegarde beta), vous devriez augmenter le temps entre les niveaux de sauvegarde. Sinon (en supposant que vous ayez configuré le paramètre lockfile, comme recommandé), votre sauvegarde alpha échouera parfois car beta détient toujours le verrou.

N'oubliez pas qu'il ne s'agit que des heures d'exécution du programme. Pour définir le nombre de sauvegardes stockées, définissez les nombres retain dans /etc/rsnapshot.conf

Pour vérifier l'espace disque utilisé par rsnapshot, vous pouvez l'appeler avec l'argument "du".

Par exemple :

rsnapshot du

Cela vous montrera exactement la quantité d'espace disque occupée dans la racine de sauvegarde. Cette fonctionnalité nécessite que la commande UNIX du soit installée sur votre système, qu'elle prenne en charge les arguments de ligne de commande "-csh" et qu'elle soit dans votre PATH. Vous pouvez également remplacer vos paramètres de PATH et les drapeaux passés à du en utilisant les paramètres cmd_du et du_args.

Il est également possible de passer un chemin de fichier relatif comme deuxième argument, pour obtenir un rapport sur un fichier ou un sous-répertoire particulier.

rsnapshot du localhost/home/

La version GNU de "du" est préférée. La version BSD fonctionne bien également, mais ne prend pas en charge l'option -h (utilisez plutôt -k pour voir les totaux en kilooctets). D'autres versions de "du", comme Solaris, peuvent ne pas fonctionner du tout.

Pour vérifier les différences entre deux répertoires, appelez rsnapshot avec l'argument "diff", suivi de deux niveaux de sauvegarde ou chemins de répertoire.

Par exemple :

rsnapshot diff beta.0 beta.1

rsnapshot diff beta.0/localhost/etc beta.1/localhost/etc

rsnapshot diff /.snapshots/beta.0 /.snapshots/beta.1

Cela appellera le programme "rsnapshot-diff", qui analysera les deux répertoires à la recherche de différences (basées sur les liens physiques).

rsnapshot sync

Lorsque sync_first est activé, rsnapshot doit d'abord être appelé avec l'argument sync, suivi des autres entrées cron habituelles. La synchronisation doit avoir lieu au niveau de sauvegarde le plus bas et le plus fréquent, et juste avant. Par exemple :
0 */4 * * * /usr/local/bin/rsnapshot sync && /usr/local/bin/rsnapshot alpha

50 23 * * * /usr/local/bin/rsnapshot beta

40 23 1,8,15,22 * * /usr/local/bin/rsnapshot gamma

30 23 1 * * /usr/local/bin/rsnapshot delta

L'opération de synchronisation exécute simplement rsync et tous les scripts de sauvegarde. Dans ce scénario, tous les appels effectuent simplement une rotation des répertoires, même le niveau de sauvegarde le plus bas.

Veuillez noter que la commande "rsnapshot sync && rsnapshot alpha" ci-dessus sautera la rotation chaque fois que rsnapshot terminera son opération de synchronisation "avec avertissements" (par exemple, certains fichiers ont disparu pendant que rsync s'exécutait). Si vous souhaitez garantir la rotation même en cas d'avertissements, la commande suivante peut convenir à votre travail cron :

0 */4 * * * /usr/local/bin/rsnapshot sync || [ $? -eq 2 ] && /usr/local/bin/rsnapshot alpha

rsnapshot sync [destination]

Lorsque sync_first est activé, tout le comportement de synchronisation se produit lors d'une étape de synchronisation supplémentaire (voir ci-dessus). Lors de l'utilisation de l'argument sync, il est également possible de spécifier un point de sauvegarde de destination comme paramètre facultatif. Si cela est fait, seuls les points de sauvegarde partageant ce chemin de destination seront synchronisés.

Par exemple, supposons que example.com est un chemin de destination partagé par un ou plusieurs de vos points de sauvegarde.

rsnapshot sync example.com

Cette commande ne synchronisera que les fichiers qui sont normalement sauvegardés dans example.com. Elle n'obtiendra PAS d'autres points de sauvegarde avec des valeurs légèrement différentes (comme example.com/etc/, par exemple). Pour synchroniser example.com/etc, vous devrez exécuter rsnapshot à nouveau, en utilisant example.com/etc comme paramètre facultatif.

rsnapshot configtest

Effectue une vérification rapide de la cohérence pour s'assurer que tout est prêt.

VALEURS DE RETOUR

0 Toutes les opérations se sont terminées avec succès

1 Une erreur fatale s'est produite

2 Des avertissements se sont produits, mais la sauvegarde s'est terminée

Il y a quelques différences mineures (par exemple, ne pas montrer une tentative de suppression du fichier de verrouillage car il n'a pas été réellement créé dans le test), mais cela devrait vous donner une très bonne idée de ce qui va se passer.

L'utilisation des options -v, -V et -D affichera des informations de plus en plus détaillées sur STDOUT.

Beaucoup d'autres comportements étranges peuvent probablement être attribués à de simples problèmes de permissions de système de fichiers et d'authentification ssh.

NOTES

Assurez-vous que votre fichier /etc/rsnapshot.conf contient tous les éléments séparés par des tabulations. Voir /etc/rsnapshot.conf.default pour un exemple de fichier fonctionnel.

Assurez-vous de mettre une barre oblique finale à la fin de toutes les références de répertoire. Sinon, des répertoires supplémentaires pourraient être créés dans vos instantanés. Pour plus d'informations sur la gestion de la barre oblique finale, consultez la page de manuel rsync(1).

Assurez-vous que le répertoire d'instantanés a les permissions chmod 700 et est détenu par root (en supposant que les sauvegardes sont effectuées par l'utilisateur root). Si le répertoire d'instantanés est lisible par d'autres utilisateurs, ils pourront modifier les instantanés contenant leurs fichiers, détruisant ainsi l'intégrité des instantanés.

Si vous souhaitez que les utilisateurs réguliers puissent restaurer leurs propres sauvegardes, plusieurs méthodes peuvent être utilisées. Un scénario possible serait :

Définir snapshot_root à /.private/.snapshots dans /etc/rsnapshot.conf

Définir les permissions de ces répertoires comme suit :

drwx------    /.private
drwxr-xr-x    /.private/.snapshots

Exporter le répertoire /.private/.snapshots via NFS en lecture seule, un partage Samba en lecture seule, etc.

Voir le HOWTO rsnapshot pour plus d'informations sur la manière de rendre les sauvegardes accessibles aux utilisateurs non privilégiés.

Pour que ssh fonctionne sans intervention via cron, vous voudrez probablement utiliser des connexions par clé publique. Créez une clé ssh sans phrase secrète pour root et installez la clé publique sur chaque machine que vous souhaitez sauvegarder. Si vous sauvegardez des fichiers système à partir de machines distantes, cela signifie probablement des connexions root sans intervention. Une autre possibilité est de créer un deuxième utilisateur sur la machine juste pour les sauvegardes. Donnez à l'utilisateur un nom différent tel que "rsnapshot", mais conservez l'UID et le GID définis à 0, pour lui donner les privilèges root. Cependant, rendez les connexions plus restrictives, soit via la configuration ssh, soit en utilisant un shell alternatif.

SOYEZ PRUDENT ! Si la clé privée est obtenue par un attaquant, il aura un accès libre à tous les systèmes impliqués. Si vous n'êtes pas sûr de la manière de procéder, consultez ssh(1), sshd(1) et ssh-keygen(1).

Les scripts de sauvegarde sont exécutés en tant que le même utilisateur que celui sous lequel rsnapshot s'exécute. Typiquement, c'est root. Assurez-vous que tous vos scripts de sauvegarde ne sont écrivables que par root, et qu'ils n'appellent aucun autre programme qui n'appartient pas à root. Si vous ne le faites pas, toute personne capable d'écrire dans le script de sauvegarde ou dans un programme qu'il appelle peut prendre le contrôle total de la machine. Bien sûr, ce n'est pas une situation unique à rsnapshot.

Par défaut, les transferts rsync sont effectués avec l'option --numeric-ids. Cela signifie que les noms d'utilisateur et les noms de groupe sont ignorés pendant les transferts, mais les informations UID/GID sont conservées intactes. L'hypothèse est que les sauvegardes seront restaurées dans le même environnement d'où elles proviennent. Sans cette option, la restauration de sauvegardes pour plusieurs serveurs hétérogènes serait ingérable. Si vous archivez des instantanés avec GNU tar, vous pourriez vouloir utiliser le paramètre --numeric-owner. De plus, conservez une copie des fichiers /etc/passwd et /etc/group du système archivé à portée de main pour la correspondance UID/GID vers nom.

Si vous supprimez des points de sauvegarde dans le fichier de configuration, les fichiers précédemment archivés sous ces points resteront définitivement dans le répertoire des instantanés à moins que vous ne supprimiez les fichiers vous-même. Si vous souhaitez économiser de l'espace disque, vous devrez aller dans le répertoire <snapshot_root> et supprimer manuellement les fichiers du répertoire ".0" du niveau de sauvegarde le plus bas.

Par exemple, si vous sauvegardiez auparavant /home/ avec une destination de localhost/, et que alpha est votre niveau de sauvegarde le plus bas, vous devrez faire ce qui suit pour récupérer cet espace disque :

rm -rf <snapshot_root>/alpha.0/localhost/home/

Veuillez noter que les autres instantanés précédemment créés de /home/ utiliseront toujours cet espace disque, mais comme les fichiers sont retirés de alpha.0/, ils ne seront plus copiés dans les répertoires suivants, et seront donc supprimés en temps voulu au fur et à mesure des rotations.

rsnapshot(1) - page de manuel

NAME

rsnapshot - outil de sauvegarde différentielle de type rsync

SYNOPSIS

rsnapshot [-hV] [-c config-file] [-q] [-v] [-o] [subcommand]

DESCRIPTION

rsnapshot est un outil de sauvegarde qui utilise les liens physiques (hard links) pour créer des instantanés ponctuels (snapshots) de vos systèmes de fichiers. Il utilise le programme rsync pour copier les fichiers du répertoire source vers le répertoire de destination.

L'avantage de cette approche est qu'elle permet de réaliser des sauvegardes qui économisent beaucoup d'espace disque. Chaque instantané est une copie complète des données à un moment donné, mais les fichiers qui n'ont pas changé entre deux instantanés sont référencés par des liens physiques, ce qui signifie qu'ils n'occupent qu'un seul bloc de stockage. Seuls les fichiers qui ont été modifiés sont dupliqués.

CONFIGURATION

rsnapshot est configuré par un fichier de configuration. Le fichier par défaut est /etc/rsnapshot.conf. Vous pouvez spécifier un autre fichier en utilisant l'option -c.

Le fichier de configuration contient une série de directives qui définissent les sources de sauvegarde, les destinations, les intervalles de rétention, etc.

Voici quelques directives courantes :

  • config_version : Version du fichier de configuration.
  • snapshot_root : Répertoire racine où seront stockés les instantanés.
  • verbose : Augmente le niveau de verbosité des messages.
  • ssh_args : Arguments supplémentaires pour SSH.
  • rsync_args : Arguments supplémentaires pour rsync.
  • link_dest : Spécifie si les liens physiques doivent être utilisés.
  • retain : Définit la politique de rétention pour les instantanés (par exemple, daily 7 pour conserver 7 sauvegardes quotidiennes).
  • backup : Définit un répertoire source à sauvegarder et sa destination (par exemple, backup /home/ utilisateur/ documents/ /sauvegardes/utilisateur/documents/).

USAGE

Pour exécuter une sauvegarde, utilisez la commande :

rsnapshot [options] [subcommand]

Les sous-commandes courantes sont :

  • cron : Exécute les sauvegardes en fonction des directives de rétention définies dans le fichier de configuration. C'est la méthode recommandée pour exécuter rsnapshot en tâche planifiée.
  • sync : Effectue une synchronisation des données.
  • backup : Effectue une sauvegarde complète des sources spécifiées.
  • hourly, daily, weekly, monthly : Effectuent des sauvegardes en tenant compte des politiques de rétention correspondantes.

Exemple d'exécution d'une sauvegarde quotidienne :

rsnapshot daily

EXIT VALUES

rsnapshot retourne généralement 0 en cas de succès, et une valeur non nulle en cas d'erreur.

FILES

  • /etc/rsnapshot.conf : Fichier de configuration par défaut.

VOIR AUSSI

rsync(1)

DIAGNOSTICS

rsnapshot affiche des messages détaillés sur son activité, en particulier lorsqu'il est exécuté avec l'option -v ou -vv.

BUGS

Les rapports de bugs peuvent être soumis sur le site web du projet ou via le système de suivi des bugs d'Arch Linux.

NOTES

Assurez-vous que les permissions d'accès aux répertoires sources et de destination sont correctement configurées. L'utilisation de clés SSH sans mot de passe est recommandée pour les sauvegardes distantes.
