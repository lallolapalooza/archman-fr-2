NOM

rstream - test de ping-pong en flux continu sur RDMA.

SYNTAXE

rstream [-s adresse_serveur] [-b adresse_liaison] [-f format_adresse]
			[-B taille_tampon] [-I itérations] [-C nombre_transferts]
			[-S taille_transfert] [-p port_serveur] [-T option_test]

DESCRIPTION

Utilise le protocole de flux continu sur RDMA (rsocket) pour connecter et échanger des données entre une application client et serveur.

OPTIONS

-s adresse_serveur
Le nom réseau ou l'adresse IP du système serveur qui attend des connexions. Le nom ou l'adresse utilisé doit pouvoir être routé via un périphérique RDMA. Cette option doit être spécifiée par le client.
-b adresse_liaison
L'adresse réseau locale à laquelle se lier.
-f format_adresse
Les formats d'adresse pris en charge sont ip, ipv6, gid ou name.
-B taille_tampon
Indique la taille des tampons réseau d'envoi et de réception.
-I itérations
Le nombre de fois où le nombre spécifié de messages sera échangé entre le client et le serveur. (par défaut 1000)
-C nombre_transferts
Le nombre de messages à transférer du client vers le serveur et vice-versa à chaque itération. (par défaut 1000)
-S taille_transfert
La taille de chaque transfert d'envoi, en octets. (par défaut 1000) Si 'all' est spécifié, rstream exécutera une série de tests de tailles variées.
-p port_serveur
Le numéro de port du serveur.
-T option_test
Spécifie les paramètres de test. Les options disponibles sont :

s | socket - utilise les appels socket standard pour transférer des données

a | async - utilise des opérations asynchrones (par exemple, select / poll)

b | blocking - utilise des appels bloquants

f | fork - processus serveur par fork (force l'option -T s)

n | nonblocking - utilise des appels non bloquants

r | resolve - utilise rdma cm pour résoudre l'adresse

v | verify - vérifie les transferts de données

NOTES

L'utilisation de base consiste à démarrer rstream sur un système serveur, puis à exécuter rstream -s nom_serveur sur un système client. Par défaut, rstream exécutera une série de tests de performance en latence et en bande passante. La spécification d'un nombre différent d'itérations, de nombre_transferts ou de taille_transfert exécutera un test personnalisé par l'utilisateur en utilisant les valeurs par défaut lorsque rien n'a été spécifié.

Étant donné que ce test mappe des ressources RDMA à l'espace utilisateur, les utilisateurs doivent s'assurer qu'ils disposent des ressources système et des permissions nécessaires. Voir le fichier README de libibverbs pour plus de détails.
