R2E(1) Manuel des commandes générales R2E(1)

NOM

r2e - recevoir des flux RSS par email

SYNTAXE

r2e [options] <commande> [<arguments>]

DESCRIPTION

r2e est un programme simple que vous pouvez exécuter dans votre crontab(5). Il surveille les flux RSS et vous envoie un message électronique joliment formaté pour chaque nouvel élément.

Pour un démarrage rapide avec r2e, essayez ces étapes :

r2e new votre@votredomaine.com
r2e add nomduflux http://flux.url/quelque.part.rss
r2e run

La dernière commande devrait éventuellement être mise dans votre crontab si vous souhaitez que les choses vous soient envoyées automatiquement.

OPTIONS

-h, --help
Affiche l'aide de rss2email et quitte.
-v, --version
Affiche la version de rss2email et quitte.
--full-version
Affiche les versions de Python, du compilateur utilisé pour compiler Python, et des paquets utilisés par rss2email.
-c, --config <chemin>
La configuration du programme est lue dans $XDG_CONFIG_HOME/rss2email.cfg par défaut (voir aussi FICHIERS et VARIABLES D'ENVIRONNEMENT ci-dessous). Utilisez cette option pour définir un fichier de configuration différent.
-d, --data <chemin>
Les données dynamiques du programme sont lues dans $XDG_DATA_HOME/rss2email.json par défaut (voir aussi FICHIERS et VARIABLES D'ENVIRONNEMENT ci-dessous). Utilisez cette option pour définir un fichier de données différent.
-V, --verbose
Incrémente la verbosité de la journalisation.

COMMANDES

new [<email>]
Crée une nouvelle base de données de flux. Si l'argument <email> est donné, il définit l'adresse e-mail par défaut à laquelle les e-mails sont envoyés.
email [<email>]
Met à jour l'adresse e-mail cible par défaut à <email>.
add [--only-new] <nom> <url> [<email>]
S'abonne à un flux. L'argument <nom> donne un nom au flux pour une manipulation future. <url> est l'URL du flux. L'argument optionnel <email> est l'adresse e-mail à laquelle envoyer les nouveaux éléments, remplaçant l'adresse par défaut pour ce flux particulier. Répétez pour chaque flux auquel vous souhaitez vous abonner.
L'option --only-new récupère le flux au moment de l'ajout sans envoyer les entrées, faisant en sorte que l'exécution ultérieure de run les considère comme déjà envoyées. Elle doit être utilisée lorsque l'on ne s'intéresse qu'aux entrées qui ne sont pas encore dans le flux au moment de l'exécution de add.
run [--no-send] [--clean] [<index> [<index> ...]]
Analyse les flux et envoie des e-mails pour les nouveaux éléments. Ceci peut être exécuté dans un cron job.
L'option --no-send empêche r2e d'envoyer des e-mails. Cela peut être utile la première fois que vous l'exécutez, car sinon il enverrait un e-mail pour chaque élément de flux disponible.

L'option --clean réduit la taille de la base de données en supprimant les anciennes entrées. Elle force le téléchargement des flux sélectionnés ou de tous les flux, et ne devrait être utilisée que chaque semaine ou chaque mois.

Si un <index> est spécifié, r2e ne téléchargera que ce flux. <index> peut être soit le nom du flux (tel que défini par add), soit l'index du flux (tel qu'affiché par list).

list
Liste tous les flux de la base de données.
pause [<index> [<index> ...]]
Met les flux en pause (désactive la récupération). L'option <index> sélectionne le(s) flux à mettre en pause (voir run pour les valeurs possibles). Si aucun <index> n'est donné, tous les flux sont mis en pause.
unpause [<index> [<index> ...]]
Réactive les flux (active la récupération).
delete <index> [<index> [<index> ...]]
Supprime un ou plusieurs flux de la base de données. L'option <index> sélectionne le(s) flux à supprimer (voir run pour les valeurs possibles).
reset [<index> [<index> ...]]
Oublie les données dynamiques du flux (par exemple, pour renvoyer de vieilles entrées). L'option <index> sélectionne le(s) flux à réinitialiser (voir run pour les valeurs possibles). Si aucun <index> n'est donné, tous les flux sont réinitialisés.
opmlimport [<chemin>]
Importe de nouveaux flux depuis OPML. <chemin> est le fichier à partir duquel les données OPML seront lues. Si <chemin> n'est pas donné, r2e lit les données depuis l'entrée standard.
opmlexport [<chemin>]
Exporte tous les flux vers OPML. <chemin> est le fichier vers lequel les données OPML seront écrites. Si <chemin> n'est pas donné, r2e écrit les données vers la sortie standard.

CONFIGURATION

Le comportement du programme peut être contrôlé via le fichier $XDG_CONFIG_HOME/rss2email.cfg (voir aussi FICHIERS et VARIABLES D'ENVIRONNEMENT ci-dessous). Le format du fichier est similaire à un fichier INI de Microsoft Windows. Il est analysé par la classe ConfigParser de Python, donc consultez la documentation Python à l'adresse http://docs.python.org/3/library/configparser.html pour les détails du format.

Le fichier de configuration stocke la configuration générale (appliquée à tous les flux) dans la section [DEFAULT]. La commande new créera un fichier de configuration pour vous, que vous pourrez modifier à votre guise. La commande add ajoutera des sections spécifiques aux flux. Pour remplacer un paramètre pour tous les flux, modifiez la valeur dans la section [DEFAULT]. Pour remplacer un paramètre pour un flux particulier, ajoutez ce paramètre à la section spécifique au flux. Voici un exemple remplaçant use-publisher-email et name-format pour le flux nomduflux.

[DEFAULT]
from = utilisateur@rss2email.invalid
force-from = False
use-publisher-email = False
name-format = {titre-flux}: {auteur}
  ...
verbose = warning
[feed.nomduflux]
url = http://flux.url/quelque.part.rss
use-publisher-email = True
name-format = {auteur} ({titre.flux})

Vous pouvez configurer les éléments suivants :

Adressage

from
L'adresse e-mail d'où proviennent les messages par défaut.
use-8bit
Transfer-Encoding. Pour l'envoi d'e-mails local, il est sûr et pratique d'utiliser 8bit.
force-from
True : Utilise uniquement l'adresse 'from'. False : Utilise l'adresse e-mail spécifiée par le flux, lorsque c'est possible.
use-publisher-email
True : Utilise l'e-mail de l'éditeur si vous ne trouvez pas celui de l'auteur. False : Utilise simplement l'e-mail 'from' à la place.
name-format
Si vide, utilise uniquement l'adresse e-mail du flux plutôt que le nom convivial plus l'adresse e-mail. Les attributs disponibles peuvent inclure 'feed', 'feed-name', 'feed-url', 'feed-title', 'author', et 'publisher', mais seuls 'feed', 'feed-name', et 'feed-url' sont garantis.
to
Définit les adresses e-mail par défaut dans le champ 'To'.

Récupération

proxy
Définit un proxy HTTP (par exemple, 'http://votre.proxy.ici:8080/')
feed-timeout

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Timeout

feed-timeout
Définir le délai (en secondes) pour la réponse du serveur de flux

Traitement

active
True : Récupérer, traiter et envoyer les flux par e-mail. False : Ne pas récupérer, traiter ou envoyer les flux par e-mail
digest
True : Envoyer un seul e-mail multi-entrées par flux et par exécution de rss2email. False : Envoyer un seul e-mail par entrée.
digest-type
Type de contenu du message pour les digests. Les valeurs valides sont 'multipart/digest' et 'multipart/mixed'. Le premier est la valeur par défaut, mais de nombreux clients de messagerie ne le prennent pas en charge.
date-header
True : Générer l'en-tête Date en fonction de la date de l'élément, lorsque possible. False : Générer l'en-tête Date en fonction de l'heure d'envoi.
date-header-order
Une liste délimitée par des virgules de certaines combinaisons de ('issued', 'created', 'modified', 'expired') exprimant la liste ordonnée des préférences de dates à utiliser pour l'en-tête Date de l'e-mail.
bonus-header
Définissez ceci pour ajouter des en-têtes bonus à tous les e-mails. Exemple : bonus-header = 'Approved: joe@bob.org'
trust-guid
True : Recevoir un e-mail par publication. False : Recevoir un e-mail chaque fois qu'une publication change.
trust-link
True : Recevoir un e-mail par URL de lien unique. False : S'en remettre à la préférence trust-guid. Changer cela pour les flux existants peut entraîner des doublons, car les anciennes entrées ne seront pas enregistrées sous leurs nouveaux identifiants basés sur les liens.
encodings
Pour encoder au mieux les e-mails avec des caractères internationaux, nous parcourons la liste ci-dessous et utilisons le premier jeu de caractères qui fonctionne.
post-process
Crochets de traitement utilisateur. Notez l'espace après le nom du module. Exemple : post-process = 'rss2email.post_process.downcase downcase_message'
digest-post-process
Crochets de traitement utilisateur pour les messages digests. Si 'digest' est activé, le crochet 'post-process' habituel s'applique aux messages par entrée, mais ce crochet est appelé avec le message digest complet avant son envoi. Exemple : digest-post-process = 'rss2email.post_process.downcase downcase_message'
subject-format
Le format de la ligne d'objet. Les attributs disponibles sont 'feed', 'feed-name', 'feed-url', 'feed-title'.

Conversion HTML

html-mail
True : Envoyer des messages text/html lorsque possible. False : Convertir le HTML en texte brut.
use-css
Utiliser CSS
css
Stylage CSS optionnel

Options html2text

unicode-snob
Utiliser des caractères Unicode au lieu de leurs remplacements pseudo-ascii
links-after-each-paragraph
Placer les liens après chaque paragraphe au lieu de la fin.
inline-links
Utiliser un formatage en ligne, plutôt que par référence, pour les images et les liens.
wrap-links
Retourner les lignes des liens en fonction de la largeur du corps.
body-width
Retourner les lignes longues à la position indiquée. Toute valeur négative pour aucun retour à la ligne, 0 pour une largeur de 78 (compatibilité), ou toute largeur positive.

Envoi d'e-mails

email-protocol
Sélectionner le protocole parmi : sendmail, smtp, imap, maildir
sendmail
Chemin vers sendmail (ou compatible)

Configuration SMTP

smtp-auth
Définir sur True pour utiliser l'authentification SMTP
smtp-username
nom d'utilisateur pour l'authentification SMTP
smtp-password
mot de passe pour l'authentification SMTP
smtp-server
serveur SMTP
smtp-ssl
Se connecter au serveur SMTP en utilisant SSL

Configuration IMAP

imap-auth
définir sur True pour utiliser l'authentification IMAP.
imap-username
nom d'utilisateur pour l'authentification IMAP
imap-password
mot de passe pour l'authentification IMAP
imap-server
serveur IMAP
imap-port
port IMAP
imap-ssl
se connecter au serveur IMAP en utilisant SSL
imap-mailbox
où nous devrions stocker les nouveaux messages

Configuration Maildir

maildir-path
Chemin du répertoire maildir dans lequel écrire les messages
maildir-mailbox
Boîte aux lettres dans maildir-path dans laquelle écrire les messages

Divers

user-agent
Chaîne à utiliser comme User-Agent HTTP dans les requêtes web et comme en-tête User-Agent dans les e-mails sortants. Si présent, __VERSION__ et __URL__ sont remplacés par le numéro de version de rss2email et la page web.
verbose
Verbosité (un parmi 'error', 'warning', 'info', ou 'debug').

FICHIERS

$XDG_CONFIG_HOME/rss2email.cfg
Si ce fichier existe, il est lu pour configurer le programme.
$XDG_DATA_HOME/rss2email.json
La base de données des flux. Utilisez r2e pour ajouter, supprimer ou modifier des flux, ne l'éditez pas directement.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement utilisées par r2e sont toutes définies dans la spécification XDG Base Directory, qui vise à standardiser les emplacements des fichiers de configuration et de données spécifiques à l'utilisateur.

XDG_CONFIG_HOME
Le répertoire préféré pour les fichiers de configuration. Par défaut, $HOME/.config.
XDG_DATA_HOME
Le répertoire préféré pour les fichiers de données. Par défaut, $HOME/.local/share.
XDG_RUNTIME_DIR
Le répertoire préféré pour les fichiers de verrouillage. Par défaut, /tmp/rss2email-UID
XDG_CONFIG_DIRS
Une liste d'ordres de préférence, séparée par des deux-points ':', de répertoires de base pour les fichiers de configuration en plus de $XDG_CONFIG_HOME. Par défaut, /etc/xdg. Si plusieurs fichiers de configuration sont trouvés dans ce chemin, ils seront tous lus par la classe ConfigParser (voir aussi CONFIGURATION ci-dessus).
XDG_DATA_DIRS
Une liste d'ordres de préférence, séparée par des deux-points ':', de répertoires de base pour les fichiers de données. Par défaut, /usr/local/share/:/usr/share/. Seul le premier fichier correspondant est utilisé.
