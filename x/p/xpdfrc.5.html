NOM

xpdfrc - fichier de configuration pour les outils Xpdf (version 4.05)

DESCRIPTION

Tous les outils Xpdf lisent un seul fichier de configuration.

Sur Linux/Unix/MacOS : si vous avez un fichier .xpdfrc dans votre répertoire personnel, il sera lu. Sinon, un fichier de configuration système sera lu à partir de /etc/xpdfrc, s'il existe. (C'est son emplacement par défaut ; selon les options de compilation, il peut être placé ailleurs.)

Sur Windows : le fichier doit s'appeler xpdfrc (pas de point de départ, pas d'extension), et doit être placé dans le même répertoire que l'exécutable (pdftotext.exe, xpdf.exe, etc.)

Le fichier xpdfrc est composé d'une série d'options de configuration, une par ligne. Les lignes vides et les lignes commençant par un ´#´ (commentaires) sont ignorées.

Les arguments peuvent être entre guillemets simples ou doubles, par exemple pour les noms de fichiers contenant des espaces ("aaa bbb", 'aaa bbb'). Ces guillemets ne fournissent aucune échappatoire, il n'y a donc aucun moyen d'inclure un guillemet double dans un argument entre guillemets doubles ou un guillemet simple dans un argument entre guillemets simples.

Les arguments peuvent également être entre guillemets @ : @"aaa bbb". Les chaînes entre guillemets @ permettent d'utiliser la variable DATADIR, qui est définie sur le sous-répertoire 'data' du répertoire d'installation xpdf. Le signe pourcentage (%) est un caractère d'échappement : un signe pourcentage suivi de n'importe quel autre caractère est remplacé par ce caractère.

@"abc %"def%" ghi" --> abc "def" ghi
@"${DATADIR}/foo"  --> ...répertoire-installation.../data/foo
@"%${DATADIR}/foo" --> ${DATADIR}/foo

Les sections suivantes répertorient toutes les options de configuration, triées par groupes fonctionnels. Il y a une section d'exemples à la fin.

FICHIERS INCLUS

include fichier-config
Inclut le fichier de configuration spécifié. L'effet de cette commande est équivalent à l'insertion du contenu de fichier-config directement dans le fichier de configuration parent à la place de la commande include. Les fichiers de configuration peuvent être imbriqués à volonté.

CONFIGURATION GENERALE DES POLICES

fontFile nom-police-PDF fichier-police
Mappe une police PDF, nom-police-PDF, à une police pour l'affichage ou la sortie PostScript. Le fichier de police, fichier-police, peut être de n'importe quel type autorisé dans un fichier PDF. Cette commande peut être utilisée pour les polices 8 bits ou 16 bits (CID).
fontDir répertoire
Spécifie un répertoire de recherche pour les fichiers de polices. Il peut y avoir plusieurs commandes fontDir ; tous les répertoires spécifiés seront recherchés dans l'ordre. Les fichiers de polices peuvent être de type Type 1 (.pfa ou .pfb) ou TrueType (.ttf ou .ttc) ; les autres fichiers du répertoire seront ignorés. Le nom du fichier de police (sans l'extension) doit correspondre exactement au nom de la police PDF. Cette recherche est effectuée si le nom de la police ne correspond à aucune des polices déclarées avec la commande fontFile. Il n'y a pas de répertoires fontDir par défaut.
fontFileCC collection-registry-ordering fichier-police
Mappe la collection de caractères collection-registry-ordering à une police pour l'affichage ou la sortie PostScript. Ce mappage est utilisé si le nom de la police ne correspond à aucune des polices déclarées avec les commandes fontFile, fontDir, psResidentFont16 ou psResidentFontCC.

CONFIGURATION DES POLICES POSTSCRIPT

psFontPassthrough oui | non
Si réglé sur "oui", transmet les noms de polices 8 bits à la sortie PostScript sans substitution. Les polices qui ne sont pas intégrées dans le fichier PDF sont supposées être disponibles sur l'imprimante. Ceci est réglé par défaut sur "non".
psResidentFont nom-police-PDF nom-police-PS
Lorsque la police 8 bits nom-police-PDF est utilisée (sans intégration) dans un fichier PDF, elle sera traduite en la police PostScript nom-police-PS, qui est supposée résider dans l'imprimante. Généralement, nom-police-PDF et nom-police-PS sont identiques. Par défaut, seules les polices Base-14 sont supposées résider.
psResidentFont16 nom-police-PDF wMode nom-police-PS encodage
Lorsque la police 16 bits (CID) nom-police-PDF avec le mode d'écriture wMode est utilisée (sans intégration) dans un fichier PDF, elle sera traduite en la police PostScript nom-police-PS, qui est supposée résider dans l'imprimante. Le mode d'écriture doit être soit ´H' pour horizontal, soit ´V' pour vertical. La police résidente est supposée utiliser l'encodage spécifié (qui doit avoir été défini avec la commande unicodeMap).
psResidentFontCC registry-ordering wMode nom-police-PS encodage
Lorsqu'une police 16 bits (CID) utilisant la collection de caractères registry-ordering et le mode d'écriture wMode est utilisée (sans intégration) dans un fichier PDF, la police PostScript, nom-police-PS, est substituée. La police substituée est supposée résider dans l'imprimante. Le mode d'écriture doit être soit ´H' pour horizontal, soit ´V' pour vertical. La police résidente est supposée utiliser l'encodage spécifié (qui doit avoir été défini avec la commande unicodeMap).
psEmbedType1Fonts oui | non
Si réglé sur "non", empêche l'intégration des polices Type 1 dans le PostScript généré. Ceci est réglé par défaut sur "oui".
psEmbedTrueTypeFonts oui | non
Si réglé sur "non", empêche l'intégration des polices TrueType dans le PostScript généré. Ceci est réglé par défaut sur "oui".
psEmbedCIDTrueTypeFonts oui | non
Si réglé sur "non", empêche l'intégration des polices CID TrueType dans le PostScript généré. Pour le PostScript de niveau 3, cela génère une police CID, pour les niveaux inférieurs, cela génère une police composite non CID. Ceci est réglé par défaut sur "oui".
psEmbedCIDPostScriptFonts oui | non
Si réglé sur "non", empêche l'intégration des polices CID PostScript dans le PostScript généré. Pour le PostScript de niveau 3, cela génère une police CID, pour les niveaux inférieurs, cela génère une police composite non CID. Ceci est réglé par défaut sur "oui".

CONTROLE POSTSCRIPT

psPaperSize largeur(pts) hauteur(pts)
Définit la taille du papier pour la sortie PostScript. Les paramètres largeur et hauteur donnent la taille du papier en points PostScript (1 point = 1/72 pouce).
psPaperSize letter | legal | A4 | A3 | match
Définit la taille du papier pour la sortie PostScript à une taille standard. La taille de papier par défaut est définie lors de la compilation de xpdf et pdftops, généralement sur "letter" ou "A4". Ceci peut également être réglé sur "match", ce qui définira la taille du papier pour correspondre à la taille spécifiée dans le fichier PDF.
psImageableArea llx lly urx ury
Définit la zone imprimable pour la sortie PostScript. Les quatre entiers sont les coordonnées des coins inférieur gauche et supérieur droit de la région imprimable, spécifiées en points (l'origine étant le coin inférieur gauche du papier). Ceci est par défaut la taille complète du papier ; l'option psPaperSize réinitialisera les coordonnées de la zone imprimable.
psCrop oui | non
Si réglé sur "oui", la sortie PostScript est rognée selon le CropBox spécifié dans le fichier PDF ; sinon, aucun rognage n'est effectué. Ceci est réglé par défaut sur "oui".

toUnicodeDir dir
Spécifie un répertoire de recherche, dir, pour les CMap ToUnicode. Il peut y avoir plusieurs répertoires ToUnicode. Il n'y a pas de répertoires ToUnicode par défaut.
mapNumericCharNames oui | non
Si défini sur « oui », les outils Xpdf tenteront de mapper divers noms de caractères numériques parfois utilisés dans les sous-ensembles de polices. Dans certains cas, cela conduit à un texte utilisable, et dans d'autres cas, cela conduit à du charabia — il n'y a aucun moyen pour Xpdf de le savoir. Ceci est défini par défaut sur « oui ».
mapUnknownCharNames oui | non
Si défini sur « oui », et que mapNumericCharNames est défini sur « non », les outils Xpdf appliqueront un simple mappage de passage (indice Unicode = code caractère) pour tous les noms de glyphes non reconnus. (Pour les polices CID, définir mapNumericCharNames sur « non » est inutile.) Dans certains cas, cela conduit à un texte utilisable, et dans d'autres cas, cela conduit à du charabia — il n'y a aucun moyen pour Xpdf de le savoir. Ceci est défini par défaut sur « non ».
mapExtTrueTypeFontsViaUnicode oui | non
Lors de la rastérisation de texte à l'aide d'une police TrueType externe, il existe deux options pour gérer les codes de caractères. Si mapExtTrueTypeFontsViaUnicode est défini sur « oui », Xpdf utilisera les informations d'encodage de la police/ToUnicode pour mapper les codes de caractères vers Unicode, puis utilisera le cmap Unicode de la police pour mapper Unicode vers les GID. Si mapExtTrueTypeFontsViaUnicode est défini sur « non », Xpdf supposera que les codes de caractères sont des GID (c'est-à-dire, utiliser un mappage d'identité). Ceci est défini par défaut sur « oui ».
useTrueTypeUnicodeMapping oui | non
Si défini sur « oui », les outils Xpdf utiliseront les informations d'encodage Unicode dans les polices TrueType (16 bits uniquement), si disponibles, pour remplacer les cartes ToUnicode du PDF. Sinon, les cartes ToUnicode sont toujours utilisées lorsqu'elles sont présentes. Ceci est défini par défaut sur « non ».
ignoreWrongSizeToUnicode oui | non
Si défini sur « oui », Xpdf ignorera toutes les CMap ToUnicode qui ne correspondent pas au type de police (8 bits contre 16 bits). La spécification PDF exige que les CMap ToUnicode correspondent, et Adobe semble ignorer les CMap qui ne correspondent pas. Ceci est défini par défaut sur « non » (pour des raisons de compatibilité ascendante).
dropFont nom-police
Supprime tout texte dessiné dans la police spécifiée. Pour supprimer le texte dessiné dans des polices sans nom, utilisez : 
    dropFont ""
Il peut y avoir n'importe quel nombre de commandes dropFont.
separateRotatedText oui | non
Si défini sur « non », pdftotext tentera de placer le texte pivoté à l'emplacement « correct » dans la sortie. Si défini sur « oui », lors de l'utilisation du mode d'ordre de lecture, pdftotext ajoutera le texte pivoté à la fin, après le texte non pivoté. Ceci est défini par défaut sur « non ».

PARAMÈTRES DU RASTÉRISEUR

enableFreeType oui | non
Active ou désactive l'utilisation de FreeType (un rastériseur de polices TrueType / Type 1). Ceci n'est pertinent que si les outils Xpdf ont été construits avec le support FreeType. ("enableFreeType" remplace l'ancienne option "freetypeControl".) Cette option est définie par défaut sur « oui ».
disableFreeTypeHinting oui | non
Si ceci est défini sur « oui », l'anticrénelage FreeType sera forcé à « off ». Cette option est définie par défaut sur « non ».
antialias oui | non
Active ou désactive l'anticrénelage de polices dans le rastériseur PDF. Cette option affecte tous les rastériseurs de polices. ("antialias" remplace le contrôle d'anticrénelage fourni par les anciennes options "t1libControl" et "freetypeControl".) Ceci est défini par défaut sur « oui ».
vectorAntialias oui | non
Active ou désactive l'anticrénelage des graphiques vectoriels dans le rastériseur PDF. Ceci est défini par défaut sur « oui ».
imageMaskAntialias oui | non
Active ou désactive l'anticrénelage des masques d'image (lors de la sous-échantillonnage ou sur-échantillonnage) dans le rastériseur PDF. Ceci est défini par défaut sur « oui ».
antialiasPrinting oui | non
Si ceci est « oui », les bitmaps envoyés à l'imprimante seront anticrénelés (conformément aux paramètres "antialias" et "vectorAntialias"). Si ceci est « non », les bitmaps imprimés ne seront pas anticrénelés. Ceci est défini par défaut sur « non ».
strokeAdjust oui | non | cad
Définit le mode d'ajustement des traits. S'il est défini sur « non », aucun ajustement des traits ne sera effectué. S'il est défini sur « oui », un ajustement normal des traits sera effectué : les lignes horizontales et verticales seront déplacées jusqu'à un demi-pixel pour les rendre plus nettes lorsque l'anticrénelage vectoriel est activé. S'il est défini sur « cad », un algorithme d'ajustement des traits légèrement différent sera utilisé pour garantir que les lignes de même largeur d'origine auront toujours la même largeur ajustée (au détriment de permettre des espaces et des chevauchements entre les lignes adjacentes). Ceci est défini par défaut sur « oui ».
forceAccurateTiling oui | non
Si ceci est défini sur « oui », le TilingType est forcé à 2 (pas de distorsion) pour tous les motifs de tramage, quelle que soit la définition dans le dictionnaire du motif. Ceci est défini par défaut sur « non ».
screenType dispersed | clustered | stochasticClustered
Définit le type de trame de demi-teintes, qui sera utilisé lors de la génération d'un bitmap monochrome (1 bit). Les trois options sont le tramage par points dispersés, le tramage par points groupés (avec un point rond et un angle de trame de 45 degrés), et le tramage par points groupés stochastiques. Par défaut, « stochasticClustered » est utilisé pour les résolutions de 300 dpi et plus, et « dispersed » est utilisé pour les résolutions inférieures à 300 dpi.
screenSize entier
Définit la taille de la matrice de seuil de la trame de demi-teintes (carrée). Par défaut, elle est de 4 pour le tramage par points dispersés, 10 pour le tramage par points groupés, et 100 pour le tramage par points groupés stochastiques.
screenDotRadius entier
Définit le rayon du point de la trame de demi-teintes. Ceci n'est utilisé que lorsque screenType est défini sur stochasticClustered, et il est défini par défaut sur 2. En mode points groupés, le rayon du point est la moitié de la taille de la trame. Le tramage par points dispersés n'a pas de rayon de point.
screenGamma flottant
Définit le paramètre de correction gamma de la trame de demi-teintes. Les valeurs gamma supérieures à 1 rendent la sortie plus lumineuse ; les valeurs gamma inférieures à 1 la rendent plus sombre. La valeur par défaut est 1.
screenBlackThreshold flottant
Lors du tramage, toutes les valeurs inférieures à ce seuil sont forcées à un noir plein. Ce paramètre est une valeur à virgule flottante comprise entre 0 (noir) et 1 (blanc). La valeur par défaut est 0.
screenWhiteThreshold flottant
Lors du tramage, toutes les valeurs supérieures à ce seuil sont forcées à un blanc plein. Ce paramètre est une valeur à virgule flottante comprise entre 0 (noir) et 1 (blanc). La valeur par défaut est 1.
minLineWidth flottant
Définit la largeur de ligne minimale, en pixels de périphérique. Ceci n'affecte que le rastériseur, pas le convertisseur PostScript (sauf lorsqu'il utilise la rastérisation pour gérer la transparence). La valeur par défaut est 0 (pas de minimum).
enablePathSimplification oui | non
Si défini sur « oui », simplifie les chemins en supprimant les points où cela ne ferait pas une différence significative pour la forme. La valeur par défaut est « non ».
overprintPreview oui | non
Si défini sur « oui », génère une sortie d'aperçu de surimpression, en respectant les paramètres OP/op/OPM dans le fichier PDF. Ignoré pour la sortie non CMJN. La valeur par défaut est « non ».

PARAMÈTRES DU VISUALISEUR

Ces paramètres ne s'appliquent qu'au visualiseur PDF GUI d'Xpdf.

initialZoom pourcentage | page | largeur
Définit le facteur de zoom initial. Un nombre spécifie un pourcentage de zoom, où 100 signifie 72 dpi. Vous pouvez également spécifier « page », pour ajuster la page à la taille de la fenêtre, ou « largeur », pour ajuster la largeur de la page à la largeur de la fenêtre.
defaultFitZoom pourcentage
Si xpdf est démarré avec un zoom ajuster-page ou ajuster-largeur et aucune géométrie de fenêtre, il calculera une taille de fenêtre souhaitée basée sur la taille de la page PDF et cette valeur defaultFitZoom. Autrement dit, la taille de la fenêtre sera choisie de manière à ce qu'une seule page tienne dans la fenêtre à ce facteur de zoom (qui doit être un pourcentage). La valeur par défaut est basée sur la résolution de l'écran.
zoomScaleFactor ratio | actuel
Les pourcentages de zoom seront mis à l'échelle par ce facteur. Par défaut, un zoom de 100 % correspond à 72 dpi. Définir zoomScaleFactor sur 1,5 rendra un zoom de 100 % 1,5 fois plus grand, c'est-à-dire 108 dpi. S'il est défini sur « actuel », le facteur de mise à l'échelle du zoom sera calculé en fonction de la résolution de l'écran. La valeur par défaut est 1,0.
zoomValues zoom1 zoom2 zoom3 ...
Définit la liste des valeurs de zoom (en pourcentage) affichées dans la liste déroulante de zoom. La liste par défaut est : 25 50 75 100 110 125 150 175 200 300 400 600 800.
initialDisplayMode single | continuous | sideBySideSingle | sideBySideContinuous | horizontalContinuous
Définit le mode d'affichage initial. Le réglage par défaut est "continuous".
initialToolbarState yes | no
Si défini sur "yes", xpdf s'ouvre avec la barre d'outils visible. Si défini sur "no", xpdf s'ouvre avec la barre d'outils masquée. La valeur par défaut est "yes".
initialSidebarState yes | no
Si défini sur "yes", xpdf s'ouvre avec la barre latérale (onglets, plan, etc.) visible. Si défini sur "no", xpdf s'ouvre avec la barre latérale réduite. La valeur par défaut est "yes".
initialSidebarWidth width
Définit la largeur initiale de la barre latérale, en pixels. Ceci n'est pertinent que si initialSidebarState est "yes". La valeur par défaut est zéro, ce qui indique à xpdf d'utiliser une taille par défaut interne.
initialSelectMode block | linear
Définit le mode de sélection initial. Le réglage par défaut est "linear".
paperColor color
Définit la couleur du "papier", c'est-à-dire l'arrière-plan de l'affichage de la page. La couleur peut être #RRGGBB (hexadécimal) ou un nom de couleur. Cette option ne fonctionnera pas bien avec les fichiers PDF qui font des choses comme remplir un fond blanc derrière le texte.
matteColor color
Définit la couleur mate, c'est-à-dire la couleur utilisée pour l'arrière-plan en dehors de la zone de page réelle. La couleur peut être #RRGGBB (hexadécimal) ou un nom de couleur.
fullScreenMatteColor color
Définit la couleur mate pour le mode plein écran. La couleur peut être #RRGGBB (hexadécimal) ou un nom de couleur.
selectionColor color
Définit la couleur de sélection. La couleur peut être #RRGGBB (hexadécimal) ou un nom de couleur.
reverseVideoInvertImages yes | no
Si défini sur "no", le mode vidéo inversée de xpdf inverse le texte et le contenu graphique vectoriel, mais pas les images. Si défini sur "yes", xpdf inverse également les images. La valeur par défaut est "no".
popupMenuCmd title command ...
Ajoute une commande au menu contextuel. Title est le texte à afficher dans le menu. Command est une commande Xpdf (voir la section COMMANDS de la page de manuel xpdf(1) pour plus de détails). Plusieurs commandes sont séparées par des espaces.
maxTileWidth pixels
Définit la largeur maximale des carreaux à utiliser par xpdf lors de la rastérisation des pages. La valeur par défaut est 1500.
maxTileHeight pixels
Définit la hauteur maximale des carreaux à utiliser par xpdf lors de la rastérisation des pages. La valeur par défaut est 1500.
tileCacheSize tiles
Définit le nombre maximum de carreaux à mettre en cache par xpdf lors de la rastérisation des pages. La valeur par défaut est 10.
workerThreads numThreads
Définit le nombre de threads de travail à utiliser par xpdf lors de la rastérisation des pages. La valeur par défaut est 1.
allowLinksToChangeZoom yes | no
Les liens PDF, y compris les éléments du plan, peuvent inclure un nouveau niveau de zoom. Si ce paramètre est "yes", Xpdf modifie le zoom lorsque les liens sont cliqués ; si "no", Xpdf se déplace vers la destination mais ne modifie pas le zoom. La valeur par défaut est "yes".
launchCommand command
Définit la commande exécutée lorsque vous cliquez sur un lien de type "launch". L'intention est que la commande soit un programme/script qui détermine le type de fichier et exécute le visualiseur approprié. La ligne de commande sera composée du fichier à lancer, suivi de tous les paramètres spécifiés avec le lien. N'utilisez pas "%s" dans "command". Par défaut, ceci n'est pas défini, et Xpdf essaiera simplement d'exécuter le fichier (après avoir demandé à l'utilisateur).
movieCommand command
Définit la commande exécutée lorsque vous cliquez sur une annotation de film. La chaîne "%s" sera remplacée par le nom du fichier du film. Ceci n'a pas de valeur par défaut.
defaultPrinter printer
Définit l'imprimante par défaut utilisée dans la boîte de dialogue d'impression du visualiseur.
bind modifiers-key context command ...
Ajoute une liaison de touche ou de bouton de souris. Modifiers peut être zéro ou plusieurs des éléments suivants : 
    shift-
    ctrl-
    alt-
Key peut être un caractère ASCII régulier, ou l'un des éléments suivants : 
    space
    tab
    return
    enter
    backspace
    esc
    insert
    delete
    home
    end
    pgup
    pgdn
    left / right / up / down                (touches fléchées)
    f1 .. f35                               (touches de fonction)
    mousePress1 .. mousePress7              (boutons de la souris)
    mouseRelease1 .. mouseRelease7          (boutons de la souris)
    mouseClick1 .. mouseClick7              (boutons de la souris)
    mouseDoubleClick1 .. mouseDoubleClick7  (boutons de la souris)
    mouseTripleClick1 .. mouseTripleClick7  (boutons de la souris)
Context est soit "any", soit une combinaison séparée par des virgules de : 
    fullScreen / window       (mode plein écran activé/désactivé)
    continuous / singlePage   (mode continu activé/désactivé)
    overLink / offLink        (souris sur un lien ou non)
    scrLockOn / scrLockOff    (verrouillage du défilement activé/désactivé)
La chaîne de contexte ne peut inclure qu'un seul élément de chaque paire dans la liste ci-dessus.

Command est une commande Xpdf (voir la section COMMANDS de la page de manuel xpdf(1) pour plus de détails). Plusieurs commandes sont séparées par des espaces.

La commande bind remplace toute liaison existante, mais seulement si elle a été définie pour les mêmes modificateurs, touche et contexte exacts. Tous les jetons (modificateurs, touche, contexte, commandes) sont sensibles à la casse.

Exemples de liaisons de touches :

    # lie ctrl-a dans n'importe quel contexte à la commande nextPage
    # suivante
    bind ctrl-a any nextPage
    # lie B majuscule, en mode continu
    # avec scroll lock activé, à la commande reload
    # suivie de la commande prevPage
    bind B continuous,scrLockOn reload prevPage
Voir la page de manuel xpdf(1) pour plus d'exemples.
unbind modifiers-key context
Supprime une liaison de touche établie avec la commande bind. Ceci est très utile pour supprimer les liaisons de touches par défaut avant d'en établir de nouvelles (par exemple, si la liaison de touche par défaut est donnée pour le contexte "any", et que vous souhaitez créer de nouvelles liaisons de touches pour plusieurs contextes).
tabStateFile path
Définit le fichier utilisé par les commandes loadTabState et saveTabState (voir la page de manuel xpdf(1) pour plus d'informations). Le chemin par défaut est ~/.xpdf.tabstate.
sessionFile path
Définit le fichier utilisé par les commandes saveSession et loadSession (voir la page de manuel xpdf(1) pour plus d'informations). Le chemin par défaut est ~/.xpdf.session. Lorsque xpdf enregistre automatiquement la session via un gestionnaire de session, il ajoute ".managed" au chemin.
saveSessionOnQuit yes | no
Si défini sur "yes", xpdf enregistrera automatiquement la session actuelle (équivalent à la commande saveSession) lors de la fermeture (via le menu ou une liaison de touche). La valeur par défaut est "yes".

PARAMÈTRES DIVERS

drawAnnotations yes | no
Si défini sur "no", les annotations ne seront pas dessinées ni imprimées. La valeur par défaut est "yes".
drawFormFields yes | no
Si défini sur "no", les champs de formulaire ne seront pas dessinés ni imprimés. La valeur par défaut est "yes".
enableXFA yes | no
Si un formulaire XFA est présent, et que cette option est définie sur "yes", Xpdf analysera le formulaire XFA et utilisera certaines informations XFA pour remplacer les informations AcroForm. Si défini sur "no", le formulaire XFA ne sera pas lu. La valeur par défaut est "yes".
savePageNumbers yes | no
Si défini sur "yes", xpdf enregistrera les numéros de page actuels de tous les fichiers ouverts dans ~/.xpdf.pages lors de la fermeture des fichiers (ou lors de la sortie de xpdf). La prochaine fois que le fichier sera ouvert, le numéro de page précédemment consulté sera restauré. La valeur par défaut est "yes".
printCommands yes | no
Si défini sur "yes", les commandes de dessin sont imprimées au fur et à mesure de leur exécution (utile pour le débogage). Par défaut, c'est "no".
printStatusInfo
Si défini sur "yes", un message d'état est imprimé (sur stdout) avant le traitement de chaque page. Par défaut, c'est "no".
errQuiet yes | no
Si défini sur "yes", cela supprime tous les messages d'erreur et d'avertissement de tous les outils Xpdf. Par défaut, c'est "no".

/etc/xpdfrc

C'est le fichier de configuration de l'utilisateur. S'il existe, il sera lu à la place du fichier de configuration du système.
