NOM

xtables-nft — iptables utilisant l'API du noyau nftables

DESCRIPTION

xtables-nft sont des versions d'iptables qui utilisent l'API nftables. Il s'agit d'un ensemble d'outils pour aider l'administrateur système à migrer l'ensemble des règles de iptables(8), ip6tables(8), arptables(8), et ebtables(8) vers nftables(8).

L'ensemble xtables-nft est composé de plusieurs commandes :

•
iptables-nft
•
iptables-nft-save
•
iptables-nft-restore
•
ip6tables-nft
•
ip6tables-nft-save
•
ip6tables-nft-restore
•
arptables-nft
•
ebtables-nft

Ces outils utilisent les extensions de la structure libxtables et s'accrochent au sous-système du noyau nf_tables via le module nft_compat.

UTILISATION

Les outils xtables-nft vous permettent de gérer le backend nf_tables en utilisant la syntaxe native de iptables(8), ip6tables(8), arptables(8), et ebtables(8).

Vous devriez utiliser les outils xtables-nft exactement de la même manière que vous utiliseriez les outils originaux correspondants.

L'ajout d'une règle se traduira par l'ajout de cette règle au sous-système du noyau nf_tables. La liste des règles utilisera également le backend nf_tables.

Lorsque ces outils ont été conçus, l'idée principale était de remplacer chaque binaire hérité par un lien symbolique vers le programme xtables-nft, par exemple :

/sbin/iptables -> /usr/sbin/iptables-nft-multi
/sbin/ip6tables -> /usr/sbin/ip6tables-nft-multi
/sbin/arptables -> /usr/sbin/arptables-nft-multi
/sbin/ebtables -> /usr/sbin/ebtables-nft-multi

La chaîne de version d'iptables indiquera si l'API héritée (get/setsockopt) ou la nouvelle API nf_tables est utilisée :

iptables -V
iptables v1.7 (nf_tables)

DIFFÉRENCES AVEC IPTABLES LEGACY

Comme les outils xtables-nft utilisent l'API du noyau nf_tables, l'ajout et la suppression de règles sont toujours atomiques. Contrairement à iptables-legacy, iptables-nft -A .. n'aura PAS besoin de récupérer l'ensemble des règles actuel du noyau, de le modifier et de recharger l'ensemble modifié. Au lieu de cela, iptables-nft demandera au noyau d'ajouter une règle. Pour cette raison, l'option --wait d'iptables-legacy est une opération vide dans iptables-nft.

L'utilisation des outils xtables-nft permet de surveiller les changements de l'ensemble des règles à l'aide de la commande xtables-monitor(8).

Lorsque vous utilisez -j TRACE pour déboguer le parcours des paquets dans l'ensemble des règles, notez que vous devrez utiliser xtables-monitor(8) en mode --trace pour obtenir des événements de suivi de surveillance.

EXEMPLES

Un exemple de base consiste à créer la structure de règles dans nf_tables à partir des outils xtables-nft, sur une machine fraîchement installée :

root@machine:~# iptables-nft -L
[...]
root@machine:~# ip6tables-nft -L
[...]
root@machine:~# arptables-nft -L
[...]
root@machine:~# ebtables-nft -L
[...]
root@machine:~# nft list ruleset
table ip filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}
table ip6 filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}
table bridge filter {
	chain INPUT {
		type filter hook input priority -200; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority -200; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority -200; policy accept;
	}
}
table arp filter {
	chain INPUT {
		type filter hook input priority 0; policy accept;
	}
	chain FORWARD {
		type filter hook forward priority 0; policy accept;
	}
	chain OUTPUT {
		type filter hook output priority 0; policy accept;
	}
}

(Veuillez noter que sur les machines fraîchement installées, la première liste de l'ensemble des règles entraîne la création de toutes les tables et chaînes).

Pour migrer votre ensemble de règles de filtrage complet, dans le cas d'iptables(8), vous utiliseriez :

root@machine:~# iptables-legacy-save > myruleset # lit depuis x_tables
root@machine:~# iptables-nft-restore myruleset   # écrit dans nf_tables
ou 
root@machine:~# iptables-legacy-save | iptables-translate-restore | less

pour voir à quoi ressembleraient les règles dans la syntaxe nft(8) de nft.

LIMITATIONS

Vous devriez utiliser le noyau Linux >= 4.17.

La cible CLUSTERIP n'est pas prise en charge.

Pour obtenir des informations à jour à ce sujet, veuillez vous rendre sur http://wiki.nftables.org/.
