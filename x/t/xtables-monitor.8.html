NOM

xtables-monitor — affiche les modifications de l'ensemble de règles et les événements de traçage

SYNTAXE

xtables-monitor [-t] [-e] [-4||-6]

DESCRIPTION

xtables-monitor est utilisé pour surveiller les modifications de l'ensemble de règles ou pour afficher les événements d'évaluation des règles pour les paquets marqués à l'aide de la cible TRACE. xtables-monitor s'exécute jusqu'à ce que l'utilisateur interrompe l'exécution, généralement en utilisant CTRL-C.

OPTIONS

-e, --event

Surveille les mises à jour de l'ensemble de règles.
Les mises à jour incluent la création de nouvelles tables, chaînes et règles, ainsi que le nom du programme qui a provoqué la mise à jour de la règle.
-t, --trace
Surveille les événements de traçage générés par les paquets marqués à l'aide de la cible TRACE.
-4
Restreint la sortie à IPv4.
-6
Restreint la sortie à IPv6.

EXEMPLE DE SORTIE

xtables-monitor --trace


1 TRACE: 2 fc475095 raw:PREROUTING:rule:0x3:CONTINUE -4 -t raw -A PREROUTING -p icmp -j TRACE
2 PACKET: 0 fc475095 IN=lo LL=0x304 0000000000000000000000000800 SRC=127.0.0.1 DST=127.0.0.1 LEN=84 TOS=0x0 TTL=64 ID=38349DF
3 TRACE: 2 fc475095 raw:PREROUTING:return:
4 TRACE: 2 fc475095 raw:PREROUTING:policy:ACCEPT
5 TRACE: 2 fc475095 filter:INPUT:return:
6 TRACE: 2 fc475095 filter:INPUT:policy:DROP
7 TRACE: 2 0df9d3d8 raw:PREROUTING:rule:0x3:CONTINUE -4 -t raw -A PREROUTING -p icmp -j TRACE

La première ligne montre un paquet entrant dans l'évaluation des règles. Le numéro de protocole est affiché (AF_INET dans ce cas), puis un numéro d'identification de paquet qui permet de corréler les messages venant de l'évaluation des règles de ce paquet. Après cela, la règle qui a correspondu au paquet est affichée. C'est la règle TRACE qui active les événements de traçage pour ce paquet.

La deuxième ligne affiche des informations sur le paquet. L'interface entrante et les en-têtes de paquet tels que les adresses source et destination sont affichés.

La troisième ligne montre que le paquet a terminé la traversée de la chaîne PREROUTING de la table raw, et qu'il revient, suivi de l'utilisation de la politique de chaîne pour prendre une décision d'acceptation/rejet (l'exemple montre que l'acceptation est appliquée). La cinquième ligne montre que le paquet quitte la chaîne INPUT du filtre, c'est-à-dire qu'aucune règle de la chaîne INPUT de la table de filtrage n'a correspondu au paquet. Il a ensuite été REJETÉ par la politique de la table INPUT, comme le montre la ligne six. La dernière ligne montre l'arrivée d'un autre paquet -- l'identifiant du paquet est différent.

Lors de l'utilisation de la cible TRACE, il est généralement judicieux de ne sélectionner que les paquets pertinents, par exemple via

iptables -t raw -A PREROUTING -p tcp --dport 80 --syn -m limit --limit 1/s -j TRACE
xtables-monitor --event

1 EVENT: nft: NEW table: table filter ip flags 0 use 4 handle 444
2 EVENT: # nft: ip filter INPUT use 2 type filter hook input prio 0 policy drop packets 0 bytes 0
3 EVENT: # nft: ip filter FORWARD use 0 type filter hook forward prio 0 policy accept packets 0 bytes 0
4 EVENT: # nft: ip filter OUTPUT use 0 type filter hook output prio 0 policy accept packets 0 bytes 0
5 EVENT: -4 -t filter -N TCP
6 EVENT: -4 -t filter -A TCP -s 192.168.0.0/16 -p tcp -m tcp --dport 22 -j ACCEPT
7 EVENT: -4 -t filter -A TCP -p tcp -m multiport --dports 80,443 -j ACCEPT
8 EVENT: -4 -t filter -A INPUT -p tcp -j TCP
9 EVENT: -4 -t filter -A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
10 NEWGEN: GENID=13904 PID=25167 NAME=iptables-nftables-restore

Cet exemple montre la surveillance des événements. La ligne un montre la création d'une table (filter dans ce cas), suivie de trois crochets de base INPUT, FORWARD et OUTPUT. Les outils iptables-nftables créent tous les tables et les chaînes de base automatiquement lorsque nécessaire, donc ceci est attendu lorsqu'une table n'a pas encore été initialisée ou lorsqu'elle est recréée à partir de zéro par iptables-nftables-restore. La ligne cinq montre l'ajout d'une nouvelle chaîne définie par l'utilisateur (TCP), suivi de l'ajout de quelques règles. La dernière ligne montre qu'une nouvelle génération de règles est devenue active, c'est-à-dire que les modifications de l'ensemble de règles sont maintenant actives. Cela liste également l'identifiant du processus et le nom du programme.

LIMITATIONS

xtables-monitor ne fonctionne qu'avec les règles ajoutées en utilisant iptables-nftables, les règles ajoutées en utilisant iptables-legacy ne peuvent pas être surveillées.
