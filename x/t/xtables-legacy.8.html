NOM

xtables-legacy — iptables utilisant l'ancienne API du noyau basée sur getsockopt/setsockopt

DESCRIPTION

xtables-legacy sont les versions originales d'iptables qui utilisent l'ancienne interface noyau basée sur getsockopt/setsockopt. Cette interface noyau a certaines limitations, par conséquent iptables peut aussi être utilisé avec la nouvelle API basée sur nf_tables. Voir xtables-nft(8) pour des informations sur les variantes d'iptables basées sur xtables-nft.

UTILISATION

Le binaire xtables-legacy-multi peut être lié aux noms traditionnels :

/sbin/iptables -> /sbin/iptables-legacy-multi
/sbin/ip6tables -> /sbin/ip6tables-legacy-multi
/sbin/iptables-save -> /sbin/ip6tables-legacy-multi
/sbin/iptables-restore -> /sbin/ip6tables-legacy-multi

La chaîne de version d'iptables indiquera si l'API héritée (get/setsockopt) ou la nouvelle API nf_tables est utilisée :

iptables -V
iptables v1.7 (legacy)

LIMITATIONS

Lors de l'insertion d'une règle à l'aide de iptables -A ou iptables -I, iptables doit d'abord récupérer l'ensemble de règles actives actuel, le modifier pour inclure la nouvelle règle, puis réengager le résultat. Cela signifie que si deux instances d'iptables s'exécutent simultanément, l'une des mises à jour pourrait être perdue. Ceci peut être partiellement contourné avec l'option --wait.

Il n'y a pas non plus de méthode pour surveiller les changements de l'ensemble de règles, sauf en appelant périodiquement iptables-legacy-save et en vérifiant les différences dans la sortie. xtables-monitor(8) nécessitera les versions xtables-nft(8) pour fonctionner, il ne peut pas afficher les changements effectués à l'aide des outils iptables-legacy.
