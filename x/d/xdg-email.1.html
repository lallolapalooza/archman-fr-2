NOM

xdg-email - outil en ligne de commande pour envoyer des courriels en utilisant le compositeur de courriels préféré de l'utilisateur

SYNTAXE

xdg-email [--utf8] [--cc adresse] [--bcc adresse] [--subject texte] [--body texte] [--attach fichier] [uri-mailto | adresse(s)]

xdg-email {--help | --manual | --version}

DESCRIPTION

xdg-email ouvre le compositeur de courriels préféré de l'utilisateur afin d'envoyer un courriel à adresse(s) ou uri-mailto. Le RFC2368 définit les URI mailto:. xdg-email limite le support aux champs 'to', 'cc', 'subject' et 'body' dans uri-mailto, tous les autres champs sont ignorés silencieusement. adresse(s) doit suivre la syntaxe du RFC822. Plusieurs adresses peuvent être fournies comme arguments séparés.

Toutes les informations fournies en ligne de commande sont utilisées pour pré-remplir les champs correspondants dans le compositeur de courriels de l'utilisateur. L'utilisateur aura la possibilité de modifier ces informations avant d'envoyer réellement le courriel.

xdg-email est destiné à être utilisé à l'intérieur d'une session de bureau uniquement. Il n'est pas recommandé d'utiliser xdg-email en tant que root.

OPTIONS

--utf8

Indique que toutes les options de ligne de commande qui suivent sont en utf8. Sans cette option, les options de ligne de commande sont attendues être encodées selon la locale. Si la locale spécifie déjà utf8, cette option n'a aucun effet. Cette option n'affecte pas les URI mailto qui sont passés sur la ligne de commande.

--cc adresse

Spécifie un destinataire à mettre en copie du courriel.

--bcc adresse

Spécifie un destinataire à mettre en copie cachée du courriel.

--subject texte

Spécifie un sujet pour le courriel.

--body texte

Spécifie un corps pour le courriel. Étant donné que l'utilisateur pourra apporter des modifications avant d'envoyer le courriel, ceci peut être utilisé pour fournir à l'utilisateur un modèle de courriel. texte peut contenir des sauts de ligne.

--attach fichier

Spécifie une pièce jointe pour le courriel. fichier doit pointer vers un fichier existant.

Certaines applications de courriels exigent que le fichier reste présent après que xdg-email ait retourné.

--help

Affiche la syntaxe de la commande.

--manual

Affiche cette page de manuel.

--version

Affiche les informations de version de xdg-utils.

VARIABLES D'ENVIRONNEMENT

xdg-email respecte les variables d'environnement suivantes :

XDG_UTILS_DEBUG_LEVEL

Définir cette variable d'environnement à une valeur numérique non nulle fait en sorte que xdg-email fournisse des rapports plus verbeux sur stderr. Une valeur plus élevée augmente la verbosité.

CODES DE SORTIE

Un code de sortie de 0 indique le succès, tandis qu'un code de sortie non nul indique un échec. Les codes d'échec suivants peuvent être retournés :

1

Erreur dans la syntaxe de la ligne de commande.

2

Un des fichiers passés sur la ligne de commande n'a pas existé.

3

Un outil requis n'a pas pu être trouvé.

4

L'action a échoué.

5

Aucune permission pour lire un des fichiers passés sur la ligne de commande.

VOIR AUSSI

xdg-open(1), xdg-mime(1), Spécification des associations d'applications MIME[1], RFC 6068 - Le schéma d'URI 'mailto'[2]

EXEMPLES

xdg-email 'Jeremy White <jwhite@example.com>'
xdg-email --attach /tmp/logo.png \
          --subject 'Concours de logo' \
          --body 'Vous trouverez ci-joint le logo pour le concours.' \
          'jwhite@example.com'
xdg-email --subject 'Votre mot de passe va expirer' \
          'jwhite@example.com' 'bastian@example.com' 'whipple@example.com'
