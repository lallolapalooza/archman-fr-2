NOM

XDP-monitor - un outil simple de surveillance XDP basé sur BPF

SYNTAXE

XDP-monitor est un outil qui surveille diverses statistiques et événements liés à XDP en utilisant l'infrastructure des points de trace BPF, en essayant d'avoir une surcharge aussi faible que possible.

Notez que par défaut, les statistiques pour les événements de redirection XDP réussis sont désactivées, car cela entraîne une surcharge de traçage BPF par paquet, qui, bien que de faible surcharge, peut dégrader le traitement des paquets.

Cet outil repose sur l'infrastructure des points de trace bruts BPF du noyau.

Il y a plus d'informations sur la signification de la sortie, en mode de sortie par défaut (concis) et en mode détaillé, dans la section Description du format de sortie.

Exécution de xdp-monitor

La syntaxe pour exécuter xdp-monitor est :

xdp-monitor [options]

Les options supportées sont :

-i, --interval <SECONDES>

Définit l'intervalle de scrutation pour la collecte de toutes les statistiques et leur affichage. L'unité de l'intervalle est en secondes.

-s, --stats

Active les statistiques pour la redirection réussie. Cette option entraîne une surcharge de traçage par paquet, pour enregistrer toutes les redirections réussies.

-e, --extended

Démarre xdp-bench en mode de sortie « étendu ». S'il n'est pas défini, xdp-bench démarrera en mode « concis ». Le mode de sortie peut être changé en appuyant sur Ctrl + \ pendant que le programme s'exécute. Voir également la section Description du format de sortie ci-dessous.

-v, --verbose

Active la journalisation détaillée. Fournissez deux fois pour activer la journalisation détaillée des bibliothèques sous-jacentes libxdp et libbpf.

--version

Affiche la version de l'application et quitte.

-h, --help

Affiche un résumé des options disponibles.

Description du format de sortie

Par défaut, les statistiques de réussite de redirection sont désactivées, utilisez --stats pour les activer. Le mode de sortie concis est le défaut, le mode de sortie étendu peut être activé en utilisant l'option de ligne de commande --extended.

SIGQUIT (Ctrl + \) peut être utilisé pour changer le mode dynamiquement à l'exécution.

Le mode concis affiche au plus les champs suivants :

rx/s		Nombre de paquets reçus par seconde
redir/s	Nombre de paquets redirigés avec succès par seconde
err,drop/s	Nombre agrégé d'erreurs par seconde (y compris les paquets abandonnés)
xmit/s	Nombre de paquets transmis sur le périphérique de sortie par seconde

Le mode de sortie détaillé affiche au plus les champs suivants :

CHAMP		  DESCRIPTION
receive	       Affiche le nombre de paquets reçus et les erreurs rencontrées
                        Chaque fois qu'une erreur ou un abandon de paquet se produit, les détails
                        par CPU des erreurs et des paquets abandonnés sont développés en ligne
                        en mode concis.
                                        pkt/s		- Paquets reçus par seconde
                                        drop/s		- Paquets abandonnés par seconde
                                        error/s		- Erreurs rencontrées par seconde
                                        redirect	- Affiche le nombre de paquets redirigés avec succès
                       Les erreurs rencontrées sont développées sous le champ
                       redirect_err
                       Notez que passer -s pour l'activer a une surcharge par paquet
                                        redir/s		- Paquets redirigés avec succès par seconde
redirect_err	  Affiche le nombre de paquets dont la redirection a échoué
                        L'errno est développé sous ce champ avec un compte par CPU
                       Les erreurs reconnues sont :
                                        EINVAL:		Redirection invalide
                                        ENETDOWN:	Le périphérique vers lequel rediriger est hors service
                                        EMSGSIZE:	La taille du paquet est trop grande pour le périphérique
                                        EOPNOTSUPP:	Opération non supportée
                                        ENOSPC:		Pas d'espace dans le ptr_ring du kthread de cpumap
                                        error/s		- Paquets dont la redirection a échoué par seconde
enqueue to cpu N Affiche le nombre de paquets mis en file d'attente dans la file d'attente groupée du CPU N
                       Se développe en cpu:FROM->N pour afficher les statistiques
                       d'enfilement pour chaque CPU qui enfile vers le CPU N
                       Les paquets reçus peuvent être associés au CPU auquel le programme
                       de redirection XDP met en file d'attente des paquets.
                                        pkt/s		- Paquets mis en file d'attente par seconde depuis un autre CPU vers le CPU N
                                        drop/s		- Paquets abandonnés lors de la tentative d'enfilement vers le CPU N
                                        bulk-avg	- Nombre moyen de paquets traités pour chaque événement
kthread	       Affiche le nombre de paquets traités dans le kthread CPUMAP pour chaque CPU
                       Paquets consommés à partir du ptr_ring dans le kthread, et ses xdp_stats
                       (après l'appel du programme bpf CPUMAP) sont développés ci-dessous.
                       Les xdp_stats sont développés comme un total, puis par CPU pour
                       les associer au kthread CPUMAP de chaque CPU.
                                        pkt/s		- Paquets consommés par seconde à partir du ptr_ring
                                        drop/s		- Paquets abandonnés par seconde dans le kthread
                                        sched		- Nombre de fois où le kthread a appelé schedule()
                       xdp_stats (se développe également en comptes par CPU)
                                        pass/s		- Compte XDP_PASS pour l'exécution du programme CPUMAP
                                        drop/s		- Compte XDP_DROP pour l'exécution du programme CPUMAP
                                        redir/s		- Compte XDP_REDIRECT pour l'exécution du programme CPUMAP
xdp_exception	  Affiche les événements de point de trace xdp_exception
                        Cela peut se produire en raison d'erreurs internes du pilote,
                        d'actions XDP non reconnues et en raison d'un déclenchement
                        explicite par l'utilisateur via XDP_ABORTED
                       Chaque action est développée sous ce champ avec son compte
                                        hit/s		- Nombre de fois où le point de trace a été atteint par seconde
devmap_xmit      Affiche les événements de point de trace devmap_xmit
                        Ce point de trace est appelé pour les transmissions réussies sur le
                        périphérique de sortie, mais ces statistiques ne sont pas disponibles
                        pour le mode XDP générique, elles seront donc omises de la sortie
                        lors de l'utilisation du mode SKB
                                        xmit/s		- Nombre de paquets transmis par seconde
                                        drop/s		- Nombre de paquets dont la transmission a échoué par seconde
                                        drv_err/s	- Nombre d'erreurs internes du pilote par seconde
                                        bulk-avg	- Nombre moyen de paquets traités pour chaque événement

NOM

xdp-monitor — Moniteur XDP pour le trafic réseau.

SYNTAXE

xdp-monitor [options]

Description du format de sortie

Le programme xdp-monitor affiche des informations sur le trafic réseau intercepté par le programme XDP. Le format de sortie est conçu pour être lisible par l'homme et peut contenir des détails tels que les adresses source et destination, les ports, les protocoles, et des statistiques sur les paquets.
