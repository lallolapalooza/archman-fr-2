NOM

xdpdump - un outil simple de type tcpdump pour capturer des paquets au niveau XDP

SYNOPSIS

xdpdump est un outil simple de capture de paquets XDP qui tente de se comporter de manière similaire à tcpdump, mais il n'a pas de capacités de filtrage ou de décodage de paquets.

Ceci peut être utilisé pour déboguer les programmes XDP qui sont déjà chargés sur une interface. Les paquets peuvent être sauvegardés/inspectés avant d'entrer dans le programme XDP (à l' entrée), ou après en être sorti (à la sortie). De plus, à la sortie, l'action XDP est également capturée. Cela signifie que même les paquets qui sont rejetés au niveau XDP peuvent être capturés via cet outil.

xdpdump fonctionne en attachant un programme de trace bpf à la fonction d'entrée et/ou de sortie XDP qui stocke le paquet brut dans un tampon de trace perf. Si aucun programme XDP n'est chargé, cette approche ne peut pas être utilisée et l'outil utilisera une capture en direct libpcap pour être rétrocompatible.

Exécution de xdpdump

La syntaxe pour exécuter xdpdump est :

Usage: xdpdump [options]
 Outil XDPDump pour sauvegarder le trafic réseau
Options:
     --rx-capture <mode>    Point de capture pour la direction rx (valeurs valides : entry,exit)
 -D, --list-interfaces      Imprimer la liste des interfaces disponibles
 -i, --interface <ifname>   Nom de l'interface sur laquelle capturer
     --perf-wakeup <events>  Réveiller xdpdump tous les <events> paquets
 -p, --program-names <prog>  Programme spécifique à attacher
 -s, --snapshot-length <snaplen>  Nombre d'octets minimum à capturer par paquet
     --use-pcap             Utiliser le format pcap hérité pour les traces XDP
 -w, --write <file>         Écrire les paquets bruts dans un fichier pcap
 -x, --hex                  Imprimer le paquet complet en hexadécimal
 -v, --verbose              Activer la journalisation détaillée (-vv : plus de détails)
     --version              Afficher les informations de version
 -h, --help                 Afficher cette aide

Les options expliquées

L'outil xdpdump tente d'imiter les options de base de tcpdump, mais au cas où, ci-dessous, chacune des options disponibles est expliquée :

--rx-capture <mode>

Spécifie où le paquet entrant est capturé. Soit à l'entrée du programme XDP, soit à la sortie du programme XDP, soit aux deux. Les options valides sont entry, exit, ou les deux entry,exit. Le paquet à la sortie peut être modifié par le programme XDP. Si vous souhaitez voir le paquet original et modifié, utilisez l'option entry,exit. Avec cela, chaque paquet est capturé deux fois. La valeur par défaut pour ceci est entry.

-D, --list-interfaces

Affiche une liste des interfaces disponibles et de tout programme XDP chargé.

--load-xdp-mode

Spécifie quel mode chargeur utiliser avec l'option --load-xdp-program. Les valeurs valides sont ‘native’, qui est le mode XDP par défaut dans le pilote, ‘skb’, qui provoque l'utilisation du mode dit skb (également connu sous le nom de XDP générique), ‘hw’ qui provoque le déchargement du programme sur le matériel, ou ‘unspecified’ qui laisse le soin au noyau de choisir un mode (il choisira le mode natif si le pilote le prend en charge, sinon le mode générique). Notez que l'utilisation de ‘unspecified’ peut rendre difficile de prédire dans quel mode un programme sera finalement chargé. Pour cette raison, la valeur par défaut est ‘native’.

--load-xdp-program

Si aucun programme XDP n'est chargé sur l'interface, par défaut, xdpdump reviendra au mode de capture en direct de libpcap pour capturer les paquets. Alternativement, avec cette option, vous pouvez demander à xdpdump de charger un programme XDP pour capturer directement les paquets.

-i, --interface <ifname>

Écoute sur l'interface ifname. Notez que si aucun programme XDP n'est chargé sur l'interface, il utilisera le mode de capture en direct de libpcap pour capturer les paquets.

--perf-wakeup <events>

Permet au noyau de réveiller xdpdump une fois pour chaque <events> posté dans le tampon d'anneau perf. Plus le nombre est élevé, moins l'impact sur le programme XDP réel est important. La valeur par défaut est 0, ce qui calcule automatiquement la valeur en fonction des CPU/tampons disponibles. Utilisez -v pour voir la valeur réellement utilisée.

-p, --program-names [<prog>|all]

Cette option vous permet de capturer des paquets pour un ou plusieurs programmes XDP spécifiques, ou tous les programmes XDP chargés sur l'interface. Vous pouvez spécifier les noms de programmes réels ou les ID de programmes séparés par des virgules. Dans le cas où plusieurs programmes sont attachés avec le même nom, vous devriez utiliser l'ID du programme. Utilisez l'option -D pour voir les programmes chargés et leurs ID.

De plus, l'API Linux ne fournit pas le nom complet de la fonction d'entrée eBPF attachée si elle dépasse 15 caractères. xdpdump essaiera de deviner le nom de fonction correct à partir des informations de débogage BTF disponibles. Cependant, si plusieurs fonctions existent avec le même nom de préfixe, il ne pourra pas choisir la bonne. Il affichera les fonctions disponibles, et vous pourrez choisir la bonne et la fournir avec cette option. Si vous avez des programmes avec des noms longs dupliqués, vous devrez également spécifier l'ID du programme avec le nom complet. Cela peut être fait en ajoutant l'ID au nom avec le suffixe @<id>.

-P, --promiscuous-mode

Cette option met l'interface en mode promiscuous.

-s, --snapshot-length <snaplen>

Capture snaplen octets d'un paquet plutôt que les 262144 octets par défaut.

--use-pcap

Utilise le format pcap hérité pour les traces XDP. Par défaut, il utilisera le format PcapNG afin de pouvoir stocker diverses métadonnées.

-w, --write <file>

Écrit les paquets bruts dans un fichier pcap au lieu de les imprimer en hexadécimal. La sortie standard est utilisée si file est -.

-x, --hex

Lors de la sauvegarde des paquets sur la console, imprime également le contenu complet du paquet en hexadécimal.

-v, --verbose

Active la journalisation de débogage. Spécifiez deux fois pour encore plus de détails.

--version

Affiche les informations de version de xpdump et quitte.

-h, --help

Affiche un résumé des options disponibles.

Exemples

Ce qui suit chargera le programme xdp-filter sur eth0, mais il n'effectuera aucun filtrage réel :

# xdp-filter load --mode skb eth0
#
# xdpdump -D
Interface        Prio  Nom du programme      Mode     ID   Tag               Chaîne actions
--------------------------------------------------------------------------------------
lo                     <Aucun programme XDP chargé !>
eth0                   xdp_dispatcher    skb      10651 d51e469e988d81da
 =>              10     xdpfilt_alw_all           10669 0b394f43ab24501c  XDP_PASS

Maintenant, nous pouvons essayer xdpdump :

xdpdump(8)

NAME

xdpdump ― dump XDP packets captured by the kernel

SYNOPSIS

xdpdump [ -i interface ] [ -x ] [ -w file ] [ -c count ] [ --rx-capture mode ] [ -p program ] [ --json ] [ --verbose ]

The options explained

The following options are available:

-i interface
Specify the network interface to capture packets from.
-x
Display packet contents in hexadecimal format.
-w file
Write captured packets to the specified file. Use '-' to write to standard output.
-c count
Capture only count packets.
--rx-capture mode
Specify the capture mode. Supported modes are: entry, exit, entry,exit.
-p program
Capture packets only for the specified XDP program(s). You can specify program names or their IDs. Use commas to separate multiple programs.
--json
Output captured packets in JSON format.
--verbose
Increase verbosity of output.
