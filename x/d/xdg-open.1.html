NOM

xdg-open - ouvre un fichier ou une URL dans l'application préférée de l'utilisateur

SYNOPIS

xdg-open {fichier | URL}

xdg-open {--help | --manual | --version}

DESCRIPTION

xdg-open ouvre un fichier ou une URL dans l'application préférée de l'utilisateur. Si une URL est fournie, l'URL sera ouverte dans le navigateur web préféré de l'utilisateur. Si un fichier est fourni, le fichier sera ouvert dans l'application préférée pour les fichiers de ce type. xdg-open prend en charge les URL de type file, ftp, http et https.

xdg-open est destiné à être utilisé uniquement dans une session de bureau. Il n'est pas recommandé d'utiliser xdg-open en tant que root.

Comme xdg-open ne peut pas gérer les arguments commençant par un “-”, il est recommandé de passer les chemins de fichiers d'une des manières suivantes :

•Passer des chemins absolus, c'est-à-dire en utilisant realpath comme préprocesseur.
•Préfixer les chemins relatifs connus par un “./”. Par exemple, en utilisant sed -E 's|^[^/]|./\0|'.
•Passer une URL de fichier.

OPTIONS

--help

Affiche le synopsis de la commande.

--manual

Affiche cette page de manuel.

--version

Affiche les informations de version de xdg-utils.

CODES DE RETOUR

Un code de retour de 0 indique le succès tandis qu'un code de retour non nul indique un échec. Les codes d'échec suivants peuvent être retournés :

1

Erreur dans la syntaxe de la ligne de commande.

2

Un des fichiers passés en ligne de commande n'existait pas.

3

Un outil requis n'a pas pu être trouvé.

4

L'action a échoué.

En cas de succès, le processus lancé depuis le fichier .desktop ne sera pas détaché (forké) et xdg-open pourrait donc s'exécuter pendant un temps très long. Ce comportement diffère intentionnellement de la plupart des ouvreurs spécifiques aux bureaux pour permettre aux applications en ligne de commande de s'exécuter en utilisant le même terminal à partir duquel xdg-open a été appelé.

SIGNALEMENT DES PROBLÈMES

Veuillez garder à l'esprit que xdg-open hérite de la plupart des défauts de sa configuration et de l'ouvreur sous-jacent.

Dans le cas où la commande xdg-mime query default "$(xdg-mime query filetype path/to/troublesome_file)" nomme le programme responsable d'un comportement inattendu, vous pouvez corriger cela en définissant un gestionnaire différent. (Si le programme est défectueux, informez les développeurs)

Consultez également la note de sécurité sur xdg-mime(1) pour la sous-commande par défaut.

Si un défaut est reproductible en utilisant l'ouvreur spécifique au bureau (et qu'il ne s'agit pas d'un problème de configuration) : Veuillez d'abord en informer la personne responsable (signaler à xdg-utils est mieux que de ne pas signaler du tout, mais comme les utilitaires xdg sont maintenus avec très peu de temps libre, une correction prendra beaucoup plus de temps)

En cas de problème spécifique à xdg-open, veuillez le signaler à https://gitlab.freedesktop.org/xdg/xdg-utils/-/issues .

VOIR AUSSI

xdg-mime(1), xdg-settings(1), Spécification des associations d'applications MIME[1]

EXEMPLES

xdg-open 'http://www.freedesktop.org/'

Ouvre le site web freedesktop.org dans le navigateur par défaut de l'utilisateur.

xdg-open /tmp/foobar.png

Ouvre le fichier image PNG /tmp/foobar.png dans l'application de visualisation d'images par défaut de l'utilisateur.
