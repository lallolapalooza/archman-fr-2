NOM

xdp-forward - le plan de transmission XDP

SYNOPSIS

xdp-forward est un plan de transmission XDP, qui accélérera la transmission de paquets en utilisant XDP. Pour l'utiliser, chargez-le simplement sur l'ensemble des interfaces pour lesquelles vous souhaitez accélérer la transmission. Le composant en espace utilisateur de xdp-forward configurera ensuite et chargera les programmes XDP sur ces interfaces, et transmettra les paquets entre elles en utilisant XDP_REDIRECT, en utilisant la table de routage du noyau ou la table de flux netfilter pour déterminer la destination de chaque paquet.

Tout paquet que xdp-forward ne sait pas comment transmettre sera passé à la pile réseau et géré par le noyau comme d'habitude. Selon le mode dans lequel xdp-forward est chargé, cela conduit à différents comportements de transmission. Voir la section sur les Modes de fonctionnement ci-dessous.

Exécution de xdp-forward

La syntaxe pour exécuter xdp-forward est :

xdp-forward COMMANDE [options]
Où COMMANDE peut être l'une des suivantes :
       load        - Charger le plan de transmission XDP
       unload      - Décharger le plan de transmission XDP
       help        - afficher la liste des commandes disponibles

Chaque commande et ses options sont expliquées ci-dessous. Ou utilisez xdp-forward COMMANDE --help pour voir les options de chaque commande.

La commande LOAD

La commande load charge le plan de transmission XDP sur une liste d'interfaces.

La syntaxe de la commande load est :

xdp-forward load [options] <ifname...>

Où <ifname...> est le nom de l'ensemble des interfaces entre lesquelles transmettre les paquets. Un programme XDP sera chargé sur chaque interface, configuré pour transmettre les paquets à toutes les autres interfaces de l'ensemble (en utilisant la table de routage du noyau pour déterminer l'interface de destination de chaque paquet).

Les options prises en charge sont :

-f, --fwd-mode <mode>

Spécifie le mode de transmission dans lequel xdp-forward doit opérer. Selon le mode sélectionné, xdp-forward effectuera la transmission de différentes manières, ce qui peut conduire à différents comportements, y compris quel sous-ensemble de configuration du noyau (comme les règles de pare-feu) est respecté pendant la transmission. Voir la section MODES DE TRANSMISSION ci-dessous pour une description complète de chaque mode.

-F, --fib-mode <mode>

Spécifie comment xdp-forward effectue la recherche dans la table de routage du noyau Linux. Voir la section MODES FIB ci-dessous pour une description complète de chaque mode.

-m, --mode <mode>

Spécifie le mode dans lequel charger le programme XDP. Les valeurs valides sont 'native', qui est le mode XDP natif dans le pilote par défaut, 'skb', qui provoque l'utilisation du soi-disant mode skb (également connu sous le nom de XDP générique), 'hw' qui provoque le déchargement du programme vers le matériel, ou 'unspecified' qui laisse le noyau choisir un mode (il choisira le mode natif si le pilote le prend en charge, ou le mode générique sinon). Notez que l'utilisation de 'unspecified' peut rendre difficile la prédiction du mode dans lequel un programme sera finalement chargé. Pour cette raison, la valeur par défaut est 'native'. Notez que le matériel prenant en charge le mode 'hw' est rare : les cartes Solarflare (utilisant le pilote 'sfc') sont les seuls périphériques prenant en charge cela dans le noyau Linux principal.

-v, --verbose

Activer la journalisation de débogage. Spécifiez deux fois pour une verbosité encore plus grande.

-h, --help

Afficher un résumé des options disponibles

La commande UNLOAD

La commande unload est utilisée pour décharger les programmes d'une interface.

La syntaxe de la commande unload est :

xdp-forward unload [options] <ifname...>

Où <ifname...> est la liste des interfaces à partir desquelles décharger le plan de transmission XDP. Notez que bien que xdp-forward examine les programmes XDP chargés sur chaque interface et s'assure de ne décharger que son propre programme, il ne vérifiera pas que la liste des interfaces fournies est identique à celle fournie lors du chargement. En tant que tel, il est possible d'effectuer un déchargement partiel en fournissant une liste d'interfaces différente, ce qui peut entraîner un comportement inattendu.

Les options prises en charge sont :

-v, --verbose

Activer la journalisation de débogage. Spécifiez deux fois pour une verbosité encore plus grande.

-h, --help

Afficher un résumé des options disponibles

MODES DE TRANSMISSION

L'utilitaire xdp-forward prend en charge les modes de transmission suivants (sélectionnés par le paramètre --fwd-mode de xdp-forward load.

fib (par défaut)

En mode de transmission fib, xdp-forward effectuera une recherche dans la table de routage du noyau (ou FIB) pour chaque paquet, et transmettra les paquets entre les interfaces configurées en fonction du résultat de la recherche. Tout paquet pour lequel la recherche échoue sera transmis à la pile. Cela inclut les paquets qui nécessitent une découverte de voisin pour le prochain saut, ce qui signifie que les paquets passeront périodiquement par la pile du noyau pour la découverte du prochain saut (initialement, et lorsque l'entrée du prochain saut expire).

Notez qu'aucune vérification autre que la recherche FIB n'est effectuée ; en particulier, cela contourne complètement le sous-système netfilter, donc les règles de pare-feu ne seront pas vérifiées avant la transmission.

flowtable

Le mode de fonctionnement flowtable décharge la logique de table de flux netfilter logicielle dans la couche XDP si la table de flux matérielle n'est pas disponible. Actuellement, xdp-forward est capable de décharger uniquement les entrées de table de flux netfilter TCP ou UDP vers XDP. L'utilisateur est censé configurer la table de flux séparément.

MODES FIB

L'utilitaire xdp-forward prend en charge les modes fib suivants (sélectionnés par le paramètre --fib-mode de xdp-forward load.

full (par défaut)

En mode de fonctionnement full, xdp-forward effectuera une recherche complète dans la table de routage du noyau (ou FIB) pour chaque paquet, et transmettra les paquets entre les interfaces configurées en fonction du résultat de la recherche. En particulier, il appliquera toutes les règles de routage de politique configurées par l'utilisateur.

direct

Le mode direct fonctionne comme full, sauf qu'il transmet le drapeau BPF_FIB_LOOKUP_DIRECT à la routine de recherche FIB. Cela signifie que toutes les règles de routage de politique configurées seront ignorées pendant la recherche, ce qui peut améliorer les performances (mais ne respectera évidemment pas la politique de ces règles).

Exemples

Pour activer le déchargement de la table de flux pour le trafic tcp et udp entre les cartes réseau n0 et n1, émettez les commandes suivantes :

#nft -f /dev/stdin <<EOF
table inet filter {
    flowtable ft {
        hook ingress priority filter
        devices = { n0, n1 }
    }
    chain forward {
        type filter hook forward priority filter
        meta l4proto { tcp, udp } flow add @ft
    }
}
EOF
#xdp-forward load -f flowtable n0 n1

xdp-forward - XDP packet forwarder

SYNOPSIS

xdp-forward [options] [interface[@queue]]...

The LOAD command

The load command loads the xdp-forward eBPF program to the specified interface. It will bind to all queues on the interface by default. The program is specified via the -S or -n option to the xdp-forward command. The program will be loaded in native mode by default. Setting the -N or -d option will load the program in the driver mode or the generic mode, respectively.

The -r, -l, -i, -m and -c options can be used to specify the forwarding mode, the FIB mode, the interface to use, the map file and the core to bind to, respectively.

See the xdp-forward --help output for a full list of options.

The UNLOAD command

The unload command unloads the xdp-forward eBPF program from the specified interface. It will unbind from all queues on the interface by default.

The -r, -l, -i, -m and -c options can be used to specify the forwarding mode, the FIB mode, the interface to use, the map file and the core to bind to, respectively.

See the xdp-forward --help output for a full list of options.

FORWARDING_MODES

The -r option can be used to specify the forwarding mode. The following modes are supported:

rr
Round-robin forwarding to all interfaces.
fib
Forwarding based on the FIB (Forwarding Information Base).
vlan
VLAN-aware forwarding.

FIB MODES

The -l option can be used to specify the FIB mode. The following modes are supported:

lpm
Longest prefix match (LPM) based FIB lookup.
hash
Hash based FIB lookup.

Examples

Load the xdp-forward program in native mode on interface eth0:

xdp-forward -n eth0

Load the xdp-forward program in driver mode on interface eth0, using FIB mode with LPM lookup and round-robin forwarding:

xdp-forward -d -l lpm -r rr eth0

Unload the xdp-forward program from interface eth0:

xdp-forward -u eth0
