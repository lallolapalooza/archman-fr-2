NOM

xdg-desktop-menu - outil en ligne de commande pour (dé)l'installation d'éléments de menu de bureau

SYNTAXE

xdg-desktop-menu install [--noupdate] [--novendor] [--mode mode] fichier-répertoire(s) fichier-bureau(s)

xdg-desktop-menu uninstall [--noupdate] [--mode mode] fichier-répertoire(s) fichier-bureau(s)

xdg-desktop-menu forceupdate [--mode mode]

xdg-desktop-menu {--help | --manual | --version}

DESCRIPTION

Le programme xdg-desktop-menu peut être utilisé pour installer de nouvelles entrées de menu dans le menu des applications du bureau.

Le menu des applications fonctionne selon la spécification XDG des menus de bureau à l'adresse http://www.freedesktop.org/wiki/Specifications/menu-spec

COMMANDES

install

Installe une ou plusieurs applications dans un sous-menu du système de menu du bureau.

fichier-bureau: Un fichier de bureau représente une seule entrée de menu dans le menu. Les fichiers de bureau sont définis par la spécification de fichier d'entrée de bureau de freedesktop.org. Les aspects les plus importants des fichiers *.desktop sont résumés ci-dessous.

Les entrées de menu peuvent être ajoutées au système de menu de deux manières différentes. Elles peuvent être ajoutées à un sous-menu prédéfini dans le système de menu, basé sur un ou plusieurs mots-clés de catégorie, ou elles peuvent être ajoutées à un nouveau sous-menu.

Pour ajouter une entrée de menu à un sous-menu prédéfini, le fichier de bureau représentant l'entrée de menu doit avoir une entrée Categories= qui liste un ou plusieurs mots-clés. L'élément de menu sera inclus dans un sous-menu approprié en fonction des mots-clés inclus.

Pour ajouter des éléments de menu à un nouveau sous-menu, les fichiers de bureau doivent être précédés d'un fichier répertoire qui décrit le sous-menu. Si plusieurs fichiers de bureau sont spécifiés, toutes les entrées seront ajoutées au même menu. Si des entrées sont installées dans un menu qui a été créé avec un appel précédent à xdg-desktop-menu, les entrées seront installées en plus de toutes les entrées déjà existantes.

fichier-répertoire: Le fichier *.directory indiqué par fichier-répertoire représente un sous-menu. Le fichier répertoire fournit le nom et l'icône d'un sous-menu. Le nom du fichier répertoire est utilisé pour identifier le sous-menu.

Si plusieurs fichiers répertoire sont fournis, chaque fichier représentera un sous-menu dans le menu qui le précède, créant une hiérarchie de menus imbriqués (sous-sous-menus). Les entrées de menu seront ajoutées au dernier sous-menu.

Les fichiers répertoire suivent la syntaxe définie par la spécification de fichier d'entrée de bureau de freedesktop.org.

uninstall

Supprime les applications ou les sous-menus du système de menu du bureau précédemment installés avec xdg-desktop-menu install.

Un sous-menu et le fichier répertoire associé ne sont supprimés que lorsque le sous-menu ne contient plus aucune entrée de menu.

forceupdate

Force la mise à jour du système de menus.

Cette commande n'est utile que si le dernier appel à xdg-desktop-menu incluait l'option --noupdate.

OPTIONS

--noupdate

Retarde la mise à jour du système de menus. Si plusieurs modifications sont apportées au système de menus en séquence, ce drapeau peut être utilisé pour indiquer que d'autres modifications suivront et qu'il n'est pas nécessaire de mettre à jour le système de menus immédiatement.

--novendor

Normalement, xdg-desktop-menu vérifie que tous les fichiers *.directory et *.desktop à installer ont un préfixe de vendeur. Cette option peut être utilisée pour désactiver cette vérification.

Un préfixe de vendeur se compose de caractères alphabétiques ([a-zA-Z]) et est terminé par un tiret ("-"). Les entreprises et les organisations sont encouragées à utiliser un mot ou une phrase, de préférence le nom de l'organisation, pour lequel elles détiennent une marque commerciale, comme préfixe de vendeur. Le but du préfixe de vendeur est d'éviter les conflits de noms.

--mode mode

mode peut être user ou system. En mode utilisateur, le fichier est (dé)installé uniquement pour l'utilisateur courant. En mode système, le fichier est (dé)installé pour tous les utilisateurs du système. Habituellement, seul root est autorisé à installer en mode système.

Par défaut, le mode système est utilisé lorsqu'il est appelé par root et le mode utilisateur lorsqu'il est appelé par un utilisateur non-root.

--help

Affiche la syntaxe de la commande.

--manual

Affiche cette page de manuel.

--version

Affiche les informations de version de xdg-utils.

FICHIERS DE BUREAU

Une entrée d'application dans le menu des applications est représentée par un fichier *.desktop. Un fichier *.desktop se compose d'un en-tête [Desktop Entry] suivi de plusieurs lignes Clé=Valeur.

Un fichier *.desktop peut fournir un nom et une description pour une application dans plusieurs langues différentes. Ceci est fait en ajoutant un code de langue tel qu'utilisé par LC_MESSAGES entre crochets derrière la Clé. De cette façon, on peut spécifier différentes valeurs pour la même Clé en fonction de la langue actuellement sélectionnée.

Les clés suivantes sont souvent utilisées :

Type=Application

Il s'agit d'un champ obligatoire qui indique que le fichier *.desktop décrit un lanceur d'application.

Name=Nom de l'application

Le nom de l'application. Par exemple Mozilla

GenericName=Nom générique

Une description générique de l'application. Par exemple Navigateur Web

Comment=Commentaire

Champ optionnel pour spécifier une infobulle pour l'application. Par exemple Visiter des sites web sur Internet

Icon=Fichier d'icône

L'icône à utiliser pour l'application. Il peut s'agir soit d'un chemin absolu vers un fichier image, soit d'un nom d'icône. Si un nom d'icône est fourni, une recherche d'image par nom est effectuée dans le thème d'icônes actuel de l'utilisateur. La commande xdg-icon-resource peut être utilisée pour installer des fichiers image dans des thèmes d'icônes. L'avantage d'utiliser un nom d'icône au lieu d'un chemin absolu est qu'avec un nom d'icône, l'icône de l'application peut être fournie dans plusieurs tailles différentes ainsi que dans plusieurs styles thématiques différents.

Exec=Ligne de commande

La ligne de commande pour lancer l'application. Si l'application peut ouvrir des fichiers, le spécificateur %f doit être fourni. Lorsqu'un fichier est glissé sur le lanceur d'application, %f est remplacé par le chemin du fichier déposé. Si plusieurs fichiers peuvent être spécifiés sur la ligne de commande, le spécificateur %F doit être utilisé à la place de %f. Si l'application est capable d'ouvrir des URL en plus des fichiers locaux, alors %u ou %U peuvent être utilisés à la place de %f ou %F.

Categories=Catégories

Une liste de catégories séparées par des points-virgules. Une catégorie est un mot-clé qui décrit et classe l'application. Par défaut, les applications sont organisées dans le menu des applications en fonction de leur catégorie. Lorsque les entrées de menu sont explicitement assignées à un nouveau sous-menu, il n'est pas nécessaire de lister de catégories.

Lors de l'utilisation de catégories, il est recommandé d'inclure l'une des catégories suivantes : AudioVideo, Development, Education, Game, Graphics, Network, Office, Settings, System, Utility.

Voir l'Annexe A de la Spécification XDG des menus de bureau pour des informations sur les catégories supplémentaires : http://standards.freedesktop.org/menu-spec/menu-spec-1.0.html#category-registry

MimeType=Mimetypes

Une liste de types MIME séparés par des points-virgules. Ce champ est utilisé pour indiquer les types de fichiers que l'application est capable d'ouvrir.

Pour un aperçu complet du format des fichiers *.desktop, veuillez visiter http://www.freedesktop.org/wiki/Specifications/desktop-entry-spec

NAME

xdg-desktop-menu - Add or remove desktop files from the freedesktop.org application menu

SYNOPSIS

xdg-desktop-menu command [options] [files...]

DESCRIPTION

The xdg-desktop-menu tool can be used to install and uninstall desktop files in the freedesktop.org application menu and its submenus.

Desktop files are configuration files for applications that are used to provide information about the application to the desktop environment. This information includes the application's name, icon, and the command to execute to start it.

The freedesktop.org application menu is a hierarchical menu system that is used to organize and present the installed applications to the user. The menu system is based on a set of XML files that define the structure and contents of the menu.

xdg-desktop-menu allows you to add or remove desktop files to the menu system, thereby making your applications visible to the user. It also allows you to create and manage submenus.

COMMANDS

install
Installs the given desktop files and/or directory files into the application menu. If no files are given, then all files in the current directory will be installed.
uninstall
Uninstalls the given desktop files and/or directory files from the application menu. If no files are given, then all files in the current directory will be uninstalled.
forceupdate
Forces an update of the application menu. This is useful if you have made changes to the menu structure or contents and want to ensure that the changes are reflected immediately.

OPTIONS

--noupdate
Do not perform an update of the application menu after installing or uninstalling files. This can be useful if you are installing multiple files and want to perform a single update at the end.
--autostart
Install the desktop file as an autostart entry.
--nomaid
Do not prompt the user for confirmation before installing or uninstalling files.
--help
Show help message and exit.
--version
Show version information and exit.

DESKTOP FILES

Desktop files are INI-style files containing key-value pairs. They are used to describe applications and can be used to integrate them into the desktop environment. A desktop file must start with a [Desktop Entry] header.

The following keys are relevant for desktop files:

Type
Specifies the type of the entry. For applications, this must be Application.
Name
The name of the application as it should be displayed in the menu. It can also be translated using language codes, e.g. Name[nl]=WebSpiegel.
Exec
The command to execute to start the application. This can include arguments.
Icon
The icon to use for the application. This can be an icon name (e.g. webmirror) or an absolute path to an icon file.
Categories
A semicolon-separated list of categories that the application belongs to. This is used to organize the application in the menu. For example: Categories=Network;WebDevelopment;.

DIRECTORY FILES

A .directory file is used to define a submenu in the application menu. It has the same format as a desktop file, starting with a [Desktop Entry] header followed by several Key=Value lines.

A *.directory file can provide a title (name) for the submenu in several different languages. This is done by adding a language code as used by LC_MESSAGES in square brackets behind the Key. This way one can specify different values for the same Key depending on the currently selected language.

The following keys are relevant for submenus:

Type=Directory

This is a mandatory field that indicates that the *.directory file describes a submenu.

Name=Menu Name

The title of submenu. For example Mozilla

Comment=Comment

Optional field to specify a tooltip for the submenu.

Icon=Icon File

The icon to use for the submenu. This can either be an absolute path to an image file or an icon-name. If an icon-name is provided an image lookup by name is done in the user's current icon theme. The xdg-icon-resource command can be used to install image files into icon themes. The advantage of using an icon-name instead of an absolute path is that with an icon-name the submenu icon can be provided in several different sizes as well as in several differently themed styles.

ENVIRONMENT VARIABLES

xdg-desktop-menu honours the following environment variables:

XDG_UTILS_DEBUG_LEVEL

Setting this environment variable to a non-zero numerical value makes xdg-desktop-menu do more verbose reporting on stderr. Setting a higher value increases the verbosity.

XDG_UTILS_INSTALL_MODE

This environment variable can be used by the user or administrator to override the installation mode. Valid values are user and system.

EXIT CODES

An exit code of 0 indicates success while a non-zero exit code indicates failure. The following failure codes can be returned:

1

Error in command line syntax.

2

One of the files passed on the command line did not exist.

3

A required tool could not be found.

4

The action failed.

5

No permission to read one of the files passed on the command line.

SEE ALSO

xdg-desktop-icon(1), xdg-icon-resource(1), xdg-mime(1), Desktop entry specification[1], Desktop menu specification[2]

EXAMPLES

The company ShinyThings Inc. has developed an application named "WebMirror" and would like to add it to the application menu. The company will use "shinythings" as its vendor id. In order to add the application to the menu there needs to be a .desktop file with a suitable Categories entry:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
  Categories=Network;WebDevelopment;

Now the xdg-desktop-menu tool can be used to add the shinythings-webmirror.desktop file to the desktop application menu:

xdg-desktop-menu install ./shinythings-webmirror.desktop

Note that for the purpose of this example the menu items are available in two languages, English and Dutch. The language code for Dutch is nl.

In the next example the company ShinyThings Inc. will add its own submenu to the desktop application menu consisting of a "WebMirror" menu item and a "WebMirror Admin Tool" menu item.

First the company needs to create two .desktop files that describe the two menu items. Since the items are to be added to a new submenu it is not necessary to include a Categories= line:

shinythings-webmirror.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror
  Icon=shinythings-webmirror
  Name=WebMirror
  Name[nl]=WebSpiegel
shinythings-webmirror-admin.desktop:
  [Desktop Entry]
  Encoding=UTF-8
  Type=Application
  Exec=webmirror-admintool
  Icon=shinythings-webmirror-admintool
  Name=WebMirror Admin Tool
  Name[nl]=WebSpiegel Administratie Tool

In addition a .directory file needs to be created to provide a title and icon for the sub-menu itself:

shinythings-webmirror.directory:
  [Desktop Entry]
  Encoding=UTF-8
  Icon=shinythings-webmirror-menu
  Name=WebMirror
  Name[nl]=WebSpiegel

These file can now be installed with:

xdg-desktop-menu install ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop ./shinythings-webmirror-admin.desktop

The menu entries could also be installed one by one:

xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror.desktop
xdg-desktop-menu install --noupdate ./shinythings-webmirror.directory \
      ./shinythings-webmirror-admin.desktop
xdg-desktop-menu forceupdate

Although the result is the same it is slightly more efficient to install all files at the same time.

The *.desktop and *.directory files reference icons with the names webmirror, webmirror-admin and webmirror-menu which should also be installed. In this example the icons are installed in two different sizes, once with a size of 22x22 pixels and once with a size of 64x64 pixels:

xdg-icon-resource install --size 22 ./wmicon-22.png shinythings-webmirror
xdg-icon-resource install --size 22 ./wmicon-menu-22.png shinythings-webmirror-menu
xdg-icon-resource install --size 22 ./wmicon-admin-22.png shinythings-webmirror-admin
xdg-icon-resource install --size 64 ./wmicon-64.png shinythings-webmirror
xdg-icon-resource install --size 64 ./wmicon-menu-64.png shinythings-webmirror-menu
xdg-icon-resource install --size 64 ./wmicon-admin-64.png shinythings-webmirror-admin
