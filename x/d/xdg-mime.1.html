XDG-MIME(1) Manuel xdg-mime XDG-MIME(1)

NOM

xdg-mime - outil en ligne de commande pour interroger les informations sur la gestion des types de fichiers et ajouter des descriptions pour de nouveaux types de fichiers

SYNTAXE

xdg-mime query {filetype FICHIER | default type_mime}

xdg-mime default application type(s)_mime

xdg-mime install [--mode mode] [--novendor] fichier-types-mime

xdg-mime uninstall [--mode mode] fichier-types-mime

xdg-mime {--help | --manual | --version}

DESCRIPTION

Le programme xdg-mime peut être utilisé pour interroger les informations sur les types de fichiers et pour ajouter des descriptions pour de nouveaux types de fichiers.

COMMANDES

query filetype

Retourne le type de fichier de FICHIER sous forme de type MIME.

Veuillez noter que les noms de FICHIER commençant par un - seront rejetés, cela peut être atténué :

•Utilisez des chemins absolus, c'est-à-dire en utilisant realpath comme préprocesseur.
•Préfixez les chemins de fichiers relatifs connus avec un “./”. Par exemple, en utilisant sed -E 's|^[^/]|./\0|' comme préprocesseur.

L'option query filetype est réservée à une utilisation dans une session de bureau uniquement. Il n'est pas recommandé d'utiliser xdg-mime query filetype en tant que root.

query default

Retourne l'application par défaut que l'environnement de bureau utilise pour ouvrir les fichiers de type type_mime. L'application par défaut est identifiée par son fichier *.desktop.

La valeur renvoyée par cette commande peut correspondre ou non à l'application lancée par xdg-open, car xdg-open délègue souvent à des ouvreurs spécifiques au bureau qui peuvent implémenter leur propre logique.

L'option query default est réservée à une utilisation dans une session de bureau uniquement. Il n'est pas recommandé d'utiliser xdg-mime query default en tant que root.

default

Demande à l'environnement de bureau de faire de application l'application par défaut pour ouvrir les fichiers de type type_mime. Une application peut devenir le gestionnaire par défaut pour plusieurs types de fichiers en spécifiant plusieurs types MIME.

application est l'identifiant du fichier .desktop de l'application et a la forme nom-vendeur.desktop. application doit déjà être installé dans le menu des applications avant de pouvoir être désigné comme gestionnaire par défaut. Le fichier .desktop de l'application doit lister la prise en charge de tous les types MIME pour lesquels il souhaite être le gestionnaire par défaut.

Les demandes pour faire d'une application un gestionnaire par défaut peuvent être soumises à la politique du système ou à l'approbation de l'utilisateur final. xdg-mime query peut être utilisé pour vérifier si une application est le gestionnaire par défaut réel pour un type de fichier spécifique.

Note de sécurité : Ne définissez jamais un gestionnaire qui exécutera aveuglément du code ou des commandes à partir du fichier traité. Un tel comportement conduira tôt ou tard à une exécution de code non intentionnelle, par exemple via un utilisateur curieux essayant d'inspecter un fichier fraîchement téléchargé mais l'exécutant par accident.

Garder les actions d'ouverture et d'exécution séparées aide les gens à se protéger contre les logiciels malveillants, le gestionnaire par défaut est un ouvreur, pas un exécuteur.

L'option default est réservée à une utilisation dans une session de bureau uniquement. Il n'est pas recommandé d'utiliser xdg-mime default en tant que root.

install

Ajoute les descriptions de types de fichiers fournies dans fichier-types-mime à l'environnement de bureau. fichier-types-mime doit être un fichier XML qui suit la spécification de la base de données Shared MIME-info de freedesktop.org et qui a un élément mime-info comme racine de document. Pour chaque nouveau type de fichier, une ou plusieurs icônes nommées type-sous-type doivent être installées avec la commande xdg-icon-resource dans le contexte mimetypes. Par exemple, le type de fichier application/vnd.oasis.opendocument.text nécessite une icône nommée application-vnd.oasis.opendocument.text installée (sauf si le type de fichier recommande un autre nom d'icône).

uninstall

Supprime les descriptions de types de fichiers fournies dans fichier-types-mime et précédemment ajoutées avec xdg-mime install de l'environnement de bureau. fichier-types-mime doit être un fichier XML qui suit la spécification de la base de données Shared MIME-info de freedesktop.org et qui a un élément mime-info comme racine de document.

OPTIONS

--mode mode

mode peut être user ou system. En mode utilisateur, le fichier est (dés)installé pour l'utilisateur actuel uniquement. En mode système, le fichier est (dés)installé pour tous les utilisateurs du système. Habituellement, seul root est autorisé à installer en mode système.

La valeur par défaut est d'utiliser le mode système lorsqu'il est appelé par root et le mode utilisateur lorsqu'il est appelé par un utilisateur non root.

--novendor

Normalement, xdg-mime vérifie que le fichier-types-mime à installer a un préfixe vendeur approprié. Cette option peut être utilisée pour désactiver cette vérification.

Un préfixe vendeur se compose de caractères alphabétiques ([a-zA-Z]) et est terminé par un tiret ("-"). Les entreprises et organisations sont encouragées à utiliser un mot ou une phrase, de préférence le nom de l'organisation, pour lequel elles détiennent une marque commerciale comme préfixe vendeur. Le but du préfixe vendeur est d'éviter les conflits de noms.

--help

Affiche la syntaxe de la commande.

--manual

Affiche cette page de manuel.

--version

Affiche les informations de version de xdg-utils.

VARIABLES D'ENVIRONNEMENT

xdg-mime respecte les variables d'environnement suivantes :

XDG_UTILS_DEBUG_LEVEL

Définir cette variable d'environnement sur une valeur numérique non nulle fait que xdg-mime génère des rapports plus détaillés sur stderr. Une valeur plus élevée augmente la verbosité.

XDG_UTILS_INSTALL_MODE

Cette variable d'environnement peut être utilisée par l'utilisateur ou l'administrateur pour outrepasser le mode d'installation. Les valeurs valides sont user et system.

CODES DE RETOUR

Un code de retour de 0 indique le succès, tandis qu'un code de retour non nul indique un échec. Les codes d'échec suivants peuvent être renvoyés :

1

Erreur de syntaxe dans la ligne de commande.

2

Un des fichiers passés en ligne de commande n'existait pas.

3

Un outil requis n'a pas pu être trouvé.

4

L'action a échoué.

5

Pas la permission de lire l'un des fichiers passés en ligne de commande.

VOIR AUSSI

xdg-icon-resource(1), xdg-desktop-menu(1), Spécification de la base de données Shared MIME[1], Spécification des associations d'applications MIME[2]

EXEMPLES

xdg-mime query filetype /tmp/foobar.png

Affiche le type MIME du fichier /tmp/foobar.png, dans ce cas image/png

xdg-mime query default image/png

Affiche le nom du fichier .desktop de l'application qui est enregistrée pour ouvrir les fichiers PNG.

xdg-mime install shinythings-shiny.xml

Ajoute une description de type de fichier pour les fichiers "shiny". "shinythings-" est utilisé comme préfixe vendeur. La description du type de fichier pourrait ressembler à ceci.

shinythings-shiny.xml:
<?xml version="1.0"?>
<mime-info xmlns='http://www.freedesktop.org/standards/shared-mime-info'>
  <mime-type type="text/x-shiny">
    <comment>Nouveau type de fichier Shiny</comment>
    <glob pattern="*.shiny"/>
    <glob pattern="*.shi"/>
  </mime-type>
</mime-info>

Une icône pour ce nouveau type de fichier doit également être installée, par exemple avec :

xdg-icon-resource install --context mimetypes --size 64 shiny-file-icon.png text-x-shiny
