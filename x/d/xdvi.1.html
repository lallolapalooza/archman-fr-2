DESCRIPTION

Xdvi est un programme d'aperçu de fichiers dvi, tels que produits par exemple par le programme tex(1), sous le système X Window.

Xdvi peut afficher le fichier réduit par divers facteurs entiers, et il dispose d'une "loupe" pour visualiser des parties de la page agrandies (voir la section LOUPE ci-dessous). Cette version de xdvi est aussi référencée sous le nom de xdvik car elle utilise la bibliothèque kpathsea pour localiser et générer les fichiers de polices. De plus, elle supporte les fonctionnalités suivantes :

-
liens hypertextes dans les fichiers DVI (section LIENS HYPERTEXTES),
-
rendu direct des polices PostScript<tm> de Type 1 (section POLICES DE TYPE 1),
-
spéciaux de source dans le fichier DVI (section SPÉCIAUX DE SOURCE),
-
recherche de chaînes dans les fichiers DVI (section RECHERCHE DE CHAINES),
-
sauvegarde ou impression (de parties) du fichier DVI (sections DIALOGUE D'IMPRESSION et DIALOGUE DE SAUVEGARDE).

Xdvi peut être compilé avec la boîte à outils Motif ou la boîte à outils Xaw (Athena) (et ses variantes), et la version Motif a une interface graphique légèrement différente ; ces différences sont notées ci-dessous.

Avant d'afficher une page d'un fichier DVI, xdvi vérifie si le fichier a été modifié depuis la dernière visualisation. Si c'est le cas, il rechargera le fichier. Cette fonctionnalité permet de prévisualiser de nombreuses versions du même fichier en exécutant xdvi une seule fois. Comme il ne peut pas lire les fichiers DVI partiels, les versions de xdvik à partir de 22.74.3 créeront une copie temporaire du fichier DVI visualisé, afin de garantir que le fichier puisse être visualisé sans interruption. (L'option -notempfile peut être utilisée pour désactiver cette fonctionnalité).

Xdvi peut afficher les spéciaux PostScript<tm> par l'une des trois méthodes. Il essaiera d'abord d'utiliser Display PostScript<tm>, puis NeWS, puis il essaiera d'utiliser Ghostscript pour rendre les images. Toutes ces options dépendent de logiciels supplémentaires pour fonctionner correctement ; de plus, certaines d'entre elles peuvent ne pas être compilées dans cette copie de xdvi.

Pour des raisons de performance, xdvi ne rend pas les spéciaux PostScript dans la loupe.

Si aucun nom de fichier n'est spécifié sur la ligne de commande, xdvi tentera d'ouvrir le fichier le plus récemment ouvert ; si l'historique des fichiers (accessible via le menu Fichier > Ouvrir récent) est vide, ou si aucun des fichiers de l'historique n'est un fichier DVI valide, il affichera un sélecteur de fichiers pour choisir un nom de fichier. (Dans les versions précédentes, qui n'avaient pas d'historique de fichiers, le sélecteur de fichiers était toujours utilisé ; vous pouvez définir la ressource X noFileArgUseHistory à false pour retrouver le comportement ancien.)

OPTIONS

En plus de spécifier le fichier dvi (avec ou sans l'extension .dvi), xdvi supporte les options de ligne de commande suivantes. Si l'option commence par un `+' au lieu d'un `-', l'option est restaurée à sa valeur par défaut. Par défaut, ces options peuvent être définies via les noms de ressources donnés entre parenthèses dans la description de chaque option.

+page
Spécifie la première page à afficher. Si + est donné sans nombre, la dernière page est supposée ; la première page est la valeur par défaut.
-allowshell
(.allowShell) Cette option active l'échappement de shell dans les spéciaux PostScript. (Pour des raisons de sécurité, les échappements de shell sont désactivés par défaut.) Cette option devrait être rarement utilisée ; en particulier, elle ne devrait pas être utilisée juste pour décompresser des fichiers : cette fonction est effectuée automatiquement si le nom de fichier se termine par .Z, .gz, ou .bz2. Les échappements de shell sont toujours désactivés si l'option -safer est utilisée.
-altfont police
(.altFont) Déclare une police par défaut à utiliser lorsque la police du fichier dvi ne peut pas être trouvée. Ceci est utile, par exemple, avec les polices PostScript <tm>.
-anchorposition ancre
Saute vers l'ancre après avoir ouvert le fichier DVI. Ceci n'est utile que lors de l'invocation de xdvi depuis d'autres applications.
-background couleur
(.background) Détermine la couleur de fond. Identique à -bg.
-bg couleur
(.background) Détermine la couleur de fond.
-browser navigateur
(.wwwBrowser) Définit le navigateur web utilisé pour gérer les URLs externes. La valeur de cette option ou ressource a la même syntaxe que la variable d'environnement BROWSER ; voir l'explication de cette variable dans la section `ENVIRONNEMENT' ci-dessous pour une description détaillée. Si ni l'option ni la ressource X wwwBrowser ne sont spécifiées, les variables d'environnement BROWSER et WWWBROWSER (dans cet ordre) sont utilisées pour déterminer la commande du navigateur. Si celles-ci ne sont pas non plus définies, la valeur par défaut suivante est utilisée : xdg-open %s:htmlview %s:firefox -remote -remote "openURL(%s,new-window)":mozilla -remote "openURL(%s,new-window)":netscape -raise -remote "openURL(%s,new-window)":xterm -e w3m %s:xterm -e lynx %s:xterm -e wget %s
-copy
(.copy) Utilise toujours l'opération de copie lors de l'écriture de caractères sur l'écran. Cette option peut être nécessaire pour un fonctionnement correct sur un écran couleur, mais les caractères de surimpression seront incorrects. Si l'anti-aliasing en niveaux de gris est utilisé, l'opération -copy désactivera l'utilisation des plans de couleur et rendra les surimpressions incorrectes. Voir aussi -thorough.

(.cursorColor) Détermine la couleur du curseur de la souris. La valeur par défaut est la même que la couleur de premier plan.

(.debugLevel) Si non nul, affiche des informations supplémentaires sur la sortie standard. L'argument peut être soit un masque binaire spécifié comme un nombre décimal, soit une liste de chaînes séparées par des virgules.

-density densité
(.densityPercent) Détermine la densité utilisée lors de la réduction des bitmaps pour les polices. Une valeur plus élevée produit une police plus claire. La valeur par défaut est 40. Si la mise en niveaux de gris est activée, cet argument ne s'applique pas ; utilisez -gamma à la place. Voir aussi la touche `S'. Identique à -S.
-display hôte:écran
Spécifie l'hôte et l'écran à utiliser pour afficher le fichier dvi. Par défaut, cela est obtenu à partir de la variable d'environnement DISPLAY.
-dvipspath chemin
(.dvipsPath) Utilise chemin comme programme dvips à utiliser lors de l'impression. La valeur par défaut est dvips. Le programme ou le script devrait lire le fichier DVI depuis l'entrée standard et écrire le fichier PostScript en sortie standard.
-editor éditeur
(.editor) Spécifie l'éditeur qui sera appelé lorsque l'action source-special() est déclenchée pour démarrer une recherche inversée (par défaut via Ctrl-Souris 1). L'argument de cette option est une chaîne de formatage dans laquelle les occurrences de ``%f'' sont remplacées par le nom du fichier, les occurrences de ``%l'' par le numéro de ligne dans le fichier, et les occurrences optionnelles de ``%c'' par le numéro de colonne dans la ligne.

Si ni l'option ni la ressource X .editor n'est spécifiée, les variables d'environnement suivantes sont vérifiées pour déterminer la commande de l'éditeur : XEDITOR, VISUAL et EDITOR (dans cet ordre). Si la chaîne est trouvée comme valeur des variables d'environnement VISUAL ou EDITOR, alors ``xterm -e '' est ajouté en préfixe à la chaîne ; si l'éditeur est spécifié par d'autres moyens, alors il doit être sous la forme d'une commande shell pour ouvrir une fenêtre X avec un éditeur. Si aucune de ces variables n'est définie, un message d'avertissement s'affiche et la commande ``xterm -e vi +%l %f'' est utilisée.

Si aucun ``%f'' ou ``%l'' n'apparaît dans la chaîne, les chaînes de formatage manquantes sont ajoutées automatiquement. (Ceci pour la compatibilité avec d'autres programmes lors de l'utilisation de l'une des variables d'environnement).

Une nouvelle instance de l'éditeur est démarrée chaque fois que cette commande est utilisée ; il est donc préférable d'utiliser un éditeur qui peut être appelé en mode `client' pour charger de nouveaux fichiers dans la même instance. Exemples de configurations :

emacsclient --no-wait
(anciennes versions d'Emacs)
gnuclient -q
(XEmacs et versions plus récentes d'Emacs)
gvim --servername xdvi --remote
(VIM v6.0+ ; l'option `--servername xdvi' fera exécuter à gvim une instance dédiée pour les fichiers ouverts par xdvi.)
nc
(nedit)

Notez que ces chaînes doivent être mises entre guillemets lors de leur utilisation en ligne de commande pour les protéger du shell ; lors de leur utilisation comme argument de la ressource .editor dans un fichier de ressources X, aucun guillemet ne doit être utilisé.

-expert
Cette option n'est prise en charge que pour des raisons de compatibilité ascendante ; elle est équivalente à -expertmode 0, qui devrait être préférée.
-expertmode indicateur
(.expertMode) Avec un argument de 0, cette option désactive l'affichage des boutons, des barres de défilement, de la barre d'outils (Motif uniquement), de la ligne de statut et de la liste des pages. Ces éléments de l'interface graphique peuvent également être activés/désactivés séparément, en combinant les valeurs appropriées dans l'argument indicateur. Cela fonctionne de manière similaire à l'option -debug : l'entier indicateur est traité comme une bitmap où chaque bit représente un élément. Si le bit a la valeur 1, l'élément est activé, s'il a la valeur 0, l'élément est désactivé. La signification des bits est la suivante : 
1	statusline
2	scrollbars
4	Motif : pagelist, Xaw : buttons and pagelist
8	toolbar (Motif uniquement)
16	menubar (Motif uniquement)
Par exemple, pour activer uniquement la ligne de statut et les barres de défilement, utilisez 3 (= 1 + 2). Voir aussi la touche `x', où les bits sont adressés par leurs positions, de 1 à 3 (Xaw) ou 5 (Motif), respectivement.

Si la ligne de statut n'est pas active, tous les messages qui seraient normalement imprimés sur la ligne de statut seront imprimés sur stdout, sauf si l'option -hushstdout est utilisée.

-fg couleur
(.foreground) Détermine la couleur du texte (premier plan).
-findstring chaîne
Cette option déclenche une recherche de chaîne dans le fichier DVI mentionné en ligne de commande, similaire à la recherche avant (voir la description de l'option sourceposition) : S'il existe déjà une autre instance de xdvi en cours d'exécution affichant ce fichier DVI, cette instance effectuera la recherche à la place. La recherche commence en haut de la page actuelle du fichier DVI.
-font police
(*font) Définit la police utilisée dans les menus, les boutons, etc., comme décrit dans la page de manuel X(7x). La police pour les fenêtres enfants peut être définie séparément, par exemple :
xdvi*statusline*font: \
   -*-helvetica-medium-r-*-*-12-*-*-*-*-*-*-*
-foreground couleur
Identique à -fg.
-fullscreen
Lorsque cette option est utilisée, xdvi s'exécute (tente de s'exécuter) en mode plein écran, sans décorations de fenêtre. Cette option n'est pas garantie de fonctionner avec tous les gestionnaires de fenêtres/bureau ; si vous rencontrez des problèmes avec, utilisez plutôt l'option -geometry, et un réglage approprié du gestionnaire de fenêtres pour supprimer les décorations de fenêtre. Lors de l'utilisation de cette option pour des présentations, vous pourriez vouloir vous débarrasser de tous les widgets de contrôle également, en utilisant l'option -expertmode. Cette option peut également être basculée à l'exécution en utilisant l'action fullscreen (par défaut liée à Ctrl-l).
-gamma gamma
(.gamma) Contrôle l'interpolation des couleurs dans la palette de couleurs anti-aliasing en niveaux de gris. La valeur par défaut est 1.0. Pour 0 < gamma < 1, les polices seront plus claires (plus proches de l'arrière-plan), et pour gamma > 1, les polices seront plus sombres (plus proches du premier plan). Les valeurs négatives se comportent de la même manière, mais utilisent un algorithme légèrement différent. Pour les écrans couleur et niveaux de gris ; pour les écrans monochromes, voir -density. Voir aussi la touche `S'.
-geometry géométrie
(.geometry) Spécifie la géométrie initiale de la fenêtre principale, comme décrit dans la page de manuel X(7x). La géométrie des fenêtres enfants peut être définie séparément, par exemple :
xdvi*helpwindow.geometry: 600x800
-gsalpha
(.gsAlpha) Force l'appel de Ghostscript avec le pilote x11alpha au lieu du pilote x11. Le pilote x11alpha active l'anti-aliasing dans les spéciaux PostScript, pour une meilleure apparence. Il est disponible dans les versions plus récentes de Ghostscript. Cette option peut également être basculée avec la touche `V'.
-gspalette palette
(.palette) Spécifie la palette à utiliser lors de l'utilisation de Ghostscript pour le rendu des spéciaux PostScript. Les valeurs possibles sont Color, Greyscale et Monochrome. La valeur par défaut est Color.
-h, -help, --help
Affiche un court texte d'aide avec un aperçu des options de la ligne de commande sur la sortie standard.
-hl couleur
(.highlight) Détermine la couleur de la bordure de la page, de la règle en `mode règle', et des marqueurs de surbrillance dans la recherche avant et la recherche de chaîne. La valeur par défaut est la couleur du premier plan.
-hush
(.Hush) Force xdvi à supprimer tous les avertissements suppressibles.
-hushbell
(.hushBell) Ne pas émettre de sonnerie X en cas d'erreur.

-hushchecksums
(.hushChecksums) Indique à xdvi de supprimer les avertissements concernant les dissidences de sommes de contrôle entre le fichier dvi et le fichier de police.
-hushstdout
(.hushStdout) Supprime l'affichage des messages d'état sur la sortie standard (*stdout*). Notez que les erreurs ou avertissements seront toujours affichés sur la sortie d'erreur (*stderr*) même si cette option est utilisée.
-icongeometry géométrie
(.iconGeometry) Spécifie la position initiale pour l'icône.
-iconic
(.iconic) Fait en sorte que la fenêtre xdvi démarre dans un état iconisé. Par défaut, la fenêtre démarre ouverte.
-install
(.install) Si xdvi fonctionne sous un affichage PseudoColor, il vérifie (par défaut) s'il existe des affichages TrueColor avec plus de bits par pixel, et bascule vers un tel affichage s'il en existe un. S'il n'en existe pas, il utilisera l'affichage et la palette de couleurs actuels. Si -install est sélectionné, cependant, il utilisera toujours un affichage TrueColor d'une profondeur supérieure, si disponible ; sinon, il installera sa propre palette de couleurs sur l'affichage actuel. Si l'affichage actuel n'est pas PseudoColor, alors xdvi ne changera pas l'affichage ou la palette de couleurs, quelles que soient ses options. La valeur par défaut de la ressource install est la valeur spéciale, maybe. Il n'y a pas d'option +install. Voir aussi -noinstall, et la section GRISSCALE ET PALETTES DE COULEURS.
-interpreter nom_fichier
(.interpreter) Utilise nom_fichier comme interpréteur Ghostscript. Par défaut, il utilise gs.
-keep
(.keepPosition) Définit un indicateur pour indiquer que xdvi ne doit pas se déplacer à la position d'origine lors du passage à une nouvelle page. Voir aussi la touche de raccourci `k'. Cet indicateur est respecté par toutes les actions de changement de page et par up-or-previous() / down-or-next(), bien que ces dernières ne respectent que la position horizontale, pas la verticale. Cela permet un défilement "continu" dans un document avec une fenêtre d'affichage plus étroite que la largeur d'une page.

-margins dimen
(.Margin) Spécifie la taille de la marge supérieure et de la marge latérale. Ceci détermine la position "d'origine" de la page dans la fenêtre comme suit. Si la page entière tient dans la fenêtre, alors les paramètres de marge sont ignorés. Si, même après avoir retiré les marges de gauche, de droite, du haut et du bas, la page ne peut toujours pas tenir dans la fenêtre, alors la page est placée dans la fenêtre de manière à ce que les marges supérieure et gauche soient cachées, et supposément le coin supérieur gauche du texte sur la page sera dans le coin supérieur gauche de la fenêtre. Sinon, le texte est centré dans la fenêtre. La dimension doit être un nombre décimal optionnellement suivi par l'une des abréviations de deux lettres pour les unités acceptées par TeX (pt, pc, in, bp, cm, mm, dd, cc, ou sp). Par défaut, l'unité sera cm (centimètres). Voir aussi -sidemargin, -topmargin, et la touche de raccourci `M.'
-mfmode mode-def
(.mfMode) Spécifie une chaîne mode-def, qui peut être utilisée dans la recherche de polices (voir ENVIRONNEMENT, ci-dessous). Généralement, lors du changement du mode-def, il est également nécessaire de changer la taille de la police à la valeur appropriée pour ce mode. Ceci est fait en ajoutant un deux-points et la valeur en points par pouce ; par exemple, -mfmode ljfour:600. Cette méthode remplace toute valeur donnée par la ressource pixelsPerInch ou l'argument de ligne de commande -p. Le mode metafont est également passé à metafont lors de la création automatique de polices. Par défaut, il est non spécifié.
-mgs taille
Identique à -mgs1.
-mgs[n] taille
(.magnifierSize[n]) Spécifie la taille de la fenêtre à utiliser pour la "loupe" du Bouton n. La taille peut être donnée sous forme d'entier (indiquant que la loupe doit être carrée), ou sous la forme largeurxhauteur. Voir la section ACTIONS DE LA SOURIS. Les valeurs par défaut sont 200x150, 400x250, 700x500, 1000x800 et 1200x1200.
-mousemode [0|1|2]
(.mouseMode) Spécifie le mode par défaut de xdvi au démarrage : Loupe (0), Mode de sélection de texte (1) ou Mode règle (2). Voir la section MODES, ci-dessous, pour plus d'informations.
-nocolor
(.color) Désactive l'utilisation des spécifications de couleur. Cette option peut être basculée avec la touche de raccourci `C'. (Note : -nocolor correspond à color:off ; +nocolor à color:on.)
-nofork
(.fork) Avec les options -sourceposition et -unique, le comportement par défaut est que xdvi se mette en arrière-plan (comme un démon) s'il n'y a pas d'instance appropriée de xdvi déjà en cours d'exécution. Cet argument le fait fonctionner au premier plan à la place. Ceci est utile pour le débogage, ou si votre application cliente ne gère pas bien qu'un programme se mette en arrière-plan de cette manière -- par exemple, les fonctions IPC dans emacs sont connues pour avoir des problèmes avec cela. Si aucun argument -sourceposition ou -unique n'est donné, alors cette option n'a aucun effet. (Note : -nofork correspond à fork:off ; +nofork à fork:on.)
-noghostscript
(.ghostscript) Inhibe l'utilisation de Ghostscript pour l'affichage des spécifications PostScript<tm>. (Note : -noghostscript correspond à ghostscript:off ; +noghostscript à ghostscript:on.)
-nogrey
(.grey) Désactive l'utilisation de l'anti-crénelage en niveaux de gris lors de l'impression de bitmaps réduits. (Note : -nogrey correspond à grey:off ; +nogrey à grey:on.) Voir aussi la touche de raccourci `G'.
-nogssafer
(.gsSafer) Normalement, si Ghostscript est utilisé pour rendre les spécifications PostScript, l'interpréteur Ghostscript est exécuté avec l'option -dSAFER. L'option -nogssafer exécute Ghostscript sans -dSAFER. L'option -dSAFER dans Ghostscript désactive les opérateurs PostScript tels que deletefile, pour empêcher les programmes PostScript potentiellement malveillants d'avoir un effet. Si l'option -safer est spécifiée, alors cette option n'a aucun effet ; dans ce cas Ghostscript est toujours exécuté avec -dSAFER. (Note : -nogssafer correspond à gsSafer:off ; +nogssafer à gsSafer:on.)
-noinstall
(.install) Inhibe le comportement par défaut de basculement vers un affichage TrueColor s'il est disponible avec plus de bits par pixel que l'affichage actuel. (Note : -noinstall correspond à install:off ; il n'y a pas d'option +noinstall.) Voir aussi -install, et la section GRISSCALE ET PALETTES DE COULEURS.
-nomakepk
(.makePk) Désactive la génération automatique de fichiers de polices qui ne peuvent pas être trouvés par d'autres moyens. (Note : -nomakepk correspond à makePk:off ; +nomakepk à makePK:on.)
-nomatchinverted
(.matchInverted) Ne surligne pas les correspondances de recherche de chaînes en couleur inversée ; dessine plutôt un rectangle dans la couleur de surlignage (voir l'option -hl) autour de la correspondance. Cette option est activée automatiquement si l'affichage ne fonctionne pas en TrueColor. (Note : -nomatchInverted correspond à matchInverted:off ; +nomatchInverted à matchInverted:on.)
-noomega
(.omega) Ceci désactivera l'utilisation des extensions Omega lors de l'interprétation des fichiers DVI. Par défaut, les codes d'opération supplémentaires 129 et 134 sont reconnus par xdvi comme des extensions Omega et interprétés comme des demandes de définition de caractères sur 2 octets. Le seul inconvénient est que le tableau de polices virtuelles nécessitera 65536 positions au lieu des 256 positions par défaut, c'est-à-dire que les exigences en mémoire de xdvi seront légèrement plus élevées. Si vous trouvez cela inacceptable ou rencontrez un autre problème avec les extensions Omega, vous pouvez désactiver cette extension en utilisant -noomega (mais veuillez envoyer un rapport de bug si vous rencontrez de tels problèmes - voir l'adresse des bugs dans la section AUTEURS ci-dessous).
(Note : -noomega correspond à omega: off ; +noomega à omega: on.)
-noscan
(.prescan) Par défaut, xdvi effectue un balayage préliminaire du fichier dvi pour traiter toutes les spécifications papersize ; ceci est particulièrement important au démarrage car la taille du papier peut être nécessaire pour determine la taille de la fenêtre. Si PostScript<tm> est utilisé, alors un pré-balayage est également nécessaire afin de traiter correctement les fichiers d'en-tête. De plus, un pré-balayage est nécessaire pour déterminer correctement la couleur d'arrière-plan d'une page. Cette option désactive ce pré-balayage. (Le pré-balayage sera automatiquement réactivé si xdvi détecte des spéciaux mentionnés ci-dessus.) (Note : -noscan correspond à prescan:off ; +noscan à prescan:on.)
-notempfile
(.tempFile) Comme mentionné dans la section DESCRIPTION ci-dessus, xdvi créera une copie temporaire du fichier DVI afin qu'il puisse être accessible sans interruptions même lorsque le fichier est réécrit par TeX. Comme cela entraîne des frais généraux de copie du fichier à chaque fois qu'il est modifié, -notempfile vous permet de désactiver ce comportement. Dans ce cas, exposer des parties de la fenêtre pendant que le fichier DVI est écrit par TeX effacera le contenu actuel de la fenêtre jusqu'à ce que le fichier DVI puisse être entièrement relu.
(Note : -notempfile correspond à tempFile:off ; +notempfile à tempFile:on.)
-notype1fonts
(.type1) Cela désactivera l'utilisation de la bibliothèque FreeType pour afficher les polices PostScript<tm> Type 1. Utilisez cette option comme solution de contournement lorsque vous rencontrez des problèmes avec l'affichage des polices Type 1 (mais n'oubliez pas d'envoyer un rapport de bug dans ce cas, à l'URL mentionnée dans la section AUTEURS ci-dessous).
(Note : -notype1fonts correspond à type1:off ; +notype1fonts à type1:on.)
-offsets dimen
(.Offset) Spécifie la taille des décalages horizontal et vertical de la sortie sur la page. Par décret du Stanford TeX Project, l'origine de page TeX par défaut est toujours à 1 pouce vers la droite et vers le bas à partir du coin supérieur gauche de la page, même lorsque des tailles de papier non américaines sont utilisées. Par conséquent, les décalages par défaut sont de 1,0 pouce. L'argument dimen doit être un nombre décimal éventuellement suivi de l'une des abréviations de deux lettres pour les unités acceptées par TeX (pt, pc, in, bp, cm, mm, dd, cc ou sp). Par défaut, l'unité sera cm (centimètres). Voir également -xoffset et -yoffset.
-p pixels
(.pixelsPerInch) Définit la taille des polices à utiliser, en pixels par pouce. La valeur par défaut est 600. Cette option n'est fournie que pour la compatibilité descendante ; la méthode préférée consiste à définir à la fois la résolution et le mode Metafont via l'option -mfmode (voir ci-dessous).
-paper papertype
(.paper) Spécifie la taille de la page imprimée. Notez que dans la plupart des cas, il est préférable de spécifier la taille du papier dans le fichier d'entrée TeX via la ligne

\usepackage[dvips]{geometry}

qui sera reconnue par dvips et xdvi ; dans ce cas, l'utilisation d'une option `-paper' devrait être inutile.
La taille du papier peut être spécifiée sous la forme largeurxhauteur éventuellement suivie d'une unité, où largeur et hauteur sont des nombres décimaux donnant la largeur et la hauteur du papier, respectivement, et l'unité est l'une des abréviations de deux lettres pour les unités acceptées par TeX (pt, pc, in, bp, cm, mm, dd, cc ou sp). Par défaut, l'unité est cm (centimètres).
Il existe également des synonymes qui peuvent être utilisés : us (8.5x11in), legal (8.5x14in), foolscap (13.5x17in), ainsi que les formats ISO a1-a7, b1-b7, c1-c7. Chacun d'eux a également une variante paysage ou "rotative" : usr (11x8.5in), a1r-a7r, etc. Pour la compatibilité avec dvips, les formats letter (8.5x11in), ledger (17x11in) et tabloid (11x17in) sont également pris en charge (ceux-ci n'ont pas de variantes rotatives).
N'importe laquelle des tailles ci-dessus peut être précédée d'un signe plus (`+') ; cela provoque le remplacement de la taille du papier donnée ici par toute taille de papier donnée dans le fichier dvi. La taille de papier par défaut est de 21 x 29,7 cm (format A4).

-pause
(.pause) Cette option fournit une implémentation simple d'affichage incrémental (par étapes), qui peut être utilisée pour des présentations. Lorsque cette option est utilisée, xdvi mettra en pause l'affichage de la page actuelle chaque fois qu'il rencontrera une chaîne spéciale special-string (xdvi:pause par défaut ; la chaîne peut être personnalisée via -pausespecial, voir ci-dessous), et le curseur changera de forme. L'action unpause-or-next() (par défaut liée à la touche Espace) affichera la partie suivante de la page jusqu'à la chaîne spéciale suivante, ou jusqu'à la fin de la page. Lorsque l'option n'est pas utilisée, les spéciaux contenant special-string seront ignorés.

(.pauseSpecial) Définit la chaîne spéciale qui provoque la mise en pause de xdvi lorsque l'option -pause est active. La valeur par défaut de special-string est xdvi:pause.

Une valeur de 1 (par défaut) active les spéciaux PostScript<tm>. Avec une valeur de 2, les spéciaux PostScript<tm> sont affichés avec leurs boîtes englobantes ; cela vous permet de vérifier visuellement la correction des boîtes englobantes. Les valeurs peuvent également être basculées à l'exécution avec la touche `v' et les arguments numériques préfixés correspondants 0, 1 et 2.

(.ps2pdfPath) Utilise path comme programme de conversion PostScript vers PDF. Le programme ou script doit accepter deux arguments de ligne de commande : Le fichier PostScript comme premier argument, et le fichier de sortie PDF comme deuxième argument.
-rulecolor color
(.ruleColor) Détermine la couleur des règles utilisées pour la loupe (par défaut : couleur de premier plan).

(.reverseVideo) Affiche la page avec des caractères blancs sur fond noir, au lieu de l'inverse.
-S density
(.densityPercent) Identique à -density (voir ci-dessous).

(.shrinkFactor) Définit le facteur de réduction initial. La valeur par défaut est 8. Si shrink est donné comme 0, alors le facteur de réduction initial est calculé de manière à ce que la page s'insère dans la fenêtre (comme si la touche `s' était pressée sans numéro).

(.safer) Cette option active toutes les options de sécurité disponibles ; elle est conçue pour être utilisée lorsque xdvi est appelé par un navigateur qui obtient un fichier dvi ou TeX d'un autre site. Cette option sélectionne +nogssafer et +allowshell.
-sidemargin dimen
(.sideMargin) Spécifie la marge latérale (voir -margins).
-sourceposition ligne[:col][ ]filename
Cette option permet à xdvi de rechercher dans le fichier dvi l'emplacement correspondant à la ligne (et, éventuellement, la colonne) indiquée dans le fichier source .tex, et de surligner l'emplacement trouvé en dessinant un rectangle dans la couleur highlight (voir l'option -hl) autour du texte correspondant. De plus, lorsqu'il est exécuté avec cet argument (et que l'option -nofork n'est pas donnée, voir ci-dessous), xdvi retournera immédiatement : s'il trouve une autre instance de xdvi affichant déjà dvi_file, alors il fera en sorte que cette instance lève sa fenêtre et se déplace vers l'endroit donné dans le fichier dvi ; sinon, il lancera sa propre instance en arrière-plan. Si plusieurs instances de xdvi affichent le fichier dvi respectif, l'instance qui a été levée le plus récemment au premier plan sera utilisée.

L'espace avant filename n'est nécessaire que si le nom de fichier commence par un chiffre. Lorsque l'espace est utilisé, l'argument doit être entouré de guillemets pour éviter que le shell n'interprète mal l'espace comme séparateur d'arguments.

Cette option nécessite que dvi_file soit préparé avec des informations spéciales de source. Voir la section sur les SPÉCIAUX DE SOURCE pour plus de détails sur la façon de le faire.

Voici une description plus détaillée de la façon dont le nom de fichier dans l'argument -sourceposition est mis en correspondance avec le nom de fichier dans les spéciaux de source :

1.
Si aucun des noms de fichiers ne contient de composante de chemin, les noms de fichiers sont comparés en ignorant les extensions `.tex' dans les deux noms de fichiers.
2.
Sinon, si l'un des noms de fichiers contient une composante de chemin (par exemple : ./test.tex, ../test.tex, /my/homedir/tex/test.tex ou toute combinaison de ceux-ci), les deux noms de fichiers sont développés en un chemin complet, avec toute occurrence de ../ et ./ développée, et les slashs multiples supprimés.
Le chemin dans -sourceposition est développé par rapport au répertoire de travail actuel de l'invocation xdvi -sourceposition, et les chemins dans les spéciaux de source sont développés par rapport au chemin du fichier DVI actuel en cours de visualisation.
Les noms de chemin sont ensuite comparés en ignorant les extensions `.tex' dans les deux noms de chemin.

(.textEncoding) Utilise encoding comme encodage de texte de la chaîne dans la fenêtre "Rechercher". Normalement, cela ne devrait pas être nécessaire puisque l'encodage est déterminé à partir des paramètres régionaux.
-thorough
(.thorough) Xdvi essaiera normalement de s'assurer que les caractères superposés (par exemple \notin) sont imprimés correctement. Sur les affichages monochromes, cela est toujours possible avec une seule opération logique, soit and soit or. Sur les affichages couleur, cependant, cela peut nécessiter deux opérations, une pour définir les bits appropriés et une pour effacer les autres bits. Si tel est le cas, par défaut xdvi utilisera l'opération copy, qui ne gère pas correctement la superposition. L'option -thorough choisit le choix plus lent mais plus correct. Voir également -copy.
-topmargin dimen
(.topMargin) Spécifie les marges supérieure et inférieure (voir -margins).
-unique
(.unique) Cette option fera qu'une autre instance de xdvi fonctionnant sur le même affichage agira comme un « serveur ». Par exemple, l'invocation

xdvi -unique +5 file.dvi

demandera à cette autre instance de charger file.dvi à la page 5 à la place du fichier qu'elle affiche actuellement. S'il y a déjà une autre instance de xdvi affichant le fichier file.dvi, elle sautera simplement à la page 5. Si l'autre instance de xdvi affiche un fichier différent, elle chargera file.dvi à la place. Sinon, si aucune autre instance de xdvi n'est actuellement en cours d'exécution sur l'affichage, cette option démarre plutôt une nouvelle instance de xdvi en arrière-plan (sauf si l'option -nofork est spécifiée, voir celle-ci) affichant la page 5 de file.dvi.
Le nom du fichier et l'option +n pour le numéro de page sont les seules options disponibles pour contrôler une instance distante de xdvi de cette manière ; toutes les autres options sont actuellement ignorées.

-useTeXpages
Utilise les pages logiques TeX (les valeurs du registre \count0) au lieu des pages physiques pour les étiquettes de la liste de pages et lors du saut à une page dans un document avec la touche « g » (ou l'action goto-page()). Cette option peut être activée/désactivée via la touche « T ».
-version
Affiche les informations sur la version de xdvi.
-visitedlinkcolor
(.visitedLinkColor) Couleur utilisée pour les hyperliens visités (« Purple4 » par défaut). Les hyperliens deviennent visités une fois que vous cliquez dessus. Comme pour linkColor, la valeur doit être soit un nom de couleur X valide, soit une chaîne de couleur hexadécimale.
-warnspecials
(.warnSpecials) Indique à xdvi d'imprimer des avertissements concernant les chaînes \special qu'il ne peut pas traiter sur stderr. Ces avertissements sont supprimés par défaut.
-watchfile n
(.watchFile) Si cette option est définie sur une valeur supérieure à 0, xdvi vérifiera le fichier DVI pour des changements toutes les n secondes. Si le fichier DVI a été complètement écrit par TeX, il sera rechargé automatiquement. Les valeurs fractionnaires (par exemple, « 2.5 ») sont possibles. La valeur par défaut pour cette option est 0, c'est-à-dire aucune surveillance.
Étant donné que xdvi ne peut pas gérer les fichiers DVI partiels, il essaie de ne pas recharger le fichier pendant qu'il est en cours d'écriture. Cependant, l'utilisation de la loupe ou le changement de pages nécessite la lecture (d'une partie) du fichier DVI, et si l'option tempfile est désactivée, cela effacera le contenu actuel de la fenêtre jusqu'à ce que le fichier DVI puisse être lu entièrement.
-wheelunit pixels
(.wheelUnit) Définit le nombre de pixels de déplacement pour un mouvement de la molette d'une souris, vers le haut, le bas, la gauche ou la droite. (Voir les actions wheel et hwheel, ci-dessous, pour plus d'informations à ce sujet.) Si la valeur est mise à zéro, la fonctionnalité de la molette de la souris est (essentiellement) désactivée. La valeur par défaut est 80.
-xoffset dimen
(.xOffset) Spécifie la taille du décalage horizontal de la sortie sur la page. Voir -offsets.
-yoffset dimen

Xdvi reconnaît les frappes de touches suivantes lorsqu'elles sont tapées dans sa fenêtre. Chacune peut éventuellement être précédée d'un nombre (positif ou négatif), un « argument préfixe », dont l'interprétation dépendra de la frappe de touche particulière. Cet argument préfixe peut être supprimé en appuyant sur la touche « Escape ». S'ils sont présents, les touches « Help », « Prior » et « Next » sont des synonymes des touches `?', `b' et `f', respectivement.

Les liaisons de touches listées ici sont celles que xdvi assigne par défaut. Les noms apparaissant entre crochets au début des descriptions sont les noms des actions associées aux touches ; ceux-ci peuvent être utilisés pour personnaliser les liaisons de touches, comme expliqué plus en détail dans la section PERSONNALISATION ci-dessous. Si seule une liaison en minuscules est répertoriée, les touches majuscules et minuscules fonctionneront pour cette liaison.

m
[toggle-mark()] Active ou désactive la marque pour la page actuelle dans la liste des pages. Lorsqu'une page est marquée, elle est affichée avec une petite étoile `*' à côté du numéro de page. Les pages marquées peuvent ensuite être imprimées ou enregistrées dans un fichier. Une page ou plusieurs pages peuvent également être marquées en cliquant ou en faisant glisser la souris avec le bouton Mouse-2 dans la liste des pages.
Ctrl-n
[toggle-mark()forward-page()] Active ou désactive la marque pour la page actuelle dans la liste des pages, et passe à la page suivante. Cela vous permet de marquer rapidement une série de pages consécutives.
n
[forward-page()] Passe à la page suivante (ou à la n-ième page suivante si un nombre est donné). Les synonymes sont `f', Return, et Line Feed.
Ctrl-o
[select-dvi-file()] Lit un nouveau fichier dvi. Un widget de sélection de fichier s'affiche pour vous permettre de choisir le fichier DVI. Si un argument préfixe n est donné, le n-ième fichier de l'historique des fichiers est ouvert à la place.
P
[declare-page-number()] ``Ceci est la page numéro n.'' Ceci peut être utilisé pour faire en sorte que la touche `g' fasse référence à un numéro de page différent de la page physique. (Si vous souhaitez utiliser les numéros de page `logiques' ou TeX au lieu des pages physiques, envisagez d'utiliser plutôt l'option -useTeXpages.) L'argument n doit être donné comme préfixe à cette touche.
Ctrl-p
[print()] Ouvre une fenêtre contextuelle pour imprimer le fichier DVI, ou des parties de celui-ci. Voir la section PRINT DIALOG pour une explication des options disponibles, et les ressources pour personnaliser le comportement par défaut.
p
[back-page()] Passe à la page précédente (ou remonte de n pages). Les synonymes sont `b', Ctrl-h et Backspace.
q
[quit()] Quitte le programme.
Ctrl-r
[forward-page(0)] Redessine la page actuelle.
R
[reread-dvi-file()] Force la relecture du fichier dvi. Cela vous permet de prévisualiser de nombreuses versions du même fichier tout en exécutant xdvi une seule fois.
r
[right()] Déplace la page vers la droite des deux tiers de la hauteur de la fenêtre.
Ctrl-s
[save()] Ouvre une fenêtre contextuelle pour enregistrer le fichier DVI, ou des parties de celui-ci. Voir la section SAVE DIALOG ci-dessous pour plus d'informations à ce sujet.
S
[set-density()] Définit le facteur de densité à utiliser lors de la réduction des bitmaps. Ce devrait être un nombre entre 0 et 100 ; des nombres plus élevés produisent des caractères plus clairs. Si le mode niveaux de gris est activé, cela modifie la valeur de gamma à la place. La nouvelle valeur de gamma est le nombre donné divisé par 100 ; les valeurs négatives sont autorisées.
s
[set-shrink-factor()] Modifie le facteur de réduction au nombre donné. Si aucun nombre n'est donné, le plus petit facteur qui permet à la page entière de tenir dans la fenêtre sera utilisé. (Les marges sont ignorées dans ce calcul.)
T
[use-tex-pages()] Utilise les pages TeX logiques (les valeurs du registre \count0) au lieu des pages physiques pour les étiquettes de la liste de pages et lors du saut à une page dans un document via goto-page(). Voir aussi l'option -useTeXpages.
t
[switch-magnifier-units()] Change les unités utilisées pour les marques du zoom, et pour signaler la distance entre le pointeur de la souris et le centre de la règle en mode règle (voir la section MODES). La valeur par défaut est spécifiée par la ressource X tickUnits (`mm' par défaut). Les unités basculent à travers les valeurs suivantes ; à l'exception de `px', toutes correspondent aux unités de TeX : mm (millimètres) pt (points TeX), in (pouces), sp (points mis à l'échelle, l'unité utilisée en interne par TeX) bp (points gros ou `points PostScript'), cc (points cicero), dd (points didot), pc (pica), et px (pixels d'écran).
Ctrl-u
[back-page()toggle-mark()] Passe à la page précédente et active ou désactive la marque pour cette page. C'est l'action duale de Ctrl-n.
u
[up()] Déplace la page vers le haut des deux tiers de la hauteur de la fenêtre. Avec un argument flottant à "up", déplace vers le haut la fraction correspondante de la hauteur de la fenêtre.
Ctrl-v
[show-source-specials()] Affiche les boîtes englobantes pour chaque spécial source sur la page actuelle, et imprime les chaînes contenues dans ces spéciaux sur stderr. Avec le préfixe 1, affiche toutes les boîtes englobantes sur la page. Ceci est principalement à des fins de débogage.
V
[set-gs-alpha()] Cette touche active ou désactive l'anticrénelage des spéciaux PostScript<tm> lorsque Ghostscript est utilisé comme rendeur. De plus, les séquences de touches `0V' et `1V' effacent et définissent respectivement ce drapeau. Voir aussi l'option -gsalpha.

[set-ps()] Cette touche bascule le rendu des spéciaux PostScript<tm> entre 3 états :
- les spéciaux (comme les graphiques EPS) sont affichés ;
- les spéciaux sont affichés avec leur boîte englobante (si disponible) ;
- seule la boîte englobante est affichée.

Le st

ates peuvent également être sélectionnés directement en utilisant `1v', `2v' et `0v' respectivement. Voir aussi l'option -postscript.

Ctrl-x
[source-what-special()] Affiche des informations sur le spécial source situé à côté du curseur de la souris dans la barre d'état. Il s'agit du même spécial qui serait trouvé par source-special(), mais sans invoked l'éditeur. À des fins de débogage.
x
[set-expert-mode()] Active ou désactive le mode expert, dans lequel la barre d'état, les barres de défilement, les boutons de menu, la barre d'outils (Motif uniquement) et la liste des pages ne sont pas affichés. Taper `1x' active ou désactive l'affichage de la barre d'état en bas de la fenêtre. Taper `2x' active ou désactive les barres de défilement (si disponibles). Pour Xaw, `3x' active ou désactive les boutons de menu et la liste des pages, pour Motif, il active ou désactive la liste des pages. Voir aussi l'option -expertmode (les nombres ci-dessus correspondent aux bits de l'argument de -expertmode).

ACTIONS DE SOURIS DANS LA FENÊTRE PRINCIPALE

Les actions de la souris peuvent être personnalisées en définissant la ressource X mouseTranslations. Comme il existe trois modes de souris différents (voir la section MODES ci-dessous), il existe une action spéciale mouse-modes qui liste les actions pour chacun des trois modes : mouse-modes("ACTIONS-POUR-MODE1", "ACTIONS-POUR-MODE2", "ACTIONS-POUR-MODE3"). Si un seul argument est spécifié, cette action est utilisée pour tous les modes. Les liaisons par défaut sont les suivantes :

xdvi.mouseTranslations: \
Shift<Btn1Down>:mouse-modes("drag(+)")\n\
Shift<Btn2Down>:mouse-modes("drag(|)")\n\
Shift<Btn3Down>:mouse-modes("drag(-)")\n\
Ctrl<Btn1Down>:mouse-modes("source-special()")\n\
<Btn1Down>: mouse-modes("do-href()magnifier(*2)", "text-selection()", "ruler()")\n\
<Btn2Down>: mouse-modes("do-href-newwindow()magnifier(*2)", "text-selection()", "ruler()")\n\
<Btn3Down>: mouse-modes("magnifier(*3)")\n\
<Btn4Down>: mouse-modes("wheel(-0.2)")\n\
<Btn5Down>: mouse-modes("wheel(0.2)")\n\
<Btn6Down>: mouse-modes("hwheel(-0.2)")\n\
<Btn7Down>: mouse-modes("hwheel(0.2)")\n\
Toutes ces actions sont décrites plus en détail ci-dessous. Notez l'utilisation des guillemets autour des chaînes d'action, qui sont nécessaires pour les grouper en un seul argument. Les boutons 4, 5, 6 et 7 font référence aux mouvements de molette (molette haut/bas/gauche/droite) sur les souris à molette. Toutes les souris ne supportent pas le défilement horizontal.

Les routines du X Toolkit qui implémentent les traductions ne prennent pas en charge les types d'événements Btn6Down ou Btn7Down. Pour cette raison, xdvi implémente son propre analyseur pour les traductions données dans mouseTranslations. Cet analyseur est plus limité que l'analyseur intégré au X Toolkit. La chaîne donnée dans mouseTranslations ne doit pas commencer par « #replace », « #augment » ou « #override ». Les modificateurs de la forme @keysym ne sont pas pris en charge, et le type d'événement doit être de la forme BtnDown ou BtnnDown, où n est un entier positif sans zéros non significatifs. De plus, certaines limitations s'appliquent au champ d'action.

do-href()
do-href-newwindow()
Habituellement, si une liaison spécifie plus d'une action, toutes les actions sont exécutées séquentiellement. Les liaisons d'hyperliens do-href() et do-href-newwindow() sont spéciales en ce sens qu'elles sont utilisées comme *alternative* à d'autres actions qui pourraient les suivre *si* la souris est actuellement située sur un hyperlien. Dans ce cas, aucune des autres actions ne sera exécutée ; sinon, seules les autres actions sont exécutées.
L'action do-href() saute à la cible du lien dans la fenêtre xdvi actuelle (basculant éventuellement vers une autre page), et do-href-newwindow() ouvre une nouvelle instance de xdvi pour la cible du lien. Dans les deux cas, l'emplacement de la cible est indiqué par une petite flèche dessinée dans la même couleur qu'un lien visité dans le coin gauche de la fenêtre.
magnifier(n x m)
magnifier(*n)
Cette action fait apparaître une « loupe » qui montre l'image non réduite de la région autour du pointeur de la souris. La loupe disparaît lorsque le bouton de la souris est relâché. Déplacer le curseur de la souris tout en maintenant le bouton enfoncé déplacera la loupe.
Différents boutons de souris produisent des fenêtres de tailles différentes, comme indiqué par l'argument de l'action magnifier(). Son argument est soit une chaîne de la forme largeurxhauteur, comme dans l'option de ligne de commande -mgsn, soit l'une des chaînes *1 à *5, faisant référence à la valeur spécifiée par l'option -mgsn correspondante.
drag(+)
drag(|)
drag(-)
Fait glisser la page avec la souris. Cette action doit avoir un paramètre, le caractère « | », « - » ou « + », indiquant uniquement le glissement vertical, uniquement le glissement horizontal ou le glissement dans toutes les directions.
source-special()
Cette action démarre une « recherche inversée », ouvrant l'éditeur à l'emplacement dans le fichier TeX correspondant à l'emplacement du pointeur dans le fichier DVI. Voir la section sur les SPÉCIAUX SOURCE, ci-dessous, pour plus d'informations à ce sujet.
wheel()
Cette action peut être utilisée pour faire défiler l'image avec une souris à molette, où elle est généralement liée au bouton 4 (molette vers le haut) ou 5 (molette vers le bas) de la souris. L'action prend un paramètre, donnant la distance de défilement de l'image. Si le paramètre contient un point décimal, la distance est donnée en unités de molette ; sinon, en pixels. Une valeur négative fait défiler vers le haut, une valeur positive fait défiler vers le bas.
hwheel()
Cette action peut être utilisée pour faire défiler l'image horizontalement avec une souris à molette, où elle est généralement liée au bouton 6 (molette vers la gauche) ou 7 (molette vers la droite) de la souris. L'action prend un paramètre, donnant la distance de défilement de l'image. Si le paramètre contient un point décimal, la distance est donnée en unités de molette ; sinon, en pixels. Une valeur négative fait défiler vers la gauche, une valeur positive fait défiler vers la droite. Toutes les souris ne supportent pas le défilement horizontal ; ceci est principalement pour les pavés tactiles, etc.
text-selection()
Cette action vous permet de marquer une région rectangulaire de texte dans le fichier DVI. Le texte est placé dans le tampon de sélection X et peut être collé dans d'autres applications (par exemple, des éditeurs de texte). Cela fonctionne de manière similaire à l'option Texte brut dans la boîte de dialogue Enregistrer ; voir la discussion là-bas pour plus d'informations sur les problèmes d'encodage.
ruler()
Cette action crée une règle en forme de croix. Déplacer la souris et maintenir le bouton enfoncé fait glisser la règle et vous permet de mesurer les distances sur la page. Voir la section Mode Règle pour plus d'informations à ce sujet.

ACTIONS NON LIÉES

Les actions suivantes ne sont pas liées à une touche par défaut, mais sont disponibles pour personnalisation.

quit-confirm()
Fait apparaître une fenêtre de confirmation pour quitter xdvi. Pour la lier à la touche `q' au lieu de l'action par défaut `quit()', mettez ce qui suit dans votre fichier ~/.Xdefaults :

xdvi.mainTranslations: #override\
<Key>q: quit-confirm()\n

down-or-next()
Similaire à unpause-or-next() : Descend des deux tiers de la hauteur de la fenêtre, ou passe à la page suivante si déjà en bas de la page.
shrink-to-dpi()
Cette action prend un (obligatoire) argument. Elle définit le facteur de réduction à un entier afin d'approximer l'utilisation de polices avec le nombre correspondant de points par pouce. Si xdvi utilise des polices redimensionnées pour p points par pouce, et que l'argument de shrink-to-dpi est n, alors le facteur de réduction correspondant est le rapport p/n, arrondi à l'entier le plus proche.
user-exec()
Cette action prend un argument (obligatoire). Exécute un programme externe spécifié par l'argument, qui est tokenisé sur les espaces. La variable d'environnement XDVI_FILE est définie sur le chemin absolu du fichier DVI, de sorte que le programme puisse trouver le DVI. Par exemple, pour établir la touche `m' comme liaison de touche qui régénère le fichier DVI avec `make', mettez ce qui suit dans votre fichier ~/.Xdefaults :

xdvi.mainTranslations: #override\
<Key>m: user-exec(xdvi-remake)\n

où `xdvi-remake' nomme un programme dans votre PATH analogue à `cd $(dirname $XDVI_FILE) && make $(basename $XDVI_FILE)'. (Voir aussi la section SIGNALS pour une manière de faire en sorte que xdvi recharge le fichier DVI une fois qu'il a été régénéré.)

PERSONNALISATION

Les affectations de touches et de boutons de souris peuvent être modifiées en définissant la ressource mainTranslations sur une chaîne de traductions telle que définie dans la documentation du toolkit X. Les actions doivent prendre la forme de noms d'action listés dans les sections KEYSTROKES et ACTIONS DE SOURIS.

Une exception à cela concerne les touches Motif osfPageUp (PgUp), osfPageDown (PgDown), osfBeginLine (Accueil) et osfEndLine (Fin) qui ne sont actuellement pas personnalisables dans la version Motif.

Les actions de touches sont généralement sans arguments ; si un argument leur est passé, il représente le nombre optionnel ou `argument préfixe' tapé avant l'action.

Certaines actions de touches peuvent prendre des arguments spéciaux, comme suit : L'argument de goto-page peut être la lettre `e', indiquant l'action d'aller à la fin du document. L'argument de set-shrink-factor peut être la lettre `a', indiquant que le facteur de réduction doit être réglé à la plus petite valeur telle que la page tienne dans la fenêtre, ou l'un des signes `+' ou `-', indiquant que le facteur de réduction doit être augmenté ou diminué, respectivement. Enfin, les actions qui effectueraient une bascule, telles que set-keep-flag, peuvent recevoir un argument `t', indiquant que l'action doit basculer indépendamment de l'argument préfixe actuel.

Les actions de souris doivent se référer uniquement aux événements ButtonPress (par exemple, <Btn1Down>:magnifier(*1)). Les événements de mouvement et de relâchement correspondants seront gérés en interne. Une action de touche peut être liée à un événement de souris, mais pas l'inverse.

Généralement, la chaîne de traductions doit commencer par ``#override'', indiquant que les affectations par défaut des touches et des boutons de souris ne doivent pas être supprimées.

Lorsque les touches ou les boutons de souris impliquant des modificateurs (tels que Ctrl ou Shift) sont personnalisés avec leurs équivalents non modifiés, les touches modifiées doivent apparaître en premier, par exemple :

xdvi.mainTranslations: #override \
Shift<Key>s: select-dvi-file()\n\
Ctrl<Key>s: save()\n\
<Key>s: find()\n

Étant donné que xdvi doit capturer les événements de mouvement du pointeur, et parce que le mécanisme de traduction de X Toolkit ne peut pas gérer simultanément les événements de mouvement et les événements de double-clic, il n'est pas possible de spécifier des actions de double-clic dans les personnalisations de xdvi. Pour plus d'informations à ce sujet et sur d'autres aspects des traductions, consultez la documentation de X Toolkit Intrinsics.

Il n'y a pas d'option en ligne de commande pour définir la ressource mainTranslations, car modifier cette ressource en ligne de commande serait fastidieux. Pour définir la ressource à des fins de test, utilisez l'option en ligne de commande -xrm fournie par le toolkit X. Par exemple, xdvi -xrm 'XDvi.mainTranslations: #override "z":quit()' ... ou xdvi -xrm 'XDvi.mainTranslations: #override <Key>z:quit()' ... provoquera la fermeture de xdvi par la touche `z'.

Certaines ressources sont fournies pour permettre la personnalisation de la géométrie des boutons de commande Xaw. Encore une fois, elles ne sont pas modifiables via les options en ligne de commande, autre que via l'option -xrm. Toutes ces ressources prennent des valeurs entières.

buttonSideSpacing
Le nombre de pixels à placer de chaque côté des boutons. La valeur par défaut est 6.
buttonTopSpacing
Le nombre de pixels entre le bouton supérieur et le haut de la fenêtre. La valeur par défaut est 50.
buttonBetweenSpacing
Le nombre de pixels entre les boutons. La valeur par défaut est 20.
buttonBetweenExtra
Le nombre de pixels d'espace supplémentaire à insérer si la chaîne de ressource buttonTranslations contient un caractère de nouvelle ligne supplémentaire. La valeur par défaut est 50.
buttonBorderWidth
La largeur de bordure des fenêtres de boutons. La valeur par défaut est 1.

LISTE DES PAGES

La liste de pages défilante sur la droite de la fenêtre principale vous permet de sauter directement à une page du fichier DVI.

Souris-1
Saute à la page où se trouve la souris.
Souris-2
[toggle-mark()] Bascule la marque de la page actuelle. Les marques sont utilisées par les dialogues `Imprimer' et `Enregistrer dans un fichier' pour sélectionner uniquement les pages marquées du fichier DVI.

Lorsque le pointeur de la souris se trouve à l'intérieur de la liste de pages, la molette de la souris passe à la page suivante ou précédente.

BARRES DE DÉFILEMENT

Les barres de défilement (si présentes) se comportent de manière standard : appuyer sur le Bouton 2 dans une barre de défilement déplace le bord supérieur ou gauche de la barre de défilement vers ce point et la fait éventuellement glisser ; appuyer sur le Bouton 1 déplace l'image vers le haut ou vers la droite d'une quantité égale à la distance entre le clic du bouton et le coin supérieur gauche de la fenêtre ; appuyer sur le Bouton 3 déplace l'image vers le bas ou vers la gauche de la même quantité.

Les barres de défilement peuvent être supprimées via le drapeau / raccourci clavier -expertmode (qui voir).

LOUPE

Par défaut, les boutons de souris 1 à 5 font apparaître une ``loupe'' qui affiche une image non réduite de la page (c'est-à-dire une image à la résolution déterminée par l'option / ressource X pixels ou mfmode) à différentes tailles. Lorsque la loupe est déplacée, de petites marques de graduation ressemblant à des règles sont affichées sur les bords de la loupe (sauf si la ressource X delayRulers est définie sur false, auquel cas les marques de graduation seront toujours affichées). L'unité des marques est déterminée par la ressource X tickUnits (mm par défaut). Cette unité peut être changée à l'exécution via l'action switch-magnifier-units(), liée par défaut au raccourci clavier `t' (voir la description de cette touche, et de switch-magnifier-units() pour plus de détails sur les unités disponibles).
La longueur des marques de graduation peut être modifiée via la ressource X tickLength (4 par défaut). Une valeur nulle ou négative supprime les marques de graduation.

HISTORIQUE DES PAGES

Xdvi conserve un historique des pages consultées, et vous pouvez vous déplacer dans l'historique et supprimer des éléments en utilisant les touches [ (pagehistory-back()), ] (pagehistory-forward()), Ctr-[ (pagehistory-delete-backward()) et Ctr-] (pagehistory-delete-forward()).

Lorsque l'une des commandes d'historique est utilisée, l'historique des pages s'affiche dans la barre d'état en bas de la fenêtre, l'élément de la liste actuel étant marqué par des crochets `[', `]' et un contexte gauche et droit d'au plus 10 éléments. Les frontières de fichiers sont marquées par `#'.

La taille de l'historique peut être personnalisée avec la ressource X pageHistorySize (la taille par défaut est de 1000 éléments). Si la taille est réglée à 0, les commandes d'historique sont désactivées.

LIENS HYPERTEXTES

Les actions do-href() et do-href-newwindow() (liées par défaut à Souris-1 et Souris-2 si le pointeur se trouve actuellement sur un lien hypertexte) peuvent être utilisées pour ouvrir la cible du lien dans la même fenêtre (do-href()) ou dans une nouvelle fenêtre (do-href-newwindow()).

Si la cible du lien n'est pas un fichier sur le disque local, xdvi tente de lancer un navigateur Web (tel que spécifié par l'option en ligne de commande -browser, la variable d'environnement BROWSER ou la ressource X wwwBrowser, dans cet ordre) pour récupérer le document. Voir la description de la variable d'environnement BROWSER, ci-dessous, pour un exemple de réglage.

Si le fichier est un fichier local, xdvi tente de déterminer s'il s'agit d'un fichier DVI. Si c'est le cas, xdvi tentera d'afficher le fichier ; sinon, il tentera de déterminer le type MIME du fichier, et à partir de là, une application appropriée pour ouvrir le fichier. Ceci est fait en analysant les fichiers spécifiés par la variable d'environnement EXTENSIONMAPS pour un mappage des extensions de noms de fichiers aux types MIME, et les fichiers déterminés par la variable d'environnement MAILCAPS pour un mappage des types MIME aux programmes d'application. Voir les descriptions de ces variables dans la section ENVIRONNEMENT, ci-dessous, pour une description plus détaillée et les valeurs par défaut de ces variables. Si aucun fichier approprié n'est trouvé, un ensemble de types MIME et d'applications par défaut intégrés est utilisé.

Xdvi utilise actuellement aucune heuristique à part le suffixe du nom de fichier pour déterminer le type MIME d'un fichier. Si un nom de fichier n'a pas de suffixe, la valeur de la ressource noMimeSuffix est utilisée (par défaut application/x-unknown). Si le suffixe ne correspond à aucun des suffixes dans mime.types, la valeur de la ressource unknownMimeSuffix est utilisée (par défaut application/x-unknown). Si les entrées mailcap ne listent pas de visionneuse pour un type MIME donné, xdvi affichera une boîte de dialogue d'avertissement. Si vous souhaitez éviter cet avertissement, et par exemple utiliser toujours le navigateur Netscape pour les types MIME inconnus, vous pourriez ajouter la ligne suivante à votre fichier ~/.mailcap :

application/xdvi-unknown; \
    netscape -raise -remote 'openURL(%s,new-window)'

RECHERCHE DE CHAÎNE

Le raccourci clavier Ctrl-f ou l'entrée de menu Fichier > Rechercher ... (ou le symbole `Jumelles' dans la barre d'outils, pour Motif) ouvre une fenêtre de dialogue pour rechercher une chaîne de texte ou une expression régulière dans le fichier DVI. Le raccourci clavier Ctrl-g saute à la prochaine correspondance (comme appuyer sur le bouton `Rechercher' dans la fenêtre de recherche).

Par défaut, les correspondances sont mises en surbrillance en couleur inversée. Si l'affichage ne fonctionne pas en TrueColor, ou si la ressource X matchHighlightInverted est définie sur false ou si l'option en ligne de commande -nomatchinverted est utilisée, xdvi dessinera à la place un rectangle dans la couleur highlight (voir l'option -hl) autour de la correspondance.

Si une correspondance traverse une limite de page, seule la partie de la première page est mise en surbrillance. Xdvi analysera jusqu'à 2 pages adjacentes pour faire correspondre des chaînes traversant les limites de pages ; mais notez que les lignes d'en-tête ou de pied de page, ou les pages flottantes intercalées seront traitées comme faisant partie du texte analysé. Un tel texte provoquera généralement l'échec de la mise en correspondance multi-pages.

Cela souligne le fait que la recherche dans le texte formaté (la sortie DVI) fonctionne différemment de la recherche dans le texte source : La recherche dans le fichier DVI permet de sauter plus facilement les instructions de formatage, et permet de rechercher par exemple les césures et les numéros d'équations ; mais parfois les résultats du formatage peuvent aussi gêner, par exemple dans le cas des notes de bas de page. Dans ces cas, il est préférable de rechercher dans la source TeX à la place. L'utilisation de source specials permettra de basculer entre l'affichage xdvi et l'éditeur avec le.

X source plus facile ; voir la section SOURCE SPECIALE ci-dessous pour plus d'informations à ce sujet.

Le texte extrait du fichier DVI est encodé en UTF-8 (vous pouvez visualiser ce texte en enregistrant le fichier au format UTF-8 via le menu Fichier > Enregistrer sous...). Si xdvi a été compilé avec la prise en charge de locale, de nl_langinfo() et d' iconv, le terme de recherche est converti à partir du jeu de caractères spécifié par la locale actuelle vers UTF-8. (Voir la sortie de locale -a pour une liste des paramètres de locale disponibles sur votre système). Si nl_langinfo() n'est pas disponible, mais qu' iconv l'est, vous pouvez spécifier l'encodage d'entrée pour iconv via la ressource X textEncoding (voir la sortie de iconv -l pour une liste des encodages valides). Si la prise en charge d' iconv n'est pas disponible, seuls les encodages ISO-8859-1 et UTF-8 sont pris en charge (ces noms ne sont pas sensibles à la casse).

Les caractères idéographiques des polices CJKV sont traités spécialement : tous les espaces blancs (espaces et sauts de ligne) avant et après ces caractères sont ignorés dans la chaîne de recherche et dans le fichier DVI.

Pour trouver un caractère de nouvelle ligne, utilisez \n dans la chaîne de recherche ; pour trouver la chaîne \n, utilisez \\n.

Si la case à cocher Expression Régulière est activée, la chaîne est traitée comme une expression régulière en syntaxe POSIX étendue, avec les propriétés suivantes :

-
a? correspond à a zéro ou une fois.
-
a* correspond à a zéro fois ou plus.
-
a+ correspond à a une fois ou plus. Notez que * et + sont gourmands, c'est-à-dire qu'ils correspondent à la plus longue sous-chaîne possible.
-
Le motif . correspond à n'importe quel caractère sauf un saut de ligne. Pour faire correspondre également un saut de ligne, utilisez `(.|\n)'.
-
a{n} correspond à a exactement n fois.
-
a{n,m} correspond à a au moins n fois et au plus m fois.
-
a|b correspond à a ou b. Les parenthèses peuvent être utilisées pour le regroupement, par exemple : (a|b)|c.
-
La chaîne correspondant au n-ième groupe peut être référencée par \n, par exemple \1 fait référence à la première correspondance.
-
Les caractères ^ et $ correspondent respectivement au début et à la fin d'une ligne.
-
[abc] correspond à l'une des lettres a, b, c, et [a-z] correspond à tous les caractères de a à z.
-
Chaque élément d'une expression régulière peut également être l'une des classes de caractères POSIX suivantes : 
[[:alnum:]] [[:alpha:]] [[:blank:]] [[:cntrl:]] [[:digit:]]
[[:graph:]] [[:lower:]] [[:print:]] [[:space:]] [[:upper:]]

Celles-ci peuvent être niées en insérant un symbole ^ après la première parenthèse : [^[:alpha:]]

Pour plus de détails sur les expressions régulières POSIX, voir par exemple la définition de la norme IEEE Std 1003.1 disponible en ligne sur :

http://www.opengroup.org/onlinepubs/007904975/basedefs/xbd_chap09.html
-
En tant qu'extension non standard, les abréviations suivantes de type Perl peuvent être utilisées à la place des classes POSIX : 
Symbole	Signification	Classe POSIX
    \w	un caractère alphanumérique	[[:alnum:]]
    \W	un caractère non alphanumérique	[^[:alnum:]]
    \d	un caractère numérique	[[:digit:]]
    \D	un caractère non numérique	[^[:digit:]]
    \s	un caractère d'espacement	[[:space:]]
    \S	un caractère non d'espacement	[^[:space:]]
-
Les caractères suivants sont des symboles spéciaux ; ils doivent être échappés avec \ pour les faire correspondre littéralement : ( ) [ ] . * ? + ^ $ \.
-
Les correspondances de longueur nulle sont ignorées silencieusement.

La boîte de dialogue propose également des cases à cocher pour :

-
rechercher en arrière ;
-
effectuer une recherche sensible à la casse (par défaut, la casse est ignorée, c'est-à-dire qu'une chaîne de recherche Test correspondra aux chaînes test et TEST dans le fichier DVI) ;
-
ignorer les sauts de ligne et les traits d'union : ceci supprime tous les traits d'union en fin de ligne et les sauts de ligne qui suivent, et remplace tous les sauts de ligne restants par des espaces blancs. Ainsi, les mots composés d'un trait d'union apparaîtront comme un seul mot pour la recherche, et une recherche de deux mots séparés par un espace trouvera également les mots s'ils sont séparés par un saut de ligne.
Notez que la suppression des traits d'union peut entraîner des effets indésirables pour les mots composés contenant des traits d'union qui sont coupés après le trait d'union, et que le remplacement des sauts de ligne affecte l'interprétation des expressions régulières comme suit : Le motif . correspondra également aux sauts de ligne, et ^ et $ ne correspondront plus aux début et fin de lignes. (Étant donné qu'il n'y a actuellement pas d'option pour désactiver la gourmandise de * et +, l'activation de cette option entraînera généralement des correspondances plus longues que souhaité.)

Les paramètres actuels des cases à cocher sont enregistrés dans le fichier ~/.xdvirc.

BOÎTE DE DIALOGUE IMPRIMER

La boîte de dialogue d'impression vous permet d'imprimer toutes les pages, les pages marquées (cliquer ou faire glisser la souris-2 dans la liste des pages pour les marquer), ou une plage de pages. Notez que les numéros de page font toujours référence aux pages physiques, donc si vous utilisez l'option `utiliser les pages TeX', vous voudrez peut-être la désactiver pour faciliter la détermination des numéros de page corrects (ou éviter ce problème entièrement en marquant les pages à imprimer).

La valeur du champ de texte Imprimante est passée à dvips via le mécanisme -o!, comme un seul argument après le `!'. Tous les arguments listés dans le champ Options dvips sont segmentés à l'espacement et passés comme arguments séparés à dvips. Si vous voulez par exemple imprimer le fichier 2-up, vous devriez entrer la chaîne suivante dans le champ Imprimante :

    psnup -2 -q | lpr -Plp

Il existe plusieurs ressources pour personnaliser le comportement et les entrées par défaut de la boîte de dialogue d'impression :

dvipsPrinterString
dvipsOptionsString
Celles-ci peuvent être utilisées pour fournir des entrées par défaut pour les champs de texte Imprimante et Options dvips, respectivement. Si aucune taille de papier n'est spécifiée dans le fichier DVI (via par exemple \usepackage[dvips]{geometry} - c'est la méthode préférée), le champ de saisie est initialisé avec la valeur actuelle de l'option en ligne de commande/ressource X paper. Par exemple, l'option -paper a4r est traduite en options dvips -t a4 -t landscape. Notez qu'aucune vérification n'est effectuée pour savoir si dvips comprend réellement ces options (il les ignorera s'il ne le peut pas) ; actuellement, toutes les options utilisées par xdvi ne sont pas non plus couvertes par dvips.
dvipsHangTime
dvipsFailHangTime
Celles-ci spécifient le temps (en millisecondes) pendant lequel la fenêtre de progression de l'impression restera ouverte après la fin du processus dvips. La valeur de dvipsHangTime est utilisée si le processus se termine avec succès ; dvipsFailHangTime est utilisée s'il se termine avec une erreur. Les valeurs par défaut sont respectivement 1,5 et 5 secondes. Si les deux valeurs sont négatives, la fenêtre restera ouverte jusqu'à ce qu'elle soit fermée par l'utilisateur.

BOÎTE DE DIALOGUE ENREGISTRER

Cette boîte de dialogue vous permet d'enregistrer toutes les pages ou les pages sélectionnées/marquées du fichier DVI actuel. Vous pouvez enregistrer dans l'un des formats suivants :

-
PostScript (utilise dvips pour convertir le fichier DVI en fichier PostScript, comme lors de l'impression vers un fichier PostScript).
-
PDF (utilise d'abord dvips pour convertir le fichier DVI en fichier PostScript, puis utilise ps2pdf pour convertir le fichier PostScript en PDF).
-
Texte brut en encodage ISO-8859-1 ou UTF-8. Ce dernier préservera davantage les caractères spéciaux LaTeX, par exemple en mode mathématique. Notez cependant que seuls quelques symboles mathématiques de LaTeX peuvent être rendus correctement sous forme de texte ; cette fonctionnalité fonctionne donc mieux pour les documents en texte brut. Si un caractère ne peut pas être affiché dans le jeu de caractères sélectionné, il est remplacé par `\' suivi du code hexadécimal du caractère. Si un caractère n'est pas reconnu du tout, il est remplacé par `?'.

Les programmes de conversion PostScript et PDF peuvent être personnalisés via les options de ligne de commande ou les ressources X -dvipspath/.dvipsPath et -ps2pdfpath/.ps2pdfPath, respectivement ; voir l'explication de ces options ci-dessus pour plus de détails.

MODES

La combinaison de touches Ctrl-m [switch-mode()] bascule entre trois configurations de souris différentes, qui peuvent également être activées via le menu Modes (dans Motif, c'est un sous-menu du menu Options appelé Mode Souris). Le mode par défaut au démarrage peut être personnalisé via la ressource X mouseMode ou l'option en ligne de commande -mousemode. Le mode de démarrage par défaut est le Mode Loupe.

Note : Les modes sont implémentés en modifiant l'action magnifier(). Le changement de mode ne fonctionnera pas si Souris-1 a été personnalisé avec une séquence d'actions ne contenant pas l'action magnifier().

Mode Loupe
Dans ce mode, les boutons de souris 1 à 5 font apparaître une « loupe » qui affiche une image non réduite de la page (c'est-à-dire une image à la résolution déterminée par l'option/ressource X pixels ou mfmode) de différentes tailles. Lorsque la loupe est déplacée, de petites marques de type règle sont affichées sur les bords de la loupe (sauf si la ressource X delayRulers est définie sur false, auquel cas les marques sont toujours affichées). L'unité des marques est déterminée par la ressource X tickUnits (mm par défaut). Cette unité peut être modifiée à la volée via l'action switch-magnifier-units(), par défaut liée à la touche `t' (voir la description de cette touche, et de switch-magnifier-units() pour plus de détails sur les unités disponibles).
La longueur des marques peut être modifiée via la ressource X tickLength (4 par défaut). Une valeur nulle ou négative supprime les marques.
Mode Sélection de Texte
Ce mode vous permet de sélectionner une région rectangulaire de texte dans le D
VI fichier en maintenant le bouton de la souris enfoncé et en déplaçant la souris. Le texte est placé dans la sélection primaire X afin qu'il puisse être collé dans d'autres applications X avec le bouton de la souris comme d'habitude.
Si xdvi a été compilé avec le support des locales, nl_langinfo() et iconv, le texte sélectionné est converti dans le jeu de caractères de la locale actuelle (voir la sortie de locale -a pour une liste des paramètres de locale disponibles sur votre système). Si nl_langinfo() n'est pas disponible, mais que iconv l'est, vous pouvez spécifier l'encodage d'entrée pour iconv via la ressource X textEncoding (voir la sortie de iconv -l pour une liste des encodages valides). Si le support iconv n'est pas disponible, seuls les encodages ISO-8859-1 et UTF-8 sont supportés (ces noms ne sont pas sensibles à la casse).
Notez que UTF-8 est le seul encodage qui peut rendre tous les caractères (par exemple, les symboles mathématiques) d'un fichier DVI. Si ISO-8859-1 est actif, les caractères qui ne peuvent pas être affichés sont remplacés par `\' suivi du code hexadécimal du caractère. Pour les autres encodages, de tels caractères peuvent déclencher des messages d'erreur iconv. Si un caractère n'est pas reconnu du tout, il est remplacé par `?'.
Pour extraire de plus grandes portions de texte, vous pouvez alternativement enregistrer des pages sélectionnées ou le fichier entier en format texte via le menu Fichier > Enregistrer sous....
Mode Règle
Ce mode offre un moyen simple de mesurer les distances sur la page.
Lorsque ce mode est activé, le curseur de la souris se transforme en une croix fine, et une règle plus grande en forme de croix est dessinée dans la couleur de surbrillance à l'emplacement de la souris. La règle n'a pas d'unités attachées ; au lieu de cela, la distance actuelle entre la règle et le curseur de la souris est continuellement affichée dans la barre d'état.
Lorsque le mode Règle est activé, la règle est d'abord attachée à la souris et peut être déplacée. Elle peut ensuite être positionnée à un endroit fixe en cliquant sur le bouton de la souris. Après cela, le curseur de la souris peut être déplacé pour mesurer la distance horizontale (dx), verticale (dy) et directe (la plus courte) (dr) entre le centre de la règle et la souris.
Cliquer à nouveau sur le bouton de la souris déplacera la règle vers la position actuelle de la souris, et maintenir le bouton de la souris enfoncé déplacera la règle.
En mode Règle, les raccourcis clavier suivants étendent ou remplacent les raccourcis par défaut :
o
[ruler-snap-origin()] Ancre la règle à l'origine des coordonnées (0,0).
t
[remplace switch-magnifier-units()] Bascule entre différentes unités de règle, qui peuvent être spécifiées par la ressource X tickUnits (`mm' par défaut).
P
[remplace declare-page-number()] Affiche les distances indiquées dans la barre d'état sur la sortie standard.

La barre d'outils Motif peut également être personnalisée. Le fichier XPM utilisé pour les icônes de la barre d'outils peut être spécifié via la ressource toolbarPixmapFile, qui doit contenir un nom de fichier pouvant être trouvé dans l'un des XFILESEARCHPATH ou XDVIINPUTS (voir la section RECHERCHE DE FICHIERS ci-dessous pour plus d'informations sur ces variables). - l'index d'une icône dans le fichier image (commençant à zéro) ;

- une séquence d'actions à effectuer lorsque le bouton de la barre d'outils correspondant est enfoncé.

MISE EN NUANCES DE GRIS ET CARTES DE COULEURS

La fonction d'anti-crénelage en nuances de gris dans xdvi ne fonctionnera pas de manière optimale si l'écran ne dispose pas de suffisamment de couleurs. Cela peut se produire si d'autres applications utilisent la plupart de la carte de couleurs (même si elles sont iconifiées). Si cela se produit, xdvi affichera un message d'erreur et activera l'option -copy. Cela entraînera l'affichage incorrect des caractères superposés ; cela peut également entraîner une mauvaise qualité d'affichage si le nombre de couleurs disponibles est très faible.

Généralement, ce problème survient sur les écrans qui allouent huit bits de mémoire vidéo par pixel. Pour savoir combien de bits par pixel votre écran utilise, tapez xwininfo dans une fenêtre xterm, puis cliquez sur la fenêtre racine lorsque vous y êtes invité. L'entrée "Depth:" vous indiquera combien de bits sont alloués par pixel.

Les écrans utilisant au moins 15 bits par pixel sont généralement des visuels TrueColor, qui ne posent pas ce problème, car leur carte de couleurs est allouée de manière permanente et disponible pour toutes les applications. (La classe visuelle est également affichée par xwininfo.) Pour plus d'informations sur les classes visuelles, consultez la documentation du système X Window.

Pour atténuer ce problème, on peut donc (a) exécuter avec plus de bits par pixel (cela peut nécessiter d'ajouter de la mémoire vidéo ou de remplacer la carte vidéo), (b) fermer d'autres applications qui pourraient utiliser une grande partie de la carte de couleurs, puis redémarrer xdvi, ou (c) exécuter xdvi avec l'option -install.

Une application qui est souvent à l'origine de ce problème est Netscape. Dans ce cas, il existe deux autres alternatives pour remédier à la situation. On peut exécuter "netscape -install" pour que Netscape installe une carte de couleurs privée. Cela peut provoquer des changements de couleur étranges lorsque la souris est déplacée vers une autre fenêtre. Ou bien, on peut exécuter "netscape -ncols 220" pour limiter Netscape à un plus petit nombre de couleurs. Un nombre plus petit garantira que d'autres applications disposent de plus de couleurs, mais dégradera la qualité des couleurs dans la fenêtre Netscape.

GESTION DES FIGURES POSTSCRIPT

Xdvi peut afficher des fichiers PostScript encapsulés (EPS) inclus dans le fichier dvi. Ces fichiers sont d'abord recherchés dans le répertoire où se trouve le fichier dvi, puis en utilisant les règles normales de Kpathsea. Il y a une exception à cela : si le nom du fichier commence par une apostrophe inversée (`), les caractères restants dans le nom du fichier donnent une commande shell (souvent zcat) qui est exécutée ; sa sortie standard est ensuite envoyée pour être interprétée comme du PostScript. Comme l'exécution de commandes shell arbitraires avec les permissions de l'utilisateur représente un risque de sécurité énorme, l'évaluation de ces commandes entre apostrophes inversées est désactivée par défaut. Elle doit être activée via l'option de ligne de commande -allowshell. NOTE : Vous ne devriez jamais utiliser cette option lorsque vous visualisez des documents que vous n'avez pas vous-même compilés. Les apostrophes inversées ne sont pas nécessaires pour décompresser des fichiers PostScript zippés, car xdvi peut le faire à la volée si le nom du fichier se termine par .eps.gz ou .eps.Z (et si les premiers octets du fichier indiquent que le fichier est effectivement compressé). Ceci est plus sûr et plus flexible que l'approche par apostrophes inversées, car les règles de recherche de fichiers par défaut s'appliqueront également à ces noms de fichiers.

POLICES TYPE 1

En utilisant FreeType (version 2), xdvi peut rendre les polices PostScript<tm> Type 1 directement, sans passer par les polices TeX en pixels (pk). L'avantage est qu'une seule taille de chaque police doit être stockée sur le disque. À moins que l'option -notype1fonts ne soit utilisée, xdvi tentera de rendre chaque police en utilisant FreeType. Ce n'est qu'en dernier recours qu'il invoquera un programme externe (comme mktexpk, qui peut à son tour invoquer des utilitaires comme ps2pk ou gsftopk) pour générer une police en pixels à partir de la source Type 1. Le rendu direct des polices Computer Modern devrait fonctionner immédiatement, tandis que d'autres polices Type 1 telles que les 35 polices PostScript<tm> `standard' résidentes dans les imprimantes peuvent devoir être rendues accessibles pour être utilisées avec xdvi, à moins que votre administrateur système ou votre distribution TeX ne l'ait déjà fait (ce qui est le cas par exemple pour les distributions TeX Live actuelles). Pour les 35 polices PostScript<tm> résidentes, xdvik recherchera en utilisant la Fontmap fournie avec Ghostscript, si nécessaire. De plus, la distribution xdvik est livrée avec un utilitaire appelé t1mapper pour rendre ces polices disponibles pour xdvi ; voir la page de manuel de t1mapper(1) pour les détails d'utilisation. Ce programme sera probablement supprimé à l'avenir, car il n'est probablement plus nécessaire.

SPÉCIALES (GÉNÉRALEMENT)

Toutes les spéciales utilisées par xdvi peuvent être précédées des caractères « xdvi: ». Cela ne modifie pas le comportement de la spéciale sous xdvi, mais indique aux autres pilotes dvi (comme par exemple dvips) d'ignorer la spéciale.

SPÉCIALES SOURCE

Certaines implémentations TeX ou packages de macros fournissent la possibilité d'inclure automatiquement des « spéciales source » dans un fichier DVI. Celles-ci contiennent le numéro de ligne, éventuellement un numéro de colonne, et le nom du fichier source .tex. Cela permet de passer d'un fichier .dvi à l'endroit correspondant dans le source .tex et vice versa (également appelé « recherche inversée » - passer du fichier DVI au fichier TeX est aussi connu sous le nom de « recherche inverse », et passer du fichier TeX au fichier DVI comme « recherche avant »).

Pour être utilisables avec xdvi, les spéciales source dans le fichier dvi doivent avoir l'un des formats suivants :

    src:ligne[ ]nomfichier
    src:ligne:col[ ]nomfichier
    src:ligne
    src:ligne:col
    src::col
Si nomfichier ou ligne sont omis, les dernières valeurs utilisées sont conservées. La première spéciale source sur chaque page doit être dans l'une des deux premières formes, car les valeurs par défaut ne sont pas héritées d'une page à l'autre.

Vous aurez besoin d'une implémentation TeX qui fournit un commutateur approprié (par exemple, -src) ou d'un package de macros (comme srcltx.sty ou srctex.sty, disponibles sur CTAN:macros/latex/contrib/supported/srcltx/) pour insérer de telles spéciales source dans le fichier DVI.

Pour la recherche inversée, la combinaison Ctrl-Souris 1 ouvrira xdvi dans un éditeur (la valeur de l'option de ligne de commande -editor) avec le fichier et le numéro de ligne de la source .tex. Voir la description de l'option -editor pour plus d'informations et d'exemples de configuration.

Pour la recherche avant, xdvi dispose d'une option -sourceposition qui fait que xdvi saute à la page dans le fichier DVI correspondant à la ligne donnée (ou la ligne la plus proche ayant une spéciale source) du fichier spécifié et met en évidence la région trouvée. Voir la description de l'option -sourceposition pour plus de détails.

Plus d'informations sur la configuration de divers éditeurs pour une utilisation avec des spéciales source sont disponibles sur :

http://xdvi.sourceforge.net/inverse-search.html

SPÉCIALES TAILLE DE PAPIER

xdvi accepte des spéciales pour définir la taille du papier du document. Ces spéciales doivent être de la forme

    papersize=[*]largeur,hauteur

où largeur et hauteur donnent respectivement la largeur et la hauteur du papier. Chacune d'elles doit apparaître sous la forme d'un nombre décimal suivi de l'une des abréviations de deux lettres pour les unités acceptées par TeX (pt, pc, in, bp, cm, mm, dd, cc, ou sp). Si un astérisque (*) apparaît juste avant la largeur, alors les mesures se réfèrent aux dimensions du document (par exemple pt par opposition à truept). Cela permet à un package de macros de faire varier la taille de la page en fonction des éléments du document ; par exemple :

\special{xdvi: papersize=*\number\wd\mybox sp,
         \number\ht\mybox sp}

À l'exception de l'astérisque, ce format est compatible avec dvips.

La dernière spéciale papersize sur une page détermine la taille de cette page. S'il n'y a pas de telle spéciale sur une page donnée, la dernière papersize est utilisée, ou, s'il n'y a pas de spéciales papersize sur les pages précédentes, alors la valeur de la ressource paper (ou l'option -paper sur la ligne de commande) est utilisée. Ainsi, la taille du papier peut varier pour différentes pages du fichier dvi.

Si la ressource paper (ou l'option de ligne de commande -paper) commence par un signe plus (« + »), alors toutes les spéciales papersize du fichier dvi sont ignorées.

Les spéciales de couleur prises en charge par xdvi sont les mêmes que celles prises en charge par dvips, à l'exception que la spécification de couleur PostScript littérale (comme dans l'exemple AggiePattern de la documentation dvips) n'est pas prise en charge. Il y a également des restrictions dues à la manière dont les routines de dessin d'xdvi sont implémentées ; par exemple, les macros \colorbox et \fcolorbox ne fonctionnent pas avec xdvi. ENVIRONNEMENT

Xdvik utilise les mêmes variables d'environnement et algorithmes pour rechercher des fichiers de polices que TeX et ses associés. Voir la documentation de la bibliothèque Kpathsea, kpathsea.dvi, pour une description détaillée de ceux-ci.

De plus, xdvik accepte les variables suivantes :

DISPLAY
Spécifie quel terminal graphique utiliser.
KPATHSEA_DEBUG
Traçage des recherches Kpathsea ; définissez-le à -1 (= tous les bits activés) pour un traçage complet.
EXTENSIONMAPS
Une liste de fichiers à rechercher pour les entrées de types MIME (comme pour Acrobat Reader). Les entrées antérieures dans l'un de ces fichiers remplacent les entrées ultérieures. Si cette variable n'est pas définie, le chemin par défaut suivant est utilisé :
$HOME/.mime.types:/etc/mime.types:\
    /usr/etc/mime.types:/usr/local/etc/mime.types
MAILCAPS
Une liste de fichiers à rechercher pour les entrées mailcap, telles que définies par la RFC 1343. Voir cette RFC ou la page de manuel mailcap(4) pour une description détaillée du format du fichier mailcap. Actuellement, seules les fonctionnalités mailcap suivantes sont prises en charge :
test=commande
L'entrée n'est utilisée que si commande peut être exécutée via l'appel system() et si l'appel system() renvoie la valeur 0 (succès). La chaîne commande peut contenir la chaîne de format %s, qui sera remplacée par le nom du fichier.
needsterminal
Si ce drapeau est utilisé, la commande sera exécutée dans une nouvelle fenêtre xterm en ajoutant « xterm -e » à la chaîne de commande.
Tous les autres champs de l'entrée mailcap sont ignorés par xdvi. Les entrées antérieures dans l'un de ces fichiers remplacent les entrées ultérieures. Si la variable n'est pas définie, le chemin par défaut suivant est utilisé : 
$HOME/.mailcap:/etc/mailcap:/usr/etc/mailcap:\
    /usr/local/etc/mailcap
Pour des raisons de sécurité, certains caractères spéciaux (c'est-à-dire ( ) ` \ ;) sont échappés dans l'argument avant d'être passés à system().
BROWSER
Détermine le navigateur web utilisé pour ouvrir les liens externes (c'est-à-dire toutes les URL qui ne commencent pas par le schéma `file:' et qui ne sont pas des liens relatifs dans le fichier DVI local), et pour ouvrir les liens pour lesquels aucun visualiseur n'a été spécifié dans les fichiers mailcap. La valeur de cette variable est une liste de commandes séparées par des deux-points. Xdvi essaiera chacune d'elles en séquence jusqu'à ce que l'une réussisse (c'est-à-dire qu'elle ne renvoie pas immédiatement le statut 0). Cela vous permet de spécifier votre navigateur préféré au début

ENVIRONNEMENT

BROWSER
Une liste de commandes de navigateur Web séparées par des deux-points. La première commande qui réussit à ouvrir une URL est utilisée. Chaque occurrence de %s dans la chaîne est remplacée par l'URL cible ; chaque occurrence de %% est remplacée par un seul %. Si aucun %s n'est présent, la chaîne d'URL est ajoutée comme argument supplémentaire.
Un exemple de configuration est :
netscape -raise -remote 'openURL(%s,new-window)':xterm -e lynx %s:xterm -e wget %s:lynx %s:wget %s
Voir
http://www.catb.org/~esr/BROWSER/

pour plus de détails sur la variable d'environnement BROWSER.

GS_LIB
Une liste de répertoires séparés par des deux-points à rechercher pour les fichiers Fontmap, etc., tels qu'utilisés pour Ghostscript. Elle a la même signification que lors de l'exécution de Ghostscript. Dans xdvik, elle est utilisée lors de la recherche de fichiers de polices lorsque le fichier de correspondance ne donne pas de nom de fichier pour la police (ce qui devrait être assez rare). La commande gs -h listera la valeur par défaut que Ghostscript utilise. Voir aussi la variable d'environnement XDVI_GS_LIB (ci-dessous).
XDVI_GS_LIB
Ceci a le même effet que GS_LIB mais n'affecte que xdvi. Utilisez ceci lorsque vous souhaitez utiliser une valeur différente pour GS_LIB lors de l'exécution de xdvi, mais utilisez soit la valeur par défaut compilée, soit une autre valeur lors de l'exécution de Ghostscript. Si GS_LIB et XDVI_GS_LIB sont tous deux définis, alors xdvi utilise XDVI_GS_LIB. Pour utiliser la valeur par défaut compilée dans xdvi tout en conservant la possibilité de définir GS_LIB pour une utilisation avec Ghostscript, vous pouvez définir XDVI_GS_LIB sur la chaîne vide.
TMPDIR
Le répertoire à utiliser pour stocker les fichiers temporaires créés lors de la décompression des fichiers PostScript.
XEDITOR
Détermine la commande d'éditeur utilisée pour la recherche inversée de spécials source, si ni l'option de ligne de commande -editor ni la ressource .editor ne sont spécifiées. Voir la description de l'option de ligne de commande -editor pour les détails sur le format.
VISUAL
Détermine un éditeur qui sera ouvert dans une fenêtre xterm si ni -editor, ni .editor, ni XEDITOR ne sont spécifiés.
EDITOR
Détermine un éditeur qui sera ouvert dans une fenêtre xterm si ni -editor, ni .editor, ni XEDITOR, ni VISUAL ne sont spécifiés.
WWWBROWSER
Obsolète ; utilisez BROWSER à la place.

LIMITATIONS

xdvi accepte de nombreux types de specials PostScript acceptés par dvips, mais pas tous. Par exemple, il accepte la plupart des specials générés par epsf et psfig. Il ne prend cependant pas en charge bop-hook ou eop-hook, ni ne permet aux commandes PostScript d'affecter le rendu des éléments qui ne sont pas PostScript (par exemple, les exemples « NEAT » et « A » pivoté dans le manuel de dvips). Ces restrictions sont dues à la conception de xdvi ; il est fort probable qu'elles resteront toujours.

Les specials de rotation LaTeX2e ne sont actuellement pas pris en charge.

Les fichiers MetaPost contenant du texte inclus ne sont pas pris en charge.

La gestion des couleurs de Xdvi ne prend pas en charge les macros \colorbox et \fcolorbox ; il est peu probable que cela change dans un avenir proche. Cela signifie également que, par exemple, les tableaux colorés (tels que créés par le paquet colortbl) peuvent être mal rendus : le texte dans des couleurs autres que la couleur de premier plan par défaut peut ne pas s'afficher. Lorsque la page est redessinée (par exemple, après avoir utilisé le magnétoscope), la couleur d'arrière-plan des cellules peut masquer le texte.

FICHIERS

$HOME/.xdvirc
Un fichier qui contient tous les paramètres que l'utilisateur a modifiés via les touches, les menus `Options' et les menus et boîtes de dialogue Xaw, en tant que ressources X. Ces ressources remplacent les paramètres dans $HOME/.Xdefaults. Ce fichier est ignoré si l'option -q est utilisée ou si la ressource X noInitFile est définie.
config.xdvi
Un fichier de configuration optionnel pour la configuration des polices Type 1, qui spécifie des fichiers de correspondance de type dvips spécifiques à xdvik. S'il est utilisé, il doit être présent dans le répertoire déterminé par la variable d'environnement TEXCONFIG. Son format est similaire aux fichiers de configuration de dvips, sauf qu'il n'est analysé que pour les noms de fichiers de correspondance (directives p et p+).
