NOM

xdg-dbus-proxy - Proxy D-Bus

SYNTAXE

xdg-dbus-proxy [OPTION...] [ADRESSE CHEMIN [OPTION...]...]

DESCRIPTION

xdg-dbus-proxy est un proxy filtrant pour les connexions D-Bus. Ses arguments sont une ou plusieurs paires ADRESSE-CHEMIN spécifiant les bus à proxifier, avec des options qui spécifient le filtrage à appliquer.

Fonctionnement de base

Le proxy écoute sur la socket de domaine Unix à CHEMIN, et pour chaque client qui se connecte à la socket, il ouvre une nouvelle connexion vers lADRESSE D-Bus spécifiée (typiquement le bus de session) et transmet les données entre les deux. Pendant la phase d'authentification, toutes les données sont transmises telles que reçues, et en plus pour le premier octet zéro, nous envoyons également les identifiants du proxy au bus.

Une fois la connexion authentifiée, il existe deux modes : filtré et non filtré. En mode non filtré, tous les messages sont transmis tels qu'ils sont reçus. En mode filtré, une politique est appliquée pour déterminer quels messages sont autorisés et lesquels sont rejetés.

Le filtrage est appliqué uniquement aux signaux et appels de méthodes sortants et aux signaux de diffusion entrants. Toutes les réponses (erreurs ou retours de méthodes) sont autorisées une fois pour un appel de méthode en attente, et jamais sinon.

Si un client reçoit jamais un message d'un autre pair sur le bus, le nom unique de l'expéditeur est rendu visible, afin que le client puisse suivre la durée de vie des appelants via les signaux NameOwnerChanged. Si un client appelle une méthode sur ou reçoit un signal de diffusion d'un nom (même s'il est filtré sur un sous-ensemble de chemins ou d'interfaces), la politique de base de ce nom est considérée comme (au moins) TALK, à partir de ce moment.

Politique

La politique pour le filtrage consiste en un mappage de noms bien connus à une politique qui est soit SEE, TALK, soit OWN. La politique initiale par défaut est que l'utilisateur n'est autorisé qu'à TALKER avec le bus lui-même (org.freedesktop.DBus, ou aucune destination spécifiée), et à TALKER avec son propre identifiant unique. Tous les autres clients sont invisibles.

Voici une description des niveaux de politique (chaque niveau implique les précédents) :

SEE

Le nom/ID est visible dans la réponse ListNames

Le nom/ID est visible dans la réponse ListActivatableNames

Vous pouvez appeler GetNameOwner sur le nom

Vous pouvez appeler NameHasOwner sur le nom

Vous voyez les signaux NameOwnerChanged sur le nom

Vous voyez les signaux NameOwnerChanged sur l'ID lorsque le client se déconnecte

Vous pouvez appeler les méthodes GetXXX sur le nom/ID pour obtenir, par exemple, le PID du pair

Vous obtenez AccessDenied plutôt que NameHasNoOwner lors de l'envoi de messages au nom/ID

TALK

Vous pouvez envoyer des appels de méthodes et des signaux au nom/ID

Vous recevrez des signaux de diffusion du nom/ID (si vous avez une règle de correspondance pour eux)

Vous pouvez appeler StartServiceByName sur le nom

OWN

Vous êtes autorisé à appeler RequestName/ReleaseName/ListQueuedOwners sur le nom

La politique est spécifiée avec les options --see, --talk et --own. Les noms bien connus dans ces options peuvent avoir un suffixe de '.*'. Un nom de « org.foo.* » correspond à « org.foo », « org.foo.bar » et « org.foo.bar.gazonk », mais pas à « org.foobar ».

Les politiques sont spécifiées pour les noms bien connus, mais elles affectent également le propriétaire de ce nom, de sorte que la politique pour un ID unique est l'union des politiques pour tous les noms qu'il possède. Pour des raisons techniques, la politique pour un nom unique est « collante », dans le sens où la politique la plus élevée accordée par un nom possédé une fois est conservée, même lorsque le client libère ce nom. Ceci est impossible à éviter d'une manière sans courses dans un proxy. Mais ce n'est généralement pas un problème en pratique, car peu de clients libèrent des noms et restent sur le bus.

En plus de la politique de base SEE/TALK/OWN, il est possible de spécifier des règles plus complexes concernant les appels de méthodes qui peuvent être effectués et les signaux de diffusion qui peuvent être reçus à partir de noms bien connus. Une règle peut restreindre les appels/signaux autorisés à un chemin d'objet spécifique ou à un sous-arbre de chemins d'objet, et elle peut restreindre l'interface autorisée jusqu'à une méthode ou un nom de signal individuel.

Les règles sont spécifiées avec les options --call et --broadcast. La RÈGLE dans ces options détermine quelles interfaces, méthodes et chemins d'objet sont autorisés. Elle doit être de la forme [MÉTHODE][@CHEMIN], où MÉTHODE peut être soit '*' soit une interface D-Bus, éventuellement avec un suffixe '/*', soit un nom de méthode entièrement qualifié, et CHEMIN est un chemin d'objet D-Bus, éventuellement avec un suffixe '/*'.

OPTIONS

Lorsque les options sont utilisées plusieurs fois, la dernière option l'emporte, sauf indication contraire.

Options générales :

--help

Afficher l'aide et quitter

--version

Afficher la version

--fd=FD

Écrire sur FD lorsque les proxys sont prêts, et arrêter lorsque FD est fermé.

--args=FD

Analyser les arguments séparés par nul à partir du descripteur de fichier donné. Cette option peut être utilisée plusieurs fois pour analyser les options depuis plusieurs sources.

Options du proxy :

Ces options ne peuvent être utilisées qu'après une ADRESSE et s'appliquent au proxy pour cette adresse.

--filter

Activer le filtrage

--log

Activer la journalisation

--sloppy-names

Rendre tous les noms uniques visibles.

--see=NOM

Définir la politique SEE pour le nom donné.

--talk=NOM

Définir la politique TALK pour le nom donné.

--own=NOM

Définir la politique OWN pour le nom donné.

--call=NOM=RÈGLE

Définir une règle pour les appels sur le nom donné.

--broadcast=NOM=RÈGLE

Définir une règle pour les signaux de diffusion provenant du nom donné.

EXEMPLES

$ xdg-dbus-proxy --fd=26 unix:path=/run/usr/1000/bus /run/usr/1000/.dbus-proxy/session-bus-proxy --filter --own=org.gnome.ghex.* --talk=ca.desrt.dconf --call=org.freedesktop.portal.*=* --broadcast=org.freedesktop.portal.*=@/org/freedesktop/portal/*
