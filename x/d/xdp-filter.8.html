xdp-filter(8) Un filtre de paquets simple basé sur XDP xdp-filter(8)

NOM

xdp-filter - un filtre de paquets simple basé sur XDP

SYNTAXE

Xdp-filter est un utilitaire de filtrage de paquets basé sur XDP. Il est délibérément simple et n'a donc pas les mêmes capacités de correspondance que, par exemple, netfilter. Au lieu de cela, grâce à XDP, il peut atteindre des taux de rejet très élevés : des dizaines de millions de paquets par seconde sur un seul cœur de CPU.

Exécution de xdp-filter

La syntaxe pour exécuter xdp-filter est :

xdp-filter COMMANDE [options]
Où COMMAND peut être l'un des suivants :
       load        - charger xdp-filter sur une interface
       unload      - décharger xdp-filter d'une interface
       port        - ajouter un port à la liste de filtre
       ip          - ajouter une adresse IP à la liste de filtre
       ether       - ajouter une adresse MAC Ethernet à la liste de filtre
       status      - afficher l'état actuel de xdp-filter
       poll        - interroger la sortie des statistiques
       help        - afficher la liste des commandes disponibles

Chaque commande et ses options sont expliquées ci-dessous. Ou utilisez xdp-filter COMMANDE --help pour voir les options de chaque commande.

La commande LOAD

Pour utiliser xdp-filter, il doit d'abord être chargé sur une interface. Ceci est accompli avec la commande load, qui prend le nom de l'interface comme paramètre, et permet éventuellement de spécifier les fonctionnalités qui doivent être incluses. Par défaut, toutes les fonctionnalités sont chargées, mais la désélection de certaines fonctionnalités peut accélérer la correspondance des paquets et augmenter considérablement les performances.

La syntaxe pour la commande load est :

xdp-filter load [options] <nom_interface>

Où <nom_interface> est le nom de l'interface sur laquelle charger xdp-filter, et doit être spécifié. Les options supportées sont :

-m, --mode <mode>

Spécifie le mode dans lequel le programme XDP doit être chargé. Les valeurs valides sont 'native', qui est le mode XDP par défaut dans le pilote, 'skb', qui provoque l'utilisation du soi-disant mode skb (également connu sous le nom de XDP générique), ou 'hw' qui provoque le déchargement du programme sur le matériel.

-p, --politique <politique>

Ceci définit la politique que xdp-filter applique aux paquets **ne correspondant pas** à aucune des règles de filtre. La valeur par défaut est allow (autoriser), dans laquelle les paquets ne correspondant à aucune règle sont autorisés à passer. L'autre option est deny (refuser), dans laquelle **tous** les paquets sont rejetés **sauf** ceux qui correspondent aux options de filtre.

xdp-filter ne peut pas être chargé simultanément en mode de politique deny et allow sur le système. Notez que le chargement de xdp-filter en mode deny rejettera tout le trafic sur l'interface jusqu'à ce que des règles d'autorisation appropriées soient installées, donc une certaine prudence est nécessaire pour éviter d'être bloqué hors d'un système distant.

-f, --fonctionnalites <fonct>

Utilisez cette option pour sélectionner les fonctionnalités à inclure lors du chargement de xdp-filter. Par défaut, toutes les fonctionnalités disponibles sont chargées. Sélectionnez donc des fonctionnalités individuelles en spécifiant une ou plusieurs des suivantes :

  • tcp : Support du filtrage sur le numéro de port TCP
  • udp : Support du filtrage sur le numéro de port UDP
  • ipv6 : Support du filtrage sur les adresses IPv6
  • ipv4 : Support du filtrage sur les adresses IPv4
  • ethernet : Support du filtrage sur les adresses MAC Ethernet

Spécifiez plusieurs fonctionnalités en les séparant par une virgule. Par exemple : tcp,udp,ipv6.

-v, --verbose

Activer la journalisation de débogage. Spécifiez deux fois pour encore plus de verbosité.

-h, --help

Afficher un résumé des options disponibles

La commande UNLOAD

La commande unload décharge xdp-filter d'une (ou de toutes les) interfaces, et nettoie l'état du programme.

La syntaxe pour la commande load est :

xdp-filter unload [options] <nom_interface>

Où <nom_interface> est le nom de l'interface dont il faut décharger xdp-filter, et doit être spécifié à moins que l'option --all ne soit utilisée. Les options supportées sont :

-a, --tout

Spécifiez cette option pour supprimer xdp-filter de toutes les interfaces sur lesquelles il a été chargé. Si cette option est spécifiée, aucun <nom_interface> n'est nécessaire.

Cette option peut également être utilisée pour nettoyer tout l'état de xdp-filter si le(s) programme(s) XDP ont été déchargé(s) par d'autres moyens.

-k, --garder-cartes

Spécifiez cette option pour empêcher xdp-filter de vider l'état de ses cartes (maps). Par défaut, toutes les cartes BPF qui ne sont plus nécessaires par aucun programme chargé sont supprimées. Cependant, cela supprimera également le contenu des cartes (les règles de filtrage), donc cette option peut être utilisée pour conserver les cartes afin que les règles persistent jusqu'à ce que xdp-filter soit rechargé.

-v, --verbose

Activer la journalisation de débogage. Spécifiez deux fois pour encore plus de verbosité.

-h, --help

Afficher un résumé des options disponibles

La commande PORT

Utilisez la commande port pour ajouter un port TCP ou UDP à la liste de correspondance xdp-filter. Pour que cela fonctionne, xdp-filter doit être chargé avec la fonctionnalité udp ou tcp (ou les deux) sur au moins une interface.

La syntaxe pour la commande port est :

xdp-filter port [options] <port>

Où <port> est le numéro de port à ajouter (ou à supprimer si l'option --remove est spécifiée). Les options supportées sont :

-r, --remove

Supprimer le port au lieu de l'ajouter.

-m, --mode <mode>

Sélectionnez le mode de filtrage. Les options valides sont src et dst, qui peuvent toutes deux être spécifiées comme src,dst. Si src est spécifié, le numéro de port sera ajouté comme correspondance de port source, tandis que si dst est spécifié, le numéro de port sera ajouté comme correspondance de port destination. Si les deux sont spécifiés, un paquet sera mis en correspondance si soit son port source soit son port de destination est le port spécifié.

-p, --proto <proto>

Spécifiez un (ou les deux) de udp et/ou tcp pour faire correspondre les ports UDP ou TCP, respectivement.

-s, --status

Si cette option est spécifiée, la liste actuelle des ports correspondants sera affichée après l'insertion du numéro de port. Sinon, rien ne sera affiché.

-v, --verbose

Activer la journalisation de débogage. Spécifiez deux fois pour encore plus de verbosité.

-h, --help

Afficher un résumé des options disponibles

La commande IP

Utilisez la commande ip pour ajouter une adresse IPv6 ou IPv4 à la liste de correspondance xdp-filter.

La syntaxe pour la commande ip est :

xdp-filter ip [options] <ip>

Où <ip> est l'adresse IP à ajouter (ou à supprimer si l'option --remove est spécifiée). Des adresses IPv4 ou IPv6 peuvent être spécifiées, mais xdp-filter doit être chargé avec les fonctionnalités correspondantes (ipv4 et ipv6, respectivement). Les options supportées sont :

xdp-filter(8) — xdp-tools 1.5.7

NAME

xdp-filter — control xdp-filter XDP program

SYNOPSIS

xdp-filter load [options] iface...

xdp-filter unload [options] iface...

xdp-filter port [options] port...

xdp-filter ip [options] addr...

xdp-filter ether [options] addr...

xdp-filter status [options]

xdp-filter poll [options]

The LOAD command

Load the xdp-filter XDP program on the specified interface(s). The program can filter based on MAC addresses, IP addresses, or TCP/UDP ports. Use the -f option to select which features should be enabled.

The syntax for the load command is:

xdp-filter load [options] <iface>...

Where <iface> is the network interface to load the program on. The supported options are:

-f, --feature <features>

Select which features to enable in the XDP program. Supported features are ethernet, ipv4, ipv6, tcp, udp. Multiple features can be specified by separating them with commas. For example: -f ethernet,ipv4,tcp. The default is to enable all features.

-p, --policy <policy>

Set the default policy for the XDP program. Supported options are allow and deny. If set to allow, all packets that are not explicitly matched by a rule will be allowed. If set to deny, all packets that are not explicitly matched by a rule will be denied. The default policy is allow.

-m, --mode <mode>

Set the mode for how the XDP program handles matched packets. Supported options are drop and pass. If set to drop, matched packets will be dropped. If set to pass, matched packets will be passed to the host network stack. The default mode is drop.

-d, --driver-mode <mode>

Set the driver mode for the XDP program. Supported options are native, skb, and offload. The default is native.

-s, --status

If this option is specified, the current status of the xdp-filter program will be printed after loading it. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The UNLOAD command

Unload the xdp-filter XDP program from the specified interface(s).

The syntax for the unload command is:

xdp-filter unload [options] <iface>...

Where <iface> is the network interface to unload the program from. The supported options are:

-s, --status

If this option is specified, the current status of the xdp-filter program will be printed after unloading it. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The PORT command

Use the port command to add a TCP or UDP port to the xdp-filter match list. For this to work, xdp-filter must be loaded with either the tcp or udp feature on at least one interface.

The syntax for the port command is:

xdp-filter port [options] <port>...

Where <port> is the port number to add (or remove if the --remove is specified). The supported options are:

-r, --remove

Remove the port from the list instead of adding it.

-m, --mode <mode>

Select filtering mode. Valid options are src and dst, both of which may be specified as src,dst. If src is specified, the port number will be added as a source port match, while if dst is specified, the port number will be added as a destination port match. If both are specified, a packet will be matched if either its source or destination port is the specified port number.

-s, --status

If this option is specified, the current list of matched ports will be printed after inserting the port number. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The IP command

Use the ip command to add an IP address to the xdp-filter match list. For this to work, xdp-filter must be loaded with either the ipv4 or ipv6 feature on at least one interface.

The syntax for the ip command is:

xdp-filter ip [options] <addr>...

Where <addr> is the IP address to add (or remove if the --remove is specified). The supported options are:

-r, --remove

Remove the IP address instead of adding it.

-m, --mode <mode>

Select filtering mode. Valid options are src and dst, both of which may be specified as src,dst. If src is specified, the IP address will be added as a source IP match, while if dst is specified, the IP address will be added as a destination IP match. If both are specified, a packet will be matched if either its source or destination IP is the specified IP address.

-s, --status

If this option is specified, the current list of matched ips will be printed after inserting the IP address. Otherwise, nothing will be printed.

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The STATUS command

The status command prints the current status of xdp-filter: Which interfaces it is loaded on, the current list of rules, and some statistics for how many packets have been processed in total, and how many times each rule has been hit.

The syntax for the status command is:

xdp-filter status [options]

Where the supported options are:

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

The POLL command

The poll command periodically polls the xdp-filter statistics map and prints out the total number of packets and bytes processed by xdp-filter, as well as the number in the last polling interval, converted to packets (and bytes) per second. This can be used to inspect the performance of xdp-filter, and to compare the performance of the different feature sets selectable by the load parameter.

The syntax for the poll command is:

xdp-filter poll [options]

Where the supported options are:

-i, --interval <interval>

The polling interval, in milliseconds. Defaults to 1000 (1 second).

-v, --verbose

Enable debug logging. Specify twice for even more verbosity.

-h, --help

Display a summary of the available options

Examples

To filter all packets arriving on port 80 on eth0, issue the following commands:

# xdp-filter load eth0 -f tcp,udp
# xdp-filter port 80

To filter all packets except those from IP address fc00:dead:cafe::1 issue the following commands (careful, this can lock you out of remote access!):

# xdp-filter load eth0 -f ipv6 -p deny
# xdp-filter ip fc00:dead:cafe::1 -m src

To allow packets from either IP fc00:dead:cafe::1 or arriving on port 22, issue the following (careful, this can lock you out of remote access!):

# xdp-filter load eth0 -f ipv6,tcp -p deny
# xdp-filter port 22
# xdp-filter ip fc00:dead:cafe::1 -m src
