XXD(1) Manuel des commandes générales XXD(1)

NOM

xxd - créer une "hex dump" ou faire l'inverse.

SYNTAXE

xxd -h[elp]
xxd [options] [fichier_entree [fichier_sortie]]
xxd -r[evert] [options] [fichier_entree [fichier_sortie]]

DESCRIPTION

xxd crée une "hex dump" d'un fichier donné ou de l'entrée standard. Il peut aussi convertir une "hex dump" en sa forme binaire d'origine. Comme uuencode(1) et uudecode(1), il permet la transmission de données binaires dans une représentation ASCII "mail-safe", mais il a l'avantage de décoder vers la sortie standard. De plus, il peut être utilisé pour effectuer des modifications de fichiers binaires.

OPTIONS

Si aucun fichier_entree n'est donné, l'entrée standard est lue. Si fichier_entree est spécifié comme un caractère `-', alors l'entrée provient de l'entrée standard. Si aucun fichier_sortie n'est donné (ou si un caractère `-' le remplace), les résultats sont envoyés à la sortie standard.

Notez qu'un analyseur "paresseux" est utilisé, qui ne vérifie que la première lettre de l'option, sauf si l'option est suivie d'un paramètre. Les espaces entre une seule lettre d'option et son paramètre sont facultatifs. Les paramètres des options peuvent être spécifiés en notation décimale, hexadécimale ou octale. Ainsi -c8, -c 8, -c 010 et -cols 8 sont tous équivalents.

-a | -autoskip
Basculer l'autoskip : Un seul '*' remplace les lignes de NUL. Désactivé par défaut.
-b | -bits
Passer à une "hex dump" en bits (chiffres binaires) au lieu d'une "hex dump" normale. Cette option écrit les octets comme huit chiffres "1" ou "0" au lieu d'une "hex dump" normale. Chaque ligne est précédée d'un numéro de ligne en hexadécimal et suivie d'une représentation ASCII (ou EBCDIC). Le commutateur de ligne de commande -p ne fonctionne pas avec ce mode. Peut être combiné avec -i.
-c cols | -cols cols
Formater <cols> octets par ligne. Par défaut 16 (-i: 12, -ps: 30, -b: 6). Max 256. Pas de maximum pour -ps. Avec -ps, 0 résulte en une seule longue ligne de sortie.
-C | -capitalize
Mettre en majuscules les noms de variables dans le style des fichiers d'inclusion C, lors de l'utilisation de -i.
-d
Afficher le décalage en décimal au lieu d'hexadécimal.
-E | -EBCDIC
Changer le codage des caractères dans la colonne de droite de ASCII à EBCDIC. Cela ne change pas la représentation hexadécimale. L'option est sans signification en combinaison avec -r, -p ou -i.
-e
Passer à une "hex dump" en little-endian. Cette option traite les groupes d'octets comme des mots en ordre d'octets little-endian. Le groupement par défaut de 4 octets peut être modifié en utilisant -g. Cette option s'applique uniquement à la "hex dump", laissant la représentation ASCII (ou EBCDIC) inchangée. Les commutateurs de ligne de commande -r, -p, -i ne fonctionnent pas avec ce mode.
-g bytes | -groupsize bytes
Séparer la sortie de chaque <bytes> octets (deux caractères hexadécimaux ou huit chiffres binaires chacun) par un espace. Spécifier -g 0 pour supprimer le regroupement. <Bytes> par défaut à 2 en mode normal, 4 en mode little-endian et 1 en mode bits. Le regroupement ne s'applique pas au style PostScript ou include.
-h | -help
Afficher un résumé des commandes disponibles et quitter. Aucune "hex dump" n'est effectuée.
-i | -include
Sortie dans le style des fichiers d'inclusion C. Une définition complète de tableau statique est écrite (nommée d'après le fichier d'entrée), sauf si xxd lit depuis stdin. Peut être combiné avec -b.
-l len | -len len
Arrêter après avoir écrit <len> octets.
-n name | -name name
Remplacer le nom de variable de sortie lorsque -i est utilisé. Le tableau est nommé name et la longueur est nommée name_len.
-o offset
Ajouter <offset> à la position du fichier affichée.
-p | -ps | -postscript | -plain
Sortie dans le style "hex dump" continue PostScript. Également connu sous le nom de style "hex dump" simple.
-r | -revert
Opération inverse : convertir (ou patcher) une "hex dump" en binaire. Si vous n'écrivez pas sur stdout, xxd écrit dans son fichier de sortie sans le tronquer. Utiliser la combinaison -r -p pour lire des "hex dumps" simples sans informations de numéro de ligne et sans mise en page particulière. Les espaces supplémentaires et les sauts de ligne sont autorisés n'importe où. Utiliser la combinaison -r -b pour lire une "hex dump" en bits au lieu d'une "hex dump" normale.
-R when
Dans la sortie, la valeur hexadécimale et la valeur sont toutes deux colorées avec la même couleur en fonction de la valeur hexadécimale. Aide principalement à différencier les caractères imprimables et non imprimables. when est never, always, ou auto (par défaut : auto). Lorsque la variable d'environnement $NO_COLOR est définie, la coloration sera désactivée.
-seek offset
Lorsqu'utilisé après -r : inverser avec <offset> ajouté aux positions de fichier trouvées dans la "hex dump".
-s [+][-]seek
Commencer au décalage de fichier absolu (ou relatif) <seek> octets. + indique que le déplacement est relatif à la position actuelle du fichier stdin (sans signification si l'on ne lit pas depuis stdin). - indique que le déplacement doit être ce nombre de caractères depuis la fin de l'entrée (ou s'il est combiné avec + : avant la position actuelle du fichier stdin). Sans l'option -s, xxd commence à la position actuelle du fichier.
-u
Utiliser des lettres hexadécimales majuscules. Par défaut, ce sont des minuscules.
-v | -version
Afficher la chaîne de version.

POINTS ATTENTION

xxd -r a une magie intégrée lors de l'évaluation des informations de numéro de ligne. Si le fichier de sortie est cherchable, alors les numéros de ligne au début de chaque ligne de "hex dump" peuvent être désordonnés, des lignes peuvent manquer ou se chevaucher. Dans ces cas, xxd utilisera lseek(2) pour passer à la position suivante. Si le fichier de sortie n'est pas cherchable, seuls les écarts sont autorisés, qui seront remplis par des octets nuls.

xxd -r ne génère jamais d'erreurs d'analyse. Les données incorrectes sont silencieusement ignorées.

Lors de la modification des "hex dumps", veuillez noter que xxd -r ignore tout sur la ligne d'entrée après avoir lu suffisamment de colonnes de données hexadécimales (voir l'option -c). Cela signifie également que les modifications apportées aux colonnes ASCII (ou EBCDIC) imprimables sont toujours ignorées. L'inversion d'une "hex dump" de style simple (ou PostScript) avec xxd -r -p ne dépend pas du bon nombre de colonnes. Ici, tout ce qui ressemble à une paire de chiffres hexadécimaux est interprété.

Notez la différence entre
% xxd -i fichier
et
% xxd -i < fichier

xxd -s +seek peut être différent de xxd -s seek, car lseek(2) est utilisé pour "rembobiner" l'entrée. Un '+' fait une différence si la source d'entrée est stdin, et si la position de fichier de stdin n'est pas au début du fichier au moment où xxd est démarré et reçoit son entrée. Les exemples suivants peuvent aider à clarifier (ou à embrouiller davantage !) :

Rembobiner stdin avant la lecture ; nécessaire car `cat' a déjà lu jusqu'à la fin de stdin.
% sh -c "cat > plain_copy; xxd -s 0 > hex_copy" < file

"Hex dump" à partir de la position 0x480 (=1024+128) du fichier. Le signe `+' signifie "relatif à la position actuelle", ainsi le `128' s'ajoute au 1k où dd s'est arrêté.

Manuel page for xxd

May 2024

NOM

xxd - créer un vidage hexadécimal de fichiers ; inversement

SYNTAXE

xxd [options] [input-file [output-file]]

DESCRIPTION

La commande xxd crée un vidage hexadécimal d'un fichier d'entrée, ou inversement, récupère un vidage hexadécimal vers un fichier binaire. Elle peut également être utilisée comme un filtre dans un éditeur de texte.

Quand elle est appelée sans options, xxd lit à partir de l'entrée standard et écrit sur la sortie standard, produisant un vidage hexadécimal standard.

Quand elle est appelée avec l'option -r, xxd lit un vidage hexadécimal et écrit les données binaires correspondantes sur la sortie standard.

Si un fichier d'entrée est spécifié, xxd le lit. S'il est omis, l'entrée standard est lue.

Si un fichier de sortie est spécifié, xxd y écrit. S'il est omis, la sortie standard est utilisée.

OPTIONS

Les options suivantes sont disponibles :

-a
Interrupteur d'auto-saut. Lorsque le vidage est fait avec -s, les lignes identiques qui sont consécutives sont affichées comme une seule ligne précédée de *. Non utilisable avec -r.
-c cols
Définit le nombre d'octets par ligne dans le vidage hexadécimal. La valeur par défaut est 16.
-h
Identique à -H.
-H
Sortie hexadécimale des octets sans espaces et sans en-tête d'adresse. Utilisable avec -r.
-i
Produit une sortie au format C hexadécimal. Cela peut être utilisé pour générer un tableau d'octets C. Non utilisable avec -r.
-l len
Arrête la lecture après len octets.
-p
Vidage hexadécimal "pur". Ne pas imprimer le décalage, les espaces et les caractères. Utilisable avec -r.
-r [...] [input [output]]
Inverse l'opération. Lit un vidage hexadécimal et écrit les données binaires. Peut aussi prendre des options pour modifier l'opération d'inversement. Par exemple, -p peut être utilisé pour lire des vidages hexadécimaux sans espaces. Sans cette option, l'entrée doit correspondre à la sortie standard de xxd. Avec -p, elle lit les vidages hexadécimaux 'purs'. Avec -r -s, il est possible de patcher un fichier. L'option -i est utilisée pour patcher des tableaux d'octets C. Voir l'exemple ci-dessous.
-s [[+/-]] offset
Commence la lecture du vidage hexadécimal à l'offset spécifié. L'offset peut être donné en décimal, en hexadécimal (avec le préfixe 0x) ou en octal (avec le préfixe 0). Si + est utilisé, l'offset est ajouté au décalage courant, et si - est utilisé, il est soustrait.
-u
Affiche les caractères ASCII en majuscules (par défaut, ils sont en minuscules).

CAVEATS

Il est possible de créer un vidage qui ne peut pas être lu par xxd -r. Par exemple, si vous produisez un vidage avec xxd -ps -c 1, vous obtiendrez une séquence de nibbles hexadécimaux. Tenter de lire ce vidage avec xxd -r échouera car xxd -r s'attend à des octets complets, ou à une séquence d'octets parsable.

Le comportement de -s + et -s - est quelque peu déroutant. Voici une explication. Le décalage par défaut pour xxd est 0. L'option -s permet de modifier ce décalage. Si vous utilisez -s 0x100, le vidage commencera à l'octet 256. Si vous utilisez -s -0x80, le vidage commencera à l'octet -128 (ce qui est illégal). Cela dit, il est possible de l'utiliser pour déterminer une position de fin. Par exemple, avec dd of=plain_snippet bs=1k count=1; xxd -s +128 > hex_snippet < file, cela lit à partir de la position 128, mais la commande dd s'assure que seuls 1024 octets sont utilisés.

La commande suivante est plus complexe :

% sh -c "dd of=plain_snippet bs=1k count=1; xxd -s +-768 > hex_snippet" < file

Cependant, c'est une situation rare et l'utilisation de + est rarement nécessaire. L'auteur préfère surveiller l'effet de xxd avec strace(1) ou truss(1), lorsque -s est utilisé.

EXEMPLES

Affiche tout sauf les trois premières lignes (0x30 octets hexadécimaux) de file.
% xxd -s 0x30 file

Affiche 3 lignes (0x30 octets hexadécimaux) à partir de la fin de file.
% xxd -s -0x30 file

Copie input_file vers output_file et préfixe avec 100 octets de valeur 0x00.
% xxd input_file | xxd -r -s 100 > output_file

Crée un fichier de 65537 octets avec tous les octets à 0x00, sauf le dernier qui est 'A' (0x41 hexadécimal).
% echo "010000: 41" | xxd -r > file

Vidage hexadécimal de ce fichier avec auto-saut.
% xxd -a -c 12 file

Crée un fichier de 1 octet contenant un seul caractère 'A'. Le nombre après '-r -s' s'ajoute aux numéros de ligne trouvés dans le fichier ; en effet, les octets de tête sont supprimés.
% echo "010000: 41" | xxd -r -s -0x10000 > file

Utilise xxd comme filtre dans un éditeur tel que vim(1) pour vider en hexadécimal une région marquée entre `a' et `z'.
:'a,'z!xxd

Utilise xxd comme filtre dans un éditeur tel que vim(1) pour récupérer un vidage hexadécimal binaire marqué entre `a' et `z'.
:'a,'z!xxd -r

Utilise xxd comme filtre dans un éditeur tel que vim(1) pour récupérer une ligne d'un vidage hexadécimal. Déplacez le curseur sur la ligne et tapez :
!!xxd -r

Lit des caractères individuels à partir d'une ligne série
% xxd -c1 < /dev/term/b &
% stty < /dev/term/b -echo -opost -isig -icanon min 1
% echo -n foo > /dev/term/b

VALEURS RETOURNÉES

Les valeurs d'erreur suivantes sont retournées :

0
aucune erreur rencontrée.
-1
opération non supportée (xxd -r -i toujours impossible).
1
erreur lors de l'analyse des options.
2
problèmes avec le fichier d'entrée.
3
problèmes avec le fichier de sortie.
4,5
la position de recherche souhaitée est inaccessible.
