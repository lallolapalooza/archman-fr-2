XH(1) Commandes utilisateur XH(1)

NOM

xh - Outil convivial et rapide pour envoyer des requêtes HTTP

SYNTAXE

xh [OPTIONS] [METHODE] URL [--] [ELEMENT_REQUETE ...]

DESCRIPTION

xh est un client HTTP avec une interface en ligne de commande conviviale. Il s'efforce d'avoir une sortie lisible et des options faciles à utiliser.

xh est largement compatible avec HTTPie : voir http(1).

L'option --curl peut être utilisée pour imprimer une traduction curl(1) de la commande au lieu d'envoyer une requête.

ARGUMENTS POSITIONNELS

[METHODE]
La méthode HTTP à utiliser pour la requête.

Par défaut, c'est GET, ou POST si la requête contient un corps.

URL
L'URL à requêter.

Le schéma d'URL par défaut est "http://", ou "https://" si le programme est appelé "xhs".

Un deux-points en préfixe fonctionne comme raccourci pour localhost. ":8000" équivaut à "localhost:8000", et ":/chemin" équivaut à "localhost/chemin".

[ELEMENT_REQUETE ...]
Paires clé-valeur optionnelles à inclure dans la requête.

Le séparateur est utilisé pour déterminer le type :

clé==valeur
Ajoute une chaîne de requête à l'URL.
clé=valeur
Ajoute une propriété JSON (--json) ou un champ de formulaire (--form) au corps de la requête.
clé:=valeur
Ajoute un champ avec une valeur JSON littérale au corps de la requête.

Exemple : "nombres:=[1,2,3] activé:=vrai"

clé@fichier
Télécharge un fichier (nécessite --form ou --multipart).

Pour définir le nom du fichier et le type MIME, ";type=" et ";filename=" peuvent être utilisés respectivement.

Exemple : "pfp@ra.jpg;type=image/jpeg;filename=profil.jpg"

@fichier
Utilise un fichier comme corps de requête.
en-tête:valeur
Ajoute un en-tête, par ex. "user-agent:foobar"
en-tête:
Supprime un en-tête, par ex. "connection:"
en-tête;
Ajoute un en-tête avec une valeur vide.
Un préfixe "@" peut être utilisé pour lire une valeur depuis un fichier. Par exemple : "x-api-key:@api-key.txt".

Un anti-slash peut être utilisé pour échapper les caractères spéciaux, par ex. "clef\:bizarre=valeur".

Pour construire un objet JSON complexe, la clé de l'ELEMENT_REQUETE peut être définie sur un chemin JSON au lieu d'un nom de champ. Pour plus d'informations sur cette syntaxe, consultez https://httpie.io/docs/cli/nested-json.

OPTIONS

Chaque --OPTION peut être réinitialisée avec un argument --no-OPTION.

-j, --json
(par défaut) Sérialise les éléments de données de la ligne de commande sous forme d'objet JSON.

Remplace à la fois --form et --multipart.

-f, --form
Sérialise les éléments de données de la ligne de commande sous forme de champs de formulaire.

Remplace à la fois --json et --multipart.

--multipart
Similaire à --form, mais force une requête multipart/form-data même sans fichiers.

Remplace à la fois --json et --form.

--raw=BRUT
Passe les données de requête brutes sans traitement supplémentaire.
--pretty=STYLE
Contrôle le traitement de la sortie. Les valeurs possibles sont :


all (par défaut) Active la coloration et la mise en forme
colors Applique la coloration syntaxique à la sortie
format Met en forme proprement le json et trie les en-têtes
none Désactive la coloration et la mise en forme

Par défaut "format" si l'environnement NO_COLOR est défini et "none" si la sortie standard n'est pas un tty.

--format-options=OPTIONS_FORMAT
Définit les options de mise en forme de la sortie. Les options prises en charge sont :


json.indent:<NOMBRE>
json.format:<vrai|faux>
headers.sort:<vrai|faux>

Exemple : --format-options=json.indent:2,headers.sort:false.

-s, --style=THÈME
Style de coloration de la sortie.

[valeurs possibles : auto, solarized, monokai, fruity]

--response-charset=ENCODAGE
Remplace l'encodage de la réponse pour l'affichage dans le terminal.

Exemple : --response-charset=latin1.

--response-mime=TYPE_MIME
Remplace le type MIME de la réponse pour la coloration et la mise en forme dans le terminal.

Exemple : --response-mime=application/json.

-p, --print=FORMAT
Chaîne spécifiant ce que la sortie doit contenir


'H' en-têtes de requête
'B' corps de requête
'h' en-têtes de réponse
'b' corps de réponse
'm' métadonnées de réponse

Exemple : --print=Hb.

-h, --headers
N'imprime que les en-têtes de réponse. Raccourci pour --print=h.
-b, --body
N'imprime que le corps de réponse. Raccourci pour --print=b.
-m, --meta
N'imprime que les métadonnées de réponse. Raccourci pour --print=m.
-v, --verbose
Imprime la requête entière ainsi que la réponse.

De plus, cela active --all pour imprimer les requêtes/réponses intermédiaires lors du suivi des redirections.

Utiliser verbose deux fois, c'est-à-dire -vv, imprimera également les métadonnées de réponse.

Équivaut à --print=HhBb --all.

--debug
Imprime les traces complètes des erreurs et les messages de journalisation de débogage.

La journalisation peut être configurée plus en détail en utilisant la variable d'environnement `$RUST_LOG`. Définissez `RUST_LOG=trace` pour afficher encore plus de messages. Voir https://docs.rs/env_logger/0.11.3/env_logger/#enabling-logging.

--all
Affiche toutes les requêtes/réponses intermédiaires lors du suivi des redirections avec --follow.
-P, --history-print=FORMAT
Identique à --print mais s'applique uniquement aux requêtes/réponses intermédiaires.
-q, --quiet
Ne pas imprimer sur la sortie standard ou l'erreur standard.

Utiliser quiet deux fois, c'est-à-dire -qq, supprimera également les avertissements.

-S, --stream
Toujours diffuser le corps de la réponse.
-x, --compress
Contenu compressé (encodé) avec l'algorithme Deflate.

L'en-tête Content-Encoding est défini sur deflate.

La compression est ignorée s'il semble que le rapport de compression est négatif. La compression peut être forcée en répétant cette option.

Remarque : La compression ne peut pas être utilisée si l'en-tête de requête Content-Encoding est présent.

-o, --output=FICHIER
Enregistre la sortie dans FICHIER au lieu de la sortie standard.
-d, --download
Télécharge le corps dans un fichier au lieu de l'imprimer.

Le Accept-Encodin

Manuel des pages Arch Linux | Propriété de Arch Linux

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

g header est défini pour identifier et toute redirection sera suivie.

-c, --continue
Reprendre un téléchargement interrompu. Nécessite --download et --output.
--session=FICHIER
Créer ou réutiliser et mettre à jour une session.

Au sein d'une session, les en-têtes personnalisés, les identifiants d'authentification, ainsi que tous les cookies envoyés par le serveur persistent entre les requêtes.

--session-read-only=FICHIER
Créer ou lire une session sans la mettre à jour à partir de l'échange requête/réponse.
-A, --auth-type=TYPE_AUTH
Spécifier le mécanisme d'authentification.

[valeurs possibles: basic, bearer, digest]

-a, --auth=USER[:PASS] | TOKEN
S'authentifier en tant qu'USER avec PASS (-A basic|digest) ou avec TOKEN (-A bearer).

PASS sera demandé si manquant. Utilisez une apostrophe à la fin (par exemple, "USER:") pour vous authentifier avec un nom d'utilisateur uniquement.

TOKEN est attendu si --auth-type=bearer.

--ignore-netrc
Ne pas utiliser les identifiants de .netrc.
--offline
Construire des requêtes HTTP sans les envoyer.
--check-status
(par défaut) Quitter avec un code d'état d'erreur si le serveur répond avec une erreur.

Le code de sortie sera 4 pour les 4xx (Erreur Client), 5 pour les 5xx (Erreur Serveur), ou 3 pour les 3xx (Redirection) si --follow n'est pas défini.

Si stdout est redirigé, un avertissement est écrit sur stderr.

-F, --follow
Suivre les redirections.
--max-redirects=NUM
Nombre de redirections à suivre. Uniquement respecté si --follow est utilisé.
--timeout=SEC
Délai d'attente de la connexion de la requête.

La valeur par défaut est "0", c'est-à-dire qu'il n'y a pas de limite de délai.

--proxy=PROTOCOLE:URL
Utiliser un proxy pour un protocole. Par exemple : --proxy https:http://proxy.host:8080.

PROTOCOLE peut être "http", "https" ou "all".

Si votre proxy nécessite des identifiants, placez-les dans l'URL, comme ceci : --proxy http:socks5://user:password@proxy.host:8000.

Vous pouvez spécifier des proxys pour plusieurs protocoles en répétant cette option.

Les variables d'environnement "http_proxy" et "https_proxy" peuvent également être utilisées, mais elles sont complètement ignorées si --proxy est passé.

--verify=VERIFICATION
Si "no", ignorer la vérification SSL. Si c'est un chemin de fichier, l'utiliser comme un paquet CA.

Spécifier un paquet CA désactivera les certificats racines intégrés du système.

"false" au lieu de "no" fonctionne également. La valeur par défaut est "yes" ("true").

--cert=FICHIER
Utiliser un certificat client pour SSL.
--cert-key=FICHIER
Un fichier de clé privée à utiliser avec --cert.

Uniquement nécessaire si la clé privée n'est pas contenue dans le fichier cert.

--ssl=VERSION
Forcer une version TLS particulière.

"auto" donne le comportement par défaut de négocier une version avec le serveur.

[valeurs possibles: auto, tls1, tls1.1, tls1.2, tls1.3]

--native-tls
Utiliser la bibliothèque TLS système au lieu de rustls (si activée à la compilation).
--https
Effectuer des requêtes HTTPS si elles ne sont pas spécifiées dans l'URL.
--http-version=VERSION
Version HTTP à utiliser.

[valeurs possibles: 1.0, 1.1, 2, 2-prior-knowledge, 3-prior-knowledge]

--resolve=HOST:ADRESSE
Remplacer la résolution DNS pour un domaine spécifique par une adresse IP personnalisée.

Vous pouvez remplacer plusieurs domaines en répétant cette option.

Exemple : --resolve=example.com:127.0.0.1.

--interface=NOM
Se lier à une interface réseau ou à une adresse IP locale.

Exemple : --interface=eth0 --interface=192.168.0.2.

-4, --ipv4
Résoudre le nom d'hôte en adresses ipv4 uniquement.
-6, --ipv6
Résoudre le nom d'hôte en adresses ipv6 uniquement.
--unix-socket=FICHIER
Se connecter en utilisant un socket de domaine Unix.

Exemple : xh :/index.html --unix-socket=/var/run/temp.sock.

-I, --ignore-stdin
Ne pas tenter de lire depuis stdin.

Ceci désactive le comportement par défaut de lecture du corps de la requête depuis stdin lorsqu'une entrée redirigée est détectée.

Il est recommandé de passer ce drapeau lors de l'utilisation de xh à des fins de scripting. Pour plus d'informations, consultez https://httpie.io/docs/cli/best-practices.

--curl
Afficher une traduction en commande curl.

Pour traduire dans l'autre sens, essayez https://curl2httpie.online/.

--curl-long
Utiliser les versions longues des drapeaux de curl.
--generate=TYPE
Générer des complétions de shell ou des man pages. Les valeurs possibles sont :


complete-bash
complete-elvish
complete-fish
complete-nushell
complete-powershell
complete-zsh
man

Exemple : xh --generate=complete-bash > xh.bash.

--help
Afficher l'aide.
-V, --version
Afficher la version.

STATUT DE SORTIE

0
Exécution réussie du programme.
1
Erreur d'utilisation, de syntaxe ou de réseau.
2
Délai d'attente de la requête.
3
Redirection HTTP 3xx inattendue.
4
Erreur Client HTTP 4xx.
5
Erreur Serveur HTTP 5xx.
6
Trop de redirections.

ENVIRONNEMENT

XH_CONFIG_DIR
Spécifie où chercher les données de configuration config.json et de session nommée. Par défaut, c'est ~/.config/xh sous Linux/macOS et %APPDATA%\xh sous Windows.
XH_HTTPIE_COMPAT_MODE
Active le Mode Compatibilité HTTPie. La seule différence actuelle est que --check-status n'est pas activé par défaut. Une alternative à la définition de cette variable d'environnement est de renommer le binaire en http ou https.
REQUESTS_CA_BUNDLE, CURL_CA_BUNDLE
Définit un chemin de paquet CA personnalisé.
http_proxy=[protocole://]<hôte>[:port]
Définit le serveur proxy à utiliser pour HTTP.
HTTPS_PROXY=[protocole://]<hôte>[:port]
Définit le serveur proxy à utiliser pour HTTPS.
NO_PROXY
Liste d'hôtes séparés par des virgules pour lesquels ignorer les autres variables d'environnement de proxy. "*" correspond à tous les noms d'hôtes.
NETRC
Emplacement du fichier .netrc.
NO_COLOR
Désactive la coloration de la sortie. Voir https://no-color.org
RUST_LOG
Configure les messages de débogage de bas niveau. Voir https://docs.rs/env_logger/0.11.3/env_logger/#enabling-logging

FICHIERS

~/.config/xh/config.json
Fichier de configuration de xh. La seule option configurable est "default_options", qui est une liste d'arguments shell par défaut qui sont passés à xh. Exemple :
{ "default_options": ["--native-tls", "--style=solarized"] }
~/.netrc, ~/_netrc
Fichier d'informations de connexion automatique.
~/.config/xh/sessions
Répertoire de données de session regroupées par domaine et numéro de port.

EXEMPLES

xh httpbin.org/json
Envoyer une requête GET.
xh httpbin.org/post name=ahmed age:=24
Envoyer une requête POST avec le corps {"name": "ahmed", "age": 24}.
xh get httpbin.org/json id==5 sort==true
Envoyer une requête GET vers http://httpbin.org/json?id=5&sort=true.
xh get httpbin.org/json x-api-key:12345
Envoyer une requête GET et inclure un en-tête nommé X-Api-Key avec la valeur 12345.
echo "[1, 2, 3]" | xh post httpbin.org/post
Envoyer une requête POST avec le corps lu depuis stdin.
xh put httpbin.org/put id:=49 age:=25 | less
Envoyer une requête PUT et rediriger le résultat vers less.
xh -d httpbin.org/json -o res.json
Télécharger et enregistrer dans res.json.
xh httpbin.org/get user-agent:foobar
Effectuer une requête avec un agent utilisateur personnalisé.
xhs example.com
Effectuer une requête HTTPS vers https://example.com.
