XHOST(1) Manuel des commandes générales XHOST(1)

NOM

xhost - programme de contrôle d'accès au serveur pour X

SYNTAXE

xhost [[+-]nom ...]

DESCRIPTION

Le programme xhost est utilisé pour ajouter et supprimer des noms d'hôtes ou des noms d'utilisateurs de la liste des autorisés à établir des connexions avec le serveur X. Dans le cas des hôtes, cela fournit une forme rudimentaire de contrôle de confidentialité et de sécurité. Elle n'est suffisante que pour un environnement de poste de travail (utilisateur unique), bien qu'elle limite les pires abus. Les environnements qui nécessitent des mesures plus sophistiquées devraient implémenter le mécanisme basé sur les utilisateurs ou utiliser les crochets du protocole pour passer d'autres données d'authentification au serveur.

OPTIONS

Xhost accepte les options de ligne de commande suivantes décrites ci-dessous. Pour des raisons de sécurité, les options qui affectent le contrôle d'accès ne peuvent être exécutées que depuis l'"hôte de contrôle". Pour les postes de travail, c'est la même machine que le serveur. Pour les terminaux X, c'est l'hôte de connexion.

-help
Affiche un message d'utilisation.
[+]nom
Le nom donné (le signe plus est facultatif) est ajouté à la liste des autorisés à se connecter au serveur X. Le nom peut être un nom d'hôte ou un nom complet (Voir NOMS pour plus de détails).
-nom
Le nom donné est supprimé de la liste des autorisés à se connecter au serveur. Le nom peut être un nom d'hôte ou un nom complet (Voir NOMS pour plus de détails). Les connexions existantes ne sont pas rompues, mais les nouvelles tentatives de connexion seront refusées. Notez que la machine actuelle peut être supprimée ; cependant, les connexions ultérieures (y compris les tentatives de la réajouter) ne seront pas autorisées. La réinitialisation du serveur (brisant ainsi toutes les connexions) est le seul moyen de permettre à nouveau les connexions locales.
+
L'accès est accordé à tout le monde, même s'ils ne sont pas sur la liste (c'est-à-dire que le contrôle d'accès est désactivé).
-
L'accès est restreint uniquement à ceux qui sont sur la liste (c'est-à-dire que le contrôle d'accès est activé).
rien
Si aucun argument de ligne de commande n'est donné, un message indiquant si le contrôle d'accès est actuellement activé ou non est affiché, suivi de la liste des autorisés à se connecter. C'est la seule option qui peut être utilisée depuis des machines autres que l'hôte de contrôle.

NOMS

Un nom complet a la syntaxe ``famille:nom'' où les familles sont les suivantes :

inet	Hôte Internet (IPv4)
inet6	Hôte Internet (IPv6)
dnet	Hôte DECnet
nis	Nom de réseau RPC sécurisé
krb	Principal Kerberos V5
local	ne contient qu'un seul nom, la chaîne vide
si	Interprété par le serveur

La famille est insensible à la casse. Le format du nom varie selon la famille.

Lorsque RPC sécurisé est utilisé, le nom de réseau indépendant (par exemple, "nis:unix.uid@nom_domaine") peut être spécifié, ou un utilisateur local peut être spécifié avec juste le nom d'utilisateur et un signe arobase final (par exemple, "nis:pat@").

Pour la compatibilité ascendante avec xhost pré-R6, les noms qui contiennent un signe arobase (@) sont supposés être dans la famille nis. Sinon, ils sont supposés être des adresses Internet. S'il est compilé pour prendre en charge IPv6, alors toutes les adresses IPv4 et IPv6 retournées par getaddrinfo(3) sont ajoutées à la liste d'accès dans la famille inet ou inet6 appropriée.

La famille locale spécifie toutes les connexions locales à la fois. Cependant, l'adresse interprétée par le serveur "si:localuser:nom_utilisateur" peut être utilisée pour spécifier un utilisateur local unique. (Voir la page de manuel Xsecurity(7) pour plus de détails.)

Les adresses interprétées par le serveur consistent en une étiquette de type sensible à la casse et une chaîne représentant une valeur donnée, séparées par un deux-points. Par exemple, "si:hostname:almas" est une adresse interprétée par le serveur de type hostname, avec une valeur de almas. Pour plus d'informations sur les formes disponibles d'adresses interprétées par le serveur, voir la page de manuel Xsecurity(7).

La liste initiale de contrôle d'accès pour le numéro d'affichage n peut être définie par le fichier /etc/Xn.hosts, où n est le numéro d'affichage du serveur. Voir Xserver(1) pour plus de détails.

DIAGNOSTICS

Pour chaque nom ajouté à la liste de contrôle d'accès, une ligne de la forme "nom ajouté à la liste de contrôle d'accès" est affichée. Pour chaque nom supprimé de la liste de contrôle d'accès, une ligne de la forme "nom supprimé de la liste de contrôle d'accès" est affichée.

VOIR AUSSI

X(7), Xsecurity(7), Xserver(1), xdm(1), xauth(1), getaddrinfo(3)

ENVIRONNEMENT

DISPLAY
pour obtenir l'hôte et l'affichage par défaut à utiliser.

BOGUES

Vous ne pouvez pas spécifier un affichage sur la ligne de commande car -display est un argument de ligne de commande valide (indiquant que vous voulez supprimer la machine nommée ``display'' de la liste d'accès).

Le serveur X stocke les adresses réseau, pas les noms d'hôtes, sauf si vous utilisez l'adresse de type nom d'hôte interprétée par le serveur. Si, pour une raison quelconque, vous modifiez l'adresse réseau d'un hôte pendant que le serveur est toujours en cours d'exécution, et que vous utilisez une forme d'authentification basée sur l'adresse réseau, xhost doit être utilisé pour ajouter la nouvelle adresse et/ou supprimer l'ancienne adresse.
