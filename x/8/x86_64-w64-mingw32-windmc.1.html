NOM

windmc - génère des ressources de messages Windows

SYNTAXE

windmc [options] fichier-entrée

DESCRIPTION

windmc lit les définitions de messages à partir d'un fichier d'entrée (.mc) et les traduit en un ensemble de fichiers de sortie. Les fichiers de sortie peuvent être de quatre types :

"h"
Un fichier d'en-tête C contenant les définitions de messages.
"rc"
Un fichier de ressources compilable par l'outil windres.
"bin"
Un ou plusieurs fichiers binaires contenant les données de ressources pour une langue de message spécifique.
"dbg"
Un fichier d'inclusion C qui mappe les identifiants de messages à leur nom symbolique.

La description exacte de ces différents formats est disponible dans la documentation de Microsoft.

Lorsque windmc convertit du format "mc" au format "bin", "rc", "h", et optionnellement "dbg", il agit comme le compilateur de messages Windows.

OPTIONS

-a
--ascii_in
Spécifie que le fichier d'entrée spécifié est en ASCII. C'est le comportement par défaut.
-A
--ascii_out
Spécifie que les messages dans les fichiers "bin" de sortie doivent être au format ASCII.
-b
--binprefix
Spécifie que les noms de fichiers "bin" doivent être préfixés par le nom de base du fichier source.
-c
--customflag
Définit le bit client dans tous les identifiants de messages.
-C codepage
--codepage_in codepage
Définit la page de code par défaut à utiliser pour convertir le fichier d'entrée en UTF16. La valeur par défaut est la page de code 1252.
-d
--decimal_values
Affiche les constantes dans le fichier d'en-tête en décimal. La valeur par défaut est l'affichage hexadécimal.
-e ext
--extension ext
L'extension pour le fichier d'en-tête. L'extension par défaut est .h.
-F cible
--target cible
Spécifie le format BFD à utiliser pour un fichier bin en sortie. Il s'agit d'un nom de cible BFD ; vous pouvez utiliser l'option --help pour voir la liste des cibles prises en charge. Normalement, windmc utilisera le format par défaut, qui est le premier listé par l'option --help.
-h chemin
--headerdir chemin
Le répertoire cible du fichier d'en-tête généré. Le répertoire par défaut est le répertoire courant.
-H
--help
Affiche une liste des options de ligne de commande puis quitte.
-m caractères
--maxlength caractères
Demande à windmc de générer un avertissement si la longueur d'un message dépasse le nombre spécifié.
-n
--nullterminate
Termine le texte du message dans les fichiers "bin" par un zéro. Par défaut, ils sont terminés par CR/LF.
-o
--hresult_use
Pas encore implémenté. Demande à "windmc" de générer un fichier d'en-tête OLE2, en utilisant les définitions HRESULT. Les codes d'état sont utilisés si l'indicateur n'est pas spécifié.
-O codepage
--codepage_out codepage
Définit la page de code par défaut à utiliser pour sortir les fichiers texte. La valeur par défaut est la page de code 1252.
-r chemin
--rcdir chemin
Le répertoire cible pour le script "rc" généré et les fichiers "bin" générés que le script du compilateur de ressources inclut. Le répertoire par défaut est le répertoire courant.
-u
--unicode_in
Spécifie que le fichier d'entrée est en UTF16.
-U
--unicode_out
Spécifie que les messages dans le fichier "bin" de sortie doivent être au format UTF16. C'est le comportement par défaut.
-v
--verbose
Active le mode verbeux.
-V
--version
Affiche le numéro de version de windmc.
-x chemin
--xdgb chemin
Le chemin du fichier d'inclusion C "dbg" qui mappe les identifiants de messages au nom symbolique. Aucun fichier de ce type n'est généré sans spécifier cet indicateur.
@fichier
Lit les options de ligne de commande à partir de fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en faisant précéder le caractère à inclure par un antislash. Le fichier peut lui-même contenir d'autres options @fichier ; de telles options seront traitées récursivement.
