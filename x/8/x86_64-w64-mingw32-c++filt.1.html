C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - décode les symboles C++ et Java

SYNTAXE

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java permettent la surcharge de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions avec le même nom, à condition que chaque fonction accepte des paramètres de types différents. Afin de pouvoir distinguer ces fonctions aux noms similaires, C++ et Java les encodent en un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de mangling (encodage). Le programme c++filt fait l'opération inverse : il décode (démangle) les noms de bas niveau en noms de niveau utilisateur afin qu'ils soient lisibles.

Chaque mot alphanumérique (composé de lettres, chiffres, soulignements, dollars ou points) vu dans l'entrée est un nom potentiellement encodé. Si le nom est décodé en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot d'origine est affiché. De cette manière, vous pouvez passer un fichier source assembleur entier, contenant des noms encodés, à travers c++filt et voir le même fichier source contenant des noms décodés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles depuis l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de ligne de commande sont censés être uniquement des noms encodés et aucun contrôle n'est effectué pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et décodera le nom en « f() », tandis que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom encodé qui le rend invalide). Cependant, cette commande fonctionnera :

echo _Z1fv, | c++filt -n

et affichera « f(), », c'est-à-dire le nom décodé suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils fassent partie d'un fichier source assembleur où il pourrait y avoir des caractères supplémentaires, parasites, après un nom encodé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ ajoutent un soulignement au début de chaque nom. Par exemple, le nom C « foo » obtient le nom de bas niveau « _foo ». Cette option supprime le soulignement initial. Le fait que c++filt supprime le soulignement par défaut dépend de la cible.
-n
--no-strip-underscore
Ne pas supprimer le soulignement initial.
-p
--no-params
Lors du décodage du nom d'une fonction, n'afficher pas les types des paramètres de la fonction.
-t
--types
Essayer de décoder les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types encodés ne sont normalement utilisés qu'en interne par le compilateur, et ils peuvent être confondus avec des noms non encodés. Par exemple, une fonction appelée « a » traitée comme un nom de type encodé serait décodée en « signed char ».
-i
--no-verbose
Ne pas inclure les détails d'implémentation (le cas échéant) dans la sortie décodée.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du décodage des chaînes. Étant donné que les formats d'encodage de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

La limite est activée par défaut, mais la désactiver peut être nécessaire pour décoder des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes d'encodage, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (méthode par défaut)
"gnu"
celle utilisée par le compilateur C++ GNU (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le C++ Annotated Reference Manual
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur Java GNU (gcj)
"gnat"
celle utilisée par le compilateur Ada GNU (GNAT).
--help
Affiche un résumé des options de c++filt et quitte.
--version
Affiche le numéro de version de c++filt et quitte.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces blancs. Un caractère d'espacement peut être inclus dans une option en entourant toute l'option de guillemets simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; ces options seront traitées récursivement.

NAME

c++filt - décode les noms C++ mangled

SYNOPSIS

c++filt [nom... ]

DESCRIPTION

c++filt décode les noms C++ mangled dans leur forme lisible. Si aucun nom n'est spécifié, c++filt lit depuis l'entrée standard.

Un nom mangled est une représentation d'un nom d'identifiant C++ qui peut contenir des caractères non alphabétiques. Ces noms sont générés par les compilateurs pour permettre la surcharge de fonctions et l'instanciation de templates.

OPTIONS

Aucune option n'est disponible pour c++filt.
