STRIP(1) Outils de développement GNU STRIP(1)

NOM

strip - supprimer les symboles et autres données des fichiers objets

SYNTAXE

strip [-F nom_bfd |--target=nom_bfd]
[-I nom_bfd |--input-target=nom_bfd]
[-O nom_bfd |--output-target=nom_bfd]
[-s|--strip-all]
[-S|-g|-d|--strip-debug]
[--strip-dwo]
[-K nom_symbole|--keep-symbol=nom_symbole]
[-M|--merge-notes][--no-merge-notes]
[-N nom_symbole |--strip-symbol=nom_symbole]
[-w|--wildcard]
[-x|--discard-all] [-X |--discard-locals]
[-R nom_section |--remove-section=nom_section]
[--keep-section=motif_section]
[--remove-relocations=motif_section]
[--strip-section-headers]
[-o fichier] [-p|--preserve-dates]
[-D|--enable-deterministic-archives]
[-U|--disable-deterministic-archives]
[--keep-section-symbols]
[--keep-file-symbols]
[--only-keep-debug]
[--plugin nom]
[-v |--verbose] [-V|--version]
[--help] [--info]
fichier_objet...

DESCRIPTION

GNU strip supprime tous les symboles des fichiers objets fichier_objet. La liste des fichiers objets peut inclure des archives. Au moins un fichier objet doit être fourni.

strip modifie les fichiers nommés dans ses arguments, plutôt que d'écrire des copies modifiées sous des noms différents.

OPTIONS

-F nom_bfd
--target=nom_bfd
Traiter le fichier_objet original comme un fichier avec le format de code objet nom_bfd, et le réécrire dans le même format.
--help
Afficher un résumé des options de strip et quitter.
--info
Afficher une liste montrant tous les architectures et formats d'objets disponibles.
-I nom_bfd
--input-target=nom_bfd
Traiter le fichier_objet original comme un fichier avec le format de code objet nom_bfd.
-O nom_bfd
--output-target=nom_bfd
Remplacer fichier_objet par un fichier dans le format de sortie nom_bfd.
-R nom_section
--remove-section=nom_section
Supprimer toute section nommée nom_section du fichier de sortie, en plus des sections qui seraient autrement supprimées. Cette option peut être donnée plusieurs fois. Notez qu'utiliser cette option de manière inappropriée peut rendre le fichier de sortie inutilisable. Le caractère générique * peut être donné à la fin de nom_section. Si c'est le cas, toute section commençant par nom_section sera supprimée.

Si le premier caractère de motif_section est le point d'exclamation (!), alors les sections correspondantes ne seront pas supprimées même si une utilisation antérieure de --remove-section sur la même ligne de commande les supprimerait autrement. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=motif_section
Lors de la suppression de sections du fichier de sortie, conservez les sections qui correspondent à motif_section.
--remove-relocations=motif_section
Supprimer les relocations du fichier de sortie pour toute section correspondant à motif_section. Cette option peut être donnée plusieurs fois. Notez qu'utiliser cette option de manière inappropriée peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans motif_section. Par exemple : 
--remove-relocations=.text.*

supprimera les relocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de motif_section est le point d'exclamation (!), alors les sections correspondantes n'auront pas leurs relocations supprimées même si une utilisation antérieure de --remove-relocations sur la même ligne de commande entraînerait autrement la suppression des relocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les relocations pour les sections correspondant au motif '.text.*', mais ne supprimera pas les relocations pour la section '.text.foo'.

--strip-section-headers
Supprimer les en-têtes de section. Cette option est spécifique aux fichiers ELF. Implique --strip-all et --merge-notes.
-s
--strip-all
Supprimer tous les symboles.
-g
-S
-d
--strip-debug
Supprimer uniquement les symboles de débogage.
--strip-dwo
Supprimer le contenu de toutes les sections DWARF .dwo, en laissant les sections de débogage restantes et tous les symboles intacts. Voir la description de cette option dans la section objcopy pour plus d'informations.
--strip-unneeded
Supprimer tous les symboles qui ne sont pas nécessaires au traitement des relocations en plus des symboles et sections de débogage supprimés par --strip-debug.
-K nom_symbole
--keep-symbol=nom_symbole
Lors de la suppression de symboles, conserver le symbole nom_symbole même s'il serait normalement supprimé. Cette option peut être donnée plusieurs fois.
-M
--merge-notes
--no-merge-notes
Pour les fichiers ELF, essayer (ou ne pas essayer) de réduire la taille des sections de type SHT_NOTE en supprimant les notes dupliquées. Par défaut, cette réduction est tentée, sauf si des informations de débogage ou DWO sont supprimées.
-N nom_symbole
--strip-symbol=nom_symbole
Supprimer le symbole nom_symbole du fichier source. Cette option peut être donnée plusieurs fois, et peut être combinée avec d'autres options de strip à l'exception de -K.
-o fichier
Placer la sortie dépouillée dans fichier, plutôt que de remplacer le fichier existant. Lorsque cet argument est utilisé, un seul argument fichier_objet peut être spécifié.
-p
--preserve-dates
Conserver les dates d'accès et de modification du fichier.
-D
--enable-deterministic-archives
Fonctionner en mode déterministe. Lors de la copie des membres d'archive et de l'écriture de l'index d'archive, utiliser zéro pour les UID, GID, horodatages, et utiliser des modes de fichier cohérents pour tous les fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec l'option -U, ci-dessous.

-U
--disable-deterministic-archives
Ne pas fonctionner en mode déterministe. Lorsque vous copiez des membres d'archive et que vous écrivez l'index d'archive, utilisez les UID, GID et horodatages réels des fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, ce mode est activé par défaut. Cette option le désactive.

--keep-section-symbols
Conserver les symboles liés aux sections.
--keep-file-symbols
Conserver les symboles liés aux fichiers.
--only-keep-debug
Ne conserver que les informations de débogage.
--plugin nom
Charger un plugin BFD nommé nom.
-v
--verbose
Afficher le nom de chaque fichier avant de le traiter.
-V
--version
Afficher les informations sur la version de strip et quitter.
-w
--wildcard
Autoriser les caractères génériques dans nom_symbole lorsque vous utilisez les options -K, -N, -R ou --remove-section. Notez que le comportement des caractères génériques est défini par la bibliothèque BFD, qui les fait généralement correspondre à des caractères littéraux, sauf indication contraire.
-x
--discard-all
Supprimer tous les symboles, à l'exception de ceux qui sont liés aux sections nécessaires.
-X
--discard-locals
Supprimer tous les symboles locaux, à l'exception de ceux qui sont liés aux sections nécessaires.

VOIR AUSSI

ld(1), a.out(5), coff(5), ecoff(5), elf(5), m32(5), svr4(5).

strip(1) — MinGW-w64-binutils 2.45

NAME

strip - discard symbols from object files

SYNOPSIS

strip [-F bfdname] [-I list] [-K name] [-N name] [-R section] [-a] [-d] [-g] [-i] [-k] [-l] [-N] [-s] [-t] [-u] [-w] [-x] [--all-empty] [--discard-all] [--discard-in-section=name] [--discard-locals] [--file-alignment=num] [--heap-size=num] [--info-script=name] [--keep-file-symbols] [--keep-section-symbols] [--no-merge-explanations] [--no-symbol-table] [--only-keep-debug] [--plugin=name] [--preserve-dates] [--quiet] [--remove-section=section] [--strip-debug] [--strip-unneeded] [--strip-symbol=name] [--target=bfdname] [--verbose] [--wildcard] [-V] [--version] [-o outfile] [--output-file=outfile] [@file...] [objfile...]

DESCRIPTION

The strip utility is used to discard symbols from object files. It can be used on any object file that the system's assembler and linker can process, including the standard formats like a.out, COFF, ECOFF, XCOFF, MS-DOS, alpha, omf, elf, and aix. Striping an object file reduces its size. If you are distributing executables, you should strip them to reduce their size.

By default, strip will remove the symbol table and the relocation bits from an object file. It will also remove all symbols that are not global, and all symbols that it does not recognize.

The strip program is, in fact, a wrapper around the objcopy program. The options are passed on to objcopy.

OPTIONS

-a
--strip-unneeded
Remove all symbols, except for those required for relocation processing. This option is used to strip symbol table entries which are not needed for run-time relocation processing.
-d
--strip-debug
Remove the debugging symbol information from the object file. This includes debugging information stored in formats that are not used by the linker. Note that this option does not remove symbols that are needed for relocation processing.
-g
--discard-locals
Remove compiler-generated local symbols. (These usually start with L or ..)
-i
--info-script=name
Use the script name to control the output. This is only useful when generating executable files.
-k
--keep-file-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying source file names, which would otherwise get stripped.
-l
--no-merge-explanations
Do not merge explanations. This is only useful when generating executable files.
-N
--no-symbol-table
Do not write the symbol table.
-s
--strip-symbols
Do not write the symbol table. This is equivalent to the -s option in the AT&T strip utility.
-t
--only-keep-debug
Strip a file, emptying the contents of any sections that would not be stripped by --strip-debug and leaving the debugging sections intact. In ELF files, this preserves all the note sections in the output as well.

Note - the section headers of the stripped sections are preserved, including their sizes, but the contents of the section are discarded. The section headers are preserved so that other tools can match up the debuginfo file with the real executable, even if that executable has been relocated to a different address space.

The intention is that this option will be used in conjunction with --add-gnu-debuglink to create a two part executable. One a stripped binary which will occupy less space in RAM and in a distribution and the second a debugging information file which is only needed if debugging abilities are required. The suggested procedure to create these files is as follows:

1.<Link the executable as normal. Assuming that it is called>
"foo" then...
1.<Run "objcopy --only-keep-debug foo foo.dbg" to>
create a file containing the debugging info.
1.<Run "objcopy --strip-debug foo" to create a>
stripped executable.
1.<Run "objcopy --add-gnu-debuglink=foo.dbg foo">
to add a link to the debugging info into the stripped executable.

Note---the choice of ".dbg" as an extension for the debug info file is arbitrary. Also the "--only-keep-debug" step is optional. You could instead do this:

1.<Link the executable as normal.>
1.<Copy "foo" to "foo.full">
1.<Run "strip --strip-debug foo">
1.<Run "objcopy --add-gnu-debuglink=foo.full foo">

i.e., the file pointed to by the --add-gnu-debuglink can be the full executable. It does not have to be a file created by the --only-keep-debug switch.

Note---this switch is only intended for use on fully linked files. It does not make sense to use it on object files where the debugging information may be incomplete. Besides the gnu_debuglink feature currently only supports the presence of one filename containing debugging information, not multiple filenames on a one-per-object-file basis.

-u
--discard-all
Remove all symbols, except for dynamic symbols, which are symbols needed for linking.
-w
--wildcard
Permit regular expressions in symbolnames used in other command line options. The question mark (?), asterisk (*), backslash (\) and square brackets ([]) operators can be used anywhere in the symbol name. If the first character of the symbol name is the exclamation point (!) then the sense of the switch is reversed for that symbol. For example: 
-w -K !foo -K fo*

would cause strip to only keep symbols that start with the letters "fo", but to discard the symbol "foo".

-x
--keep-section-symbols
When stripping a file, perhaps with --strip-debug or --strip-unneeded, retain any symbols specifying section names, which would otherwise get stripped.
--preserve-dates
When copying archive members and writing the archive index, preserve their original timestamp values. This option is the inverse of the -D option, above: when copying archive members and writing the archive index, use their actual UID, GID, timestamp, and file mode values.

This is the default unless binutils was configured with --enable-deterministic-archives.

--plugin name
Load the plugin called name to add support for extra target types. This option is only available if the toolchain has been built with plugin support enabled.

If --plugin is not provided, but plugin support has been enabled then strip iterates over the files in ${libdir}/bfd-plugins in alphabetic order and the first plugin that claims the object in question is used.

Please note that this plugin search directory is not the one used by ld's -plugin option. In order to make strip use the linker plugin it must be copied into the ${libdir}/bfd-plugins directory. For GCC based compilations the linker plugin is called liblto_plugin.so.0.0.0. For Clang based compilations it is called LLVMgold.so. The GCC plugin is always backwards compatible with earlier versions, so it is sufficient to just copy the newest one.

-V
--version
Show the version number for strip.
-v
--verbose
Verbose output: list all object files modified. In the case of archives, strip -v lists all members of the archive.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
