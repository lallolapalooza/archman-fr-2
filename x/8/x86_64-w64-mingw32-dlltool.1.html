NOM

DESCRIPTION

dlltool lit ses entrées, qui peuvent provenir des options -d et -b ainsi que des fichiers objets spécifiés en ligne de commande. Il traite ensuite ces entrées et si l'option -e a été spécifiée, il crée un fichier d'exportations. Si l'option -l a été spécifiée, il crée un fichier de bibliothèque et si l'option -z a été spécifiée, il crée un fichier def. Toutes ou une partie des options -e, -l et -z peuvent être présentes dans une seule invocation de dlltool.

Lors de la création d'une DLL, en plus du code source de la DLL, trois autres fichiers sont nécessaires. dlltool peut aider à la création de ces fichiers.

Le premier fichier est un fichier .def qui spécifie quelles fonctions sont exportées depuis la DLL, quelles fonctions la DLL importe, etc. C'est un fichier texte qui peut être créé manuellement, ou dlltool peut être utilisé pour le créer en utilisant l'option -z. Dans ce cas, dlltool analysera les fichiers objets spécifiés en ligne de commande à la recherche des fonctions qui ont été spécialement marquées comme étant exportées et placera des entrées pour elles dans le fichier .def qu'il crée.

Afin de marquer une fonction comme étant exportée d'une DLL, elle doit avoir une entrée -export:<nom_de_la_fonction> dans la section .drectve du fichier objet. Ceci peut être fait en C en utilisant l'opérateur asm() :

asm (".section .drectve");
asm (".ascii \"-export:my_func\"");

int my_func (void) { ... }

Le deuxième fichier nécessaire à la création de DLL est un fichier d'exportations. Ce fichier est lié aux fichiers objets qui composent le corps de la DLL et gère l'interface entre la DLL et le monde extérieur. C'est un fichier binaire et il peut être créé en donnant l'option -e à dlltool lorsqu'il crée ou lit un fichier .def.

Le troisième fichier nécessaire à la création de DLL est le fichier de bibliothèque avec lequel les programmes se lieront pour accéder aux fonctions de la DLL (une « bibliothèque d'importation »). Ce fichier peut être créé en donnant l'option -l à dlltool lorsqu'il crée ou lit un fichier .def.

Si l'option -y est spécifiée, dlltool génère une bibliothèque d'importation retardée qui peut être utilisée à la place de la bibliothèque d'importation normale pour permettre à un programme de se lier à la dll seulement dès qu'une fonction importée est appelée pour la première fois. L'exécutable résultant devra être lié à la bibliothèque statique delayimp contenant __delayLoadHelper2(), qui à son tour importera LoadLibraryA et GetProcAddress de kernel32.

dlltool construit le fichier de bibliothèque à la main, mais il construit le fichier d'exportations en créant des fichiers temporaires contenant des instructions assembleur, puis en les assemblant. L'option de ligne de commande -S peut être utilisée pour spécifier le chemin de l'assembleur que dlltool utilisera, et l'option -f peut être utilisée pour passer des indicateurs spécifiques à cet assembleur. L'option -n peut être utilisée pour empêcher dlltool de supprimer ces fichiers assembleur temporaires une fois terminé, et si -n est spécifié deux fois, cela empêchera dlltool de supprimer les fichiers objets temporaires qu'il a utilisés pour construire la bibliothèque.

Voici un exemple de création d'une DLL à partir d'un fichier source dll.c et aussi de création d'un programme (à partir d'un fichier objet appelé program.o) qui utilise cette DLL :

gcc -c dll.c
dlltool -e exports.o -l dll.lib dll.o
gcc dll.o exports.o -o dll.dll
gcc program.o dll.lib -o program

dlltool peut également être utilisé pour interroger une bibliothèque d'importation existante afin de déterminer le nom de la DLL à laquelle elle est associée. Voir la description de l'option -I ou --identify.

OPTIONS

Les options de ligne de commande ont les significations suivantes :

-d nom-fichier
--input-def nom-fichier
Spécifie le nom d'un fichier .def à lire et à traiter.
-b nom-fichier
--base-file nom-fichier
Spécifie le nom d'un fichier de base à lire et à traiter. Le contenu de ce fichier sera ajouté à la section de relocalisation dans le fichier d'exportations généré par dlltool.
-e nom-fichier
--output-exp nom-fichier
Spécifie le nom du fichier d'exportations à créer par dlltool.
-z nom-fichier
--output-def nom-fichier
Spécifie le nom du fichier .def à créer par dlltool.
-l nom-fichier
--output-lib nom-fichier
Spécifie le nom du fichier de bibliothèque à créer par dlltool.
-y nom-fichier
--output-delaylib nom-fichier
Spécifie le nom du fichier de bibliothèque d'importation retardée à créer par dlltool.
--deterministic-libraries
--non-deterministic-libraries
Lors de la création de bibliothèques de sortie en réponse aux options --output-lib ou --output-delaylib, utiliser soit la valeur zéro pour les horodatages, identifiants utilisateur et identifiants groupe créés (--deterministic-libraries), soit les horodatages, identifiants utilisateur et identifiants groupe réels (--non-deterministic-libraries).
--export-all-symbols
Traite tous les symboles globaux et faibles définis trouvés dans les fichiers objets d'entrée comme des symboles à exporter. Il existe une petite liste de symboles qui ne sont pas exportés par défaut ; voir l'option --no-default-excludes. Vous pouvez ajouter à la liste des symboles à ne pas exporter en utilisant l'option --exclude-symbols.
--no-export-all-symbols
N'exporte que les symboles explicitement listés dans un fichier .def d'entrée ou dans des sections .drectve dans les fichiers objets d'entrée. C'est le comportement par défaut. Les sections .drectve sont créées par les attributs dllexport dans le code source.
--exclude-symbols liste
N'exporte pas les symboles de la liste. C'est une liste de noms de symboles séparés par des virgules ou des deux-points. Les noms de symboles ne doivent pas contenir de tiret de soulignement initial. Ceci n'est pertinent que lorsque --export-all-symbols est utilisé.
--no-default-excludes
N'applique pas la liste par défaut des symboles à ne pas exporter lorsque l'option --export-all-symbols est utilisée. -S chemin
--as chemin
Spécifie le chemin, y compris le nom du fichier, de l'assembleur à utiliser pour créer le fichier d'exportations.
-f options
--as-flags options
Spécifie toutes les options de ligne de commande spécifiques à passer à l'assembleur lors de la construction du fichier d'exportations. Cette option fonctionnera même si l'option -S n'est pas utilisée. Cette option ne prend qu'un seul argument, et si elle apparaît plusieurs fois sur la ligne de commande, les occurrences ultérieures remplaceront les occurrences précédentes. Donc, s'il est nécessaire de passer plusieurs options à l'assembleur, elles doivent être entourées de guillemets doubles.
-D nom
--dll-name nom
Spécifie le nom à stocker dans le fichier .def en tant que nom de la DLL lorsque l'option -e est utilisée. Si cette option n'est pas présente, alors le nom de fichier donné à l'option -e sera utilisé comme nom de la DLL.
-m machine
-machine machine
Spécifie le type de machine pour lequel le fichier de bibliothèque doit être créé. dlltool a un type par défaut intégré, en fonction de la manière dont il a été créé, mais cette option peut être utilisée pour le remplacer. Ceci n'est normalement utile que lors de la création de DLL pour un processeur ARM, lorsque le contenu de la DLL est réellement encodé à l'aide d'instructions Thumb.
-a
--add-indirect
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit ajouter une section qui permet de référencer les fonctions exportées sans utiliser la bibliothèque d'importation. Quoi que cela puisse signifier !
-U
--add-underscore
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit préfixer un trait de soulignement aux noms de tous les symboles exportés.
--no-leading-underscore
--leading-underscore
Spécifie si les symboles standards doivent être préfixés ou non.
--add-stdcall-underscore
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit préfixer un trait de soulignement aux noms des fonctions stdcall exportées. Les noms de variables et les noms de fonctions non-stdcall ne sont pas modifiés. Cette option est utile lors de la création de bibliothèques d'importation compatibles avec GNU pour des DLL tierces qui ont été construites avec des outils MS-Windows.
-k
--kill-at
Spécifie que les suffixes @<nombre> doivent être omis des noms des fonctions stdcall qui seront importées depuis la DLL. Ceci est utile lors de la création d'une bibliothèque d'importation pour une DLL qui exporte des fonctions stdcall mais sans le suffixe de nom de symbole habituel @<nombre>.

Cela ne modifie pas la dénomination des symboles fournis par la bibliothèque d'importation aux programmes liés contre elle, mais uniquement les entrées dans la table d'importation (c'est-à-dire la section .idata).

-A
--add-stdcall-alias
Spécifie que lorsque dlltool crée le fichier d'exportations, il doit ajouter des alias pour les symboles stdcall sans @ <nombre> en plus des symboles avec @ <nombre>.
-p
--ext-prefix-alias préfixe
Demande à dlltool de créer des alias externes pour toutes les importations de DLL avec le préfixe spécifié. Les alias sont créés pour les symboles externes et d'importation sans trait de soulignement initial.
-x
--no-idata4
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques, il doit omettre la section ".idata4". Ceci est pour la compatibilité avec certains systèmes d'exploitation.
--use-nul-prefixed-import-tables
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques, il doit préfixer les tables d'importation ".idata4" et ".idata5" par un élément nul. Ceci émule l'ancienne génération de bibliothèques d'importation GNU de "dlltool". Par défaut, cette option est désactivée.
-c
--no-idata5
Spécifie que lorsque dlltool crée les fichiers d'exportations et de bibliothèques, il doit omettre la section ".idata5". Ceci est pour la compatibilité avec certains systèmes d'exploitation.
-I nom_fichier
--identify nom_fichier
Spécifie que dlltool doit inspecter la bibliothèque d'importation indiquée par nom_fichier et signaler, sur "stdout", le(s) nom(s) de la (des) DLL(s) associée(s). Ceci peut être effectué en plus de toute autre opération indiquée par les autres options et arguments. dlltool échoue si la bibliothèque d'importation n'existe pas ou n'est pas réellement une bibliothèque d'importation. Voir également --identify-strict.
--identify-strict
Modifie le comportement de l'option --identify, de telle sorte qu'une erreur soit signalée si nom_fichier est associée à plus d'une DLL.
-i
--interwork
Spécifie que dlltool doit marquer les objets dans le fichier de bibliothèque et le fichier d'exportations qu'il produit comme supportant l'intertravail entre le code ARM et Thumb.
-n
--nodelete
Demande à dlltool de préserver les fichiers assembleur temporaires qu'il a utilisés pour créer le fichier d'exportations. Si cette option est répétée, alors dlltool préservera également les fichiers objets temporaires qu'il utilise pour créer le fichier de bibliothèque.
-t préfixe
--temp-prefix préfixe
Demande à dlltool d'utiliser préfixe lors de la construction des noms des fichiers assembleur et objet temporaires. Par défaut, le préfixe du fichier temporaire est généré à partir du PID.
-v
--verbose
Demande à dlltool de décrire ce qu'il fait.
-h
--help
Affiche une liste des options de ligne de commande puis quitte.
-V
--version
Affiche le numéro de version de dlltool puis quitte.
@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière soit de guillemets simples, soit de guillemets doubles. N'importe quel caractère (y compris un antislash) peut être inclus en préfixant le caractère à inclure avec un antislash. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées récursivement.
