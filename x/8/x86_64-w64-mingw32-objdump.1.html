DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options contrôlent quelles informations spécifiques afficher. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent juste que leur programme compile et fonctionne.

fichier_objet... sont les fichiers objets à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objets membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes. Au moins une option de la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-header
Si l'un des fichiers fichier_objet est une archive, affiche les informations de l'en-tête d'archive (dans un format similaire à ls -l). Outre les informations que vous pourriez lister avec ar tv, objdump -a affiche le format du fichier objet de chaque membre de l'archive.
--adjust-vma=decalage
Lors de l'affichage des informations, ajoute d'abord decalage à toutes les adresses de section. Ceci est utile si les adresses de section ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise de sections à des adresses spécifiques lorsque l'on utilise un format qui ne peut pas représenter les adresses de section, comme a.out.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet des fichiers objet est nom_bfd. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche des informations résumées des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer l'underscore initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Puisque les formats de mangling de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une erreur de mémoire. La limite essaie d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, un épuisement de la pile est possible et tout rapport de bogue concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Ceci tente d'analyser les informations du format de débogage STABS stockées dans le fichier et de les afficher en utilisant une syntaxe similaire à C. Si aucun débogage STABS n'a été trouvé, cette option se rabat sur l'option -W pour afficher toute information DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques de l'assembleur pour les instructions machine du fichier d'entrée. Cette option désassemble uniquement les sections qui sont censées contenir des instructions. Si l'argument optionnel symbole est donné (peut-être plusieurs fois), alors affiche les mnémoniques de l'assembleur en commençant à (tous les) symbole. Si symbole est un nom de fonction, le désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lorsqu'le symbole suivant sera rencontré. S'il n'y a pas de correspondance pour un symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lus et utilisés lors du désassemblage.

-D
--disassemble
Affiche les mnémoniques de l'assembleur pour toutes les instructions machine du fichier d'entrée. Ceci est similaire à l'option -d, mais cette option tente de désassembler toutes les sections du fichier, y compris celles qui ne sont normalement pas censées contenir de code exécutable.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-eall
Comme -d, mais désassemble le contenu de toutes les sections non vides, à l'exception des sections bss, et non seulement celles censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est activée, objdump suppose que tous les symboles présents dans une section de code se trouvent à la frontière entre les instructions et refuse de désassembler au-delà d'une telle frontière. Cependant, lorsque l'option -D est activée, cette supposition est supprimée. Cela signifie que la sortie de -d et -D peut différer si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur oblige également le désassembleur à décoder des morceaux de données trouvés dans les sections de code comme s'il s'agissait d'instructions.

Notez que si l'option --dwarf=follow-links est activée, les tables de symboles des fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

--no-addresses
Lors du désassemblage, n'affiche pas les adresses sur chaque ligne, ni pour les symboles et les décalages de relocalisation. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, affiche l'adresse complète sur chaque ligne. C'est le format de désassemblage plus ancien.
-EB
-EL
--endian={big|little}
Spécifie l'endianness des fichiers objets. Cela n'affecte que le désassemblage. Cela peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas les informations d'endianness, comme les S-records.
-f
--file-headers
Affiche les informations récapitulatives de l'en-tête général de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage des sections, chaque fois qu'un symbole est affiché, affiche également le décalage de fichier de la région de données qui est sur le point d'être déversée. Si des zéros sont ignorés, alors lorsque le désassemblage reprend, informe l'utilisateur du nombre de zéros ignorés et du décalage de fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du déversement de sections, affiche le décalage de fichier de l'emplacement à partir duquel le déversement commence.
--file-start-context
Spécifie que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, le contexte est étendu au début du fichier.
-h
--section-headers
--headers
Affiche les informations récapitulatives des en-têtes de section du fichier objet.

Les segments de fichier peuvent être déplacés vers des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata ou -Tbss de ld. Cependant, certains formats de fichiers objets, tels que a.out, ne stockent pas l'adresse de départ des segments de fichier. Dans ces situations, bien que ld déplace correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section de fichier ne peut pas afficher les adresses correctes. Au lieu de cela, il affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que, dans certains cas, une section peut avoir à la fois les attributs READONLY et NOREAD définis. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump rapportera les deux, car le réglage exact des bits de drapeau peut être important.

-H
--help
Affiche un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant toutes les architectures et tous les formats d'objets disponibles pour la spécification avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non de débogage trouvées dans des fichiers de débogage séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom de fichier et les numéros de ligne source correspondant au code objet ou aux relocalisations affichées. Utile uniquement avec -d, -D ou -r.
-m machine
--architecture=machine
Spécifie l'architecture à utiliser lors du désassemblage des fichiers objets. Cela peut être utile lors du désassemblage de fichiers objets qui ne décrivent pas les informations d'architecture, tels que les S-records. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par deux points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Cela peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il restreint le désassemblage aux seules instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information d'architecture, mais que vous souhaitez également désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Transmet des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plusieurs options de désassembleur, plusieurs options -M peuvent être utilisées ou regroupées dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'affichage des instructions DSP, spfp sélectionne l'affichage des instructions FP à virgule flottante simple précision FPX, dpfp sélectionne l'affichage des instructions FP à virgule flottante double précision FPX, quarkse_em sélectionne l'affichage des instructions spéciales QuarkSE-EM, fpuda sélectionne l'affichage des instructions d'assistance à virgule flottante double précision, fpus sélectionne l'affichage des instructions FP à virgule flottante simple précision FPU, tandis que fpud sélectionne l'affichage des instructions FP à virgule flottante double précision FPU. De plus, on peut choisir d'afficher tous les immédiats en hexadécimal en utilisant hex. Par défaut, les immédiats courts sont affichés en décimal, tandis que les valeurs d'immédiats longs sont affichées en hexadécimal.

cpu=... permet de forcer un ISA particulier lors du désassemblage d'instructions, remplaçant la valeur de -m ou ce qui se trouve dans le fichier ELF. Cela pourrait être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur des données d'en-tête ELF privées pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois ; seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option de l'assembleur -mcpu=....

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner l'ensemble de noms de registres utilisé lors du désassemblage. Spécifier -M reg-names-std (par défaut) sélectionne les noms de registres tels qu'utilisés dans la documentation du jeu d'instructions ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. Spécifier -M reg-names-apcs sélectionne l'ensemble de noms utilisé par l'ARM Procedure Call Standard, tandis que spécifier -M reg-names-raw utilise simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de nommage des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de nommage de l'ARM/Thumb Procedure Call Standard. (Soit avec les noms de registres normaux, soit avec les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Cela peut être utile lors de la tentative de désassemblage de code Thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées en tant qu'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instructions doivent être générées sous forme de commentaires dans le désassemblage en utilisant -M notes.

Pour le x86, certaines des options dupliquent les fonctions du commutateur -m, mais permettent un contrôle plus fin.

"x86-64"
"i386"
"i8086"
Sélectionne le désassemblage pour l'architecture donnée.
"intel"
"att"
Sélectionne entre le mode syntaxe Intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre l'ISA AMD64 et l'ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Sélectionne entre le mode mnémonique Intel et le mode mnémonique AT&T. Note : "intel-mnemonic" implique "intel" et "att-mnemonic" implique "att".
"addr64"
"addr32"
"addr16"
"data32"
"data16"
Spécifiez la taille d'adresse et la taille d'opérande par défaut. Ces cinq options seront écrasées si "x86-64", "i386" ou "i8086" apparaissent plus tard dans la chaîne d'options.
"suffix"
En mode AT&T et également pour un ensemble limité d'instructions en mode Intel, demande au désassembleur d'afficher un suffixe mnémonique même quand le suffixe pourrait être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument -M raw sélectionne le désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont supportés. Ce sont : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, power11, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwr11, pwrx, titan, vle, et future. 32 et 64 modifient la sélection de CPU par défaut ou antérieure, désactivant et activant respectivement les instructions 64 bits. En outre, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des capacités à une sélection de CPU précédente *ou ultérieure*. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations différentes ou des arguments différents, vous pourriez ne pas obtenir le désassemblage attendu. Si vous désassemblez sans spécifier de sélection de CPU, un choix par défaut sera fait à partir des informations collectées par BFD dans les en-têtes des fichiers objets, mais le résultat pourrait encore ne pas être celui que vous attendez.

Pour RISC-V, les options suivantes sont supportées :

"max"
Désassembler sans vérifier la chaîne d'architecture. C'est un mode de meilleure effort, donc pour les extensions ISA qui se chevauchent, la première correspondance (éventuellement incorrecte dans un contexte donné) sera utilisée pour décoder l'instruction. C'est utile si le fichier ELF n'expose pas la chaîne ISA, empêchant la déduction automatique du sous-ensemble ISA, et que la chaîne ISA de repli par défaut ("rv64gc") ne couvre pas toutes les instructions du binaire.
"numeric"
Afficher les noms de registres numériques, plutôt que les noms ABI (par exemple, afficher "x2" au lieu de "sp").
"no-aliases"
Désassembler uniquement en instructions canoniques. Par exemple, les instructions compressées seront représentées comme telles ("addi sp,sp,-128" deviendra "c.addi16sp sp,-128").
"priv-spec=SPEC"
Afficher le CSR selon la version de la spécification de privilège choisie (par exemple, 1.10, 1.11, 1.12, 1.13).

Pour MIPS, cette option contrôle l'affichage des noms d'instructions et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées :

"no-aliases"
Afficher l'instruction 'brute' au lieu d'une pseudo-instruction. C'est-à-dire, afficher 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassembler les instructions MSA.
"virt"
Désassembler les instructions de virtualisation ASE.
"xpa"
Désassembler les instructions d'adresse physique étendue (XPA) ASE.
"gpr-names=ABI"
Afficher les noms des registres généraux (GPR) appropriés pour l'ABI spécifié. Par défaut, les noms des GPR sont sélectionnés selon l'ABI du binaire en cours de désassemblage.
"fpr-names=ABI"
Afficher les noms des registres flottants (FPR) appropriés pour l'ABI spécifié. Par défaut, les numéros des FPR sont affichés plutôt que leurs noms.
"cp0-names=ARCH"
Afficher les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) appropriés pour le CPU ou l'architecture spécifiée par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés selon l'architecture et le CPU du binaire en cours de désassemblage.
"hwr-names=ARCH"
Afficher les noms des registres matériels (HWR, utilisés par l'instruction "rdhwr") appropriés pour le CPU ou l'architecture spécifiée par ARCH. Par défaut, les noms des HWR sont sélectionnés selon l'architecture et le CPU du binaire en cours de désassemblage.
"reg-names=ABI"
Afficher les noms des GPR et FPR appropriés pour l'ABI sélectionné.
"reg-names=ARCH"
Afficher les noms des registres spécifiques au CPU (registres CP0 et noms HWR) appropriés pour le CPU ou l'architecture sélectionné.

Pour l'une des options listées ci-dessus, ABI ou ARCH peut être spécifié comme numeric pour afficher des nombres plutôt que des noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier des adresses d'entrée de fonction avec -M entry:0xf00ba. Vous pouvez l'utiliser plusieurs fois pour désassembler correctement les fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme les dumps ROM). Dans ces cas, le masque d'entrée de fonction serait sinon décodé comme des instructions VAX, ce qui conduirait probablement au mauvais désassemblage du reste de la fonction.

-p
--private-headers
Affiche les informations spécifiques au format de fichier objet. Les informations exactes affichées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est affichée.
-P options
--private=options
Affiche les informations spécifiques au format de fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (les listes d'options sont affichées avec l'aide).

Pour XCOFF, les options disponibles sont :

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Pour PE, les options disponibles sont :

"header"
"sections"

Tous les formats d'objets ne supportent pas cette option. En particulier, le format ELF ne l'utilise pas.

-r
--reloc
Affiche les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont affichées entremêlées avec le désassemblage.
-R
--dynamic-reloc
Affiche les entrées de relocalisation dynamique du fichier. Ceci n'a de sens que pour les objets dynamiques, comme certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont affichées entremêlées avec le désassemblage.

Note : objdump ne supporte pas l'affichage des relocalisations de type RELR. Celles-ci peuvent être affichées par le programme readelf.

-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non BSS sont affichées. Par défaut, toute section compressée sera affichée sous sa forme compressée. Pour voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source entremêlé avec le désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Typiquement, txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut de "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifie prefix à ajouter aux chemins absolus lorsqu'utilisé avec -S.
--prefix-strip=level
Indique combien de noms de répertoires initiaux doivent être supprimés des chemins absolus codés en dur. N'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, affiche l'instruction en hexadécimal ainsi que sous forme symbolique. C'est le comportement par défaut sauf lorsque --prefix-addresses est utilisé.
--no-show-raw-insn
--no-show-raw-insn

Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et selon le terminal utilisé, la sortie colorée peut ne pas être lisible.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

Affiche le contenu complet des sections demandées. Affiche le contenu des sections .stab, .stab.index et .stab.excl d'un fichier ELF. Ceci n'est utile que sur les systèmes (comme Solaris 2.0) où les entrées de table de symboles de débogage ".stab" sont conservées dans une section ELF. Dans la plupart des autres formats de fichier, les entrées de table de symboles de débogage sont entrelacées avec les symboles de liaison et sont visibles dans la sortie de --syms.

Commence l'affichage des données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
--stop-address=adresse
Arrête l'affichage des données à l'adresse spécifiée. Ceci affecte la sortie des options -d, -r et -s.
-t
--syms
Imprime les entrées de la table des symboles du fichier. Ceci est similaire à l'information fournie par le programme nm, bien que le format d'affichage soit différent. Le format de la sortie dépend du format du fichier dumpé, mais il existe deux types principaux. L'un ressemble à ceci : 
[  4](sec  3)(fl 0x00)(ty   0)(scl   3) (nx 1) 0x00000000 .bss
[  6](sec  1)(fl 0x00)(ty   0)(scl   2) (nx 0) 0x00000000 fred

où le numéro entre crochets est le numéro de l'entrée dans la table des symboles, le numéro sec est le numéro de section, la valeur fl représente les bits de drapeau du symbole, le numéro ty est le type du symbole, le numéro scl est la classe de stockage du symbole et la valeur nx est le nombre d'entrées auxiliaires associées au symbole. Les deux derniers champs sont la valeur du symbole et son nom.

L'autre format de sortie courant, généralement observé avec les fichiers basés sur ELF, ressemble à ceci :

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Ici, le premier numéro est la valeur du symbole (parfois appelée son adresse). Le champ suivant est en fait un ensemble de caractères et d'espaces indiquant les bits de drapeau qui sont définis sur le symbole. Ces caractères sont décrits ci-dessous. Ensuite vient la section avec laquelle le symbole est associé ou *ABS* si la section est absolue (c'est-à-dire non liée à une section), ou *UND* si la section est référencée dans le fichier dumpé, mais pas définie ici.

Après le nom de la section vient un autre champ, un nombre, qui pour les symboles communs est l'alignement et pour les autres symboles est la taille. Enfin, le nom du symbole est affiché.

Les caractères de drapeau sont divisés en 7 groupes comme suit :

"l"
"g"
"u"
"!"
Le symbole est local (l), global (g), global unique (u), ni global ni local (un espace) ou à la fois global et local (!). Un symbole peut être ni local ni global pour diverses raisons, par exemple, parce qu'il est utilisé pour le débogage, mais ce serait probablement une indication de bug s'il était à la fois local et global. Les symboles globaux uniques sont une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, l'éditeur de liens dynamique s'assurera qu'il n'y a qu'un seul symbole de ce nom et de ce type utilisé dans l'ensemble du processus.
"w"
Le symbole est faible (w) ou fort (un espace).
"C"
Le symbole désigne un constructeur (C) ou un symbole ordinaire (un espace).
"W"
Le symbole est un avertissement (W) ou un symbole normal (un espace). Le nom d'un symbole d'avertissement est un message à afficher si le symbole suivant le symbole d'avertissement est jamais référencé.
"I"
"i"
Le symbole est une référence indirecte à un autre symbole (I), une fonction à évaluer pendant le traitement de la relocalisation (i) ou un symbole normal (un espace).
"d"
"D"
Le symbole est un symbole de débogage (d) ou un symbole dynamique (D) ou un symbole normal (un espace).
"F"
"f"
"O"
Le symbole est le nom d'une fonction (F) ou d'un fichier (f) ou d'un objet (O) ou juste un symbole normal (un espace).
-T
--dynamic-syms
Imprime les entrées de la table des symboles dynamiques du fichier. Ceci n'est significatif que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Ceci est similaire à l'information fournie par le programme nm lorsqu'il reçoit l'option -D (--dynamic).

Le format de sortie est similaire à celui produit par l'option --syms, sauf qu'un champ supplémentaire est inséré avant le nom du symbole, donnant les informations de version associées au symbole. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées au symbole, elle est affichée telle quelle, sinon elle est mise entre parenthèses.

--special-syms
Lors de l'affichage des symboles, inclure ceux que la cible considère comme spéciaux d'une manière ou d'une autre et qui ne seraient normalement pas d'intérêt pour l'utilisateur.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multibytes encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), ils ne reçoivent aucun traitement spécial. L'option --unicode=locale affiche la séquence dans la locale actuelle, qui peut ou non les supporter. Les options --unicode=hex et --unicode=invalid les affichent sous forme de séquences d'octets hexadécimaux entourées de crochets angulaires ou accolades.

L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en évidence en rouge (si supporté par le périphérique de sortie). Le coloriage est destiné à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

-V
--version
Imprime le numéro de version de objdump et quitte.
-x
--all-headers
Affiche toutes les informations d'en-tête disponibles, y compris la table des symboles et les entrées de relocalisation. L'utilisation de -x est équivalente à la spécification de toutes les options -a -f -h -p -r -t.
-w
--wide
Formate certaines lignes pour les périphériques de sortie ayant plus de 80 colonnes. Ne tronque pas non plus les noms de symboles lorsqu'ils sont affichés.
-z
--disassemble-zeroes
Normalement, la sortie de désassemblage ignore les blocs de zéros. Cette option demande au désassembleur de désassembler ces blocs, comme tout autre donnée.
-Z
--decompress
L'option -Z est destinée à être utilisée conjointement avec l'option -s. Elle demande à objdump de décompresser toutes les sections compressées avant d'en afficher le contenu.
@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière d'apostrophes simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure par une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées récursivement.

NOM

objdump - display information from object files

SYNTAXE

objdump [option...] [arg...]

DESCRIPTION

objdump displays information from object files. The exact information displayed depends upon the options you specify. By default, objdump displays information about the input section, the symbol table, and the relocation entries.

Object files include:

* files referred to by the command line arguments.

* archive files. The default behavior for archives is to process each file within the archive.

You can use objdump to see the disassembled function headings, to print the symbol table, to print relocation information, to print the dynamic section, and more.

OPTIONS

The options available for objdump are described below. You can also type objdump -? to see all the options available.

-a, --archive-header
Print the archive header for each archive specified.
-A, --automake
Same as the --hl option.
-b, --target BFDname
Display the contents of object files that have been created with a different format. For example, if you have an object file for a Mips machine, you can specify -b mips16-coff.
-C, --demangle[=style]
Decode symbol names which are in the output of c++filt. You can also specify an optional demangling style.
-d, --disassemble
Disassemble the contents of the natural sndsection of the object file and print the assembly code.
-D, --disassemble-all
Disassemble all sections of the object file.
-e, --file-header
Print the detail from the universal, core, and elf file headers of the object file.
-f, --verbose
Print the contents of the file header for the object file.
-g, --debugging
Print the debugging information found in the object file.
-h, --section-headers
Print the section header for the object file.
-i, --info
List the target formats supported by this version of objdump.
-j, --section name
Like --disassemble but only process the section called name. This option can be specified multiple times.
-l, --line-numbers
Print line number information, if available, for the object file. This option will cause objdump to look for the source file corresponding to the object file. If you are disassembling, this will print the source code lines corresponding to the instructions.
-m, --architecture name
Disassemble the indicated architecture.
-M, --disassembler-options options
Pass options relating to the disassembler.
-p, --private-headers
Print the ELF private headers.
-P, --help
Print the help message.
-r, --reloc
Print the relocation entries if any exist in the object file.
-R, --dynamic-reloc
Print the dynamic relocation entries if any exist in the object file.
-s, --full-contents
Print the full contents of all sections, not just the default set.
-S, --source
Display the source code accompanying the assembly code.
-t, --syms
Print the symbol table of the object file.
-T, --dynamic-syms
Print the dynamic symbol table of the object file.
-x, --all-headers
Print all available header information. This is equivalent to specifying -a, -d, -e, -f, -g, -h, -p, -r, and -t.
-W[keyword[=value]], --hash-damping[keyword[=value]]
Set the hash damping. Keyword can be "debug" or "strings".
-X, --dynamic-linker
Print the name of the dynamic linker.
--prefix-addresses
Prefix all output with the page offset address.
--in-order
Print the sections in the order they appear in the file.
--wide
Output wider lines
--adjust-vma=offset
Add offset to all section addresses when printing.
--no-adjust-vma=offset
Subtract offset from all section addresses when printing.
--all-warnings
Same as -W.
--no-show-pages
Do not add page headers.
--version
Show the version number of objdump and exit.
-v, --version
Show the version number of objdump and exit.
-z, --debugging
Print the debugging information found in the object file.
-Z, --no-debugging
Do not print the debugging information found in the object file.
--help
Print the help message.
