Paquet: mingw-w64-binutils

SIZE(1) Outils de développement GNU SIZE(1)

NOM

size - lister les tailles de sections et la taille totale des fichiers binaires

SYNOPSIS

size [-A|-B|-G|--format=compatibilité]
[--help]
[-d|-o|-x|--radix=nombre]
[--common]
[-t|--totals]
[--target=nom_bfd] [-V|--version]
[-f]
[fichier_objet...]

DESCRIPTION

L'utilitaire GNU size liste les tailles de sections et la taille totale pour chacun des fichiers binaires fichier_objet de sa liste d'arguments. Par défaut, une ligne de sortie est générée pour chaque fichier ou pour chaque module si le fichier est une archive.

fichier_objet... sont les fichiers à examiner. Si aucun n'est spécifié, le fichier "a.out" sera utilisé à la place.

OPTIONS

Les options en ligne de commande ont les significations suivantes :

-A
-B
-G
--format=compatibilité
En utilisant l'une de ces options, vous pouvez choisir si la sortie de GNU size ressemble à la sortie de size de System V (en utilisant -A, ou --format=sysv), ou à la sortie de size de Berkeley (en utilisant -B, ou --format=berkeley). Le défaut est le format sur une seule ligne similaire à celui de Berkeley. Alternativement, vous pouvez choisir le format de sortie GNU (en utilisant -G, ou --format=gnu), qui est similaire au format de sortie de Berkeley, mais les tailles sont comptées différemment.

Voici un exemple du format de sortie de Berkeley (par défaut) de size :

$ size --format=Berkeley ranlib size
   text    data     bss     dec     hex filename
 294880   81920   11592  388392   5ed28 ranlib
 294880   81920   11888  388688   5ee50 size

La sortie de style Berkeley compte les données en lecture seule dans la colonne "text", pas dans la colonne "data". Les colonnes "dec" et "hex" affichent toutes deux la somme des colonnes "text", "data" et "bss" en décimal et en hexadécimal respectivement.

Le format GNU compte les données en lecture seule dans la colonne "data", pas dans la colonne "text", et affiche la somme des colonnes "text", "data" et "bss" une seule fois, dans la colonne "total". L'option --radix peut être utilisée pour changer la base numérique de toutes les colonnes. Voici les mêmes données affichées avec les conventions GNU :

$ size --format=GNU ranlib size
      text       data        bss      total filename
    279880      96920      11592     388392 ranlib
    279880      96920      11888     388688 size

Voici les mêmes données, mais affichées plus près des conventions de System V :

$ size --format=SysV ranlib size
ranlib  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11592       385024
Total         388392


size  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11888       385024
Total         388688
--help
-h
-H
-?
Afficher un résumé des arguments et options acceptables.
-d
-o
-x
--radix=nombre
En utilisant l'une de ces options, vous pouvez contrôler si la taille de chaque section est donnée en décimal (-d, ou --radix=10) ; octal (-o, ou --radix=8) ; ou hexadécimal (-x, ou --radix=16). Dans --radix=nombre, seules les trois valeurs (8, 10, 16) sont supportées. La taille totale est toujours donnée dans deux bases ; décimale et hexadécimale pour la sortie -d ou -x, ou octale et hexadécimale si vous utilisez -o.
--common
Afficher la taille totale des symboles communs dans chaque fichier. Lors de l'utilisation du format Berkeley ou GNU, ceux-ci sont inclus dans la taille bss.
-t
--totals
Afficher les totaux de tous les objets listés (mode format Berkeley ou GNU uniquement).
--target=nom_bfd
Spécifier que le format du code objet de fichier_objet est nom_bfd. Cette option peut ne pas être nécessaire ; size peut reconnaître automatiquement de nombreux formats.
-v
-V
--version
Afficher le numéro de version de size.
-f
Ignoré. Cette option est utilisée par d'autres versions du programme size, mais elle n'est pas supportée par la version GNU Binutils.
@fichier
Lire les options en ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière avec des guillemets simples ou doubles. N'importe quel caractère (y compris un antislash) peut être inclus en préfixant le caractère à inclure avec un antislash. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.
