NOM

gprof - afficher les données de profil de graphe d'appels

SYNOPIS

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nom] ]
[ -I répertoires ] [ -d[num] ] [ -k de/à ]
[ -m nb-min ] [ -R fichier-map ] [ -t longueur-tableau ]
[ --[no-]annotated-source[=nom] ]
[ --[no-]exec-counts[=nom] ]
[ --[no-]flat-profile[=nom] ] [ --[no-]graph[=nom] ]
[ --[no-]time=nom] [ --all-lines ] [ --brief ]
[ --debug[=niveau] ] [ --function-ordering ]
[ --file-ordering fichier-map ] [ --directory-path=répertoires ]
[ --display-unused-functions ] [ --file-format=nom ]
[ --file-info ] [ --help ] [ --line ] [ --inline-file-names ]
[ --min-count=n ] [ --no-static ] [ --print-path ]
[ --separate-files ] [ --static-call-graph ] [ --sum ]
[ --table-length=longueur ] [ --traditional ] [ --version ]
[ --width=n ] [ --ignore-non-functions ]
[ --demangle[=STYLE] ] [ --no-demangle ]
[--external-symbol-table=nom]
[ fichier-image ] [ fichiers-profil ... ]

DESCRIPTION

"gprof" produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré au profil de chaque appelant. Les données de profil proviennent du fichier de profil de graphe d'appels (gmon.out par défaut) qui est créé par les programmes compilés avec l'option -pg de "cc", "pc" et "f77". L'option -pg lie également les versions des routines de bibliothèque qui sont compilées pour le profilage. "Gprof" lit le fichier objet donné (par défaut "a.out") et établit la relation entre sa table de symboles et le profil de graphe d'appels de gmon.out. Si plusieurs fichiers de profil sont spécifiés, la sortie de "gprof" montre la somme des informations de profil dans les fichiers de profil donnés.

"Gprof" calcule le temps passé dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appels. Les cycles sont découverts, et les appels dans un cycle sont attribués pour partager le temps du cycle.

Plusieurs formes de sortie sont disponibles à partir de l'analyse.

Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment la plupart du temps CPU, c'est indiqué de manière concise ici.

Le graphe d'appels montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a aussi une estimation du temps passé dans les sous-programmes de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonction qui consomment beaucoup de temps.

La liste de code source annoté est une copie du code source du programme, étiquetée avec le nombre de fois que chaque ligne du programme a été exécutée.

OPTIONS

Ces options spécifient le format de sortie que "gprof" doit produire.

Beaucoup de ces options prennent un symspec optionnel pour spécifier les fonctions à inclure ou exclure. Ces options peuvent être spécifiées plusieurs fois, avec différents symspecs, pour inclure ou exclure des ensembles de symboles.

La spécification de l'une de ces options remplace le comportement par défaut (-p -q), qui imprime un profil plat et une analyse de graphe d'appels pour toutes les fonctions.

"-A[symspec]"
"--annotated-source[=symspec]"
L'option -A fait en sorte que "gprof" imprime le code source annoté. Si symspec est spécifié, imprime la sortie uniquement pour les symboles correspondants.
"-b"
"--brief"
Si l'option -b est donnée, "gprof" n'imprime pas les longs textes qui essaient d'expliquer la signification de tous les champs dans les tableaux. Ceci est utile si vous avez l'intention d'imprimer la sortie, ou si vous en avez assez des textes explicatifs.
"-B"
L'option -B fait en sorte que "gprof" imprime l'analyse du graphe d'appels.
"-C[symspec]"
"--exec-counts[=symspec]"
L'option -C fait en sorte que "gprof" imprime un décompte des fonctions et le nombre de fois où chacune a été appelée. Si symspec est spécifié, imprime le décompte uniquement pour les symboles correspondants.

Si le fichier de données de profil contient des enregistrements de comptage de blocs de base, la spécification de l'option -l, en même temps que -C, fera en sorte que les comptages d'exécution de blocs de base soient comptabilisés et affichés.

"-i"
"--file-info"
L'option -i fait en sorte que "gprof" affiche des informations récapitulatives sur les fichiers de données de profil et quitte ensuite. Le nombre d'enregistrements d'histogramme, de graphe d'appels et de comptage de blocs de base est affiché.
"-I répertoires"
"--directory-path=répertoires"
L'option -I spécifie une liste de répertoires de recherche dans lesquels trouver les fichiers source. La variable d'environnement GPROF_PATH peut également être utilisée pour transmettre ces informations. Principalement utilisé pour la sortie de code source annoté.
"-J[symspec]"
"--no-annotated-source[=symspec]"
L'option -J fait en sorte que "gprof" n'imprime pas le code source annoté. Si symspec est spécifié, "gprof" imprime le code source annoté, mais exclut les symboles correspondants.
"-L"
"--print-path"
Normalement, les noms de fichiers source sont imprimés avec le composant chemin supprimé. L'option -L fait en sorte que "gprof" imprime le chemin complet des noms de fichiers source, qui est déterminé à partir des informations de débogage symboliques dans le fichier image et est relatif au répertoire dans lequel le compilateur a été invoqué.
"-p[symspec]"
"--flat-profile[=symspec]"
L'option -p fait en sorte que "gprof" imprime un profil plat. Si symspec est spécifié, imprime le profil plat uniquement pour les symboles correspondants.
"-P[symspec]"
"--no-flat-profile[=symspec]"
L'option -P fait en sorte que "gprof" supprime l'impression d'un profil plat. Si symspec est spécifié, "gprof" imprime un profil plat, mais exclut les symboles correspondants.
"-q[symspec]"
"--graph[=symspec]"
L'option -q fait en sorte que "gprof" imprime l'analyse du graphe d'appels. Si symspec est spécifié, imprime le graphe d'appels uniquement pour les symboles correspondants et leurs enfants.
"-Q[symspec]"
"--no-graph[=symspec]"
L'option -Q fait en sorte que "gprof" supprime l'impression du graphe d'appels. Si symspec est spécifié, "gprof" imprime un graphe d'appels, mais exclut les symboles correspondants.
"-t"
"--table-length=num"
L'option -t fait en sorte que les num lignes sources les plus actives dans chaque fichier source soient listées lorsque l'annotation source est activée. La valeur par défaut est 10.
"-y"
"--separate-files"
Cette option n'affecte que la sortie du code source annoté. Normalement, "gprof" imprime les fichiers source annotés sur la sortie standard. Si cette option est spécifiée, le code source annoté pour un fichier nommé chemin/nom_fichier est généré dans le fichier nom_fichier-ann. Si le système de fichiers sous-jacent tronquait nom_fichier-ann de manière à écraser le fichier original nom_fichier, "gprof" génère alors le code source annoté dans le fichier nom_fichier.ann (si le nom de fichier original avait une extension, cette extension est remplacée par .ann).
"-Z[symspec]"
"--no-exec-counts[=symspec]"
L'option -Z fait en sorte
s "gprof" ne pas imprimer un décompte des fonctions et du nombre de fois où chacune a été appelée. Si symspec est spécifié, imprimez le décompte, mais excluez les symboles correspondants.
"-r"
"--function-ordering"
L'option --function-ordering fait que "gprof" imprime une suggestion d'ordre des fonctions pour le programme basée sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui prennent en charge l'ordre arbitraire des fonctions dans un exécutable.

Les détails exacts sur la façon de forcer le lieur à placer les fonctions dans un ordre particulier dépendent du système et sortent du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering fait que "gprof" imprime une suggestion d'ordre de ligne de liaison .o pour le programme basée sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de TLB et de cache pour le programme sur les systèmes qui ne prennent pas en charge l'ordre arbitraire des fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin d'accès à un fichier qui fournit des mappages de noms de fonction à fichiers objet. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec GNU "nm", tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T fait que "gprof" imprime sa sortie dans le style BSD "traditionnel".
"-w width"
"--width=width"
Définit la largeur des lignes de sortie sur width. Actuellement, uniquement utilisé lors de l'impression de l'index des fonctions en bas du graphe d'appels.
"-x"
"--all-lines"
Cette option affecte uniquement la sortie annotée de la source. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne d'un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à "tcov"'s -a.
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démanglés lors de l'impression de la sortie. Par défaut, les symboles sont démanglés. L'option "--no-demangle" peut être utilisée pour désactiver le démanglage. Différents compilateurs ont différents styles de manglage. L'argument optionnel de style de démanglage peut être utilisé pour choisir un style de démanglage approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a fait que "gprof" supprime l'impression des fonctions déclarées statiquement (privées). (Ce sont des fonctions dont les noms ne sont pas listés comme globaux et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels depuis/vers celles-ci, etc., seront tous attribués à la fonction qui a été chargée juste avant dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c fait que le graphe d'appels du programme est augmenté par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonction dans le code machine binaire. Comme les enregistrements normaux du graphe d'appels ne sont générés que lorsque les fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels aux fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais uniquement s'il existe des entrées de table de symboles pour elles. Les appels aux routines de bibliothèques dynamiques ne sont généralement pas trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des décomptes d'appels de 0.
"-D"
"--ignore-non-functions"
L'option -D fait que "gprof" ignore les symboles qui ne sont pas connus comme étant des fonctions. Cette option donnera des données de profilage plus précises sur les systèmes où elle est prise en charge (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appels tous les arcs des symboles correspondant à from à ceux correspondant à to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les succès de l'histogramme sont imputés à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec les programmes compilés par d'anciennes versions du compilateur "gcc". Les versions plus récentes de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option indiquera également combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où un programme passe son temps dans une grande fonction, il augmente également considérablement le temps d'exécution de "gprof", et amplifie les inexactitudes statistiques.

"--inline-file-names"
Cette option fait que "gprof" imprime le nom du fichier source après chaque symbole dans le profil plat et le graphe d'appels. Le chemin complet du fichier est imprimé si l'option -L est utilisée.
"-m num"
"--min-count=num"
Cette option affecte uniquement la sortie du décompte d'exécution. Les symboles qui sont exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n fait que "gprof", dans son analyse du graphe d'appels, propage uniquement les temps pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n fait que "gprof", dans son analyse du graphe d'appels, ne propage pas les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S fait que "gprof" lit un fichier de table de symboles externe, tel que /proc/kallsyms, plutôt que de lire la table de symboles à partir du fichier objet donné (par défaut, c'est "a.out"). Ceci est utile pour le profilage des modules noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z, "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et dans lesquelles aucun temps n'a été passé. Ceci est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, toutes les options de débogage sont activées.
"-h"
"--help"
L'option -h affiche l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profilage. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic et prof (pas encore pris en charge).
"-s"
"--sum"
L'option -s fait que "gprof" résume les informations des fichiers de données de profilage qu'il a lus, et écrit un fichier de données de profilage appelé gmon.sum, qui contient toutes les informations des fichiers de données de profilage que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter "gprof" à nouveau sans -s pour analyser les données cumulées dans le fichier gmon.sum.

"-v"
"--version"
L'option -v fait que "gprof" imprime le numéro de version actuel, puis quitte.

Options obsolètes

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer les informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme enfant de toute fonction qui l'appelle, mais son numéro d'index sera indiqué comme [non imprimé]. Plus d'une option -e peut être donnée ; un seul function_name peut être indiqué avec chaque option -e.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e", mais le temps passé dans la fonction (et ses enfants qui n'ont été appelés par personne d'autre), ne sera pas utilisé pour calculer les pourcentages de temps pour le graphe d'appels. Plus d'une option -E peut être donnée ; un seul function_name peut être indiqué avec chaque option -E.

BOGUES

La granularité de l'échantillonnage est montrée, mais reste au mieux statistique. Nous supposons que le temps pour chaque exécution d'une fonction peut être exprimé par le temps total pour la fonction divisé par le nombre de fois où la fonction est appelée. Ainsi, le temps propagé le long des arcs du graphe d'appels vers les parents de la fonction est directement proportionnel au nombre de fois où cet arc est traversé.

Les parents qui ne sont pas eux-mêmes profilés auront le temps de leurs enfants profilés propagé à eux, mais ils apparaîtront comme spontanément invoqués dans la liste du graphe d'appels, et leur temps ne sera pas propagé plus loin. De même, les capteurs de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Tout enfant profiilés des capteurs de signaux devrait avoir son temps propagé correctement, à moins que le capteur de signaux n'ait été invoqué pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou retourner normalement pour que les informations de profilage soient sauvegardées dans le fichier gmon.out.
