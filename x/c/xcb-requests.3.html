NOM

xcb-requests - à propos des man pages des requêtes

DESCRIPTION

Chaque requête X11, comme MapWindow, correspond à un certain nombre de fonctions et de structures de données dans XCB. Pour MapWindow, XCB fournit la fonction xcb_map_window, qui remplit la structure de données xcb_map_window_request_t et l'écrit dans la connexion X11. Comme la requête MapWindow n'a pas de réponse, c'est le cas le plus simple.

RÉPONSES

De nombreuses requêtes ont des réponses. Pour chaque réponse, XCB fournit au moins une structure de données correspondante et une fonction pour renvoyer un pointeur vers une structure de données remplie. Prenons la requête InternAtom comme exemple : XCB fournit la structure de données xcb_intern_atom_reply_t et la fonction xcb_intern_atom_reply. Pour les réponses plus complexes (par exemple, des listes, comme dans xcb_list_fonts), des fonctions d'accès sont fournies.

COOKIES

XCB renvoie un cookie pour chaque requête que vous envoyez. Il s'agit d'une structure de données spécifique à XCB contenant le numéro de séquence avec lequel la requête a été envoyée au serveur X11. Pour obtenir une réponse, vous devez fournir ce cookie (afin que XCB sache quelle réponse en attente vous voulez). Voici un exemple pour illustrer l'utilisation des cookies :

void my_example(xcb_connection *conn) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    cookie = xcb_intern_atom(conn, 0, strlen("_NET_WM_NAME"), "_NET_WM_NAME");
    /* ... faire d'autres choses ici si possible ... */
    if ((reply = xcb_intern_atom_reply(conn, cookie, NULL))) {
        printf("L'atome _NET_WM_NAME a l'ID %u\n", reply->atom);
    }
    free(reply);
}

CHECKED VS. UNCHECKED

Les suffixes checked et unchecked pour les fonctions déterminent le type de gestion des erreurs utilisé pour cette requête spécifique.

Pour les requêtes qui n'ont pas de réponse (par exemple xcb_map_window), les erreurs seront délivrées à la boucle d'événements (vous recevrez un événement X11 de type 0 en appelant xcb_poll_for_event). Si vous souhaitez vérifier explicitement les erreurs de manière bloquante, appelez la version _checked de la fonction (par exemple xcb_map_window_checked) et utilisez xcb_request_check.

Pour les requêtes qui ont une réponse (par exemple xcb_intern_atom), les erreurs seront vérifiées lors de l'appel de la fonction de réponse. Pour obtenir les erreurs dans la boucle d'événements à la place, utilisez la version _unchecked de la fonction (par exemple xcb_intern_atom_unchecked).

Voici un exemple qui illustre les quatre différentes manières de gérer les erreurs :

/*
 * Requête sans réponse, gestion des erreurs dans la boucle d'événements (par défaut)
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    /* C'est une requête sans réponse. Les erreurs seront délivrées à la boucle
     * d'événements. Recevoir une erreur pour xcb_map_window est très probablement
     * un bug dans notre programme, nous n'avons donc pas besoin de le vérifier
     * de manière bloquante. */
    xcb_map_window(conn, window);
    /* ... bien sûr, votre boucle d'événements ne serait pas dans la même fonction ... */
    while ((event = xcb_wait_for_event(conn)) != NULL) {
        if (event->response_type == 0) {
            fprintf("Erreur X11 reçue %d\n", error->error_code);
            free(event);
            continue;
        }
        /* ... gérer un événement normal ... */
    }
}
/*
 * Requête sans réponse, gestion directe des erreurs
 *
 */
void my_example(xcb_connection *conn, xcb_window_t deco, xcb_window_t window) {
    /* Un gestionnaire de fenêtres de reparentage veut savoir si une nouvelle
     * fenêtre a été reparentée avec succès. Sinon (parce que la fenêtre a été
     * détruite, par exemple), il ne sert à rien de mapper une décoration de
     * fenêtre vide, nous devons donc le savoir immédiatement. */
    xcb_void_cookie_t cookie = xcb_reparent_window_checked(conn, window,
                                                           deco, 0, 0);
    xcb_generic_error_t *error;
    if ((error = xcb_request_check(conn, cookie))) {
        fprintf(stderr, "Impossible de reparentrer la fenêtre\n");
        free(error);
        return;
    }
    /* ... faire des choses de gestionnaire de fenêtres ici ... */
}
/*
 * Requête avec réponse, gestion directe des erreurs (par défaut)
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    xcb_generic_error_t *error;
    cookie = xcb_intern_atom(c, 0, strlen("_NET_WM_NAME"), "_NET_WM_NAME");
    /* ... faire d'autres choses ici si possible ... */
    if ((reply = xcb_intern_atom_reply(c, cookie, &error))) {
        printf("L'atome _NET_WM_NAME a l'ID %u\n", reply->atom);
        free(reply);
    } else {
        fprintf(stderr, "Erreur X11 %d\n", error->error_code);
        free(error);
    }
}
/*
 * Requête avec réponse, gestion des erreurs dans la boucle d'événements
 *
 */
void my_example(xcb_connection *conn, xcb_window_t window) {
    xcb_intern_atom_cookie_t cookie;
    xcb_intern_atom_reply_t *reply;
    cookie = xcb_intern_atom_unchecked(c, 0, strlen("_NET_WM_NAME"),
                                       "_NET_WM_NAME");
    /* ... faire d'autres choses ici si possible ... */
    if ((reply = xcb_intern_atom_reply(c, cookie, NULL))) {
        printf("L'atome _NET_WM_NAME a l'ID %u\n", reply->atom);
        free(reply);
    }
    /* ... bien sûr, votre boucle d'événements ne serait pas dans la même fonction ... */
    while ((event = xcb_wait_for_event(conn)) != NULL) {
        if (event->response_type == 0) {
            fprintf("Erreur X11 reçue %d\n", error->error_code);
            free(event);
            continue;
        }
        /* ... gérer un événement normal ... */
    }
}
