ARGUMENTS DE LA REQUÊTE

conn
La connexion XCB à X11.
gc
Le contexte graphique à modifier.
value_mask
L'une des valeurs suivantes :
XCB_GC_FUNCTION
TODO: Se référer à GX
XCB_GC_PLANE_MASK
Dans les opérations graphiques, étant donné un pixel source et un pixel destination, le résultat est calculé bit à bit sur les bits correspondants des pixels ; c'est-à-dire qu'une opération booléenne est effectuée dans chaque plan de bits. Le masque de plan restreint l'opération à un sous-ensemble de plans, de sorte que le résultat est :


((SRC FONCTION DST) ET masque-plan) OU (DST ET (NON masque-plan))

XCB_GC_FOREGROUND
Couleur de premier plan (pixel).
XCB_GC_BACKGROUND
Couleur d'arrière-plan (pixel).
XCB_GC_LINE_WIDTH
La largeur de ligne est mesurée en pixels et peut être supérieure ou égale à un, une ligne large, ou la valeur spéciale zéro, une ligne fine.
XCB_GC_LINE_STYLE
Le style de ligne définit quelles sections d'une ligne sont dessinées : Solid (Pleine) Le chemin complet de la ligne est dessiné. DoubleDash (Double Tiret) Le chemin complet de la ligne est dessiné, mais les tirets pairs sont remplis différemment
que les tirets impairs (voir style de remplissage), avec un style de bout Butt aux jonctions des tirets pairs et
impairs. OnOffDash (Tiret Activé/Désactivé) Seuls les tirets pairs sont dessinés, et le style de bout s'applique à toutes les extrémités internes
des tirets individuels (sauf NotLast qui est traité comme Butt).
XCB_GC_CAP_STYLE
Le style de bout définit comment les extrémités d'un chemin sont dessinées : NotLast (Pas le dernier) Le résultat est équivalent à Butt, sauf que pour une largeur de ligne nulle, la dernière
extrémité n'est pas dessinée. Butt (Carré) Le résultat est carré aux extrémités (perpendiculaire à la pente de la ligne)
sans projection au-delà. Round (Arrondi) Le résultat est un arc circulaire dont le diamètre est égal à la largeur de ligne, centré
sur l'extrémité ; il est équivalent à Butt pour une largeur de ligne nulle. Projecting (En projection) Le résultat est carré à l'extrémité, mais le chemin continue au-delà de l'extrémité sur
une distance égale à la moitié de la largeur de ligne ; il est équivalent à Butt pour une largeur de ligne
nulle.
XCB_GC_JOIN_STYLE
Le style de jointure définit comment les coins sont dessinés pour les lignes larges : Miter (En onglet) Les bords extérieurs des deux lignes se prolongent pour se rencontrer en angle. Cependant, si l'angle
est inférieur à 11 degrés, un style de jointure Bevel est utilisé à la place. Round (Arrondi) Le résultat est un arc circulaire dont le diamètre est égal à la largeur de ligne, centré
sur le point de jonction. Bevel (Biseauté) Le résultat est des styles d'extrémité Butt, puis la découpe triangulaire est remplie.
XCB_GC_FILL_STYLE
Le style de remplissage définit le contenu de la source pour les requêtes de ligne, de texte et de remplissage. Pour toutes les requêtes de texte et de remplissage (par exemple, PolyText8, PolyText16, PolyFillRectangle, FillPoly, et PolyFillArc) ainsi que pour les requêtes de ligne avec un style de ligne Solid (par exemple, PolyLine, PolySegment, PolyRectangle, PolyArc) et pour les tirets pairs des requêtes de ligne avec un style de ligne OnOffDash ou DoubleDash : Solid (Plein) Premier plan Tiled (Tuilé) Tuile OpaqueStippled (Pointillé opaque) Une tuile de la même largeur et hauteur que le pointillé
mais avec l'arrière-plan partout où le pointillé a un zéro et avec le premier plan partout où le pointillé
a un un Stippled (Pointillé) Premier plan masqué par le pointillé Pour les tirets impairs des requêtes de ligne avec un style de ligne DoubleDash : Solid (Plein) Arrière-plan Tiled (Tuilé) Identique aux tirets pairs OpaqueStippled (Pointillé opaque) Identique aux tirets pairs Stippled (Pointillé) Arrière-plan masqué par le pointillé
XCB_GC_FILL_RULE
XCB_GC_TILE
La tuile/pointillé représente un plan bidimensionnel infini avec la tuile/pointillé répliquée dans toutes les dimensions. Lorsque ce plan est superposé au dessin pour être utilisé dans une opération graphique, le coin supérieur gauche d'une instance quelconque de la tuile/pointillé se trouve aux coordonnées spécifiées dans le dessin par l'origine de la tuile/pointillé. Les origines de la tuile/pointillé et du masque sont interprétées par rapport à l'origine du dessin de destination spécifié dans une requête graphique. La pixmap de tuile doit avoir la même racine et la même profondeur que le gcontext (sinon une erreur Match survient). La pixmap de pointillé doit avoir une profondeur d'un et la même racine que le gcontext (sinon une erreur Match survient). Pour le style de remplissage Stippled (mais pas OpaqueStippled), le motif de pointillé est tuilé dans un seul plan et agit comme un masque de découpe supplémentaire à combiner avec AND avec le masque de découpe. N'importe quelle taille de pixmap peut être utilisée pour le tuilage ou le pointillage, bien que certaines tailles puissent être plus rapides à utiliser que d'autres.
XCB_GC_STIPPLE
La tuile/pointillé représente un plan bidimensionnel infini avec la tuile/pointillé répliquée dans toutes les dimensions. Lorsque ce plan est superposé au dessin pour être utilisé dans une opération graphique, le coin supérieur gauche d'une instance quelconque de la tuile/pointillé se trouve aux coordonnées spécifiées dans le dessin par l'origine de la tuile/pointillé. Les origines de la tuile/pointillé et du masque sont interprétées par rapport à l'origine du dessin de destination spécifié dans une requête graphique. La pixmap de tuile doit avoir la même racine et la même profondeur que le gcontext (sinon une erreur Match survient). La pixmap de pointillé doit avoir une profondeur d'un et la même racine que le gcontext (sinon une erreur Match survient). Pour le style de remplissage Stippled (mais pas OpaqueStippled), le motif de pointillé est tuilé dans un seul plan et agit comme un masque de découpe supplémentaire à combiner avec AND avec le masque de découpe. N'importe quelle taille de pixmap peut être utilisée pour le tuilage ou le pointillage, bien que certaines tailles puissent être plus rapides à utiliser que d'autres.

XCB_GC_SUBWINDOW_MODE
Pour ClipByChildren, les fenêtres source et destination sont également découpées par tous les enfants InputOutput visibles. Pour IncludeInferiors, ni la fenêtre source ni la fenêtre destination ne sont découpées par les inférieurs. Cela aura pour effet d'inclure le contenu des sous-fenêtres dans la source et de dessiner à travers les limites des sous-fenêtres de la destination. L'utilisation de IncludeInferiors avec une fenêtre source ou destination d'une profondeur différente avec des inférieurs mappés de profondeur différente n'est pas illégale, mais la sémantique n'est pas définie par le protocole de base.

Changes the Y origin for the tile.

Changes the font.
XCB_GC_SUBWINDOW_MODE
Changes the subwindow mode.
XCB_GC_CLIP_ORIGIN
Changes the clip origin. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request. If a pixmap is specified as the clip-mask, it must have depth 1 and have the same root as the gcontext (or a Match error results).
XCB_GC_CLIP_MASK
Changes the clip-mask. Pixels are not drawn outside the area covered by the clip-mask or where the clip-mask has bits set to 0. The clip-mask affects all graphics requests, but it does not clip sources. The clip-mask origin is interpreted relative to the origin of whatever destination drawable is specified in a graphics request. If a pixmap is specified as the clip-mask, it must have depth 1 and have the same root as the gcontext (or a Match error results). If clip-mask is None, then pixels are always drawn, regardless of the clip origin. The clip-mask can also be set with the xcb_change_gc_rectangles(3) request.

EXAMPLE

/*
 * Changes the foreground color component of the specified graphics context.
 *
 */
void my_example(xcb_connection_t *conn, xcb_gcontext_t gc, uint32_t fg, uint32_t bg) {
    /* C99 allows us to use a compact way of changing a single component: */
    xcb_change_gc(conn, gc, XCB_GC_FOREGROUND, (uint32_t[]){ fg });
    /* The more explicit way. Beware that the order of values is important! */
    uint32_t mask = 0;
    mask |= XCB_GC_FOREGROUND;
    mask |= XCB_GC_BACKGROUND;
    uint32_t values[] = {
        fg,
        bg
    };
    xcb_change_gc(conn, gc, mask, values);
    xcb_flush(conn);
}
