NOM

xca - Gestion de certificats et clés XCA

Une interface graphique pour gérer les certificats X509, les clés RSA/DSA/EC, les requêtes PKCS#10 et les CRL dans le logiciel et sur les cartes à puce.

SYNTAXE

xca [OPTIONS]

DESCRIPTION

Cette application est destinée à être une AC (Autorité de Certification), un magasin de certificats et de clés. Elle utilise une base de données SQL pour stocker les éléments. Par défaut, il s'agit de SQLite3, mais MySQL et PostgreSQL sont également testés et pris en charge. Les types connus sont les demandes de signature de certificat (PKCS#10), les certificats (X509v3), les clés RSA, DSA et EC, et les listes de révocation de certificats. La signature des requêtes et la création de certificats auto-signés sont prises en charge. Les deux peuvent utiliser des modèles pour simplifier. Les structures PKI peuvent être importées et exportées dans plusieurs formats tels que PKCS#12, PEM, DER, PKCS#8, PKCS#7.
XCA permet aux utilisateurs de gérer les cartes à puce via l'interface PKCS#11.

OPTIONS

--crlgen=<identifiant-ac> *
Générer une CRL pour <ac>. Utilisez l'option 'name' pour définir le nom interne de la nouvelle CRL.
--database=<base-de-donnees>
Nom du fichier (*.xdb) de la base de données SQLite ou un descripteur de base de données distante : [utilisateur@hote/TYPE:nom_db#prefix].
--exit
Quitter après avoir importé les éléments.
--help
Afficher cette aide et quitter.
--hierarchy=<repertoire> *
Sauvegarder la hiérarchie d'index OpenSSL dans <dir>.
--index=<fichier> *
Sauvegarder l'index OpenSSL dans <fichier>.
--import *
Importer tous les éléments fournis dans la base de données.
--import-names *
Une liste de noms séparés par des points-virgules appliquée aux éléments importés dans l'ordre où ils sont trouvés dans le fichier PEM et sur la ligne de commande.
--issuers *
Afficher tous les certificats émetteurs connus qui ont une clé privée associée et dont les contraintes de base de l'AC sont définies sur 'true'.
--keygen=<type> *
Générer une nouvelle clé et l'importer dans la base de données. Utilisez l'option 'name' pour définir le nom interne de la nouvelle clé. Le paramètre <type> a le format : '[RSA|DSA|EC]:[<taille>|<courbe>].
--list-curves
Affiche toutes les courbes elliptiques connues.
--list-items *
Lister tous les éléments dans la base de données.
--name=<nom-interne> *
Fournit le nom des nouveaux éléments générés. Un nom automatique sera généré si omis.
--no-native-dialogs
Désactive les dialogues natifs du système d'exploitation pour les messages et les opérations de fichiers et utilise à la place les dialogues spécifiques à Qt.
--no-gui
Ne pas démarrer l'interface graphique. Alternativement, définir la variable d'environnement XCA_NO_GUI=1 ou appeler xca comme lien symbolique 'xca-console'.
--password=<mot-de-passe>
Mot de passe de la base de données pour déverrouiller la base de données. Voir ci-dessous pour les options de format de mot de passe.
--pem
Afficher la représentation PEM des fichiers fournis. N'affiche que la partie publique des clés privées.
--pem-file
Spécifier un nom de fichier pour les données PEM. Implique '--pem'.
--print
Afficher un résumé des fichiers fournis.
--select=<liste-id> *
Sélectionne tous les éléments de la liste d'ID séparés par des virgules à afficher avec 'print', 'text' ou 'pem'.
--sqlpass=<mot-de-passe>
Mot de passe pour accéder au serveur SQL distant. Voir ci-dessous pour les options de format de mot de passe.
--text
Afficher le contenu des fichiers fournis comme le fait OpenSSL.
--verbose
Afficher le journal de débogage sur stderr. Équivalent à définir XCA_DEBUG=all. Voir XCA_DEBUG
--version
Afficher les informations de version et quitter.
Les options marquées d'un astérisque nécessitent une base de données. Soit depuis la ligne de commande, soit comme base de données par défaut.

ARGUMENTS PHRASE DE PASSE

Les options de mot de passe acceptent la même syntaxe qu'openssl :

env:var
Obtenir le mot de passe à partir de la variable d'environnement var. Étant donné que l'environnement d'autres processus est visible sur certaines plateformes (par exemple, ps sous certains systèmes d'exploitation Unix), cette option doit être utilisée avec prudence.
fd:number
Lire le mot de passe à partir du descripteur de fichier number. Ceci peut être utilisé pour envoyer les données via un pipe, par exemple.
file:pathname
La première ligne de pathname est le mot de passe. Si le même argument pathname est fourni aux arguments password et sqlpassword, la première ligne sera utilisée pour les deux mots de passe. pathname n'a pas besoin de faire référence à un fichier régulier : il pourrait par exemple faire référence à un périphérique ou à un tube nommé.
pass:password
Le mot de passe réel est password. Comme le mot de passe est visible par les utilitaires (comme 'ps' sous Unix), cette forme ne doit être utilisée que là où la sécurité n'est pas importante.
stdin
Lire le mot de passe depuis l'entrée standard.

VARIABLES ENVIRONNEMENT

Certaines variables d'environnement plus ou moins utiles sont évaluées par xca

XCA_NO_GUI=1
Ne pas démarrer l'interface graphique de manière forcée. Équivalent à l'argument --no-gui. Si les deux n'ont pas été fournis, XCA essaie d'être intelligent et examine les autres arguments pour juger s'il faut démarrer l'interface graphique ou non.
XCA_DEBUG=<pattern>
La variable d'environnement XCA_DEBUG contrôle le débogage dynamique. Le format est une liste de motifs séparés par des virgules. Chaque motif est : all|[-]<fonction>|[-]<nom_fichier>:<premiere_ligne>[-<derniere_ligne>] Un tiret en préfixe saute la correspondance. La premiere_ligne et la derniere_ligne peuvent être vides et seront remplacées par la première et la dernière ligne du fichier. Si -<derniere_ligne> est omis, seule la ligne exacte de derniere_ligne correspondra.
Exemple : XCA_DEBUG=all,-timerEvent Journalise tout mais saute les messages ennuyeux de timerEvent.
Exemple : XCA_DEBUG=pki_base.cpp:100-,-pki_base.cpp:340 Journalise les messages de pki_base de la ligne 100 jusqu'à la dernière ligne, sauf la ligne 340.
XCA_ABORT_ON_WARNING=1
Option développeur pour planter dans le débogueur en cas de message de journalisation de niveau avertissement. Documenté pour des raisons de complétude. Pas utile pour les non-développeurs.
XCA_PORTABLE=1
Force le mode portable de Windows. Documenté pour des raisons de complétude. Pas utile pour les non-développeurs.
XCA_ARGUMENTS=<man|rst|completion>
>
Affiche les arguments de la ligne de commande au format nroff des pages man, rst de sphinx ou sous forme de liste sur une seule ligne pour la complétion automatique des commandes afin de mettre à jour la documentation si de nouveaux arguments sont ajoutés.
XCA_QPSQL_OPTIONS XCA_QMYSQL_OPTIONS XCA_QODBC_OPTIONS
Options de connexion supplémentaires pour les pilotes de base de données SQL, comme décrit dans https://doc.qt.io/qt-5/qsqldatabase.html#setConnectOptions comme QPSQL_OPTIONS=requiressl=1
