NOM

xcb_change_window_attributes - modifier les attributs d'une fenêtre

SYNTAXE

#include <xcb/xproto.h>

Fonction de requête

xcb_void_cookie_t xcb_change_window_attributes(xcb_connection_t *conn, xcb_window_t window, uint32_t value_mask, const void *value_list);

ARGUMENTS DE LA REQUÊTE

conn
La connexion XCB à X11.
window
La fenêtre à modifier.
value_mask
L'une des valeurs suivantes :
XCB_CW_BACK_PIXMAP
Remplace le pixmap d'arrière-plan par défaut. Le pixmap d'arrière-plan et la fenêtre doivent avoir la même racine et la même profondeur. Tout pixmap de n'importe quelle taille peut être utilisé, bien que certaines tailles puissent être plus rapides que d'autres.

Si XCB_BACK_PIXMAP_NONE est spécifié, la fenêtre n'a pas d'arrière-plan défini. Le serveur peut remplir le contenu avec le contenu précédent de l'écran ou avec du contenu de son choix.

Si XCB_BACK_PIXMAP_PARENT_RELATIVE est spécifié, l'arrière-plan du parent est utilisé, mais la fenêtre doit avoir la même profondeur que le parent (sinon une erreur Match se produit). L'arrière-plan du parent est suivi, et la version actuelle est utilisée chaque fois que l'arrière-plan de la fenêtre est requis.

XCB_CW_BACK_PIXEL
Remplace BackPixmap. Un pixmap de taille indéfinie rempli avec le pixel d'arrière-plan spécifié est utilisé pour l'arrière-plan. Aucune vérification de plage n'est effectuée, le pixel d'arrière-plan est tronqué au nombre approprié de bits.
XCB_CW_BORDER_PIXMAP
Remplace le pixmap de bordure par défaut. Le pixmap de bordure et la fenêtre doivent avoir la même racine et la même profondeur. Tout pixmap de n'importe quelle taille peut être utilisé, bien que certaines tailles puissent être plus rapides que d'autres.

La valeur spéciale XCB_COPY_FROM_PARENT signifie que la pixmap de bordure du parent est copiée (les modifications ultérieures de l'attribut de bordure du parent n'affectent pas l'enfant), mais la fenêtre doit avoir la même profondeur que le parent.

XCB_CW_BORDER_PIXEL
Remplace BorderPixmap. Un pixmap de taille indéfinie rempli avec le pixel de bordure spécifié est utilisé pour la bordure. Aucune vérification de plage n'est effectuée sur la valeur du pixel de bordure, elle est tronquée au nombre approprié de bits.
XCB_CW_BIT_GRAVITY
Définit quelle région de la fenêtre doit être conservée si la fenêtre est redimensionnée.
XCB_CW_WIN_GRAVITY
Définit comment la fenêtre doit être repositionnée si le parent est redimensionné (voir ConfigureWindow).
XCB_CW_BACKING_STORE
Un stockage de sauvegarde WhenMapped (lorsqu'elle est mappée) conseille au serveur que le maintien du contenu des régions occultées lorsque la fenêtre est mappée serait bénéfique. Un stockage de sauvegarde Always (toujours) conseille au serveur que le maintien du contenu même lorsque la fenêtre est non mappée serait bénéfique. Dans ce cas, le serveur peut générer un événement d'exposition lors de la création de la fenêtre. Une valeur de NotUseful (inutile) conseille au serveur que le maintien du contenu est inutile, bien qu'un serveur puisse toujours choisir de maintenir le contenu pendant que la fenêtre est mappée. Notez que si le serveur maintient le contenu, alors le serveur doit maintenir le contenu complet, pas seulement la région à l'intérieur des limites du parent, même si la fenêtre est plus grande que son parent. Pendant que le serveur maintient le contenu, les événements d'exposition ne seront normalement pas générés, mais le serveur peut cesser de maintenir le contenu à tout moment.
XCB_CW_BACKING_PLANES
Les plans de sauvegarde indiquent (avec des bits mis à 1) quels plans de bits de la fenêtre contiennent des données dynamiques qui doivent être préservées dans les stockages de sauvegarde et pendant les save-unders.
XCB_CW_BACKING_PIXEL
Le pixel de sauvegarde spécifie la valeur à utiliser dans les plans non couverts par les plans de sauvegarde. Le serveur est libre de sauvegarder uniquement les plans de bits spécifiés dans le stockage de sauvegarde ou le save-under et de régénérer les plans restants avec la valeur de pixel spécifiée. Tous les bits au-delà de la profondeur spécifiée de la fenêtre dans ces valeurs sont simplement ignorés.
XCB_CW_OVERRIDE_REDIRECT
L'override-redirect spécifie si les requêtes de mappage et de configuration sur cette fenêtre doivent remplacer un SubstructureRedirect sur le parent, typiquement pour informer un gestionnaire de fenêtres de ne pas manipuler la fenêtre.
XCB_CW_SAVE_UNDER
Si 1, le serveur est informé que lorsque cette fenêtre est mappée, la sauvegarde du contenu des fenêtres qu'elle occulte serait bénéfique.
XCB_CW_EVENT_MASK
Le masque d'événements définit les événements qui intéressent le client pour cette fenêtre (ou pour certains types d'événements, les inférieurs de la fenêtre).
XCB_CW_DONT_PROPAGATE
Le masque do-not-propagate définit quels événements ne doivent pas être propagés aux fenêtres ancêtres lorsqu'aucun client n'a le type d'événement sélectionné dans cette fenêtre.
XCB_CW_COLORMAP
La carte de couleurs spécifie la carte de couleurs qui reflète le mieux les vraies couleurs de la fenêtre. Les serveurs capables de prendre en charge plusieurs cartes de couleurs matérielles peuvent utiliser cette information, et les gestionnaires de fenêtres peuvent l'utiliser pour les requêtes InstallColormap. La carte de couleurs doit avoir le même type visuel et la même racine que la fenêtre (sinon une erreur Match se produit). Si CopyFromParent est spécifié, la carte de couleurs du parent est copiée (les modifications ultérieures de l'attribut de carte de couleurs du parent n'affectent pas l'enfant). Cependant, la fenêtre doit avoir le même type visuel que le parent (sinon une erreur Match se produit), et le parent ne doit pas avoir de carte de couleurs None (sinon une erreur Match se produit). Pour une explication de None, voir la requête FreeColormap. La carte de couleurs est copiée en partageant l'objet carte de couleurs entre l'enfant et le parent, et non en faisant une copie complète du contenu de la carte de couleurs.
XCB_CW_CURSOR
Si un curseur est spécifié, il sera utilisé chaque fois que le pointeur se trouve dans la fenêtre. Si None est spécifié, le curseur du parent sera utilisé lorsque le pointeur se trouve dans la fenêtre, et tout changement dans le curseur du parent provoquera un changement immédiat du curseur affiché.
value_list
Valeurs pour chacun des attributs spécifiés dans le masque de bits value_mask. L'ordre doit correspondre à l'ordre des bits possibles de value_mask. Voir l'exemple.

DESCRIPTION

Modifie les attributs spécifiés par value_mask pour la window spécifiée.

VALEUR DE RETOUR

Retourne un xcb_void_cookie_t. Les erreurs (le cas échéant) doivent être gérées dans la boucle d'événements.

Si vous souhaitez gérer les erreurs directement avec xcb_request_check à la place, utilisez xcb_change_window_attributes_checked. Voir xcb-requests(3) pour plus de détails.
