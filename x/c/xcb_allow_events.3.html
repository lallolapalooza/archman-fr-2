NOM

xcb_allow_events - libérer les événements mis en file d'attente

SYNTAXE

#include <xcb/xproto.h>

Fonction de requête

xcb_void_cookie_t xcb_allow_events(xcb_connection_t *conn, uint8_t mode, xcb_timestamp_t time);

ARGUMENTS DE LA REQUÊTE

conn
La connexion XCB à X11.
mode
Une des valeurs suivantes :
XCB_ALLOW_ASYNC_POINTER
Pour AsyncPointer, si le pointeur est gelé par le client, le traitement des événements du pointeur continue normalement. Si le pointeur est gelé deux fois par le client pour le compte de deux saisies distinctes, AsyncPointer débloque les deux. AsyncPointer n'a aucun effet si le pointeur n'est pas gelé par le client, mais le pointeur n'a pas besoin d'être saisi par le client.

XCB_ALLOW_SYNC_POINTER
Pour SyncPointer, si le pointeur est gelé et saisi activement par le client, le traitement des événements du pointeur continue normalement jusqu'à ce que le prochain événement ButtonPress ou ButtonRelease soit rapporté au client, auquel cas le pointeur semble à nouveau se figer. Cependant, si l'événement rapporté provoque la libération de la saisie du pointeur, alors le pointeur ne se fige pas. SyncPointer n'a aucun effet si le pointeur n'est pas gelé par le client ou si le pointeur n'est pas saisi par le client.
XCB_ALLOW_REPLAY_POINTER
Pour ReplayPointer, si le pointeur est saisi activement par le client et est gelé à la suite d'un événement envoyé au client (soit par l'activation d'un GrabButton, soit par un précédent AllowEvents avec le mode SyncPointer mais pas par un GrabPointer), alors la saisie du pointeur est libérée et cet événement est complètement retraité, en ignorant cette fois toute saisie passive au niveau ou au-dessus (vers la racine) de la fenêtre de saisie de la saisie juste libérée. La requête n'a aucun effet si le pointeur n'est pas saisi par le client ou si le pointeur n'est pas gelé à la suite d'un événement.
XCB_ALLOW_ASYNC_KEYBOARD
Pour AsyncKeyboard, si le clavier est gelé par le client, le traitement des événements du clavier continue normalement. Si le clavier est gelé deux fois par le client pour le compte de deux saisies distinctes, AsyncKeyboard débloque les deux. AsyncKeyboard n'a aucun effet si le clavier n'est pas gelé par le client, mais le clavier n'a pas besoin d'être saisi par le client.
XCB_ALLOW_SYNC_KEYBOARD
Pour SyncKeyboard, si le clavier est gelé et saisi activement par le client, le traitement des événements du clavier continue normalement jusqu'à ce que le prochain événement KeyPress ou KeyRelease soit rapporté au client, auquel cas le clavier semble à nouveau se figer. Cependant, si l'événement rapporté provoque la libération de la saisie du clavier, alors le clavier ne se fige pas. SyncKeyboard n'a aucun effet si le clavier n'est pas gelé par le client ou si le clavier n'est pas saisi par le client.
XCB_ALLOW_REPLAY_KEYBOARD
Pour ReplayKeyboard, si le clavier est saisi activement par le client et est gelé à la suite d'un événement envoyé au client (soit par l'activation d'un GrabKey, soit par un précédent AllowEvents avec le mode SyncKeyboard mais pas par un GrabKeyboard), alors la saisie du clavier est libérée et cet événement est complètement retraité, en ignorant cette fois toute saisie passive au niveau ou au-dessus (vers la racine) de la fenêtre de saisie de la saisie juste libérée. La requête n'a aucun effet si le clavier n'est pas saisi par le client ou si le clavier n'est pas gelé à la suite d'un événement.
XCB_ALLOW_ASYNC_BOTH
Pour AsyncBoth, si le pointeur et le clavier sont gelés par le client, le traitement des événements pour les deux périphériques continue normalement. Si un périphérique est gelé deux fois par le client pour le compte de deux saisies distinctes, AsyncBoth débloque les deux. AsyncBoth n'a aucun effet à moins que le pointeur et le clavier ne soient gelés par le client.
XCB_ALLOW_SYNC_BOTH
Pour SyncBoth, si le pointeur et le clavier sont gelés par le client, le traitement des événements (pour les deux périphériques) continue normalement jusqu'à ce que le prochain événement ButtonPress, ButtonRelease, KeyPress ou KeyRelease soit rapporté au client pour un périphérique saisi (événement de bouton pour le pointeur, événement de touche pour le clavier), auquel cas les périphériques se figent à nouveau. Cependant, si l'événement rapporté provoque la libération de la saisie, alors les périphériques ne se figent pas (mais si l'autre périphérique est toujours saisi, un événement ultérieur pour celui-ci provoquera toujours le gel des deux périphériques). SyncBoth n'a aucun effet à moins que le pointeur et le clavier ne soient gelés par le client. Si le pointeur ou le clavier est gelé deux fois par le client pour le compte de deux saisies distinctes, SyncBoth débloque les deux (mais un gel ultérieur pour SyncBoth ne figera chaque périphérique qu'une seule fois).
time
Horodatage pour éviter les conditions de concurrence lors de l'exécution de X sur le réseau.

La valeur spéciale XCB_CURRENT_TIME sera remplacée par l'heure actuelle du serveur.

DESCRIPTION

Libère les événements mis en file d'attente si le client a provoqué le gel d'un périphérique (pointeur/clavier) en le saisissant activement. Cette requête n'a aucun effet si time est antérieure à l'heure de la dernière saisie de la saisie active la plus récente pour ce client ou si time est ultérieure à l'heure actuelle du serveur X.

VALEUR DE RETOUR

Retourne un xcb_void_cookie_t. Les erreurs (le cas échéant) doivent être gérées dans la boucle d'événements.

Si vous souhaitez gérer les erreurs directement avec xcb_request_check, utilisez xcb_allow_events_checked. Voir xcb-requests(3) pour les détails.

ERREURS

xcb_value_error_t
Vous avez spécifié un mode invalide.

    xcb_allow_events, xcb_allow_events_checked — allow events

    xcb_allow_events, xcb_allow_events_checked

    xcb_allow_events, xcb_allow_events_checked - allow events

    SYNTAX

    xcb_allow_events (xcb_connection_t *connection, uint8_t mode)
xcb_allow_events_checked (xcb_connection_t *connection, uint8_t mode)
    -> xcb_void_cookie_t

    DESCRIPTION

    Allow events. This function allows the X server to deliver events that have been temporarily blocked by xcb_grab_pointer, xcb_grab_keyboard or xcb_grab_button. The mode parameter can have the following values:

    • XCB_ALLOW_REPLAY_KEYBOARD: Replay the keyboard events that were suppressed by the grab.

    • XCB_ALLOW_SYNC_KEYBOARD: Synchronize the keyboard device with the display.

    • XCB_ALLOW_ASYNC_KEYBOARD: Allow keyboard events to be delivered asynchronously.

    • XCB_ALLOW_REPLAY_POINTER: Replay the pointer events that were suppressed by the grab.

    • XCB_ALLOW_SYNC_POINTER: Synchronize the pointer device with the display.

    • XCB_ALLOW_ASYNC_POINTER: Allow pointer events to be delivered asynchronously.

    xcb_allow_events_checked can be used only if the following protocol request is available: Asynchronous Event Processing

    PARAMETERS

    connection
    The XCB connection to the X server.
    mode
    The mode in which to allow events.

    RETURN VALUE

    Returns an xcb_void_cookie_t. The structure of the cookie is described below. In order to check if the request was successful, use the xcb_request_check() function. To get the value or the error, use the appropriate accessor functions.
