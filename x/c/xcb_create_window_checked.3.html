value_mask
Une des valeurs suivantes :
XCB_CW_BACK_PIXMAP
Remplace le pixmap d'arrière-plan par défaut. Le pixmap d'arrière-plan et la fenêtre doivent avoir la même racine et la même profondeur. N'importe quelle taille de pixmap peut être utilisée, bien que certaines tailles puissent être plus rapides que d'autres.

Si XCB_BACK_PIXMAP_NONE est spécifié, la fenêtre n'a pas d'arrière-plan défini. Le serveur peut remplir les contenus avec le contenu précédent de l'écran ou avec un contenu de son choix.

Si XCB_BACK_PIXMAP_PARENT_RELATIVE est spécifié, l'arrière-plan du parent est utilisé, mais la fenêtre doit avoir la même profondeur que le parent (ou une erreur de correspondance en résulte). L'arrière-plan du parent est suivi, et la version actuelle est utilisée chaque fois que l'arrière-plan de la fenêtre est requis.

XCB_CW_BACK_PIXEL
Remplace BackPixmap. Un pixmap de taille indéfinie rempli du pixel d'arrière-plan spécifié est utilisé pour l'arrière-plan. Aucune vérification des limites n'est effectuée, le pixel d'arrière-plan est tronqué au nombre approprié de bits.
XCB_CW_BORDER_PIXMAP
Remplace le pixmap de bordure par défaut. Le pixmap de bordure et la fenêtre doivent avoir la même racine et la même profondeur. N'importe quelle taille de pixmap peut être utilisée, bien que certaines tailles puissent être plus rapides que d'autres.

La valeur spéciale XCB_COPY_FROM_PARENT signifie que le pixmap de bordure du parent est copié (les changements ultérieurs à l'attribut de bordure du parent n'affectent pas l'enfant), mais la fenêtre doit avoir la même profondeur que le parent.

XCB_CW_BORDER_PIXEL
Remplace BorderPixmap. Un pixmap de taille indéfinie rempli du pixel de bordure spécifié est utilisé pour la bordure. Aucune vérification des limites n'est effectuée sur la valeur du pixel de bordure, elle est tronquée au nombre approprié de bits.
XCB_CW_BIT_GRAVITY
Définit quelle région de la fenêtre doit être conservée si la fenêtre est redimensionnée.
XCB_CW_WIN_GRAVITY
Définit comment la fenêtre doit être repositionnée si le parent est redimensionné (voir ConfigureWindow).
XCB_CW_BACKING_STORE
Un backing-store de WhenMapped conseille au serveur que le maintien du contenu des régions obscurcies lorsque la fenêtre est mappée serait bénéfique. Un backing-store de Always conseille au serveur que le maintien du contenu même lorsque la fenêtre est démappée serait bénéfique. Dans ce cas, le serveur peut générer un événement d'exposition lors de la création de la fenêtre. Une valeur de NotUseful conseille au serveur que le maintien du contenu est inutile, bien qu'un serveur puisse toujours choisir de maintenir le contenu pendant que la fenêtre est mappée. Notez que si le serveur maintient le contenu, alors le serveur doit maintenir le contenu complet, pas seulement la région dans les limites du parent, même si la fenêtre est plus grande que son parent. Pendant que le serveur maintient le contenu, les événements d'exposition ne seront normalement pas générés, mais le serveur peut arrêter de maintenir le contenu à tout moment.
XCB_CW_BACKING_PLANES
Les backing-planes indiquent (avec les bits mis à 1) quelles paires de bits de la fenêtre contiennent des données dynamiques qui doivent être préservées dans les backing-stores et pendant les save-unders.
XCB_CW_BACKING_PIXEL
Le backing-pixel spécifie la valeur à utiliser dans les plans non couverts par les backing-planes. Le serveur est libre de ne sauvegarder que les paires de bits spécifiées dans le backing-store ou le save-under et de régénérer les paires restantes avec la valeur de pixel spécifiée. Tous les bits au-delà de la profondeur spécifiée de la fenêtre dans ces valeurs sont simplement ignorés.
XCB_CW_OVERRIDE_REDIRECT
L'override-redirect spécifie si les requêtes de mappage et de configuration sur cette fenêtre doivent outrepasser un SubstructureRedirect sur le parent, typiquement pour informer un gestionnaire de fenêtres de ne pas manipuler la fenêtre.
XCB_CW_SAVE_UNDER
Si 1, le serveur est informé que lors du mappage de cette fenêtre, sauvegarder le contenu des fenêtres qu'elle obscurcit serait bénéfique.
XCB_CW_EVENT_MASK
Le masque d'événements définit quels événements intéressent le client pour cette fenêtre (ou pour certains types d'événements, les inférieurs de la fenêtre).
XCB_CW_DONT_PROPAGATE
Le masque do-not-propagate définit quels événements ne doivent pas être propagés aux fenêtres ancêtres lorsqu'aucun client n'a le type d'événement sélectionné dans cette fenêtre.
XCB_CW_COLORMAP
La colormap spécifie la carte de couleurs qui reflète le mieux les vraies couleurs de la fenêtre. Les serveurs capables de supporter plusieurs cartes matérielles peuvent utiliser cette information, et les gestionnaires de fenêtres peuvent l'utiliser pour les requêtes InstallColormap. La carte de couleurs doit avoir le même type visuel et la même racine que la fenêtre (ou une erreur de correspondance en résulte). Si CopyFr

Specifies the background pixmap for the window. Can be a pixmap or XCB_PIXMAP_NONE.
XCB_CW_BACK_PIXEL
Specifies the background pixel for the window. If the window has a colormap, this pixel value is interpreted in that colormap. Otherwise, it is interpreted in the default colormap for the screen.
XCB_CW_BORDER_PIXMAP
Specifies the border pixmap for the window. Can be a pixmap or XCB_PIXMAP_NONE.

XCB_CW_BIT_GRAVITY
Specifies the bit gravity for the window. This determines how the window's contents are translated when the window is resized.
XCB_CW_WINDOW_GRAVITY
Specifies the window gravity for the window. This determines how the window is positioned relative to its parent when the parent is resized.
XCB_CW_FOREGROUND_PIXEL
Specifies the foreground pixel for the window. This is used for drawing borders and underlining subwindow text. It is interpreted in the window's colormap.
XCB_CW_BACKGROUND_STIPPLE
Specifies the background stipple for the window. This is used to tile the background of the window. It is interpreted in the window's colormap.
XCB_CW_BORDER_STIPPLE
Specifies the border stipple for the window. This is used to tile the border of the window. It is interpreted in the window's colormap.

Specifies whether the window should receive SubstructureRedirectMask events. Only one client can select for these events.

Specifies whether the window should receive SubstructureNotifyMask events. These events are used to notify clients about changes to the window hierarchy.
XCB_CW_COLORMAP
If a colormap is specified, it will be used by the new window. If the parent is specified, the parent's colormap is copied (subsequent changes to the parent's colormap attribute do not affect the child). DESCRIPTION

Creates an unmapped window as child of the specified parent window. A CreateNotify event will be generated. The new window is placed on top in the stacking order with respect to siblings.

The coordinate system has the X axis horizontal and the Y axis vertical with the origin [0, 0] at the upper-left corner. Coordinates are integral, in terms of pixels, and coincide with pixel centers. Each window and pixmap has its own coordinate system. For a window, the origin is inside the border at the inside, upper-left corner.

The created window is not yet displayed (mapped), call xcb_map_window to display it.

The created window will initially use the same cursor as its parent.

RETURN VALUE

Returns an xcb_void_cookie_t. Errors (if any) have to be handled in the event loop.

If you want to handle errors directly with xcb_request_check instead, use xcb_create_window_checked. See xcb-requests(3) for details.
