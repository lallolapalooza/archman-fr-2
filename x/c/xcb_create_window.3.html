value_mask
Une des valeurs suivantes :
XCB_CW_BACK_PIXMAP
Remplace le pixmap d'arrière-plan par défaut. Le pixmap d'arrière-plan et la fenêtre doivent avoir la même racine et la même profondeur. N'importe quelle taille de pixmap peut être utilisée, bien que certaines tailles puissent être plus rapides que d'autres.

Si XCB_BACK_PIXMAP_NONE est spécifié, la fenêtre n'a pas d'arrière-plan défini. Le serveur peut remplir le contenu avec le contenu précédent de l'écran ou avec un contenu de son choix.

Si XCB_BACK_PIXMAP_PARENT_RELATIVE est spécifié, l'arrière-plan du parent est utilisé, mais la fenêtre doit avoir la même profondeur que le parent (sinon une erreur Match survient). L'arrière-plan du parent est suivi, et la version actuelle est utilisée à chaque fois que l'arrière-plan de la fenêtre est requis.

XCB_CW_BACK_PIXEL
Remplace BackPixmap. Un pixmap de taille indéfinie rempli avec le pixel d'arrière-plan spécifié est utilisé pour l'arrière-plan. Aucune vérification de plage n'est effectuée, le pixel d'arrière-plan est tronqué au nombre approprié de bits.
XCB_CW_BORDER_PIXMAP
Remplace le pixmap de bordure par défaut. Le pixmap de bordure et la fenêtre doivent avoir la même racine et la même profondeur. N'importe quelle taille de pixmap peut être utilisée, bien que certaines tailles puissent être plus rapides que d'autres.

La valeur spéciale XCB_COPY_FROM_PARENT signifie que le pixmap de bordure du parent est copié (les changements ultérieurs de l'attribut de bordure du parent n'affectent pas l'enfant), mais la fenêtre doit avoir la même profondeur que le parent.

XCB_CW_BORDER_PIXEL
Remplace BorderPixmap. Un pixmap de taille indéfinie rempli avec le pixel de bordure spécifié est utilisé pour la bordure. Aucune vérification de plage n'est effectuée sur la valeur du pixel de bordure, elle est tronquée au nombre approprié de bits.
XCB_CW_BIT_GRAVITY
Définit quelle région de la fenêtre doit être conservée si la fenêtre est redimensionnée.
XCB_CW_WIN_GRAVITY
Définit comment la fenêtre doit être repositionnée si son parent est redimensionné (voir ConfigureWindow).
XCB_CW_BACKING_STORE
Un backing-store de WhenMapped conseille au serveur que le maintien du contenu des régions occultées lorsque la fenêtre est mappée serait bénéfique. Un backing-store de Always conseille au serveur que le maintien du contenu même lorsque la fenêtre est non mappée serait bénéfique. Dans ce cas, le serveur peut générer un événement d'exposition lorsque la fenêtre est créée. Une valeur de NotUseful conseille au serveur que le maintien du contenu est inutile, bien qu'un serveur puisse quand même choisir de maintenir le contenu pendant que la fenêtre est mappée. Notez que si le serveur maintient le contenu, alors le serveur doit maintenir un contenu complet, pas seulement la région à l'intérieur des limites du parent, même si la fenêtre est plus grande que son parent. Pendant que le serveur maintient le contenu, les événements d'exposition ne seront normalement pas générés, mais le serveur peut arrêter de maintenir le contenu à tout moment.
XCB_CW_BACKING_PLANES
Les backing-planes indiquent (avec des bits mis à 1) quelles sont les planes de bits de la fenêtre qui contiennent des données dynamiques qui doivent être préservées dans les backing-stores et pendant les save-unders.
XCB_CW_BACKING_PIXEL
Le backing-pixel spécifie la valeur à utiliser dans les planes non couvertes par les backing-planes. Le serveur est libre de sauvegarder uniquement les planes de bits spécifiées dans le backing-store ou le save-under et de régénérer les planes restantes avec la valeur de pixel spécifiée. Tous les bits au-delà de la profondeur spécifiée de la fenêtre dans ces valeurs sont simplement ignorés.
XCB_CW_OVERRIDE_REDIRECT
L'override-redirect spécifie si les requêtes map et configure sur cette fenêtre doivent outrepasser un SubstructureRedirect sur le parent, typiquement pour informer un gestionnaire de fenêtres de ne pas altérer la fenêtre.
XCB_CW_SAVE_UNDER
Si 1, le serveur est informé que lorsque cette fenêtre sera mappée, la conservation du contenu des fenêtres qu'elle occulte serait bénéfique.
XCB_CW_EVENT_MASK
Le masque d'événements définit les événements pour lesquels le client est intéressé pour cette fenêtre (ou pour certains types d'événements, les inférieurs de la fenêtre).
XCB_CW_DONT_PROPAGATE
Le masque do-not-propagate définit les événements qui ne doivent pas être propagés aux fenêtres ancêtres lorsqu'aucun client n'a le type d'événement sélectionné dans cette fenêtre.
XCB_CW_COLORMAP
Le colormap spécifie la table des couleurs qui reflète le mieux les couleurs réelles de la fenêtre. Les serveurs capables de supporter plusieurs tables de couleurs matérielles peuvent utiliser cette information, et les gestionnaires de fenêtres peuvent l'utiliser pour les requêtes InstallColormap. Le colormap doit avoir le même type visuel et la même racine que la fenêtre (sinon une erreur Match survient). Si CopyFromParent
value_list

DESCRIPTION

Crée une fenêtre et la retourne au client. La fenêtre est créée avec la profondeur spécifiée. Les coordonnées x et y, la largeur et la hauteur spécifient la géométrie de la fenêtre à l'intérieur de son parent. La largeur et la hauteur doivent être inférieures ou égales à la largeur et la hauteur du parent moins les coordonnées x et y du parent.

Le masque value_mask et la liste de valeurs value_list permettent de spécifier de manière optionnelle les attributs de la fenêtre, qui sont décrits dans la section ARGUMENTS DE LA REQUÊTE.

Toutes les valeurs par défaut sont utilisées pour les attributs non spécifiés dans le masque.

Si la fenêtre parente est une fenêtre InputOnly, alors la nouvelle fenêtre doit être InputOnly et sa profondeur doit être zéro. Pour créer une fenêtre qui deviendra visible, vous devez l' mapper après sa création.

RETOUR

Une structure xcb_void_cookie_t. L'évaluation de cette structure renverra une erreur ou rien.

ERREURS

xcb_create_window peut retourner les erreurs suivantes :

BadGC
Une valeur de masque contient une valeur GC invalide.
BadValue
Une valeur invalide a été spécifiée pour un argument.
BadWindow
Une valeur de fenêtre invalide a été spécifiée.
Match
La profondeur ou le visuel ne correspond pas à ceux du parent.

DESCRIPTION

Crée une fenêtre non mappée comme enfant de la fenêtre parent spécifiée. Un événement CreateNotify sera généré. La nouvelle fenêtre est placée en haut de l'ordre d'empilement par rapport aux frères et sœurs.

Le système de coordonnées a l'axe X horizontal et l'axe Y vertical avec l'origine [0, 0] dans le coin supérieur gauche. Les coordonnées sont intégrales, en termes de pixels, et coïncident avec les centres de pixels. Chaque fenêtre et pixmap a son propre système de coordonnées. Pour une fenêtre, l'origine se trouve à l'intérieur de la bordure, au coin supérieur gauche intérieur.

La fenêtre créée n'est pas encore affichée (mappée), appelez xcb_map_window pour l'afficher.

La fenêtre créée utilisera initialement le même curseur que son parent.

VALEUR DE RETOUR

Retourne un xcb_void_cookie_t. Les erreurs (le cas échéant) doivent être gérées dans la boucle d'événements.

Si vous souhaitez gérer les erreurs directement avec xcb_request_check à la place, utilisez xcb_create_window_checked. Voir xcb-requests(3) pour plus de détails.
