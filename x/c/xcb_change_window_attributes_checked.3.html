NOM

xcb_change_window_attributes - changer les attributs de la fenêtre

SYNTAXE

#include <xcb/xproto.h>

Fonction de requête

xcb_void_cookie_t xcb_change_window_attributes(xcb_connection_t *conn, xcb_window_t window, uint32_t value_mask, const void *value_list);

ARGUMENTS DE LA REQUÊTE

conn
La connexion XCB à X11.
window
La fenêtre à modifier.
value_mask
L'une des valeurs suivantes :
XCB_CW_BACK_PIXMAP
Remplace le pixmap de fond par défaut. Le pixmap de fond et la fenêtre doivent avoir la même racine et la même profondeur. Des pixmaps de n'importe quelle taille peuvent être utilisés, bien que certaines tailles puissent être plus rapides que d'autres.

Si XCB_BACK_PIXMAP_NONE est spécifié, la fenêtre n'a pas de fond défini. Le serveur peut remplir les contenus avec le contenu précédent de l'écran ou avec un contenu de son choix.

Si XCB_BACK_PIXMAP_PARENT_RELATIVE est spécifié, le fond du parent est utilisé, mais la fenêtre doit avoir la même profondeur que le parent (sinon une erreur Match survient). Le fond du parent est suivi, et la version actuelle est utilisée chaque fois que le fond de la fenêtre est requis.

XCB_CW_BACK_PIXEL
Remplace BackPixmap. Un pixmap de taille indéfinie rempli avec le pixel de fond spécifié est utilisé pour le fond. La vérification des bornes n'est pas effectuée, le pixel de fond est tronqué au nombre de bits approprié.
XCB_CW_BORDER_PIXMAP
Remplace le pixmap de bordure par défaut. Le pixmap de bordure et la fenêtre doivent avoir la même racine et la même profondeur. Des pixmaps de n'importe quelle taille peuvent être utilisés, bien que certaines tailles puissent être plus rapides que d'autres.

La valeur spéciale XCB_COPY_FROM_PARENT signifie que le pixmap de bordure du parent est copié (les changements ultérieurs de l'attribut de bordure du parent n'affectent pas l'enfant), mais la fenêtre doit avoir la même profondeur que le parent.

XCB_CW_BORDER_PIXEL
Remplace BorderPixmap. Un pixmap de taille indéfinie rempli avec le pixel de bordure spécifié est utilisé pour la bordure. La vérification des bornes n'est pas effectuée sur la valeur du pixel de bordure, elle est tronquée au nombre de bits approprié.
XCB_CW_BIT_GRAVITY
Définit quelle région de la fenêtre doit être conservée si la fenêtre est redimensionnée.
XCB_CW_WIN_GRAVITY
Définit comment la fenêtre doit être repositionnée si le parent est redimensionné (voir ConfigureWindow).
XCB_CW_BACKING_STORE
Un backing-store de WhenMapped conseille au serveur que le maintien du contenu des régions occultées lorsque la fenêtre est affichée serait bénéfique. Un backing-store de Always conseille au serveur que le maintien du contenu même lorsque la fenêtre n'est pas affichée serait bénéfique. Dans ce cas, le serveur peut générer un événement d'exposition lorsque la fenêtre est créée. Une valeur de NotUseful conseille au serveur que le maintien du contenu est inutile, bien qu'un serveur puisse toujours choisir de maintenir le contenu lorsque la fenêtre est affichée. Notez que si le serveur maintient le contenu, alors le serveur doit maintenir un contenu complet et pas seulement la région à l'intérieur des limites du parent, même si la fenêtre est plus grande que son parent. Tant que le serveur maintient le contenu, les événements d'exposition ne seront normalement pas générés, mais le serveur peut cesser de maintenir le contenu à tout moment.
XCB_CW_BACKING_PLANES
Les backing_planes indiquent (avec des bits à 1) quelles pistes de bits de la fenêtre contiennent des données dynamiques qui doivent être conservées dans les backing-stores et lors des save-unders.
XCB_CW_BACKING_PIXEL
Le backing_pixel spécifie quelle valeur utiliser dans les pistes qui ne sont pas couvertes par les backing_planes. Le serveur est libre de ne sauvegarder que les pistes de bits spécifiées dans le backing-store ou save-under et de régénérer les pistes restantes avec la valeur de pixel spécifiée. Tous les bits au-delà de la profondeur spécifiée de la fenêtre dans ces valeurs sont simplement ignorés.
XCB_CW_OVERRIDE_REDIRECT
L'override-redirect spécifie si les requêtes map et configure sur cette fenêtre doivent outrepasser un SubstructureRedirect sur le parent, typiquement pour informer un gestionnaire de fenêtres de ne pas modifier la fenêtre.
XCB_CW_SAVE_UNDER
Si 1, le serveur est informé que lorsque cette fenêtre est affichée, sauvegarder le contenu des fenêtres qu'elle occulte serait bénéfique.
XCB_CW_EVENT_MASK
Le event_mask définit quels événements intéressent le client pour cette fenêtre (ou pour certains types d'événements, les inférieurs de la fenêtre).
XCB_CW_DONT_PROPAGATE
Le do-not-propagate-mask définit quels événements ne doivent pas être propagés aux fenêtres ancêtres lorsqu'aucun client n'a sélectionné le type d'événement dans cette fenêtre.
XCB_CW_COLORMAP
La colormap spécifie la table de couleurs qui reflète le mieux les vraies couleurs de la fenêtre. Les serveurs capables de supporter plusieurs tables de couleurs matérielles peuvent utiliser cette information, et les gestionnaires de fenêtres peuvent l'utiliser pour les requêtes InstallColormap. La table de couleurs doit avoir le même type visuel et la même racine que la fenêtre (sinon une erreur Match survient). Si CopyFromParent est spécifié, la table de couleurs du parent est copiée (les changements ultérieurs de l'attribut de table de couleurs du parent n'affectent pas l'enfant). Cependant, la fenêtre doit avoir le même type visuel que le parent (sinon une erreur Match survient), et le parent ne doit pas avoir de colormap de None (sinon une erreur Match survient). Pour une explication de None, voir la requête FreeColormap. La table de couleurs est copiée en partageant l'objet colormap entre l'enfant et le parent, et non en faisant une copie complète du contenu de la table de couleurs.
XCB_CW_CURSOR
Si un curseur est spécifié, il sera utilisé chaque fois que le pointeur se trouvera dans la fenêtre. Si None est spécifié, le curseur du parent sera utilisé lorsque le pointeur se trouvera dans la fenêtre, et tout changement du curseur du parent entraînera un changement immédiat du curseur affiché.
value_list
Valeurs pour chacun des attributs spécifiés dans le masque binaire value_mask. L'ordre doit correspondre à l'ordre des bits possibles de value_mask. Voir l'exemple.

DESCRIPTION

Modifie les attributs spécifiés par value_mask pour la window spécifiée.

VALEUR DE RETOUR

Retourne un xcb_void_cookie_t. Les erreurs (le cas échéant) doivent être gérées dans la boucle d'événements.

Si vous souhaitez gérer les erreurs directement avec xcb_request_check à la place, utilisez xcb_change_window_attributes_checked. Voir xcb-requests(3) pour plus de détails.
