NOM

xcb_grab_pointer - Saisir le pointeur

SYNTAXE

#include <xcb/xproto.h>

Fonction de requête

xcb_grab_pointer_cookie_t xcb_grab_pointer(xcb_connection_t *conn, uint8_t owner_events, xcb_window_t grab_window, uint16_t event_mask, uint8_t pointer_mode, uint8_t keyboard_mode, xcb_window_t confine_to, xcb_cursor_t cursor, xcb_timestamp_t time);

Structure de données de réponse

typedef struct xcb_grab_pointer_reply_t {
    uint8_t  response_type;
    uint8_t  status;
    uint16_t sequence;
    uint32_t length;
} xcb_grab_pointer_reply_t;

Fonction de réponse

xcb_grab_pointer_reply_t *xcb_grab_pointer_reply(xcb_connection_t *conn, xcb_grab_pointer_cookie_t cookie, xcb_generic_error_t **e);

ARGUMENTS DE LA REQUÊTE

conn
La connexion XCB à X11.
owner_events
Si 1, la grab_window recevra toujours les événements du pointeur. Si 0, les événements ne sont pas rapportés à la grab_window.
grab_window
Spécifie la fenêtre sur laquelle le pointeur doit être saisi.
event_mask
Spécifie quels événements du pointeur sont rapportés au client.

pointer_mode
L'une des valeurs suivantes :
XCB_GRAB_MODE_SYNC
L'état du clavier semble se figer : Aucun événement clavier supplémentaire n'est généré par le serveur jusqu'à ce que le client saisissant émette une requête AllowEvents de libération ou jusqu'à ce que la saisie du clavier soit libérée.
XCB_GRAB_MODE_ASYNC
Le traitement des événements clavier continue normalement.
keyboard_mode
L'une des valeurs suivantes :
XCB_GRAB_MODE_SYNC
L'état du clavier semble se figer : Aucun événement clavier supplémentaire n'est généré par le serveur jusqu'à ce que le client saisissant émette une requête AllowEvents de libération ou jusqu'à ce que la saisie du clavier soit libérée.
XCB_GRAB_MODE_ASYNC
Le traitement des événements clavier continue normalement.
confine_to
Spécifie la fenêtre dans laquelle le pointeur doit être confiné (l'utilisateur ne pourra pas déplacer le pointeur en dehors de cette fenêtre).

La valeur spéciale XCB_NONE signifie ne pas confiner le pointeur.

cursor
Spécifie le curseur qui doit être affiché ou XCB_NONE pour ne pas changer le curseur.
time
L'argument de temps permet d'éviter certaines circonstances qui surviennent si les applications répondent lentement ou s'il y a des délais réseau importants. Considérons une situation où vous avez deux applications, qui saisissent toutes deux le pointeur lorsqu'elles sont cliquées. Si les deux applications spécifient l'horodatage de l'événement, la deuxième application peut se réveiller plus rapidement et saisir le pointeur avec succès avant la première application. La première application recevra alors une indication que l'autre application a saisi le pointeur avant que sa requête ne soit traitée.

La valeur spéciale XCB_CURRENT_TIME sera remplacée par l'heure actuelle du serveur.

length
La longueur de la réponse, en mots (un mot fait 4 octets).

DESCRIPTION

Saisit activement le contrôle du pointeur. Les événements de pointeur ultérieurs ne sont rapportés qu'au client saisissant. Remplace toute saisie de pointeur active par ce client.

VALEUR DE RETOUR

Retourne une xcb_grab_pointer_cookie_t. Les erreurs doivent être gérées lors de l'appel de la fonction de réponse xcb_grab_pointer_reply.

Si vous souhaitez gérer les erreurs dans la boucle d'événements à la place, utilisez xcb_grab_pointer_unchecked. Voir xcb-requests(3) pour plus de détails.

EXEMPLE

/*
 * Saisit activement le pointeur
 *
 */
void my_example(xcb_connection_t *conn, xcb_screen_t *screen, xcb_cursor_t cursor) {
    xcb_grab_pointer_cookie_t cookie;
    xcb_grab_pointer_reply_t *reply;
    cookie = xcb_grab_pointer(
        conn,
        false,               /* obtenir tous les événements du pointeur spécifiés par le masque suivant */
        screen->root,        /* saisir la fenêtre racine */
        XCB_NONE,            /* quels événements laisser passer */
        XCB_GRAB_MODE_ASYNC, /* les événements du pointeur doivent continuer normalement */
        XCB_GRAB_MODE_ASYNC, /* mode clavier */
        XCB_NONE,            /* confine_to = dans quelle fenêtre le curseur doit rester */
        cursor,              /* nous changeons le curseur pour celui que l'utilisateur a voulu */
        XCB_CURRENT_TIME
    );
    if ((reply = xcb_grab_pointer_reply(conn, cookie, NULL))) {
        if (reply->status == XCB_GRAB_STATUS_SUCCESS)
            printf("pointeur saisi avec succès\n");
        free(reply);
    }
}

NAME

xcb_grab_keyboard_reply -

SYNOPSIS

In xcb_grab_keyboard_reply.h

int xcb_grab_keyboard_reply (xcb_connection_t *c,
xcb_grab_keyboard_cookie_t cookie,
void *e);

REQUEST ARGUMENTS

c
The xcb_connection_t to use.
cookie
The xcb_grab_keyboard_cookie_t returned by a previous xcb_grab_keyboard or xcb_grab_keyboard_checked.
e
If not NULL,POPULATE a xcb_grab_keyboard_reply_t.

REPLY FIELDS

response_type
The type of the reply, discriminant.
sequence
The sequence number of the reply.
length
The length of the reply, in chunks of 4 bytes.
status
The status of the grab.
owner_events
Whether the owner of the grab events.

DESCRIPTION

Grab keyboard reply.

RETURN VALUE

Returns an int. >= 0 means that the reply is valid. The value is the sequence number of the reply. 0 means that the reply is not valid. It is also possible that the reply is not valid if the sequence number is negative.

If you want to leave the reply to the xcb_connection_t, set e to NULL.

ERRORS

The following errors may be generated:

xcb_grab_keyboard_error_t
  • XCB_GRAB_KEYBOARD_ERROR_ACCESS
