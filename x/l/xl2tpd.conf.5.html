xl2tpd.conf(5) Manuel des formats de fichiers xl2tpd.conf(5)

NOM

xl2tpd.conf - Fichier de configuration L2TPD

DESCRIPTION

Le fichier xl2tpd.conf contient des informations de configuration pour xl2tpd, l'implémentation libre du protocole l2tp.

Le fichier de configuration est composé de sections et de paramètres. Chaque section a un nom donné qui sera utilisé lors de l'utilisation du FIFO de configuration (normalement /var/run/xl2tpd/l2tp-control). Voir xl2tpd.8 pour plus de détails.

Le nom spécial donné default spécifiera les paramètres applicables à toutes les sections suivantes.

SECTION GLOBALE

fichier auth
Spécifie où trouver le fichier d'authentification utilisé pour authentifier les tunnels l2tp. Le défaut est /etc/xl2tpd/l2tp-secrets.
ipsec saref
Utilise le suivi d'association de sécurité IPsec. Lorsque ceci est activé, les paquets reçus par xl2tpd devraient avoir deux champs supplémentaires (refme et refhim) qui permettent le suivi de plusieurs clients utilisant la même adresse IP interne NATée, et permettent le suivi de plusieurs clients derrière le même routeur NAT. Ceci doit être supporté par le noyau. Actuellement, ceci ne fonctionne qu'avec Openswan KLIPS en mode "mast". (voir http://www.openswan.org/)

Définissez ceci à yes et le système fournira des valeurs SAref correctes dans les appels recvmsg().

Les valeurs peuvent être 'yes' ou 'no'. Le défaut est 'no'.

saref refinfo
Lors de l'utilisation du suivi d'association de sécurité IPsec, un nouveau setsockopt est utilisé. Puisque ce n'est pas (encore ?) une option officielle du noyau Linux, nous avons été décalés. Openswan jusqu'à 2.6.35 pour les noyaux Linux jusqu'à 2.6.35 utilisait un numéro saref de 22. Linux 3.6.36+ utilise 22 pour IP_NODEFRAG. Nous avons déplacé notre IP_IPSEC_REFINFO à 30. Si non défini, le défaut est d'utiliser 30. Pour les anciens noyaux patchés SAref, utilisez 22.
listen-addr
L'adresse IP de l'interface sur laquelle le démon écoute. Par défaut, il écoute sur INADDR_ANY (0.0.0.0), ce qui signifie qu'il écoute sur toutes les interfaces.
port
Spécifie quel port UDP xl2tpd doit utiliser. Le défaut est 1701.
contrôle d'accès
Si défini à 'yes', le processus xl2tpd n'acceptera que les connexions des adresses des pairs spécifiées dans les sections suivantes. Le défaut est 'no'.
debug avp
Définissez ceci à 'yes' pour activer la sortie syslog des informations de débogage AVP L2TP.
debug network
Définissez ceci à 'yes' pour activer la sortie syslog des informations de débogage réseau.
debug packet
Définissez ceci à 'yes' pour activer l'affichage des informations de débogage des paquets L2TP. Note : La sortie va sur STDOUT, utilisez donc ceci uniquement en conjonction avec l'option de ligne de commande -D.
debug state
Définissez ceci à 'yes' pour activer la sortie syslog des informations de débogage FSM.
debug tunnel
Définissez ceci à 'yes' pour activer la sortie syslog des informations de débogage de tunnel.
max retries
Spécifie combien de tentatives avant qu'un tunnel ne soit fermé. S'il n'y a pas de tunnel, alors arrêter de retransmettre. Le défaut est 5.

SECTION LNS

exclusive
Si défini à 'yes', un seul tunnel de contrôle sera autorisé à être construit entre 2 pairs.
(no) ip range
Spécifie la plage d'adresses IP que le LNS assignera aux tunnels PPP LAC connectés. Plusieurs plages peuvent être définies. L'utilisation de la mention 'no' interdit l'utilisation de cette plage particulière. Les plages sont définies en utilisant le format IP - IP (exemple : 1.1.1.1 - 1.1.1.10). Notez qu'au moins une option ip range doit être donnée, ou vous devez définir assign ip à no.
assign ip
Définissez ceci à 'no' si xl2tpd ne doit pas assigner d'adresses IP à partir du pool défini avec l'option ip range. Ceci peut être utile si vous avez un autre moyen d'assigner des adresses IP, par exemple un pppd qui supporte RADIUS AAA.
(no) lac
Spécifie les adresses IP des LAC autorisés à se connecter à xl2tpd agissant en tant que LNS. Le format est le même que l'option ip range.
hidden bit
Si défini à 'yes', xl2tpd utilisera la fonctionnalité de masquage AVP de L2TP. Pour obtenir plus d'informations sur les AVP masqués et les AVP en général, référez-vous à rfc2661 (ajouter URL ?)
local ip
Utiliser l'IP suivante comme adresse IP propre à xl2tpd.
local ip range
Spécifie la plage d'adresses que le LNS assignera comme adresse locale aux tunnels PPP LAC connectés. Cette option est mutuellement exclusive avec l'option local ip et est utile dans les cas où il est souhaitable d'avoir une adresse IP unique pour chaque tunnel. Spécifiez la valeur de la plage exactement comme l'option ip range. Notez que l'option assign ip n'a aucun effet sur cette option.
length bit
Si défini à 'yes', le bit de longueur présent dans la charge utile du paquet l2tp sera utilisé.
(refuse | require) chap
Exigera ou refusera que le pair distant soit authentifié via CHAP pour l'authentification ppp.
(refuse | require) pap
Exigera ou refusera que le pair distant soit authentifié via PAP pour l'authentification ppp.
(refuse | require) authentication
Exigera ou refusera que le pair distant s'authentifie.
unix authentication
Si défini à 'yes', /etc/passwd sera utilisé pour l'authentification ppp du pair distant.
hostname
Rapportera ceci comme le nom d'hôte xl2tpd dans la négociation.
ppp debug
Ceci activera le débogage pour pppd.
pass peer
Passe l'adresse IP du pair à pppd en tant qu'ipparam. Activé par défaut.
pppoptfile
Spécifie le chemin d'un fichier contenant les paramètres de configuration de pppd à utiliser.
call rws
Cette option est obsolète et ne fonctionne plus. Elle était utilisée pour définir la taille de la fenêtre de contrôle de flux pour les appels ou sessions L2TP individuels. La norme L2TP (RFC2661) ne définit plus le contrôle de flux ni les tailles de fenêtre sur les appels ou les sessions.
tunnel rws
Ceci définit la taille de la fenêtre du canal de contrôle. La taille de la fenêtre est définie comme le nombre de paquets en attente non acquittés, et non comme un nombre d'octets.
flow bits
Si défini à 'yes', les numéros de séquence seront inclus dans la communication. La fonctionnalité d'utilisation des numéros de séquence dans les sessions est actuellement défectueuse et ne fonctionne pas.
challenge
Si défini à 'yes', utilisez l'authentification par défi pour authentifier le pair.
rx bps
Si défini, le maximum de bande passante de réception sera réglé à cette valeur.
tx bps
Si défini, le maximum de bande passante de transmission sera réglé à cette valeur.

OPTIONS

The following options are available for the global section and for each tunnel:

access control
The file containing the access control list. See xl2tpd.conf(5) for more details. Defaults to /etc/xl2tpd/xl2tpd.conf.
audit
Set to 'yes' to enable audit logging.
debug avp
Enable debugging of AVP packets.
debug chaps
Enable debugging of CHAP packets.
debug filter
Enable debugging of filter packets.
debug icmp
Enable debugging of ICMP packets.
debug l2tp
Enable debugging of L2TP packets.
debug ppp
Enable debugging of PPP packets.
debug radius
Enable debugging of RADIUS packets.
debug stun
Enable debugging of STUN packets.
default mss
Set the default MSS value. Defaults to 1400.
flowbits
Set to 'yes' to enable flowbits.
listen ip
The ip address to listen on. Defaults to any.
local ip
The ip address to use for outgoing packets. Defaults to the ip address of the interface.
maximizeppp
If set to 'yes', xl2tpd will attempt to maximize the PPP frame size.
name
The name of the tunnel. Defaults to the name of the section.
require chap
If set to 'yes', xl2tpd will require CHAP authentication.
require authentication
If set to 'yes', xl2tpd will require authentication.
require pap
If set to 'yes', xl2tpd will require PAP authentication.
radius
Set to 'yes' to enable RADIUS authentication.
radius log
Set to 'yes' to enable RADIUS logging.
radius retry
Set the number of retries for RADIUS. Defaults to 3.
radius timeout
Set the timeout for RADIUS. Defaults to 5 seconds.
running
Set to 'no' to disable the tunnel.
use send
Set to 'yes' to use the send command.

LNS SECTION

The following options are specific to the LNS section. These options are used when xl2tpd is acting as the LNS (e.g. when a remote LAC connects to it).

lns
Set the dns name or ip address of the LNS to connect to.
autodial
If set to 'yes', xl2tpd will automatically dial the LAC during startup.
redial
If set to 'yes', xl2tpd will attempt to redial if the call get disconnected. Note that, if enabled, xl2tpd will keep passwords in memory: a potential security risk.
redial timeout
Wait X seconds before redial. The redial option must be set to yes to use this option. Defaults to 30 seconds.
max redials
Will give up redial tries after X attempts.

LAC SECTION

The following options are specific to the LAC section. These options are used when xl2tpd is acting as the LAC (e.g. when it connects to a remote LNS).

autodial
If set to 'yes', xl2tpd will automatically dial the LNS during startup.
redial
If set to 'yes', xl2tpd will attempt to redial if the call get disconnected. Note that, if enabled, xl2tpd will keep passwords in memory: a potential security risk.
redial timeout
Wait X seconds before redial. The redial option must be set to yes to use this option. Defaults to 30 seconds.
max redials
Will give up redial tries after X attempts.
lns
The ip address or dns name of the LNS to connect to.
ppp
The options to pass to pppd. See pppd(8) for more details.

FILES

/etc/xl2tpd/xl2tpd.conf
Configuration file of xl2tpd, used by default.
/etc/xl2tpd/l2tp-secrets
Secrets file, used by default.
/var/run/xl2tpd/l2tp-control
Control file, used by default.
