NOM

xloadimage, xsetbg, xview - charger des images dans une fenêtre X11 ou sur la fenêtre racine

SYNTAXE

xloadimage [options_globales] {[options_image] image ...}
xloadimage [options_globales] [options_image] stdin < image

DESCRIPTION

Xloadimage affiche des images dans une fenêtre X11, les charge sur la fenêtre racine, ou les écrit dans un fichier. De nombreux types d'images sont reconnus ; utilisez l'option -supported pour les lister.

Si le nom de fichier stdin est donné, xloadimage lira l'image depuis l'entrée standard si cette capacité est supportée par le chargeur pour ce type d'image (la plupart des types supportent la lecture depuis stdin).

Si l'écran de destination ne peut pas supporter le nombre de couleurs de l'image, l'image sera tramée (destination monochrome) ou sa palette sera réduite (destination couleur) comme il convient. Ceci peut aussi être fait de force avec les options -halftone, -dither, et -colors.

Une variété de manipulations d'images peuvent être spécifiées, incluant la correction gamma, le blanchiment, le rognage, le tramage, la réduction de profondeur, la rotation et le zoom. La plupart de ces manipulations ont des implémentations simples ; la vitesse a été privilégiée sur la précision.

Si vous visualisez une grande image dans une fenêtre, la fenêtre initiale fera au plus 90% de la taille de l'écran, sauf si le gestionnaire de fenêtres ne gère pas correctement les requêtes de taille de fenêtre ou si vous avez utilisé l'option -fullscreen. Vous pouvez déplacer l'image dans la fenêtre en glissant avec le premier bouton de la souris. Le curseur indiquera dans quelles directions vous pouvez glisser, le cas échéant. Vous pouvez quitter la fenêtre en tapant 'q' ou '^C' lorsque le focus du clavier est sur la fenêtre.

Si plusieurs fichiers image sont spécifiés sur la ligne de commande, chaque image sera affichée dans l'ordre (sauf si -merge ou -goto sont utilisés).

Une grande variété de manipulations d'images courantes peuvent être réalisées en mélangeant et associant les options disponibles. Voir la section intitulée CONSEILS POUR DE BONS AFFICHAGES D'IMAGES pour quelques idées.

L'option -dump fait que l'image est écrite dans un fichier au lieu d'être affichée après traitement. Cela vous permet de lire une image, d'effectuer un certain nombre d'opérations de traitement dessus, et de sauvegarder l'image résultante. Cela permet aussi la traduction depuis n'importe lequel des types d'images reconnus vers n'importe lequel des formats qui supportent le vidage. Xsetbg est équivalent à xloadimage -onroot -quiet et xview est équivalent à xloadimage -view -verbose.

CLASSE RESSOURCE

Xloadimage utilise le nom de classe de ressource Xloadimage pour les gestionnaires de fenêtres qui ont besoin que cette ressource soit définie. Ce nom a changé dans les versions 2.00 et 2.01 ; certaines versions précédentes utilisaient le nom XLoadImage (qui était difficile à prédire) ou xloadimage (qui entrait en conflit avec les conventions de nommage de classe).

OPTIONS GLOBALES

Les options suivantes affectent le fonctionnement global de xloadimage. Elles peuvent être spécifiées n'importe où sur la ligne de commande. De plus, l'option -global peut être utilisée pour forcer une option d'image à s'appliquer à toutes les images.

-bordure couleur
Définit la partie d'arrière-plan de la fenêtre qui n'est couverte par aucune image à couleur.
-configuration
Affiche le chemin des images, les suffixes d'images et les filtres supportés qui seront utilisés lors de la recherche et de la lecture d'images. Ceux-ci sont chargés depuis ~/.xloadimagerc et éventuellement depuis un fichier système (normalement /usr/lib/xloadimagerc). Ceci remplace l'option -path.
-défaut
Utilise le tissage racine par défaut comme image. Cette option force -onroot. Si -défaut est utilisé seul, il est identique à xsetroot sans argument. Si utilisé conjointement avec -tuile, cette option peut être utilisée pour placer des images sur le tissage racine par défaut (voir EXEMPLES ci-dessous).
-debug
Communique avec le serveur X en mode synchrone. Ceci est utile pour le débogage. Si une erreur X est rencontrée dans ce mode, un cœur sera vidé.
-affichage nom_affichage
Nom d'affichage X11 vers lequel envoyer l'(les) image(s).
-dump type_image[,option=valeur] fichier_vidage
Au lieu d'afficher l'image chargée et traitée, la vidanger dans un fichier image du type spécifié. Pour une liste des types d'images qui peuvent être vidés, utilisez l'option -supported. Certains types d'images ont des options qui affectent le format du fichier créé. Voir OPTIONS DE VIDAGE ci-dessous. Une image peut être vidée dans n'importe quel format de vidage supporté, quel que soit le type d'image original, donc la traduction de fichiers image est possible en utilisant cette option.
-adapter
Force l'image à utiliser la représentation visuelle et la palette de couleurs par défaut. Ceci est utile si vous ne souhaitez pas d'effets technicolor lorsque la palette de couleurs est centrée dans la fenêtre d'image, mais cela peut réduire la qualité de l'image affichée. Ceci est activé par défaut si -onroot ou -windowid est spécifié.
-fork
Fork xloadimage. Ceci fait que xloadimage se désassocie du shell. Cette option active automatiquement -quiet.
-plein_ecran
Utilise tout l'écran pour afficher les images. Si combiné avec -onroot, l'image sera mise à l'échelle pour remplir toute la fenêtre racine.
-geometrie WxH[{+-X}{+-}Y]
Ceci définit la taille de la fenêtre sur laquelle les images sont chargées à une valeur différente de la taille de l'image. Lors de la visualisation d'une image dans une fenêtre, ceci peut être utilisé pour réduire la taille de la fenêtre de destination. Lors du chargement d'une image sur la fenêtre racine, cette option contrôle la taille du pixmap qui sera chargé sur la racine. Si la taille est plus petite que celle de l'écran, l'image sera répliquée.
-aller image_nom
Force l'image suivante à être affichée à être l'image nommée image_nom. Ceci est utile pour générer des diaporamas en boucle. Si plus d'une image du même nom que la cible existe dans la liste des arguments, la première dans la liste des arguments est utilisée.
-aide [option ...]
Donne des informations sur une option ou une liste d'options. Si aucune option n'est donnée, un simple outil d'aide interactif est lancé.
-identifier
Identifie les images fournies plutôt que de les afficher.
-installer
Installe de force la palette de couleurs de l'image lorsque la fenêtre a le focus. Ceci viole les normes ICCCM et n'existe que pour permettre le fonctionnement avec des gestionnaires de fenêtres naïfs. Utilisez cette option uniquement si votre gestionnaire de fenêtres n'installe pas correctement les palettes de couleurs.
-lister
Liste les images qui se trouvent le long du chemin des images.
-sur_racine
Charge l'(les) image(s) sur la fenêtre racine au lieu de les visualiser dans une fenêtre. Cette option active automatiquement l'option -adapter. C'est le contraire de -vue. XSetbg a cette option activée par défaut.
-chemin
Affiche des informations diverses sur la configuration du programme. Cette option est obsolète et a été remplacée par -configuration.
-pixmap
Force l'utilisation d'un pixmap comme stockage intermédiaire. Ceci est fourni pour les serveurs où le stockage intermédiaire est défectueux (comme certaines versions du serveur AIXWindows). Cela peut améliorer les performances de défilement sur les serveurs qui fournissent un stockage intermédiaire.
-privé
Force l'utilisation d'une palette de couleurs privée. Normalement, les couleurs sont allouées en partage à moins qu'il n'y ait pas assez de couleurs disponibles.
-silencieux
Force xloadimage et xview à être silencieux. C'est le défaut pour xsetbg, mais les autres aiment bien siffler.
-supporté
Liste les types d'images supportés.
-type type_name
Force xloadimage à essayer de charger l'image comme un type de fichier particulier plutôt que d'essayer de deviner. Cela améliore souvent considérablement les performances de chargement.
-verbose
Fait en sorte que xloadimage soit bavard, vous indiquant quel type d'image il traite et tout traitement spécial qu'il doit effectuer. C'est le comportement par défaut pour xview et xloadimage.
-version
Affiche le numéro de version et le niveau de correctif de cette version de xloadimage.
-view
Affiche l'image (ou les images) dans une fenêtre. C'est l'inverse de -onroot et le comportement par défaut pour xview et xloadimage.
-visual visual_name
Force l'utilisation d'un type visuel spécifique pour afficher une image. Normalement, xloadimage essaie de choisir la meilleure image disponible pour un type d'image particulier. Les types visuels disponibles sont : DirectColor, TrueColor, PseudoColor, StaticColor, GrayScale et StaticGray. Les noms qui ne créent pas de conflit peuvent être abrégés et la casse est ignorée.
-windowid hex_window_id
Définit le pixmap d'arrière-plan d'un identifiant de fenêtre particulier. L'argument doit être en hexadécimal et doit être précédé de "0x" (par ex. -windowid 0x40000b. Ceci est destiné à définir le pixmap d'arrière-plan de certains serveurs qui utilisent des racines virtuelles non étiquetées (par ex. HP-VUE), mais peut avoir d'autres applications intéressantes.

OPTIONS D'IMAGE

Les options suivantes peuvent précéder chaque image. Ces options sont locales à l'image qu'elles précèdent.

-at X,Y
Indique les coordonnées auxquelles charger l'image sur l'image de base. S'il s'agit d'une option pour la première image, et que l'option -onroot est spécifiée, l'image sera chargée à l'emplacement donné sur l'arrière-plan de l'affichage.
-background color
Utilise color comme couleur d'arrière-plan au lieu de la couleur par défaut (généralement blanc, mais cela dépend du type d'image) si vous transférez une image monochrome vers un écran couleur.
-brighten percentage
Spécifie un multiplicateur en pourcentage pour la table des couleurs d'une image couleur. Une valeur supérieure à 100 éclaircira une image, une valeur inférieure à 100 l'assombrira.
-center
Centre l'image sur l'image de base chargée. S'il s'agit d'une option pour la première image, et que l'option -onroot est spécifiée, l'image sera centrée sur l'arrière-plan de l'affichage.
-clip X,Y,W,H
Recadre l'image avant de la charger. X et Y définissent le coin supérieur gauche de la zone de recadrage, et W et H définissent les extensions de la zone. Une valeur zéro pour W ou H sera interprétée comme le reste de l'image.
-colors n
Spécifie le nombre maximum de couleurs à utiliser dans l'image. C'est une façon de réduire de force la profondeur d'une image.
-delay secs
Passe automatiquement à l'image suivante après secs secondes. Vous pourriez vouloir utiliser le commutateur -global avec cette commande pour créer un diaporama avec plusieurs images.
-dither
Applique un tramage à une image couleur pour la convertir en monochrome en utilisant un algorithme de tramage Floyd-Steinberg. Cela se produit par défaut lors de l'affichage d'images couleur sur un écran monochrome. C'est plus lent que -halftone et affecte la précision de l'image, mais cela rend généralement beaucoup mieux.
-foreground color
Utilise color comme couleur de premier plan au lieu de noir si vous transférez une image monochrome vers un écran couleur. Cela peut également être utilisé pour inverser les couleurs de premier plan et d'arrière-plan d'une image monochrome.
-gamma display_gamma
Spécifie la correction gamma pour l'affichage. La valeur par défaut est 1.0, un écran typique a besoin de 2.0 à 2.5.
-global
Force l'option suivante à s'appliquer à toutes les images plutôt qu'à une image spécifique. Les options d'image locales outrepasseront temporairement toute option spécifiée avec -global.
-gray
Convertit une image en niveaux de gris. Ceci est très utile lors de l'affichage d'images colorées sur des serveurs avec une capacité de couleur limitée. Il peut également être utilisé pour convertir une image bitmap en image en niveaux de gris, bien que l'image résultante soit plus petite que l'original. L'orthographe optionnelle -grey peut également être utilisée.
-halftone
Force le tramage d'une image couleur lors de l'affichage sur un écran monochrome. Cette option est ignorée pour les images monochromes. Cet algorithme de tramage agrandit une image par seize ; si vous n'aimez pas cela, l'option -dither n'agrandira pas l'image mais prendra plus de temps à traiter et sera moins précise.
-idelay secs
Cette option n'est plus prise en charge en raison de l'ajout de -global. La même fonctionnalité peut être obtenue avec -delay.
-invert
Inverse une image monochrome. C'est un raccourci pour -foreground white -background black.
-merge
Fusionne cette image sur l'image de base après traitement local. L'image de base est considérée comme la première image spécifiée ou la dernière image qui n'était pas précédée de -merge. Si utilisé conjointement avec -at et -clip, des images très complexes peuvent être construites. Cette option est activée par défaut pour toutes les images si les options -onroot ou -windowid sont spécifiées.
-name image_name
Force le prochain argument à être traité comme un nom d'image. Ceci est utile si le nom de l'image est par exemple -dither.
-newoptions
Réinitialise les options spécifiées globalement.
-normalize
Normalise une image couleur.
-rotate degrees
Fait pivoter l'image de degrees degrés dans le sens des aiguilles d'une montre. Le nombre doit être un multiple de 90.
-shrink
Réduit une image pour qu'elle tienne sur l'écran. Ceci est particulièrement utile avec les serveurs qui ne supportent pas les tailles de fenêtre supérieures à l'écran physique (par exemple, les serveurs DECWINDOWS).
-smooth
Lisse une image couleur. Cela réduit la pixellisation après avoir agrandi une image. Si utilisé sur une image monochrome, rien ne se passe. Cette option peut prendre du temps à s'exécuter, surtout sur de grandes images. Vous pouvez spécifier plusieurs options -smooth par image, ce qui provoque plusieurs itérations de l'algorithme de lissage.
-tile
Mosaïque cette image (après toute fusion ou mosaïque nécessaire) pour créer une image plein écran. Ceci est généralement utilisé pour créer une grande image d'arrière-plan sur laquelle fusionner d'autres images. -geometry peut être utilisé pour définir la nouvelle taille de l'image à autre chose que -fullscreen.
-title title
Change le titre de l'image. Ceci définit le titre de la barre de titre si l'affichage se fait dans une fenêtre ou le titre de l'image du fichier NIFF lors de l'exportation de l'image.
-xzoom percentage
Zoome l'axe X d'une image d'un pourcentage. Un nombre supérieur à 100 agrandira l'image, un plus petit la compressera. Une valeur zéro sera ignorée. Cette option, et la -yzoom associée, sont utiles pour corriger le rapport d'aspect des images à afficher.
-yzoom percentage
Zoome l'axe Y d'une image d'un pourcentage. Voir -xzoom pour plus d'informations.
-zoom percentage
Zoome les axes X et Y d'un pourcentage. Voir -xzoom pour plus d'informations. Techniquement, le pourcentage effectivement zoomé est le carré du nombre fourni car le zoom s'applique aux deux axes, mais j'ai opté pour la cohérence plutôt que pour la précision.

EXEMPLES

Pour charger le fichier raster "my.image" sur l'arrière-plan et le répliquer pour remplir tout l'arrière-plan :

xloadimage -onroot my.image

Pour centrer une image sur l'arrière-plan racine par défaut :

xloadimage -default -tile my.image

Si vous utilisez un écran monochrome et une image couleur, vous voudrez probablement tramé l'image pour un affichage plus propre (et plus rapide) :

xloadimage -default -tile -dither my.image

Pour charger une image monochrome "my.image" sur l'arrière-plan, en utilisant le rouge comme couleur de premier plan, répliquer l'image et superposer "another.image" dessus à la coordonnée (10,10) :

xloadimage -foreground red my.image -at 10,10 another.image

Pour centrer la région rectangulaire de 10 à 110 sur l'axe X et de 10 à la hauteur de l'image sur l'axe Y :

xloadimage -center -clip 10,10,100,0 my.image

Pour doubler la taille d'une image :

xloadimage -zoom 200 my.image

Pour réduire de moitié la taille d'une image :

xloadimage -zoom 50 my.image

Pour éclaircir une image sombre :

xloadimage -brighten 150 my.image

Pour assombrir une image claire :

xloadimage -brighten 50 my.image

CONSEILS POUR DE BONS AFFICHAGES D'IMAGES

Étant donné que les images proviennent probablement de diverses sources, elles peuvent avoir des rapports d'aspect variés qui ne sont peut-être pas pris en charge par votre écran. Les options -xzoom et -yzoom peuvent être utilisées pour modifier le rapport d'aspect d'une image avant l'affichage. Si vous utilisez ces options, il est recommandé d'augmenter la taille d'une des dimensions au lieu de réduire l'autre, car la réduction entraîne une perte d'informations.

ASTUCES POUR AMÉLIORER LES DÉTAILS

De nombreuses images GIF et G3 FAX ont un rapport X:Y d'environ 2:1. Vous pouvez corriger cela pour un affichage sur un écran 1:1 avec soit -xzoom 50 soit -yzoom 200 (réduire l'axe X à 50% de sa taille et agrandir l'axe Y à 200% de sa taille, respectivement), mais ce dernier doit être utilisé afin qu'aucun détail ne soit perdu lors de la conversion.

Lors de l'agrandissement d'images couleur, vous pouvez réduire le carré avec l'option -smooth. Pour des zooms de 300% ou plus, je recommande deux passes de lissage (bien que cela puisse prendre du temps sur des machines lentes). L'amélioration de l'image sera notable.

Vous pouvez effectuer un traitement d'image sur une petite partie d'une image en chargeant l'image plusieurs fois et en utilisant les options -merge, -at et -clip. Chargez l'image, puis fusionnez-la avec une version rognée et traitée d'elle-même. Pour éclaircir une portion rectangulaire de 100x100 d'une image située à (50,50), par exemple, vous pouvez taper :

xloadimage my.image -merge -at 50,50 -clip 50,50,100,100 -brighten 150 my.image

Si vous utilisez un écran avec une petite palette de couleurs pour afficher des images colorées, essayez d'utiliser l'option -gray pour convertir en niveaux de gris.

CHEMINS ET EXTENSIONS

Le fichier ~/.xloadimagerc (et éventuellement un fichier au niveau du système) définit un certain nombre d'options de configuration qui affectent xloadimage.

Ce fichier est divisé en trois sections : la section path, la section extension et la section filter. Les sections sont identifiées en tapant le nom de la section suivi d'un signe égal, par exemple "path =".

L'instruction path est utilisée pour fournir un ensemble de chemins de recherche à utiliser lors de la recherche d'une image d'un nom spécifié. Séparez chaque chemin de la liste par un espace blanc (par exemple, un ou plusieurs espaces, tabulations ou sauts de ligne). Le chemin est recherché dans l'ordre spécifié. Par exemple :

  path = ~/images /usr/local/images ~fred

recherchera d'abord le nom de l'image que vous avez spécifié, puis recherchera le nom dans ~/images (le tilde est développé à la valeur de $HOME), puis dans /usr/local/images, puis dans le répertoire personnel de l'utilisateur fred. Cela permet une utilisation facile des dépôts d'images.

L'instruction extension est utilisée pour fournir un ensemble d'extensions par défaut à utiliser lors de la recherche d'une image d'un nom spécifié. Séparez chaque extension de la liste par un espace blanc. Les extensions sont recherchées dans l'ordre dans lequel elles sont spécifiées. Par exemple :

  extension = .gif .jpg

Si vous avez un fichier nommé myimage.gif, vous pouvez spécifier le nom myimage et xloadimage ajoutera automatiquement l'extension .gif.

L'instruction filter est utilisée pour décrire des programmes de filtrage, tels que "uncompress", qui doivent être appliqués automatiquement aux fichiers image. Vous spécifiez un programme de filtrage et un nombre quelconque d'extensions reconnues suivant le mot-clé filter. Par exemple :

  filter = uncompress .Z

spécifie que le programme uncompress doit être utilisé comme filtre chaque fois qu'un fichier image a une extension .Z. Par défaut, des filtres sont fournis pour les fichiers compressés (.Z) et les fichiers GNU zip (.gz). Voir la section FILTERS pour plus d'informations sur la définition de vos propres filtres.

Tout texte sur une ligne suivant un dièse (#) est ignoré ; si vous souhaitez utiliser un dièse dans un chemin, une extension ou un filtre, vous pouvez l'échapper à l'aide d'une barre oblique inverse (\).

Si vous souhaitez inclure des espaces blancs dans le nom d'un programme de filtrage, un chemin ou une extension, vous pouvez entourer tout le texte de guillemets doubles. Par exemple :

  filter = "gzip -cd" .gz

Utilisez des caractères de barre oblique inverse (\) pour autoriser l'inclusion de guillemets doubles ou de sauts de ligne.

Voici un exemple de fichier ~/.xloadimagerc :

  # chemins pour rechercher les images
  path = /usr/local/images        # dépôt d'images système
        ~/images                 # images personnelles
        /usr/include/X11/bitmaps # bitmaps X standard
  # extensions par défaut pour les images
  extension = .csun .msun .sun .face .xbm .bm
  # invoquer GNU zip si une extension .z ou .zip est trouvée
  filter = "gzip -cd" .z .zip

TYPES D'IMAGES

Xloadimage prend actuellement en charge de nombreux types d'images courants et certains moins courants, et peut créer des images dans plusieurs formats. Pour une liste complète, utilisez l'option -supported.

SAUVEGARDE D'IMAGES

Plusieurs programmes de sauvegarde d'images sont inclus et peuvent être utilisés pour créer une nouvelle image après le chargement et le traitement. Le format NIFF (Native Image File Format) est le plus simple et crée des images que xloadimage peut lire le plus rapidement ; il s'agit essentiellement d'une copie du format d'image interne.

Certains programmes de sauvegarde d'images autorisent des options qui affectent la sortie de l'image. Ces options sont ajoutées au type d'image après une virgule et sont séparées par des virgules. Si une valeur est souhaitée, elle peut être spécifiée après un signe égal. Par exemple, pour créer un fichier image JPEG monochrome avec un facteur de qualité de 80, vous utiliseriez la ligne de commande suivante :

xloadimage image_name -dump jpeg,quality=80,grayscale new_image.jpg

Les noms d'options peuvent être abrégés mais si l'abréviation est trop courte pour être unique, l'option qui sera utilisée est indéterminée.

FILTRES

Xloadimage prend en charge le filtrage automatique en reconnaissant les extensions de fichiers. Par défaut, les fichiers "compress" et "gzip" sont reconnus et leurs noms sont transmis aux commandes appropriées pour les décompresser.

La distribution xloadimage comprend un décodeur uu spécial et "intelligent", appelé uufilter, qui peut être utilisé pour décoder automatiquement les fichiers uu pour traitement. Uufilter ignore les lignes superflues dans le fichier, il est donc particulièrement utile si le fichier uuencodé a été créé en concaténant des e-mails ou des publications de news qui contenaient des en-têtes ou des indicateurs de saut de ligne.

Pour utiliser uufilter, vous pouvez ajouter ce qui suit à votre fichier .xloadimagerc :

  filter = "uufilter -s" .uu .uue
Le filtre sera automatiquement invoqué sur tout fichier ayant une extension .uu ou .uue.

Pour une liste des filtres automatiquement reconnus par xloadimage, utilisez l'option -configuration.

OPTIONS D'IMAGE SUPPORTÉES

Le programme de sauvegarde d'images JPEG prend en charge les options suivantes :

arithmetic
Utiliser le codage arithmétique.
grayscale
Forcer la création d'une image monochrome (niveaux de gris) à partir d'une image couleur.
nointerleave
Créer un fichier non entrelacé.
optimize
Activer l'optimisation des paramètres d'entropie.
quality
Ajuster la qualité de l'image à créer. Le facteur de qualité par défaut est 75 ; des valeurs plus basses créent des images de moindre qualité.
restart interval
Définir l'intervalle de redémarrage en lignes MCU, ou MCU si 'b' suit la valeur de l'intervalle.
smooth smoothing_factor
Définir le facteur de lissage. La valeur doit être comprise entre 0 et 100, inclus.

Si vous n'êtes pas familier avec la signification de ces options, vous pouvez contacter le groupe Independent JPEG (IJG) par e-mail à jpeg@cs.columbia.edu.

Le programme de sauvegarde d'images PBM prend en charge les options suivantes :

normal
Sauvegarder un fichier PBM/PPM normal (ascii).
raw
Sauvegarder un fichier PBM/PPM au format RawBits. C'est le défaut et cela résulte en des fichiers image significativement plus petits qu'avec l'option normal.

Il n'y a aucun moyen de sauvegarder un fichier au format PGM ou un fichier PBM au format "compact" (désolé).

Le programme de sauvegarde d'images TIFF prend en charge les options suivantes :

compression
Technique de compression des données d'image. Peut être l'une des options suivantes : none (pas de compression), rle (compression CCITT RLE), g3fax (compression CCITT Group 3 FAX), g4fax (compression CCITT Group 4 FAX), lzw (compression Limpel-Ziv-Welsh, par défaut), jpeg (compression JPEG), next (compression run-length NeXT), rlew (compression CCITT RLEW), mac (compression Macintosh PackBits), packbits (identique à mac), thunderscan (compression ThunderScan).

Xloadimage sauvegardera en utilisant les photometric MINISBLACK, MINISWHITE, COLORMAP ou RGB selon ce qui est approprié pour son format d'image interne. Il n'y a aucun moyen de spécifier une photometric particulière ou tout autre champ TIFF.

HINTS FOR GOOD IMAGE DISPLAYS

xloadimage is an X11 application, so it obeys X11 conventions. See the X(7x) man page for more information.

The GIF format allows more than one image to be stored in a single GIF file, but xloadimage will only display the first.

Only GIF87a format is supported.

One of the pseudonyms for xloadimage, xview, is the same name as Sun uses for their SunView-under-X package. This will be confusing if you're one of those poor souls who has to use Sun's XView.

Some window managers do not correctly handle window size requests. In particular, many versions of the twm window manager use the MaxSize hint instead of the PSize hint, causing images which are larger than the screen to display in a window larger than the screen, something which is normally avoided. Some versions of twm also ignore the MaxSize argument's real function, to limit the maximum size of the window, and allow the window to be resized larger than the image. If this happens, xloadimage merely places the image in the upper-left corner of the window and uses the zero-value'ed pixel for any space which is not covered by the image. This behavior is less-than-graceful but so are window managers which are cruel enough to ignore such details.
