XFSCTL(3) Manuel des fonctions de bibliothèque XFSCTL(3)

NOM

xfsctl - contrôler les systèmes de fichiers XFS et les fichiers individuels

SYNOPSIS C

#include <xfs/xfs.h>

int xfsctl(const char *path, int fd, int cmd, void *ptr);

int platform_test_xfs_fd(int fd);
int platform_test_xfs_path(const char *path);

DESCRIPTION

Certaines fonctionnalités spécifiques au système de fichiers XFS sont accessibles aux applications via des interfaces d'appels système spécifiques à la plateforme. Ces opérations peuvent être divisées en deux sections - les opérations qui agissent sur des fichiers individuels et les opérations qui agissent sur le système de fichiers lui-même. Il faut prendre soin lors de l'émission d'appels xfsctl() pour s'assurer que le chemin cible et le descripteur de fichier (les deux doivent être fournis) représentent bien un fichier d'un système de fichiers XFS. Les appels système statfs(2) et fstatfs(2) peuvent être utilisés pour déterminer si un chemin d'accès arbitraire ou un descripteur de fichier appartiennent ou non à un système de fichiers XFS. Cependant, ceux-ci ne sont pas portables, donc les routines platform_test_xfs_fd() et platform_test_xfs_path() fournissent un mécanisme indépendant de la plateforme.

Opérations sur les fichiers

Pour effectuer une opération sur un fichier individuel, le nom de chemin et les arguments descripteurs passés à xfsctl identifient le fichier sur lequel l'opération est effectuée. Le dernier argument décrit ci-dessous fait référence au dernier argument de xfsctl. Toutes les structures de données et macros mentionnées ci-dessous sont définies dans le fichier d'en-tête <xfs/xfs_fs.h>.

XFS_IOC_ALLOCSP
XFS_IOC_ALLOCSP64
XFS_IOC_FREESP

XFS_IOC_FREESP64
Modifier l'espace de stockage associé à une section du fichier ordinaire spécifié. La section est spécifiée par une variable de type xfs_flock64_t, pointée par le dernier argument. Le type de données xfs_flock64_t contient les membres suivants : l_whence est 0, 1 ou 2 pour indiquer que le décalage relatif l_start sera mesuré à partir du début du fichier, de la position actuelle ou de la fin du fichier, respectivement (c'est-à-dire que l_start est le décalage par rapport à la position spécifiée dans l_whence). Si le décalage spécifié est antérieur à la fin actuelle du fichier, toute donnée précédemment écrite dans cette section n'est plus accessible. Si le décalage spécifié est au-delà de la fin actuelle du fichier, le fichier est agrandi et rempli de zéros. Le champ l_len est actuellement ignoré et doit être mis à zéro.

Les opérations XFS_IOC_ALLOCSP, XFS_IOC_ALLOCSP64, XFS_IOC_FREESP et XFS_IOC_FREESP64 sont toutes identiques.

Ces ioctls ne sont plus pris en charge depuis Linux 5.17.

XFS_IOC_FSSETDM
Définir les champs di_dmevmask et di_dmstate dans un inode XFS sur disque. Les seules valeurs légitimes pour ces champs sont celles précédemment retournées dans les champs bs_dmevmask et bs_dmstate de la structure bulkstat. Les données référencées par le dernier argument sont une struct fsdmidata. Les membres de cette structure sont fsd_dmevmask et fsd_dmstate. Le champ di_dmevmask est défini à la valeur de fsd_dmevmask. Le champ di_dmstate est défini à la valeur de fsd_dmstate. Cette commande est réservée à root ou aux processus ayant des capacités de gestion de périphériques. Son seul but est de permettre aux programmes de sauvegarde et de restauration de restaurer les champs critiques de l'inode sur disque mentionnés ci-dessus. Cet ioctl n'est pas pris en charge depuis Linux 5.5.
XFS_IOC_DIOINFO
Obtenir les informations nécessaires pour effectuer des E/S directes sur le descripteur de fichier spécifié. Les E/S directes sont effectuées directement depuis et vers un tampon de données utilisateur. Comme le cache de tampons du noyau n'est plus interposé, le tampon de données utilisateur doit respecter les mêmes contraintes que celles requises pour accéder à une partition disque brute. Le dernier argument pointe vers une variable de type struct dioattr, qui contient les membres suivants : d_mem est l'exigence d'alignement mémoire du tampon de données utilisateur. d_miniosz spécifie la taille du bloc, la taille minimale des requêtes d'E/S et l'alignement des E/S. La taille de toutes les requêtes d'E/S doit être un multiple de ce montant et la valeur du pointeur de recherche au moment de la requête d'E/S doit également être un multiple entier de ce montant. d_maxiosz est la taille maximale des requêtes d'E/S pouvant être effectuées sur le descripteur de fichier. Si une requête d'E/S ne respecte pas ces contraintes, la lecture (read(2)) ou l'écriture (write(2)) échouera avec EINVAL. Toutes les requêtes d'E/S restent cohérentes avec toute donnée amenée dans le cache par un accès via un descripteur de fichier non direct. 
XFS_IOC_FSGETXATTR
XFS_IOC_FSGETXATTRA
XFS_IOC_FSSETXATTR
Voir ioctl_xfs_fsgetxattr(2) pour plus d'informations. 
XFS_IOC_GETBMAP
XFS_IOC_GETBMAPA
XFS_IOC_GETBMAPX
Voir ioctl_getbmap(2) pour plus d'informations.

XFS_IOC_RESVSP

XFS_IOC_RESVSP64
Cette commande est utilisée pour allouer de l'espace à un fichier. Une plage d'octets est spécifiée à l'aide d'un pointeur vers une variable de type xfs_flock64_t dans le dernier argument. Les blocs sont alloués, mais pas mis à zéro, et la taille du fichier ne change pas. Si le système de fichiers XFS est configuré pour marquer les extensions de fichiers non écrites, les performances seront négativement affectées lors de l'écriture dans l'espace préalloué, car des transactions de système de fichiers supplémentaires sont requises pour convertir les drapeaux d'extension sur la plage du fichier écrite. Si xfs_info(8) signale unwritten=1, alors le système de fichiers a été configuré pour marquer les extensions non écrites.

XFS_IOC_UNRESVSP

XFS_IOC_UNRESVSP64
Cette commande est utilisée pour libérer de l'espace d'un fichier. Une plage d'octets est spécifiée à l'aide d'un pointeur vers une variable de type xfs_flock64_t dans le dernier argument. Les blocs partiels du système de fichiers sont mis à zéro, et les blocs complets du système de fichiers sont retirés du fichier. La taille du fichier ne change pas.
XFS_IOC_ZERO_RANGE
Cette commande est utilisée pour convertir une plage d'un fichier en zéros sans effectuer d'E/S de données. Une plage d'octets est spécifiée à l'aide d'un pointeur vers une variable de type xfs_flock64_t dans le dernier argument. Des blocs sont préalloués pour les régions qui traversent des trous dans le fichier, et toute la plage est convertie en extensions non écrites. Cette opération est une méthode rapide pour écraser toute donnée de la plage spécifiée avec des zéros sans supprimer de blocs ni avoir à écrire de zéros sur disque. Toute lecture ultérieure dans la plage donnée renverra des zéros jusqu'à ce que de nouvelles données soient écrites. Cette fonctionnalité nécessite que les systèmes de fichiers prennent en charge les extensions non écrites. Si xfs_info(8) signale unwritten=1, alors le système de fichiers a été configuré pour marquer les extensions non écrites. 
XFS_IOC_PATH_TO_HANDLE
XFS_IOC_PATH_TO_FSHANDLE
XFS_IOC_FD_TO_HANDLE
XFS_IOC_OPEN_BY_HANDLE
XFS_IOC_READLINK_BY_HANDLE
XFS_IOC_ATTR_LIST_BY_HANDLE
XFS_IOC_ATTR_MULTI_BY_HANDLE
XFS_IOC_FSSETDM_BY_HANDLE
Ce sont toutes des interfaces utilisées pour implémenter diverses fonctions libhandle (voir open_by_handle(3)). Elles sont toutes sujettes à modification et ne doivent pas être appelées directement par les applications. XFS_IOC_FSSETDM_BY_HANDLE n'est pas pris en charge depuis Linux 5.5.

Opérations sur le système de fichiers

Pour effectuer l'une des opérations suivantes, le nom de chemin et les arguments descripteurs passés à xfsctl() peuvent être n'importe quel fichier ouvert dans le système de fichiers XFS en question.

XFS_IOC_FSINUMBERS
Voir ioctl_xfs_fsinumbers(2) pour plus d'informations.
XFS_IOC_FSGEOMETRY
Voir ioctl_xfs_fsgeometry(2) pour plus d'informations.
XFS_IOC_AG_GEOMETRY
Voir ioctl_xfs_ag_geometry(2) pour plus d'informations.
XFS_IOC_FSBULKSTAT ou XFS_IOC_FSBULKSTAT_SINGLE
Voir ioctl_xfs_fsbulkstat(2) pour plus d'informations.
XFS_IOC_SCRUB_METADATA
Voir ioctl_xfs_scrub_metadata(2) pour plus d'informations.
XFS_IOC_FSCOUNTS
Voir ioctl_xfs_fscounts(2) pour plus d'informations.
XFS_IOC_GET_RESBLKS
XFS_IOC_SET_RESBLKS
Voir ioctl_xfs_getresblks(2) pour plus d'informations. Épargnez-vous beaucoup de frustration et évitez ces ioctls.
XFS_IOC_GOINGDOWN
Voir ioctl_xfs_goingdown(2) pour plus d'informations. 
XFS_IOC_THAW
XFS_IOC_FREEZE
XFS_IOC_FSGROWFSDATA
XFS_IOC_FSGROWFSLOG
XFS_IOC_FSGROWFSRT
Ces interfaces sont utilisées pour implémenter diverses opérations internes du système de fichiers sur les systèmes de fichiers XFS. Le reste de ces opérations ne sera pas décrit plus en détail car elles ne sont pas d'un usage général pour les applications.
