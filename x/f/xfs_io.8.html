xfs_io(8) Manuel de l'administrateur système xfs_io(8)

NOM

xfs_io - déboguer le chemin d'E/S d'un système de fichiers XFS

SYNTAXE

xfs_io [ -adfimrRstxT ] [ -c cmd ] ... [ -C cmd ] ... [ -p prog ] [ fichier ]
xfs_io -V

DESCRIPTION

xfs_io est un outil de débogage similaire à xfs_db(8), mais il est destiné à examiner les chemins d'E/S de fichiers ordinaires plutôt que le volume XFS brut lui-même. Ces chemins de code incluent non seulement les interfaces évidentes de lecture/écriture/mmap pour manipuler les fichiers, mais couvrent également toutes les extensions XFS (telles que la préallocation d'espace, les indicateurs d'inode supplémentaires, etc.).

OPTIONS

Les commandes xfs_io peuvent être exécutées en mode interactif (par défaut) ou comme arguments sur la ligne de commande. Le mode interactif exécute toujours les commandes sur le fichier ouvert actuel, tandis que les commandes exécutées depuis la ligne de commande peuvent être répétées sur tous les fichiers ouverts plutôt que sur le seul fichier ouvert actuel. En général, l'itération sur les fichiers ouverts se produira pour les commandes qui opèrent sur le contenu ou l'état du fichier. En revanche, les commandes qui opèrent sur l'état du système de fichiers ou à l'échelle du système ne seront exécutées que sur le fichier actuel, quelle que soit le nombre de fichiers ouverts. Plusieurs arguments peuvent être fournis sur la ligne de commande et ils sont exécutés dans l'ordre donné. Le programme se termine une fois que toutes les commandes ont été exécutées.

-c cmd
Exécute la commande spécifiée sur tous les fichiers actuellement ouverts. Pour maintenir la compatibilité avec l'usage historique, les commandes qui ne peuvent pas être exécutées sur tous les fichiers ouverts seront toujours exécutées mais uniquement une fois sur le fichier ouvert actuel. Plusieurs arguments -c peuvent être donnés et peuvent être entrelacés sur la ligne de commande dans n'importe quel ordre avec les commandes -C.
-C cmd
Exécute la commande spécifiée uniquement sur le fichier ouvert actuel. Plusieurs arguments -C peuvent être donnés et peuvent être entrelacés sur la ligne de commande dans n'importe quel ordre avec les commandes -c.
-p prog
Définit le nom du programme pour les invites et certains messages d'erreur, la valeur par défaut est xfs_io.
-f
Crée fichier s'il n'existe pas déjà.
-r
Ouvre fichier en lecture seule, initialement. Ceci est requis si fichier est immuable ou en mode ajout uniquement.
-i
Démarre un thread inactif. Le but de ce thread inactif est de tester les E/S provenant d'un processus multi-threadé. Avec un processus mono-threadé, la table des fichiers n'est pas partagée et les structures de fichiers ne sont pas comptées en références. Le lancement d'un thread inactif peut aider à détecter les fuites de comptage de références des structures de fichiers.
-x
Mode expert. Les commandes dangereuses ne sont disponibles que dans ce mode. Ces commandes ont également tendance à nécessiter des privilèges supplémentaires.
-V
Affiche le numéro de version et quitte.

Les autres options open(2) décrites ci-dessous sont également disponibles en ligne de commande.

CONCEPTS

xfs_io maintient un certain nombre de fichiers ouverts et de mappages mémoire. Les fichiers peuvent être ouverts initialement sur la ligne de commande (facultatif), et des fichiers supplémentaires peuvent également être ouverts plus tard.

Les commandes xfs_io peuvent être divisées en trois groupes. Certaines commandes visent à effectuer des E/S de fichiers ordinaires - lecture, écriture, synchronisation, préallocation d'espace, etc.

Le deuxième ensemble de commandes sert à manipuler les régions mémoire mappées d'un fichier - mappage, accès, stockage, démappage, vidage, etc.

Les commandes restantes sont destinées à la navigation et à l'affichage des structures de données relatives aux fichiers ouverts, aux mappages et aux systèmes de fichiers sur lesquels ils résident.

De nombreuses commandes disposent d'une aide en ligne étendue. Utilisez la commande help pour plus de détails sur n'importe quelle commande.

Cela permet à xfs_io de créer des discordances entre les permissions du fichier et le mode du descripteur de fichier ouvert en lecture/écriture pour tester les vérifications de permissions dans divers appels système.

-s

-b
utilisé pour définir la taille de bloc dans laquelle les requêtes d' write(2) seront divisées. La taille de bloc par défaut est de 4096 octets.
-S

-F

-B

-R

-Z semence

-V vecteurs

bmap [ -adelpv ] [ -n nx ]
Affiche le mappage des blocs pour le fichier actuellement ouvert. Reportez-vous à la page de manuel xfs_bmap(8) pour la documentation complète.
fiemap [ -alv ] [ -n nx ] [ decalage [ longueur ]]
Affiche le mappage des blocs pour le fichier actuellement ouvert en utilisant l'ioctl fiemap. Les options se comportent comme décrit dans la page de manuel xfs_bmap(8).
Optionnellement, cette commande prend également en charge le passage du décalage de départ à partir duquel commencer le mappage et la longueur de cette région. Le noyau renverra tous les extents complets qui intersectent la plage demandée, et la commande fiemap les affichera dans leur intégralité. Si la plage demandée commence ou se termine dans un trou, fiemap affichera le trou, tronqué à la plage demandée.
extsize [ -R | -D ] [ valeur ]
Affiche et/ou modifie la taille préférée des extents utilisée lors de l'allocation d'espace pour le fichier actuellement ouvert. Si l'option -R est spécifiée, une descente récursive est effectuée pour toutes les entrées de répertoire sous le fichier actuellement ouvert (-D peut être utilisé pour restreindre la sortie aux répertoires uniquement). Si le fichier cible est un répertoire, la taille de l'extent héritée est définie pour ce répertoire (les nouveaux fichiers créés dans ce répertoire héritent de cette taille d'extent). La valeur doit être spécifiée en octets, ou en utilisant l'une des suffixes d'unités habituels (k, m, g, b, etc.). La taille de l'extent est toujours rapportée en octets.
cowextsize [ -R | -D ] [ valeur ]
Affiche et/ou modifie la taille préférée des extents de copie sur écriture utilisée lors de l'allocation d'espace pour le fichier actuellement ouvert. Si l'option -R est spécifiée, une descente récursive est effectuée pour toutes les entrées de répertoire sous le fichier actuellement ouvert (-D peut être utilisé pour restreindre la sortie aux répertoires uniquement). Si le fichier cible est un répertoire, la taille de l'extent de copie sur écriture héritée est définie pour ce répertoire (les nouveaux fichiers créés dans ce répertoire héritent de cette taille d'extent de copie sur écriture). La valeur doit être spécifiée en octets, ou en utilisant l'une des suffixes d'unités habituels (k, m, g, b, etc.). La taille de l'extent est toujours rapportée en octets.
allocsp taille 0
Définit la taille du fichier à taille et met à zéro tout espace supplémentaire alloué en utilisant l'appel système XFS_IOC_ALLOCSP/XFS_IOC_FREESP décrit dans la page de manuel xfsctl(3). allocsp et freesp font exactement la même chose.

Ces commandes ne sont plus prises en charge à partir de Linux 5.17.

freesp taille 0

fadvise [ -r | -s | [[ -d | -n | -w ] decalage longueur ]]
Sur les plateformes qui le prennent en charge, permet de donner des indications au système concernant les motifs d'E/S attendus sur le fichier. Les arguments de plage sont requis par certaines commandes de conseil ([*] ci-dessous), et les autres ne doivent pas avoir d'arguments de plage. Sans arguments, le conseil POSIX_FADV_NORMAL est implicite (réadahead par défaut).
-d
les données ne seront plus accédées dans un futur proche (POSIX_FADV_DONTNEED[*]).
-n
les données seront consultées une fois et non réutilisées (POSIX_FADV_NOREUSE[*]).
-r
on s'attend à accéder aux données dans un ordre aléatoire (POSIX_FADV_RANDOM), ce qui définit le réadahead à zéro.
-s
on s'attend à accéder aux données dans un ordre séquentiel (POSIX_FADV_SEQUENTIAL), ce qui double le réadahead par défaut sur le fichier.
-w
indique que les données spécifiées seront à nouveau nécessaires (POSIX_FADV_WILLNEED[*]) ce qui force le réadahead maximal.
fdatasync
Appelle fdatasync(2) pour vider les données en mémoire du fichier sur le disque.
fsync
Appelle fsync(2) pour vider tout l'état en mémoire du fichier sur le disque.
s
Voir la commande fsync.

-a

-b
attend que les E/S dans la plage donnée se terminent avant l'écriture (SYNC_FILE_RANGE_WAIT_BEFORE).
-w
démarre la rétroaction des données sales dans la plage donnée (SYNC_FILE_RANGE_WRITE).
sync

finsert decalage longueur

Sur les plates-formes qui prennent en charge les options lseek(2) SEEK_DATA et SEEK_HOLE, affiche les décalages des segments spécifiés.

reflink [ -C ] [ -q ] src_file [src_offset dst_offset length]
Sur les systèmes de fichiers qui prennent en charge les ioctls FICLONERANGE ou BTRFS_IOC_CLONE_RANGE, mappe length octets à l'offset dst_offset dans le fichier ouvert aux mêmes blocs physiques que ceux mappés à l'offset src_offset dans le fichier src_file, en remplaçant tout contenu qui pourrait déjà s'y trouver. Si un programme écrit dans une plage de blocs reflinkée de l'un ou l'autre fichier, les blocs modifiés seront clonés, écrits et remappés ("copie à l'écriture") dans le fichier affecté, laissant les autres fichiers inchangés. Si src_offset, dst_offset et length sont omis, tout le contenu de src_file sera reflinké dans le fichier ouvert.
-C
Affiche les statistiques de temps dans un format condensé.
-q
N'affiche pas du tout les statistiques de temps.
dedupe [ -C ] [ -q ] src_file src_offset dst_offset length
Sur les systèmes de fichiers qui prennent en charge les ioctls FIDEDUPERANGE ou BTRFS_IOC_FILE_EXTENT_SAME, mappe length octets à l'offset dst_offset dans le fichier ouvert aux mêmes blocs physiques que ceux mappés à l'offset src_offset dans le fichier src_file, mais seulement si le contenu des deux plages est identique. C'est ce qu'on appelle la déduplication basée sur les blocs. Si un programme écrit dans une plage de blocs reflinkée de l'un ou l'autre fichier, les blocs modifiés seront clonés, écrits et remappés ("copie à l'écriture") dans le fichier affecté, laissant les autres fichiers inchangés.
-C
Affiche les statistiques de temps dans un format condensé.
-q
N'affiche pas du tout les statistiques de temps.
copy_range [ -s src_offset ] [ -d dst_offset ] [ -l length ] src_file | -f N
Sur les systèmes de fichiers qui prennent en charge l'appel système copy_file_range(2), copie des données du fichier source dans le fichier ouvert courant. La source doit être spécifiée soit par chemin (src_file), soit comme un autre fichier ouvert (-f). Si length n'est pas spécifié, cette commande copie les données de src_offset à la fin de src_file vers dst_file à dst_offset.
-s
Copie les données de src_file à partir de src_offset.
-d
Copie les données dans le fichier ouvert à partir de dst_offset.
-l
Copie jusqu'à length octets de données.
swapext donor_file
Échange les forks d'extension entre les fichiers. Le fichier ouvert courant est la cible. Le fichier donneur est spécifié par son chemin. Notez que les données du fichier ne sont pas copiées (le contenu du fichier se déplace avec le(s) fork(s)).
exchangerange [OPTIONS]donor_file
Échange le contenu entre les fichiers. Le fichier ouvert courant est la cible. Le fichier donneur est spécifié par son chemin. Notez que les données du fichier ne sont pas copiées (le contenu du fichier se déplace avec le(s) fork(s)). Les options incluent :
-C
Affiche les informations de temps dans un format condensé.
-c
Échange le contenu uniquement si file2 n'a pas changé.
-d dest_offset
Échange les extensions avec le fichier ouvert à partir de dest_offset.
-f
Force les données modifiées du fichier et les métadonnées du fichier sur disque.
-l length
Échange jusqu'à length octets de données.
-n
Effectue toutes les vérifications de validation des paramètres mais ne modifie rien.
-s src_offset
Échange les extensions avec le fichier donneur à partir de src_offset.
-t
Affiche les informations de temps.
-w
Échange uniquement les plages écrites dans le fichier fourni.
set_encpolicy [ -c mode ] [ -n mode ] [ -f flags ] [ -s log2_dusize ] [ -v version ] [ keyspec ]
Sur les systèmes de fichiers qui prennent en charge le chiffrement, assigne une politique de chiffrement au fichier courant. keyspec est une chaîne hexadécimale qui spécifie la clé de chiffrement à utiliser. Pour les politiques de chiffrement v1, keyspec doit être une chaîne hexadécimale de 16 caractères (8 octets). Pour les politiques v2, keyspec doit être une chaîne hexadécimale de 32 caractères (16 octets). Si non spécifié, une valeur de zéros est utilisée.
-c mode
mode de chiffrement du contenu (par exemple, AES-256-XTS)
-n mode
mode de chiffrement des noms de fichiers (par exemple, AES-256-CTS)
-f flags
drapeaux de politique (numérique)
-s log2_dusize
logarithme en base 2 de la taille de l'unité de données. Non pris en charge par les politiques v1.
-v version
version de la politique. Par défaut 1 ou 2 selon la longueur de keyspec ; ou 1 si keyspec n'est pas spécifié.
get_encpolicy [ -1 ] [ -t ]
Sur les systèmes de fichiers qui prennent en charge le chiffrement, affiche la politique de chiffrement du fichier courant.
-1
Utilise uniquement l'ancien ioctl pour obtenir la politique de chiffrement. Cela ne fonctionne que si le fichier a une politique de chiffrement v1.
-t
Teste si les politiques de chiffrement v2 sont prises en charge. Affiche "supported", "unsupport
ed", ou un message d'erreur.
add_enckey [ -d descripteur ] [ -k id_clé ]
Sur les systèmes de fichiers qui prennent en charge le chiffrement, ajoutez une clé de chiffrement au système de fichiers contenant le fichier actuellement ouvert. Par défaut, la clé brute en format binaire (généralement 64 octets) est lue depuis l'entrée standard.
-d descripteur
Descripteur de clé, sous forme d'une chaîne hexadécimale de 16 caractères (8 octets). S'il est fourni, la clé sera disponible pour les politiques de chiffrement v1 utilisant ce descripteur. Sinon, la clé est ajoutée comme clé de politique v2, et en cas de succès, l'"identifiant de clé" résultant sera affiché.
-k id_clé

COMMANDES D'E/S SUR MÉMOIRE MAPÉE

mmap [ N | [[ -rwxS ] [-s taille ] offset longueur ]]
Sans arguments, mmap affiche les mappings actuels. La spécification d'un argument numérique unique N définit le mapping courant. Si deux arguments sont spécifiés (une plage spécifiée par offset et longueur), un nouveau mapping est créé couvrant la plage, et le mode de protection peut être donné comme une combinaison de PROT_READ (-r), PROT_WRITE (-w) et PROT_EXEC (-x). Le mapping sera créé avec le flag MAP_SHARED par défaut, ou avec les flags spécifiques à Linux (MAP_SYNC | MAP_SHARED_VALIDATE) si -S est donné. -s taille est utilisé pour effectuer une opération mmap(taille) && munmap(taille) au début, essayer de réserver un espace mémoire libre extensible, si taille est plus grande que le paramètre longueur. Mais il n'y a aucune garantie que la mémoire après longueur (jusqu'à taille) restera libre. par ex. "mmap -rw -s 8192 1024" mappera 0 ~ 1024 octets de mémoire, mais essaiera de réserver 1024 ~ 8192 d'espace libre (sans garantie). Cet espace libre sera utile pour "mremap 8192" sans le flag MREMAP_MAYMOVE.

Voir la commande mmap.

Change la taille du mapping courant à nouvelle_longueur. Le fait que le mapping puisse être déplacé est contrôlé par les flags passés ; MREMAP_FIXED (-f), ou MREMAP_MAYMOVE (-m). nouvelle_longueur spécifie une adresse alignée sur page vers laquelle le mapping doit être déplacé. Elle peut être définie à 139946004389888, 4096k ou 1g, etc.

Voir la commande munmap.

Les deux modes verbeux diffèrent seulement par les offsets relatifs qu'ils affichent, l'option -f est relative au début du fichier, tandis que -v affiche les offsets relatifs au début du mapping.

Les stockages en mémoire sont effectués séquentiellement à partir de l'offset de départ par défaut, mais peuvent aussi être effectués de la fin vers l'arrière à travers le mapping si l'option -r est spécifiée.

Une deuxième option -v imprimera la légende des drapeaux. Cette option n'est pas compatible avec le drapeau -m.

Imprime l'UUID du système de fichiers monté.
sysfspath
Imprime le chemin sysfs ou debugfs pour le système de fichiers monté.

L'option -d sélectionne debugfs au lieu de sysfs.

getfsprops nom [ noms... ]
Récupère les valeurs des propriétés spécifiées du système de fichiers.
listfsprops [ -v ]
Liste toutes les propriétés du système de fichiers qui ont été stockées dans le système de fichiers. Si l'indicateur -v est spécifié, il imprime les valeurs des propriétés.
setfsprops nom=valeur [ nom=valeur... ]
Définit les propriétés spécifiées du système de fichiers aux valeurs indiquées.
removefsprops nom [ noms... ]
Supprime les propriétés spécifiées du système de fichiers.

dmsetup message périphérique 0 mark marque


lw
