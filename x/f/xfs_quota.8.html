NOM

xfs_quota - gère l'utilisation des quotas sur les systèmes de fichiers XFS

SYNTAXE

xfs_quota [ -x ] [ -f ] [ -p prog ] [ -c cmd ] ... [ -d projet ] ... [ -D fichier_projets ] [ -P fichier_projid ] [ chemin ... ]
xfs_quota -V

DESCRIPTION

xfs_quota est un utilitaire pour rapporter et éditer divers aspects des quotas de système de fichiers.

Les options de xfs_quota sont :

-c cmd
Les commandes de xfs_quota peuvent être exécutées de manière interactive (par défaut) ou comme arguments sur la ligne de commande. Plusieurs arguments -c peuvent être donnés. Les commandes sont exécutées dans l'ordre spécifié, puis le programme se termine.
-p prog
Définit le nom du programme pour les invites et certains messages d'erreur, la valeur par défaut est xfs_quota.
-x
Active le mode expert. Toutes les commandes administratives (voir la section COMMANDES ADMINISTRATEUR ci-dessous) qui permettent des modifications du système de quota ne sont disponibles qu'en mode expert.
-f
Active le mode système de fichiers étranger. Un nombre limité de commandes utilisateur et administratives sont disponibles pour une utilisation sur certains systèmes de fichiers étrangers (non-XFS).
-d projet
Les noms de projet ou les identifiants numériques peuvent être spécifiés avec cette option, ce qui restreint la sortie des commandes individuelles de xfs_quota à l'ensemble des projets spécifiés. Plusieurs arguments -d peuvent être donnés.
-D fichier_projets
Spécifie un fichier contenant la correspondance entre les identifiants de projet numériques et les arborescences de répertoires. /etc/projects par défaut, si cette option n'est pas présente.
-P fichier_projid
Spécifie un fichier contenant la correspondance entre les identifiants de projet numériques et les noms de projet. /etc/projid par défaut, si cette option n'est pas présente.
-V
Affiche le numéro de version et quitte.

L'argument facultatif chemin peut être utilisé pour spécifier des points de montage ou des fichiers de périphériques qui identifient les systèmes de fichiers XFS. La sortie des commandes individuelles de xfs_quota sera alors limitée à l'ensemble des systèmes de fichiers spécifiés.

Cette page de manuel est divisée en deux sections : d'abord, les informations pour les utilisateurs de systèmes de fichiers avec quotas activés, et les commandes xfs_quota qui intéressent ces utilisateurs ; ensuite, les informations utiles uniquement aux administrateurs de systèmes de fichiers XFS utilisant les quotas et les commandes de quota qui permettent les modifications du système de quotas.

Notez que les options communes à presque toutes les commandes individuelles décrites ci-dessous sont celles permettant de spécifier les types de quota qui intéressent : quota utilisateur (-u), quota groupe (-g), et/ou quota projet (-p). De plus, plusieurs commandes offrent des options pour opérer sur les "blocs utilisés" (-b), les "inodes utilisés" (-i), et/ou les "blocs temps réel utilisés" (-r).

De nombreuses commandes disposent également d'une aide en ligne complète. Utilisez la commande help pour plus de détails sur n'importe quelle commande.

APERÇU DES QUOTAS

Dans la plupart des environnements informatiques, l'espace disque n'est pas infini. Le sous-système de quotas fournit un mécanisme pour contrôler l'utilisation de l'espace disque. Les quotas peuvent être définis pour chaque utilisateur individuel sur n'importe quel/tous les systèmes de fichiers locaux. Le sous-système de quotas avertit les utilisateurs lorsqu'ils dépassent leur limite allouée, mais permet un peu d'espace supplémentaire pour le travail en cours (limite dure/limite souple). De plus, les systèmes de fichiers XFS avec la vérification des limites désactivée peuvent être utilisés comme un système de comptabilisation efficace de l'utilisation du disque.

Vue des quotas disque par les utilisateurs

Pour la plupart des utilisateurs, les quotas disque ne les concernent pas ou sont une réalité inévitable. Il existe deux quotas possibles qui peuvent être imposés : une limite peut être fixée sur la quantité d'espace qu'un utilisateur peut occuper, et il peut y avoir une limite sur le nombre de fichiers (inodes) qu'il peut posséder.

La commande quota fournit des informations sur les quotas définis par les administrateurs système et sur l'utilisation actuelle.

Il y a quatre nombres pour chaque limite : utilisation actuelle, limite souple (quota), limite dure et délai. La limite souple est le nombre de blocs de 1 Ko (ou de fichiers) que l'utilisateur est censé respecter. La limite dure ne peut pas être dépassée. Si l'utilisation d'un utilisateur atteint la limite dure, les demandes ultérieures d'espace (ou les tentatives de création d'un fichier) échouent avec l'erreur "Quota dépassé" (EDQUOT).

Lorsqu'un utilisateur dépasse la limite souple, le minuteur est activé. Chaque fois que le quota descend en dessous des limites souples, le minuteur est désactivé. Si le minuteur expire, la limite particulière qui a été dépassée est traitée comme si la limite dure avait été atteinte, et aucune autre ressource n'est allouée à l'utilisateur. La seule façon de réinitialiser cette condition, sans désactiver la vérification des limites ou augmenter la limite, est de réduire l'utilisation en dessous du quota. Seul le superutilisateur (c'est-à-dire un processus suffisamment capable) peut définir les limites de temps, et cela se fait par système de fichiers.

Survivre lorsque la limite de quota est atteinte

Dans la plupart des cas, le seul moyen pour un utilisateur de se remettre de conditions de dépassement de quota est d'interrompre toute activité en cours sur le système de fichiers qui a atteint sa limite, de supprimer suffisamment de fichiers pour ramener la limite en dessous du quota, et de réessayer le programme qui a échoué.
Cependant, si un utilisateur est dans l'éditeur et qu'une écriture échoue en raison d'une situation de dépassement de quota, ce n'est pas une solution appropriée. Il est fort probable que la première tentative d'écriture du fichier ait tronqué son contenu précédent, donc si l'éditeur est abandonné sans écrire correctement le fichier, non seulement les modifications récentes sont perdues, mais potentiellement une grande partie, voire la totalité, du contenu précédent.
Il existe plusieurs sorties possibles en toute sécurité pour un utilisateur pris dans cette situation. Ils peuvent utiliser la commande d'évasion de shell de l'éditeur pour examiner leur espace de fichiers et supprimer les fichiers excédentaires. Alternativement, en utilisant sh(1), ils peuvent suspendre l'éditeur, supprimer quelques fichiers, puis le reprendre. Une troisième possibilité est d'écrire le fichier sur un autre système de fichiers (peut-être dans un fichier sur /tmp) où le quota de l'utilisateur n'a pas été dépassé. Ensuite, après avoir rectifié la situation du quota, le fichier peut être déplacé vers le système de fichiers auquel il appartient.

Quotas par défaut

Le sous-système de quotas XFS permet d'appliquer un quota par défaut à tout utilisateur, groupe ou projet pour lequel aucune limite de quota explicite n'est définie. Ces limites sont stockées et affichées comme les limites de l'ID 0, bien qu'elles ne limitent pas réellement l'ID 0.

ADMINISTRATION DES QUOTAS

Le système de quotas XFS diffère de celui des autres systèmes de fichiers de plusieurs manières. Plus important encore, XFS considère les informations de quota comme des métadonnées du système de fichiers et utilise la journalisation pour fournir une garantie de cohérence plus élevée. En tant que tel, il est administré différemment, en particulier :

1.
La commande quotacheck n'a aucun effet sur les systèmes de fichiers XFS. La première fois que la comptabilisation des quotas est activée (au montage), XFS effectue automatiquement une vérification interne des quotas ; par la suite, le système de quotas sera toujours complètement cohérent jusqu'à ce que les quotas soient désactivés manuellement.
2.
Il n'est pas nécessaire d'avoir des fichiers de quota à la racine du système de fichiers XFS.
3.
XFS distingue la comptabilisation des quotas de l'application des limites. La comptabilisation des quotas doit être activée au moment du montage du système de fichiers XFS. Cependant, il est possible d'activer/désactiver l'application des limites à tout moment lorsque la comptabilisation des quotas est activée. L'option « quota » de la commande mount active à la fois la comptabilisation et l'application des quotas (utilisateur). L'option « uqnoenforce » doit être utilisée pour activer la comptabilisation utilisateur avec l'application des limites désactivée.
4.
L'activation des quotas sur le système de fichiers racine est légèrement différente de ce qui précède. Pour XFS sous Linux, les indicateurs de montage de quota doivent être transmis avec le paramètre de démarrage « rootflags= ».
5.
Il est utile d'utiliser state pour surveiller le sous-système de quotas XFS à différentes étapes - il peut être utilisé pour voir si les quotas sont activés, et aussi pour surveiller l'espace occupé par le système de quotas lui-même.
6.
Il existe un mécanisme intégré à xfsdump qui permet de sauvegarder les informations de limite de quota pour une restauration ultérieure, si le besoin s'en fait sentir.
7.
Les limites de quota ne peuvent pas être définies avant l'activation des quotas.
8.
Les systèmes de fichiers XFS maintiennent la comptabilisation des quotas pour le superutilisateur (ID utilisateur zéro) et l'outil affichera les informations d'utilisation du superutilisateur. Cependant, les limites ne sont jamais appliquées au superutilisateur (ni aux groupes et projets dont l'ID est zéro).
9.
Les systèmes de fichiers XFS effectuent la comptabilisation des quotas, que l'utilisateur ait des limites de quota ou non.
10.
XFS prend en charge la notion de quota projet, qui peut être utilisée pour implémenter une forme de quota d'arborescence de répertoires (c'est-à-dire restreindre une arborescence de répertoires à n'utiliser qu'une partie de l'espace disponible du système de fichiers ; ou simplement pour suivre l'espace utilisé, ou le nombre d'inodes, dans l'arborescence).

COMMANDES ADMINISTRATEUR

path [ N ]
Liste tous les chemins avec des périphériques/identifiants de projet ou définit le chemin actuel sur la N-ième entrée de la liste (le chemin actuel est utilisé par de nombreuses commandes décrites ici, il identifie le système de fichiers vers lequel une commande est dirigée). La liste des chemins peut provenir de plusieurs sources : la ligne de commande, la table de montage et le fichier /etc/projects.

report [ -gpu ] [ -bir ] [ -ahntlLNU ] [ -f fichier ]
Rapporte les informations de quota du système de fichiers. Ceci rapporte toute l'utilisation du quota pour un système de fichiers, pour le type de quota spécifié (u/g/p et/ou blocs/inodes/temps réel). Il rapporte les blocs par défaut en unités de 1 Ko. L'option -h affiche les informations dans un format « lisible par l'homme » similaire à la commande df(1). L'option -f envoie le rapport au fichier au lieu de stdout. L'option -a rapporte sur tous les systèmes de fichiers. Par défaut, affiche le nom de l'utilisateur/groupe/projet. Si aucun nom n'est défini pour un ID donné, affiche l'ID numérique à la place. L'option -n affiche l'ID numérique au lieu du nom. Les options -L et -U spécifient les bornes inférieure et/ou supérieure des ID à rapporter. Si des bornes supérieure/inférieure sont spécifiées, alors par défaut seuls les ID seront affichés ; avec l'option -l, une recherche sera effectuée pour traduire ces ID en noms. L'option -N rapporte les informations sans la ligne d'en-tête. L'option -t effectue un rapport succinct.

state [ -gpu ] [ -av ] [ -f fichier ]
Rapporte les informations globales sur l'état des quotas. Ceci rapporte l'état de la comptabilisation des quotas, de l'application des quotas, et le nombre d'étendues utilisées par les métadonnées de quota dans le système de fichiers. L'option -f envoie les informations d'état au fichier au lieu de stdout. L'option -a rapporte l'état sur tous les systèmes de fichiers et pas seulement sur le chemin actuel.

limit [ -g | -p | -u ] bsoft=N | bhard=N | isoft=N | ihard=N | rtbsoft=N | rtbhard=N -d | id | nom
Définit les limites de blocs de quota (bhard/bsoft), les limites de nombre d'inodes (ihard/isoft) et/ou les limites de blocs temps réel (rtbhard/rtbsoft) à N, où N est un nombre représentant des octets ou des inodes. Pour les limites de blocs, un nombre avec un suffixe multiplicateur s/b/k/m/g/t/p/e tel que décrit dans mkfs.xfs(8) est également accepté. Pour les limites d'inodes, aucun suffixe n'est autorisé. L'option -d (par défaut) peut être utilisée pour définir la valeur par défaut qui sera utilisée, sinon un nom ou un identifiant numérique spécifique d'utilisateur/groupe/projet doit être spécifié.

timer [ -g | -p | -u ] [ -bir ] valeur [ -d | id | nom ]
Permet de modifier le délai d'application des quotas (c'est-à-dire le temps accordé avant que les limites souples ne soient appliquées comme limites dures). Le délai d'application actuel peut être affiché à l'aide de la commande state.
Lors de la définition du délai par défaut via l'option -d, ou pour l'ID 0, ou si aucun argument n'est donné après valeur, l'argument valeur est un nombre de secondes indiquant le temps relatif après le dépassement des limites souples, avant que les limites dures ne soient appliquées.
Lors de la définition de tout autre délai individuel par id ou nom, la valeur est le nombre de secondes à partir de maintenant, auquel moment les limites dures seront appliquées. Cela permet d'étendre le délai de grâce d'un utilisateur individuel qui a dépassé les limites souples.
Pour valeur, les unités « minutes », « heures », « jours » et « semaines » sont également comprises (ainsi que leurs abréviations « m », « h », « j » et « s »).

warn [ -g | -p | -u ] [ -bir ] valeur -d | id | nom
Permet de visualiser et de modifier la limite d'avertissements de quota (c'est-à-dire le nombre de fois qu'un avertissement sera envoyé à quelqu'un en dépassement de quota). L'option -d (par défaut) peut être utilisée pour définir le temps par défaut qui sera utilisé, sinon un nom ou un identifiant numérique spécifique d'utilisateur/groupe/projet doit être spécifié. NOTE : cette fonctionnalité n'est pas implémentée actuellement.

enable [ -gpu ] [ -v ]
Active l'application des quotas pour le système de fichiers identifié par le chemin actuel. Cela nécessite que le système de fichiers ait été monté avec les quotas activés et que la comptabilisation soit actuellement active. L'option -v (verbeuse) affiche l'état après la fin de l'opération.
disable [ -gpu ] [ -v ]
Désactive l'application des quotas, tout en laissant la comptabilisation des quotas active. L'option -v (verbeuse) affiche l'état après la fin de l'opération.
off [ -gpu ] [ -v ]
Désactive définitivement les quotas pour le système de fichiers identifié par le chemin actuel. Les quotas ne peuvent être réactivés par la suite qu'en démontant puis en remontant.
remove [ -gpu ] [ -v ]
Supprime tout espace alloué aux métadonnées de quota du système de fichiers identifié par le chemin actuel. Les quotas ne doivent pas être activés sur le système de fichiers, sinon cette opération signalera une erreur.

dump [ -g | -p | -u ] [ -L | -U ] [ -f fichier ]
Extrait les informations de limite de quota pour les utilitaires de sauvegarde, soit vers la sortie standard (par défaut), soit vers un fichier. Les options -L et -U spécifient les bornes inférieure et/ou supérieure des ID à extraire. Il ne s'agit que des limites, pas des informations d'utilisation, bien entendu.

restore [ -g | -p | -u ] [ -f fichier ]
Restaure les limites de quota à partir d'un fichier de sauvegarde. Le fichier doit être dans le format produit par la commande dump.

quot [ -g | -p | -u ] [ -bir ] [ -acnv ] [ -f fichier ]
Résume la propriété du système de fichiers, par utilisateur, groupe ou projet. Cette commande utilise une interface spéciale XFS « bulkstat » pour scanner rapidement un système de fichiers entier et rapporter les informations d'utilisation. Cette commande peut être utilisée même lorsque les quotas du système de fichiers ne sont pas activés, car il s'agit d'un scan complet du système de fichiers (cela peut également prendre beaucoup de temps...). L'option -a affiche des informations sur tous les systèmes de fichiers. L'option -c affiche un histogramme au lieu d'un rapport. L'option -n affiche les ID numériques plutôt que les noms. L'option -v affiche des informations détaillées. L'option -f envoie la sortie au fichier au lieu de stdout.

project [ -cCs [ -d profondeur ] [ -p chemin ] id | nom ]
Les options -c, -C et -s permettent de maintenir le mécanisme de quota d'arborescence de répertoires. -d permet de limiter le niveau de récursion lors du traitement des répertoires de projets et -p permet de spécifier les chemins de projet à la ligne de commande (au lieu de /etc/projects). Toutes les options sont discutées en détail ci-dessous.

QUOTA D'ARBORESCENCE DE RÉPERTOIRE

Le mécanisme de quota de projet dans XFS peut être utilisé pour implémenter une forme de quota d'arborescence de répertoires, où un répertoire spécifié et tous les fichiers et sous-répertoires en dessous (c'est-à-dire une arborescence) peuvent être limités à l'utilisation d'une partie de l'espace disponible dans le système de fichiers.

xfs_quota(8) — XFS quotas

NAME

xfs_quota — report and administer filesystem quotas for XFS

SYNOPSIS

xfs_quota [ -x ] [ -c command ] [ -d max_depth ] [ -p project_path ] [ -v ] [ -V ] [ filesystem ... ]

DESCRIPTION

The xfs_quota utility is used to display and administer filesystem quotas for XFS filesystems. It supports user, group, and project quotas.

The following options are available:

-x
Enable expert mode. This is required for most administration commands. Some commands (like report) are available in both user and expert mode.
-c command
Execute a single command. This option can be specified multiple times to execute multiple commands. Each command is processed in order.
-d max_depth
Limit recursion depth for commands that descend directory trees, such as project -s. A value of -1 means infinite depth (default), 0 means top level only, 1 means first level and so on.
-p project_path
Specify project paths on the command line. This allows setting up project quotas without needing /etc/projects or /etc/projid to exist. If these files exist, they are also used.
-v
Verbose mode. Display more detailed information.
-V
Display version information and exit.

If no filesystem is specified, xfs_quota will attempt to operate on all mounted XFS filesystems for which quotas are enabled.

QUOTA OVERVIEW

Quotas are a mechanism for limiting filesystem resource consumption. XFS supports user quotas (limiting users), group quotas (limiting groups), and project quotas (limiting directory trees). Limits can be set as soft (graceful limits) or hard (absolute limits).

Quotas are enabled on a per-filesystem basis using the mount options usrquota (for user quotas), grpquota (for group quotas), or prjquota (for project quotas).

Quota information is stored in files within the filesystem's root directory, typically aquota.user, aquota.group, and aquota.project (for the new quota format).

USER COMMANDS

These commands can be run as a regular user (without the -x option).

report
Display current quota usage and limits. Can be used with or without -x. Without -x, it reports quotas only for the current user or group. With -x, it reports quotas for all users and groups, and projects.

QUOTA ADMINISTRATION

These commands require the -x option.

limit
Set or modify quota limits. Usage: limit [-u|g|p] limit_spec name. limit_spec can be bslimit=, bsoftlimit=, hardlimit=, grace=, inodeslimit=, softlimit=, projectlimit=. -u applies to users, -g to groups, -p to projects.
disable
Disable quotas for a specified user, group, or project.
enable
Enable quotas for a specified user, group, or project.
remove
Remove quota limits for a specified user, group, or project.
reconcile
Reconcile filesystem quota usage with actual disk usage. This can be time-consuming and should be run when the filesystem is quiescent.

ADMINISTRATOR COMMANDS

state
Display current quota state information.
off
Turn off disk quota enforcement for the specified filesystem.
on
Turn on disk quota enforcement for the specified filesystem. This initializes the quota files if they do not exist.
writeall
Force update of quota information in the quota files for all users, groups, and projects.
print
Print quota information in a machine-readable format.

DIRECTORY TREE QUOTA

Project quotas allow for limiting resources associated with specific directory trees. To use project quotas, the filesystem must be mounted with the prjquota option.

Project identifiers (numeric) are mapped to project names and directory trees in /etc/projects and /etc/projid.

A managed tree must be setup initially using the -s option to the project command. The specified project name or identifier is matched to one or more trees defined in /etc/projects, and these trees are then recursively descended to mark the affected inodes as being part of that tree. This process sets an inode flag and the project identifier on every file in the affected tree. Once this has been done, new files created in the tree will automatically be accounted to the tree based on their project identifier. An attempt to create a hard link to a file in the tree will only succeed if the project identifier matches the project identifier for the tree. The xfs_io utility can be used to set the project ID for an arbitrary file, but this can only be done by a privileged user.

A previously setup tree can be cleared from project quota control through use of the project -C option, which will recursively descend the tree, clearing the affected inodes from project quota control.

Finally, the project -c option can be used to check whether a tree is setup, it reports nothing if the tree is correct, otherwise it reports the paths of inodes which do not have the project ID of the rest of the tree, or if the inode flag is not set.

Option -d can be used to limit recursion level (-1 is infinite, 0 is top level only, 1 is first level ... ). Option -p adds possibility to specify project paths in command line without a need for /etc/projects to exist. Note that if projects file exists then it is also used.

EXAMPLES

Enabling quota enforcement on an XFS filesystem (restrict a user to a set amount of space).

# mount -o uquota /dev/xvm/home /home
# xfs_quota -x -c 'limit bsoft=500m bhard=550m tanya' /home
# xfs_quota -x -c report /home

Enabling project quota on an XFS filesystem (restrict files in log file directories to only using 1 gigabyte of space).

# mount -o prjquota /dev/xvm/var /var
# echo 42:/var/log >> /etc/projects
# echo logfiles:42 >> /etc/projid
# xfs_quota -x -c 'project -s logfiles' /var
# xfs_quota -x -c 'limit -p bhard=1g logfiles' /var

Same as above without a need for configuration files.

# rm -f /etc/projects /etc/projid
# mount -o prjquota /dev/xvm/var /var
# xfs_quota -x -c 'project -s -p /var/log 42' /var
# xfs_quota -x -c 'limit -p bhard=1g 42' /var

CAVEATS

The XFS allocation mechanism will always reserve the maximum amount of space required before proceeding with an allocation. If insufficient space for this reservation is available, due to the block quota limit being reached for example, this may result in the allocation failing even though there is sufficient space. Quota enforcement can thus sometimes happen in situations where the user is under quota and the end result of some operation would still have left the user under quota had the operation been allowed to run its course. This additional overhead is typically in the range of tens of blocks.

Both of these properties are unavoidable side effects of the way XFS operates, so should be kept in mind when assigning block limits.

BUGS

Quota support for filesystems with realtime subvolumes is not yet implemented, nor is the quota warning mechanism (the Linux warnquota(8) tool can be used to provide similar functionality on that platform).
