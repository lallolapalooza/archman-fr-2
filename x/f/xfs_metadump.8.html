NOM

xfs_metadump - copier les métadonnées du système de fichiers XFS dans un fichier

SYNTAXE

xfs_metadump [ -aefFgow ] [ -m max_extents ] [ -l logdev ] [ -r rtdev ] [ -v version ] source cible
xfs_metadump -V

DESCRIPTION

xfs_metadump est un outil de débogage qui copie les métadonnées d'un système de fichiers XFS dans un fichier. L'argument source doit être le chemin d'accès du périphérique ou du fichier contenant le système de fichiers XFS et l'argument cible spécifie le nom du fichier de destination. Si cible est -, alors la sortie est envoyée vers stdout. Cela permet de rediriger la sortie vers un autre programme tel qu'une application de compression.

xfs_metadump ne peut être utilisé que pour copier des systèmes de fichiers non montés, ou des systèmes de fichiers montés en lecture seule.

xfs_metadump ne modifie en aucun cas le système de fichiers source. L'image cible est un fichier contigu (non éparse) contenant toutes les métadonnées et index du système de fichiers vers lesquels les blocs ont été copiés.

Par défaut, xfs_metadump obfusque la plupart des noms de fichiers (fichier régulier, répertoire et lien symbolique) et des noms d'attributs étendus afin de permettre l'envoi des dumps sans révéler d'informations confidentielles. Les valeurs des attributs étendus sont mises à zéro et aucune donnée n'est copiée. Les seules exceptions sont les noms de fichiers ou d'attributs de 4 caractères ou moins. Les noms de fichiers qui s'étendent sur plusieurs extents (cela ne peut arriver qu'avec les options mkfs.xfs(8) où -n taille > -b taille) ne sont pas obfusqués. Les noms entre 5 et 8 caractères inclus sont partiellement obfusqués.

xfs_metadump ne peut pas obfusquer les métadonnées dans le journal du système de fichiers. La récupération du journal d'une image metadump obfusquée peut exposer des métadonnées en texte clair et/ou causer une corruption du système de fichiers dans l'image restaurée. Il est recommandé de monter puis démonter d'abord le système de fichiers source, si possible, pour s'assurer que le journal est propre. Une invocation ultérieure de xfs_metadump capturera un journal propre et obfusquera toutes les métadonnées correctement.

Si un metadump doit être produit à partir d'un système de fichiers avec un journal sale, il est recommandé de désactiver l'obfuscation avec l'option -o, si les métadonnées telles que les noms de fichiers ne sont pas considérées comme sensibles. Si l'obfuscation est requise sur un metadump avec un journal sale, veuillez en informer le destinataire de l'image metadump à ce sujet.

Le contenu d'un périphérique de journal externe ne peut être dumpé que lorsque le format v2 est utilisé. Metadump au format v2 peut être généré en passant l'option "-v 2". Metadump au format v2 est généré par défaut si le système de fichiers possède un journal externe et que la version de metadump à utiliser n'est pas explicitement mentionnée.

xfs_metadump ne doit pas être utilisé à d'autres fins que le débogage et le signalement de problèmes de système de fichiers. Le scénario d'utilisation le plus courant pour cet outil est lorsque xfs_repair(8) échoue à réparer un système de fichiers et qu'une image metadump peut être envoyée pour analyse.

Le fichier généré par xfs_metadump peut être restauré dans une image de système de fichiers (sans les données) en utilisant l'outil xfs_mdrestore(8).

OPTIONS

-a
Copie les blocs de métadonnées entiers. Normalement, xfs_metadump mettra à zéro les octets obsolètes dispersés parmi les métadonnées en cours d'utilisation. Utilisez cette option pour copier des blocs de métadonnées complets, afin de fournir plus d'informations de débogage pour un système de fichiers corrompu. Notez que les données supplémentaires ne seront pas obfusquées.
-e
Arrête le dump en cas d'erreur de lecture. Normalement, il ignorera les erreurs de lecture et copiera toutes les métadonnées accessibles.
-f
Spécifie que l'image du système de fichiers à traiter est stockée dans un fichier régulier (voir l'option de fichier mkfs.xfs -d). Cela peut également se produire si une copie image d'un système de fichiers a été faite dans un fichier ordinaire avec xfs_copy(8).
-F
Spécifie que nous voulons continuer même si le magic du superbloc n'est pas correct. Si la source n'est vraiment pas un système de fichiers XFS, l'image résultante sera inutile, et xfs_metadump pourrait planter.
-g
Affiche la progression du dump. Ceci est envoyé vers stdout si la cible est un fichier, ou vers stderr si la cible est stdout.
-l logdev
Pour les systèmes de fichiers qui utilisent un journal externe, cela spécifie le périphérique où réside le journal externe. Si le format metadump v2 est sélectionné, le contenu du journal externe sera copié dans le metadump. Le format metadump v2 sera sélectionné automatiquement si cette option est spécifiée.
-m
Définit la taille maximale d'un extent de métadonnées autorisé. Les extents de métadonnées extrêmement volumineux sont susceptibles d'être corrompus et seront ignorés s'ils dépassent cette valeur. La taille par défaut est de 2097151 blocs.
-o
Désactive l'obfuscation des noms de fichiers et des attributs étendus.
-r rtdev
Pour les systèmes de fichiers qui ont une section temps réel, cela spécifie le périphérique où réside la section temps réel. Si le format metadump v2 est sélectionné, les superblocs de groupe temps réel seront copiés dans le metadump. Le format metadump v2 sera sélectionné automatiquement si le système de fichiers contient des groupes temps réel.
-v
Le format du fichier metadump à produire. Les valeurs valides sont 1 et 2. Le format metadump par défaut est 1.
-w
Imprime les avertissements de métadonnées incohérentes rencontrées sur stderr. Les métadonnées incorrectes sont quand même copiées.
-V
Imprime le numéro de version et quitte.

DIAGNOSTICS

xfs_metadump retourne un code de sortie de 0 si toutes les métadonnées lisibles ont été copiées avec succès, ou 1 si une erreur d'écriture se produit ou si une erreur de lecture se produit et que l'option -e est utilisée.

NOTES

Comme xfs_metadump ne copie que les métadonnées, peu importe que le système de fichiers source ait une section temps réel ou non. Si le système de fichiers possède un journal externe, il n'est pas copié. Les journaux internes sont copiés et les transactions de journal en attente ne sont pas obfusquées si elles contiennent des noms.

xfs_metadump est un wrapper shell autour de la commande xfs_db(8) metadump.

VOIR AUSSI

NOM

xfs_metadump — Sauvegarde de métadonnées XFS

SYNOPIS

xfs_metadump [ options ] disque [ fichier_sortie ]

DESCRIPTION

xfs_metadump est un utilitaire de diagnostic XFS qui sauvegarde la structure des métadonnées d'un système de fichiers XFS sur un fichier. Cela est utile pour analyser les corruptions de système de fichiers, car cela capture l'état exact des métadonnées au moment de l'exécution.

L'argument disque est le périphérique de bloc qui contient le système de fichiers XFS. S'il n'est pas spécifié, xfs_metadump tentera de le lire depuis l'entrée standard.

L'argument fichier_sortie est le chemin du fichier dans lequel les métadonnées seront écrites. S'il n'est pas spécifié, xfs_metadump écrira dans la sortie standard.

xfs_metadump ne doit pas être exécuté sur un système de fichiers monté, car cela pourrait entraîner des incohérences dans les métadonnées sauvegardées.

OPTIONS

-c, --cpu-cores nombre
Spécifie le nombre de cœurs de processeur à utiliser pour la sauvegarde. Par défaut, il utilise tous les cœurs disponibles.
-v, --verbose
Active la sortie verbeuse.
-p, --progress
Affiche la progression de la sauvegarde.
-d, --debug
Active la sortie de débogage.
-o, --offset octet
Spécifie un décalage en octets depuis le début du périphérique où commencer la sauvegarde.
-s, --size octet
Spécifie la taille en octets du dump. Par défaut, il tente de sauvegarder tout le système de fichiers.

DIAGNOSTICS

Les erreurs sont signalées sur la sortie d'erreur standard. Les codes de sortie sont :

0
Succès.
1
Erreur générale.
2
Erreur d'argument.
3
Erreur d'ouverture de périphérique.
4
Erreur de lecture de périphérique.
5
Erreur d'écriture de fichier.

NOTES

Il est fortement recommandé de démonter le système de fichiers XFS avant d'exécuter xfs_metadump. Si le système de fichiers ne peut pas être démonté, assurez-vous qu'il est en lecture seule et qu'aucun processus n'écrit dessus.
