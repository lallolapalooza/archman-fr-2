xfs(5) Formats de fichiers xfs(5)

NOM

xfs - disposition, options de montage et attributs de fichiers pris en charge pour le système de fichiers XFS

DESCRIPTION

Un système de fichiers XFS peut résider sur une partition de disque normale ou sur un volume logique. Un système de fichiers XFS comporte jusqu'à trois parties : une section de données, une section de journal et une section temps réel. En utilisant les options par défaut de mkfs.xfs(8), la section temps réel est absente et la zone de journal est contenue dans la section de données. La section de journal peut être soit séparée de la section de données, soit contenue à l'intérieur de celle-ci. Les sections du système de fichiers sont divisées en un certain nombre de blocs, dont la taille est spécifiée lors de l'exécution de mkfs.xfs(8) avec l'option -b.

La section de données contient toutes les métadonnées du système de fichiers (inodes, répertoires, blocs indirects) ainsi que les données des fichiers utilisateur pour les fichiers ordinaires (non temps réel) et la zone de journal si le journal est interne à la section de données. La section de données est divisée en un certain nombre de groupes d'allocation. Le nombre et la taille des groupes d'allocation sont choisis par mkfs.xfs(8) de sorte qu'il y ait normalement un petit nombre de groupes de taille égale. Le nombre de groupes d'allocation contrôle le parallélisme disponible dans l'allocation de fichiers et de blocs. Il doit être augmenté par rapport à la valeur par défaut s'il y a suffisamment de mémoire et une forte activité d'allocation. Le nombre de groupes d'allocation ne doit pas être très élevé, car cela peut entraîner une utilisation importante du temps CPU par le système de fichiers, en particulier lorsqu'il est presque plein. D'autres groupes d'allocation sont ajoutés (de la taille d'origine) lorsque xfs_growfs(8) est exécuté.

La section de journal (ou zone, si elle est interne à la section de données) est utilisée pour stocker les modifications apportées aux métadonnées du système de fichiers pendant son fonctionnement, jusqu'à ce que ces modifications soient appliquées à la section de données. Elle est écrite séquentiellement en fonctionnement normal et lue uniquement lors du montage. Lors du montage d'un système de fichiers après un crash, le journal est lu pour terminer les opérations en cours au moment du crash.

La section temps réel est utilisée pour stocker les données des fichiers temps réel. Ces fichiers avaient un bit d'attribut défini via xfsctl(3) après la création du fichier, avant que toute donnée ne soit écrite dans le fichier. La section temps réel est divisée en un certain nombre d'étendues de taille fixe (spécifiée lors de l'exécution de mkfs.xfs(8)). Chaque fichier dans la section temps réel a une taille d'étendue qui est un multiple de la taille d'étendue de la section temps réel.

Chaque groupe d'allocation contient plusieurs structures de données. Le premier secteur contient le superbloc. Pour les groupes d'allocation autres que le premier, le superbloc n'est qu'une copie et n'est pas mis à jour après l'exécution de mkfs.xfs(8). Les trois secteurs suivants contiennent des informations pour l'allocation des blocs et des inodes au sein du groupe d'allocation. Sont également contenus dans chaque groupe d'allocation des structures de données pour localiser les blocs et les inodes libres ; celles-ci sont accessibles via les structures d'en-tête.

Chaque système de fichiers XFS est étiqueté avec un Identificateur Universel Unique (UUID). L'UUID est stocké dans chaque en-tête de groupe d'allocation et sert à distinguer un système de fichiers XFS d'un autre. Par conséquent, vous devez éviter d'utiliser dd(1) ou d'autres programmes de copie bloc par bloc pour copier des systèmes de fichiers XFS. Si deux systèmes de fichiers XFS sur la même machine ont le même UUID, xfsdump(8) peut être confus lors des sauvegardes incrémentielles et reprises. xfsdump(8) et xfsrestore(8) sont recommandés pour faire des copies de systèmes de fichiers XFS. Pour monter un instantané d'un système de fichiers déjà monté, vous devrez peut-être fournir l'option nouuid à mount(8).

OPÉRATIONS

Certaines fonctionnalités spécifiques au système de fichiers XFS sont accessibles aux applications via les interfaces xfsctl(3) et by-handle (voir open_by_handle(3)).

OPTIONS DE MONTAGE

Les options de montage XFS spécifiques suivantes peuvent être utilisées lors du montage d'un système de fichiers XFS. D'autres options génériques peuvent également être utilisées ; référez-vous à la page de manuel mount(8) pour plus de détails.

allocsize=taille
Définit la taille de préallocation de fin de fichier pour les E/S bufferisées lors de l'écriture différée d'allocation. Les valeurs valides pour cette option vont de la taille de page (typiquement 4 kio) jusqu'à 1 Gio, incluses, par incréments de puissance de 2.

Le comportement par défaut est une taille de préallocation de fin de fichier dynamique, qui utilise un ensemble d'heuristiques pour optimiser la taille de préallocation en fonction des schémas d'allocation actuels dans le fichier et des schémas d'accès au fichier. La spécification d'une valeur fixe pour allocsize désactive le comportement dynamique.

attr2|noattr2
Remarque : Ces options ont été dépréciées à partir du noyau v5.10 ; l'option noattr2 sera supprimée au plus tôt en septembre 2025 et l'option attr2 sera une valeur par défaut immuable.

Ces options activent/désactivent une amélioration « opportuniste » dans la manière dont les attributs étendus en ligne sont stockés sur disque. Lorsque le nouveau format est utilisé pour la première fois lorsque attr2 est sélectionné (soit lors de la définition, soit lors de la suppression d'attributs étendus), le champ de bit de fonctionnalité du superbloc sur disque sera mis à jour pour refléter que ce format est utilisé.

Le comportement par défaut est déterminé par le bit de fonctionnalité sur disque indiquant que le comportement attr2 est actif. Si l'une des options de montage est définie, elle devient le nouveau comportement par défaut utilisé par le système de fichiers.

Les systèmes de fichiers activés pour CRC utilisent toujours le format attr2 et rejetteront donc l'option de montage noattr2 si elle est définie.

dax=valeur
Définit le comportement d'accès direct CPU (DAX) pour le système de fichiers actuel. Cette option de montage accepte les valeurs suivantes :

« dax=inode » DAX sera activé uniquement sur les fichiers réguliers avec FS_XFLAG_DAX appliqué.

« dax=never » DAX ne sera activé pour aucun fichier. FS_XFLAG_DAX sera ignoré.

« dax=always » DAX sera activé pour tous les fichiers réguliers, quel que soit l'état de FS_XFLAG_DAX.

Si aucune option n'est utilisée lors du montage d'un système de fichiers stocké sur un périphérique compatible DAX, dax=inode sera utilisé par défaut.

Pour plus de détails sur le comportement DAX dans le noyau, veuillez consulter la documentation du noyau à l'adresse filesystems/dax.txt.

discard|nodiscard
Active/désactive l'émission de commandes pour permettre au périphérique bloc de récupérer l'espace libéré par le système de fichiers. Ceci est utile pour les périphériques SSD, les LUNs provisionnés de manière fine et les images de machines virtuelles, mais peut avoir un impact sur les performances.

Remarque : Il est actuellement recommandé d'utiliser l'application fstrim pour supprimer les blocs inutilisés plutôt que l'option de montage discard, car l'impact sur les performances de cette option est assez sévère. Pour cette raison, nodiscard est la valeur par défaut.

grpid|bsdgroups|nogrpid|sysvgroups
Ces options définissent l'ID de groupe qu'un fichier nouvellement créé reçoit. Lorsque grpid est défini, il prend l'ID de groupe du répertoire dans lequel il est créé ; sinon, il prend le fsgid du processus actuel, à moins que le répertoire ait le bit setgid défini, auquel cas il prend le gid du répertoire parent, et reçoit également le bit setgid s'il s'agit d'un répertoire lui-même.
filestreams
Fait en sorte que l'allocateur de données utilise le mode d'allocation filestreams sur l'ensemble du système de fichiers plutôt que uniquement sur les répertoires configurés pour l'utiliser.
ikeep|noikeep
Remarque : Ces options ont été dépréciées à partir du noyau v5.10 ; l'option noikeep sera supprimée au plus tôt en septembre 2025 et l'option ikeep sera une valeur par défaut immuable.

Lorsque ikeep est spécifié, XFS ne supprime pas les clusters d'inodes vides et les conserve sur disque. Lorsque noikeep est spécifié, les clusters d'inodes vides sont retournés au pool d'espace libre. noikeep est la valeur par défaut.

inode32|inode64
Lorsque inode32 est spécifié, il indique que XFS limite la création d'inodes aux emplacements qui ne résulteront pas en des numéros d'inodes de plus de 32 bits.

xfs(5) — Manuel XFS

NAME

xfs — XFS filesystem constants and attributes

DESCRIPTION

The XFS filesystem is a high-performance journaling file system. This man page describes various constants, attributes and mount options related to XFS.

OPERATIONS

The XFS filesystem supports the following operations via the xfsctl(3) interface. These operations are not mount options, but rather operations that can be performed on an open file.

XFS_IOC_ATTR_REMOVE
Remove extended attributes from a file.
XFS_IOC_ATTR_SET
Set extended attributes on a file.
XFS_IOC_ATTR_LIST
List extended attributes on a file.
XFS_IOC_ZERO_RANGE
Deallocate a range of blocks in a file. This operation is equivalent to the fallocate(1) command with the --punch-hole option.
XFS_IOC_UNSHARE_ILOCK
Remove the i_shared flag from an inode. This is not generally useful except in specific testing scenarios.
XFS_IOC_IGET_SPECIFIC
Get a specific inode by its inode number.
XFS_IOC_FSGEOMETRY
Get filesystem geometry information.
XFS_IOC_BIGTIME
Enable the use of 64-bit timestamps for files. This is the default for newly created filesystems.
XFS_IOC_SWAPVTOC
Swap the primary and alternate volume table of contents. This is useful for filesystem recovery.

MOUNT OPTIONS

The following options can be specified to the mount command when mounting an XFS filesystem.

allocsize=value
Set the filesystem page size. This value must be a power of 2, and must be between 4 KiB and 1 GiB. The default is 64 KiB. This option is only relevant for filesystems created with an explicit page size.
integrity|nointegrity
Enable or disable data and metadata checksumming. If "nointegrity" is specified, then data and metadata checksumming are disabled. If "integrity" is specified, then data and metadata checksumming are enabled. The default behavior depends on how the filesystem was created.
inode32|inode64

When inode64 is specified, it indicates that XFS is allowed to create inodes at any location in the filesystem, including those which will result in inode numbers occupying more than 32 bits of significance.

inode32 is provided for backwards compatibility with older systems and applications, since 64 bits inode numbers might cause problems for some applications that cannot handle large inode numbers. If applications are in use which do not handle inode numbers bigger than 32 bits, the inode32 option should be specified.

For kernel v3.7 and later, inode64 is the default.

largeio|nolargeio
If "nolargeio" is specified, the optimal I/O reported in st_blksize by stat(2) will be as small as possible to allow user applications to avoid inefficient read/modify/write I/O. This is typically the page size of the machine, as this is the granularity of the page cache.

If "largeio" specified, a filesystem that was created with a "swidth" specified will return the "swidth" value (in bytes) in st_blksize. If the filesystem does not have a "swidth" specified but does specify an "allocsize" then "allocsize" (in bytes) will be returned instead. Otherwise the behavior is the same as if "nolargeio" was specified. nolargeio is the default.

logbufs=value
Set the number of in-memory log buffers. Valid numbers range from 2–8 inclusive.

The default value is 8 buffers.

If the memory cost of 8 log buffers is too high on small systems, then it may be reduced at some cost to performance on metadata intensive workloads. The logbsize option below controls the size of each buffer and so is also relevant to this case.

logbsize=value
Set the size of each in-memory log buffer. The size may be specified in bytes, or in kibibytes (KiB) with a "k" suffix. If set manually, logbsize must be one of the specified valid sizes and a multiple of the log stripe unit - configured at mkfs time.

Valid sizes for version 1 and version 2 logs are 16384 (value=16k) and 32768 (value=32k). Valid sizes for version 2 logs also include 65536 (value=64k), 131072 (value=128k) and 262144 (value=256k).

The default value for version 1 logs is 32768, while the default value for version 2 logs is max(32768, log_sunit) even if log_sunit does not match one of the valid values above.

logdev=device and rtdev=device
Use an external log (metadata journal) and/or real-time device. An XFS filesystem has up to three parts: a data section, a log section, and a real-time section. The real-time section is optional, and the log section can be separate from the data section or contained within it.
noalign
Data allocations will not be aligned at stripe unit boundaries. This is only relevant to filesystems created with non-zero data alignment parameters (sunit, swidth) by mkfs.
norecovery
The filesystem will be mounted without running log recovery. If the filesystem was not cleanly unmounted, it is likely to be inconsistent when mounted in "norecovery" mode. Some files or directories may not be accessible because of this. Filesystems mounted "norecovery" must be mounted read-only or the mount will fail.
nouuid
Don't check for double mounted file systems using the file system uuid. This is useful to mount LVM snapshot volumes, and often used in combination with "norecovery" for mounting read-only snapshots.
noquota
Forcibly turns off all quota accounting and enforcement within the filesystem.
uquota/usrquota/quota/uqnoenforce/qnoenforce
User disk quota accounting enabled, and limits (optionally) enforced. Refer to xfs_quota(8) for further details.
gquota/grpquota/gqnoenforce
Group disk quota accounting enabled and limits (optionally) enforced. Refer to xfs_quota(8) for further details.
pquota/prjquota/pqnoenforce
Project disk quota accounting enabled and limits (optionally) enforced. Refer to xfs_quota(8) for further details.
sunit=value and swidth=value
Used to specify the stripe unit and width for a RAID device or a stripe volume. "value" must be specified in 512-byte block units. These options are only relevant to filesystems that were created with non-zero data alignment parameters.

The sunit and swidth parameters specified must be compatible with the existing filesystem alignment characteristics. In general, that means the only valid changes to sunit are increasing it by a power-of-2 multiple. Valid swidth values are any integer multiple of a valid sunit value.

Typically the only time these mount options are necessary if after an underlying RAID device has had it's geometry modified, such as adding a new disk to a RAID5 lun and reshaping it.

swalloc
Data allocations will be rounded up to stripe width boundaries when the current end of file is being extended and the file size is larger than the stripe width size.
wsync
When specified, all filesystem namespace operations are executed synchronously. This ensures that when the namespace operation (create, unlink, etc) completes, the change to the namespace is on stable storage. This is useful in HA setups where failover must not result in clients seeing inconsistent namespace presentation during or after a failover event.

REMOVED MOUNT OPTIONS

The following mount options have been removed from the kernel, and will yield mount failures if specified. Mount options are deprecated for a significant period time prior to removal.

Name Removed
---- -------
delaylog/nodelaylog v4.0
ihashsize v4.0
irixsgid v4.0
osyncisdsync/osyncisosync v4.0
barrier/nobarrier v4.19

FILE ATTRIBUTES

The XFS filesystem supports setting the following file attributes on Linux systems using the chattr(1) utility:

a - append only

A - no atime updates

d - no dump

i - immutable

S - synchronous updates

For descriptions of these attribute flags, please refer to the chattr(1) man page.
