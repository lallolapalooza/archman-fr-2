NOM

xfsdump - utilitaire de sauvegarde incrémentielle du système de fichiers XFS

SYNTAXE

xfsdump -h
xfsdump [ options ] -f dest [ -f dest ... ] filesystem
xfsdump [ options ] - filesystem
xfsdump -I [ subopt=valeur ... ]

DESCRIPTION

xfsdump sauvegarde les fichiers et leurs attributs dans un système de fichiers. Les fichiers sont sauvegardés sur un support de stockage, un fichier régulier ou la sortie standard. Les options permettent à l'opérateur de sauvegarder tous les fichiers, seulement les fichiers qui ont changé depuis une sauvegarde précédente, ou seulement les fichiers contenus dans une liste de chemins.

L'utilitaire xfsrestore(8) re-remplit un système de fichiers avec le contenu de la sauvegarde.

Chaque invocation de xfsdump sauvegarde un seul système de fichiers. Cette invocation est appelée une session de sauvegarde. La session de sauvegarde divise le système de fichiers en un ou plusieurs flux de sauvegarde, un par destination. La division est effectuée par ordre de numéros d'inode (ino) du système de fichiers, aux limites sélectionnées pour égaliser la taille de chaque flux. De plus, les points de coupure entre les flux peuvent se trouver au milieu de fichiers très volumineux (aux limites d'étendue) si nécessaire pour obtenir une égalisation raisonnable de la taille des flux. Chaque flux de sauvegarde peut couvrir plusieurs objets médias, et un seul objet média peut contenir plusieurs flux de sauvegarde. L'objet média typique est une cartouche de bande. L'objet média enregistre le flux de sauvegarde comme un ou plusieurs fichiers médias. Un fichier média est une sauvegarde partielle autonome, destinée à minimiser l'impact des interruptions de média sur l'ensemble du flux de sauvegarde, au détriment d'un temps plus long pour terminer la sauvegarde. Par défaut, un seul fichier média est écrit, sauf si une taille de fichier média est spécifiée à l'aide de l'option -d. D'autres techniques, comme la création d'une deuxième copie de l'image de sauvegarde, offrent plus de protection contre les défaillances de médias que plusieurs fichiers médias.

xfsdump maintient un inventaire de sauvegarde en ligne dans /var/lib/xfsdump/inventory. L'option -I affiche le contenu de l'inventaire de manière hiérarchique. Les niveaux de la hiérarchie sont : système de fichiers, session de sauvegarde, flux et fichier média.

Les options de xfsdump sont :

-a
Spécifie que les fichiers pour lesquels le Data Migration Facility (DMF) a des copies hors ligne complètes (fichiers bi-état) doivent être traités comme s'ils étaient hors ligne (OFL). Cela signifie que les données du fichier ne seront pas sauvegardées par xfsdump, résultant en un fichier de sauvegarde plus petit. Si le fichier est restauré ultérieurement, les données du fichier restent accessibles via DMF. Si les deux options '-a' et '-z' sont spécifiées, l'option '-a' a la priorité (voir l'option '-z' ci-dessous).
-b taille_bloc
Spécifie la taille du bloc, en octets, à utiliser pour la sauvegarde. La même taille de bloc doit être spécifiée pour restaurer la bande. Si l'option -m n'est pas utilisée, alors -b n'a pas besoin d'être spécifié. Au lieu de cela, une taille de bloc par défaut de 1 Mo sera utilisée.
-c nom_prog
Utilise le programme spécifié pour alerter l'opérateur lorsqu'un changement de média est requis. Le programme d'alerte est généralement un script pour envoyer un mail ou faire clignoter une fenêtre pour attirer l'attention de l'opérateur.
-d taille_fichier
Spécifie la taille, en mégaoctets, des fichiers médias de sauvegarde. Si non spécifié, xfsdump sauvegardera les données sur bande en utilisant un seul fichier média par objet média. La taille de fichier média spécifiée peut devoir être ajustée si, par exemple, xfsdump ne peut pas placer un fichier média sur une seule bande.
-e
Permet d'exclure des fichiers de la sauvegarde. Cela fera ignorer à xfsdump les fichiers qui ont l'attribut de fichier "pas de sauvegarde" défini. Voir la section "Exclure des fichiers individuels" ci-dessous pour plus de détails sur la définition de cet attribut de fichier.
-f dest [ -f dest ... ]
Spécifie une destination de sauvegarde. Une destination de sauvegarde peut être le chemin d'un périphérique (tel qu'un lecteur de bande), un fichier régulier ou un lecteur de bande distant (voir rmt(8)). Cette option doit être omise si l'option de sortie standard (un simple - précédant la spécification du système de fichiers source) est spécifiée.
-l niveau
Spécifie un niveau de sauvegarde de 0 à 9. Le niveau de sauvegarde détermine la sauvegarde de base à laquelle cette sauvegarde est relative. La sauvegarde de base est la sauvegarde la plus récente à un niveau inférieur. Une sauvegarde de niveau 0 est absolue - tous les fichiers sont sauvegardés. Une sauvegarde de niveau où 1 <= niveau <= 9 est appelée une sauvegarde incrémentielle. Seuls les fichiers qui ont été modifiés depuis la sauvegarde de base sont sauvegardés. Les sauvegardes de sous-arborescence (voir l'option -s ci-dessous) ne peuvent pas être utilisées comme base pour les sauvegardes incrémentielles.
-m
Utilise le protocole de bande minimal pour les destinations de bande non SCSI ou les destinations de bande distantes qui ne sont pas des lecteurs de bande SCSI Linux ni des lecteurs de bande IRIX. Cette option ne peut pas être utilisée sans spécifier une taille de bloc à utiliser (voir l'option -b ci-dessus).
-o
Écrase la bande. Avec cette option, xfsdump ne lit pas la bande au préalable pour vérifier son contenu. Cette option peut être utilisée si xfsdump ne parvient pas à déterminer la taille du bloc d'une bande.
-p intervalle
Provoque l'affichage de rapports d'avancement à l'intervalle spécifié. intervalle est donné en secondes. Le rapport d'avancement indique le nombre de fichiers sauvegardés, le nombre total de fichiers à sauvegarder, le pourcentage de données sauvegardées et le temps écoulé.
-q
Le lecteur de bande de destination est une bande QIC. Les bandes QIC n'utilisent qu'une taille de bloc de 512 octets, pour laquelle xfsdump doit faire des aménagements spéciaux.
-s chemin [ -s chemin ... ]
Restreint la sauvegarde aux fichiers contenus dans les chemins spécifiés (sous-arborescences). Un chemin doit être relatif au point de montage du système de fichiers. Par exemple, si un système de fichiers est monté sur /d2, l'argument chemin pour le répertoire /d2/users est ``users''. Un chemin peut être un fichier ou un répertoire ; s'il s'agit d'un répertoire, l'intégralité de la hiérarchie des fichiers et sous-répertoires dont la racine est ce répertoire est sauvegardée. Les sauvegardes de sous-arborescence ne peuvent pas être utilisées comme base pour les sauvegardes incrémentielles (voir l'option -l ci-dessus).
-t fichier
Définit l'heure de la sauvegarde sur l'heure de modification de fichier plutôt que sur l'heure actuelle. xfsdump utilise l'heure de la sauvegarde pour déterminer quels fichiers doivent être sauvegardés lors d'une sauvegarde incrémentielle. Cette option doit être utilisée lors de la sauvegarde d'instantanés afin que l'heure de la sauvegarde corresponde à l'heure à laquelle l'instantané a été pris. Sinon, les fichiers modifiés après la prise d'un instantané pourraient être ignorés lors de la prochaine sauvegarde incrémentielle.
-v niveau_verbeux
-v sous_sys=niveau_verbeux[,sous_sys=niveau_verbeux,...]
Spécifie le niveau de détail utilisé pour les messages affichés pendant le déroulement de la sauvegarde. L'argument niveau_verbeux peut être passé sous forme de chaîne de caractères ou d'entier. S'il est passé sous forme de chaîne, les valeurs suivantes peuvent être utilisées : silent, verbose, trace, debug ou nitty. S'il est passé sous forme d'entier, les valeurs de 0 à 5 peuvent être utilisées. Les valeurs 0 à 4 correspondent aux chaînes déjà listées. La valeur 5 peut être utilisée pour produire une sortie de débogage encore plus détaillée.

La première forme de cette option active la journalisation des messages pour tous les sous-systèmes de sauvegarde. La deuxième forme permet de contrôler le niveau de journalisation des messages par sous-système. Les deux formes peuvent être combinées (voir l'exemple ci-dessous). L'argument sous_sys peut prendre l'une des valeurs suivantes : general, proc, drive, media, inventory, inomap et excluded_files.

Par exemple, pour sauvegarder le système de fichiers racine avec le traçage activé pour tous les sous-systèmes : 

# xfsdump -v trace -f /dev/tape /


Pour activer le traçage de niveau débogage pour les opérations de lecteur et de média : 

# xfsdump -v drive=debug,media=debug -f /dev/tape /


Pour activer le traçage pour tous les sous-systèmes, et le traçage de niveau débogage uniquement pour les opérations de lecteur : 

# xfsdump -v trace,drive=debug -f /dev/tape /


Pour lister les fichiers qui

seront exclus de la sauvegarde : 

# xfsdump -e -v excluded_files=debug -f /dev/tape /


-z taille
Spécifie la taille maximale, en kilo-octets, des fichiers à inclure dans la sauvegarde. Les fichiers dont la taille dépasse cette limite seront exclus de la sauvegarde, à l'exception des fichiers DMF à double état lorsque l'option '-a' est spécifiée (voir l'option '-a' ci-dessus). Lorsque spécifiée, l'option '-a' prend le pas sur l'option '-z'. La taille est une estimation basée sur le nombre de blocs disque réellement utilisés par le fichier et n'inclut donc pas les trous. En d'autres termes, la taille fait référence à l'espace qu'occuperait le fichier dans la sauvegarde résultante. Lors d'une restauration interactive, le fichier ignoré est visible avec 'ls' de xfsrestore et bien que vous puissiez utiliser les commandes 'add' et 'extract', rien ne sera restauré.
-A
Ne pas sauvegarder les attributs étendus des fichiers. Lors de la sauvegarde d'un système de fichiers géré dans un environnement DMF, cette option ne doit pas être utilisée. DMF stocke l'état de migration des fichiers dans des attributs étendus associés à chaque fichier. Si ces attributs ne sont pas préservés lors de la restauration du système de fichiers, les fichiers qui étaient dans un état migré ne seront pas rappelables par DMF. Notez que les sauvegardes contenant des attributs étendus de fichiers ne peuvent pas être restaurées avec les anciennes versions de xfsrestore(8).
-B id_session
Spécifie l'ID de la session de sauvegarde sur laquelle cette session de sauvegarde doit être basée. Si cette option est spécifiée, les options -l (niveau) et -R (reprise) ne sont pas autorisées. Au lieu de cela, xfsdump détermine si la session de sauvegarde actuelle doit être incrémentielle et/ou reprise, en examinant le niveau de la session de base et les attributs interrompus. Si la session de base a été interrompue, la session de sauvegarde actuelle est une reprise de cette base au même niveau. Sinon, la session de sauvegarde actuelle est une sauvegarde incrémentielle avec un niveau supérieur de un à celui de la session de base. Cette option permet aux sauvegardes incrémentielles et reprises d'être basées sur n'importe quelle sauvegarde précédente, plutôt que seulement sur la plus récente.
-D
Contrôle quelles répertoires sont sauvegardés lors d'une sauvegarde incrémentielle. Par défaut, les répertoires inchangés sont sauvegardés si des fichiers ou des répertoires en dessous d'eux ont changé. Cela résulte en une sauvegarde autonome -- si une sauvegarde de base est perdue, ou si vous savez que le(s) fichier(s) que vous souhaitez restaurer se trouve(nt) dans une sauvegarde incrémentielle, vous pouvez restaurer uniquement cette sauvegarde sans avoir à charger les sauvegardes de base au préalable. Cependant, cette méthode nécessite un parcours potentiellement coûteux du système de fichiers.

Lorsque -D est spécifié, les répertoires inchangés ne sont pas sauvegardés. Cela permet une sauvegarde plus rapide, mais les fichiers se retrouveront dans le répertoire orphelinat de xfsrestore(8) à moins que la ou les sauvegardes de base ne soient chargées au préalable.

-E
Effacer le média au préalable. Si cette option est spécifiée, le média est effacé avant utilisation. L'opérateur est invité à confirmer, sauf si l'option -F est également spécifiée.
-F
Ne pas interroger l'opérateur. Lorsque xfsdump rencontre un objet média contenant des données autres que xfsdump, xfsdump demande normalement à l'opérateur la permission d'écraser. Avec cette option, l'écrasement est effectué sans poser de questions. Lorsque xfsdump rencontre la fin du média pendant une sauvegarde, xfsdump demande normalement à l'opérateur si un nouvel objet média sera fourni. Avec cette option, la sauvegarde est interrompue.
-I
Affiche l'inventaire xfsdump (aucune sauvegarde n'est effectuée). xfsdump enregistre chaque session de sauvegarde dans un inventaire en ligne dans /var/lib/xfsdump/inventory. xfsdump utilise cet inventaire pour déterminer la base des sauvegardes incrémentielles. Il est également utile pour identifier manuellement une session de sauvegarde à restaurer. Les sous-options pour filtrer l'affichage de l'inventaire sont décrites plus loin.
-J
Empêche la mise à jour normale de l'inventaire. Ceci est utile lorsque le média vers lequel la sauvegarde est effectuée sera jeté ou écrasé.
-K
Génère une sauvegarde de format 2 au lieu du format actuel. Ceci est utile si la sauvegarde sera restaurée sur un système avec une version plus ancienne de xfsrestore qui ne comprend pas le format de sauvegarde actuel. L'utilisation de cette option n'est par ailleurs pas recommandée.
-L étiquette_session
Spécifie une étiquette pour la session de sauvegarde. Il peut s'agir de n'importe quelle chaîne de caractères arbitraire d'une longueur maximale de 255 caractères.
-M étiquette [ -M étiquette ... ]
Spécifie une étiquette pour le premier objet média (par exemple, une cartouche de bande) écrit sur la destination correspondante pendant la session. Il peut s'agir de n'importe quelle chaîne de caractères arbitraire d'une longueur maximale de 255 caractères. Plusieurs étiquettes d'objet média peuvent être spécifiées, une pour chaque destination.
-O fichier_options
Insère les options contenues dans fichier_options au début de la ligne de commande. Les options sont spécifiées exactement comme elles apparaîtraient si elles étaient tapées sur la ligne de commande. De plus, les caractères de nouvelle ligne (\n) peuvent être utilisés comme espaces blancs. Les options sont placées avant toutes les options réellement fournies sur la ligne de commande, juste après le nom de la commande. Une seule option -O peut être utilisée. L'utilisation récursive est ignorée. Le système de fichiers source ne peut pas être spécifié dans fichier_options.
-R
Reprend une session de sauvegarde précédemment interrompue. Si la sauvegarde la plus récente à ce niveau de sauvegarde (option -l) a été interrompue, cette sauvegarde ne contient que les fichiers qui ne se trouvent pas dans la sauvegarde interrompue et qui sont cohérents avec le niveau incrémentiel. Cependant, les fichiers contenus dans la sauvegarde interrompue qui ont été modifiés par la suite sont re-sauvegardés.
-T
Empêche les délais d'attente interactifs. Lorsque l'option -F n'est pas spécifiée, xfsdump invite l'opérateur à fournir des étiquettes et des changements de média. Chaque dialogue expire normalement si aucune réponse n'est fournie. Cette option empêche le délai d'attente.
-Y longueur
Spécifie la longueur du cycle des tampons d'E/S. xfsdump utilise un cycle de tampons de sortie pour obtenir un débit maximal lors de la sauvegarde sur des lecteurs de bande. La longueur de cycle par défaut est de 3. Cependant, cela n'est pas encore activé sous Linux, rendant cette option inoffensive.
-
Un simple - fait que le flux de sauvegarde est envoyé à la sortie standard, d'où il peut être redirigé vers une autre utilitaire tel que xfsrestore(8) ou redirigé vers un fichier. Cette option ne peut pas être utilisée avec l'option -f. Le - doit suivre toutes les autres options et précéder la spécification du système de fichiers.

Le système de fichiers, système_de_fichiers, peut être spécifié soit comme un point de montage, soit comme un fichier périphérique spécial (par exemple, /dev/dsk/dks0d1s0). Le système de fichiers doit être monté pour être sauvegardé.

NOTES

Interruption de sauvegarde

Une sauvegarde peut être interrompue à tout moment et reprise plus tard. Pour interrompre, tapez control-C (ou le caractère d'interruption du terminal actuel). L'opérateur est invité à choisir parmi plusieurs opérations, y compris l'interruption de la sauvegarde. Après que l'opérateur ait sélectionné l'interruption de la sauvegarde, la sauvegarde continue jusqu'à ce qu'un point de rupture pratique soit rencontré (typiquement la fin du fichier actuel). Les très gros fichiers sont divisés en sous-fichiers plus petits, de sorte que l'attente de la fin du fichier actuel est brève.

Reprise de sauvegarde

Une sauvegarde précédemment interrompue peut être reprise en spécifiant l'option -R. Si la sauvegarde la plus récente au niveau spécifié a été interrompue, la nouvelle sauvegarde n'inclut pas les fichiers déjà sauvegardés, à moins qu'ils n'aient été modifiés depuis la sauvegarde interrompue.

Gestion des médias

Un seul objet média peut contenir plusieurs flux de sauvegarde. Inversement, un seul flux de sauvegarde peut s'étendre sur plusieurs objets médias. Si un flux de sauvegarde est envoyé vers un objet média contenant déjà un ou plusieurs sauvegardes, xfsdump ajoute le nouveau flux de sauvegarde après le dernier flux de sauvegarde. Les fichiers médias ne sont jamais écrasés. Si la fin du média est rencontrée pendant une sauvegarde, l'opérateur est invité à insérer un nouvel objet média dans le lecteur. Le flux de continuation de la sauvegarde est ajouté après le dernier fichier média sur le nouvel objet média.

Inventaire

Chaque session de sauvegarde met à jour une base de données d'inventaire dans /var/lib/xfsdump/inventory. xfsdump utilise l'inventaire pour déterminer la base des sauvegardes incrémentielles et reprises.

Cette base de données peut être affichée en invoquant xfsdump avec l'option -I. L'affichage utilise une indentation en tabulations pour présenter l'inventaire de manière hiérarchique. Le premier niveau est le système de fichiers. Le deuxième niveau est la session. Le troisième niveau est le flux média (actuellement un seul flux est pris en charge). Le quatrième niveau liste les fichiers médias qui composent séquentiellement le flux.

Les sous-options suivantes sont disponibles pour filtrer l'affichage.

-I depth=n
(où n est 1, 2 ou 3) limite la profondeur hiérarchique de l'affichage. Lorsque n est 1, seules les informations du système de fichiers de l'inventaire sont affichées. Lorsque n est 2, seules les informations du système de fichiers et de la session sont affichées. Lorsque n est 3, seules les informations du système de fichiers, de la session et du flux sont affichées.
-I level=n
(où n est le niveau de sauvegarde) limite l'affichage aux sauvegardes de ce niveau de sauvegarde particulier.

L'affichage peut être restreint aux fichiers médias contenus dans un objet média spécifique.

-I mobjid=valeur
(où valeur est un ID média) spécifie l'objet média par son ID média.
-I mobjlabel=valeur
(où valeur est une étiquette média) spécifie l'objet média par son étiquette média.

De même, l'affichage peut être restreint à un système de fichiers spécifique.

NAME

xfsdump, xfsrestore - XFS filesystem dump and restore utility

SYNOPSIS

xfsdump [ options ] device

xfsrestore [ options ] dump-file

DESCRIPTION

xfsdump is used to back up an XFS filesystem. It can create a full backup of the entire filesystem or incremental backups. The backup is written to a file specified by the -f option.

xfsrestore is used to restore an XFS filesystem from a backup created by xfsdump.

xfsdump and xfsrestore use a special file format that is designed to be resilient to media errors. They can also handle multiple backup media.

OPTIONS

xfsdump supports the following options:

-b
Print backup information to standard output.
-c
Create a catalog of backup files.
-d
Dump the entire filesystem, including free space.
-f dump-file
Write the backup to the specified file.
-i
Interactive mode. Prompts for confirmation before each operation.
-l level
Set the dump level. 0 is a full dump, 1-9 are incremental dumps.
-m
Mute progress messages.
-p filename
Create a portable dump.
-r
Restore from a dump file.
-s file
Dump only the specified file or directory.
-v
Verbose mode. Prints detailed information about the dump.

xfsrestore supports the following options:

-a alt-restore-file
Use the specified alternate restore file.
-c
Create a catalog of backup files.
-f dump-file
Read the backup from the specified file.
-i
Interactive mode. Prompts for confirmation before each operation.
-m
Mute progress messages.
-n
Do not restore files.
-P partition
Restore to the specified partition.
-r
Restore from a dump file.
-s file
Restore only the specified file or directory.
-v
Verbose mode. Prints detailed information about the restore.

NOTES

xfsdump and xfsrestore are powerful tools that can be used to back up and restore XFS filesystems. It is important to read the man pages carefully before using these tools.

xfsdump cannot be used to dump a mounted filesystem if the filesystem is being actively written to. It is recommended to unmount the filesystem before dumping it, or to use the -P option to specify a partition.

xfsrestore can restore a filesystem to a new partition, or to an existing partition if the partition is not mounted. If restoring to an existing partition, it is recommended to unmount the partition before restoring.

It is important to keep a record of all dump operations, including the dump level, the date of the dump, and the media used. This information will be needed to restore the filesystem correctly.

If the filesystem is corrupted, it may not be possible to dump or restore it using xfsdump and xfsrestore. In such cases, it may be necessary to use a block-by-block copy program, such as dd, to make a copy of the filesystem before attempting to restore it. See xfs_copy(8) and xfs(5) for more details.

EXAMPLES

To perform a full backup of the root filesystem to a file named /backup/root.dump:

# xfsdump -f /backup/root.dump /

To perform an incremental backup of the root filesystem to a file named /backup/root.inc.1:

# xfsdump -l 1 -f /backup/root.inc.1 /

To restore the root filesystem from /backup/root.dump:

# xfsrestore -f /backup/root.dump /

To restore only the /home directory from /backup/root.dump:

# xfsrestore -s /home -f /backup/root.dump /

FILES

/etc/xfsdump.conf: Configuration file for xfsdump.

SEE ALSO

xfs_copy(8), xfs(5), mkfs.xfs(8), mount(8), umount(8)

DIAGNOSTICS

xfsdump and xfsrestore will exit with a non-zero status if an error occurs. The specific error message will be printed to standard error.

BUGS

None reported.

HISTORY

The xfsdump and xfsrestore utilities first appeared in XFS-ProJFS.

AVAILABILITY

These utilities are part of the xfsprogs package, which is available from http://xfs.org.

TRAPS

If the filesystem is heavily fragmented, or if there are many small files, the dump and restore operations may be slow. This is due to the nature of the XFS filesystem, which is designed for performance with large files.

If the dump file is corrupted, it may not be possible to restore the filesystem. It is important to ensure that the dump file is written to a reliable medium.

If you are restoring a filesystem to a different partition than the one it was originally on, you may need to adjust the filesystem's UUID and other parameters. This can be done using the xfs_admin command.

If the dump was created using dd or some other block-by-block copy program, it may not be possible to restore it using xfsrestore. See xfs_copy(8) and xfs(5) for more details.
