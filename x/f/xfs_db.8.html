NOM

xfs_db - déboguer un système de fichiers XFS

SYNTAXE

xfs_db [ -c cmd ] ... [ -i|r|x|F ] [ -f ] [ -l logdev ] [ -R rtdev ] [ -p progname ] device
xfs_db -V

DESCRIPTION

xfs_db est utilisé pour examiner un système de fichiers XFS. Dans de rares circonstances, il peut également être utilisé pour modifier un système de fichiers XFS, mais cette tâche est normalement laissée à xfs_repair(8) ou à des scripts tels que xfs_admin(8) qui exécutent xfs_db.

OPTIONS

-c cmd
Les commandes xfs_db peuvent être exécutées interactivement (par défaut) ou comme arguments sur la ligne de commande. Plusieurs arguments -c peuvent être donnés. Les commandes sont exécutées dans l'ordre spécifié, puis le programme se termine.
-f
Spécifie que l'image du système de fichiers à traiter est stockée dans un fichier régulier à l'emplacement device (voir l'option -d file de mkfs.xfs(8)). Cela peut se produire si une copie d'image d'un système de fichiers a été réalisée dans un fichier ordinaire avec xfs_copy(8).
-F
Spécifie que nous voulons continuer même si la magie du superbloc n'est pas correcte. À utiliser dans xfs_metadump.
-i
Permet l'exécution sur un système de fichiers monté, à condition qu'il soit monté en lecture seule. Utile pour les scripts shell qui ne doivent opérer que sur des systèmes de fichiers dans un état de cohérence garanti (soit non montés, soit montés en lecture seule). Ces sémantiques sont légèrement différentes de celles de l'option -r.
-l logdev
Spécifie le périphérique où réside le journal externe du système de fichiers. Uniquement pour les systèmes de fichiers qui utilisent un journal externe. Voir l'option -l de mkfs.xfs(8), et se référer à xfs(5) pour une description détaillée du journal XFS.
-p progname
Définit le nom du programme à progname pour les invites et certains messages d'erreur, la valeur par défaut est xfs_db.
-R
rtdev Spécifie le périphérique où résident les données en temps réel. Ceci n'est pertinent que pour les systèmes de fichiers qui ont une section en temps réel. Voir l'option -r de mkfs.xfs(8), et se référer à xfs(5) pour une description détaillée de la section en temps réel XFS.
-r
Ouvre device ou filename en lecture seule. Cette option est requise si le système de fichiers est monté. Il n'est nécessaire d'omettre ce drapeau que si une commande qui modifie les données (write, blocktrash, crc) doit être utilisée.
-x
Spécifie le mode expert. Ceci active les commandes (write, blocktrash, crc invalidate/revalidate).
-V
Affiche le numéro de version et quitte.

CONCEPTS

Les commandes xfs_db peuvent être divisées en deux classes. La plupart des commandes sont destinées à la navigation et à l'affichage des structures de données dans le système de fichiers. D'autres commandes servent à scanner le système de fichiers d'une manière ou d'une autre.

Les commandes utilisées pour naviguer dans la structure du système de fichiers prennent des arguments qui reflètent les noms des champs de structure du système de fichiers. Il peut y avoir plusieurs noms de champs séparés par des points lorsque les structures sous-jacentes sont imbriquées, comme en C. Les noms de champs peuvent être indexés (comme un indice de tableau) si le champ sous-jacent est un tableau. Les indices de tableau peuvent être spécifiés comme une plage, deux nombres séparés par un tiret.

xfs_db maintient une adresse courante dans le système de fichiers. La granularité de l'adresse est une structure de système de fichiers. Il peut s'agir d'un bloc de système de fichiers, d'un inode ou d'une quota (plus petit qu'un bloc de système de fichiers), ou d'un bloc de répertoire (qui pourrait être plus grand qu'un bloc de système de fichiers). Il existe une variété de commandes pour définir l'adresse courante. Associé à l'adresse courante se trouve le type de données courant, qui est le type structurel de ces données. Les commandes qui suivent la structure du système de fichiers définissent toujours le type ainsi que l'adresse. Les commandes qui examinent des parties d'un fichier individuel (inode) nécessitent que l'inode courant soit défini, ce qui est fait avec la commande inode.

Les informations d'adresse/type courantes sont en fait maintenues dans une pile qui peut être explicitement manipulée avec les commandes push, pop et stack. Cela permet un examen facile d'une structure de système de fichiers imbriquée. De plus, les derniers emplacements visités sont stockés dans un tampon circulaire qui peut être manipulé avec les commandes forward, back et ring.

Les systèmes de fichiers XFS sont divisés en un petit nombre de groupes d'allocation. xfs_db maintient une notion de groupe d'allocation courant qui est manipulé par certaines commandes. Le groupe d'allocation initial est 0.

COMMAND

Used to examine and write raw data on an XFS filesystem. The device argument must be a block special device.

SYNOPSIS

xfs_io [ -c ] [ -d ] [ -v ] [ -p ] [ -r ] [ -s ] [ -t ] [ -V ] device

DESCRIPTION

The xfs_io utility is a general purpose XFS filesystem examine tool. It can be used to read or write data on an XFS filesystem, and to examine the internal structures of the filesystem.

The xfs_io utility can be invoked in two ways:

interactive mode
when invoked with only the device argument. In this mode xfs_io prompts the user for commands. The help command gives more information on the allowed commands.
batch mode
when invoked with the -c command argument. This allows commands to be passed as a string. This mode is useful for scripting. When the write command is used, the data argument can be a sequence, a constant value, or a random value. In this mode write with no arguments gives more information on the allowed commands.
-c
batch mode. The argument is a string of commands to be executed.
-d
run non-interactively. This option is now deprecated and the batch mode described above should be used instead.
-p
pseudo-root. This allows the user to specify a different device for filesystem structures, such as the log, allocation groups, etc. This is useful for debugging corrupted filesystems, where the main device may not be mountable.
-r
read-only mode. This prevents accidental modification of the filesystem.
-s
strict mode. This prevents accidental modification of the filesystem. If this option is specified, xfs_io will only allow reading from the filesystem. This is the default behavior when the filesystem is mounted read-only.
-t
no pseudo-root. This is the default behavior.
-v
verbose mode. This enables verbose output for some commands.
-V
display version information and exit.

The write command with no arguments is used to print help information. The write command with arguments allows writing data to the filesystem. The data can be specified as a sequence, a constant value, or a random value. The -c option forces write verifiers and CRC recalculation to be skipped, allowing invalid data to be written to disk. The -d option skips write verifiers but performs CRC recalculation, allowing invalid data to be written to disk to test detection of invalid data (this is not possible for some types).

WRITE OPTIONS

-c
Skip write verifiers and CRC recalculation; allows invalid data to be written to disk.
-d
Skip write verifiers but perform CRC recalculation. This allows invalid data to be written to disk to test detection of invalid data. (This is not possible for some types.)

Si le système de fichiers possède un sous-volume temps réel, le champ rbmino du superbloc fait référence à un fichier contenant la bitmap temps réel. Chaque bit du fichier bitmap contrôle l'allocation d'une étendue temps réel unique (posé == libre). La bitmap est traitée par mots de 32 bits, le LSB d'un mot est utilisé pour la première étendue contrôlée par ce mot bitmap. Le champ atime de l'inode de la bitmap temps réel contient un compteur qui est utilisé pour contrôler où commencera le prochain nouveau fichier temps réel.

DIAGNOSTICS

De nombreux messages peuvent provenir de la commande blockget. Si le système de fichiers est complètement corrompu, un vidage de noyau peut être produit au lieu du message

device is not a valid filesystem

Si le système de fichiers est très grand (contient de nombreux fichiers), blockget pourrait manquer de mémoire. Dans ce cas, le message

out of memory
est affiché.

La description suivante concerne les problèmes les plus probables et les messages associés. La plupart des diagnostics produits ne sont significatifs qu'avec une compréhension de la structure du système de fichiers.

agf_freeblks n, counted m in ag a
Le compte des blocs libres dans l'en-tête du groupe d'allocation pour le groupe d'allocation a ne correspond pas au nombre de blocs comptés comme libres.
agf_longest n, counted m in ag a
L'extent libre le plus long dans l'en-tête du groupe d'allocation pour le groupe d'allocation a ne correspond pas à l'extent libre le plus long trouvé dans le groupe d'allocation.
agi_count n, counted m in ag a
Le compte des inodes alloués dans l'en-tête du groupe d'allocation pour le groupe d'allocation a ne correspond pas au nombre d'inodes comptés dans le groupe d'allocation.
agi_freecount n, counted m in ag a
Le compte des inodes libres dans l'en-tête du groupe d'allocation pour le groupe d'allocation a ne correspond pas au nombre d'inodes comptés comme libres dans le groupe d'allocation.
block a/b expected inum 0 got i
Le numéro de bloc est spécifié comme une paire (numéro de groupe d'allocation, bloc dans le groupe d'allocation). Le bloc est utilisé plusieurs fois (partagé), entre plusieurs inodes. Ce message suit généralement un message du type suivant.
block a/b expected type unknown got y
Le bloc est utilisé plusieurs fois (partagé).
block a/b type unknown not expected
