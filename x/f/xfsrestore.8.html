NOM

xfsrestore - Utilitaire de restauration incrémentielle de système de fichiers XFS

SYNOPIS

xfsrestore -h
xfsrestore [ options ] -f source [ -f source ... ] dest
xfsrestore [ options ] - dest
xfsrestore -I [ sous-opt=valeur ... ]

DESCRIPTION

xfsrestore restaure les systèmes de fichiers à partir de sauvegardes produites par xfsdump(8). Deux modes de fonctionnement sont disponibles : simple et cumulatif.

Le mode par défaut est le mode simple. xfsrestore remplit le répertoire de destination spécifié, dest, avec les fichiers contenus dans les médias de sauvegarde.

L'option -r spécifie le mode cumulatif. Des invocations successives de xfsrestore sont utilisées pour appliquer une séquence chronologiquement ordonnée de sauvegardes delta à une sauvegarde de base (niveau 0). Le contenu du système de fichiers au moment où chaque sauvegarde a été produite est reproduit. Cela peut impliquer l'ajout, la suppression, le renommage, la création de liens et la suppression de liens de fichiers et de répertoires.

Une sauvegarde delta est définie comme une sauvegarde incrémentielle (option xfsdump -l avec un niveau > 0) ou une sauvegarde reprise (option xfsdump -R). Les deltas doivent être appliqués dans l'ordre où ils ont été produits. Chaque delta appliqué doit avoir été produit avec le delta précédemment appliqué comme base.

xfsrestore conserve les informations d'état dans le répertoire-de-gestion-xfsrestore, pour informer les invocations ultérieures lorsqu'il est utilisé en mode cumulatif, ou en cas d'interruption d'une restauration. Pour garantir que les informations d'état peuvent être traitées, une version compatible de xfsrestore doit être utilisée pour chaque invocation ultérieure. De plus, chaque invocation doit s'exécuter sur un système ayant la même représentations des octets (endianness) et la même taille de page.

Les options de xfsrestore sont :

-a gestion
Chaque invocation de xfsrestore crée un répertoire appelé répertoire-de-gestion-xfsrestore. Ce répertoire est normalement créé directement sous le répertoire dest. L'option -a permet à l'opérateur de spécifier un répertoire alternatif, gestion, dans lequel xfsrestore crée le répertoire répertoire-de-gestion-xfsrestore. Lors d'une restauration cumulative (option -r) ou d'une reprise (option -R) d'une restauration, chaque invocation successive doit spécifier le même répertoire alternatif.
-b taille-bloc
Spécifie la taille du bloc, en octets, à utiliser pour la restauration. Pour d'autres lecteurs tels que DAT ou 8 mm , la même taille de bloc utilisée pour l'opération xfsdump doit être spécifiée pour restaurer la bande. La taille de bloc par défaut est 1 Mo.
-c nom-prog
Utilise le programme spécifié pour alerter l'opérateur lorsqu'un changement de média est requis. Le programme d'alerte est généralement un script pour envoyer un e-mail ou afficher une fenêtre pour attirer l'attention de l'opérateur.
-e
Empêche xfsrestore d'écraser les fichiers existants dans le répertoire dest.
-f source [ -f source ... ]
Spécifie une source de la sauvegarde à restaurer. Il peut s'agir du chemin d'accès d'un périphérique (tel qu'un lecteur de bande), d'un fichier régulier ou d'un lecteur de bande distant (voir rmt(8)). Cette option doit être omise si l'option d'entrée standard (un simple - précédant la spécification dest) est spécifiée.
-i
Sélectionne l'opération interactive. Une fois la hiérarchie des répertoires sur le média lue, un dialogue interactif est lancé. L'opérateur utilise un petit ensemble de commandes pour parcourir la hiérarchie des répertoires, sélectionnant les fichiers et les sous-arbres à extraire. Les commandes disponibles sont données ci-dessous. Initialement, rien n'est sélectionné, sauf les sous-arbres spécifiés avec les options de ligne de commande -s.
ls [arg]
Liste les entrées du répertoire courant ou du répertoire spécifié, ou l'entrée de fichier non-répertoire spécifiée. Le numéro d'inode original de l'entrée et son nom sont affichés. Les entrées qui sont des répertoires sont suivies d'un '/'. Les entrées sélectionnées pour l'extraction sont précédées d'un '*'.
cd [arg]
Change le répertoire de travail courant vers l'argument spécifié, ou vers le répertoire racine du système de fichiers si aucun argument n'est spécifié.
pwd
Imprime le chemin d'accès du répertoire courant, par rapport à la racine du système de fichiers.
add [arg]
Le répertoire courant ou le fichier ou répertoire spécifié dans le répertoire courant est sélectionné pour l'extraction. Si un répertoire est spécifié, alors lui et tous ses descendants sont sélectionnés. Les entrées sélectionnées pour l'extraction sont précédées d'un '*' lorsqu'elles sont listées par ls.
delete [arg]
Le répertoire courant ou le fichier ou répertoire spécifié dans le répertoire courant est désélectionné pour l'extraction. Si un répertoire est spécifié, alors lui et tous ses descendants sont désélectionnés. La manière la plus efficace d'extraire la plupart des fichiers d'un répertoire est de sélectionner le répertoire puis de désélectionner les fichiers qui ne sont pas nécessaires.
extract
Termine le dialogue interactif et provoque la restauration de tous les sous-arbres sélectionnés.
quit
xfsrestore termine le dialogue interactif et se termine immédiatement, même s'il y a des fichiers ou des sous-arbres sélectionnés pour l'extraction.
help
Liste un résumé des commandes disponibles.
-m
Utilise le protocole de bande minimal. Cette option ne peut pas être utilisée sans spécifier une taille de bloc à utiliser (voir l'option -b ci-dessus).
-n fichier
Permet à xfsrestore de ne restaurer que les fichiers plus récents que fichier. L'heure de modification de fichier (c'est-à-dire, telle qu'affichée avec la commande ls -l) est comparée à l'heure de modification des inodes de chaque fichier sur le média source (c'est-à-dire, telle qu'affichée avec la commande ls -lc). Un fichier est restauré depuis le média uniquement si son heure de modification d'inode est supérieure ou égale à l'heure de modification de fichier.
-o
Restaure le propriétaire/groupe de fichiers et répertoires même si l'utilisateur n'est pas root. Lorsqu'il est exécuté avec un identifiant d'utilisateur effectif root, xfsrestore restaure le propriétaire et le groupe de chaque fichier et répertoire. Lorsqu'il est exécuté avec un autre identifiant d'utilisateur effectif, il ne le fait pas, sauf si cette option est spécifiée.
-p intervalle
Fait imprimer des rapports de progression à des intervalles de intervalle secondes. La valeur de l'intervalle est approximative, xfsrestore retardera les rapports de progression pour éviter une surcharge de traitement indue.
-q
Le lecteur de bande source est une bande QIC. Les bandes QIC n'utilisent qu'une taille de bloc de 512 octets, pour laquelle xfsrestore doit faire des aménagements spéciaux.
-r
Sélectionne le mode cumulatif de fonctionnement. Les options -a et destination doivent être les mêmes pour chaque invocation.
-s sous-arbre
Spécifie un sous-arbre à restaurer. Un nombre quelconque d'options -s est autorisé. La restauration est limitée à l'union de tous les sous-arbres spécifiés. Chaque sous-arbre est spécifié comme un chemin d'accès relatif à la dest de restauration. Si un répertoire est spécifié, le répertoire et tous les fichiers sous ce répertoire sont restaurés.
-t
Affiche le contenu de la sauvegarde, mais ne crée ni ne modifie de fichiers ou de répertoires. Il peut être souhaitable de régler le niveau de verbosité sur silencieux lors de l'utilisation de cette option.
-x
Cette option peut être utile pour corriger un problème où les fichiers sont restaurés dans un répertoire orphelin en raison d'un problème avec xfsdump (v3.1.7 - v3.1.9). Une sauvegarde normale ne peut pas être restaurée avec cette option. Cette option ne fonctionne que pour une sauvegarde corrompue. Si une sauvegarde est créée par un xfsdump problématique (v3.1.7 - v3.1.9), vous devriez voir le contenu de la sauvegarde avec l'option -t b

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

avant la restauration. Ensuite, si un fichier est placé dans le répertoire orphanage, vous devez utiliser cette option -x pour restaurer la sauvegarde. Sinon, vous pouvez restaurer la sauvegarde sans cette option.

En mode cumulatif, cette option n'est requise que pour une sauvegarde de base (niveau 0). Vous n'avez plus besoin de cette option pour les sauvegardes de niveau 1+.

-v verbeux
-v sous_système=verbeux[,sous_système=verbeux,...]
Spécifie le niveau de détail utilisé pour les messages affichés pendant la restauration. L'argument verbeux peut être passé sous forme de chaîne de caractères ou d'entier. S'il est passé sous forme de chaîne, les valeurs suivantes peuvent être utilisées : silent, verbose, trace, debug, ou nitty. S'il est passé sous forme d'entier, les valeurs de 0 à 5 peuvent être utilisées. Les valeurs 0 à 4 correspondent aux chaînes déjà répertoriées. La valeur 5 peut être utilisée pour produire une sortie de débogage encore plus détaillée.

La première forme de cette option active la journalisation des messages sur tous les sous-systèmes de restauration. La seconde forme permet de contrôler le niveau de journalisation des messages par sous-système. Les deux formes peuvent être combinées (voir l'exemple ci-dessous). L'argument sous_système peut prendre l'une des valeurs suivantes : general, proc, drive, media, inventory, et tree.

Par exemple, pour restaurer le système de fichiers racine avec le traçage activé pour tous les sous-systèmes : 

# xfsrestore -v trace -f /dev/tape /


Pour activer le traçage de niveau débogage pour les opérations de lecteur et de média : 

# xfsrestore -v drive=debug,media=debug -f /dev/tape /


Pour activer le traçage pour tous les sous-systèmes, et le traçage de niveau débogage uniquement pour les opérations de lecteur : 

# xfsrestore -v trace,drive=debug -f /dev/tape /


-A
Ne pas restaurer les attributs de fichier étendus. Lors de la restauration d'un système de fichiers géré dans un environnement DMF, cette option ne doit pas être utilisée. DMF stocke l'état de migration des fichiers dans des attributs étendus associés à chaque fichier. Si ces attributs ne sont pas préservés lors de la restauration du système de fichiers, les fichiers qui étaient dans un état migré ne pourront pas être rappelés par DMF. Notez que la sauvegarde des attributs de fichier étendus est également facultative.
-B
Changer la propriété et les permissions du répertoire de destination pour qu'elles correspondent à celles du répertoire racine de la sauvegarde.
-D
Restaurer les paramètres d'événements DMAPI (Data Management Application Programming Interface). Si le système de fichiers restauré doit être géré dans le même environnement DMF que la sauvegarde d'origine, il est essentiel d'utiliser l'option -D. Sinon, il n'est généralement pas souhaitable de restaurer ces paramètres.
-E
Empêche xfsrestore d'écraser les versions plus récentes des fichiers. L'heure de modification de l'inode du fichier sur le média est comparée à l'heure de modification de l'inode du fichier correspondant dans le répertoire dest. Le fichier n'est restauré que si la version sur le média est plus récente que la version dans le répertoire dest. L'heure de modification de l'inode d'un fichier peut être affichée avec la commande ls -lc.
-F
Inhiber les invites interactives de l'opérateur. Cette option empêche xfsrestore de demander à l'opérateur la vérification de la sauvegarde sélectionnée comme cible de restauration et de demander tout changement de média.
-I
Affiche l'inventaire de xfsdump (aucune restauration n'est effectuée). Chaque fois que xfsdump est utilisé, un inventaire en ligne dans /var/lib/xfsdump/inventory est mis à jour. Ceci est utilisé pour déterminer la base des sauvegardes incrémentielles. Il est également utile pour identifier manuellement une session de sauvegarde à restaurer (voir les options -L et -S). Les sous-options pour filtrer l'affichage de l'inventaire sont décrites plus loin.
-J
Inhibe la mise à jour de l'inventaire lors de la rencontre d'un inventaire de session sur le média pendant la restauration. xfsrestore met à jour de manière opportuniste l'inventaire en ligne lorsqu'il rencontre un inventaire de session sur le média, mais uniquement s'il est exécuté avec un identifiant d'utilisateur effectif de root et uniquement si cette option n'est pas donnée.
-K
Force xfsrestore à utiliser les numéros de génération du format de sauvegarde 2. Normalement, la nécessité de cela est déterminée automatiquement, mais cette option est requise lors de la première invocation de xfsrestore dans le cas rare où une restauration cumulative commence avec une sauvegarde de format 3 (ou plus récent) et sera suivie d'une sauvegarde de format 2.
-L label_session
Spécifie le libellé de la session de sauvegarde à restaurer. Le média source est recherché pour ce libellé. Il s'agit d'une chaîne de caractères arbitraire d'une longueur maximale de 255 caractères. Le libellé de la session de sauvegarde souhaitée peut être copié à partir de l'affichage de l'inventaire produit par l'option -I.
-O fichier_options
Insère les options contenues dans fichier_options au début de la ligne de commande. Les options sont spécifiées exactement comme elles apparaîtraient si elles étaient tapées sur la ligne de commande. De plus, les caractères de nouvelle ligne (\n) peuvent être utilisés comme espace blanc. Les options sont placées avant toutes les options effectivement données sur la ligne de commande, juste après le nom de la commande. Une seule option -O peut être utilisée. L'utilisation récursive est ignorée. Le répertoire de destination ne peut pas être spécifié dans fichier_options.
-Q
Force l'achèvement d'une session de restauration interrompue. Cette option est requise pour contourner un scénario pathologique spécifique. Lors de la restauration d'une session de sauvegarde qui a été interrompue en raison d'une condition de fin de média (EOM) et qu'aucun inventaire de session en ligne n'est disponible, xfsrestore ne peut pas savoir quand la restauration de cette session de sauvegarde est terminée. L'opérateur est forcé d'interrompre la session de restauration. Dans ce cas, si l'opérateur essaie ensuite d'appliquer une sauvegarde reprise (en utilisant l'option -r), xfsrestore refuse de le faire. L'opérateur doit indiquer à xfsrestore de considérer la restauration de base comme terminée en utilisant cette option lors de l'application de la sauvegarde reprise.
-R
Reprend une restauration précédemment interrompue. xfsrestore peut être interrompu à tout moment en appuyant sur le caractère d'interruption du terminal (voir stty(1)). Utilisez cette option pour reprendre la restauration. Les options -a et destination doivent être les mêmes.
-S id_session
Spécifie l'UUID de la session de sauvegarde à restaurer. Le média source est recherché pour cet UUID. L'UUID de la session de sauvegarde souhaitée peut être copié à partir de l'affichage de l'inventaire produit par l'option -I.
-T
Inhibe les délais d'attente des dialogues interactifs. xfsrestore invite l'opérateur à changer de média. Ce dialogue expire normalement si aucune réponse n'est fournie. Cette option empêche l'expiration.
-X sous_arbre
Spécifie un sous-arbre à exclure. C'est l'inverse de l'option -s. N'importe quel nombre d'options -X est autorisé. Chaque sous-arbre est spécifié comme un chemin d'accès relatif à la dest de restauration. Si un répertoire est spécifié, le répertoire et tous les fichiers situés en dessous de ce répertoire sont exclus.
-Y longueur_anneau_io
Spécifie la longueur de l'anneau des tampons d'E/S. xfsrestore utilise un anneau de tampons d'entrée pour obtenir un débit maximal lors de la restauration à partir de lecteurs de bande. La longueur par défaut de l'anneau est de 3. Cependant, cela n'est pas encore activé sous Linux, rendant cette option inoffensive.
-
Un simple - provoque la lecture de l'entrée standard comme source de la sauvegarde à restaurer. L'entrée standard peut être un pipe d'un autre utilitaire (tel que xfsdump(8)) ou un fichier redirigé. Cette option ne peut pas être utilisée avec l'option -f. Le - doit suivre toutes les autres options et précéder la spécification dest.

Le système de fichiers sauvegardé est restauré dans le répertoire dest. Il n'y a pas de valeur par défaut ; le dest doit être spécifié.

NOTES

Restauration Cumulati­ve

Une sauvegarde de base (niveau 0) et un ensemble ordonné de sauvegardes delta peuvent être restaurés séquentiellement, chacune par-dessus la précédente, pour reproduire le contenu du système de fichiers d'origine au moment où la dernière sauvegarde delta a été produite. L'opérateur invoque xfsrestore une fois pour chaque sauvegarde. L'option -r doit être spécifiée. Le répertoire dest doit être le même pour toutes les invocations. Chaque invocation laisse un répertoire nommé xfsrestorehousekeeping dans le répertoire dest (cependant, voir l'option -a ci-dessus). Ce répertoire contient les informations d'état qui doivent être communiquées entre les invocations. L'opérateur doit supprimer ce répertoire après que la dernière sauvegarde delta a été appliquée.

xfsrestore génère également un répertoire nommé orphanage dans le répertoire dest. xfsrestore supprime ce répertoire après avoir terminé une restauration simple. Cependant, si orphanage n'est pas vide, il n'est pas supprimé. Cela peut se produire si des fichiers présents sur le média de sauvegarde ne sont référencés par aucun des répertoires restaurés. L'orphanage contient une entrée pour chaque fichier de ce type. Le nom de l'entrée est le numéro d'inode d'origine du fichier, un point ("."), et le compteur de génération du fichier modulo 4096 (seuls les 12 bits inférieurs du compteur de génération sont utilisés).

xfsrestore ne supprime pas l'orphanage après des restaurations cumulatives. Comme pour le répertoire xfsrestorehousekeeping, l'opérateur doit le supprimer après avoir appliqué toutes les sauvegardes delta.

Gestion des Média

Une sauvegarde se compose d'un ou plusieurs fichiers média contenus sur un ou plusieurs objets média. Un fichier média contient tout ou partie de la sauvegarde du système de fichiers. Les grands systèmes de fichiers sont divisés en plusieurs fichiers média pour minimiser l'impact des interruptions de média et pour s'adapter aux limites des objets média (fin de média).

DESCRIPTION

Le programme xfsrestore restaure un système de fichiers XFS à partir d'un flux de sauvegarde créé par xfsdump. Les flux de sauvegarde peuvent être des fichiers ordinaires, des périphériques de bande ou la sortie standard. La restauration peut être effectuée sur le système de fichiers d'origine ou sur un nouveau système de fichiers.

L'opération de restauration peut être lancée en spécifiant le flux de sauvegarde à l'aide de l'option -f, et le répertoire de destination à l'aide de l'argument de ligne de commande dest. Si dest est omis, le répertoire de travail actuel est utilisé.

Les flux de sauvegarde peuvent s'étendre sur plusieurs objets de média. Ceci est courant lorsque des bandes sont utilisées comme support de stockage. Dans ce cas, xfsrestore doit être invité à charger le support suivant à chaque fois qu'un objet de média est terminé. La restauration s'arrêtera à l'invite pour le support suivant. Si vous souhaitez que la restauration se poursuive sans intervention de l'opérateur, vous pouvez fournir un programme d'alerte pour vous inviter via -s. Si xfsrestore est invité à changer de support, il utilise généralement l'utilitaire rmt pour contrôler le périphérique de bande.

Les flux de sauvegarde peuvent contenir plusieurs sessions de sauvegarde. Par défaut, xfsrestore restaure la première session rencontrée. Les sessions de sauvegarde peuvent être sélectionnées individuellement à l'aide de l'option -L, qui spécifie le libellé de la session de sauvegarde, ou de l'option -S, qui spécifie l'UUID de la session de sauvegarde.

Les lecteurs de médias amovibles ne sont pas pris en charge. Les cartouches de bande peuvent contenir plusieurs fichiers de média, qui sont généralement séparés par (dans le jargon des bandes) des marques de fichier. Si une sauvegarde s'étend sur plusieurs objets de média, la restauration doit commencer par l'objet de média contenant le premier fichier de média sauvegardé. L'opérateur est invité lorsque le prochain objet de média est nécessaire.

Les objets de média peuvent contenir plus d'une sauvegarde. L'opérateur peut sélectionner la sauvegarde souhaitée en spécifiant le libellé de la sauvegarde (option -L), ou en spécifiant l'UUID de la sauvegarde (option -S). Si aucun des deux n'est spécifié, xfsrestore analyse l'intégralité de l'objet de média, invitant l'opérateur à chaque fois qu'une session de sauvegarde est rencontrée.

L'affichage de l'inventaire (option -I) est utile pour identifier les objets de média requis. Il est également utile pour identifier une session de sauvegarde. L'UUID de la session peut être copié à partir de l'affichage de l'inventaire vers l'argument de l'option -S pour identifier sans ambiguïté une session de sauvegarde à restaurer.

Les sauvegardes placées dans des fichiers ordinaires ou dans la sortie standard ne s'étendent pas sur plusieurs objets de média, ni ne contiennent plusieurs sauvegardes.

Inventaire

Chaque session de sauvegarde met à jour une base de données d'inventaire dans /var/lib/xfsdump/inventory. Cette base de données peut être affichée en appelant xfsrestore avec l'option -I. L'affichage utilise une indentation en tabulation pour présenter l'inventaire hiérarchiquement. Le premier niveau est le système de fichiers. Le deuxième niveau est la session. Le troisième niveau est le flux de média (actuellement un seul flux est pris en charge). Le quatrième niveau liste les fichiers média qui composent séquentiellement le flux.

Les sous-options suivantes sont disponibles pour filtrer l'affichage.

-I depth=n
(où n est 1, 2 ou 3) limite la profondeur hiérarchique de l'affichage. Lorsque n est 1, seules les informations du système de fichiers de l'inventaire sont affichées. Lorsque n est 2, seules les informations du système de fichiers et de la session sont affichées. Lorsque n est 3, seules les informations du système de fichiers, de la session et du flux sont affichées.
-I level=n
(où n est le niveau de sauvegarde) limite l'affichage aux sauvegardes de ce niveau de sauvegarde particulier.

L'affichage peut être restreint aux fichiers média contenus dans un objet de média spécifique.

-I mobjid=valeur
(où valeur est un ID de média) spécifie l'objet de média par son ID de média.
-I mobjlabel=valeur
(où valeur est un libellé de média) spécifie l'objet de média par son libellé de média.

De même, l'affichage peut être restreint à un système de fichiers spécifique.

-I mnt=point_montage
(c'est-à-dire [nom_hôte:]chemin_d'accès), identifie le système de fichiers par son point de montage. La spécification du nom d'hôte est facultative, mais peut être utile dans un environnement en cluster où plusieurs hôtes peuvent être responsables de la sauvegarde d'un système de fichiers.
-I fsid=id_système_fichiers
identifie le système de fichiers par son ID de système de fichiers.
-I dev=chemin_périphérique
(c'est-à-dire [nom_hôte:]chemin_périphérique) identifie le système de fichiers par son périphérique. Comme avec le filtre -mnt, la spécification du nom d'hôte est facultative.

Plusieurs de ces sous-options, séparées par des virgules, peuvent être spécifiées en même temps pour limiter l'affichage de l'inventaire à ces sauvegardes d'intérêt. Cependant, au plus quatre sous-options peuvent être spécifiées à la fois : une pour contraindre la profondeur de la hiérarchie d'affichage, une pour contraindre le niveau de sauvegarde, une pour contraindre l'objet de média, et une pour contraindre le système de fichiers.

Par exemple, -I depth=1,mobjlabel="tape 1",mnt=host1:/test_mnt afficherait uniquement les informations du système de fichiers (depth=1) pour les systèmes de fichiers qui étaient montés sur host1:/test_mnt au moment de la sauvegarde, et uniquement les systèmes de fichiers sauvegardés sur l'objet de média étiqueté "tape 1".

Les enregistrements de sauvegarde peuvent être supprimés (élagués) de l'inventaire en utilisant le programme xfsinvutil.

Un fichier média supplémentaire est placé à la fin de chaque flux de sauvegarde. Ce fichier média contient les informations d'inventaire pour la session de sauvegarde en cours. Si les fichiers d'inventaire en ligne dans /var/lib/xfsdump/inventory manquent d'informations pour la session de sauvegarde en cours, les informations d'inventaire du fichier média sont automatiquement ajoutées aux fichiers dans /var/lib/xfsdump/inventory. Si vous souhaitez intégrer les informations d'inventaire du fichier média sans restaurer de données, vous pouvez le faire en utilisant l'option -t :

# xfsrestore -t -f /dev/tape

Ceci est utile pour reconstruire la base de données d'inventaire si elle est perdue ou corrompue. Le seul bémol est que xfsrestore doit lire l'intégralité de la sauvegarde pour atteindre le fichier média d'inventaire. Cela peut prendre du temps pour les sessions de sauvegarde avec de gros fichiers média.

Erreurs de média

xfsdump est tolérant aux erreurs de média, mais ne peut pas corriger les erreurs. Si une erreur de média survient dans le corps d'un fichier média, le fichier du système de fichiers représenté à ce point est perdu. La partie défectueuse du média est ignorée, et la restauration reprend au prochain fichier du système de fichiers après la partie défectueuse du média.

Si une erreur de média survient au début du fichier média, l'intégralité du fichier média est perdue. Pour cette raison, les sauvegardes volumineuses sont divisées en un certain nombre de fichiers média de taille raisonnable. La restauration reprend avec le fichier média suivant.

Quotas

Lorsque xfsdump sauvegarde un système de fichiers avec des quotas utilisateur, il crée un fichier à la racine de la sauvegarde appelé xfsdump_quotas. xfsrestore peut restaurer ce fichier comme tout autre fichier inclus dans la sauvegarde. Ce fichier peut être traité par la commande de restauration de xfs_quota(8) pour réactiver les quotas. Cependant, le fichier xfsdump_quotas contient des informations qui peuvent nécessiter une modification ; spécifiquement le nom du système de fichiers et les identifiants utilisateur. Si vous restaurez les quotas pour les mêmes utilisateurs sur le même système de fichiers à partir duquel la sauvegarde a été effectuée, aucune modification ne sera nécessaire. Cependant, si vous restaurez la sauvegarde sur un système de fichiers différent, vous devrez :

- vous assurer que le nouveau système de fichiers est monté avec l'option de quota

- modifier le fichier xfsdump_quotas pour qu'il contienne le nouveau nom du système de fichiers

- vous assurer que les uid dans le fichier xfsdump_quotas sont corrects

Une fois les informations de quota vérifiées, la commande de restauration de xfs_quota (8) peut être utilisée pour appliquer les limites de quota au système de fichiers.

Les quotas de groupe et de projet sont gérés de manière similaire et seront restaurés dans des fichiers appelés respectivement xfsdump_quotas_group et xfsdump_quotas_proj.

EXEMPLES

Pour restaurer le système de fichiers racine à partir d'une bande montée localement :

# xfsrestore -f /dev/tape /

Pour restaurer à partir d'une bande distante, en spécifiant l'ID de session de sauvegarde :

# xfsrestore -L session_1 -f otherhost:/dev/tape /new

Pour restaurer le contenu d'une sauvegarde dans un autre sous-répertoire :

# xfsrestore -f /dev/tape /newdir

Pour copier le contenu d'un système de fichiers dans un autre répertoire (voir xfsdump(8)) :

# xfsdump -J - / | xfsrestore -J - /new

DIAGNOSTICS

Le code de sortie est 0 en cas d'achèvement normal, et non nul si une erreur s'est produite ou si la restauration a été interrompue par l'opérateur.

Pour tous les niveaux de verbosité supérieurs à 0 (silencieux), la dernière ligne de la sortie indique le code de statut de la restauration. Elle se présente sous la forme :

xfsdump: Restore Status: code

Où code prend l'une des valeurs suivantes : SUCCESS (achèvement normal), INTERRUPT (interrompu), QUIT (média inutilisable), INCOMPLETE (restauration incomplète), FAULT (erreur logicielle), et ERROR (erreur de ressource). Tous les efforts seront faits pour conserver la syntaxe et la sémantique de ce message de journal dans les futures versions de xfsrestore. Cependant, il peut être nécessaire d'affiner ou d'étendre l'ensemble des codes de sortie, ou leur interprétation à un moment donné.

BOGUES

Les chemins des fichiers non-répertoires restaurés (relatifs au répertoire dest) doivent être inférieurs ou égaux à 1023 caractères (MAXPATHLEN). Les chemins plus longs sont ignorés et un message d'avertissement est affiché.

Il n'y a pas d'option de vérification pour xfsrestore. Cela permettrait à l'opérateur de comparer une sauvegarde de système de fichiers à un système de fichiers existant, sans effectuer de restauration.

Les commandes interactives (option -i) ne comprennent pas les expressions régulières.

Lorsque l'option rmt minimale est spécifiée, xfsrestore l'applique à toutes les sources de bande distantes. Le même taille de bloc (spécifiée par l'option -b) est utilisée pour tous ces lecteurs distants.

xfsrestore utilise le programme d'alerte uniquement lorsqu'un changement de média est requis.

Le mode cumulatif (option -r) exige que l'opérateur invoque xfsrestore pour la base et pour chaque delta à appliquer séquentiellement à la base. Il serait préférable de permettre à l'opérateur d'identifier le dernier delta dans la séquence d'intérêt, et de laisser xfsrestore travailler à rebours à partir de ce delta pour identifier et appliquer les deltas précédents et la sauvegarde de base, le tout en une seule invocation.
