xfs_copy(8) Manuel de l'administrateur système xfs_copy(8)

NOM

xfs_copy - Copie le contenu d'un système de fichiers XFS

SYNTAXE

xfs_copy [ -bd ] [ -L log ] source cible1 [ cible2 ... ]
xfs_copy -V

DESCRIPTION

xfs_copy copie un système de fichiers XFS vers une ou plusieurs cibles en parallèle (voir xfs(5)). Le premier argument (source) doit être le chemin d'accès du périphérique ou du fichier contenant le système de fichiers XFS. Les arguments suivants spécifient un ou plusieurs périphériques ou noms de fichiers cibles. Si les chemins spécifient des périphériques, une copie du système de fichiers XFS source est créée sur chaque périphérique. La cible peut également être le nom d'un fichier ordinaire, auquel cas une image du système de fichiers XFS source est créée dans ce fichier. Si le fichier n'existe pas, xfs_copy crée le fichier. La longueur du fichier résultant est égale à la taille du système de fichiers source. Cependant, si le fichier est créé sur un système de fichiers XFS, le fichier consomme à peu près la quantité d'espace réellement utilisée dans le système de fichiers source par le système de fichiers et le journal XFS. L'économie d'espace est due au fait que xfs_copy saute les blocs libres au lieu de les copier et que le système de fichiers XFS prend en charge les fichiers épars efficacement.

xfs_copy ne doit être utilisé que pour copier des systèmes de fichiers non montés, des systèmes de fichiers montés en lecture seule, ou des systèmes de fichiers gelés (voir xfs_freeze(8)). Sinon, les nouveaux systèmes de fichiers générés seraient incohérents ou corrompus.

xfs_copy ne modifie en aucun cas le système de fichiers source. Chaque nouveau système de fichiers (cible) est identique au système de fichiers d'origine, à l'exception du fait que chaque nouveau système de fichiers possède un nouvel identifiant unique de système de fichiers (UUID). Par conséquent, si les anciens et les nouveaux systèmes de fichiers doivent être utilisés comme systèmes de fichiers distincts, xfs_copy ou xfsdump(8)/xfsrestore(8) devraient être utilisés pour générer les nouveaux systèmes de fichiers au lieu de dd(1) ou d'autres programmes de copie de disque bloc par bloc.

xfs_copy utilise des écritures synchrones pour garantir que les erreurs d'écriture sont détectées.

xfs_copy utilise les pthreads(7) pour effectuer des écritures parallèles simultanées. xfs_copy crée un thread supplémentaire pour chaque cible à écrire. Tous les threads meurent si xfs_copy se termine ou est avorté.

OPTIONS

-d
Crée un système de fichiers dupliqué (vrai clone). Cela ne devrait être fait que si le nouveau système de fichiers doit être utilisé en remplacement du système de fichiers d'origine (comme dans le cas du remplacement d'un disque).
-b
L'option buffered peut être utilisée pour garantir qu'aucune E/S directe n'est tentée sur les fichiers cibles. Ceci est utile lorsque le système de fichiers contenant le fichier cible ne prend pas en charge les E/S directes.
-L log
Spécifie l'emplacement du log si l'emplacement par défaut de /var/tmp/xfs_copy.log.XXXXXX n'est pas souhaité.
-V
Affiche le numéro de version et quitte.

DIAGNOSTICS

xfs_copy signale les erreurs à stderr et sous une forme plus détaillée dans un fichier journal généré dont le nom est de la forme /var/tmp/xfs_copy.log.XXXXXX ou un fichier journal spécifié par l'option -L. Si xfs_copy détecte une erreur d'écriture sur une cible, la copie de cette cible unique est abandonnée et un message d'erreur est émis à la fois vers stderr et le fichier journal, mais les autres copies continuent. Lorsque xfs_copy se termine, toutes les cibles abandonnées sont signalées à la fois à stderr et dans le fichier journal.

Si toutes les cibles sont abandonnées ou s'il y a une erreur lors de la lecture du système de fichiers source, xfs_copy est immédiatement abandonné.

xfs_copy renvoie un code de sortie de 0 si toutes les cibles sont copiées avec succès et un code de sortie de 1 si une cible échoue.

NOTES

Lors du déplacement de systèmes de fichiers d'un disque à un autre, si le système de fichiers d'origine est significativement plus petit que le nouveau système de fichiers et sera agrandi, nous recommandons d'utiliser mkfs.xfs(8) et xfsdump(8)/xfsrestore(8) au lieu d'utiliser xfs_copy et xfs_growfs(8). La disposition du système de fichiers résultant de l'utilisation de xfs_copy/xfs_growfs est presque toujours pire que le résultat de l'utilisation de mkfs.xfs/xfsdump/xfsrestore, mais dans le cas de petits systèmes de fichiers, les différences peuvent avoir un impact significatif sur les performances. Ceci est dû à la manière dont fonctionne xfs_growfs(8), et non à une quelconque lacune de xfs_copy lui-même.

AVERTISSEMENTS

xfs_copy ne copie pas les systèmes de fichiers XFS qui ont une section temps réel ou des systèmes de fichiers XFS avec des journaux externes. Dans les deux cas, xfs_copy s'interrompt avec un message d'erreur.

VOIR AUSSI

mkfs.xfs(8), xfsdump(8), xfsrestore(8), xfs_freeze(8), xfs_growfs(8), xfs(5).
