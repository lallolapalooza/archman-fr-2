xorg.conf(5) Manuel des formats de fichier xorg.conf(5)

NOM

xorg.conf, xorg.conf.d - fichiers de configuration pour le serveur Xorg

INTRODUCTION

Xorg prend en charge plusieurs mécanismes pour fournir/obtenir des paramètres de configuration et d'exécution : options de ligne de commande, variables d'environnement, fichiers de configuration xorg.conf et xorg.conf.d, détection automatique et valeurs par défaut de secours. Lorsque les mêmes informations sont fournies de plusieurs manières, le mécanisme de priorité la plus élevée est utilisé. La liste des mécanismes est ordonnée de la priorité la plus élevée à la plus basse. Notez que tous les paramètres ne peuvent pas être fournis par toutes les méthodes. Les options de ligne de commande et variables d'environnement disponibles (et certains défauts) sont décrites dans les pages de manuel Xserver(1) et Xorg(1). La plupart des paramètres des fichiers de configuration, avec leurs valeurs par défaut, sont décrits ci-dessous. Les paramètres de configuration spécifiques aux pilotes et aux modules sont décrits dans la page de manuel du pilote ou du module concerné.

DESCRIPTION

Xorg utilise un fichier de configuration appelé xorg.conf et des fichiers se terminant par le suffixe .conf du répertoire xorg.conf.d pour sa configuration initiale. Le fichier de configuration xorg.conf est recherché aux endroits suivants lorsque le serveur est démarré en tant qu'utilisateur normal :

/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

où <cmdline> est un chemin relatif (sans composants “..”) spécifié avec l'option de ligne de commande -config, $XORGCONFIG est le chemin relatif (sans composants “..”) spécifié par cette variable d'environnement, et <hostname> est le nom d'hôte de la machine tel que rapporté par gethostname(3).

Lorsque le serveur Xorg est démarré par l'utilisateur “root”, les emplacements de recherche du fichier de configuration sont les suivants :

<cmdline>
/etc/X11/<cmdline>
/usr/etc/X11/<cmdline>
$XORGCONFIG
/etc/X11/$XORGCONFIG
/usr/etc/X11/$XORGCONFIG
/etc/X11/xorg.conf
/etc/xorg.conf
/usr/etc/X11/xorg.conf.<hostname>
/usr/etc/X11/xorg.conf
/usr/lib/X11/xorg.conf.<hostname>
/usr/lib/X11/xorg.conf

où <cmdline> est le chemin spécifié avec l'option de ligne de commande -config (qui peut être absolu ou relatif), $XORGCONFIG est le chemin spécifié par cette variable d'environnement (absolu ou relatif), $HOME est le chemin spécifié par cette variable d'environnement (généralement le répertoire personnel), et <hostname> est le nom d'hôte de la machine tel que rapporté par gethostname(3).

Des fichiers de configuration supplémentaires sont recherchés dans les répertoires suivants lorsque le serveur est démarré en tant qu'utilisateur normal :

/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

où <cmdline> est un chemin relatif (sans composants “..”) spécifié avec l'option de ligne de commande -configdir.

Lorsque le serveur Xorg est démarré par l'utilisateur “root”, les emplacements de recherche du répertoire de configuration sont les suivants :

<cmdline>
/etc/X11/<cmdline>
/etc/X11/<cmdline>
/etc/X11/xorg.conf.d
/etc/X11/xorg.conf.d

où <cmdline> est le chemin spécifié avec l'option de ligne de commande -configdir (qui peut être absolu ou relatif).

Enfin, les fichiers de configuration seront également recherchés dans un répertoire réservé à l'usage du système. Ceci afin de séparer les fichiers de configuration des paquets de fournisseurs ou tiers de ceux de l'administration locale. Ces fichiers se trouvent dans le répertoire suivant :

/usr/share/X11/xorg.conf.d

Les fichiers xorg.conf et xorg.conf.d sont composés d'un certain nombre de sections qui peuvent être présentes dans n'importe quel ordre, ou omises pour utiliser les valeurs de configuration par défaut. Chaque section a la forme suivante :

Section  "NomSection"
    EntreeSection
    ...
EndSection

Les noms des sections sont :

Files          Chemins des fichiers
ServerFlags    Indicateurs du serveur
Module         Chargement dynamique des modules
Extensions     Activation des extensions
InputDevice    Description du périphérique d'entrée
InputClass     Description de la classe d'entrée
OutputClass    Description de la classe de sortie
Device         Description du périphérique graphique
VideoAdaptor   Description de l'adaptateur vidéo Xv
Monitor        Description du moniteur
Modes          Descriptions des modes vidéo
Screen         Configuration de l'écran
ServerLayout   Disposition générale
DRI            Configuration spécifique à DRI
Vendor         Configuration spécifique au vendeur

Les noms de sections obsolètes suivants sont toujours reconnus à des fins de compatibilité. Dans les nouveaux fichiers de configuration, la section InputDevice doit être utilisée à la place.

Keyboard       Configuration du clavier
Pointer        Configuration du pointeur/souris

L'ancienne section XInput n'est plus reconnue.

Les sections ServerLayout sont au plus haut niveau. Elles assemblent les périphériques d'entrée et de sortie qui seront utilisés dans une session. Les périphériques d'entrée sont décrits dans les sections InputDevice. Les périphériques de sortie se composent généralement de plusieurs composants indépendants (par exemple, une carte graphique et un moniteur). Ces composants multiples sont assemblés dans les sections Screen, et ce sont elles qui sont référencées par la section ServerLayout. Chaque section Screen assemble une carte graphique et un moniteur. Les cartes graphiques sont décrites dans les sections Device, et les moniteurs dans les sections Monitor.

Les mots-clés des fichiers de configuration ne sont pas sensibles à la casse, et les caractères “_” sont ignorés. La plupart des chaînes (y compris les noms d'Option) ne sont pas sensibles à la casse, ni aux espaces blancs et aux caractères “_”.

Chaque entrée de fichier de configuration occupe généralement une seule ligne dans le fichier. Elles se composent d'un mot-clé, éventuellement suivi d'un ou plusieurs arguments, dont le nombre et les types dépendent du mot-clé. Les types d'arguments sont :

Integer     un nombre entier décimal, hexadécimal ou octal
Real        un nombre à virgule flottante
String      une chaîne de caractères entre guillemets doubles (")

Note : les valeurs entières hexadécimales doivent être précédées de “0x”, et les valeurs octales de “0”.

Un mot-clé spécial appelé Option peut être utilisé pour fournir des données de forme libre à divers composants du serveur. Le mot-clé Option prend un ou deux arguments chaîne. Le premier est le nom de l'option, et le second argument facultatif est la valeur de l'option. Certains types de valeurs d'option couramment utilisés incluent :

Integer     un nombre entier décimal, hexadécimal ou octal
Real        un nombre à virgule flottante
String      une séquence de caractères
Boolean     une valeur booléenne (voir ci-dessous)
Frequency   une valeur de fréquence (voir ci-dessous)

Notez que *toutes* les valeurs d'Option, pas seulement les chaînes, doivent être mises entre guillemets.

Les options booléennes peuvent éventuellement avoir une valeur spécifiée. Lorsqu'aucune valeur n'est spécifiée, la valeur de l'option est TRUE. Les valeurs d'option booléennes suivantes sont reconnues comme TRUE :

1, on, true, yes

et les valeurs d'option booléennes suivantes sont reconnues comme FALSE :

0, off, false, no

Si un nom d'option est préfixé par "No", alors la valeur de l'option est inversée.

Exemple : les entrées d'option suivantes sont équivalentes :

Option "Accel"   "Off"
Option "NoAccel"
Option "NoAccel" "On"
Option "Accel"   "false"
Option "Accel"   "no"

Les valeurs de fréquence d'option se composent d'un nombre réel qui est facultativement suivi de l'un des unités de fréquence suivantes :

Hz, k, kHz, M, MHz

Lorsque le nom de l'unité est omis, les unités correctes seront déterminées à partir de t

FICHIERS SECTION

La section Files est utilisée pour spécifier certains noms de chemin requis par le serveur. Certains de ces chemins peuvent également être définis depuis la ligne de commande (voir Xserver(1) et Xorg(1)). Les paramètres de la ligne de commande remplacent les valeurs spécifiées dans le fichier de configuration. La section Files est facultative, tout comme toutes les entrées qui peuvent y apparaître.

Les entrées qui peuvent apparaître dans cette section sont :

FontPath "chemin"
définit le chemin de recherche des polices. Ce chemin est une liste d'éléments de chemin de polices séparés par des virgules que le serveur Xorg recherche pour les bases de données de polices. Plusieurs entrées FontPath peuvent être spécifiées, et elles seront concaténées pour construire le chemin de polices utilisé par le serveur. Les éléments de chemin de polices peuvent être des chemins de répertoires absolus, des répertoires de catalogue ou un identifiant de serveur de polices. Les formats des deux derniers sont expliqués ci-dessous :
Répertoires de catalogue :
Les répertoires de catalogue peuvent être spécifiés en utilisant le préfixe catalogue: avant le nom du répertoire. Le répertoire peut alors être rempli de liens symboliques pointant vers les répertoires de polices réels, en utilisant la syntaxe suivante dans le nom du lien symbolique :
<identifiant>:[attribut]:pri=<priorité>

où <identifiant> est un identifiant alphanumérique, [attribut] est un attribut qui sera passé au FPE sous-jacent et <priorité> est un nombre utilisé pour ordonner les FPE de fichiers de polices. Exemples :

75dpi:unscaled:pri=20 -> /usr/share/X11/fonts/75dpi
gscript:pri=60 -> /usr/share/fonts/default/ghostscript
misc:unscaled:pri=10 -> /usr/share/X11/fonts/misc
Identifiants de serveur de polices :
Les identifiants de serveur de polices ont la forme :

<trans>/<nom_hôte>:<numéro_port>

où <trans> est le type de transport à utiliser pour se connecter au serveur de polices (par exemple, unix pour les sockets de domaine UNIX ou tcp pour une connexion TCP/IP), <nom_hôte> est le nom d'hôte de la machine exécutant le serveur de polices, et <numéro_port> est le numéro de port sur lequel le serveur de polices écoute (généralement 7100).

Lorsque cette entrée n'est pas spécifiée dans le fichier de configuration, le serveur utilise le chemin de polices par défaut intégré, qui contient les éléments de chemin de polices suivants (qui peuvent être définis dans un répertoire de catalogue) :

/usr/share/fonts/X11/misc/
/usr/share/fonts/X11/TTF/
/usr/share/fonts/X11/OTF/
/usr/share/fonts/X11/Type1/
/usr/share/fonts/X11/100dpi/
/usr/share/fonts/X11/75dpi/

Les éléments de chemin de polices qui s'avèrent invalides sont supprimés du chemin de polices au démarrage du serveur.

ModulePath "chemin"
définit le chemin de recherche des modules Xorg chargeables. Ce chemin est une liste de répertoires séparés par des virgules que le serveur Xorg recherche pour les modules chargeables, en chargeant dans l'ordre spécifié. Plusieurs entrées ModulePath peuvent être spécifiées, et elles seront concaténées pour construire le chemin de recherche des modules utilisé par le serveur. Le chemin de modules par défaut est
lib/xorg/modules
XkbDir "chemin"
définit le répertoire de base pour les fichiers de disposition du clavier. L'option de ligne de commande -xkbdir peut être utilisée pour remplacer cela. Le répertoire par défaut est
/usr/share/X11/xkb

SECTION SERVERFLAGS

En plus des options spécifiques à cette section (décrites ci-dessous), la section ServerFlags est utilisée pour spécifier certaines options globales du serveur Xorg. Toutes les entrées de cette section sont des Options, bien que pour des raisons de compatibilité, certaines entrées anciennes soient encore reconnues. Ces anciennes entrées ne sont pas documentées ici, et leur utilisation est déconseillée. La section ServerFlags est facultative, tout comme les entrées qui peuvent y être spécifiées.

Les Options spécifiées dans cette section (à l'exception de l'Option "DefaultServerLayout") peuvent être remplacées par les Options spécifiées dans la section ServerLayout active. Les options ayant des équivalents en ligne de commande sont remplacées lorsque leur équivalent en ligne de commande est utilisé. Les options reconnues par cette section sont :

Option "Debug" "chaîne"
Cette liste séparée par des virgules permet de contrôler divers commutateurs de débogage à partir du fichier de configuration. Pour le moment, la seule valeur définie est dmabuf_capable, qui demande à glamor d'activer un code de gestion de tampons instable.
Option "DefaultServerLayout" "identifiant_disposition"
Ceci spécifie la section ServerLayout par défaut à utiliser en l'absence de l'option de ligne de commande -layout.
Option "DontVTSwitch" "booléen"
Ceci désactive l'utilisation de la séquence Ctrl+Alt+Fn (où Fn fait référence à l'une des touches de fonction numérotées). Cette séquence est normalement utilisée pour passer à un autre « terminal virtuel » sur les systèmes d'exploitation qui ont cette fonctionnalité. Lorsque cette option est activée, cette séquence de touches n'a pas de signification spéciale et est transmise aux clients. Par défaut : désactivé.
Option "DontZap" "booléen"
Ceci désactive l'utilisation de l'action XKB Terminate_Server (généralement Ctrl+Alt+Retour arrière, selon les options XKB). Cette action est normalement utilisée pour terminer le serveur Xorg. Lorsque cette option est activée, l'action n'a aucun effet. Par défaut : désactivé.
Option "DontZoom" "booléen"
Ceci désactive l'utilisation des séquences Ctrl+Alt+Rep. Num. Plus et Ctrl+Alt+Rep. Num. Moins. Ces séquences permettent de basculer entre les modes vidéo. Lorsque cette option est activée, ces séquences de touches n'ont pas de signification spéciale et sont transmises aux clients. Par défaut : désactivé.
Option "DisableVidModeExtension" "booléen"
Ceci désactive les parties de l'extension VidMode utilisées par le client xvidtune qui peuvent être utilisées pour modifier les modes vidéo. Par défaut : l'extension VidMode est activée.
Option "AllowNonLocalXvidtune" "booléen"
Ceci permet au client xvidtune (et à d'autres clients utilisant l'extension VidMode) de se connecter depuis un autre hôte. Par défaut : désactivé.
Option "AllowMouseOpenFail" "booléen"
Ceci indique aux pilotes mousedrv(4) et vmmouse(4) de ne pas signaler d'échec si le périphérique de la souris ne peut être ouvert/initialisé. Cela n'a aucun effet sur evdev(4) ou d'autres pilotes. Par défaut : faux.
Option "BlankTime" "temps"
définit le délai d'inactivité pour la phase blank de l'économiseur d'écran. temps est en minutes. Ceci est équivalent à l'indicateur -s du serveur Xorg, et la valeur peut être modifiée à l'exécution avec xset(1). Par défaut : 10 minutes.
Option "StandbyTime" "temps"
définit le délai d'inactivité pour la phase standby du mode DPMS. temps est en minutes, et la valeur peut être modifiée à l'exécution avec xset(1). Par défaut : 10 minutes. Ceci convient uniquement aux moniteurs compatibles VESA DPMS, et peut ne pas être pris en charge par tous les pilotes vidéo. Il n'est activé que pour les écrans pour lesquels l'option "DPMS" est définie (voir la section MONITOR ci-dessous).
Option "SuspendTime" "temps"
définit le délai d'inactivité pour la phase suspend du mode DPMS. temps est en minutes, et la valeur peut être modifiée à l'exécution avec xset(1). Par défaut : 10 minutes. Ceci convient uniquement aux moniteurs compatibles VESA DPMS, et peut ne pas être pris en charge par tous les pilotes vidéo. Il n'est activé que pour les écrans pour lesquels l'option "DPMS" est définie (voir la section MONITOR ci-dessous).
Option "OffTime" "temps"
définit le délai d'inactivité pour la phase off du mode DPMS. temps est en minutes, et la valeur peut être modifiée à l'exécution avec xset(1). Par défaut : 10 minutes. Ceci convient uniquement aux moniteurs compatibles VESA DPMS, et peut ne pas être pris en charge par tous les pilotes vidéo. Il n'est activé que pour les écrans pour lesquels l'option "DPMS" est définie (voir la section MONITOR ci-dessous).
Option "MaxClients" "entier"
Définit le nombre maximum de clients autorisés à se connecter au serveur X. Les valeurs acceptables sont 64, 128, 256 ou 512.
Option "NoPM" "booléen"
Désactive quelque chose lié aux événements de gestion d'énergie. Par défaut : la gestion d'énergie est activée sur les plateformes qui la supportent.
Option "Xinerama" "booléen"
activer ou désactiver l'extension XINERAMA. Par défaut : désactivé.
Option "IndirectGLX" "booléen"
activer ou désactiver les contextes GLX indirects. Les contextes GLX indirects sont désactivés par défaut.
Option "DRI2" "booléen"
activer ou désactiver DRI2. DRI2 est désactivé par défaut.

Option "GlxVisuals" "chaîne de caractères"

Cette option contrôle le nombre de visuels GLX que le module GLX configure. La valeur par défaut est typical, qui configure un sous-ensemble typique des GLXFBConfigs fournis par le pilote comme visuels GLX. D'autres options sont minimal, qui configure l'ensemble minimal autorisé par la spécification GLX, et all, qui configure les visuels GLX pour tous les GLXFBConfigs.
Option "UseDefaultFontPath" "booléen"
Inclut le chemin de police par défaut même si d'autres chemins sont spécifiés dans xorg.conf. Si activé, les autres chemins de police sont également inclus. Activé par défaut.
Option "IgnoreABI" "booléen"
Permet le chargement de modules construits pour une version différente, potentiellement incompatible, du serveur X. Désactivé par défaut.
Option "AutoAddDevices" "booléen"
Si cette option est désactivée, aucun périphérique ne sera ajouté à partir des backends HAL ou udev. Activé par défaut.
Option "AutoEnableDevices" "booléen"
Si cette option est désactivée, les périphériques seront ajoutés (et l'événement DevicePresenceNotify sera envoyé), mais pas activés, laissant ainsi la politique au client. Activé par défaut.
Option "AutoAddGPU" "booléen"
Si cette option est désactivée, aucun périphérique GPU ne sera ajouté à partir du backend udev. Activé par défaut. (Peut être désactivé pour configurer Xinerama).
Option "AutoBindGPU" "booléen"
Si activé, les GPU secondaires seront automatiquement configurés comme sorties et sources de délestage. Cela rend, par exemple, les sorties d'ordinateurs portables connectées uniquement au GPU secondaire directement disponibles sans avoir à exécuter "xrandr --setprovideroutputsource". Activé par défaut.
Option "Log" "chaîne de caractères"
Cette option contrôle si le journal est vidé et/ou synchronisé sur disque après chaque message. Les valeurs possibles sont flush ou sync. Non défini par défaut.
Option "AllowByteSwappedClients" "booléen"
Autorise les clients ayant un ordre d'octets différent de celui du serveur. Activé par défaut.

SECTION MODULE

La section Module est utilisée pour spécifier quels modules du serveur Xorg doivent être chargés. Cette section est ignorée lorsque le serveur Xorg est compilé sous forme statique. Le type de modules normalement chargés dans cette section sont les modules d'extension du serveur Xorg. La plupart des autres types de modules sont chargés automatiquement lorsqu'ils sont nécessaires via d'autres mécanismes. La section Module est facultative, tout comme toutes les entrées qui peuvent y être spécifiées.

Les entrées de cette section peuvent prendre deux formes. La première forme, la plus couramment utilisée, est une entrée qui utilise le mot-clé Load, comme décrit ici :

Load "nomdumodule"
Ceci demande au serveur de charger le module nommé nomdumodule. Le nom du module donné doit être le nom standard du module, pas le nom du fichier du module. Le nom standard est sensible à la casse et n'inclut pas les préfixes “lib” ou “cyg”, ni les suffixes “.so” ou “.dll”.
Exemple : le module d'extension DRI peut être chargé avec l'entrée suivante :
Load "dri"
Disable "nomdumodule"
Ceci demande au serveur de ne pas charger le module nommé nomdumodule. Certains modules sont chargés par défaut dans le serveur, et ceci remplace cette valeur par défaut. Si une instruction Load est donnée pour le même module, elle remplace l'instruction Disable et le module est chargé. Le nom du module donné doit être le nom standard du module, pas le nom du fichier du module. Comme pour l'instruction Load, le nom standard est sensible à la casse et n'inclut pas le préfixe "lib", ni les suffixes ".a", ".o" ou ".so".

La deuxième forme d'entrée est une SubSection, dont le nom est le nom du module, et dont le contenu sont des Options qui sont passées au module lors de son chargement.

Exemple : le module extmod (qui contient un groupe diversifié d'extensions de serveur) peut être chargé, avec l'extension XFree86-DGA désactivée en utilisant l'entrée suivante :

SubSection "extmod"
   Option  "omit XFree86-DGA"
EndSubSection

Les modules sont recherchés dans chaque répertoire spécifié dans le chemin de recherche ModulePath, et dans les sous-répertoires drivers, extensions, input, internal et multimedia de chacun de ces répertoires. En plus de cela, les sous-répertoires spécifiques au système d'exploitation de tous les éléments ci-dessus sont recherchés en premier s'ils existent.

Pour voir quels modules d'extension sont disponibles, consultez le sous-répertoire extensions sous :

lib/xorg/modules

Les modules d'extension “extmod”, “dbe”, “dri”, “dri2”, “glx”, et “record” sont chargés automatiquement, s'ils sont présents, à moins d'être désactivés avec des entrées "Disable". Il est recommandé de charger au moins le module d'extension “extmod”. Sinon, certaines extensions couramment utilisées (comme l'extension SHAPE) ne seront pas disponibles.

SECTION EXTENSIONS

La section Extensions est utilisée pour spécifier quelles extensions de protocole X11 doivent être activées ou désactivées. La section Extensions est facultative, tout comme toutes les entrées qui peuvent y être spécifiées.

Les entrées de cette section sont listées comme des instructions Option avec le nom de l'extension comme premier argument et une valeur booléenne comme second. Le nom de l'extension est sensible à la casse et correspond à la forme indiquée dans la sortie de "Xorg -extension ?".

Exemple : l'extension MIT-SHM peut être désactivée avec l'entrée suivante : 
Section "Extensions"
    Option "MIT-SHM" "Disable"
EndSection

SECTION INPUTDEVICE

Le fichier de configuration peut comporter plusieurs sections InputDevice. Les serveurs X récents utilisent des backends HAL ou udev pour l'énumération des périphériques d'entrée et le branchement/débranchement à chaud des périphériques d'entrée. Il n'est généralement pas nécessaire de fournir des sections InputDevice dans xorg.conf si le branchement/débranchement à chaud est utilisé (c'est-à-dire si AutoAddDevices est activé). Si le branchement/débranchement à chaud est activé, les sections InputDevice utilisant les pilotes mouse, kbd et vmmouse seront ignorées.

Si le branchement/débranchement à chaud est désactivé, il y en aura normalement au moins deux : une pour le clavier (principal) et une pour le pointeur principal. Si l'une de ces deux est manquante, une configuration par défaut pour celles qui manquent sera utilisée. En l'absence d'un périphérique d'entrée principal explicitement spécifié, le premier InputDevice marqué comme CorePointer (ou CoreKeyboard) est utilisé. S'il n'y a pas de correspondance, le premier InputDevice qui utilise le pilote “mouse” (ou “kbd”) est utilisé. Le dernier recours est d'utiliser des configurations par défaut intégrées. Actuellement, la configuration par défaut peut ne pas fonctionner comme prévu sur toutes les plateformes.

Les sections InputDevice ont le format suivant :

Section "InputDevice"
    Identifier "nom"
    Driver     "piloteentree"
    options
    ...
EndSection

Les entrées Identifier et Driver sont requises dans toutes les sections InputDevice. Toutes les autres entrées sont facultatives.

L'entrée Identifier spécifie le nom unique de ce périphérique d'entrée. L'entrée Driver spécifie le nom du pilote à utiliser pour ce périphérique d'entrée. Lors de l'utilisation du serveur chargeable, le module de pilote d'entrée "piloteentree" sera chargé pour chaque section InputDevice active. ACCÉLÉRATION DU POINTER

Pour les périphériques de pointage, les options suivantes contrôlent comment le pointeur est accéléré ou décéléré par rapport au mouvement physique du périphérique. La plupart d'entre elles peuvent être ajustées à l'exécution, voir la page de manuel xinput(1) pour plus de détails. Seules les options d'accélération les plus importantes sont discutées ici.

Option "AccelerationProfile" "entier"
Sélectionne le profil. En termes simples, le profil constitue le "ressenti" de l'accélération. Plus formellement, il définit comment la fonction de transfert (accélération réelle en fonction de la vitesse actuelle du périphérique et des contrôles d'accélération) est construite. C'est principalement une question de préférence personnelle.
 0      classique (principalement compatible)
-1      aucun (seule une décélération constante est appliquée)
 1      dépendant du périphérique
 2      polynomial (fonction polynomiale)
 3      linéaire doux (genou souple, puis linéaire)
 4      simple (normal à basse vitesse, accéléré sinon)
 5      puissance (fonction puissance)
 6      linéaire (plus de vitesse, plus d'accélération)
 7      limité (comme linéaire, mais plafonne à un seuil)
Option "ConstantDeceleration" "réel"
Rend le pointeur décléré fois plus lent que la normale. Le plus utile pour les périphériques haute résolution. Une valeur comprise entre 0 et 1 accélérera le pointeur.
Option "AdaptiveDeceleration" "réel"
Permet de décélérer réellement le pointeur lorsqu'il se déplace lentement. Au maximum, il sera décléré adaptatif fois plus lent. Permet un positionnement précis du pointeur sans sacrifier la vitesse.
Option "AccelerationScheme" "chaîne"
Sélectionne le schéma, qui est l'algorithme sous-jacent.
prédictible   algorithme par défaut (comportement plus prédictible)
léger         ancien code d'accélération (tel que spécifié dans la spécification du protocole X)
aucun         pas d'accélération ni de décélération
Option "AccelerationNumerator" "entier"
Option "AccelerationDenominator" "entier"
Définit le numérateur et le dénominateur du facteur d'accélération. Le facteur d'accélération est une fraction qui, avec le seuil, peut être utilisée pour ajuster les profils aux besoins de l'utilisateur. Les profils simple et limité l'utilisent directement (c'est-à-dire qu'ils accélèrent du facteur), pour les autres profils, un facteur d'accélération plus élevé devrait entraîner un pointeur plus rapide. Typiquement, 1 est non accéléré et les valeurs jusqu'à 5 sont raisonnables.
Option "AccelerationThreshold" "entier"
Définit le seuil, qui est approximativement la vitesse (généralement des unités de périphérique par 10 ms) requise pour que l'accélération devienne effective. L'effet précis varie cependant selon le profil.

SECTION INPUTCLASS

Le fichier de configuration peut contenir plusieurs sections InputClass. Ces sections sont optionnelles et sont utilisées pour fournir la configuration d'une classe de périphériques d'entrée lorsqu'ils sont ajoutés automatiquement. Un périphérique d'entrée peut correspondre à plusieurs sections InputClass. Chaque classe peut remplacer les paramètres d'une classe précédente, il est donc préférable de disposer les sections avec les correspondances les plus génériques en premier.

Les sections InputClass ont le format suivant :

Section "InputClass"
    Identifier  "nom"
    entrées
    ...
    options
    ...
EndSection

L'entrée Identifier est requise dans toutes les sections InputClass. Toutes les autres entrées sont optionnelles.

L'entrée Identifier spécifie le nom unique de cette classe d'entrée. L'entrée Driver spécifie le nom du pilote à utiliser pour ce périphérique d'entrée. Après l'examen de toutes les classes, le module "inputdriver" de la première entrée Driver sera activé lors de l'utilisation du serveur chargeable.

Lorsqu'un périphérique d'entrée est ajouté automatiquement, ses caractéristiques sont vérifiées par rapport à toutes les sections InputClass. Chaque section peut contenir des entrées optionnelles pour affiner la correspondance de la classe. Si aucune des entrées optionnelles n'apparaît, la section InputClass est générique et correspondra à tout périphérique d'entrée. Si plusieurs de ces entrées apparaissent, elles doivent toutes correspondre pour que la configuration s'applique.

Il existe deux types d'entrées de correspondance utilisées dans les sections InputClass. La première permet de faire correspondre divers jetons aux attributs du périphérique. Une entrée peut être construite pour faire correspondre des attributs de différents périphériques en séparant les arguments par un caractère '|'. Plusieurs entrées du même type peuvent être fournies pour ajouter plusieurs conditions de correspondance sur le même attribut. Par exemple :

Section "InputClass"
    Identifier   "Ma Classe"
    # la chaîne du produit doit contenir exemple et
    # soit gizmo soit gadget
    MatchProduct "exemple"
    MatchProduct "gizmo|gadget"
    NoMatchDriver "nomdriver"
    ...
EndSection

MatchVendor "matchvendor"
Cette entrée peut être utilisée pour vérifier si la sous-chaîne "matchvendor" apparaît dans le nom du fournisseur du périphérique.

Cette entrée peut être utilisée pour vérifier si les balises attribuées par le backend de configuration correspondent au motif "matchtag". Une correspondance est trouvée si au moins une des balises fournies dans "matchtag" correspond à au moins une des balises attribuées par le backend.

SECTION OUTPUTCLASS

Le fichier de configuration peut contenir plusieurs sections OutputClass. Ces sections sont facultatives et sont utilisées pour fournir la configuration d'une classe de périphériques de sortie lorsqu'ils sont automatiquement ajoutés. Un périphérique de sortie peut correspondre à plusieurs sections OutputClass. Chaque classe peut remplacer les paramètres d'une classe précédente, il est donc préférable d'organiser les sections avec les correspondances les plus génériques en premier.

Les sections OutputClass ont le format suivant :

Section "OutputClass"
    Identifier  "nom"
    entrées
    ...
EndSection

L'entrée Identifier est requise dans toutes les sections OutputClass. Toutes les autres entrées sont facultatives.

L'entrée Identifier spécifie le nom unique de cette classe de sortie. L'entrée Driver spécifie le nom du pilote à utiliser pour ce périphérique de sortie. Après avoir examiné toutes les classes, le module "outputdriver" de la première entrée Driver sera activé lors de l'utilisation du serveur chargeable.

Lorsqu'un périphérique de sortie est ajouté automatiquement, ses caractéristiques sont vérifiées par rapport à toutes les sections OutputClass. Chaque section peut contenir des entrées facultatives pour affiner la correspondance de la classe. Si aucune des entrées facultatives n'apparaît, la section OutputClass est générique et correspondra à n'importe quel périphérique de sortie. Si plusieurs de ces entrées apparaissent, elles doivent toutes correspondre pour que la configuration s'applique.

La liste suivante de jetons peut être comparée aux attributs du périphérique. Une entrée peut être construite pour faire correspondre les attributs de différents périphériques en séparant les arguments par un caractère '|'.

Par exemple :

Section "OutputClass"
    Identifier   "Ma Classe"
    # le pilote du noyau doit être foo ou bar
    MatchDriver "foo|bar"
    ...
EndSection
MatchDriver "matchdriver"
Compare la chaîne sensible à la casse "matchdriver" avec le pilote du noyau du périphérique.

Lorsqu'un périphérique de sortie a été associé à la section OutputClass, toutes les entrées Option sont appliquées au périphérique. Une Option spécifique à OutputClass est reconnue. Voir la section Device ci-dessous pour une description des entrées Option restantes.

Option "PrimaryGPU" "boolean"
Cette option spécifie que le périphérique correspondant doit être traité comme le GPU principal, remplaçant la sélection du GPU utilisé comme sortie par le firmware. Si plusieurs périphériques de sortie correspondent à une section OutputClass avec l'option PrimaryGPU activée, le premier énuméré devient le GPU principal.

Une section OutputClass peut contenir des entrées ModulePath. Lorsqu'un périphérique de sortie correspond à une section OutputClass, toutes les entrées ModulePath de cette OutputClass sont ajoutées au début du chemin de recherche des modules chargeables du serveur Xorg. Voir ModulePath dans la section Files pour plus d'informations.

Le fichier de configuration peut contenir plusieurs sections Device. Il doit y en avoir au moins une, pour la carte vidéo utilisée.

Les sections Device ont le format suivant :

Section "Device"
    Identifier "nom"
    Driver     "driver"
    entrées
    ...
EndSection

Les entrées Identifier et Driver sont requises dans toutes les sections Device. Toutes les autres entrées sont facultatives.

L'entrée Identifier spécifie le nom unique de ce périphérique graphique. L'entrée Driver spécifie le nom du pilote à utiliser pour ce périphérique graphique. Lors de l'utilisation du serveur chargeable, le module de pilote "driver" sera chargé pour chaque section Device active. Une section Device est considérée comme active si elle est référencée par une section Screen active.

Les sections Device reconnaissent certaines entrées et Options indépendantes du pilote, qui sont décrites ici. Tous les pilotes n'utilisent pas ces entrées indépendantes du pilote, et beaucoup de ceux qui le font n'ont pas besoin qu'elles soient spécifiées car les informations sont détectées automatiquement. Voir les pages man des pilotes graphiques individuels pour plus d'informations à ce sujet, et pour une description des options spécifiques au périphérique. Ceci spécifie l'emplacement bus de la carte graphique. Pour les cartes PCI/AGP, la chaîne id-bus a la forme PCI:bus@domaine:device:function (par exemple, “PCI:1@0:0:0” pourrait être approprié pour une carte AGP). La partie "@domaine" peut être omise pour le domaine PCI 0. Ce champ est généralement facultatif dans les configurations mono-écran lors de l'utilisation de la carte graphique principale. Dans les configurations multi-écran, ou lors de l'utilisation d'une carte graphique secondaire dans une configuration mono-écran, cette entrée est obligatoire. Son objectif principal est d'établir une connexion sans ambiguïté entre la section de périphérique et le matériel qu'elle représente. Ces informations peuvent généralement être trouvées en exécutant l'outil pciaccess scanpci.

Cette option est obligatoire pour les cartes où une seule entité PCI peut piloter plusieurs écrans (c'est-à-dire, plusieurs CRTCs partageant un seul accélérateur graphique et une mémoire vidéo). Une section Device est requise pour chaque tête, et ce paramètre détermine à quelle tête chaque section Device s'applique. Cette entrée, généralement facultative, spécifie le chipset utilisé sur la carte graphique. Dans la plupart des cas, cette entrée n'est pas requise car les pilotes interrogeront le matériel pour déterminer le type de chipset. Ne la spécifiez pas à moins que la documentation spécifique du pilote ne le recommande.
Ramdac "type-ramdac"
Cette entrée facultative spécifie le type de RAMDAC utilisé sur la carte graphique. Elle n'est utilisée que par quelques pilotes, et dans la plupart des cas, elle n'est pas requise car les pilotes interrogeront le matériel pour déterminer le type de RAMDAC lorsque cela est possible. Ne la spécifiez pas à moins que la documentation spécifique du pilote ne le recommande.

Cette entrée facultative est utilisée pour spécifier le type de puce d'horloge sur les cartes graphiques qui ont un générateur d'horloge programmable. Seuls quelques pilotes Xorg prennent en charge les puces d'horloge programmables. Pour plus de détails, consultez la page man du pilote approprié.

SECTION MONITOR

Le fichier de configuration peut comporter plusieurs sections Monitor. Il devrait normalement y en avoir au moins une, pour le moniteur utilisé, mais une configuration par défaut sera créée lorsqu'une n'est pas spécifiée.

Les sections Monitor ont le format suivant :

Section "Monitor"
    Identifier "nom"
    entrées
    ...
EndSection

La seule entrée obligatoire dans une section Monitor est l'entrée Identifier.

L'entrée Identifier spécifie le nom unique de ce moniteur. La section Monitor peut être utilisée pour fournir des informations sur les spécifications du moniteur, des Options spécifiques au moniteur, et des informations sur les modes vidéo à utiliser avec le moniteur.

Avec les pilotes compatibles RandR 1.2, les sections de moniteur peuvent être liées à des sorties spécifiques de la carte vidéo. En utilisant le nom de la sortie définie par le pilote vidéo plus l'identifiant d'une section de moniteur, on associe une section de moniteur à une sortie en ajoutant une option à la section Device dans le format suivant :

Option "Monitor-nom_sortie" "section_moniteur"

(par exemple, Option "Monitor-VGA" "Moniteur VGA" pour une sortie VGA)

En l'absence d'association spécifique des sections de moniteur aux sorties, si une section de moniteur est présente, le serveur l'associera à une sortie pour préserver la compatibilité avec les configurations mono-écran précédentes.

La spécification des modes vidéo est facultative car le serveur utilisera les informations DDC ou autres fournies par le moniteur pour configurer automatiquement la liste des modes disponibles. Lorsque les modes sont spécifiés explicitement dans la section Monitor (avec les mots-clés Mode, ModeLine, ou UseModes), les modes intégrés portant les mêmes noms ne sont pas inclus. Les modes intégrés portant des noms différents sont cependant toujours inclus implicitement, lorsqu'ils répondent aux exigences du moniteur.

SECTION MODES

Le fichier de configuration peut avoir plusieurs sections Modes, ou aucune. Ces sections fournissent un moyen de définir des ensembles de modes vidéo indépendamment des sections Monitor. Les sections Monitor peuvent inclure les définitions fournies dans ces sections en utilisant le mot-clé UseModes. Dans la plupart des cas, les sections Modes ne sont pas nécessaires car l'ensemble intégré des modes standard VESA sera suffisant.

Les sections Modes ont le format suivant :

Section "Modes"
    Identifier "nom"
    entrées
    ...
EndSection

L'entrée Identifier spécifie le nom unique de cet ensemble de descriptions de modes. Les autres entrées autorisées dans les sections Modes sont les entrées Mode et ModeLine qui sont décrites ci-dessus dans la section Monitor.

SECTION SCREEN

Le fichier de configuration peut avoir plusieurs sections Screen. Il doit y en avoir au moins une pour l'écran utilisé. Un "écran" représente la liaison d'un périphérique graphique (section Device) et d'un moniteur (section Monitor). Une section Screen est considérée comme "active" si elle est référencée par une section ServerLayout active ou par l'option de ligne de commande -screen. Si aucune de ces conditions n'est remplie, la première section Screen trouvée dans le fichier de configuration est considérée comme active.

Les sections Screen ont le format suivant :

Section "Screen"
    Identifier "nom"
    Device     "id-dev"
    GPUDevice  "id-dev"
    Monitor    "id-mon"
    entrées
    ...
    SubSection "Display"
       entrées
       ...
    EndSubSection
    ...
EndSection

L'entrée Identifier est obligatoire. Toutes les autres sont optionnelles.

L'entrée Identifier spécifie le nom unique de cet écran. La section Screen fournit des informations spécifiques à l'ensemble de l'écran, y compris les Options spécifiques à l'écran. Dans les configurations multi-têtes, il y aura plusieurs sections Screen actives, une pour chaque tête. Les entrées disponibles pour cette section sont :

Device "id-périphérique"
Cette entrée spécifie la section Device à utiliser pour cet écran. Lorsque plusieurs cartes graphiques sont présentes, c'est ce qui lie une carte spécifique à un écran. L'id-périphérique doit correspondre à l'Identifier d'une section Device dans le fichier de configuration.
GPUDevice "id-périphérique"
Cette entrée spécifie la section Device à utiliser comme périphérique GPU secondaire pour cet écran. Lorsque plusieurs cartes graphiques sont présentes, c'est ce qui lie une carte secondaire spécifique à un écran. L'id-périphérique doit correspondre à l'Identifier d'une section Device dans le fichier de configuration. Ceci peut être spécifié jusqu'à 4 fois pour un seul écran.
Monitor "id-moniteur"
spécifie quelle description de moniteur doit être utilisée pour cet écran. Si un nom de Monitor n'est pas spécifié, une configuration par défaut est utilisée. Actuel
ly la configuration par défaut peut ne pas fonctionner comme prévu sur toutes les plateformes.
VideoAdaptor "xv-id"
spécifie une description facultative de l'adaptateur vidéo Xv à utiliser avec cet écran.
DefaultDepth depth
spécifie la profondeur de couleur que le serveur doit utiliser par défaut. L'option de ligne de commande -depth peut être utilisée pour la remplacer. Si aucune des deux n'est spécifiée, la profondeur par défaut dépend du pilote, mais dans la plupart des cas, c'est 8.
DefaultFbBpp bpp
spécifie quelle disposition de la mémoire tampon d'image (framebuffer) utiliser par défaut. L'option de ligne de commande -fbbpp peut être utilisée pour la remplacer. Dans la plupart des cas, le pilote choisira la meilleure valeur par défaut pour cela. Le seul cas où il y a même un choix dans cette valeur concerne la profondeur 24, où certains matériels prennent en charge à la fois une disposition de mémoire tampon d'image de 24 bits compressée et une disposition de mémoire tampon d'image de 32 bits éparse.

Appliquer cette section Screen uniquement si le serveur X a été démarré avec l'option -seat seat-id.
Options
Divers indicateurs Option peuvent être spécifiés dans la section Screen. Certains sont spécifiques au pilote et sont décrits dans la documentation du pilote. D'autres sont indépendants du pilote et seront décrits ici à terme.
Option "Accel"
Active l'accélération matérielle 2D. Cette option est activée par défaut, mais il peut être nécessaire de la désactiver en cas de bogues dans le pilote. Il existe de nombreuses options pour désactiver des opérations accélérées spécifiques, listées ci-dessous. Notez que la désactivation d'une opération n'aura aucun effet si l'opération n'est pas accélérée (soit par manque de support dans le matériel, soit dans le pilote).
Option "GlxVendorLibrary" "string"
Cette option spécifie une liste d'espaces séparés de bibliothèques de fournisseurs OpenGL à utiliser pour l'écran. Ceci peut être utilisé pour sélectionner une implémentation alternative pour le développement, le débogage ou des ensembles de fonctionnalités alternatifs. Défaut : mesa.
Option ®enderingAPI" "string"
Cette option spécifie une API de rendu à utiliser conjointement avec la méthode d'accélération Glamor. Vous pouvez spécifier OpenGL avec la valeur "gl" et OpenGL ES avec la valeur "es", et la valeur par défaut est les deux, lorsque Glamor se rabat sur GLES si GL 2.1 n'est pas disponible. Cela peut être utile pour les cartes embarquées et anciennes, où l'ensemble de fonctionnalités GL ES fonctionne plus rapidement que l'ensemble de fonctionnalités GL. Défaut : gl.
Option "InitPrimary" "boolean"
Utilise le module Int10 pour initialiser la carte graphique principale. Normalement, seules les cartes secondaires sont démarrées par logiciel à l'aide du module Int10, car la carte principale a déjà été initialisée par le BIOS au démarrage. Défaut : false.
Option "NoInt10" "boolean"
Désactive le module Int10, un module qui utilise l'appel int10 au BIOS de la carte graphique pour l'initialiser. Défaut : false.

Chaque section Screen peut éventuellement contenir une ou plusieurs sous-sections Display. Ces sous-sections fournissent des informations de configuration spécifiques à la profondeur/fbbpp, et celle choisie dépend de la profondeur et/ou du fbbpp utilisé pour l'écran. Le format de la sous-section Display est décrit dans la section ci-dessous.

SOUS-SECTION DISPLAY

Chaque section Screen peut avoir plusieurs sous-sections Display. La sous-section Display « active » est la première qui correspond aux valeurs de profondeur et/ou fbbpp utilisées, ou à défaut, la première qui n'a ni valeur de profondeur ni de fbbpp spécifiée. Les sous-sections Display sont optionnelles. Lorsqu'il n'y en a pas qui corresponde aux valeurs de profondeur et/ou fbbpp utilisées, tous les paramètres qui peuvent être spécifiés ici reviennent à leurs valeurs par défaut.

Les sous-sections Display ont le format suivant :

    SubSection "Display"
        Depth  depth
        entries
        ...
    EndSubSection
Depth depth
Cette entrée spécifie pour quelle profondeur de couleur la sous-section Display doit être utilisée. Cette entrée est généralement spécifiée, mais elle peut être omise pour créer une sous-section Display correspondant à tout ou lors du souhait de ne correspondre qu'au paramètre FbBpp. La plage des valeurs depth autorisées dépend du pilote. La plupart des pilotes prennent en charge 8, 15, 16 et 24. Certains prennent également en charge 1 et/ou 4, et d'autres peuvent prendre en charge d'autres valeurs (comme 30). Remarque : depth signifie le nombre de bits par pixel réellement utilisés pour déterminer la couleur du pixel. 32 n'est pas une valeur depth valide. La plupart des matériels qui utilisent 32 bits par pixel n'en utilisent que 24 pour stocker les informations de couleur, ce qui signifie que la profondeur de couleur est de 24, pas de 32.
FbBpp bpp
Cette entrée spécifie le format de la mémoire tampon d'image pour lequel cette sous-section Display doit être utilisée. Cette entrée n'est nécessaire que lors de la fourniture de configurations de profondeur 24 qui permettent un choix entre un format de mémoire tampon d'image compressée de 24 bpp et un format de mémoire tampon d'image éparse de 32 bpp. Dans la plupart des cas, cette entrée ne doit pas être utilisée.
Weight red-weight green-weight blue-weight
Cette entrée facultative spécifie la pondération RVB relative à utiliser pour un écran utilisé à la profondeur 16 pour les pilotes qui autorisent plusieurs formats. Ceci peut également être spécifié depuis la ligne de commande avec l'option -weight (voir Xorg(1)).
Virtual xdim ydim
Cette entrée facultative spécifie la résolution de l'écran virtuel à utiliser. xdim doit être un multiple de 8 ou 16 pour la plupart des pilotes, et un multiple de 32 lors de l'exécution en mode monochrome. La valeur donnée sera arrondie à la baisse si ce n'est pas le cas. Les modes vidéo trop grands pour la taille virtuelle spécifiée seront rejetés. Si cette entrée est absente, la résolution de l'écran virtuel sera définie pour accueillir tous les modes vidéo valides indiqués dans l'entrée Modes. Certaines combinaisons pilote/matériel ne prennent pas en charge les écrans virtuels. Référez-vous à la documentation spécifique du pilote approprié pour plus de détails.
ViewPort x0 y0
Cette entrée facultative définit le coin supérieur gauche de l'affichage initial. Ceci n'est pertinent que lorsque la résolution de l'écran virtuel est différente de la résolution du mode vidéo initial. Si cette entrée n'est pas fournie, l'affichage initial sera centré dans la zone d'affichage virtuelle.
Modes "mode-name" ...
Cette entrée facultative spécifie la liste des modes vidéo à utiliser. Chaque mode-name spécifié doit être entre guillemets doubles. Ils doivent correspondre à ceux spécifiés ou référencés dans la section Monitor appropriée (y compris les modes standard VESA intégrés référencés implicitement). Le serveur supprimera les modes de cette liste qui ne satisfont pas diverses exigences. Le premier mode valide de cette liste sera le mode d'affichage par défaut au démarrage. La liste des modes valides est convertie en interne en une liste circulaire. Il est possible de passer au mode suivant avec Ctrl+Alt+Keypad-Plus et au mode précédent avec Ctrl+Alt+Keypad-Minus. Lorsque cette entrée est omise, les modes valides référencés par la section Monitor appropriée seront utilisés. Si la section Monitor ne contient aucun mode, la sélection sera prise parmi les modes standard VESA intégrés.
Visual "visual-name"
Cette entrée facultative définit le type visuel racine par défaut. Ceci peut également être spécifié depuis la ligne de commande (voir la page de manuel Xserver(1)). Les types visuels disponibles pour la profondeur 8 sont (par défaut PseudoColor) :
StaticGray
GrayScale
StaticColor
PseudoColor
TrueColor
DirectColor
Les types visuels disponibles pour les profondeurs 15, 16 et 24 sont (par défaut TrueColor) : 
TrueColor
DirectColor

Tous les pilotes ne prennent pas en charge DirectColor à ces profondeurs.

Les types visuels disponibles pour la profondeur 4 sont (par défaut StaticColor) :

StaticGray
GrayScale
StaticColor
PseudoColor

Black red green blue
Cette entrée facultative permet de spécifier la couleur « noir ». Ceci n'est pris en charge qu'à la profondeur 1. La valeur par défaut est le noir.
White red green blue
Cette entrée facultative permet de spécifier la couleur « blanc ». Ceci n'est pris en charge qu'à la profondeur 1. La valeur par défaut est le blanc.
Options
Les indicateurs d'options peuvent être spécifiés dans les sous-sections Display. Ceux-ci peuvent inclure des options spécifiques au pilote et des options indépendantes du pilote. Les premières sont décrites dans la documentation spécifique du pilote. Certaines des secondes sont décrites ci-dessus dans la section concernant la section Screen, et elles peuvent également être incluses ici.

SECTION SERVERLAYOUT

Le fichier de configuration peut contenir plusieurs sections ServerLayout. Une « disposition de serveur » représente la liaison d'un ou plusieurs écrans (sections Screen) et d'un ou plusieurs périphériques d'entrée (sections InputDevice) pour former une configuration complète. Dans les configurations multi-moniteurs, elle spécifie également la disposition relative des têtes. Une section ServerLayout est considérée comme « active » si elle est référencée par l'option de ligne de commande -layout ou par une entrée Option "DefaultServerLayout" dans la section ServerFlag

SECTION SERVERLAYOUT

Ce sont les sections les plus importantes d'un fichier de configuration du serveur X. Ils spécifient la manière dont les écrans, les zones et les périphériques d'entrée sont connectés. Plusieurs sections ServerLayout peuvent être présentes dans un fichier de configuration. Le serveur X en choisit une comme étant active. Les critères sont les suivants, par ordre de priorité décroissante :

  • Une section ServerLayout explicitement sélectionnée par l'option de ligne de commande -layout.

  • Une section ServerLayout portant le nom "Default Layout".

  • La première section ServerLayout trouvée dans le fichier de configuration.

Si aucune section ServerLayout n'est présente, le comportement par défaut est le suivant : le premier écran actif et les deux périphériques d'entrée (généralement le clavier et la souris principaux) sont sélectionnés, comme décrit dans les sections pertinentes ci-dessus.

Les sections ServerLayout ont le format suivant :

Section "ServerLayout"
    Identifier   "nom"
    Screen       "id-ecran"
    ...
    InputDevice  "id-périph-entrée"
    ...
    options
    ...
EndSection

Chaque section ServerLayout doit avoir une entrée Identifier et au moins une entrée Screen.

L'entrée Identifier spécifie le nom unique de cette disposition de serveur. La section ServerLayout fournit des informations spécifiques à l'ensemble de la session, y compris les Options spécifiques à la session. Les options ServerFlags (décrites ci-dessus) peuvent être spécifiées ici, et celles données ici remplacent celles données dans la section ServerFlags.

Les entrées qui peuvent être utilisées dans cette section sont décrites ici.

Screen num-ecran "id-ecran" informations-positionnement
Une de ces entrées doit être fournie pour chaque écran utilisé dans une session. Le champ id-ecran est obligatoire et spécifie la section Screen référencée. Le champ num-ecran est optionnel et peut être utilisé pour spécifier le numéro de l'écran dans les configurations multi-écrans. Lorsque ce champ est omis, les écrans seront numérotés dans l'ordre où ils sont listés. La numérotation commence à 0 et doit être consécutive. Le champ informations-positionnement décrit la manière dont plusieurs écrans sont positionnés. Il existe plusieurs façons de fournir ces informations :
x y
Absolute x y
Ces deux spécifications indiquent que les coordonnées du coin supérieur gauche sont (x,y). Le mot-clé Absolute est facultatif. Certaines anciennes versions de XFree86 (4.2 et antérieures) ne reconnaissent pas le mot-clé Absolute, il est donc plus sûr de spécifier simplement les coordonnées sans celui-ci.
RightOf "id-ecran"
LeftOf "id-ecran"
Above "id-ecran"
Below "id-ecran"
Relative "id-ecran" x y
Ces options donnent la position de l'écran par rapport à un autre écran. Les quatre premières placent l'écran immédiatement à droite, à gauche, au-dessus ou en dessous de l'autre écran. Lors du positionnement à droite ou à gauche, les bords supérieurs sont alignés. Lors du positionnement au-dessus ou en dessous, les bords gauches sont alignés. La forme Relative spécifie le décalage de l'origine de l'écran (coin supérieur gauche) par rapport à l'origine d'un autre écran.
InputDevice "id-périph-entrée" "option" ...
Une de ces entrées doit être fournie pour chaque périphérique d'entrée utilisé dans une session. Normalement, au moins deux sont requis, un pour le pointeur principal et un pour le clavier principal. Si l'un d'eux est manquant, des entrées InputDevice appropriées sont recherchées en utilisant la méthode décrite ci-dessus dans la section INPUTDEVICE. Le champ id-périph-entrée est obligatoire et spécifie le nom de la section InputDevice référencée. Plusieurs champs option peuvent être spécifiés, chacun entre guillemets doubles. Les options autorisées ici sont celles qui peuvent également être fournies dans les sections InputDevice. Normalement, seules les options de périphérique d'entrée spécifiques à la session seraient utilisées ici. Les options les plus couramment utilisées sont :
"CorePointer"
"CoreKeyboard"
"SendCoreEvents"
et les deux premières devraient normalement être utilisées pour indiquer respectivement le pointeur principal et le clavier principal.
MatchSeat id-siège
Appliquer cette section ServerLayout uniquement si le serveur X a été démarré avec l'option -seat id-siège.
Options
En plus de ce qui suit, toute option autorisée dans la section ServerFlags peut également être spécifiée ici. Lorsque la même option apparaît aux deux endroits, la valeur donnée ici remplace celle donnée dans la section ServerFlags.
Option "IsolateDevice" "id-bus"
Restreindre les réinitialisations de périphériques au id-bus spécifié. Voir l'option BusID (décrite dans la section DEVICE SECTION, ci-dessus) pour le format du paramètre id-bus. Cette option remplace SingleCard, si elle est spécifiée. Actuellement, seuls les périphériques PCI peuvent être isolés de cette manière.
Option "SingleCard" "booléen"
Identique à IsolateDevice, sauf que l'ID du bus du premier périphérique de la disposition est utilisé.

Voici un exemple de section ServerLayout pour une configuration à deux têtes avec deux souris :

Section "ServerLayout"
    Identifier  "Disposition 1"
    Screen      "MGA 1"
    Screen      "MGA 2" RightOf "MGA 1"
    InputDevice "Clavier 1" "CoreKeyboard"
    InputDevice "Souris 1"    "CorePointer"
    InputDevice "Souris 2"    "SendCoreEvents"
    Option      "BlankTime"  "5"
EndSection

SECTION DRI

Cette section facultative est utilisée pour fournir des informations pour l'infrastructure de rendu direct (Direct Rendering Infrastructure). Les détails sur le format de cette section se trouvent en ligne sur https://dri.freedesktop.org/.

SECTION VENDOR

La section facultative Vendor peut être utilisée pour fournir des informations de configuration spécifiques au vendeur. Plusieurs sections Vendor peuvent être présentes, et elles peuvent contenir une entrée Identifier et plusieurs indicateurs Option. Les données qu'elles contiennent ne sont pas utilisées dans cette version.

NOM

xorg.conf - Fichier de configuration du serveur Xorg

INTRODUCTION

Le fichier de configuration Xorg est utilisé pour configurer le serveur Xorg (Xorg.bin). Il contient des informations sur le matériel, les pilotes, les polices de caractères, la disposition de l'écran, etc.

DESCRIPTION

Le fichier de configuration Xorg est généralement situé dans /etc/X11/xorg.conf ou /usr/share/X11/xorg.conf. Il est divisé en plusieurs sections, chacune configurant un aspect spécifique du système X.

SECTION FICHIERS

La section Files spécifie les chemins d'accès aux répertoires contenant les polices de caractères et les modules.

SECTION SERVERFLAGS

La section ServerFlags configure des options générales pour le serveur X, telles que le comportement du serveur au démarrage ou la gestion des événements.

SECTION MODULES

La section Module permet de charger des modules Xorg, qui étendent les fonctionnalités du serveur.

SECTION EXTENSIONS

La section Extensions configure les extensions X, qui fournissent des fonctionnalités supplémentaires pour les applications graphiques.

SECTION INPUTDEVICE

La section InputDevice configure les périphériques d'entrée, tels que les claviers et les souris.

SECTION INPUTCLASS

La section InputClass permet de définir des règles pour la configuration automatique des périphériques d'entrée en fonction de leurs caractéristiques.

SECTION OUTPUTCLASS

La section OutputClass permet de définir des règles pour la configuration automatique des sorties vidéo (moniteurs) en fonction de leurs caractéristiques.

SECTION DEVICE

La section Device configure les cartes graphiques et leurs pilotes associés.

SECTION VIDEOADAPTOR

La section VideoAdaptor configure les adaptateurs vidéo, qui sont généralement des cartes graphiques.

SECTION MONITOR

La section Monitor configure les moniteurs connectés, y compris leurs résolutions et fréquences de rafraîchissement.

SECTION MODES

La section Modes définit les modes d'affichage (résolutions et fréquences de rafraîchissement) qui peuvent être utilisés.

SECTION SCREEN

La section Screen associe une carte graphique (Device) à un moniteur (Monitor) et définit les modes d'affichage disponibles pour cette combinaison.

SOUS-SECTION DISPLAY

La sous-section Display dans la section Screen spécifie la résolution et la profondeur de couleur par défaut.

SECTION SERVERLAYOUT

La section ServerLayout définit la disposition globale des écrans, en spécifiant quel écran est le principal, les écrans secondaires et leur position relative.

SECTION DRI

La section DRI (Direct Rendering Infrastructure) configure l'accès au matériel graphique pour le rendu 3D direct.

SECTION VENDOR

La section Vendor fournit des informations spécifiques au vendeur du matériel graphique.

VOIR AUSSI

Xorg(1), X(7), xorg.conf.d(5).
