NOM

xorriso-dd-target - Évaluateur de périphériques et copieur d'images disque pour GNU/Linux

SYNOPSIS

xorriso-dd-target [ options ] [ noms_périphériques ]

DESCRIPTION

xorriso-dd-target évalue les périphériques blocs du noyau Linux pour déterminer s'ils sont des cibles appropriées pour un fichier image disque et copie éventuellement le fichier image sur l'un d'eux.
Il est spécialisé dans les noms de périphériques du noyau Linux et utilise les capacités du programme lsblk de util-linux. Par conséquent, il refuse de s'exécuter sur des noyaux autres que Linux.

Le but principal de xorriso-dd-target est d'inspecter les fichiers périphériques des supports de stockage de type disque et de juger s'ils ressemblent à des périphériques amovibles avec un contenu jetable.
Si un seul candidat plausible est détecté, le programme est disposé à copier un fichier image disque dessus. Cela écrasera ou rendra inaccessible la table de partitions précédente et tout le contenu précédent du périphérique cible.
Des pouvoirs de superutilisateur sont souvent nécessaires pour l'identification du type de système de fichiers, pour le démontage éventuel et pour l'écriture éventuelle de l'image. L'option -with_sudo offre un moyen d'obtenir ces pouvoirs uniquement pour ces tâches et d'exécuter le programme autrement avec les pouvoirs d'un utilisateur normal.
Si un fichier image disque particulier est destiné à être la source de copie, alors son chemin doit être donné par l'option -image_file, afin que sa taille puisse être utilisée comme critère de décision.

Voici des descriptions de cas d'utilisation avec des exemples :
- Lister les noms de périphériques bruts
- Lister tous les périphériques avec justification
- Évaluer des périphériques donnés particuliers
- Détecter le périphérique visé par branchement
- Écrire une image sur un périphérique conseillé
- Afficher les commandes pour écrire sur un périphérique non conseillé

Lister les noms de périphériques bruts :

Le cas d'utilisation le plus simple et le moins intéressant est une exécution du programme sans noms de périphériques et sans les options -list_all, -plug_test, -DO_WRITE, -dummy_force. Il imprime sur la sortie standard (stdout) uniquement les noms des périphériques conseillables sans le préfixe "/dev/". Un nom par ligne et sans aucun texte de justification.
L'invite éventuelle du mot de passe sudo, le message concernant sudo et la ligne vide après celui-ci ne vont pas sur stdout.
Exemple :
$ xorriso-dd-target -with_sudo
Test de sudo pour obtenir éventuellement le mot de passe maintenant :
[sudo] mot de passe pour thomas :
sudo /bin/lsblk semble OK.

sde

Lister tous les périphériques avec justification :

Pour l'utilisateur plus curieux, il y a l'option -list_all qui imprime l'évaluation de chaque périphérique de type disque listé par le programme lsblk. Les lecteurs optiques, les disquettes, les périphériques blocs de RAM, les périphériques loop sont exclus, cependant.
Chaque périphérique est montré par une ligne de la forme :
nom : conseil : justification : info
nom est le nom du périphérique sans le préfixe "/dev/".
conseil est soit "YES" soit "NO". "YES" indique que le périphérique semble être un disque amovible, non utilisé comme disque système ou stockage de données sincère, et - si testé - de taille suffisante ou plausible.
justification est une liste de mots séparés par des espaces avec le suffixe '+' pour une propriété de périphérique attrayante ou '-' pour une propriété prohibitive. Normalement, une seule raison '-' disqualifie le périphérique d'être conseillé. Seulement si l'option -look_for_iso est donnée, une raison "has_XYZ-" peut être remplacée par la présence d'un système de fichiers ISO 9660 sur le périphérique.
info est composé de VENDOR et MODEL tels que rapportés par lsblk.
L'option -list_long provoque pour chaque ligne une liste supplémentaire des informations fournies par lsblk qui ont conduit aux raisons affichées.
Exemple :
$ xorriso-dd-target -with_sudo -list_all
...
sda : NO : not_usb- has_vfat+ has_ext4- : ATA Samsung SSD 850
sdb : NO : not_usb- has_swap- has_ext4- : ATA WDC WD20EFRX-68A
sdc : YES : usb+ has_iso9660+ has_vfat+ : Intenso Ultra Line
sdd : NO : usb+ has_iso9660+ has_vfat+ has_ext2- : SanDisk Cruzer

Évaluer des périphériques donnés particuliers :

Si des noms de périphériques sont donnés au lieu de l'option -list_all, alors seuls ces périphériques sont inspectés. Leur résultat est listé sans la partie ": info", sauf si l'option -with_vendor_model est donnée.
Les noms de périphériques ne doivent pas commencer par '-' et doivent être des mots uniques composés des caractères [A-za-z0-9_/-]. Ils ne doivent pas contenir '/'. Par exemple, 'sdc' est valide, '/dev/sdc' ne l'est pas.
Si l'un des noms de périphériques donnés n'est pas conseillé, la valeur de sortie est 1.
Il est peu utile de donner des noms de périphériques qui ne sont pas listés par -list_all.
Exemples :
$ xorriso-dd-target -with_sudo sdc
...
sdc : YES : usb+ has_iso9660+ has_vfat+
$ xorriso-dd-target -with_sudo -with_vendor_model sdc
...
sdc : YES : usb+ has_iso9660+ has_vfat+ : Intenso Ultra Line
$ xorriso-dd-target sdc
sdc : NO : usb+ no_fs_while_not_su-

Détecter le périphérique visé par branchement :

L'option -plug_test déclenche une méthode interactive pour déterminer sans ambiguïté le candidat périphérique cible visé. Elle consiste en 2 ou 3 étapes.
Étape 1 consiste à avoir le périphérique de stockage visé débranché et à confirmer cela en appuyant sur la touche Entrée à l'invite du programme. Le programme évaluera alors la liste des périphériques non désirés.
Étape 2 consiste à brancher le périphérique de stockage visé et à confirmer cela en appuyant une seconde fois sur la touche Entrée. Le programme attendra jusqu'à 10 secondes pour un périphérique de stockage de type disque qui n'est pas dans la liste des périphériques non désirés. L'utilisateur peut attendre en appuyant sur la touche jusqu'à ce que le clignotement du périphérique semble être prêt.
Seulement si un seul nouveau périphérique est trouvé, le programme continuera comme si un seul nom de périphérique avait été donné. L'option -list_all et tous les noms de périphériques donnés en arguments seront ignorés.
Étape 3 se produit uniquement si les options -DO_WRITE ou -dummy_force sont données. Le programme demande une saisie finale du mot 'yes' avant que l'écriture réelle ou simulée ne commence.
Exemple :
$ xorriso-dd-target -with_sudo -plug_test
...

Écrire une image sur un périphérique conseillé :

Seulement si l'option -DO_WRITE est donnée et -list_all ne l'est pas, et si exactement un périphérique conseillé est listé, il sera réellement écrasé par le contenu du fichier de -image_file donné. Dans ce cas, la valeur de sortie est zéro si l'écriture a réussi, non nulle sinon.
L'option -dummy empêche ce type d'action réelle et montre plutôt les commandes umount et dd prévues sur stdout.
Exemple :
$ xorriso-dd-target -with_sudo -plug_test -DO_WRITE \
-image_file debian-live-10.0.0-amd64-xfce.iso

NAME

xorriso-dd-target - find storage device for dd, offer safety checks

SYNOPSIS

xorriso-dd-target [options] [device name]

DESCRIPTION

This program helps to choose a proper storage device for the command dd. It analyzes available devices and checks them against several criteria that would make them unsuitable or dangerous targets for writing an image file.

The program runs lsblk to get information about the devices and their filesystems. It interprets the output of lsblk and also the system's knowledge about device types and connection busses.

It prefers USB mass storage devices and memory cards. It warns or refuses to act on devices that look like optical drives, floppy drives, loop devices, RAM disks, or partitions. It also checks size constraints and the presence of filesystems.

If the option -DO_WRITE is given, it may perform write operations like unmounting partitions and using dd to write an image file. This is a dangerous operation that can destroy data on the target device.

The option -dummy can be used to see what commands would be executed without actually performing them.

Safety and Potential Misuse:

xorriso-dd-target tries to prevent accidental data loss by advising against writing to unsuitable devices. However, the user is ultimately responsible for the choice of the target device.

The outmost complicity to potentially unwise actions is offered by option -dummy_force. If given together with a single device name or with option -plug_test it will act like -dummy -DO_WRITE with this device, even if it looks not advisable. I.e. it will show the shell commands which the program does not dare to perform.

Example:

$ xorriso-dd-target -with_sudo -list_long -dummy_force sdd \
  -image_file debian-live-10.0.0-amd64-xfce.iso
...
sdd : NO : usb+ has_iso9660+ has_vfat+ has_ext2-
NAME SIZE FSTYPE TRAN LABEL
sdd 3.8G iso9660 usb d-live 9.5.0 xf i386
|-sdd1 1.9G iso9660 d-live 9.5.0 xf i386
|-sdd2 320K vfat
`-sdd3 512M ext2

Overriding any advice because of -dummy_force
Looking for mount points of sdd:
/dev/sdd1 on /mnt/iso type iso9660 (ro,relatime)
/dev/sdd2 on /mnt/fat type vfat (rw,...,errors=remount-ro)
/dev/sdd3 on /mnt/ext type ext2 (rw,relatime)
AGAINST THE ADVICE BY THIS PROGRAM, a daring user could do:
sudo /bin/umount /dev/sdd1

Alphabetical List of positive and negative reasons:

As stated with use case "List all devices", reasons are words with either suffix '+' for an inviting device property or '-' for a prohibitive property.
Normally a single '-' reason disqualifies the device from being advisable.

has_XYZ-
A filesystem of type XYZ is detected on base device or partition and is spoiling the impression of a device with disposable content.
has_iso9660+
An ISO 9660 filesystem is detected.
has_vfat+
A FAT (MS-DOS-like) filesystem is detected.
look_for_iso++
Option -look_for_iso is given and an ISO 9660 filesystem is detected. This reason overrides any "has_XYZ-" reason.
looks_like_cd_drive-
A given device name looks like the name of an optical drive: sr[0-9]*. Use program xorrecord for this kind of devices.
looks_like_disk_partition-
A given device name looks like the name of a partition. Expected are names of base devices, like "sde", not of their partitions, like "sde1".
looks_like_floppy-
A given device name looks like the name of a floppy disk drive: fd[0-9]*.
looks_like_loopdev-
A given device name looks like the name of a loop device: loop[0-9]*.
looks_like_ramdev-
A given device name looks like the name of a RAM block device: zram[0-9]*.
lsblk_no_size-
A size test is given by -max_size, -min_size, or -image_file but the size of the device cannot be inquired by lsblk. This is supposed to happen only with given inappropriate device names.
mmcblk+
The device name looks like a directly connected memory card.
name_with_slash-
A given device name contains '/' characters.
no_bus_info-
The device is not a memory card and lsblk reports nothing about the way how it is connected to the computer.
no_fs_while_not_su-
No filesystem is reported by lsblk and the program does not believe to have run it with superuser powers. There is the risk that lsblk silently failed to detect existing filesystems.
no_iso9660-
Option -look_for_iso is given but no ISO 9660 filesystem is detected.
not_usb-
The device is not a memory card and lsblk reports that it is connected by something other than USB.
size_too_large-
Option -max_size is given with a size smaller than the size of the device.
size_too_small-
Option -min_size or -image_file is given with size or file size larger than the size of the device.
usb+
The device is reported by lsblk to be connected via USB.

OPTIONS

-plug_test
Find the target device by asking the user to press the Enter key when the desired target is _not_ plugged in, to then plug it in, and to press Enter again.
This overrides device names and option -list_all. The found device is then shown with advice, vendor, and model.
Option -DO_WRITE is obeyed if given. In this case, the word 'yes' has to be entered to let unmounting and writing begin.
-list_all
Print list of all found devices with advice, vendor and model. One per line. Ignore any device names. Ignore -DO_WRITE.
-list_long
After each result line, which shows reasons, add an additional listing of the information provided by lsblk which led to the reasons and add an empty line.
-with_vendor_model
Print vendor and model with each submitted device name.
-max_size n[M|G|T]
Set the upper byte size limit for advisable devices. Plain numbers get rounded down to full millions. As suffix are recognized: M = million, G = billion, T = trillion.
Be generous to avoid problems with GB < GiB.
-min_size n[M|G|T]
Set the lower byte size limit for advisable devices. After processing like with -max_size, one million gets added to the size limit.
-look_for_iso
Demand presence of an ISO 9660 filesystem. If so, then any further filesystem type is acceptable on that device.
If this option is missing, only ISO 9660 and VFAT filesystems are accepted.
-with_sudo
Run 'lsblk -o FSTYPE' by sudo. If no filesystems are detected on a device while the program has no superuser power, then the device is not advised. Option -with_sudo avoids this refusal without the need to run the whole program as superuser.
If -DO_WRITE -with_sudo is given, then the programs umount and dd will be run by sudo, too.
-trust_lsblk_udev
Suppress the reason no_fs_while_not_su- if lsblk is linked with libudev.so. In this case it is likely that lsblk can retrieve FSTYPE even if run by a non-priviledged user.
This option is intended for use by frontend programs which are certain that they do not encounter a udev-using version of lsblk which nevertheless fails to detect existing filesystems. Human users should better acquire superuser powers if reason no_fs_while_not_su- is reported.
-image_file PATH
Set the path of the image file which shall be written to a device. Its size will be set as -min_size.
-DO_WRITE
Write the given -image_file to the one advisable device that is found. If more than one such device is found, then they get listed but no writing happens.
In this case, to get a real write run, consider unplugging unneeded devices, or using option -plug_test, or a re-run with one of the advised device names as additional argument.
-no_pacifier
Do not use dd options to print progress messages and to perform synchronized output. These options are used by default if program dd offers progress messages.
-dummy
Report the -DO_WRITE actions but do not perform them.
-dummy_force
If a single device name is given, do a run of -dummy -DO_WRITE even against the advice of this program. This probably shows you ways to shoot your own foot.
-version
Print the program name, version text, and timestamp to stdout and then end the program.
-help
Print the help text to stdout and then end the program.
