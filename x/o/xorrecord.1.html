XORRECORD(1) Manuel des commandes générales XORRECORD(1)

NOM

xorrecord - Émulation du programme de gravure CD/DVD/BD cdrecord par le programme xorriso

SYNTAXE

xorrecord [ options ] dev=périphérique [source_piste]

DESCRIPTION

xorrecord écrit des données préformatées sur des supports CD, DVD et BD.

Il comprend certaines options du programme cdrecord de cdrtools par Joerg Schilling. Son implémentation fait partie du programme xorriso qui ne partage aucun code source avec cdrtools, mais utilise plutôt libburn pour communiquer avec le graveur.
Un autre émulateur cdrecord, plus complet, est le programme cdrskin qui utilise les mêmes fonctions de gravure que xorrecord, mais est capable de graver des CD audio et de gérer le CD-TEXT.

Types de médias, sessions, pistes et formats MMC :

MMC est une norme de la famille SCSI qui définit l'interaction entre les ordinateurs et les lecteurs optiques. Depuis plus d'une décennie, tous les graveurs de CD, DVD ou BD respectent cette norme, quel que soit le bus de connexion à l'ordinateur. libburn s'appuie sur cette conformité et sur la capacité du système d'exploitation à effectuer des transactions SCSI sur le câblage du bus particulier.
Une Session est une région de données sur un disque optique qui est généralement gravée en une seule fois. Elle contient au moins une Piste qui est une séquence continue de blocs lisibles. xorrecord produit une seule session avec une seule piste de données constituée de blocs de 2048 octets chacun. Il choisit automatiquement le mode d'écriture en fonction du type de média, de l'état du support et de l'option -multi.
Sur les supports CD, il existe d'autres types de pistes, comme l'audio, et des modes d'écriture particuliers comme TAO et SAO. Les supports CD et DVD- peuvent contenir plusieurs pistes dans une session. Certaines de ces fonctionnalités peuvent être gérées par le programme cdrskin.
MMC décrit plusieurs types de médias enregistrables qui forment globalement deux familles.
Les supports enregistrables séquentiellement sont CD-R, CD-RW, DVD-R, DVD-R DL, DVD-RW, DVD+R, DVD+R DL, BD-R. À l'exception de DVD-R DL, ils peuvent stocker plusieurs sessions s'il reste de l'espace non gravé et si la session précédente a été gravée avec l'option -multi. CD-RW et DVD-RW peuvent être effacés pour être réutilisés à partir de zéro.
Les supports réinscriptibles sont DVD-RAM, DVD+RW, DVD-RW formaté, BD-RE. Ils offrent une seule session avec une seule piste pour une écriture à accès aléatoire. Il n'est pas nécessaire d'effacer les supports réinscriptibles avant de les réutiliser.
Les supports DVD-RW sont vendus à l'état enregistrable séquentiellement mais peuvent être formatés une fois pour devenir réinscriptibles. Voir les options blank=format_overwrite et blank=deformat.
Si des systèmes de fichiers ISO 9660 doivent être stockés sur des supports réinscriptibles, il est alors possible d'émuler plusieurs sessions en utilisant l'option --grow_overwriteable_iso. Dans ce cas, la nécessité d'effacer avant la réutilisation est également émulée.

Préparation et adressage du graveur :

Les graveurs CD, DVD ou BD sont accessibles via des adresses de fichiers spécifiques à libburn et au système d'exploitation. Ces adresses sont listées par une exécution de xorrecord --devices ou xorriso -device_links.
Sur GNU/Linux, FreeBSD et NetBSD, l'utilisateur a besoin de la permission rw pour le fichier périphérique. Sur Solaris, l'utilisateur a besoin de la permission r et du privilège "sys_devices", qui est généralement obtenu en exécutant xorrecord via la commande pfexec.
Ces permissions ou privilèges sont déjà nécessaires pour lister un graveur. Il peut donc être nécessaire d'obtenir l'aperçu en tant que superutilisateur ou via pfexec.
xorrecord n'effectue pas l'option -scanbus de cdrecord et n'accepte pas les adresses du type Bus,Cible,Lun indiquées par -scanbus. Si le support de ces adresses est nécessaire, envisagez d'utiliser le programme cdrskin.
Il est possible de faire fonctionner xorrecord sur des graveurs émulés. Leurs adresses commencent par le préfixe "stdio:" suivi d'une adresse de fichier. Le comportement du support émulé dépend du type de fichier. Voir le manuel de xorriso pour plus de détails.
Si la sortie standard est choisie comme graveur émulé, alors tous les textes de résultat du programme, qui apparaissent normalement sur la sortie standard, seront redirigés vers la sortie d'erreur standard.

Relation avec le programme xorriso :

xorrecord est en fait un mode de commande du programme xorriso, qui est activé soit par la commande xorriso "-as cdrecord", soit en lançant le programme sous l'un des noms "xorrecord", "cdrecord", "wodim" ou "cdrskin".
Ce mode de commande peut être quitté par l'argument "--" qui mène au mode de commande générique de xorriso. Voir man xorriso pour sa description. Contrairement au mode de commande de xorriso, la séquence des options d'émulation cdrecord n'a pas d'importance. Toutes les actions en attente sont effectuées dans un ordre fixe avant la fin de l'exécution du programme ou avant la fin de l'émulation cdrecord.

OPTIONS

Adressage du graveur :
--devices
Affiche la liste des graveurs CD, DVD ou BD accessibles sur la sortie standard. Les graveurs peuvent être inaccessibles si l'utilisateur n'a pas les permissions pour les utiliser ou si le graveur est utilisé par un autre programme.
Chaque graveur accessible est affiché sur une ligne comme suit :
0 -dev '/dev/sr0' rwrw-- : 'TSSTcorp' 'CDDVDW SH-S203B'
L'adresse libburn de ce graveur est '/dev/sr0'. 'TSSTcorp' est le nom du fabricant (dans ce cas : Toshiba Samsung Storage Technologies Corporation), 'CDDVDW SH-S203B' est le nom du modèle (dans ce cas : un graveur DVD).
Ensuite, met fin à l'émulation sans effectuer d'autres opérations sur le graveur.
dev=adresse_graveur
Définit l'adresse libburn du graveur à utiliser.
Exemple sur GNU/Linux : dev=/dev/sr0
Exemple sur FreeBSD : dev=/dev/cd0
Exemple sur NetBSD : dev=/dev/rcd0d
Exemple sur Solaris : dev=/dev/rdsk/c2t2d0s2
Voir aussi ci-dessus "Préparation et adressage du graveur".
Le support dans le graveur ne doit pas être monté ou être utilisé autrement.
Cette option ne sera effective que si une source de piste, une option blank= ou une option d'interrogation du graveur est fournie. Sinon, elle entraînera un événement SORRY et provoquera normalement une valeur de sortie non nulle.
Interrogation du graveur et du support :
-inq
Affiche sur la sortie standard : le fabricant, le nom du modèle et la révision du firmware du graveur.
-checkdrive
Affiche sans condition que le graveur prend en charge burnfree, SAO et TAO. Affiche également la sortie de l'option -inq.
-atip
Affiche la sortie de -checkdrive, le profil le plus performant du support dans le graveur, la liste des profils supportés par le graveur, s'il est effaçable (c'est-à-dire qu'il peut être effacé), le fabricant du support et le nom du produit du support.
Les profils sont des modèles d'utilisation, souvent liés à un type de support particulier (par exemple, CD-RW), mais peuvent également s'appliquer à une famille de supports. Par exemple, le profil CD-ROM s'applique à tous les supports CD contenant des données.
-toc
Affiche une table des matières du support dans le graveur. La sortie n'est pas compatible avec l'option -toc de cdrecord, mais plutôt avec celle de la commande xorriso -toc. Elle liste l'adresse, le fabricant, le nom du modèle et la révision du firmware du graveur.
Concernant le support, elle indique le nom du produit et le fabricant, s'il y a déjà du contenu gravé, et si c'est le cas, si le support est fermé ou ajoutable. Les supports ajoutables peuvent recevoir une autre session. La quantité de données lisibles et gravables est indiquée. S'il y a des sessions, leur adresse de début et leur taille sont rapportées. Si une session contient un système de fichiers ISO 9660, son identifiant de volume est rapporté. Si le support est inscriptible, l'adresse du prochain bloc inscriptible est rapportée.
Si l'option --grow_overwriteable_iso n'est pas donnée ou si aucun système de fichiers ISO 9660 n'est présent sur le support, les supports réinscriptibles sont signalés comme étant vierges. Ceci est dû au fait qu'ils peuvent être gravés à partir de zéro sans préparation supplémentaire, et que MMC ne fait pas de distinction entre les données gravées lors de la dernière opération de gravure et les données plus anciennes qui n'ont pas été écrasées par cette opération. -msinfo
Imprimer le texte de l'argument pour l'option -C des programmes mkisofs, genisoimage ou xorrisofs. Il est constitué de deux nombres séparés par une virgule.
Le premier nombre indique le premier bloc de la première piste de la dernière session enregistrée. C'est aussi l'adresse utilisée par défaut lorsque les systèmes d'exploitation montent un média avec par exemple un système de fichiers ISO 9660.
Le second nombre indique l'adresse inscriptible suivante, où xorrecord commencera à écrire la prochaine session.
Cette option n'est valide que pour les médias enregistrés et ajoutables. Dans tous les autres cas, elle ne produira aucune sortie texte mais terminera le programme avec une valeur de sortie non nulle.
Paramètres pour la gravure :

Une opération de gravure nécessite exactement un argument de source de piste, qui indique d'où lire les données à mettre dans la prochaine session. L'état du média doit être vierge ou ajoutable.
La source de piste peut être "-" pour l'entrée standard ou l'adresse d'un fichier lisible de tout type sauf les répertoires. Presque tous les types de médias acceptent une source de piste d'un nombre d'octets imprévisible, comme l'entrée standard ou les pipes nommés. Néanmoins, les DVD-R DL et les DVD-RW effacés avec le mode deformat_quickest demandent une réservation exacte à l'avance de la taille de la piste, de sorte qu'ils nécessitent soit d'être lus à partir d'une source de longueur prévisible, soit d'être accompagnés de l'option tsize= ou de l'option -isosize.
Plusieurs options attendent une valeur de taille comme argument. Un nombre avec une lettre finale "b" ou sans lettre finale est un simple nombre d'octets. D'autres lettres finales provoquent la multiplication du nombre donné par un facteur d'échelle :
"k" ou "K" = 1024 , "m" ou "M" = 1024k , "g" ou "G" = 1024m , "s" ou "S" = 2048
Par exemple, tsize=234567s signifie une taille de 234567 * 2048 = 480393216 octets.

blank=mode
Effacer un CD-RW ou un DVD-RW pour le rendre réutilisable à partir de zéro. Formater un DVD-RW, DVD+RW, DVD-RAM, BD-R ou BD-RE s'il n'est pas encore formaté.
Cette opération rend normalement toutes les données enregistrées sur le média illisibles. Elle peut être combinée avec la gravure dans la même exécution de xorrecord, ou être effectuée sans source de piste, laissant le média vide.
Le mode donné avec blank= sélectionne le comportement particulier :

as_needed
Essayer de rendre le média prêt pour l'écriture à partir de zéro. S'il nécessite un formatage, alors le formater. S'il n'est pas vierge, alors essayer d'appliquer blank=fast. Il est raisonnable d'avorter si le média ne peut pas assumer un état complètement inscriptible, par exemple s'il s'agit d'un support non vierge inscriptible une seule fois.
Cela laisse les DVD-RW non formatés dans un état vierge non formaté. Pour formater un DVD-RW, utiliser blank=format_overwrite. Les BD-R vierges non formatés restent non formatés.
(Note : blank=as_needed n'est pas une option originale de cdrecord.)
all
Effacer un CD-RW entier ou un DVD-RW non formaté.
fast
Effacer un minimum un CD-RW entier ou effacer un DVD-RW non formaté.
deformat
Comme blank=all mais avec la capacité supplémentaire d'effacer les DVD-RW réinscriptibles. Cela détruira leur formatage et les rendra enregistrables séquentiellement.
(Note : blank=deformat n'est pas une option originale de cdrecord)
deformat_quickest
Comme blank=deformat mais efface les DVD-RW uniquement de manière minimale. C'est plus rapide qu'un effacement complet mais produit des médias incapables d'écrire des pistes de taille imprévisible. La multi-session ne sera pas non plus possible.
(Note : blank=deformat_quickest n'est pas une option originale de cdrecord.)
format_overwrite
Formater un DVD-RW en "Restricted Overwrite". L'utilisateur doit faire preuve de patience.
Formater un DVD+RW, BD-RE ou BD-R non formaté à sa taille par défaut. Il n'est pas obligatoire de le faire avec les médias DVD+RW et BD-RE, car ils seront formatés automatiquement lors de la première tentative d'écriture.
Les médias BD-R peuvent être écrits dans un état non formaté. Cela désactive le remplacement des blocs défectueux et permet la vitesse d'écriture nominale maximale. Une fois les médias BD-R gravés, ils ne peuvent plus être formatés.
Pour reformater des médias déjà formatés ou pour formater avec une taille non par défaut, utiliser le programme xorriso avec la commande -format.
(Note : blank=format_overwrite n'est pas une option originale de cdrecord)
help
Afficher un bref aperçu des modes d'effacement sur la sortie d'erreur standard.
Ensuite, terminer l'émulation sans effectuer d'opération sur le lecteur.
-multi
Cette option maintient les CD, les DVD-R[W] non formatés, les DVD+R ou les BD-R ajoutables après l'écriture de la session en cours. Sans elle, le disque est fermé et ne peut plus être écrit - sauf s'il s'agit d'un -RW et qu'il est effacé, ce qui entraîne la perte de son contenu.
Cette option ne peut pas être appliquée aux DVD-R DL ou aux DVD-RW qui ont été effacés par le mode "deformat_quickest". L'option --multi_if_possible peut automatiquement reconnaître et gérer cette situation.
Afin d'avoir accès à l'intégralité du contenu du système de fichiers, le système de fichiers ISO-9660 éventuel d'une session ultérieure doit être préparé d'une manière spéciale par le programme de formatage du système de fichiers. mkisofs, genisoimage et xorrisofs attendent des informations particulières sur la situation qui peuvent être récupérées par l'option -msinfo de xorrecord.
Avec les médias DVD ou BD réinscriptibles, -multi ne peut pas marquer la fin de la session. Donc, lors de l'ajout d'une nouvelle session, cette fin doit être déterminée à partir de la charge utile. Actuellement, seuls les systèmes de fichiers ISO-9660 peuvent être utilisés de cette manière. Voir l'option --grow_overwriteable_iso.
-dummy
Essayer d'effectuer les opérations du lecteur sans affecter réellement le média inséré. Il n'y a aucune garantie que cela fonctionne avec une combinaison particulière de lecteur et de média. L'effacement est cependant évité de manière fiable. Pour éviter toute gravure réelle accidentelle, -dummy refuse les opérations de gravure sur autre chose que des CD-R[W], DVD-R[W], ou des lecteurs stdio émulés.
-waiti
Attendre que les données d'entrée soient disponibles sur stdin ou que l'EOF se produise sur stdin. Seulement alors commencer à accéder aux lecteurs.
Il faut utiliser ceci si xorrisofs travaille à la fin d'un pipe où le processus d'alimentation lit depuis le lecteur avant de commencer à écrire sa sortie dans xorrisofs. Exemple :
xorrisofs ... -C 0,12800 -M /dev/sr0 ... | \
xorrecord dev=/dev/sr0 ... -waiti -
Cette option fonctionne même si l'entrée standard n'est pas la source de la piste. Si aucun processus n'envoie de données, alors la touche Entrée de votre terminal agira comme déclencheur pour xorrecord. Notez que cette ligne d'entrée ne sera pas consommée par cdrskin si l'entrée standard n'est pas la source de la piste. Elle finira par être une commande shell, généralement.
tsize=taille
Annoncer la taille exacte de la source de la piste. Ceci est nécessaire avec les médias DVD-R DL et les DVD-RW effacés le plus rapidement possible, si la taille ne peut pas être déterminée à l'avance à partir de la source de la piste. Par exemple, s'il s'agit de l'entrée standard ou d'un pipe nommé.
Si la source de piste ne fournit pas la quantité d'octets prédite, le reste de la piste est complété par des zéros. Ceci n'est pas considéré comme une erreur. Si, en revanche, la source de piste fournit plus d'octets que ceux annoncés, la piste sur le média sera tronquée à la taille prédite et xorrecord se terminera avec une valeur non nulle.
-isosize
Essayer d'obtenir la taille de la piste à partir du contenu de la source de la piste. Ceci ne fonctionne que si la source de la piste contient un système de fichiers ISO 9660. Tout autre contenu de source de piste provoquera l'échec de l'opération de gravure.
Si la source de piste n'est pas un fichier régulier ou un périphérique bloc, alors cette option ne fonctionnera que si la taille du fifo du programme est d'au moins 64k. Voir l'option fs=.
padsize=taille
Ajouter la quantité donnée de zéros de fin à la piste à venir. Cette fonctionnalité peut être désactivée par la taille 0. Par défaut, c'est 300 kB afin de contourner un problème avec GNU/Linux qui échoue souvent à lire les derniers blocs d'une piste de CD gravée en mode d'écriture TAO. TAO est utilisé par xorrecord si la taille de la piste ne peut pas être prédite ou si le média CD n'est pas vierge mais ajoutable.
-nopad
Identique à padsize=0.
-pad
Identique à padsize=15s. C'était autrefois suffisant avec les anciens noyaux GNU/Linux. Entre-temps, il faut au moins utiliser padsize=128k, sinon padsize=300k.
-data
Annoncer explicitement que la source de la piste doit être enregistrée en tant que piste de données, et non en tant que piste audio. Cette option n'a aucun effet avec xorrecord, car il n'y a de toute façon aucun support pour d'autres formats de piste.
-tao
Demander explicitement que le type d'écriture TAO soit utilisé pour les CD, ou Incrémental pour les DVD-R. Normalement, le programme choisira le type d'écriture en fonction de l'état du média donné, de l'option -multi et de la source de la piste. Le demander explicitement empêche le démarrage d'une opération d'écriture si elle n'est pas appropriée à la situation.
-sao
Demander explicitement que le type d'écriture SAO soit utilisé pour les CD, ou DAO pour les DVD-R. Cela pourrait empêcher l'opération d'écriture si elle n'est pas appropriée à la situation.
-dao
Alias de -sao.
fs=taille
Définir la taille du buffer fifo du programme à la valeur donnée plutôt que par défaut de 4m.
Le fifo met en mémoire tampon un surplus temporaire de données de la source de la piste afin de fournir un flux constant au lecteur pendant les périodes de manque temporaire d'approvisionnement de la source de piste.
Contrairement à cdrecord, xorrecord active la protection contre les sous-débits du buffer du lecteur par défaut et n'attend pas que le fifo soit plein pour la première fois avant d'écrire. Sur de très anciens lecteurs CD et des ordinateurs lents, cela pourrait entraîner des échecs d'opération de gravure. Dans ce cas, envisagez d'utiliser le programme cdrskin pour la gravure de CD. Les lecteurs DVD et BD tolèrent les sous-débits sans problème.
Plus le fifo est grand, plus les périodes de faible approvisionnement de la source peuvent être compensées. Mais un grand fifo peut priver le système d'exploitation du cache de lecture pour de meilleures performances du système de fichiers.
vitesse=valeur
Définir la vitesse d'écriture. La valeur par défaut est 0 = vitesse maximale. La vitesse peut être donnée en nombres x-speed dépendant du type de média ou en débit souhaité par seconde en kB (1000) ou MB (1000 kB) conformes MMC. Le facteur x-speed du média peut être défini explicitement en ajoutant "c"{ "description": "\" pour CD, \"d\" pour DVD, \"b\" pour BD. \"x\" est facultatif.\n
\n Exemples de vitesses :\n
\n 706k = 706 Ko/s = 4c = 4xCD\n
\n 5540k = 5540 Ko/s = 4d = 4xDVD\n
\n S'il n'y a pas d'indication de l'unité de vitesse, le support dans le\n lecteur décidera. L'unité par défaut est CD, 1x = 176 400 octets bruts/seconde.\n Avec DVD, 1x = 1 385 000 octets/seconde. Avec BD, 1x = 4 495 625 octets/seconde.\n
\n Les lecteurs MMC activent généralement leur propre idée de la vitesse et ne prennent\n la valeur de vitesse donnée par le programme de gravure que comme un indice pour leur\n propre décision.

Options non\n compatibles avec cdrecord :
\n
\n
--no_rc
\n
Uniquement si utilisée comme premier argument de ligne de commande, cette option empêche\n la lecture et l'interprétation des fichiers de démarrage. Voir la section FICHIERS ci-dessous.
\n
--drive_not_exclusive
\n
Cette option désactive l'utilisation des mécanismes de verrouillage de fichier de périphérique\n lors de l'acquisition du lecteur. Sur GNU/Linux, le verrouillage est effectué par open(O_EXCL),\n sur FreeBSD par flock(LOCK_EX).\n
\n Attention, cela peut causer des problèmes si vous utilisez un lecteur qui est monté, ou\n ouvert par un autre processus, ou protégé par /dev/pktcdvd*. Assurez-vous que les\n autres utilisateurs du lecteur ne provoquent pas d'activités sur le lecteur pendant\n une exécution de gravure de xorrecord.
\n
drive_scsi_dev_family=sr|scd|sg|default
\n
Spécifique à GNU/Linux :\n
\n Par défaut, cdrskin essaie de mapper les adresses de lecteur Linux à /dev/sr* avant\n qu'elles ne soient ouvertes pour l'exploitation du lecteur. Cela se coordonne bien avec\n d'autres utilisations des lecteurs optiques, comme mount(8). Mais depuis 2010, tous les\n /dev/sr* partagent un verrou global qui ne permet qu'à un seul lecteur de traiter une\n commande SCSI pendant que tous les autres doivent attendre sa complétion. Cela entraîne\n un débit horrible si plusieurs lecteurs écrivent ou lisent simultanément.\n
\n Le verrou global ne s'applique pas aux fichiers de périphériques /dev/sg* ni aux\n appels système read(2), write(2). Mais ioctl(SG_IO) est affecté, ce qui est nécessaire\n pour effectuer les commandes SCSI pour la gravure optique.\n
\n Ainsi, pour des gravures simultanées sur des GNU/Linux modernes, il est conseillé d'utiliser\n drive_scsi_dev_family="sg". Les adresses des lecteurs peuvent alors être données\n comme /dev/sr*, mais seront néanmoins utilisées comme /dev/sg*.
\n
--grow_overwriteable_iso
\n
Activer l'émulation d'écriture multi-sessions sur des supports réinscriptibles contenant un\n système de fichiers ISO 9660. Cette émulation est apprise de growisofs -M mais adaptée\n au modèle d'utilisation de\n
\n xorrecord -msinfo\n
\n xorrisofs -C -M | xorrecord -waiti -multi -\n
\n pour les supports séquentiels.\n
\n --grow_overwriteable_iso n'entrave pas l'utilisation de vrais supports multi-sessions.\n Autrement dit, il est possible d'utiliser les mêmes options xorrecord avec les deux\n types de supports et d'obtenir des résultats similaires si des images de système de fichiers\n ISO 9660 doivent être écrites. Cette option implique l'option -isosize et demande\n donc que la source de la piste soit une image de système de fichiers ISO 9660.\n
\n Avec des supports réinscriptibles et sans l'option blank=fast|all, elle développe un éventuel\n système de fichiers ISO 9660 sur le support. On suppose que la description de la taille interne\n de cette image pointe vers la fin des données valides. Les supports réinscriptibles avec une\n taille ISO 9660 reconnaissable seront considérés comme ajoutables plutôt que vierges.\n Autrement dit, les options -msinfo et -toc fonctionneront. -toc affichera toujours une seule\n session dont la taille augmentera à chaque image ISO 9660 ajoutée.
\n
--multi_if_possible
\n
Appliquer l'option -multi si le support est approprié. Ne sont pas appropriés les DVD-R DL\n et DVD-RW, qui ont été effacés avec le mode \"deformat_quickest\".\n
\n Tous les lecteurs ne reconnaissent pas correctement ces DVD-RW effacés rapidement qui nécessitent\n \"on\". S'il y a une suspicion fondée qu'une gravure a échoué en raison de -multi, cela\n provoque une nouvelle tentative sans -multi.
\n
stream_recording="on"|"off"|nombre
\n
Le mode \"on\" demande que la conformité au réglage de vitesse souhaité soit préférée à la\n gestion des erreurs d'écriture. Avec DVD-RAM et BD, cela peut rapprocher la vitesse\n d'écriture effective de la vitesse d'écriture nominale des supports. Mais cela désactivera\n également l'utilisation automatique des blocs de remplacement si des erreurs d'écriture surviennent.\n Cela pourrait également être mal supporté ou ignoré par le lecteur.\n
\n Si un nombre est donné, la gestion des erreurs reste activée pour toutes les adresses d'octets\n en dessous de ce nombre. Tout nombre inférieur à 16s est identique à \"off\".
\n
dvd_obs="default"|"32k"|"64k"
\n
Définir le nombre d'octets à transmettre à chaque opération d'écriture sur des supports DVD\n ou BD. Avec la plupart des types d'écriture, les pistes sont complétées jusqu'au prochain\n multiple de cette taille d'écriture (voir l'option --obs_pad). Un nombre de 64 Ko peut\n améliorer le débit sur les systèmes de bus qui présentent des problèmes de latence. La\n valeur par défaut dépend du type de support, de l'option stream_recording=, et des\n options de compilation.
\n
--obs_pad
\n
Compléter les données de la dernière opération d'écriture d'une session DVD-R[W] DAO, ou\n d'une session BD-R, ou d'une session pseudo-lecteur stdio:, jusqu'à la taille complète\n d'un bloc de sortie. Cette complétion doit être appliquée automatiquement aux autres\n types de supports DVD et BD, où elle provoque par exemple que les images ISO aient des\n blocs excédentaires non attribués. Son application automatique aux BD-R dépend de l'option\n --bdr_obs_exempt.\n
\n Utilisez cette option s'il y a une suspicion que les sessions DVD-R[W] DAO ou BD-R\n s'interrompent avec votre noyau et/ou lecteur DVD, si leur taille n'est pas un multiple\n de 16 blocs.\n
\n Cette option peut également être activée lors de la compilation de libburn.
\n
--bdr_obs_exempt
\n
Exempter les supports BD-R du remplissage inconditionnel automatique de fin de transaction,\n à condition que ce remplissage ne soit pas demandé par --obs_pad et qu'aucun\n stream_recording ne soit demandé.\n
\n C'est une nouvelle fonctionnalité introduite avec la version 1.5.6. Elle pourrait devenir\n par défaut dans les versions ultérieures.
\n
modesty_on_drive=paramètre[:paramètres]
\n
Contrôler si le tampon du lecteur doit être empêché d'être complètement rempli. Le paramètre\n \"on\" (ou \"1\") empêche le programme d'essayer d'écrire sur le graveur pendant que son tampon\n risque d'être rempli au-delà d'une limite donnée. Si ce remplissage est dépassé, le programme\n attendra jusqu'à ce que le remplissage atteigne une valeur de pourcentage basse donnée.\n
\n Cela peut alléger la charge sur le système d'exploitation et le contrôleur du lecteur et ainsi\n aider à obtenir une meilleure bande passante d'entrée si le disque et le graveur ne sont pas\n sur des contrôleurs indépendants (comme hda et hdb). Cela peut également aider pour les\n gravures simultanées sur différents graveurs avec des noyaux Linux comme 3.16, si l'on a\n une raison de ne pas résoudre le problème par\n drive_scsi_dev_family="sg". D'un autre côté, cela augmente le risque de sous-flux du\n tampon et donc une vitesse d'écriture réduite.\n
\n Certains graveurs ne conviennent pas car ils signalent le remplissage du tampon avec une\n granulométrie trop grossière en taille ou en temps, ou s'attendent à ce que leur tampon soit\n rempli à son maximum avant de passer à pleine vitesse.\n
\n Les paramètres \"off\" ou \"0\" désactivent cette fonctionnalité.\n
\n Le seuil pour commencer à attendre est donné par le paramètre\n \"max_percent=\". Le paramètre \"min_percent=\" définit le seuil pour reprendre la transmission.\n Les pourcentages sont admissibles dans la plage de 25 à 100. Les nombres dans cette plage\n sans nom préfixé sont interprétés comme \"on:min_percent=\".\n
\n Exemple : modesty_on_drive=75\n
\n Les valeurs optimales dépendent du comportement du tampon du lecteur.\n
\n Le paramètre \"timeout_sec=\" définit le temps d'attente infructueuse après lequel la modestie\n sera désactivée car elle ne fonctionne pas.\n
\n Le paramètre \"min_usec=\" définit la période de veille initiale en microsecondes. Si le\n tampon du lecteur semble trop plein pour envoyer plus de données, le programme attendra\n le temps donné et vérifiera à nouveau l'état du remplissage du tampon. Si des vérifications\n répétées montrent un espace libre insuffisant, le temps de veille augmentera lentement\n pour atteindre ce que le paramètre \"max_usec=\" définit.\n
\n Paramètres, qui ne sont pas mentionnés avec un mode" } sty_on_drive= option, rester inchangé. La valeur par défaut est :
modesty_on_drive=off:min_percent=90:max_percent=95:
timeout_sec=120:min_usec=5000:max_usec=25000
use_immed_bit="on"|"off"|"default"
Contrôle si plusieurs commandes SCSI de longue durée doivent être exécutées avec le bit Immed, ce qui fait que les commandes se terminent tôt pendant que l'opération du lecteur est encore en cours. xorriso interroge ensuite l'indication de progression jusqu'à ce que le lecteur signale qu'il est à nouveau prêt. Si cette fonctionnalité est désactivée, le nettoyage et le formatage n'afficheront aucune indication de progression.
Il peut dépendre du système d'exploitation que -use_immed_bit soit défini sur "off" par défaut.
write_start_address=value
Définit l'adresse de bloc sur le support réinscriptible où commencer l'écriture de la piste. Avec DVD+RW, DVD-RAM ou BD-RE, byte_offset doit être aligné sur des blocs de 2 KiB, mais il est préférable d'utiliser 32 KiB sur DVD et 64 KiB sur BD. Avec un DVD-RW formaté, un alignement de 32 KiB est obligatoire.
Les autres supports ne conviennent pas à cette option.
stdio_sync="on"|"off"|nombre
Définit le nombre d'octets après lequel forcer la sortie vers les lecteurs emulés stdio : Cela évite que la mémoire ne soit encombrée par une grande quantité de données en attente pour des périphériques lents. La valeur par défaut "on" est identique à "16m". La sortie forcée peut être désactivée par "off".

EXEMPLES

Aperçu des exemples :

Obtenir un aperçu des lecteurs et de leurs adresses
Obtenir des informations sur un lecteur particulier ou un média chargé
Préparer un CD-RW ou un DVD-RW pour réutilisation, un BD-R pour la gestion des blocs défectueux
Formater un DVD-RW pour éviter le besoin de le nettoyer avant réutilisation
Déformater un DVD-RW pour le rendre à nouveau capable de plusieurs sessions
Écrire une seule image de système de fichiers ISO 9660
Écrire plusieurs sessions ISO 9660
Écrire une session ISO 9660 à la volée
Écrire une archive afio compressée à la volée

Obtenir un aperçu des lecteurs et de leurs adresses :


$ xorrecord --devices

Obtenir des informations sur un lecteur particulier et un média chargé :


$ xorrecord dev=/dev/sr0 -atip -toc --grow_overwriteable_iso

Préparer un CD-RW ou un DVD-RW pour réutilisation :


$ xorrecord -v dev=/dev/sr0 blank=as_needed -eject

Formater un DVD-RW pour éviter le besoin de le nettoyer avant réutilisation :


$ xorrecord -v dev=/dev/sr0 blank=format_overwrite -eject
Cette commande peut également être utilisée pour formater les médias BD-R avant leur première utilisation, afin de permettre la gestion des erreurs d'écriture. Plusieurs centaines de Mo de blocs de réserve seront réservés et les enregistrements sur de tels médias seront effectués à une vitesse inférieure à la moitié de la vitesse nominale.

Déformater un DVD-RW pour le rendre à nouveau capable de multiples sessions :


$ xorrecord -v dev=/dev/sr0 blank=deformat

Écrire une seule image de système de fichiers ISO 9660 :


$ xorrecord -v dev=/dev/sr0 speed=12 fs=8m \
blank=as_needed -eject padsize=300k my_image.iso

Écrire plusieurs sessions ISO 9660 :

C'est possible avec tous les médias sauf les DVD-RW et DVD-R DL minimement nettoyés, qui ne peuvent pas gérer plusieurs sessions.
La première session est écrite comme dans l'exemple précédent, sauf que l'option -multi est utilisée. Elle contiendra les fichiers du répertoire du disque dur ./tree1 sous le répertoire ISO 9660 /dir1 :
$ xorrisofs -o image_1.iso -J -graft-points /dir1=./tree1
$ xorrecord -v dev=/dev/sr0 speed=12 fs=8m \
-multi --grow_overwriteable_iso \
blank=as_needed -eject padsize=300k image_1.iso
Pour la deuxième session, xorrisofs doit connaître les numéros -msinfo du média. De plus, il lira les données du média en utilisant le pilote de lecteur CD-ROM en lecture seule du système.
De nombreux systèmes ne tiennent pas compte des activités d'écriture de xorrecord. Il est nécessaire de forcer leur attention en éjectant et en rechargeant le tiroir du lecteur. C'est pourquoi l'exécution ci-dessus utilise l'option -eject.
Obtenez les numéros -msinfo (et rechargez correctement le tiroir s'il a un moteur) en :
$ m=$(xorrecord dev=/dev/sr0 -msinfo)
Proposez une victime pour tout problème causé par des démons intrusifs après le chargement du tiroir :
$ dd if=/dev/sr0 count=1 >/dev/null 2>&1
Utilisez les numéros avec xorrisofs pour ajouter ./tree2 à l'image sous /dir2 :
$ xorrisofs -M /dev/sr0 -C $m -o image_2.iso \
-J -graft-points /dir2=./tree2
Gravez maintenant la nouvelle session sur le même média. Cette fois, sans nettoyage :
$ xorrecord -v dev=/dev/sr0 speed=12 fs=8m \
-multi --grow_overwriteable_iso \
-eject padsize=300k image_2.iso
Les systèmes d'exploitation qui monteront ce média liront le superbloc de la deuxième session et afficheront les deux répertoires /dir1 et /dir2.

Écrire une session ISO 9660 à la volée :

Il est possible de combiner l'exécution de xorrisofs et xorrecord dans un pipeline sans stocker l'image ISO 9660 sous forme de fichier sur disque dur.
Le pipeline est plus vulnérable au problème que certains systèmes n'ont pas assez de patience avec le chargement automatique du tiroir et que des démons peuvent interférer avec une première tentative de lecture du lecteur CD-ROM à partir d'un média fraîchement chargé. Il est conseillé de charger le tiroir manuellement ou via une exécution séparée de xorriso suivie d'une exécution de dd.
Encore une fois, xorriso a la patience et dd est une victime facultative pour les démons.
$ m=$(xorrecord dev=/dev/sr0 -msinfo)
$ dd if=/dev/sr0 count=1 >/dev/null 2>&1
$ xorrisofs -M /dev/sr0 -C $m \
-J -graft-points /dir2=./tree2 \
| xorrecord -v dev=/dev/sr0 speed=12 fs=8m \
-waiti -multi --grow_overwriteable_iso \
-eject padsize=300k -
C'est aussi le cas d'utilisation principal du programme xorriso lui-même, où l'exécution ne nécessiterait aucune solution de contournement système et ressemblerait simplement à :
$ xorriso -dev /dev/sr0 -joliet on -speed 12 -fs 8m \
-map ./tree2 /dir2 -commit_eject all

Écrire une archive afio compressée à la volée :

C'est possible avec tous les médias sauf les DVD-RW et DVD-R DL minimement nettoyés. Étant donné que le flux de sortie compressé est de vitesse très variable, un FIFO plus grand est conseillé. Néanmoins, cet exemple ne convient pas aux très anciens lecteurs CD qui n'ont pas de protection contre les sous-dépassements et qui abandonneraient donc l'exécution de la gravure en cas de manque temporaire de données.
$ find . | afio -oZ - | \
xorrecord -v dev=/dev/sr0 speed=12 fs=64m \
-multi padsize=300k -
Les archives afio ne contiennent pas de références aux adresses de blocs de données absolues. Elles n'ont donc pas besoin de précautions particulières pour les sessions multiples. On peut obtenir les adresses de début de session via l'option -toc, puis utiliser l'option skip= de dd pour commencer à lire à l'une de ces adresses. Par exemple, pour lister son contenu :
$ dd if=/dev/sr0 bs=2048 skip=64046 | afio -tvZ -
afio saura quand la fin de l'archive est atteinte.

FICHIERS

Fichiers de démarrage :

Si --no_rc n'est pas donné comme premier argument, alors xorrecord tente au démarrage de lire et d'exécuter les lignes des fichiers suivants :
/etc/default/xorriso
/etc/opt/xorriso/rc
/etc/xorriso/xorriso.conf
$HOME/.xorrisorc
Les fichiers sont lus dans l'ordre donné ici, mais aucun d'eux n'est obligatoire. Les lignes ne sont pas interprétées comme des options xorrecord mais comme des commandes génériques xorriso. Voir man xorriso.
