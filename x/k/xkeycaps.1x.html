XKeyCaps(1) Manuel des commandes générales XKeyCaps(1)

NOM

xkeycaps - affiche et modifie graphiquement la disposition du clavier X

SYNTAXE

xkeycaps [-option-toolkit ...] [-option ...]

DESCRIPTION

Le programme xkeycaps affiche un clavier. Déplacer la souris sur une touche décrit les symboles de touche (keysyms) et les modificateurs que cette touche génère. Cliquer avec le bouton gauche sur une touche simule un événement KeyPress. Cliquer avec le bouton droit sur une touche fait apparaître un menu d'opérations, y compris une commande pour changer les symboles de touche générés par cette touche. Ce programme est, en partie, une interface graphique pour xmodmap(1).

OPTIONS

xkeycaps accepte toutes les options standard du toolkit, et accepte également les options suivantes :

-clavier nom-du-clavier ou -kbd nom-du-clavier
Spécifie le type de clavier à afficher. Il existe de nombreux claviers d'ordinateurs différents dans le monde, et xkeycaps doit savoir lequel vous utilisez pour fonctionner correctement. La casse n'a pas d'importance lors de la spécification d'un nom de clavier.

Si vous travaillez sur l'écran de console d'un Sun ou d'un HP, xkeycaps interrogera directement le matériel du clavier connecté pour déterminer quel clavier vous utilisez. Mais si vous travaillez à distance, ou sur un autre type de machine, vous devez spécifier un clavier d'une manière ou d'une autre.

-aide
Liste les valeurs reconnues pour l'option -clavier.
-largeur-gouttiere nombre ou -gw nombre
Spécifie le nombre de pixels d'espace à laisser entre chaque touche.
-police nom-de-police
Spécifie la police à utiliser pour afficher les légendes des touches.

Les arguments de ligne de commande standard du X Toolkit suivants sont couramment utilisés avec xkeycaps :

-affichage hote:dpy
Cette option spécifie le serveur X à contacter.
-geometrie geometrie
Cette option spécifie la taille et la position préférées de la fenêtre.
-bg couleur
Cette option spécifie la couleur à utiliser pour l'arrière-plan de la fenêtre. La valeur par défaut est le gris clair.
-fg couleur
Cette option spécifie la couleur à utiliser pour le premier plan de la fenêtre. La valeur par défaut est le noir.
-bw nombre
Cette option spécifie la largeur en pixels de la bordure entourant la fenêtre.
-xrm chaine-ressource
Cette option spécifie une chaîne de ressource à utiliser. Ceci est particulièrement utile pour définir des ressources qui n'ont pas d'options de ligne de commande distinctes.

AFFICHAGE

La partie inférieure de la fenêtre est un dessin d'un clavier. En haut à gauche de chaque touche est imprimée la chaîne qui apparaît réellement sur la surface de la touche. En bas à droite de la touche se trouve le code de touche (keycode) (hexadécimal) que cette touche génère.

En haut de l'écran se trouvent plusieurs lignes de texte décrivant la touche sous la souris (ou la touche tapée le plus récemment.) Ces lignes sont :

CodeTouche:
Ceci affiche le texte imprimé sur la touche physique, et le code de touche généré par cette touche en hexadécimal, décimal et octal.
SymbolTouche:
Ceci affiche l'ensemble des symboles de touche que cette touche génère actuellement.
ASCII:
Ceci affiche l'équivalent ASCII de cette touche, en tenant compte des touches modifiables actuellement enfoncées.
Modificateurs:
Ceci affiche les bits de modification que cette touche génère. Si une touche génère des modificateurs, c'est une touche d'accord comme Majuscule ou Contrôle.
RepetitionAuto:
Si le serveur X prétend que cette touche se répète automatiquement. Je dis ``prétend'' parce que le serveur X OpenWindows est le seul que j'ai rencontré pour lequel ces informations sont exactes. Le drapeau de répétition automatique par touche semble être presque universellement ignoré.

COMMANDES

Il y a plusieurs boutons dans le coin supérieur gauche de la fenêtre. Ils sont :

Quitter
Ferme le programme.
Choisir Clavier
Fait apparaître une boîte de dialogue à partir de laquelle vous pouvez changer le clavier affiché. La colonne de gauche liste les types de claviers connus, et la colonne de droite liste les dispositions (mappings) connues de ces claviers.
Taper sur la Fenêtre
Après avoir sélectionné cela, il vous est demandé de cliquer sur une autre fenêtre. Après avoir fait cela, cliquer sur les touches de la représentation du clavier simulera des événements de touche sur la fenêtre que vous avez sélectionnée. Sélectionner la fenêtre racine ou la fenêtre xkeycaps désactive cette fonction.

Si vous utilisez un gestionnaire de fenêtres (par exemple, twm(1)) dans lequel vous pouvez verrouiller le focus du clavier sur une fenêtre et toujours cliquer sur d'autres fenêtres sans que le focus ne change, vous pouvez accomplir la même chose simplement en focalisant sur une autre fenêtre et en cliquant sur les touches de la fenêtre xkeycaps.

Restaurer la Disposition par Défaut
Cette commande restaure le clavier à son état par défaut. Si vous exécutez cette commande tout en affichant un clavier qui n'est pas le type de clavier que vous utilisez réellement, votre configuration de touches sera dans un état absurde. Il n'y a aucun moyen pour xkeycaps de savoir quel clavier vous utilisez sauf en vous croyant sur parole, alors ne mentez pas.
Écrire la Sortie
Cette commande écrit un fichier d'entrée xmodmap représentant l'état actuel du clavier (y compris toutes vos modifications) dans un fichier de votre répertoire personnel. Notez que cette commande N'ÉCRIT PAS la configuration par défaut pour ce type de clavier, sauf si vous avez cliqué sur Restaurer la Disposition par Défaut auparavant.

Le fichier sera appelé .xmodmap-nomhote, où nomhote est le nom de la machine sur laquelle vous travaillez. Il vous avertira si le fichier existe déjà.

Il vous invite avec une boîte de dialogue : vous pouvez soit écrire un fichier xmodmap représentant l'état de chaque touche, soit écrire un fichier plus petit qui décrit uniquement les modifications.

L'idée est que dans le script de démarrage approprié, vous ajouteriez une ligne comme

xmodmap  /.xmodmap-`uname -n`
dans le fichier init approprié, afin que ces modifications du clavier soient effectuées chaque fois que vous vous connectez. (Si vous n'êtes pas sûr où cette commande doit aller, demandez à votre administrateur système, car cela a tendance à varier d'un site à l'autre.)

Cliquer avec le bouton gauche sur une touche simule un événement KeyPress. Relâcher le bouton simule un événement KeyRelease. Si vous cliquez avec le bouton gauche sur une touche et que vous déplacez la souris pendant que le bouton est enfoncé, des événements KeyPress et KeyRelease seront simulés sur chaque touche sur laquelle vous déplacez la souris. Pensez à la souris comme à votre doigt : si vous faites glisser la souris sur plusieurs touches, elles s'enfonceront et se relâcheront l'une après l'autre.

Cliquer avec le bouton gauche sur une touche associée à des bits de modification (comme Majuscule ou Contrôle) fait que cette touche reste ``enfoncée''. Cliquer à nouveau avec le bouton gauche la relâche. De cette façon, vous pouvez générer des combinaisons de touches avec la souris : pour générer Contrôle-C, cliquez avec le bouton gauche sur la touche Contrôle, puis cliquez sur la touche C. Cliquez à nouveau sur Contrôle pour désactiver le modificateur de contrôle.

Taper une touche sur le clavier réel simule une paire d'événements KeyPress/KeyRelease de la même manière que cliquer sur une touche.

UTILISATION DE XMODMAP

Ce programme vous permet de modifier la façon dont votre clavier est configuré. Vous pouvez modifier la table des raccourcis clavier, c'est-à-dire la table qui associe les touches du clavier à des KeySyms.

L'exécution de xmodmap sans arguments affiche votre table des raccourcis clavier actuelle. Si vous tapez un caractère normal, rien ne se passe. Mais si vous tapez la touche Shift, puis un caractère, l'événement simulé aura le modificateur Shift activé. Et si vous maintenez enfoncée la vraie touche Control et cliquez sur la touche C dans la fenêtre, un événement Control-C sera généré. (En supposant, bien sûr, que votre gestionnaire de fenêtres n'intercepte pas le clic gauche de la souris avec Control à ses propres fins.)

Cliquer avec le bouton droit sur une touche fait apparaître un menu de commandes pour la touche donnée. Ils sont :

Échanger les touches
Après avoir sélectionné cet élément de menu, il vous est demandé de cliquer sur une autre touche. Cette touche et la touche sur laquelle vous avez fait apparaître le menu seront échangées. Cela modifie la table des raccourcis clavier immédiatement.
Dupliquer la touche
Après avoir sélectionné cet élément de menu, il vous est demandé de cliquer sur une autre touche. Cette touche sera une copie de la touche sur laquelle vous avez fait apparaître le menu. Autrement dit, les deux touches généreront le même ensemble de keysyms et de modificateurs. Cela modifie la table des raccourcis clavier immédiatement.
Désactiver la touche
La touche sur laquelle vous avez fait apparaître le menu ne générera aucun keysym ni aucun modificateur. Cela modifie la table des raccourcis clavier immédiatement.
Restaurer la touche par défaut
La touche sur laquelle vous avez fait apparaître le menu sera restaurée à son état par défaut ; aucune autre touche ne sera modifiée. Cela modifie en fait la table des raccourcis clavier actuelle.
Modifier les KeySyms de la touche
Cela fait apparaître la fenêtre "Modifier la touche", qui vous permet de changer arbitrairement les keysyms et les modificateurs que cette touche génère.

Sur le côté gauche de la fenêtre se trouve la liste des keysyms que cette touche génère actuellement. (Une touche peut générer jusqu'à huit keysyms ; l'interprétation de ces keysyms est décrite dans le document du protocole X, et est résumée plus loin dans la section KEYSYMS ET KEYCODES de cette page de manuel.)

La deuxième colonne est une liste à choix multiples des huit bits de modificateurs que cette touche peut générer. Par exemple, si vous voulez qu'une touche se comporte comme une touche ``contrôle'', vous devez sélectionner le modificateur Control.

Les troisième et quatrième colonnes (les listes déroulantes) servent à modifier le keysym associé à la touche. Lorsque vous sélectionnez une position de keysym dans la première colonne, l'ensemble de caractères et le keysym s'affichent dans les listes déroulantes. Cliquer sur un keysym dans la colonne ``KeySym'' installera ce keysym dans l'emplacement mis en surbrillance dans la première colonne.

Pour sélectionner un keysym d'un ensemble de caractères différent, cliquez sur le nom de l'ensemble de caractères dans la deuxième colonne. (Les ensembles de caractères Latin1 et Keyboard sont les plus couramment utilisés.)

En bas de la fenêtre se trouvent trois boutons : Undo, Abort et Ok. Cliquer sur Undo ramène la fenêtre Modifier la touche à l'état actuel de la touche en question. Abort ferme la fenêtre Modifier la touche sans apporter de modifications. Ok ferme la fenêtre Modifier la touche et applique vos modifications (la table des raccourcis clavier actuelle est modifiée.)

KEYSYMS ET KEYCODES

Pour modifier efficacement votre table des raccourcis clavier, certains termes doivent vous être familiers :

KeyCode
C'est un code de balayage brut lu depuis le clavier ; chaque touche physique du clavier a un numéro différent qui lui est associé ; cette table ne peut pas être modifiée (mais ce n'est pas grave).

En général, chaque clavier a son propre ensemble de KeyCodes, c'est pourquoi vous aurez probablement besoin d'une table des raccourcis clavier différente pour chaque système que vous utilisez.

KeySym
C'est un symbole qui peut être généré par une seule pression sur une touche du clavier : par exemple, toutes les lettres, les chiffres et la ponctuation sont des keysyms, tout comme des éléments plus abstraits comme "shift" et "control".

Chaque KeyCode (c'est-à-dire, touche du clavier) est associé à certains KeySyms. Ce sont les KeySyms qui donnent leur sémantique aux touches (et font que la touche A génère un A), et non les KeyCodes.

Habituellement, les touches sont associées à un ou deux keysyms, qui correspondent aux symboles générés lorsque la touche est pressée, et lorsqu'elle est pressée alors que la touche shift est enfoncée. Il existe un cas spécial : si la touche ne contient qu'un seul KeySym, et que c'est une lettre, alors la touche Shift fait ce que l'on attend d'elle pour les lettres.

KeyCap
Ne pas confondre avec les KeySyms, cela fait référence au texte qui est imprimé sur les touches physiques : il est immuable (sauf si vous repeignez votre clavier...).
Chord
Ce terme fait référence à un ensemble de deux touches ou plus maintenues enfoncées simultanément (par analogie avec les claviers de piano.) Toutes les touches sauf une seront généralement des touches modificatrices. Parfois Constellation est utilisé pour signifier la même chose.
Touche modificatrice (Modifier Key)
C'est une touche comme shift ou control, qui est utilisée pour modifier l'interprétation d'autres touches qui sont maintenues enfoncées en même temps. En général, appuyer sur une touche modificatrice sans appuyer également sur une touche non modificatrice ne fait rien.

Une touche est une touche modificatrice si elle a un Modifier KeySym dessus. (Plus précisément, si le KeyCode de cette touche est associé à un Modifier KeySym.)

Modifier KeySym
Un KeySym est un modifier keysym s'il a un Modifier Bit associé. Mais les règles sont un peu plus compliquées que cela. Il est plus facile de décrire par exemple :

Pour qu'une touche se comporte comme on attend qu'une touche shift se comporte, le keycode doit avoir le bit modificateur Control activé ; et la touche doit générer l'un des keysyms Shift_L ou Shift_R. Si l'un de ces éléments n'est pas vrai, la touche ne se comportera pas comme une touche shift.

De manière analogue, une touche control doit avoir le modificateur Control activé et utiliser l'un des keysyms Control_L ou Control_R.

Cela implique que si vous vouliez échanger vos touches shift et control, il ne suffirait pas d'échanger leurs bits modificateurs : vous devez également échanger leurs keysyms. Si vous n'échangez que les bits modificateurs, cela peut sembler fonctionner au début, mais d'autres éléments fonctionneraient mal.

Les touches comme Meta (et Super, Hyper, etc.) sont un peu plus compliquées (voir ci-dessous.)

Modifier Bit
Les bits modificateurs sont des attributs que certains keysyms peuvent avoir. Certains bits modificateurs ont des sémantiques prédéfinies : Shift, Lock et Control. Les bits modificateurs restants (Mod1 à Mod5) ont des sémantiques qui sont définies par les touches auxquelles ils sont associés.

Autrement dit, le modificateur Control signifie Control s'il est attaché à Control_L ou Control_R, et est illégal ailleurs.

Mais Mod1 signifie Meta s'il est attaché à Meta_L ou Meta_R ; mais il signifierait Alt s'il était attaché à Alt_L ou Alt_R ; ou Hyper avec Hyper_L ou Hyper_R ; et ainsi de suite. (Il ne pourrait cependant pas être attaché à Control_L, car le modificateur Control s'est déjà approprié ces keysyms.)

Si vous pensez que tout cela est inutilement compliqué... vous avez raison.

DOCUMENT DU PROTOCOLE X SUR LES KEYMAPS

Voici une explication technique plus précise sur le fonctionnement de la table des raccourcis clavier. Cette description provient du document du protocole X, et est reproduite ici pour votre commodité :

Une liste de KeySyms est associée à chaque KeyCode. Si cette liste (en ignorant les entrées NoSymbol à la fin) est un seul KeySym ``K'', alors la liste est traitée comme si elle était la liste ``K NoSymbol K NoSymbol''. Si la liste (en ignorant les entrées NoSymbol à la fin) est une paire de KeySyms ``K1 K2'', alors la liste est traitée comme si elle était la liste ``K1 K2 K1 K2''. Si la liste (en ignorant les entrées NoSymbol à la fin) est un triple de KeySyms ``K1 K2 K3'', alors la liste est traitée comme si elle était la liste ``K1 K2 K3 NoSymbol''.

Les quatre premiers éléments de la liste sont divisés en deux groupes de KeySyms. Le groupe 1 contient le premier et le deuxième KeySym, le groupe 2 contient le troisième et le quatrième KeySym. Dans chaque groupe, si le deuxième élément du groupe est NoSymbol, alors le groupe doit être traité comme si le deuxième élément était identique au premier élément, sauf lorsque le premier élément est un KeySym alphabétique ``K'' pour lequel les formes minuscules et majuscules sont définies. Dans ce cas, le groupe doit être traité comme si le premier élément était la forme minuscule de ``K'' et le deuxième élément la forme majuscule de ``K''.

Les règles standard pour obtenir un KeySym à partir d'un événement KeyPress n'utilisent que les KeySyms du groupe 1 et du groupe 2 ; aucune interprétation des autres KeySyms de la liste n'est donnée ici. (Autrement dit, les quatre derniers KeySyms sont inutilisés.)

Le groupe à utiliser est déterminé par l'état du modificateur. Le passage d'un groupe à l'autre est contrôlé par le KeySym nommé Mode_switch.

En attachant ce KeySym à un KeyCode et en attachant ce KeyCode à l'un des modificateurs Mod1 à Mod5. Ce modificateur est appelé le ``modificateur de groupe''. Pour tout KeyCode, le groupe 1 est utilisé lorsque le modificateur de groupe est désactivé, et le groupe 2 est utilisé lorsque le modificateur de groupe est activé.

Au sein d'un groupe, le KeySym à utiliser est également déterminé par l'état du modificateur. Le premier KeySym est utilisé lorsque les modificateurs Shift et Lock sont désactivés. Le deuxième KeySym est utilisé lorsque le modificateur Shift est activé, ou lorsque le modificateur Lock est activé et que le deuxième KeySym est une majuscule alphabétique, ou lorsque le modificateur Lock est activé et interprété comme ShiftLock. Sinon, lorsque le modificateur Lock est activé et interprété comme CapsLock, l'état du modificateur Shift est appliqué d'abord pour sélectionner un KeySym, mais si ce KeySym est une minuscule alphabétique, alors le KeySym majuscule correspondant est utilisé à la place.

ICCCM SUR LA CARTOGRAPHIE DES MODIFICATEURS

Voici une explication technique plus précise sur la façon dont les touches modificatrices sont interprétées. Cette description provient du Manuel des conventions de communication inter-clients, et est reproduite ici

era pour votre convenance :

X11 prend en charge 8 bits de modificateurs, dont 3 sont prédéfinis pour Maj (Shift), Verrou (Lock) et Ctrl (Control). Chaque bit de modificateur est contrôlé par l'état d'un ensemble de touches, et ces ensembles sont spécifiés dans un tableau accessible par GetModifierMapping() et SetModifierMapping().

Un client nécessitant l'utilisation d'un des modificateurs prédéfinis doit supposer que le tableau des modificateurs a été correctement configuré pour contrôler ces modificateurs. Le modificateur Verrou doit être interprété comme Verrouillage des majuscules (Caps Lock) ou Verrouillage Maj (Shift Lock), selon que les keycodes de son ensemble de contrôle incluent XK_Caps_Lock ou XK_Shift_Lock.

Les clients doivent déterminer la signification d'un bit de modificateur à partir des keysyms utilisés pour le contrôler.

Un client nécessitant l'utilisation d'un modificateur supplémentaire, par exemple Meta, doit :

Analyser les mappings de modificateurs existants. S'il trouve un modificateur qui contient un keycode dont l'ensemble de keysyms inclut XK_Meta_L ou XK_Meta_R, il doit utiliser ce bit de modificateur.

S'il n'existe aucun modificateur contrôlé par XK_Meta_L ou XK_Meta_R, il doit sélectionner un bit de modificateur inutilisé (un avec un ensemble de contrôle vide) et :

S'il existe un keycode avec XL_Meta_L dans son ensemble de keysyms, ajouter ce keycode à l'ensemble pour le modificateur choisi, puis

s'il existe un keycode avec XL_Meta_R dans son ensemble de keysyms, ajouter ce keycode à l'ensemble pour le modificateur choisi, puis

si l'ensemble de contrôle est toujours vide, interagir avec l'utilisateur pour sélectionner une ou plusieurs touches qui seront Meta.

S'il n'y a pas de bits de modificateurs inutilisés, demander à l'utilisateur de prendre des mesures correctives.

Ce qui précède signifie que le modificateur Mod1 ne signifie pas nécessairement Meta, bien que certaines applications (telles que twm et emacs 18) le supposent. N'importe lequel des cinq bits de modificateurs non assignés pourrait signifier Meta ; ce qui importe, c'est qu'un bit de modificateur soit généré par un keycode associé au keysym Meta_L ou Meta_R.

Par conséquent, si vous souhaitez créer une touche « meta », la bonne manière est de faire en sorte que le keycode en question génère à la fois un keysym Meta et un bit de modificateur précédemment non assigné.

LE KEYSYM MODE_SWITCH

Au cas où ce qui précède n'aurait pas été clair, ce que fait le keysym Mode_switch, c'est essentiellement agir comme un type de touche Maj supplémentaire. Si vous avez quatre keysyms attachés à la touche A, ces quatre keysyms seront accessibles par les combinaisons : A ; Maj-A, Mode_switch-A ; et Mode_switch-Maj-A, respectivement.

Comme toute touche Modificateur, pour que Mode_switch fonctionne, il doit avoir un bit de modificateur qui lui est attaché. Donc, sélectionnez l'un des bits Mod1 à Mod5 (celui qui est inutilisé) et attachez-le à la touche Mode_switch.

LE KEYSYM MULTI_KEY

À ne pas confondre avec Mode_switch, Multi_key permet l'entrée de séquences de plusieurs caractères qui représentent un seul caractère (keysym). Un nom plus traditionnel pour ce keysym pourrait être Compose.

Le keysym Multi_key n'est pas un keysym de modificateur. Autrement dit, pour qu'il fonctionne correctement, il ne doit avoir aucun bit de modificateur qui lui soit associé. En effet, ce n'est pas une touche de « combinaison » : vous ne la maintenez pas enfoncée avec d'autres touches. Au lieu de cela, vous appuyez sur Multi_key, vous la relâchez, puis vous appuyez et relâchez une autre touche, et les deux ensemble produisent un nouveau caractère.

Par exemple, une liaison traditionnelle serait pour Multi_key, suivi de l'apostrophe, suivi de A pour produire le keysym Aacute.

Tous les fournisseurs ne prennent pas en charge l'utilisation du keysym Multi_key ; en particulier, Digital, Sun et HP le prennent en charge, mais le Consortium X non. (La raison en est, m'a-t-on dit, que les séquences « Compose » sont considérées comme obsolètes ; la ligne officielle est que vous devriez utiliser les méthodes d'entrée pour cela.)

Le fonctionnement de Multi_key est une propriété de la bibliothèque Xt (pas du serveur X). Il est donc possible que sur un même système, Multi_key fonctionne avec certaines applications et pas avec d'autres (selon la manière dont ces applications ont été compilées et liées).

Si vous utilisez Lucid Emacs ou XEmacs, vous pouvez profiter des séquences Multi_key même si votre version de Xt ne les prend pas en charge, en chargeant la bibliothèque x-compose, qui simule le comportement traditionnel de Xt. Pour plus d'informations, lisez les commentaires en haut du fichier « /usr/local/lib/xemacs-*/lisp/x11/x-compose.el ».

LES KEYSYMS MORTS

Les touches mortes fonctionnent de manière similaire à Multi_key, mais ce sont des commandes à deux frappes au lieu de trois. Par exemple, appuyer sur la touche Dead_tilde, la relâcher, puis appuyer sur la touche A générerait le keysym unique Atilde. (On les appelle touches « mortes » parce qu'elles n'insèrent pas de caractères par elles-mêmes, mais modifient le caractère suivant tapé. Mais HP aime les appeler « muettes » au lieu de « mortes », sans doute pour éviter d'effrayer les enfants.)

Là encore, toutes les versions de la bibliothèque Xt ne les prennent pas en charge (mais elles peuvent être simulées par XEmacs.)

Notez également que différents fournisseurs ont des noms différents pour les keysyms morts. Par exemple : selon votre fournisseur, la version de votre serveur X et la phase de la lune, vous pourriez constater que le nom de « dead-tilde » est Dead_Tilde, Dtilde, SunFA_Tilde, SunXK_FA_Tilde, DXK_tilde, DXK_tilde_accent, hpmute_asciitilde, hpXK_mute_asciitilde, ou même XK_mute_asciitilde. C'est un désordre ! Vous devrez simplement essayer pour voir ce qui fonctionne, le cas échéant.

CE QUE VOUS NE POUVEZ PAS FAIRE

Les gens demandent souvent si xkeycaps ou xmodmap peuvent être utilisés pour faire en sorte qu'une touche génère une séquence de caractères. Malheureusement, non : vous ne pouvez pas faire ce genre de choses en manipulant les keymaps du serveur. Le modèle de clavier X ne fonctionne tout simplement pas comme ça.

La façon de faire de telles choses est de définir des ressources de traduction sur des widgets particuliers. Cela doit être fait application par application. Par exemple, voici comment vous pourriez convaincre xterm(1) d'insérer la chaîne next lorsque vous appuyez sur F17 :

xterm*VT100.Translations: #override \
    <Key>F17: string("next")
D'autres applications peuvent avoir des mécanismes différents pour accomplir la même chose, et certaines applications peuvent ne pas le prendre en charge du tout. Consultez les pages de manuel pertinentes pour les détails.

De même, vous ne pouvez pas convaincre une touche de générer une autre touche avec des modificateurs (par exemple, vous ne pouvez pas faire en sorte que F1 se comporte comme Ctrl-A, sauf en utilisant des traductions, comme ci-dessus.)

Il n'est pas non plus possible de faire en sorte qu'une touche de clavier se comporte comme un bouton de souris.

FOURNISSEURS PERDANTS

HP et S.u.S.E. livrent leurs systèmes avec des configurations de clavier défectueuses par défaut. Ils devraient vraiment savoir mieux, mais ils ne le font pas.

Comme expliqué ci-dessus, il s'agit d'un comportement indéfini pour qu'un bit de modificateur soit partagé entre deux touches ayant des sémantiques différentes.

Par défaut, HP utilise Mod1 à la fois pour Meta et pour Mode_switch. Cela signifie qu'il est impossible pour un programme de faire la différence entre, par exemple, Meta-X et Mode_switch-X.

Donc, pour réparer ce désordre, vous devez attribuer un bit de modificateur différent à la touche Mode_switch (par exemple, mod2). Ou, vous pourriez simplement la supprimer complètement du keymap.

S.u.S.E. Linux est encore plus mal loti que HP : alors que la keymap par défaut de HP ne contient qu'un seul bug, la map par défaut de S.u.S.E. contient trois erreurs complètement différentes !

Premièrement, leur keymap par défaut associe le modificateur Control à la fois à la touche Control et à Multi_key. C'est complètement fou, car non seulement Multi_key n'est pas une touche de contrôle, mais ce n'est même pas une touche de combinaison ! Aucun bit de modificateur ne doit lui être associé.

Deuxièmement, ils associent Mod1 à Meta_L et aussi à Alt_R. Certaines personnes pensent que « meta » et « alt » sont synonymes, mais le fait est que le système X Window n'est pas d'accord. Ce sont des touches distinctes. Il est possible d'avoir à la fois des touches « meta » et « alt » sur le clavier en même temps, et de faire en sorte que les programmes les interprètent différemment. Mais bien sûr, seulement s'ils ne partagent pas bogusly le même bit de modificateur, rendant l'interprétation de ce bit ambiguë.

Troisièmement, ils associent Mod5 à la fois à Scroll_Lock et à Hyper_R, ce qui est faux pour des raisons qui devraient maintenant être évidentes.

Le moyen le plus simple de corriger votre configuration S.u.S.E. est de : supprimer control de Multi_key ; changer la touche Alt gauche pour générer Alt_L au lieu de Meta_L ; et supprimer le keysym Hyper_R du clavier.

Si vous avez une influence sur ces fournisseurs, je vous encourage à les encourager à se ressaisir.

xkeycaps*Keyboard.Shift.borderWidth: 2

ACTIONS

Il est possible de remapper les actions qui se produisent lorsqu'une touche ou un bouton de souris est pressé ou relâché. Ces actions sont disponibles sur le widget Keyboard :

HighlightKey(condition, arg)
Ceci place la touche en question dans l'état mis en surbrillance.

Si aucun argument n'est passé à cette action, alors la touche est déterminée par l'événement qui a déclenché cette action. Si cette action est déclenchée par un événement KeyPress ou KeyRelease, le widget de touche est la touche correspondant à la touche que l'événement représente. S'il s'agit d'un événement ButtonPress, ButtonRelease ou PointerMotion, alors le widget de touche est celui situé sous la souris.

L'argument peut être l'un des mots mouse, highlighted, ou displayed, signifiant respectivement la touche sous la souris, la touche mise en surbrillance la plus récemment, ou la touche actuellement décrite dans la zone ``Info'' en haut de la fenêtre.

La condition peut être l'un des mots ifmod, unlessmod, iftracking, unlesstracking, ifhighlighted, ou unlesshighlighted. Si ifmod a été spécifié et que la touche en question (déterminée par l'argument ou par l'événement déclencheur) n'est pas une touche modificateur, alors cette action n'est pas exécutée. La condition unlessmod est l'inverse. Les conditions iftracking et unlesstracking vous permettent d'effectuer certaines actions uniquement si (ou sauf si) la touche est ``suivie'' par la souris (voir ci-dessous.) Les actions ifhighlighted et unlesshighlighted vous permettent d'effectuer certaines actions uniquement si (ou sauf si) la touche en question est actuellement dans l'état mis en surbrillance.

UnhighlightKey(condition, arg)
Ceci place la touche en question dans l'état non mis en surbrillance. Les arguments sont les mêmes qu'au-dessus.
ToggleKey(condition, arg)
Ceci rend la touche mise en surbrillance si elle ne l'est pas, ou non mise en surbrillance si elle l'est. Les arguments sont les mêmes qu'au-dessus.
SimulateKeyPress(condition, arg)
Cette action crée un événement KeyPress correspondant à la touche sur la fenêtre focalisée. Les arguments sont les mêmes qu'au-dessus.
SimulateKeyRelease(condition, arg)
Cette action crée un événement KeyRelease correspondant à la touche sur la fenêtre focalisée. Les arguments sont les mêmes qu'au-dessus.
TrackKey(condition, arg)
Ceci fait que la touche en question commence à être ``suivie'', ce qui signifie que déplacer la souris hors de celle-ci simulera une action de relâchement de bouton, puis simulera une action de pression de bouton sur la touche vers laquelle la souris s'est déplacée. Cette action ne peut être déclenchée qu'à partir d'un événement ButtonPress ou ButtonRelease.
UntrackKey(condition, arg)
Ceci fait que la touche en question n'est plus ``suivie''.
DescribeKey(condition, arg)
Cette action provoque l'affichage de la touche et de ses liaisons dans la section ``Info'' en haut de la fenêtre, si elle n'y est pas déjà décrite.

Les actions par défaut pour le widget Keyboard sont :

<Motion>:   DescribeKey(mouse,unlessTracking)      \n\
\
<KeyDown>:  HighlightKey()                         \
            DescribeKey(unlessMod)                 \
            DescribeKey(displayed)                 \
            SimulateKeyPress()                     \n\
\
<KeyUp>:    UnhighlightKey()                       \
            DescribeKey(displayed)                 \
            SimulateKeyRelease()                   \n\
\
<Btn1Down>: HighlightKey(unlessMod)                \
            ToggleKey(ifMod)                       \
            TrackKey(unlessMod)                    \
            SimulateKeyPress(ifHighlighted)        \
            SimulateKeyRelease(unlessHighlighted)  \n\
\
<Btn1Up>:   UntrackKey(highlighted)                \
            SimulateKeyRelease(highlighted,unlessMod) \
            UnhighlightKey(highlighted,unlessMod)  \n\
\
<Btn3Down>: XawPositionSimpleMenu(keyMenu)         \
            MenuPopup(keyMenu)                     \n
Si vous ne voulez pas qu'une touche soit décrite chaque fois que la souris la survole, vous pouvez supprimer l'action <Motion>. Dans ce cas, vous devriez probablement ajouter DescribeKey() aux actions <Btn1Down> et <KeyDown>.

Si vous voulez que la touche sous la souris soit décrite même lorsque la souris se déplace avec un bouton enfoncé, supprimez le paramètre unlessTracking de l'action DescribeKey liée à <Motion>.

Si vous ne voulez pas que les touches modificateurs basculent, modifiez les actions Button1 en

xkeycaps*Keyboard.actions:  #override               \
        <Btn1Down>: HighlightKey()                  \
                    TrackKey(unlessmod)             \
                    SimulateKeyPress()              \n\
        <Btn1Up>:   UntrackKey(highlighted)         \
                    SimulateKeyRelease(highlighted) \
                    UnhighlightKey(highlighted)     \n
N'oubliez pas que ces actions existent sur le widget Keyboard, et non sur les widgets Key. Si vous ajoutez des actions aux widgets Key, les choses fonctionneront mal.

BOGUES

Comme ce programme a des couleurs par défaut qui ne sont pas "noir" et "blanc", l'option de ligne de commande -rv ne fonctionne pas. Mais l'incantation

% xkeycaps -fg white -bg black -bd white

fera ce que vous voulez sur un écran monochrome.

La carte par défaut de NeXT est censée être incorrecte ; quelqu'un ayant accès à un NeXT devra déboguer cela.

Il n'y a pas de moyen portable de savoir quel clavier est utilisé ; cela signifie qu'il ne choisira souvent pas le bon par défaut, et si l'utilisateur apporte des modifications à la configuration du clavier pendant l'affichage d'un clavier qui n'est pas le bon, de très mauvaises choses peuvent arriver.

Si vous appuyez sur plus d'une douzaine de touches à la fois, de nombreux serveurs X se confondent et ne transmettent pas suffisamment d'événements KeyRelease ; le résultat est que les touches xkeycaps resteront ``collées'' jusqu'à ce qu'elles soient pressées à nouveau. (Ne faites pas ça.)

Le drapeau AutoRepeat est apparemment inutile sur tous les serveurs X sauf celui d'OpenWindows (je n'ai jamais vu un autre serveur qui l'ignore.)

Vous ne pouvez pas sélectionner parmi l'ensemble des keysyms Vendor (ces keysyms qui sont définis dans le fichier XKeysymDB) à moins que vous n'exécutiez X11r5 ou une version plus récente.

Les claviers non-US de NCD n'utilisent pas le mécanisme standard R4/R5 pour attacher plus de deux keysyms à une touche ; au lieu d'avoir simplement trois ou quatre keysyms attachés au keycode en question, la touche Compose modifie le keycode réel de la touche (elle active son bit de poids fort). Le programme xkeycaps ne comprend pas vraiment cela. Quelqu'un du support NCD m'a dit qu'ils feraient les choses à la manière R4/R5 dans les futures versions au lieu de la manière dont ils font les choses maintenant, donc modifier xkeycaps pour comprendre le comportement actuel ne vaut probablement pas l'effort.

La commande Type at Window ne semble pas fonctionner sur la version WreckStation de XTerm. Je suppose qu'une variation de la commande normale Allow SendEvents de XTerm est nécessaire.

Si vous ne pouvez rien sélectionner dans le menu contextuel du bouton droit, c'est peut-être parce que NumLock ou CapsLock est activé. Je ne suis pas sûr de comment résoudre cela, cela semble être un défaut de Xt.

Si le menu contextuel est toujours grisé, ou ne correspond pas à la touche sur laquelle vous avez cliqué, c'est peut-être parce que vous exécutez xswarm, une ancienne version de xautolock, ou un autre programme qui interfère antisocialement avec la propagation des événements. (Ne faites pas ça.)

En raison de la manière non linéaire dont ce programme utilise XLookupString, il n'y a pas de moyen sensé pour lui de gérer le traitement de composition, et de vous montrer les résultats des séquences de touches "mortes" ou Multi_key.

Il a besoin de connaître plus de types de claviers (et sans aucun doute en aura toujours besoin...)

Les touches en forme de L ne sont pas dessinées avec précision. Nous devrions utiliser l'extension Shape pour cela.

En plus d'afficher la version ASCII du caractère donné, il devrait afficher le caractère correspondant dans le jeu de caractères (Latin2, Kana, Grec, etc.) Cela nécessiterait d'avoir des polices pour tous ces jeux de caractères, cependant, et pour autant que je puisse le dire, elles ne sont pas toutes standard.

Lorsqu'on exécute sur un Sun et qu'on communique avec un serveur OpenWindows, il faudrait analyser le fichier approprié de $OPENWINHOME/etc/keytables/ pour déterminer la configuration du clavier par défaut. Sans doute existe-t-il des moyens spécifiques au système pour faire cela dans d'autres environnements également.

BUGS

Certaines versions de l'hp-hpib-config le programme de configuration de périphériques HP, incluent un fichier d'en-tête qui définit de manière incorrecte des types de données, ce qui provoque des erreurs de compilation lorsque cc est utilisé pour compiler les programmes X sans spécifier l'option -Aa (ANSI). Ce comportement erroné est dû au compilateur HP et non à xkeycaps.

Le programme xmodmap reste peu fiable. Comme ses directives ADD et REMOVE prennent des keysyms comme arguments au lieu de keycodes, il existe des choses que vous pouvez faire avec XKeyCaps qui ne peuvent pas être représentées dans un script xmodmap (du moins, pas sans grande difficulté).

Le programme xmodmap ne possède pas de commandes pour modifier le statut de répétition automatique des touches. Par conséquent, ces informations ne sont pas enregistrées dans la sortie. Peut-être pourrions-nous écrire une commande xset appropriée à la place. (Par exemple, pour activer la répétition automatique de la touche PgUp (qui a le keycode 103) sur Solaris, vous devriez exécuter : "xset r 103".)

Certaines versions d'OpenWound utilisent un mécanisme non standard pour spécifier quelles touches ont un comportement de bascule (semblable à Verrouillage majuscule) (alors que la plupart des autres serveurs X basent ce comportement sur le keysym : si Caps_Lock ou Shift_Lock est généré, la touche est verrouillée, sinon elle ne l'est pas.) XKeyCaps ne sait pas comment modifier le statut de verrouillage sur ces serveurs. C'est parce que je ne sais pas comment faire non plus. Si vous connaissez les appels système nécessaires pour modifier ce comportement, faites-le moi savoir.

L'interface XKB de X11R6 semble fournir la plupart des informations que xkeycaps doit connaître, mais je n'ai pas encore eu le temps de l'étudier.
