XKIBITZ(1) Manuel des commandes générales XKIBITZ(1)

NOM

xkibitz - permet à plusieurs personnes d'interagir dans un xterm

SYNTAXE

xkibitz [ args-xkibitz ] [ programme args-programme... ]

INTRODUCTION

xkibitz permet à des utilisateurs dans des xterms séparés de partager un shell (ou tout autre programme s'exécutant dans un xterm). Utilisations possibles :

•
Un utilisateur novice peut demander de l'aide à un utilisateur expert. En utilisant xkibitz, l'expert peut voir ce que fait l'utilisateur et offrir des conseils ou montrer comment faire correctement.
•
En lançant xkibitz puis un éditeur plein écran, des personnes peuvent mener une conversation, en conservant la capacité de faire défiler en arrière, d'enregistrer toute la conversation, ou même de l'éditer pendant qu'elle est en cours.
•
Des personnes peuvent s'associer pour des jeux, l'édition de documents, ou d'autres tâches coopératives où chaque personne a des forces et des faiblesses qui se complètent.
•
Si vous voulez qu'un grand nombre de personnes effectuent une revue de code en ligne, vous pouvez placer deux personnes devant chaque poste de travail, puis les connecter toutes ensemble pendant que vous examinez le code ensemble dans l'éditeur.

UTILISATION

Pour lancer xkibitz, un utilisateur (le maître) exécute xkibitz sans arguments.

xkibitz lance un nouveau shell (ou un autre programme, s'il est donné en ligne de commande). L'utilisateur peut interagir normalement avec le shell, ou après avoir entré un caractère d'échappement (décrit au moment où xkibitz démarre) peut ajouter des utilisateurs à l'interaction.

Pour ajouter des utilisateurs, entrez « + affichage » où affichage est le nom d'affichage X. S'il n'y a pas de « :X.Y » dans le nom d'affichage, « :0.0 » est supposé. L'utilisateur maître doit avoir la permission d'accéder à chaque affichage. Chaque affichage se voit attribuer une étiquette - un petit entier qui peut être utilisé pour référencer l'affichage.

Pour afficher les étiquettes et les affichages actuels, entrez « = ».

Pour supprimer un affichage, entrez « - étiquette » où étiquette est l'étiquette de l'affichage selon la commande « = ».

Pour revenir au shell partagé, entrez « return ». Ensuite, les frappes de toutes les utilisateurs deviennent l'entrée du shell. Similairement, tous les utilisateurs reçoivent la sortie du shell.

Pour terminer xkibitz, il suffit de terminer le shell lui-même. Par exemple, si un utilisateur tape ^D (et que le shell l'accepte comme fin de fichier), le shell se termine suivi de xkibitz.

Normalement, tous les caractères sont passés sans interprétation. Cependant, dans le dialogue d'échappement, l'utilisateur parle directement à l'interpréteur xkibitz. Les commandes Expect(1) ou Tcl(3) peuvent également être données. De plus, le contrôle de job peut être utilisé lorsqu'on est dans l'interpréteur, pour, par exemple, suspendre ou redémarrer xkibitz.

Divers processus peuvent produire divers effets. Par exemple, vous pouvez émuler une session write(1) multi-utilisateurs avec la commande :

xkibitz sleep 1000000

ARGUMENTS

xkibitz comprend quelques arguments spéciaux qui doivent apparaître avant le nom du programme (s'il est donné). Chaque argument doit être séparé par un espace. Si les arguments eux-mêmes prennent des arguments, ceux-ci doivent également être séparés par des espaces.

-escape définit le caractère d'échappement. Le caractère d'échappement par défaut est ^].

-display ajoute un affichage, un peu comme la commande « + ». Plusieurs drapeaux -display peuvent être donnés. Par exemple, pour démarrer xkibitz avec trois affichages supplémentaires :

xkibitz -display mercury -display fox -display dragon:1.0

LIMITATIONS

En raison des limitations de X et UNIX, la propagation des redimensionnements est faible.

Lorsque l'utilisateur maître redimensionne l'xterm, tous les autres xterms sont logiquement redimensionnés. Malheureusement, xkibitz ne peut pas forcer la taille physique de l'xterm à correspondre aux tailles logiques des xterms.

Les autres utilisateurs sont libres de redimensionner leur xterm mais leurs tailles ne sont pas propagées. Le maître peut vérifier les tailles logiques avec la commande « = ».

La déduction de la taille de la fenêtre est une opération non portable. Le code est connu pour fonctionner avec les versions récentes de SunOS, AIX, Unicos et HPUX. Envoyez des modifications si vous ajoutez la prise en charge d'autre chose.

ENVIRONNEMENT

La variable d'environnement SHELL est utilisée pour déterminer et lancer un shell, si aucun autre programme n'est donné sur la ligne de commande.

Si la variable d'environnement DISPLAY est définie, sa valeur est utilisée pour le nom d'affichage du maître xkibitz (l'affichage avec l'étiquette numéro 0). Sinon, ce nom reste vide.

Des arguments supplémentaires peuvent être passés aux nouveaux xterms via la variable d'environnement XKIBITZ_XTERM_ARGS. Par exemple, pour créer des xterms avec une barre de défilement et un curseur de pointeur vert :

XKIBITZ_XTERM_ARGS="-sb -ms green"
export XKIBITZ_XTERM_ARGS
(ceci est pour le shell Bourne - utilisez la syntaxe appropriée pour votre shell préféré). N'importe quelle option valide pour la commande xterm peut être donnée, à l'exception de -display, -geometry et -S, car celles-ci sont définies par xkibitz.
