XKBEVD(1) Manuel des commandes générales XKBEVD(1)

NOM

xkbevd - démon d'événements XKB

SYNTAXE

xkbevd [ options ]

DESCRIPTION

Cette commande est très basique et n'est donc que partiellement implémentée ; nous la présentons ici comme un prototype brut pour les développeurs, et non comme un outil d'usage général pour les utilisateurs finaux. Quelque chose comme cela pourrait remplacer xev ; je ne m'engage pas, bien sûr, mais c'est une idée intéressante.

Le démon d'événements xkbevd écoute les événements XKB spécifiés et exécute les commandes demandées si elles se produisent. Le fichier de configuration consiste en une liste de paires spécification d'événement/action et/ou de définitions de variables.

Une spécification d'événement consiste en un nom d'événement XKB court suivi d'une chaîne ou d'un identifiant qui sert de qualificateur entre parenthèses ; des parenthèses vides indiquent aucune qualification et servent à spécifier la commande par défaut qui est appliquée aux événements qui ne correspondent à aucune des autres spécifications. L'interprétation du qualificateur dépend du type de l'événement : les événements Bell correspondent en utilisant le nom de la sonnerie, les événements message correspondent au contenu de la chaîne du message, et les événements de touche lente acceptent l'un des termes press, release, accept, ou reject. Aucun autre événement n'est actuellement reconnu.

Une action consiste en un mot-clé optionnel suivi d'un argument de chaîne optionnel. Actuellement, xkbev reconnaît les actions : none, ignore, echo, printEvent, sound, et shell. Si l'action n'est pas spécifiée, la chaîne est prise comme le nom d'un fichier son à jouer, sauf si elle commence par un point d'exclamation, auquel cas elle est prise comme une commande shell.

Les définitions de variables dans la chaîne d'argument sont développées avec des champs de l'événement en question avant que la chaîne d'argument ne soit transmise au processeur d'actions. La syntaxe générale d'une variable est soit $c soit $(str), où c est un caractère unique et str est une chaîne de longueur arbitraire. Tous les paramètres ont des noms à un seul caractère et des noms longs.

La liste des paramètres reconnus varie d'un événement à l'autre et est trop longue pour être listée ici pour le moment. Il s'agit de toute façon d'une version développeur, vous pouvez donc être censé consulter le code source (evargs.c est d'un intérêt particulier).

Les actions ignore, echo, printEvent, sound, et shell font ce que vous attendez des commandes nommées ignore, echo, printEvent, sound, et shell, sauf que la commande sound n'a été implémentée et testée que sur les machines SGI. Elle lance actuellement un programme externe, elle devrait donc être assez facile à adapter, surtout si vous aimez les indications audio qui arrivent environ une demi-seconde après ce que vous attendez.

Les seules variables actuellement reconnues sont soundDirectory et soundCmd. Je suis sûr que vous pouvez deviner ce qu'elles font.

OPTIONS

-aide
Affiche un message d'utilisation bien plus à jour que tout ce qui se trouve dans cette page de manuel.
-cfg fichier
Spécifie le fichier de configuration à lire. Si aucun fichier de configuration n'est spécifié, xkbevd recherche ~/.xkb/xkbevd.cf et $(LIBDIR)/xkb/xkbevd.cf dans cet ordre.
-sc cmd
Spécifie la commande utilisée pour jouer les sons.
-sd répertoire
Spécifie un répertoire de haut niveau pour les fichiers sonores.
-affichage affichage
Spécifie l'affichage à utiliser. Si absent, xkbevd utilise $DISPLAY.
-bg
Indique à xkbevd de se forker (et de s'exécuter en arrière-plan).
-synch
Force la synchronisation de toutes les requêtes X. Lent.
-v
Affiche plus d'informations, y compris les messages de débogage. Plusieurs spécifications de -v provoquent plus de sorties, jusqu'à un certain point.
-version
Affiche la version du programme et quitte.
