NOM

xine - un lecteur vidéo libre

MRL (localisateur de ressource multimédia)

Les MRL sont similaires aux URL de votre navigateur Web. Elles décrivent le média à lire. Les MRL valides peuvent être des noms de fichiers simples ou l'un des éléments suivants (voir également les notes ci-dessous) :

• Système de fichiers :

file:<chemin>
fifo:<chemin>
stdin:/
• CD et DVD :

dvd:/[nom_de_périphérique][/titre[.partie]]
dvd:/fichier_image_DVD[/titre[.partie]]
dvd:/répertoire_DVD[/titre[.partie]]
(utilisez le chemin du répertoire qui contient VIDEO_TS)
vcd://[image_CD_ou_nom_de_périphérique][@[lettre]numéro]
vcdo://numéro_de_piste
cdda:/[périphérique][/numéro_de_piste]
• Périphériques vidéo :

v4l://[périphérique_tuner/fréquence]
v4l2://périphérique_tuner
dvb://numéro_de_canal
(nième canal dans votre channels.conf)
dvb://nom_de_canal
dvbc://nom_de_canal:paramètres_de_syntonisation
dvbs://nom_de_canal:paramètres_de_syntonisation
dvbt://nom_de_canal:paramètres_de_syntonisation
dvba://nom_de_canal:paramètres_de_syntonisation
pvr:/chemin_fichiers_temporaires!chemin_fichiers_enregistrés!âge_max_page
(pour WinTV PVR 250 et 350)
• Réseau :

http://hôte...
tcp://hôte[:port]
udp://hôte[:port[?iface=interface]]
rtp://hôte[:port[?iface=interface]]
(port par défaut pour tcp, udp et rtp est 7658)
smb://...
mms://hôte...
pnm://hôte...
rtsp://hôte... (nécessite les codecs Real)

Des plugins d'entrée supplémentaires fourniront des types MRL supplémentaires. Ceux listés ci-dessus sont disponibles avec la libxine standard.

NOTE : lorsque un nom de fichier est requis, le chemin complet doit être fourni - depuis un shell, vous pouvez normalement utiliser "$PWD/fichier" ou "$(pwd)/fichier" ou "`pwd`/fichier" si le fichier est dans le répertoire courant. (L'un d'eux dépend de votre shell ; les trois fonctionnent dans bash. De plus, les règles d'encodage URL normales s'appliquent ; `%` en particulier doit être encodé en `%25'.)

Depuis xine-lib 1.1.3, le numéro de titre DVD peut être 0 (sélectionner la navigation) et le numéro de chapitre peut être 0 (titre complet).

Syntaxe MRL VCD

Un simple vcd:/ lance l'élément par défaut (par exemple, peut-être la piste 1 ou l'entrée 0) en utilisant le périphérique VCD par défaut (par exemple /dev/cdrom). L'élément par défaut et le périphérique par défaut sont configurables par l'utilisateur.

Il est cependant également possible de spécifier explicitement le périphérique/nom de fichier de la Video CD et l'élément dans la MRL.

Par exemple, vcd:/dev/dvd spécifie l'entrée par défaut en utilisant le périphérique /dev/dvd, ce qui peut être utile s'il s'agit de votre DVD et qu'il est différent de votre périphérique CD-ROM et que votre lecteur DVD peut lire des CD. Et vcd://test_svcd_ntsc.cue spécifie le fichier cue pour l'image CD sur disque. (test_svcd_ntsc.bin est le fichier bin correspondant, mais son utilisation ne fonctionnera pas.)

Après le nom de périphérique ou le nom de fichier optionnel, vous pouvez nommer le type d'unité, précédé d'un deux-points. Une MRL qui se termine par un deux-points est comme ne pas l'ajouter du tout : le type et le numéro d'entrée par défaut sont utilisés. Les éléments se présentent en 4 saveurs : « Track », « Entry », « Playback » et « Segment ». Ces unités sont indiquées par la première lettre majuscule de chaque type : T, E, P, S, s. Un S majuscule dans l'affichage MRL indique un segment NTSC tandis qu'un s minuscule indique un segment PAL. Cependant, lorsque vous entrez une MRL, la casse de ces lettres est insignifiante.

En fonction de la Video CD, vous pourriez ne pas avoir de segments jouables (S,s) ou de contrôle de lecture (P). Si vous donnez une MRL qui fait référence à une entrée de contrôle de lecture mais qu'il n'y a pas de contrôle de lecture, votre numéro de lecture sera silencieusement converti en numéro d'entrée correspondant.

Vous pouvez configurer diverses choses qui affectent la façon dont les MRL sont sélectionnées lorsqu'il y a une ambiguïté dans le nom de la MRL. media.vcd.autoplay définit le type d'unité à utiliser dans une MRL s'il n'y en a pas. Un autre paramètre de configuration, vcd.device, détermine le périphérique à utiliser si cette partie n'est pas donnée. Lorsque vous appuyez sur le bouton VCD, cela équivaut à entrer vcd:/ et donc ces deux paramètres de configuration sont utilisés pour développer la MRL.

Quelques exemples de MRL sont donnés ci-dessous. Dans les exemples, nous supposons les paramètres de configuration suivants :

vcd://
Lit (navigue) l'élément par défaut (dans ce cas, l'ID d'entrée 0) depuis le périphérique par défaut (dans ce cas, défini sur /dev/cdrom)
vcd://@
Identique à ci-dessus
vcd:///dev/cdrom@
Même effet qu'auparavant puisque le périphérique par défaut est défini sur /dev/cdrom.
vcd:///dev/cdrom@E0
Identique à ci-dessus. Mais notez que c'est parce que nous avons autoplay:entry, qui n'est plus la valeur par défaut.
vcd:///dev/cdrom2@
Lit (navigue) l'élément par défaut de /dev/cdrom2
vcd:///dev/cdrom2
devrait être identique à ci-dessus mais est actuellement cassé ?
vcd:///dev/cdrom2@T1
Lit la piste 1 depuis /dev/cdrom2
vcd:///dev/cdrom@S1
Lit le segment 1 depuis /dev/cdrom. Cela suppose qu'il *existe* un segment 1. Vérifiez la liste des MRL pour voir si c'est le cas.
vcd://@P1
Lit l'élément de la liste de lecture 1 depuis le périphérique par défaut. S'il n'y a pas de contrôle de lecture, la MRL sera convertie en vcd:/@E0. Vérifiez à nouveau la liste des MRL pour voir s'il y a un P1.
vcd://@P1*
Probablement identique à ci-dessus.
vcd:///dev/cdrom@E1
Lit l'entrée id 1 depuis le périphérique par défaut.
vcd://@S0
Lit le segment 0 depuis le périphérique par défaut.
vcd://@3
Lit la piste 3 depuis le périphérique par défaut.
vcd:///dev/cdrom2:1
Lit la piste 1 depuis /dev/cdrom2.
vcd:///tmp/ntsc.cue@
Lit l'élément par défaut (E0) de /tmp/ntsc.bin. Notez le @ final.
vcd://ntsc.cue/@E0
Lit l'entrée 0 de ntsc.bin.
vcd:///tmp/ntsc.nrg/@E0
Lit l'entrée 0 de /tmp/ntsc.nrg (fichier Nero). Fonctionne pour quelques images Nero simples.

DVB

Les MRL DVB nécessitent que xine-lib/channels.conf existe dans $XDG_CONFIG_HOME/ ou ~/.config/ et contienne des données valides. Ceci peut être obtenu en générant un fichier de syntonisation avec l'utilitaire des applications DVB de LinuxTV appelé « scan » (ou « dvbscan » si vous utilisez une version plus récente que 1.1.0) :

scan -o zap /usr/share/doc/dvb-utils/examples/scan/dvb-t/uk-PontopPike >~/.config/xine-lib/channels.conf

(Cet exemple est pour l'émetteur local de l'auteur, utilisant un fichier du paquet dvb-utils de Debian.)

MRLs (media resource locators) for xine

MRL (media resource locator)

The MRL is the main way to access media files. It consists of a protocol and a location. Examples are:

file://...
A local file.
http://...
An HTTP stream.
ftp://...
An FTP stream.
mms://...
A MMS stream.
rtp://...
An RTP stream.
udp://...
An UDP stream.
tcp://...
A TCP stream.
dvb:
A DVB stream.

A DVB stream has the following formats:

DVB-S
<fréquence>:<polarisation>:<num-sat>:<débit-symbole>:<vpid>:<apid>:<id-service>
DVB-C
<fréquence>:<inversion>:<débit-symbole>:<fec>:<qam>:<vpid>:<apid>:<id-service>
DVB-T
<fréquence>:<inversion>:<bande-passante>:<fec-hp>:<fec-lp>:<qam>:<mode-transmission>:<intervalle-garde>:<info-hiérarchie>:<vpid>:<apid>:<id-service>
DVB-A
<fréquence>:<qam>:<vpid>:<apid>:<id-service>

Les paramètres individuels sont :

fréquence
nombre, généralement en kHz
polarisation
`v' ou `h'
num-sat
entier non signé long, généralement 0
débit-symbole
débit symboles en MSyms/sec
inversion
INVERSION_ON, INVERSION_OFF, INVERSION_AUTO
fec, fec-hp, fec-lp
FEC_1_2, FEC_2_3, FEC_3_4 ... FEC_8_9, FEC_AUTO, FEC_NONE
qam
QPSK, QAM_128, QAM_16 ...
bande-passante
BANDWIDTH_6_MHZ, BANDWIDTH_7_MHZ, BANDWIDTH_8_MHZ
mode-transmission
TRANSMISSION_MODE_2K, TRANSMISSION_MODE_8K
intervalle-garde
GUARD_INTERVAL_1_4, GUARD_INTERVAL_1_8, GUARD_INTERVAL_1_16, GUARD_INTERVAL_1_32,
info-hiérarchie
HIERARCHY_1, HIERARCHY_2, HIERARCHY_4, HIERARCHY_NONE
vpid
id du programme vidéo
apid
id du programme audio
id-service
id du service (nécessaire pour les informations actuelles/suivantes etc.)

Les entrées clavier & souris suivantes peuvent être acceptées :

Menu 2
Démarrer/arrêter l'enregistrement
Menu 3
Basculer le zoom
Menu 7
Afficher/masquer l'affichage actuel/suivant
Chapitre Précédent/Suivant
Canal précédent/suivant
Molette souris & bouton 1
Faire défiler la liste des canaux & sélectionner le canal en surbrillance

SOUS-TITRES

fichiers de sous-titres externes (n'importe quel mrl)
Les fichiers de sous-titres texte peuvent être ajoutés à la fin du MRL :.

<mrl>#subtitle:<fichier-sous-titre>
C'est la manière normale de définir le fichier de sous-titres à utiliser. Le frontend ne prêtera aucune attention au fichier de sous-titres. Par exemple :
file://home/user/wibble.mpg#subtitle:/home/user/wibble.sub
(Notez que certains frontends peuvent détecter des fichiers de sous-titres dont le nom diffère, comme montré dans l'exemple.)

OPTIONS DE FLUX

Après un délimiteur # vous pouvez ajouter plusieurs paramètres de flux :

novideo
La vidéo sera ignorée.
noaudio
L'audio sera ignoré.
nospu
Les sous-images seront ignorées.
demux:<nom-du-démux>
Spécifier le plugin de démux à utiliser.
volume:<niveau>
Régler le volume audio.
compression:<niveau>
Régler la compression de la plage dynamique audio.
<entrée-de-config>:<valeur-de-config>
Assigner une nouvelle valeur à n'importe quelle entrée de configuration.
save:<fichier>
Sauvegarder le flux (si autorisé) dans le fichier nommé, relatif au répertoire spécifié par l'option "media.capture.save_dir".
modifier l'option de configuration 'à la volée' :

Vous pouvez modifier n'importe quelle option de configuration à tout moment, en utilisant le style spécial MRL cfg:/. La syntaxe est :
cfg:/<entrée-de-config> : <valeur-de-config>
Contrairement aux options de configuration de flux, vous pouvez changer n'importe quoi *avant* de lire le flux.
