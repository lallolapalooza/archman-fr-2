NOM

xindy - créer un index trié et étiqueté à partir d'un index brut

SYNTAXE

xindy [-V?h] [-qv] [-d magic] [-o fichier.ind] [-t log] \
      [-L langue] [-C codepage] [-M module] [-I entree] \
      [idx0 idx1 ...]

Options longues style GNU pour options courtes :

-V / --version
-? / -h / --help
-q / --quiet
-v / --verbose
-d / --debug          (plusieurs fois)
-o / --out-file
-t / --log-file
-L / --language
-C / --codepage
-M / --module         (plusieurs fois)
-I / --input-markup   (supporté : latex, xelatex, omega, xindy)

DESCRIPTION

xindy est la commande indépendante du formatteur du système d'indexation flexible xindy. Elle prend un index brut en entrée et produit un index fusionné, trié et étiqueté. La fusion, le tri et l'étiquetage sont contrôlés par des fichiers de style xindy.

Les fichiers contenant l'index brut sont passés en arguments. Si aucun argument n'est passé, l'index brut sera lu depuis l'entrée standard.

xindy est entièrement décrit dans son manuel que vous trouverez sur son site Web, http://www.xindy.org/. Une bonne introduction descriptive se trouve dans le chapitre sur l'indexation du LaTeX Companion (2e éd.)

Si vous souhaitez produire un index pour des documents LaTeX, la commande texindy(1) est probablement plus intéressante pour vous. C'est un wrapper pour xindy qui active par défaut de nombreuses conventions LaTeX.

OPTIONS

"--version" / -V
affiche les numéros de version de tous les composants pertinents et quitte.
"--help" / -h / -?
affiche le message d'utilisation avec l'explication des options.
"--quiet" / -q
Ne pas afficher les messages de progression. Afficher uniquement les messages d'erreur.
"--verbose" / -v
Afficher les messages de progression détaillés.
"--debug" magic / -d magic
Affiche les messages de débogage, cette option peut être spécifiée plusieurs fois. magic détermine ce qui est affiché : 
magic          remarque
------------------------------------------------------------
script         messages de progression internes des scripts pilotes
keep_tmpfiles  ne pas supprimer les fichiers temporaires
markup         trace de sortie du balisage, comme expliqué dans le manuel xindy
level=n        niveau de journalisation, n est 0 (défaut), 1, 2 ou 3
"--out-file" fichier.ind / -o fichier.ind
Produit l'index dans le fichier fichier.ind. Si cette option n'est pas utilisée, le nom du fichier de sortie est le nom de base du premier argument avec l'extension ind. Si l'index brut est lu depuis l'entrée standard, cette option est obligatoire.
"--log-file" log.ilg / -t log.ilg
Produit les messages de journalisation dans le fichier log.ilg. Ces messages de journalisation sont indépendants des messages de progression que vous pouvez contrôler avec "--debug" ou "--verbose".
"--language" langue / -L langue
L'index est trié selon les règles de la langue langue. Ces règles sont encodées dans un module xindy créé par make-rules.

Si aucun encodage d'entrée n'est spécifié via "--codepage" ou forcé par le balisage d'entrée, un module xindy pour cette langue est recherché avec un encodage latin, cp, iso, ascii, ou utf8, dans cet ordre.

Les modules de langue sont placés soit dans le sous-répertoire lang, soit dans le sous-répertoire contrib/lang du répertoire de base des modules.

"--codepage" enc / -C enc
L'entrée brute est dans l'encodage d'entrée enc. Cette information est utilisée pour sélectionner le bon module de tri xindy et l'encodage de sortie des titres de groupe de lettres.

Lorsque le balisage d'entrée "xelatex" ou "omega" est utilisé, "utf8" est toujours utilisé comme codepage, puis cette option est ignorée.

Si l'entrée brute est en LICR, texindy(1) doit être utilisé au lieu de xindy(1). Il activera un mappage de l'encodage inputenc pour le balisage d'entrée "latex" vers la codepage d'entrée brute choisie.

"--module" module / -M module
Charge le module xindy module.xdy. Cette option peut être spécifiée plusieurs fois. Les modules sont recherchés dans le chemin de recherche xindy qui peut être modifié par la variable d'environnement "XINDY_SEARCHPATH".
"--input-markup" entree / -I entree
Spécifie le balisage d'entrée de l'index brut. Les valeurs supportées pour entree sont "latex", "xelatex", "omega", et "xindy".

"latex" et "xelatex" sont le balisage d'entrée qui est émis par défaut par le noyau LaTeX, ou par le package macro "index" de David Jones. La notation ^^- des caractères à octet unique est supportée. Le remappage des caractères encodés en LICR n'est pas effectué ; utilisez texindy(1) pour cela. Utilisez le balisage d'entrée "latex" si vous utilisez LaTeX standard ou pdfLaTeX et le balisage d'entrée "xelatex" si vous utilisez XeLaTeX ou LuaLaTeX.

"omega" le balisage d'entrée est similaire au balisage d'entrée "latex", mais avec la notation ^^- d'Omega comme encodage pour les caractères non-ASCII.

"xindy" le balisage d'entrée est spécifié dans le manuel xindy.

"--interactive"
Démarre xindy en mode interactif. Vous serez dans une boucle read-eval-loop de xindy où les expressions du langage xindy sont lues et évaluées interactivement.
"--mem-file" xindy.mem
Cette option n'est utilisable que par les développeurs ou dans des situations très rares. Le noyau xindy compilé est stocké dans un fichier dit de mémoire, nommé canoniquement xindy.mem, et situé dans le répertoire de la bibliothèque xindy. Cette option permet d'utiliser un autre noyau xindy.

ENVIRONNEMENT

"XINDY_SEARCHPATH"
Une liste de répertoires où les modules xindy sont recherchés. Aucune recherche dans les sous-arborescences n'est effectuée (comme dans TeX conforme au TDS).

Si cette variable d'environnement n'est pas définie, la valeur par défaut est utilisée : ".:"modules_dir":"modules_dir"/base". modules_dir est déterminé au moment de l'exécution, par rapport à l'emplacement de la commande xindy : soit c'est ../modules, ce qui est le cas pour les installations opt. Soit c'est ../lib/xindy/modules, ce qui est le cas pour les installations usr.

"XINDY_LIBDIR"
Répertoire de la bibliothèque où se trouve xindy.mem.

Le répertoire des modules peut aussi être un sous-répertoire.

COMPATIBILITÉ AVEC MAKEINDEX

xindy ne prétend pas être entièrement compatible avec MakeIndex, cela empêcherait certaines de ses améliorations. Cela dit, nous nous efforçons de fournir autant de compatibilité que possible. Les incompatibilités les plus importantes sont

  • Pour les entrées d'index brutes en syntaxe LaTeX, "\index{aaa|bbb}" est interprété différemment. Pour MakeIndex, "bbb" est un balisage qui est affiché comme une étiquette LaTeX pour ce numéro de page. Pour xindy, il s'agit d'un attribut de localisation, un identifiant abstrait qui sera plus tard associé au balisage qui doit être affiché pour cet attribut.

    Pour une utilisation simple, lorsque "bbb" est "textbf" ou similaire, nous fournissons des définitions d'attributs de localisation qui imitent le comportement de MakeIndex.

    Pour une utilisation plus complexe, lorsque "bbb" n'est pas un identifiant, il n'existe pas de définitions de compatibilité de ce type et elles ne peuvent pas non plus être créées avec la version actuelle de xindy. En particulier, cela signifie que par défaut, le package LaTeX "hyperref" crée des fichiers d'index bruts qui ne peuvent pas être traités par xindy. Ce n'est pas un bug, c'est le résultat malheureux d'une incompatibilité voulue. Il n'est actuellement pas possible d'obtenir à la fois les liens d'index de hyperref et d'utiliser xindy.

    Une situation similaire est rapportée pour la classe LaTeX "memoir".

    Les programmeurs qui connaissent Common Lisp et Lex et qui souhaitent travailler sur un remède sont priés de contacter l'auteur.

  • Si vous avez une plage d'index et un attribut de localisation, par exemple, "\index{key\(attr}" commence la plage, il faut (1) spécifier cet attribut dans l'entrée de fermeture de plage également (c'est-à-dire comme "\index{key\)attr}") et (2) il faut déclarer l'attribut d'index dans un fichier de style xindy.

    MakeIndex affichera le balisage "\attr{page1--page2}" pour une telle construction. Ceci n'est pas possible à réaliser dans xindy, la sortie sera "\attrMarkup{page1}--\attrMarkup{page2}". (Ceci est en fait considéré comme un bug, mais pas une priorité élevée.)

    La différence entre les étiquettes de numéro de page de MakeIndex et les attributs de localisation de xindy a déjà été expliquée dans le point précédent.

  • Les définitions de compatibilité MakeIndex ne prennent en charge que la syntaxe d'index brute par défaut et la définition de balisage. Il n'est pas possible de configurer l'analyse des index bruts ou d'utiliser un fichier de style MakeIndex pour décrire le balisage de sortie.

PROBLÈMES CONNUS

L'option -q empêche également l'affichage des messages d'erreur. Les messages d'erreur devraient être affichés sur stderr, les messages de progression sur stdout.

Il devrait y avoir un moyen d'afficher l'index final sur stdout. Cela impliquerait -q, bien sûr.

L'analyse des index bruts LaTeX devrait être configurable.

Le codepage "utf8" devrait être pris en charge pour toutes les langues, et devrait être utilisé comme codepage interne pour le réencodage de l'inputenc de LaTeX.
