XINE(1) Manuel des commandes générales XINE(1)

NOM

xine - un lecteur vidéo libre

SYNTAXE

xine [options] [MRL] ...

DESCRIPTION

Cette page de manuel documente brièvement le lecteur audio/vidéo xine.

xine lit les flux système MPEG (audio et vidéo), les flux élémentaires MPEG (par ex. fichiers .mp3 ou .mpv), les flux de transport MPEG, les fichiers ogg, les fichiers avi, les fichiers asf, les fichiers quicktime, les (S)VCD et les DVD, et bien plus encore.

OPTIONS

Les programmes suivent la syntaxe habituelle des lignes de commande GNU, avec des options longues commençant par deux traits d'union (`--'). Un résumé des options est inclus ci-dessous. Pour une description complète, consultez README et FAQ dans /usr/share/doc/xine-ui ou sur la page d'accueil de xine.

-h, --help
Affiche un résumé des options et des pilotes de sortie disponibles (plugins).
--verbose[=niveau]
Définit le niveau de verbosité.
-c, --config <fichier>
Utilise le fichier de configuration au lieu du fichier par défaut.
-a, --audio-channel <num>
Sélectionne le canal audio donné. <num> est le numéro du canal audio, le défaut est 0.
xine 0.5 et plus récents essaient de collecter tous les canaux audio valides (ac3, mpeg audio, avi audio, ...) du flux et les mappent à des canaux "virtuels" avec des numéros de canaux commençant à 0.
-V, --video-driver <drv>
Sélectionne le pilote vidéo. Consultez xine --help pour une liste des plugins de sortie vidéo disponibles sur votre système. Cette sélection est automatiquement enregistrée dans votre fichier ~/.xine/config, vous n'aurez donc à spécifier le pilote vidéo qu'une seule fois.
-A, --audio-driver <drv>
Sélectionne le pilote audio. Consultez xine --help pour une liste des plugins de sortie audio disponibles sur votre système. Cette sélection est automatiquement enregistrée dans votre fichier ~/.xine/config, vous n'aurez donc à spécifier le pilote audio qu'une seule fois.
-u, --spu-channel <num>
Sélectionne le canal de sous-titres (SPU). <num> est l'ID du canal de sous-titres, le défaut est aucun sous-titre (-1).
-p, --auto-play=[f][F][h][w][q][d][v]
Commence la lecture immédiatement après le démarrage. Peut être suivi de :
`f' en mode plein écran,
`F' en mode plein écran xinerama,
`h' pour masquer l'interface graphique (panneau principal, etc...),
`w' pour masquer la fenêtre de sortie vidéo,
`q' pour quitter après la lecture,
Il est également possible de demander la liste de lecture du DVD `d', ou du VCD `v'. Il existe maintenant une option plus générique, --auto-scan, pour cela (voir ci-dessous).
-s, --auto-scan <plugin>
Scanne automatiquement la liste de lecture depuis le plugin d'entrée nommé. De nombreux plugins permettent de lire une liste de lecture par défaut, afin de tout jouer. Cela fonctionne bien pour les DVD ou les VCD, par exemple. Donner cette option a le même effet que d'appuyer sur le bouton correspondant sur le panneau principal de xine.

Cette option est particulièrement utile en combinaison avec l'auto-lecture. Vous pourriez lancer xine --auto-play --auto-scan dvd pour lire un DVD entier sans avoir à appuyer sur d'autres boutons. Cela fonctionne aussi pour les plugins qui ne sont pas fournis avec xine, donnez simplement le nom du bouton que le plugin souhaité ajoute au panneau xine !

-f, --fullscreen
Passe xine en mode plein écran au démarrage (comme appuyer sur `f')
-F, --xineramafull
Passe xine en mode plein écran xinerama au démarrage (comme appuyer sur `F'). C'est-à-dire, essayer d'étendre l'affichage sur plusieurs écrans. Les écrans à utiliser sont définis dans le fichier de configuration.
-g, --hide-gui
Masque toutes les fenêtres de l'interface graphique (sauf la fenêtre vidéo) au démarrage. C'est la même chose que d'appuyer sur `G' dans xine.
-H, --hide-video
Masque la fenêtre de sortie vidéo.
-L, --no-lirc
Désactive le support LIRC. Cette option est uniquement disponible si xine a été compilé avec le support LIRC.
--visual <classe-visuelle-ou-id>
Essaie d'utiliser une visualisation spécifique du serveur X11 pour les fenêtres xine. Le paramètre <classe-visuelle-ou-id> est soit le nom d'une classe visuelle X11 (StaticGray, GrayScale, StaticColor, PseudoColor, TrueColor ou DirectColor) soit la valeur hexadécimale d'une visualisation spécifique X11.

Lorsqu'elle est utilisée avec un nom de classe visuelle, xine essaie de trouver une visualisation de ce type avec une profondeur de 15 ou 16, 24, 32 ou 8 (dans cet ordre). La classe visuelle par défaut utilisée par xine en l'absence d'une option --visual est TrueColor.

Si aucune visualisation utilisable n'est trouvée, xine revient à la visualisation par défaut utilisée pour la fenêtre racine du serveur X11.

--install
Lors de l'utilisation d'une visualisation X11 avec des couleurs modifiables (colormaps), installe une colormap privée pour xine. Avec une colormap privée, xine peut allouer plus de couleurs afin que la sortie vidéo puisse paraître meilleure.
--keymap [=option]
Affiche la table des raccourcis clavier. Les options sont :
`default' affiche la table des raccourcis par défaut,
`lirc' affiche un brouillon d'un fichier de configuration ~/.lircrc,
`remapped' table des raccourcis redéfinis par l'utilisateur,
`file:<fichier>' utilise le fichier comme table des raccourcis,
Si aucune option n'est donnée, `default' est sélectionné.
-n, --network
Active le serveur de contrôle à distance par réseau. Pour utiliser le serveur de contrôle à distance par réseau, un fichier de mots de passe est requis. Si xine ne le trouve pas, le serveur s'arrête. La syntaxe du fichier de mots de passe suit le schéma (familier) <identification>:<motdepasse>. Comme la cryptographie est sujette à des problèmes juridiques dans certains pays, le mot de passe n'est pas crypté et est également transmis sans cryptage, faites donc attention aux connexions à distance. Deux règles génériques (optionnelles) sont également disponibles (une à la fois) 
ALL:ALLOW ou ALL:DENY
Dans le premier cas, tous les clients sont autorisés à exécuter toutes les commandes disponibles, sans restriction. Dans le second cas, personne n'est autorisé à exécuter de commandes, à l'exception des utilisateurs identifiés (en utilisant la commande 'identify').

Si une entrée de mot de passe commence par un astérisque `*', l'utilisateur est bloqué. Si une entrée de mot de passe est vide, l'entrée complète est ignorée. Voici un exemple d'un petit fichier ~/.xine/passwd :

ALL:DENY
daniel:mypasswd
foo:*
Ceci n'autorisera que 'daniel' à exécuter des commandes, après une étape d'identification réussie.

Le port par défaut du serveur est 6789, ce numéro est totalement arbitraire. Vous pouvez vous connecter au serveur en utilisant une simple commande telnet :

telnet localhost 6789
Pour changer le port par défaut, vous pouvez (en tant que root) éditer votre fichier /etc/services et ajouter une entrée comme celle-ci : 
xinectl    7890/tcp        # xine control
Ceci changera le port par défaut de 6789 à 7890, et créera un service "humain" appelé xinectl.

Le serveur lui-même offre une aide/syntaxe de commande :
help [commande]
Sans spécifier de commande, toutes les commandes disponibles seront affichées. Si une commande est spécifiée, un bref texte sur la fonctionnalité de la commande sera donné.
syntax <commande>
Affiche la syntaxe de la commande.

MRL (localisateur de ressource média)

Les MRL sont similaires aux URL de votre navigateur web. Ils décrivent le média à lire. xine(5) les décrit en détail. xine étend la syntaxe comme suit :

<mrl>::<fichier_sous-titre>
C'est la manière spécifique à xine-ui de définir le fichier de sous-titres à utiliser. Le nom de fichier sera extrait par le frontend, ce qui permet de le modifier, de l'enregistrer dans une liste de lecture, etc...

Après un délimiteur #, vous pouvez ajouter plusieurs paramètres de flux :

la vidéo sera ignorée

définir la compression de la plage dynamique audio

attribuer une nouvelle valeur à n'importe quelle entrée de configuration

Vous pouvez changer une option de configuration à tout moment, en utilisant le style spécial cfg:/ mrl. La syntaxe est :
cfg:/<entree_config> : <valeur_config>
Contrairement aux options de configuration de flux, vous pouvez changer n'importe quoi avant de lire le flux.

DESCRIPTION

La plupart des commandes de xine peuvent être précédées d'un argument numérique. Ceci s'applique à la plupart des commandes qui peuvent être activées par une combinaison de touches. Par exemple, si vous tapez 3 puis la touche de fonction associée à la commande, celle-ci sera exécutée 3 fois. Cependant, il y a quelques exceptions importantes.

Les commandes qui peuvent être préfacées par un argument numérique sont les commandes qui peuvent être invoquées par une combinaison de touches, comme par exemple le passage à la piste suivante ou précédente (TRACK_NEXT, TRACK_PRIOR), le passage au chapitre suivant ou précédent (CHAPTER_NEXT, CHAPTER_PRIOR), le passage à la page suivante ou précédente (PAGE_NEXT, PAGE_PRIOR), la recherche (SEEK), etc.

Il est possible de définir la longueur du saut en avant ou en arrière pour la commande SEEK. Par exemple, en tapant "99/", c'est-à-dire la touche numérique 9 deux fois puis la touche slash, vous devriez rechercher 99% du flux actuel.

Le nouveau plugin VCD/SVCD permet une certaine saisie numérique. En entrant un nombre suivi de la touche "Sélectionner événement" (par défaut, la touche entrée du pavé numérique), on peut aller à un "Chapitre" (piste ou entrée) ou un numéro de sélection spécifique. Comme il s'agit d'une fonctionnalité relativement nouvelle, il est possible qu'à terme, davantage de plugins utilisent la sélection numérique.

D'autres commandes pouvant être précédées d'un argument numérique sont le MRL suivant/précédent (MRL_NEXT, MRL_PRIOR), le sous-titre suivant/précédent (SPU_NEXT, SPU_PRIOR), et le canal audio suivant/précédent (AUDIOCHAN_NEXT, AUDIOCHAN_PRIOR). Avec un préfixe numérique, c'est comme si l'on avait entré cette commande autant de fois. Ici, l'argument 0, étant autrement dénué de sens, est interprété comme 1.

Certes, l'utilité de la saisie numérique ici est limitée. Au fil du temps, des commandes plus utiles, comme la spécification d'un numéro de MRL, de sous-titre ou de canal audio spécifique ou absolu, seront peut-être implémentées.
