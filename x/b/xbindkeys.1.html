NOM

xbindkeys - un programme de capture de touches pour X

SYNTAXE

xbindkeys [ options ]

DESCRIPTION

XbindKeys est un programme qui capture les événements de touches et de boutons de souris dans X et lance des commandes shell associées.

OPTIONS EN LIGNE DE COMMANDE

Les options en ligne de commande disponibles sont les suivantes :

-d, --defaults
Imprime un fichier rc par défaut
-f, --file
Utilise un fichier rc alternatif
-h, --help
Aide courte sur les options plus des informations sur la version/l'auteur.
-X, --display
Définit l'affichage X à utiliser
-v, --verbose
Plus d'informations sur xbindkeys lorsqu'il s'exécute
-k, --key
Identifie une touche pressée (utile pour la configuration)
-mk, --multikey
Identifie une combinaison de touches pressées (utile pour la configuration)
-g, --geometry
Taille et position de la fenêtre avec l'option -k|-mk
-n, --nodaemon
ne démarre pas en tant que démon

Si le support guile n'a pas été désactivé :

-dg, --defaults-guile
Imprime un fichier de configuration guile par défaut
-fg, --file-guile
Utilise un fichier de configuration guile alternatif

XBINDKEYSRC

Le fichier de configuration par défaut de XBindKeys est $HOME/.xbindkeysrc, utilisé uniquement pour un utilisateur.

Le fichier de configuration consiste en des commandes entre guillemets doubles, et les touches associées sur la ligne suivante.

Les commentaires sont commencés par un dièse (#) et s'étendent jusqu'à la fin de la ligne.

Vous pouvez voir une configuration par défaut avec --defaults


KEYSYMS

Le programme attend des combinaisons de keysyms à utiliser en combinant les caractères plus (+) les uns avec les autres.

Le format d'une ligne de commande est :

    "commande à lancer &"
       touche associée
Pour spécifier une touche associée, vous pouvez utiliser `xbindkeys --key` ou
`xbindkeys --multikey` et placer l'une des deux lignes dans le fichier de configuration.

Une liste de touches se trouve dans /usr/include/X11/keysym.h et dans /usr/include/X11/keysymdef.h. Le préfixe XK_ n'est pas nécessaire.

Liste des modificateurs :

    Release, Control, Shift, Mod1 (Alt), Mod2 (NumLock),
    Mod3 (CapsLock), Mod4, Mod5 (Scroll).
Le modificateur Release n'est pas un modificateur X standard, mais vous pouvez l'utiliser si vous souhaitez capturer les événements de relâchement au lieu des événements de pression. Les modificateurs ne sont pas sensibles à la casse.

Par défaut, xbindkeys ne fait pas attention aux modificateurs NumLock, CapsLock et ScrollLock. Ajoutez les lignes ci-dessous dans le fichier de configuration si vous souhaitez y prêter attention.


keystate_numlock = enable

    keystate_capslock = enable
    keystate_scrolllock= enable

EXEMPLES

# control+shift+q lance xterm

"xterm"
  control+shift + q
# Touche Menu lance xbindkeys_show
"xbindkeys_show"
  Menu
# Control + bouton de souris 1 lance xterm
"xterm"
  Control + b:1
# Control+Shift+a  événement de relâchement lance rxvt
"rxvt"
  release+control+shift + a
# Control + bouton de souris 2 événement de relâchement lance rxvt
"rxvt"
  Control + b:2 + Release

STYLE DE CONFIGURATION SCHEME

Une configuration Scheme peut être utilisée si le support guile n'a pas été désactivé. La configuration standard est chargée uniquement si la configuration scheme n'est pas disponible.

Pour plus de détails, veuillez consulter ici

http://www.gnu.org/software/guile/guile.html 
Note : Le fichier de configuration guile est préféré pour les configurations non triviales
, par exemple les doubles clics, les clics chronométrés ou les combinaisons de touches.
L'emplacement par défaut est ~/.xbindkeysrc.scm
Utilisez xbindkeys --defaults-guile pour plus de détails.
Et xbindkeys --defaults-guile > ~/.xbindkeysrc.scm pour utiliser cette méthode.

NOTE

xbindkeys recharge le fichier de configuration s'il est modifié. Envoyez un signal HUP pour forcer le rechargement :

killall -HUP xbindkeys

Lorsqu'un signal HUP est envoyé à xbindkeys, les changements prennent effet uniquement après le déplacement de la souris.
