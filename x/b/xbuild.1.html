xbuild(1) Manuel des commandes générales xbuild(1)

NOM

xbuild - Outil de Mono pour construire des fichiers de projet MSBuild

SYNTAXE

xbuild [option] [fichier-projet]

DESCRIPTION

xbuild peut être utilisé pour construire des fichiers de projet MSBuild. Les environnements de développement intégrés comme MonoDevelop et "Microsoft Visual Studio .NET" utilisent le format de fichier de projet msbuild.

xbuild prend le chemin du fichier de projet ou de solution à construire comme argument principal. Si aucun fichier n'est spécifié, il essaie de construire n'importe quel fichier de solution ou de projet dans le répertoire courant qui a une extension *proj.

OPTIONS

/target:T1[,TN]
Liste des cibles à construire
/property:Nom=Valeur
Définir ou remplacer des propriétés de projet
/logger:<logger>
Journaliseur personnalisé pour enregistrer les événements de construction
/toolsversion:version , /tv:version
Spécifie la version de la boîte à outils à utiliser.

Ex. /tv:4.0
Cela provoquera l'utilisation de la version 4.0 de Microsoft.Common.targets (entre autres). Cela remplace
la valeur spécifiée dans un fichier projet.

Valeurs valides : 2.0, 3.0, 3.5 et 4.0

/verbosity:<level>
Niveau de verbosité du journaliseur : quiet, minimal, normal, detailed, diagnostic
/validate
Valide le fichier projet par rapport au schéma
/validate:<schema>
Valide le fichier projet par rapport au schéma spécifié
/consoleloggerparameters:<params> , /clp:<params>
Paramètres pour le journaliseur de console : PerfomanceSummary, Summary, NoSummary, NoItemAndPropertyList, Verbosity
/filelogger[n] , /fl[n]
Enregistre la sortie dans un fichier, nommé 'msbuild.log' par défaut. Si le numéro optionnel 'n' est spécifié, alors il enregistre dans 'msbuild[n].log'. Les paramètres de ce journaliseur, y compris le nom du fichier journal, peuvent être spécifiés via une option /flp[n] correspondante. La verbosité par défaut pour les journaux de fichiers est 'detailed'. 'n' peut être compris entre 1 et 9.
/fileloggerparameters[n]:<params> , /flp[n]:<params>
Paramètres pour un journaliseur de fichiers. Ceci implique un /fl[n] correspondant. 'n' peut être compris entre 1 et 9, et est utilisé pour ajouter jusqu'à 10 journaux de fichiers. Les paramètres peuvent être, en plus de ceux disponibles pour le journaliseur de console :
LogFile=<fichier>
Fichier dans lequel le journal de construction sera écrit.
Append
Si cela est utilisé, le fichier journal est ajouté, sinon un nouveau sera créé.
Encoding=<encodage>
Encodage à utiliser pour le fichier journal, par ex. UTF-8, ASCII.
Ex. : xbuild foo.csproj /flp:Verbosity=normal "/flp1:LogFile=build.log;Append;Encoding=ASCII"
/nologo
Ne pas afficher la bannière initiale de xbuild
/help
Afficher l'utilisation de xbuild
/version
Afficher la version de xbuild

VARIABLES D'ENVIRONNEMENT

XBUILD_EMIT_SOLUTION
Si cette variable est définie, alors le fichier projet généré à partir d'un fichier solution est émis.
XBUILD_LOG_REFERENCE_RESOLVER
Les références sont résolues en essayant une liste de chemins de recherche d'assemblages ($(AssemblySearchPaths)). Si xbuild ne parvient pas à résoudre une référence, il enregistre les détails expliquant pourquoi les différents chemins de recherche ont échoué. Si cette variable est définie, il enregistre la même chose même pour les références qui ont été résolues avec succès. Ces journaux apparaissent si la verbosité est définie sur 'detailed' ou plus.
MSBuildExtensionsPath
Les extensions MSBuild sont généralement installées dans $(MSBuildExtensionsPath), que xbuild résout en $prefix/lib/mono/xbuild. Lorsqu'il est utilisé dans un Import, comme :


<Import Project="$(MSBuildExtensionsPath)\TestTargets.targets"/>

xbuild essaie différentes valeurs pour la propriété msbuild $(MSBuildExtensionsPath), dans cet ordre :


1. Chemins spécifiés dans la variable d'environnement $MSBuildExtensionsPath.
2. /Library/Frameworks/Mono.framework/External/xbuild sur Mac OSX.
3. $XDG_CONFIG_HOME/xbuild/tasks (ou Environment.SpecialFolder.ApplicationData)
4. $prefix/lib/mono/xbuild (emplacement par défaut)

N'importe où ailleurs dans les fichiers projet, $(MSBuildExtensionsPath) se résoudra toujours à l'emplacement par défaut. Ceci est une fonctionnalité propre à xbuild. Ceci s'applique également aux propriétés $(MSBuildExtensionsPath32) et $(MSBuildExtensionsPath64), et les variables d'environnement ont les noms correspondants - MSBuildExtensionsPath32/64.

XBUILD_FRAMEWORK_FOLDERS_PATH
Avec ToolsVersion 4.0, les projets peuvent cibler des frameworks arbitraires référencés par TargetFrameworkMoniker, qui est du format :


Identifier,Version=<version>[,Profile=<profile>]

Ex. : ".NETFramework,Version=v4.0"

Les 3 parties du moniker sont données par les propriétés msbuild :


$(TargetFrameworkIdentifier), $(TargetFrameworkVersion) et $(TargetFrameworkProfile)

Ce moniker correspond à un fichier de description de framework sur disque :


<framework_root>/Identifier/Version/[Profile]/RedistList/FrameworkList.xml

Ce fichier est utilisé pour déterminer le chemin où trouver les assemblages du framework pour ce framework particulier.

La racine du framework ici est configurable et est résolue dans l'ordre suivant :

  1. Chemins spécifiés dans la variable d'environnement $XBUILD_FRAMEWORK_FOLDERS_PATH
  2. /Library/Frameworks/Mono.framework/External/xbuild-frameworks sur Mac OSX.
  3. Propriété MSBuild $(TargetFrameworkRoot)
  4. $prefix/lib/mono/xbuild-frameworks (emplacement par défaut)

XBuild essaie les chemins donnés ci-dessus, dans l'ordre, jusqu'à ce qu'il trouve un FrameworkList.xml pour le moniker. L'exécution avec une verbosité /v:detailed ou supérieure montrera les différents chemins qu'il essaie.

Le FrameworkList.xml lui-même a juste un élément racine comme :


<FileList Name=".NET Framework 3.5" TargetFrameworkDirectory="..\..\..\..\3.5" IncludeFramework="v3.0">
</FileList>

Ici, l'attribut TargetFrameworkDirectory spécifie le répertoire où les assemblages pour ce framework particulier peuvent être trouvés. S'il n'est pas défini, alors le parent du dossier contenant le fichier xml est considéré comme le répertoire du framework.

L'attribut IncludeFramework spécifie la version d'un framework (sous le *même* $(TargetFrameworkIdentifier)) qui devrait être incluse dans la liste finale des répertoires du framework cible.

XBUILD_COLORS
Si cette variable est définie, elle contient une chaîne de la forme "type=foreground,type=.." qui spécifie quelle couleur utiliser pour afficher les erreurs/avertissements etc sur certains terminaux. Le type ici peut être : 
errors, warnings, messages ou events
events : Ce sont des événements de début et de fin de projet/cible/tâche
        messages.

Les couleurs possibles pour le premier plan sont : black, red, brightred, green, brightgreen, yellow, brightyellow, blue, brightblue, magenta, brightmagenta, cyan, brightcyan, grey, white et brightwhite.

Par exemple, vous pourriez définir cette variable depuis votre shell :

export XBUILD_COLORS
XBUILD_COLORS=errors=brightred,warnings=blue

Vous pouvez désactiver le schéma de couleurs intégré en définissant cette variable sur "disable".

NOTES

Sur Mac OSX, pour localiser les fichiers pkg-config (.pc), xbuild recherche également dans "/Library/Frameworks/Mono.framework/Extern
