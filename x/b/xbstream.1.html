NOM

xbstream - Documentation Percona xbstream

Pour prendre en charge la compression et le streaming simultanés, un nouveau format de streaming personnalisé appelé xbstream a été introduit dans Percona XtraBackup en plus du format TAR. Cela était nécessaire pour surmonter certaines limitations des formats d'archive traditionnels tels que tar, cpio et autres, qui ne permettaient pas le streaming de fichiers générés dynamiquement, par exemple des fichiers compressés dynamiquement. D'autres avantages d'xbstream par rapport aux formats de streaming/archive traditionnels incluent la capacité de streamer plusieurs fichiers simultanément (il est donc possible d'utiliser le streaming au format xbstream avec l'option --parallel) et un stockage de données plus compact.

Cet utilitaire a une interface similaire à tar :

  • avec l'option -x, il extrait les fichiers du flux lu depuis son entrée standard vers le répertoire courant, sauf indication contraire avec l'option -c. La prise en charge de l'extraction parallèle avec l'option --parallel a été implémentée dans Percona XtraBackup 2.4.7.
  • avec l'option -c, il transmet les fichiers spécifiés sur la ligne de commande à sa sortie standard.
  • avec l'option --decrypt=ALGO, xbstream déchiffrera automatiquement les fichiers chiffrés lors de l'extraction du flux d'entrée. Les valeurs supportées pour cette option sont : AES128, AES192 et AES256. Les options --encrypt-key ou --encrypt-key-file doivent être spécifiées pour fournir la clé de chiffrement, mais pas les deux. Cette option a été implémentée dans Percona XtraBackup 2.4.7.
  • avec l'option --encrypt-threads, vous pouvez spécifier le nombre de threads pour le chiffrement parallèle des données. La valeur par défaut est 1. Cette option a été implémentée dans Percona XtraBackup 2.4.7.
  • l'option --encrypt-key est utilisée pour spécifier la clé de chiffrement qui sera utilisée. Elle ne peut pas être utilisée avec l'option --encrypt-key-file car elles sont mutuellement exclusives. Cette option a été implémentée dans Percona XtraBackup 2.4.7.
  • l'option --encrypt-key-file est utilisée pour spécifier le fichier contenant la clé de chiffrement. Elle ne peut pas être utilisée avec l'option --encrypt-key car elles sont mutuellement exclusives. Cette option a été implémentée dans Percona XtraBackup 2.4.7.

L'utilitaire tente également de minimiser son impact sur le cache de pages du système d'exploitation en utilisant les appels posix_fadvise() appropriés lorsqu'ils sont disponibles.

Lorsque la compression est activée avec xtrabackup, toutes les données sont compressées, y compris le fichier journal des transactions et les fichiers de métadonnées, en utilisant l'algorithme de compression spécifié. Le seul algorithme actuellement supporté est quicklz.

Les fichiers résultants ont le format d'archive qpress, c'est-à-dire que chaque fichier *.qp produit par xtrabackup est essentiellement une archive qpress en un seul fichier et peut être extrait et décompressé par l'archiveur de fichiers qpress. Cela signifie qu'il n'est pas nécessaire de décompresser une sauvegarde entière pour restaurer une seule table comme avec tar.gz.

Pour décompresser des fichiers individuels, exécutez xbstream avec l'option --decompress. Vous pouvez contrôler le nombre de threads utilisés pour la décompression en passant l'option --decompress-threads.

De plus, les fichiers peuvent être décompressés à l'aide de l'outil qpress qui peut être téléchargé ici. Qpress prend en charge la décompression multi-thread.
