XGETTEXT(1) Commandes utilisateur XGETTEXT(1)

NOM

xgettext - extrait les chaînes gettext des sources

SYNTAXE

xgettext [OPTION] [FICHIER_ENTREE]...

DESCRIPTION

Extrait les chaînes traduisibles des fichiers d'entrée donnés.

Les arguments obligatoires pour les options longues sont également obligatoires pour les options courtes. Idem pour les arguments optionnels.

Emplacement du fichier d'entrée :

FICHIER_ENTREE ...
fichiers d'entrée
-f, --files-from=FICHIER
obtient la liste des fichiers d'entrée depuis FICHIER
-D, --directory=REPERTOIRE
ajoute REPERTOIRE à la liste pour la recherche des fichiers d'entrée

Si le fichier d'entrée est -, l'entrée standard est lue.

Emplacement du fichier de sortie :

-d, --default-domain=NOM
utilise NOM.po pour la sortie (au lieu de messages.po)
-o, --output=FICHIER
écrit la sortie dans le fichier spécifié
-p, --output-dir=DIR
les fichiers de sortie seront placés dans le répertoire DIR

Si le fichier de sortie est -, la sortie est écrite sur la sortie standard.

Choix de la langue du fichier d'entrée :

-L, --language=NOM
reconnaît la langue spécifiée (C, C++, ObjectiveC, PO, Python, Java, JavaProperties, C#, JavaScript, TypeScript, TSX, Scheme, Guile, Lisp, EmacsLisp, librep, Rust, Go, Ruby, Shell, awk, Lua, Modula-2, D, Smalltalk, Vala, Tcl, Perl, PHP, GCC-source, YCP, NXStringTable, RST, RSJ, Glade, GSettings, Desktop)
-C, --c++
raccourci pour --language=C++

Par défaut, la langue est devinée en fonction de l'extension du nom du fichier d'entrée.

Interprétation du fichier d'entrée :

--from-code=NOM
encodage des fichiers d'entrée (sauf pour Python, Tcl, Glade)

Par défaut, les fichiers d'entrée sont supposés être en ASCII.

Mode de fonctionnement :

-j, --join-existing
fusionne les messages avec le fichier existant
-x, --exclude-file=FICHIER.po
les entrées de FICHIER.po ne sont pas extraites
-cTAG, --add-comments=TAG
place les blocs de commentaires commençant par TAG et précédant les lignes de mots-clés dans le fichier de sortie
-c, --add-comments
place tous les blocs de commentaires précédant les lignes de mots-clés dans le fichier de sortie
--check=NOM
effectue une vérification de syntaxe sur les messages (ellipsis-unicode, space-ellipsis,
quote-unicode, bullet-unicode)
--sentence-end=TYPE
type décrivant la fin de phrase (single-space, qui est la valeur par défaut,
ou double-space)

Options spécifiques à la langue :

-a, --extract-all
extrait toutes les chaînes (uniquement les langues C, C++, ObjectiveC, Python, Java, C#, JavaScript, TypeScript, TSX, Scheme, Guile, Lisp, EmacsLisp, librep, Rust, Go, Shell, awk, Lua, Modula-2, D, Vala, Tcl, Perl, PHP, GCC-source, Glade, GSettings)
-kMOT, --keyword=MOT
recherche MOT comme mot-clé supplémentaire
-k, --keyword
n'utilise pas les mots-clés par défaut (uniquement les langues C, C++, ObjectiveC, Python, Java, C#, JavaScript, TypeScript, TSX, Scheme, Guile, Lisp, EmacsLisp, librep, Rust, Go, Shell, awk, Lua, Modula-2, D, Vala, Tcl, Perl, PHP, GCC-source, Glade, GSettings, Desktop)
--flag=MOT:ARG:FLAG
drapeau supplémentaire pour les chaînes à l'intérieur de l'argument numéro ARG du mot-clé MOT
(uniquement les langues C, C++, ObjectiveC, Python,
Java, C#, JavaScript, TypeScript, TSX, Scheme, Guile, Lisp, EmacsLisp, librep, Rust, Go, Shell, awk, Lua, Modula-2, D, Vala, Tcl, Perl, PHP, GCC-source, YCP)
--tag=MOT:FORMAT
définit le comportement des littéraux de gabarits balisés avec le tag MOT
(uniquement la langue JavaScript)
-T, --trigraphs
comprend les trigraphes ANSI C pour l'entrée (obsolète ; uniquement les langues C, C++, ObjectiveC)
--its=FICHIER
applique les règles ITS du FICHIER (uniquement les langues basées sur XML)
--qt
reconnaît les chaînes de format Qt (uniquement la langue C++)
--kde
reconnaît les chaînes de format KDE 4 (uniquement la langue C++)
--boost
reconnaît les chaînes de format Boost (uniquement la langue C++)
--debug
résultat de reconnaissance de chaîne de format plus détaillé

Détails de la sortie :

--color
utilise toujours les couleurs et autres attributs de texte
--color=QUAND
utilise les couleurs et autres attributs de texte si QUAND. QUAND peut être 'always', 'never', 'auto', ou 'html'.
--style=FICHIER_STYLE
spécifie le fichier de règles CSS pour --color
-e, --no-escape
n'utilise pas les échappements C dans la sortie (par défaut)
-E, --escape
utilise les échappements C dans la sortie, pas de caractères étendus
--force-po
écrit le fichier PO même s'il est vide
-i, --indent
écrit le fichier .po en utilisant un style indenté
--no-location
n'écrit pas les lignes '#: nom_fichier:ligne'
-n, --add-location
génère les lignes '#: nom_fichier:ligne' (par défaut)
--strict
écrit un fichier .po strictement conforme à Uniforum
--properties-output
écrit un fichier .properties Java
--stringtable-output
écrit un fichier .strings NeXTstep/GNUstep
--itstool
écrit les commentaires itstool
-w, --width=NOMBRE
définit la largeur de page de sortie
--no-wrap
ne coupe pas les longues lignes de messages, plus longues que la largeur de page de sortie, en plusieurs lignes
xgettext(1) — Arch Linux

NAME

xgettext - extract internationalization (NLS) strings from source code

Synopsis

xgettext [OPTION]... [FILE]...

DESCRIPTION

xgettext is a tool to get български internationalization strings from source files.

It scans the source files specified by FILE arguments for calls to gettext-compatible functions (like gettext, ngettext, catenate, etc.) and writes the found strings, comments and other information to a template file in the standard PO format.

This template file is then used to produce the language-specific message files for each language.

Options:

-s, --sort-output
generate sorted output (deprecated)
-F, --sort-by-file
sort output by file location
--omit-header
don't write header with 'msgid ""' entry
--no-git
don't use the git program to produce a reproducible 'POT-Creation-Date' field in the output.
--copyright-holder=STRING
set copyright holder in output
--foreign-user
omit FSF copyright in output for foreign user
--package-name=PACKAGE
set package name in output
--package-version=VERSION
set package version in output
--msgid-bugs-address=EMAIL@ADDRESS
set report address for msgid bugs
--generated=FILE
Declares that the given FILE is generated and therefore should not have an influence on the 'POT-Creation-Date' field in the output.
--reference=FILE
Declares that the output depends on the contents of the given FILE. This has an influence on the 'POT-Creation-Date' field in the output.
-m[STRING], --msgstr-prefix[=STRING]
use STRING or "" as prefix for msgstr values
-M[STRING], --msgstr-suffix[=STRING]
use STRING or "" as suffix for msgstr values

Informative output:

-h, --help
display this help and exit
-V, --version
output version information and exit
-v, --verbose
increase verbosity level
