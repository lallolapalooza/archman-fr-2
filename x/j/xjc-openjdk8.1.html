NOM

xjc - Compile un fichier de schéma XML en classes Java entièrement annotées.

SYNTAXE

xjc [ options ] schéma fichier/URL/répertoire/jar ... [-b infos_liaison ] ...
options
Les options de ligne de commande. Voir Options.
schéma fichier/URL/répertoire/jar ...
L'emplacement du fichier de schéma XML. Si répertoire est spécifié, tous les fichiers de schéma qu'il contient sont compilés. Si jar est spécifié, le fichier de liaison /META-INF/sun-jaxb.episode est compilé.
-b infos_liaison

L'emplacement des fichiers de liaison.

DESCRIPTION

Démarrez le compilateur de liaison avec le script shell xjc approprié dans le répertoire bin pour votre plateforme. Il existe également une tâche Ant pour exécuter le compilateur de liaison. Voir Utilisation de XJC avec Ant à http://jaxb.java.net/nonav/2.1.3/docs/xjcTask.html

OPTIONS

•
Voir aussi Options non standard
•
Voir aussi Options obsolètes et supprimées
-nv

Par défaut, le compilateur de liaison XJC effectue une validation stricte du schéma source avant de le traiter. Utilisez cette option pour désactiver la validation stricte du schéma. Cela ne signifie pas que le compilateur de liaison n'effectuera aucune validation, mais qu'il effectuera une validation moins stricte.
-extension

Par défaut, le compilateur de liaison XJC applique strictement les règles décrites dans le chapitre Compatibilité de la spécification JAXB. L'annexe E.2 définit un ensemble de fonctionnalités W3C XML Schema qui ne sont pas entièrement prises en charge par JAXB v1.0. Dans certains cas, vous pourrez être autorisé à les utiliser en mode -extension activé par ce commutateur. En mode par défaut (strict), vous êtes également limité à l'utilisation des personnalisations de liaison définies dans la spécification. En utilisant le commutateur -extension, vous serez autorisé à utiliser les extensions du fournisseur JAXB.
-b fichier

Spécifie un ou plusieurs fichiers de liaison externes à traiter. Chaque fichier de liaison doit avoir son propre commutateur -b. La syntaxe des fichiers de liaison externes est flexible. Vous pouvez avoir un seul fichier de liaison contenant des personnalisations pour plusieurs schémas ou vous pouvez diviser la personnalisation en plusieurs fichiers de liaison : xjc schema1.xsd schema2.xsd schema3.xsd -b bindings123.xjbxjc schema1.xsd schema2.xsd schema3.xsd -b bindings1.xjb -b bindings2.xjb -b bindings3.xjb. De plus, l'ordre des fichiers de schéma et des fichiers de liaison sur la ligne de commande n'a pas d'importance.
-d répertoire

Par défaut, le compilateur de liaison XJC génère les classes de contenu Java dans le répertoire courant. Utilisez cette option pour spécifier un répertoire de sortie alternatif. Le répertoire de sortie doit déjà exister. Le compilateur de liaison XJC ne le crée pas pour vous.
-p pkg

Lorsque vous spécifiez un package cible avec cette option de ligne de commande, elle remplace toute personnalisation de liaison pour le nom du package et l'algorithme de nommage de package par défaut défini dans la spécification.
-httpproxy proxy

Spécifie le proxy HTTP ou HTTPS au format [utilisateur[:mot_de_passe]@]hôte_proxy[:port_proxy]. Les anciennes options -host et -port sont toujours prises en charge par la RI pour des raisons de compatibilité descendante, mais elles ont été dépréciées. Le mot de passe spécifié avec cette option est un argument visible par les autres utilisateurs qui utilisent la commande `top`. Pour une plus grande sécurité, utilisez l'option -httpproxyfile.
-httpproxyfile fichier

Spécifie le proxy HTTP ou HTTPS avec un fichier. Même format que l'option -httpproxy, mais le mot de passe spécifié dans le fichier n'est pas visible par les autres utilisateurs.
-classpath arg

Spécifie où trouver les fichiers de classe des applications clientes utilisés par la personnalisation jxb:javaType et xjc:superClass.
-catalog fichier

Spécifie des fichiers catalogue pour résoudre les références d'entités externes. Prend en charge les formats TR9401, XCatalog et OASIS XML Catalog. Voir Resolvers d'entités et URI XML à http://xerces.apache.org/xml-commons/components/resolver/resolver-article.html
-readOnly

Par défaut, le compilateur de liaison XJC ne rend pas les fichiers source Java générés protégés en écriture. Utilisez cette option pour forcer le compilateur de liaison XJC à marquer les sources Java générées comme en lecture seule.
-npa

Supprime la génération d'annotations au niveau du package dans **/package-info.java. L'utilisation de ce commutateur oblige le code généré à internaliser ces annotations dans les autres classes générées.
-no-header

Supprime la génération d'un commentaire d'en-tête de fichier qui inclut une note et un horodatage. Son utilisation rend le code généré plus compatible avec la commande diff.
-target 2.0

Évite de générer du code qui dépend de fonctionnalités JAXB 2.1. Cela permettra au code généré de s'exécuter avec un environnement d'exécution JAXB 2.0 (tel que Java SE 6).
-xmlschema

Traite les schémas d'entrée comme W3C XML Schema (par défaut). Si vous ne spécifiez pas ce commutateur, vos schémas d'entrée seront traités comme des schémas W3C XML.
-relaxing

Traite les schémas d'entrée comme RELAX NG (expérimental et non pris en charge). La prise en charge des schémas RELAX NG est fournie en tant qu'extension du fournisseur JAXB.
-relaxing-compact

Traite les schémas d'entrée comme syntaxe compacte RELAX NG (expérimental et non pris en charge). La prise en charge des schémas RELAX NG est fournie en tant qu'extension du fournisseur JAXB.
-dtd

Traite les schémas d'entrée comme DTD XML (expérimental et non pris en charge). La prise en charge des schémas RELAX NG est fournie en tant qu'extension du fournisseur JAXB.
-wsdl

Traite l'entrée comme WSDL et compile les schémas qu'elle contient (expérimental et non pris en charge).
-quiet

Supprime la sortie du compilateur, telle que les informations de progression et les avertissements.
-verbose

Soyez très verbeux, par exemple en affichant des messages informatifs ou en affichant des traces de pile lors de certaines erreurs.
-help

Affiche un bref résumé des commutateurs du compilateur.
-version

Affiche les informations sur la version du compilateur.
schéma fichier/URL/répertoire
Spécifie un ou plusieurs fichiers de schéma à compiler. Si vous spécifiez un répertoire, la commande xjc le parcourt pour trouver tous les fichiers de schéma et les compile.

OPTIONS NON STANDARD

-XLocator

Induit que le code généré expose les informations SAX Locator sur le XML source dans les instances de beans Java après le dé-sérialisation.
-Xsync-methods

Induit que toutes les signatures de méthodes générées incluent le mot-clé synchronized.

NOM

xjc - Compilation de schémas en classes Java

SYNOPSIS

xjc [options] <schema-file>+

DESCRIPTION

Le compilateur xjc (XML Schema to Java Code) est un outil de ligne de commande qui génère des classes Java à partir d'un ou plusieurs fichiers de schéma XML (XSD).

Les classes Java générées sont conformes aux spécifications JAXB (Java Architecture for XML Binding). Elles fournissent une représentation orientée objet de la structure de vos documents XML définis par les schémas.

Vous pouvez personnaliser le processus de génération de code à l'aide de diverses options en ligne de commande et de fichiers de liaison (binding files).

OPTIONS

Les options suivantes sont disponibles :

-b fichier-de-liaison

Spécifie un fichier de liaison externe pour personnaliser le mappage entre le schéma XML et le code Java.
-d répertoire-de-sortie

Spécifie le répertoire où les fichiers Java générés doivent être placés.
-p nom-de-paquetage

Définit le nom du paquetage Java par défaut pour les classes générées. Cette option a la priorité sur les autres méthodes de détermination du nom de paquetage.
-q

Mode silencieux. Supprime les messages informatifs de la sortie.
-verbose

Active la sortie détaillée du compilateur.
-encoding encodage

Spécifie l'encodage des fichiers source Java générés.
-enable-external-entity

Autorise le traitement des entités externes dans les schémas XML. À utiliser avec prudence.
-grammar

Génère des classes pour la grammaire W3C XML Schema.
-g

Génère les classes d'interface **/runtime.
-mark-generated

Marque le code généré avec l'annotation @javax.annotation.Generated.
-episode fichier-episode

Génère le fichier épisode spécifié pour la compilation séparée.

OPTIONS OBSOLÈTES ET SUPPRIMÉES

-host et -port

Ces options sont remplacées par l'option -httpproxy. Pour des raisons de compatibilité ascendante, ces options sont prises en charge, mais ne seront pas documentées et pourraient être supprimées dans les futures versions.
-use-runtime

Comme la spécification JAXB 2.0 a défini un environnement d'exécution portable, il n'est plus nécessaire pour le JAXB RI de générer des paquets **/impl/runtime. Par conséquent, ce commutateur est obsolète et a été supprimé.
-source

Le commutateur de compatibilité -source a été introduit dans la première version préliminaire de JAXB 2.0. Ce commutateur est supprimé des futures versions de JAXB 2.0. Si vous avez besoin de générer du code 1.0.x, utilisez une installation de la base de code 1.0.x.

RESTRICTIONS DU COMPILATEUR

En général, il est plus sûr de compiler tous les schémas associés comme une seule unité avec les mêmes commutateurs de compilation de liaison. Gardez à l'esprit la liste des restrictions suivantes lorsque vous exécutez la commande xjc. La plupart de ces problèmes ne s'appliquent que lorsque vous compilez plusieurs schémas avec plusieurs invocations de la commande xjc.

Pour compiler plusieurs schémas en même temps, gardez à l'esprit les règles de précédence suivantes pour le nom du paquetage Java cible :

1.
L'option -p a la priorité la plus élevée.
2.
Personnalisation jaxb:package.
3.
Si targetNamespace est déclaré, appliquez le targetNamespace à l'algorithme de nom de paquetage Java défini dans la spécification.
4.
Si aucun targetNamespace n'est déclaré, utilisez un paquetage codé en dur nommé generated.

Vous ne pouvez pas avoir plus d'une seule jaxb:schemaBindings par espace de noms, il est donc impossible de compiler deux schémas dans le même espace de noms cible dans différents paquetages Java.

Tous les schémas compilés dans le même paquetage Java doivent être soumis au compilateur de liaison XJC en même temps. Ils ne peuvent pas être compilés indépendamment et fonctionner comme prévu.

Les groupes de substitution d'éléments répartis sur plusieurs fichiers de schéma doivent être compilés en même temps.
