XMODMAP(1) Manuel des commandes générales XMODMAP(1)

NOM

xmodmap - utilitaire pour modifier les mappages de touches et les boutons de curseur dans X

SYNTAXE

xmodmap [-options ...] [nom_fichier]

DESCRIPTION

Le programme xmodmap est utilisé pour éditer et afficher la table de mappage des modificateurs du clavier et la table de mappage des touches qui sont utilisées par les applications clientes pour convertir les codes de touches événements en keysyms. Il est généralement lancé depuis le script de démarrage de la session de l'utilisateur pour configurer le clavier selon les préférences personnelles.

OPTIONS

Les options suivantes peuvent être utilisées avec xmodmap:

-display affichage
Cette option spécifie l'hôte et l'affichage à utiliser.
-help
Cette option indique qu'une brève description des arguments de la ligne de commande doit être imprimée sur le canal d'erreur standard. Cela sera fait chaque fois qu'un argument non géré sera donné à xmodmap.
-grammar
Cette option indique qu'un message d'aide décrivant la grammaire des expressions utilisées dans les fichiers et avec les expressions -e doit être imprimé sur l'erreur standard.
-version
Cette option indique que xmodmap doit imprimer ses informations de version et quitter.
-verbose
Cette option indique que xmodmap doit imprimer des informations de journalisation lors de l'analyse de son entrée.
-quiet
Cette option désactive la journalisation détaillée. C'est le comportement par défaut.
-n
Cette option indique que xmodmap ne doit pas modifier les mappages, mais doit afficher ce qu'il ferait, comme make(1) le fait lorsqu'il reçoit cette option.
-e expression
Cette option spécifie une expression à exécuter. Un nombre quelconque d'expressions peut être spécifié depuis la ligne de commande.
-pm
Cette option indique que la table de mappage des modificateurs actuelle doit être imprimée sur la sortie standard. C'est le mode de fonctionnement par défaut si aucune autre option de mode n'est spécifiée.
-pk
Cette option indique que la table de mappage des touches actuelle doit être imprimée sur la sortie standard.
-pke
Cette option indique que la table de mappage des touches actuelle doit être imprimée sur la sortie standard sous forme d'expressions pouvant être renvoyées à xmodmap.
-pp
Cette option indique que la table de mappage du curseur actuelle doit être imprimée sur la sortie standard.
-
Un tiret seul signifie que l'entrée standard doit être utilisée comme fichier d'entrée.

Le nom_fichier spécifie un fichier contenant des expressions xmodmap à exécuter. Ce fichier est généralement conservé dans le répertoire personnel de l'utilisateur sous un nom tel que .xmodmaprc.

GRAMMAIRE DES EXPRESSIONS

Le programme xmodmap lit une liste d'expressions et les analyse toutes avant de tenter d'en exécuter une seule. Cela permet de faire référence à des keysyms qui sont redéfinis de manière naturelle sans avoir à se soucier autant des conflits de noms.

La liste des noms de keysyms peut être trouvée dans le fichier d'en-tête <X11/keysymdef.h> (sans le préfixe XK_). Les keysyms correspondant aux caractères Unicode peuvent être spécifiés comme "U0020" à "U007E" et "U00A0" à "U10FFFF" pour tous les caractères Unicode possibles.

keycode NOMBRE = NOM_KEYSYM ...
La liste des keysyms est assignée au keycode indiqué (qui peut être spécifié en décimal, hexadécimal ou octal et peut être déterminé en lançant le programme xev). Jusqu'à huit keysyms peuvent être attachés à une touche, cependant les quatre derniers ne sont utilisés dans aucune implémentation majeure de serveur X. Le premier keysym est utilisé lorsqu'aucune touche modificatrice n'est pressée en conjonction avec cette touche, le deuxième avec Shift, le troisième lorsque la touche Mode_switch est utilisée avec cette touche et le quatrième lorsque les touches Mode_switch et Shift sont utilisées.
keycode any = NOM_KEYSYM ...
Si aucune touche existante n'a la liste spécifiée de keysyms qui lui est assignée, une touche libre du clavier est sélectionnée et les keysyms lui sont assignés. La liste des keysyms peut être spécifiée en décimal, hexadécimal ou octal.
keysym NOM_KEYSYM = NOM_KEYSYM ...
Le NOM_KEYSYM du côté gauche est traduit en keycodes correspondants utilisés pour exécuter l'ensemble des expressions keycode correspondantes. Notez que si le même keysym est lié à plusieurs touches, l'expression est exécutée pour chaque keycode correspondant.
clear NOM_MODIFICATEUR
Cela supprime toutes les entrées de la table de modificateurs pour le modificateur donné, où les noms valides sont : Shift, Lock, Control, Mod1, Mod2, Mod3, Mod4, et Mod5 (la casse n'a pas d'importance dans les noms de modificateurs, bien qu'elle soit importante pour tous les autres noms). Par exemple, ``clear Lock'' supprimera toutes les touches qui étaient liées au modificateur de verrouillage majuscule.
add NOM_MODIFICATEUR = NOM_KEYSYM ...
Cela ajoute toutes les touches contenant les keysyms donnés à la table de modificateurs indiquée. Les noms de keysyms sont évalués après la lecture de toutes les expressions d'entrée pour faciliter l'écriture d'expressions pour échanger des touches (voir la section EXEMPLES).
remove NOM_MODIFICATEUR = NOM_KEYSYM ...
Cela supprime toutes les touches contenant les keysyms donnés de la table de modificateurs indiquée. Contrairement à add, les noms de keysyms sont évalués lors de la lecture de la ligne. Cela vous permet de supprimer des touches d'un modificateur sans avoir à vous soucier de savoir si elles ont été réaffectées ou non.
pointer = default
Cela rétablit la table du curseur à ses paramètres par défaut (bouton 1 génère un code de 1, bouton 2 génère un 2, etc.).
pointer = NOMBRE ...
Cela définit la table du curseur pour contenir les codes de boutons indiqués. La liste commence toujours par le premier bouton physique. Définir un code de bouton à 0 désactive les événements de ce bouton.

Les lignes qui commencent par un point d'exclamation (!) sont considérées comme des commentaires.

Si vous souhaitez modifier la liaison d'une touche modificatrice, vous devez également la supprimer de la table de modificateurs appropriée.

EXEMPLES

De nombreux curseurs sont conçus de telle sorte que le premier bouton est pressé en utilisant l'index de la main droite. Les gauchers trouvent fréquemment qu'il est plus confortable d'inverser les codes de boutons générés afin que le bouton principal soit pressé avec l'index de la main gauche. Cela pourrait être fait sur un curseur à 3 boutons comme suit :

%  xmodmap -e "pointer = 3 2 1"

De nombreuses applications prennent en charge la notion de touches Meta (similaires aux touches Control, sauf que Meta est maintenue enfoncée au lieu de Control). Cependant, certains serveurs n'ont pas de keysym Meta dans la table de mappage par défaut, il faut donc en ajouter une à la main. La commande suivante attachera Meta à la touche Multi-langue (parfois étiquetée Caractère de composition). Elle tire également parti du fait que les applications qui ont besoin d'une touche Meta doivent simplement obtenir le keycode et n'ont pas besoin que le keysym soit dans la première colonne de la table de mappage. Cela signifie que les applications qui recherchent une Multi_key (y compris la table de modificateurs par défaut) ne remarqueront aucun changement.

%  xmodmap -e "

;clésym Multi_key = Multi_key Meta_L"

De même, certains claviers ont une touche Alt mais pas de touche Meta. Dans ce cas, ce qui suit peut être utile :

%  xmodmap -e "keysym Alt_L = Meta_L Alt_L"

L'une des utilisations les plus simples, mais pratiques, de xmodmap est de faire en sorte que la touche "rubout" du clavier génère une clé alternative. Cela implique souvent d'échanger Backspace avec Delete pour être plus confortable pour l'utilisateur. Si la ressource ttyModes dans xterm est également définie, toutes les fenêtres de l'émulateur de terminal utiliseront la même touche pour effacer les caractères :

%  xmodmap -e "keysym BackSpace = Delete"
%  echo "XTerm*ttyModes:  erase ^?" | xrdb -merge

Certains claviers ne génèrent pas automatiquement les caractères inférieur et supérieur lorsque les touches virgule et point sont majusculées. Cela peut être corrigé avec xmodmap en réinitialisant les liaisons pour la virgule et le point avec les scripts suivants :

!
! faire de la touche Maj-, < et de la touche Maj-. >
!
keysym comma = comma less
keysym period = period greater

L'une des différences les plus irritantes entre les claviers est l'emplacement des touches Contrôle et Verr Maj. Une utilisation courante de xmodmap est d'échanger ces deux touches comme suit :

!
! Échanger Caps_Lock et Control_L
!
remove Lock = Caps_Lock
remove Control = Control_L
keysym Control_L = Caps_Lock
keysym Caps_Lock = Control_L
add Lock = Caps_Lock
add Control = Control_L

Cet exemple peut être exécuté à nouveau pour échanger les clés et les remettre à leurs affectations précédentes.

La commande keycode est utile pour affecter la même clé à plusieurs codes de touches. Bien que non portable, elle permet également d'écrire des scripts qui peuvent réinitialiser le clavier à un état connu. Le script suivant fait en sorte que la touche retour arrière génère Delete (comme montré ci-dessus), vide toutes les liaisons de verrouillage des majuscules existantes, fait de la touche Verr Maj une touche de contrôle, fait que F5 génère Échap, et fait de Pause/Réinitialisation un verrouillage des majuscules.

!
! Sur le HP, les codes de touches suivants correspondent aux touches indiquées :
!
!     101  Retour arrière
!      55  Maj
!      14  Ctrl
!      15  Pause/Réinitialisation
!      86  Arrêt
!      89  F5
!
keycode 101 = Delete
keycode 55 = Control_R
clear Lock
add Control = Control_R
keycode 89 = Escape
keycode 15 = Caps_Lock
add Lock = Caps_Lock

ENVIRONNEMENT

DISPLAY
pour obtenir l'hôte et le numéro d'affichage par défaut.

VOIR AUSSI

X(7), xev(1), setxkbmap(1), XStringToKeysym(3), documentation Xlib sur les événements clavier et souris

BOGUES

Chaque fois qu'une expression keycode est évaluée, le serveur génère un événement MappingNotify sur chaque client. Cela peut provoquer une certaine surcharge. Toutes les modifications doivent être regroupées et effectuées en une seule fois. Les clients qui reçoivent une entrée clavier et ignorent les événements MappingNotify ne remarqueront aucun changement apporté aux mappages clavier.

Xmodmap devrait générer automatiquement des expressions "add" et "remove" chaque fois qu'un code de touche déjà associé à un modificateur est modifié.

Il devrait y avoir un moyen pour que l'expression remove accepte les codes de touches ainsi que les clés pour les cas où vous détruisez vraiment vos mappages.
