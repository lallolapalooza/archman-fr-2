NOM

xml_grep - Recherche dans les fichiers XML en quête d'éléments spécifiques

SYNTAXE

xml_grep [options] <liste de fichiers>

ou

xml_grep <expression XPath> <liste de fichiers>

Par défaut, vous pouvez simplement fournir à "xml_grep" une expression XPath et une liste de fichiers, et obtenir un fichier XML avec le résultat.

Ceci est équivalent à écrire

xml_grep --group_by_file fichier --pretty_print indenté --cond <liste de fichiers>

OPTIONS

--help
message d'aide bref
--man
documentation complète
--Version
affiche la version de l'outil
--root <cond>
recherche et retourne les fragments XML correspondant à <cond>

si ni "--root" ni "--file" ne sont utilisés, alors l'élément (les éléments) qui déclenche(nt) l'option "--cond" est (sont) utilisé(s). Si "--cond" n'est pas utilisé, alors tous les éléments correspondant à <cond> sont retournés.

plusieurs "--root" peuvent être fournis

--cond <cond>
retourne les fragments (ou noms de fichiers) seulement s'ils contiennent des éléments correspondant à <cond>

plusieurs "--cond" peuvent être fournis (auquel cas ils sont combinés par un OU)

--files
retourne seulement les noms de fichiers (ne génère pas de sortie XML)

l'utilisation de cette option exclut l'utilisation des options qui définissent la sortie XML : "--roots", "--encoding", "--wrap", "--group_by_file" ou "--pretty_print"

--count
retourne seulement le nombre de correspondances dans chaque fichier

l'utilisation de cette option exclut l'utilisation des options qui définissent la sortie XML : "--roots", "--encoding", "--wrap", "--group_by_file" ou "--pretty_print"

--strict
sans cette option, les erreurs d'analyse sont signalées sur STDOUT et le fichier est sauté
--date
lorsqu'elle est activée (par défaut), l'élément enveloppant reçoit un attribut "date" qui indique la date à laquelle l'outil a été exécuté.

avec "--nodate", cet attribut n'est pas ajouté, ce qui peut être utile si vous avez besoin de comparer 2 exécutions.

--encoding <enc>
encodage de la sortie XML (utf-8 par défaut)
--nb_results <nb>
affiche seulement <nb> résultats
--by_file
affiche seulement <nb> résultats par fichier
--wrap <tag>
enveloppe le résultat XML dans la balise fournie (par défaut 'xml_grep')

Si wrap est défini sur une chaîne vide ("--wrap ''"), alors le résultat XML n'est pas enveloppé du tout.

--nowrap
identique à l'utilisation de "--wrap ''" : le résultat XML n'est pas enveloppé.
--descr <chaîne>
attributs de la balise enveloppante (par défaut "version="<VERSION>" date="<date>"")
--group_by_file <balise_optionnelle>
enveloppe les résultats pour chaque fichier dans un élément séparé. Par défaut, cet élément est nommé "file". Il possède un attribut nommé "filename" qui donne le nom du fichier.

la version courte de cette option est -g

--exclude <condition>
identique à l'utilisation de "-v" dans grep : les éléments qui correspondent à la condition sont exclus du résultat, le ou les fichiers d'entrée restent inchangés.

la forme courte de cette option est -v

--pretty_print <style_optionnel>
imprime joliment la sortie en utilisant les styles de XML::Twig ('"indented"', '"record"' ou '"record_c"' sont probablement ce que vous recherchez)

si l'option est utilisée mais qu'aucun style n'est donné, alors '"indented"' est utilisé

forme courte pour cet argument est -s

--text_only
Affiche le texte des résultats, une ligne par résultat.
--html
Permet une entrée HTML, les fichiers sont convertis en utilisant HTML::TreeBuilder
--Tidy
Permet une entrée HTML, les fichiers sont convertis en utilisant HTML::Tidy

Syntaxe de condition

<cond> est une expression de type XPath telle qu'autorisée par XML::Twig pour déclencher des gestionnaires.

exemples :
'para'
'para[@compact="compact"]'
'*[@urgent]'
'*[@urgent="1"]'
'para[string()="WARNING"]'

voir XML::Twig pour une description plus complète de la syntaxe <cond>

les options sont traitées par Getopt::Long, elles peuvent donc commencer par '-' ou '--' et peuvent être abrégées ("-r" au lieu de "--root" par exemple)

DESCRIPTION

xml_grep effectue une recherche dans les fichiers XML. Au lieu d'utiliser des expressions régulières, il utilise des expressions XPath (en fait, le sous-ensemble d'XPath pris en charge par XML::Twig).

les résultats peuvent être les noms des fichiers ou des éléments XML contenant des éléments correspondants.
