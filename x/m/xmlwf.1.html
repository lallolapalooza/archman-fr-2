NOM

xmlwf - Détermine si un document XML est bien formé

SYNTAXE


xmlwf
[OPTIONS] [FICHIER ...]

xmlwf
-h | --help

xmlwf
-v | --version

DESCRIPTION

xmlwf utilise la bibliothèque Expat pour déterminer si un document XML est bien formé. Il n'est pas validant.

Si vous ne spécifiez aucun fichier sur la ligne de commande, et si vous avez une version récente de xmlwf, le fichier d'entrée sera lu depuis l'entrée standard.

DOCUMENTS BIEN FORMÉS

Un document bien formé doit respecter les règles suivantes :

•
Le fichier commence par une déclaration XML. Par exemple, <?xml version="1.0" standalone="yes"?>. NOTE : xmlwf ne vérifie actuellement pas la validité de la déclaration XML.
•
Chaque balise ouvrante est soit vide (<balise/>) soit possède une balise fermante correspondante.
•
Il y a exactement un élément racine. Cet élément doit contenir tous les autres éléments du document. Seuls les commentaires, les espaces blancs et les instructions de traitement peuvent apparaître après la fermeture de l'élément racine.
•
Tous les éléments s'imbriquent correctement.
•
Toutes les valeurs d'attributs sont entourées de guillemets (simples ou doubles).

Si le document possède une DTD et qu'il est strictement conforme à cette DTD, alors le document est également considéré comme valide. xmlwf est un analyseur non validant -- il ne vérifie pas la DTD. Cependant, il prend en charge les entités externes (voir l'option -x).

OPTIONS

Lorsqu'une option inclut un argument, vous pouvez spécifier l'argument soit séparément ("-d sortie") soit concaténé avec l'option ("-dsortie"). xmlwf prend en charge les deux.

-a facteur
Définit le facteur d'amplification maximum toléré pour se protéger contre les attaques de type "mille milliards de rires" (par défaut : 100.0). Le facteur d'amplification est calculé comme .. 
            amplification := (direct + indirect) / direct

.. lors de l'analyse, où <direct> est le nombre d'octets lus depuis le document principal lors de l'analyse et <indirect> est le nombre d'octets ajoutés par l'expansion des entités et la lecture des fichiers DTD externes, combinés.

NOTE : Si vous devez jamais augmenter cette valeur pour une charge utile non-attaquante, veuillez signaler un bug.

-b octets
Définit le nombre d'octets de sortie (y compris l'amplification) nécessaires pour activer la protection contre les attaques de type "mille milliards de rires" (par défaut : 8 Mio). Cela peut être considéré comme un "seuil d'activation".

NOTE : Si vous devez jamais augmenter cette valeur pour une charge utile non-attaquante, veuillez signaler un bug.

-c
Si le fichier d'entrée est bien formé et que xmlwf ne rencontre aucune erreur, le fichier d'entrée est simplement copié dans le répertoire de sortie tel quel. Cela implique aucune espace de noms (désactive -n) et nécessite -d pour spécifier un répertoire de sortie.
-d rep-sortie
Spécifie un répertoire pour contenir les représentations transformées des fichiers d'entrée. Par défaut, -d génère une représentation canonique (décrite ci-dessous). Vous pouvez sélectionner différents formats de sortie en utilisant -c, -m et -N.

Les noms de fichiers de sortie seront exactement les mêmes que les noms de fichiers d'entrée ou "STDIN" si l'entrée provient de l'entrée standard. Par conséquent, vous devez faire attention à ce que le fichier de sortie n'aille pas dans le même répertoire que le fichier d'entrée. Sinon, xmlwf supprimera le fichier d'entrée avant de générer le fichier de sortie (comme exécuter cat < fichier > fichier dans la plupart des shells).

Deux documents XML structurellement équivalents ont une représentation XML canonique identique octet pour octet. Notez que les espaces blancs ignorables sont considérés comme significatifs et sont traités de manière équivalente aux données. Pour en savoir plus sur XML canonique, consultez http://www.jclark.com/xml/canonxml.html .

-e encodage
Spécifie l'encodage de caractères du document, remplaçant toute déclaration d'encodage du document. xmlwf prend en charge quatre encodages intégrés : US-ASCII, UTF-8, UTF-16 et ISO-8859-1. Voir aussi l'option -w.
-g octets
Définit la taille du tampon à demander par paire d'appels à XML_GetBuffer et read (par défaut : 8 Kio).
-h, --help
Affiche des informations d'utilisation succinctes sur la commande xmlwf, puis quitte. Similaire à cette page de manuel mais plus concise.
-k
Lors du traitement de plusieurs fichiers, xmlwf s'arrête par défaut après le premier fichier rencontrant une erreur. Ceci indique à xmlwf de signaler l'erreur mais de continuer le traitement. Ceci peut être utile, par exemple, lors du test d'un filtre qui convertit de nombreux fichiers en XML et que vous souhaitez savoir rapidement quelles conversions ont échoué.
-m
Génère un fichier XML d'un type étrange qui décrit complètement le fichier d'entrée, y compris les positions des caractères. Nécessite -d pour spécifier un fichier de sortie.
-n
Active le traitement des espaces de noms. (décrire les espaces de noms) -c désactive les espaces de noms.
-N
Ajoute une déclaration doctype et des déclarations de notation à la sortie XML canonique. Ceci correspond à la sortie exemple utilisée par les cas de test XML formels. Nécessite -d pour spécifier un fichier de sortie.
-p
Indique à xmlwf de traiter les DTD externes et les entités paramétriques.

Normalement, xmlwf n'analyse jamais les entités paramétriques. -p lui dit de toujours les analyser. -p implique -x.

-q
Désactive le report de ré-analyse et permet un temps d'analyse quadratique sur de grands jetons (par défaut : report de ré-analyse activé).
-r
Normalement, xmlwf utilise la mémoire mappée pour le fichier XML avant l'analyse ; cela peut entraîner une analyse plus rapide sur de nombreuses plateformes. -r désactive la mémoire mappée et utilise à la place des appels d'E/S de fichier normaux. Bien sûr, la mémoire mappée est automatiquement désactivée lors de la lecture depuis l'entrée standard.

L'utilisation de la mémoire mappée peut amener certaines plateformes à signaler une utilisation de mémoire considérablement plus élevée pour xmlwf, mais cela semble être une question de système d'exploitation rapportant la mémoire de manière étrange ; il n'y a pas de fuite dans xmlwf.

-s
Affiche une erreur si le document n'est pas autonome. Un document est autonome s'il n'a pas de sous-ensemble externe et aucune référence à des entités paramétriques.
-t
Active les chronométrages. Ceci indique à Expat d'analyser le fichier entier, mais de ne pas effectuer de traitement. Ceci donne une idée assez précise de la vitesse brute d'Expat lui-même sans surcharge client. -t désactive la plupart des options de sortie (-d, -m, -c, ...).
-v, --version
Affiche la version de la bibliothèque Expat utilisée, y compris des informations sur la configuration au moment de la compilation de la bibliothèque, puis quitte.
-w
Active la prise en charge des pages de codes Windows. Normalement, xmlwf lèvera une erreur s'il rencontre un encodage qu'il n'est pas équipé pour gérer lui-même. Avec -w, xmlwf essaiera d'utiliser une page de codes Windows. Voir aussi -e.
-x
Active l'analyse des entités externes.

Les analyseurs non validants ne sont pas tenus de résoudre les entités externes, ni même d'étendre les entités. Expat étend toujours les entités internes (?), mais l'analyse des entités externes doit être activée explicitement.

xmlwf(1) - Expat XML tools

NOM

xmlwf - Un outil pour vérifier la validité des documents XML

SYNOPSIS

xmlwf [-e|--encoding encoding] [-n|--normalize] [-x|--xml-declaration] [-d|--output-dir directory] [-c|--catalogs catalog] [-m|--dtd dtd] [-s|--no-deprecation-warnings] [-v|--version] [-h|--help] [--] file...

DESCRIPTION

xmlwf est un outil en ligne de commande qui utilise la bibliothèque Expat pour vérifier si des documents XML sont bien formés. Il traite chaque document XML spécifié comme argument de ligne de commande.

Par défaut, xmlwf ne produit aucune sortie pour les documents bien formés. Les erreurs de syntaxe ou les problèmes rencontrés lors du traitement des fichiers sont signalés sur la sortie standard.

DOCUMENTS BIEN FORMÉS

Un document XML est considéré comme bien formé s'il respecte les règles de syntaxe définies par la norme XML. Cela inclut des éléments correctement imbriqués, des attributs correctement cités, et une seule racine principale.

OPTIONS

Les options suivantes sont disponibles :

-e, --encoding encoding
Spécifie le jeu de caractères du document d'entrée. Si cette option n'est pas fournie, xmlwf essaiera de détecter le jeu de caractères à partir de la déclaration XML (si elle existe) ou utilisera par défaut UTF-8.
-n, --normalize
Normalise les fins de ligne dans le document XML. Cela remplace les séquences CRLF (retour chariot + saut de ligne) par un simple saut de ligne LF (saut de ligne).
-x, --xml-declaration
Exige que le document XML commence par une déclaration XML valide (par exemple, `<?xml version="1.0"?>`).
-d, --output-dir directory
Spécifie un répertoire dans lequel les documents externes (entités) référencés par le document XML principal seront enregistrés. Si cette option n'est pas fournie, les entités externes ne seront pas écrites sur le disque.
-c, --catalogs catalog
Spécifie un ou plusieurs fichiers catalogue pour la résolution des entités externes.
-m, --dtd dtd
Charge le DTD spécifié. Cela peut être utile pour la validation des documents par rapport à un schéma DTD.
-s, --no-deprecation-warnings
Désactive les avertissements de dépréciation qui pourraient être émis par la bibliothèque Expat.
-v, --version
Affiche la version de xmlwf et de la bibliothèque Expat utilisée, puis quitte.
-h, --help
Affiche un message d'aide résumant les options disponibles et quitte.
--
(Deux tirets.) Termine la liste des options. Ceci n'est nécessaire que si un nom de fichier commence par un tiret. Par exemple :

xmlwf -- -myfile.xml

exécutera xmlwf sur le fichier -myfile.xml.

Les anciennes versions de xmlwf ne supportent pas la lecture depuis l'entrée standard.

SORTIE

xmlwf ne produit aucune sortie pour les fichiers qui sont sans problème. Si un fichier d'entrée n'est pas bien formé, ou si la sortie pour un fichier d'entrée ne peut pas être ouverte, xmlwf imprime une seule ligne décrivant le problème sur la sortie standard.

Si l'option -k n'est pas fournie, xmlwf s'arrête lors de la rencontre d'une erreur de bien-formation ou de fichier de sortie. Si -k est fournie, xmlwf continue de traiter les fichiers d'entrée restants, décrivant les problèmes rencontrés avec chacun d'eux.

STATUT DE SORTIE

Pour les options -v|--version ou -h|--help, xmlwf se termine toujours avec le code de statut 0. Dans les autres cas, les codes de statut de sortie suivants sont retournés :

0
Les fichiers d'entrée sont bien formés et la sortie (si demandée) a été écrite avec succès.
1
Une erreur interne s'est produite.
2
Un ou plusieurs fichiers d'entrée n'étaient pas bien formés ou n'ont pas pu être analysés.
3
Si vous utilisez l'option -d, une erreur s'est produite lors de l'ouverture d'un fichier de sortie.
4
Il y a eu une erreur d'argument de ligne de commande dans la manière dont xmlwf a été invoqué.

BOGUES

Les erreurs devraient être envoyées sur la sortie d'erreur standard, et non sur la sortie standard.

Il devrait y avoir un moyen de faire en sorte que -d envoie sa sortie sur la sortie standard plutôt que de forcer l'utilisateur à l'envoyer dans un fichier.

Je n'ai aucune idée de pourquoi quelqu'un voudrait utiliser les options -d, -c et -m. Si quelqu'un pouvait me l'expliquer, j'aimerais ajouter cette information à cette page de manuel.
