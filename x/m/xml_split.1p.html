NOM

xml_split - découpe un gros fichier XML en plus petits morceaux

DESCRIPTION

"xml_split" prend un fichier XML (probablement volumineux) et le divise en plusieurs fichiers plus petits. La mémoire utilisée est celle nécessaire pour le plus gros morceau (c'est-à-dire que la mémoire est réutilisée pour chaque nouveau morceau).

Il peut découper à un niveau donné dans l'arbre (par défaut, découpe les enfants de la racine) ou selon une condition (en utilisant le sous-ensemble d'XPath compris par XML::Twig, donc "section" ou "/doc/section").

Chaque fichier généré est remplacé par une instruction de traitement qui permettra à "xml_merge" de reconstruire le document d'origine. Le format de l'instruction de traitement est "<?merge subdocs=[01] :<nom_fichier> ?>"

Les noms de fichiers sont <fichier>-<nb>.xml, avec <fichier>-00.xml contenant le document principal.

OPTIONS

-l <niveau>
niveau de découpe : 1 génère un fichier pour chaque enfant de la racine, 2 pour chaque petit-enfant

par défaut à 1

-c <condition>
génère un fichier pour chaque élément qui satisfait la condition

xml_split -c <section> placera chaque élément "section" dans son propre fichier (les sections imbriquées sont également gérées)

Notez qu'à l'heure actuelle, cette option est beaucoup plus lente que l'utilisation de "-l"

-s <taille>
génère des fichiers d'une taille (approximative) de <taille>. Le contenu de chaque fichier est encapsulé dans un nouvel élément ("xml_split::root"), donc c'est du XML bien formé. La taille peut être donnée en octets, Ko, Mo ou Go.
-g <nb>
regroupe <nb> éléments dans un seul fichier. Le contenu de chaque fichier est encapsulé dans un nouvel élément ("xml_split::root"), donc c'est du XML bien formé.
-b <nom>
nom de base pour la sortie, les fichiers seront nommés <base>-<nb><.ext>

<nb> est un numéro de séquence, voir ci-dessous "--nb_digits" <ext> est une extension, voir ci-dessous "--extension"

par défaut au nom du fichier d'origine (s'il est disponible) ou "out" (si l'entrée provient de l'entrée standard)

-n <nb>
nombre de chiffres dans le numéro de séquence pour chaque fichier

si plus de chiffres que <nb> sont nécessaires, alors ils sont utilisés : si "--nb_digits 2" est utilisé et 112 fichiers sont générés, ils seront nommés "<fichier>-01.xml" à "<fichier>-112.xml"

par défaut à 2

-e <ext>
extension à utiliser pour les fichiers générés

par défaut à l'extension du fichier d'origine ou ".xml"

-i
utilise des éléments XInclude au lieu d'instructions de traitement pour marquer où les sous-fichiers doivent être inclus
-v
sortie verbeuse

notez que cette option peut considérablement ralentir le traitement (d'un ordre de grandeur) lors de la génération de nombreux petits documents

-V
affiche la version et quitte
-h
aide rapide
-m
man (nécessite que pod2text soit dans le chemin)

EXEMPLES

xml_split foo.xml             # découpe au niveau 1
xml_split -l 2 foo.xml        # découpe au niveau 2
xml_split -c section foo.xml  # un fichier est généré pour chaque élément section
                              # les sections imbriquées sont correctement découpées
