NOM

xml_pp - imprimante XML formatée

SYNTAXE

xml_pp [options] [<fichiers>]

DESCRIPTION

Imprimante XML formatée utilisant XML::Twig

OPTIONS

-i[<extension>]
modifie le(s) fichier(s) sur place, si une extension est fournie (pas d'espace entre "-i" et l'extension) alors le fichier d'origine est sauvegardé avec cette extension

Les règles pour l'extension sont les mêmes que celles de Perl (voir perldoc perlrun) : si l'extension ne contient pas de "*", elle est ajoutée au nom du fichier d'origine. Si l'extension contient un ou plusieurs caractères "*", chaque "*" est remplacé par le nom du fichier actuel.

-s <style>
le style à utiliser pour l'impression formatée : none, nsgmls, nice, indented, record, ou record_c (voir la documentation de XML::Twig pour la description exacte de ces styles), 'indented' par défaut
-p <balise(s)>
préserve les espaces blancs dans les balises. Vous pouvez utiliser plusieurs options "-p" ou mettre les balises entre guillemets si vous en avez besoin de plus d'une
-e <encodage>
utilise l'option output_encoding de XML::Twig (basé sur Text::Iconv ou Unicode::Map8 et Unicode::String) pour définir l'encodage de sortie. Par défaut, l'encodage d'origine est préservé.

Si cette option est utilisée, la déclaration XML est mise à jour (et créée s'il n'y en avait pas).

Assurez-vous que l'encodage est supporté par l'analyseur que vous utilisez si vous souhaitez pouvoir traiter le fichier formaté (XML::Parser ne supporte pas 'latin1' par exemple, vous devez utiliser 'iso-8859-1')

-l
charge les documents en mémoire au lieu de les sortir au fur et à mesure de leur analyse.

Cela évite un bug (voir BUGS) mais utilise plus de mémoire

-f <fichier>
lit la liste des fichiers à traiter depuis <fichier>, un par ligne
-v
verbeux (liste le fichier en cours de traitement)
--
arrête le traitement des arguments (pour traiter les fichiers commençant par -)
-h
affiche l'aide

EXEMPLES

xml_pp foo.xml > foo_pp.xml           # formatage de foo.xml 
xml_pp < foo.xml > foo_pp.xml         # formatage depuis l'entrée standard
xml_pp -v -i.bak *.xml                # formatage des fichiers .xml, avec sauvegardes
xml_pp -v -i'orig_*' *.xml            # les sauvegardes sont nommées orig_<nom_fichier>
xml_pp -i -p pre foo.xhtml            # préserve les espaces dans les balises pre

xml_pp -i.bak -p 'pre code' foo.xml   # préserve les espaces dans les balises pre et code
xml_pp -i.bak -p pre -p code foo.xml  # identique
xml_pp -i -s record mydb_export.xml   # formatage utilisant le style record
xml_pp -e utf8 -i foo.xml             # la sortie sera en utf8
xml_pp -e iso-8859-1 -i foo.xml       # la sortie sera en iso-8859-1
xml_pp -v -i.bak -f lof               # formatage sur place des fichiers de lof

xml_pp -- -i.xml                      # formatage du fichier -i.xml
xml_pp -l foo.xml                     # charge le fichier entier en mémoire 
                                      # avant de le formater
xml_pp -h                             # affiche l'aide

BOGUES

Les éléments avec un contenu mixte commençant par un élément imbriqué obtiennent un \n supplémentaire

<elt><b>b</b>toto<b>bold</b></elt>

sera sorti comme

<elt>
  <b>b</b>toto<b>bold</b></elt>

L'utilisation de l'option "-l" résout ce bug (mais utilise plus de mémoire)

À FAIRE

mettre à jour XML::Twig pour utiliser Encode avec perl 5.8.0
