XMLSEC1(1) Commandes utilisateur XMLSEC1(1)

NOM

xmlsec1 - signer, vérifier, chiffrer et déchiffrer des documents XML

SYNTAXE

xmlsec <commande> [<options>] [<fichiers>]

DESCRIPTION

xmlsec est un outil en ligne de commande pour signer, vérifier, chiffrer et déchiffrer des documents XML. Les valeurs autorisées pour <commande> sont :

--help
afficher cette aide et quitter
--help-all
afficher l'aide pour toutes les commandes/options et quitter
--help-<cmd>
afficher l'aide pour la commande <cmd> et quitter
--version
afficher les informations de version et quitter
--keys
manipulation de fichier XML de clés
--sign
signer des données et produire un document XML
--verify
vérifier un document signé
--sign-tmpl
créer et signer un modèle de signature généré dynamiquement
--encrypt
chiffrer des données et produire un document XML
--decrypt
déchiffrer des données à partir d'un document XML

OPTIONS

--ignore-manifests

ne pas traiter les éléments <dsig:Manifest>

--store-references

stocker et afficher le résultat du traitement de l'élément <dsig:Reference/> juste avant de calculer le digest

--store-signatures

stocker et afficher le résultat du traitement de <dsig:Signature> juste avant de calculer la signature

--enabled-reference-uris <liste>

liste séparée par des virgules des valeurs suivantes : "empty", "same-doc", "local", "remote" pour restreindre les valeurs possibles de l'attribut URI pour l'élément <dsig:Reference>

--enable-visa3d-hack

active un hack spécifique au protocole Visa3D pour le traitement des attributs URI lorsque nous essayons de ne pas utiliser le moteur XPath/XPointer ; ceci est un hack et je ne sais pas ce qui d'autre pourrait être cassé dans votre application lorsque vous l'utilisez (vérifiez également l'option "--id-attr" car vous pourriez en avoir besoin)

--hmac-min-out-len <bits>

définit la longueur minimale de sortie HMAC à <bits>

--binary-data <fichier>

fichier binaire <fichier> à chiffrer

--xml-data <fichier>

fichier XML <fichier> à chiffrer

--enabled-cipher-reference-uris <liste>

liste séparée par des virgules des valeurs suivantes : "empty", "same-doc", "local", "remote" pour restreindre les valeurs possibles de l'attribut URI pour l'élément <enc:CipherReference>

--session-key <klassClé>-<tailleClé>

génère une nouvelle clé de session <klassClé> de <tailleClé> bits (par exemple, "--session des-192" génère une nouvelle clé DES de 192 bits pour le chiffrement DES3)

--output <nomFichier>

écrit le document résultant dans le fichier <nomFichier> ; le <nomFichier> peut être un modèle et inclure '{inputfile}' qui sera remplacé par le nom du fichier d'entrée

--print-debug

affiche les informations de débogage sur stdout

--print-xml-debug

affiche les informations de débogage sur stdout au format xml

--dtd-file <fichier>

charge le fichier spécifié comme DTD

--node-id <id>

définit le point de départ de l'opération sur le nœud avec l'identifiant <id> donné

--node-name [<uri-namespace>:]<nom>

définit le point de départ de l'opération sur le premier nœud avec le <nom> et l'URI de <namespace> donnés

--node-xpath <expression>

définit le point de départ de l'opération sur le premier nœud sélectionné par l'expression XPath spécifiée

--id-attr[:<nomAttr>] [<uri-namespace-nœud>:]<nomNœud>

ajoute les attributs <nomAttr> (valeur par défaut "id") de tous les nœuds avec <nomNœud> et l'espace de noms <uri-namespace-nœud> à la liste des attributs ID connus ; ceci est un hack et si vous pouvez utiliser DTD ou schéma pour déclarer les attributs ID à la place (voir l'option "--dtd-file")

--add-id-attr <nomAttrId>

ajoute l'attribut <nomAttrId> à tous les nœuds du document ; ceci est un hack et si vous pouvez utiliser DTD ou schéma pour déclarer les attributs ID à la place (voir l'option "--dtd-file")

--enabled-key-data <liste>

liste séparée par des virgules des types de données de clé à activer. Exemple :
rsa,key-value,x509
-> remplit <RSAKeyValue> et conserve <X509Data>
lorsque les placeholders <KeyValue/> et <X509Data/>
sont présents dans le modèle.
Utilisez "--list-key-data" pour voir la liste complète des classes de données de clé enregistrées. Par défaut, toutes les données de clé enregistrées sont activées.

--enabled-retrieval-method-uris <liste>

liste séparée par des virgules des valeurs suivantes : "empty", "same-doc", "local", "remote" pour restreindre les valeurs possibles de l'attribut URI pour l'élément <dsig:RetrievalMethod>.

--enabled-key-info-reference-uris <liste>

liste séparée par des virgules des valeurs suivantes : "empty", "same-doc", "local", "remote" pour restreindre les valeurs possibles de l'attribut URI pour l'élément <dsig11:KeyInfoReference>.

--gen-key[:<nom>] <klassClé>-<tailleClé>

génère une nouvelle clé <klassClé> de <tailleClé> bits, définit le nom de la clé à <nom> et ajoute le résultat au gestionnaire de clés (par exemple, "--gen:mykey rsa-1024" génère une nouvelle clé RSA de 1024 bits et la nomme "mykey")

--keys-file <fichier>

charge les clés depuis un fichier XML

--privkey-pem[:<nom>] <fichier>[,<fichierCA>[,<fichierCA>[...]]]

charge la clé privée depuis un fichier PEM et les certificats qui vérifient cette clé

--privkey-der[:<nom>] <fichier>[,<fichierCA>[,<fichierCA>[...]]]

charge la clé privée depuis un fichier DER et les certificats qui vérifient cette clé

--pkcs8-pem[:<nom>] <fichier>[,<fichierCA>[,<fichierCA>[...]]]

charge la clé privée depuis un fichier PEM PKCS8 et les certificats PEM qui vérifient cette clé

--pkcs8-der[:<nom>] <fichier>[,<fichierCA>[,<fichierCA>[...]]]

charge la clé privée depuis un fichier DER PKCS8 et les certificats DER qui vérifient cette clé

--privkey-openssl-store[:<nom>] <uri>

charge la clé privée et les certificats via l'interface ossl_store d'OpenSSL (par exemple, depuis un HSM)

--privkey-openssl-engine[:<nom>] <moteur-openssl>;<id-clé-openssl>[,<fichierCert>[,<fichierCert>[...]]]

NAME

xmlsec1

command line utility for XML Security.

SYNOPSIS

xmlsec1 [--transport <transport>] [--input <file>] [--output <file>] [--output-is-file] [--sign] [--verify] [--encrypt] [--decrypt] [--transform <name>] [--key <keyinfo>] [--keys <keyinfo>] [--key-password <password>] [--signature-key <keyinfo>] [--signature-private-key <keyinfo>] [--signature-public-key <keyinfo>] [--signature-cert <keyinfo>] [--signature-trusted-cert <keyinfo>] [--signature-untrusted-cert <keyinfo>] [--signature-crl <keyinfo>] [--crypto-xmlsec-attributes <attrs>] [--app-xmlsec-attributes <attrs>] [--cert-validation-error <error>] [--cert-revocation-error <error>] [--xml-regexp <regexp>] [--xml-regexp-file <file>] [--xml-regexp-ns <nsuri>] [--xml-regexp-ns-file <file>] [--x509-data <data>] [--load-key-from-file] [--load-key-from-file-password <password>] [--load-key-from-file-pkcs12 <pkcs12>] [--load-key-from-file-pkcs12-password <password>] [--load-key-from-file-private-key <private>] [--load-key-from-file-private-key-password <password>] [--load-key-from-file-public-key <public>] [--load-key-from-file-certificate <certificate>] [--load-key-from-file-certificate-password <password>] [--load-key-from-file-trusted-certificate <certificate>] [--load-key-from-file-trusted-certificate-password <password>] [--load-key-from-file-untrusted-certificate <certificate>] [--load-key-from-file-untrusted-certificate-password <password>] [--load-key-from-file-crl <crl>] [--load-key-from-file-crl-password <password>] [--load-key-from-file-verification-time <time>] [--load-key-from-file-verification-gmt-time <time>] [--load-key-from-file-X509-skip-time-checks] [--load-key-from-file-depth <number>] [--load-key-from-file-X509-skip-strict-checks] [--load-key-from-file-insecure] [--load-key-from-file-crypto <name>] [--load-key-from-file-crypto-config <path>] [--load-key-from-file-verbose] [--load-key-from-file-print-crypto-library-errors] [--load-key-from-file-repeat <number>] [--load-key-from-file-base64-line-size <size>] [--load-key-from-file-transform-binary-chunk-size <size>] [--load-key-from-file-xxe] [--load-key-from-file-url-map:<url> <file>] [--load-key-from-file-help] [--help] [-h]

DESCRIPTION

The xmlsec1 utility is a command line tool for applying XML Signature and XML Encryption to XML documents.

OPTIONS

--transport <transport>

the transport type, used for signing and verifying (e.g. "http", "smtp", "file").

--input <file>

the input XML document file

--output <file>

the output XML document file

--output-is-file

output to a file instead of stdout

--sign

sign the XML document

--verify

verify the XML document signature

--encrypt

encrypt the XML document

--decrypt

decrypt the XML document

--transform <name>

the name of the transform to apply (e.g. "base64", "c14n", etc.)

--key <keyinfo>

the key used for signing or encryption. <keyinfo> can be a file name or a string in the format: "name:value"

--keys <keyinfo>

the keys used for signing or verification. <keyinfo> can be a file name or a string in the format: "name:value"

--key-password <password>

the password for private keys

--signature-key <keyinfo>

the key used for signature (e.g. private key for signing, public key for verification)

--signature-private-key <keyinfo>

the private key for signature

--signature-public-key <keyinfo>

the public key for signature

--signature-cert <keyinfo>

the certificate for signature

--signature-trusted-cert <keyinfo>

trusted certificate for signature verification

--signature-untrusted-cert <keyinfo>

untrusted certificate for signature verification

--signature-crl <keyinfo>

certificate revocation list for signature verification

--crypto-xmlsec-attributes <attrs>

attributes for crypto engine (e.g. "id:mykey")

--app-xmlsec-attributes <attrs>

attributes for application (e.g. "id:myapp")

--cert-validation-error <error>

the error to report for invalid certificates

--cert-revocation-error <error>

the error to report for revoked certificates

--xml-regexp <regexp>

the regular expression to match XML elements

--xml-regexp-file <file>

the file containing the regular expression to match XML elements

--xml-regexp-ns <nsuri>

the namespace URI for XML elements

--xml-regexp-ns-file <file>

the file containing the namespace URIs for XML elements

--x509-data <data>

the X.509 data to use

--load-key-from-file

load key from file

--load-key-from-file-password <password>

the password for the key file

--load-key-from-file-pkcs12 <pkcs12>

load key from PKCS#12 file

--load-key-from-file-pkcs12-password <password>

the password for the PKCS#12 file

--load-key-from-file-private-key <private>

load private key from file

--load-key-from-file-private-key-password <password>

the password for the private key file

--load-key-from-file-public-key <public>

load public key from file

--load-key-from-file-certificate <certificate>

load certificate from file

--load-key-from-file-certificate-password <password>

the password for the certificate file

--load-key-from-file-trusted-certificate <certificate>

load trusted certificate from file

--load-key-from-file-trusted-certificate-password <password>

the password for the trusted certificate file

--load-key-from-file-untrusted-certificate <certificate>

load untrusted certificate from file

--load-key-from-file-untrusted-certificate-password <password>

the password for the untrusted certificate file

--load-key-from-file-crl <crl>

load CRL from file

--load-key-from-file-crl-password <password>

the password for the CRL file

--load-key-from-file-verification-time <time>

the local time in "YYYY-MM-DD HH:MM:SS" format used certificates verification

--load-key-from-file-verification-gmt-time <time>

the GMT time in "YYYY-MM-DD HH:MM:SS" format used certificates verification

--load-key-from-file-X509-skip-time-checks

skip time checking of X509 certificates and CLRs

--load-key-from-file-depth <number>

maximum certificates chain depth

--load-key-from-file-X509-skip-strict-checks

skip strict checking of X509 data

--load-key-from-file-insecure

do not verify certificates

--load-key-from-file-crypto <name>

the name of the crypto engine to use from the following list: openssl, mscrypto, nss, gnutls, gcrypt (if no crypto engine is specified then the default one is used)

--load-key-from-file-crypto-config <path>

path to crypto engine configuration

--load-key-from-file-verbose

print detailed error messages

--load-key-from-file-print-crypto-library-errors

print errors from crypto library (OpenSSL only)

--load-key-from-file-repeat <number>

repeat the operation <number> times

--load-key-from-file-base64-line-size <size>

sets the max line size for base64 encodings to <size>

--load-key-from-file-transform-binary-chunk-size <size>

sets the transforms binary processing chunk size to <size>; increasing chunk size might improve performance at the expense of increased memory usage

--load-key-from-file-xxe

enable External Entity resolution. WARNING: this may allow the reading of arbitrary files and URLs, controlled by the input XML document. Use with caution!

--load-key-from-file-url-map:<url> <file>

maps a given <url> to the given <file> for loading external resources

--load-key-from-file-help

print help information about loading keys from file

--private-key <file>

load private key from file

--private-key-password <password>

the password for the private key file

--private-key-openssl-store <uri>

load private key through OpenSSL ossl_store interface (e.g. from HSM)

--private-key-openssl-engine <openssl-engine>;<openssl-key-id>[,<crtfile>[,<crtfile>[...]]]

load private key by OpenSSL ENGINE interface; specify the name of engine (like with -engine params), the key specs (like with -inkey or -key params) and optionally certificates that verify this key

--pubkey-pem:<name> <file>

load public key from PEM file

--pubkey-der:<name> <file>

load public key from DER file

--pubkey-openssl-store:<name> <uri>

load pubkey key and certs through OpenSSL ossl_store interface (e.g. from HSM)

--pubkey-openssl-engine:<name> <openssl-engine>;<openssl-key-id>[,<crtfile>[,<crtfile>[...]]]

load public key by OpenSSL ENGINE interface; specify the name of engine (like with -engine params), the key specs (like with -inkey or -key params) and optionally certificates that verify this key

--pwd <password>

the password to use for reading keys and certs

--lax-key-search

enable lax key search (e.g. by key type like "rsa") vs default strict key search mode using only information from <dsig:KeyInfo/> node (e.g. key name)

--verify-keys

force verification of public/private keys loaded from the command: keys are required to have a key certificate that will be verified against the certificates in the key store

--aes-key:<name> <file>

load AES key from binary file <file>

--concatkdf-key:<name> <file>

load ConcatKDF key from binary file <file>

--des-key:<name> <file>

load DES key from binary file <file>

--hmac-key:<name> <file>

load HMAC key from binary file <file>

--pbkdf2-key:<name> <file>

load Pbkdf2 key from binary file <file>

--pkcs12:<name> <file>

load load private key from pkcs12 file <file>

--pkcs12-persist

persist loaded private key

--pubkey-cert-pem:<name> <file>

load public key from PEM cert file

--pubkey-cert-der:<name> <file>

load public key from DER cert file

--trusted-pem <file>

load trusted (root) certificate from PEM file <file>

--untrusted-pem <file>

load untrusted certificate from PEM file <file>

--trusted-der <file>

load trusted (root) certificate from DER file <file>

--untrusted-der <file>

load untrusted certificate from DER file <file>

--crl-pem <file>

load CRLs from PEM file <file>

--crl-der <file>

load CRLs from DER file <file>

--verification-time <time>

the local time in "YYYY-MM-DD HH:MM:SS" format used certificates verification

--verification-gmt-time <time>

the GMT time in "YYYY-MM-DD HH:MM:SS" format used certificates verification

--X509-skip-time-checks

skip time checking of X509 certificates and CLRs

--depth <number>

maximum certificates chain depth

--X509-skip-strict-checks

skip strict checking of X509 data

--insecure

do not verify certificates

--crypto <name>

the name of the crypto engine to use from the following list: openssl, mscrypto, nss, gnutls, gcrypt (if no crypto engine is specified then the default one is used)

--crypto-config <path>

path to crypto engine configuration

--verbose

print detailed error messages

--print-crypto-library-errors

print errors from crypto library (OpenSSL only)

--repeat <number>

repeat the operation <number> times

--base64-line-size <size>

sets the max line size for base64 encodings to <size>

--transform-binary-chunk-size <size>

sets the transforms binary processing chunk size to <size>; increasing chunk size might improve performance at the expense of increased memory usage

--xxe

enable External Entity resolution. WARNING: this may allow the reading of arbitrary files and URLs, controlled by the input XML document. Use with caution!

--url-map:<url> <file>

maps a given <url> to the given <file> for loading external resources

--help

print help information about the command
