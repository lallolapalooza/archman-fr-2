NOM

xmllint - outil XML en ligne de commande

SYNTAXE

xmllint [--version | --debug | --quiet | --shell | --xpath "expression_XPath" | --copy | --recover | --huge | --nocompact | --nodefdtd | --nodict | --noenc | --noent | --nofixup-base-uris | --noout | --nonet | --path "CHEMIN(S)" | --load-trace | --valid | --postvalid | --dtdvalid URL | --dtdvalidfpi FPI | --timing | --output FICHIER | --repeat | --insert | --strict-namespace | --compress | --html | --xmlout | --push | --memory | --max-ampl ENTIER | --maxmem NB octets | --nowarning | --noblanks | --nocdata | --format | --pretty ENTIER | --encode ENCODAGE | --dropdtd | --nsclean | --catalogs | --nocatalogs | --auto | --xinclude | --noxincludenode | --loaddtd | --dtdattr | --stream | --walker | --pattern VALEUR_MOTIF | --relaxng SCHEMA | --schema SCHEMA | --schematron SCHEMA | --c14n | --c14n11 | --exc-c14n | --pedantic | --sax | --sax1 | --oldxml10] {FICHIER(S)_XML... | -}

DESCRIPTION

Le programme xmllint analyse un ou plusieurs fichiers XML, spécifiés sur la ligne de commande comme FICHIER_XML (ou l'entrée standard si le nom de fichier fourni est - ). Il imprime divers types de sorties, selon les options sélectionnées. Il est utile pour détecter des erreurs à la fois dans le code XML et dans le parseur XML lui-même.

xmllint fait partie de la bibliothèque libxml2.

OPTIONS DE VALIDATION

Options activant la validation.

--dtdvalid URL

Utilise la DTD spécifiée par une URL pour la validation.

--dtdvalidfpi FPI

Utilise la DTD spécifiée par un Identifiant Public Formel FPI pour la validation, notez que cela nécessitera un catalogue exportant cet Identifiant Public Formel pour fonctionner.

--relaxng SCHEMA

Utilise le fichier RelaxNG nommé SCHEMA pour la validation.

--schema SCHEMA

Utilise un fichier de Schéma XML W3C nommé SCHEMA pour la validation.

--schematron SCHEMA

Utilise un fichier Schematron nommé SCHEMA pour la validation.

--valid

Détermine si le document est une instance valide de la Définition de Type de Document (DTD) incluse. Une DTD pour valider contre peut également être spécifiée sur la ligne de commande en utilisant l'option --dtdvalid. Par défaut, xmllint vérifie également si le document est bien formé.

--strict-namespace

Retourne une erreur si le document est bien formé, mais contient des erreurs de namespace. Ceci impose la conformité des namespaces.

OPTIONS DU PARSEUR

Les options suivantes définissent les options du parseur respectives.

--dtdattr

Récupère les DTD externes et peuple l'arbre avec les attributs hérités. Implique --loaddtd.

--huge

Ignore certaines limites prédéfinies du parseur.

--loaddtd

Récupère une DTD externe et les entités de paramètres externes.

--max-ampl ENTIER

Définit le facteur d'amplification maximum qui protège contre l'expansion exponentielle d'entités ("billion laughs"). La valeur par défaut est 5. Les documents utilisant intensivement l'expansion d'entités peuvent nécessiter une valeur plus élevée.

--noblanks

Supprime les espaces blancs "ignorables". Cette option n'est pas fiable et ne devrait pas être utilisée.

--nocatalogs

N'utilise aucun catalogue.

--nocdata

Remplace les sections CDATA par des nœuds de texte équivalents.

--nodefdtd

Ne définit pas le doctype HTML par défaut (option du parseur HTML_PARSE_NODEFDTD).

--noenc

Ignore la déclaration d'encodage (option du parseur XML_PARSE_IGNORE_ENC).

--noent

Remplace les valeurs d'entité par des références d'entité. Par défaut, xmllint laisse les références d'entité en place. Ceci active le chargement des DTD et entités externes.

--nofixup-base-uris

Ne corrige pas les URI xml:base lors du traitement des XInclude (option du parseur XML_PARSE_NOBASEFIX).

--nonet

N'utilise pas Internet pour récupérer les DTD ou les entités. N'a aucun effet avec libxml2 2.15 ou plus récent.

--nowarning

Ne génère pas d'avertissements du parseur et/ou du validateur.

--nsclean

Supprime les déclarations de namespace redondantes.

--oldxml10

Utilise les règles de parsing obsolètes avant XML 1.0, 5ème édition.

--pedantic

Active des avertissements supplémentaires.

--recover

Affiche les portions analysables d'un document invalide. Le comportement exact n'est pas spécifié. L'utilisation de cette option est déconseillée.

--xinclude

Effectue le traitement XInclude.

OPTIONS DIVERSES

Options qui ne rentrent dans aucune autre catégorie.

--catalogs

Utilise le(s) catalogue(s) SGML de SGML_CATALOG_FILES. Les catalogues XML sont chargés par défaut.

--dropdtd

Supprime la DTD après l'analyse.

--html

Utilise le parseur HTML.

--path "CHEMIN(S)"

Utilise la liste de chemins de fichiers (séparés par des espaces ou des deux-points) spécifiée par CHEMINS pour charger les DTD ou les entités. Entourez les listes séparées par des espaces par des guillemets.

--quiet

N'imprime pas les messages d'information sur stderr.

--sax

Imprime les rappels SAX pour le débogage. Peut être utilisé pour le streaming de la validation DTD et Schéma lorsqu'il est utilisé avec --noout.

--shell

Lance un shell de navigation. Détails sur les commandes disponibles en mode shell ci-dessous (voir la section intitulée « COMMANDES DU SHELL »).

--stream

Utilise l'API de streaming - utile lorsqu'il est utilisé en combinaison avec les options --relaxng ou --valid pour la validation de fichiers trop volumineux pour être conservés en mémoire.

--version

Affiche la version de libxml2 utilisée.

OPTIONS DE SORTIE

Options contrôlant la sortie. À l'exception de --noout, elles n'ont aucun effet en mode SAX ou stream.

--compress

Active la compression gzip(1) de la sortie.

--c14n, --c14n11, --exc-c14n

Utilise la Canonicalisation XML W3C (C14N) pour sérialiser le résultat de l'analyse vers la sortie standard. Elle conserve les commentaires dans le résultat.

--encode ENCODAGE

Sortie dans l'encodage donné. Notez que cela fonctionne pour le document complet, pas pour les fragments ou les résultats des requêtes XPath.

--format

Reformate et réindente la sortie. La variable d'environnement XMLLINT_INDENT contrôle l'indentation. La valeur par défaut est deux espaces " ").

En particulier en l'absence d'une DTD, cette fonctionnalité n'a jamais fonctionné de manière fiable et est fondamentalement défectueuse.

--noout

Supprime la sortie. Par défaut, xmllint affiche l'arbre résultat.
/b>FICHIER

Définissez un chemin de fichier où xmllint enregistrera le résultat de l'analyse. Habituellement, les programmes construisent un arbre et l'enregistrent sur la sortie standard, avec cette option, l'instance XML résultante sera enregistrée dans un fichier.

--pretty INTEGER

La valeur 0 signifie aucune mise en forme, 1 signifie XML_SAVE_FORMAT (identique à --format), 2 signifie XML_SAVE_WSNONSIG.

--xmlout

Utilisé en conjonction avec --html. Habituellement, lorsque le HTML est analysé, le document est enregistré avec le sérialiseur HTML. Mais avec cette option, le document résultant est enregistré avec le sérialiseur XML. Ceci est principalement utilisé pour générer du XHTML à partir d'une entrée HTML.

OPTIONS DE DÉBOGAGE

Les options suivantes peuvent être utilisées pour déboguer la bibliothèque libxml2. Le comportement de ces options peut changer sans préavis.

--auto

Génère un petit document à des fins de test.

--copy

Teste l'implémentation interne de copie.

--debug

Analyse un fichier et affiche un arbre annoté de la version en mémoire du document.

--insert

Test pour des insertions valides. OBSOLÈTE : Cette fonctionnalité sera supprimée.

--load-trace

Affiche tous les documents chargés pendant le traitement vers stderr.

--maxmem NNBYTES

Teste le support mémoire de l'analyseur. NNBYTES est le nombre maximum d'octets que la bibliothèque est autorisée à allouer. Ceci peut également être utilisé pour s'assurer que le traitement par lots de fichiers XML n'épuisera pas la mémoire virtuelle du serveur qui les exécute.

--memory

Analyse depuis la mémoire.

--nocompact

Ne génère pas de nœuds de texte compacts (option d'analyse XML_PARSE_COMPACT). Uniquement pour le débogage.

--nodict

N'utilise pas de dictionnaires (option d'analyse XML_PARSE_NODICT). Uniquement pour le débogage.

--noxincludenode

Effectue le traitement XInclude mais ne génère pas de nœuds de début et de fin XInclude.

--pattern PATTERNVALUE

Utilisé pour exercer le moteur de reconnaissance de motifs, qui peut être utilisé avec l'interface du lecteur de l'analyseur. Il permet de sélectionner certains nœuds dans le document en fonction d'une expression XPath (sous-ensemble). Utilisé pour le débogage.

--postvalid

Valide après la fin de l'analyse.

--push

Utilise le mode push de l'analyseur.

--repeat

Répète 100 fois, pour le chronométrage ou le profilage.

--sax1

Utilise l'interface SAX1 obsolète (uniquement pour le débogage).

--timing

Affiche des informations sur le temps nécessaire à xmllint pour effectuer les différentes étapes.

--walker

Teste le module walker, qui est une interface de lecteur mais pour un arbre de document, au lieu d'utiliser l'API du lecteur sur un document non analysé, il fonctionne sur un arbre en mémoire existant. Utilisé pour le débogage.

--xpath "Expression_XPath"

Exécute une expression XPath donnée en argument et affiche le résultat. Dans le cas d'un résultat de nœuds, chaque nœud de l'ensemble de nœuds est sérialisé en entier dans la sortie. Dans le cas d'un ensemble de nœuds vide, le résultat « L'ensemble XPath est vide » sera affiché et le code de sortie 11 sera renvoyé.

COMMANDES SHELL

xmllint offre un mode shell interactif invoqué avec la commande --shell. Les commandes disponibles en mode shell incluent (par ordre alphabétique) :

base

Affiche la base XML du nœud.

bye

Quitte le shell.

cat NODE

Affiche le nœud donné ou le nœud courant.

cd PATH

Change le nœud courant vers le chemin donné (s'il est unique) ou vers la racine si aucun argument n'est donné.

dir PATH

Affiche des informations sur le nœud (espace de noms, attributs, contenu).

du PATH

Montre la structure du sous-arbre sous le chemin donné ou le nœud courant.

exit

Quitte le shell.

help

Affiche cette aide.

load FILENAME

Charge un nouveau document avec le nom de fichier donné.

ls PATH

Liste le contenu du chemin donné ou du répertoire courant.

pwd

Affiche le chemin vers le nœud courant.

quit

Quitte le shell.

save FILENAME

Enregistre le document courant dans le nom de fichier donné ou dans le nom d'origine.

validate

Vérifie le document pour les erreurs.

write FILENAME

Écrit le nœud courant dans le nom de fichier donné.

ENVIRONNEMENT

SGML_CATALOG_FILES

Le comportement du catalogue SGML peut être modifié en redirigeant les requêtes vers les propres catalogues de l'utilisateur. Ceci peut être fait en définissant la variable d'environnement SGML_CATALOG_FILES à une liste de catalogues. Une liste vide devrait désactiver le chargement du catalogue par défaut.

XML_CATALOG_FILES

Le comportement du catalogue XML peut être modifié en redirigeant les requêtes vers les propres catalogues de l'utilisateur. Ceci peut être fait en définissant la variable d'environnement XML_CATALOG_FILES à une liste de catalogues séparée par des espaces. Utilisez l'encodage pourcentage pour échapper les espaces ou autres caractères. Une variable vide devrait désactiver le chargement du catalogue par défaut.

XML_DEBUG_CATALOG

Définir la variable d'environnement XML_DEBUG_CATALOG à une valeur non nulle en utilisant la commande export affiche des informations de débogage relatives aux opérations de catalogue.

XMLLINT_INDENT

Définir la variable d'environnement XMLLINT_INDENT contrôle l'indentation. La valeur par défaut est deux espaces " ".

DIAGNOSTICS

Les codes de retour de xmllint fournissent des informations qui peuvent être utilisées lors de son appel depuis des scripts.

0

Aucune erreur

1

Non classifié

2

Erreur dans la DTD

3

Erreur de validation

4

Le document n'est pas bien formé ou n'a pas pu être lu

5

Erreur dans la compilation du schéma

6

Erreur lors de l'écriture de la sortie

7

Erreur de motif (générée lorsque l'option --pattern est utilisée)

9

Erreur de mémoire insuffisante

10

Erreur d'évaluation XPath

11

Le résultat XPath est vide
