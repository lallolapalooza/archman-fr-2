NOM

xmlto - appliquer une feuille de style XSL à un document XML

SYNTAXE

xmlto [-o répertoire_sortie] [-x xsl_personnalisé] [-m fragment_xsl] [-v] [-p opts_postprocesseur] [--extensions] [--searchpath chemin] [--skip-validation] [--stringparam nomparam=valeurparam] [--noclean] [--noautosize] [--noextensions] [--profile] [--with-fop] [--with-dblatex] {format} {fichier}

xmlto {[--help] | [--version]}

DESCRIPTION

Le but de xmlto est de convertir un fichier XML vers le format désiré en utilisant tous les moyens nécessaires. Cela peut impliquer deux étapes :

1.L'application d'une feuille de style XSL appropriée en utilisant un processeur XSL-T.
2.Un traitement ultérieur avec d'autres outils. Cette étape peut ne pas être nécessaire.

Pour décider quelle feuille de style utiliser et ce qui doit être fait, le cas échéant, pour post-traiter la sortie, xmlto utilise des scripts de format, qui sont de simples scripts shell que xmlto appelle pendant la conversion.

Le script de format approprié est sélectionné en fonction du type de fichier XML et du format de sortie désiré. xmlto est livré avec quelques scripts de format pour convertir des fichiers XML DocBook dans divers formats. Vous pouvez spécifier votre propre script de format en utilisant un nom de fichier absolu pour format sur la ligne de commande.

Premièrement, si xmlto n'a pas été explicitement informé de la feuille de style à utiliser (avec l'option -x), le script de format sera appelé avec $1 défini à stylesheet. La variable d'environnement XSLT_PROCESSOR contient le nom de base de l'exécutable qui sera utilisé pour effectuer la transformation XSL-T (par exemple xsltproc). Le script de format doit écrire le nom de la feuille de style à utiliser en sortie standard et se terminer avec succès, ou se terminer avec un code de retour non nul s'il n'y a pas de feuille de style appropriée à utiliser (par exemple, si la seule feuille de style disponible est connue pour ne pas fonctionner avec le processeur XSL-T qui sera utilisé). Si rien n'est écrit en sortie standard mais que le script se termine avec succès, aucune transformation XSL-T ne sera effectuée.

Deuxièmement, après qu'un processeur XSL-T a été exécuté en utilisant la feuille de style, le script de format sera appelé à nouveau, cette fois avec $1 défini à post-process. Le script de format doit effectuer toutes les étapes nécessaires pour traduire la sortie traitée par XSL-T dans le format de sortie désiré, y compris la copie de la sortie dans le répertoire de sortie désiré. Pour le post-traitement, le script de format est exécuté dans un répertoire temporaire contenant uniquement la sortie traitée (dont le nom est stocké dans XSLT_PROCESSED et dont le nom de base est celui du fichier XML original avec toute extension de nom de fichier remplacée par .proc). INPUT_FILE est défini sur le nom du fichier XML original, OUTPUT_DIR est défini sur le nom du répertoire dans lequel la sortie (et uniquement la sortie) doit se retrouver, et SEARCHPATH est défini sur une liste de répertoires de secours séparés par des deux-points dans lesquels chercher les entrées (pour les images, par exemple). Si cette étape échoue, le script de format doit se terminer avec un code de retour non nul.

OPTIONS

-v

Être verbeux (-vv pour très verbeux).

-x feuille_style

Utiliser feuille_style au lieu de demander au script de format d'en choisir une.

-m fragment

Utiliser le fragment XSL fourni pour modifier la feuille de style.

-o répertoire

Placer la sortie dans le répertoire spécifié au lieu du répertoire de travail courant.

-p opts_postprocesseur

Passer opts_postprocesseur aux étapes de traitement après l'application de la feuille de style (par ex. lynx ou links lors de la conversion de HTML vers texte, ou xmltex lors de la conversion de TeX vers DVI). Si -p est spécifié une deuxième fois, les options spécifiées seront passées au post-traitement de second niveau ; actuellement, cela n'est applicable que lors de la conversion via xmltex et dvips vers PostScript.

--extensions

Activer les extensions de feuille de style pour la chaîne d'outils en cours d'utilisation (use.extensions est activé). Les variables activées sont celles utilisées par les feuilles de style XSL DocBook de Norman Walsh.

--searchpath chemin

Ajouter la liste de répertoires séparés par des deux-points dans chemin comme répertoires de secours pour inclure les entrées.

--skip-validation

Ignorer l'étape de validation normalement effectuée.

--stringparam nomparam=valeurparam

Passer un paramètre nommé nomparam avec la valeur valeurparam à la feuille de style depuis la ligne de commande.

--noclean

Les fichiers temporaires ne sont pas supprimés (leurs noms sont affichés et conservés dans le répertoire tmp). Cela peut aider à analyser les problèmes.

--noautosize

Par défaut, certaines variables XSL sont remplacées par une autodétection (page.width et page.height pour l'utilisation de paperconf (libpaper), paper.type pour la sélection basée sur la locale (LC_PAPER)). Avec cette option, xmlto n'utilise pas cette autodétection et l'utilisateur peut modifier les valeurs par défaut lui-même (soit via une modification de la feuille de style param.xsl par défaut, soit via un fragment XSL défini par l'utilisateur).

--noextensions

Par défaut, xmlto active les paramètres XSL passivetex.extensions pour le backend passivetex et fop.extensions et fop1.extensions pour le backend fop. Cela produit généralement de meilleurs résultats. Si, pour une raison quelconque, vous ne souhaitez pas utiliser ces paramètres, désactivez-les simplement avec cette option.

--profile

Pré-traiter le document XML avec la feuille de style de profilage.

--with-fop

Utiliser fop pour le formatage. C'est une option expérimentale, attend fop à un emplacement spécifique (détecté au moment de la configuration), peut être modifié manuellement dans le script xmlto en modifiant FOP_PATH

--with-dblatex

Utiliser dblatex pour le formatage. C'est une option expérimentale, attend dblatex à un emplacement spécifique (détecté au moment de la configuration), peut être modifié manuellement dans le script xmlto en modifiant DBLATEX_PATH

--help

Afficher un court message d'utilisation. Il décrira les options de xmlto et les formats de sortie disponibles.

--version

Afficher le numéro de version de xmlto.

ENVIRONNEMENT

XSLT_PROCESSOR

Nom de base de l'exécutable qui sera utilisé pour effectuer la transformation XSL-T (par défaut : xsltproc(1)).

TMPDIR

Répertoire où créer les feuilles de style temporaires (par défaut : /tmp).

DIAGNOSTICS

0

Tout s'est bien passé. C'est le code de sortie attendu.

1

xmlto a été appelé avec des arguments insuffisants.

2

mktemp(1) n'a pas réussi à créer un fichier/répertoire. Assurez-vous que /tmp ou TMPDIR est accessible en écriture.

3

xmlto n'a pas réussi à trouver un binaire à l'emplacement configuré. Assurez-vous que tous les paquets requis sont installés et que les chemins dans le script xmlto sont correctement définis.

10+(Code d'erreur de validation non nul)

xmlto a essayé de valider un document xml, mais la validation a échoué. Pour un diagnostic plus précis, la sortie de validation et le code de sortie de xmllint sont fournis. Envisagez soit de corriger votre document, soit d'utiliser --skip-validation.

EXEMPLES

Pour convertir un document DocBook XML en PDF, utilisez :

xmlto pdf mon_doc.xml

Pour convertir un document DocBook XML en HTML et stocker les fichiers HTML résultants dans un répertoire séparé, utilisez :

xmlto -o rep_html html mon_doc.xml

Pour convertir un document DocBook XML en un seul fichier HTML, utilisez :

xmlto html-nochunks mon_doc.xml

"Pp">Pour modifier la sortie à l'aide d'un fragment XSL, utilisez :

xmlto -m ulink.xsl pdf mon_document.xml

Pour spécifier quelle feuille de style utiliser (en remplaçant celle que le script de format choisirait), utilisez :

xmlto -x ma_feuille_de_style.xsl pdf mon_document.xml
