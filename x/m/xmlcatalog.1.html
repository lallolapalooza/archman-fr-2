NOM

xmlcatalog - Outil en ligne de commande pour analyser et manipuler les fichiers de catalogue XML ou SGML.

SYNTAXE

xmlcatalog [--sgml | --shell | --convert | --create | --del VALEUR(S) | [ --add TYPE ORIG REMPLACEMENT  | --add NOMFICHIER] | --noout | --no-super-update | [-v | --verbose]] {FICHIERCATALOGUE} {ENTITES...}

DESCRIPTION

xmlcatalog est une application en ligne de commande permettant aux utilisateurs de surveiller et de manipuler les catalogues XML et SGML. Il est inclus dans libxml(3).

Ses fonctions peuvent être appelées à partir d'une seule commande depuis la ligne de commande, ou il peut effectuer plusieurs fonctions en mode interactif. Il peut fonctionner sur des fichiers XML et SGML.

OPTIONS

xmlcatalog accepte les options suivantes (par ordre alphabétique) :

--add TYPE ORIG REMPLACEMENT

Ajoute une entrée à FICHIERCATALOGUE. TYPE indique le type d'entrée. Les types possibles sont : public, system, uri, rewriteSystem, rewriteURI, delegatePublic, delegateSystem, delegateURI, nextCatalog. ORIG est la référence originale à remplacer, et REMPLACEMENT est l'URI de l'entité de remplacement à utiliser. L'option --add ne remplacera pas FICHIERCATALOGUE, elle sortira vers stdout, sauf si --noout est utilisé. L'option --add prendra toujours trois paramètres même si certaines des constructions de catalogue XML n'ont qu'un seul argument.

--add NOMFICHIER

Si l'option --add est utilisée après l'option --sgml, un seul argument, un NOMFICHIER, est utilisé. Ceci est utilisé pour ajouter le nom d'un fichier de catalogue à un super-catalogue SGML, un fichier qui contient des références à d'autres fichiers de catalogue SGML inclus.

--convert

Convertit un catalogue SGML en XML.

--create

Crée un nouveau catalogue XML. Sortie vers stdout, ignorant nomfichier sauf si --noout est utilisé, auquel cas il crée un nouveau fichier de catalogue nomfichier.

--del VALEUR(S)

Supprime les entrées de FICHIERCATALOGUE correspondant à VALEUR(S). L'option --del ne remplacera pas FICHIERCATALOGUE, elle sortira vers stdout, sauf si --noout est utilisé.

--noout

Sauvegarde la sortie dans le fichier nommé plutôt que de l'afficher sur stdout.

--no-super-update

Ne met pas à jour le super-catalogue SGML.

--shell

Exécute un shell permettant des requêtes interactives sur le fichier de catalogue FICHIERCATALOGUE. Pour l'ensemble des commandes disponibles, voir la section « COMMANDES SHELL ».

--sgml

Utilise les super-catalogues SGML pour les options --add et --del.

-v, --verbose

Affiche des informations de débogage.

L'invocation de xmlcatalog de manière non interactive sans action désignée (imposée par des options telles que --add) entraînera une recherche de l'entrée de catalogue pour ENTITES dans le catalogue désigné par FICHIERCATALOGUE. Les entrées correspondantes seront affichées sur la ligne de commande. Ce mode de fonctionnement, ainsi que le mode --shell et les actions directes non modifiantes (c'est-à-dire sans --noout), permet un raccourci spécial pour la spécification du FICHIERCATALOGUE vide (éventuellement exprimé comme "" dans l'environnement shell) désignant le catalogue système par défaut. Cela simplifie la gestion lorsque son emplacement exact n'est pas pertinent mais que la référence intégrée respective doit toujours être consultée.

COMMANDES SHELL

L'invocation de xmlcatalog avec l'option --shell FICHIERCATALOGUE ouvre un shell de ligne de commande permettant un accès interactif au fichier de catalogue identifié par FICHIERCATALOGUE. L'invocation du shell fournit une invite de commande après laquelle les commandes suivantes (décrites par ordre alphabétique) peuvent être entrées.

add TYPE ORIG REMPLACEMENT

Ajoute une entrée au fichier de catalogue. TYPE indique le type d'entrée. Les types possibles sont : public, system, uri, rewriteSystem, rewriteURI, delegatePublic, delegateSystem, delegateURI, nextCatalog. ORIG est la référence originale à remplacer, et REMPLACEMENT est l'URI de l'entité de remplacement à utiliser. L'option --add ne remplacera pas FICHIERCATALOGUE, elle sortira vers stdout, sauf si --noout est utilisé. L'option --add prendra toujours trois paramètres même si certaines des constructions de catalogue XML n'ont qu'un seul argument.

debug

Affiche des instructions de débogage montrant les étapes exécutées par xmlcatalog.

del VALEUR(S)

Supprime l'entrée de catalogue correspondant à VALEUR(S).

dump

Affiche le catalogue actuel.

exit

Quitte le shell.

public ID-PUBLIC

Exécute une recherche d'identifiant public formel de l'entrée de catalogue pour ID-PUBLIC. L'entrée correspondante sera affichée sur la ligne de commande.

system ID-SYSTEME

Exécute une recherche d'identifiant public formel de l'entrée de catalogue pour ID-SYSTEME. L'entrée correspondante sera affichée sur la ligne de commande.

ENVIRONNEMENT

XML_CATALOG_FILES

Le comportement du catalogue XML peut être modifié en redirectionnant les requêtes vers les propres catalogues de l'utilisateur. Ceci peut être fait en définissant la variable d'environnement XML_CATALOG_FILES à une liste de catalogues séparés par des espaces. Utilisez l'encodage de pourcentage pour échapper les espaces ou autres caractères. Une variable vide devrait désactiver le chargement du catalogue par défaut à partir de /etc/xml/catalog ou, plus spécifiquement, de ${sysconfdir}/xml/catalog.

DIAGNOSTICS

Les codes de retour de xmlcatalog fournissent des informations qui peuvent être utilisées lors de son appel depuis des scripts.

0

Aucune erreur

1

Échec de la suppression d'une entrée du catalogue

2

Échec de la sauvegarde dans le catalogue, vérifier les permissions du fichier

3

Échec de l'ajout d'une entrée au catalogue

4

Échec de la recherche d'une entrée dans le catalogue
