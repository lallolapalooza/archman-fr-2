XML2ODF(1) Commandes utilisateur XML2ODF(1)



NOM
xml2odf - Créer un paquet ODF à partir d'OpenDocument sous forme XML



SYNTAXE

xml2odf [-o fichier_sortie] [-s] [fichier_entree]



DESCRIPTION

OpenDocument peut être un document de bureau complet dans un seul fichier XML. Le script prendra un tel document et créera un paquet. Ceci est principalement utile comme post-traitement d'un programme produisant du XML, tel qu'une feuille de style.

“fichier_entree” est supposé être un fichier OpenDocument sous forme XML. S'il n'y a pas de fichier_entree, le programme lira depuis l'entrée standard. L'option -s ajoute le suffixe correct au nom de fichier selon le type MIME trouvé dans le fichier XML, au cas où vous ne connaîtriez pas déjà le type de document que vous empaquetez.

Si le fichier de sortie n'est pas spécifié, la sortie sera envoyée à la sortie standard.

La section 2.1.1 du format Open Document pour les applications de bureau stipule que le fichier [content.xml] contient le contenu du document, ainsi que les *styles automatiques* nécessaires au contenu du document. Le fichier [styles.xml] contient tous les styles nommés d'un document, ainsi que les *styles automatiques* nécessaires aux styles nommés. L'application ne sait pas quel style automatique est nécessaire pour quoi, elle place donc le même ensemble de styles automatiques dans les deux fichiers.

On pourrait supposer que l'opération inverse serait plus facile, mais OpenOffice.org est tout à fait satisfaite d'utiliser les mêmes noms pour deux styles automatiques différents. Par exemple, un style utilisé à l'intérieur de <style:footer> peut avoir le même nom qu'un style utilisé à l'intérieur de <office:text> mais être un style de paragraphe différent. Ceci est rapporté comme le bug #90494 (http://www.openoffice.org/issues/show_bug.cgi?id=90494)



EXEMPLE

xml2odf -o document_test -s fichier_xml



VOIR AUSSI

odftools(1), odf2xml(1)



BOGUES

Ne gère pas les données externes -- images et autres.

La bibliothèque utilisée pour l'analyse XML développe les éléments vides de <element/> en <element></element>. Cela ne devrait pas avoir d'effet sur l'analyse du document.
