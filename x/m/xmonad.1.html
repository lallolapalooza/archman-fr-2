Nom

xmonad - Gestionnaire de fenêtres en mosaïque

Description

xmonad est un gestionnaire de fenêtres minimaliste en mosaïque pour X, écrit en Haskell. Les fenêtres sont gérées à l'aide d'algorithmes de disposition automatiques, qui peuvent être reconfigurés dynamiquement. À tout moment, les fenêtres sont arrangées de manière à maximiser l'utilisation de l'espace écran. Toutes les fonctionnalités du gestionnaire de fenêtres sont accessibles uniquement au clavier : une souris est entièrement facultative. xmonad est configuré en Haskell, et des algorithmes de disposition personnalisés peuvent être implémentés par l'utilisateur dans les fichiers de configuration. Un principe de xmonad est la prévisibilité : l'utilisateur doit savoir à l'avance précisément quel arrangement de fenêtres résultera de toute action.

Par défaut, xmonad fournit trois algorithmes de disposition : vertical, large et plein écran. En mode vertical ou large, les fenêtres sont disposées en mosaïque et arrangées pour éviter les chevauchements et maximiser l'utilisation de l'écran. Des ensembles de fenêtres sont regroupés sur des écrans virtuels, et chaque écran conserve sa propre disposition, qui peut être reconfigurée dynamiquement. Plusieurs moniteurs physiques sont pris en charge via Xinerama, permettant un affichage simultané d'un certain nombre d'écrans.

En utilisant l'expressivité d'un langage fonctionnel moderne avec un système de types statique riche, xmonad fournit un gestionnaire de fenêtres complet et riche en fonctionnalités en moins de 1200 lignes de code, avec un accent sur l'exactitude et la robustesse. Les propriétés internes du gestionnaire de fenêtres sont vérifiées à l'aide d'une combinaison de garanties statiques fournies par le système de types et de tests automatisés basés sur les types. Un avantage est que le code est simple à comprendre et facile à modifier.

Utilisation

xmonad place chaque fenêtre dans un « espace de travail ». Chaque espace de travail peut contenir un nombre quelconque de fenêtres, que vous pouvez parcourir avec mod-j et mod-k. Les fenêtres sont soit affichées en plein écran, soit disposées horizontalement en mosaïque, soit disposées verticalement en mosaïque. Vous pouvez basculer le mode de disposition avec mod-espace, ce qui parcourra les modes disponibles.

Vous pouvez passer à l'espace de travail N avec mod-N. Par exemple, pour passer à l'espace de travail 5, vous appuierez sur mod-5. De même, vous pouvez déplacer la fenêtre actuelle vers un autre espace de travail avec mod-shift-N.

Lors de l'exécution avec plusieurs moniteurs (Xinerama), chaque écran a exactement 1 espace de travail visible. mod-{w,e,r} bascule le focus entre les écrans, tandis que shift-mod-{w,e,r} déplace la fenêtre actuelle vers cet écran. Lorsque xmonad démarre, l'espace de travail 1 est sur l'écran 1, l'espace de travail 2 sur l'écran 2, etc. Lors du passage à un espace de travail déjà visible, l'espace de travail actuel et l'espace de travail visible sont échangés.

Options

xmonad dispose de plusieurs options que vous pouvez passer à l'exécutable. Ces options sont :

--recompile
Recompile votre configuration xmonad.hs
--restart
Redémarre le processus xmonad actuellement en cours d'exécution
--replace
Remplace le gestionnaire de fenêtres actuel par xmonad
--version
Affiche la version de xmonad
--verbose-version
Affiche la version détaillée de xmonad

Exemples

Pour utiliser xmonad comme gestionnaire de fenêtres, ajoutez à votre fichier ~/.xinitrc :

exec xmonad

Personnalisation

xmonad est personnalisé dans votre fichier xmonad.hs, puis redémarré avec mod-q. Vous pouvez choisir où se trouve votre fichier de configuration en :

1.
Définissant XMONAD_DATA_DIR, XMONAD_CONFIG_DIR et XMONAD_CACHE_DIR ; xmonad.hs est alors attendu dans XMONAD_CONFIG_DIR.
2.
Créant xmonad.hs dans ~/.xmonad.
3.
Créant xmonad.hs dans XDG_CONFIG_HOME. Notez que, dans ce cas, xmonad utilisera XDG_DATA_HOME et XDG_CACHE_HOME pour son répertoire de données et de cache respectivement.

Vous pouvez trouver de nombreuses extensions aux fonctionnalités de base dans le paquet xmonad-contrib, disponible via votre gestionnaire de paquets ou sur xmonad.org.

Configuration modulaire

Depuis xmonad-0.9, tout module Haskell supplémentaire peut être placé dans ~/.xmonad/lib/ et sera disponible dans le chemin de recherche de GHC. Les modules hiérarchiques sont pris en charge : par exemple, le fichier ~/.xmonad/lib/XMonad/Stack/MyAdditions.hs pourrait contenir :

module XMonad.Stack.MyAdditions (function1) where
  function1 = error "function1: Pas encore implémenté !"

Votre xmonad.hs peut alors importer XMonad.Stack.MyAdditions comme si ce module était contenu dans xmonad ou xmonad-contrib.
