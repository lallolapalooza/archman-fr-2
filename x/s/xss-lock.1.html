NOM

xss-lock - utiliser un bloqueur externe comme économiseur d'écran X

SYNTAXE

xss-lock [-n cmd_notifieur] [-s ID_session] [--ignore-sleep] [-l] [-v|-q] [--] bloqueur [arg] ...
xss-lock --help|--version

DESCRIPTION

xss-lock connecte votre bloqueur préféré à l'extension d'économiseur d'écran de X ainsi qu'au gestionnaire de connexion de systemd.

xss-lock doit être exécuté dans votre session X, soit en le démarrant dans votre fichier .xsessionrc, soit par d'autres moyens spécifiques à la session (par exemple, configuration du gestionnaire de fenêtres). Notez que xss-lock s'exécute au premier plan (c'est-à-dire qu'il ne se divise pas) et vous devrez donc peut-être l'exécuter en arrière-plan (par exemple, en utilisant &).

Le bloqueur est exécuté en réponse aux événements provenant de ces deux sources :

  • Les signaux X signalent l'activation forcée de l'économiseur d'écran ou après une période d'inactivité de l'utilisateur (définie avec xset s TIMEOUT). Dans ce dernier cas, la commande de notifieur, si elle est spécifiée, est exécutée en premier.
  • Le gestionnaire de connexion peut également demander le verrouillage de la session ; par exemple, suite à l'exécution de loginctl lock-sessions. De plus, xss-lock utilise la logique d'inhibition pour verrouiller l'écran avant que le système ne passe en veille.

xss-lock attend que le bloqueur se termine – ou le tue lorsque la désactivation de l'économiseur d'écran ou le déverrouillage de la session sont forcés – la commande ne doit donc pas se diviser.

En outre, xss-lock gère l'indice d'inactivité de la session de connexion. L'état d'inactivité de la session est directement lié à l'activité de l'utilisateur telle que rapportée par X (sauf lorsque le notifieur s'exécute avant de verrouiller l'écran). Lorsque toutes les sessions sont inactives, le gestionnaire de connexion peut prendre des mesures (telles que la suspension du système) après un délai préconfiguré.

OPTIONS

-n cmd, --notifier=cmd
Exécute cmd lorsque l'économiseur d'écran s'active en raison de l'inactivité de l'utilisateur. Les guillemets de style shell sont pris en charge. Le notifieur est tué avec le signal SIGHUP lorsque X signale une activité utilisateur ou avec le signal SIGTERM lorsque le bloqueur est lancé. Le bloqueur est lancé après le premier cycle de l'économiseur d'écran, tel que défini avec xset s TIMEOUT CYCLE. Si le temps de cycle de l'économiseur d'écran est 0, le notifieur n'est pas exécuté et le bloqueur est lancé immédiatement après le délai.

Ceci peut être utilisé pour exécuter un compte à rebours ou (sur les ordinateurs portables) atténuer l'écran avant de verrouiller. Pour un exemple, voir le script /usr/share/doc/xss-lock/dim-screen.sh.

Pour un exemple sur la façon d'utiliser les deux signaux différents reçus par la commande de notifieur, voir le script /usr/share/doc/xss-lock/dim-screen2.sh.

-l, --transfer-sleep-lock
Permet au processus bloqueur d'hériter du descripteur de fichier qui représente le verrouillage du délai obtenu à partir du gestionnaire de connexion. L'index correspondant sera disponible dans la variable d'environnement $XSS_SLEEP_LOCK_FD ; cela ne sera défini que si la raison du verrouillage est que le système se prépare à se mettre en veille. Le bloqueur doit fermer ce descripteur de fichier pour indiquer qu'il est prêt.

Des scripts d'exemple qui encapsulent des bloqueurs existants sont disponibles sous /usr/share/doc/xss-lock/transfer-sleep-lock-*.sh.

-s ID, --session=ID
Utilise la session ID au lieu de la session actuelle.

Exemple : /usr/share/doc/xss-lock/xss-lock.service.

--ignore-sleep
Ne pas verrouiller lors de la mise en veille/hibernation.
-q, --quiet
N'afficher que les erreurs fatales.
-v, --verbose
Afficher plus de messages.
-h, --help
Afficher le message d'aide et quitter.
--version
Afficher le numéro de version et quitter.

SIGNALS

SIGHUP
À la réception de ce signal, xss-lock réinitialise l'économiseur d'écran, mais seulement si l'écran n'est pas actuellement verrouillé (contrairement à xset s reset).

Cela peut être utilisé dans la configuration de MPlayer comme solution de contournement à l'échec de MPlayer de redémarrer le minuteur de l'économiseur d'écran lorsque la lecture est en pause :

heartbeat-cmd="killall -HUP xss-lock"
stop-xscreensaver=false

NOTE :

Ceci est inefficace avec mplayer2 (et mpv), car son cœur continue de battre pendant que la lecture est en pause.
SIGINT/SIGTERM
À la réception de ce signal, xss-lock se termine après avoir tué tout notifieur ou bloqueur en cours d'exécution.

NOTES

•
Certaines applications dépendent du script xdg-screensaver d'xdg-utils, qui utilise xset s off et xset s default pour suspendre et reprendre respectivement l'économiseur d'écran. Ce dernier réinitialise le délai et le cycle aux valeurs par défaut du serveur (xset s on utilise un remplacement codé en dur à la place), donc cela ne fonctionne que si vous êtes satisfait (ou pouvez contrôler) les paramètres du serveur.

Pour corriger l'action de reprise dans ce script (ou une copie dans ~/bin précédant l'original dans $PATH), remplacez on par votre délai et cycle préférés, ou évitez les valeurs de temps codées en dur en patchant le script pour exécuter une boucle de suspension comme il le fait pour les autres économiseurs d'écran, en utilisant /usr/share/doc/xss-lock/xdg-screensaver.patch.

EXEMPLES

•
Utilisation avec xscreensaver via .xsessionrc (donc en arrière-plan) :
xscreensaver &
xss-lock -- xscreensaver-command --lock &
•
Exécuter xlock après dix minutes d'inactivité :
xset s 600
xss-lock xlock +resetsaver

Sans +resetsaver, xlock force une réinitialisation de l'économiseur d'écran au démarrage, disant ainsi à xss-lock de tuer immédiatement xlock.

•
Atténuer l'écran après trois minutes d'inactivité, verrouiller l'écran deux minutes plus tard en utilisant i3lock :
xset s 180 120
xss-lock -n dim-screen.sh -- i3lock -n

NOTE :

Un script est fourni pour utiliser le mode de division de i3lock avec l'option --transfer-sleep-lock (voir ci-dessus).
