XScreenSaver(1) Manuel des commandes générales XScreenSaver(1)

NOM

xscreensaver - framework extensible de sauvegarde d'écran et de verrouillage d'écran

SYNOPIS

xscreensaver [--display hôte:écran.moniteur] [--verbose] [--version] [--no-splash] [--log nom_fichier]

DESCRIPTION

XScreenSaver attend que l'utilisateur soit inactif, puis lance des démos graphiques choisies au hasard. Il peut également verrouiller votre écran et permet la configuration et le contrôle de la gestion de l'alimentation de l'affichage.

XScreenSaver est également disponible sur macOS, iOS et Android.

PREMIERS PAS

XScreenSaver est un démon qui s'exécute en arrière-plan. Vous le configurez avec le programme xscreensaver-settings(1).

xscreensaver &
xscreensaver-settings

COMMENT CA MARCHE

Lorsqu'il est temps d'activer l'économiseur d'écran, une fenêtre noire plein écran est créée pour couvrir chaque moniteur. Un sous-processus est lancé pour chacun, exécutant une démo graphique, pointant vers la fenêtre appropriée. De ce fait, tout programme capable de dessiner dans une fenêtre fournie peut être utilisé comme économiseur d'écran. Les diverses démos graphiques sont, en fait, de simples programmes autonomes qui font cela.

Lorsque l'utilisateur redevient actif, les fenêtres de l'économiseur d'écran sont démappées et les sous-processus en cours sont tués.

Les modes d'affichage sont exécutés avec une faible priorité de processus et passent la plupart de leur temps à dormir/inactifs par défaut, ils ne devraient donc pas consommer de ressources système importantes.

OPTIONS EN LIGNE DE COMMANDE

--display hôte:écran.moniteur
L'affichage X à utiliser. Pour les écrans multiples, XScreenSaver gérera tous les écrans simultanément.
--verbose
Affiche des diagnostics sur stderr.
--version
Affiche le numéro de version et quitte.
--log nom_fichier
Ajoute toute sortie de diagnostic au fichier donné. Cela implique également --verbose. Utilisez ceci lors du signalement de bugs.
--no-splash
N'affiche pas l'écran de démarrage lors du lancement.

GESTION DE L'ALIMENTATION

Le programme xscreensaver-settings(1) est là où vous configurez si et quand votre moniteur doit s'éteindre. Il enregistre les paramètres dans votre fichier ~/.xscreensaver. N'utilisez pas xset(1) pour modifier manuellement les paramètres de gestion de l'alimentation, cela ne fonctionnera pas.

Lorsque le moniteur est éteint, les démos d'écran cessent de s'exécuter (bien qu'il puisse s'écouler une minute ou deux avant que XScreenSaver ne s'en aperçoive).

COUVERCLES D'ORDINATEUR PORTABLE

Si votre système utilise systemd(1) ou elogind(8), alors fermer le couvercle de votre ordinateur portable verrouillera l'écran immédiatement.

Sinon, l'écran pourrait ne pas se verrouiller avant quelques secondes *après* que vous ayez rouvert le couvercle. Ce qui est loin d'être idéal. Donc, si vous n'avez pas systemd(1), vous pourriez prendre l'habitude de verrouiller manuellement votre écran *avant* de fermer le couvercle (xscreensaver-command --lock).

LECTURE DE VIDEOS

De même, si vous avez systemd(1) ou elogind(8), alors tous les lecteurs vidéo populaires et navigateurs web empêcheront XScreenSaver de rendre l'écran vide pendant la lecture vidéo.

Ces deux fonctionnalités nécessitent que xscreensaver-systemd(6) puisse se connecter à D-Bus.

INSTALLATION

Chaque environnement de bureau a son propre système pour lancer des démons de longue durée comme XScreenSaver, et comme beaucoup d'entre eux sont livrés avec leurs propres frameworks de verrouillage d'écran (bogues, non sécurisés, inférieurs), il est également nécessaire de désactiver ces autres frameworks avant que XScreenSaver ne puisse fonctionner.

INSTALLATION DE XSCREENSAVER SUR GNOME OU UNITY

Pendant de nombreuses années, GNOME incluait XScreenSaver tel quel, et tout fonctionnait. Plus maintenant !

1: Désinstallez complètement les autres paquets d'économiseur d'écran :
	sudo apt remove gnome-screensaver
	sudo apt remove mate-screensaver
	sudo apt remove cinnamon-screensaver
	sudo apt remove light-locker
ou
	sudo rpm -e gnome-screensaver
	sudo rpm -e mate-screensaver
	sudo rpm -e cinnamon-screensaver
	sudo rpm -e light-locker
Faites attention à ce qu'il ne tente pas de désinstaller tout GNOME.
2: Désactivez la mise en veille de l'écran intégrée de GNOME.
Réglez tous les paramètres suivants sur « Jamais » ou « Désactivé », car ceux-ci sont maintenant contrôlés par xscreensaver-settings(1) :

"Paramètres / Confidentialité / Verrouillage de l'écran / Délai de mise en veille de l'écran"
"Paramètres / Confidentialité / Verrouillage de l'écran / Verrouillage automatique de l'écran"
"Paramètres / Alimentation / Écran noir"
"Paramètres / Alimentation / Suspension automatique"

3: Lancez XScreenSaver à la connexion.
Lancez « Outils de personnalisation », sélectionnez « Applications au démarrage », cliquez sur le signe plus et sélectionnez « XScreenSaver » (pas « Paramètres XScreenSaver ») dans le menu (très long).

Ou, voir la section « LANCEMENT DE XSCREENSAVER DEPUIS SYSTEMD » ci-dessous. Cela fonctionne aussi.

4: Faites en sorte que l'icône « Verrouiller » de GNOME utilise XScreenSaver.
Cela fonctionnait auparavant, mais ce n'est plus le cas avec GNOME 3.38. Si vous trouvez une solution, faites-le moi savoir ! Cela fonctionne toujours pour Cinnamon 4.8 et MATE 1.24 : 
sudo ln -sf /usr/bin/xscreensaver-command \
       /usr/bin/gnome-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
    /usr/bin/cinnamon-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
        /usr/bin/mate-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
       /usr/bin/xfce4-screensaver-command
sudo ln -sf /usr/bin/xscreensaver-command \
            /usr/bin/light-locker-command
Cette modification sera écrasée lors de votre mise à niveau.

INSTALLATION DE XSCREENSAVER SUR KDE

Comme GNOME, KDE a également décidé de réinventer la roue. Pour remplacer l'économiseur d'écran KDE par XScreenSaver, procédez comme suit :

1: Désactivez la mise en veille de l'écran intégrée de KDE.
Dans Paramètres système, décochez les éléments suivants, car ils sont maintenant contrôlés par xscreensaver-settings(1) :

"Comportement de l'espace de travail / Verrouillage de l'écran / Verrouiller automatiquement"
"Comportement de l'espace de travail / Verrouillage de l'écran / Après le retour de veille"
"Comportement de l'espace de travail / Verrouillage de l'écran / Raccourci clavier"
"Matériel / Gestion de l'alimentation / Économie d'énergie de l'écran"
"Matériel / Gestion de l'alimentation / Session de mise en veille prolongée"
"Matériel / Gestion de l'alimentation / Couvercle d'ordinateur portable fermé" = Ne rien faire

S'il y a plusieurs onglets, vous devrez peut-être modifier ces paramètres dans les trois : « Sur secteur », « Batterie » et « Batterie faible ».

2: Lancez XScreenSaver à la connexion.
Copiez le fichier /usr/share/applications/xscreensaver.desktop dans le répertoire ~/.config/autostart/
3: Faites en sorte que l'icône « Verrouiller » de KDE utilise XScreenSaver.
Trouvez le programme « kscreenlocker_greet ». Il pourrait se trouver dans

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

« /usr/lib/*/libexec/ », ou il peut se trouver ailleurs. Supprimez ce fichier et remplacez-le par un fichier contenant ces deux lignes. Rendez-le exécutable (chmod a+x). 
#!/bin/sh
xscreensaver-command --lock &
Cette modification sera perdue lors de la mise à niveau.
4 : Désactiver le verrouillage intégré de KDE lors de la mise en veille prolongée, encore plus fort.
Même après avoir désactivé le verrouillage de l'écran de KDE, ci-dessus, il est possible que KDE utilise toujours son propre verrouillage lorsqu'il ferme le capot de votre ordinateur portable. Si cela se produit, vérifiez à nouveau les paramètres ci-dessus, mais s'ils sont corrects, essayez ce qui suit. Tout d'abord, assurez-vous d'exécuter KDE 5.21 ou plus récent. Ensuite, activez les "sessions utilisateur systemd" pour KDE afin de pouvoir modifier les paramètres de ksmserver : 
kwriteconfig5 --file startkderc --group General \
  --key systemdBoot true
Déconnectez-vous et reconnectez-vous.

Ensuite, modifiez le service plasma-ksmserver pour changer la manière dont ksmserver est lancé :

ExecStart=
ExecStart=/usr/bin/ksmserver --no-lockscreen
Ensuite, déconnectez-vous et reconnectez-vous encore.

LANCEMENT DE XSCREENSAVER DEPUIS LXDE

Ajoutez la ligne @xscreensaver à /etc/xdg/lxsession/LXDE/autostart ou /etc/xdg/lxsession/LXDE-pi/autostart.

LANCEMENT DE XSCREENSAVER DEPUIS SYSTEMD

Si vous n'utilisez ni GNOME, ni KDE, ni LXDE, la manière de lancer XScreenSaver à la connexion est probablement systemd(1).

Copiez le fichier /usr/share/xscreensaver/xscreensaver.service dans le répertoire ~/.config/systemd/user/. Créez ce répertoire d'abord s'il n'existe pas. Ensuite, activez-le avec :

systemctl --user enable xscreensaver

LANCEMENT DE XSCREENAVER DEPUIS UPSTART

Si vous n'utilisez ni GNOME, ni KDE, ni LXDE, et que votre système utilise upstart(7) au lieu de systemd(1), lancez l'applet "Applications au démarrage", cliquez sur "Ajouter", et entrez ces lignes :

Name: XScreenSaver
Command: xscreensaver
Comment: XScreenSaver

COUVERCLES D'ORDINATEUR PORTABLE SANS SYSTEMD

Les systèmes BSD ou d'autres systèmes sans systemd(1) ou elogind(8) pourraient avoir de la chance en ajoutant "xscreensaver-command --suspend" à un endroit approprié dans /etc/acpi/events/anything ou dans /etc/acpi/handler.sh, si ces fichiers existent.

LANCEMENT DE XSCREENSAVER DEPUIS GDM

Vous pouvez exécuter xscreensaver depuis votre session gdm(1), afin que l'économiseur d'écran s'exécute même lorsque personne n'est connecté sur la console. Pour ce faire, exécutez gdmconfig(1).

Dans la page Général, réglez le Greeter Local sur Greeter Standard.

Dans la page Arrière-plan, tapez la commande "xscreensaver --no-splash" dans le champ Programme d'arrière-plan. Cela fera exécuter gdm XScreenSaver pendant que personne n'est connecté, et le tuera dès que quelqu'un se connectera. (L'utilisateur sera alors responsable de lancer XScreenSaver lui-même, s'il le souhaite.)

Si cela ne fonctionne pas, vous pouvez éditer le fichier de configuration directement. Éditez /etc/X11/gdm/gdm.conf pour inclure :

Greeter=/usr/bin/gdmlogin
BackgroundProgram=xscreensaver --no-splash
RunBackgroundProgramAlways=true
Dans cette situation, le processus xscreensaver s'exécutera sous l'utilisateur gdm. Vous pouvez configurer les paramètres de cet état de non-connexion (délais, DPMS, etc.) en modifiant le fichier ~gdm/.xscreensaver.

Si vous obtenez des erreurs "connexion refusée" lors de l'exécution de xscreensaver depuis gdm, cela signifie probablement que vous avez des problèmes de xauth(1). Pour plus d'informations sur les mécanismes de contrôle d'accès du serveur X, consultez les pages de manuel de X(1), Xsecurity(1), xauth(1), et xhost(1).

Il existe peut-être un moyen d'y parvenir avec d'autres gestionnaires d'affichage. C'est un mystère !

LE PROBLÈME WAYLAND

Wayland est un système de fenêtrage complètement différent destiné à remplacer X11. Après 14 ans d'essais, certaines distributions Linux ont finalement commencé à l'activer par défaut. La plupart des déploiements incluent également XWayland, qui est une couche de compatibilité permettant à certains programmes X11 de continuer à fonctionner dans un environnement Wayland.

Malheureusement, XScreenSaver ne fait pas partie de ces programmes.

Si votre système exécute XWayland, XScreenSaver fonctionnera mal de deux manières :

1 : Il sera incapable de détecter l'activité utilisateur dans les programmes non-X11.

Cela signifie que lorsqu'un programme natif Wayland est sélectionné, XScreenSaver pensera que vous êtes inactif et pourrait éteindre l'écran prématurément.

2 : Il sera incapable de verrouiller l'écran.

C'est parce que les captures X11 ne fonctionnent pas correctement sous XWayland, il n'y a donc aucun moyen pour XScreenSaver d'empêcher l'utilisateur de passer du verrouillage d'écran à une autre application.

En bref, pour que XScreenSaver fonctionne correctement, vous devrez désactiver Wayland et utiliser le système X Window comme au "bon vieux temps".

POUR DÉSACTIVER WAYLAND SOUS GNOME

L'écran de connexion devrait avoir un menu avec une icône d'engrenage qui vous permet de changer le type de session de "GNOME" (la session Wayland) à "GNOME sur Xorg" (la session X11).

Alternativement, éditez /etc/gdm/custom.conf et assurez-vous qu'il inclut cette ligne :

WaylandEnable=false

POUR DÉSACTIVER WAYLAND SOUS KDE

L'écran de connexion devrait avoir un menu qui vous permet de changer le type de session en "Plasma (X11)".

Alternativement, éditez /etc/sddm.conf et changez la ligne SessionDir sous la section [Wayland] pour dire :

SessionDir=/dev/null

PRÉOCCUPATIONS DE SÉCURITÉ

XScreenSaver a une longue expérience de plus de dix ans en matière de verrouillage sécurisé de votre écran. Cependant, de nombreuses choses peuvent mal tourner. X11 est un système très ancien et présente un certain nombre de défauts de conception qui le rendent susceptible de se tirer une balle dans le pied.

RACCOURCIS CLAVIATURAUX MAGIQUES DE PORTE D'ARRIÈRE

Les serveurs Xorg et XFree86, ainsi que le noyau Linux, interceptent certains raccourcis clavier magiques avant même que les programmes clients X11 ne les voient. Si vous tenez à maintenir votre écran verrouillé, c'est un problème majeur.

Ctrl+Alt+Backspace
Ce raccourci clavier tue le serveur X et, sur certains systèmes, vous ramène à une console texte. Si l'utilisateur a lancé X11 manuellement, cette console texte sera toujours connectée. Pour désactiver ce raccourci clavier globalement et de manière permanente, vous devez définir le drapeau DontZap dans votre fichier xorg.conf(5) ou XF86Config(5).
Ctrl-Alt-F1, Ctrl-Alt-F2, etc.
Ces raccourcis clavier basculent vers une console virtuelle différente, tout en laissant la console sur laquelle X11 s'exécute verrouillée. Si vous avez laissé un shell connecté sur une autre console virtuelle, il est sans protection. Ne vous laissez donc pas connecté sur d'autres consoles. Vous pouvez désactiver le changement de VT globalement et de manière permanente en définissant DontVTSwitch dans votre xorg.conf(5), mais cela pourrait rendre votre système plus difficile à utiliser, car le changement de VT est une fonctionnalité réellement utile.

Il n'y a aucun moyen de désactiver le changement de VT uniquement lorsque l'écran est verrouillé. C'est tout ou rien.

Ctrl-Alt-KP_Multiply
Ce raccourci clavier tue toute application X11 qui détient un verrou, donc taper ceci tuera XScreenSaver et déverrouillera l'écran. Vous pouvez le désactiver en désactivant AllowClosedownGrabs dans xorg.conf(5).
Alt-SysRq-F
C'est le raccourci clavier du "tueur OOM" (Out-Of-Memory killer) du noyau Linux. Il supprime des programmes de longue durée aléatoires de son choix, et pourrait donc cibler et tuer XScreenSaver. Vous pouvez désactiver ce raccourci clavier globalement avec : 
echo 176 > /proc/sys/kernel/sysrq
Il y a peu de choses que je puisse faire pour rendre le verrou d'écran sécurisé tant que les développeurs du noyau et de X11 travaillent activement contre la sécurité de cette manière. La solidité du verrou de votre porte d'entrée n'a pas beaucoup d'importance tant que quelqu'un d'autre dans la maison insiste pour laisser une clé sous le paillasson.

LE TUEUR OOM

Même si vous avez désactivé le raccourci clavier du tueur OOM Alt-SysRq-F, le tueur OOM pourrait toujours décider d'assassiner XScreenSaver de manière aléatoire, ce qui déverrouillerait votre écran. Si le programme xscreensaver-auth(6) est installé setuid, il tente de dire au tueur OOM de laisser tranquille le démon XScreenSaver, mais cela peut fonctionner ou non.

On pourrait penser que le tueur OOM choisirait le processus utilisant le plus de mémoire, mais la plupart du temps, il semble choisir le processus qui serait le plus comiquement gênant, comme votre verrou d'écran, ou crond(8). Vous pouvez désactiver le tueur OOM entièrement avec :

echo 2 > /proc/sys/vm/overcommit_memory
echo vm.overcommit_memory = 2 >> /etc/sysctl.conf
> En plus du tueur OOM du noyau, systemd(1) a le sien. Le fichier xscreensaver.service inclus tente de l'éviter, mais vous pourriez vouloir le désactiver de toute façon : 
sudo systemctl disable --now systemd-oomd
sudo systemctl mask systemd-oomd

ACCÈS AU SERVEUR X EST FIN DE PARTIE

Le modèle de sécurité de X11 est tout ou rien. Si un programme peut se connecter à votre serveur X, que ce soit localement ou sur le réseau, il peut enregistrer toutes vos frappes, simuler des frappes, lancer des programmes arbitraires et modifier les paramètres d'autres programmes. Supposez que tout ce qui peut se connecter à votre serveur X peut exécuter du code arbitraire en tant qu'utilisateur connecté. Voir Xsecurity(1) et xauth(1).

MOTS DE PASSE PAM

Si votre système utilise PAM (Pluggable Authentication Modules), alors PAM doit être configuré pour XScreenSaver. Si ce n'est pas le cas, vous pourriez vous retrouver dans une situation où vous ne pouvez pas déverrouiller. Le fichier dont vous avez probablement besoin est /etc/pam.d/xscreensaver.

NE VOUS CONNECTEZ PAS EN ROOT

Ne vous connectez jamais en tant que root. Connectez-vous en tant qu'utilisateur normal et utilisez sudo(1) si nécessaire. Si vous êtes connecté en tant que root, XScreenSaver ne verrouillera pas votre écran et n'exécutera pas les modes d'affichage, pour de nombreuses raisons bonnes et légitimes.

CONFIGURATION MULTI-UTILISATEUR OU SITE

Pour un utilisateur unique, la manière appropriée de configurer XScreenSaver est de simplement lancer le programme xscreensaver-settings(1) et de modifier les paramètres via l'interface graphique. Les modifications sont écrites dans le fichier ~/.xscreensaver.

Si vous souhaitez définir les valeurs par défaut pour tout le système, modifiez plutôt /etc/X11/app-defaults/XScreenSaver. Les deux fichiers ont une syntaxe similaire (mais pas identique).

Vous pouvez également apporter des modifications via la base de données de ressources X et xrdb(1), mais cela peut être très déroutant et n'est pas vraiment recommandé.

Les options dans ~/.xscreensaver remplacent tous les paramètres de la base de données de ressources ou du fichier app-defaults.

Si vous modifiez un paramètre dans le fichier .xscreensaver alors que XScreenSaver est déjà en cours d'exécution, il le remarquera et rechargera le fichier si nécessaire. Mais si vous modifiez un paramètre dans la base de données de ressources X, vous devrez redémarrer XScreenSaver pour que ces modifications prennent effet :

xrdb < ~/.Xdefaults
xscreensaver-command --restart

RESSOURCES X

Ce sont les ressources X utilisées par le programme XScreenSaver. Vous n'aurez probablement pas besoin de les modifier manuellement : c'est pour cela que le programme xscreensaver-settings(1) existe.

timeout (classe Time)
Le économiseur d'écran s'activera (l'écran sera noir) après que le clavier et la souris soient restés inactifs pendant ce nombre de minutes. Par défaut 10 minutes.
cycle (classe Time)
Après que l'économiseur d'écran ait fonctionné pendant ce nombre de minutes, le sous-processus graphique en cours sera tué (avec SIGTERM) et un nouveau sera lancé. Si c'est 0, le graphique ne changera jamais : un seul démo s'exécutera jusqu'à ce que l'économiseur d'écran soit désactivé par l'activité de l'utilisateur. Par défaut 10 minutes.

S'il y a plusieurs écrans, les économiseurs sont légèrement décalés afin que, bien qu'ils changent tous toutes les cycles minutes, ils ne changent pas tous en même temps.

lock (classe Boolean)
Active le verrouillage : avant que l'économiseur d'écran ne s'éteigne, il vous demandera le mot de passe de l'utilisateur connecté.
lockTimeout (classe Time)
Si le verrouillage est activé, cela contrôle la durée de la "période de grâce" entre l'activation de l'économiseur d'écran et le verrouillage de l'écran. Par exemple, si c'est 5, et que timeout est 10, alors après 10 minutes, l'écran deviendra noir. S'il y avait une activité de l'utilisateur à 12 minutes, aucun mot de passe ne serait requis pour réactiver l'écran. Mais, s'il y avait une activité de l'utilisateur à 15 minutes ou plus tard (c'est-à-dire, lockTimeout minutes après l'activation) alors un mot de passe serait requis. La valeur par défaut est 0, ce qui signifie que si le verrouillage est activé, un mot de passe sera requis dès que l'écran sera noir.
passwdTimeout (classe Time)
Si l'écran est verrouillé, c'est le nombre de secondes pendant lesquelles la boîte de dialogue du mot de passe reste affichée avant d'abandonner (par défaut 30 secondes). Quelques secondes sont ajoutées chaque fois que vous tapez un caractère.
dpmsEnabled (classe Boolean)
Si la gestion de l'alimentation est activée.
dpmsStandby (classe Time)
Si la gestion de l'alimentation est activée, combien de temps avant que le moniteur ne devienne complètement noir.
dpmsSuspend (classe Time)
Si la gestion de l'alimentation est activée, combien de temps avant que le moniteur n'entre en mode d'économie d'énergie.
dpmsOff (classe Time)
Si la gestion de l'alimentation est activée, combien de temps avant que le moniteur ne s'éteigne complètement. Notez que ces paramètres n'auront aucun effet à moins que le serveur X et le matériel d'affichage ne prennent en charge la gestion de l'alimentation ; ce n'est pas toujours le cas. Voir la section Gestion de l'alimentation, ci-dessous, pour plus d'informations.
dpmsQuickOff (classe Boolean)
Si mode est blank et que ceci est vrai, alors l'écran sera éteint immédiatement après avoir été mis en veille, indépendamment des autres paramètres de gestion de l'alimentation.
verbose (classe Boolean)
S'il faut afficher des diagnostics. Par défaut false.
splash (classe Boolean)
S'il faut afficher un écran de démarrage au lancement. Par défaut true.
splashDuration (classe Time)
Combien de temps l'écran de démarrage doit rester visible ; par défaut 5 secondes.
helpURL (classe URL)
L'écran de démarrage a un bouton Aide. Lorsque vous appuyez dessus, il affichera la page Web indiquée ici dans votre navigateur Web.
loadURL (classe LoadURL)
C'est la commande shell utilisée pour charger une URL dans votre navigateur Web.
demoCommand (classe DemoCommand)
C'est la commande shell exécutée lorsque le bouton Démonstration de la fenêtre de démarrage est pressé. Par défaut, c'est xscreensaver-settings(1).
newLoginCommand (classe NewLoginCommand)
Si défini, c'est la commande shell qui est exécutée lorsque le bouton "Nouvelle connexion" est pressé dans la boîte de dialogue de déverrouillage, afin de créer une nouvelle session de bureau sans déconnecter l'utilisateur qui a verrouillé l'écran. Typiquement, ce sera une variante de gdmflexiserver(1), kdmctl(1), lxdm(1) ou dm-tool(1).
nice (classe Nice)
Les sous-processus lancés par XScreenSaver seront "nicés" à ce niveau, de sorte qu'ils auront une priorité inférieure à celle des autres processus du système et n'augmenteront pas inutilement la charge. Par défaut, c'est 10. (Des nombres plus élevés signifient une priorité plus faible ; voir nice(1) pour les détails.)
fade (classe Boolean)
Si c'est vrai, alors lorsque l'économiseur d'écran s'active, le bureau s'estompera vers le noir au lieu de disparaître simplement. Par défaut : true.
unfade (classe Boolean)
Si c'est vrai, alors lorsque l'économiseur d'écran se désactive, le bureau réapparaîtra au lieu d'apparaître immédiatement. Cela n'est fait que si fade est également vrai. Par défaut : true.
fadeSeconds (classe Time)
Si fade est vrai, c'est la durée de l'estompage en secondes. Par défaut 3 secondes.
ignoreUninstalledPrograms (classe Boolean)
Il peut y avoir des programmes dans la liste qui ne sont pas installés sur le système, mais qui sont marqués comme "activés". Si cette préférence est vraie, alors ces programmes seront simplement ignorés. Si elle est fausse, un avertissement sera affiché si une tentative est faite pour exécuter le programme inexistant. De plus, le programme xscreensaver-settings(1) supprimera les programmes inexistants de la liste si ceci est vrai. Par défaut : false.
authWarningSlack (classe Integer)
Après avoir déverrouillé l'écran avec succès, une boîte de dialogue peut apparaître pour vous informer des tentatives de connexion précédentes qui ont échoué. Si toutes ces tentatives de connexion ont eu lieu dans ce laps de temps, elles sont ignorées. L'hypothèse est que les mots de passe incorrects entrés quelques secondes avant un mot de passe correct sont une erreur de l'utilisateur plutôt qu'une action hostile. Par défaut 20 secondes.
mode (classe Mode)
Contrôle le comportement d'économie d'écran. Les valeurs valides sont :
random
Lors de la mise en veille de l'écran, sélectionne un écran aléatoire
random-same
Comme random, mais s'il y a plusieurs écrans, chaque écran exécutera le même mode d'affichage aléatoire, au lieu que chaque écran exécute un mode différent.
one
Lors de la mise en veille de l'écran, n'utilisez toujours qu'un mode d'affichage particulier (celui indiqué par le réglage selected).
blank
Lors de la mise en veille de l'écran, affichez simplement du noir : n'exécutez aucune animation graphique.
off
Ne mettez jamais l'écran en veille, et ne permettez jamais au moniteur de s'éteindre.
selected (classe Integer)
Lorsque mode est réglé sur one, il s'agit du mode unique, indiqué par son index dans la liste programs. Vous êtes fou si vous les comptez et réglez ce nombre à la main : laissez xscreensaver-settings(1) s'en charger pour vous !
programs (classe Programs)
Les animations graphiques que XScreenSaver exécute lorsque l'utilisateur est inactif. La valeur de cette ressource est une chaîne multiligne, une commande au format sh par ligne. Chaque ligne doit contenir exactement une commande : pas de points-virgules, pas d'esperluettes.

Lorsque le screensaver démarre, l'une de ces animations est sélectionnée (conformément au réglage mode) et exécutée. Après l'expiration de la période cycle, elle est arrêtée, et une autre est sélectionnée et exécutée.

Si une ligne commence par un tiret (-) alors ce programme particulier est désactivé : il ne sera pas sélectionné au hasard (bien que vous puissiez toujours le sélectionner explicitement à l'aide du programme xscreensaver-settings(1)).

Si tous les programmes sont désactivés, l'écran deviendra simplement noir, comme lorsque mode est réglé sur blank.

Pour désactiver un programme, vous devez le marquer comme désactivé avec un tiret au lieu de le supprimer de la liste. C'est parce que les paramètres système (app-defaults) et personnels (.xscreensaver) sont fusionnés, et si un utilisateur supprime simplement une entrée de sa liste de programmes, mais que cette entrée existe toujours dans la liste système, elle réapparaîtra. Cependant, si l'utilisateur la désactive, son réglage a la priorité.

Le répertoire par défaut des animations XScreenSaver (généralement /usr/libexec/xscreensaver/) est ajouté à $PATH avant de rechercher ces programmes.

Pour utiliser un programme comme screensaver, il doit être capable de dessiner sur la fenêtre qui lui est fournie dans la variable d'environnement $XSCREENSAVER_WINDOW. S'il crée et affiche sa propre fenêtre à la place, cela ne fonctionnera pas. Il doit dessiner sur la fenêtre fournie.

Visuels :

Parce que XScreenSaver a été créé à l'époque où les dinosaures rôdaient sur terre, il contient toujours la prise en charge de choses que vous n'avez probablement jamais vues, telles que les moniteurs monochromes 1 bit, les moniteurs en niveaux de gris, et les moniteurs capables d'afficher uniquement des images mappées en couleurs 8 bits.

S'il y a certains programmes que vous souhaitez exécuter uniquement lorsque vous utilisez un écran couleur, et d'autres que vous souhaitez exécuter uniquement lorsque vous utilisez un écran monochrome, vous pouvez le spécifier comme suit :

mono:   mono-program  -root        \n\
color:  color-program -root        \n\
Plus généralement, vous pouvez spécifier le type de visuel qui doit être utilisé pour la fenêtre sur laquelle le programme dessinera. Par exemple, si un programme fonctionne mieux s'il possède une palette de couleurs, mais qu'un autre fonctionne mieux s'il possède un visuel 24 bits, les deux peuvent être accommodés : 
PseudoColor: cmap-program  -root   \n\
TrueColor:   24bit-program -root   \n\
En plus des noms de visuels symboliques décrits ci-dessus (dans la discussion de la ressource visualID), un autre nom de visuel est pris en charge dans la liste programs :
default-n
Ceci est comme default, mais demande aussi l'utilisation de la palette de couleurs par défaut, au lieu d'une palette de couleurs privée.

Si vous spécifiez un visuel particulier pour un programme, et que ce visuel n'existe pas sur l'écran, alors ce programme ne sera pas choisi pour être exécuté. Cela signifie que sur les écrans avec plusieurs écrans de profondeurs différentes, vous pouvez organiser pour que les animations appropriées soient exécutées sur chacun. Par exemple, si un écran est en couleur et l'autre en monochrome, les animations qui rendent bien en mono peuvent être exécutées sur l'un, et les animations qui ne rendent bien qu'en couleur apparaîtront sur l'autre.

visualID (classe VisualID)
Ceci est un vestige historique laissé depuis que les écrans 8 bits étaient encore courants. Vous devriez probablement ignorer ceci.

Spécifiez quel visuel X utiliser par défaut. (Notez bien que cette ressource s'appelle visualID, et pas simplement visual ; si vous définissez la ressource visual à la place, les choses fonctionneront mal de manière obscure pour des raisons obscures.)

Les valeurs valides pour la ressource VisualID sont :

default
Utiliser le visuel par défaut de l'écran (le visuel de la fenêtre racine). C'est la valeur par défaut.
best
Utiliser le visuel qui prend en charge le plus de couleurs. Notez, cependant, que le visuel avec le plus de couleurs pourrait être un visuel TrueColor, qui ne prend pas en charge l'animation de palette de couleurs. Certains programmes ont un comportement plus intéressant lorsqu'ils sont exécutés sur des visuels PseudoColor que sur TrueColor.
mono
Utiliser un visuel monochrome, s'il en existe un.
gray
Utiliser un visuel en niveaux de gris ou StaticGray, s'il en existe un et qu'il a plus d'un plan (c'est-à-dire qu'il n'est pas monochrome).
color
Utiliser le meilleur des visuels couleur, s'il y en a.
GL
Utiliser le visuel qui convient le mieux aux programmes OpenGL. (Les programmes OpenGL ont des exigences légèrement différentes des autres programmes X.)
class
où class est l'un de StaticGray, StaticColor, TrueColor, GrayScale, PseudoColor, ou DirectColor. Sélectionne le visuel le plus profond de la classe donnée.
N
où number (décimal ou hexadécimal) est interprété comme un numéro d'ID de visuel, tel que rapporté par le programme xdpyinfo(1) ; de cette manière, vous pouvez avoir un contrôle plus fin sur le visuel exact qui sera utilisé, par exemple, pour en sélectionner un moins profond que celui qui aurait été choisi autrement.

Notez que cette option spécifie uniquement le visuel par défaut qui sera utilisé : le visuel utilisé peut être remplacé programme par programme. Voir la description de la ressource programs, ci-dessus.

installColormap (classe Boolean)
Ceci est un vestige historique laissé depuis que les écrans 8 bits étaient encore courants. Sur les écrans PseudoColor (8 bits), installez une palette de couleurs privée pendant que le screensaver est actif, afin que les animations graphiques puissent obtenir autant de couleurs que possible. C'est la valeur par défaut. (Ceci ne s'applique que lorsque le visuel par défaut de l'écran est utilisé, car les visuels non par défaut obtiennent leurs propres palettes de couleurs automatiquement.) Ceci peut également être remplacé pour chaque animation : voir la discussion du nom default-n dans la section concernant la ressource programs.

Ceci ne fait rien si vous avez un écran TrueColor (16 bits ou plus profond). (Ce qui, en ce siècle, est votre cas.)

pointerHysteresis (classe Integer)
Si la souris se déplace de moins de ce nombre de pixels par seconde, ignorez-la (ne considérez pas cela comme une "activité"). Ceci est fait pour que l'écran ne se désactive pas (ou n'échoue pas à se désactiver) simplement parce que vous avez heurté le bureau. Défaut : 10 pixels.

Un seul pixel de mouvement provoquera toujours le redémarrage du moniteur, mais pas sa réactivation. C'est parce que le serveur X11 lui-même gère malheureusement la détection d'activité liée à la gestion de l'alimentation plutôt que XScreenSaver.

pour obtenir l'hôte et le numéro d'affichage par défaut, et pour informer les sous-programmes de l'écran sur lequel dessiner.

pour trouver les sous-programmes à exécuter, y compris les modes d'affichage.
HOME
pour le répertoire dans lequel lire le fichier .xscreensaver.

pour obtenir le nom d'un fichier de ressources qui remplace les ressources globales stockées dans la propriété RESOURCE_MANAGER.
