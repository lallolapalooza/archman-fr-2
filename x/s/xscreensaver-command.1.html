xscreensaver-command(1)

Paquet: xscreensaver

Licences: BSD

XScreenSaver(1) Manuel des commandes générales XScreenSaver(1)

NOM

xscreensaver-command - contrôler un processus xscreensaver en cours d'exécution

SYNTAXE

xscreensaver-command [--display hôte:écran.subécran] [--help | --quiet | --verbose | --activate | --deactivate | --cycle | --next | --prev | --select n | --lock | --suspend | --exit | --restart | --time | --watch | --version]

DESCRIPTION

Le programme xscreensaver-command contrôle un démon xscreensaver(1) en cours d'exécution.

OPTIONS

xscreensaver-command accepte les options de ligne de commande suivantes :

--help
Affiche un bref résumé des options de ligne de commande.
--quiet
N'affiche une sortie que si une erreur se produit.
--verbose
Opposé de --quiet. Par défaut.
--activate
Demande à xscreensaver de s'activer immédiatement (c'est-à-dire d'assombrir l'écran, comme si l'utilisateur était resté inactif assez longtemps.) L'économiseur d'écran se désactivera dès qu'il y aura une activité utilisateur, comme d'habitude.
--deactivate
Ceci indique à xscreensaver de simuler une activité utilisateur récente. Cela signifie que si l'économiseur d'écran est actif (l'écran est assombri), cette commande fera réapparaître le contenu de l'écran comme s'il y avait eu une activité du clavier ou de la souris. Si l'écran est verrouillé, la boîte de dialogue du mot de passe apparaîtra d'abord, comme d'habitude. Si l'écran n'est pas assombri, cette activité utilisateur simulée redémarrera le compte à rebours (ainsi, l'émission périodique de la commande --deactivate est une façon d'empêcher l'écran de s'assombrir.)
--cycle
Si l'économiseur d'écran est actif (l'écran est assombri), arrête la démo graphique en cours et en lance une nouvelle (choisie aléatoirement.)
--next
Ceci est similaire à --activate ou --cycle, selon ce qui est le plus approprié, sauf que le module graphique qui sera lancé est le suivant dans la liste, au lieu d'un choix aléatoire. En d'autres termes, l'exécution répétée de --next fera en sorte que le processus xscreensaver invoque chaque démo graphique séquentiellement. (Bien que l'utilisation de l'option --settings soit probablement un moyen plus simple d'y parvenir.)
--prev
Ceci est similaire à --next, mais parcourt dans l'autre direction.
--select n
Similaire à --activate, mais lance le N-ième élément de la liste des modules. En connaissant le contenu de la liste programs, et leur ordre, vous pouvez utiliser ceci pour activer l'économiseur d'écran avec une démo graphique particulière. (Le premier élément de la liste est numéroté 1, pas 0.)
--lock
Demande au processus xscreensaver en cours d'exécution de verrouiller l'écran immédiatement. Ceci est similaire à --activate, mais force également le verrouillage, même si le verrouillage n'est pas par défaut (c'est-à-dire, même si la ressource lock de xscreensaver est fausse, et même si la ressource lockTimeout est non nulle.)

Notez que le verrouillage ne fonctionne pas à moins que le processus xscreensaver ne s'exécute en tant que vous. Voir xscreensaver(1) pour plus de détails.

--suspend
Similaire à --activate, mais ignore lockTimeout et éteint immédiatement l'écran sans fondu. Ceci est destiné à être exécuté juste après la fermeture du capot de votre ordinateur portable, et juste avant que le processeur ne s'arrête, pour verrouiller les choses rapidement.
--exit
Provoque la sortie propre du processus xscreensaver. Ceci ne fait rien si l'écran est actuellement verrouillé. Attention : n'utilisez jamais kill -9 avec xscreensaver. Cela peut laisser les choses dans un état incohérent, et vous pourriez avoir besoin de vous déconnecter pour réparer les dégâts.
--restart
Provoque la sortie du processus de l'économiseur d'écran, puis son redémarrage avec les mêmes arguments de ligne de commande qu'auparavant. Vous ne devriez pas vraiment avoir besoin de faire cela, car xscreensaver remarque lorsque le fichier .xscreensaver a changé et le relit au besoin.
--time
Affiche l'heure à laquelle l'économiseur d'écran s'est activé ou désactivé pour la dernière fois (approximativement, combien de temps l'utilisateur a été inactif ou actif : mais pas exactement, car il indique seulement quand l'écran est devenu assombri ou réapparu.)
--watch
Affiche une ligne chaque fois que l'économiseur d'écran change d'état : lorsque l'écran s'assombrit, se verrouille, réapparaît, ou lorsque le module en cours d'exécution est modifié. Cette option ne retourne jamais ; elle est destinée à être utilisée par des scripts shell qui veulent réagir à l'économiseur d'écran d'une manière ou d'une autre. Un exemple de sa sortie serait : 
BLANK Ven Nov  5 01:57:22 1999
RUN 34
RUN 79
RUN 16
LOCK Ven Nov  5 01:57:22 1999
RUN 76
RUN 12
UNBLANK Ven Nov  5 02:05:59 1999
Ce qui précède montre l'économiseur d'écran s'activant, exécutant trois modules différents, puis se verrouillant (peut-être parce que le délai de verrouillage a expiré), puis réapparaissant (parce que l'utilisateur est devenu actif et a tapé le bon mot de passe.) Les numéros des modules sont leur index dans la liste `programs' (commençant par 1, pas 0, comme pour la commande --select.)

Par exemple, supposez que vous vouliez exécuter un programme qui baisse le volume de votre machine lorsque l'écran s'assombrit, et le remonte lorsque l'écran réapparaît. Vous pourriez le faire en exécutant un programme Perl comme celui ci-dessous en arrière-plan. Le programme suivant suit la sortie de la commande --watch et réagit en conséquence :

#!/usr/bin/perl
my $blanked = 0;
open (my $in, "xscreensaver-command -watch |") || die;
while (<$in>) {
  if (m/^(BLANK|LOCK)/) {
    if (!$blanked) {
      system ("sound-off");
      $blanked = 1;
    }
  } elsif (m/^UNBLANK/) {
    system ("sound-on");
    $blanked = 0;
  }
}
Notez que LOCK peut apparaître avec ou sans BLANK précédent (selon que le délai de verrouillage est non nul), donc le programme ci-dessus suit les deux.
--version
Affiche la version de xscreensaver qui s'exécute actuellement sur l'écran : c'est-à-dire, le numéro de version réel du processus d'arrière-plan xscreensaver en cours d'exécution, plutôt que le numéro de version de xscreensaver-command. (Pour voir le numéro de version de xscreensaver-command lui-même, utilisez l'option --help.)

ARRÊTER LES GRAPHIQUES

Si xscreensaver est en cours d'exécution, mais que vous voulez qu'il arrête d'exécuter des modules d'écran (par exemple, si vous êtes connecté à distance, et que vous voulez que la console reste verrouillée mais juste noire, sans processus graphiques en cours d'exécution) vous pouvez y parvenir en éteignant simplement le moniteur à distance. Dans une minute ou deux, xscreensaver remarquera que le moniteur est éteint, et arrêtera d'exécuter des modules d'écran. Vous pouvez éteindre le moniteur comme suit :

xset dpms force off

Voir le manuel de xset(1) pour plus d'informations.

Vous pouvez également utiliser xscreensaver-settings(1) pour faire en sorte que le moniteur s'éteigne après quelques heures, ce qui signifie que xscreensaver exécutera des graphiques jusqu'à ce qu'il soit resté inactif pendant la durée que vous avez spécifiée ; et après cela, le moniteur s'éteindra, et les modules d'écran ne seront plus exécutés.

DIAGNOSTICS

Si une erreur se produit lors de la communication avec le démon xscreensaver, ou si le démon signale une erreur, un message de diagnostic sera imprimé sur stderr, et xscreensaver-command se terminera avec une valeur non nulle. Si la commande est acceptée, une indication de cela sera imprimée sur stdout, et la valeur de sortie sera zéro.

ENVIRONNEMENT

DISPLAY
pour obtenir l'hôte et le numéro d'écran de l'écran dont l'économiseur doit être manipulé.
PATH
pour trouver l'exécutable à redémarrer (pour la commande --restart). Notez que cette variable est consultée dans l'environnement du processus xscreensaver, et non dans celui du processus xscreensaver-command.
