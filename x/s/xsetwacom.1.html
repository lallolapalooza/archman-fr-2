xsetwacom(1) Manuel des commandes générales xsetwacom(1)

NOM

xsetwacom - utilitaire en ligne de commande pour interroger et modifier les paramètres du pilote wacom.

SYNOPSIS

xsetwacom [options] [commande [arguments]]

DESCRIPTION

Ce programme interroge ou modifie les propriétés des périphériques chargés par le pilote wacom. La modification des propriétés se fait à la volée et n'est pas persistante lors des redémarrages du serveur X.

OPTIONS GÉNÉRALES

-d, --display nom_affichage
Se connecter au serveur X spécifié dans nom_affichage ; voir X(7).
-h, --help
Affiche une aide succincte.
-v, --verbose
Activer la sortie détaillée, utile pour le débogage.
-V, --version
Afficher le numéro de version et quitter.

COMMANDES

Les commandes autorisées sont list, get, et set. La commande peut être spécifiée avec ou sans un ou deux tirets précédents, c.-à-d. --list équivaut à -list et list.

COMMANDES LIST

list devices
Lister les périphériques connus. Seuls les périphériques d'entrée gérés par le pilote wacom sont listés.
list parameters
Lister les paramètres connus. Liste tous les paramètres adaptés à la commande get ou set. Notez que tous les paramètres ne sont pas disponibles sur tous les types de périphériques.
list modifiers
Lister les alias pour les modificateurs et autres touches qui peuvent être utilisés lors de la définition des mappages d'actions de boutons.

COMMANDES GET

get nom_périphérique paramètre
Obtenir les paramètres actuels pour le paramètre sur le périphérique donné. Notez que tous les paramètres ne sont pas disponibles sur tous les types de périphériques. Le nom de paramètre spécial "all" peut être fourni pour afficher tous les paramètres actuels sur le périphérique.
Par défaut, les options sont imprimées sur la ligne de commande dans le format respectif.
Le format de sortie peut être modifié avec l'une des options suivantes :
-s, --shell
Afficher la sortie au format shell, c.-à-d. comme des commandes shell à xsetwacom pour reproduire le même paramètre.
-x, --xconf
Afficher la sortie au format xorg.conf, c.-à-d. comme des lignes d'options qui peuvent être ajoutées à la section InputDevice dans le fichier xorg.conf.

COMMANDES SET

set nom_périphérique paramètre [valeur]
Définir la valeur du paramètre sur le périphérique donné à la valeur fournie. Notez que tous les paramètres ne sont pas inscriptibles, certains sont en lecture seule et entraînent une erreur lors d'une tentative de modification.

PARAMÈTRES

Tous les paramètres ne sont pas disponibles sur tous les outils. Utilisez la commande get avec le paramètre ou le paramètre "all" pour les paramètres applicables aux outils d'entrée spécifiques et les paramètres actuels.

Area x1 y1 x2 y2
Définir la zone d'entrée de la tablette en coordonnées du périphérique sous la forme coin supérieur gauche x/y et coin inférieur droit x/y. Le coin supérieur gauche et le coin inférieur droit sont définis dans l'orientation native du périphérique, indépendamment de la rotation actuellement appliquée. Les entrées en dehors de ces coordonnées seront coupées aux bords de la zone définie. Défaut : 0 0 x2 y2 ; avec x2 et y2 spécifiques à la tablette.
ResetArea
Définir la zone d'entrée de la tablette à l'ensemble par défaut. L'ensemble est défini dans l'orientation native du périphérique, indépendamment de la rotation actuellement appliquée.
Button numéro-bouton [mappage]
AbsWheelUp [mappage]
AbsWheelDown [mappage]
AbsWheel2Up [mappage]
AbsWheel2Down [mappage]
DialCW [mappage]
DialCCW [mappage]
Dial2CW [mappage]
Dial2CCW [mappage]
RelWheelUp [mappage]
RelWheelDown [mappage]
RelWheel2Up [mappage]
RelWheel2Down [mappage]
Définit un mappage pour le contrôle spécifié. Les mappages prennent la forme soit d'un seul bouton numérique, soit d'une 'action' à effectuer. Si aucun mappage n'est fourni, le mappage par défaut est restauré. Si un contrôle est mappé à 0, l'événement est ignoré.

Les mappages de boutons numériques indiquent à quel numéro de bouton X11 le numéro-bouton donné doit correspondre. Par exemple, un mappage de "3" signifie qu'une pression sur le bouton donné produira une pression sur le bouton X11 3 (c.-à-d. clic droit).

Les mappages d'actions permettent aux pressions de boutons d'effectuer de nombreux événements. Ils prennent la forme d'une chaîne de mots-clés et d'arguments.

Le mot-clé "key" est suivi d'une liste de noms de touches. Ceux-ci peuvent éventuellement être précédés de "+" pour la pression et de "-" pour le relâchement. Si +/- n'est pas donné, la pression-relâchement est supposée, sauf pour les touches modificatrices qui restent enfoncées. Les noms de touches peuvent être des KeySyms X11 ou certains alias tels que 'shift' ou 'f1' (la liste complète peut être consultée avec la commande list modifiers).

Pour attribuer une touche qui ne figure pas dans la liste des modificateurs, utilisez le KeySym dans /usr/include/X11/keysymdef.h avec le préfixe XK_ supprimé ou sa valeur réelle telle quelle. Par exemple, XK_BackSpace doit être spécifié comme "BackSpace". "0xff80" peut également être utilisé pour remplacer "BackSpace" car c'est la valeur KeySym unique de la touche Backspace.

Voici un exemple combiné : "key +a shift b shift -a 0xff0d" convertit le bouton en une série de frappes. Dans cet exemple, "presse a, presse shift, presse et relâche b, relâche shift, relâche a, puis presse et relâche entrée". "key +a +shift b -shift -a 0xff0d" fait la même chose.

Le mot-clé "button" est similaire sauf que ses arguments sont des numéros de boutons X11.

Le mot-clé "modetoggle" est également reconnu ; il ne prend aucun argument et bascule le mode du périphérique entre le suivi de pointeur relatif et absolu.

Le mot-clé "pan" provoque l'envoi d'événements de défilement par le pilote lors du déplacement du stylet. Cela facilite le défilement des listes et des documents, le panoramique des toiles 2D et le zoom avant/arrière des scènes 3D (le comportement exact dépend de l'interprétation par l'application des événements de la molette de défilement). Le déplacement du stylet de haut en bas envoie des événements de défilement vers le bas/haut ; le déplacer de gauche à droite envoie des événements de défilement vers la droite/gauche.

Les événements dans le mappage d'actions sont envoyés lorsque le bouton physique est pressé. Si le mappage d'actions laisse des boutons ou des touches enfoncés (comme une touche modificatrice), ils seront relâchés lorsque le bouton physique sera relâché.

Plusieurs mots-clés peuvent être présents dans une action si désiré : par exemple "key +ctrl button 5 ke

xsetwacom(1) — Arch manual pages

NAME

xsetwacom — utility for querying and modifying Wacom device properties

SYNOPSIS

xsetwacom [options] [{--all | --display <display>}] [--list | --dump [device]] [device [ <attribute> [ <value>] [ ... ] ] ...]

DESCRIPTION

The xsetwacom utility is used to query and modify the properties of Wacom graphics tablets. It works by communicating with the xf86-input-wacom Xorg driver. The driver handles the communication with the tablet hardware and exposes a set of properties that can be queried and modified by xsetwacom.

The driver supports multiple tools (stylus, eraser, pen, mouse, etc.) and multiple devices (tablets). Each tool and device has a unique serial number or identifier. xsetwacom can query properties for a specific device or globally for all devices.

For a list of available devices and their properties, run xsetwacom --list.

The following options are available:

--all
Modifies all devices.
--display <display>
Use the specified X display. Defaults to the value of the DISPLAY environment variable.
--list
Lists all devices. If a device name is given, lists all attributes for that device.
--dump [device]
Dumps all properties for the specified device or for all devices if no device is given. The output is formatted as a series of xsetwacom commands.
--version
Prints the program version and exits.

If no options are specified, xsetwacom behaves like xsetwacom --list.

When modifying device properties, use the format:

xsetwacom --set device attribute [value] [...]

You can specify multiple device/attribute pairs in a single command. If the --all option is used, the properties are set for all devices.

DEVICE PROPERTIES

The following properties can be set for a Wacom device:

Action [index] [action]
Map a button or key to an action. The index refers to the button number on the device (starts at 0 for the tablet itself, then buttons on the stylus/eraser, then buttons on the pad). The action is a sequence of key presses and releases.

Key sequences are defined as:

  • -key: Release the specified key.
  • +key: Press the specified key.
  • key: Press and release the specified key.
  • +shift, -shift: Press and release the Shift key.
  • +ctrl, -ctrl: Press and release the Control key.
  • +alt, -alt: Press and release the Alt key.
  • +meta, -meta: Press and release the Meta key (usually the Windows key).
  • +super, -super: Press and release the Super key (usually the Windows key).
  • +hyper, -hyper: Press and release the Hyper key.
  • +iso key, -iso key: Press and release the specified ISO key.
  • +ctrl&alt, -ctrl&alt: Press and release Ctrl+Alt together.
  • x,y: Move the pointer to the specified coordinates.
  • key x,y: Press and release the specified key combination and move the pointer.
  • -clear: Clears all bound actions for the given button.

A maximum of 256 presses and/or releases can be specified in an action mapping.

The driver can only simulate physical key events but not keysyms and xsetwacom translates the mapping sequence into such events. Thus, symbols on the same physical key will generate the same event. For example, '1' and '!' are on the same key on a US keyboard and thus have the same keycode). For access to keys on a higher shift level, the sequence should be entered as it would be typed on a physical keyboard. For example, a exclamation mark is entered by the sequence of "key +shift 1 -shift".

BindToSerial [serial|0]
Bind the device to the tool with the specified serial number. Once bound, the device will ignore events from other tools. A serial of 0 means the device is unbound and will react to any tool of the matching type. Default: 0
MapToOutput [output]
Map the tablet's input area to a given output (e.g. "VGA1"). Output names may either be the name of a head available through the XRandR extension, or an X11 geometry string of the form WIDTHxHEIGHT+X+Y. To switch to the next available output, the "next" keyword is also supported. This will cycle between the individual monitors connected to the system, and then the entire desktop. The mapping may be reset to the entire desktop at any time with the output name "desktop". Users of the NVIDIA binary driver should use the output names "HEAD-0" and "HEAD-1" until the driver supports XRandR 1.2 or later.

The output mapping configuration is a onetime setting and does not track output reconfigurations; the command needs to be re-run whenever the output configuration changes. When used with tablet rotation, the tablet must be rotated before it is mapped to the new screen. This parameter is write-only and cannot be queried.

Mode Absolute|Relative
Set the device mode as either Relative or Absolute. Relative means pointer tracking for the device will function like a mouse, whereas Absolute means the pointer corresponds to the device's actual position on the tablet or tablet PC screen. Default: Absolute for stylus, eraser and tablet PC touch; Relative for cursor and tablet touch.
PressureCurve x1 y1 x2 y2
A Bezier curve of third order, composed of two anchor points (0,0 and 100,100) and two user modifiable control points that define the curve's shape. Raise the curve (x1<y1 x2<y2) to "soften" the feel and lower the curve (x1>y1 x2>y2) for a "firmer" feel. Sigmoid shaped curves are permitted (x1>y1 x2<y2 or x1<y1 x2>y2). Default: 0 0 100 100, a linear curve; range of 0 to 100 for all four values.
RawSample level
Set the sample window size (a sliding average sampling window) for incoming input tool raw data points. Default: 4, range of 1 to 20.
Rotate none|half|cw|ccw
Set the tablet to the given rotation:
none: the tablet is not rotated and uses its natural rotation
half: the tablet is rotated by 180 degrees (upside-down)
cw: the tablet is rotated 90 degrees clockwise
ccw: the tablet is rotated 90 degrees counter-clockwise

Rotation is a tablet-wide option: rotation of one tool affects all other tools associated with the same tablet. When the tablet is physically rotated, rotate any tool to the corresponding orientation. Default: none

Suppress level
Set the delta (difference) cutoff level for further processing of incoming input tool coordinate values. For example a X or Y coordinate event will be sent only if the change between the current X or Y coordinate and the previous one is greater than the Suppress value. The same applies to pressure level (Z coordinate) and Tilt rotation values. With a current absolute wheel (AbsWheel) or Tilt value the delta between it and the previous value must be equal to or greater than the Suppress value in order to be sent on. Suppress is a tablet wide parameter. A specified delta level for one input tool is applied to all input tool coordinates. To disable suppression use a level of 0. Default: 2, range of 0 to 100.
TabletDebugLevel level
Set the debug level for this tablet to the given level. This only affects code paths that are shared between several tools on the same physical tablet. A higher level means more fine-grained debug messages, a level of 0 turns debugging off for this tool. Requires the driver to be built with debugging enabled. See also ToolDebugLevel. Default: 0, range of 0 to 12.
TabletPCButton on|off
If on, the stylus must be in contact with the screen for a stylus side button to work. If off, stylus buttons will work once the stylus is in proximity of the tablet (regardless of whether it is touching the screen). Default: on for Tablet PCs; off for all other models.
ToolSerialPrevious
Get the serial number of the tool that was last in proximity last. This serial number is updated whenever the tool goes out of proximity. If the current tool went out of proximity once, this serial number is the one of the current tool. This is a read-only parameter.
Touch on|off
If on, touch events are reported to userland, i.e., system cursor moves when user touches the tablet. If off, touch events are ignored. Default: on for devices that support touch; off for all other models.
HWTouchSwitchState on|off
If on, it means touch switch is turned off. That is, touch events are reported to userland. If off, touch switch is turned on, i.e., touch events are ignored. This is a read-only parameter. Initial touch switch state is retrieved from the kernel when X driver starts.
CursorProximity distance
Set the distance at which a relative tool is treated as being out of proximity. Beyond this distance the cursor will stop responding to tool motion. The default value for pucks is 10 (Intuos Pro) or 42 (Intuos/Bamboo). The default value for pens is 30.
Threshold level
Set the minimum pressure necessary to generate a Button event for the stylus tip, eraser, or touch. The pressure levels of all tablets are normalized to 2048 levels irregardless of the actual hardware supported levels. This parameter is independent of the PressureCurve parameter. Default: 27, range of 0 to 2047.
ToolDebugLevel level
Set the debug level for this tool to the given level. This only affects code paths that are specific to a given tool. A higher level means more fine-grained debug messages, a level of 0 turns debugging off for this tool. Requires the driver to be built with debugging enabled. See also TabletDebugLevel. Default: 0, range of 0 to 12.
PressureRecalibration on|off
If the initial pressure of a device is != 0 the driver recalibrates the pressure range. This is to account for worn out devices. The downside is that when the user hits the tablet very hard the initial pressure reading may be unequal to zero even for a perfectly good pen. If the consecutive pressure readings are not higher than the initial pressure by a threshold no button event will be generated. This option allows to disable the recalibration. Default: on
PanScrollThreshold distance
This specifies the distance the pen must move (in tablet units) before a scroll event is generated when using the "pan" action. Smaller values will require less distance and be more sensitive. Larger values will require more distance and be less sensitive. Default: 1300 or 2600 depending on tablet resolution (corresponds to 13 mm of distance).

WAYLAND SUPPORT

This tool provides access to the device properties implemented in the xf86-input-wacom X server input module. It does not work under a Wayland compositor as the input module is not active.

See https://github.com/linuxwacom/xf86-input-wacom/wiki/Wayland for details.
