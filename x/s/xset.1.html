XSET(1) Manuel des commandes générales XSET(1)

NOM

xset - utilitaire de préférences utilisateur pour X

SYNTAXE

xset [-display affichage]
[-b] [b {on|off}] [b [volume [pitch [durée]]]]
[-bc] [bc]
[-c] [c {on|off}] [c [volume]]
[+dpms] [-dpms]
[dpms veille [suspension [arrêt]]]
[dpms force {veille|suspension|arrêt|on}]
[fp=liste_chemins] [-fp=liste_chemins] [+fp=liste_chemins] [fp-liste_chemins] [fp+liste_chemins]
[fp default] [fp rehash]
[-led [entier|nommé indicateur]] [led [entier|nommé indicateur]]
[led {on|off}]
[souris [mult_accel[/div_accel] [seuil]]] [souris par défaut]
[p pixel couleur]
[-r [keycode]] [r [keycode]] [r {on|off}] [r taux délai [taux]]
[s [longueur [période]]] [s {vide|pasvide}]
[s {expose|pasexpose}] [s {on|off}] [s par défaut] [s activer] [s réinitialiser]
[q]
[-version]

DESCRIPTION

Ce programme est utilisé pour définir diverses options de préférences utilisateur du système d'affichage.

OPTIONS

-display affichage
Cette option spécifie le serveur à utiliser ; voir X(7).
b
L'option b contrôle le volume, la hauteur et la durée du carillon. Cette option accepte jusqu'à trois paramètres numériques, un tiret précédant (-) ou un indicateur 'on/off'. Si aucun paramètre n'est donné, ou si l'indicateur 'on' est utilisé, les valeurs par défaut du système seront utilisées. Si le tiret ou 'off' est donné, le carillon sera désactivé. Si un seul paramètre numérique est donné, le volume du carillon sera réglé à cette valeur, en pourcentage de son maximum. De même, le second paramètre numérique spécifie la hauteur du carillon, en hertz, et le troisième paramètre numérique spécifie la durée en millisecondes. Notez que tous les matériels ne peuvent pas varier les caractéristiques du carillon. Le serveur X réglera les caractéristiques du carillon aussi près que possible des spécifications de l'utilisateur.
bc
L'option bc contrôle le mode de compatibilité des bugs (bug compatibility) dans le serveur, si possible ; un tiret précédant (-) désactive le mode, sinon le mode est activé. Divers clients pré-R4 passent des valeurs illégales dans certaines requêtes de protocole, et les serveurs pré-R4 ne généraient pas correctement d'erreurs dans ces cas. De tels clients, lorsqu'ils sont exécutés sur un serveur R4, se terminent anormalement ou échouent d'une autre manière à fonctionner correctement. Le mode de compatibilité des bugs réintroduit explicitement certains bugs dans le serveur X, de sorte que de nombreux clients de ce type peuvent toujours être exécutés. Ce mode doit être utilisé avec précaution ; le développement de nouvelles applications devrait être fait avec ce mode désactivé. Le serveur doit prendre en charge l'extension de protocole MIT-SUNDRY-NONSTANDARD pour que cette option fonctionne.
c
L'option c contrôle le clic de touche. Cette option peut prendre une valeur optionnelle, un tiret précédant (-), ou un indicateur 'on/off'. Si aucun paramètre ou l'indicateur 'on' n'est donné, les valeurs par défaut du système seront utilisées. Si le tiret ou l'indicateur 'off' est utilisé, le clic de touche sera désactivé. Si une valeur de 0 à 100 est donnée, elle est utilisée pour indiquer le volume, en pourcentage du maximum. Le serveur X réglera le volume à la valeur la plus proche que le matériel peut supporter.
-dpms
L'option -dpms désactive les fonctionnalités de signalisation de gestion de l'alimentation de l'affichage (DPMS).
+dpms
L'option +dpms active les fonctionnalités de signalisation de gestion de l'alimentation de l'affichage (DPMS).
dpms indicateurs...
L'option dpms permet de régler les paramètres de signalisation de gestion de l'alimentation de l'affichage (DPMS). L'option peut prendre jusqu'à trois valeurs numériques, ou l'indicateur `force' suivi d'un état DPMS. Les indicateurs `force' forcent le serveur à passer immédiatement à l'état DPMS spécifié. L'état DPMS peut être l'un des `veille', `suspension', `arrêt', ou `on'. Lorsque des valeurs numériques sont données, elles définissent la période d'inactivité (en secondes) avant que les trois modes ne soient activés. La première valeur donnée est pour le mode `veille', la seconde pour le mode `suspension', et la troisième pour le mode `arrêt'. La définition de ces valeurs active implicitement les fonctionnalités DPMS. Une valeur de zéro désactive un mode particulier.
fp= chemin,...
L'option fp= définit le chemin des polices aux entrées données dans l'argument chemin. Les entrées sont interprétées par le serveur, pas par le client. Typiquement, ce sont des noms de répertoire ou des noms de serveur de polices, mais l'interprétation dépend du serveur.
fp par défaut
L'argument par défaut réinitialise le chemin des polices aux valeurs par défaut du serveur.
fp rehash
L'argument rehash réinitialise le chemin des polices à sa valeur actuelle, faisant relire au serveur les bases de données de polices dans le chemin des polices actuel. Ceci est généralement utilisé uniquement lors de l'ajout de nouvelles polices à un répertoire de polices (après avoir exécuté mkfontdir pour recréer la base de données des polices).
-fp ou fp-
Les options -fp et fp- suppriment des éléments du chemin des polices actuel. Elles doivent être suivies d'une liste d'entrées séparées par des virgules.
+fp ou fp+
Ces options +fp et fp+ ajoutent respectivement des éléments au début et à la fin du chemin des polices actuel. Elles doivent être suivies d'une liste d'entrées séparées par des virgules.
led
L'option led contrôle les LED du clavier. Elle contrôle l'activation ou la désactivation d'une ou de toutes les LED. Elle accepte un entier optionnel, un tiret précédant (-) ou un indicateur 'on/off'. Si aucun paramètre ou l'indicateur 'on' n'est donné, toutes les LED seront allumées. Si un tiret précédant ou l'indicateur 'off' est donné, toutes les LED seront éteintes. Si une valeur comprise entre 1 et 32 est donnée, cette LED sera allumée ou éteinte en fonction de la présence d'un tiret précédant. « xset led 3 » allumerait la LED n°3. « xset -led 3 » l'éteindrait. Les valeurs de LED spécifiques peuvent se référer à différentes LED sur différents matériels. Si le serveur X prend en charge l'extension XKEYBOARD (XKB), les LED peuvent être référencées par le nom de l'indicateur XKB en spécifiant le mot-clé `named' et le nom de l'indicateur. Par exemple, pour allumer la LED Verrouillage défilant :
xset led named "Verrouillage défilant"
souris
L'option m contrôle les paramètres de la souris ; elle peut être abrégée en 'm'. Bien sûr, elle s'applique à la plupart des périphériques de pointage, pas seulement aux souris. Les paramètres du périphérique de pointage sont `accélération' et `seuil'. L'accélération peut être spécifiée comme un entier, ou comme une simple fraction. Le seuil est juste un entier. Le réglage est appliqué à tous les périphériques de pointage connectés. xinput(1) doit être utilisé si vous avez besoin de réglages spécifiques à un périphérique.

Par défaut, le pointeur (la représentation à l'écran du périphérique de pointage) ira `accélération' fois plus vite lorsque le périphérique parcourt plus de `seuil' mickeys (c'est-à-dire des pixels potentiels) en 10 ms, y compris une petite plage de transition. Ainsi, le périphérique de pointage peut être utilisé pour un alignement précis lorsqu'il est déplacé lentement, mais il peut être réglé pour traverser l'écran d'un mouvement rapide du poignet lorsque désiré. Un ou les deux paramètres de l'option m peuvent être omis, mais si un seul est donné, il sera interprété comme l'accélération. Si aucun paramètre ou l'indicateur 'par défaut' n'est utilisé, les valeurs par défaut du système seront définies.

Si le paramètre `seuil' est fourni et vaut 0, le paramètre `accélération' sera utilisé dans l'exposant d'une formule plus naturelle et continue, offrant un contrôle précis pour les mouvements lents mais une grande portée pour les mouvements rapides, et une transition progressive pour les mouvements intermédiaires. La valeur `accélération' recommandée dans ce cas est de 3/2 à 3, mais sans s'y limiter.

Dans le serveur X.org X version 1.6 et ultérieures, le comportement décrit jusqu'à présent est lié au profil par défaut. Il existe d'autres profils (c'est-à-dire des fonctions déterminant l'accélération du pointeur à partir de la vitesse du périphérique) et des paramètres supplémentaires, donc la description ci-dessus peut ne pas s'appliquer aux cas non par défaut. Dans le serveur X.org 1.7, ceux-ci sont disponibles en tant que propriétés de périphériques d'entrée (voir xinput).

p
L'option p contrôle les valeurs de couleur des pixels.
Les paramètres sont le numéro d'entrée de la table des couleurs en décimal, et une spécification de couleur. Les couleurs d'arrière-plan racines peuvent être modifiées sur certains serveurs en modifiant les entrées de BlackPixel et WhitePixel. Bien que ceux-ci soient souvent 0 et 1, ils ne doivent pas nécessairement l'être. De plus, un serveur peut choisir d'allouer ces couleurs en privé, auquel cas une erreur sera générée. L'entrée de la table des couleurs ne doit pas être une couleur en lecture seule, sinon une erreur en résultera.
r
L'option r contrôle l'autorépétition. L'invocation avec "-r", ou "r off", désactivera l'autorépétition, tandis que "r", ou "r on" l'activera. Suivre l'option "-r" ou "r" avec un code de touche entier entre 0 et 255 désactivera ou activera l'autorépétition sur cette touche respectivement, mais seulement si cela est logique pour le code de touche particulier. Les codes de touche inférieurs à 8 ne sont généralement pas valides pour cette commande. Exemple : "xset -r 10" désactivera l'autorépétition pour la touche "1" sur la rangée supérieure d'un clavier IBM PC.

Si le serveur prend en charge l'extension XFree86-Misc, ou l'extension XKB, alors un paramètre 'rate' est accepté et doit être suivi de zéro, une ou deux valeurs numériques. La première spécifie le délai avant le début de l'autorépétition et la seconde spécifie le taux de répétition. Dans le cas où le serveur prend en charge l'extension XKB, le délai est le nombre de millisecondes avant le début de l'autorépétition, et le taux est le nombre de répétitions par seconde. Si le taux ou le délai n'est pas donné, il sera réglé à la valeur par défaut.

s
L'option s vous permet de définir les paramètres du protecteur d'écran. Cette option accepte jusqu'à deux paramètres numériques, un indicateur 'blank/noblank', un indicateur 'expose/noexpose', un indicateur 'on/off', un indicateur 'activate/reset', ou l'indicateur 'default'. Si aucun paramètre ou l'indicateur 'default' n'est utilisé, le système sera réglé sur ses caractéristiques par défaut pour le protecteur d'écran. Les indicateurs 'on/off' activent ou désactivent simplement les fonctions du protecteur d'écran. L'indicateur 'activate' force l'activation du protecteur d'écran même s'il avait été désactivé. L'indicateur 'reset' force la désactivation du protecteur d'écran s'il est actif. L'indicateur 'blank' définit la préférence pour éteindre la vidéo (si le matériel le permet) plutôt que d'afficher un motif d'arrière-plan, tandis que 'noblank' définit la préférence pour afficher un motif plutôt que d'éteindre la vidéo. L'indicateur 'expose' définit la préférence pour autoriser les expositions de fenêtres (le serveur peut jeter librement le contenu des fenêtres), tandis que 'noexpose' définit la préférence pour désactiver le protecteur d'écran à moins que le serveur ne puisse régénérer les écrans sans provoquer d'événements d'exposition. Les paramètres de durée et de période pour la fonction de protecteur d'écran déterminent combien de temps le serveur doit être inactif pour que la protection d'écran s'active, et la période pour changer le motif d'arrière-plan afin d'éviter la brûlure de l'écran. Les arguments sont spécifiés en secondes. Si un seul paramètre numérique est donné, il sera utilisé pour la durée.
q
L'option q vous donne des informations sur les paramètres actuels.
-version
L'option -version affiche la version du programme et quitte sans faire autre chose.

Ces paramètres seront réinitialisés aux valeurs par défaut lors de votre déconnexion.

Notez que toutes les implémentations X ne sont pas garanties de respecter toutes ces options.
