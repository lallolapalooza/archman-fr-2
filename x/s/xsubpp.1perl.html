XSUBPP(1perl) Guide de référence du programmeur Perl XSUBPP(1perl)

NOM

xsubpp - compilateur pour convertir le code XS de Perl en code C

SYNTAXE

xsubpp [-v] [-except] [-s pattern] [-prototypes] [-noversioncheck] [-nolinenumbers] [-nooptimize] [-typemap typemap] [-output filename]... file.xs

DESCRIPTION

Ce compilateur est généralement exécuté par les makefiles créés par ExtUtils::MakeMaker ou par Module::Build ou d'autres outils de construction de modules Perl.

xsubpp compilera le code XS en code C en intégrant les constructions nécessaires pour permettre aux fonctions C de manipuler les valeurs Perl et crée le "colle" nécessaire pour permettre à Perl d'accéder à ces fonctions. Le compilateur utilise des typemaps pour déterminer comment mapper les paramètres et variables des fonctions C aux valeurs Perl.

Le compilateur recherchera des fichiers typemap nommés typemap. Il utilisera le chemin de recherche suivant pour trouver les typemaps par défaut, le typemap le plus à droite ayant la priorité.

../../../typemap:../../typemap:../typemap:typemap

Il utilisera également un typemap par défaut installé sous le nom de "ExtUtils::typemap".

OPTIONS

Notez que l'option "XSOPT" de MakeMaker peut être utilisée pour ajouter ces options à tous les makefiles générés par MakeMaker.

-hiertype
Conserve '::' dans les noms de types afin que les types hiérarchiques C++ puissent être mappés.
-except
Ajoute des "stubs" de gestion d'exception au code C.
-typemap typemap
Indique qu'un typemap fourni par l'utilisateur doit avoir la priorité sur les typemaps par défaut. Cette option peut être utilisée plusieurs fois, le dernier typemap ayant la priorité la plus élevée.
-output filename
Spécifie le nom du fichier de sortie à générer. Si aucun fichier n'est spécifié, la sortie sera écrite sur la sortie standard.
-v
Affiche le numéro de version de xsubpp sur la sortie standard, puis se termine.
-prototypes
Par défaut, xsubpp ne génère pas automatiquement de code prototype pour tous les xsubs. Ce drapeau active les prototypes.
-noversioncheck
Désactive le test d'exécution qui détermine si le fichier objet (dérivé du fichier ".xs") et les fichiers ".pm" ont le même numéro de version.
-nolinenumbers
Empêche l'inclusion de directives '#line' dans la sortie.
-nooptimize
Désactive certaines optimisations. La seule optimisation actuellement affectée est l'utilisation de targets par le code C de sortie (voir perlguts). Cela peut ralentir considérablement le code généré, mais c'est ainsi que xsubpp des versions 5.005 et antérieures fonctionnait.
-noinout
Désactive la reconnaissance des déclarations "IN", "OUT_LIST" et "INOUT_LIST".
-noargtypes
Désactive la reconnaissance des descriptions de signature de fonction de type ANSI.
-C++
Ne fait actuellement rien du tout. Ce drapeau est inopérant depuis de nombreuses versions de perl, au moins depuis perl5.003_07. Il est conservé ici pour des raisons de compatibilité ascendante.
-s=... ou -strip=...
Cette option est obscure et déconseillée.

Si spécifiée, la chaîne donnée sera supprimée du début du nom de la fonction C dans les fonctions XS générées (si elles commencent par ce préfixe). Cela ne s'applique qu'aux XSUBs sans blocs "CODE" ou "PPCODE". Par exemple, le XS :

void foo_bar(int i);

lorsque "xsubpp" est invoqué avec "-s foo_" installera une fonction "foo_bar" dans Perl, mais appellera réellement bar(i) en C. La plupart du temps, c'est l'inverse de ce que vous voulez et les modes d'échec sont quelque peu obscurs, veuillez donc éviter cette option si possible.

ENVIRONNEMENT

Aucune variable d'environnement n'est utilisée.
