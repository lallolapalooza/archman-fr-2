x25(7) Manuel d'informations diverses x25(7)

NOM

x25 - Interface du protocole ITU-T X.25 / ISO/IEC 8208

SYNTAXE

#include <sys/socket.h>
#include <linux/x25.h>
socket_x25 = socket(AF_X25, SOCK_SEQPACKET, 0);

DESCRIPTION

Les sockets X25 fournissent une interface au protocole de couche paquet X.25. Cela permet aux applications de communiquer sur un réseau de données X.25 public tel que standardisé par la recommandation X.25 de l'Union Internationale des Télécommunications (mode X.25 DTE-DCE). Les sockets X25 peuvent également être utilisés pour la communication sans réseau X.25 intermédiaire (mode X.25 DTE-DTE) tel que décrit dans ISO/IEC 8208.

Les limites des messages sont préservées — une lecture (read(2)) depuis un socket récupérera le même bloc de données que celui sorti avec l'écriture correspondante (write(2)) vers le socket pair. Si nécessaire, le noyau prend en charge la segmentation et la réassemblage de longs messages au moyen du bit M de X.25. Il n'y a pas de limite supérieure codée en dur pour la taille du message. Cependant, le réassemblage d'un long message peut échouer en cas de manque temporaire de ressources système ou lorsque d'autres contraintes (telles que les limites de mémoire ou de taille de tampon du socket) deviennent effectives. Si cela se produit, la connexion X.25 sera réinitialisée.

Adresses de socket

La famille d'adresses de socket AF_X25 utilise la structure sockaddr_x25 pour représenter les adresses réseau telles que définies dans la recommandation X.121 de l'UIT.


struct sockaddr_x25 {
    sa_family_t sx25_family;    /* doit être AF_X25 */
    x25_address sx25_addr;      /* Adresse X.121 */
};

sx25_addr contient un tableau de caractères x25_addr[] à interpréter comme une chaîne terminée par un caractère nul. sx25_addr.x25_addr[] consiste en jusqu'à 15 caractères (sans compter le caractère nul de fin) formant l'adresse X.121. Seuls les caractères numériques décimaux de '0' à '9' sont autorisés.

Options de socket

Les options de socket X.25 spécifiques suivantes peuvent être définies à l'aide de setsockopt(2) et lues avec getsockopt(2) avec l'argument level défini sur SOL_X25.

X25_QBITINCL
Contrôle si le bit Q (Qualified Data Bit) de X.25 est accessible par l'utilisateur. Il attend un argument entier. S'il est défini sur 0 (par défaut), le bit Q n'est jamais défini pour les paquets sortants et le bit Q des paquets entrants est ignoré. S'il est défini sur 1, un octet initial supplémentaire est ajouté au début de chaque message lu ou écrit sur le socket. Pour les données lues depuis le socket, un premier octet de valeur 0 indique que les bits Q des paquets de données entrants correspondants n'étaient pas définis. Un premier octet de valeur 1 indique que le bit Q des paquets de données entrants correspondants était défini. Si le premier octet des données écrites sur le socket est 1, le bit Q des paquets de données sortants correspondants sera défini. Si le premier octet est 0, le bit Q ne sera pas défini.

VERSIONS

La famille de protocoles AF_X25 est une nouvelle fonctionnalité de Linux 2.2.

BOGUES

Beaucoup, car l'implémentation de la PLP X.25 est CONFIG_EXPERIMENTAL.

Cette page de manuel est incomplète.

Il n'existe pas encore de fichier d'en-tête dédié pour les programmeurs d'applications ; vous devez inclure le fichier d'en-tête du noyau <linux/x25.h>. CONFIG_EXPERIMENTAL peut également impliquer que les futures versions de l'interface ne seront pas binaires compatibles.

Les événements de réinitialisation N-Reset X.25 ne sont pas encore propagés au processus utilisateur. Ainsi, si une réinitialisation s'est produite, des données pourraient être perdues sans avertissement.
