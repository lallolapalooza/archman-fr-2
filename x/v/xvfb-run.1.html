xvfb-run(1) Manuel des commandes générales xvfb-run(1)

NOM

xvfb-run - exécute un client X spécifié ou une commande dans un environnement de serveur X virtuel

SYNTAXE

xvfb-run [ options ] commande

DESCRIPTION

xvfb-run est un script d'enrobage pour la commande Xvfb(1x) qui simplifie la tâche d'exécution de commandes (typiquement un client X, ou un script contenant une liste de clients à exécuter) dans un environnement de serveur X virtuel.

xvfb-run configure un fichier d'autorité X (ou utilise un fichier spécifié par l'utilisateur), y écrit un cookie (voir xauth(1x)) puis démarre le serveur X Xvfb en tant que processus d'arrière-plan. L'ID de processus de Xvfb est stocké pour une utilisation ultérieure. La commande spécifiée est ensuite exécutée en utilisant l'affichage X correspondant au serveur Xvfb qui vient d'être démarré et le fichier d'autorité X créé précédemment.

Lorsque la commande se termine, son statut est enregistré, le serveur Xvfb est arrêté (en utilisant l'ID de processus stocké précédemment), le cookie d'autorité X est supprimé, et le fichier d'autorité est supprimé (si l'utilisateur n'en a pas spécifié un à utiliser). xvfb-run se termine alors avec le code de sortie de la commande.

xvfb-run nécessite la commande xauth pour fonctionner.

OPTIONS

-a, --auto-servernum
Essaye d'obtenir un numéro de serveur libre, en commençant par 99, ou par l'argument de --server-num.
-e fichier, --error-file=fichier
Stocke la sortie de xauth et Xvfb dans fichier. Le défaut est /dev/null.
-f fichier, --auth-file=fichier
Stocke les données d'authentification X dans fichier. Par défaut, un répertoire temporaire nommé xvfb-run.PID (où PID est l'ID de processus de xvfb-run lui-même) est créé dans le répertoire spécifié par la variable d'environnement TMPDIR (ou /tmp si cette variable est nulle ou non définie), et la commande tempfile(1) est utilisée pour créer un fichier dans ce répertoire temporaire nommé Xauthority.
-h, --help
Affiche un message d'utilisation et quitte.
-n numeroserveur, --server-num=numeroserveur
Utilise numeroserveur comme numéro de serveur (mais voir l'option -a, --auto-servernum ci-dessus). Le défaut est 99.
-l, --listen-tcp
Active l'écoute du port TCP dans le serveur X. Pour des raisons de sécurité (pour éviter les attaques par déni de service ou les exploitations), l'écoute du port TCP est désactivée par défaut.
-p nomprotocole, --xauth-protocol=nomprotocole
Utilise nomprotocole comme protocole d'autorité X à utiliser. Le défaut est ‘.’, que xauth interprète comme son propre protocole par défaut, qui est MIT-MAGIC-COOKIE-1.
-s arguments, --server-args=arguments
Passe arguments au serveur Xvfb. Faites attention à citer les caractères d'espacement qui pourraient apparaître dans arguments pour éviter qu'ils ne soient considérés comme des séparateurs pour les propres arguments de xvfb-run. Notez également que la spécification de ‘-nolisten tcp’ dans arguments peut outrepasser la fonction de la propre option -l, --listen-tcp de xvfb-run, et que la spécification du numéro de serveur (par exemple, ‘:1’) peut être ignorée en raison de la manière dont le serveur X analyse sa liste d'arguments. Utilisez l'option xvfb-run -n numeroserveur, --server-num=numeroserveur pour réaliser cette dernière fonction. Le défaut est ‘-screen 0 640x480x8’.
-w delai, --wait=delai
Attend delai secondes après le lancement de Xvfb avant de tenter de démarrer la commande spécifiée. Le défaut est 3.

ENVIRONNEMENT

COLUMNS
indique la largeur du terminal en cellules de caractères. Cette valeur est utilisée pour formater les messages de diagnostic. Si elle n'est pas définie, le terminal est interrogé en utilisant stty(1) pour déterminer sa largeur. Si cela échoue, une valeur de ‘80’ est supposée.
TMPDIR
spécifie le répertoire dans lequel placer le répertoire temporaire de xvfb-run pour stocker le fichier d'autorité X ; utilisé uniquement si les options -f ou --auth-file ne sont pas spécifiées.

FICHIERS DE SORTIE

Sauf si les options -f ou --auth-file sont spécifiées, un répertoire et un fichier temporaires y sont créés (et supprimés) pour stocker les cookies d'autorité X utilisés par le serveur Xvfb et le(s) client(s) exécuté(s) en dessous. Voir tempfile(1). Si -f ou --auth-file sont utilisés, alors le fichier d'autorité X spécifié est seulement écrit, pas créé ou supprimé (bien que xauth crée lui-même un fichier d'autorité s'il est dit d'utiliser celui qui n'existe pas encore).

Un fichier d'erreur avec un nom spécifié par l'utilisateur est également créé si les options -e ou --error-file sont spécifiées ; voir ci-dessus.

STATUT DE SORTIE

xvfb-run utilise son statut de sortie ainsi que la sortie vers l'erreur standard pour communiquer les diagnostics. Le statut de sortie ‘1’ n'est pas utilisé et doit être interprété comme un échec de la commande spécifiée.

0
xvfb-run utilise uniquement ce statut de sortie si l'option -h, --help est donnée. Dans toutes les autres situations, cela peut être interprété comme un succès de la commande spécifiée.
2
Aucune commande à exécuter n'a été spécifiée.
3
La commande xauth n'est pas disponible.
4
Le répertoire temporaire qui allait être utilisé existe déjà ; puisque xvfb-run produit un répertoire au nom unique, cela peut indiquer une tentative par un autre processus sur le système d'exploiter une condition de concurrence sur les fichiers temporaires.
5
Un problème a été rencontré lors du nettoyage du répertoire temporaire.
6
Un problème a été rencontré lors de l'utilisation de getopt(1) pour analyser les arguments de la ligne de commande.

EXEMPLES

xvfb-run --auto-servernum --server-num=1 xlogo
exécute le client de démonstration xlogo(1x) à l'intérieur du serveur X Xvfb sur le premier numéro de serveur disponible supérieur ou égal à 1.
xvfb-run --server-args="-screen 0 1024x768x24" ico -faces
exécute le client de démonstration ico(1x) (et lui passe l'argument -faces) à l'intérieur du serveur X Xvfb, configuré avec une fenêtre racine de 1024 par 768 pixels et une profondeur de couleur de 24 bits.

Notez que les clients X de démonstration utilisés dans les exemples ci-dessus ne se termineront pas d'eux-mêmes, ils devront donc être arrêtés avant que xvfb-run ne se termine.

BOGUES

Voir le système de suivi des bogues de Debian ⟨URL: http://bugs.debian.org/xvfb ⟩. Si vous souhaitez signaler un bogue dans xvfb-run, utilisez la commande reportbug(1).
