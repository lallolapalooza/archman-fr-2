NOM

xwdtopnm - convertir un fichier de vidage de fenêtre X11 ou X10 en une image PNM

SYNOPSIS

xwdtopnm [-verbose] [-headerdump] [fichier_xwd]

DESCRIPTION

Ce programme fait partie de Netpbm(1)

xwdtopnm lit un fichier de vidage de fenêtre X11 ou X10 en entrée et produit une image PNM en sortie. Le type de l'image de sortie dépend du fichier d'entrée - s'il est en noir et blanc, la sortie est PBM. S'il est en niveaux de gris, la sortie est PGM. Sinon, c'est PPM. Le programme vous indique le type qu'il écrit.

En utilisant ce programme, vous pouvez convertir tout ce que vous pouvez afficher sur l'écran d'un poste de travail X en une image PNM. Affichez simplement ce qui vous intéresse, exécutez le programme xwd pour capturer le contenu de la fenêtre, traitez-le avec xwdtopnm, puis utilisez pamcut pour sélectionner la partie que vous voulez.

Notez qu'une image XWD pseudo-couleur (typiquement ce que vous obtenez lorsque vous créez un vidage d'une fenêtre X pseudo-couleur) a une valeur maximale de 65535, ce qui signifie que le fichier PNM que xwdtopnm génère a une valeur maximale de 65535. De nombreux anciens programmes de traitement d'images (qui ne font pas partie du paquet Netpbm et n'utilisent pas la bibliothèque de programmation Netpbm) ne savent pas comment gérer une image PNM dont la valeur maximale est supérieure à 255 (car il y a deux octets au lieu d'un pour chaque échantillon de l'image). Vous pourriez donc vouloir traiter la sortie de xwdtopnm avec pamdepth avant de la transmettre à l'un de ces anciens programmes.

xwdtopnm ne peut pas convertir tous les types d'images XWD (ce qui signifie essentiellement qu'il ne peut pas convertir un XWD créé à partir de tous les types de configurations d'affichage X). En particulier, il ne peut pas convertir une image avec plus de 24 bits par pixel.

OPTIONS

-verbose
Cette option provoque l'affichage par xwdtopnm d'informations utiles sur l'image d'entrée et le processus de conversion.
-headerdump
Cette option provoque l'affichage par xwdtopnm du contenu de l'en-tête X11. Elle n'a aucun effet lorsque l'entrée est X10. Cette option est nouvelle dans Netpbm 10.26 (décembre 2004).

NOTES

Échantillons sur deux octets

xwdtopnm produit parfois une sortie avec une valeur maximale supérieure à 255, ce qui signifie que la valeur maximale d'un échantillon (une valeur d'intensité, par exemple le composant rouge d'un pixel) est supérieure à 255 et que chaque échantillon prend donc 2 octets pour être représenté. Cela peut poser problème car certains programmes attendent ces octets dans un ordre différent de celui spécifié par les spécifications du format Netpbm, ce que produit xwdtopnm, ce qui signifie qu'ils verront des couleurs totalement différentes de celles attendues. xv est un programme de ce type.

Si cela pose problème (par exemple, vous voulez regarder la sortie de xwdtopnm avec xv), il existe deux façons de résoudre ce problème :

  • Traitez la sortie avec pamendian pour produire le format attendu par le programme.
  • Traitez la sortie avec pamdepth pour réduire la valeur maximale en dessous de 256 afin qu'il n'y ait qu'un octet par échantillon.

Souvent, il n'y a aucune bonne raison d'avoir une valeur maximale supérieure à 255. Cela se produit parce que dans XWD, pas en PNM, chaque composante de couleur d'un pixel peut avoir une résolution différente, par exemple 5 bits pour le bleu (valeur maximale 31), 5 bits pour le rouge (valeur maximale 31), et 6 bits pour le vert (valeur maximale 63), pour un total de 16 bits par pixel. Afin de reproduire les couleurs aussi fidèlement que possible, xwdtopnm doit utiliser une grande valeur maximale. Dans cet exemple, il utiliserait 31 * 63 = 1953, et utiliserait 48 bits par pixel.

Comme il s'agit d'un problème courant et frustrant lors de l'utilisation de xwdtopnm, le programme émet un avertissement chaque fois qu'il génère une sortie avec des échantillons sur deux octets. Vous pouvez masquer cet avertissement avec l'option commune -quiet. L'avertissement est nouveau dans Netpbm 10.46 (mars 2009).
