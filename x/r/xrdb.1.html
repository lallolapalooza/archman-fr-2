XRDB(1) Manuel des commandes générales XRDB(1)

NOM

xrdb — utilitaire de base de données de ressources X

SYNTAXE

xrdb [-option ...] [fichier]

DESCRIPTION

Xrdb est utilisé pour obtenir ou définir le contenu de la propriété RESOURCE_MANAGER sur la fenêtre racine de l'écran 0, ou la propriété SCREEN_RESOURCES sur la fenêtre racine de tout ou partie des écrans, ou tout combiné. Normalement, vous exécuteriez ce programme depuis votre fichier de démarrage X.

La plupart des clients X utilisent les propriétés RESOURCE_MANAGER et SCREEN_RESOURCES pour obtenir les préférences de l'utilisateur concernant les couleurs, les polices, etc., pour les applications. Avoir ces informations dans le serveur (où elles sont disponibles pour tous les clients) au lieu du disque, résout le problème des versions précédentes de X qui exigeaient de maintenir des fichiers defaults sur chaque machine que vous pourriez utiliser. Cela permet également de changer dynamiquement les valeurs par défaut sans éditer de fichiers.

La propriété RESOURCE_MANAGER est utilisée pour les ressources qui s'appliquent à tous les écrans de la connexion. La propriété SCREEN_RESOURCES sur chaque écran spécifie des ressources supplémentaires (ou qui remplacent) à utiliser pour cet écran. (Lorsqu'il n'y a qu'un seul écran, SCREEN_RESOURCES n'est normalement pas utilisé, toutes les ressources sont simplement placées dans la propriété RESOURCE_MANAGER.)

Le fichier spécifié par fichier (ou le contenu de l'entrée standard si - ou aucun fichier n'est donné) est éventuellement passé à travers le préprocesseur C avec les symboles suivants définis, basés sur les capacités du serveur utilisé :

SERVERHOST=nom_hôte
la partie nom d'hôte de la connexion à laquelle vous êtes connecté.
SRVR_nom
le nom d'hôte SERVERHOST transformé en identifiant légal. Par exemple, "mon-dpy.lcs.mit.edu" devient SRVR_mon_dpy_lcs_mit_edu.
HOST=nom_hôte
identique à SERVERHOST.
DISPLAY_NUM=numéro
le numéro de la connexion sur l'hôte serveur.
CLIENTHOST=nom_hôte
le nom de l'hôte sur lequel xrdb s'exécute.
CLNT_nom
le nom d'hôte CLIENTHOST transformé en identifiant légal. Par exemple, "expo.lcs.mit.edu" devient CLNT_expo_lcs_mit_edu.
RELEASE=numéro
le numéro de version du vendeur pour le serveur. L'interprétation de ce numéro variera en fonction de VENDOR.
REVISION=numéro
la version mineure du protocole X prise en charge par ce serveur (actuellement 0).
VERSION=numéro
la version majeure du protocole X prise en charge par ce serveur (devrait toujours être 11).
VENDOR="vendeur"
une chaîne littérale spécifiant le vendeur du serveur.
VNDR_nom
le nom de VENDOR transformé en identifiant légal. Par exemple, "MIT X Consortium" devient VNDR_MIT_X_Consortium.
EXT_nom
Un symbole est défini pour chaque extension de protocole prise en charge par le serveur. Chaque nom de chaîne d'extension est transformé en identifiant légal. Par exemple, "X3D-PEX" devient EXT_X3D_PEX.
NUM_SCREENS=numéro
le nombre total d'écrans.
SCREEN_NUM=numéro
le numéro de l'écran actuel (à partir de zéro).
BITS_PER_RGB=numéro
le nombre de bits significatifs dans une spécification de couleur RVB. C'est le logarithme en base 2 du nombre de nuances distinctes de chaque primaire que le matériel peut générer. Notez qu'il n'est généralement pas lié aux PLANES.
CLASS=classe_visuelle
une parmi StaticGray, GrayScale, StaticColor, PseudoColor, TrueColor, DirectColor. C'est la classe visuelle de la fenêtre racine.
CLASS_classe_visuelle=id_visuel
la classe visuelle de la fenêtre racine sous une forme sur laquelle vous pouvez faire un #ifdef. La valeur est l'identifiant numérique du visuel.
COLOR
défini uniquement si CLASS est l'une de StaticColor, PseudoColor, TrueColor, ou DirectColor.
CLASS_classe_visuelle_profondeur=numéro
Un symbole est défini pour chaque visuel pris en charge pour l'écran. Le symbole inclut la classe du visuel et sa profondeur ; la valeur est l'identifiant numérique du visuel. (Si plus d'un visuel a la même classe et la même profondeur, l'identifiant numérique du premier rapporté par le serveur est utilisé.)
HEIGHT=numéro
la hauteur de la fenêtre racine en pixels.
WIDTH=numéro
la largeur de la fenêtre racine en pixels.
PLANES=numéro
le nombre de plans de bits (la profondeur) de la fenêtre racine.
X_RESOLUTION=numéro
la résolution X de l'écran en pixels par mètre.
Y_RESOLUTION=numéro
la résolution Y de l'écran en pixels par mètre.

Les identifiants SRVR_nom, CLNT_nom, VNDR_nom, et EXT_nom sont formés en remplaçant tous les caractères autres que les lettres et les chiffres par des tirets bas (_).

Les lignes commençant par un point d'exclamation (!) sont ignorées et peuvent être utilisées comme commentaires.

Notez que comme xrdb peut lire depuis l'entrée standard, il peut être utilisé pour modifier directement le contenu des propriétés depuis un terminal ou un script shell.

OPTIONS

Le programme xrdb accepte les options suivantes :

-help
Cette option (ou toute option non supportée) provoquera l'affichage d'une brève description des options et paramètres autorisés.
-version
Cette option affichera la version de xrdb et le programme se terminera sans effectuer d'autres opérations.
-display connexion
Cette option spécifie le serveur X à utiliser ; voir X(7). Elle spécifie également l'écran à utiliser pour l'option -screen, et elle spécifie l'écran à partir duquel les symboles du préprocesseur sont dérivés pour l'option -global.
-all
Cette option indique que l'opération doit être effectuée sur la propriété de ressource indépendante de l'écran (RESOURCE_MANAGER), ainsi que sur la propriété spécifique à l'écran (SCREEN_RESOURCES) de chaque écran de la connexion. Par exemple, lorsqu'elle est utilisée conjointement avec -query, le contenu de toutes les propriétés est affiché. Pour -load, -override et -merge, le fichier d'entrée est traité une fois pour chaque écran. Les ressources qui apparaissent en commun dans la sortie de chaque écran sont collectées, et celles-ci sont appliquées comme ressources indépendantes de l'écran. Les ressources restantes sont appliquées pour chaque propriété individuelle par écran. C'est le mode de fonctionnement par défaut.
-global
Cette option indique que l'opération doit uniquement être effectuée sur la propriété indépendante de l'écran RESOURCE_MANAGER.
-screen
Cette option indique que l'opération doit uniquement être effectuée sur la propriété SCREEN_RESOURCES de l'écran par défaut de la connexion.

Cette option indique que l'opération doit être effectuée sur la propriété SCREEN_RESOURCES de chaque écran de la connexion. Pour -load, -override et -merge, le fichier d'entrée

xrdb 1.2.2

NOM

xrdb - base de données des ressources X

SYNTAXE

xrdb [-option ...] [filename]

DESCRIPTION

xrdb est un utilitaire pour lire les fichiers de ressources et les charger dans la base de données des ressources du serveur X. Cela permet aux applications d'accéder aux valeurs par défaut qui leur sont associées. Si filename n'est pas spécifié, l'entrée standard est utilisée. Si le fichier spécifié est un tiret, l'entrée standard est utilisée.

Les ressources peuvent être chargées dans la base de données du serveur, remplacées par de nouvelles valeurs, fusionnées, supprimées ou éditées dans un fichier.

Au démarrage, de nombreux gestionnaires de fenêtres et de sessions exécutent xrdb avec le fichier ~/.Xresources pour initialiser la base de données des ressources, remplaçant ainsi les fichiers ~/.Xdefaults.

Les ressources sont organisées hiérarchiquement. Par exemple, une ressource widget.resourceName est une sous-ressource de widget. Cette structure hiérarchique est utilisée pour organiser les valeurs par défaut des applications.

Le format des fichiers de ressources est similaire au langage C. Il prend en charge les commentaires (/* ... */), les directives de préprocesseur (#include, #define, #ifdef, etc.) et les assignations simples de la forme
nomDeRessource: valeur.

L'option -edit permet d'éditer les ressources dans un fichier spécifié, tout en préservant les commentaires et les lignes de préprocesseur.

OPTIONS

-load
Indique que l'entrée doit être chargée comme nouvelle valeur des propriétés spécifiées, remplaçant tout ce qui s'y trouvait (c'est-à-dire que le contenu précédent est supprimé). C'est l'action par défaut.
-override
Indique que l'entrée doit être ajoutée, au lieu de remplacer, au contenu actuel des propriétés spécifiées. Les nouvelles entrées remplacent les entrées précédentes.
-merge
Indique que l'entrée doit être fusionnée et triée lexicographiquement avec le contenu actuel des propriétés spécifiées, au lieu de le remplacer.
-remove
Indique que les propriétés spécifiées doivent être supprimées du serveur.
-edit nomDeFichier
Indique que le contenu des propriétés spécifiées doit être édité dans le fichier donné, remplaçant les valeurs déjà listées. Cela permet de remettre les modifications apportées à vos valeurs par défaut dans votre fichier de ressources, en préservant les commentaires ou les lignes de préprocesseur.
-backup chaîne
Spécifie un suffixe à ajouter au nom de fichier utilisé avec -edit pour générer un fichier de sauvegarde.
-n
Cette option indique que les modifications apportées aux propriétés spécifiées (lorsqu'elle est utilisée avec -load, -override ou -merge) ou au fichier de ressources (lorsqu'elle est utilisée avec -edit) doivent être affichées sur la sortie standard, mais ne doivent pas être effectuées.
-quiet
Indique que les avertissements concernant les entrées dupliquées ne doivent pas être affichés.
-cpp nomDeFichier
Spécifie le chemin d'accès au programme de préprocesseur C à utiliser. Bien que xrdb ait été conçu pour utiliser CPP, tout programme agissant comme un filtre et acceptant les options -D, -I et -U peut être utilisé.
-nocpp
Indique que xrdb ne doit pas exécuter le fichier d'entrée via un préprocesseur avant de le charger dans les propriétés.
-undef
Cette option est passée au préprocesseur C s'il est utilisé. Elle l'empêche de prédéfinir des macros spécifiques au système.
-E
Indique que toute commande cpp exécutée et sa sortie doivent être affichées sur la sortie standard. Si -nocpp a également été spécifié, le fichier d'entrée sera affiché tel quel. Les modifications spécifiées seront également effectuées, sauf si l'option -n est également spécifiée.
-symbols
Indique que les symboles définis pour le préprocesseur doivent être imprimés sur la sortie standard.
-query
Indique que le contenu actuel des propriétés spécifiées doit être imprimé sur la sortie standard. Notez que comme les commandes de préprocesseur dans le fichier de ressources d'entrée font partie du fichier d'entrée, et non de la propriété, elles n'apparaîtront pas dans la sortie de cette option. L'option -edit peut être utilisée pour fusionner le contenu des propriétés dans le fichier de ressources d'entrée sans endommager les commandes de préprocesseur.
-get nom
Indique que le contenu actuel de la propriété correspondant à nom doit être imprimé sur la sortie standard.
-Dnom[=valeur]
Cette option est transmise au préprocesseur et est utilisée pour définir des symboles à utiliser avec des conditionnelles telles que #ifdef.
-Unom
Cette option est transmise au préprocesseur et est utilisée pour supprimer toutes les définitions de ce symbole.
-Irépertoire
Cette option est transmise au préprocesseur et est utilisée pour spécifier un répertoire où rechercher les fichiers référencés avec #include.

FICHIERS

Xrdb ne charge aucun fichier par lui-même, mais de nombreux environnements de bureau utilisent xrdb pour charger les fichiers ~/.Xresources au démarrage de la session afin d'initialiser la base de données des ressources, en remplacement généralisé des fichiers ~/.Xdefaults.

VOIR AUSSI

X(7), appres(1), listres(1), documentation du Resource Manager de Xlib, documentation des ressources Xt

ENVIRONNEMENT

DISPLAY
pour déterminer quel écran utiliser.

BOGUES

Par défaut, l'absence d'arguments devrait interroger, et non écraser, afin d'être cohérent avec les autres programmes.
