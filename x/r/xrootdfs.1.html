NOM

xrootdfs - démon de système de fichiers FUSE de xrootd

SYNTAXE

xrootdfs [options] paramètres

DESCRIPTION

Le démon xrootdfs fournit une vue de système de fichiers d'un cluster xrootd en utilisant FUSE. La syntaxe d'utilisation peut être affichée en tapant "xrootdfs -h". Une documentation courte se trouve dans un fichier README dans le répertoire src/XrdFfs du code source.

EXEMPLES

En supposant que le redirecteur est rdr:port

exécuter depuis la ligne de commande avec sortie de débogage

xrootdfs -d -o rdr=root://rdr:port//data,uid=daemon /mnt

utiliser dans /etc/fstab

xrootdfs /mnt fuse rdr=root://rdr:port//data,uid=daemon 1 2

utiliser avec autofs

1. ajouter une ligne à /etc/auto.master
/- /etc/auto.fuse

2. créer /etc/auto.fuse avec la ligne suivante
/mnt -fstype=fuse,uid=2,rdr=root://rdr\:port//data :xrootdfs.sh

3. créer le script /usr/bin/xrootdfs.sh (s'assurer que le bit +x est défini)
#!/bin/sh
exec /usr/bin/xrootdfs $@ >/dev/null 2>&1

NOTES

La documentation pour tous les composants associés à xrootdfs se trouve sur https://xrootd.org/docs.html

xrootdfs permet aux utilisateurs et aux administrateurs de interroger et modifier les paramètres internes à la volée via les attributs étendus du système de fichiers

getfattr -n attribute_name /mount_point
setfattr -n attribute_name [ -v value ] /mount_point

attribute_name:

xroot.url: interroger l'URL ROOT réelle du fichier (c'est une ancienne)
xrootdfs.fs.nworkers: interroger ou modifier le nombre de threads travaillant en parallèle sur des opérations telles que stat(), unlink()/rmdir(), readdir(), statvfs(), etc.
xrootdfs.fs.dataserverlist: interroger ou actualiser la liste de tous les serveurs de données connus de cette instance xrootdfs (ou "kill -USR1 pid" pour actualiser)

SÉCURITÉ

Par défaut, XrootdFS n'envoie pas l'identité de l'utilisateur individuel aux serveurs de stockage Xrootd. Ainsi, le stockage Xrootd pense que toutes les opérations provenant d'une instance XrootdFS proviennent de l'utilisateur qui exécute l'instance XrootdFS. Lorsque le module de sécurité Xrootd "sss" (Simple Shared Security) est activé à la fois sur XrootdFS et sur le système de stockage Xrootd, XrootdFS enverra des informations d'identité d'utilisateur individuelles aux serveurs de stockage Xrootd. Ces informations peuvent être utilisées avec l'ACL Xrootd pour contrôler l'accès aux fichiers/répertoires.

Pour utiliser le module de sécurité "sss", les serveurs de données Xrootd et XrootdFS doivent être configurés pour utiliser "sss" d'une manière particulière, par exemple, les deux côtés doivent utiliser un fichier de clé contenant la même clé générée par le programme xrdsssadmin de la manière suivante :

xrdsssadmin -k my_key_name -u anybody -g usrgroup add keyfile

(ne modifiez que "my_key_name" et "keyfile"). Veuillez vous référer à la variable d'environnement "XrdSecsssKT" dans la "Référence de configuration de l'authentification et du contrôle d'accès" de Xrootd pour plus d'informations sur l'emplacement du fichier de clé et ses bits de permission Unix. Ce même document décrit également le fichier de base de données ACL Xrootd.

Pour activer "sss" avec XrootdFS, utilisez l'option sss=/keyfile avec XrootdFS.

L'exemple suivant montre comment utiliser les modules de sécurité unix et sss avec les serveurs de données Xrootd.


xrootd.seclib /usr/lib64/libXrdSec.so
sec.protocol /usr/lib64 sss -s /keyfile
sec.protocol /usr/lib64 unix
acc.authdb /votre_fichier_acl_xrootd_auth_db
acc.authrefresh 300
ofs.authorize

DIAGNOSTICS

Les erreurs génèrent un message d'erreur et un statut de sortie non nul. Le programme ne se termine jamais en cas de succès. Utilisez la commande umount pour terminer le programme.

Des informations de journalisation supplémentaires peuvent être trouvées dans syslog (/var/log/messages)
