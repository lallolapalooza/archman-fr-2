xrdcp(1) Manuel des commandes générales xrdcp(1)

NOM

xrdcp - copie des fichiers

SYNTAXE

xrdcp [options] source destination
options: [--cksum args] [--debug lvl]
[--coerce] [--force] [--help] [--license]
[--nopbar] [--posc] [--proxy ipaddr:port]
[--recursive] [--retry time] [--server]
[--silent] [--sources num] [--streams num]
[--tpc [delegate] first|only] [--verbose]
[--version] [--xrate rate] [--zip file]
[--dynamic-src] [--infiles fn]
[--parallel n] [--allow-http] [--xattr]
[--notlsok] [--tlsnodata] [--tlsmetalink]
[--zip-mtln-cksum] [--rm-bad-cksum] [--continue]
[--xrate-threshold] [--retry-policy]
legacy options: [-adler] [-DSparm string] [-DIparm number]
[-md5] [-np] [-ODcgi] [-OScgi] [-x]

DESCRIPTION

L'utilitaire xrdcp copie un ou plusieurs fichiers d'un emplacement à un autre. La source et la destination des données peuvent être un fichier ou un répertoire local ou distant. De plus, la source des données peut également résider sur plusieurs serveurs.

OPTIONS

-C | --cksum type[:valeur|print|source]

obtient la somme de contrôle de type (c'est-à-dire adler32, crc32, md5 ou zcrc32) à partir de la source, calcule la somme de contrôle à la destination et vérifie qu'elles sont identiques. Si auto est choisi comme type de somme de contrôle, xrdcp essaiera d'inférer automatiquement le bon type de somme de contrôle en fonction de la configuration source/destination, du type de fichier source (metalink, ZIP) et des plugins de somme de contrôle disponibles. Si une valeur est spécifiée, elle est utilisée comme somme de contrôle source. Lorsque print est spécifié, la somme de contrôle à la destination est affichée mais n'est pas vérifiée.
-d | --debug lvl
niveau de débogage : 1 (faible), 2 (moyen), 3 (élevé)
-F | --coerce
ignore les sémantiques de verrouillage sur le fichier de destination. Cette option peut entraîner la corruption du fichier si elle n'est pas utilisée correctement.
-f | --force
recrée un fichier s'il est déjà présent.
-h | --help
affiche les informations d'utilisation.
-H | --license
affiche les termes et conditions de la licence.
-N | --nopbar
n'affiche pas la barre de progression.
-P | --posc
demande un traitement POSC (persist-on-successful-close) pour créer un nouveau fichier. Les fichiers sont automatiquement supprimés s'ils ne sont pas fermés avec succès.
-D | --proxy proxyaddr:proxyport
[PAS ENCORE IMPLÉMENTÉ]

utilise proxyaddr:proxyport comme proxy SOCKS4. Seules les adresses numériques sont prises en charge.

-r | --recursive
copie récursivement tous les fichiers à partir du répertoire source donné.
--retry
réessaye les tâches de copie échouées.
--server
s'exécute comme dans un environnement serveur. Utilisé uniquement pour le support de copie tierce côté serveur.
-s | --silent
ne produit ni informations récapitulatives ni barre de progression.
-y | --sources num
utilise jusqu'à num sources pour copier le fichier.
-S | --streams num
utilise num flux de données parallèles pour effectuer le transfert (le flux principal n'est pas utilisé dans ce cas pour effectuer le transfert). La valeur maximale est de 15. La valeur par défaut est 0 (c'est-à-dire, utiliser uniquement le flux de contrôle).
--tpc [delegate] first|only
copie le fichier d'un serveur distant à un serveur distant en utilisant le protocole de copie tierce (c'est-à-dire, les données circulent de serveur à serveur). Les serveurs source et destination doivent prendre en charge les copies tierces. Des restrictions de sécurité supplémentaires peuvent s'appliquer et provoquer l'échec de la copie si elles ne peuvent pas être satisfaites. L'argument 'first' essaie le tpc et si cela échoue, effectue une copie normale ; tandis que 'only' fait échouer la copie sauf si le tpc réussit. Lorsque 'delegate' est spécifié, la copie délègue les identifiants de l'émetteur de la commande au serveur cible qui utilise ces identifiants pour s'authentifier auprès du serveur source. La délégation est ignorée si le serveur cible n'est pas configuré pour utiliser des identifiants délégués. Actuellement, seuls les identifiants gsi peuvent être délégués.
-v | --verbose
affiche un résumé.
-V | -version
affiche les informations de version et quitte immédiatement.
-z | --zip file
copie le fichier donné à partir d'une archive ZIP (équivalent aux informations opaques de xrdcl.unzip).
-X | --xrate rate
limite la vitesse de copie au taux spécifié. Le taux peut être qualifié par la lettre k, m, ou g pour indiquer des kilo, méga ou giga octets, respectivement. L'option ne s'applique que lorsque la source ou la destination est locale.
-X | --xrate-threshold rate
Si le taux de transfert descend en dessous du seuil donné, force le client à utiliser une source différente ou, si aucune autre source n'est disponible, fait échouer le transfert.
-Z | --dynamic-src
la taille du fichier peut changer pendant la copie
-I | --infiles fn
spécifie le fichier qui contient une liste de fichiers d'entrée
--parallel n
nombre de tâches de copie à exécuter simultanément
--allow-http
autorise HTTP comme protocole source ou destination. Nécessite le plugin client XrdClHttp
--xattr
préserve les attributs étendus
--notlsok
Si le serveur est trop ancien pour prendre en charge le chiffrement TLS, revenir à une communication non chiffrée.
--tlsnodata
Dans le cas des protocoles roots/xroots, chiffrer uniquement le flux de contrôle et laisser les flux de données non chiffrés.
--tlsmetalink
Traite toutes les URL dans metalink comme des roots/xroots.
--zip-mtln-cksum
Utilise la somme de contrôle disponible dans un fichier metalink même si un fichier est extrait d'une archive ZIP.
--rm-bad-cksum
Supprime le fichier cible si la vérification de la somme de contrôle a échoué (active également la sémantique POSC).
--continue
Continue la copie d'un fichier à partir du point où la copie précédente a été interrompue.

OPTIONS LEGACY

Les options legacy sont fournies pour la compatibilité descendante. Elles sont maintenant dépréciées et devraient être évitées.
-adler

équivalent à "--cksum adler32:source".
-DIpname numberval
définit le paramètre interne pname avec la valeur numérique numberval.
-DSpname stringval
définit le paramètre interne pname avec la valeur chaîne stringval.
-md5
équivalent à "--cksum md5:source".
-np
équivalent à "--nopbar".
-ODcgi
ajoute les informations cgi cgi à toute URL xrootd de destination. Vous devez spécifier les informations opaques directement sur l'URL de destination.
-OScgi
ajoute les informations cgi cgi à toute URL xrootd source.
-x
équivalent à "--sources 12".

OPÉRANDES

source

un tiret (c'est-à-dire -) indiquant l'entrée standard, un fichier local, un nom de répertoire local se terminant par /, ou une URL xrootd sous la forme
xroot://[user@]host[:port]/cheminabsolu
Le cheminabsolu peut être un répertoire.
destination
un tiret (c'est-à-dire -) indiquant la sortie standard, un fichier local, un nom de répertoire local se terminant par /, ou une URL xrootd sous la forme
xroot://[user@]host[:port]/cheminabsolu
Le cheminabsolu peut être un répertoire.

s et toute autre application utilisant la bibliothèque libXrdCl, sauf indication contraire. Le texte entre crochets est le nom du paramètre de ligne de commande correspondant à xrdcp.

XRD_LOGLEVEL

Détermine la quantité de diagnostics qui doivent être imprimés. Les valeurs valides sont : Dump, Debug, Info, Warning et Error.

XRD_LOGFILE

Si défini, les diagnostics seront imprimés dans le fichier spécifié au lieu de stderr.

XRD_LOGMASK

Détermine quels sujets de diagnostic doivent être imprimés à tous les niveaux. C'est une liste de sujets séparés par "|". Le premier élément peut être "All" auquel cas tous les sujets sont activés et les éléments suivants peuvent les désactiver, ou "None" auquel cas tous les sujets sont désactivés et les indicateurs suivants peuvent les activer. Si le nom du sujet est préfixé par "^", cela signifie que le sujet doit être désactivé. Si le nom du sujet n'est pas préfixé, cela signifie que le sujet doit être activé.

Le masque de journalisation peut également être géré pour chaque niveau de diagnostic séparément en définissant une ou plusieurs des variables suivantes : XRD_LOGMASK_ERROR, XRD_LOGMASK_WARNING, XRD_LOGMASK_INFO, XRD_LOGMASK_DEBUG et XRD_LOGMASK_DUMP. La valeur par défaut pour chaque niveau est "All", à l'exception du niveau Dump, dont la valeur par défaut est "All|^PollerMsg". Cela signifie qu'au niveau Dump, tous les sujets sauf "PollerMsg" sont activés.

Sujets disponibles : AppMsg, UtilityMsg, FileMsg, PollerMsg, PostMasterMsg, XRootDTransportMsg, TaskMgrMsg, XRootDMsg, FileSystemMsg, AsyncSockMsg, TlsMsg

XRD_TLSDBGLVL

Détermine le niveau de débogage pour le composant TLS. Les valeurs valides sont : OFF, CTX, SOK, SIO, ALL et OUT. La valeur par défaut est OFF.

XRD_PARALLELEVTLOOP

Le nombre de boucles d'événements (c'est-à-dire le nombre de threads gérant les requêtes). Le nombre par défaut est 10.

XRD_READRECOVERY

Détermine si la récupération en lecture doit être activée ou désactivée (activée par défaut).

XRD_WRITERECOVERY

Détermine si la récupération en écriture doit être activée ou désactivée (activée par défaut).

XRD_OPENRECOVERY

Détermine si la récupération à l'ouverture doit être activée ou désactivée pour les ouvertures modifiables (tronquer ou créer) (activée par défaut).

XRD_CONNECTIONWINDOW (-DIConnectionWindow)

Une fenêtre temporelle pour l'établissement de la connexion. Un échec de connexion est déclaré si la connexion n'est pas établie dans la fenêtre temporelle. Si un échec de connexion se produit plus tôt, une autre tentative de connexion ne sera effectuée qu'au début de la fenêtre suivante.

XRD_CONNECTIONRETRY (-DIConnectionRetry)

Nombre de tentatives de connexion qui doivent être effectuées (nombre de fenêtres de connexion disponibles) avant de déclarer un échec permanent.

XRD_REQUESTTIMEOUT (-DIRequestTimeout)

Valeur par défaut du temps après lequel une erreur est déclarée s'il était impossible d'obtenir une réponse à une requête.

XRD_STREAMTIMEOUT (-DIStreamTimeout)

Valeur par défaut du temps après lequel une erreur de connexion est déclarée (et une récupération tentée) s'il y a des requêtes non satisfaites et qu'il n'y a pas d'activité socket ou de délai d'attente d'attente enregistré.

XRD_SUBSTREAMSPERCHANNEL (-DISubStreamsPerChannel)

Nombre de flux par session.

XRD_TIMEOUTRESOLUTION (-DITimeoutResolution)

Résolution des événements de délai d'attente. Par exemple, les événements de délai d'attente ne seront traités que toutes les secondes de XRD_TIMEOUTRESOLUTION.

XRD_STREAMERRORWINDOW (-DIStreamErrorWindow)

Temps après lequel les indicateurs d'échec permanent sont effacés et une nouvelle connexion peut être tentée si nécessaire.

XRD_RUNFORKHANDLER (-DIRunForkHandler)

Détermine si les gestionnaires de fork doivent être activés, rendant l'API sûre pour le fork.

XRD_REDIRECTLIMIT (-DIRedirectLimit)

Nombre maximum de redirections autorisées.

XRD_NOTAUTHORIZEDRETRYLIMIT (-dNotAuthorizedRetryLimit)

Nombre maximum de nouvelles tentatives autorisées auprès d'un métagérent pour une erreur non autorisée.

XRD_POLLERPREFERENCE (-DSPollerPreference)

Une liste d'implémentations de poller séparées par des virgules, par ordre de préférence. La valeur par défaut est : intégrée.

XRD_CLIENTMONITOR (-DSClientMonitor)

Chemin d'accès à la bibliothèque de surveillance client.

XRD_CLIENTMONITORPARAM (-DSClientMonitorParam)

Paramètres optionnels supplémentaires qui seront passés à l'objet de surveillance lors de l'initialisation.

XRD_WORKERTHREADS (-DIWorkerThreads)

Nombre de threads traitant les rappels utilisateur.

XRD_CPPARALLELCHUNKS (-DICPParallelChunks)

Nombre maximum de requêtes asynchrones traitées par la commande xrdcp par sous-flux de canal connecté (ajusté en temps réel).

XRD_CPCHUNKSIZE (-DICPChunkSize)

Taille d'un bloc de données unique géré par xrdcp.

XRD_NETWORKSTACK (-DSNetworkStack)

La pile réseau que le client doit utiliser pour se connecter au serveur. Les valeurs possibles sont :

IPAuto - détecter automatiquement la pile IP à utiliser

IPAll - utiliser la pile IPv6 (sockets AF_INET6) et les adresses IPv6 et IPv4 (mappées en IPv6)

IPv6 - utiliser uniquement la pile et les adresses IPv6

IPv4 - utiliser uniquement la pile et les adresses IPv4 (sockets AF_INET)

IPv4Mapped6 - utiliser la pile IPv6 et les adresses IPv4 mappées

XRD_DATASERVERTTL (-DIDataServerTTL)

Période après laquelle une connexion inactive à un serveur de données doit être fermée.

XRD_LOADBALANCERTTL (-DILoadBalancerTTL)

Période après laquelle une connexion inactive à un gestionnaire ou à un répartiteur de charge doit être fermée.

XRD_APPNAME (-DSAppName)

Remplace le nom de l'application signalé au serveur.

XRD_PLUGINCONFDIR

Un emplacement personnalisé contenant les fichiers de configuration des plugins client.

XRD_PLUGIN

Un plugin client par défaut à utiliser.

XRD_CPINITTIMEOUT (-DICPInitTimeout)

Temps maximum autorisé pour l'initialisation du processus de copie, c'est-à-dire l'ouverture des fichiers source et destination.

XRD_CPTPCTIMEOUT (-DICPTPCTimeout)

Temps maximum autorisé pour qu'une opération de copie tierce se termine.

XRD_TCPKEEPALIVE (-DITCPKeepAlive)

Active/désactive la fonctionnalité TCP keep alive.

XRD_TCPKEEPALIVETIME (-DITCPKeepAliveTime)

Temps entre le dernier paquet de données envoyé et la première sonde keepalive (Linux uniquement).

XRD_TCPKEEPALIVEINTERVAL (-DITCPKeepAliveInterval)

Intervalle entre les sondes keepalive successives (Linux uniquement).

XRD_TCPKEEPALIVEPROBES (-DITCPKeepProbes)

Nombre de sondes non reconnues avant de considérer la connexion comme morte (Linux uniquement).

XRD_METALINKPROCESSING

Active/désactive le traitement Metalink (activé par défaut).

XRD_LOCALMETALINKFILE

Active/désactive le traitement des fichiers Metalink locaux (par convention, le schéma d'URL suivant doit être utilisé : root://localfile//chemin/nom_fichier.meta4) Le sémantique 'localfile' est maintenant déprécié, utilisez plutôt file://localhost/chemin/nom_fichier.meta4 !

XRD_GLFNREDIRECTOR

Le réducteur sera utilisé en dernier recours si la balise GLFN est spécifiée dans un fichier Metalink.

XRD_XCPBLOCKSIZE

Taille maximale d'un bloc de données assigné à une seule source en cas de transfert de copie extrême.

XRD_NODELAY

Désactive l'algorithme de Nagle s'il est défini sur 1 (par défaut), l'active s'il est défini sur 0.

XRD_PREFERIPV4

Si défini, le client essaie d'abord l'adresse IPv4 (désactivé par défaut).

XRD_MAXMETALINKWAIT

Temps maximum en secondes pendant lequel un client peut être bloqué par le serveur si un réducteur Metalink est disponible (par défaut 60s).

XRD_PRESERVELOCATETRIED

Si défini sur 1, le client XRootD conservera les informations opaques cgi tried/triedrc pour la requête kXR_locate lors des redirections/nouvelles tentatives. Si défini sur 0, le client XRootD traitera kXR_locate comme toute autre requête passive.

XRD_PRESERVEXATTRS

Si défini sur 1 (par défaut), xrdcp conservera les attributs étendus du fichier. S'il est défini sur 0, les attributs étendus du fichier ne seront pas conservés.

XRD_NOTLSOK

Si défini sur 1 et que le serveur est trop ancien pour supporter le chiffrement TLS, xrdcp se rabattra sur une transmission non chiffrée bien que le protocole roots/xroots ait été utilisé. Par défaut, défini sur 0.

XRD_TLSNODATA

Si défini sur 1, dans le cas du protocole roots/xroots, seul le flux de contrôle sera chiffré, les flux de données resteront non chiffrés. Par défaut, défini sur 0.

XRD_TLSMETALINK

Si défini sur 1, toutes les URL dans metalink seront traitées comme roots/xroots. Par défaut, défini sur 0.

XRD_ZIPMTLNCKSUM

Si défini sur 1, utilisez la somme de contrôle disponible dans un fichier metalink même si un fichier est extrait d'une archive ZIP. Par défaut, défini sur 0.

XRD_CPTIMEOUT

Délai d'attente pour une copie classique (pas TPC). Par défaut, défini sur 0 (désactivé).

XRD_CLCONFDIR

Répertoire défini par l'utilisateur avec des fichiers de configuration (*.conf).

XRD_CLCONFFILE

Fichier de configuration défini par l'utilisateur.

XRD_CPRETRY

Nombre maximum de tentatives pour les jobs de copie échoués (défaut : 0).

XRD_CPRETRYPOLICY

Politique de nouvelle tentative pour les jobs de copie, soit force, soit retry (défaut : force).

XRD_CPUSEPGWRTRD

Active la correction d'erreurs en ligne des pages corrompues (défaut : 1).

CODES DE RETOUR

50 : erreur générique (par ex. config, interne, données, OS, option de ligne de commande)

51 : erreur liée au socket

52 : erreur liée au postmaster

53 : erreur XRootD

54 : erreur de redirection

55 : la réponse à la requête était négative (ce n'est pas une erreur)

NOTES

La documentation pour tous les composants associés à xrdcp se trouve à l'adresse https://xrootd.org/docs.html

DIAGNOSTICS

Les erreurs génèrent un message d'erreur et un statut de sortie non nul.
