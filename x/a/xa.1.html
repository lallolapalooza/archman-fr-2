XA(1) Manuel des commandes générales XA(1)

NOM

xa - cross-assembleur pour 6502/R65C02/65816

SYNTAXE

xa [OPTION]... FICHIER

DESCRIPTION

xa est un cross-assembleur multi-passes pour les processeurs 8 bits de la série 6502 (tels que le 6502, 65C02, 6504, 6507, 6510, 7501, 8500, 8501 et 8502), le Rockwell R65C02, et le processeur 16 bits 65816. Pour une description de la syntaxe, voir SYNTAXE DE L'ASSEMBLEUR plus loin dans cette page de manuel.

OPTIONS

-E
Ne pas s'arrêter après 20 erreurs, mais montrer toutes les erreurs.
-v
Sortie verbeuse.
-C
Pas d'octets de code CMOS (par défaut, les octets de code R65C02 sont autorisés).
-W
Pas d'octets de code 65816 (par défaut).
-w
Autoriser les octets de code 65816.
-B
Afficher les lignes avec ouverture/fermeture de bloc (voir PSEUDO-OPS).
-c
Produire des fichiers objet o65 au lieu de fichiers exécutables (aucun linking effectué) ; les fichiers peuvent contenir des références non définies.
-o nomfichier
Définir le nom du fichier de sortie. Par défaut, c'est a.o65 ; utiliser le nom de fichier spécial - pour sortir vers la sortie standard.
-P nomfichier
Définir le nom du fichier de liste. Par défaut, il n'y en a pas ; utiliser le nom de fichier spécial - pour imprimer la liste sur la sortie standard.
-F format
Définir le format de la liste ; par défaut, c'est plain. Le seul autre format actuellement supporté est html.
-e nomfichier
Définir le nom du fichier de log d'erreurs ; par défaut, il n'y en a pas.
-l nomfichier
Définir le nom du fichier de liste d'étiquettes ; par défaut, il n'y en a pas. C'est la table des symboles et elle peut être utilisée par des désassembleurs tels que dxa(1) pour reconstruire le code source.
-r
Ajouter une liste de références croisées à la liste d'étiquettes (nécessite -l).
-Xcompatset
Active les paramètres de compatibilité pour être plus (pas entièrement !) compatible avec d'autres assembleurs et bases de code 6502. Actuellement supportés : les ensembles de compatibilité MASM, CA65 et C, avec XA23 disponible comme option dépréciée pour les bases de code s'appuyant sur la compatibilité avec la version précédente de xa. Plusieurs ensembles de compatibilité peuvent être spécifiés et combinés, par exemple, -XMASM -XXA23.
-XMASM autorise les deux-points dans les commentaires pour la compatibilité MASM. Cela n'affecte pas l'interprétation des deux-points ailleurs et pourrait devenir la valeur par défaut dans une version future.
-XCA65 ajoute des fonctionnalités syntaxiques plus compatibles avec ca65(1). Il autorise := pour définir des étiquettes (au lieu de juste =), et ajoute le support des étiquettes sans nom et des étiquettes locales « bon marché » utilisant le caractère @, mais désactive son autre signification pour le mode 24 bits (voir SYNTAXE DE L'ASSEMBLEUR).
-XC active l'utilisation des encodages numériques de style C 0xHEX et 0OCTAL.
-XXA23 restaure une compatibilité partielle avec xa 2.3.x. En particulier, il utilise ^ pour générer des caractères de contrôle, désactive les caractères échappés avec \, autorise les commentaires multi-lignes imbriqués, et désactive toutes les macros prédéfinies du préprocesseur xa. Bien que certaines parties de cette option restent une syntaxe supportée, l'option elle-même est intrinsèquement dépréciée et peut être supprimée dans la prochaine version 2.x ou 3.x.
-a
Supporte les étiquettes sans nom de style ca65(1) utilisant des deux-points, mais pas le reste des autres fonctionnalités supportées par ca65(1). Cela permet leur utilisation avec le mode 65816, par exemple. Implique -XMASM.
-M
Cette option est dépréciée et sera supprimée dans une version future ; utiliser -XMASM à la place. Autorise les deux-points dans les commentaires pour la compatibilité MASM. Cela n'affecte pas l'interprétation des deux-points ailleurs, et pourrait devenir la valeur par défaut dans une version future.
-k
Permet au caratère ^ de masquer un caractère avec $1f/31. Cela peut être utilisé comme raccourci pour les caractères de contrôle, par exemple ^m^j devient un retour chariot suivi d'un saut de ligne.
-R
Démarre l'assembleur en mode relocalisable, c'est-à-dire utilise des segments.
-U
Ne pas autoriser les étiquettes non définies en mode relocalisable.
-Llabel
Définit label comme une étiquette absolue (mais non définie) même lors du linking.
-b? addr
Définit la base du segment pour le segment ? à l'adresse addr. ? doit être t, d, b ou z pour les segments de texte, données, bss ou zéro, respectivement.
-A addr
Fait démarrer le segment de texte à une adresse telle que, lorsque le fichier démarrer à l'adresse addr, la relocalisation ne soit pas nécessaire. Remplace -bt ; les autres segments doivent toujours être gérés avec -b.
-G
Supprimer la liste des globales exportées.
-DDEF=TEXTE
Définit une macro de préprocesseur sur la ligne de commande (voir PRÉPROCESSEUR).
-I dir
Ajoute le répertoire dir au chemin d'inclusion (avant XAINPUT ; voir ENVIRONNEMENT).
-O jeu_car
Définit le jeu de caractères de sortie pour les chaînes de caractères. Actuellement supportés : ASCII (par défaut), PETSCII (codes ASCII Commodore), PETSCREEN (codes écran Commodore) et HIGH (met le bit haut sur tous les caractères).
-p?
Définit le caractère alternatif du préprocesseur à ?. Ceci est utile lorsque vous souhaitez utiliser cpp(1) et le préprocesseur intégré en même temps (voir PRÉPROCESSEUR). Les caractères peuvent devoir être échappés pour votre shell (exemple : -p'~' ).
--help
Afficher un résumé des options (-? est un synonyme).
--version
Afficher la version du programme.

SYNTAXE DE L'ASSEMBLEUR

Une introduction au langage d'assemblage 6502 et à ses mnémoniques dépasse le cadre de cette page de manuel. Nous vous invitons à consulter un nombre quelconque d'excellents livres sur le sujet ; un titre utile est « Machine Language For Beginners » de Richard Mansfield (COMPUTE !), couvrant les systèmes 8 bits Atari, Commodore et Apple, et est largement disponible sur le marché de l'occasion.

xa supporte à la fois les instructions standard du NMOS 6502 et les instructions Rockwell CMOS utilisées dans le 65C02 (R65C02). Avec l'option -w, xa acceptera également les instructions du 65816. Les instructions non documentées du NMOS 6502 ne sont intentionnellement pas supportées, et doivent être saisies manuellement en utilisant le pseudo-op .byte (voir PSEUDO-OPS). En raison de conflits entre les jeux d'instructions du R65C02 et du 65816 et les instructions non documentées du NMOS 6502, leur utilisation est déconseillée.

En général, xa accepte le format d'assembleur 6502 plus ou moins standard popularisé par MASM et TurboAssembler. Les valeurs et adresses peuvent être exprimées soit comme des littéraux, soit comme des expressions ; à savoir,

123
valeur décimale
$234
valeur hexadécimale (0x234 est accepté avec -XC)
&123
octal (0123 est accepté avec -XC)
%010110
binaire
*
valeur actuelle du compteur de programme

La valeur ASCII de tout caractère entre guillemets est insérée directement dans le texte du programme (exemple : "A" insère l'octet « A » dans le flux de sortie) ; voir aussi la section PSEU

DO-OPS

section. Ceci est affecté par l'ensemble de caractères actuellement sélectionné, le cas échéant.

Les labels définissent des emplacements dans le texte du programme, comme dans d'autres assembleurs multi-passes. Un label est défini par tout ce qui n'est pas un opcode ; par exemple, une ligne telle que

label1 lda #0

définit label1 comme l'emplacement actuel du compteur de programme (donc l'adresse de l'opcode LDA). Un label peut être défini explicitement en lui assignant la valeur d'une expression, telle que

label2 = $d000

qui définit label2 comme l'adresse $d000, c'est-à-dire le début du bloc de registres VIC-II sur les ordinateurs Commodore 64. Le compteur de programme * est considéré comme un type spécial de label, et peut être assigné avec des instructions telles que

* = $c000

qui règle le compteur de programme à l'emplacement décimal 49152. Si -XCA65 est spécifié, vous pouvez également utiliser := ainsi que =.

À l'exception du compteur de programme, les labels ne peuvent pas être assignés plusieurs fois. Pour déclarer explicitement la redéfinition d'un label, placez un - (tiret) devant, par exemple,

-label2 = $d020

qui règle label2 sur le registre de couleur de bordure du Commodore 64. La portée d'un label est affectée par le bloc dans lequel il réside (voir PSEUDO-OPS pour les instructions de bloc). Un label peut également être spécifié de manière fixe avec l'option de ligne de commande -L.

La redéfinition d'un label ne modifie pas le code précédemment assemblé qui utilisait la valeur précédente. Par conséquent, comme le compteur de programme est un type spécial de label, modifier le compteur de programme à une valeur inférieure ne réorganise pas le code déjà assemblé et le modifier à une valeur supérieure n'émet pas de remplissage pour placer le code suivant à la nouvelle position. C'est un comportement intentionnel pour faciliter la génération de code déplaçable et indépendant de la position, mais cela peut différer d'autres assembleurs qui utilisent ce comportement pour la liaison. Cependant, il est possible d'utiliser des pseudo-ops pour simuler le comportement d'autres assembleurs et utiliser xa comme lieur ; voir PSEUDO-OPS et LINKING.

Si -XCA65 ou -a est spécifié, des labels « sans nom » peuvent être spécifiés avec : (c'est-à-dire, pas de label, juste un deux-points) ; les sauts peuvent alors faire référence à ces labels sans nom avec un deux-points et des signes plus pour les sauts avant ou des signes moins pour les sauts arrière. Par exemple (de la documentation de ca65(1)),


: lda (ptr1),y ; #1
cmp (ptr2),y
bne :+ ; -> #2
tax
beq :+++ ; -> #4
iny
bne :- ; -> #1
inc ptr1+1
inc ptr2+1
bne :- ; -> #1


: bcs :+ ; #2 -> #3
ldx #$FF
rts


: ldx #$01 ; #3
: rts ; #4

De plus, en mode -XCA65, des labels locaux « bon marché » peuvent être utilisés, marqués par le préfixe @. Ces labels temporaires n'existent qu'entre deux labels réguliers et sortent automatiquement de portée avec le prochain label régulier. Cela permet, avec un soin raisonnable, la réutilisation de noms de labels courants comme « loop ».

Pour les instructions où l'accumulateur est l'argument implicite (comme asl et lsr ; inc et dec sur R65C02 ; etc.), l'idiome consistant à spécifier explicitement l'accumulateur avec a est inutile car la forme correcte sera sélectionnée s'il n'y a pas d'argument explicite. En fait, pour la cohérence avec la gestion des labels, s'il existe un label nommé a, cela générera en fait du code référençant ce label comme une adresse mémoire et non l'accumulateur. Sinon, l'assembleur se plaindra.

Les labels et les opcodes peuvent prendre des expressions comme arguments pour permettre des valeurs calculées, et peuvent eux-mêmes référencer d'autres labels et/ou le compteur de programme. Une expression telle que lab1+1 (qui opère sur la valeur actuelle du label lab1 et l'incrémente de un) peut utiliser les opérandes suivants, classés de la priorité la plus élevée à la plus basse :

*
multiplication (priorité 10)
/
division entière (priorité 10)
+
addition (priorité 9)
-
soustraction (9)
<<
décalage à gauche (8)
>>
décalage à droite (8)
>= =>
supérieur ou égal à (7)
>
supérieur à (7)
<= =<
inférieur ou égal à (7)
<
inférieur à (7)
=
égal à (6) ; == est également accepté
<> ><
différent de (6) ; != est également accepté
&
ET bit à bit (5)
^
XOR bit à bit (4)
|
OU bit à bit (3)
&&
ET logique (2)
||
OU logique (1)

Les parenthèses sont valides. Lors de la redéfinition d'un label, la combinaison d'opérateurs arithmétiques ou bit à bit avec l'opérateur = (égal) telle que += et ainsi de suite est valide, par exemple,

-redeflabel += (label12/4)

Normalement, xa tente de déterminer la valeur de l'opérande et (lorsqu'il fait référence à une adresse mémoire) d'utiliser le mode d'adressage page zéro, 16 bits ou (pour 65816) 24 bits, le cas échéant et là où il est supporté par l'opcode particulier. Cela génère un code plus petit et plus rapide, et est presque toujours préférable.

Néanmoins, vous pouvez utiliser ces opérateurs préfixes pour forcer un rendu particulier de l'opérande. Ceux qui génèrent un résultat de huit bits peuvent également être utilisés dans des modes d'adressage 8 bits, tels que immédiat et page zéro.

<
octet de poids faible de l'expression, par exemple, lda #<vector
>
octet de poids fort de l'expression
!
dans les situations où l'expression pourrait être comprise comme une valeur absolue ou de page zéro, n'essayez pas d'optimiser vers un argument de page zéro pour les opcodes qui le supportent (c'est-à-dire, gardez comme mot de 16 bits)
@
rendre comme quantité de 24 bits pour 65816, même si elle est inférieure à 24 bits (doit spécifier l'option de ligne de commande -w, ne doit pas spécifier -XCA65)
`
forcer une optimisation supplémentaire, même si la longueur de l'instruction ne peut pas être déterminée de manière fiable (voir NOTES'N'BUGS)

Les expressions peuvent apparaître comme arguments d'opcodes ou dans le préprocesseur (voir PREPROCESSOR pour la syntaxe). Par exemple,

lda label2+1

prend la valeur à label2+1 (en utilisant la valeur de notre label précédent, ce serait $d021), et sera assemblé comme $ad $21 $d0 sur disque. De même,

lda #<label2

prendra les 8 bits les plus bas de label2 (c'est-à-dire $20), et les assignera à l'accumulateur (assemblant l'instruction comme $a9 $20 sur disque).

Les commentaires sont spécifiés avec un point-virgule (;), par exemple,

; ceci est un commentaire

Ils peuvent également être spécifiés dans le style du langage C, en utilisant /* */ et // qui sont compris au niveau du PREPROCESSOR (voir ci-après).

Normalement, le deux-points (:) sépare les instructions, par exemple,

label4 lda #0:sta $d020

ou

label2: lda #2

(notez l'utilisation d'un deux-points pour spécifier un label, similaire à certains autres assembleurs, que xa comprend avec ou sans le deux-points). Cela s'applique également aux commentaires point-virgule, de sorte que

; un commentaire:lda #0

est compris comme un commentaire suivi d'un opcode. Pour éviter cela, utilisez le mode de compatibilité -XMASM pour autoriser les deux-points dans les commentaires ; cela pourrait devenir le comportement par défaut dans une future version. La séparation des instructions par des deux-points ne s'applique pas aux commentaires /* */ et //, qui sont traités au niveau du préprocesseur (voir ci-après).

PSEUDO-OPS

Les pseudo-ops sont de faux opcodes utilisés par l'assembleur pour désigner des commandes méta- ou intégrées. Comme la plupart des assembleurs, xa en possède un riche ensemble.

.byt value1,value2,value3,...
Spécifie une séquence d'octets à placer directement dans l'objet assemblé. Les arguments peuvent être des expressions. N'importe quel nombre d'octets peut être spécifié.
.asc "text1" ,"text2",...
Spécifie une chaîne de caractères qui sera insérée dans l'objet assemblé. Les chaînes sont comprises selon l'ensemble de caractères actuellement spécifié ; par exemple, si ASCII est spécifié, elles seront rendues en ASCII, et si PETSCII est spécifié, elles seront traduites dans l'équivalent Commodore ASCII. D'autres ASCII non standard comme ATASCII pour les ordinateurs Atari devraient utiliser les caractères équivalents ASCII ; les caractères graphiques et de contrôle devraient être spécifiés explicitement en utilisant .byt pour le caractère précis que vous souhaitez. Notez que lors de la spécification de l'argument d'un opcode, .asc n'est pas nécessaire ; le caractère entre guillemets peut simplement être inséré (par exemple, lda #"A"), et est également affecté par l'ensemble de caractères actuel. N'importe quel nombre de chaînes de caractères peut être spécifié.

.byt et .asc sont synonymes, vous pouvez donc mélanger des choses comme .byt $43, 22, "une chaîne de caractères" et obtenir le résultat attendu. La chaîne est soumise à l'ensemble de caractères actuel, mais les octets restants sont insérés sans modification.

.aasc "text1" ,"text2",...
Spécifie une chaîne de caractères qui est toujours rendue en vrai ASCII, quel que soit l'ensemble de caractères actuel. Comme .asc, c'est synonyme de .byt.
.word value1,value2,value3...
Spécifie une séquence de mots de 16 bits à placer dans l'objet assemblé au format little-endian 6502 (c'est-à-dire, octet de poids faible/octet de poids fort). Les arguments peuvent être des expressions. N'importe quel nombre de mots peut être spécifié.
.dsb length,fillbyte
Spécifie un bloc de données ; un total de length répétitions de fillbyte seront insérées dans l'objet assemblé. Par exemple, .dsb 5,$10 insérera cinq octets, chacun valant 16 décimal, dans l'objet. Les arguments peuvent être des expressions. Si un seul argument est fourni, alors l'argument est traité comme un nombre d'octets nuls à insérer. Voir LINKING pour savoir comment utiliser ce pseudo-op pour lier plusieurs objets.
.bin offset,length,"filename"
Intègre un fichier binaire sans interprétation supplémentaire

PSEUDO-OPS

.byte expression
Inserts the byte value of expression into the object file. If expression is a string, then the ASCII value of the first character is inserted.
.word expression
Inserts the 16-bit value of expression into the object file. If expression is a string, then the ASCII value of the first character is inserted.
.long expression
Inserts the 32-bit value of expression into the object file. If expression is a string, then the ASCII value of the first character is inserted.
.float expression
Inserts the 32-bit floating point value of expression into the object file. Note that this is IEEE single precision floating point. Only positive values are supported.
.string expression
Inserts the null-terminated string expression into the object file. Note that no explicit length count is inserted.
.asc expression
Inserts the string expression into the object file, but does not null-terminate it. The default string length is used.
.strz expression
Same as .asc, except that the string is null-terminated. This is the default for strings.
.rept expression
Starts a repeat block. The code within the block is repeated expression number of times. The expression must evaluate to a constant.
.endr
Ends a repeat block.
.file filename
This pseudo-op has no effect other than to specify the name of the current file. It is used by the debugger to determine the name of the source file.
.import filename
This pseudo-op inserts the specified file into the object file at the current location, as if the preprocessor had done so with an #include directive (see PREPROCESSOR), but at the assembler phase after preprocessing has already occurred. It also has the side effect of adding the included file's object code to the list of files that are included by the loader.
.opt option
This pseudo-op is used to control the assembler and its output. The following options are recognized:
ALIGN   Align output to a 16-byte boundary.
NOCASE  Make symbol lookup case sensitive. Default is case insensitive.
CASE    Make symbol lookup case insensitive.
NOLIST  Disable listing output.
LIST    Enable listing output.
NOVREF  Disable cross-reference listing.
VREF    Enable cross-reference listing.
NOWARN  Disable warning messages.
WARN    Enable warning messages.
NOCONST Disable constant folding optimization.
CONST   Enable constant folding optimization.
NOWARN  Disable warning messages.
WARN    Enable warning messages.
.offset expression
This pseudo-op sets the current output file offset to expression. This is useful for inserting data into the file at specific locations. The expression may be an absolute value or a value relative to the beginning of the file. The assembler will automatically pad the file with zeros if the offset is greater than the current output position.
.space expression
This pseudo-op inserts expression number of zero bytes into the output file. It is useful for reserving space for data.
.cbm
Sets the assembler to generate code for the Commodore 64. This sets the default operand size to 8 bits, and the default index register size to 8 bits. This is equivalent to issuing .as, .xs, .al, and .xl.
.insert filename offset length
Inserts the contents of the specified filename from offset offset (relative to the beginning of the file) for length bytes. This allows you to insert data such as a previously assembled object file or an image or other binary data structure, inlined directly into this file's object. If length is zero, then the length of filename, minus the offset, is used instead. The arguments may be expressions. See LINKING for how to use this pseudo-op to link multiple objects.
.(
Opens a new block for scoping. Within a block, all labels defined are local to that block and any sub-blocks, and go out of scope as soon as the enclosing block is closed (i.e., lexically scoped). All labels defined outside of the block are still visible within it. To explicitly declare a global label within a block, precede the label with + or precede it with & to declare it within the previous level only (or globally if you are only one level deep). Sixteen levels of scoping are permitted.
.block is accepted as a synonym for .(, as well as .proc (but you cannot specify an explicit scope name as in ca65; only anonymous blocks are supported).
.)
Closes a block. .bend or .endproc are accepted as synonyms.
.as .al .xs .xl
Only relevant in 65816 mode (with the -w option specified). These pseudo-ops set what size accumulator and X/Y-register should be used for future instructions; .as and .xs set 8-bit operands for the accumulator and index registers, respectively, and .al and .xl set 16-bit operands. These pseudo-ops on purpose do not automatically issue sep and rep instructions to set the specified width in the CPU; set the processor bits as you need, or consider constructing a macro. .al and .xl generate errors if -w is not specified.
.assert expression,"message"
Evaluates expression and if it is false (i.e., evaluates to zero), prints message as a fatal error, terminating assembly immediately. For example, a block of assembly code that creates high ROM might have
.assert *<$fffa, "hit vectors"
to ensure that assembled code does not leak into the 6502 high vectors. If the preceding code is too long, the assertion will be false, and the condition will be detected in a controlled fashion. Any operation may be used as part of the expression, including logical comparisons such as =, ==, <, <=, >, >=, != and <>.
.include filename
Includes another file in place of the pseudo-op, as if the preprocessor had done so with an #include directive (see PREPROCESSOR), but at the assembler phase after preprocessing has already occurred.

The following pseudo-op applies to listing mode.

.listbytes number
In the listing output, sets the maximum number of hex bytes to be printed in the listing for pseudo-ops like .byt, by default 8. The special argument unlimited sets no upper limit. If listing mode is disabled, this pseudo-op has no observable effect.

The following pseudo-ops apply primarily to relocatable .o65 objects. A full discussion of the relocatable format is beyond the scope of this manpage; see http://www.6502.org/users/andre/o65/ for the most current specification.

.text .data .bss .zero
These pseudo-ops switch between the different segments, .text being the actual code section, .data being the data segment, .bss being uninitialized label space for allocation and .zero being uninitialized zero page space for allocation. In .bss and .zero, only labels are evaluated. These pseudo-ops are valid in relocating and absolute modes.
.code
For ca65 compatibility, this is currently mapped to .text.
.zeropage
For ca65 compatibility, this is currently mapped to .zero.
.align value
Aligns the current segment to a byte boundary (2, 4 or 256) as specified by value (and places it in the header when relocating mode is enabled). Other values generate an error.
.fopt type, value1, value2, value3, ...
Acts like .byt/.asc except that the values are embedded into the object file as file options. The argument type is used to specify the file option being referenced. A table of these options is in the relocatable o65 file format description. The remainder of the options are interpreted as values to insert. Any number of values may be specified, and may also be strings.
.import label1, label2, label3, ...
Defines the given labels as global labels which are imported and resolved during the link stage, like the -L command line parameter.
.importzp label1, label2, label3, ...
Analogous to .import, except that it only imports zeropage labels (i.e., byte values).

PRÉPROCESSEUR

xa implémente un préprocesseur très similaire à celui du préprocesseur du langage C cpp(1) et de nombreux détails s'appliquent aux deux. Par exemple, comme en C, l'utilisation de /* */ pour les délimiteurs de commentaires est également prise en charge dans xa, ainsi que les commentaires utilisant le double slash //. Le préprocesseur prend également en charge les lignes de continuation, c'est-à-dire les lignes se terminant par une barre oblique inverse (\); la ligne suivante est alors ajoutée comme s'il n'y avait pas de nouvelle ligne de division. Ceci est également géré au niveau du préprocesseur.

Pour des raisons de mémoire et de complexité, l'intégralité de la syntaxe de cpp(1) n'est pas entièrement prise en charge. En particulier, les définitions de macros ne peuvent pas être définies en avant (c'est-à-dire qu'une définition de macro ne peut référencer qu'une définition de macro précédemment définie), à l'exception des fonctions de macros, où l'évaluation récursive est prise en charge ; par exemple, pour #define WW AA , AA doit déjà avoir été défini. Certaines autres directives ne sont pas prises en charge, pas plus que la plupart des macros prédéfinies standard, et il existe d'autres limites à l'évaluation et à la longueur des lignes. Comme les mainteneurs de xa reconnaissent que certains fichiers nécessiteront un pré-traitement plus complexe que ce que le préprocesseur intégré peut fournir, le préprocesseur acceptera la sortie de ligne/fichier/drapeaux de style cpp(1). Lorsque ces lignes sont rencontrées dans le fichier d'entrée, xa les traitera comme cc le ferait, sauf que les drapeaux sont ignorés. xa n'accepte pas de fichiers sur l'entrée standard pour des raisons d'analyse, vous devriez donc vider votre sortie cpp(1) vers un fichier temporaire intermédiaire, tel que

cc -E test.s > test.xa
xa test.xa

Aucun argument spécial ne doit être passé à xa ; la présence de la sortie cpp(1) est détectée automatiquement.

Notez que passer votre fichier par cpp(1) peut interférer avec les propres directives du préprocesseur de xa. Dans ce cas, pour masquer les directives de cpp(1), utilisez l'option -p pour spécifier un caractère alternatif au lieu de #, tel que le tilde (par exemple, -p'~' ). Avec cette option et cet argument spécifiés, alors au lieu de #include, par exemple, vous pouvez également utiliser ~include, en plus de #include (qui sera toujours accepté par le préprocesseur xa, en supposant qu'il en survive cpp(1)). N'importe quel caractère peut être utilisé, bien que des choix franchement pathologiques puissent entraîner des bugs amusants et frustrants lors de l'analyse. Vous pouvez également utiliser cette option pour différer les directives du préprocesseur que cpp(1) pourrait interpréter trop tôt jusqu'à ce que le fichier parvienne effectivement à xa pour traitement.

Les macros prédéfinies suivantes sont prises en charge, sauf si -XXA23 est spécifié :

XA_MAJOR
La version majeure actuelle de xa.
XA_MINOR
La version mineure actuelle de xa.

Les directives de préprocesseur suivantes sont prises en charge :

#include "filename"
Insère le contenu du fichier filename à cette position. Si le fichier n'est pas trouvé, il est recherché en utilisant les chemins spécifiés par l'option de ligne de commande -I ou la variable d'environnement XAINPUT (voir). Lors de l'insertion, le fichier sera également analysé pour les directives du préprocesseur.
#echo comment
Insère le commentaire comment dans le fichier journal des erreurs, spécifié avec l'option de ligne de commande -e.
#print expression
Calcule la valeur de l'expression expression et l'imprime dans le fichier journal des erreurs.
#error message
Affiche le message comme une erreur et termine l'assemblage.
#define DEFINE text
Équivaut la macro DEFINE au texte text de telle sorte que partout où DEFINE apparaît dans la source d'assemblage, text est substitué à sa place (comme le ferait cpp(1)). De plus, #define peut spécifier des fonctions de macro comme cpp(1) de telle sorte qu'une directive comme #define mult(a,b) ((a)*(b)) générerait le résultat attendu partout où une expression de la forme mult(a,b) apparaît dans la source. Cela peut également être spécifié sur la ligne de commande avec l'option -D. Les arguments d'une fonction macro peuvent être évalués récursivement, contrairement aux autres #defines ; le préprocesseur tentera de réévaluer tout argument référençant une autre définition de préprocesseur jusqu'à dix fois avant de se plaindre.

Les directives suivantes sont conditionnelles. Si la condition n'est pas satisfaite, alors le code source entre la directive et son #endif terminant est expurgé et non assemblé. Jusqu'à quinze niveaux d'imbrication sont pris en charge.

#ifdef DEFINE
Vrai seulement si la macro DEFINE est définie.
#ifndef DEFINE
Le contraire ; vrai seulement si la macro DEFINE n'a pas été définie auparavant.
#if expression
Vrai si l'expression expression est évaluée à une valeur non nulle. expression peut référencer d'autres macros.
#iflused label
Vrai si le label label a été utilisé (mais pas nécessairement instancié avec une valeur). Cela fonctionne sur les labels, pas sur les macros !
#ifldef lab
xa(1) - xa assembler

NAME

xa - xa assembler

SYNOPSIS

xa

    [options] [input file]

DESCRIPTION

The xa assembler is a cross assembler for the 6502 microprocessor family. It supports the 6502, 65C02, 65802, and 65816 microprocessors, and can produce code for a variety of output formats, primarily sequential binary files.

xa is a two-pass assembler. It reads the entire assembly source file, resolves all labels and symbols, and then writes the object code. This allows for forward references and complex addressing modes.

OPTIONS

The following options are available:

-a
Assemble only, do not link.
-b
Create a relocatable object file in the o65 format.
-c
Case-insensitive assembly.
-d
Dump symbol table to stderr.
-e
Emit errors to stderr.
-f format
Specify output format (e.g., binary, o65).
-h
Display help message.
-i path
Add directory to include search path.
-l
Listings file.
-o file
Output file.
-p
Preprocess only.
-s
Suppress warnings.
-v
Verbose output.
-w
Warn on unresolved symbols.

ASSEMBLER SYNTAX

Labels are defined by a name followed by a colon (:). Instructions and directives follow the label. Comments start with a semicolon (;) and extend to the end of the line.

Expressions can be used for addresses, data, and arguments. Valid operators include +, -, *, /, %, &, |, ^, ~, !, and parentheses for grouping.

The assembler includes a preprocessor that handles conditional assembly, macros, and file inclusions.

#endif

#endif

LINKING

xa is oriented towards generating sequential binaries. Code is strictly emitted in order even if the program counter is set to a lower location than previously assembled code, and padding is not automatically emitted if the program counter is set to a higher location. Changing the program location only changes new labels for code that is subsequently emitted; previous emitted code remains unchanged. Fortunately, for many object files these conventions have no effect on their generation.

However, some applications may require generating an object file built from several previously generated components, and/or submodules which may need to be present at specific memory locations. With a minor amount of additional specification, it is possible to use xa for this purpose as well.

The first means of doing so uses the o65 format to make relocatable objects that in turn can be linked by ldo65(1) (q.v.).

The second means involves either assembled code, or insertion of previously built object or data files with .bin, using .dsb pseudo-ops with computed expression arguments to insert any necessary padding between them, in the sequential order they are to reside in memory. Consider this example:


.word $1000
* = $1000


; this is your code at $1000
part1 rts
; this label marks the end of code
endofpart1


; DON'T PUT A NEW .word HERE!
* = $2000
.dsb (*-endofpart1), 0
; yes, set it again
* = $2000


; this is your code at $2000
part2 rts

This example, written for Commodore microcomputers using a 16-bit starting address, has two "modules" in it: one block of code at $1000 (4096), indicated by the code between labels part1 and endofpart1, and a second block at $2000 (8192) starting at label part2.

The padding is computed by the .dsb pseudo-op between the two modules. Note that the program counter is set to the new address and then a computed expression inserts the proper number of fill bytes from the end of the assembled code in part 1 up to the new program counter address. Since this itself advances the program counter, the program counter is reset again, and assembly continues.

When the object this source file generates is loaded, there will be an rts instruction at address 4096 and another at address 8192, with null bytes between them.

Should one of these areas need to contain a pre-built file, instead of assembly code, simply use a .bin pseudo-op to load whatever portions of the file are required into the output. The computation of addresses and number of necessary fill bytes is done in the same fashion.

Although this example used the program counter itself to compute the difference between addresses, you can use any label for this purpose, keeping in mind that only the program counter determines where relative addresses within assembled code are resolved.

NOTES'N'BUGS

The R65C02 instructions ina (often rendered inc a) and dea (dec a) must be rendered as bare inc and dec instructions respectively.

The 65816 instructions mvn and mvp use two eight bit parameters, the only instructions in the entire instruction set to do so. Older versions of xa took a single 16-bit absolute value. As of 2.4.0, this old syntax is no longer accepted.

Forward-defined labels -- that is, labels that are defined after the current instruction is processed -- cannot be optimized into zero page instructions even if the label does end up being defined as a zero page location, because the assembler does not know the value of the label in advance during the first pass when the length of an instruction is computed. On the second pass, a warning will be issued when an instruction that could have been optimized can't be because of this limitation. (Obviously, this does not apply to branching or jumping instructions because they're not optimizable anyhow, and those instructions that can only take an 8-bit parameter will always be casted to an 8-bit quantity.) If the label cannot otherwise be defined ahead of the instruction, the backtick prefix ` may be used to force further optimization no matter where the label is defined as long as the instruction supports it. Indiscriminately forcing the issue can be fraught with peril, however, and is not recommended; to discourage this, the assembler will complain about its use in addressing mode situations where no ambiguity exists, such as indirect indexed, branching and so on.
