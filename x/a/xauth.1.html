XAUTH(1) Manuel des commandes générales XAUTH(1)

NOM

xauth - utilitaire de fichier d'autorité X

SYNTAXE

xauth [ -f fichier_auth ] [ -vqibn ] [ commande arg ... ]

DESCRIPTION

Le programme xauth est utilisé pour éditer et afficher les informations d'autorisation utilisées pour se connecter au serveur X. Ce programme est généralement utilisé pour extraire des enregistrements d'autorisation d'une machine et les fusionner sur une autre (comme c'est le cas lors de l'utilisation de connexions à distance ou de l'octroi d'accès à d'autres utilisateurs). Les commandes (décrites ci-dessous) peuvent être saisies interactivement, sur la ligne de commande xauth, ou dans des scripts. Notez que ce programme ne contacte pas le serveur X, sauf lorsque la commande generate est utilisée. Normalement, xauth n'est pas utilisé pour créer l'entrée du fichier d'autorisation en premier lieu ; le programme qui démarre le serveur X (souvent xdm ou startx) s'en charge.

OPTIONS

Les options suivantes peuvent être utilisées avec xauth. Elles peuvent être fournies individuellement (par exemple, -q -i) ou combinées (par exemple, -qi).

-f fichier_auth
Cette option spécifie le nom du fichier d'autorité à utiliser. Par défaut, xauth utilisera le fichier spécifié par la variable d'environnement XAUTHORITY ou .Xauthority dans le répertoire personnel de l'utilisateur.
-q
Cette option indique que xauth doit fonctionner silencieusement et ne pas afficher de messages de statut non sollicités. C'est le comportement par défaut si une commande xauth est fournie sur la ligne de commande ou si la sortie standard n'est pas dirigée vers un terminal.
-v
Cette option indique que xauth doit fonctionner de manière verbeuse et afficher des messages de statut indiquant les résultats des différentes opérations (par exemple, le nombre d'enregistrements lus ou écrits). C'est le comportement par défaut si xauth lit des commandes depuis son entrée standard et que sa sortie standard est dirigée vers un terminal.
-i
Cette option indique que xauth doit ignorer tout verrouillage du fichier d'autorité. Normalement, xauth refusera de lire ou d'éditer tout fichier d'autorité qui a été verrouillé par d'autres programmes (généralement xdm ou un autre xauth).
-b
Cette option indique que xauth doit tenter de lever tout verrouillage du fichier d'autorité avant de continuer. Utilisez cette option uniquement pour nettoyer des verrous obsolètes.
-n
Cette option indique que xauth ne doit pas tenter de résoudre les noms d'hôtes, mais doit simplement toujours afficher l'adresse de l'hôte telle qu'elle est stockée dans le fichier d'autorité.
-V
Cette option affiche le numéro de version de l'exécutable xauth.

COMMANDES

Les commandes suivantes peuvent être utilisées pour manipuler les fichiers d'autorité :

add nom_affichage nom_protocole clef_hex
Une entrée d'autorisation pour l'affichage indiqué, utilisant le protocole et les données de clé spécifiés, est ajoutée au fichier d'autorisation. Les données sont spécifiées sous forme d'une chaîne de longueur paire de chiffres hexadécimaux, chaque paire représentant un octet. Le premier chiffre de chaque paire donne les 4 bits de poids fort de l'octet, et le second chiffre de la paire donne les 4 bits de poids faible. Par exemple, une clef hexadécimale de 32 caractères représenterait une valeur de 128 bits. Un nom de protocole composé d'un simple point est traité comme une abréviation pour MIT-MAGIC-COOKIE-1.
generate nom_affichage nom_protocole [trusted|untrusted]
[timeout secondes] [group id_groupe] [data donnees_hex]

Cette commande est similaire à add. La principale différence est qu'au lieu d'obliger l'utilisateur à fournir les données de clé, elle se connecte au serveur spécifié dans nom_affichage et utilise l'extension SECURITY pour obtenir les données de clé à stocker dans le fichier d'autorisation. Si le serveur ne peut pas être contacté ou s'il ne prend pas en charge l'extension SECURITY, la commande échoue. Sinon, une entrée d'autorisation pour l'affichage indiqué utilisant le protocole donné est ajoutée au fichier d'autorisation. Un nom de protocole composé d'un simple point est traité comme une abréviation pour MIT-MAGIC-COOKIE-1.

Si l'option trusted est utilisée, les clients qui se connectent en utilisant cette autorisation auront un accès complet à l'affichage, comme d'habitude. Si untrusted est utilisée, les clients qui se connectent en utilisant cette autorisation seront considérés comme non fiables et empêchés de voler ou de falsifier des données appartenant à des clients fiables. Voir la spécification de l'extension SECURITY pour plus de détails sur les restrictions imposées aux clients non fiables. La valeur par défaut est untrusted.

L'option timeout spécifie la durée en secondes pendant laquelle cette autorisation sera valide. Si l'autorisation reste inutilisée (aucun client n'y est connecté) pendant plus de cette période, le serveur supprime l'autorisation, et les tentatives futures de connexion en l'utilisant échoueront. Notez que la suppression effectuée par le serveur ne supprime pas l'entrée d'autorisation du fichier d'autorisation. Le délai d'attente par défaut est de 60 secondes.

L'option group spécifie le groupe d'applications auquel les clients se connectant avec cette autorisation doivent appartenir. Voir la spécification de l'extension de groupe d'applications pour plus de détails. La valeur par défaut est de ne pas appartenir à un groupe d'applications.

L'option data spécifie les données que le serveur doit utiliser pour générer l'autorisation. Notez que ce ne sont pas les mêmes données qui sont écrites dans le fichier d'autorisation. L'interprétation de ces données dépend du protocole d'autorisation. Les donnees_hex sont dans le même format que la clef_hex décrite dans la commande add. La valeur par défaut est de ne pas envoyer de données.

[n]extract nom_fichier nom_affichage...
Les entrées d'autorisation pour chacun des affichages spécifiés sont écrites dans le fichier indiqué. Si la commande nextract est utilisée, les entrées sont écrites dans un format numérique adapté à la transmission non binaire (comme la messagerie électronique sécurisée). Les entrées extraites peuvent être relues en utilisant les commandes merge et nmerge. Si le nom de fichier consiste en un simple trait d'union, les entrées seront écrites sur la sortie standard.
[n]list [nom_affichage...]
Les entrées d'autorisation pour chacun des affichages spécifiés (ou tous si aucun affichage n'est nommé) sont affichées sur la sortie standard. Si la commande nlist est utilisée, les entrées seront affichées dans le format numérique utilisé par la commande nextract ; sinon, elles sont affichées dans un format textuel. Les données de clé sont toujours affichées au format hexadécimal décrit dans la commande add.
[n]merge [nom_fichier...]
Les entrées d'autorisation sont lues à partir des fichiers spécifiés et sont fusionnées dans la base de données d'autorisation, remplaçant toutes les entrées existantes correspondantes. Si la commande nmerge est utilisée, le format numérique décrit dans la commande extract est utilisé. Si un nom de fichier consiste en un simple trait d'union, l'entrée standard sera lue si elle n'a pas déjà été lue.
remove nom_affichage...
Les entrées d'autorisation correspondant aux affichages spécifiés sont supprimées du fichier d'autorité.
source nom_fichier
Le fichier spécifié est traité comme un script contenant des commandes xauth à exécuter. Les lignes vides et les lignes commençant par un dièse (#) sont ignorées. Un simple trait d'union peut être utilisé pour indiquer l'entrée standard, si elle n'a pas déjà été lue.
info
Des informations décrivant le fichier d'autorisation, si des modifications ont été apportées ou non, et d'où les commandes xauth sont lues sont affichées sur la sortie standard.
exit
Si des modifications ont été apportées, le fichier d'autorité est écrit (si autorisé), et le programme se termine. Une fin de fichier est traitée comme une commande exit implicite.
quit
Identique à la commande exit.

NAME

xauth - authorization manipulation tool for X

SYNOPSIS

xauth [-fpq] [-i] [-l] [-n] [-b] [-x] [-t type] [-m] [-r display] [-d display] [-a display] [-c] [-V] [file ...]

xauth add display hexkey

xauth generate display protocol [encoding]

xauth info

xauth extract filename display ...

xauth load filename

xauth merge filename

xauth remove display ...

xauth list [display ...]

xauth rename display newdisplay ...

xauth quit

xauth exit

xauth bye

xauth ?

xauth help [string]

xauth version

DESCRIPTION

The xauth program is used to edit and display the contents of an X authorization file. When a user starts the X Window System, it creates an authorization file for the user. This file contains keys that clients can use to gain access to the server. The xauth program allows users to manually add, delete, and list authorization keys.

Authorization keys are generated by the X server when it starts up. They are stored in an authorization file, which by default is named ~/.Xauthority. The xauth program can be used to examine and modify this file.

When xauth is run without any arguments, it starts up in interactive mode, reading commands from the standard input. If the file argument is given, it is assumed to be an authorization file to be used instead of the default.

OPTIONS

-f filename
Specifies the name of the authority file to use. If this option is not given, xauth will look for the file named by the XAUTHORITY environment variable, or if that is not set, it will default to ~/.Xauthority.
-q
Quiet mode. Normally, xauth prints out the contents of the authorization file on the standard output when it starts. This option suppresses that output.
-i
Ignore the contents of the authorization file. This is useful for creating a new authorization file from scratch.
-b
Always use the trusted information from the server. This is useful for hosts that do not support the magic cookie mechanism.
-x
Disable XDM-CP protocol messages. This is useful for sites that do not use the X Display Manager.
-t type
Sets the default authorization type to use. The default is MIT-MAGIC-COOKIE-1.
-m
Merge the contents of the authorization file. This is the default behavior.
-r display
Remove the authorization entry for the specified display. This is the default behavior when xauth is run interactively without any commands.
-d display
Delete the authorization entry for the specified display. Same as -r.
-a display
Add the authorization entry for the specified display. Same as add command.
-c
Check authorization file syntax. This option is useful for validating an authorization file without actually modifying it.
-n
No access control. This option is used to disable access control for the server.
-l
List the contents of the authorization file. This is the default behavior when xauth is run interactively without any commands.
-V
Display the program version number and exit.

COMMANDS

add display hexkey
Adds a new authorization entry for the specified display. The hexkey is a hexadecimal representation of the authorization key.
generate display protocol [encoding]
Generates a new authorization key for the specified display using the given protocol. If no encoding is specified, the default encoding for the protocol is used.
info
Prints information about the current authorization file, including the default display and authorization type.
extract filename display ...
Writes the authorization entries for the specified displays to the given file. If the filename is "-", the output is written to standard output.
load filename
Reads authorization entries from the given file and adds them to the current authorization file. This command is useful for merging two authorization files.
merge filename
Reads authorization entries from the given file and merges them into the current authorization file. If an entry for a display already exists, it is replaced.
remove display ...
Removes the authorization entries for the specified displays from the current authorization file.
list [display ...]
Lists the authorization entries for the specified displays. If no displays are specified, all entries in the current authorization file are listed.
rename display newdisplay ...
Renames the authorization entries for the specified displays to the new display names.
quit
Exits the program, saving any modifications made to the authorization file. This may also be accomplished by pressing the end-of-file character.
exit
The program exits, ignoring any modifications. This may also be accomplished by pressing the interrupt character.
version
This command shows the version number of the xauth executable.
help [string]
A description of all commands that begin with the given string (or all commands if no string is given) is printed on the standard output.
?
A short list of the valid commands is printed on the standard output.

DISPLAY NAMES

Display names for the add, [n]extract, [n]list, [n]merge, and remove commands use the same format as the DISPLAY environment variable and the common -display command line argument. Display-specific information (such as the screen number) is unnecessary and will be ignored. Same-machine connections (such as local-host sockets, shared memory, and the Internet Protocol hostname localhost) are referred to as hostname/unix:displaynumber so that local entries for different machines may be stored in one authority file.

EXAMPLE

The most common use for xauth is to extract the entry for the current display, copy it to another machine, and merge it into the user's authority file on the remote machine:

        %  xauth extract - $DISPLAY | ssh otherhost xauth merge -

The following command contacts the server :0 to create an authorization using the MIT-MAGIC-COOKIE-1 protocol. Clients that connect with this authorization will be untrusted.

%  xauth generate :0 .

ENVIRONMENT

This xauth program uses the following environment variables:

XAUTHORITY
to get the name of the authority file to use if the -f option isn't used.
HOME
to get the user's home directory if XAUTHORITY isn't defined.

FILES

$HOME/.Xauthority
default authority file if XAUTHORITY isn't defined.

SEE ALSO

X(7), Xsecurity(7), xhost(1), Xserver(1), xdm(1), startx(1), Xau(3).

BUGS

Users that have insecure networks should take care to use encrypted file transfer mechanisms to copy authorization entries between machines. Similarly, the MIT-MAGIC-COOKIE-1 protocol is not very useful in insecure environments. Sites that are interested in additional security may need to use encrypted authorization mechanisms such as Kerberos.

Spaces are currently not allowed in the protocol name. Quoting could be added for the truly perverse.

AUTHOR

Jim Fulton, MIT X Consortium

NOM

xauth - outil de manipulation d'autorisation pour X

SYNTAXE

xauth [-fpq] [-i] [-l] [-n] [-b] [-x] [-t type] [-m] [-r affichage] [-d affichage] [-a affichage] [-c] [-V] [fichier ...]

xauth add affichage hexkey

xauth generate affichage protocole [encodage]

xauth info

xauth extract nomfichier affichage ...

xauth load nomfichier

xauth merge nomfichier

xauth remove affichage ...

xauth list [affichage ...]

xauth rename affichage nouvel_affichage ...

xauth quit

xauth exit

xauth bye

xauth ?

xauth help [chaine]

xauth version

DESCRIPTION

Le programme xauth est utilisé pour éditer et afficher le contenu d'un fichier d'autorisation X. Lorsqu'un utilisateur démarre le système X Window, il crée un fichier d'autorisation pour cet utilisateur. Ce fichier contient des clés que les clients peuvent utiliser pour accéder au serveur. Le programme xauth permet aux utilisateurs d'ajouter, supprimer et lister manuellement les clés d'autorisation.

Les clés d'autorisation sont générées par le serveur X au démarrage. Elles sont stockées dans un fichier d'autorisation, nommé par défaut ~/.Xauthority. Le programme xauth peut être utilisé pour examiner et modifier ce fichier.

Lorsque xauth est exécuté sans arguments, il démarre en mode interactif, lisant les commandes depuis l'entrée standard. Si l'argument fichier est donné, il est supposé être un fichier d'autorisation à utiliser à la place du fichier par défaut.

OPTIONS

-f nomfichier
Spécifie le nom du fichier d'autorisation à utiliser. Si cette option n'est pas donnée, xauth recherchera le fichier nommé par la variable d'environnement XAUTHORITY, ou si celle-ci n'est pas définie, il utilisera par défaut ~/.Xauthority.
-q
Mode silencieux. Normalement, xauth affiche le contenu du fichier d'autorisation sur la sortie standard au démarrage. Cette option supprime cette sortie.
-i
Ignore le contenu du fichier d'autorisation. Ceci est utile pour créer un nouveau fichier d'autorisation à partir de zéro.
-b
Utilise toujours les informations de confiance du serveur. Ceci est utile pour les hôtes qui ne supportent pas le mécanisme de cookie magique.
-x
Désactive les messages du protocole XDM-CP. Ceci est utile pour les sites qui n'utilisent pas le X Display Manager.
-t type
Définit le type d'autorisation par défaut à utiliser. Le type par défaut est MIT-MAGIC-COOKIE-1.
-m
Fusionne le contenu du fichier d'autorisation. C'est le comportement par défaut.
-r affichage
Supprime l'entrée d'autorisation pour l'affichage spécifié. C'est le comportement par défaut lorsque xauth est exécuté interactivement sans commandes.
-d affichage
Supprime l'entrée d'autorisation pour l'affichage spécifié. Identique à -r.
-a affichage
Ajoute l'entrée d'autorisation pour l'affichage spécifié. Identique à la commande add.
-c
Vérifie la syntaxe du fichier d'autorisation. Cette option est utile pour valider un fichier d'autorisation sans le modifier réellement.
-n
Pas de contrôle d'accès. Cette option est utilisée pour désactiver le contrôle d'accès pour le serveur.
-l
Liste le contenu du fichier d'autorisation. C'est le comportement par défaut lorsque xauth est exécuté interactivement sans commandes.
-V
Affiche le numéro de version du programme et quitte.

COMMANDES

add affichage hexkey
Ajoute une nouvelle entrée d'autorisation pour l'affichage spécifié. hexkey est une représentation hexadécimale de la clé d'autorisation.
generate affichage protocole [encodage]
Génère une nouvelle clé d'autorisation pour l'affichage spécifié en utilisant le protocole donné. Si aucun encodage n'est spécifié, l'encodage par défaut pour le protocole est utilisé.
info
Affiche des informations sur le fichier d'autorisation actuel, y compris l'affichage et le type d'autorisation par défaut.
extract nomfichier affichage ...
Écrit les entrées d'autorisation pour les affichages spécifiés dans le fichier donné. Si le nom de fichier est "-", la sortie est écrite sur la sortie standard.
load nomfichier
Lit les entrées d'autorisation à partir du fichier donné et les ajoute au fichier d'autorisation actuel. Cette commande est utile pour fusionner deux fichiers d'autorisation.
merge nomfichier
Lit les entrées d'autorisation à partir du fichier donné et les fusionne dans le fichier d'autorisation actuel. Si une entrée pour un affichage existe déjà, elle est remplacée.
remove affichage ...
Supprime les entrées d'autorisation pour les affichages spécifiés du fichier d'autorisation actuel.
list [affichage ...]
Liste les entrées d'autorisation pour les affichages spécifiés. Si aucun affichage n'est spécifié, toutes les entrées du fichier d'autorisation actuel sont listées.
rename affichage nouvel_affichage ...
Renomme les entrées d'autorisation pour les affichages spécifiés avec les noms de nouvel_affichage.
quit
Quitte le programme, en sauvegardant toutes les modifications apportées au fichier d'autorisation. Ceci peut également être réalisé en appuyant sur le caractère de fin de fichier.
exit
Le programme se termine, en ignorant toutes les modifications. Ceci peut également être réalisé en appuyant sur le caractère d'interruption.
version
Cette commande affiche le numéro de version de l'exécutable xauth.
help [chaine]
Une description de toutes les commandes commençant par la chaîne donnée (ou toutes les commandes si aucune chaîne n'est donnée) est imprimée sur la sortie standard.
?
Une courte liste des commandes valides est imprimée sur la sortie standard.

NOMS D'AFFICHAGE

Les noms d'affichage pour les commandes add, [n]extract, [n]list, [n]merge, et remove utilisent le même format que la variable d'environnement DISPLAY et l'argument de ligne de commande commun -display. Les informations spécifiques à l'affichage (comme le numéro d'écran) sont inutiles et seront ignorées. Les connexions sur la même machine (comme les sockets locaux, la mémoire partagée et le nom d'hôte du protocole Internet localhost) sont référencées comme nomhote/unix:numerodisplay afin que les entrées locales pour différentes machines puissent être stockées dans un seul fichier d'autorité.

EXEMPLE

L'utilisation la plus courante de xauth est d'extraire l'entrée pour l'affichage actuel, de la copier vers une autre machine, et de la fusionner dans le fichier d'autorisation de l'utilisateur sur la machine distante :

        %  xauth extract - $DISPLAY | ssh autrehote xauth merge -

La commande suivante contacte le serveur :0 pour créer une autorisation utilisant le protocole MIT-MAGIC-COOKIE-1. Les clients qui se connectent avec cette autorisation ne seront pas fiables.

%  xauth generate :0 .

ENVIRONNEMENT

Ce programme xauth utilise les variables d'environnement suivantes :

XAUTHORITY
pour obtenir le nom du fichier d'autorisation à utiliser si l'option -f n'est pas utilisée.
HOME
pour obtenir le répertoire personnel de l'utilisateur si XAUTHORITY n'est pas défini.

FICHIERS

$HOME/.Xauthority
fichier d'autorisation par défaut si XAUTHORITY n'est pas défini.

VOIR AUSSI

X(7), Xsecurity(7), xhost(1), Xserver(1), xdm(1), startx(1), Xau(3).

BOGUES

Les utilisateurs dont les réseaux sont peu sûrs devraient prendre soin d'utiliser des mécanismes de transfert de fichiers cryptés pour copier les entrées d'autorisation entre les machines. De même, le protocole MIT-MAGIC-COOKIE-1 n'est pas très utile dans les environnements peu sûrs. Les sites intéressés par une sécurité supplémentaire pourraient avoir besoin d'utiliser des mécanismes d'autorisation cryptés tels que Kerberos.

Les espaces ne sont actuellement pas autorisés dans le nom du protocole. L'utilisation de guillemets pourrait être ajoutée pour les cas vraiment pervers.
