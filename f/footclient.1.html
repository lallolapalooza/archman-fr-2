footclient(1) Manuel des commandes générales footclient(1)

NOM

footclient - démarre de nouveaux terminaux dans un serveur foot

SYNOPHIS

footclient [OPTIONS]
footclient [OPTIONS] <commande> [OPTIONS DE COMMANDE]

Tous les arguments postfixés (non-options) sont traités comme une commande, et ses arguments, à exécuter (à la place du shell par défaut).

DESCRIPTION

footclient est utilisé conjointement avec foot(1) en mode --server.

Le lancer sans arguments ouvrira une nouvelle fenêtre de terminal (hébergée dans le serveur foot), avec votre shell par défaut. Le code de sortie sera celui du terminal. C'est-à-dire que footclient ne se termine pas tant que le terminal n'a pas terminé.

OPTIONS

-t,--term=TERM

Valeur à attribuer à la variable d'environnement TERM (voir TERMINFO et ENVIRONNEMENT). Par défaut : foot.

-T,--title=TITLE

Titre initial de la fenêtre. Par défaut : foot.

-a,--app-id=ID

Valeur à attribuer à la propriété app-id de la fenêtre Wayland. Par défaut : foot (mode normal), ou footclient (mode serveur).

-w,--window-size-pixels=LARGEURxHAUTEUR

Définit la largeur et la hauteur initiales de la fenêtre, en pixels. Par défaut : 700x500.

-W,--window-size-chars=LARGEURxHAUTEUR

Définit la largeur et la hauteur initiales de la fenêtre, en caractères. Par défaut : non défini.

-m,--maximized

Démarrer en mode maximisé. Si --maximized et --fullscreen sont tous deux spécifiés, le dernier prend le dessus.

-F,--fullscreen

Démarrer en mode plein écran. Si --maximized et --fullscreen sont tous deux spécifiés, le dernier prend le dessus.

-L,--login-shell

Démarre un shell de connexion, en ajoutant un '-' au début de argv[0].

-D,--working-directory=DIR

Répertoire de travail initial pour l'application client. Par défaut : CWD de footclient.

-s,--server-socket=CHEMIN

Se connecte à CHEMIN au lieu de $XDG_RUNTIME_DIR/foot-$WAYLAND_DISPLAY.sock.

-H,--hold

Reste ouvert après la sortie du processus enfant.

-N,--no-wait

Détache le processus client du terminal en cours d'exécution, en sortant immédiatement.

-o,--override=[SECTION.]CLÉ=VALEUR

Remplace une option définie dans le fichier de configuration. Si SECTION n'est pas donné, par défaut main.

-E,--client-environment

Le processus enfant dans la nouvelle instance de terminal utilisera l'environnement de footclient, au lieu de celui du serveur.

Les variables d'environnement listées dans la section Variables définies dans le processus enfant seront écrasées par le serveur foot. Par exemple, le nouveau terminal utilisera TERM de la configuration, et non l'environnement de footclient.

-d,--log-level={info,warning,error,none}

Niveau de journalisation, utilisé à la fois pour la sortie des journaux sur stderr et pour syslog. Par défaut : warning.

-l,--log-colorize=[{never,always,auto}]

Active ou désactive la colorisation de la sortie des journaux sur stderr.

-v,--version

Affiche le numéro de version et quitte.

-e

Ignoré ; pour compatibilité avec xterm -e. Voir foot(1) pour plus de détails.

STATUT DE SORTIE

Footclient se terminera avec le code 220 en cas d'échec de footclient lui-même (par exemple, le socket du serveur n'existe pas).

Si -N,--no-wait est utilisé, footclient se termine avec le code 0 dès que le serveur foot a reçu l'instruction d'ouvrir une nouvelle fenêtre.

Sinon, footclient peut également se terminer avec le code 230. Cela indique un échec dans le serveur foot.

Dans tous les autres cas, le code de sortie est celui de l'application client (c'est-à-dire le shell).

TERMINFO

Les applications clientes utilisent l'identifiant terminfo spécifié par la variable d'environnement TERM (définie par foot) pour déterminer les capacités du terminal.

Foot a deux définitions terminfo : foot et foot-direct, foot étant le défaut.

La différence entre les deux réside dans le nombre de couleurs qu'elles décrivent ; foot décrit 256 couleurs et foot-direct 16,7 millions de couleurs (truecolor 24 bits).

Notez que l'utilisation de terminfo foot ne limite pas le nombre de couleurs utilisables à 256 ; les applications peuvent toujours utiliser des couleurs RVB 24 bits. En fait, la plupart des applications fonctionnent mieux avec foot (y compris les couleurs 24 bits)). L'utilisation des entrées terminfo *-direct a déjà été connue pour planter certaines applications ncurses.

Cependant, certaines applications ont besoin d'une entrée terminfo *-direct pour le support 24 bits. Emacs en est un exemple.

Bien que l'utilisation de foot ou foot-direct soit fortement recommandée, il est possible d'utiliser par exemple xterm-256color. Cela peut être utile lors de la connexion à un système où les entrées terminfo de foot ne peuvent pas être facilement installées.

Notez que les entrées terminfo peuvent être installées dans le répertoire personnel de l'utilisateur. C'est-à-dire que si vous n'avez pas les droits root, ou s'il n'y a pas de paquet de distribution pour les entrées terminfo de foot, vous pouvez installer manuellement les entrées terminfo de foot en copiant foot et foot-direct dans ~/.terminfo/f/.

ENVIRONNEMENT

Variables utilisées par footclient

XDG_RUNTIME_DIR

Utilisé pour construire le CHEMIN par défaut pour l'option --server-socket, lorsqu'aucun argument explicite n'est donné (voir ci-dessus).

WAYLAND_DISPLAY

Utilisé pour construire le CHEMIN par défaut pour l'option --server-socket, lorsqu'aucun argument explicite n'est donné (voir ci-dessus).

Si le socket au CHEMIN par défaut n'existe pas, footclient se rabattra sur le chemin moins spécifique, avec la priorité suivante : $XDG_RUNTIME_DIR/foot-$WAYLAND_DISPLAY.sock, $XDG_RUNTIME_DIR/foot.sock, /tmp/foot.sock.

Variables définies dans le processus enfant

TERM

Identifiant terminfo/termcap. Il est utilisé par les applications clientes pour déterminer quelles capacités un terminal prend en charge. La valeur est définie conformément à l'option de commande --term ou à l'option de configuration term dans foot.ini(5).

COLORTERM

Cette variable est définie à truecolor, pour indiquer aux applications clientes que les couleurs RVB 24 bits sont prises en charge.

PWD

Répertoire de travail actuel (au moment du lancement de foot)

SHELL

Défini au shell lancé, si le shell est valide (il est listé dans /etc/shells).

En plus des variables listées ci-dessus, des variables d'environnement personnalisées peuvent être définies dans foot.ini(5).

Variables *non définies* dans le processus enfant

TERM_PROGRAM TERM_PROGRAM_VERSION

Ces variables d'environnement sont définies par certains autres émulateurs de terminaux. Nous les annulons pour éviter que les applications ne détectent mal foot.

En plus des variables listées ci-dessus, des variables d'environnement personnalisées à annuler peuvent être définies dans foot.ini(5).

Signaux

Les signaux suivants ont une signification spéciale dans footclient :

  • SIGUSR1 : basculer vers le thème de couleur 1 (c'est-à-dire utiliser la section [colors]).
  • SIGUSR2 : basculer vers le thème de couleur 2 (c'est-à-dire utiliser la section [colors2]).

Lors de l'envoi de SIGUSR1/SIGUSR2 à une instance de footclient, le thème est modifié dans cette seule instance. Ceci est différent de l'envoi de SIGUSR1/SIGUSR2 au processus serveur, où toutes les instances changent le thème.

Remarque : pour des raisons évidentes, cela n'est pas pris en charge lorsque footclient est démarré avec --no-wait.
