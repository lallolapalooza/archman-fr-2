funopen(3bsd)

Paquet: libbsd

Licences: custom

funopen(3bsd) 3bsd funopen(3bsd)

NOM

funopen, fropen, fwopen — ouvrir un flux

BIBLIOTHÈQUE

bibliothèque « libbsd »

SYNTAXE

#include <stdio.h> (Voir libbsd(7) pour l'utilisation de l'include.)
FILE *
funopen(const void *cookie, int (*readfn)(void *, char *, int), int (*writefn)(void *, const char *, int), off_t (*seekfn)(void *, off_t, int), int (*closefn)(void *));

FILE *
fropen(void *cookie, int (*readfn)(void *, char *, int));

FILE *
fwopen(void *cookie, int (*writefn)(void *, const char *, int));

DESCRIPTION

La fonction funopen() associe un flux à un maximum de quatre “fonctions d’E/S”. Soit readfn soit writefn doit être spécifié ; les autres peuvent être fournis sous forme de pointeur NULL de type approprié. Ces fonctions d’E/S seront utilisées pour lire, écrire, repositionner et fermer le nouveau flux.

En général, omettre une fonction signifie que toute tentative d’effectuer l’opération associée sur le flux résultant échouera. Si la fonction de fermeture est omise, la fermeture du flux videra toute sortie tamponnée puis réussira.

Les conventions d’appel de readfn, writefn, seekfn et closefn doivent correspondre respectivement à celles de read(2), write(2), lseek(2), et close(2) à la seule exception qu’elles reçoivent l’argument cookie spécifié à funopen() à la place de l’argument descripteur de fichier traditionnel.

Les fonctions d’E/S de lecture et d’écriture sont autorisées à modifier le tampon sous-jacent sur les flux entièrement tamponnés ou tamponnés par ligne en appelant setvbuf(3). Elles ne sont pas non plus obligées de remplir ou de vider complètement le tampon. Elles ne sont cependant pas autorisées à passer des flux de non-tamponnés à tamponnés ou à changer l’état du drapeau de tamponnage par ligne. Elles doivent également être préparées à ce que les appels de lecture ou d’écriture se produisent sur des tampons autres que celui le plus récemment spécifié.

Toutes les fonctions d’E/S utilisateur peuvent signaler une erreur en retournant -1. De plus, toutes les fonctions doivent définir la variable externe errno de manière appropriée en cas d’erreur.

Une erreur lors de l’appel à closefn() ne maintient pas le flux ouvert.

Par commodité, le fichier d’inclusion <stdio.h> définit les macros fropen() et fwopen() comme des appels à funopen() avec seulement une fonction de lecture ou d’écriture spécifiée.

VALEURS DE RETOUR

En cas de succès, funopen() retourne un pointeur FILE. Sinon, NULL est retourné et la variable globale errno est définie pour indiquer l’erreur.

ERREURS

[EINVAL]
La fonction funopen() a été appelée sans fonction de lecture ni d’écriture. La fonction funopen() peut également échouer et définir errno pour toutes les erreurs spécifiées pour la routine malloc(3).

VOIR AUSSI

fcntl(2), open(2), fclose(3), fopen(3), fseek(3), setbuf(3)

HISTORIQUE

Les fonctions funopen() sont apparues pour la première fois dans 4.4BSD.

BOGUES

La fonction funopen() peut ne pas être portable sur des systèmes autres que ceux basés sur BSD, glibc et musl (car l’implémentation libbsd n’est fournie que lorsque le système dispose de fopencookie()).

Sur FreeBSD, OpenBSD et DragonFly, l’interface funopen() suppose à tort que fpos_t est un type intégral et l’utilise dans le hook seekfn ; mais comme le code utilisant un hook seekfn échouera à la compilation sur les systèmes où fpos_t est une structure, et qu’il faudra de toute façon le corriger légèrement, l’implémentation fournie par libbsd (de la même manière que NetBSD) utilise les types off_t corrects.
