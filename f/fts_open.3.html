fts(3) Manuel des fonctions de bibliothèque fts(3)

NOM

fts, fts_open, fts_read, fts_children, fts_set, fts_close - parcourir une hiérarchie de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPTION

Les fonctions fts sont fournies pour parcourir les hiérarchies de fichiers. De manière générale, la fonction fts_open() renvoie un « descripteur » (de type FTS *) qui fait référence à un « flux » de hiérarchie de fichiers. Ce descripteur est ensuite fourni aux autres fonctions fts. La fonction fts_read() renvoie un pointeur vers une structure décrivant l'un des fichiers de la hiérarchie. La fonction fts_children() renvoie un pointeur vers une liste chaînée de structures, chacune décrivant l'un des fichiers contenus dans un répertoire de la hiérarchie.

En général, les répertoires sont visités deux fois de manière distinguable : en préordre (avant que leurs descendants ne soient visités) et en postordre (après que tous leurs descendants ont été visités). Les fichiers sont visités une seule fois. Il est possible de parcourir la hiérarchie « logiquement » (en visitant les fichiers vers lesquels pointent les liens symboliques) ou physiquement (en visitant les liens symboliques eux-mêmes), d'ordonner le parcours de la hiérarchie ou de tailler et/ou revisiter des portions de la hiérarchie.

Deux structures (et types associés) sont définies dans le fichier d'inclusion <fts.h>. Le premier type est FTS, la structure qui représente la hiérarchie de fichiers elle-même. Le deuxième type est FTSENT, la structure qui représente un fichier dans la hiérarchie. Normalement, une FTSENT structure est renvoyée pour chaque fichier de la hiérarchie. Dans cette page manuelle, « fichier » et « structure FTSENT » sont généralement interchangeables.

La FTSENT structure contient des champs décrivant un fichier. La structure contient au moins les champs suivants (il existe des champs supplémentaires qui doivent être considérés comme privés à l'implémentation) :


typedef struct _ftsent {
    unsigned short  fts_info;     /* drapeaux pour la structure FTSENT */
    char           *fts_accpath;  /* chemin d'accès */
    char           *fts_path;     /* chemin racine */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* nom de fichier */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* profondeur (-1 à N) */
    int             fts_errno;    /* errno du fichier */
    long            fts_number;   /* valeur numérique locale */
    void           *fts_pointer;  /* valeur d'adresse locale */
    struct _ftsent *fts_parent;   /* répertoire parent */
    struct _ftsent *fts_link;     /* structure de fichier suivante */
    struct _ftsent *fts_cycle;    /* structure de cycle */
    struct stat    *fts_statp;    /* informations [l]stat(2) */
} FTSENT;

Ces champs sont définis comme suit :

fts_info
L'une des valeurs suivantes décrivant la structure FTSENT renvoyée et le fichier qu'elle représente. À l'exception des répertoires sans erreurs (FTS_D), toutes ces entrées sont terminales, c'est-à-dire qu'elles ne seront pas revisitées, et aucun de leurs descendants ne sera visité.
FTS_D
Un répertoire étant visité en préordre.
FTS_DC
Un répertoire qui cause un cycle dans l'arbre. (Le champ fts_cycle de la FTSENT structure sera également rempli.)
FTS_DEFAULT
Toute FTSENT structure représentant un type de fichier non explicitement décrit par l'une des autres valeurs fts_info .
FTS_DNR
Un répertoire qui ne peut pas être lu. C'est un retour d'erreur, et le fts_errno champ sera défini pour indiquer ce qui a causé l'erreur.
FTS_DOT
Un fichier nommé "." ou ".." qui n'a pas été spécifié comme nom de fichier pour fts_open() (voir FTS_SEEDOT).
FTS_DP
Un répertoire étant visité en postordre. Le contenu de la FTSENT structure sera inchangé par rapport à son renvoi en préordre, c'est-à-dire avec le fts_info champ défini à FTS_D.
FTS_ERR
C'est un retour d'erreur, et le fts_errno champ sera défini pour indiquer ce qui a causé l'erreur.
FTS_F
Un fichier régulier.
FTS_NS
Un fichier pour lequel aucune informationl]stat(2) n'était disponible. Le contenu du champ fts_statp est indéfini. C'est un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_NSOK
Un fichier pour lequel aucune informationl]stat(2) n'a été demandée. Le contenu du champ fts_statp est indéfini.
FTS_SL
Un lien symbolique.
FTS_SLNONE
Un lien symbolique avec une cible inexistante. Le contenu du champ fts_statp fait référence aux informations de caractéristiques du fichier pour le lien symbolique lui-même.
fts_accpath
Un chemin pour accéder au fichier depuis le répertoire courant.
fts_path
Le chemin du fichier par rapport à la racine du parcours. Ce chemin contient le chemin spécifié à fts_open() comme préfixe.
fts_pathlen
La somme des longueurs des chaînes référencées par fts_path et fts_name.
fts_name
Le nom du fichier.
fts_namelen
La longueur de la chaîne référencée par fts_name.
fts_level
La profondeur du parcours, numérotée de -1 à N, où ce fichier a été trouvé. La FTSENT structure représentant le parent du point de départ (ou de la racine) du parcours est numérotée -1, et la FTSENT structure pour la racine elle-même est numérotée 0.
fts_errno
Si fts_children() ou fts_read() renvoie une FTSENT structure dont le champ fts_info est défini à FTS_DNR, FTS_ERR, ou FTS_NS, le champ fts_errno contient le numéro d'erreur (c'est-à-dire la valeur errno ) spécifiant l'erreur. Sinon, le contenu du champ fts_errno est indéfini.
fts_number
Ce champ est fourni pour l'utilisation du programme d'application et n'est pas modifié par les fonctions fts. Il est initialisé à 0.
fts_pointer
Ce champ est fourni pour l'utilisation du programme d'application et n'est pas modifié par les fonctions fts. Il est initialisé à NULL.
fts_parent
Un pointeur vers la FTSENT structure référençant le fichier dans la hiérarchie immédiatement au-dessus du fichier courant, c'est-à-dire le répertoire dont ce fichier est membre. fts_close()

La fts_close() fonction ferme le flux de hiérarchie de fichiers référencé par ftsp et restaure le répertoire courant au répertoire à partir duquel fts_open() a été appelé pour ouvrir ftsp. La fonction fts_close() renvoie 0 en cas de succès, et -1 si une erreur survient.

ERREURS

La fonction fts_open() peut échouer et définir errno pour l'une des erreurs spécifiées pour open(2) et malloc(3).

De plus, fts_open() peut échouer et définir errno comme suit :

ENOENT
N'importe quel élément de path_argv était une chaîne vide.

La fonction fts_close() peut échouer et définir errno pour l'une des erreurs spécifiées pour chdir(2) et close(2).

Les fonctions fts_read() et fts_children() peuvent échouer et définir errno pour l'une des erreurs spécifiées pour chdir(2), malloc(3), opendir(3), readdir(3), et [l]stat(2).

De plus, fts_children(), fts_open(), et fts_set() peuvent échouer et définir errno comme suit :

EINVAL
options ou instr était invalide.
