FROTZ(6) Manuel des jeux FROTZ(6)

NOM

frotz - interpréteur pour les jeux Infocom et autres jeux Z-Machine

SYNTAXE

frotz [options] fichier [fichier_blorb]

Au moins un fichier doit être spécifié sur la ligne de commande. Il peut s'agir d'un fichier de code Z brut ou d'un fichier Blorb. Un fichier de code Z est un exécutable compilé pour la Z-Machine. Un fichier Blorb contient de l'audio, des graphiques et d'autres éléments en plus du jeu, le tout regroupé dans un seul fichier. Il peut également contenir facultativement l'exécutable Z-Machine. Si un fichier de code Z brut est fourni, Frotz vérifiera un fichier Blorb portant le même nom de base mais une extension de .blb, .blorb, ou .zblorb et le chargera s'il est trouvé.

Si le fichier fourni sur la ligne de commande est un fichier Blorb, Frotz vérifiera si un fichier de code Z y est contenu. S'il n'est pas trouvé, Frotz se plaindra et quittera.

Un fichier Blorb portant un nom alternatif peut être fourni comme second paramètre facultatif à l'invocation de la ligne de commande.

Si vous souhaitez jouer à l'un des jeux d'Infocom qui utilisent le son ou les graphiques, vous devrez obtenir un fichier Blorb correspondant auprès de l'Interactive Fiction Archive. Voir INFORMATIONS COMPLÉMENTAIRES ci-dessous.

DESCRIPTION

Frotz est un interpréteur Z-Machine. La Z-machine est une machine virtuelle conçue par Infocom pour exécuter toutes leurs aventures textuelles. Elle a subi plusieurs révisions pendant la durée de vie de l'entreprise, et deux révisions supplémentaires (V7 et V8) ont été créées par Graham Nelson après la disparition de la société. La spécification est maintenant bien documentée ; cette version de Frotz prend en charge la version 1.1. Voir NORMES Z-MACHINE ci-dessous.

Cette version de Frotz prend entièrement en charge toutes ces versions de la Z-Machine, à l'exception de la version 6. La version 6 est partiellement prise en charge en affichant les contours des graphiques V6 avec le numéro de l'image dans le coin inférieur droit.

OPTIONS

-a
Surveiller l'assignation d'attributs. L'assignation et la suppression d'attributs sur les objets seront notées dans les messages de débogage.
-A
Surveiller le test d'attributs. Chaque fois que la Z-machine teste la valeur d'un attribut, le test et son résultat seront rapportés.
-b <nom_couleur>
Définit la couleur de fond par défaut. <nom_couleur> correspond à l'une des couleurs de la Z-machine, qui sont les suivantes :
    noir rouge vert jaune bleu magenta cyan blanc
Si la prise en charge des couleurs est désactivée ou non disponible sur votre terminal, cette option ne fait rien.
-c N
Définit le nombre de lignes de contexte utilisées. Par défaut, après une invite ''[PLUS]'', et en supposant qu'il y a suffisamment de sortie en attente, Frotz permettra à toutes les lignes visibles actuelles de défiler hors de l'écran avant de demander à nouveau. Ce commutateur spécifie combien de lignes de texte Frotz conservera et affichera en haut de l'écran suivant.
-d
Désactiver la couleur.
-e
Activer le son. Si vous avez désactivé le son dans un fichier de configuration et que vous souhaitez entendre les effets sonores, utilisez cette option.
-E <mode>
Mode d'emphase. <mode> correspond à l'une des trois méthodes possibles pour rendre le texte accentué. Les choix possibles sont les suivants :
    italique souligné aucun
Infocom a créé un STYLE_EMPHASIS pour la Z-machine, qui était censé rendre le texte souligné ou italique. Ce qu'il faut faire exactement est laissé à l'interpréteur. Certaines plateformes/terminaux pouvaient supporter l'un, les deux, ou aucun. Le soulignement était plus courant que l'italique. Cette option vous permet de choisir comment le STYLE_EMPHASIS est affiché.
-f <nom_couleur>
Définit la couleur de premier plan par défaut. <nom_couleur> correspond à l'une des couleurs de la Z-machine, qui sont les suivantes :
    noir rouge vert jaune bleu magenta cyan blanc
Si la prise en charge des couleurs est désactivée ou n'est pas disponible sur votre terminal, cette option ne fait rien.
-F
Forcer le mode couleur. Si vous avez désactivé la couleur dans un fichier de configuration et que vous souhaitez que Frotz affiche les couleurs, utilisez cette option.
-h N
Définit manuellement la hauteur du texte. Bien que la plupart des bibliothèques curses soient suffisamment intelligentes pour déterminer la largeur actuelle à partir du terminal, il peut parfois être nécessaire d'utiliser cette option pour remplacer la valeur par défaut.
-i
Ignorer les erreurs fatales. Si un interpréteur Z-Machine rencontre une erreur de zcode telle qu'une division par zéro ou un accès à un objet illégal, la réponse appropriée est d'arrêter l'exécution. Ceci est fait car le programme zcode n'a pas une idée claire de ce qui se passe. Il existe des jeux qui provoquent des erreurs fatales parce que les auteurs étaient négligents et utilisaient un interpréteur qui ne vérifiait pas correctement les erreurs. Cette option est destinée à contourner de tels bugs, mais attention, des choses étranges peuvent se produire si les erreurs fatales ne sont pas interceptées.
-I N
Définit le numéro de l'interpréteur. Infocom a conçu la Z-machine de telle sorte qu'un jeu puisse savoir sur quel type de machine tournait l'interpréteur. Voir NUMÉRO D'INTERPRÉTEUR ci-dessous.
-l N
Définit la marge gauche, pour ceux qui pourraient avoir des besoins de formatage spécifiques.
-L <nom_fichier>
Lorsque le jeu démarre, charge ce fichier de sauvegarde.
-m
Activer la prise en charge de la souris. Naturellement, celle-ci est assez limitée, mais elle est disponible pour ceux qui souhaitent l'expérimenter. Lorsqu'elle est active, la souris ne peut pas être utilisée pour copier du texte depuis le terminal.
-o
Surveiller le mouvement des objets. Cette option active les messages de débogage de l'interpréteur qui décrivent le mouvement des objets dans l'arbre des objets.
-O
Surveiller la localisation des objets. Ces messages de débogage détaillent les emplacements des objets dans l'arbre des objets.
-p
Sortie ASCII simple uniquement. Ceci inhibe la sortie des lettres accentuées et d'autres caractères de l'ensemble de caractères Latin-1, les remplaçant par des alternatives raisonnables. Cela peut être nécessaire sur des appareils dépourvus de ces caractères. Les diphtongues OE/oe sont absentes de l'ensemble Latin-1. Celles-ci sont également gérées.
-P
Modifier l'opcode @piracy. L'opcode @piracy n'a jamais été utilisé par Infocom. Ce commutateur est vraiment utile uniquement pour ceux qui aiment expérimenter avec le code Z.
-q
Silencieux. Désactive les effets sonores. Utile lorsque vous exécutez Frotz sur une machine distante et que vous ne voulez pas déranger la personne près de la console avec des bruits étranges.
-r N
Définit la marge droite.
-R <chemin>
Lecture/écriture restreinte. La lecture et l'écriture de fichiers seront limitées au chemin fourni. Normalement, Frotz écrira ou lira ses sauvegardes, ses transcriptions et ses enregistrements de mouvements dans le chemin ou le répertoire que l'utilisateur fournit lorsque les commandes SAVE, SCRIPT, ou RECORDING sont données. Cela peut être indésirable si Frotz est exécuté dans un environnement restreint, par une interface utilisateur, ou par un robot. Cette option fera que Frotz n'écrira ou ne lira qu'à l'emplacement fourni et nulle part ailleurs. Le processus de contrôle pourra alors surveiller ce répertoire pour les changements et n'aura pas à s'inquiéter de quelqu'un qui griffonne ou fouine je-ne-sais-où.
-s N
Définit la valeur de la graine du générateur de nombres aléatoires. La valeur de graine donnée est utilisée comme valeur de graine initiale à chaque redémarrage. Par défaut, le générateur de nombres aléatoires est initialisé en fonction de l'horloge système ; cela vous permet de rendre le générateur de nombres aléatoires prévisible, pour une utilisation dans des scripts enregistrés ou pour le débogage. Par exemple, Curses prend des décisions aléatoires avant la première entrée (de sorte que la touche raccourcie Alt-S n'aide pas vraiment).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

"#t">-t
Définit le bit Tandy de la Z-machine, ce qui peut affecter le comportement de certains jeux Infocom. Par exemple, Zork I fait semblant de ne pas avoir de suites, et Witness a son langage atténué.
-u N
Définit le nombre d'emplacements disponibles pour la touche de raccourci d'annulation multiple de Frotz (voir ci-dessous). La valeur par défaut est 25, ce qui devrait être suffisant pour la plupart des cas. Définir un nombre trop élevé ici peut être dangereux sur les machines à mémoire limitée.
-w N
Définit manuellement la largeur du texte.
-x
Développe les abréviations "g", "x" et "z" en "again", "examine" et "wait". Ce commutateur est destiné à être utilisé avec les anciens jeux Infocom qui n'ont pas ces abréviations courantes qui ont été introduites dans les jeux ultérieurs. Utilisez-le avec prudence : quelques jeux pourraient utiliser "g", "x" ou "z" à des fins différentes.
-v
Affiche les informations de version et quitte. Cela affichera la version de Frotz, des informations sur ce qui est activé et ce qui ne l'est pas, la date de validation du code source, et un hash git(1) de cette validation.
-Z N
Mode de vérification des erreurs.
0 = ne pas signaler les erreurs.
1 = signaler la première instance d'une erreur.
2 = signaler toutes les erreurs.
3 = quitter après toute erreur.
La valeur par défaut est 1 (signaler la première instance d'une erreur).

TOUTES LES TOUTES LES TOUTES LES CLÉS

Ces touches d'accès rapide ne sont activées que lorsque la Z-machine attend une entrée de ligne (pour les experts de la Z-machine : l'opcode @read).

Alt-D Définir les options de débogage.
Alt-H Aide (afficher la liste des touches d'accès rapide).
Alt-N Nouveau jeu (redémarrer).
Alt-P Lecture activée.
Alt-R Enregistrement activé/désactivé.
Alt-S Définir la graine du générateur de nombres aléatoires.
Alt-U Annuler un tour.
Alt-X Quitter le jeu (après confirmation).

NUMÉRO_INTERPRÈTE

Le numéro de l'interpréteur est un paramètre dans l'en-tête de la Z-machine qui est utilisé pour indiquer au jeu sur quel type de machine l'interpréteur s'exécute. Frotz choisira automatiquement le numéro le plus approprié pour un jeu Infocom donné. Si vous souhaitez outrepasser ce numéro, l'option -I est disponible.

Un interpréteur doit choisir le numéro d'interpréteur le plus adapté à la machine sur laquelle il s'exécutera. Dans les versions jusqu'à 5, la principale considération est que le comportement de 'Beyond Zork' dépend du numéro d'interpréteur (en termes d'utilisation de la police graphique de caractères). Dans la version 6, la décision est plus sérieuse, car les fichiers d'histoire Infocom existants dépendent du numéro d'interpréteur de nombreuses manières ; de plus, certains fichiers d'histoire s'attendent à n'être exécutés que sur les interpréteurs d'une machine particulière. Il existe, par exemple, des versions spécifiquement Amiga. Le DECSystem-20 était le propre ordinateur central interne d'Infocom.

Pour les quatre jeux V6 d'Infocom, le numéro d'interpréteur sera choisi automatiquement en fonction du titre et du numéro de publication. Bien entendu, cela peut être outrepassé en ligne de commande.

Infocom utilisait les numéros d'interpréteur suivants :

1  DECSystem 20
2  Apple IIe
3  Macintosh
4  Amiga
5  Atari ST
6  IBM PC
7  Commodore 128
8  Commodore 64
9  Apple IIc
10 Apple IIgs
11 Tandy Color

FICHIERS_DE_CONFIGURATION

Au démarrage, Frotz vérifiera d'abord la configuration du système frotz.conf, puis $HOME/.frotzrc pour obtenir des informations de configuration. Le fichier de configuration utilise une syntaxe simple de

<variable> <espace blanc> <valeur>

Les noms de couleur peuvent être l'un des suivants :

black | red | green | blue | magenta | cyan | white

ascii   on | off
Utiliser uniquement l'ASCII brut. La valeur par défaut est "off".

background   <nom_de_couleur>
Définit la couleur d'arrière-plan. La valeur par défaut est la couleur d'arrière-plan par défaut du terminal.

color   yes | no
Utiliser le texte en couleur. La valeur par défaut est "yes" si elle est prise en charge.

errormode   never | once | always | fatal
Définit le mode de signalement des erreurs.

never Ne pas signaler d'erreurs, sauf les erreurs fatales.
once Signaler uniquement la première occurrence d'une erreur.
always Signaler chaque occurrence d'une erreur.
fatal Arrêter en cas d'erreur, même non fatale.
La valeur par défaut est "once".

expand_abb   on | off
Développe les abréviations. La valeur par défaut est "off". Développe les abréviations "g", "x" et "z" en "again", "examine" et "wait". Ce commutateur est destiné à être utilisé avec les anciens jeux Infocom qui n'ont pas ces abréviations courantes qui ont été introduites dans les jeux ultérieurs. Utilisez-le avec prudence. Quelques jeux pourraient utiliser "g", "x" ou "z" à des fins différentes.

foreground   <nom_de_couleur>
Définit la couleur du premier plan. La valeur par défaut est la couleur du premier plan par défaut du terminal.

ignore_fatal   on | off
Ignorer les erreurs fatales. Si un interpréteur de Z-Machine rencontre une erreur zcode telle qu'une division par zéro ou un accès à un objet illégal, la réponse appropriée est d'arrêter l'exécution. Ceci est fait parce que le programme zcode n'a pas une idée claire de ce qui se passe. Il existe des jeux qui provoquent des erreurs fatales parce que les auteurs ont été négligents et ont utilisé un interpréteur qui ne vérifiait pas correctement les erreurs. Cette option est destinée à contourner de tels bugs, mais attention, des choses étranges peuvent se produire si les erreurs fatales ne sont pas interceptées.
La valeur par défaut est "off".

piracy   on | off
Modifier l'opcode de piratage. La valeur par défaut est "off". L'opcode de piratage n'a jamais été utilisé par Infocom. Cette option est uniquement utile pour ceux qui aiment jouer avec le z-code.

randseed   <entier>
Définit la graine du générateur de nombres aléatoires. La valeur par défaut provient de l'époque Unix.

sound   on | off
Activer ou désactiver les effets sonores. La valeur par défaut est "on".

tandy   on | off
Définit le bit Tandy de la machine. Cela peut affecter le comportement de certains jeux Infocom. Par exemple, Zork I fait semblant de ne pas avoir de suites, et Witness a son langage atténué. La valeur par défaut est "off".

undo_slots   <entier>
Définit le nombre d'emplacements d'annulation. La valeur par défaut est 500.

zcode_path   /chemin/vers/fichiers/zcode:/un/autre/chemin
Définit le chemin à rechercher pour les fichiers de jeu zcode. C'est tout comme la variable d'environnement $PATH, sauf que vous ne pouvez pas mettre de variables d'environnement dans le chemin ni utiliser d'autres raccourcis. Par exemple, "$HOME/games/zcode" est illégal car le shell ne peut pas interpréter la variable $HOME.

Les options suivantes sont vraiment utiles uniquement pour les terminaux inhabituels, les bibliothèques curses inhabituelles ou si vous souhaitez forcer un certain rendu (comme jouer en mode 40 colonnes).

context_lines   <entier>
Définit le nombre de lignes de contexte utilisées. Par défaut, après une invite "[MORE]", et en supposant qu'il y ait suffisamment de sortie en attente, Frotz permettra à toutes les lignes actuellement visibles de défiler hors de l'écran avant de demander à nouveau. Ce commutateur spécifie le nombre de lignes de texte que Frotz conservera et affichera en haut de l'écran suivant. La valeur par défaut est "0".

left_margin   <entier>
Définit la marge gauche. Ceci est pour ceux qui pourraient avoir des besoins de formatage spéciaux.

right_margin   <entier>
Définit la marge droite. Ceci est pour ceux qui pourraient avoir des besoins de formatage spéciaux.

text_height   <entier>
Définit manuellement la hauteur du texte. La plupart des bibliothèques curses sont suffisamment intelligentes pour déterminer la largeur actuelle du terminal. Vous devrez peut-être utiliser cette option pour outrepasser la valeur par défaut.

text_width   <entier>
Définit manuellement la largeur du texte. Encore une fois, cela ne devrait pas être nécessaire sauf dans des circonstances particulières.

script_width   <entier>
Définit la largeur du script. La valeur par défaut est de 80 colonnes par ligne, indépendamment de la largeur du texte actuelle. Ce commutateur vous permet de modifier ce paramètre. Vous pouvez le définir sur "0" pour désactiver le fractionnement automatique des lignes dans les fichiers de script.

Les options suivantes sont principalement utiles pour le débogage ou la triche.

attrib_set   on | off
Surveiller la définition des attributs. La définition et la suppression d'attributs sur les objets seront signalées dans les messages de débogage. La valeur par défaut est "off".

attrib_test   on | off
Surveiller le test des attributs. Chaque fois que la Z-machine teste la valeur d'un attribut, le test et le résultat seront signalés. La valeur par défaut est "off".

obj_loc   on | off
Surveiller la localisation des objets. Ces messages de débogage détaillent les emplacements des objets dans l'arbre d'objets. La valeur par défaut est "off".

obj_move   on | off
Surveiller le mouvement des objets. Cette option active les messages de débogage de l'interpréteur qui décrivent le mouvement des objets dans l'arbre d'objets. La valeur par défaut est "off".

COULEUR

Le fait que Frotz affiche ou non la couleur dépend de la bibliothèque curses et du terminal. En général, un xterm ou un autre émulateur de terminal basé sur X11 prendra en charge la couleur. Parfois, la valeur de $TERM devra être définie sur quelque chose comme "xterm-color" ou "rxvt-256color". Pour un Li

nux, $TERM est presque toujours défini sur "linux". Cela prendra en charge la couleur. Pour une console NetBSD ou OpenBSD sur un x86 ou amd64, la valeur par défaut de $TERM est "vt100". Pour que la couleur soit prise en charge, vous devez définir $TERM sur "pc3". La console FreeBSD a $TERM défini sur "xterm" et prendra en charge la couleur. La couleur sur les consoles texte des machines autres que x86 ou amd64 n'a pas été testée.

Sur certains systèmes d'exploitation, Xterm ne modifiera pas la couleur du curseur pour qu'elle corresponde à celle du texte. Pour résoudre ce problème, ajoutez la ligne suivante à votre fichier .Xresources et tapez xrdb -merge $HOME/.Xresources

xterm*cursorColor: *XtDefaultForeground

Ceci peut également être ajouté à un fichier système tel que /etc/X11/Xresources/x11-common ou /etc/X11/app-defaults/XTerm. Les noms et les emplacements des fichiers système peuvent varier d'un OS à l'autre.

UNICODE

Frotz prend en charge les glyphes Unicode via UTF-8 si le terminal utilisé prend en charge UTF-8. Si vous préférez utiliser xterm, lancez-le comme uxterm . C'est un script wrapper qui configure xterm avec l'environnement UTF-8. Vous pouvez également dire manuellement à un xterm de passer en mode UTF-8 en maintenant CTRL et le bouton droit de la souris pour afficher le menu VT FONTS. Selon la façon dont xterm a été installé, vous pourriez voir une option pour "UTF-8 Fonts" qui permettra à Unicode d'être correctement affiché.

Faire en sorte que xterm normal se comporte toujours ainsi peut varier d'un système à l'autre. D'autres émulateurs de terminal ont leurs propres moyens d'être configurés pour utiliser l'encodage de caractères UTF-8.

CARACTERES NON ASCII

Les glyphes non ASCII peuvent être affichés sans utiliser UTF-8 via les jeux de caractères ISO-8859-1 ou ISO-8859-15 (Latin-1 ou Latin-9). ISO-8859-15 est plus ou moins identique à ISO-8859-1 sauf que les diphtongues OE/oe sont prises en charge, remplaçant les glyphes peu utilisés 1/2 et 1/4. Voir aussi luit(1) charsets(7) iso_8859-1(7) et iso_8859-15(7) pour plus d'informations.

LOCALE

Un moyen important de s'assurer que le système sait utiliser UTF-8 est de s'assurer que la locale est correctement définie. Ceci n'est valable que lorsque Dumb Frotz s'exécute sous des systèmes de type Unix.

Utiliser la commande locale vous indiquera ce qui est actuellement utilisé. Utiliser locale -a vous montrera ce qui est disponible. Ensuite, définissez votre variable d'environnement LANG sur quelque chose de approprié en utilisant l'une de ces commandes :

export LANG=C.UTF-8 export LANG=en_US.utf8

Cela peut être mis dans votre fichier de configuration de shell, qu'il s'agisse de .profile, .bash_profile, .login, .bashrc, ou autre.

Cela peut également être défini au niveau du système dans les fichiers équivalents de /etc.

NORMES Z-MACHINE

Frotz est conforme à la norme Z-Machine 1.1 de mai 2006, révisée en février 2014. La version faisant autorité se trouve ici :
http://inform-fiction.org/zmachine/standards/z1point1/index.html

À partir de la version 1.1, un paramètre facultatif supplémentaire prompt est autorisé sur les sauvegardes/restaurations étendues de la version 5. Ce paramètre permet à un jeu de lire ou d'écrire un fichier auxiliaire (aux) sans demander au joueur. Voir la section 15 de la norme pour plus de détails. Frotz limite ces fichiers à avoir l'extension de nom de fichier ".aux". Lorsque l'option -R (lecture/écriture restreinte) est active, les lectures et écritures via ce mécanisme sont limitées au chemin fourni, comme toutes les autres opérations sur les fichiers.

ENVIRONNEMENT

Si la variable d'environnement ZCODE_PATH est définie, Frotz recherchera ce chemin pour les fichiers de jeu. Si cela n'existe pas, INFOCOM_PATH sera recherché. Tous les fichiers supplémentaires requis, tels que les fichiers auxiliaires ou blorb, doivent se trouver dans le même répertoire où Frotz trouve le fichier d'histoire.

Pour que la touche Alt soit lue correctement dans un Xterm, les lignes suivantes doivent figurer dans votre fichier .Xresources :

XTerm*metaSendsEscape: true
XTerm*eightBitInput: false

CAVEATS

La Z Machine elle-même a du mal avec le concept de redimensionnement d'un terminal. Elle suppose qu'une fois la hauteur et la largeur du texte définies, elles ne changeront jamais ; même entre les sauvegardes. Cela avait du sens lorsque les terminaux 24x80 étaient la norme et que les interfaces graphiques étaient pour la plupart inconnues. Je suis à peu près sûr qu'il existe un moyen de contourner ce problème, mais pour l'instant, ne redimensionnez pas un xterm dans lequel Frotz est en cours d'exécution. De plus, vous devriez essayer de vous assurer que le terminal sur lequel vous restaurez une partie sauvegardée a les mêmes dimensions que celui sur lequel vous avez sauvegardé la partie.

La latence audio peut être déraisonnablement longue en fonction des paramètres de votre système d'exploitation. Linux a généralement les choses en ordre. Les BSD peuvent nécessiter des ajustements des paramètres sysctl(8). Voir les pages de manuel sound(4) ou audio(4) pour plus d'informations.

Vous pouvez utiliser un chemin tel que /usr/local/games/zcode:$HOME/zcode avec $ZCODE_PATH ou $INFOCOM_PATH car le shell digérera cette variable $HOME pour vous avant de définir $ZCODE_PATH. Lors du traitement de frotz.conf et $HOME/.frotzrc, un shell n'est pas utilisé. Par conséquent, vous ne pouvez pas utiliser de variables d'environnement dans l'option zcodepath dans les fichiers de configuration.
