ÉVÉNEMENTS

access
Un fichier surveillé a été accédé.
modify
Un fichier surveillé a été modifié. Cette notification est envoyée après la fermeture du fichier et est envoyée une seule fois, même si le fichier est modifié plusieurs fois.
attrib
Les métadonnées d'un fichier surveillé ont été modifiées. Cela inclut des choses comme les permissions, le propriétaire, le groupe, etc. Cette notification est envoyée après la fermeture du fichier.
close_write
Un fichier surveillé a été ouvert en écriture et fermé. Si un fichier est ouvert en écriture plusieurs fois, alors cela ne sera signalé qu'une seule fois.
close_nowrite
Un fichier surveillé a été ouvert en lecture seule et fermé. Si un fichier est ouvert en lecture seule plusieurs fois, alors cela ne sera signalé qu'une seule fois.
close
Un fichier surveillé a été fermé. Cette notification est un alias pour la combinaison de close_write et close_nowrite.
open
Un fichier surveillé ou un fichier dans un répertoire surveillé a été ouvert.
moved_to
Un fichier ou un répertoire a été déplacé dans un répertoire surveillé. Cet événement se produit même si le fichier est simplement déplacé de et vers le même répertoire.
moved_from
Un fichier ou un répertoire a été déplacé hors d'un répertoire surveillé. Cet événement se produit même si le fichier est simplement déplacé de et vers le même répertoire.
move
Un fichier ou un répertoire a été déplacé depuis ou vers un répertoire surveillé. Notez que ceci est en fait implémenté simplement en écoutant à la fois moved_to et moved_from, donc tous les événements de fermeture reçus seront émis comme un ou les deux de ceux-ci, pas MOVE.
move_self
Un fichier ou un répertoire surveillé a été déplacé. Après cet événement, le fichier ou le répertoire n'est plus surveillé.
create
Un fichier ou un répertoire a été créé dans un répertoire surveillé.
delete
Un fichier ou un répertoire dans un répertoire surveillé a été supprimé.
delete_self
Un fichier ou un répertoire surveillé a été supprimé. Après cet événement, le fichier ou le répertoire n'est plus surveillé. Notez que cet événement peut se produire même s'il n'est pas explicitement écouté.
unmount
Le système de fichiers sur lequel réside un fichier ou un répertoire surveillé a été démonté. Après cet événement, le fichier ou le répertoire n'est plus surveillé. Notez que cet événement peut se produire même s'il n'est pas explicitement écouté.

CAVEATS

Lors de l'utilisation d'inotifywatch, le nom de fichier qui est généré n'est pas garanti d'être à jour après un déplacement, car c'est l'inode qui est surveillé. De plus, aucune des opérations observées n'est garantie d'avoir été effectuée sur le nom de fichier qu'inotifywatch a reçu l'instruction de surveiller dans les cas où le fichier est connu sous plusieurs noms dans le système de fichiers.

BUGS

Il existe des conditions de concurrence dans le code de surveillance récursive des répertoires qui peuvent entraîner la perte d'événements s'ils se produisent dans un répertoire immédiatement après la création de ce répertoire. Ce n'est probablement pas corrigeable.

Il est supposé que la file d'attente des événements inotify ne débordera jamais.
