fish écrit diverses séquences de contrôle vers le terminal. Certaines doivent être implémentées pour activer les fonctionnalités de base, tandis que d'autres permettent des fonctionnalités optionnelles et peuvent être ignorées par le

terminal.

Le terminal doit être capable d'analyser les commandes Control Sequence Introducer (CSI), Operating System Commands (OSC) et, en option, Device Control Strings (DCS). Celles-ci sont définies par ECMA-48. Si une séquence CSI, OSC ou DCS valide ne représente pas une commande implémentée par le terminal, le terminal doit

l'ignorer.

Les séquences de contrôle sont notées dans une syntaxe de type fish. Les caractères spéciaux autres que \ ne sont pas échappés. Des espaces ne sont ajoutés que pour la lisibilité et ne font pas partie de la séquence. Les emplacements de substitution sont écrits comme Ps pour un nombre ou Pt pour une chaîne imprimable

arbitraire.

REMARQUE : fish ne repose pas sur la base de données terminfo de votre système. Dans ce document, les codes terminfo (TI) sont inclus uniquement à titre de

référence.

COMMANDES DCS ET GNU

SCREEN

L'analyse DCS entièrement correcte est facultative car fish bascule vers l'écran alternatif avant d'imprimer toute commande DCS. Cependant, puisque GNU screen n'autorise ni l'activation du tampon d'écran alternatif par défaut, ni le traitement des commandes DCS de manière compatible, l'invite initial de fish peut être corrompu par une charge utile DCS comme +q696e646e. Pour l'instant, fish contourne cela en vérifiant la présence de la variable d'environnement STY. Si cela ne fonctionne pas pour une raison quelconque, vous pouvez ajouter cela à votre ~/.screen

rc : 
alt
scr
een
on

Ou ajoutez cela à votre config.fi

sh : 
function GNU-screen-workar
ound --on-event fish_prom
pt commandline -f repa
int functions --erase
GNU-screen-workaround end
