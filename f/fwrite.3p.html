FWRITE(3P) Manuel du programmeur POSIX FWRITE(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

fwrite — sortie binaire

SYNTAXE

#include <stdio.h>
size_t fwrite(const void *restrict ptr, size_t size, size_t nitems,
    FILE *restrict stream);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 renvoie à la norme ISO C.

La fonction fwrite() écrit, depuis le tableau pointé par ptr, jusqu'à nitems éléments dont la taille est spécifiée par size, dans le flux pointé par stream. Pour chaque objet, size appels à la fonction fputc() sont effectués, en prenant les valeurs (dans l'ordre) d'un tableau de unsigned char qui recouvre exactement l'objet. L'indicateur de position de fichier du flux (s'il est défini) est avancé du nombre d'octets effectivement écrits. Si une erreur se produit, la valeur résultante de l'indicateur de position de fichier du flux est non spécifiée.

Les horodatages de dernière modification de données et de dernier changement de statut de fichier du fichier sont marqués pour mise à jour entre l'exécution réussie de fwrite() et la prochaine complétion réussie d'un appel à fflush() ou fclose() sur le même flux, ou un appel à exit() ou abort().

VALEUR DE RETOUR

La fonction fwrite() retourne le nombre d'éléments écrits avec succès, ce qui peut être inférieur à nitems si une erreur d'écriture est rencontrée. Si size ou nitems est 0, fwrite() retourne 0 et l'état du flux reste inchangé. Sinon, si une erreur d'écriture se produit, l'indicateur d'erreur du flux est positionné, et errno est défini pour indiquer l'erreur.

ERREURS

Voir fputc().

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

En raison de possibles différences dans la longueur des éléments et l'ordre des octets, les fichiers écrits avec fwrite() dépendent de l'application, et ne peuvent pas être lus avec fread() par une application différente ou par la même application sur un processeur différent.
