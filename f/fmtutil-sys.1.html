Recréer et gérer les fmts TeX et les bases Metafont, collectivement appelés ici « formats ». (MetaPost n'utilise plus les « mems », équivalents de l'époque.

)

Si l'on n'opère pas en mode mktexfmt, exactement une commande doit être donnée, les suffixes de nom de fichier ne doivent généralement pas être spécifiés, aucun argument non-option n'est autorisé, et plusieurs formats peuvent être

générés.

Si le nom de la commande se termine par mktexfmt, un seul format peut être créé. Les seules options prises en charge sont --help et --version, et la ligne de commande doit être soit un nom de format, avec extension, soit un nom simple qui est passé comme argument à --byfmt (voir ci-dessous). Le nom complet du fichier généré (s'il y en a un) est écrit sur la sortie standard, et rien d'autre. Les répertoires système sont utilisés s'ils sont accessibles en écriture, sinon les répertoires

utilisateur.

Par défaut, le code de retour est zéro

si tous les formats demandés sont
construits avec succès, sinon non nul.

Explication des arbres et fichiers normalement utilisés

:
Si --cnffile est spécifié sur la ligne de commande (éventuellement plusieurs fois), sa ou ses valeurs sont utilisées. Sinon, fmtutil lit tous les fichiers fmtutil.cnf trouvés en exécutant « kpsewhich -all fmtutil.cnf », dans l'ordre renvoyé par kpsewhich. Les fichiers spécifiés via --cnffile sont d'abord essayés en chargement direct, et s'ils ne sont pas trouvés et que les noms de fichiers ne contiennent pas de parties de répertoire, ils sont recherchés via
kpsewhich.
Dans tous les cas, si plusieurs fichiers fmtutil.cnf sont trouvés, toutes les définitions de format trouvées dans tous les fichiers fmtutil.cnf sont
fusionnées.

NOM

fmtutil-sys - Créer ou mettre à jour des formats TeX Live.

SYNOPIS

fmtutil-sys [options]

DESCRIPTION

La commande fmtutil-sys est une commande de script TeX Live qui crée ou met à jour des fichiers de formats pour un système.

Elle recherche les fichiers de configuration dans la hiérarchie des répertoires de configuration système TeX Live. La priorité est donnée aux fichiers listés en premier.

Voici l'ordre de priorité dans lequel les fichiers de configuration fmtutil.cnf sont recherchés :

1) Le fichier $TEXMFCONFIG/web2c/fmtutil.cnf.
2) Le fichier $TEXMFSYSCONFIG/web2c/fmtutil.cnf.
3) Le fichier $TEXMFDIST/web2c/fmtutil.cnf.

Si plusieurs fichiers de configuration sont présents, le premier trouvé est utilisé. Si aucun fichier de configuration n'est trouvé et que des modifications sont apportées, un nouveau fichier est créé dans $TEXMFCONFIG/web2c/fmtutil.cnf.

Le principe général est que si un fichier de configuration donné n'est pas accessible en écriture, un fichier de niveau supérieur peut être utilisé. Ainsi, les paramètres de la distribution peuvent être remplacés au niveau du système via TEXMFLOCAL, et les paramètres système peuvent être écrasés à nouveau dans le TEXMFHOME ou TEXMFCONF d'un utilisateur particulier.

Résolution des définitions multiples d'un format :

Si un format est défini dans plusieurs fichiers de configuration, la définition provenant du fmtutil.cnf listé en premier est utilisée.

Désactivation des formats :

Les fichiers fmtutil.cnf de priorité plus élevée (listés plus tôt) peuvent désactiver les formats des fichiers fmtutil.cnf de priorité inférieure (listés plus tard) en écrivant une ligne comme celle-ci dans le fichier fmtutil.cnf de priorité plus élevée :
#! <nom_fmt> <nom_moteur> <tiret> <args>
Le #! doit être au début de la ligne, avec au moins un espace ou une tabulation après, et il doit y avoir un espace entre chaque mot de la liste.
Par exemple, vous pouvez désactiver le format luajitlatex en créant le fichier $TEXMFCONFIG/web2c/fmtutil.cnf avec la ligne
#! luajitlatex luajittex language.dat,language.dat.lua lualatex.ini
(Il se trouve que les formats liés à luajittex sont précisément la raison pour laquelle l'option --no-error-if-no-engine existe, car luajittex ne peut pas être compilé sur toutes les plateformes. Donc, ce n'est pas nécessaire.)

fmtutil-user (fmtutil -user) vs fmtutil-sys (fmtutil -sys) :

Lorsque fmtutil-sys est exécuté ou que l'option de ligne de commande -sys est utilisée, TEXMFSYSCONFIG et TEXMFSYSVAR sont utilisés à la place de TEXMFCONFIG et TEXMFVAR, respectivement. C'est la principale différence entre fmtutil-sys et fmtutil-user.
Voir https://tug.org/texlive/scripts-sys-user.html pour plus de détails.
D'autres emplacements peuvent être utilisés si vous les spécifiez en ligne de commande, si ces arbres n'existent pas, ou si vous n'utilisez pas la version originale de TeX Live.

Prise en charge des binaires de développement :

Si un nom de moteur se termine par "-dev", les formats sont créés dans le répertoire respectif avec le "-dev" supprimé. Cela permet d'exécuter facilement des binaires de développement en parallèle avec les binaires publiés.
