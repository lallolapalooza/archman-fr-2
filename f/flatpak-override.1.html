NOM

flatpak-override - Modifier les exigences d'une application

SYNTAXE

flatpak override [OPTION...] [APP]

DESCRIPTION

Modifie les exigences d'exécution de l'application spécifiée. Ceci peut être utilisé pour accorder à une application sandboxée plus ou moins de ressources qu'elle n'en a demandé.

Par défaut, l'application obtient l'accès aux ressources qu'elle a demandées lorsqu'elle est lancée. Mais l'utilisateur peut le modifier sur une instance particulière en spécifiant des arguments supplémentaires à flatpak run, ou à chaque fois en utilisant flatpak override.

Les modifications d'application sont enregistrées dans des fichiers texte résidant dans $XDG_DATA_HOME/flatpak/overrides en mode utilisateur.

Si l'identifiant d'application APP n'est pas spécifié, alors les modifications affectent toutes les applications, mais les modifications par application peuvent outrepasser les modifications globales.

Sauf si elles sont outrepassées avec les options --user ou --installation, cette commande modifie l'installation système par défaut.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche les options d'aide et quitte.

-u, --user

Met à jour une installation par utilisateur.

--system

Met à jour l'installation système par défaut.

--installation=NOM

Met à jour une installation système spécifiée par NOM parmi celles définies dans /etc/flatpak/installations.d/. Utiliser --installation=default équivaut à utiliser --system.

--share=SUBSYSTEM

Partage un sous-système avec la session hôte. Cela modifie la section Contexte des métadonnées de l'application. SUBSYSTEM doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs fois.

--unshare=SUBSYSTEM

Ne partage pas un sous-système avec la session hôte. Cela modifie la section Contexte des métadonnées de l'application. SUBSYSTEM doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs fois.

--socket=SOCKET

Expose un socket bien connu à l'application. Cela modifie la section Contexte des métadonnées de l'application. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs fois.

--nosocket=SOCKET

N'expose pas un socket bien connu à l'application. Cela modifie la section Contexte des métadonnées de l'application. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs fois.

--device=DEVICE

Expose un périphérique à l'application. Cela modifie la section Contexte des métadonnées de l'application. DEVICE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs fois.

--nodevice=DEVICE

N'expose pas un périphérique à l'application. Cela modifie la section Contexte des métadonnées de l'application. DEVICE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs fois.

--allow=FEATURE

Autorise l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FEATURE doit être l'un des suivants : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs fois.

Voir flatpak-build-finish(1) pour la signification des différentes fonctionnalités.

--disallow=FEATURE

Interdit l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FEATURE doit être l'un des suivants : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs fois.

--filesystem=FILESYSTEM

Autorise l'accès de l'application à un sous-ensemble du système de fichiers. Cela modifie la section Contexte des métadonnées de l'application. FILESYSTEM peut être l'un des suivants : home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, xdg-run, xdg-config, xdg-cache, xdg-data, un chemin absolu, ou un chemin relatif au répertoire personnel comme ~/dir ou des chemins relatifs aux répertoires xdg, comme xdg-download/subdir. Le suffixe :ro optionnel indique que l'emplacement sera en lecture seule. Le suffixe :create optionnel indique que l'emplacement sera en lecture-écriture et sera créé s'il n'existe pas. Cette option peut être utilisée plusieurs fois. Voir la liste "[Context] filesystems" dans flatpak-metadata(5) pour les détails de la signification de ces systèmes de fichiers.

--nofilesystem=FILESYSTEM

Annule l'effet d'un précédent --filesystem=FILESYSTEM dans le manifeste de l'application ou une couche d'écrasement de priorité inférieure, et/ou supprime un précédent --filesystem=FILESYSTEM de cette couche d'écrasement. Cela modifie la section Contexte des métadonnées de l'application. FILESYSTEM peut prendre les mêmes valeurs que pour --filesystem, mais les suffixes :ro et :create ne sont pas utilisés ici. Cette option peut être utilisée plusieurs fois.

Cette option n'empêche pas l'accès à un --filesystem plus spécifiquement défini. Par exemple, si une application a l'équivalent de --filesystem=xdg-config/MyApp dans son manifeste ou comme écrasement système, et que flatpak override --user --nofilesystem=home est utilisé comme écrasement par utilisateur, alors elle sera empêchée d'accéder à la majeure partie du répertoire personnel, mais elle sera toujours autorisée à accéder à $XDG_CONFIG_HOME/MyApp.

À titre de cas spécial, --nofilesystem=host:reset ignorera toutes les permissions --filesystem héritées du manifeste de l'application ou d'une couche d'écrasement de priorité inférieure, en plus d'avoir le comportement de --nofilesystem=host.

--add-policy=SUBSYSTEM.KEY=VALUE

Ajoute une option de politique générique. Par exemple, "--add-policy=subsystem.key=v1 --add-policy=subsystem.key=v2" correspondra aux métadonnées suivantes : 
[Policy subsystem]
key=v1;v2;

Cette option peut être utilisée plusieurs fois.

--remove-policy=SUBSYSTEM.KEY=VALUE

Supprime une option de politique générique. Cette option peut être utilisée plusieurs fois.

--env=VAR=VALUE

Définit une variable d'environnement dans l'application. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--unset-env=VAR

Supprime une variable d'environnement dans l'application. Cela modifie l'entrée unset-environment dans le groupe [Context] des métadonnées, et le groupe [Environment]. Cette option peut être utilisée plusieurs fois.

--env-fd=FD

Lit les variables d'environnement à partir du descripteur de fichier FD, et les définit comme si elles étaient fournies via --env. Ceci peut être utilisé pour éviter que les variables d'environnement et leurs valeurs ne deviennent visibles par d'autres utilisateurs.

Chaque variable d'environnement est sous la forme VAR=VALUE suivie d'un octet nul. C'est le même format utilisé par env -0 et /proc/*/environ.

--own-name=NAME

Autorise l'application à posséder le nom bien connu NAME sur le bus de session. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--talk-name=NAME

Autorise l'application à communiquer avec le nom bien connu NAME sur le bus de session. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--no-talk-name=NAME

N'autorise pas l'application à communiquer avec le nom bien connu NAME sur le bus de session. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--system-own-name=NAME

Autorise l'application à posséder le nom bien connu NAME sur le bus système. Si NAME se termine par .*, cela autorise l'application à posséder tous les noms correspondants. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--system-talk-name=NAME

Autorise l'application à communiquer avec le nom bien connu NAME sur le bus système. Si NAME se termine par .*, cela autorise l'application à communiquer avec tous les noms correspondants. Cela modifie la section Contexte des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--system-no-talk

-name=NO

M
Ne pas autoriser l'application à communiquer avec le nom bien connu NOM sur le bus système. Si NOM se termine par .*, cela autorise l'application à communiquer avec tous les noms correspondants. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--persist=NOMFICHIE

R
Si l'application n'a pas accès au vrai répertoire personnel, faire du chemin NOMFICHIER (relatif au répertoire personnel) un montage par liaison vers le chemin correspondant dans le répertoire propre à l'application, permettant ainsi à cet emplacement d'être utilisé pour des données persistantes. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--rese

t
Supprimer les surcharges. Si une APP est donnée, supprimer les surcharges pour cette application, sinon supprimer les surcharges
globales.

--sho

w
Afficher les surcharges. Si une APP est donnée, afficher les surcharges pour cette application, sinon afficher les surcharges
globales.

-v, --verbos

e
Afficher des informations de débogage pendant le traitement de la
commande.

--ostree-verbos

e
Afficher des informations de
débogage OSTree pendant le traitement de la commande.
