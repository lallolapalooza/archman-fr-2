DESCRIPTIO

N

Par défaut, aucune validation n'est effectuée sur les champs de formulaire. Vous pouvez associer un formulaire avec un type de champ, ce qui fait que la bibliothèque de formulaire valide la

saisie.

field_ar

g

Renvoie un pointeur vers le bloc d'arguments du champ. Le bloc d'arguments est une structure opaque contenant une copie des arguments fournis dans un appel à set_

field
_type.

field_typ

e

Renvoie un pointeur vers le type de champ associé au champ de formulaire, c'est-à-dire défini par un appel à set_field_typ

e
.

set_field_typ

e

La fonction set_field_type associe un type de champ à un champ de formulaire donné. C'est ce type qui est vérifié par les fonctions de validation. La plupart des types de champs sont configurables, via des arguments que l'appelant fournit lors de l'appel à set_field_type

.

Plusieurs types de

champs sont prédéfi
nis par la biblioth
èque de formulaire.

PRÉDÉFINIS

Il est possible de définir de nouveaux types de champs par le programmeur. Les types de champs sont implémentés via la structure de données FIELDTYPE, qui contient plusieurs pointeurs de

fonctions.

Voir la page manuelle form_fieldtype(3X), qui décrit les fonctions pouvant être utilisées pour construire un type de champ

dynamiquement.

Les types prédéfinis sont les suivants

TYPE_ENU

M

Accepte l'une des chaînes d'un ensemble spécifié. Paramètres requis

:
  • un troisième argument (char **) pointant vers une liste de chaînes
    • ;
  • un quatrième argument drapeau int pour activer la sensibilité à la
    • casse ;
  • un cinquième argument drapeau int spécifiant si une correspondance partielle doit être unique. Si ce drapeau est désactivé, un
    • préfixe correspond au premier élément de n'importe quel
ensemble de plus d'un élément de la liste ayant ce préfixe.

La bibliothèque copie la liste de chaînes, vous

pouvez donc utiliser une liste qui se trou

TYPE_INTEGE

R

Données entières, analysables en un entier par atoi(3). Paramètres requis

:
  • un troisième argument int contrôlant la
    • précision,
  • un quatrième argument long contraignant la valeur
    • minimale,
  • un cinquième argument long contraignant la valeur maximale. Si la valeur maximale est
    • inférieure ou égale à la valeur mini
male, la plage est simplement ignorée.

Au retour, le tampon du champ est formaté selon la spécification de format printf « .*ld », où le « * » est remplacé par l'argument de

précision.

Pour plus de détails sur le traitement de la précision, voir print

TYPE_NUMERI

C

Données numériques (peuvent avoir une partie décimale). Paramètres requis

:
  • un troisième argument int contrôlant la
    • précision,
  • un quatrième argument double contraignant la valeur
    • minimale,
  • et un cinquième argument double contraignant la valeur maximale. Si votre système prend en charge les locales, le caractère du point décimal doit être ce
    • lui spécifié par votre locale. Si la valeur maximale est inférieu
re ou égale à la valeur minimale, la plage est simplement ignorée.

Au retour, le tampon du champ est formaté selon la spécification de format printf « .*f », où le « * » est remplacé par l'argument de

précision.

Pour plus de détails sur le traitement de la précision, voir print

f(3
).

TYPE_REGEX

P

Données d'expression rationnelle. Paramètre requis

:
•
un troisième argument, une expression rationnelle (char *) chaîne. Les données sont vali
des si l'expression r
ationnelle correspond.

Les expressions rationnelles sont au format de regcomp et regexec

.

L'expression rationnelle doit correspondre à l'ensemble du champ. Si vous avez par exemple un champ de huit caractères de large, une expression rationnelle "^

[0-9]*$" signifie toujours que vous devez remplir les huit positions avec des chiffres. Si vous voulez autoriser moins de chiffres, vous pouvez utiliser par exempl
e "^[0-9]* *$" qui convient aux espaces de fin (jusqu'à un champ vide), ou "^ *[0-9]* *$" qui convient aux espaces de début et de fin autour des chiffres.
