VERSIONS

Le champ f_fsid

Solaris, Irix et POSIX ont un appel système statvfs(2) qui renvoie une struct statvfs (définie dans <sys/statvfs.h>) contenant un unsigned long f_fsid. Linux, SunOS, HP-UX, 4.4BSD ont un appel système statfs() qui renvoie une struct statfs (définie dans <sys/vfs.h>) contenant un fsid_t f_fsid, où fsid_t est défini comme struct { int val[2]; }. Il en va de même pour FreeBSD, à la différence qu'il utilise le fichier d'inclusion <sys/mount.h>.

L'idée générale est que f_fsid contient des informations aléatoires telles que la paire (f_fsid,ino) détermine de manière unique un fichier. Certains systèmes d'exploitation utilisent (une variation de) le numéro de périphérique, ou le numéro de périphérique combiné avec le type de système de fichiers. Plusieurs systèmes d'exploitation restreignent la divulgation du champ f_fsid au superutilisateur uniquement (et le mettent à zéro pour les utilisateurs non privilégiés), car ce champ est utilisé dans le descripteur de fichier du système de fichiers lorsqu'il est exporté via NFS, et sa divulgation pose un problème de sécurité.

Sous certains systèmes d'exploitation, le fsid peut être utilisé comme second argument à l'appel système sysfs(2).

HISTORIQUE

Le statfs() de Linux s'est inspiré de celui de 4.4BSD (mais ils n'utilisent pas la même structure).

Les appels système statfs() et fstatfs() d'origine sous Linux n'étaient pas conçus pour prendre en charge des tailles de fichiers extrêmement grandes. Par la suite, Linux 2.6 a ajouté les nouveaux appels système statfs64() et fstatfs64() qui utilisent une nouvelle structure, statfs64. La nouvelle structure contient les mêmes champs que la structure statfs d'origine, mais la taille de divers champs est augmentée pour tenir compte des grandes tailles de fichiers. Les fonctions d'encapsulation statfs() et fstatfs() de glibc gèrent de manière transparente les différences entre les noyaux.

LSB a déprécié les appels de bibliothèque statfs() et fstatfs() et nous demande d'utiliser statvfs(3) et fstatvfs(3) à la place.

NOTES

Le type __fsword_t utilisé pour divers champs dans la définition de la structure statfs est un type interne à glibc, non destiné à un usage public. Cela laisse le programmeur dans une situation délicate lorsqu'il essaie de copier ou de comparer ces champs avec des variables locales dans un programme. L'utilisation de unsigned int pour de telles variables suffit sur la plupart des systèmes.

Certains systèmes n'ont que <sys/vfs.h>, d'autres systèmes ont également <sys/statfs.h>, où le premier inclut le second. Il semble donc préférable d'inclure le premier.

BOGUES

De Linux 2.6.38 inclus jusqu'à Linux 3.1 inclus, fstatfs() échouait avec l'erreur ENOSYS pour les descripteurs de fichiers créés par pipe(2).
