DESCRIPTIO

N

Les fonctions truncate() et ftruncate() font tronquer le fichier régulier nommé par path ou référencé par fd à une taille de précisément length oc

tets.

Si le fichier était auparavant plus grand que cette taille, les données supplémentaires sont perdues. Si le fichier était auparavant plus court, il est étendu, et la partie étendue est lue comme des octets nuls ('\0')

.

Le décalage du fichier n'est pas

modifié.

Si la taille a changé, les champs st_ctime et st_mtime (respectivement, heure du dernier changement d'état et heure de la dernière modification ; voir inode(7)) du fichier sont mis à jour, et les bits de mode set-user-ID et set-group-ID peuvent être

effacés.

Avec ftruncate(), le fichier doit être ouvert en écriture ; avec truncate(), le fichier doit

être accessibl
e en écriture.

VERSION

S

Les détails de la section DESCRIPTION sont destinés aux systèmes conformes à XSI. Pour les systèmes non conformes à XSI, la norme POSIX autorise deux comportements pour ftruncate() lorsque length dépasse la longueur du fichier (notez que truncate() n'est pas du tout spécifié dans un tel environnement) : soit renvoyer une erreur, soit étendre le fichier. Comme la plupart des implémentations UNIX, Linux suit l'exigence XSI lorsqu'il traite les systèmes de fichiers natifs. Cependant, certains systèmes de fichiers non natifs ne permettent pas truncate() et ftruncate() d'être utilisés pour étendre un fichier au-delà de sa longueur actuelle : un exemple notable sur Linux est

VFAT.

Sur certaines architectures 32 bits, la signature d'appel de ces appels système diffère, pour les raisons décrites dans syscal

HISTORIQU

E

POSIX.1-2001, SVr4, 4.

2BSD.

Les appels système truncate() et ftruncate() d'origine de Linux n'ont pas été conçus pour gérer les grands décalages de fichiers. Par conséquent, Linux 2.4 a ajouté les appels système truncate64() et ftruncate64() qui gèrent les grands fichiers. Cependant, ces détails peuvent être ignorés par les applications utilisant g

libc, dont les fonctions enveloppe emploient transparentement
les appels système plus récents lorsqu'ils sont disponibles.
