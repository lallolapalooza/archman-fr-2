fts(3) Manuel des fonctions de bibliothèque fts(3)

NOM

fts, fts_open, fts_read, fts_children, fts_set, fts_close - parcourir une hiérarchie de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPTION

Les fonctions fts sont fournies pour parcourir les hiérarchies de fichiers. Un bref aperçu est que la fonction fts_open() retourne une "poignée" (de type FTS *) qui fait référence à un flux de hiérarchie de fichiers. Cette poignée est ensuite fournie aux autres fonctions fts. La fonction fts_read() retourne un pointeur vers une structure décrivant l'un des fichiers de la hiérarchie de fichiers. La fonction fts_children() retourne un pointeur vers une liste chaînée de structures, chacune décrivant l'un des fichiers contenus dans un répertoire de la hiérarchie.

En général, les répertoires sont visités deux fois distinctement ; en préordre (avant la visite de l'un de leurs descendants) et en postordre (après la visite de tous leurs descendants). Les fichiers sont visités une seule fois. Il est possible de parcourir la hiérarchie "logiquement" (en visitant les fichiers vers lesquels les liens symboliques pointent) ou physiquement (en visitant les liens symboliques eux-mêmes), d'ordonner le parcours de la hiérarchie ou de supprimer et/ou revisiter des portions de la hiérarchie.

Deux structures (et types associés) sont définies dans le fichier d'inclusion <fts.h>. Le premier type est FTS, la structure qui représente la hiérarchie de fichiers elle-même. Le second type est FTSENT, la structure qui représente un fichier dans la hiérarchie de fichiers. Normalement, une structure FTSENT est retournée pour chaque fichier de la hiérarchie de fichiers. Dans cette page de manuel, "fichier" et "structure FTSENT" sont généralement interchangeables.

La structure FTSENT contient des champs décrivant un fichier. La structure contient au moins les champs suivants (il y a des champs supplémentaires qui doivent être considérés comme privés à l'implémentation) :


typedef struct _ftsent {
    unsigned short  fts_info;     /* drapeaux pour la structure FTSENT */
    char           *fts_accpath;  /* chemin d'accès */
    char           *fts_path;     /* chemin racine */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* nom du fichier */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* profondeur (-1 à N) */
    int             fts_errno;    /* errno du fichier */
    long            fts_number;   /* valeur numérique locale */
    void           *fts_pointer;  /* valeur d'adresse locale */
    struct _ftsent *fts_parent;   /* répertoire parent */
    struct _ftsent *fts_link;     /* structure de fichier suivante */
    struct _ftsent *fts_cycle;    /* structure de cycle */
    struct stat    *fts_statp;    /* informations [l]stat(2) */
} FTSENT;

Ces champs sont définis comme suit :

fts_info
L'une des valeurs suivantes décrivant la structure FTSENT retournée et le fichier qu'elle représente. À l'exception des répertoires sans erreur (FTS_D), toutes ces entrées sont terminales, c'est-à-dire qu'elles ne seront pas revues, ni aucun de leurs descendants ne sera visité.
FTS_D
Un répertoire visité en préordre.
FTS_DC
Un répertoire qui provoque un cycle dans l'arbre. (Le champ fts_cycle de la structure FTSENT sera également rempli.)
FTS_DEFAULT
Toute structure FTSENT représentant un type de fichier non explicitement décrit par l'une des autres valeurs fts_info.
FTS_DNR
Un répertoire qui ne peut pas être lu. Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_DOT
Un fichier nommé "." ou ".." qui n'a pas été spécifié comme nom de fichier à fts_open() (voir FTS_SEEDOT).
FTS_DP
Un répertoire visité en postordre. Le contenu de la structure FTSENT restera inchangé par rapport à son retour en préordre, c'est-à-dire avec le champ fts_info défini sur FTS_D.
FTS_ERR
Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_F
Un fichier régulier.
FTS_NS
Un fichier pour lequel aucune information [l]stat(2) n'était disponible. Le contenu du champ fts_statp est indéfini. Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_NSOK
Un fichier pour lequel aucune information [l]stat(2) n'a été demandée. Le contenu du champ fts_statp est indéfini.
FTS_SL
Un lien symbolique.
FTS_SLNONE
Un lien symbolique avec une cible inexistante. Le contenu du champ fts_statp fait référence aux informations de caractéristiques du fichier pour le lien symbolique lui-même.
fts_accpath
Un chemin pour accéder au fichier depuis le répertoire courant.
fts_path
Le chemin du fichier relatif à la racine du parcours. Ce chemin contient le chemin spécifié à fts_open() comme préfixe.
fts_pathlen
La somme des longueurs des chaînes référencées par fts_path et fts_name.
fts_name
Le nom du fichier.
fts_namelen
La longueur de la chaîne référencée par fts_name.
fts_level
La profondeur du parcours, numérotée de -1 à N, où ce fichier a été trouvé. La structure FTSENT représentant le parent du point de départ (ou de la racine) du parcours est numérotée -1, et la structure FTSENT pour la racine elle-même est numérotée 0.
fts_errno
Si fts_children() ou fts_read() retourne une structure FTSENT dont le champ fts_info est défini sur FTS_DNR, FTS_ERR ou FTS_NS, le champ fts_errno contient le numéro d'erreur (c'est-à-dire la valeur errno) spécifiant l'erreur. Sinon, le contenu du champ fts_errno est indéfini.
fts_number
Ce champ est fourni pour l'utilisation par le programme applicatif et n'est pas modifié par les fonctions fts. Il est initialisé à 0.
fts_pointer
Ce champ est fourni pour l'utilisation par le programme applicatif et n'est pas modifié par les fonctions fts. Il est initialisé à NULL.
fts_parent
Un pointeur vers la structure FTSENT référençant le fichier dans la hiérarchie immédiatement au-dessus du fichier courant, c'est-à-dire le répertoire dont ce fichier est membre. Une structure parente pour le point d'entrée initial est également fournie, cependant, seuls les champs fts_level, fts_number et fts_pointer sont garantis d'être initialisés

fts_open(

)

La fonction fts_open() prend un pointeur vers un tableau de pointeurs de caractères nommant un ou plusieurs chemins qui constituent une hiérarchie logique de fichiers à parcourir. Le tableau doit être terminé par un pointeur

nul.

Il existe un certain nombre d'options, dont au moins une (soit FTS_LOGICAL ou FTS_PHYSICAL) doit être spécifiée. Les options sont sélectionnées en combinant (par un OU binaire) les valeurs suivantes

:
FTS_LOGIC
AL
Cette option fait en sorte que les routines fts renvoient des structures FTSENT pour les cibles des liens symboliques au lieu des liens symboliques eux-mêmes. Si cette option est définie, les seuls liens symboliques pour lesquels des structures FTSENT sont renvoyées à l'application sont ceux qui font référence à des fichiers inexistants : le champ fts_statp est obtenu via stat(2) avec un repli sur lstat(
2).
FTS_PHYSIC
AL
Cette option fait en sorte que les routines fts renvoient des structures FTSENT pour les liens symboliques eux-mêmes au lieu des fichiers cibles vers lesquels ils pointent. Si cette option est définie, des structures FTSENT pour tous les liens symboliques de la hiérarchie sont renvoyées à l'application : le champ fts_statp est obtenu via lstat(
2).
FTS_COMFOLL
OW
Cette option fait en sorte que tout lien symbolique spécifié en tant que chemin racine soit suivi immédiatement, comme si via FTS_LOGICAL, quel que soit le mode
principal.
FTS_NOCHD
IR
En tant qu'optimisation de performance, les fonctions fts changent de répertoire lorsqu'elles parcourent la hiérarchie de fichiers. Cela a pour effet secondaire qu'une application ne peut pas compter sur le fait d'être dans un répertoire particulier pendant le parcours. Cette option désactive cette optimisation, et les fonctions fts ne changeront pas le répertoire courant. Notez que les applications ne devraient pas elles-mêmes changer leur répertoire courant et essayer d'accéder à des fichiers, sauf si FTS_NOCHDIR est spécifié et que des chemins absolus ont été fournis en tant qu'arguments à fts_ope
n().
FTS_NOST
AT
Par défaut, les structures FTSENT renvoyées font référence aux informations de caractéristiques de fichier (le champ fts_statp) pour chaque fichier visité. Cette option assouplit cette exigence en tant qu'optimisation de performance, permettant aux fonctions fts de définir le champ fts_info à FTS_NSOK et de laisser le contenu du champ fts_statp ind
éfini.
FTS_SEED
OT
Par défaut, à moins qu'ils ne soient spécifiés en tant qu'arguments de chemin à fts_open(), les fichiers nommés "." ou ".." rencontrés dans la hiérarchie de fichiers sont ignorés. Cette option fait en sorte que les routines fts renvoient des structures FTSENT pour
ceux-ci.
FTS_XD

L'argument compar() spécifie une fonction définie par l'utilisateur qui peut être utilisée pour ordonner le parcours de la hiérarchie. Elle prend deux pointeurs vers des pointeurs vers des FTSENT structures en arguments et devrait renvoyer une valeur négative, zéro, ou une valeur positive pour indiquer si le fichier référencé par son premier argument vient avant, dans n'importe quel ordre par rapport à, ou après, le fichier référencé par son deuxième argument. Les champs fts_accpath, fts_path, et fts_pathlen des structures FTSENT ne peuvent jamais être utilisés dans cette comparaison. Si le champ fts_info est défini à FTS_NS ou FTS_NSOK, le champ fts_statp ne peut pas non plus l'être. fts_read(

)

La fonction fts_read() renvoie un pointeur vers une structure FTSENT décrivant un fichier dans la hiérarchie. Les répertoires (qui sont lisibles et ne provoquent pas de boucles) sont visités au moins deux fois, une fois en préordre et une fois en postordre. Tous les autres fichiers sont visités au moins une fois. (Les liens durs entre des répertoires qui ne provoquent pas de boucles ou les liens symboliques vers des liens symboliques peuvent faire en sorte que les fichiers soient visités plus d'une fois, ou les répertoires plus de deux fois.

)

Si tous les membres de la hiérarchie ont été renvoyés, fts_read() renvoie NULL et définit errno à 0. Si une erreur sans rapport avec un fichier de la hiérarchie se produit, fts_read() renvoie NULL et définit errno pour indiquer l'erreur. Si une erreur liée à un fichier renvoyé se produit, un pointeur vers une FTSENT structure est renvoyé, et errno peut avoir été défini ou non (voir fts_inf

o).

Les structures FTSENT renvoyées par fts_read() peuvent être écrasées après un appel à fts_close() sur le même flux de hiérarchie de fichiers, ou, après un appel à fts_read() sur le même flux de hiérarchie de fichiers à moins qu'elles ne représentent un fichier de type répertoire, auquel cas elles ne seront pas écrasées avant après un appel à fts_read() après que la structure FTSENT a été renvoyée par la fonction fts_read()

en pos

fts_children(

)

La fonction fts_children() renvoie un pointeur vers une structure FTSENT décrivant la première entrée d'une liste chaînée terminée par NULL des fichiers du répertoire représenté par la structure FTSENT le plus récemment renvoyée par fts_read(). La liste est chaînée via le champ fts_link de la structure FTSENT, et est ordonnée par la fonction de comparaison spécifiée par l'utilisateur, le cas échéant. Des appels répétés à fts_children() recréeront cette liste

chaînée.

En tant que cas particulier, si fts_read() n'a pas encore été appelé pour une hiérarchie, fts_children() renverra un pointeur vers les fichiers du répertoire logique spécifié à fts_open(), c'est-à-dire les arguments spécifiés à fts_open(). Sinon, si la structure FTSENT le plus récemment renvoyée par fts_read() n'est pas un répertoire visité en préordre, ou que le répertoire ne contient aucun fichier, fts_children() renvoie NULL et définit errno à zéro. Si une erreur se produit, fts_children() renvoie NULL et définit errno pour indiquer

l'erreur.

Les structures FTSENT renvoyées par fts_children() peuvent être écrasées après un appel à fts_children(), fts_close(), ou fts_read() sur le même flux de hiérarchie de

fichiers.

fts_set(

La fonction fts_set() permet à l'application utilisateur de déterminer le traitement ultérieur du fichier f du flux ftsp. La fonction fts_set() renvoie 0 en cas de succès, et -1 si une erreur se
