DESCRIPTIO

N

Les fonctions traitant des modules MIB se répartissent en quatre groupes - celles traitant de l'initialisation et de l'arrêt, de la lecture et de l'analyse des fichiers MIB, de la recherche dans l'arbre MIB, et les routines de

sortie.

Initialisation et

arrêt

add_mibdir est utilisé pour ajouter le répertoire spécifié au chemin des emplacements où sont recherchés les fichiers contenant des modules MIB. Notez que cela ne charge pas réellement les modules MIB situés dans ce répertoire, mais constitue simplement une étape d'initialisation pour les rendre disponibles à netsnmp_read_module. Cette fonction renvoie un nombre de fichiers trouvés dans le répertoire, ou -1 en cas d'erreur. Elle doit être appelée avant d'invoquer netsnmp_init_mib

.

netsnmp_init_mib configure le chemin de recherche du répertoire MIB (en utilisant add_mibdir ), met en place le cadre MIB interne, puis charge les modules MIB appropriés (en utilisant netsnmp_read_module et read_mib). Voir la section VARIABLES D'ENVIRONNEMENT pour plus de détails.
Elle doit être appelée avant toute autre routine qui manipule ou accède à l'arbre MIB (mais après tout appel supplémentaire à add_mibd

ir).

shutdown_mib effacera les informations qui ont été rassemblées par netsnmp_read_module, add_mibdir et add_module_replacement. Il est fortement recommandé de ne pas invoquer shutdown_mib alors que des session

s SNMP sont activ
ement gérées.

Lecture et analyse des

MIB

netsnmp_read_module prend le nom d'un module MIB (qui n'a pas besoin d'être identique au nom du fichier qui contient le module), le localise dans la liste configurée des répertoires MIB, et charge les définitions du module dans l'arbre MIB actif. Il charge également tous les modules MIB listés dans la clause IMPORTS de ce

module.

read_mib est similaire, mais prend le nom du fichier contenant le module MIB. Notez que ce fichier n'a pas besoin d'être situé dans la liste de recherche des répertoires MIB (bien que tous les modules listés dans la clause IMPORTS doivent y être)

.

read_all_mibs lira tous les modules MIB trouvés sur la liste de recherche des répertoires

MIB.

En général, le parseur reste silencieux sur les étrangetés qu'il voit dans les fichiers MIB. Pour obtenir des avertissements, appelez snmp_set_mib_warnings avec un level de 1 (ou 2 pour encore plus d'avertissements)

.

add_module_replacement peut être utilisé pour permettre à de nouveaux modules MIB d'obsoléter les anciens, sans avoir besoin de modifier les clauses IMPORTS des autres modules. Il prend les noms des anciens et des nouveaux modules, ainsi qu'une indication des parties de l'ancien module qui sont

affectées.

Recherche dans l'arbre

MIB

read_objid prend une chaîne contenant une version textuelle d'un identifiant d'objet (sous forme numérique ou descriptive), et la transforme en la liste de sous-identifiants correspondante. Celle-ci est renvoyée dans le paramètre output, avec le nombre de sous-identifiants renvoyés via out_len. Lors de l'appel, out_len doit contenir la longueur maximale du tableau output. Si plusieurs identifiants d'objets sont traités, cette longueur doit être réinitialisée avant chaque appel. Cette fonction renvoie une valeur de 1 si elle réussit à analyser la chaîne et 0

sinon.

snmp_parse_oid est similaire, mais renvoie un pointeur vers le tampon OID analysé (ou NULL)

.

get_module_node prend un descripteur et le nom d'un module, et renvoie la liste oid correspondante, de la même manière que read_objid ci-dessus.
Si le nom du module est spécifié comme "ANY", cette routine supposera que le descripteur donné est unique dans l'arbre, et renverra l'entrée correspondante. Si cette hypothèse est invalide, le comportement concernant la variable renvoyée dépend de l'implémentation.

Sorti

e

print_mib affichera une représentation de l'arbre MIB actuellement actif sur le pointeur FILE

spécifié.

print_objid prend un identifiant d'objet (comme renvoyé par read_objid, snmp_parse_oid ou get_module_node), et affiche la forme textuelle de cet OID sur la sortie

standard.

fprint_objid fait de même, mais affiche sur le pointeur FILE spécifié par le paramètre

initial.

snprint_objid affiche les mêmes informations dans le tampon pointé par buf qui est de longueur len. Il renvoie le nombre de caractères affichés, ou -1 si le tampon n'était pas assez grand. Dans ce dernier cas, buf contiendra généralement une version tronquée des informations (mais ce comportement n'est pas garanti)

.

print_description, fprint_description, et snprint_description prennent un identifiant d'objet similaire et affichent une version de la définition MIB pour cet objet, ainsi que l'OID complet. L'argument width contrôle la disposition de

l'OID.

Par défaut, le parseur ne sauvegarde pas les descriptions car elles peuvent être énormes. Afin de pouvoir les imprimer, il est nécessaire devoke snmp_set_save_descriptions(1)avant d'appeler init_mib

(ou
simil
aire).
