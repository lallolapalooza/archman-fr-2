SYNOPSI

S

flatpak build [OPTION...] RÉPERTOIRE [COMMANDE [ARG...

]
]

DESCRIPTIO

N

Exécute une commande de construction dans un répertoire. Le RÉPERTOIRE doit avoir été initialisé avec flatpak build

-init.

Le sdk spécifié dans le fichier de métadonnées du répertoire est monté sur /usr et les sous-répertoires

files et var sont montés sur /app et /var, respectivement. Ils sont inscriptibles et leur contenu est c
onservé entre les commandes de construction, ce qui permet d'y accumuler les artefacts de construction.

OPTION

S

Les options suivantes sont reconnues

:

-h, --hel

p
Afficher les options d'aide et
quitter.

-v, --verbos

e
Afficher les informations de débogage pendant le traitement de la
commande.

--ostree-verbos

e
Afficher les informations de débogage d'OSTree pendant le traitement de la
commande.

-r, --runtim

e
Utiliser le runtime non-devel spécifié dans les métadonnées de l'application au lieu du runtime
devel.

-p, --die-with-paren

t
Tuer le processus de construction et tous ses enfants lorsque le processus de lancement se
termine.

--bind-mount=DEST=SOURC

E
Ajouter un montage par liaison personnalisé dans l'espace de noms de construction. Peut être spécifié plusieurs
fois.

--build-dir=CHEMI

N
Démarrer la construction dans ce répertoire (par défaut dans le répertoire courant)
.

--share=SOUS-SYSTÈM

E
Partager un sous-système avec la session hôte. Cela remplace la section Context des métadonnées de l'application. SOUS-SYSTÈME doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs
fois.

--unshare=SOUS-SYSTÈM

E
Ne pas partager un sous-système avec la session hôte. Cela remplace la section Context des métadonnées de l'application. SOUS-SYSTÈME doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs
fois.

--socket=SOCKE

T
Exposer un socket bien connu à l'application. Cela remplace la section Context des métadonnées de l'application. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs
fois.

--nosocket=SOCKE

T
Ne pas exposer un socket bien connu à l'application. Cela remplace la section Context des métadonnées de l'application. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs
fois.

--device=PÉRIPHÉRIQU

E
Exposer un périphérique à l'application. Cela remplace la section Context des métadonnées de l'application. PÉRIPHÉRIQUE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs
fois.

--nodevice=PÉRIPHÉRIQU

E
Ne pas exposer un périphérique à l'application. Cela remplace la section Context des métadonnées de l'application. PÉRIPHÉRIQUE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs
fois.

--allow=FONCTIONNALIT

É
Autoriser l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FONCTIONNALITÉ doit être l'une des suivantes : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs fois.

Voir flatpak-build-finish(1) pour la signification des différentes

fonctionnalités
.

--disallow=FONCTIONNALIT

É
Interdire l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FONCTIONNALITÉ doit être l'une des suivantes : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs
fois.

--filesystem=SYSTÈME-DE-FICHIERS[:ro|:

create]
Autoriser l'application à accéder à un sous-ensemble du système de fichiers. Cela remplace la section Context des métadonnées de l'application. SYSTÈME-DE-FICHIERS peut être l'un des suivants : home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, xdg-run, xdg-config, xdg-cache, xdg-data, un chemin absolu, ou un chemin relatif au répertoire personnel comme ~/dir ou des chemins relatifs aux répertoires xdg, comme xdg-download/subdir. Le suffixe :ro optionnel indique que l'emplacement sera en lecture seule. Le suffixe :create optionnel indique que l'emplacement sera en lecture-écriture et sera créé s'il n'existe pas. Cette option peut être utilisée plusieurs fois. Voir la liste « [Context] filesystems » dans flatpak-metadata(5) pour les détails sur la signification de ces systèmes de
fichiers.

--nofilesystem=SYSTÈME-DE-FICHIER

S
Retirer l'accès au sous-ensemble spécifié du système de fichiers de l'application. Cela remplace la section Context des métadonnées de l'application. SYSTÈME-DE-FICHIERS peut être l'un des suivants : home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, un chemin absolu, ou un chemin relatif au répertoire personnel comme ~/dir. Cette option peut être utilisée plusieurs
fois.

--with-appdi

r
Exposer et configurer l'accès au répertoire de stockage propre à chaque application dans $HOME/.var/app. Cela n'est généralement pas utile lors de la construction, mais aide lors du test des applications
construites.

--add-policy=SOUS-SYSTÈME.

CLE=VALEUR
Ajouter une option de politique générique. Par exemple, « --add-policy=subsystem.key=v1 --add-policy=subsystem.key=v2 » correspondrait à ces métadonnées : 
[Policy su
bsystem]
key=v1;v2;

Cette option peu

t être utilisée
plusieurs fois.

--remove-policy=SOUS-SYSTÈME.

CLE=VALEUR
Retirer une option de politique générique. Cette option peut être utilisée plusieurs
fois.

--env=VAR=VALEU

R
Définir une variable d'environnement dans l'application. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--unset-env=VA

R
Annuler la définition d'une variable d'environnement dans l'application. Cela remplace l'entrée unset-environment du groupe [Context] des métadonnées, et le groupe [Environment]. Cette option peut être utilisée plusieurs
fois.

--env-fd=F

D
Lire les variables d'environnement depuis le descripteur de fichier FD, et les définir comme si via --env. Cela peut être utilisé pour éviter que les variables d'environnement et leurs valeurs ne deviennent visibles aux autres utilisateurs.

Chaque variable d'environnement est sous la forme VAR=VALEUR suivie d'un octet nul. C'est le même format que celui utilisé par env -0 et

/proc/*/environ
.

--own-name=NO

M
Autoriser l'application à posséder le nom bien connu NOM sur le bus de session. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--talk-name=NO

M
Autoriser l'application à communiquer avec le nom bien connu NOM sur le bus de session. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--system-own-name=NO

M
Autoriser l'application à posséder le nom bien connu NOM sur le bus système. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--system-talk-name=NO

M
Autoriser l'application à communiquer avec le nom bien connu NOM sur le bus système. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--persist=NOM-DE-FICHIE

R
Si l'application n'a pas accès au vrai répertoire personnel, faire du chemin (relatif au répertoire personnel) NOM-DE-FICHIER un montage par liaison vers le chemin correspondant dans le répertoire propre à l'application, permettant ainsi à cet emplacement d'être utilisé pour des données persistantes. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs
fois.

--sdk-dir=RÉ

P
Normalement, s'il existe un répertoire usr dans le répertoire de construction, celui-ci est utilisé pour les fichiers du runtime (cela peut être créé par --writable-sdk ou les arguments --type=runtime de build-init). Si vous spécifiez --sdk-dir, ce répertoire sera utilisé à la place. Utilisez cette option si vous avez passé --sdk-dir à
build-init.

--readonl

y
Monter les répertoires de destination normalement inscriptibles en lecture seule. Cela peut être utile si vous voulez exécuter quelque chose dans le bac à sable mais garantirque cela n'affecte pas les résultats de la construction. Par exemple, les tests.

--metadata=FICHIER

Utilisez le nom de fichier spécifié comme métadonnées dans l'application exportée au lieu du fichier par défaut (nommé metadata). Ceci est utile si vous construisez plusieurs éléments à partir d'un seul arbre de construction (comme une plateforme et un sdk).

--log-session-bus

Journaliser le trafic du bus de session. Ceci peut être utile pour voir quel accès vous devez autoriser dans votre politique D-Bus.

--log-system-bus

Journaliser le trafic du bus système. Ceci peut être utile pour voir quel accès vous devez autoriser dans votre politique D-Bus.

EXEMPLES

$ flatpak build /build/my-app rpmbuild my-app.src.rpm
