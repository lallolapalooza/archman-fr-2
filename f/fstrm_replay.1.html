fstrm_replay(1) Manuel des commandes générales fstrm_replay(1)

NOM

fstrm_replay - Rejoue les données Frame Streams sauvegardées vers une connexion socket.

SYNTAXE

fstrm_replay -t type-de-contenu -r fichier [ -r fichier ... ]
[ -u chemin-socket ] [ -a IP -p port ]

fstrm_replay --type type-de-contenu
--read fichier [ --read fichier ... ]
[ --unix chemin-socket ] [ --tcp IP --port port ]

DESCRIPTION

fstrm_replay se connecte à un récepteur Frame Streams sur le chemin-socket de domaine UNIX ou l'adresse TCP et le port spécifiés, puis lit et envoie des données du type-de-contenu fourni depuis les fichiers donnés.

OPTIONS

-t type-de-contenu | --type type-de-contenu
Spécifie le type-de-contenu à lire depuis les fichiers et à envoyer au socket Frame Streams. Les fichiers dont le type de contenu diffère sont ignorés. Si le serveur socket n'accepte pas le type-de-contenu, fstrm_replay échouera.
-r fichier | --read fichier
Lit les données depuis fichier. Plusieurs fichiers peuvent être spécifiés avec plusieurs options -r. Les fichiers qui ne peuvent pas être ouverts, ou qui ne contiennent pas de données Frame Streams valides, seront ignorés.
-u chemin-socket | --unix chemin-socket
Se connecte au chemin-socket de domaine Unix pour écrire les données Frame Streams. Une seule des options -u ou -a peut être donnée.
-a IP | --tcp IP
Se connecte à l'adresse TCP IP pour écrire les données Frame Streams. Une seule des options -u ou -a peut être donnée. L'utilisation de -a nécessite un port donné avec -p.
-p port | --port port
Si -a est donné, utilise le port TCP port pour écrire les données Frame Streams.

EXEMPLES

Rejouer des données dnstap via un socket de domaine Unix :

fstrm_replay -t protobuf:dnstap.Dnstap \
	-u /var/run/named/dnstap.sock -r dnstap-log.fstrm
