NOM

fonttosfnt - Encapsuler une police bitmap dans un conteneur sfnt (OpenType)

SYNTAXE

fonttosfnt [ options ] -o fichier.otb [ -- ] [ police ] ...

DESCRIPTION

Encapsule une police bitmap ou un ensemble de polices bitmap dans un conteneur sfnt (TrueType ou OpenType). Si aucune police n'est spécifiée, une police BDF est lue depuis l'entrée standard (stdin).

OPTIONS

-v
Soyez verbeux.
-c
Ne pas recadrer les glyphes. Ceci augmente généralement la taille du fichier, mais peut parfois entraîner une légère diminution de la taille du fichier pour les polices à petite cellule de caractères (polices de terminal).
-b
Écrire les données de glyphes alignées sur octet. Par défaut, les données non alignées sont écrites, ce qui donne une taille de fichier plus petite.
-r
Ne pas réencoder les polices. Par défaut, les polices sont réencodées en Unicode lorsque cela est possible.
-g n
Définir le type de glyphes évolutifs que nous écrivons. Si n est 0, aucun glyphe évolutif n'est écrit ; ceci est légal mais confond la plupart des logiciels actuels. Si n est 1, un seul glyphe évolutif (le glyphe indéfini) est écrit ; ceci est recommandé, mais déclenche un bug dans les versions actuelles de FreeType. Si n est 2 (par défaut), un nombre suffisamment élevé de glyphes vides est écrit, ce qui fonctionne avec FreeType mais augmente la taille du fichier.
-m n
Définir le type de métriques évolutives que nous écrivons. Si n est 0, aucune métrique évolutive n'est écrite, ce qui peut ou non être légal. Si n est 1, des métriques complètes pour un seul glyphe sont écrites, et seules les valeurs de rejet gauche sont écrites pour les autres glyphes. Si n est 2, des métriques évolutives pour tous les glyphes sont écrites, ce qui augmente la taille du fichier et n'est pas recommandé. La valeur par défaut est 1.
--
Fin des options.

BOGUES

Certaines valeurs au niveau de la police, notamment les positions de exposant et d'indice, sont des valeurs factices.

VOIR AUSSI

X(7), Xserver(1), Xft(3). Fonts in X11.
