DESCRIPTIO

N

Cette utilitaire gère les verrous flock(2) depuis des scripts shell ou depuis la ligne de

commande.

La première et la deuxième des formes ci-dessus enveloppent le verrou autour de l'exécution d'une commande, d'une manière similaire à su(1) ou newgrp(1). Elles verrouillent un fichier ou un répertoire spécifié, qui est créé (en supposant les permissions appropriées) s'il n'existe pas déjà. Par défaut, si le verrou ne peut pas être acquis immédiatement, flock attend jusqu'à ce que le verrou soit

disponible.

La troisième forme utilise un fichier ouvert par son descripteur de fichier numéro. Voir les exemples ci-dessous pou

r savoir comment cel
a peut être utilisé.

OPTION

S

-c, --command command

e
Passe une seule commande, sans arguments, au shell avec -c
.

-E, --conflict-exit-code numér

o
Le code de sortie utilisé lorsque l'option -n est utilisée, et que le verrou conflictuel existe, ou lorsque l'option -w est utilisée, et que le délai d'attente est atteint. La valeur par défaut est 1. Le numéro doit être dans la plage de 0 à
255.

-F, --no-for

k
Ne pas créer de processus fils avant d'exécuter la commande. Lors de l'exécution, le processus flock est remplacé par la commande qui continue à tenir le verrou. Cette option est incompatible avec --close car il n'y aurait autrement rien pour tenir le
verrou.

-e, -x, --exclusiv

e
Obtenir un verrou exclusif, parfois appelé verrou d'écriture. C'est le comportement par
défaut.

-n, --nb, --nonbloc

k
Échouer plutôt que d'attendre si le verrou ne peut pas être acquis immédiatement. Voir l'option -E pour le code de sortie
utilisé.

-o, --clos

e
Fermer le descripteur de fichier sur lequel le verrou est tenu avant d'exécuter la commande. C'est utile si la commande crée un processus fils qui ne devrait pas tenir le
verrou.

-s, --share

d
Obtenir un verrou partagé, parfois appelé verrou de
lecture.

-u, --unloc

k
Libérer un verrou. Cela n'est généralement pas requis, car un verrou est automatiquement libéré lorsque le fichier est fermé. Cependant, cela peut être requis dans des cas particuliers, par exemple si le groupe de commandes inclus peut avoir créé un processus d'arrière-plan qui ne devrait pas tenir le
verrou.

-w, --wait, --timeout seconde

s
Échouer si le verrou ne peut pas être acquis dans les secondes. Les valeurs fractionnaires décimales sont autorisées. Voir l'option -E pour le code de sortie utilisé. Le nombre zéro de secondes est interprété comme --nonblock
.

--fcnt

l
Au lieu de flock(2), appliquer un verrou de description de fichier ouvert fcntl(2) (c'est-à-dire en utilisant les commandes F_OFD_SETLK (non bloquant) ou F_OFD_SETLKW (bloquant)). Ces verrous sont indépendants de ceux appliqués via flock(2), mais, contrairement aux verrous POSIX fcntl() traditionnels (F_SETLK, F_SETLKW), ont une sémantique correspondant à celle de flock(2)
.

Cela n'est disponible que sur les versions du noyau >= 3.

15.

--verbos

e
Rapporter combien de temps il a fallu pour acquérir le verrou, ou pourquoi le verrou n'a pas pu être
obtenu.

-h, --hel

p
Afficher le texte d'aide et
quitter.

-V, --versio

n
Afficher l
a version e
t quitter.

CODE DE

SORTIE

La commande utilise les valeurs de code de sortie de <sysexits.h> pour tout, sauf lors de l'utilisation de l'une des options -n ou -w qui signalent un échec d'acquisition du verrou avec un code de sortie donné par l'option -E, ou 1 par défaut. Le code de sortie donné par -E doit être dans la plage de 0 à

255.

Lors de l'utilisation de la variante commande, et si l'exécution du processus fils a fonction

né, alors le code de sortie es
t celui de la commande enfant.

NOTE

S

flock ne détecte pas les impasses. Voir flock(2) pour les

détails.

Certains systèmes de fichiers (p. ex. NFS et CIFS) ont une implémentation limitée de flock(2) et flock peut toujours échouer. Pour les détails, voir flock(2), nfs(5) et mount.cifs(8). Selon les options de mo

ntage, flock peu
t toujours échouer.

EXEMPLE

S

Notez que « shell> » dans les exemples est une invite de ligne de

commande.

shell1> flock /tmp -c cat; shell2> flock -w .007 /tmp -c echo; /bin/echo

$?
Établir un verrou exclusif sur le répertoire /tmp et la deuxième commande
échouera.

shell1> flock -s /tmp -c cat; shell2> flock -s -w .007 /tmp -c echo; /bin/echo

$?
Établir un verrou partagé sur le répertoire /tmp et la deuxième commande n'échouera pas. Remarquez que la tentative d'obtenir un verrou exclusif avec la deuxième commande
échouerait.

shell> flock -x local-lock-file echo 'a b

c'
Prendre le verrou exclusif « local-lock-file » avant d'exécuter echo avec 'a b
c'.

(; flock -n 9 || exit 1; # ... commandes exécutées sous verrou ...; ) 9>/var/lock/mylockfil

e
Cette forme est pratique dans les scripts shell. Le mode utilisé pour ouvrir le fichier n'a pas d'importance pour flock ; utiliser > ou >> permet de créer le fichier de verrou s'il n'existe pas déjà, cependant, la permission d'écriture est requise. Utiliser < nécessite que le fichier existe déjà mais seule la permission de lecture est
requise.

[ "${FLOCKER}" != "$0" ] && exec env FLOCKER="$0" flock -en "$0" "$0" "$@" ||

:
Ceci est un code d'habillage utile pour les scripts shell. Placez-le en haut du script shell que vous souhaitez verrouiller et il se verrouillera automatiquement au premier lancement. Si la variable d'environnement $FLOCKER n'est pas définie au script shell qui est en cours d'exécution, alors exécutez flock et prenez un verrou exclusif non bloquant (en utilisant le script lui-même comme fichier de verrou) avant de se ré-exécuter avec les bons arguments. Cela définit également la variable d'environnement FLOCKER à la bonne valeur afin qu'il ne s'exécute pas à
nouveau.

shell> exec 4<>/var/lock/mylockfile; shell> flock -n

4
Cette forme est pratique pour verrouiller un fichier sans créer un processus fils. Le shell ouvre le fichier de verrou en lecture et écriture en tant que descripteur de fichier 4, puis flock est utilisé pour ve
rrouiller le
descripteur.
