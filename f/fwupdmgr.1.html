NOM

fwupdmgr - utilitaire client du gestionnaire de mise à jour du firmware

SYNOPSIS

fwupdmgr [CMD]

DESCRIPTION

fwupdmgr est un client fwupd en ligne de commande destiné à être utilisé de manière interactive. La sortie du terminal entre les versions de fwupd n'est pas garantie d'être stable, mais si vous prévoyez d'analyser les résultats, l'ajout de --json pourrait être exactement ce dont vous avez besoin.

Il existe également des outils graphiques pour le firmware disponibles pour divers environnements de bureau. Ces applications peuvent être plus utiles pour de nombreux utilisateurs que l'utilisation de la ligne de commande.

•
GNOME Software: https://wiki.gnome.org/Apps/Software
•
GNOME Firmware: https://gitlab.gnome.org/World/gnome-firmware
•
KDE Discover: https://userbase.kde.org/Discover
•
Canonical Firmware Updater: https://github.com/canonical/firmware-updater
•
System76 Firmware Manager: https://github.com/pop-os/firmware-manager

Sur la plupart des systèmes, fwupd est configuré pour télécharger les métadonnées depuis le Linux Vendor Firmware Service https://fwupd.org/ et plus d'informations sur le LVFS sont disponibles ici : https://lvfs.readthedocs.io/

La plupart des utilisateurs qui souhaitent simplement mettre à jour tous les appareils vers les dernières versions peuvent faire fwupdmgr refresh puis fwupdmgr update. À ce stade, le système demandera une confirmation, mettra à jour certains appareils et pourra ensuite redémarrer pour déployer les mises à jour nécessitant un redémarrage.

OPTIONS

La commande fwupdmgr prend diverses options en fonction de l'action. Les actions sont réparties en groupes de comportement approximatifs comme suit :

Interaction avec les appareils découverts

Les actions suivantes peuvent être utilisées pour afficher des détails sur les appareils énumérés sur le système :

get-devices: Afficher tous les appareils, avec un filtrage optionnel appliqué à l'aide de --filter.

get-updates: Afficher toutes les mises à jour disponibles pour un appareil spécifique.

get-releases: Afficher toutes les versions installables (plus anciennes, les mêmes ou plus récentes) pour un appareil spécifique.

get-details: Afficher les détails d'une archive .cab spécifique, même si l'appareil cible n'a pas été trouvé sur ce système.

search: Rechercher les mises à jour présentes dans les métadonnées, que l'appareil ait été énuméré sur le système ou non. La recherche correspondra aux versions de firmware par :

•
Le GUID complet d'un appareil, par exemple eb68dbae-3aef-5077-92ae-9016d1f0c856
•
L'ID AppStream d'un appareil, par exemple work.frame.Desktop.RyzenAIMax300.BIOS.firmware
•
Le nom (complet ou sous-ensemble) d'une mise à jour de firmware, par exemple Desktop Ryzen AI MAX 300
•
Le nom (complet ou sous-ensemble) d'un fabricant de firmware, par exemple Framework
•
Le protocole utilisé par le firmware, par exemple org.uefi.capsule
•
Tout problème signalé comme résolu par la mise à jour, par exemple CVE-2022-21894
•
Toute somme de contrôle de l'archive incluse avec la mise à jour, au format SHA-1 ou SHA-256, par exemple b34950fc65dabc0cb50e4c5f081829e40bf92e13

Déploiement du firmware

Les actions suivantes peuvent être utilisées pour installer du firmware sur des appareils :

update: Mettre à jour chaque appareil à son tour vers la version la plus récente disponible.

install: Installer toute version disponible sur un appareil spécifique.

reinstall: Réinstaller la même version sur un appareil spécifique si elle est disponible.

downgrade: Installer une version plus ancienne sur une version spécifique si elle est disponible.

switch-branch: Basculer entre différentes « branches » de firmware pour un appareil spécifique. Par exemple, il peut y avoir une branche « supportée par la communauté » et une branche « fournisseur propriétaire » pour exactement le même matériel, toutes deux disponibles sur le LVFS.

local-install: Installer une archive de firmware locale. La commande régulière install reviendra également à celle-ci si le premier argument est un fichier local existant.

activate: Définir la version du firmware installé comme en cours d'exécution, ce qui peut signifier que l'appareil devient hors ligne ou ne répond pas pendant quelques instants.

sync: Installer toutes les versions avec une étiquette BKC correspondante si une « Meilleure configuration connue » (Best Known Configuration) a été définie pour la machine locale.

Firmware approuvé et bloqué

Les actions suivantes peuvent être utilisées pour bloquer ou autoriser l'installation de versions de firmware spécifiques :

get-blocked-firmware: Récupère la liste des firmwares bloqués sous forme de sommes de contrôle.

block-firmware: Bloque l'installation d'un firmware spécifique par install ou update.

unblock-firmware: Débloque l'installation ou la mise à jour d'un firmware spécifique.

Les actions suivantes peuvent être utilisées pour contrôler la liste blanche de firmwares spécifiques :

set-approved-firmware: Définit la liste des firmwares approuvés. Une fois la liste blanche définie sur une valeur non vide, seuls les firmwares correspondant à ces sommes de contrôle seront installables.

get-approved-firmware: Récupère la liste des firmwares approuvés, renvoyant une liste vide s'il n'y a pas de liste blanche en place.

Les sommes de contrôle utilisées pour autoriser ou interdire sont les sommes de contrôle de l'archive au format SHA-1 ou SHA-256.

Émulation

L'émulation d'appareil permet d'enregistrer le comportement de l'appareil afin que nous puissions rejouer les réponses de l'appareil et tester l'écriture du firmware sans ce matériel réel branché.

Les actions suivantes peuvent être utilisées lors de l'émulation d'appareils :

emulation-tag: Ajoute des appareils à surveiller pour une future émulation.

emulation-save: Enregistrer les données d'émulation d'appareil capturées dans un fichier JSON. Seules les données des appareils précédemment étiquetés pour l'émulation seront renvoyées.

emulation-load: Charger les données d'émulation d'appareil depuis un fichier JSON.

emulation-untag: Supprime des appareils de la surveillance pour une future émulation.

Lors de l'étiquetage des appareils, l'ID de l'appareil ou le GUID peuvent être utilisés pour identifier l'appareil.

Les actions suivantes peuvent être utilisées pour exécuter des tests automatisés d'appareils :

device-emulate: Émuler un appareil à l'aide d'un manifeste JSON, qui n'opérera que sur des appareils émulés.

device-test: Tester un appareil à l'aide d'un manifeste JSON qui télécharge et vérifie des archives .cab et les déploie sur des appareils physiques réels.

Remotes

Les actions suivantes peuvent être utilisées pour contrôler les remotes (le magasin de métadonnées de firmware en ligne) configurés dans le daemon :

refresh: Télécharger les dernières métadonnées en ligne depuis les remotes configurés et activés.

get-remotes: Obtenir la liste des remotes configurés, qui peuvent être activés ou non.

enable-remote: Activer un remote préconfiguré afin qu'il puisse être actualisé et utilisé.

disable-remote: Désactiver un remote, mais ne pas supprimer les métadonnées stockées.

modify-remote: Modifier un remote, par exemple en activant des propriétés telles que AutomaticReports.

clean-remote: Nettoyer un remote, en supprimant les métadonnées si nécessaire.

Données historiques

Les actions suivantes peuvent être utilisées pour téléverser, exporter ou effacer les données historiques :

report-export: Exporter l'historique du firmware sous forme de fichier hors ligne pour un téléversement manuel vers un service tel que le LVFS.

report-history: Partager l'historique du firmware avec le remoteer, typiquement utilisé pour indiquer le ratio de succès d'une mise à jour spécifique. Dans certains cas, le partage de l'historique renverra des résultats vers des pages web décrivant l'échec plus en détail, certaines avec des solutions de contournement.

get-history : Affiche l'historique des mises à jour du firmware tel qu'il est stocké par fwupd.

get-results : Affiche le résultat de la dernière mise à jour du firmware pour un appareil spécifique.

clear-results : Efface les résultats de la dernière mise à jour si possible.

report-devices : Télécharge la liste des appareils pouvant être mis à jour vers un serveur distant afin qu'ils puissent faire pression sur le fournisseur pour qu'il prenne en charge les utilisateurs Linux.

Sécurité de la plateforme

Les actions suivantes peuvent être utilisées pour afficher ou corriger les problèmes de sécurité de la plateforme :

security : Obtient la liste des attributs de sécurité de l'hôte qui sont utilisés pour évaluer le niveau de sécurité de la machine.

security-fix : Corrige un échec spécifique d'attribut de sécurité de l'hôte.

security-undo : Annule la correction de l'attribut de sécurité de l'hôte, ce qui peut être nécessaire si security-fix a causé une régression.

Les actions suivantes peuvent être utilisées pour lister ou définir les paramètres du BIOS du firmware :

get-bios-settings : Récupère les paramètres du firmware du BIOS et les valeurs autorisées.

set-bios-setting : Définit un ou plusieurs paramètres du firmware du BIOS.

verify-update : Met à jour les sommes de contrôle stockées qui sont utilisées par l'action verify.

Autres

Les actions suivantes sont destinées aux scripts non interactifs ou à une utilisation en CI :

check-reboot-needed : Vérifie si des appareils sont en attente de redémarrage pour terminer la mise à jour.

device-wait : Attend qu'un appareil apparaisse dans la liste des appareils du démon.

download : Télécharge un fichier en utilisant les mêmes mécanismes que ceux utilisés pour le firmware et les métadonnées.

modify-config : Modifie une valeur de configuration du démon telle que IgnorePower. Voir man fwupd.conf pour la liste complète des variables.

reset-config : Réinitialise une section de configuration du démon aux valeurs par défaut.

quit : Demande au démon de quitter une fois qu'il a terminé toute mise à jour du firmware en cours.

inhibit : Empêche le système d'effectuer des mises à niveau manuelles ou automatiques accidentelles.

uninhibit : Autorise les mises à niveau du système.

unlock : Déverrouille l'appareil pour l'accès au firmware, ce qui peut être nécessaire pour certains appareils de plateforme.

get-plugins : Affiche tous les plugins enregistrés auprès du démon.

hwids : Renvoie tous les identifiants matériels de la machine. Ces GUIDs sont parfois appelés CHIDs lors de l'utilisation de Microsoft Windows, et les valeurs renvoyées par fwupd devraient également correspondre à celles de ComputerHardwareIds.exe.

Statut de sortie

Les commandes qui s'exécutent avec succès renverront "0", l'échec générique renvoyant "1".

Il existe également plusieurs autres codes de sortie : Un code de retour de "2" est utilisé pour les commandes qui n'ont pas d'actions mais qui ont été exécutées avec succès, et "3" est utilisé lorsqu'une ressource n'a pas été trouvée.
