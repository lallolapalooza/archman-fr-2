flatpak-build-finish

- Finaliser un réper
toire de construction

SYNOPSI

S

flatpak build-finish [

OPTION...]
RÉPERTOIRE

DESCRIPTIO

N

Finalise un répertoire de construction pour le préparer à l'exportation. RÉPERTOIRE est le nom du

répertoire.

Le résultat de cette commande est que les fichiers desktop, les icônes, les fichiers de service D-Bus et les fichiers metainfo AppStream du sous-répertoire files sont copiés dans un nouveau sous-répertoire export. Dans le fichier metadata, la clé command est définie dans le groupe [Application], et les clés prises en charge dans le groupe [Environment] sont définies selon les

options.

En tant que partie de la finalisation, vous pouvez également spécifier les permissions dont l'application a besoin, en utilisant les diverses options spécifiées ci-dessous. De plus, lors de la finalisation, les permissions du runtime sont héritées par l'application sauf si vous spécifiez --no-inherit-permission

s

Vous devriez examiner les fichiers exportés et les métadonnées de l'application avant de créer et de distribuer un bundle

d'application.

Il est une erreur d'exécuter build-finish sur un ré

pertoire qui n'a pas été initialisé comme répe
rtoire de construction, ou qui a déjà été finalisé.

OPTION

S

Les options suivantes sont reconnues

:

-h, --hel

p
Afficher les options d'aide et
quitter.

--command=COMMAND

E
La commande à utiliser. Si cette option n'est pas spécifiée, le premier exécutable trouvé dans files/bin est utilisé.

Notez que la commande est utilisée lorsque l'application est exécutée via flatpak run, et n'affecte pas ce qui est exécuté lorsque l'application est exécu

tée d'autres manières, par exemple via le
fichier desktop ou l'activation D-Bus.

--require-version=MAJEURE.MINEURE.

MICRO
Exiger cette version ou une version ultérieure de flatpak pour installer/mettre à jour vers cette
construction.

--share=SOUS-SYSTÈM

E
Partager un sous-système avec la session hôte. Cela met à jour le groupe [Context] dans les métadonnées. SOUS-SYSTÈME doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs
fois.

--unshare=SOUS-SYSTÈM

E
Ne pas partager un sous-système avec la session hôte. Cela met à jour le groupe [Context] dans les métadonnées. SOUS-SYSTÈME doit être l'un des suivants : network, ipc. Cette option peut être utilisée plusieurs
fois.

--socket=SOCKE

T
Exposer un socket bien connu à l'application. Cela met à jour le groupe [Context] dans les métadonnées. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs fois.

L'option fallback-x11 rend le socket X11 disponible uniquement si il n'y a pas de socket Wayland. Cette opt

ion a été introduite dans 0.11.3. Pour prendre en charge les versions plus anciennes de Flatpak, spécifiez
à la fois x11 et fallback-x11. L'option fallback-x11 prend le dessus lorsque les deux sont pris en charge.

--nosocket=SOCKE

T
Ne pas exposer un socket bien connu à l'application. Cela met à jour le groupe [Context] dans les métadonnées. SOCKET doit être l'un des suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs
fois.

--device=PÉRIPHÉRIQU

E
Exposer un périphérique à l'application. Cela met à jour le groupe [Context] dans les métadonnées. PÉRIPHÉRIQUE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs
fois.

--nodevice=PÉRIPHÉRIQU

E
Ne pas exposer un périphérique à l'application. Cela met à jour le groupe [Context] dans les métadonnées. PÉRIPHÉRIQUE doit être l'un des suivants : dri, input, usb, kvm, shm, all. Cette option peut être utilisée plusieurs
fois.

--allow=FONCTIONNALIT

É
Autoriser l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FONCTIONNALITÉ doit être l'une des suivantes : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs fois.

La fonctionnalité devel permet à l'application d'accéder à certaines appels système tels que ptrace(), et perf_event_open()

.

La fonctionnalité multiarch permet à l'application d'exécuter des programmes compilés pour une ABI autre que celle prise en charge nativement par le système. Par exemple, pour l'architecture x86_64, les binaires x86 32 bits seront également

autorisés.

La fonctionnalité bluetooth permet à l'application d'utiliser les sockets bluetooth (AF_BLUETOOTH). Notez que pour que le bluetooth fonctionne pleinement, vous devez également avoir un accès

réseau.

La fonctionnalité canbus permet à l'application d'utiliser les sockets canbus (AF_CAN). Notez que pour que cela fonctionne, vous devez également avoir un accès

réseau.

La fonctionnalité per-app-dev-shm partage une seule instance de /dev/shm entre l'app

lication, tous les sous-sboîtes non restreints qu'elle crée, et toutes les autres i
nstances de l'application qui sont lancées pendant qu'elle est en cours d'exécution.

--disallow=FONCTIONNALIT

É
Refuser l'accès à une fonctionnalité spécifique. Cela met à jour le groupe [Context] dans les métadonnées. FONCTIONNALITÉ doit être l'une des suivantes : devel, multiarch, bluetooth, canbus, per-app-dev-shm. Cette option peut être utilisée plusieurs
fois.

--filesystem=SYSTÈME-DE-FICHIE

RS
Autoriser l'accès de l'application à un sous-ensemble du système de fichiers. Cela met à jour le groupe [Context] dans les métadonnées. SYSTÈME-DE-FICHIERS peut être l'un des suivants : home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, xdg-run, xdg-config, xdg-cache, xdg-data, un chemin absolu, ou un chemin relatif au répertoire home comme ~/dir ou des chemins relatifs aux répertoires xdg, comme xdg-download/subdir. Le suffixe :ro optionnel indique que l'emplacement sera en lecture seule. Le suffixe :create optionnel indique que l'emplacement sera en lecture-écriture et sera créé s'il n'existe pas. Cette option peut être utilisée plusieurs fois. Voir la liste "[Context] filesystems" dans flatpak-metadata(5) pour des détails sur la signification de ces systèmes de
fichiers.

--nofilesystem=SYSTÈME-DE-FICHIER

S
Supprimer l'accès au sous-ensemble spécifié du système de fichiers de l'application. Cela remplace la section Context des métadonnées de l'application. SYSTÈME-DE-FICHIERS peut être l'un des suivants : home, host, host-os, host-etc, xdg-desktop, xdg-documents, xdg-download, xdg-music, xdg-pictures, xdg-public-share, xdg-templates, xdg-videos, un chemin absolu, ou un chemin relatif au répertoire home comme ~/dir. Cette option peut être utilisée plusieurs
fois.

--add-policy=SOUS-SYSTÈME.

CLÉ=VALEUR
Ajouter une option de politique générique. Par exemple, "--add-policy=subsystem.key=v1 --add-policy=subsystem.key=v2" correspondrait à ces métadonnées : 
[Policy su
bsystem]
key=v1;v2;

Cette option peu

t être utilisée
plusieurs fois.

--remove-policy=SOUS-SYSTÈME.

CLÉ=VALEUR
Supprimer une option de politique générique. Cette option peut être utilisée plusieurs
fois.

--usb=TYPE[:

DONNÉES]
Rend les périphériques USB correspondant à la requête visibles pour le portail USB en ajoutant la requête aux métadonnées de l'application. Cela n'a aucun effet sur les périphériques exposés dans /dev. TYPE doit être l'un des suivants : all, cls, dev, vnd.

al

l
Correspondre à tous les
périphériques.

cl

s
Une requête de classe et sous-classe de périphérique. DONNÉES doit être sous la forme CLASSE:SOUS-CLASSE où CLASSE et SOUS-CLASSE doivent être des numéros d'identification de classe hexadécimaux valides à 2 chiffres. Alternativement, SOUS-CLASSE peut être * pour correspondre à toutes les
sous-classes.

de

v
Une requête d'identification de produit de périphérique. DONNÉES doit être un numéro d'identification de produit hexadécimal valide à 4 caractères, par exemple 0a1b. Elle nécessite un filtre vnd dans la
requête.

vn

d
Une requête d'identification de fournisseur de périphérique. DONNÉES doit être un numéro d'identification de fournisseur hexadécimal valide à 4 caractères supérieur à zéro, par exemple 0fab
.

Il est possible de composer plusieurs requêtes de périphériques ensemble avec le signe +, par exemple --usb=vnd:0123+dev:4567. Le filtre dev n

écessite un vnd. Disp
onible depuis 1.15.11.

--nousb=TYPE[:

DONNÉES]
Masquer les périphériques USB correspondant à la requête du portail USB en ajoutant la requête aux métadonnées de l'application. Les requêtes qui masquent des périphériques priment sur les requêtes qui rendent les périphériques visibles (voir --usb). La syntaxe est exactement la même que --usb. Cela n'a aucun effet sur les périphériques exposés dans /dev. Disponible depuis 1.15.
11.

--usb-list-file=NOM-FICHIE

R
Ajouter des requêtes de périphériques USB aux métadonnées de l'application à partir du fichier NOM-FICHIER. La syntaxe de la ligne est exactement la même que --usb. De plus, si elle commence par !, alors la requête est comme pour --nousb. Les lignes qui commencent par # sont ignorées, comme un commentaire. Les commentaires ne seront pas persistants. Disponible depuis la version 1.15.11.

--usb-list=LIST

Ajoute des requêtes de périphériques USB aux métadonnées de l'application à partir de LIST. La syntaxe est exactement la même que pour --usb avec des requêtes séparées par des ;. De plus, si la requête commence par ! alors la requête est comme pour --nousb. Disponible depuis la version 1.15.11.

--env=VAR=VALEUR

Définit une variable d'environnement dans l'application. Cela met à jour le groupe [Environment] dans les métadonnées. Cela remplace la section Context des métadonnées de l'application. Cette option peut être utilisée plusieurs fois.

--unset-env=VAR

Supprime une variable d'environnement dans l'application. Cela met à jour l'entrée unset-environment dans le groupe [Context] des métadonnées. Cette option peut être utilisée plusieurs fois.

--env-fd=FD

Lit les variables d'environnement à partir du descripteur de fichier FD et les définit comme si elles étaient passées via --env. Ceci peut être utilisé pour éviter que les variables d'environnement et leurs valeurs ne soient visibles par d'autres utilisateurs.

Chaque variable d'environnement est sous la forme VAR=VALEUR suivie d'un octet nul. C'est le même format utilisé par env -0 et /proc/*/environ.

--own-name=NOM

Autorise l'application à posséder le nom bien connu NOM sur le bus de session. Si NOM se termine par .*, cela autorise l'application à posséder tous les noms correspondants. Cela met à jour le groupe [Session Bus Policy] dans les métadonnées. Cette option peut être utilisée plusieurs fois.

--talk-name=NOM

Autorise l'application à communiquer avec le nom bien connu NOM sur le bus de session. Si NOM se termine par .*, cela autorise l'application à communiquer avec tous les noms correspondants. Cela met à jour le groupe [Session Bus Policy] dans les métadonnées. Cette option peut être utilisée plusieurs fois.

--system-own-name=NOM

Autorise l'application à posséder le nom bien connu NOM sur le bus système. Si NOM se termine par .*, cela autorise l'application à posséder tous les noms correspondants. Cela met à jour le groupe [System Bus Policy] dans les métadonnées. Cette option peut être utilisée plusieurs fois.

--system-talk-name=NOM

Autorise l'application à communiquer avec le nom bien connu NOM sur le bus système. Si NOM se termine par .*, cela autorise l'application à communiquer avec tous les noms correspondants. Cela met à jour le groupe [System Bus Policy] dans les métadonnées. Cette option peut être utilisée plusieurs fois.

--persist=NOMFICHIER

Si l'application n'a pas accès au vrai répertoire personnel, le chemin FILENAME (relatif au répertoire personnel) sera monté en bind sur le chemin correspondant dans le répertoire par application, permettant ainsi à cet emplacement d'être utilisé pour les données persistantes. Cela met à jour le groupe [Context] dans les métadonnées. Cette option peut être utilisée plusieurs fois.

--runtime=RUNTIME, --sdk=SDK

Change le runtime ou le sdk utilisé par l'application pour le ref partiel spécifié. Les parties non spécifiées du ref sont prises des anciennes valeurs ou des valeurs par défaut.

--metadata=GROUPE=CLE[=VALEUR]

Définit une clé générique dans le fichier de métadonnées. Si la valeur est omise, elle sera définie à "true".

--extension=NOM=VARIABLE[=VALEUR]

Ajoute des informations de point d'extension. Voir la documentation de flatpak-metadata(5) pour les valeurs possibles de VARIABLE et VALEUR.

--remove-extension=NOM

Supprime les informations de point d'extension.

--extension-priority=VALEUR

Définit la priorité (ordre de remplacement de la bibliothèque) du point d'extension. Uniquement utile pour les extensions. 0 est la valeur par défaut, et une valeur plus élevée signifie une priorité plus élevée.

--extra-data=NOM:SHA256:TAILLE-TELECHARGEMENT:TAILLE-INSTALLATION:URL

Ajoute des informations sur les URI de données supplémentaires à l'application. Celles-ci seront téléchargées et vérifiées par le client lors de l'installation de l'application et placées dans le répertoire /app/extra. Vous pouvez également fournir un script /app/bin/apply_extra qui sera exécuté après le téléchargement des fichiers.

--no-exports

Ne cherche pas d'exports dans la construction.

--no-inherit-permissions

N'hérite pas des permissions du runtime dans l'application.

-v, --verbose

Affiche des informations de débogage pendant le traitement de la commande.

--ostree-verbose

Affiche des informations de débogage OSTree pendant le traitement de la commande.
