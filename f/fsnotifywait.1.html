inotifywait(1) Manuel des commandes générales inotifywait(1)

NOM

inotifywait, fsnotifywait - attendre des modifications de fichiers en utilisant inotify ou fanotify

SYNTAXE

inotifywait [-hcmrPqIFS] [-e <événement> ] [-t <secondes> ] [--format <fmt> ] [--timefmt <fmt> ] <fichier> [ ... ]

fsnotifywait [-hcmrPqIFS] [-e <événement> ] [-t <secondes> ] [--format <fmt> ] [--timefmt <fmt> ] <fichier> [ ... ]

DESCRIPTION

inotifywait attend efficacement les modifications de fichiers en utilisant l'interface inotify(7) de Linux par défaut. Il convient pour attendre des modifications de fichiers depuis des scripts shell. Il peut soit se terminer une fois qu'un événement se produit, soit s'exécuter continuellement et afficher les événements au fur et à mesure qu'ils se produisent.

fsnotifywait est similaire à inotifywait mais utilise l'interface fanotify(7) de Linux par défaut. S'il est explicitement spécifié, il utilise l'interface inotify(7).

SORTIE

inotifywait et fsnotifywait afficheront des informations diagnostiques sur la sortie d'erreur standard et des informations d'événement sur la sortie standard. La sortie d'événement peut être configurée, mais par défaut elle consiste en des lignes de la forme suivante :

nom_fichier_surveillé NOMS_ÉVÉNEMENT nom_fichier_événement

nom_fichier_surveillé
est le nom du fichier sur lequel l'événement s'est produit. Si le fichier est un répertoire, une barre oblique finale est affichée.
NOMS_ÉVÉNEMENT
sont les noms des événements inotify qui se sont produits, séparés par des virgules.
nom_fichier_événement
est affiché uniquement lorsque l'événement s'est produit sur un répertoire, et dans ce cas le nom du fichier dans le répertoire qui a causé cet événement est affiché.

Par défaut, les caractères spéciaux dans les noms de fichiers ne sont pas échappés de quelque manière que ce soit. Cela peut rendre la sortie de inotifywait difficile à analyser dans des scripts awk ou similaires. Les options --csv et --format seront utiles dans ce cas.

OPTIONS

-h, --help
Affiche une aide utile sur l'utilisation.
@<fichier>
Lors de la surveillance d'une arborescence de répertoires de manière récursive, exclut le fichier spécifié de la surveillance. Le fichier doit être spécifié avec un chemin relatif ou absolu selon que vous donnez un chemin relatif ou absolu pour les répertoires surveillés. Si un chemin spécifique est explicitement à la fois inclus et exclu, il sera toujours surveillé.

Note : Si vous avez besoin de surveiller un répertoire ou un fichier dont le nom commence par @, donnez le chemin absolu.

--fromfile <fichier>
Lit les noms de fichiers à surveiller ou à exclure d'un fichier, un nom de fichier par ligne. Si les noms de fichiers commencent par @, ils sont exclus comme décrit ci-dessus. Si <fichier> est `-', les noms de fichiers sont lus depuis l'entrée standard. Utilisez cette option si vous avez besoin de surveiller trop de fichiers pour les passer en arguments de ligne de commande.
-m, --monitor
Au lieu de se terminer après la réception d'un seul événement, exécutez indéfiniment. Le comportement par défaut est de se terminer après le premier événement.
-d, --daemon
Identique à --monitor, sauf qu'il s'exécute en arrière-plan en enregistrant les événements dans un fichier qui doit être spécifié par --outfile. Implique --syslog.
-o, --outfile <fichier>
Affiche les événements dans <fichier> plutôt que sur stdout.
-s, --syslog
Affiche les erreurs dans le module de journalisation système syslog(3) plutôt que sur stderr.
-P, --no-dereference
Ne suit pas les liens symboliques.
-r, --recursive
Surveille tous les sous-répertoires des répertoires passés en arguments. Les surveillances seront établies récursivement à une profondeur illimitée. Les liens symboliques ne sont pas parcourus. Les sous-répertoires nouvellement créés seront également surveillés.

Attention : Si vous utilisez cette option tout en surveillant la racine d'une grande arborescence, cela peut prendre beaucoup de temps avant que toutes les surveillances inotify ne soient établies, et les événements ne seront pas reçus pendant ce temps. De plus, comme une surveillance inotify sera établie par sous-répertoire, il est possible que le nombre maximum de surveillances inotify par utilisateur soit atteint. La limite par défaut est 8192 ; elle peut être augmentée en écrivant dans /proc/sys/fs/inotify/max_user_watches.

-q, --quiet
Si spécifié une fois, le programme sera moins verbeux. Spécifiquement, il n'indiquera pas quand il a terminé d'établir toutes les surveillances inotify.

Si spécifié deux fois, le programme ne produira aucune sortie, sauf en cas d'erreurs fatales.

--exclude <motif>
Ne traite aucun événement pour le sous-ensemble de fichiers dont les noms correspondent à l'expression régulière POSIX spécifiée, sensible à la casse.
--excludei <motif>
Ne traite aucun événement pour le sous-ensemble de fichiers dont les noms correspondent à l'expression régulière POSIX spécifiée, insensible à la casse.
--include <motif>
Ne traite les événements que pour le sous-ensemble de fichiers dont les noms correspondent à l'expression régulière POSIX spécifiée, sensible à la casse. Lorsqu'il est utilisé avec --recursive, les événements seront toujours générés pour les fichiers correspondants dans les répertoires nouvellement créés, même si les noms de répertoires eux-mêmes ne correspondent pas au motif.
--includei <motif>
Ne traite les événements que pour le sous-ensemble de fichiers dont les noms correspondent à l'expression régulière POSIX spécifiée, insensible à la casse.
-t <secondes>, --timeout <secondes>
Se termine si un événement approprié ne s'est pas produit dans les <secondes> secondes. Si <secondes> est zéro (la valeur par défaut), attend indéfiniment un événement.
-e <événement>, --event <événement>
Écoute uniquement des événements spécifiques. Les événements pour lesquels il est possible d'écouter sont listés dans la section ÉVÉNEMENTS. Cette option peut être spécifiée plusieurs fois. Si omise, tous les événements sont écoutés.
-c, --csv
Produit une sortie au format CSV (valeurs séparées par des virgules). Ceci est utile lorsque les noms de fichiers peuvent contenir des espaces, car dans ce cas, il n'est pas sûr de simplement diviser la sortie à chaque caractère d'espacement.
--timefmt <fmt>
Définit une chaîne de format de temps acceptée par strftime(3) pour une utilisation avec la conversion `%T' dans l'option --format.
--no-newline
N'imprime pas le symbole de nouvelle ligne après le format spécifié par l'utilisateur dans l'option --format.
--format <fmt>
Produit une sortie dans un format spécifié par l'utilisateur, en utilisant une syntaxe de type printf. Les chaînes d'événements produites sont limitées à environ 4000 caractères et seront tronquées à cette longueur. Les conversions suivantes sont prises en charge :
%w
Sera remplacé par le nom du fichier Surveillé sur lequel un événement s'est produit. Lorsqu'un événement se produit dans un répertoire Surveillé ou lors de la surveillance avec fanotify, il sera remplacé par le nom du Répertoire dans lequel l'événement s'est produit.
%f
Lorsqu'un événement se produit dans un répertoire Surveillé ou lors de la surveillance avec fanotify, il sera remplacé par le nom du Fichier qui a provoqué l'événement. Sinon, il sera remplacé par une chaîne vide.
%e
Remplacé par l'Événement(s) qui se sont produits, séparés par des virgules.
%Xe
Remplacé par l'Événement(s) qui se sont produits, séparés par le caractère qui

STATUT DE SORTIE

0
Le programme s'est exécuté avec succès et un événement attendu s'est produit.
1
Une erreur s'est produite lors de l'exécution du programme, ou un événement non attendu s'est produit. Ce dernier cas se produit généralement si quelque chose force la suppression de la surveillance inotify, comme la suppression d'un fichier surveillé ou le démontage du système de fichiers contenant un fichier surveillé.
2
L'option -t a été utilisée et aucun événement ne s'est produit dans le délai imparti.

ÉVÉNEMENTS

Les événements suivants sont valides pour l'option -e :

access
Un fichier surveillé ou un fichier dans un répertoire surveillé a été lu.
modify
Un fichier surveillé ou un fichier dans un répertoire surveillé a été écrit.
attrib
Les métadonnées d'un fichier surveillé ou d'un fichier dans un répertoire surveillé ont été modifiées. Cela inclut les horodatages, les permissions de fichiers, les attributs étendus, etc.
close_write
Un fichier surveillé ou un fichier dans un répertoire surveillé a été fermé, après avoir été ouvert en mode écriture. Cela n'implique pas nécessairement que le fichier a été écrit.
close_nowrite
Un fichier surveillé ou un fichier dans un répertoire surveillé a été fermé, après avoir été ouvert en mode lecture seule.
close
Un fichier surveillé ou un fichier dans un répertoire surveillé a été fermé, quelle que soit la manière dont il a été ouvert. Notez que ceci est en réalité implémenté en surveillant à la fois close_write et close_nowrite, donc tous les événements de fermeture reçus seront affichés comme l'un de ceux-ci, pas comme CLOSE.
open
Un fichier surveillé ou un fichier dans un répertoire surveillé a été ouvert.
moved_to
Un fichier ou un répertoire a été déplacé dans un répertoire surveillé. Cet événement se produit même si le fichier est simplement déplacé de et vers le même répertoire.
moved_from
Un fichier ou un répertoire a été déplacé hors d'un répertoire surveillé. Cet événement se produit même si le fichier est simplement déplacé de et vers le même répertoire.
move
Un fichier ou un répertoire a été déplacé depuis ou vers un répertoire surveillé. Notez que ceci est en réalité implémenté en surveillant à la fois moved_to et moved_from, donc tous les événements de déplacement reçus seront affichés comme l'un ou les deux, pas comme MOVE.
move_self
Un fichier ou répertoire surveillé a été déplacé. Après cet événement, le fichier ou répertoire n'est plus surveillé.
create
Un fichier ou un répertoire a été créé dans un répertoire surveillé.
delete
Un fichier ou un répertoire dans un répertoire surveillé a été supprimé.
delete_self
Un fichier ou répertoire surveillé a été supprimé. Après cet événement, le fichier ou répertoire n'est plus surveillé. Notez que cet événement peut se produire même s'il n'est pas explicitement surveillé.
unmount
Le système de fichiers sur lequel réside un fichier ou répertoire surveillé a été démonté. Après cet événement, le fichier ou répertoire n'est plus surveillé. Notez que cet événement peut se produire même s'il n'est pas explicitement surveillé.

EXEMPLES

Exemple 1

Exécution de inotifywait en ligne de commande pour attendre l'accès à n'importe quel fichier dans le répertoire `test'. Après l'exécution de inotifywait, `cat test/foo' est exécuté dans une console séparée.

% inotifywait test
Mise en place des surveillances.
Surveillances établies.
test/ ACCESS foo

Exemple 2

Un script shell court pour attendre efficacement les messages de log liés à httpd et effectuer une action appropriée.

#!/bin/sh
while ! inotifywait -e modify /var/log/messages; do
  if tail -n1 /var/log/messages | grep httpd; then
    kdialog --msgbox "Apache a besoin d'attention !"
  fi
done

Exemple 3

Un format de sortie personnalisé est utilisé pour surveiller `~/test'. Pendant ce temps, quelqu'un exécute `touch ~/test/badfile; touch ~/test/goodfile; rm ~/test/badfile' dans une autre console.

% inotifywait -m -r --format '%:e %f' ~/test
Mise en place des surveillances. Attention : puisque -r a été donné, cela peut prendre un certain temps !
Surveillances établies.
CREATE badfile
OPEN badfile
ATTRIB badfile
CLOSE_WRITE:CLOSE badfile
CREATE goodfile
OPEN goodfile
ATTRIB goodfile
CLOSE_WRITE:CLOSE goodfile
DELETE badfile

Exemple 4

Appliquer des permissions de fichiers dans le répertoire `~/test'

inotifywait -qmr -e 'moved_to,create' --format '%w%f%0' --no-newline ~/test |\
    while IFS= read -r -d '' file
    do
	  chmod -v a+rX "$file"
    done

AVERTISSEMENTS

Lors de l'utilisation de inotifywait, le nom de fichier qui est affiché n'est pas garanti d'être à jour après un déplacement car c'est l'inode qui est surveillé. De plus, aucune des opérations observées n'est garantie d'avoir été effectuée sur le nom de fichier que inotifywait a été instruit de surveiller dans les cas où le fichier est connu sous plusieurs noms dans le système de fichiers.

BOGUES

Il existe des conditions de concurrence dans le code de surveillance récursive des répertoires qui peuvent entraîner la perte d'événements s'ils se produisent dans un répertoire immédiatement après la création de ce répertoire. Ceci n'est probablement pas réparable.

On suppose que la file d'attente des événements inotify ne débordera jamais.
