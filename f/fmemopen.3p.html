FMEMOPEN(3P) Manuel du programmeur POSIX FMEMOPEN(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man correspondante de Linux pour plus de détails sur le comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

fmemopen — ouvrir un flux de mémoire tampon

SYNOPSIS

#include <stdio.h>
FILE *fmemopen(void *restrict buf, size_t size,
    const char *restrict mode);

DESCRIPTION

La fonction fmemopen() doit associer le tampon donné par les arguments buf et size à un flux. L'argument buf doit être soit un pointeur nul, soit pointer vers un tampon d'au moins size octets de longueur.

L'argument mode pointe vers une chaîne de caractères. Si la chaîne est l'une des suivantes, le flux doit être ouvert dans le mode indiqué. Sinon, le comportement est indéfini.

r
Ouvrir le flux en lecture.
w
Ouvrir le flux en écriture.
a
Ajout ; ouvrir le flux en écriture au premier octet nul.
r+
Ouvrir le flux pour mise à jour (lecture et écriture).
w+
Ouvrir le flux pour mise à jour (lecture et écriture). Tronquer le contenu du tampon.
a+
Ajout ; ouvrir le flux pour mise à jour (lecture et écriture) ; la position initiale est au premier octet nul.

Les implémentations doivent accepter toutes les chaînes de mode autorisées par fopen(), mais l'utilisation du caractère 'b' doit produire des résultats définis par l'implémentation, où le FILE * résultant n'a pas besoin de se comporter comme si 'b' avait été omis.

Si un pointeur nul est spécifié comme argument buf , fmemopen() doit allouer size octets de mémoire comme par un appel à malloc(). Ce tampon doit être automatiquement libéré lorsque le flux est fermé. Comme cette fonctionnalité n'est utile que lorsque le flux est ouvert pour mise à jour (car il n'y a aucun moyen d'obtenir un pointeur vers le tampon), l'appel fmemopen() peut échouer si l'argument mode n'inclut pas un '+'.

Le flux doit maintenir une position courante dans le tampon. Cette position doit être initialement définie soit au début du tampon (pour les modes r et w ), soit au premier octet nul du tampon (pour les modes a ). Si aucun octet nul n'est trouvé en mode ajout, la position initiale doit être définie à un octet après la fin du tampon.

Si buf est un pointeur nul, la position initiale doit toujours être définie au début du tampon.

Le flux doit également maintenir la taille du contenu courant du tampon ; l'utilisation de fseek() ou fseeko() sur le flux avec SEEK_END doit effectuer un déplacement relatif à cette taille. Pour les modes r et r+ , la taille doit être définie à la valeur donnée par l'argument size . Pour les modes w et w+ , la taille initiale doit être zéro et pour les modes a et a+ , la taille initiale doit être :

*
Zéro, si buf est un pointeur nul
*
La position du premier octet nul dans le tampon, si un est trouvé
*
La valeur de l'argument size , si buf n'est pas un pointeur nul et aucun octet nul n'est trouvé

Une opération de lecture sur le flux ne doit pas faire avancer la position courante du tampon au-delà de la taille courante du tampon. L'atteinte de la taille du tampon lors d'une opération de lecture doit compter comme « fin de fichier ». Les octets nuls dans le tampon ne doivent avoir aucune signification particulière pour les lectures. L'opération de lecture doit commencer à la position courante du tampon du flux.

Une opération d'écriture doit commencer soit à la position courante du flux (si mode n'a pas spécifié 'a' comme premier caractère), soit à la taille courante du flux (si mode avait 'a' comme premier caractère). Si la position courante à la fin de l'écriture est plus grande que la taille courante du tampon, la taille courante du tampon doit être définie à la position courante. Une opération d'écriture sur le flux ne doit pas faire avancer la taille courante du tampon au-delà de la taille donnée dans l'argument size .

Lorsqu'un flux ouvert en écriture est vidé ou fermé, un octet nul doit être écrit à la position courante ou à la fin du tampon, selon la taille du contenu. Si un flux ouvert pour mise à jour est vidé ou fermé et que la dernière écriture a fait avancer la taille courante du tampon, un octet nul doit être écrit à la fin du tampon s'il y a de la place.

Une tentative de déplacer un flux de mémoire tampon vers une position négative ou vers une position plus grande que la taille du tampon donnée dans l'argument size doit échouer.

VALEUR RETOURNÉE

Lors de l'achèvement réussi, fmemopen() doit renvoyer un pointeur vers l'objet contrôlant le flux. Sinon, un pointeur nul doit être renvoyé, et errno doit être défini pour indiquer l'erreur.

ERREURS

La fonction fmemopen() doit échouer si :

EMFILE
{STREAM_MAX} flux sont actuellement ouverts dans le processus appelant.

La fonction fmemopen() peut échouer si :

EINVAL
La valeur de l'argument mode n'est pas valide.
EINVAL
L'argument buf est un pointeur nul et l'argument mode n'inclut pas de caractère '+' .
EINVAL
L'argument size spécifie une taille de tampon de zéro et l'implémentation ne le prend pas en charge.
ENOMEM
L'argument buf est un pointeur nul et l'allocation d'un tampon de longueur size a échoué.
EMFILE
{FOPEN_MAX} flux sont actuellement ouverts dans le processus appelant.

EXEMPLES

#include <stdio.h>
#include <string.h>
static char buffer[] = "foobar";
int
main (void)
{
    int ch;
    FILE *stream;
    stream = fmemopen(buffer, strlen (buffer), "r");
    if (stream == NULL)
        /* handle error */;
    while ((ch = fgetc(stream)) != EOF)
        printf("Got %c\n", ch);
    fclose(stream);
    return (0);
}

Ce programme produit la sortie suivante :

Got f
Got o
Got o
Got b
Got a
Got r

UTILISATION EN APPLICATION

Aucune.

JUSTIFICATION

Cette interface a été introduite pour éliminer de nombreuses erreurs rencontrées lors de la construction de chaînes, notamment les débordements de chaînes. Cette interface empêche les débordements.

PERSPECTIVES

Une future version de cette norme peut prescrire un comportement spécifique lorsque l'argument mode inclut 'b'.

Une future version de cette norme peut exiger explicitement la prise en charge des flux de tampon de longueur zéro.
