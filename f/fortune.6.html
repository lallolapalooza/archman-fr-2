FORTUNE(6) Manuel de référence UNIX FORTUNE(6)

NOM

fortune - afficher un adage aléatoire, espérons-le intéressant

SYNOPIS


fortune [-acefilosw]
[-n longueur]
[-m modèle]
[[n%] fichier/répertoire/tout]

DESCRIPTION

Lorsque fortune est exécuté sans arguments, il affiche un épigramme aléatoire. Les épigrammes sont divisés en plusieurs catégories.

Options

Les options sont les suivantes :

-a

Choisir parmi toutes les listes d'aphorismes.

-c

Afficher le fichier de cookies d'où provient la fortune.

-e

Considérer tous les fichiers de fortunes comme de taille égale (voir la discussion ci-dessous sur les fichiers multiples).

-f

Afficher la liste des fichiers qui seraient recherchés, mais sans afficher de fortune.

-l

Uniquement les dictions longues. Voir -n pour définir ce qu'est une “longue” dans ce sens.

-m modèle

Afficher toutes les fortunes qui correspondent à l'expression régulière de base modèle. La syntaxe de ces expressions dépend de la façon dont votre système définit re_comp(3) ou regcomp(3), mais elle devrait néanmoins être similaire à la syntaxe utilisée dans grep(1).

Les fortunes sont envoyées à la sortie standard, tandis que les noms des fichiers d'où proviennent chaque fortune sont imprimés sur la sortie d'erreur standard. L'une ou l'autre, ou les deux, peuvent être redirigées ; si la sortie standard est redirigée vers un fichier, le résultat est un fichier de base de données de fortunes valide. Si la sortie d'erreur standard est également redirigée vers ce fichier, le résultat est toujours valide, mais il y aura des fortunes “falsifiées”, c'est-à-dire les noms de fichiers eux-mêmes, entre parenthèses. Ceci peut être utile si vous souhaitez supprimer les correspondances collectées de leurs fichiers d'origine, car chaque enregistrement de nom de fichier précédera les enregistrements du fichier qu'il nomme.

-n longueur

Définir la longueur maximale de fortune (en caractères) considérée comme “courte” (la valeur par défaut est 160). Toutes les fortunes plus longues que cela sont considérées comme “longues”. Faites attention ! Si vous définissez une longueur trop courte et demandez des fortunes courtes, ou trop longue et demandez des fortunes longues, fortune entrera dans une boucle infernale sans fin.

-s

Uniquement les aphorismes courts. Voir -n pour définir quelles fortunes sont considérées comme “courtes”.

-i

Ignorer la casse pour les motifs -m.

-w

Attendre avant de se terminer pendant une durée calculée à partir du nombre de caractères du message. Ceci est utile s'il est exécuté dans le cadre de la procédure de déconnexion pour garantir que le message peut être lu avant que l'écran ne soit effacé.

L'utilisateur peut spécifier des aphorismes alternatifs. Vous pouvez spécifier un fichier spécifique, un répertoire contenant un ou plusieurs fichiers, ou le mot spécial tout qui indique d'utiliser toutes les bases de données standard. Chacun de ceux-ci peut être précédé d'un pourcentage, qui est un nombre n compris entre 0 et 100 inclus, suivi d'un %. S'il y en a, il y aura une probabilité de n pour cent de choisir un adage de ce fichier ou répertoire. Si les pourcentages ne totalisent pas 100, et qu'il y a des spécifications sans pourcentages, le pourcentage restant s'appliquera à ces fichiers et/ou répertoires, auquel cas la probabilité de sélectionner parmi eux sera basée sur leur taille relative.

Par exemple, étant donné deux bases de données funny et not-funny, avec funny deux fois plus grand (en nombre de fortunes, pas en taille de fichier brute), dire

fortune funny not-funny

vous apportera des fortunes de funny deux tiers du temps. La commande

fortune 90% funny 10% not-funny

choisira 90% de ses fortunes dans funny (les “10% not-funny” sont inutiles, puisque 10% est tout ce qui reste).

L'option -e indique de considérer tous les fichiers comme égaux ; donc

fortune -e funny not-funny

est équivalent à

fortune 50% funny 50% not-funny

FICHIERS

Note : ce sont les valeurs par défaut telles que définies à la compilation.

/usr/share/fortune Répertoire pour les fortunes inoffensives.

Si un ensemble particulier de fortunes est particulièrement indésirable, il existe une solution simple : supprimer le fichier .dat associé. Cela laisse les données intactes, au cas où le fichier serait voulu plus tard, mais comme fortune ne trouve plus le fichier de pointeurs, il ignore le fichier texte.

BOGUES

Les bases de données de fortunes fournies ont été attaquées, afin de corriger les erreurs orthographiques et grammaticales, et en particulier pour réduire la redondance et la répétition et la redondance. Mais surtout pour éviter la répétitivité. Cela n'a pas été un succès complet. Dans le processus, certaines fortunes ont pu également être perdues.

Les bases de données de fortunes sont maintenant divisées en un plus grand nombre de fichiers plus petits, certains organisés par format (poésie, définitions), et d'autres par contenu (religion, politique).

HISTORIQUE

Cette version de fortune est basée sur la version 1.4 de NetBSD fortune, mais avec un certain nombre de corrections de bogues et d'améliorations.

Le format original fortune/strfile utilisait un seul fichier ; strfile lisait le fichier texte et le convertissait en chaînes délimitées par un caractère nul, qui étaient stockées après le tableau de pointeurs dans le fichier .dat. À la version 1.4 de NetBSD fortune, cela avait été modifié en deux fichiers séparés : le fichier .dat n'était que l'en-tête (le tableau de pointeurs, plus les drapeaux ; voir strfile.h), et les chaînes de texte restaient dans leur propre fichier. Le problème potentiel avec cela est que le fichier texte et le fichier d'en-tête peuvent se désynchroniser, mais l'avantage est que les fichiers texte peuvent être facilement modifiés sans recourir à unstr, et il y a une économie potentielle d'espace disque (en supposant que l'administrateur système a conservé à la fois le fichier .dat avec les chaînes et le fichier texte).

Beaucoup des améliorations apportées par rapport à la version NetBSD supposaient un système Linux, et le faisaient donc échouer sur d'autres plateformes, y compris BSD. Le code source a depuis été rendu plus générique, et fonctionne actuellement sur SunOS 4.x ainsi que sur Linux, avec une prise en charge de plus de plateformes attendue à l'avenir. Notez que certains bogues ont été involontairement découverts et corrigés au cours de ce processus.

À vue de nez, un grand nombre de personnes ont travaillé sur ce programme, beaucoup sans laisser d'attributions.

FORTUNE(6) Commandes utilisateur FORTUNE(6)

Nom

fortune - affiche une citation appropriée

Synopsis

fortune [-a] [-c] [-e] [-i] [-l] [-m] [-n nombre] [-of] [-s] [-T taille] [fichier ...]

Description

fortune choisit au hasard une citation de l'un des fichiers spécifiés, ou de ceux par défaut si aucun n'est donné, et l'affiche sur la sortie standard.

Les citations sont triées par catégorie. Par défaut, la citation sera d'une catégorie qui correspond à votre terminal, sauf si vous spécifiez le contraire.

La plupart des citations sont données avec la permission de leurs auteurs.

Il existe des fichiers de citations séparés pour les citations courtes et les citations longues.

Les fichiers de citations sont des fichiers texte contenant des citations séparées par des lignes contenant un seul caractère « % ». Les citations peuvent être divisées en catégories en plaçant un nom de catégorie suivi d'un « % » au début du fichier.

Le programme fortune cherche dans les répertoires suivants pour trouver les fichiers de citations :

/usr/share/fortune

/usr/local/share/fortune

Fichiers

/usr/share/fortune/ascii.day /usr/share/fortune/definitions /usr/share/fortune/drugs /usr/share/fortune/facts /usr/share/fortune/fortunes /usr/share/fortune/humor /usr/share/fortune/linux /usr/share/fortune/love /usr/share/fortune/meanings /usr/share/fortune/misc /usr/share/fortune/personal /usr/share/fortune/phrases /usr/share/fortune/posix /usr/share/fortune/riddles /usr/share/fortune/science /usr/share/fortune/songs /usr/share/fortune/special /usr/share/fortune/startrek /usr/share/fortune/towel /usr/share/fortune/wisdom

Bugs

La base de données des citations est assez limitée et ne contient pas suffisamment de citations sur certains sujets.

L'algorithme de sélection n'est pas particulièrement intelligent. Pour des résultats plus aléatoires, vous pourriez vouloir utiliser « shuf ».

L'algorithme de sélection aléatoire de la citation n'est pas un algorithme de choix véritablement aléatoire.

Si vous exécutez fortune plusieurs fois rapidement, vous pourriez obtenir la même citation plusieurs fois.

Histoire

Le programme fortune est apparu pour la première fois dans le système d'exploitation Unix.
