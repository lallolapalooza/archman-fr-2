Recherche dans

l'arbre

MIB read_objid prend une chaîne contenant une version textuelle d'un identifiant d'objet (sous forme numérique ou descriptive), et la transforme en la liste de sous-identifiants correspondante. Celle-ci est renvoyée dans le paramètre [[177]] output, avec le nombre de sous-identifiants renvoyés via out_len. Lors de l'appel, out_len doit contenir la longueur maximale du tableau [[180]] output. Si plusieurs identifiants d'objets sont traités, cette longueur doit être réinitialisée avant chaque appel. Cette fonction renvoie une valeur de 1 si elle parvient

à

analyser la chaîne et 0 sinon. snmp_parse_oid est similaire, mais renvoie un pointeur vers

le

tampon OID analysé (ou NULL). get_module_node prend un descripteur et le nom d'un module, et renvoie la liste oid correspondante, de la même
manière que read_objid ci-dessus. Si le nom du module est spécifié comme "ANY", cette routine supposera que le descripteur donné est unique dans l'arbre, et renverra l'entrée correspondante. Si cette hypothèse est invalide, le comportement concernant la variable renvoyée dépend de l'implémentation.

Output

Sortie print_mib affichera une représentation de l'arbre MIB actuellement actif vers le pointeur FILE

spécifié.

print_objid prend un identifiant d'objet (comme renvoyé par read_objid, snmp_parse_oid ou get_module_node), et affiche la forme textuelle de cet OID vers la sortie

standard.

fprint_objid fait de même, mais affiche vers le pointeur FILE spécifié par le paramètre

initial.

snprint_objid affiche les mêmes informations dans le tampon pointé par buf qui est de longueur len. Il renvoie le nombre de caractères affichés, ou -1 si le tampon n'était pas assez grand. Dans ce dernier cas, buf contiendra généralement une version tronquée des informations (mais ce comportement n'est pas garanti)

.

print_description, fprint_description, et snprint_description prennent un identifiant d'objet similaire et affichent une version de la définition MIB pour cet objet, ainsi que l'OID complet. L'argument [[199]] width contrôle la disposition de l'OID. Par

défaut,

le parseur ne sauvegarde pas les descriptions car elles peuvent être énormes. Afin de pouvoir les afficher, il est nécessaire pour invoquer snmp_set_save_descriptions(1)avant d'appeler init_mib

(ou
