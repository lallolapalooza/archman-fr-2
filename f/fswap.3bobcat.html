La

Les implémentations plus récentes peuvent utiliser des opérations de déplacement pour augmenter la vitesse de l'opération d'échange, mais dans les deux cas, une certaine forme de l'opérateur d'affectation doit être disponible. Il est bien connu que des objets

C'est le fondement de la fonction de gabarit FBB::fswap (échange rapide). Cette fonction d'échange utilise simplement la mémoire occupée par les objets pour implémenter l'opération d'échange et elle peut donc être utilisée avec des classes ayant des membres de données const, des membres de données par référence, des pointeurs vers de la mémoire allouée, etc. La fonction utilise simplement un bloc de mémoire libre de la taille de l'objet à échanger. Elle utilise ensuite memcpy(3) pour échanger les informations contenues dans les deux objets, en utilisant le bloc de mémoire libre comme espace réservé. Les

classes

peuvent définir des membres de données qui ne prennent pas en charge l'échange rapide. Si de tels membres de données peuvent être échangés en utilisant soit std::swap ou leur propre membre swap, alors des versions surchargées de fswap peuvent être utilisées pour échanger rapidement des objets de telles classes. De plus, les classes peuvent hériter de classes de base qui ne prennent pas en charge l'échange rapide, mais qui offrent soit leurs propres membres swap, soit peuvent être échangées en utilisant std::swap. Pour ces cas, des versions surchargées de fswap sont également disponibles. Les classes std::string et std::unordered_map sont des exemples de classes dont les objets peuvent ne pas être échangeables à l'aide d'une méthode d'échange rapide. DESCRIPTION


The fswap functions are intended to support efficient object
    swapping. They are template functions, their template argument is the SwapMode
    enumeration. For classes defining a swap member, i.e. having implemented
    their own swap member function, the default swap mode is
    SwapMode::SWAPMEMBER. Classes without a swap member will use
    SwapMode::STDSWAP by default, relying on stdswap(3).
    The default swap mode can always be explicitly requested.


All members of the specified object arguments are swapped.


The fswap functions may be called with a NULL pointer as
    first argument.


If the object type, Demo in the example below, defines a
    member swap, then that member will be used.


The type of the arguments may be specified by the SwapMember
    wrapper.


The fswap functions provide a generic interface to the swap
    operations of classes, and in particular, they provide a way to select the
    most efficient swap operation available for a given class.






NAMESPACE


This function is available in the bobcat
    namespace.






INHERITS FROM


The fswap functions are base class implementations
    of the template member functions of the same name.






ENUMERATION



  
SwapMode::DefaultSwap

  
selects the default swap mode for the class.

  
SwapMode::SWAPMEMBER

  
forces usage of the class's member swap function.

  
SwapMode::STDSWAP

  
forces usage of stdswap(3).








SWAP FUNCTIONS


The various overloaded fswap functions swap
    the specified members of the objects.


An implicit swap member swap is defined by
    the Demo class, which swaps its members.


The fswap functions offer fine-grained control
    over the swap operations, allowing explicit selection of swap modes for
    individual members.






EXAMPLE


The Demo class implements a member swap
    method which swaps all its members.


class Demo
{
    // ... members d_v1 .. d_v5 ...

    public:
        void swap(Demo &rhs)
        {
            fswap(nullptr, *this, rhs);
        }

        void show(char const *msg);
};

void Demo::swap(Demo &rhs)
{
    // using the default swap-mode (SWAPMEMBER)
//  fswap(&d_v1, *this, rhs, d_v3, d_v4);
    // explicitly requesting the
    // swap method, swapping all
//  fswap<SwapMode::SWAPMEMBER>(&d_v1, *this, rhs, d_v3, d_v4);
    // explicitly requesting another
    // swap-mode
//  fswap<SwapMode::STDSWAP>(&d_v1, *this, rhs, d_v3, d_v4);
    // use stdswap by default, but not
    // for d_v4, for which .swap() is
    // used
//  fswap(&d_v1, *this, rhs, d_v3, swapmember(d_v4));
    // same
//  fswap<SwapMode::STDSWAP>(&d_v1, *this, rhs, d_v3,
//                                              swapmember(d_v4));
    // explicitly requesting the already
    // default swap method is OK
//  fswap(&d_v1, *this, rhs, swapmember(d_v3), stdswap(d_v4));
}
void Demo::show(char const *msg)
{
    std::cout << msg << ". " << d_v1 <<
                    ", " << d_v2 <<
                    ", " << d_v3 <<
                    ", " << d_v4 <<
                    ", " << d_v5 <<
                    ’\n’;
}
using namespace std;
int main()
{
    Demo d1(10);
    Demo d2(20);
    d1.show("This is d1:");
    d2.show("This is d2:");
    cout << "swapping...\n";
    d1.swap(d2);
    d1.show("This is d1:");
    d2.show("This is d2:");
}

BOGUES


Les fonctions fswap ne doivent pas être appliquées mécaniquement
    pour échanger des objets de classes ayant des membres pointeurs définissant,
    par exemple, une liste chaînée. Considérer une liste de quatre objets comme:


    A -> B -> C -> D



l'échange rapide de B et C entraînerait la liste corrompue
    suivante:


               +------+
               |      |
    A -> C -+  +-> B -+   +-> D
            |             |
            +-------------+



Cependant, les classes implémentant une structure de données comme
    une liste chaînée peuvent toujours bénéficier d'opérations d'échange rapides:
    en implémentant leur propre membre swap elles pourraient d'abord utiliser un
    échange rapide pour échanger les objets, suivi d'un autre échange rapide pour
    déséchanger leurs pointeurs `next`.


La fonction fswap ne doit pas non plus être utilisée pour des
    objets définissant des pointeurs (arrière) vers leurs propres données. Considérer
    les objets suivants utilisant des pointeurs vers des données et des pointeurs
    (arrière) vers les objets originaux:


    Avant fswap:
        A                                  B
       +--------+   +-----------+         +--------+   +-----------+
       |        |   |           |         |        |   |           |
     +--> *Aimp------> *A (back)--+     +--> *Bimp------> *B (back)--+
     | |        |   |           | |     | |        |   |           | |
     +--**Aimp  |   +-----------+ |     +--**Bimp  |   +-----------+ |
       +--------+ <---------------+       +--------+ <---------------+
    Après fswap:
                     +-------------------------------+
                  +--|-------------------------------|-+
    +-------------|--|-----------------+             | |
    |   A         |  v                 |   B         | v
    |  +--------+ | +-----------+      |  +--------+ | +-----------+
    |  |        | | |           |      |  |        | | |           |
  +-----> *Bimp---+ |  *A (back)--+    +---> *Aimp---+ |  *B (back)--+
  | |  |        |   |           | |       |        |   |           | |
  | +---**Bimp  |   +-----------+ |    +---**Aimp  |   +-----------+ |
  |    +--------+ <---------------+    |  +--------+ <---------------+
  +------------------------------------+


Après l'échange, **Bimp devrait pointer vers l'adresse de Bimp
    (maintenant chez A), mais en fait il pointe vers l'adresse de Aimp
    (maintenant chez B). De même, les pointeurs arrière pointent toujours vers
    leurs objets d'origine plutôt que vers leurs objets échangés.

Toutes les classes stream définissent de tels pointeurs et ne
    peuvent donc pas être échangées à l'aide de fswap.


En bref, fswap ne doit être utilisé que pour des classes auto-définies
    pour lesquelles il peut être prouvé que l'échange rapide ne corrompt pas les
    valeurs de ses données pointeurs.
