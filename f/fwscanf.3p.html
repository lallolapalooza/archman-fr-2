DESCRIPTIO

N

Les fonctionnalités décrites sur cette page de référence sont alignées avec la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 se réfère à la norme ISO

C.

La fonction fwscanf() doit lire depuis le flux d'entrée nommé. La fonction wscanf() doit lire depuis le flux d'entrée standard stdin. La fonction swscanf() doit lire depuis la chaîne de caractères larges ws. Chaque fonction lit des caractères larges, les interprète selon un format et stocke les résultats dans ses arguments. Chacune attend, comme arguments, une chaîne de contrôle de caractères larges format décrite ci-dessous, et un ensemble d' arguments pointeurs indiquant où l'entrée convertie doit être stockée. Le résultat est indéfini s'il y a des arguments insuffisants pour le format. Si

le

format est épuisé alors qu'il reste des arguments, les arguments excédentaires sont évalués mais sinon ignorés. Les conversions peuvent être appliquées au n-ième argument après le format dans la liste d'arguments, plutôt qu'au prochain argument non utilisé. Dans ce cas, le caractère large de spécification de conversion % (voir ci-dessous) est remplacé par la séquence "%n$", où n est un entier décimal dans l'intervalle [1,{NL_ARGMAX}]. Cette fonctionnalité permet la définition de chaînes de caractères larges de format qui sélectionnent des arguments dans un ordre approprié à des langues spécifiques. Dansles chaînes de caractères larges de format contenant la forme "% n$" des spécifications de conversion, il n'est pas spécifié si les arguments numérotés dans la liste d'arguments peuvent être référencés depuis

la

chaîne de caractères larges de format plus d'une fois. Le format peut contenir l'une ou l'autre forme d'une spécification de conversion — c'est-à-dire,% ou "% n$" — mais les deux formes ne peuvent normalement pas être mélangées au sein d'une seule chaîne de caractères larges de format. La seule exception à cela est que %% ou%* peuvent être mélangés avec la forme "% n$". Lorsque des spécifications d'arguments numérotés sont utilisées, spécifier leN-ième argument nécessite que tous les arguments précédents, du premier au

(

N-1)-ième, soient des pointeurs. La fonction fwscanf() dans toutes ses formes permet la détection d'un caractère de base dépendant de la langue dans la chaîne d'entrée, encodé comme une valeur de caractère large. Le caractère de base est défini dans la locale courante (catégorieLC_NUMERIC). Dans la locale POSIX, ou dans une locale où le caractère de base n'est pas défini, le caractère de base doit

par défaut être un <point> (

'.'). Le format est une chaîne de caractères larges composée de zéro ou plusieurs directives. Chaque directive est composée de l'un des éléments suivants : un ou plusieurs caractères larges d'espacement blanc (<espace>, <tabulation>, <retour à la ligne>, <tabulation verticale>, ou <saut de page>) ; un caractère large ordinaire (ni '%' ni un caractère d'espacement blanc) ; ou une spécification de conversion. Il n'est pas spécifié si une erreur d'encodage se produit si la chaîne de format contient des valeurs wchar_t qui ne correspondent pas aux membres du jeu de caractères de la locale courante et si les sémantiques spécifiées ne nécessitent pas que cette valeur

soit traitée par

wcrtomb(). Chaque spécification de conversion est introduite par le'%' ou par la séquence de caractères

"%
n$", après quoi les éléments
suivants apparaissent en séquence :

Les fonctions fwscanf() doivent exécuter chaque directive du format à tour de rôle. Si une directive échoue, comme détaillé ci-dessous, la fonction doit retourner. Les échecs sont décrits comme des échecs d'entrée (dus à l'indisponibilité des octets d'entrée) ou des échecs d'appariement (dus à une entrée inappropriée)

.

Une directive composée de un ou plusieurs caractères larges d'espacement blanc est exécutée en lisant l'entrée jusqu'à ce qu'aucune entrée valide ne puisse plus être lue, ou jusqu'au premier caractère large qui n'est pas un caractère large d'espacement blanc, qui reste non

lu.

Une directive qui est un caractère large ordinaire doit être exécutée comme suit. Le prochain caractère large est lu depuis l'entrée et comparé avec le caractère large qui compose la directive ; si la comparaison montre qu'ils ne sont pas équivalents, la directive doit échouer, et les caractères larges différents et suivants restent non lus. De même, si la fin de fichier, une erreur d'encodage, ou une erreur de lecture empêche un caractère large d'être lu, la directive doit

échouer.

Une directive qui est une spécification de conversion définit un ensemble de séquences d'entrée correspondantes, comme décrit ci-dessous pour chaque caractère large de conversion. Une spécification de conversion est exécutée dans les étapes

suivantes.

Les caractères larges d'espacement blanc d'entrée (comme spécifié par iswspace()) doivent être ignorés, sauf si la spécification de conversion inclut un [, c, ou n de spécification de

conversion.

Un élément doit être lu depuis l'entrée, sauf si la spécification de conversion inclut un n caractère large de spécification de conversion. Un élément d'entrée est défini comme la plus longue séquence de caractères larges d'entrée, ne dépassant aucune largeur de champ spécifiée, qui est une sous-séquence initiale d'une séquence correspondante. Le premier caractère large, s'il y en a un, après l'élément d'entrée doit rester non lu. Si la longueur de l'élément d'entrée est zéro, l'exécution de la spécification de conversion doit échouer ; cette condition est un échec d'appariement, sauf si la fin de fichier, une erreur d'encodage, ou une erreur de lecture a empêché l'entrée du flux, auquel cas c'est un échec

d'entrée.

Sauf dans le cas d'une spécification de conversion %, l'élément d'entrée (ou, dans le cas d'une spécification de conversion %n, le nombre de caractères larges d'entrée) doit être converti en un type approprié au caractère large de conversion. Si l'élément d'entrée n'est pas une séquence correspondante, l' exécution de la spécification de conversion doit échouer ; cette condition est un échec d'appariement. Sauf si la suppression d'affectation a été indiquée par un '*', le résultat de la conversion doit être placé dans l'objet pointé par le premier argument suivant l' argument format qui n'a pas encore reçu un résultat de conversion si la spécification de conversion est introduite par %, ou dans le n-ième argument si introduite par la séquence de caractères larges "%n$". Si cet objet n'a pas un type approprié, ou si le résultat de la conversion ne peut pas être représenté dans l'espace fourni, le comportement est

indéfini.

Les spécifications de conversion %c, %s, et %[ doivent accepter un caractère facultatif d'allocation d'affectation 'm', qui doit causer l'allocation d'un tampon mémoire pour contenir la chaîne de caractères larges convertie incluant un caractère large nul de terminaison. Dans un tel cas, l'argument correspondant à la spécification de conversion doit être une référence à une valeur de pointeur qui recevra un pointeur vers le tampon alloué. Le système doit allouer un tampon comme si malloc() avait été appelé. L'application doit être responsable de libérer la mémoire après utilisation. S'il n'y a pas assez de mémoire pour allouer un tampon, la fonction doit définir errno à [ENOMEM] et une erreur de conversion doit en résulter. Si la fonction retourne EOF, toute mémoire allouée avec succès pour les paramètres utilisant le caractère d'allocation d'affectation 'm' par cet appel doit être libérée avant que la fonction ne retourne.

If a conversion specification is invalid, the behavior is

undefined.

The conversion specifiers A, E, F, G, and X are also valid and shall be equivalent to, respectively, a, e, f, g, and x

.

If end-of-file is encountered during input, conversion is terminated. If end-of-file occurs before any wide characters matching the current conversion specification (except for %n) have been read (other than leading white-space, where permitted), execution of the current conversion specification shall terminate with an input failure. Otherwise, unless execution of the current conversion specification is terminated with a matching failure, execution of the following conversion specification (if any) shall be terminated with an input

failure.

Reaching the end of the string in swscanf() shall be equivalent to encountering end-of-file for fwscanf

().

If conversion terminates on a conflicting input, the offending input shall be left unread in the input. Any trailing white space (including <newline>) shall be left unread unless matched by a conversion specification. The success of literal matches and suppressed assignments is only directly determinable via the %n conversion

specification.

The fwscanf() and wscanf() functions may mark the last data access timestamp of the file associated with stream for update. The last data access timestamp shall be marked for update by the first successful execution of fgetwc(), fgetws(), fwscanf(), getwc(), getwchar(), vfwscanf(), vwscanf(), or wscanf() using stream that returns data not supplied by a prior call to unget

VALEUR DE

RETOUR

Upon successful completion, these functions shall return the number of successfully matched and assigned input items; this number can be zero in the event of an early matching failure. If the input ends before the first conversion (if any) has completed, and without a matching failure having occurred, EOF shall be returned. If an error occurs before the first conversion (if any) has completed, and without a matching failure having occurred, EOF shall be returned and errno shall be set to indicate the error.
