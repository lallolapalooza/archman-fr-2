fts(3) Manuel des fonctions de bibliothèque fts(3)

NOM

fts, fts_open, fts_read, fts_children, fts_set, fts_close - parcourir une hiérarchie de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPTION

Les fonctions fts sont fournies pour parcourir les hiérarchies de fichiers. Un aperçu simple est que la fonction fts_open() retourne une "poignée" (de type FTS *) qui fait référence à un "flux" de hiérarchie de fichiers. Cette poignée est ensuite fournie aux autres fonctions fts. La fonction fts_read() retourne un pointeur vers une structure décrivant l'un des fichiers de la hiérarchie de fichiers. La fonction fts_children() retourne un pointeur vers une liste chaînée de structures, chacune décrivant l'un des fichiers contenus dans un répertoire de la hiérarchie.

En général, les répertoires sont visités deux fois distinctement; en pré-ordre (avant que l'un de leurs descendants ne soit visité) et en post-ordre (après que tous leurs descendants aient été visités). Les fichiers sont visités une fois. Il est possible de parcourir la hiérarchie "logiquement" (en visitant les fichiers vers lesquels les liens symboliques pointent) ou physiquement (en visitant les liens symboliques eux-mêmes), d'ordonner le parcours de la hiérarchie ou de élaguer et/ou revisiter des portions de la hiérarchie.

Deux structures (et types associés) sont définies dans le fichier d'en-tête <fts.h>. Le premier type est FTS, la structure qui représente la hiérarchie de fichiers elle-même. Le second type est FTSENT, la structure qui représente un fichier dans la hiérarchie de fichiers. Normalement, une structure FTSENT est retournée pour chaque fichier de la hiérarchie de fichiers. Dans cette page de manuel, "fichier" et "structure FTSENT" sont généralement interchangeables.

La structure FTSENT contient des champs décrivant un fichier. La structure contient au moins les champs suivants (il y a des champs supplémentaires qui devraient être considérés comme privés à l'implémentation) :


typedef struct _ftsent {
    unsigned short  fts_info;     /* drapeaux pour la structure FTSENT */
    char           *fts_accpath;  /* chemin d'accès */
    char           *fts_path;     /* chemin racine */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* nom de fichier */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* profondeur (-1 à N) */
    int             fts_errno;    /* errno du fichier */
    long            fts_number;   /* valeur numérique locale */
    void           *fts_pointer;  /* valeur d'adresse locale */
    struct _ftsent *fts_parent;   /* répertoire parent */
    struct _ftsent *fts_link;     /* prochaine structure de fichier */
    struct _ftsent *fts_cycle;    /* structure de cycle */
    struct stat    *fts_statp;    /* informations [l]stat(2) */
} FTSENT;

Ces champs sont définis comme suit :

fts_info
L'une des valeurs suivantes décrivant la structure FTSENT retournée et le fichier qu'elle représente. À l'exception des répertoires sans erreur (FTS_D), toutes ces entrées sont terminales, c'est-à-dire qu'elles ne seront pas revues, ni aucun de leurs descendants ne sera visité.
FTS_D
Un répertoire visité en pré-ordre.
FTS_DC
Un répertoire qui provoque un cycle dans l'arbre. (Le champ fts_cycle de la structure FTSENT sera également rempli.)
FTS_DEFAULT
Toute structure FTSENT représentant un type de fichier non explicitement décrit par l'une des autres valeurs fts_info.
FTS_DNR
Un répertoire qui ne peut pas être lu. Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_DOT
Un fichier nommé "." ou ".." qui n'a pas été spécifié comme nom de fichier à fts_open() (voir FTS_SEEDOT).
FTS_DP
Un répertoire visité en post-ordre. Le contenu de la structure FTSENT sera inchangé par rapport à son retour en pré-ordre, c'est-à-dire avec le champ fts_info défini à FTS_D.
FTS_ERR
Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_F
Un fichier ordinaire.
FTS_NS
Un fichier pour lequel aucune information [l]stat(2) n'était disponible. Le contenu du champ fts_statp est indéfini. Il s'agit d'un retour d'erreur, et le champ fts_errno sera défini pour indiquer ce qui a causé l'erreur.
FTS_NSOK
Un fichier pour lequel aucune information [l]stat(2) n'a été demandée. Le contenu du champ fts_statp est indéfini.
FTS_SL
Un lien symbolique.
FTS_SLNONE
Un lien symbolique avec une cible inexistante. Le contenu du champ fts_statp fait référence aux informations de caractéristiques du fichier du lien symbolique lui-même.
fts_accpath
Un chemin pour accéder au fichier depuis le répertoire courant.
fts_path
Le chemin du fichier par rapport à la racine du parcours. Ce chemin contient le chemin spécifié à fts_open() comme préfixe.
fts_pathlen
La somme des longueurs des chaînes référencées par fts_path et fts_name.
fts_name
Le nom du fichier.
fts_namelen
La longueur de la chaîne référencée par fts_name.
fts_level
La profondeur du parcours, numérotée de -1 à N, où ce fichier a été trouvé. La structure FTSENT représentant le parent du point de départ (ou racine) du parcours est numérotée -1, et la structure FTSENT pour la racine elle-même est numérotée 0.
fts_errno
Si fts_children() ou fts_read() retourne une structure FTSENT dont le champ fts_info est défini à FTS_DNR, FTS_ERR, ou FTS_NS, le champ fts_errno contient le numéro d'erreur (c'est-à-dire la valeur errno) spécifiant l'erreur. Sinon, le contenu du champ fts_errno est indéfini.
fts_number
Ce champ est fourni pour l'utilisation par le programme applicatif et n'est pas modifié par les fonctions fts. Il est initialisé à 0.
fts_pointer
Ce champ est fourni pour l'utilisation par le programme applicatif et n'est pas modifié par les fonctions fts. Il est initialisé à NULL.
fts_parent
Un pointeur vers la structure FTSENT référençant le fichier dans la hiérarchie immédiatement au-dessus du fichier courant, c'est-à-dire le répertoire dont ce fichier est membre. Une structure parente pour le point d'entrée initial est

la structure FTSENT elle-même, avec son champ fts_level défini à -1.

Le champ fts_link pointe vers la prochaine structure FTSENT dans la hiérarchie de fichiers. Si le champ fts_info est égal à FTS_D, FTS_DC, FTS_DNR, FTS_DP, ou FTS_NS, le champ fts_link est nul.

Le champ fts_cycle est utilisé pour la détection de cycles. Si le champ fts_info est égal à FTS_DC, le champ fts_cycle pointe vers la structure FTSENT qui représente le répertoire parent du répertoire qui a causé le cycle.

Le champ fts_statp pointe vers une structure stat contenant les informations du fichier obtenues par un appel à stat(2) ou lstat(2). Voir les descriptions de ces fonctions pour plus de détails.

Les drapeaux suivants peuvent être transmis dans le paramètre options à fts_open() :

FTS_ROOTONLY
Si cet indicateur est défini, les fts ne parcourront que les répertoires spécifiés dans le tableau path_argv. La traversal ne descendra pas dans les sous-répertoires.
FTS_NOCHDIR
Si cet indicateur est défini, les fts ne changeront pas de répertoire courant pendant la traversal. Cela peut être utile si le programme applicatif doit manipuler des descripteurs de fichiers dans des répertoires spécifiques. Notez que cela désactive l'optimisation qui consiste à vérifier si le répertoire a déjà été visité.
FTS_NOSTAT
Si cet indicateur est défini, les fts ne rempliront pas le champ fts_statp pour les fichiers autres que les liens symboliques. Cela peut être utile pour des performances accrues lorsque les informations d'état ne sont pas nécessaires.
FTS_PHYSICAL
Si cet indicateur est défini, les fts suivront les liens physiques au lieu de traiter les liens symboliques comme des fichiers ordinaires. Si un lien symbolique pointe vers un répertoire, il sera suivi comme tel.
FTS_LOGICAL
C'est le comportement par défaut. Les liens symboliques sont traités comme des fichiers ordinaires, sauf s'ils pointent vers un répertoire, auquel cas ils sont suivis.
FTS_MOTIONTIME
Si cet indicateur est défini, les fts utiliseront les dates de dernière modification des répertoires (lorsqu'ils sont parcourus en post-ordre) pour déterminer si un sous-arbre a été modifié depuis la dernière fois qu'il a été parcouru. Cela peut être utilisé pour éviter de retraverser des sous-arbres qui n'ont pas changé.
FTS_AGAIN
Si cet indicateur est défini, cela indique aux fts de revisiter le fichier spécifié par le paramètre f dans fts_set(). Cela peut être utilisé pour retraverser un sous-arbre après avoir apporté des modifications.
FTS_FOLLOW
Si cet indicateur est défini, cela indique aux fts de suivre les liens symboliques vers des répertoires. C'est l'équivalent de FTS_PHYSICAL si le cible est un répertoire. Sinon, c'est l'équivalent de FTS_LOGICAL.
FTS_PRUNE
Si cet indicateur est défini, cela indique aux fts de ne pas descendre dans le répertoire spécifié par le paramètre f dans fts_set(). Cela peut être utilisé pour élaguer des parties de la hiérarchie de fichiers.
FTS_SKIP
Si cet indicateur est défini, cela indique aux fts d'ignorer le fichier spécifié par le paramètre f dans fts_set(). Cela peut être utilisé pour sauter des fichiers spécifiques.
FTS_SEEDOT
Si cet indicateur est défini, cela indique aux fts de traiter les entrées "." et ".." comme des répertoires ordinaires. Normalement, elles sont ignorées.

Les indicateurs suivants peuvent être transmis dans le paramètre instr à fts_children() et fts_set() :

FTS_NAMEONLY
Si cet indicateur est défini, les fts ne rempliront pas le champ fts_statp pour les fichiers retournés par fts_children(). Cela peut être utile pour des performances accrues lorsque les informations d'état ne sont pas nécessaires.
FTS_POSTORDER
Si cet indicateur est défini, fts_read() retournera les fichiers dans l'ordre post-ordre. Par défaut, il retourne les fichiers dans l'ordre pré-ordre.
FTS_STOP
Si cet indicateur est défini, fts_read() cessera de parcourir le répertoire courant et retournera la structure FTSENT du répertoire parent. Cela est utile pour empêcher la descente dans certains répertoires.

fts_open

La fonction fts_open() initialise une structure FTS pour le parcours de la hiérarchie de fichiers spécifiée par le tableau de chaînes path_argv. Le tableau doit se terminer par un pointeur NULL. Les chemins spécifiés dans path_argv sont les points de départ de la traversal. Le paramètre options est une combinaison OR bit à bit des drapeaux décrits ci-dessus. Le paramètre compar est un pointeur vers une fonction de comparaison qui peut être utilisée pour trier les fichiers dans un répertoire. Si compar est NULL, les fichiers sont traités dans l'ordre du système de fichiers.

fts_read

La fonction fts_read() retourne la prochaine structure FTSENT dans la hiérarchie de fichiers. Si la fin de la hiérarchie est atteinte, elle retourne NULL. Si une erreur se produit, elle retourne NULL et définit errno.

fts_children

La fonction fts_children() retourne un pointeur vers une liste chaînée des structures FTSENT représentant les fichiers contenus dans le répertoire spécifié par la structure FTSENT ftsp. Le paramètre instr est une combinaison OR bit à bit des drapeaux décrits ci-dessus.

fts_set

La fonction fts_set() permet de modifier le comportement des fts pour une structure FTSENT spécifique. Le paramètre instr est une combinaison OR bit à bit des drapeaux décrits ci-dessus.

fts_close

La fonction fts_close() ferme le flux de fichiers et libère toutes les ressources associées. Elle retourne 0 en cas de succès, et -1 en cas d'erreur.

VALEUR DE RETOUR

Voir les descriptions individuelles des fonctions.

ERREURS

Les fonctions fts peuvent échouer pour diverses raisons, y compris les erreurs d'accès aux fichiers, les erreurs d'allocation de mémoire, etc. Les erreurs spécifiques sont signalées via le champ fts_errno des structures FTSENT ou via la variable globale errno.

EXEMPLES

L'exemple suivant montre comment parcourir un répertoire et imprimer les noms de tous les fichiers qu'il contient :

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>

int main(void) {
    FTS *ftsp;
    FTSENT *ent;
    char *files[] = { ".", NULL };

    ftsp = fts_open(files, FTS_PHYSICAL | FTS_NOCHDIR | FTS_XDEV, NULL);
    if (ftsp == NULL) {
        perror("fts_open");
        exit(EXIT_FAILURE);
    }

    while ((ent = fts_read(ftsp)) != NULL) {
        switch (ent->fts_info) {
            case FTS_D:
                /* Directory, entering */
                printf("Entering directory: %s\n", ent->fts_path);
                break;
            case FTS_DNR:
                /* Directory not readable */
                fprintf(stderr, "Cannot read directory: %s (%s)\n",
                        ent->fts_path, strerror(ent->fts_errno));
                break;
            case FTS_F:
                /* Regular file */
                printf("File: %s\n", ent->fts_path);
                break;
            case FTS_SL:
                /* Symbolic link */
                printf("Symbolic link: %s -> %s\n", ent->fts_path, ent->fts_name);
                break;
            case FTS_OTHER:
                /* Other file type */
                printf("Other: %s\n", ent->fts_path);
                break;
            case FTS_NS:
                /* Stat failed */
                fprintf(stderr, "Stat failed for %s: %s\n",
                        ent->fts_path, strerror(ent->fts_errno));
                break;
            case FTS_DP:
                /* Directory, leaving */
                printf("Leaving directory: %s\n", ent->fts_path);
                break;
            default:
                break;
        }
    }

    if (errno != 0) {
        perror("fts_read");
        exit(EXIT_FAILURE);
    }

    if (fts_close(ftsp) == -1) {
        perror("fts_close");
        exit(EXIT_FAILURE);
    }

    return 0;
}

fts_open(

)

La fonction fts_open() prend un pointeur vers un tableau de pointeurs de caractères nommant un ou plusieurs chemins qui constituent une hiérarchie logique de fichiers à parcourir. Le tableau doit être terminé par un pointeur

nul.

Il existe un certain nombre d'options, dont au moins une (soit FTS_LOGICAL ou FTS_PHYSICAL) doit être spécifiée. Les options sont sélectionnées en combinant par un OU logique les valeurs suivantes

:
FTS_LOGIC
AL
Cette option fait que les routines fts renvoient des structures FTSENT pour les cibles des liens symboliques au lieu des liens symboliques eux-mêmes. Si cette option est définie, les seuls liens symboliques pour lesquels des structures FTSENT sont renvoyées à l'application sont ceux faisant référence à des fichiers inexistants : le champ fts_statp est obtenu via stat(2) avec un repli sur lstat(
2).
FTS_PHYSIC
AL
Cette option fait que les routines fts renvoient des structures FTSENT pour les liens symboliques eux-mêmes au lieu des fichiers cibles vers lesquels ils pointent. Si cette option est définie, les structures FTSENT pour tous les liens symboliques de la hiérarchie sont renvoyées à l'application : le champ fts_statp est obtenu via lstat(
2).
FTS_COMFOLL
OW
Cette option fait que tout lien symbolique spécifié comme chemin racine soit suivi immédiatement, comme si via FTS_LOGICAL, quel que soit le mode
principal.
FTS_NOCHD
IR
En tant qu'optimisation de performance, les fonctions fts changent de répertoire lorsqu'elles parcourent la hiérarchie de fichiers. Cela a pour effet secondaire qu'une application ne peut pas compter sur le fait d'être dans un répertoire particulier pendant le parcours. Cette option désactive cette optimisation, et les fonctions fts ne changeront pas le répertoire courant. Notez que les applications ne devraient pas elles-mêmes changer leur répertoire courant et essayer d'accéder à des fichiers, sauf si FTS_NOCHDIR est spécifié et que des chemins absolus ont été fournis en arguments à fts_ope
n().
FTS_NOST
AT
Par défaut, les structures FTSENT renvoies font référence aux informations de caractéristiques de fichier (le champ fts_statp) pour chaque fichier visité. Cette option assouplit cette exigence comme optimisation de performance, permettant aux fonctions fts de définir le champ fts_info à FTS_NSOK et de laisser le contenu du champ fts_statp ind
éfini.
FTS_SEED
OT
Par défaut, à moins qu'ils ne soient spécifiés comme arguments de chemin à fts_open(), tout fichier nommé "." ou ".." rencontré dans la hiérarchie de fichiers est ignoré. Cette option fait que les routines fts renvoient des structures FTSENT pour
ceux-ci.
FTS_XD

Cette option empêche fts de descendre dans les répertoire
s ayant un numéro de périphérique différent de celui
du fichier à partir duquel la descente a commencé.

L'argument compar() spécifie une fonction définie par l'utilisateur qui peut être utilisée pour ordonner le parcours de la hiérarchie. Elle prend deux pointeurs vers des pointeurs vers des structures FTSENT en arguments et devrait renvoyer une valeur négative, zéro, ou une valeur positive pour indiquer si le fichier référencé par son premier argument vient avant, dans n'importe quel ordre par rapport à, ou après, le fichier référencé par son second argument. Si le champ fts_info est défini à FTS_NS ou FTS_NSOK, le champ fts_statp ne peut pas non plus l'être. isté dans le répert

fts_read(

)

La fonction fts_read() renvoie un pointeur vers une structure FTSENT décrivant un fichier dans la hiérarchie. Les répertoires (qui sont lisibles et ne provoquent pas de cycles) sont visités au moins deux fois, une fois en préordre et une fois en postordre. Tous les autres fichiers sont visités au moins une fois. (Les liens durs entre des répertoires qui ne provoquent pas de cycles ou les liens symboliques vers des liens symboliques peuvent faire que des fichiers sont visités plus d'une fois, ou des répertoires plus de deux fois.

)

Si tous les membres de la hiérarchie ont été renvoyés, fts_read() renvoie NULL et définit errno à 0. Si une erreur sans rapport avec un fichier de la hiérarchie se produit, fts_read() renvoie NULL et définit errno pour indiquer l'erreur. Si une erreur liée à un fichier renvoyé se produit, un pointeur vers une structure FTSENT est renvoyé, et errno peut avoir été défini ou non (voir fts_inf

o).

Les structures FTSENT renvoyées par fts_read() peuvent être écrasées après un appel à fts_close() sur le même flux de hiérarchie de fichiers, ou, après un appel à fts_read() sur le même flux de hiérarchie de fichiers, sauf si elles représentent un fichier de type répertoire, auquel cas elles ne seront pas écrasées avant après un appel à fts_read() après que la structure FTSENT a été renvoyée par la fonction fts_read()

en pos
tordre.

fts_children(

)

La fonction fts_children() renvoie un pointeur vers une structure FTSENT décrivant la première entrée d'une liste chaînée terminée par NULL des fichiers du répertoire représenté par la structure FTSENT le plus récemment renvoyée par fts_read(). La liste est liée via le champ fts_link de la structure FTSENT, et est ordonnée par la fonction de comparaison spécifiée par l'utilisateur, le cas échéant. Des appels répétés à fts_children() recréeront cette liste

chaînée.

Comme cas particulier, si fts_read() n'a pas encore été appelé pour une hiérarchie, fts_children() renverra un pointeur vers les fichiers du répertoire logique spécifié à fts_open(), c'est-à-dire les arguments spécifiés à fts_open(). Sinon, si la structure FTSENT le plus récemment renvoyée par fts_read() n'est pas un répertoire étant visité en préordre, ou si le répertoire ne contient aucun fichier, fts_children() renvoie NULL et définit errno à zéro. Si une erreur se produit, fts_children() renvoie NULL et définit errno pour indiquer

l'erreur.

Les structures FTSENT renvoyées par fts_children() peuvent être écrasées après un appel à fts_children(), fts_close(), ou fts_read() sur le même flux de hiérarchie de

fichiers.

fts_set(

)

La fonction fts_set() permet à l'application utilisateur de déterminer le traitement ultérieur du fichier f du flux ftsp. La fonction fts_set() renvoie 0 en cas de succès, et -1 si une erreur se

produit.

L'argument instr est soit 0 (signifiant « ne rien faire »), soit l'une des valeurs suivantes

:
