flockfile(3) Manuel des fonctions de bibliothèque flockfile(3)

NOM

flockfile, ftrylockfile, funlockfile - verrouiller un FICHIER pour stdio

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdio.h>
void flockfile(FILE *descripteur_fichier);
int ftrylockfile(FILE *descripteur_fichier);
void funlockfile(FILE *descripteur_fichier);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

Toutes les fonctions présentées ci-dessus :

    /* Depuis glibc 2.24 : */ _POSIX_C_SOURCE >= 199309L
        || /* glibc <= 2.23 : */ _POSIX_C_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Les fonctions stdio sont thread-safe. Ceci est réalisé en attribuant à chaque objet FILE un compteur de verrouillage et (si le compteur de verrouillage est non nul) un thread propriétaire. Pour chaque appel de bibliothèque, ces fonctions attendent jusqu'à ce que l'objet FILE ne soit plus verrouillé par un autre thread, puis le verrouillent, effectuent l'E/S demandée et déverrouillent l'objet à nouveau.

(Note : ce verrouillage n'a rien à voir avec le verrouillage de fichier effectué par des fonctions telles que flock(2) et lockf(3).)

Tout cela est invisible pour le programmeur C, mais il peut y avoir deux raisons pour souhaiter un contrôle plus détaillé. D'une part, peut-être qu'une série d'actions d'E/S par un thread est cohérente et ne doit pas être interrompue par les E/S d'un autre thread. D'autre part, peut-être que la surcharge de verrouillage doit être évitée pour une plus grande efficacité.

À cette fin, un thread peut verrouiller explicitement l'objet FILE, puis effectuer sa série d'actions d'E/S, puis le déverrouiller. Cela empêche d'autres threads d'intervenir. Si la raison de faire cela était d'obtenir une plus grande efficacité, on effectue les E/S avec les versions non verrouillées des fonctions stdio : avec getc_unlocked(3) et putc_unlocked(3) au lieu de getc(3) et putc(3).

La fonction flockfile() attend que *descripteur_fichier ne soit plus verrouillé par un autre thread, puis fait du thread courant le propriétaire de *descripteur_fichier, et incrémente le compteur de verrouillage.

La fonction funlockfile() décrémente le compteur de verrouillage.

La fonction ftrylockfile() est une version non bloquante de flockfile(). Elle ne fait rien si un autre thread possède *descripteur_fichier, et elle obtient la propriété et incrémente le compteur de verrouillage sinon.

VALEUR DE RETOUR

La fonction ftrylockfile() retourne zéro en cas de succès (le verrou a été obtenu), et une valeur non nulle en cas d'échec.

ERREURS

Aucune.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
flockfile (), ftrylockfile (), funlockfile () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

Ces fonctions sont disponibles lorsque _POSIX_THREAD_SAFE_FUNCTIONS est défini.
