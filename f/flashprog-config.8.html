NOM

flashprog-config - lire et écrire les registres d'état et de configuration des puces flash

SYNTAXE

flashprog config [get] <options> <paramètre>
flashprog config  set  <options> [--temporaire] <paramètre> <valeur>

Où les <options> génériques sont :

-p <nom_programmeur>[:<paramètres>] [-c <nom_puce>]
[-V[V[V]]] [-o <journal_sortie>] [-h]

DESCRIPTION

flashprog-config est un utilitaire pour lire et écrire les bits des registres d'état et de configuration des puces flash. Actuellement, il ne prend en charge que les puces NOR SPI.

OPÉRATIONS

Vous pouvez spécifier get ou set, ou aucune opération ce qui revient par défaut à lire un paramètre.

get <paramètre>

Lit et affiche la valeur du paramètre donné. Voir PARAMÈTRES ci-dessous.

set [--temporaire] <paramètre> <valeur>

Écrit la valeur donnée au paramètre. Voir PARAMÈTRES et VALEURS ci-dessous.

Lorsque l'option --temporaire est fournie, flashprog tentera d'écrire une valeur temporaire qui n'est pas stockée dans la mémoire flash. Cela nécessite un support spécifique de la puce flash pour une commande de registre d'état d'écriture volatile. La nouvelle valeur sera perdue lors de la réinitialisation de la puce flash. Il est donc inutile de l'utiliser avec des programmeurs externes qui basculent l'alimentation de la puce flash (par exemple, Dediprog).

PARAMÈTRES

qe, quad-enable

Les puces flash NOR SPI prennent souvent en charge le multiplexage de certaines de leurs broches (généralement /WP et /HOLD) avec des lignes d'E/S supplémentaires. Cela leur permet de transférer quatre bits à la fois lorsque le bit quad-enable est défini.

VALEURS

faux, vrai

Les valeurs faux et vrai seront converties en 0 et 1 respectivement.

Nombres naturels : 0, 1, ...

Lorsque des nombres naturels sont donnés, les bits les moins significatifs de leur représentation binaire seront écrits dans un paramètre.

OPTIONS

Toutes les opérations nécessitent l'utilisation de l'option -p/--programmeur (veuillez consulter pour plus d'informations sur le support et les paramètres des programmeurs).

-p, --programmeur <nom>[:<paramètre>[,<paramètre>]...]

Spécifie le périphérique programmeur. Ceci est obligatoire pour toutes les opérations. Veuillez consulter le manuel pour une liste des programmeurs actuellement pris en charge et de leurs paramètres.

-c, --puce <nom_puce>

Interroge uniquement la puce ROM flash spécifiée. Cette option prend le nom de la puce tel qu'affiché par flashprog -L sans le nom du vendeur comme paramètre. Veuillez noter que le nom de la puce est sensible à la casse.

-V, --verbeux

Sortie plus verbeuse. Cette option peut être fournie plusieurs fois (max. 3 fois, c'est-à-dire -VVV) pour encore plus de sortie de débogage.

-o, --sortie <journal_sortie>

Sauvegarde le journal de débogage complet dans <journal_sortie>. Si le fichier existe déjà, il sera écrasé. C'est la manière recommandée de collecter les journaux de flashprog car ils seront verbeux même si les messages à l'écran ne le sont pas et ne nécessitent pas de redirection de sortie.

-h, --aide

Affiche un texte d'aide et quitte.

--temporaire

Essaie d'utiliser une commande de registre d'état d'écriture volatile. Voir set sous OPÉRATIONS ci-dessus.

EXEMPLES

Pour lire le paramètre quad-enable de la mémoire flash BIOS interne :

flashprog config -p interne quad-enable
ou
flashprog config get -p interne quad-enable
Pour définir temporairement le bit quad-enable d'une puce connectée à un FT4222H :
flashprog config set -p ft4222_spi --temporaire quad-enable 1

STATUT DE SORTIE

flashprog se termine avec 0 en cas de succès, 1 dans la plupart des échecs mais avec 3 si un appel à mmap() échoue.

EXIGENCES

flashprog nécessite des permissions d'accès différentes pour différents programmeurs. Voir cette section du manuel pour plus de détails.
