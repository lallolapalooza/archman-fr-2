NOM

fp - Environnement de développement intégré du compilateur Free Pascal (FPC)

SYNTAXE

fp [options] [fichier_source]

DESCRIPTION

Ce binaire est l'environnement de développement intégré (IDE) du compilateur Free Pascal (FPC), qui est un compilateur Pascal avancé compatible Turbo Pascal et Delphi (7.0), multitarget. Le moteur de compilation n'est pas basé sur GCC, mais est entièrement autonome.

Le compilateur utilise LD(1) et peut utiliser AS(1) (voir le paramètre -Aas), mais possède également son propre générateur d'objets binaires.

Les principales cibles actuelles sont Go32V2 (extendeur DJGPP pour Dos), Freebsd, Linux, MacOS, MacOSX, MorphOS, Netware, OS/2 et Win32. Les autres cibles (compilateurs M68K pour Atari et Amiga) sont soit basées sur d'anciennes versions du compilateur, soit encore en développement.

Cette page de manuel est destinée uniquement à une référence rapide. FPC est livré avec un excellent manuel (plus de 2000 pages), constamment mis à jour, tandis que cette page de manuel peut être obsolète.

UTILISATION

L'interface utilisateur de l'IDE a été conçue pour être similaire à celle de Turbo Pascal. Elle offre à l'utilisateur un éditeur convivial, mais plutôt puissant, un système d'aide en ligne étendu et un débogueur.

Un système de fenêtrage en mode texte constitue la base de l'interface utilisateur. La souris est prise en charge, mais la plupart des gens utiliseront le clavier. L'utilisateur ouvrira généralement quelques fenêtres d'édition de texte dans lesquelles il concevra son programme, tout en pouvant vérifier et déboguer régulièrement à l'aide de raccourcis clavier. La haute vitesse du compilateur garantit que les programmeurs peuvent le faire fréquemment, permettant ainsi un développement rapide du code.

FICHIERS D'AIDE

Aucun fichier d'aide n'est fourni par défaut. L'utilisateur doit télécharger la documentation Free Pascal au format HTML et l'installer dans l'IDE via le menu Aide->Fichiers. Les fichiers .tph de Turbo Pascal peuvent également être installés dans ce menu et peuvent être utiles pour le code source qui est livré avec des fichiers .tph comme documentation.

JEUX DE CARACTÈRES

L'IDE a été conçue pour les polices de caractères en mode texte VGA. Ces polices permettent des modes texte visuellement plus intéressants que les polices VT100 normalement utilisées sur les systèmes Unix, et sont également plus portables, car la plupart des systèmes d'exploitation utilisent les jeux de caractères VGA pour leurs modes texte.

Lors de l'exécution sur un terminal compatible VT100, une certaine émulation aura lieu. En interne, l'IDE pensera qu'elle s'exécute sur une police en mode texte VGA (très probablement la page de code 850), tandis que tous les caractères seront (dans le cas de la page de code 850) convertis en Latin-1 et en caractères du jeu de caractères alternatifs VT100.

La console Linux peut utiliser les polices VGA et l'IDE peut donc être visualisée comme prévu sur celle-ci. Le mode console Linux prend en charge l'intégralité du jeu de caractères VGA via les périphériques /dev/vcsa* et la plupart via les séquences d'échappement normales. Pour éviter une mauvaise expérience utilisateur, l'IDE a été conçue pour être assez agressive dans l'utilisation des jeux de caractères VGA. Tout d'abord, elle déterminera le numéro de console réel sur lequel vous vous exécutez (même si vous vous exécutez sur un pty, comme dans Midnight Commander). Ensuite, l'IDE ouvrira le périphérique /dev/vcsa* appartenant à cette console. Si l'autorisation est refusée, l'IDE appellera l'utilitaire grab_vcsa, qui est un utilitaire setuid root qui accordera les permissions au périphérique vcsa.

Si le périphérique vcsa n'est pas disponible, l'IDE enverra des codes d'échappement pour activer la police VGA. Dans ce mode, quelques caractères dans les 32 premières positions ASCII sont indisponibles, mais principalement parce que l'ensemble complet des caractères de dessin de ligne est disponible, l'utilisateur remarquera peu de différences.

Le périphérique de framebuffer Linux et l'IDE Free Pascal forment une excellente combinaison. Avec fbdev, il est possible d'utiliser des résolutions en mode texte supérieures au 80x25 normal, ce qui permet au programmeur de voir beaucoup plus de code à la fois.

La console Linux permet à l'utilisateur de charger des polices définies par l'utilisateur. Si vous le faites, une telle police doit avoir une disposition de style VGA, c'est-à-dire la page de code 437/850/... (Notez que cela ne signifie pas que votre système de fichiers doit utiliser un tel encodage, la console Linux gère la conversion depuis ISO-8859-1, UTF-8 ou autre vers la police.) Étant donné que les polices par défaut ont une disposition en page de code 437, seuls les utilisateurs ayant expérimenté avec les polices devront faire attention ici.

L'IDE reconnaît la variable d'environnement CONSOLEFONT_CP dans laquelle vous pouvez spécifier la page de code de la police de la console. Les valeurs reconnues sont actuellement "cp437" et "cp850". Si vous ne définissez pas cette variable, la page de code 437 sera supposée. Actuellement, si vous utilisez la page de code 850 sans définir la variable, l'impact ne sera pas énorme à l'heure actuelle, les caractères utilisés par l'IDE existent dans les deux pages de code.

Remarque : Les polices KOI8-R/KOI8-U contiennent tous les caractères requis, mais les caractères de dessin de ligne ne sont pas aux bonnes positions. Nous pourrions le supporter à l'avenir, mais pas actuellement.

CLAVIER

La gestion du clavier Unix est une affaire compliquée car toutes les combinaisons de touches ne génèrent pas de codes d'échappement, différents émulateurs de terminaux génèrent différents codes d'échappement, et certaines combinaisons de touches peuvent déclencher des actions dans le gestionnaire de fenêtres X11.

Étant donné que l'interface utilisateur de l'IDE Free Pascal est conçue pour être similaire à Turbo Pascal, y compris les commandes clavier, vous pourriez rencontrer l'une des situations ci-dessus. Certaines touches alternatives ont été ajoutées, et peut-être que d'autres devront être ajoutées à l'avenir.

Lors de l'exécution sur la console Linux, le clavier est reprogrammé pour une fonctionnalité complète.

Voici quelques problèmes courants que vous pourriez rencontrer et leurs solutions possibles :

Problème : La sélection de texte avec les touches Maj+flèches ne fonctionne pas.

Solution : Utilisez la souris.

Solution : Utilisez "ctrl+k b" pour marquer le début du bloc, "ctrl+k e" pour marquer la fin du bloc, "ctrl+k h" pour masquer le bloc.

Problème : Les touches Couper/Copier/Coller ne fonctionnent pas.

Solution : Allez dans Options->Environnement->Clavier & souris et activez les touches Couper/Copier/Coller de style Microsoft.

Solution : Utilisez la barre de menu.

Problème : La touche Alt ne fonctionne pas.

Solution : Appuyez d'abord sur Échap, puis sur la touche sans Alt. Notez que cela n'est pas possible sur la console Linux, mais la touche Alt y fonctionne.

Si, pour quelque raison que ce soit, le clavier reprogrammé de la console Linux n'est pas restauré à son état d'origine après la sortie (crash de l'IDE ?), vous pouvez faire quelque chose comme "/etc/init.d/kbd start" pour le reprogrammer dans son comportement normal.
