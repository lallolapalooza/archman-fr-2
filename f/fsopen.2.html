fsopen(2) Manuel des appels système fsopen(2)

NOM

fsopen - crée un nouveau contexte de système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/mount.h>
int fsopen(const char *fsname, unsigned int flags);

DESCRIPTION

L'appel système fsopen() fait partie de la suite des mécanismes de montage basés sur les descripteurs de fichiers dans Linux.

fsopen() crée un contexte de configuration de système de fichiers vide dans le noyau pour le système de fichiers nommé par fsname et le place en mode création. Un nouveau descripteur de fichier associé au contexte de configuration du système de fichiers est ensuite renvoyé. Le processus appelant doit posséder la capacité CAP_SYS_ADMIN afin de créer un nouveau contexte de configuration de système de fichiers.

Un contexte de configuration de système de fichiers est une représentation dans le noyau d'une transaction en attente, contenant un ensemble de paramètres de configuration qui seront appliqués lors de la création d'une nouvelle instance d'un système de fichiers (ou de la modification de la configuration d'une instance existante, comme lors de l'utilisation de fspick(2)).

Après avoir obtenu un contexte de configuration de système de fichiers avec fsopen(), le flux de travail général pour manipuler le contexte est le suivant :

(1)
Transmettre le descripteur de fichier du contexte de système de fichiers à fsconfig(2) pour spécifier les paramètres du système de fichiers souhaités. Cela peut être fait autant de fois que nécessaire.
(2)
Transmettre le même descripteur de fichier du contexte de système de fichiers à fsconfig(2) avec FSCONFIG_CMD_CREATE pour créer une instance du système de fichiers configuré.
(3)
Transmettre le même descripteur de fichier du contexte de système de fichiers à fsmount(2) pour créer un nouvel objet de montage détaché pour la racine de l'instance du système de fichiers, qui est ensuite attaché à un nouveau descripteur de fichier. (Cela place également le descripteur de fichier du contexte de système de fichiers en mode reconfiguration, similaire au mode produit par fspick(2).) Une fois qu'un objet de montage a été créé avec fsmount(2), le descripteur de fichier du contexte de système de fichiers peut être fermé sans risque.
(4)
Maintenant qu'un objet de montage a été créé, vous pouvez
•
utiliser le descripteur de fichier de l'objet de montage détaché comme argument dirfd pour les appels système "*at()" ; et/ou
•
attacher l'objet de montage à un point de montage en transmettant le descripteur de fichier de l'objet de montage à move_mount(2). Cela empêchera également l'objet de montage d'être démonté et détruit lorsque le descripteur de fichier de l'objet de montage est fermé.
Le descripteur de fichier de l'objet de montage restera associé à l'objet de montage même après avoir effectué les opérations ci-dessus, vous pouvez donc utiliser à plusieurs reprises le descripteur de fichier de l'objet de montage avec move_mount(2) et/ou les appels système "*at()" autant de fois que nécessaire.

Un contexte de système de fichiers change de mode tout au long de son cycle de vie (comme la phase de création lorsqu'il est créé avec fsopen(), la phase de reconfiguration lorsqu'une instance existante de système de fichiers est sélectionnée avec fspick(2), et la phase intermédiaire « en attente de montage » entre FSCONFIG_CMD_CREATE et fsmount(2)), ce qui a une incidence sur les opérations autorisées sur le contexte de système de fichiers.

Le descripteur de fichier renvoyé par fsopen() sert également de canal permettant aux pilotes de système de fichiers de fournir des informations de diagnostic plus complètes que celles normalement fournies par l'interface standard errno(3) pour les appels système. Si une erreur se produit à tout moment pendant le flux de travail mentionné ci-dessus, l'appel à read(2) sur le descripteur de fichier du contexte de système de fichiers permettra de récupérer toute information auxiliaire sur les erreurs rencontrées. (Voir la section « Interface de récupération des messages » pour plus de détails sur le format des messages.)

flags peut être utilisé pour contrôler certains aspects de la création du descripteur de fichier du contexte de configuration de système de fichiers. Une valeur pour flags est construite en combinant par un OU bit à bit zéro ou plusieurs des constantes suivantes :

FSOPEN_CLOEXEC
Définir l'indicateur close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description de l'indicateur O_CLOEXEC dans open(2) pour savoir pourquoi cela peut être utile.

Une liste des systèmes de fichiers pris en charge par le noyau en fonctionnement (et donc une liste des valeurs valides pour fsname) peut être obtenue à partir de /proc/filesystems. (Voir aussi proc_filesystems(5).)

Interface de récupération des messages

Lors d'opérations sur un contexte de configuration de système de fichiers, le pilote du système de fichiers peut choisir de fournir des informations auxiliaires à l'espace utilisateur sous forme de chaînes de messages.

Les descripteurs de fichier du contexte de système de fichiers renvoyés par fsopen() et fspick(2) peuvent être interrogés pour obtenir des chaînes de messages à tout moment en appelant read(2) sur le descripteur de fichier. Chaque appel à read(2) renverra un message unique, préfixé pour indiquer sa classe :

emessage
Un message d'erreur a été enregistré. Cela est généralement associé à une erreur renvoyée par l'appel système correspondant qui a déclenché ce message.
wmessage
Un message d'avertissement a été enregistré.
imessage
Un message informatif a été enregistré.

Les messages sont retirés de la file d'attente lorsqu'ils sont lus. Notez que la file d'attente de messages a une profondeur limitée, il est donc possible que des messages soient perdus. S'il n'y a pas de messages dans la file d'attente de messages, read(2) renverra -1 et errno sera défini à ENODATA. Si l'argument buf de read(2) n'est pas assez grand pour contenir le message entier, read(2) renverra -1 et errno sera défini à EMSGSIZE. (Voir ANOMALIES.)

S'il existe plusieurs contextes de système de fichiers faisant référence à la même instance de système de fichiers (par exemple si vous appelez fspick(2) plusieurs fois pour le même montage), chacun dispose de sa propre file d'attente de messages indépendante. Cela ne s'applique pas à plusieurs descripteurs de fichier liés à la même description de fichier ouverte sous-jacente (comme ceux créés avec dup(2)).

Les chaînes de messages sont généralement préfixées par le nom du système de fichiers ou du sous-système du noyau qui a enregistré le message, bien que ce ne soit pas toujours le cas. Voir le code source du noyau Linux pour plus de détails.

VALEUR RENVOYÉE

En cas de succès, un nouveau descripteur de fichier est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
fsname est NULL ou un pointeur vers une zone située en dehors de l'espace d'adressage accessible du processus appelant.
EINVAL
flags contenait un indicateur invalide.
EMFILE
Le processus appelant a trop de fichiers ouverts pour en créer d'autres.
ENFILE
Le système a trop de fichiers ouverts pour en créer d'autres.
ENODEV
Le système de fichiers nommé par fsname n'est pas pris en charge par le noyau.
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour terminer l'opération.
EPERM
Le processus appelant ne possède pas la capacité CAP_SYS_ADMIN requise.

NORMES Linux.
