DESCRIPTIO

N

Les fonctions de la famille printf() produisent une sortie selon un format décrit ci-dessous. Les fonctions printf() et vprintf() écrivent la sortie vers stdout, le flux de sortie standard ; fprintf() et vfprintf() écrivent la sortie vers le flux de sortie donné ; sprintf(), snprintf(), vsprintf() et vsnprintf() écrivent vers la chaîne de caractères str

.

La fonction dprintf() est identique à fprintf() sauf qu'elle écrit vers un descripteur de fichier, fd, au lieu d'écrire vers un flu

stdio(3). Les fonctions snprintf() et vsnprintf() écrivent au plus size octets (y compris l'octet nul de fin

Les fonctions vprintf(), vfprintf(), vdprintf(), vsprintf() et vsnprintf() sont équivalentes aux fonctions printf(), fprintf(), dprintf(), sprintf() et snprintf() respectivement, sauf qu'elles sont appelées avec une va_list au lieu d'un nombre variable d'arguments. Ces fonctions n'appellent pas la macro va_end. Comme elles invoquent la macro va_arg, la valeur de ap est indéfinie après l'appel.

AVERTISSEMENTS.

Format de la chaîne de format La chaîne de format est une chaîne de caractères, commençant et se terminant dans son état de décalage initial, le cas échéant. La chaîne de format est composée de zéro ou plusieurs directives : des caractères ordinaires (non %), qui sont copiés inchangés vers le flux de sortie ; et des spécifications de conversion, chacune entraînant la récupération de zéro ou plusieurs arguments suivants. Chaque spécification de conversion est introduite par le caractère % et se termine par un spécificateur de conversion. Entre les deux, il peut y avoir (dans cet ordre) zéro ou plusieurs drapeaux, une largeur de champ facultative, une précision facultat

ive et un

modificateur de longueur

facultatif. 


La syntaxe générale d'une spécification de conversion est
:

%[argument$][drapeaux][largeur][.précision][modificateur de longueur]conversion Les arguments doivent correspondre correctement (après promotion de type) avec le spécificateur de conversion. Par défaut, les arguments sont utilisés dans l'ordre donné, où chaque '*' (voir Largeur de champ et Précision ci-dessous) et chaque spécificateur de conversion demande l'argument suivant (et c'est une erreur si le nombre d'arguments donné est insuffisant). On peut aussi spécifier explicitement quel argument est pris, à chaque endroit où un argument est requis, en écrivant "%m$" au lieu de '%' et "*m$" au lieu de '*', où l'entier

VALEUR DE RETOUR

Lors d'un retour réussi, ces fonctions retournent le nombre d'octets imprimés (hors l'octet nul utilisé pour terminer la sortie vers les chaînes).

Les fonctions snprintf() et vsnprintf() n'écrivent pas plus de size octets (y compris l'octet nul de terminaison ('\0')). Si la sortie a été tronquée en raison de cette limite, alors la valeur de retour est le nombre de caractères (hors l'octet nul de terminaison) qui auraient été écrits dans la chaîne finale si suffisamment d'espace avait été disponible. Ainsi, une valeur de retour de size ou plus signifie que la sortie a été tronquée. (Voir aussi ci-dessous sous MISES EN GARDE.)

En cas d'erreur, une valeur négative est retournée, et errno est défini pour indiquer l'erreur.

ERREURS

Voir write(2) et putwc(3). De plus, l'erreur suivante peut survenir :

EOVERFLOW
La valeur à retourner est supérieure à INT_MAX.

La fonction dprintf() peut échouer en outre si :

EBADF
L'argument fd n'est pas un descripteur de fichier valide.

MISES EN GARDE

Certains programmes s'appuient imprudemment sur du code tel que le suivant


sprintf(buf, "%s autre texte", buf);

pour ajouter du texte à buf. Cependant, les normes notent explicitement que les résultats sont indéfinis si les tampons source et destination se chevauchent lors de l'appel à sprintf(), snprintf(), vsprintf() et vsnprintf(). Selon la version de gcc(1) utilisée et les options du compilateur employées, des appels comme celui-ci ne produiront pas les résultats attendus.

L'implémentation glibc des fonctions snprintf() et vsnprintf() est conforme à la norme C99, c'est-à-dire qu'elle se comporte comme décrit ci-dessus, depuis glibc 2.1. Jusqu'à glibc 2.0.6, elles renvoyaient -1 lorsque la sortie était tronquée.

BOGUES

Étant donné que sprintf() et vsprintf() supposent une chaîne de longueur arbitraire, les appelants doivent veiller à ne pas dépasser l'espace réel ; cela est souvent impossible à garantir. Notez que la longueur des chaînes produites dépend de la locale et est difficile à prédire. Utilisez plutôt snprintf() et vsnprintf() (ou asprintf(3) et vasprintf(3)).

Un code tel que printf(foo); indique souvent un boguo, car foo peut contenir un caractère %. Si foo provient d'une entrée utilisateur non fiable, il peut contenir %n, ce qui amène l'appel printf() à écrire dans la mémoire et crée une faille de sécurité.

Pour afficher une date et une heure sous la forme « dimanche, juillet 3, 10:02 », où weekday et month sont des pointeurs vers des chaînes de caractères

#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min)
;

De nombreux pays utilisent l'ordre jour-mois-année. Par conséquent, une version internationalisée doit être capable d'afficher les arguments dans un ordre spécifié par le format

: 


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min)
;

où format dépend de la locale et peut permuter les arguments. Avec la valeur

: 


"%1$s, %3$d. %2$s, %4$d:%5$.
2d\n"

on pourrait obtenir « Sonntag, 3. Juli, 10:02 »

.

Pour allouer une chaîne suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1)

: 
#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determine required size.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* One extra byte for '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}
