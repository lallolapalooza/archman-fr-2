reallocarray(3bsd) 3bsd reallocarray(3bsd)

NOM

reallocarray, recallocarray, freezero — allocation et désallocation de mémoire

BIBLIOTHÈQUE

bibliothèque « libbsd »

SYNOPSIS

#include <stdlib.h> (Voir libbsd(7) pour l'usage de l'include.)
void *
reallocarray(void *ptr, size_t nmemb, size_t size);

void *
recallocarray(void *ptr, size_t oldnmemb, size_t nmemb, size_t size);

void
freezero(void *ptr, size_t size);

DESCRIPTION

Conçue pour l'allocation sûre de tableaux, la fonction reallocarray() est similaire à realloc() sauf qu'elle opère sur nmemb membres de taille size et vérifie le dépassement d'entier dans le calcul nmemb * size.

Utilisée pour l'allocation de mémoire contenant des données sensibles, la fonction recallocarray() garantit que la mémoire qui devient non allouée est explicitement défaussée, ce qui signifie que les objets libres mis en cache sont effacés avec explicit_bzero(3).

La fonction recallocarray() est similaire à reallocarray() sauf qu'elle assure que la mémoire nouvellement allouée est effacée de manière similaire à calloc(). Si ptr est NULL, oldnmemb est ignoré et l'appel est équivalent à calloc(). Si ptr n'est pas NULL, oldnmemb doit être une valeur telle que oldnmemb * size soit la taille de l'allocation précédente qui a retourné ptr, sinon le comportement est indéfini. La fonction freezero() est similaire à la fonction free() sauf qu'elle garantit que la mémoire est explicitement défaussée. Si ptr est NULL, aucune action n'est entreprise. Si ptr n'est pas NULL, l'argument size doit être égal ou inférieur à la taille de l'allocation précédente qui a retourné ptr. freezero() garantit que la plage mémoire commençant à ptr avec une longueur de size est défaussée tout en désallouant l'objet entier initialement alloué.

VALEURS DE RETOUR

Les fonctions reallocarray() et recallocarray() retournent un pointeur vers l'espace alloué en cas de succès ; sinon, un pointeur nul est retourné et errno est défini à ENOMEM.

Si la multiplication de nmemb et size entraîne un dépassement d'entier, reallocarray() et recallocarray() retournent NULL et définissent errno à ENOMEM.

Si ptr n'est pas NULL et que la multiplication de oldnmemb et size entraîne un dépassement d'entier, recallocarray() retourne NULL et définit errno à EINVAL.

IDIOMES

Considérez calloc() ou les extensions reallocarray() et recallocarray() lorsqu'il y a une multiplication dans l'argument size de malloc() ou realloc(). Par exemple, évitez cet idiome courant car il peut entraîner un dépassement d'entier :

if ((p = malloc(num * size)) == NULL)
	err(1, NULL);

Un remplacement direct est reallocarray() :

if ((p = reallocarray(NULL, num, size)) == NULL)
	err(1, NULL);

Alternativement, calloc() peut être utilisé au prix d'une surcharge d'initialisation.

Lors de l'utilisation de realloc(), faites attention à éviter l'idiome suivant :

size += 50;
if ((p = realloc(p, size)) == NULL)
	return (NULL);

Ne modifiez pas la variable décrivant la quantité de mémoire allouée tant que l'allocation n'a pas réussi. Cela peut entraîner un comportement aberrant du programme si la valeur de taille incorrecte est utilisée. Dans la plupart des cas, l'exemple ci-dessus entraînera également une fuite de mémoire. Comme indiqué précédemment, une valeur de retour de NULL indique que l'ancien objet reste alloué. Un meilleur code ressemble à ceci :

newsize = size + 50;
if ((newp = realloc(p, newsize)) == NULL) {
	free(p);
	p = NULL;
	size = 0;
	return (NULL);
}
p = newp;
size = newsize;

Comme avec malloc(), il est important de s'assurer que la nouvelle valeur de taille ne débordera pas ; c'est-à-dire, évitez les allocations comme celle-ci :

if ((newp = realloc(p, num * size)) == NULL) {
	...

Utilisez plutôt reallocarray() :

if ((newp = reallocarray(p, num, size)) == NULL) {
	...

Appeler realloc() avec un ptr NULL est équivalent à appeler malloc(). Au lieu de cet idiome :

if (p == NULL)
	newp = malloc(newsize);
else
	newp = realloc(p, newsize);

Utilisez le suivant :

newp = realloc(p, newsize);

La fonction recallocarray() doit être utilisée pour redimensionner des objets contenant des données sensibles comme des clés. Pour éviter les fuites d'informations, elle garantit que la mémoire est effacée avant d'être placée dans la liste des objets libres internes. La désallocation d'un tel objet doit être effectuée en appelant freezero().

VOIR AUSSI

malloc(3), calloc(3), alloca(3)

HISTORIQUE

La fonction reallocarray() est apparue dans OpenBSD 5.6, DragonFly 5.5 et glibc 2.26.

La fonction recallocarray() est apparue dans OpenBSD 6.1 et DragonFly 5.5. La fonction freezero() est apparue dans OpenBSD 6.2 et DragonFly 5.5.
