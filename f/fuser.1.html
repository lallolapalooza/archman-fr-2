FUSER(1) Commandes Utilisateur FUSER(1)

NOM

fuser - identifier les processus utilisant des fichiers ou des sockets

SYNTAXE

fuser [-fuv] [-a|-s] [-4|-6] [-c|-m|-n espace] [ -k [-i] [-M] [-w] [-SIGNAL] ] nom ...
fuser -l
fuser -V

DESCRIPTION

fuser affiche les PID des processus utilisant les fichiers spécifiés. En mode d'affichage par défaut, chaque nom de fichier est suivi d'une lettre indiquant le type d'accès :

c
répertoire courant.
e
exécutable en cours d'exécution.
f
fichier ouvert. f est omis en mode d'affichage par défaut.
F
fichier ouvert en écriture. F est omis en mode d'affichage par défaut.
r
répertoire racine.
m
fichier mmap'ed ou bibliothèque partagée.
.
Placeholder, omis en mode d'affichage par défaut.

fuser retourne un code de retour non nul si aucun des fichiers spécifiés n'est accédé ou en cas d'erreur fatale. Si au moins un accès a été trouvé, fuser retourne zéro.

Pour rechercher les processus utilisant les sockets TCP et UDP, l'espace de noms correspondant doit être sélectionné avec l'option -n. Par défaut, fuser recherchera dans les sockets IPv6 et IPv4. Pour modifier le comportement par défaut, utilisez les options -4 et -6. Les sockets peuvent être spécifiés par le port local et distant, et l'adresse distante. Tous les champs sont facultatifs, mais les virgules devant les champs manquants doivent être présentes :

[port_lcl][,[hote_rmt][,[port_rmt]]]

Des valeurs symboliques ou numériques peuvent être utilisées pour les adresses IP et les numéros de port.

fuser n'envoie que les PID vers la sortie standard, tout le reste est envoyé vers la sortie d'erreur.

OPTIONS

-a, --all
Afficher tous les fichiers spécifiés sur la ligne de commande. Par défaut, seuls les fichiers qui sont accédés par au moins un processus sont affichés.
-c
Identique à l'option -m, utilisée pour la compatibilité POSIX.
-f
Ignorée silencieusement, utilisée pour la compatibilité POSIX.
-k, --kill
Tuer les processus accédant au fichier. Sauf modification avec -SIGNAL, SIGKILL est envoyé. Un processus fuser ne se tue jamais lui-même, mais peut tuer d'autres processus fuser. L'ID utilisateur effectif du processus exécutant fuser est défini sur son ID utilisateur réel avant de tenter de tuer.
-i, --interactive
Demander confirmation à l'utilisateur avant de tuer un processus. Cette option est ignorée silencieusement si -k n'est pas présent.
-I, --inode
Pour l'espace de noms file, toutes les comparaisons sont basées sur les inodes des fichiers spécifiés et jamais sur les noms de fichiers, même sur les systèmes de fichiers réseau.
-l, --list-signals
Lister tous les noms de signaux connus.
-m NOM, --mount NOM
NOM spécifie un fichier sur un système de fichiers monté ou un périphérique bloc qui est monté. Tous les processus accédant aux fichiers de ce système de fichiers sont listés. Si un répertoire est spécifié, il est automatiquement changé en NOM/ pour utiliser tout système de fichiers qui pourrait être monté sur ce répertoire.
-M, --ismountpoint
La requête ne sera satisfaite que si NOM spécifie un point de montage. C'est une sécurité inestimable qui vous empêche de tuer la machine si NOM ne s'avère pas être un système de fichiers.
-w
Tuer uniquement les processus qui ont un accès en écriture. Cette option est ignorée silencieusement si l'option -k n'est pas présente également.
-n ESPACENOM, --namespace ESPACENOM
Sélectionner un espace de noms différent. Les espaces de noms file (noms de fichiers, par défaut), udp (ports UDP locaux) et tcp (ports TCP locaux) sont supportés. Pour les ports, le numéro de port ou le nom symbolique peut être spécifié. S'il n'y a pas d'ambiguïté, la notation raccourcie nom/espace (par exemple, 80/tcp) peut être utilisée.
-s, --silent
Opération silencieuse. -u et -v sont ignorés dans ce mode. -a ne doit pas être utilisé avec -s.
-SIGNAL
Utiliser le signal spécifié au lieu de SIGKILL lors de la mise à mort des processus. Les signaux peuvent être spécifiés par leur nom (par exemple, -HUP) ou par leur numéro (par exemple, -1). Cette option est ignorée silencieusement si l'option -k n'est pas utilisée.
-u, --user
Ajouter le nom de l'utilisateur propriétaire du processus à chaque PID.
-v, --verbose
Mode verbeux. Les processus sont affichés dans un style similaire à ps. Les champs PID, USER et COMMAND sont similaires à ps. ACCESS indique comment le processus accède au fichier. Le mode verbeux indiquera également lorsqu'un fichier particulier est accédé en tant que point de montage, exportation NFS ou fichier swap. Dans ce cas, kernel est affiché à la place du PID.
-V, --version
Afficher les informations de version.
-4, --ipv4
Rechercher uniquement les sockets IPv4. Cette option ne doit pas être utilisée avec l'option -6 et n'a d'effet qu'avec les espaces de noms tcp et udp.
-6, --ipv6
Rechercher uniquement les sockets IPv6. Cette option ne doit pas être utilisée avec l'option -4 et n'a d'effet qu'avec les espaces de noms tcp et udp.

FICHIERS

/proc
emplacement du système de fichiers proc

EXEMPLES

fuser -km /home
tue tous les processus accédant au système de fichiers /home de quelque manière que ce soit.
if fuser -s /dev/ttyS1; then :; else commande; fi
appelle commande si aucun autre processus n'utilise /dev/ttyS1.
fuser telnet/tcp
affiche tous les processus au port TELNET (local).

RESTRICTIONS

Les processus accédant au même fichier ou système de fichiers plusieurs fois de la même manière ne sont affichés qu'une seule fois.

Si le même objet est spécifié plusieurs fois sur la ligne de commande, certaines de ces entrées peuvent être ignorées.

fuser peut seulement collecter des informations partielles sauf s'il est exécuté avec les privilèges nécessaires. Par conséquent, les fichiers ouverts par des processus appartenant à d'autres utilisateurs peuvent ne pas être listés et les exécutables peuvent être classifiés uniquement comme mappés.
