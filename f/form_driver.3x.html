Une fois qu'un formulaire a été publié (affiché), vous devez acheminer les événements d'entrée vers lui via form_driver. Cette routine a trois cas d'entrée principaux

:
  • L'entrée est une demande de navigation dans le formulaire. Les codes de demande de navigation sont des constantes définies dans <form.h>, qui sont distincts des codes de touche et de caractère renvoyés par wgetch(
    • 3X).
  • L'entrée est un caractère imprimable. Les caractères imprimables (qui doivent être positifs et inférieurs à 256) sont vérifiés selon les paramètres de locale du
    • programme.
  • L'entrée est la tou
    • che spéciale KEY_MO
USE associée à un é
vénement de souris.

w

Cette extension simplifie l'utilisation de la bibliothèque de formulaires avec des caractères larges. L'entrée est soit un code de touche (une demande), soit un caractère large renvoyé par get_wch(3X). Le type doit également être transmis, afin de permettre à la bibl

iothèque de déterminer si le paramètre
est un caractère large ou une demande.

Validation des

champs

La bibliothèque de formulaires effectue des mises à jour sur la fenêtre associée aux champs de formulaire plutôt que directement sur les tampons de

champ.

Le pilote de formulaire fournit un contrôle de bas niveau sur les mises à jour des champs de formulaire. Le pilote de formulaire permet également de valider les champs modifiés afin de s'assurer que le contenu respecte les contraintes qu'une application peut attacher via set_field_type

.

Vous pouvez valider un champ sans y apporter aucune modification en utilisant REQ_VALIDATION. Le pilote de formulaire valide également un champ dans les cas suivants

:
  • un appel à set_current_field tente de se déplacer vers un autre
    • champ.
  • un appel à set_current_page tente de se déplacer vers une autre page du
    • formulaire.
  • une requête tente de se déplacer vers un autre
    • champ.
  • une requête tente de s
    • e déplacer vers une aut
re page du formulaire.

Dans chaque cas, le déplacement échoue si le champ est

invalide.

Si le champ modifié est valide, le pilote de fo

rmulaire copie les données modifiées de la fen
être associée au champ vers le tampon du champ.

Gestion de la

souris

Si le deuxième argument est la touche spéciale KEY_MOUSE, l'événement de souris associé est traduit en l'une des requêtes prédéfinies ci-dessus. Actuellement, seuls les clics dans la fenêtre utilisateur (par exemple, à l'intérieur de la zone d'affichage du formulaire ou de la fenêtre de décoration) sont

gérés.

Si vous cliquez au-dessus de la région d'affichage du formulaire

:
une REQ_PREV_FIELD est générée pour une
clic,
une REQ_PREV_PAGE est générée pour un double-clic
et
une REQ_FIRST_FIELD est générée pour un
triple-clic.

Si vous cliquez en dessous de la région d'affichage du formulaire 

:
une REQ_NEXT_FIELD est générée pour un clic
simple,
une REQ_NEXT_PAGE est générée pour un double-clic
et
une REQ_LAST_FIELD est générée pour un
triple-clic.

Si vous cliquez sur un champ à l'intérieur de la zone d'affichage du formulaire 

:
  • le curseur du formulaire est positionné sur ce
    • champ.
  • Si vous double-cliquez sur un champ, le curseur du formulaire est positionné sur ce champ et E_UNKNOWN_COMMAND est renvoyé. Cette valeur de retour a du sens, car un double-clic signifie généralement qu'une action propre au champ doit être renvoyée. C'est précisément le but de cette valeur de retour que de signaler qu'une commande spécifique à l'application doit être
    • exécutée.
  • Si une traduction en une requête a été effectuée, form_driver renvoie le
    • résu

Si vous avez cliqué en dehors de la fenêtre utilisateur ou si l'événement souris n'a pas pu être traduit en une requête de formulaire, une E_REQUEST_DENIED
