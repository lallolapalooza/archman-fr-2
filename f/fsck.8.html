FSCK(8) Administration système FSCK(8)

NOM

fsck - vérifier et réparer un système de fichiers Linux

SYNOPSIS

fsck [-lsAVRTMNP] [-r [fd]] [-C [fd]] [-t fstype] [filesystem...] [--] [fs-specific-options]

DESCRIPTION

fsck est utilisé pour vérifier et éventuellement réparer un ou plusieurs systèmes de fichiers Linux. filesystem peut être un nom de périphérique (par ex., /dev/hdc1, /dev/sdb2), un point de montage (par ex., /, /usr, /home), ou un étiquette de système de fichiers ou un spécificateur UUID (par ex., UUID=8868abf6-88c5-4a83-98b8-bfc24057f7bd ou LABEL=root). Normalement, le fsck essaiera de traiter les systèmes de fichiers sur différents disques physiques en parallèle pour réduire le temps total nécessaire pour les vérifier tous.

Si aucun système de fichiers n'est spécifié sur la ligne de commande, et si l'option -A n'est pas spécifiée, fsck vérifiera par défaut les systèmes de fichiers dans /etc/fstab de manière séquentielle. Cela équivaut aux options -As .

Le code de sortie renvoyé par fsck est la somme des conditions suivantes :

0

Aucune erreur

1

Erreurs du système de fichiers corrigées

2

Le système devrait être redémarré

4

Erreurs du système de fichiers laissées non corrigées

8

Erreur opérationnelle

16

Erreur d'utilisation ou de syntaxe

32

Vérification annulée à la demande de l'utilisateur

128

Erreur de bibliothèque partagée

Le code de sortie renvoyé lorsque plusieurs systèmes de fichiers sont vérifiés est le OU bit à bit des codes de sortie pour chaque système de fichiers vérifié.

En réalité, fsck est simplement une interface pour les différents outils de vérification de systèmes de fichiers (fsck.fstype) disponibles sous Linux. L'outil de vérification spécifique au système de fichiers est recherché dans la variable d'environnement PATH . Si le PATH n'est pas défini, on revient à /sbin.

Veuillez consulter les pages man des outils de vérification spécifiques aux systèmes de fichiers pour plus de détails.

OPTIONS

-l

Créer un fichier de verrouillage flock(2) exclusif (/run/fsck/<diskname>.lock) pour le périphérique de disque entier. Cette option ne peut être utilisée qu'avec un seul périphérique (ce qui signifie que -A et -l sont mutuellement exclusifs). Cette option est recommandée lorsque plusieurs instances de fsck sont exécutées en même temps. L'option est ignorée lorsqu'elle est utilisée pour plusieurs périphériques ou pour des disques non rotatifs. fsck ne verrouille pas les périphériques sous-jacents lorsqu'il est exécuté pour vérifier des périphériques empilés (par ex. MD ou DM) - cette fonctionnalité n'est pas encore implémentée.

-r [fd]

Afficher certaines statistiques pour chaque fsck lorsqu'il se termine. Ces statistiques incluent le code de sortie, la taille maximale de l'ensemble d'exécution (en kilo-octets), le temps écoulé total et le temps processeur utilisateur et système utilisé par l'exécution de fsck. Par exemple :

/dev/sda1: status 0, rss 92828, real 4.002804, user 2.677592, sys 0.86186

Les interfaces graphiques peuvent spécifier un descripteur de fichier fd, auquel cas les informations de la barre de progression seront envoyées à ce descripteur de fichier dans un format analysable par une machine. Par exemple :

/dev/sda1 0 92828 4.002804 2.677592 0.86186

-s

Sérialiser les opérations fsck . C'est une bonne idée si vous vérifiez plusieurs systèmes de fichiers et que les outils de vérification sont en mode interactif. (Remarque : e2fsck(8) s'exécute en mode interactif par défaut. Pour faire e2fsck(8) s'exécuter en mode non interactif, vous devez soit spécifier l'option -p ou -a si vous souhaitez que les erreurs soient corrigées automatiquement, soit l'option -n si vous ne le souhaitez pas.)

-t fslist

Spécifie le ou les types de systèmes de fichiers à vérifier. Lorsque l'indicateur -A est spécifié, seuls les systèmes de fichiers correspondant à fslist sont vérifiés. Le paramètre fslist est une liste de systèmes de fichiers et de spécificateurs d'options séparés par des virgules. Tous les systèmes de fichiers de cette liste séparée par des virgules peuvent être préfixés par un opérateur de négation 'no' ou '!', qui demande que seuls les systèmes de fichiers non listés dans fslist soient vérifiés. Si aucun des systèmes de fichiers dans fslist n'est préfixé par un opérateur de négation, alors seuls les systèmes de fichiers listés seront vérifiés.

Des spécificateurs d'options peuvent être inclus dans la liste séparée par des virgules fslist. Ils doivent avoir le format opts=fs-option. Si un spécificateur d'options est présent, alors seuls les systèmes de fichiers contenant fs-option dans leur champ d'options de montage de /etc/fstab seront vérifiés. Si le spécificateur d'options est préfixé par un opérateur de négation, alors seuls les systèmes de fichiers qui n'ont pas fs-option dans leur champ d'options de montage de /etc/fstab seront vérifiés.

Par exemple, si opts=ro apparaît dans fslist, alors seuls les systèmes de fichiers listés dans /etc/fstab avec l'option ro seront vérifiés.

Pour la compatibilité avec les distributions Mandrake dont les scripts de démarrage dépendent d'une modification non autorisée de l'interface du programme fsck , si un type de système de fichiers loop est trouvé dans fslist, il est traité comme si opts=loop avait été spécifié comme argument de l'option -t .

Normalement, le type de système de fichiers est déduit en recherchant filesys dans le fichier /etc/fstab et en utilisant l'entrée correspondante. Si le type ne peut pas être déduit, et qu'un seul système de fichiers est donné comme argument de l'option -t , fsck utilisera le type de système de fichiers spécifié. Si ce type n'est pas disponible, le type de système de fichiers par défaut (actuellement ext2) est utilisé.

-A

Parcourir le fichier /etc/fstab et essayer de vérifier tous les systèmes de fichiers en une seule exécution. Cette option est généralement utilisée depuis le fichier d'initialisation système /etc/rc , au lieu de multiples commandes pour vérifier un système de fichiers unique.

Le système de fichiers racine sera vérifié en premier, sauf si l'option -P est spécifiée (voir ci-dessous). Ensuite, les systèmes de fichiers seront vérifiés dans l'ordre spécifié par le champ fs_passno (le sixième) dans le fichier /etc/fstab . Les systèmes de fichiers ayant une valeur fs_passno de 0 sont ignorés et ne sont pas du tout vérifiés. Les systèmes de fichiers ayant une valeur fs_passno]] supérieure à zéro seront vérifiés dans l'ordre, avec les systèmes de fichiers ayant le numéro fs_passno]] le plus bas vérifiés en premier. S'il y a plusieurs systèmes de fichiers avec le même numéro de passe, fsck essaiera de les vérifier en parallèle, bien qu'il évitera d'exécuter plusieurs vérifications de systèmes de fichiers sur le même disque physique.

fsck ne vérifie pas les périphériques empilés (RAID, dm-crypt, ...) en parallèle avec un autre périphérique. Voir ci-dessous pour le paramètre FSCK_FORCE_ALL_PARALLEL . Le système de fichiers /sys est utilisé pour déterminer les dépendances entre les périphériques.

Par conséquent, une configuration très courante dans les fichiers /etc/fstab consiste à définir le système de fichiers racine avec une valeur fs_passno]] de 1 et à définir tous les autres systèmes de fichiers avec une valeur fs_passno]] de 2. Cela permettra à fsck d'exécuter automatiquement les outils de vérification de systèmes de fichiers en parallèle si c'est avantageux de le faire. Les administrateurs système peuvent choisir de ne pas utiliser cette configuration s'ils doivent éviter plusieurs vérifications de systèmes de fichiers s'exécutant en parallèle pour une raison quelconque - par exemple, si la machine en question manque de mémoire de sorte que la pagination excessive est un problème.

fsck ne vérifie normalement pas si le périphérique existe réellement avant d'appeler un outil de vérification spécifique au système de fichiers. Par conséquent, des périphériques inexistants peuvent faire entrer le système en mode de réparation de système de fichiers lors du démarrage si l'outil de vérification spécifique au système de fichiers renvoie une erreur fatale. L'option de montage /etc/fstab nofail peut être utilisée pour faire en sorte que fsck ignore les périphériques inexistants. fsck ignore également les périphériques inexistants ayant le type de système de fichiers spécial auto.

-C [fd]

Afficher les barres de progression pour les vérificateurs de systèmes de fichiers (actuellement uniquement pour ext[234]) qui les prennent en charge. fsck gérera les vérificateurs de systèmes de fichiers afin qu'un seul d'entre eux n'affiche une barre de progression à la fois. Les interfaces graphiques peuvent spécifier un descripteur de fichier fd, auquel cas les informations de la barre de progression seront envoyées à ce descripteur de fichier.

-M

Ne pas vérifier les systèmes de fichiers montés et renvoyer un code de sortie de 0 pour les systèmes de fichiers montés.

-N

Ne pas exécuter, juste montrer ce qui serait fait.

-P

Lorsque l'option -A est définie, vérifier le système de fichiers racine en parallèle avec les autres systèmes de fichiers. Ce n'est pas la chose la plus sûre au monde à faire, car si le système de fichiers racine est douteux, des choses comme l'exécutable e2fsck(8) pourraient être corrompues ! Cette option est principalement fournie pour les administrateurs système qui ne souhaitent pas repartitionner le système de fichiers racine pour le rendre petit et compact (ce qui est vraiment la bonne solution).

-R

Lors de la vérification de tous les systèmes de fichiers avec l'option -A , ignorer le système de fichiers racine. (C'est utile si le système de fichiers racine a déjà été monté en lecture-écriture.)

-T

Ne pas afficher le titre au démarrage.

-V

Produire une sortie verbeuse, incluant toutes les commandes spécifiques au système de fichiers qui sont exécutées.

-?, --help

Afficher le texte d'aide et quitter.

--version

Afficher les informations de version et quitter.

OPTIONS SPÉCIFIQUES AU SYSTÈME DE FICHIERS

Les options que fsck ne comprend pas sont transmises au vérificateur spécifique au système de fichiers !

Ces options ne doivent pas prendre d'arguments, car il n'y a aucun moyen pour fsck de deviner correctement quelles options prennent des arguments et lesquelles n'en prennent pas.

Les options et les arguments qui suivent -- sont traités comme des options spécifiques au système de fichiers à transmettre au vérificateur spécifique au système de fichiers. fichiers.

Veuillez noter que fsck n'est pas conçu pour transmettre des options arbitrairement compliquées aux vérificateurs spécifiques aux systèmes de fichiers. Si vous faites quelque chose de compliqué, veuillez simplement exécuter directement le vérificateur spécifique au système de fichiers. Si vous transmettez à fsck des options et des arguments horriblement compliqués, et qu'il ne fait pas ce que vous attendez, ne vous donnez pas la peine de le signaler comme un bogue. Vous faites presque certainement quelque chose que vous ne devriez pas faire avec fsck. Les options des différents fsck spécifiques aux systèmes de fichiers ne sont pas standardisées.

ENVIRONNEMENT

Le comportement du programme fsck est affecté par les variables d'environnement suivantes :

FSCK_FORCE_ALL_PARALLEL

Si cette variable d'environnement est définie, fsck essaiera de vérifier tous les systèmes de fichiers spécifiés en parallèle, qu'ils semblent ou non se trouver sur le même périphérique. (C'est utile pour les systèmes RAID ou les systèmes de stockage haut de gamme comme ceux vendus par des entreprises comme IBM ou EMC.) Notez que la valeur fs_passno est toujours utilisée.

FSCK_MAX_INST

Cette variable d'environnement limitera le nombre maximal de vérificateurs de systèmes de fichiers pouvant être en cours d'exécution à la fois. Cela permet aux configurations ayant un grand nombre de disques d'éviter que fsck ne lance trop de vérificateurs de systèmes de fichiers à la fois, ce qui pourrait surcharger les ressources CPU et mémoire disponibles sur le système. Si cette valeur est zéro, un nombre illimité de processus peut être lancé. C'est actuellement la valeur par défaut, mais les futures versions de fsck pourraient tenter de déterminer automatiquement combien de vérifications de systèmes de fichiers peuvent être exécutées en se basant sur la collecte de données de comptage du système d'exploitation.

PATH

La variable d'environnement PATH est utilisée pour trouver les vérificateurs de systèmes de fichiers.

FSTAB_FILE

Cette variable d'environnement permet à l'administrateur système de remplacer l'emplacement standard du fichier /etc/fstab . Elle est également utile pour les développeurs qui testent fsck.

LIBBLKID_DEBUG=all

active la sortie de débogage de libblkid.

LIBMOUNT_DEBUG=all

active la sortie de débogage de libmount.

FICHIERS

/etc/fstab

NOTES

Pendant le démarrage, systemd n'invoque pas fsck -A. Au lieu de cela, il planifie l'activation des montages individuellement, en tenant compte des dépendances sur les périphériques de support, le réseau et d'autres facteurs. Par conséquent, fsck est appelé individuellement pour chaque périphérique.
