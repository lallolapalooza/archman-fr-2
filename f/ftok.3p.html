FTOK(3P) Manuel du programmeur POSIX FTOK(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

ftok — générer une clé IPC

SYNOPSISSE

#include <sys/ipc.h>
key_t ftok(const char *path, int id);

DESCRIPTION

La ftok() fonction doit retourner une clé basée sur path et id qui est utilisable dans les appels ultérieurs à msgget(), semget(), et shmget(). L'application doit s'assurer que l'argument path est le chemin d'accès d'un fichier existant que le processus est capable de stat(), à l'exception que si stat() échouerait avec [EOVERFLOW] en raison de la taille du fichier, ftok() doit néanmoins réussir.

La ftok() fonction doit retourner la même valeur de clé pour tous les chemins qui nomment le même fichier, lorsqu'elle est appelée avec la même valeur id , et doit retourner des valeurs de clé différentes lorsqu'elle est appelée avec des valeurs id différentes ou avec des chemins qui nomment différents fichiers existant sur le même système de fichiers au même moment. Il n'est pas spécifié si ftok() doit retourner la même valeur de clé lorsqu'elle est rappelée après que le fichier nommé par path a été supprimé et recréé avec le même nom.

Seuls les 8 bits de poids faible de id sont significatifs. Le comportement de ftok() n'est pas spécifié si ces bits sont à 0.

VALEUR RENVOYÉE

Lors de l'achèvement avec succès, ftok() doit retourner une clé. Sinon, ftok() doit retourner (key_t)-1 et définir errno pour indiquer l'erreur.

ERREURS

La ftok() fonction doit échouer si :

EACCES
La permission de recherche est refusée pour un composant du préfixe de chemin.
EIO
Une erreur s'est produite lors de la lecture depuis le système de fichiers.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un composant d'un chemin d'accès est plus longue que {NAME_MAX}.
ENOENT
Un composant de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOTDIR
Un composant du préfixe de chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou l'argument path contient au moins un caractère non-<slash> et se termine par un ou plusieurs caractères <slash> finaux et le dernier composant du chemin d'accès nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.

La ftok() fonction peut échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un chemin d'accès dépasse {PATH_MAX}, ou la résolution d'un chemin d'accès d'un lien symbolique a produit un résultat intermédiaire avec une longueur qui dépasse {PATH_MAX}.

Les sections suivantes sont informatives.

EXEMPLES

Obtenir une clé IPC

L'exemple suivant obtient une clé basée sur le chemin d'accès /tmp et la valeur d'ID a. Il assigne également la valeur de la clé résultante à la variable semkey afin qu'elle soit disponible pour un appel ultérieur à semget(), msgget(), ou shmget().

#include <sys/ipc.h>
...
key_t semkey;
if ((semkey = ftok("/tmp", 'a')) == (key_t) -1) {
    perror("IPC error: ftok"); exit(1);
}

UTILISATION PAR LES APPLICATIONS

Pour une portabilité maximale, id devrait être un caractère d'un seul octet.

Les applications ne devraient pas supposer que la valeur de clé résultante est unique.

JUSTIFICATION

Aucune.

DIRECTIONS FUTURES

Les futures versions de cette norme peuvent ajouter de nouvelles interfaces pour fournir des clés uniques.
