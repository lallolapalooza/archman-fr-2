SYNTAXE

Les shells comme fish sont utilisés en leur donnant des commandes. Une commande est exécutée en écrivant le nom de la commande suivi de ses arguments. Par exemple

Chaque programme sur votre ordinateur peut être utilisé comme une commande dans fish. Si le fichier du programme se trouve dans l'un des répertoires PATH, vous pouvez simplement taper le nom du programme pour l'utiliser. Sinon, le nom de fichier complet, y compris le répertoire (comme /home/me/code/checkers/checkers ou ../checkers) est

Les commandes et les arguments sont séparés par le caractère espace ' '. Chaque commande se termine soit par un retour à la ligne (en appuyant sur la touche retour), soit par un point-virgule ;. Plusieurs commandes peuvent être écrites sur la même ligne en les séparant par des points-virgules

Un commutateur est un type d'argument spécial très courant. Les commutateurs commencent presque toujours par un ou plusieurs tirets - et modifient la manière dont une commande fonctionne. Par exemple, la commande ls liste généralement les noms de tous les fichiers et répertoires du répertoire de travail courant. En utilisant le commutateur -l, le comportement de ls est modifié pour afficher non seulement le nom du fichier, mais aussi sa taille, ses permissions, son propriétaire et l'heure de sa

modification.

Les commutateurs diffèrent d'une commande à l'autre et sont généralement documentés sur la page de manuel d'une commande. Il existe cependant certains commutateurs qui sont communs à la plupart des commandes. Par exemple, --help affichera généralement un texte d'aide, --version affichera généralement la version de la commande, et -i activera souvent une invite interactive avant d'agir. Essayez man votre-commande-ici pour obtenir des informations sur les commutateurs de votre

commande.

Ainsi, l'idée de base de fish est la même que pour les autres she

Fish comprend deux types de guillemets : simples (') et doubles ("), et les deux fonctionnent légèrement

Entre guillemets simples, fish n'effectue aucune expansion. Entre guillemets doubles, fish n'effectue que l'expansion de variable et la substitution de commande dans le $(command). Dans les guillemets, les espaces ne sont pas utilisés pour séparer les arguments, ce qui permet aux arguments entre guillemets de contenir des

espaces.

Les seules séquences d'échappement significatives dans les guillemets simples sont \', qui échappe une apostrophe, et \\, qui échappe le symbole de la barre oblique inverse. Les seules échappements significatifs dans les guillemets doubles sont \", qui échappe un guillemet double, \$, qui échappe un caractère dollar, \ suivi d'un retour à la ligne, qui supprime la barre oblique inverse et le retour à la ligne, et \\, qui échappe le symbole de la barre oblique

inverse.

Les guillemets simples n'ont pas de signification particulière à l'intérieur des guillemets doubles et vice

Quoting variables

L'expansion des variables se produit également dans les chaînes entre guillemets doubles. Dans les guillemets doubles ("ceux-ci"), les variables seront toujours étendues à un seul argument. Si elles sont vides ou non définies, cela entraînera une chaîne vide. Si elles ont un élément, elles seront étendues à cet élément. Si elles en ont plus, les éléments seront joints par des espaces, à moins que la variable ne soit une variable de chemin - dans ce cas, elle utilisera un deux-points (:) à la place [3].

Les variables de poisson sont toutes des listes, et elles sont divisées en éléments lorsqu'elles sont définies - cela signifie qu'il est important de décider s'il faut utiliser des guillemets ou non avec set <> :

set foo 1 2 3 # une variable avec trois éléments
rm $foo # exécute l'équivalent de `rm 1 2 3` - essaie de supprimer trois fichiers : 1, 2 et 3.
rm "$foo" # exécute `rm '1 2 3'` - essaie de supprimer un fichier appelé '1 2 3'
set foo # une variable vide
rm $foo # exécute `rm` sans arguments
rm "$foo" # exécute l'équivalent de `rm ''`
set foo "1 2 3"
rm $foo # exécute l'équivalent de `rm '1 2 3'` - essaie de supprimer un fichier
rm "$foo" # la même chose

Ceci est différent des autres shells, qui font ce qui est connu sous le nom de "Word Splitting", où ils divisent la variable lorsqu'elle est utilisée dans une expansion. Par exemple, en bash :

foo="1 2 3"
rm $foo # exécute l'équivalent de `rm 1 2 3`
rm "$foo" # exécute l'équivalent de `rm '1 2 3'`

C'est la cause de problèmes très courants avec les noms de fichiers contenant des espaces dans les scripts bash.

En fish, les variables non mises entre guillemets s'étendront en autant d'arguments qu'elles ont d'éléments. Cela signifie qu'une liste vide s'étendra à rien, une variable avec un élément s'étendra à cet élément, et une variable avec plusieurs éléments s'étendra à chacun de ces éléments séparément.

Si une variable s'étend à rien, elle annulera toutes les autres chaînes qui lui sont attachées. Voir la section Combinaison de listes pour plus d'informations.

La plupart du temps, ne pas mettre une variable entre guillemets est correct. L'exception est lorsque vous devez vous assurer que la variable est passée comme un seul élément, même si elle peut être non définie ou avoir plusieurs éléments. Cela arrive souvent avec test <> :

test -n "$foo"

test -n "one two three"

Dereferencing variables

Le symbole $ peut également être utilisé plusieurs fois, comme une sorte d'opérateur de "déréférencement" (le * en C ou C++), comme dans le code suivant :

$$foo[$i] est "la valeur de la variable nommée par $foo[$i]".

Cela peut également être utilisé pour donner un nom de variable à une fonction :

    for arg in $argv
        echo Variable $arg est $$arg
    end

set -g foo 1 2 3
set -g bar a b c

Bien sûr, la variable devra être accessible depuis la fonction, donc elle doit être globale/universelle ou exportée. Elle ne peut pas non plus entrer en conflit avec un nom de variable utilisé à l'intérieur de la fonction. Ainsi, si nous avions fait de $foo une variable locale, ou si nous l'avions nommée "arg" à la place, cela n'aurait pas fonctionné.

Lors de l'utilisation de cette fonctionnalité avec des tranches, les tranches seront utilisées de l'intérieur vers l'extérieur. $$foo[5] utilisera le cinquième élément de $foo comme nom de variable, au lieu de donner le cinquième élément de toutes les variables auxquelles $foo fait référence. Cela serait plutôt exprimé comme $$foo[1..-1][5] (prendre tous les éléments de $foo, les utiliser comme noms de variables, puis donner le cinquième élément de ceux-ci).

Quelques exemples supplémentaires :

# Sortie : 1 2 3

# $var[2] est listtwo, troisième élément de celle-ci est 6, sortie : 6
echo $$var[..][2]
# Le deuxième élément de chaque variable, donc sortie : 2 5

Command substitution

Une substitution de commande est une expansion qui utilise la sortie d'une commande comme arguments pour une autre. Par exemple :

echo $(pwd)

Ceci exécute la commande pwd <>, prend sa sortie (plus précisément ce qu'elle a écrit dans le flux de sortie standard "stdout") et l'utilise comme arguments pour echo <>. Ainsi, la commande interne (le pwd) est exécutée en premier et doit se terminer avant que la commande externe ne puisse même être démarrée.

Si la commande interne imprime plusieurs lignes, fish utilisera chaque ligne séparée comme un argument séparé pour la commande externe. Contrairement aux autres shells, la valeur de $IFS n'est pas utilisée [4], fish divise par les nouvelles lignes.

Les substitutions de commande peuvent également être mises entre guillemets doubles :

echo "$(pwd)"

Lors de l'utilisation de guillemets doubles, la sortie de la commande n'est pas divisée par lignes, mais les lignes vides finales sont toujours supprimées.

Si la sortie est redirigée vers string split ou string split0 <> comme dernière étape, ces divisions sont utilisées telles qu'elles apparaissent au lieu de diviser les lignes.

Fish permet également d'écrire des substitutions de commande sans le dollar, comme echo (pwd). Cette variante ne sera pas étendue dans les guillemets doubles (echo "(pwd)" affichera (pwd)).

Le code de sortie de la dernière substitution de commande exécutée est disponible dans la variable status si la substitution a lieu dans le contexte d'une commande set <> (donc if set -l (something) vérifie si something a retourné vrai).

Pour n'utiliser que certaines lignes de la sortie, référez-vous aux tranches.

Exemples :

# Affiche 'image.png'.
echo (basename image.jpg .jpg).png
# Convertit tous les fichiers JPEG du répertoire courant au
# format PNG en utilisant le programme 'convert'.
for i in *.jpg; convert $i (basename $i .jpg).png; end
# Définit la variable ``data`` au contenu de 'data.txt'
# sans la diviser en une liste.
set data "$(cat data.txt)"
# Définit ``$data`` au contenu de data, en divisant par les octets NUL.
set data (cat data | string split0)

Parfois, vous voulez passer la sortie d'une commande à une autre commande qui n'accepte que des fichiers. S'il ne s'agit que d'un seul fichier, vous pouvez généralement le passer via un pipe, comme :

grep fish myanimallist1 | wc -l

mais si vous avez besoin de plusieurs fichiers ou si la commande ne lit pas depuis l'entrée standard, la "substitution de processus" est utile. D'autres shells le permettent via foo <(bar) <(baz), et fish utilise la commande psub <> :

# Compare seulement les lignes contenant "fish" dans deux fichiers :
diff -u (grep fish myanimallist1 | psub) (grep fish myanimallist2 | psub)

Cela crée un fichier temporaire, stocke la sortie de la commande dans ce fichier et affiche le nom du fichier, qui est ensuite donné à la commande externe.

Fish a une limite par défaut de 1 Gio sur les données qu'il lira dans une substitution de commande. Si cette limite est atteinte, la commande (toute, pas seulement la substitution de commande - la commande externe ne sera même pas exécutée) échoue et $status est défini sur 122. Ceci afin que les substitutions de commande ne puissent pas provoquer une insuffisance de mémoire système, car généralement votre système d'exploitation a une limite beaucoup plus basse, donc lire plus que cela serait inutile et nuisible. Cette limite peut être ajustée avec la variable fish_read_limit (0 signifiant aucune limite). Cette limite affecte également la commande read <>.

Une exception : définir $IFS sur vide désactive la division par lignes. Ceci est obsolète, utilisez plutôt string split <>.

Exportation des

Les variables dans fish peuvent être exportées, afin qu'elles soient héritées par toutes les commandes lancées par fish. En particulier, c'est nécessaire pour les variables utilisées pour configure external commands like PAGER or GOPATH, but also for variables that contain general system settings like PATH or LANGUAGE. If an external command needs to know a variable, it needs to be exported. Exported variables are also often called "environment variables".

Cela s'applique également à fish : lorsqu'il démarre, il reçoit des variables d'environnement de son parent (généralement le terminal). Celles-ci incluent généralement la configuration du système comme PATH et les variables de localisation.

Les variables peuvent être explicitement définies pour être exportées avec le commutateur -x ou --export, ou non exportées avec le commutateur -u ou --unexport. Les règles d'exportation lors de la définition d'une variable sont similaires aux règles d'étendue des variables : lorsqu'une option est passée, elle est respectée, sinon l'état existant de la variable est utilisé. Si aucune option n'est passée et que la variable n'existait pas encore, elle n'est pas exportée.

Par convention de nommage, les variables exportées sont en majuscules et les variables non exportées sont en minuscules.

Par exemple :

set -gx ANDROID_HOME ~/.android # /opt/android-sdk
set -gx CDPATH . ~ (test -e ~/Videos; and echo ~/Videos)
set -gx EDITOR emacs -nw
set -gx GOPATH ~/dev/go
set -gx GTK2_RC_FILES "$XDG_CONFIG_HOME/gtk-2.0/gtkrc"
set -gx LESSHISTFILE "-"

Note : L'exportation n'est pas une portée, mais un état supplémentaire. Il est généralement logique de rendre les variables exportées globales aussi, mais les variables exportées locales peuvent être utiles si vous avez besoin de quelque chose de plus spécifique que les remplacements. Elles sont copiées dans les fonctions afin que la fonction ne puisse pas les modifier en dehors, et restent disponibles pour les commandes. Les variables globales sont accessibles aux fonctions qu'elles soient exportées ou non.

Listes

Fish peut stocker une liste (ou un "tableau" si vous préférez) de plusieurs chaînes dans une variable :

> set mylist first second third
> printf '%s\n' $mylist # imprime chaque élément sur sa propre ligne
first
second
third

Pour accéder à un élément d'une liste, utilisez l'index de l'élément entre crochets, comme ceci :

echo $PATH[3]

Les index de liste commencent à 1 dans fish, pas à 0 comme dans d'autres langages. C'est parce que cela nécessite moins de soustraction de 1 et que de nombreux outils Unix courants comme seq fonctionnent mieux avec ( seq 5 imprime de 1 à 5, pas de 0 à 5). Un index invalide est ignoré silencieusement, ce qui ne donne aucune valeur (même pas une chaîne vide, aucun argument du tout).

Si vous n'utilisez aucun crochet, tous les éléments de la liste seront transmis à la commande comme des éléments séparés. Cela signifie que vous pouvez itérer sur une liste avec for :

for i in $PATH
    echo $i est dans le chemin
end

Cela parcourt chaque répertoire de PATH séparément et imprime une ligne indiquant qu'il est dans le chemin.

Pour créer une variable smurf, contenant les éléments blue et small, tapez :

set smurf blue small

Il est également possible de définir ou d'effacer des éléments individuels d'une liste :

# Définir smurf comme une liste avec les éléments 'blue' et 'small'
set smurf blue small
# Changer le deuxième élément de smurf en 'evil'
set smurf[2] evil
# Effacer le premier élément
set -e smurf[1]
# Afficher 'evil'
echo $smurf

Si vous spécifiez un index négatif lors de l'expansion ou de l'affectation à une variable de liste, l'index sera pris à partir de la fin de la liste. Par exemple, l'index -1 est le dernier élément de la liste :

> set fruit apple orange banana
> echo $fruit[-1]
banana
> echo $fruit[-2..-1]
orange
banana
> echo $fruit[-1..1] # inverse la liste
banana
orange
apple

Comme vous pouvez le voir, vous pouvez utiliser une plage d'indices, voir les tranches pour plus de détails.

Toutes les listes sont unidimensionnelles et ne peuvent pas contenir d'autres listes, bien qu'il soit possible de simuler des listes imbriquées en utilisant le déréférencement - voir l'expansion des variables.

Lorsqu'une liste est exportée en tant que variable d'environnement, elle est délimitée par des espaces ou des deux-points, selon qu'il s'agit ou non d'une variable de chemin :

> set -x smurf blue small
> set -x smurf_PATH forest mushroom
> env | grep smurf
smurf=blue small
smurf_PATH=forest:mushroom

Fish crée automatiquement des listes à partir de toutes les variables d'environnement dont le nom se termine par PATH (comme PATH, CDPATH ou MANPATH), en les séparant par des deux-points. Les autres variables ne sont pas automatiquement séparées.

Les listes peuvent être inspectées avec les commandes count ou contains :

> contains blue $smurf

# (sans rien afficher)

Un avantage des listes est qu'elles sont transmises aux commandes un élément à la fois comme un argument, donc une fois que vous avez défini votre liste, vous pouvez la passer :

Contrairement aux autres shells, fish ne fait pas de "division de mots" - les éléments d'une liste restent tels quels, même s'ils contiennent des espaces ou des tabulations.

Gestion des arguments

Une liste importante est $argv, qui contient les arguments d'une fonction ou d'un script. Par exemple :

function myfunction
    echo $argv[1]
    echo $argv[3]
end

Cette fonction prend les arguments qu'elle reçoit et imprime le premier et le troisième :

> myfunction first second third
first
third
> myfunction apple cucumber banana
apple
banana

Cela couvre les arguments positionnels, mais les outils en ligne de commande reçoivent souvent diverses options et indicateurs, et $argv les contiendrait mélangés avec les arguments positionnels. La gestion typique des arguments Unix permet les options courtes (-h, également groupées comme dans ls -lah), les options longues (--help) et permet à ces options de prendre des arguments (--color=auto ou --position anywhere ou complete -C"git ") ainsi qu'un séparateur -- pour signaler la fin des options. Gérer tout cela manuellement est compliqué et sujet aux erreurs.

Une approche plus robuste pour la gestion des options est argparse, qui vérifie les options définies et les place dans diverses variables, laissant uniquement les arguments positionnels dans $argv. Voici un exemple simple :

function mybetterfunction
    # Nous informons argparse des options -h/--help et -s/--second
    # - ce sont les formes courtes et longues de la même option.
    # Le "--" ici est obligatoire,
    # il indique à partir d'où lire les arguments.
    argparse h/help s/second -- $argv
    # quitter si argparse a échoué parce que
    # il a trouvé une option qu'il ne reconnaissait pas
    # - il affichera une erreur
    or return
    # Si -h ou --help est donné, nous affichons un petit texte d'aide et retournons
    if set -ql _flag_help
        echo "mybetterfunction [-h|--help] [-s|--second] [ARGUMENT ...]"

La variable

Lorsqu'un processus se termine, un code de sortie est renvoyé au programme qui l'a lancé (généralement le shell). DÉBOGAGE DES SCRIPTS

FISH

Fish inclut des fonctionnalités de débogage intégrées de base qui vous permettent d'arrêter l'exécution d'un script à un point arbitraire. Lorsque cela se produit, vous êtes présenté avec une invite interactive où vous pouvez exécuter n'importe quelle commande fish pour inspecter ou modifier l'état (il n'y a pas de commandes de débogage en soi). Par exemple, vous pouvez vérifier ou modifier la valeur de n'importe quelles variables en utilisant printf <> et set <>. Comme autre exemple, vous pouvez exécuter status print-stack-trace <> pour voir comment le point d'arrêt actuel a été atteint. Pour reprendre l'exécution normale du script, tapez exit <> ou ctrl-d

.

Pour démarrer une session de débogage, insérez la commande builtin <> breakpoint à l'endroit dans une fonction ou un script où vous souhaitez prendre le contrôle, puis exécutez la fonction ou le script. De plus, l'action par défaut du signal TRAP est d'appeler ce builtin, ce qui signifie qu'un script en cours d'exécution peut être débogué activement en lui envoyant le signal TRAP (kill -s TRAP <PID>). Il y a une prise en charge limitée pour définir ou modifier interactivement les points d'arrêt depuis cette invite de débogage : il est possible d'insérer de nouveaux points d'arrêt dans (ou d'en supprimer d'anciens) d'autres fonctions en utilisant la fonction funced pour éditer la définition d'une fonction, mais il n'est pas possible d'ajouter ou de supprimer un point d'arrêt de la fonction/script actuellement chargé et en cours

d'exécution.

Une autre façon de déboguer les problèmes de script est de définir la variable fish_trace, par ex. fish_trace=1 fish_prompt pour voir quelles commandes fish exécute lors de l'exécution de la fonction fish_prompt <>

.
