DESCRIPTIO

N

La fonction statvfs() renvoie des informations sur un système de fichiers monté. path est le chemin d'accès de n'importe quel fichier situé à l'intérieur du système de fichiers monté. buf est un pointeur vers une structure statvfs définie approximativement comme suit

: 


struct statvfs {
    unsigned long  f_bsize;    /* Taille de bloc du système de fichiers */
    unsigned long  f_frsize;   /* Taille de fragment */
    fsblkcnt_t     f_blocks;   /* Taille du sf en unités de f_frsize */
    fsblkcnt_t     f_bfree;    /* Nombre de blocs libres */
    fsblkcnt_t     f_bavail;   /* Nombre de blocs libres pour
                                  les utilisateurs non privilégiés */
    fsfilcnt_t     f_files;    /* Nombre d'inodes */
    fsfilcnt_t     f_ffree;    /* Nombre d'inodes libres */
    fsfilcnt_t     f_favail;   /* Nombre d'inodes libres pour
                                  les utilisateurs non privilégiés */
    unsigned long  f_fsid;     /* Identifiant du système de fichiers */
    unsigned long  f_flag;     /* Drapeaux de montage */
    unsigned long  f_namemax;  /* Longueur maximale de nom de fichier */
}
;

Ici, les types fsblkcnt_t et fsfilcnt_t sont définis dans <sys/types.h>. Tous deux étaient unsigned

long.

Le champ f_flag est un masque de bits indiquant diverses options qui ont été utilisées lors du montage de ce système de fichiers. Il contient zéro ou plusieurs des drapeaux suivants

:

NOTE

S

Le noyau Linux dispose des appels système statfs(2) et fstatfs(2) pour prendre en charge cet appel de

bibliothèque.

Les implémentations glibc

de 


pathconf(path, _PC_REC_XFER_ALIGN);
pathconf(path, _PC_ALLOC_SIZE_MIN);
pathconf(path, _PC_REC_MIN_XFER_SIZE)
;

utilisent respectivement les champs f_frsize, f_frsize, et f_bsize renvoyés par un appel à statvfs() avec l'argument path

.

Sous Linux, f_favail est toujours identique à f_ffree, et il n'y a aucun moyen pour un système de fichiers de signaler autrement. Ce n'est

pas un problème, car aucun système de fichier
s avec une réservation d'inodes racine n'existe.

HISTORIQU

E

POSIX.

1-2001.

Avant glibc 2.13, statvfs() remplissait les bits du champ f_flag en analysant les options de montage affichées dans /proc/mounts. Cependant, à partir de Linux 2.6.36, l'appel système statfs(2) fournit les informations nécessaires via le champ f_flags, et depuis glibc 2.13, la fonction statvfs() utilisera les informations de ce champ plutôt que d'analyser /proc/mount

s
