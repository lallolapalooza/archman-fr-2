FLATPAK BUILD-EXPOR(1) flatpak build-export FLATPAK BUILD-EXPOR(1)

NOM

flatpak build-export - Crée un dépôt à partir d'un répertoire de compilation

SYNTAXE

flatpak build-export [OPTION...]EMPLACEMENT RÉPERTOIRE [BRANCHE]

DESCRIPTION

Crée ou met à jour un dépôt avec une compilation d'application. EMPLACEMENT est l'emplacement du dépôt. RÉPERTOIRE doit être un répertoire de compilation finalisé. Si BRANCHE n'est pas spécifié, il est supposé être "master".

Si EMPLACEMENT existe, il est supposé être un dépôt OSTree, sinon un nouveau dépôt OSTree est créé à cet emplacement. Le dépôt peut être inspecté avec l'outil ostree.

Le contenu de RÉPERTOIRE est validé sur la branche nommée app/NOMAPP/ARCH/BRANCHE, où ARCH est l'architecture du runtime que l'application utilise. Un filtre de validation est utilisé pour s'assurer que seul le contenu des sous-répertoires files/ et export/ ainsi que le fichier de métadonnées sont inclus dans la validation, tout le reste est ignoré.

Lors de l'exportation d'un flatpak à publier sur Internet, --collection-id=ID-COLLECTION doit être spécifié comme une valeur inverse DNS globalement unique pour identifier la collection de flatpaks à laquelle cela sera ajouté. La définition d'un identifiant de collection globalement unique permet aux applications du dépôt d'être partagées sur des systèmes pair-à-pair sans nécessiter de configuration supplémentaire.

La commande build-update-repo doit être utilisée pour mettre à jour les métadonnées du dépôt chaque fois que des compilations d'applications sont ajoutées à un dépôt.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche les options d'aide et quitte.

-s, --subject=SUJET

Sujet d'une ligne pour le message de validation.

-b, --body=CORPS

Description complète pour le message de validation.

--collection-id=ID-COLLECTION

Définit l'identifiant de collection du dépôt. La définition d'un identifiant de collection globalement unique permet aux applications du dépôt d'être partagées sur des systèmes pair-à-pair sans nécessiter de configuration supplémentaire. Si vous exportez vers un dépôt existant, l'identifiant de collection doit correspondre à l'identifiant de collection configuré existant pour ce dépôt.

--subset=SOUS-ENSEMBLE

Marque la validation pour être incluse dans le sous-ensemble nommé. Cela placera la validation dans le résumé du sous-ensemble nommé (en plus de celui principal), permettant aux utilisateurs de voir uniquement ce sous-ensemble au lieu de tout le dépôt.

--arch=ARCH

Spécifie le composant d'architecture de la branche à exporter. Seules les architectures compatibles avec l'hôte peuvent être spécifiées ; voir flatpak --supported-arches pour les valeurs valides.

--exclude=MOTIF

Exclut les fichiers correspondant à MOTIF de la validation. Cette option peut être utilisée plusieurs fois.

--include=MOTIF

N'exclut pas les fichiers correspondant à MOTIF de la validation, même s'ils correspondent aux motifs --exclude. Cette option peut être utilisée plusieurs fois.

--metadata=NOMFICHIER

Utilise le nom de fichier spécifié comme métadonnées dans l'application exportée au lieu du fichier par défaut (nommé metadata). Ceci est utile si vous souhaitez valider plusieurs éléments d'un seul arbre de compilation, généralement utilisé en combinaison avec --files et --exclude.

--files=SOUS-REP

Utilise les fichiers du sous-répertoire spécifié comme contenu de fichier, plutôt que le répertoire de fichiers régulier.

--timestamp=DATE

Utilise la date spécifiée au format ISO 8601 ou NOW, pour l'heure actuelle, dans les métadonnées de validation et, si --update-appstream est utilisé, les données appstream.

--end-of-life=RAISON

Marque la compilation comme en fin de vie. RAISON est un message qui peut être affiché aux utilisateurs installant cette compilation.

--end-of-life-rebase=ID

Marque la compilation comme en fin de vie. Contrairement à --end-of-life, celui-ci prend un ID qui remplace l'actuel. Sur demande de l'utilisateur, les données de l'application peuvent être conservées pour la nouvelle application.

--disable-fsync

Ne synchronise pas lors de l'écriture dans le dépôt. Cela peut entraîner une perte de données dans des situations exceptionnelles, mais peut améliorer les performances lors de l'utilisation de dépôts temporaires ou de test.

--update-appstream

Met à jour la branche appstream après la compilation.

--no-update-summary

Ne met pas à jour le fichier summary après l'ajout de la nouvelle validation. Cela signifie que le dépôt ne sera pas utilisable pour être servi via http jusqu'à ce que build-update-repo ait été exécuté. Ceci est utile si vous souhaitez effectuer plusieurs opérations de dépôt avant de mettre à jour le résumé.

--gpg-sign=IDCLEF

Signe la validation avec cette clé GPG. Cette option peut être utilisée plusieurs fois.

--gpg-homedir=CHEMIN

Répertoire GPG à utiliser lors de la recherche de porte-clés

-r, --runtime

Export un runtime au lieu d'une application (cela utilise le sous-répertoire usr comme fichiers).

-v, --verbose

Affiche les informations de débogage pendant le traitement de la commande.

--ostree-verbose

Affiche les informations de débogage OSTree pendant le traitement de la commande.

EXEMPLES

$ flatpak build-export ~/repos/gnome-calculator/ ~/build/gnome-calculator/ org.gnome.Calculator
