VALEUR RENVOYÉE

En cas de succès, fsconfig() renvoie 0. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Si une erreur se produit, le pilote du système de fichiers peut fournir des informations supplémentaires sur l'erreur via l'interface de récupération de messages pour les contextes de configuration du système de fichiers. Ces informations supplémentaires peuvent être récupérées à tout moment en appelant read(2) sur l'instance du système de fichiers ou le contexte de configuration du système de fichiers référencé par le descripteur de fichier fd. (Voir la sous-section « Interface de récupération de messages » dans fsopen(2) pour plus de détails sur le format des messages.)

Même après qu'une erreur s'est produite, le contexte de configuration du système de fichiers n'est pas invalidé, et peut donc toujours être utilisé avec d'autres fsconfig() commandes. Cela signifie que les utilisateurs peuvent tester le support des paramètres du système de fichiers paramètre par paramètre, et ajuster les paramètres qu'ils souhaitent définir.

Les valeurs d'erreur données ci-dessous résultent d'erreurs indépendantes du type de système de fichiers. Chaque type de système de fichiers peut avoir ses propres erreurs spéciales et son propre comportement spécial. Voir le code source du noyau Linux pour plus de détails.

NOTES

Paramètres génériques du système de fichiers

Chaque pilote de système de fichiers est responsable de l'analyse de la plupart des paramètres spécifiés avec fsconfig(), ce qui signifie que les systèmes de fichiers individuels peuvent avoir un comportement très différent lorsqu'ils rencontrent des paramètres portant le même nom. En général, vous ne devriez pas supposer que le comportement de fsconfig() lors de la spécification d'un paramètre pour un type de système de fichiers correspondra au comportement du même paramètre avec un type de système de fichiers différent.

Cependant, les paramètres génériques suivants s'appliquent à tous les systèmes de fichiers et ont un comportement unifié. Ils sont définis en utilisant la commande FSCONFIG_SET_* listée.

roetrw(FSCONFIG_SET_FLAG)
Configure si l'instance du système de fichiers est en lecture seule.
dirsync(FSCONFIG_SET_FLAG)
Rend les modifications de répertoire sur cette instance de système de fichiers synchrones.
syncetasync(FSCONFIG_SET_FLAG)
Configure si les écritures sur cette instance de système de fichiers seront faites de manière synchrone (comme si le drapeau O_SYNC de open(2) était spécifié pour toutes les ouvertures de fichiers dans cette instance de système de fichiers).
lazytimeetnolazytime(FSCONFIG_SET_FLAG)
Configure si les mises à jour sur disque des horodatages d'inode sur cette instance de système de fichiers doivent être réduites (comme décrit dans la section MS_LAZYTIME de mount(2)).
mandetnomand(FSCONFIG_SET_FLAG)
Configure si l'instance du système de fichiers doit permettre le verrouillage obligatoire. Depuis Linux 5.15, le verrouillage obligatoire a été déprécié et définir ce drapeau est une opération sans effet.
source(FSCONFIG_SET_STRING)
Ce paramètre est équivalent au paramètre source passé à mount(2) pour le même type de système de fichiers, et est généralement le chemin d'accès d'un périphérique bloc contenant le système de fichiers. Ce paramètre ne peut être défini qu'une fois par transaction de contexte de configuration du système de fichiers.

De plus, tous les paramètres de système de fichiers associés aux modules de sécurité Linux (LSM) sont également génériques par rapport au système de fichiers sous-jacent. Voir la documentation du LSM que vous souhaitez configurer pour plus de détails.

Attributs de montage et paramètres du système de fichiers

Certains paramètres de système de fichiers (traditionnellement associés aux options de style mount(8)) ont un attribut de montage associé avec un comportement visible par l'utilisateur superficiellement similaire.

Pour une description de la distinction entre les attributs de montage et les paramètres du système de fichiers, voir la sous-section « Attributs de montage et paramètres du système de fichiers » de mount_setattr(2).

AVERTISSEMENTS

Types de paramètres du système de fichiers

En raison du fait que chaque pilote de système de fichiers est responsable de l'analyse de la plupart des paramètres spécifiés avec fsconfig(), certains pilotes de système de fichiers peuvent avoir un comportement contre-intuitif concernant les FSCONFIG_SET_* commandes autorisées à configurer un paramètre donné.

Pour que les paramètres du système de fichiers soient rétrocompatibles avec mount(2), ils doivent être analysables en chaînes de caractères ; cela signifie presque universellement que FSCONFIG_SET_STRING peut également être utilisé pour les configurer. Cependant, les autres FSCONFIG_SET_* commandes doivent être activées par l'analyseur de paramètres de chaque pilote de système de fichiers.

L'une des instances les plus visibles de cette incohérence est que beaucoup de systèmes de fichiers ne supportent pas la configuration des paramètres de chemin avec FSCONFIG_SET_PATH (malgré le nom), ce qui peut conduire à des erreurs EINVAL quelque peu confuses. (Par exemple, le paramètre générique source —qui est généralement un chemin— ne peut être configuré qu'avec FSCONFIG_SET_STRING.)

Lors de l'écriture de programmes qui utilisent fsconfig() pour configurer des paramètres avec des commandes autres que FSCONFIG_SET_STRING, les utilisateurs devraient vérifier que les FSCONFIG_SET_* commandes utilisées pour configurer chaque paramètre sont supportées par le pilote de système de fichiers correspondant.ver.

EXEMPLES

Pour illustrer les différents types d'indicateurs qui peuvent être configurés avec fsconfig(), voici quelques exemples de création de différents systèmes de fichiers :


int fsfd, mntfd;
fsfd = fsopen("tmpfs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "inode64", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "uid", "1234", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "huge", "never", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "casefold", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NOEXEC);
move_mount(mntfd, "", AT_FDCWD, "/tmp", MOVE_MOUNT_F_EMPTY_PATH);
fsfd = fsopen("erofs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "source", "/dev/loop0", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "acl", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "user_xattr", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE_EXCL, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NOSUID);
move_mount(mntfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Généralement, spécifier plusieurs fois le même paramètre nommé par key avec fsconfig() entraîne le remplacement de la valeur du paramètre. Cependant, certains systèmes de fichiers peuvent avoir un comportement unique :


int fsfd, mntfd;
int lowerdirfd = open("/o/ctr/lower1", O_DIRECTORY | O_CLOEXEC);
fsfd = fsopen("overlay", FSOPEN_CLOEXEC);
/* "lowerdir+" ajoute à la pile des répertoires inférieurs à chaque fois */
fsconfig(fsfd, FSCONFIG_SET_FD, "lowerdir+", NULL, lowerdirfd);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower2", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower3", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower4", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "xino", "auto", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "nfs_export", "off", 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, 0);
move_mount(mntfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Et voici un exemple de la façon dont fspick(2) peut être utilisé avec fsconfig() pour reconfigurer les paramètres d'une instance de système de fichiers existante attachée à /proc :


int fsfd = fspick(AT_FDCWD, "/proc", FSPICK_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "hidepid", "ptraceable", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "subset", "pid", 0);
fsconfig(fsfd, FSCONFIG_CMD_RECONFIGURE, NULL, NULL, 0);
