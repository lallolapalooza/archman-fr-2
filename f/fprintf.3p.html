FPRINTF(3P) Manuel du programmeur POSIX FPRINTF(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

dprintf, fprintf, printf, snprintf, sprintf — écrire une sortie formatée

SYNOPIS

#include <stdio.h>
int dprintf(int fildes, const char *restrict format, ...);
int fprintf(FILE *restrict stream, const char *restrict format, ...);
int printf(const char *restrict format, ...);
int snprintf(char *restrict s, size_t n,
    const char *restrict format, ...);
int sprintf(char *restrict s, const char *restrict format, ...);

DESCRIPTION

À l'exclusion de dprintf() : La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1-2017 s'en remet à la norme ISO C.

La fonction fprintf() place la sortie sur le flux de sortie nommé. La fonction printf() place la sortie sur le flux de sortie standard stdout. La fonction sprintf() place la sortie suivie du octet nul, '\0', dans des octets consécutifs commençant à *s ; il est de la responsabilité de l'utilisateur de s'assurer que suffisamment d'espace est disponible.

La fonction dprintf() est équivalente à la fonction fprintf(), à la différence près que dprintf() écrit la sortie dans le fichier associé au descripteur de fichier spécifié par l'argument fildes plutôt que de placer la sortie sur un flux.

La fonction snprintf() est équivalente à sprintf(), avec l'ajout de l'argument n qui indique la taille du tampon référencé par s. Si n est zéro, rien ne sera écrit et s peut être un pointeur nul. Sinon, les octets de sortie au-delà du (n-1)ème seront rejetés au lieu d'être écrits dans le tableau, et un octet nul sera écrit à la fin des octets effectivement écrits dans le tableau.

Si une copie a lieu entre des objets qui se chevauchent à la suite d'un appel à sprintf() ou snprintf(), les résultats sont indéfinis.

Chacune de ces fonctions convertit, formate et écrit ses arguments sous le contrôle de format. Le format est une chaîne de caractères, commençant et se terminant dans son état de décalage initial, le cas échéant. Le format est composé de zéro ou plusieurs directives : caractères ordinaires, qui sont simplement copiés dans le flux de sortie, et spécifications de conversion, qui entraînent chacune la récupération de zéro ou plusieurs arguments. Les résultats sont indéfinis s'il n'y a pas suffisamment d'arguments pour le format. Si le format est épuisé alors que des arguments subsistent, les arguments excédentaires seront évalués mais ignorés par ailleurs.

Les conversions peuvent être appliquées au n-ième argument après le format dans la liste d'arguments, plutôt qu'au prochain argument non utilisé. Dans ce cas, le caractère spécificateur de conversion % (voir ci-dessous) est remplacé par la séquence "%n$", où n est un entier décimal dans l'intervalle [1,{NL_ARGMAX}], donnant la position de l'argument dans la liste d'arguments. Cette fonctionnalité permet la définition de chaînes de format qui sélectionnent les arguments dans un ordre approprié aux langues spécifiques (voir la section EXEMPLES).

Le format peut contenir soit des spécifications de conversion d'arguments numérotés (c'est-à-dire, "%n$" et "*m$"), soit des spécifications de conversion d'arguments non numérotés (c'est-à-dire, % et *), mais pas les deux. La seule exception est que %% peut être mélangé avec la forme "%n$". Les résultats du mélange de spécifications d'arguments numérotés et non numérotés dans une chaîne de format sont indéfinis. Lorsque des spécifications d'arguments numérotés sont utilisées, la spécification du N-ième argument nécessite que tous les arguments précédents, du premier au (N-1)ème, soient spécifiés dans la chaîne de format.

Dans les chaînes de format contenant la forme "%n$" de spécification de conversion, les arguments numérotés dans la liste d'arguments peuvent être référencés à partir de la chaîne de format autant de fois que nécessaire.

Dans les chaînes de format contenant la forme % de spécification de conversion, chaque spécification de conversion utilise le premier argument non utilisé dans la liste d'arguments.

Toutes les formes des fonctions fprintf() permettent l'insertion d'un caractère radix dépendant de la langue dans la chaîne de sortie. Le caractère radix est défini dans la locale actuelle (catégorie LC_NUMERIC). Dans la locale POSIX, ou dans une locale où le caractère radix n'est pas défini, le caractère radix sera par défaut un <point> ('.').

Chaque spécification de conversion est introduite par le caractère '%' ou par la séquence de caractères "%n$", après quoi apparaissent dans l'ordre :

*
Zéro ou plusieurs indicateurs (dans n'importe quel ordre), qui modifient la signification de la spécification de conversion.
*
Une largeur de champ minimale optionnelle. Si la valeur convertie a moins d'octets que la largeur du champ, elle sera remplie avec des caractères <espace> par défaut à gauche ; elle sera remplie à droite si l'indicateur de justification à gauche ('-'), décrit ci-dessous, est appliqué à la largeur du champ. La largeur du champ prend la forme d'un <astérisque> ('*'), décrite ci-dessous, ou d'un entier décimal.
*
Une précision optionnelle qui donne le nombre minimum de chiffres à apparaître pour les spécificateurs de conversion d, i, o, u, x et X ; le nombre de chiffres à apparaître après le caractère radix pour les spécificateurs de conversion a, A, e, E, f et F ; le nombre maximum de chiffres significatifs pour les spécificateurs de conversion g et G ; ou le nombre maximum d'octets à imprimer à partir d'une chaîne dans les spécificateurs de conversion s et S. La précision prend la forme d'un <point> ('.') suivi soit d'un <astérisque> ('*'), décrit ci-dessous, soit d'une chaîne de chiffres décimaux optionnelle, où une chaîne de chiffres nulle est traitée comme zéro. Si une précision apparaît avec tout autre spécificateur de conversion, le comportement est indéfini.
*
Un modificateur de longueur optionnel qui spécifie la taille de l'argument.
*
Un caractère spécificateur de conversion qui indique le type de conversion à appliquer.

Une largeur de champ, ou une précision, ou les deux, peuvent être indiquées par un <astérisque> ('*'). Dans ce cas, un argument de type int fournit la largeur du champ ou la précision. Les applications doivent s'assurer que les arguments spécifiant la largeur du champ, ou la précision, ou les deux, apparaissent dans cet ordre avant l'argument, le cas échéant, à convertir. Une largeur de champ négative est traitée comme un indicateur '-' suivi d'une largeur de champ positive. Une précision négative est traitée comme si la précision était omise. Dans les chaînes de format contenant la forme "%n$" de spécification de conversion, une largeur de champ ou une précision peut être indiquée par la séquence "*m$", où m est un entier décimal dans l'intervalle [1,{NL_ARGMAX}] donnant la position dans la liste d'arguments (après l'argument format) d'un argument entier contenant la largeur du champ ou la précision, par exemple :

printf("%1$d:%2$.*3$d:%4$.*3$d\n", hour, min, precision, sec);
