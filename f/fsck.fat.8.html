DESCRIPTIO

N

fsck.fat vérifie la cohérence des systèmes de fichiers MS-DOS et tente éventuellement de les

réparer.

Les problèmes de système de fichiers suivants peuvent être corrigés (dans cet ordre)

:
  • La FAT contient des numéros de grappes invalides. La grappe est changée en
    • EOF.
  • La chaîne de grappes d'un fichier contient une boucle. La boucle est
    • rompue.
  • Mauvaises grappes (erreurs de lecture). Les grappes sont marquées comme mauvaises et elles sont supprimées des fichiers qui les possèdent. Cette vérification est
    • facultative.
  • Répertoires contenant un grand nombre d'entrées mauvaises (probablement corrompus). Le répertoire peut être
    • supprimé.
  • Les fichiers . et .. ne sont pas des répertoires. Ils peuvent être supprimés ou
    • renommés.
  • Répertoires . et .. dans le répertoire racine. Ils sont
    • supprimés.
  • Noms de fichiers invalides. Ils peuvent être
    • renommés.
  • Entrées de répertoire en double. Elles peuvent être supprimées ou
    • renommées.
  • Répertoires avec un champ de taille non nul. La taille est mise à
    • zéro.
  • Le répertoire . ne pointe pas vers le répertoire parent. Le pointeur de départ est
    • ajusté.
  • Le répertoire .. ne pointe pas vers le parent du répertoire parent. Le pointeur de départ est
    • ajusté.
  • . et .. ne sont pas les deux premières entrées d'un répertoire non racine. Les entrées sont créées, en déplaçant les emplacements occupés si
    • nécessaire.
  • Le numéro de grappe de départ d'un fichier est invalide. Le fichier est
    • tronqué.
  • Le fichier contient des grappes mauvaises ou libres. Le fichier est
    • tronqué.
  • La chaîne de grappes du fichier est plus longue que ce qu'indiquent les champs de taille. Le fichier est
    • tronqué.
  • Deux fichiers ou plus partagent les mêmes grappes. Tous les fichiers sauf un sont tronqués. Si le fichier tronqué est un fichier répertoire qui a déjà été lu, la vérification du système de fichiers est redémarrée après la
    • troncature.
  • La chaîne de grappes du fichier est plus courte que ce qu'indiquent les champs de taille. Le fichier est
    • tronqué.
  • L'étiquette de volume dans le répertoire racine ou l'étiquette dans le secteur d'amorçage est invalide. Les étiquettes invalides sont
    • supprimées.
  • L'étiquette de volume dans le répertoire racine et l'étiquette dans le secteur d'amorçage sont différentes. L'étiquette de volume du répertoire racine est copiée dans le secteur
    • d'amorçage.
  • Les grappes sont marquées comme utilisée
    • s mais n'appartiennent à aucun fichier.
Elles sont marquées comme libres.

Quand fsck.fat vérifie un système de fichiers, il accumule toutes les modifications en mémoire et ne les effectue qu'après que toutes les vérifications sont terminées. Cela peut être désactivé avec l'option -w

.

Deux variantes différentes du système de fichiers FAT sont prises en charge. Le standard est les systèmes de fichiers FAT12, FAT16 et FAT32 tels que définis par Microsoft et largement utilisés sur les disques durs et les supports amovibles comme les clés USB et les cartes SD. L'autre est la variante Atari héritée utilisée sur Atari

ST.

Il y a quelques différences mineures dans le format Atari : certains champs du secteur d'amorçage sont interprétés légèrement différemment, et les entrées FAT spéciales pour la fin de fichier et l

a mauvaise grappe peuvent être différentes. Sous MS-DOS, 0xfff8 est utilisé pour la fin de fichier et Atari utilise 0xffff par défaut, mais les deux systèmes reconnaissent toutes les valeurs de 0x
fff8–0xffff comme fin de fichier. MS-DOS utilise seulement 0xfff7 pour les mauvaises grappes, où sur Atari les valeurs 0xfff0–0xfff7 sont à cette fin (mais la valeur standard est toujours 0xfff7).

OPTION

S
-
a
Réparer automatiquement le système de fichiers. Aucune intervention de l'utilisateur n'est nécessaire. Chaque fois qu'il y a plus d'une méthode pour résoudre un problème, l'approche la moins destructive est
utilisée.
-
A
Sélectionner l'utilisation de la variante Atari du système de fichiers FAT si elle n'est pas déjà active, sinon sélectionner le système de fichiers FAT standard. C'est sélectionné par défaut si mkfs.fat est exécuté sur Atari Linux
68k.
-
b
Effectuer une vérification en lecture seule du secteur
d'amorçage.
-c PA

Utiliser la page de code DOS PAGE pour décoder les noms de fichiers courts. Par défaut, la page de code 850 est
utilisée.
-d CHE
MIN
Supprimer le fichier spécifié. Si plus d'un fichier avec ce nom existe, le premier est supprimé. Cette option peut être donnée plus d'une
fois.
-
f
Récupérer les chaînes de grappes inutilisées en fichiers. Par défaut, les grappes inutilisées sont ajoutées à l'espace disque libre sauf en mode automatique (-a)
.
-F NU
M
Spécifier la table FAT NUM pour l'accès au système de fichiers. Par défaut, la valeur 0 est supposée et ensuite la première table FAT non corrompue est choisie. Non corrompue signifie que la table FAT a une première grappe valide. Si la valeur par défaut 0 est utilisée et que toutes les tables FAT sont corrompues, alors fsck.fat abandonne et n'essaie pas de réparer le système de fichiers FAT. Si une valeur NUM non nulle est spécifiée, alors fsck.fat utilise la table FAT NUM pour réparer le système de fichiers FAT. Si la table FAT NUM a une première grappe corrompue, alors fsck.fat la réparera. Dans tous les cas, si le système de fichiers FAT a plus d'une table FAT, le contenu réparé de la table FAT choisie est copié dans les autres tables FAT. Pour réparer une première grappe corrompue, il est requis d'appeler fsck.fat avec une valeur NUM non
nulle.
-
l
Lister les chemins des fichiers en cours de
traitement.
-
n
Mode sans opération : vérifier les erreurs de manière non interactive, mais ne rien écrire dans le système de
fichiers.
-
p
Identique à -a, pour la compatibilité avec les autres
*fsck.
-
r
Réparer le système de fichiers de manière interactive. L'utilisateur est consulté chaque fois qu'il y a plus d'une approche pour corriger une incohérence. C'est le mode par défaut et l'option n'est conservée que pour la compatibilité
ascendante.
-
S
Considérer les noms de fichiers courts (8.3) avec des espaces au milieu comme invalides, comme le faisaient les versions précédentes de ce programme. Bien que de tels noms de fichiers ne soient pas interdits par la spécification FAT, et n'aient jamais été traités comme des erreurs par les outils de vérification de système de fichiers de Microsoft, de nombreux programmes DOS sont incapables de gérer les fichiers avec de tels noms. L'utilisation de cette option peut les rendre accessibles à ces
programmes.
Les noms de fichiers courts qui commencent par un espace sont considérés comme invalides quel que soit le réglage de cette
option.
Les versions précédentes de ce programme traitaient exceptionnellement EA DATA. SF et WP ROOT. SF comme des noms courts valides ; l'utilisation de cette option ne préserve pas cette
exception.
-
t
Marquer les grappes illisibles comme
mauvaises.
-u CHE
MIN
Essayer de désupprimer le fichier spécifié. fsck.fat essaie d'allouer une chaîne de grappes non allouées contiguë commençant par la grappe de départ du fichier désupprimé. Cette option peut être donnée plus d'une
fois.
-
U
Considérer les étiquettes de volume et d'amorçage en minuscules comme invalides et n'autoriser que les caractères en majuscules. De telles étiquettes sont interdites par la spécification FAT, mais elles sont largement utilisées par les outils Linux. De plus, les systèmes MS-DOS et Windows n'ont pas de problèmes pour les lire. Par conséquent, les étiquettes de volume et d'amorçage avec des caractères en minuscules sont autorisées par
défaut.
-
v
Mode verbeux. Génère un peu plus de
sortie.
-
V
Effectuer une passe de vérification. La vérification du système de fichiers est répétée après la première exécution. La deuxième passe ne devrait jamais signaler d'erreurs réparables. Elle peut prendre considérablement plus de temps que la première passe, car la première passe peut avoir généré une longue liste de modifications qui doivent être scannées pour chaque lecture de
disque.
--variant TY
PE
Créer un système de fichiers de variante TYPE. Les valeurs acceptables sont standard et atari (dans toute combinaison de majuscules/minuscules). Voir ci-dessusr DESCRIPTION pour les
différences.
-
w
Écrire les changements sur le disque
immédiatement.
-
y
Identique à -a (réparer automatiquement le système de fichiers) pour la compatibilité avec d'autres outils
fsck.
