DESCRIPTIO

N

La fonctionnalité décrite sur cette page de référence est alignée avec la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 se conforme à la norme ISO

C.

La fonction freopen() doit d'abord tenter de vider le flux associé à stream comme si par un appel à fflush(stream). L'échec de vidage du flux doit être ignoré. Si pathname n'est pas un pointeur nul, freopen() doit fermer tout descripteur de fichier associé à stream. L'échec de fermeture du descripteur de fichier doit être ignoré. Les indicateurs d'erreur et de fin de fichier du flux doivent être

effacés.

La fonction freopen() doit ouvrir le fichier dont le chemin est la chaîne pointée par pathname et associer le flux pointé par stream à celui-ci. L'argument mode doit être utilisé exactement comme dans fopen

().

Le flux d'origine doit être fermé que l'ouverture suivante réussisse ou

non.

Si pathname est un pointeur nul, la fonction freopen() doit tenter de changer le mode du flux à celui spécifié par mode, comme si le nom du fichier actuellement associé au flux avait été utilisé. Dans ce cas, le descripteur de fichier associé au flux n'a pas besoin d'être fermé si l'appel à freopen() réussit. Il est défini par l'implémentation quelles modifications de mode sont autorisées (le cas échéant) et dans quelles

circonstances.

Après un appel réussi à la fonction freopen(), l'orientation du flux doit être effacée, la règle d'encodage doit être effacée, et l'objet mbstate_t associé doit être défini pour décrire un état de conversion

initial.

Si pathname n'est pas un pointeur nul, ou si pathname est un pointeur nul et que le changement de mode spécifié nécessite que le descripteur de fichier associé au flux soit fermé et rouvert, le descripteur de fichier associé au flux rouvert doit être alloué et ouvert comme si par un appel à open() avec les indicateurs suivants

UTILISATION DANS LES

APPLICATIONS

La fonction freopen() est généralement utilisée pour attacher les flux pré-ouverts associés à stdin, stdout et stderr à d'autres

fichiers.

Étant donné que les implémentations ne sont pas tenues de prendre en charge les changements de mode de flux lorsque l'argument pathname est NULL, les applications portables ne peuvent pas compter sur l'utilisation de freopen() pour changer le mode du flux, et l'utilisation de cette fonctionnalité est déconseillée. Cette fonctionnalité a été ajoutée à l'origine à la norme ISO C afin de faciliter le passage de stdin et stdout en mode binaire. Comme un caractère 'b' dans le mode n'a aucun effet sur les systèmes POSIX, cette utilisation de la fonctionnalité est inutile dans les applications POSIX. Cependant, même si le 'b' est ignoré, un appel réussi à freopen(NULL, "wb", stdout) a bien un effet. En particulier, pour les fichiers réguliers, il tronque le fichier et définit l'indicateur de position du fichier du flux au début du fichier. Il est possible que ces effets de bord soient une conséquence non intentionnelle de la manière dont la fonctionnalité est spécifiée dans la norme ISO/IEC 9899:1999, mais sauf si la norme ISO C est modifiée, les applications qui appellent avec succès freopen(NULL, "wb", stdout) se comporteront de manière inattendue sur les systèmes conformes dans des situations telles que

: 
{ appl file1
; appl file
2; } > file3

ce qui entraînera que file3 ne contienne que la sortie de la deuxième invocation de ap

pl
.
