fsmount(2) Manuel des appels système fsmount(2)

NOM

fsmount - instancier un objet de montage à partir d'un contexte de système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mount.h>
int fsmount(int fsfd, unsigned int flags, unsigned int attr_flags);

DESCRIPTION

L'appel système fsmount() fait partie de la suite des fonctionnalités de montage basées sur les descripteurs de fichiers sous Linux.

fsmount() crée un nouvel objet de montage détaché pour la racine de la nouvelle instance de système de fichiers référencée par le descripteur de fichier de contexte du système de fichiers fsfd. Un nouveau descripteur de fichier associé à l'objet de montage détaché est alors retourné. Pour créer un objet de montage avec fsmount(), le processus appelant doit posséder la capacité CAP_SYS_ADMIN.

Le contexte du système de fichiers doit avoir été créé par un appel à fsopen(2), puis une instance de système de fichiers doit avoir été instanciée avec un appel à fsconfig(2) utilisant FSCONFIG_CMD_CREATE ou FSCONFIG_CMD_CREATE_EXCL pour être dans l'état correct pour cette opération (le mode "en attente de montage" selon le jargon des développeurs du noyau). Contrairement à open_tree(2) avec OPEN_TREE_CLONE, fsmount() ne peut être appelé qu'une seule fois dans la durée de vie d'un contexte de système de fichiers pour produire un objet de montage.

Comme pour les descripteurs de fichiers retournés par open_tree(2) appelé avec OPEN_TREE_CLONE, le descripteur de fichier retourné peut alors être utilisé avec move_mount(2), mount_setattr(2), ou d'autres appels système similaires pour effectuer d'autres opérations de montage. Cet objet de montage sera démonté et détruit lorsque le descripteur de fichier sera fermé s'il n'a pas été autrement attaché à un point de montage en appelant move_mount(2). (Notez que l'opération de démontage sur close(2) est paresseuse — semblable à l'appel de umount2(2) avec MNT_DETACH ; toutes les références ouvertes existantes aux fichiers de l'objet de montage continueront de fonctionner, et l'objet de montage ne sera complètement détruit que lorsqu'il cessera d'être utilisé.) Le descripteur de fichier retourné se comporte également comme celui produit par open(2) avec O_PATH, ce qui signifie qu'il peut aussi être utilisé comme argument dirfd pour les appels système "*at()".

flags contrôle la création du descripteur de fichier retourné. Une valeur pour flags est construite en combinant par un OU bit à bit zéro ou plus des constantes suivantes :

FSMOUNT_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour comprendre pourquoi cela peut être utile.

attr_flags spécifie les attributs de montage qui seront appliqués à l'objet de montage créé, sous la forme de drapeaux MOUNT_ATTR_*. Les drapeaux sont interprétés comme si mount_setattr(2) avait été appelé avec attr.attr_set défini à la même valeur que attr_flags. Les drapeaux MOUNT_ATTR_* qui nécessiteraient la spécification de champs supplémentaires dans mount_attr(2type) (comme MOUNT_ATTR_IDMAP) ne sont pas des valeurs de drapeaux valides pour attr_flags.

Si l'opération fsmount() réussit, le contexte du système de fichiers associé au descripteur de fichier fsfd est réinitialisé et placé en mode de reconfiguration, comme s'il venait d'être retourné par fspick(2). Vous pouvez continuer à utiliser fsconfig(2) avec le contexte du système de fichiers maintenant réinitialisé, y compris en émettant la commande FSCONFIG_CMD_RECONFIGURE pour reconfigurer l'instance du système de fichiers.

VALEUR DE RETOUR

En cas de succès, un nouveau descripteur de fichier est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EBUSY
Le contexte du système de fichiers associé à fsfd n'est pas dans l'état correct pour être utilisé par fsmount().
EINVAL
flags contenait un drapeau invalide.
EINVAL
attr_flags contenait un drapeau invalide de type MOUNT_ATTR_*.
EMFILE
Le processus appelant a trop de fichiers ouverts pour en créer davantage.
ENFILE
Le système a trop de fichiers ouverts pour en créer davantage.
ENOSPC
L'espace de noms de montage "anonyme" nécessaire pour contenir le nouvel objet de montage n'a pas pu être alloué, car cela aurait dépassé la limite configurée par utilisateur sur le nombre d'espaces de noms de montage dans l'espace de noms utilisateur courant. (Voir aussi namespaces(7).)
ENOMEM
Le noyau n'a pas pu allouer suffisamment de mémoire pour terminer l'opération.
EPERM
Le processus appelant ne possède pas la capacité requise CAP_SYS_ADMIN.

NORMES

Linux.

HISTORIQUE

Linux 5.2. glibc 2.36.

EXEMPLES


int fsfd, mntfd, tmpfd;
fsfd = fsopen("tmpfs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC,
                MOUNT_ATTR_NODEV | MOUNT_ATTR_NOEXEC);
/* Créer un nouveau fichier sans attacher l'objet de montage */
tmpfd = openat(mntfd, "tmpfile", O_CREAT | O_EXCL | O_RDWR, 0600);
unlinkat(mntfd, "tmpfile", 0);
/* Attacher l'objet de montage à "/tmp" */
move_mount(mntfd, "", AT_FDCWD, "/tmp", MOVE_MOUNT_F_EMPTY_PATH);

VOIR AUSSI

fsconfig(2), fsopen(2), fspick(2), mount(2), mount_setattr(2), move_mount(2), open_tree(2), mount_namespaces(7)
