DESCRIPTIO

N

La fonction fmemopen() ouvre un flux qui autorise l'accès spécifié par mode. Le flux permet d'effectuer des entrées/sorties sur la chaîne ou le tampon mémoire pointé par buf

.

L'argument mode spécifie la sémantique des entrées/sorties sur le flux et est l'une des valeurs suivantes

:
r
Le flux est ouvert en
lecture.
w
Le flux est ouvert en
écriture.
a
Ajout ; ouvre le flux en écriture, la position initiale du tampon étant définie sur le premier octet
nul.
r
+
Ouvre le flux en lecture et en
écriture.
w
+
Ouvre le flux en lecture et en écriture. Le contenu du tampon est tronqué (c'est-à-dire que '\0' est placé dans le premier octet du tampon)
.
a
+
Ajout ; ouvre le flux en lecture et en é
criture, la position initiale du tampon
étant définie sur le premier octet nul.

Le flux maintient la notion de position courante, l'emplacement où la prochaine opération d'entrée/sortie sera effectuée. La position courante est mise à jour implicitement par les opérations d'entrée/sortie. Elle peut être mise à jour explicitement à l'aide de fseek(3), et déterminée à l'aide de ftell(3). Dans tous les modes autres que l'ajout, la position initiale est définie au début du tampon. En mode ajout, si aucun octet nul n'est trouvé dans le tampon, la position initiale est size+1

.

Si buf est spécifié comme NULL, alors fmemopen() alloue un tampon de size octets. Cela est utile pour une application qui souhaite écrire des données dans un tampon temporaire puis les relire. La position initiale est définie au début du tampon. Le tampon est automatiquement libéré lorsque le flux est fermé. Notez que l'appelant n'a aucun moyen d'obtenir un pointeur vers le tampon temporaire alloué par cet appel (mais voir open_memstream(3))

.

Si buf n'est pas NULL, alors il doit pointer vers un tampon d'au moins size octets alloué par

l'appelant.

Lorsqu'un flux ouvert en écriture est vidé (fflush(3)) ou fermé (fclose(3)), un octet nul est écrit à la fin du tampon s'il y a de la place. L'appelant doit s'assurer qu'un octet supplémentaire est disponible dans le tampon (et que size compte cet octet) pour permettre

cela.

Dans un flux ouvert en lecture, les octets nuls ('\0') dans le tampon ne provoquent pas le retour d'une indication de fin de fichier par les opérations de lecture. Une lecture depuis le tampon n'indiquera la fin de fichier que lorsque la position courante du tampon avance de size octets au-delà du début du

tampon.

Les opérations d'écriture ont lieu soit à la position courante (pour les modes autres que l'ajout), soit à la taille courante du flux (pour les modes d'ajout)

.

Les tentatives d'écrire plus de size octets dans le tampon entraînent une erreur. Par défaut, de telles erreurs ne seront visibles (par l'absence de données) que lorsque le tampon stdio est vidé. Désactiver la mise en tampon avec l'appel suivant peut être utile pour détecter les erreurs au moment d'une opération de sortie

: 


setbuf(
stream,
NULL);

HISTORIQU

E

glibc 1.0.x. POSIX.

1-2008.

POSIX.1-2008 spécifie que 'b' dans mode doit être ignoré. Cependant, le Correctif Technique 1 ajuste la norme pour permettre un traitement spécifique à l'implémentation pour ce cas, permettant ainsi le traitement de 'b' par

glibc.

Avec glibc 2.22, le mode binaire (voir ci-dessous) a été supprimé, de nombreux bugs anciens dans l'implémentation de fmemopen() ont été corrigés, et un nouveau symbole versionné a été créé pour cette

interface.

Mode

binaire

De glibc 2.9 à glibc 2.21, l'implémentation glibc de fmemopen() prenait en charge un mode « binaire », activé en spécifiant la lettre 'b' comme deuxième caractère dans mode. Dans ce mode, les écritures n'ajoutent pas implicitement un octet nul de fin, et fseek(3) SEEK_END est relatif à la fin du tampon (c'est-à-dire la valeur spécifiée par l'argument size), plutôt qu'à la longueur actuelle de la

chaîne.

Un bug d'API a affecté l'implémentation du mode binaire : pour spécifier le mode binaire, le 'b' doit être le deuxième caractère dans mode. Ainsi, par exemple, "wb+" a l'effet désiré, mais "w+b" non. Cela est incohérent avec le traitement de mode par fopen(

3).

Le mode binaire a été supprimé dans glibc 2.22 ; un 'b' spécifié dans mode n'a

aucu
n ef
fet.

ANOMALI

ES

Avant glibc 2.22, si size est spécifié comme zéro, fmemopen() échoue avec l'erreur EINVAL. Il serait plus cohérent si ce cas créait avec succès un flux qui renverrait ensuite la fin de fichier à la première tentative de lecture ; depuis glibc 2.22, l'implémentation glibc fournit ce

comportement.

Avant glibc 2.22, la spécification du mode d'ajout ("a" ou "a+") pour fmemopen() définit la position initiale du tampon sur le premier octet nul, mais (si la position courante est réinitialisée à un emplacement autre que la fin du flux) n'oblige pas les écritures ultérieures à s'ajouter à la fin du flux. Ce bug est corrigé dans glibc 2.

22.

Avant glibc 2.22, si l'argument mode de fmemopen() spécifie l'ajout ("a" ou "a+"), et que l'argument size ne couvre pas un octet nul dans buf, alors, selon POSIX.1-2008, la position initiale du tampon devrait être définie sur l'octet suivant la fin du tampon. Cependant, dans ce cas, glibc fmemopen() définit la position du tampon à -1. Ce bug est corrigé dans glibc 2.

22.

Avant glibc 2.22, lorsqu'un appel à fseek(3) avec une valeur whence de SEEK_END était effectué sur un flux créé par fmemopen(), le décalage était soustrait de la position de fin de flux, au lieu d'y être ajouté. Ce bug est corrigé dans glibc 2.

22.

L'ajout du mode « binaire » pour fmemopen() dans glibc 2.9 a silencieusement changé l'ABI : auparavant, fmemopen() ignorait 'b' dans mo

de
.

EXEMPLE

S

Le progrci-dessous utilise fmemopen() pour ouvrir un tampon d'entrée, et open_memstream(3) pour ouvrir un tampon de sortie à taille dynamique. Le programme parcourt sa chaîne d'entrée (prise du premier argument de la ligne de commande du programme) en lisant des entiers, et écrit les carrés de ces entiers dans le tampon de sortie. Un exemple de sortie produite par ce programme est le suivant

: 


$ ./a.out '1 23 43'
size=11; ptr=1 529
1849

Programme

source 
#define _GNU_SOURCE
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    FILE *out, *in;
    int v, s;
    size_t size;
    char *ptr;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s '<num>...'\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    in = fmemopen(argv[1], strlen(argv[1]), "r");
    if (in == NULL)
        err(EXIT_FAILURE, "fmemopen");
    out = open_memstream(&ptr, &size);
    if (out == NULL)
        err(EXIT_FAILURE, "open_memstream");
    for (;;) {
        s = fscanf(in, "%d", &v);
        if (s <= 0)
            break;
        s = fprintf(out, "%d ", v * v);
        if (s == -1)
            err(EXIT_FAILURE, "fprintf");
    }
    fclose(in);
    fclose(out);
    printf("size=%zu; ptr=%s\n", size, ptr);
    free(ptr);
    exit(EXIT_SUCCESS)
;
}
