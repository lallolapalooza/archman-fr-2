DESCRIPTIO

N

fsync() transfère (« vide ») toutes les données modifiées en mémoire de (c'est-à-dire les pages modifiées du cache tampon pour) le fichier auquel fait référence le descripteur de fichier fd vers le périphérique de disque (ou tout autre périphérique de stockage permanent) afin que toutes les informations modifiées puissent être récupérées même si le système plante ou redémarre. Cela inclut l'écriture directe ou le vidage d'un cache de disque s'il y en a un. L'appel se bloque jusqu'à ce que le périphérique signale que le transfert est

terminé.

En plus de vider les données du fichier, fsync() vide également les métadonnées associées au fichier (voir inode(7))

.

Appeler fsync() ne garantit pas nécessairement que l'entrée du répertoire contenant le fichier a également atteint le disque. Pour cela, un fsync() explicite sur un descripteur de fichier pour le répertoire est également

nécessaire.

fdatasync() est similaire à fsync(), mais ne vide pas les métadonnées modifiées à moins que ces métadonnées ne soient nécessaires pour qu'une récupération ultérieure de données puisse être correctement traitée. Par exemple, les modifications de st_atime ou st_mtime (respectivement, heure du dernier accès et heure de la dernière modification ; voir inode(7)) ne nécessitent pas de vidage car elles ne sont pas nécessaires pour qu'une lecture ultérieure de données soit correctement traitée. En revanche, une modification de la taille du fichier (st_size, comme effectuée par exemple par ftruncate(2)) nécessiterait un vidage des

métadonnées.

Le but de fdatasync() est de réduire l'activité du disque pour les applications qui n'o

nt pas besoin que toutes les métadonnées
soient synchronisées avec le disque.
