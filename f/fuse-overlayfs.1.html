NOM

fuse-overlayfs - Implémentation FUSE d'overlayfs

SYNOPSIS

montage
fuse-overlayfs [-f] [--debug] [-o OPTS] POINT_DE_MONTAGE

démontage
fusermount -u point_de_montage

DESCRIPTION

fuse-overlayfs fournit une implémentation FUSE d'overlayfs afin qu'elle puisse être utilisée depuis Linux 4.18 par des utilisateurs non privilégiés dans un espace de noms utilisateur.

OPTIONS

--debug Activer le mode de débogage, peut être très verbeux.

-o lowerdir=low1[:low2...] Une liste de répertoires séparés par :. Leur contenu est fusionné.

-o upperdir=upperdir Un répertoire fusionné par-dessus tous les lowerdirs où toutes les modifications apportées au système de fichiers seront écrites.

-o workdir=workdir Un répertoire utilisé en interne par fuse-overlays, doit être sur le même système de fichiers que le répertoire upper.

-o uidmapping=UID:MAPPED-UID:LEN[,UID2:MAPPED-UID2:LEN2] -o gidmapping=GID:MAPPED-GID:LEN[,GID2:MAPPED-GID2:LEN2] Spécifie le mappage dynamique des UID/GID utilisé par fuse-overlayfs lors de la lecture/écriture des fichiers sur le système.

Le mappage dynamique de fuse-overlayfs est une manière alternative et moins coûteuse de faire un chown sur les fichiers de l'hôte pour s'adapter aux paramètres de l'espace de noms utilisateur.

Il est utile de partager le même stockage entre différents espaces de noms utilisateur et de contrer l'effet du mappage effectué par l'espace de noms utilisateur lui-même, et sans nécessiter de chown sur les fichiers.

Par exemple, étant donné sur l'hôte deux fichiers comme :

$ stat -c %u:%g lower/a lower/b 0:0 1:1

Lorsque nous exécutons dans un espace de noms utilisateur avec la configuration suivante : $ cat /proc/self/uid_map
0 1000 1
1 110000 65536

Nous verrions :

$ stat -c %u:%g merged/a merged/b 65534:65534 65534:65534

65534 est l'ID de dépassement utilisé lorsque l'UID/GID n'est pas connu à l'intérieur de l'espace de noms utilisateur. Cela se produit parce que les deux utilisateurs 0:0 et 1:1 ne sont pas mappés.

Dans l'exemple ci-dessus, si nous montons le système de fichiers fuse-overlayfs en utilisant : -ouidmapping=0:1000:1:1:110000:65536,gidmapping=0:1000:1:1:110000:65536, ce qui correspond à la configuration de l'espace de noms spécifiée sur une seule ligne, nous verrions depuis le même espace de noms utilisateur :

$ stat -c %u:%g merged/a merged/b 0:0 1:1

Ce sont les mêmes ID visibles depuis l'extérieur de l'espace de noms utilisateur.

-o squash_to_root Chaque fichier et répertoire appartient à l'utilisateur root (0:0).

-o squash_to_uid=uid -o squash_to_gid=gid Chaque fichier et répertoire appartient à l'uid ou gid spécifié.

Cela a une priorité plus élevée que squash_to_root.

-o static_nlink Définit st_nlink à la valeur statique 1 pour tous les répertoires.

Cela peut être utile pour les systèmes de fichiers à latence plus élevée, tels que NFS, où le comptage du nombre de liens physiques pour un répertoire contenant de nombreux fichiers peut être une opération lente. Avec cette option activée, le nombre de liens physiques signalés lors de l'exécution de stat pour n'importe quel répertoire est de 1.

-o noacl Désactive le support ACL dans le système de fichiers FUSE.
