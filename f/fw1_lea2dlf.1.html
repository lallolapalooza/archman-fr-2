NOM

fw1_lea2dlf - convertit les journaux Check Point FireWall-1 NG en firewall DLF

SYNOPSIS

fw1_lea2dlf fichier

DESCRIPTION

fw1_lea2dlf convertit les journaux Check Point FireWall-1 NG au format firewall DLF. L'entrée de ce convertisseur est la sortie de fw1-loggrabber, un client LEA (Log Export Api) simple.

INSTRUCTIONS D'ACTIVATION

Ce convertisseur DLF n'est pas activé par défaut dans Lire. Il nécessite le module perl Date::Manip et l'outil fw1-loggrabber. Date::Manip peut être installé depuis CPAN. fw1-loggrabber est disponible depuis http://sourceforge.net/projects/fw1-loggrabber .

Si ces deux composants sont installés, vous pouvez activer le convertisseur DLF fw1_lea en décommentant sa ligne dans le fichier @sysconfdir@/@PACKAGE@/address.cf

AUTRES NOTES

Attention ! Si vous obtenez beaucoup d'avertissements se plaignant de caractères UTF-8, ressemblant à :

all all UNSET fw1_lea2dlf warning Malformed UTF-8 character
 (unexpected non-continuation byte 0x7a, immediately after
 start byte 0xe3) at /usr/lib/perl5/vendor_perl/5.8.0/Date/Manip.pm
 line 5931.

, et que votre locale est activée en UTF-8, il existe une solution de contournement : définissez les variables d'environnement LANG et LC_CTYPE à en_US au lieu de par exemple en_US.UTF-8. Vous pouvez le faire temporairement dans l'appel du convertisseur :

LANG=en_US LC_CTYPE=en_US ./fw12dlf < /votre/fichier/de/journal

fw1-loggrabber

fw1-loggrabber est construit à l'aide du Software Development Kit d'OPSEC. OPSEC (Open Platform for Security, http://www.opsec.com/) est un cadre de sécurité ouvert et multi-fournisseurs.

Quelques notes sur fw1-loggrabber citées ici.

1) Prérequis
a) pour exécuter FW1-LOGGRABBER
FW1-LOGGRABBER est lié statiquement et peut donc être
exécuté sur les systèmes suivants :
* Linux (les distributions testées sont Red Hat, SuSE et De-
  bian avec les versions de noyau 2.2.x et 2.4.x)
* Solaris SPARC (les versions testées sont Solaris 8 et 9)
 * Windows NT/2000/XP (actuellement aucune version W32 de FW1-LOGGRABBER
  n'est disponible et n'a donc pas encore été testée)
b) pour compiler FW1-LOGGRABBER
FW1-LOGGRABBER utilise les fonctions de l'API du SDK OPSEC de Checkpoint.
Afin de pouvoir compiler des applications
qui utilisent ce SDK, un environnement de compilation très
spécifique doit être utilisé. Actuellement, la compilation de FW1-LOGGRABBER
n'est prise en charge que pour la plateforme Solaris SPARC et la plateforme
Linux.
* Linux
 - Red Hat 6.2
 - gcc 2.95.1
 - Checkpoint OPSEC SDK NG-FP3 pour Linux 2.2
* Solaris SPARC
 - Solaris 8
 - gcc 2.95.2
 - Checkpoint OPSEC SDK NG-FP3 pour Solaris SPARC
* Windows
 - À MODIFIER
3) Comment l'utiliser
a) Configurer FW1 pour activer le protocole LEA
Afin de pouvoir utiliser cet outil avec une installation Checkpoint
FW-1, les tâches suivantes doivent être effectuées :
* modifier $FWDIR/conf/fwopsec.conf et définir le port
  pour les connexions lea non authentifiées.
    #  lea_server  auth_port   18184
    lea_server       port       50001
* redémarrer FW1 (cpstop / cpstart) pour activer les modifications
* ajouter une règle à la politique pour autoriser les connexions sur le port
  50001 vers le serveur de gestion FW-1
b) Utilisation de FW1-LOGGRABBER
FW1-LOGGRABBER est lié statiquement et n'est donc pas
dépendant des bibliothèques OPSEC. Le binaire peut être exécuté sur
tout système Linux ou Solaris SPARC.
Options en ligne de commande :
 -s             Adresse IP du serveur de gestion FW1
 -p             Port LEA non authentifié du serveur FW1
 -f             Nom exact du fichier journal FW1 ou motif à
                faire correspondre aux fichiers journal FW1.
 --resolve      Résoudre les adresses IP en noms
 --noresolve    Ne pas résoudre les adresses IP en noms
 --showfiles    Afficher uniquement les fichiers journal FW1 disponibles et quitter.
 --debug        Activer le mode debug de FW1-LOGGRABBER
Exemples :
o fw1-loggrabber -s 192.168.2.254 -p 50001 --showfiles

 Afficher tous les fichiers journal disponibles sur le serveur de gestion FW1
 avec l'adresse IP 192.168.2.254. Le port LEA sur lequel le serveur de gestion
 écoute les connexions non authentifiées est 50001.
o fw1-loggrabber -s 192.168.2.254 -p 50001
 Afficher toutes les entrées du fichier journal FW1 par défaut (fw.log)
 sur le serveur de gestion FW1 avec l'adresse IP
 192.168.2.254 et le port LEA 50001.
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f 2003-03-27_213652.log
 Afficher toutes les entrées du fichier journal spécifié. Si le fichier journal
 n'existe pas sur le serveur de gestion FW1 spécifié,
 aucune entrée n'est retournée.
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f 2003-03
 Afficher toutes les entrées de tous les fichiers journal sur le serveur de gestion FW1
 qui contiennent le motif "2003-03", c'est-à-dire tous les fichiers journal
 de mars 2003
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.adtlog
 Afficher toutes les entrées du fichier journal d'audit sur le serveur de gestion FW1

EXEMPLES

Pour traiter un journal tel que produit par FW-1 :

$ fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.log | fw12dlf

fw1_lea2dlf sera rarement utilisé seul, mais est plus susceptible d'être appelé par lr_log2report :

$ fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.log | \
   lr_log2report fw1_lea

BOGUES / À FAIRE

Ce convertisseur nécessite la bibliothèque Date::Manip de perl. Il vaudrait mieux utiliser un autre module pour cela, utilisé par plus de code Lire.

L'état et la licence de fw1-loggrabber sont inconnus.

VOIR AUSSI

Malheureusement, Check Point ne fournit pas de documentation facilement disponible : http://www.checkpoint.com/support/technical/documents/index.html est protégé par mot de passe. Quelques notes sur le produit FireWall-1 se trouvent sur http://www.checkpoint.com/products/protect/firewall-1.html .
