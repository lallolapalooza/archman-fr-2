flockfile(3) Manuel des fonctions de bibliothèque flockfile(3)

NOM

flockfile, ftrylockfile, funlockfile - verrouiller un FICHIER pour stdio

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdio.h>
void flockfile(FILE *filehandle);
int ftrylockfile(FILE *filehandle);
void funlockfile(FILE *filehandle);
Conditions requises pour les macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

Toutes les fonctions montrées ci-dessus :

    /* Depuis glibc 2.24 : */ _POSIX_C_SOURCE >= 199309L
        || /* glibc <= 2.23 : */ _POSIX_C_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Les fonctions stdio sont thread-safe. Ceci est réalisé en attribuant à chaque objet FILE un compteur de verrouillage et (si le compteur de verrouillage est différent de zéro) un thread propriétaire. Pour chaque appel à la bibliothèque, ces fonctions attendent jusqu'à ce que l'objet FILE ne soit plus verrouillé par un autre thread, puis le verrouillent, effectuent l'E/S demandée et déverrouillent à nouveau l'objet.

(Note : ce verrouillage n'a rien à voir avec le verrouillage de fichier effectué par des fonctions comme flock(2) et lockf(3).)

Tout cela est invisible pour le programmeur C, mais il peut y avoir deux raisons de souhaiter un contrôle plus détaillé. D'une part, peut-être qu'une série d'actions d'E/S par un thread appartient ensemble et ne devrait pas être interrompue par les E/S d'un autre thread. D'autre part, peut-être que la surcharge de verrouillage devrait être évitée pour une plus grande efficacité.

À cette fin, un thread peut verrouiller explicitement l'objet FILE, puis effectuer sa série d'actions d'E/S, puis déverrouiller. Cela empêche d'autres threads de s'intercaler. Si la raison pour faire cela était d'atteindre une plus grande efficacité, on effectue les E/S avec les versions sans verrouillage des fonctions stdio : avec getc_unlocked(3) et putc_unlocked(3) au lieu de getc(3) et putc(3).

La fonction flockfile() attend que *filehandle ne soit plus verrouillé par un autre thread, puis fait de ce thread le propriétaire de *filehandle et incrémente le compteur de verrouillage.

La fonction funlockfile() décrémente le compteur de verrouillage.

La fonction ftrylockfile() est une version non bloquante de flockfile(). Elle ne fait rien si un autre thread possède *filehandle, et elle obtient la propriété et incrémente le compteur de verrouillage sinon.

VALEUR DE RETOUR

La fonction ftrylockfile() renvoie zéro en cas de succès (le verrouillage a été obtenu) et une valeur non nulle en cas d'échec.

ERREURS

Aucune.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
flockfile (), ftrylockfile (), funlockfile () Thread safety MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

Ces fonctions sont disponibles lorsque _POSIX_THREAD_SAFE_FUNCTIONS est défini.
