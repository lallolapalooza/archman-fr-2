POURQUOI FISH

?

Fish est un shell de ligne de commande complet (comme bash ou zsh) qui est intelligent et convivial. Fish prend en charge des fonctionnalités puissantes comme la coloration syntaxique, les suggestions automatiques et les complétions par tabulation qui fonctionnent simplement, sans rien apprendre ni

configurer.

Si vous voulez rendre votre ligne de commande plus productive, plus utile e

t plus amusante, sans apprendre une foule de syntaxe ésotérique et d'optio
ns de configuration, alors fish est peut-être exactement ce que vous cherchez !

VARIABLE

S

Comme d'autres shells, un signe dollar suivi d'un nom de variable est remplacé par la valeur de cette variable

> echo My home di
rectory is $HOME
My home directory
is /home/tutorial

C'est ce qu'on appelle la substitution de variable, et cela se produit aussi dans les guillemets doubles, mais pas dans les guillemets simples

: 
> echo "My current directory is $PWD
" My current directory is /home/tuto
rial > echo 'My current directory i
s $PWD' My current directory is $PWD

Contrairement à d'autres shells, fish a une commande ordinaire pour définir des variables : set, qui prend un nom de variable, puis sa

valeur. 
> set name 'M
ister Noodle'
> echo $name
Mister Noodle

(Remarquez les guillemets : sans eux, Mister et Noodle auraient été des arguments séparés, et $name aurait été fait

VARIABLES (SET)

Les variables sont définies avec la commande set. Vous pouvez définir des variables locales, globales ou universelles.

> set myvariable hello
> echo $myvariable
hello

Contrairement à d'autres shells, les variables ne sont pas décomposées davantage après substitution :

> mkdir $name
> ls
Mister Noodle

Dans bash, cela aurait créé deux répertoires « Mister » et « Noodle ». Dans fish, cela n'en a créé qu'un : la variable avait la valeur « Mister Noodle », c'est donc l'argument qui a été passé à mkdir, espaces compris.

Vous pouvez effacer (ou « supprimer ») une variable avec -e ou --erase

> set -e MyVariable
> env | grep MyVariable
(pas de sortie)

Pour en savoir plus, consultez l'expansion de variables <#expand-variable>.

EXPORTS (VARIABLES SHELL)

Parfois, vous avez besoin qu'une variable soit disponible pour une commande externe, souvent comme paramètre. Par exemple, de nombreux programmes comme git ou man lisent la variable $PAGER pour déterminer votre programme de pagination préféré (le programme qui vous permet de faire défiler du texte). D'autres variables utilisées de cette manière incluent $BROWSER, $LANG (pour configurer votre langue) et $PATH. Vous remarquerez que celles-ci sont écrites en MAJUSCULES, mais c'est juste une convention.

Pour transmettre une variable à une commande externe, elle doit être « exportée ». Cela se fait avec un drapeau pour set, soit --export, soit simplement -x.

> set -x MyVariable SomeValue
> env | grep MyVariable
MyVariable=SomeValue

Elle peut également être dés-exportée avec --unexport ou -u.

Cela fonctionne aussi dans l'autre sens ! Si fish est démarré par autre chose, il hérite des variables exportées par son parent. Donc, si votre émulateur de terminal démarre fish, et qu'il exporte $LANG défini sur en_US.UTF-8, fish recevra ce paramètre. Et quoi qu'il en soit, ce qui a démarré votre émulateur de terminal lui a également transmis certaines variables qu'il transmettra ensuite, sauf s'il décide spécifiquement de ne pas le faire. C'est ainsi que fish reçoit généralement les valeurs de choses comme $LANG, $PATH et $TERM, sans que vous ayez à les spécifier à nouveau.

Les variables exportées peuvent être locales, globales ou universelles — « exportée » n'est pas une portée <#variables-scope> ! Habituellement, vous les rendriez globales via set -gx MyVariable SomeValue.

Pour en savoir plus, consultez l'exportation de variables <#variables-export>.

LISTES

La commande set ci-dessus a utilisé des guillemets pour s'assurer que Mister Noodle était un seul argument. S'il y avait eu deux arguments, alors name aurait été une liste de longueur 2. En fait, toutes les variables dans fish sont en réalité des listes, qui peuvent contenir n'importe quel nombre de valeurs, ou aucune.

Certaines variables, comme $PWD, n'ont qu'une seule valeur. Par convention, nous parlons de la valeur de cette variable, mais nous voulons dire sa première (et unique) valeur.

D'autres variables, comme $PATH, ont réellement plusieurs valeurs. Lors de l'expansion de variable, la variable s'étend pour devenir plusieurs arguments :

> echo $PATH
/usr/bin /bin /usr/sbin /sbin /usr/local/bin

Les variables dont le nom se termine par « PATH » sont automatiquement décomposées par des deux-points pour devenir des listes. Elles sont jointes par des deux-points lorsqu'elles sont exportées vers des sous-commandes. Ceci est pour la compatibilité avec d'autres outils, qui attendent que $PATH utilise des deux-points. Vous pouvez également ajouter explicitement cette bizarrerie à une variable avec set --path, ou la supprimer avec set --unpath.

Les listes ne peuvent pas contenir d'autres listes : il n'y a pas de récursion. Une variable est une liste de chaînes, point final.

Obtenez la longueur d'une liste avec count :

> count $PATH
5

Vous pouvez ajouter (ou préfixer) à une liste en définissant la liste sur elle-même, avec des arguments supplémentaires. Ici, nous ajoutons /usr/local/bin à $PATH :

> set PATH $PATH /usr/local/bin

Vous pouvez accéder à des éléments individuels avec des crochets. L'indexation commence à 1 à partir du début et à -1 à partir de la fin :

> echo $PATH
/usr/bin /bin /usr/sbin /sbin /usr/local/bin
> echo $PATH[1]
/usr/bin
> echo $PATH[-1]
/usr/local/bin

Vous pouvez également accéder à des plages d'éléments, connues sous le nom de « tranches » :

> echo $PATH[1..2]
/usr/bin /bin
> echo $PATH[-1..2]
/usr/local/bin /sbin /usr/sbin /bin

Vous pouvez parcourir une liste (ou une tranche) avec une boucle for :

for val in $PATH
  echo "entry: $val"
end
# Affichera :
# entry: /usr/bin/
# entry: /bin
# entry: /usr/sbin
# entry: /sbin
# entry: /usr/local/bin

Un détail particulier est que vous pouvez utiliser des listes comme l'expansion de clé <#expand-brace>. Si vous attachez une autre chaîne à une liste, elle combinera chaque élément de la liste avec la chaîne :

> set mydirs /usr/bin /bin
> echo $mydirs/fish # ceci est juste comme {/usr/bin,/bin}/fish
/usr/bin/fish /bin/fish

Cela signifie également que, si la liste est vide, il n'y aura pas d'argument :

> set empty # pas d'argument
> echo $empty/this_is_gone # affiche une ligne vide

Si vous mettez la liste entre guillemets, elle sera utilisée comme une seule chaîne et vous obtiendrez donc un argument même s'il est vide.

Pour en savoir plus, consultez Listes <#variables-lists>. Pour en savoir plus sur la combinaison de listes avec des chaînes (ou même d'autres listes), consultez les produits cartésiens <#cartesian-product> et l'expansion de variables <#expand-variable>.

WILDCARDS

Fish prend en charge le wildcard familier *. Pour lister tous les fichiers JPEG :

> ls *.jpg
lena.jpg
meena.jpg
santa maria.jpg

Vous pouvez inclure plusieurs wildcards :

> ls l*.p*
lena.png
lesson.pdf

Le wildcard récursif ** recherche les répertoires de manière récursive :

> ls /var/**.log
/var/log/system.log
/var/run/sntp.log

Si cette traversée de répertoire prend beaucoup de temps, vous pouvez l'interrompre avec ctrl-c.

Pour en savoir plus, consultez Wildcards <#expand-wildcard>.

PIPES ET REDIRECTIONS

Vous pouvez rediriger entre commandes avec la barre verticale habituelle :

> echo hello world | wc
      1       2      12

stdin et stdout peuvent être redirigés via les habituels < et >. stderr est redirigé avec un 2>.

> grep fish < /etc/shells > ~/output.txt 2> ~/errors.txt

Pour rediriger stdout et stderr dans un seul fichier, vous pouvez utiliser &> :

> make &> make_output.txt

Pour en savoir plus, consultez les redirections d'entrée et de sortie <#redirects> et les Pipes <#pipes>.

SUBSTITUTIONS DE COMMANDES

Les substitutions de commandes utilisent la sortie d'une commande comme argument pour une autre. Contrairement à d'autres shells, fish n'utilise pas les backticks `` pour les substitutions de commandes. À la place, il utilise des parenthèses avec ou sans dollar :

> echo In (pwd), running $(uname)
In /home/tutorial, running FreeBSD

Une utilisation courante consiste à capturer la sortie d'une commande dans une variable :

> set os (uname)
> echo $os
Linux

Les substitutions de commandes sans dollar ne sont pas développées entre guillemets, la version avec dollar est donc plus simple :

> touch "testing_$(date +%s).txt"
> ls *.txt
testing_1360099791.txt

Contrairement à d'autres shells, fish ne décompose pas les substitutions de commandes sur n'importe quel espace blanc (comme les espaces ou les tabulations), seulement les nouvelles lignes. C'est généralement une grande aide car les commandes unix fonctionnent ligne par ligne. Parfois, cela peut poser problème avec des commandes comme pkg-config qui affichent sur une seule ligne ce qui est censé être plusieurs arguments. Pour le décomposer également par espaces, utilisez string split.

> printf '%s\n' (pkg-config --libs gio-2.0)
-lgio-2.0 -lgobject-2.0 -lglib-2.0
> printf '%s\n' (pkg-config --libs gio-2.0 | string split -n " ")
-lgio-2.0
-lgobject-2.0
-lglib-2.0

Si vous avez besoin que la sortie d'une substitution de commande soit un seul argument, sans aucune décomposition, utilisez une substitution de commande entre guillemets :

> echo "first line
second line" > myfile
> set myfile "$(cat myfile)"
> printf '|%s|' $myfile
|first line
second line|

Pour en savoir plus, consultez Substitution de commande <#expand-command-substitution>.

SÉPARATION DES COMMANDES (POINT-VIRGULE)

Comme les autres shells, fish permet plusieurs commandes soit sur des lignes séparées, soit sur la même ligne.

Pour les écrire sur la même ligne, utilisez le point-virgule (« ; »). Cela signifie que les deux exemples suivants sont équivalents :

echo fish; echo chips
# ou
echo fish
echo chips

C'est utile interactivement pour entrer plusieurs commandes. Dans un script, il est plus facile de lire si les commandes sont sur des lignes séparées.

STATUT DE SORTIE

Lorsqu'une commande se termine, elle renvoie un code de statut sous forme d'entier non négatif (c'est un nombre entier >= 0).

Contrairement à d'autres shells, fish stocke le statut de sortie de la dernière commande dans $status au lieu de $?.

> false
> echo $status
1

Cela indique comment la commande s'est déroulée — 0 signifie généralement le succès, tandis que les autres indiquent des types d'échec. Par exemple, set --query de fish renvoie th

le nombre de variables interrogées qui n'étaient pas définies - set --query PATH renvoie généralement 0, set --query arglbargl boogagoogoo renvoie généralement

2.

Il existe également une liste de variables $pipestatus pour les codes de sortie [1] des processus dans un

pipe.

Pour plus d'informations, voir La variable status <#variables-status>

$PAT

H

$PATH est une variable d'environnement contenant les répertoires dans lesquels fish recherche les commandes. Contrairement aux autres shells, $PATH est une liste, pas une chaîne délimitée par des

deux-points.

Fish prend soin de définir $PATH à une valeur par défaut, mais généralement elle est simplement héritée du processus parent de fish et est définie à une valeur qui a du sens pour le système - voir

Exports.

Pour ajouter /usr/local/bin et /usr/sbin en tête de $PATH, vous pouvez écrire

: 
> set PATH
/usr/loca
l/bin /usr/
sbin $PATH

Pour retirer /usr/local/bin de $PATH, vous pouvez écrire

: 
> set PATH (
string match
-v /usr/loca
l/bin $PATH)

Pour la compatibilité avec les autres shells et les commandes externes, $PATH est une variable de chemin <#variables-path>, et sera donc jointe avec des deux-points (et non des espaces) lorsque vous la citez

: 
> echo "$PATH"
/usr/local/s
bin:/usr/loca
l/bin:/usr/bin

et elle sera exportée ainsi, et lorsque fish démarre, il divise le $PATH qu'il reçoit en une liste sur les

deux-points.

Vous pouvez le faire directement dans config.fish, comme vous le feriez dans d'autres shells avec .profile. Voir cet

exemple.

Une méthode plus rapide est d'utiliser la fonction fish_add_path <>, qui ajoute les répertoires donnés au chemin s'ils n'y sont pas déjà inclus. Elle le fait en modifiant la variable universelle $fish_user_paths, qui est automatiquement ajoutée en tête de $PATH. Par exemple, pour ajouter définitivement /usr/local/bin à votre $PATH, vous pourriez écrire

: 
> fish_a
dd_path
/usr/l
ocal/bin

L'avantage est que vous n'avez pas à vous embêter avec des fichiers : exécutez simplement ceci une fois à la ligne de commande, et cela affectera la session actuelle ainsi que toutes les futures instances. Vous pouvez aussi ajouter cette ligne à config.fish, car elle n'ajoute le composant que si

nécessaire.

Ou vous pouvez modifier $fish_user_paths vous-même, mais vous devriez faire attention à ne pas y ajouter inconditionnellement dans config.f

ish, sinon elle deviend
ra de plus en plus longue.

DÉMARRAGE (OÙ EST .BASHRC ?

)

Fish démarre en exécutant des commandes dans ~/.config/fish/config.fish. Vous pouvez le créer s'il n'existe

pas.

Il est possible de créer directement des fonctions et des variables dans le fichier config.fish, en utilisant les commandes montrées ci-dessus. Par exemple

: 
> cat ~/.config/fish/config.fish
set -x PATH $PATH /s
bin/ functio
n ll ls -
lh $argv end

Cependant, il est plus courant et plus efficace d'utiliser des fonctions de chargement automatique et des variables

universelles.

Si vous souhaitez organiser votre configuration, fish lit également les commandes dans les fichiers .fish dans ~/.config/fish/conf.d/. Voir Fichiers de con

figuration <#configuratio
n> pour plus de détails.

CHARGEMENT AUTOMATIQUE DES

FONCTIONS

Lorsque fish rencontre une commande, il tente de charger automatiquement une fonction pour cette commande, en cherchant un fichier portant le nom de cette commande dans ~/.config/fish/functions/

.

Par exemple, si vous vouliez avoir une fonction ll, vous ajouteriez un fichier texte ll.fish à ~/.config/fish/fu

nctions : 
> cat ~/.config/fi
sh/functions/ll.fi
sh function ll
ls -lh $argv end

C'est la méthode recommandée pour définir votre invite de commande également

: 
> cat ~/.config/fish/fu
nctions/fish_prompt.fis
h function fish_prompt
echo (pwd) "> " end

Voir la documentation de funced <> et funcsave <> pour des façon

s de créer ces fichiers automatiquement, et $fish_function_path
<#syntax-function-autoloading> pour contrôler leur emplacement.

VARIABLES

UNIVERSELLES

Une variable universelle est une variable dont la valeur est partagée entre toutes les instances de fish, maintenant et dans le futur – même après un redémarrage. Vous pouvez rendre une variable universelle avec set -

U : 
> set
-U E
DITO
R vim

Maintenant dans un autre shell

: 
> ec
ho $E
DITOR
vim

Vous n'avez besoin de définir les variables universelles qu'une seule fois de manière i

nteractive. Il n'est pas nécessaire de les ajouter à vos fichiers de configuration <#co
nfiguration>. Pour plus de détails, voir Variables universelles <#variables-universal>.
