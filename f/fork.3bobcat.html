FBB::Fork(3bobcat) Modèle de conception autour de fork(2) FBB::Fork(3bobcat)

NOM

FBB::Fork - Implémente fork(2) en utilisant le modèle de conception Template

SYNOPSIS

#include <bobcat/fork>
Option de liaison : -lbobcat

DESCRIPTION

Les objets FBB::Fork peuvent être utilisés pour implémenter l'appel fork(2) dans le cadre du modèle de conception d'algorithme Template. La classe a été conçue comme une classe de base virtuelle pour les classes implémentant les parties essentielles du processus de fork. La classe est une classe de base virtuelle. Les classes dérivées doivent implémenter les membres childProcess et parentProcess dans le cadre du « Template Method Design Pattern » (voir Gammaet al.

, 1995). Les processus fils qui se terminent envoient des signaux SIGCHLD à leurs parents. La bibliothèque C propose les macros suivantes pour analyser les valeurs de statut reçues par le processus parent lors d'un appel système wait(2) ou waitpid(2)

:
oint WIFEXITED(int status)
:
Cette macro renvoie une valeur non nulle si le processus fils s'est terminé normalement avec « exit » ou « _exit ».
oint WEXITSTATUS(int status)
:Si « WIFEXITED » est vrai pourstatus
, cette macro renvoie les 8 bits de poids faible de la valeur de code de sortie du processus fils.
oint WIFSIGNALED(int status)
:
Cette macro renvoie une valeur non nulle si le processus fils s'est terminé parce qu'il a reçu un signal qui n'a pas été traité.
oint WTERMSIG(int status)
:Si « WIFSIGNALED » est vrai pourstatus
, cette macro renvoie le numéro du signal qui a terminé le processus fils.
oint WCOREDUMP(int status)
:
Cette macro renvoie une valeur non nulle si le processus fils s'est terminé et a produit un core dump.
oint WIFSTOPPED(int status)
:
Cette macro renvoie une valeur non nulle si le processus fils est arrêté.
oint WSTOPSIG(int status)
:Si « WIFSTOPPED » est vrai pourstatus

, cette macro renvoie le numéro du signal qui a causé l'arrêt du processus fils.

FONCTIONS MEMBRES
ovoid fork()
: Effectue le fork réel. Il est implémenté de telle sorte que les processus parent et fils correspondants sont activés à partir de membres virtuels deFork . Si l'opération de fork échoue, une exception FBB::Exception

est levée.

FONCTIONS MEMBRES PROTÉGÉES
oint endChild() const
: Ce membre peut être appelé par parentProcess pour terminer le processus fils. Pour terminer le processus fils, un SIGTERM est envoyé au processus fils, suivi d'un SIGKILL (cf.signal(7) ). Si le processus fils s'est déjà terminé, la valeur de sortie du processus fils est renvoyée, sinon la fin du processus fils est forcée (en appelantkill ) et -2 est renvoyé. Ce membre appelle également waitForChild
(voir ci-dessous).
opid_t pid() const
: Renvoie l'identifiant de processus du fils dans le code du parent (c'est-à-dire dans les membresparent- ci-dessous), et 0 dans le code du fils (c'est-à-dire dans les membreschild- ci-dessous). Le membre pid renvoie -1 lorsqu'il est appelé avant que le membre fork
ait été appelé.
ovoid prepareDaemon() const
: Prépare un processus fils daemon. Cette fonction peut (devrait) être appelée depuis childProcess pour s'assurer que le processus fils change son répertoire de travail courant vers le répertoire racine (/), libérant ainsi les points de montage ; que le processus fils démarre une nouvelle session/groupe de processus pour permettre au parent (chef de groupe) de tuer tous ses processus sans terminer le daemon ; et s'assure que le processus fils ferme et rouvre les flux standards en les associant à /dev/null pour empêcher les entrées/sorties fantômes d'interférer avec les actions du daemon. Une FBB::Exception
est levée si le changement de répertoire vers le répertoire racine échoue.
o void prepareDaemon(std::string const &out, std::string const &err,mode_t mode = 0600) const
:Prépare un processus fils daemon comme la fonction membre précédente, mais permet la redirection des flux de sortie standard (out) et d'erreur standard (err ) vers des fichiers. Spécifiez des chaînes vides pour rediriger ces flux vers/dev/null . Avec des chaînes non vides, les fichiers spécifiés sont ouverts en mode ajout (et créés s'ils n'existent pas encore), par défaut avec le mode 0600 (mode lecture/écriture pour l'utilisateur uniquement). Une FBB::Exception est levée si le changement de répertoire vers le répertoire racine ou si l'utilisation des fichiers spécifiés échoue.
o
int waitForChild() const:
Ce membre peut être appelé par parentProcess pour attendre la fin du processus fils. La valeur de retour (code de sortie) du processus fils est renvoyée sous forme d'une valeur comprise entre 0 et 255. Si le processus fils se termine avant la fin du processus parent, alors waitForChild devrait être appelé pour éviter l'apparition de zombies . Alternativement, le processus parent peut se terminer (par exemple, en utilisant exit(2)) alors que le processus fils est toujours en vie. C'est la façon normale de créer un processus daemon .

FONCTIONS MEMBRES (VIRTUELLES) PRIVÉES

o
virtual void childProcess() = 0:
Ce membre doit être implémenté par les classes dérivées. Il définit les actions effectuées par le processus fils, à la suite de l'appel système fork(2) . Juste avant que childProcess soit appelé, childRedirections (voir ci-dessous) a été exécuté. La fonction childProcess() devrait terminer le processus fils. Une bonne façon de le faire est de lever une exception qui sera capturée par le bloc try de fonction de main(). Terminer un processus en utilisant exit(2) est déconseillé en C++.
o
virtual void childRedirections():
Cette fonction peut être redéfinie dans les classes dérivées pour configurer les redirections nécessaires pour communiquer avec le processus parent. Voir également les classes redirector(3bobcat) et pipe(3bobcat). Par défaut, childRedirections ne fait rien.
o
virtual void parentProcess() = 0:
Ce membre doit être implémenté par les classes dérivées. Il définit les actions sont effectuées par le processus parent, à la suite de fork(2) l'appel système. Juste avant que parentProcess ne soit appelé, parentRedirections (voir ci-dessous) a été exécuté.
Lors de la dérivation de classes à partir de Fork leur implémentation parentProcess gère de préférence toutes les actions à effectuer par le processus parent. Si le processus fils reste actif lorsque le processus parent décide que le programme a rempli ses fonctions (par ex., le processus fils est remplacé par un programme lancé par une fonction exec.. , produit continuellement une sortie, interprétée par le processus parent) alors le processus parent peut appeler endChild pour terminer le processus fils avant de terminer la fonction parentProcess .
o
virtual void parentRedirections():
Cette fonction peut être redéfinie dans les classes dérivées pour configurer les redirections nécessaires pour communiquer avec, par ex., le parent. Voir, par ex., les classes redirector(3bobcat) et pipe(3bobcat). Par défaut, parentRedirections ne fait rien.

EXEMPLES

#include <iostream>
#include <unistd.h>
#include <bobcat/fork>
using namespace std;
using namespace FBB;
class Background: public Fork
{
    public:
        void childProcess()     override;
        void parentProcess()    override;
};
void Background::childProcess()
{
    for (int idx = 0; idx < 3; ++idx)
    {
        cout << "Hello world # " << idx << endl;
        sleep(1);
    }
    throw 0;    // caught in main()
}
void Background::parentProcess()
{
    cout << "Waiting for the child process to end...\n"
            "The child returns value " << waitForChild() << endl;
}
int main()
try
{
    Background bg;
    bg.fork();
    cout << "This is from the parent\n";
}
catch(int x)
{
    cout << "The child terminates with: " << x << endl;
    return x;
}

Voici un exemple plus détaillé :

#include <iostream>
#include <string>
#include <signal.h>
#include <unistd.h>
#include <sys/types.h>
#include <bobcat/pipe>
#include <bobcat/ofdstream>
#include <bobcat/ifdstream>
#include <bobcat/process>
#include <bobcat/fork>
class ChildIO: public FBB::Fork
{
    FBB::Pipe childInput;   // child reads this
    FBB::Pipe childOutput;   // child writes this
    public:
        void childRedirections()    override;
        void childProcess()         override;
        void parentProcess()        override;
};
using namespace std;
using namespace FBB;
void ChildIO::childRedirections()
{
    childInput.readFrom(Redirector::STDIN);
    childOutput.writtenBy(Redirector::STDOUT);
}
void ChildIO::childProcess()
{
        // The /bin/cat program replaces the
        // child process started by Fork::fork()
    Process process(Process::DIRECT, "/bin/cat");
    process.start();
    // this point is never reached
}
void ChildIO::parentProcess()
{
        // Set up the parent’s sides of the pipes
    IFdStream fromChild(childOutput.readOnly());
    OFdStream toChild(childInput.writeOnly());
        // write lines to the child, read its output
    string line;
    while (true)
    {
        cout << "? ";
        line.clear();
        getline(cin, line);
        if (line.empty())
        {
            kill(pid(), SIGTERM);
            break;
        }
        toChild << line << endl;
        getline(fromChild, line);
        cout << "Got: " << line << endl;
    }
    cout << "The child returns value " << waitForChild() << endl;
}
int main()
try
{
    ChildIO io;
    io.fork();
    return 0;
}
catch(exception const &exc)
{
    cerr << "Exception: " << exc.what() << endl;
}
catch(int x)
{
    cout << "The child terminates with: " << x << endl;
    return x;
}
