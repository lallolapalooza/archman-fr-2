NOTES Les appelants ne doivent pas s'attendre à un résultat de tk fontchooser show et ne peuvent pas supposer que la boîte de dialogue a été retirée ou fermée lorsque la commande retourne. Toute interaction de l'utilisateur avec la boîte de dialogue est communiquée à l'appelant via le rappel -command et les événements virtuels <<TkFontchooser*>>. Il dépend de l'implémentation quelles actions exactes de l'utilisateur entraînent l'appel du rappel respectivement l'envoi des événements virtuels. Lorsqu'un bouton Appliquer ou OK est présent dans la boîte de dialogue, ce bouton déclenchera le rappel -command et l'événement virtuel <<TkFontchooserFontChanged>>. Dans certaines implémentations, d'autres actions de l'utilisateur peuvent également avoir cet effet ; sur macOS par exemple, la boîte de dialogue standard de sélection de police

reflète

immédiatement tous les choix de l'utilisateur à l'appelant. En présence de plusieurs widgets destinés à être influencés par la boîte de dialogue de sélection de police, il faut faire attention à gérer correctement les changements de focus : la police sélectionnée dans la boîte de dialogue doit toujours correspondre à la police actuelle du widget ayant le focus, et le rappel -command ne doit agir que sur le widget ayant le focus. La pratique recommandée est de définir les options de configuration -font et -command de la boîte de dialogue de police dans les gestionnaires <FocusIn> par widget (et si nécessaire de les annuler - c'est-à-dire les définir à la chaîne vide - dans les gestionnaires <FocusOut> correspondants). C'est particulièrement important pour les implémenteurs de code de bibliothèque utilisant la boîte de dialogue de sélection de police,

afin

d'éviter les conflits avec le code d'application qui peut également vouloir utiliser la boîte de dialogue. Parce que la boîte de dialogue de sélection de police est globale à l'application, en présence de plusieurs interpréteurs appelant tk fontchooser, seul le rappel -command défini par l'interpréteur qui a le plus récemment appelé tk fontchooser configure ou tk fontchooser show sera invoqué en réponse à une action de l'utilisateur et seul le

-parent

défini par cet interpréteur recevra les événements virtuels <<TkFontchooser*> > . L'implémentation de la boîte de dialogue de police peut ne stocker (et retourner) que les données réelles de la font comme valeur de l'option de configuration -font [[95]]. Cela peut poser problème lorsque -font est défini à une police nommée ; si cette police

proc fontchooserDemo {} {
    wm title . "Font Chooser Demo"
tk fontchooser
configure -parent .
    button .b -command fontchooserToggle -takefocus 0
    fontchooserVisibility .b
    bind .
<<TkFontchooserVisibility>> \
            [list fontchooserVisibility .b]
    foreach w {.t1 .t2} {
        text $w -width 20 -height 4 -borderwidth 1 -relief solid
        bind $w <FocusIn> [list fontchooserFocus $w]
        $w insert end "Text Widget $w"
    }
    .t1 configure -font {Courier 14}
    .t2 configure -font {Times 16}
    pack .b .
    t1 .t2; focus .t1
}
