jfs_fsck(8) Utilitaire JFS - vérification du système de fichiers jfs_fsck(8)

NOM

jfs_fsck - lance la relecture du journal de transactions JFS, et vérifie et répare un périphérique formaté JFS

SYNTAXE

jfs_fsck [ -afnpvV ] [ -j périphérique_journal ] [ --omit_journal_replay ] [ --replay_journal_only ] périphérique

DESCRIPTION

jfs_fsck est utilisé pour rejouer le journal de transactions JFS, vérifier un périphérique formaté JFS pour des erreurs, et corriger toute erreur trouvée.

périphérique est le nom du fichier spécial correspondant au périphérique à vérifier (par exemple /dev/hdb1).

jfs_fsck doit être exécuté en tant que root.

ATTENTION

jfs_fsck ne doit être utilisé que pour vérifier un système de fichiers **non monté** ou un système de fichiers monté en lecture seule. Utiliser jfs_fsck pour vérifier un système de fichiers monté autrement qu'en lecture seule pourrait sérieusement endommager le système de fichiers !

OPTIONS

Si aucune option n'est sélectionnée, le défaut est -p.

-a
Mode de vérification automatique - Rejoue le journal de transactions. Ne continue pas le traitement fsck sauf si l'état agrégé est sale ou si la relecture du journal a échoué. Équivalent fonctionnellement à -p. Le mode de vérification automatique est généralement le mode par défaut lorsque jfs_fsck est appelé au démarrage.
-f
Rejoue le journal de transactions et force la vérification même si le système de fichiers semble propre. Répare automatiquement tous les problèmes.
-j périphérique_journal
Spécifie le périphérique journal.
-n
Ouvre le système de fichiers en lecture seule. Ne rejoue pas le journal de transactions. Signale les erreurs, mais ne les répare pas.
--omit_journal_replay
Omet la relecture du journal de transactions. Cette option ne doit pas être utilisée sauf en dernier recours (c'est-à-dire si le journal a été gravement corrompu et que sa relecture cause d'autres problèmes).
-p
Répare automatiquement ("prépare") le système de fichiers. Rejoue le journal de transactions. Ne continue pas le traitement fsck sauf si l'état agrégé est sale ou si la relecture du journal a échoué. Équivalent fonctionnellement à -a.
--replay_journal_only
Ne rejoue que le journal de transactions. Ne continue pas avec une vérification complète du système de fichiers si la relecture échoue ou si le système de fichiers est toujours sale même après une relecture du journal. En général, cette option ne doit être utilisée qu'à des fins de débogage car elle pourrait laisser le système de fichiers dans un état non montable. Cette option ne peut pas être utilisée avec -f, -n, ou --omit_journal_replay.
-v
Messages verbeux - affiche les détails et les messages de débogage sur stdout.
-V
Affiche les informations de version et quitte (indépendamment de toute autre option choisie).

EXEMPLES

Vérifie la 3ème partition du 2ème disque dur, affiche des informations étendues sur stdout, rejoue le journal de transactions, force une vérification complète de jfs_fsck et autorise la réparation de toutes les erreurs :

jfs_fsck -v -f /dev/hdb3

Vérifie la 5ème partition du 1er disque dur, et signale, mais ne répare pas, les erreurs :

jfs_fsck -n /dev/hda5

CODE DE RETOUR

Le code de retour retourné par jfs_fsck représente l'une des conditions suivantes :

 0
Aucune erreur
 1
Erreurs du système de fichiers corrigées et/ou journal de transactions relu avec succès
 2
Erreurs du système de fichiers corrigées, le système doit être redémarré si le système de fichiers était monté
 4
Erreurs du système de fichiers laissées non corrigées
 8
Erreur opérationnelle
 16
Erreur d'utilisation ou de syntaxe
 128
Erreur de bibliothèque partagée

SIGNALER LES BOGUES

Si vous trouvez un bogue dans JFS ou jfs_fsck, veuillez le signaler via le système de suivi des bogues (section « Signaler les bogues ») du site Web du projet JFS :

http://jfs.sourceforge.net/

Veuillez envoyer autant d'informations pertinentes que possible, y compris la sortie complète de l'exécution de jfs_fsck avec l'option -v sur le périphérique JFS.
