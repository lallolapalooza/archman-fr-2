NOM

fluxbox-style - Un aperçu complet des styles/thèmes pour fluxbox(1).

SYNTAXE

Ce document décrit diverses options disponibles pour les styles fluxbox.

DESCRIPTION

Qu'est-ce qu'un style ?

Les styles, parfois appelés thèmes, sont une superposition graphique pour le gestionnaire de fenêtres fluxbox(1). Si vous vouliez connaître fluxbox, les styles seraient le look de l'apparence générale.

Les styles sont de simples fichiers texte ASCII qui indiquent à fluxbox(1) comment générer l'apparence de différents composants du gestionnaire de fenêtres. L'installation par défaut de fluxbox(1) est fournie avec de nombreux exemples classiques qui montrent une grande partie de ce que l'on peut faire. Pour utiliser l'un des styles standards, naviguez vers le menu Styles système sous votre menu fluxbox(1) principal.

fluxbox(1) utilise sa propre classe graphique pour rendre ses images à la volée. En utilisant des styles, vous pouvez déterminer, avec un grand niveau de configurabilité, à quoi ressemblera votre bureau. Puisque fluxbox(1) est dérivé de blackbox, beaucoup se demandent si les anciens thèmes fonctionneront sur les dernières versions de fluxbox(1). Eh bien, ils fonctionnent globalement, mais vous devrez les ajuster car le code de fluxbox(1) a pas mal changé depuis la copie initiale.

STRUCTURE

Un style est composé de quelques composants majeurs qui ont ensuite leurs propres sous-directives. Les composants majeurs sont les suivants :

Les directives window.* contrôlent l'apparence des cadres de fenêtre, window.tab.* contrôle l'apparence des onglets de fenêtre, menu.* contrôle l'apparence du menu contextuel que vous voyez lorsque vous cliquez avec le bouton droit sur le bureau. toolbar.* est la barre que vous verrez en haut ou en bas de votre écran. Enfin, slit.* a des options que vous pouvez utiliser pour personnaliser l'apparence de la barre d'outils verticale (slit). Cependant, si vous ne définissez pas spécifiquement les directives de la barre d'outils verticale, son apparence est contrôlée par les directives de la barre d'outils à la place.

Pour comprendre comment fonctionne le mécanisme de style, il est utile de connaître un peu le fonctionnement des ressources X11. Les ressources X11 consistent en une clé et une valeur. La clé est construite à partir de plusieurs petites clés (parfois appelées enfants), délimitées par un point (.). Les clés peuvent également contenir un astérisque (*) pour servir de joker, ce qui signifie qu'une ligne de texte correspondra à plusieurs clés. Ceci est utile pour les styles basés sur une ou deux couleurs.

Une référence plus complète à ce sujet se trouve dans X(7), section RESSOURCES.

EMPLACEMENT

Il existe de nombreux endroits pour stocker vos styles, le plus courant étant votre répertoire ~/.fluxbox/styles. L'installation initiale placera les styles par défaut dans /usr/share/fluxbox/styles, fournissant une configuration de base utilisable.

Lorsque vous créez votre propre style, créez un répertoire (normalement le nom de votre style) dans ~/.fluxbox/styles/ (si le répertoire styles n'existe pas, créez-le aussi). Bien qu'il n'y ait pas de structure officielle, il est courant de créer un répertoire portant le nom de votre style et d'y placer votre répertoire de pixmaps (si nécessaire) ainsi qu'un fichier nommé theme.cfg (peut également s'appeler style.cfg). C'est dans ce fichier que vous construirez votre style en utilisant les composants abordés plus loin dans cette page de manuel. Un exemple des étapes suivies lors du démarrage d'un projet de style personnel pourrait ressembler à ceci :

$ cd
$ mkdir -p ~/.fluxbox/styles/VotreStyle/pixmaps
$ cd ~/.fluxbox/styles/VotreStyle
$ nano theme.cfg

La sortie d'un style empaqueté devrait ressembler à ceci :

$ cd
$ tar -tjvf VotreStyle.tar.bz2
 .fluxbox/styles/VotreStyle/theme.cfg
 .fluxbox/styles/VotreStyle/pixmaps
 .fluxbox/styles/VotreStyle/pixmaps/stick.xpm
 ...

Bien sûr, tout cela ne sont que des préférences, fluxbox(1) permet la personnalisation de nombreuses choses, y compris la façon dont vous gérez vos styles. N'oubliez pas, cependant, que si vous prévoyez de distribuer votre style, vous pourriez rencontrer quelques chamailleries communautaires si vous ne suivez pas les pratiques. :)

CRÉER VOTRE STYLE

Comme mentionné ci-dessus, fluxbox(1) vous permet de configurer ses quatre composants principaux : la barre d'outils, les menus, la barre d'outils verticale (slit) et les décorations de fenêtres. Rappelez-vous que vous pouvez personnaliser la barre d'outils verticale avec ses propres directives, sinon elle prendra l'apparence de la barre d'outils principale.

Voici quelques exemples rapides pour illustrer la syntaxe de base :

toolbar.clock.color: green

Ceci définit la ressource de couleur de l'horloge de la barre d'outils à green. Un autre exemple :

menu*color:     rgb:3/4/5

Ceci définit la ressource de couleur du menu et de tous ses enfants à 'rgb:3/4/5'. (Pour une description des noms de couleurs, voir X(1).) Donc, ceci s'applique également à menu.title.color et menu.frame.color. Et avec

*font:  -b&h-lucida-medium-r-normal-*-*-140-*

vous définissez la ressource de police pour toutes les clés à ce nom de police en une seule fois (Pour des informations sur les polices installées sur votre système, vous pouvez utiliser un programme comme xfontsel(1), gtkfontsel, ou xlsfonts(1).)

Dans le dernier exemple, vous remarquerez le joker (*) avant font. Dans un style Fluxbox, vous pouvez définir une valeur avec un joker. L'exemple signifie que chaque police du style sera celle spécifiée. Vous pouvez faire cela avec n'importe quel composant/valeur. Par exemple, si vous vouliez que tout le texte soit d'une seule couleur, vous feriez :

*textColor:  rgb:3/4/5

Cela signifie que vous pouvez configurer un style très simple avec très peu de propriétés. Voir les EXEMPLES ci-dessous pour un exemple concret. fluxbox(1) permet également de remplacer les jokers dans votre style. Prenons notre exemple ci-dessus et ajoutons un remplacement pour le composant toolbar.clock.textColor :

*textColor: rgb:3/4/5
toolbar.clock.textColor: rgb:255/0/0

Avec cela, tout le texte sera rgb:3/4/5 sauf le texte de l'horloge de la barre d'outils qui sera rgb:255/0/0.

Ce qui rend fluxbox(1) si spectaculaire, c'est sa capacité à rendre des textures à la volée. Une texture est un motif de remplissage que l'on voit sur certains styles. Les descriptions de textures sont spécifiées directement à la clé à laquelle elles doivent s'appliquer, par exemple :

toolbar.clock:  Raised Gradient Diagonal Bevel1
toolbar.clock.color:    rgb:8/6/4
toolbar.clock.colorTo:  rgb:4/3/2

Ne vous inquiétez pas, nous allons expliquer ce que cela signifie. Une description de texture se compose de jusqu'à cinq champs, qui sont les suivants :

Flat | Raised | Sunken. donne au composant une apparence plate, en relief ou en creux.

Gradient | Solid. indique à fluxbox(1) de dessiner une couleur unie ou une texture dégradée.

Horizontal | Vertical | Diagonal | Crossdiagonal | Pipecross | Elliptic | Rectangle | Pyramid. Choisissez l'un de ces types de texture. Ils ne fonctionnent que lorsque Gradient est spécifié.

Interlaced. indique à fluxbox(1) d'entrelacer la texture (assombrir une ligne sur deux). Cette option est le plus souvent utilisée avec les textures dégradées, mais elle fonctionne aussi avec les textures unies.

Bevel1 | Bevel2. indique à fluxbox(1) quel type de biseau utiliser. Bevel1 est le biseau par défaut. L'ombrage est placé sur le bord de l'image. Bevel2 est une alternative. L'ombrage est placé à un pixel du bord de l'image.

Au lieu d'une description de texture, l'option ParentRelative est également disponible, ce qui fait que le composant apparaît comme faisant partie de son parent, par exemple totalement transparent.

Ou pour encore plus de possibilités, Pixmap. Si la texture pixmap est spécifiée (cela peut ne pas être nécessaire dans toutes les occasions), le fichier pixmap est spécifié dans une ressource pixmap séparée.

toolbar.clock: pixmap
toolbar.clock.pixmap: clock_background.xpm

Cette fonctionnalité pourrait nécessiter quelques investigations, les rapports indiquent que parfois les ressources color et colorTo doivent être définies et ensuite elles ne le sont peut-être pas.

Toutes les textures dégradées sont composées de deux valeurs de couleur : les ressources color et colorTo. Lorsque Interlaced est utilisé en mode Solid, la ressource colorTo est utilisée pour trouver la couleur d'entrelacement.

ARRIÈRE-PLA

N

Chaque style doit spécifier l'option d'arrière-plan. Si vous ne voulez pas que votre style modifie l'arrière-plan de l'utilisateur, alors utilisez « background: none ». Les options « centered », « aspect », « tiled » et « fullscreen » nécessitent que la ressource « background.pixmap » contienne un nom de fichier valide. L'option « random » nécessite que « background.pixmap » contienne un nom de répertoire valide. Pour ces options, fluxbox(1) appellera fbsetbg(1) pour définir l'arrière-plan. Les options « gradient », « solid » et « mod » nécessitent toutes que « background.color » soit défini. « gradient » et « mod » nécessitent tous deux « background.colorTo ». « mod » nécessite également que « background.modX » et « background.modY » soient définis. Ces options seront passées à fbsetroot(1) pour définir l'arrière-plan. L'option spéciale « unset » est destinée à être utilisée uniquement dans les fichiers de superposition utilisateur. Elle spécifie que fbsetbg ne doit jamais être exécuté (par défaut, même lorsque « none » est défini dans la superposition, fluxbox essaiera d'exécuter « fbsetbg -z » pour restaurer le dernier fond d'écran)

. 
background: centered|aspect|tiled|fullscreen|random|solid|gr
adient <texture>|mod|none|unset background.pixmap: <file or
directory> background.color: <color> background.colorTo: <
color> background.modX: <integer> background.modY: <integer>

EXEMPLES

Cette liste peut sembler intimidante, mais rappelez-vous que lorsque vous créez votre propre style, vous pouvez facilement définir une majorité de ces clés avec un seul composant. Par exemple :

-----------------------------------------
*color: slategrey
*colorTo:       darkslategrey
*unfocus.color: darkslategrey
*unfocus.colorTo:       black
*textColor:     white
*unfocus.textColor:     lightgrey
*font:  lucidasans-10
-----------------------------------------

Cela définit de bons paramètres par défaut pour de nombreux composants.
