NOM

funzip - filtre pour extraire d'une archive ZIP dans un tube

SYNTAXE

funzip [-motdepasse] [entrée[.zip|.gz]]

ARGUMENTS

[-motdepasse]
Mot de passe optionnel à utiliser si l'archive ZIP est chiffrée. Le déchiffrement peut ne pas être pris en charge sur certains sites. Voir DESCRIPTION pour plus de détails.
[entrée[.zip|.gz]]
Spécification optionnelle du fichier archive d'entrée. Voir DESCRIPTION pour les détails.

DESCRIPTION

funzip sans argument de fichier agit comme un filtre ; c'est-à-dire qu'il suppose qu'une archive ZIP (ou un fichier gzip'é(1)) est en cours de transmission via l'entrée standard, et il extrait le premier membre de l'archive vers la sortie standard. Lorsque stdin provient d'un terminal, funzip suppose qu'il ne peut s'agir d'un flux de données compressées (binaires) et affiche un court texte d'aide à la place. S'il y a un argument de fichier, l'entrée est lue à partir du fichier spécifié au lieu de stdin.

Un mot de passe pour les fichiers zip chiffrés peut être spécifié sur la ligne de commande (précédant le nom du fichier, le cas échéant) en préfixant le mot de passe avec un tiret. Notez que cela constitue un risque de sécurité sur de nombreux systèmes ; les processus en cours d'exécution sont souvent visibles via des commandes simples (par exemple, ps(1) sous Unix), et les historiques de commandes peuvent être lus. Si la première entrée du fichier zip est chiffrée et qu'aucun mot de passe n'est spécifié sur la ligne de commande, l'utilisateur est invité à saisir un mot de passe et celui-ci n'est pas affiché sur la console.

Compte tenu de la limitation à l'extraction d'un seul membre, funzip est surtout utile en conjonction avec un programme d'archivage secondaire tel que tar(1). La section suivante contient un exemple illustrant cette utilisation dans le cas de sauvegardes sur bande.

EXEMPLES

Pour utiliser funzip pour extraire le premier fichier membre de l'archive test.zip et le diriger vers more(1):

funzip test.zip | more

Pour utiliser funzip pour tester le premier fichier membre de test.zip (toute erreur sera signalée sur la sortie d'erreur standard) :

funzip test.zip > /dev/null

Pour utiliser zip et funzip à la place de compress(1) et zcat(1) (ou gzip(1L) et gzcat(1L)) pour les sauvegardes sur bande :

tar cf - . | zip -7 | dd of=/dev/nrst0 obs=8k
dd if=/dev/nrst0 ibs=8k | funzip | tar xf -

(où, par exemple, nrst0 est un lecteur de bande SCSI).

BOGUES

Lors de la transmission d'un fichier chiffré à more et en autorisant funzip à demander le mot de passe, le terminal peut parfois être réinitialisé en mode non-écho. Ceci est apparemment dû à une condition de course entre les deux programmes ; funzip passe le terminal en mode non-écho avant que more ne lise son état, et more ``restaure'' ensuite le terminal à ce mode avant de se terminer. Pour récupérer, exécutez funzip sur le même fichier mais redirigez vers /dev/null au lieu de piper vers more ; après avoir redemandé le mot de passe, funzip réinitialisera correctement le terminal.

Il n'y a actuellement aucun moyen d'extraire un membre autre que le premier d'une archive ZIP. Ce serait utile dans le cas où une archive ZIP est incluse dans une autre archive. Dans le cas où le premier membre est un répertoire, funzip crée simplement le répertoire et se termine.

La fonctionnalité de funzip devrait être incorporée dans unzip lui-même (version future).
