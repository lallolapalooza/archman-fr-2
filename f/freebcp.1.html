FREEBCP(1) Manuel des commandes générales FREEBCP(1)

NOM

freebcp — utilitaire de chargement en masse pour les bases de données Sybase et Microsoft

SYNTAXE

freebcp [[⟨base_de_donnees⟩.]⟨schema⟩.]⟨nom_objet⟩ {in | [query]out} fichier_donnees {-c | -n | -f fichier_format} [-S nom_serveur] [-D nom_bdd] [-U nom_utilisateur] [-P mot_de_passe] [-b taille_lot] [-F premiere_ligne] [-L derniere_ligne] [-e fichier_erreurs] [-I fichier_interfaces] [-m erreur_max] [-t delimiteur_champ] [-r delimiteur_ligne] [-h indices] [-T taille_texte] [-A taille_paquet] [-O options] [-i fichier_entree] [-o fichier_sortie] [-C jeu_caracteres] [-EdVv]

DESCRIPTION

freebcp est un programme utilitaire distribué avec FreeTDS. freebcp reproduit (en partie du moins) la fonctionnalité des utilitaires bcp distribués par Sybase et Microsoft. freebcp utilise l'API bcp de DB-Library fournie par FreeTDS. Cette API est également disponible pour les développeurs d'applications.

Les pages de manuel ou l'aide en ligne de Sybase ou SQL Server peuvent être consultées pour plus d'informations sur la fonctionnalité de bcp.

TABLES ET FICHIERS

base_de_donnees
Le nom de la base de données contenant l'objet à copier. Optionnel si la table/vue se trouve dans la base de données par défaut pour nom_utilisateur.
schema
Le schéma de l'objet en cours de copie. Si non fourni, le schéma par défaut pour nom_utilisateur est utilisé.
objet
Le nom de l'objet de base de données auquel vous souhaitez accéder, généralement une table. Il peut également s'agir d'une vue. Toutes les vues peuvent être lues ; certaines peuvent être écrites, sous réserve de contraintes. Avec queryout, objet peut également être une requête SQL.
in
Copier les données d'un fichier hôte vers une table de base de données.
out
Copier les données d'une table de base de données vers un fichier hôte.
queryout
indique que nom_table est en fait une requête SQL, plutôt qu'un objet de base de données. freebcp exécutera la requête et écrira les résultats dans un fichier. (Il est conseillé que la requête retourne un et un seul jeu de résultats.)
fichier_donnees
Le nom d'un fichier système d'exploitation.

OPTIONS

-A taille_paquet
Définit la taille d'un paquet TDS à taille_paquet. Je ne suis pas sûr pourquoi vous voudriez faire cela, sauf à titre expérimental.
-D nom_bdd
Le nom de la base de données par défaut à utiliser. Remplace la base de données par défaut associée au compte de connexion. Demande à freebcp d'émettre une commande USE nom_bdd immédiatement après la connexion, avant de commencer les opérations BCP.
-E
Écrit les données du fichier_donnees dans la colonne IDENTITY de la table. Sans ce drapeau, les données d'identité présentes dans le fichier_donnees seront ignorées, et de nouvelles valeurs IDENTITY seront générées pour les lignes importées.
-F premiere_ligne
La première ligne à copier depuis le fichier d'entrée ou la table de base de données. La valeur par défaut est la première ligne, ligne 1.
-I fichier_interfaces
Le nom et l'emplacement du fichier interfaces à rechercher lors de la connexion au nom_serveur. Remplace freetds.conf.
-L derniere_ligne
La dernière ligne à copier d'un fichier d'entrée ou d'une table de base de données. La valeur par défaut est la dernière ligne.
-O options
Texte SQL pour définir les options de connexion avant l'opération bcp. Si options est un nom de fichier valide, le SQL est lu depuis le fichier à la place. Parfois nécessaire pour queryout. Exemple : -O `SET QUOTED_IDENTIFIER ON'.
-P mot_de_passe
Le mot de passe associé à nom_utilisateur.
-S nom_serveur
Le nom du serveur de base de données auquel se connecter.
-T taille_texte
Pour les colonnes de type texte ou image, définit le nombre maximum de caractères à demander au serveur. Par défaut, la valeur est celle définie dans freetds.conf. Si elle n'est spécifiée nulle part, elle prend par défaut la taille complète des données.
-U nom_utilisateur
Un nom de connexion à la base de données. Pour les connexions TDS 7+, une tentative de connexion de domaine est effectuée si nom_utilisateur n'est pas fourni.
-b taille_lot
Le nombre de lignes par lot de données copiées. La mise en lot ne s'applique que lorsque vous copiez en masse dans la base de données. Chaque lot de données est effectivement « validé » dans la base de données. La valeur par défaut pour taille_lot est 1000.
-c
Le fichier de données hôte est (ou sera) au format « caractère », c'est-à-dire un fichier texte. L'encodage est déterminé par l'attribut charset du client dans freetds.conf.
-d
Désactive toute journalisation. (Contre-intuitif, peut-être.)
-e fichier_erreurs
Écrit les erreurs dans fichier_erreurs. Pour les transferts entrants. Comprend les informations sur la ligne et la colonne, ainsi que les données de la ligne.
-f fichier_format
Le format du fichier de données hôte est décrit par fichier_format. La mise en page de fichier_format est identique à celle comprise par les utilitaires bcp de Sybase et Microsoft, mais elle est trop compliquée pour être décrite ici.
-h indices
Définit les indices bcp. Pour les valeurs valides, voir bcp_options() dans le Manuel de référence de FreeTDS.
-m erreur_max
Arrête après avoir rencontré erreur_max erreurs. Par défaut : 10.
-n
Le fichier de données hôte est au format « natif ». Il s'agit d'un format que freebcp pourra traiter, mais qui n'est ni portable ni lisible.
-r row_te
rm
Le terminateur de ligne pour un fichier caractère. Peut être composé de plus d'un caractère. Par défaut, il s'agit du saut de ligne ('\n'). Cf. -c,
ci-dessus.

rm
Le terminateur de champ pour un fichier caractère. Aussi connu comme délimiteur de colonne. Peut être composé de plus d'un caractère. Par défaut, il s'agit de la tabulation ('\t'). Cf. -c,
ci-dessus.

NOTE

S

Lors de la connexion à un serveur de base de données Sybase, il est requis que le protocole TDS 5.0 soit utilisé. Lors de la connexion à un serveur de base de données Microsoft SQL Server 2000, le protocole TDS 7 (ou ultérieur) est

requis.

Sybase et Microsoft définissent des versions différentes de la partie bcp de TDS 4.2. Comme FreeTDS n'a aucun moyen de savoir à quel type de serveur il est connecté, freebcp ne prend pas en charge la

version 4.2
du protocole TDS.
