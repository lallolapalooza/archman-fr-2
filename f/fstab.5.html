FSTAB(5) Formats de fichiers FSTAB(5)

NOM

fstab - informations statiques sur les systèmes de fichiers

SYNOPSIS

/etc/fstab

DESCRIPTION

Le fichier fstab contient des informations descriptives sur les systèmes de fichiers que le système peut monter. fstab est uniquement lu par les programmes, et non écrit ; il incombe à l'administrateur système de créer et de maintenir correctement ce fichier. L'ordre des enregistrements dans fstab est important car fsck(8), mount(8) et umount(8) parcourent séquentiellement fstab pour effectuer leurs tâches.

Le fichier n'est pas seulement lu par mount(8), mais est souvent utilisé par de nombreux autres outils et démons, et un fonctionnement correct peut nécessiter des étapes supplémentaires. Par exemple, sur les systèmes basés sur systemd, il est recommandé d'utiliser systemctl daemon-reload après une modification de fstab.

Chaque système de fichiers est décrit sur une ligne séparée, avec des champs séparés par des tabulations ou des espaces. La ligne est divisée en champs avant d'être analysée. Cela signifie que tous les espaces ou tabulations dans les champs doivent être échappés en utilisant \040 ou \011, même à l'intérieur de chaînes de caractères entre guillemets (par exemple, LABEL="foo\040bar").

Les lignes commençant par '#' sont des commentaires. Les lignes vides sont ignorées.

Voici un exemple typique d'entrée fstab :

LABEL=t-home2   /home      ext4    defaults,auto_da_alloc      0  2

Le premier champ (fs_spec).

Ce champ décrit le périphérique spécial de bloc, le système de fichiers distant ou l'image de système de fichiers pour le périphérique de boucle à monter, ou le fichier d'échange ou le périphérique d'échange à activer.

Pour les montages ordinaires, il contiendra (un lien vers) un nœud de périphérique spécial de bloc (tel que créé par mknod(2)) pour le périphérique à monter, comme /dev/cdrom ou /dev/sdb7. Pour les montages NFS, ce champ est <hôte>:<répertoire>, par exemple, knuth.aeb.nl:/. Pour les systèmes de fichiers sans stockage, n'importe quelle chaîne peut être utilisée, et apparaîtra dans la sortie de df(1), par exemple. L'usage typique est proc pour procfs ; mem, none, ou tmpfs pour tmpfs. D'autres systèmes de fichiers spéciaux, comme udev et sysfs, ne sont généralement pas listés dans fstab.

LABEL=<label> ou UUID=<uuid> peuvent être donnés à la place d'un nom de périphérique. C'est la méthode recommandée, car les noms de périphériques sont souvent une coïncidence de l'ordre de détection du matériel, et peuvent changer lorsque d'autres disques sont ajoutés ou retirés. Par exemple, 'LABEL=Boot' ou 'UUID=3e6be9de-8139-11d1-9106-a43f08d823a6'. (Utilisez un outil spécifique au système de fichiers comme e2label(8), xfs_admin(8), ou fatlabel(8) pour définir des labels sur les systèmes de fichiers).

Il est également possible d'utiliser PARTUUID= et PARTLABEL=. Ces identifiants de partitions sont pris en charge par exemple pour la table de partition GUID (GPT).

Voir mount(8), blkid(8) ou lsblk(8) pour plus de détails sur les identifiants de périphériques.

Notez que mount(8) utilise les UUID comme chaînes. La représentation en chaîne de l'UUID doit être basée sur des caractères minuscules. Mais lors de la spécification de l'identifiant de volume des systèmes de fichiers FAT ou NTFS, des caractères majuscules sont utilisés (par exemple UUID="A40D-85E7" ou UUID="61DB7756DB7779B3").

Le deuxième champ (fs_file).

Ce champ décrit le point de montage (cible) du système de fichiers. Pour une zone de swap, ce champ doit être spécifié comme `none'. Si le nom du point de montage contient des espaces ou des tabulations, ceux-ci peuvent être échappés en tant que `\040' et `\011' respectivement.

Le troisième champ (fs_vfstype).

Ce champ décrit le type du système de fichiers. Linux prend en charge de nombreux types de systèmes de fichiers : ext4, xfs, btrfs, f2fs, vfat, ntfs, hfsplus, tmpfs, sysfs, proc, iso9660, udf, squashfs, nfs, cifs, et bien d'autres. Pour plus de détails, voir mount(8).

Une entrée swap désigne un fichier ou une partition à utiliser pour le swap, cf. swapon(8). Une entrée none est utile pour les montages de type bind ou move.

Plusieurs types peuvent être spécifiés dans une liste séparée par des virgules.

mount(8) et umount(8) prennent en charge les sous-types de système de fichiers. Le sous-type est défini par le suffixe '.subtype'. Par exemple 'fuse.sshfs'. Il est recommandé d'utiliser la notation de sous-type plutôt que d'ajouter un préfixe au premier champ fstab (par exemple 'sshfs#example.com' est obsolète).

Le quatrième champ (fs_mntops).

Ce champ décrit les options de montage associées au système de fichiers.

Il est formaté comme une liste d'options séparées par des virgules et est facultatif pour mount(8) ou swapon(8). La convention habituelle est d'utiliser au moins le mot-clé "defaults".

Il contient généralement le type de montage (ro ou rw, la valeur par défaut étant rw), ainsi que toute option supplémentaire appropriée au type de système de fichiers (y compris les options d'optimisation des performances). Pour plus de détails, voir mount(8) ou swapon(8).

Les options de base indépendantes du système de fichiers sont :

defaults

utilise les options par défaut. La valeur par défaut dépend du noyau et du système de fichiers. mount(8) n'a pas d'ensemble prédéfini d'options par défaut. La valeur par défaut du noyau est généralement rw, suid, dev, exec, auto, nouser et async.

noauto

ne pas monter lorsque mount -a est donné (par exemple, au démarrage)

user

permettre à un utilisateur de monter

owner

permettre au propriétaire du périphérique de monter

comment

ou x-<nom> destiné aux programmes de gestion de fstab

nofail

ne pas signaler d'erreurs pour ce périphérique s'il n'existe pas.

Le cinquième champ (fs_freq).

Ce champ est utilisé par dump(8) pour déterminer quels systèmes de fichiers doivent être sauvegardés (dumped). La valeur par défaut est zéro (ne pas sauvegarder) si absent.

Le sixième champ (fs_passno).

Ce champ est utilisé par fsck(8) pour déterminer l'ordre dans lequel les vérifications de systèmes de fichiers sont effectuées au démarrage. Le système de fichiers racine doit être spécifié avec un fs_passno de 1. Les autres systèmes de fichiers doivent avoir un fs_passno de 2. Les systèmes de fichiers sur le même disque seront vérifiés séquentiellement, mais les systèmes de fichiers sur différents disques seront vérifiés simultanément pour exploiter le parallélisme disponible dans le matériel. La valeur par défaut est zéro (ne pas vérifier le système de fichiers) si absent.

FICHIERS

/etc/fstab, <fstab.h>

NOTES

La manière correcte de lire les enregistrements de fstab est d'utiliser les routines getmntent(3) ou libmount.

Le mot-clé ignore comme type de système de fichiers (3ème champ) n'est plus pris en charge par la base pure libmount
