NOM

fluxbox-apps - configuration des attributs par fenêtre pour fluxbox(1)

SYNTAXE

~/.fluxbox/apps

SYNTAXE

Les paramètres variables sont affichés en italique : argument

Tous les autres caractères affichés sont requis tels quels. Les espaces blancs ne sont requis que pour délimiter les mots, mais il est acceptable d'en ajouter davantage.

DESCRIPTION

Il est possible de forcer une application à avoir toujours les mêmes dimensions, position et autres paramètres lors de son premier lancement. Ces paramètres sont enregistrés dans le fichier « apps ».

La plupart des paramètres simples peuvent être enregistrés en utilisant le sous-menu « Se souvenir de... » du menu fenêtre, qui peut généralement être ouvert par un clic droit sur la barre de titre. Des fonctionnalités plus avancées nécessitent la modification manuelle du fichier « apps ». Cela peut inclure l'utilisation de SECTIONS DE GROUPEMENT pour configurer des groupes d'onglets de fenêtres automatiques.

Vous n'avez pas besoin de « recharger » fluxbox après avoir modifié le fichier apps, les changements devraient être analysés à nouveau lors de l'ouverture de la prochaine fenêtre.

Le fichier est composé de deux types principaux de sections, les applications et les groupes, détaillés ci-dessous.

SECTIONS D'APPLICATION

Les sections [app] fournissent des paramètres pour des fenêtres d'application individuelles.

Ces sections commencent par une ligne du format

[app](modèle){compte}

Le modèle peut être un ou plusieurs modèles qui correspondent aux fenêtres. Pour plus de détails, voir MODÈLES DE CLIENTS. Si vous spécifiez plus d'un modèle, ils doivent TOUS correspondre pour que les paramètres soient appliqués.

Le {compte} est facultatif. S'il est spécifié, alors l'entrée ne correspondra qu'à un maximum de ce nombre de fenêtres à tout moment. S'il est omis, la valeur par défaut est d'appliquer les paramètres à toutes les fenêtres correspondantes.

Cette ligne d'ouverture [apps] est suivie par un nombre quelconque de paramètres pour l'application. Voir PARAMÈTRES pour plus de détails.

Chacune de ces sections se termine par la ligne unique

[end]

SECTIONS TRANSIENTES

Les sections [transient] fournissent des paramètres pour les « boîtes de dialogue ».

C'est la même chose que la section [app], mais s'applique aux fenêtres transitoires. Les fenêtres transitoires ont une propriété WM_TRANSIENT_FOR. Cela s'appliquera à toutes les boîtes de dialogue modales et à plusieurs autres qui ont un « leader » auquel elles restent au-dessus. Notamment, les boîtes de dialogue d'ouverture/enregistrement entrent dans cette catégorie.

SECTIONS DE GROUPEMENT

Le but principal des sections [group] est de grouper les fenêtres ensemble. Toutes les fenêtres d'un groupe seront automatiquement mises en onglets.

Ces sections commencent par une ligne du format

[group](modèle)

Où l'élément modèle est facultatif. S'il est spécifié, ce modèle doit correspondre pour que le groupe prenne effet. Il est courant d'utiliser des modèles non spécifiques aux fenêtres comme (workspace) ici. Voir MODÈLES DE CLIENTS pour plus de détails.

Ceci est suivi par un nombre quelconque de lignes [app]. Celles-ci ont un format similaire à la section [app] détaillée ci-dessus dans SECTIONS D'APPLICATION, mais ne contiennent aucun paramètre et n'ont pas de ligne [end] associée.

Comme ceci

[app](modèle)

Cette section peut également contenir des paramètres qui sont appliqués à chaque fenêtre du groupe. Voir la section PARAMÈTRES pour les détails.

Comme pour les sections [app], chacune de ces sections se termine par la ligne unique

[end]

PARAMÈTRES

Ces paramètres peuvent être stockés dans le fichier « apps ». Une ligne de paramètre doit apparaître à l'intérieur d'une section [app] ou [group].

Le format général est

[paramètre]{valeur}

Toutes les valeurs autorisées sont décrites ci-dessous, à l'exception de bool qui peut simplement avoir la valeur yes ou no, qui active ou désactive le paramètre associé, respectivement.

[Workspace] {numéro}

Force l'application à s'ouvrir sur le numéro d'espace de travail spécifié. Les espaces de travail sont définis par numéro, en commençant par 0.

[Jump] {bool}

Change l'espace de travail actif à celui mémorisé lorsque l'application est ouverte. Ceci est seulement utile en conjonction avec [Workspace]. Voir EXEMPLES.

[Head] {numéro}

Force l'application à s'ouvrir sur la numéro de tête spécifiée (Xinerama seulement).

[Layer] {numéro}

Spécifie la couche sur laquelle ouvrir la fenêtre (par numéro). Chaque couche a un numéro. Les nommées sont : 2-AboveDock, 4-Dock, 6-Top, 8-Normal, 10-Bottom, 12-Desktop.

[Dimensions] {largeur[%] hauteur[%]}

Ouvre l'application avec la largeur et la hauteur spécifiées, en pixels. Si la valeur est donnée en pourcentage, alors la taille de la fenêtre sera basée sur la taille de l'écran actuel.

[IgnoreSizeHints] {bool}

Certaines applications restreignent le rapport d'aspect, la taille minimale ou maximale des fenêtres. Définir cette clé sur « yes » fera ignorer ces contraintes par fluxbox. NOTEZ que de mauvaises implémentations de clients peuvent dépendre fortement de ces contraintes (en utilisant aveuglément leur géométrie dans des calculs non sauvegardés, provoquant des erreurs de division par zéro, des segfaults, etc.)

[Position] (ancre) {X[%] Y[%]}

Positionne l'application à un endroit particulier. Par défaut, le coin supérieur gauche est placé aux coordonnées de l'écran (X,Y). Si vous spécifiez une ancre, par exemple BottomRight, alors le coin inférieur droit de la fenêtre est positionné à (X,Y) pixels du coin inférieur droit de l'écran. Si la valeur est donnée en pourcentage, alors les coordonnées seront basées sur la taille de l'écran actuel.

ancre peut être réglée sur l'une des valeurs suivantes :

TopLeft Left BottomLeft Top Center Bottom TopRight Right BottomRight

[Deco] {valeur}

Spécifie l'état de décoration. Il existe plusieurs ensembles de valeurs prédéfinis :

NORMAL

Décorations standard

NONE

Aucune décoration

BORDER

Comme NONE sauf que la bordure de la fenêtre X est conservée

TAB

Comme BORDER sauf que les onglets externes (si activés) sont conservés

TINY

Barre de titre avec uniquement un bouton d'iconification

TOOL

Barre de titre seulement

La valeur peut également être un masque de bits pour un contrôle plus fin. Les bits sont, de (1<<0) à (1<<10) : Barre de titre, Poignée/Grips, Bordure, Bouton d'Iconification, Bouton de Maximisation, Bouton de Fermeture, Bouton de Menu, Bouton Collant, Bouton d'Ombrage, Onglets Externes, Focus Activé.

[Shaded] {bool}

Indique si la fenêtre est ombrée (enroulée) ou non.

[Tab] {bool}

Indique si les onglets sont activés pour la fenêtre.

[FocusNewWindow] {bool}

OBSOLÈTE ! Veuillez utiliser FocusProtection « Gain » ou « Refuse » à la place.

Si activé, une nouvelle fenêtre attrapera le focus X dès qu'elle sera ouverte. Si désactivé, une nouvelle fenêtre n'attrapera pas le focus X dès qu'elle sera ouverte.

[FocusProtection] {valeur [,valeur [, ...]] }

Liste des indicateurs de contrôle du focus séparés par des virgules. valeur peut être :

None

Comportement normal

Gain

Une nouvelle fenêtre attrapera le focus X dès qu'elle sera ouverte.

Refuse

Une nouvelle fenêtre n'attrapera pas le focus X dès qu'elle sera ouverte.

Deny

La fenêtre n'est pas autorisée
