FTW(3P) Manuel du programmeur POSIX FTW(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

ftw — parcourir (traverser) une arborescence de fichiers

SYNOPSIS

#include <ftw.h>
int ftw(const char *path, int (*fn)(const char *,
    const struct stat *ptr, int flag), int ndirs);

DESCRIPTION

La ftw() fonction doit descendre récursivement dans la hiérarchie de répertoires enracinée dans path. Pour chaque objet de la hiérarchie, ftw() doit appeler la fonction pointée par fn, en lui passant un pointeur vers une chaîne de caractères terminée par un octet nul contenant le nom de l'objet, un pointeur vers une structure stat contenant des informations sur l'objet, remplie comme si stat() ou lstat() avait été appelée pour récupérer les informations. Les valeurs possibles de l'entier, définies dans l'en-tête <ftw.h> , sont :

FTW_D
Pour un répertoire.
FTW_DNR
Pour un répertoire qui ne peut pas être lu.
FTW_F
Pour un fichier qui n'est pas un répertoire.
FTW_SL
Pour un lien symbolique (mais voir aussi FTW_NS ci-dessous).
FTW_NS
Pour un objet autre qu'un lien symbolique sur lequel stat() n'a pas pu être exécutée avec succès. Si l'objet est un lien symbolique et que stat() a échoué, il n'est pas spécifié si ftw() passe FTW_SL ou FTW_NS à la fonction fournie par l'utilisateur.

Si l'entier est FTW_DNR, les descendants de ce répertoire ne doivent pas être traités. Si l'entier est FTW_NS, la stat structure contient des valeurs indéfinies. Un exemple d'objet qui causerait le passage de FTW_NS à la fonction pointée par fn serait un fichier dans un répertoire avec la permission de lecture mais sans permission d'exécution (recherche).

La ftw() fonction doit visiter un répertoire avant de visiter l'un de ses descendants.

La ftw() fonction doit utiliser au plus un descripteur de fichier pour chaque niveau de l'arborescence.

L'argument ndirs doit être dans l'intervalle [1,{OPEN_MAX}].

La traversée de l'arborescence doit continuer jusqu'à ce que l'arborescence soit épuisée, qu'une invocation de fn retourne une valeur non nulle, ou qu'une erreur, autre que [EACCES], soit détectée à l'intérieur de ftw().

L'argument ndirs doit spécifier le nombre maximal de flux de répertoires ou de descripteurs de fichier, ou les deux, disponibles pour une utilisation par ftw() lors de la traversée de l'arborescence. Lorsque ftw() retourne, elle doit fermer tous les flux de répertoires et descripteurs de fichier qu'elle utilise, sans compter ceux ouverts par la fonction fn fournie par l'application.

Les résultats sont indéterminés si la fonction fn fournie par l'application ne préserve pas le répertoire de travail courant.

La ftw() fonction n'a pas besoin d'être sûre pour les threads.

VALEUR RETOURNÉE

Si l'arborescence est épuisée, ftw() doit retourner 0. Si la fonction pointée par fn retourne une valeur non nulle, ftw() doit arrêter sa traversée de l'arborescence et retourner la valeur retournée par la fonction pointée par fn. Si ftw() détecte une erreur, elle doit retourner -1 et définir errno pour indiquer l'erreur.

Si ftw() rencontre une erreur autre que [EACCES] (voir FTW_DNR et FTW_NS ci-dessus), elle doit retourner -1 et définir errno pour indiquer l'erreur. La variable externe errno peut contenir n'importe quelle valeur d'erreur qui est possible lorsqu'un répertoire est ouvert ou lorsqu'une des fonctions stat est exécutée sur un répertoire ou un fichier.

ERREURS

La ftw() fonction doit échouer si :

EACCES
La permission de recherche est refusée pour n'importe quel composant de path ou la permission de lecture est refusée pour path.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un composant d'un chemin d'accès est plus longue que {NAME_MAX}.
ENOENT
Un composant de path ne nomme pas un fichier existant ou path est une chaîne vide.
ENOTDIR
Un composant de path nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EOVERFLOW
Un champ dans la stat structure ne peut pas être représenté correctement dans l'environnement de programmation courant pour un ou plusieurs fichiers trouvés dans la hiérarchie de fichiers.

La ftw() fonction peut échouer si :

EINVAL
La valeur de l'argument ndirs est invalide.
ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un chemin d'accès dépasse {PATH_MAX}, ou la résolution du chemin d'accès d'un lien symbolique a produit un résultat intermédiaire avec une longueur qui dépasse {PATH_MAX}.

De plus, si la fonction pointée par fn rencontre des erreurs système, errno peut être définie en conséquence.

Les sections suivantes sont informatives.

EXEMPLES

Parcourir une structure de répertoires

L'exemple suivant parcourt la structure de répertoires courante, en appelant la fonction fn pour chaque entrée de répertoire, en utilisant au plus 10 descripteurs de fichier :

#include <ftw.h>
...
if (ftw(".", fn, 10) != 0) {
    perror("ftw"); exit(2);
}

UTILISATION PAR LES APPLICATIONS

La ftw() fonction peut allouer de la mémoire dynamique pendant son fonctionnement. Si ftw() est terminée de force, par exemple par longjmp() ou siglongjmp() exécutée par la fonction pointée par fn ou une routine d'interruption, ftw() n'a pas la possibilité de libérer cette mémoire, donc elle reste allouée de manière permanente. Une façon sûre de gérer les interruptions est de stocker le fait qu'une interruption s'est produite, et d'arranger pour que la fonction pointée par fn retourne une valeur non nulle à sa prochaine invocation.

Les applications devraient utiliser la fonction nftw() au lieu de la fonction obsolète ftw() .

JUSTIFICATION

Aucune.

PERSPECTIVES

La ftw() fonction peut être supprimée dans une version future.
