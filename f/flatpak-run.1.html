NOM

flatpak-run - Exécute une application ou ouvre un shell dans un runtime

SYNTAXE

flatpak run [OPTION...] REF [ARG...]

DESCRIPTION

Si REF nomme une application installée, Flatpak exécute l'application dans un environnement isolé (sandbox). Les arguments supplémentaires sont passés à l'application. La branche et l'architecture actuelles de l'application sont utilisées, sauf indication contraire avec --branch ou --arch. Voir flatpak-make-current(1).

Si REF nomme un runtime, un shell est ouvert dans le runtime. Ceci est utile pour le développement et les tests. S'il y a une ambiguïté quant à la branche à utiliser, vous serez invité à choisir. Utilisez --branch pour éviter cela. L'architecture principale est utilisée, sauf indication contraire avec --arch.

Par défaut, Flatpak recherche d'abord l'application ou le runtime dans l'installation utilisateur, puis dans toutes les installations système. Ceci peut être outrepassé avec les options --user, --system et --installation.

Flatpak crée un environnement isolé pour que l'application s'exécute en montant le runtime approprié sur /usr et un répertoire modifiable sur /var, dont le contenu est conservé entre les exécutions de l'application. L'application elle-même est montée sur /app.

Les détails de l'environnement isolé sont contrôlés par les métadonnées de l'application et diverses options comme --share et --socket qui sont passées à la commande de lancement : l'accès est autorisé si cela a été demandé dans le fichier de métadonnées de l'application ou avec une option, et que l'utilisateur ne l'a pas outrepassé.

Les arguments restants sont passés à la commande qui est exécutée dans l'environnement isolé. Voir l'option --file-forwarding pour la gestion des arguments de fichier.

Les variables d'environnement sont généralement passées à l'application isolée, avec certaines exceptions. Les métadonnées de l'application peuvent outrepasser les variables d'environnement, tout comme l'option --env. Flatpak définit la variable d'environnement FLATPAK_ID à l'ID de l'application exécutée.

Flatpak monte également en lecture seule /etc/os-release (si disponible, ou /usr/lib/os-release en secours) de l'hôte vers /run/host/os-release, conformément à la spécification os-release[1].

Si le contrôle parental est activé, flatpak vérifiera les paramètres de contrôle parental de l'utilisateur actuel, et refusera d'exécuter une application si elle est bloquée pour l'utilisateur actuel.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche les options d'aide et quitte.

-u, --user

Recherche l'application et le runtime dans les installations utilisateur.

--system

Recherche l'application et le runtime dans les installations système globales par défaut.

--installation=NOM

Recherche l'application et le runtime dans l'installation système spécifiée par NOM parmi celles définies dans /etc/flatpak/installations.d/. L'utilisation de --installation=default est équivalente à l'utilisation de --system.

-v, --verbose

Affiche des informations de débogage pendant le traitement de la commande.

--ostree-verbose

Affiche des informations de débogage OSTree pendant le traitement de la commande.

--arch=ARCH

L'architecture à exécuter. Voir flatpak --supported-arches pour les architectures supportées par l'hôte.

--command=COMMANDE

La commande à exécuter à la place de celle listée dans les métadonnées de l'application.

--cwd=DIR

Le répertoire dans lequel exécuter la commande. Notez que cela doit être un répertoire à l'intérieur de l'isolation.

--branch=BRANCH

La branche à utiliser.

-d, --devel

Utilise le runtime devel spécifié dans les métadonnées de l'application au lieu du runtime régulier, et utilise un profil seccomp moins susceptible de casser les outils de développement.

--runtime=RUNTIME

Utilise ce runtime au lieu de celui spécifié dans les métadonnées de l'application. Il s'agit d'un tuple complet, comme par exemple org.freedesktop.Sdk/x86_64/1.2, mais des tuples partiels sont autorisés. Toute partie vide ou manquante est remplie avec les valeurs correspondantes spécifiées par l'application.

--runtime-version=VERSION

Utilise cette version du runtime au lieu de celle spécifiée dans les métadonnées de l'application. Ceci outrepasse toute version spécifiée avec l'option --runtime.

--share=SUBSYSTEME

Partage un sous-système avec la session hôte. Ceci outrepasse la section Contexte des métadonnées de l'application. SUBSYSTEME doit être l'un des éléments suivants : network, ipc. Cette option peut être utilisée plusieurs fois.

--unshare=SUBSYSTEME

Ne partage pas un sous-système avec la session hôte. Ceci outrepasse la section Contexte des métadonnées de l'application. SUBSYSTEME doit être l'un des éléments suivants : network, ipc. Cette option peut être utilisée plusieurs fois.

--socket=SOCKET

Expose un socket bien connu à l'application. Ceci outrepasse la section Contexte des métadonnées de l'application. SOCKET doit être l'un des éléments suivants : x11, wayland, fallback-x11, pulseaudio, system-bus, session-bus, ssh-auth, pcsc, cups, gpg-agent, inherit-wayland-socket. Cette option peut être utilisée plusieurs fois.
