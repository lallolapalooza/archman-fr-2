focus(n) Commandes intégrées Tk focus(n)

NOM

focus - Gérer le focus d'entrée

SYNTAXE

focus
focus fenêtre
focus option ?arg arg ...?

DESCRIPTION

La commande focus est utilisée pour gérer le focus d'entrée de Tk. À tout moment, une fenêtre sur chaque écran est désignée comme la fenêtre de focus ; chaque événement de pression ou de relâchement de touche pour l'écran est envoyé à cette fenêtre. Il appartient normalement au gestionnaire de fenêtres de rediriger le focus parmi les fenêtres de niveau supérieur d'un écran. Par exemple, certains gestionnaires de fenêtres définissent automatiquement le focus d'entrée sur une fenêtre de niveau supérieur lorsque la souris entre en elle ; d'autres redirigent le focus d'entrée uniquement lorsque l'utilisateur clique sur une fenêtre. Généralement, le gestionnaire de fenêtres ne définit le focus que pour les fenêtres de niveau supérieur, laissant à l'application le soin de rediriger le focus parmi les enfants de la fenêtre de niveau supérieur.

Tk se souvient d'une fenêtre de focus pour chaque fenêtre de niveau supérieur (le descendant le plus récent de cette fenêtre de niveau supérieur à recevoir le focus) ; lorsque le gestionnaire de fenêtres donne le focus à une fenêtre de niveau supérieur, Tk la redirige automatiquement vers la fenêtre mémorisée. Dans une fenêtre Tk de niveau supérieur, Tk utilise par défaut un modèle de focus *explicite*. Le déplacement de la souris dans une fenêtre de niveau supérieur ne change normalement pas le focus ; le focus ne change que lorsqu'un widget décide explicitement de réclamer le focus (par exemple, en raison d'un clic sur un bouton), ou lorsque l'utilisateur tape une touche telle que Tab qui déplace le focus.

La procédure Tcl tk_focusFollowsMouse peut être invoquée pour créer un modèle de focus *implicite* : elle reconfigure Tk de manière à ce que le focus soit défini sur une fenêtre chaque fois que la souris y entre. Les procédures Tcl tk_focusNext et tk_focusPrev implémentent un ordre de focus parmi les fenêtres d'une fenêtre de niveau supérieur ; elles sont utilisées dans les liaisons par défaut pour Tab et Shift-Tab, entre autres choses.

La commande focus peut prendre l'une des formes suivantes :

focus
Retourne le nom de chemin de la fenêtre de focus sur l'écran contenant la fenêtre principale de l'application, ou une chaîne vide si aucune fenêtre de cette application n'a le focus sur cet écran. Remarque : il est préférable de spécifier l'écran explicitement à l'aide de -displayof (voir ci-dessous) afin que le code fonctionne dans les applications utilisant plusieurs écrans.
focus fenêtre
Si l'application a actuellement le focus d'entrée sur l'écran de fenêtre, cette commande réinitialise le focus d'entrée pour l'écran de fenêtre à fenêtre et retourne une chaîne vide. Si l'application n'a pas actuellement le focus d'entrée sur l'écran de fenêtre, fenêtre sera mémorisée comme étant le focus pour sa fenêtre de niveau supérieur ; la prochaine fois que le focus arrivera à la fenêtre de niveau supérieur, Tk le redirigera vers fenêtre. Si fenêtre est une chaîne vide, la commande ne fait rien.
focus -displayof fenêtre
Retourne le nom de la fenêtre de focus sur l'écran contenant fenêtre. Si la fenêtre de focus pour l'écran de fenêtre ne se trouve pas dans cette application, la valeur de retour est une chaîne vide.
focus -force fenêtre
Définit le focus de l'écran de fenêtre à fenêtre, même si l'application n'a pas actuellement le focus d'entrée pour l'écran. Cette commande doit être utilisée avec parcimonie, voire pas du tout. Dans une utilisation normale, une application ne doit pas réclamer le focus pour elle-même ; elle doit plutôt attendre que le gestionnaire de fenêtres lui donne le focus. Si fenêtre est une chaîne vide, la commande ne fait rien.
focus -lastfor fenêtre
Retourne le nom de la fenêtre la plus récente à avoir eu le focus d'entrée parmi toutes les fenêtres du même niveau supérieur que fenêtre. Si aucune fenêtre de ce niveau supérieur n'a jamais eu le focus d'entrée, ou si la fenêtre de focus la plus récente a été supprimée, le nom de la fenêtre de niveau supérieur est retourné. La valeur de retour est la fenêtre qui recevra le focus d'entrée la prochaine fois que le gestionnaire de fenêtres donnera le focus à la fenêtre de niveau supérieur.

QUIRKS

Lorsqu'une fenêtre interne reçoit le focus d'entrée, Tk ne définit pas réellement le focus X sur cette fenêtre ; du point de vue de X, le focus restera sur la fenêtre de niveau supérieur contenant la fenêtre avec le focus. Cependant, Tk génère des événements FocusIn et FocusOut comme si le focus X était sur la fenêtre interne. Cette approche résout un certain nombre de problèmes qui surviendraient si le focus X était réellement déplacé ; le fait que le focus X soit sur le niveau supérieur est invisible à moins que vous n'utilisiez du code C pour interroger directement le serveur X.

EXEMPLE

Pour qu'une fenêtre ne participe au cycle de parcours du focus que lorsqu'une variable est définie, ajoutez les liaisons suivantes aux widgets *avant* et *après* elle dans ce cycle de focus :

button .avant -text "Avant"
button .milieu -text "Milieu"
button .apres  -text "Après"
checkbutton .flag -variable traverseToMiddle -takefocus 0
pack .flag -side left
pack .avant .milieu .apres
bind .avant <Tab> {
   if {!$traverseToMiddle} {
      focus .apres
      break
   }
}
bind .apres <Shift-Tab> {
   if {!$traverseToMiddle} {
      focus .avant
      break
   }
}
focus .avant
