DESCRIPTIO

N

fy-tool est un outil général de manipulation YAML/JSON utilisant libfyaml. Son fonctionnement diffère selon la manière dont il est appelé, soit via des alias nommés fy-dump, fy-testsuite, fy-filter, fy-join, soit via les options --dump, --testsuite, --filter, --join, --ypath et --compose

.
  • En mode dump, il analysera les fichiers d'entrée YAML/JSON et produira du YAML/JSON selon les options de format de
    • sortie.
  • En mode testsuite, il analysera un seul fichier d'entrée YAML et produira la sortie de référence de la suite de tests
    • yaml.
  • En mode filter, il analysera des fichiers YAML/JSON et produira une sortie YAML/JSON filtrée selon l'option
    • donnée.
  • En mode join, il analysera des fichiers YAML/JSON et les fusionnera en un seul document YAML/JSON selon les options de ligne de commande
    • données.
  • En mode ypath, il analysera des fichiers YAML/JSON et exécutera une requête ypath qui produira un flux de documents selon les résultats. C'est un mode expérimental en développement, dont la syntaxe n'est pas encore entièrement
    • définie.
  • En mode compose, il fonctionne de manière similaire
    • au mode dump, mais
l'arbre du document est
créé à l'aide de l'API
de composition intégrée.

-w LARGEUR,

Définit la largeur de sortie préférée de l'émetteur. Il est généralement impossible pour adhérer strictement à cette limite, cela est traité au mieux comme un indice. Il n'est pas valide dans les modes de sortie sur une seule ligne (c.-à-d. flow-oneline ou json-oneline). La valeur par défaut est 80.
-m MODE, --mode=MODE
Définit le mode de sortie du YAML émis. Les valeurs possibles sont :
  • original

    Le formatage original utilisé dans l'entrée. C'est le mode par défaut.

  • block

    La sortie est forcée en mode bloc. Toutes les constructions de flux seront converties en mode bloc.

  • flow

    La sortie est forcée en mode flux. Toutes les constructions de bloc seront converties en mode flux.

  • flow-oneline

    La sortie est forcée en mode flux, mais aucune nouvelle ligne ne sera émise ; la sortie sera une ligne (potentiellement très) longue.

  • json

    La sortie est forcée en mode JSON. Notez qu'il est impossible de produire un fichier YAML arbitraire en JSON, donc cela peut échouer.

  • json-oneline

    La sortie est forcée en mode JSON et sur une seule ligne.

  • dejson

    La sortie est en mode bloc YAML mais avec une attention particulière pour convertir les chaînes JSON entre guillemets en YAML aussi peu idiomatique que possible. Par exemple, { foo: "this is a test" } sera émis comme foo: this is a test. YAML peut gérer les scalaires sans utiliser de guillemets excessifs.

options de sélection du mode outil.INDENT 0.0
--dump
Sélectionne le mode de fonctionnement dump. C'est le mode par défaut. Ce mode est également activé lorsque le binaire appelé est aliasé en fy-dump.

Dans ce mode, tous les fichiers fournis dans la ligne de commande seront vidés dans un flux continu, vers la sortie standard, en utilisant des indicateurs de début de document pour marquer le début de chaque nouveau fichier.

Si le fichier fourni est -, alors l'entrée est l'entrée standard.



--testsuite
Sélectionne le mode de fonctionnement testsuite. Ce mode est également activé lorsque le binaire appelé est aliasé en fy-testsuite.

Dans ce mode, un seul fichier YAML est lu et un flux d'événements est généré, qui est le format utilisé pour la conformité yaml-testsuite.

Si le fichier fourni est -, alors l'entrée est l'entrée standard.

--filter
Sélectionne le mode de fonctionnement filter. Ce mode est également activé lorsque le binaire appelé est aliasé en fy-filter.

Dans ce mode, un seul fichier YAML est lu depuis l'entrée standard. Pour chaque chemin fourni dans la ligne de commande, un document sera produit vers la sortie standard. Pour utiliser un fichier au lieu de l'entrée standard, utilisez l'option -f/--file.

Si le fichier fourni est -, alors l'entrée est l'entrée standard.

-f FILE, --file=FILE
Utilise le fichier donné comme entrée au lieu de l'entrée standard.

Si le premier caractère de FILE est >, alors l'entrée est le contenu de l'option qui suit. Par exemple, --file ">foo: bar" est équivalent à --file file.yaml avec file.yaml contenant "foo: bar"

--join
Sélectionne le mode de fonctionnement join. Ce mode est également activé lorsque le binaire appelé est aliasé en fy-join.

Dans ce mode, plusieurs fichiers YAML sont joints en un seul document, émis vers la sortie standard.

Si le fichier fourni est -, alors l'entrée est l'entrée standard.

-T PATH, --to=PATH
Le chemin cible de la jointure. Par défaut, c'est la racine /.

Si le premier caractère de FILE est >, alors l'entrée est le contenu de l'option qui suit.

-F PATH, --from=PATH
Le chemin d'origine de la jointure (pour chaque entrée). Par défaut, c'est la racine /.

Si le premier caractère de FILE est >, alors l'entrée est le contenu de l'option qui suit.

-t PATH, --trim=PATH
Tronque le chemin de la sortie de la jointure. Par défaut, c'est la racine /.

Si le premier caractère de FILE est >, alors l'entrée est le contenu de l'option qui suit.

--ypath
Traite les fichiers et génère les résultats de requêtes en utilisant ypath.
--compose
Utilise l'API du compositeur pour construire le document au lieu d'événements directs.
