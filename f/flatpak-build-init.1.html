NOM

flatpak build-init - Initialise un répertoire de construction

SYNTAXE

flatpak build-init [OPTION...] RÉPERTOIRE NOMAPP SDK RUNTIME [BRANCH]

DESCRIPTION

Initialise un répertoire de construction séparé. RÉPERTOIRE est le nom du répertoire. NOMAPP est l'identifiant de l'application qui sera construite. SDK et RUNTIME spécifient le sdk et le runtime sur lesquels l'application doit être construite et dans lesquels elle doit s'exécuter. BRANCH spécifie la version du sdk et du runtime.

Initialise un répertoire comme répertoire de construction qui peut être utilisé comme répertoire cible de flatpak build. Il crée des métadonnées à l'intérieur du répertoire donné. De plus, des fichiers vides et des sous-répertoires var sont créés.

Il est erroné d'exécuter build-init sur un répertoire qui a déjà été initialisé comme répertoire de construction.

OPTIONS

Les options suivantes sont comprises :

-h, --help

Affiche les options d'aide et quitte.

--arch=ARCH

L'architecture à utiliser. Voir flatpak --supported-arches pour les architectures prises en charge par l'hôte.

-v, --var=RUNTIME

Initialise var à partir du runtime nommé.

-w, --writable-sdk

Initialise /usr avec une copie du sdk, qui est accessible en écriture pendant la construction flatpak. Ceci peut être utilisé si vous avez besoin d'installer des outils de construction dans /usr pendant la construction. Ceci est stocké dans le sous-répertoire usr du répertoire de l'application, mais ne fera pas partie de l'application finale.

--tag=TAG

Ajoute une étiquette au fichier de métadonnées. Cette option peut être utilisée plusieurs fois.

--sdk-extension=EXTENSION

Lors de l'utilisation de --writable-sdk, en plus du sdk, installe également l'extension spécifiée. Cette option peut être utilisée plusieurs fois.

--extension=NAME=VARIABLE[=VALUE]

Ajoute des informations sur le point d'extension.

--sdk-dir

Spécifie un sous-répertoire personnalisé à utiliser à la place de usr pour --writable-sdk.

--update

Réinitialise le sdk et var, ne génère pas d'erreur si déjà initialisé.

--base=APP

Initialise l'application avec les fichiers d'une autre application spécifiée.

--base-version=VERSION

Spécifie la version à utiliser pour --base. Si elle n'est pas spécifiée, elle prendra par défaut la valeur « master ».

--base-extension=EXTENSION

Lors de l'utilisation de --base, installe également l'extension spécifiée de l'application. Cette option peut être utilisée plusieurs fois.

--type=TYPE

Ceci peut être utilisé pour construire différents types de choses. La valeur par défaut est « app » qui est une application régulière, mais « runtime » crée un runtime basé sur un runtime existant, et « extension » crée une extension pour une application ou un runtime.

--extension-tag=EXTENSION_TAG

Si vous construisez une extension, c'est l'étiquette à utiliser lors de la recherche du point de montage de l'extension.

--verbose

Affiche les informations de débogage pendant le traitement de la commande.

--ostree-verbose

Affiche les informations de débogage OSTree pendant le traitement de la commande.

EXEMPLES

$ flatpak build-init /build/my-app org.example.myapp org.gnome.Sdk org.gnome.Platform 3.36
