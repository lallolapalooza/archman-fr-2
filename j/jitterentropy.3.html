JITTERENTROPY(3) Manuel des fonctions de bibliothèque JITTERENTROPY(3)

NOM

jitterentropy - Générateur de nombres aléatoires basé sur le jitter CPU

SYNOPSIS

#include <jitterentropy.h>

int jent_entropy_switch_notime_impl(struct jent_notime_thread *new_thread);

int jent_set_fips_failure_callback(jent_fips_failure_cb cb);

int jent_entropy_init(void);

int jent_entropy_init_ex(unsigned int osr, unsigned int flags);

struct rand_data *jent_entropy_collector_alloc(unsigned int osr,
                                               unsigned int flags);

void jent_entropy_collector_free(struct rand_data *entropy_collector);

ssize_t jent_read_entropy(struct rand_data *entropy_collector,
                          char *data, size_t len);

ssize_t jent_read_entropy_safe(struct rand_data **entropy_collector,
                               char *data, size_t len);

#define JENT_MAJVERSION x

#define JENT_MINVERSION y

#define JENT_PATCHLEVEL z

#define JENT_VERSION (...)

unsigned int jent_version(void);

DESCRIPTION

La bibliothèque jitterentropy fournit une source d'entropie de qualité en collectant le jitter du temps d'exécution du CPU. L'entropie du jitter du temps d'exécution du CPU est amplifiée par le générateur de nombres aléatoires basé sur le jitter CPU. Le générateur de nombres aléatoires basé sur le jitter CPU utilise le jitter de timing d'exécution du CPU pour générer un flux de bits qui respecte diverses mesures statistiques déterminant que le flux de bits est aléatoire.

Le générateur de nombres aléatoires basé sur le jitter CPU fournit une entropie qui suit les exigences de la théorie de l'information. Basé sur ces études et l'implémentation, l'appelant peut supposer qu'un bit de données extrait du générateur de nombres aléatoires basé sur le jitter CPU détient un bit d'entropie.

Le générateur de nombres aléatoires basé sur le jitter CPU fournit une source d'entropie décentralisée où l'appelant n'a pas besoin de dépendre d'une source d'entropie maintenue centralement comme /dev/random ou /dev/urandom.

jent_entropy_switch_notime_impl() permet à l'appelant de définir un gestionnaire de thread qui est utilisé par le générateur de nombres aléatoires Jitter s'il fonctionne en mode sans timer. Voir jitterentropy.h pour une documentation de new_thread. Cette fonction doit être appelée avant jent_entropy_init() car après cet appel, le changement du gestionnaire de thread est refusé.

jent_set_fips_failure_callback() permet à l'appelant de définir un rappel qui est invoqué par le générateur de nombres aléatoires Jitter lorsqu'une défaillance de test de santé est détectée. Le rappel spécifié avec le paramètre cb à la fonction API reçoit l'état du générateur de nombres aléatoires Jitter avec le paramètre ec et la défaillance du test de santé FIPS avec le paramètre health_failure. Cette fonction doit être appelée avant jent_entropy_init() car après cet appel, le changement du rappel est refusé.

jent_entropy_init() initialise le générateur de nombres aléatoires basé sur le jitter CPU. La fonction effectue des tests statistiques pour vérifier que le système sous-jacent offre les propriétés nécessaires pour mesurer et collecter l'entropie. Si l'initialisation réussit, ce qui implique que les tests statistiques indiquent que le système sous-jacent est approprié, l'appel retourne avec 0. Un code de retour différent de 0 indique un échec où l'application appelante DOIT NE PAS utiliser le générateur de nombres aléatoires basé sur le jitter CPU.

jent_entropy_init_ex() se comporte de manière identique à jent_entropy_init() sauf qu'elle permet à l'appelant de fournir les paramètres osr et flags qui devraient être identiques à l'invocation ultérieure de jent_entropy_collector_alloc(). Lors de la spécification d'un taux de suréchantillonnage osr différent de la valeur par défaut, le test de démarrage respecte cette valeur et ajuste les seuils de coupure des auto-tests aux mêmes valeurs qu'utilisées à l'exécution.

jent_entropy_collector_alloc() alloue une instance de collecteur d'entropie Jitter CPU et retourne le handle à l'appelant. Si l'allocation échoue, y compris pour des contraintes mémoire, l'appel retourne NULL. La fonction nécessite deux arguments, le taux de suréchantillonnage osr et un ensemble de drapeaux avec flags. La valeur osr définit la quantité de suréchantillonnage effectuée par le collecteur d'entropie. Généralement, un appelant souhaite fournir la valeur 0 ici pour appliquer le suréchantillonnage par défaut. L'appel garantit que toute valeur inférieure à JENT_MIN_OSR est automatiquement convertie en JENT_MIN_OSR.

La valeur flags est soit zéro, soit un ou plusieurs des drapeaux suivants.

JENT_DISABLE_MEMORY_ACCESS
Si le système est contraint en mémoire, ce drapeau désactive l'allocation de cette mémoire et donc les accès mémoire. Mais cela implique également que le processus de collecte d'entropie repose uniquement sur la complexité du CPU. Notez que si quelqu'un connaît tous les détails de cette complexité CPU, cette personne peut potentiellement réduire l'entropie fournie par la complexité CPU. Si cette personne peut pousser l'entropie générée en dessous d'un seuil, le générateur de nombres aléatoires Jitter CPU commence à surestimer l'entropie de la source de bruit. Ainsi, désactiver les accès mémoire et ne s'appuyer que sur la complexité CPU ne devrait être fait que si vous savez vraiment ce que vous faites.
JENT_FORCE_INTERNAL_TIMER
Ce drapeau peut être utilisé pour forcer le générateur de nombres aléatoires Jitter à utiliser le timer interne à haute résolution au lieu d'utiliser l'horodatage matériel. Couramment, le test d'auto-vérification au démarrage effectué avec jent_entropy_init() utilise le timer matériel avec priorité s'il est identifié comme approprié pour la collecte d'entropie. Si le timer interne n'est pas compilé, demander ce drapeau retourne une erreur. Même si un thread séparé est lancé pour fournir un horodatage à haute résolution, toute cette opération est entièrement thread-safe car toutes les données pertinentes sont maintenues dans le cadre de la structure de données entropy_collector.
JENT_DISABLE_INTERNAL_TIMER
Ce drapeau peut être utilisé pour s'assurer que le timer interne n'est pas utilisé. Si ce drapeau est utilisé conjointement avec JENT_FORCE_INTERNAL_TIMER, cela est traité comme une erreur et l'allocation retourne NULL. De plus, si jent_entropy_init() détecte que le timer interne doit être utilisé mais que le drapeau de désactivation est défini, l'allocation retourne NULL.
JENT_FORCE_FIPS
Forcer la conformité complète FIPS 140 et SP800-90B, quelle que soit la configuration FIPS du système d'exploitation sous-jacent.
JENT_MAX_MEMSIZE_*
Définir la quantité maximale de mémoire que le générateur de nombres aléatoires Jitter utilisera pour son opération de support de la collecte de bruit brut. Sans utiliser l'un de ces drapeaux, le générateur de nombres aléatoires Jitter utilise une limite intégrée. Plus la quantité de mémoire est importante, plus l'entropie collectée est importante. Pourtant, la valeur par défaut est sûre sur la plupart des CPUs. Si vous avez des contraintes mémoire mais que le taux d'entropie de votre CPU est suffisant, une taille de mémoire inférieure peut être utilisée. Inversement, si vous avez suffisamment de mémoire mais une entropie insuffisante, des tailles de mémoire plus importantes peuvent être spécifiées. Dans tous les cas, le générateur de nombres aléatoires Jitter utilise au maximum autant de mémoire que la somme des caches de données du CPU.

jent_entropy_collector_free() efface et libère l'instance du collecteur d'entropie Jitter CPU donnée.

jent_read_entropy() génère un flux de bits aléatoire et le retourne à l'appelant. entropy_collector est l'instance du collecteur d'entropie Jitter CPU qui doit être utilisée pour obtenir des nombres aléatoires. data est l'emplacement mémoire de destination où le flux de bits aléatoire est écrit. La mémoire doit avoir déjà été allouée par l'appelant. len est une valeur de longueur fournie par l'appelant indiquant le nombre d'octets que le générateur de nombres aléatoires Jitter CPU doit générer. L'appelant peut fournir toute valeur supérieure à 0. L'appelant doit s'assurer que data est au moins aussi grand que ce qu'indique len. La fonction retourne le nombre d'octets générés lorsque la demande est satisfaite avec succès. Si la fonction retourne le code d'erreur -1, alors l'appelant a fourni une valeur non initialisée (c'est-à-dire NULL) pour le collecteur d'entropie. Le code de retour -2 indique que le test de santé en ligne du compteur de répétition SP800-90B a échoué. Le code d'erreur -3 spécifie que le test de santé en ligne proportionnel adaptatif SP800-90B a échoué. -4 indique que le générateur de timer interne ne peut pas être initialisé. -5 spécifie que t

he LAG predictor health test échoué. -6 indique que le test de décompte répétitif (RCT) a échoué définitivement. -7 indique que le test de proportion adaptative (APT) a échoué définitivement. -8 indique que le test de prédiction LAG a échoué définitivement.

Lorsque l'un des tests de santé en ligne échoue, le Jitter RNG n'aura pas de données fournies dans data. L'instance du collecteur d'entropie restera en état d'erreur. Pour récupérer, l'instance du collecteur d'entropie **DOIT** être désallouée et une nouvelle instance doit être allouée. Il est recommandé d'augmenter la valeur osr d'au moins un lors de l'allocation d'une nouvelle instance du Jitter RNG avec jent_entropy_collector_alloc(), ce qui implique que les tests de santé sont moins sensibles car le taux d'entropie supposé de la source de bruit est plus bas.

jent_read_entropy_safe() est une fonction de service qui fonctionne donc de manière identique à jent_read_entropy(), à l'exception qu'elle réalloue automatiquement le collecteur d'entropie si un échec de test de santé est observé. Avant la réallocation, un nouveau test de santé de mise sous tension est effectué. L'allocation du nouveau collecteur d'entropie augmente automatiquement l'OSR d'un. Ceci est basé sur l'idée qu'un échec de test de santé indique que le taux d'entropie supposé est trop élevé.

Notez que la fonction renvoie une erreur de test de santé si l'OSR devient trop grand. Si une erreur est retournée par cette fonction, le Jitter RNG n'est pas sûr d'être utilisé sur le système actuel.

La fonction jent_read_entropy_safe() a les mêmes codes d'erreur que jent_read_entropy().

JENT_MAJVERSION indique des changements incompatibles API / ABI, des changements fonctionnels qui nécessitent une mise à jour du consommateur.

JENT_MINVERSION indique une compatibilité API, l'ABI peut changer, seulement des améliorations fonctionnelles, le consommateur peut rester inchangé si les améliorations ne sont pas prises en compte.

JENT_PATCHLEVEL indique une compatibilité API / ABI, pas de changements fonctionnels, pas d'améliorations, uniquement des corrections de bugs. De plus, la collecte d'entropie n'est modifiée d'aucune manière qui nécessiterait une réévaluation.

JENT_VERSION le numéro de version de la bibliothèque sous forme d'un entier qui augmente de manière monotone. Les numéros de version sont des multiples de 100. Par exemple, la version 1.2.3 est convertie en 1020300 -- les deux derniers chiffres sont réservés pour un usage futur.

jent_version() renvoie JENT_VERSION.

Considérations FIPS 140-3

Pour que le Jitter RNG s'exécute conformément à FIPS 140-3 et par extension également à SP800-90B et SP800-90C, les considérations suivantes doivent être appliquées :

Activer le mode FIPS
Le mode FIPS est activé en utilisant le drapeau JENT_FORCE_FIPS lors de l'initialisation de la bibliothèque Jitter RNG. Sous Linux, le mode FIPS est activé de manière transparente si l'ensemble du système d'exploitation a été démarré en mode FIPS, généralement en utilisant le paramètre de ligne de commande du noyau Linux "fips=1".
Effectuer une analyse d'entropie heuristique
L'ensemble d'outils de test fourni dans le cadre de la distribution source de la bibliothèque Jitter RNG contient l'aide pour obtenir des données brutes de bruit au moment de l'exécution ainsi qu'au moment de l'initialisation pour calculer le taux d'entropie SP800-90B. Ce taux doit être supérieur à 0,333, le minimum heuristique implicite par la bibliothèque Jitter RNG.
Résoudre un manque d'entropie
Si un manque d'entropie est détecté lors de l'analyse SP800-90B susmentionnée, l'ensemble d'outils de test fournit une aide pour analyser les paramètres optimaux - voir l'ensemble d'outils de test pour l'entropie brute pour plus de détails. Les valeurs de configuration résultantes sont censées être utilisées avec le paramètre flags des appels jent_entropy_collector_alloc() et jent_entropy_init_ex(). Il est recommandé d'utiliser l'appel de fonction jent_read_entropy_safe() pour générer des nombres aléatoires.

NOTES

En plus d'utiliser le flux de bits aléatoires générés directement pour les opérations cryptographiques, la sortie de jent_read_entropy() peut être utilisée pour l'amorçage d'un générateur de nombres aléatoires déterministe.
