NOM

javadoc - générer des pages HTML de documentation API à partir de fichiers source Java

SYNOPSIS

javadoc [options] [noms_de_paquets] [fichiers_source] [@fichiers]

options
Spécifie les options de ligne de commande, séparées par des espaces. Voir Options pour javadoc, Options étendues, Options du doclet standard, et Options supplémentaires fournies par le doclet standard.
noms_de_paquets
Spécifie les noms des paquets que vous souhaitez documenter, séparés par des espaces, par exemple java.lang java.lang.reflect java.awt. Si vous souhaitez également documenter les sous-paquets, utilisez l'option -subpackages pour spécifier les paquets.

Par défaut, javadoc recherche les paquets spécifiés dans le répertoire courant et ses sous-répertoires. Utilisez l'option -sourcepath pour spécifier la liste des répertoires où rechercher les paquets.

fichiers_source
Spécifie les noms des fichiers source Java que vous souhaitez documenter, séparés par des espaces, par exemple Class.java Object.java Button.java. Par défaut, javadoc recherche les classes spécifiées dans le répertoire courant. Cependant, vous pouvez spécifier le chemin complet du fichier de classe et utiliser des caractères génériques, par exemple /home/src/java/awt/Graphics*.java. Vous pouvez également spécifier le chemin relatif au répertoire courant.
@fichiers
Spécifie les noms des fichiers contenant une liste d'options de l'outil javadoc, de noms de paquets et de noms de fichiers source dans n'importe quel ordre.

DESCRIPTION

L'outil javadoc analyse les déclarations et les commentaires de documentation dans un ensemble de fichiers source Java et produit des pages HTML correspondantes qui décrivent (par défaut) les classes publiques et protégées, les classes imbriquées (mais pas les classes internes anonymes), les interfaces, les constructeurs, les méthodes et les champs. Vous pouvez utiliser l'outil javadoc pour générer la documentation de l'API ou la documentation d'implémentation pour un ensemble de fichiers source.

Vous pouvez exécuter l'outil javadoc sur des paquets entiers, des fichiers source individuels, ou les deux. Lors de la documentation de paquets entiers, vous pouvez utiliser l'option -subpackages soit pour parcourir récursivement un répertoire et ses sous-répertoires, soit pour passer une liste explicite de noms de paquets. Lorsque vous documentez des fichiers source individuels, passez une liste de noms de fichiers source Java. Voir Aperçu de javadoc [https://www.oracle.com/pls/topic/lookup?ctx=en/java/javase/13/tools&id=JSJAV-GUID-7A344353-3BBF-45C4-8B28-15025DDCC643] dans le guide Javadoc de la Java Platform, Standard Edition pour plus d'informations sur l'utilisation de l'outil javadoc.

CONFORMANCE

Le doclet standard ne valide pas le contenu des commentaires de documentation et n'essaie pas de corriger les erreurs dans les commentaires de documentation. Il est conseillé à toute personne exécutant javadoc d'être consciente des problèmes qui peuvent survenir lors de la génération d'une sortie non conforme ou d'une sortie contenant du contenu exécutable, tel que JavaScript. Le doclet standard fournit la fonctionnalité doclint pour aider les développeurs à détecter les problèmes courants dans les commentaires de documentation ; mais il est également recommandé de vérifier la sortie générée avec tout outil de conformité approprié et autres outils de vérification.

Pour plus de détails sur les exigences de conformité pour les documents HTML5, voir Exigences de conformité [https://www.w3.org/TR/html5/infrastructure.html#conformance-requirements] dans la spécification HTML5. Pour plus de détails sur les problèmes de sécurité liés aux pages Web, voir la page du Open Web Application Security Project (OWASP) [https://www.owasp.org].

-breakiterator
Calcule la première phrase avec BreakIterator. La première phrase est copiée dans le résumé du paquet, de la classe ou du membre et dans l'index alphabétique. La classe BreakIterator est utilisée pour déterminer la fin d'une phrase pour toutes les langues, sauf l'anglais.
•
Algorithme de séparation de phrases par défaut en anglais --- S'arrête à un point suivi d'un espace ou d'une balise de bloc HTML, telle que <P>.
•
Algorithme de séparation de phrases Breakiterator --- S'arrête à un point, un point d'interrogation ou un point d'exclamation suivi d'un espace lorsque le mot suivant commence par une lettre majuscule. Ceci est destiné à gérer la plupart des abréviations (telles que "Le numéro de série. est valide", mais ne gérera pas "M. Smith"). L'option -breakiterator ne s'arrête pas aux balises HTML ou aux phrases qui commencent par des chiffres ou des symboles. L'algorithme s'arrête au dernier point dans ../nom_de_fichier, même lorsqu'il est intégré dans une balise HTML.

Le chemin d'accès à cette classe de départ est défini par l'option -docletpath.

-locale nom
Spécifie la locale que l'outil javadoc utilise lorsqu'il génère la documentation. L'argument est le nom de la locale, tel que décrit dans la documentation de java.util.Locale, par exemple en_US (anglais, États-Unis) ou en_US_WIN (variante Windows).

Note :

L'option -locale doit être placée avant (à gauche de) toutes les options fournies par le doclet standard ou tout autre doclet. Sinon, les barres de navigation apparaîtront en anglais. C'est la seule option de ligne de commande qui dépend de l'ordre.

La spécification d'une locale amène l'outil javadoc à choisir les fichiers de ressources de cette locale pour les messages tels que les chaînes de la barre de navigation, les en-têtes des listes et des tableaux, le contenu des fichiers d'aide, les commentaires du fichier stylesheet.css, etc. Elle spécifie également l'ordre de tri des listes triées alphabétiquement, et le séparateur de phrase pour déterminer la fin de la première phrase. L'option -locale ne détermine pas la locale du texte des commentaires de documentation spécifié dans les fichiers source des classes documentées.

-subpackages subpkglist
Génère la documentation à partir des fichiers source dans les packages spécifiés et récursivement dans leurs sous-packages. Cette option est utile lors de l'ajout de nouveaux sous-packages au code source car ils sont automatiquement inclus. Chaque argument de package est un sous-package de niveau supérieur (tel que java) ou un package entièrement qualifié (tel que javax.swing) qui n'a pas besoin de contenir de fichiers source. Les arguments sont séparés par des deux-points sur tous les systèmes d'exploitation. Les caractères génériques ne sont pas autorisés. Utilisez -sourcepath pour spécifier où trouver les packages. Cette option ne traite pas les fichiers source qui se trouvent dans l'arborescence source mais qui n'appartiennent pas aux packages.

Par exemple, les commandes suivantes génèrent la documentation pour les packages nommés java et javax.swing ainsi que tous leurs sous-packages.

•
Linux et OS X :

javadoc -d docs -sourcepath /home/user/src -subpackages java:javax.swing

•
Windows :

javadoc -d docs -sourcepath \user\src -subpackages java:javax.swing

-verbose
Fournit des messages plus détaillés pendant l'exécution de l'outil javadoc. Sans l'option -verbose, des messages apparaissent pour le chargement des fichiers source, la génération de la documentation (un message par fichier source) et le tri. L'option -verbose entraîne l'affichage de messages supplémentaires qui spécifient le nombre de millisecondes nécessaires pour analyser chaque fichier source Java.
--version
Affiche les informations de version.
-Werror
Signale une erreur si des avertissements surviennent.

OPTIONS DU DOCLET STANDARD

Les options suivantes sont fournies par le doclet standard.

--add-stylesheet fichier
Ajoute un fichier de feuille de style supplémentaire pour la documentation générée. Cette option peut être utilisée une ou plusieurs fois pour spécifier des feuilles de style supplémentaires incluses dans la documentation.

Exemple de ligne de commande :

javadoc --add-stylesheet new_stylesheet_1.css --add-stylesheet new_stylesheet_2.css pkg_foo

--allow-script-in-comments
Autorise JavaScript dans les options et les commentaires.
-author
Inclut le texte @author dans les documents générés.
-bottom code-html
Spécifie le texte à placer en bas de chaque fichier de sortie. Le texte est placé en bas de la page, sous la barre de navigation inférieure. Le texte peut contenir des balises HTML et des espaces blancs, mais dans ce cas, le texte doit être entouré de guillemets. Utilisez des caractères d'échappement pour tous les guillemets internes dans le texte.
-charset nom
Spécifie le jeu de caractères HTML pour ce document. Le nom doit être un nom MIME préféré tel que spécifié dans le Registre IANA, Jeux de caractères [http://www.iana.org/assignments/character-sets].

Par exemple :

javadoc -charset "iso-8859-1" mypackage

Cette commande insère la ligne suivante dans l'en-tête de chaque page générée :

<META http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

La balise META est décrite dans la norme HTML (4197265 et 4137321), Représentation des documents HTML [http://www.w3.org/TR/REC-html40/charset.html#h-5.2.2].

-d répertoire
Spécifie le répertoire de destination où l'outil javadoc enregistre les fichiers HTML générés. Si vous omettez l'option -d, les fichiers sont enregistrés dans le répertoire courant. La valeur répertoire peut être absolue ou relative au répertoire de travail courant. Le répertoire de destination est créé automatiquement lorsque l'outil javadoc s'exécute.
•
Linux et OS X : Par exemple, la commande suivante génère la documentation pour le package com.mypackage et enregistre les résultats dans le répertoire /user/doc/ :

javadoc -d /user/doc/ com.mypackage

•
Windows : Par exemple, la commande suivante génère la documentation pour le package com.mypackage et enregistre les résultats dans le répertoire \user\doc\ :

javadoc -d \user\doc\ com.mypackage

-docencoding nom
Spécifie l'encodage des fichiers HTML générés. Le nom doit être un nom MIME préféré tel que spécifié dans le Registre IANA, Jeux de caractères [http://www.iana.org/assignments/character-sets].

Trois options sont disponibles pour une utilisation dans une commande d'encodage javadoc. L'option -encoding est utilisée pour encoder les fichiers lus par l'outil javadoc, tandis que les options -docencoding et -charset sont utilisées pour encoder les fichiers écrits par l'outil. Parmi les trois options disponibles, au maximum, seule l'entrée et une option d'encodage de sortie sont utilisées dans une seule commande d'encodage. Si vous spécifiez les deux options d'encodage d'entrée et de sortie dans une commande, elles doivent avoir la même valeur. Si vous ne spécifiez aucune des deux options de sortie, l'outil utilise par défaut l'encodage d'entrée.

Par exemple :

javadoc -docencoding "iso-8859-1" mypackage

Les baliselets sont utiles pour les balises de bloc ou en ligne. Quand l'option -Xdoclint est activée, elle signale des problèmes avec des messages similaires à la commande javac. L'outil javadoc imprime un message, une copie de la ligne source, et un accent circonflexe pointant vers la position exacte où l'erreur a été détectée. Les messages peuvent être des avertissements ou des erreurs, selon leur sévérité et la probabilité de causer une erreur si la documentation générée était passée à travers un validateur. Par exemple : les commentaires de documentation manquants, les informations en double et les commentaires superflus ne causent pas que l'outil javadoc génère du HTML invalide, donc ces problèmes sont signalés comme des avertissements ; les erreurs de syntaxe, les balises HTML de fin obligatoires manquantes et les références à des éléments manquants ou mal orthographiés causent que l'outil javadoc génère une sortie invalide, donc ces problèmes sont signalés comme des

erreurs.
