JMOD(1) Commandes JDK JMOD(1)

NOM

jmod - crée des fichiers JMOD et liste le contenu des fichiers JMOD existants

SYNOPSIS

jmod (create|extract|list|describe|hash) [options] fichier-jmod

Inclut ce qui suit :

Modes d'opération principaux

create
Crée un nouveau fichier archive JMOD.
extract
Extrait tous les fichiers du fichier archive JMOD.
list
Affiche les noms de toutes les entrées.
describe
Affiche les détails du module.
hash
Détermine les modules feuilles et enregistre les hachages des dépendances qui les requièrent directement et indirectement.

Options

options
Voir Options pour jmod.

Obligatoire

fichier-jmod
Spécifie le nom du fichier JMOD à créer ou à partir duquel récupérer des informations.

DESCRIPTION

Remarque : Pour la plupart des tâches de développement, y compris le déploiement de modules sur le chemin des modules ou leur publication dans un dépôt Maven, continuez à empaqueter les modules dans des fichiers JAR modulaires. L'outil jmod est destiné aux modules qui ont des bibliothèques natives ou d'autres fichiers de configuration, ou aux modules que vous avez l'intention de lier, avec l'outil jlink, à une image d'exécution.

Le format de fichier JMOD vous permet d'agréger des fichiers autres que les fichiers .class, des métadonnées et des ressources. Ce format est transportable mais non exécutable, ce qui signifie que vous pouvez l'utiliser pendant la phase de compilation ou de liaison, mais pas pendant la phase d'exécution.

De nombreuses options jmod impliquent de spécifier un chemin dont le contenu est copié dans les fichiers JMOD résultants. Ces options copient tout le contenu du chemin spécifié, y compris les sous-répertoires et leur contenu, mais excluent les fichiers dont les noms correspondent au modèle spécifié par l'option --exclude.

Avec l'option --hash-modules ou la commande jmod hash, vous pouvez, dans le descripteur de chaque module, enregistrer les hachages du contenu des modules qui sont autorisés à en dépendre, ainsi « liant » ces modules ensemble. Cela permet à un paquet d'être exporté vers un ou plusieurs modules nommés spécifiquement et à aucun autre grâce aux exportations qualifiées. L'exécution vérifie si le hachage enregistré d'un module correspond à celui résolu lors de l'exécution ; sinon, l'exécution renvoie une erreur.

OPTIONS POUR JMOD

--class-path chemin
Spécifie l'emplacement des fichiers JAR d'application ou d'un répertoire contenant des classes à copier dans le fichier JMOD résultant.
--cmds chemin
Spécifie l'emplacement des commandes natives à copier dans le fichier JMOD résultant.
--compress compression
Spécifie la compression à utiliser lors de la création du fichier JMOD. Les valeurs acceptées sont zip-[0-9], où zip-0 ne fournit aucune compression, et zip-9 fournit la meilleure compression. La valeur par défaut est zip-6.
--config chemin
Spécifie l'emplacement des fichiers de configuration modifiables par l'utilisateur à copier dans le fichier JMOD résultant.
--dateTIMESTAMP
L'horodatage au format date-heure étendue ISO-8601 avec fuseau horaire optionnel, à utiliser pour l'horodatage des entrées, par exemple "2022-02-12T12:30:00-05:00".
--dir chemin
Spécifie l'emplacement où jmod place les fichiers extraits de l'archive JMOD spécifiée.
--dry-run
Effectue une simulation du mode hash. Il identifie les modules feuilles et leurs modules requis sans enregistrer de valeurs de hachage.
--exclude liste-de-modèles
Exclut les fichiers correspondant à la liste de modèles fournie et séparée par des virgules, chaque élément utilisant l'une des formes suivantes :
•
modèle-glob
•
glob:modèle-glob
•
regex:modèle-regex

Voir la méthode FileSystem.getPathMatcher pour la syntaxe de modèle-glob. Voir la classe Pattern pour la syntaxe de modèle-regex, qui représente une expression régulière.

--hash-modules modèle-regex
Détermine les modules feuilles et enregistre les hachages des dépendances qui les requièrent directement et indirectement, en se basant sur le graphe des modules des modules correspondant au modèle-regex donné. Les hachages sont enregistrés dans le fichier archive JMOD en cours de création, ou dans une archive JMOD ou un JAR modulaire sur le chemin des modules spécifié par la commande jmod hash.
--header-files chemin
Spécifie l'emplacement des fichiers d'en-tête à copier dans le fichier JMOD résultant.
--help ou -h
Affiche un message d'utilisation.
--help-extra
Affiche l'aide pour les options supplémentaires.
--legal-notices chemin
Spécifie l'emplacement des avis légaux à copier dans le fichier JMOD résultant.
--libs chemin
Spécifie l'emplacement des bibliothèques natives à copier dans le fichier JMOD résultant.
--main-class nom-de-classe
Spécifie la classe principale à enregistrer dans le fichier module-info.class.
--man-pages chemin
Spécifie l'emplacement des pages de manuel à copier dans le fichier JMOD résultant.
--module-version version-module
Spécifie la version du module à enregistrer dans le fichier module-info.class.
--module-path chemin ou -p chemin
Spécifie le chemin des modules. Cette option est requise si vous spécifiez également --hash-modules.
--target-platform plateforme
Spécifie la plateforme cible.
--version
Affiche les informations de version de l'outil jmod.
@nom-de-fichier
Lit les options à partir du fichier spécifié.

Un fichier d'options est un fichier texte qui contient les options et les valeurs que vous saisiriez normalement dans une invite de commande. Les options peuvent apparaître sur une seule ligne ou sur plusieurs lignes. Vous ne pouvez pas spécifier de variables d'environnement pour les noms de chemin. Vous pouvez commenter des lignes en faisant précéder un symbole dièse (#) au début de la ligne.

Voici un exemple de fichier d'options pour la commande jmod :

< jmod(1) - Manuel Arch Linux

SYNOPSIS

jmod create [options] jmod-file

jmod extract [options] jmod-file

jmod list [options] jmod-file

jmod describe [options] jmod-file

jmod hash [options] jmod-file

DESCRIPTION

La commande jmod crée des archives de modules JMOD, des archives contenant un module Java et ses ressources associées. Elle peut également être utilisée pour extraire, lister, décrire et hasher les modules des archives JMOD.

OPTIONS FOR JMOD

Les options suivantes peuvent être utilisées avec la commande jmod:

--class-path path
Chemin d'accès à un fichier JAR ou à un répertoire contenant des fichiers .class et des ressources.
--cmds dir
Répertoire contenant des commandes natives.
--config dir
Répertoire contenant des fichiers de configuration.
--date date-time
Date et heure à utiliser pour les entrées de l'archive. La chaîne doit être au format ISO 8601.
--header-files dir
Répertoire contenant des fichiers d'en-tête.
--header-linking dir
Répertoire contenant des informations de liaison d'en-tête.
--help
Afficher le message d'aide.
--libs dir
Répertoire contenant des bibliothèques natives.
--main-class class-name
Nom de la classe principale du module.
--man-pages dir
Répertoire contenant des pages de manuel.
--module-path path
Chemin d'accès aux modules.
--module-version version
Version du module.
--os-arch arch
Architecture du système d'exploitation.
--os-name name
Nom du système d'exploitation.
--os-version version
Version du système d'exploitation.
--system-modules dir
Répertoire contenant les modules système.
--version
Afficher les informations sur la version.

EXTRA OPTIONS FOR JMOD

En plus des options décrites dans Options for jmod, les options supplémentaires suivantes peuvent être utilisées avec la commande.

--do-not-resolve-by-default
Exclure de l'ensemble racine par défaut des modules
--warn-if-resolved
Indiquer à un outil d'émettre un avertissement si le module est résolu. L'une des valeurs suivantes : deprecated, deprecated-for-removal, ou incubating.

JMOD CREATE EXAMPLE

Voici un exemple de création d'un fichier JMOD :

#Mer Déc 07 00:40:19 EST 2016
create --class-path mods/com.greetings --module-path mlib
  --cmds commands --config configfiles --header-files src/h
  --libs lib --main-class com.greetings.Main
  --man-pages man --module-version 1.0
  --os-arch "x86_x64" --os-name "macOS"
  --os-version "10.10.5" greetingsmod

Créer un fichier JMOD en spécifiant la date des entrées comme 2022 Mar 15 00:00:00 :

jmod create --class-path build/foo/classes --date 2022-03-15T00:00:00Z
   jmods/foo1.jmod

JMOD HASH EXAMPLE

L'exemple suivant montre ce qui se passe lorsque vous essayez de lier un module feuille (dans cet exemple, ma) avec un module requis (mb), et que la valeur de hachage enregistrée dans le module requis ne correspond pas à celle du module feuille.

1.
Créer et compiler les fichiers .java suivants :
•
jmodhashex/src/ma/module-info.java
module ma {
  requires mb;
}
•
jmodhashex/src/mb/module-info.java
module mb {
}
•
jmodhashex2/src/ma/module-info.java
module ma {
  requires mb;
}
•
jmodhashex2/src/mb/module-info.java
module mb {
}
2.
Créer une archive JMOD pour chaque module. Créer les répertoires jmodhashex/jmods et jmodhashex2/jmods, puis exécuter les commandes suivantes depuis le répertoire jmodhashex, puis depuis le répertoire jmodhashex2 :
•
jmod create --class-path mods/ma jmods/ma.jmod
•
jmod create --class-path mods/mb jmods/mb.jmod
3.
Optionnellement, prévisualiser la commande jmod hash. Exécuter la commande suivante depuis le répertoire jmodhashex :

jmod hash --dry-run -module-path jmods --hash-modules .*

La commande affiche le résultat suivant :

Dry run:
mb
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a

Cela indique que la commande jmod hash (sans l'option --dry-run) enregistrera la valeur de hachage du module feuille ma dans le module mb.

4.
Enregistrer les valeurs de hachage dans les fichiers d'archive JMOD contenus dans le répertoire jmodhashex. Exécuter la commande suivante depuis le répertoire jmodhashex :

jmod hash --module-path jmods --hash-modules .*

La commande affiche le résultat suivant :

Hashes are recorded in module mb

5.
Afficher des informations sur chaque archive JMOD contenue dans le répertoire jmodhashex. Exécuter les commandes mises en surbrillance depuis le répertoire jmodhashex :
jmod describe jmods/ma.jmod
ma
  requires mandated java.base
  requires mb
jmod describe jmods/mb.jmod
mb
  requires mandated java.base
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a
6.
Tenter de créer une image d'exécution qui contient le module ma du répertoire jmodhashex2 mais le module mb du répertoire jmodhashex. Exécuter la commande suivante depuis le répertoire jmodhashex2 :
•
Linux et macOS :

jlink --module-path $JAVA_HOME/jmods:jmods/ma.jmod:../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

•
Windows :

jlink --module-path %JAVA_HOME%/jmods;jmods/ma.jmod;../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

La commande affiche un message d'erreur similaire à ce qui suit :

Error: Hash of ma (a2d77889b0cb067df02a3abc39b01ac1151966157a68dc4241562c60499150d2) differs to
expected hash (07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a) recorded in mb
