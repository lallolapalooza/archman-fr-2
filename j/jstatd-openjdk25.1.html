JSTATD(1) Commandes JDK JSTATD(1)

NOM

jstatd - surveille la création et la terminaison des VM Java HotSpot instrumentées

SYNTAXE

AVERTISSEMENT : Cette commande est expérimentale, non prise en charge et obsolète. Elle sera supprimée dans une future version.

jstatd [options]

options
Ceci représente les options de ligne de commande de jstatd. Voir Options pour la commande jstatd.

DESCRIPTION

La commande jstatd est une application serveur RMI qui surveille la création et la terminaison des VM Java HotSpot instrumentées et fournit une interface permettant aux outils de surveillance à distance, jstat et jps, de s'attacher aux JVM s'exécutant sur l'hôte local et de collecter des informations sur le processus JVM.

Le serveur jstatd nécessite un registre RMI sur l'hôte local. Le serveur jstatd tente de s'attacher au registre RMI sur le port par défaut, ou sur le port que vous spécifiez avec l'option -p port. Si un registre RMI n'est pas trouvé, un registre est créé dans l'application jstatd et est lié au port indiqué par l'option -p port ou au port par défaut du registre RMI lorsque l'option -p port est omise. Vous pouvez empêcher la création d'un registre RMI interne en spécifiant l'option -nr.

OPTIONS POUR LA COMMANDE JSTATD

-nr
Cette option n'essaie pas de créer un registre RMI interne dans le processus jstatd lorsqu'un registre RMI existant n'est pas trouvé.
-p port
Cette option définit le numéro de port où le registre RMI est censé être trouvé, ou lorsqu'il n'est pas trouvé, créé si l'option -nr n'est pas spécifiée.
-r rmiport
Cette option définit le numéro de port auquel le connecteur RMI est lié. S'il n'est pas spécifié, un port disponible aléatoire est utilisé.
-n rminame
Cette option définit le nom auquel l'objet RMI distant est lié dans le registre RMI. Le nom par défaut est JStatRemoteHost. Si plusieurs serveurs jstatd sont démarrés sur le même hôte, alors le nom de l'objet RMI exporté pour chaque serveur peut être rendu unique en spécifiant cette option. Cependant, cela nécessite que le nom de serveur unique soit inclus dans les chaînes hostid et vmid du client de surveillance.
-Joption
Cette option passe une option Java à la JVM, où l'option est l'une de celles décrites dans la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java.

SÉCURITÉ

Le serveur jstatd ne peut surveiller que les JVM pour lesquelles il dispose des permissions d'accès natives appropriées. Par conséquent, le processus jstatd doit s'exécuter avec les mêmes identifiants utilisateur que les JVM cibles. Certains identifiants utilisateur, tels que l'utilisateur root sous les systèmes d'exploitation Linux et macOS, ont la permission d'accéder à l'instrumentation exportée par toute JVM du système. Un processus jstatd s'exécutant avec de tels identifiants peut surveiller n'importe quelle JVM du système, mais introduit des préoccupations de sécurité supplémentaires.

Le serveur jstatd ne fournit aucune authentification des clients distants. Par conséquent, l'exécution d'un processus serveur jstatd expose l'instrumentation exportée par toutes les JVM pour lesquelles le processus jstatd a des permissions d'accès à tout utilisateur sur le réseau. Cette exposition peut être indésirable dans votre environnement, et par conséquent, les politiques de sécurité locales doivent être prises en compte avant de démarrer le processus jstatd, en particulier dans les environnements de production ou sur des réseaux non sécurisés.

Pour des raisons de sécurité, le serveur jstatd utilise un RMI ObjectInputFilter pour n'autoriser que les classes essentielles à être désérialisées.

Si vos préoccupations de sécurité ne peuvent pas être résolues, l'action la plus sûre est de ne pas exécuter le serveur jstatd et d'utiliser les outils jstat et jps localement. Cependant, lors de l'utilisation de jps pour obtenir une liste des JVM instrumentées, la liste n'inclura aucune JVM exécutée dans des conteneurs docker.

INTERFACE DISTANTE

L'interface exportée par le processus jstatd est propriétaire et susceptible de changer. Il est déconseillé aux utilisateurs et aux développeurs d'écrire pour cette interface.

EXEMPLES

Les exemples suivants illustrent la commande jstatd. Les scripts jstatd démarrent automatiquement le serveur en arrière-plan.

REGISTRE RMI INTERNE

Cet exemple montre comment démarrer une session jstatd avec un registre RMI interne. Cet exemple suppose qu'aucun autre serveur n'est lié au port par défaut du registre RMI (port 1099).

jstatd

REGISTRE RMI EXTERNE

Cet exemple démarre une session jstatd avec un registre RMI externe.

rmiregistry&
jstatd

Cet exemple démarre une session jstatd avec un serveur de registre RMI externe sur le port 2020.

jrmiregistry 2020&
jstatd -p 2020

Cet exemple démarre une session jstatd avec un serveur de registre RMI externe sur le port 2020 et un connecteur JMX lié au port 2021.

jrmiregistry 2020&
jstatd -p 2020 -r 2021

Cet exemple démarre une session jstatd avec un registre RMI externe sur le port 2020 qui est lié à AlternateJstatdServerName.

rmiregistry 2020&
jstatd -p 2020 -n AlternateJstatdServerName

ARRÊTER LA CRÉATION D'UN REGISTRE RMI IN-PROCESS

Cet exemple démarre une session jstatd qui ne crée pas de registre RMI lorsqu'il n'en trouve pas. Cet exemple suppose qu'un registre RMI est déjà en cours d'exécution. Si aucun registre RMI n'est en cours d'exécution, un message d'erreur s'affiche.

jstatd -nr

ACTIVER LA JOURNALISATION RMI

Cet exemple démarre une session jstatd avec les capacités de journalisation RMI activées. Cette technique est utile comme aide au dépannage ou pour surveiller les activités du serveur.

jstatd -J-Djava.rmi.server.logCalls=true
