JDB(1) Commandes JDK JDB(1)

NOM

jdb - trouver et corriger les bugs dans les programmes de la plateforme Java

SYNTAXE

jdb [options] [nomclasse] [arguments]

options
Ceci représente les options de ligne de commande de jdb. Voir Options pour la commande jdb.
nomclasse
Ceci représente le nom de la classe principale à déboguer.
arguments
Ceci représente les arguments passés à la méthode main() de la classe.

DESCRIPTION

Le débogueur Java (JDB) est un débogueur simple en ligne de commande pour les classes Java. La commande jdb et ses options appellent JDB. La commande jdb démontre l'architecture de débogage de la plateforme Java et fournit l'inspection et le débogage d'une JVM locale ou distante.

DÉMARRER UNE SESSION JDB

Il existe de nombreuses façons de démarrer une session JDB. La façon la plus fréquemment utilisée consiste à faire en sorte que JDB lance une nouvelle JVM avec la classe principale de l'application à déboguer. Faites-le en remplaçant la commande java par la commande jdb sur la ligne de commande. Par exemple, si la classe principale de votre application est MyClass, utilisez la commande suivante pour la déboguer sous JDB :

jdb MyClass

Lorsqu'elle est démarrée de cette manière, la commande jdb appelle une deuxième JVM avec les paramètres spécifiés, charge la classe spécifiée et arrête la JVM avant d'exécuter la première instruction de cette classe.

Une autre façon d'utiliser la commande jdb est de la joindre à une JVM déjà en cours d'exécution. La syntaxe pour démarrer une JVM à laquelle la commande jdb se joint lorsque la JVM est en cours d'exécution est la suivante. Cela charge les bibliothèques de débogage en mémoire et spécifie le type de connexion à établir.

java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n MyClass

Vous pouvez ensuite joindre la commande jdb à la JVM avec la commande suivante :

jdb -attach 8000

8000 est l'adresse de la JVM en cours d'exécution.

L'argument MyClass n'est pas spécifié sur la ligne de commande jdb dans ce cas car jdb se connecte à une JVM existante au lieu de lancer une nouvelle JVM.

Il existe de nombreuses autres façons de connecter le débogueur à une JVM, et toutes sont prises en charge par la commande jdb. L'architecture de débogage de la plateforme Java contient une documentation supplémentaire sur ces options de connexion.

POINTS D'ARRÊT

Les points d'arrêt peuvent être définis dans JDB aux numéros de ligne ou à la première instruction d'une méthode, par exemple :

•
La commande stop at MyClass:22 définit un point d'arrêt à la première instruction de la ligne 22 du fichier source contenant MyClass.
•
La commande stop in java.lang.String.length définit un point d'arrêt au début de la méthode java.lang.String.length.
•
La commande stop in MyClass.<clinit> utilise <clinit> pour identifier le code d'initialisation statique pour MyClass.

Lorsqu'une méthode est surchargée, vous devez également spécifier ses types d'arguments afin que la méthode appropriée puisse être sélectionnée pour un point d'arrêt. Par exemple, MyClass.myMethod(int,java.lang.String) ou MyClass.myMethod().

La commande clear supprime les points d'arrêt en utilisant la syntaxe suivante : clear MyClass:45. Utiliser la commande clear ou stop sans argument affiche une liste de tous les points d'arrêt actuellement définis. La commande cont continue l'exécution.

PAS À PAS

La commande step avance l'exécution à la ligne suivante, qu'elle soit dans le cadre de pile actuel ou dans une méthode appelée. La commande next avance l'exécution à la ligne suivante dans le cadre de pile actuel.

EXCEPTIONS

Lorsqu'une exception se produit pour laquelle il n'y a pas d'instruction catch dans la pile d'appels du thread qui la lance, la JVM imprime généralement une trace d'exception et se termine. Cependant, lorsque vous exécutez sous JDB, le contrôle revient à JDB au niveau de l'instruction de lancement fautive. Vous pouvez alors utiliser la commande jdb pour diagnostiquer la cause de l'exception.

Utilisez la commande catch pour que l'application déboguée s'arrête sur d'autres exceptions lancées, par exemple : catch java.io.FileNotFoundException ou catch mypackage.BigTroubleException. Toute exception qui est une instance de la classe spécifiée ou d'une sous-classe arrête l'application au point où l'exception est lancée.

La commande ignore annule l'effet d'une commande catch antérieure. La commande ignore ne fait pas en sorte que la JVM déboguée ignore des exceptions spécifiques, mais seulement qu'elle ignore le débogueur.

OPTIONS POUR LA COMMANDE JDB

Lorsque vous utilisez la commande jdb à la place de la commande java sur la ligne de commande, la commande jdb accepte de nombreuses options similaires à celles de la commande java.

Les options suivantes sont acceptées par la commande jdb :

-help
Affiche un message d'aide.
-sourcepath dir1:dir2:...
Utilise le chemin spécifié pour rechercher les fichiers source dans le chemin spécifié. Si cette option n'est pas spécifiée, utilise le chemin par défaut du point (.).
-attach adresse
Attache le débogueur à une JVM en cours d'exécution avec le mécanisme de connexion par défaut.
-listen adresse
Attend qu'une JVM en cours d'exécution se connecte à l'adresse spécifiée avec un connecteur standard.
-listenany
Attend qu'une JVM en cours d'exécution se connecte à n'importe quelle adresse disponible à l'aide d'un connecteur standard.
-launch
Démarre l'application déboguée immédiatement au démarrage de la commande jdb. L'option -launch élimine le besoin de la commande run. L'application déboguée est lancée puis arrêtée juste avant le chargement de la classe d'application initiale. À ce stade, vous pouvez définir tous les points d'arrêt nécessaires et utiliser la commande cont pour continuer l'exécution.
-listconnectors
Liste les connecteurs disponibles dans cette JVM.
-connect nom-connecteur:nom1=valeur1....
Se connecte à la JVM cible avec le connecteur nommé et les valeurs d'arguments listés.
-dbgtrace [indicateurs]
Affiche des informations pour le débogage de la commande jdb.
-tclient
Exécute l'application dans le client VM HotSpot de Java.
-trackallthreads
Suivre tous les threads lors de leur création, y compris les threads virtuels. Voir Utilisation des threads virtuels ci-dessous.
-tserver
Exécute l'application dans le serveur VM HotSpot de Java.
-Joption
Transmet option à la JVM JDB, où option est l'une des options décrites dans la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir Aperçu des options Java dans java.

Les options suivantes sont transmises au processus débogué :

-Roption
Transmet option à la JVM déboguée, où option est l'une des options décrites dans la page de référence du lanceur d'applications Java. Par exemple, -R-Xms48m définit la mémoire de démarrage à 48 Mo. Voir Aperçu des options Java dans java.
-v ou -verbose[:classe|gc|jni]
Active le mode verbeux.
-Dnom=valeur
Définit une propriété système.
-classpath dir
Liste les répertoires séparés par des deux-points dans lesquels rechercher les classes.
-X option
Une option de JVM cible non standard.

D'autres options sont prises en charge pour fournir des mécanismes alternatifs pour connecter le débogueur à la JVM qu'il doit déboguer.

UTILISATION DES THREADS VIRTUELS

Souvent, les threads virtuels sont créés en si grand nombre et si fréquemment qu'ils peuvent submerger un débogueur. Pour cette raison, par défaut, JDB ne suit pas les threads virtuels lors de leur création. Il ne suivra que les threads virtuels sur lesquels un événement est arrivé, tel qu'un événement de point d'arrêt. L'option -trackallthreads peut être utilisée pour que JDB suive tous les threads virtuels lors de leur création.

Lorsque JDB se connecte pour la première fois, il demande une liste de tous les threads connus du Deb

ug Agent. Par défaut, l'agent de débogage ne retourne aucun fil virtuel dans cette liste, encore une fois parce que la liste pourrait être si grande qu'elle submerge le débogu

eur. L'agent de débogage possède une option includevirtualthreads qui peut être activée pour changer ce comportement afin que tous les fils virtuels connus soient inclus dans la liste. L'option -trackallthreads de JDB fera que JDB activera automatiquement l'option includevirtualthreads de l'agent de débogage lorsque JDB lance une application à déboguer. Cependant, gardez à l'esprit que l'agent de débogage peut ne pas connaître les fils virtuels qui ont été créés avant que JDB ne se soit attaché à l'application déboguée. 23 DK
