Description détaillée

Signature Web JSON (RFC 7515)

Jeton Web JSON (RFC 7519)

Une Signature Web JSON (JWS) est un format de données standard pour exprimer des signatures cryptographiques en JSON. Les signatures sont produites à l'aide d'une Clé Web JSON (JWK).

Par exemple, pour créer une signature simple d'une chaîne de caractères à l'aide d'une JWK (gestion des erreurs omise) :

json_t *sig(const char *str, const json_t *jwk) {
    json_auto_t *jws = json_pack("{s:o}", "payload",
                                 jose_b64_enc(str, strlen(str)));
    jose_jws_sig(NULL, jws, NULL, jwk);
    return json_incref(jws);
}

De même, pour vérifier cette signature (à nouveau, gestion des erreurs omise) :

char *ver(const json_t *jws, const json_t *jwk) {
    char *str = NULL;
    size_t len = 0;
    if (!jose_jws_ver(NULL, jws, NULL, jwk))
        return NULL;
    len = jose_b64_dec(json_object_get(jws, "payload"), NULL, 0);
    str = calloc(1, len + 1);
    jose_b64_dec(json_object_get(jws, "payload"), str, len);
    return str;
}

Voir aussi :

https://tools.ietf.org/html/rfc7515

Un Jeton Web JSON (JWT) est un format de données standard pour exprimer des assertions transférées entre deux parties en JSON. Le JWT est encapsulé dans un nombre quelconque de Signatures (JWS) ou de Chiffrements (JWE).

bool jose_jws_sig (jose_cfg_t * cfg, json_t * jws, json_t * sig, const json_t * jwk)

Crée une ou plusieurs signatures dans un objet JWS. L'objet JWS (jws) doit contenir la propriété 'payload'.

Toutes les signatures créées seront ajoutées au JWS spécifié par jws. Si le JWS résultant (jws) ne contient qu'une seule signature, le JWS sera représenté dans la syntaxe de sérialisation JSON JWS aplatie. Sinon, il sera représenté dans la syntaxe de sérialisation JSON JWS générale.

Si jwk contient une JWK, une seule signature est créée. Dans ce cas, jws doit contenir soit un modèle d'objet de signature JWS, soit NULL. Vous pouvez spécifier des algorithmes ou d'autres comportements de signature en les spécifiant simplement dans les en-têtes JOSE du modèle d'objet de signature JWS tels que définis par la RFC 7515. Si une propriété requise est manquante, des valeurs par défaut sensées seront utilisées et insérées dans les en-têtes JOSE ; elles seront déduites de la JWK (jwk) lorsque cela est possible.

Si jwk contient un tableau de JWKs ou un JWKSet, plusieurs signatures sont créées. Dans ce cas, le paramètre sig doit contenir l'une des valeurs suivantes :

1.
Un modèle d'objet de signature JWS qui sera utilisé pour toutes les signatures. Dans ce cas, une copie sera faite pour chaque signature et sig ne sera modifié d'aucune manière.
2.
Un tableau de modèles d'objets de signature JWS. Chaque modèle sera utilisé avec sa JWK correspondante de jwk. Si les tableaux de sig et de jwk ont une taille différente, une erreur se produira.
3.
NULL. Cela a le même effet que de passer NULL pour chaque clé distincte.

Paramètres :

cfg Le contexte de configuration (facultatif).
jws L'objet JWS.
sig Le(s) modèle(s) d'objet de signature JWS ou NULL.
jwk La(les) JWK(s) ou JWKSet utilisée(s) pour créer les signatures.

Retourne :

En cas de succès, true. Sinon, false.

jose_io_t* jose_jws_sig_io (jose_cfg_t * cfg, json_t * jws, json_t * sig, const json_t * jwk)

Crée une ou plusieurs signatures dans un objet JWS en utilisant le streaming. Cette fonction se comporte essentiellement comme jose_jws_sig() sauf :

La charge utile n'est pas spécifiée dans le JWS (jws). Plutôt, la charge utile est fournie à l'aide de l'objet IO retourné. L'entrée de l'objet IO retourné ne sera pas encodée en interne en Base64. Vous devrez peut-être préfixer la chaîne IO avec le résultat de jose_b64_enc_io() (selon votre situation).

De même, la charge utile n'est pas stockée dans l'objet JWS (jws). Cela permet des charges utiles séparées et diminue l'utilisation de la mémoire pour les signatures sur de grandes charges utiles. Si vous souhaitez attacher la charge utile, il vous incombe de le faire manuellement.

Paramètres :

cfg Le contexte de configuration (facultatif).
jws L'objet JWS.
sig Le(s) modèle(s) d'objet de signature JWS ou NULL.
jwk La(les) JWK(s) ou JWKSet utilisée(s) pour créer les signatures.

Retourne :

Le nouvel objet IO ou NULL en cas d'erreur.

bool jose_jws_ver (jose_cfg_t * cfg, const json_t * jws, const json_t * sig, const json_t * jwk, bool all)

Vérifie les signatures d'une ou plusieurs JWKs dans un objet JWS. L'objet JWS (jws) doit contenir la propriété 'payload'.

Si une seule JWK (jwk) est spécifiée, le paramètre all est ignoré. Dans ce cas, si vous souhaitez vérifier un objet de signature JWS particulier, vous pouvez le spécifier à l'aide du paramètre sig. Sinon, vous pouvez simplement passer NULL pour vérifier l'un des objets de signature JWS dans l'objet JWS.

Si jwk contient un tableau de JWKs ou un JWKSet, le paramètre all détermine si une signature valide est requise pour chaque JWK afin de valider le JWS avec succès. Par exemple, si vous définissez all à false, cette fonction réussira si une signature valide est trouvée pour l'une des JWKs fournies. Lors de l'utilisation de ce mode de signature multiple JWK, le paramètre sig doit contenir l'une des valeurs suivantes :

1.
Un seul objet de signature JWS à valider contre toutes/n'importe lesquelles des JWKs fournies.
2.
Un tableau d'objets de signature JWS. Dans ce cas, chaque objet de signature JWS sera associé à sa JWK correspondante de jwk. Si les tableaux de sig et de jwk ont une taille différente, une erreur se produira.
3.
NULL. Cela a le même effet que de passer NULL pour chaque clé distincte.

Paramètres :

cfg Le contexte de configuration (facultatif).
jws L'objet JWS.
sig Le(s) objet(s) de signature JWS à vérifier ou NULL.
jwk La(les) JWK(s) ou JWKSet utilisée(s) pour vérifier les signatures.
all Si la validation de toutes les JWKs est requise ou non.

Retourne :

En cas de succès, true. Sinon, false.

jose_jws_ver_stream

Vérifie les signatures d'un ou plusieurs JWK dans un objet JWS en utilisant le streaming. Cette fonction se comporte essentiellement comme jose_jws_ver() sauf que :

La charge utile n'est pas spécifiée dans le JWS (jws). Plutôt, la charge utile est fournie en utilisant l'objet IO retourné. L'entrée de l'objet IO retourné ne sera pas encodée en interne en Base64. Vous devrez donc peut-être préfixer la chaîne IO avec le résultat de jose_b64_enc_io() (selon votre situation).

La vérification finale de la signature est retardée jusqu'à ce que jose_io_t::done() retourne.

Paramètres :

cfg Le contexte de configuration (optionnel).
jws L'objet JWS.
sig L'objet(s) de signature JWS à vérifier ou NULL.
jwk Le(s) JWK ou JWKSet utilisé(s) pour vérifier les signatures.
all Si la validation de tous les JWK est requise ou non.

Retours :

Le nouvel objet IO ou NULL en cas d'erreur.
