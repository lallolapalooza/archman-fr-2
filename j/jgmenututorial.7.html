Leçon 1 - Démarrage

Après avoir installé jgmenu, lancez le menu en exécutant la commande suivante :

jgmenu_run

Vous devriez voir un menu système Linux/BSD affichant les applications installées. Voir la leçon 7 pour plus de détails.

Créez un fichier de configuration (~/.config/jgmenu/jgmenurc) en exécutant :

jgmenu_run init

Les détails complets des options de configuration sont couverts dans jgmenu(1) (jgmenu.1.html).

En entrant en mode interactif puis en sélectionnant `t', vous pouvez essayer certains modèles/thèmes prédéfinis.

jgmenu_run init -i

Il existe un petit nombre d'options de configuration qui peuvent nécessiter une intervention manuelle pour que jgmenu s'affiche correctement sur votre système.

position_mode
Il existe plusieurs méthodes pour positionner le menu. Essayez `fixed', `ipc', `center' et `pointer' pour voir ce qui fonctionne le mieux sur votre système. Voir jgmenu(1) pour les détails complets.
menu_margin_x et menu_margin_y
Si vous utilisez `position_mode=fixed', vous devrez peut-être définir ces deux variables. Selon le gestionnaire de fenêtres et le panneau que vous utilisez, jgmenu peut être capable de trouver automatiquement une position verticale et horizontale appropriée, alors essayez sans définir ces variables d'abord.
menu_halign et menu_valign
Là encore, selon votre système, vous pourriez avoir besoin de spécifier manuellement l'alignement horizontal et vertical du menu, mais essayez sans d'abord.

Leçon 2 - Architecture

La conception de jgmenu est très modulaire, offrant une grande flexibilité dans son utilisation.

Lorsque jgmenu est lancé, deux processus sont exécutés pour produire le menu.

┌────────────────┐
│ générateur-csv  │
└────────────────┘
        |
        V
┌────────────────┐
│ menu graphique │
└────────────────┘

Le premier processus (générateur-csv) produit le contenu du menu, tandis que le second génère le menu graphique.

jgmenu_run(1) (jgmenu_run.1.html) est un script wrapper polyvalent qui fait ce qui suit en pseudo-code :

si (jgmenu est déjà en cours d'exécution)
        afficher le menu
sinon
        lancer une nouvelle instance de jgmenu

Cela le rend adapté à une utilisation avec des panneaux et des raccourcis clavier.

Leçon 3 - Scripting avec jgmenu

À partir de maintenant, on suppose que vous comprenez l'utilisation de base du shell, y compris la redirection (par exemple, <, >) et le piping (par exemple, |).

La syntaxe ci-dessous (ici-document) est utilisée pour indiquer la création d'un fichier texte à partir de tout ce qui se trouve entre les EOF. Vous pouvez bien sûr utiliser votre éditeur de texte préféré à la place.

cat >fichier <<EOF
foo
bar
EOF

Il existe de nombreuses façons de lancer jgmenu. Dans la leçon 1, vous avez vu jgmenu comme une application de longue durée. Au fur et à mesure des prochaines leçons, nous lancerons jgmenu comme une application de courte durée. Cela signifie qu'il démarre à zéro à chaque fois qu'il est appelé.

Alors revenons aux bases. Essayez ce qui suit :

echo >foo.txt <<EOF
xterm
firefox
EOF

Si vous n'êtes pas encore familiarisé avec la syntaxe here-document, cela signifie simplement que vous placez les mots « xterm » et « firefox » dans un fichier texte (ce que vous pouvez bien sûr faire en utilisant un éditeur de texte). Ensuite, exécutez l'une des commandes suivantes :

cat foo.txt | jgmenu --simple --icon-size=0
jgmenu --vsimple --csv-file="foo.txt"

L'option --simple rend jgmenu de courte durée et lit les éléments du menu depuis stdin.

L'option --icon-size=0 désactive les icônes (c'est-à-dire qu'elle ne les affiche pas simplement à taille zéro, elle ne les charge tout simplement pas).

L'argument de ligne de commande --vsimple est identique à --simple, mais désactive également les icônes et ignore jgmenurc (s'il existe).

Si vous souhaitez qu'un menu soit lancé par un seul script, vous pouvez le construire comme ceci :

cat <<EOF >menu.sh
#!/bin/sh
(
printf "foo\n"
printf "bar\n"
) | jgmenu --vsimple
EOF
chmod +x menu.sh
./menu.sh

Leçon 4 - Descriptions

Comme vous l'avez vu dans l'exemple précédent, chaque ligne fournie à stdin devient un élément de menu. Toute ligne contenant deux champs séparés par une virgule est analysée comme description,commande. Considérez les données de menu CSV suivantes :

Terminal,xterm
Gestionnaire de fichiers,pcmanfm

Cela vous permet de donner une description plus significative à chaque élément du menu.

Leçon 5 - Icônes

Pour afficher des icônes, vous devez remplir le troisième champ. Par défaut, jgmenu obtiendra le thème d'icônes à partir des xsettings (s'il est en cours d'exécution) ou de tint2rc (s'il existe). Lors de l'exécution avec l'argument --simple, assurez-vous que `icon_theme` est défini sur quelque chose de sensé dans votre $HOME/.config/jgmenu/jgmenurc. Considérez les données de menu CSV suivantes :

Navigateur,        firefox,               firefox
Gestionnaire de fichiers,   pcmanfm,               system-file-manager
Terminal,       xterm,                 utilities-terminal
Verrouiller,         i3lock -c 000000,      system-lock-screen

Leçon 5 - Icônes

Les icônes peuvent être spécifiées soit par le nom d'un thème d'icônes, soit par le chemin complet vers un fichier image. Si vous spécifiez un nom d'icône, il est recommandé de le faire en utilisant le balisage spécial : ^icon(nom_icône).

Cela permet à jgmenu de rechercher l'icône dans les thèmes d'icônes installés.

Par exemple :

Log Out,         openbox --exit,        system-log-out
Redémarrer,        systemctl -i reboot,   system-reboot
Éteindre,       systemctl -i poweroff, system-shutdown

Dans le troisième champ, vous pouvez également spécifier le chemin complet si vous le souhaitez.

Leçon 6 - Sous-menus

Jusqu'à présent, nous avons vu comment produire uniquement un menu "racine" unique. jgmenu comprend une petite quantité de balisage et permet les sous-menus via ^tag() et ^checkout(). Essayez ceci :

Terminal,xterm
Gestionnaire de fichiers,pcmanfm
Paramètres,^checkout(settings)
^tag(settings)
Définir l'image de fond,nitrogen

En pseudo-code, construisez votre fichier CSV comme suit :

# le menu-racine
item0.0
item0.1
sub1,^checkout(1)
sub2,^checkout(2)
# le premier sous-menu
^tag(1)
item1.0
item1.1
# le deuxième sous-menu
^tag(2)
item2.0
item2.1

^root() peut être utilisé à la place de ^checkout() afin d'ouvrir le sous-menu dans la fenêtre parente.

Leçon 7 - Menus d'applications XDG

XDG (freedesktop.org) a défini une spécification de menu de bureau Linux/BSD qui est suivie par les grands environnements de bureau. Voir menu-spec (http://specifications.freedesktop.org/menu-spec/latest/) pour plus de détails. En bref, il existe trois types de fichiers qui définissent un menu XDG :

.menu
Fichier XML décrivant les catégories de menu et la structure du répertoire. Situé dans /etc/xdg/menus/, ou l'équivalent XDG_CONFIG_{HOME,DIRS}.
.directory
Décrit les répertoires de menu. Situé dans /usr/share/desktop-directories/, ou l'équivalent XDG_DATA_{HOME,DIRS}.
.desktop
Décrit les applications et contient la plupart des informations nécessaires à la construction d'un menu (par exemple, Nom, commande Exec, Icône et Catégorie). Situé dans /usr/share/applications/, ou l'équivalent XDG_DATA_{HOME,DIRS}.

La plupart des applications de bureau fournissent leurs propres fichiers .desktop associés, tandis que les fichiers .menu et .directory sont fournis par des paquets de menus, tels que libmenu-cache (LXDE) et libcargon (XFCE).

Le module de base jgmenu jgmenu-apps(1) (jgmenu-apps.1.html) fournit un menu système basé sur les fichiers .desktop et les données de schéma intégrées ou un fichier de schéma spécifié, plutôt que sur les fichiers .menu et .directory du système. Bien que cela s'écarte de la spécification de menu XDG, il est beaucoup plus simple à comprendre et à ajuster. Cela évite également la dépendance aux paquets de menus.

Pour une conformité XDG stricte, le module optionnel jgmenu-lx(1) (jgmenu-lx.1.html) peut être utilisé.

Voir la Leçon 10 pour des instructions générales sur les modules.

Leçon 8 - Options de configuration

Dans la leçon 1, nous avons discuté des options de configuration position_mode, menu_margin_x, menu_margin_y, menu_halign et menu_valign.

Voici quelques options supplémentaires que vous pourriez explorer. Pour plus de détails, voir jgmenu(1) (jgmenu.1.html).

Style Rofi :

csv_no_dirs=1
csv_single_window=1
columns=2
menu_width=600
menu_valign=center
menu_halign=center

Synchroniser les couleurs, la police et les icônes avec le panneau tint2

tint2_look=1

Leçon 9 - Ajouter/Précéder et Séparateurs

Lors de l'utilisation de apps, pmenu ou lx, vous pouvez ajouter des éléments de menu en haut et en bas du menu racine en modifiant append.csv et/ou prepend.csv dans ~/.config/jgmenu. Par exemple, essayez ce qui suit :

prepend.csv

Navigateur,               firefox,               firefox
Gestionnaire de fichiers, pcmanfm,               system-file-manager
Terminal,     xterm,                 utilities-terminal
^sep()

append.csv

^sep()
Suspendre,      systemctl -i suspend,  system-log-out
Redémarrer,       systemctl -i reboot,   system-reboot
Éteindre,     systemctl -i poweroff, system-shutdown

Dans ces exemples, nous avons utilisé le balisage ^sep(), qui insère une ligne de séparation horizontale. De même, ^sep(foo) insère un séparateur de texte affichant "foo".

Leçon 10 - Générateurs CSV

Dans les leçons précédentes, nous avons introduit apps, lx et pmenu. Ces modules sont appelés "générateurs CSV" et sont invoqués comme suit :

jgmenu_run <commande>

Les "générateurs CSV" intégrés incluent : apps et ob.

Les "générateurs CSV" optionnels incluent : lx et pmenu.

Ils sont documentés par une page de manuel ou un simple message --help.

man jgmenu-<commande>
jgmenu_run <commande> --help

Voici quelques exemples de la façon dont ils peuvent être utilisés.

Spécifiez le générateur CSV dans le fichier de configuration en définissant csv_cmd dans ~/.config/jgmenu/jgmenurc

csv_cmd = pmenu

Spécifiez le générateur CSV sur la ligne de commande

jgmenu --csv-cmd="jgmenu_run pmenu"

Transmettez la sortie CSV à jgmenu (en utilisant --simple pour lire depuis stdin)

jgmenu_run pmenu | jgmenu --simple

Créez un pipemenu en utilisant le balisage ^pipe(). Considérez cet exemple

Terminal,xterm
Gestionnaire de fichiers,pcmanfm
^pipe(jgmenu_run pmenu)

Leçon 11 - Recherche

jgmenu prend en charge la recherche, qui peut être activée en tapant simplement lorsque le menu est ouvert.

Une boîte de recherche peut être insérée à l'aide de widgets. Par exemple, ajoutez ceci à ~/.config/jgmenu/prepend.csv :

@search,,3,3,150,20,2,left,top,auto,#000000 0,Tapez pour rechercher

Assurez-vous d'ajuster le remplissage du menu en conséquence, par exemple :

menu_padding_top=24

Une recherche peut également être activée en associant un widget à une commande ^filter().
