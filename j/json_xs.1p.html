NOM

json_xs - Utilitaire en ligne de commande JSON::XS

SYNOPSIS

json_xs [-v] [-f format_entree] [-t format_sortie]

DESCRIPTION

json_xs convertit entre certains formats d'entrée et de sortie (dont l'un est JSON).

Le format d'entrée par défaut est "json" et le format de sortie par défaut est "json-pretty".

OPTIONS

-v
Être légèrement plus verbeux.
-f format_entree
Lire un fichier dans le format donné depuis STDIN.

"format_entree" peut être l'un des suivants :

json - un texte json encodé, soit utf-8, utf16-be/le, utf32-be/le
cbor - CBOR (RFC 7049, CBOR::XS), une sorte de JSON binaire
storable - une valeur Storable gelée
storable-file - un fichier Storable (Storable a deux formats incompatibles)
bencode - utiliser Convert::Bencode, si disponible (utilisé par les fichiers torrent, entre autres)
clzf - format Compress::LZF (nécessite que ce module soit installé)
eval - évaluer le code donné comme Perl (non-utf-8), essentiellement l'inverse de "-t dump"
yaml - format YAML (nécessite que ce module soit installé)
string - ne pas tenter de décoder les données du fichier
none - rien n'est lu, crée un scalaire "undef" - principalement utile avec "-e"
-t format_sortie
Écrire le fichier dans le format donné sur STDOUT.

"format_sortie" peut être l'un des suivants :

json, json-utf-8 - json, encodé en utf-8
json-pretty - comme ci-dessus, mais avec indentation
json-utf-16le, json-utf-16be - utf-16 little endian/big endian
json-utf-32le, json-utf-32be - utf-32 little endian/big endian
cbor - CBOR (RFC 7049, CBOR::XS), une sorte de JSON binaire
cbor-packed - CBOR utilisant des extensions pour le rendre plus petit
storable - une valeur Storable gelée au format réseau
storable-file - un fichier Storable au format réseau (Storable a deux formats incompatibles)
bencode - utiliser Convert::Bencode, si disponible (utilisé par les fichiers torrent, entre autres)
clzf - format Compress::LZF
yaml - format YAML::XS
dump - Data::Dump
dumper - Data::Dumper
string - écrit les données comme si c'était une chaîne de caractères
none - rien n'est écrit, principalement utile avec "-e"
Notez que Data::Dumper ne gère pas correctement les structures de données autoréférentielles - utilisez "dump" à la place.
-e code
Évaluer du code perl après avoir lu les données et avant de les réécrire - peut être utilisé pour filtrer, créer ou extraire des données. Les données qui ont été écrites sont dans $_, et ce qui s'y trouve est écrit ensuite.

EXEMPLES

json_xs -t none <isitreally.json

"JSON Lint" - essaie de parser le fichier isitreally.json comme JSON - s'il s'agit de JSON valide, la commande ne produit rien, sinon elle affichera un message d'erreur et se terminera avec un code de sortie non nul.

<src.json json_xs >pretty.json

Mettre en forme joliment le fichier JSON src.json dans dst.json.

json_xs -f storable-file <file

Lire le fichier Storable sérialisé file et imprimer une version JSON lisible par l'homme sur STDOUT.

json_xs -f storable-file -t yaml <file

Identique à ci-dessus, mais écrire du YAML à la place (sans utiliser du tout JSON :)

json_xs -f none -e '$_ = [1, 2, 3]'

Afficher le tableau perl comme texte JSON encodé en UTF-8.

<torrentfile json_xs -f bencode -e '$_ = join "\n", map @$_, @{$_->{"announce-list"}}' -t string

Imprimer la liste des trackers à l'intérieur d'un fichier torrent.

lwp-request http://cpantesters.perl.org/show/JSON-XS.json | json_xs

Récupérer le résumé des résultats cpan-testers "JSON::XS" et l'afficher joliment.
