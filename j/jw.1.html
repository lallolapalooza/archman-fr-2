|default|none |--dsl fichier |default|none Permet d'utiliser
une
feuille de style personnalisée au lieu de la feuille de styleault one.

Une « cible » commençant par un dièse « # » peut être ajoutée au nom du fichier. Par conséquent, seule la partie correspondante de la feuille de style est exécutée (la « spécification de style » dont l'« identifiant » est égal au nom de la cible). Une utilisation courante de ce mécanisme est de définir les cibles « #html » et « #print » pour déclencher la partie correspondante d'une feuille de style de remplacement commune aux deux conversions HTML et impression.

En remplaçant le nom du fichier par « default », la feuille de style par défaut fournie avec le frontend est utilisée. Par exemple, le frontend docbook renvoie ./docbook.dsl#html (ou ./docbook.dsl#print) dans le répertoire de base SGML.

En remplaçant le nom du fichier par « none », aucune feuille de style de remplacement n'est utilisée, pas même la feuille de style par défaut. La feuille de style utilisée est également déterminée par le frontend. Par exemple, le frontend docbook renvoie html/docbook.dsl (ou print/docbook.dsl) de Norman Walsh trouvé quelque part sous le répertoire de base SGML.

Si aucune option --dsl n'est spécifiée, alors "--dsl default" est utilisé.

-l fichier | --dcl fichier
Permet d'utiliser une déclaration SGML personnalisée au lieu de la déclaration par défaut. Le nom du fichier de la déclaration SGML par défaut n'est pas défini pour les fichiers SGML, et est défini sur xml.dcl dans le répertoire de base SGML pour les fichiers XML.
-s chemin | --sgmlbase chemin
Permet d'utiliser un autre emplacement pour le répertoire de base SGML. C'est le répertoire sous lequel toutes les DTD SGML, feuilles de style, entités, etc. sont installées. La valeur par défaut est /usr/share/sgml.
-p programme | --parser programme
Spécifie l'analyseur à utiliser (Jade ou OpenJade) si plusieurs sont installés. Si cette option n'est pas spécifiée, le script essaie d'abord d'utiliser Jade, puis il essaie OpenJade.
-o répertoire | --output répertoire
Définit le répertoire de sortie où tous les fichiers résultants seront stockés. Si les feuilles de style définissent un sous-répertoire où stocker également les fichiers résultants, le sous-répertoire défini par les feuilles de style sera placé sous le sous-répertoire défini par cette option.
-V variable=[valeur]
Définit une variable (à une valeur, si une est spécifiée).
-u | --nochunks
Produit un seul gros fichier. Cette option n'est utile que lors de la génération de HTML, car la sortie peut être divisée en plusieurs fichiers. Cette option annule le réglage qui peut être fait dans les feuilles de style.
-i section | --include section
Déclare une section marquée SGML comme « include ». Une section marquée SGML est un type de partie conditionnelle d'un document. Si elle est déclarée « ignore », elle sera ignorée, sinon elle sera traitée. Un exemple d'une telle section marquée serait :
            <DOCTYPE mydoc [
              <!ENTITY % confidential "ignore">
            ]>
            <mydoc>
              ...
              <![ %confidential [ Some confidential text... ]]>
              ...
            </mydoc>
-w type|list | --warning type|list
Active ou désactive l'affichage de types d'avertissements donnés. Plusieurs options -w peuvent être saisies sur la ligne de commande. Les types d'avertissements qui commencent par « no- » désactivent les avertissements correspondants, les autres types les activent.

Si le type d'avertissement est remplacé par « list », une liste des types d'avertissements autorisés est affichée.

-e type|list | --error type|list
Désactive les types d'erreurs donnés. Plusieurs options -e peuvent être saisies sur la ligne de commande. Tous les types d'erreurs commencent par « no- ».

Si le type d'erreur est remplacé par « list », une liste des types d'erreurs autorisés est affichée.

-h | --help
Affiche un court message d'aide et quitte
-v | --version
Affiche l'identifiant de la version et quitte
