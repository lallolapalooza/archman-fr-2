Paquet: jdk8-openjdk

jar(1) Outils de base jar(1)

NOM

jar - Manipule les fichiers Java Archive (JAR).

SYNOPIS

Créer un fichier JAR

jar c[efmMnv0] [point_entrée] [fichier_jar] [manifeste] [-C rép] fichier ... [-Joption ...] [@fichier_args ...]

Mettre à jour un fichier JAR

jar u[efmMnv0] [point_entrée] [fichier_jar] [manifeste] [-C rép] fichier ... [-Joption ...] [@fichier_args ...]

Extraire un fichier JAR

jar x[vf] [fichier_jar] fichier ... [-Joption ...] [@fichier_args ...]

Lister le contenu d'un fichier JAR

jar t[vf] [fichier_jar] fichier ... [-Joption ...] [@fichier_args ...]

Ajouter un index à un fichier JAR

jar i fichier_jar [-Joption ...] [@fichier_args ...]

DESCRIPTION

La commande jar est un outil d'archivage et de compression à usage général, basé sur le format ZIP et la compression ZLIB. Cependant, la commande jar a été conçue principalement pour regrouper des applets ou des applications Java dans une seule archive. Lorsque les composants d'une applet ou d'une application (fichiers, images et sons) sont combinés en une seule archive, ils peuvent être téléchargés par un agent Java (tel qu'un navigateur) en une seule transaction HTTP, plutôt que d'exiger une nouvelle connexion pour chaque pièce. Cela améliore considérablement les temps de téléchargement. La commande jar compresse également les fichiers, ce qui améliore encore le temps de téléchargement. La commande jar permet également de signer individuellement des entrées dans un fichier par l'auteur de l'applet afin que leur origine puisse être authentifiée. Un fichier JAR peut être utilisé comme une entrée du chemin de classe, qu'il soit compressé ou non.

La syntaxe de la commande jar ressemble à celle de la commande tar. Elle dispose de plusieurs modes d'opération, définis par l'un des arguments d'opération obligatoires. D'autres arguments sont soit des options qui modifient le comportement de l'opération, soit des opérandes requis pour effectuer l'opération.

ARGUMENTS D'OPÉRATION

Lors de l'utilisation de la commande jar, vous devez sélectionner une opération à effectuer en spécifiant l'un des arguments d'opération suivants. Vous pouvez les mélanger avec d'autres options à une lettre sur la ligne de commande, mais généralement l'argument d'opération est le premier argument spécifié.

c
Crée une nouvelle archive JAR.
i
Génère des informations d'index pour une archive JAR.
t
Liste le contenu d'une archive JAR.
u
Met à jour une archive JAR.
x
Extrait des fichiers d'une archive JAR.

OPTIONS

Utilisez les options suivantes pour personnaliser la façon dont le fichier JAR est créé, mis à jour, extrait ou visualisé :

e
Définit la classe spécifiée par l'opérande point_entrée comme étant le point d'entrée d'une application Java autonome intégrée dans un fichier JAR exécutable. L'utilisation de cette option crée ou remplace la valeur de l'attribut Main-Class dans le fichier manifeste. L'option e peut être utilisée lors de la création (c) ou de la mise à jour (u) du fichier JAR.

Par exemple, la commande suivante crée l'archive Main.jar avec le fichier Main.class où la valeur de l'attribut Main-Class est définie sur Main :

jar cfe Main.jar Main Main.class

L'environnement d'exécution Java (JRE) peut appeler directement cette application en exécutant la commande suivante :

java -jar Main.jar

Si le nom de la classe d'entrée se trouve dans un package, il peut utiliser le point (.) ou la barre oblique (/) comme délimiteur. Par exemple, si Main.class se trouve dans un package appelé mydir, alors le point d'entrée peut être spécifié de l'une des manières suivantes :

jar -cfe Main.jar mydir/Main mydir/Main.class
jar -cfe Main.jar mydir.Main mydir/Main.class

Note

La spécification des options m et e ensemble lorsqu'un manifeste particulier contient également l'attribut Main-Class entraîne une spécification ambiguë de Main-Class. L'ambiguïté entraîne une erreur et l'opération de création ou de mise à jour de la commande jar est terminée.

f
Définit le fichier spécifié par l'opérande fichier_jar comme étant le nom du fichier JAR qui est créé (c), mis à jour (u), extrait (x) ou dont le contenu est visualisé (t). Omettre l'option f et l'opérande fichier_jar demande à la commande jar d'accepter le nom du fichier JAR depuis stdin (pour x et t) ou d'envoyer le fichier JAR vers stdout (pour c et u).
m
Inclut les noms et valeurs des attributs du fichier spécifié par l'opérande manifeste dans le fichier manifeste de la commande jar (situé dans l'archive à l'emplacement META-INF/MANIFEST.MF). La commande jar ajoute le nom et la valeur de l'attribut au fichier JAR, sauf si une entrée existe déjà avec le même nom, auquel cas la commande jar met à jour la valeur de l'attribut. L'option m peut être utilisée lors de la création (c) ou de la mise à jour (u) du fichier JAR.

Vous pouvez ajouter des paires d'attributs nom-valeur spéciales au manifeste qui ne sont pas contenues dans le fichier manifeste par défaut. Par exemple, vous pouvez ajouter des attributs qui spécifient des informations sur le fournisseur, des informations de publication, l'étanchéité des paquets, ou pour rendre exécutables les applications groupées dans des JAR. Pour des exemples d'utilisation de l'option m, voir Packaging Programs à http://docs.oracle.com/javase/tutorial/deployment/jar/index.html

M
Ne crée pas d'entrée de fichier manifeste (pour c et u), ou supprime une entrée de fichier manifeste lorsqu'elle existe (pour u). L'option M peut être utilisée lors de la création (c) ou de la mise à jour (u) du fichier JAR.
n
Lors de la création (c) d'un fichier JAR, cette option normalise l'archive afin que le contenu ne soit pas affecté par les opérations de paquetage et de déballage de la commande pack200(1). Sans cette normalisation, la signature d'un JAR signé peut devenir invalide.
v
Génère une sortie détaillée sur la sortie standard. Voir Exemples.
0
(Zéro) Crée (c) ou met à jour (u) le fichier JAR sans utiliser la compression ZIP.
-C rép

Lors de la création (c) ou de la mise à jour (u) d'un fichier JAR, cette option change temporairement de répertoire lors du traitement des fichiers spécifiés par les opérandes fichier. Son opération est destinée à être similaire à l'option -C de l'utilitaire UNIX tar. Par exemple, la commande suivante passe dans le répertoire classes et ajoute le fichier Bar.class de ce répertoire à my.jar : 
jar uf my.jar -C classes Bar.class

La commande suivante passe dans le répertoire classes et ajoute à my.jar tous les fichiers du répertoire classes (sans créer de répertoire classes dans le fichier JAR), puis revient au répertoire d'origine avant de passer dans le répertoire bin pour ajouter Xyz.class à my.jar.

jar uf my.jar -C classes . -C bin Xyz.class

Si classes contenait les fichiers bar1 et bar2, alors le fichier JAR contiendra ce qui suit après l'exécution de la commande précédente :

% jar tf my.jar
META-INF/
META-INF/MANIFEST.MF
bar1
bar2
Xyz.class
-Joption
Définit l'option JVM spécifiée
n à utiliser lorsque la JRE exécute le fichier JAR. Les options JVM sont décrites sur la page de référence de la commande java(1). Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo.

@arg-fi
le
Pour raccourcir ou simplifier la commande jar, vous pouvez spécifier les arguments dans un fichier texte séparé et le passer à la commande jar avec le signe arobase (@) comme préfixe. Lorsque la commande jar rencontre un argument commençant par le signe arobase, elle développe le contenu de ce fichier dans la liste d'arguments.

Un fichier d'arguments peut inclure les options et arguments de la commande jar (sauf les options -J, car elles sont transmises au lanceur, qui ne prend pas en charge les fichiers d'arguments). Les arguments dans un fichier peuvent être séparés par des espaces ou des caractères de nouvelle ligne. Les noms de fichiers dans un fichier d'arguments sont relatifs au répertoire courant depuis lequel vous exécutez la commande jar, et non relatifs à l'emplacement du fichier d'arguments. Les caractères génériques, tels que l'astérisque (*), qui pourraient autrement être développés par le shell du système d'exploitation, ne sont pas

développés.

L'exemple suivant montre comment créer un fichier classes.list avec les noms des fichiers du répertoire courant produits par la commande f

ind : 
find . -name '*.class' -print > classes.
list

Vous pouvez ensuite exécuter la commande jar et lui passer le fichier classes.list en utilisant la syntaxe @arg-

file : 
jar cf my.jar @classes.
list

Un fichier d'arguments peut être spécifié avec un chemin, mais tout nom de fichier à l'intérieur du fichier d'arguments ayant des chemins relatifs est relatif au répertoire de travail courant de la commande jar, et non au chemin passé, par

exemple : 
jar @dir/classes.
list

Exemple 4 Ajout d'un

index

Utilisez l'option i lorsque vous divisez les classes interdépendantes d'une application de trading en trois fichiers JAR : main.jar, buy.jar et sell.jar. Si vous spécifiez l'attribut Class-Path dans le manifeste de main.jar, vous pouvez utiliser l'option i pour accélérer le temps de chargement des classes de votre application

: 
Class-Path: buy.jar sell.
jar 
jar i main.
jar

Un fichier INDEX.LIST est inséré dans le répertoire META-INF. Cela permet au chargeur de classes de l'application de télécharger les fichiers JAR spécifiés lorsqu'il recherche des classes ou des

ressources.

Le chargeur de classes de l'application utilise les informations stockées dans ce fichier pour un chargement de classes efficace. Pour copier des répertoires, compressez d'abord les fichiers de dir1 vers stdout, puis acheminez-les par un pipeline et extrayez depuis stdin vers dir2 (en omettant l'option -f des deux commandes jar)

: 
(cd dir1; jar c .) | (cd dir2; jar
