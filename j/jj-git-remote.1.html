jj-git-remote(1) Manuel des commandes générales jj-git-remote(1)

NOM

jj-git-remote - Gérer les dépôts distants Git

SYNTAXE

jj git remote [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <sous-commandes>

DESCRIPTION

Gérer les dépôts distants Git

Le dépôt Git sera un dépôt Git nu stocké dans le répertoire `.jj/`.

OPTIONS

-h, --help
Afficher l'aide (voir un résumé avec '-h')

OPTIONS GLOBALES

-R, --repository <DÉPÔT>
Chemin vers le dépôt à traiter

Par défaut, Jujutsu recherche le répertoire `.jj/` le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas enregistrer la copie de travail et ne pas la mettre à jour

Par défaut, Jujutsu enregistre la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter d'enregistrer la copie de travail et voir plutôt un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile, par exemple, dans une invite de commande, surtout si un autre processus commit la copie de travail.

Le chargement du dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Permettre la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé `immutable` du modèle.

--at-operation <OPÉRATION_À>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID de l'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple `jj --at-op=<ID de l'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération que vous voulez. N'importe quel préfixe non ambigu de l'ID de l'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Le faire est équivalent à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Silencier la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été enregistrée ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le pagineur
--config <NOM=VALEUR>
Options de configuration supplémentaires (peuvent être répétées)

Le nom doit être spécifié sous forme de clés pointées TOML. La valeur doit être spécifiée comme une expression TOML. Si une valeur chaîne n'est pas entourée de constructions TOML (comme la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés)
