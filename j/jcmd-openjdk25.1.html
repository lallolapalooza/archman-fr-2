JCMD(1) Commandes JDK JCMD(1)

NOM

jcmd - envoyer des requêtes de commandes de diagnostic à une Machine Virtuelle Java (JVM) en cours d'exécution

SYNOPSIS

jcmd [pid | main-class] command... | PerfCounter.print | -f filename

jcmd [-l]

jcmd -h

pid
Lorsqu'il est utilisé, l'utilitaire jcmd envoie la requête de commande de diagnostic à l'identifiant de processus du processus Java.
main-class
Lorsqu'il est utilisé, l'utilitaire jcmd envoie la requête de commande de diagnostic à tous les processus Java ayant le nom de classe principale spécifié.
command
Le command doit être une commande jcmd valide pour la JVM sélectionnée. La liste des commandes disponibles pour jcmd s'obtient en exécutant la commande help (jcmd pid help) où pid est l'identifiant de processus du processus Java en cours d'exécution.
Perfcounter.print
Affiche les compteurs de performance exposés par le processus Java spécifié.
-f filename
Lit et exécute les commandes à partir d'un fichier spécifié, filename.
-l
Affiche la liste des identifiants de processus de la Machine Virtuelle Java qui ne s'exécutent pas dans un processus docker séparé, ainsi que la classe principale et les arguments de ligne de commande utilisés pour lancer le processus. Si la JVM s'exécute dans un processus docker, vous devez utiliser des outils tels que ps pour rechercher le PID.

Note :

Utiliser jcmd sans arguments est équivalent à utiliser jcmd -l.

-h
Affiche l'aide en ligne de commande de l'utilitaire jcmd .

DESCRIPTION

L'utilitaire jcmd sert à envoyer des requêtes de commandes de diagnostic à la JVM. Il doit être utilisé sur la même machine que celle où la JVM s'exécute, et avec les mêmes identifiants d'utilisateur et de groupe effectifs que ceux utilisés pour lancer la JVM. Chaque commande de diagnostic possède son propre ensemble d'options et d'arguments. Pour afficher la description, la syntaxe et la liste des options et arguments disponibles pour une commande de diagnostic, utilisez le nom de la commande comme argument. Par exemple :

jcmd pid help command

Si les arguments contiennent des espaces, vous devez les entourer de guillemets simples ou doubles (' ou "). De plus, vous devez échapper les guillemets simples ou doubles avec une barre oblique inverse (\) pour empêcher le shell du système d'exploitation de traiter les guillemets. Alternativement, vous pouvez entourer ces arguments de guillemets simples puis de guillemets doubles (ou de guillemets doubles puis de guillemets simples).

Si vous spécifiez l'identifiant de processus (pid) ou la classe principale (main-class) comme premier argument, l'utilitaire jcmd envoie la requête de commande de diagnostic au processus Java ayant l'identifiant spécifié ou à tous les processus Java ayant le nom de classe principale spécifié. Vous pouvez également envoyer la requête de commande de diagnostic à tous les processus Java disponibles en spécifiant 0 comme identifiant de processus.

COMMANDES POUR JCMD

Le command doit être une commande de diagnostic jcmd valide pour la JVM sélectionnée. La liste des commandes disponibles pour jcmd s'obtient en exécutant la commande help (jcmd pid help) où pid est l'identifiant de processus d'un processus Java en cours d'exécution. Si le pid est 0, les commandes seront envoyées à tous les processus Java. L'argument de classe principale sera utilisé pour faire correspondre, partiellement ou entièrement, la classe utilisée pour démarrer Java. Si aucune option n'est donnée, la liste des identifiants de processus Java en cours d'exécution qui ne sont pas dans des processus docker séparés est affichée, avec la classe principale et les arguments de ligne de commande utilisés pour lancer le processus (identique à l'utilisation de -l).

Les commandes jcmd peuvent prendre des options et des arguments. Les options sont spécifiées en utilisant la syntaxe key ou key=value . Les arguments sont donnés comme une simple valeur, jamais name=value.

Une autre option est d'utiliser une heure relative à l'heure actuelle qui est spécifiée par un entier négatif suivi de "s", "m" ou "h". Par exemple, "-12h", "-15m" ou "-30s"

Note:

options:

•
delay: (Optional) Length of time to wait before starting to record (INTEGER followed by 's' for seconds 'm' for minutes or 'h' for hours, 0s)

disk: (Optional) Flag for also writing the data to disk while recording (BOOLEAN, true)

If %p and/or %t is specified in the filename, it expands to the JVM's PID and the current timestamp, respectively. (FILE, no default value)
•

•
maxsize: (Optional) Maximum size of the data to keep on disk in bytes if one of the following suffixes is not used: 'm' or 'M' for megabytes OR 'g' or 'G' for gigabytes. (STRING, 0 (no maximum size))
•

•

The path information is useful for finding memory leaks but collecting it is time consuming. Turn on this flag only when you have an application that you suspect has a memory leak. If the settings parameter is set to 'profile', then the information collected includes the stack trace from where the potential leaking object was allocated. (BOOLEAN, false)
•
settings: (Optional) Name of the settings file that identifies which events to record. To specify more than one file, separate the names with a comma (','). Include the path if the file is not in JAVA-HOME/lib/jfr. The following profiles are included with the JDK in the JAVA-HOME/lib/jfr directory: 'default.jfc': collects a predefined set of information with low overhead, so it has minimal impact on performance and can be used with recordings that run continuously; 'profile.jfc': Provides more data than the 'default.jfc' profile, but with more overhead and impact on performance. Use this configuration for short periods of time when more information is needed. Use none to start a recording without a predefined configuration file. (STRING, JAVA-HOME/lib/jfr/default.jfc)

Event settings and .jfc options can be specified using the following syntax:

•
option: (Optional) Specifies the option value to modify. To list available options, use the JAVA_HOME/bin/jfr tool.
•
event-setting: (Optional) Specifies the event setting value to modify. Use the form: <event-name>#<setting-name>=<value> To add a new event setting, prefix the event name with '+'.

You can specify values for multiple event settings and .jfc options by separating them with a whitespace. In case of a conflict between a parameter and a .jfc option, the parameter will take precedence. The whitespace delimiter can be omitted for timespan values, i.e. 20ms. For more information about the settings syntax, see Javadoc of the jdk.jfr package.
