NOM

jj-file-annotate - Afficher la modification source pour chaque ligne du fichier cible

SYNOPSIS

jj file annotate [-r|--revision] [-T|--template] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <CHEMIN>

DESCRIPTION

Affiche la modification source pour chaque ligne du fichier cible.

Annote une révision ligne par ligne. Chaque ligne inclut la modification source qui a introduit la ligne associée. Un chemin vers le fichier désiré doit être fourni.

OPTIONS

-r, --revision <REVSET>
une révision optionnelle pour commencer
-T, --template <MODELE>
Rendre chaque ligne en utilisant le modèle donné

Toutes les méthodes sans argument du type [`AnnotationLine`] sont disponibles comme mots-clés dans l'expression du modèle. Voir [`jj help -k templates`] pour plus d'informations.

Si non spécifié, cela utilise par défaut le paramètre `templates.file_annotate`.

[`AnnotationLine` type]: https://docs.jj-vcs.dev/latest/templates/#annotationline-type

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-h, --help
Afficher l'aide (voir un résumé avec '-h')
<CHEMIN>
le fichier à annoter

OPTIONS GLOBALES

-R, --repository <DEPOT>
Chemin vers le dépôt sur lequel opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané du répertoire de travail, et ne pas le mettre à jour

Par défaut, Jujutsu prend un instantané du répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de prendre un instantané du répertoire de travail et voir plutôt un commit potentiellement obsolète du répertoire de travail, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile par exemple dans une invite de commande, surtout si un autre processus commite le répertoire de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option affecte uniquement la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est pratiquement identique à la valeur par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération que vous souhaitez. N'importe quel préfixe non ambigu de l'ID d'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Le faire est équivalent à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Réduire au silence la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous indiquera pas si le répertoire de travail a été snapshoté ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le pager
--config <NOM=VALEUR>
Options de configuration supplémentaires (peuvent être répétées)

Le nom doit être spécifié sous forme de clés pointées TOML. La valeur doit être spécifiée sous forme d'expression TOML. Si la valeur chaîne n'est pas entourée d'aucune construction TOML (telle que la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés)
annotate
