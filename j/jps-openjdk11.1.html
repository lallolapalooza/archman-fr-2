jps(1) Outils de surveillance jps(1)

NOM

jps - Liste les machines virtuelles Java (JVM) instrumentées sur le système cible. Cette commande est expérimentale et non prise en charge.

SYNOPSIS

jps [ options ] [ identifiant_hote ]
options
Options de ligne de commande. Voir Options.
identifiant_hote
L'identifiant de l'hôte pour lequel le rapport de processus doit être généré. L'identifiant_hote peut inclure des composants optionnels indiquant le protocole de communication, le numéro de port et d'autres données spécifiques à l'implémentation. Voir Identifiant d'hôte.

DESCRIPTION

La commande jps liste les JVM HotSpot instrumentées sur le système cible. La commande se limite à signaler des informations sur les JVM pour lesquelles elle dispose des permissions d'accès.

Si la commande jps est exécutée sans spécifier d' identifiant_hote, elle recherche les JVM instrumentées sur l'hôte local. Si elle est démarrée avec un identifiant_hote, elle recherche les JVM sur l'hôte indiqué, en utilisant le protocole et le port spécifiés. Un processus jstatd est supposé être en cours d'exécution sur l'hôte cible.

La commande jps signale l'identifiant de la JVM locale, ou lvmid, pour chaque JVM instrumentée trouvée sur le système cible. Le lvmid est généralement, mais pas nécessairement, l'identifiant de processus du système d'exploitation pour le processus JVM. Sans aucune option, jps liste l'lvmid de chaque application Java suivi de la forme courte du nom de classe de l'application ou du nom du fichier JAR. La forme courte du nom de classe ou du nom de fichier JAR omet les informations de paquetage de la classe ou les informations de chemin des fichiers JAR.

La commande jps utilise le lanceur Java pour trouver le nom de la classe et les arguments passés à la méthode main. Si la JVM cible est démarrée avec un lanceur personnalisé, le nom de la classe ou du fichier JAR et les arguments de la méthode main ne sont pas disponibles. Dans ce cas, la commande jps affiche la chaîne Unknown pour le nom de la classe ou du fichier JAR et pour les arguments de la méthode main.

La liste des JVM produites par la commande jps peut être limitée par les permissions accordées au principal exécutant la commande. La commande ne liste que les JVM pour lesquelles le principal a des droits d'accès déterminés par des mécanismes de contrôle d'accès spécifiques à la plateforme.

OPTIONS

La commande jps prend en charge un certain nombre d'options qui modifient la sortie de la commande. Ces options sont susceptibles d'être modifiées ou supprimées à l'avenir.

-q

Supprime l'affichage du nom de la classe, du nom du fichier JAR et des arguments passés à la méthode main, produisant uniquement une liste d'identifiants de JVM locaux.
-m

Affiche les arguments passés à la méthode main. La sortie peut être null pour les JVM embarquées.
-l

Affiche le nom complet du paquetage de la classe principale de l'application ou le chemin complet du fichier JAR de l'application.
-v

Affiche les arguments passés à la JVM.
-V

Supprime l'affichage du nom de la classe, du nom du fichier JAR et des arguments passés à la méthode main, produisant uniquement une liste d'identifiants de JVM locaux.
-Joption

Transmet option à la JVM, où option est l'une des options décrites dans la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).

IDENTIFIANT DHOTE

L'identifiant d'hôte, ou identifiant_hote, est une chaîne qui indique le système cible. La syntaxe de la chaîne identifiant_hote correspond à la syntaxe d'une URI :

[protocole:][[//]nom_hote][:port][/nom_serveur]
protocole
Le protocole de communication. Si le protocole est omis et qu'un nom_hote n'est pas spécifié, alors le protocole par défaut est un protocole local optimisé et spécifique à la plateforme. Si le protocole est omis et qu'un nom d'hôte est spécifié, alors le protocole par défaut est rmi.
nom_hote
Un nom d'hôte ou une adresse IP qui indique l'hôte cible. Si vous omettez le paramètre nom_hote, alors l'hôte cible est l'hôte local.
port
Le port par défaut pour la communication avec le serveur distant. Si le paramètre nom_hote est omis ou si le paramètre protocole spécifie un protocole local optimisé, alors le paramètre port est ignoré. Sinon, le traitement du paramètre port est spécifique à l'implémentation. Pour le protocole rmi par défaut, le paramètre port indique le numéro de port pour le rmiregistry sur l'hôte distant. Si le paramètre port est omis et que le paramètre protocole indique rmi, alors le port rmiregistry par défaut (1099) est utilisé.
nom_serveur
Le traitement de ce paramètre dépend de l'implémentation. Pour le protocole local optimisé, ce champ est ignoré. Pour le protocole rmi, ce paramètre est une chaîne qui représente le nom de l'objet distant RMI sur l'hôte distant. Voir l'option -n de la commande jstatd pour plus d'informations.

FORMAT DE&#x00A0;LA&#x00A0;SORTIE

La sortie de la commande jps suit le modèle suivant :

lvmid [ [ nom_classe | nom_fichier_JAR | "Unknown"] [ arg* ] [ jvmarg* ] ]

Tous les jetons de sortie sont séparés par des espaces blancs. Une valeur d'arg qui inclut des espaces blancs intégrés introduit une ambiguïté lorsqu'on tente de mapper les arguments à leurs paramètres positionnels réels.

Note : Il est recommandé de ne pas écrire de scripts pour analyser la sortie de jps car le format pourrait changer dans les futures versions. Si vous écrivez des scripts qui analysent la sortie de jps, attendez-vous à devoir les modifier pour les futures versions de cet outil.

EXEMPLES

Cette section fournit des exemples de la commande jps.

Lister les JVM instrumentées sur l'hôte local :

jps
18027 Java2Demo.JAR
18032 jps
18005 jstat

L'exemple suivant liste les JVM instrumentées sur un hôte distant. Cet exemple suppose que le serveur jstat et soit son registre RMI interne, soit un processus rmiregistry externe séparé sont en cours d'exécution sur l'hôte distant sur le port par défaut (port 1099). Il suppose également que l'hôte local dispose des permissions appropriées pour accéder à l'hôte distant. Cet exemple inclut également l'option -l pour afficher la forme longue des noms de classe ou des noms de fichiers JAR.

jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

L'exemple suivant liste les JVM instrumentées sur un hôte distant avec un port non standard pour le registre RMI. Cet exemple suppose que le serveur jstatd, avec un registre RMI interne lié au port 2002, est en cours d'exécution sur l'hôte distant. Cet exemple utilise également l'option -m pour inclure les arguments passés à la méthode main de chacune des applications Java listées.

jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
