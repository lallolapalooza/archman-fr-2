jj-bookmark-list(1) Manuel des commandes générales jj-bookmark-list(1)

NOM

jj-bookmark-list - Lister les signets et leurs cibles

SYNOPIS

jj bookmark list [-a|--all-remotes] [--remote] [-t|--tracked] [-c|--conflicted] [-r|--revisions] [-T|--template] [--sort] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [NOMS]

DESCRIPTION

Lister les signets et leurs cibles

Par défaut, un signet distant suivi ne sera inclus que si sa cible est différente de la cible locale. Un signet distant non suivi ne sera pas affiché. Pour un signet conflictuel (local et distant), les anciennes révisions de la cible sont précédées d'un "-" et les nouvelles révisions de la cible sont précédées d'un "+".

Voir [`jj help -k bookmarks`] pour plus d'informations.

[`jj help -k bookmarks`]: https://docs.jj-vcs.dev/latest/bookmarks

OPTIONS

-a, --all-remotes
Afficher tous les signets distants suivis et non suivis, y compris ceux dont les cibles sont synchronisées avec les signets locaux
--remote <DISTANT>
Afficher tous les signets distants suivis et non suivis appartenant à ce distant

Peut être combiné avec `--tracked` ou `--conflicted` pour filtrer les signets affichés (peut être répété.)

Par défaut, le nom du distant spécifié correspond exactement. Utilisez le préfixe `glob:` pour sélectionner les distants par [modèle joker].

[modèle joker]: https://docs.jj-vcs.dev/latest/revsets/#string-patterns

-t, --tracked
Afficher uniquement les signets distants suivis. Omet les signets locaux suivis par Git par défaut
-c, --conflicted
Afficher uniquement les signets conflictuels
-r, --revisions <REVSETS>
Afficher les signets dont les cibles locales se trouvent dans les révisions données

Notez que `-r deleted_bookmark` ne fonctionnera pas car `deleted_bookmark` n'aurait pas de cible locale.

-T, --template <MODELE>
Rendre chaque signet en utilisant le modèle donné

Toutes les méthodes sans argument du [type `CommitRef`] sont disponibles comme mots-clés dans l'expression de modèle. Voir [`jj help -k templates`] pour plus d'informations.

[type `CommitRef`]: https://docs.jj-vcs.dev/latest/templates/#commitref-type

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

--sort <CLE_TRI>
Trier les signets en fonction de la clé donnée (ou de plusieurs clés)

Ajoutez un `-` à la fin de la clé pour trier par ordre décroissant de la valeur (par exemple, `--sort name-`). Notez que lors de l'utilisation de plusieurs clés, la première clé est la plus significative.

Ceci est défini par défaut par le réglage `ui.bookmark-list-sort-keys`.

[valeurs possibles : name, name-, author-name, author-name-, author-email, author-email-, author-date, author-date-, committer-name, committer-name-, committer-email, committer-email-, committer-date, committer-date-]

-h, --help
Afficher l'aide (voir un résumé avec '-h')
[NOMS]
Afficher les signets dont le nom local correspond

Par défaut, le nom spécifié correspond exactement. Utilisez le préfixe `glob:` pour sélectionner les signets par [modèle joker].

[modèle joker]: https://docs.jj-vcs.dev/latest/revsets/#string-patterns

OPTIONS GLOBALES

-R, --repository <DEPOT>
Chemin d'accès au dépôt sur lequel opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané du répertoire de travail, et ne pas le mettre à jour

Par défaut, Jujutsu prend un instantané du répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de prendre un instantané du répertoire de travail et voir à la place un commit du répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile, par exemple, dans une invite de commande, surtout si un autre processus commit le répertoire de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait affiché lorsque l'opération donnée venait de se terminer. `--at-op=@` est pratiquement identique par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération souhaité. N'importe quel préfixe non ambigu de l'ID d'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Faire cela est équivalent à avoir exécuté des commandes concurrentes commençant à l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Supprimer la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si le répertoire de travail a été instantané ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le pagineur
--config <NOM=VALEUR>
Options de configuration supplémentaires (peuvent être répétées)

Le nom doit être spécifié sous forme de clés pointées TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur de type chaîne n'est pas entourée d'une construction TOML (telle que la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés)
