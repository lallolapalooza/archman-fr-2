DESCRIPTIO

N

L'outil jwebserver fournit un serveur HTTP minimal, conçu pour être utilisé pour le prototypage, les tests et le débogage. Il sert une seule hiérarchie de répertoires et ne sert que des fichiers statiques. Seul HTTP/1.1 est pris en charge ; HTTP/2 et HTTPS ne sont pas pris en

charge.

Seules les requêtes idempotentes HEAD et GET sont servies. Toute autre requête reçoit une réponse 501 - Non implémenté ou 405 - Non autorisé. Les requêtes GET sont mappées au répertoire servi, comme suit

:
•
Si la ressource demandée est un fichier, son contenu est
servi.
•
Si la ressource demandée est un répertoire contenant un fichier d'index, le contenu du fichier d'index est
servi.
•
Sinon, les noms de tous les fichiers et sous-réperto
ires du répertoire sont listés. Les liens symboliques
et les fichiers cachés ne sont ni listés ni servis.

Les types MIME sont configurés automatiquement à l'aide de la table intégrée. Par exemple, les fichiers .html sont servis en tant que text/html et les fichiers .java sont servis en tant que text/plain

.

jwebserver se trouve dans le module jdk.httpserver et peut également être démarré avec java -m jdk.httpserver. Il est basé sur l'implémentation du serveur web dans le paquet com.sun.net.httpserver. La classe com.sun.net.httpserver.SimpleFileServer fournit un moyen programmatique

de récupérer le serveur et ses composan
ts pour les réutiliser et les étendre.

Par défaut, le serveur s'exécute en avant-plan et se lie à l'adresse de boucle locale et au port 8000. Cela peut être modifié avec les options -b et -p. Par exemple, pour lier le serveur web simple à toutes les interfaces, utiliser

/cwd and subdirectories on 0.0
.0.0 (all interfaces) port 8000
URL http://123.456.7.891:8000/

sensibles.

    jwebserver-openjdk25(1)

    NOM

    jwebserver-openjdk25 - Serveur HTTP de développement pour les classes de bibliothèque Java

    SYNOPIS

    jwebserver [OPTIONS] [--bind-address ADDRESS] [--bind-port PORT] [--directory DIRECTORY] [--help] [--header NAME=VALUE] [--no-directory-listing] [--no-gzip] [--prefix PREFIX] [--show-hidden-files] [--welcome-file FILE]

    DESCRIPTION

    Le serveur jwebserver est un serveur HTTP de développement pour les classes de bibliothèque Java. Il peut être utilisé pour servir des fichiers statiques à partir d'un répertoire spécifié.

    OPTIONS

    --bind-address ADDRESS
    Spécifie l'adresse IP sur laquelle le serveur doit écouter. Par défaut, il écoute sur toutes les interfaces disponibles.
    --bind-port PORT
    Spécifie le port sur lequel le serveur doit écouter. Par défaut, il écoute sur le port 8080.
    --directory DIRECTORY
    Spécifie le répertoire à partir duquel servir les fichiers statiques. Par défaut, il sert à partir du répertoire courant.
    --help
    Affiche un message d'aide et quitte.
    --header NAME=VALUE
    Ajoute un en-tête HTTP personnalisé à toutes les réponses. Peut être spécifié plusieurs fois.
    --no-directory-listing
    Désactive la liste des répertoires. Si elle est désactivée, une erreur 403 Forbidden sera renvoyée pour les répertoires qui ne contiennent pas de fichier d'accueil.
    --no-gzip
    Désactive la compression GZIP pour les réponses.
    --prefix PREFIX
    Ajoute un préfixe à toutes les URL servies. Par exemple, si le préfixe est /api, les fichiers seront accessibles via http://localhost:8080/api/....
    --show-hidden-files
    Affiche les fichiers et répertoires cachés (ceux dont le nom commence par un point).
    --welcome-file FILE
    Spécifie le nom du fichier d'accueil à rechercher dans les répertoires. Par défaut, il cherche index.html.

    EXEMPLES

    # Sert les fichiers du répertoire courant sur le port 8080
jwebserver

# Sert les fichiers du répertoire '/var/www' sur le port 80
jwebserver --directory /var/www --bind-port 80

# Sert les fichiers avec un préfixe '/static' et affiche les fichiers cachés
jwebserver --prefix /static --show-hidden-files

# Ajoute un en-tête personnalisé
jwebserver --header "X-Custom-Header=MyValue"
