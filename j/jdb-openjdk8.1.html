DESCRIPTIO

N

Le débogueur Java (JDB) est un débogueur simple en ligne de commande pour les classes Java. La commande jdb et ses options appellent JDB. La commande jdb démontre l'architecture de débogage de la plateforme Java (JDBA) et permet l'inspection et le débogage d'une machine virtuelle Java (JVM) locale ou distante. Voir Java Platform Debugger Architecture (JDBA) à l'adresse http://docs.oracle.com/javase/8/docs/technotes/guides/jpda/index.

html

DÉMARRER UNE SESSION

JDB

Il existe de nombreuses façons de démarrer une session JDB. La méthode la plus couramment utilisée consiste à faire lancer une nouvelle JVM par JDB avec la classe principale de l'application à déboguer. Faites-le en remplaçant la commande jdb par la commande java dans la ligne de commande. Par exemple, si la classe principale de votre application est MyClass, utilisez la commande suivante pour la déboguer sous JDB

: 
jdb
MyClass

Lorsqu'elle est démarrée de cette manière, la commande jdb appelle une deuxième JVM avec les paramètres spécifiés, charge la classe spécifiée et arrête la JVM avant d'exécuter la première instruction de cette

classe.

Une autre façon d'utiliser la commande jdb est de l'attacher à une JVM déjà en cours d'exécution. La syntaxe pour démarrer une JVM à laquelle la commande jdb s'attache lorsque la JVM est en cours d'exécution est la suivante. Cela charge les bibliothèques de débogage in-process et spécifie le type de connexion à

établir. 
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n
MyClass

Vous pouvez ensuite attacher la commande jdb à la JVM avec la commande suivante

: 
jdb -attach
8000

JVM.

NAME

jdb-openjdk8 — Java Debugger

SYNOPSIS

jdb [options] [class [args...]]

jdb [options] [-sourcepath srcpath] [-classpath classpath] [args...]

DESCRIPTION

The jdb command is a Java debugger. It allows you to set breakpoints in your code, step through the execution of your program, examine variables, and inspect the state of your Java Virtual Machine (JVM).

The jdb command can be used to debug applications that are started directly from the command line, or it can be used to attach to an already running JVM.

When you use jdb to start an application, it takes the command-line arguments that would normally be passed to the java command. These arguments are passed to the JVM that is running your application.

The jdb command provides a set of commands for interacting with the debugger. Some of the most common commands include:

run [class] [args...]
Starts the application with the specified class and arguments.
cont
Continues execution of the application until the next breakpoint or exception.
step
Executes the next line of code.
next
Executes the next line of code, stepping over method calls.
print [expression]
Prints the value of the specified expression.
list
Lists the source code around the current line of execution.
threads
Lists all threads in the application.
thread [thread_id]
Switches the current thread to the specified thread.
suspend
Suspends all threads in the application.
resume
Resumes execution of all suspended threads.
stop [in class[.method[(arguments)]] | [at class:line]]
Sets a breakpoint at the specified location.
catch [classname]
Causes the debugger to stop when an exception of the specified class or subclass is thrown.
ignore [classname]
Negates the effect of an earlier catch command. The ignore command does not cause the debugged JVM to ignore specific exceptions, but only to ignore the debugger.

The catch command stops the application when an exception that is an instance of the specified class or subclass is thrown.

The ignore command negates the effect of an earlier catch command. The ignore command does not cause the debugged JVM to ignore specific exceptions, but only to ignore the debugger.

OPTIONS

When you use the jdb command instead of the java command on the command line, the jdb command accepts many of the same options as the java command, including -D, -classpath, and -X options. The following list contains additional options that are accepted by the jdb command.

Other options are supported to provide alternate mechanisms for connecting the debugger to the JVM it is to debug. For additional documentation about these connection alternatives, see Java Platform Debugger Architecture (JPDA) at http://docs.oracle.com/javase/8/docs/technotes/guides/jpda/index.html

-help

Displays a help message.
-sourcepath dir1:dir2: . . .

Uses the specified path to search for source files in the specified path. If this option is not specified, then use the default path of dot (.).
-attach address

Attaches the debugger to a running JVM with the default connection mechanism.
-listen address

Waits for a running JVM to connect to the specified address with a standard connector.
-launch

Starts the debugged application immediately upon startup of JDB. The -launch option removes the need for the run command. The debugged application is launched and then stopped just before the initial application class is loaded. At that point, you can set any necessary breakpoints and use the cont command to continue execution.
-listconnectors

List the connectors available in this JVM.
-connect connector-name:name1=value1

Connects to the target JVM with the named connector and listed argument values.
-dbgtrace [flags]

Prints information for debugging the jdb command.
-tclient

Runs the application in the Java HotSpot VM client.
-tserver

Runs the application in the Java HotSpot VM server.
-Joption

Passes option to the JVM, where option is one of the options described on the reference page for the Java application launcher. For example, -J-Xms48m sets the startup memory to 48 MB. See java(1).

OPTIONS FORWARDED TO THE DEBUGGER PROCESS

-v -verbose[:class|gc|jni]

Turns on verbose mode.
-Dname=value

Sets a system property.
-classpath dir

Lists directories separated by colons in which to look for classes.
-Xoption

Nonstandard target JVM option.
