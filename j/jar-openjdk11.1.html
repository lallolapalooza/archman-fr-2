La

commande

jar est un outil d'archivage et de compression polyvalent, basé sur ZIP et le format de compression ZLIB. Cependant, la commande jar a été conçue principalement pour regrouper des applets ou des applications Java dans une archive unique. Lorsque les composants d'une applet ou d'une application (fichiers, images et sons) sont combinés dans une seule archive, ils peuvent être téléchargés par un agent Java (comme un navigateur) en une seule transaction HTTP, plutôt que de nécessiter une nouvelle connexion pour chaque élément. Cela améliore considérablement les temps de téléchargement. La commande jar compresse également les fichiers, ce qui améliore encore le temps de téléchargement. La commande jar permet également de signer individuellement les entrées d'un fichier par l'auteur de l'applet afin que leur origine puisse être authentifiée. Un fichier JAR peut être utilisé comme entrée

de

chemin de classe, qu'il soit compressé ou non. La syntaxe de la commande jar ressemble à la syntaxe de la commande tar. Elle possède plusieurs modes de fonctionnement, définis par l'un des arguments d'opération obligatoires. Les autres arguments sont soit des options qui modifient le c

OPÉRANDE

S

Les opérandes suivants sont reconnus par la commande

jar.
fi
le
Lors de la création (c) ou de la mise à jour (u) d'un fichier JAR, l'opérande file définit le chemin et le nom du fichier ou du répertoire qui doit être ajouté à l'archive. Lors de l'extraction (x) ou de la liste du contenu (t) d'un fichier JAR, l'opérande file définit le chemin et le nom du fichier à extraire ou à lister. Au moins un fichier ou répertoire valide doit être spécifié. Séparez les opérandes file multiples par des espaces. Si les opérandes entrypoint, jarfile ou manifest sont utilisés, les opérandes file doivent être spécifiés après
eux.
entrypoi
nt
Lors de la création (c) ou de la mise à jour (u) d'un fichier JAR, l'opérande entrypoint définit le nom de la classe qui doit être le point d'entrée d'une application Java autonome regroupée dans un fichier JAR exécutable. L'opérande entrypoint doit être spécifié si l'option e est
présente.
jarfi
le
Définit le nom du fichier à créer (c), mettre à jour (u), extraire (x) ou afficher (t). L'opérande jarfile doit être spécifiée si l'option f est présente. Omettre l'option f et l'opérande jarfile indique à la commande jar de recevoir le nom du fichier JAR depuis stdin (pour x et t) ou d'envoyer le fichier JAR vers stdout (pour c et u).

Lors de l'indexation (i) d'un fichier JAR, spécifiez l'opérande jarfile sans l'option f

.
manife
st
Lors de la création (c) ou de la mise à jour (u) d'un fichier JAR, l'opérande manifest définit les fichiers de manifeste préexistants avec les noms et les valeurs des attributs à inclure dans MANIFEST.MF dans le fichier JAR. L'opérande manifest doit être spécifiée si l'option f est
présente.
@arg-fi
le
Pour raccourcir ou simplifier la commande jar, vous pouvez spécifier les arguments dans un fichier texte séparé et le passer à la commande jar avec le signe at (@) comme préfixe. Lorsque la commande jar rencontre un argument commençant par le signe at, elle développe le contenu de ce fichier dans la liste d'arguments.

Un fichier d'arguments peut inclure les options et les arguments de la commande jar (sauf les options -J, car elles sont transmises au lanceur, qui ne prend pas en charge les fichiers d'arguments). Les arguments dans un fichier peuvent être séparés par des espaces ou des caractères de nouvelle ligne. Les noms de fichiers dans un fichier d'arguments sont relatifs au répertoire courant depuis lequel vous exécutez la commande jar, et non relatifs à l'emplacement du fichier d'arguments. Les jokers, tels que l'astérisque (*), qui pourraient autrement être développés par le shell du système d'exploitation, ne sont pas

développés.

L'exemple suivant montre comment créer un fichier classes.list avec les noms de fichiers du répertoire courant produits par la commande f

ind : 
find . -name '*.class' -print > classes.
list

Vous pouvez ensuite exécuter la commande jar et lui passer le fichier classes.list en utilisant la syntaxe @arg-

file : 
jar cf my.jar @classes.
list

Un fichier d'arguments peut être spécifié avec un chemin, mais tout nom de fichier à l'intérieur du fichier d'arguments ayant des chemins relatifs est relatif au répertoire de travail courant de la commande jar, et non au chemin transmis, par

exemple : 
jar @dir/classes.
list

Exemple 4 Ajouter un

index

Utilisez l'option i lorsque vous divisez les classes interdépendantes d'une application de négociation d'actions en trois fichiers JAR : main.jar, buy.jar et sell.jar. Si vous spécifiez l'attribut Class-Path dans le manifeste de main.jar, vous pouvez utiliser l'option i pour accélérer le temps de chargement des classes de votre application

: 
Class-Path: buy.jar sell.
jar 
jar i main.
jar

Un fichier INDEX.LIST est inséré dans le répertoire META-INF. Cela permet au chargeur de classes de l'application de télécharger les fichiers JAR spécifiés lorsqu'il recherche des classes ou des

ressources.

Le chargeur de classes de l'application utilise les informations stockées dans ce fichier pour un chargement efficace des classes. Pour copier des répertoires, compressez d'abord les fichiers dans dir1 vers stdout, puis acheminez-les par pipeline et extrayez-les depuis stdin vers dir2 (en omettant l'option -f des deux commandes jar)

: 
(cd dir1; jar c .) | (cd dir2; jar
