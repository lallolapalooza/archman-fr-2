DESCRIPTIO

N

Remarque : Pour la plupart des tâches de développement, y compris le déploiement des modules sur le chemin des modules ou leur publication dans un dépôt Maven, continuez à empaqueter les modules dans des fichiers JAR modulaires. Le outil jmod est destiné aux modules qui ont des bibliothèques natives ou d'autres fichiers de configuration, ou aux modules que vous prévoyez de lier, avec l' outil jlink, à une image

d'exécution.

Le format de fichier JMOD vous permet d'agréger des fichiers autres que les fichiers .class, les métadonnées et les ressources. Ce format est transportable mais non exécutable, ce qui signifie que vous pouvez l'utiliser au moment de la compilation ou de la liaison, mais pas à

l'exécution.

De nombreuses options de jmod impliquent la spécification d'un chemin dont le contenu est copié dans les fichiers JMOD résultants. Ces options copient tout le contenu du chemin spécifié, y compris les sous-répertoires et leur contenu, mais excluent les fichiers dont les noms correspondent au motif spécifié par l'option --exclude

.

Avec l'option --hash-modules ou la commande jmod hash, vous pouvez, dans le descripteur de chaque module, enregistrer les hachages du contenu des modules qui sont autorisés à en dépendre, « reliant » ainsi ces modules. Cela permet à un paquet d'être exporté vers un ou plusieurs mod

ules nommés spécifiquement et à aucun autre par le biais d'exports qualifiés. L' environnement d'exécution vérifie si l'hach
age enregistré d'un module correspond à celui résolu à l'exécution ; sinon, l'environnement d'exécution renvoie une erreur.

OPTIONS SUPPLÉMENTAIRES POUR JMOD

En plus des options décrites dans Options pour jmod, les options suivantes peuvent être utilisées avec la commande.

--do-not-resolve-by-default
Exclure de l'ensemble racine par défaut des modules
--warn-if-resolved
Indice pour qu'un outil émette un avertissement si le module est résolu. L'une des valeurs suivantes : deprecated, deprecated-for-removal, ou incubating.

EXEMPLE DE HASH JMOD

L'exemple suivant démontre ce qui se passe lorsque vous essayez de lier un module feuille (dans cet exemple, ma) avec un module requis (mb), et que la valeur de hachage enregistrée dans le module requis ne correspond pas à celle du module feuille.

1.
Créez et compilez les fichiers .java suivants :
•
jmodhashex/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex/src/mb/module-info.java

module mb {
}
•
jmodhashex2/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex2/src/mb/module-info.java

module mb {
}
2.
Créez une archive JMOD pour chaque module. Créez les répertoires jmodhashex/jmods et jmodhashex2/jmods, puis exécutez les commandes suivantes depuis le répertoire jmodhashex, puis depuis le répertoire jmodhashex2 :
•
jmod create --class-path mods/ma jmods/ma.jmod
•
jmod create --class-path mods/mb jmods/mb.jmod
3.
Prévisualisez éventuellement la commande jmod hash. Exécutez la commande suivante depuis le répertoire jmodhashex :

jmod hash --dry-run -module-path jmods --hash-modules .*

La commande affiche ce qui suit :


Dry run:
mb
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a

Cela indique que la commande jmod hash (sans l'option --dry-run) enregistrera la valeur de hachage du module feuille ma dans le module mb.

4.
Enregistrez les valeurs de hachage dans les fichiers d'archive JMOD contenus dans le répertoire jmodhashex. Exécutez la commande suivante depuis le répertoire jmodhashex :

jmod hash --module-path jmods --hash-modules .*

La commande affiche ce qui suit :

Hashes are recorded in module mb

5.
Affichez des informations sur chaque archive JMOD contenue dans le répertoire jmodhashex. Exécutez les commandes mises en surbrillance depuis le répertoire jmodhashex :

jmod describe jmods/ma.jmod
ma
  requires mandated java.base
  requires mb
jmod describe jmods/mb.jmod
mb
  requires mandated java.base
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a
6.
Tentez de créer une image d'exécution qui contient le module ma du répertoire jmodhashex2 mais le module mb du répertoire jmodhashex. Exécutez la commande suivante depuis le répertoire jmodhashex2 :
•
Linux et OS X :

jlink --module-path $JAVA_HOME/jmods:jmods/ma.jmod:../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

•
Windows :

jlink --module-path %JAVA_HOME%/jmods;jmods/ma.jmod;../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

La commande affiche un message d'erreur similaire à ce qui suit :


Error: Hash of ma (a2d77889b0cb067df02a3abc39b01ac1151966157a68dc4241562c60499150d2) differs to
expected hash (07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a) recorded in mb
