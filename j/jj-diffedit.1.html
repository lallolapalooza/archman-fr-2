jj-diffedit(1) Manuel des commandes générales jj-diffedit(1)

NOM

jj-diffedit - Retoucher les modifications de contenu d'une révision avec un éditeur de diff

SYNTAXE

jj diffedit [-r|--revision] [-f|--from] [-t|--to] [--tool] [--restore-descendants] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [ENSEMBLES_DE_FICHIERS]

DESCRIPTION

Retoucher les modifications de contenu d'une révision avec un éditeur de diff.

Avec l'option `-r`, lance un [éditeur de diff] sur les modifications de la révision.

Avec les options `--from` et/ou `--to`, lance un [éditeur de diff] comparant la révision "from" à la révision "to".

[éditeur de diff] : https://docs.jj-vcs.dev/latest/config/#editing-diffs

Modifiez le côté droit du diff jusqu'à ce qu'il corresponde à vos attentes. Une fois l'éditeur fermé, la révision spécifiée avec `-r` ou `--to` sera mise à jour. Sauf si `--restore-descendants` est utilisé, les descendants seront rebasés par-dessus comme d'habitude, ce qui peut entraîner des conflits.

Voir `jj restore` si vous souhaitez déplacer des fichiers entiers d'une révision à une autre. Pour déplacer des modifications entre révisions, voir `jj squash -i`.

OPTIONS

-r, --revision <ENSEMBLE_DE_REVS>
La révision à retoucher

Par défaut, @ si ni `--to` ni `--from` ne sont spécifiés.

-f, --from <ENSEMBLE_DE_REVS>
Afficher les modifications à partir de cette révision

Par défaut, @ si `--to` est spécifié.

-t, --to <ENSEMBLE_DE_REVS>
Modifier les modifications dans cette révision

Par défaut, @ si `--from` est spécifié.

--tool <NOM>
Spécifier l'éditeur de diff à utiliser
--restore-descendants
Conserver le contenu (pas le diff) lors du rebasage des descendants

Lors du rebasage d'un descendant par-dessus la révision réécrite, son diff comparé à ses parents est normalement préservé, c'est-à-dire de la même manière que les descendants sont toujours rebasés. Ce drapeau fait en sorte que le contenu/état soit préservé au lieu de préserver le diff.

-h, --help
Afficher l'aide (voir un résumé avec '-h')
[ENSEMBLES_DE_FICHIERS]
Modifier uniquement ces chemins (les chemins non correspondants resteront inchangés)

OPTIONS GLOBALES

-R, --repository <RÉPERTOIRE>
Chemin vers le répertoire sur lequel opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas enregistrer le répertoire de travail et ne pas le mettre à jour

Par défaut, Jujutsu enregistre le répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter d'enregistrer le répertoire de travail et voir plutôt un commit de répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile par exemple dans une invite de commande, surtout si un autre processus commit le répertoire de travail.

Charger le répertoire à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Permettre la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé `immutable` du template.

--at-operation <OPÉRATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID_OPÉRATION>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID_OPÉRATION> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est pratiquement identique à la valeur par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération souhaitée. N'importe quel préfixe non ambigu de l'ID de l'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes de modification lors du chargement du dépôt à une opération antérieure. Le faire équivaut à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Silencer la sortie non primaire de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous indiquera pas si le répertoire de travail a été enregistré ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le pagineur
--config <NOM=VALEUR>
Options de configuration supplémentaires (peuvent être répétées)

Le nom doit être spécifié sous forme de clés ponctuées TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur chaîne n'est pas entourée de constructions TOML (comme la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés)
