NOM

j4-dmenu-desktop — menu de bureau rapide

SYNOPIS

j4-dmenu-desktop [OPTIONS]

DESCRIPTION

j4-dmenu-desktop est un remplacement plus rapide pour i3-dmenu-desktop.

Son objectif est de trouver des fichiers .desktop et de vous proposer un menu pour lancer une application en utilisant dmenu.

Les arguments sont les suivants :

-b, --display-binary
Affiche le nom binaire après chaque entrée (désactivé par défaut).
-f, --display-binary-base
Affiche le nom de base du nom binaire après chaque entrée (désactivé par défaut).
-d, --dmenu commande
Détermine la commande utilisée pour invoquer dmenu. Exécutée avec votre shell ($SHELL) ou /bin/sh.
--no-exec
Ne pas exécuter la commande sélectionnée, l'envoyer à la sortie standard à la place.
--no-generic
Ne pas inclure le nom générique des entrées de bureau.
-t, --term commande
Définit l'émulateur de terminal utilisé pour démarrer les applications terminales.
--term-mode mode
Indique à j4-dmenu-desktop comment il doit exécuter l'émulateur de terminal. Ce drapeau change également la valeur par défaut du drapeau --term.

Les valeurs possibles sont : default | xterm | alacritty | kitty | terminator | gnome-terminal | custom

Voir MODE TERMINAL pour plus d'informations.

--usage-log fichier
Doit pointer vers un fichier en lecture/écriture (sera créé s'il n'existe pas). Dans ce mode, les entrées sont triées par fréquence d'utilisation.
--prune-bad-usage-log-entries
Supprime les noms marqués dans le journal d'utilisation pour lesquels j4-dmenu-desktop n'a pas réussi à trouver de fichier de bureau. Cela peut se produire lorsqu'une application marquée dans le journal d'utilisation n'existe plus car elle a été désinstallée.
-x, --use-xdg-de
Permet de lire $XDG_CURRENT_DESKTOP pour déterminer l'environnement de bureau.
--wait-on chemin
Doit pointer vers un chemin où un fichier peut être créé. Dans ce mode, aucun menu ne sera affiché. Au lieu de cela, le programme attend que chemin soit écrit (utilisez 'echo > chemin'). Chaque fois que cela se produit, un menu sera affiché. Les fichiers de bureau sont analysés à l'avance. Effectuer 'echo -n q > chemin' quittera le programme.
--wrapper wrapper
Un binaire wrapper. L'utilisation de '--wrapper "i3 exec"' et '--wrapper "sway exec"' est dépréciée, utilisez plutôt --i3-ipc.
-I, --i3-ipc
Exécute les entrées de bureau via i3 IPC ou Sway IPC. Nécessite que i3 ou Sway soit en cours d'exécution.
--skip-i3-exec-check
Désactive la vérification pour '--wrapper "i3 exec"' ou '--wrapper "sway exec"'. j4-dmenu-desktop dispose d'un support direct pour i3/Sway via le drapeau -I qui doit être utilisé à la place de l'option --wrapper. j4-dmenu-desktop le détecte et s'arrête. Ce drapeau remplace ce comportement.
-i, --case-insensitive
Trier les applications sans tenir compte de la casse.
-v
Soyez plus verbeux. Lorsque spécifié une fois, INFO est utilisé, lorsque spécifié deux fois, DEBUG est utilisé. Voir NIVEAUX DE LOG.
--log-level ERROR | WARNING | INFO | DEBUG
Une version plus explicite de -v. Ce drapeau a la priorité sur -v.
--log-file fichier
Spécifie un fichier journal. fichier sera tronqué. Par défaut, le niveau de journalisation INFO est utilisé.
--log-file-level ERROR | WARNING | INFO | DEBUG
Définit le niveau de journalisation du fichier.
--desktop-file-quirks ARGS
Modifie le mécanisme d'analyse des fichiers de bureau de j4-dmenu-desktop pour accommoder les fichiers de bureau qui ne respectent pas la spécification des entrées de bureau. Plusieurs modes peuvent être spécifiés. Ils doivent être séparés par une virgule (,). Chaque mode a une contrepartie nomode, qui désactive le mode nommé. Pour désactiver tous les modes, utilisez --strict-parsing. Un avertissement est imprimé lorsqu'un fichier de bureau utilise une particularité activée. ARGS peut contenir les modes suivants :
wine
Tolérer les codes d'échappement invalides (tels que l'échappement d'un espace pour désactiver la séparation des arguments) dans la clé Exec des fichiers de bureau. Activé par défaut.
multispace
Tolérer l'utilisation de plusieurs espaces pour séparer les arguments dans la clé Exec des fichiers de bureau. Utile pour les fichiers de bureau générés par distrobox. Activé par défaut.

Si ce drapeau est spécifié plusieurs fois, seul le dernier prendra effet. Ils ne sont ni fusionnés ni combinés de quelque manière que ce soit.

Ce drapeau est mutuellement exclusif avec --strict-parsing.

--strict-parsing
Adhérer strictement à la spécification des entrées de bureau lors de l'analyse des fichiers de bureau. Non activé par défaut.

Ce drapeau est mutuellement exclusif avec --desktop-file-quirks.

--version
Affiche la version du programme.
-h, --help
Affiche le message d'aide.

NIVEAUX DE LOG

Certains arguments permettent de définir le niveau de journalisation. j4-dmenu-desktop utilise les niveaux de journalisation suivants : ERROR, WARNING, INFO

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

LOGLEVEL

Les niveaux de journalisation disponibles sont : INFO, DEBUG, WARNING, ERROR. Le niveau par défaut est INFO. Les niveaux WARNING et ERROR sont affichés par défaut. Les niveaux inférieurs activent automatiquement les niveaux supérieurs.

TERM MODE

Plusieurs modes sont disponibles pour le drapeau --term-mode :

default
Le mode par défaut. Un script shell temporaire est créé contenant la commande choisie. Le script se supprime lors de son exécution, j4-dmenu-desktop ne le supprime jamais lui-même. Il définit le titre de l'émulateur de terminal à l'aide de séquences d'échappement OSC (voir console_codes(4)). L'émulateur de terminal est exécuté comme suit :
[terminal emulator] -e [script temporaire généré]

D'autres modes devraient être préférés. Cette approche est universelle mais fragile.

La valeur par défaut de --term est i3-sensible-terminal.

xterm
Utilise la convention d'appel xterm :
[terminal emulator] -title [Nom de l'application de bureau] -e [ligne de commande]

La valeur par défaut de --term est xterm. D'autres émulateurs de terminal compatibles incluent : rxvt-unicode.

alacritty
Utilise la convention d'appel alacritty :
[terminal emulator] -T [Nom de l'application de bureau] -e [ligne de commande]

La valeur par défaut de --term est alacritty. D'autres émulateurs de terminal compatibles incluent : st, foot.

kitty
Utilise la convention d'appel kitty :
[terminal emulator] -T [Nom de l'application de bureau] [ligne de commande]

La valeur par défaut de --term est kitty. D'autres émulateurs de terminal compatibles incluent : foot.

terminator
Utilise la convention d'appel terminator :
[terminal emulator] -T [Nom de l'application de bureau] -x [ligne de commande]

La valeur par défaut de --term est terminator. D'autres émulateurs de terminal compatibles incluent : xfce4-terminal.

gnome-terminal
Utilise la convention d'appel gnome-terminal :
[terminal emulator] --title [Nom de l'application de bureau] -- [ligne de commande]

La valeur par défaut de --term est gnome-terminal.

custom
Permet une gestion complètement personnalisée de --term. Lorsque --term-mode custom est passé, un système alternatif de gestion de --term est utilisé. Il est géré comme une liste d'arguments séparés par un espace ( ). Aucun autre caractère d'espacement ne sert de séparateur d'arguments (ce comportement diffère du shell).

Plusieurs espaces consécutifs seront traités comme un seul espace (sauf pour les espaces échappés). Les espaces de début et de fin dans --term seront ignorés. Cela signifie qu'il n'est pas possible de passer des arguments de longueur nulle à --term.

Le contenu de --term n'est pas exécuté via un shell. Cela signifie que les constructions de shell comme la redirection, le chaînage && et ||, et plus, ne fonctionneront pas. Si vous avez besoin de cela, vous pouvez soit créer un script shell enveloppant et l'appeler depuis --term, soit appeler directement /bin/sh -c ou un autre shell depuis --term (bien que l'utilisation d'un script enveloppant soit préférable, car plus clair et plus simple à utiliser).

Les espaces réservés suivants sont reconnus :

{name}
Nom de l'application de bureau. Utile pour définir le titre.
{cmdline@}
Ligne de commande à exécuter développée en arguments séparés. Cela doit être un argument indépendant ; ‘j4-dmenu-desktop --term-mode custom --term "-e={cmdline@}"’ est invalide.
{cmdline*}
Ligne de commande à exécuter développée en un seul argument. {cmdline@} devrait être préféré à {cmdline*}. Les arguments seront échappés ; le contenu de {cmdline*} peut être passé à /bin/sh -c en toute sécurité.
{script}
Nom de fichier d'un script généré par j4-dmenu-desktop. C'est le même script que celui utilisé par --term-mode default. Le script ne sera généré que si cet espace réservé est spécifié au moins une fois dans --term. Le script définit lui-même le titre du terminal, il ne devrait pas être nécessaire de le définir manuellement.

{cmdline@} et {cmdline*} devraient être préférés à {script}.

Les séquences d'échappement suivantes sont reconnues :

\\
Caractère littéral \.
\{
Caractère littéral {.
\ 
(backslash avec espace) Ne pas traiter l'espace suivant comme un séparateur d'arguments.

Les séquences d'échappement et les espaces réservés indéfinis entraîneront un message d'erreur et l'arrêt du programme.

La valeur par défaut de --term est la même que celle du mode de terminal default.

Voici comment les autres modes s'affichent lorsqu'ils sont écrits en utilisant le mode custom :

default
‘j4-dmenu-desktop --term-mode custom --term "i3-sensible-terminal -e {script}"’
xterm
‘j4-dmenu-desktop --term-mode custom --term "xterm -title {name} -e {cmdline@}"’
alacritty
‘j4-dmenu-desktop --term-mode custom --term "alacritty -T {name} -e {cmdline@}"’
kitty
‘j4-dmenu-desktop --term-mode custom --term "kitty -T {name} {cmdline@}"’
terminator
‘j4-dmenu-desktop --term-mode custom --term "terminator -T {name} -x {cmdline@}"’
gnome-terminal
‘j4-dmenu-desktop --term-mode custom --term "gnome-terminal --title {name} -- {cmdline@}"’

Voici comment l'ancien drapeau -e de gnome-terminal pourrait être utilisé :

j4-dmenu-desktop --term-mode custom --term "gnome-terminal --title {name} -e {cmdline*}"

Voici comment les espaces réservés peuvent être échappés :

j4-dmenu-desktop --term-mode custom --term "echo \{name}\ \{cmdline*}"

--term reçoit deux arguments : ‘echo’ et ‘{name} {cmdline*}’, aucun espace réservé n'est remplacé. j4-dmenu-desktop verrait trois arguments au lieu de deux si le deuxième \ n'avait pas été passé.

ENVIRONNEMENT

I3SOCK
Cette variable remplace le chemin du socket IPC d'i3/Sway.
XDG_DATA_HOME
Répertoire principal contenant les fichiers de bureau.
XDG_DATA_DIRS
Répertoires supplémentaires contenant les fichiers de bureau.
XDG_CURRENT_DESKTOP
Environnement de bureau actuel utilisé pour activer/désactiver les fichiers de bureau dépendants de l'environnement de bureau. Doit être activé par --use-xdg-de.

Les variables d'environnement standard pour les locales sont reconnues en plus de celles listées ci-dessus. Les variables d'environnement exactes utilisées dépendent de l'implémentation, mais la définition de LC_MESSAGES, LC_ALL ou LANG devrait généralement fonctionner.
