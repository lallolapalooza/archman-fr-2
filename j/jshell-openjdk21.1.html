JSHELL(1) Commandes JDK JSHELL(1)

NOM

jshell - évalue interactivement des déclarations, instructions et expressions du langage de programmation Java dans une boucle lire-évaluer-imprimer (REPL)

SYNTAXE

jshell [options] [fichiers-à-charger]

options
Options en ligne de commande, séparées par des espaces. Voir Options pour jshell.
fichiers-à-charger
Un ou plusieurs scripts à exécuter au démarrage de l'outil. Les scripts peuvent contenir des extraits de code ou des commandes JShell valides.

Le script peut être un fichier local ou l'un des scripts prédéfinis suivants :

DEFAULT
Charge les entrées par défaut, couramment utilisées comme imports.
JAVASE
Importe tous les packages Java SE.
PRINTING
Définit les méthodes print, println et printf comme méthodes jshell à utiliser dans l'outil.
TOOLING
Définit javac, jar et d'autres méthodes pour exécuter les outils JDK via leur interface en ligne de commande dans l'outil jshell.

Pour plusieurs scripts, utilisez un espace pour séparer les noms. Les scripts sont exécutés dans l'ordre où ils sont saisis sur la ligne de commande. Les scripts en ligne de commande sont exécutés après les scripts de démarrage. Pour exécuter un script après le démarrage de JShell, utilisez la commande /open.

Pour accepter l'entrée de l'entrée standard et supprimer l'E/S interactive, entrez un trait d'union (-) pour fichiers-à-charger. Cette option permet l'utilisation de l'outil jshell dans des chaînes de tuyaux.

DESCRIPTION

JShell offre un moyen d'évaluer interactivement des déclarations, instructions et expressions du langage de programmation Java, ce qui facilite l'apprentissage du langage, l'exploration de code et d'API inconnus, et le prototypage de code complexe. Les instructions Java, les définitions de variables, les définitions de méthodes, les définitions de classes, les instructions d'importation et les expressions sont acceptées. Les fragments de code saisis sont appelés des snippets.

Au fur et à mesure que les snippets sont saisis, ils sont évalués et un retour est fourni. Le retour varie des résultats et explications des actions à rien, selon le snippet saisi et le mode de retour choisi. Les erreurs sont décrites indépendamment du mode de retour. Commencez avec le mode verbeux pour obtenir le maximum de retour lors de l'apprentissage de l'outil.

Des options en ligne de commande sont disponibles pour configurer l'environnement initial lors du démarrage de JShell. Dans JShell, des commandes sont disponibles pour modifier l'environnement selon les besoins.

Des snippets existants peuvent être chargés à partir d'un fichier pour initialiser une session JShell, ou à tout moment au cours d'une session. Les snippets peuvent être modifiés au sein de la session pour essayer différentes variantes et apporter des corrections. Pour conserver les snippets pour une utilisation ultérieure, enregistrez-les dans un fichier.

OPTIONS POUR JSHELL

--add-exports module/package
Spécifie un package à considérer comme exporté depuis son module de définition.
--add-modules module[,module...]
Spécifie les modules racines à résoudre en plus du module initial.
-Cflag
Fournit un drapeau à passer au compilateur. Pour passer plusieurs drapeaux, fournissez une instance de cette option pour chaque drapeau ou argument de drapeau nécessaire.
--class-path chemin
Spécifie les répertoires et archives où chercher les fichiers de classe. Cette option remplace le chemin dans la variable d'environnement CLASSPATH. Si la variable d'environnement n'est pas définie et que cette option n'est pas utilisée, le répertoire courant est recherché. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.
--enable-preview
Permet au code de dépendre des fonctionnalités d'aperçu de cette version.
--execution spécification
Spécifie un moteur d'exécution alternatif, où spécification est une spécification ExecutionControl. Voir la documentation du package jdk.jshell.spi pour la syntaxe de la spécification.
--feedback mode
Définit le niveau initial de retour fourni en réponse à ce qui est saisi. Le niveau initial peut être remplacé dans une session en utilisant la commande /set feedback mode. La valeur par défaut est normal.

Les valeurs suivantes sont valides pour mode :

verbose
Fournit un retour détaillé pour les entrées. Des informations supplémentaires sur l'action effectuée sont affichées après le résultat de l'action. La prochaine invite est séparée du retour par une ligne vide.
normal
Fournit une quantité moyenne de retour. La prochaine invite est séparée du retour par une ligne vide.
concise
Fournit un retour minimal. La prochaine invite suit immédiatement l'extrait de code ou le retour.
silent
Ne fournit aucun retour. La prochaine invite suit immédiatement l'extrait de code.
custom
Fournit un retour personnalisé basé sur la définition du mode. Les modes de retour personnalisés sont créés dans JShell en utilisant la commande /set mode.
--help ou -h ou -?
Affiche un résumé des options standard et quitte l'outil.
--help-extra ou -X
Affiche un résumé des options non standard et quitte l'outil. Les options non standard peuvent être modifiées sans préavis.
-Jflag
Fournit un drapeau à passer au système d'exécution. Pour passer plusieurs drapeaux, fournissez une instance de cette option pour chaque drapeau ou argument de drapeau nécessaire.
--module-path chemin-modules
Spécifie où trouver les modules d'application. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.
--no-startup
Empêche l'exécution des scripts de démarrage lorsque JShell démarre. Utilisez cette option pour exécuter uniquement les scripts saisis sur la ligne de commande lors du démarrage de JShell, ou pour démarrer JShell sans aucune information préchargée si aucun script n'est saisi. Cette option ne peut pas être utilisée si l'option --startup est utilisée.
-q
Définit le mode de retour sur concis, ce qui équivaut à entrer --feedback concise.
-Rflag
Fournit un drapeau à passer au système d'exécution distant. Pour passer plusieurs drapeaux, fournissez une instance de cette option pour chaque drapeau ou argument de drapeau à passer.
-s
Définit le mode de retour sur silencieux, ce qui équivaut à entrer --feedback silent.
--show-version
Affiche les informations de version et démarre l'outil.
--startup fichier
Remplace le script de démarrage par défaut pour cette session. Le script peut contenir des extraits de code ou des commandes valides.

Le script peut être un fichier local ou l'un des scripts prédéfinis suivants :

DEFAULT
Charge les entrées par défaut, couramment utilisées comme imports.
JAVASE
Importe tous les packages Java SE.
PRINTING
Définit les méthodes print, println et printf comme méthodes jshell à utiliser dans l'outil.
TOOLING
Définit javac, jar et d'autres méthodes pour exécuter les outils JDK via leur interface en ligne de commande dans l'outil jshell.

Pour plusieurs scripts, fournissez une instance distincte de cette option pour chaque script. Les scripts de démarrage sont exécutés lorsque JShell démarre pour la première fois et lorsque la session est redémarrée avec les commandes /reset, /reload ou /env. Les scripts de démarrage sont exécutés dans l'ordre où ils sont saisis sur la ligne de commande.

Cette option ne peut pas être utilisée si l'option --no-startup est utilisée.

-v
Définit le mode de retour sur verbeux, ce qui équivaut à entrer --feedback verbose.
--version
Affiche les informations de version et quitte l'outil.

Spécifie la chaîne à utiliser comme format de réponse pour le champ et le sélecteur spécifiés. La structure de la chaîne de format est décrite dans l'aide en ligne, accessible depuis JShell en utilisant la commande /help /set format.
sélecteur
Spécifie le contexte dans lequel le format de réponse est appliqué. Les sélecteurs sont décrits dans l'aide en ligne, accessible depuis JShell en utilisant la commande /help /set format.

Crée un mode de retour personnalisé avec le nom de mode fourni. Si le nom d'un mode existant est fourni, les paramètres du mode existant sont copiés dans le mode en cours de création.

Les options suivantes sont valides :

-command|-quiet
Spécifie le niveau de retour affiché pour les commandes lors de l'utilisation du mode. Cette option est requise lors de la création d'un mode de retour. Utilisez -command pour afficher des informations et un retour de vérification pour les commandes. Utilisez -quiet pour afficher uniquement les retours essentiels pour les commandes, tels que les messages d'erreur.
-delete
Supprime le mode de retour nommé pour cette session. Le nom du mode à supprimer est requis. Pour supprimer définitivement un mode conservé, utilisez l'option -retain avec cette option. Les modes prédéfinis ne peuvent pas être supprimés.
-retain
Conserve le mode de retour nommé entre les sessions. Le nom du mode à conserver est requis.

Configurez le nouveau mode de retour à l'aide des commandes /set prompt, /set format et /set truncation.

Pour commencer à utiliser le nouveau mode, utilisez la commande /set feedback.

prompt mode "chaîne-de-prompt" "chaîne-de-prompt-de-continuation"
Définit les prompts pour les entrées dans JShell. Si aucun mode n'est entré, les prompts actuels pour tous les modes de retour sont affichés. Si seul un mode est entré, les prompts actuels pour ce mode sont affichés.

Pour définir un prompt, les arguments suivants sont requis :

mode
Spécifie le mode de retour auquel les prompts sont appliqués. Seuls les modes personnalisés créés avec la commande /set mode peuvent être modifiés.
"chaîne-de-prompt"
Spécifie la chaîne à utiliser comme prompt pour la première ligne de l'entrée.
"chaîne-de-prompt-de-continuation"
Spécifie la chaîne à utiliser comme prompt pour les lignes d'entrée supplémentaires nécessaires pour compléter un extrait.
start [-retain] [fichier [fichier...]|option]
Définit les noms des scripts de démarrage utilisés lors de la prochaine entrée des commandes /reset, /reload, ou /env. Si plusieurs scripts sont entrés, les scripts sont exécutés dans l'ordre d'entrée. Si aucun script ou aucune option n'est entré, les paramètres de démarrage actuels sont affichés.

Les scripts peuvent être des fichiers locaux ou l'un des scripts prédéfinis suivants :

Charge les entrées par défaut, qui sont couramment utilisées comme imports.
JAVASE
Importe tous les packages Java SE.
PRINTING
Définit print, println et printf comme méthodes jshell à utiliser dans l'outil.
TOOLING
Définit javac, jar et d'autres méthodes pour exécuter des outils JDK via leur interface en ligne de commande dans l'outil jshell.

Les options suivantes sont valides :

-default
Définit les paramètres de démarrage sur les paramètres par défaut.
-none
Spécifie qu'aucun paramètre de démarrage n'est utilisé.

Utilisez l'option -retain pour enregistrer le paramètre de démarrage entre les sessions.

truncation mode longueur sélecteur
Définit la longueur maximale d'une valeur affichée. Si aucun mode n'est entré, les valeurs de troncature actuelles pour tous les modes de retour sont affichées. Si seul un mode est entré, les valeurs de troncature actuelles pour ce mode sont affichées.

Pour définir des valeurs de troncature, les arguments suivants sont requis :

mode
Spécifie le mode de retour auquel la valeur de troncature est appliquée. Seuls les modes personnalisés créés avec la commande /set mode peuvent être modifiés.
longueur
Spécifie l'entier non signé à utiliser comme longueur maximale pour le sélecteur spécifié.
sélecteur
Spécifie le contexte dans lequel la valeur de troncature est appliquée. Les sélecteurs sont décrits dans l'aide en ligne, accessible depuis JShell en utilisant la commande /help /set truncation.
/types [option]

EXEMPLE DE DÉMARRAGE ET D'ARRÊT D'UNE SESSION

JSHELL

JShell est fourni avec le JDK. Pour démarrer une session, saisissez jshell sur la ligne de commande. Un message de bienvenue est imprimé, et une invite pour saisir des commandes et des extraits est

fournie. 

% jshell
|  Bienvenue dans JShell -- Version 9
|  Pour une introduction tapez : /help intro
jshell>

Pour voir quels extraits ont été chargés automatiquement lorsque JShell a démarré, utilisez la commande /list -start. Les extraits de démarrage par défaut sont des instructions import pour les paquets courants. L'ID de chaque extrait commence par la lettre s, ce qui indique qu'il s'agit d'un extrait de

démarrage. 

jshell> /list -start
  s1 : import java.io.*;
  s2 : import java.math.*;
  s3 : import java.net.*;
  s4 : import java.nio.file.*;
  s5 : import java.util.*;
  s6 : import java.util.concurrent.*;
  s7 : import java.util.function.*;
  s8 : import java.util.prefs.*;
  s9 : import java.util.regex.*;
 s10 : import java.util.stream.*;
jshell>

Pour terminer la session, utilisez la commande

/exit. 

jshell> /exit
|  Au revoir
%

D'EXTRAITS

Les extraits sont des instructions Java, des définitions de variables, des définitions de méthodes, des définitions de classes, des instructions import et des expressions. Les points-virgules de terminaison sont automatiquement ajoutés à la fin d'un extrait terminé s'ils sont

manquants.

L'exemple suivant montre deux variables et une méthode étant définies, et la méthode étant exécutée. Notez qu'une variable temporaire est automatiquement créée pour stocker le résultat car aucune variable n'a été

fournie. 

jshell> int a=4
a ==> 4
jshell> int b=8
b ==> 8

   ...> return i1 * i1;
   ...> }
|  méthode square(int) créée
jshell> square(b)
$5 ==> 64

EXEMPLE DE MODIFICATION

D'EXTRAITS

Modifiez la définition d'une variable, d'une méthode ou d'une classe en la saisissant à

nouveau.

Les exemples suivants montrent une méthode étant définie et la méthode exécutée

: 

jshell> String grade(int testScore) {
   ...>     if (testScore >= 90) {
   ...>         return "Pass";
   ...>     }
   ...>     return "Fail";
   ...> }
|  méthode grade(int) créée
jshell> grade(88)
$3 ==> "Fail"

Pour modifier la méthode grade afin de permettre à plus d'étudiants de réussir, saisissez la définition de la méthode à nouveau et changez la note de réussite à 80. Utilisez la touche flèche haut pour récupérer les entrées précédentes afin d'éviter de devoir les ressaisir et dege dans l'instruction if. L'exemple suivant montre la nouvelle définition et relance la méthode pour montrer le nouveau résultat

: 

jshell> String grade(int testScore) {
   ...>     if (testScore >= 80) {
   ...>         return "Pass";
   ...>     }
   ...>     return "Fail";
   ...> }
|  modified method grade(int)
jshell> grade(88)
$5 ==> "Pass"

Pour les fragments de code de plus de quelques lignes, ou pour effectuer plus de quelques modifications, utilisez la commande /edit pour ouvrir le fragment dans un éditeur. Une fois les modifications terminées, fermez la fenêtre d'édition pour rendre le contrôle à la session JShell. L'exemple suivant montre la commande et le retour fourni lorsque la fenêtre d'édition est fermée. La commande /list est utilisée pour montrer que le score de passage a été modifié à

85. 

jshell> /edit grade
|  modified method grade(int)
jshell> /list grade
   6 : String grade(int testScore) {
           if (testScore >= 85) {
               return "Pass";
           }
           return "Fail";

EXEMPLE DE CRÉATION D'UN MODE DE RETOUR

PERSONNALISÉ

Le mode de retour détermine l'invite affichée, les messages de retour fournis lors de la saisie des fragments de code, et la longueur maximale d'une valeur affichée. Des modes de retour prédéfinis sont fournis. Des commandes pour créer des modes de retour personnalisés sont également

fournies.

Utilisez la commande /set mode pour créer un nouveau mode de retour. Dans l'exemple suivant, le nouveau mode mymode est basé sur le mode de retour prédéfini normal, et le retour de vérification des commandes est affiché

: 

jshell> /set mode mymode normal -command
|  Created new feedback mode: mymode

Comme le nouveau mode est basé sur le mode normal, les invites sont les mêmes. L'exemple suivant montre comment voir quelles invites sont utilisées, puis change les invites par des chaînes personnalisées. La première chaîne représente l'invite standard de JShell. La deuxième chaîne représente l'invite pour les lignes supplémentaires dans les fragments

multilignes. 

jshell> /set prompt mymode
|  /set prompt mymode "\njshell> " "   ...> "
jshell> /set prompt mymode "\nprompt$ " "   continue$ "

La longueur maximale d'une valeur affichée est contrôlée par le paramètre de troncature. Les différents types de valeurs peuvent avoir des longueurs différentes. L'exemple suivant définit une valeur de troncature globale de 72, et une valeur de troncature de 500 pour les expressions de valeur de variable

: 

jshell> /set truncation mymode 72
jshell> /set truncation mymode 500 varvalue

Le retour affiché après la saisie des fragments de code est contrôlé par le paramètre de format et est basé sur le type de fragment saisi et l'action prise pour ce fragment. Dans le mode prédéfini normal, la chaîne créée est affichée lorsqu'une méthode est créée. L'exemple suivant montre comment changer cette chaîne en défini

: 

jshell> /set format mymode action "defined" added-primary

Utilisez la commande /set feedback pour commencer à utiliser le mode de retour qui vient d'être créé. L'exemple suivant montre le mode personnalisé en cours d'utilisation

: 

jshell> /set feedback mymode
|  Feedback mode: mymode
prompt$ int square (int num1){
   continue$ return num1*num1;
   continue$ }
|  defined method square(int)
prompt$
