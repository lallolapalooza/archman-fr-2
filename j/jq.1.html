FILTRE

S

Un programme jq est un « filtre » : il prend une entrée et produit une sortie. Il existe de nombreux filtres intégrés pour extraire un champ particulier d'un objet, ou convertir un nombre en chaîne de caractères, ou diverses autres tâches

standard.

Les filtres peuvent être combinés de diverses manières - vous pouvez acheminer la sortie d'un filtre vers un autre filtre, ou collecter la sortie d'un filtre dans un

tableau.

Certains filtres produisent plusieurs résultats, par exemple il y en a un qui produit tous les éléments de son tableau d'entrée. Acheminer ce filtre vers un second exécute le second filtre pour chaque élément du tableau. Généralement, ce qui serait fait avec des boucles et de l'itération dans d'autres langages est simplement fait en collant des filtres ensemble dans

jq.

Il est important de se rappeler que chaque filtre a une entrée et une sortie. Même des littéraux comme "hello" ou 42 sont des filtres - ils prennent une entrée mais produisent toujours le même littéral en sortie. Les opérations qui combinent deux filtres, comme l'addition, alimentent généralement la même entrée dans les deux et combinent les résultats. Ainsi, vous pouvez implémenter un filtre de moyenne comme add / length - en alimentant le tableau d'entrée à la fois dans le filtre add et le filtre length puis en effectuant la

division.

INVOQUER

JQ

Les filtres jq s'exécutent sur un flux de données JSON. L'entrée de jq est analysée comme une séquence de valeurs JSON séparées par des espaces qui sont transmises au filtre fourni une à la fois. La ou les sorties du filtre sont écrites sur la sortie standard, sous forme de séquence de données JSON séparées par des retours à la

ligne.

Le filtre le plus simple et le plus courant (ou programme jq) est ., qui est l'opérateur identité, copiant les entrées du processeur jq vers le flux de sortie. Parce que le comportement par défaut du processeur jq est de lire des textes JSON depuis le flux d'entrée et d'imprimer les sorties de manière formatée, le programme . sert principalement à valider et à imprimer de manière formatée les entrées. Le langage de programmation jq est assez riche et permet bien plus que simplement la validation et l'impression

formatée.

Remarque : il est important de respecter les règles de guillemets du shell. Comme règle générale, il est préférable de toujours mettre le programme jq entre guillemets (avec des guillemets simples dans les shells Unix), car trop de caractères ayant une signification spéciale pour jq sont aussi des méta-caractères de shell. Par exemple, jq "foo" échouera sur la plupart des shells Unix car cela revient à jq foo, ce qui échouera généralement car foo n'est pas défini. Lors de l'utilisation du shell de commande Windows (cmd.exe), il est préférable d'utiliser des guillemets doubles autour de votre programme jq lorsqu'il est donné en ligne de commande (au lieu de l'option -f program-file), mais alors les guillemets doubles dans le programme jq doivent être échappés avec une barre oblique. FILTRES DE BASE

Identité : .

Le filtre le plus simple est . . Ce filtre prend son entrée et produit la même valeur en sortie. C'est donc l'opérateur d'identité.

Comme jq, par défaut, formate joliment toute sortie, un programme trivial ne contenant que . peut être utilisé pour formater la sortie JSON de, par exemple, curl.

Bien que le filtre d'identité ne modifie jamais la valeur de son entrée, le traitement par jq peut parfois donner l'impression qu'il le fait. Par exemple, en utilisant l'implémentation actuelle de jq, nous verrions que l'expression :

1E1234567890 | .

produit 1.7976931348623157e+308 sur au moins une plateforme. C'est parce que, lors de l'analyse du nombre, cette version particulière de jq l'a converti en une représentation double précision IEEE754, perdant ainsi de la précision.

La manière dont jq traite les nombres a changé au fil du temps et d'autres changements sont probables dans les limites fixées par les normes JSON pertinentes. De plus, les options de configuration de la compilation peuvent modifier la façon dont jq traite les nombres.

Les remarques suivantes sont donc faites en gardant à l'esprit qu'elles sont destinées à décrire la version actuelle de jq et ne doivent pas être interprétées comme prescriptives :

(1) Toute opération arithmétique sur un nombre qui n'a pas encore été converti en une représentation double précision IEEE754 déclenchera une conversion vers la représentation IEEE754.

(2) jq tentera de conserver la précision décimale d'origine des littéraux numériques (si l'option de configuration de compilation --disable-decnum n'a pas été utilisée), mais dans des expressions telles que 1E1234567890, la précision sera perdue si l'exposant est trop grand.

(3) Les comparaisons sont effectuées en utilisant la représentation décimale "big decimal" non tronquée des nombres si elle est disponible, comme illustré dans l'un des exemples suivants.

Les exemples ci-dessous utilisent la fonction intégrée have_decnum afin de démontrer les effets attendus de l'utilisation / de la non-utilisation de l'option de configuration de compilation --disable-decnum, et permettent également aux tests automatisés dérivés de ces exemples de passer indépendamment de l'utilisation de cette option.

SYNTAX


jq's syntax is very simple, and mostly consists of the following
    elements:




Basic Filters


The simplest filters are the . filter, which just returns
    its input, and the else filter, which returns its input.



  

  

    
jq ´.´
   123
=> 123

  

  

  








Number Literals


These are the same as in JSON.



  

  

    
jq ´12345´
   null
=> 12345
jq ´-12345´
   null
=> -12345
jq ´0.12345´
   null
=> 0.12345
jq ´1.2345e100´
   null
=> 1.2345e+100

  

  

  








String Literals


These are the same as in JSON.



  

  

    
jq ´"hello world"´
   null
=> "hello world"

  

  

  








Boolean Literals


jq has two boolean literals: true and false.



  

  

    
jq ´true´
   null
=> true
jq ´false´
   null
=> false

  

  

  








Null Literal


jq has one null literal: null.



  

  

    
jq ´null´
   null
=> null

  

  

  








Object Identifier-Index


The simplest useful filter has the form .foo. When
    given a JSON object (aka dictionary or hash) as input, .foo produces
    the value at the key "foo" if the key is present, or null
    otherwise.


A filter of the form .foo.bar is equivalent to .foo |
    .bar.


The .foo syntax only works for simple, identifier-like
    keys, that is, keys that are all made of alphanumeric characters and
    underscore, and which do not start with a digit.


If the key contains special characters or starts with a digit, you
    need to surround it with double quotes like this: ."foo$",
    or else .["foo$"].


For example .["foo::bar"] and
    .["foo.bar"] work while .foo::bar does not.



  

  

    
jq ´.foo´
   {"foo": 42, "bar": "less interesting data"}
=> 42
jq ´.foo´
   {"notfoo": true, "alsonotfoo": false}
=> null
jq ´.["foo"]´
   {"foo": 42}
=> 42

  

  

  








Optional Object Identifier-Index


Just like .foo, but does not output an error when .
    is not an object.



  

  

    
jq ´.foo?´
   {"foo": 42, "bar": "less interesting data"}
=> 42
jq ´.foo?´
   {"notfoo": true, "alsonotfoo": false}
=> null
jq ´.["foo"]?´
   {"foo": 42}
=> 42
jq ´[.foo?]´
   [1,2]
=> []

  

  

  








Object Index


You can also look up fields of an object using syntax like
    .["foo"] (.foo above is a shorthand version of this,
    but only for identifier-like strings).






Array Index


When the index value is an integer, .[<number>] can
    index arrays. Arrays are zero-based, so .[2] returns the third
    element.


Negative indices are allowed, with -1 referring to the last
    element, -2 referring to the next to last element, and so on.



  

  

    
jq ´.[0]´
   [{"name":"JSON", "good":true}, {"name":"XML", "good":false}]
=> {"name":"JSON", "good":true}
jq ´.[2]´
   [{"name":"JSON", "good":true}, {"name":"XML", "good":false}]
=> null
jq ´.[-2]´
   [1,2,3]
=> 2

  

  

  








Array/String Slice


The .[<number>:<number>] syntax can be used to
    return a subarray of an array or substring of a string. The array returned
    by .[10:15] will be of length 5, containing the elements from index
    10 (inclusive) to index 15 (exclusive). Either index may be negative (in
    which case it counts backwards from the end of the array), or omitted (in
    which case it refers to the start or end of the array). Indices are
    zero-based.



  

  

    
jq ´.[2:4]´
   ["a","b","c","d","e"]
=> ["c", "d"]
jq ´.[2:4]´
   "abcdefghi"
=> "cd"
jq ´.[:3]´
   ["a","b","c","d","e"]
=> ["a", "b", "c"]
jq ´.[-2:]´
   ["a","b","c","d","e"]
=> ["d", "e"]

  

  

  








Array/Object Value Iterator


If you use the .[index] syntax, but omit the index
    entirely, it will return all of the elements of an array. Running
    .[] with the input [1,2,3] will produce the numbers as three
    separate results, rather than as a single array. A filter of the form
    .foo[] is equivalent to .foo | .[].


You can also use this on an object, and it will return all the
    values of the object.


Note that the iterator operator is a generator of values.



  

  

    
jq ´.[]´
   [{"name":"JSON", "good":true}, {"name":"XML", "good":false}]
=> {"name":"JSON", "good":true}, {"name":"XML", "good":false}
jq ´.[]´
   []
=> 
jq ´.foo[]´
   {"foo":[1,2,3]}
=> 1, 2, 3
jq ´.[]´
   {"a": 1, "b": 1}
=> 1, 1

  

  

  








.[]?


Like .[], but no errors will be output if . is not an array
    or object. A filter of the form .foo[]? is equivalent to .foo |
    .[]?.






Comma


If two filters are separated by a comma, then the same input will
    be fed into both and the two filters´ output value streams will be
    concatenated in order: first, all of the outputs produced by the left
    expression, and then all of the outputs produced by the right. For instance,
    filter .foo, .bar, produces both the "foo" fields and
    "bar" fields as separate outputs.


The , operator is one way to construct generators.



  

  

    
jq ´.foo, .bar´
   {"foo": 42, "bar": "something else", "baz": true}
=> 42, "something else"
jq ´.user, .projects[]´
   {"user":"stedolan", "projects": ["jq", "wikiflow"]}
=> "stedolan", "jq", "wikiflow"
jq ´.[4,2]´
   ["a","b","c","d","e"]
=> "e", "c"

  

  

  








Pipe


The | operator combines two filters by feeding the output(s) of
    the one on the left into the input of the one on the right. It´s
    similar to the Unix shell´s pipe, if you´re used to that.


If the one on the left produces multiple results, the one on the
    right will be run for each of those results. So, the expression .[] |
    .foo retrieves the "foo" field of each element of the input
    array. This is a cartesian product, which can be surprising.


Note that .a.b.c is the same as .a | .b | .c.


Note too that . is the input value at the particular stage
    in a "pipeline", specifically: where the . expression
    appears. Thus .a | . | .b is the same as .a.b, as the .
    in the middle refers to whatever value .a produced.



  

  

    
jq ´.[] | .name´
   [{"name":"JSON", "good":true}, {"name":"XML", "good":false}]
=> "JSON", "XML"

  

  

  








Parenthesis


Parenthesis work as a grouping operator just as in any typical
    programming language.



  

  

    
jq ´(. + 2) * 5´
   1
=> 15

  

  

  










TYPES AND VALUES


jq supports the same set of datatypes as JSON - numbers, strings,
    booleans, arrays, objects (which in JSON-speak are hashes with only string
    keys), and "null".


Booleans, null, strings and numbers are written the same way as in
    JSON. Just like everything else in jq, these simple values take an input and
    produce an output - 42 is a valid jq expression that takes an input,
    ignores it, and returns 42 instead.


Numbers in jq are internally represented by their IEEE754 double
    precision approximation. Any arithmetic operation with numbers, whether they
    are literals or results of previous filters, will produce a double precision
    floating point result.


However, when parsing a literal jq will store the original literal
    string. If no mutation is applied to this value then it will make to the
    output in its original form, even if conversion to double would result in a
    loss.




Array construction


As in JSON, [] is used to construct arrays, as in
    [1,2,3]. The elements of the arrays can be any jq expression,
    including a pipeline. All of the results produced by all of the expressions
    are collected into one big array. You can use it to construct an array out
    of a known quantity of values (as in [.foo, .bar, .baz]) or to
    "collect" all the results of a filter into an array (as in
    [.items[].name])


Once you understand the "," operator, you can look at
    jq´s array syntax in a different light: the expression [1,2,3]
    is not using a built-in syntax for comma-separate





d tableaux, mais applique
    au contraire l'opérateur [] (collecter les résultats) à l'expression
    1,2,3 (qui produit trois résultats différents).


Si vous avez un filtre X qui produit quatre résultats,
    alors l'expression [X] produira un seul résultat, un tableau de
    quatre éléments.



  

  

  

    
jq ´[.user, .projects[]]´
   {"user":"stedolan", "projects": ["jq", "wikiflow"]}
=> ["stedolan", "jq", "wikiflow"]
jq ´[ .[] | . * 2]´
   [1, 2, 3]
=> [2, 4, 6]

Construction d'objets: {}

Comme en JSON, {} sert à construire des objets (aussi appelés dictionnaires ou tables de hachage), comme dans : {"a": 42, "b": 17}.

Si les clés sont de type "identifiant", les guillemets peuvent être omis, comme dans {a:42, b:17}. Les références de variables comme expressions de clé utilisent la valeur de la variable comme clé. Les expressions de clé autres que les littéraux constants, les identifiants ou les références de variables, doivent être mises entre parenthèses, par exemple {("a"+"b"):59}.

La valeur peut être n'importe quelle expression (bien que vous puissiez avoir besoin de l'envelopper entre parenthèses si, par exemple, elle contient des deux-points), qui est appliquée à l'entrée de l'expression {} (rappelez-vous, tous les filtres ont une entrée et une sortie).

{foo: .bar}

produira l'objet JSON {"foo": 42} si l'objet JSON {"bar":42, "baz":43} lui est donné en entrée. Vous pouvez utiliser ceci pour sélectionner des champs particuliers d'un objet : si l'entrée est un objet avec les champs "user", "title", "id" et "content" et que vous ne voulez que "user" et "title", vous pouvez écrire

{user: .user, title: .title}

Comme c'est très courant, il existe une syntaxe raccourcie pour cela : {user, title}.

Si l'une des expressions produit plusieurs résultats, plusieurs dictionnaires seront produits. Si l'entrée est

{"user":"stedolan","titles":["JQ Primer", "More JQ"]}

alors l'expression

{user, title: .titles[]}

produira deux sorties :

{"user":"stedolan", "title": "JQ Primer"}
{"user":"stedolan", "title": "More JQ"}

Mettre des parenthèses autour de la clé signifie qu'elle sera évaluée comme une expression. Avec la même entrée que ci-dessus,

{(.user): .titles}

produit

{"stedolan": ["JQ Primer", "More JQ"]}

Les références de variables comme clés utilisent la valeur de la variable comme clé. Sans valeur, le nom de la variable devient la clé et sa valeur devient la valeur,

"f o o" as $foo | "b a r" as $bar | {$foo, $bar:$foo}

produit

{"foo":"f o o","b a r":"f o o"}
jq ´{user, title: .titles[]}´
   {"user":"stedolan","titles":["JQ Primer", "More JQ"]}
=> {"user":"stedolan", "title": "JQ Primer"}, {"user":"stedolan", "title": "More JQ"}
jq ´{(.user): .titles}´
   {"user":"stedolan","titles":["JQ Primer", "More JQ"]}
=> {"stedolan": ["JQ Primer", "More JQ"]}

Descente récursive: ..

Descend récursivement dans ., produisant chaque valeur. C'est la même chose que la fonction intégrée recurse sans argument (voir ci-dessous). Ceci est destiné à ressembler à l'opérateur XPath //. Notez que ..a ne fonctionne pas ; utilisez plutôt .. | .a. Dans l'exemple ci-dessous, nous utilisons .. | .a? pour trouver toutes les valeurs des clés d'objet "a" dans n'importe quel objet trouvé "en dessous" de ..

Ceci est particulièrement utile en conjonction avec path(EXP) (voir aussi ci-dessous) et l'opérateur ?.

jq ´.. | .a?´
   [[{"a":1}]]
=> 1

OPÉRATEURS ET FONCTIONS INTÉGRÉS

Certains opérateurs jq (par exemple, +) font des choses différentes en fonction du type de leurs arguments (tableaux, nombres, etc.). Cependant, jq ne fait jamais de conversions de type implicites. Si vous essayez d'ajouter une chaîne à un objet, vous obtiendrez un message d'erreur et aucun résultat.

Veuillez noter que tous les nombres sont convertis en représentation en virgule flottante double précision IEEE754. Les opérations arithmétiques et logiques fonctionnent avec ces doubles convertis. Les résultats de toutes ces opérations sont également limités à la précision double.

La seule exception à ce comportement des nombres est une instantanéité du littéral numérique d'origine. Lorsqu'un nombre qui était initialement fourni comme littéral n'est pas muté jusqu'à la fin du programme, il est affiché en sortie sous sa forme littérale d'origine. Cela inclut les cas où le littéral d'origine serait tronqué lors de la conversion en nombre à virgule flottante double précision IEEE754.

Addition: +

L'opérateur + prend deux filtres, les applique tous deux à la même entrée, et ajoute les résultats. Ce que signifie "ajouter" dépend des types impliqués :

  • Les nombres sont ajoutés par arithmétique normale.
  • Les tableaux sont ajoutés en étant concaténés en un tableau plus grand.
  • Les chaînes sont ajoutées en étant jointes en une chaîne plus grande.
  • Les objets sont ajoutés par fusion, c'est-à-dire en insérant toutes les paires clé-valeur des deux objets dans un seul objet combiné. Si les deux objets contiennent une valeur pour la même clé, l'objet à droite du + l'emporte. (Pour une fusion récursive, utilisez l'opérateur *.)

null peut être ajouté à n'importe quelle valeur, et renvoie l'autre valeur inchangée.

jq ´.a + 1´
   {"a": 7}
=> 8
jq ´.a + .b´
   {"a": [1,2], "b": [3,4]}
=> [1,2,3,4]
jq ´.a + null´
   {"a": 1}
=> 1
jq ´.a + 1´
   {}
=> 1
jq ´{a: 1} + {b: 2} + {c: 3} + {a: 42}´
   null
=> {"a": 42, "b": 2, "c": 3}

Soustraction: -

En plus de la soustraction arithmétique normale sur les nombres, l'opérateur - peut être utilisé sur des tableaux pour supprimer toutes les occurrences des éléments du second tableau du premier tableau.

jq ´4 - .a´
   {"a":3}
=> 1
jq ´. - ["xml", "yaml"]´
   ["xml", "yaml", "json"]
=> ["json"]

Multiplication, division, modulo: *, /, %

Ces opérateurs infixes se comportent comme prévu lorsqu'ils reçoivent deux nombres. La division par zéro provoque une erreur. x % y calcule x modulo y.

Multiplier une chaîne par un nombre produit la concaténation de cette chaîne autant de fois. "x" * 0 produit "".

Diviser une chaîne par une autre divise la première en utilisant la seconde comme séparateurs.

Multiplier deux objets les fusionne récursivement : cela fonctionne comme l'addition, mais si les deux objets contiennent une valeur pour la même clé, et que les valeurs sont des objets, les deux sont fusionnés avec la même stratégie.

jq ´10 / . * 3´
   5
=> 6
jq ´. / ", "´
   "a, b,c,d, e"
=> ["a","b,c,d","e"]
jq ´{"k": {"a": 1, "b": 2}} * {"k": {"a": 0,"c": 3}}´
   null
=> {"k": {"a": 0, "b": 2, "c": 3}}
jq ´.[] | (1 / .)?´
   [1,0,-1]
=> 1, -1

La fonction intégrée keys, lorsqu'on lui donne un objet, renvoie ses clés sous forme de tableau.

Les clés sont triées "alphabétiquement", par ordre de point de code unicode. Ce n'est pas un ordre qui a un sens particulier dans une langue donnée, mais vous pouvez compter sur le fait qu'il sera le même pour deux objets ayant le même ensemble de clés, indépendamment des paramètres régionaux.

map(f), map_values(f)

Pour tout filtre f, map(f) et map_values(f) appliquent f à chacune des valeurs du tableau ou de l'objet d'entrée, c'est-à-dire aux valeurs de .[].

En l'absence d'erreurs, map(f) renvoie toujours un tableau, tandis que map_values(f) renvoie un tableau si on lui donne un tableau, ou un objet si on lui donne un objet.

Lorsque l'entrée de map_values(f) est un objet, l'objet de sortie a les mêmes clés que l'objet d'entrée, à l'exception des clés dont les valeurs, lorsqu'elles sont passées à f, ne produisent aucune valeur.

La principale différence entre map(f) et map_values(f) est que la première forme simplement un tableau à partir de toutes les valeurs de ($x|f) pour chaque valeur, $x, du tableau ou de l'objet d'entrée, mais map_values(f) n'utilise que first($x|f).

Spécifiquement, pour les entrées objet, map_values(f) construit l'objet de sortie en examinant successivement la valeur de first(.[$k]|f) pour chaque clé, $k, de l'entrée. Si cette expression ne produit aucune valeur, la clé correspondante sera supprimée ; sinon, l'objet de sortie aura cette valeur à la clé, $k.

Voici quelques exemples pour clarifier le comportement de map et map_values lorsqu'ils sont appliqués à des tableaux. Ces exemples supposent que l'entrée est [1] dans tous les cas :

map(.+1)          #=>  [2]
map(., .)         #=>  [1,1]
map(empty)        #=>  []
map_values(.+1)   #=>  [2]
map_values(., .)  #=>  [1]
map_values(empty) #=>  []

map(f) est équivalent à [.[] | f] et map_values(f) est équivalent à .[] |= f.

En fait, ce sont leurs implémentations.

jq ´map(.+1)´
   [1,2,3]
=> [2,3,4]
jq ´map_values(.+1)´
   {"a": 1, "b": 2, "c": 3}
=> {"a": 2, "b": 3, "c": 4}
jq ´map(., .)´
   [1,2]
=> [1,1,2,2]
jq ´map_values(. // empty)´
   {"a": null, "b": true, "c": false}
=> {"b":true}

La fonction sort trie son entrée, qui doit être un tableau. Les valeurs sont triées dans l'ordre suivant :

Alternative operator: //

The // operator produces all the values of its left-hand side that are neither false nor null. If the left-hand side produces no values other than false or null, then // produces all the values of its right-hand side.

AVANCÉES

Les variables sont une nécessité absolue dans la plupart des langages de programmation, mais elles sont reléguées au rang de « fonctionnalité avancée » dans

Dans la plupart des langages, les variables sont le seul moyen de transmettre des données. Si vous calculez une valeur et que vous souhaitez l'utiliser plus d'une fois, vous devrez la stocker dans une variable. Pour passer une valeur à une autre partie du programme, vous devrez que cette partie du programme définisse une variable (en tant que paramètre de fonction, membre d'objet ou autre) dans laquelle placer les

Il est également possible de définir des fonctions dans jq, bien que ce soit une fonctionnalité dont la principale utilité est la définition de la bibliothèque standard de jq (de nombreuses fonctions jq telles que map et select sont en fait écrites en jq)

jq possède des opérateurs de réduction, qui sont très puissants mais un peu délicats. Encore une fois, ceux-ci sont principalement utilisés en interne, pour définir certaines parties utiles de la bibliothèque standard de

jq.

Cela peut ne pas être évident au début, mais jq tourne autour des générateurs (oui, comme on en trouve souvent dans d'autres langages). Certaines utilitaires sont fournies pour aider à gérer les

générateurs.

Une prise en charge minimale des entrées/sorties (en plus de la lecture JSON depuis l'entrée standard et de l'écriture JSON vers la sortie standard) est

disponible.

Enfin, il existe un système de modules/bibliothèques

Dans jq, tous les filtres ont une entrée et une sortie, donc le câblage manuel n'est pas nécessaire pour passer une valeur d'une partie d'un programme à la suivante. ASSIGNMENT

Assignment works a little differently in jq than in most programming languages. jq doesn´t distinguish between references to and copies of something - two objects or arrays are either equal or not equal, without any further notion of being "the same object" or "not the same object".

If an object has two fields which are arrays, .foo and .bar, and you append something to .foo, then .bar will not get bigger, even if you´ve previously set .bar = .foo. If you´re used to programming in languages like Python, Java, Ruby, JavaScript, etc. then you can think of it as though jq does a full deep copy of every object before it does the assignment (for performance it doesn´t actually do that, but that´s the general idea).

This means that it´s impossible to build circular values in jq (such as an array whose first element is itself). This is quite intentional, and ensures that anything a jq program can produce can be represented in JSON.

All the assignment operators in jq have path expressions on the left-hand side (LHS). The right-hand side (RHS) provides values to set to the paths named by the LHS path expressions.

Values in jq are always immutable. Internally, assignment works by using a reduction to compute new, replacement values for . that have had all the desired assignments applied to ., then outputting the modified value. This might be made clear by this example: {a:{b:{c:1}}} | (.a.b|=3), .. This will output {"a":{"b":3}} and {"a":{"b":{"c":1}}} because the last sub-expression, ., sees the original value, not the modified value.

Most users will want to use modification assignment operators, such as |= or +=, rather than =.

Note that the LHS of assignment operators refers to a value in .. Thus $var.foo = 1 won´t work as expected ($var.foo is not a valid or useful path expression in .); use $var | .foo = 1 instead.

Note too that .a,.b=0 does not set .a and .b, but (.a,.b)=0 sets both.

Update-assignment: |=

This is the "update" operator |=. It takes a filter on the right-hand side and works out the new value for the property of . being assigned to by running the old value through this expression. For instance, (.foo, .bar) |= .+1 will build an object with the foo field set to the input´s foo plus 1, and the bar field set to the input´s bar plus 1.

The left-hand side can be any general path expression; see path().

Note that the left-hand side of |= refers to a value in .. Thus $var.foo |= . + 1 won´t work as expected ($var.foo is not a valid or useful path expression in .); use $var | .foo |= . + 1 instead.

If the right-hand side outputs no values (i.e., empty), then the left-hand side path will be deleted, as with del(path).

If the right-hand side outputs multiple values, only the first one will be used (COMPATIBILITY NOTE: in jq 1.5 and earlier releases, it used to be that only the last one was used).

jq ´(..|select(type=="boolean")) |= if . then 1 else 0 end´
   [true,false,[5,true,[true,[false]],false]]
=> [1,0,[5,1,[1,[0]],0]]

Arithmetic update-assignment: +=, -=, *=, /=, %=, //=

jq has a few operators of the form a op= b, which are all equivalent to a |= . op b. So, += 1 can be used to increment values, being the same as |= . + 1.

jq ´.foo += 1´
   {"foo": 42}
=> {"foo": 43}

Plain assignment: =

This is the plain assignment operator. Unlike the others, the input to the right-hand side (RHS) is the same as the input to the left-hand side (LHS) rather than the value at the LHS path, and all values output by the RHS will be used (as shown below).

If the RHS of = produces multiple values, then for each such value jq will set the paths on the left-hand side to the value and then it will output the modified .. For example, (.a,.b) = range(2) outputs {"a":0,"b":0}, then {"a":1,"b":1}. The "update" assignment forms (see above) do not do this.

This example should show the difference between = and |=:

Provide input {"a": {"b": 10}, "b": 20} to the programs

.a = .b

and

.a |= .b

The former will set the a field of the input to the b field of the input, and produce the output {"a": 20, "b": 20}. The latter will set the a field of the input to the a field´s b field, producing {"a": 10, "b": 20}.

jq ´.a = .b´
   {"a": {"b": 10}, "b": 20}
=> {"a":20,"b":20}
jq ´.a |= .b´
   {"a": {"b": 10}, "b": 20}
=> {"a":10,"b":20}
jq ´(.a, .b) = range(3)´
   null
=> {"a":0,"b":0}, {"a":1,"b":1}, {"a":2,"b":2}
jq ´(.a, .b) |= range(3)´
   null
=> {"a":0,"b":0}

Complex assignments

Lots more things are allowed on the left-hand side of a jq assignment than in most languages. We´ve already seen simple field accesses on the left hand side, and it´s no surprise that array accesses work just as well:

.posts[0].title = "JQ Manual"

What may come as a surprise is that the expression on the left may produce multiple results, referring to different points in the input document:

.posts[].comments |= . + ["this is great"]

That example appends the string "this is great" to the "comments" array of each post in the input (where the input is an object with a field "posts" which is an array of posts).

When jq encounters an assignment like ´a = b´, it records the "path" taken to select a part of the input document while executing a. This path is then used to find which part of the input to change while executing the assignment. Any filter may be used on the left-hand side of an equals - whichever paths it selects from the input will be where the assignment is performed.

This is a very powerful operation. Suppose we wanted to add a comment to blog posts, using the same "blog" input above. This time, we only want to comment on the posts written by "stedolan". We can find those posts using the "select" function described earlier:

.posts[] | select(.author == "stedolan")

The paths provided by this operation point to each of the posts that "stedolan" wrote, and we can comment on each of them in the same way that we did before:

(.posts[] | select(.author == "stedolan") | .comments) |=
    . + ["terrible."]

COMMENTS

You can write comments in your jq filters using #.

A # character (not part of a string) starts a comment. All characters from # to the end of the line are ignored.

If the end of the line is preceded by an odd number of backslash characters, the following line is also considered part of the comment and is ignored.

For example, the following code outputs [1,3,4,7]

[
  1,
  # foo \
  2,
  # bar \\
  3,
  4, # baz \\\
  5, \
  6,
  7
  # comment \
    comment \
    comment
]

Backslash continuing the comment on the next line can be useful when writing the "shebang" for a jq script:

#!/bin/sh --
# total - Output the sum of the given arguments (or stdin)
# usage: total [numbers...]
# \
exec jq --args -MRnf -- "$0" "$@"
$ARGS.positional |
reduce (
  if . == []
    then inputs
    else .[]
  end |
  . as $dot |
  try tonumber catch false |
  if not or isnan then
    @json "total: Invalid number \($dot).\n" | halt_error(1)
  end
) as $n (0; . + $n)

The exec line is considered a comment by jq, so it is ignored. But it is not ignored by sh, since in sh a backslash at the end of the line does not continue the comment. With this trick, when the script is invoked as total 1 2, /bin/sh -- /path/to/total 1 2 will be run, and sh will then run exec jq --args -MRnf -- /path/to/total 1 2 replacing itself with a jq interpreter invoked with the specified options (-M, -R, -n, --args), that evaluates th

e fichier actuel ($0), avec les arguments ($@) qui ont été passés à sh.

MODULES

jq possède un système de bibliothèques/modules. Les modules sont des fichiers dont les noms se terminent par .jq.

Les modules importés par un programme sont recherchés dans un chemin de recherche par défaut (voir ci-dessous). Les directives import et include permettent à l'importateur de modifier ce chemin.

Les chemins dans le chemin de recherche sont soumis à diverses substitutions.

Pour les chemins commençant par ~/, le répertoire personnel de l'utilisateur est substitué à ~.

Pour les chemins commençant par $ORIGIN/, le répertoire où se trouve l'exécutable jq est substitué à $ORIGIN.

Pour les chemins commençant par ./ ou les chemins qui sont ., le chemin du fichier incluant est substitué à .. Pour les programmes de niveau supérieur donnés sur la ligne de commande, le répertoire courant est utilisé.

Les directives d'importation peuvent éventuellement spécifier un chemin de recherche auquel le chemin par défaut est ajouté.

Le chemin de recherche par défaut est le chemin de recherche donné à l'option de ligne de commande -L, sinon ["~/.jq", "$ORIGIN/../lib/jq", "$ORIGIN/../lib"].

Les éléments de chemin nuls et de chaîne vide terminent le traitement du chemin de recherche.

Une dépendance avec un chemin relatif foo/bar serait recherchée dans foo/bar.jq et foo/bar/bar.jq dans le chemin de recherche donné. Ceci est destiné à permettre aux modules d'être placés dans un répertoire avec, par exemple, des fichiers de contrôle de version, des fichiers README, etc., mais aussi à permettre des modules à fichier unique.

Les composants consécutifs du même nom ne sont pas autorisés pour éviter les ambiguïtés (par exemple, foo/foo).

Par exemple, avec -L$HOME/.jq, un module foo peut être trouvé dans $HOME/.jq/foo.jq et $HOME/.jq/foo/foo.jq.

Si .jq existe dans le répertoire personnel de l'utilisateur, et qu'il s'agit d'un fichier (pas d'un répertoire), il est automatiquement sourcé dans le programme principal.

import RelativePathString as NAME [<metadata>];

Importe un module trouvé au chemin donné relatif à un répertoire dans un chemin de recherche. Un suffixe .jq sera ajouté à la chaîne de chemin relatif. Les symboles du module sont préfixés par NAME::.

Les métadonnées optionnelles doivent être une expression jq constante. Elles doivent être un objet avec des clés comme homepage, etc. Pour l'instant, jq utilise uniquement la clé/valeur search des métadonnées. Les métadonnées sont également mises à la disposition des utilisateurs via la fonction intégrée modulemeta.

La clé search dans les métadonnées, si elle est présente, doit avoir une valeur de type chaîne ou tableau (tableau de chaînes) ; c'est le chemin de recherche qui sera ajouté en préfixe au chemin de recherche de niveau supérieur.

include RelativePathString [<metadata>];

Importe un module trouvé au chemin donné relatif à un répertoire dans un chemin de recherche comme s'il était inclus sur place. Un suffixe .jq sera ajouté à la chaîne de chemin relatif. Les symboles du module sont importés dans l'espace de noms de l'appelant comme si le contenu du module avait été inclus directement.

Les métadonnées optionnelles doivent être une expression jq constante. Elles doivent être un objet avec des clés comme homepage, etc. Pour l'instant, jq utilise uniquement la clé/valeur search des métadonnées. Les métadonnées sont également mises à la disposition des utilisateurs via la fonction intégrée modulemeta.

import RelativePathString as $NAME [<metadata>];

Importe un fichier JSON trouvé au chemin donné relatif à un répertoire dans un chemin de recherche. Un suffixe .json sera ajouté à la chaîne de chemin relatif. Les données du fichier seront disponibles sous le nom $NAME::NAME.

Les métadonnées optionnelles doivent être une expression jq constante. Elles doivent être un objet avec des clés comme homepage, etc. Pour l'instant, jq utilise uniquement la clé/valeur search des métadonnées. Les métadonnées sont également mises à la disposition des utilisateurs via la fonction intégrée modulemeta.

La clé search dans les métadonnées, si elle est présente, doit avoir une valeur de type chaîne ou tableau (tableau de chaînes) ; c'est le chemin de recherche qui sera ajouté en préfixe au chemin de recherche de niveau supérieur.

module <metadata>;

Cette directive est entièrement facultative. Elle n'est pas requise pour un fonctionnement correct. Elle sert uniquement à fournir des métadonnées qui peuvent être lues avec la fonction intégrée modulemeta.

Les métadonnées doivent être une expression jq constante. Elles doivent être un objet avec des clés comme homepage. Pour l'instant, jq n'utilise pas ces métadonnées, mais elles sont mises à la disposition des utilisateurs via la fonction intégrée modulemeta.

modulemeta

Prend un nom de module en entrée et produit les métadonnées du module sous forme d'objet, avec les importations du module (y compris les métadonnées) sous forme de tableau pour la clé deps et les fonctions définies du module sous forme de tableau pour la clé defs.

Les programmes peuvent l'utiliser pour interroger les métadonnées d'un module, ce qui pourrait leur permettre, par exemple, de rechercher, télécharger et installer les dépendances manquantes.

COULEURS

Pour configurer des couleurs alternatives, définissez simplement la variable d'environnement JQ_COLORS avec une liste de séquences d'échappement de terminal partielles séparées par des deux-points, comme "1;31", dans cet ordre :

  • couleur pour null
  • couleur pour false
  • couleur pour true
  • couleur pour les nombres
  • couleur pour les chaînes
  • couleur pour les tableaux
  • couleur pour les objets
  • couleur pour les clés d'objet

Le schéma de couleurs par défaut est le même que celui de la définition de JQ_COLORS="0;90:0;39:0;39:0;39:0;32:1;39:1;39:1;34".

Ceci n'est pas un manuel pour les séquences d'échappement VT100/ANSI. Cependant, chacune de ces spécifications de couleur doit se composer de deux nombres séparés par un point-virgule, où le premier nombre est l'un des suivants :

  • 1 (brillant)
  • 2 (terne)
  • 4 (souligné)
  • 5 (clignotant)
  • 7 (inversé)
  • 8 (caché)

et le second est l'un des suivants :

  • 30 (noir)
  • 31 (rouge)
  • 32 (vert)
  • 33 (jaune)
  • 34 (bleu)
  • 35 (magenta)
  • 36 (cyan)
  • 37 (blanc)
