DESCRIPTIO

N

La commande jdeps affiche les dépendances au niveau du paquet ou au niveau de la classe des fichiers de classe Java. La classe en entrée peut être un chemin vers un fichier .class, un répertoire, un fichier JAR, ou un nom de classe entièrement qualifié pour analyser tous les fichiers de classe. Les options déterminent la sortie. Par défaut, la commande jdeps écrit les dépendances sur la sortie standard. La commande peut générer les dépendances en langage DOT (voir l'option -dotou

OPTIONS DE FILTRAGE DES

DÉPENDANCES
-p nom_paquet, -package nom_paquetg_name, ou --package pkg_name
Trouve les dépendances correspondant au nom du paquet spécifié. Vous pouvez spécifier cette option plusieurs fois pour différents paquets. Les options -p et -e sont mutuellement exclusives.
-e regex, -regex regex, ou --regex regex
Trouve les dépendances correspondant au motif spécifié. Les options -p et -e sont mutuellement exclusives.
--require module-name
Trouve les dépendances correspondant au nom du module donné (peut être donné plusieurs fois). Les options --package, --regex et --require sont mutuellement exclusives.
-f regex ou -filter regex
Filtre les dépendances correspondant au motif donné. Si donné plusieurs fois, le dernier sera sélectionné.
-filter:package
Filtre les dépendances au sein du même paquet. C'est le comportement par défaut.
-filter:archive
Filtre les dépendances au sein de la même archive.
-filter:module
Filtre les dépendances au sein du même module.
-filter:none
Aucun filtrage -filter:package et -filter:archive. Le filtrage spécifié via l'option -filter s'applique toujours.
--missing-deps
Trouve les dépendances manquantes. Cette option ne peut pas être utilisée avec les options -p, -e et -s.

OPTIONS POUR FILTRER LES CLASSES À ANALYSER

-include regex
Restreint l'analyse aux classes correspondant au motif. Cette option filtre la liste des classes à analyser. Elle peut être utilisée conjointement avec -p et -e, qui appliquent le motif aux dépendances.
-R ou --recursive
Traverse récursivement toutes les dépendances d'exécution. L'option -R implique -filter:none. Si les options -p, -e ou -f sont spécifiées, seules les dépendances correspondantes sont analysées.
--no-recursive
Ne pas traverser récursivement les dépendances.
-I ou --inverse
Analyse les dépendances selon les autres options données, puis trouve tous les artefacts qui dépendent directement ou indirectement des nœuds correspondants. Ceci est l'équivalent inverse de l'analyse de la vue de compilation et du résumé de dépendance imprimé. Cette option doit être utilisée avec les options --require, --package ou --regex.
--compile-time
Analyse la vue de compilation des dépendances transitives, telle que la vue de compilation de l'option -R. Analyse les dépendances selon les autres options spécifiées. Si une dépendance est trouvée à partir d'un répertoire, d'un fichier JAR ou d'un module, toutes les classes de l'archive contenant sont analysées.
