NOM

jfr - afficher et manipuler les fichiers Flight Recorder

SYNOPSIS

Pour afficher le contenu d'un enregistrement de vol sur la sortie standard :

jfr print [options] fichier

Pour afficher des données d'événements agrégées sur la sortie standard :

jfr view [options] fichier

Pour configurer un fichier de paramètres .jfc :

jfr configure [options]

Pour afficher les informations de métadonnées sur les événements d'enregistrement de vol :

jfr metadata [fichier]

Pour afficher les statistiques résumées d'un fichier d'enregistrement de vol :

jfr summary fichier

Pour supprimer des événements d'un fichier d'enregistrement de vol :

jfr scrub [options] fichier

Pour assembler des fichiers de fragments en un fichier d'enregistrement de vol :

jfr assemble dépôt fichier

Pour désassembler un fichier d'enregistrement de vol en fichiers de fragments :

jfr disassmble [options] fichier

options
Facultatif : spécifie les options de ligne de commande séparées par des espaces. Voir les sections des sous-composants individuels pour les descriptions des options disponibles.
fichier
Spécifie le nom du fichier d'enregistrement de vol cible (.jfr).
dépôt
Spécifie l'emplacement des fichiers de fragments qui doivent être assemblés en un enregistrement de vol.

DESCRIPTION

La commande jfr fournit un outil pour interagir avec les fichiers d'enregistrement de vol (.jfr). Sa fonction principale est de filtrer, résumer et produire en sortie les fichiers d'enregistrement de vol dans un format lisible par l'homme. Il prend également en charge le nettoyage, la fusion et la division des fichiers d'enregistrement.

Les fichiers d'enregistrement de vol sont créés et enregistrés sous forme de fichiers au format binaire. Disposer d'un outil capable d'en extraire le contenu, de le manipuler et de le traduire dans un format lisible par l'homme aide les développeurs à déboguer les problèmes de performance des applications Java.

Sous-commande jfr print

Utilisez jfr print pour afficher le contenu d'un fichier d'enregistrement de vol sur la sortie standard.

La syntaxe est :

jfr print [--xml|--json] [--categories <filtres>] [--events <filtres>] [--stack-depth <profondeur>] <fichier>

où :

--xml
Affiche l'enregistrement au format XML.
--json
Affiche l'enregistrement au format JSON.
--categories <filtres>
Sélectionne les événements correspondant à un nom de catégorie. Le filtre est une liste de noms séparés par des virgules, simples et/ou qualifiés, et/ou des motifs glob entre guillemets.
--events <filtres>
Sélectionne les événements correspondant à un nom d'événement. Le filtre est une liste de noms séparés par des virgules, simples et/ou qualifiés, et/ou des motifs glob entre guillemets.
--stack-depth <profondeur>
Nombre de trames dans les traces de pile, 5 par défaut.
<fichier>
Emplacement du fichier d'enregistrement (.jfr)

Le format par défaut pour l'affichage du contenu du fichier d'enregistrement de vol est la forme lisible par l'homme, sauf si xml ou json est spécifié. Ces options fournissent une sortie lisible par une machine qui peut être ultérieurement analysée ou traitée par des scripts créés par l'utilisateur.

Utilisez jfr --help print pour voir des exemples d'utilisation des filtres.

Pour réduire la quantité de données affichées, il est possible de filtrer des événements ou des catégories d'événements. Le filtre opère sur le nom symbolique d'un événement, défini à l'aide de l'annotation @Name, ou sur le nom de catégorie, défini à l'aide de l'annotation @Category. Si plusieurs filtres sont utilisés, les événements des deux filtres seront inclus. Si aucun filtre n'est utilisé, tous les événements seront affichés. Si une combinaison d'un filtre de catégorie et d'un filtre d'événement est utilisée, les événements sélectionnés seront l'union des deux filtres.

Par exemple, pour afficher tous les événements GC et l'événement CPULoad, la commande suivante pourrait être utilisée :

jfr print --categories GC --events CPULoad recording.jfr

Les valeurs des événements sont formatées selon les types de contenu utilisés. Par exemple, un champ avec l'annotation jdk.jfr.Percentage ayant la valeur 0,52 est formaté en 52 %.

Les traces de pile sont tronquées à 5 trames par défaut, mais le nombre peut être augmenté/diminué à l'aide de l'option de ligne de commande --stack-depth.

Sous-commande jfr view

Utilisez jfr view pour agréger et afficher les données d'événements sur la sortie standard.

La syntaxe est :

jfr view [--verbose] [--width <entier>] [--truncate <mode>] [--cell-height <entier>] <vue> <fichier>

où :

--verbose
Affiche la requête qui constitue la vue.
--width <entier>
La largeur de la vue en caractères. La valeur par défaut dépend de la vue.
--truncate <mode>
Comment tronquer le contenu qui dépasse l'espace dans une cellule de tableau. Le mode peut être 'beginning' (début) ou 'end' (fin). La valeur par défaut est 'end'.
--cell-height <entier>
Nombre maximal de lignes dans une cellule de tableau. La valeur par défaut dépend de la vue.
<vue>
Nom de la vue ou du type d'événement à afficher. Utilisez jfr --help view pour voir la liste des vues disponibles.
<fichier>
Emplacement du fichier d'enregistrement (.jfr)

Le paramètre <vue> peut être un nom de type d'événement. Utilisez jfr view types <fichier> pour voir une liste. Pour afficher toutes les vues, utilisez jfr view all-views <fichier>. Pour afficher tous les événements, utilisez jfr view all-events <fichier>.

Sous-commande jfr configure

Utilisez jfr configure pour configurer un fichier de paramètres .jfc.

La syntaxe est :

jfr configure [--interactive] [--verbose] [--input ] [--output ] [option=value]* [event-setting=value]*

--interactive
Mode interactif où la configuration est déterminée par une série de questions.
--verbose
Affiche les paramètres modifiés.
--input <fichiers>
Une liste de fichiers .jfc séparés par des virgules sur lesquels la nouvelle configuration est basée. Si aucun fichier n'est spécifié, le fichier par défaut du JDK est utilisé (default.jfc). Si 'none' est spécifié, la nouvelle configuration commence vide.
--output <fichier>
Le nom de fichier du fichier de sortie généré. S'il n'est pas spécifié, le nom de fichier custom.jfc sera utilisé.
option=value
La valeur de l'option à modifier. Pour voir les options disponibles, utilisez jfr help configure
event-setting=value
La valeur du paramètre d'événement à modifier. Utilisez la forme : <nom-événement>#<nom-paramètre>=<valeur> Pour ajouter un nouveau paramètre d'événement, préfixez le nom de l'événement avec '+'.

Le délimiteur d'espaces peut être omis pour les valeurs de durée, c'est-à-dire 20ms. Pour plus d'informations sur la syntaxe des paramètres, voir le Javadoc du paquet jdk.jfr.

Sous-commande jfr metadata

Utilisez jfr metadata pour afficher des informations sur les événements, tels que les noms d'événements, les catégories et la disposition des champs au sein d'un fichier d'enregistrement de vol.

La syntaxe est :

jfr metadata [--categories ] [--events ] []

--categories <filtre>
Sélectionne les événements correspondant à un nom de catégorie. Le filtre est une liste de noms séparés par des virgules, simples et/ou qualifiés, et/ou des motifs glob entre guillemets.
--events <filtre>
Sélectionne les événements correspondant à un nom d'événement. Le filtre est une liste de noms séparés par des virgules, simples et/ou qualifiés, et/ou des motifs glob entre guillemets.
<fichier>
Emplacement du fichier d'enregistrement (.jfr)

Si le paramètre est omis, les métadonnées du JDK où se trouve l'outil 'jfr' seront utilisées.

Sous-commande jfr summary

NAME

jfr-openjdk21 - Flight Recorder command-line tool

SYNOPSIS

jfr subcommand [options] [arguments]

DESCRIPTION

The jfr command-line tool allows you to interact with Java Flight Recorder (JFR) files. It supports various subcommands for managing and analyzing JFR recordings.

jfr print subcommand

Use jfr print to dump the contents of a flight recording file to standard output in a human-readable format.

The syntax is:

jfr print [options] <file>

--events <filter>
Only print events matching the specified filter.
--categories <filter>
Only print events matching the specified category filter.
--threads <filter>
Only print events matching the specified thread filter.
--fields <field-list>
A comma-separated list of fields to print for each event.
<file>
Location of the flight recording file (.jfr).

The filter is a comma-separated list of names, simple and/or qualified, and/or quoted glob patterns.

jfr view subcommand

Use jfr view to display the contents of a flight recording file in a graphical user interface (GUI).

The syntax is:

jfr view <file>

<file>
Location of the flight recording file (.jfr).

This subcommand requires a graphical environment to run.

jfr configure subcommand

Use jfr configure to view and modify the configuration of a flight recording file.

The syntax is:

jfr configure <file>

<file>
Location of the flight recording file (.jfr).

jfr metadata subcommand

Use jfr metadata to dump the metadata from a flight recording file.

The syntax is:

jfr metadata <file>

<file>
Location of the flight recording file (.jfr).

jfr summary subcommand

Use jfr summary to print statistics for a recording. For example, a summary can illustrate the number of recorded events and how much disk space they used. This is useful for troubleshooting and understanding the impact of event settings.

The syntax is:

jfr summary <file>

<file>
Location of the flight recording file (.jfr)

jfr scrub subcommand

Use jfr scrub to remove sensitive contents from a file or to reduce its size.

The syntax is:

jfr scrub [--include-events <filter>] [--exclude-events <filter>] [--include-categories <filter>] [--exclude-categories <filter>] [--include-threads <filter>] [--exclude-threads <filter>] <input-file> [<output-file>]

--include-events <filter>
Select events matching an event name.
--exclude-events <filter>
Exclude events matching an event name.
--include-categories <filter>
Select events matching a category name.
--exclude-categories <filter>
Exclude events matching a category name.
--include-threads <filter>
Select events matching a thread name.
--exclude-threads <filter>
Exclude events matching a thread name.
<input-file>
The input file to read events from.
<output-file>
The output file to write filter events to. If no file is specified, it will be written to the same path as the input file, but with "-scrubbed" appended to the filename.

The filter is a comma-separated list of names, simple and/or qualified, and/or quoted glob patterns. If multiple filters are used, they are applied in the specified order.

jfr assemble subcommand

Use jfr assemble to assemble chunk files into a recording file.

The syntax is:

jfr assemble <repository> <file>

where:

<repository>
Directory where the repository containing chunk files is located.
<file>
Location of the flight recording file (.jfr).

Flight recording information is written in chunks. A chunk contains all of the information necessary for parsing. A chunk typically contains events useful for troubleshooting. If a JVM should crash, these chunks can be recovered and used to create a flight recording file using this jfr assemble command. These chunk files are concatenated in chronological order and chunk files that are not finished (.part) are excluded.

jfr disassemble subcommand

Use jfr disassemble to decompose a flight recording file into its chunk file pieces.

The syntax is:

jfr disassemble [--max-chunks <chunks>] [--output <directory>] <file>

where:

--output <directory>
The location to write the disassembled file, by default the current directory
--max-chunks <chunks>
Maximum number of chunks per file, by default 5. The chunk size varies, but is typically around 15 MB.
--max-size <size>
Maximum number of bytes per file.
<file>
Location of the flight recording file (.jfr)

This function can be useful for repairing a broken file by removing the faulty chunk. It can also be used to reduce the size of a file that is too large to transfer. The resulting chunk files are named myfile_1.jfr, myfile_2.jfr, etc. If needed, the resulting file names will be padded with zeros to preserve chronological order. For example, the chunk file name is myfile_001.jfr if the recording consists of more than 100 chunks.

jfr version and help subcommands

Use jfr --version or jfr version to view the version string information for this jfr command.

To get help on any of the jfr subcommands, use:

jfr <--help|help> [subcommand]

where:

[subcommand] is any of:

•
print
•
view
•
configure
•
metadata
•
summary
•
scrub
•
assemble
•
disassemble
