jsadebugd(1) Outils de dépannage jsadebugd(1)

NOM

jsadebugd - Se connecte à un processus Java ou à un fichier core et agit comme un serveur de débogage. Cette commande est expérimentale et non prise en charge.

SYNOPSIS

jsadebugd pid [ id-serveur ]
jsadebugd executable core [ id-serveur ]
pid
L'ID du processus auquel le serveur de débogage se connecte. Le processus doit être un processus Java. Pour obtenir une liste des processus Java en cours d'exécution sur une machine, utilisez la commande jps(1). Au plus une instance du serveur de débogage peut être attachée à un seul processus.
executable
L'exécutable Java à partir duquel le vidage mémoire (core dump) a été produit.
core
Le fichier core auquel le serveur de débogage doit se connecter.
id-serveur
Un identifiant unique optionnel nécessaire lorsque plusieurs serveurs de débogage sont démarrés sur la même machine. Cet identifiant doit être utilisé par les clients distants pour identifier le serveur de débogage spécifique auquel se connecter. Sur une seule machine, cet identifiant doit être unique.

DESCRIPTION

La commande jsadebugd se connecte à un processus Java ou à un fichier core et agit comme un serveur de débogage. Les clients distants tels que jstack, jmap et jinfo peuvent se connecter au serveur via Java Remote Method Invocation (RMI). Avant de lancer la commande jsadebugd, démarrez le registre RMI avec la commande rmiregistry comme suit, où $JAVA_HOME est le répertoire d'installation du JDK :

rmiregistry -J-Xbootclasspath/p:$JAVA_HOME/lib/sajdi.jar

Si le registre RMI n'a pas été démarré, la commande jsadebugd démarre un registre RMI sur un port standard (1099) en interne. Le serveur de débogage peut être arrêté en lui envoyant un signal SIGINT. Pour envoyer un SIGINT, appuyez sur Ctrl+C.

Remarque : cet utilitaire n'est pas pris en charge et peut ou non être disponible dans les futures versions du JDK. Sur les systèmes Windows où dbgeng.dll n'est pas présent, Debugging Tools For Windows doit être installé pour que ces outils fonctionnent. La variable d'environnement PATH doit contenir l'emplacement de jvm.dll utilisé par le processus cible ou l'emplacement à partir duquel le fichier de vidage de crash a été produit. Par exemple, set PATH=%JDK_HOME%\jre\bin\client;%PATH%.
