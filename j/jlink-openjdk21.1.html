JLINK(1) Commandes JDK JLINK(1)

NOM

jlink - assemble et optimise un ensemble de modules et leurs dépendances en une image d'exécution personnalisée

SYNTAXE

jlink [options] --module-path chemin_modules --add-modules module [, module...]

options
Options de la ligne de commande séparées par des espaces. Voir Options jlink.
chemin_modules
Le chemin où l'outil jlink découvre les modules observables. Ces modules peuvent être des fichiers JAR modulaires, des fichiers JMOD, ou des modules décompressés.
module
Les noms des modules à ajouter à l'image d'exécution. L'outil jlink ajoute ces modules et leurs dépendances transitives.

DESCRIPTION

L'outil jlink assemble un ensemble de modules, ainsi que leurs dépendances transitives, pour créer une image d'exécution personnalisée.

Remarque :

Les développeurs sont responsables de la mise à jour de leurs images d'exécution personnalisées.

OPTIONS JLINK

--add-modules mod [, mod...]
Ajoute les modules nommés, mod, à l'ensemble par défaut des modules racine. L'ensemble par défaut des modules racine est vide.
--bind-services
Lie les modules fournisseurs de services et leurs dépendances.
-c ={0|1|2} ou --compress={0|1|2}
Active la compression des ressources :
•
0 : Pas de compression
•
1 : Partage de chaînes de caractères constantes
•
2 : ZIP
--disable-plugin nom_plugin
Désactive le plugin spécifié. Voir Plugins jlink pour la liste des plugins pris en charge.
--endian {little|big}
Spécifie l'ordre des octets de l'image générée. La valeur par défaut est le format de l'architecture de votre système.
-h ou --help
Affiche le message d'aide.
--ignore-signing-information
Supprime une erreur fatale lorsque des JAR modulaires signés sont liés dans l'image d'exécution. Les fichiers liés à la signature des JAR modulaires signés ne sont pas copiés dans l'image d'exécution.
--launcher commande=module ou --launcher commande=module/main
Spécifie le nom de la commande de lancement pour le module ou le nom de la commande pour le module et la classe principale (les noms du module et de la classe principale sont séparés par une barre oblique (/)).
--limit-modules mod [, mod...]
Limite l'univers des modules observables à ceux dans la fermeture transitive des modules nommés, mod, plus le module principal, le cas échéant, plus tout autre module spécifié dans l'option --add-modules.
--list-plugins
Liste les plugins disponibles, auxquels vous pouvez accéder via les options de ligne de commande ; voir Plugins jlink.
-p ou --module-path chemin_modules
Spécifie le chemin des modules.

Si cette option n'est pas spécifiée, alors le chemin des modules par défaut est $JAVA_HOME/jmods. Ce répertoire contient le module java.base et les autres modules standard et JDK. Si cette option est spécifiée mais que le module java.base ne peut pas être résolu à partir de celui-ci, alors la commande jlink ajoute $JAVA_HOME/jmods au chemin des modules.

--no-header-files
Exclut les fichiers d'en-tête.
--no-man-pages
Exclut les pages de manuel.
--output chemin
Spécifie l'emplacement de l'image d'exécution générée.
--save-opts nom_fichier
Enregistre les options jlink dans le fichier spécifié.
--suggest-providers [nom, ...]
Suggère les fournisseurs qui implémentent les types de services donnés à partir du chemin des modules.
--version
Affiche les informations de version.
@nom_fichier
Lit les options à partir du fichier spécifié.

Un fichier d'options est un fichier texte contenant les options et les valeurs que vous entreriez normalement dans une invite de commande. Les options peuvent apparaître sur une ligne ou sur plusieurs lignes. Vous ne pouvez pas spécifier de variables d'environnement pour les noms de chemins. Vous pouvez commenter des lignes en préfixant un symbole dièse (#) au début de la ligne.

L'exemple suivant est un fichier d'options pour la commande jlink :


#Mer 07 déc 00:40:19 EST 2016
--module-path mlib
--add-modules com.greetings
--output greetingsapp

PLUGINS JLINK

Remarque :

Les plugins non listés dans cette section ne sont pas pris en charge et sont sujets à modification.

Pour les options de plugin qui nécessitent une liste_de_motifs, la valeur est une liste d'éléments séparés par des virgules, chaque élément utilisant l'une des formes suivantes :

•
motif_glob
•
glob:motif_glob
•
regex:motif_regex
•
@nom_fichier
•
nom_fichier est le nom d'un fichier contenant les motifs à utiliser, un motif par ligne.

Pour obtenir la liste complète de tous les plugins disponibles, exécutez la commande jlink --list-plugins.

Plugin compress

Options
--compress={0|1|2}[:filter=liste_de_motifs]
Description
Compresse toutes les ressources dans l'image de sortie.
•
Niveau 0 : Pas de compression
•
Niveau 1 : Partage de chaînes de caractères constantes
•
Niveau 2 : ZIP

Un filtre liste_de_motifs optionnel peut être spécifié pour lister le motif des fichiers à inclure.

Plugin include-locales

Options
--include-locales=étiquette_langue[,étiquette_langue]*
Description
Inclut la liste des locales où étiquette_langue est une étiquette de langue BCP 47. Cette option prend en charge la correspondance de locale telle que définie dans la RFC 4647. Assurez-vous d'ajouter le module jdk.localedata lorsque vous utilisez cette option.

Exemple :

--add-modules jdk.localedata --include-locales=en,ja,*-IN

Plugin order-resources

Options
--order-resources=liste_de_motifs
Description
Ordonne les chemins spécifiés par ordre de priorité. Si @nom_fichier est spécifié, alors chaque ligne de liste_de_motifs doit correspondre exactement aux chemins à ordonner.

Exemple :

--order-resources=/module-info.class,@classlist,/java.base/java/lang/

Plugin strip-debug

Options
--strip-debug
Description
Supprime les informations de débogage de l'image de sortie.

Plugin generate-cds-archive

Options
--generate-cds-archive
Description
Génère une archive CDS si l'image d'exécution prend en charge la fonctionnalité CDS.

EXEMPLES JLINK

La commande suivante crée une image d'exécution dans le répertoire greetingsapp. Cette commande lie le module com.greetings, dont la définition de module est contenue dans le répertoire mlib.


jlink --module-path mlib --add-modules com.greetings --output greeti
ngsapp

La commande suivante liste les modules dans l'image d'exécution greetingsapp

: 

greetingsapp/bin/java --list-modules
com.greetings
java.base@11
java.logging@11
org.astro@1.0

La commande suivante crée une image d'exécution dans le répertoire compressedrt, débarrassée des symboles de débogage, utilisant la compression pour réduire l'espace, et incluant les informations de localisation pour la langue française

: 

jlink --add-modules jdk.localedata --strip-debug --compress=2 --include-locales=fr --output compressedrt

L'exemple suivant compare la taille de l'image d'exécution compressedrt avec fr_rt, qui n'est pas débarrassée des symboles de débogage et n'utilise pas la compression

: 

jlink --add-modules jdk.localedata --include-locales=fr --output fr_rt
du -sh ./compressedrt ./fr_rt
23M     ./compressedrt
36M     ./fr_rt

L'exemple suivant liste les fournisseurs qui implémentent java.security.Provider

: 

jlink --suggest-providers java.security.Provider

  jdk.crypto.mscapi fournit java.security.Provider utilisé par java.base
  jdk.security.jgss fournit java.security.Provider utilisé par java.base

L'exemple suivant crée une image d'exécution personnalisée nommée mybuild qui n'inclut que java.naming et jdk.crypto.cryptoki ainsi que leurs dépendances, mais aucun autre fournisseur. Notez que ces dépendances doivent exister dans le chemin des modules

: 

jlink --add-modules java.naming,jdk.crypto.cryptoki --output mybuild

La commande suivante est similaire à celle qui crée une image d'exécution nommée greetingsapp, sauf qu'elle liera les modules résolus à partir des modules racine avec la liaison de service ; voir la Configuration.resolveAndBind méthode

jlink --module-path mlib --add-modules com.greetings --output greetingsapp --bind-services
