NOM

jdb - Trouve et corrige les bugs dans les programmes de la plateforme Java.

SYNTAXE

jdb [options] [nom_classe]  [arguments]
options
Options de ligne de commande. Voir Options.
nom_classe
Nom de la classe principale à déboguer.
arguments
Arguments passés à la méthode main() de la classe.

DESCRIPTION

Le débogueur Java (JDB) est un simple débogueur en ligne de commande pour les classes Java. La commande jdb et ses options appellent JDB. La commande jdb démontre l'architecture de débogage de la plateforme Java (JDBA) et fournit l'inspection et le débogage d'une machine virtuelle Java (JVM) locale ou distante. Voir Architecture de débogage de la plateforme Java (JDBA) sur http://docs.oracle.com/javase/8/docs/technotes/guides/jpda/index.html

DÉMARRAGE&#x00A0;D&#x0027;UNE&#x00A0;SESSION&#x00A0;JDB

Il existe plusieurs façons de démarrer une session JDB. La manière la plus fréquente est de faire lancer par JDB une nouvelle JVM avec la classe principale de l'application à déboguer. Faites-le en substituant la commande jdb à la commande java sur la ligne de commande. Par exemple, si la classe principale de votre application est MaClasse, utilisez la commande suivante pour la déboguer sous JDB :

jdb MaClasse

Lorsqu'elle est démarrée de cette manière, la commande jdb appelle une deuxième JVM avec les paramètres spécifiés, charge la classe spécifiée et arrête la JVM avant d'exécuter la première instruction de cette classe.

Une autre façon d'utiliser la commande jdb est de la rattacher à une JVM déjà en cours d'exécution. La syntaxe pour démarrer une JVM à laquelle la commande jdb se rattache lorsque la JVM est en cours d'exécution est la suivante. Ceci charge les bibliothèques de débogage en mémoire et spécifie le type de connexion à établir.

java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n MaClasse

Vous pouvez ensuite rattacher la commande jdb à la JVM avec la commande suivante :

jdb -attach 8000

L'argument MaClasse n'est pas spécifié dans la ligne de commande jdb dans ce cas car la commande jdb se connecte à une JVM existante au lieu d'en lancer une nouvelle.

Il existe de nombreuses autres façons de connecter le débogueur à une JVM, et toutes sont prises en charge par la commande jdb. L'architecture de débogage de la plateforme Java contient une documentation supplémentaire sur ces options de connexion.

COMMANDES&#x00A0;DE&#x00A0;BASE&#x00A0;JDB

Voici une liste des commandes de base de jdb. JDB prend en charge d'autres commandes que vous pouvez lister avec l'option -help.

help ou ?
Les commandes help ou ? affichent la liste des commandes reconnues avec une brève description.
run
Après avoir démarré JDB et défini des points d'arrêt, vous pouvez utiliser la commande run pour exécuter l'application déboguée. La commande run n'est disponible que lorsque la commande jdb démarre l'application déboguée par opposition à la connexion à une JVM existante.
cont
Continue l'exécution de l'application déboguée après un point d'arrêt, une exception ou une étape.
print
Affiche les objets Java et les valeurs primitives. Pour les variables ou les champs de types primitifs, la valeur réelle est affichée. Pour les objets, une brève description est affichée. Voir la commande dump pour savoir comment obtenir plus d'informations sur un objet.

Note: Pour afficher les variables locales, la classe contenant doit avoir été compilée avec l'option javac -g.

La commande print prend en charge de nombreuses expressions Java simples, y compris celles avec des appels de méthode, par exemple :

print MaClasse.monChampStatique
print monObj.monChampInstance
print i + j + k (i, j, k sont des primitifs et soit des champs soit des variables locales)
print monObj.maMethode() (si maMethode retourne une valeur non nulle)
print new java.lang.String("Bonjour").length()
dump
Pour les valeurs primitives, la commande dump est identique à la commande print. Pour les objets, la commande dump affiche la valeur actuelle de chaque champ défini dans l'objet. Les champs statiques et d'instance sont inclus. La commande dump prend en charge le même ensemble d'expressions que la commande print.
threads
Liste les threads actuellement en cours d'exécution. Pour chaque thread, son nom et son état actuel sont affichés ainsi qu'un index qui peut être utilisé dans d'autres commandes. Dans cet exemple, l'index du thread est 4, le thread est une instance de java.lang.Thread, le nom du thread est main, et il est actuellement en cours d'exécution. 
4. (java.lang.Thread)0x1 main      running
thread
Sélectionne un thread pour qu'il devienne le thread courant. De nombreuses commandes jdb sont basées sur le réglage du thread courant. Le thread est spécifié avec l'index du thread décrit dans la commande threads.
where
La commande where sans arguments affiche la pile du thread courant. La commande whereall affiche la pile de tous les threads du groupe de threads courant. La commande whereindex_thread affiche la pile du thread spécifié.

Si le thread courant est suspendu soit par un événement tel qu'un point d'arrêt, soit par la commande suspend, alors les variables locales et les champs peuvent être affichés avec les commandes print et dump. Les commandes up et down sélectionnent quelle frame de pile est la frame de pile courante.

POINTS&#x00A0;D&#x0027;ARRÊT

Les points d'arrêt peuvent être définis dans JDB aux numéros de ligne ou à la première instruction d'une méthode, par exemple :

•
La commande stop at MaClasse:22 définit un point d'arrêt à la première instruction de la ligne 22 du fichier source contenant MaClasse.
•
La commande stop in java.lang.String.length définit un point d'arrêt au début de la méthode java.lang.String.length.
•
La commande stop in MaClasse.<clinit> utilise <clinit> pour identifier le code d'initialisation statique de MaClasse.

Lorsqu'une méthode est surchargée, vous devez également spécifier ses types d'arguments afin que la méthode appropriée soit sélectionnée pour un point d'arrêt. Par exemple, MaClasse.maMethode(int,java.lang.String) ou MaClasse.maMethode().

La commande clear supprime les points d'arrêt en utilisant la syntaxe suivante : clear MaClasse:45. Utiliser la commande clear ou stop sans argument affiche une liste de tous les points d'arrêt actuellement définis. La commande cont continue l'exécution.

PAS&#x00A0;PAR&#x00A0;PAS

La commande step avance l'exécution à la ligne suivante, qu'elle soit dans la frame de pile courante ou dans une méthode appelée. La commande next avance l'exécution à la ligne suivante dans la frame de pile courante.

EXCEPTIONS

Lorsqu'une exception se produit pour laquelle il n'y a pas d'instruction catch n'importe où dans la pile d'appels du thread émetteur, la JVM imprime généralement une trace d'exception et se termine. Cependant, lorsque vous exécutez sous JDB, le contrôle retourne à JDB au niveau de l'exception fautive. Vous pouvez alors utiliser la commande jdb pour diagnostiquer la cause de l'exception.

Utilisez la commande catch pour faire en sorte que l'application déboguée s'arrête sur d'autres exceptions lancées, par exemple : catch java.io.FileNotFoundException ou catchmypackage.BigTroubleException. Toute exception qui est une instance de la classe spécifiée ou d'une sous-classe arrêtera l'application.
