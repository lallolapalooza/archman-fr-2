jstatd(1) Outils de surveillance jstatd(1)

NOM

jstatd - Surveille les machines virtuelles Java (JVM) et permet aux outils de surveillance distants de s'attacher aux JVM. Cette commande est expérimentale et non prise en charge.

SYNTAXE

jstatd [ options ]
options
Les options en ligne de commande. Voir Options.

DESCRIPTION

La commande jstatd est une application serveur RMI qui surveille la création et la terminaison des JVM HotSpot instrumentées et fournit une interface permettant aux outils de surveillance distants de s'attacher aux JVM s'exécutant sur l'hôte local.

Le serveur jstatd nécessite un registre RMI sur l'hôte local. Le serveur jstatd tente de s'attacher au registre RMI sur le port par défaut, ou sur le port que vous spécifiez avec l'option -pport. Si aucun registre RMI n'est trouvé, un nouveau registre est créé dans l'application jstatd, lié au port indiqué par l'option -pport ou au port par défaut du registre RMI lorsque l'option -pport est omise. Vous pouvez empêcher la création d'un registre RMI interne en spécifiant l'option -nr.

OPTIONS

-nr

N'essaie pas de créer un registre RMI interne dans le processus jstatd lorsqu'aucun registre RMI existant n'est trouvé.
-p port

Le numéro de port où le registre RMI est censé se trouver, ou lorsqu'il n'est pas trouvé, créé si l'option -nr n'est pas spécifiée.
-n rminame

Nom auquel l'objet RMI distant est lié dans le registre RMI. Le nom par défaut est JStatRemoteHost. Si plusieurs serveurs jstatd sont démarrés sur le même hôte, le nom de l'objet RMI exporté pour chaque serveur peut être rendu unique en spécifiant cette option. Cependant, cela nécessite que le nom de serveur unique soit inclus dans les chaînes hostid et vmid du client de surveillance.
-Joption

Transmet option à la JVM, où option est l'une des options décrites sur la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).

SÉCURITÉ

Le serveur jstatd ne peut surveiller que les JVM pour lesquelles il possède les autorisations d'accès natives appropriées. Par conséquent, le processus jstatd doit être exécuté avec les mêmes identifiants d'utilisateur que les JVM cibles. Certains identifiants d'utilisateur, tels que l'utilisateur root sur les systèmes UNIX, ont l'autorisation d'accéder à l'instrumentation exportée par n'importe quelle JVM du système. Un processus jstatd exécuté avec de tels identifiants peut surveiller n'importe quelle JVM du système, mais introduit des problèmes de sécurité supplémentaires.

Le serveur jstatd ne fournit aucune authentification des clients distants. Par conséquent, l'exécution d'un processus serveur jstatd expose l'instrumentation exportée par toutes les JVM pour lesquelles le processus jstatd a des autorisations d'accès à tout utilisateur sur le réseau. Cette exposition peut être indésirable dans votre environnement, et par conséquent, les politiques de sécurité locales doivent être prises en compte avant de démarrer le processus jstatd, en particulier dans les environnements de production ou sur des réseaux non sécurisés.

Le serveur jstatd installe une instance de RMISecurityPolicy lorsqu'aucun autre gestionnaire de sécurité n'est installé, et nécessite donc un fichier de politique de sécurité à spécifier. Le fichier de politique doit être conforme à l'implémentation de politique par défaut et à la syntaxe des fichiers de politique à l'adresse http://docs.oracle.com/javase/8/docs/technotes/guides/security/PolicyFiles.html

Le fichier de politique suivant permet au serveur jstatd de s'exécuter sans aucune exception de sécurité. Cette politique est moins libérale que d'accorder toutes les permissions à toutes les bases de code, mais plus libérale qu'une politique qui accorde les permissions minimales pour exécuter le serveur jstatd.

grant codebase "file:${java.home}/../lib/tools.jar" {   
    permission java.security.AllPermission;
};

Pour utiliser ce paramètre de politique, copiez le texte dans un fichier appelé jstatd.all.policy et exécutez le serveur jstatd comme suit :

jstatd -J-Djava.security.policy=jstatd.all.policy

Pour les sites ayant des pratiques de sécurité plus restrictives, il est possible d'utiliser un fichier de politique personnalisé pour limiter l'accès à des hôtes ou réseaux spécifiques de confiance, bien que de telles techniques soient soumises à des attaques par usurpation d'adresse IP. Si vos préoccupations de sécurité ne peuvent être résolues avec un fichier de politique personnalisé, alors la mesure la plus sûre est de ne pas exécuter le serveur jstatd et d'utiliser les outils jstat et jps localement.

INTERFACE&#x00A0;DISTANTE

L'interface exportée par le processus jstatd est propriétaire et susceptible de changer. Il est déconseillé aux utilisateurs et développeurs d'écrire pour cette interface.

EXEMPLES

Voici des exemples de la commande jstatd. Les scripts jstatd démarrent automatiquement le serveur en arrière-plan.

REGISTRE&#x00A0;RMI&#x00A0;INTERNE

Cet exemple montre comment démarrer une session jstatd avec un registre RMI interne. Cet exemple suppose qu'aucun autre serveur n'est lié au port du registre RMI par défaut (port 1099).

jstatd -J-Djava.security.policy=all.policy

REGISTRE&#x00A0;RMI&#x00A0;EXTERNE

Cet exemple démarre une session jstatd avec un registre RMI externe.

rmiregistry&
jstatd -J-Djava.security.policy=all.policy

Cet exemple démarre une session jstatd avec un serveur de registre RMI externe sur le port 2020.

jrmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020

Cet exemple démarre une session jstatd avec un registre RMI externe sur le port 2020 lié à AlternateJstatdServerName.

rmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020
    -n AlternateJstatdServerName

ARRÊTER&#x00A0;LA&#x00A0;CRÉATION&#x00A0;D&#x0027;UN&#x00A0;REGISTRE&#x00A0;RMI&#x00A0;INTRAPROCESSUS

Cet exemple démarre une session jstatd qui ne crée pas de registre RMI lorsqu'un registre n'est pas trouvé. Cet exemple suppose qu'un registre RMI est déjà en cours d'exécution. Si aucun registre RMI n'est en cours d'exécution, un message d'erreur s'affiche.

jstatd -J-Djava.security.policy=all.policy -nr

ACTIVER&#x00A0;LA&#x00A0;JOURNALISATION&#x00A0;RMI

Cet exemple démarre une session jstatd avec les capacités de journalisation RMI activées. Cette technique est utile comme aide au dépannage ou pour surveiller les activités du serveur.

jstatd -J-Djava.security.policy=all.policy
    -J-Djava.rmi.server.logCalls=true
