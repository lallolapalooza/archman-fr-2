jj-rebase(1) Manuel des commandes générales jj-rebase(1)

NOM

jj-rebase - Déplacer des révisions vers un(des) autre(s) parent(s)

SYNTAXE

jj rebase [-b|--branch] [-s|--source] [-r|--revisions] [-o|--onto] [-A|--insert-after] [-B|--insert-before] [--skip-emptied] [--keep-divergent] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPTION

Déplacer des révisions vers un(des) autre(s) parent(s)

Cette commande déplace des révisions vers un(des) autre(s) parent(s) tout en préservant les changements (diff) dans les révisions.

Il existe trois façons différentes de spécifier les révisions à rebaser :

* `--source/-s` pour rebaser une révision et ses descendants * `--branch/-b` pour rebaser une branche entière, par rapport à la destination * `--revisions/-r` pour rebaser les révisions spécifiées sans leurs
descendants

Si aucune option n'est spécifiée, la valeur par défaut est `-b @`.

Il existe trois façons différentes de spécifier où les révisions doivent être rebasées :

* `--onto/-o` pour rebaser les révisions sur les cibles spécifiées * `--insert-after/-A` pour rebaser les révisions sur les cibles spécifiées et
pour rebaser les descendants des cibles sur les révisions rebasées * `--insert-before/-B` pour rebaser les révisions sur les parents des cibles
spécifiées et pour rebaser les cibles et leurs descendants sur les révisions
rebasées

Voir les sections ci-dessous pour plus de détails sur les différentes façons de spécifier les révisions à rebaser et où.

Si une révision du working-copy est abandonnée, une nouvelle révision vide lui sera donnée. Ceci est vrai en général ; ce n'est pas spécifique à cette commande.

### Spécifier quelles révisions rebaser

Avec `--source/-s`, la commande rebase la révision spécifiée et ses descendants vers la destination. Par exemple, `jj rebase -s M -o O` transformerait votre historique comme suit (les lettres suivies d'une apostrophe sont les versions post-rebase) :

```text O N' | | | N M' | | | | M O | | => | | | L | L | |/ | | | K | K |/ |/ J J ```

Chaque révision passée à `-s` deviendra un enfant direct de la destination, donc si vous exécutez plutôt `jj rebase -s M -s N -o O` (ou `jj rebase -s 'M|N' -o O`) dans l'exemple ci-dessus, alors N' serait plutôt un enfant direct de O.

Avec `--branch/-b`, la commande rebase la totalité de la "branche" contenant la révision spécifiée. Une "branche" est l'ensemble des révisions qui inclut :

* la révision spécifiée et ses ancêtres qui ne sont pas aussi des ancêtres de la
destination * tous les descendants de ces révisions

En d'autres termes, `jj rebase -b X -o Y` rebase les révisions dans le revset `(Y..X)::` (ce qui est équivalent à `jj rebase -s 'roots(Y..X)' -o Y` pour une seule racine). Par exemple, `jj rebase -b L -o O` ou `jj rebase -b M -o O` transformerait votre historique comme suit (car `L` et `M` sont sur la même "branche", par rapport à la destination) :

```text O N' | | | N M' | | | | M | L' | | => |/ | | L K' | |/ | | K O |/ | J J ```

Avec `--revisions/-r`, la commande rebase uniquement les révisions spécifiées vers la destination. Tout "trou" laissé sera comblé en rebasant les descendants sur le(s) parent(s) des révisions spécifiées. Par exemple, `jj rebase -r K -o M` transformerait votre historique comme suit :

```text M K' | | | L M | | => | | K | L' |/ |/ J J ```

Plusieurs révisions peuvent être spécifiées, et les dépendances (arêtes du graphe) au sein de l'ensemble seront préservées. Par exemple, `jj rebase -r 'K|N' -o O` transformerait votre historique comme suit :

```text O N' | | | N K' | | | | M O | | => | | | L | M' | |/ |/ | K | L' |/ |/ J J ```

`jj rebase -s X` est similaire à `jj rebase -r X::` et se comportera de la même manière si X est une révision unique. Cependant, si X est un ensemble de plusieurs révisions, ou si vous avez passé plusieurs arguments `-s`, alors `jj rebase -s` fera de chacune des révisions spécifiées un enfant immédiat de la destination, tandis que `jj rebase -r` préservera les dépendances au sein de l'ensemble.

Notez que vous pouvez créer une révision de fusion en répétant l'argument `-o`. Par exemple, si vous réalisez que la révision L dépend en fait de la révision M pour fonctionner (en plus de son parent actuel K), vous pouvez exécuter `jj rebase -s L -o K -o M` :

```text M L' | |\ | L M | | | => | | | K | K |/ |/ J J ```

### Spécifier où rebaser les révisions

Avec `--onto/-o`, la commande rebase les révisions sélectionnées sur les cibles. Les descendants existants des cibles ne seront pas affectés. Voir la section ci-dessus pour des exemples.

Avec `--insert-after/-A`, les révisions sélectionnées seront insérées après les cibles. Ceci est similaire à `-o`, mais si les cibles ont des descendants existants, ceux-ci seront rebasés sur les révisions sélectionnées rebasées.

Par exemple, `jj rebase -r K -A L` réécrira l'historique comme suit : ```text N N' | | | M | M' |/ |/ L => K' | | | K L |/ | J J ```

L'argument `-A` (et `-B`) peut également être utilisé pour réorganiser les révisions. Par exemple, `jj rebase -r M -A J` réécrira l'historique comme suit : ```text M L' | | L K' | => | K M' | | J J ```

Avec `--insert-before/-B`, les révisions sélectionnées seront insérées avant les cibles. Ceci est réalisé en rebasant les révisions sélectionnées sur les parents des révisions cibles, puis en rebasant les révisions cibles et leurs descendants sur les révisions rebasées.

Par exemple, `jj rebase -r K -B L` réécrira l'historique comme suit : ```text N N' | | | M | M' |/ |/ L => L' | | | K K' |/ | J J ```

Les arguments `-A` et `-B` peuvent également être combinés, ce qui peut être utile autour des fusions. Par exemple, vous pouvez utiliser `jj rebase -r K -A J -B M` pour créer une nouvelle fusion (mais `jj rebase -r M -o L -o K` pourrait être plus simple dans ce cas particulier) : ```text M M' | |\ L L | | => | | | K | K' |/ |/ J J ```

Pour insérer un commit dans une fusion existante avec `jj rebase -r O -A K -B M` : ```text O N' | |\ N | M' |\ | |\ | M | O'| | | => |/ / | L | L | | | | K | K | |/ |/ J J ```

OPTIONS

-b, --branch <REVSETS>
Rebaser toute la branche par rapport aux ancêtres de la destination (peut être répété)

`jj rebase -b=br -o=dst` équivaut à `jj rebase '-s=roots(dst..br)' -o=dst`.

Si aucun des arguments `-b`, `-s` ou `-r` n'est fourni, la valeur par défaut est `-b @`.

-s, --source <REVSETS>
Rebaser la ou les révisions spécifiées avec leur arborescence de descendants (peut être répété)

Chaque révision spécifiée deviendra un enfant direct de la ou des révisions de destination, même si certaines des révisions sources sont des descendants des autres.

Si aucun des arguments `-b`, `-s` ou `-r` n'est fourni, la valeur par défaut est `-b @`.

-r, --revisions <REVSETS>
Rebaser les révisions données, en rebasant les descendants sur le(s) parent(s) de cette révision

Contrairement à `-s` ou `-b`, vous pouvez `jj rebase -r` une révision `A` sur un descendant de `A`.

Si aucun des arguments `-b`, `-s` ou `-r` n'est fourni, la valeur par défaut est `-b @`.

-o, --onto <REVSETS>
La ou les révisions sur lesquelles rebaser (peut être répété pour créer une fusion)
-A, --insert-after <REVSETS>
La ou les révisions à insérer après (peut être répété pour créer une fusion)
-B, --insert-before <REVSETS>
La ou les révisions à insérer avant (peut être répété pour créer une fusion)
--skip-emptied
Si vrai, lorsqu'un rebasage produirait un commit vide, le commit est abandonné. Il ne sera pas abandonné s'il était déjà vide avant le rebasage. Ne sautera jamais les commits de fusion avec plusieurs parents non vides

Conserver les commits divergents lors du rebasage
