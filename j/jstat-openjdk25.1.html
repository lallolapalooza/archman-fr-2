JSTAT(1) Commandes JDK JSTAT(1)

NOM

jstat - surveiller les statistiques JVM

SYNTAXE

Note : Cette commande est expérimentale et non prise en charge.

jstat optionsGénérales

jstat optionsSortie [-t] [-h lignes] vmid [intervalle [compteur]]

optionsGénérales
Une seule option en ligne de commande. Voir OPTIONS GÉNÉRALES.
optionsSortie
Une option rapportée par l'option -options. Une ou plusieurs options de sortie constituées d'un seul statOption, plus les options -t, -h, et -J. Voir OPTIONS DE SORTIE POUR LA COMMANDE jstat.
-t
Affiche une colonne d'horodatage comme première colonne de sortie. L'horodatage est le temps écoulé depuis le démarrage de la JVM cible.
-h n
Affiche un en-tête de colonne tous les n échantillons (lignes de sortie), où n est un entier positif. La valeur par défaut est 0, ce qui affiche l'en-tête de colonne de la première ligne de données.
vmid
Un identifiant de machine virtuelle, qui est une chaîne indiquant la JVM cible. Voir IDENTIFIANT DE MACHINE VIRTUELLE.
intervalle
L'intervalle d'échantillonnage dans les unités spécifiées, secondes (s) ou millisecondes (ms). L'unité par défaut est les millisecondes. Doit être un entier positif. Lorsque spécifié, la commande jstat produit sa sortie à chaque intervalle.
compteur
Le nombre d'échantillons à afficher. La valeur par défaut est l'infini, ce qui amène la commande jstat à afficher les statistiques jusqu'à ce que la JVM cible se termine ou que la commande jstat soit terminée. Cette valeur doit être un entier positif.

DESCRIPTION

La commande jstat affiche des statistiques de performance pour une JVM Java HotSpot instrumentée. La JVM cible est identifiée par son identifiant de machine virtuelle, ou option vmid.

La commande jstat prend en charge deux types d'options, les options générales et les options de sortie. Les options générales amènent la commande jstat à afficher des informations simples d'utilisation et de version. Les options de sortie déterminent le contenu et le format de la sortie statistique.

Toutes les options et leurs fonctionnalités sont sujettes à modification ou suppression dans les futures versions.

OPTIONS GÉNÉRALES

Si vous spécifiez une des options générales, vous ne pouvez spécifier aucune autre option ou paramètre.

-help
Affiche un message d'aide.
-options
Affiche une liste des options statistiques. Voir OPTIONS DE SORTIE POUR LA COMMANDE jstat.

OPTIONS DE SORTIE POUR LA COMMANDE JSTAT

Si vous ne spécifiez pas d'option générale, vous pouvez spécifier des options de sortie. Les options de sortie déterminent le contenu et le format de la sortie de la commande jstat, et se composent d'un seul statOption, plus les autres options de sortie ( -h, -t, et -J). Le statOption doit venir en premier.

La sortie est formatée sous forme de tableau, avec des colonnes séparées par des espaces. Une ligne d'en-tête avec des titres décrit les colonnes. Utilisez l'option -h pour définir la fréquence d'affichage de l'en-tête. Les noms des en-têtes de colonnes sont cohérents entre les différentes options. En général, si deux options fournissent une colonne portant le même nom, la source de données pour les deux colonnes est la même.

Utilisez l'option -t pour afficher une colonne d'horodatage, nommée Timestamp, comme première colonne de sortie. La colonne Timestamp contient le temps écoulé, en secondes, depuis le démarrage de la JVM cible. La résolution de l'horodatage dépend de divers facteurs et est sujette à variation en raison du délai de planification des threads sur les systèmes fortement chargés.

Utilisez les paramètres intervalle et compteur pour déterminer la fréquence et le nombre de fois, respectivement, que la commande jstat affiche sa sortie.

Note :

Ne créez pas de scripts pour analyser la sortie de la commande jstat car le format pourrait changer dans les futures versions. Si vous créez des scripts qui analysent la sortie de la commande jstat, attendez-vous à devoir les modifier pour les futures versions de cet outil.

-statOption
Détermine les informations statistiques que la commande jstat affiche. La liste suivante contient les options disponibles. Utilisez l'option générale -options pour afficher la liste des options pour une installation de plateforme particulière. Voir OPTIONS STATISTIQUES ET SORTIE.

compiler : Affiche des statistiques sur le comportement du compilateur Just-in-Time de la JVM Java HotSpot.

gc : Affiche des statistiques sur le comportement du tas collecté par le garbage collector.

gccapacity : Affiche des statistiques sur les capacités des générations et leurs espaces correspondants.

gccause : Affiche un résumé des statistiques de garbage collection (identique à -gcutil), avec la cause des derniers événements de garbage collection et des événements actuels (le cas échéant).

gcnew : Affiche des statistiques sur le comportement de la génération nouvelle.

gcnewcapacity : Affiche des statistiques sur les tailles des générations nouvelles et leurs espaces correspondants.

gcold : Affiche des statistiques sur le comportement de la génération ancienne et des statistiques sur l'espace des métadonnées.

gcoldcapacity : Affiche des statistiques sur les tailles de la génération ancienne.

-JoptionJava
Transmet optionJava au lanceur d'application Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Pour une liste complète des options, voir java.

NAME

jstat - Java Virtual Machine statistics monitoring tool

SYNOPSIS

jstat [ -options ] [ -flags ] [ vmid [ interval [ count ]]]

DESCRIPTION

The jstat command collects and displays performance statistics from a Java Virtual Machine (JVM) running on a local or remote host. The command can provide information about garbage collection, class loading, JIT compilation, and performance counters.

The jstat command can be used to monitor applications that are running in the following environments:

  • Local Java Virtual Machine
  • Remote Java Virtual Machine

The statistics displayed by the jstat command are provided by the JVM's instrumentation and monitoring features.

GENERAL OPTIONS

vmid
The virtual machine identifier for the target JVM. This identifier can be an integer (process ID) or a URI. See the VIRTUAL MACHINE IDENTIFIER section for more details.
interval
The sampling interval in milliseconds. If omitted, only one sample is taken.
count
The number of samples to take. If omitted, samples are taken indefinitely until the command is interrupted.

OUTPUT OPTIONS FOR THE JSTAT COMMAND

The following options control the type of output generated by the jstat command.

-options
A string that specifies the type of statistics to be displayed. The string can be a single option or a comma-separated list of options. The following options are available:

See the STAT OPTIONS AND OUTPUT section for a detailed description of each available option.

-flags
Prints the given JVM flags to standard output.

STAT OPTIONS AND OUTPUT

The following options specify the type of statistics to be collected and displayed. The output for each option is a set of column headers and a line of data that corresponds to the headers. The header names are abbreviated.

The column headers are as follows:

  • S0C: Survivor space 0 capacity
  • S1C: Survivor space 1 capacity
  • S0U: Survivor space 0 utilization
  • S1U: Survivor space 1 utilization
  • EC: Eden space capacity
  • EU: Eden space utilization
  • OC: Old space capacity
  • OU: Old space utilization
  • MC: Metaspace capacity
  • MU: Metaspace utilization
  • CCSC: Compressed class space capacity
  • CCSU: Compressed class space utilization
  • YGC: Number of young generation garbage collections
  • YGCT: Young generation garbage collection time
  • FGC: Number of full garbage collections
  • FGCT: Full garbage collection time
  • GCT: Total garbage collection time

The following stat options are available:

-gc
Heap statistics. Displays heap statistics, including capacity, utilization, and garbage collection counts and times.
-gccapacity
Heap capacity statistics. Displays heap capacity, including minimum, maximum, and current capacities.
-gcnew
Young generation statistics. Displays statistics for the young generation, including survivor space and Eden space capacity and utilization.
-gcnewcapacity
Young generation capacity statistics. Displays young generation capacity, including minimum, maximum, and current capacities.
-gcold
Old generation statistics. Displays statistics for the old generation, including capacity and utilization.
-gcoldcapacity
Old generation capacity statistics. Displays old generation capacity, including minimum, maximum, and current capacities.
-compiler
JIT compiler statistics. Displays statistics about the Just-In-Time (JIT) compiler, including the number of methods compiled and compilation time.
-ClassLoading
Class loading statistics. Displays statistics about class loading, including the number of classes loaded and unloaded.
-gcutil
Heap usage statistics. Displays heap usage percentages for survivor spaces, Eden space, and old space, along with garbage collection counts and times.
-printcompilation
Prints class loading and method compilation messages. This option is equivalent to the HotSpot -XX:+PrintCompilation option. The output includes the name of the class and the method within the specified class. The format for these two fields is consistent with the HotSpot -XX:+PrintCompilation option.

VIRTUAL MACHINE IDENTIFIER

The syntax of the vmid string corresponds to the syntax of a URI:

[protocol:][//]lvmid[@hostname[:port][/servername]

The syntax of the vmid string corresponds to the syntax of a URI. The vmid string can vary from a simple integer that represents a local JVM to a more complex construction that specifies a communications protocol, port number, and other implementation-specific values.

protocol
The communications protocol. If the protocol value is omitted and a host name isn't specified, then the default protocol is a platform-specific optimized local protocol. If the protocol value is omitted and a host name is specified, then the default protocol is rmi.
lvmid
The local virtual machine identifier for the target JVM. The lvmid is a platform-specific value that uniquely identifies a JVM on a system. The lvmid is the only required component of a virtual machine identifier. The lvmid is typically, but not necessarily, the operating system's process identifier for the target JVM process. You can use the jps command to determine the lvmid provided the JVM processes is not running in a separate docker instance. You can also determine the lvmid on Linux and macOS platforms with the ps command, and on Windows with the Windows Task Manager.
hostname
A host name or IP address that indicates the target host. If the hostname value is omitted, then the target host is the local host.
port
The default port for communicating with the remote server. If the hostname value is omitted or the protocol value specifies an optimized, local protocol, then the port value is ignored. Otherwise, treatment of the port parameter is implementation-specific. For the default rmi protocol, the port value indicates the port number for the rmiregistry on the remote host. If the port value is omitted and the protocol value indicates rmi, then the default rmiregistry port (1099) is used.
servername
The treatment of the servername parameter depends on implementation. For the optimized local protocol, this field is ignored. For the rmi protocol, it represents the name of the RMI remote object on the remote host.

EXAMPLES

This section presents some examples of monitoring a local JVM with an lvmid of 21891.

THE GCUTIL OPTION

This example attaches to lvmid 21891 and takes 7 samples at 250 millisecond intervals and displays the output as specified by the -gcutil option.

The output of this example shows that a young generation collection occurred between the third and fourth sample. The collection took 0.078 seconds and promoted objects from the eden space (E) to the old space (O), resulting in an increase of old space utilization from 66.80% to 68.19%. Before the collection, the survivor space was 97.02% utilized, but after this collection it's 91.03% utilized.

REPEAT THE COLUMN HEADER STRING

This example attaches to lvmid 21891 and takes samples at 250 millisecond intervals and displays the output as specified by -gcnew option. In addition, it uses the -h3 option to output the column header after every 3 lines of data.

In addition to showing the repeating header string, this example shows that between the second and third samples, a young GC occurred. Its duration was 0.001 seconds. The collection found enough active data that the survivor space 0 utilization (S0U) would have exceeded the desired survivor size (DSS). As a result, objects were promoted to the old generation (not visible in this output), and the tenuring threshold (TT) was lowered from 31 to 2.

Another collection occurs between the fifth and sixth samples. This collection found very few survivors and returned the tenuring threshold to 31.

INCLUDE A TIME STAMP FOR EACH SAMPLE

This example attaches to lvmid 21891 and takes 3 samples at 250 millisecond intervals. The -t option is used to generate a time stamp for each sample in the first column.

The Timestamp column reports the elapsed time in seconds since the start of the target JVM. In addition, the -gcoldcapacity output shows the old generation capacity (OGC) and the old space capacity (OC) increasing as the heap expands to meet allocation or promotion demands. The old generation capacity (OGC) has grown from 11,696 KB to 13,820 KB after the eighty-first full garbage collection (FGC). The maximum capacity of the generation (and space) is 60,544 KB (OGCMX), so it still has room to expand.

MONITOR INSTRUMENTATION FOR A REMOTE JVM

This example attaches to lvmid 40496 on the system named remote.domain using the -gcutil option, with samples taken every second indefinitely.

The lvmid is combined with the name of the remote host to construct a vmid of 40496@remote.domain. This vmid results in the use of the rmi protocol to communicate to the default jstatd server on the remote host. The jstatd server is located using the rmiregistry command on remote.domain that's bound to the default port of the rmiregistry command (port 1099).

NAME

jstat — Java Virtual Machine Statistics Monitoring Tool

SYNOPSIS

jstat [general options] [options] [pid [interval]]

DESCRIPTION

The jstat utility collects and displays performance statistics for Java virtual machines (JVMs). It can be used to monitor garbage collection, class loading, JIT compilation, and other aspects of JVM performance.

The jstat command can monitor a local JVM or a remote JVM. To monitor a remote JVM, the remote JVM must be running with the appropriate management agent enabled, and the jstat command must be able to connect to it.

OPTIONS

General options:

-version
Prints version information and exits.
-help
Prints help message and exits.

Options for monitoring specific aspects of the JVM:

-class
Displays class loader statistics.
-compiler
Displays JIT compiler statistics.
-gc
Displays garbage collection statistics.
-gccapacity
Displays garbage collection capacity statistics.
-gcutil
Displays garbage collection utilization statistics.
-heap
Displays heap memory statistics.
-printcompilation
Displays compilation information.

OUTPUT

The output of jstat varies depending on the options used. However, it generally includes the following information:

  • S0C: Survivor space 0 capacity (KB)
  • S1C: Survivor space 1 capacity (KB)
  • S0U: Survivor space 0 utilization (%)
  • S1U: Survivor space 1 utilization (%)
  • EC: Eden space capacity (KB)
  • EU: Eden space utilization (%)
  • OC: Old space capacity (KB)
  • OU: Old space utilization (%)
  • MC: Metaspace capacity (KB)
  • MU: Metaspace utilization (%)
  • CCSC: Compressed class space capacity (KB)
  • CCSU: Compressed class space utilization (%)
  • YGC: Number of Young Generation garbage collections
  • YGCT: Young Generation garbage collection time
  • FGC: Number of Full garbage collections
  • FGCT: Full garbage collection time
  • GCT: Garbage collection time
  • LN: Number of loaded classes
  • UN: Number of unloaded classes
  • TIME: Time spent compiling methods
  • FAILED: Number of compilation failures

EXAMPLES

Monitor garbage collection statistics for a local JVM with process ID 12345 every 5 seconds:

jstat -gc 12345 5s

Monitor class loader statistics for a remote JVM:

jstat -class user@remotehost:12345
