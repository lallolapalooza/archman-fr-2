NOM

journal-remote.conf, journal-remote.conf.d - Fichiers de configuration pour le service acceptant les téléchargements de journaux distants

SYNTAXE

/etc/systemd/journal-remote.conf
/run/systemd/journal-remote.conf
/usr/local/lib/systemd/journal-remote.conf
/usr/lib/systemd/journal-remote.conf
/etc/systemd/journal-remote.conf.d/*.conf
/run/systemd/journal-remote.conf.d/*.conf
/usr/local/lib/systemd/journal-remote.conf.d/*.conf
/usr/lib/systemd/journal-remote.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent divers paramètres de systemd-journal-remote.service(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsque les valeurs par défaut doivent être modifiées. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des remplacements locaux peuvent également être créés en créant des drop-ins, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cet effet (ou une copie dans /etc/ s'il est livré sous /usr/), cependant l'utilisation de drop-ins pour la configuration locale est recommandée par rapport aux modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration drop-in sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces drop-ins ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée du fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure de leur apparition dans les fichiers triés.

Lorsque des paquets ont besoin de personnaliser la configuration, ils peuvent installer des drop-ins sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les drop-ins doivent être utilisés pour remplacer les drop-ins de paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités de drop-ins pour permettre aux fournisseurs d'OS de livrer des drop-ins dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les drop-ins de paquets remplacent accidentellement les drop-ins définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les drop-ins dans /usr/ et la plage 60-90 pour les drop-ins dans /etc/ et /run/, pour s'assurer que les drop-ins locaux et transitoires ont la priorité sur les drop-ins livrés par le fournisseur de l'OS.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Toutes les options sont configurées dans la section [Remote] :

Seal=

Signe périodiquement les données dans le journal en utilisant le scellement à sécurité avancée (Forward Secure Sealing).

Ajouté dans la version 229.

SplitMode=

Soit "host" soit "none".

Ajouté dans la version 220.

ServerKeyFile=

Clé SSL au format PEM.

Ajouté dans la version 220.

ServerCertificateFile=

Certificat SSL au format PEM.

Ajouté dans la version 220.

TrustedCertificateFile=

Certificat d'autorité de certification SSL.

Ajouté dans la version 220.

MaxUse=, KeepFree=, MaxFileSize=, MaxFiles=

Ces options sont analogues à SystemMaxUse=, SystemKeepFree=, SystemMaxFileSize= et SystemMaxFiles= dans journald.conf(5).

MaxUse= contrôle la quantité d'espace disque que systemd-journal-remote peut utiliser au maximum. KeepFree= contrôle la quantité d'espace disque que systemd-journal-remote doit laisser libre pour d'autres usages. systemd-journal-remote respectera les deux limites et utilisera la plus petite des deux valeurs.

MaxFiles= contrôle le nombre maximum de fichiers journaux individuels à conserver. Notez que seuls les fichiers archivés sont supprimés pour réduire le nombre de fichiers jusqu'à atteindre cette limite ; les fichiers actifs resteront. Cela signifie qu'en réalité, il pourrait encore y avoir plus de fichiers journaux au total que cette limite après la fin d'une opération de nettoyage.

Ajouté dans la version 253.

Compression=

Configure les algorithmes de compression acceptables à annoncer via l'en-tête HTTP "Accept-Encoding". Cet en-tête suggère à systemd-journal-upload de compresser les données à envoyer. Prend une liste d'algorithmes de compression séparés par des espaces, ou "no". Les algorithmes pris en charge sont "zstd", "xz", ou "lz4". Lorsqu'une liste d'algorithmes est spécifiée, l'en-tête "Accept-Encoding" sera construit avec des priorités basées sur l'ordre des algorithmes dans la liste. Lorsque "no" est spécifié, l'en-tête "Accept-Encoding" ne sera pas envoyé. Cette option peut être spécifiée plusieurs fois. Si une chaîne vide est attribuée, alors toutes les affectations précédentes sont effacées. Par défaut, non défini et tous les algorithmes de compression pris en charge seront listés dans l'en-tête.

Exemple :

Compression=zstd lz4

Ajouté dans la version 258.

NAME

journal-remote.conf — Configuration file for systemd-journal-remote

SYNOPSIS

/etc/systemd/journal-remote.conf

/usr/lib/systemd/journal-remote.conf

DESCRIPTION

The systemd-journal-remote daemon listens for journal messages sent over the network and forwards them to the local journal. This daemon is useful for centralizing logs from multiple machines to a single host.

The configuration file controls the behavior of systemd-journal-remote. It is formatted as a space, tab, and newline-separated text file. Blank lines and lines starting with ‘#’ or ‘;’ are ignored. The file is parsed in sections, enclosed in square brackets. The following sections are supported:

OPTIONS

The following options are available in the main section:

ListenStream, ListenDatagram, ListenFIFO, ListenSocket

Specifies the network addresses or file paths on which the service should listen for incoming journal messages. Multiple options may be specified. If no addresses are specified, the service will listen on all available network interfaces on the default ports (9000 for UDP, 9001 for TCP). See systemd.socket(5) for a list of valid address formats.

Seal=

Controls how journal files are sealed. The default is 0.storage, which seals journal files after 30 days and sets their permissions to read-only. runtime seals journals after 30 days. }^\s*0\.\d+$ seals journals after the specified number of days, where \d+ is a decimal number. }^\s*0$ disables sealing.

SplitMode=

Controls how journal files are split. The default is archiving, which means that journal files are archived with a timestamp. nonarchiving means that journal files are not archived.

MaxFileSec=

Specifies the maximum time for which journal files are kept. The default is 0, which means that journal files are kept indefinitely. A time value may be specified in days, hours, minutes, or seconds. For example, 1d, 12h, or 1h30min.

Compress=

Controls whether journal messages are compressed. The default is yes. Set to no to disable compression.

ServerKeyFile=, ServerCertificateFile=, CAFile=

Specifies the TLS certificate and key files to use for secure communication. These options are only relevant if TLS is enabled.

TrustedProxy=

Specifies a list of trusted IP addresses or hostnames of proxies that may forward journal messages. Messages from untrusted proxies will be ignored.

EXAMPLES

Listen on all interfaces on port 9001 (TCP):

ListenStream=9001

Listen on a specific IP address and port:

ListenStream=192.168.1.1:9001

Listen on a FIFO:

ListenFIFO=/run/journal-remote.fifo

Seal journal files after 7 days:

Seal=0.7d

Do not compress journal messages:

Compress=no
