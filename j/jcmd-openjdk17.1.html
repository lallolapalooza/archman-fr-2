DESCRIPTIO

N

L'utilitaire jcmd sert à envoyer des requêtes de commande de diagnostic à la JVM. Il doit être utilisé sur la même machine que celle où la JVM s'exécute et doit avoir les mêmes identifiants d'utilisateur et de groupe effectifs que ceux utilisés pour lancer la JVM. Chaque commande de diagnostic possède son propre ensemble d'arguments. Pour afficher la description, la syntaxe et la liste des arguments disponibles d'une commande de diagnostic, utilisez le nom de la commande comme argument. Par exemple

:

jcmd pid help comman

d
e

Si les arguments contiennent des espaces, vous devez les entourer de guillemets simples ou doubles (' ou "). De plus, vous devez échapper les guillemets simples ou doubles avec une barre oblique inverse (\) pour empêcher le shell du système d'exploitation de traiter les guillemets. Alternativement, vous pouvez entourer ces arguments de guillemets simples puis de guillemets doubles (ou de guillemets doubles puis de guillemets simples)

.

Si vous spécifiez l'identifiant de processus (pid) ou la classe principale (classe-principale) comme premier argument, alors l'utilitaire jcmd envoie la requête de commande de diagnostic au processus Java ayant l'identifiant spécifié ou à tous les processus Java dont le nom de la classe principale correspond à celui spécifié. Vous pouvez également envoyer la requête de commande de diagnostic à tous les processus Java disponibles en spécifiant 0 comme identifi

ant de pr
ocessus.

JFR.configure [options]
Définit les paramètres d'un enregistrement de vol

options :

•
globalbuffercount : (Facultatif) Nombre de buffers globaux. Cette option est une option héritée : modifiez le paramètre memorysize pour modifier le nombre de buffers globaux. •
globalbuffersize : (Facultatif) Taille des buffers globaux, en octets. Cette option est une option héritée : modifiez le paramètre memorysize pour modifier la taille des buffers globaux. memorysize : (Facultatif) Taille globale de la mémoire, en octets si aucun des suffixes suivants n'est utilisé : 'm' ou 'M' pour mégaoctets OU 'g' ou 'G' pour gigaoctets. Cette valeur ne peut pas être modifiée une fois JFR initialisé. (STRING, 10M)

•
stackdepth : (Facultatif) Profondeur de pile pour les traces de pile. Définir cette valeur au-dessus de la valeur par défaut de 64 peut entraîner une dégradation des performances. Cette valeur ne peut pas être modifiée une fois JFR initialisé. (LONG, 64)

JFR.dump [options]
Écrit les données dans un fichier pendant qu'un enregistrement de vol est en cours

Impact : Faible

Note :

Les options doivent être spécifiées en utilisant la syntaxe clé ou clé=valeur. Aucune option n'est requise. L'enregistrement continue de fonctionner après que les données ont été écrites.

options :

•
begin : (Facultatif) Spécifie l'heure à partir de laquelle les données d'enregistrement seront incluses dans le fichier de copie. Le format est spécifié comme heure locale. (STRING, pas de valeur par défaut)
•
end : (Facultatif) Spécifie l'heure jusqu'à laquelle les données d'enregistrement seront incluses dans le fichier de copie. Le format est spécifié comme heure locale. (STRING, pas de valeur par défaut)

Note : Pour begin et end, l'heure doit être dans un format qui peut être lu par java.time.LocalTime::parse(STRING), java.time.LocalDateTime::parse(STRING) ou java.time.Instant::parse(STRING). Par exemple, "13:20:15", "2020-03-17T09:00:00" ou "2020-03-17T09:00:00Z".

Note : Les heures begin et end correspondent aux horodatages trouvés dans les informations enregistrées des données d'enregistrement de vol.

Une autre option consiste à utiliser une heure relative à l'heure actuelle, spécifiée par un entier négatif suivi de "s", "m" ou "h". Par exemple, "-12h", "-15m" ou "-30s"

•
filename : (Facultatif) Nom du fichier dans lequel les données d'enregistrement de vol sont copiées. Si aucun nom de fichier n'est donné, un nom de fichier est généré à partir du PID et de la date actuelle. Le nom de fichier peut également être un répertoire, auquel cas, le nom de fichier est généré à partir du PID et de la date actuelle dans le répertoire spécifié. (STRING, pas de valeur par défaut)
•
maxage : (Facultatif) Durée pendant laquelle les données d'enregistrement de vol sont copiées dans un fichier. (INTEGER suivi de 's' pour secondes, 'm' pour minutes ou 'h' pour heures, pas de valeur par défaut)
•
maxsize : (Facultatif) Taille maximale de la quantité de données à copier d'un enregistrement de vol en octets si aucun des suffixes suivants n'est utilisé : 'm' ou 'M' pour mégaoctets OU 'g' ou 'G' pour gigaoctets. (STRING, pas de valeur par défaut)
•
name : (Facultatif) Nom de l'enregistrement. Si aucun nom n'est donné, les données de tous les enregistrements sont copiées. (STRING, pas de valeur par défaut)
•
path-to-gc-root : (Facultatif) Indicateur pour enregistrer le chemin vers les racines de garbage collection (GC) au moment où les données d'enregistrement sont copiées. Les informations de chemin sont utiles pour trouver les fuites de mémoire, mais leur collecte peut entraîner une courte pause de l'application. Activez cette
drapeau uniquement lorsque vous avez une application dont vous soupçonnez une fuit
e de mémoire. (BOOLEAN, false)
