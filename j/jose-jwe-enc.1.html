NOM

jose-jwe-enc - Chiffre du texte brut à l'aide d'une ou plusieurs clés JWK/mot de passe

SYNTAXE

jose jwe enc [-i JWE] -I PT -k JWK [-p] [-r RCP] [-o JWE] [-O CT] [-c]

APERÇU

La commande jose jwe enc chiffre des données à l'aide d'une ou plusieurs clés JWK (-k) ou mots de passe (-p). Lorsque vous spécifiez plus d'une clé JWK ou mot de passe, le déchiffrement réussira avec l'une des clés fournies.

Un JWE détaché peut être créé en spécifiant l'option -O. Dans ce cas, le texte chiffré décodé sera écrit dans la sortie spécifiée et ne sera pas inclus dans le JWE.

Si une seule clé est utilisée (-k ou -p), le JWE résultant peut être généré en utilisant la sérialisation compacte à l'aide de l'option -c.

Cette commande utilise une approche basée sur des modèles pour construire un JWE. Vous pouvez spécifier des modèles du JWE lui-même (-i) ou de l'objet destinataire JWE (-r). Les attributs spécifiés dans ces modèles apparaîtront inchangés dans la sortie. Une exception à cette règle est que l'en-tête protégé JWE doit être spécifié sous sa forme décodée dans le modèle. Cette commande l'encodera automatiquement dans le cadre du processus de chiffrement.

Si vous spécifiez un paramètre d'en-tête JOSE (via les options -i ou -r) qui affecte la construction du JWE, cette commande tentera de se comporter conformément à ce paramètre comme s'il s'agissait d'une configuration. Par exemple, spécifier le paramètre "zip" dans l'en-tête protégé JWE provoquera la compression du texte brut avant le chiffrement. Actuellement, jose modifiera son comportement pour les paramètres d'en-tête JOSE "alg", "enc" et "zip" (voir RFC 7516 Section 4.1.3), ainsi que les paramètres spécifiques aux algorithmes pour les algorithmes que nous prenons en charge (voir RFC 7518 Section 4).

Cependant, il n'est pas nécessaire de fournir de modèles : jose jwe enc remplira automatiquement les paramètres "alg" et "enc" en déduisant les algorithmes corrects des clés d'entrée fournies (JWK ou mot de passe). Par conséquent, les options -i et -r doivent généralement être utilisées pour fournir des métadonnées JWE étendues.

OPTIONS

•-i JSON, --input=JSON : Analyse le JWE à partir de JSON
•-i FICHIER, --input=FICHIER : Lit le JWE depuis FICHIER
•-i -, --input=-: Lit le JWE depuis l'entrée standard
•-I FICHIER, --detached=FICHIER : Lit le texte chiffré décodé depuis FICHIER
•-I -, --detached=- : Lit le texte chiffré décodé depuis l'entrée standard
•-r FICHIER, --recipient=FICHIER : Lit le modèle de destinataire JWE depuis FICHIER
•-r -, --recipient=- : Lit le modèle de destinataire JWE depuis l'entrée standard
•-k FICHIER, --key=FICHIER : Lit le JWK(Set) depuis FICHIER
•-k -, --key=- : Lit le JWK(Set) depuis l'entrée standard
•-p, --password : Demande un mot de passe de chiffrement
•-o FICHIER, --output=FICHIER : Écrit le JWE dans FICHIER
•-o -, --output=- : Écrit le JWE dans la sortie standard (par défaut)
•-O FICHIER, --detach=FICHIER : Détache le texte chiffré et le décode dans FICHIER
•-O -, --detach=- : Détache le texte chiffré et le décode dans la sortie standard
•-c, --compact : Génère le JWE en utilisant la sérialisation compacte

EXEMPLES

Chiffrer des données avec une clé symétrique en utilisant la sérialisation JSON JWE :

$ jose jwk gen -i '{"alg":"A128GCM"}' -o key.jwk
$ jose jwe enc -I msg.txt -k key.jwk -o msg.jwe

Chiffrer des données avec un mot de passe en utilisant la sérialisation compacte JWE :

$ jose jwe enc -I msg.txt -p -c -o msg.jwe
