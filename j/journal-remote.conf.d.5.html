NOM

journal-remote.conf, journal-remote.conf.d - Fichiers de configuration pour le service acceptant les téléchargements de journaux distants

SYNOPSIS

/etc/systemd/journal-remote.conf
/run/systemd/journal-remote.conf
/usr/local/lib/systemd/journal-remote.conf
/usr/lib/systemd/journal-remote.conf
/etc/systemd/journal-remote.conf.d/*.conf
/run/systemd/journal-remote.conf.d/*.conf
/usr/local/lib/systemd/journal-remote.conf.d/*.conf
/usr/lib/systemd/journal-remote.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent divers paramètres de systemd-journal-remote.service(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi la configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers additionnels (drop-ins), comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est livré sous /etc/), cependant l'utilisation de fichiers additionnels pour la configuration locale est recommandée plutôt que les modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration additionnels sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers additionnels ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui acceptent une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers additionnels sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers additionnels doivent être utilisés pour remplacer les fichiers additionnels des paquets, car le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un trait d'union, pour simplifier le tri. Cela définit également un concept de priorités pour les fichiers additionnels afin de permettre aux fournisseurs de systèmes d'exploitation de livrer des fichiers additionnels dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers additionnels des paquets remplacent accidentellement les fichiers additionnels définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers additionnels dans /usr/ et la plage 60-90 pour les fichiers additionnels dans /etc/ et /run/, pour s'assurer que les fichiers additionnels locaux et transitoires ont la priorité sur les fichiers additionnels livrés par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Toutes les options sont configurées dans la section [Remote] :

Seal=

Signe périodiquement les données du journal en utilisant le chiffrement Forward Secure Sealing.

Ajouté dans la version 229.

SplitMode=

L'une des valeurs : "host" ou "none".

Ajouté dans la version 220.

ServerKeyFile=

Clé SSL au format PEM.

Ajouté dans la version 220.

ServerCertificateFile=

Certificat SSL au format PEM.

Ajouté dans la version 220.

TrustedCertificateFile=

Certificat CA SSL.

Ajouté dans la version 220.

MaxUse=, KeepFree=, MaxFileSize=, MaxFiles=

Ces options sont analogues à SystemMaxUse=, SystemKeepFree=, SystemMaxFileSize= et SystemMaxFiles= dans journald.conf(5).

MaxUse= contrôle l'espace disque maximum que systemd-journal-remote peut utiliser. KeepFree= contrôle l'espace disque que systemd-journal-remote doit laisser libre pour d'autres utilisations. systemd-journal-remote respectera les deux limites et utilisera la plus petite des deux valeurs.

MaxFiles= contrôle le nombre maximum de fichiers de journal individuels à conserver. Notez que seuls les fichiers archivés sont supprimés pour réduire le nombre de fichiers jusqu'à atteindre cette limite ; les fichiers actifs resteront. Cela signifie qu'en réalité, il pourrait encore y avoir plus de fichiers de journal au total que cette limite une fois qu'une opération de nettoyage est terminée.

Ajouté dans la version 253.

Compression=

Configure les algorithmes de compression acceptables à annoncer via l'en-tête HTTP "Accept-Encoding". L'en-tête suggère à systemd-journal-upload de compresser les données à envoyer. Prend une liste d'algorithmes de compression séparés par des espaces, ou "no". Les algorithmes pris en charge sont "zstd", "xz", ou "lz4". Lorsqu'une liste d'algorithmes est spécifiée, l'en-tête "Accept-Encoding" sera construit avec des priorités basées sur l'ordre des algorithmes dans la liste. Lorsque "no" est spécifié, l'en-tête "Accept-Encoding" ne sera pas envoyé. Cette option peut être spécifiée plusieurs fois. Si une chaîne vide est assignée, alors toutes les assignations précédentes sont effacées. Par défaut, non définie et tous les algorithmes de compression pris en charge seront listés dans l'en-tête.

Exemple :

Compression=zstd lz4

Ajouté dans la version 258.
