NOM

jgmenu - Un menu X11 simple

SYNTAXE

jgmenu [--no-spawn] [--checkout=<tag>] [--config-file=<fichier>]

       [--icon-size=<taille>] [--at-pointer] [--hide-on-startup]

       [--simple] [--vsimple] [--csv-file=<fichier>]

       [--csv-cmd=<commande>] [--die-when-loaded]

       [--center] [--persistent]

Utilisez ces commandes pour commencer

jgmenu_run
Lancer le menu
jgmenu_run init
Créer le fichier de configuration ~/.config/jgmenu/jgmenurc
jgmenu_run init -i
Configuration interactive
man jgmenututorial
Tutoriel étape par étape

DESCRIPTION

jgmenu est un menu simple pour Linux/BSD. Il lit des données de menu CSV à partir d'un fichier et génère un menu graphique dans une fenêtre X11.

Champs

Chaque ligne de données de menu CSV est analysée dans les champs suivants en utilisant la virgule comme séparateur de champ :

(1)
description
(2)
commande
(3)
icône
(4)
répertoire de travail
(5)
métadonnées

Par exemple :

printf "Terminal,xterm\\nNavigateur Web,firefox" | jgmenu --vsimple

Caractères spéciaux en début de ligne

#
Ignorer la ligne
.
Une ligne commençant par un point suivi d'un espace, sourcera le fichier spécifié par la chaîne suivant le point
@
Traiter comme un widget

Caractères spéciaux dans les champs

,
Comme les virgules sont utilisées comme séparateurs de champs, les champs individuels ne peuvent contenir de virgules que s'ils sont triple guillemets. Par exemple :

foo,“““^pipe(find . -printf `%f,display %p,%p\n')”“”

< > &
Le champ description est analysé comme du balisage pango, donc <, >, et & doivent être échappés en &lt;, &gt;, et &amp; respectivement.
"
Contrairement à la plupart des implémentations CSV, une seule instance de guillemets doubles (") n'est pas considérée comme un caractère spécial. La raison en est de permettre aux utilisateurs d'écrire des commandes avec des guillemets doubles sans avoir à les échapper.
"""
Utilisez trois guillemets """ pour commencer et terminer une valeur entièrement entre guillemets. L'utilisation principale est lorsqu'une virgule est nécessaire dans une valeur.

Marquage

La syntaxe ^foo(bar) est utilisée pour effectuer l'action foo avec l'argument bar. Nous appelons bar la valeur interne.

Le balisage suivant est supporté dans le champ description

sep()
Définir un séparateur. Si une valeur interne est fournie, le séparateur apparaîtra comme un titre. Si aucune valeur interne n'est fournie, le séparateur sera simplement une ligne horizontale

Le balisage suivant est supporté dans le champ commande

^tag()
Définir le début d'un nouveau nœud de structure de menu.

Les lignes suivant ^tag(quelque chose) ne seront pas affichées dans le menu de niveau supérieur, mais pourront être ouvertes en utilisant ^checkout() ou ^root().

item0.0
item0.1
submenu1,^checkout(1)
submenu2,^root(2)
^tag(1)
item1.0
item1.1
^tag(2)
item2.0
item2.1
^checkout()
Ouvrir le tag spécifié par la valeur interne comme sous-menu dans une nouvelle fenêtre
^root()
Ouvrir le tag spécifié par la valeur interne dans la fenêtre racine, remplaçant le menu actuel
^sub()
Dessiner une flèche de sous-menu. Ceci peut être utile pour créer des sous-menus avec stay_alive=0. Par exemple :
item0.0
item0.1
submenu1,^sub(echo "item1.0" | jgmenu --simple)
^back()
Vérifier le menu parent
^term()
Exécuter le programme dans un terminal
^pipe()
Exécuter un sous-processus et vérifier un menu basé sur sa sortie standard.
^filter()
Invoquer la recherche
^quit()
Quitter

Icônes

Les icônes seront affichées si le troisième champ est rempli, par exemple :

Terminal,xterm,utilities-terminal
Firefox,firefox,firefox

OPTIONS

--no-spawn
Rediriger la commande vers la sortie standard plutôt que de l'exécuter.
--checkout=<tag>
Vérifier le sous-menu au démarrage.
--config-file=<fichier>
Lire le fichier de configuration.
--icon-size=<taille>
Spécifier la taille des icônes (22 par défaut). Si défini à 0, les icônes ne seront pas chargées.
--at-pointer
Lancer le menu au pointeur de la souris.
--hide-on-startup
Le menu de démarrage est dans un état caché.
--simple
Ignorer les paramètres de tint2 ; s'exécute en mode courte durée (c'est-à-dire quitter après un clic de souris ou touche entrée/échap) ; lire les éléments du menu depuis stdin.
--vsimple
Identique à --simple, mais désactive également les icônes et ignore jgmenurc.
--csv-file=<fichier>
Spécifier le fichier de menu (au format CSV de jgmenu). Si le fichier ne peut pas être ouvert, l'entrée est rétablie à stdin.
--csv-cmd=<commande>
Spécifier la commande pour produire les données du menu, par exemple jgmenu_run pmenu
--die-when-loaded
Ouvrir le menu puis quitter (0). Utile pour le débogage et les tests.
--center
Centrer le menu horizontalement et verticalement.
--persistent

WIDGETS

Les lignes commençant par `@` dans les fichiers CSV au format jgmenu sont analysées conformément à la syntaxe suivante :

@type,action,x,y,w,h,r,halign,valign,fgcol,bgcol,content
type
Le type de widget, qui peut être l'un des suivants :
rect
Rectangle avec une bordure de 1px dessinée en utilisant fgcol
search
Boîte de recherche affichant le filtre actuel (ce que l'utilisateur a tapé) ou le texte spécifié text si aucun filtre n'a été activé.
icon
Icône
action
L'action à effectuer lors de la sélection. Il peut s'agir d'une commande shell ou d'une action de menu telle que ^root().
x, y
Marge horizontale et verticale du widget
w, h
Largeur et hauteur du widget
r
Rayon des coins
fgcol, bgcol
Couleurs de premier plan et d'arrière-plan en utilisant la syntaxe rrggbb aaa. fgcol accepte auto pour utiliser le color_norm_fg de jgmenurc.
content
icon_path pour les widgets icon. text pour tous les autres types de widgets.
halign, valign
Alignement horizontal et vertical du widget. Cela n'a pas encore été implémenté, mais par défaut, c'est top et left.

FICHIER DE CONFIGURATION

Si aucun fichier n'est spécifié avec l'option `--config-file=`, la spécification XDG Base Directory est respectée. C'est-à-dire :

•
Configuration globale dans ${XDG_CONFIG_DIRS:-/etc/xdg}
•
Surcharge de configuration utilisateur dans ${XDG_CONFIG_HOME:-$HOME/.config}

Pour la plupart des utilisateurs, `~/.config/jgmenu/jgmenurc` convient.

Les variables de configuration globales sont définies dans l'ordre suivant (c'est-à-dire que le bas de la liste a une priorité plus élevée) :

•
valeurs par défaut intégrées (config.c)
•
fichier de configuration tint2rc (peut être spécifié par la variable d'environnement TINT2_CONFIG)
•
fichier de configuration jgmenurc (peut être spécifié par `--config-file=`)
•
arguments de ligne de commande

Syntaxe

Les lignes commençant par # sont ignorées.

Toutes les autres lignes sont reconnues comme définissant des variables au format :

key = value

Les espaces blancs sont largement ignorés.

Valeurs

Sauf indication contraire, les valeurs sont traitées comme des chaînes simples.

Voici quelques types spécifiques :

booléen
Lorsqu'une variable prend une valeur booléenne, seuls 0 et 1 sont acceptés. 0 signifie faux ; 1 signifie vrai.
entier
Lorsqu'une variable prend une valeur entière, seuls les valeurs numériques sont acceptées. Les seuls caractères valides sont les chiffres (0-9) et le signe moins. Toutes les variables entières relatives à la géométrie et à la position sont interprétées comme des valeurs en pixels, sauf indication contraire.
couleur
Lorsqu'une variable prend une valeur de couleur, seule la syntaxe #rrggbb aaa est reconnue, où rr, gg et bb représentent les valeurs hexadécimales (00-ff) pour les couleurs rouge, verte et bleue respectivement ; et aaa représente la valeur du canal alpha exprimée en pourcentage (0-100) (c'est-à-dire que 100 signifie aucune transparence et 0 signifie entièrement transparent). Par exemple, #ff0000 100 représente le rouge sans transparence, tandis que #000088 50 signifie bleu foncé avec 50% de transparence.
chemin
Lorsqu'une variable prend une valeur de chemin, elle est évaluée comme une chaîne. Si le premier caractère est un tilde (~), il sera remplacé par la variable d'environnement $HOME, tout comme un shell l'étendrait.

verbosity = entier (défaut 0)
Verbosité générale : (0) avertissements seulement ; (1) informations de base ; (2) plus d'informations ; (3) informations maximales.

Sujets spécifiques supplémentaires : (4) IPC

stay_alive = booléen (défaut 1)
Si défini sur 1, le menu se "masquera" plutôt que de se "fermer" lorsque les événements suivants se produisent : cliquer sur un élément du menu ; cliquer en dehors du menu ; appuyer sur Échap. En mode masqué, un signal USR1 "démasquera" le menu.
persistent = booléen (défaut 0)
Si défini sur 1, le menu ne se fermera ni ne se masquera lors des événements suivants : cliquer sur un élément du menu ; cliquer en dehors du menu ; appuyer sur Échap. À utiliser en conjonction avec le balisage ^quit().
hide_on_startup = booléen (défaut 0)
Si défini sur 1, jgmenu démarre en mode "masqué". Ceci est utile pour démarrer jgmenu pendant le processus de démarrage, puis envoyer une commande killall -SIGUSR1 jgmenu pour afficher le menu.

Variables du générateur CSV

Les variables suivantes commencent par csv_, ce qui indique qu'elles définissent des variables d'environnement utilisées par les générateurs CSV.

csv_name_format = chaîne (défaut %n (%g))
Définit le format du champ name pour les générateurs CSV. Pris en charge par les applications et lx. Il comprend les deux champs suivants :
%n
Nom de l'application
%g
Nom générique de l'application. Si un nom générique n'existe pas ou est identique au nom, %n sera utilisé sans aucun formatage.
csv_single_window = booléen (défaut 0)
Si défini, les générateurs csv produiront ^root() au lieu de ^checkout(). Ceci résulte en un menu à fenêtre unique, où les sous-menus apparaissent dans la même fenêtre. Ceci est pris en charge par les applications et pmenu.
csv_no_dirs = booléen (défaut 0)
Si défini, les générateurs csv produiront les applications sans aucune structure de répertoire. Ceci est pris en charge par les applications, pmenu et lx.
csv_i18n = chaîne (pas de défaut)
Recherche un fichier de traduction dans le fichier ou le répertoire spécifié. Voir `jgmenu-i18n(1) pour plus de détails. Pris en charge par les applications et ob.

NAME

jgmenu — a generic menu for all window managers and desktop environments

SYNOPSIS

jgmenu [options]
jgmenu_run [options]

DESCRIPTION

jgmenu is a graphical menu program that reads menu entries from standard input or from a file (either ~/.config/jgmenu/menu.csv or /etc/jgmenu/menu.csv).

jgmenu reads it's configuration from ~/.config/jgmenu/jgmenurc.

jgmenu_run is a wrapper script that generates a menu for use in Openbox, Fluxbox, dwm, i3, Awesome, or any other window manager or desktop environment.

jgmenu_run is used to create application menus, run commands and so on.

jgmenu_run creates the menu by passing the relevant information on to jgmenu.

The jgmenu configuration file and the jgmenu_run wrapper script share a lot of the same settings.

For a full list of settings, see the jgmenurc(5) man page.

CONFIGURATION FILE

jgmenu configuration is done via the file ~/.config/jgmenu/jgmenurc.

jgmenu_run can create the following menu files:

~/.config/jgmenu/menu.csv
~/.config/jgmenu/append.csv
~/.config/jgmenu/prepend.csv

and /etc/jgmenu/menu.csv.

The format of the menu files is:

<icon>,<label>,<command>

Where:

<icon>
is the icon to be displayed (optional).
<label>
is the text to be displayed.
<command>
is the command to be run when the menu item is selected.

For example:

icons/leaf.png,My Applications,my_apps

Inter-Process Communication (IPC)

jgmenu supports inter-process communication via named pipes. This allows external applications to communicate with a running instance of jgmenu.

The IPC mechanism is enabled by default. It can be disabled using the --no-ipc option when running jgmenu.

When enabled, jgmenu creates a named pipe at ~/.config/jgmenu/jgmenu.pipe. External applications can write commands to this pipe to interact with jgmenu.

The following commands are supported:

RELOAD
Reload the menu from its configuration file.
REBUILD
Rebuild the menu from scratch.
EXIT
Close the jgmenu window.
SET_THEME<theme_name>
Set the theme to the specified name.
SET_STYLE<style_name>
Set the style to the specified name.
SET_ICON<icon_name>
Set the icon to the specified name.

HOOKS

A hook in jgmenu is a rule which optionally triggers a command and then performs a restart if a file or directory has has changed since the last time the instance of jgmenu was mapped (=made visible - normally by running jgmenu_run).

Hooks are specified in the file $HOME/.config/jgmenu/hooks are take the format

<file>,<command>

For example, to synchronise with the GTK theme, use this hook:

~/.config/gtk-3.0/settings.ini,jgmenu_run gtktheme

Leave the <command> empty to just restart.

A number of restart-hooks are built-in by default, for example ~/.config/jgmenu/{jgmenurc,append.csv,prepend.csv} and /usr/share/applications.

To list all the built-in hooks, use the keyword print in the hook file (on a line on its own). In order to remove all the built-in hooks, use the keyword clear.

STARTUP SCRIPT

Unless the --vsimple argument is used, the file ~/.config/jgmenu/startup is executed on initial startup.
