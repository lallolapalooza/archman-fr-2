JFR(1) Commandes JDK JFR(1)

NOM

jfr - imprimer et manipuler les fichiers Flight Recorder

SYNTAXE

Pour imprimer le contenu d'un enregistrement de vol sur la sortie standard :

jfr print [options] fichier

Pour afficher les données d'événements agrégées sur la sortie standard :

jfr view [options] fichier

Pour configurer un fichier de paramètres .jfc :

jfr configure [options]

Pour imprimer les métadonnées des événements du Flight Recorder :

jfr metadata [fichier]

Pour visualiser les statistiques résumées d'un fichier d'enregistrement de vol :

jfr summary fichier

Pour supprimer des événements d'un fichier d'enregistrement de vol :

jfr scrub [options] fichier

Pour assembler des fichiers de fragments en un fichier d'enregistrement de vol :

jfr assemble dépôt fichier

Pour démonter un fichier d'enregistrement de vol en fichiers de fragments :

jfr disassemble [options] fichier

options
Optionnel : Spécifie les options de ligne de commande séparées par des espaces. Voir les sections des sous-composants individuels pour les descriptions des options disponibles.
fichier
Spécifie le nom du fichier d'enregistrement de vol cible (.jfr).
dépôt
Spécifie l'emplacement des fichiers de fragments qui doivent être assemblés en un enregistrement de vol.

DESCRIPTION

La commande jfr fournit un outil pour interagir avec les fichiers du Flight Recorder (.jfr). La fonction principale est de filtrer, résumer et sortir les fichiers d'enregistrement de vol dans un format lisible par l'homme. Il y a aussi un support pour le nettoyage, la fusion et la division des fichiers d'enregistrement.

Les fichiers d'enregistrement de vol sont créés et sauvegardés sous forme de fichiers binaires. Avoir un outil capable d'extraire le contenu d'un enregistrement de vol et de manipuler le contenu et de le traduire dans un format lisible par l'homme aide les développeurs à déboguer les problèmes de performances des applications Java.

jfr print sous-commande

Utilisez jfr print pour imprimer le contenu d'un fichier d'enregistrement de vol sur la sortie standard.

La syntaxe est :

jfr print [--xml|--json|--exact] [--categories <filtres>] [--events <filtres>] [--stack-depth <profondeur>] <fichier>

où :

--xml
Imprime l'enregistrement au format XML.
--json
Imprime l'enregistrement au format JSON.
--exact
Imprime joliment les nombres et les horodatages avec une précision complète.
--categories <filtres>
Sélectionne les événements correspondant à un nom de catégorie. Le filtre est une liste séparée par des virgules de noms, simples et/ou qualifiés, et/ou de motifs glob globés entre guillemets.
--events <filtres>
Sélectionne les événements correspondant à un nom d'événement. Le filtre est une liste séparée par des virgules de noms, simples et/ou qualifiés, et/ou de motifs glob globés entre guillemets.
--stack-depth <profondeur>
Nombre de cadres dans les traces de pile, par défaut 5.
<fichier>
Emplacement du fichier d'enregistrement (.jfr)

Le format par défaut pour imprimer le contenu du fichier d'enregistrement de vol est une forme lisible par l'homme, sauf si xml ou json est spécifié. Ces options fournissent une sortie lisible par machine qui peut être davantage analysée ou traitée par des scripts créés par l'utilisateur.

Utilisez jfr --help print pour voir des exemples d'utilisation des filtres.

Pour réduire la quantité de données affichées, il est possible de filtrer les événements ou les catégories d'événements. Le filtre agit sur le nom symbolique d'un événement, défini à l'aide de l'annotation @Name, ou le nom de la catégorie, défini à l'aide de l'annotation @Category. Si plusieurs filtres sont utilisés, les événements des deux filtres seront inclus. Si aucun filtre n'est utilisé, tous les événements seront imprimés. Si une combinaison d'un filtre de catégorie et d'un filtre d'événement est utilisée, les événements sélectionnés seront l'union des deux filtres.

Par exemple, pour afficher tous les événements GC et l'événement CPULoad, la commande suivante peut être utilisée :

jfr print --categories GC --events CPULoad enregistrement.jfr

Les valeurs des événements sont formatées selon les types de contenu utilisés. Par exemple, un champ avec l'annotation jdk.jfr.Percentage dont la valeur est 0.52 est formaté comme 52 %.

Les traces de pile sont par défaut tronquées à 5 cadres, mais le nombre peut être augmenté/diminué à l'aide de l'option de ligne de commande --stack-depth.

jfr view sous-commande

Utilisez jfr view pour agréger et afficher les données d'événements sur la sortie standard.

La syntaxe est :

jfr view [--verbose] [--width <entier>] [--truncate <mode>] [--cell-height <entier>] <vue> <fichier>

où :

--verbose
Affiche la requête qui constitue la vue.
--width <entier>
La largeur de la vue en caractères. La valeur par défaut dépend de la vue.
--truncate <mode>
Comment tronquer le contenu qui dépasse l'espace dans une cellule de tableau. Le mode peut être 'beginning' (début) ou 'end' (fin). La valeur par défaut est 'end'.
--cell-height <entier>
Nombre maximum de lignes dans une cellule de tableau. La valeur par défaut dépend de la vue.
<vue>
Nom de la vue ou du type d'événement à afficher. Utilisez jfr --help view pour voir une liste des vues disponibles.
<fichier>
Emplacement du fichier d'enregistrement (.jfr)

Le paramètre <vue> peut être un nom de type d'événement. Utilisez jfr view types <fichier> pour voir une liste. Pour afficher toutes les vues, utilisez jfr view all-views <fichier>. Pour afficher tous les événements, utilisez jfr view all-events <fichier>.

Les informations d'enregistrement de vol sont écrites en fragments. Un fragment contient toutes les informations nécessaires pour l'analyse. Un fragment contient typiquement des événements utiles pour le dépannage. Si une JVM devait planter, ces fragments peuvent être récupérés et utilisés pour créer un fichier d'enregistrement de vol en utilisant cette commande jfr assemble. Ces fichiers de fragments sont concaténés dans l'ordre

chronologique et les fichiers de fragmen
ts non terminés (.part) sont exclus.
