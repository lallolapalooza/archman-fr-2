NOM

jj-git-fetch - Récupérer depuis un dépôt distant Git

SYNTAXE

jj git fetch [-b|--branch] [--tracked] [--remote] [--all-remotes] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPTION

Récupérer depuis un dépôt distant Git

Si un commit de la copie de travail est abandonné, il recevra un nouveau commit vide. Ceci est vrai en général ; ce n'est pas spécifique à cette commande.

OPTIONS

-b, --branch <BRANCHE>
Récupérer seulement certaines branches

Par défaut, le nom spécifié correspond exactement. Utilisez le préfixe `glob:` pour développer `*` comme un motif glob, par exemple `--branch 'glob:push-*'`. D'autres caractères génériques comme `?` ne sont *pas* pris en charge. Peut être répété pour spécifier plusieurs branches.

--tracked
Récupérer seulement les signets suivis

Ceci récupère uniquement les signets qui sont déjà suivis depuis le(s) dépôt(s) distant(s) spécifié(s).

--remote <REMOTE>
Le dépôt distant à partir duquel récupérer (seuls les dépôts nommés sont pris en charge, peut être répété)

Ceci est défini par défaut par le paramètre `git.fetch`. S'il n'est pas configuré, et s'il y a plusieurs dépôts distants, le dépôt nommé "origin" sera utilisé.

Par défaut, les noms des dépôts distants spécifiés correspondent exactement. Utilisez un [modèle de chaîne], par exemple `--remote 'glob:*'`, pour sélectionner les dépôts en utilisant des modèles.

[modèle de chaîne]: https://docs.jj-vcs.dev/latest/revsets#string-patterns

--all-remotes
Récupérer depuis tous les dépôts distants
-h, --help
Imprimer l'aide (voir un résumé avec '-h')

OPTIONS GLOBALES

-R, --repository <DEPOT>
Chemin vers le dépôt sur lequel opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas instantanéer la copie de travail, et ne pas la mettre à jour

Par défaut, Jujutsu prend un instantané de la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter d'instantanéer la copie de travail et voir plutôt un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile par exemple dans une invite de commande, surtout si un autre processus committe la copie de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Permettre la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt à une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée était terminée. `--at-op=@` est à peu près identique par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération que vous souhaitez. N'importe quel préfixe non ambigu de l'ID de l'opération suffit.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Faire cela équivaut à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Supprimer la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été instantanée ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le pager
--config <NOM=VALEUR>
Options de configuration supplémentaires (peut être répété)

Le nom doit être spécifié sous forme de clés séparées par des points TOML. La valeur doit être spécifiée sous forme d'expression TOML. Si la valeur de chaîne n'est pas entourée de constructions TOML (telles que la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peut être répété)
fetch
