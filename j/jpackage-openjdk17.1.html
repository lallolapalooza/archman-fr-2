DESCRIPTIO

N

L'outil jpackage prendra en entrée une application Java et une image d'exécution Java, et produira une image d'application Java incluant toutes les dépendances nécessaires. Il sera capable de produire un paquet natif dans un format spécifique à la plateforme, comme un ex

e sous Windows ou un dmg sous macOS. Chaque format doit être construit sur la plateforme sur laquelle il s'exécute, il n'y a pas de
support multiplateforme. L'outil disposera d'options permettant de personnaliser les applications empaquetées de diverses manières.

Les clés "module", "main-jar", "main-class", "arguments", "java-options", "app-version", "icon", "linux-app-category", "linux-app-release" et "win-console" peuvent être

Ces options sont ajoutées, ou utilisées pour écraser, les options de ligne de commande originales pour construire un lanceur alternatif supplémentaire. Le lanceur principal de l'application sera construit à partir des options de ligne de commande. arguments>
Arguments de ligne de commande à passer à la classe principale si aucun argument de ligne de commande n'estre donné au lanceur

Cette option peut être utilisée plusieurs fois.

--java-options <options java>
Options à passer au runtime Java

Cette option peut être utilisée plusieurs fois.

--main-class <nom de classe>
Nom qualifié de la classe principale de l'application à exécuter

Cette option ne peut être utilisée que si l'option --main-jar est spécifiée.

--main-jar <fichier jar principal>
Le JAR principal de l'application ; contenant la classe principale (spécifiée comme un chemin relatif au chemin d'entrée)

L'option --module ou l'option --main-jar peut être spécifiée, mais pas les deux.

--module ou -m <nom du module>/<classe principale>]
Le module principal (et éventuellement la classe principale) de l'application

Ce module doit être situé sur le chemin du module.

Lorsque cette option est spécifiée, le module principal sera lié dans l'image du runtime Java. L'option --module ou l'option --main-jar peut être spécifiée, mais pas les deux.

Option spécifique à la plateforme pour la création du lanceur d'application :

Options pour la plateforme Windows (disponibles uniquement sous Windows) :

--win-console
Crée un lanceur de console pour l'application, doit être spécifié pour les applications qui nécessitent des interactions de console

Options pour la plateforme macOS (disponibles uniquement sous macOS) :

--mac-package-identifier <chaîne d'ID>
Un identifiant qui identifie de manière unique l'application pour macOS

Par défaut, le nom de la classe principale.

Peut uniquement utiliser des caractères alphanumériques (A-Z, a-z, 0-9), un trait d'union (-) et un point (.).

--mac-package-name <chaîne de nom>
Nom de l'application tel qu'il apparaît dans la barre des menus

Cela peut être différent du nom de l'application.

Ce nom doit être inférieur à 16 caractères et convenir à l'affichage dans la barre des menus et dans la fenêtre d'informations de l'application. Par défaut, le nom de l'application.

--mac-package-signing-prefix <chaîne de préfixe>
Lors de la signature du paquet d'application, cette valeur est ajoutée en préfixe à tous les composants qui doivent être signés et qui n'ont pas d'identifiant de paquet existant.
--mac-sign
Demande que le bundle soit signé.
--mac-signing-keychain <nom de la trousseau>
Nom du trousseau à rechercher pour l'identité de signature

Si non spécifié, les trousseaux standard sont utilisés.

--mac-signing-key-user-name <nom de l'équipe>
Nom de l'équipe ou du nom d'utilisateur dans les identités de signature Apple
--mac-app-store
Indique que la sortie jpackage est destinée au Mac App Store.
--mac-entitlements <chemin du fichier>
Chemin vers le fichier contenant les droits d'accès à utiliser lors de la signature des exécutables et des bibliothèques du bundle
--mac-app-category <chaîne de catégorie>
Chaîne utilisée pour construire LSApplicationCategoryType dans le plist de l'application

La valeur par défaut est « utilities ».

EXEMPLES JPACKAGE


Générer un package d'application ; adapté au système hôte :


Pour une application modulaire :
    jpackage -n nom -p chemin_module -m nom_module/nom_classe
Pour une application non modulaire :
    jpackage -i repertoire_entree -n nom \
           --main-class nom_classe --main-jar monJar.jar
À partir d'une image d'application pré-construite :
    jpackage -n nom --app-image repertoire_image_app


Générer une image d'application :


Pour une application modulaire :
    jpackage --type app-image -n nom -p chemin_module \
           -m nom_module/nom_classe
Pour une application non modulaire :
    jpackage --type app-image -i repertoire_entree -n nom \
           --main-class nom_classe --main-jar monJar.jar
Pour fournir vos propres options à jlink, exécutez jlink séparément :
    jlink --output image_runtime_app -p chemin_module \
           --add-modules nom_module \
           --no-header-files [<options_jlink_additionnelles>...]
    jpackage --type app-image -n nom \
           -m nom_module/nom_classe --runtime-image image_runtime_app


Générer un package d'exécution Java :


jpackage -n nom --runtime-image <image-runtime>
