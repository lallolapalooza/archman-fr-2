jack-dssi-host(1) Manuel des commandes générales jack-dssi-host(1)

NOM

jack-dssi-host - un hôte JACK simple pour les plugins DSSI

SYNTAXE

jack-dssi-host [-v] [-a] [-n] [-p <rep_proj>] [-c <nom_cl>] [-<i>] <nom_lib>[:<etiquette>] [...]

DESCRIPTION

jack-dssi-host est un hôte DSSI simple qui écoute les événements MIDI sur un port de séquenceur ALSA, les livre aux plugins synthétiseurs DSSI et diffuse l'audio résultant via JACK.
jack-dssi-host peut héberger jusqu'à 16 instances de plugins synthétiseurs DSSI, chacun se voyant attribuer séquentiellement un canal MIDI de 1 à 16. Les sorties des plugins (si `-a' n'est pas spécifié) sont connectées séquentiellement aux ports de sortie physiques JACK disponibles, revenant au premier port JACK lorsque les ports disponibles sont épuisés. Les interfaces utilisateur (UI) des plugins sont lancées pour chaque instance (si '-n' n'est pas spécifié.) jack-dssi-host se terminera lorsque la dernière interface utilisateur de plugin sera fermée.
À titre exceptionnel, si jack-dssi-host est lancé avec un nom différent de `jack-dssi-host', et si ce nom (plus le suffixe `.so') peut être trouvé dans le chemin de recherche DSSI_PATH (voir ENVIRONNEMENT ci-dessous) en tant que bibliothèque partagée de plugin valide, et si aucun argument de ligne de commande supplémentaire n'est donné, alors le premier plugin de cette bibliothèque sera chargé automatiquement. Cela offre un moyen pratique de lancer un plugin en créant simplement un lien symbolique du nom de base du plugin vers jack-dssi-host.

OPTIONS

-v
Mode verbeux.
-a
Désactive la connexion automatique des sorties aux sorties physiques JACK.
-n
Désactive le lancement automatique des interfaces utilisateur (UI) des plugins.
-p <rep_proj>
Le répertoire de projet à passer au plugin et à l'UI.
-c <nom_cl>
Le nom du client à utiliser pour ALSA et JACK.
-<i>
Nombre d'instances du plugin suivant à exécuter (maximum 16 au total, par défaut 1).
<nom_lib>
Nom de la bibliothèque partagée du plugin DSSI (.so) à charger. Il peut s'agir d'un chemin absolu vers le fichier de la bibliothèque, ou simplement du nom du fichier lui-même, auquel cas le chemin de recherche DSSI est parcouru (voir ENVIRONNEMENT ci-dessous).
<etiquette>
l'étiquette du plugin à charger depuis la bibliothèque. Si elle est omise, le premier plugin de la bibliothèque est utilisé.
[...]
Optionnellement plus de nombres d'instances, de plugins et d'étiquettes.

EXEMPLE

jack-dssi-host -2 lib1.so -1 lib2.so:fuzzy
Exécute deux instances du premier plugin trouvé dans lib1.so, assignées aux canaux MIDI 1 et 2 et connectées aux premières sorties JACK disponibles, et une instance du plugin "fuzzy" dans lib2.so sur le canal MIDI 3 et connectée à la sortie JACK disponible suivante.

ENVIRONNEMENT

jack-dssi-host recherchera les bibliothèques partagées de plugins dans les répertoires spécifiés par la variable d'environnement DSSI_PATH, qui est une liste de répertoires séparés par des deux-points. Si DSSI_PATH n'est pas définie, un chemin de recherche par défaut de /usr/lib/dssi, /usr/local/lib/dssi, et (en supposant que la variable d'environnement HOME est définie) $HOME/.dssi est utilisé.
