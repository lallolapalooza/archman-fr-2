jj-show(1) Manuel des commandes générales jj-show(1)

NOM

jj-show - Afficher la description d'un commit et les modifications dans une révision

SYNTAXE

jj show [-T|--template] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [--no-patch] [-w|--ignore-all-space] [-b|--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [REVSET]

DESCRIPTION

Affiche la description d'un commit et les modifications dans une révision.

OPTIONS

-T, --template <TEMPLATE>
Rendre une révision à l'aide du modèle donné

Vous pouvez spécifier des expressions de modèle arbitraires en utilisant les [mots-clés intégrés]. Voir [`jj help -k templates`] pour plus d'informations.

[mots-clés intégrés]: https://docs.jj-vcs.dev/latest/templates/#commit-keywords

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-h, --help
Afficher l'aide (voir un résumé avec '-h')
[REVSET] [défaut: @]
Afficher les modifications dans cette révision, par rapport à ses parents.

OPTIONS DE FORMATAGE DE DIFF

-s, --summary
Pour chaque chemin, afficher uniquement s'il a été modifié, ajouté ou supprimé.
--stat
Afficher un histogramme des modifications.
--types
Pour chaque chemin, afficher uniquement son type avant et après.

La différence est affichée comme deux lettres. La première lettre indique le type avant et la seconde lettre indique le type après. '-' indique que le chemin n'était pas présent, 'F' représente un fichier régulier, `L' représente un lien symbolique, 'C' représente un conflit, et 'G' représente un sous-module Git.

--name-only
Pour chaque chemin, afficher uniquement son chemin.

Généralement utile pour des commandes shell comme : `jj diff -r @- --name-only | xargs perl -pi -e's/OLD/NEW/g`

--git
Afficher un diff au format Git.
--color-words
Afficher un diff au niveau des mots avec les modifications indiquées uniquement par la couleur.
--tool <TOOL>
Générer le diff par une commande externe.

Un format intégré peut également être spécifié comme `:<nom>`. Par exemple, `--tool=:git` est équivalent à `--git`.

--context <CONTEXT>
Nombre de lignes de contexte à afficher.
--no-patch
Ne pas afficher le patch.
-w, --ignore-all-space
Ignorer les espaces blancs lors de la comparaison des lignes.
-b, --ignore-space-change
Ignorer les changements dans la quantité d'espaces blancs lors de la comparaison des lignes.

OPTIONS GLOBALES

-R, --repository <REPOSITORY>
Chemin du dépôt sur lequel opérer.

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané du répertoire de travail et ne pas le mettre à jour.

Par défaut, Jujutsu prend un instantané du répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de prendre un instantané du répertoire de travail et voir à la place un commit de répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile par exemple dans une invite de commande, surtout si un autre processus valide le répertoire de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Permettre la réécriture de commits immuables.

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni la mot-clé `immutable` du modèle.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt.

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près identique par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération que vous souhaitez. N'importe quel préfixe non ambigu de l'ID d'opération suffit.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Le faire est équivalent à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage.
--color <WHEN>
Quand coloriser la sortie.

[valeurs possibles : always, never, debug, auto]

--quiet
Silencier la sortie non principale de la commande.

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si le répertoire de travail a été snapshotté ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le pagineur.
--config <NAME=VALUE>
Options de configuration supplémentaires (peuvent être répétées).

Le nom doit être spécifié comme des clés pointées TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur chaîne n'est pas entourée par des constructions TOML (telles que la notation de tableau), les guillemets peuvent être omis.

--config-file <PATH>
Fichiers de configuration supplémentaires (peuvent être répétés).
