jmap(1) Outils de dépannage jmap(1)

NOM

jmap - Imprime les cartes mémoire des objets partagés ou les détails de la mémoire du tas pour un processus, un fichier core, ou un serveur de débogage distant. Cette commande est expérimentale et non supportée.

SYNOPSIS

jmap [ options ] pid
jmap [ options ] executable core
jmap [ options ] [ pid ] server-id@ ] nom-hôte-ou-IP-distant
options
Les options en ligne de commande. Voir Options.
pid
L'identifiant du processus pour lequel la carte mémoire doit être imprimée. Le processus doit être un processus Java. Pour obtenir une liste des processus Java en cours d'exécution sur une machine, utilisez la commande jps(1).
executable
L'exécutable Java à partir duquel le vidage du noyau a été produit.
core
Le fichier core pour lequel la carte mémoire doit être imprimée.
nom-hôte-ou-IP-distant
Le serveur de débogage distant nom-hôte ou adresse IP. Voir jsadebugd(1).
server-id
Un identifiant unique optionnel à utiliser lorsque plusieurs serveurs de débogage s'exécutent sur le même hôte distant.

DESCRIPTION

La commande jmap imprime les cartes mémoire des objets partagés ou les détails de la mémoire du tas d'un processus spécifié, d'un fichier core ou d'un serveur de débogage distant. Si le processus spécifié s'exécute sur une machine virtuelle Java (JVM) 64 bits, vous pourriez avoir besoin de spécifier l'option -J-d64, par exemple : jmap-J-d64 -heap pid.

Note : Cet utilitaire n'est pas supporté et pourrait ne pas être disponible dans les futures versions du JDK. Sur les systèmes Windows où le fichier dbgeng.dll n'est pas présent, Debugging Tools For Windows doit être installé pour que ces outils fonctionnent. La variable d'environnement PATH doit contenir l'emplacement du fichier jvm.dll utilisé par le processus cible ou l'emplacement à partir duquel le fichier de vidage de crash a été produit, par exemple : set PATH=%JDK_HOME%\jre\bin\client;%PATH%.

OPTIONS

sans option
Lorsqu'aucune option n'est utilisée, la commande jmap imprime les mappages d'objets partagés. Pour chaque objet partagé chargé dans la JVM cible, l'adresse de début, la taille du mappage et le chemin complet du fichier d'objet partagé sont imprimés. Ce comportement est similaire à l'utilitaire pmap d'Oracle Solaris.
-dump:[live,] format=b, file=nom-fichier

Vide le tas Java au format binaire hprof dans nom-fichier. La sous-option live est optionnelle, mais lorsqu'elle est spécifiée, seuls les objets actifs dans le tas sont vidés. Pour parcourir le vidage du tas, vous pouvez utiliser la commande jhat(1) pour lire le fichier généré.
-finalizerinfo

Imprime des informations sur les objets en attente de finalisation.
-heap

Imprime un résumé du tas de l'utilisation du garbage collector, de la configuration de la tête et de l'utilisation du tas par génération. De plus, le nombre et la taille des chaînes internées sont imprimés.
- histo[:live]

Imprime un histogramme du tas. Pour chaque classe Java, le nombre d'objets, la taille mémoire en octets et les noms de classe entièrement qualifiés sont imprimés. Les noms de classe internes à la JVM sont imprimés avec un préfixe astérisque (*). Si la sous-option live est spécifiée, seuls les objets actifs sont comptés.
-clstats

Imprime des statistiques par chargeur de classe du tas Java. Pour chaque chargeur de classe, son nom, son activité, son adresse, son chargeur de classe parent, ainsi que le nombre et la taille des classes qu'il a chargées sont imprimés.
-F

Forcer. Utilisez cette option avec l'option jmap -dump ou jmap -histo lorsque le pid ne répond pas. La sous-option live n'est pas supportée dans ce mode.
-h

Imprime un message d'aide.
-help

Imprime un message d'aide.
-Jindicateur

Passe indicateur à la machine virtuelle Java où la commande jmap s'exécute.
