Ne pas instantaner la copie de travail, et ne pas la mettre à jour

Par défaut, Jujutsu prend un instantané de la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous voulez éviter de prendre un instantané de la copie de travail et voir à la place un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile, par exemple, dans un invite de commande, surtout si vous avez un autre processus qui commit la copie de

travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-

cop
y`.

ble
Permettre la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit

racine.

Cette option n'affecte que la vérification. E

--at-operation <AT_OPERATIO
N>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y

en a.

Vous pouvez utiliser `--at-op=<operation ID>` pour voir à quoi ressemblait le dépôt à une opération antérieure. Par exemple, `jj --at-op=<operation ID> st` vous montrera ce que `jj st` aurait affiché lorsque l'opération donnée venait de se terminer. `--at-op=@` est presque identique à la valeur par défaut, sauf que les opérations divergentes ne seront jamais

fusionnées.

Utilisez `jj op log` pour trouver l'identifiant d'opération souhaité. N'importe quel préfixe non ambigu de l'identifiant d'opération

suffit.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été

spécifié.

Il est possible d'exécuter des commandes de mutation lors du chargement du dépôt à une opération antérieure. Cela revient à avoir exécuté des commandes concurrentes démarrant à l'opération antérieure. C'est rare jj-log(1) — Jujutsu

NAME

jj-log - View commit history

SYNOPSIS

jj log [OPTIONS] [REVSET]

DESCRIPTION

Shows the commit history. By default, it shows the history starting from the current commit. The history is displayed in reverse chronological order.

The output format is configurable via --config.

OPTIONS

--all
Show all commits, not just those reachable from the current commit.
-r, --reverse
Show commits in chronological order.
-T, --template <TEMPLATE>
Set the output format string. See TEMPLATE FORMAT for more details.
-g, --graph
Show the commit graph.
--no-graph
Do not show the commit graph. This is the default. It is impossible to have a graph of commits that are not displayed, so this option is silently ignored if any option implies commits that are not displayed. This includes listing commits by their id, revset, or tags.
--omit-missing
Omit commits that are missing from the displayed history.

DIFF FORMATTING OPTIONS

These options control the formatting of diffs shown in the log output. They are only applicable when the diff is shown.

--stat
Show statistics for each commit.
--no-stat
Do not show statistics for each commit.
--patch
Show the patch for each commit.
--no-patch
Do not show the patch for each commit. This is the default.
--unified <NUM>
Show NUM lines of context around each diff hunk.
--color-words <REGEX>
Color words matching the given regular expression.

GLOBAL OPTIONS

--debug
Enable debug logging.
--color <WHEN>
When to colorize output

[possible values: always, never, debug, auto]

--quiet
Silence non-primary command output

For example, `jj file list` will still list files, but it won't tell you if the working copy was snapshotted or if descendants were rebased.

Warnings and errors will still be printed.

--no-pager
Disable the pager.
--config <NAME=VALUE>
Additional configuration options (can be repeated)

The name should be specified as TOML dotted keys. The value should be specified as a TOML expression. If string value isn't enclosed by any TOML constructs (such as array notation), quotes can be omitted.

--config-file <PATH>
Additional configuration files (can be repeated).
