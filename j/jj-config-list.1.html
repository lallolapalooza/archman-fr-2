jj-config-list(1) Manuel des commandes générales jj-config-list(1)

NOM

jj-config-list - Liste les variables définies dans les fichiers de configuration, ainsi que leurs valeurs

SYNTAXE

jj config list [--include-defaults] [--include-overridden] [--user] [--repo] [--workspace] [-T|--template] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [NOM]

DESCRIPTION

Liste les variables définies dans les fichiers de configuration, ainsi que leurs valeurs

OPTIONS

--include-defaults
Indique s'il faut inclure explicitement les valeurs par défaut intégrées dans la liste.
--include-overridden
Permet d'imprimer les valeurs remplacées.
--user
Cible la configuration au niveau utilisateur.
--repo
Cible la configuration au niveau du dépôt.
--workspace
Cible la configuration au niveau de l'espace de travail.
-T, --template <TEMPLATE>
Affiche chaque variable à l'aide du modèle donné.

Les mots-clés suivants sont disponibles dans l'expression du modèle :

* `name: String`: Nom de la configuration. * `value: ConfigValue`: Valeur à formater en syntaxe TOML. * `overridden: Boolean`: Vrai si la valeur est masquée par d'autres. * `source: String`: Source de la valeur. * `path: String`: Chemin vers le fichier de configuration.

Peut être remplacé par le paramètre `templates.config_list`. Pour voir une liste détaillée de la configuration, utilisez le modèle `builtin_config_list_detailed`.

Voir [`jj help -k templates`] pour plus d'informations.

[`jj help -k templates`]:
https://docs.jj-vcs.dev/latest/templates/

-h, --help
Imprime l'aide (voir un résumé avec '-h').
[NOM]
Le nom optionnel d'une option de configuration spécifique à rechercher.

OPTIONS GLOBALES

-R, --repository <REPOSITORY>
Chemin vers le dépôt sur lequel opérer.

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas enregistrer l'instantané de la copie de travail et ne pas la mettre à jour.

Par défaut, Jujutsu enregistre l'instantané de la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande si celle-ci a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter d'enregistrer l'instantané de la copie de travail et voir plutôt un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile, par exemple, dans une invite de commande, surtout si un autre processus effectue des commits de la copie de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Permettre la réécriture des commits immuables.

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit, sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé `immutable` du modèle.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt.

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération souhaitée. Tout préfixe non ambigu de l'ID d'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Faire cela est équivalent à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage.
--color <WHEN>
Quand coloriser la sortie.

[valeurs possibles : always, never, debug, auto]

--quiet
Supprimer la sortie non principale de la commande.

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été enregistrée ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le pager.
--config <NAME=VALUE>
Options de configuration supplémentaires (peut être répété).

Le nom doit être spécifié sous forme de clés pointillées TOML. La valeur doit être spécifiée sous forme d'expression TOML. Si la valeur de chaîne n'est pas entourée de constructions TOML (comme la notation de tableau), les guillemets peuvent être omis.

--config-file <PATH>
Fichiers de configuration supplémentaires (peut être répété).
