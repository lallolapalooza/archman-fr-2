jj-file-chmod(1) Manuel des commandes générales jj-file-chmod(1)

NOM

jj-file-chmod - Définit ou supprime le bit exécutable pour les chemins dans le dépôt

SYNTAXE

jj file chmod [-r|--revision] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <MODE> <ENSEMBLES_FICHIERS>

DESCRIPTION

Définit ou supprime le bit exécutable pour les chemins dans le dépôt.

Contrairement à `chmod` POSIX, `jj file chmod` fonctionne également sous Windows, sur les fichiers en conflit et sur des révisions arbitraires.

OPTIONS

-r, --revision <ENSEMBLE_REV> [défaut: @]
La révision à mettre à jour.
-h, --help
Affiche l'aide (voir un résumé avec '-h').
<MODE>

Valeurs possibles :

  • n : Rendre un chemin non exécutable (alias : normal).
  • x : Rendre un chemin exécutable (alias : executable).
<ENSEMBLES_FICHIERS>
Chemins pour lesquels le bit exécutable doit être modifié.

OPTIONS GLOBALES

-R, --repository <DÉPÔT>
Chemin du dépôt sur lequel opérer.

Par défaut, Jujutsu recherche le répertoire `.jj/` le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas sauvegarder le répertoire de travail et ne pas le mettre à jour.

Par défaut, Jujutsu sauvegarde le répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande si celle-ci a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de sauvegarder le répertoire de travail et voir plutôt un commit de répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile, par exemple, dans une invite de commande, surtout si un autre processus commite le répertoire de travail.

Le chargement du dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture de commits immuables.

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble des commits immuables configurés. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit, sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <OPÉRATION_SPÉCIFIQUE>
Opération à laquelle charger le dépôt.

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID_OPÉRATION>` pour voir à quoi ressemblait le dépôt à une opération précédente. Par exemple, `jj --at-op=<ID_OPÉRATION> st` vous montrera ce que `jj st` aurait affiché lorsque l'opération donnée venait de se terminer. `--at-op=@` est quasiment identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération que vous souhaitez. N'importe quel préfixe non ambigu de l'ID d'opération suffit.

Lors du chargement du dépôt à une opération précédente, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutatives lors du chargement du dépôt à une opération précédente. Faire cela équivaut à avoir exécuté des commandes concurrentes partant de l'opération précédente. Il est rarement nécessaire de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage.
--color <QUAND>
Quand coloriser la sortie.

[valeurs possibles : always, never, debug, auto]

--quiet
Silencier la sortie non principale de la commande.

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si le répertoire de travail a été sauvegardé ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le paginateur.
--config <NOM=VALEUR>
Options de configuration supplémentaires (peuvent être répétées).

Le nom doit être spécifié sous forme de clés ponctuelles TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur chaîne n'est pas entourée de constructions TOML (comme la notation tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés).
chmod
