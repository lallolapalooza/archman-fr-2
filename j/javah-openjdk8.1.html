NOM

javah - Génère des fichiers d'en-tête et sources C à partir d'une classe Java.

SYNTAXE

javah [ options ] fnom-complet-de-classe ...
options
Les options de la ligne de commande. Voir Options.
nom-complet-de-classe
L'emplacement complet des classes à convertir en fichiers d'en-tête et sources C.

DESCRIPTION

La commande javah génère les fichiers d'en-tête et sources C nécessaires à l'implémentation des méthodes natives. Les fichiers d'en-tête et sources générés sont utilisés par les programmes C pour référencer les variables d'instance d'un objet depuis le code source natif. Le fichier .h contient une définition de struct dont la disposition correspond à celle de la classe correspondante. Les champs de la struct correspondent aux variables d'instance de la classe.

Le nom du fichier d'en-tête et la structure qu'il déclare sont dérivés du nom de la classe. Lorsque la classe passée à la commande javah fait partie d'un package, le nom du package est ajouté au début du nom du fichier d'en-tête et du nom de la structure. Les traits de soulignement (_) sont utilisés comme délimiteurs de noms.

Par défaut, la commande javah crée un fichier d'en-tête pour chaque classe répertoriée sur la ligne de commande et place les fichiers dans le répertoire courant. Utilisez l'option -stubs pour créer des fichiers sources. Utilisez l'option -o pour concaténer les résultats de toutes les classes répertoriées dans un seul fichier.

L'Interface Native Java (JNI) ne requiert pas d'informations d'en-tête ni de fichiers stubs. La commande javah peut toujours être utilisée pour générer les prototypes de fonctions de méthodes natives nécessaires aux méthodes natives de style JNI. La commande javah produit par défaut une sortie de style JNI et place le résultat dans le fichier .h.

OPTIONS

-o fichier_sortie

Concatène les fichiers d'en-tête ou sources résultants pour toutes les classes répertoriées sur la ligne de commande dans un fichier de sortie. Une seule des options -o ou -d peut être utilisée.
-d répertoire

Définit le répertoire où la commande javah enregistre les fichiers d'en-tête ou les fichiers stubs. Une seule des options -d ou -o peut être utilisée.
-stubs

Indique à la commande javah de générer des déclarations C à partir du fichier objet Java.
-verbose

Indique une sortie verbale et fait en sorte que la commande javah affiche un message sur stdout concernant l'état des fichiers générés.
-help

Affiche un message d'aide pour l'utilisation de javah.
-version

Affiche les informations de version de la commande javah.
-jni

Indique à la commande javah de créer un fichier de sortie contenant des prototypes de fonctions de méthodes natives de style JNI. C'est la sortie par défaut ; l'utilisation de -jni est facultative.
-classpath chemin

Spécifie le chemin que la commande javah utilise pour rechercher les classes. Remplace la valeur par défaut ou la variable d'environnement CLASSPATH lorsqu'elle est définie. Les répertoires sont séparés par des deux-points sur Oracle Solaris et des points-virgules sous Windows. Le format général du chemin est :

Oracle Solaris :

.:votre-chemin

Exemple : .:/home/avh/classes:/usr/local/java/classes

Windows :

.;votre-chemin

Exemple : .;C:\users\dac\classes;C:\tools\java\classes

Par souci de commodité, un élément de chemin de classe contenant un nom de base * est considéré comme équivalent à la spécification d'une liste de tous les fichiers du répertoire portant l'extension .jar ou .JAR.

Par exemple, si le répertoire mydir contient a.jar et b.JAR, alors l'élément de chemin de classe mydir/* est développé en A.jar:b.JAR, sauf que l'ordre des fichiers jar n'est pas spécifié. Tous les fichiers JAR du répertoire spécifié, y compris les fichiers cachés, sont inclus dans la liste. Une entrée de chemin de classe constituée de * est développée en une liste de tous les fichiers JAR du répertoire courant. La variable d'environnement CLASSPATH, lorsqu'elle est définie, est développée de la même manière. Tout développement de joker dans le chemin de classe se produit avant le démarrage de la Machine Virtuelle Java (JVM). Un programme Java ne verra jamais de jokers non développés, sauf en interrogeant l'environnement. Par exemple, en appelant System.getenv("CLASSPATH").

-bootclasspath chemin

Spécifie le chemin à partir duquel charger les classes bootstrap. Par défaut, les classes bootstrap sont les classes qui implémentent le cœur de la plateforme Java, situées dans jre\lib\rt.jar et plusieurs autres fichiers JAR.
-old

Indique que des fichiers d'en-tête de style ancien JDK 1.0 doivent être générés.
-force

Indique que les fichiers de sortie doivent toujours être écrits.
-Joption

Passe option à la Machine Virtuelle Java, où option est l'une des options décrites sur la page de référence du lanceur d'application Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).
