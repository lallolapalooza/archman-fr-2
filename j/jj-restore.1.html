jj-restore(1) Manuel des commandes générales jj-restore(1)

NOM

jj-restore - Restaure les chemins à partir d'une autre révision

SYNTAXE

jj restore [-f|--from] [-t|--into] [-c|--changes-in] [-i|--interactive] [--tool] [--restore-descendants] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [ENSEMBLES_DE_FICHIERS]

DESCRIPTION

Restaure les chemins à partir d'une autre révision

Cela signifie que les chemins obtiennent le même contenu dans la destination (`--into`) qu'ils avaient dans la source (`--from`). Ceci est typiquement utilisé pour annuler les modifications apportées à certains chemins dans la copie de travail (`jj restore <chemins>`).

Si seulement `--from` ou `--into` est spécifié, l'autre valeur prend par défaut la copie de travail.

Lorsque ni `--from` ni `--into` n'est spécifié, la commande restaure dans la copie de travail à partir de ses parents. `jj restore` sans arguments est similaire à `jj abandon`, sauf qu'il laisse une révision vide avec sa description et d'autres métadonnées préservées.

Voir `jj diffedit` si vous souhaitez restaurer des portions de fichiers plutôt que des fichiers entiers.

OPTIONS

-f, --from <ENSEMBLE_DE_RÉVISIONS>
Révision à partir de laquelle restaurer (source)
-t, --into <ENSEMBLE_DE_RÉVISIONS>
Révision dans laquelle restaurer (destination)
-c, --changes-in <ENSEMBLE_DE_RÉVISIONS>
Annuler les modifications dans une révision par rapport à la fusion de ses parents.

Cela annule les modifications visibles avec `jj diff -r ENSEMBLE_DE_RÉVISIONS`. Si `ENSEMBLE_DE_RÉVISIONS` n'a qu'un seul parent, cette option est équivalente à `jj restore --into ENSEMBLE_DE_RÉVISIONS --from ENSEMBLE_DE_RÉVISIONS-`.

Le comportement par défaut de `jj restore` est équivalent à `jj restore --changes-in @`.

-i, --interactive
Choisir interactivement quelles parties restaurer
--tool <NOM>
Spécifier l'éditeur de différences à utiliser (implique --interactive)
--restore-descendants
Préserver le contenu (pas le diff) lors du rebasage des descendants
-h, --help
Afficher l'aide (voir un résumé avec '-h')
[ENSEMBLES_DE_FICHIERS]
Restaure uniquement ces chemins (au lieu de tous les chemins)

OPTIONS GLOBALES

-R, --repository <RÉPERTOIRE>
Chemin du répertoire à traiter

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas enregistrer la copie de travail, et ne pas la mettre à jour

Par défaut, Jujutsu enregistre la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter d'enregistrer la copie de travail et voir à la place un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile, par exemple, dans une invite de commande, surtout si un autre processus commit la copie de travail.

Le chargement du dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture des commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit, sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé `immutable` du modèle.

--at-operation <OPERATION_SPECIFIQUE>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID_OPÉRATION>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID_OPÉRATION> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est pratiquement identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération souhaité. Tout préfixe non ambigu de l'ID d'opération est suffisant.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutatives lors du chargement du dépôt à une opération antérieure. Cela équivaut à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Silencer la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été enregistrée ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le pager
--config <NOM=VALEUR>
Options de configuration supplémentaires (peut être répété)

Le nom doit être spécifié sous forme de clés ponctuées TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur de chaîne n'est pas entourée de constructions TOML (comme la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peut être répété)
