JLINK(1) Commandes JDK JLINK(1)

NOM

jlink - assembler et optimiser un ensemble de modules et leurs dépendances en une image d'exécution personnalisée

SYNTAXE

jlink [options] --module-path chemin_modules --add-modules module [, module...]

options
Options de ligne de commande séparées par des espaces. Voir Options jlink.
chemin_modules
Le chemin où l'outil jlink découvre les modules observables. Ces modules peuvent être des fichiers JAR modulaires, des fichiers JMOD ou des modules décompressés.
module
Les noms des modules à ajouter à l'image d'exécution. L'outil jlink ajoute ces modules et leurs dépendances transitives.

DESCRIPTION

L'outil jlink lie un ensemble de modules, ainsi que leurs dépendances transitives, pour créer une image d'exécution personnalisée.

Note :

Les développeurs sont responsables de la mise à jour de leurs images d'exécution personnalisées.

OPTIONS JLINK

--add-modules mod [, mod...]
Ajoute les modules nommés, mod, à l'ensemble par défaut de modules racines. L'ensemble par défaut de modules racines est vide.
--bind-services
Lie les modules fournisseurs de services et leurs dépendances.
-c ={0|1|2} ou --compress={0|1|2}
Active la compression des ressources :
•
0 : Pas de compression
•
1 : Partage de chaînes constantes
•
2 : ZIP
--disable-plugin nom_plugin
Désactive le plug-in spécifié. Voir Plug-ins jlink pour la liste des plug-ins pris en charge.
--endian {little|big}
Spécifie l'ordre des octets de l'image générée. La valeur par défaut est le format de l'architecture de votre système.
-h ou --help
Affiche le message d'aide.
--ignore-signing-information
Supprime une erreur fatale lorsque des fichiers JAR modulaires signés sont liés dans l'image d'exécution. Les fichiers liés à la signature des fichiers JAR modulaires signés ne sont pas copiés dans l'image d'exécution.
--launcher commande=module ou --launcher commande=module/classe_principale
Spécifie le nom de la commande de lancement pour le module ou le nom de la commande pour le module et la classe principale (les noms du module et de la classe principale sont séparés par une barre oblique (/)).
--limit-modules mod [, mod...]
Limite l'univers des modules observables à ceux de la fermeture transitive des modules nommés, mod, plus le module principal, le cas échéant, plus tout autre module spécifié dans l'option --add-modules.
--list-plugins
Liste les plug-ins disponibles, auxquels vous pouvez accéder via des options de ligne de commande ; voir Plug-ins jlink.
-p ou --module-path chemin_modules
Spécifie le chemin des modules.

Si cette option n'est pas spécifiée, le chemin des modules par défaut est $JAVA_HOME/jmods. Ce répertoire contient le module java.base et les autres modules standard et JDK. Si cette option est spécifiée mais que le module java.base ne peut pas être résolu à partir de celui-ci, la commande jlink ajoute $JAVA_HOME/jmods au chemin des modules.

--no-header-files
Exclut les fichiers d'en-tête.
--no-man-pages
Exclut les pages de manuel.
--output chemin
Spécifie l'emplacement de l'image d'exécution générée.
--save-opts nom_fichier
Sauvegarde les options jlink dans le fichier spécifié.
--suggest-providers [nom, ...]
Suggère des fournisseurs qui implémentent les types de services donnés à partir du chemin des modules.
--version
Affiche les informations de version.
@nom_fichier
Lit les options à partir du fichier spécifié.

Un fichier d'options est un fichier texte contenant les options et les valeurs que vous entreriez généralement dans une invite de commande. Les options peuvent apparaître sur une seule ligne ou sur plusieurs lignes. Vous ne pouvez pas spécifier de variables d'environnement pour les noms de chemin. Vous pouvez commenter des lignes en plaçant un symbole dièse (#) au début de la ligne.

Voici un exemple de fichier d'options pour la commande jlink :


#Mer 07 déc. 00:40:19 EST 2016
--module-path mlib
--add-modules com.greetings
--output greetingsapp

PLUG-INS JLINK

Note :

Les plug-ins non répertoriés dans cette section ne sont pas pris en charge et sont sujets à modification.

Pour les options de plug-in qui nécessitent une liste_de_modèles, la valeur est une liste d'éléments séparés par des virgules, chaque élément utilisant l'une des formes suivantes :

•
modèle_glob
•
glob:modèle_glob
•
regex:modèle_regex
•
@nom_fichier
•
nom_fichier est le nom d'un fichier contenant les modèles à utiliser, un modèle par ligne.

Pour obtenir la liste complète de tous les plug-ins disponibles, exécutez la commande jlink --list-plugins.

    NOM

    jlink - jlink est un outil pour assembler et optimiser un ensemble de modules de runtime Java.

    SYNOPSIS

    jlink [options] --module-path modulepath --add-modules moduledeps ... [--output outputdir]

    DESCRIPTION

    L'outil jlink assemble un ensemble de modules Java, en créant une image runtime personnalisée. Cela permet de réduire la taille de l'application et le temps de démarrage.

    OPTIONS

    L'outil jlink accepte diverses options pour configurer la création de l'image runtime.

    OPTIONS DE JLINK

    • --module-path modulepath : Spécifie le chemin où rechercher les modules. Peut être une liste de répertoires séparés par des points-virgules.
    • --add-modules moduledeps : Spécifie les modules à inclure dans l'image runtime. Peut être une liste de noms de modules séparés par des virgules.
    • --output outputdir : Spécifie le répertoire de sortie où l'image runtime sera créée.
    • --compress level : Niveau de compression pour les ressources dans l'image runtime (0 pour aucune, 1 pour la compression standard, 2 pour la compression en utilisant `pack200`).
    • --strip-debug : Supprime les informations de débogage des classes.
    • --no-header-files : N'inclut pas les fichiers d'en-tête.
    • --no-man-pages : N'inclut pas les pages de manuel.
    • --include-locales locales : Inclut les ressources de localisation spécifiées.
    • --exclude-resources resourceglob : Exclut les ressources correspondant au modèle glob.

    PLUG-INS DE JLINK

    jlink prend en charge les plug-ins qui peuvent étendre ses fonctionnalités. Les plug-ins courants incluent ceux pour la compression, l'analyse de dépendances et la génération de documentation.

    EXEMPLES DE JLINK

    Pour créer une image runtime minimale contenant uniquement le module java.base et des modules spécifiés dans un répertoire mods, et la placer dans le répertoire output :

    jlink --module-path mods --add-modules java.base,com.example.myapp --output output
