DESCRIPTIO

N

La commande jdeps affiche les dépendances au niveau du paquet ou au niveau de la classe des fichiers de classe Java. La classe en entrée peut être un chemin vers un fichier .class, un répertoire, un fichier JAR, ou un nom de classe entièrement qualifié pour analyser tous les fichiers de classe. Les options déterminent la sortie. Par défaut, la commande jdeps écrit les dépendances sur la sortie système. La commande peut générer les dépendances en langage DOT (voir l'option -dotou

OPTIONS POUR FILTRER LES DÉPENDANCES

-p nom_paquet, -package nom_paquet, ou --package nom_paquet
Recherche les dépendances correspondant au nom de package spécifié. Vous pouvez spécifier cette option plusieurs fois pour différents packages. Les options -p et -e sont mutuellement exclusives.
-e regex, -regex regex, ou --regex regex
Recherche les dépendances correspondant au modèle spécifié. Les options -p et -e sont mutuellement exclusives.
--require nom_module
Recherche les dépendances correspondant au nom de module donné (peut être spécifié plusieurs fois). Les options --package, --regex, et --require sont mutuellement exclusives.
-f regex ou -filter regex
Filtre les dépendances correspondant au modèle donné. Si spécifié plusieurs fois, la dernière option sera sélectionnée.
-filter:package
Filtre les dépendances au sein du même package. C'est le comportement par défaut.
-filter:archive
Filtre les dépendances au sein de la même archive.
-filter:module
Filtre les dépendances au sein du même module.
-filter:none
Pas de filtrage -filter:package ni -filter:archive. Le filtrage spécifié via l'option -filter s'applique toujours.
--missing-deps
Recherche les dépendances manquantes. Cette option ne peut pas être utilisée avec les options -p, -e et -s.

OPTIONS POUR FILTRER LES CLASSES À ANALYSER

-include regex
Restreint l'analyse aux classes correspondant au modèle. Cette option filtre la liste des classes à analyser. Elle peut être utilisée avec -p et -e, qui appliquent le modèle aux dépendances.
-P ou -profile
Affiche le profil contenant un package.
-R ou --recursive
Parcourt récursivement toutes les dépendances d'exécution. L'option -R implique -filter:none. Si les options -p, -e, ou -f sont spécifiées, seules les dépendances correspondantes sont analysées.
--no-recursive
Ne pas parcourir récursivement les dépendances.
-I ou --inverse
Analyse les dépendances selon les autres options données, puis trouve tous les artefacts qui dépendent directement ou indirectement des nœuds correspondants. Ceci est équivalent à l'inverse de l'analyse de la vue compilation et du résumé d'impression des dépendances. Cette option doit être utilisée avec les options --require, --package, ou --regex.
--compile-time
Analyse la vue compilation des dépendances transitives, telle que la vue compilation de l'option -R. Analyse les dépendances selon les autres options spécifiées. Si une dépendance est trouvée à partir d'un répertoire, d'un fichier JAR ou d'un module, toutes les classes de l'archive contenant sont analysées.
