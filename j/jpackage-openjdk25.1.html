DESCRIPTIO

N

L'outil jpackage prend en entrée une application Java et une image d'exécution Java, et produit une image d'application Java incluant toutes les dépendances nécessaires. Il est capable de produire un paquet natif dans un format spécifique à la plateforme, tel qu

'un exe sous Windows ou un dmg sous macOS. Chaque format doit être construit sur la plateforme où il s'exécute, il n'y a pas de
support multiplateforme. L'outil dispose d'options permettant de personnaliser les applications empaquetées de diverses manières.

Ces options sont ajoutées, ou utilisées pour écraser, les options d'origine de la ligne de commande afin de construire un lanceur alternatif supplémentaire. Le lanceur principal de l'application sera built à partir des options de ligne de commande. Des lanceurs alternatifs supplémentaires peuvent être construits en utilisant cette option, et cette option peut être utilisée plusieurs fois pour construire plusieurs lanceurs supplémentaires.

--arguments arguments
Arguments de ligne de commande à passer à la classe principale si aucun argument de ligne de commande n'est donné au lanceur

Cette option peut être utilisée plusieurs fois.

La valeur peut contenir des sous-chaînes qui seront développées à l'exécution. Deux types de sous-chaînes sont pris en charge : les variables d'environnement et les jetons "APPDIR", "BINDIR" et "ROOTDIR".

Une sous-chaîne développable doit être enfermée entre le caractère dollar ($) et le premier caractère non alphanumérique suivant. Alternativement, elle peut être enfermée entre "${" et "}".

Les sous-chaînes développables sont sensibles à la casse sur Unix et insensibles à la casse sur Windows. Aucune expansion de chaîne ne se produit si la variable d'environnement référencée est indéfinie.

Les variables d'environnement nommées "APPDIR", "BINDIR" et "ROOTDIR" seront ignorées, et ces sous-chaînes développables seront remplacées par des valeurs calculées par le lanceur d'application.

Précéder le caractère dollar du caractère antislash (\) pour empêcher l'expansion des sous-chaînes.

--java-options options
Options à passer à l'environnement d'exécution Java

Cette option peut être utilisée plusieurs fois.

La valeur peut contenir des sous-chaînes qui seront substituées à l'exécution, comme pour l'option --arguments.

--main-class nom-classe
Nom qualifié de la classe principale de l'application à exécuter

Cette option ne peut être utilisée que si --main-jar est spécifié.

--main-jar jar-principal
Le JAR principal de l'application ; contenant la classe principale (spécifiée comme un chemin relatif au chemin d'entrée)

L'option --module ou --main-jar peut être spécifiée, mais pas les deux.

--module ou -m nom-module[/classe-principale]
Le module principal (et éventuellement la classe principale) de l'application

Ce module doit être situé sur le chemin du module.

Lorsque cette option est spécifiée, le module principal sera lié dans l'image d'exécution Java. L'option --module ou --main-jar peut être spécifiée, mais pas les deux.

EXEMPLES JPACKAGE

Génère un paquet d'application adapté au système hôte :

Pour une application modulaire :
    jpackage -n nom -p cheminModules -m nomModule/nomClasse
Pour une application non modulaire :
    jpackage -i répertoireEntrées -n nom \
        --main-class nomClasse --main-jar monJar.jar
À partir d'une image d'application pré-construite :
    jpackage -n nom --app-image répertoireImageApp

Génère une image d'application :

Pour une application modulaire :
    jpackage --type app-image -n nom -p cheminModules \
        -m nomModule/nomClasse
Pour une application non modulaire :
    jpackage --type app-image -i répertoireEntrées -n nom \
        --main-class nomClasse --main-jar monJar.jar
Pour fournir vos propres options à jlink, exécutez jlink séparément :
    jlink --output imageRuntimeApp -p cheminModules \
        --add-modules nomModule \
        --no-header-files [<options jlink supplémentaires>...]
    jpackage --type app-image -n nom \
        -m nomModule/nomClasse --runtime-image imageRuntimeApp

Génère un paquet d'exécution Java :

jpackage -n nom --runtime-image <image-runtime>

Signe l'image d'application prédéfinie (sous macOS) :

jpackage --type app-image --app-image <image-app> \
    --mac-sign [<options de signature supplémentaires>...]
Note : les seules options supplémentaires autorisées dans ce mode sont :
      l'ensemble des options de signature macOS supplémentaires et --verbose

JPACKAGE ET JLINK

jpackage utilisera jlink pour créer l'exécution Java, sauf si l'option --runtime-image est utilisée. L'image d'exécution Java créée sous Windows inclura les bibliothèques d'exécution Microsoft fournies avec le JDK. Si des bibliothèques d'exécution Microsoft d'une version différente sont nécessaires pour l'application, l'utilisateur devra les ajouter/remplacer lui-même.
