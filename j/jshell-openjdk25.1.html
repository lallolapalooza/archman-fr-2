JSHELL(1) Commandes JDK JSHELL(1)

NOM

jshell - évalue interactivement des déclarations, des instructions et des expressions du langage de programmation Java dans une boucle lire-évaluer-imprimer (REPL)

SYNTAXE

jshell [options] [fichiers-chargés]

options
Options de ligne de commande, séparées par des espaces. Voir Options pour jshell.
fichiers-chargés
Un ou plusieurs scripts à exécuter au démarrage de l'outil. Les scripts peuvent contenir tout extrait de code valide ou commandes JShell.

Le script peut être un fichier local ou l'un des scripts prédéfinis suivants :

DEFAULT
Charge les entrées par défaut, qui sont couramment utilisées comme imports.
JAVASE
Importe tous les paquets Java SE.
PRINTING
Définit print, println, et printf comme méthodes jshell à utiliser dans l'outil.
TOOLING
Définit javac, jar, et d'autres méthodes pour exécuter les outils JDK via leur interface de ligne de commande dans l'outil jshell.

Pour plus d'un script, utilisez un espace pour séparer les noms. Les scripts sont exécutés dans l'ordre où ils sont saisis sur la ligne de commande. Les scripts de ligne de commande sont exécutés après les scripts de démarrage. Pour exécuter un script après le démarrage de JShell, utilisez la commande /open.

Pour accepter l'entrée depuis l'entrée standard et supprimer les entrées/sorties interactives, entrez un tiret (-) pour fichiers-chargés. Cette option permet l'utilisation de l'outil jshell dans des chaînes de tuyaux.

DESCRIPTION

JShell offre un moyen d'évaluer interactivement des déclarations, des instructions et des expressions du langage de programmation Java, facilitant ainsi l'apprentissage du langage, l'exploration de code et d'API inconnus, et le prototypage de code complexe. Les instructions Java, les définitions de variables, les définitions de méthodes, les définitions de classes, les instructions d'importation et les expressions sont acceptées. Les éléments de code saisis sont appelés des snippets.

Au fur et à mesure que les snippets sont saisis, ils sont évalués et un retour d'information est fourni. Le retour d'information varie des résultats et explications des actions à rien, selon le snippet saisi et le mode de retour d'information choisi. Les erreurs sont décrites indépendamment du mode de retour d'information. Commencez avec le mode verbeux pour obtenir le maximum de retour d'information lors de l'apprentissage de l'outil.

Des options de ligne de commande sont disponibles pour configurer l'environnement initial au démarrage de JShell. Dans JShell, des commandes sont disponibles pour modifier l'environnement selon les besoins.

Les snippets existants peuvent être chargés à partir d'un fichier pour initialiser une session JShell, ou à tout moment au sein d'une session. Les snippets peuvent être modifiés au sein de la session pour tester différentes variations et apporter des corrections. Pour conserver les snippets pour une utilisation ultérieure, enregistrez-les dans un fichier.

OPTIONS POUR JSHELL

--add-exports module/package
Spécifie un paquet qui doit être considéré comme exporté par son module de définition.
--add-modules module[,module...]
Spécifie les modules racines à résoudre en plus du module initial.
-Cflag
transmet flag au compilateur Java interne à JShell. Par exemple, -C-Xlint active tous les avertissements de lint recommandés, et -C--release=<N> compile pour Java SE N, comme si --release N était spécifié.
--class-path chemin
Spécifie les répertoires et archives qui sont recherchés pour localiser les fichiers de classe. Cette option remplace le chemin dans la variable d'environnement CLASSPATH. Si la variable d'environnement n'est pas définie et que cette option n'est pas utilisée, le répertoire courant est recherché. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.
--enable-preview
Permet au code de dépendre des fonctionnalités d'aperçu de cette version.
--execution spécification
Spécifie un moteur d'exécution alternatif, où spécification est une spec ExecutionControl. Voir la documentation du paquet jdk.jshell.spi pour la syntaxe de la spec.
--feedback mode
Définit le niveau initial de retour d'information fourni en réponse à ce qui est saisi. Le niveau initial peut être remplacé dans une session en utilisant la commande /set feedback mode. La valeur par défaut est normal.

Les valeurs suivantes sont valides pour mode :

verbose
Fournit un retour d'information détaillé pour les entrées. Des informations supplémentaires sur l'action effectuée sont affichées après le résultat de l'action. La prochaine invite est séparée du retour d'information par une ligne vide.
normal
Fournit une quantité moyenne de retour d'information. La prochaine invite est séparée du retour d'information par une ligne vide.
concise
Fournit un retour d'information minimal. La prochaine invite suit immédiatement l'extrait de code ou le retour d'information.
silent
Ne fournit aucun retour d'information. La prochaine invite suit immédiatement l'extrait de code.
custom
Fournit un retour d'information personnalisé basé sur la définition du mode. Les modes de retour d'information personnalisés sont créés dans JShell en utilisant la commande /set mode.
--help ou -h ou -?
Affiche un résumé des options standard et quitte l'outil.
--help-extra ou -X
Affiche un résumé des options non standard et quitte l'outil. Les options non standard peuvent changer sans préavis.
-Jflag
transmet flag au système d'exécution, mais n'a aucun effet sur l'exécution des extraits de code. Pour spécifier des drapeaux qui affectent l'exécution des extraits de code, utilisez -Rflag. Alternativement, utilisez -Jflag avec --execution local.
--module-path chemin-modules
Spécifie où trouver les modules d'application. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.
--no-startup
Empêche l'exécution des scripts de démarrage au lancement de JShell. Utilisez cette option pour exécuter uniquement les scripts saisis sur la ligne de commande au démarrage de JShell, ou pour démarrer JShell sans aucune information préchargée si aucun script n'est saisi. Cette option ne peut pas être utilisée si l'option --startup est utilisée.
-q
Définit le mode de retour d'information sur concise, ce qui équivaut à saisir --feedback concise.
-Rflag
transmet flag au système d'exécution uniquement lors de l'exécution des extraits de code. Par exemple, -R-Dfoo=bar signifie que l'exécution de l'extrait System.getProperty(&

RACCOURCIS DE SAISIE

Les raccourcis suivants sont disponibles pour la saisie de commandes et d'extraits dans JShell.

Remplissage par tabulation

<tab>
Lors de la saisie d'extraits, de commandes, de sous-commandes, d'arguments de commande ou d'options de commande, utilisez la touche Tabulation pour compléter automatiquement l'élément. Si l'élément ne peut pas être déterminé à partir de ce qui a été saisi, des options possibles sont fournies.

Lors de la saisie d'un appel de méthode, utilisez la touche Tabulation après la parenthèse ouvrante de l'appel de méthode pour voir les paramètres de la méthode. Si la méthode a plus d'une signature, toutes les signatures sont affichées. Appuyer une deuxième fois sur la touche Tabulation affiche la description de la méthode et les paramètres de la première signature. Continuez d'appuyer sur la touche Tabulation pour obtenir une description de toute signature supplémentaire.

Maj+<Tab> V
Après avoir saisi une expression complète, utilisez cette séquence de touches pour convertir l'expression en une déclaration de variable d'un type déterminé par le type de l'expression.
Maj+<Tab> M
Après avoir saisi une expression ou une instruction complète, utilisez cette séquence de touches pour convertir l'expression ou l'instruction en une déclaration de méthode. Si une expression est saisie, le type de retour est basé sur le type de l'expression.
Maj+<Tab> I
Lorsqu'un identifiant est saisi et ne peut pas être résolu, utilisez cette séquence de touches pour afficher les importations possibles qui résolvent l'identifiant en fonction du contenu du chemin de classe spécifié.

Abréviations de commande

Une abréviation d'une commande est acceptée si l'abréviation identifie de manière unique une commande. Par exemple, /l est reconnu comme la commande /list. Cependant, /s n'est pas une abréviation valide car il n'est pas possible de déterminer si la commande /set ou /save est visée. Utilisez /se pour la commande /set ou /sa pour la commande /save .

Les abréviations sont également acceptées pour les sous-commandes, les arguments de commande et les options de commande. Par exemple, utilisez /m -a pour afficher toutes les méthodes.

Navigation dans l'historique

Un historique de ce qui a été saisi est maintenu entre les sessions. Utilisez les flèches haut et bas pour parcourir les commandes et les extraits des sessions actuelles et passées. Utilisez la touche Ctrl avec les flèches haut et bas pour sauter toutes les lignes sauf la première des extraits multilignes.

Recherche dans l'historique

Utilisez la combinaison de touches Ctrl+R pour rechercher dans l'historique la chaîne saisie. L'invite change pour afficher la chaîne et la correspondance. Ctrl+R recherche en arrière à partir de l'emplacement actuel dans l'historique, vers les entrées précédentes. Ctrl+S recherche en avant à partir de l'emplacement actuel dans l'historique, vers les entrées suivantes.

Les capacités d'édition de JShell sont similaires à celles des autres shells courants. Les touches du clavier et les combinaisons de touches fournissent des raccourcis d'édition de ligne. La touche Ctrl et la touche Meta sont utilisées dans les combinaisons de touches. Si votre clavier n'a pas de touche Meta, la touche Alt est souvent mappée pour fournir la fonctionnalité de la touche Meta.

JShell est fourni avec le JDK. Pour démarrer une session, tapez jshell sur la ligne de commande. Un message de bienvenue s'affiche, et une invite pour saisir des commandes et des extraits est fournie.

% jshell
|  Bienvenue dans JShell -- Version 9
|  Pour une introduction tapez : /help intro
jshell>

Pour voir quels extraits ont été automatiquement chargés au démarrage de JShell, utilisez la commande /list -start. Les extraits de démarrage par défaut sont des instructions d'importation pour les packages courants. L'ID de chaque extrait commence par la lettre s, ce qui indique qu'il s'agit d'un extrait de démarrage.

jshell> /list -start

jshell> /exit

EXEMPLE DE SAISIE D'EXTRAITS

Les extraits sont des instructions Java, des définitions de variables, des définitions de méthodes, des définitions de classes, des instructions d'importation et des expressions. Les points-virgules de terminaison sont automatiquement ajoutés à la fin d'un extrait complété s'ils sont manquants.

L'exemple suivant montre la définition de deux variables et d'une méthode, et l'exécution de la méthode. Notez qu'une variable temporaire est automatiquement créée pour contenir le résultat car aucune variable n'a été fournie.

jshell> int a=4
a ==> 4
jshell> int b=8
b ==> 8
jshell> int carre(int i1) {
   ...> return i1 * i1;
   ...> }
|  méthode carre(int) créée
jshell> carre(b)
$5 ==> 64

EXEMPLE DE MODIFICATION D'EXTRAITS

Modifiez la définition d'une variable, d'une méthode ou d'une classe en la saisissant à nouveau.

Les exemples suivants montrent la définition d'une méthode et son exécution :

jshell> String note(int scoreTest) {
   ...>     if (scoreTest >= 90) {
   ...>         return "Réussi";
   ...>     }
   ...>     return "Échoué";
   ...> }
|  méthode note(int) créée
jshell> note(88)
$3 ==> "Échoué"

Pour modifier la méthode note afin de permettre à plus d'élèves de réussir, saisissez à nouveau la définition de la méthode et changez le score de réussite à 80. Utilisez la flèche vers le haut pour récupérer les saisies précédentes afin d'éviter de les ressaisir et apportez la modification dans l'instruction if. L'exemple suivant montre la nouvelle définition et réexécute la méthode pour afficher le nouveau résultat :

jshell> String note(int scoreTest) {
   ...>     if (scoreTest >= 80) {
   ...>         return "Réussi";
   ...>     }
   ...>     return "Échoué";
   ...> }
|  méthode note(int) modifiée
jshell> note(88)
$5 ==> "Réussi"

Pour les extraits qui comportent plus de quelques lignes, ou pour effectuer plus que quelques modifications, utilisez la commande /edit pour ouvrir l'extrait dans un éditeur. Une fois les modifications terminées, fermez la fenêtre d'édition pour rendre le contrôle à la session JShell. L'exemple suivant montre la commande et le retour fourni lors de la fermeture de la fenêtre d'édition. La commande /list est utilisée pour montrer que le score de réussite a été modifié à 85.

jshell> /edit note
|  méthode note(int) modifiée
jshell> /list note
   6 : String note(int scoreTest) {
           if (scoreTest >= 85) {
               return "Réussi";
           }
           return "Échoué";
       }

Le mode de retour détermine l'invite qui est affichée, les messages de retour qui sont fournis lorsque des extraits sont saisis, et la longueur maximale d'une valeur affichée. Des modes de retour prédéfinis sont fournis. Des commandes pour créer des modes de retour personnalisés sont également fournies.

Utilisez la commande /set mode pour créer un nouveau mode de retour. Dans l'exemple suivant, le nouveau mode mymode est basé sur le mode de retour prédéfini normal, et la vérification des retours de commande est affichée :

jshell> /set mode mymode normal -command
|  Created new feedback mode: mymode

Étant donné que le nouveau mode est basé sur le mode normal, les invites sont les mêmes. L'exemple suivant montre comment voir quelles invites sont utilisées, puis modifie les invites en chaînes personnalisées. La première chaîne représente l'invite JShell standard. La seconde chaîne représente l'invite pour les lignes supplémentaires dans les extraits multilignes.

jshell> /set prompt mymode
|  /set prompt mymode "\njshell> " "   ...> "
jshell> /set prompt mymode "\nprompt$ " "   continue$ "

La longueur maximale d'une valeur affichée est contrôlée par le paramètre de troncature. Différents types de valeurs peuvent avoir des longueurs différentes. L'exemple suivant définit une valeur de troncature globale de 72, et une valeur de troncature de 500 pour les expressions de valeur de variable :

jshell> /set truncation mymode 72
jshell> /set truncation mymode 500 varvalue

Le retour affiché après la saisie des extraits est contrôlé par le paramètre de format et est basé sur le type d'extrait saisi et l'action effectuée pour cet extrait. Dans le mode prédéfini normal, la chaîne created est affichée lorsqu'une méthode est créée. L'exemple suivant montre comment modifier cette chaîne en defined :

jshell> /set format mymode action "defined" added-primary

Utilisez la commande /set feedback pour commencer à utiliser le mode de retour qui vient d'être créé. L'exemple suivant montre le mode personnalisé en cours d'utilisation :

jshell> /set feedback mymode
|  Feedback mode: mymode
prompt$ int square (int num1){
   continue$ return num1*num1;
   continue$ }
|  defined method square(int)
prompt$
