JMOD(1) Commandes JDK JMOD(1)

NOM

jmod - créer des fichiers JMOD et lister le contenu des fichiers JMOD existants

SYNTAXE

jmod (create|extract|list|describe|hash) [options] fichier-jmod

Inclut les éléments suivants :

Modes d'opération principaux

create
Crée un nouveau fichier archive JMOD.
extract
Extrait tous les fichiers du fichier archive JMOD.
list
Affiche les noms de toutes les entrées.
describe
Affiche les détails du module.
hash
Détermine les modules feuilles et enregistre les hachages des dépendances qui les nécessitent directement et indirectement.

Options

options
Voir Options pour jmod.

Obligatoire

fichier-jmod
Spécifie le nom du fichier JMOD à créer ou à partir duquel récupérer des informations.

DESCRIPTION

Note : Pour la plupart des tâches de développement, y compris le déploiement de modules sur le chemin des modules ou leur publication dans un dépôt Maven, continuez à empaqueter les modules dans des fichiers JAR modulaires. L'outil jmod est destiné aux modules qui ont des bibliothèques natives ou d'autres fichiers de configuration, ou aux modules que vous envisagez de lier, avec l'outil jlink, à une image d'exécution.

Le format de fichier JMOD vous permet d'agréger des fichiers autres que les fichiers .class, les métadonnées et les ressources. Ce format est transportable mais non exécutable, ce qui signifie que vous pouvez l'utiliser au moment de la compilation ou de la liaison, mais pas au moment de l'exécution.

De nombreuses options de jmod impliquent la spécification d'un chemin dont le contenu est copié dans les fichiers JMOD résultants. Ces options copient tout le contenu du chemin spécifié, y compris les sous-répertoires et leur contenu, mais excluent les fichiers dont les noms correspondent au modèle spécifié par l'option --exclude.

Avec l'option --hash-modules ou la commande jmod hash, vous pouvez, dans le descripteur de chaque module, enregistrer les hachages du contenu des modules autorisés à en dépendre, "liant" ainsi ces modules. Cela permet d'exporter un paquet vers un ou plusieurs modules nommés spécifiquement et aucun autre par le biais d'exportations qualifiées. L'exécution vérifie si le hachage enregistré d'un module correspond à celui résolu au moment de l'exécution ; sinon, l'exécution renvoie une erreur.

OPTIONS POUR JMOD

--class-path chemin
Spécifie l'emplacement des fichiers JAR d'application ou un répertoire contenant des classes à copier dans le fichier JMOD résultant.
--cmds chemin
Spécifie l'emplacement des commandes natives à copier dans le fichier JMOD résultant.
--compress compression
Spécifie la compression à utiliser lors de la création du fichier JMOD. Les valeurs acceptées sont zip-[0-9], où zip-0 ne fournit aucune compression et zip-9 fournit la meilleure compression. La valeur par défaut est zip-6.
--config chemin
Spécifie l'emplacement des fichiers de configuration modifiables par l'utilisateur à copier dans le fichier JMOD résultant.
--dateTIMESTAMP
L'horodatage au format ISO-8601 décalé étendu avec heure facultative, à utiliser pour l'horodatage des entrées, par exemple "2022-02-12T12:30:00-05:00".
--dir chemin
Spécifie l'emplacement où jmod place les fichiers extraits de l'archive JMOD spécifiée.
--dry-run
Exécute une simulation en mode hash. Il identifie les modules feuilles et leurs modules requis sans enregistrer de valeurs de hachage.
--exclude liste-de-modèles
Exclut les fichiers correspondant à la liste de modèles fournie, séparée par des virgules, chaque élément utilisant l'une des formes suivantes :
•
modèle-glob
•
glob:modèle-glob
•
regex:modèle-regex

Voir la méthode FileSystem.getPathMatcher pour la syntaxe de modèle-glob. Voir la classe Pattern pour la syntaxe de modèle-regex, qui représente une expression régulière.

--hash-modules modèle-regex
Détermine les modules feuilles et enregistre les hachages des dépendances qui les nécessitent directement et indirectement, en se basant sur le graphe de modules des modules correspondant au modèle-regex donné. Les hachages sont enregistrés dans le fichier archive JMOD en cours de création, ou dans un archive JMOD ou un JAR modulaire sur le chemin des modules spécifié par la commande jmod hash.
--header-files chemin
Spécifie l'emplacement des fichiers d'en-tête à copier dans le fichier JMOD résultant.
--help ou -h
Affiche un message d'utilisation.
--help-extra
Affiche l'aide pour les options supplémentaires.
--legal-notices chemin
Spécifie l'emplacement des avis légaux à copier dans le fichier JMOD résultant.
--libs chemin
Spécifie l'emplacement des bibliothèques natives à copier dans le fichier JMOD résultant.
--main-class nom-classe
Spécifie la classe principale à enregistrer dans le fichier module-info.class.
--man-pages chemin
Spécifie l'emplacement des pages man à copier dans le fichier JMOD résultant.
--module-version version-module
Spécifie la version du module à enregistrer dans le fichier module-info.class.
--module-path chemin ou -p chemin
Spécifie le chemin du module. Cette option est requise si vous spécifiez également --hash-modules.
--target-platform plateforme
Spécifie la plateforme cible.
--version
Affiche les informations de version de l'outil jmod.
@nom-fichier
Lit les options à partir du fichier spécifié.

Un fichier d'options est un fichier texte contenant les options et les valeurs que vous saisiriez normalement dans une invite de commande. Les options peuvent apparaître sur une seule ligne ou sur plusieurs. Vous ne pouvez pas spécifier de variables d'environnement pour les noms de chemin. Vous pouvez mettre en commentaire des lignes en faisant précéder le symbole dièse (#) du début de la ligne.

L'exemple suivant montre un fichier d'options pour la commande jmod :


#Mer 07 Déc 00:40:19 EST 2016
create --class-path mods/com.greetings --module-path mlib
  --cmds commands --config configfiles --header-files src/h
  --libs lib --main-class com.greetings.Main
  --man-pages man --module-version 1.0
  --os-arch "x86_x64" --os-name "macOS"
  --os-version "10.10.5" greetingsmod

OPTIONS SUPPLÉMENTAIRES POUR JMOD

En plus des options décrites dans Options pour jmod, les options suivantes sont des options supplémentaires qui peuvent être utilisées avec la commande.

--do-not-resolve-by-default
Exclure de l'ensemble racine par défaut des modules
--warn-if-resolved
Indication pour un outil d'émettre un avertissement si le module est résolu. L'une des valeurs suivantes : deprecated, deprecated-for-removal, ou incubating.

EXEMPLE DE CRÉATION JMOD

L'exemple suivant montre comment créer un fichier JMOD :


jmod create --class-path mods/com.greetings --cmds commands
  --config configfiles --header-files src/h --libs lib
  --main-class com.greetings.Main --man-pages man --module-version 1.0
  --os-arch "x86_x64" --os-name "macOS"
  --os-version "10.10.5" greetingsmod

Créez un fichier JMOD en spécifiant la date des entrées comme le 15 mars 2022 à 00h00m00s :


jmod create --class-path build/foo/classes --date 2022-03-15T00:00:00Z
   jmods/foo1.jmod

what happens when you try to link a leaf module (in this example, ma) with a required module (mb), and the hash value recorded in the required module doesn't match that of the leaf module.

1.
Create and compile the following .java files:
•
jmodhashex/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex/src/mb/module-info.java

module mb {
}
•
jmodhashex2/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex2/src/mb/module-info.java

module mb {
}
2.
Create a JMOD archive for each module. Create the directories jmodhashex/jmods and jmodhashex2/jmods, and then run the following commands from the jmodhashex directory, then from the jmodhashex2 directory:
•
jmod create --class-path mods/ma jmods/ma.jmod
•
jmod create --class-path mods/mb jmods/mb.jmod
3.
Optionally preview the jmod hash command. Run the following command from the jmodhashex directory:

jmod hash --dry-run -module-path jmods --hash-modules .*

The command prints the following:


Dry run:
mb
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a

This indicates that the jmod hash command (without the --dry-run option) will record the hash value of the leaf module ma in the module mb.

4.
Record hash values in the JMOD archive files contained in the jmodhashex directory. Run the following command from the jmodhashex directory:

jmod hash --module-path jmods --hash-modules .*

The command prints the following:

Hashes are recorded in module mb

5.
Print information about each JMOD archive contained in the jmodhashex directory. Run the highlighted commands from the jmodhashex directory:

jmod describe jmods/ma.jmod
ma
  requires mandated java.base
  requires mb
jmod describe jmods/mb.jmod
mb
  requires mandated java.base
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a
6.
Attempt to create a runtime image that contains the module ma from the directory jmodhashex2 but the module mb from the directory jmodhashex. Run the following command from the jmodhashex2 directory:
•
Linux and macOS:

jlink --module-path $JAVA_HOME/jmods:jmods/ma.jmod:../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

•
Windows:

jlink --module-path %JAVA_HOME%/jmods;jmods/ma.jmod;../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

The command prints an error message similar to the following:


Error: Hash of ma (a2d77889b0cb067df02a3abc39b01ac1151966157a68dc4241562c60499150d2) differs to
expected hash (07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a) recorded in mb
