JLINK(1) Commandes JDK JLINK(1)

NOM

jlink - assembler et optimiser un ensemble de modules et leurs dépendances en une image d'exécution personnalisée

SYNTAXE

jlink [options] --module-path cheminmodules --add-modules module[,module...]

options
Options de ligne de commande séparées par des espaces. Voir Options de jlink.
cheminmodules
Le chemin où l'outil jlink découvre les modules observables. Ces modules peuvent être des fichiers JAR modulaires, des fichiers JMOD ou des modules décompressés.
module
Les noms des modules à ajouter à l'image d'exécution. L'outil jlink ajoute ces modules et leurs dépendances transitives.

DESCRIPTION

L'outil jlink relie un ensemble de modules, ainsi que leurs dépendances transitives, pour créer une image d'exécution personnalisée.

Note :

Les développeurs sont responsables de la mise à jour de leurs images d'exécution personnalisées.

OPTIONS DE JLINK

--add-modules mod[,mod...]
Ajoute les modules nommés, mod, à l'ensemble par défaut de modules racines. L'ensemble par défaut de modules racines est vide.
--bind-services
Lie les modules fournisseurs de services et leurs dépendances.
-c ={0|1|2} ou --compress={0|1|2}
Active la compression des ressources :
•
0 : Pas de compression
•
1 : Partage de chaînes constantes
•
2 : ZIP
--disable-plugin nomplugin
Désactive le plug-in spécifié. Voir Plug-ins de jlink pour la liste des plug-ins pris en charge.
--endian {little|big}
Spécifie l'ordre des octets de l'image générée. La valeur par défaut est le format de l'architecture de votre système.
-h ou --help
Affiche le message d'aide.
--ignore-signing-information
Supprime une erreur fatale lors de la liaison de JAR modulaires signés dans l'image d'exécution. Les fichiers liés à la signature des JAR modulaires signés ne sont pas copiés dans l'image d'exécution.
--launcher commande=module ou --launcher commande=module/main
Spécifie le nom de la commande de lancement pour le module ou le nom de la commande pour le module et la classe principale (les noms du module et de la classe principale sont séparés par une barre oblique (/)).
--limit-modules mod[,mod...]
Limite l'univers des modules observables à ceux du noyau transitif des modules nommés, mod, plus le module principal, le cas échéant, plus tout module supplémentaire spécifié dans l'option --add-modules.
--list-plugins
Liste les plug-ins disponibles, auxquels vous pouvez accéder via les options de ligne de commande ; voir Plug-ins de jlink.
-p ou --module-path cheminmodules
Spécifie le chemin des modules.

Si cette option n'est pas spécifiée, le chemin des modules par défaut est $JAVA_HOME/jmods. Ce répertoire contient le module java.base et les autres modules standard et JDK. Si cette option est spécifiée mais que le module java.base ne peut pas y être résolu, la commande jlink ajoute $JAVA_HOME/jmods au chemin des modules.

--no-header-files
Exclut les fichiers d'en-tête.
--no-man-pages
Exclut les pages de manuel.
--output chemin
Spécifie l'emplacement de l'image d'exécution générée.
--save-opts nomfichier
Enregistre les options jlink dans le fichier spécifié.
--suggest-providers [nom, ...]
Suggère les fournisseurs qui implémentent les types de services donnés à partir du chemin des modules.
--version
Affiche les informations de version.
@nomfichier
Lit les options à partir du fichier spécifié.

Un fichier d'options est un fichier texte qui contient les options et les valeurs que vous saisiriez normalement dans une invite de commande. Les options peuvent apparaître sur une seule ligne ou sur plusieurs lignes. Vous ne pouvez pas spécifier de variables d'environnement pour les noms de chemin. Vous pouvez commenter des lignes en faisant précéder un symbole dièse (#) au début de la ligne.

Voici un exemple de fichier d'options pour la commande jlink :

#Mer 07 déc 00:40:19 EST 2016
--module-path mlib
--add-modules com.greetings
--output greetingsapp

PLUG-INS DE JLINK

Note :

Les plug-ins non listés dans cette section ne sont pas pris en charge et sont sujets à modification.

Pour les options de plug-in qui nécessitent une liste de modèles, la valeur est une liste d'éléments séparés par des virgules, chaque élément utilisant l'une des formes suivantes :

•
modèleglob
•
glob:modèleglob
•
regex:modèleregex
•
@nomfichier
•
nomfichier est le nom d'un fichier contenant les modèles à utiliser, un modèle par ligne.

Pour obtenir la liste complète de tous les plug-ins disponibles, exécutez la commande jlink --list-plugins.

Plug-in compress

Options
--compress={0|1|2}[:filter=liste_de_modèles]
Description
Compresse toutes les ressources de l'image de sortie.
•
Niveau 0 : Pas de compression
•
Niveau 1 : Partage de chaînes constantes
•
Niveau 2 : ZIP

Un filtre de liste de modèles optionnel peut être spécifié pour lister les modèles de fichiers à inclure.

Plug-in include-locales

Options
--include-locales=étiquette_langue[,étiquette_langue]*
Description
Inclut la liste des locales où étiquette_langue est une étiquette de langue BCP 47. Cette option prend en charge la correspondance des locales telle que définie dans le RFC 4647.
jlink(1) — Arch manual pages

NAME

jlink — Link modules and required packages into a custom runtime image

SYNOPSIS

jlink [options] --module-path modulepath --add-modules module

DESCRIPTION

The jlink command links a set of modules and their dependencies into a custom runtime image. A runtime image is a Java Virtual Machine (JVM) together with a specified set of modules. A custom runtime image contains only the modules that are required by an application, and thus reduces the size of the runtime image. This command is useful for deploying applications on platforms where a full JDK is not available or required.

JLINK OPTIONS

--module-path modulepath
A list of directories or archives containing modules. Separate directories and archives with the path separator character of the operating system. For example, on Unix, use colon (:) and on Windows, use semicolon (;).
--add-modules module,...
A list of root modules to add to the beginning of the module graph. Use this option to specify the modules that your application needs. If not specified, then the command attempts to resolve the module graph from the current directory.
--output output-dir
The directory where the runtime image is written.
--compress[=policy]
Enables compression of the runtime image. The compression policy can be one of the following:
0
No compression.
1
Compress resources using the ZIP file format.
2
Compress resources using the pack200/unpack200 scheme.
If no policy is specified, then the default is 1.
--include-locales locales
A comma-separated list of locales to include in the runtime image. If you use this option, then you must also add the module jdk.localedata when using this option.

Example:

--add-modules jdk.localedata --include-locales=en,ja,*-IN

JLINK PLUG-INS

Plugin order-resources

Options
--order-resources=pattern-list
Description
Orders the specified paths in priority order. If @filename is specified, then each line in pattern-list must be an exact match for the paths to be ordered.

Example:

--order-resources=/module-info.class,@classlist,/java.base/java/lang/

Plugin strip-debug

Options
--strip-debug
Description
Strips debug information from the output image.

Plugin generate-cds-archive

Options
--generate-cds-archive
Description
Generate CDS archive if the runtime image supports the CDS feature.

JLINK EXAMPLES

The following command creates a runtime image in the directory greetingsapp. This command links the module com.greetings, whose module definition is contained in the directory mlib.

jlink --module-path mlib --add-modules com.greetings --output greetingsapp

The following command lists the modules in the runtime image greetingsapp:

greetingsapp/bin/java --list-modules
com.greetings
java.base@11
java.logging@11
org.astro@1.0

The following command creates a runtime image in the directory compressedrt that's stripped of debug symbols, uses compression to reduce space, and includes French language locale information:

jlink --add-modules jdk.localedata --strip-debug --compress=2 --include-locales=fr --output compressedrt

The following example compares the size of the runtime image compressedrt with fr_rt, which isn't stripped of debug symbols and doesn't use compression:

jlink --add-modules jdk.localedata --include-locales=fr --output fr_rt
du -sh ./compressedrt ./fr_rt
23M     ./compressedrt
36M     ./fr_rt

The following example lists the providers that implement java.security.Provider:

jlink --suggest-providers java.security.Provider
Suggested providers:
  java.naming provides java.security.Provider used by java.base
  java.security.jgss provides java.security.Provider used by java.base
  java.security.sasl provides java.security.Provider used by java.base
  java.smartcardio provides java.security.Provider used by java.base
  java.xml.crypto provides java.security.Provider used by java.base
  jdk.crypto.cryptoki provides java.security.Provider used by java.base
  jdk.crypto.ec provides java.security.Provider used by java.base
  jdk.crypto.mscapi provides java.security.Provider used by java.base
  jdk.security.jgss provides java.security.Provider used by java.base

The following example creates a custom runtime image named mybuild that includes only java.naming and jdk.crypto.cryptoki and their dependencies but no other providers. Note that these dependencies must exist in the module path:

jlink --add-modules java.naming,jdk.crypto.cryptoki --output mybuild

The following command is similar to the one that creates a runtime image named greetingsapp, except that it will link the modules resolved from root modules with service binding; see the Configuration.resolveAndBind method.

jlink --module-path mlib --add-modules com.greetings --output greetingsapp --bind-services
