DESCRIPTIO

N

jshon analyse, lit et crée du JSON. Il est conçu pour être aussi utilisable que possible depuis le shell et remplace les analyseurs fragiles ad hoc construits avec grep/sed/awk ainsi que les analyseurs sur une ligne lourds construits avec

perl/python.

jshon charge le texte json depuis stdin, effectue des actions, puis affiche la dernière action sur stdout. Certaines options produisent du json, d'autres produisent des résumés en texte brut. Parce que Bash a des structures de données imbriquées très pauvres, jshon ne renvoie pas le JSON comme un objet natif comme le ferait une bibliothèque typique. Au lieu de cela jshon conserve un historique des modifications dans une

pile, et vous manipulez
l'élément JSON le plus haut.

S

{"a":1,"b":[true,false,null,"str"],"c":{"d":4,"e":5}}

Il existe plusieurs méta-options qui ne modifient pas directement le json. Appelez-les au plus une fois par

invocation.
-F
<chemin>
(file) lit depuis un fichier au lieu de stdin. La seule option non-manipulation qui prend un
argument.
-
P
(jsonp) supprime un rappel jsonp avant de continuer
normalement.
-
S
(sort) renvoie le json trié par clé, au lieu de l'ordre
original.
-
Q
(quiet) désactive le rapport d'erreurs sur stderr, afin que vous n'ayez pas à parsemer "2> /dev/null" dans votre
script.
-
V
(by-value) active le passage par valeur sur la pile d'historique de modification. Dans des cas extrêmes avec des milliers de valeurs profondément imbriquées, cela peut entraîner jshon s'exécutant plusieurs fois plus lentement tout en utilisant plusieurs fois plus de mémoire. Cependant, by-value est plus sûr que by-reference et provoque généralement moins de surprises. By-reference est activé par défaut parce qu'il n'y a pas de risque pendant les opérations en lecture seule et que cela rend généralement l'édition du json plus pratique.

jshon -e c -n 7 -i d -p -> c["d"] == 7
jshon -V -e c -n 7 -i d -p -> c["d"] == 5
jshon -V -e c -n 7 -i d -i c -> c["d"]

== 7

Avec -V , les modifications doivent être manuellement réinsérées à travers la pile

au lieu de simplement être retirées en
dépilement des valeurs intermédiaires.
-
C
(continue) sur des erreurs potentiellement récupérables. Par exemple, extraire des valeurs qui n'existent pas ajoutera 'null' à la pile de modification au lieu d'interrompre. Le comportement peut changer à
l'avenir.
-
I
(in-place) édition de fichier. Nécessite un fichier à modifier et ne fonctionne donc qu'avec -F. C'est destiné à faire de légères modifications à un fichier json. Lorsqu'il est utilisé, la sortie normale est supprimée et le bas de la pile de modification est
écrit.
-
0
(null delimiters) Change le délimiteur de -u d'un saut de ligne à un null. Cette option n'affecte que -u car c'est le seul moment où un saut de ligne peut légitimement apparaître dans la
sortie.

NAME

jshon — command line JSON processor

SYNOPSIS

jshon [options]

DESCRIPTION

The jshon utility is a command line JSON processor. It can be used to parse, query, and manipulate JSON data.

ACTIONS

The following actions can be chained together:

-a
output JSON array.
-c
output JSON object.
-e <key>
enter an object/array element.
-p
print (output) JSON.
-u
unwrap (output) plaintext.
-v
output JSON values.

Example:

jshon -e name -e first -u < data.json

will extract the value of the 'first' property from the 'name' object.

Arguments can be chained together. The following example gets the value of the 'foo' property of the object found in the 'bar' property of the root object.

jshon -e bar -e foo -u < data.json

If the value is an array, you may want to print each element individually. To do so, you can use the -a flag before printing. The following example prints each element of the 'names' array individually:

jshon -e names -a -u < data.json

If the value is an object, you may want to print each value individually. To do so, you can use the -c flag before printing. The following example prints each value of the 'address' object individually:

jshon -e address -c -u < data.json

NON-MANIPULATION

The following options do not manipulate the JSON structure.

-l
output JSON on one line.
-S
output JSON sorted by keys.
-s
output JSON pretty-printed.
-r
output JSON pretty-printed raw.

The '-s' option will pretty-print the JSON to standard output. The '-r' option will pretty-print the JSON to standard output, but it will not escape characters.

OTHER TOOLS

Sometimes JSON is output line by line. This can be useful for piping data into jshon, but it is not valid JSON. The following example converts it into a valid JSON array:

jshon -a -u < <(cat data.json | sed -e 's/^/{/' -e 's/$/}/')

Or, if each line is a separate JSON object:

jshon ... | sed 's/^$/-/' | paste -s -d '\t\t\n'

This replaces blanks with '-' and merges every three lines into one.

Columns can also be extracted with a while loop, and conveniently loaded into variables at the same time:

while {
read -r var1
read -r var2
read -r var3
}; do [thing with vars]
done < <(jshon ...)

If you are using 'read' with -0, be aware that read (bash built in) does not follow IFS. Instead use

read -r -d $'\0' var1

There are more and more tools that produce json output. Often these use a line-oriented json/plaintext hybrid where each line is an independent json structure. Sadly this means the output as a whole is not legitimate json. Either loop though the data line by line (calling jshon once for each line) or convert it to a legitimate json array. For example:

while read line; do jshon <<< "$line"; done < <(journalctl -o json)

journalctl -o json | sed -e '1i[' -e '$!s/$/,/' -e '$a]' | jshon

GOLF

If you care about extremely short one liners, arguments can be condensed when it does not cause ambiguity. The example from -p(op) can be golfed as follows:

jshon -e c -e d -u -p -e e -u == jshon -ec -ed -upee -u

I do not recommend doing this (it makes things much harder to understand) but some people golf despite the consequences.
