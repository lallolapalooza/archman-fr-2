NOM

jj-git-push - Pousser vers un dépôt distant Git

SYNOPSIS

jj git push [--remote] [-b|--bookmark] [--all] [--tracked] [--deleted] [--allow-empty-description] [--allow-private] [-r|--revisions] [-c|--change] [--named] [--dry-run] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPTION

Pousse vers un dépôt distant Git

Par défaut, pousse les signets suivis pointant vers `remote_bookmarks(remote=<remote>)..@`. Utilisez `--bookmark` pour pousser des signets spécifiques. Utilisez `--all` pour pousser tous les signets. Utilisez `--change` pour générer des noms de signets basés sur les identifiants de modification de commits spécifiques.

Contrairement à Git, le dépôt distant vers lequel pousser n'est pas dérivé des signets de dépôt suivis. Utilisez `--remote` pour sélectionner le dépôt Git distant par son nom. Il n'y a pas d'option pour pousser vers plusieurs dépôts distants.

Avant que la commande ne déplace, crée ou supprime un signet distant, elle effectue plusieurs [vérifications de sécurité]. En cas de problème, vous devrez peut-être exécuter `jj git fetch --remote <nom du dépôt distant>` et/ou résoudre certains [conflits de signets].

[vérifications de sécurité]: https://docs.jj-vcs.dev/latest/bookmarks/#pushing-bookmarks-safety-checks

[conflits de signets]: https://docs.jj-vcs.dev/latest/bookmarks/#conflicts

OPTIONS

--remote <REMOTE>
Le dépôt distant vers lequel pousser (seuls les dépôts distants nommés sont pris en charge)

Ceci est défini par défaut par le paramètre `git.push`. S'il n'est pas configuré et s'il existe plusieurs dépôts distants, le dépôt nommé « origin » sera utilisé.

-b, --bookmark <BOOKMARK>
Pousse uniquement ce signet, ou les signets correspondant à un motif (peut être répété)

Par défaut, le nom spécifié correspond exactement. Utilisez le préfixe `glob:` pour sélectionner les signets par [motif générique].

[motif générique]: https://docs.jj-vcs.dev/latest/revsets#string-patterns

--all
Pousse tous les signets (y compris les nouveaux signets)
--tracked
Pousse tous les signets suivis

Cela signifie généralement que le signet a déjà été poussé ou récupéré depuis le [dépôt distant pertinent].

[dépôt distant pertinent]: https://docs.jj-vcs.dev/latest/bookmarks#remotes-and-tracked-bookmarks

--deleted
Pousse tous les signets supprimés

Seuls les signets suivis peuvent être supprimés avec succès sur le dépôt distant. Un avertissement sera affiché si des signets distants non suivis correspondent à des signets locaux manquants.

--allow-empty-description
Autorise la poussée de commits avec des descriptions vides
--allow-private
Autorise la poussée de commits privés

L'ensemble des commits privés peut être configuré par le paramètre `git.private-commits`. La valeur par défaut est `none()`, ce qui signifie que tous les commits sont éligibles pour être poussés.

-r, --revisions <REVSETS>
Pousse les signets pointant vers ces commits (peut être répété)
-c, --change <REVSETS>
Pousse ce commit en créant un signet (peut être répété)

Le signet créé sera automatiquement suivi. Utilisez le paramètre `templates.git_push_bookmark` pour personnaliser le nom du signet généré. Par défaut, c'est `"push-" ++ change_id.short()`.

--named <NOM=RÉVISION>
Spécifie un nouveau nom de signet et une révision à pousser sous ce nom, par exemple « --named monfeature=@ »

Suit automatiquement le signet s'il est nouveau.

--dry-run
Affiche uniquement ce qui va changer sur le dépôt distant
-h, --help
Affiche l'aide (voir un résumé avec '-h')

OPTIONS GLOBALES

-R, --repository <RÉPOSITORIE>
Chemin vers le dépôt à opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas enregistrer la copie de travail, et ne pas la mettre à jour

Par défaut, Jujutsu enregistre la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter d'enregistrer la copie de travail et voir un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile par exemple dans une invite de commande, surtout si vous avez un autre processus qui enregistre la copie de travail.

Le chargement du dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autorise la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est pratiquement identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération souhaité. Toute préfixe non ambigu de l'ID d'opération suffit.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Cela équivaut à avoir exécuté des commandes concurrentes à partir de l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Active la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Silencie la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été enregistrée ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactive le pager
