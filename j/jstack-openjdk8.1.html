jstack(1) Outils de dépannage jstack(1)

NOM

jstack - Affiche les traces de pile des threads Java pour un processus Java, un fichier core, ou un serveur de débogage distant. Cette commande est expérimentale et non prise en charge.

SYNOPSIS

jstack [ options ] pid 
jstack [ options ] executable core
jstack [ options ] [ server-id@ ] nom_hote_distant_ou_IP
options
Les options de ligne de commande. Voir Options.
pid
L'identifiant du processus pour lequel la trace de pile est affichée. Le processus doit être un processus Java. Pour obtenir une liste des processus Java en cours d'exécution sur une machine, utilisez la commande jps(1).
executable
L'exécutable Java à partir duquel le vidage du noyau a été produit.
core
Le fichier core pour lequel la trace de pile doit être affichée.
nom_hote_distant_ou_IP
Le serveur de débogage distant nom d'hôte ou adresse IP. Voir jsadebugd(1).
server-id
Un identifiant unique facultatif à utiliser lorsque plusieurs serveurs de débogage sont en cours d'exécution sur le même hôte distant.

DESCRIPTION

La commande jstack affiche les traces de pile Java des threads Java pour un processus Java, un fichier core ou un serveur de débogage distant spécifié. Pour chaque frame Java, le nom complet de la classe, le nom de la méthode, l'index de code binaire (BCI) et le numéro de ligne, lorsqu'ils sont disponibles, sont affichés. Avec l'option -m, la commande jstack affiche les frames Java et natifs de tous les threads avec le compteur de programme (PC). Pour chaque frame natif, le symbole natif le plus proche du PC, lorsqu'il est disponible, est affiché. Les noms C++ renommés ne sont pas démanglés. Pour démangler les noms C++, la sortie de cette commande peut être redirigée vers c++filt. Lorsque le processus spécifié est en cours d'exécution sur une machine virtuelle Java 64 bits, vous pourriez avoir besoin de spécifier l'option -J-d64, par exemple : jstack -J-d64 -m pid.

Remarque : cet utilitaire n'est pas pris en charge et pourrait ne pas être disponible dans les futures versions du JDK. Sur les systèmes Windows où le fichier dbgeng.dll est absent, Debugging Tools For Windows doit être installé pour que ces outils fonctionnent. La variable d'environnement PATH doit contenir l'emplacement du jvm.dll utilisé par le processus cible, ou l'emplacement à partir duquel le fichier de vidage de crash a été produit. Par exemple :

set PATH=<jdk>\jre\bin\client;%PATH%

OPTIONS

-F

Force un vidage de pile lorsque jstack [-l] pid ne répond pas.
-l

Liste longue. Affiche des informations supplémentaires sur les verrous, telles qu'une liste des synchroniseurs possédé par java.util.concurrent. Voir la description de la classe AbstractOwnableSynchronizer à http://docs.oracle.com/javase/8/docs/api/java/util/concurrent/locks/AbstractOwnableSynchronizer.html
-m

Affiche une trace de pile en mode mixte contenant des frames Java et C/C++ natifs.
-h

Affiche un message d'aide.
-help

Affiche un message d'aide.

BOGUES CONNUS

En mode trace de pile mixte, l'option -m ne fonctionne pas avec le serveur de débogage distant.
