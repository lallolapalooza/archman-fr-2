jj-git-clone(1) Manuel des commandes générales jj-git-clone(1)

NOM

jj-git-clone - Crée un nouveau dépôt sauvegardé par un clone d'un dépôt Git

SYNTAXE

jj git clone [--remote] [--colocate] [--no-colocate] [--depth] [--fetch-tags] [-b|--branch] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <SOURCE> [DESTINATION]

DESCRIPTION

Crée un nouveau dépôt sauvegardé par un clone d'un dépôt Git

OPTIONS

--remote <NOM_DU_DISTANT> [défaut: origin]
Nom du distant nouvellement créé
--colocate
Colocaliser le dépôt Jujutsu avec le dépôt git

Spécifie que le dépôt `jj` doit également être un dépôt `git` valide, permettant l'utilisation des commandes `jj` et `git` dans le même répertoire.

Le dépôt contiendra un répertoire `.git` au niveau supérieur. Les outils Git réguliers pourront opérer sur le dépôt.

**C'est le comportement par défaut**, et cette option n'a aucun effet, sauf si la configuration [git.colocate] est définie à `false`.

[configuration git.colocate]: https://docs.jj-vcs.dev/latest/config/#default-colocation

--no-colocate
Désactiver la colocalisation du dépôt Jujutsu avec le dépôt git

Empêche les outils Git qui ne sont pas conscients de `jj` et les commandes Git régulières d'opérer sur le dépôt. Le dépôt Git qui stocke la plupart des données du dépôt sera caché à l'intérieur d'un sous-répertoire du répertoire `.jj`.

Voir la [documentation sur la colocalisation] pour quelques avantages mineurs des espaces de travail non colocalisés.

[documentation sur la colocalisation]: https://docs.jj-vcs.dev/latest/git-compatibility/#colocated-jujutsugit-repos

--depth <PROFONDEUR>
Crée un clone superficiel de la profondeur donnée
--fetch-tags <FETCH_TAGS>
Configure quand récupérer les tags

Sauf indication contraire, le clone initial récupérera tous les tags, tandis que toutes les récupérations ultérieures ne récupéreront que les tags inclus.

Valeurs possibles :

  • all: Récupérer toujours tous les tags
  • included: Ne récupérer que les tags qui pointent vers des objets déjà en cours de transmission
  • none: Ne récupérer aucun tag
-b, --branch <BRANCHE>
Nom de la branche à récupérer et à utiliser comme parent du changement de la copie de travail

Si absent, toutes les branches sont récupérées et la branche par défaut du dépôt est utilisée comme parent du changement de la copie de travail.

Par défaut, le nom spécifié correspond exactement. Utilisez le préfixe `glob:` pour développer `*` comme un motif glob, par exemple `--branch 'glob:push-*'`. D'autres caractères de remplacement tels que `?` ne sont *pas* pris en charge. Peut être répété pour spécifier plusieurs branches, auquel cas le premier nom de branche exact est utilisé comme parent de la copie de travail.

-h, --help
Imprimer l'aide (voir un résumé avec '-h')
<SOURCE>
URL ou chemin du dépôt Git à cloner

Le chemin local sera résolu en forme absolue.

[DESTINATION]
Spécifie le répertoire cible pour le clone du dépôt Jujutsu. S'il n'est pas fourni, utilise par défaut un répertoire nommé d'après le dernier composant de l'URL source. Le chemin complet du répertoire sera créé s'il n'existe pas.

OPTIONS GLOBALES

-R, --repository <DEPOT>
Chemin vers le dépôt sur lequel opérer

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané de la copie de travail, et ne pas la mettre à jour

Par défaut, Jujutsu prend un instantané de la copie de travail au début de chaque commande. La copie de travail est également mise à jour à la fin de la commande, si la commande a modifié le commit de la copie de travail (`@`). Si vous souhaitez éviter de prendre un instantané de la copie de travail et voir plutôt un commit de copie de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile, par exemple, dans une invite de commande, surtout si un autre processus s'occupe de commiter la copie de travail.

Charger le dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture de commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt lors d'une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID d'opération que vous souhaitez. N'importe quel préfixe non ambigu de l'ID d'opération suffit.

Lors du chargement du dépôt à une opération antérieure, la copie de travail sera ignorée, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Faire cela équivaut à avoir exécuté des commandes concurrentes commençant à l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Réduire au silence la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si la copie de travail a été mise en instantané ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours imprimés.

--no-pager
Désactiver le paginator
--config <NOM=VALEUR>
Options de configuration supplémentaires (peut être répété)

Le nom doit être spécifié comme des clés pointées TOML. La valeur doit être spécifiée comme une expression TOML. Si la valeur de chaîne n'est pas entourée de constructions TOML (telles que la notation de tableau), les guillemets peuvent être omis.

--config-file <CHEMIN>
Fichiers de configuration supplémentaires (peuvent être répétés)
