jj-evolog(1) Manuel des commandes générales jj-evolog(1)

NOM

jj-evolog - Montrer comment une modification a évolué au fil du temps

SYNTAXE

jj evolog [-r|--revisions] [-n|--limit] [--reversed] [-G|--no-graph] [-T|--template] [-p|--patch] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [--ignore-all-space] [--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPTION

Montrer comment une modification a évolué au fil du temps

Liste les commits précédents auxquels une modification a pointé. Le commit actuel d'une modification évolue lorsque la modification est mise à jour, rebasée, etc.

OPTIONS

-r, --revisions <ENSEMBLES_REV> [défaut : @]
Suivre les modifications à partir de ces révisions
-n, --limit <LIMITE>
Limiter le nombre de révisions à afficher

Appliqué après que les révisions ont été triées topologiquement, mais avant d'être inversées.

--reversed
Afficher les révisions dans l'ordre inverse (anciennes révisions d'abord)
-G, --no-graph
Ne pas afficher le graphe, afficher une liste plate de révisions
-T, --template <MODELE>
Rendre chaque révision en utilisant le modèle donné

Toutes les méthodes sans argument du type [`CommitEvolutionEntry`] sont disponibles comme mots-clés dans l'expression du modèle. Voir [`jj help -k templates`] pour plus d'informations.

Si non spécifié, cela utilise par défaut le paramètre `templates.evolog`.

[`CommitEvolutionEntry` type]: https://docs.jj-vcs.dev/latest/templates/#commitevolutionentry-type

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-p, --patch
Afficher le patch par rapport à la version précédente de cette modification

Si la version précédente a des parents différents, elle sera temporairement rebasée sur les parents de la nouvelle version, de sorte que la différence ne soit pas contaminée par des modifications non liées.

-h, --help
Imprimer l'aide (voir un résumé avec '-h')

OPTIONS DE MISE EN FORME DES DIFFÉRENCES

-s, --summary
Pour chaque chemin, afficher seulement s'il a été modifié, ajouté ou supprimé
--stat
Afficher un histogramme des modifications
--types
Pour chaque chemin, afficher seulement son type avant et après

La différence est affichée sous forme de deux lettres. La première lettre indique le type avant et la seconde lettre indique le type après. '-' indique que le chemin n'était pas présent, 'F' représente un fichier normal, `L' représente un lien symbolique, 'C' représente un conflit et 'G' représente un sous-module Git.

--name-only
Pour chaque chemin, afficher seulement son chemin

Généralement utile pour les commandes shell comme : `jj diff -r @- --name-only | xargs perl -pi -e's/ANCIEN/NOUVEAU/g`

--git
Afficher une différence au format Git
--color-words
Afficher une différence au niveau des mots avec les modifications indiquées uniquement par la couleur
--tool <OUTIL>
Générer la différence par une commande externe

Un format intégré peut également être spécifié comme `:<nom>`. Par exemple, `--tool=:git` équivaut à `--git`.

--context <CONTEXTE>
Nombre de lignes de contexte à afficher
--ignore-all-space
Ignorer les espaces lors de la comparaison des lignes
--ignore-space-change
Ignorer les changements dans la quantité d'espaces lors de la comparaison des lignes

OPTIONS GLOBALES

-R, --repository <RÉPERTOIRE>
Chemin vers le répertoire sur lequel opérer

Par défaut, Jujutsu recherche le répertoire `.jj/` le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané du répertoire de travail, et ne pas le mettre à jour

Par défaut, Jujutsu prend un instantané du répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de prendre un instantané du répertoire de travail et voir plutôt un commit du répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Cela peut être utile par exemple dans une invite de commande, surtout si un autre processus commit le répertoire de travail.

Charger le répertoire à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture de commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré des commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID_OPÉRATION>` pour voir à quoi ressemblait le dépôt à une opération antérieure. Par exemple `jj --at-op=<ID_OPÉRATION> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près la même chose que par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération que vous voulez. N'importe quel préfixe non ambigu de l'ID de l'opération suffit.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Le faire est équivalent à avoir exécuté des commandes concurrentes commençant à l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <QUAND>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Réduire au silence la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si le répertoire de travail a été snapshoté ou si les descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le paginator
--config <NOM=VALEUR>
Options de configuration supplémentaires (peut être répété)

Le nom doit être spécifié sous forme de k pointillé TOML

s. La valeur doit être spécifiée sous forme d'expression TOML. Si la valeur de chaîne n'est entourée par aucune construction TOML (comme la notation de tableau), les guillemets peuvent être omis.
