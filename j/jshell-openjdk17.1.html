JSHELL(1) Commandes JDK JSHELL(1)

NOM

jshell - évalue interactivement des déclarations, des instructions et des expressions du langage de programmation Java dans une boucle lire-évaluer-imprimer (REPL)

SYNTAXE

jshell [options] [fichiers-chargés]

options
Options de ligne de commande, séparées par des espaces. Voir Options pour jshell.
fichiers-chargés
Un ou plusieurs scripts à exécuter au démarrage de l'outil. Les scripts peuvent contenir tout extrait de code ou commande JShell valide.

Le script peut être un fichier local ou l'un des scripts prédéfinis suivants :

DÉFAUT
Charge les entrées par défaut, couramment utilisées comme imports.
JAVASE
Importe tous les packages Java SE.
IMPRESSION
Définit print, println et printf comme méthodes jshell à utiliser dans l'outil.

Pour plus d'un script, utilisez un espace pour séparer les noms. Les scripts sont exécutés dans l'ordre où ils sont saisis sur la ligne de commande. Les scripts de ligne de commande sont exécutés après les scripts de démarrage. Pour exécuter un script après le démarrage de JShell, utilisez la commande /open.

Pour accepter l'entrée de l'entrée standard et supprimer l'E/S interactive, entrez un trait d'union (-) pour fichiers-chargés. Cette option permet d'utiliser l'outil jshell dans des chaînes de pipes.

DESCRIPTION

JShell offre un moyen d'évaluer interactivement des déclarations, des instructions et des expressions du langage de programmation Java, ce qui facilite l'apprentissage du langage, l'exploration de code et d'API inconnus, et le prototypage de code complexe. Les instructions Java, les définitions de variables, les définitions de méthodes, les définitions de classes, les instructions d'importation et les expressions sont acceptées. Les fragments de code saisis sont appelés des snippets.

Au fur et à mesure que les snippets sont saisis, ils sont évalués et un retour d'information est fourni. Ce retour d'information varie des résultats et des explications des actions à rien, selon le snippet saisi et le mode de retour d'information choisi. Les erreurs sont décrites quel que soit le mode de retour d'information. Commencez avec le mode verbeux pour obtenir le maximum de retour d'information lors de l'apprentissage de l'outil.

Des options de ligne de commande sont disponibles pour configurer l'environnement initial au démarrage de JShell. Au sein de JShell, des commandes sont disponibles pour modifier l'environnement selon les besoins.

Les snippets existants peuvent être chargés à partir d'un fichier pour initialiser une session JShell, ou à tout moment au cours d'une session. Les snippets peuvent être modifiés pendant la session pour essayer différentes variations et apporter des corrections. Pour conserver les snippets pour une utilisation ultérieure, enregistrez-les dans un fichier.

OPTIONS POUR JSHELL

--add-exports module/paquet
Spécifie un paquet à considérer comme exporté par son module de définition.
--add-modules module[,module...]
Spécifie les modules racines à résoudre en plus du module initial.
-Cindicateur
Fournit un indicateur à passer au compilateur. Pour passer plus d'un indicateur, fournissez une instance de cette option pour chaque indicateur ou argument d'indicateur nécessaire.
--class-path chemin
Spécifie les répertoires et archives dans lesquels chercher les fichiers de classe. Cette option remplace le chemin dans la variable d'environnement CLASSPATH. Si la variable d'environnement n'est pas définie et que cette option n'est pas utilisée, le répertoire courant est recherché. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.
--enable-preview
Permet au code de dépendre des fonctionnalités d'aperçu de cette version.
--execution spécification
Spécifie un moteur d'exécution alternatif, où spécification est une spécification ExecutionControl. Voir la documentation du package jdk.jshell.spi pour la syntaxe de la spécification.
--feedback mode
Définit le niveau initial de retour d'information fourni en réponse à ce qui est saisi. Le niveau initial peut être remplacé dans une session en utilisant la commande /set feedback mode. La valeur par défaut est normal.

Les valeurs suivantes sont valides pour mode :

verbose
Fournit un retour d'information détaillé pour les entrées. Des informations supplémentaires sur l'action effectuée sont affichées après le résultat de l'action. L'invite suivante est séparée du retour d'information par une ligne vide.
normal
Fournit une quantité moyenne de retour d'information. L'invite suivante est séparée du retour d'information par une ligne vide.
concis
Fournit un retour d'information minimal. L'invite suivante suit immédiatement l'extrait de code ou le retour d'information.
silencieux
Ne fournit aucun retour d'information. L'invite suivante suit immédiatement l'extrait de code.
personnalisé
Fournit un retour d'information personnalisé en fonction de la définition du mode. Les modes de retour d'information personnalisés sont créés dans JShell en utilisant la commande /set mode.
--help ou -h ou -?
Affiche un résumé des options standard et quitte l'outil.
--help-extra ou -X
Affiche un résumé des options non standard et quitte l'outil. Les options non standard sont sujettes à modification sans préavis.
-Jindicateur
Fournit un indicateur à passer au système d'exécution. Pour passer plus d'un indicateur, fournissez une instance de cette option pour chaque indicateur ou argument d'indicateur nécessaire.
--module-path chemin_modules
Spécifie où trouver les modules d'application. Pour Linux et macOS, utilisez un deux-points (:) pour séparer les éléments du chemin. Pour Windows, utilisez un point-virgule (;) pour séparer les éléments.

Spécifie le contexte dans lequel le format de réponse est appliqué. Les sélecteurs sont décrits dans l'aide en ligne, accessible depuis JShell en utilisant la commande /help /set format.

Crée un mode de retour d'information personnalisé avec le nom de mode fourni. Si le nom d'un mode existant est fourni, alors les paramètres du mode existant sont copiés dans le mode en cours de création.

Spécifie le niveau de retour d'information affiché pour les commandes lors de l'utilisation du mode. Cette option est requise lors de la création d'un mode de retour d'information. Utilisez -command pour afficher des informations et des retours de vérification pour les commandes. Utilisez -quiet pour afficher uniquement les retours essentiels pour les commandes, tels que les messages d'erreur.

-retain
Conserve le mode de retour d'information nommé entre les sessions. Le nom du mode à conserver est requis.

Pour définir une invite, les arguments suivants sont requis :

Définit les noms des scripts de démarrage utilisés lorsque la prochaine commande /reset, /reload ou /env est entrée. S'il y a plus d'un script entré, alors les scripts sont exécutés dans l'ordre où ils sont entrés. Si aucun script ou option n'est entré, alors les paramètres de démarrage actuels sont affichés.

Les scripts peuvent être des fichiers locaux ou l'un des scripts prédéfinis suivants :

DEFAULT
Charge les entrées par défaut, qui sont couramment utilisées comme importations.

Définit print, println, et printf comme méthodes jshell à utiliser dans l'outil.

-default
Définit les paramètres de démarrage sur les paramètres par défaut.
-none

Utilisez l'option -retain pour conserver le paramètre de démarrage entre les sessions.

sélecteur
>

UNE SESSION JSHELL


Une session JShell est un environnement interactif où des instructions
    Java peuvent être saisies et exécutées immédiatement. La saisie d'une
    instruction se termine par un saut de ligne. Si JShell peut déterminer que
    l'instruction est complète, elle est immédiatement traitée. Sinon, JShell
    affiche un indicateur pour indiquer qu'il attend la suite de l'instruction.


Les instructions JShell sont appelées "snippets". Un snippet peut
    être une instruction Java, une déclaration de variable, une définition de
    méthode, une définition de classe, une instruction d'importation ou une
    expression. Les points-virgules sont automatiquement ajoutés à la fin d'un
    snippet terminé s'ils sont manquants.


Les exemples suivants montrent l'importation de plusieurs packages
    qui sont nécessaires pour l'utilisation de JShell.



  

  

    
  s1 : import java.io.*;

  s4 : import java.nio.file.*;

  s6 : import java.util.concurrent.*;
  s7 : import java.util.function.*;
  s8 : import java.util.prefs.*;
  s9 : import java.util.regex.*;

EXEMPLE
    DE CRÉATION D'UN MODE DE RETROACTION PERSONNALISÉ


Le mode de rétroaction détermine l'invite affichée, les messages de
    rétroaction fournis lorsque les snippets sont saisis et la longueur maximale
    d'une valeur affichée. Des modes de rétroaction prédéfinis sont fournis. Des
    commandes pour créer des modes de rétroaction personnalisés sont également
    fournies.


Utilisez la commande /set mode pour
    créer un nouveau mode de rétroaction. Dans l'exemple suivant, le nouveau mode
    mymode est basé sur le mode de rétroaction
    prédéfini normal et la rétroaction des commandes
    de vérification est affichée :



  

  

    

jshell> /set mode mymode normal -command
|  Nouveau mode de rétroaction créé : mymode


  




Comme le nouveau mode est basé sur le mode
    normal, les invites sont identiques. L'exemple
    suivant montre comment afficher les invites utilisées, puis modifie les
    invites avec des chaînes personnalisées. La première chaîne représente
    l'invite JShell standard. La seconde chaîne représente l'invite pour les lignes
    supplémentaires dans les snippets multilignes.



  

  

    

jshell> /set prompt mymode
|  /set prompt mymode "\njshell> " "   ...> "
jshell> /set prompt mymode "\nprompt$ " "   continue$ "

    paramètre de troncature. Différents types de valeurs peuvent avoir des longueurs

    et une valeur de troncature de 500 pour les expressions de valeur de variable
     :



  

  

    

jshell> /set truncation mymode 72
jshell> /set truncation mymode 500 varvalue
