NOM

jj-util-completion - Imprime un script d'achèvement de ligne de commande

SYNTAXE

jj util completion [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <SHELL>

DESCRIPTION

Imprime un script d'achèvement de ligne de commande

Appliquez-le en exécutant l'une des commandes suivantes :

- Bash : `source <(jj util completion bash)` - Fish : `jj util completion fish | source` - Nushell :
```nu
jj util completion nushell | save -f "completions-jj.nu"
use "completions-jj.nu" * # Ou `source "completions-jj.nu"`
``` - Zsh :
```shell
autoload -U compinit
compinit
source <(jj util completion zsh)
```

Voir la documentation sur [achèvement de ligne de commande] pour plus de détails.

[achèvement de ligne de commande] :
https://docs.jj-vcs.dev/latest/install-and-setup/#command-line-completion

OPTIONS

-h, --help
Imprime l'aide (voir un résumé avec '-h')
<SHELL>

[valeurs possibles : bash, elvish, fish, nushell, power-shell, zsh]

OPTIONS GLOBALES

-R, --repository <REPOSITORY>
Chemin vers le dépôt à traiter

Par défaut, Jujutsu recherche le répertoire .jj/ le plus proche dans un ancêtre du répertoire de travail actuel.

--ignore-working-copy
Ne pas prendre d'instantané du répertoire de travail, et ne pas le mettre à jour

Par défaut, Jujutsu prend un instantané du répertoire de travail au début de chaque commande. Le répertoire de travail est également mis à jour à la fin de la commande, si la commande a modifié le commit du répertoire de travail (`@`). Si vous souhaitez éviter de prendre un instantané du répertoire de travail et voir plutôt un commit du répertoire de travail potentiellement obsolète, vous pouvez utiliser `--ignore-working-copy`. Ceci peut être utile, par exemple, dans une invite de commande, surtout si un autre processus commite le répertoire de travail.

Le chargement du dépôt à une opération spécifique avec `--at-operation` implique `--ignore-working-copy`.

--ignore-immutable
Autoriser la réécriture des commits immuables

Par défaut, Jujutsu empêche la réécriture des commits dans l'ensemble configuré de commits immuables. Cette option désactive cette vérification et vous permet de réécrire n'importe quel commit, sauf le commit racine.

Cette option n'affecte que la vérification. Elle n'affecte pas le revset `immutable_heads()` ni le mot-clé de modèle `immutable`.

--at-operation <AT_OPERATION>
Opération à laquelle charger le dépôt

Opération à laquelle charger le dépôt. Par défaut, Jujutsu charge le dépôt à l'opération la plus récente, ou à la fusion des opérations divergentes s'il y en a.

Vous pouvez utiliser `--at-op=<ID d'opération>` pour voir à quoi ressemblait le dépôt à une opération antérieure. Par exemple, `jj --at-op=<ID d'opération> st` vous montrera ce que `jj st` aurait montré lorsque l'opération donnée venait de se terminer. `--at-op=@` est à peu près identique au comportement par défaut, sauf que les opérations divergentes ne seront jamais fusionnées.

Utilisez `jj op log` pour trouver l'ID de l'opération souhaitée. Tout préfixe non ambigu de l'ID de l'opération suffit.

Lors du chargement du dépôt à une opération antérieure, le répertoire de travail sera ignoré, comme si `--ignore-working-copy` avait été spécifié.

Il est possible d'exécuter des commandes mutantes lors du chargement du dépôt à une opération antérieure. Faire cela équivaut à avoir exécuté des commandes concurrentes commençant à l'opération antérieure. Il y a rarement une raison de le faire, mais c'est possible.

--debug
Activer la journalisation de débogage
--color <WHEN>
Quand coloriser la sortie

[valeurs possibles : always, never, debug, auto]

--quiet
Silencier la sortie non principale de la commande

Par exemple, `jj file list` listera toujours les fichiers, mais il ne vous dira pas si le répertoire de travail a été pris en instantané ou si des descendants ont été rebasés.

Les avertissements et les erreurs seront toujours affichés.

--no-pager
Désactiver le pagineur
--config <NAME=VALUE>
Options de configuration supplémentaires (peuvent être répétées)

Le nom doit être spécifié sous forme de clés pointillées TOML. La valeur doit être spécifiée sous forme d'expression TOML. Si la valeur de chaîne n'est pas entourée de constructions TOML (telles que la notation de tableau), les guillemets peuvent être omis.

--config-file <PATH>
Fichiers de configuration supplémentaires (peuvent être répétés)
completion
