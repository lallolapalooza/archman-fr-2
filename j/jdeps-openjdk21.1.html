JDEPS(1) Commandes JDK JDEPS(1)

NOM

jdeps - lance l'analyseur de dépendances de classes Java

SYNTAXE

jdeps [options] chemin ...

options
Options de ligne de commande. Pour des descriptions détaillées des options utilisables, voir
•
Options possibles
•
Options d'analyse des dépendances de modules
•
Options pour filtrer les dépendances
•
Options pour filtrer les classes à analyser
chemin
Un chemin vers le fichier .class, répertoire ou fichier JAR à analyser.

DESCRIPTION

La commande jdeps affiche les dépendances au niveau du paquet ou de la classe des fichiers de classes Java. La classe d'entrée peut être un nom de chemin vers un fichier .class, un répertoire, un fichier JAR, ou elle peut être un nom de classe complètement qualifié pour analyser tous les fichiers de classes. Les options déterminent la sortie. Par défaut, la commande jdeps écrit les dépendances sur la sortie système. La commande peut générer les dépendances en langage DOT (voir l'option -dotoutput).

OPTIONS POSSIBLES

-? ou -h ou --help
Affiche le message d'aide.
-dotoutput dir ou --dot-output dir
Spécifie le répertoire de destination pour la sortie des fichiers DOT. Si cette option est spécifiée, la commande jdeps génère un fichier .dot pour chaque archive analysée nommé nom-du-fichier-archive.dot qui liste les dépendances, ainsi qu'un fichier récapitulatif nommé summary.dot qui liste les dépendances entre les fichiers d'archives.
-s ou -summary
Affiche uniquement un résumé des dépendances.
-v ou -verbose
Affiche toutes les dépendances au niveau de la classe. Ceci est équivalent à

-verbose:class -filter:none

-verbose:package
Affiche les dépendances au niveau du paquet, excluant par défaut les dépendances au sein du même paquet.
-verbose:class
Affiche les dépendances au niveau de la classe, excluant par défaut les dépendances au sein de la même archive.
-apionly ou --api-only
Restreint l'analyse aux API, par exemple, aux dépendances de la signature des membres publics et protégés des classes publiques, y compris le type des champs, les types de paramètres des méthodes, le type de retour et les types d'exception vérifiés.
-jdkinternals ou --jdk-internals
Trouve les dépendances au niveau de la classe dans les API internes du JDK. Par défaut, cette option analyse toutes les classes spécifiées dans l'option --classpath et les fichiers d'entrée, sauf si vous avez spécifié l'option -include. Vous ne pouvez pas utiliser cette option avec les options -p, -e et -s.

Attention : Les API internes du JDK sont inaccessibles.

-cp chemin, -classpath chemin, ou --class-path chemin
Spécifie où trouver les fichiers de classes.
--module-path chemin_module
Spécifie le chemin des modules.
--upgrade-module-path chemin_module
Spécifie le chemin des modules de mise à niveau.
--system java-home
Spécifie un chemin de module système alternatif.
--add-modules nom_module[, nom_module...]
Ajoute des modules à l'ensemble racine pour l'analyse.
--multi-release version
Spécifie la version lors du traitement des fichiers JAR multi-versions. version doit être un entier >=9 ou 'base'.
-q ou -quiet
N'affiche pas les dépendances manquantes dans la sortie de -generate-module-info.
-version ou --version
Affiche les informations de version.

OPTIONS D'ANALYSE DES DENSIONS DE MODULES

-m nom_module ou --module nom_module
Spécifie le module racine pour l'analyse.
--generate-module-info dir
Génère module-info.java sous le répertoire spécifié. Les fichiers JAR spécifiés seront analysés. Cette option ne peut pas être utilisée avec les options --dot-output ou --class-path. Utilisez l'option --generate-open-module pour les modules ouverts.
--generate-open-module dir
Génère module-info.java pour les fichiers JAR spécifiés sous le répertoire spécifié comme modules ouverts. Cette option ne peut pas être utilisée avec les options --dot-output ou --class-path.
--check nom_module [, nom_module...]
Analyse la dépendance des modules spécifiés. Elle affiche le descripteur de module, les dépendances de module résultantes après analyse et le graphe après réduction de transition. Elle identifie également les exportations qualifiées inutilisées.
--list-deps
Liste les dépendances des modules et aussi les noms des paquets des API internes du JDK (si référencés). Cette option analyse transitivement les bibliothèques sur le chemin des classes et le chemin des modules si référencées. Utilisez l'option --no-recursive pour une analyse de dépendance non transitive.
--list-reduced-deps
Identique à --list-deps sans lister les liens de lecture implicites du graphe de modules. Si le module M1 lit M2, et que M2 requiert transitivement M3, alors M1 lisant M3 est implicite et n'est pas montré dans le graphe.
--print-module-deps
Identique à --list-reduced-deps en affichant une liste séparée par des virgules des dépendances de modules. La sortie peut être utilisée par jlink --add-modules pour créer une image personnalisée contenant ces modules et leurs dépendances transitives.
--ignore-missing-deps
Ignore les dépendances manquantes.

OPTIONS POUR FILTRER LES DENSIONS

-p nom_paquet, -package nom_paquet, ou --package nom_paquet
Trouve les dépendances correspondant au nom du paquet spécifié. Vous pouvez spécifier cette option plusieurs fois pour différents paquets. Les options -p et -e sont mutuellement exclusives.
-e regex, -regex regex, ou --regex regex
Trouve les dépendances correspondant au modèle spécifié. Les options -p et -e sont mutuellement exclusives.
--require nom_module
Trouve les dépendances correspondant au nom du module donné (peut être donné plusieurs fois). Les options --package, --regex et --require sont mutuellement exclusives.
-f regex ou -filter regex
Filtre les dépendances correspondant au modèle donné. Si donné plusieurs fois, le dernier sera sélectionné.
-filter:package
Filtre les dépendances au sein du même paquet. C'est le comportement par défaut.
-filter:archive
Filtre les dépendances au sein de la même archive.
-filter:module
Filtre les dépendances au sein du même module.
-filter:none
Aucun filtrage -filter:package et -filter:archive. Le filtrage spécifié via l'option -filter s'applique toujours.
--missing-deps
Trouve les dépendances manquantes. Cette option ne peut pas être utilisée avec les options -p, -e et -s.

OPTIONS POUR FILTRER LES CLASSES À ANALYSER

-include regex
Restreint l'analyse aux classes correspondant au modèle. Cette option filtre la liste des classes à analyser. Elle peut être utilisée conjointement avec -p et -e, qui appliquent le modèle aux dépendances.
-P ou -profile
Affiche le profil contenant un paquet. Cette option est dépréciée et pourrait être supprimée dans une future version.
-R ou --recursive
Parcourt récursivement toutes les dépendances d'exécution. L'option -R implique -filter:none. Si les options -p, -e ou -f sont spécifiées, seules les dépendances correspondantes sont analysées.
--no-recursive
Ne pas parcourir récursivement les dépendances.
-I ou --inverse
Analyse les dépendances selon les autres options données, puis trouve tous les artefacts qui dépendent directement et indirectement des nœuds correspondants. Ceci est équivalent à l'inverse de l'analyse de la vue de compilation et du résumé d'impression des dépendances. Cette option doit être utilisée avec les options --require, --package ou --regex.
--compile-time
Analyse la vue de compilation des dépendances transitives, telle que la vue de compilation de l'option -R. Analyse les dépendances selon les autres options spécifiées. Si une dépendance est trouvée à partir d'un répertoire, d'un fichier JAR ou d'un module, toutes les classes dans l'archive contenant sont analysées.

EXEMPLE D'ANALYSE DES DÉPENDANCES

L'exemple suivant illustre l'analyse des dépendances du fichier Notepad.jar.

Linux et macOS :


$ jdeps demo/jfc/Notepad/Notepad.jar

Notepad.jar -> java.desktop
Notepad.jar -> java.logging
   <unnamed> (Notepad.jar)
      -> java.awt
      -> java.awt.event
      -> java.beans
      -> java.io
      -> java.lang
      -> java.net
      -> java.util
      -> java.util.logging
      -> javax.swing
      -> javax.swing.border
      -> javax.swing.event
      -> javax.swing.text
      -> javax.swing.tree
      -> javax.swing.undo

EXEMPLE UTILISANT L'OPTION --INVERSE


 $ jdeps --inverse --require java.xml.bind
Dépendances transitives inverses sur [java.xml.bind]
java.xml.bind <- java.se.ee
java.xml.bind <- jdk.xml.ws
java.xml.bind <- java.xml.ws <- java.se.ee
java.xml.bind <- java.xml.ws <- jdk.xml.ws
java.xml.bind <- jdk.xml.bind <- jdk.xml.ws
