JOIN(1P) Manuel du programmeur POSIX JOIN(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

join — opérateur de base de données relationnelle

SYNTAXE

join [-a numéro_fichier|-v numéro_fichier] [-e chaîne] [-o liste] [-t caractère]
    [-1 champ] [-2 champ] fichier1 fichier2

DESCRIPTION

L'utilitaire join effectue une jointure par égalité sur les fichiers fichier1 et fichier2. Les fichiers joints sont écrits sur la sortie standard.

Le champ de jointure est un champ dans chaque fichier sur lequel les fichiers sont comparés. L'utilitaire join écrit une ligne en sortie pour chaque paire de lignes dans fichier1 et fichier2 qui ont des champs de jointure qui se trient de manière égale. La ligne de sortie est par défaut constituée du champ de jointure, puis des autres champs de fichier1, puis des autres champs de fichier2. Ce format peut être modifié en utilisant l'option -o (voir ci-dessous). L'option -a peut être utilisée pour ajouter les lignes non appariées à la sortie. L'option -v peut être utilisée pour ne sortir que les lignes non appariées.

Les fichiers fichier1 et fichier2 doivent être ordonnés selon la séquence de tri de sort -b sur les champs sur lesquels ils doivent être joints, par défaut le premier de chaque ligne. Toute la sortie sélectionnée doit être écrite dans la même séquence de tri.

Les délimiteurs de champs d'entrée par défaut sont les caractères <espace>. Dans ce cas, plusieurs délimiteurs comptent comme un seul séparateur de champ, et les séparateurs en tête sont ignorés. Le séparateur de champs de sortie par défaut est un <espace>.

Le séparateur de champs et la séquence de tri peuvent être modifiés en utilisant l'option -t (voir ci-dessous).

Si le même champ apparaît plus d'une fois dans un fichier, toutes les combinaisons de l'ensemble des champs restants dans fichier1 et de l'ensemble des champs restants dans fichier2 sont sorties dans l'ordre des lignes rencontrées.

Si les fichiers d'entrée ne sont pas dans la séquence de tri appropriée, les résultats ne sont pas spécifiés.

OPTIONS

L'utilitaire join doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être supportées :

-a numéro_fichier

Produit une ligne pour chaque ligne non appariable dans le fichier numéro_fichier, où numéro_fichier est 1 ou 2, en plus de la sortie par défaut. Si -a1 et -a2 sont toutes deux spécifiées, toutes les lignes non appariables seront produites.
-e chaîne
Remplace les champs de sortie vides dans la liste sélectionnée par -o par la chaîne chaîne.
-o liste
Construit la ligne de sortie pour comprendre les champs spécifiés dans liste, dont chaque élément aura l'une des deux formes suivantes :
1.
numéro_fichier.champ, où numéro_fichier est un numéro de fichier et champ est un numéro de champ décimal entier
2.
0 (zéro), représentant le champ de jointure

Les éléments de liste seront séparés par des virgules ou des espaces (<blank>), comme spécifié dans la Directive 8 du volume des Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires. Les champs spécifiés par liste seront écrits pour toutes les lignes de sortie sélectionnées. Les champs sélectionnés par liste qui n'apparaissent pas dans l'entrée seront traités comme des champs de sortie vides. (Voir l'option -e.) Seuls les champs spécifiquement demandés seront écrits. L'application doit s'assurer que liste est un seul argument de ligne de commande.

-t caractère
Utilise le caractère caractère comme séparateur, pour l'entrée et la sortie. Chaque apparition de caractère dans une ligne sera significative. Lorsque cette option est spécifiée, la séquence de tri sera la même que sort sans l'option -b.
-v numéro_fichier

Au lieu de la sortie par défaut, produit une ligne uniquement pour chaque ligne non appariable dans numéro_fichier, où numéro_fichier est 1 ou 2. Si -v1 et -v2 sont toutes deux spécifiées, toutes les lignes non appariables seront produites.
-1 champ
Joint sur le champième champ du fichier 1. Les champs sont des entiers décimaux commençant à 1.
-2 champ
Joint sur le champième champ du fichier 2. Les champs sont des entiers décimaux commençant à 1.

OPÉRANDES

Les opérandes suivants doivent être supportés :

fichier1, fichier2
Un chemin d'accès à un fichier à joindre. Si l'un des opérandes fichier1 ou fichier2 est '-', l'entrée standard sera utilisée à sa place.

STDIN

L'entrée standard sera utilisée uniquement si l'opérande fichier1 ou fichier2 est '-'. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de join :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale de la séquence de tri que join s'attend à ce qu'elle ait été utilisée lors du tri des fichiers d'entrée.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données texte en caractères (par exemple, caractères mono-octet par opposition aux multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie de join est une concaténation de champs de caractères sélectionnés. Lorsque l'option -o n'est pas spécifiée, la sortie est :

"%s%s%s\n", <champ de jointure>, <autres champs fichier1>,
    <autres champs fichier2>

Si le champ de jointure n'est pas le premier champ d'un fichier, les <autres champs de fichier> pour ce fichier sont :

<champs précédant le champ de jointure>, <champs suivant le champ de jointure>

Lorsque l'option -o est spécifiée, le format de sortie est :

"%s\n", <concaténation des champs>

Pour les deux formats, chaque champ (sauf le dernier) est écrit avec son caractère séparateur final. Si le séparateur est celui par défaut (caractères <espace>), un seul <espace> est écrit après chaque champ (sauf le dernier).

CODE DE RETOUR

Les valeurs de retour suivantes doivent être renvoyées :

0
Tous les fichiers d'entrée ont été traités avec succès.
>0
Une erreur s'est produite.

UTILISATION DANS LES APPLICATIONS

Les chemins composés de chiffres numériques ou de la forme chaîne.chaîne chaîne.chaîne ne doivent pas être spécifiés directement après la -o liste.

Si la séquence de collation de la locale courante n'a pas un ordre total de tous les caractères (voir le volume Base Definitions de POSIX.1‐2017, Section 7.3.2, LC_COLLATE), join traite les champs qui sont équivalents pour la collation mais non identiques comme étant les mêmes. Si ce comportement n'est pas souhaité, il peut être évité en forçant l'utilisation de la locale POSIX (ce qui signifie toutefois de trier à nouveau les fichiers d'entrée selon la séquence de collation de la locale POSIX.)

Lors de l'utilisation de join pour traiter des chemins, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les chemins peuvent contenir des séquences d'octets qui ne forment pas de caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire serait indéfini. Dans la locale POSIX, chaque octet est un caractère simple d'un octet valide, et donc ce problème est évité.

EXEMPLES

Le champ -o 0 sélectionne essentiellement l'union des champs de jointure. Par exemple, étant donné le fichier phone:

!Name           Phone Number
Don             +1 123-456-7890
Hal             +1 234-567-8901
Yasushi         +2 345-678-9012

et le fichier fax:

!Name           Fax Number
Don             +1 123-456-7899
Keith           +1 456-789-0122
Yasushi         +2 345-678-9011

(où les grandes étendues d'espaces blancs sont censées représenter chacune une seule <tabulation>), la commande :

join -t "<tab>" -a 1 -a 2 -e '(unknown)' -o 0,1.2,2.2 phone fax

(où <tab> est un caractère <tabulation> littéral) produirait :

!Name           Phone Number            Fax Number
Don             +1 123-456-7890         +1 123-456-7899
Hal             +1 234-567-8901         (unknown)
Keith           (unknown)               +1 456-789-0122
Yasushi         +2 345-678-9012         +2 345-678-9011

Les instances multiples de la même clé produiront des résultats combinatoires. Ce qui suit :

fa:
    a x
    a y
    a z
fb:
    a p

produira :

a x p
a y p
a z p

Et ce qui suit :

fa:
    a b c
    a d e
fb:
    a w x
    a y z
    a o p

produira :

a b c w x
a b c y z
a b c o p
a d e w x
a d e y z
a d e o p

JUSTIFICATION

L' -e option n'est efficace que lorsqu'elle est utilisée avec -o car, à moins que des champs spécifiques soient identifiés à l'aide de -o, join n'a pas connaissance des champs qui pourraient être vides. L'exception à cela est le champ de jointure, mais identifier un champ de jointure vide avec la -e chaîne n'est pas une pratique historique et certains scripts pourraient cesser de fonctionner si cela était modifié.

Le champ 0 dans la -o liste a été adopté de la version de la Dixième Édition de join pour satisfaire des objections internationales selon lesquelles le join des documents de base pour IEEE Std 1003.2‐1992 ne prenait pas en charge la « jointure complète » ou « jointure externe » décrite dans la littérature des bases de données relationnelles. Bien qu'il ait été possible d'inclure un champ de jointure dans la sortie (par défaut, ou par numéro de champ à l'aide de -o), le champ de jointure ne pouvait pas être inclus pour une ligne non appariée sélectionnée par -a. Le champ -o 0 sélectionne essentiellement l'union des champs de jointure.

Ce type de jointure externe n'était pas possible avec les join des documents de base pour IEEE Std 1003.2‐1992. Le champ -o 0 a été choisi car il s'agit d'un changement compatible avec les versions supérieures pour les applications. Une alternative a été envisagée : faire que le champ de jointure représente l'union des champs des fichiers (où ils sont identiques pour les lignes appariées, et où l'un ou les deux sont nuls pour les lignes non appariées). Cela n'a pas été adopté car cela casserait certaines applications historiques.

La possibilité de spécifier file2 comme - n'est pas une pratique historique ; cela a été ajouté pour plus de complétude.

L' -v option n'est pas une pratique historique, mais a été considérée comme nécessaire car elle permettait d'écrire uniquement les lignes qui ne correspondent pas sur le champ de jointure, par opposition à l' -a option, qui imprime à la fois les lignes qui correspondent et celles qui ne correspondent pas. Cette fonctionnalité supplémentaire est parallèle à l' -v option de grep.

Certaines implémentations historiques ont été rencontrées où une ligne vide dans l'un des fichiers d'entrée était considérée comme la fin du fichier ; la description dans ce volume de POSIX.1‐2017 ne cite pas cela comme un cas autorisé.

Les versions antérieures de cette norme autorisaient les options -j, -j1, -j2 , et une forme de l' -o option qui permettait à l' liste argument d'option d'être multiple. Ces formes ne sont plus spécifiées par POSIX.1‐2008 mais peuvent être présentes dans certaines implémentations.
