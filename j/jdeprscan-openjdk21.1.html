DESCRIPTIO

N

L'outil jdeprscan est un outil d'analyse statique fourni par le JDK qui examine un fichier JAR ou une autre agrégation de fichiers de classes à la recherche d'utilisations d'éléments d'API obsolètes. Les API obsolètes identifiées par l'outil jdeprscan sont uniquement celles qui sont définies par Java SE. Les API obsolètes définies par des bibliothèques tierces ne sont pas

signalées.

Pour examiner un fichier JAR ou un ensemble de fichiers de classes, vous devez d'abord vous assurer que toutes les classes dont dépendent les classes examinées sont présentes dans le chemin de classe. Définissez le chemin de classe à l'aide de l'option --class-path décrite dans Options de la commande jdeprscan. Typiquement, vous utiliserez le même chemin de classe que celui que vous utilisez lors de l'invocation de votre

application.

Si jdeprscan ne peut pas trouver toutes les classes dépendantes, il générera un message d'erreur pour chaque classe manquante. Ces messages d'erreur sont généralement de la forme

:

error: cannot find class .

.
.

Si ces erreurs se produisent, vous devez

ajuster le chemin de classe afin qu'il
inclue toutes les classes dépendantes.

JDEPRSCAN

Le fichier JAR pour cette bibliothèque sera nommé quelque chose comme commons-math3-3.6.1.jar. Pour examiner ce fichier JAR à la recherche d'utilisations d'API obsolètes, exécutez la commande suivante

:

jdeprscan c

ommons-math
3-3.6.1.jar

Cette commande produit plusieurs lignes de sortie. Par exemple, une ligne de sortie pourrait être

: 

class org/apache/commons/math3/util/MathUtils uses deprecated method java/lang/Double::<init>(D)V

Remarque

:

Le nom de classe est spécifié en utilisant le nom binaire séparé par des barres obliques comme décrit dans JVMS 4.2.1. C'est la forme utilisée en interne dans les fichiers de

classe.

L'API obsolète utilisée est une méthode sur la classe java.lang.

Double.

Le nom de la méthode obsolète est <init>, qui est un nom spécial signifiant que la méthode est en fait un constructeur. Un autre nom spécial est <clinit>, qui indique un initialiseur statique de

classe.

Les autres méthodes sont listées simplement par leur nom de méthode. Après le nom de méthode se trouve la liste d'arguments et le type de retour

:

(

D)
V

Cela indique qu'elle prend une seule valeur double (un primitif) et retourne void. Les types d'arguments et de retour peuvent devenir cryptiques. Par exemple, une autre ligne de sortie pourrait être

: 

class org/apache/commons/math3/util/Precision uses deprecated method java/math/BigDecimal::setScale(II)Ljava/math/BigDecimal;

Dans cette ligne de sortie, la méthode obsolète est sur la classe java.math.BigDecimal, et la métho

de est setScale(). Dans ce cas, le (II) signifie qu'elle prend deux arguments int. Le Ljava/math/B
igDecimal; après les parenthèses signifie qu'elle retourne une référence vers java.math.BigDecimal.

L'ANALYSE JDEPRSCAN PEUT ÊTRE SPÉCIFIQUE À LA

VERSION

Vous pouvez utiliser jdeprscan par rapport aux trois versions précédentes du JDK. Par exemple, si vous exécutez le JDK 9, vous pouvez vérifier par rapport au JDK 8, 7 et

6.

À titre d'exemple, regardez cet extrait de code

: 

public class Deprecations {
   SecurityManager sm = new RMISecurityManager();    // deprecated in 8
   Boolean b2 = new Boolean(true);          // deprecated in 9
}

La classe complète se compile sans avertissements dans le JDK

7.

Si vous exécutez jdeprscan sur un système avec le JDK 9, vous obtenez

: 

$ jdeprscan --class-path classes --release 7 example.Deprecations
(pas de sortie)

Exécutez jdeprscan avec une valeur de release de 8

: 

$ jdeprscan --class-path classes --release 8 example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated

Exécutez jdeprscan sur le JDK 9

: 

$ jdeprscan --class-path classes example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method java/lang/Boolean <init> (Z)V deprecated
