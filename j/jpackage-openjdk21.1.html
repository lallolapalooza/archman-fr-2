JPACKAGE(1) Commandes JDK JPACKAGE(1)

NOM

jpackage - outil pour empaqueter des applications Java autonomes.

SYNOPSIS

jpackage [options]

options
Options de ligne de commande séparées par des espaces. Voir Options de jpackage.

DESCRIPTION

L'outil jpackage prend en entrée une application Java et une image d'exécution Java, et produit une image d'application Java qui inclut toutes les dépendances nécessaires. Il peut produire un paquet natif dans un format spécifique à la plateforme, tel qu'un exe sous Windows ou un dmg sous macOS. Chaque format doit être construit sur la plateforme sur laquelle il s'exécute, il n'y a pas de support multiplateforme. L'outil disposera d'options permettant de personnaliser les applications empaquetées de diverses manières.

OPTIONS DE JPACKAGE

Options génériques :

@fichier
Lire les options depuis un fichier.

Cette option peut être utilisée plusieurs fois.

--type ou -t type
Le type de paquet à créer

Les valeurs valides sont : {"app-image", "exe", "msi", "rpm", "deb", "pkg", "dmg"}

Si cette option n'est pas spécifiée, un type par défaut dépendant de la plateforme sera créé.

--app-version version
Version de l'application et/ou du paquet
--copyright copyright
Copyright pour l'application
--description description
Description de l'application
--help ou -h
Afficher le texte d'utilisation avec une liste et une description de chaque option valide pour la plateforme actuelle sur le flux de sortie, puis quitter.
--icon chemin
Chemin de l'icône du paquet de l'application

(chemin absolu ou relatif au répertoire courant)

--name ou -n nom
Nom de l'application et/ou du paquet
--dest ou -d destination
Chemin où le fichier de sortie généré est placé

(chemin absolu ou relatif au répertoire courant).

Par défaut, le répertoire de travail courant.

--temp répertoire
Chemin d'un nouveau répertoire vide utilisé pour créer des fichiers temporaires

(chemin absolu ou relatif au répertoire courant)

Si spécifié, le répertoire temporaire ne sera pas supprimé à la fin de la tâche et doit être supprimé manuellement.

Si non spécifié, un répertoire temporaire sera créé et supprimé à la fin de la tâche.

--vendor vendeur
Vendeur de l'application
--verbose
Active la sortie détaillée.
--version
Afficher la version du produit sur le flux de sortie puis quitter.

Options pour créer l'image d'exécution :

--add-modules nom-module [,nom-module...]
Une liste de modules à ajouter séparés par des virgules (",")

Cette liste de modules, ainsi que le module principal (s'il est spécifié), sera passée à jlink comme argument --add-module. Si non spécifié, soit le module principal seul (si --module est spécifié), soit l'ensemble par défaut des modules (si --main-jar est spécifié) sont utilisés.

Cette option peut être utilisée plusieurs fois.

--module-path ou -p chemin-module [,chemin-module...]
Une liste de chemins séparés par File.pathSeparator

Chaque chemin est soit un répertoire de modules, soit le chemin d'un jar modulaire, et est absolu ou relatif au répertoire courant.

Cette option peut être utilisée plusieurs fois.

--jlink-options options
Une liste d'options séparées par des espaces à passer à jlink

Si non spécifié, la valeur par défaut est "--strip-native-commands --strip-debug --no-man-pages --no-header-files"

Cette option peut être utilisée plusieurs fois.

--runtime-image répertoire
Chemin de l'image d'exécution prédéfinie qui sera copiée dans l'image de l'application

(chemin absolu ou relatif au répertoire courant)

Si --runtime-image n'est pas spécifié, jpackage exécutera jlink pour créer l'image d'exécution en utilisant les options spécifiées par --jlink-options.

Options pour créer l'image de l'application :

--input ou -i répertoire
Chemin du répertoire d'entrée contenant les fichiers à empaqueter

(chemin absolu ou relatif au répertoire courant)

Tous les fichiers du répertoire d'entrée seront empaquetés dans l'image de l'application.

`--app-content contenu-supplémentaire[,contenu-supplémentaire...]
Une liste de chemins vers des fichiers et/ou répertoires à ajouter au contenu de l'application, séparés par des virgules.

Cette option peut être utilisée plus d'une fois.

Options pour créer le(s) lanceur(s) de l'application :

--add-launcher nom=chemin
Nom du lanceur, et chemin vers un fichier Properties contenant une liste de paires clé, valeur

(chemin absolu ou relatif au répertoire courant)

Les clés "module", "main-jar", "main-class", "description", "arguments", "java-options", "app-version", "icon", "launcher-as-service", "win-console", "win-shortcut", "win-menu", "linux-app-category", et "linux-shortcut" peuvent être utilisées.

Ces options sont ajoutées, ou utilisées pour écraser, les options originales de la ligne de commande pour construire un lanceur alternatif supplémentaire. Le lanceur principal de l'application sera construit à partir des options de la ligne de commande. Des lanceurs alternatifs supplémentaires peuvent être construits en utilisant cette option, et cette option peut être utilisée plusieurs fois pour construire plusieurs lanceurs supplémentaires.

--arguments arguments
Arguments de ligne de commande à passer à la classe principale si aucun argument de ligne de commande n'est donné au lanceur

Cette option peut être utilisée plusieurs fois.

--java-options options
Options à passer à l'exécution Java

Cette option peut être utilisée plusieurs fois.

--main-class nom-classe
Nom qualifié de la classe principale de l'application à exécuter

Cette option ne peut être utilisée que si --main-jar est spécifié.

--main-jar jar-principal
Le JAR principal de l'application ; contenant la classe principale (spécifiée sous forme de chemin relatif au chemin d'entrée)

Soit l'option --module, soit l'option --main-jar peut être spécifiée, mais pas les deux.

--module ou -m nom-module[/nom-classe]
Le module principal (et éventuellement la classe principale) de l'application

Ce module doit être situé sur le chemin des modules.

Lorsque cette option est spécifiée, le module principal sera lié dans l'image d'exécution Java. Soit l'option --module, soit l'option --main-jar peut être spécifiée, mais pas les deux.

Option dépendante de la plateforme pour créer le lanceur de l'application :

Options de plateforme Windows (disponibles uniquement lors de l'exécution sous Windows) :

--win-console
<dd>Crée un lanceur de console pour l'application, doit être spécifié pour les applications qui nécessitent des interactions console

Options de la plateforme macOS (disponibles uniquement lors de l'exécution sur macOS) :

--mac-package-identifier identifiant
Un identifiant qui identifie de manière unique l'application pour macOS

Par défaut, le nom de la classe principale.

Peut uniquement utiliser des caractères alphanumériques (A-Z, a-z, 0-9), des traits d'union (-) et des points (.).

--mac-package-name nom
Nom de l'application tel qu'il apparaît dans la barre de menu

Cela peut être différent du nom de l'application.

Ce nom doit être inférieur à 16 caractères et être adapté à l'affichage dans la barre de menu et la fenêtre d'informations de l'application. Par défaut, le nom de l'application.

--mac-package-signing-prefix préfixe
Lors de la signature du package d'application, cette valeur est ajoutée en préfixe à tous les composants qui doivent être signés et qui n'ont pas d'identifiant de package existant.
--mac-sign
Demande que le package ou l'image d'application prédéfinie soit signé.
--mac-signing-keychain nom-de-la-trouvaille
Nom de la trouvaille à rechercher pour l'identité de signature

Si non spécifié, les trouvailles standard sont utilisées.

--mac-signing-key-user-name nom
Partie du nom de l'équipe ou de l'utilisateur dans les identités de signature Apple
--mac-app-store
Indique que la sortie de jpackage est destinée au Mac App Store.
--mac-entitlements chemin
Chemin vers le fichier contenant les autorisations à utiliser lors de la signature des exécutables et des bibliothèques dans le bundle
--mac-app-category catégorie
Chaîne utilisée pour construire LSApplicationCategoryType dans le plist de l'application

La valeur par défaut est "utilities".

Options pour la création du package d'application :

--about-url url
URL de la page d'accueil de l'application
--app-image répertoire
Emplacement de l'image d'application prédéfinie utilisée pour construire un package installable (sur toutes les plateformes) ou pour être signée (sur macOS)

(chemin absolu ou relatif au répertoire courant)

--file-associations chemin
Chemin vers un fichier de propriétés contenant une liste de paires clé, valeur

(chemin absolu ou relatif au répertoire courant)

Les clés "extension", "mime-type", "icon" et "description" peuvent être utilisées pour décrire l'association.

Cette option peut être utilisée plusieurs fois.

--install-dir chemin
Chemin absolu du répertoire d'installation de l'application (sur macOS ou linux), ou sous-chemin relatif du répertoire d'installation tel que "Program Files" ou "AppData" (sur Windows)
--license-file chemin
Chemin vers le fichier de licence

(chemin absolu ou relatif au répertoire courant)

--resource-dir chemin
Chemin pour remplacer les ressources de jpackage

(chemin absolu ou relatif au répertoire courant)

Les icônes, les fichiers modèles et autres ressources de jpackage peuvent être remplacés en ajoutant des ressources de remplacement dans ce répertoire.

--runtime-image chemin
Chemin de l'image d'exécution prédéfinie à installer

(chemin absolu ou relatif au répertoire courant)

L'option est requise lors de la création d'un installateur d'exécution.

--launcher-as-service
Demande la création d'un installateur qui enregistrera le lanceur d'application principal en tant qu'application de type service en arrière-plan.

Options dépendantes de la plateforme pour la création du package d'application :

Options de la plateforme Windows (disponibles uniquement lors de l'exécution sur Windows) :

--win-dir-chooser
Ajoute une boîte de dialogue permettant à l'utilisateur de choisir un répertoire dans lequel le produit est installé.
--win-help-url url
URL où l'utilisateur peut obtenir des informations supplémentaires ou un support technique
--win-menu
Demande l'ajout d'un raccourci dans le menu Démarrer pour cette application
--win-menu-group nom-du-groupe-de-menu
Groupe du menu Démarrer dans lequel cette application est placée
--win-per-user-install
Demande l'exécution d'une installation par utilisateur
--win-shortcut
Demande la création d'un raccourci sur le bureau pour cette application
--win-shortcut-prompt
Ajoute une boîte de dialogue permettant à l'utilisateur de choisir si des raccourcis seront créés par l'installateur
--win-update-url url
URL des informations de mise à jour de l'application disponibles
--win-upgrade-uuid id
UUID associé aux mises à niveau pour ce package

Options de la plateforme Linux (disponibles uniquement lors de l'exécution sur Linux) :

--linux-package-name nom
Nom du package Linux

Par défaut, le nom de l'application.

--linux-deb-maintainer adresse-email
Responsable du bundle .deb
--linux-menu-group nom-du-groupe-de-menu
Groupe de menu dans lequel cette application est placée
--linux-package-deps
Packages ou capacités requis pour l'application
--linux-rpm-license-type type
Type de licence ("License: valeur" du fichier .spec RPM)
--linux-app-release version
Valeur de la version du fichier .spec RPM <nom> ou valeur de révision Debian du fichier de contrôle DEB
--linux-app-category valeur-de-catégorie
Valeur du groupe du fichier .spec RPM ou valeur de Section du fichier de contrôle DEB
--linux-shortcut
Crée un raccourci pour l'application.

Options de la plateforme macOS (disponibles uniquement lors de l'exécution sur macOS) :

'--mac-dmg-content contenu-additionnel[,contenu-additionnel...]'
Inclut tout le contenu référencé dans le dmg.

Cette option peut être utilisée plus d'une fois.

EXEMPLES JPACKAGE


Générer un package d'application adapté au système hôte :


Pour une application modulaire :
    jpackage -n nom -p cheminModule -m nomModule/nomClasse
Pour une application non modulaire :
    jpackage -i repertoireEntree -n nom \
        --main-class nomClasse --main-jar monJar.jar
À partir d'une image d'application pré-construite :
    jpackage -n nom --app-image repertoireImageApp


Générer une image d'application :


Pour une application modulaire :
    jpackage --type app-image -n nom -p cheminModule \
        -m nomModule/nomClasse
Pour une application non modulaire :
    jpackage --type app-image -i repertoireEntree -n nom \
        --main-class nomClasse --main-jar monJar.jar
Pour fournir vos propres options à jlink, exécutez jlink séparément :
    jlink --output imageRuntimeApp -p cheminModule \
        --add-modules nomModule \
        --no-header-files [<options jlink supplémentaires>...]
    jpackage --type app-image -n nom \
        -m nomModule/nomClasse --runtime-image imageRuntimeApp


Générer un package d'exécution Java :


jpackage -n nom --runtime-image <image-d'exécution>


Signer l'image d'application prédéfinie (sur macOS) :


jpackage --type app-image --app-image <image-d'application> \
    --mac-sign [<options de signature supplémentaires>...]
Remarque : les seules options supplémentaires autorisées dans ce mode sont :
      l'ensemble des options de signature mac supplémentaires et --verbose

RÉPERTOIRE RESSOURCES JPACKAGE

Les icônes, les fichiers modèles et autres ressources de jpackage peuvent être remplacés en ajoutant des ressources de remplacement dans ce répertoire. jpackage recherchera les fichiers par des noms spécifiques dans le répertoire de ressources.

Fichiers du répertoire de ressources pris en compte uniquement lors de l'exécution sur Linux :

<nom-lanceur>.png
Icône du lanceur d'application

La ressource par défaut est JavaApp.png

<nom-lanceur>.desktop
Un fichier de bureau à utiliser avec la commande xdg-desktop-menu

Prend en compte

rouge avec des lanceurs d'application enregistrés pour les associations de fichiers et/ou ayant une icône

La ressource par défaut est template.desktop

Fichiers du répertoire de ressources considérés uniquement lors de la construction des installateurs Linux DEB/RPM :

<package-name>-<launcher-name>.service
Fichier unit systemd pour un lanceur d'application enregistré en tant qu'application de service en arrière-plan

La ressource par défaut est unit-template.service

Fichiers du répertoire de ressources considérés uniquement lors de la construction de l'installateur Linux RPM :

<package-name>.spec
Fichier spec RPM

La ressource par défaut est template.spec

Fichiers du répertoire de ressources considérés uniquement lors de la construction de l'installateur Linux DEB :

control
Fichier de contrôle

La ressource par défaut est template.control

copyright
Fichier de copyright

La ressource par défaut est template.copyright

preinstall
Script shell de pré-installation

La ressource par défaut est template.preinstall

prerm
Script shell de pré-suppression

La ressource par défaut est template.prerm

postinstall
Script shell de post-installation

La ressource par défaut est template.postinstall

postrm
Script shell de post-suppression

La ressource par défaut est template.postrm

Fichiers du répertoire de ressources considérés uniquement lors de l'exécution sur Windows :

<launcher-name>.ico
Icône du lanceur d'application

La ressource par défaut est JavaApp.ico

<launcher-name>.properties
Fichier de propriétés pour l'exécutable du lanceur d'application

La ressource par défaut est WinLauncher.template

Fichiers du répertoire de ressources considérés uniquement lors de la construction des installateurs Windows MSI/EXE :

<application-name>-post-image.wsf
Un fichier Windows Script File (WSF) à exécuter après la construction de l'image de l'application
main.wxs
Fichier de projet WiX principal

La ressource par défaut est main.wxs

Fichier de projet WiX des surcharges

La ressource par défaut est overrides.wxi

Pris en compte si certains lanceurs d'application sont enregistrés en tant qu'applications de service en arrière-plan

La ressource par défaut est service-install.wxi

<launcher-name>-service-config.wxi
Fichier de projet WiX de l'installation du service

Pris en compte si certains lanceurs d'application sont enregistrés en tant qu'applications de service en arrière-plan

La ressource par défaut est service-config.wxi

InstallDirNotEmptyDlg.wxs
Fichier de projet WiX pour la boîte de dialogue d'interface de l'installateur vérifiant que le répertoire d'installation n'existe pas ou est vide

La ressource par défaut est InstallDirNotEmptyDlg.wxs

ShortcutPromptDlg.wxs
Fichier de projet WiX pour la boîte de dialogue d'interface de l'installateur configurant les raccourcis

La ressource par défaut est ShortcutPromptDlg.wxs

bundle.wxf
Fichier de projet WiX avec la hiérarchie des composants de l'image de l'application

Fichier de projet WiX pour l'interface de l'installateur

Fichiers du répertoire de ressources considérés uniquement lors de la construction de l'installateur Windows EXE :

Fichier de propriétés pour l'exécutable de l'installateur

La ressource par défaut est WinInstaller.template

Un fichier Windows Script File (WSF) à exécuter après la construction de l'installateur MSI embarqué pour l'installateur EXE
