JAR(1) Commandes JDK JAR(1)

NOM

jar - crée une archive pour les classes et les ressources, et manipule ou restaure des classes ou des ressources individuelles à partir d'une archive

SYNTAXE

jar [OPTION ...] [ [--release VERSION] [-C dir] fichiers] ...

DESCRIPTION

La commande jar est un outil d'archivage et de compression à usage général, basé sur les formats de compression ZIP et ZLIB. Initialement, la commande jar a été conçue pour empaqueter des applets Java (non prises en charge depuis JDK 11) ou des applications ; cependant, depuis JDK 9, les utilisateurs peuvent utiliser la commande jar pour créer des JAR modulaires. Pour le transport et le déploiement, il est généralement plus pratique d'empaqueter les modules sous forme de JAR modulaires.

La syntaxe de la commande jar ressemble à celle de la commande tar. Elle possède plusieurs modes d'opération principaux, définis par l'un des arguments d'opération obligatoires. D'autres arguments sont soit des options qui modifient le comportement de l'opération, soit nécessaires pour effectuer l'opération.

Lorsque les modules ou les composants d'une application (fichiers, images et sons) sont combinés en une seule archive, ils peuvent être téléchargés par un agent Java (tel qu'un navigateur) en une seule transaction HTTP, plutôt que de nécessiter une nouvelle connexion pour chaque élément. Cela améliore considérablement les temps de téléchargement. La commande jar compresse également les fichiers, ce qui améliore encore le temps de téléchargement. La commande jar permet également de signer des entrées individuelles dans un fichier, afin que leur origine puisse être authentifiée. Un fichier JAR peut être utilisé comme une entrée de chemin de classe, qu'il soit compressé ou non.

Une archive devient un JAR modulaire lorsque vous incluez un descripteur de module, module-info.class, à la racine des répertoires donnés ou à la racine de l'archive .jar. Les opérations suivantes décrites dans Modificateurs d'opération valides Uniquement en modes Création et Mise à jour ne sont valides que lors de la création ou de la mise à jour d'un JAR modulaire ou de la mise à jour d'un JAR non modulaire existant :

•
--module-version
•
--hash-modules
•
--module-path

Note :

Tous les arguments obligatoires ou optionnels pour les options longues sont également obligatoires ou optionnels pour toutes les options courtes correspondantes.

MODES D'OPÉRATION PRINCIPAUX

Lors de l'utilisation de la commande jar, vous devez spécifier l'opération à effectuer. Vous spécifiez le mode d'opération pour la commande jar en incluant les arguments d'opération appropriés décrits dans cette section. Vous pouvez mélanger un argument d'opération avec d'autres options à une seule lettre. Généralement, l'argument d'opération est le premier argument spécifié sur la ligne de commande.

-c ou --create
Crée l'archive.
-i=FICHIER ou --generate-index=FICHIER
Génère des informations d'index pour le fichier JAR spécifié.
-t ou --list
Liste la table des matières de l'archive.
-u ou --update
Met à jour un fichier JAR existant.
-x ou --extract
Extrait les fichiers nommés (ou tous) de l'archive.
-d ou --describe-module
Affiche le descripteur de module ou le nom de module automatique.

MODIFICATEURS D'OPÉRATION VALIDES DANS TOUT MODE

Vous pouvez utiliser les options suivantes pour personnaliser les actions de tout mode d'opération inclus dans la commande jar.

-C DIR
Change le répertoire spécifié et inclut les fichiers spécifiés à la fin de la ligne de commande.

jar [OPTION ...] [ [--release VERSION] [-C dir] fichiers]

-f=FICHIER ou --file=FICHIER
Spécifie le nom du fichier archive.
--release VERSION
Crée un fichier JAR multi-versions. Place tous les fichiers spécifiés après l'option dans un répertoire versionné du fichier JAR nommé META-INF/versions/VERSION/, où VERSION doit être un entier positif dont la valeur est 9 ou supérieure.

Au moment de l'exécution, lorsqu'il existe plusieurs versions d'une classe dans le JAR, le JDK utilisera la première qu'il trouve, en recherchant initialement dans l'arborescence de répertoires dont le numéro de VERSION correspond au numéro de version majeure du JDK. Il recherchera ensuite dans les répertoires avec des numéros de VERSION successivement inférieurs, et enfin recherchera dans la racine du JAR.

-v ou --verbose
Envoie ou imprime une sortie détaillée sur la sortie standard.

MODIFICATEURS D'OPÉRATION VALIDES UNIQUEMENT EN MODES CRÉATION ET MISE À JOUR

Vous pouvez utiliser les options suivantes pour personnaliser les actions des modes d'opération principaux de création et de mise à jour :

-e=NOM_CLASSE ou --main-class=NOM_CLASSE
Spécifie le point d'entrée de l'application pour les applications autonomes regroupées dans un JAR modulaire ou exécutable.
-m=FICHIER ou --manifest=FICHIER
Inclut les informations du manifeste du fichier manifeste donné.
-M ou --no-manifest
Ne crée pas de fichier manifeste pour les entrées.
--module-version=VERSION
Spécifie la version du module lors de la création ou de la mise à jour d'un fichier JAR modulaire, ou de la mise à jour d'un fichier JAR non modulaire.
--hash-modules=MOTIF
Calcule et enregistre les hachages des modules correspondant au motif donné et qui dépendent directement ou indirectement d'un fichier JAR modulaire en cours de création ou d'un fichier JAR non modulaire en cours de mise à jour.
-p ou --module-path
Spécifie l'emplacement de la dépendance du module pour la génération du hachage.
@fichier
Lit les options jar et les noms de fichiers à partir d'un fichier texte comme s'ils étaient fournis sur la ligne de commande

MODES GENERATE-INDEX

Vous pouvez utiliser les options suivantes pour personnaliser les actions des modes d'opération principaux de création (-c ou --create), de mise à jour (-u ou --update) et de génération d'index (-i ou --generate-index=FICHIER) :

-0 ou --no-compress
Stocke sans utiliser de compression ZIP.

AUTRES OPTIONS

Les options suivantes sont reconnues par la commande jar et ne sont pas utilisées avec les modes d'opération :

-h ou --help[:compat]
Affiche l'aide de la ligne de commande pour la commande jar ou, éventuellement, l'aide de compatibilité.
--help-extra
Affiche l'aide sur les options supplémentaires.
--version
Imprime la version du programme.

EXEMPLES DE SYNTAXE DE LA COMMANDE JAR

•
Crée une archive, classes.jar, qui contient deux fichiers de classe, Foo.class et Bar.class.

jar --create --file classes.jar Foo.class Bar.class

•
Crée une archive, classes.jar, en utilisant un manifest existant, mymanifest, qui contient tous les fichiers du répertoire foo/.

jar --create --file classes.jar --manifest mymanifest -C foo/

•
Crée une archive JAR modulaire, foo.jar, où le descripteur de module se trouve dans classes/module-info.class.

jar --create --file foo.jar --main-class com.foo.Main --module-version 1.0 -C foo/classes resources

•
Met à jour un fichier JAR non modulaire existant, foo.jar, en un fichier JAR modulaire.

jar --update --file foo.jar --main-class com.foo.Main --module-version 1.0 -C foo/module-info.class

•
Crée un JAR versionné ou multi-versions, foo.jar, qui place les fichiers du répertoire classes à la racine du JAR, et les fichiers du répertoire classes-10 dans le répertoire META-INF/versions/10 du JAR.

Dans cet exemple, le répertoire classes/com/foo contient deux classes, com.foo.Hello (la classe de point d'entrée) et com.foo.NameProvider, toutes deux compilées pour JDK 8. Le répertoire classes-10/com/foo contient une version différente de la classe com.foo.NameProvider, contenant du code spécifique à JDK 10 et compilée pour JDK 10.

Étant donné cette configuration, créez un fichier JAR multi-versions foo.jar en exécutant la commande suivante depuis le répertoire contenant les répertoires classes et classes-10.

jar --create --file foo.jar --main-class com.foo.Hello -C classes . --release 10 -C classes-10 .

Le fichier JAR foo.jar contient maintenant :


% jar -tf foo.jar
META-INF/
META-INF/MANIFEST.MF
com/
com/foo/
com/foo/Hello.class
com/foo/NameProvider.class
META-INF/versions/10/com/
META-INF/versions/10/com/foo/
META-INF/versions/10/com/foo/NameProvider.class

Entre autres informations, le fichier META-INF/MANIFEST.MF contiendra les lignes suivantes pour indiquer qu'il s'agit d'un fichier JAR multi-versions avec un point d'entrée com.foo.Hello.


...
Main-Class: com.foo.Hello
Multi-Release: true

En supposant que la classe com.foo.Hello appelle une méthode sur la classe com.foo.NameProvider, l'exécution du programme utilisant JDK 10 garantira que la classe com.foo.NameProvider est celle située dans META-INF/versions/10/com/foo/. L'exécution du programme utilisant JDK 8 garantira que la classe com.foo.NameProvider est celle située à la racine du JAR, dans com/foo.

•
Crée une archive, my.jar, en lisant les options et les listes de fichiers de classe à partir du fichier classes.list.

Remarque :

Pour raccourcir ou simplifier la commande jar, vous pouvez spécifier les arguments dans un fichier texte séparé et le passer à la commande jar avec le signe arobase (@) comme préfixe.

Pour raccourcir ou simplifier la commande jar, vous pouvez fournir un fichier d'arguments qui liste les fichiers à inclure dans le fichier JAR et le passer à la commande jar avec le signe arobase (@) comme préfixe.

jar --create --file my.jar @classes.list

Si une ou plusieurs entrées du fichier d'arguments ne sont pas trouvées, la commande jar échoue sans créer le fichier JAR.
