NOM

jgmenu-i18n - support de la traduction des données de menu au format CSV de jgmenu

SYNOPSIS

jgmenu_run i18n <fichier-de-traduction>

jgmenu_run i18n --init [<fichier-de-traduction>]

DESCRIPTION

jgmenu_run i18n lit les données de menu au format CSV de jgmenu depuis stdin et soit les traduit, soit crée un fichier de traduction de type po

L'argument <fichier-de-traduction> peut être un fichier ou un répertoire. S'il s'agit de ce dernier, les fichiers de traduction seront recherchés dans ce répertoire en fonction de la variable d'environnement $LANG, qui sera supposée être au format ll_CC.UTF8 où ll est un code langue de deux lettres ISO 639 et CC un code pays de deux lettres ISO 3166. Les fichiers nommés ll_CC et ll seront utilisés dans ledit ordre.

OPTIONS

--init
Crée un fichier de traduction modèle de type po avec des entrées msgid vides

EXEMPLES

Créer un modèle de fichier de traduction pour traduction manuelle

Les modules jgmenu-apps(1) et jgmenu-ob(1) ont un support i18n intégré. Pour utiliser ces fonctionnalités, un fichier de traduction est requis. Voici des exemples de la façon dont un fichier de traduction peut être créé :

Exemple 1.

jgmenu_run ob | jgmenu_run i18n --init >sv

Exemple 2.

jgmenu_run i18n --init <prepend.csv >sv

Le résultat des commandes ci-dessus serait un fichier de traduction squelette (sv dans ce cas) contenant des entrées comme celles-ci :

msgid "Web Browser"
msgstr ""

Traduisez manuellement les champs msgstr vides.

Utiliser le fichier de traduction

Si vous utilisez les modules jgmenu-apps(1) ou jgmenu-ob(1), définissez simplement csv_i18n dans jgmenurc pour pointer directement vers un fichier-de-traduction ou un répertoire contenant des fichiers de traduction.

Dans des circonstances spéciales, vous pourriez souhaiter inclure i18n dans la tuyauterie de commande. Voici un exemple de la façon dont cela pourrait être construit :

<commande-générant-csv> \
    | jgmenu_run i18n <fichier-de-traduction> \
    | jgmenu --vsimple
