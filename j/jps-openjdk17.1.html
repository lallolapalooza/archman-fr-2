DESCRIPTIO

N

La commande jps liste les JVM Java HotSpot instrumentées sur le système cible. La commande est limitée à la remontée d'informations sur les JVM pour lesquelles elle dispose des permissions

d'accès.

Si la commande jps est exécutée sans spécifier de hostid, elle recherche alors les JVM instrumentées sur l'hôte local. Si elle est démarrée avec un hostid, elle recherche alors les JVM sur l'hôte indiqué, en utilisant le protocole et le port spécifiés. Un processus jstatd est supposé être en cours d'exécution sur l'hôte

cible.

La commande jps rapporte l'identifiant local de la JVM, ou lvmid, pour chaque JVM instrumentée trouvée sur le système cible. Le lvmid est généralement, mais pas nécessairement, l'identifiant de processus du système d'exploitation du processus JVM. Sans options, la commande jps liste le lvmid de chaque application Java suivi de la forme abrégée du nom de classe ou du nom de fichier jar de l'application. La forme abrégée du nom de classe ou du nom de fichier JAR omet les informations de paquet de la classe ou les informations de chemin du fichier

JAR.

La commande jps utilise le lanceur Java pour trouver le nom de classe et les arguments passés à la méthode main. Si la JVM cible est démarrée avec un lanceur personnalisé, alors le nom de la classe ou du fichier JAR et les arguments de la méthode main ne sont pas disponibles. Dans ce cas, la commande jps produit la chaîne Unknown pour le nom de classe ou le nom de fichier JAR, et pour les arguments de la méthode m

ain.

La liste des JVM produite par la commande jps peut être limitée par les permissions accordées à l'entité exécutant la commande. La commande ne liste que les JVM pour lesque

lles l'entité dispose des droits d'accès, tels que déterminés par les
mécanismes de contrôle d'accès spécifiques au système d'exploitation.

NAME

jps - Local JVM process status tool

SYNOPSIS

jps [ options ] [ host-identifier ]

OPTIONS

The jps command supports the following options:

-l
Output the full package name for the application's principal class or the full path to the application's JAR file, or the full path to the application executable.
-m
Output the arguments passed to the main method.
-v
Output the arguments passed to the JVM.
-q
Only output the LVMT IDs of the local JVMs.
-f
Output the full path to the command line that started the JVM.

DESCRIPTION

The jps command lists the instrumented Java Virtual Machine (JVM) processes. It provides information about running Java processes on the local machine, or on a remote machine if configured.

By default, jps outputs the LVMT ID and the name of the Java class or JAR file of the application. The LVMT ID is a unique identifier for the JVM process.

When listing remote JVMs, jps uses the Java Remote Method Invocation (RMI) registry and requires the jstatd daemon to be running on the remote host.

HOST IDENTIFIER

The host-identifier parameter specifies the target host. It can be either a hostname or an IP address. If the port is not specified, the default RMI registry port 1099 is used.

The format for specifying a remote host is:

hostname: port

If the host-identifier is omitted, jps will list the JVMs on the local host.

OUTPUT FORMAT OF THE JPS COMMAND

The output of the jps command typically consists of two columns:

LVMT ID Application Name
  • The LVMT ID is the process identifier of the JVM.
  • The Application Name is the name of the application running in the JVM. This can be the principal class name, the JAR file name, or the executable name, depending on the options used.

EXAMPLES

The following example lists the instrumented JVMs running on the remote host remote.domain. It assumes that the jstatd RMI server is running on the remote host on the default port (port 1099). It also assumes that the local host has appropriate permissions to access the remote host. This example includes the -l option to output the long form of the class names or JAR file names.


jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

The following example lists the instrumented JVMs on a remote host with a nondefault port for the RMI registry. This example assumes that the jstatd server, with an internal RMI registry bound to port 2002, is running on the remote host. This example also uses the -m option to include the arguments passed to the main method of each of the listed Java applications.


jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
