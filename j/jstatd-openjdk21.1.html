JSTATD(1) Commandes JDK JSTATD(1)

NOM

jstatd - surveiller la création et la terminaison des JVM HotSpot instrumentées

SYNTAXE

Note : Cette commande est expérimentale et non prise en charge.

jstatd [options]

options
Ceci représente les options de ligne de commande de jstatd. Voir Options pour la commande jstatd.

DESCRIPTION

La commande jstatd est une application serveur RMI qui surveille la création et la terminaison des JVM HotSpot instrumentées et fournit une interface permettant aux outils de surveillance à distance, jstat et jps, de s'attacher aux JVM en cours d'exécution sur l'hôte local et de collecter des informations sur le processus JVM.

Le serveur jstatd nécessite un registre RMI sur l'hôte local. Le serveur jstatd tente de s'attacher au registre RMI sur le port par défaut, ou sur le port que vous spécifiez avec l'option -p port. Si aucun registre RMI n'est trouvé, un nouveau sera créé dans l'application jstatd, lié au port indiqué par l'option -p port ou au port du registre RMI par défaut lorsque l'option -p port est omise. Vous pouvez empêcher la création d'un registre RMI interne en spécifiant l'option -nr.

OPTIONS POUR LA COMMANDE JSTATD

-nr
Cette option n'essaie pas de créer un registre RMI interne dans le processus jstatd lorsqu'un registre RMI existant n'est pas trouvé.
-p port
Cette option définit le numéro de port où le registre RMI est censé être trouvé, ou lorsqu'il n'est pas trouvé, créé si l'option -nr n'est pas spécifiée.
-r rmiport
Cette option définit le numéro de port auquel le connecteur RMI est lié. S'il n'est pas spécifié, un port disponible aléatoire est utilisé.
-n rminame
Cette option définit le nom auquel l'objet RMI distant est lié dans le registre RMI. Le nom par défaut est JStatRemoteHost. Si plusieurs serveurs jstatd sont démarrés sur le même hôte, le nom de l'objet RMI exporté pour chaque serveur peut être rendu unique en spécifiant cette option. Cependant, cela nécessite que le nom de serveur unique soit inclus dans les chaînes hostid et vmid du client de surveillance.
-Joption
Cette option passe une option Java au JVM, où l'option est l'une de celles décrites sur la page de référence du lanceur d'applications Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java.

SÉCURITÉ

Le serveur jstatd ne peut surveiller que les JVM pour lesquelles il dispose des autorisations d'accès natives appropriées. Par conséquent, le processus jstatd doit être exécuté avec les mêmes identifiants utilisateur que les JVM cibles. Certains identifiants utilisateur, tels que l'utilisateur root sous Linux et macOS, ont l'autorisation d'accéder à l'instrumentation exportée par n'importe quelle JVM sur le système. Un processus jstatd exécuté avec de tels identifiants peut surveiller n'importe quelle JVM sur le système, mais cela introduit des préoccupations de sécurité supplémentaires.

Le serveur jstatd ne fournit aucune authentification des clients distants. Par conséquent, l'exécution d'un processus serveur jstatd expose l'instrumentation exportée par toutes les JVM pour lesquelles le processus jstatd a des autorisations d'accès à tout utilisateur sur le réseau. Cette exposition peut être indésirable dans votre environnement, et par conséquent, les politiques de sécurité locales doivent être prises en compte avant de démarrer le processus jstatd, en particulier dans les environnements de production ou sur des réseaux non sécurisés.

Pour des raisons de sécurité, le serveur jstatd utilise un filtre d'objets RMI (RMI ObjectInputFilter) pour autoriser uniquement la désérialisation des classes essentielles.

Si vos préoccupations de sécurité ne peuvent pas être résolues, l'action la plus sûre est de ne pas exécuter le serveur jstatd et d'utiliser les outils jstat et jps localement. Cependant, lors de l'utilisation de jps pour obtenir une liste des JVM instrumentées, la liste n'inclura pas les JVM s'exécutant dans des conteneurs Docker.

INTERFACE DISTANTE

L'interface exportée par le processus jstatd est propriétaire et est susceptible d'être modifiée. Il est déconseillé aux utilisateurs et aux développeurs d'écrire en fonction de cette interface.

EXEMPLES

Les exemples suivants illustrent l'utilisation de la commande jstatd. Les scripts jstatd démarrent automatiquement le serveur en arrière-plan.

REGISTRE RMI INTERNE

Cet exemple montre comment démarrer une session jstatd avec un registre RMI interne. Cet exemple suppose qu'aucun autre serveur n'est lié au port du registre RMI par défaut (port 1099).

jstatd

REGISTRE RMI EXTERNE

Cet exemple démarre une session jstatd avec un registre RMI externe.


rmiregistry&
jstatd

Cet exemple démarre une session jstatd avec un serveur de registre RMI externe sur le port 2020.


jrmiregistry 2020&
jstatd -p 2020

Cet exemple démarre une session jstatd avec un serveur de registre RMI externe sur le port 2020 et un connecteur JMX lié au port 2021.


jrmiregistry 2020&
jstatd -p 2020 -r 2021

Cet exemple démarre une session jstatd avec un registre RMI externe sur le port 2020, lié à AlternateJstatdServerName.


rmiregistry 2020&
jstatd -p 2020 -n AlternateJstatdServerName

ARRÊTER LA CRÉATION DUN REGISTRE RMI INTRAPROCESSUS

Cet exemple démarre une session jstatd qui ne crée pas de registre RMI s'il n'en trouve pas. Cet exemple suppose qu'un registre RMI est déjà en cours d'exécution. Si aucun registre RMI n'est en cours d'exécution, un message d'erreur s'affichera.

jstatd -nr

ACTIVER LA JOURNALISATION RMI

Cet exemple démarre une session jstatd avec la journalisation RMI activée. Cette technique est utile comme aide au dépannage ou pour surveiller les activités du serveur.

jstatd -J-Djava.rmi.server.logCalls=true
