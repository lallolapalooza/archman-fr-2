NOM

jbgtopbm - convertisseur JBIG1 vers fichier bitmap portable

SYNTAXE

jbgtopbm [ options ] [ fichier-entrée | - [ fichier-sortie ]]

DESCRIPTION

Lit une entité image JBIG1 (BIE) à partir d'un fichier ou de l'entrée standard, la décompresse et génère un fichier bitmap portable (PBM).

JBIG1 est un algorithme de compression sans perte très efficace pour les images bi-niveaux (un bit par pixel), particulièrement adapté aux pages de documents numérisés.

Une image encodée JBIG1 peut être stockée dans plusieurs résolutions dans une ou plusieurs BIE. Toutes les couches de résolution sauf la plus basse sont stockées efficacement sous forme de différences par rapport à la couche de résolution inférieure. Les options -x et -y peuvent être utilisées pour arrêter la décompression à une taille d'image de sortie spécifiée. Avec l'option -m, le fichier d'entrée peut consister en plusieurs BIE concaténées contenant différentes couches de résolution croissantes de la même image.

Si plus d'un bit par pixel est stocké dans le fichier JBIG1, un fichier PGM sera produit.

OPTIONS

-
Un simple tiret au lieu d'un nom de fichier d'entrée fera en sorte que jbgtopbm lise les données depuis l'entrée standard au lieu d'un fichier.
-x nombre
Ne décoder que jusqu'à la couche de résolution la plus grande qui ne dépasse pas nombre pixels de largeur. Si aucune couche de résolution de ce type n'existe, utiliser la plus petite disponible.
-y nombre
Ne décoder que jusqu'à la couche de résolution la plus grande qui ne dépasse pas nombre pixels de hauteur. Si aucune couche de résolution de ce type n'existe, utiliser la plus petite disponible. Les options -x et -y peuvent également être utilisées conjointement, auquel cas la plus grande couche satisfaisant les deux limites sera sélectionnée.
-m
Traiter plusieurs BIE concaténées. S'il reste des octets après le dernier SDE dans la première BIE, alors avec cette option, jbgtopbm tentera de les décoder comme le début d'une autre BIE qui pourrait contenir des données de résolution plus élevée. Normalement, tout octet restant générera un message d'avertissement.
-b
Utiliser des valeurs binaires au lieu de mots de code Gray pour décoder les valeurs de pixels à partir de plusieurs plans de bits. Cette option n'a d'effet que si l'entrée a plus d'un plan de bits et qu'un fichier PGM est produit. Notez que le décodeur doit être utilisé dans le même mode que l'encodeur et ne peut pas déterminer à partir de la BIE si des mots de code Gray ou binaires ont été utilisés par l'encodeur.
-d
Diagnostiquer une seule BIE. Avec cette option, jbgtopbm affichera un résumé des informations d'en-tête trouvées dans le fichier d'entrée, suivi d'une liste de toutes les séquences de marqueurs PSCD et ESC rencontrées jusqu'à la fin du fichier. fichier est atteint.
-p nombre
Si l'entrée contient plusieurs plans de bits, n'extraire que le plan unique spécifié sous forme de fichier PBM. Le premier plan a le numéro 0.

BOGUES

L'utilisation de l'entrée standard et de la sortie standard pour les données binaires ne fonctionne que sur les systèmes où il n'y a pas de différence entre les flux binaires et textuels (par exemple, Unix). Sur d'autres systèmes (par exemple, MS-DOS), l'utilisation de l'entrée standard ou de la sortie standard peut entraîner l'insertion ou la suppression de caractères de contrôle tels que CR ou LF, ce qui endommagera les données binaires.

NORMES

Ce programme implémente l'algorithme de codage d'image JBIG1 tel que spécifié dans la norme ISO/IEC 11544:1993 et la recommandation ITU-T T.82(1993).

AUTEUR

Le programme jbgtopbm fait partie du package JBIG-KIT, qui a été développé par Markus Kuhn. La version la plus récente de cette bibliothèque portable JBIG1 et de cet ensemble d'outils est disponible sur http://www.cl.cam.ac.uk/~mgk25/jbigkit/.
