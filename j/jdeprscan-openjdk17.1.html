NOM

jdeprscan - outil d'analyse statique qui analyse un fichier jar (ou une autre agrégation de fichiers de classe) à la recherche d'utilisations d'éléments d'API obsolètes

SYNTAXE

jdeprscan [options] {répertoire|jar|classe}

options
Voir Options de la commande jdeprscan
répertoire|jar|classe
jdeprscan analyse chaque argument à la recherche d'utilisations d'API obsolètes. Les arguments peuvent être un :
•
répertoire : Répertoire
•
jar : Fichier JAR
•
classe : Nom de classe ou fichier de classe

Le nom de classe doit utiliser un point (.) comme séparateur. Par exemple :

java.lang.Thread

Pour les classes imbriquées, le caractère séparateur signe dollar $ doit être utilisé. Par exemple :

java.lang.Thread$State

Un fichier de classe peut également être nommé. Par exemple :

build/classes/java/lang/Thread$State.class

DESCRIPTION

L'outil jdeprscan est un outil d'analyse statique fourni par le JDK qui analyse un fichier JAR ou une autre agrégation de fichiers de classe à la recherche d'utilisations d'éléments d'API obsolètes. Les API obsolètes identifiées par l'outil jdeprscan sont uniquement celles qui sont définies par Java SE. Les API obsolètes définies par des bibliothèques tierces ne sont pas signalées.

Pour analyser un fichier JAR ou un ensemble de fichiers de classe, vous devez d'abord vous assurer que toutes les classes dont dépendent les classes analysées sont présentes dans le classpath. Définissez le classpath en utilisant l'option --class-path décrite dans Options de la commande jdeprscan. Généralement, vous utiliserez le même classpath que celui que vous utilisez lors de l'invocation de votre application.

Si jdeprscan ne parvient pas à trouver toutes les classes dépendantes, il générera un message d'erreur pour chaque classe manquante. Ces messages d'erreur sont généralement de la forme :

erreur : impossible de trouver la classe ...

Si ces erreurs se produisent, vous devez ajuster le classpath pour qu'il inclue toutes les classes dépendantes.

OPTIONS DE LA COMMANDE JDEPRSCAN

Les options suivantes sont disponibles :

--class-path chemin
Fournit un chemin de recherche pour la résolution des classes dépendantes.

chemin peut être un chemin de recherche composé d'un ou plusieurs répertoires séparés par le séparateur de chemin spécifique au système. Par exemple :

•
Linux et OS X :

--class-path /some/directory:/another/different/dir

Note :

Sur Windows, utilisez un point-virgule (;) comme séparateur au lieu d'un deux-points (:).

•
Windows :

--class-path \some\directory;\another\different\dir

--for-removal
Limite l'analyse ou la liste aux API obsolètes pour suppression. Ne peut pas être utilisé avec une valeur de version de 6, 7 ou 8.
--full-version
Affiche la chaîne de version complète de l'outil.
--help ou -h
Affiche un message d'aide complet.
--list ou -l
Affiche l'ensemble des API obsolètes. Aucune analyse n'est effectuée, donc aucun argument de répertoire, jar ou classe ne doit être fourni.
--release 6|7|8|9
Spécifie la version de Java SE qui fournit l'ensemble des API obsolètes pour l'analyse.
--verbose ou -v
Active la sortie de messages supplémentaires pendant le traitement.
--version
Affiche la chaîne de version abrégée de l'outil.

EXEMPLE DE SORTIE JDEPRSCAN

Le fichier JAR pour cette bibliothèque sera nommé de manière similaire à commons-math3-3.6.1.jar. Pour analyser ce fichier JAR à la recherche d'utilisations d'API obsolètes, exécutez la commande suivante :

jdeprscan commons-math3-3.6.1.jar

Cette commande produit plusieurs lignes de sortie. Par exemple, une ligne de sortie pourrait être :


classe org/apache/commons/math3/util/MathUtils utilise méthode obsolète java/lang/Double::<init>(D)V

Note :

Le nom de la classe est spécifié en utilisant le nom binaire séparé par des barres obliques comme décrit dans JVMS 4.2.1. C'est la forme utilisée en interne dans les fichiers de classe.

L'API obsolète qu'il utilise est une méthode de la classe java.lang.Double.

Le nom de la méthode obsolète est <init>, qui est un nom spécial signifiant que la méthode est en fait un constructeur. Un autre nom spécial est <clinit>, qui indique un initialiseur statique de classe.

Les autres méthodes sont répertoriées simplement par leur nom de méthode. Après le nom de la méthode se trouve la liste des arguments et le type de retour :

(D)V

Cela indique qu'elle prend un seul double (un primitif) et retourne void. Les types d'arguments et de retour peuvent devenir cryptiques. Par exemple, une autre ligne de sortie pourrait être :


classe org/apache/commons/math3/util/Precision utilise méthode obsolète java/math/BigDecimal::setScale(II)Ljava/math/BigDecimal;

Dans cette ligne de sortie, la méthode obsolète se trouve sur la classe java.math.BigDecimal, et la méthode est setScale(). Dans ce cas, (II) signifie qu'elle prend deux arguments int. Le Ljava/math/BigDecimal; après les parenthèses signifie qu'elle retourne une référence à java.math.BigDecimal.

NAME

jdeprscan - Scanner d'API dépréciées

SYNOPSIS

jdeprscan [options] class/package

DESCRIPTION

Le scanner jdeprscan analyse des fichiers de classes Java à la recherche d'API dépréciées.

Ce scanner est similaire à javac, jar, javadoc, et jlink dans la mesure où il est basé sur le compilateur Java. Il analyse les API dépréciées des fichiers de classes cibles, et imprime un message sur la sortie standard chaque fois qu'une API dépréciée est utilisée. Par défaut, il ne génère aucune sortie si aucune API dépréciée n'est trouvée.

Il est utilisé pour analyser l'utilisation des API dépréciées dans des applications qui ciblent une version antérieure du JDK.

Les options suivantes sont disponibles :

--class-path classpath
Spécifie le chemin des fichiers de classes à analyser. Les entrées du chemin sont séparées par des séparateurs de chemin spécifiques au système d'exploitation. L'option -cp est un synonyme de --class-path.
--classpath classpath
Synonyme de --class-path.
--release version
Spécifie la version des API dépréciées à scanner. La valeur de version est un entier représentant la version du JDK, par exemple, 7, 8 ou 9. Par défaut, la valeur est celle du JDK en cours d'exécution.
--help
Affiche un message d'aide et quitte.
--list-deprecated
Liste toutes les API dépréciées disponibles dans le JDK spécifié. Les API dépréciées sont les types, méthodes, champs et méthodes de constructeur.
--scan-all-errors
S'il est spécifié, jdeprscan imprime tous les messages d'erreur, même si une API dépréciée est utilisée sans avertissement. Par défaut, ce comportement est désactivé.

OPTIONS FOR THE JDEPRSCAN COMMAND

jdeprscan prend en charge les options suivantes :

--add-exports innersubset=target
Exporte le package donné innersubset vers le module cible target. Cela doit être utilisé avec --release.
--limit-modules modulelist
Limite le jeu de modules accessibles à celui spécifié par modulelist. Cela doit être utilisé avec --release.

EXAMPLE OF JDEPRSCAN OUTPUT

La sortie suivante est générée par l'exécution de jdeprscan sur la classe example.Deprecations dans l'exemple de code ci-dessous.

import java.rmi.RMISecurityManager;
public class Deprecations {
    public static void main(String[] args) {
        RMISecurityManager sm = new RMISecurityManager();
        Boolean b2 = new Boolean(true);
    }
}

La classe complète est compilée sans avertissements dans JDK 7.

Si vous exécutez jdeprscan sur un système avec JDK 9, vous voyez :

$ jdeprscan --class-path classes --release 7 example.Deprecations
(pas de sortie)

Exécutez jdeprscan avec une valeur de version de 8 :

$ jdeprscan --class-path classes --release 8 example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated

Exécutez jdeprscan sur JDK 9 :

$ jdeprscan --class-path classes example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method java/lang/Boolean <init> (Z)V deprecated

JDEPRSCAN ANALYSIS CAN BE VERSION-SPECIFIC

Le scanner jdeprscan analyse l'utilisation des API dépréciées pour une version cible donnée. Cela signifie qu'une application peut compiler sans avertissement pour une version donnée, mais générer des avertissements pour une autre version.

Par exemple, l'API RMISecurityManager a été dépréciée en Java 8, et l'API Boolean(boolean) a été dépréciée en Java 9. Si vous exécutez jdeprscan sur une application qui utilise ces deux API, la sortie dépendra de la valeur fournie à l'option --release.
