NOM

jose-jws-sig - Signe une charge utile en utilisant un ou plusieurs JWK

SYNTAXE

jose jws sig [-i JWS] [-I PAY] [-s SIG] -k JWK [-o JWS] [-O PAY] [-c]

APERÇU

La commande jose jws sig signe une charge utile à l'aide d'un ou plusieurs JWK. La charge utile peut être fournie soit sous sa forme décodée (-I), soit intégrée dans un JWS existant (-i).

Un JWS détaché peut être créé en spécifiant l'option -O. Dans ce cas, la charge utile décodée sera écrite dans la sortie spécifiée et ne sera pas incluse dans le JWS.

Si une seule clé est utilisée (-k), le JWS résultant peut être produit en sérialisation compacte en utilisant l'option -c.

Cette commande utilise une approche basée sur des modèles pour construire un JWS. Vous pouvez spécifier des modèles du JWS lui-même (-i) ou pour l'objet JWS Signature (-r). Les attributs spécifiés dans l'un de ces modèles apparaîtront inchangés dans la sortie. Une exception à cette règle est que l'en-tête protégé du JWS doit être spécifié sous sa forme décodée dans le modèle d'objet de signature JWS. Cette commande l'encoderera automatiquement dans le cadre du processus de chiffrement.

Si vous spécifiez un paramètre d'en-tête JOSE (via les options -i ou -r) qui affecte la construction du JWE, cette commande tentera de se comporter conformément à ce paramètre comme s'il s'agissait d'une configuration. Actuellement, jose modifiera son comportement pour le paramètre d'en-tête JOSE "alg" (voir RFC 7515 Section 4.1.1).

Cependant, il n'est pas nécessaire de fournir de modèles : jose jwe enc remplira automatiquement le paramètre "alg" en déduisant l'algorithme correct à partir des JWK d'entrée fournis. Par conséquent, les options -i et -r doivent généralement être utilisées pour fournir des métadonnées JWE étendues.

Il est possible de spécifier un JWS existant comme entrée de modèle JWS (-i). Cela permet d'ajouter de nouvelles signatures à un JWS existant.

OPTIONS

•-i JSON, --input=JSON : Analyser le modèle JWS à partir de JSON
•-i FICHIER, --input=FICHIER : Lire le modèle JWS depuis FICHIER
•-i -, --input=- : Lire le modèle JWS depuis l'entrée standard
•-I FICHIER, --detached=FICHIER : Lire la charge utile décodée depuis FICHIER
•-I -, --detached=- : Lire la charge utile décodée depuis l'entrée standard
•-s JSON, --signature=JSON : Analyser le modèle de signature JWS à partir de JSON
•-s FICHIER, --signature=FICHIER : Lire le modèle de signature JWS depuis FICHIER
•-s -, --signature=- : Lire le modèle de signature JWS depuis l'entrée standard
•-k FICHIER, --key=FICHIER : Lire JWK(Set) depuis FICHIER
•-k -, --key=- : Lire JWK(Set) depuis l'entrée standard
•-o FICHIER, --output=FICHIER : Écrire JWS dans FICHIER
•-o -, --output=- : Écrire JWS sur stdout (par défaut)
•-O FICHIER, --detach=FICHIER : Détacher la charge utile et la décoder dans FICHIER
•-O -, --detach=- : Détacher la charge utile et la décoder sur la sortie standard
•-c, --compact : Produire JWS en utilisant la sérialisation compacte

EXEMPLES

Signer des données avec une clé symétrique en utilisant la sérialisation JSON JWE :

$ jose jwk gen -i '{"alg":"HS256"}' -o key.jwk
$ jose jws sig -I msg.txt -k key.jwk -o msg.jws

Signer des données en utilisant la sérialisation compacte JWE détachée :

$ jose jws sig -I msg.txt -k key.jwk -O /dev/null -c -o msg.jws

Signer avec deux clés :

$ jose jwk gen -i '{"alg":"ES256"}' -o ec.jwk
$ jose jwk gen -i '{"alg":"RS256"}' -o rsa.jwk
$ jose jws sig -I msg.txt -k ec.jwk -k rsa.jwk -o msg.jws
