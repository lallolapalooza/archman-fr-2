JDEPRSCAN(1) Commandes JDK JDEPRSCAN(1)

NOM

jdeprscan - outil d'analyse statique qui scanne un fichier jar (ou une autre agrégation de fichiers de classe) à la recherche d'utilisations d'éléments d'API obsolètes

SYNTAXE

jdeprscan [options] {rép|jar|classe}

options
Voir Options pour la commande jdeprscan
rép|jar|classe
jdeprscan analyse chaque argument pour détecter les utilisations d'API obsolètes. Les arguments peuvent être un :
•
rép : Répertoire
•
jar : Fichier JAR
•
classe : Nom de classe ou fichier de classe

Le nom de classe doit utiliser le point (.) comme séparateur. Par exemple :

java.lang.Thread

Pour les classes imbriquées, le caractère séparateur dollar ($) doit être utilisé. Par exemple :

java.lang.Thread$State

Un fichier de classe peut également être nommé. Par exemple :

build/classes/java/lang/Thread$State.class

DESCRIPTION

L'outil jdeprscan est un outil d'analyse statique fourni par le JDK qui scanne un fichier JAR ou une autre agrégation de fichiers de classe à la recherche d'utilisations d'éléments d'API obsolètes. Les API obsolètes identifiées par l'outil jdeprscan sont uniquement celles qui sont définies par Java SE. Les API obsolètes définies par des bibliothèques tierces ne sont pas signalées.

Pour analyser un fichier JAR ou un ensemble de fichiers de classe, vous devez d'abord vous assurer que toutes les classes dont les classes analysées dépendent sont présentes dans le chemin de classes. Définissez le chemin de classes à l'aide de l'option --class-path décrite dans Options pour la commande jdeprscan. Généralement, vous utiliserez le même chemin de classes que celui que vous utilisez lors de l'invocation de votre application.

Si jdeprscan ne parvient pas à trouver toutes les classes dépendantes, il générera un message d'erreur pour chaque classe manquante. Ces messages d'erreur sont généralement de la forme :

error: cannot find class ...

Si ces erreurs se produisent, vous devez ajuster le chemin de classes pour qu'il inclue toutes les classes dépendantes.

OPTIONS POUR LA COMMANDE JDEPRSCAN

Les options suivantes sont disponibles :

--class-path chemin
Fournit un chemin de recherche pour la résolution des classes dépendantes.

chemin peut être un chemin de recherche composé d'un ou plusieurs répertoires séparés par le séparateur de chemin spécifique au système. Par exemple :

•
Linux et macOS :

--class-path /some/directory:/another/different/dir

Remarque :

Sous Windows, utilisez un point-virgule (;) comme séparateur au lieu d'un deux-points (:).

•
Windows :

--class-path \some\directory;\another\different\dir

--for-removal
Limite l'analyse ou la liste aux API qui sont obsolètes pour suppression. Ne peut pas être utilisé avec une valeur de version de 6, 7 ou 8.
--full-version
Affiche la chaîne de version complète de l'outil.
--help ou -h
Affiche un message d'aide complet.
--list ou -l
Affiche l'ensemble des API obsolètes. Aucune analyse n'est effectuée, donc aucun argument de répertoire, jar ou classe ne doit être fourni.
--release 6|7|8|9
Spécifie la version Java SE qui fournit l'ensemble des API obsolètes pour l'analyse.
--verbose ou -v
Active la sortie de messages supplémentaires pendant le traitement.
--version
Affiche la chaîne de version abrégée de l'outil.

EXEMPLE DE SORTIE JDEPRSCAN

Le fichier JAR de cette bibliothèque sera nommé de manière similaire à commons-math3-3.6.1.jar. Pour analyser ce fichier JAR à la recherche d'utilisations d'API obsolètes, exécutez la commande suivante :

jdeprscan commons-math3-3.6.1.jar

Cette commande produit plusieurs lignes de sortie. Par exemple, une ligne de sortie pourrait être :

class org/apache/commons/math3/util/MathUtils uses deprecated method java/lang/Double::<init>(D)V

Remarque :

Le nom de classe est spécifié en utilisant le nom binaire séparé par des barres obliques, comme décrit dans JVMS 4.2.1. C'est la forme utilisée en interne dans les fichiers de classe.

L'API obsolète utilisée est une méthode de la classe java.lang.Double.

Le nom de la méthode obsolète est <init>, qui est un nom spécial signifiant que la méthode est en fait un constructeur. Un autre nom spécial est <clinit>, qui indique un initialiseur statique de classe.

D'autres méthodes sont répertoriées simplement par leur nom de méthode. Après le nom de la méthode se trouve la liste des arguments et le type de retour :

(D)V

Cela indique qu'elle ne prend qu'une seule valeur double (une primitive) et ne retourne rien (void). Les types des arguments et des retours peuvent devenir cryptiques. Par exemple, une autre ligne de sortie pourrait être :

class org/apache/commons/math3/util/Precision uses deprecated method java/math/BigDecimal::setScale(II)Ljava/math/BigDecimal;

Dans cette ligne de sortie, la méthode obsolète se trouve dans la classe java.math.BigDecimal, et la méthode est setScale(). Dans ce cas, (II) signifie qu'elle prend deux arguments int. Le Ljava/math/BigDecimal; après les parenthèses signifie qu'elle retourne une référence à java.math.BigDecimal.

L'ANALYSE JDEPRSCAN PEUT ETRE SPECIFIQUE A UNE VERSION

Vous pouvez utiliser jdeprscan par rapport aux trois versions JDK précédentes. Par exemple, si vous utilisez JDK 9, vous pouvez vérifier par rapport aux versions JDK 8, 7 et 6.

À titre d'exemple, regardez cet extrait de code :

public class Deprecations {
   SecurityManager sm = new RMISecurityManager();    // deprecated in 8
   Boolean b2 = new Boolean(true);          // deprecated in 9
}

La classe complète compile sans avertissements dans JDK 7.

Si vous exécutez jdeprscan sur un système avec JDK 9, vous verrez :

$ jdeprscan --class-path classes --release 7 example.Deprecations
(pas de sortie)

Exécutez jdeprscan avec une valeur de version de 8 :

$ jdeprscan --class-path classes --release 8 example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated

Exécutez jdeprscan sur JDK 9 :

$ jdeprscan --class-path classes --release 9 example.Deprecations
class example/Deprecations uses type java/lang/Boolean deprecated
class example/Deprecations uses method in type java/lang/Boolean deprecated

NAME

jdeprscan - outil d'analyse des API obsolètes du JDK

SYNOPSIS

jdeprscan [OPTIONS] CLASS_PATH CLASS_NAME

DESCRIPTION

jdeprscan est un outil d'analyse qui vérifie les classes Java pour l'utilisation d'API obsolètes. Il peut être utilisé pour identifier les endroits dans votre code qui dépendent de méthodes ou de classes marquées comme obsolètes dans le JDK. Ceci est utile pour la maintenance du code et pour s'assurer de la compatibilité avec les futures versions de Java.

OPTIONS FOR THE JDEPRSCAN COMMAND

--class-path classes
Spécifie le chemin des classes à analyser. Vous pouvez fournir plusieurs chemins séparés par des points-virgules.

EXAMPLE OF JDEPRSCAN OUTPUT

Voici un exemple de sortie de jdeprscan analysant une classe nommée example.Deprecations:

prscan --class-path classes example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method java/lang/Boolean <init> (Z)V deprecated

Dans cet exemple, la classe example.Deprecations utilise des types et des méthodes qui sont marqués comme obsolètes dans le JDK.

JDEPRSCAN ANALYSIS CAN BE VERSION-SPECIFIC

L'analyse effectuée par jdeprscan dépend de la version du JDK utilisée. Les API marquées comme obsolètes peuvent varier entre les différentes versions du JDK. Il est donc recommandé d'utiliser la version de jdeprscan qui correspond à la version du JDK pour laquelle vous effectuez l'analyse.
