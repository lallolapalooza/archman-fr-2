NOM

llvm-reduce - Réducteur automatique de cas de test LLVM.

SYNTAXE

llvm-reduce [options] [entrée...]

DESCRIPTION

L'outil llvm-reduce est un projet qui peut être utilisé pour réduire la taille des cas de test LLVM. Il fonctionne en supprimant le code redondant ou inutile des cas de test LLVM, tout en préservant leur capacité à détecter les bugs.

Si entrée est "-", llvm-reduce lit depuis l'entrée standard. Sinon, il lira depuis les noms de fichiers spécifiés.

LLVM-Reduce est un outil utile pour réduire la taille et la complexité des cas de test LLVM, facilitant ainsi l'identification et le débogage des problèmes dans l'infrastructure du compilateur LLVM.

OPTIONS GÉNÉRALES

--help
Affiche les options disponibles (--help-hidden pour plus d'options).
--abort-on-invalid-reduction
Arrêter si une réduction entraîne un IR invalide.
--in-place
ATTENTION : Cette option remplacera votre fichier d'entrée par la version réduite !
--ir-passes=<chaîne>
Une description textuelle du pipeline de passes, identique à ce qui est passé à opt -passes.
-j <entier_non_signé>
Nombre maximum de threads à utiliser pour traiter les blocs. Définir à 1 pour désactiver le parallélisme.
--max-pass-iterations=<entier>
Nombre maximum de fois où le jeu complet de passes delta sera exécuté (défaut=5).
--mtriple=<chaîne>
Définir le triple de destination.
--preserve-debug-environment
Ne pas désactiver les fonctionnalités utilisées pour le débogage des crashs (rapports de crash, llvm-symbolizer et dumps de noyau).
--print-delta-passes
Imprimer la liste des passes delta, pouvant être passée à --delta-passes en tant que liste séparée par des virgules.
--skip-delta-passes=<chaîne>
Passes delta à ne pas exécuter, séparées par des virgules. Par défaut, tous les passes delta sont exécutés.
--starting-granularity-level=<entier_non_signé>
Nombre de fois où les blocs seront divisés avant le premier test.

Note : La granularité fait référence au niveau de détail auquel le processus de réduction opère. Une granularité plus faible signifie que le processus de réduction opère à un niveau plus grossier, tandis qu'une granularité plus élevée signifie qu'il opère à un niveau plus fin.

--test=<chaîne>
Nom du test d'intérêt à exécuter.
--test-arg=<chaîne>
Arguments passés au test d'intérêt.
--verbose
Afficher des informations de débogage supplémentaires.
--write-tmp-files-as-bitcode
Écrire toujours les fichiers temporaires en tant que bitcode au lieu d'IR textuel.
-x={ir|mir}
Langage d'entrée : ir ou mir.

STATUT DE SORTIE

llvm-reduce renvoie 0 en cas de fonctionnement normal. Il renvoie un code de sortie non nul en cas d'erreur. Renvoie 2 si le test d'intérêt a signalé que l'entrée initiale n'était pas intéressante.

EXEMPLE

llvm-reduce peut être utilisé pour simplifier un test qui provoque un crash du compilateur.

Par exemple, supposons que opt plante sur le fichier IR test.ll avec le message d'erreur Assertion failed at line 1234 of WhateverFile.cpp, lors de l'exécution en mode -O2.

Le cas de test de test.ll peut être réduit en appelant la commande suivante :

$(LLVM_BUILD_FOLDER)/bin/llvm-reduce --test=script.sh <chemin vers>/test.ll

Le script shell passé à l'option test consiste en ce qui suit :

$(LLVM_BUILD_FOLDER)/bin/opt -O2 -disable-output $1 \
  |& grep "Assertion failed at line 1234 of WhateverFile.cpp"

(Dans ce script, grep renvoie 0 s'il trouve la chaîne, et cela devient le statut de l'ensemble du script.)

Cet exemple peut être généralisé à d'autres outils qui traitent des fichiers IR, par exemple llc.
