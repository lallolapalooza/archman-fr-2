NOM

llvm-profdata - Outil de données de profil

SYNTAXE

llvm-profdata commande [arguments...]

DESCRIPTION

L'outil llvm-profdata est une petite utilitaire pour travailler avec des fichiers de données de profil.

COMMANDES

  • merge
  • show
  • overlap
  • order

MERGE

SYNTAXE

llvm-profdata merge [options] [nom_de_fichier...]

DESCRIPTION

llvm-profdata merge prend plusieurs fichiers de données de profil générés par l'instrumentation PGO et les fusionne en un seul fichier de données de profil indexé.

Par défaut, les données de profil sont fusionnées sans modification. Cela signifie que l'importance relative de chaque fichier d'entrée est proportionnelle au nombre d'échantillons ou de comptes qu'il contient. En général, les entrées d'une exécution d'entraînement plus longue seront interprétées comme étant relativement plus importantes qu'une exécution plus courte. Selon la nature des exécutions d'entraînement, il peut être utile d'ajuster le poids attribué à chaque fichier d'entrée en utilisant l'option -weighted-input.

Les profils passés via -weighted-input, -input-files, ou via des arguments positionnels sont traités une fois pour chaque fois qu'ils sont vus.

OPTIONS

--help
Affiche un résumé des options de ligne de commande.
--output=<sortie>, -o
Spécifie le nom du fichier de sortie. Sortie ne peut pas être - car les données de profil indexées résultantes ne peuvent pas être écrites sur la sortie standard.
--weighted-input=<poids,nom_de_fichier>
Spécifie un nom de fichier d'entrée avec un poids. Les comptes de profil du nom_de_fichier fourni seront mis à l'échelle (multipliés) par le poids fourni, où poids est un entier décimal >= 1. Les fichiers d'entrée spécifiés sans utiliser cette option se voient attribuer un poids par défaut de 1. Des exemples sont montrés ci-dessous.
--input-files=<chemin>, -f
Spécifie un fichier contenant une liste de fichiers à fusionner. Les entrées de ce fichier sont séparées par des nouvelles lignes. Les lignes commençant par '#' sont ignorées. Les entrées peuvent être de la forme <nom_de_fichier> ou <poids>,<nom_de_fichier>.
--remapping-file=<chemin>, -r
Spécifie un fichier contenant un remappage des noms de symboles dans le profil d'entrée vers les noms de symboles qui doivent être utilisés dans le profil de sortie. Le fichier doit contenir des lignes de la forme <symbole_entree> <symbole_sortie>. Les lignes vides et les lignes commençant par # sont ignorées.

L'outil llvm-cxxmap <> peut être utilisé pour générer le fichier de remappage de symboles.

--instr (par défaut)
Spécifie que le profil d'entrée est basé sur l'instrumentation.
--sample
Spécifie que le profil d'entrée est basé sur des échantillons.

Le format du fichier généré peut être produit de l'une des trois manières suivantes :

--binary (par défaut)

Émet le profil en utilisant un encodage binaire. Pour les profils basés sur l'instrumentation, le format de sortie est le format binaire indexé.

--extbinary

Émet le profil en utilisant un encodage binaire extensible. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons. L'encodage binaire extensible peut être plus compact avec la compression activée et peut être chargé plus rapidement que l'encodage binaire par défaut.

--text

Émet le profil en mode texte. Cette option peut également être utilisée avec des profils basés sur des échantillons et sur l'instrumentation. Lorsque cette option est utilisée, le profil sera déversé dans le format texte qui peut être analysé par le lecteur de profil.

--gcc

Émet le profil en utilisant le format gcov de GCC (Pas encore pris en charge).

--sparse[=vrai|faux]
N'émet pas les enregistrements de fonctions avec un nombre d'exécutions de 0. Ne peut être utilisé qu'en conjonction avec -instr. Par défaut, la valeur est faux, car cela peut empêcher l'optimisation du compilateur pendant PGO.
--num-threads=<N>, -j
Utilise N threads pour effectuer la fusion des profils. Lorsque N=0, llvm-profdata détecte automatiquement un nombre approprié de threads à utiliser. C'est le défaut.
--failure-mode=[any|all]
Définit le mode d'échec. Il existe deux options : 'any' fait échouer la commande de fusion si des profils sont invalides, et 'all' fait échouer la commande de fusion uniquement si tous les profils sont invalides. Si 'all' est défini, les informations provenant de profils invalides sont exclues du produit fusionné final. Le mode d'échec par défaut est 'any'.
--prof-sym-list=<chemin>
Spécifie un fichier contenant une liste de symboles pour générer une liste de symboles de profil dans le profil. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons au format extbinary. Les entrées de ce fichier sont séparées par des nouvelles lignes.
--compress-all-sections=[true|false]
Compresse toutes les sections lors de l'écriture du profil. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons au format extbinary.
--use-md5=[true|false]
Utilise MD5 pour représenter la chaîne dans la table des noms lors de l'écriture du profil. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons au format extbinary.
--gen-partial-profile=[true|false]
Marque le profil comme étant un profil partiel qui ne fournit qu'une couverture de profil partielle pour la cible optimisée. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons au format extbinary.
--split-layout=[true|false]
Divise la section des données de profil en deux, l'une contenant les profils d'échantillons avec les fonctions inline, et l'autre non. Cette option ne peut être utilisée qu'avec des profils basés sur des échantillons au format extbinary.
--convert-sample-profile-layout=[nest|flat]
Convertit le profil fusionné en un profil avec une nouvelle disposition. Les dispositions prises en charge sont nest (profil imbriqué, l'entrée doit être un profil plat CS) et flat (profil avec les inlineurs imbriqués aplatis).
--supplement-instr-with-sample=<fichier>
Complète un profil d'instrumentation avec un profil d'échantillons. Le profil d'échantillons est l'entrée du drapeau. La sortie sera au format ins

llvm-profdata - LLVM instrumentation and profiling data tool

 LLVM  llvm-profdata  Manual

NAME

llvm-profdata - LLVM instrumentation and profiling data tool

SYNOPSIS

llvm-profdata merge [options] [filenames...]

llvm-profdata show [options] [filename]

DESCRIPTION

The llvm-profdata utility is a tool for processing LLVM profile data files. It supports merging multiple profile data files and displaying the information contained within them.

COMMANDS

MERGE

The merge command merges multiple profile data files into a single profile data file. This is useful when you have collected profile data from multiple runs of your program and want to combine them for more accurate profiling.

SHOW

The show command displays the information contained in a profile data file. You can use it to inspect the profile counts for specific functions or to get a summary of the profile data.

MERGE OPTIONS

--threads=<int>
Number of threads to use for merging the profile data. Defaults to the number of logical cores on the system.
--output=<output>, -o
Specify the output file name. If output is - or it isn't specified, then the output is sent to standard output.
--input=<input>
Path to the input profile data file. This option can be used multiple times to specify multiple input files. If this option is not used, the profile data files will be read from the command line arguments.
--weighted-input=<string>
Specifies an input file and a corresponding weight. The format is 
--weighted-input=<weight>,<filename>
This allows you to scale the counts from specific input files. This option can be used multiple times. It is equivalent to specifying multiple 
--input
options and then using the 
--weighted-list
option. Useful for programmatic invocation.
--weighted-list=<input>
A file containing a list of input files and their weights. The format is one entry per line: 
<weight>,<filename>
This option can be used multiple times.
--collapse-paths
Collapse equivalent profile paths into a single entry. This can reduce the size of the output profile file, especially when dealing with instrumentation-based profiles.
--object-suffix=<string>
String to be appended to object file names when processing the profile. This is useful when you have multiple versions of the same object file with different suffixes (e.g., for different architectures).
--instr
Treat the input profile data as instrumentation-based profile data.
--sample
Treat the input profile data as sample-based profile data.
--sparse
Use sparse data structures for the profile data. This can significantly reduce memory usage when the profile data is sparse.
--zero-counter-threshold=<float>
For functions that are cold in the instrumentation profile but hot in the sample profile, if the ratio of the number of zero counters divided by the total number of counters is above the threshold, the profile of the function will be considered harmful to performance and will be dropped.
--instr-prof-cold-threshold=<int>
User-specified cold threshold for instrumentation profile, which will override the cold threshold obtained from the profile summary.
--suppl-min-size-threshold=<int>
If the size of a function is smaller than the threshold, it is assumed to be inlined by the PGO early inliner and will not be adjusted based on the sample profile.
--debug-info=<path>
Specify the executable or .dSYM containing debug information for the raw profile. When --debug-info-correlate or --profile-correlate=debug-info was used for instrumentation, use this option to correlate the raw profile.
--binary-file=<path>
Specify the executable containing profile data and profile name sections for the raw profile. When -profile-correlate=binary was used for instrumentation, use this option to correlate the raw profile.
--debuginfod
Use debuginfod to find associated executables containing profile data and name sections for the raw profiles to correlate them. When -profile-correlate=binary was used for instrumentation, this option can be used for correlation.
--debug-file-directory=<dir>
Use provided local directories to search for executables containing profile data and name sections for the raw profiles to correlate them. When -profile-correlate=binary was used for instrumentation, this option can be used for correlation.
--correlate=<kind>
Specify the correlation kind (debug_info or binary) to use when -debuginfod or -debug-file-directory=<dir> option is provided.
--temporal-profile-trace-reservoir-size
The maximum number of temporal profile traces to be stored in the output profile. If more traces are added, reservoir sampling will be used to select which traces to keep. Note that changing this value between different merge invocations on the same indexed profile could result in sample bias. The default value is 100.
--temporal-profile-max-trace-length
The maximum number of functions in a single temporal profile trace. Longer traces will be truncated. The default value is 1000.
--function=<string>
Only keep functions matching the regex in the output; all others are erased from the profile.
--no-function=<string>
Remove functions matching the regex from the profile. If both --function and --no-function are specified and a function matches both, it is removed.

EXAMPLES

Basic Usage

Merge three profiles:

llvm-profdata merge foo.profdata bar.profdata baz.profdata -output merged.profdata

Weighted Input

The input file foo.profdata is especially important, multiply its counts by 10:

llvm-profdata merge --weighted-input=10,foo.profdata bar.profdata baz.profdata --output merged.profdata

Exactly equivalent to the previous invocation (explicit form; useful for programmatic invocation):

llvm-profdata merge --weighted-input=10,foo.profdata --weighted-input=1,bar.profdata --weighted-input=1,baz.profdata --output merged.profdata

SHOW

SYNOPSIS

llvm-profdata show [options] [filename]

DESCRIPTION

llvm-profdata show takes a profile data file and displays the information about the profile counters for this file and for any of the specified function(s).

If filename is omitted or is -, then llvm-profdata show reads its input from standard input.

OPTIONS

--all-functions
Print details for every function.
--binary-ids
Print embedded binary ids in a profile.
--counts
Print the counter values for the displayed functions.
--show-format=<text|json|yaml>
Emit output in the selected format if supported by the provided profile type.
--function=<string>
Print details for a function if the function's name contains the given string.
--help
Print a summary of command line options.
--output=<output>, -o
Specify the output file name. If output is - or it isn't specified, then the output is sent to standard output.
--instr (default)
Specify that the input profile is an instrumentation-based profile.
--text
Instruct the profile dumper to show profile counts in the text format of the instrumentation-based profile data representation. By default, the profile information is dumped in a more human readable form (also in text) with annotations.
--topn=<n>
Instruct the profile dumper to show the top n functions with the hottest basic blocks in the summary section. By default, the topn functions are not dumped.
--sample
Specify that the input profile is a sample-based profile.
--memop-sizes
Show the profiled sizes of the memory intrinsic calls for shown functions.
--value-cutoff=<n>
Show only those functions whose max count values are greater or equal to n. By default, the value-cutoff is set to 0.
--list-below-cutoff
Only output names of functions whose max count value are below the cutoff value.
--profile-version
Print profile version.
--showcs
Only show context sensitive profile counts. The default is to filter all context sensitive profile counts.
--show-prof-sym-list=[true|false]
Show profile symbol list if it exists in the profile. This option is only meaningful for sample-based profile in extbinary format.
--show-sec-info-only=[true|false]
Show basic information about each section in the profile. This option is only meaningful for sample-based profile in extbinary format.
--debug-info=<path>
Specify the executable or .dSYM that contains debug info for the raw profile. When --debug-info-correlate or --profile-correlate=debug-info was used for instrumentation, use this option to show the correlated functions from the raw profile.
--covered
Show only the functions that have been executed, i.e., functions with non-zero counts.

OVERLAP

SYNTHÈSE

llvm-profdata overlap [options] [fichier de profil de base] [fichier de profil de test]

DESCRIPTION

llvm-profdata overlap prend deux fichiers de données de profil et affiche le chevauchement de la distribution des compteurs entre les fichiers entiers et entre les fonctions spécifiées.

Dans cette commande, chevauchement est défini comme suit : Supposons que le fichier de profil de base ait les comptes suivants : {c1_1, c1_2, ..., c1_n, c1_u_1, c2_u_2, ..., c2_u_s}, et que le fichier de profil de test ait {c2_1, c2_2, ..., c2_n, c2_v_1, c2_v_2, ..., c2_v_t}. Ici, c{1|2}_i (i = 1 .. n) sont des compteurs correspondants et c1_u_i (i = 1 .. s) et c2_v_i (i = 1 .. v) sont des compteurs non correspondants (ou existant uniquement dans) le fichier de profil de base et le fichier de profil de test, respectivement. Soit sum_1 = c1_1 + c1_2 + ... + c1_n + c1_u_1 + c2_u_2 + ... + c2_u_s, et sum_2 = c2_1 + c2_2 + ... + c2_n + c2_v_1 + c2_v_2 + ... + c2_v_t. chevauchement = min(c1_1/sum_1, c2_1/sum_2) + min(c1_2/sum_1, c2_2/sum_2) + ... + min(c1_n/sum_1, c2_n/sum_2).

La distribution de chevauchement résultante est un pourcentage, allant de 0,0 % à 100,0 %, où 0,0 % signifie qu'il n'y a pas de chevauchement et 100,0 % signifie un chevauchement parfait.

Voici un exemple : si le fichier de profil de base a les comptes {400, 600}, et le fichier de profil de test a les comptes correspondants {60000, 40000}. Le chevauchement est de 80 %.

OPTIONS

--function=<chaîne>
Affiche les détails d'une fonction si le nom de la fonction contient la chaîne donnée.
--help
Affiche un résumé des options de la ligne de commande.
--output=<sortie>, -o
Spécifie le nom du fichier de sortie. Si sortie est - ou n'est pas spécifié, la sortie est envoyée à la sortie standard.
--value-cutoff=<n>
Affiche uniquement les fonctions dont les valeurs de compte maximales sont supérieures ou égales à n. Par défaut, le cutoff de valeur est défini sur le maximum d'entiers non signés longs.
--cs
Affiche uniquement le chevauchement pour les comptes de profil sensibles au contexte. Par défaut, affiche les comptes de profil non sensibles au contexte.

ORDER

SYNTHÈSE

llvm-profdata order [options] [nom de fichier]

DESCRIPTION

llvm-profdata order utilise les traces de profilage temporel d'un profil pour trouver un ordre de fonctions qui réduit le nombre de fautes de page pour ces traces. Cette sortie peut être directement transmise à lld via --symbol-ordering-file= pour ELF ou -order-file pour Mach-O. Si les traces trouvées dans le profil sont représentatives du monde réel, cet ordre devrait améliorer les performances de démarrage.

OPTIONS

--help
Affiche un résumé des options de la ligne de commande.
--output=<sortie>, -o
Spécifie le nom du fichier de sortie. Si sortie est - ou n'est pas spécifié, la sortie est envoyée à la sortie standard.

STATUT DE SORTIE

llvm-profdata retourne 1 si la commande est omise ou invalide, s'il ne peut pas lire les fichiers d'entrée, ou s'il y a une discordance entre leurs données.
