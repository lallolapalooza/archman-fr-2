NOM

llvm-dwarfdump - exporter et vérifier les informations de débogage DWARF

SYNTAXE

llvm-dwarfdump [options] [fichier ...]

DESCRIPTION

llvm-dwarfdump analyse les sections DWARF dans les fichiers objets, les archives et les bundles .dSYM et affiche leur contenu sous forme lisible par l'homme. Seule la section .debug_info est affichée, sauf si l'une des options spécifiques à une section ou --all est spécifiée.

Si aucun fichier d'entrée n'est spécifié, a.out est utilisé à la place. Si - est utilisé comme fichier d'entrée, llvm-dwarfdump lit l'entrée depuis son flux d'entrée standard.

OPTIONS

-a, --all
Exporter toutes les sections DWARF supportées.
--arch=<architecture>
Exporter les informations de débogage DWARF pour l'architecture CPU spécifiée. Les architectures peuvent être spécifiées par nom ou par numéro. Cette option peut être spécifiée plusieurs fois, une fois pour chaque architecture désirée. Toutes les architectures CPU seront affichées par défaut.
-c, --show-children
Afficher les enfants d'une entrée d'information de débogage lors de l'impression sélective avec l'argument =<offset> de --debug-info, ou des options telles que --find ou --name.
--color
Utiliser des couleurs dans la sortie.
--error-display=<valeur>
Définir le niveau de détail et de résumé à afficher lors de la vérification. Implique --verify. Les valeurs supportées sont :

quiet - Afficher uniquement si des erreurs se sont produites. summary - Afficher seulement un résumé des erreurs trouvées. details - Afficher chaque erreur en détail mais pas de résumé. full - Afficher chaque erreur ainsi qu'un résumé. [défaut]

-f <nom>, --find=<nom>
Rechercher le texte exact <nom> dans les tables d'accélérateurs et imprimer les entrées d'information de débogage correspondantes. Lorsqu'il n'y a pas de tables d'accélérateurs ou que le nom de l'ENT que vous recherchez n'est pas trouvé dans les tables d'accélérateurs, essayez d'utiliser l'option plus lente mais plus complète --name.
-F, --show-form
Afficher les types de formulaire DWARF après les types d'attributs DWARF.
-h, --help
Afficher l'aide et l'utilisation de cette commande.
--help-list
Afficher l'aide et l'utilisation de cette commande sans regrouper les options par catégories.
-i, --ignore-case
Ignorer les différences de casse lors de l'utilisation de --name.
-n <nom>, --name=<nom>
Trouver et imprimer toutes les entrées d'information de débogage dont le nom (attribut DW_AT_name) est <nom>.
--lookup=<adresse>
Rechercher <adresse> dans les informations de débogage et imprimer les détails du fichier, de la fonction, du bloc et de la table de lignes.
-o <chemin>
Rediriger la sortie vers un fichier spécifié par <chemin>, où - représente le flux de sortie standard.
-p, --show-parents
Afficher les parents d'une entrée d'information de débogage lors de l'impression sélective avec l'argument =<offset> de --debug-info, ou des options telles que --find ou --name.
--parent-recurse-depth=<N>
Lors de l'affichage des parents des entrées d'information de débogage, ne les afficher que jusqu'à une profondeur maximale de <N>.
--quiet
À utiliser avec --verify pour ne pas émettre sur STDOUT.
-r <N>, --recurse-depth=<N>
Lors de l'affichage des entrées d'information de débogage, n'afficher les enfants que jusqu'à une profondeur maximale de <N>.
--show-section-sizes
Afficher les tailles de toutes les sections de débogage, exprimées en octets.
--show-sources
Afficher tous les fichiers source mentionnés dans les informations de débogage. Les chemins absolus sont donnés autant que possible.
--statistics
Collecter des métriques de qualité des informations de débogage et afficher les résultats sous forme de sortie JSON sur une seule ligne, lisible par machine. Le format de sortie est décrit dans la section ci-dessous (FORMAT DE LA SORTIE DES STATISTIQUES).
--summarize-types
Abréger la description des entrées d'unité de type.
-x, --regex
Traiter les chaînes <nom> comme des expressions régulières lors de la recherche avec --name. Si --ignore-case est également spécifié, l'expression régulière devient insensible à la casse.
-u, --uuid
Afficher l'UUID pour chaque architecture.
--diff
Exporter la sortie dans un format plus adapté à la comparaison des sorties DWARF de deux fichiers différents.
-v, --verbose
Afficher des informations détaillées lors de l'exportation. Cela peut aider à déboguer les problèmes DWARF.
--verify
Vérifier la structure des informations DWARF en vérifiant les chaînes d'unités de compilation, le graphe des relations des ENT, les plages d'adresses, et plus encore.
--verify-json=<chemin>
Exporter le résumé des erreurs au format JSON vers le fichier spécifié par <chemin>. Implique --verify. Le format de sortie est décrit dans la section ci-dessous (FORMAT DE LA SORTIE JSON DE VÉRIFICATION).
--version
Afficher la version de l'outil.
--debug-abbrev, --debug-addr, --debug-aranges, --debug-cu-index, --debug-frame [=<offset>], --debug-gnu-pubnames, --debug-gnu-pubtypes, --debug-info [=<offset>], --debug-line [=<offset>], --debug-line-str, --debug-loc [=<offset>], --debug-loclists [=<offset>], --debug-macro, --debug-names, --debug-pubnames, --debug-pubtypes, --debug-ranges, --debug-rnglists, --debug-str, --debug-str-offsets, --debug-tu-index, --debug-types [=<offset>], --eh-frame [=<offset>], --gdb-index, --apple-names, --apple-types, --apple-namespaces, --apple-objc
Exporter la section DWARF spécifiée par son nom. Seule la section .debug_info est affichée par défaut. OPTIONS

--debug-macro

Dump the .debug_macro and .debug_macinfo sections. If an offset is specified, only the entry at that offset will be dumped, else the entire section will be dumped.

--debug-macro

The --debug-macro option prints both the .debug_macro and the .debug_macinfo sections.

--debug-frame et --eh-frame

The --debug-frame and --eh-frame options are aliases, in cases where both sections are present one command outputs both.

@<FILE>
Read command-line options from <FILE>.

FORMAT OF STATISTICS OUTPUT

The --statistics option generates single-line JSON output representing quality metrics of the processed debug info. These metrics are useful to compare changes between two compilers, particularly for judging the effect that a change to the compiler has on the debug info quality.

The output is formatted as key-value pairs. The first pair contains a version number. The following naming scheme is used for the keys:

  • variables ==> local variables and parameters
  • local vars ==> local variables
  • params ==> formal parameters

For aggregated values, the following keys are used:

  • sum_of_all_variables(...) ==> the sum applied to all variables
  • #bytes ==> the number of bytes
  • #variables - entry values ... ==> the number of variables excluding the entry values etc.

FORMAT OF VERIFY JSON OUTPUT

The format of the JSON output created by the --verify-json is:

{
  "error-categories": {
    "<first category description>": {"count": 1234},
    "<next category description>": {"count": 4321}
  },
  "error-count": 5555
}

The following is generated if there are no errors reported:

{
  "error-categories": {},
  "error-count": 0
}

EXIT STATUS

llvm-dwarfdump returns 0 if the input files were parsed and dumped successfully. Otherwise, it returns 1.
