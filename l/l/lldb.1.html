NOM

lldb - Documentation LLDB

SYNTAXE

lldb [options] exécutable

DESCRIPTION

lldb est un débogueur de nouvelle génération, haute performance. Il est construit comme un ensemble de composants réutilisables qui tirent fortement parti des bibliothèques existantes du projet LLVM plus large, comme l'analyseur d'expressions Clang et le désassembleur LLVM.

lldb est le débogueur par défaut dans Xcode sur macOS et prend en charge le débogage de C, Objective-C et C++ sur les appareils de bureau et iOS, ainsi que sur simulateur.

Tout le code du projet LLDB est disponible sous licence Apache 2.0 avec exceptions LLVM.

Indique au débogueur de s'attacher à un processus portant le nom donné.
--attach-pid <pid>
Indique au débogueur de s'attacher à un processus portant le pid donné.
-n <valeur>
Alias pour --attach-name

Indique au débogueur d'attendre qu'un processus avec le pid ou le nom donné soit lancé avant de s'attacher.

Indique au débogueur d'exécuter les commandes de -s, -S, -o & -O, puis de quitter.

N'analyse automatiquement aucun fichier '.lldbinit'.
--one-line-before-file <commande>
Indique au débogueur d'exécuter cette commande lldb sur une seule ligne avant le chargement de tout fichier fourni en ligne de commande.

En mode batch, indique au débogueur d'exécuter cette commande lldb sur une seule ligne si la cible plante.
--one-line <commande>
Indique au débogueur d'exécuter cette commande lldb sur une seule ligne après le chargement de tout fichier fourni en ligne de commande.

-o <valeur>
Alias pour --one-line
-Q
Alias pour --source-quietly
--source-before-file <fichier>
Indique au débogueur de lire et d'exécuter les commandes lldb du fichier donné, avant le chargement d'un fichier.
--source-on-crash <fichier>
En mode batch, indique au débogueur de sourcer ce fichier de commandes lldb si la cible plante.
--source-quietly
Indique au débogueur de ne pas afficher les commandes lors du sourçage de fichiers ou de commandes sur une seule ligne fournies en ligne de commande.
--source <fichier>
Indique au débogueur de lire et d'exécuter les commandes lldb du fichier donné, après le chargement d'un fichier.

EXEMPLES

Le débogueur peut être démarré dans plusieurs modes.

Passer un exécutable comme argument positionnel prépare lldb à déboguer l'exécutable donné. Pour désambiguïser entre les arguments passés à lldb et les arguments passés à l'exécutable débogué, les arguments commençant par un - doivent être passés après --.

lldb --arch x86_64 /path/to/program program argument -- --arch armv7

Par souci de commodité, passer l'exécutable après -- est également supporté.

lldb --arch x86_64 -- /path/to/program program argument --arch armv7

Passer l'une des options d'attachement amène lldb à se connecter immédiatement au processus donné.

lldb -p <pid> lldb -n <process-name>

Passer --repl démarre lldb en mode REPL.

lldb -r

Passer --core amène lldb à déboguer le fichier core.

lldb -c /path/to/core

Les options de commande peuvent être combinées avec ces modes et amènent lldb à exécuter les commandes spécifiées avant ou après des événements, comme le chargement du fichier ou un crash, dans l'ordre où elles sont fournies sur la ligne de commande.

lldb -O 'settings set stop-disassembly-count 20' -o 'run' -o 'bt' lldb -S /source/before/file -s /source/after/file lldb -K /source/before/crash -k /source/after/crash

Note : En mode REPL, aucun fichier n'est chargé, donc les commandes spécifiées pour être exécutées après le chargement du fichier (via -o ou -s) seront ignorées.

UTILISATION DE LLDB

Dans lldb, il existe une commande d'aide qui peut être utilisée pour trouver des descriptions et des exemples de toutes les commandes lldb. Pour obtenir de l'aide sur "breakpoint set", vous tapez "help breakpoint set".

Il existe également une commande apropos qui recherchera dans le texte d'aide de toutes les commandes un terme donné ‐‐ cela est utile pour localiser une commande par sujet. Par exemple, "apropos breakpoint" listra toute commande qui contient le mot "breakpoint" dans son texte d'aide.

FICHIERS DE CONFIGURATION

lldb lit des éléments tels que les paramètres, les alias et les commandes à partir du fichier .lldbinit.

Premièrement, lldb essaiera de lire le fichier d'initialisation spécifique à l'application dont le nom est ~/.lldbinit suivi d'un tiret et du nom du programme actuel. Ce serait ~/.lldbinit-lldb pour le lldb en ligne de commande et ~/.lldbinit-Xcode pour Xcode. S'il n'y a pas de fichier d'initialisation spécifique à l'application, lldb recherchera un fichier d'initialisation dans le répertoire personnel. S'il est lancé avec une option REPL, il recherchera d'abord un fichier de configuration REPL, spécifique au langage REPL. Le fichier d'initialisation doit être nommé comme suit : .lldbinit-<language>-repl (c'est-à-dire .lldbinit-swift-repl). Si ce fichier n'existe pas, ou si lldb n'a pas été lancé avec REPL, ce qui signifie qu'il n'y a ni fichier d'initialisation REPL ni fichier d'initialisation spécifique à l'application, lldb se rabattra sur le global ~/.lldbinit.

Deuxièmement, il recherchera un fichier .lldbinit dans le répertoire de travail actuel. Pour des raisons de sécurité, lldb affichera un avertissement et ne sourcera pas ce fichier par défaut. Ce comportement peut être modifié en changeant le paramètre target.load-cwd-lldbinit.

Pour toujours charger le fichier .lldbinit dans le répertoire de travail actuel, ajoutez la commande suivante à ~/.lldbinit :

settings set target.load-cwd-lldbinit true

Pour ne jamais charger le fichier .lldbinit dans le répertoire de travail actuel et supprimer l'avertissement, ajoutez la commande suivante à ~/.lldbinit :

settings set target.load-cwd-lldbinit false
