NOM

llvm-objcopy - outil de copie et d'édition d'objets

SYNTAXE

llvm-objcopy [options] entrée [sortie]

DESCRIPTION

llvm-objcopy est un outil pour copier et manipuler des objets. En utilisation basique, il effectue une copie sémantique de l'entrée vers la sortie. Si des options sont spécifiées, la sortie peut être modifiée en cours de route, par exemple par la suppression de sections.

Si aucun fichier de sortie n'est spécifié, le fichier d'entrée est modifié sur place. Si "-" est spécifié pour le fichier d'entrée, l'entrée est lue depuis le flux d'entrée standard du programme. Si "-" est spécifié pour le fichier de sortie, la sortie est écrite dans le flux de sortie standard du programme.

Si l'entrée est une archive, toutes les opérations demandées seront appliquées individuellement à chaque membre de l'archive.

L'outil est encore en développement actif, mais dans la plupart des scénarios, il fonctionne comme un remplacement direct pour objcopy de GNU.

OPTIONS GÉNÉRIQUES ET MULTIPLATEFORMES

Les options suivantes sont soit indépendantes du format de fichier, soit s'appliquent à plusieurs formats de fichiers.

--add-gnu-debuglink <fichier-debug>
Ajoute une section .gnu_debuglink pour <fichier-debug> à la sortie.
--add-section <section=fichier>
Ajoute une section nommée <section> avec le contenu de <fichier> à la sortie. Pour les objets ELF, la section sera de type SHT_NOTE, si le nom commence par ".note". Sinon, elle aura le type SHT_PROGBITS. Peut être spécifiée plusieurs fois pour ajouter plusieurs sections.

Pour les objets MachO, <section> doit être formaté comme <nom-segment>,<nom-section>.

--binary-architecture <arch>, -B
Ignoré pour des raisons de compatibilité.
--disable-deterministic-archives, -U
Utilise des valeurs réelles pour les UID, GID et timestamps lors de la mise à jour des en-têtes des membres d'archives.
--discard-all, -x
Supprime la plupart des symboles locaux non référencés par les relocalisations de la sortie. Différents formats de fichiers peuvent limiter cela à un sous-ensemble des symboles locaux. Par exemple, les symboles de fichier et de section dans les objets ELF ne seront pas supprimés. De plus, supprime toutes les sections de débogage.
--dump-section <section>=<fichier>
Extrait le contenu de la section <section> dans le fichier <fichier>. Peut être spécifié plusieurs fois pour extraire plusieurs sections vers différents fichiers. <fichier> n'est pas lié aux fichiers d'entrée et de sortie fournis à llvm-objcopy et, par conséquent, les opérations normales de copie et d'édition seront toujours effectuées. Aucune opération n'est effectuée sur les sections avant leur extraction.

Pour les objets MachO, <section> doit être formaté comme <nom-segment>,<nom-section>.

--enable-deterministic-archives, -D
Active le mode déterministe lors de la copie d'archives, c'est-à-dire utilise 0 pour les champs UID, GID et timestamp des en-têtes des membres d'archives. Activé par défaut.
--globalize-symbol <symbole>
Marque les symboles définis nommés <symbole> comme symboles globaux dans la sortie. Peut être spécifié plusieurs fois pour marquer plusieurs symboles.
--globalize-symbols <nom-fichier>
Lit une liste de noms à partir du fichier <nom-fichier> et marque les symboles définis portant ces noms comme globaux dans la sortie. Dans le fichier, chaque ligne représente un seul symbole, avec les espaces blancs de début et de fin ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire des noms à partir de plusieurs fichiers.
--help, -h
Affiche un résumé des options de la ligne de commande.
--keep-global-symbol <symbole>, -G
Marque tous les symboles comme locaux dans la sortie, à l'exception des symboles nommés <symbole>. Peut être spécifié plusieurs fois pour ignorer plusieurs symboles.
--keep-global-symbols <nom-fichier>
Marque tous les symboles comme locaux dans la sortie, à l'exception des symboles nommés dans le fichier <nom-fichier>. Dans le fichier, chaque ligne représente un seul symbole, avec les espaces blancs de début et de fin ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire des noms à partir de plusieurs fichiers.
--localize-symbol <symbole>, -L
Marque les symboles définis non-communs nommés <symbole> comme symboles locaux dans la sortie. Peut être spécifié plusieurs fois pour marquer plusieurs symboles comme locaux.
--localize-symbols <nom-fichier>
Lit une liste de noms à partir du fichier <nom-fichier> et marque les symboles définis non-communs portant ces noms comme locaux dans la sortie. Dans le fichier, chaque ligne représente un seul symbole, avec les espaces blancs de début et de fin ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire des noms à partir de plusieurs fichiers.
--only-keep-debug
Produit un fichier de débogage en sortie qui ne préserve que le contenu des sections utiles à des fins de débogage.

Pour les objets ELF, cela supprime le contenu des sections SHF_ALLOC qui ne sont pas SHT_NOTE en les transformant en SHT_NOBITS et en rétrécissant les en-têtes de programme lorsque cela est possible.

--only-section <section>, -j
Supprime toutes les sections de la sortie, à l'exception des sections nommées <section>. Peut être spécifié plusieurs fois pour conserver plusieurs sections.

Pour les objets MachO, <section> doit être formaté comme <nom-segment>,<nom-section>.

--redefine-sym <ancien>=<nouveau>
Renomme les symboles appelés <ancien> en <nouveau> dans la sortie. Peut être spécifié plusieurs fois pour renommer plusieurs symboles.
--redefine-syms <nom-fichier>
Renomme les symboles dans la sortie tels que décrits dans le fichier <nom-fichier>. Dans le fichier, chaque ligne représente un seul symbole à renommer, avec l'ancien nom et le nouveau nom séparés par des espaces blancs. Les espaces blancs de début et de fin sont ignorés, tout comme tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire des noms à partir de plusieurs fichiers.
--regex
Si spécifié, les noms de symboles et de sections spécifiés par d'autres options sont traités comme des motifs d'expression régulière POSIX étendue.
--remove-symbol-prefix <préfixe>
Supprime <préfixe> du début de chaque nom de symbole. Ne fait rien pour les symboles qui ne commencent pas par <préfixe>.
--remove-section <section>, -R
Supprime la section spécifiée de la sortie. Peut être spécifié plusieurs fois pour supprimer plusieurs sections simultanément.

Pour les objets MachO, <section> doit être formaté comme <nom de segment>,<nom de section>.

--set-section-alignment <section>=<align>
Définit l'alignement de la section <section> sur <align>. Peut être spécifié plusieurs fois pour mettre à jour plusieurs sections.
--set-section-flags <section>=<flag>[,<flag>,...]
Définit les propriétés de section dans la sortie de la section <section> en fonction des valeurs <flag> spécifiées. Peut être spécifié plusieurs fois pour mettre à jour plusieurs sections.

Les noms de drapeaux pris en charge sont alloc, load, noload, readonly, exclude, debug, code, data, rom, share, contents, merge, strings et large. Tous les drapeaux ne sont pas significatifs pour tous les formats de fichiers objets ou architectures cibles.

Pour les objets ELF, les drapeaux ont les effets suivants :

  • alloc = ajoute le drapeau SHF_ALLOC.
  • load = si la section a le type SHT_NOBITS, la marque comme une section SHT_PROGBITS.
  • readonly = si ce drapeau n'est pas spécifié, ajoute le drapeau SHF_WRITE.
  • exclude = ajoute le drapeau SHF_EXCLUDE.
  • code = ajoute le drapeau SHF_EXECINSTR.
  • merge = ajoute le drapeau SHF_MERGE.
  • strings = ajoute le drapeau SHF_STRINGS.
  • contents = si la section a le type SHT_NOBITS, la marque comme une section SHT_PROGBITS.
  • large = ajoute SHF_X86_64_LARGE sur x86_64 ; rejeté si l'architecture cible n'est pas x86_64.

Pour les objets COFF, les drapeaux ont les effets suivants :

  • alloc = ajoute les drapeaux IMAGE_SCN_CNT_UNINITIALIZED_DATA et IMAGE_SCN_MEM_READ, sauf si le drapeau load est spécifié.
  • noload = ajoute les drapeaux IMAGE_SCN_LNK_REMOVE et IMAGE_SCN_MEM_READ.
  • readonly = si ce drapeau n'est pas spécifié, ajoute le drapeau IMAGE_SCN_MEM_WRITE.
  • exclude = ajoute les drapeaux IMAGE_SCN_LNK_REMOVE et IMAGE_SCN_MEM_READ.
  • debug = ajoute les drapeaux IMAGE_SCN_CNT_INITIALIZED_DATA, IMAGE_SCN_MEM_DISCARDABLE et IMAGE_SCN_MEM_READ.
  • code = ajoute les drapeaux IMAGE_SCN_CNT_CODE, IMAGE_SCN_MEM_EXECUTE et IMAGE_SCN_MEM_READ.
  • data = ajoute les drapeaux IMAGE_SCN_CNT_INITIALIZED_DATA et IMAGE_SCN_MEM_READ.
  • share = ajoute les drapeaux IMAGE_SCN_MEM_SHARED et IMAGE_SCN_MEM_READ.
--skip-symbol <symbol>
Ne modifie pas les paramètres du symbole <symbol> lors de l'exécution d'autres options pouvant modifier le nom, la liaison ou la visibilité du symbole.
--skip-symbols <filename>
Ne modifie pas les paramètres des symboles nommés dans le fichier <filename> lors de l'exécution d'autres options pouvant modifier le nom, la liaison ou la visibilité du symbole. Dans le fichier, chaque ligne représente un seul symbole, les espaces blancs en tête et en queue étant ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--strip-all-gnu
Supprime tous les symboles, sections de débogage et relocations de la sortie. Cette option est équivalente au commutateur --strip-all de objcopy de GNU.
--strip-all, -S
Pour les objets ELF, supprime de la sortie tous les symboles et sections non allouables qui ne sont pas dans des segments, à l'exception des sections .gnu.warning, .ARM.attribute et de la table des noms de sections.

Pour les objets COFF et Mach-O, supprime tous les symboles, sections de débogage et relocations de la sortie.

--strip-debug, -g
Supprime toutes les sections de débogage de la sortie.
--strip-symbol <symbol>, -N
Supprime tous les symboles nommés <symbol> de la sortie. Peut être spécifié plusieurs fois pour supprimer plusieurs symboles.
--strip-symbols <filename>
Supprime de la sortie tous les symboles dont les noms apparaissent dans le fichier <filename>. Dans le fichier, chaque ligne représente un seul nom de symbole, les espaces blancs en tête et en queue étant ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--strip-unneeded-symbol <symbol>
Supprime de la sortie tous les symboles nommés <symbol> qui sont locaux ou indéfinis et qui ne sont requis par aucune relocation.
--strip-unneeded-symbols <filename>
Supprime de la sortie tous les symboles dont les noms apparaissent dans le fichier <filename>, s'ils sont locaux ou indéfinis et ne sont pas requis par une relocation. Dans le fichier, chaque ligne représente un seul nom de symbole, les espaces blancs en tête et en queue étant ignorés, ainsi que tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--strip-unneeded
Supprime de la sortie tous les symboles locaux ou indéfinis qui ne sont pas requis par les relocations. Supprime également toutes les sections de débogage.
--update-section <name>=<file>
Remplace le contenu de la section <name> par le contenu du fichier <file>. Si la section <name> fait partie d'un segment, le nouveau contenu ne peut pas être plus volumineux que la section existante.
--version, -V
Affiche la version de l'exécutable llvm-objcopy.
--wildcard, -w
Autorise la syntaxe générique pour les options relatives aux symboles. Activée par défaut pour les options relatives aux sections. Incompatible avec --regex.

La syntaxe générique autorise les symboles spéciaux suivants :

Caractère Signification Équivalent
* Nombre quelconque de caractères .*
? Un seul caractère quelconque .
\ Échappe le caractère suivant \
[a-z] Classe de caractères [a-z]
[!a-z], [^a-z] Classe de caractères niée [^a-z]

De plus, commencer une expression générique par '!' empêchera une correspondance, même si une autre option correspond. Par exemple, -w -N '*' -N '!x' supprimera tous les symboles sauf x.

L'ordre des expressions génériques n'a pas d'importance. Par exemple, -w -N '*' -N '!x' est identique à -w -N '!x' -N '*'.

@<FILE>
Lit les options et commandes de la ligne de commande à partir du fichier de réponse <FILE>.

OPTIONS SPÉCIFIQUES ELF

Les options suivantes sont implémentées uniquement pour les objets ELF. Si elles sont utilisées avec d'autres objets, llvm-objcopy émettra une erreur ou les ignorera silencieusement.

--add-symbol <name>=[<section>:]<value>[,<flags>]
Ajoute un nouveau symbole appelé <name> à la table des symboles de sortie, dans la section nommée <section>, avec la valeur <value>. Si <section> n'est pas spécifié, le symbole est ajouté comme symbole absolu. Les <flags> affectent les propriétés du symbole. Les valeurs acceptées sont :
  • global = le symbole aura une liaison globale.
  • local = le symbole aura une liaison locale.
  • weak = le symbole aura une liaison faible.
  • default = le symbole aura une visibilité par défaut.
  • hidden = le symbole aura une visibilité cachée.
  • protected = le symbole aura une visibilité protégée.
  • file = le symbole sera un symbole STT_FILE.
  • section = le symbole sera un symbole STT_SECTION.
  • object = le symbole sera un symbole STT_OBJECT.
  • function = le symbole sera un symbole STT_FUNC.
  • indirect-function = le symbole sera
llvm-objcopy

OPTIONS

The following options are available:

Options starting with -- can be abbreviated to a reasonable prefix of themselves. For example, --output-target can be specified as --output.

For options that accept <section>, <symbol>, <format> or <type> arguments, the argument is usually a regular expression. However, the following flags are accepted but ignored for these arguments:

  • case-insensitive
  • empty
  • integer
  • leading-control-character
  • no-leading-control-character
  • no-leading-or-trailing-whitespace
  • no-trailing-whitespace
  • trailing-control-character
  • trailing-whitespace
  • always-match
  • left-most-match
  • longest-match
  • multiline

Flags of type STT_GNU_IFUNC symbol.

Additionally, the following flags are accepted but ignored: debug, constructor, warning, indirect, synthetic, unique-object, before.

Can be specified multiple times to add multiple symbols.

--allow-broken-links
Permet à llvm-objcopy de supprimer des sections même si cela laisse des références de section invalides. Tous les champs sh_link invalides seront mis à zéro.
--change-section-lma \*{+-}<val>
Déplace le LMA des segments de taille non nulle de <val>.
--change-section-address <section>{=+-}<val>, --adjust-section-vma
Modifie l'adresse des sections qui correspondent au motif <section> à la valeur spécifiée, ou applique +<val>/-<val> à la valeur actuelle. Peut être spécifié plusieurs fois pour spécifier plusieurs motifs. Chaque section n'est modifiée que par un seul argument --change-section-address. Si un nom de section correspond à plusieurs motifs, la dernière modification s'applique. Le fichier objet doit être de type ET_REL.
--change-start <incr>, --adjust-start
Ajoute <incr> à l'adresse de départ du programme. Peut être spécifié plusieurs fois, auquel cas les valeurs seront appliquées cumulativement.
--compress-debug-sections [<format>]
Compresse les sections de débogage DWARF dans la sortie, en utilisant le format spécifié. Les formats pris en charge sont zlib et zstd. Utilisez zlib si <format> est omis.
--compress-sections <section>=<format>
Compresse ou décompresse les sections correspondant à <section> en utilisant le format spécifié. Les formats pris en charge sont zlib et zstd. Spécifiez none pour la décompression. Lorsqu'une section est correspondant par plusieurs options, la dernière l'emporte. Un caractère générique <section> commençant par '!' est interdit. Les sections au sein d'un segment ne peuvent pas être (dé)compressées.
--decompress-debug-sections
Décompresse toutes les sections de débogage DWARF compressées dans la sortie.
--discard-locals, -X
Supprime les symboles locaux commençant par ".L" non référencés par des relocations de la sortie.
--extract-dwo
Supprime toutes les sections qui ne sont pas des sections DWARF .dwo de la sortie.
--extract-main-partition
Extrait la partition principale de la sortie.
--extract-partition <name>
Extrait la partition nommée de la sortie.
--gap-fill <value>
Pour les sorties binaires, remplit les espaces entre les sections avec <value> au lieu de zéro. La valeur doit être un entier de 8 bits non signé.
--input-target <format>, -I
Lit l'entrée comme le format spécifié. Voir FORMATS SUPPORTÉS pour une liste des valeurs valides de <format>. Si non spécifié, llvm-objcopy tentera de déterminer le format automatiquement.
--keep-file-symbols
Conserve les symboles de type STT_FILE, même s'ils seraient sinon supprimés.
--keep-section <section>
Lors de la suppression de sections de la sortie, ne supprime pas les sections nommées <section>. Peut être spécifié plusieurs fois pour conserver plusieurs sections.
--keep-symbol <symbol>, -K
Lors de la suppression de symboles de la sortie, ne supprime pas les symboles nommés <symbol>. Peut être spécifié plusieurs fois pour conserver plusieurs symboles.
--keep-symbols <filename>
Lors de la suppression de symboles de la sortie, ne supprime pas les symboles nommés dans le fichier <filename>. Dans le fichier, chaque ligne représente un seul symbole, avec les espaces blancs au début et à la fin ignorés, tout comme tout ce qui suit un '#'. Peut être spécifié plusieurs fois pour lire des noms à partir de plusieurs fichiers.
--localize-hidden
Marque tous les symboles avec une visibilité cachée ou interne comme locaux dans la sortie.
--new-symbol-visibility <visibility>
Spécifie la visibilité des symboles créés automatiquement lors de l'utilisation d'une entrée binaire ou de --add-symbol. Options valides :
  • default
  • hidden
  • internal
  • protected

La valeur par défaut est default.

--no-verify-note-sections
Lors de l'ajout de sections de notes, ne vérifie pas si le format de la section est valide.
--output-target <format>, -O
Écrit la sortie dans le format spécifié. Voir FORMATS SUPPORTÉS pour une liste des valeurs valides de <format>. Si non spécifié, le format de sortie est supposé être le même que la valeur spécifiée pour --input-target ou le format du fichier d'entrée si cette option est également non spécifiée.
--pad-to <address>
Pour les sorties binaires, remplit la sortie jusqu'à l'adresse de chargement <address> en utilisant une valeur de zéro ou la valeur spécifiée par --gap-fill.
--prefix-alloc-sections <prefix>
Ajoute <prefix> au début des noms de toutes les sections allocables dans la sortie.
--prefix-symbols <prefix>
Ajoute <prefix> au début de chaque nom de symbole dans la sortie.
--preserve-dates, -p
Conserve les horodatages d'accès et de modification dans la sortie.
--remove-note [<name>/]<type>
Supprime les notes de type entier <type> et de nom <name> des sections SHT_NOTE qui ne sont pas dans un segment. Peut être spécifié plusieurs fois.
--rename-section <old>=<new>[,<flag>,...]
Renomme les sections appelées <old> en <new> dans la sortie, et applique les valeurs de <flag> spécifiées. Voir --set-section-flags pour une liste des drapeaux pris en charge. Peut être spécifié plusieurs fois pour renommer plusieurs sections.
--set-section-type <section>=<type>
Définit le type de la section <section> sur l'entier <type>. Peut être spécifié plusieurs fois pour mettre à jour plusieurs sections.
--set-start <addr>
Définit l'adresse de départ de la sortie à <addr>. Remplace toutes les options --change-start ou --adjust-start spécifiées précédemment.
--set-symbol-visibility <symbol>=<visibility>
Change la visibilité d'un symbole à la valeur spécifiée.
--set-symbols-visibility <filename>=<visibility>
Lit une liste de symboles à partir de <filename> et change leur visibilité à la valeur spécifiée. Valeurs de visibilité : default, internal, hidden, protected.
--split-dwo <dwo-file>
Équivalent à exécuter llvm-objcopy avec --extract-dwo et <dwo-file> comme fichier de sortie et sans autres options, puis avec --strip-dwo sur le fichier d'entrée.
--strip-dwo
Supprime toutes les sections DWARF .dwo de la sortie.
--strip-non-alloc
Supprime de la sortie toutes les sections non allouables qui ne sont pas dans des segments.
--strip-sections
Supprime de la sortie tous les en-têtes de section et toutes les données de section qui ne sont pas dans des segments. Notez que de nombreux outils ne pourront pas utiliser

OPTIONS GÉNÉRALES ET MULTIPLATES-FORMES

--input-format <format>
Spécifier le format des fichiers d'entrée. Voir la section SUPPORTED FORMATS pour une liste des valeurs valides pour <format>. Sans cette option, llvm-objcopy tentera de deviner le format d'entrée.
--output-format <format>
Spécifier le format des fichiers de sortie. Voir la section SUPPORTED FORMATS pour une liste des valeurs valides pour <format>. Sans cette option, le format de sortie est déduit du format d'entrée.
--disable-magic
Ne pas utiliser de « magic numbers » pour détecter le format d'entrée. Cette option n'a d'effet que lorsque le format d'entrée n'est pas spécifié explicitement par --input-format ou --target.
--strip-unneeded
Supprimer les informations de débogage et de relocalisation inutilisées. Par défaut, seul le symbole de fin est supprimé.
--globalize-symbol <symbole>
Rendre le symbole <symbole> global dans la sortie. Peut être spécifié plusieurs fois pour rendre plusieurs symboles globaux.
--globalize-symbols <nom_fichier>
Lire une liste de noms à partir du fichier <nom_fichier> et rendre les symboles globaux avec ces noms dans la sortie. Dans le fichier, chaque ligne représente un symbole unique, en ignorant les espaces blancs en début et fin, ainsi que tout ce qui suit un « # ». Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--localize-symbol <symbole>
Rendre le symbole <symbole> local dans la sortie. Peut être spécifié plusieurs fois pour rendre plusieurs symboles locaux.
--localize-symbols <nom_fichier>
Lire une liste de noms à partir du fichier <nom_fichier> et rendre les symboles locaux avec ces noms dans la sortie. Dans le fichier, chaque ligne représente un symbole unique, en ignorant les espaces blancs en début et fin, ainsi que tout ce qui suit un « # ». Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--remove-symbol <symbole>
Supprimer le symbole <symbole> de la sortie. Peut être spécifié plusieurs fois pour supprimer plusieurs symboles.
--remove-symbols <nom_fichier>
Lire une liste de noms à partir du fichier <nom_fichier> et supprimer les symboles avec ces noms de la sortie. Dans le fichier, chaque ligne représente un symbole unique, en ignorant les espaces blancs en début et fin, ainsi que tout ce qui suit un « # ». Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--add-symbol <nom>=<valeur>
Ajouter un nouveau symbole <nom> avec la valeur <valeur> dans la sortie. Peut être spécifié plusieurs fois pour ajouter plusieurs symboles. La valeur doit être un entier.
--change-symbol-section <nom>=<section>
Changer la section du symbole <nom> pour <section>. Peut être spécifié plusieurs fois pour changer la section de plusieurs symboles.
--dyn-syms fichier
Supprimer tous les symboles dynamiques du fichier spécifié par fichier.
--no-strip-redirects
Ne pas supprimer les symboles de redirection. Par défaut, les symboles de redirection sont supprimés.
--extract-symbol <symbole>
Ne conserver que le symbole <symbole> et les symboles nécessaires à son évaluation dans la sortie. Peut être spécifié plusieurs fois pour ne conserver que plusieurs symboles.
--extract-symbols <nom_fichier>
Ne conserver que les symboles listés dans le fichier <nom_fichier> et les symboles nécessaires à leur évaluation dans la sortie. Dans le fichier, chaque ligne représente un symbole unique, en ignorant les espaces blancs en début et fin, ainsi que tout ce qui suit un « # ». Peut être spécifié plusieurs fois pour lire les noms à partir de plusieurs fichiers.
--rename-section <ancien_nom>=<nouveau_nom>
Renommer la section <ancien_nom> en <nouveau_nom>. Peut être spécifié plusieurs fois pour renommer plusieurs sections.
--set-start <symbole>

FORMATS SUPPORTÉS

Les valeurs suivantes sont actuellement supportées par llvm-objcopy pour les options --input-target, --output-target et --target. Pour la compatibilité avec GNU objcopy, les valeurs sont toutes des bfdnames.

  • binary
  • ihex
  • elf32-i386
  • elf32-x86-64
  • elf64-x86-64
  • elf32-iamcu
  • elf32-littlearm
  • elf64-aarch64
  • elf64-littleaarch64
  • elf32-littleriscv
  • elf64-littleriscv
  • elf32-powerpc
  • elf32-powerpcle
  • elf64-powerpc
  • elf64-powerpcle
  • elf32-bigmips
  • elf32-ntradbigmips
  • elf32-ntradlittlemips
  • elf32-tradbigmips
  • elf32-tradlittlemips
  • elf64-tradbigmips
  • elf64-tradlittlemips
  • elf32-sparc
  • elf32-sparcel
  • elf32-hexagon
  • elf32-loongarch
  • elf64-loongarch
  • elf64-s390

Les formats suivants sont supportés par llvm-objcopy pour --output-target uniquement :

•
srec

De plus, toutes les cibles sauf binary, ihex et srec peuvent avoir le suffixe -freebsd.

ENTRÉE ET SORTIE BINAIRE

Si binary est utilisé comme valeur pour --input-target, le fichier d'entrée sera intégré en tant que section de données dans un objet ELF relocatable, avec les symboles _binary_<nom_fichier>_start, _binary_<nom_fichier>_end et _binary_<nom_fichier>_size représentant le début, la fin et la taille des données, où <nom_fichier> est le chemin du fichier d'entrée tel que spécifié sur la ligne de commande avec les caractères non alphanumériques convertis en « _ ».

Si binary est utilisé comme valeur pour --output-target, le fichier de sortie sera un fichier binaire brut, contenant l'image mémoire du fichier d'entrée. Les symboles et les informations de relocalisation seront jetés. L'image commencera à l'adresse de la première section chargeable dans la sortie.

STATUT DE SORTIE

llvm-objcopy se termine avec un code de sortie non nul en cas d'erreur. Sinon, il se termine avec le code 0.

BOGUES

Pour signaler des bogues, veuillez visiter <https://github.com/llvm/llvm-project/labels/tools:llvm-objcopy/strip/>.

Il existe un problème connu avec --input-target et --target qui fait que seuls les formats binary et ihex ont un effet. Les autres valeurs seront ignorées et llvm-objcopy tentera de deviner le format d'entrée.
