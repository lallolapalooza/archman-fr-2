listxattr(2) Manuel des appels système listxattr(2)

NOM

listxattr, llistxattr, flistxattr - lister les noms d'attributs étendus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/xattr.h>
ssize_t listxattr(const char *chemin, char *_Nullable liste, size_t taille);
ssize_t llistxattr(const char *chemin, char *_Nullable liste, size_t taille);
ssize_t flistxattr(int fd, char *_Nullable liste, size_t taille);

DESCRIPTION

Les attributs étendus sont des paires nom:valeur associées aux inodes (fichiers, répertoires, liens symboliques, etc.). Ce sont des extensions aux attributs normaux associés à tous les inodes du système (c'est-à-dire les données de stat(2)). Un aperçu complet des concepts d'attributs étendus se trouve dans xattr(7).

listxattr() récupère la liste des noms d'attributs étendus associés au chemin donné dans le système de fichiers. La liste récupérée est placée dans liste, un tampon alloué par l'appelant dont la taille (en octets) est spécifiée dans l'argument taille. La liste est l'ensemble des noms (terminés par null), les uns après les autres. Les noms d'attributs étendus auxquels le processus appelant n'a pas accès peuvent être omis de la liste. La longueur de la liste des noms d'attributs est retournée.

llistxattr() est identique à listxattr(), sauf dans le cas d'un lien symbolique, où la liste des noms d'attributs étendus associés au lien lui-même est récupérée, et non pas le fichier auquel il renvoie.

flistxattr() est identique à listxattr(), seul le fichier ouvert référencé par fd (tel que retourné par open(2)) est interrogé à la place de chemin.

Un nom d'attribut étendu unique est une chaîne terminée par null. Le nom inclut un préfixe d'espace de noms ; il peut y avoir plusieurs espaces de noms disjoints associés à un inode individuel.

Si taille est spécifié comme zéro, ces appels retournent la taille actuelle de la liste des noms d'attributs étendus (et laissent liste inchangé). Ceci peut être utilisé pour déterminer la taille du tampon qui devrait être fourni dans un appel ultérieur. (Cependant, il faut garder à l'esprit qu'il est possible que l'ensemble des attributs étendus puisse changer entre les deux appels, de sorte qu'il est toujours nécessaire de vérifier le statut de retour du second appel.)

Exemple

La liste des noms est retournée comme un tableau non ordonné de chaînes de caractères terminées par null (les noms d'attributs sont séparés par des octets null ('\0')), comme ceci :


user.nom1\0system.nom1\0user.nom2\0

Les systèmes de fichiers qui implémentent les ACL POSIX à l'aide d'attributs étendus pourraient retourner une liste comme ceci :


system.posix_acl_access\0system.posix_acl_default\0

VALEUR DE RETOUR

En cas de succès, un nombre non négatif est retourné indiquant la taille de la liste des noms d'attributs étendus. En cas d'échec, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

E2BIG
La taille de la liste des noms d'attributs étendus est supérieure à la taille maximale autorisée ; la liste ne peut pas être récupérée. Ceci peut se produire sur les systèmes de fichiers qui prennent en charge un nombre illimité d'attributs étendus par fichier, tels que XFS, par exemple. Voir BUGS.
ENOTSUP
Les attributs étendus ne sont pas pris en charge par le système de fichiers, ou sont désactivés.
ERANGE
La taille du tampon liste est trop petite pour contenir le résultat.

De plus, les erreurs documentées dans stat(2) peuvent également survenir.

NORMES

Linux.

HISTORIQUE

Linux 2.4, glibc 2.3.

BOGUES

Comme indiqué dans xattr(7), le VFS impose une limite de 64 kio à la taille de la liste des noms d'attributs étendus retournée par listxattr(). Si la taille totale des noms d'attributs attachés à un fichier dépasse cette limite, il n'est plus possible de récupérer la liste des noms d'attributs.

EXEMPLES

Le programme suivant démontre l'utilisation de listxattr() et de getxattr(2). Pour le fichier dont le nom de chemin est fourni en argument de ligne de commande, il liste tous les attributs de fichier étendus et leurs valeurs.

Pour garder le code simple, le programme suppose que les clés et valeurs d'attributs sont constantes pendant l'exécution du programme. Un programme de production devrait s'attendre à et gérer les changements pendant l'exécution du programme. Par exemple, le nombre d'octets requis pour les clés d'attributs pourrait augmenter entre les deux appels à listxattr(). Une application pourrait gérer cette possibilité en utilisant une boucle qui réessaie l'appel (peut-être jusqu'à un nombre maximum prédéterminé de tentatives) avec un tampon plus grand à chaque fois qu'il échoue avec l'erreur ERANGE. Les appels à getxattr(2) pourraient être gérés de manière similaire.

La sortie suivante a été enregistrée en créant d'abord un fichier, en définissant certains attributs de fichier étendus, puis en listant les attributs avec le programme d'exemple.

Sortie d'exemple


$ touch /tmp/foo;
$ setfattr -n user.fred -v chocolate /tmp/foo;
$ setfattr -n user.frieda -v bar /tmp/foo;
$ setfattr -n user.empty /tmp/foo;
$ ./listxattr /tmp/foo;
user.fred: chocolate
user.frieda: bar
user.empty: <pas de valeur>

Source du programme (listxattr.c)

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/xattr.h>
int
main(int argc, char *argv[])
{
    char     *buf, *key, *val;
    ssize_t  buflen, keylen, vallen;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s chemin\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /*
     * Déterminer la longueur du tampon nécessaire.
     */
    buflen = listxattr(argv[1], NULL, 0);
    if (buflen == -1) {
        perror("listxattr");
        exit(EXIT_FAILURE);
    }
    if (buflen == 0) {
        printf("%s n'a pas d'attributs.\n", argv[1]);
        exit(EXIT_SUCCESS);
    }
    /*
     * Allouer le tampon.
     */
    buf = malloc(buflen);
    if (buf == NULL) {
        perror("malloc");
        exit(EXIT_FAILURE);
    }
    /*
     * Copier la liste des clés d'attributs dans le tampon.
     */
    buflen = listxattr(argv[1], buf, buflen);
    if (buflen == -1) {
        perror("listxattr");
        exit(EXIT_FAILURE);
    }
    /*
     * Parcourir la liste des chaînes terminées par zéro avec les
     * clés d'attributs. Utiliser la longueur restante du tampon pour déterminer
     * la fin de la liste.
     */
    key = buf;
    while (buflen > 0) {
        /*
         * Afficher la clé d'attribut.
         */
        printf("%s: ", key);
        /*
         * Déterminer la longueur de la valeur.
         */
        vallen = getxattr(argv[1], key, NULL, 0);
        if (vallen == -1)
            perror("getxattr");
        if (vallen > 0) {
            /*
             * Allouer le tampon de valeur.
             * Un octet supplémentaire est nécessaire pour ajouter 0x00.
             */
            val = malloc(vallen + 1);
            if (val == NULL) {
                perror("malloc");
                exit(EXIT_FAILURE);
            }
            /*
             * Copier la valeur dans le tampon.
             */
            vallen = getxattr(argv[1], key, val, vallen);
            if (vallen == -1) {
                perror("getxattr");
            } else {
                /*
                 * Afficher la valeur de l'attribut.
                 */
                val[vallen] = 0;
                printf("%s", val);
            }
        }
        printf("\n");
        /*
         * Passer à la clé d'attribut suivante.
         */
        keylen = strlen(key) + 1;
        buflen -= keylen;
        key += keylen;
    }
    free(buf);
    exit(EXIT_SUCCESS);
}

llistxattr(2) — man pages

NAME

llistxattr, llistxattr64 — lister les attributs étendus d'un fichier

LIBRARY

Bibliothèque C standard (libc), depuis glibc 2.3

SYNOPSIS

                        #include <syscalls.h>

                        ssize_t llistxattr(const char *path,
                                             char *list, size_t size);
                        ssize_t llistxattr64(const char *path,
                                              char *list, size_t size);

DESCRIPTION

La fonction llistxattr renvoie une liste de tous les attributs étendus associés au fichier spécifié par path. La liste est écrite dans le tampon pointé par list, et la taille du tampon est donnée par size. La liste des attributs est une séquence de chaînes de caractères se terminant par un caractère nul (un `\0`).

Si le tampon list est trop petit pour contenir tous les noms d'attributs, llistxattr renvoie -1 et positionne errno à ERANGE.

Le nombre d'octets réellement écrits dans le tampon est renvoyé par la fonction. Ce nombre n'inclut pas le caractère nul final si un attribut est trouvé.

Si le fichier spécifié n'a aucun attribut étendu, llistxattr renvoie 0.

La fonction llistxattr64 est un alias de llistxattr utilisé pour assurer la compatibilité avec les systèmes 64 bits.

RETURN VALUE

En cas de succès, llistxattr renvoie le nombre d'octets écrits dans le tampon list, sans inclure le caractère nul final. Si le fichier n'a aucun attribut étendu, 0 est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini en conséquence.

ERRORS

Les erreurs suivantes peuvent être définies pour llistxattr :

EACCES
Aucune autorisation de lecture pour le répertoire contenant le fichier.
EBADF
Le descripteur de fichier fd n'est pas valide.
EINVAL
Le descripteur de fichier fd est associé à un fichier qui ne peut pas être ouvert pour la lecture.
EIO
Une erreur d'entrée/sortie s'est produite.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de path.
ENAMETOOLONG
path est trop long.
ENOENT
Le fichier spécifié par path n'existe pas.
ENOMEM
Mémoire insuffisante pour allouer un tampon interne.
ENOTSUP
Le système de fichiers ne prend pas en charge les attributs étendus.
EOVERFLOW
Le fichier spécifié par path se trouve sur un système de fichiers qui prend en charge les attributs étendus, mais les limites de taille du système de fichiers ont été dépassées.
ERANGE
Le tampon list est trop petit pour contenir tous les noms d'attributs.

STANDARDS

Ces fonctions sont conformes à la spécification des attributs étendus de Linux. La fonction llistxattr est présente depuis le noyau Linux 2.6.

HISTORY

La fonction llistxattr a été introduite dans le noyau Linux 2.6. Lors de son introduction, elle s'appelait listxattr. L'appel système llistxattr a été ajouté dans glibc 2.3.

BUGS

Aucun bug connu.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <sys/xattr.h>

int
main(int argc, char *argv[])
{
    char buf[1024];
    char *key, *val;
    ssize_t buflen, vallen;
    size_t keylen;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    buflen = llistxattr(argv[1], buf, sizeof(buf));
    if (buflen == -1) {
        perror("llistxattr");
        exit(EXIT_FAILURE);
    }

    if (buflen == 0) {
        printf("No extended attributes\n");
        exit(EXIT_SUCCESS);
    }

    key = buf;
    while (buflen > 0) {
        printf("name: [%s]\n", key);
        vallen = getxattr(argv[1], key, NULL, 0);
        if (vallen == -1) {
            if (errno != ENODATA) {
                perror("getxattr");
                exit(EXIT_FAILURE);
            }
            printf("  value: <no value>\n");
            val = NULL;
        } else {
            val = malloc(vallen);
            if (val == NULL) {
                perror("malloc");
                exit(EXIT_FAILURE);
            }
            if (getxattr(argv[1], key, val, vallen) == -1) {
                perror("getxattr");
                free(val);
                exit(EXIT_FAILURE);
            }
            printf("  value: [%.*s]\n", (int)vallen, val);
            free(val);
        }
        /*
         * Forward to next attribute key.
         */
        keylen = strlen(key) + 1;
        buflen -= keylen;
        key += keylen;
    }
    exit(EXIT_SUCCESS);
}
