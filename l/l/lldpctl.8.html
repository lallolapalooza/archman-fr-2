LLDPCLI(8) Manuel de l'administrateur système LLDPCLI(8)

NOM

lldpcli, lldpctl — contrôler le démon LLDP

SYNOPIS

lldpcli [-dv] [-u socket] [-f format] [-c fichier] [commande ...]

lldpctl [-dv] [-u socket] [-f format] [interfaces ...]

DESCRIPTION

Le programme lldpcli contrôle le démon lldpd(8).

Lorsqu'aucune commande n'est spécifiée, lldpcli démarrera un shell interactif qui pourra être utilisé pour saisir des commandes arbitraires comme si elles étaient spécifiées sur la ligne de commande. Ce shell interactif devrait fournir des fonctionnalités de complétion et d'historique.

Les options sont les suivantes :

-d
Activer plus d'informations de débogage. Ce drapeau peut être répété.
-u socket
Spécifier le socket de domaine Unix utilisé pour la communication avec lldpd(8).
-v
Afficher la version de lldpcli. Lorsqu'il est répété, afficher plus d'informations de compilation.
-f format
Choisir le format de sortie. Actuellement les formats plain, xml, json, json0 et keyvalue sont disponibles. Par défaut, c'est plain. json0 est plus verbeux que json mais la structure de l'objet JSON n'est pas affectée par le nombre d'interfaces ou le nombre de voisins. Il est donc plus facile à analyser.
-c fichier
Lire le fichier de configuration donné. Cette option peut être répétée plusieurs fois. Si un répertoire est fourni, chaque fichier s'y trouvant avec l'extension .conf sera lu. L'ordre est alphabétique.

Lorsqu'il est invoqué comme lldpctl, lldpcli affichera des informations détaillées sur chaque voisin sur les interfaces spécifiées ou sur toutes les interfaces si aucune n'est spécifiée. Cette commande est principalement conservée pour la compatibilité ascendante avec les versions antérieures.

Les commandes suivantes sont prises en charge par lldpcli. Lorsqu'il n'y a pas d'ambiguïté, les mots-clés peuvent être abrégés. Par exemple, show neighbors ports eth0 summary et sh neigh p eth0 sum sont la même commande.

exit
Quitter lldpcli.

help [...]

Afficher l'aide générale ou l'aide sur une commande. Vous pouvez également obtenir de l'aide en utilisant la complétion ou en appuyant sur la touche ?. La complétion et l'aide en ligne peuvent être indisponibles, cependant, si lldpcli a été compilé sans prise en charge de readline, mais la commande help est toujours disponible.

show neighbors [ports ethX [,...]] [details | summary] [hidden]

Afficher les informations sur chaque voisin connu du démon lldpd(8). Avec summary, seul le nom et la description du port de chaque hôte distant seront affichés. En revanche, avec details, toutes les informations disponibles seront affichées, offrant une vue verbeuse. En utilisant hidden, afficher également les ports distants cachés par le filtre intelligent. Lors de la spécification d'un ou plusieurs ports, les informations affichées sont limitées à la liste des ports donnée.

show interfaces [ports ethX [,...]] [details | summary] [hidden]

Afficher les informations sur chaque interface locale connue du démon lldpd(8). Avec summary, seul le nom et la description du port de chaque interface locale seront affichés. En revanche, avec details, toutes les informations disponibles seront affichées, offrant une vue verbeuse. En utilisant hidden, afficher également les ports locaux cachés par le filtre intelligent. Lors de la spécification d'un ou plusieurs ports, les informations affichées sont limitées à la liste des ports donnée.

show chassis [details | summary]

Afficher les informations sur le châssis local. Avec summary, la plupart des détails sont omis. En revanche, avec details, toutes les informations disponibles seront affichées, offrant une vue verbeuse.

watch [ports ethX [,...]] [details | summary] [hidden] [limit X]

Observer les changements de voisins et les signaler dès qu'ils se produisent. Lors de la spécification de ports, les changements ne sont signalés que lorsqu'ils se produisent sur les ports donnés. hidden, summary et details ont la même signification que décrite précédemment. Si limit est spécifié, lldpcli se terminera après avoir reçu le nombre d'événements spécifié.

show configuration

Afficher la configuration globale du démon lldpd(8).

show statistics [ports ethX [,...]] [summary]

Rapporter les statistiques relatives à LLDP, comme le nombre de LLDPDU transmis, reçus, rejetés ou non reconnus. Lors de la spécification de ports, seules les statistiques du port donné sont rapportées. Avec summary, les statistiques de chaque port sont additionnées.

update

Faire en sorte que lldpd(8) mette à jour ses informations et envoie de nouveaux PDU LLDP sur toutes les interfaces.

configure system hostname nom

Remplacer le nom d'hôte du système par la valeur fournie. Par défaut, le nom du système est le FQDN trouvé à partir de la valeur résolue de uname -n. Comme valeur spéciale, utiliser "." (point) pour utiliser le nom d'hôte court au lieu d'un FQDN.

unconfigure system hostname

Ne pas remplacer le nom d'hôte du système et rétablir l'utilisation du nom du nœud.

configure system description description

Remplacer la description du châssis par la valeur fournie au lieu d'utiliser le nom du noyau, le nom du nœud, la version du noyau, la date de compilation et l'architecture.

unconfigure system description

Ne pas remplacer la description du châssis et utiliser une valeur calculée à partir du nom du nœud, du nom du noyau, de la version du noyau, de la date de compilation et de l'architecture à la place.

configure system chassisid description

Remplacer l'ID du châssis par la valeur fournie au lieu d'utiliser l'adresse MAC d'une interface ou le nom d'hôte.

unconfigure system chassisid

Ne pas remplacer l'ID du châssis, mais utiliser à la place une valeur calculée à partir de l'une des adresses MAC de l'interface (ou du nom d'hôte si aucune n'est trouvée).

configure system platform description

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Remplacez la description de la plateforme par la valeur fournie au lieu d'utiliser le nom du noyau. Cette valeur est actuellement uniquement utilisée pour CDP.

unconfigure system platform

Ne remplacez pas la description de la plateforme et utilisez le nom du noyau. Cette option annule la précédente.

configure system capabilities enabled capabilities

Remplacez les capacités système par la valeur fournie au lieu d'utiliser les informations du noyau. Plusieurs capacités peuvent être spécifiées, séparées par des virgules. Seules les capacités disponibles peuvent être activées. Les capacités valides sont :
bridge
 
docsis
 
other
 
repeater
 
router
 
station
 
telephone
 
wlan
 
Voici un exemple d'utilisation :
configure system capabilities enabled bridge,router

unconfigure system capabilities enabled

Ne remplacez pas les capacités, mais utilisez plutôt les informations du noyau. Cette option annule la précédente.

configure system interface pattern pattern

Spécifiez sous forme de valeurs séparées par des virgules (CSV) les interfaces sur lesquelles écouter et à partir desquelles envoyer des LLDPDU. Sans cette option, lldpd utilisera toutes les interfaces physiques disponibles. Cette option peut utiliser des jokers. Plusieurs interfaces peuvent être spécifiées, séparées par des virgules. Il est également possible de supprimer une interface en la faisant précéder d'un point d'exclamation. Il est possible d'autoriser une interface en la faisant précéder de deux points d'exclamation. Une interface autorisée l'emporte sur une interface interdite, qui l'emporte sur une interface simplement correspondante. Par exemple, avec eth*,!eth1,!eth2 lldpd utilisera uniquement les interfaces commençant par eth, à l'exception de eth1 et eth2. Alors qu'avec *,!eth*,!!eth1 lldpcli utilisera toutes les interfaces, à l'exception des interfaces commençant par eth, à l'exception de eth1. Lorsqu'une correspondance exacte est trouvée, elle contourne certains tests. Par exemple, si eth0.12 est spécifié, il sera accepté même s'il s'agit d'une interface VLAN.

unconfigure system interface pattern

Supprimez tout modèle d'interface précédemment configuré et utilisez toutes les interfaces physiques. Cette option annule la précédente.

configure system interface permanent pattern

Spécifiez les interfaces dont la configuration est conservée de manière permanente par lldpd. Par défaut, lldpd ignore toutes les données relatives aux interfaces lorsqu'elles sont supprimées du système (statistiques, configuration personnalisée). Cette option permet de spécifier un modèle similaire au modèle d'interface. Si une interface disparaît mais correspond au modèle, ses données sont conservées en mémoire et réutilisées si l'interface réapparaît à un moment donné. Par exemple, sous Linux, on pourrait utiliser le modèle eth*,eno*,enp*, qui devrait correspondre aux interfaces fixes sur la plupart des systèmes.

unconfigure system interface permanent

Supprimez tout modèle d'interface permanente précédemment configuré. Toute interface supprimée du système sera oubliée. Cette option annule la précédente.

configure system interface description

Certains systèmes d'exploitation permettent à l'utilisateur de définir une description pour une interface. La définition de cette option permettra à lldpd de remplacer cette description par le nom du voisin pair s'il en trouve un, ou par le nombre de voisins trouvés.

unconfigure system interface description

Ne mettez pas à jour la description de l'interface avec le nom du voisin pair. Cette option annule la précédente.

configure system interface promiscuous

Activez le mode promu sur les interfaces gérées.

Lorsque l'interface n'est plus gérée (ou lorsque vous quittez lldpd), l'interface reste en mode promu car il est difficile de savoir si quelqu'un d'autre l'a également mise en mode promu.

Cette option s'est avérée utile lorsque le commutateur distant est un Cisco 2960 et que la carte réseau locale dispose d'une accélération matérielle VLAN. Dans ce cas, vous pourriez ne pas recevoir les trames LLDP du commutateur distant. L'explication la plus plausible est que la trame est étiquetée avec un certain VLAN (généralement le VLAN 1) et que votre carte réseau filtre les VLANs. Ce n'est pas la seule solution disponible pour contourner ce problème. Si vous êtes préoccupé par les problèmes de performance, vous pouvez également étiqueter le VLAN 1 sur chaque interface à la place.

Actuellement, cette option n'a d'effet que sous Linux. Sur d'autres systèmes d'exploitation, désactivez l'accélération VLAN, étiquetez le VLAN 1 ou activez le mode promu manuellement sur l'interface.

unconfigure system interface promiscuous

Ne définissez pas le mode promu sur les interfaces gérées. Cette option ne désactive pas le mode promu sur les interfaces qui l'utilisent déjà.

configure system ip management pattern pattern

Spécifiez les adresses de gestion de ce système sous forme de valeurs séparées par des virgules (CSV). Comme pour les interfaces (décrites ci-dessus), cette option peut utiliser des jokers et des inversions. Sans cette option, la première adresse IPv4 et la première adresse IPv6 sont utilisées. Si une adresse IP exacte est fournie, elle est utilisée comme adresse de gestion sans aucune vérification. Si seuls des modèles négatifs sont fournis, une seule adresse IPv4 et une seule adresse IPv6 sont choisies. Sinon, plusieurs d'entre elles peuvent être sélectionnées. Pour supprimer les adresses IPv6, utilisez !*:*. Si un nom d'interface correspond, la première adresse IPv4 et la première adresse IPv6 associées à cette interface seront choisies.

unconfigure system ip management pattern

Annule tout modèle spécifique pour la correspondance des adresses de gestion. Cette option annule la précédente.

configure system bond-slave-src-mac-type value

Définissez le type de MAC source dans les trames LLDP envoyées sur les esclaves de liaison.

Les types valides sont :

real
MAC réel de l'esclave
zero
MAC tout zéro
fixed
Une valeur fixe arbitraire (00:60:08:69:97:ef)
local
MAC réel avec le bit d'administration locale défini. Si le MAC réel a déjà le bit d'administration locale défini, revenez à la valeur fixe.

La valeur par défaut pour bond-slave-src-mac-type est local. Certains commutateurs peuvent se plaindre lorsque l'on utilise l'une des deux autres valeurs possibles (soit parce que 00:00:00:00:00:00 n'est pas une adresse MAC valide, soit parce que l'adresse MAC change d'un port à l'autre). L'utilisation de local peut entraîner une adresse MAC dupliquée sur le réseau (mais c'est assez improbable).

configure system max-neighbors neighbors

Modifiez le nombre maximum de voisins acceptés (pour chaque protocole) sur une interface. Il s'agit d'une valeur globale. La valeur par défaut est 32. Ce paramètre ne s'applique qu'aux futurs voisins.

configure lldp agent-type nearest-bridge | nearest-non-tpmr-bridge | nearest-customer-bridge

L'adresse MAC de destination utilisée pour envoyer les LLDPDU permet à un agent de contrôler la propagation des LLDPDU. Par défaut, l'adresse MAC 01:80:c2:00:00:0e est utilisée et limite la propagation des LLDPDU au pont le plus proche (nearest-bridge). Pour indiquer à lldpd d'utiliser l'adresse MAC 01:80:c2:00:00:03 à la place, utilisez nearest-nontpmr-bridge. Pour utiliser l'adresse MAC 01:80:c2:00:00:00 à la place, utilisez nearest-customer-bridge.

configure lldp capabilities-advertisements

Activez la publicité du TLV des capacités du châssis. Actuellement, c'est le défaut.

unconfigure lldp capabilities-advertisements

Désactivez la publicité du TLV des capacités du châssis.

configure lldp management-addresses-advertisements

Activez la publicité du TLV des adresses de gestion. Actuellement, c'est le défaut.

unconfigure lldp management-addresses-advertisements

Désactivez la publicité du TLV des adresses de gestion.

configure lldp portidsubtype ifname | macaddress

configure [ports ethX [,...]] lldp portidsubtype local valeur

Force le sous-type de l'ID du port. Par défaut, lldpd utilise l'adresse MAC comme identifiant de port et le nom de l'interface comme description de port, sauf si l'interface possède un alias. Dans ce cas, le nom de l'interface sera utilisé comme identifiant de port et la description sera l'alias de l'interface. Avec cette commande, vous pouvez forcer l'identifiant de port à être le nom de l'interface (avec ifname), l'adresse MAC (avec macaddress) ou une valeur locale (avec valeur). Dans ce dernier cas, la valeur locale doit être fournie.

configure [ports ethX [,...]] lldp portdescription description

Force la description du port à la chaîne fournie.

configure lldp tx-interval intervalle

Change le délai de transmission à la valeur spécifiée en secondes. Le délai de transmission est le délai entre deux transmissions de PDU LLDP. La plage valide est de 1 à 3600 secondes. La valeur par défaut est de 30 secondes. Remarque : lldpd démarre également un autre minuteur de rafraîchissement basé sur le système sur chaque port pour détecter les changements tels que le nom d'hôte. Il s'agit de la valeur de tx-interval multipliée par 20.

Vous pouvez spécifier une valeur d'intervalle en millisecondes en ajoutant un suffixe "ms" à la valeur (par exemple, "configure lldp tx-interval 1500ms" est 1,5s, pas 1500s). Dans ce cas, la durée de vie (TTL) des trames LLDP reçues et envoyées est arrondie à la seconde supérieure. Remarque : l'intervalle effectif peut être limité par les capacités du système d'exploitation et la vitesse du processeur.

configure lldp tx-hold hold

Change la valeur de maintien de transmission à la valeur spécifiée. Cette valeur est utilisée pour calculer la durée de vie (TTL) des paquets transmis, qui est le produit de cette valeur et du délai de transmission. La plage valide est de 1 à 100. La valeur par défaut est 4, et donc la durée de vie par défaut est de 120 secondes.

configure [ports ethX [,...]] lldp status rx-and-tx | rx-only | tx-only | disabled

Configure le statut administratif du port donné. Par défaut, tous les ports sont configurés en mode rx-and-tx. Cela signifie qu'ils peuvent recevoir et transmettre des trames LLDP (ainsi que d'autres protocoles si nécessaire). En mode rx-only, ils n'émettent aucune trame et en mode tx-only, ils ne reçoivent aucune trame. En mode disabled, aucune trame n'est envoyée et toute trame entrante est ignorée. Ce paramètre ne remplace pas le mode de fonctionnement du démon principal. S'il est configuré en mode réception seule (avec le drapeau -r), la définition de tout mode de transmission n'aura aucun effet.

configure [ports ethX [,...]] lldp vlan-tx vlan_id [prio priorité [dei dei]]

Configure le port donné pour envoyer des trames LLDP sur un VLAN spécifié. Avec l'identifiant VLAN (VID) comme vlan_id, le Priority Code Point (PCP) comme priorité, et le Drop Eligible Indicator (DEI) comme dei. lldpd accepte les trames LLDP sur tous les VLAN.

configure [ports ethX [,...]] lldp custom-tlv [add | replace] oui oui subtype subtype [oui-info contenu]

Émet un TLV personnalisé pour OUI oui, avec le sous-type subtype et facultativement avec les octets spécifiés dans contenu. oui et contenu doivent être une liste d'octets séparés par des virgules au format hexadécimal. oui doit avoir exactement 3 octets de long. Si add est spécifié, le TLV sera ajouté. C'est l'action par défaut. Si replace est spécifié, tous les TLV ayant le même oui et subtype seront remplacés.

unconfigure [ports ethX [,...]] lldp custom-tlv [oui oui] [subtype subtype]

Lorsque aucun OUI n'est spécifié, supprime tous les TLV personnalisés précédemment configurés. Lorsque l'OUI oui et le sous-type subtype sont spécifiés, supprime des instances spécifiques de TLV personnalisés.

configure [ports ethX [,...]] lldp vlan-advertisements pattern pattern

Configure les annonces VLAN pour le port donné sous forme de valeurs séparées par des virgules (CSV). Comme pour les interfaces (décrit ci-dessus), cette option peut utiliser des caractères génériques et des inversions. Sans cette option, lldpd annoncera tous les VLAN.

unconfigure [ports ethX [,...]] lldp vlan-advertisements pattern

Supprime tout modèle d'annonce VLAN précédemment configuré pour le port donné.

configure lldp fast-start enable | tx-interval intervalle

Configure le mécanisme de démarrage rapide LLDP. Lorsqu'un nouveau voisin LLDP est détecté, le démarrage rapide permet à lldpd de raccourcir l'intervalle entre deux LLDPDU. enable doit activer le démarrage rapide LLDP tandis que tx-interval spécifie l'intervalle entre deux LLDPDU en secondes. La plage d'intervalles valide est de 1 à 3600 secondes. L'intervalle par défaut est de 1 seconde. Une fois 4 LLDPDU envoyées, le mécanisme de démarrage rapide est désactivé jusqu'à ce qu'un nouveau voisin soit détecté.

unconfigure lldp fast-start

Désactive le mécanisme de démarrage rapide LLDP.

configure [ports ethX [,...]] med location coordinate latitude latitude longitude longitude altitude altitude unité datum datum

Annonce une localisation basée sur des coordonnées sur les ports donnés (ou sur tous les ports si aucun port n'est spécifié). Le format de latitude est un nombre décimal à virgule flottante suivi de N ou S. Le format de longitude est un nombre décimal à virgule flottante suivi de E ou W. altitude est un nombre décimal à virgule flottante suivi de m lorsqu'il est exprimé en mètres ou f lorsqu'il est exprimé en étages. Un espace est attendu entre le nombre à virgule flottante et l'unité. datum est l'une des valeurs suivantes :
  • WGS84
  • NAD83
  • NAD83/MLLW

Une utilisation valide de cette commande est :

configure ports eth0 med location coordinate latitude 48.85667N longitude 2.2014E altitude 117.47 m datum WGS84

configure [ports ethX [,...]] med location address country pays [type valeur [...]]

Annonce une adresse civique sur les ports donnés (ou sur tous les ports si aucun port n'est spécifié). pays est le code à deux lettres représentant le pays. Les arguments restants doivent être appariés pour former l'adresse. Le premier membre de chaque paire indique le type du second membre, qui est un texte libre. Voici la liste des types valides :
  • language
  • country-subdivision
  • county
  • city
  • city-division
  • block
  • street
  • direction
  • trailing-street-suffix
  • street-suffix
  • number
  • number-suffix
  • landmark
  • additional
  • name
  • zip
  • building
  • unit
  • floor
  • room
  • place-type
  • script

Une utilisation valide de cette commande est :

configure ports eth1 med location address country US street "Commercial Road" city "Roseville"

configure [ports ethX [,...]] med location elin numero

Annonce la disponibilité d'un numéro ELIN. Ceci est utilisé pour établir des appels d'urgence. Si le numéro fourni est trop petit, il sera complété par des 0. Voici un exemple d'utilisation :
configure ports eth2 med location elin 911

configure [ports ethX [,...]] med policy application application [unknown] [tagged] [vlan vlan] [priority priorité] [dscp dscp]

Annonce une politique réseau spécifique pour les ports donnés (ou pour tous les ports si aucun port n'a été fourni). Seul le type d'application est obligatoire. application doit être l'une des valeurs suivantes :
  • voice
  • voice-signaling
  • guest-voice
  • guest-voice-signaling
  • softphone-voice
  • video-conferencing
  • st
    • reaming-video
    • video-signaling

    L'indicateur unknown indique que la politique réseau pour le type d'application spécifié est requise par l'appareil mais est actuellement inconnue. Ceci est utilisé par les appareils terminaux, pas par les appareils de connectivité réseau. Si non spécifié, la politique réseau pour le type d'application donné est définie.

    Un VLAN spécifié avec vlan indique quel ID de VLAN 802.1q doit être annoncé pour la politique réseau. Une valeur valide est comprise entre 1 et 4094. tagged indique que le VLAN doit être balisé (tagged) pour le type d'application spécifié.

    priority permet de spécifier la priorité de couche 2 IEEE 802.1d / IEEE 802.1p, également connue sous le nom de classe de service (CoS), à utiliser pour le type d'application spécifié. Ce champ est généralement ignoré si aucun VLAN n'est spécifié. Les noms correspondent à la norme 802.1D-2004 (tableau G-2). Certaines normes plus récentes peuvent utiliser des étiquettes différentes. Seules les valeurs numériques doivent être utilisées. Les étiquettes acceptées sont :

    1
    background
    0
    best-effort
    2
    excellent-effort
    3
    critical-applications
    4
    video
    5
    voice
    6
    internetwork-control
    7
    network-control

    dscp représente la valeur DSCP à annoncer pour la politique réseau donnée. DiffServ/Differentiated Services Code Point (DSCP) valeur telle que définie dans la RFC 2474 de l'IETF pour le type d'application spécifié. Valeur : 0 (par défaut selon RFC 2475) à 63. Note : Les valeurs DSCP de sélecteur de classe sont rétrocompatibles pour les appareils qui ne prennent en charge que l'ancien format Type de Service (ToS) de précédence IP. (Voir les RFC pour la signification de ces valeurs)

    Une utilisation valide de cette commande est :

    configure med policy application voice vlan 500 priority voice dscp 46

configure [ports ethX [,...]] med power pse | pd source source priority priority value value

Annonce le TLV LLDP-MED POE-MDI pour les ports spécifiés ou pour toutes les interfaces si aucun port n'est fourni. On peut agir comme un PD (consommateur d'énergie) ou un PSE (fournisseur d'énergie). Aucune vérification n'est effectuée sur la validité des paramètres, bien que LLDP-MED requière certaines restrictions :
  • Le PD ne doit jamais demander plus de puissance que la classe physique 802.3af.
  • Le PD ne doit jamais consommer plus que la puissance maximale annoncée par le PSE.
  • Le PSE ne doit pas réduire la puissance allouée au PD lorsque cette puissance est utilisée.
  • Le PSE peut demander une puissance réduite en utilisant le mode de conservation d'énergie.
  • Être PSE ou PD est un paramètre global, pas un paramètre par port. lldpcli n'applique pas cela : un port peut être configuré comme PD ou PSE. LLDP-MED exige également qu'un PSE ait une seule source d'alimentation (primaire ou de secours). Encore une fois, lldpcli n'applique pas cela. Chaque port peut avoir sa propre source d'alimentation. Il en va de même pour le PD et la priorité d'alimentation. Le MIB LLDP-MED ne permet pas ce type de représentation.

Les types valides sont :

pse
Power Sourcing Entity (fournisseur d'énergie)
pd
Power Device (consommateur d'énergie)

Les sources valides sont :

unknown
Inconnue
primary
Pour le PSE, la source d'alimentation est la source d'alimentation principale.
backup
Pour le PSE, la source d'alimentation est la source d'alimentation de secours, ou un mode de conservation d'énergie est demandé (le PSE peut fonctionner sur onduleur, par exemple).
pse
Pour le PD, la source d'alimentation est le PSE.
local
Pour le PD, la source d'alimentation est une source locale.
both
Pour le PD, la source d'alimentation est à la fois le PSE et une source locale.

Les priorités valides sont :

unknown
Priorité inconnue
critical
Critique
high
Élevée
low
Basse

value doit être la puissance totale en milliwatts requise par le périphérique PD ou disponible par le périphérique PSE.

Voici un exemple d'utilisation :

configure med power pd source pse priority high value 5000

configure [ports ethX [,...]] dot3 power pse | pd [supported] [enabled] [paircontrol] powerpairs powerpairs [class class] [type type source source priority priority requested requested allocated allocated]

Annonce le TLV Dot3 POE-MDI pour le port donné ou pour tous les ports si aucun n'a été fourni. On peut agir comme un PD (consommateur d'énergie) ou un PSE (fournisseur d'énergie). Cette configuration est distincte de la configuration de la transmission du TLV LLDP-MED POE-MDI, mais l'utilisateur doit s'assurer de la cohérence de ces deux configurations si elles sont utilisées ensemble.

supported signifie que l'alimentation MDI est prise en charge sur le port donné, tandis que enabled signifie que l'alimentation MDI est activée. paircontrol est utilisé pour indiquer si la sélection de paires peut être contrôlée. Les valeurs valides pour powerpairs sont :

signal
Seules les paires de signalisation sont utilisées.
spare
Seules les paires de réserve sont utilisées.

Lorsque spécifié, class est class-, suivi d'un nombre de 0 à 4. Par exemple, class-0, class-1, class-2, class-3, classe-4.

Pour 802.3at, les classes sont les suivantes :

0
Défaut (Non spécifié), PD 0.44-12.95 W, PSE 15.4 W
1
Appareil à très faible consommation, PD 0.44-3.84 W, PSE 4.0 W
2
Appareil à faible consommation, PD 3.84-6.49 W, PSE 7.0 W
3
Appareil à consommation moyenne, PD 6.49-12.95 W, PSE 15.4 W
4
Appareil à forte consommation (PoE+), PD 12.95-25.5 W, PSE 30.0 W

Les paramètres restants sont conformes à 802.3at et sont optionnels. type doit être 1 ou 2, indiquant si l'appareil est conforme à 802.3at type 1 ou 802.3at type 2. Les valeurs de source et priority sont les mêmes que pour le TLV LLDP-MED POE-MDI. requested et allocated sont exprimés en milliwatts.

Voici deux utilisations valides de cette commande :

configure ports eth3 dot3 power pse supported enabled paircontrol powerpairs spare class class-3
configure dot3 power pd supported enabled powerpairs spare class class-3 type 1 source pse priority low requested 10000 allocated 15000

pause

Met en pause les opérations de lldpd. lldpd n'enverra ni ne recevra plus de trames. Ceci peut être annulé avec la commande resume. Ceci ne fonctionne qu'en mode interactif car lldpd demande à lldpcli de reprendre après avoir lu le fichier de configuration.

resume

Reprend les opérations de lldpd. lldpd commencera à envoyer et recevoir des trames. Cette commande est émise en interne après le traitement de la configuration mais peut être utilisée à tout moment si une commande pause manuelle est émise.
