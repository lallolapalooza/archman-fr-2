SYNTAXE

llvm-debuginfo-analyzer [options] [fichier ...]

DESCRIPTION

llvm-debuginfo-analyzer analyse les sections de débogage et de texte dans les fichiers objets binaires et affiche leur contenu dans une vue logique, qui est une représentation lisible par l'homme correspondant étroitement à la structure du code source original de l'utilisateur. Les formats de fichiers objets pris en charge incluent ELF, Mach-O, WebAssembly, PDB et COFF.

La vue logique abstrait la complexité associée aux différentes représentations de bas niveau des informations de débogage intégrées dans le fichier objet. llvm-debuginfo-analyzer produit une vue canonique des informations de débogage, quelle que soit la façon dont elles sont formatées. La même vue logique sera observée quel que soit le format du fichier objet, à condition que les informations de débogage représentent correctement le même code source original.

La vue logique comprend les éléments logiques suivants : type, portée, symbole et ligne, qui sont les éléments logiciels de base utilisés dans le langage de programmation C/C++. Chaque élément logique possède un ensemble d'attributs, tels que types, classes, fonctions, variables, paramètres, etc. L'option --attribute peut être utilisée pour spécifier les attributs à inclure lors de l'affichage d'un élément logique. Un élément logique peut avoir un type qui décrit des types spécifiques d'éléments. Par exemple, une portée pourrait avoir une valeur de type fonction, classe, espace de noms.

llvm-debuginfo-analyzer affiche par défaut une disposition pré-définie d'éléments et d'attributs logiques. Les options de ligne de commande peuvent être utilisées pour contrôler les éléments affichés (--print), en utilisant une disposition spécifique (--report), en faisant correspondre un modèle donné (--select, --select-offsets). En outre, la sortie peut être limitée aux éléments logiques spécifiés en utilisant (--select-lines, --select-scopes, --select-symbols, --select-types).

llvm-debuginfo-analyzer peut également comparer un ensemble de vues logiques (--compare), pour trouver des différences et identifier d'éventuels problèmes de syntaxe des informations de débogage (--warning) dans tout fichier objet.

OPTIONS

Les options de llvm-debuginfo-analyzer sont divisées en plusieurs catégories, chacune adaptée à un objectif différent :

  • GÉNÉRAL - Options LLVM standard pour afficher l'aide, la version, etc.
  • ATTRIBUTS - Décrit comment inclure différents détails lors de l'affichage d'un élément.
  • AFFICHAGE - Spécifie quels éléments seront inclus lors de l'affichage de la vue.
  • SORTIE - Décrit les formats pris en charge lors de l'affichage de la vue.
  • RAPPORT - Décrit les mises en page des formats pour l'affichage de la vue.
  • SÉLECTION - Permet d'utiliser des critères ou conditions spécifiques pour sélectionner les éléments à afficher.
  • COMPARAISON - Compare les vues logiques et affiche les éléments manquants et/ou ajoutés.
  • AVERTISSEMENT - Affiche les avertissements détectés lors de la création de la vue.
  • INTERNE - Analyse interne de la vue logique.

REPORT

Selon la tâche exécutée (imprimer, comparer, sélectionner), plusieurs mises en page sont prises en charge pour afficher les éléments de manière plus appropriée, afin de rendre la sortie plus facile à comprendre.

--report=<valeur[,valeur,...]>
Avec valeur étant l'une des options dans la liste suivante.
=all: Inclure tous les rapports ci-dessous.
=children: Les éléments et leurs enfants sont affichés dans un format arborescent.
=list: Les éléments sont affichés dans un format tabulaire.
=parents: Les éléments et leurs parents sont affichés dans un format arborescent.
=view: Les éléments, les parents et les enfants sont affichés dans un format arborescent.

La mise en page list présente les éléments logiques sous forme tabulaire sans aucune relation parent-enfant. Cela peut être la manière préférée d'afficher les éléments qui correspondent à des critères spécifiques lors de la comparaison des vues logiques, ce qui facilite la recherche des différences.

Les mises en page children, parents et view affichent les éléments dans un format arborescent, les portées représentant leurs nœuds, et les types, symboles, lignes et autres portées représentant les enfants. La mise en page montre la relation de portée lexicale entre les éléments, le fichier binaire étant la racine de l'arbre (niveau 0) et chaque unité de compilation étant un enfant (niveau 1).

La mise en page children inclut les éléments qui correspondent à tout critère donné (--select) ou (--compare) et ses enfants.

La mise en page parents inclut les éléments qui correspondent à tout critère donné (--select) ou (--compare) et ses parents.

La mise en page combinée view inclut les éléments qui correspondent à tout critère donné (--select) ou (--compare), leurs parents et leurs enfants.

Notes :

1.
Lorsqu'un critère de sélection (--select) est spécifié sans option de rapport, la mise en page list est choisie.

SELECTION

As the printed output can reach a considerable size, several selection options, enable printing of specific elements.

The pattern matching can ignore the case (--select-nocase) and be extended to use regular expressions (--select-regex).

COMPARE

When dealing with debug information, there are situations when the printing of the elements is not the correct approach. That is the case, when we are interested in the effects caused by different versions of the same toolchain, or the impact of specific compiler optimizations.

For those cases, we are looking to see which elements have been added or removed. Due to the complicated debug information format, it is very difficult to use a regular diff tool to find those elements; even impossible when dealing with different debug formats.

llvm-debuginfo-analyzer supports a logical element comparison, allowing to find semantic differences between logical views, produced by different toolchain versions or even debug information formats.

When comparing logical views created from different debug formats, its accuracy depends on how close the debug information represents the user code. For instance, a logical view created from a binary file with DWARF debug information may include more detailed data than a logical view created from a binary file with CodeView debug information.

The following options describe the elements to compare.

--compare=<value[,value,...]>
With value being one of the options in the following list.
=all: Include all the below elements.
=lines: Include lines.
=scopes: Include scopes.
=symbols: Include symbols.
=types: Include types.

llvm-debuginfo-analyzer takes the first binary file on the command line as the reference and the second one as the target. To get a more descriptive report, the comparison is done twice. The reference and target views are swapped, in order to produce those missing elements from the target view and those added elements to the reference view.

See --report options on how to describe the comparison reports.

WARNING

When reading the input object files, llvm-debuginfo-analyzer can detect issues in the raw debug information. These may not be considered fatal to the purpose of printing a logical view but they can give an indication about the quality and potentially expose issues with the generated debug information.

The following options describe the warnings to be recorded for later printing, if they are requested by --print.

--warning=<value[,value,...]>
With value being one of the options in the following list.
=all: Include all the below warnings.

The following options collect additional information during the creation of the logical view, to include invalid coverage values and locations for symbols; invalid code ranges; lines that are zero.

=coverages: Invalid symbol coverages values.
=lines: Debug lines that are zero.
=locations: Invalid symbol locations.
=ranges: Invalid code ranges.

valeur étant l'une des options de la liste suivante.

Les options suivantes permettent de vérifier l'intégrité de la vue logique ; collecter les tags de débogage qui sont traités ou non implémentés ; ignorer le numéro de ligne de l'élément logique, pour faciliter la comparaison de la vue logique lors de l'utilisation d'outils de comparaison externes ; afficher les options de la ligne de commande utilisées pour invoquer llvm-debuginfo-analyzer.

=id: Afficher l'ID unique de l'élément.
=cmdline: Afficher la ligne de commande.
=integrity: Vérifier l'intégrité des éléments.
=none: Ignorer le numéro de ligne de l'élément.
=tag: Tags d'informations de débogage.

Note : Pour le format ELF, les tags collectés représentent les tags de débogage qui ne sont pas traités. Pour le format PE/COFF, ils représentent les tags qui sont traités.

MODE DE COMPARAISON

Dans ce mode, llvm-debuginfo-analyzer compare les vues logiques pour produire un rapport sur les éléments logiques manquants ou ajoutés. C'est une aide très puissante pour trouver des différences sémantiques dans les informations de débogage produites par différentes versions de la chaîne d'outils ou même par des chaînes d'outils complètement différentes (Par exemple, un compilateur produisant DWARF peut être directement comparé à un compilateur complètement différent produisant CodeView).

En utilisant l'exemple précédent, nous avons trouvé le problème d'informations de débogage ci-dessus (lié à l'emplacement incorrect de portée précédente pour le 'typedef int INTEGER') en comparant avec un autre compilateur.

En utilisant GCC pour générer test-dwarf-gcc.o, nous pouvons appliquer un modèle de sélection avec le mode d'affichage pour obtenir la sortie de vue logique suivante.

                        --report=list
                        --print=symbols,types
                        test-dwarf-clang.o test-dwarf-gcc.o

MODE DE COMPARAISON

En utilisant l'exemple précédent, nous avons trouvé le problème des informations de débogage ci-dessus (lié à l'emplacement de portée invalide précédent pour le >'typedef int INTEGER') en comparant avec un autre compilateur.

En utilisant GCC pour générer test-dwarf-gcc.o, nous pouvons appliquer un modèle de sélection avec le mode d'impression pour obtenir la vue logique suivante :

llvm-debuginfo-analyzer --attribute=level
                        --select-regex --select-nocase --select=INTe
                        --report=list
                        --print=symbols,types
                        test-clang.o test-dwarf-gcc.o
Vue logique :
[000]           {File} 'test-clang.o'
[001]           {CompileUnit} 'test.cpp'
[003]     4     {TypeAlias} 'INTEGER' -> 'int'
[004]     5     {Variable} 'CONSTANT' -> 'const INTEGER'
Vue logique :
[000]           {File} 'test-dwarf-gcc.o'
[001]           {CompileUnit} 'test.cpp'
[004]     4     {TypeAlias} 'INTEGER' -> 'int'
[004]     5     {Variable} 'CONSTANT' -> 'const INTEGER'

La sortie montre que les deux objets contiennent les mêmes éléments. Mais le 'typedef INTEGER' est situé à un niveau d'étendue différent. L'objet généré par GCC affiche '4', ce qui est la valeur correcte.

Il existe 2 méthodes de comparaison : vue logique et éléments logiques.

VUE LOGIQUE

Elle compare la vue logique dans son ensemble ; pour qu'il y ait une correspondance, chaque élément logique comparé doit avoir les mêmes parents et enfants.

La sortie affiche sous forme de vue les éléments manquants (-), ajoutés (+), donnant plus de contexte en échangeant les fichiers objets de référence et cible.

llvm-debuginfo-analyzer --attribute=level
                        --compare=types
                        --report=view
                        --print=symbols,types
                        test-clang.o test-dwarf-gcc.o
Référence : 'test-clang.o'
Cible :    'test-dwarf-gcc.o'
Vue logique :
 [000]           {File} 'test-clang.o'
 [001]             {CompileUnit} 'test.cpp'
 [002]     1         {TypeAlias} 'INTPTR' -> '* const int'
 [002]     2         {Function} extern not_inlined 'foo' -> 'int'
 [003]                 {Block}

+[004]     4             {TypeAlias} 'INTEGER' -> 'int'

La sortie montre le chemin de fusion de la vue (référence et cible) avec les éléments manquants et ajoutés.

ÉLÉMENTS LOGIQUES

Elle compare des éléments logiques individuels sans tenir compte de la parenté. Pour les deux méthodes de comparaison, les critères d'égalité incluent le nom, l'emplacement dans le code source, le type, le niveau d'étendue lexicale.
