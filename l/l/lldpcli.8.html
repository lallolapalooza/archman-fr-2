LLDPCLI(8) Manuel de l'administrateur système LLDPCLI(8)

NOM

lldpcli, lldpctl — contrôler le démon LLDP

SYNTAXE

lldpcli [-dv] [-u socket] [-f format] [-c fichier] [commande ...]

lldpctl [-dv] [-u socket] [-f format] [interfaces ...]

DESCRIPTION

Le programme lldpcli contrôle le démon lldpd(8).

Lorsqu'aucune commande n'est spécifiée, lldpcli démarrera un shell interactif qui pourra être utilisé pour entrer des commandes arbitraires comme si elles étaient spécifiées en ligne de commande. Ce shell interactif devrait fournir des fonctionnalités de complétion et d'historique.

Les options sont les suivantes :

-d
Activer plus d'informations de débogage. Ce drapeau peut être répété.
-u socket
Spécifier le socket de domaine Unix utilisé pour la communication avec lldpd(8).
-v
Afficher la version de lldpcli. Lorsque répété, afficher plus d'informations de construction.
-f format
Choisir le format de sortie. Actuellement, les formats plain, xml, json, json0 et keyvalue sont disponibles. La valeur par défaut est plain. json0 est plus verbeux que json, mais la structure de l'objet JSON n'est pas affectée par le nombre d'interfaces ou le nombre de voisins. Il est donc plus facile à analyser.
-c fichier
Lire le fichier de configuration donné. Cette option peut être répétée plusieurs fois. Si un répertoire est fourni, chaque fichier à l'intérieur se terminant par .conf sera lu. L'ordre est alphabétique.

Lorsqu'il est invoqué sous le nom lldpctl, lldpcli affichera des informations détaillées sur chaque voisin sur les interfaces spécifiées ou sur toutes les interfaces si aucune n'est spécifiée. Cette commande est principalement conservée pour la compatibilité descendante avec les versions plus anciennes.

Les commandes suivantes sont prises en charge par lldpcli. Lorsqu'il n'y a pas d'ambiguïté, les mots clés peuvent être abrégés. Par exemple, show neighbors ports eth0 summary et sh neigh p eth0 sum sont la même commande.

exit
Quitter lldpcli.

help [...]

Afficher l'aide générale ou l'aide sur une commande. Vous pouvez également obtenir de l'aide en utilisant la complétion ou en appuyant sur la touche ?. La complétion et l'aide en ligne peuvent ne pas être disponibles, cependant, si lldpcli a été compilé sans prise en charge de readline, mais la commande help est toujours disponible.

show neighbors [ports ethX [,...]] [details | summary] [hidden]

Afficher les informations sur chaque voisin connu du démon lldpd(8). Avec summary, seul le nom et la description du port de chaque hôte distant seront affichés. D'autre part, avec details, toutes les informations disponibles seront affichées, donnant une vue détaillée. En utilisant hidden, afficher également les ports distants masqués par le filtre intelligent. Lors de la spécification d'un ou plusieurs ports, les informations affichées sont limitées à la liste de ports donnée.

show interfaces [ports ethX [,...]] [details | summary] [hidden]

Afficher les informations sur chaque interface locale connue du démon lldpd(8). Avec summary, seul le nom et la description du port de chaque interface locale seront affichés. D'autre part, avec details, toutes les informations disponibles seront affichées, donnant une vue détaillée. En utilisant hidden, afficher également les ports locaux masqués par le filtre intelligent. Lors de la spécification d'un ou plusieurs ports, les informations affichées sont limitées à la liste de ports donnée.

show chassis [details | summary]

Afficher les informations sur le châssis local. Avec summary, la plupart des détails sont ignorés. D'autre part, avec details, toutes les informations disponibles seront affichées, donnant une vue détaillée.

watch [ports ethX [,...]] [details | summary] [hidden] [limit X]

Surveiller tout changement de voisin et les signaler dès qu'ils se produisent. En spécifiant des ports, les changements ne sont signalés que lorsqu'ils se produisent sur les ports donnés. hidden, summary et details ont la même signification que celle décrite précédemment. Si limit est spécifié, lldpcli se terminera après avoir reçu le nombre d'événements spécifié.

show configuration

Afficher la configuration globale du démon lldpd(8).

show statistics [ports ethX [,...]] [summary]

Signaler les statistiques liées à LLDP, comme le nombre de LLDPDU transmis, reçus, ignorés ou non reconnus. En spécifiant des ports, seules les statistiques du port donné sont signalées. Avec summary, les statistiques de chaque port sont additionnées.

update

Faire en sorte que lldpd(8) met à jour ses informations et envoie de nouveaux paquets LLDP sur toutes les interfaces.

configure system hostname nom

Remplace le nom d'hôte système par la valeur fournie. Par défaut, le nom du système est le nom de domaine complet (FQDN) trouvé à partir de la valeur résolue de uname -n. Comme valeur spéciale, utilisez "." (point) pour utiliser le nom d'hôte court au lieu d'un FQDN.

unconfigure system hostname

Ne pas remplacer le nom d'hôte système et rétablir l'utilisation du nom du nœud.

configure system description description

Remplace la description du châssis par la valeur fournie au lieu d'utiliser le nom du noyau, le nom du nœud, la version du noyau, la date de compilation et l'architecture.

unconfigure system description

Ne pas remplacer la description du châssis et utiliser une valeur calculée à partir du nom du nœud, du nom du noyau, de la version du noyau, de la date de compilation et de l'architecture à la place.

configure system chassisid description

Remplace l'ID du châssis par la valeur fournie au lieu d'utiliser l'adresse MAC d'une interface ou le nom d'hôte.

unconfigure system chassisid

Ne pas remplacer l'ID du châssis, mais utiliser une valeur calculée à partir des adresses MAC d'une interface (ou du nom d'hôte si aucune n'est trouvée).

configure system platform description

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Remplace la description de la plateforme par la valeur fournie au lieu d'utiliser le nom du noyau. Cette valeur est actuellement uniquement utilisée pour CDP.

unconfigure system platform

Ne remplace pas la description de la plateforme et utilise le nom du noyau. Cette option annule la précédente.

configure system capabilities enabled capabilities

Remplace les capacités du système par la valeur fournie au lieu d'utiliser les informations du noyau. Plusieurs capacités peuvent être spécifiées, séparées par des virgules. Seules les capacités disponibles peuvent être activées. Les capacités valides sont :
bridge
 
docsis
 
other
 
repeater
 
router
 
station
 
telephone
 
wlan
 
Voici un exemple d'utilisation :
configure system capabilities enabled bridge,router

unconfigure system capabilities enabled

Ne remplace pas les capacités, mais utilise plutôt les informations du noyau. Cette option annule la précédente.

configure system interface pattern pattern

Spécifie sous forme de valeurs séparées par des virgules (CSV) les interfaces sur lesquelles écouter et à partir desquelles envoyer les LLDPDU. Sans cette option, lldpd utilisera toutes les interfaces physiques disponibles. Cette option peut utiliser des caractères génériques. Plusieurs interfaces peuvent être spécifiées, séparées par des virgules. Il est également possible de supprimer une interface en la faisant précéder d'un point d'exclamation. Il est possible d'autoriser une interface en la faisant précéder de deux points d'exclamation. Une interface autorisée prime sur une interface interdite, qui prime sur une interface simplement correspondante. Par exemple, avec eth*,!eth1,!eth2 lldpd n'utilisera que les interfaces commençant par eth à l'exception de eth1 et eth2. Tandis qu'avec *,!eth*,!!eth1 lldpcli utilisera toutes les interfaces, à l'exception des interfaces commençant par eth à l'exception de eth1. Lorsqu'une correspondance exacte est trouvée, certains tests sont contournés. Par exemple, si eth0.12 est spécifié, il sera accepté même s'il s'agit d'une interface VLAN.

unconfigure system interface pattern

Supprime tout motif d'interface précédemment configuré et utilise toutes les interfaces physiques. Cette option annule la précédente.

configure system interface permanent pattern

Spécifie les interfaces dont la configuration est conservée de manière permanente par lldpd. Par défaut, lldpd ignore toute donnée concernant les interfaces lorsqu'elles sont supprimées du système (statistiques, configuration personnalisée). Cette option permet de spécifier un motif similaire au motif d'interface. Si une interface disparaît mais correspond au motif, ses données sont conservées en mémoire et réutilisées si l'interface réapparaît à un moment donné. Par exemple, sous Linux, on pourrait utiliser le motif eth*,eno*,enp*, qui devrait correspondre aux interfaces fixes sur la plupart des systèmes.

unconfigure system interface permanent

Supprime tout motif d'interface permanente précédemment configuré. Toute interface supprimée du système sera oubliée. Cette option annule la précédente.

configure system interface description

Certains systèmes d'exploitation permettent à l'utilisateur de définir une description pour une interface. L'activation de cette option permettra à lldpd de remplacer cette description par le nom du voisin distant s'il en trouve un, ou par le nombre de voisins trouvés.

unconfigure system interface description

Ne met pas à jour la description de l'interface avec le nom du voisin distant. Cette option annule la précédente.

configure system interface promiscuous

Active le mode promiscueux sur les interfaces gérées.

Lorsque l'interface n'est plus gérée (ou lors de la sortie de lldpd), l'interface reste en mode promiscueux car il est difficile de savoir si quelqu'un d'autre a également mis l'interface en mode promiscueux.

Cette option s'est avérée utile lorsque le commutateur distant est un Cisco 2960 et que la carte réseau locale dispose d'une accélération matérielle VLAN. Dans ce cas, vous pourriez ne pas recevoir les trames LLDP du commutateur distant. L'explication la plus plausible est que la trame est étiquetée avec un certain VLAN (généralement le VLAN 1) et que votre carte réseau filtre les VLAN. Ce n'est pas la seule solution disponible pour contourner ce problème. Si vous êtes préoccupé par les problèmes de performance, vous pouvez également étiqueter le VLAN 1 sur chaque interface à la place.

Actuellement, cette option n'a d'effet que sur Linux. Sur d'autres systèmes d'exploitation, désactivez l'accélération VLAN, étiquetez le VLAN 1 ou activez manuellement le mode promiscueux sur l'interface.

unconfigure system interface promiscuous

Ne met pas le mode promiscueux sur les interfaces gérées. Cette option ne désactive pas le mode promiscueux sur les interfaces qui l'utilisent déjà.

configure system ip management pattern pattern

Spécifie les adresses de gestion de ce système sous forme de valeurs séparées par des virgules (CSV). Comme pour les interfaces (décrites ci-dessus), cette option peut utiliser des caractères génériques et des inversions. Sans cette option, la première adresse IPv4 et la première adresse IPv6 sont utilisées. Si une adresse IP exacte est fournie, elle est utilisée comme adresse de gestion sans aucune vérification. Si seuls des motifs négatifs sont fournis, une adresse IPv4 et une adresse IPv6 sont choisies. Sinon, plusieurs d'entre elles peuvent être sélectionnées. Pour supprimer les adresses IPv6, utilisez !*:*. Si un nom d'interface correspond, la première adresse IPv4 et la première adresse IPv6 associées à cette interface seront choisies.

unconfigure system ip management pattern

Désactive tout motif spécifique pour la correspondance des adresses de gestion. Cette option annule la précédente.

configure system bond-slave-src-mac-type value

Définit le type de MAC source dans les trames LLDP envoyées sur les esclaves de liaison (bond slaves).

Les types valides sont :

real
MAC réel de l'esclave
zero
MAC tout zéro
fixed
Une valeur fixe arbitraire (00:60:08:69:97:ef)
local
MAC réel avec le bit localement administré activé. Si le MAC réel a déjà le bit localement administré activé, revient à la valeur fixe.

La valeur par défaut pour bond-slave-src-mac-type est local. Certains commutateurs peuvent se plaindre lors de l'utilisation de l'une des deux autres valeurs possibles (soit parce que 00:00:00:00:00:00 n'est pas un MAC valide, soit parce que l'adresse MAC bascule d'un port à un autre). L'utilisation de local peut entraîner une adresse MAC dupliquée sur le réseau (mais c'est assez peu probable).

configure system max-neighbors neighbors

Modifie le nombre maximum de voisins acceptés (pour chaque protocole) sur une interface. Il s'agit d'une valeur globale. La valeur par défaut est 32. Ce paramètre ne s'applique qu'aux futurs voisins.

configure lldp agent-type nearest-bridge | nearest-non-tpmr-bridge | nearest-customer-bridge

L'adresse MAC de destination utilisée pour envoyer les LLDPDU permet à un agent de contrôler la propagation des LLDPDU. Par défaut, l'adresse MAC 01:80:c2:00:00:0e est utilisée et limite la propagation du LLDPDU au pont le plus proche (nearest-bridge). Pour indiquer à lldpd d'utiliser l'adresse MAC 01:80:c2:00:00:03 à la place, utilisez nearest-non-tpmr-bridge. Pour utiliser l'adresse MAC 01:80:c2:00:00:00 à la place, utilisez nearest-customer-bridge.

configure lldp capabilities-advertisements

Active la publicité du TLV des capacités du châssis. Actuellement la valeur par défaut.

unconfigure lldp capabilities-advertisements

Désactive la publicité du TLV des capacités du châssis.

configure lldp management-addresses-advertisements

Active la publicité du TLV des adresses de gestion. Actuellement la valeur par défaut.

unconfigure lldp management-addresses-advertisements

Désactive la publicité du TLV des adresses de gestion.

configure lldp portidsubtype ifname | macaddress

configure [ports ethX [,...]] lldp portidsubtype local value

Force le type de sous-entité de l'ID de port. Par défaut, lldpd utilisera l'adresse MAC comme identifiant de port et le nom de l'interface comme description de port, sauf si l'interface a un alias. Dans ce cas, le nom de l'interface sera utilisé comme identifiant de port et la description sera l'alias de l'interface. Avec cette commande, vous pouvez forcer l'identifiant de port à être le nom de l'interface (avec ifname), l'adresse MAC (avec macaddress) ou une valeur locale (avec value). Dans ce dernier cas, la valeur locale doit être fournie.

configure [ports ethX [,...]] lldp portdescription description

Force la description du port à la chaîne fournie.

configure lldp tx-interval interval

Change le délai de transmission à la valeur spécifiée en secondes. Le délai de transmission est le délai entre deux transmissions de paquets LLDP. La plage valide est de 1 à 3600 secondes. La valeur par défaut est de 30 secondes. Note : lldpd démarre également un autre minuteur de rafraîchissement système sur chaque port pour détecter les changements tels qu'un nom d'hôte. C'est la valeur du `tx-interval` multipliée par 20.

Vous pouvez spécifier une valeur d'interval en millisecondes en ajoutant un suffixe "ms" au chiffre (par exemple, "configure lldp tx-interval 1500ms" est égal à 1,5 s, pas à 1500 s). Dans ce cas, la durée de vie (TTL) des trames LLDP reçues et émises est arrondie à la seconde supérieure. Note : l'intervalle effectif peut être limité par les capacités du système d'exploitation et la vitesse du processeur.

configure lldp tx-hold hold

Change la valeur de maintien de transmission à la valeur spécifiée. Cette valeur est utilisée pour calculer la durée de vie (TTL) des paquets transmis, qui est le produit de cette valeur et du délai de transmission. La plage valide est de 1 à 100. La valeur par défaut est 4, et par conséquent la durée de vie (TTL) par défaut est de 120 secondes.

configure [ports ethX [,...]] lldp status rx-and-tx | rx-only | tx-only | disabled

Configure le statut administratif du port donné. Par défaut, tous les ports sont configurés pour être en mode rx-and-tx. Cela signifie qu'ils peuvent recevoir et transmettre des trames LLDP (ainsi que d'autres protocoles si nécessaire). En mode rx-only, ils n'émettront aucune trame et en mode tx-only, ils ne recevront aucune trame. En mode disabled, aucune trame ne sera envoyée et toute trame reçue sera ignorée. Ce paramètre ne remplace pas le mode opérationnel du démon principal. S'il est configuré en mode réception uniquement (avec le drapeau -r), la définition de tout mode de transmission n'aura aucun effet.

configure [ports ethX [,...]] lldp vlan-tx vlan_id [prio priority [dei dei]]

Configure le port donné pour envoyer des trames LLDP sur un VLAN spécifié. Avec l'identifiant VLAN (VID) comme vlan_id, le Point de Code Prioritaire (PCP) comme priority, et l'Indicateur Éligible à la Suppression (DEI) comme dei. lldpd accepte les trames LLDP sur tous les VLANs.

configure [ports ethX [,...]] lldp custom-tlv [add | replace] oui oui subtype subtype [oui-info content]

Émet un TLV personnalisé pour l'OUI oui, avec le sous-type subtype et optionnellement avec les octets spécifiés dans content. L'oui et le content doivent être une liste d'octets séparés par des virgules au format hexadécimal. L'oui doit être exactement de 3 octets. Si add est spécifié, le TLV sera ajouté. C'est l'action par défaut. Si replace est spécifié, tous les TLVs avec le même oui et le même subtype seront remplacés.

unconfigure [ports ethX [,...]] lldp custom-tlv [oui oui] [subtype subtype]

Lorsque aucun OUI n'est spécifié, supprime tous les TLVs personnalisés précédemment configurés. Lorsque l'OUI oui et le sous-type subtype sont spécifiés, supprime des instances spécifiques de TLV personnalisé.

configure [ports ethX [,...]] lldp vlan-advertisements pattern pattern

Configure les annonces VLAN pour le port donné sous forme de valeurs séparées par des virgules (CSV). Comme pour les interfaces (décrites ci-dessus), cette option peut utiliser des caractères génériques et des inversions. Sans cette option, lldpd annoncera tous les VLANs.

unconfigure [ports ethX [,...]] lldp vlan-advertisements pattern

Supprime tout motif d'annonce VLAN précédemment configuré pour le port donné.

configure lldp fast-start enable | tx-interval interval

Configure le mécanisme de démarrage rapide de LLDP. Lorsqu'un nouveau voisin LLDP est détecté, le démarrage rapide permet à lldpd de raccourcir l'intervalle entre deux LLDPDU. enable doit activer le démarrage rapide de LLDP tandis que tx-interval spécifie l'intervalle entre deux LLDPDU en secondes. La plage d'intervalles valide est de 1 à 3600 secondes. L'intervalle par défaut est de 1 seconde. Une fois que 4 LLDPDU ont été envoyées, le mécanisme de démarrage rapide est désactivé jusqu'à ce qu'un nouveau voisin soit détecté.

unconfigure lldp fast-start

Désactive le mécanisme de démarrage rapide de LLDP.

configure [ports ethX [,...]] med location coordinate latitude latitude longitude longitude altitude altitude unit datum datum

Annonce une localisation basée sur des coordonnées sur les ports donnés (ou sur tous les ports si aucun port n'est spécifié). Le format de la latitude est un nombre décimal à virgule flottante suivi de N ou S. Le format de la longitude est un nombre décimal à virgule flottante suivi de E ou W. L'altitude est un nombre décimal à virgule flottante suivi de m lorsqu'elle est exprimée en mètres ou de f lorsqu'elle est exprimée en étages. Un espace est attendu entre le nombre à virgule flottante et l'unité. datum est l'une des valeurs suivantes :
  • WGS84
  • NAD83
  • NAD83/MLLW

Une utilisation valide de cette commande est :

configure ports eth0 med location coordinate latitude 48.85667N longitude 2.2014E altitude 117.47 m datum WGS84

configure [ports ethX [,...]] med location address country country [type value [...]]

Annonce une adresse civique sur les ports donnés (ou sur tous les ports si aucun port n'est spécifié). La country est le code à deux lettres représentant le pays. Les arguments restants doivent être associés pour former l'adresse. Le premier membre de chaque paire indique le type du second membre, qui est un texte libre. Voici la liste des types valides :
  • language
  • country-subdivision
  • county
  • city
  • city-division
  • block
  • street
  • direction
  • trailing-street-suffix
  • street-suffix
  • number
  • number-suffix
  • landmark
  • additional
  • name
  • zip
  • building
  • unit
  • floor
  • room
  • place-type
  • script

Une utilisation valide de cette commande est :

configure ports eth1 med location address country US street "Commercial Road" city "Roseville"

configure [ports ethX [,...]] med location elin number

Annonce la disponibilité d'un numéro ELIN. Ceci est utilisé pour la mise en place d'appels d'urgence. Si le numéro fourni est trop petit, il sera complété par des 0. Voici un exemple d'utilisation :
configure ports eth2 med location elin 911

configure [ports ethX [,...]] med policy application application [unknown] [tagged] [vlan vlan] [priority priority] [dscp dscp]

Annonce une politique réseau spécifique pour les ports donnés (ou pour tous les ports si aucun port n'a été fourni). Seul le type d'application est obligatoire. application doit être l'une des valeurs suivantes :
  • voice
  • voice-signaling
  • guest-voice
  • guest-voice-signaling
  • softphone-voice
  • video-conferencing
  • st
  • reaming-video
  • video-signaling

L'indicateur unknown indique que la politique réseau pour le type d'application spécifié est requise par le périphérique mais est actuellement inconnue. Ceci est utilisé par les périphériques de terminaison, pas par les périphériques de connectivité réseau. Si non spécifié, la politique réseau pour le type d'application donné est définie.

Une VLAN spécifiée avec vlan indique quel identifiant de VLAN 802.1q doit être annoncé pour la politique réseau. Une valeur valide est comprise entre 1 et 4094. tagged indique que le VLAN doit être étiqueté pour le type d'application spécifié.

priority permet de spécifier la priorité de couche 2 IEEE 802.1d / IEEE 802.1p, également connue sous le nom de classe de service (CoS), à utiliser pour le type d'application spécifié. Ce champ est généralement ignoré si aucun VLAN n'est spécifié. Les noms correspondent à la norme 802.1D-2004 (tableau G-2). Certaines normes plus récentes peuvent utiliser des étiquettes différentes. Seules les valeurs numériques doivent être utilisées. Les étiquettes acceptées sont :

1
background
0
best-effort
2
excellent-effort
3
critical-applications
4
video
5
voice
6
internetwork-control
7
network-control

dscp représente la valeur DSCP à annoncer pour la politique réseau donnée. Valeur DiffServ/Differentiated Services Code Point (DSCP) telle que définie dans la RFC 2474 de l'IETF pour le type d'application spécifié. Valeur : 0 (par défaut selon RFC 2475) à 63. Remarque : Les valeurs DSCP de sélecteur de classe sont rétrocompatibles avec les périphériques qui ne prennent en charge que l'ancien format IP precedence Type of Service (ToS). (Voir les RFC pour la signification de ces valeurs)

Un exemple d'utilisation valide est :

configure med policy application voice vlan 500 priority voice dscp 46

configure [ports ethX [,...]] med power pse | pd source source priority priority value value

Annonce le TLV LLDP-MED POE-MDI pour les ports spécifiés ou pour toutes les interfaces si aucun port n'est fourni. On peut agir en tant que PD (consommateur d'énergie) ou PSE (fournisseur d'énergie). Aucune vérification de la validité des paramètres n'est effectuée, bien que LLDP-MED exige certaines restrictions :
  • Le PD ne doit jamais demander plus d'énergie que la classe physique 802.3af.
  • Le PD ne doit jamais consommer plus que la puissance maximale annoncée par le PSE.
  • Le PSE ne doit pas réduire la puissance allouée au PD lorsque cette puissance est utilisée.
  • Le PSE peut demander une puissance réduite en utilisant le mode d'économie d'énergie.
  • Être PSE ou PD est un paramètre global, pas un paramètre par port. lldpcli n'applique pas cela : un port peut être défini comme PD ou PSE. LLDP-MED exige également qu'un PSE ait une seule source d'alimentation (primaire ou de secours). Encore une fois, lldpcli n'applique pas cela. Chaque port peut avoir sa propre source d'alimentation. Il en va de même pour le PD et la priorité d'alimentation. Le MIB LLDP-MED ne permet pas ce type de représentation.

Les types valides sont :

pse
Power Sourcing Entity (fournisseur d'énergie)
pd
Power Device (consommateur d'énergie)

Les sources valides sont :

unknown
Inconnu
primary
Pour le PSE, la source d'alimentation est la source d'alimentation principale.
backup
Pour le PSE, la source d'alimentation est la source d'alimentation de secours, ou un mode d'économie d'énergie est demandé (le PSE peut fonctionner sur onduleur, par exemple).
pse
Pour le PD, la source d'alimentation est le PSE.
local
Pour le PD, la source d'alimentation est une source locale.
both
Pour le PD, la source d'alimentation est à la fois le PSE et une source locale.

Les priorités valides sont :

unknown
Priorité inconnue
critical
Critique
high
Élevée
low
Basse

value doit être la puissance totale en milliwatts requise par le périphérique PD ou disponible par le périphérique PSE.

Voici un exemple d'utilisation :

configure med power pd source pse priority high value 5000

configure [ports ethX [,...]] dot3 power pse | pd [supported] [enabled] [paircontrol] powerpairs powerpairs [class class] [type type source source priority priority requested requested allocated allocated]

Annonce le TLV Dot3 POE-MDI pour le port donné ou pour tous les ports si aucun n'a été fourni. On peut agir en tant que PD (consommateur d'énergie) ou PSE (fournisseur d'énergie). Cette configuration est distincte de la configuration de la transmission du TLV LLDP-MED POE-MDI, mais l'utilisateur doit s'assurer de la cohérence de ces deux configurations si elles sont utilisées ensemble.

supported signifie que la puissance MDI est prise en charge sur le port donné, tandis que enabled signifie que la puissance MDI est activée. paircontrol est utilisé pour indiquer si le contrôle des paires peut être activé. Les valeurs valides pour powerpairs sont :

signal
Seules les paires de signalisation sont utilisées.
spare
Seules les paires de réserve sont utilisées.

Lorsque spécifié, class est class-, suivi d'un nombre de 0 à 4. Par exemple class-0, class-1, class-2, class-3, classe-4.

Pour 802.3at, les classes sont les suivantes :

0
Défaut (Non spécifié), PD 0.44-12.95 W, PSE 15.4 W
1
Appareil très basse consommation, PD 0.44-3.84 W, PSE 4.0 W
2
Appareil basse consommation, PD 3.84-6.49 W, PSE 7.0 W
3
Appareil moyenne consommation, PD 6.49-12.95 W, PSE 15.4 W
4
Appareil haute consommation (PoE+), PD 12.95-25.5 W, PSE 30.0 W

Les paramètres restants sont conformes à 802.3at et sont optionnels. type doit être 1 ou 2, indiquant si l'appareil est conforme à la norme 802.3at type 1 ou 802.3at type 2. Les valeurs de source et priority sont les mêmes que pour le TLV LLDP-MED POE-MDI. requested et allocated sont exprimés en milliwatts.

Voici deux utilisations valides de cette commande :

configure ports eth3 dot3 power pse supported enabled paircontrol powerpairs spare class class-3
configure dot3 power pd supported enabled powerpairs spare class class-3 type 1 source pse priority low requested 10000 allocated 15000

pause

Met en pause les opérations de lldpd. lldpd n'enverra ni ne recevra plus de trames. Ceci peut être annulé avec la commande resume. Ceci ne fonctionne qu'interactivement car lldpd demande à lldpcli de reprendre après avoir lu le fichier de configuration.

resume

Reprend les opérations de lldpd. lldpd commencera à envoyer et à recevoir des trames. Cette commande est émise en interne après le traitement de la configuration, mais peut être utilisée à tout moment si une commande manuelle pause est émise.
