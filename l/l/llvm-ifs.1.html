NOM

llvm-ifs - outil d'empotage d'objets partagés

SYNOPIS

llvm-ifs [options] entrées

DESCRIPTION

llvm-ifs est un outil qui produit conjointement des empotages lisibles par l'homme (fichiers .ifs) pour les objets partagés et des empotages d'objets partagés linkables (fichiers .so) à partir d'objets partagés ELF ou d'empotages textuels. Les empotages textuels sont utiles pour surveiller les changements d'ABI de l'objet partagé. Les empotages d'objets partagés linkables peuvent être utilisés pour éviter des relinks inutiles lorsque l'ABI des bibliothèques partagées ne change pas.

FORMATS IFS

Voici un exemple de représentation textuelle (IFS) d'un objet partagé produit par llvm-ifs :

--- !ifs-v1
IFSVersion: 3.0
SoName: libtest.so /* Optionnel */
Target: x86_64-unknown-linux-gnu   /* Optionnel, format 1, même format que le triple cible llvm */
Target: { Arch: x86_64, Endianness: little, Bitwidth: 64 } /* Optionnel, format 2 */
NeededLibs:
  - libc.so.6
Symbols:
  - { Name: sym0, Type: Notype }
  - { Name: sym1, Type: Object, Size: 0 }
  - { Name: sym2, Type: Func, Weak: false }
  - { Name: sym3, Type: TLS }
  - { Name: sym4, Type: Unknown, Warning: foo }
...
  • IFSVersion : Version du fichier IFS pour la compatibilité du lecteur.
  • SoName (facultatif) : Nom du fichier d'objet partagé qui est empoté.
  • Target (facultatif) : L'architecture, l'endianness et les informations de largeur de bits de cet objet partagé. Il peut être dans un format explicite ou dans le format de triple cible LLVM implicite. Il peut être facultatif et peut être remplacé par des options de ligne de commande.
  • NeededLibs : La liste des objets partagés externes dont cette bibliothèque dépend.
  • Symbols : Une collection de toutes les données nécessaires pour lier les objets pour chaque symbole, triées par nom dans l'ordre croissant.
  • Name : Nom du symbole.
  • Type : Indique si le symbole est un objet, une fonction, sans type, un stockage local thread (TLS) ou inconnu. Les types de symboles non explicitement pris en charge sont mappés en tant qu'inconnus pour améliorer le rapport signal/bruit.
  • Size : La taille du symbole en question, ne s'applique pas aux fonctions, et est facultative pour les symboles de type "NoType".
  • Undefined : Indique si le symbole est défini ou non dans ce fichier d'objet partagé.
  • Weak : Indique si le symbole doit être traité comme faible ou non.
  • Warning (facultatif) : Texte d'avertissement à afficher lors du lien de ce symbole.

Ce format textuel basé sur YAML contient tout ce qui est nécessaire pour générer un objet partagé ELF linkable ainsi qu'un fichier au format Apple TAPI. L'ordre des symboles est trié, de sorte que ces fichiers peuvent être facilement comparés à l'aide d'outils de comparaison (diff). Si le contenu du fichier change, cela indique un changement potentiellement destructeur pour l'ABI.

FORMAT D'EMPÔTAGE ELF

Un fichier ELF minimum pouvant être utilisé par l'éditeur de liens doit avoir les sections suivantes correctement renseignées :

  • En-tête ELF.
  • En-têtes de section.
  • Table des symboles dynamiques (section .dynsym).
  • Table des chaînes dynamiques (section .dynstr).
  • Table dynamique (section .dynamic).
  • Entrée DT_SYMTAB.
  • Entrée DT_STRTAB.
  • Entrée DT_STRSZ.
  • Entrées DT_NEEDED. (facultatif)
  • Entrée DT_SONAME. (facultatif)
•
Table des chaînes d'en-tête de section (section .shstrtab)

Ce fichier ELF peut présenter des problèmes de compatibilité avec les outils d'analyse ELF qui dépendent des en-têtes de programme. Les éditeurs de liens comme LLD fonctionnent correctement avec un tel fichier ELF minimum sans erreur.

OPTIONS

--input-format=[IFS|ELF|OtherObjectFileFormats]
Spécifie le format du fichier d'entrée. Actuellement, seuls les fichiers IFS texte et les fichiers d'objets partagés ELF sont pris en charge. Ce drapeau est facultatif car le format d'entrée peut être déduit.
--output-elf=<nom-fichier-sortie>
Spécifie le fichier de sortie pour l'empotage d'objet partagé ELF.
--output-ifs=<nom-fichier-sortie>
Spécifie le fichier de sortie pour l'IFS texte.
--output-tbd=<nom-fichier-sortie>
Spécifie le fichier de sortie pour le tbd au format Apple TAPI.
--arch=[x86_64|AArch64|...]
Ce drapeau est facultatif et ne doit être utilisé que lors de la lecture d'un fichier IFS qui ne définit pas l'Arch (architecture). Ce drapeau définit l'architecture du fichier de sortie, et peut être n'importe quelle chaîne prise en charge par le champ 'e_machine' d'ELF. Si la valeur est en conflit avec le fichier IFS, une erreur sera signalée et le programme s'arrêtera.
--endianness=[little|big]
Ce drapeau est facultatif et ne doit être utilisé que lors de la lecture d'un fichier IFS qui ne définit pas l'Endianness. Ce drapeau définit l'endianness du fichier de sortie. Si la valeur est en conflit avec le fichier IFS, une erreur sera signalée et le programme s'arrêtera.
--bitwidth=[32|64]
Ce drapeau est facultatif et ne doit être utilisé que lors de la lecture d'un fichier IFS qui ne définit pas la BitWidth. Ce drapeau définit la largeur de bits du fichier de sortie. Si la valeur est en conflit avec le fichier IFS d'entrée, une erreur sera signalée et le programme s'arrêtera.
--target=<triple cible>
Ce drapeau est facultatif et ne doit être utilisé que lors de la lecture d'un fichier IFS qui ne définit aucune information de cible. Ce drapeau définit l'architecture, l'endianness et la largeur de bits du fichier de sortie en utilisant le triple cible llvm. Ce drapeau ne peut pas être utilisé simultanément avec d'autres drapeaux liés à la cible.
--hint-ifs-target=<triple cible>
Ce drapeau est facultatif et ne doit être utilisé que lors de la lecture d'un objet partagé ELF et de la génération d'un fichier IFS. Par défaut, llvm-ifs utilisera les champs 'Arch, Endianness et BitWidth' pour refléter les informations de cible du fichier objet d'entrée. L'utilisation de ce drapeau indiquera à llvm-ifs le triple cible attendu dans le fichier IFS de sortie. Si la valeur correspond aux informations de cible du fichier objet, cette valeur sera utilisée dans le champ 'Target:' de l'IFS généré. Si elle entre en conflit avec le fichier objet d'entrée, une erreur sera signalée et le programme s'arrêtera.
--hint-ifs-target
Ce drapeau est facultatif et ne doit être utilisé que lors de la génération d'un fichier IFS. Ce drapeau supprime le champ Arch du fichier IFS afin qu'il puisse être remplacé ultérieurement.
--strip-ifs-endianness
Ce drapeau est facultatif et ne doit être utilisé que lors de la génération d'un fichier IFS. Ce drapeau supprime le champ Endianness du fichier IFS afin qu'il puisse être remplacé ultérieurement.
--strip-ifs-bitwidth
Ce drapeau est facultatif et ne doit être utilisé que lors de la génération d'un fichier IFS. Ce drapeau supprime le champ BitWidth du fichier IFS afin qu'il puisse être remplacé ultérieurement.
--strip-ifs-target
Ce drapeau est facultatif et ne doit être utilisé que lors de la génération d'un fichier IFS. Ce drapeau supprime le champ

--write-if-changed
Lorsque ce drapeau est défini, llvm-ifs n'écrira le fichier de sortie que s'il n'existe pas déjà ou si son contenu est différent du fichier existant.
--strip-size
Lorsque ce drapeau est défini, llvm-ifs supprimera le champ de taille du fichier ifs de sortie. Ceci est utile pour les objets partagés qui n'ont l'intention d'être liés qu'à du code indépendant de la position qui n'a pas besoin de décalages de copie, ou lorsque la taille d'un objet n'est pas une partie utile de l'abi à suivre.

STATUT DE SORTIE

Si llvm-ifs réussit, il se terminera avec 0. Sinon, si une erreur se produit, il se terminera avec une valeur non nulle.
