NOM

llvm-remarkutil - Utilitaire de remarques

SYNTAXE

llvm-remarkutil [sous-commande] [options]

DESCRIPTION

Utilitaire pour afficher des informations à partir de, et convertir entre différents formats de remarques https://llvm.org/docs/Remarks.html.

SOUS-COMMANDES

  • bitstream2yaml - Resérialise les remarques bitstream en YAML.
  • yaml2bitstream - Resérialise les remarques YAML en bitstream.
  • instruction-count - Affiche les comptes d'instructions des fonctions.
  • annotation-count - Compte les types de remarques à partir des remarques d'annotation.
  • size-diff - Calcule la différence dans les remarques de taille.

bitstream2yaml

SYNTAXE : llvm-remarkutil bitstream2yaml <fichier d'entrée> -o <fichier de sortie>

Résumé

Prend un fichier de remarques bitstream en entrée et le resérialise au format YAML.

yaml2bitstream

SYNTAXE : llvm-remarkutil yaml2bitstream <fichier d'entrée> -o <fichier de sortie>

Résumé

Prend un fichier de remarques YAML en entrée et le resérialise au format bitstream.

instruction-count

SYNTAXE : llvm-remarkutil instruction-count <fichier d'entrée> --parser=<bitstream|yaml> [--use-debug-loc] -o <fichier de sortie>

Résumé

Affiche des remarques de comptage d'instructions pour chaque fonction. Les remarques de comptage d'instructions encodent le nombre d'instructions dans une fonction au moment de l'impression de l'assembleur.

Les remarques de comptage d'instructions nécessitent des remarques d'asm-printer.

Le format CSV est le suivant :

Fonction,NombreInstructions
foo,123

Si --use-debug-loc est passé, le CSV inclura le chemin source, le numéro de ligne et la colonne.

Source,Fonction,NombreInstructions
chemin:ligne:colonne,foo,3

annotation-count

SYNTAXE : llvm-remarkutil annotation-count <fichier d'entrée> --parser=<bitstream|yaml> --annotation-type=<type> [--use-debug-loc] -o <fichier de sortie>

Résumé

Affiche un compte pour le type d'annotation <type> de remarque pour chaque fonction. Le compte exprime le nombre de vérifications de remarques insérées dans la fonction.

Les remarques de comptage d'annotations nécessitent des remarques de l'AnnotationRemarksPass.

Le format CSV est le suivant :

Fonction,Compte
foo,123

Si --use-debug-loc est passé, le CSV inclura le chemin source, le numéro de ligne et la colonne.

Source,Fonction,Compte
chemin:ligne:colonne,foo,3

count

SYNTAXE : llvm-remarkutil count [options] <fichier d'entrée>

Résumé

llvm-remarkutil count compte les remarques https://llvm.org/docs/Remarks.html en fonction des propriétés spécifiées. Par défaut, l'outil compte les remarques en fonction du nombre d'occurrences dans un fichier source ou une fonction, ou le total pour le fichier de remarques généré. L'outil prend également en charge la collecte du compte en fonction d'arguments de remarque spécifiques. Les arguments spécifiés doivent avoir une valeur entière pour pouvoir signaler un compte.

L'outil contient des utilitaires pour filtrer le compte de remarques en fonction du nom de la remarque, du nom du passage, de la valeur de l'argument et du type de remarque.

Options

--parser=<yaml|bitstream>
Sélectionne le type de parseur de remarques en entrée. Obligatoire.
  • yaml : L'outil analysera les remarques YAML.
  • bitstream : L'outil analysera les remarques bitstream.
--count-by=<valeur>
Sélectionne l'option pour collecter les remarques.
  • remark-name : compte combien de remarques individuelles existent.
  • arg : compte les remarques en fonction des arguments spécifiés passés par --(r)args. La valeur de l'argument doit être un nombre.
--group-by=<valeur>
Groupe le compte des remarques par propriété.
  • source : Le compte sera collecté par chemin source. Les remarques sans localisation de débogage ne seront pas comptées.
  • function : Le compte est collecté par fonction.
  • function-with-loc : Le compte est collecté par fonction et par source. Les remarques sans localisation de débogage ne seront pas comptées.
  • Total : Affiche un compte pour le fichier de remarques fourni.
--args[=arguments]
Si count-by est défini sur arg, ce drapeau peut être utilisé pour collecter à partir d'arguments de remarque spécifiés représentés sous forme de chaîne de caractères séparée par des virgules. Les arguments doivent avoir une valeur numérique pour pouvoir compter les remarques par.
--rargs[=arguments]
Si count-by est défini sur arg, ce drapeau peut être utilisé pour collecter à partir d'arguments de remarque spécifiés à l'aide d'une expression régulière. Les arguments doivent avoir une valeur numérique pour pouvoir compter les remarques par.
--pass-name[=<chaîne>]
Filtre le compte par nom de passage.
--rpass-name[=<chaîne>]
Filtre le compte par nom de passage en utilisant des expressions régulières.
--remark-name[=<chaîne>]
Filtre le compte par nom de remarque.
--rremark-name[=<chaîne>]
Filtre le compte par nom de remarque en utilisant des expressions régulières.
--filter-arg-by[=<chaîne>]
Filtre le compte par valeur d'argument.
--rfilter-arg-by[=<chaîne>]
Filtre le compte par valeur d'argument en utilisant des expressions régulières.
--remark-type=<valeur>
Filtre les remarques par type avec les options suivantes.
  • unknown
  • passed
  • missed
  • analysis
  • analysis-fp-commute
  • analysis-aliasing
  • failure

size-diff

SYNTAXE : llvm-remarkutil size-diff [options] fichier_a fichier_b --parser parseur

Résumé

Calcule la différence entre deux fichiers de remarques de taille. Les remarques de taille enregistrent les métriques de taille pour différentes régions du programme.

Les options incluent :

--parser=<yaml|bitstream>
Spécifie le format des fichiers de remarques d'entrée. Obligatoire.
--output-diff=<fichier>
Écrit la différence des remarques de taille dans le fichier spécifié.

L'outil compare les régions correspondantes dans les deux fichiers et génère un rapport sur les changements de taille.

OPTIONS

Les options globales suivantes sont disponibles pour tous les sous-commandes :

-h, --help
Affiche un message d'aide et quitte.
--help-all
Affiche l'aide pour tous les sous-commandes et quitte.
--version
Affiche le numéro de version de l'outil et quitte.

EXEMPLES

Convertir un fichier de remarques au format bitstream en YAML :

llvm-remarkutil bitstream2yaml remarks.bc -o remarks.yaml

Compter les instructions par fonction à partir d'un fichier YAML :

llvm-remarkutil instruction-count remarks.yaml --parser=yaml

Compter les remarques de type "missed" dans une fonction spécifique :

llvm-remarkutil count remarks.yaml --parser=yaml --remark-type=missed --group-by=function --function-name=my_function

Calculer la différence entre deux fichiers de remarques de taille :

llvm-remarkutil size-diff file_a.yaml file_b.yaml --parser=yaml --output-diff=diff.txt

NAME

llvm-remarkutil-size-diff

diff size remarks

SYNOPSIS

llvm-remarkutil size-diff file_a file_b

DESCRIPTION

llvm-remarkutil size-diff compare les remarques de taille https://llvm.org/docs/Remarks.html dans deux fichiers de remarques : file_a et file_b.

llvm-remarkutil size-diff peut être utilisé pour obtenir des informations sur les fonctions qui ont été le plus impactées par les changements de génération de code.

Dans la plupart des cas d'utilisation courants, file_a et file_b seront des remarques générées en compilant un code source fixe avec des compilateurs différents ou des paramètres d'optimisation différents.

llvm-remarkutil size-diff gère les remarques au format YAML https://llvm.org/docs/Remarks.html#yaml-remarks et au format bitstream https://llvm.org/docs/Remarks.html#llvm-bitstream-remarks.

Options

--parser=<yaml|bitstream>

Sélectionne le type d'analyseur de remarques d'entrée. Obligatoire.

  • yaml : L'outil analysera les remarques YAML.
  • bitstream : L'outil analysera les remarques bitstream.
--report-style=<human|json>
Style de sortie.
  • human : Rapport textuel lisible par l'homme. Option par défaut.
  • json : Rapport JSON.
--pretty
Pour formater joliment la sortie JSON. Optionnel.

Si la sortie n'est pas définie sur JSON, ceci n'a aucun effet.

-o=<file>
Fichier de sortie pour le rapport. Sortie vers stdout par défaut.

Sortie lisible par l'homme

Le format lisible par l'homme pour llvm-remarkutil size-diff est composé de deux sections :

  • Changements par fonction.
  • Un résumé de haut niveau de tous les changements.

Section des fonctions modifiées

Supposons que vous compariez deux fichiers de remarques ANCIEN et NOUVEAU.

Pour chaque fonction ayant un nombre d'instructions modifié dans ANCIEN et NOUVEAU, llvm-remarkutil size-diff émettra une ligne similaire à celle ci-dessous :

(++|--|==) (>|<) nom_fonction, N instructions, M octets de pile

Une description du format est ci-dessous :

(++|--|==)
Indique dans lequel des fichiers ANCIEN et NOUVEAU la nom_fonction est présente.
  • ++ : Uniquement dans NOUVEAU. ("Ajouté")
  • -- : Uniquement dans ANCIEN. ("Supprimé")
  • == : Dans les deux.
(>|<)
Indique si la nom_fonction a plus ou moins d'instructions dans le second fichier.
  • > : Plus d'instructions dans le second fichier que dans le premier fichier.
  • < : Moins d'instructions dans le second fichier que dans le premier fichier.
nom_fonction
Le nom de la fonction modifiée.
N instructions
Nombre d'instructions du second fichier - nombre d'instructions du premier fichier.
M octets de pile
Nombre d'octets de pile du second fichier - nombre d'octets de pile du premier fichier.

Section Résumé

llvm-remarkutil size-diff affichera un résumé de haut niveau après avoir imprimé toutes les fonctions modifiées.

nombre d'instructions: N (pct_chg_instr%)
utilisation octets de pile: M (pct_chg_pile%)
N
Somme de toutes les modifications du nombre d'instructions entre le second et le premier fichier.
pct_chg_instr%
Pourcentage d'augmentation ou de diminution du nombre d'instructions entre le second et le premier fichier.
M
Somme de toutes les modifications du nombre d'octets de pile entre le second et le premier fichier.
pct_chg_pile%
Pourcentage d'augmentation ou de diminution de l'utilisation des octets de pile entre le second et le premier fichier.

Sortie JSON

Vue de haut niveau

Supposons que nous comparions deux fichiers, ANCIEN et NOUVEAU.

llvm-remarkutil size-diff produira une sortie JSON comme suit.

"Fichiers": [
  "A": "chemin/vers/ANCIEN",
  "B": "chemin/vers/NOUVEAU"
]
"DansLesDeux": [
  ...
],
"UniquementDansA": [
  ...
],
"UniquementDansB": [
  ...
]
Fichiers
Chemins d'origine des fichiers de remarques.
  • A : Chemin vers le premier fichier.
  • B : Chemin vers le second fichier.
DansLesDeux
Fonctions présentes dans les deux fichiers.
UniquementDansA
Fonctions présentes uniquement dans le premier fichier.
UniquementDansB
Fonctions présentes uniquement dans le second fichier.

JSON de fonction

Les sections DansLesDeux, UniquementDansA et UniquementDansB contiennent des informations de taille pour chaque fonction dans les fichiers de remarques d'entrée.

{
  "NomFonction" : "nom_fonction"
  "CompteInstructions": [
      COMPTE_INSTR_A,
      COMPTE_INSTR_B
    ],
  "TaillePile": [
      OCTETS_PILE_A,
      OCTETS_PILE_B
    ],
}
NomFonction
Nom de la fonction.
CompteInstructions
Comptes d'instructions pour la fonction.
  • COMPTE_INSTR_A : Nombre d'instructions dans ANCIEN.
  • COMPTE_INSTR_B : Nombre d'instructions dans NOUVEAU.
TaillePile
Nombre d'octets de pile pour la fonction.
  • OCTETS_PILE_A : Octets de pile dans ANCIEN.
  • OCTETS_PILE_B : Octets de pile dans NOUVEAU.

Calcul des différences à partir du JSON de fonction

Le JSON de fonction ne contient pas les différences. Les outils qui consomment la sortie JSON de llvm-remarkutil size-diff sont responsables du calcul des différences séparément.

Pour calculer les différences :

  • Différence de nombre d'instructions : COMPTE_INSTR_B - COMPTE_INSTR_A
  • Différence de nombre d'octets de pile : OCTETS_PILE_B - OCTETS_PILE_A

Statut de sortie

llvm-remarkutil size-diff retourne 0 en cas de succès, et une valeur non nulle sinon.
