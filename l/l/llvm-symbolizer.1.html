NOM

llvm-symbolizer - convertir les adresses en emplacements de code source

SYNOPSIS

llvm-symbolizer [options] [adresses...]

DESCRIPTION

llvm-symbolizer lit des noms d'entrée et des adresses depuis la ligne de commande et imprime les emplacements de code source correspondants sur la sortie standard. Il peut également symboliser des logs contenant du balisage Symbolizer <> via --filter-markup. Les adresses peuvent être spécifiées comme des nombres ou des noms de symboles.

Si aucune adresse n'est spécifiée sur la ligne de commande, il lit les adresses depuis l'entrée standard. Si aucun nom d'entrée n'est spécifié sur la ligne de commande, mais que des adresses le sont, la première valeur d'adresse est interprétée comme un nom d'entrée. Si une valeur d'entrée n'est pas reconnue, il signale que les informations source n'ont pas été trouvées.

Les noms d'entrée peuvent être spécifiés avec les adresses, soit sur l'entrée standard, soit comme arguments positionnels sur la ligne de commande. Par défaut, les noms d'entrée sont interprétés comme des chemins de fichiers objet. Cependant, préfixer un nom avec BUILDID: indique qu'il s'agit d'un ID de build hexadécimal plutôt qu'un chemin. Cela recherchera le binaire de débogage correspondant. Par souci de cohérence, préfixer un nom avec FILE: indique explicitement qu'il s'agit d'un chemin de fichier objet (le défaut).

Un argument positionnel ou une valeur d'entrée standard peut être précédé de "DATA" ou "CODE" pour indiquer que l'adresse doit être symbolisée comme des données ou du code exécutable respectivement. Si aucun n'est spécifié, "CODE" est supposé. DATA est symbolisé comme l'adresse et la taille du symbole plutôt que le numéro de ligne.

llvm-symbolizer analyse les options de la variable d'environnement LLVM_SYMBOLIZER_OPTS après avoir analysé les options de la ligne de commande. LLVM_SYMBOLIZER_OPTS est principalement utile pour compléter les options de la ligne de commande lorsque llvm-symbolizer est invoqué par un autre programme ou runtime.

EXEMPLES

Tous les exemples suivants utilisent les deux fichiers source suivants comme entrée. Ils utilisent un mélange de liaison de style C et C++ pour illustrer comment ces noms sont imprimés différemment (voir --demangle).

// test.h
extern "C" inline int foz() {
  return 1234;
}
// test.cpp
#include "test.h"
int bar=42;
int foo() {
  return bar;
}
int baz() {
  volatile int k = 42;
  return foz() + k;
}
int main() {
  return foo() + baz();
}

Ces fichiers sont construits comme suit :

$ clang -g test.cpp -o test.elf
$ clang -g -O2 test.cpp -o inlined.elf

Exemple 1 - adresses et objet sur la ligne de commande :

$ llvm-symbolizer --obj=test.elf 0x4004d0 0x400490
foz
/tmp/test.h:1:0
baz()
/tmp/test.cpp:11:0

Exemple 2 - adresses sur l'entrée standard :

$ cat addr.txt
0x4004a0
0x400490
0x4004d0
$ llvm-symbolizer --obj=test.elf < addr.txt
main
/tmp/test.cpp:15:0
baz()
/tmp/test.cpp:11:0
foz
/tmp/./test.h:1:0

Exemple 3 - objet spécifié avec l'adresse :

$ llvm-symbolizer "test.elf 0x400490" "FILE:inlined.elf 0x400480"
baz()
/tmp/test.cpp:11:0
foo()
/tmp/test.cpp:8:10
$ cat addr2.txt
FILE:test.elf 0x400490
inlined.elf 0x400480
$ llvm-symbolizer < addr2.txt
main
/tmp/test.cpp:15:0
foo()
/tmp/test.cpp:8:10

Exemple 4 - préfixes BUILDID et FILE :

$ llvm-symbolizer "FILE:test.elf 0x400490" "DATA BUILDID:123456789abcdef 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr3.txt
FILE:test.elf 0x400490
DATA BUILDID:123456789abcdef 0x601028
$ llvm-symbolizer < addr3.txt
baz()
/tmp/test.cpp:11:0
bar
6295592 4

Exemple 5 - préfixes CODE et DATA :

$ llvm-symbolizer --obj=test.elf "CODE 0x400490" "DATA 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr4.txt
CODE test.elf 0x4004a0
DATA inlined.elf 0x601028
$ llvm-symbolizer < addr4.txt
main
/tmp/test.cpp:15:0
bar
6295592 4

Exemple 6 - options de style chemin :

Cet exemple utilise le même fichier source que ci-dessus, mais le chemin complet du fichier source est /tmp/foo/test.cpp et il est compilé comme suit. Le premier cas montre le chemin absolu par défaut, le second --basenames, et le troisième montre --relativenames.

$ pwd
/tmp
$ clang -g foo/test.cpp -o test.elf
$ llvm-symbolizer --obj=test.elf 0x4004a0
main
/tmp/foo/test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --basenames
main
test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --relativenames
main
foo/test.cpp:15:0

Exemple 7 - Adresses comme noms de symboles :

$ llvm-symbolizer --obj=test.elf main
main
/tmp/test.cpp:14:0
$ llvm-symbolizer --obj=test.elf "CODE foz"
foz
/tmp/test.h:1:0

Exemple 8 - sortie --skip-line-zero pour une adresse sans correspondance de ligne (une adresse associée à la ligne zéro) :

// test.c
int foo = 0;
int x = 1234;
int main() {
  if (x)
    return foo;
  else
    return x;
}

Ces fichiers sont construits comme suit :

$ clang -g -O2 -S test.c -o test.s
$ llvm-mc -filetype=obj -triple=x86_64-unknown-linux  test.s -o test.o
$ llvm-symbolizer --obj=test.o --skip-line-zero 0xa
main
/tmp/test.c:5:7 (approximatif)

OPTIONS

--adjust-vma <offset>
Ajouter le décalage spécifié aux adresses des fichiers objet lors de la recherche. Cela peut être utilisé pour effectuer des recherches comme si l'objet était relocalisé par le décalage.
--skip-line-zero
Si une adresse n'a pas de numéro de ligne associé, utiliser le dernier numéro de ligne de la séquence actuelle dans la table des lignes. Ces lignes sont étiquetées comme "approximatives" dans la sortie car elles peuvent être trompeuses.
--basenames, -s
Imprimer seulement le nom du fichier sans aucun répertoire, au lieu du chemin absolu.
--build-id
Rechercher l'objet en utilisant l'ID de build donné, spécifié sous forme de chaîne hexadécimale. Mutuellement exclusif avec --obj.
--color [=<always|auto|never>]
Spécifier si l'utilisation de la couleur doit être activée en mode --filter-markup. Par défaut, c'est auto, qui détecte si la sortie standard supporte la couleur. Spécifier --color seul est équivalent à --color=always.
--debug-file-directory <path>
Fournir un chemin vers un répertoire contenant un sous-répertoire .build-id pour rechercher les informations de débogage pour les binaires dépouillés. Plusieurs instances de cet argument sont recherchées dans l'ordre donné.
--debuginfod, --no-debuginfod
Indique s'il faut essayer ou non les recherches debuginfod pour les binaires de débogage. Sauf indication contraire, debuginfod n'est activé que si libcurl a été compilé (LLVM_ENABLE_CURL) et qu'au moins une URL de serveur a été fournie par la variable d'environnement DEBUGINFOD_URLS.
--demangle, -C
Imprimer les noms de fonctions démanglés, si les noms sont manglés (par exemple, le nom manglé _Z3bazv devient baz(), tandis que le nom non manglé foz est imprimé tel quel). Par défaut, c'est vrai.
--dwp <path>
Utiliser

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

le fichier DWP spécifié à l'adresse <chemin> pour toutes les CU qui ont des données de débogage DWARF fragmentées.
--fallback-debug-path <chemin>
Lorsqu'un fichier séparé contient des données de débogage, et est référencé par une section de lien de débogage GNU, utilisez le chemin spécifié comme base pour localiser les données de débogage si elles ne peuvent pas être trouvées par rapport à l'objet.
--filter-markup
Lit depuis l'entrée standard, convertit le balisage de symbolisation contenu <> sous une forme lisible par l'homme, et imprime les résultats sur la sortie standard. Les éléments de balisage suivants ne sont pas encore pris en charge :
  • {{{hexdict}}}
  • {{{dumpfile}}}

L'élément de trace de pile {{{bt}}} rapporte les trames en utilisant la syntaxe suivante :

#<numéro>[.<inline>] <adresse> <fonction> <fichier>:<ligne>:<colonne> (<module>+<adresse relative>)

<inline> fournit les numéros de trames pour les appels incorporés dans l'appelant correspondant à <numéro>. Les numéros d'appel incorporés commencent à 1 et augmentent du plus petit appelant au plus grand appelant.

<adresse> est une adresse à l'intérieur de l'instruction d'appel de la fonction. L'adresse peut ne pas être le début de l'instruction. <adresse relative> est le décalage virtuel correspondant dans le <module> chargé à cette adresse.

--functions [=<none|short|linkage>], -f
Spécifie la manière dont les noms de fonctions sont imprimés (omettre le nom de la fonction, imprimer le nom court de la fonction, ou imprimer le nom complet de liaison, respectivement). Par défaut, c'est linkage.
--help, -h
Affiche l'aide et l'utilisation de cette commande.
--inlining, --inlines, -i
Si un emplacement de code source se trouve dans une fonction incorporée, imprime toutes les trames incorporées. C'est le comportement par défaut.
--no-inlines
N'imprime pas les trames incorporées.
--no-demangle
N'imprime pas les noms de fonctions démêlés.
--obj <chemin>, --exe, -e
Chemin du fichier objet à symboliser. Si - est spécifié, lit l'objet directement depuis le flux d'entrée standard. Mutuellement exclusif avec --build-id.
--output-style <LLVM|GNU|JSON>
Spécifie le style de sortie préféré. Par défaut, c'est LLVM. Lorsque le style de sortie est défini sur GNU, l'outil suit le style de addr2line de GNU. Les différences par rapport au style LLVM sont :
  • Ne imprime pas la colonne d'un emplacement de code source.
  • N'ajoute pas de ligne vide après le rapport d'une adresse.
  • Ne remplace pas le nom d'une fonction incorporée par le nom de l'appelant principal lorsque les trames incorporées ne sont pas affichées.
  • Imprime le discriminateur des données de débogage d'une adresse lorsqu'il est non nul. Une façon de produire des discriminateurs est de compiler avec l'option -fdebug-info-for-profiling de clang.
Le style JSON fournit une sortie lisible par machine au format JSON. Si des adresses sont
fournies via stdin, la sortie JSON sera une série d'objets individuels. Sinon, tous les résultats seront contenus dans un seul tableau.

--pretty-print, -p
Imprime une sortie lisible par l'homme. Si --inlining est spécifié, la portée englobante est préfixée par (inlined by). Pour la sortie JSON, l'option fera en sorte que le JSON soit indenté et divisé sur plusieurs lignes. Sinon, la sortie JSON sera imprimée sous forme compacte.
$ llvm-symbolizer --obj=inlined.elf 0x4004be --inlining --pretty-print
baz() at /tmp/test.cpp:11:18
 (inlined by) main at /tmp/test.cpp:15:0
--print-address, --addresses, -a
Imprime l'adresse avant l'emplacement du code source. Par défaut, il est faux.
$ llvm-symbolizer --obj=inlined.elf --print-address 0x4004be
0x4004be
baz()
/tmp/test.cpp:11:18
main
/tmp/test.cpp:15:0
$ llvm-symbolizer --obj=inlined.elf 0x4004be --pretty-print --print-address
0x4004be: baz() at /tmp/test.cpp:11:18
 (inlined by) main at /tmp/test.cpp:15:0
--print-source-context-lines <N>
Imprime N lignes de contexte source pour chaque adresse symbolisée.
$ llvm-symbolizer --obj=test.elf 0x400490 --print-source-context-lines=3
baz()
/tmp/test.cpp:11:0
10  :   volatile int k = 42;
11 >:   return foz() + k;
12  : }
--relativenames
Imprime le chemin du fichier relatif au répertoire de compilation, au lieu du chemin absolu. Si la ligne de commande du compilateur incluait le chemin complet, cela sera identique au comportement par défaut.
--verbose
Imprime des informations détaillées sur l'adresse, la ligne et la colonne.

--version, -v
Imprime les informations de version de l'outil.
@<FICHIER>
Lit les options de ligne de commande depuis le fichier de réponse <FICHIER>.

OPTIONS SPÉCIFIQUES WINDOWS/PDB

--dia
Utilise le SDK DIA de Windows pour la symbolisation. Si le SDK DIA n'est pas trouvé, llvm-symbolizer utilisera l'implémentation native.

OPTIONS SPÉCIFIQUES MACH-O

--default-arch <arch>
Si un binaire contient des fichiers objets pour plusieurs architectures (par exemple, s'il s'agit d'un binaire universel Mach-O), symbolise le fichier objet pour une architecture donnée. Vous pouvez également spécifier l'architecture en écrivant nom_binaire:nom_arch dans l'entrée (voir l'exemple ci-dessous). Si l'architecture n'est spécifiée d'aucune manière, l'adresse ne sera pas symbolisée. Par défaut, la chaîne est vide.
$ cat addr.txt
/tmp/mach_universal_binary:i386 0x1f84
/tmp/mach_universal_binary:x86_64 0x100000f24
$ llvm-symbolizer < addr.txt
_main
/tmp/source_i386.cc:8
_main
/tmp/source_x86_64.cc:8
--dsym-hint <chemin/vers/fichier.dSYM>
Si les informations de débogage d'un binaire ne sont pas présentes à l'emplacement par défaut, recherchez les informations de débogage au chemin .dSYM fourni via cette option. Ce drapeau peut être utilisé plusieurs fois.

STATUT DE SORTIE

llvm-symbolizer retourne 0. D'autres codes de sortie impliquent une erreur interne du programme.
