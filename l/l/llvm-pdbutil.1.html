llvm-pdbutil - Outil médico-légal et de diagnostic de fichiers PDB

SYNOPSIS

llvm-pdbutil [sous-commande] [options]

DESCRIPTION

Affiche les types, symboles, enregistrements CodeView et autres informations d'un fichier PDB, tout en manipulant et créant des fichiers PDB. llvm-pdbutil est normalement utilisé par les tests basés sur FileCheck pour tester les fonctionnalités de lecture et d'écriture PDB de LLVM, mais peut également être utilisé pour l'investigation et l'analyse médico-légale générale des fichiers PDB, ou comme remplacement de cvdump.

SOUS-COMMANDES

llvm-pdbutil est divisé en plusieurs sous-commandes, chacune adaptée à un objectif différent. Un bref résumé de chaque commande suit, avec plus de détails dans les sections suivantes.

  • pretty - Affiche les informations de symboles et de types dans un format qui essaie de ressembler autant que possible au code source original.
  • dump - Affiche les types et structures de bas niveau du fichier PDB, y compris les enregistrements CodeView, les tables de hachage, les flux PDB, etc.
  • bytes - Affiche les données des flux, enregistrements, types, symboles, etc. du fichier PDB sous forme d'octets bruts.
  • yaml2pdb - Étant donné une description yaml d'un fichier PDB, produit un fichier PDB valide qui correspond à cette description.
  • pdb2yaml - Pour un fichier PDB donné, produit une description YAML d'une partie ou de la totalité du fichier d'une manière qui permet de reconstruire le PDB.
  • merge - Étant donné deux PDB, produit un troisième PDB qui est le résultat de la fusion des deux PDB d'entrée.

pretty

Important :

La sous-commande pretty est basée sur le SDK Windows DIA et, à ce titre, n'est pas prise en charge sur les plateformes non Windows.

UTILISATION : llvm-pdbutil pretty [options] <fichier PDB d'entrée>

Résumé

La sous-commande pretty affiche une représentation de très haut niveau des informations de débogage de votre programme. Étant donné qu'elle repose sur le SDK Windows DIA, qui est l'API standard utilisée par les outils et débogueurs Windows pour interroger les informations de débogage, elle présente une vue plus faisant autorité de la manière dont un débogueur va interpréter vos informations de débogage qu'un mode qui affiche les enregistrements CodeView de bas niveau.

Options

Options de filtrage et de tri

Note :

Les filtres exclude (exclure) ont la priorité sur les filtres include (inclure). Ainsi, si un filtre correspond à la fois à une règle d'inclusion et à une règle d'exclusion, il est exclu.
-exclude-compilands=<chaîne>
Lors de l'affichage des compilands, des contributions de fichiers source des compilands ou des symboles par compiland, cette option demande à llvm-pdbutil d'omettre tous les compilands qui correspondent à l'expression régulière spécifiée.
-exclude-symbols=<chaîne>
Lors de l'affichage des symboles globaux, publics ou par compiland, cette option demande à llvm-pdbutil d'omettre tous les symboles qui correspondent à l'expression régulière spécifiée.
-exclude-types=<chaîne>
Lors de l'affichage des types, cette option demande à llvm-pdbutil d'omettre tous les types qui correspondent à l'expression régulière spécifiée.
-include-compilands=<chaîne>
Lors de l'affichage des compilands, des contributions de fichiers source des compilands ou des symboles par compiland, limitez la recherche initiale uniquement aux compilands qui correspondent à l'expression régulière spécifiée.
-include-symbols=<chaîne>
Lors de l'affichage des symboles globaux, publics ou par compiland, limitez la recherche initiale uniquement aux symboles qui correspondent à l'expression régulière spécifiée.
-include-types=<chaîne>
Lors de l'affichage des types, limitez la recherche initiale uniquement aux types qui correspondent à l'expression régulière spécifiée.
-min-class-padding=<entier non signé>
Affichez uniquement les types qui ont au moins le montant spécifié de remplissage d'alignement, en tenant compte du remplissage dans les classes de base et les membres de champs agrégés.
-min-class-padding-imm=<entier non signé>
Affichez uniquement les types qui ont au moins le montant spécifié de remplissage d'alignement, en ignorant le remplissage dans les classes de base et les membres de champs agrégés.
-min-type-size=<entier non signé>
Affichez uniquement les types T où sizeof(T) est supérieur ou égal au montant spécifié.
-no-compiler-generated
N'affichez pas les types et symboles générés par le compilateur.
-no-enum-definitions
Lors de l'affichage d'une énumération, n'affichez pas l'énumération complète (par exemple, les valeurs d'énumérateur individuelles).
-no-system-libs
N'affichez pas les symboles des bibliothèques système.

Options de type de symbole

-all
Implique toutes les autres options de cette catégorie.
-class-definitions=<format>
Affiche les définitions de classe dans le format spécifié.
=all      - Affiche tous les membres de classe, y compris les données, constantes, typedefs, fonctions, etc. (par défaut)
=layout   - Affiche uniquement les membres qui contribuent à la taille de la classe.
=none     - N'affiche pas les définitions de classe (par exemple, affiche uniquement le nom et la liste des bases)
-class-order
Affiche les classes dans l'ordre spécifié.
=none            - Indéfini / pas d'ordre de tri particulier (par défaut)
=name            - Trier les classes par nom
=size            - Trier les classes par taille
=padding         - Trier les classes par quantité de remplissage
=padding-pct     - Trier les classes par pourcentage d'espace occupé par le remplissage
=padding-imm     - Trier les classes par quantité de remplissage immédiat
=padding-pct-imm - Trier les classes par pourcentage d'espace occupé par le remplissage immédiat
-class-recurse-depth=<uint>
Lors de la vidange des définitions de classes, arrête après avoir récursivement parcouru le nombre spécifié de fois. La valeur par défaut est 0, ce qui signifie aucune limite.
-classes
Afficher les classes
-compilands
Afficher les compilands (par exemple, les fichiers objet)
-enums
Afficher les énumérations
-externals
Vidanger les symboles externes (par exemple, exportés)
-globals
Vidanger les symboles globaux
-lines
Vidanger les mappages entre les lignes source et les adresses de code.
-module-syms
Afficher les symboles (variables, fonctions, etc.) pour chaque compiland
-sym-types=<types>
Type de symboles à vidanger lorsque -globals, -externals ou -module-syms est spécifié. (par défaut tous)
=thunks - Afficher les symboles thunks
=data   - Afficher les symboles de données
=funcs  - Afficher les symboles de fonctions
=all    - Afficher tous les symboles (par défaut)
-symbol-order=<order>
Pour les symboles vidangés via les options -module-syms, -globals ou -externals, trier les résultats dans l'ordre spécifié.
=none - Indéfini / pas d'ordre de tri particulier
=name - Trier les symboles par nom
=size - Trier les symboles par taille
-typedefs
Afficher les types typedef
-types
Afficher tous les types (implique -classes, -enums, -typedefs)

Autres Options

-color-output
Forcer la sortie en couleur activée ou désactivée. Par défaut, la couleur est utilisée si la sortie est dirigée vers un terminal.
-load-address=<uint>
Lors de l'affichage des adresses virtuelles relatives, supposer que le processus est chargé à l'adresse donnée et afficher quelle serait l'adresse absolue.

dump

USAGE : llvm-pdbutil dump [options] <fichier PDB d'entrée>

Résumé

La sous-commande dump affiche des informations de bas niveau sur la structure d'un fichier PDB. Elle est largement utilisée par l'infrastructure de test de LLVM, mais peut également être utilisée pour des analyses forensiques de PDB. Elle joue un rôle similaire à celui de l'outil cvdump de Microsoft.

Note :

La sous-commande dump expose les détails internes du format de fichier. Par conséquent, le lecteur doit être familier avec Le format de fichier PDB <> avant d'utiliser cette commande.

Options

Options du Conteneur MSF

-streams
vidanger un résumé de tous les flux dans le fichier PDB.
-stream-blocks
En conjonction avec -streams, ajouter des informations à la sortie sur les blocs que le flux spécifié occupe.
-summary
Vidanger les informations des en-têtes MSF et PDB.

Options Module et Fichier

-modi=<uint>
Pour toutes les options qui vidangent les informations de chaque module/compiland, limiter au module spécifié.
-files
Vidanger les fichiers source qui contribuent à chaque module affiché.
-il
Vidanger les informations de lignes des inlinees (sous-section CodeView DEBUG_S_INLINEELINES)
-l
Vidanger les informations de lignes (sous-section CodeView DEBUG_S_LINES)
-modules
Vidanger les informations des compilands
-xme
Vidanger les exportations inter-modules (sous-section CodeView DEBUG_S_CROSSSCOPEEXPORTS)
-xmi
Vidanger les importations inter-modules (sous-section CodeView DEBUG_S_CROSSSCOPEIMPORTS)

Options de Symboles

-globals
vidanger les enregistrements de symboles globaux
-global-extras
vidanger des informations supplémentaires sur les globaux, telles que les buckets de hachage et les valeurs de hachage.
-publics
vidanger les enregistrements de symboles publics
-public-extras
vidanger des informations supplémentaires sur les symboles publics, telles que les buckets de hachage et les valeurs de hachage.
-symbols
vidanger les symboles (fonctions, variables, etc.) pour chaque module vidangé.
-sym-data
Pour chaque enregistrement de symbole vidangé en résultat de l'option -symbols, afficher également les octets complets de l'enregistrement en binaire.

Options des enregistrements de type

-types
Vidanger les enregistrements de type CodeView du flux TPI
-type-extras
Vidanger des informations supplémentaires du flux TPI, telles que les hachages et le tableau des décalages d'indices de type.
-type-data
Pour chaque enregistrement de type vidangé, afficher également les octets complets de l'enregistrement en binaire.
-type-index=<uint>
Ne vidanger que les types avec l'indice de type spécifié.
-ids
Vidanger les enregistrements de type CodeView du flux IPI.
-id-extras
Vidanger des informations supplémentaires du flux IPI, telles que les hachages et le tableau des décalages d'indices de type.
-id-data
Pour chaque enregistrement d'ID vidangé, afficher également les octets complets de l'enregistrement en binaire.
-id-index=<uint>
ne vidanger que les enregistrements d'ID avec l'indice de type hexadécimal spécifié.
-dependents
Utilisé en conjonction avec -type-index ou -id-index, vidange l'intégralité du graphe de dépendance pour l'indice spécifié au lieu de seulement l'enregistrement unique avec l'indice spécifié. Par exemple, si l'indice de type 0x4000 est une fonction dont le type de retour a l'indice 0x3000, et que vous spécifiez -dependents=0x4000, cela vidangera les deux enregistrements (ainsi que tous les autres dépendants dans l'arbre).

Options diverses

-all
Implique la plupart des autres options.

NOM

llvm-pdbutil - outil utilitaire pour les fichiers PDB LLVM

SYNOPIS

llvm-pdbutil [options] [subcommand] [subcommand options]

DESCRIPTION

Cet outil est conçu pour inspecter et manipuler les fichiers de base de données de programme (PDB) utilisés par le compilateur LLVM et d'autres outils LLVM. Il prend en charge diverses opérations, notamment l'extraction d'informations, la conversion vers et depuis YAML, et la fusion de fichiers PDB.

Les sous-commandes disponibles sont :

  • dump : Extrait des informations de haut niveau sur la structure d'un fichier PDB.
  • bytes : Extrait des informations de bas niveau sur la structure d'un fichier PDB pour une analyse plus approfondie.
  • pdb2yaml : Convertit un fichier PDB en une description YAML.
  • yaml2pdb : Génère un fichier PDB à partir d'une description YAML.
  • merge : Fusionne deux fichiers PDB en un seul fichier.

SOUS-COMMANDES

dump

USAGE: llvm-pdbutil dump [options] <fichier PDB d'entrée>

Résumé

La commande dump affiche des informations de haut niveau sur la structure d'un fichier PDB. Elle peut afficher diverses informations, notamment les flux de PDB, les informations du flux DBI, les informations du flux d'informations du module, les informations du flux de types, etc.

Options

-streams
Affiche des informations sur tous les flux du fichier PDB.
-info-stream
Affiche les informations du flux PDB.
-global-symbols
Affiche les symboles globaux.
-string-table
Affiche la table des chaînes PDB.
-section-contribs
Affiche les contributions de section.
-section-headers
Affiche les en-têtes de section d'image.
-section-map
Affiche la carte des sections.
-string-table
Affiche la table des chaînes PDB.

bytes

USAGE: llvm-pdbutil bytes [options] <fichier PDB d'entrée>

Résumé

Comme la sous-commande dump, la sous-commande bytes affiche des informations de bas niveau sur la structure d'un fichier PDB, mais elle est utilisée pour une analyse encore plus approfondie. La sous-commande bytes trouve diverses structures dans un fichier PDB en fonction des options de ligne de commande spécifiées et les affiche en hexadécimal. Quelqu'un travaillant sur le support de la génération de PDB l'utiliserait beaucoup, par exemple, pour comparer un PDB à un autre PDB afin d'assurer la compatibilité octet par octet. Il ne suffit pas de comparer les octets d'un fichier entier, ou d'un flux entier, car il est tout à fait normal que la même structure existe à différents emplacements dans deux PDB différents, et « trouver » la structure est la moitié du travail.

Options

Options de fichier MSF

-block-range=<début[-fin]>
Affiche les données binaires de la plage spécifiée de blocs de fichier MSF.
-byte-range=<début[-fin]>
Affiche les données binaires de la plage spécifiée d'octets dans le fichier.
-fpm
Affiche la carte des pages libres MSF.
-stream-data=<chaîne>
Affiche les données binaires des flux spécifiés. Le format est SN[:Start][@Size]. Par exemple, -stream-data=7:3@12 affiche 12 octets du flux 7, en commençant à l'offset 3 dans le flux.

Options de flux PDB

-name-map
Affiche les octets de la carte de noms PDB.

Options de flux DBI

-ec
Affiche le sous-flux de la carte d'édition et de continuation du flux DBI.
-files
Affiche le sous-flux d'informations de fichier du flux DBI.
-modi
Affiche le sous-flux modi du flux DBI.
-sc
Affiche le sous-flux des contributions de section du flux DBI.
-sm
Affiche la carte des sections du flux DBI.
-type-server
Affiche la carte du serveur de types du flux DBI.

Options de module

-mod=<entier>
Limite toutes les options de cette catégorie à l'index de module spécifié. Par défaut, les options de cette catégorie afficheront les octets de tous les modules.
-chunks
Affiche les octets de la sous-section de débogage C13 de chaque module.
-split-chunks
Lorsqu'elle est spécifiée avec -chunks, divise la sous-section de débogage C13 en un bloc distinct pour chaque type de sous-section et les affiche séparément.
-syms
Affiche le sous-flux d'enregistrements de symboles de chaque module.

Options d'enregistrement de types

-id=<entier>
Affiche l'enregistrement du flux IPI avec l'index de type donné.
-type=<entier>
Affiche l'enregistrement du flux TPI avec l'index de type donné.

pdb2yaml

USAGE: llvm-pdbutil pdb2yaml [options] <fichier PDB d'entrée>

Résumé

Options

yaml2pdb

USAGE: llvm-pdbutil yaml2pdb [options] <fichier YAML d'entrée>

Résumé

Génère un fichier PDB à partir d'une description YAML. La syntaxe YAML n'est pas décrite ici. Utilisez plutôt llvm-pdbutil pdb2yaml et examinez la sortie pour obtenir un point de départ.

Options

-pdb=<nom-de-fichier>

Écrit le PDB résultant dans le fichier spécifié.

merge

USAGE: llvm-pdbutil merge [options] <fichier PDB d'entrée 1> <fichier PDB d'entrée 2>

Résumé

Fusionne deux fichiers PDB en un seul fichier.

Options

-pdb=<nom-de-fichier>

Écrit le PDB résultant dans le fichier spécifié.
