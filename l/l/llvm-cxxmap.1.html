NOM

llvm-cxxmap - Outil de réattribution de noms symboliques C++

SYNTAXE

llvm-cxxmap [options] fichier-symboles-1 fichier-symboles-2

DESCRIPTION

L'outil llvm-cxxmap effectue une mise en correspondance approximative des noms symboliques C++ (mangled names), basée sur un fichier décrivant les composants de nom qui doivent être considérés comme équivalents.

Les fichiers symboliques doivent contenir une liste de noms symboliques C++ (un par ligne). Les lignes vides et les lignes commençant par # sont ignorées. La sortie est une liste de paires de symboles équivalents, une par ligne, de la forme

<symbole-1> <symbole-2>

où <symbole-1> est un symbole du fichier-symboles-1 et <symbole-2> est un symbole du fichier-symboles-2. Les correspondances pour lesquelles les deux symboles sont identiques sont omises.

OPTIONS

-remapping-file=fichier, -r=fichier
Spécifie un fichier contenant une liste de règles d'équivalence qui doivent être utilisées pour déterminer si deux symboles sont équivalents. Obligatoire. Voir FICHIER DE RÉATTRIBUTION.
-output=fichier, -o=fichier
Spécifie un fichier pour écrire la liste des noms correspondants. Si non spécifié, la liste sera écrite sur la sortie standard (stdout).
-Wambiguous
Produit un avertissement s'il existe plusieurs symboles équivalents (mais distincts) dans le fichier-symboles-2.
-Wincomplete
Produit un avertissement si le fichier-symboles-1 contient un symbole pour lequel il n'y a pas de symbole équivalent dans le fichier-symboles-2.

FICHIER DE RÉATTRIBUTION

Le fichier de réattribution est un fichier texte contenant des lignes de la forme

type-fragment fragment1 fragment2

où type-fragment est l'un des mots suivants : name, type, ou encoding, indiquant si les fragments de nom symbolique suivants sont des <nom http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.name>s, des <type http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.type>s, ou des <encoding http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.encoding>s, respectivement. Les lignes vides et les lignes commençant par # sont ignorées.

Les noms C non symboliques peuvent être exprimés comme un encoding qui est un <nom-source http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.source-name> (précédé de sa longueur) :

# La fonction C "void foo_bar()" est réattribuée à la fonction C++ "void foo::bar()".
encoding 7foo_bar _Z3foo3barv

Pour plus de commodité, les <substitution>s intégrés comme St et Ss sont acceptés comme des <nom>s (même s'ils ne sont techniquement pas des <nom>s).

Par exemple, pour spécifier que absl::string_view et std::string_view doivent être traités comme équivalents, le fichier de réattribution suivant pourrait être utilisé :

# absl::string_view est considéré comme équivalent à std::string_view
type N4absl11string_viewE St17basic_string_viewIcSt11char_traitsIcEE
# std:: pourrait être std::__1:: dans libc++ ou std::__cxx11:: dans libstdc++
name St St3__1
name St St7__cxx11

Note :

La réattribution de symboles n'est actuellement prise en charge que pour les noms symboliques C++ suivant le schéma de symbolisation Itanium C++ ABI. Cela couvre toutes les cibles C++ prises en charge par Clang, à l'exception des cibles Windows.
