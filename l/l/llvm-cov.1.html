NOM

llvm-cov - émettre des informations de couverture

SYNTHAXE

llvm-cov commande [arguments...]

DESCRIPTION

L'outil llvm-cov affiche des informations de couverture de code pour les programmes qui sont instrumentés pour émettre des données de profilage. Il peut être utilisé pour travailler avec la couverture de style gcov ou avec le profilage basé sur l'instrumentation de clang.

Si le programme est appelé avec un nom de base gcov, il se comportera comme si la commande llvm-cov gcov avait été appelée. Sinon, une commande doit être fournie.

COMMANDES

  • gcov
  • show
  • report
  • export

COMMANDE GCOV

SYNTHAXE

llvm-cov gcov [options] FICHIER_SOURCE

DESCRIPTION

L'outil llvm-cov gcov lit les fichiers de données de couverture de code et affiche les informations de couverture pour un fichier source spécifié. Il est compatible avec l'outil gcov de la version 4.2 de GCC et peut également être compatible avec certaines versions ultérieures de gcov.

Pour utiliser llvm-cov gcov, vous devez d'abord compiler une version instrumentée de votre application qui collecte les données de couverture lors de son exécution. Compilez avec les options -fprofile-arcs et -ftest-coverage pour ajouter l'instrumentation. (Alternativement, vous pouvez utiliser l'option --coverage, qui inclut ces deux autres options.)

Au moment où vous compilez le code instrumenté, un fichier de données .gcno sera généré pour chaque fichier objet. Ces fichiers .gcno contiennent la moitié des données de couverture. L'autre moitié des données provient des fichiers .gcda qui sont générés lorsque vous exécutez le programme instrumenté, avec un fichier .gcda distinct pour chaque fichier objet. Chaque fois que vous exécutez le programme, les nombres d'exécution sont additionnés dans tous les fichiers .gcda existants, alors assurez-vous de supprimer les anciens fichiers si vous ne souhaitez pas que leur contenu soit inclus.

Par défaut, les fichiers .gcda sont écrits dans le même répertoire que les fichiers objets, mais vous pouvez modifier cela en définissant les variables d'environnement GCOV_PREFIX et GCOV_PREFIX_STRIP. La variable GCOV_PREFIX_STRIP spécifie un nombre de composants de répertoire à supprimer du début du chemin absolu vers le répertoire du fichier objet. Après avoir supprimé ces répertoires, le préfixe de la variable GCOV_PREFIX est ajouté. Ces variables d'environnement vous permettent d'exécuter le programme instrumenté sur une machine où les répertoires des fichiers objets d'origine ne sont pas accessibles, mais vous devrez alors copier les fichiers .gcda dans les répertoires des fichiers objets où llvm-cov gcov s'attend à les trouver.

Une fois que vous avez généré les fichiers de données de couverture, exécutez llvm-cov gcov pour chaque fichier source principal où vous souhaitez examiner les résultats de couverture. Cela doit être exécuté depuis le même répertoire où vous avez précédemment exécuté le compilateur. Les résultats pour le fichier source spécifié sont écrits dans un fichier nommé en ajoutant le suffixe .gcov. Un fichier de sortie distinct est également créé pour chaque fichier inclus par le fichier source principal, avec également un suffixe .gcov ajouté.

Le contenu de base d'un fichier de sortie .gcov est une copie du fichier source avec un compte d'exécution et un numéro de ligne précédant chaque ligne. Le compte d'exécution est affiché comme - si une ligne ne contient aucun code exécutable. Si une ligne contient du code mais que ce code n'a jamais été exécuté, le compte est affiché comme #####.

OPTIONS

-a, --all-blocks
Affiche tous les blocs de base. S'il y a plusieurs blocs pour une seule ligne de code source, cette option amène llvm-cov à afficher le compte pour chaque bloc au lieu d'un seul compte pour toute la ligne.
-b, --branch-probabilities
Affiche les probabilités de branchement conditionnel et un résumé des informations de branchement.
-c, --branch-counts
Affiche les comptes de branchement au lieu des probabilités (nécessite -b).
-m, --demangled-names
Démangle les noms de fonctions.
-f, --function-summaries
Affiche un résumé de la couverture pour chaque fonction au lieu d'un seul résumé pour un fichier source entier.
--help
Affiche les options disponibles (--help-hidden pour plus).
-l, --long-file-names
Pour la sortie de couverture des fichiers inclus à partir du fichier source principal, ajoutez le nom du fichier principal suivi de ## comme préfixe aux noms de fichiers de sortie. Ceci peut être combiné avec l'option --preserve-paths pour utiliser des chemins complets pour le fichier principal et le fichier inclus.
-n, --no-output
Ne génère aucun fichier .gcov. Les informations de résumé sont toujours affichées.
-o <DIR|FICHIER>, --object-directory=<DIR>, --object-file=<FICHIER>
Recherche les objets dans DIR ou basé sur le chemin de FICHIER. Si vous spécifiez un fichier objet particulier, les fichiers de données de couverture sont attendus avec le même nom de base et les extensions .gcno et .gcda. Si vous spécifiez un répertoire, les fichiers sont attendus dans ce répertoire avec le même nom de base que le fichier source.
-p, --preserve-paths
Conserve les composants de chemin lors de la dénomination des fichiers de sortie de couverture. En plus du nom du fichier source, incluez les répertoires du chemin vers ce fichier. Les répertoires sont séparés par des caractères #, avec les répertoires . supprimés et les répertoires .. remplacés par des caractères ^. Lorsqu'il est utilisé avec l'option --long-file-names, cela s'applique au nom du fichier principal et au nom du fichier inclus.
-r
N'affiche que les fichiers avec des chemins relatifs ou des chemins absolus avec le préfixe spécifié par -s.
-s <chaîne>
Préfixe source à élider.
-t, --stdout
Imprime sur la sortie standard au lieu de générer des fichiers .gcov.
-u, --unconditional-branches
Inclut les branches inconditionnelles dans la sortie pour l'option --branch-probabilities.
-version
Affiche la version de llvm-cov.
-x, --hash-filenames
Utilise le hachage md5 du nom de fichier lors de la dénomination des fichiers de sortie de couverture. Le nom du fichier source sera suffixé par ## suivi du hachage MD5 calculé pour celui-ci.

CODE DE RETOUR

llvm-cov gcov retourne 1 s'il ne peut pas lire les fichiers d'entrée. Sinon, il se termine avec zéro.

COMMANDE SHOW

SYNTHAXE

llvm-cov show [options] -instr-profile PROFIL [BIN] [-object BI

DESCRIPTION

La commande llvm-cov show affiche les informations de couverture de code extraites d'un fichier de profilage d'instrumentation (généralement créé par Clang).

La commande llvm-cov show peut afficher la couverture par fichier, par fonction ou par région de code.

Les fichiers de profilage peuvent être générés à l'aide de l'option d'instrumentation -fprofile-instr-use et des arguments de compilation appropriés. Par exemple, pour compiler une application avec la couverture activée :

    clang -o myapp -fprofile-instr-generate -fcoverage-mapping myapp.c

Après avoir exécuté l'application compilée (qui produira un fichier de profilage, par défaut myapp.profdata), vous pouvez utiliser llvm-cov show comme suit :

    llvm-cov show -instr-profile=myapp.profdata ./myapp

OPTIONS

-arch=<architecture>
Spécifie l'architecture pour laquelle les données de couverture doivent être affichées.
-c
Affiche la couverture par bloc de base.
-dump
Écrit le contenu des données de couverture dans un format lisible par l'homme. Utile pour le débogage.
-e
Affiche les lignes non couvertes.
-export-diff
Exporte la différence de couverture entre deux fichiers de profilage.
-fi
Ne génère pas de fichier de sortie. Les informations de couverture sont imprimées directement sur la sortie standard.
-func-groups
Regroupe les fonctions par fichier source.
--help
Affiche les options disponibles.
-i
Affiche le numéro de ligne pour chaque instruction exécutée.
-instr-profile <fichier_profil>
Spécifie le fichier de profilage à utiliser.
-no-warn-filename
Ne pas avertir si les noms de fichiers du profil ne correspondent pas aux noms de fichiers des objets.
-num-threads=<nombre>
Définit le nombre de threads à utiliser pour le traitement.
-o <fichier_sortie>
Spécifie le fichier de sortie où écrire les informations de couverture. Si cette option n'est pas spécifiée, les informations sont imprimées sur la sortie standard.
-p
Affiche les probabilités de branchement.
-pretty
Formate la sortie de manière plus lisible.
-region-coverage
Affiche la couverture par région de code.
-skip-expansions
Ne pas tenir compte des expansions de macros.
-skip-functions
Ne pas tenir compte des fonctions spécifiées.
-skip-lines=<lignes>
Ne pas tenir compte des lignes spécifiées.
-summary
Affiche un résumé de la couverture.
-t
Affiche la couverture par ligne.
-version
Affiche la version de llvm-cov.
-vcols
Affiche les colonnes virtuelles pour le code.
-word-wrap
Retour à la ligne des lignes longues.

CODE DE RETOUR

llvm-cov show retourne 1 s'il ne peut pas lire les fichiers d'entrée ou s'il y a une erreur de traitement. Sinon, il se termine avec zéro.

COMMANDE REPORT

SYNTHAXE

llvm-cov report [options] -instr-profile PROFILE [BIN] [-object BIN...]

DESCRIPTION

La commande llvm-cov report génère un résumé de la couverture de code à partir d'un fichier de profilage d'instrumentation. Ce résumé peut inclure des informations sur le nombre total de lignes, les lignes couvertes, les lignes non couvertes, le pourcentage de couverture, ainsi que des détails par fichier source.

Pour utiliser cette commande, vous devez avoir préalablement compilé votre programme avec l'instrumentation de couverture activée (par exemple, en utilisant -fprofile-instr-generate -fcoverage-mapping avec Clang) et avoir exécuté le programme pour générer le fichier de profilage (par défaut, NOM_DU_PROGRAMME.profdata).

Exemple d'utilisation :

    llvm-cov report -instr-profile=myapp.profdata ./myapp

Cette commande affichera un résumé de la couverture de l'ensemble du projet.

OPTIONS

-arch=<architecture>
Spécifie l'architecture pour laquelle les données de couverture doivent être affichées.
-demangle
Démangle les noms de fonctions dans le rapport.
-fail-under=<pourcentage>
Utilisé dans un contexte d'intégration continue. Si le pourcentage de couverture est inférieur à la valeur spécifiée, la commande retournera un code de sortie non nul.
--help
Affiche les options disponibles.
-instr-profile <fichier_profil>
Spécifie le fichier de profilage à utiliser.
-num-threads=<nombre>
Définit le nombre de threads à utiliser pour le traitement.
-output=<fichier>
Écrit le rapport dans le fichier spécifié au lieu de l'imprimer sur la sortie standard.
-skip-expansions
Ne pas tenir compte des expansions de macros.
-skip-functions
Ne pas tenir compte des fonctions spécifiées.
-skip-lines=<lignes>
Ne pas tenir compte des lignes spécifiées.
-summary
Affiche uniquement un résumé global de la couverture.
-version
Affiche la version de llvm-cov.

CODE DE RETOUR

llvm-cov report retourne 1 si les fichiers d'entrée ne peuvent pas être lus ou s'il y a une erreur lors de la génération du rapport. Dans le cas où le pourcentage de couverture est inférieur à la valeur spécifiée avec -fail-under, il retourne également un code de sortie non nul.

COMMANDE EXPORT

SYNTHAXE

llvm-cov export [options] -instr-profile PROFILE [BIN] [-object BIN...]

DESCRIPTION

La commande llvm-cov export exporte les données de couverture de code dans un format spécifié, généralement JSON. Ce format est utile pour une intégration avec d'autres outils d'analyse ou de reporting.

Les données exportées contiennent des informations détaillées sur la couverture par fichier, par fonction et par ligne, y compris le nombre d'exécutions et les régions couvertes.

Exemple d'utilisation pour exporter les données au format JSON :

    llvm-cov export -instr-profile=myapp.profdata -format=json ./myapp > coverage.json

OPTIONS

-arch=<architecture>
Spécifie l'architecture pour laquelle les données de couverture doivent être exportées.
-format=<format>
Spécifie le format de sortie. Les formats pris en charge incluent json.
--help
Affiche les options disponibles.
-instr-profile <fichier_profil>
Spécifie le fichier de profilage à utiliser.
-num-threads=<nombre>
Définit le nombre de threads à utiliser pour le traitement.
-skip-expansions
Ne pas tenir compte des expansions de macros.
-skip-functions
Ne pas tenir compte des fonctions spécifiées.
-skip-lines=<lignes>
Ne pas tenir compte des lignes spécifiées.
-version
Affiche la version de llvm-cov.

CODE DE RETOUR

llvm-cov export retourne 1 s'il ne peut pas lire les fichiers d'entrée ou s'il y a une erreur lors de l'exportation des données. Sinon, il se termine avec zéro.

NOM

llvm-cov show

SYNTAXIS

llvm-cov show [OPTIONS] [-sources] [SOURCE]...

DESCRIPTION

La commande llvm-cov show affiche la couverture ligne par ligne des binaires BIN... en utilisant les données de profil PROFILE. Elle peut optionnellement être filtrée pour n'afficher que la couverture des fichiers listés dans SOURCE....

BIN peut être un exécutable, un fichier objet, une bibliothèque dynamique, ou une archive (mince ou autre).

Pour utiliser llvm-cov show, vous avez besoin d'un programme compilé avec une instrumentation pour émettre des données de profil et de couverture. Pour compiler un tel programme avec clang, utilisez les options -fprofile-instr-generate et -fcoverage-mapping. Si vous liez avec le pilote clang, passez -fprofile-instr-generate à l'étape de liaison pour vous assurer que les bibliothèques d'exécution nécessaires sont liées.

Les informations de couverture sont stockées dans l'exécutable ou la bibliothèque compilée elle-même, et c'est ce que vous devez passer à llvm-cov show comme argument BIN. Les données de profil sont générées en exécutant normalement ce programme instrumenté. Lorsque le programme se termine, il écrit un fichier de profil brut, typiquement nommé default.profraw, qui peut être converti dans un format adapté à l'argument PROFILE en utilisant l'outil llvm-profdata merge.

OPTIONS

-show-branches=<VIEW>
Affiche la couverture des conditions de branche soit en nombre, soit en pourcentage. Les vues supportées sont : "count", "percent".
-show-mcdc
Affiche la couverture modifiée des conditions/décisions (MC/DC) pour chaque expression booléenne applicable.
-show-line-counts
Affiche les nombres d'exécution pour chaque ligne. Par défaut, vrai, sauf si une autre option -show est utilisée.
-show-expansions
Développe les inclusions, telles que les macros de préprocesseur ou les inclusions textuelles, en ligne dans l'affichage du fichier source. Par défaut, faux.
-show-instantiations
Pour les régions sources qui sont instanciées plusieurs fois, telles que les modèles en C++, affiche chaque instanciation séparément ainsi qu'un résumé combiné. Par défaut, vrai.
-show-regions
Affiche les nombres d'exécution pour chaque région en affichant une caret qui pointe vers le caractère où la région commence. Par défaut, faux.
-show-line-counts-or-regions
Affiche les nombres d'exécution pour chaque ligne s'il n'y a qu'une seule région sur la ligne, mais affiche les régions individuelles s'il y en a plusieurs sur la ligne. Par défaut, faux.
-show-directory-coverage
Génère un fichier d'index dans chaque répertoire qui contient au moins un fichier source avec un index de niveau supérieur montrant les agrégats. Par défaut, faux.
-use-color
Active ou désactive la sortie couleur. Par défaut, c'est automatiquement détecté.
-arch=[*NAMES*]
Spécifie une liste d'architectures telle que la N-ième entrée de la liste corresponde au N-ième binaire spécifié. Si l'objet couvert est un binaire universel, ceci spécifie l'architecture à utiliser. Il est interdit de spécifier une architecture qui n'est pas incluse dans le binaire universel ou d'utiliser une architecture qui ne correspond pas à un binaire non universel.
-name=<NAME>
Affiche la couverture de code uniquement pour les fonctions portant le nom donné.
-name-allowlist=<FILE>
Affiche la couverture de code uniquement pour les fonctions listées dans le fichier donné. Chaque ligne du fichier doit commencer par allowlist_fun:, immédiatement suivie du nom de la fonction à accepter. Ce nom peut être une expression générique.
-name-regex=<PATTERN>
Affiche la couverture de code uniquement pour les fonctions qui correspondent à l'expression régulière donnée.
-ignore-filename-regex=<PATTERN>
Ignore les fichiers de code source dont les chemins correspondent à l'expression régulière donnée.
-format=<FORMAT>
Utilise le format de sortie spécifié. Les formats supportés sont : "text", "html".
-tab-size=<TABSIZE>
Remplace les tabulations par <TABSIZE> espaces lors de la préparation des rapports. Actuellement, ce n'est pris en charge que pour le format html.
-output-dir=PATH
Spécifie un répertoire pour écrire les rapports de couverture. Si le répertoire n'existe pas, il est créé. Lorsqu'il est utilisé en mode vue de fonction (c'est-à-dire lorsque -name ou -name-regex sont utilisés pour sélectionner des fonctions spécifiques), le rapport est écrit dans PATH/functions.EXTENSION. Lorsqu'il est utilisé en mode vue de fichier, un rapport pour chaque fichier est écrit dans PATH/REL_PATH_TO_FILE.EXTENSION.
-Xdemangler=<TOOL>|<TOOL-OPTION>
Spécifie un décodeur de symboles. Ceci peut être utilisé pour rendre les rapports plus lisibles. Cette option peut être spécifiée plusieurs fois pour fournir des arguments au décodeur (par exemple -Xdemangler c++filt -Xdemangler -n pour C++). Le décodeur est censé lire une liste de symboles séparés par des nouvelles lignes depuis l'entrée standard et écrire une liste de la même longueur, séparée par des nouvelles lignes, vers la sortie standard.
-num-threads=N, -j=N
Utilise N threads pour écrire les rapports de fichiers (uniquement applicable lorsque -output-dir est spécifié). Lorsque N=0, llvm-cov détecte automatiquement un nombre approprié de threads à utiliser. C'est le défaut.
-compilation-dir=<dir>
Répertoire utilisé comme base pour les chemins relatifs de mappage de couverture. Applicable uniquement lorsque les binaires ont été compilés avec l'une des options -fcoverage-prefix-map -fcoverage-compilation-dir, ou -ffile-compilation-dir.
-line-coverage-gt=<N>
Affiche la couverture de code uniquement pour les fonctions avec une couverture de ligne supérieure au seuil donné.
-line-coverage-lt=<N>
Affiche la couverture de code uniquement pour les fonctions avec une couverture de ligne inférieure au seuil donné.
-region-coverage-gt=<N>
Affiche la couverture de code uniquement pour les fonctions avec une couverture de région supérieure au seuil donné.
-region-coverage-lt=<N>
Affiche la couverture de code uniquement pour les fonctions avec une couverture de région inférieure au seuil donné.
-path-equivalence=<from>,<to>
Mappe les chemins dans les données de couverture aux chemins de fichiers sources locaux. Ceci vous permet de générer les données de couverture sur une machine, puis d'utiliser llvm-cov sur une machine différente où vous avez les mêmes fichiers sur un chemin différent. Plusieurs arguments -path-equivalence peuvent être passés pour spécifier différentes mappages. Chaque argument consiste en un chemin source <from> et son chemin local correspondant <to>. Les mappages sont appliqués dans l'ordre où ils sont spécifiés. Si plusieurs mappages peuvent être appliqués à un chemin unique, le premier mappage rencontré est utilisé.
-coverage-watermark=<high>,<low>
Définit les seuils haut et bas pour la couverture dans la sortie au format html. Ceci vous permet de définir le seuil haut et bas de couverture comme souhaité, vert lorsque la couverture >= high, rouge lorsque la couverture < low, et jaune sinon. High et low doivent être compris entre 0 et 100 et high > low.
-debuginfod
Utilise debuginfod pour rechercher le mappage de couverture pour les identifiants binaires présents dans le profil mais absents d'aucun objet fourni sur la ligne de commande. Par défaut, vrai si debuginfod est compilé et configuré via la variable d'environnement DEBUGINFOD_URLS.
-debug-file-directory=<dir>
Fournit des répertoires locaux à rechercher pour les objets correspondant aux identifiants binaires dans le profil (comme avec debuginfod). Par défaut, les répertoires système d'identifiants de construction.
-check-binary-ids
Échoue si un fichier objet ne peut pas être trouvé pour un identifiant binaire présent dans le profil, ni sur la ligne de commande ni via la recherche par identifiant binaire.
-empty-profile
Affiche la couverture de référence des binaires avec tous les comptes d'exécution à zéro. Mutuellement exclusif avec d'autres options de profil.
clusive avec -instr-profile.

SIGNALER COMMANDE

SYNTAXE

llvm-cov report [options] -instr-profile PROFIL [BIN] [-object BIN]... [-sources] [SOURCE]...

DESCRIPTION

La commande llvm-cov report affiche un résumé de la couverture des binaires BIN... en utilisant les données de profil PROFIL. Elle peut éventuellement être filtrée pour n'afficher que la couverture des fichiers listés dans SOURCE....

BIN peut être un exécutable, un fichier objet, une bibliothèque dynamique ou une archive (thin ou autre).

Si aucun fichier source n'est fourni, une ligne de résumé est imprimée pour chaque fichier dans les données de couverture. Si des fichiers sont fournis, des résumés peuvent être affichés pour chaque fonction dans les fichiers listés si l'option -show-functions est activée.

Pour plus d'informations sur la compilation de programmes pour la couverture et la génération de données de profil, voir la commande SHOW COMMAND.

OPTIONS

-use-color[=VALEUR]
Active ou désactive la sortie couleur. Par défaut, elle est détectée automatiquement.
-arch=<nom>
Si le binaire couvert est un binaire universel, sélectionnez l'architecture à utiliser. Il est interdit de spécifier une architecture qui n'est pas incluse dans le binaire universel ou d'utiliser une architecture qui ne correspond pas à un binaire non universel.
-show-region-summary
Affiche les statistiques pour toutes les régions. Par défaut, vrai.
-show-branch-summary
Affiche les statistiques pour toutes les conditions de branchement. Par défaut, vrai.
-show-mcdc-summary
Affiche les statistiques MC/DC. Par défaut, faux.
-show-functions
Affiche les résumés de couverture pour chaque fonction. Par défaut, faux.
-show-instantiation-summary
Affiche les statistiques pour toutes les instanciations de fonction. Par défaut, faux.
-ignore-filename-regex=<MOTIF>
Ignore les fichiers de code source dont les chemins correspondent à l'expression régulière donnée.
-compilation-dir=<dir>
Répertoire utilisé comme base pour les chemins de mappage de couverture relatifs. Applicable uniquement lorsque les binaires ont été compilés avec l'une des options -fcoverage-prefix-map -fcoverage-compilation-dir ou -ffile-compilation-dir.
-debuginfod
Tente de rechercher le mappage de couverture à partir des objets en utilisant debuginfod. Ceci est tenté par défaut pour les identifiants binaires présents dans le profil mais non fournis sur la ligne de commande, tant que debuginfod est compilé et configuré via DEBUGINFOD_URLS.
-debug-file-directory=<dir>
Fournit un répertoire pour rechercher les objets correspondant aux identifiants binaires dans le profil.
-check-binary-ids
Échoue si un fichier objet ne peut pas être trouvé pour un identifiant binaire présent dans le profil, ni sur la ligne de commande, ni via la recherche par identifiant binaire.
-empty-profile
Affiche la couverture de base des binaires avec tous les comptes d'exécution à zéro. Mutuellement exclusif avec -instr-profile.

EXPORTER COMMANDE

SYNTAXE

llvm-cov export [options] -instr-profile PROFIL [BIN] [-object BIN]... [-sources] [SOURCE]...

DESCRIPTION

La commande llvm-cov export exporte les données de couverture des binaires BIN... en utilisant les données de profil PROFIL au format de fichier trace JSON ou lcov.

Lors de l'exportation JSON, les régions, fonctions, branches, expansions et résumés des données de couverture seront exportés. Lors de l'exportation d'un fichier trace lcov, la couverture par ligne, la couverture de branche et les résumés seront exportés.

Les données exportées peuvent éventuellement être filtrées pour exporter uniquement la couverture des fichiers listés dans SOURCE....

Pour plus d'informations sur la compilation de programmes pour la couverture et la génération de données de profil, voir la commande SHOW COMMAND.

OPTIONS

-arch=<nom>
Si le binaire couvert est un binaire universel, sélectionnez l'architecture à utiliser. Il est interdit de spécifier une architecture qui n'est pas incluse dans le binaire universel ou d'utiliser une architecture qui ne correspond pas à un binaire non universel.
-format=<FORMAT>
Utilise le format de sortie spécifié. Les formats pris en charge sont : "text" (JSON), "lcov".
-summary-only
Exportez uniquement les informations récapitulatives pour chaque fichier dans les données de couverture. Ce mode n'exporter pas les informations de couverture pour des unités plus petites comme les fonctions ou les régions individuelles. Le résultat contiendra les mêmes informations que celles produites par la commande llvm-cov report, mais présentées au format JSON ou lcov plutôt qu'en texte.
-ignore-filename-regex=<MOTIF>
Ignore les fichiers de code source dont les chemins correspondent à l'expression régulière donnée.
-skip-expansions
Ignore l'exportation des données de couverture d'expansion de macro.
-skip-functions
Ignore l'exportation des données de couverture par fonction.
-num-threads=N, -j=N
Utilise N threads pour exporter les données de couverture. Lorsque N=0, llvm-cov détecte automatiquement un nombre approprié de threads à utiliser. C'est le comportement par défaut.
-compilation-dir=<dir>
Répertoire utilisé comme base pour les chemins de mappage de couverture relatifs. Applicable uniquement lorsque les binaires ont été compilés avec l'une des options -fcoverage-prefix-map -fcoverage-compilation-dir ou -ffile-compilation-dir.
-debuginfod
Tente de rechercher le mappage de couverture à partir des objets en utilisant debuginfod. Ceci est tenté par défaut pour les identifiants binaires présents dans le profil mais non fournis sur la ligne de commande, tant que debuginfod est compilé et configuré via DEBUGINFOD_URLS.
-debug-file-directory=<dir>
Fournit un répertoire pour rechercher les objets correspondant aux identifiants binaires dans le profil.
-check-binary-ids
Échoue si un fichier objet ne peut pas être trouvé pour un identifiant binaire présent dans le profil, ni sur la ligne de commande, ni via la recherche par identifiant binaire.
-empty-profile
Exportez la couverture de base des binaires avec tous les comptes d'exécution à zéro. Mutuellement exclusif avec -instr-profile.

CONVERTIR-POUR-TEST COMMANDE

Attention :

Cette commande est destinée aux développeurs LLVM qui travaillent uniquement sur llvm-cov.

SYNTAXE

llvm-cov convert-for-testing BIN -o OUT

DESCRIPTION

La commande llvm-cov convert-for-testing sert à tester llvm-cov lui-même. Elle peut extraire toutes les données de couverture de code du binaire BIN vers le fichier OUT, réduisant ainsi la taille des fichiers de test. Le fichier de sortie porte généralement l'extension .covmapping.

Les fichiers .covmapping peuvent être relus par llvm-cov au même titre que les fichiers binaires ordinaires.

llvm-cov(1)

llvm-cov – instrumented code coverage tool

SYNOPSIS

llvm-cov command [ options ]

DESCRIPTION

The llvm-cov tool is a wrapper for the Clang source-based code coverage utility (llvm-cov). It provides a unified interface to work with code coverage data generated by Clang.

COMMANDS

The following commands are supported by llvm-cov:

  • gcov: This command provides an interface to the gcov coverage tool.
  • show: This command displays coverage information for source files.
  • report: This command generates a textual report of coverage statistics.
  • export: This command exports coverage data in various formats.
  • convert-for-testing: This command converts coverage data to a format suitable for testing.

GCOV COMMAND

The gcov command is used to generate coverage data in gcov format. It is a wrapper around the gcov tool and provides compatibility with Clang's coverage data.

Options:

-h, --help
Show help message.

-version
Show version information.

-o <directory>
Specify the output directory for the gcov files.

SHOW COMMAND

The show command displays coverage information for source files. It highlights lines that have been executed and lines that have not.

Options:

-h, --help
Show help message.

-version
Show version information.

-o <directory>
Specify the output directory for the coverage reports.

-instr-profile <file>
Specify the profile data file.

-sources <file>
Specify the source files to include in the report.

-format <format>
Specify the output format (e.g., text, html).

REPORT COMMAND

The report command generates a textual report of coverage statistics. It provides a summary of the coverage for the entire project.

Options:

-h, --help
Show help message.

-version
Show version information.

-o <directory>
Specify the output directory for the coverage reports.

-instr-profile <file>
Specify the profile data file.

-sources <file>
Specify the source files to include in the report.

EXPORT COMMAND

The export command exports coverage data in various formats, such as JSON or XML. This can be useful for integrating coverage data with other tools.

Options:

-h, --help
Show help message.

-version
Show version information.

-o <directory>
Specify the output directory for the exported data.

-instr-profile <file>
Specify the profile data file.

-format <format>
Specify the output format (e.g., json, xml).

CONVERT-FOR-TESTING COMMAND

The convert-for-testing command converts coverage data to a format suitable for testing. This can be used to generate test cases based on coverage information.

Options:

-h, --help
Show help message.

-version
Show version information.

-o <directory>
Specify the output directory for the converted data.

-instr-profile <file>
Specify the profile data file.
