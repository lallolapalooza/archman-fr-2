NOM

lldpd — démon LLDP

SYNTAXE

lldpd [-dxcseiklrv] [-D debug] [-p pidfile] [-S description] [-P plateforme] [-X socket] [-m management] [-u fichier] [-I interfaces] [-C interfaces] [-M classe] [-H masquer] [-L lldpcli] [-O fichier_config]

DESCRIPTION

lldpd est un démon capable de recevoir et d'envoyer des trames LLDP. Le protocole LLDP (Link Layer Discovery Protocol) est un protocole de couche 2 indépendant du vendeur qui permet à un périphérique réseau d'annoncer son identité et ses capacités sur le réseau local.

lldpd implémente également un sous-agent SNMP utilisant le protocole AgentX pour s'interfacer avec un agent SNMP régulier comme Net-SNMP. Pour activer ce sous-agent, vous avez besoin de quelque chose comme ceci dans votre snmpd.conf(5):

master agentx

Ce démon implémente à la fois la réception et l'envoi. Il collectera diverses informations pour envoyer des trames LLDP à toutes les interfaces Ethernet, y compris l'adresse de gestion, la vitesse et les noms VLAN.

Les options sont les suivantes :

-d
Ne pas daemoniser. Si cette option est spécifiée, lldpd fonctionnera au premier plan. Lorsqu'elle est spécifiée une fois de plus, lldpd n'enverra pas de logs à syslog mais uniquement sur stderr. Ensuite, cette option peut être spécifiée plusieurs fois pour augmenter la verbosité. Lorsqu'elle est spécifiée quatre fois, les journaux de débogage seront activés. Ils peuvent être filtrés avec l'indicateur -D.
-D debug
Cette option permet à l'utilisateur de filtrer les informations de débogage en spécifiant des jetons autorisés. Cette option peut être répétée plusieurs fois pour autoriser plusieurs jetons. Cette option doit être combinée avec l'indicateur -d pour avoir un effet. Seuls les journaux de débogage peuvent être filtrés. Voici une liste de jetons autorisés avec leur description :

Utiliser le fichier PID fourni pour enregistrer le PID de lldpd au lieu de /run/lldpd/pid.

Désactiver la publicité de la version du noyau, de la version et de la machine. Le nom du noyau (par ex: Linux) sera toujours partagé, et la version du logiciel d'inventaire sera définie sur 'Inconnue'.
-S description
Remplacer la description du système par la description fournie. La description par défaut est le nom du noyau, le nom de l'hôte, la version du noyau, la date de compilation et l'architecture (sauf si vous utilisez l'indicateur -k décrit ci-dessus).
-P plateforme
Remplacer le nom de la plateforme CDP par la valeur fournie. La description par défaut est le nom du noyau (Linux).
-x
Activer le sous-agent SNMP. Avec cette option, lldpd activera un sous-agent SNMP utilisant le protocole AgentX. Cela vous permet d'obtenir des informations sur le système local et les systèmes distants via SNMP.
-X socket
Activer le sous-agent SNMP en utilisant le socket spécifié. lldpd activera un sous-agent SNMP utilisant le protocole AgentX pour le socket donné. Cette option implique la précédente. Le socket par défaut est généralement /var/agentx/master. Vous pouvez spécifier un socket comme tcp:127.0.0.1:705 par exemple. Comme le processus qui ouvrira ce socket est encapsulé dans un chroot, vous devez spécifier une adresse IP (pas un nom d'hôte) lorsque vous utilisez un socket TCP ou UDP.

Si répété une fois de plus (c'est-à-dire -ccccc), CDPv1 sera désactivé et CDPv2 sera forcé.

OPTIONS

-s
Only send LLDP frames. Useful for network devices that need to advertise their presence but do not need to discover their neighbors. If repeated, SNMP traps are sent when a new neighbor is detected.
-p
Only send LLDP frames and do not listen to any incoming frames. This is useful for devices that want to advertise their presence but do not need to discover their neighbors. It also prevents LLDP frames from being forwarded through the device.
-S
There is no SONMP peer detected.
-e
Enable the support of EDP protocol to deal with Extreme routers and switches that do not speak LLDP. If repeated, EDP packets will be sent even when there is no EDP peer detected.
-l
Force to send LLDP packets even when there is no LLDP peer detected but there is a peer speaking another protocol detected. By default, LLDP packets are sent when there is a peer speaking LLDP detected or when there is no peer at all. If repeated, LLDP is disabled.
-r
Receive-only mode. With this switch, lldpd will not send any frame. It will only listen to neighbors.
-m management
Specify the management addresses of this system. As for interfaces (described below), this option can use wildcards and inversions. Without this option, the first IPv4 and the first IPv6 are used. If an exact IP address is provided, it is used as a management address without any check. If only negative patterns are provided, only one IPv4 and one IPv6 addresses are chosen. Otherwise, many of them can be selected. If you want to remove IPv6 addresses, you can use !*:*. If an interface name is matched, the first IPv4 address and the first IPv6 address associated to this interface will be chosen.
-u file
Specify the Unix-domain socket used for communication with lldpctl(8).
-I interfaces
Specify which interface to listen upon and send LLDPDU from. Without this option, lldpd will use all available physical interfaces. This option can use wildcards. Several interfaces can be specified separated by commas. It is also possible to remove an interface by prefixing it with an exclamation mark. It is possible to allow an interface by prefixing it with two exclamation marks. An allowed interface beats a forbidden interface which beats a simple matched interface. For example, with eth*,!eth1,!eth2 lldpd will only use interfaces starting with eth with the exception of eth1 and eth2. While with *,!eth*,!!eth1 lldpd will use all interfaces, except interfaces starting with eth with the exception of eth1. When an exact match is found, it will circumvent some tests. For example, if eth0.12 is specified, it will be accepted even if this is a VLAN interface.
-C interfaces
Specify which interfaces to use for computing chassis ID. Without this option, all interfaces are considered. lldpd will take the first MAC address from all the considered interfaces to compute the chassis ID. The logic of this option is the same as for -I flag: you can exclude interfaces with an exclamation mark and use globbing to specify several interfaces. If all interfaces are removed (with !*), the system name is used as a chassis ID instead.
-M class
Enable emission of LLDP-MED frames. Depending on the selected class, the standard defines which set of TLV should be transmitted. See section 10.2.1. Some devices may be strict in this aspect. The class should be one of the following values:
1
Generic Endpoint (Class I)
2
Media Endpoint (Class II). In this case, the standard requires to define at least one network policy via lldpcli.
3
Communication Device Endpoints (Class III). In this case, the standard requires to define at least one network policy via lldpcli.
4
Network Connectivity Device
-i
Disable LLDP-MED inventory TLV transmission. lldpd will still receive (and publish using SNMP if enabled) those LLDP-MED TLV but will not send them. Use this option if you don't want to transmit sensitive information like serial numbers.
-H hide
Filter neighbors. See section FILTERING NEIGHBORS for details.
-L lldpcli
Provide an alternative path to lldpcli for configuration. If empty, does not use lldpcli for configuration.
-O configfile
Override default configuration locations processed by lldpcli at start. If a directory is provided, each file therein suffixed with .conf. will be read. Order is alphabetical.
-v
Show lldpd version. When repeated, show more build information.

FILTRAGE DES VOISINS

Dans un réseau hétérogène, vous pouvez voir plusieurs hôtes différents sur le même port, même s'il n'y en a qu'un physiquement branché à ce port. Par exemple, si vous avez un commutateur Nortel exécutant LLDP qui est connecté à un commutateur Cisco exécutant CDP et que votre hôte est connecté au commutateur Cisco, vous verrez également le commutateur Nortel car les trames LLDP sont transmises par le commutateur Cisco. Ce n'est peut-être pas ce que vous voulez. Le paramètre -H hide vous permet de dire à lldpd d'ignorer certaines trames qu'il reçoit et d'éviter d'en envoyer d'autres.

Le filtrage entrant et le filtrage sortant ne sont pas liés. Le filtrage entrant masquera certains ports distants pour vous donner une chance de savoir exactement quel équipement se trouve de l'autre côté du lien. Le filtrage sortant évitera d'utiliser certains protocoles pour éviter de saturer votre réseau avec un protocole qui n'est pas géré par l'équipement le plus proche. Gardez à l'esprit que même sans filtrage, lldpd parlera les protocoles pour lesquels au moins une trame a été reçue et LLDP sinon (il existe d'autres options pour modifier ce comportement, par exemple -cc, -ss, -ee, -ll et -ff).

Lors de l'activation du filtrage entrant, lldpd essaiera de sélectionner un protocole et filtrera les voisins utilisant d'autres protocoles. Pour sélectionner ce protocole, la règle est de prendre le protocole le moins utilisé. Si sur un port, vous obtenez 12 voisins CDP et 1 voisin LLDP, cela signifie que le commutateur distant parle LLDP et ne filtre pas CDP. Par conséquent, nous sélectionnons LLDP. Lors de l'activation du filtrage sortant, lldpd essaiera également de sélectionner un protocole et ne parlera que ce protocole. Le filtrage est effectué par port. Chaque port peut sélectionner un protocole différent.

Il existe deux critères supplémentaires lors de l'activation du filtrage : permettre à un ou plusieurs protocoles d'être sélectionnés (en cas d'égalité) et permettre à un ou plusieurs voisins d'être sélectionnés. Même en autorisant plusieurs protocoles, la règle de sélection des protocoles avec le moins de voisins s'applique toujours. Si lldpd sélectionne LLDP et CDP, cela signifie qu'ils ont le même nombre de voisins. La sélection du voisin est aléatoire. Le filtrage entrant sélectionnera un ensemble de voisins à afficher tandis que le filtrage sortant utilisera l'ensemble de voisins sélectionnés pour décider quels protocoles utiliser : si un voisin sélectionné parle LLDP et un autre CDP, lldpd parlera CDP et LLDP sur ce port.

Il existe des cas particuliers. Un exemple typique est un commutateur parlant deux protocoles (CDP et LLDP par exemple). Vous voulez obtenir les informations du meilleur protocole mais vous voulez parler les deux protocoles car certains outils utilisent la table CDP et d'autres la table LLDP.

Le tableau ci-dessous résume toutes les valeurs acceptées pour le paramètre -H hide. La valeur par défaut est 15, ce qui correspond au cas particulier décrit ci-dessus. La colonne filter signifie que le filtrage est activé. La colonne 1proto indique qu'un seul protocole sera conservé. La colonne 1neigh indique qu'un seul voisin sera conservé.

entrant sortant
filtrer 1proto 1neigh filtrer 1proto 1neigh

SYNOPSIS

lldpd [-d] [-k] [-S chassisid] [-i interface] [-I ignoreinterface] [-p pidfile] [-c configfile]

DESCRIPTION

lldpd is a daemon that initializes and maintains the network interfaces it finds and answers to LLDP requests.

LLDP (Link Layer Discovery Protocol) is a vendor-neutral standard defined by the IEEE 802.1ab working group. It allows devices on a network to advertise information about themselves to other devices on the same network. This information can include device type, manufacturer, model name, software version, etc.

The lldpd daemon listens for LLDP notifications from the kernel. It can also periodically poll network interfaces for information about remote devices.

The lldpd daemon can be controlled using the lldpctl(8) command.

The daemon can also be configured using a configuration file. The configuration file is read at startup by lldpcli(8).

Options:

-d
Daemonize. Fork and run in the background.
-k
Don't trap kernel notifications. Poll interfaces instead. This can be useful on systems that do not support netlink or where it is not available.
-S chassisid
Set the chassis ID. If not specified, the chassis ID is derived from the MAC address of the first interface. The chassis ID can be a MAC address or an arbitrary string. The string format is MAC:macaddr, hostname:hostname, or interface:interface.
-i interface
Only use the specified interface. This option can be specified multiple times to include multiple interfaces. If this option is not specified, all available interfaces are used.
-I ignoreinterface
Ignore the specified interface. This option can be specified multiple times to ignore multiple interfaces. This option is processed after the -i option.
-p pidfile
Write the process ID to the specified pidfile. This is useful when controlling the daemon from a script.
-c configfile
Use the specified configfile instead of the default /etc/lldpd.conf. This option is processed after reading the default configuration file and files in /etc/lldpd.d/.
