NOM

llc - Compilateur statique LLVM

SYNTAXE

llc [options] [nom_de_fichier]

DESCRIPTION

La commande llc compile les entrées source LLVM en langage d'assemblage pour une architecture spécifiée. Le code assembleur généré peut ensuite être passé par un assembleur natif et un éditeur de liens pour générer un exécutable natif.

Le choix de l'architecture pour le code assembleur de sortie est déterminé automatiquement à partir du fichier d'entrée, sauf si l'option -march est utilisée pour remplacer la valeur par défaut.

OPTIONS

Si nom_de_fichier est "-" ou omis, llc lit depuis l'entrée standard. Sinon, il lit depuis nom_de_fichier. Les entrées peuvent être au format de langage d'assemblage LLVM (.ll) ou au format bitcode LLVM (.bc).

Si l'option -o est omise, alors llc enverra sa sortie vers la sortie standard si l'entrée provient de l'entrée standard. Si l'option -o spécifie "-", alors la sortie sera également envoyée vers la sortie standard.

Si aucune option -o n'est spécifiée et qu'un fichier d'entrée autre que "-" est spécifié, alors llc crée le nom de fichier de sortie en prenant le nom du fichier d'entrée, en supprimant toute extension .bc existante et en ajoutant un suffixe .s.

Les autres options de llc sont décrites ci-dessous.

Options pour l'utilisateur final

-help
Affiche un résumé des options de ligne de commande.
-M
Transmet des options InstPrinter spécifiques à la cible. Se référer à l'option -M de llvm-objdump(1) <llvm-objdump.html>.
-o <nom_de_fichier>
Utilise <nom_de_fichier> comme nom de fichier de sortie. Voir le résumé ci-dessus pour plus de détails.
-O=uint
Génère du code à différents niveaux d'optimisation. Ceux-ci correspondent aux niveaux d'optimisation -O0, -O1, -O2 et -O3 utilisés par clang.
-mtriple=<triple_cible>
Remplace la triple cible spécifiée dans le fichier d'entrée par la chaîne spécifiée.
-march=<arch>
Spécifie l'architecture pour laquelle générer l'assemblage, remplaçant la cible encodée dans le fichier d'entrée. Voir la sortie de llc -help pour une liste des architectures valides. Par défaut, elle est inférée à partir de la triple cible ou détectée automatiquement comme l'architecture actuelle.
-mcpu=<nom_cpu>
Spécifie une puce particulière dans l'architecture actuelle pour laquelle générer le code. Par défaut, elle est inférée à partir de la triple cible et détectée automatiquement comme l'architecture actuelle. Pour une liste des CPU disponibles, utilisez :
llvm-as < /dev/null | llc -march=xyz -mcpu=help
-filetype=<type_de_fichier_de_sortie>
Spécifie quel type de sortie llc doit générer. Les options sont : asm pour l'assemblage textuel ( '.s'), obj pour les fichiers objet natifs ('.o') et null pour ne rien émettre (pour les tests de performance).

Notez que toutes les cibles ne prennent pas en charge toutes les options.

-mattr=a1,+a2,-a3,...
Remplace ou contrôle des attributs spécifiques de la cible, comme l'activation ou non des opérations SIMD. L'ensemble par défaut d'attributs est défini par le CPU actuel. Pour une liste des attributs disponibles, utilisez :
llvm-as < /dev/null | llc -march=xyz -mattr=help
--frame-pointer
Spécifie l'effet de l'optimisation d'élimination du pointeur de frame (all,non-leaf,none).
--disable-excess-fp-precision
Désactive les optimisations qui peuvent produire une précision excessive pour les nombres à virgule flottante. Notez que cette option peut considérablement ralentir le code sur certains systèmes (par exemple, X86).
--enable-no-infs-fp-math
Active les optimisations qui supposent l'absence de valeurs Inf.
--enable-no-nans-fp-math
Active les optimisations qui supposent l'absence de valeurs NAN.
--enable-no-signed-zeros-fp-math
Active les optimisations de calcul à virgule flottante qui supposent que le signe de 0 est insignifiant.
--enable-no-trapping-fp-math
Active la définition de l'attribut de compilation des exceptions à virgule flottante pour ne pas utiliser d'exceptions.
--enable-unsafe-fp-math
Active les optimisations qui font des hypothèses non sécurisées sur les mathématiques IEEE (par exemple, que l'addition est associative) ou qui peuvent ne pas fonctionner pour toutes les plages d'entrées. Ces optimisations permettent au générateur de code d'utiliser certaines instructions qui ne seraient pas utilisables autrement (comme fsin sur X86).
--stats
Affiche les statistiques enregistrées par les passes de génération de code.
--time-passes
Enregistre le temps nécessaire pour chaque passe et affiche un rapport vers l'erreur standard.
--load=<chemin_dso>
Charge dynamiquement chemin_dso (un chemin vers un objet partagé dynamique) qui implémente une cible LLVM. Cela permettra d'utiliser le nom de la cible avec l'option -march afin que le code puisse être généré pour cette cible.
-meabi=[default|gnu|4|5]
Spécifie quelle version de l'EABI doit être conforme. Les versions valides de l'EABI sont gnu, 4 et 5. La valeur par défaut (default) dépend de la triple.
-stack-size-section
Émet la section .stack_sizes qui contient les métadonnées de taille de pile. La section contient un tableau de paires de valeurs de symboles de fonction (taille de pointeur) et de tailles de pile (LEB128 non signé). Les valeurs de taille de pile n'incluent que l'espace alloué dans le prologue de la fonction. Les fonctions avec des allocations de pile dynamiques ne sont pas incluses.
-remarks-section
Émet la section __remarks (MachO) qui contient des métadonnées sur les diagnostics de remarques.

Options de tuning et configuration

--print-after-isel
Affiche le code machine généré après la sélection des instructions (utile pour le débogage).
--regalloc=<allocateur>
Spécifiez l'allocateur de registres à utiliser. Les allocateurs de registres valides sont :

basic

Allocateur de registres basique.

fast

Allocateur de registres rapide. C'est le choix par défaut pour le code non optimisé.

greedy

Allocateur de registres "glouton". C'est le choix par défaut pour le code optimisé.

pbqp

Allocateur de registres basé sur le "Partitioned Boolean Quadratic Programming".
--spiller=<spiller>
Spécifiez le "spiller" à utiliser pour les allocateurs de registres qui le prennent en charge. Actuellement, cette option n'est utilisée que par l'allocateur de registres par scan linéaire. Le spiller par défaut est local. Les "spillers" valides sont :

simple

Spiller simple

local

Spiller local

Options spécifiques à Intel IA-32

--x86-asm-syntax=[att|intel]
Spécifiez si le code assembleur doit être émis en syntaxe AT&T (par défaut) ou en syntaxe Intel.

Statut de sortie

Si llc réussit, il se terminera avec 0. Sinon, en cas d'erreur, il se terminera avec une valeur non nulle.
