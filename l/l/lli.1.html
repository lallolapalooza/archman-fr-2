NOM

lli - exécute directement des programmes depuis le code binaire LLVM

SYNTAXE

lli [options] [nom_fichier] [arguments_programme]

DESCRIPTION

lli exécute directement des programmes au format code binaire LLVM. Il prend un programme au format code binaire LLVM et l'exécute à l'aide d'un compilateur juste-à-temps (JIT) ou d'un interpréteur.

lli n'est pas un émulateur. Il n'exécutera pas d'IR d'architectures différentes et ne peut interpréter (ou compiler JIT) que pour l'architecture hôte.

Le compilateur JIT prend les mêmes arguments que d'autres outils, comme llc, mais ils ne fonctionnent pas nécessairement pour l'interpréteur.

Si nom_fichier n'est pas spécifié, alors lli lit le code binaire LLVM du programme depuis l'entrée standard.

Les arguments_programme optionnels spécifiés sur la ligne de commande sont passés au programme en tant qu'arguments.

OPTIONS GÉNÉRALES

-fake-argv0=exécutable
Remplace la valeur de argv[0] passée au programme exécuté.
-force-interpreter={faux,vrai}
Si défini sur vrai, utilise l'interpréteur même si un compilateur juste-à-temps est disponible pour cette architecture. Par défaut : faux.
-help
Affiche un résumé des options de ligne de commande.
-load=nom_fichier_plugin
Induit lli à charger le plugin (objet partagé) nommé nom_fichier_plugin et à l'utiliser pour l'optimisation.
-stats
Affiche les statistiques des passes de génération de code. Ceci n'est significatif que pour le compilateur juste-à-temps, actuellement.
-time-passes
Enregistre le temps nécessaire pour chaque passe de génération de code et l'affiche sur la sortie d'erreur standard.
-version
Affiche la version de lli et quitte sans rien faire d'autre.

OPTIONS CIBLE

-mtriple=cible
Remplace la triple cible spécifiée dans le fichier code binaire d'entrée par la chaîne spécifiée. Cela peut entraîner un plantage si vous choisissez une architecture incompatible avec le système actuel.
-march=arch
Spécifie l'architecture pour laquelle générer de l'assembleur, remplaçant la cible codée dans le fichier code binaire. Voir la sortie de llc -help pour une liste des architectures valides. Par défaut, cela est déduit de la triple cible ou détecté automatiquement sur l'architecture actuelle.
-mcpu=nom_cpu
Spécifie un processeur spécifique dans l'architecture actuelle pour lequel générer du code. Par défaut, cela est déduit de la triple cible et détecté automatiquement sur l'architecture actuelle. Pour une liste des processeurs disponibles, utilisez : llvm-as < /dev/null | llc -march=xyz -mcpu=help
-mattr=a1,+a2,-a3,...
Remplace ou contrôle des attributs spécifiques de la cible, comme l'activation ou la désactivation des opérations SIMD. L'ensemble par défaut d'attributs est défini par le processeur actuel. Pour une liste des attributs disponibles, utilisez : llvm-as < /dev/null | llc -march=xyz -mattr=help

OPTIONS POINT FLOTTANT

-disable-excess-fp-precision
Désactive les optimisations qui peuvent augmenter la précision des nombres à virgule flottante.
-enable-no-infs-fp-math
Active les optimisations qui supposent l'absence de valeurs Inf.
-enable-no-nans-fp-math
Active les optimisations qui supposent l'absence de valeurs NaN.
-enable-unsafe-fp-math
Induit lli à activer des optimisations qui peuvent diminuer la précision des nombres à virgule flottante.
-soft-float
Induit lli à générer des appels de bibliothèque logicielle pour les nombres à virgule flottante au lieu des instructions matérielles équivalentes.

OPTIONS DE GÉNÉRATION DE CODE

-code-model=modèle
Choisit le modèle de code parmi :
défaut : Modèle de code par défaut de la cible
tiny : Modèle de code tiny
small : Modèle de code small
kernel : Modèle de code kernel
medium : Modèle de code medium
large : Modèle de code large
-disable-post-RA-scheduler
Désactive la planification après allocation de registres.
-disable-spill-fusing
Désactive la fusion du code de débordement dans les instructions.
-jit-enable-eh
La gestion des exceptions doit être activée dans le compilateur juste-à-temps.
-join-liveintervals
Fusionne les copies (par défaut=vrai).
-nozero-initialized-in-bss
Ne place pas les symboles initialisés à zéro dans la section BSS.
-pre-RA-sched=planificateur
Planificateurs d'instructions disponibles (avant allocation de registres) :
=défaut : Meilleur planificateur pour la cible
=none : Aucune planification : séquençage par parcours en largeur
=simple : Planification simple en deux passes : minimise la route critique et maximise l'utilisation du processeur
=simple-noitin : Planification simple en deux passes : Identique à simple sauf qu'elle utilise la latence générique
=list-burr : Planification par liste de réduction de registres de bas en haut (bottom-up)
=list-tdrr : Planification par liste de réduction de registres de haut en bas (top-down)
=list-td : Planificateur par liste de haut en bas
-regalloc=allocateur
Allocateur de registres à utiliser (par défaut=linearscan)
=bigblock : Allocateur de registres en gros blocs
=linearscan : Allocateur de registres par scan linéaire
=local : Allocateur de registres local
=simple : Allocateur de registres simple
-relocation-model=modèle
Choisit le modèle de relocalisation parmi :
=défaut : Modèle de relocalisation par défaut de la cible
=static : Code non relocalisable
=pic : Code entièrement relocalisable et indépendant de la position (position independent code)
=dynamic-no-pic : Références externes relocalisables, code non relocalisable
-spiller
Spilleur à utiliser (par défaut=local)

NAME

lli — a front-end for the LLVM bitcode interpreter

SYNOPSIS

lli [options] [input file...]

DESCRIPTION

The lli utility is a simple interpreter for the LLVM bitcode format. It can execute bitcode files directly or interpret bitcode piped to its standard input.

When no input files are specified, lli will read bitcode from its standard input. If an input file is specified with the special name -, then lli will read bitcode from its standard input.

The lli utility can interpret bitcode for multiple target architectures. If multiple bitcode files are specified, lli will attempt to load and link them all together into a single program. If linking fails, lli will exit with an error message and an exit code of 1.

If the program being executed by lli calls the exit function, then lli will return the exit code provided to exit. Otherwise, lli will return 0.

GENERAL OPTIONS

-help
Print a summary of command-line options.
-version
Print the version of this program.

TARGET OPTIONS

-march=target
Use LLVM backend for the specified target architecture. If not specified, the native target will be used.
-mtriple=triple
Use LLVM backend for the specified target triple. If not specified, the native target triple will be used.

FLOATING POINT OPTIONS

-float-abi=abi
Use the specified floating-point ABI. Supported values include llvmpcc-intrin, llvmpcr-intrin, and llvmpcr+-intrin.
-soft
Use software floating-point library. This is the default for many targets.
-hard
Use hardware floating-point instructions. This is the default for many targets.
-no-implicit-float
Do not implicitly use floating-point instructions.
-use-soft-float
Use software floating-point library.
-use-hard-float
Use hardware floating-point instructions.

CODE GENERATION OPTIONS

-fast-mem
Enable fast memory access.
-no-implicit-float-codegen
Do not implicitly use floating-point instructions during code generation.
-disable-spill-init-of-regs
Disable spill initialization of registers.
-spill-init-of-regs
Enable spill initialization of registers.
-x86-asm-syntax=syntax
Choose style of code to emit from X86 backend:
=att: Emit AT&T-style assembly
=intel: Emit Intel-style assembly

EXIT STATUS

If lli fails to load the program, it will exit with an exit code of 1. Otherwise, it will return the exit code of the program it executes.
