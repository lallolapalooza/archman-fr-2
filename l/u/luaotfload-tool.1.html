LUAOTFLOAD-TOOL(1) traitement de texte LUAOTFLOAD-TOOL(1)

NOM

luaotfload-tool - générer et interroger la base de données des noms de polices Luaotfload

SYNTAXE

luaotfload-tool [ -bcDfFiIlLnpqRSuvVhw ]

luaotfload-tool --update [ --force ] [ --quiet ] [ --verbose ]
[ --prefer-texmf ] [ --dry-run ] [ --formats=[+|-]EXTENSIONS ] [ --no-compress ] [ --no-strip ] [ --local ] [ --max-fonts=N ]
luaotfload-tool --find=NOM_POLICE [ --fuzzy ] [ --info ] [ --inspect ]
[ --no-reload ]

luaotfload-tool --flush-lookups

luaotfload-tool --cache=DIRECTIVE

luaotfload-tool --list=CRITERE[:VALEUR] [ --fields=F1,F2,...,Fn ]

luaotfload-tool --bisect=DIRECTIVE

luaotfload-tool --help

luaotfload-tool --version

luaotfload-tool --show-blacklist

luaotfload-tool --diagnose=VERIFICATION

luaotfload-tool --conf=FICHIER --dumpconf

DESCRIPTION

luaotfload-tool accède à la base de données des noms de polices requise par le package Luaotfload. Il existe deux modes généraux : update (mise à jour) et query (interrogation).

  • update : met à jour la base de données ou la reconstruit entièrement ;
  • query : résout un nom de police ou affiche les correspondances proches.

OPTIONS

mode mise à jour

--update, -u
Met à jour la base de données ; indexe les nouvelles polices.
--force, -f
Force la reconstruction de la base de données ; ré-indexe toutes les polices.
--local, -L
Inclut les fichiers de polices dans $PWD. Cette option entraînera la reconstruction de larges parties de la base de données. Elle est donc assez inefficace. De plus, si des fichiers de polices locaux sont trouvés, la base de données n'est pas enregistrée sur disque, les polices locales doivent donc être analysées à chaque invocation de luaotfload-tool.
--no-reload, -n
Supprime les mises à jour automatiques de la base de données (par exemple, lorsque --find reçoit un nom inconnu).
--no-compress, -c
Ne filtre pas la version texte brut de l'index de polices via gzip. Utile pour le débogage si votre éditeur est compilé sans zlib.
--prefer-texmf, -p
Organise la base de données des noms de fichiers de manière à privilégier les polices de l'arborescence TEXMF par rapport aux polices système si elles sont installées dans les deux.
--formats=EXTENSIONS
Extensions des fichiers de polices à indexer. Où EXTENSIONS est une liste d'extensions de fichiers séparées par des virgules (otf, ttf, ttc). Si la liste est préfixée par un signe +, la liste donnée est ajoutée à celle actuellement active ; - soustrait. Défaut : otf,ttf,ttc. Exemples :
1.
--formats=-ttc,ttf ignorerait les polices TrueType et les collections de polices ;
2.
--formats=otf n'analyserait que les fichiers OpenType ;
3.
--formats=+afm inclut les fichiers Postscript binaires accompagnés d'un fichier AFM.

mode interrogation

--find=NOM
Résout un nom de police ; recherche <nom> dans la base de données et imprime le nom du fichier auquel il est mappé. --find comprend également la syntaxe de requête, c'est-à-dire --find=file:foo.otf vérifie si foo.otf est indexé.
--fuzzy, -F
Affiche les correspondances approximatives du nom de fichier si la recherche a échoué (nécessite --find).
--info, -i
Affiche des informations de base sur un fichier de police résolu (nécessite --find).
--inspect, -I
Affiche des informations détaillées en chargeant la police et en analysant la table de polices ; très lent ! Pour la signification des champs retournés, consultez la documentation de LuaTeX. (nécessite --find).
--list=CRITERE
Affiche les entrées, où CRITERE est l'un des éléments suivants :
1.
le caractère *, sélectionnant toutes les entrées ;
2.
un champ d'une entrée de base de données, par exemple version ou format*, selon lequel la sortie sera triée. Les informations d'une base de données non dépouillée (voir l'option --no-strip ci-dessus) sont imbriquées : les sous-champs d'un enregistrement peuvent être adressés en utilisant le séparateur ->, par exemple file->location, style->units_per_em, ou names->sanitized->english->prefmodifiers. NB : la syntaxe du shell exige que les arguments contenant -> soient correctement cités !
3.
une expression de la forme champ:valeur pour limiter la sortie aux entrées dont le champ correspond à valeur. La valeur peut contenir * pour faire correspondre un nombre arbitraire de caractères.

Par exemple, pour afficher les noms de fichiers et leurs versions correspondantes, triés par format de police :

./luaotfload-tool.lua --list="format" --fields="file->base,version"

Ceci affiche :

otf latinmodern-math.otf  Version 1.958
otf lmromancaps10-oblique.otf 2.004
otf lmmono8-regular.otf 2.004
otf lmmonoproplt10-bold.otf 2.004
otf lmsans10-oblique.otf  2.004
otf lmromanslant8-regular.otf 2.004
otf lmroman12-italic.otf  2.004
otf lmsansdemicond10-oblique.otf  2.004
...
--fields=CHAMPS
Liste séparée par des virgules des champs à afficher. Les informations d'une base de données non dépouillée (voir l'option --no-strip ci-dessus) sont imbriquées : les sous-champs d'un enregistrement peuvent être adressés en utilisant le séparateur ->, par exemple file->location, style->units_per_em, ou names->sanitized->english->subfamily. Le défaut est plainname,version*. (Uniquement significatif avec --list.)

caches de polices et de recherche

--flush-lookups
Efface le cache de recherche des noms de polices (expérimental).
--cache=DIRECTIVE
Contrôle du cache, où DIRECTIVE est l'un des éléments suivants :
1.
purge -> supprime les fichiers Lua du cache ;
2.
erase -> supprime les fichiers Lua et Luc du cache ;
3.
show -> affiche les statistiques.

méthodes de débogage

--show-blacklist, -b
Affiche les fichiers mis en liste noire (pas les répertoires).
--dry-run, -D
Ne charge pas les polices lors de la mise à jour de la base de données ; analyse uniquement les répertoires. (Pour le débogage des problèmes liés au système de fichiers.)
--no-strip
Ne retire pas les informations redondantes après la construction de la base de données. Attention : cela augmentera l'index d'environ deux à trois fois la taille normale.
--max-fonts=<

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

/b>N
Traitez au maximum N fichiers de polices, y compris les polices déjà indexées dans le compte.
--bisect=DIRECTIVE
Bisection de la base de données des polices. Ce mode est destiné à aider au débogage du moteur Luatex, en particulier lors de la recherche de fuites de mémoire ou de polices défectueuses.

DIRECTIVE peut être l'un des éléments suivants :

1.
run -> Faire en sorte que luaotfload-tool respecte la progression de la bisection lors de l'exécution. Combiné avec --update et éventuellement --force, cela ne traitera que les fichiers du début jusqu'au pivot et ignorera le reste.
2.
start -> Démarrer la bisection : créer un fichier d'état de bisection et initialiser les indices bas, hauts et pivot.
3.
stop -> Terminer la session de bisection actuelle en supprimant le fichier d'état.
4.
good | bad -> Marquer la section traitée dernièrement comme « bonne » ou « mauvaise », respectivement. La prochaine étape de bisection continuera avec la section mauvaise.
5.
status -> Afficher les informations d'état sur la session de bisection actuelle. Astuce : Utiliser avec des paramètres de verbosité plus élevés pour plus de sortie.

Une session de bisection est initiée en émettant la directive start. Cela définit le pivot au milieu de la liste des fichiers de polices disponibles. Exécutez maintenant luaotfload-tool avec le drapeau --update défini ainsi que --bisect=run : seules les polices jusqu'au pivot seront prises en compte. Si cette tâche a présenté le problème que vous suivez, alors indiquez à Luaotfload en utilisant --bisect=bad. La prochaine étape de --bisect=run continuera la bisection avec la partie des fichiers sous le pivot. De même, émettez --bisect=good afin de continuer avec les polices au-dessus du pivot, en supposant que la partie testée de la liste n'a pas déclenché le bug.

Une fois que la police coupable est identifiée, good ou bad n'auront plus aucun effet. run finira toujours par traiter le seul fichier de police restant. Utilisez --bisect=stop pour effacer l'état de la bisection.

divers

--verbose=N, -v
Définir le niveau de verbosité à n ou au nombre de répétitions de -v.
--quiet
Pas de sortie verbeuse (niveau de journalisation défini à zéro).
--log=CHANNEL
Rediriger la sortie du journal (pour le dépannage de la base de données), où CHANNEL peut être
1.
stdout -> toute la sortie sera envoyée au terminal (par défaut) ; ou
2.
file -> écrire dans un fichier dans le répertoire temporaire (le nom sera choisi automatiquement).
--version, -V
Afficher les numéros de version des composants ainsi que quelques informations de base et quitter.
--help, -h
Afficher le message d'aide et quitter.
--diagnose=CHECK
Exécuter la procédure de diagnostic CHECK. Les procédures disponibles sont :
1.
files -> vérifier les fichiers Luaotfload pour les modifications ;
2.
permissions -> vérifier les permissions des répertoires et fichiers de cache ;
3.
environment -> afficher les variables d'environnement et kpse pertinentes ;
4.
repository -> vérifier le dépôt git pour les nouvelles versions,
5.
index -> vérifier la base de données, afficher des informations à son sujet.

Les procédures peuvent être chaînées en les concaténant avec des virgules, par exemple --diagnose=files,permissions. Spécifiez thorough pour exécuter toutes les vérifications.

--conf=FILE
Lire la configuration de FILE. Voir luaotfload.conf(%) pour la documentation concernant le format et les options disponibles.
--dumpconf
Afficher la configuration actuellement active ; la sortie peut être enregistrée dans un fichier et utilisée pour amorcer des fichiers de configuration personnalisés.
--aliases
Exporter la base de données des noms de polices sous forme de fichier d'alias kpathsea. Cette option est expérimentale et pourrait disparaître.

FICHIERS

La base de données des noms de polices se trouve généralement dans le répertoire texmf-var/luatex-cache/generic/names/ ($TEXMFCACHE tel que défini dans texmf.cnf) de votre distribution TeX Live sous forme de fichier compressé zlib luaotfload-names.lua.gz. Le cache de recherche expérimental sera créé sous le nom luaotfload-lookup-cache.lua dans le même répertoire. Ces tables Lua ne sont cependant pas utilisées directement par Luaotfload. Au lieu de cela, elles sont compilées en bytecode Lua qui est écrit dans des fichiers correspondants avec l'extension .luc dans le même répertoire. Lors de la modification manuelle des fichiers, gardez à l'esprit que ce n'est que si les fichiers de bytecode sont manquants que Luaotfload utilisera la version simple à la place. Les deux types de fichiers peuvent être supprimés en toute sécurité, au prix de leur régénération lors de la prochaine exécution de LuaTeX.
