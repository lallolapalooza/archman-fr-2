NOM

luaotfload.conf - Fichier de configuration de Luaotfload

SYNTAXE

  • ./luaotfload{.conf,rc}
  • XDG_CONFIG_HOME/luaotfload/luaotfload{.conf,rc}
  • ~/.luaotfloadrc

DESCRIPTION

Le fichier luaotfload.conf contient les options de configuration pour Luaotfload, un composant de chargement et de gestion de polices pour LuaTeX.

EXEMPLE

Un petit fichier de configuration Luaotfload avec quelques personnalisations pourrait ressembler à ceci :

[db]
    formats = afm,ttf
    compress = false
[misc]
    termwidth = 60
[run]
    log-level = 6

Cela fera en sorte que Luaotfload ignore tous les fichiers de polices sauf les polices binaires PostScript avec un fichier AFM correspondant et les polices Truetype. De plus, un fichier d'index non compressé sera sauvegardé, ce qui sera beaucoup plus volumineux que l'index compressé par défaut avec gzip. La largeur du terminal est tronquée à 60 caractères, ce qui affecte la sortie verbeuse lors de l'indexation. Enfin, la verbosité est considérablement augmentée : chaque fichier de police traité sera imprimé sur la sortie standard sur une ligne séparée, ainsi que de nombreuses autres informations.

Pour observer la différence de comportement, enregistrez l'extrait ci-dessus dans ./luaotfload.conf et mettez à jour l'index des polices :

luaotfload-tool --update --force

La configuration actuelle peut être écrite sur disque à l'aide de luaotfload-tool :

luaotfload-tool --dumpconf > luaotfload.conf

Le résultat peut lui-même être utilisé comme fichier de configuration.

SYNTAXE DU FICHIER

La syntaxe du fichier de configuration suit le format INI courant. Pour une description plus détaillée, veuillez vous référer à la section « FICHIER DE CONFIGURATION » de git-config(1). Une brève liste des règles est donnée ci-dessous :

  • Les lignes vides et les lignes commençant par un point-virgule (;) sont ignorées.
  • Un fichier de configuration est partitionné en sections qui sont déclarées en spécifiant le titre de la section entre crochets sur une ligne séparée :
[some-section]
... contenu de la section ...
•
Les sections consistent en une ou plusieurs affectations de variables de la forme nom-de-variable = valeur Par exemple :
[foo]
    bar = baz
    quux = xyzzy
    ...
•
Les noms de section et de variable ne peuvent contenir que des lettres majuscules et minuscules ainsi que des tirets (-).

VARIABLES

Les variables appartiennent à une section de configuration et leurs valeurs doivent être d'un certain type. Certaines ont des contraintes supplémentaires. Par exemple, le « rappel de couleur » doit être une chaîne de caractères parmi les valeurs post_linebreak_filter, pre_linebreak_filter, ou pre_output_filter, définies dans la section run du fichier de configuration.

Actuellement, la configuration est organisée en quatre sections :

db
Options relatives à l'index des polices.
misc
Options sans catégorie clairement définie.
paths
Paramètres de chemin et de nom de fichier.
run
Options contrôlant le comportement d'exécution de Luaotfload.

La liste des variables valides, les sections auxquelles elles appartiennent et leur type sont donnés ci-dessous. Les types représentent les types Lua aux- quels les valeurs doivent être convertibles ; ils sont abrégés comme suit : s pour le type chaîne de caractères, n pour nombre, b pour booléen. Une valeur nil signifie que la variable n'est pas définie.

Section db

variable type par défaut
compress b true
designsize-dimen b bp
formats s "otf,ttf,ttc"
location-precedence s "system,texmf,local
max-fonts n 2^51
scan-local b false
skip-read b false
strip b true
update-live b true

Le drapeau compress détermine si l'index de polices (généralement luaotfload-names.lua[.gz]) sera stocké sous forme compressée. S'il n'est pas défini, cela équivaut à passer --no-compress à luaotfload-tool. Étant donné que le fichier n'est créé que par convention et n'a aucun effet sur le comportement d'exécution de Luaotfload, le drapeau doit rester activé. La plupart des éditeurs prennent en charge zlib de toute façon.

Le paramètre designsize-dimen s'applique lors de la recherche de polices appartenant à des familles avec des tailles de conception. En OpenType, celles-ci sont spécifiées en « décipoints », où un décipoint équivaut à dix « big points » au style DTP. Lors de l'indexation des polices, ces valeurs sont converties en sp. Afin de traiter les valeurs comme si elles avaient été spécifiées en points TeX ou en points Didot, définissez designsize-dimen à pt ou dd.

La liste des formats doit être une séquence de chaînes de caractères séparées par des virgules contenant un ou plusieurs des éléments suivants :

  • otf (format OpenType),
  • ttf et ttc (format TrueType),
  • afm (Adobe Font Metrics),

Cela correspond vaguement à l'option --formats de luaotfload-tool. Les membres invalides ou dupliqués sont ignorés ; si la liste ne contient aucun identifiant utile, la liste par défaut "otf,ttf,ttc" sera utilisée.

La variable location-precedence sélectionne où et dans quel ordre luaotfload recherche les polices. Les polices situées dans les emplacements précédents sont préférées. Les trois emplacements pris en charge sont system pour les répertoires de polices spécifiques au système, texmf pour les polices qui font partie de la distribution TeX et local pour les polices locales.

La variable max-fonts détermine après le traitement de combien de fichiers de polices le scanner de polices terminera la recherche. Ceci est utile pour déboguer les problèmes avec l'index des polices et a le même effet que l'option --max

-polices à luaotfload-tools.

L'indicateur scan-local, s'il est défini, intégrera le répertoire de travail actuel comme emplacement de recherche de polices. NB : cela ralentira potentiellement le traitement du document car un index de polices avec des polices locales ne sera pas sauvegardé sur disque, ces polices devront donc être ré-indexées à chaque compilation du document. Définir scan_local sur false équivaut à supprimer local de location-precedence.

L'indicateur skip-read n'est utile que pour le débogage : il fait en sorte que Luaotfload ignore la lecture des polices. Les informations sur les polices pour reconstruire l'index sont tirées de celui qui existe actuellement.

La désactivation de l'indicateur strip empêche Luaotfload de supprimer du index des données qui ne sont utiles que lors du traitement des fichiers de polices. NB : cela peut augmenter considérablement la taille des fichiers d'index et n'a aucun effet sur le comportement à l'exécution.

Si update-live est défini, Luaotfload rechargera la base de données s'il ne trouve pas une police demandée. Ceux qui préfèrent mettre à jour manuellement à l'aide de luaotfload-tool devraient désactiver cet indicateur. Cette option n'affecte pas les reconstructions dues à une incompatibilité de version.

Section default-features

Par défaut, Luaotfload active le mode node et choisit les fonctionnalités de polices par défaut prescrites dans la norme OpenType. Ce comportement peut être remplacé dans la section default-features. Les valeurs par défaut globales qui seront appliquées à tous les scripts peuvent être définies via l'option global, les autres par le script sur lequel elles doivent être appliquées. Par exemple, un réglage de

[default-features]
    global = mode=base,color=0000FF
    dflt   = smcp,onum

forcerait le mode base, teinterait toutes les polices en bleu et activerait les petites capitales et les chiffres de texte globalement. Les fonctionnalités sont spécifiées comme une liste séparée par des virgules de variables ou de paires variable-valeur. Les variables sans valeur explicite sont définies sur true.

Section misc

variable type défaut
statistics b false
termwidth n nil
version s <version de Luaotfload>
keepnames b true

Avec statistics activé, des statistiques supplémentaires seront collectées pendant la création de l'index et ajoutées au fichier d'index. Il pourra ensuite être interrogé côté Lua ou inspecté en lisant le fichier lui-même.

La valeur de termwidth, si elle est définie, remplace la valeur récupérée en interrogeant les propriétés du terminal dans lequel Luatex s'exécute. Ceci est utile si le moteur s'exécute avec shell_escape désactivé et que les dimensions réelles du terminal ne peuvent pas être récupérées.

La valeur de version est dérivée de la chaîne de version codée en dur dans la source de Luaotfload. Remplacez à vos risques et périls.

L'option keepnames décide si le chargeur de polices ConTeXt doit conserver les noms qu'il considère comme inutiles ou s'ils doivent être rejetés. Cette option ne prend effet qu'après la régénération des caches de polices.

Section paths

variable type défaut
cache-dir s "fonts"
names-dir s "names"
index-file s "luaotfload-names.lua"
lookups-file s "luaotfload-lookup-cache.lua"

Les chemins cache-dir et names-dir déterminent le sous-répertoire à l'intérieur du sous-arbre Luaotfload du répertoire luatex-cache où le cache de polices et l'index de polices seront stockés, respectivement.

À l'intérieur du répertoire d'index, les noms du fichier d'index et du cache de recherche de polices seront dérivés des valeurs respectives de index-file et lookups-file. C'est la base du nom de fichier pour la version compilée en bytecode ainsi que - pour l'index - la version compressée.

Section run

variable type défaut
anon-sequence s "tex,path,name"
color-callback s "post_linebreak_filter"
definer s "patch"
log-level n 0
resolver s "cached"
fontloader s "default"
default_dvi_driver s "dvisvgm"

Les recherches de polices non qualifiées sont traitées avec le mécanisme flexible “anonyme”. Cela implique une chaîne de recherches appliquées successivement jusqu'à ce que la première donne une correspondance. Par défaut, la recherche cherchera d'abord les polices TFM en utilisant la bibliothèque Kpathsea. Si cela n'a pas abouti, une tentative est faite pour interpréter la demande comme un chemin absolu (comme la syntaxe [/path/to/font/foo.ttf]) ou un nom de fichier (file:foo.ttf). Enfin, la demande est interprétée comme un nom de police et récupérée de l'index (name:Foo Regular). Ce comportement peut être configuré en spécifiant une liste comme valeur pour anon-sequence. Les éléments disponibles sont tex, path, name - représentant les recherches décrites ci-dessus, respectivement - et file pour rechercher un nom de fichier mais pas un chemin absolu. De plus, les recherches my sont des valeurs valides mais elles ne doivent être utilisées qu'à partir de documents TeX, car il n'y a aucun moyen de personnaliser une recherche my en ligne de commande.

L'option color-callback détermine le stade auquel les polices définies avec une fonctionnalité color=xxyyzz seront colorisées. Par défaut, cela se produit dans un post_linebreak_filter mais alternativement le pre_linebreak_filter ou le pre_output_filter peuvent être choisis, ce qui est plus rapide mais peut produire des résultats incohérents. Le pre_output_filter était le défaut dans la série 1.x de Luaotfload, tandis que les versions ultérieures jusqu'à et y compris 2.5 se accrochaient au pre_linebreak_filter qui, naturellement, n'affectait aucun glyphe inséré pendant la césure. Les deux sont conservés comme options pour restaurer le comportement précédent si nécessaire.

Le definer permet de changer le rappel define_font. En dehors du patch par défaut, on peut également choisir celui generic qui accompagne le chargeur de polices standard. Attention, cela pourrait casser des outils comme Fontspec qui s'appuient sur le rappel patch_font fourni par Luaotfload pour effectuer des corrections importantes sur les données des polices.

Le backend du chargeur de polices peut être sélectionné en définissant la valeur de fontloader. Les choix les plus importants sont default, qui chargera le chargeur de polices dédié Luaotfload, et reference, le package en amont tel qu'expédié avec Luaotfload. Outre ceux-ci, un nom de fichier accessible via kpathsea peut être spécifié.

Alternativement, les fichiers individuels qui constituent le chargeur de polices peuvent être chargés directement. Bien que moins efficace, cela aide grandement au débogage car les messages d'erreur référenceront les numéros de ligne réels des fichiers source et les commentaires explicatifs ne sont pas supprimés. Actuellement, trois stratégies de chargement distinctes sont disponibles : unpackaged chargera le lot qui fait partie de Luaotfload. Ceux-ci contiennent le code source identique à partir duquel le chargeur de polices de référence a été compilé. Une autre option, context tentera de charger les mêmes fichiers par leurs noms au format Context depuis le chemin de recherche. Par conséquent, cette option permet d'utiliser la version de Context qui accompagne la distribution TeX. Les distributions ont tendance à préférer la version stable (“current” dans le jargon Context) odef ceux files so certain bugs encountered in the more bleeding edge Luaotfload can be avoided this way. A third option is to use context with a colon to specify a directory prefix where the TEXMF is located that the files should be loaded from, e. g. context:~/context/tex/texmf-context. This can be used when referencing another distribution like the Context minimals that is installed under a different path not indexed by kpathsea.

The value of log-level sets the default verbosity of messages printed by Luaotfload. Only messages defined with a verbosity of less than or equal to the supplied value will be output on the terminal. At a log level of five Luaotfload can be very noisy. Also, printing too many messages will slow down the interpreter due to line buffering being disabled (see setbuf(3)).

The resolver setting allows choosing the font name resolution function: With the default value cached Luaotfload saves the result of a successful font name request to a cache file to speed up subsequent lookups. The alternative, normal circumvents the cache and resolves every request individually. (Since to the restructuring of the font name index in Luaotfload 2.4 the performance difference between the cached and uncached lookups should be marginal.)

When luaotfload is used in DVI mode, the default_dvi_driver option determines how OpenType fonts are represented in the DVI output. In most cases the default value dvisvgm should be set, it uses a format supported by multiple backends including dvipdfmx and dvisvgm which uses GIDs to identify characters. Setting this to xdvipsk uses an unstable internal format instead which will change depending on the luaotfload, engine, or font version. No one should rely on the mapping between DVI character codes and font glyphs in this mode unless they tightly control all involved versions and are deeply familiar with the implementation.

FILES

Luaotfload only processes the first configuration file it encounters at one of the search locations. The file name may be either luaotfload.conf or luaotfloadrc, except for the dotfile in the user’s home directory which is expected at ~/.luaotfloadrc.

Configuration files are located following a series of steps. The search terminates as soon as a suitable file is encountered. The sequence of locations that Luaotfload looks at is

i.
The current working directory of the LuaTeX process.
ii.
The subdirectory luaotfload/ inside the XDG configuration tree, e. g. /home/oenothea/config/luaotfload/.
iii.
The dotfile.
iv.
The TEXMF (using kpathsea).
