LUAC(1) Manuel des commandes générales LUAC(1)

NOM

luac - Compilateur Lua

SYNTAXE

luac [ options ] [ fichiers ]

DESCRIPTION

luac est le compilateur Lua. Il traduit les programmes écrits dans le langage de programmation Lua en fichiers binaires qui peuvent ensuite être chargés et exécutés.

Les principaux avantages de la pré-compilation des blocs sont : un chargement plus rapide, la protection du code source contre les modifications accidentelles par l'utilisateur, et la vérification de la syntaxe hors ligne.

La pré-compilation n'implique pas une exécution plus rapide car dans Lua, les blocs sont toujours compilés en bytecode avant d'être exécutés. luac permet simplement de sauvegarder ces bytecodes dans un fichier pour une exécution ultérieure.

Les blocs pré-compilés ne sont pas nécessairement plus petits que la source correspondante. L'objectif principal de la pré-compilation est un chargement plus rapide.

Les fichiers binaires créés par luac ne sont portables qu'entre architectures ayant la même taille de mot et le même ordre des octets.

luac produit un seul fichier de sortie contenant les bytecodes de tous les fichiers sources donnés. Par défaut, le fichier de sortie est nommé luac.out, mais vous pouvez le changer avec l'option -o.

Dans la ligne de commande, vous pouvez mélanger des fichiers texte contenant du code source Lua et des fichiers binaires contenant des blocs pré-compilés. Ceci est utile pour combiner plusieurs blocs pré-compilés, même issus de plateformes différentes (mais compatibles), en un seul bloc pré-compilé.

Vous pouvez utiliser '-' pour indiquer l'entrée standard comme fichier source et '--' pour signaler la fin des options (c'est-à-dire que tous les arguments restants seront traités comme des fichiers même s'ils commencent par '-').

Le format interne des fichiers binaires produits par luac est susceptible de changer lors de la sortie d'une nouvelle version de Lua. Par conséquent, sauvegardez les fichiers sources de tous les programmes Lua que vous pré-compilez.

OPTIONS

Les options doivent être séparées.

-l
produit une liste du bytecode compilé pour la machine virtuelle Lua. La liste des bytecodes est utile pour apprendre le fonctionnement de la machine virtuelle Lua. Si aucun fichier n'est donné, luac charge luac.out et liste son contenu.
-o fichier
écrit dans fichier, au lieu du fichier par défaut luac.out. (Vous pouvez utiliser '-' pour la sortie standard, mais pas sur les plateformes qui ouvrent la sortie standard en mode texte.) Le fichier de sortie peut être un fichier source car tous les fichiers sont chargés avant que le fichier de sortie ne soit écrit. Faites attention à ne pas écraser des fichiers précieux.
-p
charge les fichiers mais ne génère aucun fichier de sortie. Utilisé principalement pour la vérification de la syntaxe et pour tester les blocs pré-compilés : les fichiers corrompus généreront probablement des erreurs lors du chargement. Lua effectue toujours un test d'intégrité approfondi sur les blocs pré-compilés. Le bytecode qui réussit ce test est complètement sûr, dans le sens où il ne plantera pas l'interpréteur. Cependant, rien ne garantit que ce code fasse quelque chose de sensé. (Aucune garantie ne peut être donnée, car le problème de l'arrêt est insoluble.) Si aucun fichier n'est donné, luac charge luac.out et teste son contenu. Aucun message n'est affiché si le fichier passe le test d'intégrité.
-s
supprime les informations de débogage avant d'écrire le fichier de sortie. Cela économise de l'espace dans les blocs très volumineux, mais si des erreurs surviennent lors de l'exécution d'un bloc dépouillé, les messages d'erreur peuvent ne pas contenir toutes les informations habituelles. Par exemple, les numéros de ligne et les noms des variables locales sont perdus.
-v
affiche les informations de version.

FICHIERS

luac.out
fichier de sortie par défaut
