NOM

luksmeta - Utilitaire pour stocker des métadonnées dans un en-tête LUKSv1

SYNTAXE

luksmeta test -d DEVICE

luksmeta nuke -d DEVICE [-f]

luksmeta init -d DEVICE [-f] [-n]

luksmeta show -d DEVICE [-s SLOT]

luksmeta save -d DEVICE [-s SLOT] -u UUID < DATA

luksmeta load -d DEVICE -s SLOT [-u UUID] > DATA

luksmeta wipe -d DEVICE -s SLOT [-u UUID] [-f]

APERÇU

L'utilitaire luksmeta permet à un administrateur de stocker des métadonnées dans l'espace entre la fin de l'en-tête LUKSv1 et le début des données chiffrées. Ceci est utile pour stocker des données disponibles avant le déverrouillage du volume, généralement pour être utilisées pendant le processus de déverrouillage du volume.

Les métadonnées sont stockées dans une série d'emplacements de type UUID, permettant plusieurs blocs de métadonnées. Bien que les emplacements de luksmeta soient inspirés des emplacements LUKS, ils sont fonctionnellement indépendants et ne partagent qu'une relation informelle. Les emplacements fournissent simplement un indice qu'un bloc de métadonnées donné est associé à un mot de passe LUKSv1 spécifique (dans un emplacement du même numéro). Cependant, luksmeta lui-même est indifférent à la relation entre un emplacement LUKSv1 et l'emplacement luksmeta correspondant, à une exception près (détaillée ci-dessous).

Après qu'un volume LUKSv1 a été initialisé à l'aide de cryptsetup(8), il doit également être initialisé pour le stockage des métadonnées par luksmeta init. Une fois cela terminé, le périphérique est prêt à stocker des métadonnées.

Les données peuvent être écrites dans un emplacement à l'aide de luksmeta save ou lues depuis un emplacement à l'aide de luksmeta load. Vous pouvez également effacer les données dans un emplacement existant à l'aide de luksmeta wipe ou interroger les emplacements à l'aide de luksmeta show.

GÉNÉRATION UUID

Il est souvent supposé que le stockage de métadonnées dans un emplacement nécessite un UUID spécifique ou qu'il existe un registre officiel des types d'UUID. Ceci est incorrect.

UUID signifie Universally Unique IDentifier. Les UUID sont un type de données standardisé et largement utilisé pour l'identification sans registre central. Pour les normes pertinentes, voir ISO 9834-8:2005 et RFC 4122.

Les UUID sont suffisamment grands pour que la collision soit pratiquement impossible. Donc, si votre application souhaite stocker des données dans un emplacement luksmeta, générez simplement votre propre UUID et utilisez-le de manière cohérente pour faire référence à votre type de données. Si vous avez plusieurs types de données, n'hésitez pas à générer plusieurs UUID.

Le moyen le plus simple de générer un UUID est d'utiliser uuidgen(1). Cependant, tout générateur d'UUID conforme suffira.

INITIALISATION

Avant de lire ou d'écrire des métadonnées, le périphérique de bloc LUKSv1 doit être initialisé pour le stockage des métadonnées. Trois commandes aident à ce processus : luksmeta test, luksmeta nuke et luksmeta init.

La commande luksmeta test vérifie simplement un périphérique de bloc existant pour voir s'il est initialisé pour le stockage des métadonnées. Cette commande ne produit aucune sortie, alors assurez-vous de vérifier son code de retour (voir ci-dessous).

La commande luksmeta nuke effacera (remplira de zéros) tout l'espace de l'en-tête LUKSv1. Étant donné que cette opération est destructive, une confirmation de l'utilisateur sera requise avant d'effacer l'espace, sauf si l'option -f est fournie.

La commande luksmeta init initialise le périphérique de bloc LUKSv1 pour le stockage des métadonnées. Ce processus effacera toutes les données dans l'espace de l'en-tête LUKSv1. Pour cette raison, cette commande exigera une confirmation de l'utilisateur avant toute écriture de données, sauf si l'option -f est fournie. Notez que cette commande réussit sans aucune modification si le périphérique est déjà initialisé. Si vous souhaitez forcer la création d'un état d'initialisation propre, vous pouvez spécifier l'option -n pour effacer l'espace de l'en-tête LUKSv1 avant l'initialisation (mais après confirmation de l'utilisateur).

ÉTAT MÉTA-DONNÉES

La commande luksmeta show affiche l'état actuel des emplacements sur le périphérique de bloc LUKSv1. Si aucun emplacement n'est spécifié, elle imprime un tableau composé du numéro d'emplacement, de l'état de l'emplacement LUKSv1 correspondant et de l'UUID des données stockées dans l'emplacement luksmeta (ou "vide" si aucune donnée n'est stockée). Si un emplacement est spécifié, cette commande imprime simplement l'UUID des données dans l'emplacement. Si l'emplacement ne contient pas de données, elle n'imprime rien.

GESTION MÉTA-DONNÉES

La gestion des métadonnées dans les emplacements est effectuée avec trois commandes : luksmeta save, luksmeta load et luksmeta wipe. Ces commandes écrivent des métadonnées dans un emplacement, lisent des métadonnées depuis un emplacement et effacent des métadonnées dans un emplacement, respectivement.

La commande luksmeta save lit les métadonnées sur l'entrée standard et les écrit dans l'emplacement spécifié en utilisant l'UUID spécifié. Si aucun emplacement n'est spécifié, luksmeta recherchera le premier numéro d'emplacement pour lequel l'emplacement LUKSv1 est inactif et l'emplacement luksmeta est vide. Cela représente la seule corrélation officielle entre les emplacements LUKSv1 et les emplacements luksmeta. Dans ce cas, les métadonnées sont écrites dans le premier emplacement applicable en utilisant l'UUID spécifié et le numéro d'emplacement est imprimé sur la sortie standard. Dans les deux cas, cette commande ne remplacera jamais les données existantes. Pour remplacer les données dans un emplacement, vous devrez exécuter luksmeta wipe avant luksmeta save.

La commande luksmeta load lit les données de l'emplacement spécifié et les écrit sur la sortie standard. Si un UUID est spécifié, la commande vérifiera que l'UUID associé aux métadonnées dans l'emplacement correspond à l'UUID spécifié. Ce contrôle de type aide à garantir que vous recevez toujours le type de données attendu en sortie. Si les UUID ne correspondent pas, la commande échouera.

La commande luksmeta wipe efface les données de l'emplacement donné. Si un UUID est spécifié, la commande vérifiera que l'UUID associé aux métadonnées dans l'emplacement correspond à l'UUID spécifié. Ce contrôle de type aide à garantir que vous n'effacez que les données que vous aviez l'intention d'effacer. Comme il s'agit d'une opération destructive, cette commande exigera une confirmation de l'utilisateur avant que toute donnée ne soit effacée, sauf si l'option -f est fournie. Notez que cette commande réussit si vous tentez d'effacer un emplacement déjà vide.

AVERTISSEMENTS

La quantité de stockage dans l'espace de l'en-tête LUKSv1 est extrêmement limitée. Elle varie également en fonction de la configuration utilisée par LUKSv1 au moment de l'initialisation du périphérique. Dans certaines configurations LUKSv1, il n'y a même pas assez d'espace pour tous les emplacements de métadonnées, même à la plus petite taille d'emplacement possible.

Au cours de la conception de cet utilitaire, nous avons considéré comme probable que les utilisateurs voudraient réduire le nombre d'emplacements utilisables en échange de plus d'espace de stockage dans les emplacements utilisés. Afin d'offrir cette flexibilité, la quantité de stockage disponible par emplacement est dynamique. En termes simples, les emplacements n'ont pas de taille fixe. Cela signifie qu'il est possible (et même assez probable) de rencontrer une erreur lors de luksmeta save indiquant un espace insuffisant.

Cette erreur n'est pas un bug de programmation. Si vous rencontrez cette erreur, cela signifie probablement que soit tout l'espace est consommé par les emplacements déjà écrits, soit que les métadonnées que vous tentez d'écrire ne rentrent tout simplement pas.

Vous pouvez tenter de résoudre ce problème en appelant luksmeta wipe sur les emplacements qui ne sont plus utilisés. Cela libérera l'espace de stockage pour être utilisé par d'autres emplacements. Notez que luksmeta ne procéde cependant pas à la défragmentation, car le nombre de blocs utilisables est plutôt limité. Vous pouvez tenter de contourner cela manuellement en extrayant toutes les données des emplacements, en effaçant les emplacements et en les rechargeant dans l'ordre. Cependant, cette opération est potentiellement dangereuse et doit être effectuée avec beaucoup de prudence.

OPTIONS

•-d PÉRIPHÉRIQUE, --device=PÉRIPHÉRIQUE : Le périphérique sur lequel effectuer l'opération.
•-s EMPLACEMENT, --slot=EMPLACEMENT : Le numéro d'emplacement sur lequel effectuer l'opération.
•-u UUID, --uuid=UUID : L'UUID à associer à l'opération.
•-f, --force : Supprime forcément

VALEURS DE RETOUR

Cette commande utilise les valeurs de retour telles que définies par sysexit.h. Les erreurs générales suivantes sont partagées par toutes les commandes luksmeta :

•EX_OK : L'opération a réussi.
•EX_OSERR : Une erreur système indéfinie s'est produite.
•EX_USAGE : Le programme a été appelé avec des paramètres invalides.
•EX_IOERR : Une erreur d'E/S s'est produite lors de l'écriture sur le périphérique.
•EX_OSFILE : Le périphérique n'est pas initialisé ou est corrompu.
•EX_NOPERM : L'utilisateur n'a pas accordé la permission lors de la confirmation.
•EX_NOINPUT : Une erreur s'est produite lors de la lecture de l'entrée standard.
•EX_DATAERR : L'UUID spécifié ne correspond pas à l'UUID de l'emplacement.
•EX_CANTCREAT : Il n'y a pas assez d'espace dans l'en-tête LUKSv1.

De plus, luksmeta save retournera EX_UNAVAILABLE lorsque vous tenterez de sauvegarder des données dans un emplacement déjà utilisé. De même, luksmeta load retournera EX_UNAVAILABLE lorsque vous tenterez de lire à partir d'un emplacement vide.

EXEMPLES

Détruit toutes les données (y compris les données LUKSMeta) dans l'espace libre de l'en-tête LUKSv1 et initialise cet espace pour le stockage LUKSMeta :

$ luksmeta init -n -f -d /dev/sdz

Si déjà initialisé, ne fait rien. Sinon, détruit toutes les données non-LUKSMeta dans l'espace libre de l'en-tête LUKSv1 et initialise cet espace pour le stockage LUKSMeta :

$ luksmeta init -f -d /dev/sdz

Écrit des données dans un emplacement :

$ UUID=*uuidgen*
$ echo $UUID
31c25e3b-b8e2-4eaa-a427-23aa882feef2
$ echo "Hello, World" | luksmeta save -d /dev/sdz -s 0 -u $UUID

Lit les données :

$ luksmeta load -d /dev/sdz -s 0 -u $UUID
Hello, World

Efface les données de l'emplacement :

$ luksmeta wipe -d /dev/sdz -s 0 -u $UUID

Efface toute trace de LUKSMeta :

$ luksmeta nuke -f -d /dev/sdz
