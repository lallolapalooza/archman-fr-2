LUATEX(1) Manuel des commandes générales LUATEX(1)

NOM

luatex, dviluatex, luahbtex, luajittex, texlua, texluac - Une version étendue de TeX utilisant Lua comme langage de script embarqué

SYNTAXE

luatex [--lua=FICHIER] [OPTION]... [NOMTEX[.tex]] [COMMANDES]
luatex [--lua=FICHIER] [OPTION]... \PREMIERE-LIGNE
luatex [--lua=FICHIER] [OPTION]... &FMT [ARGS]

DESCRIPTION

Exécute le compositeur luaTeX sur NOMTEX, créant généralement NOMTEX.pdf. Toute COMMANDE restante est traitée comme une entrée luaTeX, après la lecture de NOMTEX.

Alternativement, si le premier argument non-optionnel commence par une barre oblique inverse, interpréter tous les arguments non-optionnels comme une ligne d'entrée luaTeX.

Alternativement, si le premier argument non-optionnel commence par un &, le mot suivant est considéré comme le FMT à lire, annulant tout le reste. Tous les arguments restants sont traités comme ci-dessus.

Si aucun argument ou option n'est spécifié, demande une entrée.

S'il est appelé en tant que texlua, il agit comme un interpréteur Lua. S'il est appelé en tant que texluac, il agit comme un compilateur de bytecode Lua.

LuaTeX a commencé comme une version étendue de pdfTeX avec le support des polices Unicode et OpenType, un langage de script Lua embarqué, les extensions e-TeX et Omega, ainsi qu'un moteur MetaPost intégré, capable de créer des fichiers PDF ainsi que des fichiers DVI. Pour plus d'informations sur luatex, consultez http://www.luatex.org ; vous pouvez lire le manuel LuaTeX en utilisant l'utilitaire texdoc (texdoc luatex).

Toute entrée et sortie texte de LuaTeX est considérée comme du texte Unicode, bien que divers filtres permettent de supporter n'importe quel encodage.

En mode DVI, LuaTeX peut être utilisé comme un remplacement complet du moteur TeX.

En mode PDF, LuaTeX peut gérer nativement les formats graphiques PDF, JPG, JBIG2 et PNG. LuaTeX ne peut pas inclure les fichiers graphiques PostScript ou Encapsulated PostScript (EPS) ; convertissez-les d'abord en PDF en utilisant epstopdf(1).

La variante luajittex inclut le compilateur juste-à-temps Lua.

La variante luahbtex peut utiliser le moteur HarfBuzz pour le façonnage des glyphes, au lieu du façonneur intégré de LuaTeX.

OPTIONS

Lorsque l'exécutable LuaTeX démarre, il recherche l'option de ligne de commande --lua. S'il n'y a pas d'option --lua, la ligne de commande est interprétée de manière similaire aux programmes pdfTeX et Aleph traditionnels. Mais si l'option est présente, LuaTeX entrera dans un mode d'analyse de ligne de commande alternatif par rapport aux programmes web2c standards. La présence de --lua rend la plupart des autres options peu fiables, car le fichier d'initialisation lua peut désactiver kpathsea et/ou accrocher des fonctions à divers callbacks.

--lua=FICHIER
Le fichier d'initialisation lua.

Les deux options suivantes modifient le comportement de l'exécutable :

--luaonly
Démarre LuaTeX comme un interpréteur Lua. Dans ce mode, il définit arg[0] de Lua au nom du script trouvé, en plaçant les options précédentes dans des valeurs négatives et le reste de la ligne de commande dans les valeurs positives, tout comme l'interpréteur Lua. LuaTeX se terminera immédiatement après l'exécution du script Lua spécifié.
--luaconly
Démarre LuaTeX comme un compilateur de bytecode Lua. Dans ce mode, LuaTeX est exactement comme luac de la distribution Lua autonome, sauf qu'il n'a pas le commutateur -l, et qu'il accepte (mais ignore) le commutateur --luaconly.

Ensuite, les options web2c régulières :

--debug-format

Débogage du chargement des formats.
--draftmode
Définit \pdfdraftmode afin que luaTeX n'écrive pas de PDF et ne lise aucune image incluse, accélérant ainsi l'exécution.
--enable-write18

Synonyme de --shell-escape.
--disable-write18

Synonyme de --no-shell-escape.
--shell-escape

Active la construction \write18{commande}, ainsi que les fonctions Lua os.execute(), os.exec(), os.spawn() et io.popen(). La commande peut être n'importe quelle commande shell. Cette construction est normalement interdite pour des raisons de sécurité.
--no-shell-escape

Désactive la construction \write18{commande} et les autres fonctions Lua, même si elle est activée dans le fichier texmf.cnf.
--shell-restricted
Active une version restreinte de \write18, os.execute(), os.exec(), os.spawn() et io.popen() ; seules les commandes listées dans le fichier texmf.cnf sont autorisées.
--file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, similaire à la façon dont de nombreux compilateurs les formatent.
--no-file-line-error
Désactive l'affichage des messages d'erreur dans le style fichier:ligne:erreur.
--fmt=FORMAT
Utilise FORMAT comme nom du format à utiliser, au lieu du nom sous lequel luaTeX a été appelé ou d'une ligne %&.
--help
Affiche le message d'aide et quitte.
--ini
Démarre en mode INI, utilisé pour sauvegarder les formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et les initialisations de base comme la définition des catcodes peuvent être nécessaires.
--interaction=MODE
Définit le mode d'interaction. Le MODE peut être batchmode, nonstopmode, scrollmode ou errorstopmode. La signification de ces modes est la même que celle des \commandes correspondantes.
--jobname=NOM
Utilise NOM pour le nom du job, au lieu de le dériver du nom du fichier d'entrée.
--kpathsea-debug=MASQUE_BINAIRE
Définit les indicateurs de débogage de recherche de chemin selon le MASQUE_BINAIRE. Voir le manuel de Kpathsea pour les détails.
--mktex=FMT
Active la génération de mktexFMT, où FMT doit être tex ou tfm.
--nosocket
Désactive la bibliothèque luasocket (réseau).
--output-comment=CHAINE
En mode DVI, utilise CHAINE pour le commentaire du fichier DVI au lieu de la date. Cette option est ignorée en mode PDF.
--output-directory=REPERTOIRE
Écrit les fichiers de sortie dans REPERTOIRE au lieu du répertoire courant. Recherche les fichiers d'entrée dans REPERTOIRE en premier, puis le long du chemin de recherche normal.
--output-format=FORMAT
Définit le mode de format de sortie, où FORMAT doit être soit pdf soit dvi. Cela influence également l'ensemble des formats graphiques compris par luaTeX.
--progname=NOM
Fait semblant d'être le programme NOM (uniquement pour kpathsea).
--recorder
Active l'enregistreur de noms de fichiers. Cela laisse une trace des fichiers ouverts en entrée et en sortie dans un fichier avec l'extension .fls.
--safer
Désactive certaines commandes Lua qui peuvent être facilement abusées par un document malveillant.

NAME

luajittex - LuaTeX compiler using the LuaJIT engine

SYNOPSIS

luajittex [OPTIONS] <tex-file>

DESCRIPTION

LuaTeX is a TeX engine that integrates the Lua scripting language. LuaJIT is a Just-In-Time compiler for the Lua language. This is LuaTeX compiled with LuaJIT instead of standard Lua.

See the documentation for pdftex(1) for a description of the available command-line options. LuaTeX accepts all options recognized by pdftex, with the following exceptions:

OPTIONS

--interaction=MODE
Set interaction mode. Valid modes are batchmode, nonstopmode, inputmode, scrollmode, errorstopmode, and nonstopmode. The default is errorstopmode.
--job-name=NAME
Set the job name.
--output-directory=DIR
Set the output directory.
--version
Print version information and exit.
--credits
Print credits and version details.
The following options are ignored:
--8bit, --etex, --parse-first-line, --no-parse-first-line
These are always on.
--default-translate-file=TCXNAME, --translate-file=TCXNAME
These are always off.

SEE ALSO

pdftex(1), etex(1), aleph(1), lua(1), luatex(1).

AUTHORS

The primary authors of LuaTeX are Taco Hoekwater, Hartmut Henkel, Hans Hagen, and Luigi Scarso, with help from Martin Schröder, Karel Skoupy, and Han The Thanh.

TeX was designed by Donald E. Knuth, who implemented it using his Web system for Pascal programs. It was ported to Unix at Stanford by Howard Trickey, and at Cornell by Pavel Curtis. The version now offered with the Unix TeX distribution is that generated by the Web to C system (web2c), originally written by Tomas Rokicki and Tim Morgan.

The LuaTeX home page is http://luatex.org.
