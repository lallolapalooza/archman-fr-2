LD.LLD(1) Manuel des commandes générales LD.LLD(1)

NOM

ld.lld — Éditeur de liens ELF du projet LLVM

SYNTAXE

ld.lld [options] fichier_objet ...

DESCRIPTION

Un éditeur de liens prend un ou plusieurs fichiers objets, archives et bibliothèques, et les combine en un fichier de sortie (un exécutable, une bibliothèque partagée ou un autre fichier objet). Il relocalise le code et les données des fichiers d'entrée et résout les références de symboles entre eux.

ld.lld est un substitut direct pour les éditeurs de liens GNU BFD et gold. Il accepte la plupart des mêmes arguments de ligne de commande et scripts d'édition de liens que les éditeurs de liens GNU.

ld.lld prend actuellement en charge les cibles i386, x86-64, ARM, AArch64, LoongArch, PowerPC32, PowerPC64, MIPS32, MIPS64, RISC-V, AMDGPU, Hexagon et SPARC V9. ld.lld agit comme un éditeur de liens compatible avec Microsoft link.exe s'il est invoqué en tant que lld-link et comme ld de macOS s'il est invoqué en tant que ld.ld64. Toutes ces cibles sont toujours prises en charge quelle que soit la façon dont ld.lld a été construit, vous pouvez donc toujours utiliser ld.lld comme éditeur de liens natif ainsi que comme éditeur de liens croisé.

OPTIONS

De nombreuses options ont une forme à une seule lettre et une forme longue. Lors de l'utilisation des formes longues, les options autres que celles commençant par la lettre o peuvent être spécifiées à l'aide d'un ou deux traits d'union précédant le nom de l'option. Les options longues commençant par o nécessitent deux traits d'union pour éviter la confusion avec l'option -o chemin.

--allow-multiple-definition
Ne pas générer d'erreur si un symbole est défini plusieurs fois. La première définition sera utilisée.
--allow-shlib-undefined
Autoriser les références non résolues dans les bibliothèques partagées. Cette option est activée par défaut lors de l'édition de liens d'une bibliothèque partagée.
--apply-dynamic-relocs
Appliquer les valeurs de temps d'édition de liens pour les relocations dynamiques.
--as-needed
Ne définir DT_NEEDED pour les bibliothèques partagées que si elles sont utilisées.
--auxiliary=valeur
Définir le champ DT_AUXILIARY sur le nom spécifié.
--Bdynamic, --dy
Éditer les liens avec des bibliothèques partagées.
--Bstatic, --static, --dn
Ne pas éditer les liens avec des bibliothèques partagées.
-Bno-symbolic
Ne pas lier localement les symboles définis avec la visibilité par défaut pour -shared (par défaut).
-Bsymbolic
Lier localement les symboles définis avec la visibilité par défaut pour -shared. Définit également le drapeau DF_SYMBOLIC.
-Bsymbolic-non-weak
Lier localement les symboles STB_GLOBAL définis avec la visibilité par défaut pour -shared.
-Bsymbolic-functions
Lier localement les symboles de fonction définis avec la visibilité par défaut pour -shared.
-Bsymbolic-non-weak-functions
Lier localement les symboles de fonction STB_GLOBAL définis avec la visibilité par défaut pour -shared.
--be8
Écrire un fichier ELF Big Endian au format BE8 (AArch32 uniquement)
--branch-to-branch
Activer les optimisations branchement-à-branchement : un branchement dont la cible est une autre instruction de branchement est réécrit pour pointer vers la cible du second branchement (AArch64 et X86_64 uniquement). Activé par défaut à -O2.
--build-id=valeur
Générer une note d'identifiant de construction (build ID). valeur peut être l'une des suivantes : fast, md5, sha1, tree, uuid, 0xchaîne-hexadécimale, et none. tree est un alias pour sha1. Les identifiants de construction de type fast, md5, sha1, et tree sont calculés à partir du contenu des objets. fast n'est pas destiné à être cryptographiquement sécurisé.
--build-id
Synonyme de --build-id=sha1.
--call-graph-profile-sort=algorithme
algorithme peut être :
none
Ignorer le profil du graphe d'appels.
hfsort
Utiliser hfsort.
cdsort
Utiliser cdsort (par défaut).
--color-diagnostics=valeur
Utiliser les couleurs dans les diagnostics. valeur peut être l'une des suivantes : always, auto, et never. auto active la couleur si et seulement si la sortie est destinée à un terminal.
--color-diagnostics
Alias pour --color-diagnostics=auto.
--compress-debug-sections=valeur
Compresser les sections de débogage DWARF. Les sections restent non compressées si le contenu compressé serait plus volumineux. valeur peut être :
none
Aucune compression.
zlib
Le niveau de compression par défaut est 1 (le plus rapide) car les informations de débogage se compressent généralement bien à ce niveau.
zstd
Utiliser le niveau de compression par défaut de zstd.
--compress-sections=glob-section={none,zlib,zstd}[:niveau]
Compresser les sections de sortie qui correspondent au glob et qui n'ont pas le drapeau SHF_ALLOC. Les sections correspondantes restent non compressées si le contenu compressé serait plus volumineux. Le niveau de compression est niveau (si spécifié) ou un niveau par défaut axé sur la vitesse. Ceci est comme une généralisation de --compress-debug-sections.
--cref
Générer un tableau de références croisées. Si -Map est spécifié, écrire dans le fichier de mappage.
--debug-names
Générer une section fusionnée .debug_names.

--warn-ifunc-textrel
Avertir de l'utilisation des symboles ifunc en conjonction avec des relocations de texte. Les versions plus anciennes de la bibliothèque glibc (2.28 et antérieures) comportent un bug qui fait que le segment incluant les symboles ifunc est marqué comme non exécutable lorsqu'ils sont relocalisés. Par conséquent, bien que le programme compile et lie avec succès, il génère une erreur de segmentation lorsque le pointeur d'instruction atteint un symbole ifunc. Utilisez -warn-ifunc-textrel pour que ldd donne un avertissement, si le code peut inclure des symboles ifunc, effectuer des relocations de texte et être lié à une version plus ancienne de glibc. Sinon, il n'est pas nécessaire de l'utiliser, car la valeur par défaut ne donne pas d'avertissement. Ce drapeau a été introduit fin 2018, n'a pas d'équivalent dans les linkers ld et gold, et pourrait être supprimé à l'avenir.

VARIABLES ENVIRONNEMENTALES

LLD_REPRODUCE
ld.lld crée une archive tar avec le nom de fichier spécifié. Si --reproduce est spécifié, --reproduce a la priorité.
LLD_VERSION
ld.lld crée une section nommée .comment contenant la chaîne de version de LLD. La chaîne de version peut être remplacée par cette variable d'environnement, ce qui est utile pour éliminer les différences dans le binaire causées par les différences de numéro de version de LLD.

NOTES D'IMPLÉMENTATION

ld.lld gère les fichiers archives (ceux avec une extension de fichier .a) différemment des linkers traditionnels utilisés sur les systèmes Unix.

Les linkers traditionnels maintiennent un ensemble de symboles indéfinis pendant l'édition des liens. Le linker traite chaque fichier dans l'ordre où il apparaît sur la ligne de commande, jusqu'à ce que l'ensemble des symboles indéfinis soit vide. Un fichier objet est lié à l'objet de sortie lorsqu'il est rencontré, avec ses symboles indéfinis ajoutés à l'ensemble. En rencontrant un fichier archive, un linker traditionnel recherche les objets qu'il contient et traite ceux qui satisfont les symboles de l'ensemble non résolu.

La gestion des archives mutuellement dépendantes peut être compliquée lors de l'utilisation d'un linker traditionnel. Les fichiers archives peuvent avoir à être spécifiés plusieurs fois, ou les options de ligne de commande spéciales --start-group et --end-group peuvent être utilisées pour que le linker boucle sur les fichiers du groupe jusqu'à ce qu'aucun nouveau symbole ne soit ajouté à l'ensemble.

ld.lld enregistre tous les symboles trouvés dans les objets et les archives lors de son itération sur les arguments de la ligne de commande. Lorsque ld.lld rencontre un symbole indéfini qui peut être résolu par un fichier objet contenu dans un fichier archive précédemment traité, il l'extrait et le lie immédiatement à l'objet de sortie.

Avec certaines entrées d'archives, ld.lld peut produire des résultats différents par rapport aux linkers traditionnels. En pratique, de grands volumes de logiciels tiers ont été liés avec ld.lld sans problèmes majeurs.

L'option --warn-backrefs peut être utilisée pour identifier une invocation de linker qui pourrait être incompatible avec le comportement traditionnel des linkers Unix.
