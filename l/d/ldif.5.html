LDIF(5) Manuel des formats de fichiers LDIF(5)

NOM

ldif - Format d'échange de données LDAP

DESCRIPTION

Le format d'échange de données LDAP (LDIF) est utilisé pour représenter les entrées LDAP et les enregistrements de modification sous forme de texte. Les outils LDAP, tels que ldapadd(1) et ldapsearch(1), lisent et écrivent des enregistrements d'entrées LDIF. ldapmodify(1) lit des enregistrements de modification LDIF.

Cette page de manuel fournit une description de base du LDIF. Une spécification formelle du LDIF est publiée dans la RFC 2849.

ENREGISTREMENTS D'ENTRÉE

Les enregistrements d'entrées LDIF sont utilisés pour représenter les entrées d'annuaire. La forme de base d'un enregistrement d'entrée est :

dn: <nom unique>
<descAttribut>: <valeurAttribut>
<descAttribut>: <valeurAttribut>
<descAttribut>:: <valeur encodée en base64>
<descAttribut>:< <URL>
...

La valeur peut être spécifiée sous forme de texte UTF-8 ou de données encodées en base64, ou une URI peut être fournie pour l'emplacement de la valeur de l'attribut.

Une ligne peut être continuée en commençant la ligne suivante par un espace simple ou une tabulation, par ex.

dn: cn=Barbara J Jensen,dc=exam
 ple,dc=com

Les lignes commençant par un dièse ('#') sont ignorées.

Plusieurs valeurs d'attribut sont spécifiées sur des lignes séparées, par ex.

cn: Barbara J Jensen
cn: Babs Jensen

Si une valeur contient un caractère non imprimable, ou commence par un espace ou un deux-points ':', le <typeAttribut> est suivi d'un double deux-points et la valeur est encodée en notation base 64. par ex., la valeur " commence par un espace" serait encodée comme suit :

cn:: IGJlZ2lucyB3aXRoIGEgc3BhY2U=

Si la valeur de l'attribut se trouve dans un fichier, le <typeAttribut> est suivi d'un ':<' et d'une URI de type file:. par ex., la valeur contenue dans le fichier /tmp/value serait listée comme suit :

cn:< file:///tmp/value
D'autres schémas d'URI (ftp, http) peuvent également être pris en charge.

Les entrées multiples dans le même fichier LDIF sont séparées par des lignes vides.

EXEMPLE D'ENREGISTREMENT D'ENTRÉE

Voici un exemple de fichier LDIF contenant trois entrées.

dn: cn=Barbara J Jensen,dc=example,dc=com
cn: Barbara J Jensen
cn: Babs Jensen
objectclass: person
description:< file:///tmp/babs
sn: Jensen
dn: cn=Bjorn J Jensen,dc=example,dc=com
cn: Bjorn J Jensen
cn: Bjorn Jensen
objectclass: person
sn: Jensen
dn: cn=Jennifer J Jensen,dc=example,dc=com
cn: Jennifer J Jensen
cn: Jennifer Jensen
objectclass: person
sn: Jensen
jpegPhoto:: /9j/4AAQSkZJRgABAAAAAQABAAD/2wBDABALD
 A4MChAODQ4SERATGCgaGBYWGDEjJR0oOjM9PDkzODdASFxOQ
 ERXRTc4UG1RV19iZ2hnPk1xeXBkeFxlZ2P/2wBDARESEhgVG
...

Notez que la description dans l'entrée de Barbara Jensen est lue à partir de file:///tmp/babs et que le jpegPhoto dans l'entrée de Jennifer Jensen est encodé en utilisant la base 64.

ENREGISTREMENTS DE MODIFICATION

Les enregistrements de modification LDIF sont utilisés pour représenter les requêtes de modification de l'annuaire. Chaque enregistrement de modification commence par une ligne indiquant le nom unique de l'entrée à modifier :

dn: <nom unique>
changetype: <[modify|add|delete|modrdn]>

Enfin, les informations de modification sont fournies, dont le format dépend du type de modification spécifié ci-dessus. Pour un changetype de modify, le format est un ou plusieurs des éléments suivants :

add: <typeAttribut>
<descAttribut>: <valeur1>
<descAttribut>: <valeur2>
...
-

Ou, pour une modification de remplacement :

replace: <typeAttribut>
<descAttribut>: <valeur1>
<descAttribut>: <valeur2>
...
-

Si aucune ligne de typeAttribut n'est donnée pour remplacer, l'attribut entier doit être supprimé (s'il est présent).

Ou, pour une modification de suppression :

delete: <typeAttribut>
<descAttribut>: <valeur1>
<descAttribut>: <valeur2>
...
-

Si aucune ligne de typeAttribut n'est donnée pour supprimer, l'attribut entier doit être supprimé.

Pour un changetype de add, le format est :

<descAttribut1>: <valeur1>
<descAttribut1>: <valeur2>
...
<descAttributN>: <valeur1>
<descAttributN>: <valeur2>

Pour un changetype de modrdn ou moddn, le format est :

newrdn: <nouveauRDN>
deleteoldrdn: 0 | 1
newsuperior: <DN>

où une valeur de 1 pour deleteoldrdn signifie supprimer les valeurs formant l'ancien RDN de l'entrée, et une valeur de 0 signifie laisser les valeurs comme attributs non uniques dans l'entrée. La ligne newsuperior est optionnelle et, si présente, spécifie le nouveau supérieur vers lequel déplacer l'entrée.

Pour un changetype de delete, aucune information supplémentaire n'est nécessaire dans l'enregistrement.

Notez que les valeurs d'attribut peuvent être présentées en utilisant la base64 ou dans des fichiers comme décrit pour les enregistrements d'entrée. Les lignes dans les enregistrements de modification peuvent également être continuées de la manière décrite pour les enregistrements d'entrée.

EXEMPLE D'ENREGISTREMENT DE MODIFICATION

Le fichier LDIF d'exemple suivant contient un enregistrement de chaque type de modification.

dn: cn=Babs Jensen,dc=example,dc=com
changetype: add
objectclass: person
objectclass: extensibleObject
cn: babs
cn: babs jensen
sn: jensen
dn: cn=Babs Jensen,dc=example,dc=com
changetype: modify
add: givenName
givenName: Barbara
givenName: babs
-
replace: description
description: the fabulous babs
-
delete: sn
sn: jensen
-
dn: cn=Babs Jensen,dc=example,dc=com
changetype: modrdn
newrdn: cn=Barbara J Jensen
deleteoldrdn: 0
newsuperior: ou=People,dc=example,dc=com
dn: cn=Barbara J Jensen,ou=People,dc=example,dc=com
changetype: delete

DÉCLARATION INCLUDE

L'analyseur LDIF a été étendu pour prendre en charge une déclaration include pour référencer d'autres fichiers LDIF. La déclaration include doit être séparée des autres enregistrements par une ligne vide. Le fichier référencé est spécifié à l'aide d'une URI de type file: et tout son contenu est incorporé comme s'il faisait partie du fichier LDIF original. Comme ci-dessus, d'autres schémas d'URI peuvent être pris en charge. Par exemple :

dn: dc=example,dc=com
objectclass: domain
dc: example
include: file:///tmp/example.com.ldif
dn: dc=example,dc=org
objectclass: domain
dc: example
Cette fonctionnalité ne fait pas partie de la spécification LDIF de la RFC 2849 mais devrait apparaître dans une future révision de cette spécification. Elle est prise en charge par les commandes ldapadd(1), ldapmodify(1) et slapadd(8).

VOIR AUSSI

ldap(3), ldapsearch(1), ldapadd(1), ldapmodify(1), slapadd(8), slapcat(8), slapd-ldif(5).

"LDAP Data Interchange Format," Good, G., RFC 2849.
