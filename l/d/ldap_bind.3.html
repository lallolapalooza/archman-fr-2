DESCRIPTION

Ces routines fournissent diverses interfaces pour l'opération de liaison LDAP. Après qu'une association avec un serveur LDAP est établie à l'aide de ldap_init(3), une opération de liaison LDAP doit être effectuée avant de tenter d'autres opérations sur la connexion. Une liaison LDAP est requise lors de l'utilisation de la version 2 du protocole LDAP ; elle est facultative pour la version 3 mais est généralement nécessaire en raison de considérations de sécurité.

Il existe trois types d'appels de liaison : ceux qui fournissent une authentification simple, ceux qui fournissent une authentification SASL, et des routines générales capables de gérer l'une ou l'autre authentification simple ou SASL.

SASL (Simple Authentication and Security Layer) peut négocier l'un des nombreux types d'authentification différents. Des versions synchrones et asynchrones de chaque variante de l'appel de liaison sont fournies. Toutes les routines prennent ld comme premier paramètre, tel que retourné par ldap_init(3).

AUTHENTIFICATION SIMPLE

La forme la plus simple de l'appel de liaison est ldap_simple_bind_s(). Elle prend le DN à lier sous forme de who, et le userPassword associé à l'entrée dans passwd. Elle retourne une indication d'erreur LDAP (voir ldap_error(3)). L'appel ldap_simple_bind() est asynchrone, prenant les mêmes paramètres mais initiant uniquement l'opération de liaison et retournant l'identifiant du message de la requête envoyée. Le résultat de l'opération peut être obtenu par un appel ultérieur à ldap_result(3). Les fonctions ldap_sasl_bind_s() et ldap_sasl_bind() (asynchrone) peuvent également être utilisées pour effectuer une liaison simple en utilisant LDAP_SASL_SIMPLE comme mécanisme SASL.

AUTHENTIFICATION GÉNÉRALE

Les routines ldap_bind() et ldap_bind_s() peuvent être utilisées lorsque la méthode d'authentification à utiliser doit être sélectionnée à l'exécution. Elles prennent toutes deux un paramètre method supplémentaire sélectionnant la méthode d'authentification à utiliser. Il doit être défini sur LDAP_AUTH_SIMPLE pour sélectionner l'authentification simple. ldap_bind() retourne l'identifiant du message de la requête qu'elle initie. ldap_bind_s() retourne une indication d'erreur LDAP.

AUTHENTIFICATION SASL

Pour les liaisons SASL, le serveur ignore toujours tout DN fourni, donc le paramètre dn doit toujours être NULL. ldap_sasl_bind_s() envoie une seule requête de liaison SASL avec le mechanism SASL donné et les informations d'identification dans le paramètre cred. Le format des informations d'identification dépend du mécanisme SASL particulier utilisé. Pour les mécanismes qui fournissent une authentification mutuelle, les informations d'identification du serveur seront retournées dans le paramètre servercredp. La routine retourne une indication d'erreur LDAP (voir ldap_error(3)). L'appel ldap_sasl_bind() est asynchrone, prenant les mêmes paramètres mais envoyant uniquement la requête et retournant l'identifiant du message de la requête envoyée. Le résultat de l'opération peut être obtenu par un appel ultérieur à ldap_result(3). Le résultat doit être analysé davantage par ldap_parse_sasl_bind_result() pour obtenir toutes les informations d'identification du serveur envoyées par le serveur.

Toutes les informations d'identification du serveur retournées doivent être libérées à l'aide de ber_bvfree().

De nombreux mécanismes SASL nécessitent plusieurs échanges de messages pour effectuer une authentification complète. Les applications devraient généralement utiliser ldap_sasl_interactive_bind_s() plutôt que d'appeler directement les fonctions de base ldap_sasl_bind(). Le paramètre mechs doit contenir une liste de mécanismes candidats séparés par des espaces à utiliser. Si ce paramètre est NULL ou vide, la bibliothèque interrogera l'attribut supportedSASLMechanisms du rootDSE du serveur pour obtenir la liste des mécanismes SASL pris en charge par le serveur. Le paramètre flags contrôle l'interaction utilisée pour récupérer les paramètres d'authentification SASL nécessaires et doit être l'un des suivants :

LDAP_SASL_AUTOMATIC
utiliser les valeurs par défaut si disponibles, sinon demander
LDAP_SASL_INTERACTIVE
toujours demander
LDAP_SASL_QUIET
ne jamais demander

La fonction interact utilise les defaults fournis pour gérer les demandes de la bibliothèque SASL concernant des paramètres d'authentification particuliers. Il n'y a pas de format défini pour les informations de defaults ; il appartient à l'appelant d'utiliser le format approprié pour la fonction interact fournie. Le paramètre sasl_interact provient de la bibliothèque SASL sous-jacente. Lorsqu'il est utilisé avec Cyrus SASL, il s'agit d'un tableau de structures sasl_interact_t. Les applications qui ont besoin de gérer les connexions de manière asynchrone peuvent utiliser ldap_sasl_interactive_bind() au lieu de la version synchrone. Un paramètre mechs valide doit être fourni, sinon la bibliothèque sera forcée de interroger le serveur pour obtenir une liste des mécanismes pris en charge, et cette interrogation sera effectuée de manière synchrone. Les autres paramètres sont identiques à ceux de la fonction synchrone, avec trois paramètres supplémentaires. Le mécanisme SASL réel qui a été utilisé, et l'identifiant du message à utiliser avec ldap_result() seront retournés respectivement dans rmechp et msgidp. La valeur dans rmechp ne doit pas être modifiée par l'appelant et doit être passée à nouveau à chaque appel ultérieur. Le message obtenu à partir de ldap_result() doit être passé dans le paramètre result. Ce paramètre doit être NULL lors de l'initiation d'un nouveau Bind. L'appelant doit libérer le message résultat après chaque appel en utilisant ldap_msgfree(). La fonction ldap_sasl_interactive_bind() renvoie un code de résultat LDAP. Si le code est LDAP_SASL_BIND_IN_PROGRESS, alors le Bind n'est pas encore terminé, et cette fonction doit être appelée à nouveau avec le résultat suivant du serveur.

REDEFINITION

La fonction ldap_set_rebind_proc() définit le processus à utiliser pour la liaison lorsqu'une opération renvoie une référence. Cette fonction est utilisée lorsqu'une application a besoin de se lier à un autre serveur pour suivre une référence ou une référence de continuation de recherche.

La fonction prend ld, la fonction rebind et les params, les données arbitraires comme les informations d'état dont le client pourrait avoir besoin pour se reconnecter correctement. L'option LDAP_OPT_REFERRALS dans ld doit être définie sur ON pour que les bibliothèques utilisent la fonction de rebind. Utilisez la fonction ldap_set_option pour définir la valeur.

Les paramètres de la fonction de rebind sont les suivants :

Le paramètre ld doit être utilisé par l'application lors de la liaison au serveur référencé si l'application souhaite que les bibliothèques suivent la référence.

Le paramètre url pointe vers la chaîne de référence d'URL reçue du serveur LDAP. L'application LDAP peut utiliser la fonction ldap_url_parse(3) pour analyser la chaîne en ses composants.

Le paramètre request spécifie le type de requête qui a généré la référence.

Le paramètre msgid spécifie l'identifiant du message de la requête générant la référence.

Le paramètre params est la même valeur que celle passée initialement à la fonction ldap_set_rebind_proc().

Les bibliothèques LDAP définissent tous les paramètres lorsqu'elles appellent la fonction de rebind. L'application ne doit pas tenter de libérer ni les structures ld ni url dans la fonction de rebind.

L'application doit fournir à la fonction de rebind les informations d'authentification requises telles que le nom d'utilisateur, le mot de passe et les certificats. La fonction de rebind doit utiliser une méthode de liaison synchrone.

DECONNEXION

L'appel ldap_unbind() est utilisé pour se déconnecter de l'annuaire, terminer l'association en cours et libérer les ressources contenues dans la structure ld. Une fois appelé, la connexion au serveur LDAP est fermée, et la structure ld est invalide. L'appel ldap_unbind_s() est juste un autre nom pour ldap_unbind() ; ces deux appels sont de nature synchrone.

Les fonctions ldap_unbind_ext() et ldap_unbind_ext_s() permettent de spécifier des contrôles pour les opérations.

ERREURS

Les routines asynchrones renverront -1 en cas d'erreur, en définissant le paramètre ld_errno de la structure ld. Les routines synchrones renvoient la valeur définie pour ld_errno. Voir ldap_error(3) pour plus d'informations.

NOTES

Si une liaison anonyme est suffisante pour l'application, le processus de rebind n'a pas besoin d'être fourni. Les bibliothèques LDAP avec l'option LDAP_OPT_REFERRALS définie sur ON (valeur par défaut) suivront automatiquement les références en utilisant une liaison anonyme.

Si l'application a besoin d'une authentification plus forte qu'une liaison anonyme, vous devez fournir un processus de rebind pour cette méthode d'authentification. La méthode de liaison doit être synchrone.
