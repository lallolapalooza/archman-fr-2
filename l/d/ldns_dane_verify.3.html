NOM

ldns_dane_verify, ldns_dane_verify_rr - Fonctions de vérification des enregistrements TLSA

SYNOPSIS

#include <stdint.h>
#include <stdbool.h>

#include <ldns/ldns.h>

ldns_status ldns_dane_verify(const ldns_rr_list* tlsas, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store);

ldns_status ldns_dane_verify_rr(const ldns_rr* tlsa_rr, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store);

DESCRIPTION

ldns_dane_verify() ATTENTION ! Nous recommandons vivement d'utiliser les fonctions de vérification DANE d'OpenSSL 1.1.0 au lieu de celles fournies par ldns. Lorsque OpenSSL 1.1.0 était disponible, ldns utilisait les fonctions de vérification DANE d'OpenSSL 1.1.0 en arrière-plan. Lorsque ldns était lié avec OpenSSL < 1.1.0, cette fonction ne pourra pas vérifier les enregistrements TLSA avec les types d'usage DANE-TA.

ATTENTION ! Les fonctions de vérification DANE de ldns n'effectuent *pas* de vérifications de noms de serveur. L'utilisateur doit effectuer lui-même des vérifications supplémentaires de noms de serveur !

Vérifie si l'un des enregistrements de ressources TLSA fournis correspond au certificat donné.

tlsas : Les enregistrements de ressources qui spécifient quoi et comment faire correspondre le certificat. Un enregistrement doit correspondre pour que cette fonction réussisse. Avec tlsas == NULL ou un nombre d'enregistrements TLSA dans tlsas == 0, une validation PKIX régulière est effectuée.
cert : Le certificat à faire correspondre (et à valider).
extra_certs : Certificats intermédiaires qui peuvent être nécessaires pour créer la chaîne de validation.
pkix_validation_store : Utilisé lorsque l'usage du certificat est "CA constraint" ou "Service Certificate Constraint" pour valider le certificat.

Retourne LDNS_STATUS_OK en cas de succès, LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA lorsqu'au moins un des TLSA avait le type d'usage DANE-TA et aucun des TLSA n'a correspondu ou n'a été validé PKIX, LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE lorsqu'un des TLSA a correspondu mais que la validation PKIX a échoué, LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH lorsqu'aucun des TLSA n'a correspondu, ou d'autres erreurs ldns_status.

ldns_dane_verify_rr() ATTENTION ! Nous recommandons vivement d'utiliser les fonctions de vérification DANE d'OpenSSL 1.1.0 au lieu de celles fournies par ldns. Lorsque OpenSSL 1.1.0 était disponible, ldns utilisait les fonctions de vérification DANE d'OpenSSL 1.1.0 en arrière-plan. Lorsque ldns était lié avec OpenSSL < 1.1.0, cette fonction ne pourra pas vérifier les enregistrements TLSA avec les types d'usage DANE-TA.

ATTENTION ! Les fonctions de vérification DANE de ldns n'effectuent *pas* de vérifications de noms de serveur. L'utilisateur doit effectuer lui-même des vérifications supplémentaires de noms de serveur !

Vérifie si l'enregistrement de ressource TLSA fourni correspond au certificat donné. Le rapport sur une non-concordance TLSA rr (LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH) est préféré à un échec PKIX (LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE). Ainsi, lorsque la validation PKIX est requise par l'usage du certificat TLSA, mais que les données TLSA ne correspondent pas, LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH est retourné, que la validation PKIX ait réussi ou non.

Lorsque ldns est lié avec OpenSSL < 1.1.0 et que cette fonction est disponible, alors le type d'usage DANE-TA ne sera pas vérifié, et sur un tlsa_rr avec ce type d'usage, LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA sera retourné.

tlsa_rr : L'enregistrement de ressource qui spécifie quoi et comment faire correspondre le certificat. Avec tlsa_rr == NULL, une validation PKIX régulière est effectuée.
cert : Le certificat à faire correspondre (et à valider).
extra_certs : Certificats intermédiaires qui peuvent être nécessaires pour créer la chaîne de validation.
pkix_validation_store : Utilisé lorsque l'usage du certificat est "CA constraint" ou "Service Certificate Constraint" pour valider le certificat.

Retourne LDNS_STATUS_OK en cas de succès, LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA lorsque le TLSA fourni avait le type d'usage DANE-TA, LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH en cas de non-concordance des données TLSA, LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE lorsque le TLSA a correspondu, mais que la validation PKIX a échoué, ou d'autres erreurs ldns_status.
