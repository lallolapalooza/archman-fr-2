LDAP_RESULT(3) Manuel des fonctions de bibliothèque LDAP_RESULT(3)

NOM

ldap_result - Attend le résultat d'une opération LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>
int ldap_result( LDAP *ld, int msgid, int all,
	struct timeval *timeout, LDAPMessage **result );
int ldap_msgfree( LDAPMessage *msg );
int ldap_msgtype( LDAPMessage *msg );
int ldap_msgid( LDAPMessage *msg );

DESCRIPTION

La routine ldap_result() est utilisée pour attendre et retourner le résultat d'une opération précédemment initiée par l'une des routines d'opération asynchrones LDAP (par exemple, ldap_search_ext(3), ldap_modify_ext(3), etc.). Ces routines retournent -1 en cas d'erreur, et un identifiant d'invocation lors de l'initiation réussie de l'opération. L'identifiant d'invocation est choisi par la bibliothèque et est garanti d'être unique sur la session LDAP. Il peut être utilisé pour demander le résultat d'une opération spécifique à ldap_result() via le paramètre msgid.

La routine ldap_result() bloquera ou non, en fonction du paramètre timeout. Si timeout n'est pas un pointeur NULL, il spécifie un intervalle maximum pour attendre l'achèvement de la sélection. Si timeout est un pointeur NULL, la valeur LDAP_OPT_TIMEOUT définie par ldap_set_option(3) est utilisée. Avec le réglage par défaut, la sélection bloque indéfiniment. Pour effectuer un sondage, l'argument timeout doit être un pointeur non NULL, pointant vers une structure timeval avec une valeur nulle. Pour obtenir le comportement du réglage par défaut, en ignorant toute valeur définie par ldap_set_option(3), définissez le champ tv_sec du paramètre timeout à -1. Voir select(2) pour plus de détails.

Si le résultat d'une opération spécifique est requis, msgid doit être défini sur l'identifiant d'invocation retourné lors de l'initiation de l'opération, sinon LDAP_RES_ANY ou LDAP_RES_UNSOLICITED doit être fourni pour attendre toute réponse ou une réponse non sollicitée.

Le paramètre all, s'il est différent de zéro, fait que ldap_result() retourne toutes les réponses avec msgid, sinon seule la prochaine réponse est retournée. Ceci est couramment utilisé pour obtenir toutes les réponses d'une opération de recherche.

Une réponse de recherche est composée de zéro ou plusieurs entrées de recherche, zéro ou plusieurs références de recherche, et zéro ou plusieurs réponses partielles étendues suivies d'un résultat de recherche. Si all est défini sur 0, les entrées de recherche seront retournées une par une au fur et à mesure qu'elles arrivent, via des appels séparés à ldap_result(). Si elles sont définies sur 1, la réponse de recherche ne sera retournée dans son intégralité que lorsque toutes les entrées, toutes les références, toutes les réponses partielles étendues et le résultat final de la recherche auront été reçus.

VALEUR DE RETOUR

En cas de succès, le type du résultat reçu est retourné et le paramètre result contiendra le résultat de l'opération ; sinon, le paramètre result est indéfini. Ce résultat doit être transmis aux routines d'analyse LDAP, ldap_first_message(3) et similaires, pour interprétation.

Les types de résultats possibles retournés sont :

LDAP_RES_BIND (0x61)
LDAP_RES_SEARCH_ENTRY (0x64)
LDAP_RES_SEARCH_REFERENCE (0x73)
LDAP_RES_SEARCH_RESULT (0x65)
LDAP_RES_MODIFY (0x67)
LDAP_RES_ADD (0x69)
LDAP_RES_DELETE (0x6b)
LDAP_RES_MODDN (0x6d)
LDAP_RES_COMPARE (0x6f)
LDAP_RES_EXTENDED (0x78)
LDAP_RES_INTERMEDIATE (0x79)

La routine ldap_msgfree() est utilisée pour libérer la mémoire allouée pour le(s) résultat(s) par ldap_result() ou ldap_search_ext_s(3) et similaires. Elle prend un pointeur vers le résultat ou la chaîne de résultats à libérer et retourne le type du dernier message de la chaîne. Si le paramètre est NULL, la fonction ne fait rien et retourne zéro.

La routine ldap_msgtype() retourne le type d'un message.

La routine ldap_msgid() retourne l'identifiant du message d'un message.

ERREURS

ldap_result() retourne -1 si quelque chose se passe mal, et zéro si le délai spécifié est dépassé. ldap_msgtype() et ldap_msgid() retournent -1 en cas d'erreur.

VOIR AUSSI

ldap(3), ldap_first_message(3), select(2)
