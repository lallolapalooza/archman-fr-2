ldap_dup(3)

Paquet: libldap

Licences: custom

LDAP_OPEN(3) Manuel des fonctions de bibliothèque LDAP_OPEN(3)

NOM

ldap_dup, ldap_destroy, - Dupliquer et détruire les descripteurs de session LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>
LDAP *ldap_dup(
LDAP *old );
int ldap_destroy(
LDAP *old );

DESCRIPTION

ldap_dup() duplique un descripteur de session LDAP (LDAP *) existant. Le nouveau descripteur de session peut être utilisé simultanément avec le descripteur de session d'origine. Dans un environnement multi-threadé, différents threads peuvent exécuter des requêtes simultanées sur la même connexion/session sans crainte de contamination. Chaque descripteur de session gère ses propres résultats d'erreur privés.

ldap_destroy() détruit un descripteur de session existant.

Les fonctions ldap_dup() et ldap_destroy() sont utilisées conjointement avec une version "thread-safe" de libldap pour activer des appels API thread-safe, afin qu'une seule session puisse être utilisée simultanément à travers plusieurs threads avec une gestion cohérente des erreurs.

Lorsqu'une session est créée via l'une des fonctions de création de session, y compris ldap_open(3), ldap_init(3), ldap_initialize(3) ou ldap_init_fd(3), un descripteur de session LDAP * est retourné à l'application. Le descripteur de session peut être partagé entre les threads, mais les codes d'erreur sont uniques à un descripteur de session. Plusieurs threads effectuant différentes opérations en utilisant le même descripteur de session entraîneront des codes d'erreur et des valeurs de retour incohérents.

Pour éviter cette confusion, ldap_dup() est utilisé pour dupliquer un descripteur de session existant afin que plusieurs threads puissent partager la session et maintenir des informations d'erreur et des résultats cohérents.

Les files de messages pour une session sont partagées entre les descripteurs de session frères. Les résultats des opérations sur des descripteurs de session frères sont accessibles à tous les descripteurs de session frères. Les applications souhaitant des résultats associés à une opération spécifique doivent fournir l'identifiant de message approprié à ldap_result(). Les applications doivent éviter d'appeler ldap_result() avec LDAP_RES_ANY car cela pourrait "voler" et retourner des résultats dans le thread appelant dont une autre opération dans un thread différent, utilisant un descripteur de session différent, pourrait avoir besoin pour se terminer.

Lorsque ldap_unbind() est appelé sur un descripteur de session avec des frères, tous les frères deviennent invalides.

Les frères doivent être détruits en utilisant ldap_destroy(). Les ressources du descripteur de session associées à l'original (LDAP *) seront libérées lorsque le dernier descripteur de session sera détruit ou lorsque ldap_unbind() sera appelé, si aucun autre descripteur de session n'existe actuellement.

ERREURS

Si une erreur se produit, ldap_dup() retournera NULL et errno devrait être correctement défini. ldap_destroy() retournera directement le code LDAP associé à l'erreur (ou LDAP_SUCCESS en cas de succès) ; errno devrait également être défini chaque fois que cela est approprié.

VOIR AUSSI

ldap_open(3), ldap_init(3), ldap_initialize(3), ldap_init_fd(3), errno(3)
