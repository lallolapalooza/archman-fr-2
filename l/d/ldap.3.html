LDAP(3) Manuel des fonctions de bibliothèque LDAP(3)

NOM

ldap - API du protocole LDAP (Lightweight Directory Access Protocol)

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>

DESCRIPTION

Le protocole LDAP (Lightweight Directory Access Protocol) (RFC 4510) fournit un accès aux services d'annuaire X.500. Ces services peuvent être autonomes ou faire partie d'un service d'annuaire distribué. Cette API client prend en charge LDAP sur TCP (RFC 4511), LDAP sur TLS/SSL, et LDAP sur IPC (sockets de domaine UNIX). Cette API prend en charge SASL (RFC 4513) et Start TLS (RFC 4513) ainsi qu'un certain nombre d'extensions de protocole. Cette API est vaguement basée sur le projet (orphelin) de spécification de l'API C LDAP de l'IETF/LDAPEXT.

Le paquet logiciel OpenLDAP comprend un serveur autonome dans slapd(8), divers clients LDAP et une bibliothèque client LDAP utilisée pour fournir un accès programmatique au protocole LDAP. Cette page de manuel donne un aperçu des routines de la bibliothèque LDAP.

Les API synchrones et asynchrones sont fournies. Sont également incluses diverses routines pour analyser les résultats retournés par ces routines. Ces routines se trouvent dans la bibliothèque -lldap.

L'interaction de base est la suivante. Un descripteur de session est créé à l'aide de ldap_initialize(3) et la version du protocole est définie sur 3 en appelant ldap_set_option(3). La session sous-jacente est établie lors de la première opération émise. Il s'agirait généralement d'une opération Start TLS ou Bind, ou d'une opération de recherche pour lire les attributs du Root DSE. Une opération Start TLS est effectuée en appelant ldap_start_tls_s(3). Une opération de liaison LDAP est effectuée en appelant ldap_sasl_bind(3) ou l'une de ses fonctions associées. Une opération de recherche est effectuée en appelant ldap_search_ext_s(3) ou l'une de ses fonctions associées.

Par la suite, des opérations supplémentaires sont effectuées en appelant l'une des routines synchrones ou asynchrones (par exemple, ldap_compare_ext_s(3) ou ldap_compare_ext(3) suivi de ldap_result(3)). Les résultats retournés par ces routines sont interprétés en appelant les routines d'analyse LDAP telles que ldap_parse_result(3). L'association LDAP et la connexion sous-jacente sont terminées en appelant ldap_unbind_ext(3). Les erreurs peuvent être interprétées en appelant ldap_err2string(3).

VERSIONS LDAP

Cette bibliothèque prend en charge la version 3 du protocole LDAP (LDAPv3) tel que défini dans la RFC 4510. Elle prend également en charge une variante de la version 2 de LDAP telle que définie par U-Mich LDAP et, dans une certaine mesure, par la RFC 1777. La version 2 (toutes variantes) est considérée comme obsolète. La version 3 doit être utilisée à la place.

Pour des raisons de compatibilité ascendante, la bibliothèque utilise la version 2 par défaut. Par conséquent, toutes les nouvelles applications (et toutes les applications activement maintenues) devraient utiliser ldap_set_option(3) pour sélectionner la version 3. Les pages de manuel de la bibliothèque supposent que la version 3 a été sélectionnée.

PARAMÈTRES D'ENTRÉE et DE SORTIE

Toutes les chaînes de caractères d'entrée/sortie sont censées être/sont encodées en Unicode UTF-8 (version 3.2).

Les noms distinctifs (DN) (et les noms distinctifs relatifs (RDN) à passer aux routines LDAP doivent être conformes à la représentation textuelle UTF-8 de la RFC 4514.

Les filtres de recherche à passer aux routines de recherche doivent être construits manuellement et être conformes à la représentation textuelle UTF-8 de la RFC 4515.

Les URL LDAP à passer aux routines doivent être conformes au format de la RFC 4516. Les routines ldap_url(3) peuvent être utilisées pour manipuler les URL LDAP.

Les contrôles LDAP à passer aux routines peuvent être manipulés à l'aide des routines ldap_controls(3).

AFFICHAGE DES RÉSULTATS

Les résultats obtenus à partir des routines de recherche peuvent être affichés manuellement, en appelant ldap_first_entry(3) et ldap_next_entry(3) pour parcourir les entrées retournées, ldap_first_attribute(3) et ldap_next_attribute(3) pour parcourir les attributs d'une entrée, et ldap_get_values(3) pour récupérer les valeurs d'un attribut donné. Les valeurs d'attribut peuvent ou non être affichables.

ROUTINES UTILITAIRES

Diverses routines utilitaires sont également fournies. Les routines ldap_sort(3) sont utilisées pour trier les entrées et les valeurs retournées via les routines de recherche ldap.

INTERFACES OBSOLÈTES

Un certain nombre d'interfaces sont maintenant considérées comme obsolètes. Par exemple, ldap_add(3) est obsolète au profit de ldap_add_ext(3). Les interfaces obsolètes restent généralement dans la bibliothèque. Le macro LDAP_DEPRECATED peut être défini sur une valeur non nulle (par exemple, -DLDAP_DEPRECATED=1) lors de la compilation d'un programme conçu pour utiliser des interfaces obsolètes. Il est recommandé que les développeurs écrivant de nouveaux programmes, ou mettant à jour de vieux programmes, évitent d'utiliser les interfaces obsolètes. Au fil du temps, il est prévu que la documentation (et, éventuellement, le support) des interfaces obsolètes soit éliminée.

BIBLIOTHÈQUE BER

Est également incluse dans la distribution un ensemble de routines légères de règles d'encodage de base (Basic Encoding Rules - BER). Ces routines sont utilisées par les routines de la bibliothèque LDAP pour encoder et décoder les éléments du protocole LDAP à l'aide des règles d'encodage de base (légèrement simplifiées) définies par LDAP. Elles ne sont normalement pas utilisées directement par un programme d'application LDAP, sauf pour la gestion des contrôles et des opérations étendues. Ces routines sont décrites dans lber-decode(3), lber-encode(3), lber-memory(3), et lber-types(3).
