ldns-dane(1) Manuel des commandes générales ldns-dane(1)

NOM

ldns-dane - vérifier ou créer l'authentification TLS avec DANE (RFC6698)

SYNTAXE

ldns-dane [OPTIONS] vérifier nom port

ldns-dane [OPTIONS] -t fichier_tlsa vérifier

ldns-dane [OPTIONS] créer nom port


[ usage_certificat [ sélecteur [ type_correspondance ] ] ]

ldns-dane -h

ldns-dane -v

DESCRIPTION

Dans la première forme : une connexion TLS est établie avec nom:port. Les enregistrements de ressources TLSA pour nom sont utilisés pour authentifier la connexion.

Dans la deuxième forme : les enregistrements TLSA sont lus depuis fichier_tlsa et utilisés pour authentifier le service TLS auquel ils font référence.

Dans la troisième forme : une connexion TLS est établie avec nom:port et utilisée pour créer les enregistrements de ressources TLSA qui authentifieraient la connexion. Les paramètres pour la création des enregistrements TLSA sont :

usage_certificat :

0 | PKIX-TA
contrainte de l'AC
1 | PKIX-EE
contrainte du certificat de service
2 | DANE-TA
assertion de point d'ancrage de confiance
3 | DANE-EE
certificat émis par le domaine (par défaut)

sélecteur :

0 | Cert
certificat complet
1 | SPKI
SubjectPublicKeyInfo (par défaut)

type_correspondance :

0 | Full
aucun hachage utilisé
1 | SHA2-256
SHA-256 (par défaut)
2 | SHA2-512
SHA-512

OPTIONS

-4
Connexion TLS uniquement en IPv4
-6
Connexion TLS uniquement en IPv6
-a adresse
Ne pas essayer de résoudre nom, mais se connecter à adresse à la place.

Cette option peut être spécifiée plusieurs fois.

-b
imprimer la forme "nom. TYPE52 \# taille données_hex" au lieu du format de présentation TLSA.
-c fichier_cert
Ne pas établir de connexion TLS à nom:port, mais authentifier (ou créer des enregistrements TLSA) pour le certificat (chaîne) dans fichier_cert à la place.
-d
Supposer la validité DNSSEC même lorsque les enregistrements TLSA ont été acquis de manière non sécurisée ou étaient invalides.
-f fichier_AC
Utiliser fichier_AC pour valider.
-h
Afficher l'aide d'utilisation courte
-i
Interagir après la connexion.
-k fichier_clé
Spécifier un fichier contenant un enregistrement DNSKEY ou DS de confiance. Les clés sont utilisées lors du suivi des signatures (c'est-à-dire lorsque -S est donné).

Cette option peut être spécifiée plusieurs fois.

Alternativement, si -k n'est pas spécifié, et qu'un point d'ancrage de confiance par défaut (/etc/trusted-key.key) existe et contient un enregistrement DNSKEY ou DS valide, il sera utilisé comme point d'ancrage de confiance.

-n
Ne **pas** vérifier le nom du serveur dans le certificat.
-o décalage
Lors de la création d'un enregistrement de ressource TLSA "Assertion de point d'ancrage de confiance", sélectionner le décalage-ième décalage de certificat à partir de la fin de la chaîne de validation. 0 signifie le dernier certificat, 1 l'avant-dernier, 2 l'antépénultième, etc.

Lorsque décalage est -1 (par défaut), le dernier certificat est utilisé (comme avec 0) qui DOIT être auto-signé. Cela peut aider à s'assurer que le point d'ancrage de confiance prévu (auto-signé) est effectivement présent dans la chaîne de certificats du serveur (ce qui est une exigence de DANE).

-p chemin_AC
Utiliser les certificats dans le répertoire chemin_AC pour valider.
-s
Lors de la création d'enregistrements TLSA avec l'utilisation de certificat "Contrainte de l'AC" et "Contrainte du certificat de service", ne pas valider et supposer que PKIX est valide.

Pour la "Contrainte de l'AC", cela signifie que la vérification doit se terminer par un certificat auto-signé.

-S
Suivre la ou les signatures jusqu'à une clé connue.

Sans cette option, le réseau local est considéré comme fiable pour fournir un résolveur DNSSEC (c'est-à-dire que le bit AD est vérifié).

-t fichier_tlsa
Lire l'enregistrement TLSA ou les enregistrements TLSA depuis fichier_tlsa. Lorsque nom et port sont également fournis, seuls les enregistrements TLSA qui correspondent au nom, port et transport sont utilisés. Sinon, le nom du propriétaire des enregistrements TLSA sera utilisé pour déterminer le nom, le port et le transport.
-T
Retourner le statut de sortie 2 pour les connexions validées PKIX sans enregistrement(s) TLSA (sécurisé(s)).
-u
Utiliser le transport UDP au lieu de TCP.
-v
Afficher la version et quitter.

FICHIERS

/etc/trusted-key.key
Le fichier à partir duquel les clés de confiance sont chargées pour le suivi des signatures, lorsqu'aucune option -k n'est donnée.
