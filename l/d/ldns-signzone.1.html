ldns-signzone(1) Manuel des commandes générales ldns-signzone(1)

NOM

ldns-signzone - signe un fichier de zone avec des données DNSSEC

SYNTAXE

ldns-signzone [ OPTIONS ] FICHIERZONE CLÉ [CLÉ [CLÉ] ... ]

DESCRIPTION

ldns-signzone est utilisé pour générer une zone signée DNSSEC. Lors de son exécution, il crée un nouveau fichier de zone contenant des enregistrements de ressources RRSIG et NSEC, tels que spécifiés dans les RFC 4033, 4034 et 4035.

Les clés doivent être spécifiées par leur nom de base (c'est-à-dire sans .private). Si le DNSKEY appartenant à la clé dans le fichier .private n'est pas présent dans la zone, il sera lu depuis le fichier <nom de base>.key. Si ce fichier n'existe pas, la valeur DNSKEY sera générée à partir de la clé privée.

Plusieurs clés peuvent être spécifiées. Les clés de signature de zone (Key Signing Keys) sont utilisées comme telles lorsqu'elles sont déjà présentes dans la zone, ou spécifiées dans un fichier .key, et que le bit KSK est activé.

OPTIONS

-b
Augmente la zone et les RR avec des textes de commentaires supplémentaires pour une mise en page plus lisible et plus facile à déboguer. Les enregistrements DS auront une version "bubblebabble" des données dans le texte du commentaire, les enregistrements NSEC3 auront les noms de propriétaires non hachés dans le texte du commentaire.

Sans cette option, seuls les RR DNSKEY auront leur Tag de Clé annoté dans le texte du commentaire.

-d
Normalement, si le RR DNSKEY pour une clé utilisée pour signer la zone n'est pas trouvé dans le fichier de zone, il sera lu depuis le fichier .key, ou dérivé de la clé privée (dans cet ordre). Cette option désactive cette fonctionnalité, de sorte que seules les signatures sont ajoutées à la zone.
-e date
Définit la date d'expiration des signatures à cette date. Le format peut être AAAAAMMJJ[hhmmss] ou un horodatage.
-f fichier
Utilise ce fichier pour stocker la zone signée (par défaut <fichier_original>.signed)
-i date
Définit la date de début des signatures à cette date. Le format peut être AAAAAMMJJ[hhmmss] ou un horodatage.
-o origine
Utilise ceci comme origine de la zone.
-u
Définit le numéro de série SOA au nombre de secondes depuis le 01/01/1970.
-v
Affiche la version et quitte.
-z [schéma:]hash
Calcule le condensat de la zone et les ajoute en tant qu'enregistrements ZONEMD. Le `schéma` (optionnel) doit être `simple` (ou 1) et `hash` doit être `sha384` (ou 1) ou `sha512` (ou 2). Cette option peut être donnée plus d'une fois.
-Z
Permet d'ajouter des ZONEMD sans signature.
-A
Signe l'enregistrement DNSKEY avec toutes les clés. Par défaut, il est signé avec un nombre minimal de clés, pour maintenir la taille de la réponse pour la requête DNSKEY petite, et seules les clés SEP fournies sont utilisées. S'il n'y a pas de clés SEP, le jeu d'enregistrements DNSKEY est signé avec les clés non-SEP. Cette option désactive le comportement par défaut et toutes les clés sont utilisées pour signer le jeu d'enregistrements DNSKEY.
-U
Signe avec chaque algorithme unique parmi les clés fournies. Le jeu DNSKEY est signé avec toutes les clés SEP, plus toutes les clés non-SEP ayant un algorithme qui n'était pas présent dans le jeu de clés SEP.
-E nom
Utilise le moteur cryptographique EVP avec le nom donné pour la signature. Cela peut avoir des options supplémentaires ; voir OPTIONS DES MOTEURS pour plus d'informations.
-K id_algo,id_clé

Utilise la clé `id_clé' comme clé de signature pour l'algorithme `id_algo' en tant que clé de signature de zone (KSK). Cette option est utilisée lorsque vous utilisez un moteur OpenSSL, voir OPTIONS DES MOTEURS pour plus d'informations.

-k id_algo,id_clé
Utilise la clé `id_clé' comme clé de signature pour l'algorithme `id_algo' en tant que clé de signature de zone (ZSK). Cette option est utilisée lorsque vous utilisez un moteur OpenSSL, voir OPTIONS DES MOTEURS pour plus d'informations.
-n
Utilise NSEC3 au lieu de NSEC.
Si vous utilisez NSEC3, vous pouvez spécifier les options supplémentaires suivantes :
-a algorithme
Algorithme utilisé pour créer les noms de propriétaires NSEC3 hachés.
-p
Désactivation (Opt-out). Tous les enregistrements NSEC3 dans la zone auront le drapeau Opt-out activé. Après la signature, vous pouvez ajouter des délégations non sécurisées à la zone signée.
-s chaîne
Sel (Salt).
-t nombre
Nombre d'itérations de hachage.

OPTIONS DES MOTEURS

Vous pouvez modifier les moteurs possibles, s'ils sont supportés, en définissant un fichier de configuration OpenSSL. Ceci est fait via la variable d'environnement OPENSSL_CONF.

Les options de clé (-k et -K) fonctionnent comme suit : vous spécifiez un algorithme DNSSEC (en utilisant son nom symbolique, par exemple, RSASHA256 ou son identifiant numérique, par exemple, 8), suivi d'une virgule et d'un identifiant de clé (les espaces blancs ne sont pas autorisés entre l'algorithme et la virgule, ni entre la virgule et l'identifiant de clé).

L'identifiant de clé peut être l'un des suivants :


<id>
<slot>:<id>
id_<id>
slot_<slot>-id_<id>
label_<label>
slot_<slot>-label_<label>

Où '<id>' est l'identifiant de clé PKCS #11 en notation hexadécimale, '<label>' est le libellé lisible par l'homme PKCS #11, et '<slot>' est le numéro d'emplacement où le jeton est présent.

Les versions plus récentes des moteurs OpenSSL peuvent prendre en charge le schéma URI PKCS #11 (RFC 7512), veuillez consulter la documentation de votre moteur.

Si elle n'est pas déjà présente, un enregistrement DNSKEY est généré à partir des données de la clé et ajouté à la zone.

EXEMPLES

ldns-signzone nlnetlabs.nl Knlnetlabs.nl.+005+12273
Signe la zone dans le fichier 'nlnetlabs.nl' avec la clé dans les fichiers 'Knlnetlabs.nl.+005+12273.private'. Si le DNSKEY n'est pas présent dans la zone, utilise la clé dans le fichier 'Knlnetlabs.nl.+005+12273.key'. Si celui-ci n'est pas présent, en génère un avec les valeurs par défaut à partir de 'Knlnetlabs.nl.+005+12273.private'.

ldns-signzone

ldns-signzone - signer une zone DNS en utilisant des clés DNSSEC

SYNTAXE

ldns-signzone [-aalg<alg>] [-A] [-c <chain_file>] [-d] [-D] [-f <file>] [-g] [-h] [-H <hmac_alg>] [-k] [-K <key_dir>] [-m] [-p] [-P <parent_ds_file>] [-q] [-r] [-s <start_date>] [-S] [-t] [-T <ttl>] [-u] [-V] [-v <verbosity>] [-x] [-z] zone [keyfile ...]

DESCRIPTION

ldns-signzone est un utilitaire pour signer une zone DNS avec des clés DNSSEC. Il prend une zone DNS en entrée et génère une nouvelle zone signée qui inclut les enregistrements RRSIG, DNSKEY et NSEC/NSEC3. L'utilitaire peut utiliser des clés fournies en ligne de commande ou lire des clés à partir d'un répertoire spécifié.

OPTIONS

-a, --algo <alg>
Spécifie l'algorithme de signature à utiliser pour les signatures RRSIG. Les algorithmes disponibles sont RSA/SHA1 (1), RSA/SHA256 (8), RSA/SHA512 (10), ECDSA/P256/SHA256 (13), ECDSA/P384/SHA384 (14), ED25519 (15). La valeur par défaut est 8 (RSA/SHA256).
-A
Signe tous les enregistrements de la zone (par défaut, seuls les enregistrements qui ne sont pas déjà signés le sont).
-c <chain_file>
Spécifie un fichier contenant la chaîne de confiance pour la validation des clés.
-d
Supprime les signatures existantes dans la zone avant de signer.
-D
Supprime les enregistrements de la zone si le fichier de clé spécifié est vide.
-f <file>
Lit la zone à partir du fichier spécifié au lieu de l'entrée standard.
-g
Génère les clés de signature de zone (ZSK) et les clés de signature de clé (KSK).
-h
Affiche un message d'aide et quitte.
-H <hmac_alg>
Spécifie l'algorithme HMAC à utiliser pour les signatures HMAC.
-k
Supprime les enregistrements de clé de signature de zone (ZSK) existants.
-K <key_dir>
Spécifie le répertoire où rechercher les fichiers de clé.
-m
Génère automatiquement les enregistrements DS pour la zone parente.
-p
Affiche les enregistrements DS de la zone parente.
-P <parent_ds_file>
Spécifie un fichier contenant les enregistrements DS de la zone parente.
-q
Mode silencieux, moins d'informations affichées.
-r
Supprime les enregistrements de clés d'échange de clés (KEY) existants.
-s <start_date>
Spécifie la date de début de validité des signatures (format AAMMJJHHMMSS).
-S
Génère les enregistrements NSEC3 au lieu de NSEC.
-t
Supprime les enregistrements RRSIG existants.
-T <ttl>
Définit le TTL (Time To Live) pour les enregistrements générés.
-u
Déballe la zone avant de la signer.
-V
Affiche la version de lns-signzone et quitte.
-v <verbosity>
Définit le niveau de verbosité (0-5).
-x
Supprime les enregistrements de clés de signature de clé (KSK) existants.
-z
Signe les enregistrements ZSK.

OPTIONS MOTEUR

Le moteur de cryptographie sous-jacent peut également être configuré à l'aide d'options spécifiques. Ces options sont généralement passées à l'aide de la variable d'environnement LDNS_ENGINE_OPTIONS ou via des arguments spécifiques à la commande si le moteur le prend en charge.

EXEMPLES

Signer une zone nommée "example.com" avec les clés "Kexample.com.+008+12345.key" et "Kexample.com.+008+12345.private":

ldns-signzone -a8 example.com Kexample.com.+008+12345.key Kexample.com.+008+12345.private

Générer de nouvelles clés KSK et ZSK pour la zone "example.com" et les signer:

ldns-signzone -g example.com

Signer la zone "example.com" en utilisant le répertoire de clés "/etc/ldns/keys":

ldns-signzone -K /etc/ldns/keys example.com
