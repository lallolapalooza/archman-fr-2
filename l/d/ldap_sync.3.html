LDAP_SYNC(3) Manuel des fonctions de bibliothèque LDAP_SYNC(3)

NOM

ldap_sync_init, ldap_sync_init_refresh_only, ldap_sync_init_refresh_and_persist, ldap_sync_poll - Routines de synchronisation LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>
int ldap_sync_init(ldap_sync_t *ls, int mode);
int ldap_sync_init_refresh_only(ldap_sync_t *ls);
int ldap_sync_init_refresh_and_persist(ldap_sync_t *ls);
int ldap_sync_poll(ldap_sync_t *ls);
ldap_sync_t * ldap_sync_initialize(ldap_sync_t *ls);
void ldap_sync_destroy(ldap_sync_t *ls, int freeit);
typedef int (*ldap_sync_search_entry_f)(ldap_sync_t *ls,
LDAPMessage *msg, struct berval *entryUUID,
ldap_sync_refresh_t phase);
typedef int (*ldap_sync_search_reference_f)(ldap_sync_t *ls,
LDAPMessage *msg);
typedef int (*ldap_sync_intermediate_f)(ldap_sync_t *ls,
LDAPMessage *msg, BerVarray syncUUIDs,
ldap_sync_refresh_t phase);
typedef int (*ldap_sync_search_result_f)(ldap_sync_t *ls,
LDAPMessage *msg, int refreshDeletes);

DESCRIPTION

Ces routines fournissent une interface pour l'opération de synchronisation de contenu LDAP (RFC 4533). Elles nécessitent qu'une structure ldap_sync_t soit configurée avec les paramètres requis pour les différentes phases de l'opération ; cela inclut la définition de certains gestionnaires pour les événements spéciaux. Tous les gestionnaires prennent un pointeur vers la structure ldap_sync_t comme premier argument, et un pointeur vers la structure LDAPMessage telle que reçue du serveur par la bibliothèque client, plus, occasionnellement, d'autres arguments spécifiques.

Les membres de la structure ldap_sync_t sont :

char *ls_base
La base de recherche ; par défaut, l'option BASE dans ldap.conf(5).
int ls_scope
La portée de la recherche (l'une des valeurs : LDAP_SCOPE_BASE, LDAP_SCOPE_ONELEVEL, LDAP_SCOPE_SUBORDINATE ou LDAP_SCOPE_SUBTREE ; voir ldap.h pour les détails).
char *ls_filter
Le filtre (RFC 4515) ; par défaut, (objectClass=*).
char **ls_attrs
Les attributs demandés ; par défaut NULL, indiquant tous les attributs utilisateur.
int ls_timelimit
La limite de temps demandée (en secondes) ; par défaut 0, pour indiquer aucune limite.
int ls_sizelimit
La limite de taille demandée (en entrées) ; par défaut 0, pour indiquer aucune limite.
int ls_timeout
Le délai d'attente souhaité lors de l'interrogation avec ldap_sync_poll(3). Une valeur de -1 signifie que l'interrogation est bloquante, donc ldap_sync_poll(3) ne retournera pas avant qu'un message soit reçu ; une valeur de 0 signifie que l'interrogation retourne immédiatement, qu'une réponse soit disponible ou non ; une valeur positive représente le délai d'attente pendant lequel la fonction ldap_sync_poll(3) attendra une réponse avant de retourner, à moins qu'un message ne soit reçu ; dans ce cas, ldap_sync_poll(3) retourne dès que le message est disponible.
ldap_sync_search_entry_f ls_search_entry
Une fonction qui est appelée chaque fois qu'une entrée est retournée. L'argument msg est le LDAPMessage qui contient le searchResultEntry ; il peut être analysé en utilisant les routines API client régulières, comme ldap_get_dn(3), ldap_first_attribute(3), et ainsi de suite. L'argument entryUUID contient l'entryUUID de l'entrée. L'argument phase indique le type d'opération : l'une des valeurs LDAP_SYNC_CAPI_PRESENT, LDAP_SYNC_CAPI_ADD, LDAP_SYNC_CAPI_MODIFY, LDAP_SYNC_CAPI_DELETE ; dans le cas de LDAP_SYNC_CAPI_PRESENT ou LDAP_SYNC_CAPI_DELETE, seule la DN est contenue dans le LDAPMessage ; dans le cas de LDAP_SYNC_CAPI_MODIFY, l'entrée entière est contenue dans le LDAPMessage, et l'application est responsable de déterminer les différences entre la nouvelle vue de l'entrée fournie par l'appelant et les données déjà connues.
ldap_sync_search_reference_f ls_search_reference
Une fonction qui est appelée chaque fois qu'une référence de recherche est retournée. L'argument msg est le LDAPMessage qui contient le searchResultReference ; il peut être analysé en utilisant les routines API client régulières, comme ldap_parse_reference(3).
ldap_sync_intermediate_f ls_intermediate
Une fonction qui est appelée chaque fois que quelque chose de pertinent se produit pendant la phase de rafraîchissement de la recherche, marquée par un type de message intermediateResponse. L'argument msg est le LDAPMessage qui contient la réponse intermédiaire ; il peut être analysé en utilisant les routines API client régulières, comme ldap_parse_intermediate(3). L'argument syncUUIDs contient un tableau d'UUID des entrées qui dépend de la valeur de l'argument phase. Dans le cas de LDAP_SYNC_CAPI_PRESENTS, la phase "present" est entrée ; cela signifie que la séquence suivante de résultats consistera en des entrées dans l'état de synchronisation "present". Dans le cas de LDAP_SYNC_CAPI_DELETES, la phase "deletes" est entrée ; cela signifie que la séquence suivante de résultats consistera en des entrées dans l'état de synchronisation "delete". Dans le cas de LDAP_SYNC_CAPI_PRESENTS_IDSET, le message contient un ensemble d'UUID des entrées qui sont présentes ; il remplace une phase "presents". Dans le cas de LDAP_SYNC_CAPI_DELETES_IDSET, le message contient un ensemble d'UUID des entrées qui ont été supprimées ; il remplace une phase "deletes". Dans le cas de LDAP_SYNC_CAPI_DONE, une phase "presents" avec "refreshDone" réglé sur "TRUE" a été retournée pour indiquer que la phase de rafraîchissement de refreshAndPersist est terminée, et que le client doit commencer l'interrogation. À l'exception des cas LDAP_SYNC_CAPI_PRESENTS_IDSET et LDAP_SYNC_CAPI_DELETES_IDSET, syncUUIDs est NULL.
ldap_sync_search_result_f ls_search_result
Une fonction qui est appelée chaque fois qu'un searchResultDone est retourné. Dans refreshAndPersist, cela ne peut se produire que lorsque le serveur décide que la recherche doit être interrompue. L'argument msg est le LDAPMessage qui contient la réponse ; il peut être analysé en utilisant les routines API client régulières, comme ldap_parse_result(3). L'argument refreshDeletes n'est pas pertinent dans ce cas ; il doit toujours être -1.
void *ls_private
Un pointeur vers des données privées. Le client peut y enregistrer un pointeur vers des données dont les gestionnaires ci-dessus pourraient avoir besoin.
LDAP *ls_ld
Un pointeur vers une structure LDAP utilisée pour se connecter au serveur. Il incombe au client d'initialiser la structure et de fournir une authentification et une sécurité appropriées.

NOM

ldap_sync_init, ldap_sync_init_refresh_only, ldap_sync_init_refresh_and_persist, ldap_sync_destroy, ldap_sync_poll - Interface de synchronisation LDAP

BIBLIOTHÈQUE

Bibliothèque de développement LDAP (libldap, -lldap).

SYNTAXE

#include <ldap.h>

int ldap_sync_init( LDAP *ld, int mode, LDAPSyncUpdate **updp, LDAPSyncCtl **ctlp );

int ldap_sync_init_refresh_only( LDAP *ld, LDAPSyncUpdate *upd, LDAPSyncCtl *ctl );

int ldap_sync_init_refresh_and_persist( LDAP *ld, LDAPSyncUpdate *upd, LDAPSyncCtl *ctl );

int ldap_sync_destroy( LDAPSyncUpdate *upd );

int ldap_sync_poll( LDAP *ld, LDAPSyncUpdate *upd, LDAPControl **ctrls );

DESCRIPTION

Ces routines fournissent une interface pour le protocole de synchronisation LDAP, décrit dans RFC 4533.

La fonction ldap_sync_init() est la routine générique pour initialiser une session de synchronisation. Le paramètre mode spécifie la fonctionnalité de synchronisation demandée. Les modes valides sont LDAP_SYNC_REFRESH_ONLY et LDAP_SYNC_REFRESH_AND_PERSIST. Les paramètres updp et ctlp sont des pointeurs vers les structures LDAPSyncUpdate et LDAPSyncCtl, respectivement. Si le paramètre est NULL, une nouvelle structure est allouée et retournée. Sinon, la structure existante est utilisée.

Les routines ldap_sync_init_refresh_only() et ldap_sync_init_refresh_and_persist() sont des fonctions d'aide qui correspondent à des appels à ldap_sync_init() avec le mode approprié.

La fonction ldap_sync_destroy() nettoie et libère la mémoire allouée pour la structure LDAPSyncUpdate. Elle doit être appelée à la fin de la session de synchronisation.

La fonction ldap_sync_poll() est utilisée pour interroger le serveur pour les mises à jour synchronisées. Le paramètre ctrls peut être utilisé pour passer des contrôles LDAP supplémentaires.

UTILISATION GÉNÉRALE

L'interface de synchronisation LDAP est conçue pour fonctionner avec les contrôles de synchronisation LDAP. La structure ldap_sync_t est utilisée pour maintenir l'état de la session de synchronisation.

La routine ldap_sync_init() est utilisée pour remplir une structure ldap_sync_t existante, et définit des valeurs appropriées pour certains membres. Après cela, l'appelant est responsable de la mise en place de la connexion (membre ls_ld), de la mise en place éventuelle de la sécurité des transports (TLS), de la liaison et de toute autre initialisation. L'appelant doit également remplir tous les champs documentés liés à la recherche de la structure ldap_sync_t.

À la fin d'une session, la structure peut être nettoyée en appelant ldap_sync_destroy(3), qui prend en charge la libération de toutes les données en supposant qu'elles ont été allouées par les routines ldap_mem*(3). Sinon, l'appelant doit prendre soin de détruire et de mettre à zéro les champs documentés liés à la recherche, et d'appeler ldap_sync_destroy(3) pour libérer les membres non documentés définis par l'API.

REFRESH ONLY

La fonctionnalité refreshOnly est obtenue en appelant périodiquement ldap_sync_init(3) avec le mode défini sur LDAP_SYNC_REFRESH_ONLY, ou, ce qui est équivalent, en appelant directement ldap_sync_init_refresh_only(3). L'état de la recherche, et la cohérence des paramètres de recherche, sont préservés d'un appel à l'autre en passant la structure ldap_sync_t telle qu'elle a été laissée par l'appel précédent.

REFRESH AND PERSIST

La fonctionnalité refreshAndPersist est obtenue en appelant ldap_sync_init(3) avec le mode défini sur LDAP_SYNC_REFRESH_AND_PERSIST, ou, ce qui est équivalent, en appelant directement ldap_sync_init_refresh_and_persist(3) et, après un retour réussi, en interrogeant de manière répétée avec ldap_sync_poll(3) selon le modèle souhaité.

Un client peut insérer un appel à ldap_sync_poll(3) dans une boucle externe pour vérifier si des modifications ont été retournées; dans ce cas, il peut être approprié de définir ls_timeout sur 0, ou de le définir sur une valeur finie et petite. Sinon, si le but principal du client consiste à attendre des réponses, un délai d'attente de -1 est le plus approprié, de sorte que la fonction ne retourne qu'après que des données ont été reçues et traitées.

ERREURS

Toutes les routines retournent toute erreur LDAP résultant d'une erreur de niveau inférieur dans les appels d'API sur lesquels elles sont basées, ou LDAP_SUCCESS en cas de succès. ldap_sync_poll(3) peut retourner LDAP_SYNC_REFRESH_REQUIRED si un rafraîchissement complet est demandé par le serveur. Dans ce cas, il est approprié d'appeler à nouveau ldap_sync_init(3), en passant la même structure ldap_sync_t qu'en résultant de tout appel précédent.
