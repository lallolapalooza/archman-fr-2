LDAPSEARCH(1) Manuel des commandes générales LDAPSEARCH(1)

NOM

ldapsearch - outil de recherche LDAP

SYNTAXE

ldapsearch [-V[V]] [-d niveau_debug] [-n] [-v] [-c] [-u] [-t[t]] [-T chemin] [-F préfixe] [-A] [-L[L[L]]] [-S attribut] [-b base_de_recherche] [-s {base|one|sub|children}] [-a {never|always|search|find}] [-l limite_temps] [-z limite_taille] [-f fichier] [-M[M]] [-x] [-D dn_liaison] [-W] [-w motdepasse] [-y fichmotdepasse] [-H ldapuri] [-P {2|3}] [-e [!]ext[=param_ext]] [-E [!]ext[=param_ext]] [-o opt[=param_opt]] [-O propriétés-sécurité] [-I] [-Q] [-N] [-U cid_auth] [-R domaine] [-X zid_auth] [-Y mécanisme] [-Z[Z]] filtre [attrs...]

DESCRIPTION

ldapsearch est une interface accessible par shell pour l'appel de bibliothèque ldap_search_ext(3).

ldapsearch ouvre une connexion à un serveur LDAP, se lie (bind) et effectue une recherche en utilisant les paramètres spécifiés. Le filtre doit être conforme à la représentation textuelle des filtres de recherche telle que définie dans la RFC 4515. S'il n'est pas fourni, le filtre par défaut, (objectClass=*), est utilisé.

Si ldapsearch trouve une ou plusieurs entrées, les attributs spécifiés par attrs sont retournés. Si * est listé, tous les attributs utilisateur sont retournés. Si + est listé, tous les attributs opérationnels sont retournés. Si aucun attrs n'est listé, tous les attributs utilisateur sont retournés. Si seul 1.1 est listé, aucun attribut ne sera retourné.

Les résultats de la recherche sont affichés en utilisant une version étendue de LDIF. L'option -L contrôle le format de la sortie.

OPTIONS

-V[V]
Affiche les informations de version. Si -VV est donné, quitte après avoir fourni les informations de version. Sinon, continue avec la recherche spécifiée.
-d niveau_debug
Définit le niveau de débogage LDAP à niveau_debug. ldapsearch doit être compilé avec LDAP_DEBUG défini pour que cette option ait un effet quelconque.
-n
Indique ce qui serait fait, mais sans effectuer réellement la recherche. Utile pour le débogage en conjonction avec -v.
-v
Exécute en mode verbeux, avec de nombreux diagnostics écrits sur la sortie standard.
-c
Mode d'opération continu. Les erreurs sont signalées, mais ldapsearch continuera les recherches. Par défaut, il quitte après avoir signalé une erreur. Utile uniquement en conjonction avec -f.
-u
Inclut la forme Nom Convivial (User Friendly Name) du Nom Distingué (DN) dans la sortie.
-t[t]
Un seul -t écrit les valeurs non imprimables récupérées dans un ensemble de fichiers temporaires. C'est utile pour traiter les valeurs contenant des données non textuelles telles que jpegPhoto ou audio. Un deuxième -t écrit toutes les valeurs récupérées dans des fichiers.
-T chemin
Écrit les fichiers temporaires dans le répertoire spécifié par chemin (par défaut : répertoire temporaire par défaut du système). Les variables d'environnement TMPDIR, TMP ou TEMP remplaceront le chemin par défaut.
-F préfixe
Préfixe d'URL pour les fichiers temporaires. Par défaut, c'est file://chemin, où chemin est le répertoire temporaire par défaut du système ou la valeur spécifiée avec -T.
-A
Récupère uniquement les attributs (pas les valeurs). Ceci est utile lorsque vous voulez simplement voir si un attribut est présent dans une entrée et que vous ne vous intéressez pas aux valeurs spécifiques.
-L
Les résultats de la recherche sont affichés au format LDIF (LDAP Data Interchange Format) détaillé dans ldif(5). Un seul -L limite la sortie à LDIFv1.
Un deuxième -L désactive les commentaires. Un troisième -L désactive l'affichage de la version LDIF. Par défaut, une version étendue de LDIF est utilisée.
-S attribut
Trie les entrées retournées en fonction de l'attribut. Par défaut, les entrées retournées ne sont pas triées. Si attribut est une chaîne vide (""), les entrées sont triées par les composants de leur Nom Distingué. Voir ldap_sort(3) pour plus de détails. Notez que ldapsearch affiche normalement les entrées au fur et à mesure de leur réception. L'utilisation de l'option -S annule ce comportement, provoquant la récupération de toutes les entrées, puis leur tri, puis leur affichage.
-b base_de_recherche
Utilise base_de_recherche comme point de départ pour la recherche au lieu de la valeur par défaut.
-s {base|one|sub|children}
Spécifie la portée de la recherche comme étant l'une des valeurs : base, one, sub, ou children pour spécifier un objet de base, un niveau, un sous-arbre, ou une recherche des enfants. Par défaut, c'est sub. Note : la portée children nécessite l'extension de fonctionnalité subordonnée LDAPv3.
-a {never|always|search|find}
Spécifie comment les alias sont déréférencés. Doit être l'une des valeurs : never, always, search, ou find pour spécifier que les alias ne sont jamais déréférencés, toujours déréférencés, déréférencés lors de la recherche, ou déréférencés uniquement lors de la localisation de l'objet de base pour la recherche. Par défaut, les alias ne sont jamais déréférencés.
-l limite_temps
Attend au maximum limite_temps secondes pour qu'une recherche se termine. Une limite de temps de 0 (zéro) ou none signifie aucune limite. Une limite de temps de max signifie l'entier maximum autorisé par le protocole. Un serveur peut imposer une limite de temps maximale que seul l'utilisateur root peut outrepasser.
-z limite_taille
Récupère au maximum limite_taille entrées pour une recherche. Une limite de taille de 0 (zéro) ou none signifie aucune limite. Une limite de taille de max signifie l'entier maximum autorisé par le protocole. Un serveur peut imposer une limite de taille maximale que seul l'utilisateur root peut outrepasser.
-f fichier
Lit une série de lignes depuis fichier, effectuant une recherche LDAP pour chaque ligne. Dans ce cas, le filtre donné sur la ligne de commande est traité comme un modèle où la première et unique occurrence de %s est remplacée par une ligne de fichier. Toute autre occurrence du caractère % dans le modèle sera considérée comme une erreur. Lorsque vous souhaitez que le filtre de recherche inclue un caractère %, ce caractère doit être encodé en \25 (voir RFC 4515). Si fichier est un seul caractère -, alors les lignes sont lues depuis l'entrée standard. ldapsearch quittera lors de la première résultat de recherche non réussi retourné, sauf si -c est utilisé.
-M[M]
Active le contrôle "manage DSA IT". -MM rend le contrôle critique.
-x
Utilise l'authentification simple au lieu de SASL.
-D dn_liaison
Utilise le Nom Distingué dn_liaison pour se lier à l'annuaire LDAP. Pour les liaisons SASL, le serveur est censé ignorer cette valeur.
-W
Demande le mot de passe pour l'authentification simple. Ceci est utilisé au lieu de spécifier le mot de passe sur la ligne de commande.
-w motdepasse
Utilise motdepasse comme

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

-y passwdfile
Utilise le contenu complet de passwdfile comme mot de passe pour l'authentification simple.
-H ldapuri
Spécifie l'URI (ou les URI) faisant référence au(x) serveur(s) LDAP ; une liste d'URI, séparées par des espaces ou des virgules, est attendue ; seuls les champs protocole/hôte/port sont autorisés. À titre d'exception, si aucun hôte/port n'est spécifié, mais qu'un DN l'est, le DN est utilisé pour rechercher les hôtes correspondants à l'aide des enregistrements DNS SRV, conformément à la RFC 2782. Le DN doit être une séquence non vide d'AVA dont le type d'attribut est « dc » (composant de domaine) et doit être échappé conformément à la RFC 2396.
-P {2|3}
Spécifie la version du protocole LDAP à utiliser.
-e [!]ext[=extparam]
-E [!]ext[=extparam]

Spécifie les extensions générales avec -e et les extensions de recherche avec -E. « ! » indique la criticité.

Extensions générales :

  [!]assert=<filtre>    (un filtre RFC 4515)
  !authzid=<authzid>    (« dn:<dn> » ou « u:<utilisateur> »)
  [!]bauthzid           (contrôle RFC 3829 authzid)
  [!]chaining[=<résoudre>[/<cont>]]
  [!]manageDSAit
  [!]noop
  ppolicy
  [!]postread[=<attrs>] (une liste d'attributs séparés par des virgules)
  [!]preread[=<attrs>]  (une liste d'attributs séparés par des virgules)
  [!]relax
  sessiontracking[=<nomutilisateur>]
  abandon,cancel,ignore (SIGINT envoie abandon/cancel,
  ou ignore la réponse ; si critique, n'attend pas SIGINT.
  pas vraiment des contrôles)

Extensions de recherche :

  !dontUseCopy
  [!]domainScope                       (portée du domaine)
  [!]mv=<filtre>                       (filtre sur les valeurs correspondantes)
  [!]pr=<taille>[/prompt|noprompt]       (résultats paginés/demande)
  [!]sss=[-]<attr[:OID]>[/[-]<attr[:OID]>...]  (tri côté serveur)
  [!]subentries[=true|false]           (sous-entrées)
  [!]sync=ro[/<cookie>]                (synchronisation LDAP refreshOnly)
          rp[/<cookie>][/<slimit>]     (synchronisation LDAP refreshAndPersist)
  [!]vlv=<avant>/<après>(/<décalage>/<nombre>|:<valeur>)  (vue de liste virtuelle)
  [!]deref=derefAttr:attr[,attr[...]][;derefAttr:attr[,attr[...]]]
  [!]<oid>[=:<valeur>|::<valeurbase64>]
-o opt[=optparam]

Spécifie une option quelconque de ldap.conf(5) ou l'une des suivantes :

  nettimeout=<délai>  (en secondes, ou « none » ou « max »)
  ldif_wrap=<largeur>     (en colonnes, ou « no » pour pas de retour à la ligne)
-O propriétés-sécurité
Spécifie les propriétés de sécurité SASL.
-I
Active le mode interactif SASL. Demande toujours. Par défaut, ne demande que si nécessaire.
-Q
Active le mode silencieux SASL. Ne demande jamais.
-N
N'utilise pas la résolution DNS inversée pour canoniser le nom d'hôte SASL.
-U authcid
Spécifie l'identifiant d'authentification pour le bind SASL. La forme de l'identifiant dépend du mécanisme SASL réellement utilisé.
-R realm
Spécifie le realm de l'identifiant d'authentification pour le bind SASL. La forme du realm dépend du mécanisme SASL réellement utilisé.
-X authzid
Spécifie l'identifiant d'autorisation demandé pour le bind SASL. authzid doit être dans l'un des formats suivants : dn:<nom distingué> ou u:<nom d'utilisateur>
-Y mech
Spécifie le mécanisme SASL à utiliser pour l'authentification. S'il n'est pas spécifié, le programme choisira le meilleur mécanisme connu du serveur.
-Z[Z]
Émet l'opération étendue StartTLS (Transport Layer Security). Si vous utilisez -ZZ, la commande exigera que l'opération réussisse.

FORMAT DE SORTIE

Si une ou plusieurs entrées sont trouvées, chaque entrée est écrite sur la sortie standard au format LDAP Data Interchange Format ou ldif(5) :

    version: 1
    # bjensen, example, net
    dn: uid=bjensen,dc=example,dc=net
    objectClass: person
    objectClass: dcObject
    uid: bjensen
    cn: Barbara Jensen
    sn: Jensen
    ...

Si l'option -t est utilisée, l'URI d'un fichier temporaire est utilisé à la place de la valeur réelle. Si l'option -A est donnée, seule la partie « nomattribut » est écrite.

EXEMPLE

La commande suivante :

    ldapsearch -LLL "(sn=smith)" cn sn telephoneNumber

effectuera une recherche dans l'arborescence (en utilisant la base de recherche par défaut et d'autres paramètres définis dans ldap.conf(5)) pour les entrées dont le nom de famille (sn) est smith. Le nom commun (cn), le nom de famille (sn) et le numéro de téléphone (telephoneNumber) seront récupérés et imprimés sur la sortie standard. La sortie pourrait ressembler à ceci si deux entrées sont trouvées :

    dn: uid=jts,dc=example,dc=com
    cn: John Smith
    cn: John T. Smith
    sn: Smith
    sn;lang-en: Smith
    sn;lang-de: Schmidt
    telephoneNumber: 1 555 123-4567
    dn: uid=sss,dc=example,dc=com
    cn: Steve Smith
    cn: Steve S. Smith
    sn: Smith
    sn;lang-en: Smith
    sn;lang-de: Schmidt
    telephoneNumber: 1 555 765-4321

La commande :

    ldapsearch -LLL -u -t "(uid=xyz)" jpegPhoto audio

effectuera une recherche dans l'arborescence en utilisant la base de recherche par défaut pour les entrées dont l'identifiant utilisateur (uid) est « xyz ». La forme conviviale du DN de l'entrée sera affichée après la ligne contenant le DN lui-même, et les valeurs jpegPhoto et audio seront récupérées et écrites dans des fichiers temporaires. La sortie pourrait ressembler à ceci si une entrée avec une valeur pour chacun des attributs demandés est trouvée :

    dn: uid=xyz,dc=example,dc=com
    ufn: xyz, example, com
    audio:< file:///tmp/ldapsearch-audio-a19924
    jpegPhoto:< file:///tmp/ldapsearch-jpegPhoto-a19924

Cette commande :

    ldapsearch -LLL -s one -b "c=US" "(o=University*)" o description

effectuera une recherche sur un seul niveau à la base c=US pour toutes les entrées dont le nom d'organisation (o) commence par University. Le nom d'organisation et les valeurs de l'attribut de description seront récupérés et imprimés sur la sortie standard, produisant une sortie similaire à celle-ci :

    dn: o=University of Alaska Fairbanks,c=US
    o: University of Alaska Fairbanks
    description: Naturally Inspiring
    description: leaf node only
    dn: o=University of Colorado at Boulder,c=US
    o: University of Colorado at Boulder
    description: No personnel information
    description: Institution of education and research
    dn: o=University of Colorado at Denver,c=US
    o: University of Colorado at Denver
    o: UCD
    o: CU/Denver
    o: CU-Denver
    description: Institute for Higher Learning and Research
    dn: o=University of Florida,c=US
    o: University of Florida
    o: UFl
    description: Warper of young minds
    ...

DIAGNOSTICS

Le code de sortie est zéro si aucune erreur ne se produit. Les erreurs entraînent un code de sortie non nul et l'écriture d'un message de diagnostic sur la sortie d'erreur standard.
