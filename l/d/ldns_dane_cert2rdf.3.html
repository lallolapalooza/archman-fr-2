NOM

ldns_dane_create_tlsa_rr, ldns_dane_create_tlsa_owner, ldns_dane_cert2rdf, ldns_dane_select_certificate - Fonctions de création d'enregistrement TLSA

SYNTAXE

#include <stdint.h>
#include <stdbool.h>

#include <ldns/ldns.h>

ldns_status ldns_dane_create_tlsa_rr(ldns_rr** tlsa, ldns_tlsa_certificate_usage certificate_usage, ldns_tlsa_selector selector, ldns_tlsa_matching_type matching_type, X509* cert);

ldns_status ldns_dane_create_tlsa_owner(ldns_rdf** tlsa_owner, const ldns_rdf* name, uint16_t port, ldns_dane_transport transport);

ldns_status ldns_dane_cert2rdf(ldns_rdf** rdf, X509* cert, ldns_tlsa_selector selector, ldns_tlsa_matching_type matching_type);

ldns_status ldns_dane_select_certificate(X509** selected_cert, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store, ldns_tlsa_certificate_usage cert_usage, int index);

DESCRIPTION

ldns_dane_create_tlsa_rr() Crée un enregistrement de ressource TLSA à partir du certificat. Aucune validation PKIX n'est effectuée ! Le certificat donné est utilisé comme données, quelle que soit la valeur de certificate_usage.

tlsa : L'enregistrement de ressource TLSA créé.
certificate_usage : La valeur pour le champ Utilisation du certificat
selector : La valeur pour le champ Sélecteur
matching_type : La valeur pour le type de correspondance
cert : Le certificat dont les données seront représentées

Retourne LDNS_STATUS_OK en cas de succès ou un code d'erreur sinon.

ldns_dane_create_tlsa_owner() Crée un nom de domaine (dname) composé du nom donné, préfixé par le port de service et le type de transport : _<EM>port</EM>._<EM>transport</EM>.<EM>nom</EM>.

tlsa_owner : Le nom de domaine créé.
name : Le nom de domaine qui doit être préfixé.
port : Le numéro de port de service pour lequel le nom doit être créé.
transport : Le transport pour lequel le nom doit être créé.
Retourne LDNS_STATUS_OK en cas de succès ou un code d'erreur sinon.

ldns_dane_cert2rdf() Crée un RDF de type LDNS_RDF_TYPE_HEX basé sur les données binaires choisies par le sélecteur et encodées à l'aide du type de correspondance.

rdf : Le RDF créé de type LDNS_RDF_TYPE_HEX.
cert : Le certificat à partir duquel les données sont sélectionnées
selector : Le certificat complet ou la clé publique
matching_type : Les données complètes ou le hachage SHA256 ou SHA512 des données sélectionnées
Retourne LDNS_STATUS_OK en cas de succès ou un code d'erreur sinon.

ldns_dane_select_certificate() Sélectionne le certificat parmi cert, extra_certs ou pkix_validation_store en fonction de la valeur de cert_usage et de l'index.

selected_cert : Le certificat sélectionné.
cert : Le certificat à valider (ou non)
extra_certs : Certificats intermédiaires qui pourraient être nécessaires pendant la validation. Peut être NULL, sauf lorsque l'utilisation du certificat est "Assertion d'ancre de confiance" car l'ancre de confiance doit être fournie. (sinon choisissez un "Certificat émis par le domaine !"
pkix_validation_store : Utilisé lorsque l'utilisation du certificat est "Contrainte CA" ou "Contrainte de certificat de service" pour valider le certificat et, dans le cas de "Contrainte CA", sélectionner la CA. Lorsque pkix_validation_store est NULL, la validation est explicitement désactivée et le comportement est alors le même que pour "Assertion d'ancre de confiance" et "Certificat émis par le domaine" respectivement.
cert_usage : Quel certificat utiliser et comment valider.
index : Utilisé pour sélectionner l'ancre de confiance lorsque l'utilisation du certificat est "Assertion d'ancre de confiance". 0 est le dernier certificat de la chaîne de validation. 1 l'avant-dernier, etc. Lorsque l'index est -1, le dernier certificat est utilisé et il DOIT être auto-signé. Cela peut aider à garantir que l'ancre de confiance auto-signée prévue est bien présente dans extra_certs (ce qui est une exigence DANE).
Retourne LDNS_STATUS_OK en cas de succès ou un code d'erreur sinon.
