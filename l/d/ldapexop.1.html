LDAPEXOP(1) Manuel des commandes générales LDAPEXOP(1)

NOM

ldapexop - émettre des opérations étendues LDAP

SYNTAXE

ldapexop [-V[V]] [-d niveau_debug] [-n] [-v] [-f fichier] [-x] [-D dn_liaison] [-W] [-w motdepasse] [-y fichier_motdepasse] [-H URI] [-e [!]ext[=param_ext]] [-o opt[=param_opt]] [-O propriétés-sécurité] [-I] [-Q] [-N] [-U id_authentification] [-R domaine] [-X authzid] [-Y mécanisme] [-Z[Z]] {oid | oid:données | oid::données_b64 | whoami | cancel id_annulation | refresh DN [ttl]}

DESCRIPTION

ldapexop émet l'opération étendue LDAP spécifiée par oid ou par l'un des mots-clés spéciaux whoami, cancel ou refresh.

Des données supplémentaires pour l'opération étendue peuvent être transmises au serveur en utilisant données ou des données encodées en base64 comme données_b64 dans le cas de oid, ou en utilisant les paramètres supplémentaires dans le cas des opérations étendues nommées spécialement ci-dessus.

Veuillez noter que ldapexop se comporte différemment pour la même opération étendue lorsqu'elle est donnée sous forme d'OID ou de nommage spécialisé :

Appeler ldapexop avec l'OID de l'opération étendue whoami (RFC 4532)

  ldapexop [<options>] 1.3.6.1.4.1.4203.1.11.3
donne 
  # extended operation response
  data:: <base64 encoded response data>
tout en appelant avec le mot-clé whoami 
  ldapexop [<options>] whoami
résulte en 
  dn:<client's identity>

OPTIONS

-V[V]
Afficher les informations de version. Si -VV est donné, seules les informations de version sont affichées.
-d niveau_debug
Définir le niveau de débogage LDAP à niveau_debug.
-n
Montrer ce qui serait fait mais ne pas le faire réellement. Utile pour le débogage en conjonction avec -v.
-v
Exécuter en mode verbeux, avec de nombreux diagnostics écrits sur la sortie standard.
-f fichier
Lire les opérations depuis fichier.
-x
Utiliser l'authentification simple au lieu de SASL.
-D dn_liaison
Utiliser le Distinguished Name dn_liaison pour se lier au répertoire LDAP.
-W
Demander le mot de passe pour l'authentification simple. Ceci est utilisé à la place de la spécification du mot de passe sur la ligne de commande.
-w motdepasse
Utiliser motdepasse comme mot de passe pour l'authentification simple.
-y fichier_motdepasse
Utiliser le contenu complet de fichier_motdepasse comme mot de passe pour l'authentification simple.
-H URI
Spécifier la ou les URI(s) faisant référence au(x) serveur(s) LDAP ; seuls les champs protocole/hôte/port sont autorisés ; une liste d'URI, séparées par des espaces ou des virgules est attendue.
-e [!]ext[=param_ext]
Spécifier des extensions générales. ´!´ indique la criticité. 
  [!]assert=<filtre>    (un filtre RFC 4515)
  !authzid=<authzid>    ("dn:<dn>" ou "u:<utilisateur>")
  [!]bauthzid           (contrôle authzid RFC 3829)
  [!]chaining[=<resolve>[/<cont>]]
  [!]manageDSAit
  [!]noop
  ppolicy
  [!]postread[=<attributs>] (une liste d'attributs séparés par des virgules)
  [!]preread[=<attributs>]  (une liste d'attributs séparés par des virgules)
  [!]relax
  sessiontracking[=<nom_utilisateur>]
  abandon,cancel,ignore (SIGINT envoie abandon/cancel,
  ou ignore la réponse ; si critique, n'attend pas SIGINT.
  pas vraiment des contrôles)
-o opt[=param_opt]

Spécifier toute option de ldap.conf(5) ou l'une des suivantes :

  nettimeout=<timeout>  (en secondes, ou "none" ou "max")
  ldif_wrap=<largeur>     (en colonnes, ou "no" pour pas de retour à la ligne)
-O propriétés-sécurité
Spécifier les propriétés de sécurité SASL.
-I
Activer le mode interactif SASL. Demander toujours. Par défaut, ne demander que si nécessaire.
-Q
Activer le mode silencieux SASL. Ne jamais demander.
-N
Ne pas utiliser la résolution DNS inversée pour canonicaliser le nom d'hôte SASL.
-U id_authentification
Spécifier l'identifiant d'authentification pour la liaison SASL. La forme de l'identifiant dépend du mécanisme SASL réellement utilisé.
-R domaine
Spécifier le domaine de l'identifiant d'authentification pour la liaison SASL. La forme du domaine dépend du mécanisme SASL réellement utilisé.
-X authzid
Spécifier l'identifiant d'autorisation demandé pour la liaison SASL. authzid doit être l'un des formats suivants : dn:<nom distinctif> ou u:<nom_utilisateur>
-Y mécanisme
Spécifier le mécanisme SASL à utiliser pour l'authentification. Sans cette option, le programme choisira le meilleur mécanisme que le serveur connaît.
-Z[Z]
Émettre l'opération étendue StartTLS (Transport Layer Security). Donner deux fois (-ZZ) obligera l'opération à réussir.

DIAGNOSTICS

Le code de sortie est zéro si aucune erreur ne se produit. Les erreurs entraînent un code de sortie non nul et l'écriture d'un message de diagnostic sur la sortie d'erreur standard.
