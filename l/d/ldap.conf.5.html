LDAP.CONF(5) Manuel des formats de fichiers LDAP.CONF(5)

NOM

ldap.conf, .ldaprc - Fichier de configuration LDAP / variables d'environnement

SYNTAXE

ETCDIR/ldap.conf, ldaprc, .ldaprc, $LDAP<nom-option>

DESCRIPTION

Si la variable d'environnement LDAPNOINIT est définie, toutes les valeurs par défaut sont désactivées.

Le fichier de configuration ldap.conf est utilisé pour définir les valeurs par défaut du système à appliquer lors de l'exécution des clients ldap.

Les utilisateurs peuvent créer un fichier de configuration optionnel, ldaprc ou .ldaprc, dans leur répertoire personnel qui sera utilisé pour remplacer le fichier de valeurs par défaut du système. Le fichier ldaprc dans le répertoire de travail courant est également utilisé.

Des fichiers de configuration supplémentaires peuvent être spécifiés en utilisant les variables d'environnement LDAPCONF et LDAPRC. LDAPCONF peut être défini sur le chemin d'un fichier de configuration. Ce chemin peut être absolu ou relatif au répertoire de travail courant. LDAPRC, s'il est défini, doit être le nom de base d'un fichier dans le répertoire de travail courant ou dans le répertoire personnel de l'utilisateur.

Les variables d'environnement peuvent également être utilisées pour augmenter les valeurs par défaut basées sur les fichiers. Le nom de la variable est le nom de l'option avec le préfixe LDAP ajouté. Par exemple, pour définir BASE via l'environnement, définissez la variable LDAPBASE à la valeur souhaitée.

Certaines options sont réservées aux utilisateurs. Ces options sont ignorées si elles sont présentes dans ldap.conf (ou dans le fichier spécifié par LDAPCONF).

Ainsi, les fichiers et variables suivants sont lus, dans l'ordre :

    variable     $LDAPNOINIT, et si ce dernier n'est pas défini :
    fichier système  ETCDIR/ldap.conf,
    fichiers utilisateur  $HOME/ldaprc,  $HOME/.ldaprc,  ./ldaprc,
    fichier système  $LDAPCONF,
    fichiers utilisateur  $HOME/$LDAPRC, $HOME/.$LDAPRC, ./$LDAPRC,
    variables    $LDAP<nom d'option en majuscules>.
Les paramètres plus tardifs dans la liste remplacent les précédents.

SYNTAXE

Les options de configuration ne sont pas sensibles à la casse ; leur valeur, selon le cas, peut être sensible à la casse.

Les lignes vides sont ignorées.
Les lignes commençant par une dièse (`#') sont des commentaires et sont ignorées.

Les lignes valides sont composées du nom d'une option (une séquence de caractères non blancs, conventionnellement écrite en majuscules, bien que ce ne soit pas obligatoire), suivie d'une valeur. La valeur commence par le premier caractère non blanc après le nom de l'option et se termine à la fin de la ligne, ou à la dernière séquence d'espaces avant la fin de la ligne. La tokenisation de la valeur, le cas échéant, est déléguée aux gestionnaires de cette option, le cas échéant. La mise entre guillemets de valeurs contenant des espaces peut être incorrecte, car les guillemets feraient partie de la valeur. Par exemple,

# Incorrect - guillemets erronés :
URI     "ldap:// ldaps://"
# Correct - liste d'URI séparée par des espaces, sans guillemets :
URI     ldap:// ldaps://
# Correct - la syntaxe DN nécessite des guillemets pour Example, Inc :
BASE    ou=IT staff,o="Example, Inc",c=US
# ou :
BASE    ou=IT staff,o=Example\2C Inc,c=US
# Incorrect - commentaire sur la même ligne que l'option :
DEREF   never           # Ne jamais suivre les alias

Une ligne ne peut pas être plus longue que LINE_MAX, qui devrait être supérieure à 2000 octets sur toutes les plateformes. Il n'existe aucun mécanisme pour diviser une longue ligne sur plusieurs lignes, que ce soit pour l'esthétique ou pour dépasser la limite ci-dessus.

OPTIONS

Les différentes options de configuration sont :

URI <ldap[si]://[nom[:port]] ...>
Spécifie l'URI (ou les URI) du ou des serveurs LDAP auxquels la bibliothèque LDAP doit se connecter. Le schéma URI peut être ldap, ldaps ou ldapi, qui font référence à LDAP sur TCP, LDAP sur SSL (TLS) et LDAP sur IPC (sockets de domaine UNIX), respectivement. Le nom de chaque serveur peut être spécifié comme un nom de style domaine ou une adresse IP littérale. Facultativement, le nom du serveur peut être suivi d'un ':' et du numéro de port sur lequel le serveur LDAP écoute. Si aucun numéro de port n'est fourni, le port par défaut pour le schéma est utilisé (389 pour ldap://, 636 pour ldaps://). Pour LDAP sur IPC, nom est le nom du socket, et aucun port n'est requis, ni autorisé ; notez que les séparateurs de répertoire doivent être encodés en URL, comme tout autre caractère spécial pour les URL ; ainsi le socket

/usr/local/var/ldapi

doit être spécifié comme

ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

Une liste d'URI séparée par des espaces peut être fournie.

BASE <base>
Spécifie le DN de base par défaut à utiliser lors des opérations ldap. La base doit être spécifiée sous forme de Distinguished Name au format LDAP.
BINDDN <dn>
Spécifie le DN de liaison par défaut à utiliser lors des opérations ldap. Le DN de liaison doit être spécifié sous forme de Distinguished Name au format LDAP. Ceci est une option réservée aux utilisateurs.
DEREF <quand>
Spécifie comment les alias sont déréférencés lors d'une recherche. <quand> peut être spécifié comme l'un des mots-clés suivants :
jamais
Les alias ne sont jamais déréférencés. C'est la valeur par défaut.
recherche
Les alias sont déréférencés dans les subordonnés de l'objet de base, mais pas lors de la localisation de l'objet de base de la recherche.
recherche_de_base
Les alias ne sont déréférencés que lors de la localisation de l'objet de base de la recherche.
toujours
Les alias sont déréférencés à la fois lors de la recherche et lors de la localisation de l'objet de base de la recherche.
HOST <nom[:port] ...>
Spécifie le ou les noms d'un ou plusieurs serveurs LDAP auxquels la bibliothèque LDAP doit se connecter. Chaque nom de serveur peut être spécifié comme un nom de style domaine ou une adresse IP et éventuellement suivi d'un ':' et du numéro de port sur lequel le serveur ldap écoute. Une liste d'hôtes séparée par des espaces peut être fournie. HOST est déprécié au profit de URI.
KEEPALIVE_IDLE
Définit/obtient le nombre de secondes pendant lesquelles une connexion doit rester inactive avant que TCP ne commence à envoyer des sondes keepalive. Linux uniquement.
KEEPALIVE_PROBES
Définit/obtient le nombre maximum de sondes keepalive que TCP doit envoyer avant de fermer la connexion. Linux uniquement.
KEEPALIVE_INTERVAL
Définit/obtient l'intervalle en secondes entre les sondes keepalive individuelles. Linux uniquement.
NETWORK_TIMEOUT <entier>
Spécifie le délai d'attente (en secondes) après lequel poll(2)/select(2) suivant un connect(2) retourne en cas de non activité.
PORT <port>
Spécifie le port par défaut utilisé lors de la connexion au(x) serveur(s) LDAP. Le port peut être spécifié comme un nombre. PORT est déprécié au profit de URI.
REFERRALS <on/true/yes/off/false/no>
Spécifie si le client doit suivre automatiquement les renvois renvoyés par les serveurs LDAP. La valeur par défaut est 'on'. Notez que les outils en ligne de commande comme ldapsearch(1) &c font toujours passer outre cette option.
SIZELIMIT <entier>
Spécifie une limite de taille (nombre d'entrées) à utiliser lors des recherches. Le nombre doit être un entier non négatif. Une SIZELIMIT de zéro (0) spécifie une requête pour une taille de recherche illimitée. Veuillez noter que le serveur peut toujours appliquer une limite côté serveur sur la quantité d'entrées pouvant être retournées par une opération de recherche.
SOCKET_BIND_ADDRESSES <IP>
Spécifie l'adresse IP source à utiliser pour se connecter au serveur LDAP cible. Plusieurs adresses IP doivent être séparées par des espaces. Une seule adresse IPv4 et/ou une seule adresse IPv6 valide sont autorisées dans la liste.
TIMELIMIT <entier>
Spécifie une limite de temps (en secondes) à utiliser lors des opérations LDAP. Le nombre doit être un entier non négatif. Une TIMELIMIT de zéro (0) spécifie une requête pour une limite de temps illimitée. Notez que le serveur peut toujours appliquer une limite de temps côté serveur.

EXEMPLES

Le fichier /etc/ldap/ldap.conf peut ressembler à ceci :

# LDAPv3
ID anggaran de fonctionnement = openldap
BASE    dc=example,dc=com
URI     ldaps://ldap.example.com ldaps://ldap-backup.example.com
TIMELIMIT       10
SIZELIMIT      500

Le fichier ~/.ldaprc peut ressembler à ceci :

# Ne pas suivre les renvois
REFERRALS       off
# utiliser un DN de liaison spécifique
BINDDN          cn=admin,dc=example,dc=com

ldap.conf(5), ldapsearch(1), ldapadd(1), ldapmodify(1), ldapmodrdn(1), ldapurl(3)

TIMELIMIT <entier>
Spécifie une limite de temps (en secondes) à utiliser lors de la recherche. Le nombre doit être un entier non négatif. Une TIMELIMIT de zéro (0) spécifie une durée de recherche illimitée. Veuillez noter que le serveur peut toujours appliquer sa propre limite sur la durée d'une opération de recherche.
VERSION {2|3}
Spécifie la version du protocole LDAP à utiliser.
TIMEOUT <entier>
Spécifie un délai d'attente (en secondes) après lequel les appels aux API LDAP synchrones seront annulés si aucune réponse n'est reçue. Également utilisé pour tous les appels à ldap_result(3) où un paramètre de délai d'attente NULL est fourni.

OPTIONS SASL

Si OpenLDAP est compilé avec le support de Simple Authentication and Security Layer, vous pouvez spécifier des options supplémentaires.

SASL_MECH <mécanisme>
Spécifie le mécanisme SASL à utiliser.
SASL_REALM <domaine>
Spécifie le domaine SASL.
SASL_AUTHCID <authcid>
Spécifie l'identité d'authentification. Ceci est une option réservée aux utilisateurs.
SASL_AUTHZID <authcid>
Spécifie l'identité d'autorisation par procuration. Ceci est une option réservée aux utilisateurs.
SASL_SECPROPS <propriétés>
Spécifie les propriétés de sécurité Cyrus SASL. Les <propriétés> peuvent être spécifiées comme une liste séparée par des virgules des éléments suivants :
none
(sans aucune autre propriété) efface les propriétés par défaut ("noanonymous,noplain").
noplain
désactive les mécanismes susceptibles d'attaques passives simples.
noactive
désactive les mécanismes susceptibles d'attaques actives.
nodict
désactive les mécanismes susceptibles d'attaques par dictionnaire passif.
noanonymous
désactive les mécanismes qui supportent la connexion anonyme.
forwardsec
exige une confidentialité avancée entre les sessions.
passcred
exige des mécanismes qui transmettent les identifiants du client (et permet aux mécanismes qui le peuvent de le faire).
minssf=<facteur>
spécifie le facteur de force de sécurité minimum acceptable sous forme d'un entier approximativement égal à la longueur effective de la clé utilisée pour le chiffrement. 0 (zéro) implique aucune protection, 1 implique seulement une protection d'intégrité, 128 autorise RC4, Blowfish et d'autres chiffrements similaires, 256 nécessitera des chiffrements modernes. La valeur par défaut est 0.
maxssf=<facteur>
spécifie le facteur de force de sécurité maximum acceptable sous forme d'un entier (voir la description de minssf). La valeur par défaut est INT_MAX.
maxbufsize=<facteur>
spécifie la taille maximale du tampon de réception de la couche de sécurité autorisée. 0 désactive les couches de sécurité. La valeur par défaut est 65536.
SASL_NOCANON <on/true/yes/off/false/no>
Ne pas effectuer de recherches DNS inversées pour canonicaliser les noms d'hôtes SASL. La valeur par défaut est off.
SASL_CBINDING <none/tls-unique/tls-endpoint>
Le type de canal-binding à utiliser, voir aussi LDAP_OPT_X_SASL_CBINDING. La valeur par défaut est none.

OPTIONS GSSAPI

Si OpenLDAP est compilé avec le support de Generic Security Services Application Programming Interface, vous pouvez spécifier des options supplémentaires.

GSSAPI_SIGN <on/true/yes/off/false/no>
Spécifie si la signature GSSAPI (GSS_C_INTEG_FLAG) doit être utilisée. La valeur par défaut est off.
GSSAPI_ENCRYPT <on/true/yes/off/false/no>
Spécifie si le chiffrement GSSAPI (GSS_C_INTEG_FLAG et GSS_C_CONF_FLAG) doit être utilisé. La valeur par défaut est off.
GSSAPI_ALLOW_REMOTE_PRINCIPAL <on/true/yes/off/false/no>
Spécifie si l'authentification basée sur GSSAPI doit tenter de former le nom principal cible à partir de l'attribut ldapServiceName ou dnsHostName de l'entrée RootDSE de la cible. La valeur par défaut est off.

OPTIONS TLS

Si OpenLDAP est compilé avec le support de Transport Layer Security, vous pouvez spécifier des options supplémentaires. Ces options sont utilisées lorsqu'une URI ldaps:// est sélectionnée (par défaut ou autrement) ou lorsque l'application négocie TLS en émettant l'opération LDAP StartTLS.

TLS_CACERT <nom_fichier>
Spécifie le fichier contenant les certificats de toutes les autorités de certification que le client reconnaîtra.
TLS_CACERTDIR <chemin>
Spécifie le chemin des répertoires contenant les certificats d'autorité de certification dans des fichiers individuels séparés. Plusieurs répertoires peuvent être spécifiés, séparés par un point-virgule. Le fichier TLS_CACERT est toujours utilisé avant le répertoire TLS_CACERTDIR.
TLS_CERT <nom_fichier>
Spécifie le fichier contenant le certificat client. Ceci est une option réservée aux utilisateurs.
TLS_ECNAME <nom>
Spécifie le nom de la ou des courbes à utiliser pour l'échange de clés éphémères Diffie-Hellman elliptique. Cette option n'est utilisée que pour OpenSSL. Cette option n'est pas utilisée avec GnuTLS ; les courbes peuvent être choisies dans la spécification de la suite de chiffrement GnuTLS.
TLS_KEY <nom_fichier>
Spécifie le fichier contenant la clé privée qui correspond au certificat stocké dans le fichier TLS_CERT. Actuellement, la clé privée ne doit pas être protégée par un mot de passe, il est donc d'une importance capitale que le fichier de clé soit protégé avec soin. Ceci est une option réservée aux utilisateurs.
TLS_CIPHER_SUITE <spécification_suite_de_chiffrement>
Spécifie les suites de chiffrement acceptables et leur ordre de préférence. <spécification_suite_de_chiffrement> doit être une spécification de chiffrement pour la bibliothèque TLS utilisée (OpenSSL ou GnuTLS). Exemple :
OpenSSL:
TLS_CIPHER_SUITE HIGH:MEDIUM:+SSLv2
GnuTLS:
TLS_CIPHER_SUITE SECURE256:!AES-128-CBC

Pour vérifier quels chiffrements une spécification donnée sélectionne dans OpenSSL, utilisez :

openssl ciphers -v <spécification_suite_de_chiffrement>

Avec GnuTLS, les spécifications disponibles se trouvent dans la page de manuel de gnutls-cli(1) (voir la description de l'option --priority).

Dans les versions plus anciennes de GnuTLS, où gnutls-cli ne prend pas en charge l'option --priority, vous pouvez obtenir la liste — plus limitée — des chiffrements en appelant :

gnutls-cli -l
TLS_PROTOCOL_MIN <majeur>[.<mineur>]
Spécifie la version minimale du protocole SSL/TLS qui sera négociée. Si le serveur ne prend pas en charge au moins cette version, la négociation SSL échouera. Pour exiger TLS 1.x ou supérieur, définissez cette option sur 3.(x+1), par exemple : 
TLS_PROTOCOL_MIN 3.2

exigerait TLS 1.1. Spécifier un minimum supérieur à celui pris en charge par l'implémentation OpenLDAP entraînera l'exigence du niveau le plus élevé qu'elle supporte. Ce paramètre est ignoré avec GnuTLS.

TLS_RANDFILE <nom_fichier>
Spécifie le fichier à partir duquel obtenir les bits aléatoires lorsque /dev/[u]random n'est pas disponible. Généralement défini sur le nom du socket EGD/PRNGD. La variable d'environnement RANDFILE peut également être utilisée pour spécifier le nom du fichier. Ce paramètre est ignoré avec GnuTLS.
TLS_REQCERT <niveau>
Spécifie les vérifications à effectuer sur les certificats serveur dans une session TLS. Le <niveau> peut être spécifié comme l'un des mots-clés suivants :
never
Le client ne demandera ni ne vérifiera aucun certificat serveur.
allow
Le certificat serveur est demandé. Si un certificat invalide est fourni, il sera ignoré et la session se poursuivra normalement.
try
Le certificat serveur est demandé. Si un certificat invalide est fourni, la session sera immédiatement terminée.
demand | hard
Ces mots-clés sont équivalents et identiques à try. C'est le paramètre par défaut.
TLS_REQSAN <niveau>
Spécifie les vérifications à effectuer sur les extensions subjectAlternativeName (SAN) dans un certificat serveur lors de la validation du nom de certificat par rapport au nom d'hôte spécifié du serveur. Le <niveau> peut être spécifié comme l'un des mots-clés suivants :
jamais
Le client ne vérifiera aucun SAN dans le certificat.
autoriser
Le SAN est vérifié par rapport à l'hôte spécifié. Si un SAN est présent mais qu'aucun ne correspond à l'hôte spécifié, les SAN sont ignorés et la vérification habituelle par rapport au DN du certificat est utilisée. Ceci est le paramètre par défaut.
essayer
Le SAN est vérifié par rapport à l'hôte spécifié. Si aucun SAN n'est présent dans le certificat du serveur, la vérification habituelle par rapport au DN du certificat est utilisée. Si un SAN est présent mais ne correspond pas à l'hôte spécifié, la session est immédiatement terminée. Ce paramètre peut être préféré lorsqu'un mélange de certificats avec et sans SAN est utilisé.
exiger | dur
Ces mots-clés sont équivalents. Le SAN est vérifié par rapport à l'hôte spécifié. Si aucun SAN n'est présent dans le certificat du serveur, ou si aucun SAN ne correspond, la session est immédiatement terminée. Ce paramètre doit être utilisé lorsque seuls des certificats avec SAN sont utilisés.
TLS_CRLCHECK <niveau>
Spécifie si la liste de révocation de certificats (CRL) de l'AC doit être utilisée pour vérifier si les certificats du serveur n'ont pas été révoqués. Cela nécessite que le paramètre TLS_CACERTDIR soit défini. Ce paramètre est ignoré avec GnuTLS. <niveau> peut être spécifié comme l'un des mots-clés suivants :
aucun
Aucune vérification de CRL n'est effectuée
pair
Vérifie la CRL du certificat du pair
tout
Vérifie la CRL pour toute la chaîne de certificats
TLS_CRLFILE <nom_de_fichier>
Spécifie le fichier contenant une liste de révocation de certificats à utiliser pour vérifier si les certificats du serveur n'ont pas été révoqués. Ce paramètre est uniquement pris en charge avec GnuTLS.
