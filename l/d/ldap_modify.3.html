LDAP_MODIFY(3) Manuel des fonctions de bibliothèque LDAP_MODIFY(3)

NOM

ldap_modify_ext, ldap_modify_ext_s - Effectuer une opération de modification LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>
int ldap_modify_ext(
LDAP *ld,
char *dn,
LDAPMod *mods[],
LDAPControl **sctrls,
LDAPControl **cctrls,
int *msgidp );
int ldap_modify_ext_s(
LDAP *ld,
char *dn,
LDAPMod *mods[],
LDAPControl **sctrls,
LDAPControl **cctrls );
void ldap_mods_free(
LDAPMod **mods,
int freemods );

DESCRIPTION

La routine ldap_modify_ext_s() est utilisée pour effectuer une opération de modification LDAP. dn est le DN de l'entrée à modifier, et mods est un tableau terminé par NULL de modifications à apporter à l'entrée. Chaque élément du tableau mods est un pointeur vers une structure LDAPMod, qui est définie ci-dessous.

typedef struct ldapmod {
    int mod_op;
    char *mod_type;
    union {
        char **modv_strvals;
        struct berval **modv_bvals;
    } mod_vals;
} LDAPMod;
#define mod_values mod_vals.modv_strvals
#define mod_bvalues mod_vals.modv_bvals

Le champ mod_op est utilisé pour spécifier le type de modification à effectuer et doit être l'un des LDAP_MOD_ADD, LDAP_MOD_DELETE, ou LDAP_MOD_REPLACE. Les champs mod_type et mod_values spécifient le type d'attribut à modifier et un tableau terminé par NULL des valeurs à ajouter, supprimer ou remplacer respectivement.

Si vous devez spécifier une valeur non-chaîne (par exemple, pour ajouter une valeur d'attribut photo ou audio), vous devez définir mod_op à l'opération logique OR de l'opération comme ci-dessus (par exemple, LDAP_MOD_REPLACE) et la constante LDAP_MOD_BVALUES. Dans ce cas, mod_bvalues doit être utilisé à la place de mod_values, et il doit pointer vers un tableau terminé par NULL de struct bervals, tel que défini dans <lber.h>.

Pour les modifications LDAP_MOD_ADD, les valeurs fournies sont ajoutées à l'entrée, créant l'attribut si nécessaire. Pour les modifications LDAP_MOD_DELETE, les valeurs fournies sont supprimées de l'entrée, supprimant l'attribut s'il ne reste aucune valeur. Si l'attribut entier doit être supprimé, le champ mod_values doit être défini à NULL. Pour les modifications LDAP_MOD_REPLACE, l'attribut aura les valeurs listées après la modification, ayant été créé si nécessaire. Toutes les modifications sont effectuées dans l'ordre où elles sont listées.

ldap_mods_free() peut être utilisé pour libérer chaque élément d'un tableau terminé par NULL de structures mod. Si freemods est non nul, le pointeur mods lui-même est également libéré.

ldap_modify_ext_s() retourne un code indiquant le succès ou, en cas d'échec, indiquant la nature de l'échec. Voir ldap_error(3) pour plus de détails.

L'opération ldap_modify_ext() fonctionne de la même manière que ldap_modify_ext_s(), à la différence qu'elle est asynchrone. L'entier vers lequel pointe msgidp est défini à l'identifiant du message de la requête de modification. Le résultat de l'opération peut être obtenu en appelant ldap_result(3).

Les deux ldap_modify_ext() et ldap_modify_ext_s() permettent de passer des contrôles serveur et client via les paramètres sctrls et cctrls, respectivement.

INTERFACES OBSOLÈTES

Les routines ldap_modify() et ldap_modify_s() sont obsolètes au profit des routines ldap_modify_ext() et ldap_modify_ext_s(), respectivement.

Les interfaces obsolètes restent généralement dans la bibliothèque. Le macro LDAP_DEPRECATED peut être défini à une valeur non nulle (par exemple, -DLDAP_DEPRECATED=1) lors de la compilation d'un programme conçu pour utiliser des interfaces obsolètes. Il est recommandé que les développeurs écrivant de nouveaux programmes, ou mettant à jour d'anciens programmes, évitent d'utiliser des interfaces obsolètes. Au fil du temps, il est prévu que la documentation (et, à terme, le support) des interfaces obsolètes soit éliminée.
