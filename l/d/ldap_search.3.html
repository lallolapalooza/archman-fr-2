LDAP_SEARCH(3) Manuel des fonctions de bibliothèque LDAP_SEARCH(3)

NOM

ldap_search, ldap_search_s, ldap_search_st, ldap_search_ext, ldap_search_ext_s - Effectuer une opération de recherche LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <sys/types.h>
#include <ldap.h>
int ldap_search_ext(
LDAP *ld,
char *base,
int scope,
char *filter,
char *attrs[],
int attrsonly,
LDAPControl **serverctrls,
LDAPControl **clientctrls,
struct timeval *timeout,
int sizelimit,
int *msgidp );
int ldap_search_ext_s(
LDAP *ld,
char *base,
int scope,
char *filter,
char *attrs[],
int attrsonly,
LDAPControl **serverctrls,
LDAPControl **clientctrls,
struct timeval *timeout,
int sizelimit,
LDAPMessage **res );

DESCRIPTION

Ces routines sont utilisées pour effectuer des opérations de recherche LDAP. La routine ldap_search_ext_s() effectue la recherche de manière synchrone (c'est-à-dire qu'elle ne revient pas tant que l'opération n'est pas terminée), fournissant un pointeur vers les messages LDAP résultants à l'emplacement pointé par le paramètre res.

La routine ldap_search_ext() est la version asynchrone, initiant la recherche et retournant l'identifiant du message de l'opération qu'elle a initiée dans l'entier pointé par le paramètre msgidp.

Le paramètre base est le DN de l'entrée à partir de laquelle démarrer la recherche.

Le paramètre scope est la portée de la recherche et doit être l'une des valeurs LDAP_SCOPE_BASE, pour rechercher l'objet lui-même, LDAP_SCOPE_ONELEVEL, pour rechercher les enfants immédiats de l'objet, LDAP_SCOPE_SUBTREE, pour rechercher l'objet et tous ses descendants, ou LDAP_SCOPE_CHILDREN, pour rechercher tous les descendants. Notez que cette dernière nécessite que le serveur prenne en charge l'extension de portée de recherche des subordonnés LDAP.

Le paramètre filter est une représentation sous forme de chaîne du filtre à appliquer dans la recherche. La chaîne doit être conforme au format spécifié dans la RFC 4515 telle qu'étendue par la RFC 4526. Par exemple, "(cn=Jane Doe)". Notez que l'utilisation de l'extension nécessite que le serveur prenne en charge l'extension de filtre Absolu Vrai/Faux LDAP. NULL peut être spécifié pour indiquer que la bibliothèque doit envoyer le filtre (objectClass=*).

Le paramètre attrs est un tableau terminé par null de descriptions d'attributs à retourner à partir des entrées correspondantes. Si NULL est spécifié, le retour de tous les attributs utilisateur est demandé. La description "*" (LDAP_ALL_USER_ATTRIBUTES) peut être utilisée pour demander le retour de tous les attributs utilisateur. La description "+" (LDAP_ALL_OPERATIONAL_ATTRIBUTES) peut être utilisée pour demander le retour de tous les attributs opérationnels. Notez que cela nécessite que le serveur prenne en charge l'extension d'attributs opérationnels LDAP. Pour demander aucun attribut, la description "1.1" (LDAP_NO_ATTRS) doit être listée seule.

Le paramètre attrsonly doit être défini à une valeur non nulle si seules les descriptions d'attributs sont souhaitées. Il doit être défini à zéro (0) si les descriptions d'attributs et les valeurs d'attributs sont souhaitées.

Les paramètres serverctrls et clientctrls peuvent être utilisés pour spécifier respectivement les contrôles serveur et client.

La routine ldap_search_ext_s() est la version synchrone de ldap_search_ext().

Elle retourne également un code indiquant le succès ou, en cas d'échec, indiquant la nature de l'échec de l'opération. Voir ldap_error(3) pour les détails.

NOTES

Notez que les fonctionnalités de lecture (read) et de liste (list) sont toutes deux incluses dans ces routines, en utilisant un filtre tel que "(objectclass=*)" et une portée de LDAP_SCOPE_BASE (pour émuler la lecture) ou LDAP_SCOPE_ONELEVEL (pour émuler la liste).

Ces routines peuvent allouer dynamiquement de la mémoire. L'appelant est responsable de la libération de cette mémoire à l'aide des routines de désallocation fournies. Les valeurs de retour sont contenues dans <ldap.h>.

Notez que le paramètre res de ldap_search_ext_s() et ldap_search_s() doit être libéré avec ldap_msgfree() quel que soit le résultat de ces fonctions.

INTERFACES OBSOLÈTES

La routine ldap_search() est obsolète au profit de la routine ldap_search_ext(). Les routines ldap_search_s() et ldap_search_st() sont obsolètes au profit de la routine ldap_search_ext_s().

Les interfaces obsolètes restent généralement dans la bibliothèque. La macro LDAP_DEPRECATED peut être définie à une valeur non nulle (par exemple, -DLDAP_DEPRECATED=1) lors de la compilation d'un programme conçu pour utiliser des interfaces obsolètes. Il est recommandé aux développeurs écrivant de nouveaux programmes, ou mettant à jour d'anciens programmes, d'éviter l'utilisation d'interfaces obsolètes. Au fil du temps, il est attendu que la documentation (et, éventuellement, le support) pour les interfaces obsolètes soit éliminée.
