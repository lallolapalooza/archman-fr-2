ldap_open(3)

Paquet: libldap

Licences: custom

LDAP_OPEN(3) Manuel des fonctions de bibliothèque LDAP_OPEN(3)

NOM

ldap_init, ldap_initialize, ldap_open - Initialise la bibliothèque LDAP et ouvre une connexion à un serveur LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNTAXE

#include <ldap.h>
LDAP *ldap_open(host, port)
char *host;
int port;
LDAP *ldap_init(host, port)
char *host;
int port;
int ldap_initialize(ldp, uri)
LDAP **ldp;
char *uri;
int ldap_connect(ldp)
LDAP *ldp;
int ldap_set_urllist_proc(ld, proc, params)
LDAP *ld;
LDAP_URLLIST_PROC *proc;
void *params;
int (LDAP_URLLIST_PROC)(ld, urllist, url, params);
LDAP *ld;
LDAPURLDesc **urllist;
LDAPURLDesc **url;
void *params;
#include <openldap.h>
int ldap_init_fd(fd, proto, uri, ldp)
ber_socket_t fd;
int proto;
char *uri;
LDAP **ldp;

DESCRIPTION

ldap_open() ouvre une connexion à un serveur LDAP et alloue une structure LDAP qui est utilisée pour identifier la connexion et pour maintenir des informations par connexion. ldap_init() alloue une structure LDAP mais n'ouvre pas de connexion initiale. ldap_initialize() alloue une structure LDAP mais n'ouvre pas de connexion initiale. ldap_init_fd() alloue une structure LDAP en utilisant une connexion existante sur le descripteur de fichier fourni. Une de ces routines doit être appelée avant toute tentative d'opération.

ldap_open() prend host, le nom d'hôte sur lequel le serveur LDAP s'exécute, et port, le numéro de port auquel se connecter. Si le port par défaut assigné par l'IANA, 389, est souhaité, LDAP_PORT doit être spécifié pour port. Le paramètre host peut contenir une liste d'hôtes séparés par des espaces à essayer de connecter, et chaque hôte peut éventuellement être sous la forme host:port. Si présent, le :port remplace le paramètre port de ldap_open(). En cas de succès de la connexion à un serveur LDAP, ldap_open() retourne un pointeur vers une structure LDAP opaque, qui doit être passée aux appels ultérieurs à ldap_bind(), ldap_search(), etc. Certains champs de la structure LDAP peuvent être définis pour indiquer la limite de taille, la limite de temps, et la manière dont les alias sont gérés pendant les opérations ; l'accès en lecture et en écriture à ces champs doit se faire en appelant ldap_get_option(3) et ldap_set_option(3) respectivement, chaque fois que possible.

ldap_init() agit comme ldap_open(), mais n'ouvre pas de connexion au serveur LDAP. L'ouverture de la connexion réelle se produira lors de la première tentative d'opération.

ldap_initialize() agit comme ldap_init(), mais elle retourne un entier indiquant soit le succès soit la raison de l'échec, et elle permet de spécifier les détails de la connexion dans la partie schéma de l'URI. Le paramètre uri peut être une liste d'URI séparés par des virgules ou des espaces ne contenant que les champs schéma, hôte, et port. En dehors de ldap, d'autres valeurs (non standard) reconnues pour le champ schéma sont ldaps (LDAP sur TLS), ldapi (LDAP sur IPC), et cldap (LDAP sans connexion). Si d'autres champs sont présents, le comportement est indéfini.

À l'heure actuelle, ldap_open() et ldap_init() sont dépréciés au profit de ldap_initialize(), essentiellement parce que cette dernière permet de spécifier un schéma dans l'URI et qu'elle retourne explicitement un code d'erreur.

ldap_connect() force une poignée créée par ldap_initialize() à se connecter au serveur. Ceci est utile dans les situations où un descripteur de fichier est requis avant qu'une requête ne soit effectuée.

ldap_init_fd() permet d'initialiser une structure LDAP en utilisant une connexion déjà ouverte. Le paramètre proto doit être un parmi LDAP_PROTO_TCP, LDAP_PROTO_UDP, ou LDAP_PROTO_IPC pour une connexion utilisant TCP, UDP, ou IPC, respectivement. La valeur LDAP_PROTO_EXT peut également être spécifiée si des gestionnaires de sockbuf fournis par l'utilisateur vont être utilisés. Notez que le support d'UDP n'est pas implémenté à moins que libldap n'ait été compilé avec LDAP_CONNECTIONLESS défini. Le paramètre uri peut être fourni optionnellement à titre informatif.

ldap_set_urllist_proc() permet de définir une fonction proc de type LDAP_URLLIST_PROC qui est appelée lorsqu'une connexion réussie peut être établie. Cette fonction reçoit la liste des URI analysés à partir de la chaîne uri initialement passée à ldap_initialize(), et celle qui s'est connectée avec succès. La fonction peut manipuler la liste d'URI ; l'utilisation typique consiste à déplacer l'URI réussie en tête de liste, de sorte que les tentatives ultérieures de connexion à l'un des URI en utilisant la même poignée LDAP essaieront d'abord celui-ci. Si ld est nul, proc est défini comme un paramètre global qui est hérité par tous les gestionnaires du processus qui sont créés après l'appel à ldap_set_urllist_proc(). Par défaut, aucun LDAP_URLLIST_PROC n'est défini. Dans un environnement multithreadé, ldap_set_urllist_proc() doit être appelé avant que toute opération concurrente utilisant la poignée LDAP ne soit lancée.

Remarque : le premier appel à la bibliothèque LDAP initialise également les options globales de la bibliothèque. Par conséquent, le premier appel doit être monothreadé ou autrement protégé pour garantir qu'un seul appel est actif. Il est recommandé d'utiliser ldap_get_option() ou ldap_set_option() dans le thread principal du programme avant que des threads supplémentaires ne soient créés. Voir ldap_get_option(3).

ERREURS

Si une erreur se produit, ldap_open() et ldap_init() retourneront NULL et errno devrait être correctement défini. ldap_initialize() et ldap_init_fd() retourneront directement le code LDAP associé à l'erreur (ou LDAP_SUCCESS en cas de succès) ; errno devrait également être défini chaque fois que cela est approprié. ldap_set_urllist_proc() retourne LDAP_OPT_ERROR en cas d'erreur, et LDAP_OPT_SUCCESS en cas de succès.
