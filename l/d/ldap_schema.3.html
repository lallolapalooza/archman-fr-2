DESCRIPTION

Ces routines sont utilisées pour analyser les définitions de schéma au format défini par la RFC 4512 en structures et pour gérer ces structures. Ces routines gèrent quatre types de définitions : syntaxes, règles de correspondance, types d'attributs et classes d'objet. Pour chaque type de définition, quatre routines sont fournies.

ldap_str2xxx() prend une définition au format RFC 4512 dans l'argument s comme une chaîne terminée par NUL et retourne, si possible, un pointeur vers une structure nouvellement allouée du type approprié. L'appelant est responsable de libérer la structure en appelant ldap_xxx_free() lorsqu'elle n'est plus nécessaire. La routine retourne NULL si un problème survient. Dans ce cas, l'entier pointé par l'argument code recevra un code d'erreur (voir ci-dessous la description de ldap_scherr2str() pour une explication des valeurs) et un pointeur vers une chaîne terminée par NUL sera placé là où demandé par l'argument errp, indiquant où dans l'argument s l'erreur s'est produite, il ne doit donc pas être libéré par l'appelant. L'argument flags est un masque de bits d'options d'analyse contrôlant le relâchement de la syntaxe reconnue. Les valeurs suivantes sont définies :

LDAP_SCHEMA_ALLOW_NONE
analyse stricte selon la RFC 4512.
LDAP_SCHEMA_ALLOW_NO_OID
permet les définitions qui ne contiennent pas d'OID initial.
LDAP_SCHEMA_ALLOW_QUOTED
permet les guillemets autour de certains éléments qui ne devraient pas en avoir.
LDAP_SCHEMA_ALLOW_DESCR
permet une descr au lieu d'un OID numérique aux endroits où la syntaxe attend ce dernier.
LDAP_SCHEMA_ALLOW_DESCR_PREFIX
permet que l'OID numérique initial contienne un préfixe au format descr.
LDAP_SCHEMA_ALLOW_ALL
être très libéral, inclure toutes les options.

Les structures retournées sont les suivantes :

typedef struct ldap_schema_extension_item {
	char *lsei_name;	/* Nom de l'extension */
	char **lsei_values;	/* Valeurs de l'extension */
} LDAPSchemaExtensionItem;
typedef struct ldap_syntax {
	char *syn_oid;		/* OID */
	char **syn_names;	/* Noms */
	char *syn_desc;		/* Description */
	LDAPSchemaExtensionItem **syn_extensions; /* Extension */
} LDAPSyntax;
typedef struct ldap_matchingrule {
	char *mr_oid;		/* OID */
	char **mr_names;	/* Noms */
	char *mr_desc;		/* Description */
	int  mr_obsolete;	/* Obsolète ? */
	char *mr_syntax_oid;	/* OID de la syntaxe des valeurs affirmées */
	LDAPSchemaExtensionItem **mr_extensions; /* Extensions */
} LDAPMatchingRule;
typedef struct ldap_attributetype {
	char *at_oid;		/* OID */
	char **at_names;	/* Noms */
	char *at_desc;		/* Description */
	int  at_obsolete;	/* Obsolète ? */
	char *at_sup_oid;	/* OID du type supérieur */
	char *at_equality_oid;	/* OID de la règle de correspondance d'égalité */
	char *at_ordering_oid;	/* OID de la règle de correspondance d'ordre */
	char *at_substr_oid;	/* OID de la règle de correspondance de sous-chaînes */
	char *at_syntax_oid;	/* OID de la syntaxe des valeurs */
	int  at_syntax_len;	/* Longueur maximale minimale suggérée */
	int  at_single_value;	/* Est à valeur unique ? */
	int  at_collective;	/* Est collectif ? */
	int  at_no_user_mod;	/* Les modifications sont-elles interdites via LDAP ? */
	int  at_usage;		/* Utilisation, voir ci-dessous */
	LDAPSchemaExtensionItem **at_extensions; /* Extensions */
} LDAPAttributeType;
typedef struct ldap_objectclass {
	char *oc_oid;		/* OID */
	char **oc_names;	/* Noms */
	char *oc_desc;		/* Description */
	int  oc_obsolete;	/* Obsolète ? */
	char **oc_sup_oids;	/* OIDs des classes supérieures */
	int  oc_kind;		/* Type, voir ci-dessous */
	char **oc_at_oids_must;	/* OIDs des types d'attributs requis */
	char **oc_at_oids_may;	/* OIDs des types d'attributs optionnels */
	LDAPSchemaExtensionItem **oc_extensions; /* Extensions */
} LDAPObjectClass;

Certains champs entiers (ceux décrits avec un point d'interrogation) ont une valeur booléenne, pour ces champs les valeurs possibles sont :

LDAP_SCHEMA_NO
La réponse à la question est non.
LDAP_SCHEMA_YES
La réponse à la question est oui.

Pour les types d'attributs, les utilisations suivantes sont possibles :

LDAP_SCHEMA_USER_APPLICATIONS
le type d'attribut n'est pas opérationnel.
LDAP_SCHEMA_DIRECTORY_OPERATION
le type d'attribut est opérationnel et pertinent pour le répertoire lui-même, c'est-à-dire qu'il a la même valeur sur tous les serveurs qui fournissent l'entrée contenant ce type d'attribut.
LDAP_SCHEMA_DISTRIBUTED_OPERATION
le type d'attribut est opérationnel et pertinent pour la réplication, l'ombrage ou d'autres aspects du répertoire distribué. À confirmer.
LDAP_SCHEMA_DSA_OPERATION
le type d'attribut est opérationnel et pertinent pour le serveur de répertoire lui-même, c'est-à-dire qu'il peut avoir des valeurs différentes pour la même entrée lorsqu'il est récupéré à partir de serveurs différents qui fournissent l'entrée.

Les classes d'objet peuvent être de trois types :

LDAP_SCHEMA_ABSTRACT
la classe d'objet est abstraite, c'est-à-dire qu'il ne peut y avoir d'entrées de cette classe seules.
LDAP_SCHEMA_STRUCTURAL
la classe d'objet est structurelle, c'est-à-dire qu'elle décrit le rôle principal de l'entrée. Sur certains serveurs, une fois l'entrée créée, l'ensemble des classes d'objet structurelles assignées ne peut pas être modifié : aucune de celles présentes ne peut être supprimée et aucune autre ne peut être ajoutée.
LDAP_SCHEMA_AUXILIARY
la classe d'objet est auxiliaire, c'est-à-dire qu'elle est destinée

pour aller avec d'autres classes d'objets structurels. Celles-ci peuvent être ajoutées ou supprimées à tout moment si des types d'attributs sont ajoutés ou supprimés en même temps, selon les besoins de l'ensemble des classes d'objets résultant de l'opération.

Les routines ldap_xxx2name() retournent un nom canonique pour la définition.

Les routines ldap_xxx2str() retournent une représentation sous forme de chaîne de caractères dans le format décrit par la RFC 4512 de la structure passée en argument. La chaîne est une chaîne nouvellement allouée qui doit être libérée par l'appelant. Ces routines peuvent retourner NULL si aucune mémoire ne peut être allouée pour la chaîne.

ldap_scherr2str() retourne une chaîne terminée par NUL avec une description textuelle de l'erreur trouvée. Il s'agit d'un pointeur vers une zone statique, elle ne doit donc pas être libérée par l'appelant. L'argument code provient de l'une des routines d'analyse et peut prendre les valeurs suivantes :

LDAP_SCHERR_OUTOFMEM
Manque de mémoire.
LDAP_SCHERR_UNEXPTOKEN
Jeton inattendu.
LDAP_SCHERR_NOLEFTPAREN
Parenthèse ouvrante manquante.
LDAP_SCHERR_NORIGHTPAREN
Parenthèse fermante manquante.
LDAP_SCHERR_NODIGIT
Chiffre attendu.
LDAP_SCHERR_BADNAME
Nom attendu.
LDAP_SCHERR_BADDESC
Description incorrecte.
LDAP_SCHERR_BADSUP
Supérieurs incorrects.
LDAP_SCHERR_DUPOPT
Option dupliquée.
LDAP_SCHERR_EMPTY
Fin de données inattendue.
