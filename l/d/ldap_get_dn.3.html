ldap_get_dn(3)

LDAP_GET_DN(3) Manuel des fonctions de bibliothèque LDAP_GET_DN(3)

NOM

ldap_get_dn, ldap_explode_dn, ldap_explode_rdn, ldap_dn2ufn - Routines de gestion des DN LDAP

BIBLIOTHÈQUE

OpenLDAP LDAP (libldap, -lldap)

SYNOPSIS

#include <ldap.h>
char *ldap_get_dn( LDAP *ld, LDAPMessage *entry )
int ldap_str2dn( const char *str, LDAPDN *dn, unsigned flags )
void ldap_dnfree( LDAPDN dn )
int ldap_dn2str( LDAPDN dn, char **str, unsigned flags )
char **ldap_explode_dn( const char *dn, int notypes )
char **ldap_explode_rdn( const char *rdn, int notypes )
char *ldap_dn2ufn( const char * dn )
char *ldap_dn2dcedn( const char * dn )
char *ldap_dcedn2dn( const char * dn )
char *ldap_dn2ad_canonical( const char * dn )

DESCRIPTION

Ces routines permettent d'obtenir, d'analyser, de convertir sous une forme conviviale et de tester les noms d'entrée LDAP (Distinguished Names, ou DN). Un DN a la forme décrite dans la RFC 4414 « Lightweight Directory Access Protocol (LDAP): String Representation of Distinguished Names ».

La routine ldap_get_dn() prend une entrée telle que renvoyée par ldap_first_entry(3) ou ldap_next_entry(3) et renvoie une copie du DN de l'entrée. L'espace pour le DN sera obtenu dynamiquement et doit être libéré par l'appelant à l'aide de ldap_memfree(3).

ldap_str2dn() analyse une représentation textuelle d'un nom distinctif contenu dans str en ses composantes, qui sont stockées dans dn sous forme de structures ldap_ava, organisées en termes LDAPAVA, LDAPRDN et LDAPDN. L'espace pour dn sera obtenu dynamiquement et doit être libéré par l'appelant à l'aide de ldap_dnfree(3). Le LDAPDN est défini comme suit :

typedef struct ldap_ava {
    struct berval la_attr;
    struct berval la_value;
    unsigned la_flags;
} LDAPAVA;
typedef LDAPAVA** LDAPRDN;
typedef LDAPRDN* LDAPDN;
Les types d'attributs et les valeurs d'attributs ne sont pas normalisés. Les la_flags peuvent être soit LDAP_AVA_STRING soit LDAP_AVA_BINARY, ce dernier signifiant que la valeur est encodée en BER/DER et doit donc être représentée comme, citant la RFC 4514, « ... un caractère octothorpe ('#' ASCII 35) suivi de la représentation hexadécimale de chacun des octets de l'encodage BER de la valeur de l'attribut X.500. » Le paramètre flags de ldap_str2dn() peut être 
LDAP_DN_FORMAT_LDAPV3
LDAP_DN_FORMAT_LDAPV2
LDAP_DN_FORMAT_DCE
qui définit la syntaxe DN attendue (selon les RFC 4514, 1779 et le DCE, respectivement). Le format peut être combiné par OU* avec les flags 
LDAP_DN_P_NO_SPACES
LDAP_DN_P_NO_SPACE_AFTER_RDN
...
LDAP_DN_PEDANTIC
Ce dernier est un raccourci pour toutes les limitations précédentes.

LDAP_DN_P_NO_SPACES n'autorise pas d'espaces supplémentaires dans le dn ; par défaut, les espaces autour des séparateurs AVA ('='), des séparateurs de composants RDN ('+' pour LDAPv3/LDAPv2 ou ',' pour DCE) et des séparateurs RDN (',' LDAPv3/LDAPv2 ou '/' pour DCE) sont silencieusement éliminés.

LDAP_DN_P_NO_SPACE_AFTER_RDN n'autorise pas un espace unique après les séparateurs RDN.

ldap_dn2str() effectue l'opération inverse, produisant dans str une représentation textuelle de dn. Elle autorise les mêmes valeurs pour les flags que ldap_str2dn(), plus

LDAP_DN_FORMAT_UFN
LDAP_DN_FORMAT_AD_CANONICAL
pour le nommage convivial (RFC 1781) et le format canonique AD.

Les routines suivantes sont considérées comme obsolètes au profit de ldap_str2dn() et ldap_dn2str(). Elles sont fournies pour supporter les applications héritées.

La routine ldap_explode_dn() prend un DN tel que renvoyé par ldap_get_dn() et le décompose en ses parties constituantes. Chaque partie est connue sous le nom de Relative Distinguished Name, ou RDN. ldap_explode_dn() renvoie un tableau terminé par NULL, dont chaque composant contient un RDN du DN. Le paramètre notypes est utilisé pour demander que seules les valeurs RDN soient renvoyées, et non leurs types. Par exemple, le DN « cn=Bob, c=US » serait renvoyé comme { "cn=Bob", "c=US", NULL } ou { "Bob", "US", NULL }, selon que notypes vaut 0 ou 1, respectivement. Les valeurs d'assertion dans les chaînes RDN peuvent inclure des caractères échappés. Le résultat peut être libéré en appelant ldap_value_free(3).

De même, la routine ldap_explode_rdn() prend un RDN tel que renvoyé par ldap_explode_dn(dn,0) et le décompose en ses parties « type=valeur » (ou simplement « valeur », si le paramètre notypes est défini). Notez que la valeur n'est pas déséchappée. Le résultat peut être libéré en appelant ldap_value_free(3).

ldap_dn2ufn() est utilisé pour transformer un DN tel que renvoyé par ldap_get_dn(3) en une forme plus conviviale, en retirant tous les noms de type. Voir « Using the Directory to Achieve User Friendly Naming » (RFC 1781) pour plus de détails sur le format UFN. En raison de la nature ambiguë du format, il est généralement utilisé uniquement à des fins d'affichage. L'espace pour l'UFN renvoyé est obtenu dynamiquement et l'utilisateur est responsable de sa libération via un appel à ldap_memfree(3).

ldap_dn2dcedn() est utilisé pour transformer un DN tel que renvoyé par ldap_get_dn(3) en un DN de style DCE, par exemple une chaîne avec les RDN du plus significatif au moins significatif séparés par des slashs ('/'); les composants RDN sont séparés par des virgules (','). Seuls les caractères imprimables (par exemple, la chaîne imprimable LDAPv2) sont autorisés, du moins dans cette implémentation. ldap_dcedn2dn() effectue l'opération inverse. ldap_dn2ad_canonical() transforme un DN en un nom canonique AD, qui est essentiellement un DN DCE sans les types d'attributs. Le domaine final, s'il est présent, est transformé en un domaine de type DNS. L'espace pour la valeur renvoyée est obtenu dynamiquement et l'utilisateur est responsable de sa libération via un appel à ldap_memfree(3).

ERREURS

Si une erreur se produit dans ldap_get_dn(), NULL est renvoyé et le champ ld_errno du paramètre ld est défini pour indiquer l'erreur. Voir ldap_error(3) pour une description des codes d'erreur possibles. ldap_explode_dn(), ldap_explode_rdn(), ldap_dn2ufn(), ldap_dn2dcedn(), ldap_dcedn2dn() et ldap_dn2ad_canonical() renverront NULL avec errno(3) défini de manière appropriée en cas de problème.

NOTES

Ces routines allouent dynamiquement de la mémoire que l'appelant doit libérer.
