LDMTOOL(1) Commandes utilisateur LDMTOOL(1)

NOM

ldmtool - Un outil pour gérer les disques dynamiques Microsoft Windows

SYNTAXE

ldmtool [options]

ldmtool [options] scan [périphérique...]

ldmtool [options] show diskgroup {GUID de groupe de disques}

ldmtool [options] show {volume | partition | disque} {GUID de groupe de disques} {nom d'objet}

ldmtool [options] {create | remove} all

ldmtool [options] {create | remove} volume {GUID de groupe de disques} {nom de volume}

OPTIONS

-d|--device périphérique

Scan automatiquement le périphérique.

DESCRIPTION

ldmtool est un outil pour gérer les disques dynamiques Microsoft Windows, qui utilisent les métadonnées LDM de Microsoft. Il peut les inspecter, et aussi créer et supprimer des périphériques de bloc device-mapper qui peuvent être montés.

Bien qu'un système de fichiers puisse être monté en lecture-écriture et son contenu modifié, ldmtool n'est pas capable de modifier les métadonnées LDM elles-mêmes. C'est-à-dire qu'il ne peut pas créer, supprimer ou éditer des disques dynamiques.

Il n'est pas non plus capable de monter des volumes RAID5 auxquels une partition manque, bien qu'il puisse monter des volumes mis en miroir auxquels une partition manque. Cependant, monter un volume avec une partition manquante n'est pas recommandé, car ldmtool ne met pas à jour les métadonnées LDM de quelque manière que ce soit. Cela signifie que Windows n'aura aucun moyen de déterminer que les partitions ne sont pas synchronisées lors de leur montage ultérieur, ce qui peut entraîner une corruption.

INVOQUER

ldmtool peut être invoqué soit comme un shell pour exécuter plusieurs actions, soit pour exécuter une seule action et retourner. Si une action est donnée sur la ligne de commande, elle sera exécutée en mode action unique. Si aucune action n'est donnée, il lancera un shell.

Mode shell

Lorsqu'il est invoqué comme un shell, ldmtool ne scannera aucun périphérique de bloc par défaut. Si des périphériques de bloc sont donnés sur la ligne de commande avec l'option -d, ils seront scannés. Sinon, les périphériques de bloc devront être scannés explicitement avec l'action scan.

Quittez le mode shell en envoyant un EOF, ou avec les actions quit ou exit.

Mode action unique

Lorsqu'il est invoqué pour exécuter une seule action, tous les périphériques de bloc seront scannés par défaut. Dans ce cas, si des périphériques de bloc sont spécifiés avec l'option -d, seuls ces périphériques de bloc seront scannés.

RÉSULTATS

ldmtool renvoie les résultats sous forme de données formatées en JSON. Les données précises renvoyées sont décrites en détail ci-dessous. Si une commande échoue, elle ne renverra aucune donnée JSON, mais affichera un message d'erreur. En mode shell, l'échec peut être détecté par l'absence d'un résultat formaté en JSON. En mode action unique, l'appelant peut en outre vérifier le code de sortie de la commande.

ACTIONS

scan [périphérique...]

Scanne tous les [périphérique]s pour les métadonnées LDM.

Renvoie une liste de tous les GUID de groupes de disques connus. Notez qu'il ne renvoie pas uniquement les groupes de disques nouvellement découverts.

show diskgroup {GUID}

Renvoie des informations détaillées sur un seul groupe de disques.

Renvoie :

name

Le nom lisible du groupe de disques

guid

Le GUID du groupe de disques attribué par Windows

volumes

Une liste des noms de tous les volumes du groupe de disques

disks

Une liste du nom de tous les disques du groupe de disques

show volume {GUID de groupe de disques} {nom de volume}

Renvoie des informations détaillées sur un volume.

Renvoie :

name

Le nom du volume

guid

Le GUID du volume attribué par Windows

type

Le type de volume. L'un des suivants : simple , spanned , striped , mirrored , raid5

size

La taille du volume en secteurs

chunk-size

La taille des blocs, en secteurs, utilisée par les volumes striped et raid5. Pour les autres types de volumes, elle sera de 0.

hint

L'indice de montage du volume. Cette valeur spécifie comment Windows s'attend à ce que le volume soit monté. Pour un volume avec une lettre de lecteur attribuée, cela pourrait être 'E:'.

device

Le périphérique device-mapper hôte qui a été créé pour ce volume, le cas échéant (par exemple /dev/mapper/ldm_vol_Machine-Dg0_Volume1)

partitions

Une liste des noms des partitions qui constituent ce volume.

show partition {GUID de groupe de disques} {nom de partition}

Renvoie des informations détaillées sur une partition.

Renvoie :

name

Le nom de la partition

start

Le décalage, en secteurs, du début de la partition par rapport au début du disque

size

La taille de la partition en secteurs

disk

Le nom du disque sur lequel se trouve la partition

show disk {GUID de groupe de disques} {nom de disque}

Renvoie des informations détaillées sur un disque.

Renvoie :

name

Le nom lisible du disque

guid

Le GUID du disque

present

Si le disque a été découvert lors du scan : true ou false

Si le disque est présent, renvoie en plus :

device

Le nom du périphérique hôte (par exemple /dev/sda)

data-start

Le secteur de début de la partie données du disque

data-size

La taille, en secteurs, de la partie données du disque

metadata-start

Le secteur de début de la partie métadonnées du disque

metadata-size

La taille, en secteurs, de la partie métadonnées du disque

create {volume { GUID de groupe de disques } { nom de volume } | all}

Crée un périphérique device-mapper pour soit le volume spécifié, soit tous les volumes dans tous les groupes de disques détectés.

Renvoie une liste des noms de périphériques device-mapper qui ont été créés par cette action. Notez que si un périphérique existait déjà pour un volume, il ne sera pas renvoyé dans cette liste.

NOM

supprimer {volume { GUID du groupe de disques } { nom du volume } | tout}

DESCRIPTION

Supprime les périphériques device-mapper pour le volume spécifié ou pour tous les volumes de tous les groupes de disques détectés.

Retourne une liste des noms de périphériques device-mapper qui ont été supprimés par cette action. Notez que si aucun périphérique n'existait pour un volume, celui-ci ne sera pas retourné dans cette liste.

EXEMPLES

Les exemples suivants forment une séquence d'une seule session de ldmtool exécuté en mode shell.

Analyser tous les périphériques loop pour les métadonnées LDM :

ldm> scan /dev/loop[0-9]*
[
  "03c0c4fc-8b6f-402b-9431-4be2e5823b1c",
  "06495a84-fbfd-11e1-8cf9-52540061f5db"
]

Deux groupes de disques ont été détectés. La liste contient leurs GUIDs.

Afficher des informations détaillées sur l'un des groupes de disques :

ldm> show diskgroup 06495a84-fbfd-11e1-8cf9-52540061f5db
{
  "name" : "WIN-ERRDJSBDAVF-Dg0",
  "guid" : "06495a84-fbfd-11e1-8cf9-52540061f5db",
  "volumes" : [
    "Volume4",
    "Volume1",
    "Volume2",
    "Volume3",
    "Volume5"
  ],
  "disks" : [
    "Disk1",
    "Disk2",
    "Disk3",
    "Disk4",
    "Disk5",
    "Disk6",
    "Disk7",
    "Disk8",
    "Disk9"
  ]
}

Afficher des informations détaillées sur l'un des volumes du groupe de disques :

ldm> show volume 06495a84-fbfd-11e1-8cf9-52540061f5db Volume1
{
  "name" : "Volume1",
  "guid" : "c08309e9-1d30-43e5-8dc3-fcec8be76fcc",
  "type" : "spanned",
  "size" : 129024,
  "chunk-size" : 0,
  "hint" : "E:",
  "device" : "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1",
  "partitions" : [
    "Disk1-01",
    "Disk2-01"
  ]
}

Afficher des informations détaillées sur l'une des partitions du volume :

ldm> show partition 06495a84-fbfd-11e1-8cf9-52540061f5db Disk1-01
{
  "name" : "Disk1-01",
  "start" : 65,
  "size" : 96256,
  "disk" : "Disk1"
}

Afficher des informations détaillées sur le disque contenant la partition :

ldm> show disk 06495a84-fbfd-11e1-8cf9-52540061f5db Disk1
{
  "name" : "Disk1",
  "guid" : "06495a85-fbfd-11e1-8cf9-52540061f5db",
  "present" : true,
  "device" : "/dev/loop15",
  "data-start" : 63,
  "data-size" : 100289,
  "metadata-start" : 100352,
  "metadata-size" : 2048
}

Créer un périphérique device-mapper pour un volume :

ldm> create volume 06495a84-fbfd-11e1-8cf9-52540061f5db Volume1
[
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1"
]

Un nouveau périphérique device-mapper a été créé, nommé ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1. Selon la configuration d'udev, il sera probablement disponible sous /dev/mapper/ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1.

Notez que le nom retourné du périphérique device-mapper créé est décodé et peut donc contenir des caractères non autorisés. Les outils device-mapper en espace utilisateur (comme dmsetup) et la bibliothèque libdevmapper acceptent les noms décodés (s'ils sont correctement configurés) mais prenez soin de composer vous-même le chemin d'accès au périphérique créé. Envisagez d'utiliser le champ « device » de la sortie de la commande show volume.

Créer des périphériques device-mapper pour tous les volumes des deux groupes de disques :

ldm> create all
[
  "ldm_vol_Red-nzv8x6obywgDg0_Volume2",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume1",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume4",
  "ldm_vol_Red-nzv8x6obywgDg0_Stripe1",
  "ldm_vol_Red-nzv8x6obywgDg0_Raid1",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume3",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume4",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume2",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume3",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume5"
]

Notez que ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1 n'est pas dans la liste des périphériques qui ont été créés car il existait déjà.

Supprimer le périphérique device-mapper pour un volume unique :

ldm> remove volume 06495a84-fbfd-11e1-8cf9-52540061f5db Volume2
[
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume2"
]

ldm> remove all
[
  "ldm_vol_Red-nzv8x6obywgDg0_Volume2",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume1",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume4",
  "ldm_vol_Red-nzv8x6obywgDg0_Stripe1",
  "ldm_vol_Red-nzv8x6obywgDg0_Raid1",
  "ldm_vol_Red-nzv8x6obywgDg0_Volume3",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume4",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume1",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume3",
  "ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume5"
]

Notez que ldm_vol_WIN-ERRDJSBDAVF-Dg0_Volume2 n'est pas dans la liste des périphériques qui ont été supprimés, car il avait été supprimé précédemment.
