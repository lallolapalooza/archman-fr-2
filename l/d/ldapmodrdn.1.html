LDAPMODRDN(1) Manuel des commandes générales LDAPMODRDN(1)

NOM

ldapmodrdn - Outil de modification du nom usuel relatif (RDN) dans LDAP

SYNTAXE

ldapmodrdn [-V[V]] [-d niveau_debug] [-n] [-v] [-r] [-s nouv_sup] [-c] [-f fichier] [-M[M]] [-x] [-D dn_connexion] [-W] [-w motdepasse] [-y fichier_motdepasse] [-H uri_ldap] [-P {2|3}] [-e [!]ext[=param_ext]] [-E [!]ext[=param_ext]] [-o opt[=valeur_opt]] [-O proprietes_securite] [-I] [-Q] [-N] [-U cid_auth] [-R domaine] [-X zid_auth] [-Y meca] [-Z[Z]] [dn rdn]

DESCRIPTION

ldapmodrdn est une interface accessible par script pour l'appel de bibliothèque ldap_rename(3).

ldapmodrdn ouvre une connexion à un serveur LDAP, se lie, et modifie le RDN des entrées. Les informations de l'entrée sont lues depuis l'entrée standard, depuis fichier via l'option -f, ou depuis la paire d'arguments en ligne de commande dn et rdn.

OPTIONS

-V[V]
Affiche les informations de version. Si -VV est donné, seules les informations de version sont affichées.
-d niveau_debug
Définit le niveau de débogage LDAP à niveau_debug. ldapmodrdn doit être compilé avec LDAP_DEBUG défini pour que cette option ait un effet.
-n
Montre ce qui serait fait, mais ne modifie pas réellement les entrées. Utile pour le débogage en conjonction avec -v.
-v
Utilise le mode verbeux, avec de nombreux diagnostics écrits sur la sortie standard.
-r
Supprime les anciennes valeurs du RDN de l'entrée. Par défaut, les anciennes valeurs sont conservées.
-s nouv_sup
Spécifie une nouvelle entrée parente. (C'est-à-dire, déplace l'entrée cible et en fait un enfant du nouveau parent.) Cette option n'est pas supportée dans LDAPv2.
-c
Mode d'opération continue. Les erreurs sont signalées, mais ldapmodrdn continuera avec les modifications. Par défaut, le programme se termine après avoir signalé une erreur.
-f fichier
Lit les informations de modification d'entrée depuis fichier au lieu de l'entrée standard ou de la ligne de commande.
-M[M]
Active le contrôle manage DSA IT. -MM rend le contrôle critique.
-x
Utilise l'authentification simple au lieu de SASL.
-D dn_connexion
Utilise le Distinguished Name (DN) dn_connexion pour se lier au répertoire LDAP. Pour les liaisons SASL, le serveur est censé ignorer cette valeur.
-W
Demande le mot de passe pour l'authentification simple. Ceci est utilisé au lieu de spécifier le mot de passe sur la ligne de commande.
-w motdepasse
Utilise motdepasse comme mot de passe pour l'authentification simple.
-y fichier_motdepasse
Utilise le contenu complet de fichier_motdepasse comme mot de passe pour l'authentification simple.
-H uri_ldap
Spécifie une ou plusieurs URI(s) faisant référence au(x) serveur(s) ldap; seuls les champs protocole/hôte/port sont autorisés; une liste d'URI, séparées par des espaces ou des virgules, est attendue.
-P {2|3}
Spécifie la version du protocole LDAP à utiliser.
-e [!]ext[=param_ext]
-E [!]ext[=param_ext]

Spécifie les extensions générales avec -e et les extensions modrdn avec -E. ´!´ indique la criticité.

Extensions générales :

  [!]assert=<filtre>    (un filtre RFC 4515)
  !authzid=<authzid>    ("dn:<dn>" ou "u:<utilisateur>")
  [!]bauthzid           (Contrôle authzid RFC 3829)
  [!]chaining[=<resolve>[/<cont>]]
  [!]manageDSAit
  [!]noop
  ppolicy
  [!]postread[=<attributs>] (une liste d'attributs séparés par des virgules)
  [!]preread[=<attributs>]  (une liste d'attributs séparés par des virgules)
  [!]relax
  sessiontracking[=<nom_utilisateur>]
  abandon,cancel,ignore (SIGINT envoie abandon/cancel,
  ou ignore la réponse ; si critique, n'attend pas SIGINT.
  pas vraiment des contrôles)

Extensions modrdn :

  (aucune)
-o opt[=valeur_opt]

Spécifie toute option de ldap.conf(5) ou l'une des suivantes :

  nettimeout=<délai>  (en secondes, ou "none" ou "max")
  ldif_wrap=<largeur>     (en colonnes, ou "no" pour aucun retour à la ligne)
-O proprietes_securite
Spécifie les propriétés de sécurité SASL.
-I
Active le mode interactif SASL. Demande toujours. Par défaut, demande seulement si nécessaire.
-Q
Active le mode silencieux SASL. Ne demande jamais.
-N
N'utilise pas la résolution DNS inversée pour canoniser le nom d'hôte SASL.
-U cid_auth
Spécifie l'identifiant d'authentification pour la liaison SASL. La forme de l'ID dépend du mécanisme SASL réellement utilisé.
-R domaine
Spécifie le domaine de l'identifiant d'authentification pour la liaison SASL. La forme du domaine dépend du mécanisme SASL réellement utilisé.
-X zid_auth
Spécifie l'identifiant d'autorisation demandé pour la liaison SASL. zid_auth doit être l'un des formats suivants : dn:<nom distinctif> ou u:<nom d'utilisateur>
-Y meca
Spécifie le mécanisme SASL à utiliser pour l'authentification. S'il n'est pas spécifié, le programme choisira le meilleur mécanisme que le serveur connaît.
-Z[Z]
Émet l'opération étendue StartTLS (Transport Layer Security). Si vous utilisez -ZZ, la commande exigera que l'opération réussisse.

FORMAT D'ENTRÉE

Si les arguments en ligne de commande dn et rdn sont donnés, rdn remplacera le RDN de l'entrée spécifiée par le DN, dn.

Sinon, le contenu de fichier (ou de l'entrée standard si le drapeau -f n'est pas donné) doit consister en une ou plusieurs entrées.

    Nom Distinctif (DN)
    Nom Distinctif Relatif (RDN)

Une ou plusieurs lignes vides peuvent être utilisées pour séparer chaque paire DN/RDN.

EXEMPLE

En supposant que le fichier /tmp/entrymods existe et a le contenu suivant :

    cn=Modify Me,dc=example,dc=com
    cn=The New Me

La commande :

    ldapmodrdn -r -f /tmp/entrymods

modifiera le RDN de l'entrée "Modify Me" de "Modify Me" à "The New Me" et l'ancien cn, "Modify Me", sera supprimé.

DIAGNOSTICS

Le statut de sortie est 0 si aucune erreur ne se produit. Les erreurs entraînent un statut de sortie non nul et un message de diagnostic écrit sur la sortie d'erreur standard.
