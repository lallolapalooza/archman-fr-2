RZ(1) Manuel des commandes générales RZ(1)

NOM

rx, rb, rz - Réception de fichiers XMODEM, YMODEM, ZMODEM (Batch)

SYNTAXE

rz [- +8abeOpqRtTuUvy]
rb [- +abqRtuUvy]
rx [- abceqRtuUv] fichier
[-][v]rzCOMMANDE

DESCRIPTION

Ce programme utilise des protocoles de correction d'erreurs pour recevoir des fichiers via un port série entrant depuis divers programmes fonctionnant sous PC-DOS, CP/M, Unix, et d'autres systèmes d'exploitation. Il est invoqué depuis une invite de commande shell manuellement, ou automatiquement suite à une commande "sz fichier ..." donnée au programme appelant.

Bien que rz soit suffisamment intelligent pour être appelé depuis cu(1), très peu de versions de cu(1) sont suffisamment intelligentes pour permettre à rz de fonctionner correctement. Des versions Unix de Professional-YAM sont disponibles pour de telles applications d'appel sortant.

Rz (Receive ZMODEM) reçoit des fichiers avec le protocole batch ZMODEM. Les noms de chemins sont fournis par le programme émetteur, et les répertoires sont créés si nécessaire (et possible). Normalement, la commande "rz" est automatiquement émise par le programme ZMODEM appelant, mais certaines implémentations ZMODEM défectueuses peuvent nécessiter de lancer rz à l'ancienne.

Rb reçoit des fichiers avec YMODEM, acceptant soit des secteurs standard de 128 octets, soit des secteurs de 1024 octets (option sb -k de YAM). L'utilisateur doit déterminer quand la longueur de bloc de 1024 octets améliore réellement le débit sans causer de perte de données ou même des plantages système.

Si les informations de fichier True YMODEM (marque déposée Omen Technology) (longueur du fichier, etc.) sont reçues, la longueur du fichier contrôle le nombre d'octets écrits dans le jeu de données de sortie, et l'heure de modification et le mode de fichier (si non nuls) sont définis en conséquence.

Si aucune information de fichier True YMODEM n'est reçue, les barres obliques dans le nom de chemin sont remplacées par des tirets bas, et tout point final dans le nom de chemin est éliminé. Cette conversion est utile pour les fichiers reçus depuis des systèmes CP/M. Avec YMODEM, chaque nom de fichier est converti en minuscules, sauf s'il contient une ou plusieurs lettres minuscules.

Rx reçoit un seul fichier avec le protocole XMODEM ou XMODEM-1k. L'utilisateur doit déterminer quand la longueur de bloc de 1024 octets améliore réellement le débit sans causer de problèmes. L'utilisateur doit fournir le nom du fichier aux programmes émetteur et récepteur. Jusqu'à 1023 caractères parasites peuvent être ajoutés au fichier reçu.

Rz peut être invoqué comme rzCOMMANDE (avec un tiret optionnel en préfixe généré par login(1)). Pour chaque fichier reçu, rz redirigera le fichier vers ``COMMANDE nom_fichier'' où nom_fichier est le nom du fichier transmis avec le contenu du fichier comme entrée standard.

Chaque transfert de fichier est acquitté lorsque COMMANDE se termine avec un statut 0. Un statut de sortie non nul termine les transferts.

Une utilisation typique de cette forme est rzrmail qui appelle rmail(1) pour poster un courrier à l'utilisateur spécifié par le nom de fichier transmis. Par exemple, l'envoi du fichier "caf" depuis un système PC-DOS vers rzrmail sur un système Unix entraînerait le courrier du contenu du fichier DOS "caf" à l'utilisateur "caf".

Sur certains systèmes Unix, le répertoire de connexion doit contenir un lien symbolique vers COMMANDE car login définit SHELL=rsh, ce qui interdit les chemins absolus. Si invoqué avec un "v" en préfixe, rz sera verbeux (voir l'option v). L'entrée suivante fonctionne pour Unix SYS III/V :
rzrmail::5:1::/usr/local:/usr/local/rzrmail
Si la variable d'environnement SHELL inclut rsh, rbash ou rksh (shell restreint), rz n'acceptera pas les chemins absolus ni les références à un répertoire parent, ne modifiera pas un fichier existant et supprimera tous les fichiers reçus par erreur.

Si rz est invoqué avec stdout et stderr vers des jeux de données différents, Verbose est réglé sur 2, provoquant des rapports de progression image par image sur stderr. Ceci peut être désactivé avec l'option q.

OPTIONS

Les significations des options disponibles sont :

-+, --append
ajouter les données reçues à un fichier existant (ZMODEM, ASCII seulement).
-a, --ascii
Convertir les fichiers selon les conventions Unix en supprimant les retours chariot et tous les caractères commençant par le premier Contrôle Z (fin de fichier CP/M).
-b, --binary
Priorité au transfert de fichier binaire (tel quel).
-B NOMBRE, --bufsize NOMBRE
Mettre en mémoire tampon NOMBRE octets avant d'écrire sur le disque. La valeur par défaut est 32768, ce qui devrait suffire dans la plupart des situations. Si vous avez une machine lente, une mauvaise interface disque, ou rencontrez d'autres problèmes matériels, vous pourriez vouloir augmenter la taille du tampon. -1 ou auto utilisent un tampon suffisamment grand pour contenir tout le fichier. Soyez prudent avec ces options - les choses s'aggravent généralement, pas s'améliorent, si la machine commence à swapper.
-c, --with-crc
XMODEM uniquement. Utiliser une CRC 16 bits (normalement une somme de contrôle d'un octet est utilisée).
-C, --allow-remote-commands
autoriser l'exécution de commandes à distance (non sécurisé). Cela permet à l'expéditeur d'exécuter une commande arbitraire via system() ou execl(). Par défaut, cette fonctionnalité est désactivée (?). Cette option est ignorée si elle est exécutée en mode restreint.
-D, --null
Envoyer les données du fichier de sortie vers /dev/null ; pour les tests. (Unix uniquement)
--delay-startup N
Attendre N secondes avant toute action.
-e, --escape
Forcer l'expéditeur à échapper tous les caractères de contrôle ; normalement XON, XOFF, DLE, CR-@-CR, et Ctrl-X sont échappés.
-E, --rename
Renommer le fichier entrant si le nom de fichier cible existe déjà. Le nouveau nom de fichier aura un point et un numéro (0..999) ajoutés.
-h, --help
afficher l'écran d'aide.
-m N, --min-bps N
Arrêter la transmission si le débit en BPS (octets par seconde) tombe en dessous de N pendant un certain temps (voir l'option --min-bps-time).
-M N, --min-bps-time
Utilisé conjointement avec --min-bps. La valeur par défaut est 120 (secondes).
-O, --disable-timeouts
Désactiver la gestion des délais de lecture. Cela fait que lrz se bloque si l'expéditeur n'envoie plus rien, mais augmente les performances (un peu) et diminue la charge système (en réduisant le nombre d'appels système d'environ 50%).

Utilisez cette option avec prudence.

--o-sync
Ouvrir les fichiers de sortie en mode écriture synchrone. Cela peut être utile si vous rencontrez des erreurs dues à des interruptions perdues lorsque update (ou bdflush ou quel que soit le nom de ce démon sur votre système) écrit les tampons sur le disque.

Cette option est ignorée et un avertissement est imprimé si votre système ne prend pas en charge O_SYNC.

-p, --protect
(ZMODEM) Protéger : ignorer le fichier si le fichier de destination existe.
-q, --quiet
Silencieux supprime la verbosité.
-r, --resume
Mode de récupération après crash. lrz tente de reprendre les transferts de fichiers interrompus.
-R, --restricted
Entrer dans un mode plus restreint. lrz ne créera pas de répertoires ni de fichiers commençant par un point si cette option est donnée deux fois.

Voir SÉCURITÉ pour des informations sur le mode restreint.

-s HH:MM, --stop-at HH:MM
Arrêter la transmission à HH heures, MM minutes. Une autre variante, utilisant +N au lieu de HH:MM, arrête la transmission en N secondes.
-S, --timesync
Demander un paquet de synchronisation horaire à l'expéditeur. L'expéditeur envoie son heure système, obligeant lrz à se plaindre d'une différence de plus de 60 secondes.

Lrz essaie de régler l'heure système locale sur l'heure distante si cette option est donnée deux fois (cela échoue si lrz n'est pas exécuté par root).

SECURITY

Contrary to the original ZMODEM lrz defaults to restricted mode. In restricted mode lrz will not accept absolute pathnames or references to a parent directory, will not modify an existing file, and removes any files received in error. Remote command execution is disabled.

To use a more restricted mode set the environment variable ZMODEM_RESTRICTED or give the R option. This disables creation of subdirectories and invisible files.

Restricted mode may be turned off with the U option, unless lrz runs under a restricted shell.

Use of the
--tcp-client or --tcp-server options imposes a security risk, as somebody else could connect to the port before you do it, and grab your data. If there's strong demand for a more secure mode i might introduce some sort of password challenge.

ENVIRONMENT

lrz uses the following environment variables:

SHELL
lrz recognizes a restricted shell if this variable includes rsh or rksh
ZMODEM_RESTRICTED
lrz enters the more restricted mode if the variable is set.

NOTES

Sending serial data to timesharing minicomputers at sustained high speeds has been known to cause lockups, system halts, kernel panics, and occasional antisocial behaviour. When experimenting with high speed input to a system, consider rebooting the system if the file transfers are not successful, especially if the personality of the system appears altered.

The Unix "ulimit" parameter must be set high enough to permit large file transfers.

The TTY input buffering on some systems may not allow long blocks or streaming input at high speed. You should suspect this problem when you can't send data to the Unix system at high speeds using ZMODEM, YMODEM-1k or XMODEM-1k, when YMODEM with 128 byte blocks works properly. If the system's tty line handling is really broken, the serial port or the entire system may not survive the onslaught of long bursts of high speed data.

The DSZ or Pro-YAM zmodem l numeric parameter may be set to a value between 64 and 1024 to limit the burst length ("zmodem pl128").

BUGS

Calling rz from most versions of cu(1) doesn't work because cu's receive process fights rz for characters from the modem.

Programs that do not properly implement the specified file transfer protocol may cause sz to "hang" the port for a minute or two. Every reported instance of this problem has been corrected by using ZCOMM, Pro-YAM, or other program with a correct implementation of the specified protocol.

Many programs claiming to support YMODEM only support XMODEM with 1k blocks, and they often don't get that quite right.

Pathnames are restricted to 127 characters. In XMODEM single file mode, the pathname given on the command line is still processed as described above. The ASCII option´s CR/LF to NL translation merely deletes CR´s; undos(omen) performs a more intelligent translation.

VMS VERSION

The VMS version does not set the file time.

VMS C Standard I/O and RMS may interact to modify file contents unexpectedly.

The VMS version does not support invocation as rzCOMMAND . The current VMS version does not support XMODEM, XMODEM-1k, or YMODEM.

According to the VMS documentation, the buffered input routine used on the VMS version of rz introduces a delay of up to one second for each protocol transaction. This delay may be significant for very short files. Removing the "#define BUFREAD" line from rz.c will eliminate this delay at the expense of increased CPU utilization.

The VMS version causes DCL to generate a random off the wall error message under some error conditions; this is a result of the incompatibility of the VMS "exit" function with the Unix/MSDOS standard.

ZMODEM CAPABILITIES

Rz supports incoming ZMODEM binary (-b), ASCII (-a), protect (-p), clobber (-y), and append (-+) requests. The default is protect (-p) and binary (-b).

The Unix versions support ZMODEM command execution.
