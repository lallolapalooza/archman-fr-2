NOM

lr_anonymize - anonymiser un fichier journal

SYNTAXE

lr_anonymize préfixe_fichier_dump

DESCRIPTION

lr_anonymize est généralement utilisé lors de l'envoi de journaux à un répondeur. Voir la section sur l'« Envoi de fichiers journaux anonymisés à un répondeur » dans le chapitre sur l'« Utilisation d'un répondeur » du Manuel de l'utilisateur de Lire pour des exemples d'utilisation.

lr_anonymize lit un fichier contenant des adresses e-mail, des numéros IP et des noms d'hôtes (typiquement un fichier journal d'un service Internet) depuis l'entrée standard, et imprime une version « anonymisée » de ce fichier sur la sortie standard. Il sauvegarde les informations pour pouvoir « désanonymiser » le fichier, en utilisant lr_deanonymize(1), dans 5 bases de données Berkeley DB ; les noms des fichiers contenant ces bases de données sont construits en concaténant les chaînes 'inaddr', 'maildomain', 'email', 'ip' et 'domain' au préfixe_fichier_dump. préfixe_fichier_dump peut être, par exemple, /tmp/dump, ../../var/dump ou dump. Les fichiers db créés écrasent silencieusement ceux qui sont obsolètes, s'ils sont trouvés.

Le script crée des fichiers temporaires. Par défaut, ils sont créés dans /tmp. Il est possible de remplacer ce comportement en définissant la variable d'environnement TMPDIR.

LIEN AVEC lr_deanonymize

Lorsque vous exécutez

$ lr_anonymize dump < log > log.anon
$ lr_deanonymize dump < log.anon > log.new

alors log et log.new auront le même contenu (sauf pour la casse, vérifiez avec diff -i).

NOTES

Nous avons essayé d'optimiser ce script pour l'utilisation de la mémoire. Cela a pour inconvénient que le script prendra pas mal de temps lors de l'anonymisation d'un gros fichier journal.

Nous avons exécuté le script sur un fichier journal sendmail de 25 Mo.

Les valeurs typiques dans un tel cas sont 2500 Ko pour la quantité totale de mémoire physique utilisée, et 15m réel, 8m utilisateur et 22s système sur un système de 64 Mo avec un processeur Pentium II de 300 MHz. La désanonymisation de ce fichier a pris 11m réel, 8m utilisateur et 17s système.

Nous sauvegardons les noms de domaine de messagerie dans le fichier dump. Ceux-ci sont utilisés par lr_deanonymize(1), au cas où les adresses e-mail de notre fichier d'entrée réapparaissent dans le fichier lu par lr_deanonymize(1) sous forme fragmentée, c'est-à-dire que joe.user@example.com apparaît sous la forme joe.user@example.com et example.com dans le fichier à désanonymiser.

Tous les objets sauvegardés sont convertis en minuscules.

BOGUES

Nous ne pouvons pas traiter les fichiers contenant des noms d'hôtes ou des adresses e-mail dans le domaine example.com, des noms d'utilisateurs de la forme john.doe.<quelques lettres> ou des numéros IP du réseau privé rfc 1918 10.0.0.0 - 10.255.255.255 (préfixe 10/8).

Nous ne gérons pas les chaînes entre guillemets ('quoted-string') dans les adresses e-mail. Nous ne gérons pas les littéraux de domaine dans le domaine des adresses e-mail.

Nous considérons 999.999.999.999 comme une adresse IP : la limite de 255 ne nous dérange pas.

Nous ne traitons pas les adresses IP de réseau comme 100.10.3 comme des adresses IP. Celles-ci ne seront *pas* anonymisées.

lr_anonymize(1)

NAME

lr_anonymize - Anonymize the traffic in a librefox trace

SYNOPSIS

lr_anonymize [OPTIONS] TRACE

DESCRIPTION

lr_anonymize anonymizes the traffic in a librefox trace. This is useful for sharing traces without revealing sensitive information.

The anonymization process replaces sensitive information such as IP addresses, hostnames, and URLs with fake data. The original data is not recoverable.

CONNECTION WITH lr_deanonymize

The anonymization is reversible using lr_deanonymize(1). This tool requires the same key and identifier used during anonymization.

NOTES

The anonymization process uses a key and an identifier to generate reproducible fake data. If you lose the key or identifier, you will not be able to deanonymize the trace.

It is recommended to use a strong key and a unique identifier for each trace to ensure the security of the anonymization.

BACKGROUND

Librefox is a web browser designed for privacy and security. It generates traces of network traffic that can be used for debugging and analysis. However, these traces may contain sensitive information that should not be shared publicly.

EXAMPLE

To anonymize a trace file named trace.log with a key mysecretkey and identifier trace123:

lr_anonymize --key mysecretkey --id trace123 trace.log

BUGS

Report bugs to <https://github.com/librefox/librefox/issues>

lr_anonymize(1)

NOM

lr_anonymize - Anonymiser le trafic dans une trace librefox

SYNTAXE

lr_anonymize [OPTIONS] TRACE

DESCRIPTION

lr_anonymize anonymise le trafic dans une trace librefox. Ceci est utile pour partager des traces sans révéler d'informations sensibles.

Le processus d'anonymisation remplace les informations sensibles telles que les adresses IP, les noms d'hôtes et les URL par des données fictives. Les données d'origine ne sont pas récupérables.

LIEN AVEC lr_deanonymize

L'anonymisation est réversible à l'aide de lr_deanonymize(1). Cet outil nécessite la même clé et le même identifiant utilisés lors de l'anonymisation.

NOTES

Le processus d'anonymisation utilise une clé et un identifiant pour générer des données fictives reproductibles. Si vous perdez la clé ou l'identifiant, vous ne pourrez pas désanonymiser la trace.

Il est recommandé d'utiliser une clé forte et un identifiant unique pour chaque trace afin d'assurer la sécurité de l'anonymisation.

CONTEXTE

Librefox est un navigateur web conçu pour la confidentialité et la sécurité. Il génère des traces de trafic réseau qui peuvent être utilisées pour le débogage et l'analyse. Cependant, ces traces peuvent contenir des informations sensibles qui ne doivent pas être partagées publiquement.

EXEMPLE

Pour anonymiser un fichier de trace nommé trace.log avec la clé mysecretkey et l'identifiant trace123 :

lr_anonymize --key mysecretkey --id trace123 trace.log

BOGUES

Signalez les bogues à <https://github.com/librefox/librefox/issues>
