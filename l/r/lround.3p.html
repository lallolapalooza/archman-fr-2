LROUND(3P) Manuel du programmeur POSIX LROUND(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

lround, lroundf, lroundl — arrondir à la valeur entière la plus proche

SYNTAXE

#include <math.h>
long lround(double x);
long lroundf(float x);
long lroundl(long double x);

DESCRIPTION

Les fonctionnalités décrites sur cette page de référence sont alignées sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 renvoie à la norme ISO C.

Ces fonctions doivent arrondir leur argument à la valeur entière la plus proche, en arrondissant les cas intermédiaires (milieu) à l'opposé de zéro, indépendamment de la direction d'arrondi actuelle.

Une application souhaitant vérifier les situations d'erreur doit initialiser errno à zéro et appeler feclearexcept(FE_ALL_EXCEPT) avant d'appeler ces fonctions. Au retour, si errno est différent de zéro ou si fetestexcept(FE_INVALID | FE_DIVBYZERO | FE_OVERFLOW | FE_UNDERFLOW) est différent de zéro, une erreur s'est produite.

VALEUR DE RETOUR

En cas de succès, ces fonctions doivent retourner la valeur entière arrondie.

Si x est NaN, une erreur de domaine doit se produire et une valeur non spécifiée est retournée.

Si x est +Inf, une erreur de domaine doit se produire et une valeur non spécifiée est retournée.

Si x est -Inf, une erreur de domaine doit se produire et une valeur non spécifiée est retournée.

Si la valeur correcte est positive et trop grande pour être représentée comme un long, une valeur non spécifiée doit être retournée. Sur les systèmes qui prennent en charge l'option de virgule flottante IEC 60559, un domaine doit se produire ; sinon, une erreur de domaine peut se produire.

Si la valeur correcte est négative et trop grande pour être représentée comme un long, une valeur non spécifiée doit être retournée. Sur les systèmes qui prennent en charge l'option de virgule flottante IEC 60559, un domaine doit se produire ; sinon, une erreur de domaine peut se produire.

ERREURS

Ces fonctions doivent échouer si :

Erreur de domaine
L'argument x est NaN ou ±Inf, ou la valeur correcte n'est pas représentable sous forme d'entier.

Si l'expression entière (math_errhandling & MATH_ERRNO) est différente de zéro, alors errno doit être défini à [EDOM]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est différente de zéro, alors l'exception de virgule flottante invalide doit être levée.

Ces fonctions peuvent échouer si :

Erreur de domaine
La valeur correcte n'est pas représentable sous forme d'entier.

Si l'expression entière (math_errhandling & MATH_ERRNO) est différente de zéro, alors errno doit être défini à [EDOM]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est différente de zéro, alors l'exception de virgule flottante invalide doit être levée.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATION

En cas d'erreur, les expressions (math_errhandling & MATH_ERRNO) et (math_errhandling & MATH_ERREXCEPT) sont indépendantes l'une de l'autre, mais au moins une d'entre elles doit être différente de zéro.

RATIONALE

Ces fonctions diffèrent des fonctions lrint() par la direction d'arrondi par défaut, les fonctions lround() arrondissant les cas intermédiaires à l'opposé de zéro et n'ayant pas besoin de lever l'exception de virgule flottante inexacte pour les arguments non entiers qui s'arrondissent dans la plage du type de retour.
