l2cap(7) Administration système Linux l2cap(7)

Nom

l2cap - Protocole L2CAP

Syntaxe

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/l2cap.h>
l2cap_socket = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_L2CAP);

Description

L2CAP est un protocole qui fournit une interface pour que les protocoles de plus haut niveau envoient et reçoivent des données sur une connexion Bluetooth. L2CAP se situe au-dessus de l'interface hôte-contrôleur Bluetooth (HCI) et fournit un ensemble de canaux qui peuvent être utilisés par les protocoles de plus haut niveau pour transmettre des données.

L2CAP fournit un certain nombre de services aux protocoles de plus haut niveau, y compris la segmentation et le réassemblage des gros paquets de données, ainsi que le contrôle de flux pour éviter de surcharger le récepteur. L2CAP prend également en charge plusieurs canaux par connexion, permettant une transmission de données simultanée à l'aide de différents protocoles.

Adresse Socket

struct sockaddr_l2 {
    sa_family_t     l2_family;
    unsigned short  l2_psm;
    bdaddr_t        l2_bdaddr;
    unsigned short  l2_cid;
    uint8_t         l2_bdaddr_type;
};

Exemple :

struct sockaddr_l2 addr;
memset(&addr, 0, sizeof(addr));
addr.l2_family = AF_BLUETOOTH;
bacpy(&addr.l2_bdaddr, bdaddr);
if (cid)
    addr.l2_cid = htobs(cid);
else
    addr.l2_psm = htobs(psm);
addr.l2_bdaddr_type = bdaddr_type;

Options Socket (SOL_BLUETOOTH)

Les options de socket listées ci-dessous peuvent être définies à l'aide de setsockopt(2) et lues avec getsockopt(2) avec le niveau de socket défini sur SOL_BLUETOOTH.

BT_SECURITÉ (depuis Linux 2.6.30)

Niveau de sécurité du canal, valeurs possibles :

Valeur Niveau de sécurité Type de clé de lien Chiffrement
BT_SECURITY_SDP 0 (SDP uniquement) Aucun Non requis
BT_SECURITY_LOW 1 (Bas) Non authentifié Non requis
BT_SECURITY_MEDIUM 2 (Moyen - par défaut) Non authentifié Désiré
BT_SECURITY_HIGH 3 (Élevé) Authentifié Requis
BT_SECURITY_FIPS (depuis Linux 3.15) 4 (Sécurisé uniquement) Authentifié (Pairage Simple Sécurisé basé sur P-256 et Authentification Sécurisée) Requis

Exemple :

int level = BT_SECURITY_HIGH;
int err = setsockopt(l2cap_socket, SOL_BLUETOOTH, BT_SECURITY, &level,
                     sizeof(level));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

BT_REMISE_EN_ATTENTE_SETUP (depuis Linux 2.6.30)

Report de l'établissement de la connexion du canal, cela contrôle si la procédure de connexion doit être autorisée par l'espace utilisateur avant de répondre, ce qui permet l'autorisation au niveau du profil, valeurs possibles :

Valeur Description Autorisation
0 Désactivé (par défaut) Non requis
1 Activé Requis

Exemple :

int defer_setup = 1;
int err = setsockopt(l2cap_socket, SOL_BLUETOOTH, BT_DEFER_SETUP,
                     &defer_setup, sizeof(defer_setup));
if (err == -1) {
    perror("setsockopt");
    return err;
}
err = listen(l2cap_socket, 5);
if (err) {
    perror("listen");
    return err;
}
struct sockaddr_l2 remote_addr = {0};
socklen_t addr_len = sizeof(remote_addr);
int new_socket = accept(l2cap_socket, (struct sockaddr*)&remote_addr,
                        &addr_len);
if (new_socket < 0) {
    perror("accept");
    return new_socket;
}
/* Pour terminer l'établissement de la connexion de new_socket, lisez 1 octet */
char c;
struct pollfd pfd;
memset(&pfd, 0, sizeof(pfd));
pfd.fd = new_socket;
pfd.events = POLLOUT;
err = poll(&pfd, 1, 0);
if (err) {
    perror("poll");
    return err;
}
if (!(pfd.revents & POLLOUT)) {
    err = read(sk, &c, 1);
    if (err < 0) {
        perror("read");
        return err;
    }
}

BT_FLUSHABLE (depuis Linux 2.6.39)

Indicateur de canal vidable, cela contrôle si les données du canal peuvent être vidées ou non, valeurs possibles :

Définition Valeur Description
BT_FLUSHABLE_OFF 0x00 (par défaut) Ne pas vider les données
BT_FLUSHABLE_ON 0x01 Vider les données

BT_POWER (depuis Linux 3.1)

Politique d'alimentation du canal, cela contrôle si le canal doit forcer la sortie du mode sniff ou non, valeurs possibles :

Définition Valeur Description
BT_POWER_FORCE_ACTIVE_OFF 0x00 Ne pas forcer la sortie du mode sniff
BT_POWER_FORCE_ACTIVE_ON 0x01 (par défaut) Forcer la sortie du mode sniff

BT_POLITIQUE_CANAL (depuis Linux 3.10)

Politique de canal haute vitesse (AMP), valeurs possibles :

Définition Valeur Description
BT_CHANNEL_POLICY_BREDR_ONLY 0 (par défaut) BR/EDR uniquement
BT_CHANNEL_POLICY_BREDR_PREFERRED 1 BR/EDR Préféré
BT_CHANNEL_POLICY_BREDR_PREFERRED 2 AMP Préféré

BT_PHY (depuis Linux 5.10)

PHY(s) supporté(s) par le canal, valeurs possibles :

Définir Valeur Description
BT_PHY_BR_1M_1SLOT BIT 0 BR 1Mbps 1SLOT
BT_PHY_BR_1M_3SLOT BIT 1 BR 1Mbps 3SLOT
BT_PHY_BR_1M_5SLOT BIT 2 BR 1Mbps 5SLOT
BT_PHY_BR_2M_1SLOT BIT 3 EDR 2Mbps 1SLOT
BT_PHY_BR_2M_3SLOT BIT 4 EDR 2Mbps 3SLOT
BT_PHY_BR_2M_5SLOT BIT 5 EDR 2Mbps 5SLOT
BT_PHY_BR_3M_1SLOT BIT 6 EDR 3Mbps 1SLOT
BT_PHY_BR_3M_3SLOT BIT 7 EDR 3Mbps 3SLOT
BT_PHY_BR_3M_5SLOT BIT 8 EDR 3Mbps 5SLOT
BT_PHY_LE_1M_TX BIT 9 LE 1Mbps TX
BT_PHY_LE_1M_RX BIT 10 LE 1Mbps RX
BT_PHY_LE_2M_TX BIT 11 LE 2Mbps TX
BT_PHY_LE_2M_RX BIT 12 LE 2Mbps RX
BT_PHY_LE_CODED_TX BIT 13 LE Coded TX
BT_PHY_LE_CODED_RX BIT 14 LE Coded RX

BT_MODE (depuis Linux 5.10)

Mode de canal, valeurs possibles :

Définir Valeur Description Lien
BT_MODE_BASIC 0x00 (par défaut) Mode de base Any
BT_MODE_ERTM 0x01 Mode de retransmission amélioré BR/EDR
BT_MODE_STREAM 0x02 Mode flux BR/EDR
BT_MODE_LE_FLOWCTL 0x03 Mode de contrôle de flux basé sur les crédits LE
BT_MODE_EXT_FLOWCTL 0x04 Mode de contrôle de flux étendu basé sur les crédits Any

OPTIONS SOCKET (SOL_SOCKET)

Les options de socket de niveau SOL_SOCKET qui modifient les fonctionnalités génériques du socket (SO_SNDBUF, SO_RCVBUF, etc.) ont leur signification habituelle, voir socket(7).

Les options de socket L2CAP de niveau SOL_SOCKET qui ont une gestion spécifique Bluetooth dans le noyau sont listées ci-dessous.

SO_TIMESTAMPING, SO_TIMESTAMP, SO_TIMESTAMPNS

Voir https://docs.kernel.org/networking/timestamping.html

Pour les sockets L2CAP, les horodatages RX logiciels sont pris en charge. Les horodatages TX logiciels (SOF_TIMESTAMPING_TX_SOFTWARE, SOF_TIMESTAMPING_TX_COMPLETION) sont pris en charge depuis Linux 6.15.

L'horodatage RX logiciel est le moment où le noyau a reçu le paquet du pilote du contrôleur.

L'horodatage SCM_TSTAMP_SND est émis lorsque le paquet est envoyé au pilote du contrôleur. L'horodatage SCM_TSTAMP_COMPLETION est émis lorsque le contrôleur signale que le paquet est terminé. Les autres types d'horodatage TX ne sont pas pris en charge.

Vous pouvez utiliser SIOCETHTOOL pour interroger les drapeaux supportés.

Les horodatages sont en temps CLOCK_REALTIME.

Exemple (Activation des horodatages RX) :

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_RX_SOFTWARE;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Exemple (Lecture d'un paquet et de son horodatage RX) :

char data_buf[256];
union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = data_buf,
    .iov_len = sizeof(data_buf),
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct scm_timestamping tss;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
}
tstamp_clock_realtime = tss.ts[0];

Exemple (Activation des horodatages TX) :

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_TX_SOFTWARE |
    SOF_TIMESTAMPING_TX_COMPLETION |
    SOF_TIMESTAMPING_OPT_ID;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Exemple (Lecture des horodatages TX) :

union {
    char buf[2 * CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = NULL,
    .iov_len = 0
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct cmsghdr *cmsg;
struct scm_timestamping tss;
struct sock_extended_err serr;
int res;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
    else if (cmsg->cmsg_level == SOL_BLUETOOTH && cmsg->cmsg_type == BT_SCM_ERROR)
        memcpy(&serr, CMSG_DATA(cmsg), sizeof(serr));
}
tstamp_clock_realtime = tss.ts[0];
tstamp_type = serr->ee_info;      /* SCM_TSTAMP_SND ou SCM_TSTAMP_COMPLETION */
tstamp_seqnum = serr->ee_data;

IOCTLS

Les ioctls suivants, avec des opérations spécifiques pour les sockets L2CAP, sont disponibles.

SIOCETHTOOL (depuis Linux 6.16-rc1)

Ne prend en charge que la commande ETHTOOL_GET_TS_INFO, qui peut être utilisée pour interroger les drapeaux SOF_TIMESTAMPING_* supportés. Les drapeaux SOF_TIMESTAMPING_OPT_* sont toujours disponibles le cas échéant.

Exemple :

#include <linux/ethtool.h>
#include <linux/sockios.h>
#include <net/if.h>
#include <sys/socket.h>
#include <sys/ioctl.h>
...
struct ifreq ifr = {};
struct ethtool_ts_info cmd = {};
int sk;
snprintf(ifr.ifr_name, sizeof(ifr.ifr_name), "hci0");
ifr.ifr_data = (void *)&cmd;
cmd.cmd = ETHTOOL_GET_TS_INFO;
sk = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_L2CAP);
if (sk < 0)
    goto error;
if (ioctl(sk, SIOCETHTOOL, &ifr))
    goto error;
sof_available = cmd.so_timestamping;
