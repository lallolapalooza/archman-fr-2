NOM

libnbd-release-notes-1.22 - notes de publication pour libnbd 1.22

DESCRIPTION

Ce sont les notes de publication pour la version stable de libnbd 1.22. Ceci décrit les changements majeurs depuis la version 1.20.

libnbd 1.22.0 a été publié le 11 février 2025.

Sécurité

Plusieurs failles dans la vérification des certificats de serveur TLS ont été découvertes et corrigées (CVE-2024-7383). Voir https://lists.libguestfs.org/archives/list/guestfs@lists.libguestfs.org/thread/LHR3BW6RJ7K4BJBQIYV3GTZLSY27VZO2/ (remerciements à Jon Szymaniak, Daniel P. Berrangé).

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour connaître les problèmes de sécurité précédents dans libnbd, voir libnbd-security(3).

Nouvelles API

nbd_set_tls_hostname(3) et nbd_get_tls_hostname(3) peuvent être utilisées pour définir et obtenir le nom d'hôte utilisé pour la vérification des certificats de serveur TLS. Ce nom d'hôte, s'il est défini, est utilisé de préférence au nom d'hôte du serveur. Ceci peut être utilisé lorsque les connexions NBD sont proxifiées ou transportées via un socket de domaine Unix.

nbd_is_uri(3) applique une heuristique pour détecter si quelque chose ressemble probablement à un URI NBD ou non.

nbd_get_subprocess_pid(3) renvoie l'identifiant de processus (PID) du sous-processus créé par des fonctions telles que nbd_connect_command(3).

Améliorations des API existantes

En tant qu'extension de nbd_connect_uri(3), vous pouvez maintenant vous connecter à des URI "nbd+ssh://" ou "nbds+ssh://", créant ainsi un tunnel NBD via une connexion SSH. C'est très pratique lorsque vous avez un accès SSH à un hôte distant, mais qu'un pare-feu empêche l'accès direct aux ports NBD.

Protocole

Nous imprimons maintenant le message d'erreur complet s'il est envoyé par le serveur. nbdkit ≥ 1.42 enverra les messages d'erreur complets des plugins via la connexion NBD aux clients NBD compatibles comme libnbd 1.22 ou qemu.

Outils

Correction de nbdfuse(1) afin que les URI TLS utilisant "?tls-certificates" ou "?tls-psk-file" fonctionnent maintenant correctement (Jon Szymaniak).

nbddump(1) a une nouvelle option --offset (Eric Blake).

Bindings linguistiques

Corrections diverses des bindings Rust (remerciements à Hanna Czenczek).

La documentation incluse dans les bindings Rust a été grandement améliorée.

Autres améliorations et corrections de bugs

Le code commun est maintenant utilisé pour obtenir la taille des périphériques de bloc, et cela a été corrigé pour fonctionner correctement sur BSD. Cela affectait au moins nbdcopy lorsqu'il était utilisé pour copier vers et depuis des périphériques de bloc sur BSD.

Documentation

Correction des liens vers nbd-server(1) et d'autres pages dans la documentation générée en HTML (Vera Wu).

Dans nbd_connect_uri(3), nous avons documenté de légères différences dans la manière dont nous analysons les URI NBD par rapport à qemu.

nbd_connect_uri(3) ajoute une documentation supplémentaire sur les numéros de port VSock réservés.

Compilation

gnutls ≥ 3.5.18 est maintenant requis. Cela correspond à la version requise par qemu. Si vous utilisez RHEL, cela signifie que RHEL ≥ 8 est maintenant requis.

libnbd devrait maintenant compiler sur macOS.

examples/connect-benchmark est un nouvel exemple qui peut être utilisé pour évaluer la performance des connexions.

Ajout du support pour GCC 15.
