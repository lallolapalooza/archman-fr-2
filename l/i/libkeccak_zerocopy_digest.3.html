LIBKECCAK_ZEROCOPY_DIGEST(3) Manuel des fonctions de bibliothèque LIBKECCAK_ZEROCOPY_DIGEST(3)

NOM

libkeccak_zerocopy_digest - Complète le hachage d'un message sans copie (AVANCÉ)

SYNTAXE

#include <libkeccak.h>
void libkeccak_zerocopy_digest(struct libkeccak_state *state, void *msg, size_t msglen,
                               size_t bits, const char *suffix, void *hashsum);

Lier avec -lkeccak.

DESCRIPTION

La fonction libkeccak_zerocopy_digest() absorbe la dernière partie d'un message (ou l'intégralité) et retourne le hachage du message entier. La dernière partie du message est spécifiée par le paramètre msg, et sa taille en octets est spécifiée par le paramètre msglen. Si tout le message a déjà été traité par des appels à la fonction libkeccak_zerocopy_update(3) (avec le même pointeur sur state), msg et msglen doivent être définis à NULL et 0, respectivement.

Si le message n'est pas composé d'un nombre entier d'octets, le nombre de bits, modulo 8, dans le message doit être spécifié dans le paramètre bits. msglen ne doit compter que le nombre d'octets entiers, c'est-à-dire le plancher du nombre de bits dans le message divisé par 8.

suffix doit être une chaîne terminée par NUL de '1' et '0' ASCII, représentant les bits qui doivent être ajoutés au message. Si cette chaîne est vide, NULL peut être utilisé à la place. Ceci est utilisé pour sélectionner l'algorithme de hachage. Pour Keccak pur, NULL ou "" est utilisé. Pour les autres algorithmes, les constantes LIBKECCAK_SHA3_SUFFIX (pour SHA-3), LIBKECCAK_RAWSHAKE_SUFFIX (pour RawSHAKE), et LIBKECCAK_SHAKE_SUFFIX (pour SHAKE), ou le retour de la fonction libkeccak_cshake_suffix(3) (pour cSHAKE), sont utilisés.

Le hachage du message sera stocké dans hashsum, sauf si hashsum est NULL (ce qui augmente la performance de l'appel). Un total de ((state->n + 7) / 8) octets sera écrit au début de hashsum. Par conséquent, hashsum a besoin au moins d'une taille d'allocation de ce nombre d'octets.

libkeccak_zerocopy_digest() écrira à et au-delà de &msg[msglen]. L'appelant doit s'assurer que suffisamment de mémoire est allouée pour le suffix ainsi que pour le remplissage d'au moins 2 bits, pour msg. La somme de msglen, des bits spécifiés dans suffix, et du remplissage, doit, en octets, être un multiple entier du débit binaire divisé par huit, qui est retourné par la fonction libkeccak_zerocopy_chunksize(3).

VALEURS DE RETOUR

La fonction libkeccak_zerocopy_digest() ne retourne pas de valeur.

ERREURS

La fonction libkeccak_zerocopy_digest() ne peut pas échouer.

NOTES

Appeler la fonction libkeccak_zerocopy_digest(3) après les fonctions libkeccak_update(3) ou libkeccak_fast_update(3), avec le même argument state, peut entraîner une mauvaise lecture du message.

NOTES

Pour cSHAKE, la fonction libkeccak_cshake_initialise(3), doit être appelée, une fois, immédiatement après l'initialisation de l'état ; avant le premier appel à l'une des fonctions libkeccak_fast_update(), libkeccak_zerocopy_update(), libkeccak_update(), et libkeccak_zerocopy_digest().
