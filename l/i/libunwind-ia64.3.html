NOM

libunwind-ia64 -- Support spécifique à IA-64 dans libunwind

INTRODUCTION

La version IA-64 de libunwind utilise une chaîne de plateforme nommée ia64 et, du moins en théorie, devrait être capable de supporter tous les systèmes d'exploitation adhérant à l'ABI spécifique au processeur définie pour l'Itanium Processor Family. Cela inclut Linux en little-endian et HP-UX en big-endian. De plus, pour permettre à une seule bibliothèque de dérouler des cibles 32 et 64 bits, le type unw_word_t est toujours défini comme étant de 64 bits de large (indépendamment de la taille naturelle du mot de l'hôte). Ceci dit, l'implémentation actuelle n'a été testée qu'avec IA-64 Linux.

Lorsqu'on cible IA-64, le fichier d'en-tête libunwind définit le macro UNW_TARGET_IA64 comme 1 et le macro UNW_TARGET comme ``ia64'' (sans les guillemets). Le premier permet au code de déroulement dépendant de la plateforme d'utiliser la compilation conditionnelle pour sélectionner une implémentation appropriée. Le second est utile à des fins de chaînage et pour construire des symboles spécifiques à la plateforme cible.

Une caractéristique spéciale de IA-64 est l'utilisation des bits NaT pour supporter l'exécution spéculative. Souvent, les bits NaT sont pensés comme le ``65ème bit'' d'un registre général. Cependant, pour tout faire rentrer dans des valeurs unw_word_t de 64 bits, libunwind traite les bits NaT comme des registres booléens séparés, dont la valeur de 64 bits est soit VRAI (non nul) soit FAUX (nul).

ÉTAT MACHINE

L'état machine (ensemble de registres) accessible via libunwind dépend du type de cadre de pile auquel un curseur pointe. Pour les cadres normaux, tous les registres « préservés » (sauvegardés par l'appelé) sont accessibles. Pour les cadres de trampoline de signal, tous les registres (y compris les registres « scratch » (sauvegardés par l'appelant)) sont accessibles. La plupart des applications n'ont pas à s'inquiéter à l'avance des registres accessibles à un moment donné. En cas de doute, il est toujours sûr d'essayer d'accéder à un registre (via unw_get_reg() ou unw_get_fpreg()) et si le registre n'est pas accessible, l'appel échouera avec une valeur de retour de -UNW_EBADREG.

Une exception spéciale à la règle générale ci-dessus est que les registres scratch r15-r18 sont toujours accessibles, même dans les cadres normaux. Cela permet de passer des arguments, par exemple, aux gestionnaires d'exception.

Pour une description détaillée de la convention d'utilisation des registres IA-64, veuillez consulter le guide ``Itanium Software Conventions and Runtime Architecture Guide'', disponible à l'adresse :
http://www.intel.com/design/itanium/downloads/245358.htm

NOMS DE REGISTRES

La version IA-64 de libunwind définit trois types de macros de noms de registres : les macros de registres de cadre, les macros de registres normaux et les macros de commodité. Ci-dessous, nous décrivons chaque type à tour de rôle :

MACROS DE REGISTRES DE CADRE

Les registres de cadre sont des registres spéciaux (pseudo) car ils ont toujours une valeur valide, même si parfois ils ne sont pas explicitement sauvegardés (par exemple, si un cadre de pile mémoire mesure 16 octets, le pointeur de pile précédent peut être calculé simplement comme sp+16, il n'est donc pas nécessaire de sauvegarder explicitement le pointeur de pile). De plus, l'ensemble des valeurs des registres de cadre identifie de manière unique un cadre de pile. L'architecture IA-64 définit deux piles (une pile mémoire et une pile de registres). En incluant le pointeur d'instruction (IP), cela fait trois registres de cadre :

UNW_IA64_IP:

Contient le pointeur d'instruction (IP, ou « compteur de programme ») du cadre de pile courant. Étant donnée cette valeur, l'état machine restant correspond aux valeurs des registres présentes dans le CPU lorsqu'il était sur le point d'exécuter l'instruction pointée par UNW_IA64_IP. Les bits 0 et 1 de ce registre de cadre codent le numéro de slot de l'instruction. Note : En raison de la manière dont l'instruction d'appel fonctionne sur IA-64, le numéro de slot est généralement zéro, mais peut être non nul, par exemple, dans le cadre de pile d'un trampoline de gestionnaire de signal.
UNW_IA64_SP:

Contient la valeur du pointeur de pile (mémoire) (SP).
UNW_IA64_BSP:

Contient le pointeur de la pile de registres de sauvegarde (BSP). Note : la valeur de ce registre est égale au contenu du registre ar.bsp au moment où l'instruction à UNW_IA64_IP était sur le point de commencer son exécution.

MACROS DE REGISTRES NORMALE

Les macros de registres normaux suivantes sont disponibles :

UNW_IA64_GR:

L'indice de base pour les registres généraux (entiers). Ajoutez un indice dans la plage 0..127 pour obtenir un registre général particulier. Par exemple, pour accéder à r4, utilisez l'indice UNW_IA64_GR+4. Les registres r0 et r1 (gp) sont en lecture seule, et toute tentative de les modifier entraînera une erreur (-UNW_EREADONLYREG). Même si r1 est en lecture seule, libunwind ajustera automatiquement sa valeur si le pointeur d'instruction (UNW_IA64_IP) est modifié. Par exemple, si UNW_IA64_IP est défini sur une valeur à l'intérieur d'une fonction func(), lire UNW_IA64_GR+1 retournera la valeur du pointeur global pour cette fonction.
UNW_IA64_NAT:

L'indice de base pour les bits NaT des registres généraux (entiers). Une valeur non nulle dans ces registres correspond à un bit NaT défini. Ajoutez un indice dans la plage 0..127 pour obtenir un registre de bit NaT particulier. Par exemple, pour accéder au bit NaT de r4, utilisez l'indice UNW_IA64_NAT+4.
UNW_IA64_FR:

L'indice de base pour les registres à virgule flottante. Ajoutez un indice dans la plage 0..127 pour obtenir un registre à virgule flottante particulier. Par exemple, pour accéder à f2, utilisez l'indice UNW_IA64_FR+2. Les registres f0 et f1 sont en lecture seule, et toute tentative d'écriture aux indices UNW_IA64_FR+0 ou UNW_IA64_FR+1 entraînera une erreur (-UNW_EREADONLYREG).
UNW_IA64_AR:

L'indice de base pour les registres d'application. Ajoutez un indice dans la plage 0..127 pour obtenir un registre d'application particulier. Par exemple, pour accéder à ar40, utilisez l'indice UNW_IA64_AR+40. L'architecture IA-64 définit plusieurs registres d'application comme « réservés pour une utilisation future ». Tenter d'accéder à de tels registres entraîne une erreur (-UNW_EBADREG).
UNW_IA64_BR:

L'indice de base pour les registres de branchement. Ajoutez un indice dans la plage 0..7 pour obtenir un registre de branchement particulier. Par exemple, pour accéder à b6, utilisez l'indice UNW_IA64_BR+6.
UNW_IA64_PR:

Contient l'ensemble des registres de prédicat. Ce registre de 64 bits de large contient les registres p0 à p63 au format « large côté ». Tout comme avec l'instruction « move predicates », les registres sont mappés comme si CFM.rrb.pr était défini à 0. Ainsi, en général, la valeur du registre de prédicat pN avec N>=16 se trouve dans le bit 16 + ((N-16)+CFM.rrb.pr) % 48.
UNW_IA64_CFM:

Contient le registre du masque de cadre actuel.

MACROS DE COMMODITE

Les macros de commodité sont simplement des alias pour certains registres fréquemment utilisés :

UNW_IA64_GP:

Alias pour UNW_IA64_GR+1, le registre du pointeur global.
UNW_IA64_TP:

Alias pour UNW_IA64_GR+13, le registre du pointeur de thread.
UNW_IA64_AR_RSC:

NAME

libunwind-ia64 - IA-64 register names for libunwind

INTRODUCTION

The libunwind library provides a generic API for unwinding stack traces. This man page describes the IA-64-specific extensions to libunwind.

MACHINE-STATE

An IA-64 machine state consists of the following registers:

UNW_IA64_GR

The 128 general-purpose registers (r0-r127).
UNW_IA64_AR

The 128 application registers (ar0-ar127).
UNW_IA64_FR

The 128 floating-point registers (f0-f127).
UNW_IA64_PR

The 64 predicate registers (p0-p63).
UNW_IA64_BRP

The branch registers (b0-b7).
UNW_IA64_CCV

The compare-and-swap value register.
UNW_IA64_IIP

The instruction pointer.
UNW_IA64_USP

The user stack pointer.
UNW_IA64_RSP

The register stack pointer.
UNW_IA64_BSP

The backing store pointer.
UNW_IA64_RBS

The register backing store.
UNW_IA64_PSR

The processor status register.
UNW_IA64_SSR

The system state register.
UNW_IA64_CPSR

The current processor status register.
UNW_IA64_UNAT

The user NaT register.
UNW_IA64_FPSR

The floating-point status register.
UNW_IA64_RNAT

The register NaT register.
UNW_IA64_PFS

The previous frame pointer.
UNW_IA64_LC

The loop count register.
UNW_IA64_EC

The epilogue count register.

REGISTER NAMES

In addition to the generic register names defined in unwind.h, the following IA-64-specific register names are available:

UNW_IA64_GR:

Alias for UNW_IA64_GR+0, the first general-purpose register.
UNW_IA64_AR:

Alias for UNW_IA64_AR+0, the first application register.
UNW_IA64_FR:

Alias for UNW_IA64_FR+0, the first floating-point register.
UNW_IA64_PR:

Alias for UNW_IA64_PR+0, the first predicate register.
UNW_IA64_BRP:

Alias for UNW_IA64_BRP+0, the first branch register.
UNW_IA64_AR_RPID:

Alias for UNW_IA64_AR+2, the return value pointer register.
UNW_IA64_AR_PFS:

Alias for UNW_IA64_AR+2, the previous frame pointer.
UNW_IA64_AR_LC:

Alias for UNW_IA64_AR+3, the loop count register.
UNW_IA64_AR_EC:

Alias for UNW_IA64_AR+4, the epilogue count register.
UNW_IA64_AR_RNAT:

Alias for UNW_IA64_AR+5, the NaT register.
UNW_IA64_AR_CCV:

Alias for UNW_IA64_AR+8, the compare-and-swap value register.
UNW_IA64_AR_UNAT:

Alias for UNW_IA64_AR+12, the user NaT register.
UNW_IA64_AR_FPSR:

Alias for UNW_IA64_AR+13, the floating-point status register.
UNW_IA64_AR_CSD:

Alias for UNW_IA64_AR+14, the compare-and-swap data register.
UNW_IA64_AR_GR:

Alias for UNW_IA64_AR+16, the general register stack pointer.
UNW_IA64_AR_BSPSTORE:

Alias for UNW_IA64_AR+18, the register-backing store write pointer.
UNW_IA64_AR_RBS:

Alias for UNW_IA64_AR+24, the register backing store.
UNW_IA64_AR_CS:

Alias for UNW_IA64_AR+25, the compare-and-swap register.
UNW_IA64_AR_SSR:

Alias for UNW_IA64_AR+26, the system state register.
UNW_IA64_AR_CPSR:

Alias for UNW_IA64_AR+27, the current processor status register.
UNW_IA64_AR_CCV:

Alias for UNW_IA64_AR+32, the compare-and-swap value register.
UNW_IA64_AR_CSD:

Alias for UNW_IA64_AR+25, the compare-and-swap-data register (used by 16-byte atomic operations).
UNW_IA64_AR_UNAT:

Alias for UNW_IA64_AR+36, the user NaT-collection register.
UNW_IA64_AR_FPSR:

Alias for UNW_IA64_AR+40, the floating-point status (and control) register.
UNW_IA64_AR_PFS:

Alias for UNW_IA64_AR+64, the previous frame-state register.
UNW_IA64_AR_LC:

Alias for UNW_IA64_GR+65 the loop-count register.
UNW_IA64_AR_EC:

Alias for UNW_IA64_GR+66, the epilogue-count register.

THE UNWIND-CONTEXT TYPE

On IA-64, unw_context_t is simply an alias for ucontext_t (as defined by the Single UNIX Spec). This implies that it is possible to initialize a value of this type not just with unw_getcontext(), but also with getcontext(), for example. However, since this is an IA-64-specific extension to libunwind, portable code should not rely on this equivalence.
