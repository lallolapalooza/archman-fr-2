SSL_CTX_SET_OPTIONS(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_OPTIONS(3)

NOM

SSL_CTX_set_options, SSL_set_options, SSL_CTX_clear_options, SSL_clear_options, SSL_CTX_get_options, SSL_get_options, SSL_get_secure_renegotiation_support — manipuler les options SSL

SYNTAXE

bibliothèque «libssl» libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_options(SSL_CTX *ctx, long options);

long
SSL_set_options(SSL *ssl, long options);

long
SSL_CTX_clear_options(SSL_CTX *ctx, long options);

long
SSL_clear_options(SSL *ssl, long options);

long
SSL_CTX_get_options(SSL_CTX *ctx);

long
SSL_get_options(SSL *ssl);

long
SSL_get_secure_renegotiation_support(SSL *ssl);

DESCRIPTION

SSL_CTX_set_options() ajoute les options définies par masque de bits dans options à ctx. Les options déjà définies auparavant ne sont pas effacées !

SSL_set_options() ajoute les options définies par masque de bits dans options à ssl. Les options déjà définies auparavant ne sont pas effacées !

SSL_CTX_clear_options() efface les options définies par masque de bits dans options de ctx.

SSL_clear_options() efface les options définies par masque de bits dans options de ssl.

SSL_CTX_get_options() retourne les options définies pour ctx.

SSL_get_options() retourne les options définies pour ssl.

SSL_get_secure_renegotiation_support() indique si le pair prend en charge la renégociation sécurisée.

Toutes ces fonctions sont implémentées à l'aide de macros.

Le comportement de la bibliothèque SSL peut être modifié en définissant plusieurs options. Les options sont codées sous forme de masques de bits et peuvent être combinées par une opération OU bit à bit (|).

SSL_CTX_set_options() et SSL_set_options() affectent le comportement (externe) du protocole de la bibliothèque SSL. Le comportement (interne) de l'API peut être modifié en utilisant les fonctions similaires SSL_CTX_set_mode(3) et SSL_set_mode(3).

Pendant une négociation, les paramètres d'options de l'objet SSL sont utilisés. Lorsqu'un nouvel objet SSL est créé à partir d'un contexte en utilisant SSL_new(3), le réglage d'options actuel est copié. Les modifications apportées à ctx n'affectent pas les objets SSL déjà créés. SSL_clear() n'affecte pas les réglages.

Les options suivantes de contournement de bogues sont disponibles :

SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Désactive une contre-mesure contre une vulnérabilité du protocole TLS 1.0 affectant les chiffrements CBC, qui ne peut pas être gérée par certaines implémentations SSL défectueuses. Cette option n'a aucun effet pour les connexions utilisant d'autres chiffrements.
SSL_OP_ALL
Il s'agit actuellement d'un alias pour SSL_OP_LEGACY_SERVER_CONNECT.

Il est généralement sûr d'utiliser SSL_OP_ALL pour activer les options de contournement de bogues si la compatibilité avec des implémentations quelque peu défectueuses est souhaitée.

Les options suivantes de modification sont disponibles :

SSL_OP_CIPHER_SERVER_PREFERENCE
Lors du choix d'un chiffrement, utiliser les préférences du serveur au lieu des préférences du client. Lorsqu'elle n'est pas définie, le serveur suit toujours les préférences du client. Lorsqu'elle est définie, le serveur choisit selon ses propres préférences.
SSL_OP_COOKIE_EXCHANGE
Activer l'échange de cookies tel que décrit dans la RFC 4347 Section 4.2.1. N'affecte que les connexions DTLS.
SSL_OP_LEGACY_SERVER_CONNECT
Permettre la renégociation héritée non sécurisée entre OpenSSL et les serveurs non patchés uniquement : cette option est actuellement définie par défaut. Voir la section RENÉGOCIATION SÉCURISÉE pour plus de détails.
SSL_OP_NO_DTLSv1
Ne pas utiliser le protocole DTLSv1. Obsolète ; utiliser SSL_CTX_set_min_proto_version(3) à la place.
SSL_OP_NO_DTLSv1_2
Ne pas utiliser le protocole DTLSv1.2. Obsolète ; utiliser SSL_CTX_set_min_proto_version(3) à la place.
SSL_OP_NO_QUERY_MTU
Ne pas interroger le MTU. N'affecte que les connexions DTLS.
SSL_OP_NO_SESSION_RESUMPTION_ON_RENEGOTIATION
Lors de la renégociation en tant que serveur, toujours démarrer une nouvelle session (c'est-à-dire que les demandes de reprise de session ne sont acceptées que lors de la négociation initiale). Cette option n'est pas nécessaire pour les clients.
SSL_OP_NO_TICKET
Normalement, les clients et les serveurs utilisant TLSv1.2 et versions antérieures, lorsque possible, utilisent de manière transparente les tickets RFC 5077 pour la reprise de session sans état.

Si cette option est définie, cette fonctionnalité est désactivée et les tickets ne seront ni utilisés par les clients ni par les serveurs.

SSL_OP_NO_TLSv1
Ne pas utiliser le protocole TLSv1.0. Obsolète ; utiliser SSL_CTX_set_min_proto_version(3) à la place.
SSL_OP_NO_TLSv1_1
Ne pas utiliser le protocole TLSv1.1. Obsolète ; utiliser SSL_CTX_set_min_proto_version(3) à la place.

SSL_OP_NO_TLSv1_2
N'utilisez pas le protocole TLSv1.2. Obsolète ; utilisez SSL_CTX_set_max_proto_version(3) plutôt.

Les options suivantes étaient prises en charge à un moment donné dans le passé et n'ont plus aucun effet : SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION, SSL_OP_EPHEMERAL_RSA, SSL_OP_MICROSOFT_BIG_SSLV3_BUFFER, SSL_OP_MICROSOFT_SESS_ID_BUG, SSL_OP_NETSCAPE_CA_DN_BUG, SSL_OP_NETSCAPE_CHALLENGE_BUG, SSL_OP_NETSCAPE_DEMO_CIPHER_CHANGE_BUG, SSL_OP_NETSCAPE_REUSE_CIPHER_CHANGE_BUG, SSL_OP_NO_COMPRESSION, SSL_OP_NO_SSLv2, SSL_OP_NO_SSLv3, SSL_OP_PKCS1_CHECK_1, SSL_OP_PKCS1_CHECK_2, SSL_OP_SAFARI_ECDHE_ECDSA_BUG, SSL_OP_SINGLE_DH_USE, SSL_OP_SINGLE_ECDH_USE, SSL_OP_SSLEAY_080_CLIENT_DH_BUG, SSL_OP_SSLREF2_REUSE_CERT_TYPE_BUG, SSL_OP_TLS_BLOCK_PADDING_BUG, SSL_OP_TLS_D5_BUG, SSL_OP_TLS_ROLLBACK_BUG, SSL_OP_TLSEXT_PADDING.

NEGOCIATION SECURE

OpenSSL 0.9.8m et versions ultérieures tentent toujours d'utiliser la négociation sécurisée telle que décrite dans la RFC 5746. Cela contrecarre l'attaque par préfixe décrite dans CVE-2009-3555 et ailleurs.

Cette attaque a des conséquences de grande portée dont les développeurs d'applications doivent être conscients. Dans la description ci-dessous, une implémentation prenant en charge la négociation sécurisée est appelée « patchée ». Un serveur ne prenant pas en charge la négociation sécurisée est appelé « non patché ».

Les sections suivantes décrivent les opérations autorisées par l'implémentation de négociation sécurisée d'OpenSSL.

Client et serveur patchés

Les connexions et les négociations sont toujours autorisées par les implémentations OpenSSL.

Client non patché et serveur OpenSSL patché

La connexion initiale réussit mais la renégociation du client est refusée par le serveur avec une alerte d'avertissement no_renegotiation.

Si le serveur OpenSSL patché tente de renégocier, une alerte fatale handshake_failure est envoyée. En effet, le code du serveur peut ne pas être conscient de la nature non patchée du client.

Notez qu'un bug dans les clients OpenSSL antérieurs à 0.9.8m (tous non patchés) entraînera le blocage de la connexion si elle reçoit une alerte no_renegotiation. Les versions d'OpenSSL 0.9.8m et ultérieures considéreront une alerte no_renegotiation comme fatale et répondront par une alerte fatale handshake_failure. En effet, l'API OpenSSL n'a actuellement aucune disposition pour indiquer à une application qu'une tentative de renégociation a été refusée.

Client OpenSSL patché et serveur non patché

Si l'option SSL_OP_LEGACY_SERVER_CONNECT est définie, les connexions initiales et les renégociations entre clients OpenSSL patchés et serveurs non patchés réussissent. Si aucune option n'est définie, les connexions initiales aux serveurs non patchés échoueront.

L'option SSL_OP_LEGACY_SERVER_CONNECT est actuellement définie par défaut, même si elle a des implications de sécurité : sinon, il serait impossible de se connecter à des serveurs non patchés (c'est-à-dire à tous initialement) et cela n'est clairement pas acceptable. La renégociation est autorisée car cela n'ajoute pas de problèmes de sécurité supplémentaires : lors d'une attaque, les clients ne voient de toute façon aucune renégociation.

Alors que de plus en plus de serveurs deviendront patchés, l'option SSL_OP_LEGACY_SERVER_CONNECT ne sera pas définie par défaut dans une future version d'OpenSSL.

Les applications clientes OpenSSL souhaitant s'assurer qu'elles peuvent se connecter à des serveurs non patchés doivent toujours définir SSL_OP_LEGACY_SERVER_CONNECT.

Les applications clientes OpenSSL qui souhaitent s'assurer qu'elles ne peuvent pas se connecter à des serveurs non patchés (et ainsi éviter tout problème de sécurité) doivent toujours effacer SSL_OP_LEGACY_SERVER_CONNECT en utilisant SSL_CTX_clear_options() ou SSL_clear_options().

VALEURS DE RETOUR

SSL_CTX_set_options() et SSL_set_options() retournent le nouveau masque d'options après avoir ajouté options.

SSL_CTX_clear_options() et SSL_clear_options() retournent le nouveau masque d'options après avoir effacé options.

SSL_CTX_get_options() et SSL_get_options() retournent le masque de bits actuel.

SSL_get_secure_renegotiation_support() retourne 1 si le pair prend en charge la renégociation sécurisée et 0 s'il n'en prend pas en charge.

HISTORIQUE

SSL_CTX_get_options() et SSL_get_options() sont apparus pour la première fois dans OpenSSL 0.9.2b et sont disponibles depuis OpenBSD 2.6.

SSL_CTX_clear_options(), SSL_clear_options(), et SSL_get_secure_renegotiation_support() sont apparus pour la première fois dans OpenSSL 0.9.8m et sont disponibles depuis OpenBSD 4.9.
