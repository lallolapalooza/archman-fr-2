LIRE.IN(1) Documentation de Lire pour LogReport LIRE.IN(1)

NOM

lire - Interface de Lire

SYNTAXE

lire

DESCRIPTION

lire a deux objectifs : configurer Lire et permettre la génération automatique de rapports.

lire est une application pilotée par menu. Vous devez utiliser la touche TAB pour naviguer entre les différents éléments de l'interface. Les touches fléchées doivent être utilisées pour naviguer dans les menus. La barre de menu principale est accessible à tout moment en utilisant F10. La souris peut être disponible en fonction de votre terminal et de l'implémentation du module Curses::UI de votre système.

Configuration de Lire

L'élément de menu 'Préférences' dans le menu 'Lire' vous donnera accès à tous les paramètres de Lire. La commande lire édite ou crée ~/.lire/config.xml.

Génération automatique de rapports

lire permet la génération automatique de rapports en créant et gérant des magasins DLF. Un magasin DLF est un dépôt de journaux. Dans un magasin DLF, vous pouvez configurer des ImportJobs et des ReportJobs qui seront exécutés régulièrement. La configuration du magasin est enregistrée dans store/config.xml.

Un ImportJob est une tâche qui importera des données de journal dans le magasin DLF. Ces données seront utilisées ultérieurement pour générer les rapports.

Les ReportJobs doivent être utilisés pour générer des rapports périodiques. Les rapports sont générés à partir des flux DLF disponibles dans votre magasin DLF. Le rapport peut être généré pour différents calendriers. Lire prend en charge 5 calendriers différents : horaire, quotidien, hebdomadaire, mensuel et annuel.

Vous devrez sélectionner le fichier de configuration de rapport à utiliser pour chaque calendrier. Les valeurs par défaut se trouvent dans <sysconfdir>/lire/, que vous devriez utiliser comme modèles à personnaliser selon votre objectif.

Les rapports peuvent être générés soit à partir des données de journal importées dans la base de données, soit à partir de rapports quotidiens générés précédemment. Ceci est utile lorsque vous avez beaucoup de données de journal et que vous ne souhaitez pas conserver toutes les données brutes disponibles. La source est sélectionnée automatiquement en fonction de la disponibilité des données. Notez cependant que seuls les rapports 'quotidiens' sont considérés comme une source de données pour les autres rapports (ce qui n'est possible qu'avec des calendriers hebdomadaires ou plus longs).

Lorsqu'il est exécuté, un ReportSchedule ne générera que le rapport et l'enregistrera dans le magasin DLF. Si vous souhaitez obtenir une copie formatée du rapport, vous devrez configurer un ou plusieurs OutputJobs.

Deux types d'OutputJob sont pris en charge :

1- Le rapport peut être envoyé par e-mail à une ou plusieurs adresses ;

2- ou il peut être enregistré dans un fichier sur le disque. Une configuration utile consiste à générer des rapports HTML dans un répertoire publié sur un site web. Lors de l'utilisation d'un OutputJob de type "fichier", vous voudrez probablement utiliser l'expansion strftime(3) afin que le nom de fichier soit différent chaque fois que le rapport est généré. Les expansions les plus courantes sont :

%Y - année à quatre chiffres (2000) ;
%m - mois à deux chiffres (01 pour janvier) ;
%V - numéro de semaine ISO ;
%d - jour du mois ;
%H - heure du jour (01-23).

De plus, contrairement à la commande lr_log2report, les rapports HTML sont générés dans un répertoire (pas dans un fichier tar).

Pour exécuter les tâches planifiées, vous devrez configurer des tâches cron. Utilisez lr_cron(1) pour traiter les tâches configurées dans un magasin.
