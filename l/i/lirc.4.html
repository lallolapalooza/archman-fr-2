lirc(4) Manuel des pilotes de périphériques lirc(4)

NOM

lirc - Périphériques lirc

DESCRIPTION

Les périphériques caractères /dev/lirc* fournissent une interface bidirectionnelle de bas niveau avec les télécommandes infrarouges (IR). La plupart de ces périphériques peuvent recevoir, et certains peuvent envoyer. Lors de la réception ou de l'envoi de données, le pilote fonctionne dans deux modes différents en fonction du matériel sous-jacent.

Certains matériels (généralement des cartes TV) décodent le signal IR en interne et fournissent les appuis sur les touches décodés sous forme de valeurs de codes de balayage (scancodes). Les pilotes pour ce type de matériel fonctionnent en mode LIRC_MODE_SCANCODE. Ces matériels ne supportent généralement pas l'envoi de signaux IR. De plus, ces matériels ne peuvent décoder qu'un ensemble limité de protocoles IR, généralement uniquement le protocole de la télécommande spécifique fournie avec, par exemple, une carte TV.

D'autres matériels fournissent un flux de durées de impulsions/espaces. Ces pilotes fonctionnent en mode LIRC_MODE_MODE2. Ces matériels peuvent être utilisés avec (presque) n'importe quel type de télécommande. Ce type de matériel peut également être utilisé en mode LIRC_MODE_SCANCODE, auquel cas les décodeurs IR du noyau décoderont l'IR. Ces décodeurs peuvent être écrits en eBPF étendu (voir bpf(2)) et attachés au périphérique lirc. Parfois, ce type de matériel supporte également l'envoi de données IR.

L'appel système LIRC_GET_FEATURES (voir ci-dessous) permet de sonder le support de la réception et de l'envoi, et dans quels modes, parmi d'autres fonctionnalités.

Lecture des entrées en mode LIRC_MODE_MODE2

En mode LIRC_MODE_MODE2, les données renvoyées par read(2) fournissent des valeurs de 32 bits représentant une durée d'impulsion ou d'espace. Le temps de la durée (en microsecondes) est encodé dans les 24 bits inférieurs. Impulsion (également appelée flash) indique une durée de détection de lumière infrarouge, et espace (également appelé intervalle) indique une durée sans infrarouge. Si la durée de l'espace dépasse le délai d'inactivité, un paquet de temporisation spécial est délivré, qui marque la fin d'un message. Les 8 bits supérieurs indiquent le type de paquet :

LIRC_MODE2_SPACE
La valeur reflète une durée d'espace (en microsecondes).
LIRC_MODE2_PULSE
La valeur reflète une durée d'impulsion (en microsecondes).
LIRC_MODE2_FREQUENCY
La valeur reflète une fréquence (Hz) ; voir l'appel système LIRC_SET_MEASURE_CARRIER_MODE.
LIRC_MODE2_TIMEOUT
La valeur reflète une durée d'espace (en microsecondes). Le paquet reflète une temporisation ; voir l'appel système LIRC_SET_REC_TIMEOUT_REPORTS.
LIRC_MODE2_OVERFLOW
Le récepteur IR a rencontré un dépassement (overflow) et, par conséquent, des données sont manquantes (depuis Linux 5.18).

Lecture des entrées en mode LIRC_MODE_SCANCODE

En mode LIRC_MODE_SCANCODE, les données renvoyées par read(2) reflètent les appuis de touche décodés, sous forme de structure lirc_scancode. Le code de balayage est stocké dans le champ scancode, et le protocole IR est stocké dans rc_proto. Ce champ contient l'une des valeurs de l'énumération rc_proto.

Écriture de sorties en mode LIRC_MODE_PULSE

Les données écrites dans le périphérique caractère à l'aide de write(2) sont une séquence d'impulsions/espaces de valeurs entières. Les impulsions et les espaces ne sont marqués qu'implicitement par leur position. Les données doivent commencer et se terminer par une impulsion, elles doivent donc toujours inclure un nombre impair d'échantillons. La fonction write(2) se bloque jusqu'à ce que les données aient été transmises par le matériel. Si plus de données sont fournies que le matériel ne peut en envoyer, l'appel write(2) échoue avec l'erreur EINVAL.

Écriture de sorties en mode LIRC_MODE_SCANCODE

Les données écrites dans les périphériques caractères doivent être une seule structure lirc_scancode. Les champs scancode et rc_proto doivent être remplis, tous les autres champs doivent être à 0. Les encodeurs IR du noyau convertiront le code de balayage en impulsions et en espaces. Le protocole ou le code de balayage est invalide, ou le périphérique lirc ne peut pas transmettre.

COMMANDES IOCTL

#include <linux/lirc.h>    /* Mais voir BUGS */
int ioctl(int fd, int cmd, int *val);

Les opérations ioctl(2) suivantes sont fournies par le périphérique caractère lirc pour sonder ou modifier les paramètres spécifiques du matériel lirc.

Commandes toujours supportées

Les périphériques /dev/lirc* supportent toujours les commandes suivantes :

LIRC_GET_FEATURES (void)
Renvoie un masque de bits des bits de fonctionnalités combinés ; voir FEATURES.

Si un périphérique renvoie un code d'erreur pour LIRC_GET_FEATURES, il est sûr de supposer qu'il ne s'agit pas d'un périphérique lirc.

Commandes optionnelles

Certains périphériques lirc supportent les commandes listées ci-dessous. Sauf indication contraire, celles-ci échouent avec l'erreur ENOTTY si l'opération n'est pas supportée, ou avec l'erreur EINVAL si l'opération a échoué, ou si des arguments invalides ont été fournis. Si un pilote n'annonce pas le support de certaines fonctionnalités, l'invocation des ioctls correspondants échouera avec l'erreur ENOTTY.

LIRC_GET_REC_MODE (void)
Si le périphérique lirc n'a pas de récepteur, cette opération échoue avec l'erreur ENOTTY. Sinon, elle renvoie le mode de réception, qui sera l'un des suivants :
LIRC_MODE_MODE2
Le pilote renvoie une séquence de durées d'impulsions/espaces.
LIRC_MODE_SCANCODE
Le pilote renvoie des valeurs de structure lirc_scancode, chacune représentant un appui de touche décodé.
LIRC_SET_REC_MODE (int)
Définit le mode de réception. val est soit LIRC_MODE_SCANCODE soit LIRC_MODE_MODE2. Si le périphérique lirc n'a pas de récepteur, cette opération échoue avec l'erreur ENOTTY.
LIRC_GET_SEND_MODE (void)
Renvoie le mode d'envoi. LIRC_MODE_PULSE ou LIRC_MODE_SCANCODE est supporté. Si le périphérique lirc ne peut pas envoyer, cette opération échoue avec l'erreur ENOTTY.
LIRC_SET_SEND_MODE (int)
Définit le mode d'envoi. val est soit LIRC_MODE_SCANCODE soit LIRC_MODE_PULSE. Si le périphérique lirc ne peut pas envoyer, cette opération échoue avec l'erreur ENOTTY.
LIRC_SET_SEND_CARRIER (int)
Définit la fréquence de modulation. L'argument est la fréquence (Hz).
LIRC_SET_SEND_DUTY_CYCLE (int)
Définit le rapport cyclique du porteuse. val est un nombre dans la plage [0,100] qui décrit la largeur d'impulsion en pourcentage du cycle total. Actuellement, aucune signification spéciale n'est définie pour 0 ou 100, mais les valeurs sont réservées pour une utilisation future.

"#LIRC_GET_MIN_TIMEOUT(">LIRC_GET_MIN_TIMEOUT(void)
LIRC_GET_MAX_TIMEOUT(void)
Certains appareils disposent de minuteries internes qui peuvent être utilisées pour détecter quand il n'y a pas eu d'activité IR pendant une longue période. Cela peut aider lircd(8) à détecter qu'un signal IR est terminé et peut accélérer le processus de décodage. Ces opérations renvoient des valeurs entières avec le délai d'attente minimum/maximum pouvant être défini (en microsecondes). Certains appareils ont un délai d'attente fixe. Pour de tels pilotes, LIRC_GET_MIN_TIMEOUT et LIRC_GET_MAX_TIMEOUT échoueront avec l'erreur ENOTTY.
LIRC_SET_REC_TIMEOUT (int)
Définit la valeur entière pour le délai d'attente d'inactivité IR (en microsecondes). Pour être acceptée, la valeur doit être comprise dans les limites définies par LIRC_GET_MIN_TIMEOUT et LIRC_GET_MAX_TIMEOUT. Une valeur de 0 (si prise en charge par le matériel) désactive tous les délais d'attente matériels et les données doivent être rapportées dès que possible. Si la valeur exacte ne peut pas être définie, alors la prochaine valeur possible *supérieure* à la valeur donnée doit être définie.
LIRC_GET_REC_TIMEOUT (void)
Retourne le délai d'attente d'inactivité actuel (en microsecondes). Disponible depuis Linux 4.18.
LIRC_SET_REC_TIMEOUT_REPORTS (int)
Active (val vaut 1) ou désactive (val vaut 0) les paquets de délai d'attente en LIRC_MODE_MODE2. Le comportement de cette opération a varié selon les versions du noyau :
•
Depuis Linux 5.17 : les paquets de délai d'attente sont toujours activés et cet ioctl est une opération nulle.
•
Depuis Linux 4.16 : les paquets de délai d'attente sont activés par défaut. Chaque fois que le périphérique lirc est ouvert, l'opération LIRC_SET_REC_TIMEOUT peut être utilisée pour désactiver (et, si désiré, pour réactiver plus tard) le délai d'attente sur le descripteur de fichier.
•
Dans Linux 4.15 et versions antérieures : les paquets de délai d'attente sont désactivés par défaut, et leur activation (via LIRC_SET_REC_TIMEOUT) sur un descripteur de fichier associé au périphérique lirc a pour effet d'activer les délais d'attente pour tous les descripteurs de fichier se référant à ce périphérique (jusqu'à ce que les délais d'attente soient désactivés à nouveau).
LIRC_SET_REC_CARRIER (int)
Définit la borne supérieure de la fréquence porteuse de réception (en Hz). Voir LIRC_SET_REC_CARRIER_RANGE.
LIRC_SET_REC_CARRIER_RANGE (int)
Définit la borne inférieure de la fréquence porteuse de réception (en Hz). Pour que cela prenne effet, définissez d'abord la borne inférieure à l'aide de l'ioctl LIRC_SET_REC_CARRIER_RANGE, puis la borne supérieure à l'aide de l'ioctl LIRC_SET_REC_CARRIER.
LIRC_SET_MEASURE_CARRIER_MODE (int)
Active (val vaut 1) ou désactive (val vaut 0) le mode de mesure. S'il est activé, à partir de la prochaine pression de touche, le pilote enverra des paquets LIRC_MODE2_FREQUENCY. Par défaut, cela doit être désactivé.
LIRC_GET_REC_RESOLUTION (void)
Retourne la résolution du pilote (en microsecondes).
LIRC_SET_TRANSMITTER_MASK (int)
Active l'ensemble des émetteurs spécifiés dans val, qui contient un masque de bits où chaque émetteur activé est un 1. Le premier émetteur est codé par le bit le moins significatif, et ainsi de suite. Lorsqu'un masque de bits invalide est donné, par exemple un bit est défini alors que l'appareil n'a pas autant d'émetteurs, cette opération renvoie le nombre d'émetteurs disponibles et ne fait rien autrement.
LIRC_SET_WIDEBAND_RECEIVER (int)
Certains appareils sont équipés d'un récepteur spécial à large bande destiné à apprendre la sortie d'une télécommande existante. Cet ioctl peut être utilisé pour activer (val égal à 1) ou désactiver (val égal à 0) cette fonctionnalité. Cela peut être utile pour les appareils qui ont par ailleurs des récepteurs à bande étroite qui les empêchent d'être utilisés avec certaines télécommandes. Les récepteurs à large bande peuvent également être plus précis. D'un autre côté, leur inconvénient est généralement une portée de réception réduite.
Note : le récepteur à large bande peut être activé implicitement si vous activez les rapports de porteuse. Dans ce cas, il sera désactivé dès que vous désactiverez les rapports de porteuse. Tenter de désactiver un récepteur à large bande alors que les rapports de porteuse sont actifs ne fera rien.

FONCTIONNALITÉS

L'ioctl LIRC_GET_FEATURES renvoie un masque de bits décrivant les fonctionnalités du pilote. Les bits suivants peuvent être renvoyés dans le masque :

LIRC_CAN_REC_MODE2
Le pilote est capable de recevoir en utilisant LIRC_MODE_MODE2.
LIRC_CAN_REC_SCANCODE
Le pilote est capable de recevoir en utilisant LIRC_MODE_SCANCODE.
LIRC_CAN_SET_SEND_CARRIER
Le pilote prend en charge la modification de la fréquence de modulation à l'aide de LIRC_SET_SEND_CARRIER.
LIRC_CAN_SET_SEND_DUTY_CYCLE
Le pilote prend en charge la modification du rapport cyclique à l'aide de LIRC_SET_SEND_DUTY_CYCLE.
LIRC_CAN_SET_TRANSMITTER_MASK
Le pilote prend en charge la modification de l'émetteur (ou des émetteurs) actif(s) à l'aide de LIRC_SET_TRANSMITTER_MASK.
LIRC_CAN_SET_REC_CARRIER
Le pilote prend en charge la définition de la fréquence porteuse de réception à l'aide de LIRC_SET_REC_CARRIER. Tout périphérique lirc depuis la fusion des pilotes dans Linux 2.6.36 doit avoir LIRC_CAN_SET_REC_CARRIER_RANGE défini si la fonctionnalité LIRC_CAN_SET_REC_CARRIER est définie.
LIRC_CAN_SET_REC_CARRIER_RANGE
Le pilote prend en charge LIRC_SET_REC_CARRIER_RANGE. La borne inférieure de la porteuse doit d'abord être définie à l'aide de l'ioctl LIRC_SET_REC_CARRIER_RANGE, avant d'utiliser l'ioctl LIRC_SET_REC_CARRIER pour définir la borne supérieure.
LIRC_CAN_GET_REC_RESOLUTION
Le pilote prend en charge LIRC_GET_REC_RESOLUTION.
LIRC_CAN_SET_REC_TIMEOUT
Le pilote prend en charge LIRC_SET_REC_TIMEOUT.
LIRC_CAN_MEASURE_CARRIER
Le pilote prend en charge la mesure de la fréquence de modulation à l'aide de LIRC_SET_MEASURE_CARRIER_MODE.
LIRC_CAN_USE_WIDEBAND_RECEIVER
Le pilote prend en charge le mode apprentissage à l'aide de LIRC_SET_WIDEBAND_RECEIVER.
LIRC_CAN_SEND_PULSE
Le pilote prend en charge l'envoi en utilisant LIRC_MODE_PULSE ou LIRC_MODE_SCANCODE

BOGUES

L'utilisation de ces appareils nécessite le fichier d'en-tête des sources du noyau lirc.h. Ce fichier n'est pas disponible avant Linux 4.6. Les utilisateurs de noyaux plus anciens pouvaient utiliser le fichier inclus dans http://www.lirc.org.
