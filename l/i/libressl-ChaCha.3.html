CHACHA(3) Manuel des fonctions de bibliothèque CHACHA(3)

NOM

ChaCha_set_key, ChaCha_set_iv, ChaCha, CRYPTO_chacha_20, CRYPTO_hchacha_20, CRYPTO_xchacha_20 — chiffrement en flux ChaCha20

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/chacha.h>

void
ChaCha_set_key(ChaCha_ctx *ctx, const unsigned char *key, unsigned int keybits);

void
ChaCha_set_iv(ChaCha_ctx *ctx, const unsigned char *iv, const unsigned char *counter);

void
ChaCha(ChaCha_ctx *ctx, unsigned char *out, const unsigned char *in, size_t len);

void
CRYPTO_chacha_20(unsigned char *out, const unsigned char *in, size_t len, const unsigned char key[32], const unsigned char iv[8], uint64_t counter);

void
CRYPTO_hchacha_20(unsigned char out[32], const unsigned char key[32], const unsigned char iv[16]);

void
CRYPTO_xchacha_20(unsigned char *out, const unsigned char *in, size_t len, const unsigned char key[32], const unsigned char iv[24]);

DESCRIPTION

Ces fonctions fournissent une implémentation de bas niveau du chiffrement en flux ChaCha avec des clés de 256 et 128 bits. Le nombre de tours est codé en dur à 20 ; les variantes avec 8 ou 12 tours ne sont pas supportées.

Au lieu d'utiliser directement ces fonctions, les programmes d'application utilisent normalement l'interface de haut niveau plus portable EVP_chacha20(3).

L'état ChaCha est contenu dans la structure ChaCha_ctx et se compose de seize entiers non signés de 32 bits.

Pour la valeur recommandée de 256 keybits, ChaCha_set_key() copie 32 octets (256 bits) de key dans les huit entiers du milieu de l'état ChaCha, en utilisant l'ordre little-endian pour chaque entier. Pour la valeur alternative de 128 keybits, seulement 16 octets (128 bits) sont copiés de key vers l'état ChaCha, mais ils sont copiés deux fois, une fois dans le deuxième quart et une fois dans le troisième quart. Le premier quart de l'état ChaCha est défini avec quatre entiers constants ; ces constantes diffèrent selon que keybits est de 128 ou 256. Le dernier quart de l'état ChaCha reste inchangé.

ChaCha_set_iv() copie huit octets (64 bits) de counter et huit octets (64 bits) de iv dans le dernier quart de l'état ChaCha, le compteur dans les deux premiers entiers et le vecteur d'initialisation dans les deux derniers entiers, toujours en ordre little-endian. Si counter est NULL, les deux entiers respectifs sont mis à 0 à la place. Les trois premiers quarts de l'état ChaCha restent inchangés.

ChaCha() chiffre len octets de données de in vers out en utilisant le ctx qui a été précédemment configuré avec ChaCha_set_key() et ChaCha_set_iv(). Il est de la responsabilité de l'appelant de fournir un tampon out d'au moins len octets. Cette fonction peut être appelée plusieurs fois de suite avec des arguments len variables. len n'a pas besoin d'être un multiple de 64.

CRYPTO_chacha_20() chiffre len octets de données de in vers out en une seule opération, en utilisant la key et l'iv donnés, comme décrit pour ChaCha_set_key() et ChaCha_set_iv(), et en copiant la moitié la moins significative de counter dans le premier entier du compteur de l'état ChaCha initial, et la moitié la plus significative dans le second entier. Il est de la responsabilité de l'appelant de fournir un tampon out d'au moins len octets. La valeur maximale supportée pour len est 2^32 - 1.

XChaCha est une variante de ChaCha conçue pour supporter des nonces plus longs, tout comme XSalsa20 est une variante de Salsa20 supportant des nonces plus longs.

CRYPTO_xchacha_20() chiffre len octets de données de in vers out en une seule opération avec l'algorithme XChaCha, en utilisant la key et l'iv donnés. C'est équivalent à CRYPTO_chacha_20() avec le dernier tiers de iv, un counter de 0, et une clé générée avec CRYPTO_hchacha_20() à partir des deux premiers tiers de iv.

VOIR AUSSI

crypto(3), EVP_chacha20(3)

NORMES

RFC 8439 : ChaCha20 et Poly1305 pour les protocoles IETF

Notez que la norme spécifie un compteur de 32 bits et un vecteur d'initialisation de 96 bits, tandis que cette implémentation suit la spécification originale de Bernstein et utilise un compteur de 64 bits et un vecteur d'initialisation de 64 bits.

Ces fonctions sont spécifiques à LibreSSL et ne sont pas fournies par OpenSSL. BoringSSL fournit bien CRYPTO_chacha_20(), mais avec une interface incompatible, acceptant un iv de 96 bits et un counter de 32 bits.

HISTORIQUE

ChaCha_set_key(), ChaCha_set_iv(), ChaCha(), et CRYPTO_chacha_20() sont apparus pour la première fois dans OpenBSD 5.6.

CRYPTO_hchacha_20() et CRYPTO_xchacha_20() sont apparus pour la première fois dans OpenBSD 6.5.
