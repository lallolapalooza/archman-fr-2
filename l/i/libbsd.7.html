NOM

libbsd — fonctions utilitaires des systèmes BSD

DESCRIPTION

La bibliothèque libbsd fournit un ensemble de macros et de fonctions de compatibilité couramment trouvées sur les systèmes basés sur BSD. Son but est de les rendre disponibles sur les systèmes non basés sur BSD afin de faciliter la portabilité.

La bibliothèque peut être utilisée en mode superposition (overlay mode), qui est la manière préférée, de sorte que le code soit portable et ne nécessite aucune modification du code BSD original. Cela peut être fait facilement avec la bibliothèque pkgconf(1) nommée libbsd-overlay. Ou en ajoutant le répertoire d'inclusion spécifique au système avec le suffixe bsd/ à la liste des chemins d'inclusion système. Avec gcc, cela pourrait être -isystem ${includedir}/bsd. De plus, la variable de préprocesseur LIBBSD_OVERLAY doit être définie. Les inclusions dans ce cas doivent être les inclusions système habituelles, telles que <unistd.h>.

L'autre façon d'utiliser la bibliothèque est d'utiliser les en-têtes nommés (namespaced headers), ce qui est une méthode déconseillée, moins portable car elle rend l'utilisation de libbsd obligatoire et ne fonctionnera pas sur les systèmes basés sur BSD, et nécessite de modifier le code BSD original. Cela peut être fait avec la bibliothèque pkgconf(1) nommée libbsd. Les inclusions dans ce cas doivent être nommées avec bsd/, telles que <bsd/unistd.h>.

Le paquet fournit également une bibliothèque statique libbsd-ctor qui peut être utilisée pour injecter des constructeurs automatiques dans un programme afin que la fonction setproctitle_init(3bsd) soit invoquée automatiquement au démarrage. Cela peut être fait avec la bibliothèque pkgconf(1) nommée libbsd-ctor.

VARIANTS

Certaines fonctions ont des prototypes différents selon le système BSD d'où elles proviennent, et ces diverses implémentations fournies sont sélectionnables au moment de la compilation.

Voici la liste des fonctions qui fournissent plusieurs implémentations :

strnvis(3bsd)
 
strnunvis(3bsd)
NetBSD a ajouté strnvis(3bsd) et strnunvis(3bsd) mais l'a malheureusement rendue incompatible avec celle existante dans OpenBSD et libbsd de Freedesktop (la première existant depuis plus de dix ans). Bien que cette incompatibilité ait été signalée lors du développement (voir http://gnats.netbsd.org/44977), ils l'ont quand même expédiée. Plus encore, FreeBSD et plus tard macOS ont adopté cette implémentation incompatible.

Fournit les deux implémentations et utilise par défaut l'implémentation historique pour éviter les cassures, mais nous passerons à celle de NetBSD dans une version ultérieure, qui est intérieurement cohérente avec les autres fonctions de vis(3bsd) et est maintenant plus répandue. Définissez LIBBSD_NETBSD_VIS pour passer à celle de NetBSD dès maintenant. Définissez LIBBSD_OPENBSD_VIS pour continuer à utiliser celle de OpenBSD.

OBSOLÈTE

Certaines fonctions ont été dépréciées, elles émettront des avertissements lors de la compilation et potentiellement lors de l'édition des liens à l'exécution. Cela peut être dû au fait que les fonctions ne sont pas du tout portables sur d'autres systèmes, rendant le paquet impossible à compiler ailleurs ; pas portables de manière correcte ou sans bug ; ou parce qu'il existe maintenant de meilleurs remplacements plus portables.

Voici la liste des macros et fonctions actuellement dépréciées :

fgetln(3bsd)
Non portable, nécessite l'aide de la couche stdio. Une implémentation doit choisir entre fuir des buffers ou être réentrante pour un nombre limité de flux (cette implémentation a choisi la dernière option avec une limite de 32). Utilisez plutôt getline(3), qui est disponible sur de nombreux systèmes et requise par IEEE Std 1003.1-2008 (« POSIX.1 »).
fgetwln(3bsd)
Non portable, nécessite l'aide de la couche stdio. Une implémentation doit choisir entre fuir des buffers ou être réentrante pour un nombre limité de flux (cette implémentation a choisi la dernière option avec une limite de 32). Utilisez plutôt fgetwc(3), qui est disponible sur de nombreux systèmes et requise par ISO/IEC 9899:1999 (« ISO C99 ») et IEEE Std 1003.1-2001 (« POSIX.1 »).

NAME

libbsd — a compatibility library for the FreeBSD API

DESCRIPTION

The libbsd project provides a library that implements the FreeBSD API on POSIX-compliant systems like Linux. It aims to allow developers to port applications that rely on FreeBSD-specific functions without major code changes.

This library is particularly useful for applications that use FreeBSD-specific system calls, data structures, or utility functions not present in standard POSIX or other common C libraries like glibc.

HEADERS

To use the functions provided by libbsd, you typically need to include the relevant FreeBSD header files. These are often available under a <bsd/<header>.h> path, for example: <bsd/string.h>, <bsd/stdlib.h>, etc.

VARIANTS

Some functions may have variants depending on the underlying system or the specific implementation. For example, functions related to random number generation might have different initialisation or seeding mechanisms.

DEPRECATED

Certain functions or features might be marked as deprecated. This means they are still available but may be removed in future versions, and developers are encouraged to use newer, preferably POSIX-compliant, alternatives.

funopen(3bsd)
Unportable, requires assistance from the stdio layer or some hook framework. On glibc- and musl-based systems the fopencookie(3) function can be used. Otherwise the code needs to be prepared for neither of these functions being available.

SUPERSEDED

Some functions have been superseded by implementations in other system libraries, and might disappear on the next SONAME bump, assuming those other implementation have widespread deployment, or the implementations are present in all major libc for example.

HISTORY

The libbsd project started in the Debian GNU/kFreeBSD port as a way to ease porting code from FreeBSD to the GNU-based system. Pretty early on it was generalized and a project created on FreeDesktop.org for other distributions and projects to use.

It is now distributed as part of most non-BSD distributions.
