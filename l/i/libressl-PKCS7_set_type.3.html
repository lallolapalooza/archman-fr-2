PKCS7_SET_TYPE(3) Manuel des fonctions de bibliothèque PKCS7_SET_TYPE(3)

NOM

PKCS7_set_type, PKCS7_set0_type_other — initialiser le type d'un ContentInfo PKCS#7

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/pkcs7.h>

int
PKCS7_set_type(PKCS7 *p7, int type);

int
PKCS7_set0_type_other(PKCS7 *p7, int type, ASN1_TYPE *content);

DESCRIPTION

Ces fonctions définissent le type d'une structure ContentInfo non utilisée p7.

La fonction PKCS7_set_type() alloue et initialise également un objet enfant vide dans p7. L'argument type peut être l'un des NID suivants, créant un objet enfant du type de données indiqué :

argument type type de données de l'enfant version
NID_pkcs7_data ASN1_OCTET_STRING n.a.
NID_pkcs7_digest PKCS7_DIGEST 0
NID_pkcs7_encrypted PKCS7_ENCRYPT 0
NID_pkcs7_enveloped PKCS7_ENVELOPE 0
NID_pkcs7_signed PKCS7_SIGNED 1
NID_pkcs7_signedAndEnveloped PKCS7_SIGN_ENVELOPE 1

Si le type fourni est invalide, p7 reste inchangé et PKCS7_set_type() échoue.

Si l'allocation mémoire échoue, PKCS7_set_type() échoue et p7 peut rester dans un état incohérent.

La fonction PKCS7_set0_type_other() accepte un NID arbitraire comme type et définit également le content, sans aucune vérification ni copie.

Pour les deux fonctions, le reste de l'état interne de p7 reste inchangé.

VALEURS DE RETOUR

La fonction PKCS7_set_type() retourne 1 en cas de succès ou 0 en cas d'échec.

La fonction PKCS7_set0_type_other() ne gère aucune erreur et retourne toujours 1.

VOIR AUSSI

ASN1_OCTET_STRING_new(3), ASN1_TYPE_new(3), PKCS7_encrypt(3), PKCS7_new(3), PKCS7_set_content(3), PKCS7_sign(3)

HISTORIQUE

La fonction PKCS7_set_type() est apparue pour la première fois dans SSLeay 0.8.1 et PKCS7_set0_type_other() dans OpenSSL 0.9.8. Les deux sont disponibles depuis OpenBSD 2.4.

ATTENTION

Si p7 a déjà été utilisé avant d'être passé à l'une de ces fonctions, il signalera le succès même s'il y a une fuite de mémoire. Plus tard, si d'autres fonctions tentent d'utiliser p7 dans son rôle précédent, elles risquent de mal fonctionner.
