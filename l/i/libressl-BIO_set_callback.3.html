DESCRIPTION

BIO_set_callback_ex() et BIO_get_callback_ex() définissent et récupèrent le rappel BIO. Le rappel est appelé lors de la plupart des opérations BIO de haut niveau. Il peut être utilisé à des fins de débogage pour tracer les opérations sur un BIO ou pour modifier son fonctionnement.

BIO_set_callback() et BIO_get_callback() sont des fonctions obsolètes qui définissent et récupèrent le rappel BIO de l'ancien style, qui n'est utilisé que si aucun rappel du nouveau style n'est défini avec BIO_set_callback_ex().

BIO_set_callback_arg() stocke le pointer en interne dans b et BIO_get_callback_arg() le récupère de b. Le nom de ces deux fonctions est trompeur : le pointer n'est jamais passé comme argument à une quelconque fonction de rappel. Mais bien sûr, les fonctions de rappel peuvent appeler BIO_get_callback_arg() et accéder au pointeur, tout comme tout autre code peut le faire.

BIO_debug_callback() est un rappel de débogage standard qui affiche des informations relatives à chaque opération BIO. Si BIO_set_callback_arg() a été appelé avec un argument non-NULL, des informations sont envoyées au BIO pointé par le pointer ; sinon, la sortie d'erreur standard est utilisée.

Les arguments des fonctions de rappel sont les suivants :

b
Le BIO auquel le rappel est attaché.
oper
L'opération en cours, qui est l'une de BIO_CB_CTRL, BIO_CB_FREE, BIO_CB_GETS, BIO_CB_PUTS, BIO_CB_READ, ou BIO_CB_WRITE. Pour certaines opérations, le rappel est appelé deux fois, une fois avant et une fois après l'opération réelle. Le dernier cas a oper OU'é avec BIO_CB_RETURN.
argp, argi, argl
La signification de ces trois arguments dépend de la valeur de oper, c'est-à-dire de l'opération en cours.
len
La longueur des données demandées en lecture ou écriture. Ceci n'est utile que si oper est BIO_CB_READ, BIO_CB_WRITE, ou BIO_CB_GETS.
ret
Lorsque oper n'inclut pas BIO_CB_RETURN, c'est-à-dire lorsque le rappel est invoqué avant une opération, la valeur passée au rappel via ret est toujours 1. Dans ce cas, si le rappel retourne une valeur négative, la bibliothèque abandonne l'opération demandée et retourne à la place la valeur de retour négative du rappel à l'application. Si le rappel retourne une valeur non négative, cette valeur de retour est ignorée par la bibliothèque, et l'opération est effectuée normalement.

Lorsque oper inclut BIO_CB_RETURN, c'est-à-dire lorsque le rappel est invoqué après une opération, la valeur passée au rappel via ret est la valeur de retour que l'opération retournerait à l'application si aucun rappel n'était présent. Lorsqu'un rappel est présent, l'opération ne transmet cette valeur qu'au rappel et au lieu de cela, retourne la valeur de retour du rappel à l'application.

processed
L'emplacement pointé est mis à jour avec le nombre d'octets réellement lus ou écrits. Utilisé uniquement pour BIO_CB_READ, BIO_CB_WRITE, BIO_CB_GETS, et BIO_CB_PUTS.

Le rappel devrait normalement simplement retourner ret une fois qu'il a terminé le traitement, sauf s'il souhaite spécifiquement abandonner l'opération ou modifier la valeur retournée à l'application.

VALEURS DE RETOUR

BIO_get_callback_ex() retourne un pointeur vers la fonction cb_ex précédemment installée avec BIO_set_callback_cb(), ou NULL si aucun rappel n'a été installé.

BIO_get_callback() retourne un pointeur vers la fonction cb précédemment installée avec BIO_set_callback(), ou NULL si aucun rappel n'a été installé.

BIO_get_callback_arg() retourne le pointeur précédemment défini avec BIO_set_callback_arg(), ou NULL si aucun pointeur n'a été défini.

BIO_debug_callback() retourne ret si le bit BIO_CB_RETURN est défini dans cmd, ou 1 sinon.

HISTORIQUE

BIO_set_callback(), BIO_get_callback(), BIO_set_callback_arg(), et BIO_debug_callback() sont apparus pour la première fois dans SSLeay 0.6.0. BIO_get_callback_arg() est apparu pour la première fois dans SSLeay 0.8.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BIO_callback_fn() est apparu pour la première fois dans OpenSSL 1.1.0. BIO_callback_fn_ex(), BIO_set_callback_ex(), et BIO_get_callback_ex() sont apparus pour la première fois dans OpenSSL 1.1.1. Ces fonctions sont disponibles depuis OpenBSD 7.1.
