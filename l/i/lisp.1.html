LISP(1) Manuel des commandes générales LISP(1)

NOM

lisp - Environnement de programmation CMU Common Lisp

SYNTAXE

lisp [fichiers-entree] [liste-options]

DESCRIPTION

lisp Lance CMU Common Lisp. Si liste-options est vide, alors Lisp entrera dans une boucle lecture-évaluation-impression en utilisant stdin, stdout et stderr. Les fichiers-entree optionnels fournissent des opérandes pour certaines options. Ces options sont définies ci-dessous :

-help
Affiche les options de la ligne de commande et quitte.
--help
Identique à -help.
-core nom-fichier
Spécifie l'image Lisp suspendue (ou `fichier noyau') à utiliser au démarrage.
-lib chemin-lib
Une liste de répertoires séparés par des deux-points à utiliser pour la liste de recherche de bibliothèque.
-batch
Fait fonctionner Lisp en mode batch, où toute l'entrée est dirigée depuis l'entrée standard. Un code de retour Unix de 0 est renvoyé en cas de fin de fichier (EOF), tandis que toute condition d'erreur non gérée provoquera une sortie immédiate avec un code de retour de 1, au lieu d'entrer dans le débogueur.
-quiet
Fait démarrer Lisp silencieusement, désactivant l'affichage de l'en-tête et supprimant la plupart des bruits inutiles, tels que les messages de GC, les messages de chargement, etc.
-dynamic-space-size
Nécessite un argument qui doit être le nombre de mégaoctets (1048576 octets) à allouer au tas (heap). Si non spécifié, une valeur par défaut spécifique à la plateforme est utilisée. La taille maximale réelle autorisée du tas est spécifique à la plateforme.
-read-only-space-size
Nécessite un argument qui doit être le nombre de mégaoctets (1048576 octets) à allouer à l'espace de lecture seule. Si non spécifié, une valeur par défaut spécifique à la plateforme est utilisée.
-static-space-size
Nécessite un argument qui doit être le nombre de mégaoctets (1048576 octets) à allouer à l'espace statique. Si non spécifié, une valeur par défaut spécifique à la plateforme est utilisée. La taille maximale réelle autorisée du tas est spécifique à la plateforme.
-control-stack-size
Nécessite un argument qui doit être le nombre de mégaoctets (1048576 octets) à allouer à la pile de contrôle. Si non spécifié, une valeur par défaut spécifique à la plateforme est utilisée. La taille maximale réelle autorisée du tas est spécifique à la plateforme.
-binding-stack-size
Nécessite un argument qui doit être le nombre de mégaoctets (1048576 octets) à allouer à la pile de liaisons. Si non spécifié, une valeur par défaut spécifique à la plateforme est utilisée. La taille maximale réelle autorisée du tas est spécifique à la plateforme. -edit Fait entrer Lisp dans l'éditeur Hemlock. Un fichier à éditer peut être spécifié en plaçant le nom du fichier entre le nom du programme (habituellement `lisp') et la première option.
-eval expression
Évalue l' expression Lisp spécifiée pendant la séquence de démarrage. La valeur du formulaire ne sera pas affichée sauf si elle est encapsulée dans un formulaire qui effectue une sortie.
-init nom-fichier
Spécifie le nom d'un fichier contenant des personnalisations utilisateur qui doit être chargé chaque fois que Lisp démarre (par défaut ~/init ou ~/.cmucl-init.) Le chargeur charge tout binaire compilé existant, ou la source ".lisp" si aucun.
-hinit nom-fichier
Similaire à -init, mais spécifie le nom du fichier d'initialisation Hemlock (par défaut `~/hemlock-init' ou ~/.hemlock-init), qui n'est chargé que lorsque Hemlock est démarré.
-noinit
Supprime le chargement du fichier d'initialisation et empêche également -edit de charger le fichier d'initialisation Hemlock.
-nositeinit
Supprime le chargement du fichier d'initialisation spécifique au site site-init.
-load nom-fichier
Charge le fichier spécifié dans Lisp avant d'entrer dans la boucle lecture-évaluation-impression de Lisp.
-slave nom-editeur
Spécifie que Lisp doit démarrer comme un Lisp esclave et essayer de se connecter à un Lisp éditeur. Le nom de l'éditeur auquel se connecter doit être spécifié. Pour trouver le nom de l'éditeur, utilisez la commande Hemlock `Accepter les connexions esclaves'. nom-editeur est de la forme `nom-machine:socket', où nom-machine est le nom d'hôte Internet de la machine et socket est le numéro décimal du socket auquel se connecter.
-debug-lisp-search
Active l'affichage de messages indiquant comment CMUCL recherche son fichier noyau. Ceci est utile si CMUCL ne trouve pas son fichier noyau pour une raison quelconque.
-fpu mode-fpu
Cette option n'est disponible que sur les systèmes x86. Cette option prend les valeurs x87, sse2, ou auto, avec auto étant la valeur par défaut. Avec la valeur par défaut, CMUCL vérifie si la machine exécutant CMUCL prend en charge SSE2 ou non. Si c'est le cas, le fichier noyau SSE2 est automatiquement sélectionné et utilisé. Sinon, le fichier noyau x87 est utilisé. Avec cette option, l'utilisateur peut outrepasser la détection et sélectionner un noyau. (Notez que vous ne pouvez pas exécuter le noyau SSE2 sur une puce qui ne dispose pas de SSE2. Mais le noyau x87 peut fonctionner sur n'importe quelle machine.)
--
Si cette option est fournie, le traitement des arguments de CMUCL est arrêté, et tout ce qui suit "--" est placé dans EXT:*COMMAND-LINE-APPLICATION-ARGUMENTS*. Cela permet à l'application de traiter ses propres options spéciales.

ENVIRONNEMENT

CMUCLLIB
Cette variable pointe vers le répertoire `lib/' contenant `lisp.core' et d'autres fichiers utilisés par Lisp au moment de l'exécution. Ceci peut être annulé en utilisant l'option de ligne de commande -lib.
CMUCLCORE
Cette variable contient le chemin vers le `lisp.core' qui doit être utilisé. Ceci peut être annulé en utilisant l'option de ligne de commande -core.
CMUCL_EMPTYFILE
[SunOS uniquement] Si `df /tmp' affiche `swap' comme système de fichiers pour le répertoire `/tmp', alors vous avez un système de fichiers "tmpfs". Dans ce cas, vous devez définir la variable d'environnement CMUCL_EMPTYFILE pour pointer vers un chemin sur un système de fichiers non-TMPFS qui peut être utilisé à la place de `/tmp/empty'.
XKEYSYMDB
Afin d'utiliser Motif (et le débogueur graphique) avec des serveurs X de fournisseurs autres que l'OSF (comme Sun), vous pourriez avoir besoin de définir la variable d'environnement XKEYSYMDB pour pointer vers le fichier `lib/XKeysymDB'. Sinon, vous obtiendrez de nombreux messages d'erreur chaque fois qu'une nouvelle connexion sera ouverte à l'interface motif de CMU CL. Ce fichier est lu par Xt de X11R5 afin d'augmenter la base de données des keysyms avec certains keysyms des fournisseurs OSF que Motif souhaite utiliser.

RECHERCHE DU FICHIER NOYAU

Lorsqu'aucun fichier noyau n'est spécifié (soit par la variable d'environnement CMUCLCORE, soit par l'option -core), CMUCL recherche dans divers endroits un fichier noyau potentiel.

Lorsque la variable d'environnement CMUCLLIB est définie ou que l'option -lib est donnée, le fichier noyau lisp est recherché dans les emplacements spécifiés. Il s'agit d'une liste de répertoires séparés par des deux-points, tout comme PATH. Cette liste de répertoires est parcourue dans l'ordre à la recherche d'un fichier nommé `lisp.core'. Le premier trouvé sera le noyau à utiliser.

Lorsque CMUCLLIB n'est pas défini et que -lib n'est pas donné, un ensemble de chemins par défaut est utilisé pour initialiser la liste de recherche de la bibliothèque, et cette liste est également utilisée pour rechercher le fichier noyau. Soit l'exécutable C de lisp situé à `<bin>/lisp'. Alors les répertoires suivants sont recherchés pour le fichier noyau :

FICHIERS

Les chemins suivants sont spécifiés par rapport au répertoire où CMU CL est installé, par exemple /usr/local.

doc/cmucl/*
Divers fichiers de documentation postscript et texte.
bin/lisp
Le programme de démarrage de lisp. Ce répertoire devrait être dans PATH.
lib/cmucl/sample-wrapper
Un script shell exemple qui configure l'environnement et exécute lisp. Ceci n'est normalement pas nécessaire à moins que vous ne vouliez une configuration spéciale.
lib/cmucl/lib/lisp.core
L'image Lisp suspendue. Mais pour les machines x86, le cœur suspendu est nommé lisp-x87.core ou lisp-sse2.core, selon que le cœur x87 ou sse2 est utilisé.
lib/cmucl/lib/site-init.lisp,generic-site.lisp
Initialisation spécifique au site (voir le fichier README.) Le fichier generic-site.lisp est un modèle qui peut être utilisé pour créer site-init.lisp. (Note : l'installation de CMUCL ne crée ni ne détruit aucun fichier site-init.lisp.)
lib/cmucl/lib/lisp.a
Un fichier archive de tout le code runtime C. Ceci est nécessaire lors de la création d'une image exécutable.
lib/cmucl/lib/linker.sh,linker-x86.sh
Scripts shell pour effectuer la liaison nécessaire à la création d'une image exécutable.
lib/cmucl/lib/hemlock11.*,lib/cmucl/lib/mh-scan,lib/cmucl/lib/spell-dictionary.bin
Fichiers Hemlock.
lib/cmucl/lib/fonts/
Polices X11 pour Hemlock.
lib/cmucl/lib/locale
Ce répertoire contient des fichiers modèles pour les messages de CMUCL. Les traductions des messages de CMUCL y sont également stockées.
lib/cmucl/lib/XKeysymDB
Base de données des noms de touches X (Keysym) pour Motif.
lib/cmucl/lib/load-foreign.csh
Script utilisé par LOAD-FOREIGN pour exécuter "ld" sur certaines plateformes.
lib/cmucl/lib/contrib
Ce répertoire contient les modules contrib, y compris asdf2 et mk-defsystem.
lib/cmucl/lib/ext-formats
Ce répertoire contient des fichiers lisp qui implémentent les différents formats externes pris en charge par CMUCL.
lib/cmucl/lib/subsystems
Ce répertoire contient les sous-systèmes de CMUCL. Les sous-systèmes incluent CLX, CLM, les flux Gray, Hemlock et les flux simples.
~/init.lisp,~/.cmucl-init.lisp
Fichiers de personnalisation utilisateur chargés au démarrage de lisp; l'un ou l'autre nom est acceptable. Les fichiers init peuvent être compilés.
~/hemlock-init.lisp,~/.hemlock-init.lisp
Fichier d'initialisation Hemlock, chargé au démarrage de Hemlock.

BOGUES

Consultez http://www.cons.org/cmucl/support.html pour des informations de support, y compris les mécanismes de signalement de bogues. Veuillez consulter votre mainteneur local de CMU CL ou un expert Common Lisp si nécessaire pour vérifier qu'un problème est bien un bogue avant de le signaler.

Problèmes connus avec cette version :

--
La détection de dépassement de pile n'est pas très élégante. Vous obtenez beaucoup d'erreurs "map failure" sur stderr.
--
Si les descripteurs de fichiers sont épuisés, Lisp mourra.
--
Plusieurs fonctionnalités proposées par ANSI Common Lisp (CLtL II) ne sont pas implémentées : toutes les fonctionnalités CLOS non implémentées par PCL, et les fonctionnalités ajoutées depuis le premier projet de norme ANSI.
--
Le pré-traitement de l'interpréteur se bloque dans les définitions de macros en vigueur au moment où une fonction interprétée est définie.
