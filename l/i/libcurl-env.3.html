NOM

libcurl-env - variables d'environnement comprises par libcurl

DESCRIPTION

libcurl lit et comprend un ensemble de variables d'environnement qui, si elles sont définies, contrôlent et modifient les comportements. Voici la liste complète des variables à définir et la description de ce qu'elles font. Notez également que curl, l'outil en ligne de commande, prend en charge un ensemble de variables d'environnement supplémentaires indépendamment de celles-ci.

[schéma]_proxy
Lorsque libcurl reçoit une URL à utiliser dans un transfert, il en extrait d'abord la partie schéma et vérifie s'il existe un proxy défini pour celle-ci dans sa variable d'environnement correspondante. Une URL comme https://example.com amène libcurl à utiliser la variable http_proxy, tandis qu'une URL comme ftp://example.com utilise la variable ftp_proxy.

Ces variables de proxy sont également recherchées dans leurs versions majuscules, à l'exception de http_proxy qui n'est utilisé qu'en minuscules. Notez également que certains systèmes gèrent les variables d'environnement sans tenir compte de la casse et dans ce cas, HTTP_PROXY fonctionne toujours.

Une exception existe pour les schémas d'URL WebSocket ws et wss, où libcurl vérifie d'abord ws_proxy ou wss_proxy, mais s'ils ne sont pas définis, il se rabat et essaie les versions http et https si elles sont définies.

ALL_PROXY
Il s'agit d'un réglage pour définir un proxy pour toutes les URL, indépendamment du schéma utilisé. Notez que les variables spécifiques au schéma remplacent celle-ci si elles sont définies.
CURL_SSL_BACKEND
Lorsque libcurl est compilé pour prendre en charge plusieurs backends SSL, il sélectionne un backend spécifique lors de sa première utilisation. Si aucun choix n'est fait par le programme utilisant libcurl, la sélection de cette variable est utilisée. La définition d'un nom qui n'est pas une alternative intégrée fait que libcurl conserve la valeur par défaut.

Noms des backends SSL (insensible à la casse) : GnuTLS, mbedTLS, OpenSSL, Rustls, Schannel, wolfSSL

HOME
Lorsque la fonctionnalité netrc est utilisée (CURLOPT_NETRC(3)), cette variable est vérifiée comme principal moyen de trouver le répertoire personnel « courant » dans lequel le fichier .netrc est susceptible de se trouver.
USERPROFILE
Lorsque la fonctionnalité netrc est utilisée (CURLOPT_NETRC(3)), cette variable est vérifiée comme moyen secondaire de trouver le répertoire personnel « courant » (uniquement sous Windows) dans lequel le fichier .netrc est susceptible de se trouver.
NETRC
Le nom du fichier utilisé comme fichier netrc lorsque CURLOPT_NETRC(3) est utilisé sans CURLOPT_NETRC_FILE(3). (Ajouté dans 8.16.0)
NO_PROXY
Ceci a la même fonctionnalité que l'option CURLOPT_NOPROXY(3) : elle donne à libcurl une liste de modèles de noms d'hôtes séparés par des virgules pour lesquels libcurl ne doit pas utiliser de proxy.
SSLKEYLOGFILE
Lorsqu'elle est définie et que libcurl fonctionne avec un backend SSL prenant en charge cette fonctionnalité, libcurl enregistre les secrets SSL dans le nom de fichier donné. En utilisant ces secrets SSL, d'autres outils (tels que Wireshark) peuvent décrypter la communication SSL et analyser/afficher le trafic.

Ces secrets et ce fichier peuvent être sensibles. Les utilisateurs sont invités à prendre des précautions pour qu'ils ne soient pas volés ou divulgués par inadvertance.

Variables de débogage

Les variables de débogage sont destinées à un usage interne et sont documentées dans libcurl-env-dbg(3).
