X509_CHECK_HOST(3) Manuel des fonctions de bibliothèque X509_CHECK_HOST(3)

NOM

X509_check_host, X509_check_email, X509_check_ip, X509_check_ip_asc — Correspondance de certificat X.509

SYNOPSIS

bibliothèque « libcrypto »
#include <openssl/x509v3.h>

int
X509_check_host(X509 *x, const char *name, size_t namelen, unsigned int flags, char **peername);

int
X509_check_email(X509 *x, const char *address, size_t addresslen, unsigned int flags);

int
X509_check_ip(X509 *x, const unsigned char *address, size_t addresslen, unsigned int flags);

int
X509_check_ip_asc(X509 *x, const char *address, unsigned int flags);

DESCRIPTION

Les fonctions de correspondance de certificat sont utilisées pour vérifier si un certificat correspond à un nom d'hôte, une adresse électronique ou une adresse IP donné(e). La validité du certificat et son niveau de confiance doivent être vérifiés par d'autres moyens.

X509_check_host() vérifie si le nom alternatif du sujet (SAN) ou le nom commun du sujet (CN) du certificat correspond au nom d'hôte spécifié, qui doit être encodé dans la syntaxe de nom préférée décrite dans la section 3.5 de la RFC 1034. Par défaut, les jokers sont pris en charge et ils ne correspondent que dans le label le plus à gauche ; ils peuvent correspondre à une partie de ce label avec un préfixe ou un suffixe explicite. Par exemple, par défaut, le nom d'hôte name « www.example.com » correspondrait à un certificat avec une valeur SAN ou CN de « *.example.com », « w*.example.com » ou « *w.example.com ».

Selon la section 6.4.2 de la RFC 6125, les valeurs name représentant des noms de domaine internationaux doivent être fournies sous forme d'étiquette A. L'argument namelen doit être le nombre de caractères dans la chaîne name ou zéro, auquel cas la longueur est calculée avec strlen(name). Lorsque name commence par un point (par exemple, « .example.com »), il sera mis en correspondance par un certificat valide pour tout sous-domaine de name; voir aussi X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS ci-dessous.

Lorsque le certificat correspond et que peername n'est pas NULL, un pointeur vers une copie du SAN ou du CN correspondant du certificat pair est stocké à l'adresse passée dans peername. L'application est responsable de libérer peername via free(3) lorsqu'il n'est plus nécessaire.

X509_check_email() vérifie si le certificat correspond à l'address électronique spécifiée. Seule la syntaxe de la boîte aux lettres de la RFC 822 est prise en charge. Les commentaires ne sont pas autorisés, et aucune tentative n'est faite pour normaliser les caractères entre guillemets. L'argument addresslen doit être le nombre de caractères dans la chaîne address ou zéro, auquel cas la longueur est calculée avec strlen(address).

X509_check_ip() vérifie si le certificat correspond à une adresse IPv4 ou IPv6 spécifiée. Le tableau address est au format binaire, en ordre des octets réseau. La longueur est soit 4 (IPv4) soit 16 (IPv6). Seules les adresses explicitement marquées dans les certificats sont prises en compte ; les adresses IP stockées dans les noms DNS et les noms communs sont ignorées.

X509_check_ip_asc() est similaire, sauf que la chaîne terminée par NUL address est d'abord convertie en représentation interne.

L'argument flags est généralement 0, mais il peut être le OU bit à bit des drapeaux suivants.

Le drapeau X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT fait en sorte que la fonction prenne en compte le sujet DN même si le certificat contient au moins un nom alternatif du sujet du bon type (nom DNS ou adresse électronique appropriée) ; par défaut, le sujet DN est ignoré lorsqu'au moins un nom alternatif du sujet correspondant est présent.

Les drapeaux restants ne sont significatifs que pour X509_check_host().

Le drapeau X509_CHECK_FLAG_NO_WILDCARDS désactive l'expansion des jokers.

Le drapeau X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS supprime la prise en charge de « * » comme modèle de joker dans les labels qui ont un préfixe ou un suffixe, tels que « www* » ou « *www ».

Le drapeau X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS permet à un « * » qui constitue le label complet d'un nom DNS (par exemple, « *.example.com ») de correspondre à plus d'un label dans name.

Le drapeau X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS restreint les valeurs name qui commencent par « . », qui autrement correspondraient à n'importe quel sous-domaine dans le certificat pair, pour ne correspondre qu'aux sous-domaines enfants directs. Ainsi, par exemple, avec ce drapeau défini, un name de « .example.com » correspondrait à un certificat pair avec un nom DNS de « www.example.com », mais ne correspondrait pas à un certificat pair avec un nom DNS de « www.sub.example.com ».

VALEUR DE RETOUR

Les fonctions retournent 1 en cas de correspondance réussie, 0 en cas d'échec de correspondance et -1 en cas d'erreur interne : généralement un échec d'allocation mémoire ou une erreur de décodage ASN.1.

Toutes les fonctions peuvent également retourner -2 si l'entrée est mal formée. Par exemple, X509_check_host() retourne -2 si le name fourni contient des octets NUL intégrés.

NOM

X509_check_host - vérifier si un nom d'hôte correspond à un nom de certificat

SYNTAXE


#include <openssl/x509.h>

int X509_check_host(X509 *x509, const char *name, size_t namelen, unsigned int flags,
                    X509_STORE_CTX *ctx);

DESCRIPTION

La fonction X509_check_host vérifie si le nom d'hôte fourni par name (de longueur namelen) correspond au nom d'hôte du certificat x509. Le certificat x509 doit être le certificat de serveur dont le nom d'hôte doit être vérifié.

Les noms d'hôtes peuvent être présents dans les extensions Subject Alternative Name (SAN), ou à défaut, dans le champ Common Name (CN) du sujet du certificat.

Si ctx est non nul, il est supposé être un pointeur vers une structure X509_STORE_CTX qui est utilisée pour la validation du certificat. Dans ce cas, des informations supplémentaires peuvent être extraites du contexte pour aider à la correspondance des noms d'hôtes.

Le paramètre flags peut être utilisé pour modifier le comportement de la fonction :

  • X509_CHECK_FLAG_NO_SUBJECT_ALT_NAME : Ignore l'extension SAN. La correspondance ne sera effectuée qu'avec le CN.
  • X509_CHECK_FLAG_NO_CANONICALIZE : Ne pas canonicaliser le nom d'hôte fourni avant la comparaison.
  • X509_CHECK_FLAG_SINGLE_LABEL_APP_INSENSITIVE : Pour les noms d'hôtes à un seul label, la comparaison est insensible à la casse. Ceci est utilisé par exemple pour les noms comme "localhost".
  • X509_CHECK_FLAG_NEVER_GLOBAL : Traite tous les noms d'hôtes comme s'ils étaient locaux.

VALEURS DE RETOUR

X509_check_host retourne :

  • 1 si une correspondance est trouvée.
  • 0 si aucune correspondance n'est trouvée.
  • -1 en cas d'erreur.
