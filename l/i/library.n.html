INTRODUCTION

Tcl inclut une bibliothèque de procédures Tcl pour des fonctions couramment nécessaires. Les procédures définies dans la bibliothèque Tcl sont génériques et conviennent à une utilisation par de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est retourné par la commande info library. En plus de la bibliothèque Tcl, chaque application aura normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la variable globale $app_library, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit sourcer le fichier init.tcl dans la bibliothèque, par exemple avec la commande Tcl

source [file join [info library] init.tcl]

Si la procédure de bibliothèque Tcl_Init est invoquée à partir de la procédure Tcl_AppInit d'une application, cela se fait automatiquement. Le code de init.tcl définira la procédure unknown et organisera le chargement des autres procédures à la demande en utilisant le mécanisme de chargement automatique défini ci-dessous.

PROCÉDURES DE COMMANDES

Les procédures suivantes sont fournies dans la bibliothèque Tcl :

auto_execok cmd
Détermine s'il existe un fichier exécutable ou une commande shell intégrée du nom de cmd. Si c'est le cas, elle renvoie une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande shell intégrée nommée par cmd. Sinon, elle renvoie une chaîne vide. Cette commande examine les répertoires du chemin de recherche actuel (donné par la variable d'environnement PATH) dans sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok mémorise des informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche de chemin dans les appels ultérieurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations mises en cache.
auto_import pattern
Auto_import est invoquée lors de namespace import pour vérifier si les commandes importées spécifiées par pattern résident dans une bibliothèque chargée automatiquement. Si c'est le cas, les commandes sont chargées de manière à être disponibles pour l'interpréteur afin de créer les liens d'importation. Si les commandes ne résident pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance de motifs est effectuée selon les règles de correspondance de namespace import.
auto_load cmd
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un chemin de chargement automatique, qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path s'il existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique se compose uniquement du répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créé avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple, parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels ultérieurs à auto_load vérifient cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index mises en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque.
auto_mkindex dir pattern pattern ...
Génère un index approprié pour auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments pattern (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commande Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun motif n'est donné, un motif de *.tcl sera supposé. Par exemple, la commande
auto_mkindex foo *.tcl

lira tous les fichiers .tcl du sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex.

Auto_mkindex analyse les scripts Tcl en les sourçant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le package auto_mkindex_parser (non documenté) pour enregistrer d'autres commandes qui peuvent contribuer à l'index de chargement automatique. Vous devrez lire auto.tcl pour voir comment cela fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl d'une manière relativement peu sophistiquée : si une ligne contient le mot “proc” comme premiers caractères, alors elle est supposée être une définition de procédure et le mot suivant de la ligne est pris comme nom de la procédure. Les définitions de procédure qui n'apparaissent pas de cette manière (par exemple, elles ont des espaces avant le proc) ne seront pas indexées. Si votre script contient du code “dangereux”, tel que du code d'initialisation global ou des noms de procédure avec des caractères spéciaux tels que $, *, [ ou ], vous êtes plus en sécurité en utilisant auto_mkindex_old.

auto_reset
Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues sur disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures listées dans l'index de chargement automatique, afin que de nouvelles copies soient chargées la prochaine fois qu'elles seront utilisées.
auto_qualify command namespace
Calcule une liste de noms entièrement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour la recherche de commandes : d'abord, il recherche la commande dans l'espace de noms actuel, puis dans l'espace de noms global. Par conséquent, si command est relative et que namespace n'est pas ::, la liste retournée a deux éléments : command avec le scope namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. Sinon, si command est absolue (elle commence par ::), ou si namespace est ::, la liste ne contient que command comme s'il s'agissait d'une commande dans l'espace de noms global.

Auto_qualify est utilisé par les installations de chargement automatique dans Tcl, à la fois pour produire des index de chargement automatique tels que pkgIndex.tcl, et pour effectuer le chargement automatique réel des fonctions à l'exécution.

NAME

library -- standard directories for Tcl scripts

SYNOPSIS

unknown ?initScript?

parray arrayName ?pattern?

tcl_endOfWord str start

tcl_startOfNextWord str start

tcl_startOfPreviousWord str start

tcl_wordBreakAfter str start

tcl_wordBreakBefore str start

INTRODUCTION

The procedures described here are part of the Tcl support library.

COMMAND PROCEDURES

unknown ?initScript?
This is a standard search procedure for use by extensions during their initialization. They call this procedure to look for their script library in several standard directories. The last component of the name of the library directory is normally basenameversion (e.g., tk8.0), but it might be “library” when in the build hierarchies. The initScript file will be sourced into the interpreter once it is found. The directory in which this file is found is stored into the global variable varName. If this variable is already defined (e.g., by C code during application initialization) then no searching is done. Otherwise the search looks in these directories: the directory named by the environment variable enVarName; relative to the Tcl library directory; relative to the executable file in the standard installation bin or bin/arch directory; relative to the executable file in the current build tree; relative to the executable file in a parallel build tree.
parray arrayName ?pattern?
Prints on standard output the names and values of all the elements in the array arrayName, or just the names that match pattern (using the matching rules of string match) and their values if pattern is given. ArrayName must be an array accessible to the caller of parray. It may be either local or global.

WORD BOUNDARY HELPERS

These procedures are mainly used internally by Tk.

tcl_endOfWord str start
Returns the index of the first end-of-word location that occurs after a starting index start in the string str. An end-of-word location is defined to be the first non-word character following the first word character after the starting point. Returns -1 if there are no more end-of-word locations after the starting point. See the description of tcl_wordchars and tcl_nonwordchars below for more details on how Tcl determines which characters are word characters.
tcl_startOfNextWord str start
Returns the index of the first start-of-word location that occurs after a starting index start in the string str. A start-of-word location is defined to be the first word character following a non-word character. Returns -1 if there are no more start-of-word locations after the starting point.
tcl_startOfPreviousWord str start
Returns the index of the first start-of-word location that occurs before a starting index start in the string str. Returns -1 if there are no more start-of-word locations before the starting point.
tcl_wordBreakAfter str start
Returns the index of the first word boundary after the starting index start in the string str. Returns -1 if there are no more boundaries after the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.
tcl_wordBreakBefore str start
Returns the index of the first word boundary before the starting index start in the string str. Returns -1 if there are no more boundaries before the starting point in the given string. The index returned refers to the second character of the pair that comprises a boundary.

VARIABLES

The following global variables are defined or used by the procedures in the Tcl library. They fall into two broad classes, handling unknown commands and packages, and determining what are words.

AUTOLOADING AND PACKAGE MANAGEMENT VARIABLES

auto_execs
Used by auto_execok to record information about whether particular commands exist as executable files.
auto_index
Used by auto_load to save the index information read from disk.
auto_noexec
If set to any value, then unknown will not attempt to auto-exec any commands.
auto_noload
If set to any value, then unknown will not attempt to auto-load any commands.
auto_path
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations (including for package index files when using the default package unknown handler). This variable is initialized during startup to contain, in order: the directories listed in the TCLLIBPATH environment variable, the directory named by the tcl_library global variable, the parent directory of tcl_library, the directories listed in the tcl_pkgPath variable. Additional locations to look for files and package indices should normally be added to this variable using lappend.
env(TCL_LIBRARY)
If set, then it specifies the location of the directory containing library scripts (the value of this variable will be assigned to the tcl_library variable and therefore returned by the command info library). If this variable is not set then a default value is used.
env(TCLLIBPATH)
If set, then it must contain a valid Tcl list giving directories to search during auto-load operations. Directories must be specified in Tcl format, using “/” as the path separator, regardless of platform. This variable is only used when initializing the auto_path variable.

WORD BOUNDARY DETERMINATION VARIABLES

These variables are only used in the tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter, and tcl_wordBreakBefore commands.

tcl_nonwordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a non-word character. On Windows platforms, spaces, tabs, and newlines are considered non-word characters. Under Unix, everything but numbers, letters and underscores are considered non-word characters.
tcl_wordchars
This variable contains a regular expression that is used by routines like tcl_endOfWord to identify whether a character is part of a word or not. If the pattern matches a character, the character is considered to be a word character. On Windows platforms, words are comprised of any character that is not a space, tab, or newline. Under Unix, words are comprised of numbers, letters or underscores.
