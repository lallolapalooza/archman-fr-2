TLS_OCSP_PROCESS_RESPONSE(3) Manuel des fonctions de bibliothèque TLS_OCSP_PROCESS_RESPONSE(3)

NOM

tls_ocsp_process_response, tls_peer_ocsp_url, tls_peer_ocsp_response_status, tls_peer_ocsp_cert_status, tls_peer_ocsp_crl_reason, tls_peer_ocsp_result, tls_peer_ocsp_revocation_time, tls_peer_ocsp_this_update, tls_peer_ocsp_next_update — inspecter une réponse OCSP

SYNOPSIS

bibliothèque “libtls” libssl libcrypto
#include <tls.h>

int
tls_ocsp_process_response(struct tls *ctx, const unsigned char *response, size_t size);

const char *
tls_peer_ocsp_url(struct tls *ctx);

int
tls_peer_ocsp_response_status(struct tls *ctx);

int
tls_peer_ocsp_cert_status(struct tls *ctx);

int
tls_peer_ocsp_crl_reason(struct tls *ctx);

const char *
tls_peer_ocsp_result(struct tls *ctx);

time_t
tls_peer_ocsp_revocation_time(struct tls *ctx);

time_t
tls_peer_ocsp_this_update(struct tls *ctx);

time_t
tls_peer_ocsp_next_update(struct tls *ctx);

DESCRIPTION

tls_ocsp_process_response() traite une réponse OCSP brute dans response de taille size pour vérifier le statut de révocation du certificat du pair à partir de ctx. Un code de retour de succès de 0 indique que le certificat n'a pas été révoqué.

tls_peer_ocsp_url() retourne l'URL pour la validation OCSP du certificat du pair à partir de ctx.

Les fonctions suivantes retournent des informations sur le certificat du pair à partir de ctx qui ont été obtenues en validant une réponse OCSP « stapled » pendant l'établissement de la connexion, ou via un appel précédent à tls_ocsp_process_response().

tls_peer_ocsp_response_status() retourne le statut de la réponse OCSP conformément à la RFC 6960 section 2.3.

tls_peer_ocsp_cert_status() retourne le code de statut du certificat OCSP conformément à la RFC 6960 section 2.2.

tls_peer_ocsp_crl_reason() retourne le code de statut de raison de révocation du certificat OCSP conformément à la RFC 5280 section 5.3.1.

tls_peer_ocsp_result() retourne une représentation textuelle du code de statut OCSP retourné par l'une des trois fonctions précédentes. Si la réponse OCSP était valide et que le certificat n'a pas été révoqué, la chaîne indique le statut du certificat OCSP. Sinon, la chaîne indique la raison de la révocation du certificat OCSP ou l'erreur OCSP.

tls_peer_ocsp_revocation_time() retourne l'heure de révocation OCSP.

tls_peer_ocsp_this_update() retourne l'heure de mise à jour OCSP.

tls_peer_ocsp_next_update() retourne l'heure de la prochaine mise à jour OCSP.

VALEUR DE RETOUR

tls_ocsp_process_response() retourne 0 en cas de succès ou -1 en cas d'erreur.

tls_peer_ocsp_url() et tls_peer_ocsp_result() retournent NULL en cas d'erreur ou de manque de mémoire.

La fonction tls_peer_ocsp_response_status() retourne l'une des valeurs suivantes : TLS_OCSP_RESPONSE_SUCCESSFUL, TLS_OCSP_RESPONSE_MALFORMED, TLS_OCSP_RESPONSE_INTERNALERROR, TLS_OCSP_RESPONSE_TRYLATER, TLS_OCSP_RESPONSE_SIGREQUIRED, ou TLS_OCSP_RESPONSE_UNAUTHORIZED en cas de succès, et -1 en cas d'erreur.

La fonction tls_peer_ocsp_cert_status() retourne l'une des valeurs suivantes : TLS_OCSP_CERT_GOOD, TLS_OCSP_CERT_REVOKED, ou TLS_OCSP_CERT_UNKNOWN en cas de succès, et -1 en cas d'erreur.

La fonction tls_peer_ocsp_crl_reason() retourne l'une des valeurs suivantes : TLS_CRL_REASON_UNSPECIFIED, TLS_CRL_REASON_KEY_COMPROMISE, TLS_CRL_REASON_CA_COMPROMISE, TLS_CRL_REASON_AFFILIATION_CHANGED, TLS_CRL_REASON_SUPERSEDED, TLS_CRL_REASON_CESSATION_OF_OPERATION, TLS_CRL_REASON_CERTIFICATE_HOLD, TLS_CRL_REASON_REMOVE_FROM_CRL, TLS_CRL_REASON_PRIVILEGE_WITHDRAWN, ou TLS_CRL_REASON_AA_COMPROMISE en cas de succès ou -1 en cas d'erreur.

tls_peer_ocsp_revocation_time(), tls_peer_ocsp_this_update(), et tls_peer_ocsp_next_update() retournent un temps en secondes depuis l'époque en cas de succès ou -1 en cas d'erreur.

VOIR AUSSI

tls_client(3), tls_config_ocsp_require_stapling(3), tls_conn_version(3), tls_connect(3), tls_handshake(3), tls_init(3)

NAME

tls_ocsp_process_response, tls_ocsp_add_status, tls_ocsp_verify_response - process an OCSP response

SYNOPSIS

#include <tls.h>

int
tls_ocsp_process_response(struct tls_config *config,
    const char *cert_der, size_t cert_der_len,
    const char *response_der, size_t response_der_len);

int
tls_ocsp_add_status(struct tls_config *config,
    const char *cert_der, size_t cert_der_len,
    const char *response_der, size_t response_der_len);

int
tls_ocsp_verify_response(struct tls_config *config,
    const char *cert_der, size_t cert_der_len,
    const char *response_der, size_t response_der_len);

DESCRIPTION

These functions are intended to be used to implement client-side OCSP stapling.

When a client connects to a server, it can request that the server provide a cached OCSP response for the server's certificate. This can be done by setting the OCSP staple extension in the client's TLS Hello message.

If the server supports OCSP stapling, it will respond with an OCSP response that is signed by the server's certificate. The client can then verify this response using tls_ocsp_process_response().

The tls_ocsp_add_status() function is intended to be used by servers to add an OCSP response to their certificate. The tls_ocsp_verify_response() function is intended to be used by clients to verify an OCSP response that has been stapled to a certificate.

The config parameter is a pointer to a struct tls_config structure that has been initialized with tls_config_create().

The cert_der and response_der parameters are pointers to DER-encoded certificates and OCSP responses, respectively. The cert_der_len and response_der_len parameters are the lengths of the certificate and response data.

RETURN VALUES

These functions return 0 on success, or -1 on error.

ssl(3), tls(3), tls_config(3), tls_connect(3), tls_accept(3)

tls_ocsp_process_response, tls_ocsp_add_status, tls_ocsp_verify_response - traiter une réponse OCSP

SYNTAXE

#include <tls.h>

int
tls_ocsp_process_response(struct tls_config *config,

DESCRIPTION

Ces fonctions sont destinées à être utilisées pour implémenter le greffage OCSP côté client.

Lorsqu'un client se connecte à un serveur, il peut demander au serveur de fournir une réponse OCSP mise en cache pour le certificat du serveur. Cela peut être fait en définissant l'extension de greffage OCSP dans le message TLS Hello du client.

Si le serveur prend en charge le greffage OCSP, il répondra avec une réponse OCSP signée par le certificat du serveur. Le client peut ensuite vérifier cette réponse en utilisant tls_ocsp_process_response().

La fonction tls_ocsp_add_status() est destinée à être utilisée par les serveurs pour ajouter une réponse OCSP à leur certificat. La fonction tls_ocsp_verify_response() est destinée à être utilisée par les clients pour vérifier une réponse OCSP qui a été greffée à un certificat.

Le paramètre config est un pointeur vers une structure struct tls_config qui a été initialisée avec tls_config_create().

Les paramètres cert_der et response_der sont des pointeurs vers des certificats et des réponses OCSP encodés en DER, respectivement. Les paramètres cert_der_len et response_der_len sont les longueurs des données du certificat et de la réponse.

VALEURS DE RETOUR

Ces fonctions retournent 0 en cas de succès, ou -1 en cas d'erreur.
