DESCRIPTION

Chacune de ces fonctions retourne un nombre premier de Sophie Germain spécifique constant p.

Si bn est NULL, un nouvel objet BIGNUM est créé et retourné. Sinon, le nombre est stocké dans *bn et bn est retourné.

Tous ces nombres sont de la forme

p=2s−2s−64−1+264*2s−130π+offset

où s est la taille de la représentation binaire du nombre en bits et apparaît à la fin des noms de fonctions. Tant que l'offset est suffisamment petit, la forme ci-dessus assure que les 64 bits supérieurs et inférieurs de chaque nombre sont tous à 1.

Les offsets sont définis dans les normes comme suit:

taille s offset
 768 = 3 * 2^8 149686
1024 = 2 * 2^9 129093
1536 = 3 * 2^9 741804
2048 = 2 * 2^10 124476
3072 = 3 * 2^10 1690314
4096 = 2 * 2^11 240904
6144 = 3 * 2^11 929484
8192 = 2 * 2^12 4743158

Pour chacun de ces nombres premiers, le groupe fini des nombres naturels inférieurs à p, où l'opération de groupe est définie comme la multiplication modulo p, est utilisé pour l'échange de clés Diffie-Hellman. Les deux premiers de ces groupes sont appelés le Premier Groupe Oakley et le Deuxième Groupe Oakley. Évidemment, tous ces groupes sont des groupes cycliques d'ordre p, respectivement, et les nombres retournés par ces fonctions ne sont pas des secrets.

VALEUR DE RETOUR

Si l'allocation de mémoire échoue, ces fonctions retournent NULL. Cela peut se produire même si bn n'est pas NULL.

VOIR AUSSI

BN_mod_exp(3), BN_new(3), BN_set_flags(3), DH_new(3)

NORMES

RFC 2409, "The Internet Key Exchange (IKE)", définit les Groupes Oakley.

RFC 2412, "The OAKLEY Key Determination Protocol", contient des informations supplémentaires sur ces nombres.

RFC 3526, "More Modular Exponential (MODP) Diffie-Hellman groups for Internet Key Exchange (IKE)", définit les six autres nombres.

HISTORIQUE

BN_get_rfc2409_prime_768(), BN_get_rfc2409_prime_1024(), BN_get_rfc3526_prime_1536(), BN_get_rfc3526_prime_2048(), BN_get_rfc3526_prime_3072(), BN_get_rfc3526_prime_4096(), BN_get_rfc3526_prime_6144(), et BN_get_rfc3526_prime_8192() sont apparues pour la première fois dans OpenSSL 1.1.0 et sont disponibles depuis OpenBSD 6.3. Les mêmes fonctions sans le préfixe BN_ sont apparues pour la première fois dans OpenSSL 0.9.8a et OpenBSD 4.5; elles ont été supprimées dans OpenBSD 7.4.

AVERTISSEMENTS

Étant donné que toute la mémoire nécessaire au stockage des nombres est allouée dynamiquement, le drapeau BN_FLG_STATIC_DATA n'est pas défini sur les objets BIGNUM retournés. Soyez donc prudent de ne pas modifier les nombres retournés.
