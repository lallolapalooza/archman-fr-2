EVP_MD_NID(3) Manuel des fonctions de bibliothèque EVP_MD_NID(3)

NOM

DESCRIPTION

EVP_MD_nid() et EVP_MD_type() sont identiques et renvoient l'identifiant numérique (NID) de md. Le NID est une valeur interne qui peut ou non avoir un identifiant d'objet ASN.1 correspondant ; voir OBJ_nid2obj(3) pour plus de détails. Par exemple, EVP_MD_type(EVP_sha512()) renvoie NID_sha512. EVP_MD_CTX_type() renvoie le NID de l'algorithme de condensation de message que ctx est configuré pour utiliser. Ces fonctions sont normalement utilisées lors de la définition des OID ASN.1.

EVP_MD_name() convertit le NID de md en son nom court avec OBJ_nid2sn(3).

EVP_MD_size() renvoie la taille en octets des condensations de message (hachages) produites par md. EVP_MD_CTX_size() renvoie la taille des hachages produits par l'algorithme de condensation de message que ctx est configuré pour utiliser.

EVP_MD_block_size() renvoie la taille de bloc en octets de md. EVP_MD_CTX_block_size() renvoie la taille de bloc de l'algorithme de condensation de message que ctx est configuré pour utiliser.

EVP_MD_flags() renvoie les indicateurs de condensation de message utilisés par md. Faites attention à ne pas confondre ces indicateurs avec les indicateurs de contexte de condensation de message non liés qui peuvent être inspectés avec EVP_MD_CTX_test_flags(3). Les indicateurs disponibles sont :

EVP_MD_FLAG_DIGALGID_NULL
Les paramètres d'un DigestAlgorithmIdentifier sont encodés en utilisant un NULL ASN.1 explicite plutôt que de les omettre. C'est le comportement par défaut, ce qui signifie qu'il prend effet pour les objets EVP_MD qui n'ont pas EVP_MD_FLAG_DIGALGID_ABSENT défini.
EVP_MD_FLAG_DIGALGID_ABSENT
Les paramètres d'un DigestAlgorithmIdentifier sont omis de l'encodage ASN.1. Ceci est utilisé par les objets EVP_MD décrits dans la page de manuel EVP_sha3_224(3) et par les objets renvoyés par EVP_sha512(3), EVP_sha512_256(3), EVP_sha512_224(3), EVP_sha384(3), EVP_sha256(3), EVP_sha224(3), EVP_sha1(3), et EVP_sm3(3).
EVP_MD_FLAG_DIGALGID_CUSTOM
Cet indicateur est réservé aux objets EVP_MD définis par l'utilisateur supportant la gestion personnalisée de DigestAlgorithmIdentifier via EVP_MD_CTX_ctrl(3), mais en réalité, il est ignoré par LibreSSL et OpenSSL et un tel comportement défini par l'utilisateur n'est pas pris en charge par les bibliothèques.
EVP_MD_FLAG_FIPS
Marque la méthode de condensation comme adaptée au mode FIPS. Cet indicateur est ignoré par LibreSSL et OpenSSL.
EVP_MD_FLAG_ONESHOT
Destiné à indiquer que la méthode de condensation ne peut gérer qu'un seul bloc d'entrée, mais en réalité, cet indicateur est ignoré par LibreSSL et OpenSSL.

EVP_MD_pkey_type() renvoie le NID de l'algorithme de signature de clé publique associé à cette condensation. Par exemple, EVP_sha512(3) est associé à RSA, donc cela renvoie NID_sha512WithRSAEncryption. Puisque les condensations et les algorithmes de signature ne sont plus liés, cette fonction n'est conservée que pour des raisons de compatibilité.

EVP_MD_nid(), EVP_MD_CTX_type(), EVP_MD_name(), EVP_MD_CTX_size(), et EVP_MD_CTX_block_size() sont implémentées sous forme de macros.

VALEURS DE RETOUR

EVP_MD_nid(), EVP_MD_type(), EVP_MD_CTX_type(), et EVP_MD_pkey_type() renvoient le NID de l'identifiant d'objet correspondant ou NID_undef si aucun n'existe.

EVP_MD_name() renvoie un pointeur vers une chaîne appartenant à un objet de bibliothèque interne ou NULL si le NID n'est ni intégré dans la bibliothèque ni ajouté à la table d'objets globale par l'une des fonctions décrites dans la page de manuel OBJ_create(3), ou si l'objet ne contient pas de nom court.

EVP_MD_size(), EVP_MD_CTX_size(), EVP_MD_block_size(), et EVP_MD_CTX_block_size() renvoient la taille en octets de la condensation ou du bloc.

VOIR AUSSI

evp(3), EVP_DigestInit(3), EVP_MD_nid(3)

NOM

#include <openssl/evp.h>
int EVP_MD_nid(const EVP_MD *md);
const char *EVP_MD_name(const EVP_MD *md);
int EVP_MD_size(const EVP_MD *md);
int EVP_MD_type(const EVP_MD *md);
int EVP_MD_pkey_type(const EVP_MD *md);
unsigned long EVP_MD_flags(const EVP_MD *md);
int EVP_MD_block_size(const EVP_MD *md);
int EVP_MD_CTX_size(const EVP_MD_CTX *ctx);
int EVP_MD_CTX_type(const EVP_MD_CTX *ctx);
int EVP_MD_CTX_block_size(const EVP_MD_CTX *ctx);

DESCRIPTION

Ces fonctions fournissent des informations sur la structure EVP_MD et la structure EVP_MD_CTX. La structure EVP_MD représente un algorithme de hachage cryptographique.

Les fonctions suivantes opèrent sur une structure EVP_MD:

EVP_MD_nid
Retourne le NID (Numeric Identifier) pour le hachage md.
EVP_MD_name
Retourne le nom canonique pour le hachage md.
EVP_MD_size
Retourne la taille de la sortie du hachage md en octets.
EVP_MD_type
Retourne le type d'objet (pour l'OBJ_obj2nid(3)) pour le hachage md.
EVP_MD_pkey_type
Retourne le type d'objet pour la clé publique associée au hachage md. Ceci est généralement utilisé pour le hachage et la signature des messages.
EVP_MD_flags
Retourne les drapeaux associés au hachage md. Voir EVP_get_digestbyname(3) pour une description des drapeaux.
EVP_MD_block_size
Retourne la taille du bloc du hachage md en octets.

Les fonctions suivantes opèrent sur une structure EVP_MD_CTX. Un EVP_MD_CTX est généralement obtenu à partir de EVP_MD_CTX_new(3) ou EVP_MD_CTX_create(3), puis initialisé avec un hachage via EVP_DigestInit(3), EVP_DigestInit_ex(3) ou EVP_MD_CTX_copy(3).

EVP_MD_CTX_size
Retourne la taille de la sortie du hachage configuré dans ctx en octets.
EVP_MD_CTX_type
Retourne le type d'objet pour le hachage configuré dans ctx.
EVP_MD_CTX_block_size
Retourne la taille du bloc du hachage configuré dans ctx en octets.

VALEURS DE RETOUR

Les fonctions qui retournent une taille ou un type retournent généralement une valeur entière non négative en cas de succès, ou 0 ou -1 en cas d'échec, selon la fonction spécifique et le contexte. Voir les pages de manuel individuelles pour plus de détails. Les fonctions qui retournent un pointeur retournent NULL en cas d'échec.

VOIR AUSSI

EVP_DigestInit(3), EVP_get_digestbyname(3), EVP_MD_CTX_new(3), EVP_MD_CTX_ctrl(3), OBJ_nid2obj(3)

NORMES

RFC 5754 : Utilisation des algorithmes SHA2 avec la syntaxe de message cryptographique

  • section 2 : Algorithmes de résumé de message

HISTORIQUE

EVP_MD_size() est apparu pour la première fois dans SSLeay 0.6.6, EVP_MD_CTX_size() et EVP_MD_CTX_type() dans SSLeay 0.8.0, EVP_MD_type() et EVP_MD_pkey_type() dans SSLeay 0.8.1, et EVP_MD_block_size() et EVP_MD_CTX_block_size() dans SSLeay 0.9.0. Toutes ces fonctions sont disponibles depuis OpenBSD 2.4.

EVP_MD_nid() et EVP_MD_name() sont apparus pour la première fois dans OpenSSL 0.9.7 et sont disponibles depuis OpenBSD 3.2.

EVP_MD_flags() est apparu pour la première fois dans OpenSSL 1.0.0 et est disponible depuis OpenBSD 4.9.

ATTENTION

Le comportement des fonctions prenant un argument EVP_MD_CTX est indéfini si elles sont appelées sur un ctx sur lequel aucun résumé de message n'a encore été configuré, par exemple un contexte fraîchement retourné par EVP_MD_CTX_new(3). Dans ce cas, le programme peut par exemple être terminé par un accès à un pointeur NULL.
