X509_PRINT_EX(3) Manuel des fonctions de bibliothèque X509_PRINT_EX(3)

NOM

X509_print_ex, X509_CERT_AUX_print, X509_print_ex_fp, X509_print, X509_print_fp — impressions lisibles d'un certificat X.509

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/x509.h>

int
X509_print_ex(BIO *bio, X509 *x, unsigned long nameflags, unsigned long skipflags);

int
X509_CERT_AUX_print(BIO *bio, X509_CERT_AUX *aux, int indent);

int
X509_print_ex_fp(FILE *fp, X509 *x, unsigned long nameflags, unsigned long skipflags);

int
X509_print(BIO *bio, X509 *x);

int
X509_print_fp(FILE *fp, X509 *x);

DESCRIPTION

X509_print_ex() imprime les informations contenues dans x dans bio sous une forme lisible par l'homme. L'impression est interrompue dès qu'une opération échoue, à l'exception des échecs lors de la tentative de décodage ou d'impression de la clé publique, des extensions X.509 version 3, ou de données auxiliaires non standard, qui ne sont pas considérés comme des erreurs.

Par défaut, les blocs d'informations suivants sont imprimés dans l'ordre suivant. Chaque bloc peut être ignoré en définissant le bit correspondant dans skipflags, fourni entre parenthèses après chaque description de bloc.

  • Une paire de lignes lisant « Certificate: » et « Data: » ne contenant aucune information. (X509_FLAG_NO_HEADER)
  • Le numéro de version du certificat tel que défini par la norme, suivi entre parenthèses de la valeur contenue dans le champ version en notation hexadécimale. Voir X509_get_version(3) pour plus de détails. (X509_FLAG_NO_VERSION)
  • Le numéro de série du certificat tel que retourné par X509_get_serialNumber(3). S'il n'est pas -1 et que sa conversion en long réussit, il est imprimé en format décimal et hexadécimal. S'il est -1, trop grand pour tenir dans un long, ou si la conversion échoue, il est imprimé octet par octet en notation hexadécimale. (X509_FLAG_NO_SERIAL)
  • Le nom de l'algorithme de signature est imprimé avec X509_signature_print(3). (X509_FLAG_NO_SIGNAME)
  • Le nom de l'émetteur retourné par X509_get_issuer_name(3) est imprimé avec X509_NAME_print_ex(3). (X509_FLAG_NO_ISSUER)
  • La période de validité de X509_get_notBefore(3) à X509_get_notAfter(3) est imprimée en utilisant ASN1_TIME_print(3). (X509_FLAG_NO_VALIDITY)
  • Le nom du sujet retourné par X509_get_subject_name(3) est imprimé avec X509_NAME_print_ex(3). (X509_FLAG_NO_SUBJECT)
  • L'algorithme de clé publique est imprimé avec i2a_ASN1_OBJECT(3), et la clé publique retournée par X509_get_pubkey(3) avec EVP_PKEY_print_public(3). (X509_FLAG_NO_PUBKEY)
  • Si un identifiant unique de l'émetteur ou du sujet est présent, son vidage hexadécimal est imprimé avec X509_signature_dump(3). (X509_FLAG_NO_IDS)
  • Toutes les extensions X.509 contenues dans le certificat sont imprimées avec X509V3_extensions_print(3). (X509_FLAG_NO_EXTENSIONS)
  • La signature est imprimée avec X509_signature_print(3). (X509_FLAG_NO_SIGDUMP)
  • Les données auxiliaires non standard associées au certificat sont imprimées en utilisant la fonction X509_CERT_AUX_print() décrite ci-dessous. (X509_FLAG_NO_AUX)

L'argument nameflags modifie le format d'impression des objets Name X.501 contenus dans x. Il est transmis à X509_NAME_print_ex(3). Si nameflags est X509_FLAG_COMPAT, l'argument indent de X509_NAME_print_ex(3) est défini à 16 espaces et le format traditionnel SSLeay est utilisé. Sinon, si le seul bit défini dans XN_FLAG_SEP_MASK est XN_FLAG_SEP_MULTILINE, indent est défini à 12 espaces. Sinon, indent est défini à zéro.

X509_CERT_AUX_print() imprime les informations contenues dans aux dans bio sous une forme lisible par l'homme avec une marge gauche de indent espaces. Si aux est NULL, elle n'imprime rien.

Les informations sont imprimées dans l'ordre suivant :

  • Les objectifs d'utilisation prévus du certificat, tels que définis par X509_add1_trust_object(3), chacun imprimé avec OBJ_obj2txt(3).
  • Les objectifs d'utilisation pour lesquels le certificat n'est pas explicitement prévu, tels que définis par X509_add1_reject_object(3), chacun à nouveau imprimé avec OBJ_obj2txt(3).
  • Si aux contient des données définies par X509_alias_set1(3), les octets bruts sont imprimés sous forme non encodée.
  • Si aux contient des données définies par X509_keyid_set1(3), les octets sont imprimés en notation hexadécimale avec des deux-points entre eux.

X509_print_ex_fp() est similaire à X509_print_ex() à l'exception près qu'elle imprime dans fp.

X509_print() et X509_print_fp() sont des fonctions d'enrobage qui définissent nameflags à XN_FLAG_COMPAT et skipflags à X509_FLAG_COMPAT.

VALEUR DE RETOUR

X509_print_ex(), X509_print_ex_fp(), X509_print(), et X509_print_fp() retournent 1 si toutes les informations demandées ont été imprimées avec succès, même si des erreurs se sont produites lors de la tentative de décodage ou d'impression de la clé publique ou des extensions X.509 version 3, ou 0 si une autre opération a échoué.

X509_CERT_AUX_print() retourne toujours 1 et ignore silencieusement les erreurs d'écriture.

VOIR AUSSI

VOIR AUSSI

HISTORIQUE

X509_print() est apparu pour la première fois dans SSLeay 0.5.1 et a été modifié pour imprimer vers un BIO dans SSLeay 0.6.0. X509_print_fp() est apparu pour la première fois dans SSLeay 0.6.0. Les deux fonctions sont disponibles depuis OpenBSD 2.4.

X509_CERT_AUX_print() est apparu pour la première fois dans OpenSSL 0.9.5 et est disponible depuis OpenBSD 2.7.

X509_print_ex() et X509_print_ex_fp() sont apparus pour la première fois dans OpenSSL 0.9.7 et sont disponibles depuis OpenBSD 3.2.

BOGUES

Si des données arbitraires ont été stockées dans x en utilisant X509_alias_set1(3), ces fonctions peuvent imprimer des données binaires et même des octets NUL.
