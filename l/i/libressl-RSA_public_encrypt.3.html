libressl-RSA_public_encrypt(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

RSA_PUBLIC_ENCRYPT(3) Manuel des fonctions de bibliothèque RSA_PUBLIC_ENCRYPT(3)

NOM

RSA_public_encrypt, RSA_private_decrypt, EVP_PKEY_encrypt_old, EVP_PKEY_decrypt_old — Cryptographie à clé publique RSA

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/rsa.h>

int
RSA_public_encrypt(int flen, const unsigned char *from, unsigned char *to, RSA *rsa, int padding);

int
RSA_private_decrypt(int flen, const unsigned char *from, unsigned char *to, RSA *rsa, int padding);

#include <openssl/evp.h>

int
EVP_PKEY_encrypt_old(unsigned char *to, const unsigned char *from, int flen, EVP_PKEY *pkey);

int
EVP_PKEY_decrypt_old(unsigned char *to, const unsigned char *from, int flen, EVP_PKEY *pkey);

DESCRIPTION

RSA_public_encrypt() chiffre les flen octets à l'adresse from (généralement une clé de session) en utilisant la clé publique rsa et stocke le texte chiffré dans to. to doit pointer vers RSA_size(rsa) octets de mémoire.

padding désigne l'un des modes suivants :

RSA_PKCS1_PADDING
Rembourrage PKCS #1 v1.5. C'est actuellement le mode le plus utilisé.
RSA_PKCS1_OAEP_PADDING
EME-OAEP tel que défini dans PKCS #1 v2.0 avec SHA-1, MGF1 et un paramètre d'encodage vide. Ce mode est recommandé pour toutes les nouvelles applications.
RSA_NO_PADDING
Chiffrement RSA brut. Ce mode ne doit être utilisé que pour implémenter des modes de remplissage cryptographiquement sûrs dans le code de l'application. Le chiffrement direct de données utilisateur avec RSA est non sécurisé.

flen doit être inférieur à RSA_size(rsa) - 11 pour les modes de remplissage basés sur PKCS #1 v1.5, inférieur à RSA_size(rsa) - 41 pour RSA_PKCS1_OAEP_PADDING et exactement RSA_size(rsa) pour RSA_NO_PADDING.

RSA_private_decrypt() déchiffre les flen octets à l'adresse from en utilisant la clé privée rsa et stocke le texte clair dans to. to doit pointer vers une section mémoire suffisamment grande pour contenir les données déchiffrées (qui est plus petite que RSA_size(rsa)). padding est le mode de remplissage utilisé pour chiffrer les données.

EVP_PKEY_encrypt_old() est une enveloppe obsolète autour de RSA_public_encrypt() qui utilise la clé publique RSA stockée dans pkey et RSA_PKCS1_PADDING.

EVP_PKEY_decrypt_old() est une enveloppe obsolète autour de RSA_private_decrypt() qui utilise la clé privée RSA stockée dans pkey et RSA_PKCS1_PADDING.

VALEURS DE RETOUR

RSA_public_encrypt() et EVP_PKEY_encrypt_old() renvoient la taille des données chiffrées (c'est-à-dire RSA_size(rsa)). RSA_private_decrypt() et EVP_PKEY_decrypt_old() renvoient la taille du texte clair retrouvé. En cas d'erreur, -1 est renvoyé ; les codes d'erreur peuvent être obtenus par ERR_get_error(3).

En plus des valeurs de retour documentées ci-dessus, EVP_PKEY_encrypt_old() peut renvoyer 0 si l'EVP_PKEY_id(3) de pkey n'est pas EVP_PKEY_RSA.

VOIR AUSSI

EVP_PKEY_decrypt(3), EVP_PKEY_encrypt(3), RSA_meth_set_priv_dec(3), RSA_new(3), RSA_size(3)

NORMES

SSL, PKCS #1 v2.0

HISTORIQUE

RSA_public_encrypt() et RSA_private_decrypt() sont apparues dans SSLeay 0.4 ou antérieur et sont disponibles depuis OpenBSD 2.4.

EVP_PKEY_encrypt() et EVP_PKEY_decrypt() sont apparues pour la première fois dans SSLeay 0.9.0 et sont disponibles depuis OpenBSD 2.4. Elles ont été renommées en EVP_PKEY_encrypt_old() et EVP_PKEY_decrypt_old() dans OpenSSL 1.0.0 et OpenBSD 4.9.

RSA_NO_PADDING est disponible depuis SSLeay 0.9.0. OAEP a été ajouté dans OpenSSL 0.9.2b.

BOGUES

Les échecs de déchiffrement dans le mode RSA_PKCS1_PADDING fuient des informations qui peuvent potentiellement être utilisées pour monter une attaque par oracle de remplissage de Bleichenbacher. Il s'agit d'une faiblesse inhérente à la conception du remplissage PKCS #1 v1.5. Préférez RSA_PKCS1_OAEP_PADDING.
