libressl-SSL_CTX_set_tmp_dh_callback(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

SSL_CTX_SET_TMP_DH_CALLBACK(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_TMP_DH_CALLBACK(3)

NOM

SSL_CTX_set_tmp_dh_callback, SSL_CTX_set_tmp_dh, SSL_set_tmp_dh_callback, SSL_set_tmp_dh — gérer les clés DH pour l'échange de clés éphémère

SYNOPSIS

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_CTX_set_tmp_dh_callback(SSL_CTX *ctx, DH *(*tmp_dh_callback)(SSL *ssl, int is_export, int keylength));

long
SSL_CTX_set_tmp_dh(SSL_CTX *ctx, DH *dh);

void
SSL_set_tmp_dh_callback(SSL *ssl, DH *(*tmp_dh_callback)(SSL *ssl, int is_export, int keylength);

long
SSL_set_tmp_dh(SSL *ssl, DH *dh);

DESCRIPTION

SSL_CTX_set_tmp_dh_callback() définit la fonction de rappel pour ctx à utiliser lorsqu'un paramètre DH est requis, vers tmp_dh_callback. Le rappel est hérité par tous les objets ssl créés à partir de ctx.

SSL_CTX_set_tmp_dh() définit les paramètres DH à utiliser par ctx. La clé est héritée par tous les objets ssl créés à partir de ctx.

SSL_set_tmp_dh_callback() définit le rappel uniquement pour ssl.

SSL_set_tmp_dh() définit les paramètres uniquement pour ssl.

Ces fonctions s'appliquent uniquement aux serveurs SSL/TLS.

Lors de l'utilisation d'un chiffrement avec authentification RSA, un échange de clés DH éphémère peut avoir lieu. Dans ces cas, les données de session sont négociées à l'aide de la clé DH éphémère/temporaire et la clé fournie et certifiée par la chaîne de certificats est uniquement utilisée pour la signature. Les chiffrements anonymes (sans clé serveur permanente) utilisent également des clés DH éphémères.

L'utilisation de l'échange de clés DH éphémère offre une sécurité parfaite de transmission (forward secrecy), car la connexion ne peut être déchiffrée que lorsque la clé DH est connue. En générant une clé DH temporaire au sein de l'application serveur qui est perdue lorsque l'application se termine, il devient impossible pour les attaquants de déchiffrer les sessions passées, même s'ils obtiennent la clé normale (certifiée), car cette clé n'a été utilisée que pour la signature.

Afin d'effectuer un échange de clés DH, le serveur doit utiliser un groupe DH (paramètres DH) et générer une clé DH. Le serveur générera toujours une nouvelle clé DH pendant la négociation.

Comme la génération de paramètres DH est extrêmement coûteuse en temps, une application ne devrait pas générer les paramètres à la volée mais fournir les paramètres. Les paramètres DH peuvent être réutilisés, car la clé réelle est nouvellement générée pendant la négociation. Le risque de réutilisation des paramètres DH est qu'un attaquant puisse se spécialiser sur un groupe DH très souvent utilisé. Les applications devraient donc générer leurs propres paramètres DH lors du processus d'installation en utilisant l'application openssl(1) dhparam. Cette application garantit que des nombres premiers "forts" sont utilisés.

Les fichiers dh2048.pem et dh4096.pem dans le répertoire apps de la version actuelle de la distribution OpenSSL contiennent les paramètres DH "SKIP", qui utilisent des nombres premiers sûrs et ont été générés de manière vérifiable pseudo-aléatoire. Ces fichiers peuvent être convertis en code C en utilisant l'option -C de l'application openssl(1) dhparam. La génération de paramètres DH personnalisés lors de l'installation devrait toujours être privilégiée pour empêcher un attaquant de se spécialiser sur un groupe couramment utilisé. Le fichier dh1024.pem contient d'anciens paramètres qui ne doivent pas être utilisés par les applications.

Une application peut soit spécifier directement les paramètres DH, soit fournir les paramètres DH via une fonction de rappel.

Les versions précédentes du rappel utilisaient les paramètres is_export et keylength pour contrôler la génération des paramètres pour les suites de chiffrement d'exportation et non d'exportation. Les serveurs modernes qui ne prennent pas en charge les chiffrements d'exportation sont invités à utiliser SSL_CTX_set_tmp_dh() ou, alternativement, à utiliser le rappel mais ignorer keylength et is_export et simplement fournir des paramètres d'au moins 2048 bits dans le rappel.

VALEURS DE RETOUR

SSL_CTX_set_tmp_dh() et SSL_set_tmp_dh() renvoient 1 en cas de succès et 0 en cas d'échec. Vérifiez la file d'attente d'erreurs pour connaître la raison de l'échec.

EXEMPLES

Configuration des paramètres DH avec une longueur de clé de 2048 bits. La gestion des erreurs est partiellement omise.

Génération de paramètres en ligne de commande :

openssl dhparam -out dh_param_2048.pem 2048

Code pour configurer les paramètres lors de l'initialisation du serveur :

SSL_CTX ctx = SSL_CTX_new();
...

/* Configuration des paramètres DH éphémères. */
DH *dh_2048 = NULL;
FILE *paramfile;
paramfile = fopen("dh_param_2048.pem", "r");
if (paramfile) {
	dh_2048 = PEM_read_DHparams(paramfile, NULL, NULL, NULL);
	fclose(paramfile);
} else {
	/* Erreur. */
}
if (dh_2048 == NULL) {
	/* Erreur. */
}
if (SSL_CTX_set_tmp_dh(ctx, dh_2048) != 1) {
	/* Erreur. */
}
