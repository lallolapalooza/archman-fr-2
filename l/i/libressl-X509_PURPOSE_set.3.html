DESCRIPTION

Les buts pour lesquels un certificat X.509 est destiné à être utilisé peuvent être identifiés de trois manières équivalentes :

  1. Par des identifiants de but, qui sont des constantes entières positives. Les identifiants de but standard se situent dans la plage de X509_PURPOSE_MIN à X509_PURPOSE_MAX, inclus, et sont listés dans la page de manuel de X509_check_purpose(3). Les identifiants de but définis par l'utilisateur sont supérieurs à X509_PURPOSE_MAX.
  2. Par des indices de but, qui sont des constantes entières non négatives mais différentes des identifiants de but pour le même but. Les indices de but standard sont inférieurs à X509_PURPOSE_MAX. Les indices de but définis par l'utilisateur sont supérieurs ou égaux à X509_PURPOSE_MAX.
  3. Par des objets de but de type X509_PURPOSE. Les objets de but standard sont disponibles dans le stockage statique. Les objets de but définis par l'utilisateur peuvent être créés avec X509_PURPOSE_add().

Les programmeurs d'applications ne peuvent pas choisir la manière d'identifier les buts qui leur plaît le plus ; selon les circonstances, les trois méthodes sont nécessaires. Attention, la dénomination de la plupart des fonctions est trompeuse.

La plupart des fonctions de l'API documentées en dehors de la présente page de manuel utilisent des identifiants de but plutôt que des indices de but.

Utilisation des identifiants de but

X509_PURPOSE_set() valide l'identifiant de but id_in. S'il est valide, il est copié dans *id_out. Sinon, *id_out reste inchangé.

X509_PURPOSE_get_by_id() convertit l'identifiant de but en l'indice de but correspondant. Pour trouver l'objet de but correspondant, passez le résultat à X509_PURPOSE_get0().

X509_PURPOSE_add() définit un but avec l'identifiant donné ou modifie ses propriétés s'il existe déjà. L'identifiant du but, l'identifiant de trust, les flags, la fonction check_purpose, le name, le nom court sname, et le pointeur usr_data sont copiés dans l'objet X509_PURPOSE. Lors de la modification d'un objet de but existant, les valeurs précédentes des champs sont écrasées et les chaînes name et sname précédentes sont libérées si elles étaient allouées dynamiquement. Lors de la création d'un nouvel objet de but, il est ajouté au tableau global des objets de but définis par l'utilisateur.

X509_PURPOSE_DYNAMIC et X509_PURPOSE_DYNAMIC_NAME sont toujours ignorés dans l'argument flags. X509_PURPOSE_DYNAMIC est automatiquement défini si l'objet a été créé par l'utilisateur. Il n'est jamais défini pour les objets standards, même s'ils ont été modifiés par l'utilisateur. X509_PURPOSE_DYNAMIC_NAME est automatiquement défini si l'objet a été créé ou modifié par l'utilisateur. Il n'est désactivé que pour les objets standards non modifiés. La bibliothèque ne semble pas définir d'autres indicateurs, donc l'argument flags est probablement inutile, sauf si les utilisateurs définissent leurs propres indicateurs et les utilisent dans la fonction check_purpose.

Le troisième et dernier argument de la fonction check_purpose est l'argument ca documenté dans X509_check_purpose(3).

X509_PURPOSE_get_count() retourne le nombre total de buts actuellement définis, y compris les buts standards et ceux définis par l'utilisateur. Si aucun but défini par l'utilisateur n'existe, la valeur retournée est X509_PURPOSE_MAX.

X509_PURPOSE_cleanup() supprime tous les objets de but définis par l'utilisateur et invalide leurs identifiants de but et leurs indices de but. Si certains des objets de but standards ont été modifiés par l'utilisateur, ces modifications ne sont pas annulées.

Utilisation des indices de but

X509_PURPOSE_get0() convertit l'index de but en un pointeur vers l'objet de but correspondant. Pour trouver l'identifiant de but correspondant, passez le résultat à X509_PURPOSE_get_id().

X509_PURPOSE_get_by_sname() retourne l'indice le plus bas d'un but portant le nom court donné.

X509_PURPOSE_get0_name() retourne le nom lisible du but.

X509_PURPOSE_get0_sname() retourne le nom court du but.

X509_PURPOSE_get_trust() retourne la valeur de confiance associée au but.

DIAGNOSTICS

Les fonctions retournent 1 en cas de succès et 0 en cas d'échec. Les raisons de l'échec sont généralement dues à des arguments invalides. Les erreurs ne sont pas signalées par un code d'erreur spécifique, mais la réinitialisation de l'état interne de la bibliothèque peut être nécessaire.

libressl X509_PURPOSE_set(3) - Arch Linux

NAME

X509_PURPOSE_set, X509_PURPOSE_get_by_id, X509_PURPOSE_get_by_sname, X509_PURPOSE_add, X509_PURPOSE_get_count, X509_PURPOSE_get0, X509_PURPOSE_get_id, X509_PURPOSE_get0_name, X509_PURPOSE_get0_sname, X509_PURPOSE_get_trust - manipulater et obtenir des informations sur les buts X509

SYNOPSIS

#include <openssl/x509.h>

int
X509_PURPOSE_set(int id, X509_PURPOSE *p);

const X509_PURPOSE *
X509_PURPOSE_get_by_id(int id);

const X509_PURPOSE *
X509_PURPOSE_get_by_sname(const char *sname);

int
X509_PURPOSE_add(int id, X509_PURPOSE *p);

int
X509_PURPOSE_get_count(void);

const X509_PURPOSE *
X509_PURPOSE_get0(int index);

int
X509_PURPOSE_get_id(const X509_PURPOSE *p);

const char *
X509_PURPOSE_get0_name(const X509_PURPOSE *p);

const char *
X509_PURPOSE_get0_sname(const X509_PURPOSE *p);

int
X509_PURPOSE_get_trust(const X509_PURPOSE *p);

DESCRIPTION

Un objet X509_PURPOSE définit un but spécifique pour un certificat X509. Le but est généralement utilisé pour déterminer si un certificat peut être utilisé pour une opération spécifique, par exemple, l’authentification serveur ou client.

X509_PURPOSE_set() définit le champ purpose de l’objet X509_PURPOSE p à la valeur id. Ce champ n’est généralement pas utilisé.

X509_PURPOSE_get_by_id() renvoie un pointeur vers l’objet X509_PURPOSE correspondant à l’identifiant id. Si aucun but correspondant n’est trouvé, il renvoie NULL.

X509_PURPOSE_get_by_sname() renvoie un pointeur vers l’objet X509_PURPOSE correspondant au nom court sname. Si aucun but correspondant n’est trouvé, il renvoie NULL.

X509_PURPOSE_add() ajoute un nouveau but à la liste des buts enregistrés. L’identifiant est donné par id et les détails du but par p. Si le but existe déjà, il est mis à jour.

X509_PURPOSE_get_count() renvoie le nombre total de buts actuellement définis.

X509_PURPOSE_get0() renvoie un pointeur vers l’objet X509_PURPOSE à l’index spécifié index. Cet index est obtenu à partir des fonctions X509_PURPOSE_get_by_id() ou X509_PURPOSE_get_by_sname().

X509_PURPOSE_get_id(), X509_PURPOSE_get0_name(), X509_PURPOSE_get0_sname(), et X509_PURPOSE_get_trust() renvoient respectivement l’identifiant, le nom complet, le nom court et l’identifiant de confiance de l’objet object.

Si un nouveau but est ajouté, il est généralement nécessaire d’appeler X509_PURPOSE_get_by_id() avec le correspondant identifiant de but, pour passer le résultat à X509_PURPOSE_get0_name(), X509_PURPOSE_get0_sname(), et X509_PURPOSE_get_trust() pour récupérer le nom, le nom court et l’identifiant de confiance à partir de l’objet, respectivement.

RETURN VALUES

X509_PURPOSE_set() renvoie 1 si id_in est valide ou 0 sinon.

X509_PURPOSE_get_by_id() et X509_PURPOSE_get_by_sname() renvoient l’index de but correspondant ou -1 si aucun but correspondant n’est trouvé.

X509_PURPOSE_add() renvoie 1 en cas de succès ou 0 en cas d’échec.

X509_PURPOSE_get_count() renvoie le nombre total de buts actuellement définis.

X509_PURPOSE_get0() renvoie un objet de but standard ou défini par l’utilisateur ou NULL si l’index est invalide.

X509_PURPOSE_get_id() renvoie toujours un identifiant de but valide.

X509_PURPOSE_get0_name() et X509_PURPOSE_get0_sname() renvoient des pointeurs vers le stockage détenu par l’object.

X509_PURPOSE_get_trust() renvoie l’identifiant de confiance associé à l’object.

ERRORS

Les diagnostics suivants peuvent être récupérés avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3):

X509V3_R_INVALID_PURPOSE "but invalide"
X509_PURPOSE_set() a été appelé avec un argument id_in invalide.
X509V3_R_INVALID_NULL_ARGUMENT "argument nul invalide"
X509_PURPOSE_add() a été appelé avec un argument name ou sname de NULL.
ERR_R_MALLOC_FAILURE "échec d’allocation mémoire"
X509_PURPOSE_add() n’a pas réussi à allouer de mémoire.

Les autres fonctions ne fournissent aucun diagnostic.

HISTORY

X509_PURPOSE_set() est apparu pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

Les autres fonctions sont apparues pour la première fois dans OpenSSL 0.9.5 et sont disponibles depuis OpenBSD 2.7.
