NOM

libguestfs-test-tool - Diagnostic pour libguestfs

SYNTAXE

libguestfs-test-tool [--options]

DESCRIPTION

libguestfs-test-tool est un programme de test fourni avec libguestfs pour vous permettre de vérifier que les fonctionnalités de base de libguestfs fonctionnent. Ceci est nécessaire car libguestfs casse occasionnellement pour des raisons indépendantes de notre volonté : généralement en raison de changements dans les paquets qemu ou noyau sous-jacents, ou dans l'environnement hôte.

Si vous suspectez un problème dans libguestfs, exécutez simplement :

libguestfs-test-tool

Cela affichera de nombreux messages de diagnostic.

S'il s'exécute avec succès, vous verrez ceci vers la fin :

===== TEST FINISHED OK =====

et l'outil de test se terminera avec le code 0.

S'il échoue (et/ou se termine avec un code d'erreur non nul), veuillez coller la sortie complète, non modifiée de l'outil de test dans un rapport de bug. Plus d'informations sur la façon de signaler des bugs peuvent être trouvées sur le site web http://libguestfs.org/.

OPTIONS

--help
Affiche des informations d'utilisation courtes et quitte.
--qemu qemu_binaire
Si vous avez téléchargé un autre binaire qemu, pointez cette option vers le chemin complet du binaire pour l'essayer.
--qemudir qemu_repertoire_source
Si vous avez compilé qemu à partir des sources, pointez cette option vers le répertoire source pour l'essayer.
-t N
--timeout N
Définit le délai de lancement à "N" secondes. La valeur par défaut est de 600 secondes (10 minutes) et ne nécessite généralement pas d'ajustement.
-V
--version
Affiche le numéro de version de libguestfs et quitte.

ESSAYER UNE VERSION DIFFÉRENTE DE QEMU

Si vous avez compilé une autre version de qemu à partir des sources et que vous souhaitez l'essayer, vous pouvez utiliser l'option --qemudir pour pointer vers le répertoire source de qemu.

Si vous avez téléchargé un binaire qemu quelque part, utilisez l'option --qemu pour pointer vers le binaire.

Notez que lors de l'utilisation de ces options, vous pouvez ignorer la gestion des scripts wrapper qemu (« QEMU WRAPPERS » dans guestfs(3)), car libguestfs-test-tool écrit un script wrapper pour vous si nécessaire.

ESSAYER UN NOYAU DIFFÉRENT

Vous pouvez dire à supermin d'essayer un noyau différent. Vous le faites en définissant les variables d'environnement "SUPERMIN_KERNEL", "SUPERMIN_KERNEL_VERSION" et/ou "SUPERMIN_MODULES".

Reportez-vous à « VARIABLES D'ENVIRONNEMENT » dans supermin(1) pour plus d'informations.

ESSAYER UNE VERSION DIFFÉRENTE DE LIBVIRT

Pour savoir quel backend est par défaut dans votre paquet libguestfs, faites :

unset LIBGUESTFS_BACKEND
guestfish get-backend

Si vous utilisez le backend libvirt, vous pouvez essayer une version différente (par exemple, en amont) de libvirt en exécutant ces commandes (pas en tant que root) :

killall libvirtd lt-libvirtd
~/path/to/libvirt/run libguestfs-test-tool

La première commande tue tout processus "libvirtd" de session qui pourrait être en cours d'exécution sur la machine. La seconde commande utilise le script "run" de libvirt (dans le répertoire de build libvirt de niveau supérieur) pour définir certaines variables d'environnement afin que la version alternative de libvirt soit utilisée pour exécuter le programme.

ESSAYER AVEC / SANS LIBVIRT

Pour savoir quel backend est par défaut dans votre paquet libguestfs, faites :

unset LIBGUESTFS_BACKEND
guestfish get-backend

Si vous utilisez le backend libvirt, vous pouvez essayer sans (c'est-à-dire libguestfs lançant directement qemu) en faisant :

export LIBGUESTFS_BACKEND=direct

Ou si vous utilisez le backend par défaut (direct), vous pouvez essayer libvirt :

export LIBGUESTFS_BACKEND=libvirt

ou avec libvirt et une URI libvirt spécifique :

export LIBGUESTFS_BACKEND=libvirt:qemu:///session

ESSAYER AVEC DES PARAMÈTRES SELINUX DIFFÉRENTS

Pour savoir quel backend est par défaut dans votre paquet libguestfs, faites :

unset LIBGUESTFS_BACKEND
guestfish get-backend

Pour savoir si SELinux est utilisé, faites :

getenforce

Si vous utilisez libvirt, SELinux et sVirt, vous pouvez essayer de voir si le passage de SELinux en mode « permissif » fait une différence. Utilisez cette commande en tant que root :

setenforce Permissive

Si cela fait une différence, recherchez dans les journaux d'audit les échecs récents (« AVC ») :

ausearch -m avc -ts recent

Vous pouvez convertir les AVC en règles de politique SELinux suggérées en utilisant des outils comme audit2allow(1). Pour plus d'informations, consultez le « Guide de l'utilisateur SELinux ».

Pour réactiver SELinux et sVirt, faites :

setenforce Enforcing

AUTO-DIAGNOSTIC

Référez-vous à « PROCESSUS DE DÉMARRAGE DE L'APPAREIL » dans guestfs(3) pour comprendre les messages produits par libguestfs-test-tool et/ou les erreurs possibles.

STATUT DE SORTIE

libguestfs-test-tool renvoie 0 si les tests se sont terminés sans erreur, ou 1 s'il y a eu une erreur.

VARIABLES D'ENVIRONNEMENT

Pour la liste complète des variables d'environnement qui peuvent affecter libguestfs, veuillez consulter la page de manuel guestfs(3).
