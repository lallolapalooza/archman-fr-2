NOM

libnbd-release-notes-1.16 - notes de publication pour libnbd 1.16

DESCRIPTION

Ce sont les notes de publication pour la version stable de libnbd 1.16. Elles décrivent les changements majeurs depuis la version 1.14.

libnbd 1.16.0 a été publié le 18 avril 2023.

Sécurité

Aucun problème de sécurité n'a été trouvé dans cette version.

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour connaître les problèmes de sécurité précédents dans libnbd, consultez libnbd-security(3).

Nouvelles API

La nouvelle API nbd_supports_vsock(3) peut être utilisée pour tester si le client prend en charge vsock (Eric Blake).

La nouvelle API nbd_poll2(3) qui permet de passer un descripteur de fichier supplémentaire (Ming Lei).

Les nouvelles API nbd_stats_bytes_sent(3), nbd_stats_bytes_received(3), nbd_stats_chunks_sent(3) et nbd_stats_chunks_received(3) exposent le nombre d'octets et de messages envoyés et reçus sur la connexion actuelle (Eric Blake).

Les nouvelles API nbd_opt_list_meta_context_queries(3) et nbd_aio_opt_list_meta_context_queries(3) vous permettent d'interroger les contextes méta disponibles de manière interactive avec le serveur pendant la phase de négociation du protocole (Eric Blake).

La nouvelle API nbd_set_request_meta_context(3) vous permet de contrôler si le contexte méta est défini pendant la négociation. Cela peut rendre certaines opérations plus rapides, en particulier "nbdinfo --list". (Eric Blake)

Les nouvelles API nbd_opt_set_meta_context(3), nbd_opt_set_meta_context_queries(3), nbd_aio_opt_set_meta_context(3) et nbd_aio_opt_set_meta_context_queries(3) vous permettent de demander des contextes méta lors de l'utilisation de nbd_set_opt_mode(3) (Eric Blake).

Les nouvelles API nbd_opt_structured_reply(3) et nbd_aio_opt_structured_reply(3) vous permettent d'affiner quand les réponses structurées sont demandées pendant la phase de négociation (Eric Blake).

Les nouvelles API nbd_opt_starttls(3) et nbd_aio_opt_starttls(3) vous permettent d'affiner quand STARTTLS est négocié (Eric Blake).

Les nouvelles API nbd_set_socket_activation_name(3) et nbd_get_socket_activation_name(3) vous permettent de nommer le socket utilisé pour l'activation par socket. Certains serveurs tels que qemu-storage-daemon utiliseront ce nom dans la ligne de commande et dans les scripts. (Merci Laszlo Ersek).

Améliorations des API existantes

nbd_connect_command(3) appelé avec un paramètre argv NULL plantait auparavant, mais retourne maintenant une erreur (Eric Blake).

nbd_opt_list_meta_context(3) peut maintenant être appelé sans avoir négocié de réponses structurées (Eric Blake).

nbd_set_strict_mode(3) dispose d'un nouveau drapeau "LIBNBD_STRICT_PAYLOAD" qui peut être utilisé pour contrôler si les messages surdimensionnés sont envoyés, afin de tester les serveurs (Eric Blake).

Les paramètres de pointeur des API C qui ne peuvent pas être NULL sont maintenant annotés avec "attribute((nonnull))" (si le compilateur le prend en charge) afin que vous receviez un avertissement à la compilation s'ils sont utilisés de manière incorrecte (merci Eric Blake).

Les API C qui allouent sont maintenant marquées avec "attribute((malloc))" et des attributions similaires pour améliorer l'analyse statique des programmes utilisant libnbd (Eric Blake).

Les API C exprimant des valeurs de drapeaux utilisent maintenant des types non signés, éliminant certains cas limites indéfinis avec les mathématiques binaires sur les entiers signés. Ce changement est rétrocompatible au niveau de l'API et de l'ABI. (Eric Blake)

Outils

Le nouveau programme nbdublk(1) est utilisé pour créer un périphérique bloc Linux /dev/ublkb<N> à partir d'un serveur NBD (merci Ming Lei).

nbdinfo(1) a maintenant une sortie colorisée (utilisez --no-color pour désactiver).

nbdinfo possède de nouvelles options --is tls et --can structured-reply pour vous permettre de tester ces fonctionnalités sur le serveur (Eric Blake).

nbdcopy(1) écrit maintenant les messages de progression sur stderr (auparavant, ils étaient écrits sur /dev/tty). Cela le rend cohérent avec d'autres outils comme dd. (Eric Blake).

Les options -c et -u de nbdsh(1) peuvent maintenant être entrelacées, ce qui facilite l'activation des fonctionnalités d'URI facultatives (Eric Blake).

Bindings de langage

La documentation des bindings OCaml inclut maintenant les noms des paramètres.

Les bindings OCaml retournent maintenant les valeurs d'erreur OCaml dans des exceptions au lieu des numéros bruts d'errno C.

Les bindings OCaml prennent maintenant en charge nbd_aio_connect(3) qui utilise directement le type sockaddr.

Les bindings Python ont maintenant une méthode explicite "h.close()". Laisser le handle sortir de portée fonctionne toujours pour fermer le handle, mais vous avez maintenant le choix de fermer explicitement le handle avant qu'il ne sorte de portée. Si vous essayez d'utiliser le handle après l'avoir fermé, une nouvelle exception "nbd.ClosedHandle" sera levée.

Les bindings Python fournissent maintenant une fonction décorée par contextlib, vous pouvez donc écrire le code plus naturel "with nbd.nbd() as h: ..."

Tests

Couverture CI plus large (Eric Blake).

Autres améliorations et corrections de bugs

La machine d'état peut maintenant gérer et récupérer de certains messages de réponse structurés incorrects et de cookies inconnus envoyés par le serveur (Eric Blake).

La bibliothèque est maintenant annotée avec "-z nodelete", l'empêchant d'être "vraiment" déchargée lorsque vous appelez dlclose(3). C'est la seule façon d'éviter un crash dans le code multithreadé. Voir le commit 368e3d0d5a887 pour plus de détails.

Amélioration du débogage lorsque le handle entre dans l'état %DEAD.

La bibliothèque est maintenant beaucoup plus conforme à POSIX et plus résiliente lors de l'exécution de sous-commandes, ne s'appuyant plus sur les particularités de l'implémentation glibc de execvp et d'autres fonctions non sûres pour les signaux asynchrones (Laszlo Ersek).

Les fichiers sources ont été reformatés pour utiliser ≤ 80 colonnes (Laszlo Ersek).

Compilation

Correction de la compilation sur Alpine Linux + musl qui déclare "AF_VSOCK" mais ne définit pas les structures associées (Eric Blake).

Distutils de Python, déprécié dans Python ≥ 3.10, a été remplacé par sysconfig (merci Miro Hrončok).
