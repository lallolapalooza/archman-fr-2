DESCRIPTION

Ces fonctions de bibliothèque font partie de Netpbm(1)

TYPES ET CONSTANTES

Chaque pixel contient trois pixvals, chacun ne devant contenir que des valeurs comprises entre 0 et PPM_MAXMAXVAL.

MANIPULATION DES PIXELS

Les macros PPM_GETR, PPM_GETG et PPM_GETB récupèrent respectivement les composantes rouge, verte ou bleue du pixel donné.

La macro PPM_ASSIGN assigne les valeurs données aux composantes rouge, verte et bleue du pixel donné.

La macro PPM_EQUAL teste l'égalité de deux pixels.

La macro PPM_ISGRAY teste si un pixel est gris. Elle retourne vrai si et seulement si la couleur du pixel p est noir, blanc ou gris.

La macro PPM_DEPTH met à l'échelle les couleurs du pixel p en fonction des anciennes et nouvelles valeurs maximales et assigne les nouvelles valeurs à newp. Elle est destinée à faciliter l'écriture de ppmtowhatever.

Les macros PPM_LUMIN, PPM_CHROM_R et PPM_CHROM_B déterminent respectivement la luminance, la chrominance rouge et la chrominance bleue du pixel p. L'échelle de toutes ces valeurs est la même que celle des échantillons d'entrée (c'est-à-dire de 0 à maxval pour la luminance, de -maxval/2 à maxval/2 pour la chrominance).

Notez que les macros effectuent cela par multiplication en virgule flottante. Si vous calculez ces valeurs sur une image entière, il peut être nettement plus rapide de le faire avec des tables de multiplication. Calculez tous les produits possibles une fois au début, puis pour chaque pixel, recherchez simplement les produits dans les tables.

INITIALISATION

ppm_init() est obsolète (au moins depuis Netpbm 9.25 (mars 2002)). Utilisez pm_proginit() à la place.

ppm_init() est identique à pm_proginit.

GESTION DE LA MÉMOIRE

ppm_allocarray() alloue un tableau de pixels.

ppm_allocrow() alloue une ligne du nombre de pixels donné.

ppm_freearray() libère le tableau alloué avec ppm_allocarray() contenant le nombre de lignes donné.

ppm_freerow() libère une ligne de pixels allouée avec ppm_allocrow().

LECTURE DE FICHIERS

Si une fonction de cette section est appelée sur un fichier au format PBM ou PGM, elle traduit le fichier PBM ou PGM en un fichier PPM à la volée et fonctionne comme si elle avait été appelée sur le fichier PPM équivalent. La valeur format retournée par ppm_readppminit() n'est cependant pas traduite. Elle représente le format réel du fichier PBM ou PGM.

ppm_readppminit() lit l'en-tête d'un fichier PPM, retourne toutes les informations de l'en-tête et laisse le fichier positionné juste après l'en-tête.

ppm_readppmrow() lit une ligne de pixels dans le tableau pixelrow. format, cols et maxval sont les valeurs retournées par ppm_readppminit().

ppm_readppm() lit une image PPM entière en mémoire, retourne le tableau alloué comme valeur de retour et retourne les informations de l'en-tête sous forme de rows, cols et maxval. Cette fonction combine ppm_readppminit(), ppm_allocarray() et ppm_readppmrow().

ÉCRITURE DE FICHIERS

ppm_writeppminit() écrit l'en-tête d'un fichier PPM et le laisse positionné juste après l'en-tête.

forceplain est une valeur logique qui

tells ppm_writeppminit() pour écrire un en-tête pour un fichier au format PPM brut, par opposition à un fichier au format PPM brut.

ppm_writeppmrow() écrit la ligne pixelrow dans un fichier PPM. Pour des résultats significatifs, cols, maxval et forceplain doivent être les mêmes que ceux utilisés avec ppm_writeppminit().

ppm_writeppm() écrit l'en-tête et toutes les données d'une image PPM. Cette fonction combine ppm_writeppminit() et ppm_writeppmrow().

DIVERS

ppm_nextimage() positionne un fichier d'entrée PPM à la prochaine image (de sorte qu'un appel ultérieur à ppm_readppminit() lise son en-tête).

ppm_nextimage() est analogue à pbm_nextimage(), mais fonctionne sur les fichiers PPM, PGM et PBM.

ppm_check() vérifie l'erreur courante d'intégrité de fichier où la taille du fichier est incorrecte pour contenir toutes les données de l'image.

ppm_check() est analogue à pbm_check(), mais fonctionne sur les fichiers PPM, PGM et PBM.

COULEUR

Luminance, Chrominance (YcbCr)


    float PPM_LUMIN(pixel p);
    float PPM_CHROM_B(pixel p);
    float PPM_CHROM_R(pixel p);

PPM_LUMIN prend un pixel comme argument et retourne la luminance de ce pixel, avec le même maxval que le pixel (par exemple, si le maxval du pixel est 255, une valeur PPM_LUMIN de 255 signifie une luminance complète).

PPM_CHROM_B et PPM_CHROM_R sont similaires, pour les valeurs de chrominance rouge et bleue.


    pixel
    ppm_color_from_ycbcr(unsigned int y, 
                         int          cb, 
                         int          cr);

ppm_color_from_ycbcr() convertit dans l'autre sens. Étant donné la luminance et la chrominance, elle retourne une valeur de pixel.

Teinte, Saturation, Valeur (TSV)


    struct hsv {
        double h;  /* teinte (degrés)  0..360 */
        double s;  /* saturation (0-1) */
        double v;  /* valeur (0-1) */
    };


    pixel
    ppm_color_from_hsv(struct hsv const hsv,
                       pixval     const maxval);


    struct hsv
    ppm_hsv_from_color(pixel  const color,
                       pixval const maxval);

Ceux-ci convertissent une couleur entre la forme pixel (RVB) et TSV.


    pixval
    ppm_saturation(pixel  const p,
                   pixval const maxval);

Ceci vous donne la saturation d'une couleur, sous forme de pixval. (par exemple, si la saturation de p est de 50% et maxval est de 100, ppm_saturation() retourne 50).

Couleur Berlin-Kay

Brent Berlin et Paul Kay ont mené en 1969 une étude qui a identifié un ensemble de 11 couleurs de base que les gens reconnaissent universellement. Ce sont :

  • noir
  • gris
  • blanc
  • rouge
  • orange
  • jaune
  • vert
  • bleu
  • violet
  • pourpre
  • brun

Le type bk_color représente une couleur de cet ensemble :


    typedef enum {
        BKCOLOR_BLACK = 0,
        BKCOLOR_GRAY,
        BKCOLOR_WHITE,
        BKCOLOR_RED,
        BKCOLOR_ORANGE,
        BKCOLOR_YELLOW,
        BKCOLOR_GREEN,
        BKCOLOR_BLUE,
        BKCOLOR_VIOLET,
        BKCOLOR_PURPLE,
        BKCOLOR_BROWN
    } bk_color;

Vous pouvez l'utiliser comme index d'un tableau, auquel cas vous pourriez également vouloir la macro BKCOLOR_COUNT, qui est le nombre de couleurs dans l'ensemble (11).

Pour traduire entre le type bk_color et les noms anglais des couleurs, utilisez ppm_bk_color_from_name() et ppm_name_from_bk_color() :


    bk_color
    ppm_bk_color_from_name(const char * name);
    
    const char *
    ppm_name_from_bk_color(bk_color bkColor);

ppm_bk_color_from_color() vous indique à quelle couleur Berlin-Kay une couleur donnée est la plus proche, au moyen d'un algorithme de correspondance de couleurs floues :


    bk_color
    ppm_bk_color_from_color(pixel  color,
                            pixval maxval);

maxval est le maxval sur lequel color est basé.

ppm_color_from_bk_color() convertit dans l'autre sens : étant donnée une couleur Berlin-Kay, elle donne la couleur, sous forme de pixel, qui la représente le mieux.


    pixel
    ppm_color_from_bk_color(bk_color bkColor,
                            pixval   maxval);

maxval est le maxval sur lequel la couleur retournée est basée.

Toutes les facilités de cette section sont nouvelles dans Netpbm 10.34 (juin 2006).

NOMS DE COULEURS

Dictionnaire des couleurs système

Netpbm utilise le dictionnaire de couleurs X11 du système (généralement dans /usr/lib/X11/rgb.txt). C'est le même fichier que le système X Window utilise généralement pour associer des couleurs à leurs noms.

Le dictionnaire de couleurs utilisé par Netpbm se trouve dans le fichier dont le nom est la valeur de la variable d'environnement RGBDEF. Si RGBDEF n'est pas définie, Netpbm utilise par défaut le premier fichier existant de cette liste :

  • /usr/lib/X11/rgb.txt
  • /usr/openwinlib/rgb.txt
  • /usr/X11R6/lib/X11/rgb.txt

Vous pouvez voir les noms de couleurs d'un dictionnaire de couleurs X11 typique, qui est probablement très proche de ce qui se trouve sur votre système, avec les couleurs, ici . Ce site web (1)
montre un tas d'autres versions que vous pourriez utiliser.

Netpbm est fourni avec un dictionnaire de couleurs. Une installation standard de Netpbm installe ce fichier sous le nom "misc/rgb.txt" dans le répertoire Netpbm. Ce dictionnaire de couleurs contient des couleurs provenant de partout où le mainteneur de Netpbm a pu les trouver, et est un sur-ensemble du dictionnaire de couleurs de XFree 86.

ppm_parsecolor

ppm_parsecolor() interprète une spécification de couleur et retourne un pixel de la couleur qu'elle indique. La spécification de couleur est du texte ASCII, dans l'un des formats suivants :

  • un nom, tel que défini dans le dictionnaire de couleurs système .

  • Un spécificateur hexadécimal de style X11 : rgb:r/g/b, où r, g et b sont chacun des nombres hexadécimaux de 1 à 4 chiffres. Pour chacun, le maxval est le nombre maximum qui peut être représenté par le nombre de chiffres hexadécimaux donnés. Exemple : rgb:01/ff/8000 spécifie 1/255 d'intensité rouge , une intensité verte maximale et environ la moitié d'intensité bleue.

  • Un spécificateur décimal de style X11 : rgbi:r/g/b, où r, g et b sont des nombres à virgule flottante de 0 à 1.
  • un triplet hexadécimal de style ancien X11 : #rgb, #rrggbb, #rrrgggbbb, ou #rrrrggggbbbb.
  • Un triplet de nombres décimaux à virgule flottante de 0.0 à 1.0, représentant respectivement les intensités rouge, verte et bleue, séparés par des virgules. Par exemple, 1.0,0.5,.25. Ceci est pour la compatibilité descendante ; il était utilisé avant que MIT ne propose le style rgbi similaire et préféré).

Si la spécification de couleur n'est conforme à aucun de ces formats, y compris le cas où il s'agit d'un nom, mais qu'il n'est pas dans le dictionnaire de couleurs du système, ppm_parsecolor() lève une erreur(1)

ppm_colorname

ppm_colorname() retourne une chaîne décrivant la couleur du pixel donné. Si un dictionnaire de couleurs système est disponible et que la couleur y figure, ppm_colorname() retourne le nom de la couleur du fichier. Si la couleur n'apparaît pas dans un dictionnaire de couleurs système et que hexok est vrai, ppm_colorname() retourne une spécification de couleur hexadécimale triplet (#rrggbb). Si un dictionnaire de couleurs système est disponible mais que la couleur n'y apparaît pas et que hexok est faux, ppm_colorname() retourne le nom de la couleur correspondante la plus proche dans le fichier de couleurs. Enfin, s'il n'y a pas de dictionnaire de couleurs système disponible et que hexok est faux, ppm_colorname() échoue et lève une erreur .

La chaîne retournée se trouve dans le stockage statique de la bibliothèque libppm, qui est écrasé à chaque appel à ppm_colorname().

ppm_readcolornamefile

ppm_readcolornamefile() lit tout le contenu du dictionnaire de couleurs du fichier nommé fileName dans des structures de données que vous pouvez utiliser pour y accéder facilement.

La fonction retourne tous les noms de couleurs sous forme d'un tableau de chaînes terminées par null. Elle alloue de la mémoire pour ce tableau et retourne son adresse à colornamesP. (*colornamesP)[i] est l'adresse du premier caractère de la chaîne terminée par null qui est le nom de la ième couleur du dictionnaire.

La fonction retourne également une colorhash_table (voir INDEX DE COULEURS ) qui correspond à tous les these noms de couleurs jusqu'aux couleurs qu'ils représentent. Il alloue de l'espace pour le colorhash_table et retourne son adresse à chtP. Le nombre que le colorhash_table associe à chaque couleur est l'index du tableau de noms de couleurs décrit ci-dessus, du nom de cette couleur.

Vous pouvez spécifier un pointeur nul pour fileName afin d'indiquer le dictionnaire de couleurs par défaut.

mustOpen est une valeur booléenne. S'il est non nul, la fonction échoue et interrompt le programme s'il ne parvient pas à ouvrir le fichier de dictionnaire de couleurs spécifié. S'il est nul, cependant, il traite simplement un dictionnaire de couleurs non ouvrable comme un dictionnaire vide. Le hash de couleur et le tableau de noms de couleurs qu'il retourne ne contiennent aucune couleur ni aucun nom.

ppm_readcolornamefile() a été introduit dans Netpbm 10.15 (avril 2003).

INDEXATION DES COULEURS

Parfois, lors du traitement d'images, vous souhaitez associer une valeur à une couleur particulière. Le plus souvent, c'est parce que vous générez un format graphique mappé par couleur. Dans un format graphique mappé par couleur, le raster contient de petits nombres, et le fichier contient une table de couleurs qui indique à quelle couleur chacun de ces petits nombres se réfère. Si votre image n'a que 256 couleurs, mais que chaque couleur prend 24 bits pour être décrite, cela peut rendre votre fichier de sortie beaucoup plus petit qu'un raster RVB simple.

Donc, en continuant l'exemple ci-dessus, disons que vous avez une valeur de pixel pour le chartreuse et que dans votre fichier de sortie, vous allez représenter le chartreuse par le nombre 12. Vous avez besoin d'une structure de données qui permette à votre programme de trouver rapidement que le nombre pour un pixel chartreuse est 12. Les types de données et les fonctions d'indexation de couleurs de Netpbm vous donnent cela.

colorhash_table est un type de données C qui associe un entier à chaque couleur d'un nombre arbitraire de couleurs. C'est une table de hachage, donc elle utilise beaucoup moins d'espace qu'un tableau indexé par les valeurs RVB de la couleur.

Le problème avec une colorhash_table est que vous ne pouvez y effectuer que des recherches. Vous ne pouvez pas savoir quelles couleurs s'y trouvent. Netpbm a donc un autre type de données pour représenter les mêmes informations, le type colorhist_vector, mal nommé mais historiquement. Un colorhist_vector est juste un tableau. Chaque entrée représente une couleur et contient la valeur de la couleur (en tant que pixel) et la valeur entière qui lui est associée. Les entrées sont remplies en commençant par l'indice 0 et en continuant consécutivement pour le nombre de couleurs dans l'histogramme.

(La raison pour laquelle le nom est mauvais est qu'un histogramme de couleurs n'est qu'une des nombreuses choses qui pourraient être représentées par lui).

colorhash_table ppm_alloccolorhash()

Cela crée une colorhash_table à l'aide d'un espace alloué dynamiquement. Il n'y a aucune couleur dedans. S'il n'y a pas assez d'espace, lève une erreur.

void ppm_freecolorhash()

Cela détruit une ppm_freecolorhash et libère tout l'espace qui lui est associé.

int ppm_addtocolorhash( colorhash_table cht, const pixel * const colorP, const int value)

Cela ajoute la couleur spécifiée à la colorhash_table spécifiée et lui associe la valeur spécifiée.

Vous devez vous assurer que la couleur que vous ajoutez n'est pas déjà présente dans la colorhash_table.

Il n'y a aucun moyen de mettre à jour une entrée ou de supprimer une entrée d'une colorhash_table.

int ppm_lookupcolor( const colorhash_table cht, const pixel * const colorP )

Cela recherche la couleur spécifiée dans la colorhash_table spécifiée. Elle retourne la valeur entière associée à cette couleur.

Si la couleur spécifiée n'est pas dans la table de hachage, la fonction retourne -1. (Donc, si vous attribuez la valeur -1 à une couleur, la valeur de retour est ambiguë).

colorhist_vector ppm_colorhashtocolorhist( const colorhash_table cht,

const int ncolors )

Cela convertit une colorhash_table en un colorhist_vector. La valeur de retour est un nouveau colorhist_vector que vous devrez éventuellement libérer avec ppm_freecolorhist().

ncolors est le nombre de couleurs dans cht. S'il contient plus de couleurs que cela, ppm_colorhashtocolorhist ne crée pas de colorhist_vector et retourne NULL.

colorhash_table ppm_colorhisttocolorhash( const colorhist_vector chv, const int ncolors )

Cette fonction mal nommée ne convertit *pas* d'un colorhist_vector vers un colorhash_table.

Elle crée une colorhash_table basée sur une entrée colorhist_vector, mais la valeur entière pour une couleur donnée dans la sortie n'est pas la même que la valeur entière pour cette même couleur dans l'entrée. ppm_colorhisttocolorhash() ignore les valeurs entières de l'entrée. Dans la sortie, la valeur entière d'une couleur est l'index dans le colorhist_vector d'entrée pour cette couleur.

Vous pouvez facilement créer une table de couleurs pour une image en exécutant ppm_computecolorhist() sur l'image, puis ppm_colorhisttocolorhash() sur le résultat. Vous pouvez maintenant utiliser ppm_lookupcolor() pour trouver un index de couleur unique pour n'importe quel pixel de l'entrée.

Si la même couleur apparaît deux fois dans l'entrée, ppm_colorhisttocolorhash() lève une erreur.

ncolors est le nombre de couleurs dans chv.

La valeur de retour est une nouvelle colorhash_table que vous devrez éventuellement libérer avec ppm_freecolorhash().

HISTOGRAMMES DES COULEURS

Les bibliothèques Netpbm vous donnent des fonctions pour examiner une image Netpbm et déterminer quelles couleurs s'y trouvent et combien de pixels de chaque couleur s'y trouvent. Cette information est connue sous le nom d'histogramme des couleurs. Netpbm utilise son type de données colorhash_table pour représenter un histogramme des couleurs.

colorhash_table ppm_computecolorhash( pixel ** const pixels, const int cols, const int rows, const int maxcolors, int* const colorsP )

Cette fonction mal nommée mais historiquement nommée génère une colorhash_table dont la valeur pour chaque couleur est le nombre de pixels d'une image spécifiée qui ont cette couleur. (C'est-à-dire un histogramme des couleurs). En bonus, elle retourne le nombre de couleurs dans l'image.

(Elle est mal nommée car toutes les colorhash_table ne sont pas des histogrammes de couleurs, mais c'est tout ce qu'elle génère).

pixels, cols et rows décrivent l'image d'entrée.

maxcolors est le nombre maximum de couleurs que vous souhaitez traiter. S'il y a plus de couleurs que cela dans l'image d'entrée, ppm_computecolorhash() retourne NULL comme valeur de retour et arrête le traitement dès qu'elle le découvre. Cela la rend plus rapide et utilise moins de mémoire. Une utilisation pour maxcolors est lorsque vous voulez juste savoir si l'image a plus de N couleurs et que vous ne voulez pas attendre de générer une table de couleurs énorme si c'est le cas. Si vous ne voulez aucune limite sur le nombre de couleurs, spécifiez maxcolors=0.

ppm_computecolorhash() retourne le nombre réel de couleurs dans l'image sous forme de *colorsP, mais seulement si c'est inférieur ou égal à maxcolors.

colorhash_table ppm_computecolorhash2( FILE * const ifp, const int cols, const int rows, const pixval maxval, const int format,

const int maxcolors, int* const colorsP )

Ceci est identique à ppm_computecolorhash() sauf qu'au lieu de lui fournir un tableau de pixels en mémoire, vous lui donnez un flux de fichier ouvert et il lit l'image du fichier. Le fichier doit être positionné après l'en-tête, au niveau du raster. Au retour, le fichier est toujours ouvert, mais sa position est indéfinie.

maxval et format sont les valeurs pour l'image (c'est-à-dire des informations de l'en-tête du fichier).

colorhist_vector ppm_computecolorhist( pixel ** pixels, int cols, int rows, int maxcolors, int * colorsP )

Ceci est similaire à ppm_computecolorhash() sauf qu'il crée un colorhist_vector au lieu d'une colorhash_table.

Si vous fournissez un argument maxcolors non nul, c'est le nombre maximum de couleurs que vous vous attendez à trouver dans l'image d'entrée. S'il y a plus de couleurs que vous ne l'indiquez dans l'image, ppm_computecolorhist() retourne un pointeur nul comme valeur de retour et rien de significatif pour *colorsP.

Sinon, la fonction retourne le nouveau colorhist_vector comme valeur de retour et le nombre réel de couleurs dans l'image comme *colorsP. Le tableau retourné a de l'espace alloué pour le nombre spécifié de couleurs, quel que soit le nombre réel. L'espace supplémentaire se trouve à la fin du tableau et est disponible pour votre utilisation dans l'extension du colorhist_vector.

Si vous spécifiez maxcolors=0, il n'y a aucune limite au nombre de couleurs retournées et le tableau de retour a de l'espace pour 5 couleurs supplémentaires à la fin pour votre utilisation dans l'extension du colorhist_vector.

colorhist_vector ppm_computecolorhist2( FILE * ifp, int cols, int rows, int maxcolors, pixval maxval, int format, int * colorsP )

Ceci est identique à ppm_computecolorhist() sauf qu'au lieu de lui fournir un tableau de pixels en mémoire, vous lui donnez un flux de fichier ouvert et il lit l'image du fichier. Le fichier doit être positionné après l'en-tête, au niveau du raster. Au retour, le fichier est toujours ouvert, mais sa position est indéfinie.
