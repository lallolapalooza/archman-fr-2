DESCRIPTION

The LibCPUID library provides functions for CPU identification.

  • cpu_get_cpu_list (cpu_vendor_t vendor, struct cpu_list_t *list)

    Obtient une liste de tous les noms de CPU connus d'un fournisseur spécifique.

  • void cpuid_free_cpu_list (struct cpu_list_t *list)

    Libère une liste de CPU.

  • void cpuid_free_raw_data_array (struct cpu_raw_data_array_t *raw_array)

    Libère un tableau brut.

  • void cpuid_free_system_id (struct system_id_t *system)

    Libère un type d'ID système.

  • struct msr_driver_t * cpu_msr_driver_open (void)

    Démarre/ouvre un pilote, nécessaire pour lire les MSR (registres spécifiques au modèle).

  • struct msr_driver_t * cpu_msr_driver_open_core (unsigned core_num)

    Similaire à cpu_msr_driver_open, mais accepte un paramètre.

  • int cpu_rdmsr (struct msr_driver_t *handle, uint32_t msr_index, uint64_t *result)

    Lit un registre spécifique au modèle (MSR).

  • int cpu_rdmsr_range (struct msr_driver_t *handle, uint32_t msr_index, uint8_t highbit, uint8_t lowbit, uint64_t *result)

    Similaire à cpu_rdmsr, mais extrait une plage de bits.

  • int cpu_msrinfo (struct msr_driver_t *handle, cpu_msrinfo_request_t which)

    Lit des informations CPU étendues à partir des registres spécifiques au modèle.

  • int msr_serialize_raw_data (struct msr_driver_t *handle, const char *filename)

    Écrit les données MSR brutes dans un fichier texte.

  • int cpu_msr_driver_close (struct msr_driver_t *handle)

    Ferme un pilote MSR ouvert.

Detailed Description

LibCPUID fournit l'identification du CPU.

int cpu_clock (void )

Obtient la fréquence d'horloge du CPU (méthode tout-en-un). C'est une méthode tout-en-un pour obtenir la fréquence d'horloge du CPU. Elle essaie d'utiliser l'OS pour cela. Si l'OS n'a pas cette information, elle utilise cpu_clock_measure avec un intervalle de temps de 200 ms et une quadruple vérification.

Retourne

la fréquence d'horloge du CPU en MHz. Si toutes les méthodes possibles échouent, le résultat est -1.

int cpu_clock_by_ic (int millis, int runs)

Mesure la fréquence d'horloge du CPU en utilisant le comptage d'instructions.

Paramètres

millis - combien de temps allouer pour chaque exécution, en millisecondes.
runs - combien d'exécutions effectuer.

La fonction effectue un cycle d'attente active ("busy-wait") en utilisant un nombre connu d'instructions "lourdes" (SSE). Ces instructions s'exécutent à un taux IPC d'environ 1 (garanti), donc en exécutant une boucle active pendant une durée fixe et en mesurant le nombre d'instructions exécutées, l'horloge du CPU est mesurée avec précision.

Bien sûr, cette fonction est toujours affectée par les schémas d'économie d'énergie, donc les avertissements de cpu_clock_measure() s'appliquent toujours. Cependant, cette fonction est insensible aux problèmes de détection liés au mode "Turbo" des processeurs Intel Nehalem, où l'horloge interne est augmentée, mais le taux RDTSC n'est pas affecté.

La fonction s'exécutera pendant environ (millis * runs) millisecondes. Vous pouvez effectuer une seule exécution en attente active (runs == 1); cependant, cela peut être affecté par la planification des tâches (qui interrompra le comptage), il est donc recommandé d'autoriser plusieurs exécutions. Comme la durée d'exécution n'est pas impérative pour des lectures précises (par exemple, 50 ms suffisent), vous pouvez vous permettre de nombreuses courtes exécutions, par exemple 10 exécutions de 50 ms ou 20 exécutions de 25 ms.

Valeurs recommandées - millis = 50, runs = 4. Pour plus de robustesse, augmentez le nombre d'exécutions.

REMARQUE : sur les processeurs Bulldozer et ultérieurs, le cycle d'attente active s'exécute à 1,4 IPC, les résultats sont donc faussés. Ceci est corrigé en interne en divisant la valeur résultante par 1,4. Cependant, cela ne se produit que si le thread est exécuté sur un seul module CMT - s'il y a d'autres threads en compétition pour les ressources, les résultats sont imprévisibles. Assurez-vous d'exécuter cpu_clock_by_ic() sur un CPU libre de threads concurrents, ou s'il y a de tels threads, ils ne doivent pas dépasser le nombre de modules. Sur un Bulldozer X8, cela signifie 4 threads.

Retourne

la fréquence d'horloge du CPU en MHz (avec une certaine marge d'erreur de mesure). Si SSE n'est pas pris en charge, le résultat est -1. Si les paramètres d'entrée sont incorrects, ou si une autre faute interne est détectée, le résultat est -2.

int cpu_clock_by_os (void )

Retourne la fréquence d'horloge du CPU, telle que rapportée par l'OS. Cette fonction utilise des fonctions spécifiques à l'OS pour obtenir la fréquence d'horloge du CPU. Elle peut différer de la fréquence réelle pour plusieurs raisons :

i) Le CPU pourrait être dans un état d'économie d'énergie, tandis que l'OS rapporte sa fréquence à pleine puissance, ou vice versa.
ii) Dans certains cas, vous pouvez augmenter ou diminuer la fréquence du CPU avec des utilitaires d'overclocking et l'OS ne s'en rendra pas compte.

Retourne

la fréquence d'horloge du CPU en MHz. Si l'OS n'est pas (encore) pris en charge ou ne dispose pas des mécanismes de rapport nécessaires, la valeur retournée est -1.

int cpu_clock_by_tsc (struct cpu_raw_data_t * raw)

Mesure la fréquence d'horloge du CPU en utilisant la fréquence TSC de CPUID.

Paramètres

raw - Entrée optionnelle - un pointeur vers les données brutes de CPUID, qui sont obtenues soit par cpuid_get_raw_data, soit par cpuid_deserialize_raw_data. Peut également être NULL, dans ce cas, la fonction appelle elle-même cpuid_get_raw_data.

La fonction lit le compteur d'horodatage (Time Stamp Counter) et la feuille d'informations sur l'horloge cristal nominale du cœur depuis CPUID. Elle détermine la fréquence de base du processeur.

REMARQUE : seuls les CPU Intel x86 depuis Skylake (6ème génération de processeurs Intel Core) sont pris en charge. Les autres vendeurs ne prennent pas en charge cette fonctionnalité.

int cpu_clock_measure (int millis, int quad_check)

Mesure la fréquence d'horloge du CPU en utilisant le compteur d'horodatage (TSC).

Paramètres

millis - combien de temps pour la mesure, en millisecondes. Minimum 1 ms.
quad_check - si vrai, quatre mesures consécutives seront effectuées. Si elles diffèrent de plus de 10%, une erreur sera retournée.

Utilise la fonction rdtsc() pour obtenir le temps écoulé. Le problème est que cette valeur est affectée par les schémas d'économie d'énergie du CPU. Par exemple, si le CPU entre dans un état d'économie d'énergie pendant la mesure, le résultat sera beaucoup plus bas que la fréquence réelle. Pour contourner ce problème, la fonction effectue plusieurs mesures et s'assure qu'elles ne diffèrent pas trop les unes des autres. Si c'est le cas, la fonction suppose que le CPU n'est pas entré dans un état d'économie d'énergie, et retourne la fréquence calculée. Sinon, elle retourne une valeur négative.

Retourne

la fréquence d'horloge du CPU en MHz. Si la mesure échoue (par exemple, si le CPU passe en mode d'économie d'énergie pendant la mesure), la fonction retourne une valeur négative. En particulier, -1 si le CPU est trop lent pour que la mesure soit exacte, et -2 si l'une des quatre mesures échoue consécutivement (indiquant un passage en mode d'économie d'énergie).

int cpu_clock_measure (int millis, int quad_check)

Mesure la fréquence de l'horloge CPU.

Paramètres

millis - Temps à attendre dans le cycle de boucle bloquante. En millisecondes. Valeurs utiles 10 - 1000
quad_check - Effectue une mesure plus approfondie si non nul (voir l'explication).

La fonction effectue un cycle de boucle bloquante pendant le temps spécifié et calcule la fréquence du CPU par la différence des valeurs TSC. La précision du calcul dépend de la durée du cycle de boucle bloquante : plus c'est long, mieux c'est, mais 100 ms devraient suffire pour la plupart des usages.

Bien que cela calcule correctement la fréquence du CPU dans la plupart des cas, il existe plusieurs raisons pour lesquelles cela pourrait être incorrect :

i) RDTSC ne garantit pas qu'il s'exécutera à la même fréquence que le CPU. Apparemment, il n'y a pas de CPUs pour le moment, mais quand même, il n'y a aucune garantie.
ii) Le CPU pourrait être en mode d'économie d'énergie basse fréquence, et le CPU pourrait être commuté à une fréquence plus élevée à tout moment. Si cela se produit pendant la mesure, le résultat peut se situer n'importe où entre les fréquences basse et haute. De plus, si vous n'êtes intéressé que par la valeur de haute fréquence, cette fonction pourrait renvoyer la valeur basse à la place.
iii) Sur les systèmes SMP présentant une dérive de TSC (voir cpu_rdtsc)

l'option quad_check effectuera quatre mesures consécutives, puis renverra la moyenne des deux résultats les plus cohérents. La durée totale d'exécution de la fonction sera toujours de `millis' - envisagez d'utiliser un peu plus de temps pour l'intervalle de temporisation.

Enfin, pour les applications de benchmarking / intensives en CPU, la meilleure stratégie est d'utiliser la méthode cpu_tsc_mark() / cpu_tsc_unmark() / cpu_clock_by_mark(). Commencez par marquer environ une seconde après le démarrage de l'application (permettant au gestionnaire d'économie d'énergie de s'activer et d'augmenter la fréquence pendant ce temps), puis dé-marquez juste avant la fin de l'application. Le résultat représentera le plus fidèlement la fréquence à laquelle votre application fonctionnait.

Retourne

la fréquence de l'horloge CPU en MHz (avec une certaine marge d'erreur de mesure). Si RDTSC n'est pas pris en charge, le résultat est -1.

int cpuid_get_total_cpus (void )

Retourne le nombre total de threads logiques de CPU (même si CPUID est absent). Sous VM, ce nombre (et total_logical_cpus, car ils sont récupérés avec le même code) peut être absurde, c'est-à-dire qu'il peut ne pas égaler NumPhysicalCPUs*NumCoresPerCPU*HyperThreading. En effet, quel que soit le nombre de threads logiques de la machine hôte, vous pouvez les limiter dans la VM à n'importe quel nombre souhaité. C'est le nombre retourné par cpuid_get_total_cpus().

Nombre de threads logiques de CPU disponibles. Égale à cpu_id_t::total_logical_cpus.
