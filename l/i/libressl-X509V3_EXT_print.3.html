X509V3_EXT_PRINT(3) Manuel des fonctions de bibliothèque X509V3_EXT_PRINT(3)

NOM

X509V3_EXT_print, X509V3_EXT_print_fp — imprimer joliment une extension X.509

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/x509v3.h>

int
X509V3_EXT_print(BIO *bio, X509_EXTENSION *ext, unsigned long flags, int indent);

int
X509V3_EXT_print_fp(FILE *file, X509_EXTENSION *ext, int flags, int indent);

DESCRIPTION

X509V3_EXT_print() et X509V3_EXT_print_fp() décodent ext et impriment les données qu'il contient à bio ou file, respectivement, dans un format lisible par l'homme avec une marge gauche de indent caractères d'espacement. Les détails du décodage et de l'impression dépendent du type de ext.

Pour la plupart des types d'extensions, le décodage est effectué de la même manière que ce serait fait par la fonction API publique appropriée, par exemple :

Certaines fonctions d'impression publiques ne sont pas encore documentées.

Si ext est d'un type d'extension inconnu ou si le décodage échoue lors de l'utilisation de la fonction de décodage pour le type pertinent, l'action entreprise dépend de l'argument flags :

  • Si le bit X509V3_EXT_PARSE_UNKNOWN est défini, ASN1_parse_dump(3) est appelé sur les données encodées en BER de l'extension, en passant -1 pour l'argument dump. Ainsi, certaines informations sur l'encodage de l'extension sont imprimées et certaines sur son contenu décodé, en revenant à BIO_dump_indent(3) pour le contenu décodé, sauf s'il existe une méthode d'impression dédiée connue pour les types de données respectifs. Notez que même si un type d'extension est inconnu, le type de données utilisé par l'extension inconnue, ou, si ce type de données est construit, des valeurs qu'il contient, peuvent être connus, ce qui peut permettre d'imprimer le contenu même d'une extension inconnue sous une forme structurée ou partiellement structurée.
  • Si le bit X509V3_EXT_DUMP_UNKNOWN est défini, BIO_dump_indent(3) est appelé sur les données encodées en BER de l'extension sans la décoder au préalable, ce qui est généralement moins lisible que ce qui précède mais présente un risque moindre d'omettre ou de représenter mal des parties des informations.
  • Si le bit X509V3_EXT_ERROR_UNKNOWN est défini, seule la chaîne fixe "<Non pris en charge>" est imprimée pour un type inconnu ou seulement la chaîne fixe "<Erreur d'analyse>" si les fonctions d'analyse échouent, mais l'impression est considérée comme réussie de toute façon.
  • Si plusieurs de ces trois bits sont définis, ou si un bit dans X509V3_EXT_UNKNOWN_MASK est défini et non listé ci-dessus, rien n'est imprimé, mais l'impression est considérée comme réussie de toute façon.
  • Si aucun des bits de X509V3_EXT_UNKNOWN_MASK n'est défini (c'est-à-dire, si flags est égal à 0), et que l'extension est d'un type inconnu ou que le décodage échoue, l'impression échoue et la fonction renvoie 0.

L'argument flags peut aussi contenir des bits spécifiés dans X509V3_add_standard_extensions(3). Si de tels bits sont présents, ils sont transmis aux fonctions d'impression spécifiques aux extensions.

L'argument indent spécifie le niveau d'indentation de sortie. Il est utilisé par les fonctions d'impression afin de mettre en forme la sortie de manière hiérarchique.

Pour des raisons de compatibilité, X509V3_EXT_print_fp() est un alias pour l'ancien X509V3_EXT_print() qui utilisait un pointeur FILE* au lieu d'un BIO*. L'utilisation de X509V3_EXT_print() est cependant recommandée.

VALEUR DE RETOUR

Les fonctions X509V3_EXT_print() et X509V3_EXT_print_fp() renvoient 1 en cas de succès, et 0 en cas d'échec.

EXEMPLES

L'exemple suivant montre comment imprimer une extension à partir d'un certificat X509.

#include <openssl/x509.h>
#include <openssl/bio.h>
#include <openssl/err.h>
int main() {
X509 *cert;
BIO *bio_err;
int ext_count, i;
cert = X509_parse_file("cert.pem");
if (cert == NULL) {
ERR_print_errors_fp(stderr);
return(1);
}
bio_err = BIO_new_fp(stderr, BIO_NOCLOSE);
ext_count = sk_X509_EXTENSION_num(cert->cert_info->extensions);
for (i = 0; i < ext_count; i++) {
X509_EXTENSION *ext;
ext = sk_X509_EXTENSION_value(cert->cert_info->extensions, i);
X509V3_EXT_print(bio_err, ext, 0, 4);
}
X509_free(cert);
BIO_free(bio_err);
return(0);
}

libressl(3) — X509V3_EXT_print

NAME

X509V3_EXT_print, X509V3_EXT_print_fp - print an X509 V3 extension

SYNOPSIS

#include <openssl/x509v3.h>

int X509V3_EXT_print(BIO *out, X509_EXTENSION *ext, unsigned int flag);
int X509V3_EXT_print_fp(FILE *fp, X509_EXTENSION *ext, unsigned int flag);

DESCRIPTION

The function X509V3_EXT_print() prints the extension ext to the BIO out. The function X509V3_EXT_print_fp() prints the extension ext to the FILE pointer fp.

The flag argument controls the output format. The following flags are supported:

X509V3_EXT_PRINT_HOME
Prints the extension in a more compact form, suitable for use in command-line tools.
X509V3_EXT_PRINT_ENABLE_DOTALL
Enables the "dotall" flag for printing.
X509V3_EXT_PRINT_NO_HEADER
Suppresses the printing of the extension header.
X509V3_EXT_PRINT_NO_EXTENSIONS
Suppresses the printing of extensions.
X509V3_EXT_UNKNOWN_MASK
If this mask is set in flag, unknown extensions are printed in a generic format. If X509V3_EXT_UNKNOWN_MASK is not set, unknown extensions are ignored and nothing is printed. If the X509V3_EXT_UNKNOWN_MASK is set, but the extension is still unknown, nothing is printed and printing is considered as failed.

RETURN VALUES

X509V3_EXT_print() and X509V3_EXT_print_fp() return 0 if failure was both detected and considered relevant. Otherwise, 1 is returned, and in general the user cannot tell whether failure simply went undetected, whether the function detected failure but regarded it as irrelevant, or whether printing did indeed succeed.

SEE ALSO

BIO_new(3), X509_EXTENSION_new(3), X509_get0_extensions(3), X509_get_ext(3), X509V3_extensions_print(3)

HISTORY

These functions first appeared in OpenSSL 0.9.2 and have been available since OpenBSD 2.6.

BUGS

These functions lack error handling throughout. When a write operation fails, they will usually ignore the fact that information was omitted from the output and report success to the caller anyway.
