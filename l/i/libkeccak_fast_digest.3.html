libkeccak_fast_digest(3)

Paquet: libkeccak

Licences: custom:ISC

LIBKECCAK_FAST_DIGEST(3) Manuel des fonctions de bibliothèque LIBKECCAK_FAST_DIGEST(3)

NOM

libkeccak_fast_digest - Finalise le hachage d'un message sans effacement

SYNOPSIS

#include <libkeccak.h>
int libkeccak_fast_digest(struct libkeccak_state *state, const void *msg, size_t msglen,
                          size_t bits, const char *suffix, void *hashsum);

Lier avec -lkeccak.

DESCRIPTION

La fonction libkeccak_fast_digest() absorbe la dernière partie d'un message (ou la totalité) et retourne le hachage du message entier. La dernière partie du message est spécifiée par le paramètre msg, et sa taille en octets est spécifiée par le paramètre msglen. Si tout le message a déjà été traité par des appels aux fonctions libkeccak_update(3), libkeccak_fast_update(3), ou libkeccak_zerocopy_update(3) (avec le même pointeur sur state), msg et msglen doivent être définis à NULL et 0, respectivement.

Si le message n'est pas composé d'un nombre entier d'octets, le nombre de bits, modulo 8, dans le message doit être spécifié dans le paramètre bits. msglen ne doit compter que le nombre d'octets entiers, c'est-à-dire le plancher du nombre de bits dans le message divisé par 8.

suffix doit être une chaîne terminée par NUL de '1' et '0' ASCII, représentant les bits qui doivent être ajoutés au message. Si cette chaîne est vide, NULL peut être utilisé à la place. Ceci est utilisé pour sélectionner l'algorithme de hachage. Pour Keccak pur, NULL ou "" est utilisé. Pour les autres algorithmes, les constantes LIBKECCAK_SHA3_SUFFIX (pour SHA-3), LIBKECCAK_RAWSHAKE_SUFFIX (pour RawSHAKE), et LIBKECCAK_SHAKE_SUFFIX (pour SHAKE), ou le retour de la fonction libkeccak_cshake_suffix(3) (pour cSHAKE), sont utilisés.

Le hachage du message sera stocké dans hashsum, sauf si hashsum est NULL (ce qui augmente les performances de l'appel.) Un total de ((state->n + 7) / 8) octets sera écrit au début de hashsum. Par conséquent, hashsum doit avoir au moins une allocation de cette taille en octets.

La fonction libkeccak_fast_digest() peut réallouer le tampon de message de l'état. Lorsqu'elle le fait, elle tente de le faire aussi rapidement que possible, plutôt que de s'assurer que les informations dans l'ancienne allocation sont supprimées en toute sécurité si une nouvelle allocation est nécessaire.

VALEUR DE RETOUR

La fonction libkeccak_fast_digest() retourne 0 en cas de succès. En cas d'erreur, -1 est retourné et errno est défini pour décrire l'erreur.

ERREURS

La fonction libkeccak_fast_digest() peut échouer pour toute raison spécifiée par la fonction realloc(3).

EXEMPLE

Cet exemple calcule le hachage Keccak[b = 1024, c = 576, n = 256] de l'entrée standard, et imprime le hachage, sous forme hexadécimale, sur la sortie standard.

struct libkeccak_state state;
struct libkeccak_spec spec;
char binhash[256 / 8];
char hexhash[256 / 8 * 2 + 1];
char chunk[4 << 10];
ssize_t len;
spec.bitrate = 1024;
spec.capacity = 576;
spec.output = 256;
if (libkeccak_state_initialise(&state, &spec) < 0)
	goto fail;
for (;;) {
	len = read(STDIN_FILENO, chunk, sizeof(chunk));
	if ((len < 0) && (errno == EINTR))
		continue;
	if (len < 0)
		goto fail;
	if (len == 0)
		break;
	if (libkeccak_fast_update(&state, chunk, (size_t)len) < 0)
		goto fail;
}
if (libkeccak_fast_digest(&state, NULL, 0, 0, "", binhash) < 0)
	goto fail;
libkeccak_behex_lower(hexhash, binhash, sizeof(binhash));
printf("%s\n", hexhash);
libkeccak_state_fast_destroy(&state);

NOTES

Pour cSHAKE, libkeccak_cshake_initialise(3), doit être appelé, une seule fois, immédiatement après l'initialisation de l'état ; avant le premier appel à l'une des fonctions libkeccak_fast_update(), libkeccak_zerocopy_update(), libkeccak_update(), et libkeccak_digest_digest().
