SSL_GET_SHARED_CIPHERS(3) Manuel des fonctions de bibliothèque SSL_GET_SHARED_CIPHERS(3)

NOM

SSL_get_shared_ciphers — chiffrements supportés par le client et le serveur

SYNOPIS

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

char *
SSL_get_shared_ciphers(const SSL *ssl, char *buf, int len);

DESCRIPTION

Si ssl contient une session en mode serveur, SSL_get_shared_ciphers() insère autant de noms de chiffrements supportés à la fois par le client et le serveur dans le tampon buf que le tampon est suffisamment long pour les contenir. Les noms sont séparés par des deux-points. Au plus len octets sont écrits dans buf, y compris le caractère NUL de terminaison.

VALEURS DE RETOUR

SSL_get_shared_ciphers() retourne buf en cas de succès ou NULL en cas d'échec. Les situations suivantes provoquent un échec :

  • SSL_is_server(3) est faux, c'est-à-dire que ssl n'est pas défini en mode serveur.
  • SSL_get_ciphers(3) est NULL ou vide, c'est-à-dire qu'aucun chiffrement n'est disponible pour être utilisé par le serveur.
  • SSL_get_session(3) est NULL, c'est-à-dire que ssl ne contient aucune session.
  • SSL_get_client_ciphers(3) est NULL ou vide, c'est-à-dire que ssl ne contient aucune information sur les chiffrements supportés par le client, ou que le client ne supporte aucun chiffrement.
  • L'argument len est inférieur à 2.

VOIR AUSSI

ssl(3), SSL_get_ciphers(3)

HISTORIQUE

SSL_get_shared_ciphers() est apparu pour la première fois dans SSLeay 0.4.5b et est disponible depuis OpenBSD 2.4.

BOGUES

Si la liste est trop longue pour tenir dans len octets, elle est silencieusement tronquée après le dernier nom de chiffrement qui convient, et tous les chiffrements suivants sont ignorés. Si le tampon est très court, de sorte que même le premier nom de chiffrement ne rentre pas, une chaîne vide est retournée même lorsque des chiffrements partagés sont effectivement disponibles.

Il n'y a pas de moyen facile de savoir quelle taille est nécessaire pour buf ou si l'espace fourni était suffisant.
