DESCRIPTION

Ces fonctions permettent d'obtenir ou de définir les versions minimale et maximale de protocole prises en charge pour ctx ou ssl. Cela fonctionne en combinaison avec les options définies via SSL_CTX_set_options(3) qui permettent également de désactiver des versions de protocole spécifiques. Utilisez ces fonctions plutôt que de désactiver des versions de protocole spécifiques.

Définir la version minimale ou maximale à 0 permettra d'activer les versions de protocole jusqu'à la version la plus basse ou jusqu'à la version la plus haute prise en charge par la bibliothèque, respectivement.

Les versions actuellement prises en charge sont TLS1_VERSION, TLS1_1_VERSION, et TLS1_2_VERSION pour TLS et DTLS1_VERSION et DTLS1_2_VERSION pour DTLS.

Dans d'autres implémentations, ces fonctions peuvent être implémentées sous forme de macros.

VALEUR DE RETOUR

Les fonctions de définition retournent 1 en cas de succès ou 0 en cas d'échec.

Les fonctions d'obtention retournent la version configurée ou 0 si ctx ou ssl a été configuré pour utiliser automatiquement la version la plus basse ou la plus haute prise en charge par la bibliothèque.

VOIR AUSSI

ssl(3), SSL_CTX_new(3), SSL_CTX_set_options(3)

HISTORIQUE

Les fonctions de définition sont apparues pour la première fois dans BoringSSL en décembre 2014, avec des noms plus courts sans la partie proto_. Deux ans plus tard, OpenSSL les a incluses dans sa version 1.1.0, changeant gratuitement les noms ; Google a haussé les épaules et a adopté les noms plus longs un mois plus tard. Elles sont disponibles depuis OpenBSD 6.2.

Les fonctions d'obtention sont apparues pour la première fois dans OpenSSL 1.1.0g et sont disponibles depuis OpenBSD 6.3.
