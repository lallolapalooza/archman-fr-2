OPENSSL(1) Manuel des commandes générales OPENSSL(1)

NOM

openssl — Outil de ligne de commande OpenSSL

SYNTAXE

openssl commande [opt_commande ...] [arg_commande ...]

openssl list-standard-commands | list-message-digest-commands | list-cipher-commands | list-cipher-algorithms | list-message-digest-algorithms | list-public-key-algorithms

openssl no-commande

DESCRIPTION

OpenSSL est une boîte à outils cryptographique implémentant le protocole réseau Transport Layer Security (TLS), ainsi que les normes cryptographiques associées.

Le programme openssl est un outil de ligne de commande permettant d'utiliser les diverses fonctions cryptographiques de la bibliothèque cryptographique openssl depuis le shell.

Les pseudo-commandes list-standard-commands, list-message-digest-commands et list-cipher-commands affichent une liste (une entrée par ligne) des noms de toutes les commandes standard, commandes de résumé de message ou commandes de chiffrement, respectivement, disponibles dans l'utilitaire openssl présent.

Les pseudo-commandes list-cipher-algorithms et list-message-digest-algorithms listent tous les noms de chiffrements et de résumés de message, une entrée par ligne. Les alias sont listés comme suit :

de => à

La pseudo-commande list-public-key-algorithms liste tous les algorithmes de clé publique pris en charge.

La pseudo-commande no-commande vérifie si une commande du nom spécifié est disponible. Si commande n'existe pas, elle retourne 0 et affiche no-commande ; sinon elle retourne 1 et affiche commande. Dans les deux cas, la sortie va vers stdout et rien n'est affiché sur stderr. Les arguments de ligne de commande supplémentaires sont toujours ignorés. Comme pour chaque chiffrement il existe une commande du même nom, cela fournit un moyen facile pour les scripts shell de tester la disponibilité des chiffrements dans le programme openssl.

Note : no-commande ne peut pas détecter les pseudo-commandes telles que quit, list-...-commands, ou no-commande elle-même.

ASN1PARSE

openssl asn1parse
[-i] [-dlimit nombre] [-dump] [-genconf fichier] [-genstr str] [-in fichier] [-inform der | pem | txt] [-length nombre] [-noout] [-offset nombre] [-oid fichier] [-out fichier] [-strparse offset]

La commande asn1parse est un utilitaire de diagnostic qui peut analyser des structures ASN.1. Elle peut également être utilisée pour extraire des données de données formatées ASN.1.

Les options sont les suivantes :

-dlimit nombre
Affiche les nombre premiers octets de données inconnues sous forme hexadécimale.
-dump
Affiche les données inconnues sous forme hexadécimale.
-genconf fichier, -genstr str
Génère des données encodées basées sur la chaîne str, le fichier fichier, ou les deux, en utilisant le format décrit dans ASN1_generate_nconf(3). Si seul fichier est présent, alors la chaîne est obtenue de la section par défaut en utilisant le nom “asn1”. Les données encodées sont transmises au parseur ASN.1 et affichées comme si elles provenaient d'un fichier ; le contenu peut ainsi être examiné et écrit dans un fichier à l'aide de l'option -out.
-i
Indente la sortie selon la “profondeur” des structures.
-in fichier
Le fichier d'entrée à lire, ou l'entrée standard si non spécifié.
-inform der | pem | txt
Le format d'entrée.
-length nombre
Nombre d'octets à analyser ; la valeur par défaut est jusqu'à la fin du fichier.
-noout
Ne pas afficher la version analysée du fichier d'entrée.
-offset nombre
Décalage de départ pour commencer l'analyse ; la valeur par défaut est le début du fichier.
-oid fichier
Un fichier contenant des identificateurs d'objet (OIDs) supplémentaires. Si un OID n'est pas dans la table interne d'openssl, il sera représenté sous forme numérique (par exemple 1.2.3.4).

Chaque ligne est composée de trois colonnes : la première colonne est l'OID sous forme numérique et doit être suivie d'un espace blanc. La deuxième colonne est le “nom court”, qui est un seul mot suivi d'un espace blanc. La dernière colonne est le reste de la ligne et est le “nom long”. asn1parse affiche le nom long.

-out fichier
Le fichier de sortie encodé en DER ; la valeur par défaut est aucune sortie encodée (utile lorsqu'il est combiné avec -strparse).
-strparse offset
Analyse les octets de contenu de l'objet ASN.1 en commençant au offset. Cette option peut être utilisée plusieurs fois pour “pénétrer” dans une structure imbriquée.

-startdate date
Définit la date de début. Le format de la date est [AA]AAAAJJHHMMSSZ, avec les quatre chiffres de l'année requis pour les dates à partir de 2050. Toutes les autres dates sont traitées comme des dates du 21ème siècle.
-status serial
Met à jour le statut d'un certificat dans la base de données des certificats et de leurs statuts. Le serial est le numéro de série du certificat.
-subj arg
Remplace le nom du sujet donné dans la requête. L'arg doit être formaté comme /type0=valeur0/type1=valeur1/type2=... ; les caractères peuvent être échappés par ‘\’ (barre oblique inverse), aucun espace n'est ignoré.
-updatedb
Met à jour la base de données des certificats et de leurs statuts. Cette option doit être utilisée en conjonction avec l'option -status.
-utf8
Interprète les valeurs de champ lues à partir d'un terminal ou obtenues à partir d'un fichier de configuration comme des chaînes UTF-8. Par défaut, elles sont interprétées comme ASCII.
-verbose
Affiche des informations détaillées sur le traitement.

La commande ca est une application minimale d'autorité de certification (AC). Elle peut être utilisée pour signer des requêtes de certificat sous diverses formes et générer des listes de révocation de certificats (CRL). Elle maintient également une base de données textuelle des certificats émis et de leur statut.

Les options pertinentes pour les AC sont les suivantes :

-batch
Mode batch. Dans ce mode, aucune question ne sera posée et tous les certificats seront certifiés automatiquement.
-cert file
Le fichier du certificat AC.
-config file
Spécifie un fichier de configuration alternatif.
-create_serial
Si la lecture du numéro de série à partir du fichier texte spécifié dans la configuration échoue, crée un nouveau numéro de série aléatoire à utiliser comme prochain numéro de série.
-days arg
Le nombre de jours pendant lesquels le certificat sera certifié.
-enddate date
Définit la date d'expiration. Le format de la date est [AA]AAAAJJHHMMSSZ, avec les quatre chiffres de l'année requis pour les dates à partir de 2050.
-extensions section
La section du fichier de configuration contenant les extensions de certificat à ajouter lors de l'émission d'un certificat (par défaut x509_extensions, sauf si l'option -extfile est utilisée). Si aucune section d'extension n'est présente, un certificat V1 est créé. Si la section d'extension est présente (même si elle est vide), alors un certificat V3 est créé. Voir la page man x509v3.cnf(5) pour les détails du format de la section d'extension.
-extfile file
Un fichier de configuration supplémentaire pour lire les extensions de certificat (en utilisant la section par défaut, sauf si l'option -extensions est également utilisée).
-gencrl
Génère une liste de révocation de certificats (CRL).
-in file
Un fichier d'entrée contenant une seule requête de certificat à signer par l'AC.
-infiles
Si présent, cette option doit être la dernière ; tous les arguments suivants sont supposés être les noms de fichiers contenant des requêtes de certificat.
-key password
Le mot de passe utilisé pour chiffrer la clé privée. Étant donné que sur certains systèmes les arguments de ligne de commande sont visibles, cette option doit être utilisée avec prudence.
-keyfile file
La clé privée pour signer les requêtes.
-keyform pem | der
Format du fichier de clé privée. Le défaut est pem.
-md alg
Le digest de message à utiliser. Les valeurs possibles incluent md5 et sha1. Cette option s'applique également aux CRL.
-multivalue-rdn
Cette option fait que l'argument -subj soit interprété avec une prise en charge complète des RDN multivalués, par exemple "/DC=org/DC=OpenSSL/DC=users/UID=123456+CN=John Doe". Si -multivalue-rdn n'est pas utilisé, la valeur UID est définie à "123456+CN=John Doe".
-name section
Spécifie la section du fichier de configuration à utiliser (remplace default_ca dans la section ca).
-noemailDN
Le DN d'un certificat peut contenir le champ EMAIL s'il est présent dans le DN de la requête, cependant il est de bonne politique de n'avoir que l'e-mail défini dans l'extension altName du certificat. Lorsque cette option est définie, le champ EMAIL est supprimé du sujet du certificat et n'est défini que dans les extensions éventuellement présentes. Le mot-clé email_in_dn peut être utilisé dans le fichier de configuration pour activer ce comportement.
-notext
Ne pas afficher la forme texte d'un certificat dans le fichier de sortie.
-out file
Le fichier de sortie pour écrire les certificats. Le défaut est la sortie standard. Les détails du certificat seront également imprimés dans ce fichier au format PEM.
-outdir directory
Le répertoire dans lequel écrire les certificats. Le certificat sera écrit dans un fichier constitué du numéro de série en hexadécimal, suivi de ".pem".
-passin arg
La source du mot de passe de la clé.
-policy arg
Définit la "politique" de l'AC à utiliser. La section de politique dans le fichier de configuration se compose d'un ensemble de variables correspondant aux champs DN du certificat. Les valeurs peuvent être "match" (la valeur doit correspondre au même champ dans le certificat AC), "supplied" (la valeur doit être présente), ou "optional" (la valeur peut être présente). Tous les champs non mentionnés dans la section de politique sont silencieusement supprimés, sauf si l'option -preserveDN est définie, mais cela peut être considéré plus comme une bizarrerie qu'un comportement intentionnel.
-preserveDN
Normalement, l'ordre du DN d'un certificat est le même que l'ordre des champs dans la section de politique pertinente. Lorsque cette option est définie, l'ordre est le même que celui de la requête. Ceci est largement pour la compatibilité avec l'ancien contrôle d'inscription IE qui n'acceptait les certificats que si leurs DN correspondaient à l'ordre de la requête. Ceci n'est pas nécessaire pour Xenroll.
-revoke file
Révoke le certificat spécifié dans le fichier. Le fichier peut être un fichier PEM contenant le certificat à révoquer, ou un fichier texte contenant une liste de numéros de série de certificats à révoquer.
-selfsign
Indique que les certificats émis doivent être signés avec la clé avec laquelle les requêtes de certificat ont été signées, fournie avec -keyfile. Les requêtes de certificat signées avec une clé différente sont ignorées. Si -gencrl ou -ss_cert sont donnés, -selfsign est ignoré.

Une conséquence de l'utilisation de -selfsign est que le certificat auto-signé apparaît parmi les entrées de la base de données des certificats (voir l'option de configuration database) et utilise le même compteur de numéros de série que tous les autres certificats signés avec le certificat auto-signé.

-sigopt nm:v
Passe des options à l'algorithme de signature lors des opérations de signature ou de certification. Les noms et valeurs de ces options sont spécifiques à l'algorithme.
-ss_cert file
Un seul certificat auto-signé à signer par l'AC.
k" href="#verbose">-verbose
Imprime des détails supplémentaires sur les opérations en cours.

Les options pertinentes pour les CRL sont les suivantes :

-crl_CA_compromise time
Ceci est identique à -crl_compromise, sauf que la raison de révocation est définie sur CACompromise.
-crl_compromise time
Définit la raison de révocation sur keyCompromise et l'heure de compromission sur time. time doit être au format GeneralizedTime, c'est-à-dire YYYYMMDDHHMMSSZ.
-crl_hold instruction
Définit le code de raison de révocation CRL sur certificateHold et l'instruction de suspension sur instruction, qui doit être un OID. Bien que tout OID puisse être utilisé, seuls holdInstructionNone (dont l'utilisation est déconseillée par la RFC 2459), holdInstructionCallIssuer ou holdInstructionReject seront normalement utilisés.
-crl_reason reason
Raison de révocation, où reason est l'une des valeurs suivantes : unspecified, keyCompromise, CACompromise, affiliationChanged, superseded, cessationOfOperation, certificateHold ou removeFromCRL. La correspondance de reason est insensible à la casse. La définition de toute raison de révocation rendra la CRL v2. En pratique, removeFromCRL n'est pas particulièrement utile car il est uniquement utilisé dans les CRL delta qui ne sont pas actuellement implémentées.
-crldays days
Le nombre de jours avant la prochaine échéance de la CRL. Il s'agit du nombre de jours à partir de maintenant à placer dans le champ nextUpdate de la CRL.
-crlexts section
La section du fichier de configuration contenant les extensions CRL à inclure. Si aucune section d'extensions CRL n'est présente, une CRL V1 est créée ; si la section d'extensions CRL est présente (même si elle est vide), une CRL V2 est créée. Les extensions CRL spécifiées sont des extensions CRL et non des extensions d'entrée CRL. Il convient de noter que certains logiciels ne peuvent pas gérer les CRL V2. Voir la page man x509v3.cnf(5) pour les détails du format de la section des extensions.
-crlhours hours
Le nombre d'heures avant la prochaine échéance de la CRL.
-crlsec seconds
Le nombre de secondes avant la prochaine échéance de la CRL.
-gencrl
Génère une CRL basée sur les informations du fichier d'index.
-revoke file
Un fichier file contenant un certificat à révoquer.
-status serial
Affiche le statut du certificat avec le numéro de série serial.
-updatedb
Met à jour la base de données d'index pour purger les certificats expirés.

Beaucoup d'options peuvent être définies dans la section ca du fichier de configuration (ou dans la section par défaut du fichier de configuration), spécifiées en utilisant default_ca ou -name. L'option preserve est lue directement à partir de la section ca.

Beaucoup d'options du fichier de configuration sont identiques aux options de la ligne de commande. Lorsque l'option est présente dans le fichier de configuration et sur la ligne de commande, la valeur de la ligne de commande est utilisée. Lorsqu'une option est décrite comme obligatoire, elle doit être présente dans le fichier de configuration ou son équivalent sur la ligne de commande (s'il y en a un) doit être utilisée.

certificate
Identique à -cert. Donne le fichier contenant le certificat CA. Obligatoire.
copy_extensions
Détermine comment les extensions dans les demandes de certificat doivent être traitées. Si défini sur none ou si cette option est absente, les extensions sont ignorées et non copiées dans le certificat. Si défini sur copy, alors toutes les extensions présentes dans la demande qui ne sont pas déjà présentes sont copiées dans le certificat. Si défini sur copyall, alors toutes les extensions de la demande sont copiées dans le certificat : si l'extension est déjà présente dans le certificat, elle est d'abord supprimée.

L'option copy_extensions doit être utilisée avec prudence. Si l'on n'y prend pas garde, cela peut représenter un risque de sécurité. Par exemple, si une demande de certificat contient une extension basicConstraints avec CA:TRUE et que la valeur de copy_extensions est définie sur copyall et que l'utilisateur ne le remarque pas lors de l'affichage du certificat, cela remettra au demandeur un certificat CA valide.

Cette situation peut être évitée en définissant copy_extensions sur copy et en incluant basicConstraints avec CA:FALSE dans le fichier de configuration. Ensuite, si la demande contient une extension basicConstraints, elle sera ignorée.

L'utilisation principale de cette option est de permettre à une demande de certificat de fournir des valeurs pour certaines extensions telles que subjectAltName.

crl_extensions
Identique à -crlexts.
crlnumber
Un fichier texte contenant le prochain numéro de CRL à utiliser en hexadécimal. Le numéro de CRL sera inséré dans les CRL uniquement si ce fichier existe. Si ce fichier est présent, il doit contenir un numéro de CRL valide.
database
Le fichier de base de données texte à utiliser. Obligatoire. Ce fichier doit exister, bien qu'initialement il soit vide.
default_crl_hours, default_crl_days
Identique aux options -crlhours et -crldays. Celles-ci ne seront utilisées que si aucune des options de la ligne de commande n'est présente. Au moins l'une d'elles doit être présente pour générer une CRL.
default_days
Identique à l'option -days. Le nombre de jours pendant lesquels un certificat est délivré.
default_enddate
Identique à l'option -enddate. Soit cette option, soit default_days (ou leurs équivalents sur la ligne de commande) doit être présente.
default_md
Identique à l'option -md. Le résumé de message à utiliser. Obligatoire.
default_startdate
Identique à l'option -startdate. La date de début pour la délivrance d'un certificat. Si elle n'est pas définie, l'heure actuelle est utilisée.
email_in_dn
Identique à -noemailDN. Si le champ EMAIL doit être supprimé du DN du certificat, définissez simplement cette option sur "no". Si elle n'est pas présente, la valeur par défaut est d'autoriser le champ EMAIL dans le DN du certificat.
name_opt, cert_opt
Ces options permettent de contrôler le format utilisé pour afficher les détails du certificat lors de la demande de confirmation de signature à l'utilisateur. Toutes les options prises en charge par les commutateurs -nameopt et -certopt des utilitaires x509 peuvent être utilisées ici, à l'exception du fait que no_signame et no_sigdump sont définis de manière permanente et ne peuvent pas être désactivés (car la signature du certificat ne peut pas être affichée car le certificat n'est pas encore signé à ce stade).

Par souci de commodité, la valeur ca_default est acceptée par les deux pour produire une sortie raisonnable.

Si aucune des options n'est présente, le format utilisé dans les versions antérieures de openssl est utilisé. L'utilisation de l'ancien format est fortement déconseillée car il n'affiche que les champs mentionnés dans la section policy, gère mal les types de chaînes de caractères multi-caractères et n'affiche pas les extensions.

new_certs_dir
Identique à l'option de ligne de commande -outdir. Elle spécifie le répertoire où seront placés les nouveaux certificats. Obligatoire.
oid_file
Spécifie un fichier contenant des identificateurs d'objet supplémentaires. Chaque ligne du fichier doit consister en la forme numérique de l'identificateur d'objet suivie d'un espace, puis du nom court suivi d'un espace et enfin du nom long.
oid_section
Spécifie une section du fichier de configuration contenant des identificateurs d'objet supplémentaires. Chaque ligne doit consister en le nom court de l'identificateur d'objet suivi de ‘=’ et de la forme numérique. Les noms courts et longs sont les mêmes lorsque cette option est utilisée.
policy
Identique à -policy. Obligatoire.
preserve
Identique à -preserveDN.
private_key
Identique à l'option -keyfile. Le fichier contenant la clé privée de l'AC. Obligatoire.
serial
Un fichier texte contenant le prochain numéro de série à utiliser en hexadécimal. Obligatoire. Ce fichier doit exister et contenir un numéro de série valide.
unique_subject
Si la valeur yes est donnée, les entrées de certificat valides dans la base de données doivent avoir des sujets uniques. Si la valeur no est donnée, plusieurs entrées de certificat valides peuvent avoir le même sujet exact. La valeur par défaut est yes.

Notez qu'il est valide dans certaines circonstances que des certificats soient créés sans sujet. Dans les cas où il existe plusieurs certificats sans sujet, cela ne compte pas comme un doublon.

x509_extensions
Identique à -extensions.

CERTHASH

openssl certhash
[-nv] dir ...

La commande certhash calcule une valeur de hachage du fichier ".pem" dans la liste de répertoires spécifiée et crée des liens symboliques pour chaque fichier, où le nom du lien est la valeur de hachage. Consultez la page de manuel SSL_CTX_load_verify_locations(3) pour savoir comment les liens de hachage sont utilisés.

Les liens créés sont de la forme "HHHHHHHH.D", où chaque ‘H’ est un caractère hexadécimal et ‘D’ est un seul chiffre décimal. Les hachages pour les CRL ressemblent, sauf que la lettre ‘r’ apparaît après le point, comme ceci : "HHHHHHHH.rD". Lors du traitement d'un répertoire, certhash supprimera d'abord tous les liens dont le nom correspond à cette syntaxe et à une référence invalide.

Plusieurs objets peuvent avoir le même hachage ; ils seront indiqués en incrémentant la valeur ‘D’. Les doublons sont trouvés en comparant l'empreinte SHA256 complète. Un avertissement sera affiché si un doublon est trouvé.

Un avertissement sera également affiché s'il y a des fichiers qui ne peuvent pas être analysés comme un certificat ou une CRL.

Les options sont les suivantes :

-n
Effectuer un essai à blanc, sans apporter de modifications.
-v
Afficher des détails supplémentaires sur le traitement.
dir ...
Spécifiez les répertoires à traiter.

CIPHERS

openssl ciphers [-hsVv] [-tls1_2] [-tls1_3] [control]

La commande ciphers convertit la chaîne control du format documenté dans SSL_CTX_set_cipher_list(3) en une liste de préférences de suites de chiffrement SSL ordonnée. Si aucune chaîne control n'est spécifiée, la liste DEFAULT est affichée.

Les options sont les suivantes :

-h, -?
Afficher un bref message d'utilisation.
-s
Lister uniquement les chiffrements pris en charge par la méthode TLS.
-tls1_2 | -tls1_3
En combinaison avec l'option -s, lister les chiffrements qui pourraient être utilisés si la version de protocole spécifiée était négociée.
-V
Verbeux. Lister les chiffrements avec le code de la suite de chiffrement au format hexadécimal, le nom du chiffrement et une description complète de la version du protocole, de l'échange de clés, de l'authentification, du chiffrement et des algorithmes mac.
-v
Comme -V, mais sans les codes de suites de chiffrement.

La commande cms gère les courriels S/MIME v3.1. Elle peut chiffrer, déchiffrer, signer et vérifier, compresser et décompresser les messages S/MIME.

Le message MIME doit être envoyé sans lignes vides entre les en-têtes et la sortie. Certains programmes de messagerie ajouteront automatiquement une ligne vide. Le pipage du courrier directement vers sendmail est un moyen d'obtenir le bon format.

Le message fourni à signer ou à chiffrer doit inclure les en-têtes MIME nécessaires, sinon de nombreux clients S/MIME ne l'afficheront pas correctement (voire pas du tout). Vous pouvez utiliser l'option -text pour ajouter automatiquement des en-têtes en texte brut.

Un message "signé et chiffré" est un message signé qui est ensuite chiffré. Cela peut être produit en chiffrant un message déjà signé.

Il existe diverses options d'opération qui définissent le type d'opération à effectuer. La signification des autres options varie en fonction du type d'opération.

-encrypt
Chiffre le courrier pour les certificats du destinataire donné. Le fichier d'entrée est le message à chiffrer. Le fichier de sortie est le courrier chiffré au format MIME. Le type CMS réel est EnvelopedData. The Online Certificate Status Protocol (OCSP) enables applications to determine the (revocation) state of an identified certificate (RFC 2560).

The ocsp command performs many common OCSP tasks. It can be used to print out requests and responses, create requests and send queries to an OCSP responder, and behave like a mini OCSP server itself.

The options are as follows:

-CAfile file, -CApath directory
A file or path containing trusted CA certificates, used to verify the signature on the OCSP response.
-cert fichier
Ajoute le certificat fichier à la requête. Le certificat de l'émetteur est pris de l'option précédente -issuer, ou une erreur se produit si aucun certificat d'émetteur n'est spécifié.
-dgst alg
Utilise l'algorithme de hachage alg pour l'identification du certificat dans la requête OCSP. Par défaut, SHA1 est utilisé.
-host nom_hote:port, -path chemin
Envoie la requête OCSP à nom_hote sur le port. -path spécifie le nom du chemin HTTP à utiliser, ou / par défaut.
-header nom valeur
Ajoute l'en-tête nom avec la valeur spécifiée à la requête OCSP envoyée au répondeur. Ceci peut être répété.
-issuer fichier
Le certificat de l'émetteur actuel, au format PEM. Peut être utilisé plusieurs fois et doit précéder toute option -cert.
-no_cert_checks
N'effectue aucune vérification supplémentaire sur le certificat du signataire de la réponse OCSP. C'est-à-dire, ne vérifie pas si le certificat du signataire est autorisé à fournir les informations de statut nécessaires : par conséquent, cette option ne doit être utilisée qu'à des fins de test.
-no_cert_verify
Ne vérifie pas du tout le certificat du signataire de la réponse OCSP. Comme cette option permet à la réponse OCSP d'être signée par n'importe quel certificat, elle ne doit être utilisée qu'à des fins de test.
-no_certs
N'inclut aucun certificat dans la requête signée.
-no_chain
N'utilise pas les certificats de la réponse comme certificats CA supplémentaires non fiables.
-no_explicit
Ne vérifie pas la confiance explicite pour la signature OCSP dans le certificat CA racine.
-no_intern
Ignore les certificats contenus dans la réponse OCSP lors de la recherche du certificat du signataire. Le certificat du signataire doit être spécifié avec l'option -verify_other ou -VAfile.
-no_signature_verify
Ne vérifie pas la signature sur la réponse OCSP. Comme cette option tolère les signatures invalides sur les réponses OCSP, elle ne sera normalement utilisée qu'à des fins de test.
-nonce, -no_nonce
Ajoute une extension nonce OCSP à une requête, ou désactive l'ajout d'un nonce OCSP. Normalement, si une requête OCSP est entrée à l'aide de l'option -respin, aucun nonce n'est ajouté : utiliser l'option -nonce forcera l'ajout d'un nonce. Si une requête OCSP est en cours de création (en utilisant les options -cert et -serial), un nonce est automatiquement ajouté ; spécifier -no_nonce annule cela.
-noverify
N'essaie pas de vérifier la signature de la réponse OCSP ou les valeurs de nonce. Ceci ne devrait normalement être utilisé que pour le débogage car cela désactive toute vérification du certificat du répondeur.
-out fichier
Spécifie le fichier de sortie dans lequel écrire, ou la sortie standard si non spécifié.
-req_text, -resp_text, -text
Affiche la forme texte de la requête OCSP, de la réponse, ou des deux, respectivement.
-reqin fichier, -respin fichier
Lit une requête ou une réponse OCSP à partir du fichier fichier. Ces options sont ignorées si la création d'une requête ou d'une réponse OCSP est implicite par d'autres options (par exemple avec les options -serial, -cert et -host).
-reqout fichier, -respout fichier
Écrit la requête ou la réponse de certificat codée en DER dans fichier.
-serial num
Identique à l'option -cert, sauf que le certificat avec le numéro de série num est ajouté à la requête. Le numéro de série est interprété comme un entier décimal sauf s'il est précédé de ‘0x’. Les entiers négatifs peuvent également être spécifiés en faisant précéder la valeur d'un signe moins.
-sign_other fichier
Certificats supplémentaires à inclure dans la requête signée.
-signer fichier, -signkey fichier
Signe la requête OCSP en utilisant le certificat spécifié dans l'option -signer et la clé privée spécifiée par l'option -signkey. Si l'option -signkey n'est pas présente, la clé privée est lue depuis le même fichier que le certificat. Si aucune des options n'est spécifiée, la requête OCSP n'est pas signée.
-timeout secondes
Délai de connexion au répondeur OCSP en secondes.
-trust_other
Les certificats spécifiés par l'option -verify_other doivent être explicitement fiables et aucune vérification supplémentaire ne sera effectuée sur eux. Ceci est utile lorsque la chaîne complète du certificat du répondeur n'est pas disponible ou que la confiance accordée à un CA racine n'est pas appropriée.
-url url_repondeur
Spécifie l'URL du répondeur. Les URL HTTP et HTTPS (SSL/TLS) peuvent être spécifiées.
-VAfile fichier
Un fichier contenant des certificats de répondeur explicitement fiables. Équivalent aux options -verify_other et -trust_other.
-validity_period nsec, -status_age age
La plage de temps, en secondes, qui sera tolérée dans une réponse OCSP. Chaque réponse de statut de certificat inclut une date de début de validité (notBefore) et une date de fin de validité (notAfter) facultative. L'heure actuelle devrait se situer entre ces deux valeurs, mais l'intervalle entre les deux peut n'être que de quelques secondes. En pratique, les horloges du répondeur OCSP et des clients peuvent ne pas être synchronisées précisément, et une telle vérification peut donc échouer. Pour éviter cela, l'option -validity_period peut être utilisée pour spécifier une plage d'erreur acceptable en secondes, la valeur par défaut étant de 5 minutes.

Si la date de fin de validité (notAfter) est omise dans une réponse, cela signifie que de nouvelles informations de statut sont immédiatement disponibles. Dans ce cas, l'âge du champ notBefore est vérifié pour s'assurer qu'il n'est pas plus ancien que age secondes. Par défaut, cette vérification supplémentaire n'est pas effectuée.

-verify_other fichier
Un fichier contenant des certificats supplémentaires à rechercher lors de la tentative de localisation du certificat de signature de la réponse OCSP. Certains répondeurs omettent le certificat du signataire réel de la réponse, cela peut donc être utilisé pour fournir le certificat nécessaire.

Les options pour le serveur OCSP sont les suivantes :

-CA fichier
Certificat CA correspondant aux informations de révocation dans indexfile.
-ignore_err
Ignore la réponse invalide.
-index indexfile
indexfile est un fichier texte au format CA contenant des informations de révocation de certificat.

Si cette option est spécifiée, ocsp est en mode répondeur, sinon il est en mode client. Les requêtes traitées par le répondeur peuvent être spécifiées sur la ligne de commande (en utilisant les options -issuer et -serial), fournies dans un fichier (en utilisant l'option -respin), ou via des clients OCSP externes (si port ou url est spécifié).

Si cette option est présente, alors les options -CA et -rsigner doivent également être présentes.

-nmin minutes, -ndays jours
Nombre de minutes ou de jours pendant lesquels des informations de révocation fraîches sont disponibles : utilisé dans le champ nextUpdate. Si aucune des options n'est présente, le champ nextUpdate est omis, ce qui signifie que des informations de révocation fraîches sont immédiatement disponibles.
-nrequest nombre
Sort après avoir reçu nombre requêtes (la valeur par défaut est illimitée).
-port portnum
Port pour écouter les requêtes OCSP. Peut également être spécifié à l'aide de l'option -url.
-resp_key_id
Identifier le certificat du signataire à l'aide de l'identifiant de clé ; par défaut, on utilise le nom du sujet.
-resp_no_certs
N'inclure aucun certificat dans la réponse OCSP.
-rkey fichier
La clé privée pour signer les réponses OCSP ; si elle n'est pas présente, le fichier spécifié dans l'option -rsigner est utilisé.
-rother fichier
Certificats supplémentaires à inclure dans la réponse OCSP.
-rsigner fichier
Le certificat pour signer les réponses OCSP.

Initialement, le certificat du répondeur OCSP est localisé et la signature sur la requête OCSP est vérifiée à l'aide de la clé publique du certificat du répondeur. Ensuite, une vérification normale de certificat est effectuée sur le certificat du répondeur OCSP, construisant une chaîne de certificats dans le processus. Les emplacements des certificats de confiance utilisés pour construire la chaîne peuvent être spécifiés par les options -CAfile et -CApath ou ils seront recherchés dans le répertoire standard des certificats openssl.

Si la vérification initiale échoue, le processus de vérification OCSP s'arrête avec une erreur. Sinon, le certificat de l'autorité émettrice dans la requête est comparé au certificat du répondeur OCSP : s'il y a une correspondance, la vérification OCSP réussit.

Sinon, l'AC du répondeur OCSP est vérifiée par rapport au certificat de l'autorité émettrice dans la requête. S'il y a une correspondance et que l'utilisation de clé étendue OCSPSigning est présente dans le certificat du répondeur OCSP, alors la vérification OCSP réussit.

Sinon, l'AC racine de l'AC du répondeur OCSP est vérifiée pour voir si elle est de confiance pour la signature OCSP. Si c'est le cas, la vérification OCSP réussit.

Si aucune de ces vérifications n'est réussie, la vérification OCSP échoue. Ce que cela signifie effectivement, c'est que si le certificat du répondeur OCSP est autorisé directement par l'AC dont il émet des informations de révocation (et qu'il est correctement configuré), alors la vérification réussira.

Si le répondeur OCSP est un répondeur global, qui peut fournir des détails sur plusieurs AC et possède sa propre chaîne de certificats séparée, alors son AC racine peut être digne de confiance pour la signature OCSP. Alternativement, le certificat du répondeur lui-même peut être explicitement approuvé avec l'option -VAfile.

[-addext ext] [-batch] [-config fichier] [-days n] [-extensions section] [-in fichier] [-inform der | pem] [-key fichier_clé] [-keyform der | pem] [-keyout fichier] [-md4 | -md5 | -sha1] [-modulus] [-multivalue-rdn] [-nameopt option] [-new] [-newhdr] [-newkey arg] [-nodes] [-noout] [-out fichier] [-outform der | pem] [-passin arg] [-passout arg] [-pkeyopt opt:valeur] [-pubkey] [-reqexts section] [-reqopt option] [-set_serial n] [-sigopt nm:v] [-subj arg] [-subject] [-text] [-utf8] [-verbose] [-verify] [-x509]

La commande req crée et traite principalement des demandes de certificat au format PKCS#10. Elle peut également créer des certificats auto-signés, à utiliser comme certificats d'autorité racine, par exemple.

Les options sont les suivantes :

-addext ext
Ajoute une extension spécifique au certificat (si l'option -x509 est présente) ou à la demande de certificat. L'argument doit avoir la forme d'une paire clé=valeur telle qu'elle apparaîtrait dans un fichier de configuration. Cette option peut être donnée plusieurs fois.
-batch
Mode non interactif.
-config fichier
Spécifie un fichier de configuration alternatif.
-days n
Spécifie le nombre de jours pendant lesquels le certificat sera valide. La valeur par défaut est 30 jours. Utilisé avec l'option -x509.
-extensions section, -reqexts section
Spécifie des sections alternatives pour inclure des extensions de certificat (avec -x509) ou des extensions de demande de certificat, permettant d'utiliser plusieurs sections différentes dans le même fichier de configuration.
-in fichier
Le fichier d'entrée à partir duquel lire une demande, ou l'entrée standard si non spécifié. Une demande n'est lue que si les options de création -new et -newkey ne sont pas spécifiées.
-inform der | pem
Le format d'entrée.
-key fichier_clé
Le fichier à partir duquel lire la clé privée. Accepte également les clés privées au format PKCS#8 pour les fichiers au format PEM.
-keyform der | pem
Le format du fichier de clé privée spécifié dans l'argument -key. La valeur par défaut est pem.
-keyout fichier
Le fichier dans lequel écrire la nouvelle clé privée créée. Si cette option n'est pas spécifiée, le nom de fichier présent dans le fichier de configuration est utilisé.
-md5 | -sha1 | -sha256
Le digest de message utilisé pour signer la demande. Ceci remplace l'algorithme de digest spécifié dans le fichier de configuration.

Certains algorithmes de clé publique peuvent remplacer ce choix. Par exemple, les signatures DSA utilisent toujours SHA1.

-modulus
Affiche la valeur du modulus de le clé publique contenue dans la requête.
-multivalue-rdn
Cette option provoque l'interprétation de l'argument -subj avec une prise en charge complète des RDN multivalués, par exemple "/DC=org/DC=OpenSSL/DC=users/UID=123456+CN=John Doe". Si -multivalue-rdn n'est pas utilisé, la valeur de l'UID est définie sur "123456+CN=John Doe".
-nameopt option, -reqopt option
Détermine comment les noms de sujet ou d'émetteur sont affichés. option peut être une seule option ou plusieurs options séparées par des virgules. Alternativement, ces options peuvent être utilisées plus d'une fois pour définir plusieurs options. Voir la section X509 ci-dessous pour plus de détails.
-new
Génère une nouvelle requête de certificat. L'utilisateur est invité à entrer les valeurs des champs pertinents. Les champs réellement demandés ainsi que leurs tailles maximale et minimale sont spécifiés dans le fichier de configuration et les extensions éventuellement demandées.

Si l'option -key n'est pas utilisée, un nouveau clé privée RSA est généré en utilisant les informations spécifiées dans le fichier de configuration.

-newhdr
Ajoute le mot NEW aux lignes d'en-tête et de pied de page du fichier PEM sur la requête générée. Certains logiciels et CA en ont besoin.
-newkey arg
Crée une nouvelle requête de certificat et une nouvelle clé privée. L'argument prend l'une des formes suivantes.

rsa:nbits génère une clé RSA de nbits bits. Si nbits est omis, la taille de clé par défaut est utilisée.

dsa:fichier génère une clé DSA en utilisant les paramètres du fichier.

param:fichier génère une clé en utilisant les paramètres ou le certificat du fichier.

Tous les autres algorithmes supportent la forme algorithme:fichier, où fichier peut être un fichier de paramètres de l'algorithme, créé par la commande genpkey -genparam ou un certificat X.509 pour une clé avec un algorithme approprié. fichier peut être omis, auquel cas tous les paramètres peuvent être spécifiés via l'option -pkeyopt.

-nodes
Ne pas chiffrer la clé privée.
-noout
Ne pas afficher la version encodée de la requête.
-out fichier
Le fichier de sortie vers lequel écrire, ou la sortie standard si non spécifié.
-outform der | pem
Le format de sortie.
-passin arg
La source du mot de passe de la clé.
-passout arg
La source du mot de passe du fichier de sortie.
-pkeyopt opt:valeur
Définit l'option de l'algorithme de clé publique opt à valeur.
-pubkey
Affiche la clé publique.
-reqopt option
Personnalise le format de sortie utilisé avec -text. L'argument option peut être une seule option ou plusieurs options séparées par des virgules. Voir aussi la discussion de -certopt dans la commande x509.
-set_serial n
Numéro de série à utiliser lors de la sortie d'un certificat auto-signé. Ceci peut être spécifié comme une valeur décimale ou hexadécimale si précédé de ‘0x’. Il est possible d'utiliser des numéros de série négatifs mais ce n'est pas recommandé.
-sigopt nm:v
Passe des options à l'algorithme de signature lors de l'opération de signature. Les noms et les valeurs de ces options sont spécifiques à l'algorithme.
-subj arg
Remplace le champ sujet d'une requête d'entrée par les données spécifiées et affiche la requête modifiée. arg doit être formaté comme /type0=valeur0/type1=valeur1/type2=...; les caractères peuvent être échappés par ‘\’ (antislash) ; aucun espace n'est ignoré.
-subject
Affiche le sujet de la requête (ou le sujet du certificat si -x509 est spécifié).
-text
Affiche la requête de certificat en texte brut.
-utf8
Interprète les valeurs des champs comme des chaînes UTF8, pas ASCII.
-verbose
Affiche des détails supplémentaires sur les opérations en cours.
-verify
Vérifie la signature sur la requête.
-x509
Affiche un certificat auto-signé au lieu d'une requête de certificat. Ceci est généralement utilisé pour générer un certificat de test ou une racine CA auto-signée. Les extensions ajoutées au certificat (le cas échéant) sont spécifiées dans le fichier de configuration. Sauf si spécifié en utilisant l'option -set_serial, 0 est utilisé pour le numéro de série.

Les options de configuration sont spécifiées dans la section "req" du fichier de configuration. Les options disponibles sont les suivantes :

attributes
La section contenant les attributs de la requête : son format est le même que distinguished_name. Typiquement, ceux-ci peuvent contenir le challengePassword ou les types unstructuredName. Ils sont actuellement ignorés par les utilitaires de signature de requête de openssl, mais certains CA pourraient les vouloir.
default_bits
La taille de clé par défaut, en bits. La valeur par défaut est 2048. Elle est utilisée si l'option -new est utilisée et peut être remplacée en utilisant l'option -newkey.
default_keyfile
Le fichier par défaut où écrire une clé privée, ou la sortie standard si non spécifié. Il peut être remplacé par l'option -keyout.
default_md
L'algorithme de hachage à utiliser. Les valeurs possibles incluent md5, sha1 et sha256 (la valeur par défaut). Il peut être remplacé en ligne de commande.
distinguished_name
La section contenant les champs du nom unique à demander lors de la génération d'un certificat ou d'une requête de certificat. Le format est décrit ci-dessous.
encrypt_key
Si défini sur "no" et qu'une clé privée est générée, elle n'est pas chiffrée. C'est l'équivalent de l'option -nodes. Pour la compatibilité, encrypt_rsa_key est une option équivalente.
input_password | output_password
Les mots de passe pour le fichier de clé privée d'entrée (s'il est présent) et le fichier de clé privée de sortie (si un sera créé). Les options de ligne de commande -passin et -passout remplacent les valeurs du fichier de configuration.
oid_file
Un fichier contenant des IDENTIFIANTS d'OBJET supplémentaires. Chaque ligne du fichier doit consister en la forme numérique de l'identifiant d'objet, suivie d'un espace blanc, puis du nom court suivi d'un espace blanc et enfin du nom long.
oid_section
Spécifie une section dans le fichier de configuration contenant des identifiants d'objet supplémentaires. Chaque ligne doit consister en le nom court de l'identifiant d'objet suivi de ‘=’ et de la forme numérique. Les noms courts et longs sont les mêmes lorsque cette option est utilisée.
prompt
Si défini sur "no", il désactive la demande des champs du certificat et prend directement les valeurs du fichier de configuration. Cela modifie également le format attendu des sections distinguished_name et attributes.
req_extensions
La section du fichier de configuration contenant une liste d'extensions à ajouter à la requête de certificat. Elle peut être remplacée par l'option -reqexts.
string_mask
Limite les types de chaînes pour l'encodage de certains champs. Les valeurs suivantes peuvent être utilisées, limitant les chaînes aux types indiqués :
utf8only
UTF8String. C'est la valeur par défaut, comme recommandé par PKIX dans la RFC 2459.
def
ault
PrintableString, IA5String, T61String, BMPString, UTF8String.
pkix
PrintableString, IA5String, BMPString, UTF8String. Inspiré de la recommandation PKIX dans la RFC 2459 pour les certificats générés avant 2004, mais différent en autorisant également IA5String.
nombstr
PrintableString, IA5String, T61String, UniversalString. Une solution de contournement pour certains logiciels anciens qui avaient des problèmes avec les types BMPString et UTF8String de taille variable.
MASK:nombre
Un masque de bits explicite des types autorisés, où nombre est un nombre hexadécimal, décimal ou octal de style C qui est un OU bit à bit des valeurs B_ASN1_* provenant de <openssl/asn1.h>.
utf8
S'il est défini sur "yes", les valeurs des champs sont interprétées comme des chaînes UTF8.
x509_extensions
La section du fichier de configuration contenant une liste d'extensions à ajouter à un certificat généré lorsque l'interrupteur -x509 est utilisé. Elle peut être remplacée par l'interrupteur de ligne de commande -extensions.

Il existe deux formats distincts pour les sections nom distinctif et attributs. Si l'option -prompt est définie sur "no", alors ces sections consistent uniquement en noms de champs et valeurs. Si l'option -prompt est absente ou non définie sur "no", alors le fichier contient des informations de demande de champ sous la forme:

nomChamp="demande"
nomChamp_defaut="valeur de champ par défaut"
nomChamp_min= 2
nomChamp_max= 4

"nomChamp" est le nom du champ utilisé, par exemple commonName (ou CN). La chaîne "demande" est utilisée pour demander à l'utilisateur d'entrer les détails pertinents. Si l'utilisateur n'entre rien, la valeur par défaut est utilisée ; s'il n'y a pas de valeur par défaut, le champ est omis. Un champ peut toujours être omis s'il y a une valeur par défaut, si l'utilisateur entre simplement le caractère ‘.’.

Le nombre de caractères entrés doit être compris entre les limites nomChamp_min et nomChamp_max : il peut y avoir des restrictions supplémentaires basées sur le champ utilisé (par exemple, countryName ne peut jamais faire que deux caractères et doit correspondre à une PrintableString).

Certains champs (comme organizationName) peuvent être utilisés plus d'une fois dans un DN. Cela pose un problème car les fichiers de configuration ne reconnaîtront pas le même nom apparaissant deux fois. Pour éviter ce problème, si le nomChamp contient des caractères suivis d'un point, ils seront ignorés. Ainsi, par exemple, un deuxième organizationName peut être saisi en l'appelant "1.organizationName".

Les noms de champs autorisés réels sont tous les identifiants d'objet, noms courts ou longs. Ceux-ci sont compilés dans openssl et incluent les valeurs habituelles telles que commonName, countryName, localityName, organizationName, organizationalUnitName, stateOrProvinceName. De plus, emailAddress est inclus ainsi que name, surname, givenName, initials et dnQualifier.

Des identifiants d'objet supplémentaires peuvent être définis avec les options oid_file ou oid_section dans le fichier de configuration. Tous les champs supplémentaires seront traités comme s'ils étaient une DirectoryString.

RSA

openssl rsa
[-aes128 | -aes192 | -aes256 | -des | -des3] [-check] [-in fichier] [-inform der | net | pem | pvk] [-modulus] [-noout] [-out fichier] [-outform der | net | pem | pvk] [-passin arg] [-passout arg] [-pubin] [-pubout] [-pvk-none | -pvk-strong | -pvk-weak] [-RSAPublicKey_in] [-RSAPublicKey_out] [-text]

La commande rsa traite les clés RSA. Elles peuvent être converties entre différentes formes et leurs composants peuvent être affichés. rsa utilise le format traditionnel compatible SSLeay pour le chiffrement des clés privées : les applications plus récentes devraient utiliser le format PKCS#8 plus sécurisé en utilisant l'utilitaire pkcs8.

Les options sont les suivantes :

-aes128 | -aes192 | -aes256 | -des | -des3
Chiffre la clé privée avec les chiffrements AES, DES ou triple DES, respectivement, avant de la sortir. Une phrase de passe est demandée. Si aucune de ces options n'est spécifiée, la clé est écrite en texte clair. Cela signifie que l'utilisation de l'utilitaire rsa pour lire une clé chiffrée sans option de chiffrement peut être utilisée pour supprimer la phrase de passe d'une clé, ou en définissant les options de chiffrement, elle peut être utilisée pour ajouter ou modifier la phrase de passe. Ces options ne peuvent être utilisées qu'avec les fichiers de sortie au format PEM.
-check
Vérifie la cohérence d'une clé privée RSA.
-in fichier
Le fichier d'entrée à lire, ou l'entrée standard si non spécifié. Si la clé est chiffrée, une phrase de passe sera demandée.
-inform der | net | pem | pvk
Le format d'entrée.
-noout
Ne pas afficher la version codée de la clé.
-modulus
Affiche la valeur du module de la clé.
-out fichier
Le fichier de sortie sur lequel écrire, ou la sortie standard si non spécifié.
-outform der | net | pem | pvk
Le format de sortie.
-passin arg
La source du mot de passe de la clé.
-passout arg
La source du mot de passe du fichier de sortie.
-pubin
Lire une clé publique, pas une clé privée.
-pubout
Sortir une clé publique, pas une clé privée. Automatiquement défini si l'entrée est une clé publique.
-pvk-none | -pvk-strong | -pvk-weak
Activer ou désactiver le codage PVK. La valeur par défaut est -pvk-strong.
-RSAPublicKey_in, -RSAPublicKey_out
Identique à -pubin et -pubout sauf que le format RSAPublicKey est utilisé à la place.
-text
Affiche les composants de la clé publique/privée en texte clair.

RSAUTL

openssl rsautl
[-asn1parse] [-certin] [-decrypt] [-encrypt] [-hexdump] [-in fichier] [-inkey fichier] [-keyform der | pem] [-oaep | -pkcs | -raw | -x931] [-out fichier] [-passin arg] [-pubin] [-rev] [-sign] [-verify]

La commande rsautl peut être utilisée pour signer, vérifier, chiffrer et déchiffrer des données en utilisant l'algorithme RSA.

Les options sont les suivantes :

-asn1parse
Analyse (Asn1parse) les données de sortie ; ceci est utile lorsqu'il est combiné avec l'option -verify.
-certin
L'entrée est un certificat contenant une clé publique RSA.
-decrypt
Déchiffre les données d'entrée en utilisant une clé privée RSA.
-encrypt
Chiffre les données d'entrée en utilisant une clé publique RSA.
-hexdump
Affiche le contenu des données de sortie en format hexadécimal.
-in fichier
Le fichier d'où lire, ou l'entrée standard si non spécifié.
-inkey fichier
Le fichier de clé d'entrée ; par défaut, une clé privée RSA.
-keyform der | pem
Le format de la clé privée. La valeur par défaut est pem.
-oaep | -pkcs | -raw | -x931
Le padding à utiliser : PKCS#1 OAEP, PKCS#1 v1.5 (par défaut), sans padding, ou ANSI X9.31, respectivement. Pour les signatures, seuls -pkcs et -raw peuvent être utilisés.
-out fichier
Le fichier de sortie où écrire, ou la sortie standard si non spécifié.
-passin arg
La source du mot de passe de la clé.
-pubin
Le fichier d'entrée est une clé publique RSA.
-rev
Inverse l'ordre du tampon d'entrée.
-sign
Signe les données d'entrée et affiche le résultat signé. Ceci nécessite une clé privée RSA.
-verify
Vérifie les données d'entrée et affiche les données récupérées.

S_CLIENT

openssl s_client
[-4 | -6] [-alpn protocoles] [-bugs] [-CAfile fichier] [-CApath répertoire] [-cert fichier] [-certform der | pem] [-check_ss_sig] [-cipher liste_de_chiffrements] [-connect hôte[:port]] [-crl_check] [-crl_check_all] [-crlf] [-debug] [-dtls] [-dtls1_2] [-extended_crl] [-groups liste] [-host hôte] [-ign_eof] [-ignore_critical] [-issuer_checks] [-key fichier_clé] [-keyform der | pem] [-keymatexport libellé] [-keymatexportlen longueur] [-legacy_server_connect] [-msg] [-mtu mtu] [-nbio] [-nbio_test] [-no_comp] [-no_ign_eof] [-no_legacy_server_connect] [-no_ticket] [-no_tls1_2] [-no_tls1_3] [-pass arg] [-policy_check] [-port port] [-prexit] [-proxy hôte:port] [-quiet] [-reconnect] [-servername nom] [-serverpref] [-sess_in fichier] [-sess_out fichier] [-showcerts] [-starttls protocole] [-state] [-status] [-timeout] [-tls1_2] [-tls1_3] [-tlsextdebug] [-use_srtp profils] [-verify profondeur] [-verify_return_error] [-x509_strict] [-xmpphost hôte]

La commande s_client implémente un client SSL/TLS générique qui se connecte à un hôte distant en utilisant SSL/TLS.

Si une connexion est établie avec un serveur SSL, toutes les données reçues du serveur sont affichées et toute frappe sera envoyée au serveur. Lorsqu'elle est utilisée de manière interactive (ce qui signifie que ni -quiet ni -ign_eof n'ont été fournis), la session sera renégociée si la ligne commence par un R ; si la ligne commence par un Q ou si la fin du fichier est atteinte, la connexion sera fermée.

Les options sont les suivantes :

-4
Tente les connexions en utilisant uniquement IPv4.
-6
Tente les connexions en utilisant uniquement IPv6.
-alpn protocoles
Active la négociation de protocole au niveau de l'application. protocoles est une liste de noms de protocoles séparés par des virgules que le client doit annoncer supporter.
-bugs
Active diverses solutions de contournement pour des implémentations boguées.
-CAfile fichier
Un fichier contenant les certificats de confiance à utiliser lors de l'authentification du serveur et à utiliser lors de la tentative de construction de la chaîne de certificats du client.
-CApath répertoire
Le répertoire à utiliser pour la vérification des certificats du serveur. Ce répertoire doit être au format "hash" ; voir -verify pour plus d'informations. Ceux-ci sont également utilisés lors de la construction de la chaîne de certificats du client.
-cert fichier
Le certificat à utiliser, si celui-ci est demandé par le serveur. Par défaut, aucun certificat n'est utilisé.
-certform der | pem
Le format du certificat. La valeur par défaut est pem.
-check_ss_sig, -crl_check, -crl_check_all, -extended_crl, -ignore_critical, -issuer_checks, -policy_check, -x509_strict
Définit diverses options de validation de la chaîne de certificats. Voir la commande verify pour plus de détails.
-cipher liste_de_chiffrements
Modifie la liste des chiffrements envoyée par le client. Bien que le serveur détermine quelle suite de chiffrement est utilisée, il devrait prendre le premier chiffrement supporté dans la liste envoyée par le client. Voir la commande ciphers pour plus d'informations.
-connect hôte[:port]
L'hôte et le port auxquels se connecter. S'ils ne sont pas spécifiés, une tentative de connexion à l'hôte local sur le port 4433 est effectuée. Alternativement, la paire hôte et port peut être séparée par un caractère slash (/), ce qui est utile pour les adresses IPv6 numériques.
-crlf
Traduit un saut de ligne du terminal en CR+LF, comme requis par certains serveurs.
-debug
Affiche des informations de débogage détaillées, y compris un dump hexadécimal de tout le trafic.
-dtls
Autorise n'importe quelle version de DTLS.
-dtls1_2
Autorise uniquement DTLS1.2.
-groups liste
Définit les groupes de courbes elliptiques supportés à la liste de groupes séparés par des deux-points liste.
NIDs ou noms tels que documentés dans SSL_CTX_set1_groups_list(3).
-host host
L'hôte auquel se connecter. La valeur par défaut est localhost.
-ign_eof
Empêche la fermeture de la connexion lorsque la fin du fichier est atteinte dans l'entrée.
-key keyfile
La clé privée à utiliser. Si elle n'est pas spécifiée, le fichier de certificat sera utilisé.
-keyform der | pem
Le format de la clé privée. La valeur par défaut est pem.
-keymatexport label
Exporte le matériel de chiffrement en utilisant le label.
-keymatexportlen len
Exporte len octets de matériel de chiffrement (par défaut 20).
-legacy_server_connect, -no_legacy_server_connect
Autorise ou refuse la connexion initiale à des serveurs qui ne prennent pas en charge RI.
-msg
Affiche tous les messages de protocole avec vidage hexadécimal.
-mtu mtu
Définit le MTU de la couche de liaison.
-nbio
Active l'E/S non bloquantes.
-nbio_test
Teste l'E/S non bloquantes.
-no_ign_eof
Ferme la connexion lorsque la fin du fichier est atteinte dans l'entrée. Peut être utilisé pour remplacer le comportement implicite de -ign_eof après -quiet.
-no_tls1_2 | -no_tls1_3
Désactive respectivement l'utilisation de TLS1.2 et 1.3.
-no_ticket
Désactive le support des tickets de session RFC 4507.
-pass arg
Source du mot de passe de la clé privée.
-port port
Le port auquel se connecter. La valeur par défaut est 4433.
-prexit
Affiche les informations de session lorsque le programme se termine. Cela tentera toujours d'afficher les informations même si la connexion échoue. Normalement, les informations ne sont affichées qu'une seule fois si la connexion réussit. Cette option est utile car le chiffrement utilisé peut être renégocié ou la connexion peut échouer parce qu'un certificat client est requis ou est demandé uniquement après une tentative d'accès à une certaine URL. Notez que la sortie produite par cette option n'est pas toujours exacte car une connexion peut ne jamais avoir été établie.
-proxy host:port
Utilise le proxy HTTP à l'hôte et port. La connexion au proxy se fait en clair et l'argument -connect est transmis au proxy. Si non spécifié, localhost est utilisé comme destination finale. Ensuite, la connexion est acheminée via le proxy vers la destination en TLS.
-quiet
Empêche l'affichage des informations de session et de certificat. Cela active implicitement également -ign_eof.
-reconnect
Reconnecte au même serveur 5 fois en utilisant le même ID de session ; cela peut être utilisé pour tester le fonctionnement de la mise en cache de session.
-servername name
Inclut l'extension Server Name Indication (SNI) de TLS dans le message ClientHello, en utilisant le nom du serveur spécifié.
-showcerts
Affiche toute la chaîne de certificats du serveur : normalement, seul le certificat du serveur lui-même est affiché.
-serverpref
Utilise les préférences de chiffrement du serveur.
-sess_in file
Charge la session TLS depuis le fichier. Le client tentera de reprendre une connexion à partir de cette session.
-sess_out file
Exporte la session TLS vers le fichier.
-starttls protocol
Envoie les messages spécifiques au protocole pour passer à TLS pour la communication. protocol est un mot-clé pour le protocole souhaité. Actuellement, les mots-clés supportés sont "ftp", "imap", "smtp", "pop3" et "xmpp".

La commande ts est une application de base client et serveur d'autorité de horodatage (TSA) telle que spécifiée dans la RFC 3161 (Time-Stamp Protocol, TSP). Une TSA peut faire partie d'un déploiement PKI et son rôle est de fournir une preuve à long terme de l'existence de données spécifiques. Voici une brève description du protocole :

  1. Le client TSA calcule une valeur de hachage unidirectionnelle pour un fichier de données et envoie le hachage à la TSA.
  2. La TSA joint la date et l'heure actuelles à la valeur de hachage reçue, les signe et renvoie le jeton d'horodatage au client. En créant ce jeton, la TSA certifie l'existence du fichier de données d'origine au moment de la génération de la réponse.
  3. Le client TSA reçoit le jeton d'horodatage et vérifie sa signature. Il vérifie également si le jeton contient la même valeur de hachage qu'il avait envoyée à la TSA.

Il existe une unité de données de protocole codée en DER définie pour le transport d'une requête d'horodatage vers la TSA et une autre pour l'envoi de la réponse d'horodatage au client. La commande ts a trois fonctions principales : créer une requête d'horodatage basée sur un fichier de données ; créer une réponse d'horodatage basée sur une requête ; et vérifier si une réponse correspond à une requête particulière ou à un fichier de données.

Il n'y a pas encore de support pour l'envoi automatique des requêtes/réponses via HTTP ou TCP, comme suggéré dans la RFC 3161. Les utilisateurs doivent envoyer les requêtes soit par FTP, soit par e-mail.

Le programme verify utilise les mêmes fonctions que la vérification interne SSL et S/MIME, avec une différence cruciale : autant que possible, une tentative est faite pour continuer après une erreur, alors qu'normalement l'opération de vérification s'arrêterait à la première erreur. Cela permet de déterminer tous les problèmes d'une chaîne de certificats.

L'opération de vérification se compose d'un certain nombre d'étapes distinctes. Premièrement, une chaîne de certificats est construite à partir du certificat fourni et se terminant par l'AC racine. C'est une erreur si toute la chaîne ne peut pas être construite. La chaîne est construite en recherchant le certificat de l'émetteur du certificat courant. Si un certificat est trouvé qui est son propre émetteur, il est supposé être l'AC racine.

Tous les certificats dont le nom de sujet correspond au nom de l'émetteur du certificat courant sont soumis à des tests supplémentaires. Les composants pertinents de l'identifiant de clé d'autorité du certificat courant (s'ils sont présents) doivent correspondre à l'identifiant de clé de sujet (s'il est présent) ainsi qu'au numéro de série et d'émetteur du candidat émetteur ; en outre, l'extension keyUsage du candidat émetteur (si présente) doit autoriser la signature de certificat.

La recherche commence par la liste des certificats non fiables et, si aucune correspondance n'est trouvée, les recherches restantes s'effectuent parmi les certificats fiables. L'AC racine est toujours recherchée dans la liste des certificats fiables : si le certificat à vérifier est un certificat racine, une correspondance exacte doit être trouvée dans la liste fiable.

La deuxième opération consiste à vérifier les extensions de chaque certificat non fiable pour la cohérence avec le but spécifié. Si l'option -purpose n'est pas incluse, aucune vérification n'est effectuée. Le certificat fourni ou le certificat "feuille" doit avoir des extensions compatibles avec le but spécifié et tous les autres certificats doivent également être des certificats d'AC valides. Les extensions précises requises sont décrites plus en détail dans la section X509 ci-dessous.

La troisième opération consiste à vérifier les paramètres de confiance de l'AC racine. L'AC racine doit être fiable pour le but spécifié. Un certificat sans paramètres de confiance est considéré comme valide pour tous les buts.

La dernière opération consiste à vérifier la validité de la chaîne de certificats. La période de validité est vérifiée par rapport à l'heure système actuelle et aux dates notBefore et notAfter dans le certificat. Les signatures de certificat sont également vérifiées à ce stade.

Si toutes les opérations se terminent avec succès, le certificat est considéré comme valide. Si une opération échoue, le certificat n'est pas valide. Lorsqu'une opération de vérification échoue, les messages de sortie peuvent être quelque peu cryptiques. La forme générale du message d'erreur est la suivante :

server.pem: /C=AU/ST=Queensland/O=CryptSoft Pty Ltd/CN=Test CA (1024-bit)
error 24 at 1 depth lookup:invalid CA certificate

La première ligne contient le nom du certificat en cours de vérification, suivi du nom du sujet du certificat. La deuxième ligne contient le numéro d'erreur tel que défini par les constantes X509_V_ERR_* dans <openssl/x509_vfy.h>, le message d'erreur associé documenté dans X509_STORE_CTX_get_error(3), et la profondeur. La profondeur est le numéro du certificat en cours de vérification lorsqu'un problème a été détecté, en commençant par zéro pour le certificat en cours de vérification lui-même, puis 1 pour l'AC qui a signé le certificat, et ainsi de suite.

Inverse les champs du DN, comme requis par la RFC 2253. En tant qu'effet secondaire, cela inverse également l'ordre des AVAs multiples.
dump_all
Dump tous les champs. Utilisé avec dump_der, il permet de déterminer sans ambiguïté l'encodage DER de la structure.
dump_der
Tous les champs qui nécessitent un dump hexadécimal sont dumpés en utilisant l'encodage DER du champ. Sinon, seuls les octets de contenu seront affichés. Les deux options utilisent le format #XXXX... de la RFC 2253.
dump_nostr
Dump les types de chaînes non caractère (par exemple OCTET STRING) ; normalement, les types de chaînes non caractère sont affichés comme si chaque octet de contenu représentait un seul caractère.
dump_unknown
Dump tout champ dont l'OID n'est pas reconnu par openssl.
esc_2253
Échappe les caractères "spéciaux" requis par la RFC 2253 dans un champ qui est « ,+"<>; ». De plus, le caractère ‘#’ est échappé au début d'une chaîne et un caractère espace au début ou à la fin d'une chaîne.
esc_ctrl
Échappe les caractères de contrôle. Ce sont ceux dont les valeurs ASCII sont inférieures à 0x20 (espace) et le caractère delete (0x7f). Ils sont échappés en utilisant la notation \XX de la RFC 2253 (où XX sont deux chiffres hexadécimaux représentant la valeur du caractère).
esc_msb
Échappe les caractères avec le bit MSB défini ; c'est-à-dire ceux dont les valeurs ASCII sont supérieures à 127.
multiline
Un format multiligne. Équivalent à esc_ctrl, esc_msb, sep_multiline, space_eq, lname, et align.
no_type
N'essaie pas d'interpréter les caractères multibytes. C'est-à-dire que les octets de contenu sont simplement dumpés comme si un octet représentait chaque caractère. Ceci est utile à des fins de diagnostic mais produit une sortie plutôt étrange.
nofname, sname, lname, oid
Modifie la façon dont le nom du champ est affiché : nofname n'affiche pas le champ du tout ; sname utilise la forme courte du nom (CN pour commonName, par exemple) ; lname utilise la forme longue. oid représente l'OID sous forme numérique et est utile à des fins de diagnostic.
oneline
Un format sur une seule ligne qui est plus lisible que RFC2253. Équivalent à esc_2253, esc_ctrl, esc_msb, utf8, dump_nostr, dump_der, use_quote, sep_comma_plus_space, space_eq, et sname.
RFC2253
Affiche les noms compatibles avec la RFC 2253. Équivalent à esc_2253, esc_ctrl, esc_msb, utf8, dump_nostr, dump_unknown, dump_der, sep_comma_plus, dn_rev, et sname.
sep_comma_plus
a>, sep_comma_plus_space, sep_semi_plus_space, sep_multiline
Détermine les séparateurs de champs : le premier caractère est celui qui sépare les RDN et le second celui qui sépare les AVA multiples (les AVA multiples sont très rares et leur utilisation est déconseillée). Les options se terminant par « space » ajoutent un espace après le séparateur pour le rendre plus lisible. sep_multiline utilise un saut de ligne pour le séparateur RDN et un « + » espacé pour le séparateur AVA, et indente les champs de quatre caractères. Si aucun séparateur de champ n'est spécifié, sep_comma_plus_space est utilisé par défaut.
show_type
Affiche le type de la chaîne de caractères ASN.1. Le type précède le contenu du champ. Par exemple, « BMPSTRING: Bonjour le monde ».
space_eq
Ajoute des espaces autour du caractère « = » qui suit le nom du champ.
use_quote
Échappe certains caractères en entourant la chaîne entière de caractères « " ». Sans cette option, tous les échappements sont faits avec le caractère « \ ».
utf8
Convertit d'abord toutes les chaînes en format UTF8, comme requis par la RFC 2253. Sur un terminal compatible UTF8, l'utilisation de cette option (et l'absence de esc_msb) peut résulter en l'affichage correct des caractères multibytes. Habituellement, les caractères multibytes supérieurs à 0xff sont représentés en utilisant le format \UXXXX pour 16 bits et \WXXXXXXXX pour 32 bits, et toutes les UTF8Strings sont d'abord converties en leur forme de caractère.
-next_serial
Affiche le prochain numéro de série.
-noout
Ne produit pas la version encodée de la requête.
-ocsp_uri
Affiche les adresses des répondants OCSP, le cas échéant.
-ocspid
Affiche les valeurs de hachage OCSP pour le nom du sujet et la clé publique.
-pubkey
Affiche la clé publique.
-serial
Affiche le numéro de série du certificat.
-sigopt nm:v
Transmet des options à l'algorithme de signature lors des opérations de signature ou de certification. Les noms et valeurs de ces options sont spécifiques à l'algorithme.
-startdate
Affiche la date de début du certificat, c'est-à-dire la date notBefore.
-subject
Affiche le nom du sujet.
-subject_hash
Affiche le hachage du nom du sujet du certificat. Ceci est utilisé dans openssl pour former un index permettant de rechercher des certificats dans un répertoire par nom de sujet.
-subject_hash_old
Affiche le hachage du nom du sujet du certificat en utilisant l'ancien algorithme utilisé par les versions de openssl antérieures à 1.0.0.
-text

Un certificat de confiance est un certificat auquel sont attachées plusieurs informations supplémentaires, telles que les utilisations permises et interdites du certificat et un alias. Lorsqu'un certificat est vérifié, au moins un certificat doit être approuvé. Par défaut, un certificat de confiance doit être stocké localement et être une autorité de certification racine. Les options suivantes concernent les paramètres de confiance x509 :

-addreject arg
Ajoute une utilisation interdite. Accepte les mêmes valeurs que l'option -addtrust.
-addtrust arg
Ajoute une utilisation de certificat approuvé. Tout nom d'objet peut être utilisé ici, mais actuellement seuls clientAuth (utilisation client SSL), serverAuth (utilisation serveur SSL) et emailProtection (e-mail S/MIME) sont utilisés.
-alias
Affiche l'alias du certificat.
-clrreject
Supprime toutes les utilisations interdites ou rejetées du certificat.
-clrtrust
Supprime toutes les utilisations permises ou approuvées du certificat.
-purpose
Effectue des tests sur les extensions du certificat. Le même code est utilisé lors de la vérification de certificats non approuvés dans des chaînes, donc cette section est utile si une chaîne est rejetée par le code de vérification.

L'indicateur CA de l'extension basicConstraints est utilisé pour déterminer si le certificat peut être utilisé comme CA. Si l'indicateur CA est vrai, c'est une CA ; si l'indicateur CA est faux, ce n'est pas une CA. Toutes les CA devraient avoir l'indicateur CA défini à vrai.

Si l'extension basicConstraints est absente, alors le certificat est considéré comme une CA possible ; d'autres extensions sont vérifiées conformément à l'utilisation prévue du certificat. Un avertissement est donné dans ce cas car le certificat ne devrait pas vraiment être considéré comme une CA. Cependant, il est autorisé à être une CA pour contourner un logiciel défectueux.

Si le certificat est un certificat V1 (et n'a donc pas d'extensions) et qu'il est auto-signé, il est également supposé être une CA mais un avertissement est à nouveau donné. Ceci est pour contourner le problème des racines Verisign qui sont des certificats auto-signés V1.

Si l'extension keyUsage est présente, alors des restrictions supplémentaires sont faites sur les utilisations du certificat. Un certificat CA doit avoir le bit keyCertSign défini si l'extension keyUsage est présente.

L'extension d'utilisation étendue de la clé impose des restrictions supplémentaires sur les utilisations du certificat. Si cette extension est présente, qu'elle soit critique ou non, la clé ne peut être utilisée que pour les objectifs spécifiés.

Une description complète de chaque test est donnée ci-dessous. Les commentaires sur basicConstraints et keyUsage et les certificats V1 ci-dessus s'appliquent à tous les certificats CA.

Client SSL
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID d'authentification client web. keyUsage doit être absent ou avoir le bit digitalSignature défini. Le type de certificat Netscape doit être absent ou avoir le bit client SSL défini.
Client CA SSL
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID d'authentification client web. Le type de certificat Netscape doit être absent ou avoir le bit CA SSL défini : ceci est utilisé comme solution de contournement si l'extension basicConstraints est absente.
Serveur SSL
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID d'authentification serveur web et/ou l'un des OIDs SGC. keyUsage doit être absent ou avoir le bit digitalSignature défini, le bit keyEncipherment défini, ou les deux bits définis. Le type de certificat Netscape doit être absent ou avoir le bit serveur SSL défini.
Serveur CA SSL
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID d'authentification serveur web et/ou l'un des OIDs SGC. Le type de certificat Netscape doit être absent ou le bit CA SSL doit être défini : ceci est utilisé comme solution de contournement si l'extension basicConstraints est absente.
Serveur SSL Netscape
Pour que les clients SSL Netscape se connectent à un serveur SSL, il doit avoir le bit keyEncipherment défini si l'extension keyUsage est présente. Ce n'est pas toujours valide car certaines suites de chiffrement utilisent la clé pour la signature numérique. Sinon, c'est identique à un serveur SSL normal.
Tests courants pour client S/MIME
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID de protection e-mail. Le type de certificat Netscape doit être absent ou avoir le bit S/MIME défini. Si le bit S/MIME n'est pas défini dans le type de certificat Netscape, alors le bit client SSL est toléré comme alternative mais un avertissement est affiché : ceci est parce que certains certificats Verisign ne définissent pas le bit S/MIME.
Signature S/MIME
En plus des tests courants pour client S/MIME, le bit digitalSignature doit être défini si l'extension keyUsage est présente.
Chiffrement S/MIME
En plus des tests S/MIME courants, le bit keyEncipherment doit être défini si l'extension keyUsage est présente.
CA S/MIME
L'extension d'utilisation étendue de la clé doit être absente ou inclure l'OID de protection e-mail. Le type de certificat Netscape doit être absent ou avoir le bit CA S/MIME défini : ceci est utilisé comme solution de contournement si l'extension basicConstraints est absente.
Signature CRL
L'extension keyUsage doit être absente ou avoir le bit de signature CRL défini.
CA de signature CRL
Les tests CA normaux s'appliquent, sauf que l'extension basicConstraints doit être présente.
-setalias arg
Définit l'alias du certificat, permettant de le référencer par
en utilisant un surnom, tel que "Certificat de Steve".
-trustout
Sortir un certificat de confiance (par défaut si des paramètres de confiance sont modifiés). Un certificat ordinaire ou de confiance peut être entré, mais par défaut un certificat ordinaire est sorti et tous les paramètres de confiance sont ignorés.

L'utilitaire x509 peut être utilisé pour signer des certificats et des requêtes : il peut ainsi se comporter comme une mini-AC. Les options de signature x509 suivantes sont disponibles :

-CA fichier
Le certificat de l'AC à utiliser pour la signature. Lorsque cette option est présente, x509 se comporte comme une mini-AC. Le fichier d'entrée est signé par l'AC en utilisant cette option ; c'est-à-dire que son nom d'émetteur est défini sur le nom du sujet de l'AC et qu'il est signé numériquement à l'aide de la clé privée de l'AC.

Cette option est normalement combinée avec l'option -req. Sans l'option -req, l'entrée est un certificat qui doit être auto-signé.

-CAcreateserial
Crée le fichier de numéro de série de l'AC s'il n'existe pas au lieu de générer une erreur. Le fichier contiendra le numéro de série ‘02’ et le certificat signé aura ‘1’ comme numéro de série.
-CAform der | pem
Le format du fichier du certificat de l'AC. Le défaut est pem.
-CAkey fichier
Définit la clé privée de l'AC pour signer un certificat. Sinon, on suppose que la clé privée de l'AC est présente dans le fichier du certificat de l'AC.
-CAkeyform der | pem
Le format de la clé privée de l'AC. Le défaut est pem.
-CAserial fichier
Utilise le numéro de série dans fichier pour signer un certificat. Le fichier doit contenir une ligne avec un nombre pair de chiffres hexadécimaux contenant le numéro de série à utiliser. Après chaque utilisation, le numéro de série est incrémenté et réécrit dans le fichier.

Le nom de fichier par défaut est le nom de base du fichier du certificat de l'AC avec .srl ajouté. Par exemple, si le fichier du certificat de l'AC s'appelle mycacert.pem, il s'attend à trouver un fichier de numéro de série appelé mycacert.srl.

-checkend arg
Vérifie si le certificat expire dans les prochaines arg secondes. Si c'est le cas, quitte avec la valeur de retour 1 ; sinon, quitte avec la valeur de retour 0.
-clrext
Supprime toutes les extensions d'un certificat. Cette option est utilisée lorsqu'un certificat est créé à partir d'un autre certificat (par exemple avec -signkey ou les options -CA). Normalement, toutes les extensions sont conservées.
-days arg
Le nombre de jours pendant lesquels un certificat doit être valide. Le défaut est de 30 jours.
-extensions section
La section à partir de laquelle ajouter les extensions de certificat. Si cette option n'est pas spécifiée, les extensions doivent soit être contenues dans la section sans nom (par défaut), soit la section par défaut doit contenir une variable appelée "extensions" qui contient la section à utiliser.
-extfile fichier
Fichier contenant les extensions de certificat à utiliser. S'il n'est pas spécifié, aucune extension n'est ajoutée au certificat.
-force_pubkey clé
Définit la clé publique du certificat à la clé publique contenue dans clé.
-keyform der | pem
Le format du fichier de clé utilisé dans les options -force_pubkey et -signkey.
-new
Génère un nouveau certificat en utilisant le sujet donné par -set_subject et signé par -signkey. Si aucune clé publique n'est fournie avec -force_pubkey, le certificat résultant est auto-signé. Cette option ne peut pas être utilisée avec -in ou -req.
-req
Attend une requête de certificat en entrée au lieu d'un certificat. Cette option ne peut pas être utilisée avec -new.
-set_issuer nom
Le nom de l'émetteur à utiliser. nom doit être formaté comme /type0=valeur0/type1=valeur1/type2=... ; les caractères peuvent être échappés par ‘\’ (antislash) ; aucun espace n'est ignoré.
-set_serial n
Le numéro de série à utiliser. Cette option peut être utilisée avec les options -signkey ou -CA. Si elle est utilisée en conjonction avec l'option -CA, le fichier de numéro de série (tel que spécifié par les options -CAserial ou -CAcreateserial) n'est pas utilisé.

Le numéro de série peut être décimal ou hexadécimal (s'il est précédé de ‘0x’). Des numéros de série négatifs peuvent également être spécifiés mais leur utilisation n'est pas recommandée.

-set_subject nom
Le nom du sujet à utiliser. nom doit être formaté comme /type0=valeur0/type1=valeur1/type2=... ; les caractères peuvent être échappés par ‘\’ (antislash) ; aucun espace n'est ignoré.
-signkey fichier
Auto-signe fichier en utilisant la clé privée fournie.

Si le fichier d'entrée est un certificat, il définit le nom de l'émetteur sur le nom du sujet (c'est-à-dire qu'il le rend auto-signé), modifie la clé publique avec la valeur fournie et modifie les dates de début et de fin. La date de début est définie sur l'heure actuelle et la date de fin est définie sur une valeur déterminée par l'option -days. Toutes les extensions de certificat sont conservées sauf si l'option -clrext est fournie.

Si l'entrée est une requête de certificat, un certificat auto-signé est créé en utilisant la clé privée fournie et le nom du sujet dans la requête.

-utf8
Interprète les valeurs des champs lus à partir d'un terminal ou obtenues à partir d'un fichier de configuration comme des chaînes UTF-8. Par défaut, elles sont interprétées comme ASCII.
-x509toreq
Convertit un certificat en une requête de certificat. L'option -signkey est utilisée pour passer la clé privée requise.

Plusieurs commandes partagent une syntaxe commune, comme détaillé ci-dessous.

Les arguments de mot de passe, généralement spécifiés à l'aide de -passin et -passout pour les mots de passe d'entrée et de sortie, permettent d'obtenir les mots de passe à partir d'une variété de sources. Ces deux options prennent un seul argument, décrit ci-dessous. Si aucun argument de mot de passe n'est donné et qu'un mot de passe est requis, alors l'utilisateur est invité à en entrer un : celui-ci sera généralement lu depuis le terminal courant sans affichage.

pass:mot de passe
Le mot de passe réel est mot de passe. Comme le mot de passe est visible par les utilitaires, cette forme ne doit être utilisée que lorsque la sécurité n'est pas importante.
env:var
Obtient le mot de passe à partir de la variable d'environnement var. Comme l'environnement des autres processus est visible, cette option doit être utilisée avec prudence.
file:chemin
La première ligne de chemin est le mot de passe. Si le même argument chemin est fourni à -passin et -passout, alors la première ligne sera utilisée pour le mot de passe d'entrée et la ligne suivante pour le mot de passe de sortie. chemin n'a pas besoin de faire référence à un fichier régulier : il pourrait, par exemple, faire référence à un périphérique ou à un tube nommé.
fd:numéro
Lit le mot de passe à partir du descripteur de fichier numéro. Ceci peut être utilisé pour envoyer les données via un tube, par exemple.
stdin
Lit le mot de passe depuis l'entrée standard.
