libssh2_sftp_write(3)

Paquet: libssh2

Licences: BSD

libssh2_sftp_write(3) libssh2 libssh2_sftp_write(3)

NOM

libssh2_sftp_write - écrire des données SFTP

SYNTAXE

#include <libssh2.h>
#include <libssh2_sftp.h>
ssize_t
libssh2_sftp_write(LIBSSH2_SFTP_HANDLE *handle,
                   const char *buffer,
                   size_t count);

DESCRIPTION

libssh2_sftp_write(3) écrit un bloc de données au serveur SFTP. Cette méthode est modelée d'après la fonction POSIX write() et utilise les mêmes sémantiques d'appel.

handle - handle de fichier SFTP retourné par libssh2_sftp_open_ex(3).

buffer - pointe vers les données à envoyer.

count - Nombre d'octets à écrire depuis 'buffer'. Notez qu'il n'est pas toujours possible d'écrire tous les octets demandés.

libssh2_sftp_handle(3) utilisera autant de données que possible du tampon et les placera dans un seul paquet du protocole SFTP. Cela signifie que pour obtenir des performances maximales lors de l'envoi de fichiers plus volumineux, vous devriez essayer de toujours fournir au moins 32 Ko de données à cette fonction.

ECRITURE ANTICIPEE

Depuis la version 1.2.8 de libssh2, le comportement par défaut de libssh2 est de créer plusieurs petits paquets sortants pour toutes les données que vous passez à cette fonction et elle retournera un nombre positif dès que le premier paquet sera acquitté par le serveur.

Cela a pour effet que parfois plus de données ont été envoyées mais ne sont pas encore acquittées lorsque cette fonction retourne, et lorsque cette fonction est appelée à nouveau pour écrire plus de données, libssh2 constatera immédiatement que les données ont déjà été reçues à distance.

Dans la plupart des situations normales, cela ne devrait pas causer de problèmes, mais il convient de noter que si vous avez déjà appelé libssh2_sftp_write() avec des données et qu'elle retourne un nombre partiel, vous DEVEZ toujours supposer que le reste des données peut avoir été mis en cache, vous devez donc vous assurer de ne pas modifier ces données et de penser que la version de votre prochaine invocation de fonction sera détectée ou utilisée.

La raison de ce comportement étrange est que SFTP ne peut envoyer que 32 Ko de données par paquet et que tous les paquets sont acquittés individuellement. Cela signifie que nous ne pouvons pas utiliser une approche série simple si nous voulons atteindre des performances élevées, même sur des connexions à latence élevée. Et nous le voulons.

VALEUR DE RETOUR

Nombre réel d'octets écrits ou négatif en cas d'échec.

Si elle est utilisée en mode non bloquant, elle retourne LIBSSH2_ERROR_EAGAIN lorsqu'elle devrait sinon bloquer. Bien que LIBSSH2_ERROR_EAGAIN soit un nombre négatif, ce n'est pas vraiment un échec en soi.

Si cette fonction retourne 0 (zéro), cela ne doit pas être considéré comme une erreur, mais plutôt qu'il n'y a pas eu d'erreur mais qu'aucune donnée utile n'a été envoyée à l'autre extrémité.

ERREURS

LIBSSH2_ERROR_ALLOC - Un appel interne d'allocation mémoire a échoué.

LIBSSH2_ERROR_SOCKET_SEND - Impossible d'envoyer des données sur la socket.

LIBSSH2_ERROR_SOCKET_TIMEOUT -

LIBSSH2_ERROR_SFTP_PROTOCOL - Une réponse invalide du protocole SFTP a été reçue sur la socket, ou une opération SFTP a provoqué le retour d'un code d'erreur par le serveur.
