DESCRIPTION

BIO_s_connect() renvoie la méthode BIO de connexion. Il s'agit d'une enveloppe autour des routines de connexion de socket TCP/IP de la plateforme.

En utilisant les BIO de connexion, des connexions TCP/IP peuvent être établies et des données transférées en utilisant uniquement des routines BIO. De cette manière, toutes les opérations spécifiques à la plateforme sont cachées par l'abstraction BIO.

Les opérations de lecture et d'écriture sur un BIO de connexion effectueront des E/S sur la connexion sous-jacente. Si aucune connexion n'est établie et que le port et le nom d'hôte (voir ci-dessous) sont correctement configurés, une connexion est établie en premier.

Les BIO de connexion supportent BIO_puts(3) mais pas BIO_gets(3).

Si l'indicateur de fermeture est défini sur un BIO de connexion, toute connexion active sera arrêtée et le socket fermé lorsque le BIO sera libéré.

Appeler BIO_reset(3) sur un BIO de connexion fermera toute connexion active et réinitialisera le BIO dans un état où il peut se connecter à nouveau au même hôte.

BIO_get_fd(3) place le socket sous-jacent dans c s'il n'est pas NULL et renvoie également le socket. Si c n'est pas NULL, il doit être de type int *.

BIO_set_info_callback(3) et BIO_callback_ctrl(3) avec une commande cmd de BIO_CTRL_SET_CALLBACK sauvegardent le pointeur vers la fonction cb en interne dans b et BIO_get_info_callback(3) récupère ce pointeur de fonction. Si un tel rappel d'informations est installé, il est appelé chaque fois qu'un changement d'état ou une erreur se produit dans la machine d'état du BIO de connexion. Les arguments du rappel incluent le nouveau state en cas de changement d'état ou l'ancien state en cas d'erreur et la valeur res que la machine d'état renverrait à l'opération qui l'a invoquée si aucun rappel d'informations n'avait été installé. Si un rappel d'informations est installé, la machine d'état renvoie la valeur de retour du rappel d'informations à la place. Par conséquent, le rappel d'informations est censé renvoyer généralement res. L'effet précis de la valeur de retour dépend de l'opération à partir de laquelle la machine d'état a été invoquée. Généralement, -1 est utilisé pour indiquer un échec et les valeurs de retour inférieures ou égales à zéro interrompent l'opération en cours, tandis que les valeurs positives indiquent un succès et permettent à l'opération de se poursuivre.

Les constantes de state passées au rappel sont nommées en fonction de l'opération qui doit être effectuée ensuite. Elles sont listées ici dans l'ordre où les états sont traversés :

BIO_CONN_S_BEFORE
Le BIO est inactif et aucune connexion n'a encore été initiée.
BIO_CONN_S_GET_IP
Le nom d'hôte à connecter doit être converti en une adresse IP.
BIO_CONN_S_GET_PORT
Le nom du service à connecter doit être converti en un numéro de port TCP.
BIO_CONN_S_CREATE_SOCKET
Le socket TCP doit être créé avec l'appel système socket(2).
BIO_CONN_S_NBIO
Les options de socket peuvent devoir être définies à l'aide de fcntl(2) et setsockopt(2).
BIO_CONN_S_CONNECT
La connexion doit être initiée avec l'appel système connect(2).
BIO_CONN_S_BLOCKED_CONNECT
L'appel système connect(2) aurait bloqué et doit être réessayé.
BIO_CONN_S_OK
La connexion a été établie et peut maintenant être utilisée pour transférer des données.

BIO_set_conn_hostname() utilise la chaîne name pour définir le nom d'hôte. Le nom d'hôte peut être une adresse IP. Le nom d'hôte peut également inclure le port sous la forme nom_hôte:port. Il est également acceptable d'utiliser les formes nom_hôte/tout/autre/chemin ou nom_hôte:port/tout/autre/chemin.

BIO_set_conn_port() définit le port à port. port est recherché comme un service en utilisant getaddrinfo(3).

BIO_set_conn_ip() définit l'adresse IP à ip en utilisant la forme binaire, c'est-à-dire quatre octets spécifiant l'adresse IP en format big-endian.

BIO_set_conn_int_port() définit le port en utilisant port. port devrait être de type int *.

BIO_get_conn_hostname() renvoie le nom d'hôte du BIO de connexion ou NULL si le BIO est initialisé mais qu'aucun nom d'hôte n'est défini.

BIO_set_conn_hostname()

Définit le nom d'hôte auquel se connecter à nom. La chaîne nom peut également inclure un nom de port séparé par un « : », par exemple « www.example.com:8080 ».

BIO_set_conn_port()

Définit le nom du port auquel se connecter à nom. La chaîne nom peut être un nom de service (par exemple « http ») ou un numéro de port.

BIO_set_conn_ip()

Définit l'adresse IP de destination en forme binaire.

BIO_set_conn_int_port()

Définit le port de destination sous la forme d'un int.

BIO_get_conn_hostname()

Renvoie le nom d'hôte auquel le BIO est configuré pour se connecter. Ce résultat est un pointeur interne qui ne doit pas être modifié.

BIO_get_conn_port()

Renvoie le port sous forme de chaîne de caractères. Ce résultat est un pointeur interne qui ne doit pas être modifié.

BIO_get_conn_ip()

Renvoie l'adresse IP sous forme binaire.

BIO_get_conn_int_port()

Renvoie le port sous la forme d'un int.

BIO_set_nbio()

Définit le drapeau d'E/S sans blocage sur n. Si n est zéro, les E/S bloquantes sont définies. Si n est 1, les E/S sans blocage sont définies. Les E/S bloquantes sont les valeurs par défaut. L'appel à BIO_set_nbio() doit être effectué avant l'établissement de la connexion, car les E/S sans blocage sont définies pendant le processus de connexion.

BIO_new_connect()

Combine BIO_new(3) et BIO_set_conn_hostname() en un seul appel. Il crée un nouveau BIO de connexion avec name.

BIO_do_connect()

Tente de connecter le BIO fourni. Il renvoie 1 si la connexion a été établie avec succès. Une valeur nulle ou négative est renvoyée si la connexion n'a pas pu être établie. L'appel à BIO_should_retry(3) doit être utilisé pour les BIO de connexion sans blocage afin de déterminer si l'appel doit être retenté.

VALEURS DE RETOUR

Si les E/S bloquantes sont définies, une valeur de retour non positive de tout appel d'E/S est causée par une condition d'erreur, bien qu'une valeur de retour nulle signifie normalement que la connexion a été fermée.

Si le nom du port est fourni dans le nom d'hôte, cela remplacera toute valeur définie avec BIO_set_conn_port(). Cela peut être indésirable si l'application ne souhaite pas autoriser la connexion à des ports arbitraires. Cela peut être évité en vérifiant la présence du caractère « : » dans le nom d'hôte passé et soit en signalant une erreur, soit en tronquant la chaîne à ce point.

Les valeurs renvoyées par BIO_get_conn_hostname(), BIO_get_conn_port(), BIO_get_conn_ip(), et BIO_get_conn_int_port() sont mises à jour lorsqu'une tentative de connexion est effectuée. Avant toute tentative de connexion, les valeurs renvoyées sont celles définies par l'application elle-même.

Les applications n'ont pas à appeler BIO_do_connect() mais peuvent souhaiter le faire pour séparer le processus de connexion du traitement d'autres E/S.

Si les E/S sans blocage sont définies, les nouvelles tentatives seront demandées comme approprié.

En plus de BIO_should_read(3) et BIO_should_write(3), il est également possible que BIO_should_io_special(3) soit vraie pendant le processus de connexion initial avec la raison BIO_RR_CONNECT. Si cela est renvoyé, c'est une indication qu'une tentative de connexion bloquerait. L'application doit alors prendre les mesures appropriées pour attendre que le socket sous-jacent se soit connecté et retenter l'appel.

Lorsque des chaînes contenant un BIO de connexion sont copiées avec BIO_dup_chain(3), BIO_set_conn_hostname(), BIO_set_conn_port(), BIO_set_nbio(), et BIO_set_info_callback(3) sont appelés en interne pour copier automatiquement le nom d'hôte, le port, le drapeau d'E/S sans blocage et le rappel d'informations de l'objet BIO d'origine vers le nouveau.

VALEURS DE RETOUR

BIO_s_connect() renvoie la méthode de BIO de connexion.

Lorsqu'elle est appelée sur un objet BIO de connexion, BIO_method_type(3) renvoie la constante BIO_TYPE_CONNECT et BIO_method_name(3) renvoie un pointeur vers la chaîne statique « socket connect ».

BIO_get_fd(3) renvoie le socket ou -1 si le BIO n'a pas été initialisé.

BIO_set_conn_hostname(), BIO_set_conn_port(), BIO_set_conn_ip(), et BIO_set_conn_int_port() renvoient toujours 1.

BIO_get_conn_hostname() renvoie le nom d'hôte connecté ou NULL s'il n'y en a aucun défini.

BIO_get_conn_port() renvoie une chaîne représentant le port connecté ou NULL s'il n'est pas défini.

BIO_get_conn_ip() renvoie un pointeur vers l'adresse IP connectée sous forme binaire ou des zéros si elle n'est pas définie.

BIO_get_conn_int_port() renvoie le port connecté ou 0 si aucun n'était défini.

BIO_set_nbio() renvoie toujours 1.

BIO_do_connect() renvoie 1 si la connexion a été établie avec succès et 0 ou -1 si la connexion a échoué.

EXEMPLES

Cet exemple se connecte à un serveur Web sur l'hôte local et tente de récupérer une page et de copier le résultat sur la sortie standard.

BIO *cbio, *out;
int len;
char tmpbuf[1024];

ERR_load_crypto_strings();
cbio = BIO_new_connect("localhost:http");
out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(cbio) <= 0) {
	fprintf(stderr, "Erreur de connexion au serveur\n");
	ERR_print_errors_fp(stderr);
	/* quoi que ce soit ... */
}
BIO_puts(cbio, "GET / HTTP/1.0\n\n");
for(;;) {
	len = BIO_read(cbio, tmpbuf, 1024);
	if (len <= 0)
		break;
	BIO_write(out, tmpbuf, len);
}
BIO_free(cbio);
BIO_free(out);
