DESCRIPTION

CMS_get0_RecipientInfos() renvoie toutes les structures RecipientInfo associées à la structure EnvelopedData cms.

CMS_RecipientInfo_type() renvoie le type de ri :

CMS_RECIPINFO_TRANS pour KeyTransRecipientInfo,
CMS_RECIPINFO_AGREE pour KeyAgreeRecipientInfo,
CMS_RECIPINFO_KEK pour KEKRecipientInfo,
CMS_RECIPINFO_PASS pour PasswordRecipientinfo, ou
CMS_RECIPINFO_OTHER pour OtherRecipientInfo.

CMS_RecipientInfo_ktri_get0_signer_id() récupère l'identifiant de certificat RecipientIdentifier associé à la structure KeyTransRecipientInfo ri. Soit SubjectKeyIdentifier sera défini dans keyid, soit le nom de l'émetteur et le numéro de série dans issuer et sno.

CMS_RecipientInfo_ktri_cert_cmp() compare le certificate avec la structure KeyTransRecipientInfo ri.

CMS_RecipientInfo_set0_pkey() associe la clé privée pkey à la structure KeyTransRecipientInfo ri.

CMS_RecipientInfo_kekri_get0_id() récupère les informations de clé de la structure KEKRecipientInfo ri. Les champs sont copiés comme suit :

keyEncryptionAlgorithm vers *palg,
keyIdentifier vers *pid,
date vers *pdate (facultatif),
other.keyAttrId vers *potherid (facultatif),
other.keyAttr vers *pothertype (facultatif).
Quand un champ est facultatif et absent, NULL est écrit au paramètre correspondant. Les paramètres qui n'intéressent pas l'application peuvent être mis à NULL.

CMS_RecipientInfo_kekri_id_cmp() compare l'identifiant dans les paramètres id et idlen avec le champ keyIdentifier de la structure KEKRecipientInfo ri.

CMS_RecipientInfo_set0_key() associe la clé symétrique key de longueur keylen à la structure KEKRecipientInfo ri.

CMS_RecipientInfo_decrypt() tente de déchiffrer la structure RecipientInfo ri dans cms. Une clé doit avoir été associée à ri au préalable.

CMS_RecipientInfo_encrypt() tente de chiffrer la structure RecipientInfo ri dans cms. Une clé doit avoir été associée à ri au préalable et la clé de chiffrement du contenu doit être disponible, par exemple suite à un appel précédent à CMS_RecipientInfo_decrypt().

Le but principal de ces fonctions est de permettre à une application de rechercher des clés de destinataire en utilisant n'importe quelle technique appropriée lorsque la méthode plus simple de CMS_decrypt(3) n'est pas appropriée.

Dans une utilisation typique, une application récupère toutes les structures CMS_RecipientInfo en utilisant CMS_get0_Recipien

int CMS_RecipientInfo_ktri_get0_signer_id(CMS_RecipientInfo *ri, ASN1_TYPE **keyid);

int CMS_RecipientInfo_set0_pkey(CMS_RecipientInfo *ri, EVP_PKEY *pkey);

int CMS_RecipientInfo_ktri_cert_cmp(CMS_RecipientInfo *ri, X509 *cert);

int CMS_RecipientInfo_kekri_get0_id(CMS_RecipientInfo *ri, ASN1_OCTET_STRING **keyid);

int CMS_RecipientInfo_set0_key(CMS_RecipientInfo *ri, unsigned char *key, size_t len);

int CMS_RecipientInfo_kekri_id_cmp(CMS_RecipientInfo *ri, const ASN1_OCTET_STRING *id);

int CMS_RecipientInfo_decrypt(CMS_RecipientInfo *ri, EVP_PKEY *pkey, OSSL_LIB_CTX *libctx, unsigned int flags);

int CMS_RecipientInfo_encrypt(CMS_RecipientInfo *ri, unsigned int flags);

DESCRIPTION

The CMS_get0_RecipientInfos() function retrieves all recipient information structures from the CMS_ContentInfo structure cms. The returned value is an internal pointer. Do not free it.

The type of a CMS_RecipientInfo structure ri is returned by CMS_RecipientInfo_type(). It can be one of CMS_RECIPIENTINFO_KEYTRANS, CMS_RECIPIENTINFO_KEYAGREE, CMS_RECIPIENTINFO_KEK, CMS_RECIPIENTINFO_PASSWD, or CMS_RECIPIENTINFO_OTHER.

The function CMS_RecipientInfo_ktri_get0_signer_id() retrieves the issuer and serial number of the certificate used for recipient key transport. This is only valid for CMS_RECIPIENTINFO_KEYTRANS recipient types. The identifier is returned in keyid.

The function CMS_RecipientInfo_set0_pkey() associates the private key pkey with the recipient information structure ri. This takes ownership of pkey.

The function CMS_RecipientInfo_ktri_cert_cmp() compares the recipient information structure ri with the certificate cert. It returns 0 if they match, non-zero otherwise.

The function CMS_RecipientInfo_kekri_get0_id() retrieves the key identifier of the Key Encryption Key (KEK) used for recipient key encryption. This is only valid for CMS_RECIPIENTINFO_KEK recipient types. The identifier is returned in keyid.

The function CMS_RecipientInfo_set0_key() associates the secret key key of length len with the recipient information structure ri. This takes ownership of the key data.

The function CMS_RecipientInfo_kekri_id_cmp() compares the recipient information structure ri with the key identifier id. It returns 0 if they match, non-zero otherwise.

The function CMS_RecipientInfo_decrypt() decrypts the encrypted content-encryption key within the recipient info structure ri. The private key pkey must be provided for key transport or key agreement recipient info types. For other types, pkey can be NULL. The libctx and flags are passed to the underlying cryptographic algorithm.

If successful, the decrypted content-encryption key can be retrieved using CMS_get0_recipient_key(). If this key is then associated with the CMS_ContentInfo structure, for example using CMS_decrypt(3), the enveloped content can be decrypted.

An application can iterate through all recipient information structures using

    CMS_ContentInfo_new(3)()
    and checks the type of each using
    CMS_RecipientInfo_type(). Depending on the type, the
    CMS_RecipientInfo structure can be ignored or its key
    identifier data retrieved using an appropriate function. If the
    corresponding secret or private key can be obtained by any appropriate
    means, it can then be associated with the structure and
    CMS_RecipientInfo_decrypt() called. If successful,
    CMS_decrypt(3) can be called
    with a NULL key to decrypt the enveloped
  content.

The function CMS_RecipientInfo_encrypt() can be used to add a new recipient to an existing enveloped data structure. Typically an application will first decrypt an appropriate CMS_RecipientInfo structure to make the content encrypt key available. It will then add a new recipient using a function such as CMS_add1_recipient_cert(3) and finally encrypt the content encryption key using CMS_RecipientInfo_encrypt().

RETURN VALUES

CMS_get0_RecipientInfos() returns an internal pointer to all the CMS_RecipientInfo structures, or NULL if an error occurs.

CMS_RecipientInfo_type() returns an integer constant.

CMS_RecipientInfo_ktri_get0_signer_id(), CMS_RecipientInfo_set0_pkey(), CMS_RecipientInfo_kekri_get0_id(), CMS_RecipientInfo_set0_key(), CMS_RecipientInfo_decrypt(), and CMS_RecipientInfo_encrypt() return 1 for success or 0 if an error occurs.

CMS_RecipientInfo_ktri_cert_cmp() and CMS_RecipientInfo_kekri_id_cmp() return 0 when ri matches or non-zero otherwise.

Any error can be obtained from ERR_get_error(3).
