LIBPIPELINE(3) Manuel des fonctions de bibliothèque LIBPIPELINE(3)

NOM

libpipeline — bibliothèque de manipulation de pipelines

SYNOPIS

#include <pipeline.h>

DESCRIPTION

libpipeline est une bibliothèque C permettant de configurer et d'exécuter des pipelines de processus, sans avoir besoin d'impliquer l'analyse des lignes de commande du shell, souvent sujette aux erreurs et dangereuse. Cela dispense les programmeurs d'avoir à construire laborieusement des pipelines à l'aide de primitives de plus bas niveau telles que fork et execve.

La manière générale d'utiliser libpipeline implique la construction d'une structure pipeline et l'ajout d'une ou plusieurs structures pipecmd à celle-ci. Une pipecmd représente un sous-processus (ou “commande”), tandis qu'une pipeline représente une séquence de sous-processus dont la sortie de chacun est connectée à l'entrée du suivant, comme dans l'exemple ls | grep pattern | less. Le programme appelant peut ajuster certaines propriétés de chaque commande indépendamment, telles que son environnement et sa priorité nice(3), ainsi que les propriétés du pipeline entier, telles que son entrée et sa sortie, et la manière dont les signaux sont gérés pendant son exécution. Le programme appelant peut ensuite démarrer le pipeline, lire sa sortie, attendre son achèvement et récupérer son code de sortie.

Les chaînes de caractères passées comme arguments de fonction const char * seront copiées par la bibliothèque.

void pipeline_connect(pipeline *source, pipeline *sink, ...)

Connecte l'entrée d'un ou plusieurs pipelines récepteurs à la sortie d'un pipeline source. Le pipeline source peut être démarré, mais dans ce cas pipeline_want_out() doit avoir été appelé avec un fd négatif ; sinon, appelle pipeline_want_out(source, -1). Dans tous les cas, appelle pipeline_want_in(sink, -1) sur tous les récepteurs, dont aucun ne doit être démarré. Terminez les arguments avec nullptr (avant C23 : (void *) 0).

Il s'agit d'une connexion au niveau de l'application ; les données peuvent être interceptées entre les pipelines par le programme avant d'appeler pipeline_pump(), qui met en flux les données du source vers les récepteurs. C'est principalement utile lorsque plus d'un pipeline récepteur est impliqué, auquel cas les pipelines ne peuvent pas simplement être concaténés en un seul.

Le résultat est similaire à tee(1), sauf que la sortie peut être envoyée à plus de deux endroits et peut facilement être envoyée à plusieurs processus.

Définit les descripteurs de fichiers à utiliser comme entrée et sortie du pipeline entier. Si non négatif, fd est utilisé directement comme descripteur de fichier. Fonctions pour exécuter les pipelines et gérer les signaux

typedef void pipeline_post_fork_fn (void);
 
void pipeline_install_post_fork(pipeline_post_fork_fn *fn)

Installe un gestionnaire post-fork. Celui-ci sera exécuté dans tout processus enfant immédiatement après sa création. Par exemple, il peut être utilisé pour nettoyer les gestionnaires de signaux spécifiques à l'application. Passez NULL pour supprimer tout gestionnaire post-fork existant.

Voir pipecmd_pre_exec pour une installation similaire limitée à une seule commande plutôt qu'globale au processus appelant.

void pipeline_start(pipeline *p)

Démarre les processus d'un pipeline. Installe le gestionnaire SIGCHLD de cette bibliothèque s'il n'est pas déjà installé. Appelle error (FATAL) en cas d'erreur.

Les descripteurs de fichiers standard (0, 1 et 2) doivent être ouverts avant d'appeler cette fonction.

int pipeline_wait_all(pipeline *p, int **statuses, int *n_statuses)

Attend qu'un pipeline se termine. Définit *statuses à un tableau nouvellement alloué de statuts d'attente, tels que retournés par waitpid(2), et *n_statuses à la longueur de ce tableau. La valeur de retour est similaire au statut de sortie qu'un shell retournerait, avec quelques modifications. Si la dernière commande se termine avec un signal (autre que SIGPIPE, qui est considéré comme équivalent à une sortie zéro), alors la valeur de retour est 128 plus le numéro du signal ; si la dernière commande se termine normalement mais avec une valeur non nulle, alors la valeur de retour est son statut de sortie ; si une autre commande se termine avec une valeur non nulle, alors la valeur de retour est 127 ; sinon, une erreur.

autrement, la valeur de retour est 0. Cela signifie que la valeur de retour n'est 0 que si toutes les commandes du pipeline se terminent avec succès.

int pipeline_wait(pipeline *p)

Attend qu'un pipeline se termine et renvoie son statut de sortie combiné, calculé comme pour pipeline_wait_all().

int pipeline_run(pipeline *p)

Démarre un pipeline, attend qu'il se termine et le libère, le tout en une seule opération.

void pipeline_pump(pipeline *p, ...)

Transfère les données entre un ou plusieurs pipelines connectés à l'aide de pipeline_connect() jusqu'à ce que tous les pipelines sources aient atteint la fin de fichier et que toutes les données aient été écrites dans tous les récepteurs (ou échoué). Tous les pipelines pertinents doivent être fournis : c'est-à-dire qu'aucun pipeline connecté à un pipeline source ne peut être fourni, sauf si ce pipeline source est également fourni. Démarre automatiquement tous les pipelines s'ils ne sont pas déjà démarrés, mais n'attend pas leur achèvement. Terminez les arguments avec nullptr (avant C23 : (void *) 0).

Fonctions pour lire la sortie des pipelines

En général, la sortie est retournée sous forme de pointeur vers un tampon appartenant au pipeline, qui est automatiquement libéré lorsque pipeline_free() est appelé. Cela évite à l'appelant d'avoir à libérer explicitement des blocs individuels de données de sortie.

const char *pipeline_read(pipeline *p, size_t *len)

Lit len octets de données à partir du pipeline, en renvoyant le bloc de données. len est mis à jour avec le nombre d'octets lus.

const char *pipeline_peek(pipeline *p, size_t *len)

Regarde à l'avance dans la sortie du pipeline pour len octets de données, en renvoyant le bloc de données. len est mis à jour avec le nombre d'octets lus. La position de départ de la prochaine lecture ou consultation n'est pas affectée par cet appel.

size_t pipeline_peek_size(pipeline *p)

Retourne le nombre d'octets de données qui peuvent être lus à l'aide de pipeline_read() ou pipeline_peek() uniquement à partir du cache de consultation, sans avoir à lire le pipeline lui-même (et donc potentiellement à bloquer).

void pipeline_peek_skip(pipeline *p, size_t len)

Ignore et écarte len octets de données du cache de consultation. Vérifie que suffisamment de données sont disponibles pour être ignorées, vous pourriez donc vouloir vérifier à l'aide de pipeline_peek_size() au préalable.

const char *pipeline_readline(pipeline *p)

Lit une ligne de données à partir du pipeline et la renvoie.

const char *pipeline_peekline(pipeline *p)

Regarde à l'avance dans la sortie du pipeline pour une ligne de données et la renvoie. La position de départ de la prochaine lecture ou consultation n'est pas affectée par cet appel.

Gestion des signaux

libpipeline installe un gestionnaire de signaux pour SIGCHLD, et collecte le statut de sortie des processus enfants dans pipeline_wait(). Les applications utilisant cette bibliothèque doivent soit s'abstenir de modifier la disposition de SIGCHLD (en d'autres termes, doivent s'appuyer sur libpipeline pour toute gestion de processus enfant), soit s'assurer de restaurer le gestionnaire SIGCHLD de libpipeline avant d'appeler l'une de ses fonctions.

Si l'indicateur ignore_signals est défini dans un pipeline (ce qui est le cas par défaut), alors les signaux SIGINT et SIGQUIT seront ignorés dans le processus parent pendant que les processus enfants s'exécutent. Ceci reflète le comportement de system(3).

libpipeline laisse les processus enfants avec la disposition par défaut de SIGPIPE, à savoir la terminaison du processus. Il ignore SIGPIPE dans le processus parent lors de l'exécution de pipeline_pump().

Récupération des processus enfants

libpipeline installe un gestionnaire SIGCHLD qui tentera de récupérer les processus enfants qui se sont terminés. Cela appelle waitpid(2) avec -1, il récupérera donc tout processus enfant, pas seulement ceux créés via cette bibliothèque. Actuellement, cela signifie que si le programme appelant crée d'autres processus enfants qui peuvent se terminer pendant qu'un pipeline est en cours d'exécution, le programme n'est pas garanti de pouvoir collecter les statuts de sortie de ces processus.

Vous ne devriez pas vous fier à ce comportement, et à l'avenir, il pourrait être modifié pour ne récupérer que les processus enfants créés par cette bibliothèque ou pour fournir un moyen de retourner les statuts étrangers à l'application. Veuillez contacter l'auteur si vous avez une application exemple et souhaitez aider à concevoir une telle interface.

ENVIRONNEMENT

Si la variable d'environnement PIPELINE_DEBUG est définie sur “1”, alors libpipeline émettra des messages de débogage sur la sortie d'erreur standard.

Si la variable d'environnement PIPELINE_QUIET est définie sur n'importe quelle valeur, alors libpipeline s'abstiendra d'imprimer un message d'erreur lorsqu'un sous-processus est terminé par un signal. Ajouté dans libpipeline 1.4.0.

EXEMPLES

Dans les exemples suivants, les noms de fonctions commençant par pipecmd_ ou pipeline_ sont de vraies fonctions de libpipeline, tandis que tous les autres noms de fonctions sont du pseudo-code. Ces exemples utilisent la syntaxe C23 de la mot-clé nullptr pour terminer les listes d'arguments variables ; sur les versions antérieures de C, utilisez (void *) 0 à la place.

Le cas le plus simple est simple. Pour exécuter une seule commande, telle que mv source dest:

pipeline *p = pipeline_new_command_args ("mv", source, dest, nullptr);
int status = pipeline_run (p);

libpipeline est souvent utilisé pour imiter les pipelines shell, comme dans l'exemple suivant :

zsoelim < input-file | tbl | nroff -mandoc -Tutf8

Le code pour construire cela serait :

pipeline *p;
int status;

p = pipeline_new ();
pipeline_want_infile (p, "input-file");
pipeline_command_args (p, "zsoelim", nullptr);
pipeline_command_args (p, "tbl", nullptr);
pipeline_command_args (p, "nroff", "-mandoc", "-Tutf8", nullptr);
status = pipeline_run (p);

Vous pourriez vouloir construire une commande plus dynamiquement :

pipecmd *manconv = pipecmd_new_args ("manconv", "-f", from_code,
                                     "-t", "UTF-8", nullptr);
if (quiet)
        pipecmd_arg (manconv, "-q");
pipeline_command (p, manconv);

Peut-être avez-vous besoin de définir une variable d'environnement uniquement pendant l'exécution d'une commande spécifique :

pipecmd *less = pipecmd_new ("less");
pipecmd_setenv (less, "LESSCHARSET", lesscharset);

Vous pourriez vous trouver dans la nécessité de passer la sortie d'un pipeline à plusieurs autres pipelines, dans un arrangement de type "tee" :

pipeline *source, *sink1, *sink2;

source = make_source ();
sink1 = make_sink1 ();
sink2 = make_sink2 ();
pipeline_connect (source, sink1, sink2, nullptr);
/* Transfère les données entre ces pipelines jusqu'à ce qu'il n'y ait plus rien. */
pipeline_pump (source, sink1, sink2, nullptr);
pipeline_free (sink2);
pipeline_free (sink1);
pipeline_free (source);

Peut-être que l'une de vos commandes est en fait une fonction dans le processus, plutôt qu'un programme externe :

pipecmd *inproc = pipecmd_new_function ("in-process", &func,
                                        NULL, NULL);
pipeline_command (p, inproc);

Parfois, votre programme doit consommer la sortie d'un pipeline, plutôt que de l'envoyer à un autre sous-processus :

pipeline *p = make_pipeline ();
const char *line;

pipeline_want_out (p, -1);

pipeline_read.3.en — libpipeline

NAME

pipeline_read, pipeline_peekline, pipeline_readline, pipeline_read_all — read output from a pipeline

LIBRARY

libpipeline — pipeline manipulation library

SYNOPSIS

#include <pipeline.h>

char *
pipeline_read(Pipeline *p);

char *
pipeline_peekline(Pipeline *p);

char *
pipeline_readline(Pipeline *p);

char *
pipeline_read_all(Pipeline *p);

DESCRIPTION

pipeline_read reads the entire output of the pipeline p and returns it as a single string. The string is terminated by a null byte. Newlines within the output are preserved. Note that this function is not suitable for reading large amounts of data, as it will allocate memory for the entire output of the pipeline.

pipeline_peekline returns the next line of output from the pipeline p without consuming it. Subsequent calls to pipeline_read, pipeline_readline, or pipeline_read_all will return the same line. If no lines are available, it returns NULL. If the pipeline is closed or encounters an error, it also returns NULL.

pipeline_readline reads and returns the next line of output from the pipeline p. The returned string does not include the trailing newline character. If no lines are available, it returns NULL. If the pipeline is closed or encounters an error, it also returns NULL.

pipeline_read_all is similar to pipeline_read, but it reads the output line by line and concatenates the lines into a single string. This can be more efficient for large amounts of output than pipeline_read, as it avoids allocating memory for the entire output at once.

All these functions return a pointer to a dynamically allocated string containing the output. The caller is responsible for freeing this memory using free() when it is no longer needed.

ENVIRONMENT

The behavior of these functions may be affected by the LANG, LC_ALL, and LC_CTYPE environment variables.

EXAMPLES

Pipeline *p;
char *line;

p = pipeline_open("ls -l", 0);
if (p == NULL) {
        perror("pipeline_open");
        exit(EXIT_FAILURE);
}

if (!pipeline_peekline(p)) {
        printf("No output from ls -l\n");
}

while (line = pipeline_readline(p)) {
        printf("  %s\n", line);
        free(line);
}

if (pipeline_error(p) != 0) {
        fprintf(stderr, "Error reading from pipeline: %s\n", pipeline_error_string(p));
}

pipeline_close(p);

The following example demonstrates reading the entire output of a pipeline into a single string:

Pipeline *p;
char *output;

p = pipeline_open("echo -e 'line1\\nline2'", 0);
if (p == NULL) {
        perror("pipeline_open");
        exit(EXIT_FAILURE);
}

output = pipeline_read_all(p);
if (output == NULL) {
        perror("pipeline_read_all");
        exit(EXIT_FAILURE);
}

printf("Pipeline output:\n%s\n", output);
free(output);
pipeline_close(p);

If the pipeline's output is known to be Unicode and starts with a UTF-8 coding declaration, the following code snippet will print the lines prefixed with "Unicode text follows:":

Pipeline *p;
char *line;

p = pipeline_open("cat utf8_file.txt", 0);
if (!p) {
    perror("pipeline_open");
    exit(EXIT_FAILURE);
}
line = pipeline_peekline (p);
if (!strstr (line, "coding: UTF-8"))
        printf ("Unicode text follows:");
while (line = pipeline_readline (p))
        printf ("  %s", line);
pipeline_free (p);
