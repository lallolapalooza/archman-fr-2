lirc-config-tool(1) Manuel des commandes générales lirc-config-tool(1)

NOM

lirc-config-tool - outil pour scanner et générer des fichiers de configuration lirc

SYNTAXE

lirc-config-tool -s|-u [ -c FICHIER]

lirc-config-tool [-o DIR] [-d] [-c FICHIER] [FICHIERS]

lirc-config-tool -l

OPTIONS

Sans options, génère tous les fichiers lircrc spécifiques aux applications disponibles dans ~/.config/lirc. Les [fichiers] optionnels sont une liste de fichiers à construire ou à extraire, tels qu'énumérés par -l.

-s
Scanne le fichier lircd pour des symboles de touches dupliqués ou non présents dans l'espace de noms.
-u
Met à jour le fichier lircd existant pour utiliser des symboles de touches dans l'espace de noms.
-l
Liste les fichiers disponibles à générer.
-d
Extrait les modèles de fichiers utilisables comme entrée standard sur la sortie standard.
-o <dir>
Répertoire de sortie, par défaut ~/.config/lirc
-c <nom_fichier_lircd>
Fichier de configuration de lircd(8), par défaut /etc/lirc/lircd.conf
-h
Affiche le message d'aide

DESCRIPTION

Le script est conçu pour aider à la configuration des fichiers de configuration de lirc(8) pour les télécommandes ordinaires. Il ne vise pas à gérer les claviers complets ou les périphériques de joystick. Les fichiers lircrc générés représentent un point de départ qui nécessitera des ajustements manuels supplémentaires, mais qui pourrait "fonctionner" de manière basique dans de nombreux cas.

La configuration implique la normalisation de lircd.conf pour utiliser des symboles dans l'espace de noms légal, et la création de fichiers lircrc spécifiques aux applications qui utilisent les symboles normalisés.

Pour aider à normaliser /etc/lircd.conf, le script peut signaler les symboles utilisés qui ne sont pas dans l'espace de noms. Il peut également mettre à jour plusieurs de ces symboles pour correspondre à des symboles dans l'espace de noms.

Le script peut également créer des fichiers lircrc spécifiques aux applications tels que mythtv.lircrc ou vlc.lircrc. Il utilise ensuite les symboles de touches normalisés dans /etc/lirdc.conf. Par défaut, les fichiers sont créés dans ~/.config/lirc.

Les fichiers lircrc générés combinent essentiellement les touches connues de /etc/lirc/lircd.conf avec des données modèles pour une application. Le processus aboutit à un fichier lircrc, une liste de touches inutilisées et quelques entrées qui ne correspondent à aucune touche existante. Les touches inutilisées et les entrées non correspondantes sont écrites sous forme de commentaires dans le fichier généré.

Une touche "illégale", c'est-à-dire une touche qui n'est pas dans l'espace de noms, ne correspondra à aucune entrée et sera donc toujours inutilisée. Cependant, il est tout à fait possible de l'utiliser plus tard en modifiant manuellement les fichiers lircrc.

Lors de la mise à jour des fichiers, le script crée toujours des copies de sauvegarde.

Les fichiers lircrc générés sont destinés à être inclus dans un fichier principal ~/.config/lircrc. Un fichier minimal pourrait ressembler à ceci :


include ~/.config/lirc/mythtv.lircrc

EXEMPLES

Analyser /etc/lirc/lircd.conf pour les symboles dupliqués et les symboles qui ne sont pas dans l'espace de noms :

lirc-config-tool -s

Mettre à jour un fichier lircd.conf local pour utiliser les symboles dans l'espace de noms :

lirc-config-tool -uc ./lircd.conf

Lister les fichiers disponibles à générer :

lirc-config-tool -l

Générer l'un des fichiers listés par -l, crée ~/.config/lirc/mythtv.lircrc :

lirc-config-tool mythtv

Extraire les données modèles pour mythtv :

lirc-config-tool -d mythtv >mythtv.lircdata

Utiliser les données éventuellement modifiées pour créer un fichier mythtv.lircrc modifié dans le répertoire courant :

lirc-config-tool -o . stdin < mythtv.lircdata

CONVERSIONS LIRCD.CONF

L'option -s signale simplement tous les symboles de touches qui ne sont pas dans l'espace de noms. Elle signale également certains symboles qui, bien que légaux, sont inappropriés dans ce contexte, notamment KEY_NUMERIC_0..KEY_NUMERIC_9. S'ils sont présents, les touches dupliquées sont également signalées.

L'option -u convertit plusieurs symboles connus en leurs symboles KEY_* correspondants. Les symboles dont les noms sont comme KEY_WINDOWS mais qui ne sont pas dans l'espace de noms reçoivent un préfixe X_, par exemple KEY_WINDOWS -> X_KEY_WINDOWS. Le fichier converti garantit ainsi que tout symbole de touche commençant par KEY_ est un symbole légal.

Toutes les touches numériques connues telles que '1', 'KEY_1', 'KEY_KP_1', 'KEY_NUMERIC_1 sont converties en KEY_1.

Toutes les modifications sont marquées par des commentaires dans le fichier.

EXTENSION

Le script peut être étendu pour supporter plus d'applications en fournissant une fonction shell nommée *.lircdata. Par exemple, pour ajouter une nouvelle application nommée "my_app" basée sur l'application vlc intégrée :


$ lirc-config-tool -d vlc >my_app.lircdata
$ function my_app_lircdata()
> {
> cat my_app.lircdata
> }
$ export -f my_app_lircdata
$ lirc-config-tool my_app

FORMAT DONNÉES

Le script utilise un format simple, orienté ligne, pour représenter les fichiers lircrc. Le but du format est d'être compact et donc de donner un bon aperçu, ainsi que d'être facile à analyser. Chaque ligne est divisée en jetons séparés par des virgules. Il existe quatre types de lignes.

Les lignes de commentaires commencent par un '#'. Elles sont copiées telles quelles dans le fichier de sortie.

La première ligne de données représente les éléments globaux, applicables à toutes les entrées. Le premier mot est le nom du programme. Il est utilisé dans la première ligne 'program='. Les mots suivants, s'ils sont présents, sont des lignes optionnelles qui seront ajoutées à chaque entrée du fichier.

Une ligne de données commençant par 'begin' ou 'end' est un descripteur de bloc de mode. Il est copié tel quel dans le fichier de sortie.

Toutes les autres lignes de données représentent une entrée de bouton/configuration. Le format est
<bouton> <configuration> [supplémentaire]...
La valeur du bouton est utilisée dans la ligne button = et l'élément de configuration est utilisé dans la ligne config =. Les deux sont obligatoires. Les éléments suivants, s'il y en a, sont copiés comme lignes littérales dans l'entrée.

Un exemple peu probable : Le format de données


monprog, flags = quitter
begin volume_mode
KEY_VOLUMEUP, volume-up, delay=4, repeat=1
KEY_VOLUMEDOWN, volume-down
end volume_mode

se traduit par :


begin volume_mode
begin
program = monprog
button = KEY_VOLUME_UP
config = volume-up
delay = 4
repeat = 1
flags = quitter
end
begin
program = monprog
button = KEY_VOLUME_DOWN
config = volume-down
flags = quitter
end
end volume_mode
