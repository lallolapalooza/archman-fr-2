SSL_SET_CONNECT_STATE(3) Manuel des fonctions de bibliothèque SSL_SET_CONNECT_STATE(3)

NOM

SSL_set_connect_state, SSL_set_accept_state, SSL_is_server — prépare un objet SSL à fonctionner en mode client ou serveur

SYNTAXE

bibliothèque «libssl» libcrypto
#include <openssl/ssl.h>

void
SSL_set_connect_state(SSL *ssl);

void
SSL_set_accept_state(SSL *ssl);

int
SSL_is_server(const SSL *ssl);

DESCRIPTION

SSL_set_connect_state() configure ssl pour fonctionner en mode client.

SSL_set_accept_state() configure ssl pour fonctionner en mode serveur.

SSL_is_server() vérifie si ssl est configuré en mode serveur.

Lorsque l'objet SSL_CTX a été créé avec SSL_CTX_new(3), il s'est vu attribuer une méthode client dédiée, une méthode serveur dédiée, ou une méthode générique pouvant être utilisée pour les connexions client et serveur. (La méthode a pu être modifiée avec SSL_CTX_set_ssl_version(3) ou SSL_set_ssl_method(3).)

Au début d'une nouvelle négociation (handshake), le moteur SSL doit savoir s'il doit appeler les routines de connexion (client) ou d'acceptation (serveur). Même si la méthode choisie peut indiquer si le mode client ou serveur a été demandé, les routines de négociation doivent être explicitement définies.

Lorsque l'on utilise les routines SSL_connect(3) ou SSL_accept(3), les routines de négociation correctes sont automatiquement définies. Lors de l'exécution d'une négociation transparente à l'aide de SSL_write(3) ou SSL_read(3), les routines de négociation doivent être explicitement définies au préalable en utilisant soit SSL_set_connect_state() soit SSL_set_accept_state().

Si SSL_is_server() est appelée avant que SSL_set_connect_state() ou SSL_set_accept_state() n'ait été appelée, soit automatiquement soit explicitement, le résultat dépend de la méthode utilisée lors de la création de SSL_CTX. Si une méthode générique ou une méthode serveur dédiée a été passée à SSL_CTX_new(3), SSL_is_server() retourne 1 ; sinon, elle retourne 0.

VALEURS DE RETOUR

SSL_is_server() retourne 1 si ssl est configuré en mode serveur, ou 0 s'il est configuré en mode client.

VOIR AUSSI

ssl(3), SSL_accept(3), SSL_connect(3), SSL_CTX_new(3), SSL_CTX_set_ssl_version(3), SSL_do_handshake(3), SSL_new(3), SSL_read(3), SSL_write(3)

HISTORIQUE

SSL_set_connect_state() et SSL_set_accept_state() sont apparues pour la première fois dans SSLeay 0.6.0 et sont disponibles depuis OpenBSD 2.4.

SSL_is_server() est apparue pour la première fois dans OpenSSL 1.0.2 et est disponible depuis OpenBSD 6.3.
