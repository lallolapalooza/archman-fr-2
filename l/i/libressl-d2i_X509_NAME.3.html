D2I_X509_NAME(3) Manuel des fonctions de bibliothèque D2I_X509_NAME(3)

NOM

d2i_X509_NAME, i2d_X509_NAME, X509_NAME_get0_der, X509_NAME_dup, X509_NAME_set, d2i_X509_NAME_ENTRY, i2d_X509_NAME_ENTRY, X509_NAME_ENTRY_dup — décode et encode les objets X.501 Name

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/x509.h>

X509_NAME *
d2i_X509_NAME(X509_NAME **val_out, const unsigned char **der_in, long length);

int
i2d_X509_NAME(X509_NAME *val_in, unsigned char **der_out);

int
X509_NAME_get0_der(X509_NAME *val_in, const unsigned char **der_out, size_t *out_len);

X509_NAME *
X509_NAME_dup(X509_NAME *val_in);

int
X509_NAME_set(X509_NAME **val_out, X509_NAME *val_in);

X509_NAME_ENTRY *
d2i_X509_NAME_ENTRY(X509_NAME_ENTRY **val_out, const unsigned char **der_in, long length);

int
i2d_X509_NAME_ENTRY(X509_NAME_ENTRY *val_in, unsigned char **der_out);

X509_NAME_ENTRY *
X509_NAME_ENTRY_dup(X509_NAME_ENTRY *val_in);

DESCRIPTION

Ces fonctions décodent et encodent les objets Name X.501 en utilisant le format DER. Pour les détails sur la sémantique, les exemples, les mises en garde et les bugs, voir ASN1_item_d2i(3).

d2i_X509_NAME() et i2d_X509_NAME() décodent et encodent une structure ASN.1 Name définie dans la section 4.1.2.4 de la RFC 5280.

X509_NAME_get0_der() est une variante de i2d_X509_NAME() qui ne copie pas la sortie encodée mais renvoie plutôt un pointeur vers la version encodée DER mise en cache en interne du nom. De plus, elle ne renvoie pas la longueur de la sortie en octets, mais la stocke dans out_len. Si la forme encodée mise en cache s'avère obsolète, les deux fonctions la mettent à jour avant de la copier ou d'en renvoyer un pointeur.

X509_NAME_dup() copie val_in en appelant i2d_X509_NAME() et d2i_X509_NAME().

X509_NAME_set() s'assure que *val_out contient les mêmes données que val_in après l'appel, sauf qu'elle échoue si val_in est NULL. Si *val_out est le même pointeur que val_in, la fonction réussit sans rien changer. Sinon, elle copie val_in en utilisant X509_NAME_dup() et, en cas de succès, libère *val_out et le définit comme pointeur vers le nouvel objet. Lorsque la fonction échoue, elle ne change jamais rien. Dans tous les cas, val_in reste valide et peut ou non être le même pointeur que *val_out après l'appel.

d2i_X509_NAME_ENTRY() et i2d_X509_NAME_ENTRY() décodent et encodent une structure ASN.1 RelativeDistinguishedName définie dans la section 4.1.2.4 de la RFC 5280.

X509_NAME_ENTRY_dup() copie val_in en appelant i2d_X509_NAME_ENTRY() et d2i_X509_NAME_ENTRY().

VALEURS DE RETOUR

d2i_X509_NAME() et X509_NAME_dup() renvoient le nouvel objet X509_NAME ou NULL si une erreur se produit.

X509_NAME_set() et X509_NAME_GET0_DER() renvoient 1 en cas de succès ou 0 si une erreur se produit.

d2i_X509_NAME_ENTRY() et X509_NAME_ENTRY_dup() renvoient le nouvel objet X509_NAME_ENTRY ou NULL si une erreur se produit.

i2d_X509_NAME() et i2d_X509_NAME_ENTRY() renvoient le nombre d'octets encodés avec succès ou une valeur négative si une erreur se produit.

VOIR AUSSI

ASN1_item_d2i(3), X509_NAME_ENTRY_new(3), X509_NAME_new(3), X509_NAME_print_ex(3)

NORMES

RFC 5280 : Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile

ITU-T Recommendation X.690, également connue sous le nom de ISO/IEC 8825-1 : Technologies de l'information - Règles d'encodage ASN.1 : Spécification des règles d'encodage de base (BER), des règles d'encodage canoniques (CER) et des règles d'encodage distinctives (DER).

HISTORIQUE

X509_NAME_dup() est apparu pour la première fois dans SSLeay 0.4.4. d2i_X509_NAME(), i2d_X509_NAME(), d2i_X509_NAME_ENTRY(), i2d_X509_NAME_ENTRY(), et X509_NAME_ENTRY_dup() sont apparus pour la première fois dans SSLeay 0.5.1. X509_NAME_set() est apparu pour la première fois dans SSLeay 0.8.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

X509_NAME_get0_der() est apparu pour la première fois dans OpenSSL 1.1.0 et est disponible depuis OpenBSD 6.3.
