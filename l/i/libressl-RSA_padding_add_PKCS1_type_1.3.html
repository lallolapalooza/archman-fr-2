DESCRIPTION

Ces fonctions sont appelées depuis les fonctions de chiffrement, déchiffrement, signature et vérification RSA. Normalement, elles ne devraient pas être appelées depuis des programmes d'application.

Cependant, elles peuvent aussi être appelées directement pour implémenter le remplissage pour d'autres chiffrements asymétriques. RSA_padding_add_PKCS1_OAEP() et RSA_padding_check_PKCS1_OAEP() peuvent être utilisées dans une application combinée avec RSA_NO_PADDING afin d'implémenter OAEP avec un paramètre d'encodage.

RSA_padding_add_*() encode fl octets à partir de f pour qu'ils s'insèrent dans tlen octets et stocke le résultat à to. Une erreur se produit si fl ne satisfait pas aux exigences de taille de la méthode d'encodage.

Les méthodes d'encodage suivantes sont implémentées :

PKCS1_type_1
PKCS #1 v2.0 EMSA-PKCS1-v1_5 (type de bloc 1 de PKCS #1 v1.5) ; utilisé pour les signatures
PKCS1_type_2
PKCS #1 v2.0 EME-PKCS1-v1_5 (type de bloc 2 de PKCS #1 v1.5)
PKCS1_OAEP
PKCS #1 v2.0 EME-OAEP
none
copie simplement les données

RSA_padding_check_*() vérifie que les fl octets à f contiennent un encodage valide pour une clé RSA de rsa_len octets selon la méthode d'encodage respective et stocke les données récupérées d'au plus tlen octets (pour RSA_NO_PADDING : de taille tlen) à to.

Pour RSA_padding_*_OAEP(), p pointe vers le paramètre d'encodage de longueur pl. p peut être NULL si pl est 0.

VALEUR DE RETOUR

Les fonctions RSA_padding_add_*() renvoient 1 en cas de succès ou 0 en cas d'erreur. Les fonctions RSA_padding_check_*() renvoient la longueur des données récupérées ou -1 en cas d'erreur. Les codes d'erreur peuvent être obtenus en appelant ERR_get_error(3).

VOIR AUSSI

RSA_new(3), RSA_private_decrypt(3), RSA_public_encrypt(3), RSA_sign(3), RSA_verify(3)

HISTORIQUE

RSA_padding_add_PKCS1_type_1(), RSA_padding_check_PKCS1_type_1(), RSA_padding_add_PKCS1_type_2(), RSA_padding_check_PKCS1_type_2(), RSA_padding_add_none(), et RSA_padding_check_none() sont apparues pour la première fois dans SSLeay 0.9.0 et sont disponibles depuis OpenBSD 2.4.

RSA_padding_add_PKCS1_OAEP() et RSA_padding_check_PKCS1_OAEP() sont apparues pour la première fois dans OpenSSL 0.9.2b et sont disponibles depuis OpenBSD 2.6.

BOGUES

La vérification de remplissage RSA_padding_check_PKCS1_type_2() divulgue des informations de timing qui pourraient potentiellement être utilisées pour monter une attaque par oracle de remplissage de Bleichenbacher. C'est une faiblesse inhérente à la conception du remplissage PKCS #1 v1.5. Préférez le remplissage PKCS1_OAEP.
