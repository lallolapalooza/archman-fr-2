SSL_ALERT_TYPE_STRING(3) Manuel des fonctions de bibliothèque SSL_ALERT_TYPE_STRING(3)

NOM

SSL_alert_type_string, SSL_alert_type_string_long, SSL_alert_desc_string, SSL_alert_desc_string_long — obtenir la description textuelle des informations d'alerte

SYNTAXE

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

const char *
SSL_alert_type_string(int valeur);

const char *
SSL_alert_type_string_long(int valeur);

const char *
SSL_alert_desc_string(int valeur);

const char *
SSL_alert_desc_string_long(int valeur);

DESCRIPTION

SSL_alert_type_string() renvoie une chaîne d'une lettre indiquant le type de l'alerte spécifiée par valeur.

SSL_alert_type_string_long() renvoie une chaîne indiquant le type de l'alerte spécifiée par valeur.

SSL_alert_desc_string() renvoie une chaîne de deux lettres sous forme courte décrivant la raison de l'alerte spécifiée par valeur.

SSL_alert_desc_string_long() renvoie une chaîne décrivant la raison de l'alerte spécifiée par valeur.

Lorsqu'un côté d'une communication SSL/TLS souhaite informer le pair d'une situation particulière, il envoie une alerte. L'alerte est envoyée sous forme de message spécial et n'influence pas le flux de données normal (sauf si son contenu entraîne l'annulation de la communication).

Une alerte d'avertissement est envoyée lorsqu'une condition d'erreur non fatale survient. L'alerte « close notify » est envoyée comme une alerte d'avertissement. D'autres exemples d'erreurs non fatales sont les erreurs de certificat (« certificate expired », « unsupported certificate »), pour lesquelles une alerte d'avertissement peut être envoyée. (La partie émettrice peut cependant décider d'envoyer une erreur fatale.) Le côté récepteur peut annuler la connexion lors de la réception d'une alerte d'avertissement à sa discrétion.

Plusieurs messages d'alerte doivent être envoyés comme messages d'alerte fatale, comme spécifié par la RFC TLS. Une alerte fatale entraîne toujours un abandon de connexion.

VALEURS DE RETOUR

Les chaînes suivantes peuvent apparaître pour SSL_alert_type_string() ou SSL_alert_type_string_long() :

"W"/"warning"
 
"F"/"fatal"
 
"U"/"unknown"
Ceci indique qu'aucun support n'est disponible pour ce type d'alerte. Probablement valeur ne contient pas un message d'alerte correct.

Les chaînes suivantes peuvent apparaître pour SSL_alert_desc_string() ou SSL_alert_desc_string_long() :

"CN"/"close notify"
La connexion doit être fermée. Ceci est une alerte d'avertissement.
"UM"/"unexpected message"
Un message inapproprié a été reçu. Cette alerte est toujours fatale et ne devrait jamais être observée dans une communication entre des implémentations correctes.
"BM"/"bad record mac"
Cette alerte est renvoyée si un enregistrement est reçu avec un MAC incorrect. Ce message est toujours fatal.
"DF"/"decompression failure"
La fonction de décompression a reçu une entrée incorrecte (par exemple, des données qui s'étendraient à une longueur excessive). Ce message est toujours fatal.
"HF"/"handshake failure"
La réception d'un message d'alerte handshake_failure indique que l'expéditeur n'a pas pu négocier un ensemble acceptable de paramètres de sécurité étant donné les options disponibles. Ceci est une erreur fatale.
"NC"/"no certificate"
Un client, à qui il a été demandé d'envoyer un certificat, n'en envoie pas (SSLv3 uniquement).
"BC"/"bad certificate"
Un certificat était corrompu, contenait des signatures qui n'ont pas pu être vérifiées correctement, etc.
"UC"/"unsupported certificate"
Un certificat était d'un type non supporté.
"CR"/"certificate revoked"
Un certificat a été révoqué par son émetteur.
"CE"/"certificate expired"
Un certificat a expiré ou n'est pas actuellement valide.
"CU"/"certificate unknown"
Un autre problème (non spécifié) est survenu lors du traitement du certificat, le rendant inacceptable.
"IP"/"illegal parameter"
Un champ dans l'échange de clés était hors limites ou incohérent avec d'autres champs. Ceci est toujours fatal.
"DC"/"decryption failed"
Un TLSCiphertext a été déchiffré d'une manière invalide : soit ce n'était pas un multiple pair de la longueur de bloc, soit ses valeurs de remplissage, lorsqu'elles étaient vérifiées, n'étaient pas correctes. Ce message est toujours fatal.
"RO"/"record overflow"
Un enregistrement TLSCiphertext a été reçu dont la longueur dépassait 2^14+2048 octets, ou un enregistrement déchiffré vers un enregistrement TLSCompressed de plus de 2^14+1024 octets. Ce message est toujours fatal.
"CA"/"unknown CA"
Une chaîne de certificats valide ou une chaîne partielle a été reçue, mais le certificat n'a pas été accepté car le certificat de l'AC n'a pas pu être trouvé ou n'a pas pu être associé à une AC connue et fiable. Ce message est toujours fatal.
"AD"/"access denied"
Un certificat valide a été reçu, mais lorsque le contrôle d'accès a été appliqué, l'expéditeur a décidé de ne pas poursuivre la négociation. Ce message est toujours fatal.
"DE"/"decode error"
Un message n'a pas pu être décodé car un champ était hors de la plage spécifiée ou la longueur du message était incorrecte. Ce message est toujours fatal.
"CY"/"decrypt error"
Une opération cryptographique de l'échange de clés a échoué, y compris l'incapacité de vérifier correctement une signature, de déchiffrer une clé d'échange, ou de valider un message de fin.
"ER"/"export restriction"
Une négociation non conforme aux restrictions d'exportation a été détectée ; par exemple, une tentative de transfert d'une clé RSA éphémère de 1024 bits pour la méthode d'échange RSA_EXPORT. Ce message est toujours fatal.
"PV"/"protocol version"
La version du protocole que le client a tenté de négocier est reconnue, mais n'est pas supportée. (Par exemple, les anciennes versions de protocole peuvent être évitées pour des raisons de sécurité.) Ce message est toujours fatal.
"IS"/"insufficient security"
Renvoyé à la place de handshake_failure lorsqu'une négociation a échoué spécifiquement parce que le serveur exige des chiffrements plus sécurisés que ceux supportés par le client. Ce message est toujours fatal.
"IE"/"internal error"
Une erreur interne non liée au pair ou à la correction du protocole rend impossible la poursuite (par exemple, une échec d'allocation mémoire). Ce message est toujours fatal.
"IF"/"inappropriate fallback"
Envoyé par un serveur en réponse à une tentative de nouvelle connexion invalide d'un client (voir RFC 7507).
"US"/"user canceled"
Cet échange de clés est annulé pour une raison non liée à une défaillance du protocole. Si l'utilisateur annule une opération après la fin de l'échange de clés, il est plus approprié de simplement fermer la connexion en envoyant un close_notify. Cette alerte doit être suivie d'un close_notify. Ce message est généralement un avertissement.
"NR"/"no renegotiation"
Envoyé par le client en réponse à une demande de hello ou par le serveur en réponse à un hello client après l'échange de clés initial. L'un ou l'autre normalementmener à une renégociation ; lorsque cela n'est pas approprié, le destinataire doit répondre avec cette alerte ; à ce stade, le demandeur initial peut décider de poursuivre la connexion. Un cas où cela serait approprié serait lorsqu'un serveur a lancé un processus pour satisfaire une requête ; le processus pourrait recevoir des paramètres de sécurité (longueur de clé, authentification, etc.) au démarrage et il pourrait être difficile de communiquer des changements à ces paramètres après ce point. Ce message est toujours un avertissement.
"UP"/"unknown PSK identity"
Envoyé par le serveur pour indiquer qu'il ne reconnaît pas une identité PSK ou une identité SRP.
"CQ"/"certificate required"
Envoyé par les serveurs lorsqu'un certificat client est souhaité mais qu'aucun n'a été fourni par le client.
"AP"/"no application protocol"
Envoyé par les serveurs lorsqu'une extension ALPN du client n'annonce que des protocoles que le serveur ne prend pas en charge (voir RFC 7301).
"UK"/"unknown"
Ceci indique qu'aucune description n'est disponible pour ce type d'alerte. Probablement value ne contient pas un message d'alerte correct.
