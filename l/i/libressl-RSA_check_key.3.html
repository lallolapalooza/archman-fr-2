Paquet: libressl

Licences: ISC, custom:OpenSSL

RSA_CHECK_KEY(3) Manuel des fonctions de bibliothèque RSA_CHECK_KEY(3)

NOM

RSA_check_key — valider les clés RSA privées

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/rsa.h>

int
RSA_check_key(RSA *rsa);

DESCRIPTION

Cette fonction valide les clés RSA. Elle vérifie que rsa->p et rsa->q sont effectivement premiers, et que rsa->n satisfait n = p*q.

Elle vérifie également que rsa->d et rsa->e satisfont d*e = 1 mod ((p-1)*(q-1)), et que rsa->dmp1, rsa->dmq1, et resa->iqmp sont correctement définis ou sont NULL.

Cette fonction ne fonctionne pas sur les clés publiques RSA qui ne contiennent que le module et l'exposant public. Elle effectue des vérifications d'intégrité sur tout le matériel de la clé RSA, donc la structure de clé RSA doit contenir toutes les données de la clé privée également. Par conséquent, elle ne peut pas être utilisée avec n'importe quel objet de clé RSA arbitraire, même s'il est autrement adapté à une opération RSA régulière.

VALEURS DE RETOUR

RSA_check_key() retourne 1 si rsa est une clé RSA valide, et 0 sinon. -1 est retourné si une erreur survient lors de la vérification de la clé.

Si la clé est invalide ou si une erreur est survenue, le code d'erreur peut être obtenu en utilisant ERR_get_error(3).

VOIR AUSSI

BN_is_prime_ex(3), RSA_get0_key(3), RSA_new(3)

HISTORIQUE

RSA_check_key() est apparu pour la première fois dans OpenSSL 0.9.4 et est disponible depuis OpenBSD 2.6.

BOGUES

Une méthode de vérification de la clé RSA utilisant des fonctions API RSA opaques pourrait devoir être envisagée. Actuellement, RSA_check_key() utilise simplement les éléments de structure RSA directement, en contournant la table RSA_METHOD (et en violant complètement l'encapsulation et l'orientation objet dans le processus). La meilleure solution sera probablement d'introduire un gestionnaire check_key() dans la table des fonctions RSA_METHOD afin que des implémentations alternatives puissent également fournir leurs propres vérificateurs.
