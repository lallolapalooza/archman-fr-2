LIRCMD(8) Utilitaires d'administration système LIRCMD(8)

NOM

lircmd - Traduit les signaux infrarouges en événements de souris.

SYNTAXE

lircmd [options] [fichier-de-configuration]

DESCRIPTION

lircmd lit les événements de pression de bouton décodés à partir d'un socket de sortie lircd(8) et les convertit en événements de souris. Ces événements sont mis à disposition soit sur le socket de sortie de lircmd (par défaut /var/run/lirc/lircmd ), soit, en utilisant l'option --uinput , sur un périphérique /dev/input comme /dev/input/event12 .

Ce démon peut simuler une souris de type MouseSystems, IntelliMouse ou IMPS/2. La fonction dépend d'un fichier de configuration, par défaut /etc/lirc/lircmd.conf . Ce fichier détermine quel bouton d'une télécommande donnée provoque un déplacement de souris ou un clic de bouton de souris. Un bouton spécial qui active ou désactive le mode souris peut également être défini.

L'utilisation normale consiste à configurer X11 pour utiliser les événements produits par lircmd comme source d'entrée. Voir VOIR AUSSI.

En utilisant l'option --uinput , le périphérique utilisateur créé par le noyau a un nom dynamique qui change généralement après un redémarrage. La distribution lirc contient une règle udev qui, si elle est installée, crée un lien fixe nommé /dev/lircmd qui peut toujours être utilisé.

Par défaut, l'utilisation de l'option --uinput nécessite que lircmd s'exécute en tant que root car le périphérique /dev/uinput n'est accessible que par root. La distribution lirc contient des exemples de règles udev et de configurations lircd-setup(8) qui peuvent être utilisés pour rendre le périphérique accessible par d'autres utilisateurs. De cette façon, lircmd peut être exécuté en tant qu'utilisateur régulier.

OPTIONS

-h --help
Affiche le message d'aide.
-v --version
Affiche la version.
-n --nodaemon
Ne pas passer en arrière-plan.
-s --socket <chemin-du-socket>
Utiliser un chemin de socket lircd alternatif (la source d'entrée de lircmd). Par défaut, il utilise la clé output dans la section [lircd] du fichier de configuration lirc_options.conf , avec un retour au /var/run/lirc/lircd.
-O --options-file=fichier
Fichier d'options par défaut alternatif, généralement /etc/lirc/lirc_options.conf.
-u --uinput
Sur les systèmes Linux, l'option --uinput activera la génération automatique d'événements d'entrée Linux. lircmd ouvrira /dev/input/uinput et injectera les événements de souris simulés dans le noyau Linux plutôt que de créer le périphérique /dev/lircm. Le noyau rendra ces événements disponibles à d'autres applications sur un périphérique /dev/input, comme tout autre périphérique d'entrée du noyau.
-D --loglevel=[niveau]
Détermine la quantité d'informations de journalisation. [niveau] peut être un niveau symbolique syslog : 'error', 'warning', 'info', 'notice' ou 'debug'. lircd définit également trois niveaux supplémentaires 'trace', 'trace1' et 'trace2' qui fournissent encore plus de messages ('trace2' fournissant le plus). Cependant, dans le journal, ces messages sont marqués comme 'debug'.

PROTOCOLE SOCKET

Le protocole du socket contient des parties non documentées. Les données sur le socket de sortie sont

MouseSystems
Paquets de 5 octets :
  • Octet 1 : Informations sur les boutons.
  • Octet 2 : Changement sur l'axe X.
  • Octet 3 : Changement sur l'axe Y.
  • Octets 4 et 5 : 0.
IMPS/2
Paquets de 4 octets. Veuillez vous référer au code source de lircmd pour plus de détails.
IntelliMouse
Paquets de 4 octets. Veuillez vous référer au code source de lircmd pour plus de détails.

FICHIERS

lircmd utilisera syslogd pour envoyer des messages d'erreur. Où ils apparaîtront dépend de la configuration de votre système.

Le fichier d'options est par défaut /etc/lirc/lirc_options.conf ; lircmd gère les valeurs sous la section [lircmd] de ce fichier. L'emplacement peut être modifié en utilisant l'option de ligne de commande -O/--options-file ou en utilisant la variable d'environnement LIRC_OPTIONS_PATH. Les valeurs ici sont utilisées comme valeurs par défaut pour toute option non présente sur la ligne de commande.

DÉMONS

lircmd est un démon. Il devrait être démarré dans un script d'initialisation dépendant du système. Outre la configuration systemd qui est installée par défaut, il existe également des scripts d'exemple pour d'autres distributions et systèmes d'initialisation dans le répertoire contrib. lircmd doit être démarré après lircd car il se connecte au socket fourni par lircd.

BOGUES

Comme le nom du périphérique utilisé lors de l'enregistrement du périphérique --uinput est fixe, une seule instance de lircmd utilisant cette option peut être exécutée sur un système donné.

Le protocole du socket est un désastre en termes de documentation.
