BIO_ACCEPT(3) Manuel des fonctions de bibliothèque BIO_ACCEPT(3)

NOM

BIO_get_host_ip, BIO_get_port, BIO_get_accept_socket, BIO_accept, BIO_sock_error, BIO_sock_non_fatal_error, BIO_sock_should_retry, BIO_socket_nbio, BIO_set_tcp_ndelay — enveloppes pour les opérations sur socket

SYNOPSIS

bibliothèque “libcrypto”
#include <openssl/bio.h>

int
BIO_get_host_ip(const char *hostname, unsigned char *in_addr_buffer);

int
BIO_get_port(const char *servname, unsigned short *port);

int
BIO_get_accept_socket(char *host_port, int bind_mode);

int
BIO_accept(int socket, char **addr);

int
BIO_sock_error(int socket);

int
BIO_sock_non_fatal_error(int errnum);

int
BIO_sock_should_retry(int retval);

int
BIO_socket_nbio(int socket, int mode);

int
BIO_set_tcp_ndelay(int socket, int on);

DESCRIPTION

BIO_get_host_ip() recherche une adresse IPv4 pour le hostname donné en utilisant getaddrinfo(3) et écrit la première adresse IPv4 retournée dans *in_addr_buffer. L'appelant est responsable de fournir un tampon d'au moins sizeof(in_addr_t) octets de long. Après un appel réussi, l'appelant doit caster in_addr_buffer en (in_addr_t *).

BIO_get_port() recherche le servname dans la base de données services(5) en utilisant getaddrinfo(3) et stocke le numéro de port associé à l'emplacement spécifié par l'argument port.

BIO_get_accept_socket() crée un socket TCP IPv4 et listen(2) pour les connexions entrantes. La chaîne host_port est analysée. Si elle contient un deux-points, la sous-chaîne avant le deux-points est interprétée comme le nom d'hôte local de l'interface à laquelle se bind(2). Si le nom d'hôte est vide, consiste en un simple astérisque ("*:..."), ou s'il n'y a pas de deux-points, INADDR_ANY est utilisé à la place d'un nom d'hôte local. Le reste de la chaîne host_port, ou la chaîne entière si elle ne contient pas de deux-points, est traité comme un nom de service. Le nom d'hôte et le nom de service sont convertis en une adresse IP locale et un numéro de port en utilisant getaddrinfo(3). Si bind_mode est la constante BIO_BIND_REUSEADDR, la réutilisation d'adresse locale est tentée en utilisant setsockopt(2) avec l'argument SO_REUSEADDR avant d'appeler bind(2).

BIO_accept() appelle accept(2) pour recevoir une connexion sur le socket. Lorsqu'il reçoit une connexion, il free(3) *addr, et s'il s'agit d'une connexion IPv4, il alloue une nouvelle chaîne, écrit l'adresse IP du pair sous forme décimale pointée, un deux-points, et le numéro de port décimal dans la chaîne, et stocke un pointeur vers la chaîne dans *addr. Pour d'autres familles d'adresses ou si getnameinfo(3) ou l'allocation mémoire échouent, *addr est mis à NULL mais BIO_accept() réussit quand même.

BIO_sock_error() récupère, efface et retourne le code d'état d'erreur du socket en appelant getsockopt(2) avec les arguments SOL_SOCKET et SO_ERROR.

BIO_sock_non_fatal_error() détermine si le code d'état d'erreur errnum représente une erreur récupérable.

BIO_sock_should_retry() détermine si une erreur récupérable s'est produite en inspectant à la fois errno(2) et retval, qui est censé être la plupart du temps la valeur de retour d'une fonction précédemment appelée comme BIO_accept(), BIO_read(3), ou BIO_write(3).

Si mode est non nul, BIO_socket_nbio() bascule le socket en mode non bloquant en utilisant fcntl(2). Si mode est 0, il bascule en mode bloquant.

BIO_set_tcp_ndelay() définit l'option TCP_NODELAY sur le socket si on est 1 ou l'efface si on est 0 ; voir tcp(4) pour les détails.

VALEUR DE RETOUR

BIO_get_host_ip(), BIO_get_port(), et BIO_socket_nbio() retournent 1 en cas de succès ou 0 en cas d'échec.

BIO_get_accept_socket() retourne le descripteur de fichier du nouveau socket d'écoute créé ou -1 si host_port est NULL, aucun service n'est spécifié, ou si getaddrinfo(3), socket(2), bind(2), listen(2), ou l'allocation mémoire échouent.

BIO_accept() retourne le descripteur de fichier de la connexion reçue, -1 en cas d'erreurs fatales, c'est-à-dire lorsque addr est NULL ou accept(2) échoue fatalement, ou -2 lorsque accept(2) échoue de manière non fatale et pourrait réussir lors d'une nouvelle tentative ultérieure.

BIO_sock_error() retourne un code d'état d'erreur tel que EAGAIN, ECONNABORTED, ECONNREFUSED, ECONNRESET, ELOOP, EMSGSIZE, ENOBUFS, ENOTCONN, EPIPE, ETIMEDOUT, ou autres, 0 si le socket n'est pas dans un état d'erreur, ou 1 si getsockopt(2) échoue.

BIO_accept(3) - Bio Functions

NOM

BIO_accept, BIO_accept_getParentFd, BIO_get_accept_socket, BIO_get_host_ip, BIO_get_port, BIO_set_tcp_ndelay, BIO_socket_nbio, BIO_sock_non_fatal_error, BIO_sock_should_retry, BIO_setup_retry - Fonctions de gestion des sockets pour les BIO

SYNTAXE

#include <openssl/bio.h>

int BIO_accept(BIO *bio, int *fd);

int BIO_setup_retry(BIO *bio, int sock);

int BIO_get_accept_socket(BIO *bio, const char *host, const char *port);

int BIO_get_host_ip(const char *host, unsigned char *ip);

int BIO_get_port(const char *port, unsigned char *ip);

int BIO_set_tcp_ndelay(int fd, int onoff);

int BIO_socket_nbio(int fd, int nonblock);

int BIO_sock_non_fatal_error(int errnum);

int BIO_sock_should_retry(int retval, int errnum);

int BIO_accept_getParentFd(BIO *bio);

DESCRIPTION

Le BIO BIO_TYPE_ACCEPT est un BIO qui écoute les connexions entrantes sur un socket, puis les accepte.

BIO_get_accept_socket() est une fonction utilitaire qui tente de créer un socket d'écoute pour le nom d'hôte et le port spécifiés. Si l'hôte est NULL, elle écoute sur toutes les interfaces. Si le port est NULL, elle essaie de trouver un port disponible. L'argument bio doit contenir un BIO de type BIO_TYPE_ACCEPT. La fonction retourne 0 en cas de succès ou -1 en cas d'échec.

BIO_get_host_ip() tente de résoudre le nom d'hôte en une adresse IP. L'adresse IP est stockée dans la variable ip sous forme d'un tableau de 4 octets. La fonction retourne 0 en cas de succès ou -1 en cas d'échec.

BIO_get_port() tente de résoudre le nom de service ou le numéro de port en un numéro de port. Le numéro de port est stocké dans la variable ip (oui, c'est bien ip, pas port, une erreur de frappe dans la documentation originale). La fonction retourne 0 en cas de succès ou -1 en cas d'échec.

BIO_accept() accepte une connexion entrante sur le socket d'écoute associé au BIO bio. Si la connexion est acceptée avec succès, le descripteur de fichier du nouveau socket est retourné dans fd. La fonction retourne 1 en cas de succès, 0 si aucune connexion n'est disponible (et que le BIO est en mode non bloquant), et -1 en cas d'erreur fatale.

BIO_setup_retry() configure le BIO bio pour tenter de réessayer une opération échouée sur le socket sock. Ceci est généralement appelé après un échec non fatal de BIO_accept(). La fonction retourne 0 en cas de succès ou -1 en cas d'échec.

BIO_accept_getParentFd() retourne le descripteur de fichier du socket d'écoute associé au BIO bio.

BIO_socket_nbio() configure le socket fd en mode non bloquant si nonblock est différent de zéro, et en mode bloquant sinon. Elle retourne 0 en cas de succès, et -1 en cas d'échec.

BIO_sock_non_fatal_error() retourne 1 si errnum est EAGAIN, EALREADY, EINPROGRESS, EINTR, ou ENOTCONN, et 0 sinon, même si errnum est 0.

BIO_sock_should_retry() retourne 1 si BIO_sock_non_fatal_error(errnum) est 1 et retval est soit 0 soit -1, ou 0 sinon.

BIO_set_tcp_ndelay() retourne 0 en cas de succès ou -1 en cas d'échec.

ERREURS

Si BIO_get_host_ip(), BIO_get_port(), ou BIO_get_accept_socket() échouent ou BIO_accept() échoue de manière fatale, les diagnostics suivants peuvent être récupérés avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3):

BIO_R_ACCEPT_ERROR "accept error"
accept(2) a échoué fatalement dans BIO_accept().
BIO_R_BAD_HOSTNAME_LOOKUP "bad hostname lookup"
getaddrinfo(3) a échoué ou hostname était NULL dans BIO_get_host_ip(), ou getaddrinfo(3) a échoué dans BIO_get_accept_socket().
BIO_R_INVALID_ARGUMENT "invalid argument"
getaddrinfo(3) a échoué dans BIO_get_port().
ERR_R_MALLOC_FAILURE "malloc failure"
L'allocation mémoire a échoué dans BIO_get_accept_socket(), ou BIO_accept() a réussi mais n'a pas pu allouer de mémoire pour *addr. Pour BIO_accept(), le descripteur de fichier retourné est valide, et la communication avec le pair peut être tentée en utilisant celui-ci.
BIO_R_NO_PORT_SPECIFIED "no port specified"
L'argument servname était NULL dans BIO_get_port(), ou host_port était NULL ou s'est terminé après le premier deux-points dans BIO_get_accept_socket().
BIO_R_NULL_PARAMETER "null parameter"
L'argument addr était NULL dans BIO_accept().
BIO_R_UNABLE_TO_BIND_SOCKET "unable to bind socket"
bind(2) a échoué dans BIO_get_accept_socket().
BIO_R_UNABLE_TO_CREATE_SOCKET "unable to create socket"
socket(2) a échoué dans BIO_get_accept_socket().
BIO_R_UNABLE_TO_LISTEN_SOCKET "unable to listen socket"
listen(2) a échoué dans BIO_get_accept_socket().

VOIR AUSSI

bind(2), connect(2), errno(2), fcntl(2), getsockopt(2), listen(2), sigaction(2), socket(2), BIO_new(3), BIO_read(3), getaddrinfo(3), ip(4), tcp(4)

HISTORIQUE

BIO_sock_should_retry() est apparu pour la première fois dans SSLeay 0.6.5 et les autres fonctions, à l'exception de BIO_socket_nbio(), dans SSLeay 0.8.0. Elles sont toutes disponibles depuis OpenBSD 2.4.

BIO_socket_nbio() est apparu pour la première fois dans SSLeay 0.9.1 et est disponible depuis OpenBSD 2.6.
