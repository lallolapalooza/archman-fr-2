PKCS7_SIGN(3) Manuel des fonctions de bibliothèque PKCS7_SIGN(3)

NOM

PKCS7_sign — crée une structure PKCS#7 signedData

SYNTAXE

bibliothèque «libcrypto»
#include <openssl/pkcs7.h>

PKCS7 *
PKCS7_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs, BIO *data, int flags);

DESCRIPTION

PKCS7_sign() crée et retourne une structure PKCS#7 signedData. signcert est le certificat à utiliser pour la signature, pkey est la clé privée correspondante. certs est un ensemble optionnel de certificats supplémentaires à inclure dans la structure PKCS#7 (par exemple, les certificats d'autorité de certification intermédiaires dans la chaîne).

Les données à signer sont lues à partir de BIO data.

flags est un ensemble optionnel d'indicateurs.

N'importe lequel des indicateurs suivants (combinés avec OR) peut être passé dans le paramètre flags.

De nombreux clients S/MIME s'attendent à ce que le contenu signé inclue des en-têtes MIME valides. Si l'indicateur PKCS7_TEXT est défini, des en-têtes MIME de type text/plain sont ajoutés en préfixe aux données.

Si PKCS7_NOCERTS est défini, le certificat du signataire ne sera pas inclus dans la structure PKCS7, bien que le certificat du signataire doive toujours être fourni dans le paramètre signcert. Cela peut réduire la taille de la signature si le certificat du signataire peut être obtenu par d'autres moyens : par exemple, un message précédemment signé.

Les données signées sont incluses dans la structure PKCS7, sauf si PKCS7_DETACHED est défini, auquel cas elles sont omises. Ceci est utilisé pour les signatures PKCS7 détachées qui sont utilisées dans les messages signés en clair S/MIME, par exemple.

Normalement, le contenu fourni est traduit dans le format canonique MIME (comme requis par les spécifications S/MIME). Si PKCS7_BINARY est défini, aucune traduction n'a lieu. Cette option doit être utilisée si les données fournies sont au format binaire ; sinon, la traduction les corrompra.

La structure signedData inclut plusieurs attributs authentifiés PKCS#7, notamment l'heure de signature, le type de contenu PKCS#7 et la liste prise en charge des chiffrements dans un attribut SMIMECapabilities. Si PKCS7_NOATTR est défini, aucun attribut authentifié ne sera utilisé. Si PKCS7_NOSMIMECAP est défini, seuls les SMIMECapabilities sont omis.

S'il est présent, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants : triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes est désactivé, il ne sera pas inclus.

Si l'indicateur PKCS7_STREAM est défini, la structure PKCS7 retournée est simplement initialisée pour effectuer l'opération de signature. La signature n'est cependant pas effectuée et les données à signer ne sont pas lues à partir du paramètre data. La signature est différée jusqu'à ce que les données aient été écrites. De cette façon, les données peuvent être signées en une seule passe.

Si l'indicateur PKCS7_PARTIAL est défini, une structure PKCS7 partielle est générée à laquelle des signataires et des capacités supplémentaires peuvent être ajoutés avant la finalisation.

Si l'indicateur PKCS7_STREAM est défini, la structure PKCS7 retournée n'est pas complète et l'affichage de son contenu via une fonction qui ne finalise pas correctement la structure PKCS7 donnera des résultats imprévisibles.

Plusieurs fonctions, dont PKCS7_final(3), SMIME_write_PKCS7(3), PEM_write_bio_PKCS7_stream(3), et i2d_PKCS7_bio_stream(3) finalisent la structure. Alternativement, la finalisation peut être effectuée en obtenant directement le BIO ASN.1 en streaming à l'aide de BIO_new_PKCS7().

Si un signataire est spécifié, il utilisera le digest par défaut pour l'algorithme de signature. Il s'agit de SHA1 pour les clés RSA et DSA.

Dans OpenSSL 1.0.0, les paramètres certs, signcert, et pkey peuvent tous être NULL si l'indicateur PKCS7_PARTIAL est défini. Un ou plusieurs signataires peuvent être ajoutés en utilisant la fonction PKCS7_sign_add_signer(3) et les attributs peuvent être ajoutés en utilisant les fonctions décrites dans PKCS7_add_attribute(3). PKCS7_final(3) doit également être appelé pour finaliser la structure si le streaming n'est pas activé. Des digests de signature alternatifs peuvent également être spécifiés en utilisant cette méthode.

Dans OpenSSL 1.0.0, si signcert et pkey sont NULL, alors une structure PKCS#7 contenant uniquement le certificat est générée.

Dans les versions d'OpenSSL antérieures à 1.0.0, les paramètres signcert et pkey ne doivent PAS être NULL.

VALEURS DE RETOUR

PKCS7_sign() retourne soit une structure PKCS7 valide, soit NULL si une erreur s'est produite. L'erreur peut être obtenue à partir de ERR_get_error(3).

VOIR AUSSI

PKCS7_add_attribute(3), PKCS7_encrypt(3), PKCS7_final(3), PKCS7_get_signer_info(3), PKCS7_new(3), PKCS7_sign_add_signer(3), PKCS7_verify(3)

HISTORIQUE

PKCS7_sign() est apparu pour la première fois dans OpenSSL 0.9.5 et est disponible depuis OpenBSD 2.7.

Les indicateurs PKCS7_PARTIAL et PKCS7_STREAM ont été ajoutés dans OpenSSL 1.0.0.

BOGUES

Certains attributs avancés tels que les contre-signatures ne sont pas pris en charge.

PKCS7_sign — génération de signature PKCS#7

NOM

PKCS7_sign — génération de signature PKCS#7

SYNOPSIS

#include <openssl/pkcs7.h>

long PKCS7_sign(PKCS7 *p7, STACK_OF(X509) *signers, EVP_PKEY *pkey, BIO *data, int flags);

DESCRIPTION

La fonction PKCS7_sign génère un objet PKCS#7 signé à partir de données fournies.

  • p7 est l'objet PKCS#7 à remplir. Il doit être correctement initialisé, généralement en utilisant PKCS7_new().
  • signers est une pile (STACK_OF(X509)) des certificats de signataire. Ces certificats seront inclus dans l'objet PKCS#7.
  • pkey est la clé privée du signataire, utilisée pour signer les données.
  • data est un objet BIO contenant les données à signer.
  • flags sont des indicateurs qui peuvent modifier le comportement de la fonction (voir ci-dessous).

La fonction remplit la structure p7 avec les informations de signature nécessaires, y compris les certificats de signataire, les informations sur l'algorithme de hachage et de signature, et la signature elle-même calculée sur les données fournies.

VALEURS DE RETOUR

La fonction retourne 1 en cas de succès, et 0 en cas d'échec.

VOIR AUSSI

PKCS7_new(3), EVP_PKEY(3), BIO(3)

HISTORIQUE

La fonction PKCS7_sign a été introduite dans OpenSSL 0.9.6.

BOGUES

Aucun bogue connu à ce jour.
