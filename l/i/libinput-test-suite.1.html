NOM

libinput-test-suite - exécute la suite de tests libinput

SYNOPIS

libinput test-suite [OPTIONS]

DESCRIPTION

La commande libinput test-suite exécute la suite de tests libinput. Son objectif principal est de vérifier les compositions de distribution après les mises à jour de paquets. Les échecs de la suite de tests indiquent généralement des correctifs manquants et/ou des couches système inférieures incompatibles.

La suite de tests ne doit pas être exécutée par les utilisateurs. Une perte de données est possible.

La suite de tests doit être exécutée en tant que root. La suite de tests installe plusieurs fichiers sur le système hôte (voir la section FICHIERS), exécute des commandes système et crée des périphériques noyau virtuels via uinput. Ces périphériques interféreront avec toute session active et peuvent causer une perte de données.

Il est recommandé d'exécuter la suite de tests dans une machine virtuelle et/ou sur un système qui n'est pas autrement utilisé. Un environnement graphique n'est pas requis pour exécuter la suite de tests.

OPTIONS

Notez que les options peuvent changer dans les futures versions de libinput. Les noms des tests, les noms des périphériques de test et les noms des groupes de tests peuvent changer à tout moment.

--filter-test "nomdutest"
Une chaîne glob limitant les tests à exécuter. La spécification d'un filtre définit --jobs à 1 par défaut.
--filter-device "nomdelapériphérique"
Une chaîne glob limitant les périphériques pour lesquels exécuter des tests. La spécification d'un filtre définit --jobs à 1 par défaut.
--filter-group "nomdugroupe"
Une chaîne glob limitant les tests à des groupes (nommés de manière arbitraire). La spécification d'un filtre définit --jobs à 1 par défaut.
--filter-deviceless
POUR USAGE INTERNE UNIQUEMENT
-h, --help
Affiche l'aide
-j, --jobs 8
Nombre de processus parallèles à exécuter. Défaut : 8.
--list
Liste tous les cas de test et les périphériques pour lesquels ils sont exécutés. Les noms des tests, les noms des périphériques de test et les noms des groupes de tests peuvent changer à tout moment.
--verbose
Active la sortie verbeuse, y compris les messages de débogage libinput.

FICHIERS

Les répertoires suivants sont modifiés :

/usr/share/libinput
Les quirks spécifiques aux périphériques de test sont installés dans ce répertoire avec un préfixe personnalisé. Les fichiers de ce répertoire ne sont pas modifiés, mais de nouveaux fichiers sont installés et supprimés à la sortie. Les fichiers existants (par exemple, d'une précédente exécution interrompue) portant le même nom seront silencieusement écrasés et supprimés.
/run/udev/rules.d
Les règles udev spécifiques aux tests sont installées dans ce répertoire et supprimées à la sortie.

CONFIGURATION SYSTEME

L'extrait xorg.conf.d(5) ci-dessous garantit que le serveur X ignore les périphériques de test créés par cette suite de tests :

Section "InputClass"
        Identifier "Ignorer les périphériques de la suite de tests libinput"
        MatchProduct "litest"
        Option "Ignore" "on"
EndSection

Aucune configuration n'est requise pour les compositeurs Wayland. Le mode par défaut de libinput ignorera les périphériques de test de cette suite de tests.

BOGUES

Certains tests sont sensibles au timing. Lorsque le système est fortement chargé, un test peut échouer. Relancer le test avec --filter-test peut aider à vérifier si un échec de cas de test était un véritable échec.
