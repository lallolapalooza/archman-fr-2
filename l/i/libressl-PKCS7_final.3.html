PKCS7_FINAL(3) Manuel des fonctions de la bibliothèque PKCS7_FINAL(3)

NOM

PKCS7_final — lire les données d'un BIO dans un objet ContentInfo

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/pkcs7.h>

int
PKCS7_final(PKCS7 *p7, BIO *data, int flags);

DESCRIPTION

PKCS7_final() lit les données et les place dans le champ de contenu approprié de p7 lui-même ou de sa sous-structure appropriée, qui peut être de type SignedData, EnvelopedData, SignedAndEnvelopedData, DigestedData, ou des données arbitraires. Le manuel PKCS7_dataFinal(3) explique dans quel champ exactement les données sont placées.

Les flags suivants sont reconnus :

PKCS7_BINARY
Copie les données verbatim sans modifier aucun octet. Par défaut, les fins de ligne sont remplacées par des séquences de deux octets "\r\n" (ASCII CR+LF). Si ce drapeau est défini, PKCS7_TEXT est ignoré.
PKCS7_TEXT
Prépare "Content-Type: text/plain"> suivi d'une ligne vide aux données. Ce drapeau est ignoré si PKCS7_BINARY est également défini.

Si d'autres bits sont définis dans flags, par exemple PKCS7_STREAM ou PKCS7_PARTIAL, ils sont ignorés, permettant de passer le même argument flags qui était déjà passé à PKCS7_sign(3) ou PKCS7_encrypt(3).

PKCS7_final() est le plus souvent utilisé pour finaliser un objet p7 retourné par un appel à PKCS7_sign(3) qui a utilisé des flags incluant PKCS7_PARTIAL ou PKCS7_STREAM. Avec ces drapeaux, PKCS7_sign(3) ignore son argument data. L'objet partiel p7 retourné peut alors être personnalisé, par exemple en configurant plusieurs signataires ou des algorithmes de hachage non par défaut avec PKCS7_sign_add_signer(3), avant d'appeler PKCS7_final().

De même, PKCS7_final() peut être utilisé pour finaliser un objet p7 retourné par un appel à PKCS7_encrypt(3) qui a utilisé des flags incluant PKCS7_STREAM.

Puisque PKCS7_final() commence par appeler PKCS7_dataInit(3) en interne, l'utiliser pour finaliser un objet p7 contenant SignedAndEnvelopedData, DigestedData, ou des données arbitraires nécessite la configuration décrite dans le manuel PKCS7_dataInit(3). Pour SignedData et EnvelopedData, une telle configuration manuelle est également réalisable, mais elle est plus facilement effectuée avec PKCS7_sign(3) ou PKCS7_encrypt(3), respectivement.

PKCS7_final() n'est qu'une parmi plusieurs fonctions qui peuvent être utilisées pour finaliser p7 ; les alternatives incluent SMIME_write_PKCS7(3), PEM_write_bio_PKCS7_stream(3), et i2d_PKCS7_bio_stream(3).

VALEURS DE RETOUR

PKCS7_final() retourne 1 en cas de succès ou 0 en cas d'échec.

Les raisons possibles d'échec incluent :

  • p7 est NULL.
  • Le champ content de p7 est vide.
  • Le contentType de p7 n'est pas pris en charge.
  • La signature ou le hachage est demandé et p7 n'est pas configuré pour stocker une signature détachée, mais ne contient pas non plus le champ requis pour stocker le contenu.
  • Au moins un signataire manque d'un algorithme de hachage utilisable.
  • Un chiffrement est requis mais aucun n'est configuré.
  • Toute opération requise échoue, par exemple la signature ou le hachage.
  • L'allocation de mémoire échoue.

Les signataires sans clés privées ne provoquent pas d'échec mais sont silencieusement ignorés.

VOIR AUSSI

HISTORIQUE

PKCS7_final() est apparu pour la première fois dans OpenSSL 1.0.0 et est disponible depuis OpenBSD 4.9.

CAVEATS

Cette fonction ne prend pas en charge EncryptedData.
