EVP_PKEY_NEW_CMAC_KEY(3) Manuel de la bibliothèque EVP_PKEY_NEW_CMAC_KEY(3)

NOM

EVP_PKEY_new_CMAC_key — CMAC dans le framework EVP

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/evp.h>

EVP_PKEY *
EVP_PKEY_new_CMAC_key(ENGINE *engine, const unsigned char *key, size_t key_len, const EVP_CIPHER *cipher);

DESCRIPTION

EVP_PKEY_new_CMAC_key() alloue une nouvelle structure EVP_PKEY, lui attribue le type EVP_PKEY_CMAC, et la configure comme un wrapper autour des fonctions de bas niveau documentées dans CMAC_Init(3) en utilisant le chiffrement par blocs cipher avec la clé symétrique d'une longueur de key_len octets.

Les fonctions pour obtenir des objets EVP_CIPHER adéquats sont listées dans la section CIPHER LISTING de la page man EVP_EncryptInit(3). Utilisez toujours un objet qui implémente le mode d'opération CBC. Comme dans CMAC_Init(3), seuls les chiffrements avec une taille de bloc de 64 ou 128 bits sont pris en charge par cette implémentation.

L'argument engine est ignoré ; il est recommandé de passer NULL.

VALEURS DE RETOUR

EVP_PKEY_new_CMAC_key() retourne la structure EVP_PKEY nouvellement allouée ou NULL en cas d'erreur.

EXEMPLES

Le code suivant chiffre un message avec AES-CMAC en utilisant la longueur de clé de 128 bits spécifiée dans la RFC 4493.

/* Clé bidon : normalement, elle serait définie à partir d'une autre source. */
const unsigned char key[] = "clé secrète symétrique";
const size_t key_len = strlen(key);  /* 16 = 128/8 */

const char *msg = "Bonjour le monde !";
const size_t msg_len = strlen(msg);

unsigned char out_mac[16];
size_t out_len = sizeof(out_mac);
size_t i;

EVP_PKEY *pkey;
EVP_MD_CTX *md_ctx;

pkey = EVP_PKEY_new_CMAC_key(NULL, key, key_len, EVP_aes_128_cbc());
if (pkey == NULL)
	err(1, "EVP_PKEY_new_CMAC_key");
md_ctx = EVP_MD_CTX_new();
if (md_ctx == NULL)
	err(1, "EVP_MD_CTX_new");

if (EVP_DigestSignInit(md_ctx, NULL, NULL, NULL, pkey) == 0)
	err(1, "EVP_DigestSignInit");
if (EVP_DigestSign(md_ctx, out_mac, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign");
EVP_MD_CTX_free(md_ctx);
EVP_PKEY_free(pkey);

printf(" MAC = ");
for (i = 0; i < out_len; i++)
	printf("%02x:", out_mac[i]);
printf("\n");

Considérez les détails suivants :

  • Même si le nom de type EVP_PKEY était à l'origine censé signifier « clé privée » et que l'API EVP_DigestSignInit(3) a été conçue pour les signatures numériques dans le contexte de la cryptographie à clé publique, les deux sont également utilisés ici car un MAC nécessite également une clé, même s'il s'agit d'une clé symétrique.
  • Contrairement à la signature numérique qui nécessite à la fois un algorithme de hachage et une clé privée, l'algorithme CMAC ne nécessite qu'un chiffrement par bloc et une clé partagée, tous deux stockés dans la structure quelque peu détournée EVP_PKEY. Par conséquent, l'argument EVP_MD *type de EVP_DigestSignInit(3) doit être défini sur NULL.
  • La taille du condensat de message résultant est égale à la taille de bloc du chiffrement utilisé.
  • La fonction EVP_DigestSignInit(3) ne transfère pas la propriété de l'objet pkey à md_ctx mais incrémente simplement le compteur de références. Par conséquent, l'appelant est responsable de la libération de l'objet EVP_PKEY lorsqu'il n'est plus nécessaire.
