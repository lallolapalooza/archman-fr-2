NOM

libpbm - fonctions libnetpbm pour lire et écrire des fichiers image PBM

SYNOPIS

#include <netpbm/pbm.h>

bit **pbm_allocarray(int cols, int rows);

bit *pbm_allocrow(int cols);

pbm_freearray(bit **bits, int rows);

pbm_freerow(bit *bitrow);

void pbm_readpbminit(FILE * fp, int *colsP, int *rowsP, int *formatP);

void pbm_readpbmrow(FILE * fp, bit *bitrow, int cols, int format);

void pbm_readpbmrow_packed(FILE * fp, unsigned char * const packed_bits, const int cols, const int format);

bit** pbm_readpbm(FILE * fp, int *colsP, int *rowsP);

void pbm_writepbminit(FILE * fp, int cols, int rows, int forceplain);

void pbm_writepbmrow(FILE * fp, bit *bitrow, int cols, int forceplain);

void pbm_writepbmrow_packed(FILE * fp, unsigned char * const packed_bits, const int cols, const int forceplain);

void pbm_writepbm(FILE * fp, bit **bits, int cols, int rows, int forceplain);

#define pbm_packed_bytes(cols) ...

void pbm_nextimage( FILE *file, int * const eofP);

void pbm_check( FILE * file, const enum pm_check_type check_type, const int format, const int cols, const int rows, enum pm_check_code * const retval);

DESCRIPTION

Ces fonctions de bibliothèque font partie de Netpbm(1)

TYPES ET CONSTANTES

typedef ... bit;

#define PBM_WHITE ...

#define PBM_BLACK ...

Chaque bit ne doit contenir que les valeurs PBM_WHITE ou PBM_BLACK.

#define PBM_FORMAT ...

#define RPBM_FORMAT ...

#define PBM_TYPE PBM_FORMAT

#define PBM_FORMAT_TYPE(f) ...

Ceux-ci servent à distinguer les différents formats et types de fichiers.

INITIALISATION

pbm_init() est obsolète (au moins depuis Netpbm 9.25 (mars 2002)). Utilisez pm_proginit() à la place.

pbm_init() est identique à pm_proginit.

GESTION DE LA MÉMOIRE

pbm_allocarray() alloue un tableau de bits. pbm_allocrow() alloue une ligne du nombre de bits donné. pbm_freearray() libère le tableau alloué avec pbm_allocarray() contenant le nombre de lignes donné. pbm_freerow() libère une ligne de bits.

LECTURE DES FICHIERS IMAGE PBM

pbm_readpbminit() lit l'en-tête d'une image PBM dans un fichier PBM, remplissant les variables lignes, colonnes et format. pbm_readpbmrow() lit une ligne de bits dans le tableau bitrow. Le format et le nombre de colonnes ont été remplis par pbm_readpbminit().

pbm_readpbmrow_packed() est comme pbm_readpbmrow() sauf qu'au lieu de retourner un tableau de bits, il retourne un tableau packed_bits d'octets contenant les pixels de la ligne de l'image empaquetés. Les pixels sont dans l'ordre de gauche à droite sur la ligne et du début du tableau à la fin. Dans un octet, les bits sont dans l'ordre du bit le plus significatif au bit le moins significatif. Si le nombre de pixels de la ligne n'est pas un multiple de 8, le dernier octet retourné est complété sur le côté du bit le moins significatif avec des bits indéfinis. Le blanc est représenté par un bit PBM_WHITE; le noir par PBM_BLACK.

pbm_readpbm() lit un fichier bitmap entier en mémoire, retournant le tableau alloué et remplissant les variables lignes et colonnes. Cette fonction combine pbm_readpbminit(), pbm_allocarray() et pbm_readpbmrow().

pbm_readpbminit() et pbm_readpbm arrêtent le programme avec un message sur la sortie d'erreur standard si l'en-tête de l'image PBM n'est pas syntaxiquement valide, y compris s'il contient un nombre trop grand pour être traité à l'aide des structures de données normales du système (c'est-à-dire, un nombre qui ne rentre pas dans un 'int' C).

ppm_readppminit() et ppm_readppm arrêtent le programme avec un message sur la sortie d'erreur standard si l'en-tête de l'image PPM n'est pas syntaxiquement valide, y compris s'il contient un nombre trop grand pour être traité à l'aide des structures de données normales du système (c'est-à-dire, un nombre qui ne rentre pas dans un 'int' C).

ÉCRITURE DES FICHIERS IMAGE PBM

pbm_writepbminit() écrit l'en-tête d'une image PBM dans un fichier PBM. forceplain est une valeur booléenne spécifiant qu'un fichier au format brut (texte) doit être écrit, par opposition à un format binaire (cru). pbm_writepbmrow() écrit une ligne dans un fichier PBM. pbm_writepbmrow_packed() est identique à pbm_writepbmrow() sauf que vous fournissez la ligne à écrire sous forme d'un tableau d'octets empaquetés avec des bits au lieu d'un tableau bits. Le format de packed_bits est le même que celui retourné par pbm_readpbmrow().

pbm_writepbm() écrit l'en-tête et toutes les données d'une image PBM dans un fichier PBM. Cette fonction combine pbm_writepbminit() et pbm_writepbmrow().

DIVERS

pbm_nextimage() positionne un fichier d'entrée PBM à la prochaine image qu'il contient (de sorte qu'un appel ultérieur à pbm_readpbminit() lise son en-tête).

Immédiatement avant un appel à pbm_nextimage(), le fichier doit être positionné soit à son début (c'est-à-dire que rien n'a encore été lu du fichier), soit juste après une image (c'est-à-dire tel que laissé par un appel à pbm_readpbmrow() de la dernière ligne de l'image).

Notez que dans les formats bruts PNM et PAM, la prochaine image commence toujours immédiatement après l'image précédente, donc tout ce que fait réellement pbm_nextimage() est de vérifier s'il y a une image suivante ou si le fichier est positionné en fin de fichier. Cependant, en PNM brut, il peut y avoir des espaces blancs entre les images.

Si pbm_nextimage() positionne avec succès à la prochaine image, il retourne *eofP à faux (0). S'il n'y a pas d'image suivante dans le fichier, il retourne *eofP à vrai. S'il ne peut pas positionner ou déterminer l'état du fichier en raison d'une erreur de fichier, il lève une erreur .

pbm_check() vérifie l'erreur courante d'intégrité de fichier où la taille du fichier est incorrecte pour contenir toutes les données de l'image. pbm_check() suppose que le fichier est positionné après un en-tête d'image (comme si pbm_readpbminit() était la dernière opération sur le fichier). Il vérifie la taille du fichier pour voir si le nombre d'octets restants dans le fichier correspond au nombre requis pour contenir le raster de l'image. Si le fichier est trop court, pbm_check() provoque l'arrêt du programme avec un message sur la sortie d'erreur standard. Sinon, il retourne l'une des valeurs suivantes (énumérations du type enum pm_check_code) dans *retval:

PM_CHECK_OK
La taille du fichier est exactement celle requise pour contenir le raster de l'image.
PM_CHECK_UNKNOWN_TYPE
format n'est pas un format dont la taille peut être vérifiée par pbm_check().
PM_CHECK_TOO_SMALL
Il y a moins d'octets dans le fichier qu'il n'en faut pour contenir le raster de l'image.
PM_CHECK_TRUNCATED
Le fichier ne contient pas assez d'octets pour le raster de l'image.
PM_CHECK_TOO_LARGE
Il y a plus d'octets dans le fichier qu'il n'en faut pour contenir le raster de l'image.

anticiper. Le seul format avec lequel pbm_check() peut traiter est le format PBM brut.
PM_CHECK_TOO_LONG
Le fichier est plus long qu'il ne devrait l'être pour contenir le raster de l'image. Les données supplémentaires peuvent constituer une autre image.
PM_CHECK_UNCHECKABLE
Le fichier n'est pas d'un type dont la taille est prévisible, il n'y a donc aucun moyen simple pour pbm_check() de savoir si sa taille est correcte. Seul un fichier régulier a une taille prévisible. Un pipe est un exemple courant de fichier qui n'en a pas.

check_type doit avoir la valeur PM_CHECK_BASIC (une valeur énumérée du type énuméré pm_check_type). Sinon, l'effet de pbm_check() est imprévisible. Cet argument existe pour une future expansion rétrocompatible de la fonction de pbm_check().
