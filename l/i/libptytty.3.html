libptytty(3) LIBPTYTTY libptytty(3)

NOM

libptytty - Gestion indépendante du système d'exploitation et sécurisée des pty/tty et des bases de données utmp/wtmp/lastlog

SYNOPSIS

cc ... -lptytty
#include <libptytty.h>
// C++
ptytty *pty = ptytty::create ();
if (!pty->get ())
  // erreur d'allocation de pty
if (nous voulons utmp)
  pty->login (process_pid, 0, "remote.host");
else if (nous voulons utmp ET wtmp/lastlog)
  pty->login (process_pid, 1, "remote.host");
// nous avons terminé
delete pty;
// C
PTYTTY pty = ptytty_create ();
if (!ptytty_get (pty))
  // erreur d'allocation de pty
if (nous voulons utmp)
  ptytty_login (pty, process_pid, 0, "remote.host");
else if (nous voulons utmp ET wtmp/lastlog)
  ptytty_login (pty, process_pid, 1, "remote.host");
// nous avons terminé
ptytty_delete (pty);

Voir aussi le répertoire eg/, qui contient actuellement le fichier c-sample.c qui lance un shell de connexion depuis C en utilisant libptytty.

DESCRIPTION

Libptytty est une petite bibliothèque qui offre une gestion de pseudo-tty de manière indépendante du système d'exploitation. Elle a été créée par frustration face aux nombreuses différences de gestion des pty/tty dans différents systèmes d'exploitation pour être utilisée à l'intérieur de "rxvt-unicode".

En plus de la simple gestion des pty/tty, elle offre également un support des bases de données de sessions (mises à jour utmp et optionnelles de wtmp/lastlog pour les shells de connexion).

Elle supporte également le fork après le démarrage et la chute des privilèges dans le processus appelant. Ainsi, si le processus appelant est compromis par l'utilisateur lançant le programme, il y a moins à gagner, car seul le processus d'aide s'exécute avec les privilèges (par ex. setuid/setgid), ce qui réduit considérablement la surface d'attaque.

Libptytty est écrite en C++, mais elle offre également une API exclusivement en C.

INSTALLATION

Libptytty utilise "CMake" comme système de construction. Pour construire libptytty, installez "CMake" et exécutez les commandes suivantes depuis le répertoire source de libptytty ou un répertoire de build séparé :

cmake -DCMAKE_INSTALL_PREFIX=<prefix> -DBUILD_SHARED_LIBS=ON <path/to/libptytty>
cmake --build .
cmake --install .

CONSIDÉRATIONS DE SÉCURITÉ

Il est primordial que vous lisiez au moins le paragraphe suivant !

Si vous écrivez un programme typique de type terminal qui souhaite juste un ou plusieurs pty, vous devriez appeler la méthode "ptytty::init ()" (en C : fonction "ptytty_init ()") comme toute première chose dans votre programme :

int main (int argc, char *argv[])
{
   // ne rien faire ici
   ptytty::init ();
   // en C : ptytty_init ();
   // initialiser, analyser les arguments, etc.
}

Cela vérifie si le programme s'exécute avec des permissions setuid ou setgid. Si c'est le cas, il lancera un processus auxiliaire et dropera les privilèges.

Certains programmes nécessitent un contrôle plus fin sur si et quand ce processus auxiliaire est lancé, et si et comment les privilèges sont dropés. Pour ces programmes, les méthodes "ptytty::use_helper" et "ptytty::drop_privileges" (et potentiellement "ptytty::sanitise_stdfd") sont plus utiles.

INTERFACE C++ : LA CLASSE ptytty

MÉTHODES STATIQUES

ptytty::init ()
La manière par défaut d'initialiser libptytty. Doit être appelée immédiatement, comme première chose dans la fonction "main", ou plus tôt, par ex. lors de la construction statique. Plus tôt, c'est mieux.

Cette méthode appelle "sanitise_stdfd" puis vérifie si le programme s'exécute avec des permissions setuid/setgid et, si oui, lance un processus auxiliaire pour la gestion du pty/tty. Il drope ensuite complètement les privilèges, de sorte que le programme réel s'exécute sans privilèges setuid/setgid.

En cas d'échec, cette méthode lance une exception "ptytty_error".

ptytty::use_helper ()
Tente de démarrer un processus auxiliaire qui conserve les privilèges même quand le processus appelant ne le fait pas. Ceci est généralement appelé depuis "ptytty::init" lorsqu'il détecte que le programme s'exécute en setuid ou setgid, mais peut être appelé manuellement s'il est gênant de dropper les privilèges au démarrage, ou lorsque vous ne vous exécutez pas en setuid/setgid mais que vous souhaitez dropper les privilèges (par ex. en tant que démon lancé par root).

Cette méthode essaiera de ne pas lancer plus d'un processus auxiliaire. Le même processus auxiliaire peut généralement être utilisé à la fois par le processus qui le démarre et par tous ses enfants forkés (non execés).

En cas d'échec, cette méthode lance une exception "ptytty_error".

ptytty::drop_privileges ()
Drope complètement les privilèges, c'est-à-dire qu'il définit les identifiants utilisateur réels, effectifs et sauvegardés à l'identifiant utilisateur réel. Utile pour s'assurer que le processus ne s'exécute pas avec des privilèges spéciaux.

En cas d'échec, cette méthode lance une exception "ptytty_error".

ptytty::sanitise_stdfd ()
Vérifie si les descripteurs de fichiers 0, 1 et 2 (stdin, stdout et stderr) sont valides (ouverts) et, si ce n'est pas le cas, les connecte à /dev/tty ou /dev/null si possible. Ceci est nécessaire car libptytty pourrait vouloir sortir des messages d'erreur sur ces descripteurs, qui au moment de la sortie de l'erreur, pourraient être connectés à quelque chose d'inapproprié ouvert par le programme inconscient lui-même (ceci peut être une faille de sécurité).

En cas d'échec, cette méthode lance une exception "ptytty_error".

bool success = ptytty::send_fd (int socket, int fd)
Méthode utilitaire pour envoyer un descripteur de fichier via un socket de domaine Unix. Renvoie vrai si succès, faux sinon. Cette méthode est seulement exposée pour votre commodité et n'est pas requise pour un fonctionnement normal.
int fd = ptytty::recv_fd (int socket)
Méthode utilitaire pour recevoir un descripteur de fichier via un socket de domaine Unix. Renvoie le fd en cas de succès et "-1" sinon. Cette méthode est seulement exposée pour votre commodité et n'est pas requise pour un fonctionnement normal.
ptytty *pty = ptytty::create ()
Crée un nouvel objet ptytty. La création ne fait encore rien d'autre que d'allouer la structure.

Une méthode statique est utilisée car l'implémentation réelle de ptytty peut différer à l'exécution, vous avez donc besoin d'une installation de création d'objet dynamique.

MEMBRES DE DONNÉES / MÉTHODES DYNAMIQUES / LIÉES À LA SESSION

int pty_fd = pty->pty
int tty_fd = pty->tty
Ces membres contiennent les descripteurs de fichiers pty et tty, respectivement. Ils contiennent initialement "-1" jusqu'à un appel réussi à "ptytty::get".

libptytty(3) — libptytty 2.0

NAME

libptytty - pseudo-terminal handling library

SYNOPSIS

    #include <ptytty.h>

    // C++ Interface
    class ptytty;
    ptytty::init ();
    ptytty *pty = ptytty::create ();
    int pty = pty->pty;
    int tty = pty->tty;
    bool success = pty->get ();
    pty->login (cmd_pid, login_shell, hostname);
    pty->close_tty ();
    bool success = pty->make_controlling_tty ();
    pty->set_utf8_mode (on);
    ptytty::drop_privileges ();
    ptytty::use_helper ();
    delete pty;

    // C Interface
    typedef struct ptytty *PTYTTY;
    ptytty_init ();
    PTYTTY ptytty_create ();
    int ptytty_pty (PTYTTY ptytty);
    int ptytty_tty (PTYTTY ptytty);
    int ptytty_get (PTYTTY ptytty);
    void ptytty_login (PTYTTY ptytty, int cmd_pid, int login_shell, const char *hostname);
    void ptytty_close_tty (PTYTTY ptytty);
    int ptytty_make_controlling_tty (PTYTTY ptytty);
    void ptytty_set_utf8_mode (PTYTTY ptytty, int on);
    void ptytty_drop_privileges ();
    void ptytty_use_helper ();
    void ptytty_delete (PTYTTY ptytty);

DESCRIPTION

The libptytty library provides a portable interface for pseudo-terminal handling. It abstracts away the differences between various Unix-like operating systems and provides a simple API for creating, managing, and using pseudo-terminals.

A pseudo-terminal (pty) is a pair of devices, a master device and a slave device. The slave device behaves like a physical terminal (e.g. /dev/tty), while the master device is used by a program to control the slave device. Typically, a program like `sshd` or `login` will create a pty, fork a child process, make the slave device the controlling terminal of the child process, and then attach the master device to the child's standard input, output, and error streams.

libptytty offers both a C++ interface (using a class `ptytty`) and a C interface (using functions like `ptytty_create`). The C++ interface is generally preferred for its object-oriented approach and automatic resource management (RAII).

INSTALLATION

libptytty is available in the Arch Linux repositories as the `libptytty` package.

    pacman -S libptytty

To use the library in your C or C++ projects, you need to link against it:

    gcc your_program.c -lptytty -o your_program
    g++ your_program.cpp -lptytty -o your_program

SECURITY CONSIDERATIONS

When creating pseudo-terminals, especially for processes that will be running with elevated privileges or handling user input, it is crucial to properly configure and clean up the terminal environment. The `ptytty` library provides functions like `make_controlling_tty` and `drop_privileges` to aid in secure usage.

Always ensure that file descriptors are closed appropriately and that any sensitive information is handled with care. The `ptytty_delete` function (or `delete pty` in C++) should be called to release resources when the pseudo-terminal is no longer needed.

C++ INTERFACE: THE ptytty CLASS

ptytty::init ()
Initializes the library. This function must be called before any other `ptytty` functions or methods. It is safe to call multiple times.
ptytty *ptytty::create ()
Creates and returns a new `ptytty` object. Returns `nullptr` on failure. The caller is responsible for `delete`-ing the returned object when it's no longer needed.
int ptytty::pty () const
Returns the file descriptor for the master side of the pseudo-terminal.
int ptytty::tty () const
Returns the file descriptor for the slave side of the pseudo-terminal.
bool ptytty::get ()
Initializes the pseudo-terminal pair, setting up necessary structures for login information. Returns `true` on success, `false` on failure. This is implicitly called by `create()`.
void ptytty::login (int cmd_pid, bool login_shell, const char *hostname)
Updates the utmp/wtmp databases to record the login session. This is typically called after successfully creating the pty/tty pair and forking the child process.

cmd_pid is the process ID of the command being executed in the new session.

login_shell should be `true` if the spawned process is a login shell (e.g., `/bin/bash --login`), and `false` otherwise.

hostname is the value of the `REMOTEHOST` environment variable or the actual remote "hostname" the user logs in from, which often is the value of the "DISPLAY" variable or tty line in case of local logins.

Calling this method is optional. A session starts at the time of the login call and extends until the ptytty object is destroyed.

pty->close_tty ()
Closes the tty. Useful after forking in the parent/pty process.
bool success = pty->make_controlling_tty ()
Tries to make the pty/tty pair the controlling terminal of the current process. Useful after forking in the child/tty process.
pty->set_utf8_mode (bool on)
On systems supporting special UTF-8 line disciplines (e.g. Linux), this tries to enable this discipline for the given pty. Can be called at any time to change the mode.

C INTERFACE: THE ptytty FAMILY OF FUNCTIONS

ptytty_init ()
See "ptytty::init ()".
PTYTTY ptytty_create ()
Creates a new opaque PTYTTY object and returns it. Do not try to access it in any way except by testing it for truthness (e.g. "if (pty) ...."). See "ptytty::create ()".
int ptytty_pty (PTYTTY ptytty)
Return the pty file descriptor. See "pty->pty".
int ptytty_tty (PTYTTY ptytty)
Return the tty file descriptor. See "pty->tty".
void ptytty_delete (PTYTTY ptytty)
Destroys the PTYTTY object, freeing the pty/tty pair and cleaning up the utmp/wtmp/lastlog databases, if initialised/used. Same as "delete pty" in C++.
int ptytty_get (PTYTTY ptytty)
See "pty->get", returns 0 in case of an error, non-zero otherwise.
void ptytty_login (PTYTTY ptytty, int cmd_pid, int login_shell, const char *hostname)
See "pty->login". Note that the `login_shell` parameter is an integer (`0` for false, non-zero for true) in the C interface, corresponding to the boolean `login_shell` in the C++ interface.
void ptytty_close_tty (PTYTTY ptytty)
See "pty->close_tty".
int ptytty_make_controlling_tty (PTYTTY ptytty)
See "pty->make_controlling_tty". Returns 0 on failure, non-zero on success.
void ptytty_set_utf8_mode (PTYTTY ptytty, int on)
See "pty->set_utf8_mode". The `on` parameter is an integer (`0` for false, non-zero for true).
void ptytty_drop_privileges ()
See "ptytty::drop_privileges".
void ptytty_use_helper ()
See "ptytty::use_helper".
