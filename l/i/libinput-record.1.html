libinput-record(1) Manuel des commandes générales libinput-record(1)

NOM

libinput-record - enregistrer les événements du noyau

SYNTAXE

libinput record [options] [/dev/input/event0 [/dev/input/event1 ...]]

DESCRIPTION

L'outil libinput record enregistre les événements du noyau d'un périphérique et les affiche dans un format qui peut être relu plus tard avec l'outil libinput replay(1). Cet outil doit être exécuté en tant que root pour lire depuis le périphérique.

La sortie de cet outil est au format YAML, voir la section FORMAT DE FICHIER pour plus de détails. Par défaut, il imprime sur la sortie standard sauf si un fichier de sortie est fourni. Par exemple, voici des invocations valides :

libinput record /dev/input/event3 touchpad.yml

libinput record recording.yml

libinput record --all all-devices.yml

libinput record /dev/input/event3 /dev/input/event4 tp-and-keyboard.yml

Les événements enregistrés sont indépendants de libinput lui-même ; la mise à jour ou la suppression de libinput ne changera pas le flux d'événements.

OPTIONS

Si un ou plusieurs nœuds de périphériques sont fournis, cet outil ouvre ces nœuds de périphériques. Sinon, une liste de périphériques est présentée et l'utilisateur peut sélectionner le périphérique à enregistrer. En cas de doute, exécutez sans aucun argument.

--help
Affiche l'aide.
--all
Enregistre tous les périphériques /dev/input/event* disponibles sur le système. Cette option ne doit être utilisée que dans des cas exceptionnels, le fichier de sortie est presque toujours trop bruyant et la relecture de l'enregistrement peut ne pas être possible. Cette option nécessite --output-file et aucun nœud de périphérique ne peut être fourni en ligne de commande.
--autorestart=s
Termine l'enregistrement en cours après s secondes d'inactivité du périphérique. Cette option nécessite que --output-file soit spécifié. Le nom du fichier de sortie est utilisé comme préfixe, suffixé par la date et l'heure de l'enregistrement. Le délai d'attente doit être supérieur à 0.
-o filename.yml
--output-file=filename.yml
Spécifie le fichier de sortie à utiliser. Si --autorestart est donné, le nom du fichier est utilisé uniquement comme préfixe. Lorsque --output-file n'est pas donné et que le premier ou le dernier argument n'est pas un périphérique d'entrée, le premier ou le dernier argument sera le fichier de sortie.
--grab
Capture exclusivement tous les périphériques ouverts. Cela empêchera les événements d'être délivrés au système hôte.
--show-keycodes
Affiche les codes de touches tels quels dans l'enregistrement. Par défaut, les touches courantes sont obfusquées et imprimées comme KEY_A pour éviter les fuites d'informations.
--with-libinput
Enregistre les événements libinput aux côtés des événements du périphérique. CETTE FONCTIONNALITÉ EST EXPÉRIMENTALE. Voir la section ENREGISTREMENT DES ÉVÉNEMENTS LIBINPUT pour plus de détails.
--with-hidraw
Enregistre les événements hidraw aux côtés des événements du périphérique. NE TAPEZ PAS DE DONNÉES SENSIBLES. Voir la section ENREGISTREMENT DES RAPPORTS HID pour plus de détails.

ENREGISTREMENT DE PÉRIPHÉRIQUES MULTIPLES

Il est parfois nécessaire d'enregistrer simultanément les événements de plusieurs périphériques, par exemple lorsqu'une interaction entre un pavé tactile et un clavier provoque un bug. libinput record enregistre plusieurs périphériques avec un décalage temporel identique, permettant une relecture correcte de l'interaction.

Si plusieurs périphériques sont enregistrés, un nom de fichier de sortie doit être fourni.

Tous les périphériques à enregistrer doivent être fournis en ligne de commande, une invocation d'exemple est :

libinput record -o tap-bug /dev/input/event3 /dev/input/event7

Notez que lors de l'enregistrement de plusieurs périphériques, seul le premier périphérique est imprimé immédiatement, tous les autres périphériques et leurs événements sont imprimés à la sortie.

ENREGISTREMENT DES ÉVÉNEMENTS LIBINPUT

Lorsque l'option de ligne de commande --with-libinput est donnée, libinput-record initialise un contexte libinput pour les périphériques en cours d'enregistrement. Les événements de ces contextes sont imprimés à côté des événements evdev. CETTE FONCTIONNALITÉ EST EXPÉRIMENTALE.

Le but principal de cette fonctionnalité est le débogage et l'analyse d'événements ; aucun appelant ne doit se fier à un format d'événement spécifique.

Notez que bien que libinput et libinput-record voient les mêmes événements à partir des nœuds de périphériques, aucune garantie ne peut être donnée quant à l'ordre correct des événements. Les événements libinput peuvent arriver plus tôt ou plus tard que les événements des nœuds de périphériques et pour certains périphériques, libinput peut modifier le flux d'événements en interne avant le traitement.

Notez que le contexte libinput créé par libinput-record n'affecte pas la session de bureau en cours et ne copie pas (ne peut pas copier !) les options de configuration de cette session.

ENREGISTREMENT DES RAPPORTS HID

Lorsque l'option de ligne de commande --with-hidraw est donnée, libinput-record recherche les nœuds hidraw des périphériques donnés et imprime tous les rapports HID entrants de ces périphériques.

Les rapports HID ne sont pas obfusqués et une personne suffisamment motivée pourrait récupérer les frappes au clavier à partir des journaux. Ne tapez pas de mots de passe lors de l'enregistrement des rapports HID.

Les clés de premier niveau sont listées ci-dessous, voir la sous-section respective pour les détails sur chaque clé.
version: int
La version du format de fichier. Cette version n'est augmentée qu'en cas de changements rétroactivement incompatibles. Un analyseur doit ignorer les clés inconnues pour être rétrocompatible.
ndevices: int
Le nombre d'enregistrements de périphériques dans ce fichier. Toujours 1 sauf si enregistré avec --multiple
libinput: {...}
Un dictionnaire avec des informations spécifiques à libinput.
system: {...}
Un dictionnaire avec des informations système.
devices: {...}
Une liste de périphériques contenant la description et les événements de chaque périphérique.

libinput

version: string
Version de libinput

system

Informations sur le système

os: string
ID de distribution et version, voir os-release(5)
kernel: string
Version du noyau, voir uname(1)
dmi: string
Modalias DMI, voir /sys/class/dmi/id/modalias

devices

Informations et événements provenant des nœuds de périphérique enregistrés

node: string
le nœud de périphérique enregistré
evdev
Un dictionnaire avec les informations du périphérique evdev.
hid
Une liste d'entiers représentant les octets du descripteur de rapport HID.
udev
Un dictionnaire avec les informations du périphérique udev.
events
Une liste de dictionnaires avec les événements enregistrés

evdev

name: string
Le nom du périphérique
id: [bustype, vendor, product, version]
Les données de la struct input_id, bustype, vendor, product, version.
codes: {type: [a, b, c ], ...}
Tous les types et codes evdev sous forme de dictionnaire imbriqué. Le type evdev est la clé, les codes sont une liste.
absinfo: {code: [min, max, fuzz, flat, resolution], ...}
Un tableau de tableaux avec 6 éléments décimaux chacun, dénotant le contenu d'une struct input_absinfo. Le premier élément est le code (par exemple, ABS_X) au format décimal.
properties: [0, 1, ...]
Tableau avec toutes les constantes INPUT_PROP_FOO. Peut être un tableau vide.

udev

properties: liste de chaînes
Une liste de propriétés udev au format key=value. Ce n'est pas la liste complète des propriétés attribuées au périphérique mais un sous-ensemble pertinent pour libinput. Ces propriétés peuvent inclure des propriétés définies sur un périphérique parent.
quirks: liste de chaînes
Une liste de corrections de périphériques au format key=value.

events

Une liste des événements enregistrés. La liste contient des dictionnaires Informations sur les événements. Le contenu est une liste de dictionnaires, avec la chaîne identifiant le type de séquence d'événements.

{ evdev: [ [sec, usec, type, code, value], ...] }
Chaque dictionnaire evdev contient le contenu d'une struct input_event au format décimal. Le dernier élément de la liste est toujours le SYN_REPORT de cette trame d'événement. La trame d'événement suivante commence une nouvelle entrée de dictionnaire evdev dans la liste parente events.
{ hid: hidrawX : [ 12, 34, 56 ], ...] }
Le dictionnaire hid contient les rapports hid au format décimal, avec le nœud hidraw comme clé. La clé spéciale time indique l'heure actuelle à laquelle le rapport a été lu depuis le noyau.

Notez que le noyau ne fournit pas d'horodatages pour les événements hidraw et que les horodatages fournis proviennent de clock_gettime(3). Ils peuvent être supérieurs à l'horodatage d'un événement evdev ultérieur.

NOTES

Cet outil enregistre les événements du noyau et est indépendant de libinput. En d'autres termes, la mise à jour ou la modification de libinput n'altérera pas la sortie de cet outil. libinput lui-même n'a pas besoin d'être en cours d'utilisation pour enregistrer des événements.
