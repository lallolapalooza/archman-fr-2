NOM

libppl - l'interface C++ de la Parma Polyhedra Library

SYNTAXE

#include <ppl.hh>

c++ fichier.cc -lppl

DESCRIPTION

Ceci est un bref aperçu de l'utilisation de la Parma Polyhedra Library (PPL) dans vos programmes C++ sur les systèmes de type Unix. Notez que la PPL a aussi des interfaces pour C, Java, OCaml et un certain nombre de systèmes Prolog : cherchez ailleurs la documentation sur ceux-ci. Notez également que le présent document ne décrit pas les fonctionnalités de la bibliothèque, ses classes ou ses méthodes et fonctions : consultez The Parma Polyhedra Library User's Manual (version 1.2) pour ce type d'information.

INCLUSION DU FICHIER D'ENTETE

L'interface C++ de la PPL n'a qu'un seul fichier d'en-tête, nommé ppl.hh. Votre programme devrait donc contenir une directive de la forme

#include <ppl.hh>

Bien sûr, vous devez vous assurer d'avoir installé la PPL dans un endroit où le compilateur peut la trouver, soit par lui-même, soit avec l'aide d'une option de ligne de commande appropriée -Idir (voir le fichier INSTALL pour savoir comment configurer la bibliothèque afin qu'elle soit installée à l'endroit de votre choix).

INITIALISATION ET FINALISATION DE LA BIBLIOTHEQUE

La simple inclusion de ppl.hh dans au moins un fichier de votre projet provoquera l'initialisation et la finalisation automatiques de la bibliothèque. Cependant, il existe des situations où l'initialisation et la finalisation automatiques ne sont pas souhaitables (par exemple, si l'application manipule les fonctions d'allocation mémoire de GMP). Dans ces cas, toute inclusion de ppl.hh doit prendre la forme

#define PPL_NO_AUTOMATIC_INITIALIZATION
#include <ppl.hh>

Lorsque l'initialisation et la finalisation automatiques sont désactivées, vous devez absolument appeler la fonction

void Parma_Polyhedra_Library::initialize()

avant d'utiliser la bibliothèque. Il est également de bonne pratique d'appeler la fonction

void Parma_Polyhedra_Library::finalize()

lorsque vous avez terminé avec la bibliothèque.

UTILISATION DE LA BIBLIOTHEQUE

En gardant à l'esprit qu'il n'y a pas de substitut à une lecture attentive de The Parma Polyhedra Library User's Manual (version 1.2), vous pouvez trouver de nombreux exemples d'utilisation dans les répertoires tests (voir le fichier README dans ce répertoire) et demos/ppl_lcdd de la distribution source.

LIAISON AVEC LA BIBLIOTHEQUE

La liaison avec l'interface C++ de la Parma Polyhedra Library se fait de préférence en utilisant le compilateur C++ lui-même : généralement, spécifier l'option de ligne de commande -lppl est suffisant. En fait, si vous utilisez une version partagée de la bibliothèque, cela enregistre automatiquement la dépendance de la bibliothèque GMP, ce que l'éditeur de liens devrait gérer avec succès. Sinon, vous devrez ajouter -lgmpxx -lgmp à la ligne de commande. Les choses sont plus complexes si vous avez installé la PPL dans un endroit non standard. Dans ce cas, vous devrez utiliser l'option -Ldir et, si vous utilisez une version partagée de la bibliothèque, éventuellement prendre des mesures supplémentaires : voir la documentation de votre système pour plus d'informations sur ce sujet (le Program Library HOWTO est particulièrement précieux pour les utilisateurs GNU/Linux).

MISE EN ŒUVRE DE CALCULS PROTÉGÉS PAR LA MÉMOIRE

Une des caractéristiques intéressantes de la Parma Polyhedra Library est la possibilité de mettre en œuvre des calculs protégés par la mémoire. L'idée est que vous pouvez limiter la quantité de mémoire virtuelle disponible pour le processus, lancer un calcul PPL, et être prêt à intercepter une exception std::bad_alloc. Puisque la bibliothèque est sûre en cas d'exception, vous pouvez prendre les mesures correctives appropriées (par exemple, simplifier les polyèdres et/ou sélectionner des algorithmes moins précis mais moins complexes), et relancer le calcul. Pour ce faire, vous devez définir des fonctions d'allocation mémoire alternatives pour GMP qui lèvent std::bad_alloc en cas d'épuisement de la mémoire. Par exemple :

#include <new>
#include <cstdlib>
extern "C" void*
cxx_malloc(size_t size) {
  void* p = malloc(size);
  if (p != 0 || size == 0)
    return p;
  throw std::bad_alloc();
}
extern "C" void*
cxx_realloc(void* q, size_t, size_t new_size) {
  void* p = realloc(q, new_size);
  if (p != 0 || new_size == 0)
    return p;
  throw std::bad_alloc();
}
extern "C" void
cxx_free(void* p, size_t) {
  free(p);
}

Ensuite, vous devez installer ces fonctions, ce qui peut se faire de deux manières différentes :

(1)
Si votre compilateur C++ prend en charge __attribute__ ((weak)) et que vous n'avez pas d'autres besoins spéciaux, vous pouvez simplement lier à votre application une fonction C ppl_set_GMP_memory_allocation_functions(void) telle que 
extern "C" void
ppl_set_GMP_memory_allocation_functions(void) {
  mp_set_memory_functions(cxx_malloc, cxx_realloc, cxx_free);
}

C'est tout ce que vous avez à faire, que vous utilisiez ou non la fonctionnalité d'initialisation automatique de la bibliothèque (voir ci-dessus) : dans tous les cas, la procédure d'initialisation appellera automatiquement ppl_set_GMP_memory_allocation_functions(void).

(2)
Si votre compilateur C++ ne prend pas en charge __attribute__ ((weak)), alors vous ne pouvez pas utiliser la fonctionnalité d'initialisation automatique de la bibliothèque (voir ci-dessus) et devez écrire un programme principal de la forme 
int main() {
  // L'ordre des appels de fonctions suivants est important.
  mp_set_memory_functions(cxx_malloc, cxx_realloc, cxx_free);
  Parma_Polyhedra_Library::initialize();
  ...
}

UTILISATION DES NOMBRES FLOTTANTS NATEFS

Au moment de l'initialisation, la Parma Polyhedra Library définit le mode d'arrondi du FPU d'une manière qui permet à ses calculs basés sur des nombres flottants d'être conservateurs (c'est-à-dire potentiellement approximés mais corrects) et raisonnablement efficaces. Dans le cas où votre application utilise elle-même des nombres flottants natifs et repose sur un mode d'arrondi particulier (en cas de doute, supposez qu'elle repose sur l'arrondi au plus près pour être efficace), vous devriez utiliser la fonction

void Parma_Polyhedra_Library::restore_pre_PPL_rounding()

après l'initialisation de la PPL et avant d'utiliser des nombres flottants natifs dans l'application. Si votre application n'utilise aucune abstraction PPL basée sur des nombres flottants, aucune autre mesure ne devrait être prise. Sinon, il est impératif d'appeler la fonction

void Parma_Polyhedra_Library::set_rounding_for_PPL()

avant d'invoquer toute interface PPL liée à de telles abstractions.
