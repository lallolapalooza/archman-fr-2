Liez avec -lcap.

DESCRIPTION

Ces fonctions primaires opèrent sur un état de capacité conservé dans la mémoire de travail et tentent de compléter l'API de l'espace utilisateur POSIX.1e (projet) pour les privilèges basés sur les capacités.

Un cap_t contient des informations sur les capacités dans chacun des trois ensembles, Permis, Héritable et Effectif. Chaque capacité dans un ensemble peut être effacée (désactivée, 0) ou définie (activée, 1).

Ces fonctions fonctionnent avec les types de données suivants :

cap_value_t
identifie une capacité, telle que CAP_CHOWN.
cap_flag_t
identifie l'un des trois drapeaux associés à une capacité (c'est-à-dire, il identifie l'un des trois ensembles de capacités). Les valeurs valides pour ce type sont CAP_EFFECTIVE, CAP_INHERITABLE ou CAP_PERMITTED.
cap_flag_value_t
identifie le paramétrage d'un drapeau de capacité particulier (c'est-à-dire, la valeur d'une capacité dans un ensemble). Les valeurs valides pour ce type sont CAP_CLEAR(0) ou CAP_SET(1).

VALEUR DE RETOUR

La valeur de retour est généralement spécifique à la fonction individuelle appelée. En cas d'échec, errno est défini de manière appropriée.

CONFORME À

Ces fonctions sont conformes à la spécification retirée du projet POSIX.1e. Les fonctions suivantes sont des extensions Linux : cap_clear_flag(), cap_drop_bound(), cap_fill(), cap_fill_flag(), cap_from_name(), cap_get_ambient(), cap_get_bound(), cap_get_mode(), cap_get_nsowner(), cap_get_secbits(), cap_mode_name(), cap_proc_root(), cap_prctl(), cap_prctlw(), cap_reset_ambient(), cap_setgroups(), cap_setuid(), cap_set_ambient(), cap_set_mode(), cap_set_nsowner(), cap_set_secbits(), cap_to_name() et cap_compare().

Sous Linux, une extension IAB des vecteurs de capacités Héritable, Bornes et Ambiant est également prise en charge par libcap. Ces fonctions sont décrites dans une page de manuel compagnon : cap_iab(3). De plus, pour gérer la complexité du lancement d'un sous-processus, libcap prend en charge l'abstraction : cap_launch(3).

En plus de l'API libcap préfixée par cap_, la bibliothèque fournit également des prototypes pour les appels système Linux qui fournissent l'API native pour les capacités de processus. Ces prototypes sont :

int capget(cap_user_header_t header, cap_user_data_t data);
int capset(cap_user_header_t header, const cap_user_data_t data);

De plus, libcap fournit une fonction de configuration,

void cap_set_syscall(
        long int (*new_syscall)(long int, long int, long int, long int),
        long int (*new_syscall6)(long int,
                                 long int, long int, long int,
                                 long int, long int, long int));

qui peut être utilisée pour rediriger son utilisation de capset() et d'autres appels système qui écrivent l'état géré par le noyau. Ceci est particulièrement utile lors de la prise en charge des sémantiques POSIX pour l'état de sécurité. Lorsqu'un programme est lié avec libpsx(3) tel que décrit dans cette page de manuel, cette fonction est utilisée pour connecter libcap aux appels système sémantiques POSIX.
