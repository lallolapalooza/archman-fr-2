DESCRIPTION

UI signifie User Interface (Interface Utilisateur) et constitue un ensemble de routines à usage général pour demander des informations textuelles à l'utilisateur. Grâce à des méthodes écrites par l'utilisateur (voir UI_create_method(3)), la demande d'informations peut être réalisée de toutes les manières imaginables, que ce soit par des invites textuelles simples, via des boîtes de dialogue ou depuis un téléphone portable.

Toutes les fonctions fonctionnent via un contexte de type UI. Ce contexte contient toutes les informations nécessaires pour une demande correcte ainsi qu'une référence à une UI_METHOD, qui est un vecteur ordonné de fonctions qui réalisent la demande effective.

La première chose à faire est de créer une UI avec UI_new() ou UI_new_method(), puis d'y ajouter des informations avec les fonctions UI_add_*() ou UI_dup_*(). De plus, des données aléatoires définies par l'utilisateur peuvent être transmises à la méthode sous-jacente par des appels à UI_add_user_data(). La méthode UI par défaut ne tient pas compte de ces données, mais d'autres méthodes pourraient le faire. Enfin, utilisez UI_process() pour effectuer réellement la demande et UI_get0_result() pour trouver le résultat de la demande.

Une UI peut contenir plus d'une demande, lesquelles sont effectuées dans l'ordre donné. Chaque demande reçoit un numéro d'index qui est retourné par les fonctions UI_add_*() et UI_dup_*(), et qui doit être utilisé pour obtenir le résultat correspondant avec UI_get0_result().

Les fonctions sont les suivantes :

UI_new() crée une nouvelle UI en utilisant la méthode UI par défaut. Une fois que vous avez terminé avec cette UI, elle doit être libérée à l'aide de UI_free().

UI_new_method() crée une nouvelle UI en utilisant la méthode UI donnée. Une fois que vous avez terminé avec cette UI, elle doit être libérée à l'aide de UI_free().

UI_free() libère la mémoire associée à la UI ui.

UI_add_input_string() ajoute une invite de chaîne de caractères à la UI ui. L'invite est affichée comme spécifié par prompt. Les drapeaux spécifiés par flags affectent la manière dont la chaîne est lue. Le résultat est stocké dans result_buf. Le argument minsize spécifie la longueur minimale autorisée pour la chaîne, et maxsize spécifie la longueur maximale.

UI_dup_input_string() est identique à UI_add_input_string(), mais duplique les chaînes de caractères plutôt que d'utiliser directement les pointeurs fournis.

UI_add_verify_string() ajoute une invite de vérification de chaîne de caractères. Elle fonctionne de manière similaire à UI_add_input_string(), mais la valeur entrée par l'utilisateur est comparée à la chaîne spécifiée par test_buf. Si les chaînes ne correspondent pas, la demande est répétée.

UI_dup_verify_string() est identique à UI_add_verify_string(), mais duplique les chaînes de caractères plutôt que d'utiliser directement les pointeurs fournis.

UI_add_input_boolean() ajoute une invite booléenne. L'invite est affichée comme spécifié par prompt. L'argument action_desc décrit l'action à effectuer. ok_chars et cancel_chars spécifient les caractères qui correspondent à une réponse "oui" et "non" respectivement. Les drapeaux spécifiés par flags affectent la manière dont la réponse est lue. Le résultat est stocké dans result_buf.

UI_dup_input_boolean() est identique à UI_add_input_boolean(), mais duplique les chaînes de caractères plutôt que d'utiliser directement les pointeurs fournis.

UI_add_info_string() ajoute une chaîne d'information à la UI ui. Les chaînes d'information sont généralement utilisées pour afficher des messages à l'utilisateur sans demander de réponse.

UI_dup_info_string() est identique à UI_add_info_string(), mais duplique la chaîne de caractères plutôt que d'utiliser directement le pointeur fourni.

UI_add_error_string() ajoute une chaîne d'erreur à la UI ui. Les chaînes d'erreur sont généralement utilisées pour afficher des messages d'erreur à l'utilisateur.

UI_dup_error_string() est identique à UI_add_error_string(), mais duplique la chaîne de caractères plutôt que d'utiliser directement le pointeur fourni.

UI_construct_prompt() construit une chaîne d'invite à partir d'une description d'objet et d'un nom d'objet. Ceci est utile pour générer des invites plus descriptives.

UI_add_user_data() ajoute des données utilisateur à la structure UI. Ces données peuvent être récupérées ultérieurement à l'aide de UI_get0_user_data().

UI_get0_user_data() renvoie les données utilisateur précédemment ajoutées à la structure UI.

UI_get0_result() renvoie le résultat de la i-ième demande dans la structure UI ui.

UI_process() traite la structure UI ui et effectue toutes les demandes définies.

UI_ctrl() permet de contrôler diverses fonctionnalités de la méthode UI. Les commandes valides sont : UI_CTRL_PRINT_ERRORS et UI_CTRL_IS_REDOABLE.

UI_set_default_method() définit la méthode UI par défaut à utiliser lorsque UI_new() est appelée.

UI_get_default_method() renvoie la méthode UI par défaut actuelle.

UI_get_method() renvoie la méthode UI actuellement utilisée par la structure UI ui.

UI_set_method() définit la méthode UI à utiliser par la structure UI ui sur meth.

UI_OpenSSL() renvoie un pointeur vers la méthode UI standard d'OpenSSL. Cette méthode gère les invites de manière interactive sur la console.

UI_null() renvoie un pointeur vers une méthode UI qui ne fait rien. Ceci est utile pour désactiver les invites dans certaines situations.

NOTES

Les fonctions UI_add_*() et UI_dup_*() ajoutent des éléments à la structure UI. La différence réside dans la façon dont elles gèrent les chaînes de caractères. Les fonctions UI_add_*() utilisent les pointeurs de chaînes fournis directement, tandis que les fonctions UI_dup_*() créent des copies des chaînes fournies. L'utilisation des fonctions UI_dup_*() est généralement plus sûre car elle évite les problèmes liés à la durée de vie des chaînes d'origine.

Les drapeaux UI_INPUT_FLAG_ECHO et UI_INPUT_FLAG_DEFAULT_PWD sont utilisés avec les fonctions de demande de chaîne de caractères. UI_INPUT_FLAG_ECHO fait que les caractères saisis sont affichés sur la console. UI_INPUT_FLAG_DEFAULT_PWD indique que la demande concerne un mot de passe et que la saisie doit être traitée en conséquence (par exemple, en ne l'affichant pas).

L'ordre des demandes ajoutées est important, car UI_process() les exécutera dans cet ordre. Le résultat de chaque demande est accessible via son index à l'aide de UI_get0_result().

La méthode UI par défaut (UI_OpenSSL()) est une implémentation de base qui fonctionne sur la console. Pour des interfaces utilisateur plus avancées (graphiques, etc.), une méthode UI personnalisée doit être créée et utilisée via UI_new_method() et potentiellement définie comme méthode par défaut avec UI_set_default_method().

EXEMPLE

Voici un exemple simple d'utilisation de l'interface UI pour demander un nom d'utilisateur et un mot de passe :

    UI *ui;
    char username[100];
    char password[100];

    ui = UI_new_method(UI_OpenSSL());
    if (!ui) {
        /* Gestion de l'erreur */
        return 1;
    }

    UI_add_input_string(ui, "Nom d'utilisateur: ", 0, username, 0, sizeof(username) - 1);
    UI_add_input_string(ui, "Mot de passe: ", UI_INPUT_FLAG_DEFAULT_PWD, password, 0, sizeof(password) - 1);

    if (UI_process(ui) != 0) {
        /* Erreur lors du traitement */
        UI_free(ui);
        return 1;
    }

    printf("Nom d'utilisateur: %s\n", UI_get0_result(ui, 0));
    printf("Mot de passe: %s\n", UI_get0_result(ui, 1));

    UI_free(ui);
    return 0;

FUNCTIONS

UI_new(), UI_new_method(), UI_free().

UI_OpenSSL() renvoie la méthode UI intégrée (notez : pas nécessairement la méthode par défaut, car la méthode par défaut peut être modifiée. Voir plus loin). Cette méthode est la partie la plus dépendante de la machine/du système d'exploitation d'OpenSSL et pose normalement le plus de problèmes lors du portage.

UI_null() renvoie une méthode UI qui ne fait rien. Son utilisation est d'éviter d'obtenir les paramètres par défaut internes pour les pointeurs UI_METHOD passés.

UI_free() supprime ui de la mémoire, ainsi que toutes les autres pièces de mémoire qui y sont connectées, comme les chaînes d'entrée dupliquées, les résultats et autres. Si ui est un pointeur NULL, aucune action n'est effectuée.

UI_add_input_string() et UI_add_verify_string() ajoutent une invite à ui, ainsi que des indicateurs et un tampon de résultat, et les tailles minimales et maximales souhaitées du résultat, sans compter le caractère NUL final. Les informations fournies sont utilisées pour demander des informations, par exemple un mot de passe, et pour vérifier un mot de passe (c'est-à-dire demander à l'utilisateur de le saisir deux fois et de vérifier que la même chaîne a été saisie deux fois). UI_add_verify_string() prend un argument supplémentaire qui doit être un pointeur vers le tampon de résultat de la chaîne d'entrée qu'elle est censée vérifier, sinon la vérification échouera.

UI_add_input_boolean() ajoute une invite à ui qui doit être répondu de manière booléenne, avec un seul caractère pour oui et un caractère différent pour non. Un ensemble de caractères qui peuvent être utilisés pour annuler l'invite est également fourni. L'invite elle-même est en réalité divisée en deux, une partie étant le texte descriptif (fourni via l'argument prompt) et une décrivant les réponses possibles (fournie via l'argument action_desc).

UI_add_info_string() et UI_add_error_string() ajoutent des chaînes qui sont affichées en même temps que l'invite pour des informations supplémentaires ou pour afficher une chaîne d'erreur. La différence entre les deux est uniquement conceptuelle. Avec la méthode intégrée, il n'y a pas de différence technique entre elles. D'autres méthodes peuvent faire une distinction entre elles, cependant.

Les indicateurs actuellement pris en charge sont UI_INPUT_FLAG_ECHO, qui est pertinent pour UI_add_input_string() et fera que la réponse de l'utilisateur soit écho (lorsqu'on demande un mot de passe, cet indicateur ne doit évidemment pas être utilisé), et UI_INPUT_FLAG_DEFAULT_PWD, ce qui signifie qu'un mot de passe par défaut d'une certaine sorte sera utilisé (entièrement dépendant de l'application et de la méthode UI).

UI_dup_input_string(), UI_dup_verify_string(), UI_dup_input_boolean(), UI_dup_info_string(), et UI_dup_error_string() sont essentiellement les mêmes que leurs homologues UI_add_*(), sauf qu'ils créent leurs propres copies de toutes les chaînes.

UI_construct_prompt() est une fonction d'assistance qui peut être utilisée pour créer une invite à partir de deux éléments d'information : une description et un nom. Le constructeur par défaut (s'il n'y en a pas fourni par la méthode utilisée) crée la chaîne « Entrer description pour name : ». Avec la description « phrase de passe » et le nom de fichier « foo.key », cela devient « Entrer la phrase de passe pour foo.key : ». D'autres méthodes peuvent créer n'importe quelle chaîne et peuvent inclure des encodages qui seront traités par les autres fonctions de la méthode.

UI_add_user_data() ajoute un pointeur de données utilisateur pour que la méthode l'utilise à tout moment. La méthode UI intégrée ne se soucie pas de ces informations. Notez que plusieurs appels à cette fonction n'ajoutent pas de données - le bloc précédent est remplacé par celui fourni en argument.

UI_get0_user_data() récupère les données qui ont été données en dernier à ui avec UI_add_user_data().

UI_get0_result() renvoie un pointeur vers le tampon de résultat associé aux informations indexées par i.

UI_process() parcourt les informations fournies jusqu'à présent, effectue toutes les impressions et les demandes, et renvoie le statut final, qui est -2 en cas d'événements hors bande (Interruption, Annulation, ...), -1 en cas d'erreur, ou 0 en cas de succès.

UI_ctrl() ajoute un contrôle supplémentaire pour l'auteur de l'application. Pour l'instant, il comprend deux commandes : UI_CTRL_PRINT_ERRORS, qui fait que UI_process() imprime la pile d'erreurs OpenSSL dans le cadre du traitement de ui, et UI_CTRL_IS_REDOABLE, qui renvoie un indicateur indiquant si ui utilisé peut être réutilisé ou non.

UI_set_default_method() modifie la méthode UI par défaut pour celle fournie. Cette fonction n'est pas thread-safe et ne doit pas être appelée en même temps que d'autres fonctions OpenSSL.

UI_get_default_method() renvoie un pointeur vers la méthode UI par défaut actuelle.

UI_get_method() renvoie la méthode UI associée à un ui donné.

UI_set_method() modifie la méthode UI associée à un ui donné.

VALEURS DE RETOUR

UI_new() et UI_new_method() renvoient une structure UI valide ou NULL si une erreur s'est produite.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string(), et UI_dup_error_string() renvoient un nombre positif en cas de succès ou un nombre inférieur ou égal à zéro en cas d'échec.

UI_construct_prompt() et UI_get0_result() renvoient une chaîne ou NULL si une erreur s'est produite.

UI_add_user_data() et UI_get0_user_data() renvoient un pointeur vers les données utilisateur qui étaient contenues dans ui avant l'appel. En particulier, NULL est une valeur de retour valide.

UI_process() renvoie 0 en cas de succès ou une valeur négative en cas d'erreur.

UI_ctrl() renvoie un masque en cas de succès ou -1 en cas d'erreur.

UI_get_default_method(), UI_OpenSSL() et UI_null() renvoient toujours un pointeur vers une structure UI_METHOD valide.

UI_get_method() et UI_set_method() renvoient un pointeur vers la structure UI_METHOD qui est installée dans ui après l'appel. La documentation OpenSSL indique qu'ils peuvent échouer et renvoyer NULL, mais actuellement, cela ne peut se produire que lorsque et après que UI_set_method() a été appelé avec un argument explicite NULL.
