DESCRIPTION

Ces fonctions opèrent sur le fichier de base de données des nombres magiques qui est décrit dans magic(5).

La fonction magic_open() crée et retourne un pointeur de cookie magique. Elle retourne NULL s'il y a eu une erreur lors de l'allocation du cookie magique. L'argument flags spécifie comment les autres fonctions magiques doivent se comporter :

MAGIC_NONE
Aucun traitement spécial.
MAGIC_DEBUG
Afficher les messages de débogage sur la sortie d'erreur standard.
MAGIC_SYMLINK
Si le fichier interrogé est un lien symbolique, le suivre.
MAGIC_COMPRESS
Si le fichier est compressé, le décompresser et examiner son contenu.
MAGIC_DEVICES
Si le fichier est un périphérique spécial de bloc ou de caractère, alors ouvrir le périphérique et essayer d'examiner son contenu.
MAGIC_MIME_TYPE
Retourner une chaîne de type MIME, au lieu d'une description textuelle.
MAGIC_MIME_ENCODING
Retourner un encodage MIME, au lieu d'une description textuelle.
MAGIC_MIME
Raccourci pour MAGIC_MIME_TYPE | MAGIC_MIME_ENCODING.
MAGIC_CONTINUE
Retourner toutes les correspondances, pas seulement la première.
MAGIC_CHECK
Vérifier la cohérence de la base de données magique et afficher des avertissements sur la sortie d'erreur standard.
MAGIC_PRESERVE_ATIME
Sur les systèmes qui supportent utime(3) ou utimes(2), tenter de préserver l'heure d'accès des fichiers analysés.
MAGIC_RAW
Ne pas traduire les caractères non imprimables en représentation octale \ooo.
MAGIC_ERROR
Traiter les erreurs du système d'exploitation lors de la tentative d'ouverture de fichiers et de suivi des liens symboliques comme de vraies erreurs, au lieu de les afficher dans le tampon magique.
MAGIC_APPLE
Retourner le créateur et le type Apple.
MAGIC_EXTENSION
Retourner une liste d'extensions séparées par des barres obliques pour ce type de fichier.
MAGIC_COMPRESS_TRANSP
Ne pas signaler la compression, seulement les données décompressées.
MAGIC_NO_CHECK_APPTYPE
Ne pas vérifier le type d'application EMX (uniquement sur EMX).
MAGIC_NO_COMPRESS_FORK
Ne pas autoriser les décompresseurs qui utilisent fork.
MAGIC_NO_CHECK_CDF
Ne pas obtenir le contenu des documents composés (CDF).

La fonction magic_close() libère le cookie magique indiqué.

La fonction magic_error() retourne un message d'erreur décrivant la dernière erreur survenue avec le cookie magique indiqué.

La fonction magic_errno() retourne le numéro d'erreur du système (type errno) correspondant à la dernière erreur survenue avec le cookie magique.

La fonction magic_descriptor() renvoie une description du fichier représenté par le descripteur de fichier fd.

La fonction magic_file() renvoie une description du fichier indiqué par filename.

La fonction magic_buffer() renvoie une description du fichier représenté par le tampon buffer de longueur length.

La fonction magic_getflags() renvoie les indicateurs actuellement définis pour le cookie magique.

La fonction magic_setflags() définit les indicateurs pour le cookie magique.

La fonction magic_check() vérifie la base de données magique spécifiée par filename pour la cohérence et écrit les avertissements éventuels sur la sortie d'erreur standard. Elle renvoie 0 en cas de succès, et -1 en cas d'erreur.

La fonction magic_compile() compile le fichier texte de la base de données magique spécifié par filename dans un fichier binaire compilé. Elle renvoie 0 en cas de succès, et -1 en cas d'erreur.

La fonction magic_list() charge les informations de la base de données magique spécifiée par filename sous forme de texte et les écrit sur la sortie standard. Elle renvoie 0 en cas de succès, et -1 en cas d'erreur.

La fonction magic_load() charge la base de données magique spécifiée par filename. Si filename est NULL, elle essaie de charger la base de données magique par défaut. Elle renvoie 0 en cas de succès, et -1 en cas d'erreur.

La fonction magic_load_buffers() charge des données de base de données magique à partir de plusieurs tampons en mémoire. Les tableaux buffers et sizes doivent contenir les pointeurs vers les tampons et leurs tailles respectives. nbuffers spécifie le nombre de tampons.

La fonction magic_getparam() récupère la valeur d'un paramètre spécifié par param. La signification de value dépend du paramètre.

La fonction magic_setparam() définit la valeur d'un paramètre spécifié par param. La signification de value dépend du paramètre.

La fonction magic_version() renvoie la version de la bibliothèque libmagic.

La fonction magic_getpath() renvoie le chemin d'accès à la base de données magique spécifiée par magicfile en fonction de l'action.

Les valeurs possibles pour param dans magic_getparam et magic_setparam sont :

MAGIC_PARAM_FLAGS
Valeur entière représentant les drapeaux.
MAGIC_PARAM_NAME
Chaîne de caractères représentant le nom du fichier magique utilisé.
MAGIC_PARAM_DEBUG
Entier représentant le niveau de débogage.
MAGIC_PARAM_CHECKPATH
Chaîne de caractères représentant le chemin de vérification.
MAGIC_PARAM_PATHLIST
Chaîne de caractères représentant la liste des chemins pour la recherche des fichiers magiques.
MAGIC_PARAM_RLAST_DIR
Chaîne de caractères représentant le dernier répertoire lu.
MAGIC_PARAM_APPLEWHACK
Entier représentant le comportement Apple.
MAGIC_PARAM_ Langkah_MAX
Entier représentant la profondeur maximale des liens.
MAGIC_PARAM_ Langkah_INDENT
Entier représentant le niveau d'indentation pour les liens.

Les valeurs possibles pour action dans magic_getpath sont :

MAGIC_GETPATH_LOOKUP
Rechercher la base de données magique.
MAGIC_GETPATH_CHECK
Vérifier la base de données magique.
MAGIC_GETPATH_COMPILE
Compiler la base de données magique.
MAGIC_GETPATH_LIST
Lister la base de données magique.

UTILISATION

L'utilisation typique de cette bibliothèque est la suivante :

1. Appeler magic_open() avec les indicateurs souhaités.

2. Charger la base de données magique en appelant magic_load() ou magic_load_buffers().

3. Appeler magic_file(), magic_buffer() ou magic_descriptor() pour obtenir la description du fichier.

4. Traiter la description retournée.

5. Appeler magic_close() pour libérer le cookie magique.

En cas d'erreur, magic_error() peut être utilisé pour obtenir un message d'erreur.

EXEMPLE

Voici un exemple simple d'utilisation de la bibliothèque libmagic :

#include <stdio.h>
#include <magic.h>

int main(void) {
    magic_t cookie;
    const char *filetype;

    /* Créer un cookie magique */
    cookie = magic_open(MAGIC_NONE);
    if (cookie == NULL) {
        fprintf(stderr, "Erreur : impossible d'ouvrir le cookie magique\n");
        return 1;
    }

    /* Charger la base de données magique */
    if (magic_load(cookie, NULL) != 0) {
        fprintf(stderr, "Erreur : %s\n", magic_error(cookie));
        magic_close(cookie);
        return 1;
    }

    /* Obtenir le type de fichier */
    filetype = magic_file(cookie, "/etc/passwd");
    if (filetype == NULL) {
        fprintf(stderr, "Erreur : %s\n", magic_error(cookie));
        magic_close(cookie);
        return 1;
    }

    printf("Le fichier /etc/passwd est de type : %s\n", filetype);

    /* Fermer le cookie magique */
    magic_close(cookie);
    return 0;
}

La fonction magic_close() ferme la base de données magic(5) et désalloue toutes les ressources utilisées.

La fonction magic_error() renvoie une explication textuelle de la dernière erreur, ou NULL s'il n'y a pas eu d'erreur.

La fonction magic_errno() renvoie le dernier numéro d'erreur du système d'exploitation (errno(2)) rencontré par un appel système.

La fonction magic_file() renvoie une description textuelle du contenu de l'argument filename, ou NULL si une erreur s'est produite. Si le filename est NULL, alors stdin est utilisé.

La fonction magic_descriptor() renvoie une description textuelle du contenu de l'argument fd, ou NULL si une erreur s'est produite.

La fonction magic_buffer() renvoie une description textuelle du contenu de l'argument buffer avec une taille de length octets.

Les fonctions magic_getflags() renvoient une valeur représentant les flags actuels définis.

La fonction magic_setflags() définit les flags décrits ci-dessus. Notez qu'utiliser les deux flags MIME ensemble peut également renvoyer des informations supplémentaires sur le jeu de caractères.

La fonction magic_check() peut être utilisée pour vérifier la validité des entrées dans les fichiers de base de données séparés par des deux-points passés comme filename, ou NULL pour la base de données par défaut. Elle renvoie 0 en cas de succès et -1 en cas d'échec.

La fonction magic_compile() peut être utilisée pour compiler la liste séparée par des deux-points des fichiers de base de données passés comme filename, ou NULL pour la base de données par défaut. Elle renvoie 0 en cas de succès et -1 en cas d'échec. Les fichiers compilés créés sont nommés à partir du basename(1) de chaque argument de fichier avec “.mgc” ajouté.

La fonction magic_list() sauvegarde toutes les entrées magiques dans un format lisible par l'homme, sauvegardant d'abord les entrées qui correspondent aux fichiers binaires, puis celles qui correspondent aux fichiers texte. Elle prend un argument optionnel filename qui est une liste de fichiers de base de données séparée par des deux-points, ou NULL pour la base de données par défaut.

La fonction magic_load() doit être utilisée pour charger la liste séparée par des deux-points des fichiers de base de données passés comme filename, ou NULL pour le fichier de base de données par défaut avant que toute requête magique puisse être effectuée.

Le fichier de base de données par défaut est nommé par la variable d'environnement MAGIC. Si cette variable n'est pas définie, le nom du fichier de base de données par défaut est /usr/share/file/misc/magic. magic_load() ajoute “.mgc” au nom du fichier de base de données si nécessaire.

La fonction magic_load_buffers() prend un tableau de taille nbuffers de buffers avec une taille respective pour chacun dans le tableau de sizes chargé avec le contenu des bases de données magiques depuis le système de fichiers. Cette fonction peut être utilisée dans des environnements où la bibliothèque magique n'a pas d'accès direct au système de fichiers, mais peut accéder à la base de données magique via la mémoire partagée ou d'autres moyens IPC.

Les fonctions magic_getparam() et magic_setparam() permettent d'obtenir et de définir diverses limites liées à la bibliothèque magique.

NAME

libmagic — magic number and charset sniffing library

LIBRARY

Provides functions that determine the type of a file.

SYNOPSIS

DESCRIPTION

The libmagic library is used to classify files based on their content. It uses a database of text strings that describe the characteristics of files. This database is specified in the file described in magic(5).

The magic_open() function initializes and returns a cookie for use in subsequent calls. The flags argument specifies how the library should behave. The flags are:

  • MAGIC_DEBUG: Debug mode. Print extra information about the rules being applied.
  • MAGIC_ERROR: Print error messages to stderr.
  • MAGIC_SYMLINKS: Cause any symbolic links listed on the command line be investigated (default).
  • MAGIC_NO_SYMLINKS: Cause any symbolic links to be ignored.
  • MAGIC_COMPRESS: Consult the compress(1) program. Defaults to consulting contents of compressed files.
  • MAGIC_NO_CHECK: Do not check for certain controllable entry types.
  • MAGIC_ALL: Check for all possible validity checks.
  • MAGIC_OLD

    The function magic_open() returns a magic cookie on success and NULL on failure setting errno to an appropriate value. It will set errno to EINVAL if an unsupported value for flags was given. The magic_list(), magic_load(), magic_compile(), and magic_check() functions return 0 on success and -1 on failure. The magic_buffer(), magic_getpath(), and magic_file(), functions return a string on success and NULL on failure. The magic_error() function returns a textual description of the errors of the above functions, or NULL if there was no error. The magic_version() always returns the version number of the library. Finally, magic_setflags() returns -1 on systems that don't support utime(3), or utimes(2) when MAGIC_PRESERVE_ATIME is set.

BUGS

The results from magic_buffer() and magic_file() where the buffer and the file contain the same data can produce different results, because in the magic_file() case, the program can lseek(2) and stat(2) the file descriptor.
