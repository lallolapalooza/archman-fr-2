libressl-EVP_PKEY_derive(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

EVP_PKEY_DERIVE(3) Manuel des fonctions de bibliothèque EVP_PKEY_DERIVE(3)

NOM

EVP_PKEY_derive_init, EVP_PKEY_derive_set_peer, EVP_PKEY_CTX_get0_peerkey, EVP_PKEY_derive — dériver un secret partagé d'algorithme de clé publique

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_PKEY_derive_init(EVP_PKEY_CTX *ctx);

int
EVP_PKEY_derive_set_peer(EVP_PKEY_CTX *ctx, EVP_PKEY *peerkey);

EVP_PKEY *
EVP_PKEY_CTX_get0_peerkey(EVP_PKEY_CTX *ctx);

int
EVP_PKEY_derive(EVP_PKEY_CTX *ctx, unsigned char *key, size_t *keylen);

DESCRIPTION

EVP_PKEY_derive_init() initialise le contexte de l'algorithme de clé publique ctx pour la dérivation d'un secret partagé en utilisant l'objet EVP_PKEY déjà stocké dans ctx. La bibliothèque offre un support intégré pour les clés dont l'EVP_PKEY_base_id(3) est EVP_PKEY_DH, EVP_PKEY_EC, EVP_PKEY_HKDF, et EVP_PKEY_X25519.

Après l'appel à EVP_PKEY_derive_init(), des opérations de contrôle spécifiques à l'algorithme peuvent être facultativement effectuées pour définir tous les paramètres appropriés pour l'opération.

EVP_PKEY_derive_set_peer() configure le ctx, qui doit déjà être initialisé avec EVP_PKEY_derive_init(), EVP_PKEY_encrypt_init(3), ou EVP_PKEY_decrypt_init(3), pour utiliser la peerkey, qui est normalement une clé publique. En cas de succès, le compteur de références de la peerkey est incrémenté d'une unité. Par conséquent, l'appelant doit appeler EVP_PKEY_free(3) sur la peerkey lorsque l'appelant n'en a plus besoin, même si elle est toujours utilisée par ctx.

EVP_PKEY_derive() dérive un secret partagé en utilisant ctx. Si key est NULL, alors la taille maximale du tampon de sortie est écrite dans le paramètre keylen. Si key n'est pas NULL, alors avant l'appel, le paramètre keylen doit contenir la longueur du tampon key. Si l'appel réussit, le secret partagé est écrit dans key et la quantité de données écrite est indiquée dans keylen.

La fonction EVP_PKEY_derive() peut être appelée plus d'une fois sur le même contexte si plusieurs opérations sont effectuées en utilisant les mêmes paramètres.

VALEURS DE RETOUR

EVP_PKEY_derive_init(), EVP_PKEY_derive_set_peer(), et EVP_PKEY_derive() retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas supportée par l'algorithme de clé publique.

Pour EVP_PKEY_derive_set_peer(), une valeur de retour de -1 peut par exemple se produire si ctx n'est pas correctement initialisé, ne contient pas d'EVP_PKEY qui peut être récupéré avec EVP_PKEY_CTX_get0_pkey(3), l'EVP_PKEY_id(3) des deux clés ne correspond pas, ou EVP_PKEY_cmp_parameters(3) indique des paramètres de clé discordants.

EVP_PKEY_derive() échoue avec une valeur de retour de -1 par exemple si ctx n'a pas été correctement initialisé avec EVP_PKEY_derive_init().

EVP_PKEY_CTX_get0_peerkey() retourne un pointeur interne vers la peerkey utilisée par ctx sans incrémenter son compteur de références.

EXEMPLES

Dérivé du secret partagé (par exemple clés DH ou EC) :

#include <openssl/evp.h>
#include <openssl/rsa.h>

EVP_PKEY_CTX *ctx;
unsigned char *skey;
size_t skeylen;
EVP_PKEY *pkey, *peerkey;

/* Suppose que pkey et peerkey ont déjà été configurés. */
ctx = EVP_PKEY_CTX_new(pkey, NULL);
if (!ctx)
	/* Une erreur s'est produite */
if (EVP_PKEY_derive_init(ctx) <= 0)
	/* Erreur */
if (EVP_PKEY_derive_set_peer(ctx, peerkey) <= 0)
	/* Erreur */

/* Déterminer la longueur du tampon */
if (EVP_PKEY_derive(ctx, NULL, &skeylen) <= 0)
	/* Erreur */

skey = malloc(skeylen);

if (!skey)
	/* Échec de malloc */

if (EVP_PKEY_derive(ctx, skey, &skeylen) <= 0)
	/* Erreur */

/* Le secret partagé est skey octets écrits dans le tampon skey */
