lib(3perl) Guide de référence du programmeur Perl lib(3perl)

NOM

lib - manipuler @INC au moment de la compilation

SYNOPIS

use lib LIST;
no lib LIST;

DESCRIPTION

C'est un petit module simple qui simplifie la manipulation de @INC au moment de la compilation.

Il est généralement utilisé pour ajouter des répertoires supplémentaires au chemin de recherche de perl afin que les instructions "use" ou "require" ultérieures puissent trouver des modules qui ne sont pas situés sur le chemin de recherche par défaut de perl.

Ajout de répertoires à @INC

Les paramètres de "use lib" sont ajoutés au début du chemin de recherche de perl. Dire

use lib LIST;

revient *presque* à dire

BEGIN { unshift(@INC, LIST) }

Pour chaque répertoire de LIST (appelé $dir ici), le module lib vérifie également s'il existe un répertoire nommé $dir/$archname/auto. Si c'est le cas, le répertoire $dir/$archname est supposé être un répertoire spécifique à l'architecture correspondant et est ajouté à @INC devant $dir. lib.pm vérifie également si les répertoires nommés $dir/$version et $dir/$version/$archname existent et ajoute ces répertoires à @INC.

La valeur actuelle de $archname peut être trouvée avec cette commande :

perl -V:archname

La commande correspondante pour obtenir la valeur actuelle de $version est :

perl -V:version

Pour éviter les fuites de mémoire, toutes les entrées dupliquées à la fin de @INC sont supprimées.

Suppression de répertoires de @INC

Vous ne devriez normalement ajouter que des répertoires à @INC. Si vous devez supprimer des répertoires de @INC, veillez à ne supprimer que ceux que vous avez ajoutés vous-même ou dont vous êtes certain qu'ils ne sont pas nécessaires à d'autres modules de votre script. D'autres modules peuvent avoir ajouté des répertoires dont ils ont besoin pour fonctionner correctement.

L'instruction "no lib" supprime toutes les occurrences de chaque répertoire nommé de @INC.

Pour chaque répertoire de LIST (appelé $dir ici), le module lib vérifie également s'il existe un répertoire nommé $dir/$archname/auto. Si c'est le cas, le répertoire $dir/$archname est supposé être un répertoire spécifique à l'architecture correspondant et est également supprimé de @INC. lib.pm vérifie également si les répertoires nommés $dir/$version et $dir/$version/$archname existent et supprime ces répertoires de @INC.

Restauration de @INC original

Lorsque le module lib est chargé pour la première fois, il enregistre la valeur actuelle de @INC dans un tableau @lib::ORIG_INC. Pour restaurer @INC à cette valeur, vous pouvez dire :

@INC = @lib::ORIG_INC;

CAVEATS

Afin de garder lib.pm petit et simple, il ne fonctionne qu'avec des chemins de fichiers Unix. Cela ne signifie pas qu'il ne fonctionne que sur Unix, mais les utilisateurs non-Unix doivent d'abord traduire leurs chemins de fichiers en conventions Unix.

# Les utilisateurs VMS voulant mettre [.stuff.moo] dans
# leur @INC écriront
use lib 'stuff/moo';

NOTES

À l'avenir, ce module utilisera probablement File::Spec pour déterminer les chemins, comme il le fait actuellement pour Mac OS (où les chemins de style Unix ou de style Mac fonctionnent, et où les chemins de style Unix sont correctement convertis en chemins de style Mac avant d'être ajoutés à @INC).

Si vous essayez d'ajouter un fichier à @INC comme suit :

use lib 'this_is_a_file.txt';

"lib" produira un avertissement à ce sujet. Les seules exceptions sont les fichiers avec l'extension ".par" qui sont destinés à être utilisés comme bibliothèques.

VOIR AUSSI

FindBin - module optionnel qui traite des chemins relatifs au fichier source.

PAR - module optionnel qui peut traiter les fichiers ".par" comme des bibliothèques Perl.
