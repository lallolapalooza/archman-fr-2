NOM

BIO_f_md, BIO_set_md, BIO_get_md, BIO_get_md_ctx, BIO_set_md_ctx — filtre BIO pour les condensats de messages

SYNOPIS

bibliothèque «libcrypto»
#include <openssl/bio.h>
#include <openssl/evp.h>

const BIO_METHOD *
BIO_f_md(void);

long
BIO_set_md(BIO *b, EVP_MD *md);

long
BIO_get_md(BIO *b, EVP_MD **mdp);

long
BIO_get_md_ctx(BIO *b, EVP_MD_CTX **mdcp);

long
BIO_set_md_ctx(BIO *b, EVP_MD_CTX *mdc);

DESCRIPTION

BIO_f_md() renvoie la méthode BIO de condensat de message. C'est un BIO de filtrage qui condense toutes les données qui le traversent. C'est un wrapper BIO pour les routines de condensat EVP_DigestInit(3), EVP_DigestUpdate(3), et EVP_DigestFinal(3).

BIO_set_md() définit le condensat de message de b à md et l'initialise en utilisant EVP_DigestInit_ex(3). Appeler cette fonction est nécessaire avant que toute donnée ne soit passée par b.

BIO_get_md() place un pointeur vers la méthode de condensat de b dans *mdp.

Toutes les données écrites ou lues à travers un BIO de condensat en utilisant BIO_read(3) et BIO_write(3) sont condensées.

BIO_gets(3), si son paramètre taille est suffisamment grand, termine le calcul du condensat et renvoie la valeur du condensat. BIO_puts(3) n'est pas pris en charge. Si une application a besoin d'appeler BIO_gets(3) ou BIO_puts(3) à travers une chaîne contenant des BIOs de condensat, cela peut être fait en préfixant un BIO tampon.

Après que le condensat a été récupéré d'un BIO de condensat, appelez BIO_reset(3) pour le réinitialiser ainsi que tous les BIOs qui le suivent dans sa chaîne avant de lui passer plus de données. S'il n'y a pas de BIOs suivants nécessitant une réinitialisation, BIO_set_md() peut être utilisé à la place de BIO_reset(3).

BIO_get_md_ctx() place un pointeur vers le contexte de condensat de b dans *mdcp et marque le BIO comme initialisé sans réellement l'initialiser. À moins que BIO_set_md() n'ait déjà été appelé sur b, l'appelant devient responsable de l'initialisation du contexte de condensat avec EVP_DigestInit_ex(3).

Le contexte renvoyé par BIO_get_md_ctx() peut être utilisé dans les appels à EVP_DigestFinal(3) et également dans les routines de signature EVP_SignFinal(3) et EVP_VerifyFinal(3).

Le contexte renvoyé par BIO_get_md_ctx() est une structure de contexte interne. Les modifications apportées à ce contexte affecteront le BIO de condensat lui-même, et le pointeur de contexte deviendra invalide lorsque le BIO de condensat sera libéré.

BIO_set_md_ctx() remplace le contexte de condensat de b par mdc. Appeler cette fonction n'est généralement pas nécessaire car la création d'un BIO de condensat avec BIO_new(3) crée automatiquement un contexte de condensat et le stocke en interne. Avant d'appeler BIO_set_md_ctx(), l'appelant doit récupérer l'ancien contexte en utilisant BIO_get_md_ctx(), et l'appelant devient également responsable de l'appel EVP_MD_CTX_free(3) sur l'ancien contexte. À moins que mdc ne soit déjà initialisé, l'appelant doit l'initialiser après avoir appelé BIO_set_md_ctx() en utilisant soit BIO_set_md() soit EVP_DigestInit(3).

Lorsqu'une chaîne contenant un BIO de condensat de message est copiée avec BIO_dup_chain(3), EVP_MD_CTX_copy_ex(3) est appelé en interne pour copier automatiquement le contexte de condensat de message de l'objet BIO existant vers le nouveau, et le drapeau d'initialisation qui peut être récupéré avec BIO_get_init(3) est défini sur 1.

BIO_ctrl(3) les arguments cmd correspondent à des macros comme suit :

cmd constante macro correspondante
BIO_C_GET_MD BIO_get_md()
BIO_C_GET_MD_CTX BIO_get_md_ctx()
BIO_C_SET_MD BIO_set_md()
BIO_C_SET_MD_CTX BIO_set_md_ctx()
BIO_CTRL_RESET BIO_reset(3)

VALEUR DE RETOUR

BIO_f_md() renvoie la méthode BIO de condensat.

Lorsqu'il est appelé sur un objet BIO de condensat de message, BIO_method_type(3) renvoie la constante BIO_TYPE_MD et BIO_method_name(3) renvoie un pointeur vers la chaîne statique « message digest ».

BIO_set_md() renvoie 1 en cas de succès ou 0 si EVP_DigestInit_ex(3) échoue.

BIO_get_md() et BIO_set_md_ctx() renvoient 1 en cas de succès ou 0 si b n'est pas initialisé.

BIO_get_md_ctx() renvoie 1 en cas de succès ou 0 en cas d'échec, mais l'implémentation actuelle ne peut pas échouer.

EXEMPLES

L'exemple suivant crée une chaîne BIO contenant un BIO de condensat SHA-1 et MD5 et lui passe la chaîne « Hello World ». La vérification des erreurs a été omise pour plus de clarté.

BIO *bio, *mdtmp;
const char message[] = "Hello World";
bio = BIO_new(BIO_s_null());
mdtmp = BIO_new(BIO_f_md());
BIO_set_md(mdtmp, EVP_sha1());
/*
 * Pour BIO_push(), nous voulons ajouter le BIO récepteur
 * et
gardez une note du début de la chaîne. */ bio = BIO_push(mdtmp, bio); mdtmp = BIO_new(BIO_f_md()); BIO_set_md(mdtmp, EVP_md5()); bio = BIO_push(mdtmp, bio); /* Note : mdtmp peut maintenant être jeté */ BIO_write(bio, message, strlen(message));

L'exemple suivant digère des données en lisant à travers une chaîne au lieu de cela :

BIO *bio, *mdtmp;
char buf[1024];
int rdlen;

bio = BIO_new_file(file, "rb");
mdtmp = BIO_new(BIO_f_md());
BIO_set_md(mdtmp, EVP_sha1());
bio = BIO_push(mdtmp, bio);
mdtmp = BIO_new(BIO_f_md());
BIO_set_md(mdtmp, EVP_md5());
bio = BIO_push(mdtmp, bio);
do {
	rdlen = BIO_read(bio, buf, sizeof(buf));
	/* Vous pourriez vouloir faire quelque chose avec les données ici */
} while (rdlen > 0);

Le prochain exemple récupère les digests de message d'une chaîne BIO et les affiche. Cela pourrait être utilisé avec les exemples ci-dessus.

BIO *mdtmp;
unsigned char mdbuf[EVP_MAX_MD_SIZE];
int mdlen;
int i;

mdtmp = bio;	/* Supposons que bio ait été configuré précédemment */
do {
	EVP_MD *md;
	mdtmp = BIO_find_type(mdtmp, BIO_TYPE_MD);
	if (!mdtmp)
		break;
	BIO_get_md(mdtmp, &md);
	printf("%s digest", OBJ_nid2sn(EVP_MD_type(md)));
	mdlen = BIO_gets(mdtmp, mdbuf, EVP_MAX_MD_SIZE);
	for(i = 0; i < mdlen; i++)
		printf(":%02X", mdbuf[i]);
	printf("\n");
	mdtmp = BIO_next(mdtmp);
} while(mdtmp);
BIO_free_all(bio);

VOIR AUSSI

BIO_new(3), EVP_DigestInit(3)

HISTORIQUE

BIO_f_md(), BIO_set_md(), et BIO_get_md() sont apparus pour la première fois dans SSLeay 0.6.0. BIO_get_md_ctx() est apparu pour la première fois dans SSLeay 0.8.1. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BIO_set_md_ctx() est apparu pour la première fois dans OpenSSL 0.9.7e et est disponible depuis OpenBSD 3.8.

Avant OpenSSL 1.0.0, l'appel à BIO_get_md_ctx() ne fonctionnait que si le BIO avait été initialisé, par exemple en appelant BIO_set_md().

BOGUES

Le manque de support pour BIO_puts(3) et le comportement non standard de BIO_gets(3) pourraient être considérés comme anormaux. On pourrait soutenir que BIO_gets(3) et BIO_puts(3) devraient être passés au BIO suivant dans la chaîne et digérer les données transmises, et que les digests devraient être récupérés à l'aide d'un appel BIO_ctrl(3) séparé.
