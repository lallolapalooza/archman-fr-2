Le paramètre x est un pointeur vers le pointeur de l'objet qui sera lu. S'il est NULL, alors un nouvel objet sera alloué.

La fonction pem_password_cb est une fonction de rappel pour demander un mot de passe si le fichier PEM est chiffré. Le paramètre u est un pointeur vers des données définies par l'utilisateur.

Pour les fonctions PEM_write_*, le paramètre enc définit le chiffrement à utiliser, kstr et klen sont les clés pour le chiffrement, et cb et u sont utilisés pour obtenir le mot de passe si nécessaire.

DESCRIPTION

Ces fonctions gèrent la lecture et l'écriture d'objets cryptographiques au format PEM. Le format PEM est couramment utilisé pour stocker des clés privées, des certificats, des requêtes de certificat et d'autres données cryptographiques dans des fichiers texte. Les fonctions permettent de lire ou d'écrire ces objets à partir de BIO (interface d'E/S abstraite) ou de FILE (flux de fichier C standard).

Les fonctions sont divisées en plusieurs catégories :

  • PEM_read_bio_PrivateKey et PEM_read_PrivateKey : Lisent une clé privée EVP_PKEY à partir d'un BIO ou d'un FILE. Elles peuvent nécessiter un mot de passe pour déchiffrer la clé.
  • PEM_write_bio_PrivateKey et PEM_write_PrivateKey : Écrivent une clé privée EVP_PKEY dans un BIO ou un FILE. Elles permettent de spécifier un chiffrement et un mot de passe pour protéger la clé écrite.
  • PEM_write_bio_PKCS8PrivateKey et PEM_write_PKCS8PrivateKey : Similaires aux fonctions PEM_write_PrivateKey, mais utilisent le format PKCS#8.
  • PEM_write_bio_PKCS8PrivateKey_nid et PEM_write_PKCS8PrivateKey_nid : Comme les précédentes, mais permettent de spécifier l'algorithme de chiffrement via son NID (Numeric Identifier).
  • PEM_read_bio_PKCS8 et PEM_read_PKCS8 : Lisent une structure X509_SIG (qui contient souvent une clé privée au format PKCS#8) à partir d'un BIO ou d'un FILE.
  • PEM_write_bio_PKCS8 et PEM_write_PKCS8 : Écrivent une structure X509_SIG dans un BIO ou un FILE.
  • PEM_read_bio_PKCS8_PRIV_KEY_INFO et PEM_read_PKCS8_PRIV_KEY_INFO : Lisent une structure PKCS8_PRIV_KEY_INFO, qui représente une clé privée au format PKCS#8 avant chiffrement ou encodage.
  • PEM_write_bio_PKCS8_PRIV_KEY_INFO et PEM_write_PKCS8_PRIV_KEY_INFO : Écrivent une structure PKCS8_PRIV_KEY_INFO.
  • PEM_read_bio_PUBKEY et PEM_read_PUBKEY : Lisent une clé publique EVP_PKEY.
  • PEM_write_bio_PUBKEY et PEM_write_PUBKEY : Écrivent une clé publique EVP_PKEY.
  • Les fonctions préfixées par RSA_, DSA_, DH_ et EC_ lisent et écrivent respectivement les clés et paramètres RSA, DSA, DH et EC. Elles peuvent être spécifiques à la clé privée ou publique, et pour DSA, aux paramètres.
  • PEM_read_bio_X509, PEM_read_X509, PEM_write_bio_X509, PEM_write_X509 : Gèrent les certificats X.509.
  • PEM_read_bio_X509_AUX, PEM_read_X509_AUX, PEM_write_bio_X509_AUX, PEM_write_X509_AUX : Gèrent des certificats X.509 avec des informations auxiliaires.
  • PEM_read_bio_X509_REQ, PEM_read_X509_REQ, PEM_write_bio_X509_REQ, PEM_write_X509_REQ : Gèrent les requêtes de certificat X.509.
  • PEM_write_bio_X509_REQ_NEW et PEM_write_X509_REQ_NEW : Écrivent une requête de certificat X.509 dans un nouveau format.
  • PEM_read_bio_X509_CRL, PEM_read_X509_CRL, PEM_write_bio_X509_CRL, PEM_write_X509_CRL : Gèrent les listes de révocation de certificats (CRL) X.509.
  • PEM_read_bio_PKCS7, PEM_read_PKCS7, PEM_write_bio_PKCS7, PEM_write_PKCS7 : Gèrent les données signées ou chiffrées au format PKCS#7.
  • PEM_read_bio_CMS, PEM_read_CMS, PEM_write_bio_CMS, PEM_write_CMS : Gèrent les données au format CMS (Cryptographic Message Syntax), qui est une évolution de PKCS#7.

Les fonctions PEM_read_* et PEM_write_* utilisent des pointeurs de fichier FILE*, tandis que les fonctions PEM_read_bio_* et PEM_write_bio_* utilisent des pointeurs BIO*, offrant ainsi plus de flexibilité pour gérer différentes sources d'entrée/sortie (fichiers, sockets, mémoire, etc.).

Le paramètre cb est un pointeur vers une fonction de rappel qui sera appelée pour obtenir un mot de passe si le fichier PEM est chiffré. Le paramètre u est un pointeur vers des données définies par l'utilisateur qui seront passées à la fonction de rappel.

Pour les fonctions d'écriture, enc spécifie l'algorithme de chiffrement à utiliser, kstr et klen fournissent la clé de chiffrement, et cb et u sont utilisés pour obtenir le mot de passe si nécessaire.

RETOUR

Les fonctions de lecture retournent un pointeur vers l'objet lu en cas de succès, et NULL en cas d'échec. Les fonctions d'écriture retournent 1 en cas de succès, et 0 en cas d'échec.

HISTORIQUE

Ces fonctions étaient disponibles dans les versions antérieures de OpenSSL.

DESCRIPTION

Les fonctions PEM lisent ou écrivent des structures au format PEM. Dans ce sens, le format PEM est simplement des données encodées en base64 entourées de lignes d'en-tête ; voir PEM_read(3) pour plus de détails.

Pour plus de détails sur la signification des arguments, consultez la section arguments des fonctions PEM.

Chaque opération a quatre fonctions associées. Par souci de concision, le terme « fonctions TYPE » sera utilisé pour désigner collectivement les fonctions PEM_read_bio_TYPE(), PEM_read_TYPE(), PEM_write_bio_TYPE() et PEM_write_TYPE(). S'il n'existe pas d'ensemble de fonctions spécifiques pour un type donné, PEM_ASN1_read(3) peut être utilisé à la place.

Les fonctions PrivateKey lisent ou écrivent une clé privée au format PEM en utilisant une structure EVP_PKEY. Les routines d'écriture utilisent le format de clé privée « traditionnel » et peuvent gérer les clés privées RSA et DSA. Les fonctions de lecture peuvent en outre gérer de manière transparente les clés chiffrées et non chiffrées au format PKCS#8.

PEM_write_bio_PKCS8PrivateKey() et PEM_write_PKCS8PrivateKey() écrivent une clé privée dans une structure EVP_PKEY au format EncryptedPrivateKeyInfo PKCS#8 en utilisant les algorithmes de chiffrement basés sur mot de passe PKCS#5 v2.0. L'argument enc spécifie l'algorithme de chiffrement à utiliser : contrairement à toutes les autres routines PEM, le chiffrement est appliqué au niveau PKCS#8 et non dans les en-têtes PEM. Si enc est NULL, aucun chiffrement n'est utilisé et une structure PrivateKeyInfo PKCS#8 est utilisée à la place.

PEM_write_bio_PKCS8PrivateKey_nid() et PEM_write_PKCS8PrivateKey_nid() écrivent également une clé privée sous forme de EncryptedPrivateKeyInfo PKCS#8. Cependant, elles utilisent les algorithmes de chiffrement PKCS#5 v1.5 ou PKCS#12 à la place. L'algorithme à utiliser est spécifié dans le paramètre nid et doit être le NID de l'OBJECT IDENTIFIER correspondant.

Les fonctions PKCS8 traitent une clé privée chiffrée en utilisant une structure X509_SIG et la fonction d2i_X509_SIG(3).

Les fonctions PKCS8_PRIV_KEY_INFO traitent une clé privée en utilisant une structure PKCS8_PRIV_KEY_INFO.

Les fonctions PUBKEY traitent une clé publique en utilisant une structure EVP_PKEY. La clé publique est encodée sous forme de structure ASN.1 SubjectPublicKeyInfo.

Les fonctions RSAPrivateKey traitent une clé privée RSA en utilisant une structure RSA. Elles gèrent les mêmes formats que les fonctions PrivateKey, mais une erreur se produit si la clé privée n'est pas RSA.

Les fonctions RSAPublicKey traitent une clé publique RSA en utilisant une structure RSA. La clé publique est encodée à l'aide d'une structure RSAPublicKey PKCS#1.

Les fonctions RSA_PUBKEY traitent également une clé publique RSA en utilisant une structure RSA. Cependant, la clé publique est encodée à l'aide d'une structure SubjectPublicKeyInfo ASN.1 et une erreur se produit si la clé publique n'est pas RSA.

Les fonctions DSAPrivateKey traitent une clé privée DSA en utilisant une structure DSA. Elles gèrent les mêmes formats que les fonctions PrivateKey, mais une erreur se produit si la clé privée n'est pas DSA.

Les fonctions DSA_PUBKEY traitent une clé publique DSA en utilisant une structure DSA. La clé publique est encodée à l'aide d'une structure SubjectPublicKeyInfo ASN.1 et une erreur se produit si la clé publique n'est pas DSA.

Les fonctions DSAparams traitent les paramètres DSA en utilisant une structure DSA. Les paramètres sont encodés à l'aide d'une structure Dss-Parms telle que définie dans la RFC 2459.

Les fonctions DHparams traitent les paramètres DH en utilisant une structure DH. Les paramètres sont encodés à l'aide d'une structure PKCS#3 DHparameter.

Les fonctions ECPKParameters traitent les paramètres EC en utilisant une structure EC_GROUP et la fonction d2i_ECPKParameters(3).

Les fonctions ECPrivateKey traitent une clé privée EC en utilisant une structure EC_KEY.

Les fonctions EC_PUBKEY traitent une clé publique EC en utilisant une structure EC_KEY.

Les fonctions X509 traitent un certificat X509 en utilisant une structure X509. Elles traiteront également un certificat X509 approuvé, mais tous les paramètres de confiance seront ignorés.

Les fonctions X509_AUX traitent un certificat X509 approuvé en utilisant une structure X509.

Les fonctions X509_REQ et X509_REQ_NEW traitent une demande de certificat PKCS#10 en utilisant une structure X509_REQ. Les fonctions d'écriture X509_REQ utilisent CERTIFICATE REQUEST dans l'en-tête, tandis que les fonctions X509_REQ_NEW utilisent NEW CERTIFICATE REQUEST (comme requis par certaines AC). Les fonctions de lecture X509_REQ géreront l'une ou l'autre forme, il n'y a donc pas de fonctions de lecture X509_REQ_NEW.

Les fonctions X509_CRL traitent une CRL X509 en utilisant une structure X509_CRL.

Les fonctions PKCS7 traitent un objet PKCS#7 en utilisant une structure ss="Vt">ContentInfo à l'aide d'une structure PKCS7.

Les fonctions CMS traitent une structure CMS_ContentInfo.

Les anciennes routines d'écriture de PrivateKey sont conservées pour des raisons de compatibilité. Les nouvelles applications devraient écrire les clés privées à l'aide des routines PEM_write_bio_PKCS8PrivateKey() ou PEM_write_PKCS8PrivateKey() car elles sont plus sécurisées (elles utilisent un nombre d'itérations de 2048 tandis que les routines traditionnelles utilisent un compte de 1) sauf si la compatibilité avec les anciennes versions d'OpenSSL est importante.

Les routines de lecture de PrivateKey peuvent être utilisées dans toutes les applications car elles gèrent tous les formats de manière transparente.

Arguments des fonctions PEM

Les fonctions PEM ont de nombreux arguments communs.

Le paramètre bp spécifie le BIO à partir duquel lire ou vers lequel écrire.

Le paramètre fp spécifie le pointeur FILE à partir duquel lire ou vers lequel écrire.

Les fonctions de lecture PEM prennent toutes un argument pointeur vers pointeur x et retournent un pointeur du même type. Si x est NULL, alors le paramètre est ignoré. Si x n'est pas NULL mais que *x est NULL, alors la structure retournée sera écrite dans *x. Si ni x ni *x ne sont NULL, alors une tentative est faite pour réutiliser la structure à *x, mais voir les sections BUGS et EXAMPLES. Indépendamment de la valeur de x, un pointeur vers la structure est toujours retourné, ou NULL si une erreur s'est produite.

Les fonctions PEM qui écrivent les clés privées prennent un paramètre enc, qui spécifie l'algorithme de chiffrement à utiliser. Le chiffrement est effectué au niveau PEM. Si ce paramètre est défini à NULL, alors la clé privée est écrite sous forme non chiffrée.

Les arguments optionnels u et cb sont un mot de passe utilisé pour chiffrer une structure PEM ou une fonction de rappel pour obtenir le mot de passe ; voir pem_password_cb(3) pour plus de détails.

Pour les routines d'écriture PEM, si le paramètre kstr n'est pas NULL, alors klen octets à kstr sont utilisés comme mot de passe et cb est ignoré.

Format de chiffrement PEM

Ces anciennes routines PrivateKey utilisent une technique non standard pour le chiffrement.

La clé privée (ou autre donnée) prend la forme suivante :

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,3F17F5316E2BAC89

...données encodées en base64...
-----END RSA PRIVATE KEY-----

La ligne commençant par “DEK-Info” contient deux informations séparées par des virgules : le nom de l'algorithme de chiffrement tel qu'utilisé par EVP_get_cipherbyname(3) et un sel de 8 octets encodé sous forme d'une série de chiffres hexadécimaux.

Après cela se trouvent les données chiffrées encodées en base64.

La clé de chiffrement est déterminée à l'aide de EVP_BytesToKey(3), en utilisant le sel et un nombre d'itérations de 1. L'IV utilisé est la valeur du sel et *pas* l'IV retourné par EVP_BytesToKey(3).

VALEURS DE RETOUR

Les routines de lecture retournent soit un pointeur vers la structure lue, soit NULL si une erreur s'est produite.

Les routines d'écriture retournent 1 en cas de succès, ou 0 en cas d'échec.

EXEMPLES

Bien que les fonctions PEM prennent plusieurs arguments, dans la quasi-totalité des applications, la plupart d'entre eux sont définis à 0 ou NULL.

Lire un certificat au format PEM à partir d'un BIO :

X509 *x;
x = PEM_read_bio_X509(bp, NULL, 0, NULL);
if (x == NULL) {
	/* Erreur */
}

Méthode alternative :

X509 *x = NULL;
if (!PEM_read_bio_X509(bp, &x, 0, NULL)) {
	/* Erreur */
}

Écrire un certificat dans un BIO :

if (!PEM_write_bio_X509(bp, x)) {
	/* Erreur */
}

Écrire une clé privée non chiffrée dans un FILE :

if (!PEM_write_PrivateKey(fp, key, NULL, NULL, 0, 0, NULL)) {
	/* Erreur */
}

Écrire une clé privée (en utilisant le format traditionnel) dans un BIO en utilisant le chiffrement triple DES ; le mot de passe est demandé :

if (!PEM_write_bio_PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, NULL)) {
	/* Erreur */
}

Écrire une clé privée (en utilisant le format PKCS#8) dans un BIO en utilisant le chiffrement triple DES, en utilisant le mot de passe "hello" :

if (!PEM_write_bio_PKCS8PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, "hello")) {
	/* Erreur */
}

Lire une clé privée à partir d'un BIO en utilisant le mot de passe "hello" :

key = PEM_read_bio_PrivateKey(bp, NULL, 0, "hello");
if (key == NULL) {
	/* Erreur */
}

Lire une clé privée à partir d'un BIO en utilisant une fonction de rappel pour le mot de passe :

key = PEM_read_bio_PrivateKey(bp, NULL, pass_cb, "Ma Clé Privée");
if (key == NULL) {
	/* Erreur */
}

Exemple de fonction de rappel pour le mot de passe :

int
pass_cb(char *buf, int size, int rwflag, void *u)
{
	char	*tmp;
	size_t	 len;

	/* Nous ferions probablement autre chose si 'rwflag' est 1 */
	printf("Entrez le mot de passe pour \"%s\"\n", u);

	/*
	 * Au lieu de la ligne suivante, obtenez le mot de passe
	 * de l'utilisateur d'une manière ou d'une autre.
	 */
	tmp = "hello";
	if (tmp == NULL) /* Une erreur s'est produite. */
		return -1;

	len = strlen(tmp);
	if (len == 0) /* Traiter un mot de passe vide comme une erreur également. */
		return -1;

	/* si trop long, tronquer */
	if (len > size)
		len = size;
	memcpy(buf, tmp, len);
	return len;
}

DESCRIPTION

Ces fonctions gèrent la lecture et l'écriture des clés privées et publiques dans le format de codage PEM. Le format PEM est essentiellement un fichier texte contenant des données binaires codées en Base64, entourées de lignes d'en-tête et de pied de page comme <<<BEGIN PRIVATE KEY>>> et <<<END PRIVATE KEY>>>.

Les fonctions dont le nom contient bio_ prennent un argument BIO, tandis que les autres prennent un argument FILE*.

Les fonctions dont le nom se termine par _nid permettent de spécifier l'algorithme de chiffrement à utiliser lors de l'écriture d'une clé privée PKCS8 en utilisant son NID (Numeric ID). Si nid est 0, aucun chiffrement n'est utilisé. Les fonctions _Bytes sont similaires, mais utilisent l'algorithme de chiffrement spécifié par enc.

cb est un pointeur vers une fonction de rappel de mot de passe. Si cb est NULL, les routines PEM essaieront de demander le mot de passe à l'utilisateur. Sinon, la fonction rappelée sera utilisée. La fonction de rappel reçoit u comme argument, qui peut être utilisé pour passer des informations supplémentaires. La fonction de rappel doit retourner 1 en cas de succès, 0 en cas d'échec. La chaîne de caractères du mot de passe doit être stockée dans le tampon de longueur len. Le mot de passe est traité comme une séquence d'octets, et aucune hypothèse n'est faite quant à son format ou à son encodage.

Les arguments x sont des pointeurs vers des pointeurs pour recevoir la clé lue. S'ils sont initialisés à NULL, une nouvelle structure sera allouée. Sinon, l'objet existant sera utilisé et libéré avant de lire les nouvelles données.

Les fonctions PEM_read_bio_PUBKEY, PEM_read_PUBKEY, PEM_write_bio_PUBKEY et PEM_write_PUBKEY peuvent lire et écrire différents types de clés publiques, y compris les clés RSA, DSA, Diffie-Hellman et ECDSA.

Les fonctions PEM_read_bio_RSA_PUBKEY, PEM_read_RSA_PUBKEY, PEM_write_bio_RSA_PUBKEY et PEM_write_RSA_PUBKEY sont spécifiques aux clés publiques RSA.

Les fonctions PEM_read_bio_DSA_PUBKEY, PEM_read_DSA_PUBKEY, PEM_write_bio_DSA_PUBKEY et PEM_write_DSA_PUBKEY sont spécifiques aux clés publiques DSA.

Les fonctions PEM_write_bio_X509_REQ_NEW et PEM_write_X509_REQ_NEW écrivent des demandes de certificat signées au format PEM.

Les fonctions PEM_read_bio_X509_AUX, PEM_read_X509_AUX, PEM_write_bio_X509_AUX et PEM_write_X509_AUX gèrent les certificats X.509 avec des informations auxiliaires.

Les fonctions PEM_read_bio_ECPKParameters, PEM_read_ECPKParameters, PEM_write_bio_ECPKParameters, PEM_write_ECPKParameters, PEM_read_bio_ECPrivateKey, PEM_read_ECPrivateKey, PEM_write_bio_ECPrivateKey, PEM_write_ECPrivateKey, PEM_read_bio_EC_PUBKEY, PEM_read_EC_PUBKEY, PEM_write_bio_EC_PUBKEY et PEM_write_EC_PUBKEY gèrent les clés privées et publiques EC (Elliptic Curve).

Les fonctions PEM_read_CMS, PEM_read_bio_CMS, PEM_write_CMS et PEM_write_bio_CMS gèrent les objets CMS (Cryptographic Message Syntax).

RETURN VALUES

Toutes ces fonctions retournent un pointeur vers la structure lue en cas de succès, et NULL en cas d'échec. Les fonctions d'écriture retournent 1 en cas de succès, et 0 en cas d'échec.

EXAMPLES

Lecture d'une clé privée à partir d'un fichier avec un mot de passe :

EVP_PKEY *pkey;
BIO *bp;
char *password = "mysecretpassword";

bp = BIO_new_file("private.key", "r");
pkey = PEM_read_bio_PrivateKey(bp, NULL, NULL, password);
BIO_free(bp);
if (pkey == NULL) {
    // Gestion de l'erreur
}
// Utiliser pkey...

Écriture d'une clé privée dans un fichier avec chiffrement AES-256 :

EVP_PKEY *pkey;
BIO *bp;
const EVP_CIPHER *cipher = EVP_aes_256_cbc();

bp = BIO_new_file("private.key.encrypted", "w");
PEM_write_bio_PrivateKey(bp, pkey, cipher, NULL, 0, NULL, NULL);
BIO_free(bp);
EVP_PKEY_free(pkey);

CAVEATS

Une cause fréquente de problèmes est de tenter d'utiliser les routines PEM comme ceci :

X509 *x;
PEM_read_bio_X509(bp, &x, 0, NULL);

C'est une erreur car une tentative sera faite pour réutiliser les données à x, qui est un pointeur non initialisé.

Ces fonctions ne font aucune hypothèse concernant la phrase de passe reçue du rappel de mot de passe. Elle sera simplement traitée comme une séquence d'octets.

BUGS

Les routines de lecture PEM dans certaines versions d'OpenSSL ne réutilisent pas correctement une structure existante. Par conséquent

PEM_read_bio_X509(bp, &x, 0, NULL);

où x contient déjà un certificat valide peut ne pas fonctionner, tandis que

X509_free(x);
x = PEM_read_bio_X509(bp, NULL, 0, NULL);

est garanti de fonctionner.
