DESCRIPTION

libinnstorage est une bibliothèque de routines utilitaires communes (le gestionnaire de stockage) pour accéder aux articles Usenet et aux données associées indépendamment des méthodes de stockage particulières; c'est ce qu'on appelle l'API de stockage.

La fonction du gestionnaire de stockage est d'isoler les applications des méthodes individuelles et de prendre les décisions de politique quant à la méthode de stockage qui doit être appelée pour stocker un article. L'un des concepts clés de l'API de stockage est que les articles ne sont pas manipulés à l'aide de l'ID de message ou du numéro d'article, mais plutôt d'un jeton qui identifie de manière unique l'article à la méthode qui l'a stocké. Cela peut sembler redondant puisque l'ID du message est déjà un identifiant unique de l'article; cependant, puisque la méthode de stockage génère le jeton, elle peut encoder toutes les informations dont elle a besoin pour localiser l'article dans le jeton.

OV est un ensemble de routines utilitaires courantes pour accéder aux groupes de discussion et aux données de présentation (overview) indépendamment des méthodes de présentation particulières.

La fonction OV consiste à isoler les applications des méthodes individuelles. Tous les articles transmis via l'API de stockage sont supposés être au format fil (wire format). Le format fil signifie que les lignes se terminent par "\r\n", les lignes doublées par des points (c'est-à-dire que les lignes commençant par "." et qui commencent déjà par "."), et que ".\r\n" à la fin de l'article sur le flux NNTP ne sont pas supprimés. Cela offre un gain de performance lors du transfert d'articles. Notez que pour la méthode tradspool, le format fil peut être désactivé. Ceci est juste pour la compatibilité, nécessaire à certains anciens outils écrits pour le spool traditionnel.

La fonction IsToken vérifie si le texte est formaté comme une chaîne de jeton textuelle. Elle renvoie true si le format est correct, false sinon.

La fonction TokenToText convertit un jeton en une chaîne de texte pour l'affichage.

La fonction TextToToken convertit une chaîne de texte en un jeton.

La fonction SMsetup configure certains paramètres à utiliser par le gestionnaire de stockage. type est l'un des éléments suivants:

"SM_RDWR"
Autoriser l'ouverture en lecture/écriture pour les fichiers de stockage (la valeur par défaut est false).
"SM_PREOPEN"
Ouvrir tous les fichiers de stockage au démarrage et les garder ouverts (la valeur par défaut est false).

value est le pointeur qui indique la valeur de chaque type. La fonction renvoie true si la configuration réussit, false sinon.

La fonction SMinit appelle la fonction de configuration pour toutes les méthodes configurées basées sur SMsetup. Cette fonction doit être appelée avant toutes les autres fonctions de l'API de stockage commençant par "SM", à l'exception de SMsetup. Elle renvoie true si l'initialisation réussit, false sinon. SMinit renvoie true, sauf si toutes les méthodes de stockage échouent à l'initialisation.

La fonction SMstore stocke un article spécifié par article. Les en-têtes et le corps de l'article sont fournis à SMstore via les membres iov et iovcnt de ARTHANDLE. (data et private sont ignorés par SMstore.) Si arrived est spécifié, SMstore utilise sa valeur comme heure d'arrivée de l'article ; sinon, SMstore utilise l'heure actuelle. SMstore renvoie le type de jeton ou TOKEN_EMPTY si l'article n'est pas stocké en raison d'une erreur ou simplement parce qu'il ne correspond à aucune expression uwildmat dans storage.conf. SMstore échoue si SM_RDWR n'a pas été défini sur true avec SMsetup.

La fonction SMretrieve récupère un article spécifié par token. amount est l'une des options suivantes qui spécifie le type de récupération :

"RETR_ALL"
Récupérer l'article entier.
"RETR_HEAD"
Récupérer les en-têtes de l'article.
"RETR_BODY"
Récupérer le corps de l'article.
"RETR_STAT"
Vérifier simplement si l'article existe.

SMretrieve fournit les données de l'article via les membres data et len de ARTHANDLE. (iov n'est pas défini par SMretrieve.) La zone de données indiquée par ARTHANDLE ne doit pas être modifiée.

La fonction SMnext est similaire en fonction à SMretrieve, sauf qu'elle est destinée à parcourir séquentiellement le stockage d'articles de la méthode. Pour démarrer une requête, SMnext doit être appelée avec un pointeur ARTHANDLE nul. Ensuite, SMnext renvoie un ARTHANDLE qui doit être utilisé pour la requête suivante. Si un pointeur ARTHANDLE nul est renvoyé, il n'y a plus d'articles à interroger. Si data de ARTHANDLE est un pointeur nul ou si len de ARTHANDLE est 0, cela indique que l'article est potentiellement corrompu et doit être annulé par SMcancel. La zone de données indiquée par ARTHANDLE ne doit pas être modifiée.

La fonction SMfreearticle libère toute la mémoire allouée utilisée par SMretrieve et SMnext. Si SMnext est appelée avec un ARTHANDLE précédemment renvoyé, SMfreearticle ne doit pas être appelée car SMnext libère la mémoire allouée en interne.

La fonction SMcancel supprime l'article spécifié par token. Elle renvoie true si l'annulation réussit, false sinon. SMcancel échoue si SM_RDWR n'a pas été défini sur true avec SMsetup.

La fonction SMprobe vérifie le jeton sur PROBETYPE. type est l'un des éléments suivants :

"SELFEXPIRE"
Vérifier si la méthode du jeton possède une fonctionnalité d'expiration automatique.
"SMARTNGNUM"
Obtenir le nom du groupe de discussion et le numéro d'article du jeton.
"EXPENSIVESTAT"
Vérifier si la vérification de

l'état de l'article est coûteuse. La valeur est une variable entière : true si coûteux, false si non.

La fonction SMprintfiles imprime les noms des fichiers stockant l'article spécifié avec token. Elle renvoie true si l'impression réussit ou false si une erreur se produit. xref est un tableau de chaînes Xref pour l'article et ngroups est le nombre de groupes de discussion dans le tableau.

La fonction SMflushcacheddata efface les données de cache spécifiées par type. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction SMexplaintoken convertit un jeton en une chaîne explicative. Elle renvoie un pointeur vers la chaîne allouée ou un pointeur nul en cas d'erreur.

La fonction SMshutdown effectue le nettoyage nécessaire avant la sortie de la bibliothèque. Elle doit être appelée avant la fin du programme.

SMerrno est une variable globale qui contient le code d'erreur du dernier échec des routines de stockage. SMerrorstr est un pointeur vers une chaîne décrivant l'erreur.

OVopen ouvre l'accès aux données de présentation. mode est une combinaison de O_RDONLY, O_WRONLY, ou O_RDWR. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVctl configure des paramètres pour les routines de présentation. type est l'un des éléments suivants :

"OVSPACE"
Vérifie s'il y a suffisamment d'espace pour une nouvelle présentation. val pointe vers une structure OVSPACE.
"OVSORT"
Spécifie le type de tri pour la recherche. val pointe vers un entier de type OVSORTTYPE.
"OVCUTOFFLOW"
Définit la limite inférieure pour l'ajout d'articles. val pointe vers un entier.
"OVGROUPBASEDEXPIRE"
Active l'expiration basée sur le groupe. val pointe vers un entier (true/false).
"OVSTATICSEARCH"
Active la recherche statique. val pointe vers un entier (true/false).
"OVSTATALL"
Demande des statistiques pour tous les groupes. val pointe vers un tableau de structures OVGROUPSTATS.
"OVCACHEKEEP"
Spécifie la durée de conservation des articles mis en cache. val pointe vers un entier.
"OVCACHEFREE"
Libère les articles mis en cache. val pointe vers un entier (nombre d'articles à libérer).

La fonction OVgroupstats récupère les statistiques d'un groupe de discussion spécifié. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVgroupadd ajoute un nouveau groupe de discussion. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVgroupdel supprime un groupe de discussion. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVadd ajoute un article à la base de données de présentation. Elle renvoie un OVADDRESULT indiquant le résultat de l'opération.

La fonction OVcancel supprime un article de la base de données de présentation. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVopensearch ouvre un handle de recherche pour un intervalle d'articles dans un groupe de discussion spécifié. Elle renvoie un pointeur vers le handle de recherche ou un pointeur nul en cas d'erreur.

La fonction OVsearch effectue une recherche dans la base de données de présentation. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVclosesearch ferme un handle de recherche. Elle ne renvoie aucune valeur.

La fonction OVgetartinfo récupère les informations d'un article spécifique. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVexpiregroup supprime les anciens articles d'un groupe de discussion. Elle renvoie true en cas de succès, false en cas d'échec.

La fonction OVclose ferme l'accès aux données de présentation. Elle ne renvoie aucune valeur.

La fonction SMprintfiles affiche le nom de fichier ou le jeton utilisable par fastrm(1).

La fonction SMflushcacheddata vide les données mises en cache pour chaque méthode de stockage. type est l'un des suivants :

"SM_HEAD"
Vide l'en-tête mis en cache.
"SM_CANCELLEDART"
Vide les articles qui doivent être annulés.
"SM_ALL"
Vide toutes les données mises en cache.

La fonction SMexplaintoken renvoie une chaîne de texte lisible par l'homme avec une forme claire et décodée du jeton de l'API de stockage.

La fonction SMshutdown appelle l'arrêt pour chaque méthode de stockage configurée, puis libère toutes les ressources qu'elle a allouées pour elle-même.

SMerrno et SMerrorstr indiquent la raison de la dernière erreur concernant le gestionnaire de stockage.

OVopen appelle la fonction de configuration pour la méthode configurée qui est spécifiée comme ovmethod dans inn.conf. mode est construit à partir de ce qui suit :

"OV_READ"
Autorise l'ouverture en lecture pour la méthode d'aperçu.
"OV_WRITE"
Autorise l'ouverture en écriture pour la méthode d'aperçu.

Cette fonction doit être appelée avant toutes les autres fonctions OV qui commencent par "OV".

La fonction OVctl sonde ou définit certains paramètres pour la méthode d'aperçu. type est l'un des suivants :

"OVGROUPBASEDEXPIRE"
Configure la manière dont l'expiration basée sur les groupes est effectuée.
"OVCUTOFFLOW"
N'ajoute pas de données d'aperçu si les données sont inférieures à l'article le plus bas.
"OVSORT"
Sonde quelle clé convient à la méthode d'aperçu.
"OVSPACE"
Sonde l'utilisation de l'espace d'aperçu.
"OVSTATALL"
Statut de tous les articles lorsque OVexpiregroup est appelé.
"OVSTATICSEARCH"
Configure si les résultats de OVsearch sont stockés dans un tampon statique et doivent être copiés avant le prochain appel à OVsearch.
"OVCACHEKEEP"
Configure si le cache doit être conservé.
"OVCACHEFREE"
Libère le cache.

La fonction OVgroupstats récupère les informations spécifiées du groupe de discussion auprès de la méthode d'aperçu.

La fonction OVgroupadd informe la méthode d'aperçu que le groupe de discussion spécifié est en cours d'ajout.

La fonction OVgroupdel informe la méthode d'aperçu que le groupe de discussion spécifié est en cours de suppression.

La fonction OVadd stocke des données d'aperçu.

La fonction OVcancel demande à la méthode d'aperçu de supprimer les données d'aperçu spécifiées avec le jeton.

La fonction OVopensearch demande à la méthode d'aperçu de préparer la récupération des données d'aperçu. La plage de la requête est déterminée par low et high. Le réglage de OVSTATICSEARCH détermine comment les données de résultat de recherche doivent être traitées. (Notez qu'avec certaines méthodes de stockage, chaque appel à OVopensearch peut entraîner la remappage du stockage interne. Par conséquent, plusieurs recherches simultanées peuvent nécessiter la copie des données entre les appels à OVsearch même si OVSTATICSEARCH est faux.)

La fonction OVsearch récupère des informations, un numéro d'article, des données d'aperçu ou l'heure d'arrivée. Elle doit être appelée avec un handle NULL lors du premier appel ; les appels ultérieurs à OVsearch doivent utiliser le handle renvoyé par l'appel précédent à OVsearch. OVsearch renvoie vrai, sauf si elle atteint high, qui est spécifié par OVopensearch. Les données d'aperçu récupérées sont triées par numéro d'article, et len est 0 s'il n'y a pas de données d'aperçu pour l'article. Notez que les données récupérées ne sont pas nécessairement terminées par null ; vous ne devez vous fier qu'aux octets len de données d'aperçu présents.

La fonction OVclosesearch libère toutes les ressources qui ont été allouées par OVopensearch.

La fonction OVgetartinfo récupère les données d'aperçu et le jeton spécifiés avec artnum.

La fonction OVexpiregroup expire les données d'aperçu du groupe de discussion. Elle vérifie l'existence de l'article et purge les données d'aperçu si l'article n'existe plus. Si groupbaseexpiry dans inn.conf est vrai, OVexpiregroup expire également les articles.

La fonction OVclose libère toutes les ressources utilisées par la méthode d'aperçu.
