DESCRIPTION

BIO_ctrl(), BIO_callback_ctrl(), BIO_ptr_ctrl(), et BIO_int_ctrl() sont des opérations de "contrôle" BIO prenant des arguments de types variés. Ces fonctions ne sont normalement pas appelées directement - diverses macros sont utilisées à la place. Les macros standards sont décrites ci-dessous. Les macros spécifiques à un type de BIO particulier sont décrites dans la page de manuel du BIO spécifique ainsi que toute caractéristique spéciale des appels standards.

Selon le cmd et le type de b, BIO_ctrl() peut avoir un effet en lecture seule sur b ou modifier des données dans b ou dans ses sous-structures. Il peut également avoir pour effet secondaire de modifier la mémoire pointée par parg.

BIO_callback_ctrl() n'appelle pas BIO_ctrl() mais exige que le type de BIO de b fournisse un pointeur de fonction callback_ctrl dédié, qui est intégré à la bibliothèque pour certains types de BIO standards et peut être fourni avec BIO_meth_set_callback_ctrl(3) pour les types de BIO définis par l'application. La seule cmd supportée par BIO_callback_ctrl() est BIO_CTRL_SET_CALLBACK.

BIO_ptr_ctrl() appelle BIO_ctrl() avec parg pointant vers l'emplacement d'une variable pointeur temporaire initialisée à NULL.

BIO_int_ctrl() appelle BIO_ctrl() avec parg pointant vers l'emplacement d'une variable int temporaire initialisée à iarg. Si BIO_ctrl() modifie la valeur stockée à *parg, la nouvelle valeur est ignorée.

BIO_reset() réinitialise généralement un BIO à un état initial. Dans le cas des BIOs liés aux fichiers, par exemple, il rembobine le pointeur de fichier au début du fichier.

BIO_seek() réinitialise la position du fichier des BIOs liés aux fichiers (c'est-à-dire les BIOs descripteurs de fichiers et FILE) à ofs octets depuis le début du fichier.

BIO_tell() retourne la position actuelle du fichier d'un BIO lié au fichier.

BIO_flush() écrit normalement toutes les données tamponnées en interne. Dans certains cas, il est utilisé pour signaler la fin de fichier (EOF) et qu'aucune donnée supplémentaire ne sera écrite.

BIO_eof() retourne 1 si le BIO a lu la fin de fichier (EOF). La signification précise de "EOF" varie selon le type de BIO.

BIO_set_close() définit le drapeau de fermeture du BIO b à flag. flag peut prendre la valeur BIO_CLOSE ou BIO_NOCLOSE. Typiquement, BIO_CLOSE est utilisé dans un BIO source/puits pour indiquer que le flux d'E/S sous-jacent doit être fermé lorsque le BIO est libéré.

BIO_get_close() retourne le drapeau de fermeture du BIO.

BIO_pending(), BIO_ctrl_pending(), BIO_wpending(), et BIO_ctrl_wpending() retournent le nombre de caractères en attente dans les tampons de lecture et d'écriture du BIO. Tous les BIOs ne supportent pas ces appels. BIO_ctrl_pending() et BIO_ctrl_wpending() retournent un type size_t et sont des fonctions.

BIO_set_info_callback() installe le pointeur de fonction cb comme rappel d'information dans b en appelant BIO_callback_ctrl() avec une commande BIO_CTRL_SET_CALLBACK. Parmi les types de BIO intégrés à la bibliothèque, seul BIO_s_c

BIO_callback_ctrl() passes the command cmd to the BIO b. It is also used for retrieving and setting callback functions.

The BIO_INFO_CB and BIO_ADDR_INFO_CB structures are used for callback information.

The following BIO types support this function: BIO_ADDR, BIO_CONNECT, BIO_f_ssl, and BIO_SOCK.

Some filter BIO types forward this control call to the next BIO in the chain instead of processing it themselves.

BIO_get_info_callback() places the function pointer to the info callback into *cbp if any was installed using BIO_set_info_callback() or BIO_callback_ctrl(). If the type of b supports setting an info callback but none was installed, it stores a NULL pointer in *cbp.

The function type name bio_info_cb is a deprecated synonym for BIO_info_cb provided for backward compatibility with some existing application software.

RETURN VALUES

The meaning of the return values of BIO_ctrl(), BIO_callback_ctrl(), and BIO_int_ctrl() depends on both the type of b and on the cmd. If b is a NULL pointer, no action occurs and 0 is returned. The return value -2 usually indicates a fatal error. In particular, it is returned if the cmd is unsupported by the type of b.

BIO_callback_ctrl() and BIO_set_info_callback() return 1 on success, 0 if b is NULL or to indicate failure of a valid cmd, or -2 if the cmd is not supported by b.

BIO_ptr_ctrl() returns NULL if the BIO_ctrl() call returns a negative value or does not change *parg, or the pointer it puts into *parg otherwise.

BIO_int_ctrl() returns the return value of BIO_ctrl().

BIO_reset() normally returns 1 for success and 0 or -1 for failure. File BIOs are an exception, returning 0 for success and -1 for failure.

BIO_seek() and BIO_tell() both return the current file position on success and -1 for failure, except file BIOs which for BIO_seek() always return 0 for success and -1 for failure.

BIO_flush() returns 1 for success and 0 or -1 for failure.

BIO_eof() returns 1 if EOF has been reached or 0 otherwise.

BIO_set_close() always returns 1.

BIO_get_close() returns the close flag value BIO_CLOSE or BIO_NOCLOSE.

BIO_pending(), BIO_ctrl_pending(), BIO_wpending(), and BIO_ctrl_wpending() return the amount of pending data.

BIO_get_info_callback() returns 1 on success, including when the type of b supports an info callback but none is installed, 0 if b is NULL or -2 if the type of b does not support an info callback.

If a callback was installed in b using BIO_set_callback_ex(3) or BIO_set_callback(3), it can modify the return values of all these functions.

NOTES

Because it can write data, BIO_flush() may return 0 or -1 indicating that the call should be retried later in a similar manner to BIO_write(3). The BIO_should_retry(3) call should be used and appropriate action taken if the call fails.

The return values of BIO_pending() and BIO_wpending() may not reliably determine the amount of pending data in all cases. For example in the case of a file BIO some data may be available in the FILE structure's internal buffers but it is not possible to determine this in a portable way. For other types of BIO they may not be supported.

If they do not internally handle a particular BIO_ctrl() operation, filter BIOs usually pass the operation to the next BIO in the chain. This often means there is no need to locate the required BIO for a particular operation: it can be called on a chain and it will be automatically passed to the relevant BIO. However, this can cause unexpected results. For example no current filter BIOs implement BIO_seek(), but this may still succeed if the chain ends in a FILE or file descriptor BIO.

Source/sink BIOs return a 0 if they do not recognize the BIO_ctrl() operation.

HISTORY

BIO_ctrl(), BIO_reset(), BIO_flush(), BIO_eof(), BIO_set_close(), BIO_get_close(), et BIO_pending() sont apparus pour la première fois dans SSLeay 0.6.0. BIO_wpending() est apparu pour la première fois dans SSLeay 0.8.1. BIO_ptr_ctrl(), BIO_int_ctrl(), BIO_get_info_callback() et BIO_set_info_callback() sont apparus pour la première fois dans SSLeay 0.9.0. Toutes ces fonctions sont disponibles depuis OpenBSD 2.4.

BIO_seek() et BIO_tell() sont apparus pour la première fois dans SSLeay 0.9.1. BIO_ctrl_pending() et BIO_ctrl_wpending() sont apparus pour la première fois dans OpenSSL 0.9.4. Ces fonctions sont disponibles depuis OpenBSD 2.6.

BIO_callback_ctrl() est apparu pour la première fois dans OpenSSL 0.9.5 et est disponible depuis OpenBSD 2.7.

bio_info_cb() est apparu pour la première fois avec un prototype plus compliqué dans OpenSSL 0.9.6 et est disponible depuis OpenBSD 2.9.

BIO_info_cb() est apparu pour la première fois dans OpenSSL 1.1.0h et est disponible depuis OpenBSD 6.3.

BUGS

Certaines des valeurs de retour sont ambiguës et il faut en prendre garde. En particulier, une valeur de retour de 0 peut être retournée si une opération n'est pas supportée, si une erreur s'est produite, si la fin du fichier n'a pas été atteinte et dans le cas de BIO_seek() sur un BIO de fichier pour une opération réussie.
