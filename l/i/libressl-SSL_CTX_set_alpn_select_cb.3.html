libressl-SSL_CTX_set_alpn_select_cb(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

SSL_CTX_SET_ALPN_SELECT_CB(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_ALPN_SELECT_CB(3)

NOM

SSL_CTX_set_alpn_protos, SSL_set_alpn_protos, SSL_CTX_set_alpn_select_cb, SSL_select_next_proto, SSL_get0_alpn_selected — gérer la négociation de protocole de couche application (ALPN)

SYNOPSIS

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos, unsigned int protos_len);

int
SSL_set_alpn_protos(SSL *ssl, const unsigned char *protos, unsigned int protos_len);

void
SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx, int (*cb)(SSL *ssl, const unsigned char **out, unsigned char *outlen, const unsigned char *in, unsigned int inlen, void *arg), void *arg);

int
SSL_select_next_proto(unsigned char **out, unsigned char *outlen, const unsigned char *peer_list, unsigned int peer_list_len, const unsigned char *supported_list, unsigned int supported_list_len);

void
SSL_get0_alpn_selected(const SSL *ssl, const unsigned char **data, unsigned int *len);

DESCRIPTION

SSL_CTX_set_alpn_protos() et SSL_set_alpn_protos() sont utilisés par le client pour définir la liste des protocoles disponibles pour la négociation. Les protos doivent être au format liste de protocoles, décrit ci-dessous. La longueur de protos est spécifiée dans protos_len.

SSL_CTX_set_alpn_select_cb() définit le rappel d'application cb utilisé par un serveur pour sélectionner le protocole à utiliser pour la connexion entrante. Lorsque cb est NULL, ALPN n'est pas utilisé. La valeur arg est un pointeur qui est passé au rappel d'application.

cb est le rappel défini par l'application. Les paramètres in, inlen forment un vecteur au format liste de protocoles. La valeur du vecteur out, outlen doit être définie à la valeur d'un seul protocole sélectionné dans le vecteur in, inlen. Le tampon out peut pointer directement vers in, ou vers un tampon qui survit à la négociation. Le paramètre arg est le pointeur défini via SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() est une fonction d'aide utilisée pour sélectionner les protocoles. On s'attend à ce que cette fonction soit appelée depuis le rappel d'application cb. Si SSL_select_next_proto() renvoie OPENSSL_NPN_NO_OVERLAP, cb doit ignorer out et échouer en renvoyant SSL_TLSEXT_ERR_ALERT_FATAL. Les données de protocole dans peer_list, peer_list_len et supported_list, supported_list_len doivent être deux listes non vides, valablement encodées dans le format liste de protocoles décrit ci-dessous. Le premier élément de peer_list qui correspond à un élément de supported_list est sélectionné et renvoyé dans out, outlen. La valeur out pointera vers peer_list ou supported_list, elle ne doit donc pas être modifiée et doit être copiée immédiatement. Si aucune correspondance n'est trouvée, le premier élément de supported_list est renvoyé dans out, outlen.

SSL_get0_alpn_selected() renvoie un pointeur vers le protocole sélectionné dans data avec la longueur len. Il n'est pas terminé par NUL. data est mis à NULL et len est mis à 0 si aucun protocole n'a été sélectionné. data ne doit pas être libéré.

Les listes de protocoles doivent être au format réseau, défini comme un vecteur de chaînes de caractères d'octets préfixées par leur longueur et non vides. Le préfixe de longueur n'est pas inclus dans la longueur. Chaque chaîne est limitée à 255 octets. Une longueur de chaîne de 0 est invalide. La longueur du vecteur n'est pas dans le vecteur lui-même, mais dans une variable séparée.

Par exemple :

const unsigned char *vector = "\x06" "spdy/1" "\x08" "http/1.1";
unsigned int length = strlen(vector);

Le rappel ALPN est exécuté après le rappel servername ; car ce rappel servername peut mettre à jour le SSL_CTX, et par conséquent, le rappel ALPN.

S'il n'y a pas de proposition ALPN dans le ClientHello, le rappel ALPN n'est pas invoqué.

VALEURS DE RETOUR

SSL_CTX_set_alpn_protos() et SSL_set_alpn_protos() renvoient 0 en cas de succès ou une valeur non nulle en cas d'échec. ATTENTION : ces fonctions inversent la convention de valeur de retour.

SSL_select_next_proto() renvoie l'une des valeurs suivantes :

OPENSSL_NPN_NEGOTIATED
Une correspondance a été trouvée et est renvoyée dans out, outlen.
OPENSSL_NPN_NO_OVERLAP
Aucune correspondance n'a été trouvée. Le premier élément de supported_list, supported_list_len est renvoyé dans out, outlen.

Le rappel de sélection ALPN cb doit renvoyer l'une des valeurs suivantes :

SSL_TLSEXT_ERR_OK
Protocole ALPN sélectionné.
SSL_TLSEXT_ERR_ALERT_FATAL
Il n'y a pas eu de chevauchement entre la liste fournie par le client et la configuration du serveur.
SSL_TLSEXT_ERR_NOACK
Protocole ALPN non sélectionné, par exemple, parce qu'aucun protocole ALPN n'est configuré pour cette connexion.

AVERTISSEMENTS

Le repli vers le premier protocole supporté dans SSL_select_next_proto() provient du mécanisme de repli opportuniste dans l'extension NPN. Ce comportement n'a pas de sens pour ALPN, où le manque de chevauchement de protocoles devrait entraîner l'échec de la négociation. Pour éviter la sélection accidentelle d'un protocole que le serveur ne supporte pas, il est recommandé de passer les protocoles configurés localement comme deuxième paire de protocoles dans le callback ALPN.

BOGUES

L'argument out de SSL_select_next_proto() aurait dû être const.
