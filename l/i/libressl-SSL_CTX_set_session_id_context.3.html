SSL_CTX_SET_SESSION_ID_CONTEXT(3) Manuel de la bibliothèque SSL_CTX_SET_SESSION_ID_CONTEXT(3)

NOM

SSL_CTX_set_session_id_context, SSL_set_session_id_context — définir le contexte dans lequel une session peut être réutilisée (côté serveur uniquement)

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_set_session_id_context(SSL_CTX *ctx, const unsigned char *sid_ctx, unsigned int sid_ctx_len);

int
SSL_set_session_id_context(SSL *ssl, const unsigned char *sid_ctx, unsigned int sid_ctx_len);

DESCRIPTION

SSL_CTX_set_session_id_context() définit le contexte sid_ctx de longueur sid_ctx_len dans lequel une session peut être réutilisée pour l'objet ctx.

SSL_set_session_id_context() définit le contexte sid_ctx de longueur sid_ctx_len dans lequel une session peut être réutilisée pour l'objet ssl.

Les sessions sont générées dans un certain contexte. Lors de l'exportation/importation de sessions avec i2d_SSL_SESSION(3) et d2i_SSL_SESSION(3), il serait possible de réimporter une session générée à partir d'un autre contexte (par exemple, une autre application), ce qui pourrait entraîner des dysfonctionnements. Par conséquent, chaque application doit définir son propre contexte d'identifiant de session sid_ctx qui est utilisé pour distinguer les contextes et est stocké dans les sessions exportées. Le sid_ctx peut être de tout type de données binaires avec une longueur donnée ; il est donc possible d'utiliser, par exemple, le nom de l'application, le nom d'hôte, le nom du service...

Le contexte d'identifiant de session fait partie de la session. Le contexte d'identifiant de session est défini par le serveur SSL/TLS. Les fonctions SSL_CTX_set_session_id_context() et SSL_set_session_id_context() sont donc uniquement utiles côté serveur.

Les clients OpenSSL vérifieront le contexte d'identifiant de session retourné par le serveur lors de la réutilisation d'une session.

La longueur maximale de sid_ctx est limitée à SSL_MAX_SSL_SESSION_ID_LENGTH.

AVERTISSEMENTS

Si le contexte d'identifiant de session n'est pas défini sur un serveur SSL/TLS et que des certificats clients sont utilisés, les sessions stockées ne seront pas réutilisées mais une erreur fatale sera signalée et la négociation échouera.

Si un serveur retourne un contexte d'identifiant de session différent à un client OpenSSL lors de la réutilisation d'une session, une erreur sera signalée et la négociation échouera. Les serveurs OpenSSL retourneront toujours le contexte d'identifiant de session correct, car un serveur OpenSSL vérifie lui-même le contexte d'identifiant de session avant de réutiliser une session comme décrit ci-dessus.

VALEURS DE RETOUR

SSL_CTX_set_session_id_context() et SSL_set_session_id_context() retournent les valeurs suivantes :

0
La longueur sid_ctx_len du contexte d'identifiant de session sid_ctx a dépassé la longueur maximale autorisée de SSL_MAX_SSL_SESSION_ID_LENGTH. L'erreur est enregistrée dans la pile d'erreurs.
1
L'opération a réussi.

VOIR AUSSI

ssl(3), SSL_SESSION_set1_id_context(3)

HISTORIQUE

SSL_set_session_id_context() est apparu pour la première fois dans OpenSSL 0.9.2b. SSL_CTX_set_session_id_context() est apparu pour la première fois dans OpenSSL 0.9.3. Les deux fonctions sont disponibles depuis OpenBSD 2.6.
