NOM

lib::core::only - Supprime tous les chemins non essentiels de @INC pour éviter les répertoires site/vendor

SYNOPSIS

use lib::core::only; # maintenant @INC contient uniquement les deux répertoires essentiels

Pour obtenir uniquement les répertoires essentiels plus ceux de local::lib en cours d'exécution :

$ perl -mlocal::lib -Mlib::core::only -Mlocal::lib=~/perl5 myscript.pl

Pour tenter de créer une construction autonome (mais notez que cela ne se propagera pas de manière fiable dans les sous-processus, voir les LIMITATIONS ci-dessous) :

$ PERL5OPT='-mlocal::lib -Mlib::core::only -Mlocal::lib=~/perl5' cpan

Veuillez noter qu'il est nécessaire d'utiliser "local::lib" deux fois pour que cela fonctionne. Premièrement, pour que "lib::core::only" n'empêche pas "local::lib" de se charger (il n'est pas actuellement essentiel) et ensuite à nouveau après "lib::core::only" afin que les chemins locaux ne soient pas supprimés.

DESCRIPTION

lib::core::only est simplement un raccourci pour dire « veuillez réduire mon @INC aux seuls répertoires lib et archlib (lib spécifique à l'architecture) de ce perl ».

Vous pourriez vouloir faire cela pour vous assurer qu'un local::lib ne contient que le code dont vous avez besoin, ou pour tester un arbre App::FatPacker, ou pour éviter des paquets vendor connus et problématiques.

Vous pourriez vouloir l'utiliser pour essayer d'installer un arbre de modules perl autonome. Soyez averti que cela ne fonctionnera probablement pas (voir "LIMITATIONS").

Ce module a été extrait de la fonctionnalité --self-contained de local::lib, et contient la seule partie qui ait jamais fonctionné. Je m'excuse auprès de quiconque pensait que quelque chose d'autre le faisait.

LIMITATIONS

Cela ne se propage **pas** correctement d'une invocation perl à l'autre comme le fait le contenu de local::lib. Cela ne peut pas. Il s'agit uniquement d'une importation de module, donc cela **affecte uniquement l'instance de machine virtuelle perl spécifique dans laquelle vous le chargez et l'importez()**.

Si vous souhaitez le faire cascader d'une invocation à l'autre, vous pouvez définir la variable d'environnement PERL5OPT à '-Mlib::core::only' et cela fonctionnera en quelque sorte. Mais gardez à l'esprit que le mode taint ignore cela, donc certains codes de construction et de test des modules probablement aussi.

Vous devez également être conscient que les options de ligne de commande de perl ne sont pas traitées dans l'ordre - les options -I prennent effet avant les options -M, donc

perl -Mlib::core::only -Ilib

ne fera probablement pas ce que vous voulez - c'est exactement équivalent à :

perl -Mlib::core::only

Si vous souhaitez combiner un @INC essentiel uniquement avec des chemins supplémentaires, vous devez ajouter les chemins supplémentaires à l'aide des options -M et du module lib :

perl -Mlib::core::only -Mlib=lib
# ou si vous essayez de tester du code compilé :
perl -Mlib::core::only -Mblib

Pour plus d'informations sur l'impossibilité de propager cela de manière saine à travers les constructions de modules sans l'aide du programme de construction, voir http://www.shadowcat.co.uk/blog/matt-s-trout/tainted-love - et pour des moyens d'obtenir les résultats de l'ancienne fonctionnalité --self-contained, regardez la fonction tree d'App::FatPacker, et la fonctionnalité --local-lib-contained d'App::cpanminus.
