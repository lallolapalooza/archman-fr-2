LIBRTMP(3) Manuel des fonctions de bibliothèque LIBRTMP(3)

NOM

librtmp - API du protocole RTMP (Real-Time Messaging Protocol) de RTMPDump

BIBLIOTHEQUE

RTMPDump RTMP (librtmp, -lrtmp)

SYNTAXE

#include <librtmp/rtmp.h>

DESCRIPTION

Le protocole RTMP (Real-Time Messaging Protocol) est utilisé pour le streaming de contenu multimédia sur un réseau TCP/IP. Cette API fournit la plupart des fonctions client et quelques fonctions serveur nécessaires pour prendre en charge RTMP, RTMP tunnellé sur HTTP (RTMPT), RTMP crypté (RTMPE), RTMP sur SSL/TLS (RTMPS) et les variantes tunnellées de ces types cryptés (RTMPTE, RTMPTS). La spécification RTMP de base a été publiée par Adobe, mais cette API a été rétro-conçue sans utiliser la spécification Adobe. En tant que telle, elle peut s'écarter des spécifications publiées, mais elle reproduit généralement le comportement réel des clients Adobe d'origine.

Le package logiciel RTMPDump comprend un utilitaire client de base dans rtmpdump(1), quelques serveurs d'exemple, et une bibliothèque utilisée pour fournir un accès programmatique au protocole RTMP. Cette page de manuel donne un aperçu des routines de la bibliothèque RTMP. Ces routines se trouvent dans la bibliothèque -lrtmp. De nombreuses autres routines sont également disponibles, mais elles ne sont pas encore documentées.

L'interaction de base se déroule comme suit. Un descripteur de session est créé à l'aide de RTMP_Alloc() et initialisé à l'aide de RTMP_Init(). Tous les paramètres de session sont fournis à l'aide de RTMP_SetupURL(). La connexion réseau est établie à l'aide de RTMP_Connect(), puis la session RTMP est établie à l'aide de RTMP_ConnectStream(). Le flux est lu à l'aide de RTMP_Read(). Un client peut publier un flux en appelant RTMP_EnableWrite() avant l'appel RTMP_Connect(), puis en utilisant RTMP_Write() après l'établissement de la session. Pendant qu'un flux est en lecture, il peut être mis en pause et repris à l'aide de RTMP_Pause(). La position de lecture du flux peut être déplacée à l'aide de RTMP_Seek(). Lorsque RTMP_Read() retourne 0 octets, le flux est terminé et peut être fermé à l'aide de RTMP_Close(). Le descripteur de session est libéré à l'aide de RTMP_Free().

Toutes les données sont transférées au format FLV. La session de base nécessite une URL RTMP. Le format de l'URL RTMP est de la forme

  rtmp[t][e|s]://hostname[:port][/app[/playpath]]

RTMP simple, ainsi que les sessions tunnellées et cryptées sont prises en charge.

Des options supplémentaires peuvent être spécifiées en ajoutant des paires clé=valeur séparées par des espaces à l'URL. Les caractères spéciaux dans les valeurs peuvent nécessiter un échappement pour éviter une mauvaise interprétation par l'analyseur d'options. L'encodage d'échappement utilise une barre oblique inverse suivie de deux chiffres hexadécimaux représentant la valeur ASCII du caractère. Par exemple, les espaces doivent être échappés sous forme de \20 et les barres obliques inverses doivent être échappées sous forme de \5c.

OPTIONS

Paramètres réseau

Ces options définissent comment se connecter au serveur multimédia.

socks=hôte:port
Utiliser le proxy SOCKS4 spécifié.

Paramètres de connexion

Ces options définissent le contenu du paquet de requête RTMP Connect. Si des valeurs correctes ne sont pas fournies, le serveur multimédia rejettera la tentative de connexion.

app=nom
Nom de l'application à laquelle se connecter sur le serveur RTMP. Remplace l'application dans l'URL RTMP. Parfois, l'analyseur d'URL de librtmp ne parvient pas à déterminer automatiquement le nom de l'application, il doit donc être fourni explicitement à l'aide de cette option.
tcUrl=url
URL du flux cible. Par défaut, rtmp[t][e|s]://host[:port]/app.
pageUrl=url
URL de la page Web dans laquelle le média a été intégré. Par défaut, aucune valeur ne sera envoyée.
swfUrl=url
URL du lecteur SWF pour le média. Par défaut, aucune valeur ne sera envoyée.
flashVer=version
Version du plugin Flash utilisé pour exécuter le lecteur SWF. Par défaut, "LNX 10,0,32,18".
conn=type:donnée
Ajoute des données AMF arbitraires au message Connect. Le type doit être B pour Booléen, N pour Nombre, S pour Chaîne, O pour Objet, ou Z pour Null. Pour les booléens, les données doivent être 0 ou 1 pour FAUX ou VRAI, respectivement. De même, pour les objets, les données doivent être 0 ou 1 pour terminer ou commencer un objet, respectivement. Les éléments de données dans les sous-objets peuvent être nommés, en préfixant le type avec 'N' et en spécifiant le nom avant la valeur, par exemple NB:monFlag:1. Cette option peut être utilisée plusieurs fois pour construire des séquences AMF arbitraires. Par exemple : 
  conn=B:1 conn=S:authMe conn=O:1 conn=NN:code:1.23 conn=NS:flag:ok conn=O:0

Paramètres de session

Ces options prennent effet après la réussite de la requête Connect.

playpath=chemin
Remplace le playpath analysé à partir de l'URL RTMP. Parfois, l'analyseur d'URL de rtmpdump ne parvient pas à déterminer automatiquement le playpath correct, il doit donc être fourni explicitement à l'aide de cette option.
playlist=0|1
Si la valeur est 1 ou VRAI, émet une commande set_playlist avant d'envoyer la commande play. La playlist contiendra uniquement le playpath actuel. Si la valeur est 0 ou FAUX, la commande set_playlist ne sera pas envoyée. La valeur par défaut est FAUX.
live=0|1
Indique que le média est un flux en direct. Aucune reprise ou recherche dans les flux en direct n'est possible.
subscribe=chemin
Nom du flux en direct auquel s'abonner. Par défaut, il s'agit de playpath.
start=num
Commencer à num secondes dans le flux. Non valide pour les flux en direct.
stop=num
Arrêter à num secondes dans le flux.
buffer=num
Définir le temps de mise en mémoire tampon à num millisecondes. Par défaut, 30000.
timeout=num
Temps d'attente de la session après num secondes sans recevoir de données du serveur. Par défaut, 120.

Paramètres de sécurité

Ces options gèrent les demandes d'authentification supplémentaires du serveur.

token=clé
Clé pour la réponse SecureToken, utilisée si le serveur nécessite une authentification SecureToken.
jtv=JSON
Jeton JSON utilisé par les anciens serveurs Justin.tv. Déclenche NetStream.Authenticate.UsherToken
swfVfy=0|1
Si la valeur est 1 ou VRAI, le lecteur SWF est récupéré depuis le swfUrl spécifié pour effectuer la vérification SWF. Le hachage SWF et la taille (utilisés dans l'étape de vérification) sont calculés automatiquement. Les informations SWF sont également mises en cache dans un fichier .swfinfo dans le répertoire personnel de l'utilisateur, afin qu'elles n'aient pas besoin d'être récupérées et recalculées à chaque fois. Le fichier .swfinfo enregistre l'URL SWF, l'heure de récupération, l'horodatage de modification du fichier SWF, sa taille et son hachage. Par défaut, les informations mises en cache seront utilisées pendant 30 jours avant une nouvelle vérification.
swfAge=jours
Spécifie combien de jours utiliser les informations SWF mises en cache avant de vérifier à nouveau. Utilisez 0 pour toujours vérifier l'URL SWF. Notez que si la vérification montre que le fichier SWF a le même horodatage de modification qu'auparavant, il ne sera pas récupéré à nouveau.

EXEMPLES

Pour lire un flux RTMP:

  rtmpdump -r rtmp://example.com/myapp/stream

Pour lire un flux RTMPT:

  rtmpdump -r rtmp://example.com/myapp/stream --rtmp-port 80 --rtmp-proto rtmpt

Pour lire un flux RTMP sur une connexion SSL/TLS:

  rtmpdump -r rtmps://example.com/myapp/stream

Pour lire un flux RTMP tunnellé sur un port HTTP différent:

  rtmpdump -r rtmp://example.com/myapp/stream --rtmp-port 8080 --rtmp-proto rtmpte

Pour lire une vidéo en direct à partir d'un serveur spécifique:

  rtmpdump -r rtmp://live.example.com/app/stream --live

Pour lire une vidéo depuis un serveur qui utilise une authentification SecureToken:

  rtmpdump -r rtmp://example.com/myapp/stream --token secure_token_key

Pour spécifier un lecteur SWF personnalisé et une URL de page:

  rtmpdump -r rtmp://example.com/myapp/stream \
    --swfUrl http://example.com/player.swf \
    --pageUrl http://example.com/page.html

Pour démarrer la lecture à partir de 60 secondes dans un flux:

  rtmpdump -r rtmp://example.com/myapp/stream --start 60

Pour spécifier un proxy SOCKS:

  rtmpdump -r rtmp://example.com/myapp/stream --socks socks.example.com:1080

Pour spécifier des paramètres de connexion personnalisés (par exemple, pour certains serveurs Flash Media Server):

  rtmpdump -r rtmp://example.com/myapp/stream \
    --app analytics \
    --tcUrl rtmp://example.com:1935/analytics \
    --flashVer "LNX 11,2,202,234"

Pour enregistrer un flux en direct dans un fichier:

  rtmpdump -r rtmp://example.com/myapp/stream --live --outfile live_stream.flv

Pour lire une playlist personnalisée:

  rtmpdump -r rtmp://example.com/myapp/playlist \
    --playlist 1 \
    --playpath "mp4:video.mp4"

Pour publier un flux RTMP:

  rtmpdump -r rtmp://example.com/myapp/my_stream --out file.flv --rtmp-enable-write

Pour envoyer des données AMF arbitraires au serveur:

  rtmpdump -r rtmp://example.com/myapp/stream \
    --conn B:1 NS:user:John Doe NN:age:30
