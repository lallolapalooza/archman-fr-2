DESCRIPTION

La structure EVP_PKEY est utilisée par diverses fonctions OpenSSL qui nécessitent une clé privée ou publique générale sans référence à un algorithme particulier.

La fonction EVP_PKEY_new() alloue une structure EVP_PKEY vide. Le compteur de références est initialisé à 1. Pour y ajouter une clé privée ou publique, utilisez les fonctions décrites dans EVP_PKEY_set1_RSA(3).

EVP_PKEY_up_ref() incrémente le compteur de références de pkey de 1.

EVP_PKEY_free() décrémente le compteur de références de pkey de 1 et, si le compteur de références atteint zéro, le libère. Si pkey est un pointeur NULL, aucune action n'est effectuée.

EVP_PKEY_new_raw_private_key() alloue une nouvelle EVP_PKEY. Le NID d'un algorithme de clé publique prenant en charge les clés privées brutes, c'est-à-dire EVP_PKEY_HMAC, EVP_PKEY_X25519, ou EVP_PKEY_ED25519, est fourni dans l'argument type et rawlen octets de données de clé privée brute de ce type dans rawpriv. La clé publique est automatiquement dérivée des données de clé privée fournies, si cela convient au type d'algorithme. L'argument ENGINE *engine est toujours ignoré et il est recommandé de passer NULL.

EVP_PKEY_new_raw_public_key() fonctionne de la même manière que EVP_PKEY_new_raw_private_key() sauf que rawpub pointe vers les données de clé publique brute. Les types d'algorithmes prenant en charge les clés publiques brutes sont EVP_PKEY_X25519 et EVP_PKEY_ED25519.

EVP_PKEY_new_mac_key() est une fonction dépréciée qui produit le même effet que EVP_PKEY_new_raw_private_key() d'une manière plus compliquée et ne fonctionne qu'avec un type de EVP_PKEY_HMAC.

EVP_PKEY_get_raw_private_key() écrit jusqu'à *rawlen octets de données de clé privée brute dans le tampon commençant à rawpriv et stocke le nombre d'octets écrits dans *rawlen. L'application appelante est responsable de s'assurer que le tampon est suffisamment grand pour recevoir les données de clé privée. Si l'argument rawpriv est NULL, le nombre d'octets requis pour contenir la clé est stocké dans *rawlen. Cette fonction ne fonctionne que pour les algorithmes qui prennent en charge les clés privées brutes. Actuellement, ce sont EVP_PKEY_HMAC, EVP_PKEY_X25519 et EVP_PKEY_ED25519.

EVP_PKEY_get_raw_public_key() est similaire à EVP_PKEY_get_raw_private_key() sauf qu'elle écrit des données de clé publique brute. Cette fonction ne fonctionne que pour les algorithmes qui prennent en charge les clés publiques brutes. Actuellement, ce sont EVP_PKEY_X25519 et EVP_PKEY_ED25519.

VALEURS DE RETOUR

EVP_PKEY_new(), EVP_PKEY_new_raw_private_key(), EVP_PKEY_new_raw_public_key(), et EVP_PKEY_new_mac_key() retournent soit la structure EVP_PKEY nouvellement allouée, soit NULL en cas d'erreur.

EVP_PKEY_up_ref(), EVP_PKEY_get_raw_private_key(), et EVP_PKEY_get_raw_public_key() retournent 1 en cas de succès, ou 0 en cas d'échec.

EXEMPLES

Le code suivant génère un digest avec HMAC-SHA256 :

/* Clé factice : serait normalement définie à partir d'une autre source */
const unsigned char *key = "key";
const size_t key_len = strlen(key);

const char *msg = "The quick brown fox jumps over the lazy dog";
const size_t msg_len = strlen(msg);

unsigned char *out_mac;
size_t out_len, i;

EVP_PKEY *pkey;
EVP_MD_CTX *md_ctx;

pkey = EVP_PKEY_new_raw_private_key(EVP_PKEY_HMAC, NULL,
    key, key_len);
if (pkey == NULL)
	err(1, "EVP_PKEY_new_raw_private_key");

md_ctx = EVP_MD_CTX_new();
if (md_ctx == NULL)
	err(1, "EVP_MD_CTX_new");

if (EVP_DigestSignInit(md_ctx, NULL, EVP_sha256(), NULL, pkey) == 0)
	err(1, "EVP_DigestSignInit");
if (EVP_DigestSign(md_ctx, NULL, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign(NULL)");
if ((out_mac = calloc(1, out_len)) == NULL)
	err(1, "calloc");
if (EVP_DigestSign(md_ctx, out_mac, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign(MAC)");

EVP_MD_CTX_free(md_ctx);
EVP_PKEY_free(pkey);

printf(" MAC = ");
for (i = 0; i < out_len; i++)
	printf("%02x", out_mac[i]);
printf("\n");
free(out_mac);

Même si le nom du type EVP_PKEY signifiait originellement « clé privée » et que l'API EVP_DigestSignInit(3) était conçue pour les signatures numériques dans le contexte de la cryptographie à clé publique, les deux sont également utilisés ici car un MAC nécessite également une clé, même s'il s'agit d'une clé symétrique.

Le même code peut être utilisé pour signer avec Ed25519 en rendant la clé ED25519_PRIVATE_KEY_LENGTH = 32 octe

HISTORIQUE

EVP_PKEY_new() et EVP_PKEY_free() sont apparus pour la première fois dans SSLeay 0.6.0 et sont disponibles depuis OpenBSD 2.4.

EVP_PKEY_new_mac_key() est apparu pour la première fois dans OpenSSL 1.0.0 et est disponible depuis OpenBSD 4.9.

EVP_PKEY_up_ref() est apparu pour la première fois dans OpenSSL 1.1.0 et est disponible depuis OpenBSD 6.3.

EVP_PKEY_new_raw_private_key(), EVP_PKEY_new_raw_public_key(), EVP_PKEY_get_raw_private_key(), et EVP_PKEY_get_raw_public_key() sont apparus pour la première fois dans OpenSSL 1.1.1 et sont disponibles depuis OpenBSD 7.3.
