EVP_VERIFYINIT(3) Manuel des fonctions de bibliothèque EVP_VERIFYINIT(3)

NOM

EVP_VerifyInit_ex, EVP_VerifyUpdate, EVP_VerifyFinal, EVP_VerifyInit — fonctions de vérification de signature EVP

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_VerifyInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *engine);

int
EVP_VerifyUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);

int
EVP_VerifyFinal(EVP_MD_CTX *ctx, unsigned char *sigbuf, unsigned int siglen, EVP_PKEY *pkey);

int
EVP_VerifyInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPTION

Les routines de vérification de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_VerifyInit_ex() configure le contexte de vérification ctx pour utiliser le digest type. Avant d'appeler cette fonction, obtenez ctx à partir de EVP_MD_CTX_new(3) ou appelez EVP_MD_CTX_reset(3) sur celui-ci. L'argument engine est toujours ignoré et il est recommandé de passer NULL.

EVP_VerifyUpdate() hache cnt octets de données situés à d dans le contexte de vérification ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires.

EVP_VerifyFinal() vérifie les données dans ctx en utilisant la clé publique pkey et par rapport aux siglen octets situés à sigbuf.

EVP_VerifyInit() initialise un contexte de vérification ctx pour utiliser l'implémentation par défaut du digest type.

L'interface EVP pour les signatures numériques devrait presque toujours être utilisée de préférence aux interfaces de bas niveau. Cela est dû au fait que le code devient ainsi transparent à l'algorithme utilisé et beaucoup plus flexible.

L'appel à EVP_VerifyFinal() finalise en interne une copie du contexte de digest. Cela signifie que les appels à EVP_VerifyUpdate() et EVP_VerifyFinal() peuvent être appelés ultérieurement pour hacher et vérifier des données supplémentaires.

Étant donné que seule une copie du contexte de digest est finalisée, le contexte doit être nettoyé après utilisation en appelant EVP_MD_CTX_free(3), sinon une fuite de mémoire se produira.

EVP_VerifyInit_ex(), EVP_VerifyUpdate(), et EVP_VerifyInit() sont implémentées sous forme de macros.

VALEURS DE RETOUR

EVP_VerifyInit_ex() et EVP_VerifyUpdate() renvoient 1 en cas de succès et 0 en cas d'échec.

EVP_VerifyFinal() renvoie 1 pour une signature correcte, 0 pour un échec, et -1 si une autre erreur s'est produite.

Les codes d'erreur peuvent être obtenus par ERR_get_error(3).

VOIR AUSSI

evp(3), EVP_DigestInit(3), EVP_SignInit(3)

HISTORIQUE

EVP_VerifyInit(), EVP_VerifyUpdate(), et EVP_VerifyFinal() sont apparues pour la première fois dans SSLeay 0.5.1 et sont disponibles depuis OpenBSD 2.4.

EVP_VerifyInit_ex() est apparue pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

BOGUES

Les versions antérieures de cette documentation indiquaient à tort que les appels à EVP_VerifyUpdate() ne pouvaient pas être faits après l'appel à EVP_VerifyFinal().

Étant donné que la clé publique est passée dans l'appel à EVP_SignFinal(3), toute erreur relative à la clé privée (par exemple une combinaison clé/digest inadaptée) ne sera indiquée qu'après que des quantités potentiellement importantes de données aient été transmises via EVP_SignUpdate(3).

Il n'est pas possible de modifier les paramètres de signature à l'aide de ces fonctions.

Les deux bogues précédents sont corrigés dans les fonctions plus récentes de la famille EVP_DigestVerifyInit(3).
