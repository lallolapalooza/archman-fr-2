NOM

libssh2_sign_sk - Créer une signature à partir d'un authentificateur FIDO2.

SYNTAXE

#include <libssh2.h>
int
libssh2_sign_sk(LIBSSH2_SESSION *session,
                unsigned char **sig,
                size_t *sig_len,
                const unsigned char *data,
                size_t data_len,
                void **abstract);
typedef struct _LIBSSH2_PRIVKEY_SK {
    int algorithm;
    uint8_t flags;
    const char *application;
    const unsigned char *key_handle;
    size_t handle_len;
    LIBSSH2_USERAUTH_SK_SIGN_FUNC((*sign_callback));
    void **orig_abstract;
} LIBSSH2_PRIVKEY_SK;

DESCRIPTION

session - Instance de session retournée par libssh2_session_init_ex(3)

sig - Un pointeur vers un tampon dans lequel placer la signature. L'appelant est responsable de libérer la signature avec LIBSSH2_FREE.

sig_len - Un pointeur vers la longueur du paramètre sig.

data - Les données à signer.

data_len - La longueur du paramètre data.

abstract - Un pointeur vers un pointeur vers une LIBSSH2_PRIVKEY_SK. Voir la description ci-dessous.

Crée une signature à partir d'un authentificateur FIDO2, en utilisant les algorithmes d'échange de clés sk-ssh-ed25519@openssh.com ou sk-ecdsa-sha2-nistp256@openssh.com.

Le paramètre abstract est un pointeur vers un pointeur en raison du fonctionnement interne de libssh2. La LIBSSH2_PRIVKEY_SK doit être entièrement remplie, et l'appelant est responsable de toute la gestion de la mémoire de ses champs.

algorithm - L'algorithme de signature à utiliser. Les valeurs possibles sont LIBSSH2_HOSTKEY_TYPE_ED25519 et LIBSSH2_HOSTKEY_TYPE_ECDSA_256.

flags - Un masque de bits spécifiant les options pour l'authentificateur. Lorsque LIBSSH2_SK_PRESENCE_REQUIRED est défini, l'authentificateur nécessite un toucher. Lorsque LIBSSH2_SK_VERIFICATION_REQUIRED est défini, l'authentificateur nécessite un PIN. De nombreux serveurs et authentificateurs ne fonctionnent pas correctement lorsque LIBSSH2_SK_PRESENCE_REQUIRED n'est pas défini.

application - Une chaîne définie par l'utilisateur à utiliser comme nom RP pour l'authentificateur. Généralement "ssh:".

key_handle - Le descripteur de clé à utiliser pour la liste d'autorisation de l'authentificateur.

handle_len - La longueur du paramètre key_handle.

abstract - Données définies par l'utilisateur. Lorsqu'un PIN est requis, utilisez-le pour passer le PIN, ou un pointeur de fonction pour récupérer le PIN.

key_handle Le descripteur de clé décodé du fichier de clé privée.

handle_len La longueur du paramètre key_handle.

sign_callback - Responsable de la communication avec l'authentificateur matériel pour générer une signature. En cas de succès, les informations de signature doivent être placées dans le paramètre `sig_info sig_info et la fonction de rappel doit retourner 0. En cas d'échec, elle doit retourner un nombre négatif. Voir libssh2_userauth_publickey_sk(3)
pour plus d'informations.

orig_abstract - Données définies par l'utilisateur. Lorsqu'un PIN est requis, utilisez-le pour passer le PIN, ou un pointeur de fonction pour récupérer le PIN.

VALEUR DE RETOUR

Retourne 0 en cas de succès ou un nombre négatif en cas d'échec.
