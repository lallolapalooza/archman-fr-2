DESCRIPTION

Un objet IPAddrBlocks représente le contenu d'une extension de délégation d'adresses IP telle que définie dans la RFC 3779, section 2.2.3.1. Il contient des listes de préfixes d'adresses IP et de plages d'adresses IP déléguées de l'émetteur au destinataire du certificat. Il peut être instancié comme expliqué dans la section EXEMPLES et ses éléments internes sont documentés dans IPAddressRange_new(3).

Chaque liste dans un objet IPAddrBlocks bien formé est identifiée de manière unique par un identifiant de famille d'adresses (AFI) et un identifiant facultatif de famille d'adresses ultérieure (SAFI). Les listes peuvent être absentes ou contenir un marqueur « hériter » pour indiquer que les ressources doivent être héritées de la liste correspondante du certificat émetteur.

Conformément à la spécification, un AFI est un entier non signé de 16 bits et un SAFI est un entier non signé de 8 bits. Pour IPv4 et IPv6, il existe les constantes prédéfinies IANA_AFI_IPV4 et IANA_AFI_IPV6, qui devraient être les seules valeurs utilisées pour afi dans cette API. En pratique, safi est toujours NULL. afi est généralement tronqué silencieusement à ses 16 bits les moins significatifs et, si safi n'est pas NULL, seuls les 8 bits les moins significatifs de la valeur pointée sont utilisés.

X509v3_addr_add_inherit() ajoute une liste avec un marqueur « hériter » à addrblocks. Si une liste correspondant à afi et safi existe déjà, aucune action n'est effectuée si elle est marquée « hériter », sinon l'appel échoue.

X509v3_addr_add_prefix() ajoute une représentation interne nouvellement allouée du prefix de longueur prefixlen à la liste correspondant à afi et au safi facultatif dans addrblocks. Si aucune liste de ce type n'existe, elle est créée en premier. Si la liste existe et est marquée « hériter », l'appel échoue. On s'attend à ce que prefix soit un tableau d'octets en ordre d'octet réseau. Il doit pointer vers suffisamment de mémoire pour accueillir prefixlen bits et il est recommandé que tous les bits non couverts par prefixlen soient mis à 0. Il incombe à l'appelant de s'assurer que le prefix n'a pas d'adresse commune avec les préfixes ou plages déjà dans la liste. Si afi est IANA_AFI_IPV4, prefixlen doit être compris entre 0 et 32 (inclus) et si afi est IANA_AFI_IPV6, prefixlen doit être compris entre 0 et 128 (inclus).

X509v3_addr_add_range() est similaire à X509v3_addr_add_prefix() pour l'intervalle fermé d'adresses IP entre min et max en présentation réseau. Si afi est IANA_AFI_IPV4, min et max doivent pointer vers 4 octets de mémoire et si afi est IANA_AFI_IPV6, min et max doivent pointer vers 16 octets de mémoire. Dans le cas où la plage d'adresses IP entre min et max est un préfixe, un préfixe sera ajouté à la place d'une plage. Il incombe à l'appelant de s'assurer que min est inférieur ou égal à max et qu'il ne contient aucune adresse déjà présente dans la liste. Le non-respect de ces conditions entraînera un échec ultérieur de X509v3_addr_canonize().

X509v3_addr_canonize() tente de mettre addrblocks non-NULL sous forme canonique. Un objet IPAddrBlocks est dit sous forme canonique s'il est conforme à l'ordre spécifié dans la RFC 3779 : la section 2.2.3.3 exige que la liste des listes soit triée d'abord par afi croissant, puis par safi croissant, où NULL est le SAFI minimal ; la section 2.2.3.6 exige que chaque liste soit sous forme minimale et triée. L'exigence de minimalité est que tous les préfixes et plages adjacents doivent être fusionnés en une seule plage et que chaque plage doit être exprimée sous forme de préfixe, si possible. En particulier, toute adresse donnée ne peut se trouver que dans une seule entrée de liste. L'ordre est par adresse IP minimale croissante en ordre d'octet réseau.

X509v3_addr_is_canonical() indique si addrblocks est sous forme canonique.

VALEURS DE RETOUR

Toutes ces fonctions retournent 1 en cas de succès et 0 en cas d'échec. Une défaillance d'allocation mémoire est une raison possible pour toutes. Parfois, un code d'erreur peut être obtenu par ERR_get_error(3).

X509v3_addr_add_inherit() échoue si la liste correspondant à afi et au safi facultatif existe déjà et n'est pas marquée « hériter ».

X509v3_addr_add_prefix() et X509v3_addr_add_range() échouent si une liste correspondant à afi et au safi facultatif existe déjà et est marquée « hériter », ou si prefixlen est en dehors de l'intervalle [0,32] pour les adresses IPv4 ou [0,128] pour les adresses IPv6.

X509v3_addr_canonize() échoue si l'une des listes dans addrblocks est malformée, en particulier si elle contient des entrées corrompues, chevauchantes ou dupliquées. La corruption comprend les plages où max est strictement inférieur à min. Les conditions d'erreur sont généralement indiscernables.

X509v3_addr_is_canonical() retourne 1 si addrblocks est sous forme canonique. Une valeur de retour de 0 peut indiquer une forme non canonique ou une liste corrompue.

DESCRIPTION

Ces fonctions gèrent les extensions X.509v3 utilisées pour déléguer des adresses IP et des identifiants de système autonome (AS).

L'extension d'adresse IP (id-pe-ipAddrBlock) est définie dans la RFC 3779 et est utilisée pour spécifier les blocs d'adresses IPv4 et IPv6 qui sont autorisés à être utilisés par le titulaire du certificat. L'extension d'identifiant AS (id-pe-autonomousSysnum) est également définie dans la RFC 3779 et est utilisée pour spécifier les blocs d'identifiants AS qui sont autorisés à être utilisés.

La structure IPAddrBlocks représente un ensemble d'entrées IPAddressFamily, où chaque entrée décrit un ensemble de blocs d'adresses IP pour une famille d'adresses donnée (IPv4 ou IPv6). De même, la structure ASIdentifiers représente un ensemble d'entrées ASNumOrRange.

Les familles d'adresses sont représentées par des constantes définies dans <openssl/x509v3.h>, telles que IANA_AFI_IPV4 et IANA_AFI_IPV6.

Les adresses IP et les identifiants AS sont représentés par des tableaux d'octets. La longueur spécifie le nombre d'octets pertinents.

La canonisation est un processus important qui garantit que les blocs d'adresses ou d'identifiants AS sont représentés dans un format normalisé, ce qui facilite la comparaison et la fusion.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <err.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <openssl/x509v3.h>

static void
hexdump(const unsigned char *buf, size_t len)
{
	size_t i;

	for (i = 1; i <= len; i++)
		printf(" 0x%02x,%s", buf[i - 1], i % 8 ? "" : "\n");
	if (len % 8)
		printf("\n");
}

int
main(void)
{
	IPAddrBlocks *addrblocks;
	X509_EXTENSION *ext;
	unsigned char *der;
	int der_len;
	size_t i;

	const char *prefixes[] = {
		"10.0.32/20", "10.0.64/24", "10.1/16",
		"10.2.48/20", "10.2.64/24", "10.3/16",
	};
#define N_PREFIXES (sizeof(prefixes) / sizeof(prefixes[0]))

	if (pledge("stdio", NULL) == -1)
		err(1, "pledge");

	/*
	 * Quelqu'un a oublié d'implémenter IPAddrBlocks_new(). IPAddrBlocks
	 * est identique à STACK_OF(IPAddressFamily). En tant que tel, il devrait
	 * avoir IPAddressFamily_cmp() comme fonction de comparaison. Il n'est
	 * pas possible d'appeler sk_new(3) car IPAddressFamily_cmp()
	 * ne fait pas partie de l'API publique. La fonction de comparaison correcte
	 * peut être installée comme effet secondaire de X509v3_addr_canonize(3).
	 */
	if ((addrblocks = sk_IPAddressFamily_new_null()) == NULL)
		err(1, "sk_IPAddressFamily_new_null");
	if (!X509v3_addr_canonize(addrblocks))
		errx(1, "X509v3_addr_canonize");

	/* Ajouter les préfixes en tant qu'unicast IPv4. */
	for (i = 0; i < N_PREFIXES; i++) {
		unsigned char addr[16] = {0};
		int len;
		int unicast = 1; /* SAFI pour le routage unicast. */

		len = inet_net_pton(AF_INET, prefixes[i], addr,
		    sizeof(addr));
		if (len == -1)
			errx(1, "inet_net_pton(%s)", prefixes[i]);
		if (!X509v3_addr_add_prefix(addrblocks, IANA_AFI_IPV4,
		    &unicast, addr, len))
			errx(1, "X509v3_addr_add_prefix(%s)", prefixes[i]);
	}
	if (!X509v3_addr_add_inherit(addrblocks, IANA_AFI_IPV6, NULL))
		errx(1, "X509v3_addr_add_inherit");

	/*
	 * Assurez-vous que l'extension est sous forme canonique. Sinon, les deux
	 * préfixes adjacents 10.2.48/20 et 10.2.64/24 ne sont pas fusionnés dans
	 * la plage 10.2.48.0--10.2.64.255. Cela entraîne un encodage DER invalide
	 * de X509V3_EXT_i2d(3) et i2d_X509_EXTENSION(3).
	 */
	if (!X509v3_addr_canonize(addrblocks))
		errx(1, "X509v3_addr_canonize");

	/* Créer l'extension avec l'OID correct ; la marquer comme critique. */
	ext = X509V3_EXT_i2d(NID_sbgp_ipAddrBlock, 1, addrblocks);
	if (ext == NULL)
		errx(1, "X509V3_EXT_i2d");

	der = NULL;
	if ((der_len = i2d_X509_EXTENSION(ext, &der)) <= 0)
		errx(1, "i2d_X509_EXTENSION");

	hexdump(der, der_len);

	/* Une façon d'implémenter IPAddrBlocks_free(). */
	sk_IPAddressFamily_pop_free(addrblocks, IPAddressFamily_free);
	X509_EXTENSION_free(ext);
	free(der);

	return 0;
}

Implémentez les API publiques manquantes d2i_IPAddrBlocks() et i2d_IPAddrBlocks() en utilisant ASN1_item_d2i(3):

IPAddrBlocks *
d2i_IPAddrBlocks(IPAddrBlocks **addrblocks, const unsigned char **in,
    long len)
{
	const X509V3_EXT_METHOD *v3_addr;

	if ((v3_addr = X509V3_EXT_get_nid(NID_sbgp_ipAddrBlock)) == NULL)
		return NULL;
	return (IPAddrBlocks *)ASN1_item_d2i((ASN1_VALUE **)addrblocks,
	    in, len, ASN1_ITEM_ptr(v3_addr->it));
}

int
i2d_IPAddrBlocks(IPAddrBlocks *addrblocks, unsigned char **out)
{
	const X509V3_EXT_METHOD *v3_addr;

	if ((v3_addr = X509V3_EXT_get_nid(NID_sbgp_ipAddrBlock)) == NULL)
		return -1;
	return ASN1_item_i2d((ASN1_VALUE *)addrblocks, out,
	    ASN1_ITEM_ptr(v3_addr->it));
}

L'utilisation de la macro non documentée ASN1_ITEM_ptr() est nécessaire si la compatibilité avec les versions modernes d'autres implémentations est souhaitée.

BOGUES

IPAddrBlocks_new(), IPAddrBlocks_free(), d2i_IPAddrBlocks(), et i2d_IPAddrBlocks() n'existent pas et IPAddrBlocks_it n'est pas public. Les exemples ci-dessus montrent comment implémenter les quatre fonctions manquantes avec l'API publique.

X509v3_addr_add_range() devrait vérifier les bornes de plage inversées et les chevauchements lors de l'insertion et échouer au lieu de créer un addrblocks absurde qui ne peut pas être canonisé par X509v3_addr_canonize().

Si NULL est passé à X509v3_asid_canonize(3), cela réussit. X509v3_addr_is_canonical() considère NULL comme un IPAddrBlocks canonique. En revanche, X509v3_addr_canonize() plante avec un déréférencement de NULL.

Le code ne prend en charge que les AFI IPv4 et IPv6. Ceci n'est pas uniformément appliqué dans les implémentations.

X509v3_addr_add_range() omet de supprimer les bits inutilisés définis à 1 dans le dernier octet de la représentation ASN1_BIT_STRING de max. Cela perturbe certains logiciels.
