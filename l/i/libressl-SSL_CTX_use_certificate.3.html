DESCRIPTION

Ces fonctions chargent les certificats et les clés privées dans l'objet SSL_CTX ou SSL, respectivement.

La classe de fonctions SSL_CTX_*() charge les certificats et les clés dans l'objet SSL_CTX ctx. Les informations sont transmises aux objets SSL ssl créés à partir de ctx avec SSL_new(3) par copie, de sorte que les modifications apportées à ctx ne se propagent pas aux objets SSL déjà existants.

La classe de fonctions SSL_*() charge uniquement les certificats et les clés dans un objet SSL spécifique. Les informations spécifiques sont conservées lorsque SSL_clear(3) est appelé pour cet objet SSL.

SSL_CTX_use_certificate_ASN1() charge le certificat codé ASN1 depuis l'emplacement mémoire d (avec la longueur len) dans ctx ; SSL_use_certificate_ASN1() charge le certificat codé ASN1 dans ssl.

SSL_CTX_use_certificate_file() charge le premier certificat stocké dans file dans ctx. Le format type du certificat doit être spécifié parmi les types connus SSL_FILETYPE_PEM et SSL_FILETYPE_ASN1. SSL_use_certificate_file() charge le certificat depuis file dans ssl. Voir la section NOTES pour savoir pourquoi SSL_CTX_use_certificate_chain_file() devrait être préférée.

Les fonctions SSL_CTX_use_certificate_chain*() chargent une chaîne de certificats dans ctx. Les certificats doivent être au format PEM et doivent être triés en commençant par le certificat de l'émetteur (certificat client ou serveur réel), suivi des certificats CA intermédiaires le cas échéant, et se terminant par la CA de plus haut niveau (racine). À l'exception de SSL_use_certificate_chain_file(), il n'existe pas de fonction correspondante travaillant sur un objet SSL unique.

SSL_CTX_use_PrivateKey() ajoute pkey en tant que clé privée à ctx. SSL_CTX_use_RSAPrivateKey() ajoute la clé privée rsa de type RSA à ctx. SSL_use_PrivateKey() ajoute pkey en tant que clé privée à ssl ; SSL_use_RSAPrivateKey() ajoute rsa en tant que clé privée de type RSA à ssl. Si un certificat a déjà été défini et que la clé privée n'appartient pas au certificat, une erreur est retournée. Pour changer une paire clé privée/certificat, le nouveau certificat doit être défini avec SSL_use_certificate() ou SSL_CTX_use_certificate() avant de définir la clé privée avec SSL_CTX_use_PrivateKey() ou SSL_use_PrivateKey().

SSL_CTX_use_PrivateKey_ASN1() ajoute la clé privée de type pk stockée à l'emplacement mémoire d (longueur len) à ctx. SSL_CTX_use_RSAPrivateKey_ASN1() ajoute la clé privée de type RSA stockée à l'emplacement mémoire d (longueur len) à ctx. SSL_use_PrivateKey_ASN1() et SSL_use_RSAPrivateKey_ASN1() ajoutent la clé privée à ssl.

SSL_CTX_use_PrivateKey_file() ajoute la première clé privée trouvée dans file à ctx. Le format type de la clé privée doit être spécifié parmi les types connus SSL_FILETYPE_PEM et SSL_FILETYPE_ASN1. SSL_CTX_use_RSAPrivateKey_file() ajoute la première clé privée RSA trouvée dans file à ctx. SSL_use_PrivateKey_file() ajoute la première clé privée trouvée dans file à ssl ; SSL_use_RSAPrivateKey_file() ajoute la première clé privée RSA trouvée à ssl.

La fonction SSL_CTX_check_private_key() est sérieusement mal nommée. Elle compare les composants de clé publique et les paramètres d'une clé privée OpenSSL avec le certificat correspondant chargé dans ctx. Si plus d'une paire clé/certificat (RSA/ECDSA) est installée, le dernier élément installé sera comparé. Si, par exemple, le dernier élément était un certificat ou une clé RSA, la paire clé/certificat RSA sera vérifiée. SSL_check_private_key() effectue la même comparaison de clé publique pour ssl. Si aucune clé/certificat n'a été explicitement ajouté pour ce ssl, le dernier élément ajouté à ctx sera vérifié.

Malgré son nom, ni SSL_CTX_check_private_key() ni SSL_check_private_key() ne vérifient si le composant de clé privée est bien une clé privée, ni s'il correspond au composant de clé publique. Ils comparent simplement les éléments publics (par exemple, l'exposant et le module d'une clé RSA) et/ou les paramètres de clé (par exemple, les paramètres EC d'une clé EC) d'une paire de clés.

NOTES

Le magasin de certificats interne d'OpenSSL peut contenir plusieurs paires clé privée/certificat à la fois. Le certificat utilisé dépend du chiffre sélectionné. Voir aussi SSL_CTX_set_cipher_list(3).

Lors de la lecture de certificats et de clés privées à partir d'un fichier, les fichiers de type SSL_FILETYPE_ASN1 (également connu sous le nom de DER, codage binaire) ne peuvent contenir qu'un seul certificat ou une seule clé privée ; par conséquent, SSL_CTX_use_certificate_chain_file() n'est applicable qu'au format PEM. Les fichiers de type SSL_FILETYPE_PEM peuvent contenir plusieurs éléments.

SSL_CTX_use_certificate_chain_file() ajoute le premier certificat trouvé dans le fichier au magasin de certificats. Les autres certificats sont ajoutés au magasin de certificats de la chaîne en utilisant SSL_CTX_add1_chain_cert(3). Il est recommandé d'utiliser la fonction SSL_CTX_use_certificate_chain_file() plutôt que la fonction SSL_CTX_use_certificate_file() afin de permettre l'utilisation de chaînes de certificats complètes, même lorsqu'aucun stockage CA de confiance n'est utilisé ou lorsque la CA émettrice du certificat ne doit pas être ajoutée au stockage CA de confiance.

Si des certificats supplémentaires sont nécessaires pour compléter la chaîne lors de la négociation TLS, les certificats CA sont recherchés en plus aux emplacements des certificats CA de confiance (voir SSL_CTX_load_verify_locations(3)).

Les clés privées chargées à partir d'un fichier peuvent être chiffrées. Afin de charger avec succès des clés chiffrées, une fonction retournant la phrase secrète doit avoir été fournie (voir SSL_CTX_set_default_passwd_cb(3)). (Les fichiers de certificats peuvent être chiffrés du point de vue technique, mais cela n'a pas de sens car les données dans le certificat sont considérées comme publiques de toute façon.)

VALEURS DE RETOUR

En cas de succès, les fonctions retournent 1. Sinon, consultez la pile d'erreurs pour connaître la raison.

DESCRIPTION

These functions are used to configure the certificate and private key that will be presented by the server or client during the SSL/TLS handshake.

SSL_CTX_use_certificate() and SSL_CTX_use_PrivateKey() set the certificate and private key of the ctx context respectively. The certificate and key are represented by X509 and EVP_PKEY objects. Note that SSL_CTX_use_PrivateKey() accepts any type of private key, including DSA, ECDSA, and RSA. SSL_CTX_use_RSAPrivateKey() and SSL_CTX_use_RSAPrivateKey() are deprecated and should not be used.

SSL_CTX_use_certificate_ASN1(), SSL_CTX_use_PrivateKey_ASN1(), and SSL_CTX_use_RSAPrivateKey_ASN1() load the certificate and private key from DER-encoded memory buffers d of length len.

SSL_CTX_use_certificate_file(), SSL_CTX_use_PrivateKey_file(), and SSL_CTX_use_RSAPrivateKey_file() load the certificate and private key from the file specified by file. The type parameter specifies the file format. It can be SSL_FILETYPE_PEM or SSL_FILETYPE_ASN1 (DER).

SSL_CTX_check_private_key() and SSL_check_private_key() check whether the private key in the ctx context or ssl object corresponds to the certificate.

SSL_CTX_use_certificate_chain_file() sets the chain of certificates to be sent to the peer. This is typically used in server configurations to provide the intermediate certificates needed to complete the chain of trust.

SSL_use_certificate_chain_file() is the per-connection equivalent of SSL_CTX_use_certificate_chain_file().

SSL_CTX_use_certificate_chain_mem() and SSL_use_certificate_chain_mem() are the memory buffer equivalents of the corresponding file-based functions.

NOTES
