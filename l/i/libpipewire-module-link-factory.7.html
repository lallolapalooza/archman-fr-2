NOM

libpipewire-module-link-factory - Fabrique de liens

DESCRIPTION

Permet aux clients de créer des liens entre des ports.

Ce module crée une nouvelle fabrique. Les clients qui peuvent voir la fabrique peuvent utiliser le nom de la fabrique (link-factory) pour créer de nouveaux objets de lien avec pw_core_create_object(). Il est également possible de créer des objets dans le fichier de configuration.

Un objet de type PW_TYPE_INTERFACE_Link sera créé et un proxy vers celui-ci sera retourné.

En tant qu'argument de l'appel create_object, un ensemble de propriétés contrôlera quels ports seront liés.

NOM DU MODULE

libpipewire-module-link-factory

OPTIONS DU MODULE

•
allow.link.passive: si la propriété link.passive est autorisée. Par défaut, faux. Par défaut, le cœur décidera si un lien est passif en fonction des propriétés du nœud et des ports.

PROPRIÉTÉS POUR L'APPEL CREATE_OBJECT

  • link.output.node: Le nœud de sortie à utiliser. Il peut s'agir de l'id de l'objet node, node.name, node.nick, node.description ou object.path d'un nœud. Lorsque la propriété n'est pas donnée ou est NULL, le port de sortie doit être spécifié.
  • link.output.port: Le port de sortie à lier. Il peut s'agir de l'id de l'objet port, port.name, port.alias ou object.path. Si un nœud de sortie est spécifié, le port doit appartenir au nœud. Trouver un port dans un nœud en utilisant port.id est déprécié et peut entraîner des résultats inattendus lorsque port.id correspond également à un object.id. Si aucun port de sortie n'est donné, un nœud de sortie doit être spécifié et un port aléatoire (non lié) sera utilisé à partir du nœud.
  • link.input.node: Le nœud d'entrée à utiliser. Il peut s'agir de l'id de l'objet node, node.name, node.nick, node.description ou object.path d'un nœud. Lorsque la propriété n'est pas donnée ou est NULL, le port d'entrée doit être spécifié.
  • link.input.port: Le port d'entrée à lier. Il peut s'agir de l'id de l'objet port, port.name, port.alias ou object.path. Si un nœud d'entrée est spécifié, le port doit appartenir au nœud. Trouver un port dans un nœud en utilisant port.id est déprécié et peut entraîner des résultats inattendus lorsque port.id correspond également à un object.id. Si aucun port d'entrée n'est donné, un nœud d'entrée doit être spécifié et un port aléatoire (non lié) sera utilisé à partir du nœud.
  • object.linger: Conserver le lien même lorsque le client qui l'a créé a disparu.
  • link.passive: Le lien est passif, ce qui signifie qu'il ne maintiendra pas les nœuds occupés. Par défaut, cette propriété est ignorée et les propriétés du nœud et des ports sont utilisées pour déterminer l'état passif du lien.

EXEMPLE DE CONFIGURATION

Le module est généralement ajouté au fichier de configuration du démon pipewire principal.

context.modules = [
{ name = libpipewire-link-factory
  args = {
      #allow.link.passive = false
  }
}
]

SOUSCRIPTION DE CONFIGURATION

Une section de configuration module.link-factory.args peut être ajoutée pour remplacer les arguments du module.

# ~/.config/pipewire/pipewire.conf.d/my-link-factory-args.conf
module.link-factory.args = {
    #allow.link.passive = false
}

OBJETS DE CONFIGURATION

Pour créer un objet à partir de la fabrique, on peut utiliser la méthode pw_core_create_object() ou créer un objet dans la section context.objects comme suit :

context.objects = [
{ factory = link-factory
    args = {
        link.output.node = system
        link.output.port = capture_2
        link.input.node  = my-mic
        link.input.port  = input_FR
    }
}

Notez que cela ne fonctionne que lorsque les ports qui doivent être liés sont disponibles au moment où le fichier de configuration est analysé.
