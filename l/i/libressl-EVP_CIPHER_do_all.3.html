EVP_CIPHER_DO_ALL(3) Manuel des fonctions de bibliothèque EVP_CIPHER_DO_ALL(3)

NOM

EVP_CIPHER_do_all, EVP_CIPHER_do_all_sorted, EVP_MD_do_all, EVP_MD_do_all_sorted, OBJ_NAME_do_all, OBJ_NAME_do_all_sorted — parcourir les tables de recherche des chiffrements et des résumés

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

void
EVP_CIPHER_do_all(void (*fn)(const EVP_CIPHER *cipher, const char *from, const char *to, void *arg), void *arg);

void
EVP_CIPHER_do_all_sorted(void (*fn)(const EVP_CIPHER *cipher, const char *from, const char *to, void *arg), void *arg);

void
EVP_MD_do_all(void (*fn)(const EVP_MD *md, const char *from, const char *to, void *arg), void *arg);

void
EVP_MD_do_all_sorted(void (*fn)(const EVP_MD *md, const char *from, const char *to, void *arg), void *arg);

typedef struct {
        int	    type;
        int	    alias;
        const char *name;
        const char *data;
} OBJ_NAME;


void
OBJ_NAME_do_all(int type, void (*fn)(const OBJ_NAME *obj_name, void *arg), void *arg);

void
OBJ_NAME_do_all_sorted(int type, void (*fn)(const OBJ_NAME *obj_name, void *arg), void *arg);

DESCRIPTION

EVP_CIPHER_do_all() appelle fn sur chaque entrée de la table globale des noms de chiffrements et de leurs alias. Pour une entrée de nom de chiffrement, fn est appelée avec un cipher non nul, son nom de chiffrement non nul from, un to nul, et le pointeur arg. Pour une entrée d'alias, fn est appelée avec un cipher nul, son alias from, le nom du chiffrement auquel cet alias pointe to, et le pointeur arg.

EVP_CIPHER_do_all_sorted() est similaire, sauf qu'elle traite les noms de chiffrements et les alias dans l'ordre lexicographique de leurs noms from tel que déterminé par strcmp(3).

EVP_MD_do_all() appelle fn sur chaque entrée de la table globale des noms de résumés et de leurs alias. Pour une entrée de nom de résumé, fn est appelée avec un md non nul, son nom de résumé non nul from, un to nul, et le pointeur arg. Pour une entrée d'alias, fn est appelée avec un md nul, son alias from, le nom du résumé auquel cet alias pointe to, et le pointeur arg.

EVP_MD_do_all_sorted() est similaire, sauf qu'elle traite les noms de résumés et les alias dans l'ordre lexicographique de leurs noms from tel que déterminé par strcmp(3).

OBJ_NAME est une abstraction des types sous-jacents des tables de recherche pour les chiffrements et leurs alias, et les résumés et leurs alias, respectivement. Pour un chiffrement, type est OBJ_NAME_TYPE_CIPHER_METH, alias est 0, name est son nom de recherche et data est l'objet EVP_CIPHER qu'il représente, casté en const char *. Pour un alias de chiffrement, type est OBJ_NAME_TYPE_CIPHER_METH, alias est OBJ_NAME_ALIAS, name est son nom de recherche et data est le nom auquel il fait référence. Les résumés représentant un objet EVP_MD et leurs alias sont représentés de manière similaire, sauf que leur type est OBJ_NAME_TYPE_MD_METH.

OBJ_NAME_do_all() appelle fn sur chaque obj_name dans la table qui a le type donné (soit OBJ_NAME_TYPE_CIPHER_METH soit OBJ_NAME_TYPE_MD_METH), passant également le pointeur arg. OBJ_NAME_do_all_sorted() est similaire sauf qu'elle traite les obj_name dans l'ordre lexicographique de leurs noms tel que déterminé par strcmp(3).

VOIR AUSSI

evp(3), EVP_get_cipherbyname(3), EVP_get_digestbyname(3)

HISTORIQUE

Ces fonctions sont apparues pour la première fois dans OpenSSL 1.0.0 et sont disponibles depuis OpenBSD 4.9.

ATTENTION

EVP_CIPHER_do_all_sorted(), EVP_MD_do_all_sorted(), et OBJ_NAME_do_all_sorted() ne peuvent pas signaler d'erreurs. Dans certaines implémentations, elles doivent allouer de la mémoire en interne et si l'allocation mémoire échoue, elles ne font rien du tout, sans en informer l'appelant.
