SMIME_WRITE_CMS(3) Manuel des fonctions de bibliothèque SMIME_WRITE_CMS(3)

NOM

SMIME_write_CMS — convertit une structure CMS au format S/MIME

SYNTAXE

bibliothèque «libcrypto»
#include <openssl/cms.h>

int
SMIME_write_CMS(BIO *out, CMS_ContentInfo *cms, BIO *data, int flags);

DESCRIPTION

SMIME_write_CMS() génère un message S/MIME sur out en écrivant des en-têtes MIME 1.0 suivis d'une sérialisation de cms encodée en BER et en base64. L'encodage BER utilise le format DER, sauf comme décrit pour CMS_STREAM ci-dessous. Si le streaming est activé, le contenu doit être fourni dans l'argument data.

Les flags peuvent être le OU logique de zéro ou plusieurs des bits suivants :

CMS_DETACHED
Utilise la signature en texte clair et génère un message S/MIME «multipart/signed». Le contenu est lu à partir de data. Si data est un pointeur NULL, ce drapeau est ignoré.

Ce drapeau n'est pris en charge que si cms est du type SignedData et CMS_DETACHED a également été défini lors de sa création avec CMS_sign(3).

Si CMS_STREAM n'est pas défini, les données doivent être lues deux fois : une fois pour calculer la signature dans CMS_sign(3) et une fois pour afficher le message S/MIME.

Si CMS_DETACHED est ignoré ou non spécifié, le type smime est choisi conformément à CMS_get0_type(3):

NID_pkcs7_enveloped
"enveloped-data"
NID_pkcs7_signed
"signed-receipt"
si CMS_get0_eContentType(3) est NID_id_smime_ct_receipt
"signed-data"
si cms spécifie un algorithme de hachage
"certs-only"
sinon
NID_id_smime_ct_compressedData
"compressed-data"
CMS_REUSE_DIGEST
Ignore les appels à CMS_dataInit(3) et CMS_dataFinal(3). Ce drapeau n'a aucun effet à moins que CMS_DETACHED ne soit également défini.
CMS_STREAM
Effectue le streaming en lisant le contenu depuis data. Cela ne fonctionne que si CMS_DETACHED n'est pas spécifié.

Ce drapeau ne doit être défini que si CMS_STREAM a également été passé à la fonction qui a créé cms.

Le contenu est affiché au format BER en utilisant un codage construit de longueur indéfinie, sauf dans le cas de SignedData avec contenu détaché, où le contenu est absent et le format DER est utilisé.

CMS_TEXT
Prépare la ligne «Content-Type: text/plain» au contenu. Ceci n'a de sens que si CMS_DETACHED est également défini. Elle est ignorée si le drapeau SMIME_BINARY est également défini.
SMIME_BINARY
Si spécifié, ce drapeau est transmis à SMIME_crlf_copy(3).
SMIME_CRLFEOL
Termine les lignes d'en-tête MIME par des paires de retour chariot et de caractères de nouvelle ligne. Par défaut, aucun caractère de retour chariot n'est écrit et les lignes d'en-tête sont terminées uniquement par des caractères de nouvelle ligne.

VALEURS DE RETOUR

SMIME_write_CMS() est censé retourner 1 en cas de succès ou 0 en cas d'échec.

VOIR AUSSI

BIO_f_base64(3), BIO_new(3), CMS_ContentInfo_new(3), CMS_encrypt(3), CMS_sign(3), d2i_CMS_ContentInfo(3), ERR_get_error(3), SMIME_crlf_copy(3), SMIME_read_CMS(3), SMIME_write_PKCS7(3)

HISTORIQUE

SMIME_write_CMS() est apparu pour la première fois dans OpenSSL 0.9.8h et est disponible depuis OpenBSD 6.7.

BOGUES

SMIME_write_CMS() ignore la plupart des erreurs et est susceptible de retourner 1 même après avoir produit une sortie corrompue ou incomplète.

SMIME_write_CMS() encode toujours les structures CMS en base64. Il devrait y avoir une option pour désactiver cela.
