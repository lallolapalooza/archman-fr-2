CRYPTO_LOCK(3) Manuel des fonctions de bibliothèque CRYPTO_LOCK(3)

NOM

CRYPTO_lock, CRYPTO_w_lock, CRYPTO_w_unlock, CRYPTO_r_lock, CRYPTO_r_unlock, CRYPTO_add — prise en charge des threads

SYNTAXE

bibliothèque «libcrypto»
#include <openssl/crypto.h>

void
CRYPTO_lock(int mode, int type, const char *file, int line);

int
CRYPTO_add(int *p, int amount, int type);

#define	CRYPTO_w_lock(type) \
	CRYPTO_lock(CRYPTO_LOCK|CRYPTO_WRITE, type, __FILE__, __LINE__)
#define	CRYPTO_w_unlock(type) \
	CRYPTO_lock(CRYPTO_UNLOCK|CRYPTO_WRITE, type, __FILE__, __LINE__)
#define	CRYPTO_r_lock(type) \
	CRYPTO_lock(CRYPTO_LOCK|CRYPTO_READ, type, __FILE__, __LINE__)
#define	CRYPTO_r_unlock(type) \
	CRYPTO_lock(CRYPTO_UNLOCK|CRYPTO_READ, type, __FILE__, __LINE__)

DESCRIPTION

Ces fonctions sont obsolètes.

CRYPTO_lock() verrouille ou déverrouille un mutex.

mode est un champ de bits décrivant ce qui doit être fait avec le verrou. Pour chaque appel, soit CRYPTO_LOCK soit CRYPTO_UNLOCK doit être inclus. Dans l'implémentation LibreSSL, CRYPTO_READ et CRYPTO_WRITE sont ignorés.

type est un nombre dans la plage 0 <= type < CRYPTO_NUM_LOCKS identifiant un verrou particulier. Actuellement, la valeur de CRYPTO_NUM_LOCKS est 41.

Les arguments file et line sont ignorés.

Dans l'implémentation LibreSSL, CRYPTO_lock() est un wrapper autour de pthread_mutex_lock(3) et pthread_mutex_unlock(3).

CRYPTO_add() verrouille le verrou numéro type, ajoute amount à *p, et déverrouille le verrou numéro type à nouveau.

VALEUR DE RETOUR

CRYPTO_add() retourne la nouvelle valeur de *p.

VOIR AUSSI

crypto(3)

HISTORIQUE

CRYPTO_lock(), CRYPTO_w_lock(), CRYPTO_w_unlock(), CRYPTO_r_lock(), et CRYPTO_r_unlock() sont apparus pour la première fois dans SSLeay 0.6.0. CRYPTO_add() est apparu pour la première fois dans SSLeay 0.6.2. Ces fonctions sont disponibles depuis OpenBSD 2.4.
