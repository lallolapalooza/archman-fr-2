EVP_DIGESTSIGNINIT(3) Manuel des fonctions de bibliothèque EVP_DIGESTSIGNINIT(3)

NOM

EVP_DigestSignInit, EVP_DigestSignUpdate, EVP_DigestSignFinal, EVP_DigestSign — fonctions de signature EVP

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_DigestSignInit(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx, const EVP_MD *type, ENGINE *engine, EVP_PKEY *pkey);

int
EVP_DigestSignUpdate(EVP_MD_CTX *ctx, const void *d, size_t cnt);

int
EVP_DigestSignFinal(EVP_MD_CTX *ctx, unsigned char *sig, size_t *siglen);

int
EVP_DigestSign(EVP_MD_CTX *ctx, unsigned char *sigret, size_t *siglen, const unsigned char *tbs, size_t tbslen);

DESCRIPTION

Les routines de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_DigestSignInit() configure le contexte de signature ctx pour utiliser le digest type et la clé privée pkey. Avant d'appeler cette fonction, obtenez ctx à partir de EVP_MD_CTX_new(3) ou appelez EVP_MD_CTX_reset(3) sur celui-ci. L'argument engine est toujours ignoré et il est recommandé de passer NULL.

Si pctx n'est pas NULL, tout pointeur passé en tant que *pctx est ignoré et remplacé par un pointeur interne vers le EVP_PKEY_CTX utilisé par l'opération de signature : ceci peut être utilisé pour définir des options de signature alternatives. Le EVP_PKEY_CTX renvoyé ne doit pas être libéré par l'application. Il est libéré automatiquement lorsque le EVP_MD_CTX est libéré.

EVP_DigestSignUpdate() hache cnt octets de données à d dans le contexte de signature ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires. Cette fonction est actuellement implémentée à l'aide d'une macro.

EVP_DigestSignFinal() signe les données dans ctx et place la signature dans sig. Si sig est NULL, alors la taille maximale du tampon de sortie est écrite dans *siglen. Si sig n'est pas NULL, alors avant l'appel, siglen doit contenir la longueur du tampon sig. Si l'appel réussit, la signature est écrite dans sig et la quantité de données écrite dans siglen.

EVP_DigestSign() signe tbslen octets de données à tbs et place la signature dans sigret et sa longueur dans siglen d'une manière similaire à EVP_DigestSignFinal(). EVP_DigestSign() est une opération unique qui signe un seul bloc de données en un seul appel de fonction. Pour les algorithmes qui prennent en charge le streaming, cela équivaut à appeler EVP_DigestSignUpdate() et EVP_DigestSignFinal().

L'interface EVP pour les signatures numériques doit presque toujours être préférée aux interfaces de bas niveau. En effet, le code devient alors transparent à l'algorithme utilisé et beaucoup plus flexible.

L'appel à EVP_DigestSignFinal() finalise en interne une copie du contexte de digest. Cela signifie que EVP_DigestSignUpdate() et EVP_DigestSignFinal() peuvent être appelés ultérieurement pour digérer et signer des données supplémentaires.

Puisque seule une copie du contexte de digest est jamais finalisée, le contexte doit être nettoyé après utilisation en appelant EVP_MD_CTX_free(3), sinon une fuite de mémoire se produira.

L'utilisation de EVP_PKEY_size(3) avec ces fonctions est déconseillée car certaines opérations de signature peuvent avoir une longueur de signature qui dépend des paramètres définis. Par conséquent, EVP_PKEY_size(3) devrait renvoyer une valeur indiquant la signature maximale possible pour n'importe quel ensemble de paramètres.

VALEURS DE RETOUR

EVP_DigestSignInit(), EVP_DigestSignUpdate(), EVP_DigestSignFinal(), et EVP_DigestSign() renvoient 1 en cas de succès et 0 en cas d'échec.

Les codes d'erreur peuvent être obtenus à partir de ERR_get_error(3).

VOIR AUSSI

evp(3), EVP_DigestInit(3), EVP_DigestVerifyInit(3)

HISTORIQUE

EVP_DigestSignInit(), EVP_DigestSignUpdate(), et EVP_DigestSignFinal() sont apparues pour la première fois dans OpenSSL 1.0.0 et sont disponibles depuis OpenBSD 4.9.

EVP_DigestSign() est apparue pour la première fois dans OpenSSL 1.1.1 et est disponible depuis OpenBSD 7.0.
