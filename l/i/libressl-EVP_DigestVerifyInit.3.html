EVP_DIGESTVERIFYINIT(3) Manuel de fonctions de bibliothèque EVP_DIGESTVERIFYINIT(3)

NOM

EVP_DigestVerifyInit, EVP_DigestVerifyUpdate, EVP_DigestVerifyFinal, EVP_DigestVerify — Fonctions de vérification de signature EVP

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_DigestVerifyInit(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx, const EVP_MD *type, ENGINE *engine, EVP_PKEY *pkey);

int
EVP_DigestVerifyUpdate(EVP_MD_CTX *ctx, const void *d, size_t cnt);

int
EVP_DigestVerifyFinal(EVP_MD_CTX *ctx, const unsigned char *sig, size_t siglen);

int
EVP_DigestVerify(EVP_MD_CTX *ctx, const unsigned char *sig, size_t siglen, const unsigned char *tbs, size_t *tbslen);

DESCRIPTION

Les routines de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_DigestVerifyInit() configure le contexte de vérification ctx pour utiliser le digest type et la clé publique pkey. Avant d'appeler cette fonction, obtenez ctx à partir de EVP_MD_CTX_new(3) ou appelez EVP_MD_CTX_reset(3) sur celui-ci. L'argument engine est toujours ignoré et il est recommandé de passer NULL.

Si pctx n'est pas NULL, tout pointeur passé comme *pctx est ignoré et écrasé par un pointeur interne vers la EVP_PKEY_CTX utilisée par l'opération de vérification : ceci peut être utilisé pour définir des options de signature alternatives. La EVP_PKEY_CTX renvoyée ne doit pas être libérée par l'application. Elle est automatiquement libérée lorsque la EVP_MD_CTX est libérée.

EVP_DigestVerifyUpdate() hache cnt octets de données à l'adresse d dans le contexte de vérification ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires. Cette fonction est actuellement implémentée à l'aide d'une macro.

EVP_DigestVerifyFinal() vérifie les données dans ctx par rapport à la signature dans sig de longueur siglen.

EVP_DigestVerify() vérifie tbslen octets à l'adresse tbs par rapport à la signature dans sig de longueur siglen. EVP_DigestVerify() est une opération unique qui vérifie un seul bloc de données en un seul appel de fonction. Pour les algorithmes qui prennent en charge le streaming, elle est équivalente à l'appel de EVP_DigestVerifyUpdate() et EVP_DigestVerifyFinal().

L'interface EVP pour les signatures numériques devrait presque toujours être préférée aux interfaces de bas niveau. En effet, le code devient alors transparent à l'algorithme utilisé et beaucoup plus flexible.

L'appel à EVP_DigestVerifyFinal() finalise en interne une copie du contexte de digest. Cela signifie que EVP_VerifyUpdate(3) et EVP_VerifyFinal(3) peuvent être appelés ultérieurement pour digérer et vérifier des données supplémentaires.

Étant donné que seule une copie du contexte de digest est jamais finalisée, le contexte doit être nettoyé après utilisation en appelant EVP_MD_CTX_free(3), sinon une fuite de mémoire se produira.

VALEURS DE RETOUR

EVP_DigestVerifyInit() et EVP_DigestVerifyUpdate() renvoient 1 en cas de succès et 0 en cas d'échec.

EVP_DigestVerifyFinal() et EVP_DigestVerify() renvoient 1 en cas de succès ; toute autre valeur indique un échec. Une valeur de retour de 0 indique que la signature n'a pas été vérifiée avec succès (c'est-à-dire que la signature ne correspondait pas aux données originales ou que la signature avait un format invalide), tandis que d'autres valeurs indiquent une erreur plus grave (et indiquent parfois également un format de signature invalide).

Les codes d'erreur peuvent être obtenus à partir de ERR_get_error(3).

VOIR AUSSI

evp(3), EVP_DigestInit(3), EVP_DigestSignInit(3)

HISTORIQUE

EVP_DigestVerifyInit(), EVP_DigestVerifyUpdate(), et EVP_DigestVerifyFinal() sont apparues pour la première fois dans OpenSSL 1.0.0 et sont disponibles depuis OpenBSD 4.9.

EVP_DigestVerify() est apparue pour la première fois dans OpenSSL 1.1.1 et est disponible depuis OpenBSD 7.0.
