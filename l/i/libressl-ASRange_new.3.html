DESCRIPTION

ASRange, ASIdOrRange, et ASIdentifierChoice sont des blocs de construction du type ASIdentifiers représentant l'extension de délégation d'identificateur de système autonome RFC 3779.

Tous les ASN1_INTEGER dans ce manuel doivent être représentables en tant qu'entiers non signés de 32 bits. L'API n'effectue aucun contrôle correspondant. Un ASN1_INTEGER peut être défini en utilisant ASN1_INTEGER_set_uint64(3).

Le type ASRange défini dans la section 3.2.3.8 de la RFC 3779 est implémenté comme suit :

typedef struct ASRange_st {
	ASN1_INTEGER *min;
	ASN1_INTEGER *max;
} ASRange;

Il représente l'intervalle fermé [min,max] des identificateurs AS entre min et max, où min doit être strictement inférieur à max.

ASRange_new() alloue un nouvel objet ASRange avec min et max alloués et vides, représentant ainsi l'intervalle invalide [0,0].

ASRange_free() libère asrange y compris toute donnée qu'il contient. Si asrange est NULL, aucune action n'est effectuée.

Le type ASIdOrRange défini dans la section 3.2.3.5 de la RFC 3779 est implémenté comme suit :

typedef struct ASIdOrRange_st {
	int type;
	union {
		ASN1_INTEGER *id;
		ASRange *range;
	} u;
} ASIdOrRange;

représentant un identificateur AS individuel ou une plage. Lors du remplissage manuel d'un objet ASIdOrRange, son type doit être défini sur ASIdOrRange_id ou ASIdOrRange_range pour indiquer quel membre de l'union u est valide.

ASIdOrRange_new() renvoie un nouvel objet ASIdOrRange avec un type invalide et des membres de l'union u à NULL.

ASIdOrRange_free() libère aor y compris toute donnée qu'il contient, à condition que type soit correctement défini. Si asrange est NULL, aucune action n'est effectuée.

Afin d'exprimer une liste d'identificateurs et de plages AS, la section 3.2.3.4 de la RFC 3779 utilise une SEQUENCE ASN.1, qui est implémentée via une construction STACK_OF(3) sur ASIdOrRange :

typedef STACK_OF(ASIdOrRange) ASIdOrRanges;

Puisqu'un objet ASIdOrRanges doit être trié d'une manière spécifique (voir X509v3_asid_canonize(3)), une fonction de comparaison est nécessaire pour une instanciation correcte avec sk_new(3). La fonction ASIdOrRange_cmp() n'est pas directement exposée et n'est pas facilement accessible depuis l'extérieur de la bibliothèque, et il est non trivial de l'implémenter. Il est donc déconseillé d'utiliser des objets ASIdOrRanges qui ne font pas partie d'un objet ASIdentifiers.

Le marqueur « inherit » de la section 3.2.3.3 de la RFC 3779 est implémenté comme ASN1_NULL. Il n'a pas de type ou d'API dédié et peut être instancié avec ASN1_NULL_new(3).

Le type ASIdentifierChoice défini dans la section 3.2.3.2 de la RFC 3779 est implémenté comme suit :

typedef struct ASIdentifierChoice_st {
	int type;
	union {
		ASN1_NULL *inherit;
		ASIdOrRanges *asIdsOrRanges;
	} u;
} ASIdentifierChoice;

où le membre type doit être défini sur ASIdentifierChoice_inherit ou ASIdentifierChoice_asIdsOrRanges pour indiquer si un objet ASIdentifierChoice donné représente une liste héritée ou une liste explicite.

ASIdentifierChoice_new() renvoie un nouvel objet ASIdentifierChoice avec un type invalide et des membres de l'union u à NULL.

ASIdentifierChoice_free() libère aic y compris toute donnée qu'il contient, à condition que type soit correctement défini.

Le type ASIdentifiers défini dans la section 3.2.3.1 de la RFC 3779 est implémenté comme suit :

typedef struct ASIdentifiers_st {
	ASIdentifierChoice *asnum;
	ASIdentifierChoice *rdi;
} ASIdentifiers;

Il doit être instancié avec ASIdentifiers_new(3) et peuplé avec X509v3_asid_add_id_or_range(3).

d2i_ASRange(), i2d_ASRange(), d2i_ASIdOrRange(), i2d_ASIdOrRange(), d2i_ASIdentifierChoice(), et i2d_ASIdentifierChoice() sont les fonctions de conversion ASN.1 DER de ces types. Elles renvoient NULL ou 0 en cas d'échec, respectivement. Le pointeur de sortie der_out est automatiquement alloué si non NULL.

Voir aussi X509V3_EXT_add_entry(3), X509_EXTENSION_set_object(3).

DESCRIPTION

Ces fonctions sont utilisées pour créer, détruire, encoder et décoder les types de données ASN.1 ASRange, ASIdOrRange et ASIdentifierChoice tels que spécifiés dans RFC 3779. Ces types de données sont utilisés dans les extensions X.509 pour représenter des identifiants de systèmes autonomes (AS).

ASRange_new(), ASIdOrRange_new(), et ASIdentifierChoice_new() allouent et retournent de nouveaux objets de leurs types respectifs. Les membres sont initialisés à des valeurs vides ou NULL.

ASRange_free(), ASIdOrRange_free(), et ASIdentifierChoice_free() libèrent la mémoire occupée par les objets fournis.

Les fonctions de décodage d2i_ASRange(), d2i_ASIdOrRange(), et d2i_ASIdentifierChoice() décodent une représentation ASN.1 de leurs types respectifs à partir des données fournies par in et len. Si l'argument x est NULL, un nouvel objet est alloué. Sinon, l'objet existant pointé par x est utilisé. Les pointeurs in et len sont mis à jour pour pointer après les données décodées.

Les fonctions d'encodage i2d_ASRange(), i2d_ASIdOrRange(), et i2d_ASIdentifierChoice() encodent la représentation ASN.1 de leurs types respectifs dans le buffer fourni par out. Si out est NULL, la mémoire nécessaire est allouée et retournée. Sinon, les données sont écrites dans le buffer fourni.

Pour plus de détails sur la sémantique, les exemples, les avertissements et les bugs, voir ASN1_item_d2i(3). Pour que l'encodage produit par i2d_ASRange() soit correct, min doit être strictement inférieur à max. Il en va de même pour i2d_ASIdOrRange() et un objet ASIdOrRange de type ASIdOrRange_range.

VALEURS DE RETOUR

ASRange_new() retourne un nouvel objet ASRange avec des membres alloués et vides, ou NULL si une erreur se produit.

ASIdOrRange_new() retourne un nouvel objet ASIdOrRange vide, ou NULL si une erreur se produit.

ASIdentifierChoice_new() retourne un nouvel objet ASIdentifierChoice vide, ou NULL si une erreur se produit.

Les fonctions de décodage d2i_ASRange(), d2i_ASIdOrRange(), et d2i_ASIdentifierChoice() retournent respectivement un objet ASRange, ASIdOrRange, ou ASIdentifierChoice, ou NULL si une erreur se produit.

Les fonctions d'encodage i2d_ASRange(), i2d_ASIdOrRange(), et i2d_ASIdentifierChoice() retournent le nombre d'octets encodés avec succès, ou une valeur <= 0 si une erreur se produit.

HISTORIQUE

Ces fonctions sont apparues pour la première fois dans OpenSSL 0.9.8e et sont disponibles depuis OpenBSD 7.1.

BOGUES

Une fonction ASIdOrRanges_new() qui installe la fonction de comparaison correcte sur la pile de ASIdOrRange aurait dû faire partie de l'API pour la rendre utilisable.

ASIdentifierChoice_new() est d'une utilité très limitée car ASIdOrRanges_new() est manquante.

Il n'y a aucun moyen de s'assurer qu'un objet ASIdOrRanges est sous forme canonique, sauf s'il fait partie d'un objet ASIdentifiers. Il est donc difficile de garantir que la sortie de i2d_ASIdentifierChoice() est conforme.

RFC 3779 3.2.3.4 a “asIdsOrRanges” alors que son type dans cette implémentation est ASIdOrRanges.
