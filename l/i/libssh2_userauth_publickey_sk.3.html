libssh2_userauth_publickey_sk(3)

Paquet: libssh2

Licences: BSD

libssh2_userauth_publickey_sk(3) libssh2 libssh2_userauth_publickey_sk(3)

NOM

libssh2_userauth_publickey_sk - authentifier une session avec un authentificateur FIDO2

SYNTAXE

#include <libssh2.h>
int
libssh2_userauth_publickey_sk(LIBSSH2_SESSION *session,
                              const char *username,
                              size_t username_len,
                              const unsigned char *publickeydata,
                              size_t publickeydata_len,
                              const char *privatekeydata,
                              size_t privatekeydata_len,
                              const char *passphrase,
                              LIBSSH2_USERAUTH_SK_SIGN_FUNC((*sign_callback)),
                              void **abstract);

CALLBACK

#define LIBSSH2_SK_PRESENCE_REQUIRED     0x01
#define LIBSSH2_SK_VERIFICATION_REQUIRED 0x04
typedef struct _LIBSSH2_SK_SIG_INFO {
    uint8_t flags;
    uint32_t counter;
    unsigned char *sig_r;
    size_t sig_r_len;
    unsigned char *sig_s;
    size_t sig_s_len;
} LIBSSH2_SK_SIG_INFO;
int name(LIBSSH2_SESSION *session, LIBSSH2_SK_SIG_INFO *sig_info,
         const unsigned char *data, size_t data_len, int algorithm,
         uint8_t flags, const char *application,
         const unsigned char *key_handle, size_t handle_len,
         void **abstract);

DESCRIPTION

session - Instance de session telle que renvoyée par libssh2_session_init_ex(3)

username - Nom de l'utilisateur pour lequel tenter l'authentification.

username_len - Longueur du paramètre username.

publickeydata - Buffer contenant le contenu d'un fichier de clé publique. Si NULL, la clé publique sera extraite de privatekeydata. Lors de l'utilisation de l'authentification par certificat, ce buffer doit contenir les données du certificat public.

publickeydata_len - Longueur des données de clé publique.

privatekeydata - Buffer contenant le contenu d'un fichier de clé privée.

privatekeydata_len - Longueur des données de clé privée.

passphrase - Phrase secrète à utiliser lors du décodage du fichier de clé privée.

sign_callback - Callback pour communiquer avec l'authentificateur FIDO2.

abstract - Données fournies par l'utilisateur à passer au callback.

Tenter l'authentification FIDO2. en utilisant les algorithmes d'échange de clés sk-ssh-ed25519@openssh.com ou sk-ecdsa-sha2-nistp256@openssh.com.

Cette fonction n'est prise en charge que lorsque libssh2 est pris en charge par OpenSSL.

DESCRIPTION DU CALLBACK

session - Instance de session telle que renvoyée par libssh2_session_init_ex(3)

sig_info - Rempli par le callback avec la signature et les informations accompagnant l'authentificateur.

data - Les données à signer.

data_len - La longueur du paramètre data.

algorithm - L'algorithme de signature à utiliser. Les valeurs possibles sont LIBSSH2_HOSTKEY_TYPE_ED25519 et LIBSSH2_HOSTKEY_TYPE_ECDSA_256.

flags - Un masque de bits spécifiant les options de l'authentificateur. Lorsque LIBSSH2_SK_PRESENCE_REQUIRED est défini, l'authentificateur nécessite un toucher. Lorsque LIBSSH2_SK_VERIFICATION_REQUIRED est défini, l'authentificateur nécessite un code PIN. De nombreux serveurs et authentificateurs ne fonctionnent pas correctement lorsque LIBSSH2_SK_PRESENCE_REQUIRED n'est pas défini.

application - Une chaîne définie par l'utilisateur à utiliser comme nom RP pour l'authentificateur. Généralement "ssh:".

key_handle - Le handle de clé à utiliser pour la liste autorisée de l'authentificateur.

handle_len - La longueur du paramètre key_handle.

abstract - Données définies par l'utilisateur. Lorsqu'un code PIN est requis, utilisez ceci pour passer le code PIN, ou un pointeur de fonction pour récupérer le code PIN.

Le sign_callback est responsable de la communication avec l'authentificateur matériel pour générer une signature. En cas de succès, les informations de signature doivent être placées dans le paramètre sig_info de `sig_info` et le callback doit renvoyer 0. En cas d'échec, il doit renvoyer un nombre négatif.

Les champs de la LIBSSH2_SK_SIG_INFO sont les suivants.

flags - Un masque de bits spécifiant les options de l'authentificateur. Ceci doit être lu depuis l'authentificateur et non simplement copié depuis le paramètre flags du callback.

counter - Une valeur renvoyée par l'authentificateur.

sig_r - Pour les signatures Ed25519, ceci contient la signature entière, telle que renvoyée directement par l'authentificateur. Pour les signatures ECDSA, ceci contient la composante r de la signature dans une représentation binaire big-endian. Pour les deux algorithmes, utilisez LIBSSH2_ALLOC pour allouer de la mémoire. Elle sera libérée par l'appelant.

sig_r_len - La longueur du paramètre sig_r.

sig_s - Pour les signatures ECDSA, ceci contient la composante s de la signature dans une représentation binaire big-endian. Utilisez LIBSSH2_ALLOC pour allouer de la mémoire. Elle sera libérée par l'appelant. Pour les signatures Ed25519, définissez ceci à NULL.

sig_s_len - La longueur du paramètre sig_s.

VALEUR DE RETOUR

Retourne 0 en cas de succès ou un nombre négatif en cas d'échec. Il renvoie LIBSSH2_ERROR_EAGAIN lorsqu'il devrait sinon bloquer. Bien que LIBSSH2_ERROR_EAGAIN soit un nombre négatif, ce n'est pas vraiment un échec en soi.

ERREURS

Certaines des erreurs que cette fonction peut retourner incluent:

LIBSSH2_ERROR_ALLOC - Un appel interne d'allocation mémoire a échoué.

LIBSSH2_ERROR_SOCKET_SEND - Impossible d'envoyer des données sur le socket.

LIBSSH2_ERROR_AUTHENTICATION_FAILED - échec, nom d'utilisateur/clé invalide.

DISPONIBILITÉ

Ajouté dans libssh2 1.10.0

Installation d'un paquet Arch Linux

Installation d'un paquet Arch Linux

Ce guide vous explique comment installer un paquet sur Arch Linux en utilisant le gestionnaire de paquets pacman.

Étape 1 : Mettre à jour votre système

Avant d'installer un nouveau paquet, il est fortement recommandé de mettre à jour votre système pour vous assurer que tous les paquets existants sont à jour. Ouvrez un terminal et exécutez la commande suivante :

sudo pacman -Syu

sudo vous permet d'exécuter la commande avec les privilèges d'administrateur.

pacman est le gestionnaire de paquets d'Arch Linux.

-S signifie synchroniser les paquets.

y télécharge les nouvelles listes de paquets depuis les dépôts.

u met à niveau tous les paquets installés qui ont des mises à jour disponibles.

Vous serez invité à entrer votre mot de passe utilisateur.

Étape 2 : Rechercher le paquet (facultatif)

Si vous ne connaissez pas le nom exact du paquet que vous souhaitez installer, vous pouvez le rechercher. Par exemple, pour rechercher des paquets liés à vlc, utilisez :

pacman -Ss vlc

-Ss recherche un paquet dans les dépôts.

La sortie listera tous les paquets correspondants avec une brève description.

Étape 3 : Installer le paquet

Une fois que vous avez le nom exact du paquet, vous pouvez l'installer en utilisant la commande suivante. Remplacez nom_du_paquet par le nom réel du paquet que vous voulez installer.

sudo pacman -S nom_du_paquet

-S est utilisé pour installer des paquets.

pacman vous demandera de confirmer l'installation, affichant la liste des paquets à installer et leur taille. Tapez Y (ou O pour Oui, selon la langue de votre système) puis appuyez sur Entrée pour continuer.

Étape 4 : Vérifier l'installation

Après l'installation, vous pouvez vérifier si le paquet est installé en essayant de l'exécuter ou en utilisant pacman pour voir ses informations :

pacman -Qi nom_du_paquet

-Q signifie interroger la base de données des paquets locaux.

i affiche des informations détaillées sur le paquet.

Installation depuis l'AUR (Arch User Repository)

Pour les paquets qui ne sont pas disponibles dans les dépôts officiels d'Arch Linux, vous pouvez utiliser l'Arch User Repository (AUR). L'AUR contient des descriptions de paquets (PKGBUILDs) créées par la communauté.

Pour installer des paquets depuis l'AUR, vous aurez généralement besoin d'un gestionnaire de paquets AUR comme yay ou paru. Si vous ne les avez pas, vous devrez d'abord les installer.

Exemple d'installation de yay :

  1. Clonez le dépôt AUR de yay :
    git clone https://aur.archlinux.org/yay.git
  2. Accédez au répertoire cloné :
    cd yay
  3. Construisez et installez le paquet :
    makepkg -si

Une fois que vous avez un gestionnaire de paquets AUR, vous pouvez l'utiliser pour installer des paquets de l'AUR. Par exemple, pour installer un paquet nommé nom_paquet_aur avec yay :

yay -S nom_paquet_aur

yay téléchargera le code source, le compilera et l'installera pour vous.

Ce guide couvre les bases de l'installation d'un paquet Arch Linux. Pour des instructions plus avancées ou des solutions de problèmes, veuillez consulter la documentation officielle d'Arch Linux ou rechercher de l'aide sur la communauté Arch Linux concernant l'installation d'un paquet Arch Linux.
