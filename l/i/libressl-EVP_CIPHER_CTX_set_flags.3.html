EVP_CIPHER_CTX_SET_FLAGS(3) Manuel des fonctions de bibliothèque EVP_CIPHER_CTX_SET_FLAGS(3)

NOM

SYNTAXE

void
EVP_CIPHER_CTX_clear_flags(EVP_CIPHER_CTX *ctx, int flags);

int
EVP_CIPHER_CTX_test_flags(EVP_CIPHER_CTX *ctx, int flags);

int
EVP_CIPHER_CTX_rand_key(EVP_CIPHER_CTX *ctx, unsigned char *key);

int
EVP_CIPHER_param_to_asn1(EVP_CIPHER_CTX *c, ASN1_TYPE *type);

int
EVP_CIPHER_asn1_to_param(EVP_CIPHER_CTX *c, ASN1_TYPE *type);

void *
EVP_CIPHER_CTX_get_app_data(const EVP_CIPHER_CTX *ctx);

void
EVP_CIPHER_CTX_set_app_data(const EVP_CIPHER_CTX *ctx, void *data);

DESCRIPTION

EVP_CIPHER_CTX_set_flags() active les flags donnés dans ctx. EVP_CIPHER_CTX_clear_flags() désactive les flags donnés dans ctx. EVP_CIPHER_CTX_test_flags() vérifie si l'un des flags donnés est actuellement défini dans ctx, retournant le sous-ensemble des flags qui sont définis, ou 0 si aucun n'est défini. Actuellement, le seul drapeau de contexte de chiffrement pris en charge est EVP_CIPHER_CTX_FLAG_WRAP_ALLOW ; voir EVP_aes_128_wrap(3) pour les détails.

EVP_CIPHER_CTX_rand_key() génère une clé aléatoire de la longueur appropriée en fonction du contexte de chiffrement. Le EVP_CIPHER peut fournir sa propre routine de génération de clé aléatoire pour prendre en charge des clés de forme spécifique. L'argument key doit pointer vers un tampon au moins aussi grand que la valeur retournée par EVP_CIPHER_CTX_key_length(3).

EVP_CIPHER_param_to_asn1() définit le paramètre ASN.1 de l'identificateur d'algorithme en fonction du chiffrement passé. Cela inclura généralement tous les paramètres et un IV. L'IV du chiffrement (le cas échéant) doit être défini lorsque cet appel est effectué. Cet appel doit être effectué avant que le chiffrement ne soit effectivement « utilisé » (avant les appels à EVP_EncryptUpdate(3) ou EVP_DecryptUpdate(3), par exemple). Cette fonction peut échouer si le chiffrement n'a aucun support ASN.1.

EVP_CIPHER_asn1_to_param() définit les paramètres de chiffrement en fonction d'un paramètre ASN.1 d'identificateur d'algorithme. L'effet précis dépend du chiffrement. Dans le cas de RC2, par exemple, il définira l'IV et la longueur effective de la clé. Cette fonction doit être appelée après que le type de chiffrement de base est défini mais avant que la clé ne soit définie. Par exemple, EVP_CipherInit(3) sera appelé avec l'IV et la clé définis sur NULL, EVP_CIPHER_asn1_to_param() sera appelé et enfin EVP_CipherInit(3) à nouveau avec tous les paramètres sauf la clé définis sur NULL. Il est possible que cette fonction échoue si le chiffrement n'a aucun support ASN.1 ou si les paramètres ne peuvent pas être définis (par exemple, la longueur effective de la clé RC2 n'est pas prise en charge).

VALEURS DE RETOUR

EVP_CIPHER_CTX_rand_key() retourne 1 en cas de succès ou 0 en cas d'échec.

EVP_CIPHER_param_to_asn1() et EVP_CIPHER_asn1_to_param() retournent une valeur supérieure à zéro en cas de succès et zéro ou un nombre négatif en cas d'échec.

VOIR AUSSI

evp(3), EVP_CIPHER_CTX_ctrl(3), EVP_CIPHER_CTX_get_cipher_data(3), EVP_CIPHER_nid(3), EVP_EncryptInit(3)

HISTORIQUE

EVP_CIPHER_CTX_set_app_data() et EVP_CIPHER_CTX_get_app_data() sont apparus pour la première fois dans SSLeay 0.8.0. EVP_CIPHER_param_to_asn1() et EVP_CIPHER_asn1_to_param() sont apparus pour la première fois dans SSLeay 0.9.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

EVP_CIPHER_CTX_rand_key() est apparu pour la première fois dans OpenSSL 0.9.8 et est disponible depuis OpenBSD 4.5.

BOGUES

Le code ASN.1 est incomplet (et parfois inexact). Il n'a été testé que pour certains chiffrements S/MIME courants (RC2, DES, triple DES) en mode CBC.
