NOM

libpfm - bibliothèque d'aide pour développer des outils de surveillance

SYNTAXE

#include <perfmon/pfmlib.h>

DESCRIPTION

Ceci est une bibliothèque d'aide utilisée par les applications pour programmer des événements de surveillance de performance spécifiques. Ces événements sont généralement fournis par le matériel ou le noyau du système d'exploitation. Les événements matériels les plus courants sont fournis par l'unité de surveillance de performance (PMU) des processeurs modernes. Ils peuvent mesurer les cycles écoulés ou le nombre de ratés de cache. Les événements logiciels comptent généralement les événements du noyau tels que le nombre de changements de contexte ou les fautes de page.

La bibliothèque regroupe les événements en fonction de la source qui les fournit. Le terme PMU est généralisé à toute source d'événements, pas seulement aux sources matérielles. La bibliothèque prend en charge les événements de performance matériels de la plupart des processeurs courants, chaque groupe étant sous un nom PMU spécifique, tel que Intel Core, IBM Power 6.

La programmation des événements se fait généralement via une API du noyau, telle qu'Oprofile, perfmon, perfctr, ou perf_events sous Linux. La bibliothèque fournit une prise en charge de perf_events qui est disponible dans le noyau Linux depuis la version 2.6.31. Perf_events prend en charge certains modèles PMU sélectionnés et plusieurs événements logiciels.

Au cœur de la bibliothèque se trouve un simple service de traduction, par lequel un utilisateur spécifie un événement à mesurer sous forme de chaîne de caractères et la bibliothèque renvoie les paramètres nécessaires pour appeler l'API du noyau. Il est important de réaliser que la bibliothèque n'effectue pas l'appel système pour programmer l'événement.

Note : Vous devez d'abord appeler pfm_initialize() pour utiliser l'une des autres fonctions fournies dans la bibliothèque.

Une première partie de la bibliothèque fournit une interface de liste et d'interrogation d'événements. Celle-ci peut être utilisée pour découvrir les événements disponibles sur une plateforme matérielle spécifique.

La deuxième partie de la bibliothèque fournit un ensemble de fonctions pour obtenir des encodages d'événements à partir de chaînes d'événements. L'encodage des événements dépend principalement du matériel sous-jacent, mais aussi de l'API du noyau. La bibliothèque offre une API générique pour répondre à la première situation, mais elle fournit également des points d'entrée pour des API spécifiques du noyau telles que perf_events. Dans ce cas, elle est capable de préparer la structure de données qui doit être passée au noyau pour programmer un événement spécifique.

DÉTECTION D'ÉVÉNEMENT

Lorsque la bibliothèque est initialisée via pfm_initialize(), elle détecte d'abord la configuration matérielle et logicielle sous-jacente. Sur la base de ces informations, elle active certaines prises en charge PMU. Plusieurs tables d'événements peuvent être activées.

Il est possible de forcer l'activation d'un PMU spécifique (groupe d'événements) en utilisant une variable d'environnement.

CHAINES D'ÉVÉNEMENT

Les événements sont exprimés sous forme de chaînes de caractères. Ces chaînes sont structurées et peuvent contenir plusieurs composants en fonction du type d'événement et du matériel sous-jacent.

L'analyse des chaînes est toujours insensible à la casse.

La structure de la chaîne est définie comme suit :


[pmu::][nom_evenement][:masque_unite][:modificateur|:modificateur=val]

ou
[pmu::][nom_evenement][.masque_unite][.modificateur|.modificateur=val]

Les composants sont définis comme suit :

pmu
Nom optionnel du PMU (groupe d'événements) auquel appartient l'événement. Ceci est utile pour désambiguïser les événements dans le cas où des événements de différentes sources ont le même nom. Si non spécifié, la première correspondance est utilisée.
nom_evenement
Le nom de l'événement. Il doit s'agir du nom complet, les correspondances partielles ne sont pas acceptées. Ce composant est obligatoire.
masque_unite
Ceci désigne des sous-événements optionnels. Certains événements peuvent être affinés à l'aide de sous-événements. Les événements peuvent avoir plusieurs masques d'unité et il peut ou non être possible de les combiner. Si plus d'un masque d'unité doit être passé, alors le motif [:masque_unite] peut être répété.
modificateur
Un modificateur est un filtre optionnel qui modifie la manière dont l'événement compte. Les modificateurs ont un type et une valeur. La valeur est spécifiée après le signe égal. Aucun espace n'est autorisé. Dans le cas de modificateurs booléens, il est possible d'omettre la valeur true (1). La présence du modificateur est interprétée comme vraie. Les événements peuvent prendre en charge plusieurs modificateurs, auquel cas le motif [:modificateur|:modificateur=val] peut être répété. Il n'y a pas de contrainte d'ordre entre les modificateurs et les masques d'unité. Les modificateurs peuvent être spécifiés avant les masques d'unité et vice versa.

VARIABLES D'ENVIRONNEMENT

Il est possible d'activer certaines fonctionnalités de débogage de la bibliothèque en utilisant des variables d'environnement. Les variables suivantes sont définies :

LIBPFM_VERBOSE
Active la sortie détaillée. La valeur doit être 0 ou 1.
LIBPFM_DEBUG
Active la sortie de débogage. La valeur doit être 0 ou 1
LIBPFM_DEBUG_STDOUT
Redirige la sortie détaillée et de débogage vers le descripteur de fichier de sortie standard (stdout). Par défaut, la sortie est dirigée vers le descripteur de fichier d'erreur standard (stderr).
LIBPFM_FORCE_PMU
Force l'activation d'un modèle PMU spécifique. Dans ce mode, seul ce modèle est activé. La valeur de la variable doit être le nom du PMU tel que renvoyé par la fonction pfm_get_pmu_name(). Notez que pour certains modèles PMU, il peut être possible de spécifier des options supplémentaires, telles que des modèles de processeur ou des révisions spécifiques. Les paramètres supplémentaires apparaissent nécessairement après une virgule. Par exemple, LIBPFM_FORCE_PMU=amd64,16,2,1.
LIBPFM_ENCODE_INACTIVE
Définissez cette variable à 1 pour activer l'encodage des événements pour les modèles PMU non détectés, mais pris en charge.
LIBPFM_DISABLED_PMUS
Fournit une liste de modèles PMU à désactiver. Il s'agit d'une liste de modèles PMU séparés par des virgules. Le modèle PMU est la chaîne de caractères dans le champ name de la structure pfm_pmu_info_t. Par exemple : LIBPFM_DISABLE_PMUS=core,snb, désactivera le support des PMU du cœur Intel Core et SandyBridge.

DESCRIPTION

La bibliothèque libpfm fournit une API pour accéder et manipuler les informations des compteurs de performance matériels présents sur les processeurs Intel et AMD. Elle permet de lister les événements disponibles, d'obtenir des descriptions détaillées de ces événements et de configurer les compteurs pour la collecte de données de performance.

SYNOPSIS

#include <perfmon/pfmlib.h>

int pfm_initialize(void);
int pfm_get_version(uint64_t *version);
// ... autres fonctions ...

INITIALISATION

Avant d'utiliser la plupart des fonctions de libpfm, il est nécessaire d'appeler pfm_initialize(). Cette fonction initialise la bibliothèque et charge la configuration matérielle du processeur en cours.

FONCTIONS

Voici quelques-unes des fonctions principales fournies par libpfm :

  • pfm_initialize() : Initialise la bibliothèque.
  • pfm_get_version() : Récupère la version de la bibliothèque.
  • pfm_num_event_mask() : Obtient le nombre d'événements de performance disponibles.
  • pfm_get_event_name() : Obtient le nom d'un événement de performance à partir de son code.
  • pfm_get_event_description() : Obtient une description textuelle d'un événement de performance.
  • pfm_get_event_code() : Obtient le code d'un événement de performance à partir de son nom.
  • pfm_get_event_info() : Obtient des informations détaillées sur un événement de performance.
  • pfm_dispatch_events() : Permet de configurer et de déclencher la collecte d'événements.
  • pfm_terminate() : Libère les ressources utilisées par la bibliothèque.

EXEMPLES

Voici un exemple simple d'utilisation de libpfm pour lister les événements disponibles : 

#include <stdio.h>
#include <perfmon/pfmlib.h>

int main() {
    uint64_t version;
    int ret;

    ret = pfm_initialize();
    if (ret != PFM_SUCCESS) {
        fprintf(stderr, "Erreur lors de l'initialisation de libpfm: %d\n", ret);
        return 1;
    }

    pfm_get_version(&version);
    printf("Version de libpfm: %llu\n", version);

    uint64_t num_events = pfm_num_event_mask();
    printf("Nombre d'événements disponibles: %llu\n", num_events);

    for (int i = 0; i < num_events; ++i) {
        char event_name[PFM_EVENT_NAME_MAX];
        if (pfm_get_event_name(i, event_name) == PFM_SUCCESS) {
            printf("  - %s\n", event_name);
        }
    }

    pfm_terminate();
    return 0;
}

La bibliothèque libpfm peut être influencée par certaines variables d'environnement, notamment pour spécifier des chemins de configuration alternatifs ou des options de débogage. Consultez la documentation de libpfm pour une liste complète.
