PKCS12_CREATE(3) Manuel des fonctions de bibliothèque PKCS12_CREATE(3)

NOM

PKCS12_create — créer une structure PKCS#12

SYNOPSIS

bibliothèque “libcrypto”
#include <openssl/pkcs12.h>

PKCS12 *
PKCS12_create(const char *pass, const char *name, EVP_PKEY *pkey, X509 *cert, STACK_OF(X509) *ca, int nid_key, int nid_cert, int iter, int mac_iter, int keytype);

DESCRIPTION

PKCS12_create() crée une structure PKCS#12.

pass est la phrase secrète à utiliser. name est le friendlyName à utiliser pour le certificat et la clé fournis. pkey est la clé privée à inclure dans la structure et cert son certificat correspondant. ca est un ensemble optionnel de certificats à inclure également dans la structure. pkey, cert, ou les deux peuvent être NULL pour indiquer qu'aucune clé ou certificat n'est requis.

nid_key et nid_cert sont les algorithmes de chiffrement qui doivent être utilisés pour la clé et le certificat, respectivement. Si l'un ou l'autre de nid_key ou nid_cert est défini sur -1, aucun chiffrement ne sera utilisé.

iter est le nombre d'itérations de l'algorithme de chiffrement à utiliser et mac_iter est le nombre d'itérations du MAC à utiliser. Si mac_iter est défini sur -1, le MAC sera omis entièrement.

keytype est le type de clé.

Les paramètres nid_key, nid_cert, iter, mac_iter, et keytype peuvent tous être mis à zéro et des valeurs par défaut raisonnables seront utilisées.

Ces valeurs par défaut sont : chiffrement RC2 40 bits pour les certificats, chiffrement triple DES pour les clés privées, un nombre d'itérations de clé de PKCS12_DEFAULT_ITER (actuellement 2048) et un nombre d'itérations de MAC de 1.

Le nombre d'itérations de MAC par défaut est 1 afin de conserver la compatibilité avec les anciens logiciels qui n'interprétaient pas les nombres d'itérations de MAC. Si une telle compatibilité n'est pas requise, mac_iter devrait être défini sur PKCS12_DEFAULT_ITER.

keytype ajoute un drapeau à la clé privée stockée. Il s'agit d'une extension non standard qui n'est actuellement interprétée que par MSIE. Si défini sur zéro, le drapeau est omis ; si défini sur KEY_SIG, la clé ne peut être utilisée que pour la signature ; et si défini sur KEY_EX, elle peut être utilisée pour la signature et le chiffrement. Cette option était utile pour les anciens logiciels d'exportation qui pouvaient utiliser des clés uniquement pour la signature de taille arbitraire mais avaient des restrictions sur les tailles de clés autorisées pour le chiffrement.

Si un certificat contient un alias ou keyid, cela sera utilisé pour le friendlyName ou localKeyID correspondant dans la structure PKCS12.

VALEURS DE RETOUR

PKCS12_create() retourne une structure PKCS12 valide ou NULL si une erreur s'est produite.

VOIR AUSSI

crypto(3), d2i_PKCS12(3), PKCS12_new(3), PKCS12_newpass(3), PKCS12_parse(3), PKCS12_SAFEBAG_new(3), X509_keyid_set1(3)

HISTORIQUE

PKCS12_create() est apparu pour la première fois dans OpenSSL 0.9.3 et est disponible depuis OpenBSD 2.6.

Avant OpenSSL 0.9.8, ni pkey ni cert n'étaient autorisés à être NULL, et une valeur de -1 n'était pas autorisée pour nid_key, nid_cert, et mac_iter.
