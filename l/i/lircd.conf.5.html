LIRCD.CONF(5) Manuel des formats de fichiers LIRCD.CONF(5)

NOM

lircd.conf - fichier de configuration principal de lirc

DESCRIPTION

Le fichier a deux objectifs : fournir des informations de synchronisation au pilote afin qu'il puisse décoder les données en appuis de boutons, et fournir une correspondance entre les appuis de boutons et les symboles de touches utilisés par lircd(8).

La structure de base est une liste de blocs distants. Les espaces blancs et les sauts de ligne sont utilisés comme délimiteurs.

Si le caractère de commentaire (#) apparaît comme premier caractère d'une ligne, le reste de la ligne est ignoré.

BLOCS DISTANTS

Les blocs distants sont normaux ou bruts.

Les blocs distants normaux commencent par begin remote et se terminent par end remote. La première partie du bloc décrit les propriétés de base de la télécommande, voir la section DESCRIPTION DE LA TÉLÉCOMMANDE. Suivent une section de codes, délimitée par begin codes et end codes.

Chaque ligne dans une section de codes contient le nom d'un bouton sur la télécommande suivi d'une valeur de données hexadécimales correspondant à la partie données de la trame IR (voir la section DESCRIPTION DE LA TÉLÉCOMMANDE). Vous ne pouvez pas attribuer le même nom à deux boutons dans la même section de télécommande.

Les blocs distants bruts sont identiques aux blocs normaux à l'exception de la section de codes qui est une liste de descriptions de boutons encadrées par begin raw_codes et end raw_codes.

Une description de bouton brut commence par le paramètre name suivi du nom du bouton. La description du bouton se termine par la description du bouton suivante ou par la fin du bloc raw_codes. Les lignes intermédiaires sont une liste de nombres décimaux décrivant le signal envoyé par ce bouton. Le premier nombre indique la durée de la première impulsion en microsecondes. Le deuxième nombre indique la durée de l'espace qui la suit. Les durées d'impulsion et d'espace alternent aussi longtemps que nécessaire. La dernière durée doit représenter une impulsion.

SECTION DESCRIPTION TÉLÉCOMMANDE

Chaque ligne de cette section contient un paramètre suivi de la ou des valeurs qui doivent être attribuées à ce paramètre. Les paramètres sont facultatifs sauf indication contraire.

Toutes les valeurs sont des entiers décimaux soit sans dimension, soit avec une unité de microsecondes sauf indication contraire. Les nombres hexadécimaux doivent être préfixés par 0x. Si la télécommande n'a pas une "fonctionnalité" particulière, alors la ligne peut être omise. Le code du bouton est envoyé juste après le signal de pré et juste avant le signal de post.

Certains paramètres décrivent les bits du protocole IR. La trame est normalement définie comme suit :

|en-tête|pré-impulsion|pré-données|pré|données|post|post-données|post-impulsion|pied|intervalle|

où la plupart des paramètres valent 0 par défaut. Certains paramètres modifient la disposition générale de la trame, par exemple le paramètre de répétition.

include ”<chemin>”
Inclure le chemin donné en utilisant les sémantiques d'inclusion normales. Si le chemin est relatif, il est interprété par rapport au fichier principal lircd.conf. <chemin> doit être entouré de guillemets doubles. Il peut contenir un modèle glob(3) auquel cas tous les fichiers correspondants sont inclus.
manual_sort <1|0>
Normalement, lircd essaie de trier plusieurs télécommandes afin que celle qui décode le plus rapidement soit utilisée en premier. Définir manual_sort à 1 dans n'importe quelle télécommande désactive cela et utilise les télécommandes dans l'ordre où elles sont listées dans lircd.conf ou en tant que noms de fichiers triés alphabétiquement dans lircd.conf.d.
name <nom télécommande>
Le nom unique attribué à la télécommande (ne peut pas contenir d'espaces). Au sein d'un même fichier, tous les noms doivent être uniques. Paramètre obligatoire.
suppress_repeat <répétitions>
Supprimer un nombre donné de répétitions pour tous les boutons de cette télécommande. La valeur par défaut est 0, ce qui signifie qu'aucune répétition n'est supprimée. Notez que lircrc a un paramètre correspondant repeat qui peut être utilisé pour supprimer les répétitions pour des combinaisons spécifiques bouton/client.
flags <indicateur1><|indicateur2>...
Les drapeaux sont des chaînes de caractères spéciales qui décrivent diverses propriétés de la télécommande et déterminent la sémantique des champs suivants. Les indicateurs multiples doivent être séparés par le symbole pipe (|). Voir INDICATEURS.
driver <nom pilote>
Pour les pilotes lirccode qui n'ont pas d'informations de synchronisation, l'attribut facultatif driver nomme le pilote requis pour utiliser cette télécommande.
bits <nombre de bits de données>
Le nombre de bits de données dans les codes hexadécimaux qui décrivent chaque bouton (entier décimal).
eps <tolérance d'erreur relative>
La tolérance d'erreur relative pour les signaux reçus en pour cent. Par défaut, irrecord la définit à 30 (c'est-à-dire 30 %).
aeps <tolérance d'erreur absolue>
La tolérance d'erreur absolue pour les signaux reçus (microsecondes). La valeur par défaut est la résolution dépendante du pilote codée en dur. Par défaut, irrecord la définit à 100.
header <pré-impulsion> <intervalle-en-tête>
L'impulsion et l'espace initiaux envoyés (microsecondes).
three <pré-impulsion> <intervalle-trois>
Utilisé uniquement par les télécommandes RC-MM
two <pré-impulsion> <intervalle-deux>
Utilisé uniquement par les télécommandes RC-MM
one <pré-impulsion> <intervalle-un>
Les longueurs d'impulsion et d'espace représentant un un.
zero <pré-impulsion> <intervalle-zéro>
Les longueurs d'impulsion et d'espace représentant un zéro.
ptrail <impulsion finale>
Une impulsion finale, immédiatement après les données post.
plead <impulsion initiale>
Une impulsion initiale, juste après l'en-tête.
foot <impulsion-pied> <intervalle-pied>
Une impulsion et un espace, immédiatement après l'impulsion finale.
repeat <pré-répétition> <intervalle-répétition>
Une impulsion et un espace qui remplacent tout entre l'impulsion initiale et l'impulsion finale, chaque fois qu'un signal est répété. Le pied n'est pas envoyé, et l'en-tête n'est pas envoyé sauf si l'indicateur REPEAT_HEADER est présent.
pre_data_bits <nombre de bits pre_data>
Le nombre de bits dans le code pre_data.
pre_data <nombre hexadécimal>
Code hexadécimal indiquant la séquence de uns et de zéros immédiatement après l'impulsion initiale.
post_data_bits <nombre de bits post_data>
Le nombre de bits dans le code post_data.
post_data <nombre hexadécimal>
Code hexadécimal indiquant la séquence de uns et de zéros immédiatement après le signal post.
pre <pré-impulsion> <intervalle-pré>
Une impulsion et un espace immédiatement après le pre_data, utilisés comme délimiteur entre pre data et data.
post <pré-impulsion> <intervalle-post>
Une impulsion et un espace immédiatement après le code du bouton.
gap <longueur intervalle>
Un espace (généralement long) qui suit l'impulsion finale.
repeat_gap <longueur intervalle de répétition>
Un intervalle immédiatement après l'impulsion finale, et précédant une répétition du même code due à une même pression du bouton.
min_repeat <nombre minimum de répétitions>
Le nombre minimum de fois où un signal est répété lors de son envoi. Notez que 0 signifie que le signal n'est envoyé qu'une seule fois. Non utilisé lors de la réception.

toggle_bit <bit à basculer>
Un bit des données pré, code ou post qui est basculé entre un et zéro à chaque fois qu'un bouton est pressé. Ce paramètre est obsolète et remplacé par toggle_bit_mask ; ne doit pas être utilisé dans les nouvelles configurations.
toggle_bit_mask <masque hexadécimal>
Bits qui sont basculés entre un et zéro à chaque fois qu'un bouton est pressé. Le masque est appliqué à la valeur concaténée des données pré - données - données post.
repeat_mask <masque>
Le masque définit quels bits sont inversés pour les répétitions.
frequency <hertz>
Fréquence de la porteuse du télécommande, par défaut 38000.
duty_cycle <durée de l'état haut>
Le pourcentage du temps pendant une impulsion pendant lequel la lumière infrarouge est envoyée. Il s'agit d'un entier compris entre 1 et 100 inclus. La valeur par défaut est 50.

FLAGS

Les drapeaux sont des valeurs définies dans le paramètre flags.

RC5
La télécommande utilise le protocole RC5.
RC6
La télécommande utilise le protocole RC6.
RCMM
La télécommande utilise le protocole RC-MM.
SHIFT_ENC
Drapeau obsolète, maintenant un synonyme de RC5. La position de l'impulsion (avant ou après l'espace) détermine si le bit est un un ou un zéro.
SPACE_ENC
Un un et un zéro peuvent être distingués par la longueur des espaces, utilisé par le protocole NEC et d'autres.
REVERSE
Inverse l'ordre des bits des données pré, des données post et des codes (par exemple, 0x123 devient 0xC48). Si ce drapeau est présent, le bit le moins significatif est envoyé en premier.
NO_HEAD_REP
L'en-tête n'est pas envoyé lorsqu'un signal (le bouton est maintenu enfoncé) est répété, même s'il n'y a pas de code de répétition spécial.
NO_FOOT_REP
Le pied de page n'est pas envoyé lorsqu'un signal est répété (le bouton est maintenu enfoncé), même s'il n'y a pas de code de répétition spécial.
CONST_LENGTH
La longueur totale du signal est toujours constante. La longueur de l'intervalle représente maintenant la longueur de l'ensemble du signal, et l'intervalle réel à la fin du signal est ajusté en conséquence.
RAW_CODES
Les codes sont au format brut.
REPEAT_HEADER
Envoie l'en-tête lorsque le signal est répété, même si la télécommande possède un code de répétition spécial.

CLAUSE DE NON-RESPONSABILITÉ

LIRC a été conçu pour collecter des données IR et les enregistrer dans un format privé, compact, mais lisible par l'homme, dans le but de pouvoir réémettre (ou reconnaître à nouveau) ces signaux. Il n'a pas été conçu dans le but de fournir un format de fichier de configuration bien documenté et testé qui pourrait être utilisé, par exemple, pour générer des signaux IR arbitraires ou pour les convertir vers d'autres formats. Le fichier de configuration ne doit donc pas être considéré comme une interface publique pour LIRC.

Cette page de manuel doit être comprise dans cet esprit. Elle a été rédigée en lisant le code de LIRC, et ne constitue pas une spécification faisant autorité du comportement de LIRC et de son fichier de configuration. De plus, certains drapeaux et paramètres moins couramment utilisés ne sont pas documentés.
