X509_STORE_CTX_SET_VERIFY_CB(3) Manuel des fonctions de bibliothèque X509_STORE_CTX_SET_VERIFY_CB(3)

NOM

X509_STORE_CTX_verify_cb, X509_STORE_CTX_set_verify_cb, X509_STORE_CTX_get_verify_cb — définir et récupérer le rappel de vérification

SYNTAXE

bibliothèque «libcrypto»
#include <openssl/x509_vfy.h>

typedef int
(*X509_STORE_CTX_verify_cb)(int ok, X509_STORE_CTX *ctx);

void
X509_STORE_CTX_set_verify_cb(X509_STORE_CTX *ctx, X509_STORE_CTX_verify_cb verify_cb);

X509_STORE_CTX_verify_cb
X509_STORE_CTX_get_verify_cb(X509_STORE_CTX *ctx);

DESCRIPTION

X509_STORE_CTX_set_verify_cb() définit le rappel de vérification de ctx sur verify_cb, écrasant tout rappel existant.

Le rappel de vérification peut être utilisé pour modifier le fonctionnement de la vérification de certificat, soit en ignorant les conditions d'erreur, soit en enregistrant les erreurs à des fins de débogage. L'utilisation d'un rappel de vérification n'est pas essentielle et ne devrait pas être utilisée dans les programmes sensibles à la sécurité.

N'utilisez pas cette fonction. Elle est extrêmement fragile et imprévisible. Ce rappel expose les détails d'implémentation de la vérification de certificat, qui changent au fur et à mesure que la bibliothèque évolue. Tenter de l'utiliser pour des vérifications de sécurité peut introduire des vulnérabilités si des hypothèses incorrectes sont faites sur le moment où le rappel est appelé. De plus, remplacer ok peut laisser ctx dans un état incohérent et casser des invariants.

Au lieu de cela, personnalisez la vérification de certificat en configurant des options sur la X509_STORE_CTX avant la vérification, ou en appliquant des vérifications supplémentaires après que X509_verify_cert(3) soit terminée avec succès.

Le paramètre ok du rappel indique la valeur que le rappel doit retourner pour conserver le comportement par défaut. S'il est zéro, une condition d'erreur est indiquée. S'il est 1, aucune erreur ne s'est produite. Comme le comportement par défaut est interne au vérificateur, et potentiellement inconnu de l'appelant, la modification de ce paramètre est intrinsèquement dangereuse et ne devrait normalement pas être faite, sauf à des fins de débogage, et ne devrait pas être considérée comme cohérente si le vérificateur change. Si le drapeau X509_V_FLAG_NOTIFY_POLICY est défini, alors ok est défini sur 2 pour indiquer que la vérification des politiques est terminée.

Le paramètre ctx du rappel est la structure X509_STORE_CTX qui effectue l'opération de vérification. Un rappel peut examiner cette structure et recevoir des informations supplémentaires sur l'erreur, par exemple en appelant X509_STORE_CTX_get_current_cert(3). Des données d'application supplémentaires peuvent être passées au rappel via le mécanisme ex_data.

Le rappel de vérification peut être défini et hérité de la structure parente effectuant l'opération. Dans certains cas (comme la vérification S/MIME), la structure X509_STORE_CTX est créée et détruite en interne, et le seul moyen de définir un rappel de vérification personnalisé est de l'hériter de la X509_STORE associée.

VALEURS DE RETOUR

X509_STORE_CTX_get_verify_cb() retourne un pointeur vers la fonction de rappel actuelle utilisée par le ctx spécifié. Si aucun rappel n'a été défini à l'aide de X509_STORE_CTX_set_verify_cb(), il s'agit d'un pointeur vers une fonction statique intégrée qui ne fait rien d'autre que de retourner l'argument ok qui lui est passé.

EXEMPLES

Opération de rappel par défaut :

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	return ok;
}

C'est probablement le seul rappel sûr à utiliser.

Exemple simple et terrible à ne pas utiliser. Supposons qu'un certificat dans la chaîne soit expiré et que nous voulions continuer après cette erreur :

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	/* Tolérer l'expiration du certificat */
	if (X509_STORE_CTX_get_error(ctx) == X509_V_ERR_CERT_HAS_EXPIRED)
		return 1;
	/* Sinon, ne pas remplacer */
	return ok;
}

Bien que cet exemple soit présenté à des fins historiques, ce n'est pas la bonne façon d'y parvenir. Le drapeau de vérification X509_V_FLAG_NO_CHECK_TIME devrait être défini sur la STORE_CTX à l'aide de X509_VERIFY_PARAM_set_flags(3) à la place.

Rappel de journalisation de débogage complet - notez que la sortie et l'ordre des événements peuvent changer avec le temps et ne doivent pas être analysés ni être considérés comme cohérents. Dans ce cas, bio_err est supposé être un BIO de journalisation global, une alternative serait de stocker un BIO dans ctx en utilisant ex_data.

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	X509 *err_cert;
	int err,depth;

	err_cert = X509_STORE_CTX_get_current_cert(ctx);
	err =	X509_STORE_CTX_get_error(ctx);
	depth =	X509_STORE_CTX_get_error_depth(ctx);

	BIO_printf(bio_err,"depth=%d ",depth);
	if (err_cert) {
		X509_NAME_print_ex(bio_err,
		    X509_get_subject_name(err_cert), 0,
		    XN_FLAG_ONELINE);
		BIO_puts(bio_err, "\n");
	} else
		BIO_puts(bio_err, "<no cert>\n");
	if (!ok)
		BIO_printf(bio_err, "verify error:num=%d:%s\n",
		    err, X509_verify_cert_error_string(err));
	switch (err) {
	case X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT:
		BIO_puts(bio_err, "issuer= ");
		X509_NAME_print_ex(bio_err,
		    X509_get_issuer_name(err_cert), 0,
		    XN_FLAG_ONELINE);
		BIO_puts(bio_err, "\n");
		break;
	case X509_V_ERR_CERT_NOT_YET_VALID:
	case X509_V_ERR_ERROR_IN_CERT_NOT_BEFORE_FIELD:
		BIO_printf(bio_err, "notBefore=");
		ASN1_TIME_print(bio_err,
		    X509_get_notBefore(err_cert));
		BIO_printf(bio_err, "\n");
		break;
	case X509_V_ERR_CERT_HAS_EXPIRED:
	case X509_V_ERR_ERROR_IN_CERT_NOT_AFTER_FIELD:
		BIO_printf(bio_err, "notAfter=");
		ASN1_TIME_print(bio_err, X509_get_notAfter(err_cert));
		BIO_printf(bio_err, "\n");
		break;
	case X509_V_ERR_NO_EXPLICIT_POLICY:
		policies_print(bio_err, ctx);
		break;
	}
	if (err == X509_V_OK && ok == 2)
		/* imprimer les politiques */

	BIO_printf(bio_err,"verify return:%d\n",ok);
	return(ok);
}

X509_STORE_CTX_set_verify_cb

NAME

X509_STORE_CTX_set_verify_cb - set a callback function for certificate verification

SYNOPSIS

 #include <openssl/x509_vfy.h>
 int X509_STORE_CTX_set_verify_cb(X509_STORE_CTX *ctx,
     int (*verify_callback)(int, X509_STORE_CTX *));

DESCRIPTION

The X509_STORE_CTX_set_verify_cb() function sets the callback function verify_callback to be used for verifying certificates in the verification context ctx. The default callback is used if this function is not called.

The callback function is called during the certificate chain verification process. It is invoked for each certificate in the chain and for the entire chain verification. The first argument, an integer, indicates the current verification step. The second argument is a pointer to the X509_STORE_CTX structure.

The callback should return 1 for success and 0 for failure.

A verification callback can be used to implement custom verification logic, such as checking certificate revocation lists (CRLs) or performing additional checks on certificate fields.

The callback is invoked at various stages of the verification. The first argument indicates the current stage:

X509_V_OK
The verification has succeeded.
X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT_LOCALLY
The issuer certificate could not be found locally.
X509_V_ERR_UNABLE_TO_VERIFY_LEAF_SIGNATURE
The signature of the leaf certificate could not be verified.
X509_V_ERR_OUT_OF_MEM
Out of memory.
X509_V_ERR_CERT_STRING_MALFORMED
The certificate string is malformed.
X509_V_ERR_WRONG_USAGE
The certificate has an incorrect usage.
X509_V_ERR_UNABLE_TO_GET_CRL_ISSUER
The CRL issuer certificate could not be found locally.
X509_V_ERR_UNABLE_TO_DECODE_ISSUER_PUBLIC_KEY
The issuer public key could not be decoded.
X509_V_ERR_CERT_SIGNATURE_FAILURE
The certificate signature verification failed.
X509_V_ERR_NAME_CONSTRAINTS_VIOLATION
Name constraints violation.
X509_V_ERR_INVALID_SIGNATURE
Invalid signature.
X509_V_ERR_INVALID_PURPOSE
Invalid purpose.
X509_V_ERR_CERT_REVOKED
The certificate has been revoked.
X509_V_ERR_INVALID_CA
Invalid CA.
X509_V_ERR_DEPTH_ZERO_SELF_SIGNED_CERT
Self-signed certificate.
X509_V_ERR_SUBJECT_ISSUER_MISMATCH
Subject issuer mismatch.
X509_V_ERR_AKID_SKID_MISMATCH
Authority Key ID / Subject Key ID mismatch.
X509_V_ERR_ISSUER_SELF_SIGNED
Issuer is self-signed.
X509_V_ERR_UNSUPPORTED_CONSTRAINT_TYPE

Application-defined verification error.

RETURN VALUES

The function returns 1 on success, and 0 on failure.

EXAMPLES

This example shows how to set a custom verification callback:

 #include <openssl/x509.h>
 #include <openssl/x509_vfy.h>
 #include <stdio.h>

 static int my_verify_callback(int preverify_ok, X509_STORE_CTX *ctx) {
     int err = X509_V_ERR_OK;
     X509 *cert = NULL;

     if (!preverify_ok) {
         err = X509_STORE_CTX_get_error(ctx);
         cert = X509_STORE_CTX_get_current_cert(ctx);
         fprintf(stderr, "Preverification failed: %d, %s\n", err, X509_verify_error_string(err));
         // Further custom checks can be done here
         // For example, check certificate details or revocation status
     }

     // Return 1 to continue verification, 0 to stop with failure
     // In this simple example, we pass through the preverify result
     return preverify_ok;
 }

 int main() {
     X509_STORE_CTX *ctx;
     // Assume ctx is initialized and populated elsewhere
     // ctx = ... ;

     if (X509_STORE_CTX_set_verify_cb(ctx, my_verify_callback) == 0) {
         fprintf(stderr, "Failed to set verification callback.\n");
         return 1;
     }

     // ... proceed with verification using X509_verify_cert(ctx) ...

     return 0;
 }

HISTORY

The function was first introduced in OpenSSL 0.9.7.

CAVEATS

A verification callback should NOT return a changed value of ok because this can allow the verification to appear to succeed in an unpredictable way. This can effectively remove all security from the application because untrusted or invalid certificates may be accepted. Doing this can possibly make X509_verify_cert(3) return what appears to be a validated chain of certificates that has not been validated or even had the signatures checked.
