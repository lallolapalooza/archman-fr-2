SSL_CLEAR(3) Manuel de fonctions de bibliothèque SSL_CLEAR(3)

NOM

SSL_clear — réinitialise un objet SSL pour permettre une autre connexion

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

int
SSL_clear(SSL *ssl);

DESCRIPTION

Réinitialise ssl pour permettre une autre connexion. Tous les paramètres (méthode, chiffrements, BIO) sont conservés.

SSL_clear() est utilisé pour préparer un objet SSL pour une nouvelle connexion. Bien que tous les paramètres soient conservés, un effet secondaire est la gestion de la session SSL actuelle. Si une session est toujours ouverte, elle est considérée comme invalide et sera retirée du cache de sessions, conformément aux exigences de la RFC 2246. Une session est considérée comme ouverte si SSL_shutdown(3) n'a pas été appelée pour la connexion ou au moins SSL_set_shutdown(3) a été utilisé pour définir l'état SSL_SENT_SHUTDOWN.

Si une session a été fermée proprement, l'objet session sera conservé ainsi que tous les paramètres correspondants. Cela signifie explicitement que, par exemple, la méthode spéciale utilisée pendant la session sera conservée pour la prochaine négociation. Ainsi, si la session était une session TLSv1, un objet client SSL utilisera une méthode client TLSv1 pour la prochaine négociation et un objet serveur SSL utilisera une méthode serveur TLSv1, même si des fonctions TLS_*_method() ont été choisies au démarrage. Cela peut entraîner des échecs de connexion (voir SSL_new(3) pour une description des propriétés de la méthode).

VALEURS DE RETOUR

Les valeurs de retour suivantes peuvent survenir :

0
L'opération SSL_clear() n'a pas pu être effectuée. Vérifiez la pile d'erreurs pour connaître la raison.
1
L'opération SSL_clear() a réussi.

VOIR AUSSI

ssl(3), SSL_CTX_set_client_cert_cb(3), SSL_CTX_set_options(3), SSL_free(3), SSL_new(3), SSL_set_shutdown(3), SSL_shutdown(3)

HISTORIQUE

SSL_clear() est apparu pour la première fois dans SSLeay 0.4.5b et est disponible depuis OpenBSD 2.4.

ATTENTION

SSL_clear() réinitialise l'objet SSL pour permettre une autre connexion. L'opération de réinitialisation conserve cependant plusieurs paramètres des dernières sessions (certains de ces paramètres ont été définis automatiquement lors de la dernière négociation. Elle n'a de sens que pour une nouvelle connexion avec exactement le même pair qui partage ces paramètres, et peut échouer si ce pair modifie ses paramètres entre les connexions. Utilisez la séquence SSL_get_session(3); SSL_new(3); SSL_set_session(3); SSL_free(3) à la place pour éviter de tels échecs (ou simplement SSL_free(3); SSL_new(3) si la réutilisation de session n'est pas souhaitée).
