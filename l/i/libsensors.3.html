libsensors(3) Manuel du programmeur Linux libsensors(3)

NOM

libsensors - fonctions accessibles publiquement fournies par la bibliothèque sensors

SYNTAXE

#include <sensors/sensors.h>
/* Initialisation et nettoyage de la bibliothèque */
int sensors_init(FILE *input);
void sensors_cleanup(void);
const char *libsensors_version;
/* Gestion des noms de puces */
int sensors_parse_chip_name(const char *orig_name,
                            sensors_chip_name *res);
void sensors_free_chip_name(sensors_chip_name *chip);
int sensors_snprintf_chip_name(char *str, size_t size,
                               const sensors_chip_name *chip);
const char *sensors_get_adapter_name(const sensors_bus_id *bus);
/* Énumération des puces et des fonctionnalités */
const sensors_chip_name *
sensors_get_detected_chips(const sensors_chip_name *match,
                           int *nr);
const sensors_feature *
sensors_get_features(const sensors_chip_name *name,
                     int *nr);
const sensors_subfeature *
sensors_get_all_subfeatures(const sensors_chip_name *name,
                            const sensors_feature *feature,
                            int *nr);
const sensors_subfeature *
sensors_get_subfeature(const sensors_chip_name *name,
                       const sensors_feature *feature,
                       sensors_subfeature_type type);
/* Accès aux fonctionnalités */
char *sensors_get_label(const sensors_chip_name *name,
                        const sensors_feature *feature);
int sensors_get_value(const sensors_chip_name *name, int subfeat_nr,
                      double *value);
int sensors_set_value(const sensors_chip_name *name, int subfeat_nr,
                      double value);
int sensors_do_chip_sets(const sensors_chip_name *name);
#include <sensors/error.h>
/* Décodage des erreurs */
const char *sensors_strerror(int errnum);
/* Gestionnaires d'erreurs */
void (*sensors_parse_error) (const char *err, int lineno);
void (*sensors_parse_error_wfn) (const char *err,
                                 const char *filename, int lineno);
void (*sensors_fatal_error) (const char *proc, const char *err);

DESCRIPTION

sensors_init() charge le fichier de configuration et la liste des puces détectées. Si cette fonction retourne une valeur différente de zéro, vous avez un problème ; vous ne pouvez pas supposer que quoi que ce soit sera correctement initialisé. Si vous souhaitez recharger le fichier de configuration, ou charger un fichier de configuration différent, appelez sensors_cleanup() ci-dessous avant de rappeler sensors_init(). Cela signifie que vous ne pouvez pas charger plusieurs fichiers de configuration simultanément en appelant sensors_init() plusieurs fois.

Le format du fichier de configuration est décrit dans sensors.conf(5).

Si FILE est NULL, les fichiers de configuration par défaut sont utilisés (voir la section FICHIERS ci-dessous). La plupart des applications voudront le faire.

sensors_cleanup() nettoie tout : vous ne pouvez rien accéder après cela, jusqu'au prochain appel à sensors_init() !

libsensors_version est une chaîne représentant la version de libsensors.

sensors_parse_chip_name() analyse un nom de puce vers sa représentation interne. Retourne 0 en cas de succès, <0 en cas d'erreur. Assurez-vous d'appeler sensors_free_chip_name() lorsque vous avez terminé avec les données.

sensors_free_chip_name() libère la mémoire qui a pu être allouée pour la représentation interne d'un nom de puce. Vous devez seulement appeler cette fonction pour les noms de puces qui n'ont pas leur origine dans libsensors elle-même (c'est-à-dire les noms de puces qui ont été générés par sensors_parse_chip_name()).

sensors_snprintf_chip_name() imprime un nom de puce à partir de sa représentation interne. Notez que chip ne doit pas contenir de valeurs génériques ! Retourne le nombre de caractères imprimés en cas de succès (identique à snprintf), <0 en cas d'erreur.

sensors_get_adapter_name() retourne le nom de l'adaptateur d'une paire type de bus, numéro, telle qu'utilisée dans la structure sensors_chip_name. S'il ne peut pas être trouvé, il retourne NULL.

Les adaptateurs décrivent comment une puce de surveillance est connectée au système. Ceci est particulièrement pertinent pour les puces de capteurs I2C/SMBus (type de bus "i2c"), qui doivent être accessibles via un contrôleur I2C/SMBus. Chacun de ces contrôleurs a un numéro différent, attribué par le système lors de l'initialisation, afin qu'ils puissent être référencés individuellement.

Les capteurs intégrés au Super-I/O ou au CPU, en revanche, peuvent être accédés directement et n'utilisent techniquement aucun adaptateur. Ils n'ont qu'un type de bus mais aucun numéro de bus, et sensors_get_adapter_name() leur retournera un nom d'adaptateur générique.

sensors_get_detected_chips() retourne toutes les puces détectées qui correspondent à un nom de puce donné, une par une. Si aucun nom de puce n'est fourni, toutes les puces détectées sont retournées. Pour commencer au début de la liste, utilisez 0 pour nr ; NULL est retourné si nous sommes à la fin de la liste. N'essayez pas de modifier ces noms de puces, car ils pointent vers des structures internes !

sensors_get_features() retourne toutes les fonctionnalités principales d'une puce spécifique. nr est une variable utilisée en interne. Mettez-la à zéro pour commencer au début de la liste. Si aucune fonctionnalité supplémentaire n'est trouvée, NULL est retourné. N'essayez pas de modifier la structure retournée ; vous corrompriez les structures de données internes.

sensors_get_all_subfeatures() retourne toutes les sous-fonctionnalités d'une fonctionnalité principale donnée. nr est une variable utilisée en interne. Mettez-la à zéro pour commencer au début de la liste. Si aucune sous-fonctionnalité supplémentaire n'est trouvée, NULL est retourné. N'essayez pas de modifier la structure retournée ; vous corrompriez les structures de données internes.

sensors_get_subfeature() retourne la sous-fonctionnalité du type donné pour une fonctionnalité principale donnée, si elle existe, sinon NULL. N'essayez pas de modifier la structure retournée ; vous corrompriez les structures de données internes.

sensors_get_label() recherche l'étiquette qui appartient à cette puce. Notez que chip ne doit pas contenir de valeurs génériques ! La chaîne retournée est nouvellement allouée (libérez-la vous-même). En cas d'échec, NULL est retourné. Si aucune étiquette n'existe pour cette fonctionnalité, son nom est retourné lui-même.

sensors_get_value() lit la valeur d'une sous-fonctionnalité d'une certaine puce. Notez que chip ne doit pas contenir de valeurs génériques ! Cette fonction retournera 0 en cas de succès, et <0 en cas d'échec.

sensors_set_value() définit la valeur d'une sous-fonctionnalité d'une certaine puce. Notez que chip ne doit pas contenir de valeurs génériques ! Cette fonction retournera 0 en cas de succès, et <0 en cas d'échec.

sensors_do_chip_sets() exécute toutes les instructions set pour cette puce particulière. La puce peut contenir des génériques ! Cette fonction retournera 0 en cas de succès, et <0 en cas d'échec.

sensors_strerror() retourne un pointeur vers une chaîne qui décrit l'erreur. errnum peut être négatif (l'erreur positive correspondante est retournée). Vous ne devez pas modifier le résultat !

sensors_parse_error() et sensors_parse_error_wfn() sont des fonctions qui sont appelées lorsqu'une erreur d'analyse est détectée. Donnez-leur de nouvelles valeurs, et vos propres fonctions seront appelées à la place de celles par défaut (qui impriment sur stderr). Ces fonctions peuvent terminer le programme, mais elles affichent généralement une erreur et reviennent. La première fonction est la fonction d'origine, la seconde a été ajoutée plus tard lorsque la prise en charge de plusieurs fichiers de configuration a été ajoutée. Le code de la bibliothèque appelle maintenant uniquement la seconde fonction. Cependant, pour des raisons de compatibilité ascendante, si une application fournit une fonction de gestion personnalisée pour la première fonction mais pas pour la seconde, toutes les erreurs d'analyse seront signalées en utilisant la première fonction (c'est-à-dire que le nom du fichier n'est jamais rapporté.) Notez que filename peut être NULL (si le nom du fichier n'est pas connu) et lineno peut être 0 (si l'erreur se produit avant le début de l'analyse réelle.)

sensors_fatal_error() est une fonction qui est appelée lorsqu'une erreur immédiatement fatale (comme le manque de mémoire) est détectée. Donnez-lui une nouvelle valeur, et votre propre fonction sera appelée à la place de celle par défaut (qui imprime sur stderr et termine le programme). Ne la laissez jamais retourner !

STRUCTURES DE DONNEES

La structure sensors_chip_name contient des informations relatives à une puce spécifique.

typedef struct sensors_chip_name {
sensors_bus_id bus;
} sensors_chip_name;

Il existe d'autres membres non documentés ici, qui sont

ne destiné qu'à un usage interne de libsensors.

La structure sensors_feature contient des informations relatives à une fonctionnalité donnée d'une puce spécifique :

typedef struct sensors_feature {
const char *name;
int number;
sensors_feature_type type;
} sensors_feature;

Il existe d'autres membres non documentés ici, qui sont uniquement destinés à un usage interne de libsensors.

La structure sensors_subfeature contient des informations relatives à une sous-fonctionnalité donnée d'une fonctionnalité de puce spécifique :

typedef struct sensors_subfeature {
const char *name;
int number;
sensors_subfeature_type type;
int mapping;
unsigned int flags;
} sensors_subfeature;

Le champ flags est un champ de bits, sa valeur est une combinaison de SENSORS_MODE_R (lisible), SENSORS_MODE_W (modifiable) et SENSORS_COMPUTE_MAPPING (affecté par les règles de calcul de la fonctionnalité principale).

FICHIERS

/etc/sensors3.conf
/etc/sensors.conf

Le fichier de configuration libsensors(3) au niveau du système. /etc/sensors3.conf est essayé en premier, et s'il n'existe pas, /etc/sensors.conf est utilisé à la place.

/etc/sensors.d

Un répertoire où vous pouvez placer des fichiers de configuration libsensors supplémentaires. Les fichiers trouvés dans ce répertoire seront traités par ordre alphabétique après le fichier de configuration par défaut. Les fichiers dont le nom commence par un point sont ignorés.
