lio_listio(3) Manuel des fonctions de bibliothèque lio_listio(3)

NOM

lio_listio - initie une liste de requêtes d'E/S

BIBLIOTHÈQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <aio.h>
int lio_listio(int n;
               int mode,
               struct aiocb *restrict const aiocb_list[restrict n],
               int n, struct sigevent *restrict sevp);

DESCRIPTION

La fonction lio_listio() initie la liste des opérations d'E/S décrites par le tableau aiocb_list.

L'opération mode prend l'une des valeurs suivantes :

LIO_WAIT
L'appel se bloque jusqu'à ce que toutes les opérations soient terminées. L'argument sevp est ignoré.
LIO_NOWAIT
Les opérations d'E/S sont mises en file d'attente pour traitement et l'appel revient immédiatement. Lorsque toutes les opérations d'E/S sont terminées, une notification asynchrone se produit, comme spécifié par l'argument sevp ; voir sigevent(3type) pour les détails. Si sevp est NULL, aucune notification asynchrone ne se produit.

L'argument aiocb_list est un tableau de pointeurs vers des structures aiocb qui décrivent les opérations d'E/S. Ces opérations sont exécutées dans un ordre non spécifié. L'argument n spécifie la taille du tableau aiocb_list. Les pointeurs nuls dans aiocb_list sont ignorés.

Dans chaque bloc de contrôle de aiocb_list, le champ aio_lio_opcode spécifie l'opération d'E/S à initier, comme suit :

LIO_READ
Initie une opération de lecture. L'opération est mise en file d'attente comme pour un appel à aio_read(3) spécifiant ce bloc de contrôle.
LIO_WRITE
Initie une opération d'écriture. L'opération est mise en file d'attente comme pour un appel à aio_write(3) spécifiant ce bloc de contrôle.
LIO_NOP
Ignore ce bloc de contrôle.

Les champs restants dans chaque bloc de contrôle ont les mêmes significations que pour aio_read(3) et aio_write(3). Les champs aio_sigevent de chaque bloc de contrôle peuvent être utilisés pour spécifier les notifications pour les opérations d'E/S individuelles (voir sigevent(7)).

VALEUR DE RETOUR

Si mode est LIO_NOWAIT, lio_listio() renvoie 0 si toutes les opérations d'E/S sont mises en file d'attente avec succès. Sinon, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

Si mode est LIO_WAIT, lio_listio() renvoie 0 lorsque toutes les opérations d'E/S sont terminées avec succès. Sinon, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

Le statut de retour de lio_listio() ne fournit des informations que sur l'appel lui-même, pas sur les opérations d'E/S individuelles. Une ou plusieurs opérations d'E/S peuvent échouer, mais cela n'empêche pas les autres opérations de se terminer. Le statut des opérations d'E/S individuelles dans aiocb_list peut être déterminé en utilisant aio_error(3). Lorsqu'une opération est terminée, son statut de retour peut être obtenu en utilisant aio_return(3). Les opérations d'E/S individuelles peuvent échouer pour les raisons décrites dans aio_read(3) et aio_write(3).

ERREURS

La fonction lio_listio() peut échouer pour les raisons suivantes :

EAGAIN
Ressources insuffisantes.
EAGAIN
Le nombre d'opérations d'E/S spécifié par n dépasserait la limite AIO_MAX.
EINTR
mode était LIO_WAIT et un signal a été intercepté avant que toutes les opérations d'E/S ne soient terminées ; voir signal(7). (Cela peut même être l'un des signaux utilisés pour la notification d'achèvement des E/S asynchrones.)
EINVAL
mode est invalide, ou n dépasse la limite AIO_LISTIO_MAX.
EIO
Une ou plusieurs des opérations spécifiées par aiocb_list ont échoué. L'application peut vérifier le statut de chaque opération en utilisant aio_return(3).

Si lio_listio() échoue avec l'erreur EAGAIN, EINTR ou EIO, alors certaines des opérations dans aiocb_list peuvent avoir été initiées. Si lio_listio() échoue pour toute autre raison, alors aucune des opérations d'E/S n'a été initiée.

ATTRIBUTS

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.1. POSIX.1-2001.

NOTES

Il est conseillé de mettre à zéro les blocs de contrôle avant leur utilisation. Les blocs de contrôle ne doivent pas être modifiés tant que les opérations d'E/S sont en cours. Les zones tampons dans lesquelles la lecture est effectuée ou à partir desquelles l'écriture est effectuée ne doivent pas être accédées pendant les opérations, sous peine de résultats indéfinis. Les zones mémoire impliquées doivent rester valides.

Les opérations d'E/S simultanées spécifiant la même structure aiocb produisent des résultats indéfinis.
