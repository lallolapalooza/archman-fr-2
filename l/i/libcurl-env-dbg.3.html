NOM

libcurl-env-dbg - variables d'environnement comprises par libcurl DEBUGBUILD

DESCRIPTION

Il s'agit d'un ensemble de variables reconnues et utilisées uniquement si libcurl a été compilé avec le débogage activé ("debug enabled"), ce qui ne devrait jamais être le cas pour une bibliothèque utilisée en production. Ces variables sont destinées à un usage interne uniquement, sont sujettes à modification et ont de nombreux effets sur le comportement de libcurl. Référez-vous au code source pour déterminer comment elles sont exactement utilisées.

CURL_ALTSVC_HTTP
Contourne la restriction du protocole HTTPS AltSvc si cette variable existe.
CURL_DBG_SOCK_RBLOCK
Le pourcentage d'appels recv() qui devraient répondre par un EAGAIN de manière aléatoire. Pour les sockets TCP/UNIX.
CURL_DBG_SOCK_RMAX
La quantité maximale de données qui doit être reçue du réseau en un seul appel recv(). Pour les sockets TCP/UNIX. Ceci est appliqué à chaque recv.

Exemple : CURL_DBG_SOCK_RMAX=400 signifie que la taille du tampon de réception est limitée à un maximum de 400 octets.

CURL_DBG_SOCK_WBLOCK
Le pourcentage d'appels send() qui devraient répondre par un EAGAIN de manière aléatoire. Pour les sockets TCP/UNIX.
CURL_DBG_SOCK_WPARTIAL
Le pourcentage de données qui doit être écrit sur le réseau. Pour les sockets TCP/UNIX. Ceci est appliqué à chaque send.

Exemple : CURL_DBG_SOCK_WPARTIAL=80 signifie qu'un send avec 1000 octets n'en enverrait que 800.

CURL_DBG_QUIC_WBLOCK
Le pourcentage d'appels send() qui devraient répondre par EAGAIN de manière aléatoire. Uniquement pour QUIC.
CURL_DEBUG
Le comportement de traçage des journaux comme alternative à l'appel de curl_global_trace(3).

Exemple : CURL_DEBUG=http/2 signifie tracer les détails de la gestion HTTP/2.

Dans l'outil en ligne de commande curl, compilé avec --enable-debug, cette variable d'environnement s'ajoute à des arguments comme --verbose, -vvv. Au moins un -v est nécessaire pour que l'exécution émette des informations de traçage, mais lorsqu'elle le fait, le contenu de CURL_DEBUG est ajouté et peut remplacer les options existantes.

Exemple : CURL_DEBUG=tcp,-http/2 curl -vv url signifie tracer les détails du protocole, déclenchés par -vv, ajoute le traçage TCP en plus et supprime le traçage HTTP/2.

CURL_DEBUG_SIZE
Falsifie la taille renvoyée par CURLINFO_HEADER_SIZE et CURLINFO_REQUEST_SIZE.
CURL_DNS_SERVER
Lorsque compilé avec c-ares pour la résolution de noms, la définition de cette variable d'environnement sur [IP:port] fait que libcurl utilise ce serveur DNS au lieu de celui par défaut du système. Ceci est utilisé par la suite de tests curl.
CURL_FTP_PWD_STOP
Lorsque défini, le premier transfert - lors de l'utilisation de ftp: - revient avant d'envoyer la commande PWD et arrête toute progression ultérieure. Ceci est utilisé pour tester un cas limite.
CURL_GETHOSTNAME
Falsifie le nom d'hôte non qualifié de la machine locale pour NTLM et SMTP.
CURL_HSTS_HTTP
Contourne la restriction du protocole HTTPS HSTS si cette variable existe.
CURL_FORCETIME
Une heure de 0 est utilisée pour les signatures AWS et NTLM si cette variable existe.
CURL_ENTROPY
Une valeur fixe falsifiée à utiliser à la place d'un nombre aléatoire afin que les fonctions de libcurl qui obtiennent autrement des sorties aléatoires puissent être testées pour ce qu'elles génèrent.
CURL_SMALLREQSEND
Une taille alternative de données HTTP à envoyer à la fois, uniquement si elle est inférieure à la taille actuelle.
CURL_SMALLSENDS
Une taille alternative de données de socket à envoyer à la fois, uniquement si elle est inférieure à la taille actuelle.
CURL_TIME
Falsifie l'horodatage Unix à utiliser pour AltSvc, HSTS et les variables CURLINFO liées au temps.

Cette variable peut également être utilisée pour falsifier les données renvoyées par certaines variables CURLINFO qui ne sont pas liées au temps (telles que CURLINFO_LOCAL_PORT), et dans ce cas, la valeur n'est pas un horodatage.

CURL_TRACE
Le traçage LDAP est activé si cette variable existe et sa valeur est de 1 ou plus.

Le traçage OpenLDAP est séparé. Référez-vous à CURL_OPENLDAP_TRACE.

CURL_OPENLDAP_TRACE
Le traçage OpenLDAP est activé si cette variable existe et sa valeur est de 1 ou plus. Il existe un certain nombre de niveaux de débogage, référez-vous aux commentaires dans openldap.c.
CURL_WS_CHUNK_SIZE
Utilisé pour influencer la taille des blocs de tampon utilisés pour le codage et le décodage WebSocket.
CURL_WS_CHUNK_EAGAIN
Utilisé pour simuler des envois bloquants après cette taille de bloc pour les connexions WebSocket.
CURL_WS_FORCE_ZERO_MASK
Utilisé pour définir le masque de tous les trames WebSocket envoyées à zéro. La valeur de la variable d'environnement n'a pas d'importance.
CURL_FORBID_REUSE
Utilisé pour définir le drapeau CURLOPT_FORBID_REUSE sur chaque transfert initié par l'outil en ligne de commande curl. La valeur de la variable d'environnement n'a pas d'importance.
CURL_GRACEFUL_SHUTDOWN
Effectue une fermeture bloquante et gracieuse de toutes les connexions restantes lorsqu'un handle multi est détruit. Ceci est implicitement déclenché pour les handles faciles qui sont exécutés via easy_perform. La valeur de la variable d'environnement donne le délai d'attente de fermeture en millisecondes.
CURL_H2_STREAM_WIN_MAX
Défini sur un nombre positif de 32 bits pour remplacer la fenêtre de flux HTTP/2 par défaut de 10 Mo. Utilisé dans les tests pour vérifier la gestion correcte des mises à jour de fenêtre.
