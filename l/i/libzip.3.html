LIBZIP(3) Manuel des fonctions de bibliothèque LIBZIP(3)

NOM

libzip — bibliothèque pour la manipulation des archives zip

BIBLIOTHÈQUE

libzip (-lzip)

SYNTAXE

#include <zip.h>

DESCRIPTION

libzip est une bibliothèque pour lire, créer et modifier des archives zip.

Les principaux critères de conception pour libzip étaient :

  • Maintenir une API stable sans rompre la compatibilité ascendante.
  • Ne pas créer de fichiers corrompus, même en cas d'erreurs.
  • Ne pas supprimer de données.
  • Être efficace.

Pour cette raison, lors de la modification d'archives zip, libzip écrit dans un fichier temporaire et remplace l'archive zip d'origine de manière atomique.

NOTES GÉNÉRALES

Lors de l'ajout de fichiers à une archive, les données du fichier ne sont lues que lorsque la nouvelle archive est écrite. Par conséquent, tous les fichiers ajoutés doivent rester valides jusqu'à ce que l'archive soit fermée avec zip_close(3) ou zip_discard(3).

Sauf indication contraire explicite, les pointeurs NULL ne doivent pas être passés en argument aux fonctions.

TYPES DE DONNÉES

Ces types de données correspondent aux concepts centraux de libzip. La plupart d'entre eux sont privés, ce qui signifie que vous ne pouvez pas les allouer ni accéder directement à leurs membres. Cela permet d'étendre les structures à l'avenir sans rompre la compatibilité.

zip_t

Ce type représente une archive ouverte. Voir zip(5).

zip_file_t

Ce type représente un fichier d'une archive ouvert en lecture. Voir zip_file(5).

zip_source_t

Ce type représente une source (ou destination) de données. Il est utilisé dans libzip pour fournir des données lors de l'ajout ou du remplacement de fichiers, pour accéder aux données d'un fichier dans une archive, et pour les données de l'archive dans son ensemble. Voir zip_source(5).

zip_error_t

Ce type représente des informations sur une erreur. Son type peut être vérifié par rapport à des constantes prédéfinies et il peut être converti en une chaîne de caractères lisible par l'homme. Voir zip_error(5).

NOMS DE FICHIERS

Encodage

Les noms des fichiers sur le système de fichiers hôte sont attendus en encodage UTF-8. Sous Windows, des variantes pour ASCII et UTF-16 sont également disponibles.

Les noms des fichiers dans les archives sont par défaut attendus en encodage UTF-8. D'autres encodages peuvent être demandés en utilisant les indicateurs ZIP_FL_ENC_CP437 et ZIP_FL_ENC_RAW.

Pour plus de détails, voir les pages de manuel pertinentes.

Séparateur de répertoire

Le format zip exige l'utilisation de la barre oblique ( ‘/’) comme séparateur de répertoire. Comme la barre oblique inverse (‘\’) peut faire partie d'un nom de fichier valide sur les systèmes Unix, libzip ne les convertit pas automatiquement, même sous Windows. Il incombe au programmeur de s'assurer que tous les séparateurs de répertoires sont passés sous forme de barres obliques à libzip.

SÉCURITÉ DES THREADS

En général, différentes archives zip ouvertes par libzip sont indépendantes les unes des autres et peuvent être utilisées par des threads s'exécutant en parallèle sans verrouillage. Si vous souhaitez utiliser une archive à partir de plusieurs threads, vous devez synchroniser vous-même l'accès à celle-ci. Si vous utilisez une archive comme source pour zip_file_add(3) ou zip_file_replace(3), l'accès à l'archive cible doit également être synchronisé avec l'accès à l'archive source.
