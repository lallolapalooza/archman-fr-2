LIBBLKID(3) Manuel du programmeur LIBBLKID(3)

NOM

libblkid - bibliothèque d'identification de périphériques blocs

SYNTAXE

#include <blkid.h>

cc fichier.c -lblkid

DESCRIPTION

La bibliothèque libblkid est utilisée pour identifier les périphériques blocs (disques) quant à leur contenu (par exemple, type de système de fichiers) ainsi que pour extraire des informations supplémentaires telles que les étiquettes/noms de volume de système de fichiers, les identifiants uniques/numéros de série. Une utilisation courante consiste à permettre l'utilisation des balises LABEL= et UUID= au lieu de coder en dur des noms de périphériques blocs spécifiques dans les fichiers de configuration. Voir la liste de toutes les balises disponibles dans la section TAGS.

La partie bas niveau de la bibliothèque permet également l'extraction d'informations sur les partitions et la topologie des périphériques blocs.

La partie haut niveau de la bibliothèque conserve les informations sur les périphériques blocs dans un fichier cache et vérifie qu'elles sont toujours valides avant d'être retournées à l'utilisateur (si l'utilisateur a la permission de lecture sur le périphérique bloc brut, sinon non). Le fichier cache permet également aux utilisateurs non privilégiés (normalement quiconque autre que root, ou ceux qui ne sont pas dans le groupe "disk") de localiser les périphériques par étiquette/identifiant. L'emplacement standard du fichier cache peut être remplacé par la variable d'environnement BLKID_FILE.

Dans les situations où l'on obtient des informations sur un seul périphérique connu, cela n'affecte pas les performances que le cache soit utilisé ou non (sauf si vous ne pouvez pas lire le périphérique bloc directement).

La partie haut niveau de la bibliothèque prend en charge deux méthodes pour déterminer LABEL/UUID. Elle lit les informations directement à partir d'un périphérique bloc ou lit les informations à partir des liens symboliques udev /dev/disk/by-*. La méthode udev est préférée par défaut.

Si vous traitez plusieurs périphériques, l'utilisation du cache est fortement recommandée (même s'il est vide), car les périphériques seront balayés au plus une fois et le cache sur disque sera mis à jour si possible.

Dans certains cas (noyaux modulaires), les périphériques blocs ne sont même pas visibles jusqu'à ce qu'ils soient accédés pour la première fois, il est donc crucial qu'il existe un moyen de localiser ces périphériques sans énumérer uniquement les périphériques visibles. L'utilisation du fichier cache est donc requise dans cette situation.

FICHIER DE CONFIGURATION

L'emplacement standard du fichier de configuration /etc/blkid.conf peut être remplacé par la variable d'environnement BLKID_CONF. Pour plus de détails sur le fichier de configuration, consultez la page de manuel de blkid(8).

TAGS

Toutes les balises disponibles sont listées ci-dessous. Toutes les balises ne sont pas prises en charge pour tous les systèmes de fichiers. Pour activer une balise, définissez l'un des indicateurs suivants avec blkid_probe_set_superblocks_flags():

BLKID_SUBLKS_TYPE

•TYPE - type de système de fichiers

BLKID_SUBLKS_SECTYPE

•SEC_TYPE - type de système de fichiers secondaire

BLKID_SUBLKS_LABEL

•LABEL - étiquette du système de fichiers

BLKID_SUBLKS_LABELRAW

•LABEL_RAW - étiquette brute du superbloc du FS

BLKID_SUBLKS_UUID

•UUID - UUID du système de fichiers (en minuscules)
•UUID_SUB - UUID du membre du pool ou UUID de l'élément de périphérique, etc. (par exemple, zfs, btrfs, ...)
•LOGUUID - UUID du journal externe (par exemple, xfs)

BLKID_SUBLKS_UUIDRAW

•UUID_RAW - UUID brut du superbloc du FS

BLKID_SUBLKS_USAGE

•USAGE - chaîne d'utilisation : "raid", "filesystem", etc.

BLKID_SUBLKS_VERSION

•VERSION - version du système de fichiers

BLKID_SUBLKS_MAGIC

•SBMAGIC - chaîne magique du super bloc
•SBMAGIC_OFFSET - décalage de SBMAGIC

BLKID_SUBLKS_FSINFO

•FSSIZE - taille du système de fichiers. Notez que pour XFS, cela renverra la même valeur que lsblk (sans les métadonnées XFS), mais pour ext4, cela renverra la taille avec les métadonnées et pour BTRFS, cela ne comptera pas la surcharge de la configuration RAID (données redondantes).
•FSLASTBLOCK - dernier fsblock/nombre total de fsblocks
•FSBLOCKSIZE - taille de bloc du système de fichiers

Les balises suivantes sont toujours activées

•BLOCK_SIZE - taille minimale de bloc accessible par le système de fichiers
•MOUNT - nom de montage cluster (ocfs uniquement)
•EXT_JOURNAL - UUID du journal externe
•SYSTEM_ID - identifiant système ISO9660
•VOLUME_SET_ID - identifiant de jeu de volumes ISO9660
•DATA_PREPARER_ID - identifiant de données ISO9660
•PUBLISHER_ID - identifiant de l'éditeur ISO9660
•APPLICATION_ID - identifiant d'application ISO9660
•BOOT_SYSTEM_ID - identifiant du système de démarrage ISO9660

libblkid(3)

libblkid — bibliothèque pour lister les disques et leur contenu

DESCRIPTION

La bibliothèque libblkid fournit des fonctions pour identifier et manipuler les appareils de blocs et leurs partitions. Elle est capable de détecter et d'extraire des informations sur les systèmes de fichiers, les partitions, les volumes logiques (LVM), les RAID logiciels, etc.

SYNTAXE

#include <blkid.h>

OPTIONS

La bibliothèque libblkid expose une API pour interagir avec les appareils de blocs. Les fonctions clés incluent :

  • blkid_get_all() : Obtient toutes les informations sur les appareils de blocs.
  • blkid_get_single() : Obtient les informations sur un appareil de bloc spécifique.
  • blkid_probe_all() : Sonde tous les appareils de blocs disponibles.
  • blkid_probe_single() : Sonde un appareil de bloc spécifique.
  • blkid_resolve_spec() : Résout une spécification d'appareil en un nom de fichier d'appareil.
  • blkid_get_devno() : Obtient le numéro de périphérique pour un nom de fichier d'appareil.
  • blkid_devno_to_partitions() : Obtient les partitions pour un numéro de périphérique donné.

EXEMPLES

Voici un exemple simple d'utilisation de libblkid pour obtenir le type de système de fichiers d'un appareil :

#include <stdio.h>
#include <blkid/blkid.h>

int main() {
    blkid_probe pr = NULL;
    const char *fstype = NULL;

    pr = blkid_new_probe();
    if (!pr) {
        perror("blkid_new_probe");
        return 1;
    }

    // Sonder un appareil (par exemple, /dev/sda1)
    blkid_probe_device(pr, "/dev/sda1", PROBE_FREE);

    fstype = blkid_get_tag(pr, "TYPE", NULL);
    if (fstype) {
        printf("Le type de système de fichiers est : %s\n", fstype);
    } else {
        printf("Impossible de déterminer le type de système de fichiers.\n");
    }

    blkid_free_probe(pr);
    return 0;
}

VALEUR DE RETOUR

Les fonctions de libblkid retournent généralement 0 en cas de succès et une valeur non nulle en cas d'erreur. Les chaînes de caractères retournées par les fonctions de récupération d'informations sont des pointeurs vers des données internes et ne doivent pas être modifiées ni libérées par l'appelant.

FICHIERS

  • /dev/sd* : Appareils de blocs typiques.
  • /etc/blkid.conf : Fichier de configuration optionnel pour libblkid.

FICHIER DE CONFIGURATION

Le fichier /etc/blkid.conf peut être utilisé pour configurer certains aspects de libblkid, tels que les chemins de recherche pour les informations sur les partitions ou les types de systèmes de fichiers.

TAGS

libblkid utilise le concept de "tags" pour stocker les métadonnées associées aux appareils. Les tags courants incluent "TYPE" (type de système de fichiers), "UUID", "LABEL", etc.
