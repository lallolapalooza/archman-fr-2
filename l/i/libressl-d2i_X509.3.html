DESCRIPTION

Ces fonctions décodent et encodent les certificats X.509 et certaines de leurs sous-structures. Pour des détails sur la sémantique, les exemples, les avertissements et les bugs, voir ASN1_item_d2i(3).

d2i_X509() et i2d_X509() décodent et encodent une structure Certificate ASN.1 définie dans la RFC 5280 section 4.1.

d2i_X509_bio(), d2i_X509_fp(), i2d_X509_bio(), et i2d_X509_fp() sont similaires sauf qu'elles décodent ou encodent en utilisant un pointeur BIO ou FILE.

d2i_X509_AUX() est similaire à d2i_X509(), mais l'entrée est supposée consister en un certificat X.509 suivi d'informations de confiance auxiliaires. Ceci est utilisé par les routines PEM pour lire les objets CERTIFICAT DE CONFIANCE. Cette fonction ne doit pas être appelée sur des entrées non fiables.

i2d_X509_AUX() est similaire à i2d_X509(), mais la sortie encodée contient à la fois le certificat et toute information de confiance auxiliaire. Ceci est utilisé par les routines PEM pour écrire les objets CERTIFICAT DE CONFIANCE. Notez qu'il s'agit d'un format de données non standard spécifique à OpenSSL.

d2i_X509_CERT_AUX() et i2d_X509_CERT_AUX() décodent et encodent des données auxiliaires optionnelles non standard ajoutées à un certificat, par exemple des noms d'alias conviviaux et des données de confiance.

d2i_X509_CINF() et i2d_X509_CINF() décodent et encodent une structure TBSCertificate ASN.1 définie dans la RFC 5280 section 4.1.

d2i_X509_VAL() et i2d_X509_VAL() décodent et encodent une structure Validity ASN.1 définie dans la RFC 5280 section 4.1.

i2d_re_X509_tbs() est similaire à i2d_X509(), sauf qu'elle encode uniquement la partie TBSCertificate du certificat. i2d_re_X509_CRL_tbs() et i2d_re_X509_REQ_tbs() sont analogues pour les listes de révocation de certificats (CRL) et les demandes de certificats, respectivement. Le "re" dans i2d_re_X509_tbs() signifie "ré-encoder" et garantit qu'un nouvel encodage est généré au cas où l'objet aurait été modifié après sa création.

L'encodage de la partie TBSCertificate d'un certificat est mis en cache dans la structure X509 en interne pour améliorer les performances d'encodage et pour garantir que les signatures de certificat sont correctement vérifiées dans certains certificats avec des encodages incorrects (non-DER).

Si, après modification, l'objet X509 est re-signé avec X509_sign(3), l'encodage est automatiquement renouvelé. Sinon, l'encodage de la partie TBSCertificate de la X509 peut être manuellement renouvelé en appelant i2d_re_X509_tbs().

VALEURS DE RETOUR

d2i_X509(), d2i_X509_bio(), d2i_X509_fp(), et d2i_X509_AUX() retournent une structure X509 valide ou NULL en cas d'erreur.

DESCRIPTION

These functions convert between the ASN.1 DER encoding of X.509 certificates and their internal C representations.

The d2i_X509(), d2i_X509_AUX(), d2i_X509_CERT_AUX(), d2i_X509_CINF(), d2i_X509_VAL(), d2i_X509_bio(), and d2i_X509_fp() functions decode an ASN.1 DER encoded X.509 certificate structure from the memory buffer pointed to by in with length len, or from a BIO or FILE stream, into an internal structure.

If the argument x is not NULL, the decoded structure is assigned to *x. Otherwise, a new structure is allocated.

The input buffer in is advanced to point to the data immediately following the decoded structure. The length len is decremented by the number of bytes consumed.

The i2d_X509(), i2d_X509_AUX(), i2d_X509_CERT_AUX(), i2d_X509_CINF(), i2d_X509_VAL(), i2d_X509_bio(), and i2d_X509_fp() functions encode the internal structure x into ASN.1 DER format. If the argument out is not NULL, a buffer is allocated, the encoded data is written into it, and *out is set to point to this buffer. The caller is responsible for freeing this buffer.

If out is NULL, the functions calculate the required buffer size and return it. The caller must then allocate a buffer of that size, and call the function again with out set to point to the allocated buffer.

i2d_re_X509_tbs(), i2d_re_X509_CRL_tbs(), and i2d_re_X509_REQ_tbs() re-encode the TBS (To Be Signed) part of a certificate, CRL, or request, respectively. This is useful when only the TBS part needs to be re-encoded, for example, when updating signatures.

RETURN VALUES

d2i_X509(), d2i_X509_AUX(), d2i_X509_CERT_AUX(), d2i_X509_CINF(), and d2i_X509_VAL() return an X509_CERT_AUX, X509_CINF, or X509_VAL object, respectively, or NULL if an error occurs.

i2d_X509(), i2d_X509_AUX(), i2d_X509_CERT_AUX(), i2d_X509_CINF(), and i2d_X509_VAL() return the number of bytes successfully encoded or a negative value if an error occurs.

i2d_X509_bio() and i2d_X509_fp() return 1 for success or 0 if an error occurs.

i2d_re_X509_tbs(), i2d_re_X509_CRL_tbs(), and i2d_re_X509_REQ_tbs() return the number of bytes successfully encoded or 0 if an error occurs.

For all functions, the error code can be obtained by ERR_get_error(3).

HISTORY

d2i_X509(), i2d_X509(), d2i_X509_fp(), i2d_X509_fp(), d2i_X509_CINF(), i2d_X509_CINF(), d2i_X509_VAL(), and i2d_X509_VAL() first appeared in SSLeay 0.5.1. d2i_X509_bio() and i2d_X509_bio() first appeared in SSLeay 0.6.0. These functions have been available since OpenBSD 2.4.
