libvirt-guests(8) Support de la virtualisation libvirt-guests(8)

Nom

libvirt-guests - suspend/resume les invités libvirt en cours d'exécution

Syntaxe

libvirt-guests COMMANDE

Description

libvirt-guests est un service qui peut être utilisé pour coordonner les actions de cycle de vie des invités et de l'hôte. Par défaut, libvirt-guests suspend les invités en cours d'exécution lorsque l'hôte s'arrête, et les restaure à leur état d'avant l'arrêt lors du redémarrage de l'hôte.

libvirt-guests est généralement contrôlé par systemd. Lorsque libvirt-guests.service est activé, systemd appelle libvirt-guests avec la COMMANDE start lors du démarrage de l'hôte. Inversement, systemd appelle libvirt-guests avec la COMMANDE stop lors de l'arrêt de l'hôte.

libvirt-guests peut être utilisé directement. En plus des COMMANDES start et stop, il prend également en charge les commandes status, restart, condrestart, try-restart, reload, force-reload, gueststatus et shutdown.

Fichiers

libvirt-guests définit plusieurs variables pour contrôler le comportement du service. La valeur par défaut de ces variables peut être remplacée dans :

•
/etc/conf.d/libvirt-guests

Les variables suivantes sont prises en charge :

  • URIS=default

    URIs à vérifier pour les invités en cours d'exécution. Exemple : URIS='default xen:///system xen+tcp://host/system lxc:///system'

  • ON_BOOT=start

    Action effectuée au démarrage de l'hôte

  • start

    Tous les invités qui étaient en cours d'exécution à l'arrêt sont démarrés au démarrage, quelles que soient leurs configurations de démarrage automatique.

  • ignore

    libvirt-guests ne démarrera aucun invité au démarrage, cependant, les invités marqués comme démarrage automatique seront toujours démarrés automatiquement par libvirtd.

  • START_DELAY=0

    Nombre de secondes à attendre entre chaque démarrage d'invité. Réglez sur 0 pour permettre un démarrage parallèle.

  • ON_SHUTDOWN=suspend

    Action effectuée à l'arrêt de l'hôte

  • suspend

    Tous les invités en cours d'exécution sont suspendus en utilisant virsh managedsave

  • shutdown

    Il est demandé à tous les invités en cours d'exécution de s'arrêter. Soyez prudent avec ce réglage car il n'y a aucun moyen de distinguer un invité bloqué ou ignorant les demandes d'arrêt d'un invité qui a simplement besoin de temps pour s'arrêter. Lorsque vous définissez ON_SHUTDOWN=shutdown, vous devez également définir SHUTDOWN_TIMEOUT à une valeur adaptée à vos invités.

  • PARALLEL_SHUTDOWN=0

    Nombre d'invités qui seront arrêtés simultanément, prenant effet lorsque "ON_SHUTDOWN" est réglé sur "shutdown". Si réglé sur 0, les invités seront arrêtés un par un. Le nombre d'invités en cours d'arrêt à tout moment ne dépassera pas le nombre défini dans cette variable.

  • SHUTDOWN_TIMEOUT=300

    Nombre de secondes que nous sommes prêts à attendre pour qu'un invité s'arrête. Si l'arrêt parallèle est activé, ce délai s'applique comme un délai pour arrêter tous les invités sur une URI donnée définie dans la variable URIS. Si ce délai est de 0, alors il n'y a pas de délai d'attente (à utiliser avec prudence, car les invités pourraient ne pas répondre à une demande d'arrêt). La valeur par défaut est de 300 secondes (5 minutes).

  • BYPASS_CACHE=0

    Si non nul, essayer de contourner le cache du système de fichiers lors de la sauvegarde et de la restauration des invités, même si cela peut entraîner des performances plus lentes pour certains systèmes de fichiers.

  • SYNC_TIME=0

    Si non nul, essayer de synchroniser l'heure de l'invité lors de la reprise du domaine. Sachez que cela nécessite un agent invité prenant en charge la synchronisation de l'heure en cours d'exécution dans l'invité. Par défaut, cette fonctionnalité est désactivée.

  • PERSISTENT_ONLY=default

    Définit à quel type de machine virtuelle invitée l'action ON_SHUTDOWN s'applique

  • default

    Ceci implémente le comportement par défaut déjà existant. Si l'action ON_SHUTDOWN est shutdown, les machines virtuelles invitées transitoires et persistantes sont invitées à s'arrêter. Si l'action ON_SHUTDOWN est suspend, seules les machines virtuelles invitées persistantes sont invitées à se suspendre.

  • true

    L'action ON_SHUTDOWN est exécutée uniquement sur les machines virtuelles invitées persistantes. Les machines virtuelles invitées transitoires ne sont pas affectées.

  • false

    L'action ON_SHUTDOWN est exécutée sur les machines virtuelles invitées persistantes et transitoires.
