libressl-SSL_CTX_set_session_cache_mode(3)

SSL_CTX_SET_SESSION_CACHE_MODE(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_SESSION_CACHE_MODE(3)

NOM

SSL_CTX_set_session_cache_mode, SSL_CTX_get_session_cache_mode — activer/désactiver la mise en cache des sessions

SYNOPSIS

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_session_cache_mode(SSL_CTX ctx, long mode);

long
SSL_CTX_get_session_cache_mode(SSL_CTX ctx);

DESCRIPTION

SSL_CTX_set_session_cache_mode() active/désactive la mise en cache des sessions en définissant le mode opérationnel pour ctx à mode.

SSL_CTX_get_session_cache_mode() retourne le mode de cache actuellement utilisé.

La bibliothèque OpenSSL peut stocker/récupérer des sessions SSL/TLS pour une réutilisation ultérieure. Les sessions peuvent être conservées en mémoire pour chaque ctx. S'il y a plus d'un objet SSL_CTX géré, les sessions sont uniques pour chaque objet SSL_CTX.

Afin de réutiliser une session, un client doit envoyer l'identifiant de la session au serveur. Il ne peut envoyer qu'un seul identifiant. Le serveur accepte alors soit de réutiliser la session, soit il démarre une négociation complète (pour créer une nouvelle session).

Un serveur recherchera la session dans son stockage de sessions interne. Si la session n'est pas trouvée dans le stockage interne ou si les recherches pour le stockage interne ont été désactivées (SSL_SESS_CACHE_NO_INTERNAL_LOOKUP), le serveur essaiera le stockage externe s'il est disponible.

Comme un client peut tenter de réutiliser une session destinée à être utilisée dans un contexte différent, le contexte de l'identifiant de session doit être défini par le serveur (voir SSL_CTX_set_session_id_context(3)).

Les modes de cache de session et les modificateurs suivants sont disponibles :

SSL_SESS_CACHE_OFF
Aucune mise en cache de session pour le client ou le serveur n'a lieu.
SSL_SESS_CACHE_CLIENT
Les sessions client sont ajoutées au cache de sessions. Comme il n'existe pas de moyen fiable pour la bibliothèque OpenSSL de savoir si une session doit être réutilisée ou quelle session choisir (en raison de la couche BIO abstraite, le moteur SSL n'a pas de détails sur la connexion), l'application doit sélectionner la session à réutiliser en utilisant la fonction SSL_set_session(3). Cette option n'est pas activée par défaut.
SSL_SESS_CACHE_SERVER
Les sessions serveur sont ajoutées au cache de sessions. Lorsqu'un client propose une session à réutiliser, le serveur recherche la session correspondante dans (d'abord) le cache de sessions interne (sauf si SSL_SESS_CACHE_NO_INTERNAL_LOOKUP est défini), puis (ensuite) dans le cache externe s'il est disponible. Si la session est trouvée, le serveur tentera de la réutiliser. C'est le comportement par défaut.
SSL_SESS_CACHE_BOTH
Active simultanément SSL_SESS_CACHE_CLIENT et SSL_SESS_CACHE_SERVER.
SSL_SESS_CACHE_NO_AUTO_CLEAR
Normalement, le cache de sessions est vérifié pour les sessions expirées toutes les 255 connexions en utilisant la fonction SSL_CTX_flush_sessions(3). Comme cela peut entraîner un délai incontrôlable, le vidage automatique peut être désactivé et SSL_CTX_flush_sessions(3) peut être appelé explicitement par l'application.
SSL_SESS_CACHE_NO_INTERNAL_LOOKUP
En définissant ce drapeau, les opérations de reprise de session dans un serveur SSL/TLS ne rechercheront pas automatiquement les sessions dans le cache interne, même si les sessions y sont stockées automatiquement. Si des rappels de mise en cache de sessions externes sont utilisés, ce drapeau garantit que toutes les recherches sont dirigées vers le cache externe. Comme la recherche automatique ne s'applique qu'aux serveurs SSL/TLS, le drapeau n'a aucun effet sur les clients.
SSL_SESS_CACHE_NO_INTERNAL_STORE
Selon la présence de SSL_SESS_CACHE_CLIENT et/ou SSL_SESS_CACHE_SERVER, les sessions négociées lors d'une négociation SSL/TLS peuvent être mises en cache pour une réutilisation éventuelle. Normalement, une nouvelle session est ajoutée au cache interne ainsi qu'à toute mise en cache de session externe (rappel) configurée pour le SSL_CTX. Ce drapeau empêchera les sessions d'être stockées dans le cache interne (bien que l'application puisse les ajouter manuellement en utilisant SSL_CTX_add_session(3)). Note : dans tous les serveurs SSL/TLS où la mise en cache externe est configurée, toute recherche de session réussie dans le cache externe (par exemple, pour des demandes de reprise de session) serait normalement copiée dans le cache local avant que le traitement ne continue – ce drapeau empêche également ces ajouts au cache interne.
SSL_SESS_CACHE_NO_INTERNAL
Active simultanément SSL_SESS_CACHE_NO_INTERNAL_LOOKUP et SSL_SESS_CACHE_NO_INTERNAL_STORE.

Le mode par défaut est SSL_SESS_CACHE_SERVER.

VALEURS DE RETOUR

SSL_CTX_set_session_cache_mode() retourne le mode de cache précédemment défini.

SSL_CTX_get_session_cache_mode() retourne le mode de cache actuellement défini.

HISTORIQUE

SSL_CTX_set_session_cache_mode() et SSL_CTX_get_session_cache_mode() sont apparus pour la première fois dans SSLeay 0.6.1 et sont disponibles depuis OpenBSD 2.4.

SSL_SESS_CACHE_NO_INTERNAL_STORE et SSL_SESS_CACHE_NO_INTERNAL ont été introduits dans OpenSSL 0.9.6h.
