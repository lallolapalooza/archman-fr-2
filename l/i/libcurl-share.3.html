NOM

libcurl-share - comment utiliser l'interface de partage

DESCRIPTION

Ceci est un aperçu de l'utilisation de l'interface de partage libcurl dans vos programmes C. Il existe des pages de manuel spécifiques pour chaque fonction mentionnée ici.

Toutes les fonctions de l'interface de partage sont préfixées par curl_share.

OBJECTIFS

L'interface de partage a été ajoutée pour permettre le partage de données entre les handles curl.

UN ENSEMBLE DE DONNEES - PLUSIEURS TRANSFERTS

Vous pouvez avoir plusieurs handles easy partageant des données entre eux. Faites-les mettre à jour et utiliser la même base de données de cookies, cache DNS, cache de sessions TLS et/ou cache de connexions. De cette façon, chaque transfert individuel profite des mises à jour de données effectuées par les autres transferts.

OBJET DE PARTAGE

Vous créez un objet de partage avec curl_share_init(3). Cela renvoie un handle pour un objet nouvellement créé.

Vous indiquez à l'objet de partage quelles données vous souhaitez qu'il partage en utilisant curl_share_setopt(3).

Étant donné que vous pouvez utiliser ce partage à partir de plusieurs threads, et que libcurl n'a pas de synchronisation interne des threads, vous devez fournir des callbacks mutex si vous utilisez ceci en mode multithread. Vous définissez les fonctions de verrouillage et de déverrouillage avec curl_share_setopt(3) également.

Ensuite, vous faites en sorte qu'un handle easy utilise ce partage, vous définissez l'option CURLOPT_SHARE(3) avec curl_easy_setopt(3), et vous lui passez le handle de partage. Vous pouvez faire en sorte qu'un nombre quelconque de handles easy partagent le même handle de partage.

Pour qu'un handle easy arrête d'utiliser ce partage particulier, vous définissez CURLOPT_SHARE(3) à NULL pour ce handle easy. Pour qu'un handle arrête de partager des données particulières, vous pouvez utiliser CURLSHOPT_UNSHARE(3).

Lorsque vous avez fini d'utiliser le partage, assurez-vous qu'aucun handle easy ne l'utilise encore, et appelez curl_share_cleanup(3) sur le handle.

VOIR AUSSI

curl_share_cleanup(3), curl_share_init(3), curl_share_setopt(3), libcurl-easy(3), libcurl-errors(3), libcurl-multi(3)
