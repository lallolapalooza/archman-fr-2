NOM

freeipmi_interpret_sensor.conf - spécifier les règles d'interprétation des capteurs

DESCRIPTION

Le fichier /etc/freeipmi//freeipmi_interpret_sensor.conf définit comment les capteurs IPMI doivent être interprétés. Les capteurs basés sur IPMI spécifient un certain nombre d'états/seuils lorsqu'ils sont lus. Sur la base de ces états/seuils, des bibliothèques et des outils tels que libfreeipmi(3), libipmimonitoring(3) et ipmi-sensors(8) peuvent indiquer si la lecture d'un capteur est "bonne" ou "mauvaise" via un rapport d'état NOMINAL, D'AVERTISSEMENT ou CRITIQUE.

Chacun des états listés ci-dessous est (espérons-le) suffisamment descriptif pour décrire les conditions d'état qui peuvent être activées/désactivées pour chaque type de capteur. Pour plus d'informations détaillées sur chacun des états individuels listés ci-dessous, veuillez consulter la spécification IPMI "Tableaux des codes de capteurs et d'événements". Ipmi-sensors(8) peut être utilisé pour déterminer les types de capteurs et les états/seuils qui existent sur un système en produisant une sortie très verbeuse et en voyant quels types d'événements d'assertion ou de désassertion sont possibles.

Les valeurs possibles pour tous les états/seuils ci-dessous sont :

Nominal - Indique une lecture nominale si l'état/seuil est déclenché

Avertissement - Indique une lecture d'avertissement si l'état/seuil est déclenché

Critique - Indique une lecture critique si l'état/seuil est déclenché

Tous les types de capteurs et types d'événements IPMI ne sont pas actuellement pris en charge. Si vous souhaitez que d'autres soient pris en charge, veuillez envoyer un e-mail à la liste de diffusion FreeIPMI.

Les valeurs par défaut sélectionnées pour les états/seuils individuels déclenchés sont basées sur des suppositions éclairées et l'analyse des cartes mères. Si vous pensez qu'elles devraient être modifiées, veuillez envoyer un e-mail à la liste de diffusion FreeIPMI pour discuter des valeurs par défaut.

La plupart des interprétations par défaut peuvent être déterminées assez facilement et répondre aux besoins de la plupart des utilisateurs. Par exemple, une lecture de "Performance_Met" est normalement meilleure que "Performance_Lags". Cependant, certains capteurs peuvent être ambigus et dépendent entièrement du fabricant. Par exemple, "State_Asserted" vs "State_Deasserted" dépendent entièrement de l'interprétation du vendeur. Il est conseillé aux utilisateurs d'ajuster les interprétations ci-dessous selon les besoins de leurs machines.

Chaque groupe de conditions d'état ci-dessous comprend une configuration pour "No_Event". C'est la condition dans laquelle aucun état/événement de capteur ne s'est produit ou n'est déclenché. Dans la plupart des conditions, un mappage à "Nominal" est préféré. Cependant, dans certaines circonstances, il peut être utile de rapporter quelque chose d'autre. Par exemple, si un capteur sur une carte mère particulière doit signaler un état/événement, une condition d'état de capteur nul pourrait indiquer un capteur défectueux. Cela dépend fortement de la carte mère.

FORMAT

Les options de configuration qui peuvent être spécifiées dans le fichier de configuration sont listées ci-dessous. Chaque option de configuration doit être listée sur une ligne séparée. Les arguments d'une option sont séparés par n'importe quelle quantité d'espaces blancs. Plusieurs arguments sont également séparés par des espaces blancs. Les commentaires peuvent être marqués en utilisant le caractère dièse (#) et les lignes peuvent être continuées sur la ligne suivante en utilisant une barre oblique inverse (\).

NAME

libipmimonitoring.conf — FreeIPMI monitoring configuration file

DESCRIPTION

The libipmimonitoring library reads the configuration file libipmimonitoring.conf to configure sensor event interpretations for various sensor types. This file allows users to map specific sensor readings or states to more descriptive events and assign severity levels (Nominal, Warning, Critical) to them.

The configuration file consists of a series of definitions, each starting with a specific sensor type or identifier, followed by specific interpretation rules.

FORMAT

The configuration file is structured as a series of definitions, each typically comprising a tag identifying the sensor type or category, followed by a description or further sub-definitions. Comments start with a # and extend to the end of the line.

The following sections detail the available configuration tags and their respective formats.

IPMI_OEM
Les options de configuration suivantes peuvent être utilisées pour configurer des interprétations spécifiques au fabricant (OEM). Les utilisateurs doivent savoir que IPMI_OEM_Bitmask et IPMI_OEM_Value peuvent tous deux être configurés pour une combinaison identique de Manufacturer-ID, Product-ID, Event-Reading-Type-Code, et Sensor-Type. Toutes les règles d'interprétation pour une combinaison spécifique sont parcourues et le pire état de capteur résultant est retourné (c'est-à-dire, Avertissement < Nominal, Critique < Avertissement). Si aucune correspondance n'est trouvée, aucun état de capteur n'est retourné pour la lecture du capteur OEM. Pour chacune des options de configuration ci-dessous, <Manufacturer-ID> est l'ID numérique IANA du fabricant en question. Le <Product-ID> est un ou plusieurs ID numériques représentant le produit du fabricant. Le <Product-ID> peut être listé comme un seul nombre numérique (par exemple, 1234), une plage d'ID séparés par un tiret (par exemple, 12-20), ou une liste d'ID de produits spécifiques séparés par un plus (par exemple, 12+19+22). Les Manufacturer-ID et Product-ID peuvent être trouvés à l'aide de bmc-info(8). Plusieurs paires de <Manufacturer-ID> et <Product-ID> peuvent être saisies séparées par des virgules. Le Event-Reading-Type-Code et Sensor-Type n'ont pas besoin d'être des types OEM. Ils peuvent être des types non-OEM et être utilisés pour fournir des règles d'interprétation pour les capteurs qui pourraient se comporter en dehors des normes de la spécification IPMI.
IPMI_OEM_Bitmask <Manufacturer-ID>:<Product-ID>,... Event-Reading-Type-Code Sensor-Type Sensor-Event-Bitmask State
IPMI_OEM_Bitmask peut être utilisé pour configurer une interprétation d'état pour une combinaison spécifique de Manufacturer-ID, Product-ID, Event-Reading-Type-Code et Sensor-Type, ainsi qu'un masque de bits spécifique de l'Sensor-Event. L'état sera accepté comme interprétation du capteur si le masque de bits saisi ET l'opération avec le masque de bits de l'événement de capteur réel est vraie. À titre de cas spécial, l'état sera accepté si le masque de bits saisi et le masque de bits de l'événement de capteur réel sont tous deux 0. En d'autres termes, si aucun événement ne s'est produit, une interprétation OEM peut être configurée pour ce cas en saisissant un masque de bits de 0x0000.
IPMI_OEM_Value <Manufacturer-ID>:<Product-ID>,... Event-Reading-Type-Code Sensor-Type Sensor-Event-Bitmask-Value State
IPMI_OEM_Value peut être utilisé pour configurer une interprétation d'état pour une combinaison spécifique de Manufacturer-ID, Product-ID, Event-Reading-Type-Code et Sensor-Type, ainsi qu'une valeur spécifique pour le Sensor-Event-Bitmask. L'état sera accepté comme interprétation du capteur si la valeur du masque de bits saisi est égale à la lecture réelle du masque de bits de l'événement du capteur.
