SSL_SET_SHUTDOWN(3) Manuel des fonctions de bibliothèque SSL_SET_SHUTDOWN(3)

NOM

SSL_set_shutdown, SSL_get_shutdown — manipuler l'état d'arrêt d'une connexion SSL

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

void
SSL_set_shutdown(SSL *ssl, int mode);

int
SSL_get_shutdown(const SSL *ssl);

DESCRIPTION

SSL_set_shutdown() définit l'état d'arrêt de ssl à mode.

SSL_get_shutdown() renvoie le mode d'arrêt de ssl.

L'état d'arrêt d'une connexion ssl est un masque de bits de :

0
Aucun réglage d'arrêt pour le moment.
SSL_SENT_SHUTDOWN
Une alerte d'arrêt « close notify » a été envoyée au pair ; la connexion est considérée comme fermée et la session est fermée correctement.
SSL_RECEIVED_SHUTDOWN
Une alerte d'arrêt a été reçue du pair, soit une alerte normale « close notify », soit une erreur fatale.

SSL_SENT_SHUTDOWN et SSL_RECEIVED_SHUTDOWN peuvent être définis en même temps.

L'état d'arrêt de la connexion est utilisé pour déterminer l'état de la session ssl. Si la session est toujours ouverte lorsque SSL_clear(3) ou SSL_free(3) est appelé, elle est considérée comme invalide et supprimée conformément à la RFC 2246. La condition réelle pour une session correctement fermée est SSL_SENT_SHUTDOWN (selon la RFC TLS, il est acceptable de seulement envoyer l'alerte « close notify » mais de ne pas attendre la réponse du pair lorsque la connexion sous-jacente est fermée). SSL_set_shutdown() peut être utilisé pour définir cet état sans envoyer d'alerte de fermeture au pair (voir SSL_shutdown(3)).

Si une alerte « close notify » a été reçue, SSL_RECEIVED_SHUTDOWN sera définie, mais pour définir SSL_SENT_SHUTDOWN, l'application doit toujours appeler SSL_shutdown(3) ou SSL_set_shutdown() elle-même.

VALEURS RENVOYÉES

SSL_get_shutdown() renvoie le réglage actuel.

VOIR AUSSI

ssl(3), SSL_clear(3), SSL_CTX_set_quiet_shutdown(3), SSL_free(3), SSL_shutdown(3)

HISTORIQUE

SSL_set_shutdown() et SSL_get_shutdown() sont apparus pour la première fois dans SSLeay 0.8.0 et sont disponibles depuis OpenBSD 2.4.
