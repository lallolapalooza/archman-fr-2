SSL_CTX_SET_MODE(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_MODE(3)

NOM

SSL_CTX_set_mode, SSL_set_mode, SSL_CTX_clear_mode, SSL_clear_mode, SSL_CTX_get_mode, SSL_get_mode — manipuler les modes du moteur SSL

SYNTAXE

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_mode(SSL_CTX *ctx, long mode);

long
SSL_set_mode(SSL *ssl, long mode);

long
SSL_CTX_clear_mode(SSL_CTX *ctx, long mode);

long
SSL_clear_mode(SSL *ssl, long mode);

long
SSL_CTX_get_mode(SSL_CTX *ctx);

long
SSL_get_mode(SSL *ssl);

DESCRIPTION

SSL_CTX_set_mode() et SSL_set_mode() activent les options contenues dans le masque de bits mode pour l'objet ctx ou ssl, respectivement. Les options qui étaient déjà activées avant l'appel ne sont pas désactivées.

SSL_CTX_clear_mode() et SSL_clear_mode() désactivent les options contenues dans le masque de bits mode pour l'objet ctx ou ssl.

SSL_CTX_get_mode() et SSL_get_mode() renvoient un masque de bits représentant les options actuellement activées pour l'objet ctx ou ssl.

Les options suivantes sont disponibles :

SSL_MODE_ENABLE_PARTIAL_WRITE
Permet à SSL_write(..., n) de retourner r avec 0<r<n (c'est-à-dire signaler le succès lorsqu'un seul enregistrement a été écrit). Lorsqu'elle n'est pas définie (par défaut), SSL_write(3) ne signalera le succès qu'une fois que le bloc complet a été écrit. Une fois que SSL_write(3) retourne avec r, r octets ont été écrits avec succès et l'appel suivant à SSL_write(3) ne doit envoyer que les n − r octets restants, imitant le comportement de write(2).
SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER
Permet de retenter SSL_write(3) avec un emplacement de tampon modifié (le contenu du tampon doit rester le même). Ce n'est pas le défaut afin d'éviter la fausse impression que SSL_write(3) non bloquant se comporte comme write(2) non bloquant.
SSL_MODE_AUTO_RETRY
Ne jamais déranger l'application avec des nouvelles tentatives si le transport est bloquant. Si une renégociation a lieu pendant le fonctionnement normal, un SSL_read(3) ou SSL_write(3) retournerait avec −1 et indiquerait la nécessité de retenter avec SSL_ERROR_WANT_READ. Dans un environnement non bloquant, les applications doivent être prêtes à gérer les opérations de lecture/écriture incomplètes. Dans un environnement bloquant, les applications ne sont pas toujours préparées à gérer les opérations de lecture/écriture qui se terminent sans rapport de succès. Le drapeau SSL_MODE_AUTO_RETRY entraînera les opérations de lecture/écriture à ne retourner qu'après la négociation et l'achèvement réussi.
SSL_MODE_RELEASE_BUFFERS
Lorsque nous n'avons plus besoin d'un tampon de lecture ou d'un tampon d'écriture pour un SSL donné, libérer la mémoire que nous avons utilisée pour le contenir. L'utilisation de ce drapeau peut économiser environ 34 Ko par connexion SSL inactive. Ce drapeau n'a aucun effet sur les connexions SSL v2 ou les connexions DTLS.

VALEUR DE RETOUR

SSL_CTX_set_mode(), SSL_set_mode(), SSL_CTX_clear_mode(), et SSL_clear_mode() retournent le nouveau masque de mode après avoir ajouté ou effacé mode.

SSL_CTX_get_mode() et SSL_get_mode() retournent le masque de bits actuel.

VOIR AUSSI

ssl(3), SSL_CTX_ctrl(3), SSL_read(3), SSL_write(3)

HISTORIQUE

SSL_CTX_set_mode(), SSL_set_mode(), SSL_CTX_get_mode(), et SSL_get_mode() sont apparues pour la première fois dans OpenSSL 0.9.4 et sont disponibles depuis OpenBSD 2.6.

SSL_CTX_clear_mode() et SSL_clear_mode() sont apparues pour la première fois dans OpenSSL 0.9.8m et sont disponibles depuis OpenBSD 4.9.

SSL_MODE_AUTO_RETRY a été ajouté dans OpenSSL 0.9.6.
