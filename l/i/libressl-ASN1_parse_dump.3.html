libressl-ASN1_parse_dump(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

ASN1_PARSE_DUMP(3) Manuel des fonctions de bibliothèque ASN1_PARSE_DUMP(3)

NOM

ASN1_parse_dump, ASN1_parse — analyser BER et afficher des informations à son sujet

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/asn1.h>

int
ASN1_parse_dump(BIO *bio, const unsigned char *ber_in, long length, int indent, int dump);

int
ASN1_parse(BIO *bio, const unsigned char *ber_in, long length, int indent);

DESCRIPTION

ASN1_parse_dump() analyse les valeurs codées en BER et affiche des informations à leur sujet dans bio. Lors de l'entrée dans la fonction, *ber_in doit pointer vers le premier octet identificateur d'une valeur codée. Au plus length octets sont inspectés.

Pour chaque valeur correctement analysée, les informations suivantes sont affichées :

  1. L'index de son premier octet identificateur par rapport à ber_in sous forme de nombre décimal suivi de deux points. Pour la première valeur analysée et affichée, c'est "0:".
  2. La profondeur d'imbrication sous forme d'entier décimal. Pour la première valeur analysée et affichée, c'est "d=0".
  3. La longueur de l'en-tête en octets, incluant les octets identificateurs et les octets de longueur, sous forme de nombre décimal. Par exemple, pour une valeur booléenne, c'est "hl=2" car le codage d'une valeur booléenne contient un octet identificateur (0x01) et un octet de longueur (également 0x01, car un octet de contenu suit l'en-tête).
  4. Si la valeur est codée en utilisant la forme définie pour les octets de longueur, le nombre codé dans les octets de longueur sous forme de nombre décimal. C'est le nombre d'octets de contenu qui suivent. Par exemple, pour une valeur booléenne, c'est "l=1". Si la valeur est codée en utilisant un octet de longueur indiquant la forme indéfinie, "l=inf" est affiché à la place.
  5. Si la valeur est primitive, "prim:" est affiché ; si elle est construite, "cons:".
  6. Le champ suivant dépend de la classe de la balise :
    V_ASN1_PRIVATE
    "priv" suivi du numéro de balise décimal entre crochets
    V_ASN1_CONTEXT_SPECIFIC
    "cont" suivi du numéro de balise décimal entre crochets
    V_ASN1_APPLICATION
    "appl" suivi du numéro de balise décimal entre crochets
    V_ASN1_UNIVERSAL
    Si le numéro de balise est 30 ou moins, la valeur de retour de ASN1_tag2str(3) est affichée ; sinon, "<ASN1" suivi du numéro de balise décimal et d'un crochet fermant.

Pour les valeurs construites, les valeurs contenues sont affichées récursivement.

Les valeurs primitives sont traitées comme suit :

V_ASN1_BOOLEAN
Sa valeur entière est affichée sous forme de nombre décimal.
V_ASN1_INTEGER
Décodé avec d2i_ASN1_INTEGER(3), affiché sous forme de nombre hexadécimal avec un nombre pair de chiffres.
V_ASN1_ENUMERATED
Décodé avec d2i_ASN1_ENUMERATED(3), affiché sous forme de nombre hexadécimal avec un nombre pair de chiffres.
V_ASN1_OBJECT
Décodé avec d2i_ASN1_OBJECT(3), affiché avec i2a_ASN1_OBJECT(3).
V_ASN1_OCTET_STRING
Décodé avec d2i_ASN1_OCTET_STRING(3). Si les données ne consistent qu'en caractères ASCII imprimables, sauts de ligne, retours chariot et tabulations horizontales, elles sont affichées sous forme de chaîne ASCII.

Sinon, l'argument dump décide du format. S'il est zéro, un dump hexadécimal brut est émis, consistant en deux chiffres hexadécimaux pour chaque octet de données. Si dump n'est pas nul, BIO_dump_indent(3) est utilisé. Sauf si dump est -1, les données sont tronquées après dump octets.

V_ASN1_PRINTABLESTRING
Affiché sous forme de chaîne ASCII. Il en va de même pour V_ASN1_IA5STRING, V_ASN1_T61STRING, V_ASN1_NUMERICSTRING, V_ASN1_VISIBLESTRING, V_ASN1_UTF8STRING, V_ASN1_UTCTIME, et V_ASN1_GENERALIZEDTIME.
Autres balises
Si l'argument dump est 0, leurs données sont ignorées silencieusement. Si dump n'est pas nul, BIO_dump_indent(3) est utilisé. Sauf si dump est -1, les données sont tronquées après dump octets.

ASN1_parse() est identique à ASN1_parse_dump() avec 0 passé comme argument dump.

VALEUR DE RETOUR

Ces fonctions retournent 1 en cas de succès ou 0 en cas d'échec.

En particulier, elles affichent un message d'erreur dans bio, arrêtent l'analyse et l'affichage, et retournent 0 en cas d'échec d'analyse ou de décodage, lors de la rencontre d'une valeur dépassant length, ou lors de la rencontre d'un niveau d'imbrication supérieur à 128. Elles arrêtent également l'analyse et l'affichage et retournent 0 lorsque toute opération d'affichage échoue.

VOIR AUSSI

ASN1_get_object(3), ASN1_item_d2i(3), ASN1_item_new(3), ASN1_STRING_print(3), ASN1_TYPE_new(3)

NORMES

Recommandation UIT-T X.690, également connue sous le nom de ISO/IEC 8825-1 : Technologies de l'information - Règles de codage ASN.1 : Spécification des règles de codage de base (BER), règles de codage canoniques (CER) et règles de codage distinguées (DER), section 8.1 : Règles générales pour le codage

HISTORIQUE

ASN1_parse() est apparu pour la première fois dans SSLeay 0.5.1 et est disponible depuis OpenBSD 2.4.

ASN1_parse_dump() est apparu pour la première fois dans OpenSSL 0.9.6 et est disponible depuis OpenBSD 2.9.

BOGUES

Le contenu des valeurs étiquetées comme V_ASN1_BMPSTRING est ignoré silencieusement et rien n'en est affiché.
