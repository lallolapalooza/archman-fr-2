DESCRIPTION

Les fonctions utilitaires d'objet ASN.1 traitent les structures ASN1_OBJECT, appelées ci-après « objets ». Un objet représente un OBJECT IDENTIFIER (OID) ASN.1. La bibliothèque maintient une table globale interne d'objets. Beaucoup de ces objets sont intégrés à la bibliothèque et contenus dans la table globale par défaut. Le programme d'application peut ajouter des objets supplémentaires à la table globale en utilisant les fonctions documentées dans la page de manuel OBJ_create(3). Par conséquent, il existe trois classes d'objets : objets de table intégrés, objets de table définis par l'utilisateur et objets hors table.

En plus de l'OID, chaque objet peut contenir un nom long, un nom court et un identifiant numérique (NID). Bien que le concept de NID soit spécifique à la bibliothèque et non standardisé, l'utilisation du NID est souvent le moyen le plus pratique pour le code source de faire référence à un OID spécifique. Les NID des objets intégrés sont disponibles sous forme de constantes définies.

Les objets de table intégrés présentent certains avantages par rapport aux objets qui ne sont pas dans la table globale : par exemple, leurs NID peuvent être utilisés dans des instructions switch en langage C. Ils sont également partagés : il n'y a qu'une seule structure constante statique pour chaque OID intégré.

Certaines fonctions opèrent uniquement sur les objets de table :

OBJ_nid2obj() récupère l'objet de table associé au nid. OBJ_nid2ln() et OBJ_nid2sn() récupèrent son nom long et son nom court, respectivement.

OBJ_obj2nid() récupère le NID associé à l'object donné, qui est soit le NID stocké dans l'object lui-même, s'il y en a un, soit le NID stocké dans un objet de table contenant le même OID.

OBJ_ln2nid() et OBJ_sn2nid() récupèrent le NID à partir de l'objet de table portant le nom long ln ou le nom court sn, respectivement.

OBJ_txt2nid() récupère le NID à partir de l'objet de table décrit par la chaîne de caractères s, qui peut être un nom long, un nom court ou la représentation numérique d'un OID.

Les fonctions restantes peuvent être utilisées à la fois pour les objets de table et pour les objets qui ne sont pas dans la table globale :

OBJ_txt2obj() récupère ou crée un objet correspondant à la chaîne de caractères s. Si no_name est 1, seule la représentation numérique d'un OID est acceptée. Si no_name est 0, les noms longs et courts sont également acceptés.

OBJ_obj2txt() écrit une représentation textuelle terminée par un NUL de l'OID contenu dans l'object donné dans buf. Au plus buf_len octets sont écrits, tronquant le résultat si nécessaire. La quantité totale d'espace requise est retournée. Si no_name est 0 et que l'objet de table contenant le même OID contient un nom long, le nom long est écrit. Sinon, si no_name est 0 et que l'objet de table contenant le même OID contient un nom court, le nom court est écrit. Sinon, la représentation numérique de l'OID est écrite.

i2t_ASN1_OBJECT() est identique à OBJ_obj2txt() avec no_name défini à 0.

i2a_ASN1_OBJECT() écrit une représentation textuelle de l'OID contenu dans l'object donné dans out_bio en utilisant BIO_write(3). Elle n'écrit pas d'octet NUL de fin. Si l'argument object est NULL ou ne contient pas d'OID, elle écrit la chaîne de 4 octets « NULL ». Si i2t_ASN1_OBJECT() échoue, i2a_ASN1_OBJECT() écrit la chaîne de 9 octets « <INVALID> ». Sinon, elle écrit la chaîne construite avec i2t_ASN1_OBJECT().

OBJ_cmp() vérifie si a et b représentent le même OBJECT IDENTIFIER ASN.1. Tous les noms et NID contenus dans les deux objets sont ignorés, même s'ils diffèrent entre les deux objets.

OBJ_dup() renvoie une copie profonde de l'object donné s'il est marqué comme alloué dynamiquement. Le nouvel objet et toutes les données qu'il contient sont marqués comme alloués dynamiquement. Si l'object donné n'est pas marqué comme alloué dynamiquement, OBJ_dup() renvoie simplement un pointeur vers l'object lui-même.

VALEUR DE RETOUR

Le code d'application doit traiter toutes les valeurs retournées — objets, noms et NID — comme des constantes.

OBJ_nid2obj() renvoie un pointeur vers un objet de table appartenant à la bibliothèque ou NULL si aucun objet de table correspondant n'est trouvé.

libressl(3) - OBJ_nid2obj

NOM

OBJ_nid2obj, OBJ_nid2ln, OBJ_nid2sn, OBJ_obj2nid, OBJ_ln2nid, OBJ_sn2nid, OBJ_txt2nid, OBJ_txt2obj, OBJ_obj2txt, i2t_ASN1_OBJECT, OBJ_cmp, OBJ_dup, i2a_ASN1_OBJECT - fonctions de gestion des objets ASN.1

SYNOPSIS

#include <openssl/objects.h>

ASN1_OBJECT *OBJ_nid2obj(int n);
char *OBJ_nid2ln(int n);
char *OBJ_nid2sn(int n);
int OBJ_obj2nid(const ASN1_OBJECT *o);
int OBJ_ln2nid(const char *ln);
int OBJ_sn2nid(const char *sn);
int OBJ_txt2nid(const char *s);
ASN1_OBJECT *OBJ_txt2obj(const char *s, int no_name);
int OBJ_obj2txt(const ASN1_OBJECT *object, char *buf, int buf_len, int req_flags);
int i2t_ASN1_OBJECT(char *buf, int buf_len, const ASN1_OBJECT *a);
int OBJ_cmp(const ASN1_OBJECT *a, const ASN1_OBJECT *b);
ASN1_OBJECT *OBJ_dup(const ASN1_OBJECT *object);
int i2a_ASN1_OBJECT(BIO *bp, const ASN1_OBJECT *a);

DESCRIPTION

Ces fonctions gèrent les objets ASN.1, qui sont utilisés pour représenter des identificateurs d'objet (OID) et d'autres données structurées. Elles permettent de convertir entre différentes représentations d'objets, notamment des identificateurs numériques (NID), des noms longs et courts, et des représentations textuelles sous forme de chaînes de caractères.

OBJ_nid2obj() renvoie un pointeur vers un objet ASN.1 associé à l'identificateur numérique n, ou NULL si aucun objet correspondant n'est trouvé.

OBJ_nid2ln() et OBJ_nid2sn() renvoient un pointeur vers une chaîne détenue par un objet de table ou NULL si aucun objet de table correspondant n'est trouvé. Pour NID_undef, elles renvoient les chaînes statiques constantes "undefined" et "UNDEF", respectivement.

OBJ_obj2nid() renvoie un NID en cas de succès, ou NID_undef si object est NULL, ne contient pas d'OID, si aucun objet de table correspondant à l'OID n'est trouvé, ou si l'objet correspondant ne contient pas de NID.

OBJ_ln2nid() et OBJ_sn2nid() renvoient un NID en cas de succès ou NID_undef si aucun objet de table correspondant n'est trouvé ou si l'objet correspondant ne contient pas de NID.

OBJ_txt2nid() renvoie un NID en cas de succès ou NID_undef si l'analyse de s ou l'allocation de mémoire échoue, si aucun objet de table correspondant n'est trouvé, ou si l'objet correspondant ne contient pas de NID.

OBJ_txt2obj() renvoie un pointeur vers un objet de table détenu par la bibliothèque si la recherche de s comme nom long ou court réussit. Sinon, elle renvoie un nouvel objet créé, transférant la propriété à l'appelant, ou NULL si l'analyse de s ou l'allocation de mémoire échoue.

OBJ_obj2txt() et i2t_ASN1_OBJECT() renvoient la taille requise en octets, y compris l'octet nul de terminaison, ou zéro si une erreur se produit avant que la taille requise puisse être calculée, en particulier si buf_len est négatif, object est NULL ou ne contient pas d'OID, ou si l'allocation de mémoire échoue.

OBJ_cmp() renvoie 0 si les deux objets font référence au même OID ou si aucun d'eux n'est associé à un OID, ou une valeur non nulle si au moins l'un d'eux fait référence à un OID mais que l'autre n'y fait pas référence.

OBJ_dup() renvoie le pointeur vers l'object d'origine s'il n'est pas marqué comme alloué dynamiquement. Sinon, elle renvoie un nouvel objet créé, transférant la propriété à l'appelant, ou NULL si object est NULL ou si l'allocation de mémoire échoue.

i2a_ASN1_OBJECT() renvoie le nombre d'octets écrits, même si l'object donné est invalide ou contient des données invalides, mais une valeur négative si l'allocation de mémoire ou une opération d'écriture échoue.

Dans certains cas d'échec de OBJ_nid2obj(), OBJ_nid2ln(), OBJ_nid2sn(), OBJ_txt2nid(), OBJ_txt2obj(), OBJ_obj2txt(), OBJ_dup(), i2t_ASN1_OBJECT(), et i2a_ASN1_OBJECT(), la raison peut être déterminée avec ERR_get_error(3).

EXEMPLES

Récupérer l'objet pour commonName :

ASN1_OBJECT *object;
object = OBJ_nid2obj(NID_commonName);

Vérifier si un objet contient l'OID pour commonName :

if (OBJ_obj2nid(object) == NID_commonName)
	/* Faire quelque chose */

Créer un nouvel objet directement :

object = OBJ_txt2obj("1.2.3.4", 1);

VOIR AUSSI

ASN1_OBJECT_new(3), BIO_new(3), d2i_ASN1_OBJECT(3), OBJ_create(3)

HISTORIQUE

OBJ_nid2obj(), OBJ_nid2ln(), OBJ_nid2sn(), OBJ_obj2nid(), OBJ_ln2nid(), OBJ_sn2nid(), OBJ_txt2nid(), OBJ_cmp(), et OBJ_dup() sont apparues pour la première fois dans SSLeay 0.5.1. i2a_ASN1_OBJECT() est apparue pour la première fois dans SSLeay 0.6.0, et i2t_ASN1_OBJECT() dans SSLeay 0.9.0. Toutes ces fonctions sont disponibles depuis OpenBSD 2.4.

OBJ_txt2obj() est apparue pour la première fois dans OpenSSL 0.9.2b. OBJ_obj2txt() est apparue pour la première fois dans OpenSSL 0.9.4. Les deux fonctions sont disponibles depuis OpenBSD 2.6.

CAVEATS

Le contrat d'API de OBJ_txt2obj() lorsqu'elle est appelée avec un argument no_name de 0 et de OBJ_dup() est problématique car l'appelant ne peut pas savoir à partir de l'objet retourné s'il est détenu par la bibliothèque ou si la propriété a été transférée à l'appelant. Par conséquent, il est recommandé de supposer que la propriété de l'objet peut avoir été transférée et d'appeler ASN1_OBJECT_free(3) sur l'objet retourné lorsque l'appelant n'en a plus besoin. Dans le cas où la bibliothèque a conservé la propriété de l'objet retourné, ASN1_OBJECT_free(3) n'a aucun effet et est inoffensive.

Les objets retournés par OBJ_txt2obj() avec un argument no_name de 1 nécessitent toujours ASN1_OBJECT_free(3) pour éviter les fuites de mémoire.

Les objets retournés par OBJ_nid2obj() ne nécessitent jamais ASN1_OBJECT_free(3), mais l'appeler de toute façon n'a aucun effet et est inoffensif.

BUGS

En général, on s'attend à ce qu'un objet contienne un NID autre que NID_undef si et seulement si c'est un objet de table. Cependant, ce n'est pas un invariant garanti par l'API. En particulier, ASN1_OBJECT_create(3) permet la création d'objets non-table contenant des NIDs invalides. OBJ_obj2nid() renvoie de tels NIDs invalides même si OBJ_nid2obj() ne peut pas les utiliser pour la récupération. De plus, la table globale contient un objet intégré avec un NID de NID_undef.

OBJ_obj2txt() est maladroite et compliquée à utiliser : elle ne suit pas la convention des autres fonctions OpenSSL où le tampon peut être défini sur NULL pour déterminer la quantité de données qui devraient être écrites. Au lieu de cela, buf doit pointer vers un tampon valide et buf_len doit être défini sur une valeur positive. Une longueur de tampon de 80 devrait être plus que suffisante pour gérer tout OID rencontré en pratique.
