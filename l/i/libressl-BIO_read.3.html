libressl-BIO_read(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

BIO_READ(3) Manuel des fonctions de bibliothèque BIO_READ(3)

NOM

BIO_read, BIO_number_read, BIO_gets, BIO_write, BIO_puts, BIO_indent, BIO_number_written — Fonctions d'E/S BIO

SYNOPIS

bibliothèque «libcrypto»
#include <openssl/bio.h>

int
BIO_read(BIO *b, void *buf, int len);

unsigned long
BIO_number_read(BIO *b);

int
BIO_gets(BIO *b, char *buf, int size);

int
BIO_write(BIO *b, const void *buf, int len);

int
BIO_puts(BIO *b, const char *string);

int
BIO_indent(BIO *b, int indent, int max);

unsigned long
BIO_number_written(BIO *b);

DESCRIPTION

BIO_read() tente de lire len octets depuis b et place les données dans buf.

BIO_number_read() retourne le total des octets lus depuis b en utilisant BIO_read() jusqu'à présent. Les octets lus avec BIO_gets() ne sont pas comptés. BIO_new(3) et BIO_set(3) initialisent le compteur à 0. Lors de la lecture de très grandes quantités de données, le compteur finira par revenir de ULONG_MAX à 0.

BIO_gets() effectue l'opération « gets » du BIO et place les données dans buf. Généralement, cette opération tentera de lire une ligne de données depuis le BIO d'une longueur maximale de size - 1. Il y a cependant des exceptions, par exemple BIO_gets() sur un BIO de hachage calculera et retournera le hachage, et d'autres BIOs peuvent ne pas supporter BIO_gets() du tout. La chaîne retournée est toujours terminée par un caractère nul.

BIO_write() tente d'écrire len octets depuis buf vers b.

BIO_puts() tente d'écrire la chaîne terminée par un caractère nul string dans b.

BIO_indent() tente d'écrire indent caractères d'espace dans b, mais pas plus de max caractères.

BIO_number_written() retourne le total des octets écrits dans b en utilisant BIO_write(), BIO_puts(), et BIO_indent() jusqu'à présent. BIO_new(3) et BIO_set(3) initialisent le compteur à 0. Lors de l'écriture de très grandes quantités de données, le compteur finira par revenir de ULONG_MAX à 0.

Une technique parfois utilisée avec les sockets bloquants est d'utiliser un appel système (tel que select(2), poll(2) ou équivalent) pour déterminer quand des données sont disponibles, puis d'appeler read(2) pour lire les données. L'équivalent avec les BIOs (c'est-à-dire appeler select(2) sur la structure E/S sous-jacente puis appeler BIO_read() pour lire les données) ne doit pas être utilisé, car un seul appel à BIO_read() peut entraîner plusieurs lectures (et écritures dans le cas des BIOs SSL) sur la structure E/S sous-jacente et peut bloquer en conséquence. À la place, select(2) (ou équivalent) doit être combiné avec des E/S non bloquantes afin que les lectures successives demandent une nouvelle tentative au lieu de bloquer.

Voir BIO_should_retry(3) pour les détails sur la façon de déterminer la cause d'une nouvelle tentative et d'autres problèmes d'E/S.

Si la fonction BIO_gets() n'est pas supportée par un BIO, il est possible de contourner ce problème en ajoutant un BIO tamponné BIO_f_buffer(3) à la chaîne.

VALEURS DE RETOUR

BIO_indent() retourne 1 en cas de succès, même si rien n'a été écrit, ou 0 si l'écriture échoue.

BIO_number_read() et BIO_number_written() retournent un nombre d'octets ou 0 si b est un pointeur NULL.

Les autres fonctions retournent soit la quantité de données lues ou écrites avec succès (si la valeur de retour est positive), soit qu'aucune donnée n'a été lue ou écrite avec succès si le résultat est 0 ou -1. Si la valeur de retour est -2, alors l'opération n'est pas implémentée dans le type de BIO spécifique. Le caractère nul final n'est pas inclus dans la longueur retournée par BIO_gets().

Un retour de 0 ou -1 n'est pas nécessairement une indication d'erreur. En particulier lorsque la source/destination n'est pas bloquante ou d'un certain type, cela peut simplement indiquer qu'aucune donnée n'est actuellement disponible et que l'application devrait réessayer l'opération plus tard.

VOIR AUSSI

BIO_meth_new(3), BIO_new(3), BIO_should_retry(3)

HISTORIQUE

BIO_read(), BIO_gets(), BIO_write(), et BIO_puts() sont apparus pour la première fois dans SSLeay 0.6.0. BIO_number_read() et BIO_number_written() sont apparus pour la première fois dans SSLeay 0.6.5. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BIO_indent() est apparu pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.4.
