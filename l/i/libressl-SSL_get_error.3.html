NOM

SSL_get_error — obtenir le code de résultat pour une opération d'E/S TLS/SSL

SYNTAXE

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_get_error(const SSL *ssl, int ret);

DESCRIPTION

SSL_get_error() renvoie un code de résultat (adapté pour l'instruction C “switch”) pour un appel précédent à SSL_connect(3), SSL_accept(3), SSL_do_handshake(3), SSL_read(3), SSL_peek(3), ou SSL_write(3) sur ssl. La valeur renvoyée par cette fonction d'E/S TLS/SSL doit être passée à SSL_get_error() dans le paramètre ret.

En plus de ssl et ret, SSL_get_error() inspecte la file d'attente d'erreurs OpenSSL du thread courant. Ainsi, SSL_get_error() doit être utilisé dans le même thread qui a effectué l'opération d'E/S TLS/SSL, et aucun autre appel de fonction OpenSSL ne doit apparaître entre les deux. La file d'attente d'erreurs du thread courant doit être vide avant que l'opération d'E/S TLS/SSL ne soit tentée, ou SSL_get_error() ne fonctionnera pas de manière fiable.

VALEURS DE RETOUR

Les valeurs de retour suivantes peuvent survenir actuellement :

SSL_ERROR_NONE
L'opération d'E/S TLS/SSL s'est terminée. Ce code de résultat est renvoyé si et seulement si ret > 0.
SSL_ERROR_ZERO_RETURN
La connexion TLS/SSL a été fermée. Si la version du protocole est SSL 3.0 ou TLS 1.0, ce code de résultat n'est renvoyé que si une alerte de fermeture s'est produite dans le protocole, c'est-à-dire si la connexion a été fermée proprement. Notez que dans ce cas, SSL_ERROR_ZERO_RETURN n'indique pas nécessairement que le transport sous-jacent a été fermé.
SSL_ERROR_WANT_READ, SSL_ERROR_WANT_WRITE
L'opération ne s'est pas terminée ; la même fonction d'E/S TLS/SSL doit être appelée à nouveau plus tard. Si, d'ici là, le BIO sous-jacent dispose de données disponibles pour la lecture (si le code de résultat est SSL_ERROR_WANT_READ) ou permet l'écriture de données (SSL_ERROR_WANT_WRITE), alors une certaine progression du protocole TLS/SSL aura lieu, c'est-à-dire qu'au moins une partie d'un enregistrement TLS/SSL sera lue ou écrite. Notez que la nouvelle tentative peut à nouveau conduire à une condition SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE. Il n'y a pas de limite supérieure fixe pour le nombre d'itérations qui peuvent être nécessaires jusqu'à ce qu'une progression devienne visible au niveau du protocole d'application.

Pour les BIO de socket (par exemple, lorsque SSL_set_fd() a été utilisé), select(2) ou poll(2) sur le socket sous-jacent peuvent être utilisés pour savoir quand la fonction d'E/S TLS/SSL doit être réessayée.

Attention : Toute fonction d'E/S TLS/SSL peut entraîner l'un ou l'autre de SSL_ERROR_WANT_READ et SSL_ERROR_WANT_WRITE. En particulier, SSL_read(3) ou SSL_peek(3) peuvent vouloir écrire des données et SSL_write(3) peut vouloir lire des données. Ceci est principalement dû au fait que les handshakes TLS/SSL peuvent se produire à tout moment pendant le protocole (initiés par le client ou le serveur) ; SSL_read(3), SSL_peek(3), et SSL_write(3) géreront tous les handshakes en attente.

SSL_ERROR_WANT_CONNECT, SSL_ERROR_WANT_ACCEPT
L'opération ne s'est pas terminée ; la même fonction d'E/S TLS/SSL doit être appelée à nouveau plus tard. Le BIO sous-jacent n'était pas encore connecté au pair et l'appel bloquerait dans connect(2)/accept(2). La fonction SSL doit être appelée à nouveau lorsque la connexion est établie. Ces messages ne peuvent apparaître qu'avec un BIO BIO_s_connect(3) ou BIO_s_accept(3), respectivement. Afin de savoir quand la connexion a été établie avec succès, sur de nombreuses plateformes, select(2) ou poll(2) pour l'écriture sur le descripteur de fichier du socket peuvent être utilisés.
SSL_ERROR_WANT_X509_LOOKUP
L'opération ne s'est pas terminée car une fonction de rappel d'application définie par SSL_CTX_set_client_cert_cb(3) a demandé à être appelée à nouveau. La fonction d'E/S TLS/SSL doit être appelée à nouveau plus tard. Les détails dépendent de l'application.
SSL_ERROR_SYSCALL
Une erreur d'E/S s'est produite. La file d'attente d'erreurs OpenSSL peut contenir plus d'informations sur l'erreur. Si la file d'attente d'erreurs est vide (c'est-à-dire que ERR_get_error() renvoie 0), ret peut être utilisé pour obtenir plus d'informations sur l'erreur : Si ret == 0, un EOF a été observé en violation du protocole. Si ret == -1, le BIO sous-jacent a signalé une erreur d'E/S (pour les E/S de socket sur les systèmes Unix, consultez errno pour les détails).
SSL_ERROR_SSL
Un échec dans la bibliothèque SSL s'est produit, généralement une erreur de protocole. La file d'attente d'erreurs OpenSSL contient plus d'informations sur l'erreur.

    NAME

    SSL_get_error - get the reason for a SSL/TLS connection error

    SYNOPSIS

    #include <openssl/ssl.h>

    int SSL_get_error(SSL *ssl, int ret);

    DESCRIPTION

    SSL_get_error() inspects the cause of the last error on the SSL/TLS connection ssl.

    The parameter ret is the return value of the SSL/TLS function call that caused the error (e.g. SSL_read(), SSL_write(), SSL_connect(), SSL_accept()).

    The possible return values are:

    • SSL_ERROR_NONE: No error occurred. This can happen if ret was 0 or negative, but no SSL/TLS-specific error occurred.
    • SSL_ERROR_ZERO_RETURN: The TLS/SSL connection has been shut down cleanly. This means that a shutdown message was received from the peer or the application explicitly called SSL_shutdown().
    • SSL_ERROR_WANT_READ: The operation did not complete because SSL was waiting for read data from the network. The calling program must wait until it can read more data from the ssl structure, and then call the function again with the same arguments.
    • SSL_ERROR_WANT_WRITE: The operation did not complete because SSL was waiting for write data to be sent to the network. The calling program must wait until it can write more data to the ssl structure, and then call the function again with the same arguments.
    • SSL_ERROR_WANT_CONNECT: The operation did not complete because SSL was waiting to be connected. This is a special case for non-blocking sockets, where SSL_connect() or SSL_accept() must be called again after the connection has been established.
    • SSL_ERROR_WANT_ACCEPT: Similar to SSL_ERROR_WANT_CONNECT, but for SSL_accept().
    • SSL_ERROR_WANT_X509_lookup: The operation did not complete because the callback function for X509 lookups needed to be called. This is a rare case and not usually encountered.
    • SSL_ERROR_SYSCALL: Some underlying system error occurred. The error status is available in the error stack by calling ERR_get_error() or directly from errno. This can be for example due to a broken pipe or a closed socket.
    • SSL_ERROR_SSL: A failure in the SSL library occurred. The error stack should be inspected by calling ERR_get_error() for more details.

    RETURN VALUES

    SSL_get_error() returns an integer indicating the type of error.

    SEE ALSO

    SSL_read(3), SSL_write(3), SSL_connect(3), SSL_accept(3), ERR_get_error(3)

    HISTORY

    The SSL_get_error() function first appeared in SSLeay 0.9.1.
