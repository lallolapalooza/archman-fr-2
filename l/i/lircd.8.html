NOM

lircd - Décode les signaux infrarouges et les fournit sur un socket.

SYNTAXE

lircd [options] [fichier de configuration]

DESCRIPTION

La tâche principale de lircd est de décoder les signaux infrarouges et de fournir une interface uniforme pour les applications clientes. Les clients peuvent se connecter à lircd via un socket de domaine Unix, par défaut /var/run/lirc/lircd. En utilisant ce socket, ils obtiennent les codes infrarouges reçus par lircd et peuvent envoyer des commandes à lircd.

ARGUMENTS

fichier de configuration
Le fichier de configuration, par défaut /etc/lirc/lircd.conf. Un chemin relatif est interprété à partir de /etc/lirc. Le fichier de configuration par défaut inclut tous les fichiers dans /etc/lircd.conf.d.
Chaque télécommande qui doit être décodée par lircd nécessite généralement l'utilisation d'un fichier spécifique, par exemple en le copiant dans /etc/lirc/lirc.conf.d/. Le format est décrit dans lircd.conf(5). Les fichiers de configuration peuvent être trouvés en utilisant irdb-get(1) ou lirc-setup(1). Il est également possible de générer un fichier de configuration en utilisant irrecord(1).

OPTIONS

Options courantes :

-d, --device <périphérique>
Sélectionne le périphérique caractère à partir duquel lircd doit lire. Le défaut est actuellement /dev/lirc0 sur la plupart des systèmes.
Certains pilotes, y compris le pilote par défaut devinput, supportent le périphérique auto qui sélectionne le premier périphérique utilisable trouvé pour le pilote actuel.
Lors de l'utilisation du pilote devinput, name=CHAINE ou phys=CHAINE peuvent être utilisés pour sélectionner le périphérique ; lircd recherchera dans /dev/input pour trouver un périphérique avec une description correspondante. Ceci est utile si le nom du périphérique n'est pas fixe. CHAINE peut contenir les caractères génériques '*' et '?' ainsi que '\' pour les marquer comme littéraux. Utilisez mode2 --driver devinput --list-devices pour lister les périphériques actuels.
-H, --driver <pilote>
Le pilote à utiliser. Utiliser --driver help liste tous les pilotes disponibles, voir CHARGEMENT DES PILOTES ci-dessous.
-h, --help
Affiche un court message d'aide.

Autres options :

-a, --allow-simulate
Active la commande SIMULATE qui peut être émise en utilisant irsend(1) ou l'API cliente. Cela permettra de simuler des événements IR arbitraires depuis la ligne de commande. Utilisez cette option avec prudence car elle donnera à tous les utilisateurs ayant accès au socket lircd un contrôle étendu sur le système. Par exemple, si vous avez configuré votre système pour qu'il s'arrête sur une pression de bouton de votre télécommande, n'importe qui pourra arrêter votre système depuis la ligne de commande.
-c, --connect [hote[:port]][,[hote[:port]]]
Se connecte à d'autres serveurs lircd qui fournissent un socket réseau à l'hôte et au port donnés (voir --listen). Le nombre de telles connexions est actuellement limité à 100. L'instance lircd qui se connecte recevra les événements IR de l'instance lircd à laquelle elle se connecte. Pour se connecter à plusieurs serveurs, ajoutez-les sous forme de liste séparée par des virgules.
-e, --effective-user <uid>
Si démarré en tant qu'utilisateur root, lircd abandonne ses privilèges et s'exécute en tant qu'utilisateur <uid> après avoir ouvert les fichiers etc.
-i, --immediate-init
Lircd initialise normalement le pilote lorsque le premier client se connecte. Si cette option est sélectionnée, le pilote est plutôt initialisé immédiatement au démarrage.
-A, --driver-options cle:valeur[|cle:valeur...]
Définit une ou plusieurs options pour le pilote. L'argument est une liste de paires clé:valeur délimitées par '|'. La clé ne peut pas contenir d'espaces, mais ceux-ci sont autorisés dans la partie valeur. Certains caractères, y compris '#' et ';', sont utilisés comme marqueurs de commentaire dans le fichier de configuration et ne sont autorisés nulle part.
-Y, --dynamic-codes [EXPÉRIMENTAL]
Permet l'utilisation de codes qui ont été décodés pour une télécommande mais qui ne sont pas définis dans lircd.conf. De nouveaux codes sont créés dynamiquement avec un nom par défaut. Cette fonctionnalité est expérimentale et sujette à toutes sortes de modifications. Elle n'a pas été testée soigneusement.
-l, --listen [[adresse:]port]]
Laisse lircd écouter les connexions réseau sur l'adresse/port donné(e). L'adresse par défaut est 0.0.0.0, ce qui signifie que les connexions sur toutes les interfaces réseau seront acceptées. L'adresse doit être donnée sous forme numérique pointée. Le port par défaut est 8765. L'instance lircd qui écoute enverra tous les événements IR aux instances lircd qui se connectent, sans aucune vérification de sécurité.
Sur les plateformes non-glibc, l'argument adresse:port est obligatoire, mais peut être donné sous forme de chaîne vide, par exemple --listen= qui utilise alors par défaut 0.0.0.0:8765.
-L, --logfile <chemin_journal>
Sélectionne le fichier journal du démon lircd. logfile est soit la chaîne 'syslog' indiquant que syslog(1) doit être utilisé, soit un chemin de fichier journal. Par défaut, syslog est utilisé.
-D, --loglevel [niveau]
Détermine la quantité d'informations de journalisation. niveau peut être un niveau syslog symbolique : 'error', 'warning', 'info', 'notice' ou 'debug'. lircd définit également trois niveaux supplémentaires 'trace', 'trace1' et 'trace2' qui fournissent encore plus de messages ('trace2' apportant le plus). Cependant, dans le journal, ces messages sont marqués comme 'debug'.
Sur les plateformes non-glibc, l'argument niveau est obligatoire, mais peut être donné sous forme de chaîne vide, par exemple --loglevel= qui utilise alors par défaut debug.
Le niveau peut également être un entier compris entre 3 (presque aucun message) et 10.
-O, --options-file <chemin>
Fichier contenant les valeurs par défaut pour toutes les options. Un chemin relatif est interprété à partir du répertoire courant. Voir [FICHIERS] ci-dessous.
-o, --output <socket_sortie>
Sélectionne le socket de domaine Unix, auquel lircd écrira les codes de touche reçus. Le défaut actuel est /var/run/lirc/lircd.
-p, --permission <perm>
Donne la permission du fichier du socket de sortie s'il doit être créé sous forme octale. Voir chmod(1). Si aucune option --permission n'est donnée lors de la création initiale du socket, la valeur par défaut est de donner à tous les utilisateurs les permissions de lecture et d'écriture (0666 en représentation octale). Si le socket existe déjà, cette option n'a aucun effet.
-p, --pidfile <chemin>
Sélectionne le fichier PID du démon lircd, le défaut est /var/run/lirc/lircd.pid.
-U --plugindir <chemin>
Définit le répertoire à partir duquel lircd charge ses pilotes en espace utilisateur. Ce sont des fichiers *.so, trouvés par défaut comme décrit sous CHARGEMENT DES PILOTES. L'argument est un chemin de recherche séparé par des ':'.
-R, --repeat-max <limite>
Définit une limite supérieure au nombre de répétitions lors de l'envoi d'un signal. Le défaut actuel est 600. Une requête SEND_START répétera le signal autant de fois. De plus, si le nombre de répétitions dans une requête SEND_ONCE dépasse ce nombre, il sera remplacé par ce nombre.

FORMAT MESSAGES BROADCAST SOCKET

Lors du décodage d'une pression de bouton ou de la réception d'un signal SIGHUP, lircd.conf lircd diffuse des messages à tous les clients connectés.

Pour chaque pression de bouton décodée, un paquet est rendu disponible sur le socket. Il s'agit de données imprimables formatées comme suit :

        <code> <nombre de répétitions> <nom du bouton> <nom de la télécommande>

par exemple,

        000000
lircd(8) — lirc 0.10.2

NAME

lircd — Linux Infrared Remote Control daemon

SYNOPSIS

lircd [-h|--help] [-v|--version] [-d|--device device] [-a|--driver driver] [-H|--driver-host host] [-p|--driver-port port] [-U|--driver-options options] [-l|--listen port] [-r|--repeat-max num] [-f|--config config-file] [-O|--options-file options-file] [-D|--debug level] [--pidfile pidfile] [--allow-simulate] [--plugindir plugindir]

DESCRIPTION

lircd is the daemon that receives IR events from the lirc driver, decodes them according to the configuration file lircd.conf, and broadcasts them to all listening clients.

The configuration file specifies how to decode IR events. It contains information about the remotes and the buttons on them. For more information see lircd.conf(5).

When receiving IR events, lircd uses a driver specified either on the command line (option -a) or in the options file (lirc_options.conf). If neither is specified, it uses a default driver determined at compile time. See DRIVER LOADING for more information about how the driver is located.

lircd supports two interfaces:

        1. A socket interface on port 8765 (or as specified with -l)
           This interface is used by clients to get IR events and to
           send commands to lircd.
        2. A command socket interface, specified with --connect
           This interface is described in SOCKET COMMAND INTERFACE.

ARGUMENTS

Most options are processed by the options file as described in lircd.conf(5).

OPTIONS

-h, --help
Print a help message and exit.
-v, --version
Print version information and exit.
-d, --device device
Use the specified device instead of the default. The device is usually /dev/lirc0.
-a, --driver driver
Use the specified driver. See DRIVER LOADING.
-H, --driver-host host
Use the specified host when loading remote drivers.
-p, --driver-port port
Use the specified port when loading remote drivers.
-U, --driver-options options
Pass the specified options to the driver.
-l, --listen port
Listen on the specified port for clients. Defaults to 8765.
-r, --repeat-max num
Set the maximum number of repeats for a button press. Defaults to 600. See SEND_ONCE.
-f, --config config-file
Read configuration from config-file instead of the default /etc/lirc/lircd.conf.
-O, --options-file options-file
Read options from options-file instead of the default /etc/lirc/lirc_options.conf.
-D, --debug level
Set the debug level. Higher levels provide more output. Level 6 is verbose debug, Level 7 prints received and decoded data.
--pidfile pidfile
Write the process ID to pidfile.
--allow-simulate
Allow the SIMULATE command. See SOCKET COMMAND INTERFACE.
--plugindir plugindir
Set the plugin directory. See DRIVER LOADING.

SOCKET BROADCAST MESSAGES FORMAT

When lircd receives an IR signal and successfully decodes it it broadcasts the decoded information to all connected clients.

The format of these messages is:

0000f40bf0 00 KEY_UP ANIMAX

The fields are:

code
A 16 hexadecimal digits number encoding of the IR signal. It's usage in applications is deprecated and it should be ignored.
repeat count
shows how long the user has been holding down a button. The counter will start at 0 and increment each time a new IR signal has been received.
button name
is the name of a key defined in the lircd.conf file.
remote control name
is the mandatory name attribute in the lircd.conf config file.

These packets are broadcasted to all clients. The only other situation when lircd broadcasts to all clients is when it receives the SIGHUP signal and successfully re-reads its config file. Then it will send a SIGHUP packet to its clients indicating that its configuration might have changed. The sighup packet is three lines

        BEGIN
        SIGHUP
        END

SOCKET COMMAND INTERFACE

Applications can also send commands to lircd over the socket interface. The most common task is sending data, but there are also other commands. Each command is a single printable line, terminated with a newline. For each command, lircd replies with a reply package.

Supported commands:

SEND_ONCE <remote control> <button name> [repeats]
Tell lircd to send the IR signal associated with the given remote control and button name, and then repeat it repeats times. repeats is a decimal number between 0 and repeat_max. The latter can be given as a --repeat-max command line argument to lircd, and defaults to 600. If repeats is not specified or is less than the minimum number of repeats for the selected remote control, the minimum value will be used.
SEND_START <remote control name> <button name>
Tell lircd to start repeating the given button until it receives a SEND_STOP command. However, the number of repeats is limited to repeat_max. lircd won't accept any new send commands while it is repeating.
SEND_STOP <remote control name> <button name>
Tell lircd to abort a SEND_START command.
LIST [remote control]
Without arguments lircd replies with a list of all defined remote controls. Given a remote control argument, lircd replies with a list of all keys defined in the given remote.
SET_INPUTLOG [path]
Given a path, lircd will start logging all received data on that file. The log is printable lines as defined in mode2(1) describing pulse/space durations. Without a path, current logfile is closed and the logging is stopped.
DRV_OPTION key value
Make lircd invoke the drvctl_func(DRVCTL_SET_OPTION, option) with option being made up by the parsed key and value. The return package reflects the outcome of the drvctl_func call.
SIMULATE key data
Given key data, instructs lircd to send this to all clients i. e., to simulate that this key has been decoded. The key data must be formatted exactly as the packet described in [SOCKET BROADCAST MESSAGES FORMAT], notably is the number of digits in code and repeat count hardcoded. This command is only accepted if the --allow-simulate command line option is active.
SET_TRANSMITTERS transmitter mask
Make lircd invoke the drvctl_func(LIRC_SET_TRANSMITTER_MASK, &channels), where channels is the decoded value of transmitter mask. See lirc(4) for more information.
VERSION
Tell lircd to send a version packet response.

The protocol guarantees that broadcasted messages won't interfere with reply packets. But broadcasts may appear at any point between packets. The only exception are SIGHUP packages. These may appear just after you have sent a command to lircd, so you have to make sure you don't confuse them with replies.

The format of the reply packet is

  BEGIN
  <command>
  [SUCCESS|ERROR]
  [DATA
  n
  n lines of data]
  END

If the command was successful, data is only sent for the commands that return some information. Note that a packet containing 0 lines of data can be a valid reply.

RUNNING AS REGULAR USER

Traditionally lircd has been running as root since accessing kernel devices like /dev/lirc0 by default requires root privileges. However, running a long-running service like this is a major security issue.

The lirc distribution contains example udev rules which makes /dev/lirc[0-9] , USB and serial devices accessible by the lirc user. Using these rules, it is possible to run lircd as a regular user and group such as lirc.

FILES

/etc/lirc/lircd.conf
Main config file, see lircd.conf(5).
/etc/lirc/lirc_options.conf
The options file. lircd handles the values under the [lircd] section in this file. The location can be changed using the -O/--options-file command-line option or using the environment variable LIRC_OPTIONS_PATH. The values here are used as defaults for any option not present on command line.

ENVIRONMENT

LIRC_OPTIONS_PATH
Options file path, see FILES.
LIRC_PLUGINDIR
Plugin load path, se DRIVER LOADING.
LIRC_DEBUG_OPTIONS
If set, enables debugging in early stages when the --debug option is yet not parsed.

DRIVER LOADING

Drivers are loaded dynamically. This is done from a traditional *ux ´:´-separated path where each component in the path is searched (leading part first, trailing last).

The path used for this is determined by (falling priority):

  • The --plugindir option.
  • The 'plugindir' entry in the [lircd] section of the lirc_options.conf file.
  • The environment variable LIRC_PLUGINDIR.
  • A hardcoded default (/usr/lib/lirc/plugins).

SIGNALS

HUP
On receiving SIGHUP lircd re-reads the lircd.conf configuration file (but not lirc_options.conf) and adjusts itself if the file has changed.
USR1
On receiving SIGUSR1 lircd makes a clean exit.

DAEMONS

lircd is a daemon. It should be started in some system-dependent init script. By default, lirc ships with systemd files enabling user to control the lircd service.
