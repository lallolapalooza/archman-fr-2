VALIDITÉ DES POINTEURS

Notez que tous les pointeurs vers des objets ayant un ID n'ont qu'une période de validité limitée, à l'exception des pointeurs Repo. Ils ne sont garantis valides que jusqu'à ce qu'un nouvel objet de ce type soit ajouté ou qu'un objet de ce type soit supprimé. Ainsi, les pointeurs vers les objets Solvable ne sont valides que jusqu'à ce qu'un autre solvable soit créé, car l'ajout d'un Solvable peut déplacer le tableau de Solvables du Pool. Il en va de même pour les chaînes de caractères du Pool, vous devriez utiliser solv_strdup() pour créer une copie de la chaîne si vous souhaitez l'utiliser plus tard. Vous devriez utiliser les IDs dans le code et non les pointeurs, sauf pour de courtes périodes où vous savez que le pointeur est sûr.

Notez également que les fonctions de recherche de données ou l'itérateur de données renvoient également des valeurs avec une durée de vie limitée, ceci est particulièrement vrai pour les données stockées dans le segment de données paginé des fichiers solv. Il s'agit normalement de données constituées de grandes chaînes de caractères comme les descriptions de paquets ou de données rarement nécessaires comme les sommes de contrôle de paquets. Ainsi, la recherche de la description d'un solvable, puis la recherche de la description d'un solvable différent, ou même de la somme de contrôle du même solvable, peut invalider le premier résultat. (L'itérateur de données supporte une fonction dataiterator_strdup() pour créer une copie sûre.)

Les liaisons linguistiques gèrent déjà la validité des pointeurs, vous n'avez donc pas à vous soucier de ce problème lorsque vous utilisez ces liaisons.
