OCSP_REQUEST_ADD1_NONCE(3) Manuel des fonctions de bibliothèque OCSP_REQUEST_ADD1_NONCE(3)

NOM

OCSP_request_add1_nonce, OCSP_basic_add1_nonce, OCSP_check_nonce, OCSP_copy_nonce — fonctions de nonce OCSP

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/ocsp.h>

int
OCSP_request_add1_nonce(OCSP_REQUEST *req, unsigned char *val, int len);

int
OCSP_basic_add1_nonce(OCSP_BASICRESP *resp, unsigned char *val, int len);

int
OCSP_check_nonce(OCSP_REQUEST *req, OCSP_BASICRESP *resp);

int
OCSP_copy_nonce(OCSP_BASICRESP *resp, OCSP_REQUEST *req);

DESCRIPTION

Un nonce OCSP est généralement ajouté à une requête OCSP pour contrecarrer les attaques par rejeu en vérifiant que la même valeur de nonce apparaît dans la réponse.

OCSP_request_add1_nonce() ajoute un nonce de valeur val et de longueur len à la requête OCSP req. Si val est NULL, un nonce aléatoire est utilisé. Si len est zéro ou négatif, une longueur par défaut sera utilisée (actuellement 16 octets). Pour la plupart des utilisations, la valeur du nonce dans une requête est définie sur une valeur aléatoire, donc le paramètre val dans OCSP_request_add1_nonce() est généralement NULL.

OCSP_basic_add1_nonce() est identique à OCSP_request_add1_nonce() à ceci près qu'il ajoute un nonce à la réponse OCSP de base resp.

OCSP_check_nonce() compare la valeur du nonce dans req et resp.

OCSP_copy_nonce() copie toute valeur de nonce présente dans req vers resp.

Certains répondants peuvent inclure un nonce dans toutes les réponses même si un n'est pas fourni.

Certains répondants mettent en cache les réponses OCSP et ne signent pas chaque réponse pour des raisons de performance. Par conséquent, ils ne prennent pas en charge les nonces.

VALEURS DE RETOUR

OCSP_request_add1_nonce() et OCSP_basic_add1_nonce() retournent 1 en cas de succès ou 0 en cas d'échec.

OCSP_copy_nonce() retourne 1 si un nonce a été copié avec succès, 2 si aucun nonce n'était présent dans req, ou 0 si une erreur s'est produite.

OCSP_check_nonce() retourne des valeurs positives en cas de succès : 1 si les nonces sont présents et égaux, 2 si les deux nonces sont absents, ou 3 si un nonce est présent uniquement dans la réponse. Un retour de zéro indique que les deux nonces sont présents mais ne correspondent pas : cela doit être traité comme une condition d'erreur. Un retour de -1 indique qu'un nonce est présent uniquement dans la requête : cela se produira si le répondant ne prend pas en charge les nonces.
