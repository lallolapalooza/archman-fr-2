Paquet: libressl

Licences: ISC, custom:OpenSSL

EVP_SIGNINIT(3) Manuel des fonctions de bibliothèque EVP_SIGNINIT(3)

NOM

EVP_SignInit_ex, EVP_SignUpdate, EVP_SignFinal, EVP_SignInit — Fonctions de signature EVP

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_SignInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *engine);

int
EVP_SignUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);

int
EVP_SignFinal(EVP_MD_CTX *ctx, unsigned char *sig, unsigned int *s, EVP_PKEY *pkey);

void
EVP_SignInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPTION

Les routines de signature EVP sont une interface de haut niveau pour les signatures numériques.

EVP_SignInit_ex() configure le contexte de signature ctx pour utiliser le digest type. Avant d'appeler cette fonction, obtenez ctx à partir de EVP_MD_CTX_new(3) ou appelez EVP_MD_CTX_reset(3) dessus. L'argument engine est toujours ignoré et il est recommandé de passer NULL.

EVP_SignUpdate() hache cnt octets de données à d dans le contexte de signature ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour inclure des données supplémentaires.

EVP_SignFinal() signe les données dans ctx en utilisant la clé privée pkey et place la signature dans sig. sig doit avoir une taille d'au moins EVP_PKEY_size(3) octets. s est un paramètre de SORTIE et n'est pas utilisé comme paramètre d'ENTRÉE. Le nombre d'octets de données écrits (c'est-à-dire la longueur de la signature) sera écrit dans l'entier à s. Au plus EVP_PKEY_size(3) octets seront écrits.

EVP_SignInit() initialise un contexte de signature ctx pour utiliser l'implémentation par défaut du digest type.

L'interface EVP pour les signatures numériques devrait presque toujours être utilisée de préférence aux interfaces de bas niveau. En effet, le code devient alors transparent à l'algorithme utilisé et beaucoup plus flexible.

L'appel à EVP_SignFinal() finalise en interne une copie du contexte de digest. Cela signifie que des appels à EVP_SignUpdate() et EVP_SignFinal() peuvent être faits plus tard pour hacher et signer des données supplémentaires.

Puisque seule une copie du contexte de digest est jamais finalisée, le contexte doit être nettoyé après utilisation en appelant EVP_MD_CTX_free(3), sinon une fuite de mémoire se produira.

EVP_SignInit_ex(), EVP_SignUpdate(), et EVP_SignInit() sont implémentées comme des macros.

VALEURS DE RETOUR

EVP_SignInit_ex(), EVP_SignUpdate(), et EVP_SignFinal() renvoient 1 en cas de succès et 0 en cas d'échec.

Les codes d'erreur peuvent être obtenus par ERR_get_error(3).

VOIR AUSSI

evp(3), EVP_DigestInit(3), EVP_PKEY_size(3), EVP_VerifyInit(3)

HISTORIQUE

EVP_SignInit(), EVP_SignUpdate(), et EVP_SignFinal() sont apparues pour la première fois dans SSLeay 0.5.1 et sont disponibles depuis OpenBSD 2.4.

EVP_SignInit_ex() est apparue pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

BOGUES

Les versions précédentes de cette documentation indiquaient à tort que des appels à EVP_SignUpdate() ne pouvaient pas être faits après l'appel à EVP_SignFinal().

Comme la clé privée est passée dans l'appel à EVP_SignFinal(), toute erreur relative à la clé privée (par exemple une combinaison clé et digest inappropriée) ne sera pas indiquée avant qu'une quantité de données potentiellement importante n'ait été transmise via EVP_SignUpdate().

Il n'est pas possible de modifier les paramètres de signature à l'aide de ces fonctions.

Les deux bogues précédents sont corrigés dans la nouvelle fonction EVP_DigestSign*.
