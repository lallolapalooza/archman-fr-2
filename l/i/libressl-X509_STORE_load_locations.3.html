libressl-X509_STORE_load_locations(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

X509_STORE_LOAD_LOCATIONS(3) Manuel des fonctions de bibliothèque X509_STORE_LOAD_LOCATIONS(3)

NOM

X509_STORE_load_locations, X509_STORE_set_default_paths, X509_STORE_load_mem, X509_STORE_add_lookup — configure les fichiers et répertoires utilisés par un magasin de certificats

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/x509_vfy.h>

int
X509_STORE_load_locations(X509_STORE *store, const char *file, const char *dirs);

int
X509_STORE_set_default_paths(X509_STORE *store);

int
X509_STORE_load_mem(X509_STORE *store, void *buffer, int length);

X509_LOOKUP *
X509_STORE_add_lookup(X509_STORE *store, const X509_LOOKUP_METHOD *method);

DESCRIPTION

X509_STORE_load_locations() demande au store d'utiliser le fichier PEM file et tous les fichiers PEM des répertoires contenus dans la liste séparée par des deux-points dirs pour la recherche de certificats, en plus des fichiers et répertoires déjà configurés. Les certificats dans les répertoires doivent être sous forme hachée, comme documenté dans X509_LOOKUP_hash_dir(3). Les répertoires déjà utilisés ne sont pas ajoutés à nouveau. Si NULL est passé pour file ou dirs, aucun nouveau fichier ou aucun nouveau répertoire n'est ajouté, respectivement.

X509_STORE_load_locations() est identique à SSL_CTX_load_verify_locations(3) sauf qu'elle opère directement sur un objet X509_STORE, plutôt que sur le magasin utilisé par un contexte SSL. Voir cette page de manuel pour plus d'informations.

X509_STORE_set_default_paths() est similaire, sauf qu'elle demande au store d'utiliser le fichier et le répertoire PEM par défaut (comme documenté dans FICHIERS) en plus de ce qui est déjà configuré. Elle ignore les erreurs qui se produisent lors de la tentative de chargement du fichier ou d'ajout du répertoire, mais elle peut quand même échouer pour d'autres raisons, par exemple lors d'une manque de mémoire en essayant d'allouer les objets X509_LOOKUP requis.

X509_STORE_set_default_paths() est identique à SSL_CTX_set_default_verify_paths(3) sauf qu'elle opère directement sur un objet X509_STORE, plutôt que sur le magasin utilisé par un contexte SSL. Voir cette page de manuel pour plus d'informations.

Les fonctions ci-dessus sont des enveloppes autour de X509_LOOKUP_load_file(3) et X509_LOOKUP_add_dir(3).

X509_STORE_load_mem() demande au store d'utiliser les certificats contenus dans le buffer de mémoire de la longueur donnée pour la recherche de certificats. C'est une enveloppe autour de X509_LOOKUP_add_mem(3).

X509_STORE_add_lookup() vérifie si le store contient déjà un objet X509_LOOKUP utilisant la méthode method donnée ; si c'est le cas, l'objet existant est retourné et aucune autre action n'est effectuée. Sinon, un nouvel objet X509_LOOKUP est alloué, ajouté et retourné. Cette fonction est utilisée en interne par toutes les fonctions listées ci-dessus.

VALEURS DE RETOUR

X509_STORE_load_locations() retourne 1 si tous les fichiers et répertoires spécifiés ont été ajoutés avec succès. Elle retourne 0 en cas d'échec. Cela peut se produire si l'ajout du fichier a échoué, si l'ajout de l'un des répertoires a échoué, ou si les deux arguments étaient NULL.

X509_STORE_set_default_paths() retourne 0 pour certaines conditions d'erreur et 1 sinon, pas seulement pour le succès, mais aussi pour divers cas d'échec.

X509_STORE_load_mem() retourne 1 en cas de succès ou 0 en cas d'échec. En particulier, les erreurs d'analyse ou le manque de mémoire peuvent causer l'échec.

X509_STORE_add_lookup() retourne l'objet de recherche existant ou nouveau, ou NULL en cas d'échec. Il s'agit d'un pointeur interne qui ne doit pas être libéré. Avec LibreSSL, la seule raison d'échec est le manque de mémoire.

FICHIERS

/etc/ssl/cert.pem
fichier PEM par défaut pour X509_STORE_set_default_paths()
/etc/ssl/certs/
répertoire par défaut pour X509_STORE_set_default_paths()

VOIR AUSSI

SSL_CTX_load_verify_locations(3), X509_load_cert_file(3), X509_LOOKUP_hash_dir(3), X509_LOOKUP_new(3), X509_STORE_new(3), X509_STORE_set1_param(3), X509_STORE_set_verify_cb(3)

HISTORIQUE

X509_STORE_load_locations(), X509_STORE_set_default_paths(), et X509_STORE_add_lookup() sont apparus pour la première fois dans SSLeay 0.8.0 et sont disponibles depuis OpenBSD 2.4.

X509_STORE_load_mem() est apparu pour la première fois dans OpenBSD 5.7.

BOGUES

Au moment où l'ajout d'un répertoire est constaté comme ayant échoué, le fichier et certains autres répertoires peuvent déjà avoir été chargés avec succès, donc ces fonctions peuvent changer l'état du magasin même lorsqu'elles échouent.

X509_STORE_set_default_paths() efface la file d'attente des erreurs, supprimant même les informations d'erreur qui étaient déjà présentes lors de son appel.
