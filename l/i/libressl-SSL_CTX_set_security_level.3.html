SSL_CTX_SET_SECURITY_LEVEL(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_SECURITY_LEVEL(3)

NOM

SSL_CTX_set_security_level, SSL_set_security_level, SSL_CTX_get_security_level, SSL_get_security_level — modifier le niveau de sécurité pour TLS

SYNOPSIS

bibliothèque « libssl »
#include <openssl/ssl.h>

void
SSL_CTX_set_security_level(SSL_CTX *ctx, int level);

void
SSL_set_security_level(SSL *s, int level);

int
SSL_CTX_get_security_level(const SSL_CTX *ctx);

int
SSL_get_security_level(const SSL *s);

DESCRIPTION

Un niveau de sécurité est un ensemble de restrictions sur les algorithmes, les longueurs de clés, les versions de protocole et d'autres fonctionnalités des connexions TLS. Ces restrictions s'ajoutent à celles qui existent lors de la sélection individuelle des fonctionnalités prises en charge, par exemple les chiffrements, les courbes ou les algorithmes.

Le tableau suivant montre les propriétés des différents niveaux de sécurité :

# sec   RSA ECC TLS MAC
0   0     0   0 1.0 MD5
1  80  1024 160 1.0 RC4
2 112  2048 224 1.0
3 128  3072 256 1.1 SHA1
4 192  7680 384 1.2
5 256 15360 512 1.2

La signification des colonnes est la suivante :

#
Le numéro du niveau.
sec
La force de sécurité minimale mesurée en bits, qui est approximativement le logarithme binaire du nombre d'opérations qu'un attaquant doit effectuer pour casser une clé cryptographique. Cette force minimale est appliquée à tous les paramètres pertinents, y compris les algorithmes de chiffrement des suites de chiffrement, les courbes ECC, les algorithmes de signature, les tailles de paramètres DH, et les algorithmes et tailles de clés de certificat. Voir SP800-57 ci-dessous VOIR AUSSI pour les détails sur les algorithmes individuels.
RSA
La longueur de clé minimale en bits pour les algorithmes RSA et DH.
ECC
La longueur de clé minimale en bits pour les algorithmes ECC.
TLS
La version minimale du protocole TLS.
MAC
Les suites de chiffrement utilisant les MAC donnés sont autorisées à ce niveau et aux niveaux inférieurs, mais pas aux niveaux supérieurs.

Le niveau 0 est fourni uniquement pour des raisons de compatibilité descendante et autorise tout.

Les niveaux 3 et supérieurs désactivent le support des tickets de session et n'acceptent que les suites de chiffrement qui fournissent une sécurité future (forward secrecy).

Les fonctions SSL_CTX_set_security_level() et SSL_set_security_level() choisissent le niveau de sécurité pour ctx ou s, respectivement. S'il n'est pas défini, le niveau de sécurité 1 est utilisé.

SSL_CTX_new(3) initialise le niveau de sécurité du nouvel objet à 1.

SSL_new(3) et SSL_set_SSL_CTX(3) copient le niveau de sécurité du contexte vers l'objet SSL.

SSL_dup(3) copie le niveau de sécurité de l'ancien objet vers le nouveau.

VALEURS DE RETOUR

SSL_CTX_get_security_level() et SSL_get_security_level() retournent le niveau de sécurité configuré dans ctx ou s, respectivement.

VOIR AUSSI

EVP_PKEY_security_bits(3), RSA_security_bits(3), ssl(3), SSL_CTX_new(3), SSL_new(3)

Elaine Barker, Recommendation for Key Management, U.S. National Institute of Standards and Technology, NIST Special Publication 800-57 Part 1 Revision 5, https://doi.org/10.6028/NIST.SP.800-57pt1r5, Gaithersburg, MD, Mai 2020.

HISTORIQUE

Ces fonctions sont apparues pour la première fois dans OpenSSL 1.1.0 et sont disponibles depuis OpenBSD 7.2.

ATTENTION

Les applications qui ne vérifient pas les valeurs de retour des fonctions de configuration se comporteront mal. Par exemple, si une application ne vérifie pas la valeur de retour après avoir essayé de définir un certificat et que le certificat est rejeté en raison du niveau de sécurité, l'application peut se comporter comme si aucun certificat n'avait été fourni.

Bien que certaines restrictions puissent être gérées avec succès par les négociations entre le client et le serveur, d'autres restrictions peuvent être fatales et provoquer l'échec de la négociation TLS. Par exemple, cela peut se produire si le certificat du pair contient une clé trop courte ou si la taille des paramètres DH est trop petite.
