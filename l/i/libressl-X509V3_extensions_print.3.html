libressl-X509V3_extensions_print(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

X509V3_EXTENSIONS_PRINT(3) Manuel des fonctions de bibliothèque X509V3_EXTENSIONS_PRINT(3)

NOM

X509V3_extensions_print — imprime joliment un tableau d'extensions X.509

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/x509v3.h>

int
X509V3_extensions_print(BIO *bio, char *title, const STACK_OF(X509_EXTENSION) *sk, unsigned long flags, int indent);

DESCRIPTION

Pour chaque membre du tableau de taille variable sk, X509V3_extensions_print() imprime les informations suivantes sur bio dans l'ordre suivant :

  • Le type d'extension tel qu'imprimé par i2a_ASN1_OBJECT(3).
  • Si l'extension est critique, la chaîne fixe "critical".
  • Une représentation lisible par l'homme des données contenues dans l'extension, telle qu'imprimée par X509V3_EXT_print(3), en passant les flags. Si cette fonction indique un échec, les données encodées BER de l'extension sont déchargées avec ASN1_STRING_print(3) sans les décoder d'abord. Dans les deux cas, une indentation augmentée de 4 espaces est utilisée.

Si sk est un pointeur NULL ou est vide, X509V3_extensions_print() n'imprime rien et indique le succès.

À moins que title ne soit NULL, il est imprimé sur sa propre ligne de sortie avant le reste de la sortie, et indent est augmenté de 4 espaces. Cette indentation globale supplémentaire est cumulative avec celle appliquée aux extensions individuelles mentionnées ci-dessus.

VALEURS DE RETOUR

X509V3_extensions_print() est censé retourner 1 en cas de succès ou 0 en cas d'erreur.

VOIR AUSSI

BIO_new(3), STACK_OF(3), X509_EXTENSION_get_critical(3), X509_get0_extensions(3), X509_get_ext(3), X509V3_EXT_print(3)

HISTORIQUE

X509V3_extensions_print() est apparu pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

BOGUES

De nombreuses erreurs d'analyse et d'impression sont ignorées silencieusement, et la fonction peut retourner un succès même si sk contient des données invalides. Même si toutes les données sont valides, un succès peut être indiqué même lorsque les informations imprimées sont incomplètes pour diverses raisons, par exemple en raison d'échecs d'allocation mémoire ou d'erreurs d'E/S.
