libvirtd(8) Support de la virtualisation libvirtd(8)

Nom

libvirtd - démon de gestion de libvirt

Syntaxe

libvirtd [OPTION]...

Description

Le programme libvirtd est le composant serveur du système de gestion de la virtualisation libvirt.

Ce démon s'exécute sur les serveurs hôtes et effectue les tâches de gestion requises pour les invités virtualisés. Cela inclut des activités telles que le démarrage, l'arrêt et la migration des invités entre les serveurs hôtes, la configuration et la manipulation des réseaux, et la gestion du stockage à utiliser par les invités.

Les bibliothèques clientes et les utilitaires de libvirt se connectent à ce démon pour émettre des tâches et collecter des informations sur la configuration et les ressources du système hôte et des invités.

Par défaut, le démon libvirtd écoute les requêtes sur un socket de domaine Unix local. En utilisant l'option de ligne de commande -l | --listen, le démon libvirtd peut être instruit pour écouter également sur un socket TCP/IP. Le socket TCP/IP à utiliser est défini dans le fichier de configuration de libvirtd.

Redémarrer libvirtd n'a pas d'impact sur les invités en cours d'exécution. Les invités continuent de fonctionner et seront automatiquement pris en compte si leur configuration XML a été définie. Tous les invités dont la configuration XML n'a pas été définie seront perdus de la configuration.

Activation par socket système

Le démon libvirtd est capable de démarrer dans deux modes.

En mode traditionnel, il créera et écoutera lui-même sur les sockets UNIX. Si le paramètre --listen est donné, il écoutera également sur les sockets TCP/IP, conformément aux options listen_tcp et listen_tls dans /etc/libvirt/libvirtd.conf

En mode d'activation par socket, il s'appuiera sur systemd pour créer et écouter sur les sockets UNIX, et éventuellement TCP/IP, et les lui passer sous forme de descripteurs de fichiers pré-ouverts. Dans ce mode, il n'est pas permis de passer le paramètre --listen, et la plupart des options de configuration relatives aux sockets dans /etc/libvirt/libvirtd.conf n'auront plus d'effet. Pour activer les sockets TCP ou TLS, utilisez soit

$ systemctl start libvirtd-tls.socket

Ou

$ systemctl start libvirtd-tcp.socket

Le mode d'activation par socket est généralement le mode par défaut lorsqu'il fonctionne sur un système d'exploitation hôte qui utilise systemd. Pour revenir au mode traditionnel, tous les fichiers d'unité de socket doivent être masqués :

$ systemctl mask libvirtd.socket libvirtd-ro.socket \
   libvirtd-admin.socket libvirtd-tls.socket libvirtd-tcp.socket

En plus de cela, assurez-vous que l'argument --timeout n'est pas utilisé pour le démon, car il ne serait pas démarré lors de toute connexion ultérieure.

Si vous utilisez le service libvirt-guests, l'ordre de ce service doit être adapté afin qu'il soit ordonné après l'unité de service au lieu de l'unité de socket. Étant donné que les dépendances et l'ordre ne peuvent pas être modifiés avec des remplacements drop-in, le fichier d'unité libvirt-guests dans son intégralité doit être modifié. Afin de préserver un tel changement, copiez le fichier d'unité installé /usr/lib/systemd/system/libvirt-guests.service vers /etc/systemd/system/libvirt-guests.service et apportez la modification là-bas, en particulier assurez-vous que le classement After= mentionne libvirtd.service et non libvirtd.socket :

[Unit]
After=libvirtd.service

Options

-h, --help

Affiche l'aide d'utilisation de la ligne de commande puis quitte.

-d, --daemon

S'exécute en tant que démon et écrit le fichier PID.

-f, --config *FICHIER*

Utilise ce fichier de configuration, en remplaçant la valeur par défaut.

-l, --listen

Écoute les connexions TCP/IP. Ceci ne doit pas être défini si vous utilisez l'activation par socket systemd. Activez plutôt les fichiers d'unité libvirtd-tls.socket ou libvirtd-tcp.socket.

-p, --pid-file *FICHIER*

Utilise ce nom pour le fichier PID, en remplaçant la valeur par défaut.

-t, --timeout *SECONDES*

Quitte après une période de délai d'attente (en secondes), à condition qu'il n'y ait ni connexions client ni domaines en cours d'exécution.

-v, --verbose

Active la sortie des messages détaillés.

--version

Affiche les informations de version puis quitte.

Signaux

Lors de la réception de SIGHUP, libvirtd recharge sa configuration.

Fichiers

Lors de l'exécution en tant que root

•
/etc/libvirt/libvirtd.conf

Le fichier de configuration par défaut utilisé par libvirtd, sauf remplacement sur la ligne de commande via l'option -f | --config.

Selon le pilote installé, les fichiers suivants sont également lus :

  • /etc/libvirt/qemu.conf pour le pilote QEMU
  • /etc/libvirt/lxc.conf pour le pilote LXC
  • /etc/libvirt/libxl.conf pour le pilote libxl

Ces fichiers contiennent divers réglages et valeurs par défaut pour les machines virtuelles créées dans leurs pilotes respectifs, et offrent un moyen de remplacer les valeurs par défaut intégrées, par exemple (mais sans s'y limiter) : les chemins vers divers binaires supplémentaires, l'emplacement des certificats TLS, la configuration des consoles graphiques et autres. L'emplacement d'aucun de ces fichiers ne peut être remplacé par un quelconque commutateur de ligne de commande.

  • /run/libvirt/libvirt-sock
  • /run/libvirt/libvirt-sock-ro

Les sockets sur lesquels libvirtd écoutera.

•
/etc/pki/CA/cacert.pem

Le certificat de l'autorité de certification TLS que libvirtd utilisera.

•
/etc/pki/libvirt/servercert.pem

Le certificat du serveur TLS que libvirtd utilisera.

•
/etc/pki/libvirt/private/serverkey.pem

La clé privée du serveur TLS que libvirtd utilisera.

•
/run/libvirtd.pid

Le fichier PID à utiliser, sauf remplacement par l'option -p | --pid-file.

Lors de l'exécution en tant que non-root

•
$XDG_CONFIG_HOME/libvirt/libvirtd.conf

Le fichier de configuration par défaut utilisé par libvirtd, sauf remplacement sur la ligne de commande via l'option -f``|--config``.

Si le pilote QEMU est installé, le fichier suivant est également lu :

•
$XDG_CONFIG_HOME/libvirt/qemu.conf

Si le fichier existe, il peut contenir divers réglages et valeurs par défaut pour les machines virtuelles créées dans le pilote QEMU, et offre un moyen de remplacer les valeurs par défaut intégrées, par exemple (mais sans s'y limiter) : les chemins vers divers binaires supplémentaires, l'emplacement des certificats TLS, la configuration des consoles graphiques et autres. L'emplacement de ce fichier ne peut être remplacé par aucun commutateur de ligne de commande.

•
$XDG_RUNTIME_DIR/libvirt/libvirt-sock

Le socket sur lequel libvirtd écoutera.

•
$HOME/.pki/libvirt/cacert.pem

Le certificat de l'autorité de certification TLS que libvirtd utilisera.

•
$HOME/.pki/libvirt/servercert.pem

Le certificat du serveur TLS que libvirtd utilisera.

•
$HOME/.pki/libvirt/serverkey.pem

La clé privée du serveur TLS que libvirtd utilisera.

&#x 2022;
$XDG_RUNTIME_DIR/libvirt/libvirtd.pid

Le fichier PID à utiliser, sauf s'il est remplacé par l'option -p``|--pid-file``.

Si $XDG_CONFIG_HOME n'est pas défini dans votre environnement, libvirtd utilisera $HOME/.config

Si $XDG_RUNTIME_DIR n'est pas défini dans votre environnement, libvirtd utilisera $HOME/.cache

EXEMPLES

Pour récupérer la version de libvirtd :

# libvirtd --version
libvirtd (libvirt) 11.10.0

Pour démarrer libvirtd, en lui demandant de se démoniaquer et de créer un fichier PID :

# libvirtd -d
# ls -la /run/libvirtd.pid
-rw-r--r-- 1 root root 6 Juil  9 02:40 /run/libvirtd.pid
