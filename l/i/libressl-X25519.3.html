X25519(3) Manuel des fonctions de bibliothèque X25519(3)

NOM

X25519, X25519_keypair, ED25519_keypair, ED25519_sign, ED25519_verify — Primitives de clé Diffie-Hellman elliptique et de signature basées sur Curve25519

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/curve25519.h>

int
X25519(uint8_t out_shared_key[X25519_KEY_LENGTH], const uint8_t private_key[X25519_KEY_LENGTH], const uint8_t peer_public_value[X25519_KEY_LENGTH]);

void
X25519_keypair(uint8_t out_public_value[X25519_KEY_LENGTH], uint8_t out_private_key[X25519_KEY_LENGTH]);

void
ED25519_keypair(uint8_t out_public_key[ED25519_PUBLIC_KEY_LENGTH], uint8_t out_private_key[ED25519_PRIVATE_KEY_LENGTH]);

int
ED25519_sign(uint8_t *out_sig, const uint8_t *message, size_t message_len, const uint8_t public_key[ED25519_PUBLIC_KEY_LENGTH], const uint8_t private_key_seed[ED25519_PRIVATE_KEY_LENGTH]);

int
ED25519_verify(const uint8_t *message, size_t message_len, const uint8_t signature[ED25519_SIGNATURE_LENGTH], const uint8_t public_key[ED25519_PUBLIC_KEY_LENGTH]);

DESCRIPTION

Curve25519 est une courbe elliptique sur un corps premier spécifié dans la RFC 7748 section 4.1. Le corps premier est défini par le nombre premier 2^255 - 19.

X25519 est la primitive Diffie-Hellman construite à partir de Curve25519 telle que décrite dans la RFC 7748 section 5. La section 6.1 décrit son utilisation prévue dans un protocole Diffie-Hellman sur courbe elliptique (ECDH).

X25519() écrit une clé partagée dans out_shared_key qui est calculée à partir de la private_key donnée et de la peer_public_value par multiplication scalaire. N'utilisez pas la clé partagée directement, mais utilisez plutôt une fonction de dérivation de clé et incluez également les deux valeurs publiques comme entrées.

X25519_keypair() définit out_public_value et out_private_key à une paire clé publique/clé privée fraîchement générée. Premièrement, la out_private_key est générée avec arc4random_buf(3). Ensuite, l'inverse du masquage décrit dans la RFC 7748 section 5 lui est appliqué pour s'assurer que la clé privée générée n'est jamais correctement masquée. Le but est de provoquer des échecs cohérents chez les implémentations incorrectes du pair. Les implémentations correctes décoderont la clé correctement même lorsqu'elle n'est pas correctement masquée. Enfin, la out_public_value est calculée à partir de la out_private_key en la multipliant par le point de base de Montgomery uint8_t u[32] = {9}.

La taille d'une clé publique et d'une clé privée est X25519_KEY_LENGTH = 32 octets chacune.

Ed25519 est un schéma de signature utilisant une courbe Edwards tordue qui est birationnellement équivalente à Curve25519.

ED25519_keypair() définit out_public_key et out_private_key à une paire clé publique/clé privée fraîchement générée. Premièrement, la out_private_key est générée avec arc4random_buf(3). Ensuite, la out_public_key est calculée à partir de la clé privée.

ED25519_sign() signe le message de message_len octets en utilisant la public_key et la private_key et écrit la signature dans out_sig.

ED25519_verify() vérifie que la signature du message de message_len octets en utilisant la public_key aboutirait effectivement à la signature donnée.

Les tailles d'une clé publique et d'une clé privée sont ED25519_PUBLIC_KEY_LENGTH et ED25519_PRIVATE_KEY_LENGTH, qui sont toutes deux de 32 octets, et la taille d'une signature est ED25519_SIGNATURE_LENGTH = 64 octets.

VALEURS DE RETOUR

X25519() et ED25519_sign() retournent 1 en cas de succès ou 0 en cas d'erreur. X25519() peut échouer si l'entrée est un point d'ordre petit. ED25519_sign() réussit toujours dans LibreSSL, mais l'API réserve la valeur de retour 0 pour un échec d'allocation mémoire.

ED25519_verify() retourne 1 si la signature est valide ou 0 sinon.
