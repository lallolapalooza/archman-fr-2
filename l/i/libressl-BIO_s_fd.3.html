BIO_S_FD(3) Manuel des fonctions de bibliothèque BIO_S_FD(3)

NOM

BIO_s_fd, BIO_set_fd, BIO_get_fd, BIO_new_fd, BIO_fd_non_fatal_error, BIO_fd_should_retry — Descripteur de fichier BIO

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/bio.h>

const BIO_METHOD *
BIO_s_fd(void);

long
BIO_set_fd(BIO *b, int fd, long close_flag);

long
BIO_get_fd(BIO *b, int *c);

BIO *
BIO_new_fd(int fd, int close_flag);

int
BIO_fd_non_fatal_error(int errnum);

int
BIO_fd_should_retry(int retval);

DESCRIPTION

BIO_s_fd() renvoie la méthode BIO du descripteur de fichier. Il s'agit d'une enveloppe autour des routines du descripteur de fichier de la plateforme telles que read(2) et write(2).

BIO_read(3) et BIO_write(3) lisent ou écrivent le descripteur sous-jacent. BIO_puts(3) est pris en charge mais BIO_gets(3) ne l'est pas.

Si l'indicateur de fermeture est défini, close(2) est appelé sur le descripteur de fichier sous-jacent lorsque le BIO est libéré.

BIO_reset(3) tente de positionner le pointeur de fichier au début du fichier à l'aide de lseek(fd, 0, 0).

BIO_seek(3) définit le pointeur de fichier à la position ofs à partir du début du fichier en utilisant lseek(fd, ofs, 0).

BIO_tell(3) renvoie la position actuelle du fichier en appelant lseek(fd, 0, 1).

BIO_set_fd() définit le descripteur de fichier de BIO b à fd et l'indicateur de fermeture à close_flag.

BIO_get_fd() place le descripteur de fichier dans c s'il n'est pas NULL et renvoie également le descripteur de fichier.

BIO_new_fd() renvoie un BIO de descripteur de fichier utilisant fd et close_flag.

BIO_fd_non_fatal_error() détermine si le code d'état d'erreur errnum représente une erreur récupérable. BIO_fd_should_retry() détermine si une erreur récupérable s'est produite en inspectant à la fois errno(2) et retval, qui est censé être généralement la valeur de retour d'une fonction précédemment appelée comme BIO_read(3) ou BIO_write(3). Ces deux fonctions sont principalement utilisées en interne ; dans le code applicatif, il est généralement plus facile et plus robuste d'utiliser BIO_should_retry(3), qui fonctionne pour tout type de BIO.

Le comportement de BIO_read(3) et BIO_write(3) dépend du comportement des appels read(2) et write(2) de la plateforme sur le descripteur. Si le descripteur de fichier sous-jacent est en mode non bloquant, alors le BIO se comportera comme décrit dans les pages de manuel de BIO_read(3) et BIO_should_retry(3).

Les BIO de descripteurs de fichier ne doivent pas être utilisés pour les E/S de socket. Utilisez plutôt les BIO de socket.

BIO_ctrl(3) cmd les arguments correspondent aux macros comme suit :

cmd constante macro correspondante
BIO_C_FILE_SEEK BIO_seek(3)
BIO_C_FILE_TELL BIO_tell(3)
BIO_C_GET_FD BIO_get_fd()
BIO_C_SET_FD BIO_set_fd()
BIO_CTRL_GET_CLOSE BIO_get_close(3)
BIO_CTRL_RESET BIO_reset(3)
BIO_CTRL_SET_CLOSE BIO_set_close(3)

VALEURS DE RETOUR

BIO_s_fd() renvoie la méthode BIO du descripteur de fichier.

Lorsqu'elle est appelée sur un objet BIO de descripteur de fichier, BIO_method_type(3) renvoie la constante BIO_TYPE_FD et BIO_method_name(3) renvoie un pointeur vers la chaîne statique "file descriptor".

BIO_set_fd() renvoie toujours 1.

BIO_get_fd() renvoie le descripteur de fichier ou -1 si le BIO n'a pas été initialisé.

BIO_new_fd() renvoie le nouveau BIO alloué ou NULL en cas d'erreur.

BIO_fd_non_fatal_error() renvoie 1 si errnum est EAGAIN, EALREADY, EINPROGRESS, EINTR, ou ENOTCONN et 0 sinon, même si errnum est 0.

BIO_fd_should_retry() renvoie 1 si BIO_fd_non_fatal_error(errno) est 1 et retval est soit 0 soit -1, ou 0 sinon.

EXEMPLES

Ceci est une version BIO de descripteur de fichier de "Hello World" :

BIO *out;
out = BIO_new_fd(fileno(stdout), BIO_NOCLOSE);
BIO_printf(out, "Hello World\n");
BIO_free(out);
