DESCRIPTION

libsox_ng est une bibliothèque de lecteurs/scripteurs de formats de fichiers d'échantillons sonores et de processeurs d'effets sonores. Elle est principalement développée pour être utilisée par SoX, mais toute application audio peut la trouver utile.

Ceci n'est pas vraiment un manuel pour l'API libsox_ng ; c'est une introduction aux opérations de base pour lire et écrire des fichiers audio et comment utiliser les chaînes d'effets, suivie de notes sur la façon d'écrire de nouveaux gestionnaires de formats et effets. Pour une description exhaustive de l'API libsox_ng, voir http://martinwguy.net/test/soxygen/sox_8h.html

int sox_format_init(void)
sox_format_init() effectue l'initialisation requise par tous les gestionnaires de formats de fichiers. Si compilé avec le support des bibliothèques dynamiques, cela détectera et initialisera toutes les bibliothèques externes. Elle doit être appelée avant toute opération sur les fichiers.
void sox_format_quit(void)
sox_format_quit() effectue le nettoyage lié à tous les gestionnaires de formats de fichiers et doit être appelée après la fin de toutes les opérations sur les fichiers.
sox_format_t *sox_open_read(char const *path, sox_signalinfo_t const *signal, sox_encodinginfo_t const *encoding, char const *filetype)
sox_open_read() ouvre un fichier en lecture. Un nom spécial `-' lit les données depuis stdin. Si signal n'est pas NULL, il spécifie les propriétés du signal audio telles que la fréquence d'échantillonnage ou le nombre de canaux. Si encoding n'est pas NULL, il spécifie l'encodage de l'échantillon. signal et encoding ne sont normalement nécessaires que pour les fichiers audio sans en-tête où ces informations ne sont pas stockées dans le fichier. Si filetype n'est pas NULL, il spécifie le type de fichier en utilisant les chaînes courtes listées dans soxformat_ng(7) ; sinon, le type de fichier est deviné à partir de l'extension du nom de fichier et/ou du contenu du fichier.

En cas de succès, sox_open_read() renvoie un pointeur vers une structure sox_format_t remplie, qui doit finalement être fermée avec sox_close(), ou NULL sinon. Actuellement, il n'y a aucun moyen de déterminer la raison de l'échec, à part le message d'erreur affiché sur la sortie d'erreur standard (stderr).

sox_format_t *sox_open_write(char const *filename, sox_signalinfo_t const *signal, sox_encodinginfo_t const *encoding, char const *filetype, sox_oob_t const *oob, sox_bool (*overwrite_permitted)(char const *filename))
sox_open_write() ouvre le fichier nommé en écriture. Un nom spécial `-' écrit les données sur stdout. Si signal n'est pas NULL, il spécifie le format des données du fichier de sortie ; la structure signal remplie par sox_open_read() peut être utilisée pour copier des données dans le même format. Si encoding n'est pas NULL, il spécifie l'encodage d'échantillon souhaité. Étant donné que la plupart des formats de fichiers peuvent encoder des données de différentes manières, cela doit généralement être spécifié ; s'il est NULL, une valeur par défaut est utilisée. Si filetype n'est pas NULL, il spécifie le type de fichier à écrire, en utilisant les chaînes courtes listées dans soxformat_ng(7) ; sinon, le type de fichier est celui de l'extension du nom de fichier. Si oob n'est pas NULL et que le type de fichier prend en charge les commentaires et autres données hors bande comme les points de boucle et les informations d'instrument, ceux-ci sont stockés dans l'en-tête du fichier. Si overwrite n'est pas NULL et que le fichier existe déjà, la fonction est appelée avec le nom du fichier comme argument pour déterminer si le fichier doit être écrasé. S'il est NULL, les fichiers existants sont écrasés.

sox_open_write() renvoie un pointeur vers une sox_format_t qui doit être fermée avec sox_close(), ou NULL en cas d'échec. Comme sox_open_read(), il n'y a aucun moyen de déterminer la raison de l'échec, à part les messages qu'elle affiche.

size_t sox_read(sox_format_t *format, sox_sample_t *buf, size_t len)
sox_read() lit len échantillons dans buf en utilisant le gestionnaire de format spécifié par format. Il est de la responsabilité de l'appelant de fournir un tampon suffisamment grand pour len échantillons. Toutes les données sont converties en échantillons signés 32 bits avant d'être placées dans buf. La valeur de len est le nombre total d'échantillons (nombre d'images d'échantillons multiplié par le nombre de canaux) et si sa valeur n'est pas un multiple du nombre de canaux, tout peut arriver.

Elle renvoie le nombre d'échantillons lus, qui peut être inférieur au nombre demandé, ou zéro à la fin du fichier ou en cas d'erreur. La valeur de retour de sox_read() ne distingue pas la fin d'un fichier d'une erreur, mais vous pouvez inspecter format->sox_errno pour faire la différence. Elle devrait être SOX_SUCCESS ou SOX_EOF à moins qu'une autre erreur ne se soit produite auparavant ; vous pouvez effacer format->sox_errno à 0 au préalable pour être sûr et, si ce n'est pas SOX_SUCCESS, il y aura une raison plus explicite dans format->sox_errstr.

size_t sox_read(sox_format_t *format, sox_sample_t *buf, size_t len)
sox_read() renvoie le nombre d'échantillons lus avec succès. En cas d'erreur ou d'atteinte de la fin du fichier, la valeur de retour est zéro ou SOX_EOF, selon la fonction.
size_t sox_write(sox_format_t *format, sox_sample_t const *buf, size_t len)
sox_write() écrit len échantillons depuis buf dans le fichier décrit par format et les données signées 32 bits dans buf sont converties selon le format. La valeur de len est le nombre total d'échantillons et doit être divisible par le nombre de canaux, sinon des choses inattendues se produiront. Elle renvoie le nombre réel d'échantillons encodés, zéro en cas d'erreur.
int sox_seek(sox_format_t *format, size_t offset, int whence)
sox_seek() repositionne le décalage du fichier associé à format au offset donné. En cas de succès, elle renvoie SOX_SUCCESS ; SOX_EOF sinon. Étant donné que sox_read() et sox_write() effectuent des transformations complexes des données des fichiers, son utilité est discutable.
int sox_close(sox_format_t *format)
sox_close() dissocie un format de son fichier sous-jacent. Si le gestionnaire de format était utilisé pour la sortie, toutes les données mises en mémoire tampon sont d'abord écrites. Il renvoie SOX_SUCCESS si tout s'est bien passé ; sinon, SOX_EOF ou, occasionnellement, un autre code d'erreur. Comme sox_open_read() et sox_open_write(), il n'y a actuellement aucun moyen de déterminer la raison précise de l'échec, à part les messages imprimés sur stderr. Dans les deux cas, aucune autre utilisation ne doit être faite du descripteur, pas même un autre appel à sox_close().

sox_find_effect() renvoie un pointeur vers le gestionnaire de l'effet nommé s'il existe, NULL sinon.
sox_effect_t *sox_create_effect(sox_effect_handler_t const *effect)
sox_create_effect() instancie un effet dans une sox_effect_t à partir de son handler. Toutes les méthodes manquantes sont automatiquement définies sur la méthode nothing appropriée. Elle renvoie un pointeur vers le nouvel effet ou NULL s'il n'a pas été trouvé ou s'il y a eu des problèmes au démarrage.
int sox_effect_options(sox_effect_t *effect, int argc, char * const argv[])
sox_effect_options() transmet des options à un effet pour contrôler son comportement. Si elle réussit, effect->in_signal doit contenir le débit et le nombre de canaux des données d'entrée qu'il requiert et effect->out_signal le débit et le nombre de canaux qu'il produit. Lorsqu'il est présent, ces informations sont utilisées pour s'assurer que les effets appropriés sont placés dans la chaîne d'effets pour gérer les conversions nécessaires. Elle renvoie le nombre d'arguments consommés ou SOX_EOF si des options invalides ont été passées.

La définition des options n'est prise en charge qu'avant le démarrage de l'effet. Le comportement n'est pas défini si elle est appelée alors que l'effet a déjà démarré.

sox_effects_chain_t *sox_create_effects_chain(sox_encodinginfo_t const *in_enc, sox_encodinginfo_t const *out_enc)
sox_create_effects_chain() crée une chaîne d'effets à laquelle des effets peuvent être ajoutés. in_enc et out_enc sont l'encodage du signal de l'entrée et de la sortie de la chaîne. Les pointeurs vers in_enc et out_enc sont stockés en interne, donc leur mémoire ne doit pas être libérée tant que la chaîne d'effets n'a pas été supprimée. Leurs valeurs peuvent changer pour refléter les nouveaux encodages d'entrée ou de sortie lorsque les effets démarrent ou sont redémarrés. Elle renvoie un pointeur vers la nouvelle chaîne ou NULL si quelque chose s'est mal passé.

sox_add_effect ajoute un effet à une chaîne. in spécifie les informations du signal d'entrée pour l'effet, out est une suggestion

TYPES

sox_format_t
This structure holds all information related to an open audio file or stream, whether it is an input or output file. See FORMATS below.
sox_effects_chain_t
This structure holds all information related to a processing chain of effects. See EFFECTS below.

DESCRIPTION

The libsox_ng library provides an API for reading and writing audio files and processing audio data using effects. It uses an internal sample format of signed 32-bit integers (or floating point samples if requested) and handles the translation from various file encodings and sample rates to this internal format.

The library is structured around the concept of effects chains, where a sequence of audio processing effects can be applied to an input stream to produce an output stream.

The main functions are:

sox_format_t * sox_open_read(const char *filename, const sox_signal_t *signal, const sox_audio_format_t *format, const char *format_hint)
Opens an audio file for reading. filename is the path to the file. If signal is non-NULL, it specifies the desired signal characteristics (sample rate, channels, precision, encoding) of the audio data that will be read. Otherwise, the characteristics are determined from the file. If format is non-NULL, it specifies the desired audio format (e.g., sample rate, number of channels) for the internal buffers. If format_hint is provided, it is used to help identify the file format.
sox_format_t * sox_open_write(const char *filename, const sox_signal_t *signal, const sox_audio_format_t *format, const char *format_hint)
Opens an audio file for writing. filename is the path to the file. signal specifies the characteristics of the audio data that will be written. format specifies the desired audio format for the file header. format_hint can be used to suggest a file format.
int sox_read(sox_format_t * in, sox_sample_t * buf, int len)
Reads up to len samples from the input file stream in into the buffer buf. The samples are returned in the library's internal format (signed 32-bit integers, or floats if requested). Returns the number of samples actually read, or 0 if EOF is reached or an error occurs.
int sox_write(sox_format_t * out, const sox_sample_t * buf, int len)
Writes up to len samples from the buffer buf to the output file stream out. The samples are converted from the library's internal format to the file's format. Returns the number of samples actually written, or 0 if an error occurs.
int sox_seek(sox_format_t * in, int offset, int whence)
Seeks within an input audio file. offset and whence have the same meaning as for the standard C fseek() function, except that offset is in samples, not bytes. Note that seeking may not be supported for all file formats or streams. Returns 0 on success, non-zero on failure.
void sox_close(sox_format_t * sf)
Closes an opened audio file stream sf and frees any associated resources.
sox_effects_chain_t * sox_create_effects_chain(const sox_signal_t *signal)
Creates a new effects processing chain. The initial signal specifies the characteristics of the audio data that will enter the chain.
int sox_add_effect(sox_effects_chain_t * ecp, const char *const * argv)
Adds a new effect to the end of the effects chain ecp. argv is a NULL-terminated array of strings representing the effect name and its arguments, similar to the command line arguments passed to the SoX utility. The effect's output characteristics are determined by the effect itself, potentially changing the sample rate, number of channels, etc. These changes are propagated to subsequent effects.
int sox_effect_options(sox_effects_chain_t * ecp, int argc, const char *const * argv)
Sets options for the effects chain ecp before any effects are added. These options typically control global behaviour of the chain, such as specifying input or output file formats or sample rates.
int sox_flow_effects(sox_effects_chain_t * ecp, sox_format_t * in, sox_format_t * out)
Processes the audio data by passing it through the effects chain ecp from input file in to output file out. The initial signal characteristics of in are used to determine what output signal characteristics the first effect should expect. However, depending on the effect options given and on in, the effect may choose a different encoding such as changing the number of channels or the sample rate. Whatever output rate and channels the effect produces are written back to in ready to be passed to subsequent calls of sox_add_effect so that changes propagate to each new effect. It returns SOX_SUCCESS if it was successful.
void sox_delete_effects_chain(sox_effects_chain_t * ecp)
Closes down an effects chain and releases any resources reserved during the creation of the chain. It also deletes all the effects in the chain.

EXAMPLES

SoX includes skeleton C files to assist you in writing new formats (skelform.c) and effects (skeleff.c). New formats can often just deal with the header and then use raw.c's routines for reading and writing.

example0.c and example1.c are a good starting point to see how to write applications using libsox_ng and sox_ng.c itself is also a good reference.

INTERNALS

SoX's formats and effects operate with an internal sample format of signed 32-bit integers. The data processing routines are called with buffers of these samples and buffer sizes which refer to the number of samples processed, not the number of bytes. File readers translate input samples to signed 32-bit integers and return the number of samples read. For example, data in linear signed byte format is left-shifted 24 bits.

Representing samples as integers can cause problems when processing audio. For example, if an effect to mix down left and right channels into one monophonic channel were to use the obvious

   *obuf++ = (*ibuf++ + *ibuf++)/2;
distortion may occur since the intermediate addition can overflow 32 bits. 
   *obuf++ = *ibuf++/2 + *ibuf++/2;
would get round the overflow but at the expense of the least significant bit.

Stereo data is stored with the left and right speaker data in successive samples and quadraphonic data is stored left front, right front, left rear, right rear.

FORMATS

A format is responsible for translating between sound sample files and an internal buffer. The internal buffer is stored in signed longs with a fixed sampling rate. The format operates from two data structures: a format structure and a private structure.

The format structure contains a list of control parameters for the audio: sampling rate, data size (8, 16 or 32 bits), encoding (unsigned, signed, floating point etc.), and the number of sound channels. It also contains other state information: whether the sample file needs to be byte-swapped, whether sox_seek() will work, its suffix, its file stream pointer, its format pointer and the format's private structure.

The private area is a preallocated data array for the format to use however it wishes. It should have a defined data structure and cast the array to that structure. See voc.c for an example of the use of a private data area. voc.c has to track the number of samples it writes and, when finishing, seek back to the beginning of the file and write it into the header. The private area is usually not very large and some effects, such as echo, lsx_malloc() larger areas for delay lines and such.

A format has 6 routines:

startread
Set up the format parameters, read in a data header and do anything else that needs to be done.
read
Given a buffer and a length, read up to that many samples, transform them into signed long integers, and copy them into the buffer. It returns the number of samples actually read.
stopread
Do what needs to be done when it has finished reading.
startwrite
Set up the format parameters, maybe write out a data header and any other preliminaries for writing the format.
write
Given a buffer and a length, copy that many samples out of the buffer, convert them from signed longs to the appropriate data and write them to the file. If it can't write out all the samples, it will return a lesser number of samples.
stopwrite
Typically, fix up the file header or whatever else needs to be done.

EFFECTS

Each effect runs with one input and one output stream. An effect's implementation comprises six functions that may be called according to the following flow diagram:

LOOP (invocations with different parameters)
  getopts
  LOOP (invocations with the same parameters)
    LOOP (channels)
      start
    LOOP (while there is input audio to process)
      LOOP (channels)
        flow
    LOOP (while there is output audio to generate)
      LOOP (channels)
        drain
    LOOP (channels)
      stop
  kill
Functions that an effect does not need can be NULL. An effect that is marked `MCHAN' does not use the LOOP (channels) lines and must perform multiple channel processing inside the affected functions. Multiple effect instances may be processed in parallel.
getopts
is called with a character string argument list for the effect.
start
is called with the signal parameters for the input and output streams.
flow
is called with input and output data buffers, and (by reference) the input and output data buffer sizes. It processes the input buffer into the output buffer, and sets the size variables to the numbers of samples actually processed. It is under no obligation to read from the input buffer or write to the output buffer during the same call. If the call returns SOX_EOF, this means that the effect will not read any more data and can be used to switch to drain mode sooner.
drain
is called when there are no more input data samples. If the effect wishes to generate more data samples, it copies the generated data into the given buffer and returns the number of samples generated. If it fills the buffer, it will be called again; The echo effect uses this to fade away.
stop
is called when there are no more input samples and no more output samples to process. It is typically used to close or free resources such as memory and temporary files that were allocated during start. See echo.c for an example.
kill
is called to allow resources allocated by getopts to be released. See pad.c for an example.

LINKING

How you link against libsox_ng depends on how SoX was built on your system. For a static build, just link against the library. For a dynamic build, use libtool to link with the correct linker flags. See the libtool manual for details; basically, you use it like this:

   libtool --mode=link gcc -o prog /path/to/libsox_ng.la

DESCRIPTION

La bibliothèque libsox_ng est une bibliothèque logicielle qui permet aux applications de lire, écrire et traiter des fichiers audio. Elle fournit une interface de programmation d'application (API) de haut niveau pour la manipulation de fichiers audio et une API de bas niveau pour le traitement des effets audio.

Gestion des fichiers

Les fonctions sox_open_read et sox_open_write sont utilisées pour ouvrir des fichiers audio en lecture ou en écriture, respectivement. Elles prennent comme arguments le chemin du fichier, les caractéristiques du signal audio (fréquence d'échantillonnage, nombre de canaux, etc.) et le format du fichier. Si le format est omis (NULL), SoX essaiera de le détecter automatiquement.

Les fonctions sox_read et sox_write sont utilisées pour lire et écrire des échantillons audio dans un fichier ouvert. Elles fonctionnent avec des tableaux d'échantillons de type sox_sample_t. La taille de ces tableaux est spécifiée en nombre d'échantillons (pas en octets).

La fonction sox_close ferme un fichier audio ouvert et libère les ressources associées.

Gestion des erreurs

La fonction sox_get_error renvoie un message d'erreur décrivant la dernière erreur survenue. La fonction sox_set_error permet de définir un message d'erreur personnalisé.

La fonction sox_strerror est une fonction de style C standard qui convertit un code d'erreur numérique en une chaîne de caractères lisible.

Initialisation et nettoyage

La fonction sox_globals_init doit être appelée une fois avant d'utiliser la bibliothèque. Elle initialise les structures de données globales nécessaires. sox_globals_cleanup doit être appelée lorsque la bibliothèque n'est plus nécessaire pour libérer ces ressources.

Version

La fonction sox_version imprime la version de la bibliothèque SoX sur la sortie standard.

Traitement des effets

La bibliothèque SoX prend en charge une vaste gamme d'effets audio qui peuvent être appliqués aux flux audio. L'interface de traitement des effets est plus complexe et implique plusieurs étapes :

  • sox_num_effects(): Renvoie le nombre total d'effets disponibles.
  • sox_effect_list(): Renvoie une liste des effets disponibles.
  • sox_effect_lookup(name): Recherche un effet par son nom.
  • sox_effect_state_size(effect): Renvoie la taille de la structure d'état nécessaire pour un effet donné.
  • sox_effect_startup(effect, signal, args): Initialise l'effet avec les paramètres spécifiés (signal d'entrée, arguments).
  • sox_effect_process(effect, in, out, samples): Traite un bloc d'échantillons audio. in est le tampon d'entrée, out est le tampon de sortie, et samples est le nombre d'échantillons à traiter. L'effet peut renvoyer moins d'échantillons qu'il n'en reçoit.
  • sox_effect_drain(effect): Indique qu'il n'y a plus d'échantillons d'entrée. Certains effets (comme les réverbérations) peuvent avoir des échantillons de sortie supplémentaires à générer après cette étape.
  • sox_effect_end(effect): Nettoie l'état de l'effet et libère les ressources.

Pour une utilisation plus simple et plus abstraite, SoX propose des chaînes d'effets :

  • sox_effect_chain_prep(chain, signal): Prépare une chaîne d'effets pour être traitée. Vous devez remplir la structure sox_effect_chain_t avec les effets et leurs arguments avant d'appeler cette fonction.
  • sox_effect_chain_flow(chain, in, out, samples): Fait passer les échantillons à travers la chaîne d'effets.
  • sox_effect_chain_end(chain): Nettoie la chaîne d'effets.

OPTIONS

Les options de ligne de commande utilisées par l'utilitaire sox ne sont pas directement exposées par l'API libsox_ng. Cependant, de nombreuses fonctionnalités sont accessibles via les arguments des effets ou en manipulant directement les structures de signal et de fichier.

EXEMPLES

Voici un exemple simple pour lire 1024 échantillons d'un fichier WAV et les écrire dans un autre fichier WAV, en changeant la fréquence d'échantillonnage.

#include <stdio.h>
#include <stdlib.h>
#include <sox.h>

#define BUFSIZE 1024

int main() {
    sox_format_t *in_fp, *out_fp;
    sox_signal_t in_signal, out_signal;
    sox_sample_t buf[BUFSIZE];
    size_t samples_read;
    int ret;

    if (sox_globals_init() != SOX_SUCCESS) {
        fprintf(stderr, "Erreur d'initialisation de SoX : %s\n", sox_get_error());
        return 1;
    }

    /* Ouvrir le fichier d'entrée */
    if (NULL == (in_fp = sox_open_read("input.wav", NULL, NULL, NULL, SOX_TRUE))) {
        fprintf(stderr, "Erreur d'ouverture du fichier d'entrée : %s\n", sox_get_error());
        sox_globals_cleanup();
        return 1;
    }
    in_signal = in_fp->signal; /* Copier le signal d'entrée */

    /* Définir le signal de sortie */
    out_signal = in_signal;
    out_signal.rate = 44100.0; /* Changer la fréquence d'échantillonnage */

    /* Ouvrir le fichier de sortie */
    if (NULL == (out_fp = sox_open_write("output.wav", &out_signal, NULL, NULL, NULL, SOX_TRUE))) {
        fprintf(stderr, "Erreur d'ouverture du fichier de sortie : %s\n", sox_get_error());
        sox_close(in_fp);
        sox_globals_cleanup();
        return 1;
    }

    /* Lire, traiter (implicitement par le changement de signal) et écrire */
    while (SOX_EOF != (samples_read = sox_read(in_fp, buf, BUFSIZE))) {
        if (SOX_EOF == sox_write(out_fp, buf, samples_read)) {
            fprintf(stderr, "Erreur d'écriture dans le fichier de sortie : %s\n", sox_get_error());
            break;
        }
    }

    /* Fermer les fichiers */
    sox_close(in_fp);
    sox_close(out_fp);

    /* Nettoyer les globales */
    sox_globals_cleanup();

    return 0;
}

NOTES

La bibliothèque libsox_ng est un fork du projet SoX original. Elle peut contenir des différences dans les fonctionnalités ou les API. Il est recommandé de consulter la documentation spécifique à la version de libsox_ng que vous utilisez.

Les échantillons audio sont stockés sous forme de nombres à virgule flottante de 32 bits (float). Les fonctions de conversion de format gèrent automatiquement la conversion vers/depuis les formats de fichier natifs (par exemple, 16 bits PCM).

La gestion des erreurs est basée sur des chaînes de caractères. Il est important de vérifier les valeurs de retour des fonctions SoX et d'utiliser sox_get_error() pour obtenir des détails en cas de problème.

BOGUES CONNUS

Aucun bogues connus n'est spécifiquement documenté ici. Reportez les bogues à l'équipe de développement de libsox_ng.

VALEURS DE RETOUR

  • Les fonctions d'ouverture de fichier renvoient un pointeur sox_format_t * en cas de succès, et NULL en cas d'erreur.
  • Les fonctions de lecture/écriture renvoient le nombre d'échantillons lus/écrits en cas de succès, SOX_EOF en fin de fichier ou en cas d'erreur.
  • Les fonctions de traitement d'effets renvoient généralement SOX_SUCCESS (0) en cas de succès, et une valeur d'erreur négative en cas d'échec.
  • sox_globals_init() renvoie SOX_SUCCESS en cas de succès.

Utilisez sox_get_error() pour obtenir des informations sur les erreurs.

EFFETS

La bibliothèque prend en charge une large gamme d'effets audio, notamment :

  • delay : Retard
  • reverb : Réverbération
  • chorus : Chorus
  • equalizer : Égaliseur
  • fade : Fondu (in/out)
  • trim : Coupe
  • pitch : Changement de hauteur
  • rate : Changement de taux (fréquence d'échantillonnage)
  • reverse : Inversion
  • Et bien d'autres...

La liste complète et la documentation des arguments de chaque effet peuvent être obtenues via sox_effect_list() et sox_get_effect_args(), ou en consultant la documentation de l'utilitaire sox.

gcc mon_programme.c -o mon_programme -lsox_ng
