DESCRIPTION

Une application cliente peut demander à un serveur d'envoyer une réponse de statut OCSP (également appelée "agrafage OCSP"). Pour ce faire, le client doit appeler la fonction SSL_set_tlsext_status_type() sur un objet SSL individuel avant le début de la négociation. Actuellement, le seul type pris en charge est TLSEXT_STATUSTYPE_ocsp. Cette valeur doit être passée dans l'argument type.

Le client doit également fournir une fonction de rappel pour décider quoi faire de la réponse OCSP reçue en appelant SSL_CTX_set_tlsext_status_cb(). La fonction de rappel doit déterminer si la réponse OCSP reçue est acceptable ou non. La valeur définie précédemment via un appel à SSL_CTX_set_tlsext_status_arg() sera passée en argument au rappel. Notez que le rappel ne sera pas appelé en cas de négociation avec reprise de session (car aucun certificat n'est échangé lors d'une telle négociation).

Le rappel défini précédemment via SSL_CTX_set_tlsext_status_cb() peut être récupéré en appelant SSL_CTX_get_tlsext_status_cb(), et l'argument en appelant SSL_CTX_get_tlsext_status_arg().

Côté client, SSL_get_tlsext_status_type() peut être utilisé pour déterminer si le client a précédemment appelé SSL_set_tlsext_status_type(). Il retournera TLSEXT_STATUSTYPE_ocsp s'il a été appelé, sinon -1. Côté serveur, SSL_get_tlsext_status_type() peut être utilisé pour déterminer si le client a demandé l'agrafage OCSP. Si le client l'a demandé, cette fonction retournera TLSEXT_STATUSTYPE_ocsp, sinon -1.

La réponse renvoyée par le serveur peut être obtenue via un appel à SSL_get_tlsext_status_ocsp_resp(). La valeur de *resp sera mise à jour pour pointer vers les données de la réponse OCSP et la valeur de retour sera la longueur de ces données. Si le serveur n'a fourni aucune donnée de réponse, alors *resp sera NULL et la valeur de retour de SSL_get_tlsext_status_ocsp_resp() sera -1.

Une application serveur doit également appeler la fonction SSL_CTX_set_tlsext_status_cb() si elle veut pouvoir fournir aux clients des réponses de statut de certificat OCSP. Typiquement, le rappel serveur obtiendrait le certificat serveur qui est envoyé au client via un appel à SSL_get_certificate(3), obtiendrait la réponse OCSP à envoyer en retour, puis définirait ces données de réponse en appelant SSL_set_tlsext_status_ocsp_resp(). Un pointeur vers les données de réponse doit être fourni dans l'argument resp, et la longueur de ces données doit être dans l'argument len.

VALEURS DE RETOUR

Le rappel, lorsqu'il est utilisé côté client, doit retourner une valeur négative en cas d'erreur, 0 si la réponse n'est pas acceptable (auquel cas la négociation échouera), ou une valeur positive si elle est acceptable.

Le rappel, lorsqu'il est utilisé côté serveur, doit retourner soit SSL_TLSEXT_ERR_OK (signifiant que la réponse OCSP définie doit être renvoyée), SSL_TLSEXT_ERR_NOACK (signifiant qu'aucune réponse OCSP ne doit être renvoyée), ou SSL_TLSEXT_ERR_ALERT_FATAL (signifiant qu'une erreur fatale s'est produite).

SSL_CTX_set_tlsext_status_cb(), SSL_CTX_get_tlsext_status_cb(), SSL_CTX_set_tlsext_status_arg(), SSL_CTX_get_tlsext_status_arg(), SSL_set_tlsext_status_type(), et SSL_set_tlsext_status_ocsp_resp() retournent toujours 1, indiquant le succès.

SSL_get_tlsext_status_type() retourne TLSEXT_STATUSTYPE_ocsp côté client si SSL_set_tlsext_status_type() a été appelé précédemment, ou côté serveur si le client a demandé l'agrafage OCSP. Sinon, -1 est retourné.

SSL_get_tlsext_status_ocsp_resp() retourne la longueur des données de réponse OCSP ou -1 s'il n'y a pas de données de réponse OCSP.
