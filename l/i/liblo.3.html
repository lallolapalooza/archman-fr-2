Description détaillée

Définit les fonctions de l'API de haut niveau nécessaires pour implémenter le support OSC. Devrait suffire pour la plupart des applications, mais si vous avez besoin d'un contrôle de plus bas niveau, vous pouvez utiliser les fonctions définies dans lo_lowlevel.h

enum lo_type

Une énumération des types OSC que liblo peut envoyer et recevoir. La valeur de l'énumération est le typechar utilisé pour taguer les messages et pour spécifier les arguments avec lo_send().

Énumérateur

LO_INT32
entier signé 32 bits.
LO_FLOAT
flottant IEEE-754 32 bits.
LO_STRING
Chaîne C standard, terminée par NULL.
LO_BLOB
Type de blob binaire OSC. Accédé via les fonctions lo_blob_*().
LO_INT64
entier signé 64 bits.
LO_TIMETAG
Type OSC TimeTag, représenté par la structure lo_timetag.
LO_DOUBLE
double IEEE-754 64 bits.
LO_SYMBOL
Chaîne C standard, terminée par NULL. Utilisée dans les systèmes qui distinguent les chaînes et les symboles.
LO_CHAR
Variable char C standard, 8 bits.
LO_MIDI
Un paquet MIDI de 4 octets.
LO_TRUE
Symbole représentant la valeur Vrai.
LO_FALSE
Symbole représentant la valeur Faux.
LO_NIL
Symbole représentant la valeur Nil.
LO_INFINITUM
Symbole représentant la valeur Infinitum.

lo_address lo_address_new (const char * host, const char * port)

Déclare une destination OSC, étant donné l'adresse IP et le numéro de port. Identique à lo_address_new_with_proto(), mais en utilisant UDP.

Paramètres

host Une adresse IP ou un numéro, ou NULL pour la machine locale.
port un numéro de port décimal ou un nom de service.

L'objet lo_address peut être utilisé comme cible des messages OSC.

Remarque : si vous souhaitez recevoir des réponses de la cible de cette adresse, vous devez soit fournir un lo_server en utilisant lo_send_from() ou lo_send_message_from() pour envoyer votre message, sinon le dernier lo_server ou lo_server_thread qui a été créé sera utilisé comme socket de réponse. Le destinataire distant peut obtenir l'adresse de réponse en appelant lo_message_get_source() dans le gestionnaire de messages. Voir example_tcp_echo_server.c pour un exemple sur la façon d'établir une communication bidirectionnelle.

lo_address lo_address_new_from_url (const char * url)

Crée un objet lo_address à partir d'une URL OSC. exemple : "osc.udp://localhost:4444/my/path/"

lo_address lo_address_new_with_proto (int proto, const char * host, const char * port)

Déclare une destination OSC, étant donné l'adresse IP et le numéro de port, en spécifiant le protocole.

Paramètres

proto Le protocole à utiliser, doit être l'un de LO_UDP, LO_TCP ou LO_UNIX.
host Une adresse IP ou un numéro, ou NULL pour la machine locale.
port un numéro de port décimal ou un nom de service.

L'objet lo_address peut être utilisé comme cible des messages OSC.

Remarque : si vous souhaitez recevoir des réponses de la cible de cette adresse, vous devez d'abord créer un objet lo_server_thread ou lo_server qui recevra les réponses. Le dernier objet lo_server(_thread) créé sera le récepteur.

void lo_address_set_ttl (lo_address t, int ttl)

Définissez la valeur Time-to-Live pour une adresse cible donnée. Ceci est nécessaire pour envoyer des messages UDP multicast. Une valeur de 1 (le cas habituel) maintient le message dans le sous-réseau, tandis que 255 signifie une portée globale et sans restriction.

Paramètres

t Une adresse OSC.
ttl Un entier spécifiant la portée d'un message UDP multicast.

int lo_send (lo_address targ, const char * path, const char * type, ...)

Envoie un message formaté OSC à l'adresse spécifiée.

Paramètres

targ L'adresse OSC cible
path Le chemin OSC auquel le message sera livré
type Les types des éléments de données dans le message, les types sont définis dans lo_osc_types.h

int lo_send_from (lo_address targ, lo_server from, lo_timetag ts, const char * path, const char * type, ...)

Envoie un message formaté OSC à l'adresse spécifiée, depuis le même socket que le serveur spécifié. Si un serveur liblo reçoit ce message, il peut répondre en obtenant l'adresse du serveur en appelant lo_message_get_source() dans le gestionnaire de messages, en passant le lo_message fourni comme argument au lo_method_handler. Par ce mécanisme, une communication bidirectionnelle peut être établie en configurant un lo_server ou lo_server_thread des deux côtés.

Paramètres

targ L'adresse OSC cible
from Le serveur depuis lequel envoyer le message (peut être NULL pour utiliser un nouveau socket)
ts L'horodatage `lo_timetag` OSC auquel le message sera traité (peut être LO_TT_IMMEDIATE si vous ne voulez pas attacher d'horodatage)
path Le chemin OSC auquel le message sera livré
type Les types des éléments de données dans le message, les types sont définis dans lo_osc_types.h
... Les valeurs de données à transmettre. Les types des arguments passés ici doivent correspondre aux types spécifiés dans le paramètre `type`.

exemple :

serv = lo_server_new(NULL, err);
lo_server_add_method(serv, "/reply", "ss", reply_handler, NULL);
lo_send_from(t, serv, LO_TT_IMMEDIATE, "/foo/bar", "ff", 0.1f, 23.0f);

Voir example_tcp_echo_server.c pour un exemple d'utilisation de lo_message_get_source() tel que décrit.

Retourne

en cas de succès, le nombre d'octets envoyés, ou -1 en cas d'échec.

int lo_send_timestamped (lo_address targ, lo_timetag ts, const char * path, const char * type, ...)

Envoie un message formaté OSC à l'adresse spécifiée, prévu pour être traité à un moment donné dans le futur.

Paramètres

targ L'adresse OSC cible
ts L'horodatage `lo_timetag` OSC auquel le message sera traité
path Le chemin OSC auquel le message sera livré
type Les types des éléments de données dans le message, les types sont définis dans lo_osc_types.h
... Les valeurs de données à transmettre. Les types des arguments passés ici doivent correspondre aux types spécifiés dans le paramètre `type`.

exemple :

lo_timetag now;<br>
lo_timetag_now(&now);<br>
lo_send_timestamped(t, now, "/foo/bar", "ff", 0.1f, 23.0f);

Retourne

en cas de succès, le nombre d'octets envoyés, ou -1 en cas d'échec.

void lo_version (char * verstr, int verstr_size, int * major, int * minor, char * extra, int extra_size, int * lt_major, int * lt_minor, int * lt_bug)

Obtenez des informations sur la version de liblo actuellement utilisée. Tous les paramètres sont optionnels et peuvent avoir la valeur 0 si ces informations ne sont pas souhaitées. Par exemple, pour obtenir seulement la version sous forme de chaîne, appelez lo_version(str, size, 0, 0, 0, 0, 0, 0, 0);

Les champs "lt", appelés version ABI, correspondent au système de versionnement de libtool pour la compatibilité de l'interface binaire, et ne sont pas liés au numéro de version de la bibliothèque. Ces informations sont généralement encodées dans le nom de fichier de la bibliothèque partagée.

En général, la chaîne retournée dans 'verstr' devrait correspondre à $major.$minor$extra, par exemple "0.28rc". S'il n'y a pas d'informations 'extra', par exemple "0.28", `extra` contiendra une chaîne nulle.

Paramètres

verstr Un tampon pour recevoir une chaîne décrivant la version de la bibliothèque.
verstr_size Taille du tampon pointé par `verstr`.
major Emplacement pour recevoir la version majeure de la bibliothèque.
minor Emplacement pour recevoir la version mineure de la bibliothèque.
extra Emplacement pour recevoir la chaîne supplémentaire de la version de la bibliothèque.
extra_size Taille du tampon pointé par `extra`.
lt_major Emplacement pour recevoir la version majeure de l'ABI.
lt_minor Emplacement pour recevoir la version mineure de l'ABI.
lt_bug Emplacement pour recevoir la version 'correction de bug' de l'ABI.

Référencé par lo::version().
