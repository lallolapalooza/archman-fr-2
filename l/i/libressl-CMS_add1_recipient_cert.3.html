CMS_ADD1_RECIPIENT_CERT(3) Manuel des fonctions de bibliothèque CMS_ADD1_RECIPIENT_CERT(3)

NOM

CMS_add1_recipient_cert, CMS_add0_recipient_key — ajouter des destinataires à une structure CMS EnvelopedData

SYNOPSIS

bibliothèque « libcrypto »
#include <openssl/cms.h>

CMS_RecipientInfo *
CMS_add1_recipient_cert(CMS_ContentInfo *cms, X509 *certificate, unsigned int flags);

CMS_RecipientInfo *
CMS_add0_recipient_key(CMS_ContentInfo *cms, int nid, unsigned char *key, size_t keylen, unsigned char *id, size_t idlen, ASN1_GENERALIZEDTIME *date, ASN1_OBJECT *otherTypeId, ASN1_TYPE *otherType);

DESCRIPTION

Ces fonctions ajoutent une nouvelle structure RecipientInfo au champ recipientInfos de la structure EnvelopedData cms, laquelle aurait dû être obtenue à partir d'un appel initial à CMS_encrypt(3) avec le drapeau CMS_PARTIAL défini.

CMS_add1_recipient_cert() ajoute le certificat du destinataire certificate en tant que structure KeyTransRecipientInfo.

CMS_add0_recipient_key() ajoute la clé symétrique key de longueur keylen en utilisant l'algorithme de chiffrement nid, l'identifiant id de longueur idlen, et les valeurs optionnelles date, otherTypeId et otherType en tant que structure KEKRecipientInfo.

Le but principal de ces fonctions est de fournir un contrôle plus fin sur une structure CMS EnvelopedData où les paramètres par défaut de la fonction plus simple CMS_encrypt(3) ne sont pas appropriés, par exemple si une ou plusieurs structures KEKRecipientInfo doivent être ajoutées. De nouveaux attributs peuvent également être ajoutés en utilisant la structure CMS_RecipientInfo retournée et les fonctions utilitaires d'attributs CMS.

Par défaut, les certificats des destinataires sont identifiés à l'aide du nom de l'émetteur et du numéro de série. Si le drapeau CMS_USE_KEYID est défini, l'identifiant de clé du sujet est utilisé à la place. Une erreur se produit si tous les certificats des destinataires n'ont pas d'extension d'identifiant de clé du sujet.

Actuellement, seuls les algorithmes d'encapsulation de clé basés sur AES sont pris en charge pour nid, spécifiquement NID_id_aes128_wrap, NID_id_aes192_wrap, et NID_id_aes256_wrap. Si nid est défini à NID_undef, alors un algorithme d'encapsulation AES sera utilisé en cohérence avec keylen.

VALEURS DE RETOUR

CMS_add1_recipient_cert() et CMS_add0_recipient_key() retournent un pointeur interne à la structure CMS_RecipientInfo qui vient d'être ajoutée, ou NULL si une erreur se produit.

VOIR AUSSI

CMS_ContentInfo_new(3), CMS_encrypt(3), CMS_final(3), ERR_get_error(3)

NORMES

RFC 5652 : Cryptographic Message Syntax

  • section 6.1 : Type EnvelopedData
  • section 6.2.1 : Type KeyTransRecipientInfo
  • section 6.2.3 : Type KEKRecipientInfo
