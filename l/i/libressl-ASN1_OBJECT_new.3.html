ASN1_OBJECT_NEW(3) Manuel des fonctions de bibliothèque ASN1_OBJECT_NEW(3)

NOM

ASN1_OBJECT_new, ASN1_OBJECT_create, ASN1_OBJECT_free — identifiants d'objets ASN.1

SYNOPSIS

bibliothèque «libcrypto»
#include <openssl/asn1.h>

ASN1_OBJECT *
ASN1_OBJECT_new(void);

ASN1_OBJECT *
ASN1_OBJECT_create(int nid, unsigned char *content, int len, const char *short_name, const char *long_name);

void
ASN1_OBJECT_free(ASN1_OBJECT *a);

DESCRIPTION

ASN1_OBJECT_new() alloue et initialise un objet ASN1_OBJECT vide, représentant un IDENTIFIANT D'OBJET ASN.1. Il peut contenir un nom court, un nom long, un identifiant numérique (NID) et une séquence d'entiers identifiant un nœud dans l'arbre des Identifiants d'Objets Internationaux tel que spécifié dans la recommandation UIT-T X.660. Le nouvel objet est marqué comme alloué dynamiquement.

Le type identifiant d'objet ASN.1 est également représenté par la constante d'identifiant de type V_ASN1_OBJECT.

ASN1_OBJECT_create() alloue un nouveau ASN1_OBJECT avec le nid donné, copie les octets de contenu DER len de content, le short_name et le long_name en son sein, et marque le nouvel objet et toutes les données qu'il contient comme étant alloués dynamiquement.

Les programmes d'application utilisent normalement des fonctions utilitaires comme OBJ_nid2obj(3) plutôt que d'utiliser directement ASN1_OBJECT_new() ou ASN1_OBJECT_create().

ASN1_OBJECT_free() a les effets suivants :

Toutes les données contenues dans a qui sont marquées comme allouées dynamiquement sont libérées, et les champs respectifs de a deviennent vides. Les données contenues non marquées comme allouées dynamiquement restent intactes.

Si l'objet a lui-même est marqué comme alloué dynamiquement, il est libéré. Sinon, le pointeur a reste valide.

Si a est un pointeur NULL ou si ni l'objet lui-même ni aucune de ses données contenues n'est marquée comme allouée dynamiquement, aucune action n'est effectuée.

VALEURS DE RETOUR

ASN1_OBJECT_new() et ASN1_OBJECT_create() renvoient un pointeur vers le nouvel objet ou NULL en cas d'échec d'allocation de mémoire.

ERREURS

Après un échec de ASN1_OBJECT_new() ou ASN1_OBJECT_create(), le diagnostic suivant peut être récupéré avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3) :

ERR_R_MALLOC_FAILURE « échec d'allocation »
L'allocation de mémoire a échoué.

Après certains cas d'échec de ASN1_OBJECT_create(), le diagnostic suivant peut être récupéré en plus de celui ci-dessus :

ERR_R_ASN1_LIB « ASN1 lib »
L'allocation de mémoire a échoué.

VOIR AUSSI

a2d_ASN1_OBJECT(3), ASN1_TYPE_get(3), d2i_ASN1_OBJECT(3), OBJ_create(3), OBJ_nid2obj(3)

NORMES

Recommandation UIT-T X.208, également connue sous le nom de ISO/IEC 8824-1 : Spécification de la notation de syntaxe abstraite un (ASN.1), section 28 : Notation pour le type identifiant d'objet.

Recommandation UIT-T X.690, également connue sous le nom de ISO/IEC 8825-1 : Technologies de l'information - Règles d'encodage ASN.1 : Spécification des règles d'encodage de base (BER), des règles d'encodage canoniques (CER) et des règles d'encodage distinctives (DER), section 8.19 : Encodage d'une valeur d'identifiant d'objet.

HISTORIQUE

ASN1_OBJECT_new() et ASN1_OBJECT_free() sont apparus pour la première fois dans SSLeay 0.5.1 et ASN1_OBJECT_create() dans SSLeay 0.8.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BOGUES

La fonction ASN1_OBJECT_new() n'est pas utile à des fins pratiques car la bibliothèque ne fournit aucune fonction capable d'ajouter des données à un objet existant. Par conséquent, si le programme d'application crée un objet avec ASN1_OBJECT_new(), cet objet restera toujours vide.

De même, si un nid de NID_undef est passé à ASN1_OBJECT_create(), ou si NULL est passé pour l'un de ses arguments de pointeur, l'objet renvoyé restera définitivement incomplet.
