NOM

nss-resolve, libnss_resolve.so.2 - Résolution de noms d'hôte via systemd-resolved.service

SYNTAXE

libnss_resolve.so.2

DESCRIPTION

nss-resolve est un module plug-in pour la fonctionnalité NSS (Name Service Switch) de la bibliothèque C GNU (glibc) lui permettant de résoudre les noms d'hôte via le service de résolution de noms réseau local systemd-resolved(8). Il remplace le module plug-in nss-dns qui résout traditionnellement les noms d'hôte via DNS.

Pour activer le module NSS, ajoutez "resolve [!UNAVAIL=return]" à la ligne commençant par "hosts:" dans /etc/nsswitch.conf. Plus précisément, il est recommandé de placer "resolve" tôt dans la ligne "hosts:" de /etc/nsswitch.conf. Il doit être placé avant l'entrée "files", car systemd-resolved prend en charge /etc/hosts en interne, mais avec mise en cache. Au contraire, il doit être placé après "mymachines", pour donner aux noms d'hôte attribués aux VMs et conteneurs locaux la priorité sur les noms reçus via DNS. Enfin, nous recommandons de placer "dns" quelque part après "resolve", pour se rabattre sur nss-dns si systemd-resolved.service n'est pas disponible.

Notez que systemd-resolved synthétisera des enregistrements de ressources DNS dans certains cas, par exemple pour "localhost" et le nom d'hôte local actuel, voir systemd-resolved(8) pour la liste complète. Cela duplique la fonctionnalité de nss-myhostname(8), mais il est toujours recommandé (voir les exemples ci-dessous) de garder nss-myhostname configuré dans /etc/nsswitch.conf, pour que ces noms restent résolubles si systemd-resolved n'est pas en cours d'exécution.

Veuillez garder à l'esprit que nss-myhostname (et nss-resolve) résolvent également dans l'autre sens — des adresses IP attachées localement vers des noms d'hôte. Si vous comptez sur cette recherche fournie par DNS, vous pourriez vouloir ordonner les choses différemment.

La communication entre nss-resolve et systemd-resolved.service s'effectue via le socket AF_UNIX /run/systemd/resolve/io.systemd.Resolve.

VARIABLES D'ENVIRONNEMENT

$SYSTEMD_NSS_RESOLVE_VALIDATE

Prend un argument booléen. Lorsqu'il est faux, la validation cryptographique des enregistrements de ressources via DNSSEC sera désactivée. Cela peut être utile pour les tests, ou lorsque le temps système est connu pour être peu fiable.

Ajouté dans la version 250.

$SYSTEMD_NSS_RESOLVE_SYNTHESIZE

Prend un argument booléen. Lorsqu'il est faux, les enregistrements synthétiques, par exemple pour le nom d'hôte local, ne seront pas retournés. Voir la section ENREGISTREMENTS SYNTHÉTIQUES dans systemd-resolved.service(8) pour plus d'informations. Cela peut être utile pour interroger les enregistrements de ressources "publics", indépendamment de la configuration de la machine locale.

Ajouté dans la version 250.

$SYSTEMD_NSS_RESOLVE_CACHE

Prend un argument booléen. Lorsqu'il est faux, le cache des enregistrements précédemment interrogés ne sera pas utilisé par systemd-resolved(8).

Ajouté dans la version 250.

$SYSTEMD_NSS_RESOLVE_ZONE

Prend un argument booléen. Lorsqu'il est faux, les réponses utilisant des enregistrements de ressources LLMNR/mDNS publics enregistrés localement ne seront pas retournées.

Ajouté dans la version 250.

$SYSTEMD_NSS_RESOLVE_TRUST_ANCHOR

Prend un argument booléen. Lorsqu'il est faux, les réponses utilisant des points d'ancrage de confiance configurés localement ne seront pas utilisées.

Ajouté dans la version 250.

$SYSTEMD_NSS_RESOLVE_NETWORK

Prend un argument booléen. Lorsqu'il est faux, les réponses seront retournées sans utiliser le réseau, c'est-à-dire soit à partir de sources locales, soit du cache dans systemd-resolved(8).

Ajouté dans la version 250.

EXEMPLE

Voici un exemple de fichier /etc/nsswitch.conf qui active correctement nss-resolve :

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis
