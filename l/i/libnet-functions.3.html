LIBNET_API char * libnet_addr2name4 (uint32_t in, uint8_t use_name)

Takes a network byte ordered IPv4 address and returns a pointer to either a canonical DNS name (if it has one) or a string of dotted decimals. This may incur a DNS lookup if the hostname and mode is set to LIBNET_RESOLVE. If mode is set to LIBNET_DONT_RESOLVE, no DNS lookup will be performed and the function will return a pointer to a dotted decimal string. The function cannot fail -- if no canonical name exists, it will fall back on returning a dotted decimal string. This function is non-reentrant.

Parameters

in network byte ordered IPv4 address
use_name LIBNET_RESOLVE or LIBNET_DONT_RESOLVE

Returns

a pointer to presentation format string

Fonctions de Construction de Paquets

Le cœur de libnet est la fonctionnalité de construction de paquets indépendante de la plateforme. Ces fonctions permettent à un programmeur d'applications de construire des en-têtes de protocole (et des données) de manière simple et cohérente sans avoir à se soucier (trop) des détails de bas niveau du réseau. Chaque fonction libnet_build() construit une partie d'un paquet (généralement un en-tête de protocole). Bien qu'il soit parfaitement possible de construire un paquet complet, prêt à être transmis, avec un seul appel à une fonction libnet_build(), plusieurs appels de fonctions de la classe builder sont généralement nécessaires pour construire un paquet complet. Un paquet complet prêt pour le réseau se compose généralement de plus d'une pièce. Chaque fonction qui construit un en-tête de protocole prend une série d'arguments correspondant approximativement aux valeurs de l'en-tête telles qu'elles apparaissent sur le fil. Ce processus est intuitif mais conduit souvent à des fonctions avec des prototypes énormes et de grandes piles d'appels. Une chose importante à noter est que vous devez appeler ces fonctions dans l'ordre, correspondant à la façon dont elles doivent apparaître sur le fil (de la couche de protocole la plus haute vers le bas). Ce processus de construction est intuitif ; il se rapproche de ce qui se passe dans un noyau de système d'exploitation. En d'autres termes, pour construire un paquet Network Time Protocol (NTP) en utilisant l'interface de couche de liaison, le programmeur d'applications appellerait les fonctions libnet_build() dans l'ordre suivant :

1.
libnet_build_ntp()
2.
libnet_build_udp()
3.
libnet_build_ipv4()
4.
libnet_build_ethernet() Cet ordre est essentiel pour que libnet 1.1.x relie correctement le paquet en interne (les versions précédentes de libnet n'avaient pas cette exigence).

L'interface de Charge Utile

L'interface de charge utile spécifie une manière optionnelle d'inclure des données directement après l'en-tête de protocole en question. Vous pouvez utiliser cette fonction à diverses fins, notamment :

  • Inclure des informations d'en-tête de protocole supplémentaires ou arbitraires qui ne sont pas disponibles à partir d'une interface libnet
  • Inclure une charge utile de paquet (segment de données)
  • Construire un autre en-tête de protocole qui n'est pas disponible à partir d'une interface libnet Pour utiliser l'interface, le programmeur d'applications doit construire les données de la charge utile et passer un const uint8_t * vers ces données et leur taille à la fonction libnet_build() souhaitée. Libnet s'occupe du reste.

Il est important de noter que certaines fonctions (notamment les constructeurs IPv6) utilisent l'interface de charge utile pour spécifier des données de longueur variable mais ostensiblement non optionnelles. Voir les fonctions individuelles libnet_build_ipv6*() pour plus d'informations.

pièce qui vient d'être créée. La responsabilité du programmeur d'application est de sauvegarder cette valeur s'il prévoit de modifier cette partie particulière plus tard dans le programme. Cette fonction est souvent utilisée comme suit :

LIBNET_API libnet_t * libnet_init (int injection_type, const char * device, char * err_buf)

Crée l'environnement libnet. Il initialise la bibliothèque et retourne un contexte libnet. Si le type d'injection est LIBNET_LINK ou LIBNET_LINK_ADV, la fonction initialise les primitives d'injection pour l'interface de couche liaison de données, permettant au programmeur d'application de construire des paquets en commençant par la couche de liaison de données (ce qui offre également un contrôle plus granulaire sur la couche IP). Si libnet utilise la couche de liaison de données et que l'argument device n'est pas NULL, la fonction tente d'utiliser le périphérique réseau spécifié pour l'injection de paquets. Il s'agit soit d'une chaîne canonique référençant le périphérique (comme 'eth0' pour une carte Ethernet 100 Mo sous Linux ou 'fxp0' pour une carte Ethernet 100 Mo sous OpenBSD), soit de la représentation en points et décimales de l'adresse IP du périphérique (192.168.0.1). Si device est NULL, libnet tente de trouver un périphérique approprié. Si le type d'injection est LIBNET_RAW4 ou LIBNET_RAW4_ADV, la fonction initialise les primitives d'injection pour l'interface de socket brut IPv4. L'argument final, err_buf, doit être un tampon de taille LIBNET_ERRBUF_SIZE et contiendra un message d'erreur si la fonction échoue. Cette fonction nécessite des privilèges root pour s'exécuter correctement. En cas de succès, la fonction retourne un contexte libnet valide à utiliser dans des appels de fonction ultérieurs ; en cas d'échec, la fonction retourne NULL.

Paramètres

injection_type type d'injection de paquet (LIBNET_LINK, LIBNET_LINK_ADV, LIBNET_RAW4, LIBNET_RAW4_ADV, LIBNET_RAW6, LIBNET_RAW6_ADV)
device l'interface à utiliser (NULL et libnet en choisira une)
err_buf contiendra un message d'erreur en cas d'échec

Retourne

contexte libnet prêt à l'emploi ou NULL en cas d'erreur.

LIBNET_API int libnet_toggle_checksum (libnet_t * l, libnet_ptag_t ptag, int mode)

Si un en-tête de protocole donné est construit

avec le champ de somme de contrôle défini sur '0', par défaut, libnet calculera la somme de contrôle de l'en-tête avant l'injection. Si l'en-tête est défini sur toute autre valeur, par défaut, libnet ne calculera pas la somme de contrôle de l'en-tête. Pour outrepasser ce comportement, utilisez libnet_toggle_checksum(). Cela suppose que le programmeur assignera une valeur (zéro ou autre) au champ de somme de contrôle. C'est souvent utile si une somme de contrôle pré-calculée ou une autre valeur prédéfinie doit être utilisée. Notez que lorsque libnet est initialisé avec LIBNET_RAW4, la somme de contrôle de l'en-tête IPv4 sera toujours calculée par le noyau avant l'injection, quel que soit ce que le programmeur définit.

mode LIBNET_ON ou LIBNET_OFF
