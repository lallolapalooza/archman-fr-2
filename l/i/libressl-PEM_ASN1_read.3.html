PEM_ASN1_READ(3) Manuel des fonctions de bibliothèque PEM_ASN1_READ(3)

NOM

d2i_of_void, PEM_ASN1_read, PEM_ASN1_read_bio — Analyse DER et PEM d'une valeur ASN.1 arbitraire

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/pem.h>

typedef void *
d2i_of_void(void **val_out, const unsigned char **der_in, long length);

void *
PEM_ASN1_read(d2i_of_void *d2i, const char *name, FILE *in_fp, void **val_out, pem_password_cb *cb, void *u);

void *
PEM_ASN1_read_bio(d2i_of_void *d2i, const char *name, BIO *in_bp, void **val_out, pem_password_cb *cb, void *u);

DESCRIPTION

Ces fonctions lisent un objet depuis in_fp ou in_bp et effectuent l'analyse aussi bien en PEM qu'en DER. Elles sont nécessaires lorsque des fonctions d'analyse plus spécifiques comme celles décrites dans PEM_read_bio_PrivateKey(3) et PEM_read_SSL_SESSION(3) sont inadéquates pour le type name.

Pour l'analyse PEM, PEM_bytes_read_bio(3) est appelée en interne. Par conséquent, le premier objet de type name est retourné et les objets précédents d'autres types sont ignorés. Si nécessaire, les données sont déchiffrées, en utilisant cb et/ou u s'ils ne sont pas NULL, comme décrit dans la page de manuel de pem_password_cb(3).

Pour l'analyse DER subséquente, passez une fonction de rappel d2i qui est adéquate pour le type name, renvoyant typiquement un pointeur d'un type plus spécifique que void *. Par exemple, d2i_ASN1_TYPE(3) peut toujours être utilisée et sa page de manuel décrit le comportement requis de la fonction de rappel à passer. Normalement, passer une fonction plus spécifique est plus utile ; les fonctions candidates peuvent être trouvées avec « man -k Nm~^d2i_ ».

Pour l'argument name, les constantes de chaîne PEM_STRING_* définies dans <openssl/pem.h> peuvent être utilisées.

L'argument val_out est inutile et ses nombreux dangers sont décrits en détail dans la page de manuel de d2i_ASN1_TYPE(3). Pour réduire le risque de bugs, il est recommandé de toujours passer NULL.

VALEURS DE RETOUR

Ces fonctions renvoient un pointeur vers l'objet décodé ou NULL en cas d'erreur. Elles échouent si PEM_bytes_read_bio(3) échoue, par exemple en raison d'une syntaxe invalide dans l'entrée, d'un chiffrement inconnu, ou d'une phrase secrète invalide saisie par l'utilisateur. Elles échouent également si d2i renvoie NULL, par exemple en raison d'erreurs d'analyse DER.

PEM_ASN1_read() peut également échouer si la mémoire est épuisée.

EXEMPLES

L'utilisation typique de PEM_ASN1_read() est démontrée par l'implémentation de la fonction plus spécifique pour analyser en PEM et DER un certificat X.509 :

X509 *
PEM_read_X509(FILE *fp, X509 **val_out, pem_password_cb *cb, void *u)
{
	return PEM_ASN1_read((d2i_of_void *)d2i_X509, PEM_STRING_X509,
	    fp, (void **)val_out, cb, u);
}

ERREURS

Les diagnostics qui peuvent être récupérés avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3) incluent :

ERR_R_BUF_LIB « BUF lib »
PEM_ASN1_read() n'a pas pu configurer un BIO temporaire, par exemple parce que la mémoire était épuisée.
ERR_R_ASN1_LIB « ASN1 lib »
d2i a renvoyé NULL, par exemple en raison d'une erreur de syntaxe DER.

D'autres types d'erreurs peuvent résulter de PEM_bytes_read_bio(3).
