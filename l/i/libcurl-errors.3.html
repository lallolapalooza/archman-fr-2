NOM

libcurl-errors - codes d'erreur dans libcurl

DESCRIPTION

Cette page de manuel comprend la plupart, sinon la totalité, des codes d'erreur disponibles dans libcurl. Pourquoi ils se produisent et éventuellement ce que vous pouvez faire pour résoudre le problème sont également inclus.

CURLcode

Presque toutes les fonctions de l'interface « easy » retournent un code d'erreur CURLcode. Quoi qu'il en soit, utiliser l'option curl_easy_setopt(3) CURLOPT_ERRORBUFFER(3) est une bonne idée car elle vous donne une chaîne d'erreur lisible par l'homme qui peut offrir plus de détails sur la cause de l'erreur que le simple code d'erreur. curl_easy_strerror(3) peut être appelée pour obtenir une chaîne d'erreur à partir d'un numéro CURLcode donné.

CURLcode est l'un des éléments suivants :

CURLE_OK (0)
Tout va bien. Poursuivre normalement.
CURLE_UNSUPPORTED_PROTOCOL (1)
L'URL que vous avez passée à libcurl utilisait un protocole que cette libcurl ne prend pas en charge. La prise en charge peut être une option de compilation que vous n'avez pas utilisée, il peut s'agir d'une chaîne de protocole mal orthographiée ou simplement d'un protocole pour lequel libcurl n'a pas de code.
CURLE_FAILED_INIT (2)
Le code d'initialisation précoce a échoué. Il s'agit probablement d'une erreur ou d'un problème interne, ou d'un problème de ressources où quelque chose de fondamental n'a pas pu être effectué au moment de l'initialisation.
CURLE_URL_MALFORMAT (3)
L'URL n'était pas correctement formatée.
CURLE_NOT_BUILT_IN (4)
Une fonctionnalité, un protocole ou une option demandée n'a pas été trouvé intégré à cette libcurl en raison d'une décision de compilation. Cela signifie qu'une fonctionnalité ou une option n'était pas activée ou a été explicitement désactivée lors de la compilation de libcurl et pour qu'elle fonctionne, vous devez obtenir une libcurl recompilée.
CURLE_COULDNT_RESOLVE_PROXY (5)
Impossible de résoudre le proxy. L'hôte proxy donné n'a pas pu être résolu.
CURLE_COULDNT_RESOLVE_HOST (6)
Impossible de résoudre l'hôte. L'hôte distant donné n'a pas été résolu.
CURLE_COULDNT_CONNECT (7)
Échec de la connexion () à l'hôte ou au proxy.
CURLE_WEIRD_SERVER_REPLY (8)
Le serveur a envoyé des données que libcurl n'a pas pu analyser. Ce code d'erreur était connu sous le nom de CURLE_FTP_WEIRD_SERVER_REPLY avant la version 7.51.0.
CURLE_REMOTE_ACCESS_DENIED (9)
L'accès à la ressource indiquée dans l'URL nous a été refusé. Pour FTP, cela se produit lors de la tentative de changement de répertoire distant.
CURLE_FTP_ACCEPT_FAILED (10)
En attendant que le serveur se connecte en retour lorsqu'une session FTP active est utilisée, un code d'erreur a été envoyé sur la connexion de contrôle ou similaire.
CURLE_FTP_WEIRD_PASS_REPLY (11)
Après avoir envoyé le mot de passe FTP au serveur, libcurl s'attend à une réponse correcte. Ce code d'erreur indique qu'un code inattendu a été retourné.
CURLE_FTP_ACCEPT_TIMEOUT (12)
Lors d'une session FTP active en attendant que le serveur se connecte, le délai d'attente CURLOPT_ACCEPTTIMEOUT_MS(3) (ou le délai interne par défaut) a expiré.
CURLE_FTP_WEIRD_PASV_REPLY (13)
libcurl n'a pas réussi à obtenir un résultat sensé du serveur en réponse à une commande PASV ou EPSV. Le serveur est défectueux.
CURLE_FTP_WEIRD_227_FORMAT (14)
Les serveurs FTP renvoient une ligne 227 en réponse à une commande PASV. Si libcurl ne parvient pas à analyser cette ligne, ce code de retour est passé.
CURLE_FTP_CANT_GET_HOST (15)
Un échec interne de recherche de l'hôte utilisé pour la nouvelle connexion.
CURLE_HTTP2 (16)
Un problème a été détecté dans la couche de trame HTTP2. C'est assez générique et peut être l'un des problèmes suivants, voir le tampon d'erreur pour plus de détails.
CURLE_FTP_COULDNT_SET_TYPE (17)
Une erreur a été reçue en essayant de définir le mode de transfert sur binaire ou ASCII.
CURLE_PARTIAL_FILE (18)
Un transfert de fichier était plus court ou plus long que prévu. Cela se produit lorsque le serveur signale d'abord une taille de transfert attendue, puis livre des données qui ne correspondent pas à la taille précédemment donnée.
CURLE_FTP_COULDNT_RETR_FILE (19)
C'était soit une réponse étrange à une commande 'RETR', soit un transfert de zéro octet terminé.
Erreur obsolète (20)
Non utilisé dans les versions modernes.
CURLE_QUOTE_ERROR (21)
Lors de l'envoi de commandes personnalisées « QUOTE » au serveur distant, l'une des commandes a retourné un code d'erreur de 400 ou plus (pour FTP) ou a autrement indiqué un achèvement non réussi de la commande.
CURLE_HTTP_RETURNED_ERROR (22)
Ceci est retourné si CURLOPT_FAILONERROR(3) est défini sur TRUE et que le serveur HTTP retourne un code d'erreur supérieur ou égal à 400.
CURLE_WRITE_ERROR (23)
Une erreur s'est produite lors de l'écriture des données reçues dans un fichier local, ou une erreur a été renvoyée à libcurl par une fonction de rappel d'écriture.

Un problème s'est produit lors de la lecture d'un fichier local ou une erreur a été retournée par la fonction de rappel de lecture.
CURLE_OUT_OF_MEMORY (27)

CURLE_OPERATION_TIMEDOUT (28)

CURLMcode

This is the generic return code used by functions in the libcurl multi interface. Also consider curl_multi_strerror(3).

CURLM_CALL_MULTI_PERFORM (-1)
This is not really an error. It means you should call curl_multi_perform(3) again without doing select() or similar in between. Before version 7.20.0 (released on February 9 2010) this could be returned by curl_multi_perform(3), but in later versions this return code is never used.
CURLM_CALL_MULTI_SOCKET (-1)
An alias for CURLM_CALL_MULTI_PERFORM. Never returned by modern libcurl versions.
CURLM_OK (0)
Things are fine.
CURLM_BAD_HANDLE (1)
The passed-in handle is not a valid CURLM handle.
