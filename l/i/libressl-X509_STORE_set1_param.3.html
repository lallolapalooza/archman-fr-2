X509_STORE_SET1_PARAM(3) Manuel des fonctions de bibliothèque X509_STORE_SET1_PARAM(3)

NOM

DESCRIPTION

X509_STORE_set1_param() copie les paramètres de vérification de pm en utilisant X509_VERIFY_PARAM_set1(3) dans l'objet de paramètres de vérification contenu dans le store.

X509_VERIFY_PARAM_set_flags(), X509_STORE_set_purpose(), X509_STORE_set_trust(), et X509_STORE_set_depth() appellent X509_VERIFY_PARAM_set_flags(), X509_VERIFY_PARAM_set_purpose(), X509_VERIFY_PARAM_set_trust(), et X509_VERIFY_PARAM_set_depth() sur l'objet de paramètres de vérification contenu dans le store.

X509_STORE_add_cert() et X509_STORE_add_crl() ajoutent le certificat x ou la liste de révocation de certificats crl au store, augmentant son compteur de références de 1 en cas de succès. Les objets non fiables ne doivent pas être ajoutés de cette manière.

X509_STORE_get_ex_new_index(), X509_STORE_set_ex_data(), et X509_STORE_get_ex_data() gèrent les données spécifiques à l'application dans les objets X509_STORE. Leur utilisation est identique à celle de RSA_get_ex_new_index(3), RSA_set_ex_data(3), et RSA_get_ex_data(3). X509_STORE_get_ex_new_index() est implémenté comme une macro.

VALEURS DE RETOUR

X509_STORE_set1_param(), X509_STORE_set_purpose(), X509_STORE_set_trust(), et X509_STORE_set_ex_data() retournent 1 en cas de succès ou 0 en cas d'échec.

X509_STORE_set_flags() et X509_STORE_set_depth() retournent toujours 1, indiquant le succès.

X509_STORE_add_cert() et X509_STORE_add_crl() retournent 1 en cas de succès ou 0 en cas d'échec. Par exemple, elles échouent si x ou crl est un pointeur NULL, si un certificat portant le même nom de sujet que x ou une liste de révocation portant le même nom d'émetteur que crl sont déjà contenus dans le store, ou si l'allocation de mémoire échoue.

X509_STORE_get0_param() retourne un pointeur interne vers l'objet de paramètres de vérification contenu dans le store. Le pointeur retourné ne doit pas être libéré par l'application appelante.

X509_STORE_get1_objects() retourne une pile nouvellement allouée contenant les certificats, les listes de révocation et les clés privées dans store, ainsi que les objets mis en cache ajoutés par X509_LOOKUP_hash_dir(3). L'appelant doit libérer le résultat avec sk_pop_free(3) et X509_OBJECT_free(3) une fois terminé.

X509_STORE_get0_objects() est une fonction obsolète retournant un pointeur interne vers la pile de certificats, de listes de révocation et de clés privées contenus dans store. Le pointeur retourné ne doit pas être modifié ni libéré par l'application appelante. Cette fonction n'est pas thread-safe. Si store est partagé entre plusieurs threads, les appelants ne peuvent pas inspecter le résultat de cette fonction en toute sécurité, car un autre thread a pu y ajouter des éléments de manière concurrente. Notamment, X509_LOOKUP_hash_dir(3) traite cette liste comme un cache et peut y ajouter des éléments au cours de la vérification des certificats.

X509_STORE_get_ex_new_index() retourne un nouvel index ou -1 en cas d'échec.

X509_STORE_get_ex_data() retourne les données d'application ou NULL en cas d'échec.

NAME

DESCRIPTION

The X509_STORE object is used to hold trusted certificates and CRLs (Certificate Revocation Lists). It is used by the verification functions like X509_verify_cert(). The functions described here provide ways to manipulate and query an X509_STORE object.

X509_STORE_new() creates and returns a new empty X509_STORE object. It returns NULL on error.

X509_STORE_free() frees the X509_STORE object st.

X509_STORE_add_lookup() adds a X509_LOOKUP object to the store st. The X509_LOOKUP object defines how certificates and CRLs are retrieved. See X509_LOOKUP_hash_dir(3).

X509_STORE_add_cert() adds the X509_STORE object cert to the store st. This is typically used to add trusted root certificates.

X509_STORE_add_crl() adds the X509_CRL object crl to the store st.

X509_STORE_load_locations() loads certificates and CRLs from the specified location. If file is NULL, then the default system locations are searched. The ui_method is used for prompting if passphrases are needed (e.g. for encrypted private keys).

X509_STORE_load_file() is a convenience function that loads certificates and CRLs from the single file file. It's similar to calling X509_STORE_load_locations() with file set and ui_method set.

X509_STORE_load_system_default() loads certificates and CRLs from the system default locations.

X509_STORE_get_by_subject() searches the store st for an object of the given type with the given name. If obj is not NULL, it is used as a template and will be reused; otherwise, a new X509_OBJECT is allocated. The function returns a pointer to the found object, or NULL on failure. Note that the returned pointer might point to an object within the store, and should not be freed.

X509_STORE_get_by_issuer_and_serial() searches the store st for a certificate with the given issuer name and serial number.

X509_STORE_set_depth() sets the maximum certificate chain depth allowed during verification. A depth of 0 means only a self-signed certificate is allowed.

X509_STORE_set_flags() sets verification flags for the store st. See X509_VERIFY_PARAM_set_flags(3) for a list of possible flags.

X509_STORE_set_purpose() sets the intended purpose for certificates in the store. See X509_VERIFY_PARAM_set_purpose(3).

X509_STORE_set_trust() sets the trust settings for certificates in the store. See X509_VERIFY_PARAM_set_trust(3).

X509_STORE_set1_param() sets the verification parameters for the store st to be a copy of param. Any existing parameters in the store are freed.

X509_STORE_get0_param() returns a pointer to the verification parameters associated with the store. The returned pointer should not be freed.

X509_STORE_get_ex_new_index() returns a new index for application specific data. It should be called only once during library initialization.

X509_STORE_set_ex_data() associates data with the index idx in the store st. idx should be an index obtained from X509_STORE_get_ex_new_index().

X509_STORE_get_ex_data() retrieves the data associated with index idx from the store st.

X509_STORE_get0_objects() returns a pointer to the stack of all objects (certificates and CRLs) currently in the store. The returned pointer should not be freed.

X509_STORE_get1_objects() returns a new copy of the stack of all objects currently in the store. The caller is responsible for freeing the returned stack using sk_X509_OBJECT_pop_free().

RETURN VALUES

X509_STORE_new(), X509_STORE_get0_objects(), and X509_STORE_get0_param() return NULL on error.

X509_STORE_add_cert(), X509_STORE_add_crl(), X509_STORE_add_lookup(), X509_STORE_load_locations(), X509_STORE_load_file(), X509_STORE_load_system_default(), X509_STORE_set1_param(), X509_STORE_set_depth(), X509_STORE_set_flags(), X509_STORE_set_purpose(), X509_STORE_set_trust() return 1 on success and 0 on error.

X509_STORE_get_by_subject() and X509_STORE_get_by_issuer_and_serial() return a pointer to the found object on success, and NULL on error or if no matching object is found.

X509_STORE_get1_objects() returns a pointer to the stack of objects on success, and NULL on error.

X509_STORE_get_ex_new_index() returns a non-negative index on success, or -1 on error.

X509_STORE_set_ex_data() returns 1 on success, or 0 on error.

X509_STORE_get_ex_data() returns the associated data on success, or NULL if no data is associated with the index.

HISTORY

X509_STORE_add_cert() first appeared in SSLeay 0.8.0. X509_STORE_add_crl() first appeared in SSLeay 0.9.0. These functions have been available since OpenBSD 2.4.

X509_STORE_set_flags(), X509_STORE_set_purpose(), and X509_STORE_set_trust() first appeared in OpenSSL 0.9.7 and have been available since OpenBSD 3.2.

X509_STORE_set1_param() and X509_STORE_set_depth() first appeared in OpenSSL 0.9.8 and have been available since OpenBSD 4.5.

X509_STORE_get0_param(), X509_STORE_get0_objects(), X509_STORE_get_ex_new_index(), X509_STORE_set_ex_data(), and X509_STORE_get_ex_data() first appeared in OpenSSL 1.1.0 and have been available since OpenBSD 6.3.

X509_STORE_get1_objects() first appeared in BoringSSL and has been available since OpenBSD 7.5.
