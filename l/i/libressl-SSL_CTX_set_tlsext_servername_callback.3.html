SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3) Manuel de fonctions de bibliothèque SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3)

NOM

SSL_CTX_set_tlsext_servername_callback, SSL_CTX_set_tlsext_servername_arg, SSL_get_servername_type, SSL_get_servername, SSL_set_tlsext_host_name — gestion de l'indication du nom du serveur (SNI)

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_tlsext_servername_callback(SSL_CTX *ctx, int (*cb)(SSL *ssl, int *alert, void *arg));

long
SSL_CTX_set_tlsext_servername_arg(SSL_CTX *ctx, void *arg);

const char *
SSL_get_servername(const SSL *ssl, const int type);

int
SSL_get_servername_type(const SSL *ssl);

int
SSL_set_tlsext_host_name(SSL *ssl, const char *name);

DESCRIPTION

SSL_CTX_set_tlsext_servername_callback() définit la fonction de rappel de l'application cb utilisée par un serveur pour effectuer toute action ou configuration requise en fonction de l'extension servername reçue dans la connexion entrante. Comme la fonction de rappel ALPN, elle est exécutée pendant le traitement du Client Hello. Lorsque cb est NULL, SNI n'est pas utilisé.

La fonction de rappel servername doit retourner l'une des valeurs suivantes :

SSL_TLSEXT_ERR_OK
Ceci est utilisé pour indiquer que le nom du serveur demandé par le client a été accepté. Typiquement, un serveur appellera SSL_set_SSL_CTX(3) dans la fonction de rappel pour configurer une configuration différente pour le nom du serveur sélectionné dans ce cas.
SSL_TLSEXT_ERR_ALERT_FATAL
Dans ce cas, le nom du serveur demandé par le client n'est pas accepté et la négociation sera interrompue. La valeur de l'alerte à utiliser doit être stockée à l'emplacement pointé par le paramètre alert pour la fonction de rappel. Par défaut, cette valeur est initialisée à SSL_AD_UNRECOGNIZED_NAME.
SSL_TLSEXT_ERR_ALERT_WARNING
Si cette valeur est retournée, le nom du serveur n'est pas accepté par le serveur. Cependant, la négociation continuera et enverra une alerte d'avertissement à la place. La valeur de l'alerte doit être stockée à l'emplacement pointé par le paramètre alert comme pour SSL_TLSEXT_ERR_ALERT_FATAL ci-dessus. Notez que TLSv1.3 ne prend pas en charge les alertes d'avertissement, donc si TLSv1.3 a été négocié, cette valeur de retour est traitée de la même manière que SSL_TLSEXT_ERR_NOACK.
SSL_TLSEXT_ERR_NOACK
Cette valeur de retour indique que le nom du serveur n'est pas accepté par le serveur. Aucune alerte n'est envoyée et le serveur n'accusera pas réception du nom du serveur demandé.

SSL_CTX_set_tlsext_servername_arg() définit un argument spécifique au contexte à passer à la fonction de rappel via le paramètre arg pour ctx.

SSL_set_tlsext_host_name() définit l'extension Client Hello d'indication du nom du serveur pour contenir la valeur name, ou la supprime si name est NULL. Le type d'extension d'indication du nom du serveur est défini comme TLSEXT_NAMETYPE_host_name tel que défini dans la RFC 3546.

Les trois fonctions sont implémentées comme des macros.

VALEURS DE RETOUR

SSL_CTX_set_tlsext_servername_callback() et SSL_CTX_set_tlsext_servername_arg() retournent toujours 1, indiquant le succès.

SSL_get_servername() retourne la valeur de l'extension servername du type spécifié si elle est fournie dans le Client Hello, ou NULL sinon.

SSL_get_servername_type() retourne le type de nom du serveur ou -1 si aucun nom de serveur n'est présent. Actuellement, le seul type pris en charge (défini dans la RFC 3546) est TLSEXT_NAMETYPE_host_name.

SSL_set_tlsext_host_name() retourne 1 en cas de succès ou 0 en cas d'erreur.

VOIR AUSSI

ssl(3), SSL_CTX_callback_ctrl(3), SSL_CTX_set_alpn_select_cb(3)

HISTORIQUE

Ces fonctions sont apparues pour la première fois dans OpenSSL 0.9.8f et sont disponibles depuis OpenBSD 4.5.
