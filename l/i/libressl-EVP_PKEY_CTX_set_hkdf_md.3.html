NOM

EVP_PKEY_CTX_set_hkdf_md, EVP_PKEY_CTX_set1_hkdf_salt, EVP_PKEY_CTX_set1_hkdf_key, EVP_PKEY_CTX_add1_hkdf_info, EVP_PKEY_CTX_hkdf_mode — Algorithme de dérivation de clé basé sur HMAC-Extract-and-Expand

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/evp.h>
#include <openssl/kdf.h>

int
EVP_PKEY_CTX_hkdf_mode(EVP_PKEY_CTX *pctx, int mode);

int
EVP_PKEY_CTX_set_hkdf_md(EVP_PKEY_CTX *pctx, const EVP_MD *md);

int
EVP_PKEY_CTX_set1_hkdf_salt(EVP_PKEY_CTX *pctx, unsigned char *salt, int saltlen);

int
EVP_PKEY_CTX_set1_hkdf_key(EVP_PKEY_CTX *pctx, unsigned char *key, int keylen);

int
EVP_PKEY_CTX_add1_hkdf_info(EVP_PKEY_CTX *pctx, unsigned char *info, int infolen);

DESCRIPTION

L'algorithme EVP_PKEY_HKDF implémente la fonction de dérivation de clé HKDF. HKDF suit le paradigme "extract-then-expand" (extraire puis développer), où la KDF est logiquement composée de deux modules. La première étape prend le matériel de clé d'entrée et en "extrait" une clé pseudorandom de longueur fixe K. La deuxième étape "développe" la clé K en plusieurs clés pseudorandom supplémentaires (la sortie de la KDF).

EVP_PKEY_CTX_hkdf_mode() définit le mode de l'opération HKDF. Il existe trois modes actuellement définis :

EVP_PKEY_HKDEF_MODE_EXTRACT_AND_EXPAND
C'est le mode par défaut. Appeler EVP_PKEY_derive(3) sur un EVP_PKEY_CTX configuré pour HKDF effectuera une extraction suivie d'une opération d'expansion en une seule fois. La clé dérivée renvoyée sera le résultat après l'opération d'expansion. La clé pseudorandom intermédiaire de longueur fixe K n'est pas renvoyée.

Dans ce mode, le condensat, la clé, le sel et les informations doivent être définis avant qu'une clé ne soit dérivée, sinon une erreur se produira.

EVP_PKEY_HKDEF_MODE_EXTRACT_ONLY
Dans ce mode, appeler EVP_PKEY_derive(3) effectuera uniquement l'opération d'extraction. La valeur renvoyée sera la clé pseudorandom intermédiaire de longueur fixe K.

Le condensat, la clé et le sel doivent être définis avant qu'une clé ne soit dérivée, sinon une erreur se produira.

EVP_PKEY_HKDEF_MODE_EXPAND_ONLY
Dans ce mode, appeler EVP_PKEY_derive(3) effectuera uniquement l'opération d'expansion. La clé d'entrée doit être définie sur la clé pseudorandom intermédiaire de longueur fixe K renvoyée par une opération d'extraction précédente.

Le condensat, la clé et les informations doivent être définis avant qu'une clé ne soit dérivée, sinon une erreur se produira.

EVP_PKEY_CTX_set_hkdf_md() définit le condensat de message associé à la HKDF.

EVP_PKEY_CTX_set1_hkdf_salt() définit le sel sur saltlen octets du tampon salt. Toute valeur existante est remplacée.

EVP_PKEY_CTX_set1_hkdf_key() définit la clé sur keylen octets du tampon key. Toute valeur existante est remplacée.

EVP_PKEY_CTX_add1_hkdf_info() définit la valeur d'information sur infolen octets du tampon info. Si une valeur est déjà définie, elle est ajoutée à la valeur existante.

CONTROLES DE CHAÎNE

HKDF prend également en charge les opérations de contrôle basées sur des chaînes via EVP_PKEY_CTX_ctrl_str(3). Le paramètre type "md" utilise la valeur fournie comme nom de l'algorithme de condensat à utiliser. Le paramètre type "mode" accepte "EXTRACT_AND_EXPAND", "EXTRACT_ONLY" et "EXPAND_ONLY" comme valeur pour déterminer le mode à utiliser. Les paramètres type "salt", "key" et "info" utilisent le paramètre valeur fourni comme graine, clé ou information. Les noms "hexsalt", "hexkey" et "hexinfo" sont similaires, sauf qu'ils prennent une chaîne hexadécimale qui est convertie en binaire.

NOTES

Toutes ces fonctions sont implémentées comme des macros.

Un contexte pour HKDF peut être obtenu en appelant :

EVP_PKEY_CTX *pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_HKDF, NULL);

La longueur totale du tampon d'informations ne peut pas dépasser 1024 octets : cela devrait être plus que suffisant pour toute utilisation normale de HKDF.

La longueur de sortie d'une opération d'expansion HKDF est spécifiée via le paramètre de longueur de la fonction EVP_PKEY_derive(3). Comme la longueur de sortie de HKDF est variable, passer un tampon NULL comme moyen d'obtenir la longueur requise n'est pas significatif avec HKDF dans un mode qui effectue une opération d'expansion. Au lieu de cela, l'appelant doit allouer un tampon de la longueur souhaitée et le passer à EVP_PKEY_derive(3) avec (un pointeur initialisé à) la longueur souhaitée. Passer un tampon NULL pour obtenir la longueur est autorisé lors de l'utilisation de EVP_PKEY_HKDEF_MODE_EXTRACT_ONLY.

VALEURS DE RETOUR

Toutes ces fonctions retournent 1 en cas de succès et 0 ou une valeur négative en cas d'échec. En particulier, une valeur de retour de -2 indique que l'opération n'est pas prise en charge par l'algorithme de clé publique.

EXEMPLES

Cet exemple dérive 10 octets en utilisant SHA-256 avec la clé secrète "secret", la valeur de sel "salt" et la valeur d'informations "label" :

EVP_PKEY_CTX *pctx;
unsigned char out[10];
size_t outlen = sizeof(out);

if ((pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_HKDF, NULL)) == NULL)
	/* Erreur */

if (EVP_PKEY_derive_init(pctx) <= 0)
	/* Erreur */
if (EVP_PKEY_CTX_set_hkdf_md(pctx, EVP_sha256()) <= 0)
	/* Erreur */
if (EVP_PKEY_CTX_set1_hkdf_salt(pctx, "salt", 4) <= 0)
	/* Erreur */
if (EVP_PKEY_CTX_set1_hkdf_key(pctx, "secret", 6) <= 0)
	/* Erreur */
if (EVP_PKEY_CTX_add1_hkdf_info(pctx, "label", 5) <= 0)
	/* Erreur */
if (EVP_PKEY_derive(pctx, out, &outlen) <= 0)
	/* Erreur */

NAME

EVP_PKEY_CTX_set_hkdf_md, EVP_PKEY_CTX_set1_hkdf_salt, EVP_PKEY_CTX_set1_hkdf_key, EVP_PKEY_CTX_add1_hkdf_info, EVP_PKEY_CTX_hkdf_mode - HKDF (HMAC-based Extract-and-Expand Key Derivation Function) key generation

SYNOPSIS

#include <openssl/evp.h>

int EVP_PKEY_CTX_set_hkdf_md(EVP_PKEY_CTX *ctx, const EVP_MD *md);
int EVP_PKEY_CTX_set1_hkdf_salt(EVP_PKEY_CTX *ctx, const unsigned char *salt,
    int len);
int EVP_PKEY_CTX_set1_hkdf_key(EVP_PKEY_CTX *ctx, const unsigned char *key,
    int len);
int EVP_PKEY_CTX_add1_hkdf_info(EVP_PKEY_CTX *ctx, const unsigned char *info,
    int len);
int EVP_PKEY_CTX_hkdf_mode(EVP_PKEY_CTX *ctx, int mode);

DESCRIPTION

HKDF is a key derivation function specified in RFC 5869. It uses an underlying HMAC construction (see HMAC(3)) to derive keys from a shared secret. It consists of two phases: Extract and Expand.

The Extract phase takes the input shared secret, and optionally a salt, and extracts it into a fixed-length pseudorandom key (PRK). If the salt is not provided, it is recommended to use a salt of zero length.

The Expand phase takes the PRK, and optional information fields, and expands it into a variable length output keying material (OKM).

The functions described here are used to configure an EVP_PKEY_CTX for use with the HKDF algorithm. The default algorithm is derived from the digest specified by EVP_PKEY_CTX_set_hkdf_md().

EVP_PKEY_CTX_set_hkdf_md() sets the digest to be used for the HMAC construction. The digest must be a digest that can be used with HMAC, e.g. SHA1, SHA256, etc. If md is NULL, then the default digest is used.

EVP_PKEY_CTX_set1_hkdf_salt() sets the salt to be used. If salt is NULL, then a salt of zero length is used. The salt can be provided multiple times, in which case the value is appended.

EVP_PKEY_CTX_set1_hkdf_key() sets the input keying material (IKM) to be used. This is the shared secret that the HKDF derivation starts with. If key is NULL, then a key of zero length is used.

EVP_PKEY_CTX_add1_hkdf_info() sets the information string to be used. This string can be used to bind the derived key to application-specific context. The information string can be provided multiple times, in which case the value is appended.

EVP_PKEY_CTX_hkdf_mode() sets the mode of operation. The possible modes are HKDF_MODE_EXTRACT_ONLY and HKDF_MODE_EXPAND_ONLY. These are typically not needed, as the default mode is to perform both the extract and expand phases.

STRING CTRLS

The following string controls are also available:

EVP_CTRL_HKDF_SET_MD
Sets the digest. The value is a pointer to an EVP_MD structure.
EVP_CTRL_HKDF_SET_SALT
Sets the salt. The value is an OSSL_PARAM structure.
EVP_CTRL_HKDF_SET_KEY
Sets the input keying material. The value is an OSSL_PARAM structure.
EVP_CTRL_HKDF_ADD_INFO
Adds to the information string. The value is an OSSL_PARAM structure.
EVP_CTRL_HKDF_SET_MODE
Sets the mode. The value is an int.

NOTES

The HKDF algorithm is described in RFC 5869.

The digest and input keying material are mandatory. The salt and info parameters are optional.

If the salt is not provided, it is recommended to use a salt of zero length.

The output key length is determined by the application and is specified when calling EVP_PKEY_derive().

RETURN VALUES

All the functions described here return 1 on success, and 0 or a negative value on failure.

EXAMPLES

Derive a 32-byte key using HKDF-SHA256:

    EVP_PKEY_CTX *pctx, *kctx;
    EVP_PKEY *hkdf;
    unsigned char *keyout;
    size_t keylen = 32;
    unsigned char *salt = (unsigned char *)"salt";
    size_t saltlen = 4;
    unsigned char *ikm = (unsigned char *)"mykey";
    size_t ikmlen = 5;
    unsigned char *info = (unsigned char *)"myinfo";
    size_t infolen = 6;

    /* Create context for HKDF */
    if (NULL == (pctx = EVP_PKEY_CTX_new_id(EVP_PKEY_HKDEF, NULL)))
        goto err;
    if (EVP_PKEY_CTX_set_hkdf_md(pctx, EVP_sha256()) <= 0)
        goto err;
    if (EVP_PKEY_CTX_set1_hkdf_salt(pctx, salt, saltlen) <= 0)
        goto err;
    if (EVP_PKEY_CTX_set1_hkdf_key(pctx, ikm, ikmlen) <= 0)
        goto err;
    if (EVP_PKEY_CTX_add1_hkdf_info(pctx, info, infolen) <= 0)
        goto err;

    /* Derive the key */
    keyout = OPENSSL_malloc(keylen);
    if (NULL == keyout)
        goto err;

    if (EVP_PKEY_derive(pctx, keyout, &keylen) <= 0)
        goto err;

    /* Use keyout... */

    OPENSSL_free(keyout);
    EVP_PKEY_CTX_free(pctx);
    return 1;

err:
    /* Handle errors... */
    return 0;
