NOM

limits.conf - fichier de configuration pour le module pam_limits

DESCRIPTION

Le module pam_limits.so applique les limites ulimit, la priorité nice et la limite du nombre de sessions de connexion simultanées aux sessions de connexion des utilisateurs. Cette description de la syntaxe du fichier de configuration s'applique au fichier /etc/security/limits.conf et aux fichiers *.conf du répertoire /etc/security/limits.d.

La syntaxe des lignes est la suivante :

<domaine> <type> <élément> <valeur>

Les champs listés ci-dessus doivent être remplis comme suit :

<domaine>

•un nom d'utilisateur
•un nom de groupe, avec la syntaxe @groupe. Ceci ne doit pas être confondu avec les netgroups.
•le joker *, pour l'entrée par défaut.
•le joker %, pour la limite maxlogins seulement, peut aussi être utilisé avec la syntaxe %groupe. Si le joker % est utilisé seul, il est identique à l'utilisation de * avec la limite maxsyslogins. Avec un groupe spécifié après %, cela limite le nombre total de connexions de tous les utilisateurs membres du groupe.
•une plage d'UID spécifiée comme <min_uid>:<max_uid>. Si min_uid est omis, la correspondance est exacte pour max_uid. Si max_uid est omis, tous les uids supérieurs ou égaux à min_uid correspondent.
•une plage de GID spécifiée comme @<min_gid>:<max_gid>. Si min_gid est omis, la correspondance est exacte pour max_gid. Si max_gid est omis, tous les gids supérieurs ou égaux à min_gid correspondent. Pour la correspondance exacte, tous les groupes, y compris les groupes supplémentaires de l'utilisateur, sont examinés. Pour les correspondances de plage, seul le groupe primaire de l'utilisateur est examiné.
•un gid spécifié comme %:<gid> applicable uniquement à la limite maxlogins. Il limite le nombre total de connexions de tous les utilisateurs membres du groupe avec le gid spécifié.

<type>

hard

pour appliquer les limites de ressources hard (duras). Ces limites sont définies par le superutilisateur et appliquées par le noyau. Les utilisateurs ne peuvent pas augmenter leur propre exigence de ressources système au-delà de ces valeurs.

soft

pour appliquer les limites de ressources soft (douces). Ces limites sont celles que l'utilisateur peut augmenter ou diminuer dans la plage autorisée par les limites hard préexistantes. Les valeurs spécifiées avec ce jeton peuvent être considérées comme des valeurs par défaut, pour une utilisation normale du système.

-

pour appliquer à la fois les limites de ressources soft et hard.

Note : si vous spécifiez un type de '-' mais omettez les champs élément et valeur, le module n'appliquera jamais de limites à l'utilisateur/groupe spécifié, etc.

<élément>

core

limite la taille du fichier core (Ko)

data

taille maximale des données (Ko)

fsize

taille maximale des fichiers (Ko)

memlock

espace maximal d'adressage verrouillé en mémoire (Ko)

nofile

nombre maximal de descripteurs de fichiers ouverts

rss

taille maximale du set résident (Ko) (Ignoré sous Linux 2.4.30 et supérieur)

stack

taille maximale de la pile (Ko)

cpu

temps CPU maximal (minutes)

nproc

nombre maximal de processus

as

limite d'espace d'adressage (Ko)

maxlogins

nombre maximal de connexions pour cet utilisateur (cette limite ne s'applique pas à l'utilisateur avec uid=0)

maxsyslogins

nombre maximal de toutes les connexions sur le système ; l'utilisateur n'est pas autorisé à se connecter si le nombre total de toutes les connexions utilisateur dépasse le nombre spécifié (cette limite ne s'applique pas à l'utilisateur avec uid=0)

nonewprivs

valeur de 0 ou 1 ; si réglé sur 1, désactive l'acquisition de nouveaux privilèges en invoquant prctl(PR_SET_NO_NEW_PRIVS)

priority

priorité d'exécution du processus utilisateur (les valeurs négatives augmentent la priorité du processus)

locks

fichiers verrouillés maximum (Linux 2.4 et supérieur)

sigpending

nombre maximal de signaux en attente (Linux 2.6 et supérieur)

msgqueue

mémoire maximale utilisée par les files de messages POSIX (octets) (Linux 2.6 et supérieur)

nice

priorité nice maximale autorisée à augmenter (Linux 2.6.12 et supérieur) valeurs : [-20,19]

rtprio

priorité temps réel maximale autorisée pour les processus non privilégiés (Linux 2.6.12 et supérieur)

rttime

Délai d'attente pour les tâches temps réel en microsecondes (Linux 2.6.25 et supérieur)

Tous les éléments supportent les valeurs -1, unlimited ou infinity indiquant aucune limite, sauf pour priority, nice et nonewprivs. Si nofile doit être réglé sur l'une de ces valeurs, il sera réglé sur le contenu de /proc/sys/fs/nr_open à la place (voir setrlimit(3)).

Si une limite dure ou douce d'une ressource est réglée sur une valeur valide, mais en dehors de la plage supportée par le système local, le système peut rejeter la nouvelle limite ou un comportement inattendu peut survenir. Si la valeur de contrôle required est utilisée, le module rejettera la connexion si une limite n'a pas pu être définie.

En général, les limites individuelles ont la priorité sur les limites de groupe, donc si vous n'imposez aucune limite au groupe admin, mais qu'un de ses membres a une ligne de limites, l'utilisateur aura ses limites définies selon cette ligne.

De plus, veuillez noter que tous les réglages de limites sont faits par connexion. Ils ne sont ni globaux, ni permanents ; ils existent uniquement pour la durée de la session. Une exception est l'option maxlogin, qui est globale au système. Mais il y a une condition de concurrence (race condition), les connexions concurrentes au même moment ne seront pas toujours détectées comme telles, mais seulement comptées comme une.

Dans le fichier de configuration limits, le caractère '#' introduit un commentaire - après lequel le reste de la ligne est ignoré.

Le module pam_limits rapporte les problèmes de configuration trouvés dans son fichier de configuration et les erreurs via syslog(3).

EXEMPLES

Voici quelques lignes d'exemple qui pourraient être spécifiées dans /etc/security/limits.conf.

*               soft    core            0
*               hard    nofile          512
@student        hard    nproc           20
@faculty        soft    nproc           20
@faculty        hard    nproc           50
ftp             hard    nproc           0
@student        -       maxlogins       4
@student        -       nonewprivs      1
:123            hard    cpu             5000
@500:           soft    cpu             10000
600:700         hard    locks           10
