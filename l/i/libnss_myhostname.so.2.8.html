NOM

nss-myhostname, libnss_myhostname.so.2 - Résolution du nom d'hôte pour le nom d'hôte du système configuré localement

SYNTAXE

libnss_myhostname.so.2

DESCRIPTION

nss-myhostname est un module plug-in pour la fonctionnalité NSS (Name Service Switch) de la bibliothèque C GNU (glibc), fournissant principalement la résolution du nom d'hôte pour le nom d'hôte du système configuré localement tel que retourné par gethostname(2). Les noms d'hôte précis résolus par ce module sont :

•Le nom d'hôte local configuré est résolu en toutes les adresses IP configurées localement, ordonnées par leur portée, ou — si aucune n'est configurée — l'adresse IPv4 127.0.0.2 (qui se trouve sur la boucle locale) et l'adresse IPv6 ::1 (qui est l'hôte local).
•Les noms d'hôte "localhost" et "localhost.localdomain" (ainsi que tout nom d'hôte se terminant par ".localhost" ou ".localhost.localdomain") sont résolus en adresses IP 127.0.0.1 et ::1.
•Le nom d'hôte "_gateway" est résolu en toutes les adresses de passerelle par défaut actuelles, ordonnées par leur métrique. Ceci assigne un nom d'hôte stable à la passerelle actuelle, utile pour y faire référence indépendamment de l'état de configuration réseau actuel.
•Le nom d'hôte "_outbound" est résolu en adresses locales IPv4 et IPv6 les plus susceptibles d'être utilisées pour la communication avec d'autres hôtes. Ce sont les adresses source préférées des passerelles par défaut si elles sont spécifiées, ou déterminées en demandant une décision de routage vers les passerelles par défaut configurées au noyau, puis en utilisant les adresses IP locales sélectionnées par cette décision. Ce nom d'hôte n'est disponible que s'il existe au moins une passerelle par défaut locale configurée. Ceci assigne un nom d'hôte stable aux adresses IP sortantes locales, utile pour y faire référence indépendamment de l'état de configuration réseau actuel.

Divers logiciels dépendent d'un nom d'hôte local toujours résolvable. Lorsque l'on utilise des noms d'hôte dynamiques, ceci est traditionnellement réalisé en modifiant /etc/hosts en même temps que le nom d'hôte. Ceci est problématique car cela nécessite un système de fichiers /etc/ accessible en écriture et est fragile car le fichier pourrait être modifié par l'administrateur en même temps. Avec nss-myhostname activé, la modification de /etc/hosts n'est pas nécessaire, et sur de nombreux systèmes, le fichier devient entièrement optionnel.

Pour activer les modules NSS, ajoutez "myhostname" à la ligne commençant par "hosts:" dans /etc/nsswitch.conf.

Il est recommandé de placer "myhostname" après "files" et avant "dns". Ceci résout localement les noms d'hôtes connus comme "localhost" et les noms d'hôtes de la machine. Ceci est cohérent avec le comportement de nss-resolve, et permet toujours de les outrepasser via /etc/hosts.

Gardez à l'esprit que nss-myhostname (et nss-resolve) résolvent également dans l'autre sens — des adresses IP localement attachées vers des noms d'hôtes. Si vous comptez sur cette recherche fournie par DNS, vous pourriez vouloir ordonner les choses différemment.

EXEMPLE

Voici un exemple de fichier /etc/nsswitch.conf qui active correctement nss-myhostname :

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis

Pour tester, utilisez l'outil getent(1) de glibc :

$ getent ahosts `hostname`
::1       STREAM omega
::1       DGRAM
::1       RAW
127.0.0.2       STREAM
127.0.0.2       DGRAM
127.0.0.2       RAW

Dans ce cas, le nom d'hôte local est omega.
