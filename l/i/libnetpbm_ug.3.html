NOM

libnetpbm_ug - code d'exemple netpbm

DESCRIPTION

La bibliothèque de programmation Libnetpbm fait partie de Netpbm(1)

Exemple

Voici un exemple de programme C qui utilise libnetpbm pour lire une image Netpbm en entrée et produire une image Netpbm en sortie.

   /* Fragment de programme exemple pour lire une image PAM ou PNM
      depuis stdin, additionner les valeurs de chaque échantillon qu'elle contient
      (je ne sais pas pourquoi), et écrire l'image inchangée vers
      stdout. */
   #include <netpbm/pam.h>
   struct pam inpam, outpam;
   tuple * tuplerow;
   unsigned int row;
   pm_init(argv[0], 0);
   pnm_readpaminit(stdin, &inpam, PAM_STRUCT_SIZE(tuple_type));
   outpam = inpam; outpam.file = stdout;
   pnm_writepaminit(&outpam);
   tuplerow = pnm_allocpamrow(&inpam);
   for (row = 0; row < inpam.height; row++) {
       unsigned int column;
       pnm_readpamrow(&inpam, tuplerow);
       for (column = 0; column < inpam.width; ++column) {
           unsigned int plane;
           for (plane = 0; plane < inpam.depth; ++plane) {
               grand_total += tuplerow[column][plane];
           }
       }
       pnm_writepamrow(&outpam, tuplerow); }
   pnm_freepamrow(tuplerow);

Guide d'utilisation de Libnetpbm

classes de libnetpbm

Dans cette section, Guide To Using Libnetpbm, nous couvrons uniquement les fonctions PAM de libnetpbm. Comme décrit dans l'introduction à libnetpbm (3), il existe quatre autres classes de fonctions de traitement d'images (PBM, PGM, PPM, PNM). Elles sont moins importantes, car vous pouvez tout faire plus facilement avec les fonctions PAM, mais si vous travaillez sur de vieux programmes ou si vous avez besoin de l'efficacité supplémentaire que ces anciennes fonctions peuvent parfois fournir, vous les trouverez documentées ici : PBMFunctionManual(3) , PGMFunctionManual(3) , PPMFunctionManual(3) , et PNMFunctionManual(3)

Au cas où vous vous poseriez la question, ce qui rend les fonctions PAM plus faciles à utiliser est :

  • Chaque fonction gère tous les formats. Elle le fait sans convertir vers un format commun, donc votre programme peut traiter les différents formats différemment s'il le souhaite. Cependant, l'interface facilite l'ignorance des différences entre les formats par votre programme si c'est ce que vous souhaitez.
  • Les listes de paramètres des fonctions PAM transmettent la plupart des informations sur l'image avec laquelle vous travaillez via une seule structure pam, que vous pouvez construire une fois et utiliser encore et encore, tandis que les anciennes fonctions nécessitent de passer jusqu'à 5 informations sur l'image (hauteur, largeur, etc.) comme arguments séparés à chaque fonction.

Initialisation de la bibliothèque

Chaque programme qui utilise la bibliothèque doit initialiser la bibliothèque, c'est-à-dire configurer le processus pour utiliser la bibliothèque, comme décrit dans Initialisation . C'est le but de l'appel à pm_init() dans l'exemple ci-dessus.

LA STRUCTURE pam

Les fonctions PAM prennent la plupart de leurs arguments sous la forme d'une seule structure pam. Ce n'est pas un objet opaque, mais juste un moyen pratique d'organiser les informations dont dépendent la plupart des fonctions. Vous êtes donc libre d'accéder ou de définir les éléments de la structure comme vous le souhaitez. Mais vous constaterez que dans la plupart des cas, il est plus pratique d'appeler pnm_readpaminit() ou pnm_writepaminit() pour définir les champs de la structure pam avant d'appeler toute autre fonction pam, puis de simplement passer la structure inchangée dans tous les appels futurs aux fonctions pam.

Les champs sont :

size
La taille de stockage en octets de cette structure entière.
len
La longueur, en octets, des informations dans cette structure. Les informations commencent dans le premier octet et sont contiguës. Cela ne peut pas être supérieur à size. size et len peuvent être utilisés pour rendre les programmes compatibles avec les versions nouvelles et plus anciennes des bibliothèques Netpbm.
file
Le fichier.
format
Le code de format de l'image. C'est PAM_FORMAT sauf si l'image PAM est en réalité une vue d'une image PBM, PGM ou PPM. Alors c'est PBM_FORMAT, RPBM_FORMAT, etc.

Il y a une bizarrerie importante dans la signification de ce membre lorsque vous utilisez la structure pam pour écrire une image : seule la partie type de celle-ci est significative. Un code de format Netpbm transmet deux informations : Le type de format (PBM, PGM, PPM ou PAM) et la nature plain/raw (PBM plain vs PBM brut, etc.). Mais lors de l'écriture, libnetpbm ignore la partie plain/raw et prend plutôt cette information du membre plainformat. Ainsi, PBM_FORMAT et RPBM_FORMAT sont identiques lors de l'écriture.

Cette bizarrerie existe pour des raisons historiques ; elle est nécessaire pour la cohérence avec les anciennes fonctions telles que pnm_writepnmrow() dont les arguments format et forceplain sont analogues.

Avant Netpbm 10.32 (février 2006), libnetpbm n'ignorait pas la nature plain/raw. Cela a entraîné un mauvais comportement de nombreux programmes, produisant une sortie au format plain alors qu'ils auraient dû, au minimum pour des raisons de compatibilité ascendante, produire une sortie au format brut.

Une façon courante d'utiliser ce membre est de copier ce membre et le membre plainformat d'un pam pour une image d'entrée vers un pam pour une image de sortie. Lorsque vous faites cela, votre image de sortie sera au format brut, que votre image d'entrée soit plain ou brute, et c'est le comportement conventionnel des programmes Netpbm.

plainformat
Ceci est une valeur booléenne (0 = faux, 1 = vrai), significative uniquement lors de l'écriture d'un fichier image. Cela signifie écrire dans la version plain (texte) du format indiqué par format par opposition à la version brute (binaire). Notez que le code de format dans format semblerait spécifier complètement le format, rendant plainformat redondant. Mais voir la description de format pour comprendre pourquoi ce n'est pas vrai.

Jusqu'à Netpbm 10.32 (février 2006), ceci était défini un peu différemment. Le membre format identifiait en fait complètement le format et plainformat était redondant et existait comme membre séparé uniquement pour la vitesse de calcul. Mais cela était incohérent avec l'ancienne interface libnetpbm (par exemple, pnm_writepnm()) et rendait difficile l'écriture de programmes compatibles avec les versions antérieures. Avant Netpbm 10.32, cela affectait la lecture ainsi que l'écriture.

Les fonctions de lecture d'images libnetpbm définissent ce champ à faux, pour votre commodité dans la construction d'un pam d'image de sortie à partir d'un pam d'image d'entrée.

height
La hauteur de l'image en lignes.
width
La largeur de l'image en nombre de colonnes (tuples par ligne).
depth
La profondeur de l'image (degré ou nombre d'échantillons dans chaque tuple).
maxval
La valeur maximale de l'image. Voir les définitions dans pam(5)
bytes_per_sample
Le nombre d'octets utilisés pour représenter chaque échantillon dans le fichier image. Voir la définition du format dans pam(5) est entièrement redondant avec maxval. Il existe comme membre séparé pour la vitesse de calcul.
tuple_type
Le type de tuple de l'image. Voir les définitions dans pam(5) sauf les suivantes, qui sont utilisées pour une image PAM qui est en réalité une vue d'une image PBM, PGM ou PPM : PAM_PBM_TUPLETYPE, PAM_PGM_TUPLETYPE, PAM_PPM_TUPLETYPE.
allocation_depth

libnetpbm_ug(3)

NAME

libnetpbm - Netpbm image processing library

DESCRIPTION

The libnetpbm library is a collection of C functions for manipulating Netpbm images. Netpbm is a collection of programs and libraries for converting images between various formats, especially the PNM (Portable AnyMap) formats.

The Netpbm formats consist of a number of individual formats, each with two variants: the older plain (ASCII) format and the newer raw (binary) format. The plain formats are human-readable but inefficient; the raw formats are more compact and efficient.

The Netpbm library is designed to make it easy to write programs that read and write these formats. It abstracts away the details of the format variants and the differences between them.

The library is organized into a number of modules, each dealing with a specific aspect of Netpbm image processing.

PAM_STRUCT_SIZE(field)
This macro is used to calculate the size of the pam_detail structure, accounting for optional fields.

The pam structure is the central data structure for PAM images. It contains information about the image, such as its dimensions, color space, pixel depth, and sample formats. Many of these fields are optional and are only present if the image has certain properties. The PAM_STRUCT_SIZE macro helps to correctly initialize the size of the structure to ensure that all relevant fields are accounted for, especially when dealing with optional fields like comment_p.

When using functions that read or write PAM images, you often need to pass the size of the pam_detail structure to them. This is done using the PAM_STRUCT_SIZE macro, passing the name of the last relevant field in the structure. For example, to include the comment_p field, you would use PAM_STRUCT_SIZE(comment_p).

Example usage:


    struct pam pam;
    ...
    pm_init("myprogram", 0);
    pam.size = PAM_STRUCT_SIZE(comment_p);
    ...

This ensures that the structure is large enough to hold all the fields that might be used, including optional ones. If you omit optional fields, you can use a smaller size, but using the full size is generally safer and recommended.

depth
The number of samples per pixel. For example, an RGB image has a depth of 3. A grayscale image has a depth of 1. A grayscale with alpha has a depth of 2.
allocation_depth
The number of samples for which memory is allocated for any tuple associated with this PAM structure. This must be at least as great as 'depth'. Only the first 'depth' of the samples of a tuple are meaningful.

The purpose of this is to make it possible for a program to change the type of a tuple to one with more or fewer planes.

0 means the allocation depth is the same as the image depth.

comment_p
Pointer to a pointer to a NUL-terminated ASCII string of comments. When reading an image, this contains the comments from the image's PAM header; when writing, the image gets these as comments, right after the magic number line. The individual comments are delimited by newlines and are in the same order as in the PAM header. The '#' at the beginning of a PAM header line that indicates the line is a comment is not part of the comment.

On output, NULL means no comments.

On input, libnetpbm mallocs storage for the comments and placed the pointer at *comment_p. Caller must free it. NULL means libnetpbm does not return comments and does not allocate any storage.

Examples:


    const char * comments;
    ...
    pam.comment_p = &comments;
    pnm_readpaminit(fileP, &pam, PAM_STRUCT_SIZE(comment_p));
    printf('The comments are:\n');
    printf('%s', comments)
    free(comments);


    const char * comments;
    ...
    comments = strdup('This is a comment 1\nThis is comment 2\n');
    pam.comment_p = &comments;
    pnm_writepaminit(&pam);
    free(comments);

This works only for PAM images. If you read a PNM image, you always get back a null string. If you write a PNM image, you always get an image that contains no comments.

This member does not exist before Netpbm 10.35 (August 2006). Before that, there is no way with libnetpbm to get or set comments. The macro PAM_HAVE_COMMENT_P is defined in pam.h where the member exists.

PLAIN VERSUS RAW FORMAT

The PNM formats each come in two varieties: the older plain (text) format and the newer raw (binary) format. There are different format codes for the plain and raw formats, but which of the two formats the pnm and pam functions write is independent of the format code you pass to them.

The pam functions always write raw formats. If you specify the format code for a plain format, a pam function assumes instead the raw version of that format.

The pnm functions choose between plain and raw based on the forceplain parameter that every write-type pnm function has. If this boolean value is true, the function writes the plain version of the format specified by the format code. If it is false, the function writes the raw version of the format specified by the format code.

We are trying to stamp out the older plain formats, so it would be a wise choice not to write a program that sets forceplain true under any circumstance. A user who needs a plain format can use the pnmtoplainpnm program to convert the output of your program to plain format.
