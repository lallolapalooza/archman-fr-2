NOM

libtiff - introduction à libtiff, une bibliothèque pour lire et écrire des fichiers TIFF

SYNTAXE

#include <tiffio.h>
cc fichier.c -ltiff

DESCRIPTION

libtiff est une bibliothèque pour lire et écrire des fichiers de données encodés avec le format “Tag Image File”, Révision 6.0 (ou révision 5.0 ou révision 4.0). Ce format de fichier convient à l'archivage de données d'images multicolores et monochromes.

La bibliothèque prend en charge plusieurs algorithmes de compression, comme indiqué par le champ Compression, notamment : pas de compression (1), compression Huffman 1D CCITT (2), compression fac-similé Groupe 3 CCITT (3), compression fac-similé Groupe 4 CCITT (4), compression Lempel-Ziv & Welch (5), compression JPEG de base (7), compression Huffman 1D alignée sur les mots (32771), compression PackBits (32773). De plus, plusieurs algorithmes de compression non standard sont pris en charge : l'algorithme de compression 4 bits utilisé par le programme ThunderScan (32809) (décompression seule), l'algorithme de compression 2 bits de NeXT (32766) (décompression seule), un algorithme expérimental de type LZ connu sous le nom de Deflate (32946), et un schéma expérimental de compression CIE LogLuv conçu pour les images à plage dynamique élevée (32845 pour LogL et 32845 pour LogLuv). Les informations de répertoire peuvent être en ordre d'octets petit-boutiste (little-endian) ou gros-boutiste (big-endian) ; l'échange d'octets est effectué automatiquement par la bibliothèque. L'ordre des bits des données peut être du bit le plus significatif (MSB) au bit le moins significatif (LSB) ou LSB au MSB. Enfin, la bibliothèque ne prend pas en charge les fichiers dans lesquels les champs BitsPerSample, Compression, MinSampleValue, ou MaxSampleValue sont définis différemment par échantillon (dans la Rev. 6.0, la balise Compression n'est pas définie par échantillon, donc cela est sans importance).

TYPES DE DONNÉES

La bibliothèque utilise intensivement des typedefs C pour promouvoir la portabilité. Deux ensembles de typedefs sont utilisés, l'un pour la communication avec les clients de la bibliothèque et l'autre pour les structures de données internes et l'analyse du format TIFF. Les typedefs suivants sont exposés aux utilisateurs soit par le biais de définitions de fonctions, soit par le biais de paramètres passés via les interfaces varargs.

typedef uint32_t ttag_t;    // balise de répertoire
typedef uint32_t tdir_t;    // index de répertoire
typedef uint16_t tsample_t; // numéro d'échantillon
typedef uint32_t tstrip_t;  // numéro de bande
typedef uint32_t ttile_t;   // numéro de tuile
typedef int64_t tmsize_t;   // type de taille signé (int32_t sur plateformes 32 bits)
typedef tmsize_t tsize_t;   // taille E/S en octets
typedef void* tdata_t;      // référence aux données d'image
typedef void* thandle_t;    // handle de données client
typedef uint64_t toff_t;    // décalage de fichier

Notez que tstrip_t, ttile_t et tsize_t sont contraints à ne pas dépasser 32 bits par les champs de 32 bits dans lesquels ils sont stockés dans l'image TIFF. De même, tsample_t est limité par le champ de 16 bits utilisé pour stocker la balise SamplesPerPixel.

tdir_t limite le nombre maximum d'IFD pouvant apparaître dans une image et peut être de taille arbitraire (sans pénalité). À partir de libtiff 4.5.0, tdir_t est un entier non signé de 32 bits. Auparavant, c'était un entier non signé de 16 bits.

ttag_t doit être soit int, unsigned int, pointeur, soit double car la bibliothèque utilise une interface varargs et C restreint le type du paramètre avant une ellipse à un type promu. toff_t est défini comme uint64_t car les décalages de fichiers TIFF sont des quantités de 32 bits (non signées), et les décalages de fichiers BigTIFF sont des quantités de 64 bits non signées. Une valeur signée est utilisée car certaines interfaces retournent -1 en cas d'erreur. Enfin, notez que les références de données spécifiées par l'utilisateur sont passées comme des handles opaques et ne sont converties qu'aux couches les plus basses où leur type est présumé.

UTILISATION DES BALISES

Pour une table des balises TIFF reconnues par la bibliothèque, consultez LibTIFF Coverage of the TIFF 6.0 Specification.

« BALISES PSEUDO »

En plus des balises TIFF normales, la bibliothèque prend en charge une collection de balises dont les valeurs se situent en dehors de la plage valide des balises TIFF. Ces balises sont appelées balises pseudo et sont utilisées pour contrôler diverses fonctions spécifiques aux codecs au sein de la bibliothèque. Le tableau ci-dessous

résume les pseudo-balises définies.

BALISES PRISES EN CHARGE PAR LIBTIFF

Nom de la balise Codec L/E Utilisation/Notes de la bibliothèque
TIFFTAG_FAXMODE G3 L/E fonctionnement général du codec
TIFFTAG_FAXFILLFUNC G3/G4 L/E fonction de remplissage bitmap
TIFFTAG_JPEGQUALITY JPEG L/E contrôle de la qualité de compression
TIFFTAG_JPEGCOLORMODE JPEG L/E contrôle des conversions d'espace colorimétrique
TIFFTAG_JPEGTABLESMODE JPEG L/E contrôle du contenu de la balise JPEGTables

TIFFTAG_FAXMODE :

Contrôle le fonctionnement du codec Groupe 3. Les valeurs possibles (bits indépendants qui peuvent être combinés par un OU bit à bit) sont :

FAXMODE_CLASSIC :

(activer le format ancien où le RTC est écrit à la fin de la dernière bande),

FAXMODE_NORTC :

(l'opposé de FAXMODE_CLASSIC ; également appelé FAXMODE_CLASSF),

FAXMODE_NOEOL :

(ne pas écrire de codes EOL au début de chaque ligne de données),

FAXMODE_BYTEALIGN :

(aligner chaque ligne encodée sur une frontière de 8 bits),

FAXMODE_WORDALIGN :

(aligner chaque ligne encodée sur une frontière de 16 bits),

La valeur par défaut dépend du schéma de compression ; cette pseudo-balise est utilisée par les différents codecs G3 et G4 pour partager du code.

TIFFTAG_FAXFILLFUNC :

Contrôle la fonction utilisée pour convertir des tableaux de segments noirs et blancs en tableaux de bits compactés. Ce crochet peut être utilisé pour imager des lignes de balayage décodées dans des rasters de plusieurs bits de profondeur (par exemple, pour un affichage en mode palette de couleurs) ou à d'autres fins. La valeur par défaut est un pointeur vers une fonction intégrée qui imager des données bilivelles compactées.

TIFFTAG_IPTCNEWSPHOTO :

La balise contient des métadonnées d'image selon la spécification IPTC newsphoto : Titre, légende, crédit, etc. Utilisé par la plupart des services de dépêches.

TIFFTAG_PHOTOSHOP :

La balise contient des informations de légende et des métadonnées Photoshop. Photoshop utilise en parallèle et de manière redondante avec les informations IPTCNEWSPHOTO.

TIFFTAG_JPEGQUALITY :

Contrôle le niveau de qualité de compression utilisé dans l'algorithme de base. Notez que les niveaux de qualité sont compris entre 0 et 100, avec une valeur par défaut de 75.

TIFFTAG_JPEGCOLORMODE :

Contrôle si des conversions sont effectuées entre les espaces colorimétriques RVB et YCbCr. Les valeurs possibles sont :

JPEGCOLORMODE_RAW :

(ne pas convertir), et

JPEGCOLORMODE_RGB :

(convertir vers/depuis RVB)

La valeur par défaut est JPEGCOLORMODE_RAW.

TIFFTAG_JPEGTABLESMODE :

Contrôle les informations écrites dans la balise JPEGTables. Les valeurs possibles (bits indépendants qui peuvent être combinés par un OU bit à bit) sont :

JPEGTABLESMODE_QUANT :

(inclure les tables de quantification), et

JPEGTABLESMODE_HUFF :

(inclure les tables de codage de Huffman).

La valeur par défaut est JPEGTABLESMODE_QUANT | JPEGTABLESMODE_HUFF.

TIFFTAG_ZIPQUALITY :

Contrôle la technique de compression utilisée par le codec Deflate. Les niveaux de qualité sont compris entre 1 et 9, les nombres plus élevés offrant une meilleure compression au prix d'un calcul plus important. Le niveau de qualité par défaut est 6, ce qui offre un bon compromis temps-espace.

TIFFTAG_PIXARLOGDATAFMT :

Contrôle le format des données utilisateur passées au codec PixarLog lors de l'encodage et passées depuis lors du décodage. Les valeurs possibles sont :

PIXARLOGDATAFMT_8BIT :

pour les pixels non signés de 8 bits,

PIXARLOGDATAFMT_8BITABGR :

pour les pixels non signés de 8 bits dans l'ordre ABGR,

PIXARLOGDATAFMT_11BITLOG :

pour les données brutes encodées en log sur 11 bits,

PIXARLOGDATAFMT_12BITPICIO :

pour les données compatibles PICIO sur 12 bits,

PIXARLOGDATAFMT_16BIT :

pour les échantillons signés de 16 bits, et

PIXARLOGDATAFMT_FLOAT :

pour les échantillons flottants IEEE de 32 bits.

TIFFTAG_PIXARLOGQUALITY :

Contrôle la technique de compression utilisée par le codec PixarLog. Cette valeur est traitée de manière identique à TIFFTAG_ZIPQUALITY ; voir la description ci-dessus.

TIFFTAG_SGILOGDATAFMT :

Contrôle le format des données client passées au codec SGILog lors de l'encodage et passées depuis lors du décodage. Les valeurs possibles sont :

SGILOGDATAFMT_FLTXYZ :

pour la conversion entre XYZ en virgule flottante IEEE 32 bits et LogLuv,

SGILOGDATAFMT_16BITLUV :

pour les pixels Luv encodés sur 16 bits,

SGILOGDATAFMT_32BITRAW : SGILOGDATAFMT_24BITRAW :

pour aucune conversion de données,

SGILOGDATAFMT_8BITRGB :

pour retourner des données RVB sur 8 bits (valide uniquement lors du décodage de données encodées en LogLuv),

SGILOGDATAFMT_FLTY :

pour la conversion entre Y en virgule flottante IEEE 32 bits et LogL,

SGILOGDATAFMT_16BITL :

pour les pixels L encodés sur 16 bits, et

SGILOGDATAFMT_8BITGRY :

pour retourner des données en niveaux de gris sur 8 bits (valide uniquement lors du décodage de données encodées en LogL).

DIAGNOSTICS

Tous les messages d'erreur sont dirigés via la routine TIFFErrorExtR(). Par défaut, les messages sont dirigés vers stderr sous la forme : module: message\n. Les messages d'avertissement sont de même dirigés via la routine TIFFWarningExtR().

BOGUES

  • La bibliothèque ne prend pas en charge les images multi-échantillons où certains échantillons ont un nombre de bits par échantillon différent.
  • La bibliothèque ne prend pas en charge l'accès aléatoire aux données compressées qui sont organisées avec plus d'une ligne par tuile ou bande.
