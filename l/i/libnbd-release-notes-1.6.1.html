NOM

libnbd-release-notes-1.6 - notes de publication pour libnbd 1.6

DESCRIPTION

Ce sont les notes de publication pour la version stable de libnbd 1.6. Elles décrivent les changements majeurs depuis la version 1.4.

libnbd 1.6.0 a été publiée le 7 janvier 2021.

Sécurité

Aucun problème de sécurité n'a été trouvé dans cette version.

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour en savoir plus sur les problèmes de sécurité précédents dans libnbd, consultez libnbd-security(3).

Nouvelles API

nbd_set_strict_mode(3)
nbd_get_strict_mode(3)
Cette API vous permet de contrôler la façon dont libnbd gère les requêtes du programme qu'elle pense déclencher un comportement indéfini côté serveur (comme l'envoi de commandes inconnues, de requêtes de taille nulle ou hors limites, etc.). Normalement, libnbd est très stricte et vous empêchera d'envoyer de telles requêtes, mais vous pouvez utiliser cette API pour assouplir ces restrictions, laissant au serveur le soin de les gérer ou de les rejeter. Certains serveurs peuvent planter si vous faites cela.
nbd_get_nr_meta_contexts(3)
nbd_get_meta_context(3)
nbd_clear_meta_contexts(3)
Ces API vous permettent de consulter ou d'effacer les contextes de métadonnées demandés.
nbd_opt_list_meta_context(3)
nbd_aio_opt_list_meta_context(3)
Demande au serveur de lister les contextes de métadonnées disponibles. Vous ne pouvez l'utiliser qu'en mode opt.

Remerciements : Eric Blake pour toutes les nouvelles API.

Améliorations des API existantes

nbd_shutdown(3) nouveau drapeau "LIBNBD_SHUTDOWN_ABANDON_PENDING" abandonne toutes les commandes en cours qui n'ont pas encore été envoyées au serveur (Eric Blake).

Toutes les API qui ont des paramètres de drapeau (masque de bits) définissent maintenant une constante "LIBNBD_*_MASK" vous permettant de savoir quels bits représentent des drapeaux valides à la compilation (Eric Blake).

Nouvelles fonctionnalités

Les performances de l'outil nbdcopy(1) ont été grandement améliorées. Il prend également en charge de nombreuses nouvelles fonctionnalités.

La nouvelle option --map de nbdinfo(1) affiche les extentions allouées et éparses d'un serveur NBD. Elle peut également afficher d'autres informations telles que les bitmaps sales.

Outils

nbdfuse(1) peut maintenant monter l'export NBD par-dessus n'importe quel fichier régulier, il n'est plus obligé de monter par-dessus un répertoire.

nbdsh(1) produit maintenant un message d'erreur clair si l'URI dans l'option -u ou la commande dans l'option -c est incorrecte (Eric Blake).

Nouvelle option --opt-mode de nbdsh(1) qui demande le mode opt sur le handle avant la connexion.

L'option --list de nbdinfo(1) affiche maintenant les contextes de métadonnées pris en charge par le serveur (Eric Blake).

La sortie de nbdinfo(1) est maintenant généralement imprimée de manière atomique, c'est-à-dire qu'elle imprimera soit la sortie complète, soit un message d'erreur, mais pas une sortie partielle suivie d'une erreur.

nbdinfo(1) peut maintenant décoder le métacontexte "qemu:allocation-depth" (Eric Blake).

Autres améliorations et corrections de bogues

Plusieurs améliorations dans la gestion du protocole NBD (Eric Blake).

Correction de la gestion des booléens dans les bindings Python (Eric Blake).

Correction de la gestion des paramètres de drapeaux dans les bindings OCaml (Eric Blake).

Corrections de style Python (Eric Blake).

Correction de multiples fuites de mémoire (Eric Blake).

Les bindings OCaml incluent maintenant la documentation générée par ocamldoc, si ocamldoc est installé au moment de la compilation.

La bibliothèque « vector » de nbdkit est maintenant utilisée par libnbd, simplifiant les endroits où nous utilisions auparavant realloc(3).
