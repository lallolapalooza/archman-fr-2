EVP_BYTESTOKEY(3) Manuel des fonctions de bibliothèque EVP_BYTESTOKEY(3)

NOM

EVP_BytesToKey — routine de chiffrement basée sur un mot de passe

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_BytesToKey(const EVP_CIPHER *type, const EVP_MD *md, const unsigned char *salt, const unsigned char *data, int datal, int count, unsigned char *key, unsigned char *iv);

DESCRIPTION

EVP_BytesToKey() dérive une clé et un vecteur d'initialisation (IV) à partir de divers paramètres. type est le chiffrement pour lequel la clé et l'IV sont dérivés. md est le condensat de message à utiliser. Le paramètre salt est utilisé comme sel dans la dérivation : il doit pointer vers un tampon contenant PKCS5_SALT_LEN = 8 octets ou NULL si aucun sel n'est utilisé. data est un tampon contenant datal octets qui est utilisé pour dériver les données de clé. count est le nombre d'itérations à utiliser. La clé et l'IV dérivés seront écrits respectivement dans key et iv.

Une application typique de cette fonction est de dériver des matériaux de clé pour un algorithme de chiffrement à partir d'un mot de passe dans le paramètre data.

Augmenter le paramètre count ralentit l'algorithme, ce qui rend plus difficile pour un attaquant de mener une attaque par force brute à l'aide d'un grand nombre de mots de passe candidats.

Si la longueur totale de la clé et de l'IV est inférieure à la longueur du condensat et que MD5 est utilisé, alors l'algorithme de dérivation est compatible avec PKCS#5 v1.5. Sinon, une extension non standard est utilisée pour dériver les données supplémentaires.

Les applications plus récentes devraient utiliser des algorithmes plus standard tels que PBKDF2 tel que défini dans PKCS#5v2.1 pour la dérivation de clé.

ALGORITHME DE DERIVATION DE CLÉ

La clé et l'IV sont dérivés en concaténant D_1, D_2, etc. jusqu'à ce que suffisamment de données soient disponibles pour la clé et l'IV. D_i est défini récursivement comme suit :

D_i = HASH^count(D_(i-1) || data || salt)

où || dénote la concaténation, D_0 est vide, HASH est l'algorithme de condensat utilisé, HASH^1(data) est simplement HASH(data), HASH^2(data) est HASH(HASH(data)) et ainsi de suite.

Les octets initiaux sont utilisés pour la clé et les octets suivants pour l'IV.

VALEURS DE RETOUR

Si data est NULL, EVP_BytesToKey() renvoie le nombre d'octets nécessaires pour stocker la clé dérivée. Sinon, EVP_BytesToKey() renvoie la taille de la clé dérivée en octets ou 0 en cas d'erreur.

VOIR AUSSI

evp(3), EVP_EncryptInit(3), PKCS5_PBKDF2_HMAC(3)

HISTORIQUE

EVP_BytesToKey() est apparu pour la première fois dans SSLeay 0.5.1 et est disponible depuis OpenBSD 2.4.
