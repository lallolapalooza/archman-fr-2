PKCS7_DATAINIT(3) Manuel des fonctions de bibliothèque PKCS7_DATAINIT(3)

NOM

PKCS7_dataInit — construire une chaîne de BIO pour ajouter ou récupérer du contenu

SYNTAXIS

bibliothèque « libcrypto »
#include <openssl/pkcs7.h>

BIO *
PKCS7_dataInit(PKCS7 *p7, BIO *indata);

DESCRIPTION

PKCS7_dataInit() construit une chaîne de BIO en préparation pour insérer des données dans ou récupérer des données de p7. Selon le contentType de p7, la chaîne créée commence par :

pour SignedData:
un ou plusieurs filtres de résumé de message BIO_f_md(3)
pour EnvelopedData:
un filtre de chiffrement BIO_f_cipher(3)
pour SignedAndEnvelopedData:
un ou plusieurs filtres de résumé de message BIO_f_md(3) suivis d'un filtre de chiffrement BIO_f_cipher(3)
pour DigestedData:
un filtre de résumé de message BIO_f_md(3)
pour des données arbitraires:
aucun filtre BIO

Un BIO supplémentaire est ajouté à la fin de la chaîne, en fonction de la première condition qui est remplie dans la liste suivante :

indata
si l'argument indata n'est pas NULL. Ceci n'a de sens que lors de la vérification d'une signature détachée, auquel cas indata est censé fournir le contenu associé à la signature détachée.
BIO_s_null(3)
si le contentType de p7 est SignedData et qu'il est configuré pour contenir une signature détachée. Ceci n'a de sens que lors de la création de la signature détachée.
BIO_new_mem_buf(3)
lors de la lecture d'un objet SignedData ou DigestedData. PKCS7_dataInit() attache la fin de la chaîne au contenu imbriqué de p7.
BIO_s_mem(3)
sinon. C'est le cas le plus courant lors de l'écriture de données dans p7. PKCS7_dataFinal(3) peut être utilisé plus tard pour transférer les données du BIO mémoire vers p7.

Ajout de contenu

Avant d'appeler PKCS7_dataInit() pour ajouter du contenu, PKCS7_new(3), PKCS7_set_type(3), et PKCS7_content_new(3) sont généralement requis pour créer p7, choisir son type désiré, et allouer la structure imbriquée ContentInfo. Alternativement, pour SignedData, PKCS7_sign(3) peut être utilisé avec les PKCS7_PARTIAL ou PKCS7_STREAM flags ou pour EnvelopedData, PKCS7_encrypt(3) avec le flag PKCS7_STREAM.

Après avoir appelé PKCS7_dataInit(), les données désirées peuvent être écrites dans le BIO renvoyé, BIO_flush(3) peut être appelé sur celui-ci, PKCS7_dataFinal(3) peut être utilisé pour transférer les données traitées du BIO mémoire renvoyé vers la structure p7, et la chaîne peut finalement être détruite avec BIO_free_all(3).

Bien que PKCS7_dataInit() prenne en charge les types EnvelopedData et SignedAndEnvelopedData, son utilisation pour ces types est maladroite et sujette aux erreurs, sauf lors de l'utilisation de PKCS7_encrypt(3) pour la configuration car PKCS7_content_new(3) ne prend pas en charge ces deux types. Ainsi, en plus de créer p7 lui-même et de définir son type, la structure imbriquée ContentInfo doit également être construite avec PKCS7_new(3) et PKCS7_set_type(3) et insérée manuellement dans le champ approprié de la sous-structure respective de p7.

Récupération de contenu

PKCS7_dataInit() peut également être appelé sur un objet entièrement rempli de type SignedData ou DigestedData. Après cela, BIO_read(3) peut être utilisé pour en récupérer les données. Dans ce cas d'utilisation, n'appelez pas PKCS7_dataFinal(3) ; procédez simplement directement à BIO_free_all(3) après avoir lu les données.

VALEURS DE RETOUR

PKCS7_dataInit() renvoie une chaîne de BIO en cas de succès ou NULL en cas d'échec. Il échoue si p7 est NULL, si le champ content de p7 est vide, si le contentType de p7 n'est pas pris en charge, si un chiffrement est requis mais qu'aucun n'est configuré, ou si une opération requise échoue, par exemple en raison d'un manque de mémoire ou pour diverses autres raisons.

VOIR AUSSI

BIO_new(3), BIO_read(3), PKCS7_content_new(3), PKCS7_dataFinal(3), PKCS7_encrypt(3), PKCS7_final(3), PKCS7_new(3), PKCS7_set_type(3), PKCS7_sign(3)

HISTORIQUE

PKCS7_dataInit() est apparu pour la première fois dans SSLeay 0.8.1 et est disponible depuis OpenBSD 2.4.

CAVEATS

Cette fonction ne prend pas en charge EncryptedData.

BOGUES

Si p7 est une structure entièrement remplie contenant EnvelopedData, SignedAndEnvelopedData, ou des données arbitraires, PKCS7_dataInit() renvoie une chaîne de BIO qui lit finalement à partir d'un BIO mémoire vide, donc la lecture à partir de celle-ci renverra immédiatement une indication de fin de fichier plutôt que de lire les données réelles contenues dans p7.

NAME

PKCS7_dataInit, PKCS7_data, PKCS7_data_finish - fonctions d'initialisation, de mise à jour et de finalisation de données pour PKCS#7

SYNOPSIS

#include <openssl/pkcs7.h>
                int PKCS7_dataInit(PKCS7 *p7, BIO *bio);
                int PKCS7_data(PKCS7 *p7, BIO *bio);
                int PKCS7_data_finish(PKCS7 *p7, BIO *bio);

DESCRIPTION

Ces fonctions gèrent la récupération des données à signer ou à vérifier à partir ou vers un objet PKCS#7.

PKCS7_dataInit() initialise l'objet PKCS#7 p7 pour qu'il contienne des données. Le paramètre bio est un BIO vers lequel les données seront écrites, ou à partir duquel elles seront lues.

PKCS7_data() est une fonction d'aide qui combine PKCS7_dataInit(), la lecture des données depuis bio et l'écriture dans le PKCS#7, et PKCS7_data_finish() en une seule opération.

PKCS7_data_finish() finalise l'opération de données.

RETURN VALUES

Toutes ces fonctions retournent 1 en cas de succès, et 0 ou un nombre négatif en cas d'échec.

SEE ALSO

PKCS7_sign(3), PKCS7_verify(3)

HISTORY

Ces fonctions ont été ajoutées dans OpenSSL 0.9.7.

CAVEATS

Le comportement de ces fonctions peut varier en fonction de la version d'OpenSSL.

BUGS

Aucun bug connu.
