NOM

libnbd-release-notes-1.18 - notes de publication pour libnbd 1.18

DESCRIPTION

Ce sont les notes de publication pour la version stable 1.18 de libnbd. Elles décrivent les principaux changements depuis la version 1.16.

libnbd 1.18.0 est sorti le 27 septembre 2023.

Sécurité

Eric Blake a découvert un cas où un serveur pouvait provoquer un crash de libnbd, bien que ce ne soit pas dans la configuration normale de libnbd. Pour plus d'informations, consultez l'annonce ici : https://listman.redhat.com/archives/libguestfs/2023-July/032035.html

Eric Blake a trouvé un problème avec nbd_get_size(3) où un serveur qui renvoie une taille > (uint64_t)INT64_MAX et < (uint64_t)-1 provoquait le retour d'un nombre négatif par nbd_get_size (qui n'est pas -1 et donc les appelants peuvent ou non le traiter comme une erreur). Bien qu'aucun code client dans libnbd lui-même ne soit affecté par cela, cela pourrait affecter les clients externes. libnbd ≥ 1.16.5 renvoie maintenant une erreur (-1) et définit nbd_get_errno sur "EOVERFLOW" dans ce cas. Ceci a été attribué au CVE-2023-5215 (gravité faible). Consultez l'annonce ici : https://listman.redhat.com/archives/libguestfs/2023-September/032711.html

Lors de tests de fuzzing de routine, nous avons découvert plusieurs problèmes de sécurité qui avaient été introduits pendant ce cycle de développement et qui ont été corrigés par la suite. Les versions stables (pairs) de libnbd ne devraient pas être vulnérables ; n'utilisez pas les versions de développement (impairs) en production.

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans le code source (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour en savoir plus sur les problèmes de sécurité précédents dans libnbd, consultez libnbd-security(3).

Nouvelles APIs

nbd_block_status_64(3)
nbd_aio_block_status_64(3)
Effectue une requête de statut de bloc 64 bits, voir "Protocole" ci-dessous (Eric Blake).
nbd_block_status_filter(3)
nbd_aio_block_status_filter(3)
Envoie une commande de statut de bloc filtrée, voir "Protocole" ci-dessous (Eric Blake).
nbd_can_block_status_payload(3)
Détermine si le serveur prend en charge la commande de statut de bloc filtrée (Eric Blake).
nbd_set_request_extended_headers(3)
nbd_get_request_extended_headers(3)
nbd_get_extended_headers_negotiated(3)
nbd_opt_extended_headers(3)
nbd_aio_opt_extended_headers(3)
Définit/obtient si nous demandons des en-têtes étendus du serveur, et détermine si nous avons négocié des en-têtes étendus, voir "Protocole" ci-dessous (Eric Blake).

Améliorations des APIs existantes

Les constantes de méta-contexte "qemu:" (par exemple "qemu:dirty-bitmap" comme "LIBNBD_CONTEXT_QEMU_DIRTY_BITMAP") sont maintenant disponibles via les liaisons de langage C, Golang, OCaml et Python (Eric Blake).

nbd_shutdown(3) fonctionne maintenant correctement en mode opt (Eric Blake).

nbd_set_strict_mode(3) ajoute "LIBNBD_STRICT_AUTO_FLAG" qui permet au client de tester le comportement des serveurs lorsque le drapeau de longueur de charge utile est ajusté (Eric Blake).

Protocole

libnbd prend maintenant en charge les tailles d'extension et les "en-têtes étendus" NBD 64 bits. En pratique, cela permet de mettre en œuvre beaucoup plus efficacement certaines requêtes, comme la remise à zéro de très grandes sections du disque, avec les serveurs qui le prennent en charge (Eric Blake).

libnbd prend maintenant en charge les requêtes de statut de bloc filtrées (Eric Blake).

Outils

nbdcopy(1), nbdinfo(1) et nbddump(1) ont été étendus pour utiliser et rapporter le support des en-têtes étendus / NBD 64 bits lorsque le serveur le prend en charge (Eric Blake).

nbdinfo --has peut être utilisé comme alias pour --can, par exemple "nbdinfo --has structured-reply URI" (Eric Blake).

nbdinfo rend la sortie de la taille d'export facultative, pour les serveurs qui envoient une taille excessive (Eric Blake).

nbdcopy prend maintenant en charge les "tailles lisibles" pour certains paramètres, par exemple "nbdcopy --request-size=1M ...".

Liaisons de langage

Nouvelles liaisons Rust. Il existe une API de base pour une utilisation ordinaire, et une API asynchrone implémentée avec Tokio. Rust ≥ 1.69 est requis. (Tage Johansson, soutenu par le parrainage de Google Summer of Code 2023, avec des révisions et des corrections supplémentaires par Eric Blake).

OCaml 5 est maintenant pris en charge.

Golang 1.21 est maintenant pris en charge. La version minimale est maintenant 1.17 (Eric Blake).

Utiliser "gofmt" pour formater les liaisons Golang (Eric Blake).

Utiliser "unsafe.Slice" lors de la conversion de tableaux C en tranches Golang (Eric Blake).

Toutes les liaisons de langage prennent en charge les en-têtes étendus / NBD 64 bits, et des exemples sur la façon d'utiliser cette fonctionnalité sont disponibles (Eric Blake).

Tests

Correction de quelques conditions de concurrence dans les tests où nous ne consommions pas entièrement stdin dans la méthode pwrite de nbdkit-sh-plugin(3) (Eric Blake).

Le fuzzing désactive maintenant les vérifications de strictitude côté client, permettant de fuzzer une plus large gamme d'entrées (Eric Blake).

Autres améliorations et corrections de bugs

Ajustement cohérent du code source à 80 colonnes (Laszlo Ersek).

Les messages de débogage n'affichent plus les transitions d'état très verbeuses à l'intérieur de la machine d'état, car elles ne sont généralement pas utiles. Vous pouvez les réactiver en définissant "-DLIBNBD_STATE_VERBOSE=1" au moment de la compilation.

Les méthodes de rappel de complétion ".callback" sont maintenant toujours appelées exactement une fois, et la documentation est plus claire sur le moment où cela se produit (Eric Blake).

Documentation

"podwrapper" a un nouveau paramètre --replace qui facilite l'utilisation des substitutions "AC_SUBST" dans la documentation.

Compilation

Des améliorations ont été apportées à la détection de la version de GCC et à la génération des messages d'erreur (Laszlo Ersek).
