LIBARCHIVE(3) Manuel des fonctions de bibliothèque LIBARCHIVE(3)

NOM

libarchive — fonctions pour lire et écrire des archives en flux

VUE D'ENSEMBLE

La bibliothèque libarchive fournit une interface flexible pour lire et écrire des archives dans divers formats tels que tar et cpio. libarchive prend également en charge la lecture et l'écriture d'archives compressées à l'aide de divers filtres de compression tels que gzip et bzip2. La bibliothèque est intrinsèquement orientée flux ; les lecteurs itèrent séquentiellement à travers l'archive, les écrivains ajoutent séquentiellement des éléments à l'archive. En particulier, notez qu'il n'y a actuellement aucun support intégré pour l'accès aléatoire ni pour la modification sur place.

Lors de la lecture d'une archive, la bibliothèque détecte automatiquement le format et la compression. La bibliothèque prend actuellement en charge la lecture de :

  • archives tar d'ancien style,
  • la plupart des variantes du format POSIX « ustar »,
  • le format POSIX « pax interchange »,
  • archives tar au format GNU,
  • la plupart des formats d'archives cpio courants,
  • archives 7-Zip,
  • archives ar (y compris les extensions GNU/SysV et BSD),
  • archives Microsoft CAB,
  • images CD ISO9660 (y compris les extensions RockRidge et Joliet),
  • archives LHA,
  • descriptions d'arbres de fichiers mtree,
  • archives RAR et la plupart des archives RAR5,
  • archives WARC,
  • archives XAR,
  • archives Zip.
La bibliothèque détecte automatiquement les archives compressées avec compress(1), bzip2(1), grzip(1), gzip(1), lrzip(1), lz4(1), lzip(1), lzop(1), xz(1), ou zstd(1) et les décompresse transparencement. La décompression de certains formats nécessite des utilitaires de décompression externes. Elle peut de même détecter et décoder des archives traitées avec uuencode(1) ou qui ont un en-tête rpm(1).

Lors de l'écriture d'une archive, vous pouvez spécifier la compression à utiliser et le format à utiliser. La bibliothèque peut écrire

  • archives POSIX standard « ustar »,
  • archives POSIX format d'échange « pax »,
  • archives cpio,
  • archives 7-Zip,
  • archives ar,
  • deux variantes différentes d'archives shar,
  • images CD ISO9660,
  • descriptions d'arbres de fichiers mtree,
  • archives XAR,
  • archive Zip.
Le format d'échange Pax est une extension du format d'archive tar qui élimine essentiellement toutes les limitations des formats tar historiques d'une manière standard prise en charge par les implémentations pax(1) conformes à POSIX sur de nombreux systèmes ainsi que plusieurs implémentations plus récentes de tar(1). Notez que le format d'écriture par défaut supprimera les attributs étendus pax pour la plupart des entrées ; demander explicitement le format pax activera ces attributs pour toutes les entrées.

Les API de lecture et d'écriture sont accessibles via les fonctions archive_read_XXX() et les fonctions archive_write_XXX() respectivement, et l'une ou l'autre peut être utilisée indépendamment de l'autre.

Le reste de cette page de manuel fournit une vue d'ensemble du fonctionnement de la bibliothèque. Des informations plus détaillées peuvent être trouvées dans les pages de manuel individuelles pour chaque fonction d'API ou utilitaire.

LECTURE D'UNE ARCHIVE

Voir archive_read(3).

ÉCRITURE D'UNE ARCHIVE

Voir archive_write(3).

ÉCRITURE DES ENTRÉES SUR DISQUE

L'API archive_write_disk(3) vous permet d'écrire des objets archive_entry(3) sur disque en utilisant la même API que celle utilisée par archive_write(3). L'API archive_write_disk(3) est utilisée en interne par archive_read_extract(); l'utiliser directement peut offrir un plus grand contrôle sur la manière dont les entrées sont écrites sur disque. Cette API permet également de partager du code entre les opérations de copie d'archive à archive et d'extraction d'archive sur disque.

LECTURE DES ENTRÉES DEPUIS LE DISQUE

Le support de archive_read_disk(3) permet de remplir des objets archive_entry(3) à partir des informations du système de fichiers. Cela inclut les informations accessibles via l'appel système stat(2) ainsi que les ACL, les attributs étendus et d'autres métadonnées. L'API archive_read_disk(3) prend également en charge l'itération sur les arbres de répertoires, ce qui permet de lire des répertoires de fichiers en utilisant une API compatible avec l'API archive_read(3).

DESCRIPTION

Les descriptions détaillées de chaque fonction sont fournies par les pages de manuel correspondantes.

Toutes les fonctions utilisent un type de données d'archive struct opaque qui fournit un accès au contenu de l'archive.

La structure struct archive_entry contient une description complète d'une seule entrée d'archive. Elle utilise une interface opaque entièrement documentée dans archive_entry(3).

Les utilisateurs familiers avec les formats historiques doivent être conscients que les variantes plus récentes ont éliminé la plupart des restrictions sur la longueur des champs textuels. Les clients ne doivent pas supposer que les noms de fichiers, les noms de liens, les noms d'utilisateur ou les noms de groupe sont limités en longueur. En particulier, le format d'échange pax peut facilement accueillir des noms de chemins dans des jeux de caractères arbitraires qui dépassent PATH_MAX.

VALEURS DE RETOUR

La plupart des fonctions retournent ARCHIVE_OK (zéro) en cas de succès, une valeur non nulle en cas d'erreur. La valeur de retour indique la gravité générale de l'erreur, allant de ARCHIVE_WARN, qui indique un problème mineur qui devrait probablement être signalé à l'utilisateur, à ARCHIVE_FATAL, qui indique un problème grave qui empêchera toute opération ultérieure sur cette archive. En cas d'erreur, la fonction archive_errno() peut être utilisée pour récupérer un code d'erreur numérique (voir errno(2)). La fonction archive_error_string() retourne un message d'erreur textuel approprié pour l'affichage.

archive_read_new() et archive_write_new() retournent des pointeurs vers un objet struct archive alloué et initialisé.

archive_read_data() et archive_write_data() retournent le nombre d'octets effectivement lus ou écrits. Une valeur de zéro indique la fin des données pour cette entrée. Une valeur négative indique une erreur, auquel cas les fonctions archive_errno() et archive_error_string() peuvent être utilisées pour obtenir plus d'informations.

ENVIRONNEMENT

Il existe des conversions de jeux de caractères au sein des fonctions archive_entry(3) qui sont affectées par la locale actuellement sélectionnée.

AUTHORS

BUGS

Some archive formats support information that is not supported by struct archive_entry. Such information cannot be fully archived or restored using this library. This includes, for example, comments, character sets, or the arbitrary key/value pairs that can appear in pax interchange format archives.

Conversely, of course, not all of the information that can be stored in an struct archive_entry is supported by all formats. For example, cpio formats do not support nanosecond timestamps; old tar formats do not support large device numbers.

The ISO9660 reader cannot yet read all ISO9660 images; it should learn how to seek.

The AR writer requires the client program to use two passes, unlike all other libarchive writers.
