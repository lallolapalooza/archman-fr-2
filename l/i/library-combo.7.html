NOM

library-combo - Support de GNUstep Make pour la compilation croisée.

DESCRIPTION

Cette page de manuel concerne la compilation croisée et les binaires universels (fat binaries). Les binaires universels sont des paquets que vous pouvez fournir et qui contiennent plus d'un binaire de votre programme (par exemple, votre application). Vous pouvez ainsi prendre en charge plusieurs plateformes avec un seul paquet.

Pour supporter cela, votre système doit être construit de manière non aplatie. Cela signifie que lors de l'installation de gnustep-make, vous auriez dû sélectionner --disable-flattened ainsi que les types de combinaisons de bibliothèques que vous souhaitez prendre en charge, via l'option --with-library-combo. Par combinaisons de bibliothèques, nous entendons le runtime Objective-C, la bibliothèque Foundation et la bibliothèque d'application. Pour plus de détails à ce sujet, voir la section LIBRARY-COMBO.

Si vous avez installé votre système GNUstep de manière non aplatie, tous les binaires dépendants du système sont installés dans des sous-répertoires avec des informations cpu/os/library-combo. Cela signifie par exemple que la bibliothèque gnustep-base sera installée dans Library/Libraries/ix86/linux/gnu-gnu-gnu/ si vous êtes sur un système Intel x86, exécutant Linux avec le runtime GNU pour Objective-C et que vous avez installé GNUstep.

Pour chaque combinaison de bibliothèques que vous souhaitez prendre en charge, vous devez créer l'environnement via gnustep-make, car il installe un config.make différent pour supporter ses propres indicateurs CC, OPTFLAGS, etc.

COMBO DE BIBLIOTHÈQUES

Un point important est de donner à un paquet la capacité de gérer les diverses bibliothèques et configurations disponibles actuellement :

Runtimes Objective-C
Dans le monde Objective-C, il existe trois runtimes majeurs : le runtime GNUstep, le runtime Apple et le runtime GNU. Ils diffèrent à plusieurs égards et un programme ou une bibliothèque qui fonctionne au niveau du runtime doit en être conscient.
Bibliothèques Foundation
Il existe différentes bibliothèques Foundation sur lesquelles une application ou un outil peut être écrit : gnustep-base, libFoundation et le système Cocoa d'Apple.
Interfaces graphiques
Jusqu'à présent, trois bibliothèques fournissent ou essaient de fournir des systèmes conformes à OpenStep : AppKit de NeXT, gnustep-gui et Cocoa d'Apple.

Si un programme veut fonctionner avec toutes les combinaisons possibles, il devra fournir différents binaires pour chaque combinaison, car il n'est pas possible d'avoir un outil compilé pour NeXT Foundation qui fonctionne avec gnustep-base ou vice-versa. Pour résumer, un programme peut être compilé pour ces combinaisons :

Runtime Objective-C
ng (pour GNUstep Next Generation avec API non fragile et prise en charge ARC, etc.), gnu (pour GNU, ou pour GNUstep sans les dernières fonctionnalités du langage), apple (pour Apple), nx (pour NeXT)
Bibliothèque Foundation
gnu (pour gnustep-base), fd (pour libFoundation), apple (pour Apple Cocoa), nx (pour NeXT Foundation)
Bibliothèque GUI
gnu (pour gnustep-gui), apple (pour Apple Cocoa), nx (pour NeXT GUI)

Nous désignerons le fait qu'une application a été compilée pour une certaine combinaison des valeurs ci-dessus en utilisant les abréviations des différents sous-systèmes et en plaçant des tirets entre eux. Par exemple, une application compilée pour NeXT Foundation utilisant NeXT AppKit aura l'attribut de compilation nx-nx-nx. Une application compilée pour Apple Cocoa avec le compilateur GNU pour Objective-C sera gnu-apple-apple et une autre compilée pour gnustep-base utilisant gnustep-gui sous Unix sera désignée par gnu-gnu-gnu. Voici une liste de quelques combinaisons possibles :


Runtime Foundation GUI

nx nx nx

nx fd gnu

gnu gnu gnu

ng gnu gnu

gnu fd gnu

apple apple apple

apple gnu gnu

Notez que l'on peut choisir ses propres paquets à construire ; il n'est pas obligatoire d'avoir tous les paquets installés sur le système. Ne pas les avoir tous installés limite seulement la capacité à construire et distribuer des binaires pour les combinaisons manquantes.

STRUCTURE DES RÉPERTOIRES

Pour la compilation croisée, une structure de répertoire non aplatie est recommandée, afin que vous puissiez stocker des binaires pour différentes machines dans la même structure de répertoire. La disposition standard du système de fichiers GNUstep est normalement utilisée lorsqu'une structure de répertoire non aplatie est utilisée ; ceci est obtenu avec l'option --with-layout=gnustep lors de la configuration de gnustep-make. L'installation complète de GNUstep est alors créée à l'intérieur de /usr/GNUstep (ou un autre répertoire si vous utilisez l'option --prefix=... lors de la configuration de gnustep-make). Les répertoires qui contiennent des binaires (comme le répertoire Libraries) à l'intérieur de /usr/GNUstep sont alors configurés pour supporter les binaires universels comme suit :

Libraries/

ix86/

linux-gnu/

gnu-gnu-gnu/
libgnustep-base.so
libgnustep-gui.so

gnu-fd-gnu/
libFoundation.so
libgnustep-gui.so

Pour permettre aux bonnes bibliothèques d'être trouvées, vous devez sourcer GNUstep.sh avant d'utiliser GNUstep, et vous devez lancer votre application en utilisant openapp, qui localisera le bon binaire pour votre combinaison de bibliothèques.

COMPILER POUR UNE COMBO DE BIBLIOTHÈQUES

Le paquet make permettra à l'utilisateur de choisir entre différentes combinaisons de bibliothèques. Pour spécifier une combinaison pour laquelle vous souhaitez compiler, tapez simplement :


$ make library_combo=library-combo

Par exemple, si vous souhaitez choisir de compiler en utilisant l'implémentation Foundation de GNUstep et d'utiliser la bibliothèque GNUstep GUI sur une machine GNU/Linux, vous pouvez faire ceci :


$ make library_combo=gnu-gnu-gnu

Si votre projet nécessite d'exécuter configure avant la compilation, deux points sont à garder à l'esprit. 'configure' est utilisé pour déterminer l'existence de fichiers d'en-tête particuliers et/ou de certaines fonctionnalités spécifiques dans les fichiers d'en-tête du système. Cette tâche est généralement effectuée en créant un fichier config.h qui contient quelques définitions comme HAVE_... qui indiquent si la fonctionnalité vérifiée est présente ou non.

Une autre utilisation de configure est de déterminer des bibliothèques spécifiques à lier et/ou des outils spécifiques. Un programme GNUstep typique n'est pas tenu de vérifier des bibliothèques supplémentaires, car cette étape est effectuée au moment où le paquet makefile est installé. Si le projet a toujours besoin de vérifier des bibliothèques et/ou des outils supplémentaires, la méthode recommandée est de produire un fichier config.mak qui est inclus par le GNUmakefile principal, plutôt que d'utiliser des fichiers Makefile.in modifiés par configure. La raison de ne pas faire cela est d'éviter que les makefiles contiennent des dépendances cibles comme ci-dessus, ne conservant ainsi qu'un seul makefile au lieu de plusieurs pour chaque machine cible.

Le paquet makefile est écrit pour GNU make car il fournit des fonctionnalités très puissantes qui font gagner du temps à la fois lors de l'écriture du paquet mais aussi à l'exécution, lors de la compilation d'un projet.

COMPILER POUR UNE ARCHITECTURE

Afin de compiler un projet pour plusieurs architectures, vous aurez besoin de l'environnement de développement pour la machine cible installé sur votre machine. Cela inclut un cross-compilateur avec tous les outils supplémentaires comme l'assembleur et l'éditeur de liens, les fichiers d'en-tête cibles et toutes les bibliothèques dont vous avez besoin.

Le paquet makefile de GNUstep devrait être capable de compiler et de lier une application pour une autre machine simplement en tapant


$ make target=target-triplet

où target-triplet est le nom canonique du système tel que rapporté par config.guess.

UTILISER UN LIBRARY-COMBO

Lorsque vous utilisez des library-combos, vous devez toujours sourcer GNUstep.sh. Cela vous permet de changer les chemins des bibliothèques à la volée. Si vous souhaitez passer à un autre library-combo dans votre shell, et si vous utilisez bash, il est courant de sourcer d'abord GNUstep-reset.sh pour réinitialiser toutes les variables du shell, puis de sourcer à nouveau GNUstep.sh. Supposons que nous utilisions gnu-gnu-gnu comme notre LIBRARY_COMBO actuel et que nous voulions passer à ng-gnu-gnu, alors nous utiliserions :


. /usr/GNUstep/System/Library/Makefiles/GNUstep-reset.sh

export LIBRARY_COMBO=ng-gnu-gnu

. /usr/GNUstep/System/Library/Makefiles/GNUstep.sh
