NOM

librrd - Fonctions de la bibliothèque RRD

DESCRIPTION

librrd contient la majeure partie des fonctionnalités de RRDtool. Les utilitaires en ligne de commande et les liaisons de langage sont souvent de simples enveloppes autour du code contenu dans librrd.

Cette page de manuel documente l'API de librrd.

NOTE : Ce document est en cours de développement et doit être considéré comme incomplet tant que cet avertissement persiste. Pour plus d'informations sur les fonctions de librrd, consultez toujours le code source.

FONCTIONS DE BASE

rrd_dump_cb_r(char *filename, int opt_header, rrd_output_callback_t cb, void *user)
Dans certaines situations, il est nécessaire d'obtenir la sortie de "rrd_dump" sans l'écrire dans un fichier ou sur la sortie standard. Dans de tels cas, une application peut demander à rrd_dump_cb_r d'appeler une fonction définie par l'utilisateur chaque fois qu'il y a une sortie à stocker quelque part. Ceci peut être utilisé, par exemple, pour alimenter directement un analyseur XML avec la sortie vidée ou pour transférer la chaîne résultante en mémoire.

Les arguments de rrd_dump_cb_r sont les mêmes que ceux de rrd_dump_opt_r, à l'exception que le paramètre du nom de fichier de sortie est remplacé par la fonction de rappel définie par l'utilisateur et un paramètre supplémentaire pour la fonction de rappel qui est passé inchangé, c'est-à-dire pour stocker les informations sur l'état du rappel nécessaires au bon fonctionnement de la fonction de rappel définie par l'utilisateur.

Les versions récentes de rrd_dump_opt_r utilisent en interne ce mécanisme de rappel pour écrire leur sortie dans le fichier fourni par l'utilisateur.

size_t rrd_dump_opt_cb_fileout(
    const void *data,
    size_t len,
    void *user)
{
    return fwrite(data, 1, len, (FILE *)user);
}

L'appel associé pour rrd_dump_cb_r ressemble à

res = rrd_dump_cb_r(filename, opt_header,
    rrd_dump_opt_cb_fileout, (void *)out_file);

où le dernier paramètre spécifie le descripteur de fichier sur lequel rrd_dump_opt_cb_fileout doit écrire. Il n'y a pas de condition spécifique pour que le rappel détecte quand il est appelé pour la première fois, ni pour la dernière fois. Si vous en avez besoin pour l'initialisation et le nettoyage, vous devriez effectuer ces tâches avant et après l'appel à rrd_dump_cb_r respectivement.

rrd_fetch_cb_register(rrd_fetch_cb_t c)
Si vos données ne résident pas dans des fichiers rrd, mais que vous souhaitez dessiner des graphiques en utilisant la fonctionnalité rrd_graph, vous pouvez fournir votre propre fonction rrd_fetch et l'enregistrer en utilisant la fonction rrd_fetch_cb_register.

La signature des arguments et l'API doivent être identiques à celles de la fonction de rappel et doivent être équivalentes à celles de rrd_fetch_fn dans rrd_fetch.c.

Pour activer la fonction de rappel, vous pouvez utiliser le nom de fichier pseudo cb//texte_libre.

Notez que le graphique rrdtool ne demandera pas les données du même rrd deux fois. Il détermine cela en construisant une clé à partir des valeurs fournies à la fonction de récupération. Si les valeurs sont identiques, la réponse précédente sera utilisée.

FONCTIONS UTILITAIRES

rrd_random()
Génère des nombres aléatoires tout comme random(). Ceci garantit en outre que le générateur de nombres aléatoires est initialisé une seule fois par processus.
rrd_strtodbl
un convertisseur chaîne vers double conscient de rrd qui définit rrd_error en cas de problème et utilise le code de retour exclusivement pour signaler le statut de la conversion.
rrd_strtod
fonctionne comme le strtod normal, mais il est indépendant de la locale (et thread-safe)
rrd_snprintf
fonctionne comme le snprintf normal, mais il est indépendant de la locale (et thread-safe)
rrd_add_ptr(void ***dest, size_t *dest_size, void *src)
Redimensionne dynamiquement le tableau pointé par "dest". "dest_size" est un pointeur vers la taille actuelle de "dest". Après un realloc() réussi, "dest_size" est incrémenté de 1 et le pointeur "src" est stocké à la fin du nouveau "dest". Retourne 1 en cas de succès, 0 en cas d'échec. 
type **arr = NULL;
type *elem = "whatever";
size_t arr_size = 0;
if (!rrd_add_ptr(&arr, &arr_size, elem))
    handle_failure();
rrd_add_ptr_chunk(void ***dest, size_t *dest_size, void *src, size_t *alloc, size_t chunk)
Comme "rrd_add_ptr", sauf que la destination est allouée par blocs de "chunk". "alloc" pointe vers le nombre d'entrées allouées, tandis que "dest_size" pointe vers le nombre de pointeurs valides. Si plus de pointeurs sont nécessaires, "chunk" pointeurs sont alloués et "alloc" est augmenté en conséquence. "alloc" doit être >= "dest_size".

Cette méthode améliore les performances sur les hôtes où "realloc()" est coûteux.

rrd_add_strdup(char ***dest, size_t *dest_size, char *src)
Comme "rrd_add_ptr", sauf qu'il ajoute une copie de la chaîne source effectuée avec "strdup". 
char **arr = NULL;
size_t arr_size = NULL;
char *str  = "example text";
if (!rrd_add_strdup(&arr, &arr_size, str))
    handle_failure();
rrd_add_strdup_chunk(char ***dest, size_t *dest_size, char *src, size_t *alloc, size_t chunk)
Comme "rrd_add_strdup", sauf que la destination est allouée par blocs de "chunk". "alloc" pointe vers le nombre d'entrées allouées, tandis que "dest_size" pointe vers le nombre de pointeurs valides. Si plus de pointeurs sont nécessaires, "chunk" pointeurs sont alloués et "alloc" est augmenté en conséquence. "alloc" doit être >= "dest_size".
rrd_free_ptrs(void ***src, size_t *cnt)
Libère un tableau de pointeurs alloués par "rrd_add_ptr" ou "rrd_add_strdup". Libère également le pointeur du tableau lui-même. Au retour, le pointeur source sera NULL et le compteur sera zéro. 
/* créé comme ci-dessus */
rrd_free_ptrs(&arr, &arr_size);
/* ici, arr == NULL && arr_size == 0 */
rrd_mkdir_p(const char *pathname, mode_t mode)
Crée le répertoire nommé "pathname" en incluant tous ses répertoires parents (similaire à "mkdir -p" en ligne de commande - voir mkdir(1) pour plus d'informations). L'argument "mode" spécifie les permissions à utiliser. Il est modifié par l'"umask" du processus. Voir mkdir(2) pour plus de détails.

La fonction retourne 0 en cas de succès, une valeur négative sinon. En cas d'erreur, "errno" est réglé en conséquence. Outre les erreurs documentées dans mkdir(2), la fonction peut échouer avec les erreurs suivantes :

EINVAL
"pathname" est "NULL" ou la chaîne vide.
ENOMEM
Mémoire insuffisante disponible.
toute erreur renvoyée par stat(2)

Contrairement à mkdir(2), la fonction ne renvoie pas d'erreur si "pathname" existe déjà et est un répertoire.

rrd_scaled_duration (const char * token, unsigned long divisor, unsigned long * valuep)
Analyse un jeton dans un contexte où il contient un nombre (de secondes ou d'instances PDP), ou une durée qui peut être convertie en nombre en représentant la durée en secondes et en la divisant par un facteur d'échelle. Par exemple, si un utilisateur exprimerait nativement une archive de 3 jours d'échantillons collectés toutes les 2 minutes, l'intervalle d'échantillon peut être représenté par "2m" au lieu de 120, et la durée de l'archive par "3d" (à diviser par 120) au lieu de 2160 (3*24*60*60 / 120). Voir plus d'exemples dans "STEP, HEARTBEAT, et Rows As Durations" dans rrdcreate.

"token" doit être un nombre avec un suffixe optionnel d'un seul caractère codant le facteur d'échelle :

"s"
indique les secondes
"m"
indique les minutes. La valeur est multipliée par 60.
"h"
indique les heures. La valeur est multipliée par 3600 (ou "60m").
"d"
indique les jours. La valeur est multipliée par 86400 (ou "24h").
"w"
indique les semaines. La valeur est multipliée par 604800 (ou "7d").
"M"
indique les mois. La valeur est multipliée par 2678400 (ou "31d"). (Notez que ce facteur prend en compte le nombre maximum de jours dans un mois.)
"y"
indique les années. La valeur est multipliée par 31622400 (ou "366d"). (Notez que ce facteur prend en compte les années bissextiles.)

"divisor" est une valeur positive représentant la durée en secondes d'un intervalle dont le résultat souhaité compte les instances.

"valuep" est un pointeur vers l'emplacement où la valeur décodée sera stockée si la conversion réussit.

Les premiers caractères de "token" doivent être la représentation en base 10 d'un entier positif, sinon la conversion échoue.

Si le reste de "token" est vide (pas de suffixe), il s'agit d'un nombre et aucune mise à l'échelle n'est effectuée.

Si "token" a l'un des suffixes ci-dessus, le nombre est multiplié pour le convertir en une durée en secondes. Le nombre de secondes résultant est divisé par "divisor" pour produire un nombre d'intervalles chacun d'une durée de "divisor" secondes. Si la division produirait un reste (par exemple, "5m" (300 secondes) divisé par "90s"), la conversion est invalide.

Si "token" a des caractères finaux non reconnus, la conversion échoue.

La fonction renvoie un pointeur nul si la conversion a réussi et que "valuep" a été mis à jour avec la valeur mise à l'échelle. En cas d'échec, elle renvoie un diagnostic textuel utilisable dans les messages d'erreur utilisateur.

FONCTIONS CLIENT

Les fonctions suivantes sont utilisées pour se connecter à une instance rrdcached, soit via une adresse Unix soit via une adresse inet, et pour créer, mettre à jour ou collecter des statistiques sur un fichier de base de données RRD spécifié.

Il existe deux interfaces différentes : La famille de fonctions rrd_client_ opère sur un objet client fourni par l'utilisateur (rrd_client_t) et prend en charge plusieurs connexions simultanées aux instances rrdcache. La famille plus simple de fonctions rrdc_ gère les connexions de manière transparente mais ne peut être utilisée que pour une seule connexion à la fois.

Toutes les fonctions et types de données suivants sont spécifiés dans le fichier d'en-tête "rrd_client.h".

rrd_client_new(const char *daemon_addr)
Crée un nouvel objet de connexion client. Si spécifié, se connecte au démon à l'adresse "daemon_addr". La connexion peut être modifiée ultérieurement en appelant rrd_client_connect.
rrd_client_destroy(rrd_client_t *client)
Ferme une connexion client et détruit l'objet en libérant toute la mémoire allouée dynamiquement. Après avoir appelé cette fonction, "client" ne peut plus être utilisé.
rrd_client_connect(rrd_client_t *client, const char *daemon_addr)
rrdc_connect(const char *daemon_addr)
Se connecte à une instance rrdcached en cours d'exécution, spécifiée via "daemon_addr". Toute connexion précédente sera fermée. Si "daemon_addr" est "NULL", elle utilise par défaut la valeur de l'adresse de l'environnement "ENV_RRDCACHED_ADDRESS".
rrd_client_is_connected(rrd_client_t *client)
Renvoie un entier booléen si le client est connecté au serveur.
rrd_client_address(rrd_client_t *client)
Renvoie l'adresse du serveur appartenant à la connexion actuelle.
rrdc_is_connected(const char *daemon_addr)
Renvoie un entier booléen pour déterminer si le client est connecté au démon rrdcache spécifié par le paramètre "daemon_addr".
rrd_client_ping(rrd_client_t *client)
rrdc_ping
Vérifie la connexion client en pingant le côté distant.
rrdc_is_any_connected
Renvoie un entier booléen si des connexions de démon sont actives.
rrd_client_disconnect(rrd_client_t *client)
rrdc_disconnect
Se déconnecte gracieusement de la connexion de démon actuelle.
rrd_client_update(rrd_client_t *client, const char *filename, int values_num, const char * const *values)
rrdc_update(const char *filename, int values_num, const char * const *values)
Met à jour le RRD "filename" via rrdcached. Où "values_num" est le nombre de valeurs à mettre à jour et "values" sont les nouvelles valeurs à ajouter.
rrd_client_info(rrd_client_t *client, const char *filename)
rrdc_info(const char *filename)
Récupère les informations rrd du RRD "filename" auprès du démon de cache connecté. Cette fonction renvoie une structure rrd_info_t de la forme suivante : 
typedef struct rrd_blob_t {
    unsigned long size; /* taille du blob */
    unsigned char *ptr; /* pointeur */
} rrd_blob_t;
typedef enum rrd_info_type { RD_I_VAL = 0,
    RD_I_CNT,
    RD_I_STR,
    RD_I_INT,
    RD_I_BLO
} rrd_info_type_t;
typedef union rrd_infoval {
    unsigned long u_cnt;
    rrd_value_t u_val;
    char     *u_str;
    int       u_int;
    rrd_blob_t u_blo;
} rrd_infoval_t;
typedef struct rrd_info_t {
    char     *key;
    rrd_info_type_t type;
    rrd_infoval_t value;
    struct rrd_info_t *next;
} rrd_info_t;
rrd_client_last(rrd_client_t *client, const char *filename)
rrdc_last(const char *filename)
Récupère l'époque Unix du dernier moment où le RRD "filename" a été mis à jour.
rrd_client_first(rrd_client_t *client, const char *filename, int rraindex)
rrdc_first(const char *filename, int rraindex)
Obtient la première valeur du premier échantillon du RRD "filename", de l'archive Round Robin (RRA) d'index "rraindex". L'index RRA peut être déterminé en extrayant le rrd_info_t du RRD.
rrd_client_create(rrd_client_t *client, const char *filename, unsigned long pdp_step, time_t last_up, int no_overwrite, int argc, const char **argv)
rrdc_create(const char *filename, unsigned long pdp_step, time_t last_up, int no_overwrite, int argc, const char **argv)
Crée une base de données RRD de chemin "filename". Le RRD aura une taille de pas (step) de "pfp_step", l'horodatage Unix epoch à partir duquel commencer à collecter les données. Le nombre de sources de données et de R
RAs "argc" et les définitions des sources de données et des RRA "argv". Enfin, s'il faut ou non écraser une RRD existante si une est trouvée avec le même nom de fichier ; "no_overwrite".
rrdc_create_r2(rrd_client_t *client, const char *filename, unsigned long pdp_step, time_t last_up, int no_overwrite, const char **sources, const char *template, int argc, const char **argv)
rrdc_create_r2(const char *filename, unsigned long pdp_step, time_t last_up, int no_overwrite, const char **sources, const char *template, int argc, const char **argv)
Crée une base de données RRD dans le démon. rrdc_create_r2 a les mêmes paramètres que rrdc_create avec deux paramètres ajoutés : "sources" et "template".

où "template" est le chemin d'accès à un fichier modèle RRD, avec le format défini dans rrdcreate(1),

Le paramètre "sources" définit des séries de chemins de fichiers avec des données définies, pour préremplir la RRD. Voir rrdcreate(1) pour plus de détails.

rrd_client_flush(rrd_client_t *client, const char *filename)
rrdc_flush(const char *filename)
Vide la RRD actuellement mise en cache dans le démon spécifié par "filename".
rrd_client_forget(rrd_client_t *client, const char *filename)
rrdc_forget(const char *filename)
Supprime les données mises en cache pour le fichier RRD spécifié par "filename".
rrdc_flush_if_daemon(const char *daemon_addr, const char *filename)
Vide la RRD spécifiée donnée par "filename" uniquement si le démon "daemon_addr" est en ligne et connecté.
rrd_client_fetch(rrd_client_t *client, const char *filename, const char *cf, time_t *ret_start, time_t *ret_end, unsigned long *ret_step, unsigned long *ret_ds_num, char ***ret_ds_names, rrd_value_t **ret_data)
rrdc_fetch(const char *filename, const char *cf, time_t *ret_start, time_t *ret_end, unsigned long *ret_step, unsigned long *ret_ds_num, char ***ret_ds_names, rrd_value_t **ret_data)
Effectue une opération de récupération sur la base de données RRD spécifiée par "filename", où "cf" est la fonction de consolidation, "ret_start" est l'heure de début donnée par l'époque Unix, "ret_end" est l'heure de fin. "ret_step" est la taille du pas en secondes, "ret_ds_num" le nombre de sources de données dans la RRD, "ret_ds_names" les noms des sources de données, et un pointeur vers un objet rrd_value_t pour transférer les données.
rrdc_stats_get(rrd_client_t *client, rrdc_stats_t **ret_stats)
rrdc_stats_get(rrdc_stats_t **ret_stats)
Obtient les statistiques du démon connecté, via une liste chaînée de la structure suivante : 
struct rrdc_stats_s {
    const char *name;
    uint16_t type;
    #define RRDC_STATS_TYPE_GAUGE   0x0001
    #define RRDC_STATS_TYPE_COUNTER 0x0002
    uint16_t flags;
    union {
        uint64_t counter;
        double   gauge;
    } value;
    struct rrdc_stats_s *next;
};
typedef struct rrdc_stats_s rrdc_stats_t;
rrdc_stats_free(rrdc_stats_t *ret_stats)
Libère la structure de statistiques allouée via rrdc_stats_get.
