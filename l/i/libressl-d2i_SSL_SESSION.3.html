D2I_SSL_SESSION(3) Manuel des fonctions de bibliothèque D2I_SSL_SESSION(3)

NOM

d2i_SSL_SESSION, i2d_SSL_SESSION — conversion de l'objet SSL_SESSION depuis/vers la représentation ASN1

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

SSL_SESSION *
d2i_SSL_SESSION(SSL_SESSION **a, const unsigned char **pp, long length);

int
i2d_SSL_SESSION(SSL_SESSION *in, unsigned char **pp);

DESCRIPTION

d2i_SSL_SESSION() transforme la représentation ASN1 externe d'une session SSL/TLS, stockée sous forme de données binaires à l'emplacement pp avec la longueur length, en un objet SSL_SESSION.

i2d_SSL_SESSION() transforme l'objet SSL_SESSION in en représentation ASN1 et la stocke à l'emplacement mémoire pointé par pp. La longueur de la représentation ASN1 résultante est retournée. Si pp est le pointeur NULL, seule la longueur est calculée et retournée.

L'objet SSL_SESSION est construit à partir de plusieurs parties allouées avec malloc(3) ; il ne peut donc pas être déplacé, copié ou stocké directement. Afin de stocker les données de session sur disque ou dans une base de données, elles doivent être transformées en une représentation ASN1 binaire.

Lors de l'utilisation de d2i_SSL_SESSION(), l'objet SSL_SESSION est automatiquement alloué. Le compteur de références est à 1, donc la session doit être explicitement libérée à l'aide de SSL_SESSION_free(3), à moins que l'objet SSL_SESSION ne soit complètement repris lors de son appel dans le cadre de get_session_cb(), voir SSL_CTX_sess_set_get_cb(3).

SSL_SESSION les objets conservent des informations de lien internes sur la liste du cache de session lors de leur insertion dans le cache de session d'un objet SSL_CTX. Un objet SSL_SESSION, indépendamment de son compteur de références, ne doit donc être utilisé qu'avec un seul objet SSL_CTX (et les objets SSL créés à partir de cet objet SSL_CTX).

Lors de l'utilisation de i2d_SSL_SESSION(), l'emplacement mémoire pointé par pp doit être suffisamment grand pour contenir la représentation binaire de la session. Il n'y a pas de limite connue à la taille de la représentation ASN1 créée, donc appelez i2d_SSL_SESSION() d'abord avec pp=NULL pour obtenir la taille encodée, avant d'allouer la quantité de mémoire requise et d'appeler i2d_SSL_SESSION() à nouveau. Notez que cela avancera la valeur contenue dans *pp, il est donc nécessaire de sauvegarder une copie de l'allocation d'origine. Par exemple :

char	*p, *pp;
int	 elen, len;

elen = i2d_SSL_SESSION(sess, NULL);
p = pp = malloc(elen);
if (p != NULL) {
	len = i2d_SSL_SESSION(sess, &pp);
	assert(elen == len);
	assert(p + len == pp);
}

VALEURS DE RETOUR

d2i_SSL_SESSION() retourne un pointeur vers le nouvel objet SSL_SESSION alloué. En cas d'échec, un pointeur NULL est retourné et le message d'erreur peut être récupéré de la pile d'erreurs.

i2d_SSL_SESSION() retourne la taille de la représentation ASN1 en octets. Lorsque la session n'est pas valide, 0 est retourné et aucune opération n'est effectuée.

VOIR AUSSI

d2i_X509(3), ssl(3), SSL_CTX_sess_set_get_cb(3), SSL_SESSION_free(3)

HISTORIQUE

d2i_SSL_SESSION() et i2d_SSL_SESSION() sont apparues pour la première fois dans SSLeay 0.5.2 et sont disponibles depuis OpenBSD 2.4.
