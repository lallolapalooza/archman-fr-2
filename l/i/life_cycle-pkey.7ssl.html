NOM

life_cycle-pkey - Le cycle de vie de l'algorithme PKEY

DESCRIPTION

Toutes les clés publiques (PKEY) passent par un certain nombre d'états dans leur cycle de vie :

start
Cet état représente la PKEY avant qu'elle n'ait été allouée. C'est l'état de départ pour toute transition de cycle de vie.
newed
Cet état représente la PKEY après qu'elle ait été allouée.
decapsulate
Cet état représente la PKEY lorsqu'elle est prête à effectuer une opération de décapsulation de clé privée.
decrypt
Cet état représente la PKEY lorsqu'elle est prête à déchiffrer un quelconque chiffré.
derive
Cet état représente la PKEY lorsqu'elle est prête à dériver un secret partagé.
signature de hachage
Cet état représente la PKEY lorsqu'elle est prête à effectuer une opération de signature de clé privée.
encapsulate
Cet état représente la PKEY lorsqu'elle est prête à effectuer une opération d'encapsulation de clé publique.
encrypt
Cet état représente la PKEY lorsqu'elle est prête à chiffrer un quelconque texte en clair.
génération de clé
Cet état représente la PKEY lorsqu'elle est prête à générer une nouvelle clé publique/privée.
génération de paramètres
Cet état représente la PKEY lorsqu'elle est prête à générer les paramètres de clé.
verify
Cet état représente la PKEY lorsqu'elle est prête à vérifier une signature de clé publique.
récupération de vérification
Cet état représente la PKEY lorsqu'elle est prête à récupérer les données de signature d'une clé publique.
freed
Cet état est atteint lorsque la PKEY est libérée. C'est l'état terminal pour toutes les transitions de cycle de vie.

NAME

life_cycle-pkey - PKEY cycle and status

DESCRIPTION

The PKEY context provides a way to handle public and private keys in a uniform manner. This document describes the intended lifecycle and status transitions of a PKEY context.

The lifecycle of a PKEY context is primarily governed by the context's state, which can be one of the following:

UNINITIALISED

This is the initial state of a PKEY context. In this state, the context is aware of its operation (e.g. encrypt, decrypt, sign, verify, derive, encapsulate, decapsulate) but no key is associated with it yet. The context can be initialised with a key or with a key generation operation.

INITIALISED

In this state, the context is ready for an operation. The context is initialised with a key, or a key generation operation has been started.

The context may be used for operations like encryption, decryption, signing, verification, derivation, encapsulation or decapsulation. It may also be used for key generation.

It is also possible to set or get parameters and to copy the context.

SIGNATURE_GENERATED

This state is only applicable for signing operations. It is reached after a signature has been generated.

VERIFY_RECOVERED

This state is only applicable for verification recovery operations. It is reached after a message has been recovered and verified.

DERIVED_KEY_GENERATED

This state is only applicable for key derivation operations. It is reached after a shared secret has been derived.

ENCAPSULATED_DATA_GENERATED

This state is only applicable for key encapsulation operations. It is reached after a public key has been encapsulated into a shared secret and ciphertext.

DECAPSULATED_DATA_GENERATED

This state is only applicable for key decapsulation operations. It is reached after a ciphertext has been decapsulated into a shared secret.

ENCRYPTED_DATA_GENERATED

This state is only applicable for encryption operations. It is reached after data has been encrypted.

DECRYPTED_DATA_GENERATED

This state is only applicable for decryption operations. It is reached after data has been decrypted.

FINALIZED

In this state, the context has completed its intended operation and its associated resources have been freed. A context in this state cannot be reused. It must be freed using EVP_PKEY_CTX_free().

               +-- DECAPSULATED_DATA_GENERATED --> FINALIZED
