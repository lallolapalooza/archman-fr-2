NOM

libnbd-release-notes-1.10 - notes de publication pour libnbd 1.10

DESCRIPTION

Ce sont les notes de publication pour la version stable 1.10 de libnbd. Elles décrivent les changements majeurs depuis la version 1.8.

libnbd 1.10.0 a été publié le 23 septembre 2021.

Sécurité

Aucun bogue de sécurité n'a été découvert dans libnbd pendant ce cycle de publication.

Si vous trouvez un problème de sécurité, veuillez lire le fichier SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour connaître les problèmes de sécurité précédents dans libnbd, consultez libnbd-security(3).

Nouvelles APIs

Aucune nouvelle API n'a été ajoutée dans la version 1.10.

Améliorations des APIs existantes

nbd_get_uri(3) ne retourne plus les noms de service (par ex. "nbd://localhost:nbd"). Au lieu de cela, elle retourne toujours les numéros de port bruts pour des raisons de portabilité.

nbd_connect_uri(3) prend désormais en charge le paramètre de requête "tls-certificates=DIR", ce qui facilite grandement la connexion à des serveurs utilisant TLS avec des certificats X.509. Les messages d'erreur de cette API ont également été améliorés dans le cas de certaines erreurs courantes de l'utilisateur d'URI.

La fonction Python "nbd.aio_connect" implémente la prise en charge des sockets "AF_UNIX".

Correction d'une utilisation invalide de "unsafe.Pointer" dans les bindings Go.

Outils

nbdcopy(1) utilise maintenant une taille de requête par défaut de 256 Ko (au lieu de 32 Mo). Ce défaut offre de meilleures performances dans la plupart des cas.

nbdinfo(1) dispose d'un nouveau mode --map --totals qui affiche un résumé de la carte. De nouvelles options --can et --is vous permettent également de tester les propriétés d'exportation (par ex. --is read-only).

nbdinfo(1) --map utilise « data » au lieu de « allocated » en raison de l'ambiguïté sur ce que signifie « allocated » (Eric Blake, Nir Soffer).

nbdinfo(1) affiche la taille de l'exportation en octets et en unités humaines (comme "1K"). La sortie JSON lisible par machine n'a pas changé.

nbdfuse(1) prend désormais en charge la mise à zéro efficace. Notez que cela nécessite le noyau Linux ≥ 5.14.

nbdsh(1) a une nouvelle option -n qui évite de créer le handle implicite "h". Il y a aussi une nouvelle option -v qui active le débogage. De plus, la bannière d'aide initiale est maintenant sensible au contexte, fournissant des informations plus pertinentes en fonction de la manière dont nbdsh a été invoqué.

Tests

Les tests CI ont été considérablement améliorés et de nombreux correctifs spécifiques à la plateforme ont été apportés. Pour voir les derniers tests et résultats CI, consultez : https://gitlab.com/nbdkit/libnbd/-/pipelines (Martin Kletzander).

Les tests utilisent maintenant la nouvelle fonctionnalité "GLIBC_TUNABLES", remplaçant "MALLOC_CHECK_" sur glibc ≥ 2.34 (merci à Eric Blake, Siddhesh Poyarekar).

Autres améliorations et corrections de bogues

La barre de progression de nbdcopy(1) devrait s'afficher plus précisément en mode multithread.

Documentation

La documentation de "nbd_connect*" et "nbd_aio_connect*" a été révisée et améliorée.

Un style d'options plus cohérent est utilisé dans toute la documentation.

podwrapper.pl a été unifié (presque) avec la copie dans nbdkit.

Compilation

configure.ac utilise maintenant les espaces de manière cohérente et a été modernisé pour prendre en charge les derniers autotools (Eric Blake).

Nous avertissons maintenant des cadres de pile volumineux, et quelques endroits qui utilisaient des cadres de pile volumineux ont été corrigés.

Fuzzing continué en utilisant AFL++. Documentation du fuzzing mise à jour.

Correction de la compilation depuis git avec --disable-ocaml. Tant que seul "ocamlc" est installé, le générateur devrait toujours être compilé et exécuté (Martin Kletzander).
