DESCRIPTION

BIO_s_accept() retourne la méthode BIO d'acceptation. Il s'agit d'un wrapper autour des routines accept(2) de socket TCP/IP de la plateforme.

En utilisant les BIOs d'acceptation, les connexions TCP/IP peuvent être acceptées et les données transférées en utilisant uniquement des routines BIO. De cette façon, toutes les opérations spécifiques à la plateforme sont masquées par l'abstraction BIO.

Les opérations de lecture et d'écriture sur un BIO d'acceptation effectueront des E/S sur la connexion sous-jacente. Si aucune connexion n'est établie et que le port (voir ci-dessous) est correctement configuré, le BIO attend une connexion entrante.

Les BIOs d'acceptation prennent en charge BIO_puts(3) mais pas BIO_gets(3).

Si l'indicateur de fermeture est défini sur un BIO d'acceptation, toute connexion active sur cette chaîne sera fermée et le socket sera fermé lorsque le BIO sera libéré.

Appeler BIO_reset(3) sur un BIO d'acceptation fermera toute connexion active et réinitialisera le BIO dans un état où il attend une autre connexion entrante.

BIO_get_fd(3) et BIO_set_fd(3) peuvent être appelés pour récupérer ou définir le socket d'acceptation. Voir BIO_s_fd(3).

BIO_set_accept_port() utilise la chaîne name pour définir le port d'acceptation. Le port est représenté par une chaîne de la forme hôte:port, où hôte est l'interface à utiliser et port est le port. L'hôte peut être "*", ce qui est interprété comme toute interface ; port a la même syntaxe que le port spécifié dans BIO_set_conn_port(3) pour les BIOs de connexion. Il peut s'agir d'une chaîne de port numérique ou d'une chaîne à rechercher à l'aide de getservbyname(3) et d'une table de services.

BIO_new_accept() combine BIO_new(3) et BIO_set_accept_port() en un seul appel. Il crée un nouveau BIO d'acceptation avec le port host_port.

BIO_set_nbio_accept() définit le socket d'acceptation en mode bloquant (par défaut) si n est 0 ou en mode non bloquant si n est 1.

BIO_set_accept_bios() peut être utilisé pour définir une chaîne de BIOs qui sera dupliquée et ajoutée en préfixe de la chaîne lorsqu'une connexion entrante est reçue. Ceci est utile si, par exemple, un BIO de mise en mémoire tampon ou SSL est requis pour chaque connexion. La chaîne de BIOs ne doit pas être libérée après cet appel - elle sera automatiquement libérée lorsque le BIO d'acceptation sera libéré.

BIO_set_bind_mode() et BIO_get_bind_mode() définissent et récupèrent le mode de liaison actuel. Si BIO_BIND_NORMAL (par défaut) est défini, alors un autre socket ne peut pas être lié au même port. Si BIO_BIND_REUSEADDR est défini, alors d'autres sockets peuvent être liés au même port. Si BIO_BIND_REUSEADDR_IF_UNUSED est défini, alors une tentative est d'abord faite pour utiliser BIO_BIN_NORMAL ; si cela échoue et que le port n'est pas utilisé, alors une seconde tentative est faite en utilisant BIO_BIND_REUSEADDR.

BIO_do_accept() sert deux objectifs. Lorsqu'il est appelé pour la première fois, après que le BIO d'acceptation a été configuré, il tentera de créer le socket d'acceptation et d'y lier une adresse. Les appels suivants à BIO_do_accept() attendront une connexion entrante, ou demanderont une nouvelle tentative en mode non bloquant.

NOTES

Lorsqu'un BIO d'acceptation se trouve à la fin d'une chaîne, il attendra une connexion entrante avant de traiter les appels d'E/S. Lorsqu'un BIO d'acceptation n'est pas à la fin d'une chaîne, il transmet les appels d'E/S au BIO suivant dans la chaîne.

Lorsqu'une connexion est établie, un nouveau BIO de socket est créé pour la connexion et ajouté à la chaîne. C'est-à-dire que la chaîne est maintenant acceptation->socket. Cela signifie effectivement que les tentatives d'E/S sur un socket d'acceptation initial attendront une connexion entrante puis effectueront des E/S dessus.

Si des BIOs supplémentaires ont été définis à l'aide de BIO_set_accept_bios(), alors ils sont placés entre le socket et le BIO d'acceptation ; c'est-à-dire que la chaîne sera acceptation->autresbios->socket.

Si un serveur souhaite traiter plusieurs connexions (comme c'est normalement le cas), alors le BIO d'acceptation doit être rendu disponible pour les connexions entrantes supplémentaires. Cela peut être fait en attendant une connexion, puis en appelant :

connection = BIO_pop(accept);

Après cet appel, connection contiendra un BIO pour la connexion récemment établie et accept sera à nouveau un seul BIO qui pourra être utilisé pour attendre d'autres connexions entrantes. Si aucune connexion supplémentaire ne sera acceptée, accept peut être libéré à l'aide de BIO_free(3).

Si une seule connexion sera traitée, il est possible d'effectuer des E/S en utilisant le BIO d'acceptation lui-même. Ceci est souvent indésirable car le BIO d'acceptation continuera d'accepter des connexions entrantes supplémentaires. Cela peut être résolu en utilisant BIO_pop(3) (voir ci-dessus) et en libérant le BIO d'acceptation après la connexion initiale.

BIO_s_accept(3) — LibreSSL manual

NAME

BIO_s_accept, BIO_new_accept, BIO_do_accept, BIO_set_accept_port, BIO_get_accept_port, BIO_set_nbio_accept, BIO_set_accept_bios, BIO_set_bind_mode, BIO_get_bind_mode - accept BIO

SYNOPSIS

#include <openssl/bio.h>

BIO_METHOD *BIO_s_accept(void);
BIO *BIO_new_accept(const char *port);
int BIO_do_accept(BIO *bio);
int BIO_set_accept_port(BIO *bio, const char *port);
int BIO_get_accept_port(BIO *bio, char *port);
int BIO_set_nbio_accept(BIO *bio, int nbio);
int BIO_set_accept_bios(BIO *bio, BIO *accept_bio);
int BIO_set_bind_mode(BIO *bio, BIO_ADDRINFO *addrinfo);
BIO_ADDRINFO *BIO_get_bind_mode(BIO *bio);

DESCRIPTION

The accept BIO is a wrapper for the accept() system call. It is a server-side BIO which listens on a port and accepts incoming connections. When a connection is accepted, it returns a new BIO representing the connection.

The BIO_new_accept() function creates a new accept BIO listening on the specified port. If port is NULL, then the default port is used. The port string can be a port number or a service name.

The BIO_do_accept() function is used to initiate the accept operation. It should be called once before any calls to BIO_read() or BIO_write() on the accept BIO.

The BIO_set_accept_port() function sets the port to listen on. This function may be called before or after BIO_do_accept().

The BIO_get_accept_port() function retrieves the port the BIO is listening on.

The BIO_set_nbio_accept() function sets the BIO to non-blocking mode if nbio is 1, and to blocking mode if nbio is 0. Non-blocking mode is the default.

The BIO_set_accept_bios() function can be used to pre-create a BIO that will be used for the accepted connection. This is useful for setting up specific BIO chains, e.g. for SSL connections.

The BIO_set_bind_mode() function sets the binding mode for the accept BIO. The addrinfo argument specifies how the BIO should bind to the network address. This can be used to control whether the socket is bound to a specific interface or to all interfaces.

The BIO_get_bind_mode() function retrieves the current binding mode.

NOTES

The accept BIO can be used in both blocking and non-blocking modes. In non-blocking mode, if no connection is pending, a call to BIO_do_accept() will return 0. The application should then wait for the underlying socket to become readable before retrying the call.

If BIO_do_accept() returns -1, it indicates an error. The specific error can be determined by calling BIO_getsockerr() or by checking the BIO_RR_ACCEPT error code.

If BIO_do_accept() returns 1, it indicates that a connection has been successfully accepted. The new connection BIO can be retrieved using BIO_pop().

RETURN VALUES

When called on an accept BIO object, BIO_method_type(3) returns the constant BIO_TYPE_ACCEPT and BIO_method_name(3) returns a pointer to the static string "socket accept".

BIO_do_accept(), BIO_set_accept_port(), BIO_set_nbio_accept(), BIO_set_accept_bios(), and BIO_set_bind_mode() return 1 for success or 0 or -1 for failure.

BIO_get_accept_port() returns the port as a string or NULL on error.

BIO_get_bind_mode() returns the set of BIO_BIND flags or -1 on failure.

BIO_new_accept() returns a BIO or NULL on error.

EXAMPLES

This example accepts two connections on port 4444, sends messages down each and finally closes both down.

BIO *abio, *cbio, *cbio2;
ERR_load_crypto_strings();
abio = BIO_new_accept("4444");

/* First call to BIO_accept() sets up accept BIO */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error setting up accept\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}

/* Wait for incoming connection */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error accepting connection\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}
fprintf(stderr, "Connection 1 established\n");

/* Retrieve BIO for connection */
cbio = BIO_pop(abio);

BIO_puts(cbio, "Connection 1: Sending out Data on initial connection\n");
fprintf(stderr, "Sent out data on connection 1\n");

/* Wait for another connection */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error accepting connection\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}
fprintf(stderr, "Connection 2 established\n");

/* Close accept BIO to refuse further connections */
cbio2 = BIO_pop(abio);
BIO_free(abio);

BIO_puts(cbio2, "Connection 2: Sending out Data on second\n");
fprintf(stderr, "Sent out data on connection 2\n");
BIO_puts(cbio, "Connection 1: Second connection established\n");

/* Close the two established connections */
BIO_free(cbio);
BIO_free(cbio2);
