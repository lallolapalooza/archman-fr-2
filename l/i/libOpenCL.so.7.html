NOM

libOpenCL, libOpenCL.so - Implémentation OCL-ICD du chargeur ICD OpenCL

DESCRIPTION

libOpenCL.so est la bibliothèque liée par les programmes OpenCL. Elle ne contient aucune implémentation OpenCL elle-même, mais sert simplement de répartiteur vers les véritables implémentations OpenCL fournies en tant que pilotes clients installables OpenCL (ICD). Un chargeur ICD doit être capable de charger les ICD fournis par n'importe quel fournisseur.

Selon les spécifications OpenCL de Khronos (voir [Khronos]), le chargeur ICD recherche des fichiers dans le répertoire /etc/OpenCL/vendors et, pour chaque fichier dont le nom se termine par .icd, le chargeur ICD charge avec dlopen(3) la bibliothèque partagée dont le nom figure sur la première ligne du fichier .icd.

Chaque nom de bibliothèque partagée dans les fichiers « .icd » peut contenir son chemin, ou peut être un simple nom de fichier. Dans ce dernier cas, la bibliothèque partagée ICD sera recherchée dans les chemins de chargement de bibliothèques dynamiques standards.

ENVIRONNEMENT

Certaines variables d'environnement peuvent être utilisées pour modifier le comportement par défaut de libOpenCL.

OPENCL_VENDOR_PATH

Cette variable permet de modifier le chemin par défaut /etc/OpenCL/vendors. Elle est compatible avec certains autres chargeurs ICD (mais pas tous, car la variable ne fait pas partie du standard). Notez que $OCL_ICD_VENDORS (voir ci-dessous) est utilisé en priorité si elle est définie et non vide.

OCL_ICD_VENDORS

Cette variable permet de modifier la façon dont les ICD sont recherchés sur le système. Plusieurs cas sont considérés :
1. Si $OCL_ICD_VENDORS est un chemin de répertoire, alors ce chemin remplace le chemin « /etc/OpenCL/vendors » dans le comportement standard : le chargeur utilisera les fichiers .icd de ce répertoire ;
2. Sinon, si $OCL_ICD_VENDORS se termine par .icd, libOpenCL.so ne chargera que l'ICD dont le nom de bibliothèque partagée est écrit dans le fichier « .icd » spécifié ;

S'il n'y a pas de barres obliques dans $OCL_ICD_VENDORS, libOpenCL.so tentera d'abord d'utiliser /etc/OpenCL/vendors/$OCL_ICD_VENDORS (ou $OPENCL_VENDOR_PATH/$OCL_ICD_VENDORS si OPENCL_VENDOR_PATH est définie). Si cela échoue ou s'il y a des barres obliques, il utilise $OCL_ICD_VENDORS (comme nom de fichier relatif ou absolu).

3. Sinon, libOpenCL.so tentera de charger $OCL_ICD_VENDORS comme bibliothèque partagée ICD elle-même (c'est-à-dire de la charger directement avec dlopen(3)).

OPENCL_LAYERS

Cette variable permet de spécifier une liste de couches séparées par des deux-points à charger, en spécifiant leurs chemins.

OPENCL_LAYER_PATH

Cette variable permet de remplacer le chemin de recherche des couches système par défaut (/etc/OpenCL/layers).

OCL_ICD_ASSUME_ICD_EXTENSION

Si elle est définie sur une valeur non vide, contrairement à la spécification Khronos, le chargeur ne vérifiera pas que les ICD chargés déclarent l'extension cl_khr_icd. Il utilisera également clGetPlatformInfo de la table de dispatch s'il n'existe aucune fonction de ce type globalement disponible. Vous pourriez avoir besoin de définir cette variable d'environnement si vous utilisez des ICD non (pleinement) conformes, ou si vous utilisez l'ICD Intel conjointement avec optirun(1). Dans ce dernier cas, un bug dans l'ICD Intel fera planter l'application.

Si elle est définie sur la valeur debug, des messages supplémentaires seront imprimés en mode débogage (voir OCL_ICD_DEBUG ci-dessous).

OCL_ICD_PLATFORM_SORT

Permet de choisir la manière dont les plateformes sont triées lorsqu'elles sont présentées aux programmes via clGetPlatformIDs(3). Les algorithmes actuellement proposés sont :
•devices : d'abord, liste les plateformes qui prennent en charge le plus de GPU, puis le plus de CPU, puis le plus d'accélérateurs. Si OCL_ICD_PLATFORM_SORT n'est pas définie ou est définie sur une valeur inconnue, cet algorithme est utilisé.
•none : aucun tri n'est effectué et l'ordre peut changer à chaque exécution.

OCL_ICD_DEFAULT_PLATFORM

Numéro de la plateforme à choisir comme plateforme par défaut. Notez que l'utilisation de cette variable d'environnement sans garantir l'utilisation d'un algorithme de tri pour les plateformes n'est pas vraiment utile.

OCL_ICD_DEBUG

Si ocl-icd a été compilé avec le support du débogage, vous pouvez définir cette variable d'environnement sur une valeur où chaque bit affiche une sorte d'informations. Les valeurs définies sont :
•1 : avertissements (activés par défaut si le support du débogage est présent et OCL_ICD_DEBUG n'est pas défini)
•2 : messages informatifs
•4 : entrée/sortie de certaines fonctions OpenCL
•8 : décharge de la structure interne des ICD chargés

OCL_ICD_DEBUG est principalement utile pour le développement d'ocl-icd lui-même et/ou pour le développement d'ICD.
