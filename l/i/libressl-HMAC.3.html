HMAC(3) Manuel des fonctions de bibliothèque HMAC(3)

#include <openssl/hmac.h>

DESCRIPTION

HMAC est un MAC (message authentication code), c'est-à-dire une fonction de hachage clé utilisée pour l'authentification de messages, qui est basée sur une fonction de hachage.

HMAC() calcule le code d'authentification de message des n octets à l'adresse d en utilisant la fonction de hachage evp_md et la clé key d'une longueur de key_len octets.

Il place le résultat dans md, qui doit avoir de la place pour la sortie de la fonction de hachage, soit au maximum EVP_MAX_MD_SIZE octets. La taille de la sortie est placée dans md_len, sauf si elle est NULL.

evp_md peut être EVP_sha1(3), EVP_ripemd160(3), etc.

HMAC_CTX_new() alloue et initialise un nouvel objet HMAC_CTX.

HMAC_CTX_reset() réinitialise et efface le contenu de ctx et ses ressources associées, le rendant apte à de nouveaux calculs comme s'il avait été supprimé avec HMAC_CTX_free() et nouvellement créé avec HMAC_CTX_new().

HMAC_CTX_free() efface la clé et d'autres données de ctx, libère toutes les ressources associées et enfin libère ctx lui-même.

Les fonctions suivantes peuvent être utilisées si le message n'est pas entièrement stocké en mémoire :

HMAC_Init_ex() configure ou réutilise ctx pour utiliser la fonction de hachage evp_md et la clé key. L'un ou l'autre peut être NULL, dans ce cas, celui existant est réutilisé. ctx doit avoir été créé avec HMAC_CTX_new() avant la première utilisation dans cette fonction. Si HMAC_Init_ex() est appelée avec une clé NULL mais que evp_md n'est ni NULL ni identique au digest précédent utilisé par ctx, une erreur est retournée car la réutilisation d'une clé existante avec un digest différent n'est pas prise en charge. L'argument ENGINE *engine est toujours ignoré et il est recommandé de passer NULL.

HMAC_Update() peut être appelée à plusieurs reprises avec des fragments du message à authentifier (len octets à data).

HMAC_Final() place le code d'authentification de message dans md, qui doit avoir de la place pour la sortie de la fonction de hachage.

HMAC_CTX_copy() copie tout l'état interne de sctx dans dctx.

HMAC_CTX_set_flags() applique les drapeaux spécifiés aux objets EVP_MD_CTX internes. Les valeurs de drapeaux possibles EVP_MD_CTX_FLAG_* sont définies dans <openssl/evp.h>.

HMAC_size() retourne la longueur en octets de la sortie de la fonction de hachage sous-jacente. Elle est implémentée comme une macro.

VALEURS DE RETOUR

HMAC() retourne un pointeur vers le code d'authentification de message ou NULL si une erreur s'est produite.

HMAC_CTX_new() retourne un pointeur vers le nouvel objet HMAC_CTX ou NULL si une erreur s'est produite.

HMAC_CTX_reset(), HMAC_Init_ex(), HMAC_Update(), HMAC_Final(), et HMAC_CTX_copy() retournent 1 en cas de succès ou 0 en cas d'erreur.

HMAC_CTX_get_md() retourne le digest de message qui a été précédemment défini pour ctx avec HMAC_Init_ex(), ou NULL si aucun n'a été défini.

HMAC_size() retourne la longueur en octets de la sortie de la fonction de hachage sous-jacente ou 0 en cas d'erreur.

VOIR AUSSI

CMAC_Init(3), EVP_DigestInit(3)

NORMES

RFC 2104

HISTORIQUE

HMAC(), HMAC_Update(), HMAC_Final(), et HMAC_size() sont apparus pour la première fois dans SSLeay 0.9.0 et sont disponibles depuis OpenBSD 2.4.

HMAC_Init_ex() est apparu pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

HMAC_CTX_set_flags() est apparu pour la première fois dans OpenSSL 0.9.7f et est disponible depuis OpenBSD 3.8.

HMAC(3) — LibreSSL 4.2.1

NOM

HMAC — fonction de hachage à clé de message

SYNOPSIS

#include <openssl/hmac.h>

int HMAC_Final(HMAC_CTX *ctx, unsigned char *digest, EVP_PKEY_size_t *digestlen);
int HMAC_copy(HMAC_CTX *dst, const HMAC_CTX *src);

int HMAC_PKEY_CTX_ctrl_str(EVP_PKEY_CTX *pctx, const char *type, const char *value);
int HMAC_CTX_get_keylen(const HMAC_CTX *ctx);

DESCRIPTION

The HMAC algorithm is a message authentication code involving a cryptographic hash function in combination with a secret cryptographic key. HMAC can use any iterative cryptographic hash function, such as SHA-1 or MD5, in its construction. The cryptographic strength of HMAC depends on the properties of the underlying hash function, on the properties of the secret key such as its length, and on the quantities and nature of the messages being authenticated.

HMAC is defined in RFC 2104.

The functions HMAC(), HMAC_size(), HMAC_Init(), HMAC_Update(), and HMAC_Final() are convenience functions. They are equivalent to using HMAC_CTX_new(), HMAC_Init_ex(), HMAC_Update(), and HMAC_Final() respectively, and then freeing the context with HMAC_CTX_free().

The HMAC() function computes the message authentication code for the given data using the hash function specified by md and the secret key key of length keylen. The result is stored in the buffer digest. The caller must allocate sufficient space for digest. This can be determined by calling HMAC_size() or HMAC_CTX_size(). If md is NULL, the default MD5 digest is used.

The function HMAC_size() returns the output size in bytes of the digest produced by the hash function md. If md is NULL, it returns the size of the MD5 digest.

The HMAC context structure HMAC_CTX is used to compute an HMAC value incrementally. This is useful for computing the HMAC of large messages or for computing multiple HMACs using the same key.

HMAC_CTX_new() allocates and initialises a new HMAC_CTX structure.

HMAC_CTX_free() frees the HMAC_CTX structure pointed to by ctx.

HMAC_CTX_reset() resets the HMAC context to its initial state, ready to compute a new HMAC value.

HMAC_Init() initializes the HMAC context ctx with the secret key key of length keylen and the hash function specified by md. If md is NULL, the default MD5 digest is used.

HMAC_Update() processes the next chunk of data, of length datalen, from the message to be authenticated.

HMAC_Final() computes the HMAC digest of the data processed so far and stores it in the buffer digest. The actual number of bytes written is stored in digestlen. After calling HMAC_Final(), the HMAC context ctx is no longer valid for further updates. It can be reset using HMAC_CTX_reset() or freed using HMAC_CTX_free().

HMAC_copy() copies the HMAC context from src to dst. Both contexts must have been previously initialised. dst must point to a valid but not yet initialised HMAC_CTX structure.

HMAC_CTX_get_md() returns the digest algorithm currently configured for the HMAC context ctx. If no digest has been set, it returns NULL.

HMAC_CTX_get_current_md() returns the digest algorithm currently in use by the HMAC context ctx. This may differ from the initial digest algorithm if the context has been updated to use a different digest algorithm.

HMAC_CTX_get_md_ctx() returns the underlying EVP_MD_CTX used by the HMAC context ctx. This can be used to access lower-level functionality of the digest algorithm.

HMAC_load_funcs() and HMAC_cleanup() are deprecated and should not be used.

The functions HMAC_PKEY_CTX_free(), HMAC_PKEY_CTX_init(), HMAC_PKEY_CTX_set_md(), HMAC_PKEY_CTX_ctrl(), and HMAC_PKEY_CTX_ctrl_str() are used for key generation and management operations involving HMAC. They are part of the OpenSSL provider interface.

HMAC_CTX_get_keylen() returns the length of the key used in the HMAC context ctx.

RETURN VALUES

The HMAC(), HMAC_Init(), HMAC_Update(), and HMAC_Final() functions return 1 on success, and 0 on failure.

The HMAC_size() and HMAC_CTX_size() functions return the size of the digest in bytes.

The HMAC_CTX_new() function returns a pointer to a newly allocated HMAC_CTX structure, or NULL if the allocation fails.

The HMAC_CTX_free() and HMAC_CTX_reset() functions do not return values.

The HMAC_copy() function returns 1 on success, and 0 on failure.

The HMAC_CTX_get_md() and HMAC_CTX_get_current_md() functions return a pointer to the EVP_MD structure, or NULL if no digest has been set.

The HMAC_CTX_get_md_ctx() function returns a pointer to the EVP_MD_CTX structure, or NULL if the context is not initialized or if an error occurred.

The HMAC_CTX_get_keylen() function returns the length of the key in bytes, or 0 if the key has not been set.

SEE ALSO

EVP_DigestInit(3), HMAC_Init_ex(3), OpenSSL_add_all_digests(3)

STANDARDS

RFC 2104 defines the HMAC algorithm.

HISTORY

HMAC_size() was first introduced in OpenSSL 0.9.7.

HMAC_Init_ex() was added in OpenSSL 1.1.0.

HMAC_CTX_copy() first appeared in OpenSSL 1.0.0 and has been available since OpenBSD 4.9.

HMAC_CTX_new(), HMAC_CTX_reset(), HMAC_CTX_free(), and HMAC_CTX_get_md() first appeared in OpenSSL 1.1.0 and have been available since OpenBSD 6.3.

CAVEATS

Other implementations allow md in HMAC() to be NULL and return a static array, which is not thread safe.
