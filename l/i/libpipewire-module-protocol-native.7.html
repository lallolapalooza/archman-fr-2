NOM

libpipewire-module-protocol-native - Protocole Natif

DESCRIPTION

Le module de protocole natif implémente la communication PipeWire entre un client et un serveur à l'aide de sockets locaux Unix.

Normalement, ce module est chargé dans les fichiers de configuration du client et du serveur afin qu'ils puissent communiquer.

NOM DU MODULE

libpipewire-module-protocol-native

OPTIONS DU MODULE

Le module prend en charge les arguments suivants :

•
sockets: [ { nom = "nom_socket", propriétaire = "propriétaire", groupe = "groupe", mode = "mode", contexte_selinux = "contexte" }, props = { ... }, ... ]

Tableau de noms de sockets Unix et (facultativement) de propriétaire/permissions à servir, si le contexte est un serveur. S'il ne s'agit pas de chemins absolus, les sockets sont créés dans le répertoire d'exécution par défaut.

Les props sont copiés directement à tout client qui se connecte via ce socket serveur et peuvent être utilisés pour configurer des permissions spéciales.

La valeur par défaut est [ { nom = "NOM_DU_COEUR" }, { nom = "NOM_DU_COEUR-manager" } ], où NOM_DU_COEUR est le nom du cœur PipeWire, généralement pipewire-0.

Les permissions n'ont aucun effet pour les sockets provenant de l'activation de socket systemd. Ceux-ci doivent être configurés via le mécanisme systemd.socket(5).

OPTIONS GÉNÉRALES

Le nom du cœur est obtenu comme suit :

  • PIPEWIRE_CORE : la variable d'environnement avec le nom du cœur
  • core.name : dans les propriétés du contexte
  • un nom basé sur l'identifiant du processus

Le contexte deviendra également un serveur si :

  • PIPEWIRE_DAEMON : l'environnement est vrai
  • core.daemon : dans les propriétés du contexte est vrai

Le socket sera situé dans le répertoire obtenu en examinant les variables d'environnement suivantes :

  • PIPEWIRE_RUNTIME_DIR
  • XDG_RUNTIME_DIR
  • USERPROFILE

L'adresse du socket sera écrite dans le descripteur de fichier de notification si la variable d'environnement suivante est définie :

•
PIPEWIRE_NOTIFICATION_FD

Lorsqu'un client se connecte, la connexion sera établie à :

  • PIPEWIRE_REMOTE : l'environnement avec le nom distant
  • remote.name : la propriété dans le contexte.
  • Le nom distant par défaut "pipewire-0"

Un nom distant spécial "internal" peut être utilisé pour établir une connexion avec le contexte local. Cela peut être fait même lorsque le serveur n'est pas un démon. Il peut être utilisé pour traiter un contexte local comme s'il s'agissait d'un serveur.

SUBSTITUTION DE CONFIG

Une section de configuration module.protocol-native.args peut être ajoutée pour remplacer les arguments du module.

# ~/.config/pipewire/pipewire.conf.d/mes-args-protocol-native.conf
module.protocol-native.args = {
       sockets = [
           { nom = "pipewire-0" }
           { nom = "pipewire-0-manager" }
       ]
}

EXEMPLE DE CONFIGURATION

context.modules = [
{ name = libpipewire-module-protocol-native }
]
context.modules = [
 { name = libpipewire-module-protocol-native,
   args = {
       sockets = [
           { nom = "pipewire-0" }
           { nom = "pipewire-0-manager" }
           { nom = "pipewire-1"
             props = { mon.connexion = "l'autre" }
           }
       ]
   }
 }
]
