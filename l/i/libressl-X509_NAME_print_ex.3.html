libressl-X509_NAME_print_ex(3)

Paquet: libressl

X509_NAME_PRINT_EX(3) Manuel des fonctions de bibliothèque X509_NAME_PRINT_EX(3)

NOM

X509_NAME_print_ex, X509_NAME_print_ex_fp, X509_NAME_oneline — Routines d’impression de X509_NAME

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/x509.h>

int
X509_NAME_print_ex(BIO *out, const X509_NAME *nm, int indent, unsigned long flags);

int
X509_NAME_print_ex_fp(FILE *fp, const X509_NAME *nm, int indent, unsigned long flags);

char *
X509_NAME_oneline(const X509_NAME *a, char *buf, int size);

DESCRIPTION

X509_NAME_print_ex() imprime une version lisible par l'homme de nm dans le BIO out. Chaque ligne (pour les formats multilignes) est indentée de indent espaces. Le format de sortie peut être personnalisé de manière extensive en utilisant le paramètre flags.

X509_NAME_print_ex_fp() est identique à X509_NAME_print_ex() sauf que la sortie est écrite dans le pointeur FILE fp.

X509_NAME_oneline() imprime une version ASCII de a dans buf. Si buf est NULL, alors un tampon est alloué dynamiquement et renvoyé, et size est ignoré. Sinon, au maximum size octets seront écrits, y compris le NUL final, et buf est renvoyé.

X509_NAME_oneline() est une fonction héritée qui produit une forme de sortie non standard. Elle ne gère pas les champs multi-caractères et présente diverses bizarreries et incohérences. Son utilisation est fortement déconseillée dans les nouvelles applications.

Bien qu'il existe un grand nombre de drapeaux possibles, pour la plupart des usages, XN_FLAG_ONELINE, XN_FLAG_MULTILINE, ou XN_FLAG_RFC2253 suffiront. Comme indiqué sur la page de manuel de ASN1_STRING_print_ex(3), pour les terminaux UTF-8, ASN1_STRFLGS_ESC_MSB doit être désactivé : ainsi, par exemple, XN_FLAG_ONELINE & ~ASN1_STRFLGS_ESC_MSB serait utilisé.

L'ensemble complet des drapeaux pris en charge par X509_NAME_print_ex est listé ci-dessous.

Plusieurs options peuvent être combinées par OU.

Les options XN_FLAG_SEP_COMMA_PLUS, XN_FLAG_SEP_CPLUS_SPC, XN_FLAG_SEP_SPLUS_SPC et XN_FLAG_SEP_MULTILINE déterminent les séparateurs de champs à utiliser. Deux séparateurs distincts sont utilisés entre les composants RelativeDistinguishedName distincts et des valeurs séparées dans le même RDN pour un RDN multivalué. Les RDN multivalués sont actuellement très rares, donc le deuxième séparateur ne sera presque jamais utilisé.

XN_FLAG_SEP_COMMA_PLUS utilise la virgule et le plus comme séparateurs. XN_FLAG_SEP_CPLUS_SPC utilise la virgule et le plus avec des espaces : c'est plus lisible que la simple virgule et le plus. XN_FLAG_SEP_SPLUS_SPC utilise le point-virgule espacé et le plus. XN_FLAG_SEP_MULTILINE utilise respectivement le saut de ligne espacé et le plus. XN_FLAG_SEP_MASK contient les bits utilisés pour représenter ces quatre options.

Si XN_FLAG_DN_REV est défini, le DN entier est imprimé dans l'ordre inverse.

Les champs XN_FLAG_FN_SN, XN_FLAG_FN_LN, XN_FLAG_FN_OID et XN_FLAG_FN_NONE déterminent comment un nom de champ est affiché. Il utilisera le nom court (par exemple, CN), le nom long (par exemple, commonName), utilisera toujours la forme numérique OID (normalement, les OID ne sont utilisés que si le nom du champ n'est pas reconnu) et aucun nom de champ, respectivement. XN_FLAG_FN_MASK contient les bits utilisés pour représenter ces quatre options.

Si XN_FLAG_SPC_EQ est défini, alors des espaces seront placés autour du caractère ‘=’ séparant les noms de champs et les valeurs.

Si XN_FLAG_DUMP_UNKNOWN_FIELDS est défini, alors l'encodage des champs inconnus sera imprimé au lieu des valeurs.

Si XN_FLAG_FN_ALIGN est défini, alors les noms de champs seront alignés sur 20 caractères : ceci n'est utile que pour le format multiligne.

De plus, toutes les options prises en charge par ASN1_STRING_print_ex(3) peuvent être utilisées pour contrôler la façon dont chaque valeur de champ est affichée.

En outre, un certain nombre d'options peuvent être définies pour des formats couramment utilisés.

XN_FLAG_RFC2253 définit les options qui produisent une sortie compatible avec RFC 2253. Elle est équivalente à ASN1_STRFLGS_RFC2253 | XN_FLAG_SEP_COMMA_PLUS | XN_FLAG_DN_REV | XN_FLAG_FN_SN | XN_FLAG_DUMP_UNKNOWN_FIELDS.

XN_FLAG_ONELINE est un format sur une ligne plus lisible, qui est le même que : ASN1_STRFLGS_RFC2253 | ASN1_STRFLGS_ESC_QUOTE | XN_FLAG_SEP_CPLUS_SPC | XN_FLAG_SPC_EQ | XN_FLAG_FN_SN.

XN_FLAG_MULTILINE est un format multiligne qui est le même que : ASN1_STRFLGS_ESC_CTRL | ASN1_STRFLGS_ESC_MSB | XN_FLAG_SEP_MULTILINE | XN_FLAG_SPC_EQ | XN_FLAG_FN_LN | XN_FLAG_FN_ALIGN.

XN_FLAG_COMPAT utilise le format SSLeay traditionnel non standard.

VALEURS DE RETOUR

X509_NAME_print_ex() et X509_NAME_print_ex_fp() retournent 1 en cas de succès ou 0 en cas d'erreur si XN_FLAG_COMPAT est défini dans flags. Sinon, elles retournent le nombre d'octets imprimés, y compris l'indentation, ou -1 en cas d'erreur.

X509_NAME_oneline() renvoie une chaîne valide en cas de succès ou NULL en cas d'erreur.

VOIR AUSSI

ASN1_STRING_print_ex(3), d2i_X509_NAME(3), X509_NAME_get_index_by_NID(3), X509_NAME_new(3)

HISTORIQUE

X509_NAME_oneline() est apparu pour la première fois dans SSLeay 0.5.1 et est disponible depuis OpenBSD 2.4.

X509_NAME_print_ex() et X509_NAME_print_ex_fp() sont apparus pour la première fois dans OpenSSL 0.9.6 et sont disponibles depuis OpenBSD 2.9.

X509_NAME_print_ex(3)

NOM

X509_NAME_print_ex, X509_NAME_print, X509_NAME_print_ex_fp, X509_NAME_print_fp — imprime une structure X509_NAME dans un flux ou une chaîne.

SYNTAXE

#include <openssl/x509.h>

int X509_NAME_print_ex(BIO *out, X509_NAME *nm, int indent, unsigned long flags);
int X509_NAME_print(BIO *out, X509_NAME *nm, int indent);
int X509_NAME_print_ex_fp(FILE *fp, X509_NAME *nm, int indent, unsigned long flags);
int X509_NAME_print_fp(FILE *fp, X509_NAME *nm, int indent);

DESCRIPTION

Les fonctions X509_NAME_print_ex et X509_NAME_print_ex_fp impriment la structure X509_NAME référencée par nm. Le résultat est soit écrit dans le descripteur BIO out, soit dans le descripteur de fichier fp.

Le paramètre indent spécifie le niveau d'indentation pour le rendu. L'indentation n'est utilisée que si le drapeau XN_FLAG_SEP_SPACE ou XN_FLAG_SEP_COMMA_PRINTABLE n'est pas utilisé.

Le paramètre flags peut être utilisé pour modifier le comportement d'impression. Les valeurs possibles pour les drapeaux sont (les deux dernières sont des combinaisons de drapeaux qui sont déjà traitées) :

XN_FLAG_ONELINE : Imprime le nom sur une seule ligne. Les différents attributs sont séparés par des virgules et des espaces.
XN_FLAG_ARRAY : Imprime le nom sous forme de tableau. Les différents attributs sont séparés par des retours à la ligne.
XN_FLAG_FN_SN : Imprime le nom des champs, suivi du nom court des champs.
XN_FLAG_FN_LN : Imprime le nom des champs, suivi du nom long des champs.
XN_FLAG_FN_ANY : Imprime le nom des champs, suivi du nom court ou long des champs si disponible.
XN_FLAG_NO_PRINT_REDUNDANT : Si un champ a plusieurs valeurs et que le même champ est déjà imprimé, il n'est pas imprimé à nouveau.
XN_FLAG_CIPHER_SERVICE : Les champs d'attributs sont imprimés sous forme de chaînes encodées en Base64.
XN_FLAG_SHOW_TYPE : Les champs d'attributs sont imprimés sous forme de chaînes décodées en Base64.
XN_FLAG_DUMP_UNKNOWN : Les champs d'attributs inconnus sont imprimés sous forme de chaînes décodées en Base64.
XN_FLAG_SEP_SPACE : Les attributs sont séparés par une virgule et un espace.
XN_FLAG_SEP_COMMA_PRINTABLE : Les attributs sont séparés par une virgule et un espace si tous les attributs sont imprimables. Sinon, les attributs sont séparés par un retour à la ligne.

X509_NAME_print et X509_NAME_print_fp sont des fonctions obsolètes qui appellent X509_NAME_print_ex avec flags défini à 0.

VALEURS DE RETOUR

Ces fonctions retournent le nombre total de caractères imprimés en cas de succès, ou -1 en cas d'erreur.

VOIR AUSSI

BIO_free(3), X509_NAME_new(3)

HISTORIQUE

La fonction X509_NAME_print_ex et les drapeaux associés ont été ajoutés dans OpenSSL 1.0.0.

Les fonctions X509_NAME_print et X509_NAME_print_fp ont été dépréciées dans OpenSSL 1.0.0.
