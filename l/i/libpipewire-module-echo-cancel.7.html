NOM

libpipewire-module-echo-cancel - Annulation d'écho

DESCRIPTION

Le module echo-cancel effectue l'annulation d'écho.

Le module crée des nœuds sources et sorties virtuels echo-cancel-capture et echo-cancel-playback, ainsi que les flux associés.

Le module echo-cancel est principalement utilisé dans les applications de vidéoconférence ou de conférence audio. Lorsque les autres participants parlent et que l'audio est diffusé vers les haut-parleurs, le signal est de nouveau capté par le microphone et renvoyé aux autres participants (avec votre voix), ce qui entraîne un écho. C'est gênant car les autres participants entendront leur propre écho via vous.

Conceptuellement, l'annuleur d'écho est composé de 4 flux :

.--------.     .---------.     .--------.     .----------.     .-------.
|  mic   | --> | capture | --> |        | --> |  source  | --> |  app  |
                               | cancel |
.--------.     .---------.     |        |     .----------.     .---------.
|  app   | --> |  sink   | --> |        | --> | playback | --> | speaker |
  • Un flux de capture qui enregistre l'audio d'un microphone.
  • Une sortie (Sink) qui reçoit le signal contenant les données qui doivent être annulées du flux de capture. C'est ici que l'application (application de vidéoconférence) envoie l'audio, et elle contient le signal des autres participants qui parlent et qui doit être annulé.
  • Un flux de lecture (playback) qui transmet simplement le signal de la sortie vers le haut-parleur. Ceci est fait pour que vous puissiez entendre les autres participants. C'est aussi le signal qui est capté par le microphone et qui doit éventuellement être supprimé à nouveau.
  • Une source (Source) qui expose les données capturées et annulées de l'écho provenant du flux de capture. Les données du flux de sortie et du flux de capture sont corrélées et le signal du flux de sortie est supprimé des données du flux de capture. Ces données sont ensuite transmises à l'application (l'application de conférence) et ne contiennent plus l'écho des autres participants.

NOM DU MODULE

libpipewire-module-echo-cancel

OPTIONS DU MODULE

Options spécifiques au comportement de ce module

  • capture.props = {}: propriétés à passer au flux de capture
  • source.props = {}: propriétés à passer au flux source
  • sink.props = {}: propriétés à passer au flux de sortie
  • playback.props = {}: propriétés à passer au flux de lecture
  • library.name = <str>: la bibliothèque d'annulation d'écho. Actuellement supporté : aec/libspa-aec-webrtc. Laisser non défini pour utiliser la méthode par défaut (aec/libspa-aec-webrtc).
  • aec.args = <str>: arguments à passer à la méthode d'annulation d'écho
  • monitor.mode: Au lieu de créer une sortie, créer un flux qui capture depuis les ports de moniteur de la sortie par défaut.

OPTIONS GÉNÉRALES

Options avec un comportement bien connu :

  • audio.rate
  • audio.channels
  • audio.position
  • media.class
  • node.latency
  • node.name
  • node.description
  • node.group
  • node.link.group
  • node.virtual
  • node.latency
  • remote.name

EXEMPLE DE CONFIGURATION

 # ~/.config/pipewire/pipewire.conf.d/my-echo-cancel.conf
 context.modules = [
  {   name = libpipewire-module-echo-cancel
      args = {
          # library.name  = aec/libspa-aec-webrtc
          # node.latency = 1024/48000
          # monitor.mode = false
          capture.props = {
             node.name = "Capture d'annulation d'écho"
          }
          source.props = {
             node.name = "Source d'annulation d'écho"
          }
          sink.props = {
             node.name = "Sortie d'annulation d'écho"
          }
          playback.props = {
             node.name = "Lecture d'annulation d'écho"
          }
      }
  }
]
