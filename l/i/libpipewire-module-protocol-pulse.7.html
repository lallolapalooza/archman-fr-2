NOM

libpipewire-module-protocol-pulse - Protocole Pulse

DESCRIPTION

Ce module implémente un serveur PulseAudio complet basé sur PipeWire.

Ceci n'est que l'implémentation du serveur, les clients sont censés utiliser la bibliothèque client PulseAudio d'origine. Cela offre un haut niveau de compatibilité avec les applications existantes ; en fait, tous les outils PulseAudio habituels tels que pavucontrol, pactl, pamon, paplay continueront de fonctionner comme avant.

Ce module est généralement chargé dans le cadre d'un processus pipewire autonome, appelé pipewire-pulse, avec le fichier de configuration pipewire-pulse.conf.

Le serveur pulse implémente un cache d'échantillons qui n'est pas autrement disponible dans PipeWire.

NOM DU MODULE

libpipewire-module-protocol-pulse

OPTIONS DU MODULE

Les arguments du module peuvent être le contenu de pulse.properties, mais il est recommandé de créer une section pulse.properties distincte dans le fichier de configuration afin que les remplacements puissent être effectués.

PULSE.PROPRIÉTÉS

Une section de configuration avec des propriétés serveur peut être fournie.

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.properties = {
    # les adresses sur lesquelles ce serveur écoute
    server.address = [
        "unix:native"
        #"unix:/tmp/quelquechose"              # les chemins absolus peuvent être utilisés
        #"tcp:4713"                         # IPv4 et IPv6 sur toutes les adresses
        #"tcp:[::]:9999"                    # IPv6 sur toutes les adresses
        #"tcp:127.0.0.1:8888"               # IPv4 sur une seule adresse
        #
        #{ address = "tcp:4713"             # adresse
        #  max-clients = 64                 # nombre maximum de clients
        #  listen-backlog = 32              # backlog dans la file d'attente d'écoute du serveur
        #  client.access = "restricted"     # permissions pour les clients
        #}
    ]
    #server.dbus-name       = "org.pulseaudio.Server"
    #pulse.allow-module-loading = true
    #pulse.min.req          = 128/48000     # 2.7ms
    #pulse.default.req      = 960/48000     # 20 millisecondes
    #pulse.min.frag         = 128/48000     # 2.7ms
    #pulse.default.frag     = 96000/48000   # 2 secondes
    #pulse.default.tlength  = 96000/48000   # 2 secondes
    #pulse.min.quantum      = 128/48000     # 2.7ms
    #pulse.default.format   = F32
    #pulse.default.position = [ FL FR ]
    #pulse.idle.timeout     = 0
}
pulse.properties.rules = [
    {   matches = [ { cpu.vm.name = !null } ]
        actions = {
            update-props = {
                # Ces remplacements ne sont appliqués que lors de l'exécution dans une VM.
                pulse.min.quantum = 1024/48000      # 22ms
            }
        }
    }
]

Options de connexion

...
server.address = [
    "unix:native"
    # "tcp:4713"
]
...

Les adresses sur lesquelles le serveur écoute au démarrage. Décommentez l'entrée tcp:4713 pour que le serveur écoute également sur un socket tcp. Ceci équivaut au chargement de libpipewire-module-native-protocol-tcp.

Il existe également une syntaxe légèrement plus verbeuse avec plus d'options :

....
server.address = [
  {  address = "tcp:4713"             # adresse
     max-clients = 64                 # nombre maximum de clients
     listen-backlog = 32              # backlog dans la file d'attente d'écoute du serveur
     client.access = "restricted"     # permissions pour les clients
  }
....

Utilisez client.access pour utiliser l'une des méthodes d'accès afin de restreindre les permissions accordées aux clients connectés via cette adresse.

Par défaut, l'accès réseau reçoit les permissions « restricted ». Le gestionnaire de session est responsable de l'attribution des permissions aux clients ayant des permissions restreintes (généralement des permissions en lecture seule).

server.dbus-name       = "org.pulseaudio.Server"

Le nom DBus à réserver pour le serveur. Si vous avez plusieurs serveurs, vous voudrez peut-être changer le nom.

pulse.allow-module-loading = true

Par défaut, les clients sont autorisés à charger et décharger des modules. Vous pouvez désactiver cette fonctionnalité avec cette option.

Options de mise en tampon de lecture

pulse.min.req = 128/48000              # 2.7ms

La quantité minimale de données à demander pour les clients. Les valeurs demandées par le client seront limitées à cette valeur. Diminuer cette valeur avec tlength peut réduire la latence si le client le souhaite, mais augmenter la charge CPU.

pulse.default.req = 960/48000          # 20 millisecondes

La quantité par défaut de données à demander pour les clients. Si le client ne spécifie aucune valeur particulière, cette valeur par défaut sera utilisée. Diminuer cette valeur avec tlength peut réduire la latence mais augmenter la charge CPU.

pulse.default.tlength = 96000/48000    # 2 secondes

La quantité cible de données à mettre en tampon côté serveur. Si le client n'a pas spécifié de valeur, cette valeur par défaut sera utilisée. Des valeurs plus faibles peuvent réduire la latence.

Options de mise en tampon d'enregistrement

pulse.min.frag = 128/48000             # 2.7ms

La taille minimale autorisée du tampon de capture avant qu'il ne soit envoyé à un client. La valeur demandée par le client sera limitée à cela. Diminuer cette valeur peut réduire la latence au détriment d'une utilisation accrue du CPU.

pulse.default.frag = 96000/48000       # 2 secondes

La taille par défaut du tampon de capture avant qu'il ne soit envoyé à un client. Si le client n'a spécifié aucune valeur, cette valeur par défaut sera utilisée. Diminuer cette valeur peut réduire la latence au détriment d'une utilisation accrue du CPU.

Options de planification

pulse.min.quantum = 128/48000          # 2.7ms

Le quantum minimum (taille du tampon en échantillons) à utiliser pour les clients pulseaudio. Cette valeur est calculée en fonction des frag et req/tlength pour les flux d'enregistrement et de lecture respectivement, puis limitée à cette valeur pour garantir qu'aucun client pulseaudio ne demande des quantums trop petits. Diminuer cette valeur pourrait réduire la latence au détriment d'une utilisation accrue du CPU.

Options de format

pulse.default.format = F32

Certains modules utiliseront ce format par défaut lorsqu'aucun autre format n'est spécifié. Ceci est équivalent à l'option de format d'échantillon par défaut de PulseAudio dans /etc/pulse/daemon.conf.

pulse.default.position = [ FL FR ]

Certains modules utiliseront cette carte de canaux (avec son nombre de canaux) par défaut. Ceci est équivalent aux options de canaux d'échantillon par défaut et de carte de canaux par défaut de PulseAudio dans /etc/pulse/daemon.conf.

Options de correction

pulse.fix.format = "S16LE"

Lorsqu'un flux utilise le drapeau FIX_FORMAT, le format est fixé à cette valeur. Normalement, le format serait fixé au puits/source auquel le flux se connecte. Lorsqu'un format invalide (null ou « " ») est défini, le drapeau FIX_FORMAT est ignoré.

pulse.fix.rate = 48000

Lorsqu'un flux utilise le drapeau FIX_RATE, le taux d'échantillonnage est fixé à cette valeur. Normalement, le taux serait fixé au puits/source auquel le flux se connecte. Lorsqu'un taux de 0 est défini, le drapeau FIX_RATE est ignoré.

pulse.fix.position = "[ FL FR ]"

Lorsqu'un flux utilise le drapeau FIX_CHANNELS, le nombre de canaux est fixé à cette valeur. Normalement, les canaux seraient fixés au puits/source auquel le flux se connecte. Lorsqu'une position invalide (null ou « " ») est définie, le drapeau FIX_CHANNELS est ignoré.

pulse.idle.timeout = 0

Certains clients n'envoient pas de données alors qu'ils le devraient et provoquent des sous-dépassements. Lors de la définition de cette option, ces clients seront mis en pause s'ils sous-dépassement pendant la durée donnée en secondes. Cela garantit que les puits peuvent se suspendre et économiser de l'énergie. Lorsque le client reprend, il sera de nouveau débloqué. Une valeur de 0 désactive cette fonctionnalité.

libpipewire-module-protocol-pulse(7) — PipeWire

NAME

libpipewire-module-protocol-pulse 7 — PipeWire's PulseAudio protocol implementation

DESCRIPTION

This module implements the PulseAudio network protocol on top of PipeWire. It allows PulseAudio clients to connect to PipeWire and use its functionality.

The module is configured via properties in pipewire-pulse.conf, which is usually located in /usr/share/pipewire/pipewire-pulse.conf or /etc/pipewire/pipewire-pulse.conf. Fragments can be placed in /etc/pipewire/pipewire-pulse.conf.d/ and ~/.config/pipewire/pipewire-pulse.conf.d/

MODULE NAME

The module is loaded with load-module module-protocol-pulse.

MODULE OPTIONS

The module takes the following arguments:

session.suspend-timeout-seconds
The timeout in seconds after which an idle stream will be suspended. Default is 5 seconds.
session.intended-roles
A boolean string with intended roles. This is a comma-separated list of roles. Default is empty.
session.source/sink.node-latency
The node latency to set for the created source and sink nodes.
session.props
A dictionary of properties to apply to the core object. See pipewire.conf(5).
session.source/sink.props
A dictionary of properties to apply to the source and sink nodes. See pipewire.conf(5).
session.node.name
The name to give to the created nodes.
session.node.description
The description to give to the created nodes.
session.node.group
The group to give to the created nodes.

Example:

context.modules = [
    {   name = libpipewire-module-protocol-pulse
        args = {
            session.suspend-timeout-seconds = 10
            session.intended-roles = "Music,Media,Communication"
            session.props = {
                api.alsa.period-size = 1024
                api.alsa.headset-profile = true
            }
            session.source.props = {
                node.description = "My Microphone"
            }
            session.sink.props = {
                node.description = "My Speakers"
            }
        }
    }
]

PULSE.PROPERTIES

The pulse protocol module can be configured using the pulse.properties section. This section allows you to set properties that affect the behavior of the pulse server.

pulse.properties = {
    # Use "unix:native" for the native socket, or "tcp:PORT" for TCP listening.
    server.address = [ "unix:native" ]
    # Dump configuration to a file (useful for debugging)
    # config.log-level = 3
    # config.log-target = "/var/log/pipewire-pulse.log"

    # Set the default sample rate and format
    default.clock.rate = 48000
    default.clock.allowed-rates = [ 44100 48000 88200 96000 ]
    default.clock.quantum = 1024
    default.clock.min-quantum = 32
    default.clock.max-quantum = 2048
    default.clock.min-quantum-async = 256
    default.clock.max-quantum-async = 4096

    # Make PulseAudio use the specified sink by default
    # default.clock.fallback-sink = "alsa_output.pci-0000_00_1f.3.analog-stereo"

    # Allow applications to specify their own quantum
    # pulse.min.quantum = 256/48000
    # pulse.max.quantum = 2048/48000
}

The pulse.properties section can contain various settings to control the PulseAudio compatibility layer. Some common settings include:

  • server.address: A list of addresses where the PulseAudio server should listen. This can be a Unix domain socket (e.g., unix:native) or a TCP port (e.g., tcp:4713).
  • default.clock.rate: The default sample rate.
  • default.clock.allowed-rates: A list of allowed sample rates.
  • default.clock.quantum: The default buffer size (quantum).
  • default.clock.min-quantum: The minimum buffer size.
  • default.clock.max-quantum: The maximum buffer size.
  • default.clock.min-quantum-async: The minimum buffer size for asynchronous operations.
  • default.clock.max-quantum-async: The maximum buffer size for asynchronous operations.
  • default.clock.fallback-sink: The default sink to use if no other sink is specified.
  • pulse.min.quantum: Minimum quantum override for PulseAudio clients.
  • pulse.max.quantum: Maximum quantum override for PulseAudio clients.

COMMAND EXECUTION

The pulse.cmd section allows you to execute commands when the server starts. This is useful for loading modules or executing other PipeWire commands.

# Extra commands can be executed here.
#   load-module : loads a module with args and flags
#      args = "<module-name> <module-args>"
#      ( flags = [ "no-fail" ] )
#      ( condition = [ { <key1> = <value1>, ... } ... ] )
# conditions will check the pulse.properties key/values.
pulse.cmd = [
    { cmd = "load-module" args = "module-always-sink" flags = [ ] }
    #{ cmd = "load-module" args = "module-switch-on-connect" condition = [ { pulse.cmd.switch-on-connect = true } ]
    #{ cmd = "load-module" args = "module-gsettings" flags = [ "nofail" ] }
]

The following commands are supported:

load-module
Loads a PipeWire module.
args
The module name and its arguments.
flags
A list of flags, e.g., nofail.
condition
A list of conditions that must be met for the module to be loaded. Conditions are checked against the properties in pulse.properties.

DYNAMIC PROPERTIES

The pulse.properties.rules section allows you to dynamically update properties based on certain conditions. This is useful for applying specific settings only when certain criteria are met.

pulse.properties.rules = [
    {   matches = [ { cpu.vm.name = !null } ]
        actions = {
            update-props = {
                # These overrides are only applied when running in a vm.
                pulse.min.quantum = 1024/48000      # 22ms
            }
        }
    }
]

In this example, if the system is running in a virtual machine (indicated by cpu.vm.name not being null), the pulse.min.quantum property will be overridden. This is beneficial because VMs often cannot achieve the same low latency as real hardware.

STREAM SETTINGS AND RULES

Streams created by module-protocol-pulse can be configured using the stream.properties and stream.rules sections, similar to other PipeWire modules.

APPLICATION SETTINGS (RULES)

The pulse protocol module supports generic configuration rules that apply to clients. The pulse.rules section allows you to define these rules, which can include quirks and property updates.

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.rules = [
    {
        # skype does not want to use devices that don't have an S16 sample format.
        matches = [
             { application.process.binary = "teams" }
             { application.process.binary = "teams-insiders" }
             { application.process.binary = "skypeforlinux" }
        ]
        actions = { quirks = [ force-s16-info ] }
    }
    {
        # speech dispatcher asks for too small latency and then underruns.
        matches = [ { application.name = "~speech-dispatcher*" } ]
        actions = {
            update-props = {
                pulse.min.req          = 1024/48000     # 21ms
                pulse.min.quantum      = 1024/48000     # 21ms
                pulse.idle.timeout     = 5              # pause after 5 seconds of underrun
            }
        }
    }
]

Quirks

The quirks action applies specific fixes or workarounds for clients:

  • force-s16-info: Pretends that the sample format is S16 (16-bit) samples. Useful for applications that refuse sinks/sources without this format.
  • remove-capture-dont-move: Removes the DONT_MOVE flag on capture streams, allowing them to be moved by tools like pavucontrol.
  • block-source-volume: Prevents the client from modifying source volumes (e.g., disabling automatic gain control).
  • block-sink-volume: Prevents the client from modifying sink volumes.
  • block-record-stream: Prevents the client from creating record streams.
  • block-playback-stream: Prevents the client from creating playback streams.

update-props

The update-props action allows you to override specific client properties. This is often used to adjust quantum values or other stream-related settings.

startup notification

If the environment variable PIPEWIRE_PULSE_NOTIFICATION_FD is set, a newline character will be written to the specified file descriptor when the server has started.

EXAMPLE CONFIGURATION

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
context.modules = [
{   name = libpipewire-module-protocol-pulse
    args = { }
}
]
pulse.properties = {
    server.address = [ "unix:native" ]
}
pulse.rules = [
    {
       # skype does not want to use devices that don't have an S16 sample format.
       matches = [
            { application.process.binary = "teams" }
            { application.process.binary = "teams-insiders" }
            { application.process.binary = "skypeforlinux" }
       ]
       actions = { quirks = [ force-s16-info ] }
   }
   {
       # speech dispatcher asks for too small latency and then underruns.
       matches = [ { application.name = "~speech-dispatcher*" } ]
       actions = {
           update-props = {
               pulse.min.req          = 1024/48000     # 21ms
               pulse.min.quantum      = 1024/48000     # 21ms
               pulse.idle.timeout     = 5              # pause after 5 seconds of underrun
           }
       }
   }
]
