libressl-BN_zero(3)

Paquet: libressl

BN_ZERO(3) Manuel des fonctions de bibliothèque BN_ZERO(3)

NOM

BN_zero, BN_one, BN_value_one, BN_set_word, BN_get_word — Opérations d'affectation BIGNUM

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/bn.h>

void
BN_zero(BIGNUM *a);

int
BN_one(BIGNUM *a);

const BIGNUM *
BN_value_one(void);

int
BN_set_word(BIGNUM *a, BN_ULONG w);

BN_ULONG
BN_get_word(const BIGNUM *a);

DESCRIPTION

BN_ULONG est une macro qui s'étend à un type entier non signé optimisé pour l'implémentation la plus efficace sur la plateforme locale. C'est unsigned long (= uint64_t) sur les plateformes _LP64 et unsigned int (= uint32_t) ailleurs.

BN_zero(), BN_one(), et BN_set_word() définissent a aux valeurs 0, 1 et w respectivement.

BN_value_one() retourne une constante BIGNUM de valeur 1. Cette constante est utile pour les comparaisons et les affectations.

VALEURS DE RETOUR

BN_get_word() retourne la valeur a, ou un nombre avec tous les bits à 1 si a ne peut pas être représenté comme un BN_ULONG.

BN_one() et BN_set_word() retournent 1 en cas de succès, 0 sinon. BN_value_one() retourne la constante.

VOIR AUSSI

BN_bn2bin(3), BN_new(3), BN_set_bit(3), BN_set_negative(3)

HISTORIQUE

BN_zero(), BN_one(), BN_value_one(), et BN_set_word() sont apparues pour la première fois dans SSLeay 0.5.1. BN_get_word() est apparue pour la première fois dans SSLeay 0.6.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BOGUES

Quelqu'un pourrait modifier la constante.

Si la valeur d'un BIGNUM est égale à un BN_ULONG avec tous les bits à 1, la valeur de retour de BN_get_word() entre en collision avec la valeur de retour utilisée pour indiquer les erreurs.

BN_ULONG devrait probablement être un `typedef` plutôt qu'une macro.
