BIO_s_mem, BIO_set_mem_eof_return, BIO_get_mem_data, BIO_set_mem_buf, BIO_get_mem_ptr, BIO_new_mem_buf — BIO de mémoire

SYNTAXE

const BIO_METHOD *
BIO_s_mem(void);

long

long

long

long
BIO_get_mem_ptr(BIO *b, BUF_MEM **pp);

BIO *
BIO_new_mem_buf(const void *buf, int len);

DESCRIPTION

BIO_s_mem() renvoie la fonction de méthode BIO de mémoire.

Un BIO de mémoire est un BIO source/destination qui utilise la mémoire pour ses entrées/sorties. Les données écrites dans un BIO de mémoire sont stockées dans une structure BUF_MEM qui est étendue comme nécessaire pour contenir les données stockées.

Toutes les données écrites dans un BIO de mémoire peuvent être récupérées en le lisant. Sauf si le BIO de mémoire est en lecture seule, les données lues sont supprimées du BIO. Pour savoir si un BIO de mémoire est en lecture seule, on peut appeler BIO_test_flags(3) avec l'argument BIO_FLAGS_MEM_RDONLY.

Les BIO de mémoire prennent en charge BIO_gets(3) et BIO_puts(3).

Si le drapeau BIO_CLOSE est défini lors de la libération d'un BIO de mémoire, la structure BUF_MEM sous-jacente est également libérée.

L'appel à BIO_reset(3) sur un BIO de mémoire en lecture/écriture efface toutes les données qu'il contient. Sur un BIO en lecture seule, il restaure le BIO à son état initial et les données en lecture seule peuvent être relues.

BIO_eof(3) renvoie vrai s'il n'y a pas de données dans le BIO.

BIO_ctrl_pending(3) renvoie le nombre d'octets actuellement stockés.

BIO_set_mem_eof_return() définit le comportement du BIO de mémoire b lorsqu'il est vide. Si v est zéro, alors un BIO de mémoire vide renverra EOF : il renverra zéro et BIO_should_retry() sera faux. Si v est non nul, il renverra v lorsqu'il est vide et il définira le drapeau de nouvelle tentative de lecture : BIO_read_retry() sera vrai. Pour éviter toute ambiguïté avec une valeur de retour positive normale, v doit être défini sur une valeur négative, typiquement -1.

BIO_get_mem_data() définit *pp sur un pointeur vers le début des données du BIO de mémoire et renvoie la quantité totale de données disponibles.

BIO_set_mem_buf() définit la structure BUF_MEM interne sur bm et définit le drapeau de fermeture sur c. C'est-à-dire que c doit être soit BIO_CLOSE, soit BIO_NOCLOSE.

BIO_get_mem_ptr() place la structure BUF_MEM sous-jacente dans *pp.

BIO_new_mem_buf() crée un BIO de mémoire en utilisant len octets de données à buf. Si len est -1, alors buf est supposé se terminer par un caractère nul et sa longueur est déterminée par strlen(3). Le BIO est défini en lecture seule et ne peut donc pas être écrit. Ceci est utile lorsque des données doivent être rendues disponibles à partir d'une zone mémoire statique sous forme de BIO. Les données fournies sont lues directement depuis le tampon fourni : elles ne sont pas copiées au préalable, de sorte que la zone mémoire fournie doit rester inchangée jusqu'à ce que le BIO soit libéré.

Les écritures dans les BIO de mémoire réussiront toujours si de la mémoire est disponible : leur taille peut croître indéfiniment.

VALEURS DE RETOUR

BIO_s_mem() renvoie un pointeur vers un objet statique.

Lorsqu'il est appelé sur un objet BIO de mémoire, BIO_method_type(3) renvoie la constante BIO_TYPE_MEM et BIO_method_name(3) renvoie un pointeur vers la chaîne statique « memory buffer ».

BIO_set_mem_eof_return(), BIO_get_mem_data(), BIO_set_mem_buf(), et BIO_get_mem_ptr() renvoient 1 en cas de succès ou une valeur inférieure ou égale à 0 en cas d'erreur.

BIO_new_mem_buf() renvoie un objet BIO nouvellement alloué en cas de succès ou NULL en cas d'erreur.

libressl(3) — BIO_s_mem

NAME

BIO_s_mem, BIO_new_mem_buf, BIO_set_mem_buf, BIO_get_mem_ptr, BIO_set_mem_eof_return, BIO_get_mem_data — memory BIO

SYNOPSIS

#include <openssl/bio.h>

BIO *BIO_new_mem_buf(const void *buf, int len);
BIO *BIO_new(BIO_METHOD *type);
int BIO_set_mem_buf(BIO *b, const char *buf, int len);
int BIO_set_mem_eof_return(BIO *b, int eof);
int BIO_get_mem_ptr(BIO *b, char **p);
int BIO_get_mem_data(BIO *b, char **pp, int *length);
void BIO_set_close(BIO *b, int mode);

DESCRIPTION

The memory BIO is a BIO which reads from and writes to an internal memory buffer. It is useful for testing and for passing data between different parts of an application without involving actual I/O.

BIO_new(BIO_s_mem()) creates a new memory BIO. This BIO is initially empty and can be written to. When data is written to it, it grows dynamically. It can be read from after data has been written to it, or it can be pre-filled with data.

BIO_new_mem_buf() creates a new memory BIO which is initialized with the data in buf. The parameter len is the length of the data. If len is negative, the length is computed using strlen(). The data in buf is copied into the memory BIO, so the caller may free up the original buffer buf after this call.

BIO_set_mem_buf() takes an existing BIO b and sets its internal buffer to buf with length len. If len is negative, the length is computed using strlen(). The existing contents of the BIO are discarded. The data in buf is *not* copied, and the caller must ensure that the buffer remains valid as long as the BIO is in use. The BIO is set to be readable but not writable.

BIO_set_mem_eof_return() sets the value returned by a memory BIO when it reaches the end of its data. The default value is 0, meaning that reads will return 0 indefinitely once EOF is reached. If set to EOF (i.e., -1), reads will return -1 once EOF is reached.

BIO_get_mem_ptr() retrieves the internal BUF_MEM structure of a memory BIO. The address of the pointer to the structure is passed in p. It is crucial that BIO_set_close(b, BIO_NOCLOSE) is called before BIO_free(b) to prevent the BIO from freeing the buffer when the BIO itself is freed.

BIO_get_mem_data() retrieves the internal buffer pointer and its length. The pointer is stored in pp and the length is stored in length. Similar to BIO_get_mem_ptr(), care must be taken to manage the lifetime of the buffer.

BIO_set_close() controls whether the BIO should free the underlying buffer when BIO_free() is called. The mode can be BIO_CLOSE (the default) or BIO_NOCLOSE.

RETURN VALUES

BIO_new_mem_buf(), BIO_new() and BIO_set_mem_buf() return a pointer to the created or modified BIO object, or NULL on failure.

BIO_set_mem_eof_return() returns 1 on success, 0 on failure.

BIO_get_mem_ptr() returns 1 on success, 0 on failure.

BIO_get_mem_data() returns the current number of bytes available in the buffer on success, or -1 on error.

EXAMPLES

Create a writable memory BIO and write some data to it:

BIO *mem = BIO_new(BIO_s_mem());
BIO_puts(mem, "Hello World\n");

Create a read only memory BIO:

char data[] = "Hello World";
BIO *mem;
mem = BIO_new_mem_buf(data, -1);

Extract the BUF_MEM structure from a memory BIO and then free up the BIO:

BUF_MEM *bptr;
BIO_get_mem_ptr(mem, &bptr);
/* Make sure BIO_free() leaves BUF_MEM alone. */
BIO_set_close(mem, BIO_NOCLOSE);
BIO_free(mem);

HISTORY

BIO_s_mem() first appeared in SSLeay 0.6.0. BIO_set_mem_buf() and BIO_get_mem_ptr() first appeared in SSLeay 0.6.5. These functions have been available since OpenBSD 2.4.

BIO_set_mem_eof_return() and BIO_get_mem_data() first appeared in SSLeay 0.9.1 and have been available since OpenBSD 2.6.

BIO_new_mem_buf() first appeared in OpenSSL 0.9.5 and has been available since OpenBSD 2.7.

CAVEATS

Do not manually switch a writable memory BIO to read-only mode: calling BIO_set_flags(3) with an argument of BIO_FLAGS_MEM_RDONLY will ultimately result in a memory leak when the BIO object is finally handed to BIO_free(3). It might also cause security issues because it prevents BIO_reset(3) from clearing the data.

BUGS

There should be an option to set the maximum size of a memory BIO.

There should be a way to "rewind" a read/write BIO without destroying its contents.
