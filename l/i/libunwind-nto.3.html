NOM

libunwind-nto -- Support QNX Neutrino dans libunwind

SYNTAXE

#include <libunwind-nto.h>

unw_accessors_t unw_nto_accessors;

void *unw_nto_create(pid_t, pthread_t);
void unw_nto_destroy(void *);

int unw_nto_find_proc_info(unw_addr_space_t, unw_word_t, unw_proc_info_t *, int, void *);
void unw_nto_put_unwind_info(unw_addr_space_t, unw_proc_info_t *, void *);
int unw_nto_get_dyn_info_list_addr(unw_addr_space_t, unw_word_t *, void *);
int unw_nto_access_mem(unw_addr_space_t, unw_word_t, unw_word_t *, int, void *);
int unw_nto_access_reg(unw_addr_space_t, unw_regnum_t, unw_word_t *, int, void *);
int unw_nto_access_fpreg(unw_addr_space_t, unw_regnum_t, unw_fpreg_t *, int, void *);
int unw_nto_get_proc_name(unw_addr_space_t, unw_word_t, char *, size_t, unw_word_t *, void *);
int unw_nto_resume(unw_addr_space_t, unw_cursor_t *, void *);

DESCRIPTION

Le système d'exploitation QNX permet à un processus d'accéder à l'état de la machine et à la mémoire virtuelle d'un autre processus, ou d'un autre fil d'exécution au sein du même processus. Il est possible de connecter libunwind à un autre processus. Bien que ce ne soit pas très difficile à faire directement, libunwind facilite davantage cette tâche en fournissant des rappels prêts à l'emploi à cet effet. Les routines et variables qui implémentent cette fonctionnalité utilisent un préfixe de nom unw_nto, qui signifie « unwind-via-nto ».

Une application qui souhaite utiliser la fonctionnalité NTO distante de libunwind doit suivre les étapes suivantes.

1.
Créez un nouvel espace d'adressage libunwind qui représente le processus et le fil d'exécution cibles. Ceci est fait en appelant unw_create_addr_space(). Dans de nombreux cas, l'application voudra simplement passer l'adresse de unw_nto_accessors comme premier argument à cette routine. Cela garantira que libunwind pourra désenchevêtrer correctement le processus cible.
2.
Créez une structure d'informations NTO en appelant unw_nto_create(), en passant le pid et le tid du fil d'exécution cible comme arguments. Cela arrêtera le fil d'exécution cible. L'identifiant du processus (pid) de la cible doit être connu, et seul un seul fil d'exécution peut être désenchevêtré à la fois, donc l'identifiant du fil d'exécution (tid) doit également être spécifié.
3.
Le pointeur opaque retourné doit ensuite être passé comme argument « argument » (troisième argument) à unw_init_remote().

Lorsque l'application a terminé d'utiliser libunwind sur le processus cible, unw_nto_destroy() doit être appelée, en lui passant le pointeur opaque qui a été retourné par l'appel à unw_nto_create(). Cela garantit que toute la mémoire et les autres ressources sont libérées.

La fonction unw_nto_resume() n'est pas prise en charge sur la cible NTO distante.

Dans des circonstances spéciales, une application peut préférer utiliser uniquement des portions de la fonctionnalité NTO distante de libunwind. Pour cette raison, les routines de rappel individuelles (unw_nto_find_proc_info(), unw_nto_put_unwind_info(), etc.) sont également disponibles pour une utilisation directe. Bien sûr, les adresses de ces routines pourraient également être récupérées à partir de unw_nto_accessors, mais cela empêcherait l'initialisation statique. De plus, lors de l'utilisation de unw_nto_accessors, toutes les routines de rappel seront liées dans l'application, même si elles ne sont jamais réellement appelées.

SURETÉ DES THREADS

La fonctionnalité NTO distante de libunwind suppose qu'une seule structure unw_nto-info n'est jamais partagée entre les threads du programme en cours de désenchevêtrement. Pour cette raison, aucun verrouillage explicite n'est utilisé. Tant qu'un seul thread utilise une structure d'informations NTO à un moment donné, cette fonctionnalité est sûre pour les threads.

VALEUR DE RETOUR

unw_nto_create() peut retourner NULL s'il échoue à créer la structure d'informations NTO pour une raison quelconque.

EXEMPLE

    #include <libunwind-nto.h>
    #include <stdio.h>
    #include <stdlib.h>
    int
    main (int argc, char **argv)
    {
      if (argc != 2) {
        fprintf (stderr, "usage: %s PID\n", argv[0]);
        exit (EXIT_FAILURE);
      }
      char *endptr;
      pid_t target_pid = strtoul (argv[1], &endptr, 10);
      if (target_pid == 0 && argv[1] == endptr) {
        fprintf (stderr, "usage: %s PID\n", argv[0]);
        exit (EXIT_FAILURE);
      }
      unw_addr_space_t as = unw_create_addr_space (&unw_nto_accessors, 0);
      if (!as) {
        fprintf (stderr, "unw_create_addr_space() failed");
        exit (EXIT_FAILURE);
      }
      void *ui = unw_nto_create (target_pid, (thread_t)1);
      if (!ui) {
        fprintf (stderr, "unw_nto_create() failed");
        exit (EXIT_FAILURE);
      }
      unw_cursor_t cursor;
      int ret = unw_init_remote (&cursor, as, ui);
      if (ret < 0) {
        fprintf (stderr, "unw_init_remote() failed: ret=%d\n", ret);
        exit (EXIT_FAILURE);
      }
      do {
        unw_proc_info_t pi;
        ret = unw_get_proc_info (&cursor, &pi);
        if (ret == -UNW_ENOINFO) {
          fprintf (stdout, "no info\n");
        } else if (ret >= 0) {
          printf ("\tproc=%#016lx-%#016lx\thandler=%#016lx lsda=%#016lx",
                  (long) pi.start_ip, (long) pi.end_ip,
                  (long) pi.handler, (long) pi.lsda);
        }
        ret = unw_step (&cursor);
      } while (ret > 0);
      if (ret < 0) {
        fprintf (stderr, "unwind failed with ret=%d\n", ret);
        exit (EXIT_FAILURE);
      }
      unw_nto_destroy (ui);
      unw_destroy_addr_space (as);
      exit (EXIT_SUCCESS);
    }
