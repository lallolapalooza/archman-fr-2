CMS_ADD1_SIGNER(3) Manuel des fonctions de bibliothèque CMS_ADD1_SIGNER(3)

NOM

CMS_add1_signer, CMS_SignerInfo_sign — ajouter un signataire à une structure SignedData de CMS

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/cms.h>

CMS_SignerInfo *
CMS_add1_signer(CMS_ContentInfo *cms, X509 *signcert, EVP_PKEY *pkey, const EVP_MD *md, unsigned int flags);

int
CMS_SignerInfo_sign(CMS_SignerInfo *si);

DESCRIPTION

CMS_add1_signer() ajoute un signataire avec le certificat signcert et la clé privée pkey en utilisant le digest de message md au champ signerInfos de la structure SignedData cms, qui aurait dû être obtenu à partir d'un appel initial à CMS_sign(3) avec le drapeau CMS_PARTIAL défini, ou qui peut être une structure SignedData valide dans le cas d'une signature multiple.

Si md est NULL, le digest par défaut pour l'algorithme de clé publique de pkey est utilisé.

Sauf si le drapeau CMS_REUSE_DIGEST est défini, la structure cms reste incomplète et doit être finalisée soit par streaming (si applicable), soit par un appel à CMS_final(3).

Le but principal de CMS_add1_signer() est de fournir un contrôle plus fin sur une structure SignedData de CMS où les paramètres par défaut de la fonction CMS_sign(3) plus simple ne sont pas appropriés, par exemple si plusieurs signataires ou des algorithmes de digest non par défaut sont nécessaires. De nouveaux attributs peuvent également être ajoutés en utilisant la structure CMS_SignerInfo retournée et les fonctions utilitaires d'attributs CMS ou les fonctions de demande de reçu signé CMS.

N'importe lequel des drapeaux suivants (combinés par OU) peut être passé dans le paramètre flags :

CMS_REUSE_DIGEST
Tenter de copier la valeur du digest de contenu d'une des structures CMS_SignerInfo existantes dans cms tout en ajoutant un autre signataire. Une erreur se produit si une valeur de digest correspondante ne peut pas être trouvée à copier. La structure cms sera valide et finalisée lorsque ce drapeau est défini.
CMS_PARTIAL
Si ce drapeau est défini en plus de CMS_REUSE_DIGEST, la structure CMS_SignerInfo retournée ne sera pas finalisée afin que des attributs supplémentaires puissent être ajoutés. Dans ce cas, un appel explicite à CMS_SignerInfo_sign() est nécessaire pour la finaliser.
CMS_NOCERTS
Ne pas ajouter le certificat du signataire au champ certificates de cms. Le certificat du signataire doit toujours être fourni dans le paramètre signcert. Ce drapeau peut réduire la taille de la signature si le certificat du signataire peut être obtenu par d'autres moyens, par exemple à partir d'un message précédemment signé.
CMS_NOATTR
Laisser le champ signedAttrs de la structure CMS_SignedData retournée vide. Par défaut, plusieurs SignedAttributes CMS sont ajoutés, y compris l'heure de signature, le type de contenu CMS, et la liste des algorithmes de chiffrement pris en charge dans un attribut SMIMECapabilities.
CMS_NOSMIMECAP
Omettre uniquement l'attribut SMIMECapabilities.
CMS_USE_KEYID
Utiliser la valeur de l'identifiant de clé du sujet pour identifier les certificats de signature. Une erreur se produit si le certificat de signature n'a pas d'extension d'identifiant de clé du sujet. Par défaut, le nom de l'émetteur et le numéro de série sont utilisés à la place.

Le cas échéant, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants par ordre de préférence : AES 256 bits, AES 192 bits, AES 128 bits, triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes n'est pas disponible, il ne sera pas inclus.

La fonction CMS_SignerInfo_sign() signe explicitement si. Son utilisation principale est lorsque les drapeaux CMS_REUSE_DIGEST et CMS_PARTIAL ont tous deux été définis dans l'appel à CMS_add1_signer() qui a créé si.

VALEURS DE RETOUR

CMS_add1_signer() retourne un pointeur interne vers la nouvelle structure CMS_SignerInfo qui vient d'être ajoutée ou NULL si une erreur se produit.

libressl-CMS_add1_signer.3

SYNOPSIS

#include <openssl/cms.h>

int CMS_add1_signer(CMS_ContentInfo *cms, X509 *cert, EVP_PKEY *key, const EVP_MD *digest, unsigned int flags);

DESCRIPTION

CMS_add1_signer adds a signer information to the CMS structure pointed to by cms.

The signer information will be identified by cert and key. The digest algorithm to be used is specified by digest. flags can be used to control signing behaviour.

RETURN VALUES

CMS_add1_signer returns 1 on success, 0 on failure.
