CRYPTO(3) Manuel des fonctions de bibliothèque CRYPTO(3)

NOM

crypto — Bibliothèque cryptographique OpenSSL

DESCRIPTION

La bibliothèque cryptographique OpenSSL implémente une large gamme d'algorithmes cryptographiques utilisés dans divers standards Internet. Les services fournis par cette bibliothèque sont utilisés par les implémentations OpenSSL de TLS et S/MIME, et ils ont également été utilisés pour implémenter SSH, OpenPGP, et d'autres standards cryptographiques.

Chiffrements symétriques comprenant AES, Blowfish, CAST, ChaCha20, IDEA, DES, RC2 et RC4 sont fournis par l'interface générique EVP_EncryptInit(3). Les interfaces autonomes de bas niveau incluent AES_encrypt(3), BF_set_key(3), ChaCha(3), DES_set_key(3), RC2_encrypt(3), et RC4(3).

Cryptographie à clé publique et accord de clé sont fournis par DH_new(3), ECDH_compute_key(3), X25519(3), DSA_new(3), ECDSA_SIG_new(3), RSA_new(3), et EVP_PKEY_new(3).

Certificats sont gérés par X509_new(3) et X509v3_add_ext(3).

Codes d'authentification et fonctions de hachage offerts incluent EVP_DigestInit(3), CMAC_Init(3), HMAC(3), MD4(3), MD5(3), RIPEMD160(3), SHA1(3), et SHA256(3).

Entrées, sorties et encodage de données installations incluent ASN1_TYPE_get(3), BIO_new(3), CMS_ContentInfo_new(3), evp(3), EVP_EncodeInit(3), PEM_read(3), PKCS7_encrypt(3), PKCS7_sign(3), PKCS12_create(3), et SMIME_write_PKCS7(3).

Fonctionnalités auxiliaires incluent :

  • gestion des fichiers de configuration : voir OPENSSL_config(3)
  • rapport d'erreurs : voir ERR(3)
  • OCSP_REQUEST_new(3)
  • UI_new(3)

Utilitaires internes incluent BIO_f_buffer(3), BN_new(3), EC_GROUP_new_by_curve_name(3), lh_new(3), et STACK_OF(3).

CONVENTIONS DE NOMMAGE

Les éléments utilisés dans les noms des fonctions API incluent les suivants :

add0
Voir « set0 » ci-dessous.
add1
Voir « set1 » ci-dessous.
BIO
abstraction basique d'entrée et/ou de sortie : La fonction manipule des objets du type d'objet idiosyncratique OpenSSL BIO. Voir BIO_new(3).
bio
La fonction utilise un objet BIO pour l'entrée ou la sortie. Dans de nombreux cas, des variantes plus simples de la fonction sont disponibles qui opèrent directement sur des objets FILE de <stdio.h> ou directement en RAM, utilisant généralement des tableaux d'octets.
BIO_f_
BIO de filtrage : La fonction renvoie un pointeur vers un objet statique intégré qui, lorsqu'il est passé à BIO_new(3), aboutit à la création d'un objet BIO capable de lire et/ou d'écrire des données à partir d'un autre objet BIO.
BIO_s_
BIO source et/ou puits : La fonction renvoie un pointeur vers un objet statique intégré qui, lorsqu'il est passé à BIO_new(3), aboutit à la création d'un objet BIO capable d'écrire des données vers une destination externe et/ou de lire des données à partir d'une source externe, par exemple un descripteur de fichier ou un objet, un tampon mémoire, ou le réseau.
BN
grand nombre : La fonction opère sur des objets BIGNUM représentant des nombres entiers de taille variable, presque illimitée. Voir BN_new(3).
cb
rappel (callback) : La fonction prend ou renvoie un pointeur de fonction qui est appelé par les fonctions API depuis l'intérieur de la bibliothèque. La fonction pointée peut être définie par le programme d'application. Dans certains cas, les fonctions API avec « cb » dans leur nom peuvent renvoyer des pointeurs de fonction vers des fonctions internes définies à l'intérieur de la bibliothèque qui ne sont pas des fonctions API. L'élément « cb » est également utilisé dans les noms de certains types de données de pointeurs de fonction déclarés avec typedef. Dans un petit nombre de cas, la forme tout en majuscules « CB » est utilisée avec le même sens.
CTX
contexte : La fonction opère sur un objet wrapper autour d'un autre objet. Les buts et propriétés de tels objets wrappers « CTX » varient considérablement en fonction des objets concernés. Quelques noms de fonctions utilisent la forme en minuscules « ctx » dans le même sens.
d2i
DER vers interne : La fonction décode une entrée conforme aux règles de codage basiques ASN.1 (BER) et stocke le résultat soit dans un objet existant, soit dans un objet nouvellement alloué. Ce dernier est généralement préférable car la création d'un nouvel objet est plus robuste et moins sujette aux erreurs. Malgré le nom, l'entrée n'a généralement pas besoin de se conformer aux règles de codage distinguées ASN.1 (DER), qui sont plus restrictives que BER.
EVP
bibliothèque EnVeloPpe numérique : Voir evp(3).
ex
Cet élément de nom est utilisé pour deux objectifs complètement sans rapport.

version étendue : La fonction est similaire à une fonction plus ancienne sans le « ex » dans son nom, mais prend un ou plusieurs arguments supplémentaires afin de la rendre plus polyvalente. Dans plusieurs cas, la version plus ancienne est maintenant dépréciée.

données supplémentaires : Certains types d'objets prennent en charge le stockage de données supplémentaires spécifiques à l'application à l'intérieur des objets en plus des données que l'objet est conçu pour contenir. La fonction définit, récupère ou prépare l'utilisation de telles données supplémentaires. Les noms de fonctions connexes contiennent généralement « ex_data » ou « ex_new_index ». Voir CRYPTO_set_ex_data(3).

fp
pointeur de fichier : La fonction prend un argument FILE *. Généralement, la fonction est une variante d'une autre fonction qui prend un argument BIO * à la place.
i2d
interne vers DER : La fonction code un objet passé comme argument selon les règles de codage distinguées ASN.1 (DER). Il existe quelques rares exceptions de fonctions qui ont « i2d » dans leur nom mais produisent néanmoins une sortie qui ne respecte que les règles de codage basiques ASN.1 (BER) et non DER.

libressl-crypto(3) — LibreSSL crypto API

NAME

libressl-crypto - LibreSSL crypto API

DESCRIPTION

This manual page describes naming conventions used in the LibreSSL crypto API.

NAMING CONVENTIONS

cb
callback: The function is a callback function. It is typically invoked by the library when a specific event occurs. The function is usually passed as a pointer to a function to a high-level API function. See also the “meth” entry in the present list.
cmp
compare: The function compares two objects. It returns a negative value if the first object is less than the second, zero if they are equal, and a positive value if the first object is greater than the second.
copy
The function copies an object. It returns a pointer to a newly allocated copy of the object. The caller is responsible for freeing the returned object when it is no longer needed.
dup
duplicate: The function duplicates an object. It returns a pointer to a newly allocated copy of the object. The caller is responsible for freeing the returned object when it is no longer needed.
free
The function frees an object. The object must have been allocated by a corresponding “new”, “alloc”, “copy”, or “dup” function. After calling the “free” function, the pointer to the object should be set to NULL.
get0
The function returns a pointer to a sub-object of an object passed as an argument. The returned pointer should not be freed by the calling code. It remains valid as long as the parent object is valid. Any attempt to free this pointer will lead to undefined behavior and likely memory corruption.
get1
The function returns a copy of a sub-object of an object passed as an argument. The caller is responsible for freeing the returned object when it is no longer needed.

If the object type is reference counted, usually the reference count is incremented instead of copying the object. Consequently, modifying the returned object may still impact all objects containing references to it. The caller is responsible for freeing the returned object when it is no longer needed; for reference-counted objects still referenced elsewhere, this will merely decrement the reference count.

get
Functions containing “get” in their name without a following digit may behave in “get0” or, more rarely, in “get1” style. To find out which is the case, refer to the individual manual pages.
lh
linear hash: The function manipulates a dynamic hash table. See lh_new(3).
md
message digest. Some function names use the all caps form “MD” in the same sense.
meth
The function manipulates an object holding a function table. Usually, such function tables allow the application program to implement additional cryptographic or I/O algorithms and to use them with the same high-level API functions as the algorithms provided by the library itself, or to replace the implementations of algorithms provided by the library with custom implementations provided by the application program. Some API functions use the name elements “method” or “METHOD” in the same sense. See also the “cb” entry in the present list.
nid
numerical identifier: A non-standard, LibreSSL-specific int number associated with an ASN.1 object identifier. In several cases, the all caps form “NID” is used in the same sense. See OBJ_nid2obj(3).
obj
This name element and its all caps form “OBJ” usually refer to ASN.1 object identifiers represented by the ASN1_OBJECT data type. See ASN1_OBJECT_new(3).
PKEY
In most cases, this name element and its lower case form “pkey” mean “private key”, but for both forms, there are some cases where they mean “public key” instead.
set0
The function transfers ownership of a pointer passed as an argument to an object passed as another argument, by storing the pointer inside the object. The transferred pointer must not be freed by the calling code. It will be freed automatically when the object now owning the pointer will be freed.
set1
The function copies the content of one object passed as an argument into another object also passed as an argument. When the calling code no longer needs the copied object, it can free that object.

In some cases, if the object to be copied is reference counted, the function does not actually copy the object but merely increments its reference count and stores the pointer to it in the other object. When the calling code no longer needs its original pointer to the now inner object, it can free the original pointer, thus decrementing the reference count of the inner object and transferring ownership of the inner object to the outer object. The inner object will then be freed automatically when the outer object is freed later on.

set
Functions containing “set” in their name without a following digit may behave in “set0” or, more rarely, in “set1” style. To find out which is the case, refer to the individual manual pages.
sk
stack: The function manipulates a variable-sized array of pointers in the idiosyncratic style described in OPENSSL_sk_new(3).
TS
X.509 time-stamp protocol: See TS_REQ_new(3).
up_ref
The function increments the reference count of the argument by one. Only a minority of object types support reference counting. For those that do, if the reference count is greater than one, the corresponding “free” function reverses the effect of one call to the “up_ref” function rather than freeing the object.
