link(2) Manuel des appels système link(2)

NOM

link, linkat - créer un nouveau nom pour un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int link(const char *oldpath, const char *newpath);
#include <fcntl.h>           /* Définition des constantes AT_* */
#include <unistd.h>
int linkat(int olddirfd, const char *oldpath,
           int newdirfd, const char *newpath, int flags);
Conditions de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

linkat():

    Depuis glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Avant glibc 2.10:
        _ATFILE_SOURCE

DESCRIPTION

link() crée un nouveau lien (également appelé lien physique) vers un fichier existant.

Si newpath existe, il ne sera pas écrasé.

Ce nouveau nom peut être utilisé exactement comme l'ancien pour toute opération ; les deux noms font référence au même fichier (et ont donc les mêmes permissions et propriété) et il est impossible de dire quel nom était l'"original".

linkat()

L'appel système linkat() fonctionne exactement de la même manière que link(), à l'exception des différences décrites ici.

Si le chemin donné dans oldpath est relatif, alors il est interprété par rapport au répertoire référencé par le descripteur de fichier olddirfd (plutôt que par rapport au répertoire de travail actuel du processus appelant, comme le fait link() pour un chemin relatif).

Si oldpath est relatif et olddirfd est la valeur spéciale AT_FDCWD, alors oldpath est interprété par rapport au répertoire de travail actuel du processus appelant (comme link()).

Si oldpath est absolu, alors olddirfd est ignoré.

L'interprétation de newpath est la même que pour oldpath, sauf qu'un chemin relatif est interprété par rapport au répertoire référencé par le descripteur de fichier newdirfd.

Les valeurs suivantes peuvent être combinées par OR bit à bit dans flags:

AT_EMPTY_PATH (depuis Linux 2.6.39)
Si oldpath est une chaîne vide, crée un lien vers le fichier référencé par olddirfd (qui a pu être obtenu en utilisant l'option open(2) O_PATH). Dans ce cas, olddirfd peut faire référence à n'importe quel type de fichier sauf un répertoire. Cela ne fonctionnera généralement pas si le fichier a un compte de liens de zéro (les fichiers créés avec O_TMPFILE et sans O_EXCL font exception). L'appelant doit avoir la capacité CAP_DAC_READ_SEARCH pour utiliser cette option. Cette option est spécifique à Linux ; définissez _GNU_SOURCE pour obtenir sa définition.
AT_SYMLINK_FOLLOW (depuis Linux 2.6.18)
Par défaut, linkat() ne déréférence pas oldpath s'il s'agit d'un lien symbolique (comme link()). L'option AT_SYMLINK_FOLLOW peut être spécifiée dans flags pour provoquer le déréférencement de oldpath s'il s'agit d'un lien symbolique. Si procfs est monté, cela peut être utilisé comme alternative à AT_EMPTY_PATH, comme ceci :

linkat(AT_FDCWD, "/proc/self/fd/<fd>", newdirfd,
       newname, AT_SYMLINK_FOLLOW);

Avant Linux 2.6.18, l'argument flags n'était pas utilisé et devait être spécifié comme 0.

Voir openat(2) pour une explication de la nécessité de linkat().

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
L'accès en écriture au répertoire contenant newpath est refusé, ou le permis de recherche est refusé pour l'un des répertoires du préfixe de chemin de oldpath ou newpath. (Voir aussi path_resolution(7).)
EDQUOT
Le quota de blocs disque de l'utilisateur sur le système de fichiers est épuisé.
EEXIST
newpath existe déjà.
EFAULT
oldpath ou newpath pointe en dehors de votre espace d'adressage accessible.
EIO
Une erreur d'E/S s'est produite.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de oldpath ou newpath.
EMLINK
Le fichier référencé par oldpath a déjà le nombre maximum de liens qui lui sont associés. Par exemple, sur un système de fichiers ext4(5) qui n'utilise pas la fonctionnalité dir_index, la limite du nombre de liens physiques vers un fichier est de 65 000 ; sur btrfs(5), la limite est de 65 535 liens.
ENAMETOOLONG
oldpath ou newpath était trop long.
ENOENT
Un composant de répertoire dans oldpath ou newpath n'existe pas ou est un lien symbolique pendant.
ENOMEM
Mémoire noyau insuffisante disponible.
ENOSPC
Le périphérique contenant le fichier n'a pas de place pour la nouvelle entrée de répertoire.
ENOTDIR
Un composant utilisé comme répertoire dans oldpath ou newpath n'est pas, en fait, un répertoire.
EPERM
oldpath est un répertoire.
EPERM
Le système de fichiers contenant oldpath et newpath ne prend pas en charge la création de liens physiques.
EPERM (depuis Linux 3.6)
L'appelant n'a pas la permission de créer un lien physique vers ce fichier (voir la description de /proc/sys/fs/protected_hardlinks dans proc_sys_fs(5)).
EPERM
oldpath est marqué comme immuable ou append-only. (Voir FS_IOC_SETFLAGS(2const).)
EROFS
Le fichier se trouve sur un système de fichiers en lecture seule.
EXDEV
oldpath et newpath ne sont pas sur le même système de fichiers monté. (Linux permet à un système de fichiers d'être monté à plusieurs endroits, mais link() ne fonctionne pas entre différents montages, même si le même système de fichiers est monté sur les deux.)

Les erreurs supplémentaires suivantes peuvent survenir pour linkat():

EBADF
oldpath (newpath) est relatif mais olddirfd (newdirfd) n'est ni AT_FDCWD ni un descripteur de fichier valide.
EINVAL
Une valeur d'option invalide a été spécifiée dans flags.
ENOENT
AT_EMPTY_PATH a été spécifié dans flags, mais l'appelant n'avait pas la capacité CAP_DAC_READ_SEARCH.
ENOENT
Une tentative a été faite

ERRORS

EACCES
A component of either path prefix of oldpath or newpath denies search permission; or, either oldpath or newpath is within a directory that denies write permissions; or, a required directory for oldpath or newpath does not allow search permission.
EEXIST
newpath already exists. The link created by link() is a hard link. A hard link cannot be created for a file that already exists. See also the description of the O_CREAT flag for open(2).
EINVAL
The flags argument contained a value other than AT_SYMLINK_NOFOLLOW or AT_EMPTY_PATH.
EISDIR
newpath refers to a directory.
ELOOP
Too many symbolic links were encountered while resolving oldpath or newpath.
EMLINK
The directory containing the link has reached the maximum number of hard links.
EMLINK

open(path, O_TMPFILE | O_EXCL, mode);

See open(2).
ENOENT
An attempt was made to link to a /proc/self/fd/NN file corresponding to a file that has been deleted.
ENOENT
oldpath is a relative pathname and olddirfd refers to a directory that has been deleted, or newpath is a relative pathname and newdirfd refers to a directory that has been deleted.
ENOTDIR
oldpath is relative and olddirfd is a file descriptor referring to a file other than a directory; or similar for newpath and newdirfd
EPERM
AT_EMPTY_PATH was specified in flags, oldpath is an empty string, and olddirfd refers to a directory.

VERSIONS

POSIX.1-2001 says that link() should dereference oldpath if it is a symbolic link. However, since Linux 2.0, Linux does not do so: if oldpath is a symbolic link, then newpath is created as a (hard) link to the same symbolic link file (i.e., newpath becomes a symbolic link to the same file that oldpath refers to). Some other implementations behave in the same manner as Linux. POSIX.1-2008 changes the specification of link(), making it implementation-dependent whether or not oldpath is dereferenced if it is a symbolic link. For precise control over the treatment of symbolic links when creating a link, use linkat().

glibc

On older kernels where linkat() is unavailable, the glibc wrapper function falls back to the use of link(), unless the AT_SYMLINK_FOLLOW is specified. When oldpath and newpath are relative pathnames, glibc constructs pathnames based on the symbolic links in /proc/self/fd that correspond to the olddirfd and newdirfd arguments.

STANDARDS

POSIX.1-2024.

HISTORY

link()
SVr4, 4.3BSD, POSIX.1-2001 (but see VERSIONS).
linkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

NOTES

Hard links, as created by link(), cannot span filesystems. Use symlink(2) if this is required.

BUGS

On NFS filesystems, the return code may be wrong in case the NFS server performs the link creation and dies before it can say so. Use stat(2) to find out if the link got created.
