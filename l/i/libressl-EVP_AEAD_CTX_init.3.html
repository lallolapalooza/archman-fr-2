DESCRIPTION

AEAD (Authenticated Encryption with Additional Data) couple la confidentialité et l'intégrité en une seule primitive. Les algorithmes AEAD prennent une clé et peuvent ensuite sceller et ouvrir des messages individuels. Chaque message a un nonce unique par message et, optionnellement, des données supplémentaires qui sont authentifiées mais non incluses dans la sortie.

EVP_AEAD_CTX_new() alloue un nouveau contexte à utiliser avec EVP_AEAD_CTX_init(). Il peut être nettoyé pour une réutilisation avec EVP_AEAD_CTX_cleanup() et doit être libéré avec EVP_AEAD_CTX_free().

EVP_AEAD_CTX_free() nettoie ctx et libère l'espace qui lui était alloué.

EVP_AEAD_CTX_init() initialise le contexte ctx pour l'algorithme AEAD donné aead. L'argument engine doit être NULL pour l'implémentation par défaut ; les autres valeurs ne sont pas prises en charge. Les tags d'authentification peuvent être tronqués en passant une longueur de tag. Un argument tag_len de EVP_AEAD_DEFAULT_TAG_LENGTH, qui a la valeur 0, entraîne l'utilisation de la longueur de tag par défaut.

EVP_AEAD_CTX_cleanup() libère toutes les données allouées pour le contexte ctx. Après EVP_AEAD_CTX_cleanup(), ctx est dans le même état qu'après EVP_AEAD_CTX_new().

EVP_AEAD_CTX_open() authentifie l'entrée in et les données supplémentaires optionnelles ad, déchiffre l'entrée et l'écrit comme sortie out. Cette fonction peut être appelée (avec le même EVP_AEAD_CTX) concurremment avec elle-même ou avec EVP_AEAD_CTX_seal(). Au plus le nombre d'octets d'entrée est écrit en sortie. Pour garantir le succès, max_out_len doit être au moins égal à la longueur d'entrée in_len. En cas de retour réussi, out_len est défini sur le nombre réel d'octets écrits. La longueur du nonce spécifié avec nonce_len doit être égale au résultat de EVP_AEAD_nonce_length pour cet AEAD. EVP_AEAD_CTX_open() ne produit jamais de sortie partielle. Si max_out_len est insuffisant, zéro sera retourné et out_len sera mis à zéro. Si l'entrée et la sortie sont aliasées, alors out doit être <= in.

EVP_AEAD_CTX_seal() chiffre et authentifie l'entrée, et authentifie toutes les données supplémentaires fournies dans ad, l'entrée chiffrée et le tag d'authentification étant écrits comme sortie out. Cette fonction peut être appelée (avec le même EVP_AEAD_CTX) concurremment avec elle-même ou avec EVP_AEAD_CTX_open(). Au plus max_out_len octets sont écrits en sortie et, afin d'assurer le succès, cette valeur doit être la in_len plus le résultat de EVP_AEAD_max_overhead(). En cas de retour réussi, out_len est défini sur le nombre réel d'octets écrits. La longueur du nonce spécifié avec nonce_len doit être égale au résultat de EVP_AEAD_nonce_length() pour cet AEAD. EVP_AEAD_CTX_seal() ne produit jamais de sortie partielle. Si max_out_len est insuffisant, zéro sera retourné et out_len sera mis à zéro. Si l'entrée et la sortie sont aliasées, alors out doit être <= in.

EVP_AEAD_key_length(), EVP_AEAD_max_overhead(), EVP_AEAD_max_tag_len(), et EVP_AEAD_nonce_length() fournissent des informations sur l'algorithme AEAD aead.

DESCRIPTION

The EVP_AEAD interface provides a unified way to access various authenticated encryption with associated data (AEAD) ciphers. AEAD ciphers are a class of symmetric key cryptographic algorithms that simultaneously provide both confidentiality and integrity of the data, and optionally authenticity of additional, unencrypted data.

The EVP_AEAD_CTX structure is a context for an AEAD cipher. It is created by EVP_AEAD_CTX_new() and initialized by EVP_AEAD_CTX_init(). It should be destroyed by EVP_AEAD_CTX_free().

The EVP_AEAD_CTX_init() function initializes the AEAD context pointed to by ctx using the AEAD algorithm specified by aead, the key material in key of length key_len, and the authentication tag length specified by tag_len. If tag_len is EVP_AEAD_DEFAULT_TAG_LENGTH, then the default tag length for the specified AEAD algorithm is used. The maximum value for tag_len is EVP_AEAD_MAX_TAG_LENGTH.

The parameter flags can be used to modify the behavior of the AEAD cipher. Currently, the only defined flag is EVP_AEAD_FLAG_CALL_CTRUBUG, which is used with the given aead. This is the largest value that can be passed as the tag_len argument to EVP_AEAD_CTX_init(). No built-in EVP_AEAD object has a maximum tag length larger than the constant EVP_AEAD_MAX_TAG_LENGTH.

All cipher algorithms have a fixed key length unless otherwise stated. The following ciphers are available:

EVP_aead_aes_128_gcm()
AES-128 in Galois Counter Mode, using a key_len of 16 bytes and a nonce_len of 12 bytes.
EVP_aead_aes_256_gcm()
AES-256 in Galois Counter Mode, using a key_len of 32 bytes and a nonce_len of 12 bytes.
EVP_aead_chacha20_poly1305()
ChaCha20 with a Poly1305 authenticator, using a key_len of 32 bytes and a nonce_len of 12 bytes. The constant EVP_CHACHAPOLY_TLS_TAG_LEN specifies the length of the authentication tag in bytes and has a value of 16.
EVP_aead_xchacha20_poly1305()
XChaCha20 with a Poly1305 authenticator, using a key_len of 32 bytes and a nonce_len of 24 bytes.

Unless compatibility with other implementations like OpenSSL or BoringSSL is required, using the EVP_AEAD interface to AEAD ciphers is recommended in preference to the functions documented in the EVP_EncryptInit(3), EVP_aes_256_gcm(3), and EVP_chacha20_poly1305(3) manual pages. The code then becomes transparent to the AEAD cipher used and much more flexible. It is also safer to use as it prevents common mistakes with the EVP APIs.

VALEURS DE RETOUR

EVP_AEAD_CTX_new() renvoie le nouvel objet EVP_AEAD_CTX en cas de succès; sinon, NULL est renvoyé et errno est défini sur ENOMEM.

EVP_AEAD_CTX_init(), EVP_AEAD_CTX_open(), et EVP_AEAD_CTX_seal() renvoient 1 en cas de succès ou zéro en cas d'échec.

EVP_AEAD_key_length() renvoie la longueur de la clé utilisée pour cet AEAD.

EVP_AEAD_max_overhead() renvoie le nombre maximal d'octets supplémentaires ajoutés par l'action de sceller des données avec l'AEAD.

EVP_AEAD_max_tag_len() renvoie la longueur maximale de la balise lors de l'utilisation de cet AEAD.

EVP_AEAD_nonce_length() renvoie la longueur du nonce par message.

EXEMPLES

Chiffrer une chaîne en utilisant ChaCha20-Poly1305 :

const EVP_AEAD *aead = EVP_aead_chacha20_poly1305();
static const unsigned char nonce[32] = {0};
size_t buf_len, nonce_len;
EVP_AEAD_CTX *ctx;

ctx = EVP_AEAD_CTX_new();
EVP_AEAD_CTX_init(ctx, aead, key32, EVP_AEAD_key_length(aead),
    EVP_AEAD_DEFAULT_TAG_LENGTH, NULL);
nonce_len = EVP_AEAD_nonce_length(aead);

EVP_AEAD_CTX_seal(ctx, out, &out_len, BUFSIZE, nonce,
    nonce_len, in, in_len, NULL, 0);

EVP_AEAD_CTX_free(ctx);

HISTORIQUE

AEAD est basé sur l'implémentation d'Adam Langley pour Chromium/BoringSSL et est apparu pour la première fois dans OpenBSD 5.6.

EVP_AEAD_CTX_new() et EVP_AEAD_CTX_free() sont apparus pour la première fois dans OpenBSD 7.1.

CAVEATS

Les publications et le code originaux d'Adam Langley utilisaient une construction AEAD modifiée qui est incompatible avec le style commun utilisé par AEAD dans TLS et incompatible avec RFC 7905 :

A. Langley et W. Chang, ChaCha20 and Poly1305 based Cipher Suites for TLS, draft-agl-tls-chacha20poly1305-04, novembre 2013.

Y. Nir et A. Langley, ChaCha20 and Poly1305 for IETF Protocols, RFC 8439, juin 2018.

En particulier, la version originale utilisait un nonce_len de 8 octets.
