libressl-CMS_get0_type(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

CMS_GET0_TYPE(3) Manuel des fonctions de bibliothèque CMS_GET0_TYPE(3)

NOM

CMS_get0_type, CMS_get_version, CMS_set1_eContentType, CMS_get0_eContentType, CMS_get0_content — obtention et définition des types et du contenu CMS

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/cms.h>

const ASN1_OBJECT *
CMS_get0_type(const CMS_ContentInfo *cms);

int
CMS_get_version(const CMS_ContentInfo *cms, long *version);

int
CMS_set1_eContentType(CMS_ContentInfo *cms, const ASN1_OBJECT *oid);

const ASN1_OBJECT *
CMS_get0_eContentType(CMS_ContentInfo *cms);

ASN1_OCTET_STRING **
CMS_get0_content(CMS_ContentInfo *cms);

DESCRIPTION

CMS_get0_type() renvoie le type de contenu de la structure ContentInfo cms. La valeur ASN1_OBJECT retournée peut être convertie en une valeur NID entière à l'aide de OBJ_obj2nid(3). Les types de contenu suivants sont identifiés par les NIDs suivants :

SignedData NID_pkcs7_signed
EnvelopedData NID_pkcs7_enveloped
DigestedData NID_pkcs7_digest
EncryptedData NID_pkcs7_encrypted
AuthenticatedData NID_id_smime_ct_authData
CompressedData NID_id_smime_ct_compressedData
données arbitraires NID_pkcs7_data

Les types SignedData, DigestedData, AuthenticatedData et CompressedData contiennent un champ encapContentInfo pour permettre l'intégration de contenu, et les types EnvelopedData et EncryptedData contiennent un champ encryptedContentInfo à cet effet. Le type du contenu intégré à stocker dans ce champ peut être défini avec la fonction CMS_set1_eContentType(), à appeler sur les structures cms retournées par des fonctions telles que CMS_sign(3) ou CMS_encrypt(3) avec le flag CMS_PARTIAL défini et avant que la structure ne soit finalisée ; sinon, les résultats sont indéfinis. CMS_set1_eContentType() copie le oid fourni, il doit donc être libéré après utilisation.

CMS_get_version() définit *version au numéro de version de syntaxe de la structure ContentInfo cms. La version est un nombre compris entre 0 et 5 et est définie pour tous les types de contenu ci-dessus, à l'exception des données arbitraires. Pour les données arbitraires et les types de contenu non pris en charge, CMS_get_version() échoue et le contenu de *version n'est pas spécifié.

CMS_get0_eContentType() renvoie le type du contenu intégré.

CMS_get0_content() renvoie un pointeur vers l'emplacement de stockage où le pointeur vers le contenu intégré est stocké. Cela signifie par exemple qu'après

ASN1_OCTET_STRING **pconf = CMS_get0_content(cms);

*pconf peut être NULL s'il n'y a pas de contenu intégré. Les applications peuvent accéder, modifier ou créer le contenu intégré dans une structure CMS_ContentInfo en utilisant cette fonction. Les applications n'auront généralement pas besoin de modifier le contenu intégré car il est normalement défini par des fonctions de niveau supérieur.

VALEURS DE RETOUR

CMS_get0_type() et CMS_get0_eContentType() renvoient des pointeurs internes vers des structures OBJECT IDENTIFIER.

CMS_get_version() renvoie 1 en cas de succès et 0 en cas d'échec.

CMS_get0_content() renvoie un pointeur interne vers l'emplacement de stockage où le pointeur vers le contenu intégré est stocké.

CMS_set1_eContentType() renvoie 1 en cas de succès ou 0 si une erreur s'est produite. L'erreur peut être obtenue à partir de ERR_get_error(3).

VOIR AUSSI

CMS_ContentInfo_new(3), d2i_CMS_ContentInfo(3), SMIME_read_CMS(3)

NORMES

RFC 5652 : Cryptographic Message Syntax

RFC 3274 : Compressed Data Content Type for Cryptographic Message Syntax (CMS)
