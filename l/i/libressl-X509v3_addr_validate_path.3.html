X509V3_ADDR_VALIDATE_PATH(3) Manuel des fonctions de bibliothèque X509V3_ADDR_VALIDATE_PATH(3)

NOM

X509v3_addr_validate_path, X509v3_addr_validate_resource_set, X509v3_asid_validate_path, X509v3_asid_validate_resource_set — Validation de chemin RFC 3779 pour la délégation d'adresses IP et de numéros AS

SYNOPSIS

bibliothèque «libcrypto»
#include <openssl/x509v3.h>

int
X509v3_addr_validate_path(X509_STORE_CTX *ctx);

int
X509v3_addr_validate_resource_set(STACK_OF(X509) *chain, IPAddrBlocks *addrblocks, int allow_inherit);

int
X509v3_asid_validate_path(X509_STORE_CTX *ctx);

int
X509v3_asid_validate_resource_set(STACK_OF(X509) *chain, ASIdentifiers *asid, int allow_inherit);

DESCRIPTION

Les deux extensions RFC 3779 nécessitent des vérifications supplémentaires lors de la validation du chemin de certification.

  1. L'ensemble initial de ressources d'adresses IP et de numéros AS autorisés est défini dans l'ancre de confiance, où l'héritage n'est pas autorisé.
  2. Un émetteur ne peut déléguer que des sous-ensembles de ressources présents dans ses extensions RFC 3779 ou des sous-ensembles de ressources héritées de son émetteur.
  3. Si une extension RFC 3779 est présente dans un certificat, le même type d'extension doit également être présent chez son émetteur.
  4. Toutes les extensions RFC 3779 apparaissant dans le chemin de validation doivent être sous forme canonique conformément à X509v3_addr_is_canonical(3) et X509v3_asid_is_canonical(3).

X509v3_addr_validate_path() et X509v3_asid_validate_path() sont appelés depuis X509_verify_cert(3) dans le cadre de la construction de la chaîne de vérification. Lors de la rencontre d'une erreur ou d'une violation des règles ci-dessus, error, error_depth, et current_cert sont définis sur ctx et la fonction de rappel de vérification est appelée avec ok défini à 0. X509_V_ERR_INVALID_EXTENSION indique une ressource non canonique, X509_V_ERR_UNNESTED_RESOURCE indique une violation des autres règles ci-dessus. Dans de rares circonstances, l'erreur peut être X509_V_ERR_UNSPECIFIED et pour les ressources d'adresses IP X509_V_ERR_OUT_OF_MEM est également possible.

X509v3_addr_validate_resource_set() valide les ressources dans addrblocks par rapport à un certificat spécifique chain. Après avoir vérifié que addrblocks est canonique, ses adresses IP sont vérifiées pour être couvertes dans le certificat à la profondeur 0, puis la chaîne est parcourue jusqu'à l'ancre de confiance jusqu'à ce qu'une erreur ou une violation des règles ci-dessus soit rencontrée. addrblocks est autorisé à utiliser l'héritage conformément à X509v3_addr_inherits(3) si et seulement si allow_inherit est non nul.

X509v3_asid_validate_resource_set() effectue des vérifications similaires à X509v3_addr_validate_resource_set() pour asid.

VALEURS DE RETOUR

Toutes ces fonctions retournent 1 en cas de validation réussie et 0 sinon.

Pour X509v3_addr_validate_path() et X509v3_asid_validate_path(), une chain non vide et une verify_cb doivent être présentes sur ctx, sinon elles échouent et définissent error sur ctx à X509_V_ERR_UNSPECIFIED. La verify_cb est appelée avec les codes d'erreur décrits ci-dessus lors de la plupart des erreurs rencontrées pendant la validation. Certaines extensions malformées peuvent entraîner une erreur qui ne peut pas être interceptée par la fonction de rappel. À l'exception d'une erreur d'allocation, aucun code d'erreur n'est défini sur la pile d'erreurs.

X509v3_addr_validate_resource_set() accepte un NULL addrblocks et X509v3_asid_validate_resource_set() accepte un NULL asid comme valide. Ils échouent si chain est NULL ou vide. Si allow_inherit est 0, addrblocks ou asid est vérifié pour l'héritage avec X509v3_addr_inherits(3) ou X509v3_asid_inherits(3). Les cas d'échec restants sont les mêmes que pour X509v3_addr_validate_path() et X509v3_asid_validate_path(). Ils ne peuvent pas et n'essaient pas de communiquer la cause de l'erreur à l'appelant.

libressl-X509v3_addr_validate_path.3

SYNOPSIS

#include <openssl/x509v3.h>

int X509_check_host(const char *name, const char *addr, size_t alen, unsigned int flags, X509_NAME *nm);

int X509_check_IP_ (const char *addr, const char *ip, size_t ip_len, unsigned int flags);

int X509_check_email(const char *email, const char *addr, size_t alen);

int X509_check_fpki_addr(const char *addr, const X509_VERIFY_PARAM *param);

int X509_check_fpki_host(const char *name, const char *addr, size_t alen, unsigned int flags, const X509_VERIFY_PARAM *param);

int X509v3_addr_validate_path(X509 *x, const char *addr, size_t alen);

DESCRIPTION

Ces fonctions sont utilisées pour valider la compatibilité d'une adresse réseau avec un certificat donné.

X509_check_host()
Vérifie si le nom de l'hôte spécifié par name correspond à l'adresse réseau addr. Les drapeaux flags peuvent modifier ce comportement. Si nm est non NULL, il est utilisé pour extraire les noms alternatifs du sujet du certificat.
X509_check_IP_ ()
Vérifie si l'adresse IP ip correspond à l'adresse réseau addr. Les drapeaux flags peuvent modifier ce comportement.
X509_check_email()
Vérifie si l'adresse e-mail spécifiée par email correspond à l'adresse réseau addr.
X509_check_fpki_addr()
Valide l'adresse réseau addr par rapport aux paramètres spécifiés dans param.
X509_check_fpki_host()
Vérifie si le nom de l'hôte spécifié par name correspond à l'adresse réseau addr, en utilisant les paramètres spécifiés dans param. Les drapeaux flags peuvent modifier ce comportement.
X509v3_addr_validate_path()
Valide le chemin de certification donné par x par rapport à l'adresse réseau addr.

RETURN VALUES

Ces fonctions retournent 1 en cas de succès, 0 en cas d'échec.

SEE ALSO

X509_check_host(3), X509_check_IP_(3), X509_check_email(3), X509_check_fpki_addr(3), X509_check_fpki_host(3), X509v3_addr_validate_path(3)

STANDARDS

Aucune norme spécifique.
