SYNTAXE

bibliothèque « libcrypto »
#include <openssl/ocsp.h>

OCSP_REQ_CTX *
OCSP_sendreq_new(BIO *io, const char *path, OCSP_REQUEST *req, int maxline);

int
OCSP_sendreq_nbio(OCSP_RESPONSE **presp, OCSP_REQ_CTX *rctx);

void
OCSP_REQ_CTX_free(OCSP_REQ_CTX *rctx);

int
OCSP_REQ_CTX_add1_header(OCSP_REQ_CTX *rctx, const char *name, const char *value);

int
OCSP_REQ_CTX_set1_req(OCSP_REQ_CTX *rctx, OCSP_REQUEST *req);

int
OCSP_parse_url(const char *url, char **phost, char **pport, char **ppath, int *pssl);

OCSP_RESPONSE *
OCSP_sendreq_bio(BIO *io, const char *path, OCSP_REQUEST *req);

DESCRIPTION

La fonction OCSP_sendreq_new() retourne une structure OCSP_REQ_CTX en utilisant le répondeur io, le chemin URI path, la requête OCSP req et avec une longueur maximale de ligne d'en-tête de réponse de maxline. Si maxline est zéro, une valeur par défaut de 4k est utilisée. La requête OCSP req peut être mise à NULL et fournie plus tard si nécessaire.

Les arguments de OCSP_sendreq_new() correspondent aux composants de l'URI. Par exemple, si l'URI du répondeur est http://ocsp.com/ocspreq, le BIO io doit être connecté à l'hôte ocsp.com sur le port 80 et path doit être défini sur « /ocspreq ».

OCSP_sendreq_nbio() effectue des E/S non bloquantes sur le contexte de requête OCSP rctx. Lorsque l'opération est terminée, elle retourne la réponse dans *presp. Si OCSP_sendreq_nbio() indique qu'une opération doit être retentée, le BIO correspondant peut être examiné pour déterminer quelle opération (lecture ou écriture) doit être retentée et une action appropriée peut être entreprise, par exemple un appel à select(2) sur le socket sous-jacent.

OCSP_REQ_CTX_free() libère le contexte OCSP rctx.

OCSP_REQ_CTX_add1_header() ajoute l'en-tête name avec la valeur value au contexte rctx. Les en-têtes ajoutés sont de la forme « name : value » ou simplement « name » si value est NULL. OCSP_REQ_CTX_add1_header() peut être appelé plus d'une fois pour ajouter plusieurs en-têtes. Il doit être appelé avant tout appel à OCSP_sendreq_nbio(). Le paramètre req dans l'appel initial à OCSP_sendreq_new() doit être défini sur NULL si des en-têtes supplémentaires sont définis.

OCSP_REQ_CTX_set1_req() définit la requête OCSP dans rctx à req. Cette fonction doit être appelée après tout appel à OCSP_REQ_CTX_add1_header().

OCSP_parse_url() est une fonction utilitaire pour analyser une url de la forme http[s]://hôte[:port][/chemin] et stocker des pointeurs vers des copies nouvellement allouées des chaînes hôte, port et chemin dans *phost, *pport et *ppath, respectivement. Par défaut, *ppath est défini sur « / » et *pport sur « 443 » pour https ou « 80 » pour http. Pour https, *pssl est défini sur 1 ; sinon, sur 0.

OCSP_sendreq_bio() effectue une requête OCSP en utilisant le répondeur io, le chemin URI path, la requête OCSP req. Il ne prend pas en charge les nouvelles tentatives et ne peut donc pas gérer efficacement les E/S non bloquantes. Il est conservé pour la compatibilité et son utilisation dans de nouvelles applications n'est pas recommandée.

VALEURS DE RETOUR

OCSP_sendreq_new() retourne une structure valide OCSP_REQ_CTX ou NULL si une erreur s'est produite.

OCSP_sendreq_nbio() retourne 1 si l'opération a été terminée avec succès, -1 si l'opération doit être retentée, ou 0 si une erreur s'est produite.

OCSP_REQ_CTX_add1_header(), OCSP_REQ_CTX_set1_req() et OCSP_parse_url() retournent 1 en cas de succès ou 0 en cas d'échec.

OCSP_sendreq_bio() retourne la structure OCSP_RESPONSE envoyée par le répondeur ou NULL si une erreur s'est produite.

EXEMPLES

Ajouter un en-tête Host pour ocsp.com:

OCSP_REQ_CTX_add1_header(ctx, Host, ocsp.com );

OCSP_sendreq_new(3)

NAME

OCSP_sendreq_new, OCSP_req_add1_cert, OCSP_req_add1_issuer, OCSP_request_sign, OCSP_sendreq_ctx, OCSP_sendreq_verify, OCSP_sendreq_free - OCSP request creation and sending

SYNOPSIS

OCSP_REQUEST *OCSP_sendreq_new(
    STACK_OF(X509) *chain,
    X509 *cert,
    X509 *issuer,
    int flags);
OCSP_REQUEST *OCSP_sendreq_new(
    STACK_OF(X509) *chain,
    X509 *cert,
    X509 *issuer,
    int flags);
int OCSP_req_add1_cert(
    OCSP_REQUEST *req,
    X509 *cert);
int OCSP_req_add1_issuer(
    OCSP_REQUEST *req,
    X509 *issuer);
int OCSP_request_sign(
    OCSP_REQUEST *req,
    X509 *signer_cert,
    EVP_PKEY *signer_key,
    STACK_OF(X509) *chain,
    unsigned long flags);
OCSP_RESPONSE *OCSP_sendreq_ctx(
    OCSP_REQ_CTX *ctx,
    const char *host,
    const char *port);
OCSP_RESPONSE *OCSP_sendreq_verify(
    OCSP_REQ_CTX *ctx,
    const char *host,
    const char *port);
void OCSP_sendreq_free(
    OCSP_REQ_CTX *ctx);

DESCRIPTION

These functions provide a high-level interface for creating and sending OCSP requests.

OCSP_sendreq_new() creates a new OCSP request object containing the certificate chain and issuer certificate specified.

OCSP_req_add1_cert() adds a certificate to be checked to the OCSP request.

OCSP_req_add1_issuer() adds the issuer certificate to the OCSP request.

OCSP_request_sign() signs the OCSP request using the provided signer certificate and key.

OCSP_sendreq_ctx() creates an OCSP request context, sends the request to the specified host and port, and returns the OCSP response.

OCSP_sendreq_verify() is similar to OCSP_sendreq_ctx(), but it also verifies the OCSP response signature.

OCSP_sendreq_free() frees the OCSP request context.

RETURN VALUES

See the relevant man pages for detailed return values.

HISTORY

CAVEATS

The OCSP_sendreq_new() function is a simplified interface and may not support all OCSP features. For more advanced features, an application should use an alternative, more complete, HTTP library.

Currently only HTTP POST queries to responders are supported.
