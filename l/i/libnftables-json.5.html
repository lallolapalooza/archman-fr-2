NOM

libnftables-json - Schéma JSON pris en charge par libnftables

SYNTAXE

{ "nftables": [ OBJETS ] }

OBJETS := LISTE_OBJETS | OBJETS_CMD

LISTE_OBJETS := OBJET_LISTE [ , LISTE_OBJETS ]

OBJETS_CMD := OBJET_CMD [ , OBJETS_CMD ]

OBJET_CMD := { CMD: OBJET_LISTE } | OBJET_METADATA

CMD := "add" | "replace" | "create" | "insert" | "delete" | "list" | "reset" | "flush" | "rename"

OBJET_LISTE := TABLE | CHAINE | REGLE | SET | MAP | ELEMENT | TABLE_FLUX | COMPTEUR | QUOTA | ASSISTANT_CT | LIMITE | OBJET_METADATA | TIMEOUT_CT | ATTENTE_CT

DESCRIPTION

libnftables prend en charge l'entrée et la sortie au format JSON. Ceci est implémenté comme une interface alternative au parseur de syntaxe CLI standard, par conséquent le comportement de base est identique et, pour (presque) toute opération disponible en syntaxe standard, il devrait y avoir un équivalent en JSON.

L'entrée JSON peut être fournie dans une seule chaîne en tant que paramètre de nft_run_cmd_from_buffer() ou dans un fichier identifié par le paramètre filename de la fonction nft_run_cmd_from_filename().

La sortie JSON doit être activée via la fonction nft_ctx_output_set_json(), transformant la sortie standard de la bibliothèque en format JSON. La sortie d'erreur reste inchangée.

STRUCTURE GLOBALE

En général, toute entrée ou sortie JSON est encapsulée dans un objet avec une seule propriété nommée nftables. Sa valeur est un tableau contenant des commandes (pour l'entrée) ou des éléments de règles (pour la sortie).

Une commande est un objet avec une seule propriété dont le nom identifie la commande. Sa valeur est un élément de règles - essentiellement identique aux éléments de sortie, à part certaines propriétés qui peuvent être interprétées différemment ou sont requises lorsque la sortie les omet généralement.

OBJET METADATA

En sortie, le premier objet d'un tableau nftables est un objet spécial contenant des informations sur la bibliothèque. Son contenu est le suivant :

{ "metainfo": {
        "version": CHAINE,
        "release_name": CHAINE,
        "json_schema_version": NOMBRE
}}

Les valeurs des propriétés version et release_name sont égales à la version du paquet et au nom de la version tels qu'affichés par nft -v. La valeur de la propriété json_schema_version est un entier indiquant la version du schéma.

Si elle est fournie dans l'entrée de la bibliothèque, le parseur vérifiera que la valeur json_schema_version ne dépasse pas celle codée en dur en interne (pour s'assurer que le schéma donné est entièrement compris). À l'avenir, un nombre inférieur à celui en interne pourra activer le mode de compatibilité pour analyser une entrée JSON obsolète et incompatible.

OBJETS COMMANDE

La structure accepte un nombre arbitraire de commandes qui sont interprétées dans l'ordre d'apparition. Par exemple, l'entrée en syntaxe standard suivante :

flush ruleset
add table inet mytable
add chain inet mytable mychain
add rule inet mytable mychain tcp dport 22 accept

se traduit en JSON comme suit :

{ "nftables": [
        { "flush": { "ruleset": null }},
        { "add": { "table": {
                        "family": "inet",
                        "name": "mytable"
        }}},
        { "add": { "chain": {
                        "family": "inet",
                        "table": "mytable",
                        "name": "mychain"
        }}},
        { "add": { "rule": {
                        "family": "inet",
                        "table": "mytable",
                        "chain": "mychain",
                        "expr": [
                                { "match": {
                                        "op": "==",
                                        "left": { "payload": {
                                                        "protocol": "tcp",
                                                        "field": "dport"
                                        }},
                                        "right": 22
                                }},
                                { "accept": null }
                        ]
        }}}
]}

AJOUTER

{ "add": OBJET_AJOUT }
OBJET_AJOUT := TABLE | CHAINE | REGLE | SET | MAP | ELEMENT |
                TABLE_FLUX | COMPTEUR | QUOTA | ASSISTANT_CT | LIMITE |
                TIMEOUT_CT | ATTENTE_CT

Ajoute un nouvel élément de règles au noyau.

REMPLACER

{ "replace": REGLE }

Remplace une règle. Dans REGLE, la propriété handle est obligatoire et identifie la règle à remplacer.

CRÉER

{ "create": OBJET_AJOUT }

Identique à la commande add, mais renvoie une erreur si l'objet existe déjà.

INSÉRER

{ "insert": REGLE }

Cette commande est identique à add pour les règles, mais au lieu d'ajouter la règle à la chaîne par défaut, elle l'insère à la première position. Si une propriété handle ou index est donnée, la règle est insérée avant la règle identifiée par ces propriétés.

SUPPRIMER

{ "delete": OBJET_AJOUT }

Supprime un objet de l'ensemble de règles. Seul le nombre minimal de propriétés requises pour identifier de manière unique un objet est généralement nécessaire dans OBJET_AJOUT. Pour la plupart des éléments de règles, il s'agit de family et table plus soit handle soit name (sauf pour les règles car elles n'ont pas de nom).

LISTER

{ "list": OBJET_LISTE }
OBJET_LISTE := TABLE | TABLES | CHAINE | CHAINES | SET | SETS |
                 MAP | MAPS | COMPTEUR | COMPTEURS | QUOTA | QUOTAS |
                 ASSISTANT_CT | ASSISTANTS_CT | LIMITE | LIMITES | RULESET |
                 METRE | METRES | TABLE_FLUX | TABLES_FLUX |
                 TIMEOUT_CT | ATTENTE_CT

Liste les éléments de l'ensemble de règles. Les formes plurielles sont utilisées pour lister tous les objets de ce type, éventuellement filtrés par family et pour certains, également par table.

RESETTER

{ "reset": OBJET_RESET }
OBJET_RESET := COMPTEUR | COMPTEURS | QUOTA | QUOTAS | REGLE | REGLES | SET | MAP | ELEMENT

Réinitialise l'état dans les objets appropriés, c'est-à-dire remet à zéro leur compteur interne.

VIDER

{ "flush": OBJET_VIDER }
OBJET_VIDER := TABLE | CHAINE | SET | MAP | METRE | REGLE

Supprime tous les éléments d'un objet spécifié.

RENOMMER

{ "rename": {
                OBJET_IDENTIFIABLE,
                "newname": STRING
        }}
OBJET_IDENTIFIABLE := TABLE | CHAIN | SET | MAP | METER

Renomme un objet existant. L'objet à renommer est identifié par ses propriétés habituelles (par exemple, family et name pour une table). La nouvelle valeur du nom est spécifiée dans la propriété newname.

OBJETS RÈGLES

Un objet règle est un objet JSON représentant une seule règle nftables. Il contient plusieurs propriétés qui définissent la règle, y compris le tableau d'expressions expr.

{
        "family": STRING,
        "table": STRING,
        "chain": STRING,
        "priority": STRING,
        "handle": NUMBER,
        "index": NUMBER,
        "stmt": STATEMENT,
        "expr": [ EXPRESSION [, EXPRESSION]... ]
}

Certaines propriétés peuvent être omises en fonction du contexte de la commande (par exemple, table et chain pour les tables, chaînes ou ensembles lors de leur suppression).

L'ordre des propriétés dans l'objet JSON n'a pas d'importance.

TABLE

Représente une table nftables.

{
        "family": STRING,
        "name": STRING,
        "handle": NUMBER
}

family : Le protocole de la table (par ex., "ip", "ip6", "inet", "arp", "bridge", "netdev", "ipoib").

name : Le nom de la table.

handle : Le numéro de handle de la table (généralement émis en sortie, peut être utilisé en entrée pour référencer la table dans d'autres objets).

CHAÎNE

Représente une chaîne nftables.

{
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "handle": NUMBER,
        "hook": STRING,
        "priority": PRIORITY_VALUE,
        "type": STRING,
        "policy": STRING
}

family, table, name : Identificateurs de la chaîne.

handle : Numéro de handle de la chaîne.

hook : Le point d'accroche du noyau où la chaîne est placée (par exemple, "prerouting", "input", "forward", "output", "postrouting").

priority : La priorité de la chaîne dans le hook. Peut être un entier ou une chaîne prédéfinie (par exemple, "filter", "nat", "mangle", "raw", "security", "connsecmark", " 0").

type : Le type de chaîne (par exemple, "filter", "nat", "route", "trap", " இணைப்பு", "queue").

policy : La politique par défaut de la chaîne (par exemple, "accept", "drop", "reject").

RÈGLE

Représente une règle nftables.

{
        "handle": NUMBER,
        "family": STRING,
        "table": STRING,
        "chain": STRING,
        "priority": PRIORITY_VALUE,
        "index": NUMBER,
        "expr": [ EXPRESSION [, EXPRESSION]... ]
}

handle : Handle de la règle (unique au sein d'une chaîne).

family, table, chain : Identificateurs de la chaîne parente.

priority : Priorité de la règle dans la chaîne (si elle est utilisée lors de l'ajout d'une nouvelle chaîne).

index : Index de la règle (peut être utilisé pour remplacer ou insérer une règle à un endroit spécifique).

expr : Un tableau d'expressions qui constituent la règle. La dernière expression est généralement l'action (par exemple, accept, drop, reject).

EXPRESSION

Une expression représente une opération ou une partie d'une règle. Les expressions peuvent être imbriquées.

EXPRESSION := MATCH_EXPR | ACTION_EXPR | META_EXPR | PAYLOAD_EXPR |
                ADDRESS_EXPR | NUMBER_EXPR | SET_EXPR | MAP_EXPR |
                FUNCTION_CALL | COUNTER_EXPR | QUOTA_EXPR | LIMIT_EXPR |
                CT_EXPR | CONNTRACK_HELPER_EXPR | NAT_EXPR |
                MISC_EXPR | LOG_EXPR

MATCH_EXPR

Une expression de correspondance.

{ "match": {
        "op": OPERATOR,
        "left": EXPRESSION_PART,
        "right": EXPRESSION_PART
}}

op : L'opérateur de comparaison (par exemple, "==", "!=", "<", ">", "<=", ">=", "in", "notin", "contains", "!contains", "startswith", "endswith", "=(mask)?").

left, right : Les opérandes de la comparaison. Peuvent être des adresses IP, des ports, des champs de charge utile, etc.

ACTION_EXPR

Une expression d'action.

{ "accept": null }
{ "drop": null }
{ "reject": { "type": STRING }}

reject : Peut avoir un type facultatif pour spécifier la façon dont le rejet doit être effectué (par exemple, "icmp-type", "tcp-reset").

META_EXPR

Une expression de métadonnées.

{ "meta": {
        "key": STRING,
        "op": OPERATOR,
        "value": VALUE
}}

key : La clé de métadonnées (par exemple, "mark", "length", "priority", "skuid", "skgid", "rtclass", "iif", "oif", "iifname", "oifname", "cgroup", "pkttype", "isfrag", "nfacct").

op, value : Comme pour MATCH_EXPR.

PAYLOAD_EXPR

Accède aux données de la charge utile.

{ "payload": {
        "protocol": STRING,
        "field": STRING,
        "offset": NUMBER,
        "len": NUMBER
}}

protocol : Le protocole de la couche (par exemple, "ip", "tcp", "udp", "icmp", "icmp6").

field : Le champ spécifique dans la charge utile (par exemple, "dport", "sport", "ttl", "tos", "id", "flags").

offset, len : OffSet et longueur facultatifs pour accéder à une partie spécifique du champ.

ADDRESS_EXPR

Représente des adresses IP ou des blocs CIDR.

{ "ip": STRING }
{ "ip": { "addr": STRING, "mask": STRING }}
{ "ip": { "addr": STRING, "len": NUMBER }}
{ "ip": { "addr": STRING, "from": STRING, "to": STRING }}

Peut représenter une seule adresse, un bloc CIDR, une plage d'adresses ou une plage avec un masque.

NUMBER_EXPR

Représente une valeur numérique, souvent utilisée pour les ports ou les identifiants.

{ "integer": NUMBER }
{ "port": NUMBER }

SET_EXPR

Fait référence à un ensemble (set) pour la correspondance.

{ "set": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "key": VALUE
}}

MAP_EXPR

Fait référence à une map pour la correspondance.

{ "map": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "key": VALUE
}}

FUNCTION_CALL

Appelle une fonction intégrée.

{ "function": {
        "name": STRING,
        "arguments": [ ARGUMENT [, ARGUMENT]... ]
}}

name : Le nom de la fonction (par exemple, "limit", "log", "counter", "meter").

arguments : Tableau d'arguments pour la fonction.

COUNTER_EXPR

Fait référence à un compteur.

{ "counter": {
        "name": STRING
}}

QUOTA_EXPR

Fait référence à un quota.

{ "quota": {
        "name": STRING
}}

LIMIT_EXPR

Fait référence à une limite.

{ "limit": {
        "name": STRING
}}

CT_EXPR

Fait référence à un état de suivi de connexion (conntrack).

{ "ct": {
        "key": STRING,
        "value": VALUE
}}

key : La clé de l'état conntrack (par exemple, "status", "state", "mark", "timeout", "expiration", "bytes", "packets", "zone").

value : La valeur à vérifier ou à définir.

CONNTRACK_HELPER_EXPR

Fait référence à un assistant conntrack.

{ "helper": {
        "name": STRING
}}

NAT_EXPR

Effectue une opération NAT.

{ "nat": {
        "type": STRING,
        "target": IP_OR_ADDRESS
}}

type : Le type de NAT (par exemple, "destination", "source").

target : L'adresse IP ou le bloc CIDR de destination/source.

MISC_EXPR

Expressions diverses.

{ "masquerade": null }
{ "redirect": { "to": PORT_OR_RANGE }}
{ "tunnel": { "key": STRING }}

LOG_EXPR

Journalise les paquets.

{ "log": {
        "prefix": STRING,
        "flags": NUMBER
}}

prefix : Un préfixe facultatif pour le message de journal.

flags : Indicateurs facultatifs pour le module de journalisation (par exemple, "log-ipv4-options", "log-ipv6-options", "log-common", "log-invalid").

SET

Représente un ensemble (set).

{
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "handle": NUMBER,
        "type": STRING,
        "flags": [ STRING ... ]
}

type : Le type d'éléments dans l'ensemble (par exemple, "ip", "ipv6", "ethernet", "integer", "string").

flags : Indicateurs facultatifs (par exemple, "atomic", "timeout").

ÉLÉMENT

Représente un élément dans un ensemble (set) ou une map.

{
        "set": SET_REFERENCE
        "map": MAP_REFERENCE
        "key": VALUE,
        "value": VALUE  (pour les maps)
}

set ou map : Référence à l'ensemble ou à la map.

key : La clé de l'élément.

value : La valeur associée (uniquement pour les maps).

MAP

Représente une map.

{
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "handle": NUMBER,
        "type": STRING,
        "flags": [ STRING ... ]
}

Similaire à SET, mais avec des paires clé-valeur.

TABLE_FLUX

Représente une table de flux.

{
        "family": STRING,
        "name": STRING,
        "handle": NUMBER,
        "hook": STRING,
        "priority": PRIORITY_VALUE,
        "type": STRING,
        "flavor": STRING,
        "timeout": NUMBER
}

flavor : Le type de table de flux (par exemple, "conntrack").

timeout : Temps d'attente en secondes.

COMPTEUR

Représente un compteur.

{
        "name": STRING,
        "packets": NUMBER,
        "bytes": NUMBER
}

QUOTA

Représente un quota.

{
        "name": STRING,
        "quota": NUMBER,
        "used": NUMBER
}

ASSISTANT_CT

Représente un assistant de suivi de connexion.

{
        "name": STRING
}

LIMITE

Représente une limite de débit.

{
        "name": STRING,
        "rate": NUMBER,
        "unit": STRING
}

rate : Le taux de la limite.

unit : L'unité du taux (par exemple, "second", "minute", "hour", "day").

TIMEOUT_CT

Définit les délais d'expiration du suivi de connexion.

{
        "family": STRING,
        "name": STRING,
        "timeout": NUMBER
}

ATTENTE_CT

Définit les attentes de suivi de connexion.

{
        "family": STRING,
        "name": STRING,
        "timeout": NUMBER,
        "count": NUMBER
}

ÉTIQUETTES ET CHAMPS

Les étiquettes et les champs sont utilisés dans diverses expressions pour identifier des parties spécifiques des paquets ou des états du noyau.

PRIORITY_VALUE

La valeur de priorité peut être un entier ou une chaîne prédéfinie.

PRIORITY_VALUE := NUMBER | STRING

Les chaînes prédéfinies courantes incluent :

        "filter"      (0)
        "nat"         (100)
        "mangle"      (200)
        "raw"         (300)
        "security"    (400)
        "connsecmark" (32767)
        "0"

OPERATOR

Les opérateurs utilisés dans les expressions de correspondance.

OPERATOR := "==" | "!=" | "<" | ">" | "<=" | ">=" | "in" |
              "notin" | "contains" | "!contains" | "startswith" |
              "endswith" | "=(mask)?"

VALUE

Une valeur peut être une chaîne, un nombre, une adresse IP, un bloc CIDR, une plage, un tableau, un objet ou null.

VALUE := STRING | NUMBER | IP_OR_ADDRESS | PORT_OR_RANGE | ARRAY | OBJECT | null

IP_OR_ADDRESS

Une adresse IP ou un bloc CIDR.

IP_OR_ADDRESS := STRING

Exemples : "192.168.1.1", "2001:db8::1", "192.168.1.0/24".

PORT_OR_RANGE

Un port unique ou une plage de ports.

PORT_OR_RANGE := NUMBER | STRING | JSON_OBJECT

Exemples : 80, "http", { "from": 1024, "to": 65535 }.

ARRAY

Un tableau JSON.

ARRAY := [ VALUE [, VALUE]... ]

OBJECT

Un objet JSON.

OBJECT := { STRING: VALUE [, STRING: VALUE]... }

EXEMPLES

Pour lister toutes les tables :

{ "nftables": [ { "list": { "tables": null }} ] }

Pour ajouter une table :

{ "nftables": [ { "add": { "table": { "family": "ip", "name": "test" }}} ] }

Pour ajouter une règle qui accepte le trafic TCP sur le port 22 :

{ "nftables": [ { "add": { "rule": {
                "family": "ip",
                "table": "filter",
                "chain": "input",
                "expr": [
                        { "match": {
                                "op": "==",
                                "left": { "payload": {
                                                "protocol": "tcp",
                                                "field": "dport"
                                }},
                                "right": { "port": 22 }
                        }},
                        { "accept": null }
                ]
}}} ] }

ELEMENTS DE REGLE

TABLE

{ "table": {
        "family": CHAÎNE,
        "name": CHAÎNE,
        "handle": NOMBRE,
        "flags": FLAGS_TABLE
}}
FLAGS_TABLE := FLAG_TABLE | [ LISTE_FLAGS_TABLE ]
LISTE_FLAGS_TABLE := FLAG_TABLE [, LISTE_FLAGS_TABLE ]
FLAG_TABLE := "dormant" | "owner" | "persist"

Cet objet décrit une table.

family

La famille de la table, par exemple "ip" ou "ip6".

name

Le nom de la table.

handle

Le handle de la table. En entrée, il est utilisé uniquement dans la commande delete comme alternative à name.

flags

Les drapeaux de la table.

CHAIN

{ "chain": {
        "family": CHAÎNE,
        "table": CHAÎNE,
        "name": CHAÎNE,
        "newname": CHAÎNE,
        "handle": NOMBRE,
        "type": CHAÎNE,
        "hook": CHAÎNE,
        "prio": NOMBRE,
        "dev": CHAÎNE,
        "policy": CHAÎNE
}}

Cet objet décrit une chaîne.

family

La famille de la table.

table

Le nom de la table.

name

Le nom de la chaîne.

handle

Le handle de la chaîne. En entrée, il est utilisé uniquement dans la commande delete comme alternative à name.

newname

Un nouveau nom pour la chaîne, pertinent uniquement dans la commande rename.

Les propriétés suivantes sont requises pour les chaînes de base :

type

Le type de la chaîne.

hook

Le point d'accroche (hook) de la chaîne.

prio

La priorité de la chaîne.

dev

L'interface liée à la chaîne (si elle appartient à la famille netdev).

policy

La politique de la chaîne.

RULE

{ "rule": {
        "family": CHAÎNE,
        "table": CHAÎNE,
        "chain": CHAÎNE,
        "expr": [ INSTRUCTIONS ],
        "handle": NOMBRE,
        "index": NOMBRE,
        "comment": CHAÎNE
}}
INSTRUCTIONS := INSTRUCTION [, INSTRUCTIONS ]

Cet objet décrit une règle. Les éléments de base des règles sont les instructions. Chaque règle en comprend au moins une.

family

La famille de la table.

table

Le nom de la table.

chain

Le nom de la chaîne.

expr

Un tableau d'instructions composant cette règle. En entrée, il est utilisé uniquement dans les commandes add/insert/replace.

handle

Le handle de la règle. Dans les commandes delete/replace, il sert d'identifiant de la règle à supprimer/remplacer. Dans les commandes add/insert, il sert d'identifiant d'une règle existante à laquelle la règle sera ajoutée/précédée.

index

La position de la règle pour les commandes add/insert. Il est utilisé comme alternative à handle dans ce cas.

comment

Commentaire optionnel de la règle.

SET / MAP

{ "set": {
        "family": CHAÎNE,
        "table": CHAÎNE,
        "name": CHAÎNE,
        "handle": NOMBRE,
        "type": TYPE_SET,
        "policy": POLITIQUE_SET,
        "flags": FLAGS_SET,
        "elem": ELEMENTS_SET,
        "timeout": NOMBRE,
        "gc-interval": NOMBRE,
        "size":  NOMBRE,
        "auto-merge": BOOLÉEN
}}
{ "map": {
        "family": CHAÎNE,
        "table": CHAÎNE,
        "name": CHAÎNE,
        "handle": NOMBRE,
        "type": TYPE_SET,
        "map": CHAÎNE,
        "policy": POLITIQUE_SET,
        "flags": FLAGS_SET,
        "elem": ELEMENTS_SET,
        "timeout": NOMBRE,
        "gc-interval": NOMBRE,
        "size": NOMBRE,
        "auto-merge": BOOLÉEN
}}
TYPE_SET := CHAÎNE | [ LISTE_TYPE_SET ] | { "typeof": EXPRESSION }
LISTE_TYPE_SET := CHAÎNE [, LISTE_TYPE_SET ]
POLITIQUE_SET := "performance" | "memory"
FLAGS_SET := FLAG_SET | [ LISTE_FLAGS_SET ]
LISTE_FLAGS_SET := FLAG_SET [, LISTE_FLAGS_SET ]
FLAG_SET := "constant" | "interval" | "timeout"
ELEMENTS_SET := EXPRESSION | [ LISTE_EXPRESSIONS ]
LISTE_EXPRESSIONS := EXPRESSION [, LISTE_EXPRESSIONS ]

Ces objets décrivent un ensemble (set) ou une table de correspondance (map) nommée. Les maps sont une forme spéciale d'ensembles qui traduisent une clé unique en une valeur.

family

La famille de la table.

table

Le nom de la table.

name

Le nom de l'ensemble.

handle

Un verdict termine soit le parcours du paquet dans la chaîne actuelle, soit le délègue à une autre.

Les instructions jump et goto attendent un nom de chaîne cible.

MATCH

{ "match": {
        "left": EXPRESSION,
        "right": EXPRESSION,
        "op": CHAÎNE
}}

Ceci compare l'expression de gauche (typiquement un en-tête de paquet ou des méta-informations du paquet) avec l'expression de droite (typiquement une valeur constante). Si l'instruction s'évalue à vrai, l'instruction suivante de cette règle est considérée. Sinon, le traitement continue avec la règle suivante dans la même chaîne.

left

Côté gauche de cette correspondance.
v>

right

Côté droit de cette correspondance.

op

Opérateur indiquant le type de comparaison.

OPERATORS

== Égal
!= Différent
< Plus petit que
> Plus grand que
⇐ Plus petit ou égal à
>= Plus grand ou égal à
in Effectuer une recherche, c'est-à-dire tester si les bits du côté droit sont contenus dans la valeur du côté gauche

Contrairement à l'API standard, l'opérateur est obligatoire ici. Dans l'API standard, un opérateur manquant peut être résolu de deux manières, en fonction du type d'expression du côté droit :

•Si le côté droit est un masque de bits ou une liste de masques de bits, l'expression se résout en une opération binaire avec l'opérateur d'inégalité, comme ceci : LHS & RHS != 0.
•Dans tous les autres cas, l'opérateur d'égalité est simplement inséré.

Pour le premier cas non trivial, l'API JSON prend en charge l'opérateur in.
