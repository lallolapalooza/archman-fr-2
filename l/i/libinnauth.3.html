NOM

libinnauth - Routines pour écrire des résolveurs et des authentificateurs nnrpd

SYNTAXE

#include "libinnauth.h"
struct res_info {
    struct sockaddr *client;
    struct sockaddr *local;
    char *clienthostname;
};
struct auth_info {
    char *username;
    char *password;
};
struct auth_info *get_auth_info(FILE *);
struct res_info  *get_res_info (FILE *);
void free_auth_info(struct auth_info*);
void free_res_info (struct res_info*);

DESCRIPTION

Ces fonctions fournissent une interface C pratique pour l'interface d'authentification externe de nnrpd documentée dans doc/external-auth. L'utilisation de cette bibliothèque n'est **pas** requise ; en particulier, les résolveurs et authentificateurs externes écrits dans des langages autres que C devront implémenter la fonctionnalité nécessaire eux-mêmes.

Les fonctions get_auth_info() et get_res_info() allouent suffisamment de mémoire pour une struct auth_info ou struct res_info et tous les champs nécessaires, et retournent un pointeur vers la structure avec les champs remplis à partir des informations fournies par nnrpd (le paramètre FILE* devrait généralement être "stdin"). Les deux fonctions retournent NULL en cas d'erreur. L'appelant est responsable de la désallocation de la mémoire en utilisant les fonctions ci-dessous.

Les champs de type chaîne des deux structures sont simples. Les champs client et local de struct res_info pointent en fait vers des instances de struct sockaddr_in (ou struct sockaddr_in6 si le support IPv6 est compilé).

Les fonctions free_auth_info() et free_res_info() libèrent la structure passée en argument et tous les champs nécessaires.

BOGUES

Dans de nombreux cas, nnrpd fournit plus d'informations que ce qui est normalement utile (par exemple, même lors de l'appel d'un authentificateur, les informations du résolveur sont souvent fournies.) D'un autre côté, dans certains cas, il fournit moins d'informations que ce qui pourrait être attendu (par exemple, si nnrpd lit à partir de stdin plutôt que d'une socket). L'implémentation est capable de gérer au moins le premier de ces problèmes, mais cette fonctionnalité n'est pas exposée dans l'interface.

Actuellement, libinnauth.h et son implémentation se trouvent dans authprogs/ ; ne devraient-ils pas être déplacés respectivement dans include/ et lib/ ?
