NOM

libpfm_intel_snbep_unc_cbo - support pour le PMU C-Box uncore d'Intel Sandy Bridge-EP

SYNOPSIS

#include <perfmon/pfmlib.h>

Nom du PMU : snbep_unc_cbo[0-7]
Desc. PMU : PMU uncore C-Box d'Intel Sandy Bridge-EP

DESCRIPTION

La bibliothèque prend en charge le PMU uncore C-Box (moteur de cohérence) d'Intel Sandy Bridge. Ce modèle de PMU n'existe que sur le modèle 45 de Sandy Bridge. Il y a un PMU C-Box par cœur physique. Par conséquent, il y a huit instances de PMU C-Box identiques numérotées de 0 à 7. Sur les systèmes à double socket, le numéro fait référence au PMU C-Box sur le socket où le programme s'exécute. Par exemple, si vous exécutez sur le CPU8, alors snbep_unc_cbo0 fait référence au C-Box pour le cœur physique 0 sur le socket 1. Inversement, si vous exécutez sur le CPU0, le même snbep_unc_cbo0 fait référence au C-Box pour le cœur physique 0 mais sur le socket 0.

Chaque PMU C-Box implémente 4 compteurs génériques et un registre de filtrage utilisé uniquement avec certains événements et masques de bits (umasks).

MODIFICATEURS

Les modificateurs suivants sont pris en charge sur le PMU uncore C-Box d'Intel Sandy Bridge:

i
Inverse la signification de l'événement. Le compteur comptera maintenant les cycles C-Box pendant lesquels l'événement ne se produit **pas**. C'est un modificateur booléen.
e
Active la détection de front, c'est-à-dire compte uniquement lorsqu'il y a une transition d'état de non-occurrence de l'événement à au moins une occurrence. Ce modificateur doit être combiné avec un modificateur de seuil (t) avec une valeur supérieure ou égale à un. C'est un modificateur booléen.
t
Définit la valeur de seuil. Lorsqu'il est défini sur une valeur non nulle, le compteur compte le nombre de cycles C-Box pendant lesquels le nombre d'occurrences de l'événement est supérieur ou égal au seuil. C'est un modificateur entier avec des valeurs dans la plage [0:255].
nf
Filtre de nœud. Certains événements, tels que UNC_C_LLC_LOOKUP, UNC_C_LLC_VICTIMS, fournissent un masque de bits NID. Parfois, le NID est combiné avec d'autres capacités de filtrage, telles que les opcodes. Le filtre de nœud est un masque de bits maximal de 8 bits. Un nœud correspond à un socket processeur. Les valeurs légales dépendent donc de la configuration matérielle sous-jacente. Pour les systèmes à double socket, le masque de bits a deux bits valides [0:1].
cf
Filtre de cœur. Il s'agit d'un filtre de 3 bits utilisé pour filtrer en fonction de l'origine du cœur physique de la requête C-Box. Les valeurs possibles sont 0-7. Si le filtre n'est pas spécifié, aucun filtrage n'a lieu.
tf
Filtre de thread. Il s'agit d'un filtre de 1 bit utilisé pour filtrer les requêtes C-Box en fonction de l'identification du processeur logique (hyper-thread). Les valeurs possibles sont 0-1. Si le filtre n'est pas spécifié, aucun filtrage n'a lieu.

Filtrage d'opcode

Certains événements, tels que UNC_C_TOR_INSERTS, prennent en charge la correspondance d'opcode sur le type de transaction C-BOX. Pour utiliser cette fonctionnalité, un masque de bits de correspondance d'opcode doit d'abord être sélectionné, par exemple, MISS_OPCODE. Ensuite, l'opcode sur lequel faire la correspondance doit être sélectionné via un second masque de bits parmi les masques de bits OPC_*. Par exemple, UNC_C_TOR_INSERTS:OPCODE:OPC_RFO, compte le nombre d'insertions de TOR pour les transactions RFO.

La correspondance d'opcode peut être combinée avec le filtrage de nœud avec certains masques de bits. En général, la prise en charge du filtrage est codée dans le nom du masque de bits, par exemple, NID_OPCODE prend en charge le filtrage des nœuds et des opcodes. Par exemple, UNC_C_TOR_INSERTS:NID_OPCODE:OPC_RFO:nf=1.
