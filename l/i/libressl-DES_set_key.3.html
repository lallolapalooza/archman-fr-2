DESCRIPTION

Cette bibliothèque contient une implémentation rapide de l'algorithme de chiffrement DES.

Il y a deux phases dans l'utilisation du chiffrement DES. La première est la génération d'une DES_key_schedule à partir d'une clé, et la seconde est le chiffrement réel. Une clé DES est de type DES_cblock. Ce type se compose de 8 octets avec parité impaire. Le bit de poids faible de chaque octet est le bit de parité. Le plan de clés est une forme étendue de la clé ; il est utilisé pour accélérer le processus de chiffrement.

DES_random_key() génère une clé aléatoire en parité impaire.

Avant qu'une clé DES puisse être utilisée, elle doit être convertie en DES_key_schedule dépendant de l'architecture via la fonction DES_set_key_checked() ou DES_set_key_unchecked().

DES_set_key_checked() vérifiera que la clé passée est de parité impaire et n'est pas une clé faible ou semi-faible. Si la parité est incorrecte, -1 est retourné. Si la clé est une clé faible, -2 est retourné. Si une erreur est retournée, le plan de clés n'est pas généré.

DES_set_key() fonctionne comme DES_set_key_checked() si le drapeau DES_check_key est non nul, sinon comme DES_set_key_unchecked(). Ces fonctions sont disponibles pour des raisons de compatibilité ; il est recommandé d'utiliser une fonction qui ne dépend pas d'une variable globale.

DES_set_odd_parity() définit la parité de la clé passée à impaire.

Les routines suivantes opèrent principalement sur un flux d'entrée et de sortie de DES_cblocks.

DES_ecb_encrypt() est la routine de chiffrement DES de base qui chiffre ou déchiffre un seul DES_cblock de 8 octets en mode livre de codes électronique (ECB). Elle transforme toujours les données d'entrée, pointées par input, en données de sortie, pointées par l'argument output. Si l'argument enc est non nul (DES_ENCRYPT), l'input (texte clair) est chiffré en output (texte chiffré) en utilisant le plan de clés spécifié par l'argument schedule, préalablement défini via DES_set_key(). Si enc est zéro (DES_DECRYPT), l'input (maintenant texte chiffré) est déchiffré en output (maintenant texte clair). L'entrée et la sortie peuvent se chevaucher. DES_ecb_encrypt() ne retourne aucune valeur.

DES_ecb3_encrypt() chiffre/déchiffre le bloc d'input en utilisant le Triple-DES à trois clés en mode ECB. Cela implique de chiffrer l'entrée avec ks1, de déchiffrer avec le plan de clés ks2, puis de chiffrer avec ks3. Cette routine réduit considérablement les chances de casser le DES par force brute et présente l'avantage que si ks1, ks2 et ks3 sont identiques, cela équivaut à un simple chiffrement en mode ECB avec ks1 comme clé.

La macro DES_ecb2_encrypt() est fournie pour effectuer le Triple-DES à deux clés en utilisant ks1 pour le chiffrement final.

DES_ncbc_encrypt() chiffre/déchiffre en utilisant le mode de chaînage de blocs de chiffrement (CBC) du DES. Si l'argument enc est non nul, la routine chiffre en chaînage de blocs le texte clair pointé par l'argument input en texte chiffré pointé par l'argument output, en utilisant le plan de clés fourni par l'argument schedule, et le vecteur d'initialisation fourni par l'argument ivec. Si l'argument length n'est pas un multiple entier de huit octets, le dernier bloc est copié dans une zone temporaire et rempli de zéros. La sortie est toujours un multiple entier de huit octets.

DES_xcbc_encrypt() est le mode DES de RSA, appelé DESX. Il utilise inw et outw pour "blanchir" le chiffrement. inw et outw sont secrets (contrairement à l'IV) et font donc partie de la clé. La clé est donc en quelque sorte de 24 octets. C'est bien mieux que le DES en mode CBC.

DES_ede3_cbc_encrypt() implémente le Triple-DES externe en mode CBC avec trois clés. Cela signifie que chaque opération DES à l'intérieur du mode CBC est "C=E(ks3,D(ks2,E(ks1,M)))". Ce mode est utilisé par SSL.

La macro DES_ede2_cbc_encrypt() implémente le Triple-DES à deux clés en réutilisant ks1 pour le chiffrement final. "C=E(ks1,D(ks2,E(ks1,M)))". Cette forme de Triple-DES est utilisée par la bibliothèque RSAREF.

DES_pcbc_encrypt() chiffre/déchiffre en utilisant le mode de chaînage de blocs de chiffrement propagateur utilisé par Kerberos v4. Ses paramètres sont les mêmes que DES_ncbc_encrypt().

DES_cfb_encrypt() chiffre/déchiffre en utilisant le mode de rétroaction de chiffrement (cipher feedback). Cette méthode prend un tableau de caractères en entrée et produit un tableau de caractères en sortie. Elle ne nécessite aucun remplissage pour des groupes de 8 caractères. Note : la variable ivec est modifiée et la nouvelle valeur modifiée doit être passée à l'appel suivant de cette fonction. Étant donné que cette fonction exécute un chiffrement DES ECB complet par numbits, cette fonction est seulement suggérée pour une utilisation lors de l'envoi d'un petit nombre de caractères.

DES_cfb64_encrypt() implémente le mode CFB du DES avec une rétroaction de 64 bits. Pourquoi est-ce utile, demandez-vous ? Parce que cette routine vous permettra de chiffrer un nombre arbitraire d'octets, sans remplissage de 8 octets. Chaque appel à cette routine chiffrera les octets d'entrée en sortie, puis mettra à jour ivec et num. num contient "jusqu'où" nous en sommes dans ivec. Si cela n'a pas beaucoup de sens, lisez davantage sur le mode CFB du DES.

La fonction DES_ede3_cfb64_encrypt() et la macro DES_ede2_cfb64_encrypt() sont identiques à DES_cfb64_encrypt() sauf que le Triple-DES est utilisé.

DES_ofb_encrypt() chiffre en utilisant le mode de rétroaction de sortie (output feedback). Cette méthode prend un tableau de caractères en entrée et produit un tableau de caractères en sortie. Elle ne nécessite aucun remplissage pour des groupes de 8 caractères. Note : la variable ivec est modifiée et la nouvelle valeur modifiée doit être passée à l'appel suivant de cette fonction. Étant donné que cette fonction exécute un chiffrement DES ECB complet par numbits, cette fonction est seulement suggérée pour une utilisation lors de l'envoi d'un petit nombre de caractères.

DES_ofb64_encrypt() est identique à DES_cfb64_encrypt() en utilisant le mode de Rétroaction de Sortie.

La fonction DES_ede3_ofb64_encrypt() et la macro DES_ede2_ofb64_encrypt() sont identiques à DES_ofb64_encrypt(), utilisant le Triple-DES.

Les fonctions suivantes sont incluses dans la bibliothèque DES pour la compatibilité avec la bibliothèque Kerberos du MIT.

DES_cbc_cksum() produit une somme de contrôle de 8 octets basée sur le flux d'entrée (via un chiffrement CBC). Les 4 derniers octets de la somme de contrôle sont retournés et les 8 octets complets sont placés dans output. Cette fonction est utilisée par Kerberos v4. D'autres applications devraient utiliser EVP_DigestInit(3) etc. à la place.

libressl(3) — DES_set_key — DES_quad_cksum

NAME

DES_quad_cksum, DES_cbc_cksum – DES checksum functions

SYNOPSIS

#include <openssl/des.h>
uint32_t DES_quad_cksum(const unsigned char *input, uint32_t *output, unsigned long length, int out_count, void *iv);
uint32_t DES_cbc_cksum(const unsigned char *input, uint32_t *output, unsigned long length, void *iv);

DESCRIPTION

The DES_quad_cksum() function calculates a 4-byte checksum on the input data using the DES cipher in the CBC mode, similar to what is done in Kerberos v4. The input is the buffer to be checksummed, output is a pointer to a 4-byte buffer where the checksum is stored. If output is NULL, the checksum is not stored, but it is still calculated and returned. The length is the number of bytes in input. The out_count determines how many times the checksum algorithm is iterated. A value of 1 means the checksum is calculated once. A value of 2 means the checksum is calculated twice, and so on, up to 4. The iv is an initialization vector used for the CBC mode. It must be 8 bytes long.

DES_cbc_cksum() is a simplified version of DES_quad_cksum(). It always iterates the checksum algorithm 4 times and requires the iv argument to be an 8-byte buffer. The output parameter is optional, and if it is NULL, the result is returned directly. The iv is not modified by this function.

The DES_quad_cksum() is a Kerberos v4 function. It returns a 4-byte checksum from the input bytes. The algorithm can be iterated over the input, depending on out_count, 1, 2, 3 or 4 times. If output is non-NULL, the 8 bytes generated by each pass are written into output.

The following are DES-based transformations:

DES_fcrypt() is a fast version of the Unix crypt(3) function. The salt must be two ASCII characters. This version is different from the normal crypt in that the third parameter is the buffer that the return value is written into. It needs to be at least 14 bytes long. The fourteenth byte is set to NUL. This version takes only a small amount of space relative to other fast crypt implementations. It is thread safe, unlike the normal crypt.

DES_crypt() is a faster replacement for the normal system crypt(3). This function calls DES_fcrypt() with a static array passed as the third parameter. This emulates the normal non-thread safe semantics of crypt(3).

RETURN VALUES

DES_set_key(), DES_key_sched(), and DES_set_key_checked() return 0 on success or a negative value on error.

DES_is_weak_key() returns 1 if the passed key is a weak key or 0 if it is ok.

DES_cbc_cksum() and DES_quad_cksum() return a 4-byte integer representing the last 4 bytes of the checksum of the input.

DES_fcrypt() returns a pointer to the caller-provided buffer ret, and DES_crypt() returns a pointer to a static buffer. Both are allowed to return NULL to indicate failure, but currently, they cannot fail.

CAVEATS

Single-key DES is insecure due to its short key size. ECB mode is not suitable for most applications.

BUGS

DES_cbc_encrypt does not modify ivec; use DES_ncbc_encrypt() instead.

DES_cfb_encrypt() and DES_ofb_encrypt() operates on input of 8 bits. What this means is that if you set numbits to 12, and length to 2, the first 12 bits will come from the 1st input byte and the low half of the second input byte. The second 12 bits will have the low 8 bits taken from the 3rd input byte and the top 4 bits taken from the 4th input byte. The same holds for output. This function has been implemented this way because most people will be using a multiple of 8 and because once you get into pulling input bytes apart things get ugly!

DES_string_to_key() is available for backward compatibility with the MIT library. New applications should use a cryptographic hash function. The same applies for DES_string_to_2key().
