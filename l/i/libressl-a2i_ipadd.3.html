A2I_IPADD(3) Manuel des fonctions de bibliothèque A2I_IPADD(3)

NOM

a2i_ipadd, a2i_IPADDRESS, a2i_IPADDRESS_NC — analyse les adresses de protocole Internet en chaînes OCTET ASN.1 pour X.509

SYNOPIS

bibliothèque “libcrypto”
#include <openssl/x509v3.h>

int
a2i_ipadd(unsigned char *ipout, const char *ipasc);

ASN1_OCTET_STRING *
a2i_IPADDRESS(const char *ipasc);

ASN1_OCTET_STRING *
a2i_IPADDRESS_NC(const char *ipasc);

DESCRIPTION

a2i_ipadd() et a2i_IPADDRESS() analysent la chaîne ipasc contenant une adresse IPv4 ou IPv6 dans l'un des formats suivants :

d.d.d.d
x:x:x:x:x:x:x:x (exactement 8 mots)
(x:)*x::x(:x)* (moins de 8 mots)
(x:)*x:: (moins de 8 mots)
::x(:x)* (moins de 8 mots)
::
(x:)*d.d.d.d (jusqu'à 6 mots hexadécimaux, :: peut être utilisé)

où chaque d représente un nombre décimal non négatif inférieur à 256 avec un, deux ou trois chiffres, et chaque x représente un nombre hexadécimal non négatif avec un, deux, trois ou quatre chiffres. Les lettres minuscules a-f et majuscules A-F peuvent être utilisées.

a2i_ipadd() stocke les octets de l'adresse en ordre d'octets réseau (big endian) à partir de ipout. L'appelant est responsable de fournir un espace suffisant ; il est toujours recommandé de fournir un tampon d'au moins 16 octets, même si une adresse IPv4 est attendue, afin d'éviter les dépassements de tampon si ipasc est mal formé.

a2i_IPADDRESS() stocke l'adresse dans un objet OCTET STRING ASN.1 nouvellement alloué.

a2i_IPADDRESS_NC() attend que ipasc contienne deux adresses de la même famille d'adresses sous la forme ci-dessus, séparées par un caractère slash (‘/’), et stocke la concaténation des deux adresses dans un objet OCTET STRING ASN.1 nouvellement alloué, ce qui est typiquement utilisé pour les paires adresse/masque dans les extensions de contraintes de nom des certificats CA.

VALEURS DE RETOUR

a2i_ipadd() renvoie le nombre d'octets écrits dans ipout en cas de succès, c'est-à-dire 4 pour une adresse IPv4 ou 16 pour une adresse IPv6, ou 0 si l'analyse a échoué.

a2i_IPADDRESS() et a2i_IPADDRESS_NC() renvoient le nouvel objet ou NULL si l'analyse ou l'allocation mémoire a échoué.

VOIR AUSSI

NORMES

RFC 5280 : Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile

  • section 4.2.1.6 : Subject Alternative Name
  • section 4.2.1.10 : Name Constraints

HISTORIQUE

a2i_IPADDRESS() et a2i_IPADDRESS_NC() sont apparus pour la première fois dans OpenSSL 0.9.8 et a2i_ipadd() dans OpenSSL 0.9.8e. Ils sont disponibles depuis OpenBSD 4.5.

ATTENTION

Bien que certaines erreurs de syntaxe soient détectées, une validation minimale est effectuée et ces fonctions renvoient souvent des objets qui n'ont aucun sens, en particulier dans le contexte d'IPv6. Par exemple, la syntaxe :d.d.d.d à la fin peut être ajoutée à une partie hexadécimale qui produit douze octets arbitraires.
