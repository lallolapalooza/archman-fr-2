libressl-SSL_CTX_set_generate_session_id(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

SSL_CTX_SET_GENERATE_SESSION_ID(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_GENERATE_SESSION_ID(3)

NOM

SSL_CTX_set_generate_session_id, SSL_set_generate_session_id, SSL_has_matching_session_id, GEN_SESSION_CB — manipuler la génération des identifiants de session SSL (serveur uniquement)

SYNOPIS

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

typedef int
(*GEN_SESSION_CB)(const SSL *ssl, unsigned char *id, unsigned int *id_len);

int
SSL_CTX_set_generate_session_id(SSL_CTX *ctx, GEN_SESSION_CB cb);

int
SSL_set_generate_session_id(SSL *ssl, GEN_SESSION_CB cb);

int
SSL_has_matching_session_id(const SSL *ssl, const unsigned char *id, unsigned int id_len);

DESCRIPTION

SSL_CTX_set_generate_session_id() définit la fonction de rappel pour la génération de nouveaux identifiants de session pour les sessions SSL/TLS pour ctx à être cb.

SSL_set_generate_session_id() définit la fonction de rappel pour la génération de nouveaux identifiants de session pour les sessions SSL/TLS pour ssl à être cb.

SSL_has_matching_session_id() vérifie si une session avec l'identifiant id (de longueur id_len) est déjà contenue dans le cache de session interne du contexte parent de ssl.

Lorsqu'une nouvelle session est établie entre le client et le serveur, le serveur génère un identifiant de session. L'identifiant de session est une séquence arbitraire d'octets. La longueur de l'identifiant de session est comprise entre 1 et 32 octets. L'identifiant de session n'est pas critique en matière de sécurité mais doit être unique pour le serveur. De plus, l'identifiant de session est transmis en clair lors de la réutilisation de la session, il ne doit donc pas contenir d'informations sensibles.

Sans fonction de rappel définie, un serveur OpenSSL générera un identifiant de session unique à partir de nombres pseudo-aléatoires de la longueur maximale possible. En utilisant la fonction de rappel, l'identifiant de session peut être modifié pour contenir des informations supplémentaires comme, par exemple, un identifiant d'hôte afin d'améliorer l'équilibrage de charge ou les techniques de mise en cache externes.

La fonction de rappel reçoit un pointeur vers l'emplacement mémoire où placer id et un pointeur vers la longueur maximale autorisée id_len. Le tampon à l'emplacement id a une taille garantie égale à id_len. La fonction de rappel est autorisée à générer uniquement un identifiant plus court et à réduire id_len; la fonction de rappel ne doit jamais augmenter id_len ni écrire dans l'emplacement id au-delà de la limite spécifiée.

L'emplacement id est rempli de 0x00 avant que la fonction de rappel ne soit appelée, de sorte que la fonction de rappel ne peut remplir qu'une partie de la longueur possible et laisser id_len inchangé tout en maintenant la reproductibilité.

Étant donné que les sessions doivent être distinguées, les identifiants de session doivent être uniques. Sans la fonction de rappel, un nombre aléatoire est utilisé, de sorte que la probabilité de générer le même identifiant de session est extrêmement faible (2^256 pour TLSv1). Afin d'assurer l'unicité de l'identifiant de session généré, la fonction de rappel doit appeler SSL_has_matching_session_id() et générer un autre identifiant si un conflit se produit. Si un conflit d'identifiant n'est pas résolu, la négociation échouera. Si l'application encode, par exemple, un identifiant d'hôte unique, un numéro de processus unique et un numéro de séquence unique dans l'identifiant de session, l'unicité peut être facilement obtenue sans l'ajout d'aléatoire (il convient cependant de veiller à ce qu'aucune information confidentielle ne soit divulguée de cette manière). Si l'application ne peut pas garantir l'unicité, il est recommandé d'utiliser la longueur maximale id_len et de remplir les octets non utilisés pour coder des informations spéciales avec des données aléatoires afin d'éviter les collisions.

SSL_has_matching_session_id() ne consultera que le cache de session interne, pas le cache externe. Comme l'identifiant de session est généré avant que la négociation ne soit terminée, il n'est pas immédiatement ajouté au cache. Si un autre thread utilise le même cache de session interne, une condition de concurrence peut se produire, dans laquelle un autre thread génère le même identifiant de session. Des collisions peuvent également se produire lors de l'utilisation d'un cache de session externe, car le cache externe n'est pas testé avec SSL_has_matching_session_id() et la même condition de concurrence s'applique.

La fonction de rappel doit retourner 0 si elle ne peut pas générer d'identifiant de session pour quelque raison que ce soit et retourner 1 en cas de succès.

VALEUR DE RETOUR

SSL_CTX_set_generate_session_id() et SSL_set_generate_session_id() retournent toujours 1.

SSL_has_matching_session_id() retourne 1 si une autre session avec le même identifiant est déjà dans le cache.

EXEMPLES

La fonction de rappel ci-dessous générera un identifiant de session avec l'identifiant du serveur donné et remplira le reste avec des octets pseudo-aléatoires :

const char session_id_prefix = "www-18";

#define MAX_SESSION_ID_ATTEMPTS 10
static int
generate_session_id(const SSL *ssl, unsigned char *id,
    unsigned int *id_len)
{
	unsigned int count = 0;

	do {
		RAND_pseudo_bytes(id, *id_len);
		/*
		 * Préfixer le session_id avec le préfixe requis. NB : Si
		 * notre préfixe est trop long, le tronquer – mais il y aura
		 * aussi des effets plus graves, par exemple le serveur ne pourrait
		 * créer qu'un seul ID de session (le préfixe !) donc toutes
		 * les négociations de session futures échoueront en raison de conflits.
		 */
		memcpy(id, session_id_prefix,
		    (strlen(session_id_prefix) < *id_len) ?
		    strlen(session_id_prefix) : *id_len);
	} while (SSL_has_matching_session_id(ssl, id, *id_len) &&
	    (++count < MAX_SESSION_ID_ATTEMPTS));

	if (count >= MAX_SESSION_ID_ATTEMPTS)
		return 0;
	return 1;
}
