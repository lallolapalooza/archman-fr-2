DESCRIPTION

Les routines d'encodage EVP fournissent une interface de haut niveau pour l'encodage et le décodage base64. L'encodage base64 convertit les données binaires en une forme imprimable qui utilise les caractères A-Z, a-z, 0-9, "+" et "/" pour représenter les données. Pour chaque 3 octets de données binaires fournis, 4 octets de données encodées en base64 seront produits, plus quelques sauts de ligne occasionnels. Si la longueur des données d'entrée n'est pas un multiple de 3, les données de sortie seront complétées à la fin à l'aide du caractère "=".

EVP_ENCODE_CTX_new() alloue, initialise et retourne un contexte à utiliser pour les fonctions d'encodage et de décodage.

EVP_ENCODE_CTX_free() libère ctx.

L'encodage des données binaires est effectué par blocs de 48 octets d'entrée (ou moins pour le bloc final). Pour chaque bloc d'entrée de 48 octets encodé, 64 octets de données base64 sont produits, plus un caractère de saut de ligne supplémentaire, soit 65 octets au total. Le bloc final, qui peut être inférieur à 48 octets, produira 4 octets pour chaque 3 octets d'entrée. Si la longueur des données n'est pas divisible par 3, alors 4 octets complets sont toujours produits pour les 1 ou 2 derniers octets d'entrée. De même, un caractère de saut de ligne sera également produit.

EVP_EncodeInit() initialise ctx pour le début d'une nouvelle opération d'encodage.

EVP_EncodeUpdate() encode inl octets de données trouvés dans le tampon pointé par in. La sortie est stockée dans le tampon out et le nombre d'octets de sortie est stocké dans *outl. Il incombe à l'appelant de s'assurer que le tampon à out est suffisamment grand pour accueillir les données de sortie. Seuls les blocs de données complets (48 octets) seront immédiatement traités et produits par cette fonction. Tout reste est conservé dans l'objet ctx et sera traité par un appel ultérieur à EVP_EncodeUpdate() ou EVP_EncodeFinal(). Pour calculer la taille requise du tampon de sortie, ajoutez la valeur de inl à la quantité de données non traitées conservées dans ctx et divisez le résultat par 48 (ignorez tout reste). Cela donne le nombre de blocs de données qui seront traités. Assurez-vous que le tampon de sortie contient 65 octets de stockage pour chaque bloc, plus un octet supplémentaire pour un terminateur NUL. EVP_EncodeUpdate() peut être appelée à plusieurs reprises pour traiter de grandes quantités de données d'entrée. En cas d'erreur, EVP_EncodeUpdate() définira *outl à 0 et retournera 0. En cas de succès, 1 sera retourné.

EVP_EncodeFinal() doit être appelée à la fin d'une opération d'encodage. Elle traitera tout bloc de données partiel restant dans l'objet ctx. Les données de sortie seront stockées dans out et la longueur des données écrites sera stockée dans *outl. Il incombe à l'appelant de s'assurer que out est suffisamment grand pour accueillir les données de sortie, qui ne dépasseront jamais 65 octets plus un terminateur NUL supplémentaire, soit 66 octets au total.

EVP_EncodeBlock() encode un bloc complet de données d'entrée dans f et de longueur n et le stocke dans t. Pour chaque 3 octets d'entrée fournis, 4 octets de données de sortie seront produits. Si n n'est pas divisible par 3, alors le bloc est encodé comme un bloc final de données et la sortie est complétée de manière à être toujours divisible par 4. De plus, un caractère terminateur NUL sera ajouté. Par exemple, si 16 octets de données d'entrée sont fournis, alors 24 octets de données encodées sont créés plus 1 octet pour un terminateur NUL, soit 25 octets au total. La longueur des données générées sans le terminateur NUL est retournée par la fonction.

EVP_DecodeInit() initialise ctx pour le début d'une nouvelle opération de décodage.

EVP_DecodeUpdate() décode inl caractères de données trouvés dans le tampon pointé par in. La sortie est stockée dans le tampon out et le nombre d'octets de sortie est stocké dans *outl. Il incombe à l'appelant de s'assurer que le tampon à out est suffisamment grand pour accueillir les données de sortie. Cette fonction tentera de décoder autant de données que possible par blocs de 4 octets. Tous les espaces blancs, sauts de ligne ou retours chariot sont ignorés. Tout bloc partiel de données non traitées (1, 2 ou 3 octets) qui reste à la fin sera conservé dans l'objet ctx et traité par un appel ultérieur à EVP_DecodeUpdate(). Si des caractères base64 illégaux sont rencontrés ou si le caractère de remplissage base64 "=" est rencontré au milieu des données, la fonction retourne -1 pour indiquer une erreur. Une valeur de retour de 0 ou 1 indique un traitement réussi des données. Une valeur de retour de 0 indique en outre que les derniers caractères de données d'entrée traités incluaient le caractère de remplissage base64 "=" et qu'aucun autre caractère de données de remplissage n'est attendu pour être traité. Pour chaque 4 octets base64 valides traités — en ignorant les espaces blancs, les retours chariot et les sauts de ligne — 3 octets de données binaires de sortie seront produits, ou moins à la fin des données.

EVP_DecodeFinal() doit être appelée à la fin d'une opération de décodage. Elle traitera toute données restantes dans ctx, y compris les caractères de remplissage. La sortie est stockée dans out et la longueur des données écrites est stockée dans *outl. Il incombe à l'appelant de s'assurer que out est suffisamment grand pour accueillir la sortie. La valeur de retour indique si le décodage s'est terminé avec succès (1) ou s'il y a eu une erreur, comme des caractères illégaux ou un remplissage incorrect (0).

EVP_DecodeBlock() décode un bloc complet de données d'entrée dans f et de longueur n et le stocke dans t. Pour chaque 4 caractères d'entrée fournis, 3 octets de données de sortie seront produits. Les caractères d'espacement, les retours chariot et les sauts de ligne sont ignorés. Si le nombre d'octets d'entrée valides n'est pas un multiple de 4, alors le bloc est traité comme un bloc final de données et la sortie est complétée pour être toujours divisible par 3. La longueur des données générées sans le caractère de remplissage est retournée par la fonction. La fonction retourne -1 en cas d'erreur.

libressl(3) - EVP_EncodeInit

NAME

EVP_EncodeInit, EVP_EncodeUpdate, EVP_EncodeBlock, EVP_DecodeInit, EVP_DecodeUpdate, EVP_DecodeFinal, EVP_DecodeBlock - base64 encoding and decoding

SYNOPSIS

#include <openssl/evp.h>

int EVP_EncodeInit(EVP_ENCODE_CTX *ctx);
int EVP_EncodeUpdate(EVP_ENCODE_CTX *ctx, unsigned char *out, int *outl, const unsigned char *in, int inl);
int EVP_EncodeBlock(unsigned char *t, const unsigned char *f, int n);
int EVP_DecodeInit(EVP_ENCODE_CTX *ctx);
int EVP_DecodeUpdate(EVP_ENCODE_CTX *ctx, unsigned char *out, int *outl, const unsigned char *in, int inl);
int EVP_DecodeFinal(EVP_ENCODE_CTX *ctx, unsigned char *out, int *outl);
int EVP_DecodeBlock(unsigned char *t, const unsigned char *f, int n);

DESCRIPTION

The base64 encoding is a way of representing binary data in an ASCII string format. The base64 encoding process maps 3 bytes of binary data to 4 ASCII characters. The base64 alphabet is A-Z, a-z, 0-9, +, and /. The padding character is "=".

The functions EVP_EncodeInit(), EVP_EncodeUpdate(), and EVP_EncodeBlock() can be used to encode data into base64 format.

The functions EVP_DecodeInit(), EVP_DecodeUpdate(), EVP_DecodeFinal(), and EVP_DecodeBlock() can be used to decode base64 encoded data.

The functions EVP_EncodeInit() and EVP_DecodeInit() initialize an EVP_ENCODE_CTX context structure pointed to by ctx.

The function EVP_EncodeUpdate() encodes the block of inl bytes pointed to by in and writes the result to the buffer pointed to by out. The length of the written data will be stored in the location pointed to by outl. The output buffer should be large enough to hold the encoded data. The size required is approximately 4/3 times the input size, rounded up to the nearest multiple of 4.

The function EVP_EncodeBlock() encodes the block of n bytes pointed to by f and stores the result in the buffer pointed to by t. The output buffer must be large enough to hold the encoded data. For every 3 input bytes, 4 output bytes will be produced. The output will be padded with "=" characters if necessary. The function returns the length of the data encoded, excluding the NUL terminator. This function does not require an EVP_ENCODE_CTX and is suitable for simple, one-off encodings.

The function EVP_DecodeUpdate() decodes the block of inl characters pointed to by in and writes the result to the buffer pointed to by out. The length of the written data will be stored in the location pointed to by outl. Whitespace characters are ignored. The output buffer should be large enough to hold the decoded data. The size required is approximately 3/4 times the input size.

The function EVP_DecodeFinal() must be called at the end of a decoding operation. If there is any unprocessed data still in ctx, then the input data must not have been a multiple of 4 and therefore an error has occurred. The function will return -1 in this case. Otherwise the function returns 1 on success.

The function EVP_DecodeBlock() will decode the block of n characters of base64 data contained in f and store the result in t. Any leading whitespace will be trimmed as will any trailing whitespace, newlines, carriage returns or EOF characters. After such trimming the length of the data in f must be divisible by 4. For every 4 input bytes, exactly 3 output bytes will be produced. The output will be padded with 0 bits if necessary to ensure that the output is always 3 bytes for every 4 input bytes. This function will return the length of the data decoded or -1 on error.

RETURN VALUES

EVP_ENCODE_CTX_new() returns a pointer to the newly allocated EVP_ENCODE_CTX object or NULL on error.

EVP_EncodeUpdate() returns 0 on error or 1 on success.

EVP_EncodeBlock() returns the number of bytes encoded excluding the NUL terminator.

EVP_DecodeUpdate() returns -1 on error and 0 or 1 on success. If 0 is returned, then no more non-padding base64 characters are expected.

EVP_DecodeFinal() returns -1 on error or 1 on success.

EVP_DecodeBlock() returns the length of the data decoded or -1 on error.

SEE ALSO

BIO_f_base64(3), evp(3)

HISTORY

The EVP_Encode*() and EVP_Decode*() functions first appeared in SSLeay 0.5.1 and have been available since OpenBSD 2.4.

EVP_ENCODE_CTX_new() and EVP_ENCODE_CTX_free() first appeared in OpenSSL 1.1.0 and have been available since OpenBSD 6.5.
