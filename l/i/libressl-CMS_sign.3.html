CMS_SIGN(3) Manuel des fonctions de bibliothèque CMS_SIGN(3)

NOM

CMS_sign — créer une structure CMS SignedData

SYNOPSIS

bibliothèque « libcrypto »
#include <openssl/cms.h>

CMS_ContentInfo *
CMS_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs, BIO *data, unsigned int flags);

DESCRIPTION

CMS_sign() crée et renvoie une structure CMS SignedData. signcert est le certificat à utiliser pour la signature, pkey est la clé privée correspondante. certs est un ensemble optionnel de certificats supplémentaires à inclure dans la structure CMS (par exemple, les éventuels certificats intermédiaires de la chaîne). L'un quelconque ou la totalité de ces paramètres peuvent être NULL.

Les données à signer sont lues à partir de data.

Les drapeaux suivants (combinés par un OU bit à bit) peuvent être passés dans l'argument flags:

CMS_TEXT
Ajoute des en-têtes MIME pour le type text/plain aux données. De nombreux clients S/MIME attendent que le contenu signé inclue des en-têtes MIME valides.
CMS_NOCERTS
N'inclut pas le certificat du signataire dans la structure CMS_ContentInfo. Le certificat du signataire doit néanmoins être fourni dans le paramètre signcert. Cela peut réduire la taille de la signature si le certificat du signataire peut être obtenu par d'autres moyens, par exemple à partir d'un message précédemment signé.
CMS_DETACHED
Omet les données signées de la structure CMS_ContentInfo. Ceci est utilisé pour les signatures détachées CMS_ContentInfo, qui sont utilisées dans les messages signés en texte brut S/MIME par exemple.
CMS_BINARY
Ne traduit pas le contenu fourni au format canonique MIME, même si cela est requis par les spécifications S/MIME. Cette option doit être utilisée si les données fournies sont au format binaire. Sinon, la traduction les corrompra.
CMS_NOATTR
N'ajoute aucun SignedAttributes. Par défaut, le champ signerInfos inclut plusieurs SignedAttributes CMS, y compris l'heure de signature, le type de contenu CMS et la liste des chiffreurs pris en charge dans un attribut SMIMECapabilities.
CMS_NOSMIMECAP
Omet uniquement les SMIMECapabilities. Si présent, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants par ordre de préférence : AES 256 bits, AES 192 bits, AES 128 bits, triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes n'est pas disponible, il ne sera pas inclus.
CMS_USE_KEYID
Utilise la valeur de l'identifiant de clé du sujet pour identifier les certificats de signature. Une erreur se produit si le certificat de signature ne possède pas d'extension d'identifiant de clé du sujet. Par défaut, le nom de l'émetteur et le numéro de série sont utilisés à la place.
CMS_STREAM
Initialise uniquement la structure CMS_ContentInfo renvoyée pour la préparer à l'opération de signature. La signature n'est cependant *pas* effectuée et les données à signer ne sont pas lues à partir du paramètre data. La signature est différée jusqu'à ce que les données aient été écrites. De cette manière, les données peuvent être signées en une seule passe. La structure CMS_ContentInfo renvoyée n'est *pas* complète et la sortie de son contenu via une fonction qui ne finalise pas correctement la structure CMS_ContentInfo donnera des résultats imprévisibles. Plusieurs fonctions, dont SMIME_write_CMS(3), i2d_CMS_bio_stream(3), ou PEM_write_bio_CMS_stream(3) finalisent la structure. Alternativement, la finalisation peut être effectuée en obtenant directement le flux ASN1 BIO en utilisant BIO_new_CMS(3).
CMS_PARTIAL
Produit une structure CMS_ContentInfo partielle à laquelle des signataires et des capacités supplémentaires peuvent être ajoutés avant la finalisation.

Si un signataire est spécifié, il utilisera le digest par défaut pour l'algorithme de signature. Il s'agit de SHA-1 pour les clés RSA et DSA.

Si signcert et pkey sont NULL, alors une structure CMS ne contenant que des certificats est produite.

La fonction CMS_sign() est une fonction de signature CMS de base dont la sortie conviendra à de nombreux usages. Pour un contrôle plus fin du format de sortie, les paramètres certs, signcert et pkey peuvent tous être NULL et le drapeau CMS_PARTIAL défini. Ensuite, un ou plusieurs signataires peuvent être ajoutés en utilisant la fonction CMS_add1_signer(3), des digests non par défaut peuvent être utilisés et des attributs personnalisés ajoutés. CMS_final(3) doit ensuite être appelé pour finaliser la structure si le streaming n'est pas activé.

VALEUR DE RETOUR

CMS_sign() renvoie soit une structure CMS_ContentInfo valide, soit NULL si une erreur s'est produite. L'erreur peut être obtenue via ERR_get_error(3).

VOIR AUSSI

CMS_add0_cert(3), CMS_add1_signer(3), CMS_ContentInfo_new(3), CMS_final(3), CMS_sign_receipt(3), CMS_verify(3)

NORMES

RFC 5652 : Cryptographic Message Syntax (CMS)

  • section 5.1 : Type SignedData
  • section 5.3 : Type SignerInfo

RFC 8419 : Use of Edwards-Curve Digital Signature Algorithm (EdDSA) Signatures in the Cryptographic Message Syntax (CMS)

RFC 8551 : Secure/Multipurpose Internet Mail Extensions (S/MIME) Version 4.0 Message Specification, section 2.5.2 : Attribut SMIMECapabilities

HISTORIQUE

CMS_sign() est apparu pour la première fois dans OpenSSL 0.9.8h et est disponible depuis OpenBSD 6.7.

BOGUES

Certains attributs tels que les contre-signatures ne sont pas pris en charge.

libressl-CMS_sign(3)

libressl - 2023-10-11

NAME

CMS_sign, CMS_sign_receipt - fonctions de signature de CMS

SYNOPSIS

DESCRIPTION

Le schéma de chiffrement de syntaxe de messagerie (CMS) est un ensemble de normes de sécurité pour les e-mails, défini par le RFC 3851.

Il utilise des fonctions de chiffrement asymétrique et symétrique. Le chiffrement asymétrique est utilisé pour les échanges de clés et la signature numérique. Le chiffrement symétrique est utilisé pour le chiffrement du contenu du message.

Les fonctions suivantes sont fournies pour la création de signatures CMS :

int CMS_sign(STACK_OF(X509) *certs, STACK_OF(X509_ALGOR) *digests, STACK_OF(PKCS7_SIGNER_INFO) *sinfos, BIO *data, BIO *bio, int flags);

Crée une signature CMS et l'écrit dans bio. Les certificats de confiance sont fournis dans certs. Les algorithmes de hachage sont fournis dans digests. Les informations sur les signataires sont fournies dans sinfos.

int CMS_sign_receipt(CMS_SignerInfo *si, X509 *recip_cert, STACK_OF(X509) *recip_certs, unsigned int flags);

Crée une accusé de réception de signature CMS. L'accusé de réception de signature est stocké dans si. Le certificat du destinataire est fourni dans recip_cert. Les certificats de confiance du destinataire sont fournis dans recip_certs.

VALEURS DE RETOUR

Les fonctions retournent 1 en cas de succès, 0 en cas d'échec.

VOIR AUSSI

CMS_verify(3)

NORMES

RFC 3851

HISTORIQUE

La première version de cette fonction est apparue dans OpenSSL 1.0.0.

BOGUES

Aucun bogue connu.
