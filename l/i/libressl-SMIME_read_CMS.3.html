SMIME_READ_CMS(3) Manuel des fonctions de bibliothèque SMIME_READ_CMS(3)

NOM

SMIME_read_CMS — extrait la CMS ContentInfo d'un message S/MIME

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/cms.h>

CMS_ContentInfo *
SMIME_read_CMS(BIO *in, BIO **bcont);

DESCRIPTION

SMIME_read_CMS() analyse un message au format S/MIME depuis in.

Si le message utilise la signature en texte clair, le contenu est sauvegardé dans un BIO mémoire qui est écrit dans *bcont et qui peut ensuite être passé à CMS_verify(3) avec le drapeau CMS_DETACHED activé. Sinon, *bcont est mis à NULL et le type de la structure retournée peut être déterminé en utilisant CMS_get0_type(3).

Pour supporter une future fonctionnalité si bcont n'est pas NULL, *bcont doit être initialisé à NULL, par exemple :

BIO *cont = NULL;
CMS_ContentInfo *cms = SMIME_read_CMS(in, &cont);

VALEURS DE RETOUR

SMIME_read_CMS() retourne une structure CMS_ContentInfo valide ou NULL si une erreur s'est produite. L'erreur peut être obtenue depuis ERR_get_error(3).

VOIR AUSSI

BIO_f_base64(3), BIO_new(3), CMS_ContentInfo_new(3), CMS_decrypt(3), CMS_get0_type(3), CMS_verify(3), d2i_CMS_ContentInfo(3), SMIME_read_PKCS7(3), SMIME_text(3), SMIME_write_CMS(3)

HISTORIQUE

SMIME_read_CMS() est apparu pour la première fois dans OpenSSL 0.9.8h et est disponible depuis OpenBSD 6.7.

BOGUES

L'analyseur MIME utilisé par SMIME_read_CMS() est quelque peu primitif. Bien qu'il gère la plupart des messages S/MIME, des formats composés plus complexes peuvent ne pas fonctionner.

L'analyseur suppose que la structure CMS_ContentInfo est toujours encodée en base64 et ne gère pas le cas où elle est au format binaire ou utilise le format quoted-printable.

L'utilisation d'un BIO mémoire pour contenir le contenu signé limite la taille du message qui peut être traité en raison de contraintes de mémoire : une option de streaming en une seule passe devrait être disponible.
