LINUXDOC(1) Manuel des commandes générales LINUXDOC(1)

NOM

linuxdoc - Convertisseur SGML LinuxDoc DTD vers d'autres formats de sortie

SYNTAXE

linuxdoc --backend=format
[--papersize=taille] [--language=lang] [--charset=char] [--style=fichier] [--debug] [--define attribut=valeur] [--include entite] [options-backend...] fichier(.sgml)

ou (Usage ancien, obsolète)
sgmlxxxx [options-generiques...] [options-backend...]   fichier(.sgml)

DESCRIPTION

La suite linuxdoc est une collection d'outils de formatage qui comprennent un fichier source SGML LinuxDoc DTD. Chaque outil de formatage (ou "backend") rend le fichier source dans une variété de formats de sortie, y compris HTML, TeX, DVI, PostScript, texte brut et source groff(1) au format page de manuel. La suite linuxdoc est fournie pour des raisons de compatibilité descendante, car il existe encore de nombreux documents utiles écrits en SGML LinuxDoc DTD.

Les langages de balisage acceptés par ces outils de formatage sont décrits dans le *Guide de l'utilisateur de Linuxdoc-Tools*. Ce sont des variantes d'une définition de type de document SGML initialement conçue par Matt Welsh pour la documentation Linux.

OPTIONS GÉNÉRIQUE

La plupart des options de ligne de commande sont acceptées par tous les backends. Certains backends ont des options spécifiques supplémentaires pour contrôler le rendu vers leur format de sortie particulier. Voici les options courantes :

--backend=format, -B
Définit le backend pour le format spécifié. Par défaut, aucun format réel, mais affiche juste l'utilisation de cette suite. Les formats disponibles sont : html, info, latex, lyx, rtf, txt, check.
--papersize=taille, -p
Définit la taille du papier. Par défaut, c'est ``a4'' (papier européen 297x210mm). Vous pouvez également spécifier la taille ``letter''.
--language=lang, -l
Spécifie la langue du document (cela peut changer les fichiers de style utilisés pour le formatage par un backend). La langue par défaut est l'anglais. Exécutez une commande LinuxDoc-tools sans arguments pour voir la liste des codes de langue valides.
--charset=chars, -c
Spécifie le codage des caractères de sortie. Par défaut, ``ascii'' sélectionne le jeu ASCII ; vous pouvez spécifier "latin" pour spécifier le jeu de caractères ISO 8859-1 (Latin-1). De plus, ``nippon'' et ``euc-kr'' sont nécessaires pour gérer les fichiers sgml encodés euc-jp et euc-kr. ``utf-8'' est également accepté, bien qu'il ne soit que partiellement pris en charge.
--style=fichier, -S
Inclut une DTD auxiliaire (Document Type Definition) depuis /usr/share/linuxdoc-tools/dtd.
--tabsize=n, -t
Définit l'espacement des tabulations supposé pour la génération du document de sortie. L'espacement de tabulation par défaut est 8.
--debug, -d
Ne supprime pas les fichiers intermédiaires (comme les fichiers .TeX générés en route vers un .dvi, ou les fichiers .man supprimés en route vers du texte brut).
--define, -D
Passe des paires attribut/valeur à faire correspondre avec les conditions "if" et "unless". Voir le Guide de l'utilisateur pour une discussion détaillée de cette fonctionnalité. Cette conditionnalisation est gérée par la commande sgmlpre. Voir sgmlpre(1) ainsi que le Guide de l'utilisateur.
--include, -i
Passe une option -i à nsgmls(1). Ceci peut être utilisé pour une inclusion conditionnelle. Voir la page de manuel de nsgmls(1) pour les détails.
--pass, -P
Passe une chaîne d'options au backend. La sémantique exacte de cette option dépend du backend et devrait être expliquée dans les pages de manuel individuelles de chacun.
fichier
Le fichier source SGML avec l'extension .sgml, nommé soit fichier, soit fichier.sgml. Il doit utiliser la DTD linuxdoc. D'autres DTD ne sont pas supportées.

Exécuter un backend sans arguments provoquera l'affichage de toutes ses options (le message d'erreur concernant "aucun nom de fichier donné" peut être ignoré en toute sécurité dans ce cas). Les backends disponibles comprennent (les noms entre crochets sont des formes anciennes et obsolètes) :

linuxdoc -B html (sgml2html)
traduit en HTML
linuxdoc -B info (sgml2info)
traduit en info GNU
linuxdoc -B lyx (sgml2lyx)
traduit en macros Lyx
linuxdoc -B latex (sgml2latex)
traduit en LaTeX 2e
linuxdoc -B rtf (sgml2rtf)
traduit en format Rich Text de Microsoft
linuxdoc -B txt (sgml2txt)
traduit en texte brut ou balisage de page de manuel Unix

Il existe également un outil linuxdoc-Bcheck
(sgmlcheck) disponible pour vérifier la syntaxe SGML Linuxdoc DTD des sources de documents sans réellement générer de version traduite.

PILOTES BACKEND

Voici la description de chaque pilote backend :


****************************************************

linuxdoc -B html (sgml2html) convertit un fichier source SGML LinuxDoc DTD en sortie HTML. La sortie apparaîtra dans le fichier de premier niveau file.html et file-n.html pour chaque section (action par défaut, mais peut être modifiée par une option), où file est le nom du fichier source SGML et n est le nom de la section.

La paire attribut/valeur "output=html" est définie pour les conditions.

linuxdoc -B html accepte les options suivantes : [--split 0|1|2 ] [--dosnames] [--imagebuttons] [--toc 0|1|2 ]

Leurs significations sont :

--split, -s
Niveau auquel diviser les documents sources. 0 = ne pas diviser, 1 = diviser par sections principales, 2 = diviser par sous-sections.
--toc, -T
Niveau de génération de la table des matières.
0 = ne génère pas de table des matières du tout,
1 = inclut les sections principales (/chapitres/parties),
2 = inclut les sous-sections.
--dosnames, -h
Utilise ".htm" plutôt que ".html" comme extension des fichiers html.
--imagebuttons, -I
Utilise les icônes d'images de flèches "suivant", "précédent" et "contenu" incluses dans /usr/share/linuxdoc-tools comme boutons de navigation.
--footer, -F
Utilise le fichier spécifié comme pied de page dans chaque fichier html résultant. Le pied de page par défaut est juste du texte brut 
 </BODY>\n </HTML>\n
--header, -H
Utilise le fichier spécifié comme partie supérieure de l'en-tête dans chaque fichier html résultant. Notez que ce n'est pas la partie complète de l'en-tête, c'est-à-dire que le titre et les liens (suivant, précédent, contenu) dans l'en-tête par défaut sont conservés. Le défaut est 
 <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 3.2 Final//EN">\n
 <HTML>\n <HEAD>\n
--rtldirection, -r
Définit la direction de droite à gauche dans le fichier html.


****************************************************

linuxdoc -B info (sgml2info) convertit un fichier source SGML de la DTD LinuxDoc au format GNU info. La sortie apparaîtra dans fichier.info où fichier est le nom du fichier source SGML.

La paire attribut/valeur "output=info" est définie pour les conditionnels.

linuxdoc -B info n'a pas d'options spécifiques au backend.


****************************************************

linuxdoc -B latex (sgml2latex) convertit un fichier source SGML de la DTD LinuxDoc en sortie LaTeX, en utilisant l'analyseur nsgmls(1) ou onsgmls(1), et le traducteur sgmlsasp(1). En utilisant la sortie LaTeX, et le formateur de texte latex(1), vous pouvez ensuite créer une sortie DVI, et une sortie PostScript en utilisant le convertisseur dvips(1). La sortie apparaîtra dans fichier.tex pour la sortie LaTeX, fichier.dvi pour la sortie DVI, ou fichier.ps pour la sortie PostScript, où fichier est le nom du fichier source SGML.

En utilisant la sortie LaTeX, et le formateur de texte pdflatex(1), vous pouvez ensuite créer une belle sortie PDF, adaptée à la visualisation avec des visualiseurs PDF tels que xpdf(1), acroread(1) ou ghostview(1).

La paire attribut/valeur "output=latex2e" est définie pour les conditionnels.

linuxdoc -B latex accepte les options suivantes spécifiques au backend : [--output=tex|dvi|ps|pdf] [--bibtex] [--makeindex] [--pagenumber=n] --quick [--latex=latex|hlatexp|platex|jlatex] [--dvips=dvips|dvi2ps] [--verbosity=n]

Leurs significations sont :

--output=fmt, -o
Spécifie le format de sortie désiré. Le spécificateur fmt peut être ``tex'', ``dvi'', ``ps'', ou ``pdf''.

Note : Cette version ne remplace pas/ne supprime pas les fichiers intermédiaires : fichier tex pour la sortie dvi, ou fichiers tex/dvi pour la sortie ps. Ceci est un comportement différent de la version originale de SGML-Tools 1.0.9, vous êtes donc avertis ici.

--bibtex, -b
Traite le TeX généré avec bibtex(1).
--makeindex, -m
Génère un fichier d'index TeX adapté au traitement avec makeindex(1) à partir des balises <idx> et <cdx> présentes dans la source SGML.
--pagenumber, -n
Définit le numéro de page de départ dans le fichier DVI ou PS de sortie.
--quick, -q
Effectue une seule passe de mise en forme LaTeX. Ce n'est souvent pas suffisant pour produire une sortie finale (à cause des références, etc.) mais est utile pour repérer les erreurs TeX et les problèmes de justification.
--pass, -P
L'argument de l'option de passe est inséré juste après le préambule LaTeX généré par la balise de type de document. Spécifie le format de sortie désiré. Le spécificateur fmt peut être ``tex'', ``dvi'', ``ps'', ou ``pdf''.
--latex=commande_latex_alternative, -x
Cette option est actuellement pour le coréen et le japonais. La commande_latex_alternative peut être ``latex'' (par défaut), ``hlatexp'' (pour le coréen), ``platex'' ou ``jlatex'' (pour le japonais). Cette option peut être utilisée pour rendre un document coréen en utilisant HLaTeXp, ou pour rendre un document japonais en utilisant pLaTeX/jLaTeX. Sinon, HLaTeX doit être installé pour rendre un document coréen. D'autre part, un document japonais peut être rendu avec jLaTeX
(qui est le défaut quand ``-c nippon'' est spécifié), donc si vous avez déjà jLaTeX, vous n'aurez peut-être pas besoin d'installer pLaTeX.
--dvips=commande_dvips_alternative, -s
Cette option est actuellement pour le japonais. La commande_dvips_alternative peut être ``dvips'' ou ``dvi2ps''. Si vous ne savez pas, alors vous n'en avez peut-être pas besoin.
--verbosity, -V
Définit la verbosité. '0' (par défaut) affichera des informations sur l'exécution LaTeX uniquement en cas d'erreurs. '1' affichera toujours des informations pour la dernière exécution. '2' affichera des informations pour toutes les exécutions.


****************************************************

linuxdoc -B lyx (sgml2lyx) convertit un fichier source SGML de la DTD LinuxDoc en sortie LyX. La sortie apparaîtra dans fichier.lyx où fichier est le nom du fichier source SGML.

La paire attribut/valeur "output=lyx" est définie pour les conditionnels.

linuxdoc -B lyx n'a pas d'options spécifiques au backend.


****************************************************

linuxdoc -B rtf (sgml2rtf) convertit un fichier source SGML de la DTD LinuxDoc en RTF, le format texte enrichi (Rich Text Format) utilisé par le système d'aide de Microsoft Windows. La sortie apparaîtra dans le fichier de niveau supérieur fichier.rtf et fichier-n.rtf pour chaque section, où fichier est le nom du fichier source SGML. La sortie RTF est adaptée à la compilation par le compilateur d'aide Windows (hc31.exe).

La paire attribut/valeur "output=rtf" est définie pour les conditionnels.

linuxdoc -B rtf accepte [--twosplit] comme une option spécifique au backend. Voici la signification de cette option :

--twosplit, -2
Divise les fichiers à la fois aux sections n. et aux sous-sections n.m.


****************************************************

linuxdoc -B txt (sgml2txt) convertit un fichier source SGML de la DTD LinuxDoc en sortie ASCII, ISO-8859-1, ou EUC-JP. La sortie apparaîtra dans fichier.txt où fichier est le nom du fichier source SGML.

La paire attribut/valeur "output=txt" est définie pour les conditionnels.

linuxdoc -B txt accepte les options de backend suivantes : [--manpage] [--filter] [--blanks=n]

La signification de ces options est :

--manpage, -m
Produit un fichier source groff, adapté à la mise en forme avec groff -man pour les pages de manuel.
--filter, -f
Supprime les surimpressions de retour arrière de la forme intermédiaire générée par groff(1).
--pass, -P
L'argument de l'option de passe est ajouté aux options de ligne de commande transmises à groff(1).
--blanks=n, -b
Définit la limite des lignes blanches continues pour la génération du document de sortie. La limite par défaut est de 3. Si 0 (zéro) est spécifié, le résultat aura de nombreuses lignes blanches continues.


****************************************************

linuxdoc -B check (sgmlcheck) exécute une analyse SGML sur la source du document spécifié. Toutes les erreurs sont rapportées sur la sortie standard. Aucune version formatée de la source n'est produite.

Notez que linuxdoc -B check prétraite la source SGML de la DTD LinuxDoc, effectuant la conditionnalisation décrite par les balises <#if></#if> et <#unless></#unless>. Les sources de documents contenant ces balises confondront un analyseur SGML autonome. linuxdoc -B check n'a pas d'options spécifiques au backend.
****************************************************
