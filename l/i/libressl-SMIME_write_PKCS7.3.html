SMIME_WRITE_PKCS7(3) Manuel des fonctions de bibliothèque SMIME_WRITE_PKCS7(3)

NOM

SMIME_write_PKCS7 — convertit une structure PKCS#7 au format S/MIME

SYNTAXE

bibliothèque «libcrypto»
#include <openssl/pkcs7.h>

int
SMIME_write_PKCS7(BIO *out, PKCS7 *p7, BIO *data, int flags);

DESCRIPTION

SMIME_write_PKCS7() génère un message S/MIME sur out en écrivant des en-têtes MIME 1.0 suivis d'une sérialisation de p7 encodée en BER et en base64. L'encodage BER utilise le format DER, sauf comme décrit pour PKCS7_STREAM ci-dessous. Si le streaming est activé, le contenu doit être fourni dans l'argument data.

Les flags peuvent être l'OU logique de zéro ou plusieurs des bits suivants :

PKCS7_DETACHED
Utilise la signature en texte clair et génère un message S/MIME "multipart/signed". Le contenu est lu à partir de data. Si data est un pointeur NULL, ce drapeau est ignoré.

Ce drapeau n'est pris en charge que pour signedData où PKCS7_DETACHED est également défini lors de l'appel à PKCS7_sign(3).

Si PKCS7_STREAM n'est pas défini, les données doivent être lues deux fois : une fois pour calculer la signature dans PKCS7_sign(3) et une fois pour écrire le message S/MIME.

Si PKCS7_DETACHED est ignoré ou non spécifié, le type smime est choisi en fonction du type de p7 :

NID_pkcs7_enveloped
"enveloped-data"
NID_pkcs7_signed
"signed-data"
si p7 spécifie un algorithme de hachage
"certs-only"
sinon
NID_id_smime_ct_compressedData
"compressed-data"
PKCS7_REUSE_DIGEST
Ignore les appels à PKCS7_dataInit(3) et PKCS7_dataFinal(3). Ce drapeau n'a aucun effet sauf si PKCS7_DETACHED est également défini.
PKCS7_STREAM
Effectue le streaming en lisant le contenu à partir de data. Cela ne fonctionne que si PKCS7_DETACHED n'est pas spécifié.

Ce drapeau ne doit être défini que si PKCS7_STREAM a également été défini dans l'appel précédent à PKCS7_sign(3) ou PKCS7_encrypt(3).

Le contenu est écrit au format BER en utilisant un encodage construit de longueur indéfinie, sauf dans le cas de données signées avec contenu détaché où le contenu est absent et le format DER est utilisé.

PKCS7_TEXT
Prépare la ligne "Content-Type: text/plain" au contenu. Cela n'a de sens que si PKCS7_DETACHED est également défini. Ceci est ignoré si le drapeau SMIME_BINARY est également défini.
SMIME_BINARY
Si spécifié, ce drapeau est transmis à SMIME_crlf_copy(3).
SMIME_CRLFEOL
Termine les lignes d'en-tête MIME par des paires de caractères retour chariot et nouvelle ligne. Par défaut, aucun caractère retour chariot n'est écrit et les lignes d'en-tête se terminent par des caractères de nouvelle ligne uniquement.
SMIME_OLDMIME
Si ce bit est défini dans l'argument flags, "application/pkcs7-mime" ou "application/pkcs7-signature" est utilisé dans les en-têtes Content-Type. Sinon, "application/x-pkcs7-mime" ou "application/x-pkcs7-signature" est utilisé.

VALEURS DE RETOUR

SMIME_write_PKCS7() est censé retourner 1 en cas de succès ou 0 en cas d'échec.

VOIR AUSSI

BIO_f_base64(3), BIO_new(3), i2d_PKCS7_bio_stream(3), PEM_write_bio_PKCS7_stream(3), PEM_write_PKCS7(3), PKCS7_final(3), PKCS7_new(3), SMIME_crlf_copy(3), SMIME_read_PKCS7(3), SMIME_write_CMS(3)

HISTORIQUE

SMIME_write_PKCS7() est apparu pour la première fois dans OpenSSL 0.9.5 et est disponible depuis OpenBSD 2.7.

BOGUES

SMIME_write_PKCS7() ignore la plupart des erreurs et renverra probablement 1 même après avoir produit une sortie corrompue ou incomplète.

SMIME_write_PKCS7() encode toujours les structures PKCS#7 en base64. Il devrait y avoir une option pour désactiver cela.
