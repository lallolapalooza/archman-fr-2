DESCRIPTION

BN_is_prime_ex() et BN_is_prime_fasttest_ex() testent si le nombre a est premier. Dans LibreSSL, les deux fonctions se comportent de manière identique et utilisent l'algorithme de Baillie-Pomerance-Selfridge-Wagstaff combiné avec checks rounds de Miller-Rabin. L'argument do_trial_division est ignoré.

Il est inconnu si un nombre composé existe et que l'algorithme Baillie-PSW classe à tort comme premier. Certains pensent qu'il pourrait exister une infinité de tels nombres, mais aucun n'est connu actuellement. Il est connu qu'aucun tel nombre n'existe en dessous de 2^64.

Afin de réduire la probabilité qu'un nombre composé passe les tests de primalité de BN_is_prime_fasttest_ex() et BN_is_prime_ex(), un certain nombre de rounds du test probabiliste de Miller-Rabin est effectué. Si checks est positif, il est utilisé comme nombre de rounds ; s'il est zéro ou la valeur spéciale BN_prime_checks, un nombre approprié de rounds est calculé à partir de la longueur en bits de a.

Si NULL est passé pour l'argument ctx, ces fonctions allouent un objet BN_CTX en interne lorsqu'elles en ont besoin et le libèrent avant de retourner. Alternativement, pour économiser la surcharge d'allocation et de libération de cet objet pour chaque appel, l'appelant peut pré-allouer un objet BN_CTX et le passer dans l'argument ctx.

BN_generate_prime_ex() génère un nombre premier pseudo-aléatoire d'une longueur d'au moins bits bits et le place dans ret. La primalité de ret est testée en interne en utilisant BN_is_prime_ex(). Par conséquent, pour des bits supérieurs à 64, il est théoriquement possible que cette fonction place un nombre composé dans ret ; la probabilité d'un tel événement est inconnue mais très faible.

Le nombre premier peut devoir satisfaire des exigences supplémentaires pour être utilisé dans l'échange de clés Diffie-Hellman :

  • Si modulus n'est pas NULL, un nombre premier est généré qui satisfait la condition ret % modulus = remainder. Si l'argument remainder est NULL, 1 est utilisé comme reste désiré.
  • Si l'argument safe est non nul, un nombre premier sûr est généré, c'est-à-dire que (ret - 1)/2 est également premier.

Si cb n'est pas NULL, il est utilisé comme suit :

  • BN_GENCB_call(cb, 0, serial_number) est appelé après la génération d'un nombre premier potentiel.
  • Le state_code de 1 est réservé pour les callbacks pendant le test de primalité, mais LibreSSL n'effectue aucun de ces callbacks.
  • Lorsque safe est non nul et qu'un nombre premier sûr a été trouvé, BN_GENCB_call(cb, 2, serial_number) est appelé.
  • Les appelants de BN_generate_prime_ex() peuvent appeler BN_GENCB_call() avec d'autres valeurs comme décrit dans leurs pages de manuel respectives ; voir VOIR AUSSI.

Dans tous les cas, le serial_number est le nombre de candidats qui ont déjà été écartés pour ne pas être premiers ; c'est-à-dire que serial_number est 0 pour le premier candidat et est ensuite incrémenté chaque fois qu'un nouveau candidat est généré.

BN_GENCB_call() appelle la fonction de rappel contenue dans cb et passe le state_code et le serial_number comme arguments. Si cb est NULL ou ne contient pas de fonction de rappel, aucune action n'est effectuée.

BN_GENCB_new() alloue un nouvel objet BN_GENCB.

BN_GENCB_free() libère cb. Si cb est NULL, aucune action n'est effectuée.

BN_GENCB_set() initialise cb pour utiliser le pointeur de fonction de rappel cb_fp et l'argument de rappel supplémentaire cb_arg.

La fonction obsolète BN_GENCB_set_old() initialise cb pour utiliser le pointeur de fonction de rappel de style ancien cb_fp et l'argument de rappel supplémentaire cb_arg.

VALEURS DE RETOUR

BN_is_prime_ex() et BN_is_prime_fasttest_ex() retournent 0 si le nombre est composé, 1 s'il est premier avec une probabilité d'erreur très faible, ou -1 en cas d'erreur.

BN_generate_prime_ex() retourne 1 en cas de succès ou 0 en cas d'erreur.

BN_GENCB_call() retourne 1 en cas de succès, y compris lorsque cb est NULL ou ne contient pas de fonction de rappel, ou 0 en cas d'erreur.

NAME

BN_generate_prime, BN_GENCB, BN_GENCB_call, BN_GENCB_free, BN_GENCB_get_arg, BN_GENCB_new, BN_GENCB_set, BN_GENCB_set_old - generate a prime number

SYNOPSIS

#include <openssl/bn.h>

int BN_generate_prime_ex(BIGNUM *ret, int bits, int safe, BIGNUM *add, BIGNUM *rem, BN_GENCB *cb);
int BN_is_prime_ex(const BIGNUM *p, int nchecks, BN_CTX *ctx, BN_GENCB *cb);
int BN_is_prime_fasttest_ex(const BIGNUM *p, int nchecks, BN_CTX *ctx, int do_trial_division, BN_GENCB *cb);

BN_GENCB *BN_GENCB_new(void);
void BN_GENCB_free(BN_GENCB *cb);
int BN_GENCB_get_arg(BN_GENCB *cb);
void BN_GENCB_set(BN_GENCB *cb, int (*callback)(int, int, void *), void *arg);
void BN_GENCB_set_old(BN_GENCB *cb, int (*callback)(int, int), void *arg);
int BN_GENCB_call(BN_GENCB *cb, int p1, int p2);

DESCRIPTION

The BN_generate_prime_ex() function generates a prime number of bits length and stores it in ret. If safe is non-zero, a safe prime is generated (a prime p such that p = 2*q + 1 where q is also prime). If add is non-NULL, the generated prime will be equal to add + rem (mod 2^bits). If rem is non-NULL, the generated prime will be equal to add + rem (mod 2^bits).

BN_is_prime_ex() tests if p is prime. nchecks is the number of probabilistic checks to perform. If cb is not NULL, it is a callback function that is called during the primality test.

BN_is_prime_fasttest_ex() performs a quick primality test on p. nchecks is the number of Miller-Rabin checks to perform. If do_trial_division is true, trial division is performed first. If cb is not NULL, it is a callback function that is called during the primality test.

The BN_GENCB_new() function allocates and initialises a new BN_GENCB structure.

The BN_GENCB_free() function frees the memory associated with cb.

The BN_GENCB_set() and BN_GENCB_set_old() functions set the callback function and user data pointer arg in the cb structure.

The BN_GENCB_call() function calls the callback function set in cb with parameters p1 and p2.

RETURN VALUES

BN_generate_prime_ex(), BN_is_prime_ex(), and BN_is_prime_fasttest_ex() return 1 on success, or 0 on failure.

BN_GENCB_new() returns a pointer to the newly allocated BN_GENCB object or NULL if memory allocation fails.

The callback functions pointed to by the cb_fp arguments are supposed to return 1 on success or 0 on error.

BN_GENCB_get_arg() returns the cb_arg pointer that was previously stored in cb using BN_GENCB_set() or BN_GENCB_set_old().

In some cases, error codes can be obtained by ERR_get_error(3).

HISTORY

BN_generate_prime_ex(), BN_is_prime_ex(), BN_is_prime_fasttest_ex(), BN_GENCB_call(), BN_GENCB_set_old(), and BN_GENCB_set() first appeared in OpenSSL 0.9.8 and have been available since OpenBSD 4.5.

BN_GENCB_new(), BN_GENCB_free(), and BN_GENCB_get_arg() first appeared in OpenSSL 1.1.0 and have been available since OpenBSD 6.3.
