DESCRIPTION

Le type de données ASN1_TYPE et la constante d'identifiant de type V_ASN1_ANY représentent le type ANY d'ASN.1. Un objet ASN1_TYPE peut stocker une valeur ASN.1 de type arbitraire, y compris des types construits tels qu'une SÉQUENCE. Il mémorise également en interne le type qu'il contient actuellement.

ASN1_TYPE_new() alloue et initialise un objet ASN1_TYPE vide de type V_ASN1_UNDEF.

ASN1_TYPE_free() libère a, y compris la valeur qui y est stockée, le cas échéant. Si a est un pointeur NULL, aucune action n'est effectuée.

ASN1_TYPE_get() renvoie le type actuellement contenu par a, représenté par l'une des constantes V_ASN1_* définies dans <openssl/asn1.h>.

ASN1_TYPE_set() libère la valeur contenue dans a, le cas échéant, et définit la valeur et le type maintenant contenus dans a. Cette fonction utilise le pointeur value en interne, il ne doit donc pas être libéré après l'appel.

ASN1_TYPE_set1() définit le type contenu par a à type et sa valeur à une copie de value. Si la copie réussit, la valeur précédente contenue dans a est libérée. Si la copie échoue, a reste inchangé.

Le type et la signification de l'argument value de ASN1_TYPE_set() et ASN1_TYPE_set1() sont déterminés par l'argument type. Si type est V_ASN1_NULL, value est ignoré. Si type est V_ASN1_BOOLEAN, alors la valeur booléenne est définie sur VRAI si value n'est pas NULL. Si type est V_ASN1_OBJECT, alors value est une structure ASN1_OBJECT. Sinon, type est une structure ASN1_STRING. Si type correspond à un type primitif ou à un type chaîne, alors le contenu de ASN1_STRING contient les octets de contenu du type. Si type correspond à un type construit ou à un type étiqueté (V_ASN1_SEQUENCE, V_ASN1_SET, ou V_ASN1_OTHER), alors ASN1_STRING contient l'encodage ASN.1 complet tel quel, y compris les octets d'étiquette et de longueur.

ASN1_TYPE_set_octetstring() alloue un nouvel objet ASN1_OCTET_STRING, copie len octets de data dedans en utilisant ASN1_STRING_set(3), et remplace la valeur de a par celle-ci en appelant ASN1_TYPE_set() avec un type de V_ASN1_OCTET_STRING.

ASN1_TYPE_get_octetstring() copie le contenu de l'objet ASN1_OCTET_STRING contenu dans a, mais pas plus de buflen octets, dans le buffer fourni par l'appelant.

ASN1_TYPE_set_int_octetstring() libère la valeur contenue dans a, le cas échéant, définit son type à V_ASN1_SEQUENCE, et définit sa valeur à une séquence ASN.1 à deux éléments composée d'un objet INTEGER ASN.1 avec la valeur num et d'un objet OCTET STRING ASN.1 contenant une copie des len octets pointés par data.

ASN1_TYPE_get_int_octetstring() copie la valeur entière du premier élément de la séquence ASN.1 a dans *num si num n'est pas un pointeur NULL, et copie la valeur de chaîne d'octets du second élément, mais pas plus de buflen octets, dans le buffer fourni par l'appelant si buffer n'est pas un pointeur NULL.

ASN1_TYPE_cmp() vérifie que a et b contiennent le même type, la même valeur et sont encodés de la même manière.

Si les types concordent et que les valeurs ont la même signification mais sont encodées différemment, elles sont considérées comme différentes. Par exemple, une valeur booléenne est représentée à l'aide d'un seul octet de contenu. Sous BER, tout octet non nul représente la valeur VRAI, mais ASN1_TYPE_cmp() ne signalera une correspondance que si l'octet de contenu est le même.

SYNOPSIS

#include <openssl/asn1.h>
ASN1_TYPE *ASN1_TYPE_new(void);
void ASN1_TYPE_free(ASN1_TYPE *a);
int ASN1_TYPE_set(ASN1_TYPE *c, int type, void *data);
int ASN1_TYPE_set1(ASN1_TYPE *c, int type, const void *data);
int ASN1_TYPE_get(ASN1_TYPE *a);
int ASN1_TYPE_set_octetstring(ASN1_TYPE *c, const unsigned char *data, int len);
int ASN1_TYPE_get_octetstring(ASN1_TYPE *a, unsigned char *buffer, int buflen);
int ASN1_TYPE_set_int_octetstring(ASN1_TYPE *c, long type, const unsigned char *data, int len);
int ASN1_TYPE_get_int_octetstring(ASN1_TYPE *a, long *ptype, unsigned char *buffer, int buflen);
int ASN1_TYPE_cmp(const ASN1_TYPE *a, const ASN1_TYPE *b);

DESCRIPTION

The ASN.1 type system allows a value to be of one of several possible types. This is represented by the ASN1_TYPE structure.

ASN1_TYPE_new() allocates and initialises a new ASN1_TYPE object.

ASN1_TYPE_free() frees the ASN1_TYPE object a.

ASN1_TYPE_set() sets the type of c to type and the value to data. Note that this function makes a copy of data. This may be an issue for large data blobs.

ASN1_TYPE_set1() is similar to ASN1_TYPE_set() but it makes a duplicate of data using the appropriate ASN1 duplication function, for example ASN1_STRING_dup() for V_ASN1_OCTET_STRING.

ASN1_TYPE_get() returns the type currently held by a. The value V_ASN1_NULL is returned if the type is NULL.

Note that ASN1_TYPE_set() and ASN1_TYPE_set1() set the type field in the ASN1_TYPE structure to the value of the type argument. This argument should be one of the V_ASN1_* constants defined in <openssl/asn1.h>. However, the data argument is a generic void * pointer. The actual type of data depends on the value of type. For example, if type is V_ASN1_OCTET_STRING, then data should be a pointer to an ASN1_OCTET_STRING structure. If type is V_ASN1_INTEGER, then data should be a pointer to an ASN1_INTEGER structure. If type is V_ASN1_OBJECT_IDENTIFIER, then data should be a pointer to an ASN1_OBJECT structure. If type is V_ASN1_UTF8STRING, V_ASN1_PRINTABLESTRING, etc., then data should be a pointer to an ASN1_STRING structure.

ASN1_TYPE_set_octetstring() and ASN1_TYPE_get_octetstring() are convenience functions for setting and getting OCTET STRING types.

ASN1_TYPE_set_int_octetstring() and ASN1_TYPE_get_int_octetstring() are convenience functions for setting and getting ASN.1 sequences containing an integer and an octet string. The integer is intended to be the type tag, for example V_ASN1_OBJECT_IDENTIFIER.

ASN1_TYPE_cmp() compares two ASN1_TYPE objects a and b. It returns 0 if they are equal, and non-zero otherwise. The comparison considers the type and the value of the ASN.1 objects. Note that this comparison does not handle the case where both types are absent or NULL correctly. The arguments are NULL, the two types could be absent OPTIONAL fields and so should match, however passing NULL values could also indicate a programming error (for example an unparsable type which returns NULL) for types which do not match. So applications should handle the case of two absent values separately.

RETURN VALUES

ASN1_TYPE_new() returns the new ASN1_TYPE object or NULL if an error occurs.

ASN1_TYPE_get() returns the type currently held by a or 0 if an error occurs. The latter can happen if a does not contain a value even though its type is not V_ASN1_NULL. For example, it will always happen for empty objects newly constructed with ASN1_TYPE_new().

ASN1_TYPE_set1(), ASN1_TYPE_set_octetstring(), and ASN1_TYPE_set_int_octetstring() return 1 on success or 0 on failure.

ASN1_TYPE_get_octetstring() returns the number of data bytes contained in the ASN1_OCTET_STRING object contained in a or -1 if a is not of the type V_ASN1_OCTET_STRING or does not contain any object. If the return value is greater than the buflen argument, the content was truncated when copied to the buffer.

ASN1_TYPE_get_int_octetstring() returns the number of data bytes contained in the ASN1_OCTET_STRING object that is the second element of the ASN.1 sequence a or -1 if a is not of the type V_ASN1_SEQUENCE or if decoding fails. If the return value is greater than the buflen argument, the content was truncated when copied to the buffer.

ASN1_TYPE_cmp() returns 0 for a match or non-zero for a mismatch.

HISTORY

ASN1_TYPE_new() and ASN1_TYPE_free() first appeared in SSLeay 0.5.1, ASN1_TYPE_get() and ASN1_TYPE_set() in SSLeay 0.8.0, and ASN1_TYPE_set_octetstring(), ASN1_TYPE_get_octetstring(), ASN1_TYPE_set_int_octetstring(), and ASN1_TYPE_get_int_octetstring() in SSLeay 0.9.0. These functions have been available since OpenBSD 2.4.

ASN1_TYPE_set1() first appeared in OpenSSL 0.9.8h and has been available since OpenBSD 4.5.

ASN1_TYPE_cmp() first appeared in OpenSSL 0.9.8zd, 1.0.0p, and 1.0.1k and has been available since OpenBSD 4.9.
