libressl-OPENSSL_init_crypto(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

OPENSSL_INIT_CRYPTO(3) Manuel des fonctions de bibliothèque OPENSSL_INIT_CRYPTO(3)

NOM

OPENSSL_init_crypto, OPENSSL_init — initialiser la bibliothèque cryptographique

SYNOPIS

bibliothèque «libcrypto»
#include <openssl/crypto.h>

int
OPENSSL_init_crypto(uint64_t options, const void *dummy);

void
OPENSSL_init(void);

DESCRIPTION

Ces fonctions sont dépréciées. Il n'est jamais utile pour un programme d'application d'en appeler une explicitement.

La bibliothèque appelle automatiquement OPENSSL_init_crypto() en interne avec un argument options de 0 chaque fois que nécessaire. Il est plus sûr de supposer que toute fonction peut le faire.

Pour activer ou désactiver le fichier de configuration standard, utilisez plutôt OPENSSL_config(3) ou OPENSSL_no_config(3), respectivement. Pour charger un fichier de configuration non standard, référez-vous à CONF_modules_load_file(3).

Si OPENSSL_init_crypto() est appelée avant toute autre fonction cryptographique ou ssl, la bibliothèque cryptographique est initialisée en allouant diverses ressources internes, notamment en appelant ERR_load_crypto_strings(3).

Les options suivantes sont prises en charge :

OPENSSL_INIT_LOAD_CONFIG
À la fin de l'initialisation, appelez OPENSSL_config(3) avec un argument NULL, chargeant le fichier de configuration par défaut.
OPENSSL_INIT_NO_LOAD_CONFIG
Ignorez tous les appels ultérieurs à OPENSSL_config(3).

Les autres indicateurs options définis par OpenSSL sont tous ignorés par LibreSSL. L'argument dummy n'a aucun effet.

Si cette fonction est appelée plus d'une fois, aucun des appels, sauf le premier, n'a d'effet.

OPENSSL_init() n'a aucun effet.

VALEURS DE RETOUR

OPENSSL_init_crypto() est destiné à retourner 1 en cas de succès ou 0 en cas d'erreur.

VOIR AUSSI

CONF_modules_load_file(3), OPENSSL_config(3), openssl.cnf(5)

HISTORIQUE

OPENSSL_init() est apparu pour la première fois dans OpenSSL 1.0.0e et est disponible depuis OpenBSD 5.3. Il a cessé d'avoir un effet dans OpenSSL 1.1.1 et dans OpenBSD 5.6.

OPENSSL_init_crypto() est apparu pour la première fois dans OpenSSL 1.1.0 et est disponible depuis OpenBSD 6.3.

BOGUES

OPENSSL_init_crypto() ignore silencieusement presque toutes sortes d'erreurs. En particulier, si l'allocation de mémoire échoue, l'initialisation risque de rester incomplète, la bibliothèque peut être dans un état interne incohérent, mais la valeur de retour indiquera généralement le succès. Il n'y a aucun moyen pour le programme d'application de savoir si l'initialisation de la bibliothèque est réellement complète, ni de revenir à un état cohérent si ce n'est pas le cas.
