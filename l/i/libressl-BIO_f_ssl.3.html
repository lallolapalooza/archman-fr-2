DESCRIPTION

BIO_f_ssl() renvoie la méthode BIO SSL. Il s'agit d'un BIO filtre qui est une enveloppe des routines SSL d'OpenSSL, ajoutant une « saveur » de BIO aux entrées/sorties SSL.

Les entrées/sorties effectuées sur un BIO SSL communiquent en utilisant le protocole SSL avec les BIO de lecture et d'écriture du SSL. Si une connexion SSL n'est pas établie, une tentative est faite pour en établir une lors du premier appel d'entrée/sortie.

Si un BIO est ajouté à un BIO SSL à l'aide de BIO_push(3), il est automatiquement utilisé comme BIO de lecture et d'écriture du BIO SSL.

Appeler BIO_reset(3) sur un BIO SSL ferme toute connexion SSL en cours en appelant SSL_shutdown(3). BIO_reset(3) est ensuite envoyé au BIO suivant dans la chaîne ; cela déconnectera typiquement le transport sous-jacent. Le BIO SSL est alors réinitialisé à l'état initial d'acceptation ou de connexion.

Si l'indicateur de fermeture est défini lors de la libération d'un BIO SSL, la structure SSL interne est également libérée à l'aide de SSL_free(3).

BIO_set_ssl() définit le pointeur SSL interne du BIO b à ssl en utilisant l'indicateur de fermeture c.

BIO_get_ssl() récupère le pointeur SSL du BIO b ; il peut ensuite être manipulé à l'aide des fonctions de la bibliothèque SSL standard.

BIO_set_ssl_mode() définit le mode du BIO SSL à client. Si client vaut 1, le mode client est défini. Si client vaut 0, le mode serveur est défini.

BIO_set_ssl_renegotiate_bytes() définit le nombre d'octets de renégociation à num. Lorsqu'il est défini, après chaque num octets d'entrée/sortie (lecture et écriture), la session SSL est automatiquement renégociée. num doit être d'au moins 512 octets.

BIO_set_ssl_renegotiate_timeout() définit le délai de renégociation à seconds. Lorsque le délai de renégociation expire, la session est automatiquement renégociée.

BIO_get_num_renegotiates() renvoie le nombre total de renégociations de session dues aux entrées/sorties ou au délai d'attente.

BIO_new_ssl() alloue un BIO SSL en utilisant SSL_CTX ctx et en utilisant le mode client si client est non nul.

BIO_new_ssl_connect() crée une nouvelle chaîne de BIO constituée d'un BIO SSL (utilisant ctx) suivi d'un BIO de connexion.

BIO_new_buffer_ssl_connect() crée une nouvelle chaîne de BIO constituée d'un BIO tamponné, d'un BIO SSL (utilisant ctx) et d'un BIO de connexion.

BIO_ssl_copy_session_id() copie un identifiant de session SSL entre les chaînes de BIO from et to. Elle le fait en localisant les BIO SSL dans chaque chaîne et en appelant SSL_copy_session_id(3) sur le pointeur SSL interne.

BIO_ssl_shutdown() ferme une connexion SSL sur la chaîne de BIO bio. Elle le fait en localisant le BIO SSL dans la chaîne et en appelant SSL_shutdown(3) sur son pointeur SSL interne.

BIO_do_handshake() tente de terminer une négociation SSL sur le BIO fourni et d'établir la connexion SSL. Il renvoie 1 si la connexion a été établie avec succès. Une valeur zéro ou négative est renvoyée si la connexion n'a pas pu être établie ; l'appel

DESCRIPTION

BIO_f_ssl() returns a pointer to a static BIO_METHOD structure that may be used to create an SSL BIO, i.e.

BIO_new_fp(NULL, BIO_NOCLOSE), BIO_push(BIO_f_ssl(), BIO_new_socket(sock, BIO_NOCLOSE)).

BIO_new_ssl(ctx, client) returns a pointer to a new SSL BIO chain. The SSL context is given by ctx and the client flag should be set to 1 for a client, or 0 for a server.

BIO_new_ssl_connect(ctx) returns a pointer to a new SSL BIO chain. This is similar to BIO_new_ssl() except that it also includes a connect BIO and the underlying SSL BIO is configured as a client.

BIO_new_buffer_ssl_connect(ctx) is the same as BIO_new_ssl_connect() except that it also includes a buffering BIO.

BIO_ssl_copy_session_id(to, from) copies the session ID from the SSL object in the BIO in from to the SSL object in the BIO in to.

BIO_ssl_shutdown(bio) performs an SSL shutdown on the given BIO.

BIO_get_ssl(bio, sslp) retrieves the SSL object from the BIO in bio and stores it in the location pointed to by sslp.

BIO_set_ssl_mode(bio, mode) sets the SSL mode for the BIO to mode. The mode can be either SSL_MODE_SERVER or SSL_MODE_CLIENT.

BIO_set_ssl_renegotiate_bytes(bio, num) sets the number of bytes after which a renegotiation will be triggered to num. A value of 0 disables this feature.

BIO_set_ssl_renegotiate_timeout(bio, seconds) sets the timeout in seconds after which a renegotiation will be triggered to seconds. A value of 0 disables this feature.

BIO_get_num_renegotiates(bio) returns the current number of renegotiations that have occurred.

BIO_do_handshake(bio) performs the SSL handshake.

BIO_should_retry(3) should be used for non blocking connect BIOs to determine if the call should be retried. If an SSL connection has already been established, this call has no effect.

When a chain containing an SSL BIO is copied with BIO_dup_chain(3), SSL_dup(3) is called internally to copy the SSL object from the existing BIO object to the new BIO object, and the internal data related to BIO_set_ssl_renegotiate_bytes() and BIO_set_ssl_renegotiate_timeout() is also copied.

SSL BIOs are exceptional in that if the underlying transport is non-blocking they can still request a retry in exceptional circumstances. Specifically this will happen if a session renegotiation takes place during a BIO_read(3) operation. One case where this happens is when step up occurs.

In OpenSSL 0.9.6 and later the SSL flag SSL_AUTO_RETRY can be set to disable this behaviour. In other words, when this flag is set an SSL BIO using a blocking transport will never request a retry.

Since unknown BIO_ctrl(3) operations are sent through filter BIOs, the server name and port can be set using BIO_set_conn_hostname(3) and BIO_set_conn_port(3) on the BIO returned by BIO_new_ssl_connect() without having to locate the connect BIO first.

Applications do not have to call BIO_do_handshake() but may wish to do so to separate the handshake process from other I/O processing.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), BIO_get_num_renegotiates(), and BIO_do_handshake() are implemented as macros.

RETURN VALUES

BIO_f_ssl() returns a pointer to a static BIO_METHOD structure.

When called on an SSL BIO object, BIO_method_type(3) returns the constant BIO_TYPE_SSL and BIO_method_name(3) returns a pointer to the static string "ssl".

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), and BIO_get_num_renegotiates() return 1 on success or a value less than or equal to 0 if an error occurred.

BIO_new_ssl(), BIO_new_ssl_connect(), and BIO_new_buffer_ssl_connect() returns a pointer to a newly allocated BIO chain or NULL if an error occurred.

BIO_ssl_copy_session_id() returns 1 on success or 0 on error.

BIO_do_handshake() returns 1 if the connection was established successfully or a value less than or equal to 0 otherwise.

EXAMPLES

This SSL/TLS client example attempts to retrieve a page from an SSL/TLS web server. The I/O routines are identical to those of the unencrypted example in BIO_s_connect(3).

BIO *sbio, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;

ERR_load_crypto_strings();
ERR_load_SSL_strings();
OpenSSL_add_all_algorithms();

/*
 * We would seed the PRNG here if the platform didn't do it automatically
 */

ctx = SSL_CTX_new(SSLv23_client_method());

/*
 * We'd normally set some stuff like the verify paths and mode here because
 * as things stand this will connect to any server whose certificate is
 * signed by any CA.
 */

sbio = BIO_new_ssl_connect(ctx);

BIO_get_ssl(sbio, &ssl);

if (!ssl) {
	fprintf(stderr, "Can't locate SSL pointer\n");
	/* whatever ... */
}

/* Don't want any retries */
SSL_set_mode(ssl, SSL_MODE_AUTO_RETRY);

/* We might want to do other things with ssl here */

BIO_set_conn_hostname(sbio, "localhost:https");

out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(sbio) <= 0) {
	fprintf(stderr, "Error connecting to server\n");
	ERR_print_errors_fp(stderr);
	/* whatever ... */
}

if (BIO_do_handshake(sbio) <= 0) {
	fprintf(stderr, "Error establishing SSL connection\n");
	ERR_print_errors_fp(stderr);
	/* whatever ... */
}

/* Could examine ssl here to get connection info */

BIO_puts(sbio, "GET / HTTP/1.0\n\n");
for (;;) {
	len = BIO_read(sbio, tmpbuf, 1024);
	if(len <= 0) break;
	BIO_write(out, tmpbuf, len);
}
BIO_free_all(sbio);
BIO_free(out);

Here is a simple server example. It makes use of a buffering BIO to allow lines to be read from the SSL BIO using BIO_gets(3). It creates a pseudo web page containing the actual request from a client and also echoes the request to standard output.

BIO *sbio, *bbio, *acpt, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;

ctx = SSL_CTX_new(SSLv23_server_method());

if (!SSL_CTX_use_certificate_file(ctx,"server.pem",SSL_FILETYPE_PEM)
    || !SSL_CTX_use_PrivateKey_file(ctx,"server.pem",SSL_FILETYPE_PEM)
    || !SSL_CTX_check_private_key(ctx)) {
	fprintf(stderr, "Error setting up SSL_CTX\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

/*
 * Might do other things here like setting verify locations and DH and/or
 * RSA temporary key callbacks
 */

/* New SSL BIO setup as server */
sbio = BIO_new_ssl(ctx,0);

BIO_get_ssl(sbio, &ssl);

if (!ssl) {
	fprintf(stderr, "Can't locate SSL pointer\n");
	/* whatever ... */
}

/* Don't want any retries */
SSL_set_mode(ssl, SSL_MODE_AUTO_RETRY);

/* Create the buffering BIO */

bbio = BIO_new(BIO_f_buffer());

/* Add to chain */
sbio = BIO_push(bbio, sbio);

acpt = BIO_new_accept("4433");

/*
 * By doing this when a new connection is established we automatically
 * have sbio inserted into it. The BIO chain is now 'swallowed' by the
 * accept BIO and will be freed when the accept BIO is freed.
 */

BIO_set_accept_bios(acpt,sbio);

out = BIO_new_fp(stdout, BIO_NOCLOSE);

/* Wait for incoming connection */
if (BIO_do_accept(acpt) <= 0) {
	fprintf(stderr, "Error setting up accept BIO\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

/* We only want one connection so remove and free accept BIO */

sbio = BIO_pop(acpt);

BIO_free_all(acpt);

if (BIO_do_handshake(sbio) <= 0) {
	fprintf(stderr, "Error in SSL handshake\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

BIO_puts(sbio, "HTTP/1.0 200 OK\r\nContent-type: text/plain\r\n\r\n");
BIO_puts(sbio, "\r\nConnection Established\r\nRequest headers:\r\n");
BIO_puts(sbio, "--------------------------------------------------\r\n");

for (;;) {
	len = BIO_gets(sbio, tmpbuf, 1024);
	if (len <= 0)
		break;
	BIO_write(sbio, tmpbuf, len);
	BIO_write(out, tmpbuf, len);
	/* Look for blank line signifying end of headers */
	if ((tmpbuf[0] == '\r') || (tmpbuf[0] == '\n'))
		break;
}

BIO_puts(sbio, "--------------------------------------------------\r\n");
BIO_puts(sbio, "\r\n");

/* Since there is a buffering BIO present we had better flush it */
BIO_flush(sbio);

BIO_free_all(sbio);

NOM

BIO_f_ssl - Interface BIO pour les sockets SSL/TLS

SYNOPSIS

#include <openssl/bio.h>
#include <openssl/ssl.h>

BIO *BIO_f_ssl(void);

DESCRIPTION

L'interface BIO BIO_f_ssl() crée un objet BIO qui encapsule un autre objet BIO et gère les opérations SSL/TLS sur celui-ci.

Lorsqu'un objet BIO BIO_f_ssl() est créé, il est associé à une structure SSL (via SSL_new(3) et BIO_ctrl_set_ssl(3)). Les opérations de lecture et d'écriture sur le BIO BIO_f_ssl() sont traduites en opérations SSL/TLS sur la connexion sous-jacente.

Le BIO BIO_f_ssl() gère le handshake SSL/TLS, le chiffrement et le déchiffrement des données.

VALEURS DE RETOUR

La fonction BIO_f_ssl() retourne un pointeur vers un objet BIO, ou NULL en cas d'échec.

VOIR AUSSI

BIO_new(3), SSL_new(3), BIO_ctrl_set_ssl(3)

HISTORIQUE

La fonction BIO_f_ssl() a été introduite dans OpenSSL.
