ASN1_GET_OBJECT(3) Manuel des fonctions de bibliothèque ASN1_GET_OBJECT(3)

NOM

ASN1_get_object — analyse les octets d'identificateur et de longueur

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/asn1.h>

int
ASN1_get_object(const unsigned char **ber_in, long *plength, int *ptag, int *pclass, long omax);

DESCRIPTION

ASN1_get_object() analyse les octets d'identificateur et de longueur d'une valeur codée en BER. À l'entrée de la fonction, *ber_in doit pointer vers le premier octet d'identificateur. Si les octets d'identificateur et de longueur sont valides, la fonction avance *ber_in vers le premier octet de contenu avant de retourner.

Si les octets d'identificateur sont valides, ASN1_get_object() stocke le numéro d'étiquette dans *ptag et la classe de l'étiquette dans *pclass. La classe est soit V_ASN1_UNIVERSAL, soit V_ASN1_APPLICATION, soit V_ASN1_CONTEXT_SPECIFIC, soit V_ASN1_PRIVATE.

Si les octets de longueur sont également valides, ASN1_get_object() stocke le nombre encodé dans les octets de longueur dans *plength. Si l'octet de longueur indique la forme indéfinie, *plength est mis à 0.

ASN1_get_object() inspecte au maximum omax octets. Si l'analyse des octets de longueur reste incomplète après avoir inspecté ce nombre d'octets, l'analyse échoue avec ASN1_R_HEADER_TOO_LONG.

VALEURS DE RETOUR

Les bits définis dans la valeur de retour de ASN1_get_object() ont les significations suivantes :

0x80
Une erreur s'est produite. L'une des ERREURS décrites ci-dessous a été définie.
0x20 = V_ASN1_CONSTRUCTED
Le codage est construit plutôt que primitif, et l'identificateur et les octets de longueur sont valides.
0x01
L'octet de longueur indique la forme indéfinie. Ce bit ne peut apparaître que si V_ASN1_CONSTRUCTED est également défini.

Par conséquent, les combinaisons suivantes peuvent se produire :

0x00
Un codage primitif valide.
0x20
Un codage construit valide, forme définie.
0x21
Un codage construit valide, forme indéfinie.
0x80
Soit un codage primitif avec une étiquette et une longueur définie valides, mais les octets de contenu ne tiennent pas dans omax, soit l'analyse a échoué. Utilisez ERR_GET_REASON(3) pour distinguer les deux cas.
0xa0
Un codage construit avec une étiquette et une longueur définie valides, mais les octets de contenu ne tiennent pas dans omax.

Les combinaisons de bits 0x01, 0x81 et 0xa1 ne peuvent pas apparaître comme valeurs de retour.

ERREURS

Si le bit 0x80 est défini dans la valeur de retour, les diagnostics peuvent être récupérés avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3) :

ASN1_R_HEADER_TOO_LONG « header trop long »
L'inspection de omax octets n'a pas suffi pour terminer l'analyse, le numéro d'étiquette encodé dans les octets d'identificateur dépasse INT_MAX, le nombre encodé dans les octets de longueur dépasse LONG_MAX, ou l'utilisation de la forme indéfinie pour les octets de longueur est tentée même si le codage est primitif.

Dans ce cas, la valeur de retour est exactement 0x80 ; aucun autre bit n'est défini.

Si le problème est survenu lors de l'analyse des octets d'identificateur, *ptag et *pclass restent inchangés. Si le problème est survenu lors de l'analyse des octets de longueur, *ptag et *pclass sont définis conformément aux octets d'identificateur. Dans les deux cas, *ber_in et *plength restent inchangés.

Le message d'erreur est trompeur. D'une part, l'en-tête peut être tout à fait correct, et la cause première du problème pourrait être que l'argument omax choisi était trop petit. D'autre part, les erreurs de syntaxe BER pures sont également signalées comme ASN1_R_HEADER_TOO_LONG.

ASN1_R_TOO_LONG « trop long »
Les octets d'identificateur et de longueur sont valides, mais les octets de contenu ne tiendront pas dans omax. Les éléments suivants ont été définis de manière appropriée et peuvent être inspectés en toute sécurité : *pclass, *ptag, *plength, et les bits V_ASN1_CONSTRUCTED et 0x01 dans la valeur de retour. Le pointeur d'analyse *ber_in a été avancé vers le premier octet de contenu.

Encore une fois, le message d'erreur peut parfois sembler trompeur. La longueur du contenu peut être raisonnable, et la cause première du problème peut être que l'argument omax choisi était trop petit.
