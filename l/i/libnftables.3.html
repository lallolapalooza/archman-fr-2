NOM

libnftables - bibliothèque frontend de nftables

SYNTAXE

Liez avec -lnftables.

DESCRIPTION

Cette bibliothèque a été conçue pour l'intégration de nftables dans des applications. Son API est donc maintenue aussi simple que possible, ce qui limite quelque peu sa flexibilité. Cependant, grâce à la prise en charge des balisages JSON pour l'entrée et la sortie, une utilisation pratique de la construction et de l'analyse des données d'entrée et de sortie peut être réalisée en utilisant une bibliothèque tierce telle que libjansson.

Au niveau le plus basique, il faut allouer un nouvel objet de type struct nft_ctx en utilisant la fonction nft_ctx_new(), puis passer les commandes via les fonctions nft_run_cmd_from_buffer() ou nft_run_cmd_from_filename(). Par défaut, toute sortie est écrite dans stdout (ou stderr pour les messages d'erreur). Ces pointeurs de fichier peuvent être modifiés à l'aide des fonctions nft_ctx_set_output() et nft_ctx_set_error(). En outre, il est possible de mettre en tampon toute sortie par la bibliothèque pour une récupération ultérieure sous forme de tampon statique. Voir les fonctions nft_ctx_buffer_output() et nft_ctx_buffer_error() pour plus de détails.

nft_ctx_new() et nft_ctx_free()

Ces fonctions facilitent la gestion du contexte nft. Afin d'utiliser la bibliothèque, au moins un objet de contexte doit être alloué. Le contexte contient des données temporaires telles que des caches, la configuration de la bibliothèque et (si activés) des tampons de sortie et d'erreur.

La fonction nft_ctx_new() alloue et retourne un nouvel objet de contexte. Le paramètre flags est inutilisé à ce stade et doit être mis à zéro. Par souci de commodité, la macro NFT_CTX_DEFAULT est définie à cette valeur.

La fonction nft_ctx_free() libère l'objet de contexte pointé par ctx, y compris les caches ou tampons qu'il peut contenir.

nft_ctx_get_dry_run() et nft_ctx_set_dry_run()

Le réglage de l'exécution à blanc contrôle si les changements de règles sont effectivement validés côté noyau ou non. Il permet de vérifier si une opération donnée réussirait sans apporter de modifications réelles à la règles. Le réglage par défaut est false.

La fonction nft_ctx_get_dry_run() retourne la valeur du réglage d'exécution à blanc contenue dans ctx.

La fonction nft_ctx_set_dry_run() règle le paramètre d'exécution à blanc dans ctx à la valeur de dry.

nft_ctx_input_get_flags() et nft_ctx_input_set_flags()

Le réglage des drapeaux contrôle le format d'entrée.

enum {
        NFT_CTX_INPUT_NO_DNS = (1 << 0),
        NFT_CTX_INPUT_JSON   = (1 << 1),
};

NFT_CTX_INPUT_NO_DNS

Évite de résoudre les adresses IP avec un appel bloquant à getaddrinfo(). Dans ce cas, seules les adresses IP brutes sont acceptées.

NFT_CTX_INPUT_JSON : Lors de l'analyse de l'entrée, essayez d'abord d'interpréter l'entrée comme du JSON avant de revenir au format nftables. Ce comportement est implicite lors de la définition du drapeau NFT_CTX_OUTPUT_JSON.

La fonction nft_ctx_input_get_flags() retourne la valeur du réglage des drapeaux d'entrée dans ctx.

La fonction nft_ctx_input_set_flags() règle le paramètre des drapeaux d'entrée dans ctx à la valeur de val et retourne les précédents drapeaux.

nft_ctx_output_get_flags() et nft_ctx_output_set_flags()

Le réglage des drapeaux contrôle le format de sortie.

enum {
        NFT_CTX_OUTPUT_REVERSEDNS     = (1 << 0),
        NFT_CTX_OUTPUT_SERVICE        = (1 << 1),
        NFT_CTX_OUTPUT_STATELESS      = (1 << 2),
        NFT_CTX_OUTPUT_HANDLE         = (1 << 3),
        NFT_CTX_OUTPUT_JSON           = (1 << 4),
        NFT_CTX_OUTPUT_ECHO           = (1 << 5),
        NFT_CTX_OUTPUT_GUID           = (1 << 6),
        NFT_CTX_OUTPUT_NUMERIC_PROTO  = (1 << 7),
        NFT_CTX_OUTPUT_NUMERIC_PRIO   = (1 << 8),
        NFT_CTX_OUTPUT_NUMERIC_SYMBOL = (1 << 9),
        NFT_CTX_OUTPUT_NUMERIC_TIME   = (1 << 10),
        NFT_CTX_OUTPUT_NUMERIC_ALL    = (NFT_CTX_OUTPUT_NUMERIC_PROTO |
                                         NFT_CTX_OUTPUT_NUMERIC_PRIO  |
                                         NFT_CTX_OUTPUT_NUMERIC_SYMBOL |
                                         NFT_CTX_OUTPUT_NUMERIC_TIME),
        NFT_CTX_OUTPUT_TERSE          = (1 << 11),
};

NFT_CTX_OUTPUT_REVERSEDNS

Des recherches DNS inversées sont effectuées pour les adresses IP lors de l'impression. Notez que cela peut ajouter un délai supplémentaire aux commandes list en fonction de la vitesse du résolveur DNS.

NFT_CTX_OUTPUT_SERVICE

Imprime les numéros de port comme services tels que décrits dans le fichier /etc/services.

NFT_CTX_OUTPUT_STATELESS

Si une sortie sans état a été demandée, alors les données avec état ne sont pas imprimées. Les données avec état se réfèrent aux objets qui transportent des données d'exécution, par exemple, l'instruction counter contient des valeurs de compteur de paquets et d'octets, ce qui la rend avec état.

NFT_CTX_OUTPUT_HANDLE

Lors de l'insertion dans la règles, certains éléments se voient attribuer un identifiant unique à des fins d'identification. Par exemple, lors de la suppression d'une table ou d'une chaîne, elle peut être identifiée par son nom ou son identifiant. Les règles, en revanche, doivent être supprimées par identifiant, car il n'y a pas d'autre moyen de les identifier uniquement. Ce drapeau fait en sorte que les listages de règles incluent les valeurs des identifiants.

NFT_CTX_OUTPUT_JSON

Si activé au moment de la compilation, libnftables accepte les entrées au format JSON et est capable d'imprimer la sortie au format JSON également. Voir libnftables-json(5) pour une description du schéma pris en charge. Ce drapeau active le format de sortie JSON. Si le drapeau est défini, l'entrée sera d'abord essayée au format JSON, avant de revenir au format nftables. Ce drapeau implique NFT_CTX_INPUT_JSON.

NFT_CTX_OUTPUT_ECHO

Le réglage d'écho permet à libnftables d'imprimer les changements une fois qu'ils sont validés dans le noyau, tout comme le ferait une instance en cours d'exécution de nft monitor. Entre autres choses, cela permet de récupérer l'identifiant d'une règle ajoutée de manière atomique.

NFT_CTX_OUTPUT_GUID

Affiche l'UID et le GID tels que décrits dans les fichiers /etc/passwd et /etc/group.

NFT_CTX_OUTPUT_NUMERIC_PR

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OTO

Afficher le protocole de couche 4 numériquement.

NFT_CTX_OUTPUT_NUMERIC_PRIO

Afficher la priorité de la chaîne de base numériquement.

NFT_CTX_OUTPUT_NUMERIC_SYMBOL

Afficher le type de données de l'expression sous forme numérique.

NFT_CTX_OUTPUT_NUMERIC_TIME

Afficher les valeurs d'heure, de jour et d'heure au format numérique.

NFT_CTX_OUTPUT_NUMERIC_ALL

Tout afficher numériquement.

NFT_CTX_OUTPUT_TERSE

Si une sortie concise a été demandée, le contenu des ensembles n'est pas imprimé.

La fonction nft_ctx_output_get_flags() renvoie la valeur du paramètre des indicateurs de sortie dans ctx.

La fonction nft_ctx_output_set_flags() définit le paramètre des indicateurs de sortie dans ctx à la valeur de val.

nft_ctx_output_get_debug() et nft_ctx_output_set_debug()

Libnftables prend en charge le débogage distinct de différentes parties de ses mécanismes internes. Pour faciliter cela, la sortie de débogage est contrôlée via un masque de bits. Les bits sont définis comme suit :

enum nft_debug_level {
        NFT_DEBUG_SCANNER               = 0x1,
        NFT_DEBUG_PARSER                = 0x2,
        NFT_DEBUG_EVALUATION            = 0x4,
        NFT_DEBUG_NETLINK               = 0x8,
        NFT_DEBUG_MNL                   = 0x10,
        NFT_DEBUG_PROTO_CTX             = 0x20,
        NFT_DEBUG_SEGTREE               = 0x40,
};

NFT_DEBUG_SCANNER

Imprimer la sortie de débogage LEX.

NFT_DEBUG_PARSER

Imprimer la sortie de débogage YACC.

NFT_DEBUG_EVALUATION

Imprimer les informations de débogage sur la phase d'évaluation.

NFT_DEBUG_NETLINK

Imprimer la sortie de débogage Netlink.

NFT_DEBUG_MNL

Imprimer la sortie de débogage libmnl.

NFT_DEBUG_PROTO_CTX

Imprimer la sortie de débogage du contexte de protocole.

NFT_DEBUG_SEGTREE

Imprimer la sortie de débogage segtree (c'est-à-dire les ensembles d'intervalles).

La fonction nft_ctx_output_get_debug() renvoie la valeur du paramètre de sortie de débogage dans ctx.

La fonction nft_ctx_output_set_debug() définit le paramètre de sortie de débogage dans ctx à la valeur de mask.

Contrôle de la sortie standard et d'erreur de la bibliothèque

Par défaut, toute sortie de la bibliothèque (par exemple, après une commande list) est écrite dans stdout et tout message d'erreur est écrit dans stderr. Pour permettre aux applications de les contrôler, il existe des fonctions pour assigner des pointeurs de fichiers personnalisés ainsi que pour mettre en mémoire tampon ce qui serait écrit pour une récupération ultérieure dans un tampon statique. Ce tampon est garanti d'être terminé par un caractère nul et ne doit pas être libéré. Notez que les fonctions de récupération rembobinent l'indicateur de position du tampon. Une sortie supplémentaire de la bibliothèque écrasera probablement le contenu du tampon et pourrait potentiellement le rendre invalide (en raison d'une réallocation).

Les fonctions nft_ctx_set_output() et nft_ctx_set_error() définissent le pointeur de fichier de sortie ou d'erreur dans ctx à la valeur de fp. Elles renvoient la valeur précédente pour aider aux remplacements temporaires de pointeurs de fichiers. En cas d'erreur, ces fonctions renvoient NULL. Cela ne se produit que si fp est NULL ou invalide (testé à l'aide de la fonction ferror()).

Les fonctions nft_ctx_buffer_output() et nft_ctx_buffer_error() activent la mise en mémoire tampon de la sortie standard ou d'erreur de la bibliothèque. Les fonctions renvoient zéro en cas de succès, une valeur non nulle sinon. Cela peut se produire si l'appel interne à fopencookie() a échoué.

Les fonctions nft_ctx_unbuffer_output() et nft_ctx_unbuffer_error() désactivent la mise en mémoire tampon de la sortie standard ou d'erreur de la bibliothèque. En cas d'échec, les fonctions renvoient une valeur non nulle, ce qui ne peut se produire que si la mise en mémoire tampon n'était pas activée au moment où la fonction a été appelée.

Les fonctions nft_ctx_get_output_buffer() et nft_ctx_get_error_buffer() renvoient un pointeur vers la sortie mise en mémoire tampon (qui peut être vide).

nft_ctx_add_include_path() et nft_ctx_clear_include_path()

La commande include dans les règles nftables permet d'externaliser des parties de l'ensemble de règles dans un fichier différent. Le chemin d'inclusion définit où ces fichiers sont recherchés. Libnftables permet d'avoir une liste de ces chemins qui sont recherchés dans l'ordre. La liste de chemins d'inclusion par défaut contient une seule entrée définie à la compilation (typiquement /etc/).

La fonction nft_ctx_add_include_path() étend la liste des chemins d'inclusion dans ctx avec celui fourni dans path. La fonction renvoie zéro en cas de succès ou une valeur non nulle si l'allocation mémoire a échoué.

La fonction nft_ctx_clear_include_paths() supprime tous les chemins d'inclusion, même celui par défaut intégré.

nft_ctx_add_var() et nft_ctx_clear_vars()

La commande define dans l'ensemble de règles nftables permet de définir des variables.

La fonction nft_ctx_add_var() étend la liste des variables dans ctx. La variable doit être fournie au format clé=valeur. La fonction renvoie zéro en cas de succès ou une valeur non nulle si la variable est mal formée.

La fonction nft_ctx_clear_vars() supprime toutes les variables.

nft_run_cmd_from_buffer() et nft_run_cmd_from_filename()

Ces fonctions effectuent le travail réel de analyse de l'entrée utilisateur en commandes nftables et de leur exécution.

La fonction nft_run_cmd_from_buffer() transmet la ou les commandes contenues dans buf (qui doit être terminé par un caractère nul) à la bibliothèque, en respectant les paramètres et l'état de nft.

La fonction nft_run_cmd_from_filename() transmet le contenu de filename à la bibliothèque, en respectant les paramètres et l'état de nft.

Les deux fonctions renvoient zéro en cas de succès. Un code de retour non nul indique une erreur lors de l'analyse ou de l'exécution de la commande. Cet événement doit être accompagné d'un message d'erreur écrit dans la sortie d'erreur de la bibliothèque.

EXEMPLE

#include <stdio.h>
#include <string.h>
#include <nftables/libnftables.h>
int main(void)
{
        char *list_cmd = "list ruleset";
        struct nft_ctx *nft;
        const char *output, *p;
        char buf[256];
        int rc = 0;
        nft = nft_ctx_new(NFT_CTX_DEFAULT);
        if (!nft)
                return 1;
        while (1) {
                if (nft_ctx_buffer_output(nft) ||
                    nft_run_cmd_from_buffer(nft, list_cmd)) {
                        rc = 1;
                        break;
                }
                output = nft_ctx_get_output_buffer(nft);
                if (strlen(output)) {
                        printf("\nThis is the current ruleset:\n| ");
                        for (p = output; *(p + 1); p++) {
                                if (*p == '\n')
                                        printf("\n| ");
                                else
                                        putchar(*p);
                        }
                        putchar('\n');
                } else {
                        printf("\nCurrent ruleset is empty.\n");
                }
                nft_ctx_unbuffer_output(nft);
                printf("\nEnter command ('q' to quit): ");
                fflush(stdout);
                fgets(buf, 256, stdin);
                if (strlen(buf))
                        buf[strlen(buf) - 1] = '\0';
                if (buf[0] == 'q' && buf[1] == '\0')
                        break;
                if (nft_run_cmd_from_buffer(nft, buf)) {
                        rc = 1;
                        break;
                }
        }
        nft_ctx_free(nft);
        return rc;
}
