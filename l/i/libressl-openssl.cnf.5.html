OPENSSL.CNF(5) Manuel des formats de fichiers OPENSSL.CNF(5)

NOM

openssl.cnf — Fichiers de configuration OpenSSL

DESCRIPTION

La bibliothèque CONF d'OpenSSL peut être utilisée pour lire des fichiers de configuration ; voir CONF_modules_load_file(3). Elle est utilisée pour le fichier de configuration maître d'OpenSSL /etc/ssl/openssl.cnf et dans quelques autres endroits comme les fichiers d'extensions de certificats pour l'utilitaire openssl(1) x509. Les applications OpenSSL peuvent également utiliser la bibliothèque CONF à leurs propres fins.

Un fichier de configuration est divisé en un certain nombre de sections. Chaque section commence par une ligne [nom_section] et se termine lorsqu'une nouvelle section commence ou que la fin du fichier est atteinte. Un nom de section peut être composé de caractères alphanumériques et de traits de soulignement.

La première section d'un fichier de configuration est spéciale et est appelée la section « par défaut ». Elle n'est généralement pas nommée et s'étend du début du fichier jusqu'à la première section nommée. Lorsqu'un nom est recherché, il est d'abord recherché dans une section nommée (le cas échéant), puis dans la section par défaut.

L'environnement est mappé sur une section appelée ENV.

Les commentaires peuvent être inclus en les faisant précéder du caractère « # ».

Chaque section d'un fichier de configuration se compose d'un certain nombre de paires nom et valeur de la forme nom=valeur.

Le nom nom peut contenir des caractères alphanumériques ainsi que quelques symboles de ponctuation tels que « . », « , », « ; » et « _ ».

La chaîne valeur consiste en la chaîne suivant le caractère « = » jusqu'à la fin de la ligne, avec suppression des espaces blancs principaux et finaux.

La chaîne de valeur subit une expansion de variables. Cela peut être fait en incluant des sous-chaînes de la forme $nom ou ${nom} : cela substituera la valeur de la variable nommée dans la section courante. Il est également possible de substituer une valeur d'une autre section en utilisant la syntaxe $section::nom ou ${section::nom}. En utilisant la forme $ENV::nom, les variables d'environnement peuvent être substituées. Il est également possible d'assigner des valeurs aux variables d'environnement en utilisant le nom ENV::nom. Cela fonctionnera si le programme recherche les variables d'environnement à l'aide de la bibliothèque CONF au lieu d'appeler getenv(3) directement. La chaîne de valeur ne doit pas dépasser 64 Ko après l'expansion des variables, sinon une erreur se produira.

Il est possible d'échapper certains caractères en utilisant n'importe quel type de guillemets ou le caractère « \ ». En faisant du dernier caractère d'une ligne un « \ », une chaîne valeur peut s'étendre sur plusieurs lignes. De plus, les séquences « \n », « \r », « \b », et « \t » sont reconnues.

CONFIGURATION DE LA BIBLIOTHÈQUE OPENSSL

Les applications peuvent configurer automatiquement certains aspects d'OpenSSL en utilisant le fichier de configuration maître d'OpenSSL, ou optionnellement un fichier de configuration alternatif. L'utilitaire openssl(1) inclut cette fonctionnalité : toute sous-commande utilise le fichier de configuration maître d'OpenSSL à moins qu'une option ne soit utilisée dans la sous-commande pour utiliser un fichier de configuration alternatif.

Pour activer la configuration de la bibliothèque, la section par défaut doit contenir une ligne appropriée qui pointe vers la section de configuration principale. Le nom par défaut est openssl_conf, qui est utilisé par l'utilitaire openssl(1). D'autres applications peuvent utiliser un nom alternatif tel que myapplication_conf. Toutes les lignes de configuration de la bibliothèque apparaissent dans la section par défaut au début du fichier de configuration.

La section de configuration doit consister en un ensemble de paires nom-valeur qui contiennent des informations de configuration de module spécifiques. Le nom représente le nom du module de configuration. La signification de la valeur est spécifique au module : elle peut, par exemple, représenter une section de configuration supplémentaire contenant des informations spécifiques au module de configuration. Par exemple :

# La ligne suivante doit être dans la section par défaut.
openssl_conf = openssl_init

[openssl_init]
oid_section = new_oids

[new_oids]
... nouveaux OIDs ici ...

Les fonctionnalités de chaque module de configuration sont décrites ci-dessous.

Module de configuration d'objet ASN.1

Ce module a le nom oid_section. La valeur de cette variable pointe vers une section contenant des paires nom-valeur d'OIDs : le nom est le nom court et long de l'OID, et la valeur est la forme numérique de l'OID. Bien que certaines des sous-commandes de l'utilitaire openssl(1) aient déjà leur propre fonctionnalité de section d'objet ASN1, toutes ne l'ont pas. En utilisant le module de configuration d'objet ASN1, toutes les sous-commandes de l'utilitaire openssl(1) peuvent voir les nouveaux objets ainsi que toutes les applications conformes. Par exemple :

[new_oids]
some_new_oid = 1.2.3.4
some_other_oid = 1.2.3.5

Il est également possible de définir la valeur par le nom long suivi d'une virgule et de la forme numérique de l'OID. Par exemple :

shortName = nom long de l'objet, 1.2.3.4

EXEMPLES

Voici un exemple de fichier de configuration utilisant certaines des fonctionnalités mentionnées ci-dessus :

# C'est la section par défaut.
HOME=/temp
RANDFILE= ${ENV::HOME}/.rnd
configdir=$ENV::HOME/config

[ section_one ]
# Nous sommes maintenant dans la section un.

# Les guillemets autorisent les espaces blancs en début et fin de ligne
any = " any variable name "

other = Une chaîne qui peut \
s'étendre sur plusieurs lignes \
en incluant des caractères \\

message = Hello World\n

[ section_two ]
greeting = $section_one::message

Cet exemple montre comment développer les variables d'environnement en toute sécurité.

Supposons que vous vouliez une variable appelée tmpfile pour faire référence à un nom de fichier temporaire. Le répertoire dans lequel il est placé peut être déterminé par les variables d'environnement TEMP ou TMP, mais elles peuvent ne pas avoir de valeur du tout. Si vous incluez simplement les noms des variables d'environnement et que la variable n'existe pas, cela provoquera une erreur lors de la tentative de chargement du fichier de configuration. En utilisant la section par défaut, les deux valeurs peuvent être recherchées, TEMP ayant la priorité et /tmp étant utilisé si aucune n'est définie :

TMP=/tmp
# La valeur ci-dessus est utilisée si TMP n'est pas dans l'environnement
TEMP=$ENV::TMP
# La valeur ci-dessus est utilisée si TEMP n'est pas dans l'environnement
tmpfile=${ENV::TEMP}/tmp.filename

Configuration plus complexe de la bibliothèque OpenSSL. Ajouter un OID :

# Nom d'application par défaut : doit correspondre au paramètre "appname" (le cas échéant)
# fourni à CONF_modules_load_file et autres.
openssl_conf = openssl_conf_section

[openssl_conf_section]
# Liste des modules de configuration
oid_section = new_oids

[new_oids]
# Nouvel OID, juste le nom court
newoid1 = 1.2.3.4.1
# Nouvel OID, nom court et nom long
newoid2 = Nom long du Nouvel OID 2, 1.2.3.4.2

Les exemples ci-dessus peuvent être utilisés avec n'importe quelle application prenant en charge la configuration de la bibliothèque si "openssl_conf" est modifié pour correspondre au "appname" approprié.

AVERTISSEMENTS

Si un fichier de configuration tente d'étendre une variable qui n'existe pas, une erreur est signalée et le fichier ne sera pas chargé. Cela peut également se produire si une tentative est faite pour étendre une variable d'environnement qui n'existe pas. Par exemple, dans une version précédente d'OpenSSL, le fichier de configuration maître d'OpenSSL par défaut utilisait la valeur de HOME qui peut ne pas être définie sur les systèmes non Unix et provoquerait une erreur.

Cela peut être contourné en incluant une section par défaut pour fournir une valeur par défaut : ainsi, si la recherche de la variable d'environnement échoue, la valeur par défaut sera utilisée à la place. Pour que cela fonctionne correctement, la valeur par défaut doit être définie plus tôt dans le fichier de configuration que l'extension. Voir la section EXEMPLES pour un exemple sur la façon de procéder.

Si la même variable est définie plus d'une fois dans la même section, toutes les valeurs sauf la dernière seront ignorées silencieusement. Dans certaines circonstances, comme avec les DN, le même champ peut apparaître plusieurs fois. Cela est généralement résolu en ignorant tous les caractères avant un point initial ‘.’, par exemple :

1.OU="My first OU"
2.OU="My Second OU"

BOGUES

Actuellement, il n'y a aucun moyen d'inclure des caractères en utilisant la forme octale \nnn. Les chaînes sont toutes terminées par NUL, donc les octets NUL ne peuvent pas faire partie de la valeur.

L'échappement n'est pas tout à fait correct : si vous voulez utiliser des séquences telles que ‘\n’, vous ne pouvez pas utiliser d'échappement de guillemets sur la même ligne.

Les fichiers sont chargés en une seule passe. Cela signifie qu'une extension de variable ne fonctionnera que si les variables référencées sont définies plus tôt dans le fichier.
