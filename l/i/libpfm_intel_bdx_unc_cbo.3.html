NOM

libpfm_intel_bdx_unc_cbo - prise en charge du PMU uncore C-Box d'Intel Broadwell Server

SYNTAXE

#include <perfmon/pfmlib.h>

Nom du PMU : bdx_unc_cbo[0-21]
Description du PMU : PMU uncore C-Box d'Intel Broadwell Server

DESCRIPTION

La bibliothèque prend en charge le PMU uncore C-Box (moteur de cohérence) d'Intel Broadwell Server. Ce modèle de PMU existe sur divers modèles de serveurs Broadwell (79, 86). Il y a un PMU C-Box par cœur physique. Par conséquent, il existe jusqu'à vingt-et-une instances de PMU C-Box identiques numérotées de 0 à 21. Sur les systèmes à double socket, le numéro fait référence au PMU C-Box du socket sur lequel le programme s'exécute. Par exemple, si le programme s'exécute sur le CPU18, alors bdx_unc_cbo0 fait référence au C-Box du cœur physique 0 sur le socket 1. Inversement, si le programme s'exécute sur le CPU0, le même bdx_unc_cbo0 fait référence au C-Box du cœur physique 0 mais sur le socket 0.

Chaque PMU C-Box implémente 4 compteurs génériques et deux registres de filtrage utilisés uniquement avec certains événements et umasks.

MODIFICATEURS

Les modificateurs suivants sont pris en charge sur le PMU uncore C-Box d'Intel Broadwell :

e
Active la détection de front, c'est-à-dire que l'on ne compte que lors d'une transition d'état de non-occurrence de l'événement à au moins une occurrence. Ce modificateur doit être combiné avec un modificateur de seuil (t) d'une valeur supérieure ou égale à un. C'est un modificateur booléen.
t
Définit la valeur du seuil. Lorsqu'elle est définie sur une valeur non nulle, le compteur compte le nombre de cycles C-Box pendant lesquels le nombre d'occurrences de l'événement est supérieur ou égal au seuil. C'est un modificateur entier avec des valeurs dans la plage [0:255].
nf
Filtre de nœud. Certains événements, tels que UNC_C_LLC_LOOKUP, UNC_C_LLC_VICTIMS, fournissent un umask NID. Parfois, le NID est combiné avec d'autres capacités de filtrage, telles que les opcodes. Le filtre de nœud est un masque de bits maximal de 8 bits. Un nœud correspond à un socket processeur. Les valeurs légales dépendent donc de la configuration matérielle sous-jacente. Pour les systèmes à double socket, le masque de bits a deux bits valides [0:1].
cf
Filtre de cœur. Il s'agit d'un filtre de 5 bits utilisé pour filtrer en fonction de l'origine du cœur physique de la requête C-Box. Les valeurs possibles sont 0-63. Si le filtre n'est pas spécifié, aucun filtrage n'est effectué. Les bits 0 à 3 indiquent l'ID du cœur physique et le bit 4 filtre sur les données non liées aux threads.
tf
Filtre de thread. Il s'agit d'un filtre de 1 bit utilisé pour filtrer les requêtes C-Box en fonction de l'identification du processeur logique (hyper-thread). Les valeurs possibles sont 0-1. Si le filtre n'est pas spécifié, aucun filtrage n'est effectué.
nc
Non-Coherent. Il s'agit d'un filtre de 1 bit utilisé pour filtrer les requêtes C-Box uniquement pour les umasks TOR_INSERTS et TOR_OCCUPANCY en utilisant le comparateur OPCODE. Si le filtre n'est pas spécifié, aucun filtrage n'est effectué.
isoc
Isochrone. Il s'agit d'un filtre de 1 bit utilisé pour filtrer les requêtes C-Box uniquement pour les umasks TOR_INSERTS et TOR_OCCUPANCY en utilisant le comparateur OPCODE. Si le filtre n'est pas spécifié, aucun filtrage n'est effectué.

Filtrage d'opcode

Certains événements, tels que UNC_C_TOR_INSERTS, prennent en charge la comparaison d'opcodes sur le type de transaction C-BOX. Pour utiliser cette fonctionnalité, un umask de comparaison d'opcode doit d'abord être sélectionné, par exemple MISS_OPCODE. Ensuite, l'opcode à comparer doit être sélectionné via un second umask parmi les umasks OPC_*. Par exemple, UNC_C_TOR_INSERTS:OPCODE:OPC_RFO, compte le nombre d'insertions TOR pour les transactions RFO.

La comparaison d'opcodes peut être combinée avec le filtrage de nœuds avec certains umasks. En général, la prise en charge du filtrage est codée dans le nom de l'umask, par exemple NID_OPCODE prend en charge le filtrage de nœuds et d'opcodes. Par exemple, UNC_C_TOR_INSERTS:NID_OPCODE:OPC_RFO:nf=1.
