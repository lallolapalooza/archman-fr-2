DESCRIPTION

Une autorité d'horodatage est une tierce partie de confiance qui permet à ses clients de prouver que des données spécifiques existaient à un moment donné. Les clients envoient des requêtes d'horodatage au serveur d'horodatage, qui renvoie des jetons d'horodatage aux clients.

TS_REQ_new() alloue et initialise un objet TS_REQ vide, représentant une structure ASN.1 TimeStampReq définie dans la section 2.4.1 de la RFC 3161. Il peut contenir un hachage de la donnée à horodater et certaines informations auxiliaires optionnelles. TS_REQ_free() libère req.

TS_RESP_new() alloue et initialise un objet TS_RESP vide, représentant une structure ASN.1 TimeStampResp définie dans la section 2.4.2 de la RFC 3161. Il peut contenir des informations de statut et un jeton d'horodatage. TS_RESP_free() libère resp.

TS_STATUS_INFO_new() alloue et initialise un objet TS_STATUS_INFO vide, représentant une structure ASN.1 PKIStatusInfo définie dans la section 2.4.2 de la RFC 3161. Il est utilisé à l'intérieur de TS_RESP et décrit le résultat d'une requête d'horodatage. TS_STATUS_INFO_free() libère status.

TS_TST_INFO_new() alloue et initialise un objet TS_TST_INFO vide, représentant une structure ASN.1 TSTInfo définie dans la section 2.4.2 de la RFC 3161. C'est le jeton d'horodatage inclus dans un objet TS_RESP en cas de succès, et il peut contenir le hachage de la donnée copiée à partir d'une requête, l'heure de génération et certaines informations auxiliaires. TS_TST_INFO_free() libère token.

TS_ACCURACY_new() alloue et initialise un objet TS_ACCURACY vide, représentant une structure ASN.1 Accuracy définie dans la section 2.4.2 de la RFC 3161. Il peut être utilisé à l'intérieur d'un objet TS_TST_INFO et indique l'erreur maximale de l'heure indiquée dans le jeton. TS_ACCURACY_free() libère accuracy.

TS_MSG_IMPRINT_new() alloue et initialise un objet TS_MSG_IMPRINT vide, représentant une structure ASN.1 MessageImprint définie dans la section 2.4.1 de la RFC 3161. Il est utilisé à l'intérieur des objets TS_REQ et TS_RESP. Il spécifie un algorithme de hachage et stocke la valeur de hachage de la donnée. TS_MSG_IMPRINT_free() libère imprint.

VALEUR DE RETOUR

TS_REQ_new(), TS_RESP_new(), TS_STATUS_INFO_new(), TS_TST_INFO_new(), TS_ACCURACY_new(), et TS_MSG_IMPRINT_new() retournent le nouvel objet TS_REQ, TS_RESP, TS_STATUS_INFO, TS_TST_INFO, TS_ACCURACY, ou TS_MSG_IMPRINT, respectivement, ou NULL si une erreur s'est produite.

NORMES

RFC 3161 : Protocole de timestamping de l'infrastructure à clé publique Internet X.509

Notez que la RFC 3161 a été mise à jour par la RFC 5816 : Mise à jour de l'attribut Signing Certificate pour la RFC 3161. Cette mise à jour permet d'utiliser la version 2 de la définition de l'attribut de certificat de signature selon la RFC 5035, mais l'implémentation actuelle ne prend en charge que la version 1 de la définition de l'attribut de certificat de signature selon la RFC 2634, et donc ne prend en charge que la RFC 3161, mais pas les fonctionnalités de la RFC 5816.

NAME

NAME

TS_REQ_new, TS_REQ_print, TS_REQ_free - Create, print, and free a TS_REQ structure

SYNOPSIS

SYNOPSIS

All functions are declared in openssl/ts.h and linked with -lcrypto.

TS_REQ *TS_REQ_new(const ASN1_INTEGER *version, const char *prog_name,
    const char *req_version, STACK_OF(TS_POLICY_ID) *policies,
    const ASN1_OCTET_STRING *message, const X509_ALGOR *digest_alg,
    const ASN1_INTEGER *nonce, const GENERAL_NAME *nonce_type,
    const ASN1_INTEGER *ordering, const GENERAL_NAME *ordering_type,
    STACK_OF(GENERAL_NAME) *tsa_names, int ask_extensions);

int TS_REQ_print(BIO *bio, const TS_REQ *a);

void TS_REQ_free(TS_REQ *a);

DESCRIPTION

DESCRIPTION

The timestamping request (TS_REQ) structure is defined in RFC 3161. It is used to request a timestamp token from a TSA.

The TS_REQ_new function creates and allocates a new TS_REQ structure. The parameters are used to fill the structure fields. If a parameter is NULL or zero, the corresponding field is left uninitialized or omitted if allowed by the ASN.1 definition. The ask_extensions parameter must be set to 1 to enable the request of extensions, and 0 otherwise. The returned structure must be freed using TS_REQ_free.

The TS_REQ_print function prints the contents of the TS_REQ structure a to the bio.

The TS_REQ_free function frees the allocated TS_REQ structure a.

RETURN VALUES

RETURN VALUES

The TS_REQ_new function returns a pointer to the newly created TS_REQ structure, or NULL if an error occurred.

The TS_REQ_print function returns 1 on success, or 0 if an error occurred.

The TS_REQ_free function does not return a value.
