NOM

libnbd-release-notes-1.8 - notes de publication pour libnbd 1.8

DESCRIPTION

Ce sont les notes de publication pour la version stable de libnbd 1.8. Elles décrivent les changements majeurs depuis la version 1.6.

libnbd 1.8.0 a été publié le 7 juin 2021.

libnbd est maintenant hébergé sur gitlab : https://listman.redhat.com/archives/libguestfs/2021-February/msg00021.html

Sécurité

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour en savoir plus sur les problèmes de sécurité précédents dans libnbd, voir libnbd-security(3).

Un bogue de sécurité a été découvert dans libnbd durant ce cycle de publication.

CVE-2021-20286 déni de service lors de l'utilisation de nbd_set_opt_mode(3)

Voir l'annonce complète ici : https://listman.redhat.com/archives/libguestfs/2021-March/msg00092.html (Trouvé et corrigé par Eric Blake).

Nouvelles APIs

nbd_get_private_data(3)
nbd_set_private_data(3)
Ces appels permettent de stocker un entier non signé ou un pointeur dans le handle pour que l'application puisse l'utiliser à ses propres fins.
nbd_get_uri(3)
Cet appel construit une URI NBD qui peut être utilisée pour se connecter au même serveur (en utilisant nbd_connect_uri(3) ou depuis d'autres outils qui supportent la norme URI NBD).

Améliorations des APIs existantes

Les URI IPv6 numériques (comme "nbd://[::1]/") sont maintenant prises en charge.

libnbd donne un meilleur message d'erreur si la file d'attente du serveur déborde (remerciements à Xin Long, Lukas Doktor, Eric Blake, Martin Kletzander).

Nouvelles fonctionnalités

Les tests d'intégration continue (CI) s'exécutent maintenant sur chaque commit et requête de fusion dans le dépôt principal (Martin Kletzander).

Outils

Une grande partie du travail a été consacrée à l'amélioration des performances de nbdcopy(1) (Nir Soffer, Eric Blake).

Sous Linux, nbdcopy utilise maintenant la prélecture lors de la lecture de fichiers et prend des mesures pour préserver le cache de pages de l'hôte.

nbdcopy a une nouvelle option --request-size pour permettre de contrôler la taille des requêtes adressées aux serveurs NBD. L'ajustement de cette valeur peut affecter les performances (Nir Soffer).

nbdcopy supporte maintenant la cible pseudo "null:", où il rejette la sortie. Ceci est utile pour le benchmarking.

nbdcopy a un nouveau drapeau -v pour activer la journalisation libnbd et autres débogages.

nbdinfo(1) --list (qui liste toutes les exportations d'un serveur) ne se termine plus prématurément si une des exportations est inaccessible ou en cas d'erreur récupérable (Eric Blake).

nbdinfo affiche maintenant l'URI de chaque exportation dans la sortie, facilitant la reconnexion à chaque exportation.

nbdfuse(1) est maintenant multithreadé et supporte l'émission de commandes NBD parallèles sur une seule connexion ainsi que le multi-conn, et d'autres améliorations ont été apportées. Cela a entraîné une amélioration des performances d'environ 50% lors des tests avec fio.

nbdfuse supporte maintenant le style nbdcopy "[ CMD ]", par exemple :
nbdfuse dir/ramdisk [ nbdkit memory 1G ]

nbdfuse supporte maintenant le trimming. Il supporte également la mise à zéro rapide, mais cela nécessite un futur patch du noyau avant de fonctionner.

nbdfuse définit correctement les permissions virtuelles des fichiers si l'exportation NBD est en lecture seule.

nbdfuse a un nouveau drapeau -v pour activer la journalisation libnbd et autres débogages.

Tests

Ajout d'un test d'interopérabilité avec qemu-storage-daemon(1). Notez que qemu-storage-daemon était cassé dans qemu 6.0.0, donc ce test peut échouer sauf si vous mettez à jour vers une version corrigée (remerciements à Stefan Hajnoczi, Daniel Berrangé).

Ajout d'un test de nbdcopy avec TLS qui n'était pas testé auparavant.

Les tests de style de code Python sont maintenant optionnels en utilisant
./configure --enable-python-code-style

Plus de tests devraient maintenant s'exécuter sur FreeBSD et ne pas être ignorés.

Les tests nbdfuse garantissent maintenant que les erreurs de NBD sont transmises via FUSE au client local.

"MALLOC_CHECK_" et "MALLOC_PERTURB_" ne sont activés que lors de l'exécution des tests, et non lors de l'exécution des programmes libnbd depuis le répertoire de construction. Cela facilite les benchmarks.

Autres améliorations et corrections de bogues

Le compilateur C minimum requis est maintenant ISO C99 (auparavant ANSI C90).

FUSE 3 (au lieu de FUSE 2) est maintenant requis pour compiler nbdfuse.

La bibliothèque essaie plus fort de ne pas fuir la mémoire du stockage local au thread lors de dlclose ou de la sortie. (En raison de la conception de Linux, il n'est pas toujours possible d'éviter cela, en particulier dans les programmes multithreadés.)

Correction de la barre de progression dans nbdcopy(1).

Les noms d'exportations UTF-8 sont maintenant correctement traités et affichés par nbdinfo(1).

La sortie --help de nbdcopy, nbdfuse et nbdinfo affiche maintenant un bref résumé de toutes les options et contient quelques exemples.

Le générateur ne nécessite plus que ocamlc, pas ocamlfind (Abhay Raj Singh).

Les liaisons Golang utilisent et nécessitent maintenant les modules golang.

Documentation

Documentation sur l'utilisation de libnbd avec le système de construction Meson.

Ajout d'exemples Python.

Ajout d'un exemple sur la façon d'intégrer libnbd avec libev (Nir Soffer).
