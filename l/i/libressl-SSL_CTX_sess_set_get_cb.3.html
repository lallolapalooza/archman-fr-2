NOM

DESCRIPTION

SSL_CTX_sess_set_new_cb() définit la fonction de rappel qui est appelée automatiquement chaque fois qu'une nouvelle session a été négociée.

SSL_CTX_sess_set_remove_cb() définit la fonction de rappel qui est appelée automatiquement chaque fois qu'une session est supprimée par le moteur SSL (parce qu'elle est considérée comme défectueuse ou qu'elle est devenue obsolète en raison du dépassement de la valeur de délai d'expiration).

SSL_CTX_sess_set_get_cb() définit la fonction de rappel qui est appelée chaque fois qu'un client SSL/TLS propose de reprendre une session mais que la session ne peut pas être trouvée dans le cache de sessions interne (voir SSL_CTX_set_session_cache_mode(3)). (Serveur SSL/TLS uniquement.)

SSL_CTX_sess_get_new_cb(), SSL_CTX_sess_get_remove_cb(), et SSL_CTX_sess_get_get_cb() récupèrent les pointeurs de fonction des fonctions de rappel fournies. Si une fonction de rappel n'a pas été définie, le pointeur NULL est retourné.

Afin de permettre la mise en cache de sessions externe, la synchronisation avec le cache de sessions interne est réalisée via des fonctions de rappel. Dans ces fonctions de rappel, les sessions peuvent être sauvegardées sur disque ou placées dans une base de données en utilisant l'interface d2i_SSL_SESSION(3).

La fonction new_session_cb() est appelée chaque fois qu'une nouvelle session a été négociée et que la mise en cache de sessions est activée (voir SSL_CTX_set_session_cache_mode(3)). La fonction new_session_cb() reçoit la connexion ssl et la session ssl sess. Si le rappel retourne 0, la session sera immédiatement supprimée à nouveau.

La fonction remove_session_cb() est appelée chaque fois que le moteur SSL supprime une session du cache interne. Cela se produit lorsque la session est supprimée car elle est expirée ou lorsqu'une connexion n'a pas été fermée proprement. Cela se produit également pour toutes les sessions du cache interne lorsque SSL_CTX_free(3) est appelée. La fonction remove_session_cb() reçoit le ctx et la session ssl sess. Elle ne fournit aucun retour.

La fonction get_session_cb() n'est appelée que sur les serveurs SSL/TLS avec l'ID de session proposé par le client. La fonction get_session_cb() est toujours appelée, même lorsque la mise en cache de sessions a été désactivée. La fonction get_session_cb() reçoit la connexion ssl, l'ID de session de longueur len à l'emplacement mémoire data. Avec le paramètre copy, le rappel peut demander au moteur SSL d'incrémenter le compteur de référence de l'objet SSL_SESSION. Normalement, le compteur de référence n'est pas incrémenté et par conséquent, la session ne doit pas être explicitement libérée avec SSL_SESSION_free(3).

NAME

SSL_CTX_sess_set_get_cb, SSL_CTX_sess_get_cb, SSL_CTX_sess_set_new_cb, SSL_CTX_sess_get_new_cb - set or get session cache callback functions

SYNOPSIS

```c #include <openssl/ssl.h> typedef int (SSL_CTX_psk_client_callback_t)(SSL *ssl, void *arg, unsigned char *psk, int psk_len); typedef int (SSL_CTX_psk_server_callback_t)(SSL *ssl, void *arg, const unsigned char *name, size_t name_len, unsigned char *psk, int psk_len); typedef int (SSL_CTX_psk_find_session_callback_t)(SSL *ssl, void *arg, unsigned char *key, int *key_len); typedef int (SSL_CTX_psk_new_session_callback_t)(SSL *ssl, void *arg, unsigned char *key, int key_len); void SSL_CTX_sess_set_get_cb(SSL_CTX *ctx, SSL_CTX_psk_find_session_callback_t *callback); SSL_CTX_psk_find_session_callback_t *SSL_CTX_sess_get_cb(SSL_CTX *ctx); void SSL_CTX_sess_set_new_cb(SSL_CTX *ctx, SSL_CTX_psk_new_session_callback_t *callback); SSL_CTX_psk_new_session_callback_t *SSL_CTX_sess_get_new_cb(SSL_CTX *ctx); ```

DESCRIPTION

These functions allow you to get or set callback functions for session caching.

SSL_CTX_sess_set_get_cb() sets the callback function that is used to retrieve a cached session. This callback is invoked when a session is needed, for example, during the TLS handshake.

SSL_CTX_sess_get_cb() returns the currently set callback function for retrieving sessions.

SSL_CTX_sess_set_new_cb() sets the callback function that is used to cache a newly created session. This callback is invoked when a new session is established.

SSL_CTX_sess_get_new_cb() returns the currently set callback function for caching new sessions.

The callback functions are expected to have the following signatures:

SSL_CTX_psk_find_session_callback_t: This callback is invoked when a session needs to be retrieved from the cache. The `key` and `key_len` parameters contain the key to identify the session. The callback should return 1 if a session was found and successfully decrypted, and 0 otherwise. The `ssl` parameter is the SSL object, and `arg` is the user-defined data passed during context creation.

SSL_CTX_psk_new_session_callback_t: This callback is invoked when a new session is created and needs to be added to the cache. The `key` and `key_len` parameters contain the key to identify the session, and the `ssl` parameter is the SSL object. The `arg` parameter is the user-defined data passed during context creation. The callback should return 1 on success and 0 on failure.

RETURN VALUES

SSL_CTX_sess_get_cb() and SSL_CTX_sess_get_new_cb() return the currently set callback function, or NULL if no callback is set.

The callback functions themselves return 1 on success and 0 on failure.

SEE ALSO

SSL_CTX_new(3)

HISTORY

The functions described here were added in OpenSSL 1.1.0.

NOM

SSL_CTX_sess_set_get_cb, SSL_CTX_sess_get_cb, SSL_CTX_sess_set_new_cb, SSL_CTX_sess_get_new_cb - définir ou obtenir les fonctions de rappel du cache de session

SYNOPSIS

```c #include <openssl/ssl.h> typedef int (SSL_CTX_psk_client_callback_t)(SSL *ssl, void *arg, unsigned char *psk, int psk_len); typedef int (SSL_CTX_psk_server_callback_t)(SSL *ssl, void *arg, const unsigned char *name, size_t name_len, unsigned char *psk, int psk_len); typedef int (SSL_CTX_psk_find_session_callback_t)(SSL *ssl, void *arg, unsigned char *key, int *key_len); typedef int (SSL_CTX_psk_new_session_callback_t)(SSL *ssl, void *arg, unsigned char *key, int key_len); void SSL_CTX_sess_set_get_cb(SSL_CTX *ctx, SSL_CTX_psk_find_session_callback_t *callback); SSL_CTX_psk_find_session_callback_t *SSL_CTX_sess_get_cb(SSL_CTX *ctx); void SSL_CTX_sess_set_new_cb(SSL_CTX *ctx, SSL_CTX_psk_new_session_callback_t *callback); SSL_CTX_psk_new_session_callback_t *SSL_CTX_sess_get_new_cb(SSL_CTX *ctx); ```

DESCRIPTION

Ces fonctions vous permettent d'obtenir ou de définir des fonctions de rappel pour la mise en cache de sessions.

SSL_CTX_sess_set_get_cb() définit la fonction de rappel utilisée pour récupérer une session mise en cache. Ce rappel est appelé lorsqu'une session est nécessaire, par exemple, pendant la négociation TLS.

SSL_CTX_sess_get_cb() renvoie la fonction de rappel actuellement définie pour récupérer les sessions.

SSL_CTX_sess_set_new_cb() définit la fonction de rappel utilisée pour mettre en cache une nouvelle session créée. Ce rappel est appelé lorsqu'une nouvelle session est établie.

SSL_CTX_sess_get_new_cb() renvoie la fonction de rappel actuellement définie pour la mise en cache de nouvelles sessions.

Les fonctions de rappel doivent avoir les signatures suivantes :

SSL_CTX_psk_find_session_callback_t : Ce rappel est appelé lorsqu'une session doit être récupérée du cache. Les paramètres `key` et `key_len` contiennent la clé pour identifier la session. Le rappel doit retourner 1 si une session a été trouvée et déchiffrée avec succès, et 0 sinon. Le paramètre `ssl` est l'objet SSL, et `arg` sont les données définies par l'utilisateur passées lors de la création du contexte.

SSL_CTX_psk_new_session_callback_t : Ce rappel est appelé lorsqu'une nouvelle session est créée et doit être ajoutée au cache. Les paramètres `key` et `key_len` contiennent la clé pour identifier la session, et le paramètre `ssl` est l'objet SSL. Le paramètre `arg` sont les données définies par l'utilisateur passées lors de la création du contexte. Le rappel doit retourner 1 en cas de succès et 0 en cas d'échec.

VALEURS DE RETOUR

SSL_CTX_sess_get_cb() et SSL_CTX_sess_get_new_cb() renvoient la fonction de rappel actuellement définie, ou NULL si aucune fonction de rappel n'est définie.

Les fonctions de rappel elles-mêmes retournent 1 en cas de succès et 0 en cas d'échec.
