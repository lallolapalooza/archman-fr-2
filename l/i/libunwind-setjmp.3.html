LIBUNWIND-SETJMP(3libunwind) Bibliothèque de programmation LIBUNWIND-SETJMP(3libunwind)

NOM

libunwind-setjmp -- sauts non locaux basés sur libunwind

SYNTAXE

#include <setjmp.h>

int setjmp(jmp_buf env);
void longjmp(jmp_buf env, int val);
int _setjmp(jmp_buf env);
void _longjmp(jmp_buf env, int val);
int sigsetjmp(sigjmp_buf env, int savemask);
void siglongjmp(sigjmp_buf env, int val);

DESCRIPTION

La bibliothèque unwind-setjmp offre une implémentation basée sur libunwind des sauts non locaux. Cette implémentation est conçue pour être un remplacement direct des routines normales du même nom fournies par le système. L'avantage principal de l'utilisation de la bibliothèque unwind-setjmp est que la mise en place d'un saut non local via l'une des routines setjmp() est très rapide. Généralement, seulement 2 ou 3 mots doivent être sauvegardés dans le tampon de saut (plus un appel à sigprocmask(2), dans le cas de sigsetjmp). D'autre part, l'exécution d'un saut non local en appelant l'une des routines longjmp() a tendance à être beaucoup plus lente qu'avec les routines fournies par le système. En fait, le temps passé sur un longjmp() sera proportionnel au nombre de cadres d'appel qui existent entre les points où setjmp() et longjmp() ont été appelés. Pour cette raison, la bibliothèque unwind-setjmp est principalement bénéfique dans les applications qui appellent fréquemment setjmp() mais appellent rarement longjmp().

LIMITATIONS

*
Le fonctionnement correct de cette bibliothèque dépend de la présence d'une information de déroulement correcte. Sur les plateformes plus récentes, ceci est rarement un problème. Sur les plateformes plus anciennes, il faut faire attention à garantir que chacune des fonctions dont les cadres de pile peuvent avoir à être déroulés lors d'un longjmp() aient des informations de déroulement correctes (sur ces plateformes, il y a généralement un commutateur de compilateur, tel que -funwind-tables, pour demander la génération d'informations de déroulement).
*
Le contenu de jmp_buf et sigjmp_buf, tel que configuré et utilisé par ces routines, est complètement différent de celui utilisé par les routines fournies par le système. Ainsi, un tampon de saut créé par setjmp()/_setjmp basé sur libunwind ne peut être utilisé que dans un appel à longjmp()/_longjmp basé sur libunwind. L'analogue s'applique à sigjmp_buf avec sigsetjmp() et siglongjmp().

FICHIERS

-lunwind-setjmp

La bibliothèque à lier avec une application pour s'assurer qu'elle utilise les routines de saut non locaux basées sur libunwind.
