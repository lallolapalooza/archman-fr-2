PEM_X509_INFO_READ_BIO(3) Manuel des fonctions de bibliothèque PEM_X509_INFO_READ_BIO(3)

NOM

PEM_X509_INFO_read_bio — Décodage PEM et DER des certificats, clés privées et listes de révocation X.509

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/pem.h>

STACK_OF(X509_INFO) *
PEM_X509_INFO_read_bio(BIO *in_bp, STACK_OF(X509_INFO) *sk, pem_password_cb *cb, void *u);

DESCRIPTION

Cette fonction lit zéro ou plusieurs objets liés aux certificats X.509 depuis in_bp, effectue le décodage PEM et DER, et encapsule les objets résultants dans des conteneurs X509_INFO nouvellement alloués.

Il est recommandé de définir sk à NULL, auquel cas une nouvelle pile est allouée, remplie et retournée. Si une sk existante est passée, les objets X509_INFO créés sont empilés sur cette pile.

Pour le décodage PEM, PEM_read_bio(3) est utilisé en interne, ce qui implique que toute donnée non-PEM avant, entre et après les objets est silencieusement ignorée.

Pour le décodage DER ultérieur, la fonction de décodage et le champ de la structure X509_INFO dans lequel stocker le nouvel objet sont sélectionnés en fonction du nom du type PEM :

Nom du type PEM décodeur X509_INFO champ
CERTIFICATE d2i_X509(3) certificate
X509 CERTIFICATE d2i_X509(3) certificate
TRUSTED CERTIFICATE d2i_X509_AUX(3) certificate
X509 CRL d2i_X509_CRL(3) revocation list
RSA PRIVATE KEY d2i_PrivateKey(3) private key
DSA PRIVATE KEY d2i_PrivateKey(3) private key
EC PRIVATE KEY d2i_PrivateKey(3) private key

Lorsque le champ sélectionné est déjà occupé, un nouveau conteneur X509_INFO est alloué et empilé. Selon la séquence des objets dans l'entrée, cela peut entraîner l'empilement de plusieurs conteneurs X509_INFO partiellement remplis sur la pile.

Les objets PEM de types non listés dans le tableau ci-dessus sont silencieusement ignorés.

Les certificats et listes de révocation chiffrés sont déchiffrés en appelant PEM_do_header(3) en interne, en passant les arguments optionnels cb et u. Les clés privées chiffrées ne sont pas déchiffrées. Au lieu de cela, la forme chiffrée est stockée telle quelle. Néanmoins, PEM_get_EVP_CIPHER_INFO(3) est appelée en interne pour vérifier que les en-têtes PEM, s'il y en a, sont valides et spécifient un chiffrement que la bibliothèque est prête à gérer.

Si une erreur survient, les objets qui avaient déjà été lus lors du même appel sont à nouveau supprimés et sk reste inchangé.

VALEURS DE RETOUR

Cette fonction retourne un pointeur vers la pile sur laquelle les objets lus ont été empilés ou NULL si une erreur se produit. Elle échoue si PEM_read_bio(3), PEM_get_EVP_CIPHER_INFO(3), PEM_do_header(3), ou le décodage DER échouent, ou si la mémoire est épuisée.

ERREURS

Les diagnostics qui peuvent être récupérés avec ERR_get_error(3), ERR_GET_REASON(3), et ERR_reason_error_string(3) incluent :

ERR_R_ASN1_LIB "ASN1 lib"
Le décodage DER d'un objet PEM a échoué.
ERR_R_MALLOC_FAILURE "malloc failure"
PEM_X509_INFO_read_bio() n'a pas pu allouer un nouvel objet X509_INFO, STACK_OF(X509_INFO), ou X509_PKEY.

D'autres types d'erreurs peuvent résulter de PEM_read_bio(3), PEM_get_EVP_CIPHER_INFO(3), et PEM_do_header(3).

Après l'échec de cette fonction en raison d'une exhaustion de mémoire, ERR_get_error(3) peut parfois retourner 0.

VOIR AUSSI

BIO_new(3), d2i_PrivateKey(3), d2i_X509(3), d2i_X509_CRL(3), EVP_PKEY_new(3), PEM_read(3), PEM_read_bio_PrivateKey(3), STACK_OF(3), X509_CRL_new(3), X509_INFO_new(3), X509_LOOKUP_new(3), X509_new(3)

HISTORIQUE

PEM_X509_INFO_read_bio() est apparu pour la première fois dans SSLeay 0.6.0 et est disponible depuis OpenBSD 2.4.

MISE EN GARDE

Ce n'est pas une erreur si l'entrée ne contient aucun objet des types désirés. Dans ce cas, rien n'est ajouté à sk, ou si sk est NULL, une pile vide nouvellement allouée est retournée. La seule façon de détecter cette situation est de comparer le nombre d'objets sur la pile avant et après l'appel.

BOGUES

Lorsqu'il atteint la fin de l'entrée, cette fonction appelle ERR_clear_error(3), ce qui peut masquer des erreurs survenues avant son appel.

DESCRIPTION

La fonction PEM_X509_INFO_read_bio() lit des informations X.509 à partir d'un flux BIO.

Le paramètre bp est un pointeur vers le flux BIO à partir duquel les informations seront lues.

Le paramètre name est le nom du fichier ou de la ressource à partir de laquelle les informations sont lues.

Le paramètre err est un pointeur vers une structure X509_INFO où les informations lues seront stockées.

Le paramètre options est un entier qui spécifie diverses options de lecture. Les options possibles sont :

  • PEM_IGNORE_DUPS : Ignore les entrées en double.
  • PEM_STRICT : Traite les erreurs de manière stricte.

La fonction retourne 1 en cas de succès, et 0 en cas d'échec.

VALEURS DE RETOUR

La fonction retourne 1 en cas de succès, et 0 en cas d'échec.

ERREURS

La fonction peut échouer pour diverses raisons, notamment :

  • bp est NULL.
  • Une erreur lors de la lecture du flux BIO.
  • Une erreur lors de l'analyse du contenu PEM.

VOIR AUSSI

PEM_read_bio(), X509_INFO_new(), BIO_new()

HISTORIQUE

Cette fonction a été introduite dans OpenSSL version 1.0.0.

MISES EN GARDE

Il est important de s'assurer que le flux BIO est correctement initialisé et que le contenu PEM est valide.

BOGUES

Aucun bug connu pour le moment.
