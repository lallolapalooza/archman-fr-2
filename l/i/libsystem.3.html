Nom

pm_system - exécuter un programme Netpbm avec entrée et sortie de programme

Synopsis


#include <netpbm/pm_system.h>
pm_system(void                  stdinFeeder(int, void *),
          void *          const feederParm,
          void                  stdoutAccepter(int, void *),
          void *          const accepterParm,
          const char *    const shellCommand);
pm_system_lp(const char *  const progName,
             void                stdinFeeder(int, void *),
             void *        const feederParm,
             void                stdoutAccepter(int, void *),
             void *        const accepterParm,
             ...);
pm_system_vp(const char *  const progName,
             const char ** const argArray,
             void                stdinFeeder(int, void *),
             void *        const feederParm,
             void                stdoutAccepter(int, void *),
             void *        const accepterParm);

Exemple

Cet exemple simple convertit une image PNM de l'entrée standard en image JFIF (JPEG) sur la sortie standard. Dans ce cas, pm_system() ne fait rien de plus que ce que ferait system().


    pm_system(NULL, NULL, NULL, NULL, "pnmtojpeg");

Cet exemple fait la même chose, mais déplace les données à travers des tampons mémoire pour illustrer l'utilisation avec des tampons mémoire, et nous ajoutons une étape pour réduire l'image également :

#include <netpbm/pm_system.h>
char              pnmData[100*1024];   /* Le fichier d'entrée a intérêt à faire < 100 Ko */
char              jfifData[100*1024];
struct bufferDesc pnmBuffer;
struct bufferDesc jfifBuffer;
unsigned int      jfifSize;
pnmBuffer.size = fread(pnmData, 1, sizeof(pnmData), stdin);
pnmBuffer.buffer = pnmData;
pnmBuffer.bytesTransferredP = NULL;
jfifBuffer.size = sizeof(jfifData);
jfifBuffer.buffer = jfifData;
jfifBuffer.bytesTransferredP = &jfifSize; 
pm_system(&pm_feed_from_memory, &pnmBuffer,
          &pm_accept_to_memory, &jfifBuffer,
          "pamscale .5 | pnmtojpeg");
fwrite(jfifData, 1, jfifSize, stdout);

Cet exemple lit une image dans des structures PAM libnetpbm, puis l'éclaircit, puis l'écrit, pour illustrer l'utilisation de pm_system avec des structures PAM.

#include <netpbm/pam.h>
#include <netpbm/pm_system.h>
struct pam       inpam;
struct pam       outpam;
tuple **         inTuples;
tuple **         outTuples;
struct pamtuples inPamtuples;
struct pamtuples outPamtuples;
inTuples = pnm_readpam(stdin, &inpam, sizeof(inpam));
outpam = inpam;
inPamtuples.pamP = &inpam;
inPamtuples.tuplesP = &inTuples;
outPamtuples.pamP = &outpam;
outPamtuples.tuplesP = &outTuples;
pm_system(&pm_feed_from_pamtuples, &inPamtuples,
          &pm_accept_to_pamtuples, &outPamtuples,
          "ppmbrighten -v 100");
outpam.file = stdout;
pnm_writepam(&outpam, outTuples);

DESCRIPTION

Ces fonctions de bibliothèque font partie de Netpbm(1)

pm_system() est très similaire à la sous-routine system() de la bibliothèque C standard. Elle exécute un shell et fait exécuter à ce shell une commande shell que vous spécifiez. Mais pm_system() vous donne plus de contrôle sur l'entrée standard et la sortie standard de cette commande shell que system(). system() passe à la commande shell comme entrée standard et sortie standard ce qui est l'entrée standard et la sortie standard du processus qui appelle system(). Mais avec pm_system(), vous spécifiez comme arguments des sous-routines à exécuter pour générer le flux d'entrée standard de la commande shell et pour traiter le flux de sortie standard de la commande shell.

Votre sous-routine de diffusion d'entrée standard peut générer le flux de manière illimitée. pm_system() lui donne un descripteur de fichier d'un tube auquel écrire le flux qu'elle génère. pm_system() connecte l'autre extrémité de ce tube à l'entrée standard de la commande shell.

De même, votre sous-routine d'acceptation de sortie standard peut faire ce qu'elle veut du flux qu'elle reçoit. pm_system() lui donne un descripteur de fichier d'un tube à partir duquel lire le flux. pm_system() connecte l'autre extrémité de ce tube à la sortie standard de la commande shell.

L'argument stdinFeeder est un pointeur de fonction qui identifie votre sous-routine de diffusion d'entrée standard. pm_system() l'exécute dans un processus enfant et attend que ce processus se termine (et accepte son statut de complétion) avant de revenir. feederParm est l'argument que pm_system() passe à la sous-routine ; il est opaque pour pm_system().

Si vous passez stdinFeeder = NULL, pm_system() passe simplement votre flux d'entrée standard actuel à la commande shell (comme le ferait system()), et ne crée pas de processus enfant.

L'argument stdoutAccepter est un pointeur de fonction qui identifie votre sous-routine d'acceptation de sortie standard. pm_system() l'appelle dans le processus actuel. accepterParm est un argument analogue à feederParm.

Si vous passez stdoutAccepter = NULL, pm_system() passe simplement votre flux de sortie standard actuel à la commande shell (comme le ferait system().

L'argument shellCommand est une chaîne terminée par un octet nul contenant la commande shell que le shell doit exécuter. Il peut s'agir de n'importe quelle commande qui a un sens pour le shell et qui peut accepter un tube pour l'entrée standard et la sortie standard. Exemple :


    ppmbrighten -v 100 | pamdepth 255 | pamscale .5

pm_system() crée un processus enfant pour exécuter le shell et attend que ce processus se termine (et accepte son statut de complétion) avant de revenir.

pm_system_lp()

pm_system_lp() est similaire à pm_system(), sauf qu'au lieu d'exécuter un shell, qui à son tour exécute généralement un autre programme, vous exécutez directement un programme de votre choix.

L'argument progName identifie le programme à exécuter, de la même manière qu'avec execlp() ou une commande shell : s'il contient une barre oblique (/), il s'agit du nom complet du fichier qui contient le programme. Sinon, il s'agit d'un nom à rechercher dans le chemin de recherche des programmes du système (déterminé par la variable d'environnement PATH).

Vous identifiez les arguments du programme de la même manière qu'avec execlp() : avec les arguments variables à la fin de la liste d'arguments de pm_system_lp(). Chaque argument est une chaîne terminée par un NUL. Le dernier argument doit être NULL pour indiquer à pm_system_lp() où se terminent les arguments.

Notez que le premier argument ('arg0') d'un programme est conventionnellement le premier mot de la commande utilisée pour exécuter le programme, comme s'il était exécuté via une commande shell. En d'autres termes, généralement le nom du programme.

Exemple :


    pm_system_lp('pnmtojpeg', NULL, NULL, NULL, NULL,
                 'pnmtojpeg', 'mypicture.jpg', '-quality=50', NULL);

pm_system_lp() est beaucoup plus sûr que pm_system() lorsque votre programme calcule les arguments ou les obtient d'un utilisateur. Si vous construisez une commande shell à l'aide de tels arguments, à moins d'être vraiment prudent, vous pourriez finir par construire une commande shell qui fait quelque chose de très différent de ce que vous aviez l'intention, car l'argument pourrait contenir des caractères qui ont un sens pour le shell, comme '|'.

pm_system_lp() peut également être considérablement plus rapide que pm_system(), car il saute toute l'étape d'exécution du shell.

pm_system_vp()

pm_system_vp() est similaire à pm_system_lp(), sauf qu'au lieu de fournir les arguments du programme comme arguments variables, vous les fournissez sous forme de tableau, comme avec execvp(). Un élément NULL dans le tableau identifie la fin des arguments.

Exemple :


    const char * argArray[3];
    argArray[0] = 'pnmtojpeg';
    argArray[1] = '-quality=50';
    argArray[2] = NULL;
    pm_system_vp('pnmtojpeg', argArray, NULL, NULL, NULL, NULL);

pm_system(3) - netpbm documentation

Name

pm_system, pm_system_vp, pm_system_write, pm_system_read, pm_system_read_write - exécuter un programme externe

Synopsis

#include <netpbm/pm_system.h>
int pm_system(const char * command, ...);
int pm_system_vp(const char * command, char * const argv[],
                 FILE * stdin_feeder, FILE * stdout_acceptor,
                 FILE * stderr_acceptor, FILE * stdin_for_stderr_acceptor);
int pm_system_write(const char * command, char * const argv[],
                    FILE * stdout_acceptor,
                    FILE * stdin_for_stdout_acceptor);
int pm_system_read(const char * command, char * const argv[],
                   FILE * stdin_feeder,
                   FILE * stderr_acceptor,
                   FILE * stdin_for_stderr_acceptor);
int pm_system_read_write(const char * command, char * const argv[],
                         FILE * stdin_feeder, FILE * stdout_acceptor,
                         FILE * stderr_acceptor,
                         FILE * stdin_for_stderr_acceptor);

Example

Pour exécuter pnmtojpeg avec un argument --stdin et écrire la sortie vers un descripteur de fichier output_file :

    char *argArray[4];
    
    argArray[0] = "--stdin";
    argArray[1] = NULL;
    pm_system_write("pnmtojpeg", argArray, output_file, NULL);

Exécuter pnmtojpeg avec le membre buffer d'une structure bufferDesc comme entrée standard et envoyer la sortie standard vers le membre buffer d'une autre structure bufferDesc :

    struct bufferDesc input_buffer;
    struct bufferDesc output_buffer;
    char *argArray[3];
    
    /* ... initialiser input_buffer et output_buffer ... */
    
    argArray[0] = NULL;
    argArray[1] = NULL;
    argArray[2] = NULL;
    pm_system_vp('pnmtojpeg', argArray, pm_feed_from_memory(&input_buffer), pm_accept_to_memory(&output_buffer), NULL, NULL);

DESCRIPTION

La fonction pm_system est une version améliorée de la fonction system() de la bibliothèque C standard. Elle exécute une commande externe et est conçue pour faciliter le traitement des images Netpbm. Elle permet de rediriger l'entrée standard, la sortie standard et l'erreur standard du programme externe vers ou depuis des flux ou des tampons mémoire, ce qui est très utile pour intégrer des programmes Netpbm dans d'autres applications C.

Les fonctions pm_system_vp, pm_system_write, pm_system_read et pm_system_read_write offrent des interfaces plus spécialisées pour gérer les flux d'entrée/sortie.

pm_system
C'est la fonction la plus générale. Elle prend la commande comme premier argument, suivie d'une liste variable d'arguments (...) qui sont passés au programme externe. Elle permet également de spécifier des flux pour l'entrée standard, la sortie standard, l'erreur standard et même une entrée pour le gestionnaire d'erreur standard. Les arguments peuvent être des pointeurs vers des fonctions qui agissent comme des "feeders" (pour l'entrée standard) ou des "acceptors" (pour la sortie standard).
pm_system_vp
Cette fonction est similaire à pm_system mais prend un tableau de chaînes de caractères (argv) pour les arguments de la commande. Les arguments restants pour la redirection des flux sont les mêmes que pour pm_system.
pm_system_write
Utilitaire pour écrire vers un programme externe. Il prend la commande, ses arguments, un flux pour la sortie standard (stdout_acceptor) et un flux optionnel pour l'entrée standard du gestionnaire d'erreur (stdin_for_stderr_acceptor).
pm_system_read
Utilitaire pour lire depuis un programme externe. Il prend la commande, ses arguments, un flux pour l'entrée standard (stdin_feeder), un flux pour l'erreur standard (stderr_acceptor) et un flux optionnel pour l'entrée standard du gestionnaire d'erreur (stdin_for_stderr_acceptor).
pm_system_read_write
Fonction complète pour lire et écrire avec un programme externe. Elle inclut la gestion de l'entrée standard, de la sortie standard et de l'erreur standard.

Les fonctions pm_system* retournent le code de sortie du programme externe. Si l'exécution échoue pour une raison quelconque (par exemple, la commande n'est pas trouvée), elles retournent -1.

Applications

Le but de pm_system et de ses variantes est de vous permettre d'écrire un programme C qui utilise d'autres programmes en interne, comme le ferait un script shell. Ceci est particulièrement souhaitable avec Netpbm, car Netpbm se compose d'un grand nombre de programmes qui effectuent des manipulations graphiques de base et vous voudriez pouvoir construire un programme qui effectue une manipulation graphique plus sophistiquée en appelant les programmes Netpbm plus basiques. Ces programmes de construction prennent typiquement leur entrée de l'entrée standard et écrivent leur sortie vers la sortie standard.

L'alternative évidente est d'utiliser un langage de plus haut niveau - Bourne Shell ou Perl, par exemple. Mais souvent, vous voulez que votre programme effectue des manipulations de vos données graphiques qui sont plus faciles et plus efficaces en C. Ou vous voulez utiliser la bibliothèque de sous-routines Netpbm dans votre programme. La bibliothèque de sous-routines Netpbm est une bibliothèque à liaison C; les sous-routines qu'elle contient ne sont pas utilisables depuis un programme Bourne Shell ou Perl.

Une utilisation typique de pm_system est de placer le contenu d'un fichier image graphique en mémoire, d'exécuter un programme Netpbm dessus, et de faire en sorte que ce qui irait normalement dans un fichier de sortie soit également en mémoire, pour un traitement ultérieur. Pour ce faire, vous pouvez utiliser le distributeur d'entrée standard et le récepteur de sortie standard du tampon mémoire décrits ci-dessous.

Si votre programme utilise la bibliothèque de sous-routines Netpbm pour lire, écrire et manipuler des images, vous pouvez avoir une image dans un tableau de tuples PAM. Si vous souhaitez manipuler cette image avec un programme Netpbm (peut-être remapper les couleurs en utilisant pnmremap), vous pouvez utiliser le distributeur d'entrée standard et le récepteur de sortie standard pamtuple décrits ci-dessous.

Comportement en cas de tuyau brisé

Lorsque vous configurez une commande shell pour qu'elle prenne son entrée depuis un tuyau, comme vous le faites avec pm_system, vous devez comprendre comment fonctionnent les tuyaux par rapport aux programmes aux deux extrémités du tuyau qui s'accordent sur la quantité de données à transférer. Voici quelques notes à ce sujet.

Il est normal de lire un tuyau avant que le processus de l'autre côté n'ait écrit les données que vous espérez lire, et il est normal d'écrire dans un tuyau avant que le processus de l'autre côté n'ait essayé de lire vos données. Les écritures dans un tuyau peuvent être mises en mémoire tampon jusqu'à ce que l'extrémité de lecture demande les données. Un processus lisant ou écrivant dans un tuyau peut se bloquer jusqu'à ce que l'autre extrémité soit prête. Ou une lecture ou une écriture peut se terminer avec une indication que l'autre extrémité n'est pas prête pour le moment et donc aucune donnée, ou moins de données que ce qui a été demandé, n'a été transférée.

Le tuyau est normalement contrôlé par l'extrémité d'écriture. Lorsque vous lisez depuis un tuyau, vous continuez à lire jusqu'à ce que le programme de l'autre côté du tuyau le ferme, et vous obtenez alors une indication de fin de fichier. Vous fermez alors normalement l'extrémité de lecture du tuyau, car elle n'est plus utile.

Lorsque vous fermez l'extrémité de lecture d'un tuyau avant d'obtenir l'indication de fin de fichier et que l'écrivain essaie ensuite d'écrire dans le tuyau, il s'agit d'une condition d'erreur pour l'écrivain. Dans un environnement Unix par défaut typique, cette erreur provoque la réception d'un signal SIGPIPE par l'écrivain, et ce signal provoque la terminaison anormale du processus d'écriture. Mais si, alternativement, l'écrivain a demandé que SIGPIPE soit bloqué, ignoré ou géré, le signal ne provoque pas la mort de l'écrivain. Au lieu de cela, l'opération d'écriture se termine simplement avec une indication d'erreur.

Distributeurs et récepteurs standard

Vous pouvez fournir n'importe quoi comme distributeur d'entrée standard ou récepteur de sortie standard, mais la bibliothèque de sous-routines Netpbm est livrée avec quelques-uns qui effectuent des fonctions couramment nécessaires.

Tampon mémoire

Ces routines sont destinées aux cas où vous voulez simplement traiter une zone mémoire comme un fichier. Si la commande shell lirait normalement un fichier régulier de 513 octets de son entrée standard, vous voulez qu'elle prenne 513 octets d'une certaine adresse dans la mémoire de votre processus. Tous les octets que la commande shell voudra écrire dans son fichier de sortie, vous voulez qu'elle les stocke à une autre adresse dans la mémoire de votre processus.

Le distributeur d'entrée standard pour cela s'appelle pm_feed_from_memory. Le récepteur de sortie standard est pm_accept_to_memory.

Pour ces deux, l'argument est l'adresse d'une structure bufferDesc, qui est définie comme suit :

struct bufferDesc {
    unsigned int    size;
    unsigned char * buffer;
    unsigned int *  bytesTransferredP;
};

size est la taille du tampon mémoire et buffer est son emplacement en mémoire (adresse). Le distributeur d'entrée standard tentera de fournir l'intégralité du tampon à l'entrée standard de la commande shell ; le récepteur de sortie standard n'acceptera pas plus de données de la sortie standard de la commande shell que ce qui rentre dans le tampon. Les deux retournent le montant réel de données lues ou écrites, en octets, à l'emplacement identifié par bytesTransferredP. Sauf si bytesTransferredP est NULL.

Étant donné qu'un processus se termine généralement de manière anormale lorsqu'il n'est pas en mesure d'écrire tout ce qu'il voulait dans un tuyau, bytesTransferredP n'est généralement pas utile dans le cas du distributeur d'entrée standard.

Pamtuple

Ces routines sont destinées aux cas où vous avez des images en mémoire dans les structures de données utilisées par la famille de sous-routines PAM de la bibliothèque Netpbm - c'est-à-dire la structure PAM et un tableau de structures tuple. Avec ces routines, vous pouvez exécuter un programme Netpbm sur une telle image, tout comme vous le feriez avec la même image dans un fichier régulier.

Le distributeur d'entrée standard pour cela s'appelle pm_feed_from_pamtuples. Le récepteur de sortie standard est pm_accept_to_pamtuples.

Pour ces deux, l'argument est l'adresse d'une structure pamtuples, qui est définie comme suit :

struct pamtuples {
    struct pam * pamP;
    tuple ***    tuplesP;
};

Pour le distributeur d'entrée standard, vous fournissez une structure pam, valide jusqu'au membre tuple_type (sauf qu'il n'a pas d'importance quel est le membre file) et un tableau de tuples.

Pour le récepteur de sortie standard, vous fournissez uniquement de l'espace en mémoire pour la structure pam et l'adresse du tableau de tuples. La routine remplit la structure pam jusqu'au membre tuple_type (sauf qu'elle laisse le membre file indéfini) et alloue de l'espace pour le tableau de tuples avec malloc(). Vous êtes responsable de libérer cette mémoire.
