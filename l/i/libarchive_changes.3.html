NOM

libarchive_changes — modifications de l'interface libarchive

CHANGEMENTS DANS LIBARCHIVE 3

Cette page décrit les changements visibles par l'utilisateur dans libarchive3, et liste les fonctions publiques et autres symboles modifiés, dépréciés ou supprimés dans libarchive3, avec leurs remplacements éventuels.

Filtres multiples

Libarchive2 permettait un seul filtre (en entrée ou en sortie) actif sur une archive. Libarchive3 étend cela à une pile de longueur variable. Là où archive_write_set_compression_XXX() remplaçait tout filtre existant, archive_write_add_filter_XXX() étend le pipeline d'écriture avec un filtre supplémentaire.

Gestion des jeux de caractères

Libarchive2 supposait que la plateforme locale utilise Unicode comme encodage natif de wchar_t, ce qui est vrai sous Windows, Linux moderne et quelques autres systèmes, mais n'est certainement pas universel. En conséquence, les archives au format pax étaient écrites incorrectement sur certains systèmes, car le format pax nécessite UTF-8 et libarchive 2 supposait à tort que les chaînes wchar_t pouvaient être facilement converties en UTF-8.

Libarchive3 utilise la bibliothèque standard iconv pour convertir entre les jeux de caractères et introduit la notion de « jeu de caractères par défaut pour l'archive ». Pour prendre en charge cela, les objets archive_entry peuvent maintenant être liés à une archive particulière lorsqu'ils sont créés. Les conversions automatiques de jeux de caractères effectuées par les objets archive_entry lors de la lecture et de l'écriture des noms de fichiers, des noms d'utilisateur et d'autres chaînes utiliseront désormais un jeu de caractères par défaut approprié :

Si l'objet archive_entry est lié à une archive, il utilisera le jeu de caractères par défaut de cette archive.

Le codage par défaut de la plateforme (tel que retourné par nl_langinfo(CHARSET)) sera utilisé si rien d'autre n'est spécifié.

Libarchive3 introduit également des options de jeu de caractères pour de nombreux lecteurs et écrivains d'archives afin de contrôler le jeu de caractères qui sera utilisé pour les noms de fichiers écrits dans ces archives. Lorsque cela est possible, cela sera défini automatiquement en fonction des informations contenues dans l'archive elle-même. La combinaison de cela avec la notion d'un jeu de caractères par défaut pour l'archive devrait vous permettre de configurer libarchive pour lire des archives provenant d'autres plateformes et d'avoir les noms de fichiers et autres informations convertis de manière transparente dans le jeu de caractères adapté à votre application.

Changements de prototype

Ces changements cassent la compatibilité binaire ; libarchive3 a une nouvelle version de bibliothèque partagée pour refléter ces changements. La bibliothèque utilise maintenant des types larges portables tels que int64_t au lieu de types moins portables tels que off_t, gid_t, uid_t et ino_t.

Il y a quelques cas où ces changements affecteront votre code source :

  • Dans certains cas, les types plus larges de libarchive introduiront la possibilité de troncature : par exemple, sur un système avec un uid_t de 16 bits, vous risquez que le uid 65536 soit tronqué en uid 0, ce qui peut causer de graves problèmes de sécurité.
  • Les types de pointeurs de fonction typedef seront incompatibles. Par exemple, si vous définissez des callbacks de saut personnalisés, vous devrez peut-être utiliser un code similaire à ce qui suit si vous souhaitez prendre en charge la compilation avec libarchive2 et libarchive3 : 
    #if ARCHIVE_VERSION_NUMBER < 3000000
typedef off_t myoff_t;
#else
typedef int64_t myoff_t;
#endif

myoff_t
my_skip_function(struct archive *a, void *v, myoff_t o)
{
    ... implementation ...
}

Fonctions affectées :

  • archive_entry_gid(), archive_entry_set_gid()
  • archive_entry_uid(), archive_entry_set_uid()
  • archive_entry_ino(), archive_entry_set_ino()
  • archive_read_data_block(), archive_write_data_block()
  • archive_read_disk_gname(), archive_read_disk_uname()
  • archive_read_disk_set_gname_lookup(), archive_read_disk_set_group_lookup(), archive_read_disk_set_uname_lookup(), archive_read_disk_set_user_lookup()
  • archive_skip_callback()
  • archive_read_extract_set_skip_file(), archive_write_disk_set_skip_file(), archive_write_set_skip_file()
  • archive_write_disk_set_group_lookup(), archive_write_disk_set_user_lookup()

Là où ces fonctions ou leurs arguments prenaient ou retournaient gid_t, ino_t, off_t ou uid_t, ils prennent ou retournent maintenant int64_t ou équivalent.
