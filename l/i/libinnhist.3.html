NOM

his - routines pour la gestion de l'historique INN

SYNTAXE

#include <inn/history.h>
struct history;
struct token;
struct histstats {
    int hitpos;
    int hitneg;
    int misses;
    int dne;
};
#define HIS_RDONLY ...
#define HIS_RDWR ...
#define HIS_CREAT ...
#define HIS_ONDISK ...
#define HIS_INCORE ...
#define HIS_MMAP ...
enum {
    HISCTLG_PATH,
    HISCTLS_PATH,
    HISCTLS_SYNCCOUNT,
    HISCTLS_NPAIRS,
    HISCTLS_IGNOREOLD,
    HISCTLS_STATINTERVAL
};
struct history *HISopen(const char *path, const char *method,
                        int flags);
bool HISclose(struct history *history);
bool HISsync(struct history *history);
void HISsetcache(struct history *history, size_t size);
bool HISlookup(struct history *history, const char *key,
               time_t *arrived, time_t *posted, time_t *expires,
               TOKEN *token);
bool HIScheck(struct history *history, const char *key);
bool HISwrite(struct history *history, const char *key,
              time_t arrived, time_t posted, time_t expires,
              const TOKEN *token);
bool HISremember(struct history *history, const char *key,
                 time_t arrived, time_t posted);
bool HISreplace(struct history *history, const char *key,
                time_t arrived, time_t posted, time_t expires,
                const TOKEN *token);
bool HISexpire(struct history *history, const char *path,
               const char *reason, bool writing, void *cookie,
               time_t threshold,
               bool (*exists)(void *cookie, time_t arrived,
                              time_t posted, time_t expires,
                              const TOKEN *token));
bool HISwalk(struct history *history, const char *reason,
             void *cookie,
             bool (*callback)(void *cookie, time_t arrived,
                              time_t posted, time_t expires,
                              const TOKEN *token));
struct histstats HISstats(struct history *history);
const char *HISerror(struct history *history);
bool HISctl(struct history *history, int request, void *val);

DESCRIPTION

Ces fonctions fournissent l'accès à la base de données d'historique INN. Elles maintiennent des paires clé/valeur dans une base de données opaque tout en permettant l'expiration des informations obsolètes.

La structure d'historique est une poignée opaque retournée par HISopen.

La fonction HISopen ouvre le fichier d'historique désigné par path en utilisant le mode flags et la méthode spécifiée method. flags peut être HIS_RDONLY pour indiquer un accès en lecture seule à la base de données d'historique, ou HIS_RDWR pour un accès en lecture/écriture. Les méthodes d'historique sont définies au moment de la compilation ; la méthode d'historique actuellement disponible est "hisv6". En cas de succès, une poignée d'historique nouvellement initialisée est retournée, ou NULL en cas d'échec.

HIS_ONDISK, HIS_INCORE et HIS_MMAP peuvent être logiquement combinés (OR) dans flags pour donner une indication au gestionnaire d'historique sous-jacent sur la manière dont il doit gérer ses fichiers de données ; HIS_ONDISK indique que l'appelant souhaite que le maximum de données soit conservé sur disque (et hors mémoire), HIS_INCORE indique que les fichiers de données doivent être conservés en mémoire principale autant que possible, et HIS_MMAP que les fichiers doivent être mappés (mmap()) dans l'espace d'adressage du processus. HIS_INCORE est généralement utilisé lors d'une reconstruction massive de la base de données d'historique ; le gestionnaire d'historique sous-jacent peut supposer que l'appelant appellera HISsync() pour synchroniser les fichiers de données sur disque.

Le drapeau HIS_CREAT indique que la base de données d'historique doit être initialisée comme nouvelle ; si des options qui affectent la création de la base de données doivent être définies, une poignée d'historique anonyme doit être créée en appelant HISopen avec path défini sur NULL, toutes les options définies à l'aide de HISctl, puis la base de données ouverte en appelant HISctl avec HISCTLS_PATH.

La fonction HISclose ferme la poignée history et désalloue toutes les ressources associées. Elle retourne false en cas d'échec ou true en cas de succès.

La fonction HISsync synchronise toutes les transactions en attente associées à history sur le disque.

HISsetcache associe un cache utilisé pour accélérer HIScheck à history. Le cache occupera environ size octets.

HISlookup récupère un jeton de history basé sur la key fournie (normalement l'ID du message). Si aucune entrée avec un jeton associé ne peut être trouvée, HISlookup retourne false. Si un jeton est trouvé, arrived, expires et posted sont remplis avec les heures d'arrivée, d'expiration et de publication du message respectivement (ou zéro, si la composante temporelle n'est pas disponible), en plus de token qui est défini sur le jeton récupéré et une valeur de retour de fonction de true. N'importe lequel de arrived, expires, posted, ou token peut être NULL auquel cas cette composante n'est pas retournée à l'appelant, sans affecter la valeur de retour.

HIScheck vérifie dans la base de données history si la key (normalement l'ID du message) existe ; si la key a été précédemment définie via HISwrite, HIScheck retourne true, sinon false.

HISwrite écrit une nouvelle entrée dans la base de données history associée à la key. arrived, posted et expired spécifient les temps d'arrivée, de publication et d'expiration respectivement ; posted et expired peuvent être spécifiés comme <= 0 auquel cas cette composante sera traitée comme absente dans la base de données. token est associé à la key spécifiée. HISwrite retourne true en cas de succès, ou false en cas d'échec. Le comportement lorsque la key n'est pas unique par rapport aux entrées existantes dans history n'est pas spécifié.

HISremember écrit une nouvelle entrée dans la base de données history associée à la key, se contentant de se souvenir que cette key a été vue, avec son temps d'arrivée arrived et également son temps de publication posted, si connu. (Sinon, son temps de publication peut être spécifié comme <= 0 au cas où il est absent.) HISremember retourne true en cas de succès, ou false en cas d'échec. Le comportement lorsque la key n'est pas unique par rapport aux entrées existantes dans history n'est pas spécifié.

HISreplace remplace une entrée existante dans la base de données history, associée à la key. arrived, posted, expired spécifient les temps d'arrivée, de publication et d'expiration respectivement ; posted et expired peuvent être spécifiés comme <= 0 auquel cas cette composante sera traitée comme absente dans la base de données. token est associé à la key spécifiée ; si NULL alors la base de données d'historique se contente de se souvenir que cette key a été vue, avec son temps d'arrivée. HISreplace retourne true en cas de succès, ou false en cas d'échec.

HISexpire expire la base de données d'historique associée à history, créant une nouvelle base de données de remplacement au même endroit si path est NULL, ou dans path si ce n'est pas NULL ; si path n'est pas NULL, le remplacement de l'ancienne base de données d'historique par la nouvelle est supposé être effectué hors bande par l'appelant. Le drapeau writing est normalement passé comme true, si vous souhaitez interdire l'écriture de la nouvelle base de données (et donc simplement voir les rappels), writing peut être mis à false.

Si le mécanisme d'historique sous-jacent a besoin de suspendre le serveur, la chaîne reason est utilisée comme argument de la commande `ctlinnd pause', et à ce titre le serveur doit être réservé par l'appelant avant d'appeler HISexpire ; si l'appelant souhaite interdire la pause du serveur, passer NULL y parviendra. Si reason n'est pas NULL, alors au retour réussi de HISexpire le serveur sera laissé en pause et l'appelant devra le débloquer.

La base de données d'historique est scannée et les entrées avec un jeton de stockage associé sont passées à la fonction de discrimination exists.

Si exists() retourne false, cela indique que l'entité stockée associée au jeton n'est plus disponible (ou n'est plus requise), et par conséquent l'entrée d'historique associée peut être expirée une fois qu'elle répond à la contrainte de threshold. Si exists() retourne true, l'entrée est conservée telle quelle dans la nouvelle base de données expirée.

La fonction exists reçoit les temps d'arrivée, de publication et d'expiration, en plus du jeton associé à l'entrée. Notez que la publication et/ou l'expiration peuvent être zéro, mais que le jeton ne sera jamais NULL (de telles entrées sont gérées uniquement via le mécanisme de seuil). Le jeton de stockage passé à la fonction de discrimination peut être mis à jour si nécessaire (par exemple, comme pourrait l'exiger une implémentation de gestion de stockage hiérarchique).

Si path n'est pas NULL, le fichier indiqué par path est utilisé pour la nouvelle base de données d'historique. Si path est NULL, la nouvelle base de données est créée dans le même répertoire que l'ancienne. Si writing est true, la nouvelle base de données est écrite. Sinon, la fonction se contente de scanner l'ancienne base de données et de renvoyer les entrées qui ne sont pas expirées dans la nouvelle.

Le cookie est une valeur opaque qui est passée à la fonction exists et qui peut être utilisée pour stocker des informations dont cette dernière pourrait avoir besoin.

La fonction HISwalk parcourt la base de données d'historique et appelle la fonction callback pour chaque entrée. La fonction callback reçoit le cookie, les temps d'arrivée, de publication et d'expiration, ainsi que le jeton associé à l'entrée. Si la fonction callback retourne false, le parcours est arrêté. La fonction HISwalk retourne true si le parcours s'est terminé normalement, et false si il a été arrêté prématurément.

La fonction HISstats retourne une structure histstats contenant des statistiques sur l'utilisation de la base de données d'historique.

La fonction HISerror retourne une chaîne de caractères décrivant la dernière erreur qui s'est produite.

La fonction HISctl permet de contrôler le comportement du gestionnaire d'historique. Les requêtes possibles sont : HISCTLG_PATH pour obtenir le chemin du fichier d'historique ; HISCTLS_PATH pour définir le chemin du fichier d'historique ; HISCTLS_SYNCCOUNT pour définir le nombre de transactions avant une synchronisation ; HISCTLS_NPAIRS pour définir le nombre de paires clé/valeur à conserver en mémoire ; HISCTLS_IGNOREOLD pour ignorer les entrées plus anciennes qu'un certain temps ; HISCTLS_STATINTERVAL pour définir l'intervalle de temps pour la collecte de statistiques.

NAME

libinnhist — routines for manipulating INN history databases

SYNOPSIS

#include <inn/hist.h>

HIScheck(3), HISclose(3), HISctl(3), HISerror(3), HISexpire(3), HISfeed(3), HISfifo(3), HISopen(3), HISremember(3), HISreplace(3), HISstats(3), HISwalk(3), HISwrite(3)

DESCRIPTION

The history database is used to store information about articles that have been processed by the news server. This information can then be used to avoid processing duplicate articles, and also to determine which articles have expired and should be removed from the server.

HIScheck checks the history database for the given token. The result is true if the token is found in the history database, and false otherwise. If the token is found, the arrival and posting times are returned in atime and ptime respectively. If the posting time is unknown, ptime will be set to the arrival time. The token is the Message-ID of the article.

HISwrite adds the given token to the history database with the given arrival and posting times. The token is the Message-ID of the article.

HISremember is similar to HISwrite, but it will only add the token if it is not already present in the history database. This is useful for preventing duplicate writes.

HISreplace is similar to HISwrite, but it will replace an existing entry if the token is already present in the history database. This is useful for updating the arrival and posting times of an article.

HISexpire removes entries from the history database that have expired. The threshold is a time value; entries with a posting time less than threshold are removed. If the posting time is unknown, the arrival time is used instead. The token is the Message-ID of the article. The reason argument can be used to pass a reason for the expiration to the underlying history manager.

Entries in the database with a posting time less than threshold with no token associated with them are deleted from the database. In case the posting time is unknown, the arrival time is used instead.

The parameter cookie is passed to the discrimination function, and may be used for any purpose required by the caller.

If the discrimination function attempts to access the underlying database (for read or write) during the callback, the behaviour is unspecified.

HISwalk provides an iteration function for the specified history database. For every entry in the history database, callback is invoked, passing the cookie, arrival, posting, and expiry times, in addition to the token associated with the entry. If the callback() returns false the iteration is aborted and HISwalk returns false to the caller.

To process the entire database in the presence of a running server, reason may be passed; if this argument is not NULL, it is used as an an argument to the `ctlinnd (reserve|pause|go)' commands. If reason is NULL and the server is running, the behaviour of HISwalk is undefined.

If the callback function attempts to access the underlying database during the callback, the behaviour is unspecified.

HISstats returns statistics on the history cache mechanism; given a handle history, the return value is a struct histstats detailing:

"hitpos"
The number of times an item was found directly in the cache and known to exist in the underlying history manager.
"hitneg"
The number of times an item was found directly in the cache and known not to exist in the underlying history manager.
"misses"
The number of times an item was not found directly in the cache, but on retrieval from the underlying history manager was found to exist.
"dne"
The number of times an item was not found directly in the cache, but on retrieval from the underlying history manager was found not to exist.

Note that the history cache is only checked by HIScheck and only affected by HIScheck, HISwrite, HISremember and HISreplace. Following a call to HISstats the history statistics associated with history are cleared.

HISerror returns a string describing the most recent error associated with history; the format and content of these strings is history manager dependent. Note that on setting an error, the history API will call the warn function from libinn(3).

HISctl provides a control interface to the underlying history manager. The request argument determines the type of the request and the meaning of the val argument. The values for request are:

"HISCTLG_PATH" (const char **)
Get the base file path which the history handle represents. val should be a pointer to a location of type const char *. The result must not later be passed to free(3).
"HISCTLS_PATH" (const char *)
Set the base file path which this history handle should use; typically this is used after an anonymous handle has been created using HISopen(NULL, ...). val should be a value of type const char * and will be copied before being stored internally.
"HISCTLS_SYNCCOUNT" (size_t *)
Set an upper bound on how many history operations may be pending in core before being synced to permanent storage; 0 indicates unlimited. val should be a pointer to a value of type size_t and will not be modified by the call.
"HISCTLS_NPAIRS" (size_t *)
Set a hint to the to the underlying history manager as to how many entries there are expected to be in the history database; 0 indicates that an automatic or default sizing should be made. val should be a pointer to a value of type size_t and will not be modified by the call.
"HISCTLS_IGNOREOLD" (bool *)
Instruct the underlying history manager to ignore existing database when creating new ones; typically this option may be set to true if the administrator believes that the existing history database is corrupt and that ignoring it may help. val should be a pointer to a value of type bool and will not be modified by the call.
"HISCTLS_STATINTERVAL" (time_t *)
For the history v6 and tagged hash managers, set the interval, in seconds, between stat(2)s of the history files checking for replaced files (as happens during expire); this option is typically used by nnrpd(8) like applications. val should be a pointer to a value of type time_t and will not be modified by the call.
