X509_REQ_PRINT_EX(3) Manuel des fonctions de bibliothèque X509_REQ_PRINT_EX(3)

NOM

X509_REQ_print_ex, X509_REQ_print, X509_REQ_print_fp — imprimer joliment une demande de certification PKCS#10

SYNOPSIS

bibliothèque “libcrypto”
#include <openssl/x509.h>

int
X509_REQ_print_ex(BIO *bio, X509_REQ *req, unsigned long nameflags, unsigned long skipflags);

int
X509_REQ_print(BIO *bio, X509_REQ *req);

int
X509_REQ_print_fp(FILE *fp, X509_REQ *req);

DESCRIPTION

X509_REQ_print_ex() imprime les informations contenues dans req dans bio sous une forme lisible par l'homme. L'impression est interrompue dès qu'une opération échoue, à l'exception des échecs lors de la tentative de décodage ou d'impression de la clé publique qui ne sont pas considérés comme des erreurs.

Par défaut, les blocs d'informations suivants sont imprimés dans l'ordre suivant. Chaque bloc peut être ignoré en définissant le bit correspondant dans skipflags, fourni entre parenthèses après chaque description de bloc.

  • Une paire de lignes indiquant "Certificate Request:" et "Data:" ne contenant aucune information. (X509_FLAG_NO_HEADER)
  • La valeur contenue dans le champ version en notation décimale et hexadécimale. (X509_FLAG_NO_VERSION)
  • Le nom du sujet est imprimé avec X509_NAME_print_ex(3). (X509_FLAG_NO_SUBJECT)
  • L'algorithme de clé publique est imprimé avec i2a_ASN1_OBJECT(3), et la clé publique retournée par X509_REQ_get_pubkey(3) avec EVP_PKEY_print_public(3). (X509_FLAG_NO_PUBKEY)
  • Pour chaque attribut X.501 qui n'est pas une extension demandée selon X509_REQ_extension_nid(3), l'identificateur d'objet est imprimé avec i2a_ASN1_OBJECT(3), et toutes les valeurs des types V_ASN1_PRINTABLESTRING, V_ASN1_T61STRING, et V_ASN1_IA5STRING sont imprimées avec BIO_write(3). (X509_FLAG_NO_ATTRIBUTES)
  • Les extensions demandées sont récupérées avec X509_REQ_get_extensions(3) et leurs types et valeurs sont imprimés avec i2a_ASN1_OBJECT(3) et X509V3_EXT_print(3), ou, si cette dernière échoue, avec ASN1_STRING_print(3). (X509_FLAG_NO_EXTENSIONS)
  • La signature est imprimée avec X509_signature_print(3). (X509_FLAG_NO_SIGDUMP)

L'argument nameflags modifie le format d'impression des objets Name X.501 contenus dans req. Il est transmis à X509_NAME_print_ex(3). Si nameflags est défini à X509_FLAG_COMPAT, l'argument indent de X509_NAME_print_ex(3) est défini à 16 espaces et le format traditionnel SSLeay est utilisé. Sinon, si le seul bit défini dans XN_FLAG_SEP_MASK est XN_FLAG_SEP_MULTILINE, indent est défini à 12 espaces. Sinon, indent est défini à zéro.

X509_REQ_print() est une fonction d'encapsulation définissant nameflags à XN_FLAG_COMPAT et skipflags à X509_FLAG_COMPAT.

X509_REQ_print_fp() est similaire à X509_REQ_print() sauf qu'elle imprime vers fp.

VALEURS DE RETOUR

Ces fonctions retournent 1 si toutes les informations demandées ont été imprimées avec succès, même si des erreurs se sont produites lors de la tentative de décodage ou d'impression de la clé publique, ou 0 si une opération échoue.

VOIR AUSSI

BIO_new(3), X509_print_ex(3), X509_REQ_new(3)

HISTORIQUE

X509_REQ_print() est apparu pour la première fois dans SSLeay 0.4.4 et X509_REQ_print_fp() dans SSLeay 0.6.0. Ces fonctions sont disponibles depuis OpenBSD 2.4.

X509_REQ_print_ex() est apparu pour la première fois dans OpenSSL 0.9.7 et est disponible depuis OpenBSD 3.2.

BOGUES

Certains échecs d'impression sont ignorés silencieusement lors de l'impression des extensions, ce qui peut entraîner l'impression de données incomplètes.
