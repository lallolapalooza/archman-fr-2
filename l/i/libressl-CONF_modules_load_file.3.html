libressl-CONF_modules_load_file(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

CONF_MODULES_LOAD_FILE(3) Manuel des fonctions de bibliothèque CONF_MODULES_LOAD_FILE(3)

NOM

CONF_modules_load_file, CONF_modules_load, X509_get_default_cert_area — Fonctions de configuration OpenSSL

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/conf.h>

int
CONF_modules_load_file(const char *filename, const char *appname, unsigned long flags);

int
CONF_modules_load(const CONF *cnf, const char *appname, unsigned long flags);

#include <openssl/x509.h>

const char *
X509_get_default_cert_area(void);

DESCRIPTION

La fonction CONF_modules_load_file() configure OpenSSL en utilisant le fichier filename au format openssl.cnf(5) et le nom d'application appname. Si filename est NULL, le fichier de configuration OpenSSL standard /etc/ssl/openssl.cnf est utilisé. Si appname est NULL, le nom d'application OpenSSL standard "openssl_conf" est utilisé. Le comportement peut être personnalisé à l'aide de flags.

Voir la section EXEMPLES pour les fonctions supplémentaires qui pourraient devoir être appelées. Appeler les fonctions de configuration dans le bon ordre pour obtenir l'effet désiré peut être délicat car de nombreuses fonctions de configuration s'appellent mutuellement en interne.

CONF_modules_load() est identique à CONF_modules_load_file() sauf qu'elle lit les informations de configuration à partir de cnf.

Les flags suivants sont actuellement reconnus :

CONF_MFLAGS_IGNORE_ERRORS
Ignore les erreurs retournées par les modules de configuration individuels. Par défaut, la première erreur de module est considérée comme fatale et aucun module supplémentaire n'est chargé.
CONF_MFLAGS_SILENT
N'ajoute aucune information d'erreur. Par défaut, toutes les erreurs de module ajoutent des informations d'erreur à la file d'attente des erreurs.
CONF_MFLAGS_NO_DSO
Désactive le chargement des modules de configuration à partir des DSO. Ce drapeau est fourni à des fins de compatibilité et n'a aucun effet.
CONF_MFLAGS_IGNORE_MISSING_FILE
Permet à CONF_modules_load_file() d'ignorer les fichiers de configuration manquants. Par défaut, un fichier de configuration manquant retourne une erreur.
CONF_MFLAGS_DEFAULT_SECTION
Si appname n'est pas NULL mais n'existe pas, bascule vers la section par défaut "openssl_conf".

En utilisant CONF_modules_load_file() avec les drapeaux appropriés, une application peut personnaliser la configuration de l'application pour mieux répondre à ses besoins. Dans certains cas, l'utilisation d'un fichier de configuration est facultative et son absence n'est pas une erreur : dans ce cas, CONF_MFLAGS_IGNORE_MISSING_FILE serait activé.

Les erreurs lors de la configuration peuvent également être traitées différemment par différentes applications. Par exemple, dans certains cas, une erreur peut simplement afficher un message d'avertissement et l'application peut continuer. Dans d'autres cas, une application peut considérer une erreur de fichier de configuration comme fatale et se terminer immédiatement.

Les applications peuvent utiliser la fonction CONF_modules_load() si elles souhaitent charger un fichier de configuration elles-mêmes et avoir un contrôle plus fin sur la façon dont les erreurs sont traitées.

VALEURS DE RETOUR

CONF_modules_load_file() et CONF_modules_load() retournent 1 en cas de succès et zéro ou une valeur négative en cas d'échec. Si les erreurs de module ne sont pas ignorées, le code de retour reflétera la valeur de retour du module défaillant (ce sera toujours zéro ou négatif).

X509_get_default_cert_area() retourne un pointeur vers la chaîne constante "/etc/ssl".

FICHIERS

/etc/ssl
répertoire de configuration standard
/etc/ssl/openssl.cnf
fichier de configuration standard

EXEMPLES

Charge un fichier de configuration et affiche toutes les erreurs, puis quitte (fichier manquant considéré comme fatal) :

if (CONF_modules_load_file(NULL, NULL, 0) <= 0) {
	fprintf(stderr, "FATAL: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
	exit(1);
}

Charge le fichier de configuration par défaut en utilisant la section indiquée par "myapp", tolère les fichiers manquants, mais quitte en cas d'autres erreurs :

if (CONF_modules_load_file(NULL, "myapp",
    CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
	fprintf(stderr, "FATAL: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
	exit(1);
}

Charge un fichier et une section de configuration personnalisés au lieu de ceux standards, affiche uniquement des avertissements en cas d'erreur, fichier de configuration manquant ignoré :

OPENSSL_no_config();
if (CONF_modules_load_file("/something/app.cnf", "myapp",
    CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
	fprintf(stderr, "WARNING: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
}

Dans l'exemple précédent, l'appel à OPENSSL_no_config(3) est requis en premier pour supprimer le chargement automatique du fichier de configuration standard.

Charge et analyse le fichier de configuration manuellement, gestion personnalisée des erreurs :

FILE	*fp;
CONF	*cnf = NULL;
long	 eline;

fp = fopen("/somepath/app.cnf", "r");
if (fp == NULL) {
	fprintf(stderr, "Error opening configuration file\n");
	/* Autre comportement en cas de fichier de configuration manquant */
} else {
	cnf = NCONF_new(NULL);
	if (NCONF_load_fp(cnf, fp, &eline) == 0) {
		fprintf(stderr, "Error on line %ld of configuration file\n",
		    eline);
		ERR_print_errors_fp(stderr);
		/* Autre comportement en cas de fichier de configuration malformé */
	} else if (CONF_modules_load(cnf, "appname", 0) <= 0) {
		fprintf(stderr, "Error configuring application\n");
		ERR_print_errors_fp(stderr);
		/* Autre comportement en cas d'erreur de configuration */
	}
	fclose(fp);
	NCONF_free(cnf);
}
