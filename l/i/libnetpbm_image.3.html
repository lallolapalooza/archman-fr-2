NAME

libnetpbm_image - aperçu des fonctions de traitement d'images netpbm

DESCRIPTION

Ce manuel de référence couvre les fonctions de la bibliothèque libnetpbm pour le traitement d'images, en utilisant les formats d'images Netpbm et les formats d'images en mémoire de libnetpbm.

Pour des raisons historiques ainsi que pour éviter le désordre, il ne couvre pas les classes largement obsolètes de fonctions libnetpbm pour PBM, PGM, PPM et PNM. Pour celles-ci, voir le Manuel des fonctions PBM (3), Manuel des fonctions PGM (3), Manuel des fonctions PPM (3), et Manuel des fonctions PNM (3). Les programmes qui traitent des images PBM, PGM, PPM et PNM ont besoin des fonctions de ces manuels. Les fonctions de ce manuel sont suffisantes pour cela.

Les fonctions de dessin PPM sont couvertes séparément dans le Manuel des fonctions de dessin PPM (1).

Pour des informations générales et d'introduction à l'utilisation de libnetpbm, voir le Guide de l'utilisateur Libnetpbm (3).

libnetpbm contient également des fonctions qui ne sont pas spécifiquement orientées vers le traitement des données d'images. Lisez à leur sujet dans le Manuel utilitaire Libnetpbm (3).

Pour utiliser ces services, incluez pam.h.

Types

Voici quelques types importants que vous utilisez avec libnetpbm:

sample
Un échantillon d'une image Netpbm. Voir les spécifications du format -- à titre d'exemple, l'intensité rouge d'un pixel particulier d'une image PPM est un échantillon. C'est un type entier.
tuple
Une tuple d'une image PAM ou l'équivalent PAM d'une image PNM. Voir la spécification du format PAM -- à titre d'exemple, un pixel d'une image PPM serait une tuple. Une tuple est un tableau d'échantillons.
samplen
Identique à sample, sauf sous forme normalisée. C'est un type à virgule flottante avec une valeur dans la plage 0..1. 0 correspond à une valeur d'échantillon PAM/PNM de 0. 1 correspond à une valeur d'échantillon PAM/PNM égale au maxval de l'image.
tuplen
Identique à tuple, sauf qu'elle est composée d'échantillons normalisés (samplen) au lieu d'échantillons réguliers (sample).

struct pam

L'argument principal de la plupart des fonctions PAM est l'adresse d'une structure pam, qui est définie comme suit :

  
    struct pam {
        int size
        int len
        FILE *file   
        int format
        int plainformat
        int height
        int width
        int depth
        sample maxval
        int bytes_per_sample
        char tuple_type[256]
        int allocation_depth
        char **comment_p;
    }

Voir Le Guide de l'utilisateur Libnetbm pour des informations sur la structure pam.

Macros

PNM_MAXMAXVAL est le maxval maximum que les images Netpbm pouvaient historiquement avoir : 255. De nombreux programmes ne sont pas capables de gérer des images Netpbm avec un maxval supérieur à celui-ci. Il est nommé ainsi pour une compatibilité ascendante -- il portait ce nom à l'époque où c'était *le* maxval maximum.

PNM_OVERALLMAXVAL est le maxval maximum que les images Netpbm peuvent avoir aujourd'hui (65535).

PBM_FORMAT, RPBM_FORMAT, PGM_FORMAT, RPGM_FORMAT, PPM_FORMAT, RPPM_FORMAT, et PAM_FORMAT sont les codes de format des différents formats Netpbm. RPBM_FORMAT est le format PBM brut et PBM_FORMAT est le format PBM simple, et ainsi de suite. Voir le membre format de la structure pam.

PAM_FORMAT_TYPE(format) donne le type d'un format, étant donné le code de format. Les types de formats sont PBM, PGM, PPM, et PAM, et les macros pour les codes de type sont respectivement PBM_TYPE, PGM_TYPE, PPM_TYPE, et PAM_TYPE. Notez qu'il y a plus de codes de format qu'il n'y a de types de format car il existe différents codes de format pour les sous-formats simples et bruts de chaque format.

Description

pnm_readpaminit() lit l'en-tête d'une image PAM ou PNM et remplit les membres de la structure pam que vous lui transmettez. Il peut aussi demander à l'appelant de définir un certain nombre d'autres membres de la structure.

L'argument size est la taille en octets de la structure que vous transmettez dans pamP. Cet argument permet de gérer les changements potentiels de la structure au fil du temps, avec l'ajout de nouveaux champs à la fin. Cet argument permet à pnm_readpaminit de distinguer entre un nouveau programme qui souhaite exploiter les fonctionnalités supplémentaires et un ancien programme qui ne le peut pas (ou un nouveau programme qui ne souhaite tout simplement pas gérer la complexité accrue). Au minimum, cette taille doit contenir les membres jusqu'à tuple_type. Vous devriez utiliser la macro PAM_STRUCT_SIZE pour calculer cet argument. Par exemple, PAM_STRUCT_SIZE(tuple_type).

PAM_STRUCT_SIZE a été introduite dans Netpbm 10.23 (juillet 2004). Dans les anciennes versions de Netpbm, vous pouvez simplement utiliser sizeof(), mais votre code n'est alors *pas* compatible ascendante au niveau du code source avec les versions plus récentes de libnetpbm (car lorsque vous le compilez avec les fichiers d'en-tête plus récents de libnetpbm, vous indiquerez que votre structure contient tous les nouveaux membres qui ont été inventés, mais votre code ne les initialisera pas réellement). Vous pourriez donc vouloir calculer une taille correcte vous-même.

La fonction s'attend à trouver le fichier image positionné au début de l'en-tête et le laisse positionné au début du raster.

pnm_readpamrow() lit une ligne du raster à partir d'un fichier image Netpbm. Elle s'attend à ce que tous les membres de la structure *pamP soient définis lors de l'invocation et ne les modifie pas. Elle s'attend à trouver le fichier positionné au début de la ligne en question dans le raster et le laisse positionné juste après. Elle renvoie la ligne sous forme de tableau de tuples tuplerow, qui doit déjà avoir ses pointeurs de colonne configurés de manière à former un tableau C bidimensionnel. Le tuple le plus à gauche est l'élément 0 de ce tableau.

pnm_readpam() lit une image entière à partir d'un fichier image PAM ou PNM et alloue l'espace pour renvoyer le raster. Elle s'attend à trouver le fichier positionné au premier octet de l'image et le laisse positionné juste après l'image.


La fonction n'exige pas que *pamP ait des membres définis et les définit tous. size est la taille de stockage en octets de la structure *pamP, normalement sizeof(struct pam).

La valeur de retour est un tableau nouvellement alloué des lignes de l'image, la ligne supérieure étant l'élément 0 du tableau. Chaque ligne est représentée telle que pnm_readpamrow() la renverrait.

La valeur de retour est également effectivement un tableau C tridimensionnel d'échantillons, les dimensions correspondant à la hauteur, la largeur et la profondeur de l'image, dans cet ordre.

pnm_readpam() combine les fonctions de pnm_allocpamarray(), pnm_readpaminit() et des itérations de pnm_readpamrow(). Elle peut nécessiter plus de stockage dynamique que vous ne pouvez vous le permettre.

pnm_readpamrown() est similaire à pnm_readpamrow() sauf qu'elle renvoie le contenu de la ligne sous forme normalisée (composé de tuples normalisés (tuplen) au lieu de la forme de base (tuple).

pnm_readpaminit() et pnm_readpam arrêtent le programme avec un message sur la sortie d'erreur standard si l'en-tête de l'image PAM ou PNM n'est pas syntaxiquement valide, y compris s'il contient un nombre trop grand pour être traité en utilisant les structures de données normales du système (c'est-à-dire un nombre qui ne rentre pas dans un 'int' C).

Les membres de la structure *pamP qui doivent être configurés à l'invocation, et leurs significations, sont les mêmes que pour pnm_writepaminit.

pnm_writepam() définit le membre bytes_per_sample en fonction des informations fournies.

tuplearray est un tableau de lignes tel que vous passeriez à pnm_writepamrow(), la ligne supérieure étant l'élément 0 du tableau.

pnm_writepam() combine les fonctions de pnm_writepaminit() et des itérations de pnm_writepamrow(). Son entrée raster peut nécessiter plus de stockage que vous ne pouvez vous le permettre.

pnm_writepamrown() est similaire à pnm_writepamrow() sauf qu'elle prend le contenu de la ligne sous forme normalisée (composé de tuples normalisés (tuplen) au lieu de la forme de base (tuple).

pnm_formatpamrow() est similaire à pnm_writepamrow(), sauf qu'au lieu d'écrire une ligne dans un fichier, elle place les mêmes octets qui iraient dans le fichier dans un tampon que vous fournissez. Il n'existe pas de fonction équivalente pour construire un en-tête d'image ; c'est-à-dire qu'il n'y a pas d'analogue à pnm_writepaminit(). Mais le format de l'en-tête, particulièrement pour PAM, est si simple que vous pouvez facilement le construire vous-même avec les fonctions de bibliothèque C standard.

pnm_formatpamrow() a été ajoutée dans Netpbm 10.25 (octobre 2004).

NAME

libnetpbm_image - manipuler des lignes de pixels d'images Netpbm

DESCRIPTION

Ce document décrit des fonctions pour manipuler des lignes de pixels dans le format d'image PAM (Portable Arbitrary Map). PAM est un format d'image simple, de haut niveau, conçu pour être facile à analyser et à étendre. Il peut représenter des images en niveaux de gris, en couleur RVB, et avec des plans de transparence (canaux alpha).

Les fonctions décrites ici travaillent sur des lignes de pixels, représentées par des pointeurs vers des structures `tuple`. Une ligne de pixels est une séquence de `tuple`s, où chaque `tuple` représente un pixel. Les `tuple`s peuvent avoir différents types, comme `RGB` pour la couleur, `GRAYSCALE` pour les niveaux de gris, ou `RGB_ALPHA` et `GRAYSCALE_ALPHA` pour inclure un canal alpha.

Types

Les types de `tuple` les plus courants sont :

  • WHITE: pixel blanc.
  • BLACK: pixel noir.
  • GRAYSCALE: un niveau de gris.
  • RED: composante rouge d'un pixel RVB.
  • GREEN: composante verte d'un pixel RVB.
  • BLUE: composante bleue d'un pixel RVB.
  • RGB: couleur RVB.
  • BLACK_ALPHA: pixel noir avec canal alpha.
  • WHITE_ALPHA: pixel blanc avec canal alpha.
  • GRAYSCALE_ALPHA: niveau de gris avec canal alpha.
  • RED_ALPHA: composante rouge avec canal alpha.
  • GREEN_ALPHA: composante verte avec canal alpha.
  • BLUE_ALPHA: composante bleue avec canal alpha.
  • RGB_ALPHA: couleur RVB avec canal alpha.

Les types se terminant par `_ALPHA` incluent un canal alpha qui indique le niveau d'opacité du pixel.

Macros

Il existe plusieurs macros pour obtenir des informations sur un `tuple` ou une ligne de pixels :

pnm_tuple_type(p): Renvoie le type de `tuple` de l'image PAM pointée par p.

pnm_maxval(p): Renvoie la valeur maximale pour un échantillon dans l'image PAM pointée par p.

pnm_channels(p): Renvoie le nombre de canaux (échantillons par pixel) dans l'image PAM pointée par p.

pnm_tuple_size(p): Renvoie la taille en octets d'un `tuple` dans l'image PAM pointée par p.

pnm_row_size(p): Renvoie la taille en octets d'une ligne de pixels dans l'image PAM pointée par p.

pnm_black_tuple(p): Renvoie un `tuple` représentant un pixel noir pour l'image PAM pointée par p.

pnm_white_tuple(p): Renvoie un `tuple` représentant un pixel blanc pour l'image PAM pointée par p.

Functions

pnm_applyopacityrown() et pnm_unapplyopacityrown():

La fonction pnm_applyopacityrown() applique le canal alpha d'une image. Si une image possède un plan d'opacité (c'est-à-dire si son type de `tuple` inclut `_ALPHA`), cette fonction réduit l'intensité de chaque échantillon de chaque pixel en fonction de la valeur du canal alpha. Cela est utile pour composer des images. Par exemple, si la moitié gauche de l'image a une opacité de 50% et la moitié droite de 100%, pnm_applyopacityrown() réduira l'intensité des échantillons de la moitié gauche de 50%.

Si l'image n'a pas de plan d'opacité, pnm_applyopacityrown() ne fait rien (ce qui équivaut à une opacité de 100%). Les types de `tuple` reconnus comme ayant une opacité sont RGB_ALPHA et GRAYSCALE_ALPHA.

pnm_unapplyopacityrown() fait l'inverse. Elle suppose que les intensités sont déjà réduites selon le plan d'opacité et les ramène à leur valeur normale.

pnm_applyopacityrown() travaille sur des `tuple`s normalisés et *proportionnels à l'intensité*. Cela signifie que vous devriez généralement lire la ligne depuis le fichier image avec pnm_readpamrown(), puis la corriger avec un gamma en utilisant pnm_ungammarown(), et ensuite appeler pnm_applyopacityrown(). Vous manipulez ensuite la ligne (par exemple, en l'ajoutant à d'autres lignes traitées de manière similaire), puis vous appelez pnm_unapplyopacityrown(), puis pnm_gammarown(), et enfin pnm_writepamrown().

pnm_applyopacityrown() et pnm_unapplyopacityrown() ont été introduites dans Netpbm 10.25 (octobre 2004).

pnm_normalizetuple() et pnm_unnormalizetuple() convertissent entre les types de données `tuple` et `tuplen`. Le premier représente une valeur d'échantillon en utilisant le même entier non signé que dans l'image PAM, tandis que le second représente une valeur d'échantillon comme un nombre mis à l'échelle entre 0 et 1 par rapport à la valeur maximale. C'est-à-dire que pnm_normalizetuple() divise chaque valeur d'échantillon par la valeur maximale, et pnm_unnormalizetuple() multiplie chaque valeur par la valeur maximale.

pnm_normalizeRow() et pnm_unnormalizeRow() font la même chose sur une ligne de `tuple` entière, mais ont une fonctionnalité supplémentaire : vous pouvez spécifier une fonction de transformation à appliquer en plus. Typiquement, il s'agit d'une transformation gamma. Vous pouvez bien sûr appliquer votre fonction de transformation plus facilement séparément de la normalisation, mais tout faire en une seule fois est généralement bien plus rapide. Pourquoi ? Parce que vous pouvez utiliser une table de correspondance (lookup table) indexée par un entier d'un côté et produisant un nombre en virgule flottante de l'autre. Pour le faire séparément, vous devriez soit effectuer des calculs en virgule flottante sur la valeur normalisée, soit effectuer la transformation sur les valeurs entières et perdre beaucoup de précision.

Si vous n'avez aucune transformation à appliquer, spécifiez simplement NULL pour l'argument transform, et la fonction se contentera de normaliser (c'est-à-dire diviser ou multiplier par la valeur maximale).

Voici un exemple de réalisation d'une transformation. L'exemple compose deux images ensemble, ce qui doit être fait avec des valeurs d'échantillons linéaires en intensité.

pnm_transformMap * const transform1 = pnm_createungammatransform(&inpam1);
pnm_transformMap * const transform2 = pnm_createungammatransform(&inpam2);
pnm_transformMap * const transformOut = pnm_creategammatransform(&outpam);
pnm_readpamrow(&inpam1, inrow1);
pnm_readpamrow(&inpam2, inrow2);
pnm_normalizeRow(&inpam1, inrow1, transform1, normInrow1);
pnm_normalizeRow(&inpam2, inrow2, transform2, normInrow2);
for (col = 0; col < outpam.width; ++col)
    normOutrow[col] = (normInrow1[col] + normInrow2[col])/2;
pnm_unnormalizeRow(&outpam, normOutrow, transformOut, outrow);
pnm_writepamrow(&outpam, outrow);

Pour spécifier une transformation, vous devez créer un objet spécial pnm_transformMap et le passer comme argument transform. Typiquement, votre transformation est une transformation gamma car vous voulez travailler avec des valeurs d'échantillons linéaires en intensité et le format d'image PAM utilise des valeurs ajustées par gamma. Dans ce cas, utilisez simplement pnm_creategammatransform() et pnm_createungammatransform() pour créer cet objet et ne vous souciez pas de son contenu.

pnm_creategammatransform() et pnm_createungammatransform() créent des objets que vous utilisez avec pnm_normalizeRow() et pnm_unnormalizeRow() comme décrit ci-dessus. L'objet créé décrit une transformation qui applique ou inverse l'ajustement gamma de la recommandation ITU-R BT.709 utilisée dans les images visuelles PAM et normalise ou dénormalise les valeurs d'échantillons.

pnm_freegammatransform() et pnm_freeungammatransform() détruisent les objets.
