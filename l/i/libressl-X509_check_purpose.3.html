NOM

X509_check_purpose — vérifier l'usage prévu d'une clé publique

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/x509v3.h>

int
X509_check_purpose(X509 *certificat, int but, int ca);

DESCRIPTION

Si l'argument but est -1, X509_check_purpose() ignore l'argument ca et vérifie que toutes les extensions du certificat peuvent être analysées et passent des contrôles de cohérence minimaux, garantissant qu'aucune extension n'apparaît plus d'une fois. Elle s'assure également que toutes les extensions sont mises en cache dans l'objet X509.

Si l'argument but n'est pas -1 et que le drapeau ca est 0, X509_check_purpose() vérifie également si la clé publique contenue dans le certificat est destinée à être utilisée pour le but donné, qui peut être l'une des constantes entières suivantes. La vérification réussit si aucune des conditions énumérées ci-dessous n'est violée. Elle échoue toujours si l'analyse échoue pour toute extension contenue dans le certificat.

X509_PURPOSE_SSL_CLIENT
  • Si le certificat contient une extension d'usage étendu de clé (Extended Key Usage), il contient le but RFC 5280 « Authentification client TLS WWW » (NID_client_auth).
  • Si le certificat contient une extension d'usage de clé (Key Usage), le bit digitalSignature est défini.
  • Si le certificat contient une extension de type de certificat Netscape (Netscape Cert Type), le bit « Certificat client SSL » est défini (NS_SSL_CLIENT).
X509_PURPOSE_SSL_SERVER
  • Si le certificat contient une extension d'usage étendu de clé, il contient le but RFC 5280 « Authentification serveur TLS WWW » (NID_server_auth) ou le but privé « Netscape Server Gated Crypto » (NID_ns_sgc) ou « Microsoft Server Gated Crypto » (NID_ms_sgc).
  • Si le certificat contient une extension d'usage de clé, au moins l'un des bits digitalSignature et keyEncipherment est défini.
  • Si le certificat contient une extension de type de certificat Netscape, le bit « Certificat serveur SSL » est défini (NS_SSL_SERVER).
X509_PURPOSE_NS_SSL_SERVER
Ceci effectue les mêmes vérifications que X509_PURPOSE_SSL_SERVER et exige en outre qu'une extension d'usage de clé, si elle est présente, ait le bit keyEncipherment défini.
X509_PURPOSE_SMIME_SIGN
  • Si le certificat contient une extension d'usage étendu de clé, il contient le but RFC 5280 « Protection par e-mail » (NID_email_protect).
  • Si le certificat contient une extension d'usage de clé, au moins l'un des bits digitalSignature et nonRepudiation est défini.
  • Si le certificat contient une extension de type de certificat Netscape, il a le bit « Certificat S/MIME » défini. Si le bit « Certificat client SSL » est défini mais pas le bit « Certificat S/MIME », aucune décision n'est prise.
X509_PURPOSE_SMIME_ENCRYPT
  • Si le certificat contient une extension d'usage étendu de clé, il contient le but RFC 5280 « Protection par e-mail » (NID_email_protect).
  • Si le certificat contient une extension d'usage de clé, le bit keyEncipherment est défini.
  • Si le certificat contient une extension de type de certificat Netscape, il a le bit « Certificat S/MIME » défini. Si le bit « Certificat client SSL » est défini mais pas le bit « Certificat S/MIME », aucune décision n'est prise.
X509_PURPOSE_CRL_SIGN
  • Si le certificat contient une extension d'usage de clé, le bit cRLSign est défini.
X509_PURPOSE_ANY
Rien n'est requis sauf que, si des extensions sont présentes, leur analyse doit réussir.
X509_PURPOSE_OCSP_HELPER
Rien n'est requis sauf que, si des extensions sont présentes, leur analyse doit réussir. Le programme applicatif est censé effectuer la vérification réelle par d'autres moyens.
X509_PURPOSE_TIMESTAMP_SIGN
  • Le certificat contient une extension d'usage étendu de clé contenant le but RFC 5280 « Horodatage » et aucun autre but. Cette extension est marquée comme critique.
  • Si le certificat contient une extension d'usage de clé, au moins l'un des bits digitalSignature et nonRepudiation est défini, et aucun autre bit n'est défini.

Si l'argument but n'est pas -1 et que le drapeau ca est non nul, X509_check_purpose() vérifie, en plus des contrôles de cohérence minimaux, si le certificat peut être utilisé comme certificat d'autorité de certification dans le contexte du but donné. Pour réussir, la vérification exige toujours qu'aucune des conditions suivantes ne soit violée :

  • Si le certificat contient des extensions, leur analyse réussit.
  • Si le certificat contient une extension d'usage de clé, le bit keyCertSign est défini.
  • Si le certificat contient une extension de contraintes de base (Basic Constraints), le champ cA est défini.
  • Si le certificat est un certificat de version 1, le nom du sujet correspond au nom de l'émetteur et le certificat est auto-signé.

NOM

X509_check_purpose, X509_check_host, X509_check_email — vérifier le but d'un certificat X509

SYNOPSIS

#include <openssl/x509v3.h>

int
X509_check_purpose(X509 *x, int purpose, int ca);

int
X509_check_host(X509 *x, const char *name, size_t namelen,
    unsigned int flags, STACK_OF(X509_EXTENSION) *ext);

int
X509_check_email(X509 *x, const char *email, size_t emaillen,
    unsigned int flags);

DESCRIPTION

La fonction X509_check_purpose() vérifie si le certificat x peut être utilisé pour le purpose spécifié. Le paramètre ca indique si le certificat est censé être utilisé comme une autorité de certification (CA). Si ca est non nul, le certificat est vérifié comme une CA. Sinon, il est vérifié comme un certificat d'utilisateur final.

Les valeurs prédéfinies pour purpose sont les suivantes :

X509_PURPOSE_SSL_CLIENT ou X509_PURPOSE_NS_SSL_CLIENT
  • Si le certificat contient une extension Usage des Clés Étendu, il contient le but RFC 5280 « Authentification du client TLS » (NID_client_auth).
  • Si le certificat n'est pas un certificat de version 1 et ne contient pas d'extension Contraintes de Base, il contient une extension Usage des Clés avec le bit keyCertSign défini ou une extension Type de Certificat Netscape avec le bit « Certificat CA SSL » défini.
X509_PURPOSE_SSL_SERVER ou X509_PURPOSE_NS_SSL_SERVER
  • Si le certificat contient une extension Usage des Clés Étendu, il contient le but RFC 5280 « Authentification du serveur WWW TLS » (NID_server_auth) ou le but privé « Netscape Server Gated Crypto » (NID_ns_sgc) ou « Microsoft Server Gated Crypto » (NID_ms_sgc).
  • Si le certificat n'est pas un certificat de version 1 et ne contient pas d'extension Contraintes de Base, il contient une extension Usage des Clés avec le bit keyCertSign défini ou une extension Type de Certificat Netscape avec le bit « Certificat CA SSL » défini.
X509_PURPOSE_SMIME_SIGN ou X509_PURPOSE_SMIME_ENCRYPT
  • Si le certificat contient une extension Usage des Clés Étendu, il contient le but RFC 5280 « Protection des e-mails » (NID_email_protect).
  • Si le certificat n'est pas un certificat de version 1 et ne contient pas d'extension Contraintes de Base, il contient une extension Usage des Clés avec le bit keyCertSign défini ou une extension Type de Certificat Netscape avec le bit « Certificat CA S/MIME » défini.
X509_PURPOSE_CRL_SIGN, X509_PURPOSE_OCSP_HELPER, ou X509_PURPOSE_TIMESTAMP_SIGN
  • Si le certificat n'est pas un certificat de version 1 et ne contient pas d'extension Contraintes de Base, il contient une extension Usage des Clés avec le bit keyCertSign défini ou une extension Type de Certificat Netscape avec au moins un des bits « Certificat CA SSL », « Certificat CA S/MIME », ou « Certificat CA de signature d'objet » définis.
X509_PURPOSE_ANY
Rien n'est requis sauf que, si des extensions sont présentes, leur analyse doit réussir. La vérification réussit même si les trois autres conditions communes citées ci-dessus sont violées.

Si la fonction X509_PURPOSE_add(3) a été appelée avant X509_check_purpose(), elle peut avoir installé différentes fonctions de vérification fournies par l'utilisateur pour certains des buts standard listés ci-dessus, ou elle peut avoir installé des fonctions de vérification supplémentaires fournies par l'utilisateur pour des identifiants de purpose définis par l'utilisateur non listés ci-dessus.

VALEURS DE RETOUR

Si l'analyse des extensions du certificat échoue, si les vérifications de cohérence échouent ou si le purpose est invalide, X509_check_purpose() retourne -1 pour indiquer l'erreur.

Si l'argument purpose est -1 et que l'analyse et les vérifications de cohérence minimales réussissent, X509_check_purpose() retourne 1 pour indiquer le succès.

Sinon, elle retourne les valeurs suivantes :

Si ca est 0 :

0 Échec Le certificat ne peut pas être utilisé pour le purpose.
1 Succès Le certificat peut être utilisé pour le purpose.
2 Inconnu Aucune décision ne peut être prise.

Si ca est non nul :

0 Échec Le certificat ne peut pas être utilisé comme une CA pour le purpose.
1 Succès Le certificat peut être utilisé comme une CA pour le purpose.
3 Succès Le certificat est une CA de version 1.
4 Succès L'Usage des Clés autorise keyCertSign.
5 Succès Un Type de Certificat Netscape autorise l'utilisation comme CA.
