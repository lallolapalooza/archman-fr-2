NOM

libudev - API pour énumérer et introspecter les périphériques locaux

SYNTAXE

#include <libudev.h>

pkg-config --cflags --libs libudev

DESCRIPTION

libudev.h fournit une API pour introspecter et énumérer les périphériques sur le système local. Cette bibliothèque est prise en charge, mais ne devrait pas être utilisée dans de nouveaux projets. Veuillez consulter sd-device(3) pour un remplacement équivalent avec une API plus moderne.

Toutes les fonctions nécessitent un contexte libudev pour fonctionner. Ce contexte peut être créé via udev_new(3). Il est utilisé pour suivre l'état de la bibliothèque et lier les objets ensemble. Aucun état global n'est utilisé par libudev, tout est toujours lié à un contexte udev.

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de ne faire des appels à setenv() qu'à partir d'une phase précoce du programme lorsque aucun autre thread n'a été démarré.

Pour introspecter un périphérique local sur un système, un objet périphérique udev peut être créé via udev_device_new_from_syspath(3) et fonctions similaires. L'objet périphérique permet de consulter l'état actuel, de lire et écrire des attributs, et de rechercher des propriétés du périphérique en question.

Pour énumérer les périphériques locaux sur le système, un objet d'énumération peut être créé via udev_enumerate_new(3).

Pour surveiller le système local pour les périphériques branchés ou débranchés à chaud, un moniteur peut être créé via udev_monitor_new_from_netlink(3).

Chaque fois que libudev renvoie une liste d'objets, l'API udev_list_entry(3) doit être utilisée pour itérer, accéder et modifier ces listes.

De plus, libudev exporte également des API héritées qui ne devraient pas être utilisées par de nouveaux logiciels (et ne sont donc pas documentées dans le cadre de ce manuel). Cela inclut la base de données matérielle connue sous le nom de udev_hwdb (veuillez utiliser la nouvelle API sd-hwdb(3) à la place) et l'objet udev_queue pour interroger le démon udev (qui ne devrait pas du tout être utilisé par de nouveaux logiciels).
