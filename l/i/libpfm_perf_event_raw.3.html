LIBPFM(3) Manuel du programmeur Linux LIBPFM(3)

NOM

libpfm_perf_event_raw - prise en charge de la syntaxe des événements bruts perf_events

SYNOPSIS

#include <perfmon/pfmlib.h>

Nom du PMU : perf_raw
Desc. du PMU : Syntaxe brute des événements perf_events

DESCRIPTION

La bibliothèque prend en charge un modèle de PMU pseudo afin de permettre le codage brut des événements PMU pour l'interface noyau perf_events de Linux.

Avec ce PMU, il est possible de fournir le codage hexadécimal brut de tout événement matériel pour tous les modèles de PMU. Le codage brut est passé tel quel au noyau. Tous les événements sont codés en tant que PERF_TYPE_RAW. Par conséquent, les événements génériques de perf_events, tels que les cycles, les instructions, ne peuvent pas être codés par ce PMU.

La syntaxe est très simple : rX. X est la valeur hexadécimale sur 64 bits pour l'événement. Elle peut inclure des filtres d'événements sur certains modèles de PMU. Le nombre hexadécimal est passé sans le préfixe 0x, par exemple, r01c4.

Les attributs perf_events standard de la bibliothèque sont pris en charge par ce modèle de PMU. Ils sont séparés par des deux-points, comme il est d'usage avec la bibliothèque.

MODIFICATEURS

Les modificateurs suivants sont pris en charge par ce modèle de PMU :

u
Mesurer au niveau utilisateur, ce qui inclut les niveaux de privilège 1, 2, 3. Ceci correspond à PFM_PLM3. C'est un modificateur booléen.
k
Mesurer au niveau noyau, ce qui inclut le niveau de privilège 0. Ceci correspond à PFM_PLM0. C'est un modificateur booléen.
h
Mesurer au niveau hyperviseur. Ceci correspond à PFM_PLMH. C'est un modificateur booléen.
mg
Mesurer uniquement l'exécution de l'invité. C'est un modificateur booléen.
mh
Mesurer uniquement l'exécution de l'hôte. C'est un modificateur booléen.
period
Spécifier la valeur de la période d'échantillonnage. La valeur peut être exprimée en décimal ou en hexadécimal. La valeur est sur 64 bits. Cette option est mutuellement exclusive avec freq. La période est exprimée dans l'unité de l'événement. Il n'y a pas de valeur par défaut.
freq
Spécifier la valeur de la fréquence d'échantillonnage. La valeur peut être exprimée en décimal ou en hexadécimal. La valeur est sur 64 bits. Cette option est mutuellement exclusive avec period. La valeur est exprimée en Hertz. Par exemple, freq=100 signifie que l'événement doit être échantillonné 100 fois par seconde en moyenne. Il n'y a pas de valeur par défaut.
excl
L'événement associé est le seul événement mesuré sur le PMU. Cela ne s'applique qu'aux événements matériels. Cet attribut nécessite des privilèges d'administrateur. La valeur par défaut est désactivée.
precise
Active le mode d'échantillonnage précis. Cette option n'est valide que lors de l'échantillonnage sur des événements. L'option prend un argument entier. Elle peut avoir les valeurs suivantes : 1=activer l'échantillonnage précis, 2=activer l'échantillonnage précis et éliminer le décalage, 3=activer l'échantillonnage précis, éliminer le décalage et le biais. Tous les événements ne prennent pas nécessairement en charge le mode précis à tous les niveaux, cela dépend du PMU sous-jacent. L'élimination du décalage est une fonctionnalité de meilleure volonté. Elle peut ne pas fonctionner pour tous les échantillons. Cette option est mutuellement exclusive avec hw_smpl. Cette option implique l'utilisation du mécanisme d'assistance matérielle d'échantillonnage.
hw_smpl
Active l'assistance matérielle d'échantillonnage. C'est une option booléenne. Elle est fausse par défaut. Sur certains processeurs, il est possible que le matériel enregistre des échantillons dans un tampon, puis notifie le noyau lorsqu'il est plein. Une telle fonctionnalité peut ne pas être disponible pour tous les événements. L'utilisation d'un tampon matériel n'élimine pas nécessairement le décalage et le biais, elle réduit généralement la surcharge de l'échantillonnage basé sur interruption en amortissant l'interruption sur plusieurs échantillons. Cette option est généralement implicite avec les événements d'échantillonnage précis.
cpu
Cette option entière est utilisée avec les événements système, c'est-à-dire les événements attachés à un CPU plutôt qu'à un thread. La valeur désigne le CPU auquel attacher l'événement. Il appartient à l'appelant de la bibliothèque d'utiliser le champ cpu dans l'argument de codage de l'événement de la bibliothèque pour créer l'événement. Aucune vérification de la validité du numéro de CPU n'est effectuée par la bibliothèque. La valeur par défaut est -1 pour ce champ.
pinned
Cette option booléenne est utilisée avec les événements système, c'est-à-dire les événements attachés à un CPU plutôt qu'à un thread. Si elle est définie, l'événement est marqué comme épinglé. Cela signifie qu'il doit rester sur les compteurs en permanence, c'est-à-dire qu'il ne peut pas être multiplexé. Il ne peut y avoir que autant d'événements épinglés qu'il y a de compteurs, bien que la bibliothèque ne vérifie pas cela, c'est le sous-système perf_event qui le fait. La valeur par défaut pour ce champ est false, c'est-à-dire que l'événement n'est pas épinglé.
