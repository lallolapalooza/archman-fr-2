libnids - bibliothèque de boîte E pour système de détection d'intrusion réseau

DESCRIPTION

libnids fournit la fonctionnalité d'un composant boîte E de système de détection d'intrusion réseau (NIDS). Il effectue actuellement :

1. Défragmentation IP
2. Réassemblage de flux TCP
3. Détection de balayage de ports TCP

libnids effectue le réassemblage TCP/IP exactement de la même manière que les noyaux Linux 2.0.36, et gère correctement toutes les attaques implémentées dans fragrouter(8) (ainsi que de nombreuses autres attaques).

ROUTINES

nids_init() initialise l'application pour la capture, en se basant sur les valeurs définies dans la variable globale nids_params, déclarée comme suit :

struct nids_prm {
	int	n_tcp_streams;
	int	n_hosts;
	char	*device;
	char	*filename;
	int	sk_buff_size;
	int	dev_addon;
	void	(*syslog)(int type, int err, struct ip *iph, void *data);
	int	syslog_level;
	int	scan_num_hosts;
	int	scan_num_ports;
	int	scan_delay;
	void	(*no_mem)(void);
	int	(*ip_filter)(struct ip *iph);
	char	*pcap_filter;
	int	promisc;
	int	one_loop_less;
	int	pcap_timeout;
	int	multiproc;
	int	queue_limit;
	int	tcp_workarounds;
	pcap_t	*pcap_desc;
} nids_params;

Les membres de cette structure sont :

n_tcp_streams
Taille de la table de hachage utilisée pour stocker les informations de connexion TCP (un maximum de 3/4 des connexions TCP de n_tcp_streams seront suivies simultanément). Valeur par défaut : 1024
n_hosts
Taille de la table de hachage utilisée pour stocker les informations de défragmentation IP. Valeur par défaut : 256
filename
Si cette variable est définie, libnids appellera pcap_open_offline avec cette variable comme argument (au lieu de pcap_open_live()). Valeur par défaut : NULL
device
Interface à surveiller. Valeur par défaut : NULL (auquel cas un périphérique approprié est déterminé automatiquement). Si cette variable prend la valeur all, libnids tentera de capturer les paquets sur toutes les interfaces (ce qui ne fonctionne que sous Linux)
sk_buff_size
Taille de struct sk_buff (utilisé pour la mise en file d'attente des paquets), qui doit correspondre à la valeur sur les hôtes surveillés. Valeur par défaut : 168
dev_addon
Nombre d'octets dans struct sk_buff réservé aux informations de la couche liaison. Valeur par défaut : -1 (auquel cas un décalage approprié est déterminé automatiquement en fonction du type de couche liaison)
syslog
Fonction de rappel syslog, utilisée pour signaler les conditions inhabituelles, telles que les tentatives de scan de ports, les drapeaux d'en-tête TCP invalides, etc. Valeur par défaut : nids_syslog (qui enregistre les messages via syslog(3) sans tenir compte du taux de messages par seconde ou de l'espace disque libre)
syslog_level
Niveau de journalisation utilisé par nids_syslog pour signaler les événements via syslog(3). Valeur par défaut : LOG_ALERT
scan_num_hosts
Taille de la table de hachage utilisée pour stocker les informations de scan de ports (le nombre maximum de scans de ports qui seront détectés simultanément). S'il est défini à 0, la détection de scan de ports sera désactivée. Valeur par défaut : 256
scan_num_ports
Nombre minimum de ports qui doivent être scannés depuis le même hôte source avant qu'il ne soit identifié comme un scan de ports. Valeur par défaut : 10
scan_delay
Délai maximum (en millisecondes) entre les connexions à différents ports pour qu'elles soient identifiées comme faisant partie d'un scan de ports. Valeur par défaut : 3000
no_mem
Fonction de rappel en cas de manque de mémoire, utilisée pour terminer le processus appelant gracieusement.
ip_filter
Fonction de rappel de filtrage IP, utilisée pour rejeter sélectivement les paquets IP, inspectés après réassemblage. Si la fonction retourne une valeur non nulle, le paquet est traité ; sinon, il est rejeté. Valeur par défaut : nids_ip_filter (qui retourne toujours 1)
pcap_filter
Chaîne de filtre pcap(3) appliquée à la couche liaison (paquets bruts, non assemblés). Remarque : les filtres comme ``tcp dst port 23'' ne géreront PAS correctement le trafic fragmenté de manière appropriée, par ex. des fragments IP de 8 octets ; il faut ajouter "or (ip[6:2] & 0x1fff != 0)" à la fin du filtre pour traiter les paquets réassemblés. Valeur par défaut : NULL
promisc
Si non nul, libnids mettra l'interface (ou les interfaces) sur lesquelles elle écoute en mode promiscue. Valeur par défaut : 1
one_loop_less
Désactivé par défaut ; voir les commentaires dans le fichier API.html
pcap_timeout
Définit le délai d'attente de lecture de pcap, qui peut être pris en charge ou non par votre plateforme. Valeur par défaut : 1024.
multiproc
S'il est non nul, crée un thread séparé pour le traitement des paquets. Voir API.html. Valeur par défaut : 0.
queue_limit
Si multiproc est non nul, c'est le nombre maximum de paquets mis en file d'attente dans le thread qui lit les paquets de libpcap. Valeur par défaut : 20000
tcp_workarounds
Active des vérifications supplémentaires pour les implémentations TCP défectueuses telles que celles qui permettent la fermeture de connexions malgré le fait que des retransmissions de paquets perdus devraient avoir lieu en premier (comme indiqué par RFC 793, section 3.5). Si non nul, libnids définira l'état NIDS_TIMED_OUT pour les connexions fermées de manière brutale. Valeur par défaut : 0
pcap_desc
Si cette variable est définie, libnids n'appellera ni pcap_open_live ni pcap_open_offline, mais utilisera un descripteur PCAP pré-ouvert ; utilisez ceci avec nids_pcap_handler() afin de fournir interactivement des paquets à libnids. Valeur par défaut : NULL

Retourne 1 en cas de succès, 0 en cas d'échec (auquel cas nids_errbuf contient un message d'erreur approprié).

libnids(3) — libnids — Documentation Arch Linux

NAME

libnids(3) ― analyseur de paquets réseau pour le système d'exploitation Linux

SYNOPSIS

#include <sys/types.h>
#include <netinet/in.h>
#include <libnids.h>

void nids_register_udp(nids_udp_hdr_func handler);
void nids_register_tcp(nids_tcp_hdr_func handler);
void nids_unregister_tcp(nids_tcp_hdr_func handler);
void nids_killtcp(struct tcp_stream *tcp_stream);
void nids_discard(struct half_stream *half, int discard);
int nids_run(void);
int nids_dispatch(int cnt);
int nids_next(void);
int nids_getfd(void);
void nids_register_chksum_ctl(struct nids_chksum_ctl *chksum_ctl_array, int len);
void nids_pcap_handler(const u_char *user, const struct pcap_pkthdr *h, const u_char *bytes);
struct tcp_stream *nids_find_tcp_stream(struct tuple4 *tuple);
void nids_free_tcp_stream(struct tcp_stream *stream);

DESCRIPTION

libnids est une bibliothèque qui analyse le trafic réseau et fournit une interface pour l'accès aux flux TCP et UDP. Elle prend en charge la réassemblage des fragments IP et la gestion des connexions TCP.

La fonction nids_register_udp() enregistre une fonction de rappel définie par l'utilisateur pour traiter les paquets UDP.

La fonction nids_register_tcp() enregistre une fonction de rappel définie par l'utilisateur pour traiter les flux TCP validés et réassemblés par libnids. La structure tcp_stream est définie comme suit :

struct tcp_stream {
	struct tuple4 {
		u_short source;
		u_short	dest;
		u_int	saddr;
		u_int	daddr;
	} addr;
	char			nids_state;
	struct half_stream {
		char	state;
		char	collect;
		char	collect_urg;
		char	*data;
		u_char	urgdata;
		int	count;
		int	offset;
		int	count_new;
		char	count_new_urg;
		...
	} client;
	struct half_stream	server;
	...
	void			*user;
};

Les membres de la structure tuple4 identifient une connexion TCP unique :

source, dest
Numéros de port client et serveur
saddr, daddr
Adresses IP client et serveur

Les membres de la structure half_stream décrivent chaque moitié d'une connexion TCP (client et serveur) :

state
État du socket (par exemple, TCP_ESTABLISHED).
collect
Un booléen qui spécifie si les données doivent être collectées pour cette moitié de la connexion dans le tampon data.
collect_urg
Un booléen qui spécifie si les données urgentes pointées par le pointeur d'urgence TCP doivent être collectées dans le tampon urgdata pour cette moitié de la connexion.
data
Tampon pour les données normales.
urgdata
Tampon d'un octet pour les données urgentes.
count
Le nombre d'octets ajoutés à data depuis la création de la connexion.
offset
L'offset actuel par rapport au premier octet stocké dans le tampon data, identifiant le début des données nouvellement reçues.
count_new
Le nombre d'octets ajoutés à data depuis la dernière invocation de la fonction de rappel TCP (si 0, aucune nouvelle donnée n'est arrivée).
count_new_urg
Le nombre d'octets ajoutés à urgdata depuis la dernière invocation de la fonction de rappel TCP (si 0, aucune nouvelle donnée urgente n'est arrivée).

La valeur du champ nids_state fournit des informations sur l'état de la connexion TCP, à utiliser par la fonction de rappel TCP :

NIDS_JUST_EST
Connexion nouvellement établie. Les paramètres de connexion dans la structure addr sont disponibles pour inspection. Si la connexion est intéressante, la fonction de rappel TCP peut spécifier quelles données elle souhaite recevoir à l'avenir en définissant des valeurs non nulles pour les variables collect ou collect_urg dans les membres appropriés de la structure half_stream du client ou du serveur.
NIDS_DATA
De nouvelles données sont arrivées sur une connexion. Les structures half_stream contiennent des tampons de données.
NIDS_CLOSE, NIDS_RESET, NIDS_TIMED_OUT
Connexion fermée. La fonction de rappel TCP doit libérer toutes les ressources qu'elle a pu allouer pour cette connexion.

Le pointeur param passé par libnids en argument à la fonction de rappel TCP peut être défini pour enregistrer un pointeur vers des données spécifiques à la connexion définies par l'utilisateur afin de les passer aux invocations ultérieures de la fonction de rappel TCP (par exemple, le répertoire de travail courant pour une connexion de contrôle FTP, etc.).

Le pointeur user dans la structure tcp_stream a le même but, sauf qu'il est global au flux, tandis que le pointeur param est différent d'une fonction de rappel à l'autre, même si elles ont été appelées pour le même flux.

nids_unregister_tcp() désenregistre une fonction de rappel définie par l'utilisateur pour traiter les flux TCP.

nids_killtcp() met fin à la connexion TCP spécifiée avec des paquets RST symétriques entre le client et le serveur.

nids_discard() peut être appelée depuis la fonction de rappel TCP pour spécifier le nombre d'octets à ignorer à partir du début du tampon data (en mettant à jour la valeur offset en conséquence) après la sortie de la fonction de rappel TCP. Sinon, les nouvelles données (totalisant count_new octets) seront ignorées par défaut.

nids_run() démarre l'application pilotée par les paquets, lisant les paquets dans une boucle infinie et invoquant les fonctions de rappel enregistrées pour gérer les nouvelles données au fur et à mesure qu'elles arrivent. Cette fonction ne retourne pas.

nids_dispatch() tente de traiter cnt paquets avant de retourner, avec un cnt de -1 compris comme tous les paquets disponibles dans un tampon pcap, ou tous les paquets d'un fichier lors d'une lecture hors ligne. En cas de succès, retourne le nombre de paquets traités, qui peut être zéro en cas de fin de fichier (lecture hors ligne) ou lors de l'atteinte de pcap_timeout (si pris en charge par votre plateforme). En cas d'échec, retourne -1, plaçant un message d'erreur approprié dans nids_errbuf.

nids_next() traite le prochain paquet disponible avant de retourner. Retourne 1 en cas de succès, 0 si aucun paquet n'a été traité, en mettant nids_effbuf approprié si une erreur a empêché le traitement des paquets.

nids_getfd() peut être utilisé par une application dormante dans select(2) pour surveiller un descripteur de fichier socket présent dans le jeu de descripteurs de lecture fd_set. Retourne le descripteur de fichier en cas de succès, -1 en cas d'échec (auquel cas nids_errbuf contient un message d'erreur approprié).

nids_register_chksum_ctl() prend comme arguments un tableau d'éléments struct nids_chksum_ctl et le nombre d'éléments dans le tableau. Un élément nids_chksum_ctl est défini comme suit :

struct nids_chksum_ctl {
	u_int netaddr;
	u_int mask;
	u_int action;
	/* private members */
};

Les fonctions de somme de contrôle internes vérifieront d'abord les éléments de ce tableau un par un, et si l'adresse IP source SRCIP du paquet actuel satisfait la condition


(SRCIP&chksum_ctl_array[i].mask)==chksum_ctl_array[i].netaddr

alors si le champ action est NIDS_DO_CHKSUM, le paquet sera soumis à la somme de contrôle ; si le champ action est NIDS_DONT_CHKSUM, le paquet ne sera pas soumis à la somme de contrôle. Si le paquet ne correspond à aucun des éléments du tableau, l'action par défaut est d'effectuer la somme de contrôle.

nids_pcap_handler() peut être utilisé par une application qui exécute déjà une capture avec libpcap, afin de passer des trames à libnids de manière interactive (trame par trame) au lieu de demander à libnids d'effectuer la capture elle-même.

nids_find_tcp_stream() retourne un pointeur vers la structure tcp_stream correspondant au tuple passé en argument si libnids connaît déjà cette connexion TCP, sinon elle retourne NULL.

nids_free_tcp_stream() supprime la structure tcp_stream donnée de la liste des flux suivis par libnids. Attention : son utilisation peut entraîner des plantages ! Voir les commentaires dans le fichier API.html.
