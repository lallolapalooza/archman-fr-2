Table Des Matières

Ces fonctions de bibliothèque font partie de Netpbm(1)

Cette page documente les fonctions de la bibliothèque de sous-routines libnetpbm qui ne sont pas directement liées aux données d'image.

Pour des informations introductives et générales sur l'utilisation de libnetpbm, voir le Guide de l'utilisateur Libnetpbm(3)

Les fonctions libnetpbm les plus couramment utilisées sont celles qui lisent, écrivent et traitent les images Netpbm. Celles-ci sont documentées dans le Manuel de traitement des images Netpbm Libnetpbm(3)

Pour utiliser ces services, inclure pam.h.

Fonctions

Initialisation

Aperçu

void pm_init( const char * progname, unsigned int flags );

void pm_proginit( int * argcP, char * argv[] );

Description

Tous les programmes Netpbm doivent appeler pm_proginit() juste après le démarrage, avant de traiter leurs arguments. pm_proginit(), entre autres choses, traite les arguments universels Netpbm et les supprime de la liste des arguments.

Un programme qui n'est pas un programme Netpbm, mais qui utilise simplement les services de libnetpbm, n'a pas besoin d'invoquer pm_proginit. Mais un tel programme doit invoquer pm_init().

Par 'programme Netpbm', nous entendons un programme qui fait partie du paquet Netpbm ou qui est destiné à agir comme tel. pm_proginit() fait des choses que tous les programmes Netpbm font par convention. Par exemple, il analyse la liste des arguments pour les
options communes , les gère et les supprime de la liste des arguments. Par conséquent, si vous voulez que votre programme ait les mêmes options communes que celles du paquet Netpbm, vous pourriez utiliser pm_proginit(), et si ce n'est pas le cas, vous ne le devez pas.

pm_proginit() est principalement destiné aux développeurs Netpbm, vous ne devez donc pas vous attendre à ce qu'il ait une fonction stable d'une version à l'autre, et vous devez consulter les commentaires dans le code source pour voir exactement ce qu'il fait.

Tout programme qui utilise libnetpbm mais n'appelle pas pm_proginit (c'est-à-dire qu'il n'est pas un programme Netpbm) doit appeler pm_init(). L'endroit conventionnel pour le faire est tout au début du programme. Ceci configure certaines variables globales du programme pour une utilisation par les fonctions libnetpbm.

L'argument progname est le nom du programme que les fonctions libnetpbm utiliseront dans les messages qu'elles émettent. Normalement, vous utiliseriez argv[0] pour cela.

flags est sans signification, mais pour la compatibilité future, vous devez le définir à zéro.

pm_init() et pm_proginit() existent au moins depuis Netpbm 9.25 (mars 2002). Une autre fonction nommée pm_init() existe dans les anciennes versions de Netpbm, mais était à usage interne. Les programmes Netpbm de cette époque utilisent pbm_init(), etc. pour faire ce que pm_proginit() fait aujourd'hui. Aujourd'hui, pbm_init(), etc. existent pour la compatibilité ascendante et sont identiques à pm_proginit().

Accès à un flux de fichier ou d'image

Aperçu

FILE *pm_openr( char * name );

FILE *pm_openw( char * name );

FILE *pm_openr_seekable( const char * name );

FILE *pm_close( FILE * fp );

void pm_tell2( FILE * fileP, pm_filepos * fileposP, unsigned int fileposSize );

unsigned int pm_tell( FILE * fileP );

void pm_seek2( FILE * fileP, const pm_filepos * fileposP, unsigned int fileposSize );

void pm_seek( FILE * fileP, unsigned long filepos );

char *pm_read_unknown_size( FILE * fp, long * nread );

Description

Un flux d'image est simplement un flux de fichier (représenté dans la bibliothèque C standard par le type FILE *).

Ces routines fonctionnent sur des fichiers de plus de 2 Gio si le système sous-jacent le fait, en utilisant l'interface standard des gros fichiers. Avant Netpbm 10.15 (avril 2003), cependant, elles échouaient à ouvrir tout fichier de cette taille ou à traiter tout décalage dans un fichier qui ne pouvait pas être représenté sur 32 bits.

pm_openr() ouvre le fichier donné en lecture, avec une gestion des erreurs appropriée. Un nom de fichier de - est interprété comme l'entrée standard. pm_openw() ouvre le fichier donné en écriture, avec une gestion des erreurs appropriée. pm_close() ferme le descripteur de fichier, avec une gestion des erreurs appropriée.

pm_openr_seekable() semble ouvrir le fichier comme pm_openr(), mais le fichier ainsi ouvert est garanti être positionnable (vous pouvez utiliser ftell() et fseek() dessus). pm_openr_seekable() réalise cela en copiant l'intégralité du fichier dans un fichier temporaire et en vous donnant le descripteur du fichier temporaire, si nécessaire. Si le fichier que vous nommez est un fichier régulier, il est déjà positionnable, donc pm_openr_seekable() fait la même chose que pm_openr().

Mais s'il s'agit, par exemple, d'un tuyau, il n'est pas positionnable. Donc pm_openr_seekable() lit le tuyau jusqu'à EOF dans un fichier temporaire, puis ouvre ce fichier temporaire et renvoie le descripteur du fichier temporaire. Le fichier temporaire est positionnable.


Le fichier créé par pm_openr_seekable() est un fichier que le système d'exploitation reconnaît comme temporaire, donc lorsque vous fermez le fichier, par quelque moyen que ce soit, il est supprimé.

Vous avez besoin d'un fichier positionnable si vous avez l'intention de faire plusieurs passes dans le fichier. La seule alternative est de lire l'image entière en mémoire et de travailler à partir de cette copie. Cela peut utiliser trop de mémoire. Notez que l'image prend moins de place dans le cache de fichiers que dans un tampon en mémoire. Jusqu'à 96 fois moins d'espace ! Chaque échantillon est un entier dans le tampon, qui fait généralement 96 bits. Dans le fichier, un échantillon peut faire jusqu'à 1 bit et rarement plus de 8 bits.

pm_tell2() renvoie un identifiant pour la position actuelle du flux d'image (fichier), qu'il s'agisse de l'en-tête ou d'une ligne de la trame raster. Utilisez cet identifiant comme argument pour pm_seek2() afin de repositionner le fichier ultérieurement. Le fichier doit être positionnable (ce que vous pouvez garantir en l'ouvrant avec pm_openr_seekable()) ou cela peut échouer.

L'identifiant de position de fichier est de type pm_filepos, qui est destiné à être opaque, c'est-à-dire à n'être utilisé qu'avec ces deux fonctions. En pratique, il s'agit d'un décalage de fichier et il fait 32 ou 64 bits selon la capacité du système sous-jacent. Pour une compatibilité ascendante et descendante maximale, les fonctions qui prennent ou renvoient un pm_filepos ont un argument fileposSize pour la taille de la structure de données. En C, codez simplement sizeof(pm_filepos) pour cela.

pm_seek() et pm_tell sont uniquement pour la compatibilité ascendante. Ne les utilisez pas dans du nouveau code. Ces fonctions ne sont pas capables de gérer des positions dans des fichiers dont le décalage en octets ne peut pas être représenté sur 32 bits.

pm_tell2() et pm_seek2() ont remplacé pm_tell() et pm_seek() dans Netpbm 10.15 (avril 2003).

pm_read_unknown_size() lit un fichier entier ou un flux d'entrée de taille inconnue dans un tampon. Il alloue plus de mémoire si nécessaire. La routine appelante doit libérer le tampon alloué avec free().

pm_read_unknown_size() renvoie un pointeur vers le tampon alloué. L'argument nread renvoie le nombre d'octets lus.

NAME

libpm - Netpbm library utility functions

SYNOPSIS

#include <pam.h>

int pm_readlittlelong( FILE * in, long * lP );

int pm_writelittlelong( FILE * out, long l );

void pm_readcharu( FILE * in, char * sP );

void pm_writecharu( FILE * out, char s );

int pm_readbigshortu( FILE * in, short * sP );

int pm_writebigshortu( FILE * out, short s );

int pm_readbiglongu( FILE * in, long * lP );

int pm_writebiglongu( FILE * out, long l );

int pm_readlittleshortu( FILE * in, short * sP );

int pm_writelittleshortu( FILE * out, short s );

int pm_readlittlelongu( FILE * in, long * lP );

int pm_writelittlelongu( FILE * out, long l );

Description

pm_readchar(), pm_writechar(), pm_readbigshort(), pm_writebigshort(), pm_readbiglong(), pm_writebiglong(), pm_readlittleshort(), pm_writelittleshort(), pm_readlittlelong(), and pm_writelittlelong() are routines to read and write 1-byte, 2-byte, and 4-byte pure binary integers in either big- or little-endian byte order. Note that a 'long int' C type might be wider than 4 bytes, but the 'long' routines still read and write 4 bytes.

pm_readbiglongu(), etc. (names ending in u) are the same except they work on unsigned versions of the type.

The routines with declared return values always return 0. Before Netpbm 10.27 (March 2005), they returned -1 on failure, including EOF. Now, they issue an error message to Standard Error and abort the program if the I/O fails or encounters EOF.

The 1-byte routines were new in Netpbm 10.27 (March 2005). The unsigned versions were new somewhere around Netpbm 10.21 (2004).

Maxval Arithmetic

Entry Points

int pm_maxvaltobits( int maxval );

int pm_bitstomaxval( int bits );

unsigned int pm_lcm( unsigned int x, unsigned int y, unsigned int z, unsigned int limit );

Description

pm_maxvaltobits() and pm_bitstomaxval() convert between a maxval and the minimum number of bits required to hold it.

pm_lcm() computes the least common multiple of 3 integers. You also specify a limit and if the LCM would be higher than that limit, pm_lcm() just returns that limit.

Gamma Arithmetic

Entry Points

float pm_gamma709( float intensity );

float pm_ungamma709( float brightness );

Description

In graphics processing, there are two common ways of representing numerically the intensity of a pixel, or a component of a pixel.

The obvious way is with a number that is directly proportional to the light intensity (e.g. 10 means twice as many milliwatts per square centimeter as 5). There are two problems with this:

  • To the human eye, a 1 milliwatt per square centimeter difference
    in a bright image is much less apparent than a 1 milliwatt per
    square centimeter difference in a dark image. So if you have
    a fixed number of bits in which to store the intensity value,
    you're wasting resolution at the bright end and skimping on it at
    the dark end.
  • Monitor inputs and camera outputs aren't directly proportional to
    the light intensity they project or detect.

For these reasons, light intensities are often represented in graphics processing by an exponential scale. The transfer function is called a gamma function and the resulting numbers are called gamma-corrected or gamma-adjusted. There are various gamma functions. The Netpbm formats specify that intensities are represented by gamma-adjusted numbers of a particular gamma transfer function.

These functions let you convert back and forth between these two scales, using the same gamma transfer function that is specified in the Netpbm format specifications.

pm_gamma709 converts from an intensity-proportional intensity value to a gamma-adjusted intensity value (roughly proportional to brightness, which is the human subjective perception of intensity), using the ITU-R Recommendation BT.709 gamma transfer function.

pm_ungamma709 is the inverse of pm_gamma709.

Messages

Overview

void pm_message( char * fmt, ... );

void pm_setusermessagefn(pm_usermessagefn * function);

Description

pm_message() is a printf() style routine to write an informational message to the Standard Error file stream. pm_message() suppresses the message, however, if the user specified the -quiet common option on the command line. Note that Netpbm programs are often used interactively, but also often used by programs. In the interactive case, it is nice to issue messages about what the program is doing, but in the program case, such messages are usually undesirable. By using pm_message() for all your messages, you make your program usable in both cases. Without any effort on your part, program users of your program can avoid the messages by specifying the -quiet option.

Netpbm distinguishes between error messages and information messages; pm_message() is just for informational messages. To issue an error message, see pm_errormsg() .

pm_setusermessagefn registers a handler for informational messages, called a user message routine. Any library function (including pm_message()) that wants to issue an informational message in the future will call that function with the message as an argument instead of writing the message to Standard Error.

The argument the user message routine gets is English text designed for human reading. It is just the text of the message; there is no attempt at formatting in it (so you won't see any newline or tab characters).

To capture error messages in addition to informational messages, see pm_setusererrormsgfn() .

You can remove the user message routine, so that the library issues future informational messages in its default way (write to Standard Error) by specifying a null pointer for function.

Example:


    static pm_usermessagefn logfilewrite;
    static void
    logfilewrite(const char * const msg) {
        fprintf(mymsglog, 'Netpbm message: %s', msg);
    }
    pm_setusermessagefn(&logfilewrite);
    
    pm_message('Message for the message log');

Keyword Matching

Entry Points

void pm_keymatch();

Description

This subroutine is obsolete. It used to be used for command line option processing. Today, you can do better option processing more easily with the shhopt facility. See any recent program in the Netpbm package for an example.

pm_keymatch() does a case-insensitive match of str against keyword. str can be a leading substring of keyword, but at least minchars must be present.
