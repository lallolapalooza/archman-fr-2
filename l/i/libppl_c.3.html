NOM

libppl_c - l'interface C de la Parma Polyhedra Library

SYNTAXE

#include <ppl_c.h>

cc file.c -lppl

DESCRIPTION

Ceci est un bref aperçu de l'utilisation de la Parma Polyhedra Library (PPL) dans vos programmes C sur les systèmes de type Unix. Notez que la PPL dispose également d'interfaces pour C++, Java, OCaml et un certain nombre de systèmes Prolog : consultez ailleurs la documentation relative à ceux-ci. Notez également que le présent document ne décrit pas les fonctionnalités de la bibliothèque, ses classes ou ses méthodes et fonctions : consultez The Parma Polyhedra Library User's Manual (version 1.2) et The Parma Polyhedra Library C Language Interface User's Manual (version 1.2) pour ce type d'informations.

INCLUSION DU FICHIER D'EN-TÊTE

L'interface C de la PPL ne comporte qu'un seul fichier d'en-tête, nommé ppl_c.h. Votre programme doit donc contenir une directive de la forme

#include <ppl_c.h>

Bien sûr, vous devez vous assurer que vous avez installé la PPL dans un endroit où le compilateur peut la trouver, soit par elle-même, soit avec l'aide d'une option de ligne de commande appropriée -Idir (voir le fichier INSTALL pour des informations sur la façon de configurer la bibliothèque afin qu'elle soit installée à l'endroit de votre choix).

INITIALISATION ET FINALISATION DE LA BIBLIOTHÈQUE

Afin d'initialiser la Parma Polyhedra Library, vous devez appeler la fonction

int ppl_initialize(void)

avant d'utiliser l'une de ses fonctionnalités. Il est également de bonne pratique d'appeler la fonction

int ppl_finalize(void)

lorsque vous avez terminé avec la bibliothèque.

UTILISATION DE LA BIBLIOTHÈQUE

En gardant à l'esprit qu'il n'y a pas de substitut à une lecture attentive de The Parma Polyhedra Library User's Manual (version 1.2) et The Parma Polyhedra Library C Language Interface User's Manual (version 1.2), vous pouvez trouver des exemples d'utilisation dans les répertoires interfaces/C/tests et demos/ppl_lpsol de la distribution source.

LIAISON AVEC LA BIBLIOTHÈQUE

La liaison avec l'interface C de la Parma Polyhedra Library se fait de préférence en utilisant le compilateur C lui-même : généralement, spécifier l'option de ligne de commande -lppl_c est suffisant. En fait, si vous utilisez une version partagée de la bibliothèque, cela enregistre automatiquement la dépendance par rapport au cœur de PPL et aux bibliothèques GMP, ce que l'éditeur de liens devrait gérer correctement. Sinon, vous devrez ajouter -lppl -lgmpxx -lgmp à la ligne de commande. Les choses sont plus complexes si vous avez installé la PPL dans un endroit non standard. Dans ce cas, vous devrez utiliser l'option -Ldir et, si vous utilisez une version partagée de la bibliothèque, éventuellement prendre des mesures supplémentaires : consultez la documentation de votre système pour plus d'informations sur ce sujet (le Program Library HOWTO est particulièrement précieux pour les utilisateurs GNU/Linux).

VALEURS DE RETOUR

Toutes les fonctions de l'interface C de la PPL retournent un int : une valeur négative signifie qu'une erreur s'est produite. Voir The Parma Polyhedra Library C Language Interface User's Manual (version 1.2) pour les codes d'erreur.

IMPLÉMENTATION DE CALCULS PROTÉGÉS PAR LA MÉMOIRE

L'une des caractéristiques intéressantes de la Parma Polyhedra Library est la possibilité d'implémenter des calculs protégés par la mémoire. L'idée est que vous pouvez limiter la quantité de mémoire virtuelle disponible pour le processus, lancer un calcul PPL, et être prêt à recevoir un code d'erreur PPL_ERROR_OUT_OF_MEMORY. Vous pouvez alors prendre les mesures correctives appropriées (par exemple, simplifier les polyèdres et/ou sélectionner des algorithmes moins précis mais moins complexes), et redémarrer le calcul. Pour ce faire, vous devriez définir des fonctions d'allocation de mémoire alternatives pour GMP qui lèvent std::bad_alloc en cas d'épuisement de la mémoire. Voir libppl(3) pour des instructions sur la façon de faire.

UTILISATION DES NOMBRES FLOTTANTS NAtIFS

Au moment de l'initialisation, la Parma Polyhedra Library configure le mode d'arrondi du FPU d'une manière qui permet à ses calculs basés sur les nombres flottants d'être conservateurs (c'est-à-dire éventuellement approximés mais corrects) et raisonnablement efficaces. Dans le cas où votre application utilise elle-même des nombres flottants natifs et repose sur un mode d'arrondi particulier (en cas de doute, supposez qu'elle repose sur l'arrondi au plus près), vous devriez utiliser la fonction

int ppl_restore_pre_PPL_rounding()

après l'initialisation de la PPL et avant d'utiliser des nombres flottants natifs dans l'application. Si votre application n'utilise aucune abstraction PPL basée sur des nombres flottants, aucune mesure supplémentaire ne devrait être prise. Sinon, il est impératif d'appeler la fonction

int ppl_set_rounding_for_PPL()

avant d'invoquer toute interface PPL liée à de telles abstractions.
