DESCRIPTION

IPAddressRange, IPAddressOrRange, IPAddressChoice, et IPAddressFamily sont les éléments constitutifs du type IPAddrBlocks représentant l'extension de délégation d'adresses IP RFC 3779.

Selon la RFC 3779, section 2.1.1, une adresse IPv4 ou IPv6 est codée en ordre d'octets réseau dans une ASN.1 BIT STRING de taille 32 ou 128 bits, respectivement. La taille en bits d'un préfixe est sa longueur de préfixe ; tous les bits zéro insignifiants sont omis de l'encodage. Selon la section 2.1.2, une plage d'adresses est exprimée comme une paire de BIT STRINGs où tous les bits zéro les moins significatifs de la borne inférieure et tous les bits un les moins significatifs de la borne supérieure sont omis.

La bibliothèque ne fournit aucune API pour convertir directement une adresse ou un préfixe IP (sous quelque forme que ce soit) vers et depuis une ASN1_BIT_STRING. Elle ne fournit pas non plus d'API pour gérer directement les plages. Les détails internes de ASN1_BIT_STRING sont subtils et leur manipulation directe dans le contexte de l'API RFC 3779 est déconseillée. La taille en bits d'une ASN1_BIT_STRING représentant un préfixe ou une plage d'adresses IP est égale à huit fois son membre length moins les trois bits les moins significatifs de son indicateur flags, à condition que l'indicateur ASN1_STRING_FLAG_BITS_LEFT soit défini.

Le type IPAddressRange défini dans la RFC 3779 section 2.2.3.9 est implémenté comme suit :

typedef struct IPAddressRange_st {
	ASN1_BIT_STRING *min;
	ASN1_BIT_STRING *max;
} IPAddressRange;

Il représente l'intervalle fermé [min,max] d'adresses IP entre min et max, où min doit être strictement inférieur à max et la plage ne doit pas être exprimable comme un préfixe.

IPAddressRange_new() alloue un nouvel objet IPAddressRange avec des membres min et max alloués et vides, représentant ainsi l'espace d'adressage entier de manière invalide en tant que non-préfixe.

IPAddressRange_free() libère range y compris toutes les données qu'il contient. Si range est NULL, aucune action n'est effectuée.

Il n'y a pas de type dédié représentant le type IPAddress défini dans la RFC 3779 section 2.2.3.8. L'API utilise ASN1_BIT_STRING pour cela.

Le type IPAddressOrRange défini dans la RFC 3779 section 2.2.3.7 est implémenté comme suit :

typedef struct IPAddressOrRange_st {
	int type;
	union {
		ASN1_BIT_STRING *addressPrefix;
		IPAddressRange *addressRange;
	} u;
} IPAddressOrRange;

représentant un préfixe d'adresse individuel ou une plage d'adresses. Le membre type doit être défini sur IPAddressOrRange_addressPrefix ou IPAddressOrRange_addressRange pour indiquer quel membre de l'union u est valide.

IPAddressOrRange_new() renvoie un nouvel objet IPAddressOrRange avec un type et des membres de l'union u non valides et NULL.

IPAddressOrRange_free() libère aor y compris toutes les données qu'il contient, à condition que type soit correctement défini. Si aor est NULL, aucune action n'est effectuée.

Afin d'exprimer une liste de préfixes d'adresses et de plages d'adresses, la RFC 3779 section 2.2.3.6 utilise une ASN.1 SEQUENCE, qui est implémentée via une construction STACK_OF(3) sur IPAddressOrRange :

typedef STACK_OF(IPAddressOrRange) IPAddressOrRanges;

DESCRIPTION

Les objets IPAddressOrRanges ne sont pas directement exposés et ne sont pas facilement accessibles depuis l'extérieur de la bibliothèque, et ils sont non triviaux à implémenter. Il est par conséquent déconseillé d'utiliser des objets IPAddressOrRanges qui ne font pas partie d'un objet IPAddrBlocks.

Le marqueur « inherit » de la section 2.2.3.5 de la RFC 3779 est implémenté comme ASN1_NULL. Il n'a pas de type dédié ni d'API et peut être instancié avec ASN1_NULL_new(3).

Le type IPAddressChoice défini dans la section 2.2.3.4 de la RFC 3779 est implémenté comme

typedef struct IPAddressChoice_st {
	int type;
	union {
		ASN1_NULL *inherit;
		IPAddressOrRanges *addressesOrRanges;
	} u;
} IPAddressChoice;

où le membre type doit être défini à IPAddressChoice_inherit ou IPAddressChoice_addressesOrRanges pour indiquer si un objet IPAddressChoice donné représente une liste héritée ou une liste explicite.

IPAddressChoice_new() renvoie un nouvel objet IPAddressChoice avec un type invalide et des membres de l'union u à NULL.

IPAddressChoice_free() libère ac y compris toutes les données qu'il contient, à condition que type soit correctement défini.

L'élément addressFamily défini dans la section 2.2.3.3 de la RFC 3779 est implémenté comme un ASN1_OCTET_STRING et il contient deux ou trois octets. Les deux premiers octets sont toujours présents et représentent l'identifiant de la famille d'adresses (AFI) en ordre de réseau. L'identifiant optionnel de la famille d'adresses supplémentaire (SAFI) occupe le troisième octet. Pour IPv4 et IPv6, IANA_AFI_IPV4 et IANA_AFI_IPV6 sont prédéfinis. Les autres AFI ne sont pas pris en charge par cette implémentation.

Le type IPAddressFamily défini dans la section 2.2.3.2 de la RFC 3779 est implémenté comme

typedef struct IPAddressFamily_st {
	ASN1_OCTET_STRING *addressFamily;
	IPAddressChoice *ipAddressChoice;
} IPAddressFamily;

Le membre addressFamily indique la famille d'adresses que ipAddressChoice représente.

IPAddressFamily_new() renvoie un nouvel objet IPAddressFamily avec des membres addressFamily et ipAddressChoice vides et alloués.

IPAddressFamily_free() libère af y compris toutes les données qu'il contient. Si af est NULL, aucune action n'est effectuée.

Le type IPAddrBlocks défini dans la section 2.2.3.1 de la RFC 3779 utilise une SEQUENCE ASN.1, qui est implémentée via une construction STACK_OF(3) sur IPAddressFamily :

typedef STACK_OF(IPAddressFamily) IPAddrBlocks;

Il peut être instancié avec sk_IPAddressFamily_new_null() et la fonction de tri correcte peut être installée avec X509v3_addr_canonize(3). Pour le peupler, utilisez X509v3_addr_add_prefix(3) et les fonctions associées.

d2i_IPAddressRange(), i2d_IPAddressRange(), d2i_IPAddressOrRange(), i2d_IPAddressOrRange(), d2i_IPAddressChoice(), i2d_IPAddressChoice(), d2i_IPAddressFamily(), et i2d_IPAddressFamily() décodent et encodent des objets ASN.1 IPAddressRange, IPAddressOrRange, IPAddressChoice, et IPAddressFamily. Pour plus de détails sur la sémantique, les exemples, les mises en garde et les bugs, voir ASN1_item_d2i(3). Il n'y a pas de moyen simple de garantir que les encodages générés par ces fonctions sont corrects, à moins qu'ils ne soient appliqués à des objets qui font partie d'une structure IPAddrBlocks canonique, voir X509v3_addr_is_canonical(3).

VALEURS DE RETOUR

IPAddressRange_new() renvoie un nouvel objet IPAddressRange avec des membres alloués et vides, ou NULL en cas d'erreur.

IPAddressOrRange_new() renvoie un nouvel objet IPAddressOrRange vide, ou NULL en cas d'erreur.

IPAddressChoice_new() renvoie un nouvel objet IPAddressChoice vide, ou NULL en cas d'erreur.

IPAddressFamily_new() renvoie un nouvel objet IPAddressFamily avec des membres alloués et vides, ou NULL en cas d'erreur.

Les fonctions de décodage d2i_IPAddressRange(), d2i_IPAddressOrRange(), d2i_IPAddressChoice(), et d2i_IPAddressFamily() renvoient un objet IPAddressRange, un IPAddressOrRange, un IPAddressChoice, ou un IPAddressFamily respectivement, ou NULL en cas d'erreur.

Les fonctions d'encodage i2d_IPAddressRange(), i2d_IPAddressOrRange(), i2d_IPAddressChoice(), et i2d_IPAddressFamily() renvoient le nombre d'octets encodés avec succès ou une valeur <= 0 en cas d'erreur.

HISTORIQUE

Ces fonctions sont apparues pour la première fois dans OpenSSL 0.9.8e et sont disponibles depuis OpenBSD 7.1.

BUGS

En l'état, l'API est à peine utilisable en raison de l'absence d'accesseurs, constructeurs et destructeurs pratiques et en raison de l'absence totale d'API vérifiant que les éléments constitutifs individuels sont corrects. L'extraction d'informations à partir d'un objet donné peut se faire de manière relativement sûre. Cependant, la construction d'objets est très sujette aux erreurs, que ce soit manuellement ou en utilisant l'API boguée X509v3_addr_add_inherit(3).

La RFC 3779 a un élément « addressesOrRanges ». Son type dans cette API est IPAddressOrRanges.
