SSL_WRITE(3) Manuel des fonctions de bibliothèque SSL_WRITE(3)

NOM

SSL_write_ex, SSL_write — écrire des octets dans une connexion TLS

SYNTAXE

bibliothèque « libssl » libcrypto
#include <openssl/ssl.h>

int
SSL_write_ex(SSL *ssl, const void *buf, size_t num, size_t *written);

int
SSL_write(SSL *ssl, const void *buf, int num);

DESCRIPTION

SSL_write_ex() et SSL_write() écrivent num octets à partir du tampon buf dans la connexion ssl spécifiée. En cas de succès, SSL_write_ex() stocke le nombre d'octets écrits dans *written.

Ci-après, SSL_write_ex() et SSL_write() sont appelées « fonctions d'écriture ».

Si nécessaire, une fonction d'écriture négocie une session TLS, si elle n'a pas déjà été explicitement effectuée par SSL_connect(3) ou SSL_accept(3). Si le pair demande une renégociation, elle sera effectuée de manière transparente pendant l'opération de la fonction d'écriture. Le comportement des fonctions d'écriture dépend du BIO sous-jacent.

Pour que la négociation transparente réussisse, le ssl doit avoir été initialisé en mode client ou serveur. Ceci est fait en appelant SSL_set_connect_state(3) ou SSL_set_accept_state(3) avant le premier appel à une fonction d'écriture.

Si le BIO sous-jacent est bloquant, la fonction d'écriture ne retournera que lorsque l'opération d'écriture sera terminée ou qu'une erreur sera survenue, sauf lorsqu'une renégociation a lieu, auquel cas un SSL_ERROR_WANT_READ peut survenir. Ce comportement peut être contrôlé avec le drapeau SSL_MODE_AUTO_RETRY de l'appel SSL_CTX_set_mode(3).

Si le BIO sous-jacent est non bloquant, la fonction d'écriture retournera également lorsque le BIO sous-jacent n'aura pas pu satisfaire les besoins de la fonction pour continuer l'opération. Dans ce cas, un appel à SSL_get_error(3) avec la valeur de retour de la fonction d'écriture retournera SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE. Comme à tout moment une renégociation est possible, un appel à une fonction d'écriture peut également provoquer des opérations de lecture. Le processus appelant doit alors répéter l'appel après avoir pris les mesures appropriées pour satisfaire les besoins de la fonction d'écriture. L'action dépend du BIO sous-jacent. Lors de l'utilisation d'un socket non bloquant, rien ne doit être fait, mais select(2) peut être utilisé pour vérifier la condition requise. Lors de l'utilisation d'un BIO tamponné, comme une paire de BIO, les données doivent être écrites dans ou récupérées hors du BIO avant de pouvoir continuer.

Les fonctions d'écriture ne retourneront avec succès que lorsque la totalité du contenu de buf d'une longueur de num aura été écrite. Ce comportement par défaut peut être modifié avec l'option SSL_MODE_ENABLE_PARTIAL_WRITE de SSL_CTX_set_mode(3). Lorsque ce drapeau est défini, les fonctions d'écriture retourneront également avec succès lorsqu'une écriture partielle aura été complétée avec succès. Dans ce cas, l'opération de la fonction d'écriture est considérée comme terminée. Les octets sont envoyés et un nouvel appel d'écriture avec un nouveau tampon (avec les octets déjà envoyés retirés) doit être démarré. Une écriture partielle est effectuée avec la taille d'un bloc de message, qui est de 16 Ko.

Lorsqu'un appel de fonction d'écriture doit être répété parce que SSL_get_error(3) a retourné SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE, il doit être répété avec les mêmes arguments.

Lors de l'appel à SSL_write() avec num=0 octets à envoyer, le comportement est indéfini. SSL_write_ex() peut être appelée avec num=0, mais n'enverra pas de données d'application au pair.

VALEURS DE RETOUR

SSL_write_ex() retourne 1 en cas de succès ou 0 en cas d'échec. Le succès signifie que tous les octets de données d'application demandés ont été écrits dans la connexion TLS ou, si SSL_MODE_ENABLE_PARTIAL_WRITE est utilisé, qu'au moins un octet de données d'application a été écrit dans la connexion TLS. L'échec signifie que tous les octets demandés n'ont pas encore été écrits (si SSL_MODE_ENABLE_PARTIAL_WRITE n'est pas utilisé) ou qu'aucun octet n'a pu être écrit dans la connexion TLS (si SSL_MODE_ENABLE_PARTIAL_WRITE est utilisé). Les échecs peuvent être répétables (par exemple, le tampon d'écriture réseau s'est temporairement rempli) ou non répétables (par exemple, une erreur réseau fatale). En cas d'échec, appeler SSL_get_error(3) pour connaître la raison qui indique si l'appel est répétable ou non.

Pour SSL_write(), les valeurs de retour suivantes peuvent se produire :

>0
L'opération d'écriture a réussi. La valeur de retour est le nombre d'octets effectivement écrits dans la connexion TLS.
0
L'opération d'écriture n'a pas réussi. La connexion sous-jacente a probablement été fermée. Appeler SSL_get_error(3) avec la valeur de retour pour savoir si une erreur s'est produite ou si la connexion a été fermée proprement (SSL_ERROR_ZERO_RETURN).
<0
L'opération d'écriture n'a pas réussi, soit parce qu'une erreur s'est produite, soit parce qu'une action doit être entreprise par le processus appelant. Appeler SSL_get_error(3) avec la valeur de retour pour connaître la raison.

HISTORIQUE

SSL_write() est apparue dans SSLeay 0.4 ou antérieur et est disponible depuis OpenBSD 2.4.

SSL_write_ex() est apparue pour la première fois dans OpenSSL 1.1.1 et est disponible depuis OpenBSD 7.1.
