libressl-tls_accept_socket(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

TLS_ACCEPT_SOCKET(3) Manuel des fonctions de bibliothèque TLS_ACCEPT_SOCKET(3)

NOM

tls_accept_socket, tls_accept_fds, tls_accept_cbs — accepter une connexion client entrante dans un serveur TLS

SYNTAXE

bibliothèque « libtls » libssl libcrypto
#include <tls.h>

int
tls_accept_socket(struct tls *tls, struct tls **cctx, int socket);

int
tls_accept_fds(struct tls *tls, struct tls **cctx, int fd_read, int fd_write);

int
tls_accept_cbs(struct tls *tls, struct tls **cctx, ssize_t (*tls_read_cb)(struct tls *ctx, void *buf, size_t buflen, void *cb_arg), ssize_t (*tls_write_cb)(struct tls *ctx, const void *buf, size_t buflen, void *cb_arg), void *cb_arg);

DESCRIPTION

Après avoir créé un contexte serveur TLS tls avec tls_server(3) et l'avoir configuré avec tls_configure(3), un serveur peut accepter une nouvelle connexion client en appelant tls_accept_socket() sur un socket déjà établi.

Alternativement, une nouvelle connexion client peut être acceptée sur une paire de descripteurs de fichiers existants en appelant tls_accept_fds().

L'appel à tls_accept_cbs() permet aux fonctions de rappel de lecture et d'écriture de gérer les transferts de données. Le paramètre cb_arg spécifié est renvoyé aux fonctions et peut contenir un pointeur vers des données spécifiées par l'appelant.

Toutes ces fonctions créent un nouveau contexte adapté à la lecture et à l'écriture et le retournent dans *cctx.

VALEURS DE RETOUR

Ces fonctions retournent 0 en cas de succès ou -1 en cas d'erreur.

VOIR AUSSI

tls_close(3), tls_config_set_session_id(3), tls_configure(3), tls_connect(3), tls_init(3), tls_server(3)

HISTORIQUE

tls_accept_socket() est apparu dans OpenBSD 5.6 et a reçu son nom définitif dans OpenBSD 5.7.

tls_accept_fds() est apparu dans OpenBSD 5.8 et tls_accept_cbs() dans OpenBSD 6.1.
