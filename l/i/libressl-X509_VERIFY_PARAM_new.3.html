DESCRIPTION

X509_VERIFY_PARAM_new() alloue et initialise un objet X509_VERIFY_PARAM vide.

X509_VERIFY_PARAM_inherit() copie certaines données de l'objet source vers l'objet destination.

Les drapeaux de vérification définis avec X509_VERIFY_PARAM_set_flags(3) dans l'objet source sont toujours combinés par un OU (OR) avec les drapeaux de vérification de l'objet destination.

Les champs ayant leur valeur par défaut dans l'objet source ne sont pas copiés.

Par défaut, les champs de l'objet destination ayant déjà une valeur non-défaut ne sont pas écrasés. Cependant, si au moins un des objets source ou destination a été créé lors d'un appel à X509_STORE_CTX_init(3) qui n'avait pas d'argument store, et si cet objet n'a pas été précédemment utilisé comme destination lors d'un appel antérieur à X509_VERIFY_PARAM_inherit(), cette restriction est levée et même les champs non-défaut de l'objet destination sont écrasés. Si les champs écrasés de cette manière contiennent des pointeurs vers de la mémoire allouée, cette mémoire est libérée.

Dans la mesure permise par les règles ci-dessus, les champs suivants sont copiés :

  • l'identifiant de but de vérification défini avec X509_VERIFY_PARAM_set_purpose(3)
  • le réglage de confiance défini avec X509_VERIFY_PARAM_set_trust(3)
  • l'heure de vérification définie avec X509_VERIFY_PARAM_set_time(3) ; dans ce cas, la seule condition est que X509_V_FLAG_USE_CHECK_TIME ne soit pas défini dans l'objet destination, tandis que la valeur temporelle dans l'objet destination n'est pas inspectée avant d'être écrasée
  • la politique acceptable définie avec X509_VERIFY_PARAM_set1_policies(3)
  • la profondeur de vérification maximale définie avec X509_VERIFY_PARAM_set_depth(3)
  • les drapeaux qui ont été définis avec X509_VERIFY_PARAM_set_hostflags(3)
  • la liste des noms d'hôtes DNS attendus construite avec X509_VERIFY_PARAM_set1_host(3) et X509_VERIFY_PARAM_add1_host(3)
  • l'adresse e-mail RFC 822 attendue définie avec X509_VERIFY_PARAM_set1_email(3)
  • l'adresse IP attendue définie avec X509_VERIFY_PARAM_set1_ip(3) ou X509_VERIFY_PARAM_set1_ip_asc(3)

Certaines données pouvant être contenues dans l'objet source ne sont jamais copiées, par exemple le nom du sujet du certificat pair qui peut être récupéré avec X509_VERIFY_PARAM_get0_peername(3).

Si source est un pointeur NULL, la fonction n'a aucun effet mais retourne successfullement.

X509_VERIFY_PARAM_set1() est identique à X509_VERIFY_PARAM_inherit() sauf que les champs de l'objet destination sont écrasés même s'ils ne correspondent pas à leurs valeurs par défaut. Néanmoins, les champs ayant leur valeur par défaut dans l'objet source ne sont pas copiés.

Si X509_VERIFY_PARAM_inherit() ou X509_VERIFY_PARAM_set1() échouent, une copie partielle peut avoir eu lieu, donc toutes les données de l'objet destination doivent être considérées comme invalides.

X509_VERIFY_PARAM_inherit() est utilisé en interne par X509_STORE_CTX_init(3) et par X509_STORE_CTX_set_default(3), et X509_VERIFY_PARAM_set1() est utilisé en interne par X509_STORE_set1_param(3).

X509_VERIFY_PARAM_free() efface toutes les données contenues dans param et libère toute la mémoire utilisée par celui-ci. Si param est un pointeur NULL, aucune action n'est effectuée.

X509_VERIFY_PARAM_add0_table() ajoute param à une liste statique d'objets X509_VERIFY_PARAM maintenue par la bibliothèque. Cette fonction est extrêmement dangereuse car contrairement au nom de la fonction, si la liste contient déjà un objet qui porte le même nom, cet ancien objet est non seulement retiré silencieusement de la liste, mais également libéré silencieusement, ce qui peut invalider silencieusement divers pointeurs existant ailleurs dans le programme.

X509_VERIFY_PARAM_lookup() recherche dans cette liste un objet du nom donné. Si aucune correspondance n'est trouvée, les objets prédéfinis intégrés à la bibliothèque sont également inspectés.

X509_VERIFY_PARAM_get_count() renvoie la somme du nombre d'objets dans cette liste et du nombre d'objets prédéfinis intégrés à la bibliothèque.

DESCRIPTION

The X509_VERIFY_PARAM structure holds various parameters that control certificate verification. These include the context for looking up trusted CAs, the verification depth, the expected CA name, the acceptable time, and flags controlling specific verification steps.

The library maintains a table of predefined and user-defined X509_VERIFY_PARAM objects. The predefined objects are used for default verification behavior. User-defined objects can be added to the table to customize verification behavior for specific applications.

The following functions are available:

X509_VERIFY_PARAM_new()
Allocates and initializes a new X509_VERIFY_PARAM object with default values. The caller is responsible for freeing the returned object using X509_VERIFY_PARAM_free().
X509_VERIFY_PARAM_inherit()
Copies the parameters from the source object to the param object. This is useful for creating a new verification context based on an existing one.
X509_VERIFY_PARAM_set1()
Copies the parameters from the source object to the param object. It differs from X509_VERIFY_PARAM_inherit() in that it makes copies of any data owned by the parameters, such as CA names or CRL distribution points.
X509_VERIFY_PARAM_free()
Frees the memory allocated for the X509_VERIFY_PARAM object param. If param is NULL, the function does nothing.
X509_VERIFY_PARAM_lookup()
Looks up an X509_VERIFY_PARAM object in the table by its name. Returns a pointer to the object if found, or NULL otherwise. The returned object should not be freed by the caller.
X509_VERIFY_PARAM_add0_table()
Adds the param object to the table of user-defined objects. The object is added without making a copy, so the caller must not free it after this call. The object will be freed by X509_VERIFY_PARAM_table_cleanup().
X509_VERIFY_PARAM_get_count()
Returns the total number of predefined and user-defined objects in the table.
X509_VERIFY_PARAM_get0()
Accesses predefined and user-defined objects using id as an index, useful for looping over objects without knowing their names. An argument less than the number of predefined objects selects one of the predefined objects; a higher argument selects an object from the list.
X509_VERIFY_PARAM_table_cleanup()
Deletes all objects from this list. It is extremely dangerous because it also invalidates all data that was contained in all objects that were on the list and because it frees all these objects, which may invalidate various pointers existing elsewhere in the program.

Note that this is not necessarily the total number of X509_VERIFY_PARAM objects existing in the program because there may be additional such objects that were never added to the list.

RETURN VALUES

X509_VERIFY_PARAM_new() returns a pointer to the new object, or NULL on allocation failure.

X509_VERIFY_PARAM_inherit(), X509_VERIFY_PARAM_set1(), and X509_VERIFY_PARAM_add0_table() return 1 for success or 0 for failure.

X509_VERIFY_PARAM_lookup() and X509_VERIFY_PARAM_get0() return a pointer to an existing built-in or user-defined object, or NULL if no object with the given name is found, or if id is at least X509_VERIFY_PARAM_get_count().

X509_VERIFY_PARAM_get_count() returns a number of objects.
