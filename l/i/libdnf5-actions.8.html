NOM

libdnf5-actions - Module d'actions

DESCRIPTION

Ce module permet de définir des actions à exécuter via les hooks de rappel de libdnf5. Chaque action est accrochée à un rappel spécifique. Les actions pour les rappels goal_resolved, pre_transaction et post_transaction peuvent définir une règle de filtrage (similaire à glob) sur le NEVRA du paquet ou sur les fichiers du paquet, ainsi que si le paquet est entrant ou sortant.

CONFIGURATION

Le module n'étend pas la configuration standard. Cependant, il lit les fichiers "actions".

Les fichiers d'actions sont lus depuis le répertoire <libdnf5_plugins_config_dir>/actions.d/. Seuls les fichiers avec l'extension ".actions" sont lus.

FORMAT DES FICHIERS D'ACTIONS

Les lignes vides et les lignes commençant par un caractère '#' (ligne de commentaire) sont ignorées.

Chaque ligne non commentée définit une action et se compose de cinq éléments séparés par des deux-points : nom_rappel:filtre_paquet:direction:options:commande.

nom_rappel

  • pre_base_setup
  • post_base_setup
  • repos_configured (ajouté dans la version 1.0.0)
  • repos_loaded (ajouté dans la version 1.0.0)
  • pre_add_cmdline_packages (ajouté dans la version 1.0.0)
  • post_add_cmdline_packages (ajouté dans la version 1.0.0)
  • goal_resolved (ajouté dans la version 1.3.0)
  • pre_transaction
  • post_transaction
filtre_paquet
Une règle de filtrage (similaire à glob) appliquée au NEVRA du paquet (également sous formes abrégées) ou aux fichiers du paquet.

Un filtre vide signifie exécuter la commande une fois sans information sur le paquet. Le filtre "*" signifie exécuter la commande pour chaque paquet de la transaction qui correspond au filtre de direction. Le filtre ne peut être non vide que pour les rappels goal_resolved, pre_transaction et post_transaction.

direction
Filtre les paquets par leur direction (entrant dans le système / sortant du système) dans une transaction. Si vide, le filtre n'est pas appliqué. Le filtre ne peut être non vide que lorsqu'il est combiné à un filtre_paquet non vide.
  • in - paquets entrant dans le système (descente, installation, réinstallation, mise à niveau)
  • out - paquets sortant du système (mise à niveau, descente, réinstallation, suppression, remplacement/obsolescence)
options
Les options sont séparées par des espaces. Un espace dans une option peut être écrit en utilisant l'échappement.
•
enabled=<valeur> - la valeur spécifie quand l'action est activée (ajouté dans la version 0.3.0)
  • 1 - l'action est toujours activée
  • host-only - l'action est activée uniquement pour les opérations sur l'hôte
  • installroot-only - l'action est activée uniquement pour les opérations dans l'"installroot" alternatif
•
raise_error=<valeur> - la <valeur> spécifie comment les erreurs du processus d'action sont gérées. Que se passe-t-il si le processus d'action n'a pas démarré ou s'est terminé avec un code de sortie non nul ou s'est terminé anormalement (a reçu un signal) ou si une erreur s'est produite pendant la communication (erreur de syntaxe, interruption de communication, échec de traitement de la ligne de sortie en mode de communication texte). Si l'option n'est pas présente, raise_error=0 par souci de compatibilité ascendante. (ajouté dans la version 1.4.0)
  • 0 - les erreurs sont enregistrées
  • 1 - une exception est levée
commande
Tout fichier exécutable avec des arguments.

Les arguments sont séparés par des espaces. Un espace dans un argument peut être écrit en utilisant l'échappement. L'échappement peut également être utilisé pour empêcher la substitution et passer les caractères spéciaux \a, \b, \f, \n, \r, \t, \v. Le déséchappement des arguments est effectué après la substitution.

Les variables suivantes dans la commande seront substituées :

  • ${pid} - ID du processus
  • ${plugin.version} - version du module d'actions (ajouté dans la version 0.3.0)
  • ${conf.<nom_option>} - option de la configuration de base
  • ${conf.<motif_idrepo>.<nom_option>[=<motif_valeur>]} - liste des paires "idrepo.option=valeur" (ajouté dans la version 1.1.0)
  • ${var.<nom_variable>} - variable
  • ${tmp.<nom_variable_module_actions>} - variable existe uniquement dans le contexte du module d'actions
  • ${pkg.<nom_attribut_paquet>} - valeur de l'attribut du paquet
  • ${pkg.name} - nom du paquet
  • ${pkg.arch} - architecture du paquet
  • ${pkg.version} - version du paquet
  • ${pkg.release} - release du paquet
  • ${pkg.epoch} - epoch du paquet
  • ${pkg.na} - nom.architecture du paquet
  • ${pkg.evr} - epoch-version-release du paquet
  • ${pkg.nevra} - nevra du paquet (l'epoch 0 est caché)
  • ${pkg.full_nevra} - nevra complet du paquet (l'epoch est toujours présent) ${name}-${epoch}:${ver}-${rel}.${arch}
  • ${pkg.repo_id} - ID du dépôt du paquet
  • ${pkg.license} - licence du paquet
  • ${pkg.location} - le changement d'état du paquet dans la transaction:
  • ${pkg.vendor} - fournisseur du paquet
  • ${pkg.action} - action effectuée sur le paquet :
  • I - paquet nouvellement installé
  • U - paquet installé comme mise à niveau
  • D - paquet installé comme descente
  • R - paquet utilisé pour la réinstallation
  • E - paquet effacé (supprimé) du système (a été mis à niveau/descendu/réinstallé/supprimé)
  • O - paquet remplacé (obsolète)

La commande sera évaluée pour chaque paquet qui correspond au filtre_paquet et à la direction. Cependant, après la substitution des variables, toutes les commandes dupliquées seront supprimées et chaque commande ne sera exécutée qu'une seule fois par transaction. Les commandes sont exécutées séquentiellement. Il n'y a pas de parallélisme. La substitution d'arguments est effectuée après que la commande précédente soit terminée. Cela permet à la substitution d'utiliser les résultats des commandes précédentes. L'ordre d'exécution des commandes suit l'ordre dans les fichiers d'actions, mais peut différer de l'ordre des paquets dans la transaction. En d'autres termes, lorsque vous définissez plusieurs lignes d'action pour le même filtre_paquet et la même direction, ces lignes seront exécutées dans l'ordre où elles ont été définies dans le fichier d'actions lorsque le filtre_paquet et la direction correspondent à un paquet. Cependant, l'ordre dans lequel un filtre_paquet particulier est appelé dépend de la position du paquet correspondant dans la transaction.

Les paires idrepo.option=valeur dans la liste sont séparées par le caractère ','. Le caractère ',' dans la valeur est remplacé par la séquence d'échappement "\x2C". Si motif_valeur est utilisé, seules les paires avec la valeur correspondante sont listées. Le motif_idrepo et le motif_valeur peuvent contenir des jokers.

FORMAT DE LA SORTIE STANDARD DES ACTIONS

La sortie standard de chaque action exécutée (commande) est capturée et traitée. Chaque ligne de sortie peut modifier la valeur d'une option de configuration de base, la valeur d'une option de configuration dans les dépôts correspondants, ou une variable. Elle peut également définir ou annuler une variable du module d'actions. La valeur de cette variable est disponible pour les commandes suivantes en utilisant la substitution ${tmp.<nom_variable_module_actions>}.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

.

Les actions doivent modifier la configuration des dépôts dans le hook repos_configured. À ce stade, la configuration des dépôts est chargée mais pas encore appliquée.

Depuis la version 1.4.0, la ligne de sortie peut écrire un message au logger, lancer une exception de type stop et une exception d'erreur.

Format de la ligne de sortie

  • tmp.<nom_variable_plugin_actions>=<valeur> - définit la valeur de la variable du plugin d'actions <nom_variable_plugin_actions>
  • tmp.<nom_variable_plugin_actions> - supprime la variable du plugin d'actions si elle existe
  • conf.<nom_option>=<valeur> - définit la valeur de l'option <nom_option> dans la configuration de base
  • conf.<modèle_id_dépôt>.<nom_option>=<valeur> - définit la valeur de l'option <nom_option> dans les dépôts correspondants (ajouté dans la version 1.1.0)
  • var.<nom_variable>=<valeur> - définit la valeur de la variable <nom_variable>
  • stop=<message> - lance une exception de type stop avec <message> (ajouté dans la version 1.4.0)
  • error=<message> - le message d'erreur <message> est enregistré ou lance une exception d'erreur avec <message> si raise_error=1 (ajouté dans la version 1.4.0)
  • log.<niveau>=<message> - écrit <message> dans le logger avec la priorité <niveau> (ajouté dans la version 1.4.0)
Niveaux : CRITICAL, ERROR, WARNING, NOTICE, INFO, DEBUG, TRACE

EXEMPLE DE FICHIER ACTIONS :

# Imprime l'en-tête avec l'ID du processus
pre_base_setup::::/usr/bin/sh -c echo\ -------------------------------------\ >>/tmp/actions-trans.log
pre_base_setup::::/usr/bin/sh -c date\ >>/tmp/actions-trans.log
pre_base_setup::::/usr/bin/sh -c echo\ libdnf5\ pre_base_setup\ a\ été\ appelé.\ Process\ ID\ =\ '${pid}'.\ >>/tmp/actions-trans.log
pre_base_setup:::enabled=installroot-only:/usr/bin/sh -c echo\ run\ in\ alternative\ "installroot":\ installroot\ =\ '${conf.installroot}'\ >>/tmp/actions-trans.log
# Imprime la valeur de l'option de configuration "defaultyes".
pre_base_setup::::/bin/sh -c echo\ 'pre_base_setup:\ conf.defaultyes=${{conf.defaultyes}}'\ >>\ {context.dnf.installroot}/actions.log
# Imprime un message indiquant que le rappel "post_base_setup" a été appelé.
post_base_setup::::/usr/bin/sh -c echo\ libdnf5\ post_base_setup\ a\ été\ appelé.\ >>/tmp/actions-trans.log
# Imprime une liste des dépôts configurés avec leur état d'activation.
repos_configured::::/usr/bin/sh -c echo\ Dépôts:\ ${conf.*.enabled}\ >>/tmp/repos.log
# Imprime une liste des dépôts qui utilisent le protocole http dans baseurl.
repos_configured::::/usr/bin/sh -c echo\ "${conf.*.baseurl=*http://*}"\ >>/tmp/baseurl_http.log
# Désactive tous les dépôts dont l'ID commence par "rpmfusion".
repos_configured::::/usr/bin/sh -c echo\ conf.rpmfusion*.enabled=0
# Imprime les informations sur le début de la transaction.
# Comme package_filter est vide, il exécute les commandes une seule fois.
pre_transaction::::/usr/bin/sh -c echo\ Transaction\ début.\ Paquets\ dans\ la\ transaction:\ >>/tmp/actions-trans.log
# Enregistre tous les paquets (action du paquet, full_nevra, id du dépôt) dans la transaction dans un fichier.
# Utilise la commande shell "echo" et la redirection vers un fichier.
pre_transaction:*:::/usr/bin/sh -c echo\ '${pkg.action}'\ '${pkg.full_nevra}'\ '${pkg.repo_id}'\ >>/tmp/actions-trans.log
# Imprime la date et l'heure ainsi que les informations sur la fin de la transaction.
# Comme package_filter est vide, il exécute les commandes une seule fois.
post_transaction::::/usr/bin/sh -c date\ >>/tmp/actions-trans.log
post_transaction::::/usr/bin/sh -c echo\ Transaction\ fin.\ Dépôts\ utilisés\ dans\ la\ transaction:\ >>/tmp/actions-trans.log
# Enregistre tous les dépôts à partir desquels des paquets ont été utilisés dans la transaction pour l'installation sur le système.
# Chaque dépôt ne sera listé qu'une seule fois, même si plusieurs paquets du même dépôt ont été utilisés.
# La même commande (après substitution de variables) n'est exécutée qu'une seule fois par transaction.
post_transaction:*:in::/usr/bin/sh -c echo\ '${pkg.repo_id}'\ >>/tmp/actions-trans.log
# ==============================================================================================
# Les deux actions suivantes émulent le plugin snapper de DNF4. Il utilise le programme en ligne de commande "snapper".
# Crée un instantané pré-transaction et stocke le numéro de l'instantané dans la variable "tmp.snapper_pre_number".
pre_transaction::::/usr/bin/sh -c echo\ "tmp.snapper_pre_number=$(snapper\ create\ -t\ pre\ -p)"
# Si la variable "tmp.snapper_pre_number" existe, il crée un instantané post-transaction et supprime la variable "tmp.snapper_pre_number".
post_transaction::::/usr/bin/sh -c [\ -n\ "${tmp.snapper_pre_number}"\ ]\ &&\ snapper\ create\ -t\ post\ --pre-number\ "${tmp.snapper_pre_number}"\ ;\ echo\ tmp.snapper_pre_number
