CMAC_INIT(3) Manuel des fonctions de bibliothèque CMAC_INIT(3)

NOM

CMAC_CTX_new, CMAC_Init, CMAC_Update, CMAC_Final, CMAC_CTX_copy, CMAC_CTX_get0_cipher_ctx, CMAC_CTX_cleanup, CMAC_CTX_free — Code d'authentification de message basé sur un chiffrement

SYNTAXE

bibliothèque « libcrypto »
#include <openssl/cmac.h>

CMAC_CTX *
CMAC_CTX_new(void);

int
CMAC_Init(CMAC_CTX *ctx, const void *key, size_t key_len, const EVP_CIPHER *cipher, ENGINE *engine);

int
CMAC_Update(CMAC_CTX *ctx, const void *in_data, size_t in_len);

int
CMAC_Final(CMAC_CTX *ctx, unsigned char *out_mac, size_t *out_len);

int
CMAC_CTX_copy(CMAC_CTX *out_ctx, CMAC_CTX *in_ctx);

EVP_CIPHER_CTX *
CMAC_CTX_get0_cipher_ctx(CMAC_CTX *ctx);

void
CMAC_CTX_cleanup(CMAC_CTX *ctx);

void
CMAC_CTX_free(CMAC_CTX *ctx);

DESCRIPTION

CMAC est un algorithme de code d'authentification de message qui peut utiliser un bloc de chiffrement arbitraire avec une clé symétrique.

La présente page de manuel décrit les fonctions de bas niveau qui implémentent CMAC. Au lieu d'utiliser directement ces fonctions, les programmes d'application appellent normalement EVP_PKEY_new_CMAC_key(3) puis passent l'objet EVP_PKEY résultant à EVP_DigestSignInit(3).

L'API CMAC est orientée objet. Le calcul d'un code d'authentification de message nécessite un objet CMAC_CTX. Généralement, les fonctions CMAC_CTX_new(), CMAC_Init(), CMAC_Update(), CMAC_Final(), et CMAC_CTX_free() doivent être appelées dans cet ordre.

CMAC_CTX_new() alloue un nouvel objet CMAC_CTX, initialise l'objet EVP_CIPHER_CTX intégré, et marque l'objet lui-même comme non initialisé.

CMAC_Init() sélectionne le cipher de bloc donné pour être utilisé par ctx. Les fonctions permettant d'obtenir des objets EVP_CIPHER appropriés sont listées dans la section CIPHER LISTING de la page de manuel EVP_EncryptInit(3). Sauf si key est NULL, CMAC_Init() initialise également ctx pour l'utilisation avec la clé symétrique key donnée, qui a une longueur de key_len octets. En particulier, elle calcule et stocke en interne les deux sous-clés et initialise ctx pour alimenter ensuite des données avec CMAC_Update(). L'argument engine est ignoré ; il est recommandé de passer NULL.

Si ctx est déjà initialisé, CMAC_Init() peut être appelé à nouveau avec key et cipher tous deux définis à NULL et key_len défini à 0. Dans ce cas, toute donnée déjà traitée est ignorée et ctx est réinitialisé pour commencer à lire les données à nouveau.

CMAC_Update() traite in_len octets de données d'entrée pointés par in_data. Selon le nombre d'octets d'entrée déjà mis en cache dans ctx, sur in_len, et sur la taille du bloc, cela peut chiffrer zéro ou plusieurs blocs. Sauf si in_len est zéro, cette fonction laisse au moins un octet et au plus un bloc d'entrée en cache mais non traité à l'intérieur de l'objet ctx. CMAC_Update() peut être appelé plusieurs fois pour concaténer plusieurs morceaux de données d'entrée de tailles variables.

CMAC_Final() stocke la longueur du code d'authentification de message en octets, qui est égale à la taille du bloc de chiffrement, dans *out_len. Sauf si out_mac est NULL, elle chiffre le dernier bloc, le complétant si nécessaire, et copie le code d'authentification de message résultant dans out_mac. L'appelant est responsable de fournir un tampon de taille suffisante.

CMAC_CTX_copy() effectue une copie profonde de in_ctx, déjà initialisé, dans out_ctx.

CMAC_CTX_cleanup() met à zéro les deux sous-clés et toutes les données temporaires dans ctx et dans l'objet EVP_CIPHER_CTX intégré, libère toute la mémoire allouée qui lui est associée, à l'exception de ctx lui-même, et le marque comme non initialisé, de sorte qu'il puisse être réutilisé pour un CMAC_Init() ultérieur.

CMAC_CTX_free() appelle CMAC_CTX_cleanup(), puis libère ctx lui-même. Si ctx est NULL, aucune action n'est effectuée.

VALEURS DE RETOUR

CMAC_CTX_new() renvoie le nouvel objet contexte ou NULL en cas d'échec. Il réussit sauf si la mémoire est épuisée.

CMAC_Init(), CMAC_Update(), CMAC_Final(), et CMAC_CTX_copy() renvoient 1 en cas de succès ou 0 en cas d'échec. CMAC_Init() échoue si l'initialisation de l'objet EVP_CIPHER_CTX intégré échoue. Les autres échouent si in_ctx n'est pas initialisé. CMAC_Update() et CMAC_Final() échouent également si le chiffrement d'un bloc échoue, et CMAC_CTX_copy() si la copie de l'objet EVP_CIPHER_CTX intégré échoue, ce qui peut par exemple se produire lorsque la mémoire est épuisée.

CMAC_CTX_get0_cipher_ctx() renvoie un pointeur interne vers l'objet EVP_CIPHER_CTX intégré dans ctx.

ERREURS

Le code CMAC lui-même n'utilise pas le framework <openssl/err.h>, donc en général, les raisons de l'échec ne peuvent pas être découvertes avec ERR_get_error(3). Cependant, étant donné que les fonctions EVP_EncryptInit(3) sont utilisées en interne, des entrées peuvent toujours être ajoutées à la pile d'erreurs dans certains cas d'échec.

VOIR AUSSI

EVP_aes_128_cbc(3), EVP_DigestSignInit(3), CMAC_Init(3)

NOM

CMAC_Init, CMAC_Update, CMAC_Final, CMAC_CTX_new, CMAC_CTX_free – calcul de code d'authentification de message basé sur un chiffrement par blocs en mode CMAC

SYNOPSIS

#include <openssl/cmac.h> 





Fonctions de traitement CMAC


int
CMAC_Init(CMAC_CTX *ctx, const unsigned char *key, size_t key_len,
    const EVP_CIPHER *cipher, ENGINE *engine);
int
CMAC_Update(CMAC_CTX *ctx, const unsigned char *data, size_t data_len);
int
CMAC_Final(CMAC_CTX *ctx, unsigned char *out, size_t *out_len);




Fonctions de gestion du contexte


CMAC_CTX *
CMAC_CTX_new(void);
void
CMAC_CTX_free(CMAC_CTX *ctx);










DESCRIPTION


Le mode CMAC (Cipher-based Message Authentication Code) est une
    méthode d'authentification de message pour les chiffrements par blocs,
    spécifiée dans la publication SP 800-38B du NIST. Il est similaire
    à la méthode HMAC, mais utilise un chiffrement par blocs au lieu
    d'une fonction de hachage cryptographique.


La fonction CMAC_Init() initialise une
    structure CMAC_CTX pour un calcul CMAC. Le paramètre
    ctx est un pointeur vers le contexte à initialiser.
    Si ctx est NULL, un nouveau contexte est alloué et
    initialisé.


Le paramètre key et key_len
    spécifient la clé à utiliser pour le calcul CMAC. Si key
    est NULL, une clé sera générée à partir du chiffrement
    fourni.


Le paramètre cipher est un pointeur vers
    la structure EVP_CIPHER qui définit le chiffrement
    par blocs et la taille de clé à utiliser. Le paramètre engine
    permet de spécifier un moteur cryptographique particulier.


La fonction CMAC_Update() met à jour
    le calcul CMAC avec les données spécifiées par data
    et data_len. Cette fonction peut être appelée
    plusieurs fois pour traiter des données consécutives.


La fonction CMAC_Final() termine le calcul
    CMAC et stocke le code d'authentification de message résultant dans le
    tampon out. La taille du code d'authentification est
    stockée dans out_len. Le contexte ctx
    n'est plus utilisable après cet appel.


La fonction CMAC_CTX_new() alloue et
    initialise un nouveau contexte CMAC_CTX. La fonction
    CMAC_CTX_free() libère la mémoire associée
    au contexte ctx.






VALEUR DE RETOUR


CMAC_Init, CMAC_Update
    et CMAC_Final retournent 1 en cas de succès, et
    0 en cas d'échec.


CMAC_CTX_new retourne un pointeur vers un
    nouveau contexte CMAC_CTX, ou NULL en cas d'erreur.






ERREURS


Voir ERR_get_error(3)
    pour plus d'informations sur les erreurs.
