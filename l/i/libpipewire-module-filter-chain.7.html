NOM

libpipewire-module-filter-chain - Chaîne de filtres

DESCRIPTION

La chaîne de filtres permet de créer un graphe de traitement arbitraire à partir de filtres LADSPA, LV2 et intégrés.

Ce filtre peut être transformé en une source/puits virtuelle ou placé entre deux nœuds quelconques du graphe.

La chaîne de filtres est construite avec 2 flux : un flux de capture fournissant l'entrée à la chaîne de filtres et un flux de lecture envoyant le flux filtré vers les nœuds suivants du graphe.

Étant donné que les deux extrémités de la chaîne de filtres sont construites avec des flux, le gestionnaire de session peut gérer automatiquement la configuration et la connexion avec les puits et les sources.

NOM DU MODULE

libpipewire-module-filter-chain

OPTIONS DU MODULE

  • node.description: un nom lisible par l'homme pour la chaîne de filtres
  • filter.graph = []: une description du graphe de filtres à exécuter, voir ci-dessous
  • capture.props = {}: propriétés à passer au flux d'entrée
  • playback.props = {}: propriétés à passer au flux de sortie

DESCRIPTION DU GRAPHE DE FILTRES

La structure générale de la description du graphe est la suivante :

 filter.graph = {
     nodes = [
         {
             type = <ladspa | lv2 | builtin | sofa>
             name = <nom>
             plugin = <plugin>
             label = <étiquette>
             config = {
                 <cle_config> = <valeur> ...
             }
             control = {
                 <nom_contrôle|index_contrôle> = <valeur> ...
             }
         }
         ...
     ]
     links = [
         { output = <nom_port> input = <nom_port> }
         ...
     ]
     inputs = [ <nom_port> ... ]
     outputs = [ <nom_port> ... ]
     capture.volumes = [
         { control = <nom_port>  min = <valeur>  max = <valeur>  scale = <échelle> } ...
     ]
     playback.volumes = [
         { control = <nom_port>  min = <valeur>  max = <valeur>  scale = <échelle> } ...
     ]
}

Nœuds

Les nœuds décrivent les filtres de traitement dans le graphe. Utilisez un outil comme lv2ls ou listplugins pour obtenir une liste des plugins disponibles, des étiquettes et des noms de ports.

  • type est l'un des suivants : ladspa, lv2, builtin, sofa ou ebur128.
  • name est le nom de ce nœud, vous pourriez en avoir besoin plus tard pour faire référence à ce nœud et à ses ports lors de la définition des contrôles ou de la création de liens.
  • plugin est le nom spécifique du plugin selon le type.
•
Pour les plugins LADSPA, il ajoutera .so pour trouver l'objet partagé portant ce nom dans le chemin des plugins LADSPA.
•
Pour LV2, il s'agit de l'URI du plugin obtenu avec lv2ls.
•
Pour builtin, sofa et ebur128, ceci est ignoré.
•
label est le filtre spécifique au type à l'intérieur du plugin.
•
Pour LADSPA, c'est l'étiquette.
•
Pour LV2, ceci est inutilisé.
•
Pour builtin, sofa et ebur128, c'est le nom du filtre à utiliser.
  • config contient une section de configuration spécifique au filtre. Certains plugins en ont besoin (convolver, sofa, delay, ...).
  • control contient les valeurs initiales pour les ports de contrôle du filtre. Normalement, ceux-ci sont donnés avec le nom du port, mais il est également possible de donner l'indice du contrôle comme clé.

Liens

Des liens peuvent être créés entre les ports des nœuds. Le nom du port est donné sous la forme <nom_nœud>:<nom_port>.

Vous pouvez "télégraphier" la sortie des filtres vers plusieurs autres filtres. Vous avez besoin d'utiliser un mixeur si vous souhaitez que la sortie de plusieurs filtres aille vers un port d'entrée de filtre.

Les liens peuvent être omis lorsque le graphe ne contient qu'un seul filtre.

Entrées et sorties

Ce sont les ports d'entrée et de sortie de la définition du graphe. Leur nombre définit le nombre de canaux utilisés par la chaîne de filtres.

Chaque entrée/sortie du graphe ne peut être liée qu'à une seule entrée/sortie de filtre. Vous devez utiliser le filtre intégré copy si le signal d'entrée doit être acheminé vers plusieurs filtres. Vous devez utiliser le plugin intégré mixer si plusieurs sorties du graphe doivent aller vers un seul flux de sortie.

Les entrées et sorties peuvent être omises, auquel cas la chaîne de filtres utilisera toutes les entrées du premier filtre et toutes les sorties du dernier nœud de filtre. Le graphe sera alors dupliqué autant de fois que nécessaire pour correspondre au nombre de canaux d'entrée/sortie des flux.

Volumes

Normalement, le volume du puits/source est géré par le volume logiciel du flux. Avec les propriétés capture.volumes et playback.volumes, cela peut être géré par un port de contrôle dans le graphe à la place. Utilisez capture.volumes pour le volume de l'entrée du filtre (lorsqu'il est utilisé par exemple comme puits). Utilisez playback.volumes pour le volume de la sortie du filtre (lorsqu'il est utilisé par exemple comme source).

Les valeurs min et max (par défaut 0.0 et 1.0 respectivement) peuvent être utilisées pour mettre à l'échelle et traduire les valeurs min et max du volume.

Normalement, les valeurs de contrôle sont linéaires et on suppose que le plugin n'effectue aucune mise à l'échelle des valeurs. Ceci peut être modifié avec la propriété scale. Par défaut, elle est linéaire mais peut être définie sur cubique lorsque le contrôle applique une transformation cubique.

FILTRES INTÉGRÉS

Il existe quelques filtres intégrés utiles disponibles. Vous les sélectionnez avec l'étiquette du nœud de filtre.

Mixeur

Utilisez le plugin mixeur si vous avez plusieurs signaux d'entrée qui doivent être mélangés.

Le plugin mixeur possède jusqu'à 8 ports d'entrée étiquetés "In 1" à "In 8" et chacun avec un contrôle de gain étiqueté "Gain 1" à "Gain 8". Il y a un port de sortie étiqueté "Out". Les ports d'entrée inutilisés seront ignorés et ne causeront pas de surcharge.

Copie

Utilisez le plugin copy si vous avez besoin de copier un signal d'entrée de flux vers plusieurs filtres.

Il a un port d'entrée "In" et un port de sortie "Out".

Biquads

Les Biquads peuvent être utilisés pour effectuer toutes sortes de filtrages. Ils sont également utilisés lors de la création d'égaliseurs.

Tous les filtres biquad ont un port d'entrée "In" et un port de sortie "Out". Ils ont un contrôle "Freq", "Q" et "Gain". Leur signification dépend du biquad particulier utilisé. Les biquads ont également des ports "b0", "b1", "b2", "a0", "a1" et "a2" qui sont en lecture seule, sauf pour le biquad bq_raw, qui peut configurer des valeurs par défaut en fonction du taux du graphe et les modifier à l'exécution.

Nous renvoyons à https://arachnoid.com/BiQuadDesigner/index.html pour une explication des contrôles.

Les étiquettes suivantes peuvent être utilisées :

  • bq_lowpass un filtre passe-bas.
  • bq_highpass un filtre passe-haut.
  • bq_bandpass un filtre passe-bande.
  • bq_lowshelf un filtre en plateau bas.
  • bq_highshelf un filtre en plateau haut.
  • bq_peaking un filtre de crête.
  • bq_notch un filtre coupe-bande.
  • bq_allpass un filtre passe-partout.
  • bq_raw un filtre biquad brut. Vous avez besoin d'une section de configuration pour spécifier les coefficients par taux d'échantillonnage. Les coefficients du taux d'échantillonnage le plus proche du taux du graphe sont sélectionnés :
filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = bq_raw
            config = {
                coefficients = [
                    { rate =  44100, b0=.., b1=.., b2=.., a0=.., a1=.., a2=.. },
                    { rate =  48000, b0=.., b1=.., b2=.

Égaliseur paramétrique

L'égaliseur paramétrique enchaîne un certain nombre de biquads. Il est plus efficace que de spécifier un certain nombre de biquads en chaîne et il peut également charger la configuration à partir d'un fichier.

L'égaliseur paramétrique prend en charge le traitement multicanal et dispose de 8 ports d'entrée et 8 ports de sortie qui ne nécessitent pas tous d'être connectés. Les ports sont nommés Entrée 1 à Entrée 8 et Sortie 1 à Sortie 8.

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = param_eq
            config = {
                filename = "..."
                #filename1 = "...", filename2 = "...", ...
                filters = [
                    { type = ..., freq = ..., gain = ..., q = ... },
                    { type = ..., freq = ..., gain = ..., q = ... },
                    ....
                ]
                #filters1 = [ ... ], filters2 = [ ... ], ...
            }
            ...
        }
    ]
    ...
}

Soit un nom de fichier, soit un tableau de filtres peut être spécifié. La configuration sera utilisée pour tous les canaux. Alternativement, filenameX ou filtersX où X est le numéro de canal (entre 1 et 8) peut être utilisé pour charger une configuration spécifique au canal.

Le nom de fichier doit pointer vers une configuration d'égaliseur paramétrique générée à partir du projet AutoEQ ou Squiglink. Les deux projets permettent d'égaliser des casques ou des écouteurs intra-auriculaires à une courbe cible.

Un exemple populaire de ce qui précède est l'égalisation à la courbe cible de Harman ou l'égalisation d'un casque/IEM à un autre.

Pour AutoEQ, voir https://github.com/jaakkopasanen/AutoEq. Pour SquigLink, voir https://squig.link/.

La configuration de l'égaliseur paramétrique générée à partir d'AutoEQ ou de Squiglink ressemble à ceci.

Preamp: -6.8 dB
Filter 1: ON PK Fc 21 Hz Gain 6.7 dB Q 1.100
Filter 2: ON PK Fc 85 Hz Gain 6.9 dB Q 3.000
Filter 3: ON PK Fc 110 Hz Gain -2.6 dB Q 2.700
Filter 4: ON PK Fc 210 Hz Gain 5.9 dB Q 2.100
Filter 5: ON PK Fc 710 Hz Gain -1.0 dB Q 0.600
Filter 6: ON PK Fc 1600 Hz Gain 2.3 dB Q 2.700

Fc, Gain et Q spécifient respectivement la fréquence, le gain et le facteur Q. La quatrième colonne peut être PK, LSC ou HSC spécifiant respectivement un filtre en pic, un filtre passe-haut et un filtre passe-bas. Le plus souvent, seuls des filtres en pic sont impliqués.

Les filtres (ou les filtres spécifiques au canal filtersX où X est le canal entre 1 et 8) peuvent contenir un tableau d'objets de spécification de filtre avec les clés suivantes :

type spécifie le type de filtre, choisissez-en un parmi les étiquettes biquad disponibles. freq est la fréquence transmise au biquad. gain est le gain transmis au biquad. q est le Q transmis au biquad.

Cela permet également d'utiliser le paramètre eq sans fichier et avec tous les biquads disponibles.

Convoluteur

Le convoluteur peut être utilisé pour appliquer une réponse impulsionnelle à un signal. Il est généralement utilisé pour les réverbérations ou le son surround virtuel. Le convoluteur est implémenté avec une implémentation FFT rapide.

Le convoluteur a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il nécessite une section de configuration dans la déclaration du nœud dans ce format :

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = convolver
            config = {
                blocksize = ...
                tailsize = ...
                gain = ...
                delay = ...
                filename = ...
                offset = ...
                length = ...
                channel = ...
                resample_quality = ...
            }
            ...
        }
    ]
    ...
}
  • blocksize spécifie la taille des blocs à utiliser dans la FFT. C'est une valeur comprise entre 64 et 256. Lorsque non spécifié, cette valeur est calculée automatiquement à partir du nombre d'échantillons dans le fichier.
  • tailsize spécifie la taille des blocs de queue à utiliser dans la FFT.
  • gain le gain global à appliquer au fichier IR.
  • delay Le délai supplémentaire à ajouter à l'IR. Un nombre à virgule flottante sera interprété comme des secondes et un entier comme des échantillons. L'utilisation du délai en secondes est indépendante de la fréquence d'échantillonnage du graphique et de l'IR et est recommandée.
  • filename L'IR à charger ou à créer. Les valeurs possibles sont :
•
/hilbert crée une fonction de Hilbert qui peut être utilisée pour déphaser le signal de +/- 90 degrés. La longueur sera utilisée comme nombre de coefficients.
•
/dirac crée une fonction de Dirac qui peut être utilisée comme gain.
•
Un nom de fichier à charger comme IR. Il doit s'agir d'un format de fichier pris en charge par sndfile.
•
[ filename, ... ] un tableau de noms de fichiers. Le fichier dont la fréquence d'échantillonnage correspond le mieux à la fréquence d'échantillonnage du graphique sera utilisé.
  • offset Le décalage d'échantillons dans le fichier comme début de l'IR.
  • length Le nombre d'échantillons à utiliser comme IR.
  • channel Le canal à utiliser dans le fichier comme IR.
  • resample_quality La qualité de rééchantillonnage au cas où l'IR ne correspondrait pas à la fréquence d'échantillonnage du graphique.

Délai

Le délai peut être utilisé pour retarder un signal dans le temps.

Le délai a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port de contrôle « Délai (s) ». Il nécessite une section de configuration dans la déclaration du nœud dans ce format :

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = delay
            config = {
                "max-delay" = ...
            }
            control = {
                "Delay (s)" = ...
            }
            ...
        }
    ]
    ...
}
•
max-delay le délai maximum en secondes. Le paramètre « Délai (s) » sera limité à cette valeur.

Inverser

Le plugin d'inversion peut être utilisé pour inverser la phase du signal.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ».

Limiter

Le plugin de limitation peut être utilisé pour limiter les échantillons entre les valeurs min et max.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port « Contrôle » et « Notification » pour les valeurs de contrôle.

Le résultat final est limité aux valeurs de contrôle « Min » et « Max ».

Linéaire

Le plugin linéaire peut être utilisé pour appliquer une transformation linéaire aux échantillons ou aux valeurs de contrôle.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port « Contrôle » et « Notification » pour les valeurs de contrôle.

Les valeurs de contrôle « Mult » et « Add » sont utilisées pour configurer la transformation linéaire. Chaque échantillon ou valeur de contrôle sera calculé comme suit : nouveau = ancien * Mult + Add.

Réciproque

Le plugin réciproque peut être utilisé pour calculer le réciproque (1/x) des échantillons ou des valeurs de contrôle.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port « Contrôle » et « Notification » pour les valeurs de contrôle.

Absolu

Le plugin abs peut être utilisé pour calculer la valeur absolue des échantillons.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ».

Racine carrée

Le plugin sqrt peut être utilisé pour calculer la racine carrée des échantillons.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ».

Exp

Le plugin exp peut être utilisé pour calculer l'exponentielle (base^x) des échantillons ou des valeurs de contrôle.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port « Contrôle » et « Notification » pour les valeurs de contrôle.

La valeur de contrôle « Base » est utilisée pour calculer base ^ x pour chaque échantillon.

Log

Le plugin log peut être utilisé pour calculer le logarithme des échantillons ou des valeurs de contrôle.

Il a un port d'entrée « Entrée » et un port de sortie « Sortie ». Il a également un port « Contrôle » et « Notification » pour les valeurs de contrôle.

Les valeurs de contrôle « Base », « M1 » et « M2 » sont utilisées pour calculer out = M2 * log2f(fabsf(in * M1)) / log2f(Base) pour chaque échantillon.

Multiplier

Le plugin mult peut être utilisé pour multiplier des échantillons entre eux.

Il a 8 ports d'entrée nommés « Entrée 1 » à « Entrée 8 » et un port de sortie « Sortie ».

Tous les échantillons des ports d'entrée sont multipliés entre eux dans la sortie. Les ports d'entrée inutilisés seront ignorés et ne causeront pas de surcharge.

Sinus

Le plugin sinus génère une onde sinusoïdale.

Il a un port de sortie « Sortie » et également un port de sortie de contrôle « notification ».

« Freq », « Ampl », « Offset » et « Phase » peuvent être utilisés pour contrôler la fréquence, l'amplitude, le décalage et la phase de l'onde sinusoïdale.

Max

Utilisez le plugin max si vous devez sélectionner la valeur maximale de deux canaux.

Il a deux ports d'entrée « Entrée 1 » et « Entrée 2 » et un port de sortie « Sortie ».

Filtre passe-haut DC

Utilisez le plugin dcblock qui implémente un filtre passe-haut DC.

Il a 8 ports d'entrée « Entrée 1 » à « Entrée 8 » et les ports de sortie correspondants « Sortie 1 » à « Sortie 8 ». Tous les ports n'ont pas besoin d'être connectés.

Il dispose également d'un port d'entrée de contrôle « R » qui contrôle la pipewire-filter-chain(5)

Introduction

This document describes the filters that can be used in the filter chain module.

FILTER CHAIN FILTER

The filter chain module is a graph of filters. The filters can be built-in, LADSPA, or LV2 plugins. Filters are connected to each other using ports.

Ramp

Use the ramp plugin creates a linear ramp from Start to Stop.

It has 3 input control ports "Start", "Stop" and "Duration (s)". It also has one output port "Out". A linear ramp will be created from "Start" to "Stop" for a duration given by the "Duration (s)" control in (fractional) seconds. The current value will be stored in the output notify port "Current".

The ramp output can, for example, be used as input for the mult plugin to create a volume ramp up or down. For more a more coarse volume ramp, the "Current" value can be used in the linear plugin.

SOFA FILTER

There is an optional builtin SOFA filter available.

Spatializer

The spatializer can be used to place the sound in a 3D space.

The spatializer has an input port "In" and a stereo pair of output ports called "Out L" and "Out R". It requires a config section in the node declaration in this format:

The control can be changed at runtime to move the sounds around in the 3D space.

filter.graph = {
    nodes = [
        {
            type   = sofa
            name   = ...
            label  = spatializer
            config = {
                blocksize = ...
                tailsize = ...
                filename = ...
            }
            control = {
                "Azimuth" = ...
                "Elevation" = ...
                "Radius" = ...
            }
            ...
        }
    ]
    ...
}
  • blocksize specifies the size of the blocks to use in the FFT. It is a value between 64 and 256. When not specified, this value is computed automatically from the number of samples in the file.
  • tailsize specifies the size of the tail blocks to use in the FFT.
  • filename The SOFA file to load. SOFA files usually end in the .sofa extension and contain the HRTF for the various spatial positions.
  • Azimuth controls the azimuth, this is the direction the sound is coming from in degrees between 0 and 360. 0 is straight ahead. 90 is left, 180 behind, 270 right.
  • Elevation controls the elevation, this is how high/low the signal is in degrees between -90 and 90. 0 is straight in front, 90 is directly above and -90 directly below.
  • Radius controls how far away the signal is as a value between 0 and 100. default is 1.0.

EBUR128 FILTER

There is an optional EBU R128 filter available.

ebur128

The ebur128 plugin can be used to measure the loudness of a signal.

It has 7 input ports "In FL", "In FR", "In FC", "In UNUSED", "In SL", "In SR" and "In DUAL MONO", corresponding to the different input channels for EBUR128. Not all ports need to be connected for this filter.

The input signal is passed unmodified on the "Out FL", "Out FR", "Out FC", "Out UNUSED", "Out SL", "Out SR" and "Out DUAL MONO" output ports.

There are 7 output control ports that contain the measured loudness information and that can be used to control the processing of the audio. Some of these ports contain values in LUFS, or "Loudness Units relative to Full Scale". These are negative values, closer to 0 is louder. You can use the lufs2gain plugin to convert this value to again to adjust a volume (See below).

"Momentary LUFS" contains the momentary loudness measurement with a 400ms window and 75% overlap. It works mostly like an R.M.S. meter.

"Shortterm LUFS" contains the shortterm loudness in LUFS over a 3 second window.

"Global LUFS" contains the global integrated loudness in LUFS over the max-history window. "Window LUFS" contains the global integrated loudness in LUFS over the max-window window.

"Range LU" contains the loudness range (LRA) in LU units.

"Peak" contains the peak loudness.

"True Peak" contains the true peak loudness oversampling the signal. This can more accurately reflect the peak compared to "Peak".

The node also has an optional config section with extra configuration:

filter.graph = {
    nodes = [
        {
            type   = ebur128
            name   = ...
            label  = ebur128
            config = {
                max-history = ...
                max-window = ...
                use-histogram = ...
            }
            ...
        }
    ]
    ...
}
  • max-history the maximum history to keep in (float) seconds. Default to 10.0
  • max-window the maximum window to keep in (float) seconds. Default to 0.0 You will need to set this to some value to get "Window LUFS" output control values.
  • use-histogram uses the histogram algorithm to calculate loudness. Defaults to false.

lufs2gain

The lufs2gain plugin can be used to convert LUFS control values to gain. It needs a target LUFS control input to drive the conversion.

It has 2 input control ports "LUFS" and "Target LUFS" and will produce 1 output control value "Gain". This gain can be used as input for the builtin linear node, for example, to adust the gain.

GENERAL OPTIONS

Options with well-known behavior. Most options can be added to the global configuration or the individual streams:

  • remote.name
  • audio.rate
  • audio.channels
  • audio.position
  • media.name
  • node.latency
  • node.description
  • node.group
  • node.link.group
  • node.virtual
  • node.name : See notes below. If not specified, defaults to 'filter-chain-PID-MODULEID'.

Stream only properties:

  • media.class
  • node.name : if not given per stream, the global node.name will be prefixed with 'input.' and 'output.' to generate a capture and playback stream node.name respectively.

EXAMPLE CONFIGURATION OF A VIRTUAL SOURCE

This example uses the rnnoise LADSPA plugin to create a new virtual source.

Run with pipewire -c filter-chain.conf. The configuration can also be put under pipewire.conf.d/ to run it inside the PipeWire server.

# ~/.config/pipewire/filter-chain.conf.d/my-filter-chain-1.conf
context.modules = [
{   name = libpipewire-module-filter-chain
    args = {
        node.description =  "Noise Canceling source"
        media.name =  "Noise Canceling source"
        filter.graph = {
            nodes = [
                {
                    type = ladspa
                    name = rnnoise
                    plugin = ladspa/librnnoise_ladspa
                    label = noise_suppressor_stereo
                    control = {
                        "VAD Threshold (%)" 50.0
                    }
                }
            ]
        }
        capture.props = {
            node.name =  "capture.rnnoise_source"
            node.passive = true
        }
        playback.props = {
            node.name =  "rnnoise_source"
            media.class = Audio/Source
        }
    }
}
]

EXAMPLE CONFIGURATION OF A DOLBY SURROUND ENCODER VIRTUAL SINK

This example uses the ladpsa surround encoder to encode a 5.1 signal to a stereo Dolby Surround signal.

# ~/.config/pipewire/filter-chain.conf.d/my-filter-chain-2.conf
context.modules = [
{   name = libpipewire-module-filter-chain
    args = {
        node.description = "Dolby Surround Sink"
        media.name       = "Dolby Surround Sink"
        filter.graph = {
            nodes = [
                {
                    type  = builtin
                    name  = mixer
                    label = mixer
                    control = { "Gain 1" = 0.5 "Gain 2" = 0.5 }
                }
                {
                    type   = ladspa
                    name   = enc
                    plugin = surround_encoder_1401
                    label  = surroundEncoder
                }
            ]
            links = [
                { output = "mixer:Out" input = "enc:S" }
            ]
