NOM

libnbd-release-notes-1.20 - notes de publication pour libnbd 1.20

DESCRIPTION

Ce sont les notes de publication de la version stable de libnbd 1.20. Elles décrivent les principaux changements depuis la version 1.18.

libnbd 1.20.0 est sortie le 5 avril 2024.

Sécurité

Le fuzzing a découvert et Eric Blake a corrigé une assertion qui pouvait être déclenchée en se connectant à un serveur malveillant. Cela a reçu l'identifiant CVE-2023-5871 (gravité faible). Voir l'annonce ici : https://lists.libguestfs.org/archives/list/guestfs@lists.libguestfs.org/thread/5CRC7LRTN35WPZZ4BT6NAMH4JGMF47IK/

Si vous trouvez un problème de sécurité, veuillez lire SECURITY dans les sources (en ligne ici : https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Pour connaître les problèmes de sécurité précédents dans libnbd, voir libnbd-security(3).

Améliorations apportées aux API existantes

nbd_connect_uri(3) prend désormais correctement en charge les URI insensibles à la casse.

Protocole

Améliore l'interopérabilité avec nbd-server(1) qui prend en charge les réponses structurées mais pas le contexte méta (Eric Blake).

Outils

nbdinfo(1) ajoute la prise en charge de --isnt, --cannot, --hasnt, ce qui vous permet de vérifier si des fonctionnalités d'un serveur NBD ne sont pas prises en charge.

nbdinfo(1) ajoute la prise en charge de --uri qui affiche simplement l'URI canonique du serveur.

nbdinfo(1) affiche désormais des tailles lisibles pour les contraintes de taille de bloc (Eric Blake).

Bindings linguistiques

Une nouvelle page de manuel libnbd-rust(3) a été ajoutée, fournissant un aperçu pour écrire des programmes Rust utilisant libnbd.

La documentation Rust a été améliorée en utilisant un traducteur personnalisé de notre propre format de documentation (Perl POD) vers rustdoc.

Certains avertissements du compilateur Rust ont été corrigés (Eric Blake).

Les bindings OCaml prennent désormais en charge le zéro copie dans les fonctions AIO pread et pwrite. Ce changement est rétrocompatible avec le code existant. (Merci à Nicolas Ojeda Bar, Anil Madhavapeddy, Simon Cruanes).

Les bindings OCaml utilisent désormais "Gc.finalize" (finaliseurs au niveau OCaml au lieu de finaliseurs au niveau C) ce qui améliore la compatibilité dans OCaml 5.1.1 et supérieur (Guillaume Munch-Maccagnoni).

OCaml ≥ 4.05 est formellement requis et vérifié dans ./configure. Auparavant, nous ne spécifiions pas de version minimale d'OCaml, mais en pratique, les versions antérieures à 4.05 ne fonctionnaient probablement pas.

Tests

L'approche de fuzzing a été modifiée pour utiliser des commandes asynchrones. Cela améliore considérablement la vitesse du fuzzing et devrait permettre de trouver plus de problèmes.

Plusieurs corrections de CI (Eric Blake).

Respect du choix de l'utilisateur pour qemu-nbd, nbdkit et autres binaires à partir de (par ex.) "./configure NBDKIT=/quelque/part/nbdkit". Auparavant, nous testions souvent avec les binaires trouvés dans le PATH, même si l'utilisateur avait spécifié d'autres binaires à utiliser.

Autres améliorations et corrections de bugs

nbdinfo(1) se déconnecte désormais gracieusement du serveur en cas d'erreur, améliorant la sortie (Eric Blake).

"struct nbd_handle" contient désormais une valeur magique qui est vérifiée à l'entrée dans libnbd, ce qui devrait identifier les erreurs où les programmes appelant libnbd passent un pointeur incorrect.

Documentation

Un exemple a été ajouté sur la manière d'utiliser userfaultfd pour mmap un disque supporté par NBD. Voir examples/userfault-map.c dans les sources de libnbd.

La documentation des états de poignée acceptables dans les pages de manuel a été améliorée.

Compilation

contrib/libnbd.m4 est un test de configuration contribué pour libnbd (Bruno Haible).

"./configure --with-bash-completions" échouera désormais si le paquet bash-completions requis n'est pas installé.
