listmount(2) Manuel des appels système listmount(2)

NOM

listmount - obtenir une liste d'identifiants de montage

BIBLIOTHEQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/mount.h>  /* Définition des constantes de la structure mnt_id_req */
#include <unistd.h>
int syscall(size_t n;
            SYS_listmount, struct mnt_id_req *req,
            uint64_t mnt_ids[n], size_t n,
            unsigned long flags);
#include <linux/mount.h>
struct mnt_id_req {
    __u32  size;    /* sizeof(struct mnt_id_req) */
    __u64  mnt_id;  /* L'identifiant de montage parent recherché */
    __u64  param;   /* Le prochain identifiant de montage que nous voulons trouver */
};

Note : glibc ne fournit pas de fonction d'enrobage pour listmount(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

Pour accéder aux montages dans votre espace de noms, vous devez posséder CAP_SYS_ADMIN dans l'espace de noms utilisateur.

Cette fonction renvoie une liste d'identifiants de montage sous le req.mnt_id. Elle est conçue pour être utilisée conjointement avec statmount(2) afin de fournir un moyen d'itérer et de découvrir les systèmes de fichiers montés.

La structure mnt_id_req

req.size est utilisé par le noyau pour déterminer quelle structure mnt_id_req est passée, il doit toujours être défini à sizeof(struct mnt_id_req).

req.mnt_id est l'identifiant de montage parent à partir duquel nous listerons, ce qui peut être soit LSMT_ROOT, ce qui signifie le montage racine de l'espace de noms de montage actuel, soit un identifiant de montage obtenu soit depuis statx(2) en utilisant STATX_MNT_ID_UNIQUE, soit depuis listmount(2).

req.param est utilisé pour indiquer au noyau quel identifiant de montage utiliser comme point de départ de la liste. Ceci est utile si plusieurs appels à listmount(2) sont nécessaires. Il peut être défini à l'aide du dernier identifiant de montage renvoyé pour reprendre à partir d'un point précédent dans la liste.

VALEUR DE RETOUR

En cas de succès, le nombre d'entrées remplies dans mnt_ids est renvoyé ; 0 s'il n'y a plus de montages restants. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EPERM
L'appelant ne possède pas CAP_SYS_ADMIN dans l'espace de noms utilisateur.
EFAULT
req ou mnt_ids pointe vers un emplacement en dehors de l'espace d'adressage accessible du processus.
EINVAL
Indicateur invalide spécifié dans flags.
EINVAL
La taille de req est insuffisante pour être utilisée.
E2BIG
req est trop grand, la limite est la taille de page de l'architecture.
ENOENT
L'identifiant req.mnt_id spécifié n'existe pas.
ENOMEM
Plus de mémoire (c'est-à-dire mémoire noyau).

NORMES

Linux.

VOIR AUSSI

statmount(2), statx(2)
