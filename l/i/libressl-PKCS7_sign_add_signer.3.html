PKCS7_SIGN_ADD_SIGNER(3) Manuel des fonctions de bibliothèque PKCS7_SIGN_ADD_SIGNER(3)

NOM

PKCS7_sign_add_signer — ajoute un signataire à une structure SignedData

SYNOPSIS

bibliothèque “libcrypto”
#include <openssl/pkcs7.h>

PKCS7_SIGNER_INFO *
PKCS7_sign_add_signer(PKCS7 *p7, X509 *signcert, EVP_PKEY *pkey, const EVP_MD *md, int flags);

DESCRIPTION

PKCS7_sign_add_signer() ajoute un signataire avec le certificat signcert et la clé privée pkey en utilisant le condensat de message md à une structure de données signées PKCS7 p7.

La structure PKCS7 doit être obtenue à partir d'un appel initial à PKCS7_sign(3) avec le drapeau PKCS7_PARTIAL défini ou, dans le cas d'une nouvelle signature, une structure de données signées PKCS7 valide.

Si le paramètre md est NULL, alors le condensat par défaut pour l'algorithme de clé publique sera utilisé.

À moins que le drapeau PKCS7_REUSE_DIGEST ne soit défini, la structure PKCS7 renvoyée n'est pas complète et doit être finalisée soit par streaming (si applicable), soit par un appel à PKCS7_final(3).

Le but principal de cette fonction est de fournir un contrôle plus fin sur une structure de données signées PKCS#7 où la fonction plus simple PKCS7_sign(3) avec ses valeurs par défaut ne convient pas, par exemple s'il faut plusieurs signataires ou des algorithmes de condensat non par défaut.

N'importe lequel des drapeaux suivants (combinés par OU bit à bit) peut être passé dans le paramètre flags.

Si PKCS7_REUSE_DIGEST est défini, alors une tentative est faite pour copier la valeur du condensat de contenu de la structure PKCS7 : pour ajouter un signataire à une structure existante. Une erreur se produit si un condensat correspondant ne peut pas être trouvé pour être copié. La structure PKCS7 renvoyée sera valide et finalisée lorsque ce drapeau est défini.

Si PKCS7_PARTIAL est défini en plus de PKCS7_REUSE_DIGEST, alors la structure PKCS7_SIGNER_INO ne sera pas finalisée, afin que des attributs supplémentaires puissent être ajoutés. Dans ce cas, un appel explicite à PKCS7_SIGNER_INFO_sign() est nécessaire pour la finaliser.

Si PKCS7_NOCERTS est défini, le certificat du signataire ne sera pas inclus dans la structure PKCS7, bien que le certificat du signataire doive toujours être fourni dans le paramètre signcert. Cela peut réduire la taille de la signature si le certificat du signataire peut être obtenu par d'autres moyens : par exemple, un message précédemment signé.

La structure signedData inclut plusieurs PKCS#7 authenticatedAttributes, notamment l'heure de signature, le type de contenu PKCS#7 et la liste des chiffrements pris en charge dans un attribut SMIMECapabilities. Si PKCS7_NOATTR est défini, alors aucun authenticatedAttributes ne sera utilisé. Si PKCS7_NOSMIMECAP est défini, alors seuls les SMIMECapabilities seront omis.

Si présent, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants : triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes est désactivé, il ne sera pas inclus.

PKCS7_sign_add_signer() renvoie un pointeur interne vers la structure PKCS7_SIGNER_INFO qui vient d'être ajoutée, qui peut être utilisée pour définir des attributs supplémentaires avec les fonctions décrites dans PKCS7_add_attribute(3) avant qu'elle ne soit finalisée.

VALEUR DE RETOUR

PKCS7_sign_add_signer() renvoie un pointeur interne vers la structure PKCS7_SIGNER_INFO qui vient d'être ajoutée ou NULL si une erreur se produit. Dans certains cas d'échec, la raison peut être déterminée avec ERR_get_error(3).

VOIR AUSSI

EVP_DigestInit(3), PKCS7_add_attribute(3), PKCS7_final(3), PKCS7_get_signer_info(3), PKCS7_new(3), PKCS7_sign(3)
