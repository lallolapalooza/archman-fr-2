SSL(3) Manuel des fonctions de bibliothèque SSL(3)

NOM

ssl — Bibliothèque TLS OpenSSL

DESCRIPTION

La bibliothèque ssl implémente le protocole Transport Layer Security (TLS), successeur du protocole Secure Sockets Layer (SSL).

Un objet SSL_CTX est créé comme cadre pour établir des connexions utilisant TLS/SSL (voir SSL_CTX_new(3)). Diverses options concernant les certificats, les algorithmes, etc., peuvent être définies dans cet objet.

Lorsqu'une connexion réseau a été créée, elle peut être associée à un objet SSL. Après la création de l'objet SSL en utilisant SSL_new(3), SSL_set_fd(3) ou SSL_set_bio(3) peuvent être utilisés pour associer la connexion réseau à l'objet.

Ensuite, la négociation TLS/SSL est effectuée en utilisant SSL_accept(3) ou SSL_connect(3) respectivement. SSL_read(3) et SSL_write(3) sont utilisés pour lire et écrire des données sur la connexion TLS/SSL. SSL_shutdown(3) peut être utilisé pour fermer la connexion TLS/SSL.

STRUCTURES DE DONNÉES

Actuellement, les fonctions de la bibliothèque ssl traitent les structures de données suivantes :

SSL_METHOD (Méthode SSL)
C'est une structure de dispatch décrivant les méthodes/fonctions internes de la bibliothèque ssl qui implémentent les diverses versions de protocole. Elle est nécessaire pour créer un SSL_CTX. Voir TLS_method(3) pour les constructeurs.
SSL_CIPHER (Chiffrement SSL)
Cette structure contient les informations d'algorithme pour un chiffrement particulier qui est un élément central du protocole SSL/TLS. Les chiffrements disponibles sont configurés sur une base SSL_CTX et ceux réellement utilisés font alors partie de la SSL_SESSION.
SSL_CTX (Contexte SSL)
C'est la structure de contexte globale qui est créée par un serveur ou un client une fois par durée de vie du programme et qui contient principalement les valeurs par défaut pour les structures SSL qui sont ensuite créées pour les connexions.
SSL_SESSION (Session SSL)
C'est une structure contenant les détails de la session TLS/SSL actuelle pour une connexion : SSL_CIPHERs, certificats client et serveur, clés, etc.
SSL (Connexion SSL)
C'est la structure principale SSL/TLS qui est créée par un serveur ou un client par connexion établie. C'est en fait la structure centrale de l'API SSL. En cours d'exécution, l'application traite généralement avec cette structure qui a des liens vers la plupart des autres structures.

FICHIERS DE HEADERS

Actuellement, la bibliothèque ssl fournit les fichiers d'en-tête C suivants contenant les prototypes pour les structures de données et les fonctions :

ssl.h
C'est le fichier d'en-tête commun pour l'API SSL/TLS. Incluez-le dans votre programme pour rendre l'API de la bibliothèque ssl disponible. Il inclut en interne des en-têtes SSL plus privés et des en-têtes de la bibliothèque crypto. Chaque fois que vous avez besoin de détails approfondis sur l'intérieur de l'API SSL, regardez à l'intérieur de ce fichier d'en-tête.
ssl3.h
C'est le sous-fichier d'en-tête traitant uniquement le protocole SSLv3.
Généralement, vous n'avez pas besoin de l'inclure explicitement car il est déjà inclus par ssl.h.
tls1.h
C'est le sous-fichier d'en-tête traitant uniquement le protocole TLSv1.
Généralement, vous n'avez pas besoin de l'inclure explicitement car il est déjà inclus par ssl.h.
