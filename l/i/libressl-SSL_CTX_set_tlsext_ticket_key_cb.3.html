SSL_CTX_SET_TLSEXT_TICKET_KEY_CB(3) Manuel des fonctions de bibliothèque SSL_CTX_SET_TLSEXT_TICKET_KEY_CB(3)

NOM

SSL_CTX_set_tlsext_ticket_key_cb — définir une fonction de rappel pour le traitement des tickets de session

SYNTAXE

bibliothèque «libssl» libcrypto
#include <openssl/tls1.h>

long
SSL_CTX_set_tlsext_ticket_key_cb(SSL_CTX sslctx, int (*cb)(SSL *s, unsigned char key_name[16], unsigned char iv[EVP_MAX_IV_LENGTH], EVP_CIPHER_CTX *ctx, HMAC_CTX *hctx, int enc));

DESCRIPTION

SSL_CTX_set_tlsext_ticket_key_cb() définit une fonction de rappel cb pour le traitement des tickets de session pour le contexte ssl sslctx. Les tickets de session, définis dans la RFC 5077, fournissent une capacité de reprise de session améliorée où l'implémentation du serveur n'est pas obligée de maintenir un état par session.

La fonction de rappel cb sera appelée pour chaque session TLS initiée par le client lorsque l'extension de ticket de session est présentée dans le message TLS hello. Il incombe à cette fonction de créer ou de récupérer les paramètres cryptographiques et de maintenir leur état.

La bibliothèque OpenSSL utilise la fonction de rappel pour aider à implémenter un état de construction de ticket TLS commun conformément à la section 4 de la RFC 5077, de sorte qu'un état par session ne soit pas nécessaire et qu'un petit ensemble de variables cryptographiques doive être maintenu par l'implémentation de la fonction de rappel.

Afin de réutiliser une session, un client TLS doit envoyer une extension de ticket de session au serveur. Le client ne peut envoyer qu'un seul ticket de session. Le serveur, via la fonction de rappel, accepte de réutiliser les informations du ticket de session ou lance une négociation TLS complète pour créer un nouveau ticket de session.

La fonction de rappel est appelée avec ctx et hctx qui ont été nouvellement alloués avec EVP_CIPHER_CTX_new(3) et HMAC_CTX_new(3), respectivement.

Pour les nouveaux tickets de session, lorsque le client ne présente pas de ticket de session, ou qu'une tentative de récupération du ticket a échoué, ou qu'une option de renouvellement a été indiquée, la fonction de rappel sera appelée avec enc égal à 1. La bibliothèque OpenSSL s'attend à ce que la fonction définisse un key_name arbitraire, initialise iv, et définisse le contexte de chiffrement ctx et le contexte de hachage hctx.

Le key_name a 16 caractères de long et est utilisé comme identifiant de clé.

La longueur de iv est la longueur de l'IV du chiffrement correspondant. La longueur maximale de l'IV est EVP_MAX_IV_LENGTH octets définis dans <openssl/evp.h>.

Le vecteur d'initialisation iv doit être une valeur aléatoire. Le contexte de chiffrement ctx doit utiliser le vecteur d'initialisation iv. Le contexte de chiffrement peut être défini à l'aide de EVP_EncryptInit_ex(3). Le contexte hmac peut être défini à l'aide de HMAC_Init_ex(3).

Lorsque le client présente un ticket de session, la fonction de rappel sera appelée avec enc défini à 0 indiquant que la fonction cb doit récupérer un ensemble de paramètres. Dans ce cas, key_name et iv ont déjà été extraits du ticket de session. La bibliothèque OpenSSL s'attend à ce que le key_name soit utilisé pour récupérer des paramètres cryptographiques et que le contexte cryptographique ctx soit défini avec les paramètres récupérés et le vecteur d'initialisation iv à l'aide d'une fonction telle que EVP_DecryptInit_ex(3). Le hctx doit être défini à l'aide de HMAC_Init_ex(3).

Si le key_name est toujours valide mais qu'un renouvellement du ticket est requis, la fonction de rappel doit retourner 2. La bibliothèque appellera à nouveau la fonction de rappel avec un argument de enc égal à 1 pour définir le nouveau ticket.

La valeur de retour de la fonction cb est utilisée par OpenSSL pour déterminer le traitement ultérieur. Les valeurs de retour suivantes ont une signification :

2
Cela indique que ctx et hctx ont été définis et que la session peut se poursuivre sur ces paramètres. De plus, cela indique que le ticket de session est dans une période de renouvellement et doit être remplacé. La bibliothèque OpenSSL appellera à nouveau cb avec un argument enc de 1 pour définir le nouveau ticket (voir RFC 5077 3.3 paragraphe 2).
1
Cela indique que ctx et hctx ont été définis et que la session peut se poursuivre sur ces paramètres.
0
Cela indique qu'il n'a pas été possible de définir/récupérer un ticket de session et que la session SSL/TLS continuera en négociant un ensemble de paramètres cryptographiques ou en utilisant le mécanisme alternatif de reprise SSL/TLS, les identifiants de session.

Si elle est appelée avec enc égal à 0, la bibliothèque appellera à nouveau cb pour obtenir un nouvel ensemble de paramètres.

inférieur à 0
Cela indique une erreur.

La reprise de session évite le TLS afin que la négociation de certificat client ne se produise pas. Elle compense cela en stockant le certificat client et toutes les autres informations d'état négociées de manière chiffrée dans le ticket. Dans une session reprise, les applications disposeront de toutes ces informations d'état exactement comme si une négociation complète avait eu lieu.

Si un attaquant peut obtenir la clé utilisée pour chiffrer un ticket de session, il peut obtenir le secret maître de n'importe quel ticket utilisant cette clé et déchiffrer n'importe quel trafic utilisant cette session : même si la suite de chiffrement prend en charge la confidentialité avant (forward secrecy). Par conséquent, les applications peuvent souhaiter utiliser plusieurs clés et éviter d'utiliser des clés à long terme stockées dans des fichiers.

Les applications peuvent utiliser des clés plus longues pour maintenir un niveau de sécurité cohérent. Par exemple, si une suite de chiffrement utilise des chiffrements de 256 bits mais seulement une clé de ticket de 128 bits, la sécurité globale n'est que de 128 bits car la rupture de la clé de ticket permettra à un attaquant d'obtenir les clés de session.

VALEUR DE RETOUR

Cette fonction retourne 0 pour indiquer que la fonction de rappel a été définie.

EXEMPLES

Implémentation de référence :

SSL_CTX_set_tlsext_ticket_key_cb(SSL, ssl_tlsext_ticket_key_cb);
....
static int ssl_tlsext_ticket_key_cb(SSL *s, unsigned char key_name[16],
    unsigned char *iv, EVP_CIPHER_CTX *ctx, HMAC_CTX *hctx, int enc)
{
	if (enc) { /* créer une nouvelle session */
		if (RAND_bytes(iv, EVP_MAX_IV_LENGTH))
			return -1; /* aléatoire insuffisant */

		key = currentkey(); /* quelque chose que vous devez implémenter */
		if (!key) {
			/* la clé actuelle n'existe pas ou n'est pas valide */
			key = createkey();
			    /* quelque chose que vous devez implémenter.
			     * createkey doit initialiser un nom,
			     * une clé aes, une clé hmac, et éventuellement
			     * une heure d'expiration. */
			if (!key) /* la clé n'a pas pu être créée */
				return 0;
		}
		memcpy(key_name, key->name, 16);

		EVP_EncryptInit_ex(&ctx, EVP_aes_128_cbc(), NULL,
		    key->aes_key, iv);
		HMAC_Init_ex(&hctx, key->hmac_key, 16, EVP_sha256(), NULL);

		return 1;

	} else { /* récupérer la session */
		key = findkey(name);

		if  (!key || key->expire < now())
			return 0;

		HMAC_Init_ex(&hctx, key->hmac_key, 16, EVP_sha256(), NULL);
		EVP_DecryptInit_ex(&ctx, EVP_aes_128_cbc(), NULL,
		    key->aes_key, iv );

		if (key->expire < (now() - RENEW_TIME))
		    /* cette session obtiendra un nouveau ticket
		     * même si l'actuel est toujours valide */
		    return 2;

		return 1;
	}
}
