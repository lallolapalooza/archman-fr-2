DESCRIPTION

Les routines de hachage EVP sont une interface de haut niveau pour les fonctions de hachage de messages et doivent être utilisées à la place des fonctions spécifiques au chiffrement.

EVP_MD_CTX_new() alloue un nouveau contexte de hachage vide.

EVP_MD_CTX_reset() nettoie ctx et le réinitialise à l'état qu'il avait après EVP_MD_CTX_new(), de sorte qu'il puisse être réutilisé.

EVP_MD_CTX_free() nettoie ctx et libère l'espace qui lui a été alloué.

EVP_MD_CTX_init() est une fonction obsolète pour effacer un contexte de hachage sur la pile avant utilisation. Ne l'utilisez pas sur un contexte de hachage retourné par EVP_MD_CTX_new() ou sur un contexte déjà utilisé.

EVP_MD_CTX_create(), EVP_MD_CTX_cleanup(), et EVP_MD_CTX_destroy() sont des alias obsolètes pour EVP_MD_CTX_new(), EVP_MD_CTX_reset(), et EVP_MD_CTX_free(), respectivement.

EVP_DigestInit_ex() configure le contexte de hachage ctx pour utiliser un hachage type. Le type sera typiquement fourni par une fonction telle que EVP_sha512(). L'argument ENGINE *engine est toujours ignoré et il est recommandé de passer NULL.

EVP_DigestUpdate() hache cnt octets de données à d dans le contexte de hachage ctx. Cette fonction peut être appelée plusieurs fois sur le même ctx pour hacher des données supplémentaires.

EVP_DigestFinal_ex() récupère la valeur du hachage à partir de ctx et la place dans md. Si le paramètre s n'est pas NULL, alors le nombre d'octets de données écrits (c'est-à-dire la longueur du hachage) sera écrit dans l'entier à s; au maximum EVP_MAX_MD_SIZE octets seront écrits. Après avoir appelé EVP_DigestFinal_ex(), aucun appel supplémentaire à EVP_DigestUpdate() ne peut être effectué, mais EVP_DigestInit_ex() peut être appelé

EVP_DigestInit_ex, EVP_DigestUpdate, EVP_DigestFinal_ex, EVP_Digest, EVP_MD_CTX_copy_ex, EVP_DigestInit, EVP_DigestFinal, EVP_MD_CTX_copy, EVP_sha224, EVP_sha256, EVP_sha384, EVP_sha512, EVP_ripemd160, EVP_sha512_224, EVP_sha512_256, EVP_md_null, EVP_get_digestbyname, EVP_get_digestbynid, EVP_get_digestbyobj, EVP_MD_CTX_new, EVP_MD_CTX_free, EVP_MD_CTX_create, EVP_MD_CTX_init, EVP_MD_CTX_cleanup, EVP_MD_CTX_reset, EVP_MD_CTX_destroy, EVP_MD_CTX_md - Interface de haut niveau pour les fonctions de hachage.

DESCRIPTION

Une opération de hachage à l'aide de l'interface EVP se déroule en trois phases :

  1. EVP_DigestInit_ex() initialise la structure EVP_MD_CTX (qui est allouée par l'EVP_MD_CTX_new() ou l'EVP_MD_CTX_create()) qui doit être utilisée pour hacher les données. Le paramètre type spécifie le type de hachage à utiliser, par exemple EVP_sha256(). Le paramètre engine est une ancienne fonctionnalité et ne doit généralement pas être utilisé ; passer NULL est recommandé. Si le contexte ctx est déjà utilisé, il est réinitialisé avant d'être utilisé avec le nouveau type de hachage.

  2. EVP_DigestUpdate() peut être appelé plusieurs fois pour hacher des morceaux de données. Le paramètre d est un pointeur vers les données, et cnt est le nombre d'octets à hacher.

  3. EVP_DigestFinal_ex() calcule le hachage final des données hachées jusqu'à présent. Le résultat du hachage est placé dans le tampon md. Le paramètre s est un pointeur vers un entier qui reçoit la longueur du hachage calculé en octets. Le tampon md doit être assez grand pour contenir le plus grand hachage possible, qui est défini par EVP_MAX_MD_SIZE. Après cet appel, le contexte EVP_MD_CTX n'est plus utilisable pour de nouvelles opérations jusqu'à ce qu'il soit réinitialisé à l'aide de EVP_MD_CTX_reset() ou qu'un nouvel appel à EVP_DigestInit_ex() soit effectué. Le paramètre engine est ignoré et passer NULL est recommandé.

Les fonctions suivantes sont également disponibles :

EVP_MD_CTX_new()
Alloue et initialise un nouvel objet EVP_MD_CTX. Doit être libéré avec EVP_MD_CTX_free().
EVP_MD_CTX_free()
Libère un objet EVP_MD_CTX précédemment alloué avec EVP_MD_CTX_new() ou EVP_MD_CTX_create().
EVP_MD_CTX_create()
Identique à EVP_MD_CTX_new().
EVP_MD_CTX_init()
Identique à EVP_MD_CTX_reset() mais sans nettoyage préalable.
EVP_MD_CTX_cleanup()
Nettoie un objet EVP_MD_CTX, mais ne libère pas la mémoire. Ne doit pas être utilisé dans les nouvelles applications.
EVP_MD_CTX_reset()
Réinitialise le contexte de hachage EVP_MD_CTX pour pouvoir être réutilisé. Les données hachées précédemment sont effacées.
EVP_MD_CTX_destroy()
Identique à EVP_MD_CTX_free().
EVP_MD_CTX_md()
Retourne l'EVP_MD utilisé par ctx.
EVP_Digest()
est une fonction wrapper simple pour hacher cnt octets de données à d en utilisant le hachage type dans une opération en une seule passe et placer la valeur du hachage dans md, et, sauf si s est NULL, la longueur du hachage en octets dans *s. Ce wrapper utilise un contexte de hachage temporaire et passe ses arguments à EVP_DigestInit_ex(), EVP_DigestUpdate(), et EVP_DigestFinal_ex() en interne. L'argument ENGINE *engine est toujours ignoré et passer NULL est recommandé.

EVP_MD_CTX_copy_ex()
peut être utilisée pour copier l'état du hachage de message de in à out. Ceci est utile si de grandes quantités de données doivent être hachées qui ne diffèrent que sur les derniers octets.
EVP_DigestInit()
est une fonction obsolète se comportant comme EVP_DigestInit_ex() sauf qu'elle nécessite EVP_MD_CTX_reset() avant de pouvoir être utilisée sur un contexte déjà utilisé.
EVP_DigestFinal()
est une fonction obsolète se comportant comme EVP_DigestFinal_ex() sauf que le contexte de hachage ctx est automatiquement nettoyé après utilisation en appelant EVP_MD_CTX_reset() en interne.
EVP_MD_CTX_copy()
est une fonction obsolète se comportant comme EVP_MD_CTX_copy_ex() sauf qu'elle nécessite EVP_MD_CTX_reset() avant qu'un contexte déjà utilisé puisse être passé comme out.
EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), et EVP_ripemd160()
retournent des structures EVP_MD pour les algorithmes de hachage SHA-224, SHA-256, SHA-384, SHA-512 et RIPEMD-160 respectivement.
EVP_sha512_224() et EVP_sha512_256()
retournent une structure EVP_MD qui fournit les variantes SHA-512 tronquées SHA-512/224 et SHA-512/256, respectivement.
EVP_md_null()
est un hachage de message "nul" qui ne fait rien : c'est-à-dire que le hachage qu'il retourne est de longueur nulle.
EVP_get_digestbyname(), EVP_get_digestbynid(), et EVP_get_digestbyobj()
retournent une structure EVP_MD lorsqu'on leur passe respectivement un nom de hachage, un NID de hachage, ou une structure ASN1_OBJECT.
EVP_get_digestbynid() et EVP_get_digestbyobj()
sont implémentées comme des macros.

L'interface EVP pour les hachages de message devrait presque toujours être préférée aux interfaces de bas niveau. En effet, le code devient alors transparent au hachage utilisé et beaucoup plus flexible.

L'argument ENGINE *engine est toujours ignoré et passer NULL est recommandé.

Les fonctions EVP_DigestInit(), EVP_DigestFinal(), et EVP_MD_CTX_copy() sont obsolètes mais sont conservées pour maintenir la compatibilité avec le code existant. Les nouvelles applications doivent utiliser EVP_DigestInit_ex(), EVP_DigestFinal_ex(), et EVP_MD_CTX_copy_ex() car elles peuvent réutiliser efficacement un contexte de hachage au lieu de l'initialiser et de le nettoyer à chaque appel.

Si les contextes de hachage ne sont pas nettoyés après utilisation, des fuites de mémoire se produiront.

VALEURS DE RETOUR

EVP_MD_CTX_new() et EVP_MD_CTX_create() retournent le nouvel objet EVP_MD_CTX ou NULL en cas d'échec.

EVP_MD_CTX_reset(), EVP_MD_CTX_init(), et EVP_MD_CTX_cleanup() retournent toujours 1.

EVP_DigestInit_ex(), EVP_DigestUpdate(), EVP_DigestFinal_ex(), EVP_Digest(), EVP_MD_CTX_copy_ex(), EVP_DigestInit(), EVP_DigestFinal(), et EVP_MD_CTX_copy() retournent 1 en cas de succès ou 0 en cas d'échec.

EVP_MD_CTX_md() retourne l'objet EVP_MD utilisé par ctx, ou NULL si ctx est NULL ou n'a pas encore d'algorithme de hachage de message assigné.

EVP_md_null(), EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), EVP_sha512_224(), EVP_sha512_256(), et EVP_ripemd160() retournent des pointeurs vers des objets statiques constants appartenant à la bibliothèque.

EVP_get_digestbyname(), EVP_get_digestbynid(), et EVP_get_digestbyobj() retournent soit une structure EVP_MD soit NULL en cas d'erreur.

EXEMPLES

Cet exemple hache les données "Test Message\n" et "Hello World\n", en utilisant le nom du hachage passé en ligne de commande.

#include <stdio.h>
#include <string.h>
#include <openssl/evp.h>

int
main(int argc, char *argv[])
{
	EVP_MD_CTX *mdctx;
	const EVP_MD *md;
	const char mess1[] = "Test Message\n";
	const char mess2[] = "Hello World\n";
	unsigned char md_value[EVP_MAX_MD_SIZE];
	unsigned int md_len, i;

	if (argc <= 1) {
		printf("Usage: mdtest digestname\n");
		exit(1);
	}

	md = EVP_get_digestbyname(argv[1]);
	if (md == NULL) {
		printf("Unknown message digest %s\n", argv[1]);
		exit(1);
	}

	mdctx = EVP_MD_CTX_new();
	EVP_DigestInit_ex(mdctx, md, NULL);
	EVP_DigestUpdate(mdctx, mess1, strlen(mess1));
	EVP_DigestUpdate(mdctx, mess2, strlen(mess2));
	EVP_DigestFinal_ex(mdctx, md_value, &md_len);
	EVP_MD_CTX_free(mdctx);

	printf("Digest is: ");
	for(i = 0; i < md_len; i++)
		printf("%02x", md_value[i]);
	printf("\n");

	return 0;
}
