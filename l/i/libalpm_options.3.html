Accesseurs vers le répertoire racine

Le répertoire racine est le préfixe où libalpm installe les paquets.

Les hooks et les scripts seront également exécutés dans un chroot pour garantir qu'ils se comportent correctement dans des racines alternatives.
const char * alpm_option_get_root (alpm_handle_t *handle)
Retourne le chemin de la racine.

Accesseurs vers le chemin de la base de données

Le chemin dbpath est l'endroit où libalpm stocke la base de données locale et télécharge les bases de données synchronisées.
const char * alpm_option_get_dbpath (alpm_handle_t *handle)
Retourne le chemin du répertoire de la base de données.

Accesseurs vers le fichier de verrouillage

Le fichier de verrouillage est utilisé pour s'assurer que deux instances de libalpm ne peuvent pas écrire dans la base de données en même temps.

Le fichier de verrouillage est créé lors de la validation d'une transaction et libéré lorsque la transaction est terminée. Ou lors de l'appel à alpm_unlock.
const char * alpm_option_get_lockfile (alpm_handle_t *handle)
Obtient le nom du fichier de verrouillage de la base de données.

Accesseurs pour l'extension de la base de données

Ceci contrôle l'extension utilisée pour les bases de données de synchronisation.

libalpm utilisera cette extension pour rechercher les bases de données distantes et comme nom utilisé lors de leur ouverture en lecture.

Ceci est utile pour les bases de données de fichiers. Comme les fichiers peuvent augmenter considérablement la taille d'une base de données, un serveur pourrait détenir une base de données sans fichiers sous une extension, et une autre avec des fichiers sous une autre extension.

Laquelle est téléchargée et utilisée dépend alors de ce réglage.
const char * alpm_option_get_dbext (alpm_handle_t *handle)
Obtient l'extension de base de données configurée. int alpm_option_set_dbext (alpm_handle_t *handle, const char *dbext)
