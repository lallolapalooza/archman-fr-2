EVP_CIPHER_CTX_INIT(3) Manuel de fonctions de bibliothèque EVP_CIPHER_CTX_INIT(3)

NOM

EVP_CIPHER_CTX_init, EVP_CIPHER_CTX_cleanup, EVP_Cipher — fonctions de chiffrement EVP obsolètes

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_CIPHER_CTX_init(EVP_CIPHER_CTX *ctx);

int
EVP_CIPHER_CTX_cleanup(EVP_CIPHER_CTX *ctx);

int
EVP_Cipher(EVP_CIPHER_CTX *ctx, unsigned char *out, const unsigned char *in, unsigned int in_len);

DESCRIPTION

EVP_CIPHER_CTX_init() est une fonction dépréciée qui pouvait être utilisée pour effacer un contexte de chiffrement sur la pile avant que EVP_CIPHER_CTX ne devienne opaque. L'appeler sur un contexte de chiffrement retourné par EVP_CIPHER_CTX_new(3) n'a aucun effet. L'appeler sur un contexte de chiffrement qui a déjà été utilisé peut entraîner une fuite de mémoire avec les anciennes versions de la bibliothèque. Utilisez plutôt EVP_CIPHER_CTX_reset(3) ou EVP_CIPHER_CTX_free(3).

EVP_CIPHER_CTX_cleanup() est un alias déprécié pour EVP_CIPHER_CTX_reset(3). Il efface toutes les informations de ctx et libère toute la mémoire allouée qui lui est associée, à l'exception de l'objet ctx lui-même.

EVP_Cipher() expose des détails d'implémentation des fonctions EVP_CipherUpdate(3) et EVP_CipherFinal(3) qui n'auraient jamais dû faire partie de l'API publique.

Si le drapeau EVP_CIPH_FLAG_CUSTOM_CIPHER est défini pour le chiffrement utilisé par ctx, le comportement dépend de in. Si cet argument est NULL et que in_len est 0, le comportement est similaire à EVP_CipherFinal(3) ; si in_len n'est pas 0, le comportement est indéfini. Si in n'est pas NULL, le comportement est similaire à EVP_CipherUpdate(3). Dans les deux cas, les exceptions à la similarité sont que les arguments et les valeurs de retour diffèrent.

Si le drapeau EVP_CIPH_FLAG_CUSTOM_CIPHER n'est pas défini pour le chiffrement utilisé par ctx, il chiffre ou déchiffre des blocs de données alignés dont les longueurs correspondent à la taille du bloc de chiffrement. Il exige que l'opération de chiffrement ou de déchiffrement précédente utilisant le même ctx, s'il y en a eu une, se soit terminée exactement sur une limite de bloc et que in_len soit un multiple entier de la taille du bloc de chiffrement. Si l'une de ces conditions n'est pas respectée, EVP_Cipher() produit silencieusement des résultats incorrects. Pour cette raison, il est fortement recommandé d'utiliser plutôt la fonction EVP_CipherUpdate(3). Cette dernière peut gérer en toute sécurité des blocs partiels, et même si in_len est effectivement un multiple de la taille du bloc de chiffrement pour tous les appels, la surcharge entraînée par l'utilisation de EVP_CipherUpdate(3) est minimale.

VALEURS DE RETOUR

EVP_CIPHER_CTX_init() retourne toujours 1.

EVP_CIPHER_CTX_cleanup() retourne 1 en cas de succès ou 0 en cas d'échec.

Avec EVP_CIPH_FLAG_CUSTOM_CIPHER, EVP_Cipher() retourne le nombre d'octets écrits dans out en cas de succès ou -1 en cas d'échec. Sans EVP_CIPH_FLAG_CUSTOM_CIPHER, il retourne 1 en cas de succès ou 0 en cas d'échec.

VOIR AUSSI

evp(3), EVP_EncryptInit(3)

HISTORIQUE

EVP_Cipher() est apparu pour la première fois dans SSLeay 0.6.5. EVP_CIPHER_CTX_cleanup() est apparu pour la première fois dans SSLeay 0.8.0. EVP_CIPHER_CTX_init() est apparu pour la première fois dans SSLeay 0.9.0. Toutes ces fonctions sont disponibles depuis OpenBSD 2.4.

AVERTISSEMENTS

La vérification de la valeur de retour de EVP_Cipher() nécessite une attention particulière : zéro signale le succès si EVP_CIPH_FLAG_CUSTOM_CIPHER est défini ou l'échec sinon.
