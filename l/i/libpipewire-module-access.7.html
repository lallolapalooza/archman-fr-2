NOM

libpipewire-module-access - Accès

DESCRIPTION

Le module d'accès effectue des vérifications d'accès sur les clients.

La vérification d'accès n'est effectuée qu'une seule fois par client, les vérifications ultérieures retournent la même résolution.

Les permissions attribuées à un client sont configurées en tant qu'arguments de ce module, voir ci-dessous. La gestion des permissions au-delà de l'accès illimité est déléguée à un agent externe, généralement le gestionnaire de session.

Ce module définit pipewire.access comme suit :

•
Si l'option de module access.legacy n'est pas activée :

La valeur définie pour le socket dans l'option de module access.socket, ou "default" si aucune valeur n'est définie.

•
Si access.legacy est activé, la valeur est :
•
"flatpak" : si le client est un client Flatpak
•
"unrestricted" : si la propriété de client pipewire.client.access est définie à "allowed"
•
Valeur de la propriété de client pipewire.client.access, si définie
•
"unrestricted" : sinon

Si la valeur résultante de pipewire.access est "unrestricted", ce module accordera au client toutes les permissions d'accès à toutes les ressources. Sinon, le client sera obligé d'attendre qu'un acteur externe, tel que le gestionnaire de session, mette à jour les permissions du client.

Pour les connexions des applications s'exécutant à l'intérieur de Flatpak, et non médiatisées par d'autres clients (par exemple, portal ou pipewire-pulse), la propriété pipewire.access.portal.app_id est définie sur l'ID de l'application Flatpak, si trouvé. De plus, pipewire.sec.flatpak est défini à true.

NOM DU MODULE

libpipewire-module-access

OPTIONS DU MODULE

Options spécifiques au comportement de ce module

•
access.socket = { "nom-socket" = "valeur-accès", ... }:

Permissions d'accès spécifiques au socket. A la valeur par défaut { "CORENAME-manager": "unrestricted" } où CORENAME est le nom du cœur PipeWire, généralement pipewire-0.

•
access.legacy = true : active le mode d'accès compatible avec les versions antérieures. Ne peut pas être activé lors de l'utilisation des permissions basées sur les sockets.

Si access.socket n'est pas spécifié, a la valeur par défaut true, sinon false.

Attention

Le mode hérité est déprécié. La valeur par défaut est sujette à modification et le mode hérité pourrait être supprimé dans les futures versions de PipeWire.

OPTIONS GÉNÉRALES

Options avec un comportement bien connu :

  • pipewire.access
  • pipewire.client.access

SUBSTITUTION DE CONFIGURATION

Une section de configuration module.access.args peut être ajoutée pour remplacer les arguments du module.

# ~/.config/pipewire/pipewire.conf.d/my-access-args.conf
module.access.args = {
     access.socket = {
         pipewire-0 = "default",
         pipewire-0-manager = "unrestricted",
     }
}

CONFIGURATION EXEMPLE

 context.modules = [
  {   name = libpipewire-module-access
      args = {
          # Utiliser un socket séparé pour les applications du gestionnaire de session,
          # et pipewire-0 pour les applications habituelles.
          access.socket = {
              pipewire-0 = "default",
              pipewire-0-manager = "unrestricted",
          }
      }
  }
]
