listen(2) Manuel des appels système listen(2)

NOM

listen - écouter les connexions sur une socket

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/socket.h>
int listen(int sockfd, int backlog);

DESCRIPTION

La fonction listen() marque la socket désignée par sockfd comme une socket passive, c'est-à-dire une socket qui sera utilisée pour accepter les demandes de connexion entrantes à l'aide de accept(2).

L'argument sockfd est un descripteur de fichier qui fait référence à une socket de type SOCK_STREAM ou SOCK_SEQPACKET.

L'argument backlog définit la longueur maximale que peut atteindre la file d'attente des connexions en attente pour sockfd. Si une demande de connexion arrive alors que la file est pleine, le client peut recevoir une erreur indiquant ECONNREFUSED ou, si le protocole sous-jacent supporte la retransmission, la demande peut être ignorée afin qu'une tentative ultérieure de connexion réussisse.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EADDRINUSE
Une autre socket écoute déjà sur le même port.
EADDRINUSE
(Sockets du domaine Internet) La socket désignée par sockfd n'avait pas été liée à une adresse précédemment et, lors de la tentative de la lier à un port éphémère, il a été déterminé que tous les numéros de port de la plage des ports éphémères sont actuellement utilisés. Voir la discussion sur /proc/sys/net/ipv4/ip_local_port_range dans ip(7).
EBADF
L'argument sockfd n'est pas un descripteur de fichier valide.
ENOTSOCK
Le descripteur de fichier sockfd ne fait pas référence à une socket.
EOPNOTSUPP
Le type de la socket ne supporte pas l'opération listen().

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, 4.4BSD (apparue pour la première fois dans 4.2BSD).

NOTES

Pour accepter les connexions, les étapes suivantes sont effectuées :

(1)
Une socket est créée avec socket(2).
(2)
La socket est liée à une adresse locale en utilisant bind(2), afin que d'autres sockets puissent y être connectées avec connect(2).
(3)
La volonté d'accepter les connexions entrantes et une limite de file d'attente pour les connexions entrantes sont spécifiées avec listen().
(4)
Les connexions sont acceptées avec accept(2).

Le comportement de l'argument backlog sur les sockets TCP a changé avec Linux 2.2. Il spécifie maintenant la longueur de la file d'attente pour les sockets complètement établies attendant d'être acceptées, au lieu du nombre de requêtes de connexion incomplètes. La longueur maximale de la file pour les sockets incomplètes peut être définie via /proc/sys/net/ipv4/tcp_max_syn_backlog. Lorsque les syncookies sont activées, il n'y a pas de longueur maximale logique et ce paramètre est ignoré. Voir tcp(7) pour plus d'informations.

Si l'argument backlog est supérieur à la valeur dans /proc/sys/net/core/somaxconn, il est silencieusement limité à cette valeur. Depuis Linux 5.4, la valeur par défaut dans ce fichier est 4096 ; dans les noyaux précédents, la valeur par défaut était 128. Avant Linux 2.4.25, cette limite était une valeur codée en dur, SOMAXCONN, avec la valeur 128.

EXEMPLES

Voir bind(2).

VOIR AUSSI

accept(2), bind(2), connect(2), socket(2), socket(7)
