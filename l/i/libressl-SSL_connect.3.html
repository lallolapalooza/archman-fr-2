SSL_CONNECT(3) Manuel des fonctions de bibliothèque SSL_CONNECT(3)

NOM

SSL_connect — initier le handshake TLS/SSL avec un serveur TLS/SSL

SYNOPHIS

bibliothèque «libssl» libcrypto
#include <openssl/ssl.h>

int
SSL_connect(SSL *ssl);

DESCRIPTION

SSL_connect() initie le handshake TLS/SSL avec un serveur. Le canal de communication doit avoir déjà été établi et assigné au ssl en configurant un BIO sous-jacent.

Le comportement de SSL_connect() dépend du BIO sous-jacent.

Si le BIO sous-jacent est en mode bloquant, SSL_connect() ne retournera qu'une fois le handshake terminé ou une erreur survenue.

Si le BIO sous-jacent est en mode non bloquant, SSL_connect() retournera également lorsque le BIO sous-jacent n'a pas pu satisfaire les besoins de SSL_connect() pour continuer le handshake, indiquant le problème avec la valeur de retour −1. Dans ce cas, un appel à SSL_get_error(3) avec la valeur de retour de SSL_connect() donnera SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE. Le processus appelant doit alors réitérer l'appel après avoir pris les mesures appropriées pour satisfaire les besoins de SSL_connect(). L'action dépend du BIO sous-jacent. Lors de l'utilisation d'une socket non bloquante, rien ne doit être fait, mais select(2) peut être utilisé pour vérifier la condition requise. Lors de l'utilisation d'un BIO tamponné, comme une paire de BIO, les données doivent être écrites dans ou récupérées depuis le BIO avant de pouvoir continuer.

VALEURS DE RETOUR

Les valeurs de retour suivantes peuvent survenir :

0
Le handshake TLS/SSL n'a pas réussi mais a été arrêté de manière contrôlée et conformément aux spécifications du protocole TLS/SSL. Appelez SSL_get_error(3) avec la valeur de retour ret pour connaître la raison.
1
Le handshake TLS/SSL s'est terminé avec succès et une connexion TLS/SSL a été établie.
<0
Le handshake TLS/SSL n'a pas réussi, car une erreur fatale s'est produite au niveau du protocole ou une défaillance de connexion s'est produite. L'arrêt n'a pas été propre. Cela peut également se produire si une action est nécessaire pour continuer l'opération pour les BIO non bloquants. Appelez SSL_get_error(3) avec la valeur de retour ret pour connaître la raison.

VOIR AUSSI
