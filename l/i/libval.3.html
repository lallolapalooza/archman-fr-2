val_context_setqflags() - gérer les indicateurs du contexte du validateur

val_resolve_and_check(), val_free_result_chain() - interroger et valider les réponses d'un serveur DNS

val_istrusted() - vérifier si la valeur de statut correspond à celle d'une réponse de confiance

val_isvalidated() - vérifier si la valeur de statut représente une réponse qui est cryptographiquement chaînée à partir d'une ancre de confiance configurée

DESCRIPTION

La fonction val_resolve_and_check() interroge un ensemble de serveurs de noms pour le tuple <domain_name, type, class> et vérifie et valide la réponse. La vérification implique de vérifier les RRSIGs, et la validation est la vérification d'une chaîne d'authentification à partir d'une ancre de confiance configurée.

Le paramètre flags peut être utilisé pour contrôler les résultats de la validation. Les valeurs suivantes, qui peuvent être combinées par OR, sont actuellement définies pour ce champ :

VAL_QUERY_DONT_VALIDATE
Cet indicateur fait que le validateur désactive la validation pour cette requête.
VAL_QUERY_IGNORE_SKEW
Cet indicateur fait que le validateur désactive la vérification des heures d'inception et d'expiration des signatures sur les RRSIGs.
VAL_QUERY_AC_DETAIL
Cet indicateur fait que le validateur copie les détails de la chaîne d'authentification dans le membre val_rc_answer de la structure val_result_chain retournée.
VAL_QUERY_ASYNC
Cet indicateur active la résolution asynchrone des requêtes pour cette recherche.
VAL_QUERY_NO_DLV
Cet indicateur fait que le validateur désactive le traitement DLV pour cette requête. Ceci n'est disponible que si la bibliothèque libval(3) a été compilée avec le support DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
En interrogeant divers serveurs de noms, libsres(3) tentera également plusieurs tailles EDNS0, se terminant par une requête où EDNS0 est désactivé (c'est-à-dire sans bit CD défini). Cet indicateur fait que libval désactive le fallback EDNS0 pour la requête.
VAL_QUERY_ITERATE
Cet indicateur force libval à rechercher itérativement le nom en interrogeant divers serveurs de noms dans la hiérarchie de délégation, au lieu de demander ces informations à tout serveur de noms de cache qui pourrait être configuré dans dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Cet indicateur force libval à ne consulter que son cache lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_CACHE
Il y a deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données dans les deux caches lors de la tentative de résolution d'un nom.
VAL_QUERY_SKIP_ANS_CACHE
Il y a deux niveaux de mise en cache dans libval : au niveau de l'assertion et au niveau de la réponse. Cet indicateur force libval à ignorer les données dans le cache de réponses lors de la tentative de résolution d'un nom. Si une assertion existe déjà pour le nom, la classe et le type donnés, cette assertion est réutilisée jusqu'à son expiration. Une fois expirée, le nom est recherché via une requête, même si un enregistrement plus récent (obtenu par une autre assertion dans le même contexte ou un contexte différent) est disponible dans son cache de réponses.

Le premier paramètre de val_resolve_and_check() est le contexte du validateur. Les applications peuvent créer un nouveau contexte de validateur en utilisant la fonction val_create_context(). Cette fonction analyse les fichiers de configuration du résolveur et du validateur et crée le handle newcontext pour ces informations analysées. Les informations stockées dans le contexte du validateur comprennent la politique de validation et la politique du résolveur.

Les politiques du validateur et du résolveur sont lues à partir des fichiers /etc/dnsval.conf et /etc/resolv.conf par défaut. /etc/root.hints fournit les informations d'amorçage pour le validateur lorsqu'il fonctionne comme un résolveur complet (voir dnsval.conf(3)). Ces valeurs par défaut peuvent être différentes si une autre valeur a été spécifiée lors de la configuration de la bibliothèque. Si le fichier de configuration du résolveur par défaut n'est pas trouvé à l'emplacement spécifié, libval essaiera également de se rabattre sur /etc/resolv.conf en dernier recours.

Les applications peuvent également créer un contexte de validateur avec une politique personnalisée en utilisant la fonction val_create_context_ex().

L'argument opt dans val_create_context_ex() pointe vers la structure suivante :

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags spécifie les indicateurs de requête par défaut pour les requêtes associées au contexte. Ce champ est identique au paramètre flags de la fonction val_resolve_and_check().

Les champs vc_val_conf, vc_res_conf et vc_root_conf peuvent être utilisés pour spécifier des fichiers de configuration alternatifs à la place des fichiers par défaut utilisés pour les informations de configuration du validateur, du résolveur et des indices racine.

Le champ vc_valpol peut être utilisé pour fournir un "extrait" de configuration de validateur personnalisé au validateur. Le validateur analyse ces informations et les applique à la configuration par défaut du validateur, soit comme une extension, soit comme un remplacement, tel que spécifié par le champ vc_polflags. Le champ vc_nslist, de manière similaire, peut être utilisé pour fournir une liste personnalisée de serveurs de noms récursifs auxquels envoyer les requêtes, en plus (ou à la place) de la liste des serveurs de noms spécifiée dans le fichier resolv.conf. La liste des serveurs de noms dans vc_res_conf doit être spécifiée comme une liste d'adresses IP ou IPv6 délimitées par des espaces.

Un mappage personnalisé entre une zone et un serveur de noms peut être créé en utilisant la fonction val_context_store_ns_for_zone().

vc_polflags peut être configuré avec les valeurs suivantes :

CTX_DYN_POL_VAL_OVR
Lorsque cet indicateur est défini, seule la configuration du validateur spécifiée dans le champ vc_valpol est utilisée pour la configuration du validateur. Les options spécifiées dans le fichier dnsval.conf sont ignorées.
CTX_DYN_POL_RES_OVR
Lorsque cet indicateur est défini, seule la configuration du résolveur spécifiée dans le champ vc_res_conf est utilisée pour la configuration du résolveur. Les options spécifiées dans le fichier resolv.conf sont ignorées.

Voir dnsval.conf(3) pour la description de la syntaxe des politiques de validation et de résolution.

Les structures retournées par val_resolve_and_check() sont chaînées.

struct val_result_chain {
    val_status_t vr_status;
    struct val_result_chain *vr_next;
    dns_rcode_t vr_rcode;
    int vr_ttl;
    dns_rr_t *vr_answer;
    dns_rr_t *vr_authority;
    dns_rr_t *vr_additional;
    val_astatus_t vr_auth_chain_status;
    struct val_result_chain *vr_auth_chain;
    dns_rr_t *vr_auth_chain_answer;
    dns_rr_t *vr_auth_chain_authority;
    dns_rr_t *vr_auth_chain_additional;
};

Les champs vr_answer, vr_authority, et vr_additional pointent vers les enregistrements RR qui sont retournés. Si plus d'une réponse est retournée, les enregistrements RR sont chaînés via leur champ rr_next. Les structures val_result_chain sont également chaînées via le champ vr_next. La dernière structure val_result_chain dans la chaîne retournera un pointeur NULL dans son champ vr_next.

Les fonctions val_istrusted(), val_isvalidated(), et val_does_not_exist() sont des fonctions utilitaires qui retournent une valeur booléenne indiquant si le statut retourné par la fonction val_resolve_and_check() est celui d'une réponse de confiance, d'une réponse validée, ou d'une réponse inexistante, respectivement.

Les fonctions p_val_status(), p_ac_status(), et p_val_error() sont utilisées pour convertir les valeurs d'état et d'erreur numériques en chaînes de caractères lisibles par l'homme.

La fonction val_log_add_optarg() est utilisée pour contrôler la verbosité et l'emplacement de sortie des messages de journal générés par libval. Les arguments sont une chaîne de caractères de la même forme que ceux utilisés pour contrôler la verbosité de BIND, par exemple "level:file". L'argument use_stderr indique si la sortie doit être envoyée à stderr.

La fonction val_context_setqflags() peut être utilisée pour modifier les indicateurs de requête par défaut pour un contexte donné. Le paramètre action peut être `VAL_SET_FLAGS`, `VAL_CLEAR_FLAGS`, ou `VAL_RESET_FLAGS`.

Les fonctions val_create_context() et val_free_context() sont utilisées pour créer et détruire des contextes de validateur. Le paramètre label peut être utilisé pour identifier un contexte particulier dans les journaux.

La fonction val_free_result_chain() est utilisée pour libérer la mémoire allouée pour une chaîne de résultats.

VALEUR RETOURNÉE

Toutes les fonctions retournent 0 en cas de succès, ou un code d'erreur négatif en cas d'échec. Les codes d'erreur sont définis dans <validator/val_errors.h>.

Le champ gopt pointe vers la structure suivante :

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Définir une valeur de 1 pour local_is_trusted est équivalent à spécifier l'option trust-oob-answers dans le fichier dnsval.conf à yes. De même, définir les membres closest_ta_only et rec_fallback à 1 est équivalent à définir les options closest-ta-only et rec-fallback à yes dans le fichier dnsval.conf. Une valeur de 0 est équivalente au réglage no pour ces options.

Définir le membre edns0_size à une valeur particulière a le même effet que de définir l'option edns0-size dans le fichier dnsval.conf.

Définir le membre max_refresh à une valeur particulière a le même effet que de définir l'option max-refresh dans le fichier dnsval.conf.

Définir le membre proto à une valeur particulière a le même effet que de définir l'option proto dans le fichier dnsval.conf.

env_policy et app_policy peuvent être définis sur l'une des valeurs VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE ou VAL_POL_GOPT_OVERRIDE. Ces valeurs correspondent directement aux options disable, enable et override pour les paramètres env-policy et app-policy dans le fichier dnsval.conf.

Les valeurs de -1 pour les champs ci-dessus sont traitées comme des conditions d'"ignorer" en ce sens que le validateur n'inclura pas les options globales fournies dynamiquement avec une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant les options globales fournies dans le fichier dnsval.conf par défaut.

Le champ log_target permet à l'application de fournir des cibles de journalisation en plus de celles configurées dans le fichier de configuration.

Voir dnsval.conf(3) pour plus de détails sur la manière de spécifier la politique du validateur.

Les drapeaux de requête par défaut peuvent être définis et annulés pour un contexte donné en utilisant val_context_setqflags(). Cela permet à une application de modifier le traitement du validateur DNSSEC, tout en conservant la plupart des configurations par défaut plus granulaires spécifiées dans son fichier de configuration. Le paramètre action peut être défini sur l'une des options suivantes.

VAL_CTX_FLAG_SET
Cette option amène le validateur à définir le drapeau donné comme l'un des drapeaux de requête par défaut.
VAL_CTX_FLAG_RESET
Cette option amène le validateur à réinitialiser le drapeau donné s'il était défini comme l'un des drapeaux de requête par défaut pour le contexte.

Les réponses renvoyées par val_resolve_and_check() sont mises à disposition dans la liste chaînée *results. Chaque réponse correspond à un RRset distinct ; plusieurs RR au sein du RRset font partie de la même réponse. Plusieurs réponses sont possibles lorsque type est ns_t_any ou ns_t_rrsig.

Les éléments individuels dans *results pointent vers des listes chaînées val_authentication_chain. Les éléments de la chaîne d'authentification dans val_authentication_chain contiennent les RRsets réels renvoyés par le serveur de noms en réponse à la requête.

Les valeurs de résultat de validation renvoyées dans val_result_chain peuvent être converties en format ASCII en utilisant p_val_status(). Les valeurs de statut de la chaîne d'authentification renvoyées dans chaque élément de la liste chaînée val_authentication_chain peuvent être converties en format ASCII en utilisant les fonctions p_ac_status().

Bien que certaines applications telles que les utilitaires de dépannage DNSSEC et les outils d'inspection de paquets puissent examiner les éléments individuels de la chaîne d'authentification pour identifier les raisons réelles de l'erreur de validation, la plupart des applications ne seront intéressées que par un seul code d'erreur pour déterminer l'authenticité des données.

val_isvalidated() identifie si une valeur de statut de résultat de validation donnée correspond à une réponse qui a été cryptographiquement vérifiée et validée à l'aide d'une ancre de confiance configurée localement.

val_istrusted() identifie si une valeur de statut de validateur donnée est de confiance. Une réponse peut être localement fiable sans être validée.

val_does_not_exist() identifie si une valeur de statut de validateur donnée correspond à l'un des types de non-existence.

La bibliothèque libval alloue de la mémoire en interne pour *results et celle-ci doit être libérée par l'application appelante en utilisant l'interface free_result_chain().

STRUCTURES DE DONNÉES

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Chaîne d'authentification pour un RRset donné.
val_rc_next
Pointeur vers le RRset suivant dans l'ensemble des réponses renvoyées pour une requête.
val_rc_proofs
Pointeur vers les chaînes d'authentification pour toute preuve de non-existence qui a été renvoyée pour la requête.
val_rc_proof_count
Nombre d'éléments de preuve stockés dans val_rc_proofs. Le nombre ne peut pas dépasser MAX_PROOFS.
val_rc_alias
Pour un élément val_result_chain qui pointe vers un alias de nom, ce champ contient la valeur cible.
val_rc_rrset
Pour un élément val_result_chain contenant un champ val_rc_answer valide (non NULL), le champ val_rc_rrset pointe vers l'élément val_rrset_rec le plus haut dans la chaîne d'authentification val_rc_answer.
val_rc_status
Statut de validation pour un RRset donné. Cela peut être l'un des éléments suivants :
VAL_SUCCESS
Réponse reçue et validée avec succès.
VAL_NONEXISTENT_NAME
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant (plage NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_TYPE
Aucun type n'existait pour le nom et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été validés individuellement.
VAL_NONEXISTENT_NAME_NOCHAIN
Aucun nom n'était présent et une preuve valide de non-existence confirmant le nom manquant a été renvoyée. Les composants de la preuve ont également été identifiés comme dignes de confiance, mais ils n'ont pas été validés individuellement.
VAL_NONEXISTENT_TYPE_NOCHAIN
Aucun type n'existait pour le nom et une preuve valide de non-existence confirmant le nom manquant (plage NSEC ou NSEC3) a été renvoyée. Les composants de la preuve ont également été identifiés comme dignes de confiance, mais ils n'ont pas été validés individuellement.
VAL_PINSECURE
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé.
VAL_PINSECURE_UNTRUSTED
L'enregistrement ou un ancêtre de l'enregistrement dans la chaîne d'authentification vers l'ancre de confiance était connu pour être prouvablement non sécurisé. Mais la condition prouvablement non sécurisée a été configurée comme non digne de confiance.
VAL_BARE_RRSIG
Aucune validation DNSSEC possible, la requête portait sur un RRSIG.
VAL_IGNORE_VALIDATION
La politique locale a été configurée pour ignorer la validation de la zone à partir de laquelle ces données ont été reçues.
VAL_UNTRUSTED_ZONE
La politique locale a été configurée pour rejeter toutes les données reçues de la zone donnée.
VAL_OOB_ANSWER
La réponse a été obtenue par une méthode hors bande (Out Of Band), telle qu'un fichier de configuration local.
VAL_BOGUS
La réponse n'a pas pu être validée en raison d'échecs de vérification de signature ou de l'impossibilité de vérifier les preuves dans la chaîne d'authentification.
VAL_DNS_ERROR
Une erreur s'est produite lors du traitement DNS.
VAL_INDETERMINATE
La réponse n'a pas pu être validée en raison de métadonnées DNSSEC manquantes.
VAL_NOTRUST
Tous les composants disponibles dans la chaîne d'authentification ont été vérifiés correctement, mais aucune ancre de confiance n'était disponible.

Les valeurs d'état de val_status_t retournées par le validateur peuvent être affichées au format ASCII en utilisant p_val_status().

val_ac_status
État de validation de l'élément de la chaîne d'authentification. Ce champ contient le code d'état pour le composant donné dans la chaîne d'authentification. Ce champ peut contenir l'une des valeurs suivantes :
VAL_AC_UNSET
L'état n'a pas pu être déterminé.
VAL_AC_IGNORE_VALIDATION
La validation de l'enregistrement de ressource donné a été ignorée, soit en raison d'une directive de politique locale, soit en raison d'un comportement spécifique au protocole.
VAL_AC_UNTRUSTED_ZONE
La politique locale a défini une zone donnée comme non fiable, sans qu'une validation plus approfondie ne soit jugée nécessaire.
VAL_AC_PINSECURE
La chaîne d'authentification d'une ancre de confiance vers une zone donnée n'a pas pu être construite en raison de l'absence prouvable d'un enregistrement DS pour cette zone dans le parent.
VAL_AC_BARE_RRSIG
La réponse concernait une requête de type RRSIG. Les RRSIG contiennent les signatures cryptographiques d'autres données DNS et ne peuvent pas être validés eux-mêmes.
VAL_AC_NO_LINK
Aucune ancre de confiance n'était configurée pour une chaîne d'authentification donnée ou la chaîne n'était pas reliée.
VAL_AC_TRUST
Au moins une des signatures couvrant l'ensemble d'enregistrements DNSKEY donné a été vérifiée directement à l'aide d'une clé configurée comme ancre de confiance DNSSEC.
VAL_AC_RRSIG_MISSING
Les données RRSIG n'ont pas pu être récupérées pour un enregistrement de ressource.
VAL_AC_DNSKEY_MISSING
La DNSKEY pour un RRSIG couvrant un enregistrement de ressource n'a pas pu être récupérée.
VAL_AC_DS_MISSING
L'enregistrement DS couvrant un enregistrement DNSKEY n'était pas disponible.
VAL_AC_DATA_MISSING
Aucune donnée n'a été retournée pour une requête et le DNS n'a pas indiqué d'erreur.
VAL_AC_DNS_ERROR
Une erreur a été rencontrée lors du traitement DNS.
VAL_AC_NOT_VERIFIED
Tous les RRSIG couvrant l'ensemble d'enregistrements n'ont pas pu être vérifiés.
VAL_AC_VERIFIED
Au moins un RRSIG couvrant un enregistrement de ressource avait un état de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Pointeur vers un ensemble d'enregistrements de type struct val_rrset_rec obtenu à partir de la réponse DNS.
val_ac_trust
Pointeur vers un élément de chaîne d'authentification qui contient soit un ensemble d'enregistrements DNSKEY pouvant être utilisé pour vérifier les RRSIG sur l'enregistrement actuel, soit un ensemble d'enregistrements DS pouvant être utilisé pour construire la chaîne de confiance vers une ancre de confiance.

JOURNALISATION

libval fournit la fonction val_log_add_optarg() pour contrôler la verbosité et l'emplacement de la sortie des messages de journal.

La fonction val_log_add_optarg() prend deux arguments : le premier argument args est une chaîne de caractères qui spécifie l'emplacement et la verbosité. Le second argument, use_stderr, s'il est défini à une valeur supérieure à 0, permet à libval d'envoyer des messages de journal à stderr.

La chaîne de caractères qui spécifie l'emplacement de destination du journal et la verbosité a un format spécifique :

<niveau-débogage>:<type-destination>[:<options-destination>]

où
<niveau-débogage> est 1-7, pour des niveaux de verbosité croissants
<type-destination> est l'un de file, net, syslog, stderr, stdout
<options-destination> dépend de <type-destination>
file:<nom-fichier> (ouvert en mode ajout)
net[:<nom-hôte>:<port-hôte>] (127.0.0.1:1053)
syslog[:facility] (0-23 (par défaut 1 USER))

Les niveaux de journal peuvent être approximativement traduits en différents types de messages de journal comme suit (les messages retournés pour chaque niveau dans cette liste englobent les messages retournés pour le niveau supérieur) :

3 : Error   : erreur rencontrée
4 : Warning : récupération après une erreur
5 : Notice  : donne les résultats finaux de validation pour une requête
              et des détails sur les fichiers de politique et les étiquettes utilisées
6 : Info    : donne des détails
libval(3) - dnssec-tools

NAME

libval - validator library functions

SYNOPSIS

#include <val.h>

int
val_get_default_validator (const char *name, val_validator_t **validator);
int
val_validator_to_string (val_validator_t *validator, char **str);
int
val_validator_destroy (val_validator_t *validator);
int
val_validator_log_level (val_validator_t *validator, int level);
int
val_validator_log_message (val_validator_t *validator, int level, const char *msg);

DESCRIPTION

The validator library provides a mechanism for validating DNSSEC data. The library is intended to be used by other applications that need to perform DNSSEC validation. The library uses a configuration file (see dnsval.conf(5)) to determine how validation should be performed. The library may also read information from resolv.conf(5).

The validator library handles the details of DNSSEC validation. This includes:

Key management
Trust anchor management
Zone validation
Chain of trust validation

The primary entry point for the library is the val_get_default_validator() function. This function returns a handle to a validator context that can be used for subsequent operations.

The validator context can be destroyed using val_validator_destroy().

Logging can be controlled using val_validator_log_level() and messages can be logged using val_validator_log_message().

DATA STRUCTURES

The primary data structure is val_validator_t. This structure holds the context for the validator library, including its configuration and state.

LOGGING

The validator library supports logging at various levels. The following log levels are defined:

0 : None  : No logging
1 : Error : gives error level information
2 : Warning : gives warning level information
3 : Info  : gives informational level messages
4 : Success : gives success level messages
5 : Debug : gives debug level information
6 : Audit : gives audit level messages
7 : Debug : gives debug level information

RETURN VALUES

Return values for various functions are given below. These values can be displayed in ASCII format using the p_val_error() function.

VAL_NO_ERROR
No error was encountered.
VAL_NOT_IMPLEMENTED
Functionality not yet implemented.
VAL_RESOURCE_UNAVAILABLE
Some resource (crypto possibly) was unavailable. Currently not implemented.
VAL_BAD_ARGUMENT
Bad arguments passed as parameters.
VAL_INTERNAL_ERROR
Encountered some internal error.
VAL_NO_PERMISSION
No permission to perform operation. Currently not implemented.
VAL_CONF_PARSE_ERROR
Error in parsing some configuration file.
VAL_CONF_NOT_FOUND
A configuration file was not available.
VAL_NO_POLICY
The policy identifier being referenced was invalid.

FILES

The validator library reads configuration information from two files, resolv.conf and dnsval.conf.

See dnsval.conf(5) for a description of the syntax for these files.
