NOM

libgps - bibliothèque de service C pour communiquer avec le démon GPS

SYNTAXE

C:

#include <gps.h>
int gps_open(char * server, char * port, struct gps_data_t * gpsdata)
int gps_send(struct gps_data_t * gpsdata, char * fmt, ...)
int gps_read(struct gps_data_t * gpsdata, char * message,
             int message_size)
bool gps_waiting(const struct gps_data_t * gpsdata, int timeout)
char * gps_data(const struct gps_data_t * gpsdata)
int gps_unpack(char * buf, struct gps_data_t * gpsdata)
int gps_close(struct gps_data_t * gpsdata)
int gps_stream(struct gps_data_t * gpsdata, unsigned int flags,
               void * data)
int gps_mainloop(struct gps_data_t * gpsdata, int timeout,
                 void (* hook)(struct gps_data_t *gpsdata))
const char * gps_errstr(int err)

Python:

import gps
session = gps.gps(host="localhost", port="2947")
session.stream(flags=gps.WATCH_JSON)
while 0 == session.read():
    process(session)
del session

DESCRIPTION

C

libgps est une bibliothèque de service qui prend en charge la communication avec une instance de gpsd(8), liez-la avec l'option de l'éditeur de liens -lgps. Certains systèmes peuvent également nécessiter -lm.


Attention

Veillez à conditionner votre code sur les symboles de version majeure et mineure de l'API dans gps.h ; idéalement, forcez un échec de compilation si GPSD_API_MAJOR_VERSION n'est pas une version que vous reconnaissez. Consultez le site web du projet GPSD pour plus d'informations sur le protocole et les changements d'API.

Toutes les fonctions décrites ici utilisent la structure gps_data_t. Consultez gps.h pour en savoir plus sur gps_data_t, ses membres de données, ses structures associées et ses horodatages associés. Notez que les informations s'accumuleront dans la structure de session au fil du temps, et le champ 'valid' n'est pas automatiquement mis à zéro par chaque gps_read(). Il appartient au client de mettre ce champ à zéro le cas échéant et de surveiller les horodatages des fixations et des phrases.


Attention

gps_data_t définit des variables à virgule flottante à NaN lorsque la valeur de la variable réelle est inconnue. Vérifiez tous les flottants et doubles avec isfinite() avant de les utiliser. isnan() n'est pas suffisant !

gps_open()

L'appel à gps_open() initialise une structure gps_data_t pour contenir les données collectées par le GPS, et met en place l'accès à gpsd(8) via le socket ou l'exportation de mémoire partagée. L'exportation de mémoire partagée est plus rapide, mais ne transmet pas d'informations sur les événements d'activation et de désactivation de l'appareil et ne vous permettra pas de surveiller le trafic de paquets de l'appareil.

gps_open() renvoie 0 en cas de succès, -1 en cas d'erreurs et est réentrante. errno est défini en fonction de l'erreur renvoyée par l'interface socket ou mémoire partagée ; voir gps.h pour les valeurs et les explications ; voir également gps_errstr(). L'adresse hôte peut être un nom DNS, un quad dotted IPv4, une adresse IPv6, ou la valeur spéciale GPSD_SHARED_MEMORY faisant référence à l'exportation de mémoire partagée ; la bibliothèque fera ce qu'il faut pour chacun d'eux.

gps_close()

gps_close() termine la session et ne doit être appelée qu'après un gps_open() réussi. Elle renvoie 0 en cas de succès, -1 en cas d'erreurs. La fermeture de l'interface de mémoire partagée renvoie toujours 0, tandis qu'une fermeture de socket peut entraîner une erreur. Pour une erreur de fermeture de socket, errno sera défini à partir de l'appel à close() du système.

gps_send()

gps_send() écrit une commande dans le démon gpsd. Elle ne fait rien lors de l'utilisation de l'exportation de mémoire partagée. Le deuxième argument doit être une chaîne de format contenant des éléments de l'ensemble de commandes documenté dans gpsd(8). Il peut avoir des éléments % comme pour sprintf(3), qui seront remplis par des arguments suivants. Cette fonction renvoie -1 s'il y a eu une erreur d'écriture au niveau Unix, sinon 0. Veuillez lire la section LIMITATIONS pour des informations et des précautions supplémentaires. Voir gps_stream() comme alternative possible.

gps_read()

gps_read() accepte une réponse, ou une séquence de réponses, du démon gpsd et décode la réponse dans une gps_data_t. Par défaut, cette fonction effectue une lecture bloquante pour les données provenant du démon gpsd ou une récupération de la mémoire partagée ; elle renvoie le nombre d'octets lus en cas de succès, -1 avec errno défini en cas d'erreur de lecture au niveau Unix, -1 sans errno défini si le socket vers le démon gpsd a été fermé ou si le segment de mémoire partagée était indisponible, et 0 s'il n'y a pas de données disponibles.

Le deuxième argument de gps_read() est généralement NULL, et le troisième argument est zéro. Si votre application souhaite voir les données brutes du démon gpsd, définissez le deuxième argument sur l'adresse de votre tampon de message, et le troisième argument est la taille de votre tampon. À utiliser avec précaution ; cela peut ne pas être une chaîne se terminant par NUL si WATCH_RAW est activé.

gps_waiting()

gps_waiting() peut être utilisée pour vérifier s'il y a de nouvelles données provenant du démon gpsd. Le deuxième argument est le temps maximum d'attente (en microsecondes) avant de retourner. Elle renvoie true s'il y a des données en attente, false en cas de délai d'attente (pas de données en attente) ou de condition d'erreur. Lors de l'utilisation de l'exportation par socket, cette fonction est un wrapper pratique autour d'un appel select(2), et met à zéro errno à l'entrée ; vous pouvez tester errno après la sortie pour obtenir plus d'informations sur les conditions d'erreur.

Attention : sous l'interface de mémoire partagée, il existe une minuscule fenêtre de concurrence entre gps_waiting() et un gps_read() suivant ; dans ce contexte, comme ce dernier ne bloque pas, il est probablement préférable d'écrire une simple boucle de lecture.

gps_mainloop()

gps_mainloop() permet à la fonction de rappel fournie d'être appelée en continu chaque fois qu'il y a des données gpsd. Le deuxième argument est le temps maximum d'attente (en microsecondes) avant de sortir de la boucle (et de renvoyer une valeur de -1). Elle renverra également une valeur négative en cas de diverses erreurs.

gps_unpack()

gps_unpack() analyse le JSON du tampon d'argument dans la cible de l'argument pointeur de la structure de session. Inclus au cas où votre application souhaiterait gérer elle-même les entrées/sorties du socket.

gps_data()

gps_data() renvoie le contenu du tampon de données client (elle renvoie NULL lors de l'utilisation de l'exportation de mémoire partagée). À utiliser avec précaution ; cela peut ne pas être une chaîne se terminant par NUL si WATCH_RAW est activé.

gps_stream()

gps_stream() demande à gpsd de vous transmettre les rapports qu'il a, pour qu'ils soient disponibles lorsque vous interrogez (non disponible lors de l'utilisation de l'exportation de mémoire partagée). Le deuxième argument est un masque de drapeaux qui définit divers bits de politique ; voir la liste ci-dessous. L'appel de gps_stream() plus d'une fois avec des masques de drapeaux différents est autorisé.

WATCH_DEVICE

Restreint la surveillance à un appareil spécifié. Le chemin de l'appareil est donné comme troisième argument (data).

WATCH_DISABLE

Désactive les modes de rapport spécifiés par les autres drapeaux WATCH_.

WATCH_ENABLE

Active les modes de rapport spécifiés par les autres drapeaux WATCH_. C'est la valeur par défaut.

WATCH_JSON

Active le rapport JSON des données. Si WATCH_ENABLE est défini, et qu'aucun autre drapeau WATCH n'est défini, c'est la valeur par défaut.

WATCH_NEWSTYLE

Force l'émission d'une initialisation JSON et l'obtention de réponses de nouveau style. C'est la valeur par défaut.

WATCH_NMEA

Active le rapport pseudo-NMEA généré sur les appareils binaires.

WATCH_OLDSTYLE

Force l'émission d'une commande W ou R et l'obtention de réponses de style ancien. Attention : ce drapeau (et la capacité) sera supprimé dans une future version.

WATCH_RARE

Active le rapport des paquets binaires en hexadécimal encodé.

WATCH_RAW

Active le passage littéral des paquets binaires.

WATCH_SCALED

Lors du rapport de données AIS ou Subframe, met à l'échelle les quantités entières en nombres à virgule flottante si elles ont un diviseur ou une formule de rendu qui leur est associé.

gps_errstr()

gps_errstr() renvoie une chaîne ASCII (en anglais) décrivant l'erreur indiquée par une valeur non nulle renvoyée par gps_op

NAME

libgps - GPSD client library

SYNOPSIS

#include <gps.h>
struct gps_data_t gps_data;
int gps_open(const char *server, const char *port,
    struct gps_data_t *gpsdata);
void gps_close(struct gps_data_t *gpsdata);
int gps_stream(struct gps_data_t *gpsdata, unsigned int flags,
    struct gps_device_t *session);
int gps_read(struct gps_data_t *gpsdata, char **buffer, int timeout);
bool gps_waiting(const struct gps_data_t *gpsdata, int timeout);
int gps_send(struct gps_data_t *gpsdata, const char *command);
int gps_query(struct gps_data_t *gpsdata, const char *command);
void gps_fill_time(struct gps_data_t *gpsdata,
    struct timespec *ts);
void gps_defer_sentence(struct gps_data_t *gpsdata, bool defer);
const char *gps_sentence_type(const char *sentence);
void gps_unjson(const char *json_sentence,
    struct gps_data_t *gpsdata);

DESCRIPTION

The libgps library provides a C interface to the gpsd(8) daemon. It allows client applications to receive data from a GPS receiver managed by gpsd(8).

The library supports C, C++, and Python clients.

C API

The C API is described in the gps(3) man page.

C++ API

The C++ API is provided by the libgpsmm(3) wrapper class. It offers an object-oriented interface to the C library's functionality.

Initialization is done via the gpsmm.Gpsmm() constructor. Data is accessed through the read() method. The session is automatically closed when the object goes out of scope.

Example:

#include <gpsmm.h>
#include <iostream>
int main() {
    gpsmm::Gpsmm gps_engine;
    gps_engine.stream(WATCH_ENABLE | WATCH_JSON);
    for (;;) {
        gps_engine.read();
        if (gps_engine.valid && gps_engine.status != STATUS_NO_FIX) {
            std::cout << "Lat: " << gps_engine.lat()
                      << " Lon: " << gps_engine.lon() << std::endl;
        } else {
            std::cout << "." << std::flush;
        }
    }
    return 0;
}

Python

The Python implementation supports the same facilities as the the C library. gps_open() is replaced by the initialization of a gps session object: session = gps.gps(...). The other calls are methods of that object, and have the same names as the corresponding C functions.

In addition to using gps.read() to read messages from gpsd, you can use the session object as an iterator, as in the code fragment given below. Python iterators implicitly call the function gps.__next__() which is just a shim over gps.read(). There is other advantage to using the implicit iterator and it does not allow the options that gps.read() does.

import gps
session = gps.gps(host="localhost", port="2947")
session.stream(flags=gps.WATCH_JSON)
for report in session:
    process(report)
del session

Resources within the session object will be properly released when it is garbage-collected.

For further information on the Python gps module, read the comments in the modules files. There is a complete Python example in the file www/gpsd-client-example-code.adoc.

ENVIRONMENT VARIABLES

By setting the environment variable GPSD_SHM_KEY, you can control the key value used to create shared-memory segment used for communication with gpsd. This will be useful mainly when isolating test instances of gpsd from production ones.

EXAMPLES

The following is a fully functional minimal C client. Check the C source for the other gpsd clients for more ideas.

// example  gpsd client
// compile this way:
//    gcc example1.c -o example1 -lgps -lm
#include <gps.h>         .. for gps_*()
#include <math.h>        // for isfinite()
#define MODE_STR_NUM 4
static char *mode_str[MODE_STR_NUM] = {
    "n/a",
    "None",
    "2D",
    "3D"
};
int main(int argc, char *argv[])
{
    struct gps_data_t gps_data;
    if (0 != gps_open("localhost", "2947", &gps_data)) {
        printf("Open error.  Bye, bye\n");
        return 1;
    }
    (void)gps_stream(&gps_data, WATCH_ENABLE | WATCH_JSON, NULL);
    while (gps_waiting(&gps_data, 5000000)) {
        if (-1 == gps_read(&gps_data, NULL, 0)) {
            printf("Read error.  Bye, bye\n");
            break;
        }
        if (MODE_SET != (MODE_SET & gps_data.set)) {
            // did not even get mode, nothing to see here
            continue;
        }
        if (0 > gps_data.fix.mode ||
            MODE_STR_NUM <= gps_data.fix.mode) {
            gps_data.fix.mode = 0;
        }
        printf("Fix mode: %s (%d) Time: ",
               mode_str[gps_data.fix.mode],
               gps_data.fix.mode);
        if (TIME_SET == (TIME_SET & gps_data.set)) {
            // not 32 bit safe
            printf("%ld.%09ld ", gps_data.fix.time.tv_sec,
                   gps_data.fix.time.tv_nsec);
        } else {
            puts("n/a ");
        }
        if (isfinite(gps_data.fix.latitude) &&
            isfinite(gps_data.fix.longitude)) {
            // Display data from the GPS receiver if valid.
            printf("Lat %.6f Lon %.6f\n",
                   gps_data.fix.latitude, gps_data.fix.longitude);
        } else {
            printf("Lat n/a Lon n/a\n");
        }
    }
    // When you are done...
    (void)gps_stream(&gps_data, WATCH_DISABLE, NULL);
    (void)gps_close(&gps_data);
    return 0;
}

LIMITATIONS

On some systems (those which do not support implicit linking in libraries) you may need to add -lm to your link line when you link libgps. It is always safe to do this.

In the C API, incautious use of gps_send() may lead to subtle bugs. In order to not bloat struct gps_data_t with space used by responses that are not expected to be shipped in close sequence with each other, the storage for fields associated with certain responses are combined in a union.

The risky set of responses includes VERSION, DEVICELIST, RTCM2, RTCM3, SUBFRAME, AIS, GST, and ERROR; it may not be limited to that set. The logic of the gpsd daemon’s watcher mode is careful to avoid dangerous sequences, but you should read and understand the layout of struct gps_data_t before using gps_send() to request any of these responses.

COMPATIBILITY

The gps_query() supported in major versions 1 and 2 of this library has been removed. With the new streaming-oriented wire protocol behind this library, it is extremely unwise to assume that the first transmission from the gpsd daemon after a command is shipped to it will be the response to command.

If you must send commands to the gpsd daemon explicitly, use gps_send() but beware that this ties your code to the GPSD wire protocol. It is not recommended.

In some versions of the API gps_read() is a blocking call and there was a POLL_NONBLOCK option to make it nonblocking. gps_waiting() was added to reduce the number of wrong ways to code a polling loop.

See the comment above the symbol GPSD_API_MAJOR_VERSION in gps.h for recent changes.
