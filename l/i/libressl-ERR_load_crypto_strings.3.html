libressl-ERR_load_crypto_strings(3)

Paquet: libressl

Licences: ISC, custom:OpenSSL

ERR_LOAD_CRYPTO_STRINGS(3) Manuel des fonctions de bibliothèque ERR_LOAD_CRYPTO_STRINGS(3)

NOM

ERR_load_crypto_strings, ERR_free_strings, SSL_load_error_strings — charger et libérer les chaînes d'erreurs OpenSSL

SYNOPSIS

bibliothèque “libcrypto”
#include <openssl/err.h>

void
ERR_load_crypto_strings(void);

void
ERR_free_strings(void);

bibliothèque “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_load_error_strings(void);

DESCRIPTION

Ces fonctions sont dépréciées. Il n'est jamais utile pour un programme applicatif de les appeler explicitement. La bibliothèque les appelle automatiquement en interne lorsque nécessaire.

ERR_load_crypto_strings() enregistre les chaînes d'erreurs pour toutes les fonctions de crypto(3). SSL_load_error_strings() fait de même, mais enregistre également les chaînes d'erreurs ssl(3).

Si les chaînes d'erreurs ont déjà été chargées auparavant, aucune action n'est effectuée.

ERR_free_strings() libère toutes les chaînes d'erreurs précédemment chargées.

VOIR AUSSI

ERR(3), ERR_error_string(3), OPENSSL_config(3)

HISTORIQUE

ERR_load_crypto_strings() et SSL_load_error_strings() sont apparues pour la première fois dans SSLeay 0.4.4. ERR_free_strings() est apparue pour la première fois dans SSLeay 0.5.1. Ces fonctions sont disponibles depuis OpenBSD 2.4.

BOGUES

Même si les chaînes d'erreurs sont déjà compilées dans le code objet de la bibliothèque sous forme de chaînes statiques, ces fonctions les stockent à nouveau en utilisant de la mémoire allouée dynamiquement sur le tas. Cela peut échouer si la mémoire disponible est insuffisante, mais ces fonctions ne signalent pas de tels échecs. Au lieu de cela, elles échouent silencieusement, possiblement après avoir enregistré aucune ou seulement une partie des chaînes demandées.
