PKCS7_VERIFY(3) Manuel des fonctions de bibliothèque PKCS7_VERIFY(3)

NOM

PKCS7_verify, PKCS7_get0_signers — vérifie une structure signedData PKCS#7

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/pkcs7.h>

int
PKCS7_verify(PKCS7 *p7, STACK_OF(X509) *certs, X509_STORE *store, BIO *indata, BIO *out, int flags);

STACK_OF(X509) *
PKCS7_get0_signers(PKCS7 *p7, STACK_OF(X509) *certs, int flags);

DESCRIPTION

PKCS7_verify() vérifie une structure signedData PKCS#7. p7 est la structure PKCS7 à vérifier. certs est un ensemble de certificats dans lequel rechercher le certificat du signataire. store est un magasin de certificats de confiance (utilisé pour la vérification de chaîne). indata sont les données signées si le contenu n'est pas présent dans p7, c'est-à-dire s'il est détaché. Le contenu est écrit dans out si celui-ci n'est pas NULL.

flags est un ensemble optionnel d'indicateurs, qui peuvent être utilisés pour modifier l'opération de vérification.

PKCS7_get0_signers() récupère les certificats du signataire depuis p7. Les signataires doivent être libérés avec sk_X509_free(). Il ne vérifie pas leur validité ni si les signatures sont valides. Les paramètres certs et flags ont les mêmes significations qu'en PKCS7_verify().

Normalement, le processus de vérification se déroule comme suit.

Initialement, certaines vérifications de cohérence sont effectuées sur p7. Le type de p7 doit être signedData. Il doit y avoir au moins une signature sur les données et si le contenu est détaché, indata ne peut pas être NULL.

Une tentative est faite pour localiser tous les certificats du signataire, en recherchant d'abord dans le paramètre certs (s'il n'est pas NULL) puis en recherchant parmi les certificats contenus dans la structure p7 elle-même. Si les certificats d'un signataire ne peuvent pas être localisés, l'opération échoue.

Chaque certificat de signataire est vérifié en chaîne en utilisant le but smimesign et le magasin de certificats de confiance fourni. Tous les certificats internes dans le message sont utilisés comme AC non fiables. Si une vérification de chaîne échoue, un code d'erreur est retourné.

Enfin, le contenu signé est lu (et écrit dans out s'il n'est pas NULL) et les signatures sont vérifiées.

Si toutes les signatures sont correctement vérifiées, la fonction réussit.

N'importe lequel des indicateurs suivants (combinés par OU logique) peut être passé dans le paramètre flags pour modifier le comportement de vérification par défaut. Seul l'indicateur PKCS7_NOINTERN est significatif pour PKCS7_get0_signers().

Si PKCS7_NOINTERN est défini, les certificats du message lui-même ne sont pas recherchés lors de la localisation du certificat du signataire. Cela signifie que tous les certificats du signataire doivent se trouver dans le paramètre certs.

Si l'indicateur PKCS7_TEXT est défini, les en-têtes MIME pour le type text/plain sont supprimés du contenu. Si le contenu n'est pas du type text/plain, une erreur est retournée.

Si PKCS7_NOVERIFY est défini, les certificats du signataire ne sont pas vérifiés en chaîne.

Si PKCS7_NOCHAIN est défini, alors les certificats contenus dans le message ne sont pas utilisés comme AC non fiables. Cela signifie que toute la chaîne de vérification (à part le certificat du signataire) doit être contenue dans le magasin de confiance.

Si PKCS7_NOSIGS est défini, alors les signatures sur les données ne sont pas vérifiées.

Une application de PKCS7_NOINTERN consiste à accepter uniquement les messages signés par un petit nombre de certificats. Les certificats acceptables seraient passés dans le paramètre certs. Dans ce cas, si le signataire n'est pas l'un des certificats fournis dans certs, la vérification échouera car le signataire ne peut pas être trouvé.

Des précautions doivent être prises lors de la modification du comportement de vérification par défaut, par exemple, définir PKCS7_NOVERIFY | PKCS7_NOSIGS désactivera complètement toute vérification et tout message signé sera considéré comme valide. Cette combinaison est cependant utile si l'on souhaite simplement écrire le contenu dans out et que sa validité n'est pas considérée comme importante.

La vérification de chaîne devrait, selon toute vraisemblance, être effectuée en utilisant l'heure de signature plutôt que l'heure actuelle. Cependant, comme l'heure de signature est fournie par le signataire, elle ne peut pas être fiable sans preuve supplémentaire (telle qu'un horodatage de confiance).

VALEURS DE RETOUR

PKCS7_verify() retourne 1 pour une vérification réussie et 0 ou une valeur négative si une erreur se produit.

PKCS7_get0_signers() retourne tous les signataires ou NULL si une erreur s'est produite. Les signataires doivent être libérés avec sk_X509_free().

L'erreur peut être obtenue à partir de ERR_get_error(3).

VOIR AUSSI

PKCS7_decrypt(3), PKCS7_new(3), PKCS7_sign(3), X509_STORE_new(3)

HISTORIQUE

PKCS7_verify() et PKCS7_get0_signers() sont apparues pour la première fois dans OpenSSL 0.9.5 et sont disponibles depuis OpenBSD 2.7.

BOGUES

Le magasin de certificats de confiance n'est pas recherché pour le certificat du signataire. Ceci est principalement dû aux insuffisances de la fonctionnalité actuelle X509_STORE.

L'absence de traitement en une seule passe et la nécessité de conserver toutes les données en mémoire comme mentionné dans PKCS7_sign(3) s'applique également à PKCS7_verify().

PKCS7_verify

libressl manual

NAME

PKCS7_verify - verify a PKCS7 signed data sequence

SYNOPSIS

#include <openssl/pkcs7.h>

int PKCS7_verify(PKCS7 *p7, X509_STORE *store, X509_CRL *CRL,
                 BIO *data, STACK_OF(X509) *signers, long flags);

DESCRIPTION

The PKCS7_verify function verifies the PKCS#7 signed data structure p7.

The verification process involves checking the signature, the certificate chain, and the CRLs.

If data is not NULL, it is assumed to contain the signed data.

The signers argument, if not NULL, will be populated with the certificates of the signers.

The flags argument can be used to control the verification process. Currently, no flags are defined.

RETURN VALUES

The PKCS7_verify function returns 1 on success, and 0 or a negative value on failure.

SEE ALSO

PKCS7_sign(3)

HISTORY

The PKCS7_verify function first appeared in OpenSSL 0.9.8.

BUGS

No bugs have been reported.

La fonction PKCS7_verify retourne 1 en cas de succès, et 0 ou une valeur négative en cas d'échec.
