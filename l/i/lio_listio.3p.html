LIO_LISTIO(3P) Manuel du programmeur POSIX LIO_LISTIO(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

lio_listio — liste les entrées/sorties dirigées

SYNOPIS

#include <aio.h>
int lio_listio(int mode, struct aiocb *restrict const list[restrict],
    int nent, struct sigevent *restrict sig);

DESCRIPTION

La fonction lio_listio() initie une liste de requêtes d'E/S avec un seul appel de fonction.

L'argument mode prend l'une des valeurs LIO_WAIT ou LIO_NOWAIT déclarées dans <aio.h> et détermine si la fonction retourne lorsque les opérations d'E/S sont terminées, ou dès que les opérations ont été mises en file d'attente. Si l'argument mode est LIO_WAIT, la fonction attend la fin de toutes les E/S et l'argument sig est ignoré.

Si l'argument mode est LIO_NOWAIT, la fonction retourne immédiatement, et une notification asynchrone se produit, conformément à l'argument sig, lorsque toutes les opérations d'E/S sont terminées. Si sig est NULL, aucune notification asynchrone ne se produit. Si sig n'est pas NULL, la notification asynchrone se produit comme spécifié dans la Section 2.4.1, Génération et Livraison des Signaux, lorsque toutes les requêtes dans list sont terminées.

Les requêtes d'E/S énumérées par list sont soumises dans un ordre non spécifié.

L'argument list est un tableau de pointeurs vers des structures aiocb. Le tableau contient nent éléments. Le tableau peut contenir des éléments NULL, qui sont ignorés.

Si le tampon pointé par list ou les structures aiocb pointées par les éléments du tableau list deviennent des adresses illégales avant que toutes les E/S asynchrones ne soient terminées et, si nécessaire, que la notification ne soit envoyée, alors le comportement est indéfini. Si les tampons pointés par le membre aio_buf de la structure aiocb pointée par les éléments du tableau list deviennent des adresses illégales avant que les E/S asynchrones associées à cette structure aiocb ne soient terminées, le comportement est indéfini.

Le champ aio_lio_opcode de chaque structure aiocb spécifie l'opération à effectuer. Les opérations prises en charge sont LIO_READ, LIO_WRITE et LIO_NOP ; ces symboles sont définis dans <aio.h>. L'opération LIO_NOP fait ignorer l'entrée de la liste. Si l'élément aio_lio_opcode est égal à LIO_READ, une opération d'E/S est soumise comme si elle était appelée par aio_read() avec aiocbp égal à l'adresse de la structure aiocb. Si l'élément aio_lio_opcode est égal à LIO_WRITE, une opération d'E/S est soumise comme si elle était appelée par aio_write() avec aiocbp égal à l'adresse de la structure aiocb.

Le membre aio_fildes spécifie le descripteur de fichier sur lequel l'opération doit être effectuée.

Le membre aio_buf spécifie l'adresse du tampon vers ou depuis lequel les données sont transférées.

Le membre aio_nbytes spécifie le nombre d'octets de données à transférer.

Les membres de la structure aiocb décrivent plus en détail l'opération d'E/S à effectuer, d'une manière identique à celle de la structure aiocb correspondante lorsqu'elle est utilisée par les fonctions aio_read() et aio_write().

L'argument nent spécifie le nombre d'éléments constituant la liste ; c'est-à-dire la longueur du tableau.

Le comportement de cette fonction est modifié conformément aux définitions de la fin de l'intégrité des données des E/S synchronisées et de la fin de l'intégrité des fichiers des E/S synchronisées si les E/S synchronisées sont activées sur le fichier associé à aio_fildes.

Pour les fichiers réguliers, aucun transfert de données ne doit avoir lieu au-delà du décalage maximum établi dans la description de fichier ouvert associée à aiocbp->aio_fildes.

Si sig->sigev_notify est SIGEV_THREAD et sig->sigev_notify_attributes est un pointeur non nul et que le bloc pointé par ce pointeur devient une adresse illégale avant que toutes les E/S asynchrones ne soient terminées, alors le comportement est indéfini.

VALEUR RENVOYÉE

Si l'argument mode a la valeur LIO_NOWAIT, la fonction lio_listio() renvoie la valeur zéro si les opérations d'E/S sont mises en file d'attente avec succès ; sinon, la fonction renvoie la valeur -1 et définit errno pour indiquer l'erreur.

Si l'argument mode a la valeur LIO_WAIT, la fonction lio_listio() renvoie la valeur zéro lorsque toutes les E/S indiquées sont terminées avec succès. Sinon, lio_listio() renvoie la valeur -1 et définit errno pour indiquer l'erreur.

Dans les deux cas, la valeur renvoyée n'indique que le succès ou l'échec de l'appel lio_listio() lui-même, et non l'état des requêtes d'E/S individuelles. Dans certains cas, une ou plusieurs des requêtes d'E/S contenues dans la liste peuvent échouer. L'échec d'une requête individuelle n'empêche pas l'achèvement de toute autre requête individuelle. Pour déterminer le résultat de chaque requête d'E/S, l'application doit examiner le statut d'erreur associé à chaque bloc de contrôle aiocb. Les statuts d'erreur ainsi renvoyés sont identiques à ceux renvoyés par une fonction aio_read() ou aio_write().

ERREURS

La fonction lio_listio() échoue si :

EAGAIN
Les ressources nécessaires pour mettre en file d'attente toutes les requêtes d'E/S n'étaient pas disponibles. L'application peut vérifier le statut d'erreur de chaque aiocb pour déterminer la ou les requêtes individuelles qui ont échoué.
EAGAIN
Le nombre d'entrées indiqué par nent dépasserait la limite système {AIO_MAX}.
EINVAL
L'argument mode n'est pas une valeur valide, ou la valeur de nent était supérieure à {AIO_LISTIO_MAX}.
EINTR
Un signal a été délivré en attendant la fin de toutes les requêtes d'E/S pendant une opération LIO_WAIT. Notez que, puisque chaque opération d'E/S invoquée par lio_listio() peut éventuellement déclencher un signal lors de son achèvement, ce retour d'erreur peut être causé par l'achèvement d'une (ou plusieurs) des opérations d'E/S en attente. Les opérations d'E/S en suspens ne sont pas annulées, et l'application doit examiner chaque élément de la liste pour déterminer si la requête a été initiée, annulée ou achevée.
EIO
Une ou plusieurs des opérations d'E/S individuelles ont échoué. L'application peut vérifier le statut d'erreur de chaque structure aiocb pour déterminer la ou les requêtes individuelles qui ont échoué.

En plus des erreurs renvoyées par la fonction lio_listio(), si la fonction lio_listio() réussit ou échoue avec des erreurs de [EAGAIN], [EINTR], ou [EIO], alors certaines des E/S spécifiées par la liste peuvent avoir été initiées. Si la fonction lio_listio() échoue avec un code d'erreur autre que [EAGAIN], [EINTR], ou [EIO], aucune opération de la liste n'aura été initiée. L'opération d'E/S indiquée par chaque élément de la liste peut rencontrer des erreurs spécifiques à la fonction de lecture ou d'écriture individuelle effectuée. Dans ce cas, le statut d'erreur de chaque bloc de contrôle aiocb contient le code d'erreur associé. Les codes d'erreur qui peuvent être définis sont les mêmes que ceux qui seraient définis par une fonction read() ou write(), avec les codes d'erreur supplémentaires suivants possibles :

EAGAIN
L'opération d'E/S demandée n'a pas été mise en file d'attente en raison de limitations de ressources.
ECANCELED
L'E/S demandée a été annulée avant la fin de l'E/S en raison d'une demande explicite aio_cancel().
EFBIG
Le aiocbp->aio_lio_opcode est LIO_WRITE, le fichier est un fichier régulier, aiocbp->aio_nbytes est supérieur à 0, et le aiocbp->aio_offset est

EINPROGRESS
L'opération d'E/S demandée est en cours.
EOVERFLOW

RATIONALE

Bien qu'il puisse sembler y avoir des incohérences dans les circonstances spécifiées pour les codes d'erreur, la condition d'erreur [EIO] s'applique lorsque toute circonstance relative à une opération individuelle rend cette opération défaillante. Cela peut être dû à une requête mal formulée (par exemple, le champ aio_lio_opcode est invalide, et aio_error() renvoie [EINVAL]) ou peut découler du comportement de l'application (par exemple, le descripteur de fichier est fermé avant que l'opération ne soit initiée, et aio_error() renvoie [EBADF]).

La limitation de l'ensemble des codes d'erreur renvoyés lorsque les opérations de la liste ont été initiées permet aux applications de savoir quand les opérations ont été démarrées et si aio_error() est valide pour une opération spécifique.
