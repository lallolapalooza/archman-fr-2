EVP_SEALINIT(3) Manuel de la bibliothèque EVP_SEALINIT(3)

NOM

EVP_SealInit, EVP_SealUpdate, EVP_SealFinal — Chiffrement d'enveloppe EVP

SYNTAXE

bibliothèque “libcrypto”
#include <openssl/evp.h>

int
EVP_SealInit(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *type, unsigned char **ek, int *ekl, unsigned char *iv, EVP_PKEY **pubk, int npubk);

int
EVP_SealUpdate(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl, unsigned char *in, int inl);

int
EVP_SealFinal(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl);

DESCRIPTION

Les routines d'enveloppe EVP sont une interface de haut niveau pour le chiffrement d'enveloppe. Elles génèrent une clé et un vecteur d'initialisation (IV) aléatoires, puis les "enveloppent" en utilisant le chiffrement à clé publique. Les données peuvent ensuite être chiffrées à l'aide de cette clé.

EVP_SealInit() initialise un contexte de chiffrement ctx pour le chiffrement avec le chiffrement type en utilisant une clé secrète et un IV aléatoires. type est normalement fourni par une fonction telle que EVP_aes_256_cbc(3) ; voir EVP_EncryptInit(3) pour plus de détails. La clé secrète est chiffrée à l'aide d'une ou plusieurs clés publiques. Cela permet de déchiffrer les mêmes données chiffrées à l'aide de n'importe laquelle des clés privées correspondantes. ek est un tableau de tampons où la clé secrète chiffrée par clé publique sera écrite. Chaque tampon doit contenir suffisamment d'espace pour la clé secrète chiffrée correspondante : c'est-à-dire que ek[i] doit avoir de la place pour EVP_PKEY_size(pubk[i]) octets. La taille réelle de chaque clé secrète chiffrée est écrite dans le tableau ekl. pubk est un tableau de npubk clés publiques.

Le paramètre iv est un tampon où l'IV généré est écrit. Il doit contenir suffisamment d'espace pour l'IV du chiffrement correspondant, tel que déterminé par (par exemple) EVP_CIPHER_iv_length(type).

Si le chiffrement ne nécessite pas d'IV, le paramètre iv est ignoré et peut être NULL.

EVP_SealUpdate() et EVP_SealFinal() ont exactement les mêmes propriétés que les routines EVP_EncryptUpdate(3) et EVP_EncryptFinal(3).

La clé publique doit être RSA car c'est le seul algorithme de clé publique OpenSSL qui prend en charge le transport de clés.

Le chiffrement d'enveloppe est la méthode habituelle d'utilisation du chiffrement à clé publique sur de grandes quantités de données. En effet, le chiffrement à clé publique est lent mais le chiffrement symétrique est rapide. Ainsi, le chiffrement symétrique est utilisé pour le chiffrement en bloc et la petite clé symétrique aléatoire utilisée est transférée à l'aide du chiffrement à clé publique.

Il est possible d'appeler EVP_SealInit() deux fois de la même manière que EVP_EncryptInit(3). Le premier appel doit avoir npubk défini sur 0 et (après la définition de tout paramètre de chiffrement) il doit être appelé à nouveau avec type défini sur NULL.

EVP_SealUpdate() est implémenté comme une macro.

VALEURS DE RETOUR

EVP_SealInit() retourne 0 en cas d'erreur ou npubk en cas de succès.

EVP_SealUpdate() et EVP_SealFinal() retournent 1 en cas de succès et 0 en cas d'échec.

VOIR AUSSI

evp(3), EVP_EncryptInit(3), EVP_OpenInit(3)

HISTORIQUE

EVP_SealInit(), EVP_SealUpdate(), et EVP_SealFinal() sont apparus pour la première fois dans SSLeay 0.5.1 et sont disponibles depuis OpenBSD 2.4.

EVP_SealFinal() ne retournait pas de valeur avant OpenSSL 0.9.7.
