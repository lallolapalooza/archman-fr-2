lwpcook(3) Documentation Perl fournie par l'utilisateur lwpcook(3)

NOM

lwpcook - Le livre de recettes libwww-perl

DESCRIPTION

Ce document contient quelques exemples qui montrent l'utilisation typique de la bibliothèque libwww-perl. Vous devriez consulter la documentation des modules individuels pour plus de détails.

Tous les exemples devraient être des programmes exécutables. Vous pouvez, dans la plupart des cas, tester les sections de code en envoyant le texte du programme directement à perl.

GET

Il est très facile d'utiliser cette bibliothèque pour simplement récupérer des documents sur le net. Le module LWP::Simple fournit la fonction get() qui renvoie le document spécifié par son argument URL :

use LWP::Simple;
$doc = get 'http://search.cpan.org/dist/libwww-perl/';

Ou, en une seule ligne de commande perl en utilisant la fonction getprint() :

perl -MLWP::Simple -e 'getprint "http://search.cpan.org/dist/libwww-perl/"'

Ou, que diriez-vous de récupérer le dernier perl en exécutant cette commande :

perl -MLWP::Simple -e '
  getstore "ftp://ftp.sunet.se/pub/lang/perl/CPAN/src/latest.tar.gz",
           "perl.tar.gz"'

Vous voudrez probablement d'abord trouver un site CPAN plus proche de chez vous en exécutant quelque chose comme la commande suivante :

perl -MLWP::Simple -e 'getprint "http://www.cpan.org/SITES.html"'

Assez de ces choses simples ! L'interface orientée objet de LWP vous donne plus de contrôle sur la requête envoyée au serveur. En utilisant cette interface, vous avez un contrôle total sur les en-têtes envoyés et sur la manière dont vous souhaitez gérer la réponse retournée.

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
$ua->agent("$0/0.1 " . $ua->agent);
# $ua->agent("Mozilla/8.0") # faire semblant d'être un navigateur très performant
$req = HTTP::Request->new(
   GET => 'http://search.cpan.org/dist/libwww-perl/');
$req->header('Accept' => 'text/html');
# envoyer la requête
$res = $ua->request($req);
# vérifier le résultat
if ($res->is_success) {
   print $res->decoded_content;
}
else {
   print "Erreur : " . $res->status_line . "\n";
}

Le programme lwp-request (alias GET) distribué avec la bibliothèque peut également être utilisé pour récupérer des documents des serveurs WWW.

HEAD

Si vous voulez juste vérifier si un document est présent (c'est-à-dire si l'URL est valide), essayez d'exécuter un code qui ressemble à ceci :

use LWP::Simple;
if (head($url)) {
   # ok, le document existe
}

La fonction head() renvoie en réalité une liste de méta-informations sur le document. Les trois premières valeurs de la liste retournée sont le type de document, la taille du document et l'âge du document.

Un contrôle plus poussé de la requête ou l'accès à toutes les valeurs d'en-tête retournées nécessite d'utiliser l'interface orientée objet décrite pour GET ci-dessus. Remplacez simplement GET par HEAD.

POST

Il n'y a pas d'interface procédurale simple pour envoyer des données à un serveur WWW. Vous devez utiliser l'interface orientée objet pour cela. L'opération POST la plus courante consiste à accéder à une application de formulaire WWW :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
my $req = HTTP::Request->new(
    POST => 'https://rt.cpan.org/Public/Dist/Display.html');
$req->content_type('application/x-www-form-urlencoded');
$req->content('Status=Active&Name=libwww-perl');
my $res = $ua->request($req);
print $res->as_string;

Les personnes paresseuses utilisent le module HTTP::Request::Common pour configurer un message de requête POST approprié (il gère toutes les questions d'échappement) et a une valeur par défaut appropriée pour le content_type :

use HTTP::Request::Common qw(POST);
use LWP::UserAgent;
$ua = LWP::UserAgent->new;
my $req = POST 'https://rt.cpan.org/Public/Dist/Display.html',
              [ Status => 'Active', Name => 'libwww-perl' ];
print $ua->request($req)->as_string;

Le programme lwp-request (alias POST) distribué avec la bibliothèque peut également être utilisé pour envoyer des données.

PROXIES

Certains sites utilisent des proxys pour traverser les pare-feu, ou simplement comme cache afin d'améliorer les performances. Les proxys peuvent également être utilisés pour accéder à des ressources via des protocoles non pris en charge directement (ou mal pris en charge :-) par la bibliothèque libwww-perl.

Vous devriez initialiser vos paramètres de proxy avant de commencer à envoyer des requêtes :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
$ua->env_proxy; # initialiser à partir des variables d'environnement
# ou
$ua->proxy(ftp  => 'http://proxy.myorg.com');
$ua->proxy(wais => 'http://proxy.myorg.com');
$ua->no_proxy(qw(no se fi));
my $req = HTTP::Request->new(GET => 'wais://xxx.com/');
print $ua->request($req)->as_string;

L'interface LWP::Simple appellera env_proxy() automatiquement pour vous. Les applications qui utilisent la méthode $ua->env_proxy() n'utiliseront normalement pas les méthodes $ua->proxy() et $ua->no_proxy().

Certains proxys exigent également que vous leur envoyiez un nom d'utilisateur/mot de passe afin de laisser passer les requêtes. Vous devriez pouvoir ajouter l'en-tête requis, avec quelque chose comme ceci :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
$ua->proxy(['http', 'ftp'] => 'http://username:password@proxy.myorg.com');
$req = HTTP::Request->new('GET',"http://www.perl.com");
$res = $ua->request($req);
print $res->decoded_content if $res->is_success;

Remplacez "proxy.myorg.com", "username" et "password" par quelque chose qui convient à votre site.

ACCÈS AUX DOCUMENTS PROTÉGÉS

Les documents protégés par authentification basique peuvent être facilement accessibles comme ceci :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
$req = HTTP::Request->new(GET => 'http://www.linpro.no/secret/');
$req->authorization_basic('aas', 'mypassword');
print $ua->request($req)->as_string;

L'autre alternative est de fournir une sous-classe de LWP::UserAgent qui surcharge la méthode get_basic_credentials(). Étudiez le programme lwp-request pour un exemple de ceci.

COOKIES

Certains sites aiment jouer avec les cookies. Par défaut, LWP ignore les cookies fournis par les serveurs qu'il visite. LWP collectera les cookies et répondra aux requêtes de cookies si vous configurez un pot de cookies. LWP ne fournit pas de pot de cookies en soi, mais si vous installez HTTP::CookieJar::LWP, il peut être utilisé comme ceci :

use LWP::UserAgent;
use HTTP::CookieJar::LWP;
$ua = LWP::UserAgent->new(
    cookie_jar => HTTP::CookieJar::LWP->new,
);
# puis envoyez des requêtes comme vous le faisiez auparavant
$res = $ua->request(HTTP::Request->new(GET => "http://no.yahoo.com/"));
print $res->status_line, "\n";

HTTPS

Les URL avec le schéma https sont accessibles exactement de la même manière qu'avec le schéma http, à condition qu'un module d'interface SSL pour LWP ait été correctement installé (voir le fichier README.SSL trouvé dans la distribution libwww-perl pour plus de détails). Si aucune interface SSL n'est installée pour LWP, vous obtiendrez des erreurs "501 Protocol scheme 'https' is not supported" lors de l'accès à de telles URL.

Voici un exemple de récupération et d'impression d'une page WWW en utilisant SSL :

use LWP::UserAgent;
my $ua = LWP::UserAgent->new;
my $req = HTTP::Request->new(GET => 'https://www.helsinki.fi/');
my $res = $ua->request($req);
if ($res->is_success) {
    print $res->as_string;
}
else {
    print "Échec : ", $res->status_line, "\n";
}

MISE EN MIROIR

Si vous souhaitez mettre en miroir des documents d'un serveur WWW, essayez d'exécuter un code similaire à ceci à intervalles réguliers :

use LWP::Simple;
%mirrors = (
   'http://www.sn.no/'                       => 'sn.html',
   'http://www.perl.com/'                    => 'perl.html',
   'http://search.cpan.org/distlibwww-perl/' => 'lwp.html',
   'gopher://gopher.sn.no/'                  => 'gopher.html',
);
while (($url, $localfile) = each(%mirrors)) {
   mirror($url, $localfile);
}

Ou, en une seule ligne de commande perl :

perl -MLWP::Simple -e 'mirror("http://www.perl.com/", "perl.html")';

Le document ne sera pas transféré à moins qu'il n'ait été mis à jour.

Si le document que vous souhaitez récupérer est trop volumineux pour tenir en mémoire, vous avez deux alternatives. Vous pouvez demander à la bibliothèque d'écrire le contenu du document dans un fichier (deuxième argument de $ua->request() est un nom de fichier) :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
my $req = HTTP::Request->new(GET =>
    'http://www.cpan.org/CPAN/authors/id/O/OA/OALDERS/libwww-perl-6.26.tar.gz');
$res = $ua->request($req, "libwww-perl.tar.gz");
if ($res->is_success) {
   print "ok\n";
}
else {
   print $res->status_line, "\n";
}

Ou vous pouvez traiter le document au fur et à mesure de son arrivée (deuxième argument de $ua->request() est une référence de code) :

use LWP::UserAgent;
$ua = LWP::UserAgent->new;
$URL = 'ftp://ftp.isc.org/pub/rfc/rfc-index.txt';
my $expected_length;
my $bytes_received = 0;
my $res =
   $ua->request(HTTP::Request->new(GET => $URL),
             sub {
                 my($chunk, $res) = @_;
                 $bytes_received += length($chunk);
                 unless (defined $expected_length) {
                    $expected_length = $res->content_length || 0;
                 }
                 if ($expected_length) {
                      printf STDERR "%d%% - ",
                                100 * $bytes_received / $expected_length;
                 }
                 print STDERR "$bytes_received octets reçus\n";
                 # XXX Il faudrait vraiment faire quelque chose avec le chunk lui-même
                 # print $chunk;
             });
 print $res->status_line, "\n";
