lseek(2) Manuel des appels système lseek(2)

NOM

lseek - repositionner le pointeur de lecture/écriture de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);

DESCRIPTION

lseek() repositionne le décalage de fichier de la description de fichier ouverte associée au descripteur de fichier fd à l'argument offset, selon la directive whence comme suit :

SEEK_SET
Le décalage de fichier est réglé à offset octets.
SEEK_CUR
Le décalage de fichier est réglé à sa position actuelle plus offset octets.
SEEK_END
Le décalage de fichier est réglé à la taille du fichier plus offset octets.

lseek() permet de définir le décalage de fichier au-delà de la fin du fichier (mais cela ne modifie pas la taille du fichier). Si des données sont ultérieurement écrites à cet endroit, les lectures ultérieures des données dans l'espace (un "trou") retournent des octets nuls ('\0') jusqu'à ce que des données soient effectivement écrites dans l'espace.

Recherche de données et de trous de fichier

Depuis Linux 3.1, Linux prend en charge les valeurs supplémentaires suivantes pour whence :

SEEK_DATA
Ajuste le décalage de fichier à l'emplacement suivant dans le fichier, supérieur ou égal à offset, contenant des données. Si offset pointe vers des données, le décalage de fichier est réglé à offset.
SEEK_HOLE
Ajuste le décalage de fichier au trou suivant dans le fichier, supérieur ou égal à offset. Si offset pointe au milieu d'un trou, le décalage de fichier est réglé à offset. S'il n'y a pas de trou après offset, le décalage de fichier est ajusté à la fin du fichier (c'est-à-dire qu'il y a un trou implicite à la fin de tout fichier).

Dans les deux cas ci-dessus, lseek() échoue si offset pointe au-delà de la fin du fichier.

Ces opérations permettent aux applications de mapper les trous dans un fichier alloué de manière éparse. Cela peut être utile pour les applications telles que les outils de sauvegarde de fichiers, qui peuvent économiser de l'espace lors de la création de sauvegardes et préserver les trous, si elles ont un mécanisme pour découvrir les trous.

Aux fins de ces opérations, un trou est une séquence de zéros qui n'a (normalement) pas été allouée dans le stockage de fichier sous-jacent. Cependant, un système de fichiers n'est pas obligé de signaler les trous, donc ces opérations ne sont pas un mécanisme garanti pour mapper l'espace de stockage réellement alloué à un fichier. (De plus, une séquence de zéros qui a effectivement été écrite dans le stockage sous-jacent peut ne pas être signalée comme un trou.) Dans l'implémentation la plus simple, un système de fichiers peut prendre en charge les opérations en faisant toujours retourner SEEK_HOLE l'offset de la fin du fichier, et en faisant retourner SEEK_DATA offset (c'est-à-dire, même si l'emplacement référencé par offset est un trou, il peut être considéré comme composé de données qui sont une séquence de zéros).

La macro de test de fonctionnalité _GNU_SOURCE doit être définie pour obtenir les définitions de SEEK_DATA et SEEK_HOLE à partir de <unistd.h>.

Les opérations SEEK_HOLE et SEEK_DATA sont prises en charge pour les systèmes de fichiers suivants :

•
Btrfs (depuis Linux 3.1)
•
OCFS (depuis Linux 3.2)
•
XFS (depuis Linux 3.5)
•
ext4 (depuis Linux 3.8)
•
tmpfs(5) (depuis Linux 3.8)
•
NFS (depuis Linux 3.18)
•
FUSE (depuis Linux 4.5)
•
GFS2 (depuis Linux 4.15)

VALEUR DE RETOUR

En cas de succès, lseek() retourne la position de décalage résultante mesurée en octets depuis le début du fichier. En cas d'erreur, la valeur (off_t) -1 est retournée et errno est définie pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier ouvert.
EINVAL
whence n'est pas valide. Ou : le décalage de fichier résultant serait négatif, ou au-delà de la fin d'un périphérique cherchable.
ENXIO
whence est SEEK_DATA ou SEEK_HOLE, et offset est au-delà de la fin du fichier, ou whence est SEEK_DATA et offset est à l'intérieur d'un trou à la fin du fichier.
EOVERFLOW
Le décalage de fichier résultant ne peut pas être représenté dans un off_t.
ESPIPE
fd est associé à un pipe, un socket ou un FIFO.

VERSIONS

Sur Linux, l'utilisation de lseek() sur un périphérique terminal échoue avec l'erreur ESPIPE.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.3BSD.

SEEK_DATA
SEEK_HOLE
POSIX.1-2024 ; Solaris, FreeBSD, DragonFly BSD.

NOTES

Voir open(2) pour une discussion sur la relation entre les descripteurs de fichiers, les descriptions de fichiers ouverts et les fichiers.

Si l'indicateur de statut de fichier O_APPEND est défini sur la description de fichier ouverte, alors une opération write(2) déplace *toujours* le décalage de fichier vers la fin du fichier, quel que soit l'usage de lseek().

Certains périphériques sont incapables de rechercher et POSIX ne spécifie pas quels périphériques doivent prendre en charge lseek().
