NOM

lsof - lister les fichiers ouverts

SYNTAXE

lsof [ -?abChHlnNOPQRtUvVX ] [ -A A ] [ -c c ] [ +c c ] [ +|-d d ] [ +|-D D ] [ +|-e s ] [ +|-E ] [ +|-f [cfgGn] ] [ -F [f] ] [ -g [s] ] [ -i [i] ] [ -k k ] [ -K k ] [ +|-L [l] ] [ +|-m m ] [ +|-M ] [ -o [o] ] [ -p s ] [ +|-r [t[m<fmt>]] ] [ -s [p:s] ] [ -S [t] ] [ -T [t] ] [ -u s ] [ +|-w ] [ -x [fl] ] [ -z [z] ] [ -Z [Z] ] [ -- ] [noms]

DESCRIPTION

Lsof, révision 4.99.5, liste sur sa sortie standard les informations sur les fichiers ouverts par les processus pour les dialectes UNIX suivants :

Apple Darwin 9, Mac OS X 10, macOS 11 et versions ultérieures
FreeBSD 8.2 et versions ultérieures
Linux 2.1.72 et versions ultérieures
NetBSD 1.2 et versions ultérieures
OpenBSD 7.2 et versions ultérieures
Solaris 9, 10 et 11 et versions ultérieures
OpenIndiana 5.11 et versions ultérieures

(Voir la section DISTRIBUTION de cette page de manuel pour des informations sur la façon d'obtenir la dernière révision de lsof.)

Un fichier ouvert peut être un fichier régulier, un répertoire, un fichier spécial de bloc, un fichier spécial de caractère, une référence d'exécution de texte, une bibliothèque, un flux ou un fichier réseau (socket Internet, fichier NFS ou socket de domaine UNIX). Un fichier spécifique ou tous les fichiers d'un système de fichiers peuvent être sélectionnés par chemin.

Au lieu d'un affichage formaté, lsof produira une sortie qui peut être analysée par d'autres programmes. Voir la description de l'option -F et la section SORTIE POUR D'AUTRES PROGRAMMES pour plus d'informations.

En plus de produire une liste de sortie unique, lsof fonctionnera en mode répétition. En mode répétition, il produira une sortie, attendra, puis répètera l'opération de sortie jusqu'à ce qu'il soit arrêté par un signal d'interruption ou de quit. Voir la description de l'option +|-r [t[m<fmt>]] pour plus d'informations.

OPTIONS

En l'absence de toute option, lsof liste tous les fichiers ouverts appartenant à tous les processus actifs.

Si une option de demande de liste est spécifiée, d'autres demandes de liste doivent être spécifiquement demandées - par exemple, si -U est spécifié pour la liste des fichiers de socket UNIX, les fichiers NFS ne seront pas listés sauf si -N est également spécifié ; ou si une liste d'utilisateurs est spécifiée avec l'option -u, les fichiers de socket de domaine UNIX, appartenant à des utilisateurs qui ne sont pas dans la liste, ne seront pas listés sauf si l'option -U est également spécifiée.

Normalement, les options de liste qui sont spécifiquement déclarées sont combinées par OU - c'est-à-dire, spécifier l'option -i sans adresse et l'option -ufoo produit une liste de tous les fichiers réseau OU des fichiers appartenant à des processus possédés par l'utilisateur ``foo''. Les exceptions sont :

1)
le nom de connexion ou l'ID utilisateur (UID) `^' (négativé), spécifié avec l'option -u ;
2)
l'ID de processus (PID) `^' (négativé), spécifié avec l'option -p ;
3)
l'ID de groupe de processus (PGID) `^' (négativé), spécifié avec l'option -g ;
4)
la commande `^' (négativée), spécifiée avec l'option -c ;
5)
les noms d'état de protocole TCP ou UDP (`^') négativés, spécifiés avec l'option -s [p:s].

Puisqu'ils représentent des exclusions, ils sont appliqués sans OU ou ET et prennent effet avant que tout autre critère de sélection ne soit appliqué.

L'option -a peut être utilisée pour combiner les sélections par ET. Par exemple, spécifier -a, -U, et -ufoo produit une liste de fichiers de socket UNIX uniquement qui appartiennent à des processus possédés par l'utilisateur ``foo''.

Attention : l'option -a fait que toutes les options de sélection de liste sont combinées par ET ; elle ne peut pas être utilisée pour combiner par ET des paires sélectionnées d'options de sélection en la plaçant entre elles, même si son placement y est acceptable. Où que -a soit placé, elle entraîne la combinaison par ET de toutes les options de sélection.

Les éléments du même ensemble de sélection - noms de commande, descripteurs de fichiers, adresses réseau, identifiants de processus, identifiants d'utilisateur, noms de zone, contextes de sécurité - sont joints dans un seul ensemble combiné par OU et appliqués avant que le résultat ne participe à la combinaison par ET. Ainsi, par exemple, spécifier -i@aaa.bbb, -i@ccc.ddd, -a, et -ufff,ggg sélectionnera la liste des fichiers qui appartiennent soit à la connexion ``fff'' OU ``ggg'' ET ont des connexions réseau soit à l'hôte aaa.bbb OU ccc.ddd.

Les options peuvent être groupées ensemble après un seul préfixe - par exemple, l'ensemble d'options ``-a -b -C'' peut être indiqué comme -abC. Cependant, étant donné que les valeurs sont facultatives après +|-f, -F, -g, -i, +|-L, -o, +|-r, -s, -S, -T, -x et -z. lorsque vous n'avez pas de valeurs pour eux, soyez prudent car le caractère suivant n'est pas ambigu. Par exemple, -Fn pourrait représenter les options -F et -n, ou il pourrait représenter le caractère d'identifiant de champ n suivant l'option -F. Lorsqu'une ambiguïté est possible, commencez une nouvelle option avec un caractère `-` - par exemple, ``-F -n''. Si l'option suivante est un nom de fichier, suivez l'option potentiellement ambiguë avec ``--'' - par exemple, ``-F -- nom''.

Soit le préfixe `+' soit le préfixe `-' peut être appliqué à un groupe d'options. Les options qui n'ont pas de significations distinctes pour chaque préfixe - par exemple, -i - peuvent être groupées sous l'un ou l'autre préfixe. Ainsi, par exemple, ``+M -i'' peut être indiqué comme ``+Mi'' et le groupe signifie la même chose que les options séparées. Faites attention au groupement de préfixes lorsqu'une ou plusieurs options du groupe ont des significations distinctes sous des préfixes différents - par exemple, +|-M ; ``-iM'' n'est pas la même requête que ``-i +M''. En cas de doute, utilisez des options séparées avec les préfixes appropriés.

-? -h
Ces deux options équivalentes sélectionnent une liste d'utilisation (aide). Lsof affiche une forme abrégée de cette sortie lorsqu'il détecte une erreur dans les options qui lui sont fournies, après avoir affiché des messages expliquant chaque erreur. (Échappez le caractère `?' comme votre shell l'exige.)
-a
entraîne la combinaison par ET des options de sélection de liste, comme décrit ci-dessus.
-A A
est disponible sur les systèmes configurés pour AFS dont le code noyau AFS est implémenté via des modules dynamiques. Il permet à l'utilisateur de lsof de spécifier A comme un fichier de liste de noms alternatif où les adresses noyau des modules dynamiques peuvent être trouvées. Voir la FAQ de lsof (la section FAQ indique son emplacement) pour plus d'informations sur les modules dynamiques, leurs symboles et comment ils affectent lsof.
-b
amène lsof à éviter les fonctions noyau qui pourraient bloquer - lstat(2), readlink(2), et stat(2).
Voir les sections BLOCS ET TEMPS DE GARDE et ÉVITER LES BLOCS DU NOYAU pour des informations sur l'utilisation de cette option.
-c c
sélectionne la liste des fichiers pour les processus exécutant la commande qui commence par les caractères de c. Plusieurs commandes peuvent être spécifiées, en utilisant plusieurs options -c. Elles sont jointes dans un seul ensemble combiné par OU avant de participer à la sélection des options ET.
Si c commence par un `^', alors les caractères suivants spécifient un nom de commande dont les processus doivent être ignorés (exclus).
Si c commence et se termine par une barre oblique ('/'), les caractères entre les barres obliques sont interprétés comme une expression régulière. Les métacaractères du shell dans l'expression régulière doivent être cités pour empêcher leur interprétation par le shell. La barre oblique de fermeture peut être suivie de ces modificateurs :
	b	l'expression régulière est de type basique.
	i	ignore la casse des lettres.
	x	l'expression régulière est de type étendue
		(par défaut).
Voir la FAQ de lsof (la section FAQ indique son emplacement) pour plus d'informations sur les expressions régulières de base et étendues.
Le test de spécification de commande simple est effectué en premier. Si ce test échoue, le test d'expression régulière de commande est appliqué. Si le test de commande simple réussit, le test d'expression régulière de commande n'est pas effectué. Cela peut entraîner des messages ``no command found for regex:'' lorsque l'option -V de lsof est spécifiée.
+c w
définit le nombre maximum de caractères initiaux du nom, fourni par le dialecte UNIX, de la commande UNIX associée à un processus à imprimer dans la colonne COMMAND. (La valeur par défaut de lsof est neuf.)
Notez que de nombreux dialectes UNIX ne fournissent pas tous les caractères du nom de commande à lsof dans les fichiers et structures à partir desquels lsof obtient le nom de commande. Souvent, les dialectes limitent le nombre de caractères fournis dans ces sources. Par exemple, Linux 2.4.27 et Solaris 9 limitent tous deux la longueur du nom de commande à 16 caractères.
Si w est zéro ('0'), tous les caractères de commande fournis à lsof par le dialecte UNIX seront imprimés.
Si w est inférieur à la longueur du titre de la colonne, « COMMAND », il sera augmenté à cette longueur.
-C
désactive le rapport de tout composant de nom de chemin du cache de noms du noyau. Voir la section KERNEL NAME CACHE pour plus d'informations.
+d s
fait en sorte que lsof recherche toutes les instances ouvertes du répertoire s et des fichiers et répertoires qu'il contient à son premier niveau. +d NE descend PAS dans l'arborescence des répertoires, enracinée à s. L'option +D D peut être utilisée pour demander une recherche complète dans l'arborescence des répertoires, enracinée au répertoire D.
Le traitement de l'option +d ne suit pas les liens symboliques dans s à moins que l'option -x ou -x l ne soit également spécifiée. Il ne recherche pas non plus les fichiers ouverts sur les points de montage du système de fichiers dans les sous-répertoires de s à moins que l'option -x ou -x f ne soit également spécifiée.
Note : l'autorité de l'utilisateur de cette option le limite à la recherche de fichiers que l'utilisateur a la permission d'examiner avec la fonction système stat(2).
-d s
spécifie une liste de descripteurs de fichiers (FD) à exclure ou à inclure dans la liste de sortie. Les descripteurs de fichiers sont spécifiés dans l'ensemble séparé par des virgules s - par exemple, « cwd,1,3 », « ^6,^2 ». (Il ne devrait y avoir aucun espace dans l'ensemble.)
La liste est une liste d'exclusion si toutes les entrées de l'ensemble commencent par `^'. C'est une liste d'inclusion si aucune entrée ne commence par `^'. Les listes mixtes ne sont pas autorisées.
Une plage de numéros de descripteurs de fichiers peut être dans l'ensemble tant qu'aucun membre n'est vide, que les deux membres sont des nombres et que le membre de fin est supérieur au membre de départ - par exemple, « 0-7 » ou « 3-10 ». Les plages peuvent être spécifiées pour exclusion si elles ont le préfixe `^' - par exemple, « ^0-7 » exclut tous les descripteurs de fichiers 0 à 7.
Plusieurs numéros de descripteurs de fichiers sont joints dans un seul ensemble OU avant de participer à la sélection d'options ET.
Lorsqu'il y a des membres d'exclusion et d'inclusion dans l'ensemble, lsof les signale comme des erreurs et se termine avec un code de retour non nul.
Voir la description des valeurs de sortie de File Descriptor (FD) dans la section OUTPUT pour plus d'informations sur les noms de descripteurs de fichiers.
fd est un nom de descripteur de fichier pseudo pour spécifier toute la plage des numéros de descripteurs de fichiers possibles. fd n'apparaît pas dans la colonne FD de la sortie.
+D D
fait en sorte que lsof recherche toutes les instances ouvertes du répertoire D et tous les fichiers et répertoires qu'il contient, jusqu'à sa profondeur complète.
Le traitement de l'option +D ne suit pas les liens symboliques dans D à moins que l'option -x ou -x l ne soit également spécifiée. Il ne recherche pas non plus les fichiers ouverts sur les points de montage du système de fichiers dans les sous-répertoires de D à moins que l'option -x ou -x f ne soit également spécifiée.
Note : l'autorité de l'utilisateur de cette option le limite à la recherche de fichiers que l'utilisateur a la permission d'examiner avec la fonction système stat(2).
Note supplémentaire : lsof peut traiter cette option lentement et nécessiter une grande quantité de mémoire dynamique. C'est parce qu'il doit descendre toute l'arborescence des répertoires, enracinée à D, appeler stat(2) pour chaque fichier et répertoire, construire une liste de tous les fichiers qu'il trouve, et rechercher dans cette liste une correspondance avec chaque fichier ouvert. Lorsque le répertoire D est grand, ces étapes peuvent prendre beaucoup de temps, utilisez donc cette option avec prudence.
-D D
dirige l'utilisation par lsof du fichier cache de périphériques. L'utilisation de cette option est parfois restreinte. Voir la section DEVICE CACHE FILE et les sections qui la suivent pour plus d'informations sur cette option.
-D doit être suivi d'une lettre de fonction ; la lettre de fonction peut éventuellement être suivie d'un nom de chemin. Lsof reconnaît les lettres de fonction suivantes :
? - signaler les chemins du fichier cache de périphériques
b - construire le fichier cache de périphériques
i - ignorer le fichier cache de périphériques
r - lire le fichier cache de périphériques
u - lire et mettre à jour le fichier cache de périphériques
Les fonctions b, r et u, accompagnées d'un nom de chemin, sont parfois restreintes. Lorsque ces fonctions sont restreintes, elles n'apparaîtront pas dans la description de l'option -D qui accompagne la sortie de l'option -h ou -?. Voir la section DEVICE CACHE FILE et les sections qui la suivent pour plus d'informations sur ces fonctions et quand elles sont restreintes.
La fonction ? signale les chemins en lecture seule et en écriture que lsof peut utiliser pour le fichier cache de périphériques, les noms de toute variable d'environnement dont lsof examinera les valeurs lors de la formation du chemin du fichier cache de périphériques, et le format pour le chemin du fichier cache de périphériques personnel. (Échappez le caractère `?' comme votre shell l'exige.)
Lorsque disponibles, les fonctions b, r et u peuvent être suivies du chemin du fichier cache de périphériques. La valeur par défaut standard est .lsof_hostname dans le répertoire personnel de l'ID utilisateur réel qui exécute lsof, mais cela aurait pu être modifié lors de la configuration et de la compilation de lsof. (La sortie des options -h et -? montre le préfixe par défaut actuel - par exemple, « .lsof ».) Le suffixe, hostname, est le premier composant du nom de l'hôte renvoyé par gethostname(2).
Lorsqu'elle est disponible, la fonction b demande à lsof de construire un nouveau fichier cache de périphériques au chemin par défaut ou spécifié.
La fonction i demande à lsof d'ignorer le fichier cache de périphériques par défaut et d'obtenir ses informations sur les périphériques via des appels directs au noyau.
La fonction r demande à lsof de lire le cache de périphériques au chemin par défaut ou spécifié, mais l'empêche de créer un nouveau fichier cache de périphériques lorsqu'aucun n'existe ou que celui existant est mal structuré. La fonction r, lorsqu'elle est spécifiée sans nom de chemin, empêche lsof de mettre à jour un fichier cache de périphériques incorrect ou obsolète, ou d'en créer un nouveau à sa place. La fonction r est toujours disponible lorsqu'elle est spécifiée sans argument de nom de chemin ; elle peut être restreinte par les permissions du processus lsof.
Lorsqu'elle est disponible, la fonction u demande à lsof de lire le fichier cache de périphériques au chemin par défaut ou spécifié, si possible, et de le reconstruire, si nécessaire. C'est la fonction de cache de périphériques par défaut lorsqu'aucune option -D n'a été spécifiée.
+|-e s
exempte le système de fichiers dont le nom de chemin est s d'être soumis à des appels de fonction noyau qui pourraient bloquer. L'option +e exempte les appels de fonction noyau stat(2), lstat(2) et la plupart des appels de fonction noyau readlink(2). L'option -e exempte uniquement les appels de fonction noyau stat(2) et lstat(2). Plusieurs systèmes de fichiers peuvent être spécifiés avec des spécifications +|-e séparées et chacun peut avoir des appels readlink(2) exemptés ou non.
Cette option n'est actuellement implémentée que pour Linux.
ATTENTION : cette option peut facilement être mal appliquée à un système de fichiers autre que celui d'intérêt, car elle utilise le nom de chemin plutôt que les numéros de périphérique et d'inode plus fiables. (Les numéros de périphérique et d'inode sont acquis via l'appel système potentiellement bloquant stat(2) et ne sont donc pas disponibles, mais voir l'option +|-m m comme une alternative possible pour fournir les numéros de périphérique.) Utilisez cette option avec une extrême prudence et spécifiez complètement le nom de chemin du système de fichiers à exempter.
Lorsque les fichiers ouverts sur les systèmes de fichiers exemptés sont signalés, il se peut qu'il ne soit pas possible d'obtenir toutes leurs informations. Par conséquent, certaines colonnes d'informations seront vides, les caractères « UNKN » précéderont les valeurs dans la colonne TYPE, et l'option d'exemption applicable sera ajoutée entre parenthèses à la fin de la colonne NAME. (Certaines informations sur les numéros de périphérique pourraient être rendues disponibles via l'option +|-m m.)
+|-E
+E spécifie que les fichiers pipe Linux, les sockets UNIX Linux, les sockets INET(6) Linux fermés sur un hôte local, les fichiers de pseudo-terminaux Linux, l'implémentation de la file d'attente de messages POSIX sous Linux et les fichiers eventfd Linux doivent être affichés avec des informations sur les points de terminaison et que les fichiers des points de terminaison doivent également être affichés.
Note 1 : les informations sur les points de terminaison des fichiers de sockets UNIX ne sont disponibles que lorsque la ligne des fonctionnalités activées de la sortie -v contient uxsockept, et les informations sur les points de terminaison des pseudo-terminaux ne sont disponibles que lorsque la ligne des fonctionnalités activées contient ptyept.
Note 2 : les informations sur les points de terminaison des fichiers de files d'attente de messages POSIX ne sont disponibles que lorsque le système de fichiers mqueue est monté.
Les informations sur les points de terminaison des pipes sont affichées dans la colonne NAME sous la forme « PID,cmd,FDmode », où PID est l'ID du processus du point de terminaison ; cmd est la commande du processus du point de terminaison ; FD est le descripteur du fichier du point de terminaison ; et mode est le mode d'accès du fichier du point de terminaison.
Les informations sur les points de terminaison des pseudo-terminaux sont affichées dans la colonne NAME comme « ->/dev/ptsmin PID,cmd,FDmode » ou « PID,cmd,FDmode ». La première forme est pour un périphérique maître ; la seconde, pour un périphérique esclave. min est le numéro de périphérique mineur d'un périphérique esclave ; et PID, cmd, FD et mode sont les mêmes qu'avec les informations sur les points de terminaison des pipes. Note : les informations sur les points de terminaison des pseudo-terminaux i
Les informations ne sont disponibles que si la ligne des fonctionnalités activées de la sortie de -v contient ptyept. De plus, cette fonctionnalité fonctionne sur les noyaux Linux supérieurs à 4.13.0. Les informations de point de terminaison de fichier de socket UNIX sont affichées dans la colonne NAME sous la forme ``type=TYPE >INO=INODE PID,cmd,FDmode'', où TYPE est le type de socket ; INODE est le numéro i-node du socket connecté ; et PID, cmd, FD et mode sont les mêmes qu'avec les informations de point de terminaison de tuyau. Remarque : les informations de point de terminaison de fichier de socket UNIX ne sont disponibles que si la ligne des fonctionnalités activées de la sortie de -v contient uxsockept. Les informations de point de terminaison de fichier de socket INET sont insérées dans la valeur de la colonne NAME sous la forme `` > PID,cmd,FDmode'', où PID, cmd, FD et mode sont les mêmes qu'avec les informations de tuyau. Les informations de point de terminaison ne sont disponibles que si le socket est utilisé pour la communication interprocessus locale ; les deux points de terminaison sont liés à la même adresse locale IPv4 ou IPv6. Les informations de point de terminaison de fichier de file d'attente de messages POSIX sont affichées dans la colonne NAME sous la même forme que celles du tuyau. Les informations de point de terminaison eventfd sont affichées dans la colonne NAME sous la même forme que celles du tuyau. Cette fonctionnalité fonctionne sur les noyaux Linux supérieurs à 5.2.0. Des occurrences multiples de ces informations peuvent apparaître dans la colonne NAME d'un fichier. -E spécifie que les fichiers pris en charge par les points de terminaison doivent être affichés avec les informations de point de terminaison, mais pas les fichiers des points de terminaison. +|-f [cfgGn] f seul clarifie comment les arguments de nom de chemin doivent être interprétés. Lorsqu'il est suivi de c, f, g, G ou n dans n'importe quelle combinaison, il spécifie que le listage des informations de structure de fichier du noyau est à activer ('+') ou à inhiber ('-'). Normalement, un argument de nom de chemin est considéré comme un nom de système de fichiers s'il correspond à un nom de répertoire monté rapporté par mount(8), ou s'il représente un périphérique bloc, nommé dans la sortie de mount et associé à un nom de répertoire monté. Lorsque +f est spécifié, tous les arguments de nom de chemin seront considérés comme des noms de systèmes de fichiers, et lsof se plaindra s'il y en a qui ne le sont pas. Ceci peut être utile, par exemple, lorsque le nom du système de fichiers (périphérique monté) n'est pas un périphérique bloc. Ceci arrive pour certains systèmes de fichiers CD-ROM. Lorsque -f est spécifié seul, tous les arguments de nom de chemin seront considérés comme des fichiers simples. Ainsi, par exemple, les arguments ``-f -- /'' indiquent à lsof de rechercher les fichiers ouverts avec le chemin '/' comme nom de fichier, et non tous les fichiers ouverts dans le système de fichiers '/' (racine). Soyez prudent pour vous assurer que +f et -f sont correctement terminés et ne sont pas suivis d'un caractère (par exemple, du nom du fichier ou du système de fichiers) qui pourrait être pris comme paramètre. Par exemple, utilisez ``--'' après +f et -f comme dans ces exemples. ```sh $ lsof +f -- /nom/de/système/de/fichiers $ lsof -f -- /nom/de/fichier ``` Le listage des informations à partir des structures de fichiers du noyau, demandé avec la forme d'option +f [cfgGn], est normalement inhibé, et n'est pas disponible en tout ou en partie pour certains dialectes - par exemple, les noyaux Linux basés sur /proc inférieurs à 2.6.22. Lorsque le préfixe de f est un signe plus ('+'), ces caractères demandent des informations sur la structure du fichier : ``` c compteur d'utilisation de la structure de fichier (pas Linux) f adresse de la structure de fichier (pas Linux) g abréviations des drapeaux de fichier (Linux 2.6.22 et supérieur) Abréviation Drapeau dans le code C (voir open(2)) W O_WRONLY RW O_RDWR CR O_CREAT EXCL O_EXCL NTTY O_NOCTTY TR O_TRUNC AP O_APPEND ND O_NDELAY SYN O_SYNC ASYN O_ASYNC DIR O_DIRECT DTY O_DIRECTORY NFLK O_NOFOLLOW NATM O_NOATIME DSYN O_DSYNC RSYN O_RSYNC LG O_LARGEFILE CX O_CLOEXEC TMPF O_TMPFILE G drapeaux de fichier en hexadécimal (Linux 2.6.22 et supérieur) n adresse du nœud de la structure de fichier (pas Linux) ``` Lorsque le préfixe est un moins ('-'), les mêmes caractères désactivent le listage des valeurs indiquées. Les adresses des structures de fichiers, les compteurs d'utilisation, les drapeaux et les adresses de nœuds peuvent être utilisés pour détecter plus facilement les fichiers identiques hérités par les processus enfants et les fichiers identiques utilisés par différents processus. La sortie des colonnes de lsof peut être triée par les colonnes de sortie contenant les valeurs et listée pour identifier l'utilisation identique des fichiers, ou la sortie des champs de lsof peut être analysée par un filtre post-traitement AWK ou Perl, ou par un programme C. -F f spécifie une liste de caractères, f, qui sélectionne les champs à afficher pour le traitement par un autre programme, et le caractère qui termine chaque champ de sortie. Chaque champ à afficher est spécifié par un seul caractère dans f. Le terminateur de champ est NL par défaut, mais peut être changé en NUL (000). Voir la section SORTIE POUR AUTRES PROGRAMMES pour une description des caractères d'identification de champ et du processus de sortie de champ. Lorsque la liste de sélection de caractères de champ est vide, tous les champs standard sont sélectionnés (à l'exception du champ de périphérique brut, du contexte de sécurité et du champ de zone pour des raisons de compatibilité) et le terminateur de champ NL est utilisé. Lorsque la liste de sélection de caractères de champ ne contient qu'un zéro ('0'), tous les champs sont sélectionnés (à l'exception du champ de périphérique brut pour des raisons de compatibilité) et le caractère terminateur NUL est utilisé. D'autres combinaisons de champs et leur caractère terminateur de champ associé doivent être définis avec des entrées explicites dans f, comme décrit dans la section SORTIE POUR AUTRES PROGRAMMES. Lorsqu'un caractère de sélection de champ identifie un élément que lsof ne liste normalement pas - par exemple, PPID, sélectionné avec -R - la spécification du caractère de champ - par exemple, ``-FR'' - sélectionne également le listage de l'élément. Lorsque la liste de sélection de caractères de champ contient le caractère unique '?', lsof affichera une liste d'aide des caractères d'identification de champ. (Échappez le caractère '?' comme l'exige votre shell.) -g [s] exclut ou sélectionne le listage des fichiers pour les processus dont les identifiants de groupe de processus (PGID) optionnels sont dans l'ensemble séparé par des virgules s - par exemple, ``123'' ou ``123,^456''. (Il ne doit y avoir aucun espace dans l'ensemble.) Les numéros PGID qui commencent par '^' (négation) représentent des exclusions. Plusieurs numéros PGID sont joints dans un ensemble OU unique avant de participer à la sélection d'options ET. Cependant, les exclusions PGID sont appliquées sans OU ni ET et prennent effet avant que d'autres critères de sélection ne soient appliqués. L'option -g active également l'affichage des numéros PGID. Lorsqu'elle est spécifiée sans ensemble PGID, elle ne fait que cela. -H demande à lsof d'afficher des tailles lisibles par l'homme, par exemple 123.4K 456.7M. -i [i] sélectionne le listage des fichiers dont l'une des adresses Internet correspond à l'adresse spécifiée dans i. Si aucune adresse n'est spécifiée, cette option sélectionne le listage de tous les fichiers réseau Internet et x.25 (HP-UX). Si -i4 ou -i6 est spécifié sans adresse suivante, seuls les fichiers de la version IP indiquée, IPv4 ou IPv6, sont affichés. (Une spécification IPv6 peut être utilisée uniquement si les dialectes prennent en charge IPv6, comme indiqué par ``[46]'' et ``IPv[46]'' dans la sortie -h ou -? de lsof.) Spécifier séquentiellement -i4, suivi de -i6 est identique à spécifier -i, et vice versa. Spécifier -i4, ou -i6 après -i est identique à spécifier -i4 ou -i6 par lui-même. Plusieurs adresses (jusqu'à un maximum de 100) peuvent être spécifiées avec plusieurs options -i. (Une plage de numéros de port ou de noms de service est comptée comme une adresse.) Elles sont jointes dans un ensemble OU unique avant de participer à la sélection d'options ET. Une adresse Internet est spécifiée sous la forme (Les éléments entre crochets sont facultatifs.) :

[46][protocole][@nom_hôte|adresse_hôte][:service|port]

où : ``` 46 spécifie la version IP, IPv4 ou IPv6 qui s'applique à l'adresse suivante. '6' ne peut être spécifié que si le dialecte UNIX prend en charge IPv6. Si ni '4' ni '6' n'est spécifié, l'adresse suivante s'applique à toutes les versions IP. protocole est un nom de protocole - TCP, UDP ou UDPLITE. nom_hôte est un nom d'hôte Internet. Sauf si un spécifique version IP est spécifié, les fichiers réseau ouverts associés aux noms d'hôtes de toutes versions seront sélectionnés. adresse_hôte est une adresse IPv4 Internet numérique sous forme décimale ; ou une adresse numérique IPv6 sous forme de deux-points, entre crochets, si le dialecte UNIX prend en charge IPv6. Lorsqu'une version IP est sélectionnée, seules ses adresses numériques peuvent être spécifiées. service est un nom d'/etc/services - par exemple, smtp - ou une liste d'entre eux. port est un numéro de port, ou une liste d'entre eux. ``` Les options IPv6 ne peuvent être utilisées que si le dialecte UNIX prend en charge IPv6. Pour savoir si le dialecte prend en charge IPv6, exécutez lsof et spécifiez l'option -h ou -? (aide). Si la description affichée de l'option -i contient ``[46]'' et ``IPv[46]'', IPv6 est pris en charge. Les noms d'hôtes et adresses IPv4 ne peuvent pas être spécifiés si la sélection de fichiers réseau est limitée à IPv6 avec -i 6. Les noms d'hôtes et adresses IPv6 ne peuvent pas être spécifiés si la sélection de fichiers réseau est limitée à IPv4 avec -i 4. Lorsqu'une adresse de fichier réseau IPv4 ouverte est mappée dans une adresse IPv6, le type de fichier ouvert sera IPv6, pas IPv4, et son affichage sera sélectionné par '6', pas par '4'. Au moins un composant d'adresse - 4, 6, protocole, nom_hôte, adresse_hôte, ou service - doit être fourni. Le caractère '@', précédant la spécification de l'hôte, est toujours requis ; de même que le ':', précédant la spécification du port. Spécifiez soit nom_hôte, soit adresse_hôte. Spécifiez soit la liste de noms de service, soit la liste de numéros de port. Si une liste de noms de service est spécifiée, le protocole peut également devoir être spécifié si les numéros de port TCP, UDP et UDPLITE pour le nom de service sont différents. Utilisez n'importe quelle casse - minuscule ou majuscule - pour protocole. Les noms de service et les numéros de port peuvent être combinés dans une liste dont les entrées sont séparées par des virgules et dont les numérosc Les entrées de plage sont séparées par des tirets. Il ne peut y avoir d'espaces intégrés, et tous les noms de service doivent appartenir au *protocole* spécifié. Comme les noms de service peuvent contenir des tirets intégrés, l'entrée de départ d'une plage ne peut pas être un nom de service ; il peut cependant s'agir d'un numéro de port.
Voici quelques exemples d'adresses : 
	-i6 - IPv6 uniquement
	TCP:25 - TCP et port 25
	@1.2.3.4 - Adresse hôte IPv4 Internet 1.2.3.4
	@[3ffe:1ebc::1]:1234 - Adresse hôte IPv6 Internet
		3ffe:1ebc::1, port 1234
	UDP:who - Port de service UDP who
	TCP@lsof.itap:513 - TCP, port 513 et nom d'hôte lsof.itap
	tcp@foo:1-10,smtp,99 - TCP, ports 1 à 10,
		nom de service *smtp*, port 99, nom d'hôte foo
	tcp@bar:1-smtp - TCP, ports 1 à *smtp*, hôte bar
	:time - port de service TCP, UDP ou UDPLITE time
-K k
sélectionne l'affichage des tâches (threads) des processus, sur les dialectes où la prise en charge des tâches (threads) est disponible. (Si l'aide en ligne, c'est-à-dire la sortie des options -h ou -?, affiche cette option, alors la prise en charge des tâches (threads) est supportée par le dialecte.)
Si -K est suivi d'une valeur, k, celle-ci doit être ``i''. Cela amène *lsof* à ignorer les tâches, en particulier dans le cas par défaut, où tout est listé, lorsqu'aucune autre option n'est spécifiée.
Lorsque -K et -a sont tous deux spécifiés sous Linux, et que les tâches d'un processus principal sont sélectionnées par d'autres options, le processus principal sera également listé comme s'il s'agissait d'une tâche, mais sans ID de tâche. (Voir la description de la colonne TID dans la section SORTIE.)
Lorsque la version FreeBSD prend en charge les threads, tous les threads seront listés avec leurs ID.
En général, les threads et les tâches héritent des fichiers de l'appelant, mais peuvent en fermer certains et en ouvrir d'autres. Ainsi, *lsof* signale toujours tous les fichiers ouverts des threads et des tâches.
-k k
spécifie un fichier de liste de noms du noyau, k, à la place de /vmunix, /mach, etc. -k n'est pas disponible sous AIX sur l'IBM RISC/System 6000.
-l
inhibe la conversion des numéros d'ID utilisateur en noms de connexion. Il est également utile lorsque la recherche de noms de connexion ne fonctionne pas correctement ou est lente.
+|-L [l]
active ('+') ou désactive ('-') l'affichage du nombre de liens de fichiers, là où ils sont disponibles - par exemple, ils ne sont pas disponibles pour les sockets, ou la plupart des FIFOs et des pipes.
Lorsque +L est spécifié sans nombre suivant, tous les nombres de liens seront affichés. Lorsque -L est spécifié (par défaut), aucun nombre de liens ne sera affiché.
Lorsque +L est suivi d'un nombre, seuls les fichiers ayant un nombre de liens inférieur à ce nombre seront affichés. (Aucun nombre ne peut suivre -L.) Une spécification de la forme ``+L1'' sélectionnera les fichiers ouverts qui ont été désolidarisés. Une spécification de la forme ``+aL1 <système_de_fichiers>'' sélectionnera les fichiers ouverts désolidarisés sur le système de fichiers spécifié.
Pour d'autres comparaisons de nombres de liens, utilisez la sortie de champ (-F) et un script ou programme de post-traitement.
+|-m m
spécifie un fichier de mémoire noyau alternatif ou active le traitement supplémentaire de la table de montage.
La forme d'option -m m spécifie un fichier de mémoire noyau, m, à la place de /dev/kmem ou /dev/mem - par exemple, un fichier de vidage sur incident.
La forme d'option +m demande qu'un fichier supplémentaire de montage soit écrit sur le fichier de sortie standard. Toutes les autres options sont silencieusement ignorées.
Il y aura une ligne dans le fichier supplémentaire de montage pour chaque système de fichiers monté, contenant le répertoire du système de fichiers monté, suivi d'un seul espace, suivi du numéro de périphérique au format hexadécimal "0x" - par exemple,
/ 0x801
*Lsof* peut utiliser le fichier supplémentaire de montage pour obtenir les numéros de périphérique des systèmes de fichiers lorsqu'il ne peut pas les obtenir via stat(2) ou lstat(2).
La forme d'option +m m identifie m comme un fichier supplémentaire de montage.
Remarque : les options +m et +m m ne sont pas disponibles pour tous les dialectes pris en charge. Vérifiez la sortie des options -h ou -? de *lsof* pour voir si les options +m et +m m sont disponibles.
+|-M
active (+) ou désactive (-) le signalement des enregistrements du portmapper pour les ports TCP, UDP et UDPLITE locaux, là où la mise en correspondance des ports est prise en charge. (Voir le dernier paragraphe de la description de cette option pour des informations sur les endroits où le signalement des enregistrements du portmapper est pris en charge.)
Le mode de signalement par défaut est défini par le constructeur de *lsof* avec la directive #define HASPMAPENABLED dans le fichier d'en-tête machine.h du dialecte ; *lsof* est distribué avec la directive #define HASPMAPENABLED désactivée, donc le signalement du portmapper est désactivé par défaut et doit être demandé avec +M. La spécification de l'option -h ou -? de *lsof* affichera le mode par défaut. Désactiver l'enregistrement du portmapper lorsqu'il est déjà désactivé ou l'activer lorsqu'il est déjà activé est acceptable. Lorsque le signalement des enregistrements du portmapper est activé, *lsof* affiche l'enregistrement du portmapper (le cas échéant) pour les ports TCP, UDP ou UDPLITE locaux entre crochets immédiatement après les numéros de port ou les noms de service - par exemple, ``:1234[nom]'' ou ``:nom[100083]''. Les informations d'enregistrement peuvent être un nom ou un numéro, selon ce que le programme d'enregistrement a fourni au portmapper lorsqu'il a enregistré le port.
Lorsque le signalement des enregistrements du portmapper est activé, *lsof* peut s'exécuter un peu plus lentement, voire se bloquer, lorsque l'accès au portmapper est congestionné ou arrêté. Inversez le mode de signalement pour déterminer si le signalement des enregistrements du portmapper ralentit ou bloque *lsof*.
Aux fins du signalement des enregistrements du portmapper, *lsof* considère qu'un port TCP, UDP ou UDPLITE est local si : il se trouve dans la partie locale de sa structure noyau ; ou s'il se trouve dans la partie étrangère de sa structure noyau et que les adresses Internet locale et étrangère sont identiques ; ou s'il se trouve dans la partie étrangère de sa structure noyau et que l'adresse Internet étrangère est INADDR_LOOPBACK (127.0.0.1). Cette règle peut amener *lsof* à ignorer certains ports étrangers sur des machines avec plusieurs interfaces lorsque l'adresse Internet étrangère se trouve sur une interface différente de celle de la locale.
Consultez la FAQ de *lsof* (la section FAQ indique son emplacement) pour une discussion plus approfondie sur les problèmes de signalement des enregistrements du portmapper.
Le signalement des enregistrements du portmapper n'est pris en charge que sur les dialectes qui ont des fichiers d'en-tête RPC. (Certaines distributions Linux avec GlibC 2.14 ne les ont pas.) Lorsque le signalement des enregistrements du portmapper est pris en charge, l'aide en ligne -h ou -? affichera l'option +|-M.
-n
inhibe la conversion des numéros de réseau en noms d'hôtes pour les fichiers réseau. Inhiber la conversion peut rendre *lsof* plus rapide. Il est également utile lorsque la recherche de noms d'hôtes ne fonctionne pas correctement.
-N
sélectionne l'affichage des fichiers NFS.
-o
demande à *lsof* d'afficher l'offset du fichier à tout moment. Il fait en sorte que le titre de la colonne SIZE/OFF soit modifié en OFFSET. Remarque : sur certains dialectes UNIX, *lsof* ne peut pas obtenir d'informations d'offset de fichier précises ou cohérentes à partir de ses sources de données du noyau, parfois uniquement pour certains types de fichiers (par exemple, les fichiers socket). Consultez la FAQ de *lsof* (la section FAQ donne son emplacement) pour plus d'informations.
Les options -o et -s sont mutuellement exclusives ; elles ne peuvent pas être spécifiées toutes les deux. Lorsque aucune des deux n'est spécifiée, *lsof* affiche la valeur - taille ou décalage - appropriée et disponible pour le type de fichier.
-o o
définit le nombre de chiffres décimaux (o) à imprimer après le "0t" pour un décalage de fichier avant que la forme ne soit changée en "0x...". Une valeur o de zéro (illimitée) demande à *lsof* d'utiliser la forme "0t" pour toutes les sorties de décalage.
Cette option ne demande PAS à *lsof* d'afficher le décalage à tout moment ; spécifiez -o (sans nombre à la fin) pour le faire. -o o spécifie uniquement le nombre de chiffres après "0t" dans la sortie mixte taille et décalage ou décalage uniquement. Ainsi, par exemple, pour demander à *lsof* d'afficher le décalage à tout moment avec un nombre de chiffres décimaux de 10, utilisez :
	-o -o 10
ou
	-oo10
Le nombre par défaut de chiffres autorisés après "0t" est normalement de 8, mais peut avoir été modifié par le constructeur de lsof. Consultez la description de l'option -o o dans la sortie de l'option -h ou -? pour déterminer la valeur par défaut en vigueur.
-O
demande à *lsof* de contourner la stratégie qu'il utilise pour éviter d'être bloqué par certaines opérations du noyau - c'est-à-dire, en les effectuant dans des processus enfants bifurqués. Voir les sections BLOCS ET TEMPS D'ATTENTE et ÉVITER LES BLOCS DU NOYAU pour plus d'informations sur les opérations du noyau qui peuvent bloquer *lsof*.
Bien que l'utilisation de cette option réduise la surcharge de démarrage de *lsof*, elle peut également amener *lsof* à se bloquer lorsque le noyau ne répond pas à une fonction. Utilisez cette option avec prudence.
-p s
exclut ou sélectionne l'affichage des fichiers pour les processus dont les numéros d'identification de processus (PID) optionnels sont dans l'ensemble séparé par des virgules s - par exemple, "123" ou "123,^456". (Il ne devrait pas y avoir d'espaces dans l'ensemble.)
Les numéros de PID qui commencent par `^' (négation) représentent des exclusions.
Plusieurs numéros d'ID de processus sont joints dans un seul ensemble OU avant de participer à la sélection d'options ET. Cependant, les exclusions de PID sont appliquées sans OU ou ET et prennent effet avant que d'autres critères de sélection ne soient appliqués.
-P
inhibe la conversion des numéros de port en noms de port pour les fichiers réseau (la mise en correspondance est généralement apprise à partir de /etc/services). Inhiber t
La conversion peut rendre lsof un peu plus rapide. C'est aussi utile lorsque la recherche de noms de ports ne fonctionne pas correctement.
-Q
ignore les termes de recherche échoués. Lorsque lsof reçoit l'ordre de rechercher les utilisateurs d'un fichier, ou les utilisateurs d'un périphérique, ou un PID spécifique, ou certains protocoles utilisés par ce PID, etc., lsof retournera une erreur si certains des résultats de recherche sont vides. L'option -Q modifiera ce comportement de telle sorte que lsof retournera un code de sortie réussi (0) même si certains des résultats de recherche sont vides. De plus, les termes de recherche manquants ne seront pas signalés sur stderr.
+|-r [t[c<N>][m<fmt>]]
met lsof en mode répétition. Dans ce mode, lsof liste les fichiers ouverts comme sélectionnés par d'autres options, attend t secondes (15 par défaut), puis répète la liste, en attendant et en listant de manière répétitive jusqu'à ce qu'une condition définie par le préfixe de l'option soit remplie.
Si le préfixe est un `-', le mode répétition est infini. Lsof doit être terminé par un signal d'interruption ou de sortie. `c<N>' sert à spécifier les limites de répétition ; si le nombre d'itérations atteint `<N>', Lsof s'arrête de lui-même.
Si le préfixe est `+', le mode répétition se termine au premier cycle où aucun fichier ouvert n'est listé - et bien sûr lorsque lsof est arrêté par un signal d'interruption ou de sortie. Lorsque le mode répétition se termine car aucun fichier n'est listé, le code de sortie du processus sera zéro si des fichiers ouverts ont jamais été listés ; un, si aucun n'a jamais été listé.
Lsof marque la fin de chaque liste : si la sortie par champ est en cours (l'option -F a été spécifiée), le marqueur par défaut est `m' ; sinon, le marqueur par défaut est ``========''. Le marqueur est suivi d'un caractère NL.
L'argument facultatif "m<fmt>" spécifie un format pour la ligne de marqueur. Les caractères <fmt> qui suivent `m' sont interprétés comme une spécification de format pour la fonction strftime(3), lorsque celle-ci et la fonction localtime(3) sont disponibles dans la bibliothèque C du dialecte. Consultez la documentation de strftime(3) pour savoir ce qui peut apparaître dans sa spécification de format. Notez que lorsque la sortie par champ est demandée avec l'option -F, <fmt> ne peut pas contenir le format NL, "%n". Notez également que lorsque <fmt> contient des espaces ou d'autres caractères qui affectent l'interprétation des arguments par le shell, <fmt> doit être correctement mis entre guillemets.
Le mode répétition réduit les frais de démarrage de lsof, il est donc plus efficace d'utiliser ce mode que d'appeler lsof de manière répétitive à partir d'un script shell, par exemple.
Pour utiliser le mode répétition le plus efficacement, associez +|-r à la spécification d'autres options de sélection de lsof, afin que la quantité d'accès à la mémoire du noyau que lsof effectue soit minimisée. Les options qui filtrent au niveau du processus - par exemple, -c, -g, -p, -u - sont les sélecteurs les plus efficaces.
Le mode répétition est utile lorsqu'il est couplé à la sortie par champ (voir la description de l'option -F) et à un script awk ou Perl de supervision, ou à un programme C.
-R
ordonne à lsof d'afficher l'identifiant du processus parent (PID) dans la colonne PPID.
-s [p:s]
s seul ordonne à lsof d'afficher la taille du fichier à tout moment. Il provoque le changement du titre de la colonne de sortie SIZE/OFF en SIZE. Si le fichier n'a pas de taille, rien n'est affiché.
La forme facultative -s p:s n'est disponible que pour certains dialectes, et uniquement lorsque la sortie d'aide -h ou -? l'indique.
Lorsque la forme facultative est disponible, le s peut être suivi d'un nom de protocole (p), soit TCP, soit UDP, de deux points (":") et d'une liste de noms d'état de protocole séparés par des virgules, l'option provoque l'exclusion des fichiers TCP et UDP ouverts si leur(s) nom(s) d'état figurent dans la liste (s) précédée d'un "^" ; ou leur inclusion si leur(s) nom(s) ne sont pas précédés d'un "^".
Les dialectes qui prennent en charge cette option peuvent ne prendre en charge qu'un seul protocole. Lorsqu'un protocole non pris en charge est spécifié, un message s'affichera indiquant que les noms d'état pour ce protocole ne sont pas disponibles.
Lorsqu'une liste d'inclusion est définie, seuls les fichiers réseau dont les noms d'état figurent dans la liste seront présents dans la sortie de lsof. Ainsi, spécifier un seul nom d'état signifie que seuls les fichiers réseau ayant cet unique nom d'état seront listés.
La casse n'a pas d'importance dans les noms de protocole ou d'état, mais il ne peut y avoir d'espaces et le deux-points (":") séparant le nom du protocole (p) et la liste des noms d'état (s) est requis.
Si seuls les fichiers TCP et UDP doivent être listés, comme contrôlé par les exclusions et inclusions spécifiées, l'option -i doit également être spécifiée. Si seulement les fichiers d'un seul protocole doivent être listés, ajoutez son nom comme argument à l'option -i.
Par exemple, pour lister uniquement les fichiers réseau avec l'état TCP LISTEN, utilisez :
-iTCP -sTCP:LISTEN
Ou, par exemple, pour lister les fichiers réseau avec tous les états UDP sauf Idle, utilisez :
-iUDP -sUDP:^Idle
Les noms d'état varient selon les dialectes UNIX, il n'est donc pas possible de fournir une liste complète. Certains noms d'état TCP courants sont : CLOSED, IDLE, BOUND, LISTEN, ESTABLISHED, SYN_SENT, SYN_RCDV, ESTABLISHED, CLOSE_WAIT, FIN_WAIT1, CLOSING, LAST_ACK, FIN_WAIT_2, et TIME_WAIT. Deux noms d'état UDP courants sont Unbound et Idle.
Consultez la FAQ de lsof (la section FAQ indique son emplacement) pour plus d'informations sur la façon d'utiliser l'exclusion et l'inclusion d'états de protocole, y compris des exemples.
Les options -o (sans chiffre décimal de suivi) et -s (sans liste de protocole et d'état de suivi) sont mutuellement exclusives ; elles ne peuvent pas être spécifiées ensemble. Lorsque ni l'une ni l'autre n'est spécifiée, lsof affiche la valeur - taille ou décalage - qui est appropriée et disponible pour le type de fichier.
Étant donné que certains types de fichiers n'ont pas de tailles réelles - sockets, FIFOs, pipes, etc. - lsof affiche pour leur taille les quantités de contenu dans leurs tampons noyau associés, si possible.
-S [t]
spécifie une valeur facultative de secondes de délai d'attente pour les fonctions noyau - lstat(2), readlink(2), et stat(2) - qui pourraient sinon se bloquer. Le minimum pour t est deux ; la valeur par défaut, quinze ; lorsqu'aucune valeur n'est spécifiée, la valeur par défaut est utilisée.
Consultez la section BLOCS ET DÉLAIS D'ATTENTE pour plus d'informations.
-T [t]
contrôle le rapport de certaines informations TCP/TPI, également rapportées par netstat(1), après les adresses réseau. En sortie normale, les informations apparaissent entre parenthèses, chaque élément sauf le nom d'état TCP ou TPI étant identifié par un mot-clé, suivi de '=', séparé des autres par un espace unique :
<Nom d'état TCP ou TPI>
QR=<longueur de la file d'attente de lecture>
QS=<longueur de la file d'attente d'envoi>
SO=<options et valeurs du socket>
SS=<états du socket>
TF=<flags et valeurs TCP>
WR=<longueur de la fenêtre de lecture>
WW=<longueur de la fenêtre d'écriture>
Toutes les valeurs ne sont pas rapportées pour tous les dialectes UNIX. Les valeurs des éléments (lorsqu'elles sont disponibles) sont rapportées après le nom de l'élément et '='.
Lorsque le mode de sortie par champ est activé (voir la section SORTIE POUR LES AUTRES PROGRAMMES), chaque élément apparaît comme un champ avec un caractère `T' en préfixe.
-T sans caractères clés suivants désactive le rapport des informations TCP/TPI.
-T avec les caractères suivants sélectionne le rapport d'informations TCP/TPI spécifiques :
f	sélectionne le rapport des options du socket,
	des états et des valeurs, et des drapeaux et
	valeurs TCP.
q	sélectionne le rapport des longueurs de file d'attente.
s	sélectionne le rapport de l'état de la connexion.
w	sélectionne le rapport de la taille de la fenêtre.
Toutes les sélections ne sont pas activées pour tous les dialectes UNIX. L'état peut être sélectionné pour tous les dialectes et est rapporté par défaut. La sortie d'aide -h ou -? pour l'option -T montrera quelles sélections peuvent être utilisées avec le dialecte UNIX.
Lorsque -T est utilisé pour sélectionner des informations - c'est-à-dire qu'il est suivi d'un ou plusieurs caractères de sélection - l'affichage de l'état est désactivé par défaut, et il doit être explicitement sélectionné à nouveau dans les caractères qui suivent -T. (En pratique, alors, la valeur par défaut équivaut à -Ts.) Par exemple, si les longueurs de file d'attente et l'état sont désirés, utilisez -Tqs.
Les options du socket, les états du socket, certaines valeurs du socket, les drapeaux TCP et une valeur TCP peuvent être rapportés (lorsqu'ils sont disponibles dans le dialecte UNIX) sous la forme des noms qui apparaissent couramment après SO_, so_, SS_, TCP_ et TF_ dans les fichiers d'en-tête du dialecte - le plus souvent <sys/socket.h>, <sys/socketvar.h> et <netinet/tcp_var.h>. Consultez ces fichiers d'en-tête pour connaître la signification des drapeaux, options, états et valeurs.
``SO='' précède les options et valeurs du socket ; ``SS='', les états du socket ; et ``TF='', les drapeaux et valeurs TCP.
Si un drapeau ou une option a une valeur, la valeur suivra un '=' et le nom - par exemple, ``SO=LINGER=5'', ``SO=QLIM=5'', ``TF=MSS=512''. Les sept valeurs suivantes peuvent être rapportées :

Sous Linux, cette option imprime également l'état des sockets de domaine UNIX.
-t
produit une sortie concise ne comprenant que les identifiants de processus (sans en-tête), de sorte qu'elle est facile à utiliser programmatiquement
ly. par exemple. 
# recharger tout ce qui utilise un ancien SSL
lsof -t /lib/*/libssl.so.* | xargs -r kill -HUP
# obtenir la liste des processus puis itérer sur eux (Bash uniquement)
mapfile -t pids < <(
    lsof -wt /var/log/your.log
)
for pid in "${pids[@]}" ; do
    your_command -p "$pid"
done
L'option -t implique l'option -w.
-u s
sélectionne la liste des fichiers pour l'utilisateur dont les noms de connexion ou les identifiants d'utilisateur sont dans l'ensemble séparé par des virgules s - par exemple, « abe », ou « 548,root ». (Il ne doit pas y avoir d'espaces dans l'ensemble.)
Plusieurs noms de connexion ou identifiants d'utilisateur sont joints dans un seul ensemble OU avant de participer à la sélection des options ET.
Si un nom de connexion ou un identifiant d'utilisateur est précédé de `^', il devient une négation - c'est-à-dire que les fichiers des processus appartenant au nom de connexion ou à l'identifiant d'utilisateur ne seront jamais répertoriés. Une sélection de nom de connexion ou d'identifiant d'utilisateur niée n'est ni combinée par ET ni par OU avec d'autres sélections ; elle est appliquée avant toutes les autres sélections et exclut absolument la liste des fichiers du processus. Par exemple, pour demander à lsof d'exclure la liste des fichiers appartenant aux processus root, spécifiez « -u^root » ou « -u^0 ».
-U
sélectionne la liste des fichiers de sockets UNIX.
-v
sélectionne la liste des informations de version de lsof, comprenant : le numéro de révision ; quand le binaire lsof a été construit ; qui a construit le binaire et où ; le nom du compilateur utilisé pour construire le binaire lsof ; le numéro de version du compilateur lorsqu'il est facilement disponible ; les indicateurs de compilateur et de chargeur utilisés pour construire le binaire lsof ; et les informations système, généralement la sortie de la commande uname avec l'option -a.
-V
demande à lsof d'indiquer les éléments qu'il a été invité à lister et qu'il n'a pas trouvé - noms de commandes, noms de fichiers, adresses ou fichiers Internet, noms de connexion, fichiers NFS, PID, PGID et UID.
Lorsque d'autres options sont combinées par ET avec les options de recherche, ou que les options de compilation restreignent la liste de certains fichiers, lsof peut ne pas signaler qu'il n'a pas trouvé un élément de recherche lorsqu'une option combinée par ET ou une option de compilation empêche la liste du fichier ouvert contenant l'élément de recherche trouvé.
Par exemple, « lsof -V -iTCP@foobar -a -d 999 » peut ne pas signaler un échec de localisation de fichiers ouverts à « TCP@foobar » et peut n'en lister aucun, si aucun n'a un numéro de descripteur de fichier de 999. Une situation similaire survient lorsque HASSECURITY et HASNOSOCKSECURITY sont définis à la compilation et qu'ils empêchent la liste des fichiers ouverts.
+|-w
Active (+) ou désactive (-) la suppression des messages d'avertissement.
Le constructeur de lsof peut choisir d'avoir les messages d'avertissement désactivés ou activés par défaut. L'état par défaut des messages d'avertissement est indiqué dans la sortie de l'option -h ou -?. Désactiver les messages d'avertissement lorsqu'ils sont déjà désactivés ou les activer lorsqu'ils sont déjà activés est acceptable.
L'option -t implique l'option -w.
-x [fl]
peut accompagner les options +d et +D pour demander leur traitement pour traverser les liens symboliques et/ou les points de montage du système de fichiers rencontrés lors de l'analyse du répertoire (+d) ou de l'arborescence des répertoires (+D).
Si -x est spécifié seul sans paramètre suivant, le traitement croisé des liens symboliques et des points de montage du système de fichiers est activé. Notez que lorsque -x est spécifié sans paramètre, l'argument suivant doit commencer par '-' ou '+'.
Le paramètre optionnel 'f' active le traitement croisé des points de montage de systèmes de fichiers ; 'l', le traitement croisé des liens symboliques.
L'option -x ne peut pas être fournie sans également fournir une option +d ou +D.
-X
Ceci est une option spécifique au dialecte.

    AIX :
Cette option IBM AIX RISC/System 6000 demande le signalement des références aux fichiers texte exécutés et aux bibliothèques partagées.

ATTENTION : comme cette option utilise la fonction kernel readx(), son utilisation sur un système AIX occupé pourrait provoquer un blocage complet d'un processus applicatif, au point qu'il ne puisse être ni tué ni arrêté. Je n'ai jamais vu cela arriver ni eu de rapport à ce sujet, mais je pense qu'il existe une faible possibilité que cela se produise.
Par défaut, l'utilisation de readx() est désactivée. Sur AIX 5L et supérieur, lsof peut nécessiter des permissions setuid-root pour effectuer les actions demandées par cette option.
Le constructeur de lsof peut spécifier que l'option -X soit restreinte aux processus dont l'UID réel est root. Si cela a été fait, l'option -X n'apparaîtra pas dans la sortie d'aide -h ou -? sauf si l'UID réel du processus lsof est root. La distribution lsof par défaut permet à n'importe quel UID de spécifier -X, donc par défaut elle apparaîtra dans la sortie d'aide.
Lorsque l'utilisation de readx() sur AIX est désactivée, lsof peut ne pas être en mesure de signaler les informations pour toutes les références aux fichiers texte et chargeurs, mais il peut également éviter d'aggraver une erreur de recherche de répertoire du noyau AIX, connue sous le nom de bug Stale Segment ID.
La fonction readx(), utilisée par lsof ou tout autre programme pour accéder à certaines sections de la mémoire virtuelle du noyau, peut déclencher le bug Stale Segment ID. Elle peut amener la fonction dir_search() du noyau à croire à tort qu'une partie d'une copie en mémoire d'un répertoire de système de fichiers a été mise à zéro. Un autre processus applicatif, distinct de lsof, demandant au noyau de rechercher le répertoire - par exemple, en utilisant open(2) - peut faire que dir_search() boucle indéfiniment, bloquant ainsi le processus applicatif.
Consultez la FAQ lsof (la section FAQ indique son emplacement) et le fichier 00README de la distribution lsof pour une description plus complète du bug Stale Segment ID, de son APAR et des méthodes pour définir l'utilisation de readx() lors de la compilation de lsof.

    Linux :
Cette option Linux demande à lsof d'ignorer le signalement des informations sur tous les fichiers TCP, UDP et UDPLITE IPv4 et IPv6 ouverts.

Cette option Linux est la plus utile lorsque le système possède un nombre extrêmement important de fichiers TCP, UDP et UDPLITE ouverts, dont le traitement des informations dans les fichiers /proc/net/tcp* et /proc/net/udp* prendrait beaucoup de temps à lsof, et dont le signalement n'est pas d'intérêt.
Utilisez cette option avec précaution et uniquement lorsque vous êtes sûr que les informations que vous souhaitez que lsof affiche ne sont pas associées à des fichiers de socket TCP, UDP ou UDPLITE ouverts.

    Solaris 10 et supérieur :
Cette option Solaris 10 et supérieur demande le signalement des chemins mis en cache pour les fichiers qui ont été supprimés - c'est-à-dire, supprimés avec rm(1) ou unlink(2).

Le chemin mis en cache est suivi de la chaîne « (deleted) » pour indiquer que le chemin par lequel le fichier a été ouvert a été supprimé.
Comme les modifications intermédiaires apportées au chemin - c'est-à-dire, les renommages avec mv(1) ou rename(2) - ne sont pas enregistrées dans le chemin mis en cache, ce que lsof rapporte n'est que le chemin par lequel le fichier a été ouvert, et non son chemin final, potentiellement différent.
-z [z]
spécifie comment les informations de zone Solaris 10 et supérieur doivent être gérées.
Sans argument suivant - par exemple, PAS de z - l'option spécifie que les noms de zone doivent être listés dans la colonne de sortie ZONE.
L'option -z peut être suivie d'un nom de zone, z. Cela demande à lsof de lister uniquement les fichiers ouverts pour les processus dans cette zone. Plusieurs paires d'options et d'arguments -z z peuvent être spécifiées pour former une liste de zones nommées. Tout fichier ouvert de tout processus dans l'une des zones sera listé, sous réserve d'autres conditions spécifiées par d'autres options et arguments.
-Z [Z]
spécifie comment les contextes de sécurité SELinux doivent être gérés. Elle et le support du caractère de sortie du champ 'Z' sont inhibés lorsque SELinux est désactivé dans le noyau Linux en cours d'exécution. Voir SORTIE POUR D'AUTRES PROGRAMMES pour plus d'informations sur le caractère de sortie du champ 'Z'.
Sans argument suivant - par exemple, PAS de Z - l'option spécifie que les contextes de sécurité doivent être listés dans la colonne de sortie SECURITY-CONTEXT.
L'option -Z peut être suivie d'un nom de contexte de sécurité générique, Z. Cela demande à lsof de lister uniquement les fichiers ouverts pour les processus dans ce contexte de sécurité. Plusieurs paires d'options et d'arguments -Z Z peuvent être spécifiées pour former une liste de contextes de sécurité. Tout fichier ouvert de tout processus dans l'un des contextes de sécurité sera listé, sous réserve d'autres conditions spécifiées par d'autres options et arguments. Notez que Z peut être A:B:C ou *:B:C ou A:B:* ou *:*:C pour correspondre au contexte A:B:C.
--
L'option double tiret est un marqueur qui signale la fin des options clés. Elle peut être utilisée, par exemple, lorsque le premier nom de fichier commence par un tiret. Elle peut également être utilisée lorsque l'absence d'une valeur pour la dernière option clé doit être signifiée par la présence d'un tiret dans l'option suivante et avant le début des noms de fichiers.
names
Ce sont les noms de chemins de fichiers spécifiques à lister. Les liens symboliques sont résolus avant utilisation. Le premier nom peut être séparé des options précédentes avec l'option ``--''.
Si un nom est le répertoire monté d'un système de fichiers ou le périphérique du système de fichiers, lsof listera tous les fichiers ouverts sur le système de fichiers. Pour être considéré comme un système de fichiers, le nom doit correspondre à un nom de répertoire monté dans la sortie de mount(8), ou correspondre au nom d'un périphérique bloc associé à un nom de répertoire monté. L'option +|-f peut être utilisée pour forcer lsof à considérer un nom comme un identifiant de système de fichiers (+f) ou un fichier simple (-f).
Si name est un chemin vers un répertoire qui n'est pas le répertoire monté d'un système de fichiers, il est traité comme un fichier ordinaire - c'est-à-dire que sa liste est restreinte aux processus qui l'ont ouvert comme fichier ou comme répertoire spécifique au processus, tel que la racine ou le répertoire de travail courant. Pour demander à lsof de rechercher les fichiers ouverts à l'intérieur d'un nom de répertoire, utilisez les options +d s et +D D.
Si un name est le nom de base d'une famille de fichiers multiplexés - par exemple, /dev/pt[cs] sous AIX - lsof listera tous les fichiers multiplexés associés sur le périphérique qui sont ouverts - par exemple, /dev/pt[cs]/1, /dev/pt[cs]/2, etc.
Si un name est un nom de socket de domaine UNIX, lsof le recherchera généralement uniquement par les caractères du nom - exactement tels qu'ils sont spécifiés et enregistrés dans la structure du socket du noyau. (Voir le paragraphe suivant pour une exception à cette règle pour Linux.) Spécifier un chemin relatif - par exemple, ./file - à la place du chemin absolu du fichier - par exemple, /tmp/file - ne fonctionnera pas car lsof doit faire correspondre les caractères que vous spécifiez avec ceux qu'il trouve dans les structures des sockets de domaine UNIX du noyau.
Si un name est un nom de socket de domaine UNIX sous Linux, dans un cas, lsof est capable de le rechercher par son périphérique et son numéro d'inode, permettant à name d'être un chemin relatif. Le cas où le chemin absolu - c'est-à-dire celui commençant par une barre oblique ('/') - est utilisé par le processus qui a créé le socket, et donc stocké dans le fichier /proc/net/unix ; et cela nécessite que lsof puisse obtenir les numéros de périphérique et de nœud du chemin absolu dans /proc/net/unix et de name via des appels système stat(2) réussis. Lorsque ces conditions sont remplies, lsof sera capable de rechercher le socket de domaine UNIX lorsqu'un chemin y menant est spécifié dans name. Ainsi, par exemple, si le chemin est /dev/log, et qu'une recherche lsof est initiée lorsque le répertoire de travail est /dev, alors name pourrait être ./log.
Si un name ne correspond à aucun des cas ci-dessus, lsof listera tous les fichiers ouverts dont le périphérique et l'inode correspondent à ceux du chemin name spécifié.
Si vous avez également spécifié l'option -b, les seuls names que vous pouvez spécifier en toute sécurité sont les systèmes de fichiers pour lesquels votre table de montage fournit des numéros de périphérique alternatifs. Voir les sections ÉVITER LES BLOCS DU NOYAU et NUMÉROS DE PÉRIPHÉRIQUE ALTERNATIFS pour plus d'informations.
Plusieurs noms de fichiers sont joints dans un seul ensemble OU avant de participer à la sélection d'options ET.

AFS

Lsof prend en charge la reconnaissance des fichiers AFS pour ces dialectes (et versions AFS) :

AIX 4.1.4 (AFS 3.4a)
HP-UX 9.0.5 (AFS 3.4a)
Linux 1.2.13 (AFS 3.3)
Solaris 2.[56] (AFS 3.4a)

Il peut reconnaître les fichiers AFS sur d'autres versions de ces dialectes, mais cela n'a pas été testé. Selon la façon dont AFS est implémenté, lsof peut reconnaître les fichiers AFS dans d'autres dialectes, ou peut avoir des difficultés à reconnaître les fichiers AFS dans les dialectes supportés.

Lsof peut avoir des difficultés à identifier tous les aspects des fichiers AFS dans les dialectes pris en charge lorsque le support AFS du noyau est implémenté via des modules dynamiques dont les adresses n'apparaissent pas dans la liste des noms de variables du noyau. Dans ce cas, lsof pourrait devoir deviner l'identité des fichiers AFS et pourrait ne pas être en mesure d'obtenir les informations de volume du noyau nécessaires au calcul des numéros de nœud de volume AFS. Lorsque lsof ne peut pas calculer les numéros de nœud de volume, il affiche une chaîne vide dans la colonne NODE.

L'option -A A est disponible dans certaines implémentations de dialectes de lsof pour spécifier le fichier de liste de noms où les adresses du noyau de modules dynamiques peuvent être trouvées. Lorsque cette option est disponible, elle sera listée dans la sortie d'aide de lsof, présentée en réponse aux options -h ou -?

Voir la FAQ de lsof (la section FAQ donne son emplacement) pour plus d'informations sur les modules dynamiques, leurs symboles et comment ils affectent les options de lsof.

Étant donné que les recherches de chemin AFS ne semblent pas participer aux opérations de cache de noms du noyau, lsof ne peut pas identifier les composants du nom de chemin pour les fichiers AFS.

SÉCURITÉ

Lsof possède trois fonctionnalités qui peuvent poser des problèmes de sécurité. Premièrement, son mode de compilation par défaut permet à quiconque de lister tous les fichiers ouverts avec lui. Deuxièmement, par défaut, il crée un fichier cache de périphériques lisible et inscriptible par l'utilisateur dans le répertoire personnel de l'ID utilisateur réel qui exécute lsof. (La liste de tous les fichiers ouverts et les fonctionnalités de cache de périphériques peuvent être désactivées lors de la compilation de lsof.) Troisièmement, ses options -k et -m nomment des fichiers de liste de noms ou de mémoire du noyau alternatifs.

La restriction de la liste de tous les fichiers ouverts est contrôlée par les options de compilation HASSECURITY et HASNOSOCKSECURITY. Lorsque HASSECURITY est défini, lsof ne permettra qu'à l'utilisateur root de lister tous les fichiers ouverts. L'utilisateur non-root ne pourra lister que les fichiers ouverts des processus ayant le même identifiant utilisateur que l'identifiant utilisateur réel du processus lsof (celui avec lequel son utilisateur s'est connecté).

Cependant, si HASSECURITY et HASNOSOCKSECURITY sont tous deux définis, quiconque peut lister les fichiers sockets ouverts, à condition qu'ils soient sélectionnés avec l'option -i.

Lorsque HASSECURITY n'est pas défini, quiconque peut lister tous les fichiers ouverts.

La sortie d'aide, présentée en réponse à l'option -h ou -?, indique l'état des définitions HASSECURITY et HASNOSOCKSECURITY.

Voir la section Sécurité du fichier 00README de la distribution lsof pour des informations sur la compilation de lsof avec les options HASSECURITY et HASNOSOCKSECURITY activées.

La création et l'utilisation d'un fichier cache de périphériques lisible et inscriptible par l'utilisateur est contrôlée par l'option de compilation HASDCACHE. Voir la section FICHIER CACHE DE PÉRIPHÉRIQUES et les sections qui la suivent pour les détails sur la formation de son chemin. Pour des raisons de sécurité, il est important de noter que dans la distribution lsof par défaut, si l'ID utilisateur réel sous lequel lsof est exécuté est root, le fichier cache de périphériques sera écrit dans le répertoire personnel de root - par exemple, / ou /root. Lorsque HASDCACHE n'est pas défini, lsof n'écrit ni ne tente de lire de fichier cache de périphériques.

Lorsque HASDCACHE est défini, la sortie d'aide de lsof, présentée en réponse aux options -h, -D?, ou -?, fournira des informations sur la gestion du fichier cache de périphériques. Lorsque HASDCACHE n'est pas défini, la sortie de -h ou -? n'aura pas de description de l'option -D.

Avant de décider de désactiver la fonctionnalité de fichier cache de périphériques - l'activer améliore les performances de lsof en réduisant la surcharge de démarrage de l'examen de tous les nœuds dans /dev (ou /devices) - lisez la discussion à ce sujet dans le fichier 00DCACHE de la distribution lsof et la FAQ de lsof (la section FAQ donne son emplacement).

EN CAS DE DOUTE, VOUS POUVEZ DÉSACTIVER TEMPORAIREMENT L'UTILISATION DU FICHIER CACHE DE PÉRIPHÉRIQUES AVEC L'OPTION -Di.

Lorsque l'utilisateur lsof déclare des fichiers de liste de noms ou de mémoire du noyau alternatifs avec les options -k et -m, lsof vérifie l'autorisation de l'utilisateur de les lire avec access(2). Ceci est destiné à empêcher que tout pouvoir spécial que les modes de lsof pourraient lui conférer ne lui permette de lire des fichiers qui ne sont normalement pas accessibles via l'autorité de l'ID utilisateur réel.

SORTIE

Cette section décrit les informations que lsof liste pour chaque fichier ouvert. Voir la section SORTIE POUR D'AUTRES PROGRAMMES pour des informations supplémentaires sur la sortie qui peut être traitée par un autre programme.

Lsof ne produit que des caractères 8 bits imprimables (déclarés comme tels par isprint(3)). Les caractères non imprimables sont affichés sous l'une des trois formes : la forme C ``\[bfrnt]'' ; la forme de caractère de contrôle `^' (par exemple, ``^@'') ; ou la forme hexadécimale commençant par ``\x'' (par exemple, ``\xab''). L'espace est non imprimable dans la colonne COMMAND (``\x20'') et imprimable ailleurs.

Pour certains dialectes - si HASSETLOCALE est défini dans le fichier d'en-tête machine.h du dialecte - lsof affichera les caractères 8 bits étendus d'une locale linguistique. Le processus lsof doit recevoir une variable d'environnement de locale linguistique (par exemple, LANG) dont la valeur représente une locale linguistique connue dans laquelle les caractères étendus sont considérés comme imprimables par isprint(3). Sinon, lsof considère les caractères étendus comme non imprimables et les affiche selon ses règles pour les caractères non imprimables, énoncées ci-dessus. Consultez la page de manuel setlocale(3) de votre dialecte pour connaître les noms d'autres variables d'environnement qui peuvent être utilisées à la place de LANG - par exemple, LC_ALL, LC_CTYPE, etc.

La prise en charge des locales linguistiques de lsof pour un dialecte couvre également les caractères larges - par exemple, UTF-8 - lorsque HASSETLOCALE et HASWIDECHAR sont définis dans le fichier d'en-tête machine.h du dialecte, et lorsqu'une locale linguistique appropriée a été définie dans la variable d'environnement appropriée pour le processus lsof. Les caractères larges sont imprimables dans ces conditions si iswprint(3) les signale comme tels. Si HASSETLOCALE, HASWIDECHAR et une locale linguistique appropriée ne sont pas définis, ou si iswprint(3) signale des caractères larges qui ne sont pas imprimables, lsof considère les caractères larges comme non imprimables et affiche chacun de leurs 8 bits selon ses règles pour les caractères non imprimables, énoncées ci-dessus.

Consultez les réponses aux questions sur le "Support des locales linguistiques" dans la FAQ de lsof (la section FAQ donne son emplacement) pour plus d'informations.

Lsof dimensionne dynamiquement les colonnes de sortie à chaque exécution, garantissant que chaque colonne a une taille minimale. Il garantit également que chaque colonne est séparée de sa précédente par au moins un espace.

COMMAND
contient les neuf premiers caractères du nom de la commande UNIX associée au processus. Si une valeur w non nulle est spécifiée à l'option +c w, la colonne contient les w premiers caractères du nom de la commande UNIX associée au processus, dans la limite des caractères fournis à lsof par le dialecte UNIX. (Voir la description de la commande +c w ou la FAQ de lsof pour plus d'informations. La section FAQ donne son emplacement.)
Si w est inférieur à la longueur du titre de la colonne, « COMMAND », elle sera augmentée à cette longueur.

TAILLE, TAILLE/DÉCALAGE, ou DÉCALAGE
est la taille du fichier ou le décalage du fichier en octets. Une valeur est affichée dans cette colonne uniquement si elle est disponible. Lsof affiche la valeur - taille ou décalage - appropriée pour le type de fichier et la version de lsof.
Sur certains dialectes UNIX, lsof ne peut pas obtenir d'informations précises ou cohérentes sur le décalage du fichier à partir de ses sources de données du noyau, parfois uniquement pour des types de fichiers particuliers (par exemple, les fichiers socket). Dans d'autres cas, les fichiers n'ont pas de tailles réelles - par exemple, les sockets, les FIFO, les pipes - donc lsof affiche pour leurs tailles les quantités de contenu qu'il trouve dans leurs descripteurs de tampon de noyau (par exemple, les comptes de taille de tampon de socket ou les tailles de fenêtre TCP/IP). Consultez la FAQ de lsof (La section FAQ donne son emplacement) pour plus d'informations.
La taille du fichier est affichée en décimal ; le décalage est normalement affiché en décimal avec un préfixe ``0t'' s'il contient 8 chiffres ou moins ; en hexadécimal avec un préfixe ``0x'' s'il est plus long que 8 chiffres. (Consultez la description de l'option -o o pour savoir quand 8 peut par défaut à une autre valeur.)
Ainsi, le préfixe ``0t'' et ``0x'' identifient un décalage lorsque la colonne peut contenir à la fois une taille et un décalage (c'est-à-dire, son titre est TAILLE/DÉCALAGE).
Si l'option -o est spécifiée, lsof affiche toujours le décalage du fichier (ou rien si aucun décalage n'est disponible) et étiquette la colonne DÉCALAGE. Le décalage commence toujours par ``0t'' ou ``0x'' comme décrit ci-dessus.
L'utilisateur de lsof peut contrôler le passage de ``0t'' à ``0x'' avec l'option -o o. Consultez sa description pour plus d'informations.
Si l'option -s est spécifiée, lsof affiche toujours la taille du fichier (ou rien si aucune taille n'est disponible) et étiquette la colonne TAILLE. Les options -o et -s sont mutuellement exclusives ; elles ne peuvent pas être spécifiées ensemble.
Si l'option -H est spécifiée, lsof affiche la taille du fichier sous forme lisible par l'homme.
Pour les fichiers qui n'ont pas de taille fixe - par exemple, qui ne résident pas sur un périphérique de disque - lsof affichera des informations appropriées sur la taille ou la position actuelle du fichier s'il est disponible dans les structures du noyau qui définissent le fichier.

Pour les dialectes qui prennent en charge un système de fichiers ``namefs'', permettant d'attacher un fichier à un autre avec fattach(3C), lsof ajoutera ``(FA:<address1><direction><address2>)'' dans la colonne NAME. <address1> et <address2> sont des adresses vnode hexadécimales. <direction> sera ``<-'' si <address2> a été attaché avec fattach à ce vnode dont l'adresse est <address1> ; et ``->'' si <address1>, l'adresse vnode de ce vnode, a été attaché avec fattach à <address2>. <address1> peut être omis s'il apparaît déjà dans la colonne DEVICE.

Consultez la FAQ de lsof (la section FAQ indique son emplacement) pour plus d'informations sur ces ajouts à la colonne NAME.

LOCKS

Lsof ne peut pas rapporter adéquatement la grande variété de verrous de fichiers des dialectes UNIX dans un seul caractère. Ce qu'il rapporte dans un seul caractère est un compromis entre les informations qu'il trouve dans le noyau et les limitations du format de rapport.

De plus, lorsqu'un processus détient plusieurs verrous au niveau des octets sur un fichier, lsof ne rapporte que l'état du premier verrou qu'il rencontre. S'il s'agit d'un verrou au niveau des octets, le caractère de verrou sera rapporté en minuscules - c'est-à-dire `r', `w', ou `x' - plutôt qu'en majuscules équivalentes rapportées pour un verrou de fichier complet.

En général, lsof ne peut rapporter que les verrous détenus par des processus locaux sur des fichiers locaux. Lorsqu'un processus local établit un verrou sur un fichier monté à distance (par exemple, NFS), le serveur distant enregistre généralement l'état du verrou. Une exception est Solaris - à certains niveaux de correctifs de 2.3, et dans toutes les versions supérieures à 2.4, le noyau Solaris enregistre les informations sur les verrous distants dans des structures locales.

Lsof a des difficultés à rapporter les verrous pour certains dialectes UNIX. Consultez la section BUGS de cette page de manuel ou la FAQ de lsof (la section FAQ indique son emplacement) pour plus d'informations.

SORTIE POUR LES AUTRES PROGRAMMES

Lorsque l'option -F est spécifiée, lsof produit une sortie qui convient au traitement par un autre programme - par exemple, un script awk ou Perl, ou un programme C.

Chaque unité d'information est sortie dans un champ identifié par un caractère préfixe et terminé par un NL (012) (ou un NUL (000) si le caractère identificateur de champ 0 (zéro) est spécifié.) Les données du champ suivent immédiatement après le caractère d'identification du champ et s'étendent jusqu'au terminateur de champ.

Il est possible de considérer la sortie des champs comme des ensembles de processus et de fichiers. Un ensemble de processus commence par un champ dont l'identificateur est `p' (pour l'identificateur de processus (PID)). Il s'étend jusqu'au début du prochain champ PID ou jusqu'au début du premier ensemble de fichiers du processus, selon ce qui vient en premier. Les champs qui identifient la commande, le numéro d'identificateur de groupe de processus (PGID), l'ID de tâche (thread) (TID) et le numéro d'ID utilisateur (UID) ou le nom de connexion sont inclus dans l'ensemble de processus.

Un ensemble de fichiers commence par un champ dont l'identificateur est `f' (pour descripteur de fichier). Il est suivi de lignes décrivant le mode d'accès du fichier, l'état du verrou, le type, le périphérique, la taille, le décalage, l'inode, le protocole, le nom et les noms des modules stream. Il s'étend jusqu'au début du prochain ensemble de fichiers ou de processus, selon ce qui vient en premier.

Lorsque le terminateur de champ NUL (000) a été sélectionné avec le caractère d'identificateur de champ 0 (zéro), lsof termine chaque ensemble de processus et de fichiers avec un caractère NL (012).

Lsof produit toujours un champ, le champ PID (`p'). En mode répétition, le marqueur (`m') est également produit. Tous les autres champs peuvent être déclarés en option dans la liste des caractères d'identificateur de champ qui suit l'option -F. Lorsqu'un caractère de sélection de champ identifie un élément que lsof ne liste pas normalement - par exemple, PPID, sélectionné avec -R - la spécification du caractère de champ - par exemple, ``-FR'' - sélectionne également la liste de l'élément.

Lsof version 4.88 à 4.93.2 produisait toujours un champ de plus, le champ descripteur de fichier (`f'). Cependant, lsof dans cette version ne le produit pas. Ce changement vise à prendre en charge le cas où un utilisateur n'a besoin que du champ PID et pas du champ descripteur de fichier. Spécifiez `f' explicitement si vous avez besoin du champ.

Il est tout à fait possible de sélectionner un ensemble de champs qui ne peuvent pas être facilement analysés - par exemple, si le champ descripteur de fichier n'est pas sélectionné, il peut être difficile d'identifier les ensembles de fichiers. Pour vous aider à éviter cette difficulté, lsof prend en charge l'option -F ; elle sélectionne la sortie de tous les champs avec des terminateurs NL (la paire d'options -F0 sélectionne la sortie de tous les champs avec des terminateurs NUL). Pour des raisons de compatibilité, ni -F ni -F0 ne sélectionnent le champ de périphérique brut.

ÉVITEMENT DES BLOCAGES DU NOYAU

Certaines fonctions du noyau qu'il utilise - lstat(2), readlink(2), et stat(2). Ces fonctions sont bloquées dans le noyau, par exemple, lorsque les hôtes où résident les systèmes de fichiers NFS montés deviennent inaccessibles.

Lsof tente de briser ces blocages avec des temporisateurs et des processus fils, mais ces techniques ne sont pas entièrement fiables. Lorsque lsof parvient à briser un blocage, il le signale par un message d'erreur. Les messages peuvent être supprimés avec les options -t et -w.

La valeur de délai d'attente par défaut peut être affichée avec l'option -h ou -?, et elle peut être modifiée avec l'option -S[t]. Le minimum pour t est de deux secondes, mais vous devez éviter les valeurs faibles, car la lenteur de la réactivité du système peut entraîner l'expiration inattendue de délais courts et potentiellement arrêter lsof avant qu'il ne puisse produire de sortie.

Lorsque lsof doit briser un blocage lors de l'accès aux informations des systèmes de fichiers montés, il continue normalement, bien qu'avec moins d'informations disponibles à afficher sur les fichiers ouverts.

Lsof peut également être dirigé pour éviter la protection des temporisateurs et des processus fils lors de l'utilisation des fonctions du noyau qui pourraient bloquer en spécifiant l'option -O. Bien que cela permette à lsof de démarrer avec moins de surcharge, cela expose complètement lsof aux situations du noyau qui pourraient le bloquer. Utilisez cette option avec prudence.

ÉVITEMENT DES BLOCAGES DU NOYAU

Vous pouvez utiliser l'option -b pour indiquer à lsof d'éviter d'utiliser les fonctions du noyau qui bloqueraient. Certaines précautions s'appliquent.

Premièrement, l'utilisation de cette option nécessite généralement que votre système fournisse des numéros de périphérique alternatifs à la place des numéros de périphérique que lsof obtiendrait normalement avec les fonctions du noyau lstat(2) et stat(2). Voir la section NUMÉROS DE PÉRIPHÉRIQUE ALTERNATIFS pour plus d'informations sur les numéros de périphérique alternatifs.

Deuxièmement, vous ne pouvez pas spécifier de noms à lsof pour les localiser, à moins qu'il ne s'agisse de noms de systèmes de fichiers. En effet, lsof a besoin de connaître les numéros de périphérique et d'inode des fichiers répertoriés avec des noms dans les options de lsof, et l'option -b empêche lsof de les obtenir. De plus, comme lsof n'a que des numéros de périphérique pour les systèmes de fichiers qui ont des alternatives, sa capacité à localiser les fichiers sur les systèmes de fichiers dépend entièrement de la disponibilité et de l'exactitude des alternatives. Si aucune alternative n'est disponible, ou si elles sont incorrectes, lsof ne pourra pas localiser les fichiers sur les systèmes de fichiers nommés.

Troisièmement, si les noms de vos répertoires de systèmes de fichiers que lsof obtient de la table de montage de votre système sont des liens symboliques, lsof ne pourra pas résoudre les liens. En effet, l'option -b fait en sorte que lsof évite la fonction du noyau readlink(2) qu'il utilise pour résoudre les liens symboliques.

Enfin, l'utilisation de l'option -b amène lsof à émettre des messages d'avertissement lorsqu'il doit utiliser les fonctions du noyau que l'option -b lui demande d'éviter. Vous pouvez supprimer ces messages en spécifiant l'option -w, mais si vous le faites, vous ne verrez pas les numéros de périphérique alternatifs signalés dans les messages d'avertissement.

NUMÉROS DE PÉRIPHÉRIQUE ALTERNATIFS

Sur certains dialectes, lorsque lsof doit briser un blocage parce qu'il ne peut pas obtenir d'informations sur un système de fichiers monté via les fonctions du noyau lstat(2) et stat(2), ou parce que vous avez spécifié l'option -b, lsof peut obtenir certaines des informations dont il a besoin - le numéro de périphérique et éventuellement le type de système de fichiers - à partir de la table de montage du système. Lorsque cela est possible, lsof signalera le numéro de périphérique obtenu. (Vous pouvez supprimer le rapport en spécifiant l'option -w.)

Vous pouvez aider ce processus si votre table de montage est prise en charge par un fichier /etc/mtab ou /etc/mnttab qui contient un champ d'options en ajoutant un champ ``dev=xxxx'' pour les points de montage qui n'en ont pas dans leurs chaînes d'options. Remarque : vous devez pouvoir modifier le fichier - c'est-à-dire que certaines tables de montage comme le /etc/mnttab récent de Solaris ou le /proc/mounts de Linux sont en lecture seule et ne peuvent pas être modifiées.

Vous pourrez peut-être également fournir des numéros de périphérique en utilisant les options +m et +mm, à condition qu'elles soient prises en charge par votre dialecte. Vérifiez la sortie des options -h ou -? de lsof pour voir si les options +m et +mm sont disponibles.

La partie ``xxxx'' du champ est la valeur hexadécimale du numéro de périphérique du système de fichiers. (Consultez le champ st_dev de la sortie des fonctions lstat(2) et stat(2) pour les valeurs appropriées pour vos systèmes de fichiers.) Voici un exemple d'un /etc/mnttab Sun Solaris 2.6 pour un système de fichiers monté à distance via NFS :

nfs  ignore,noquota,dev=2a40001

Il y a un avantage à avoir des entrées ``dev=xxxx'' dans votre fichier de table de montage, en particulier pour les systèmes de fichiers qui sont montés depuis des serveurs NFS distants. Lorsqu'un serveur distant plante et que vous souhaitez identifier ses utilisateurs en exécutant lsof sur l'un de ses clients, lsof ne pourra probablement pas obtenir d'informations des fonctions lstat(2) et stat(2) pour le système de fichiers. S'il peut obtenir le numéro de périphérique du système de fichiers à partir de la table de montage, il pourra afficher les fichiers ouverts sur le serveur NFS planté.

Certains dialectes qui n'utilisent pas de fichier ASCII /etc/mtab ou /etc/mnttab pour la table de montage peuvent encore fournir un numéro de périphérique alternatif dans leurs tables de montage internes. Cela inclut AIX, Apple Darwin, FreeBSD, NetBSD, OpenBSD et Tru64 UNIX. Lsof sait comment obtenir le numéro de périphérique alternatif pour ces dialectes et l'utilise lorsque sa tentative de lstat(2) ou de stat(2) du système de fichiers est bloquée.

Si vous n'êtes pas sûr que votre dialecte fournisse des numéros de périphérique alternatifs pour les systèmes de fichiers à partir de sa table de montage, utilisez cette incantation lsof pour voir s'il signale des numéros de périphérique alternatifs :

lsof -b

Recherchez les messages d'avertissement du fichier d'erreurs standard qui commencent par ``assumant "dev=xxxx" de ...''.

FICHIER DE CACHE DE PÉRIPHÉRIQUE

L'examen de tous les membres de l'arborescence de nœuds /dev (ou /devices) avec les fonctions stat(2) peut être long. De plus, les informations dont lsof a besoin - numéro de périphérique, numéro d'inode et chemin - changent rarement.

Par conséquent, lsof maintient normalement un fichier texte ASCII d'informations mises en cache sur /dev (ou /devices) (exception : le lsof de Linux basé sur /proc où ce n'est pas nécessaire). L'administrateur système local qui construit lsof peut contrôler la manière dont le chemin du fichier de cache de périphérique est formé, en choisissant parmi ces options :

Chemin de l'option -D ;
Chemin d'une variable d'environnement ;
Chemin système ;
Chemin personnel (par défaut) ;
Chemin personnel, modifié par une variable d'environnement.

Consultez la sortie des options d'aide -h, -D? ou -? pour l'état actuel de la prise en charge du cache de périphérique. La sortie d'aide liste le chemin par défaut du fichier de cache de périphérique en mode lecture qui est en vigueur pour l'invocation actuelle de lsof. L'option -D? liste les chemins des fichiers de cache de périphérique en lecture seule et en écriture, les noms des variables d'environnement applicables et le format du chemin du cache de périphérique personnel.

Lsof peut détecter que le fichier de cache de périphérique actuel a été modifié accidentellement ou malicieusement par des contrôles d'intégrité, y compris le calcul et la vérification d'une somme de contrôle CRC (Cyclic Redundancy Check) de seize bits sur le contenu du fichier. Lorsque lsof détecte un problème avec le fichier, il émet un avertissement et tente de supprimer le fichier de cache actuel et d'en créer une nouvelle copie, mais uniquement vers un chemin où le processus peut légitimement écrire.

Le chemin à partir duquel un processus lsof peut tenter de lire un fichier de cache de périphérique peut ne pas être le même que le chemin vers lequel il peut légitimement écrire. Ainsi, lorsque lsof détecte qu'il doit mettre à jour le fichier de cache de périphérique, il peut choisir un chemin différent pour l'écrire par rapport au chemin à partir duquel il a lu une version incorrecte ou obsolète.

Si disponible, l'option -Dr empêchera l'écriture d'un nouveau fichier de cache de périphérique. (Elle est toujours disponible lorsqu'elle est spécifiée sans argument de nom de chemin.)

p">Lorsqu'un nouveau périphérique est ajouté au système, le fichier cache des périphériques peut nécessiter d'être recréé. Étant donné que lsof compare le mtime du fichier cache des périphériques avec le mtime et le ctime du répertoire /dev (ou /devices), il détecte généralement qu'un nouveau périphérique a été ajouté ; dans ce cas, lsof émet un message d'avertissement et tente de reconstruire le fichier cache des périphériques.

PERMISSIONS LSOF QUI AFFECTENT L'ACCÈS AU FICHIER CACHE DES PÉRIPHÉRIQUES

Deux permissions de l'exécutable lsof affectent sa capacité à accéder aux fichiers cache des périphériques. Les permissions sont définies par l'administrateur système local lors de l'installation de lsof.

La première permission, plus rare, est le setuid-root. Elle entre en vigueur lorsque lsof est exécuté ; son UID effectif est alors root, tandis que son UID réel (c'est-à-dire celui de l'utilisateur connecté) ne l'est pas. La distribution lsof recommande que les versions pour ces dialectes s'exécutent en setuid-root.

HP-UX 11.11 et 11.23
Linux

La deuxième permission, plus courante, est le setgid. Elle entre en vigueur lorsque l'identifiant de groupe effectif (GID) du processus lsof est défini sur un GID pouvant accéder aux périphériques de mémoire noyau, par exemple ``kmem'', ``sys'' ou ``system''.

Un processus lsof qui possède la permission setgid renonce généralement à cette permission après avoir accédé aux périphériques de mémoire noyau. Lorsqu'il le fait, lsof peut autoriser des formations de chemins de cache de périphériques plus libérales. (Note : lsof pour AIX 5L et supérieur a besoin de la permission setuid-root si son option -X est utilisée.)

Lsof pour ces dialectes ne prend pas en charge un cache de périphériques, donc les permissions accordées à l'exécutable ne s'appliquent pas au fichier cache des périphériques.

Linux

CHEMIN DU FICHIER CACHE DES PÉRIPHÉRIQUES DEPUIS L'OPTION -D

L'option -D offre des moyens limités pour spécifier le chemin du fichier cache des périphériques. Sa fonction ? signalera les chemins de fichiers cache des périphériques en lecture seule et en écriture que lsof utilisera.

Lorsque les fonctions b, r et u de l'option -D sont disponibles, vous pouvez les utiliser pour demander que le fichier cache soit créé dans un emplacement spécifique (b[chemin]) ; lu mais pas reconstruit (r[chemin]) ; ou lu et reconstruit (u[chemin]). Les fonctions b, r et u sont restreintes dans certaines conditions. Elles sont restreintes lorsque le processus lsof est setuid-root. Le chemin spécifié avec la fonction r est toujours en lecture seule, même lorsqu'il est disponible.

Les fonctions b, r et u sont également restreintes lorsque le processus lsof s'exécute en setgid et que lsof ne renonce pas à la permission setgid. (Voir la section PERMISSIONS LSOF QUI AFFECTENT L'ACCÈS AU FICHIER CACHE DES PÉRIPHÉRIQUES pour une liste des implémentations qui ne renoncent normalement pas à leur permission setgid.)

Une autre fonction de -D, i (pour ignore), est toujours disponible.

Lorsqu'elle est disponible, la fonction b indique à lsof de lire les informations sur les périphériques depuis le noyau avec la fonction stat(2) et de créer un fichier cache des périphériques au chemin indiqué.

Lorsqu'elle est disponible, la fonction r indique à lsof de lire le fichier cache des périphériques, mais de ne pas le mettre à jour. Lorsqu'un argument de chemin accompagne -Dr, il nomme le chemin du fichier cache des périphériques. La fonction r est toujours disponible lorsqu'elle est spécifiée sans argument de nom de chemin. Si lsof ne s'exécute pas en setuid-root et renonce à sa permission setgid, un nom de chemin peut accompagner la fonction r.

Lorsqu'elle est disponible, la fonction u indique à lsof de tenter de lire et d'utiliser le fichier cache des périphériques. S'il ne parvient pas à lire le fichier, ou s'il constate que le contenu du fichier est incorrect ou obsolète, il lira les informations du noyau et tentera d'écrire une version mise à jour du fichier cache des périphériques, mais uniquement vers un chemin qu'il considère comme légitime pour les UID effectifs et réels du processus lsof.

CHEMIN DU CACHE DES PÉRIPHÉRIQUES DEPUIS UNE VARIABLE D'ENVIRONNEMENT

Le deuxième choix de lsof pour le fichier cache des périphériques est le contenu de la variable d'environnement LSOFDEVCACHE. Il évite ce choix si le processus lsof est setuid-root, ou si l'UID réel du processus est root.

Une restriction supplémentaire s'applique à un chemin de fichier cache des périphériques tiré de la variable d'environnement LSOFDEVCACHE : lsof n'écrira pas de fichier cache des périphériques vers le chemin si le processus lsof ne renonce pas à sa permission setgid. (Voir la section PERMISSIONS LSOF QUI AFFECTENT L'ACCÈS AU FICHIER CACHE DES PÉRIPHÉRIQUES pour des informations sur les implémentations qui ne renoncent pas à leur permission setgid.)

L'administrateur système local peut désactiver l'utilisation de la variable d'environnement LSOFDEVCACHE ou changer son nom lors de la compilation de lsof. Consultez la sortie de -D? pour connaître le nom de la variable d'environnement.

CHEMIN DU CACHE DES PÉRIPHÉRIQUES AU NIVEAU DU SYSTÈME

L'administrateur système local peut choisir d'avoir un fichier cache des périphériques à l'échelle du système lors de la compilation de lsof. Ce fichier sera généralement construit par une procédure spéciale d'administration système lors du démarrage du système ou lorsque le contenu de /dev ou /devices change. S'il est défini, c'est le troisième choix de chemin de fichier cache des périphériques de lsof.

Vous pouvez savoir qu'un fichier cache des périphériques à l'échelle du système est en vigueur pour votre installation locale en examinant la sortie de l'option d'aide de lsof, c'est-à-dire la sortie de l'option -h ou -?.

Lsof n'écrira jamais par défaut dans le chemin du fichier cache des périphériques à l'échelle du système. Il doit être explicitement nommé avec une fonction -D dans une procédure appartenant à root. Une fois le fichier écrit, la procédure doit changer ses modes de permission en 0644 (lecture et écriture pour le propriétaire, lecture pour le groupe et lecture pour les autres).

CHEMIN DU CACHE DES PÉRIPHÉRIQUES PERSONNEL (PAR DÉFAUT)

Le chemin par défaut du fichier cache des périphériques de la distribution lsof est enregistré dans le répertoire personnel de l'UID réel qui exécute lsof. Ajouté au répertoire personnel se trouve un deuxième composant de chemin de la forme .lsof_nomdihôte.

C'est le quatrième choix de chemin de fichier cache des périphériques de lsof, et c'est généralement le défaut. Si un chemin de fichier cache des périphériques à l'échelle du système a été défini lors de la compilation de lsof, ce quatrième choix sera appliqué lorsque lsof ne trouvera pas le fichier cache des périphériques à l'échelle du système. C'est la **seule** fois où lsof utilise deux chemins lors de la lecture du fichier cache des périphériques.

La partie nomdihôte du deuxième composant est le nom de base de l'hôte en cours d'exécution, tel que renvoyé par gethostname(2). Le nom de base est défini comme les caractères précédant le premier `.' dans la sortie de gethostname(2), ou toute la sortie de gethostname(2) s'il ne contient pas de `.'.

Le fichier cache des périphériques appartient à l'ID utilisateur et est lisible et inscriptible par l'ID utilisateur seul, c'est-à-dire que ses modes sont 0600. Chaque ID utilisateur réel distinct sur un hôte donné qui exécute lsof possède un fichier cache des périphériques distinct. La partie nomdihôte du chemin distingue les fichiers cache des périphériques dans un répertoire personnel monté via NFS dans lequel les fichiers cache des périphériques sont écrits à partir de plusieurs hôtes différents.

Le chemin du fichier cache des périphériques personnel formé par cette méthode représente un fichier cache des périphériques que lsof tentera de lire, et tentera d'écrire s'il n'existe pas ou si son contenu est incorrect ou obsolète.

L'option -Dr sans argument de nom de chemin inhibera l'écriture d'un nouveau fichier cache des périphériques.

L'option -D? listera le format de spécification pour la construction du fichier cache des périphériques personnel. Les conversions utilisées dans la spécification du format sont décrites dans le fichier 00DCACHE de la distribution lsof.

CHEMIN MODIFIÉ DU CACHE DES PÉRIPHÉRIQUES PERSONNEL

Si cette option est définie par l'administrateur système local lors de la compilation de lsof, le contenu de la variable d'environnement LSOFPERSDCPATH peut être utilisé pour ajouter un composant au chemin du fichier cache des périphériques personnel.

Le contenu de la variable LSOFPERSDCPATH est inséré dans le chemin à l'endroit marqué par l'administrateur système local avec la conversion ``%p'' dans la spécification de format HASPERSDC du fichier d'en-tête machine.h du dialecte. (Il est placé juste après le répertoire personnel dans la distribution lsof par défaut.)

Ainsi, par exemple, si LSOFPERSDCPATH contient ``LSOF'', que le répertoire personnel est ``/Homes/abe'', que le nom d'hôte est ``lsof.itap.purdue.edu'', et que le format HASPERSDC est celui par défaut (``%h/%p.lsof_%L''), le chemin modifié du fichier cache des périphériques personnel est :

/Homes/abe/LSOF/.lsof_vic

La variable d'environnement LSOFPERSDCPATH est ignorée lorsque le processus lsof est setuid-root ou lorsque l'UID réel du processus est root.

Lsof n'écrira pas dans un chemin de fichier cache des périphériques personnel modifié si le processus lsof ne renonce pas à la permission setgid. (Voir la section PERMISSIONS LSOF QUI AFFECTENT L'ACCÈS AU FICHIER CACHE DES PÉRIPHÉRIQUES pour une liste des implémentations qui ne renoncent normalement pas à leur permission setgid.)

Si, par exemple, vous souhaitez créer un sous-répertoire de chemins de fichiers cache des périphériques personnels en utilisant la variable d'environnement LSOFPERSDCPATH pour le nommer, et que lsof ne renonce pas à sa permission setgid, vous devrez permettre à lsof de créer des fichiers cache des périphériques à l'emplacement personnel standard et les déplacer vers votre sous-répertoire

DIAGNOSTICS

Les erreurs sont identifiées par des messages sur le flux d'erreurs standard.

Lsof retourne un (1) si une erreur a été détectée, y compris l'échec de localisation des noms de commandes, des noms de fichiers, des adresses ou fichiers Internet, des noms de connexion, des fichiers NFS, des PID, des PGID ou des UID qui lui ont été demandés de lister. Si l'option -V est spécifiée, lsof indiquera les éléments de recherche qu'il n'a pas réussi à lister. Si l'option -Q est spécifiée, lsof ignorera les échecs d'éléments de recherche et ne retournera une erreur que si quelque chose d'inhabituel et d'irrécupérable s'est produit.

Il retourne un zéro (0) si aucune erreur n'a été détectée et si soit l'option -Q a été spécifiée, soit il a pu lister des informations sur tous les arguments de recherche spécifiés.

Lorsque lsof ne peut pas ouvrir l'accès à /dev (ou /devices) ou à l'un de ses sous-répertoires, ou obtenir des informations sur un fichier qui s'y trouve avec stat(2), il émet un message d'avertissement et continue. Le fait que lsof émette des messages d'avertissement concernant les fichiers inaccessibles dans /dev (ou /devices) est indiqué dans son aide - demandée avec les options -h ou >B -? - avec le message :

Inaccessible /dev warnings are enabled.

Le message d'avertissement peut être supprimé avec l'option -w. Il peut également avoir été supprimé par l'administrateur système lors de la compilation de lsof en définissant WARNDEVACCESS. Dans ce cas, la sortie des options d'aide inclura le message :

Inaccessible /dev warnings are disabled.

Les messages d'avertissement d'accès impossible aux périphériques disparaissent généralement après que lsof a créé un fichier de cache de périphériques fonctionnel.

EXAMPLES

Pour un ensemble d'exemples plus étendu, documenté plus en détail, consultez le fichier 00QUICKSTART de la distribution lsof.

Pour lister tous les fichiers ouverts, utilisez :

lsof

Pour lister tous les fichiers Internet, x.25 (HP-UX) et de domaine UNIX ouverts, utilisez :

lsof -i -U

Pour lister tous les fichiers réseau IPv4 ouverts utilisés par le processus dont le PID est 1234, utilisez :

lsof -i 4 -a -p 1234

Si cela ne pose pas de problème que le PID 1234 n'existe pas, ou que le PID 1234 n'ait pas de fichiers réseau IPv4 ouverts, ajoutez -Q :

lsof -Q -i 4 -a -p 1234

En supposant que le dialecte UNIX prend en charge IPv6, pour lister uniquement les fichiers réseau IPv6 ouverts, utilisez :

lsof -i 6

Pour lister tous les fichiers utilisant n'importe quel protocole sur les ports 513, 514 ou 515 de l'hôte wonderland.cc.purdue.edu, utilisez :

lsof -i @wonderland.cc.purdue.edu:513-515

Pour lister tous les fichiers utilisant n'importe quel protocole sur n'importe quel port de mace.cc.purdue.edu (cc.purdue.edu est le domaine par défaut), utilisez :

lsof -i @mace

Pour lister tous les fichiers ouverts pour le nom de connexion « abe », ou l'ID utilisateur 1234, ou le processus 456, ou le processus 123, ou le processus 789, utilisez :

lsof -p 456,123,789 -u 1234,abe

Pour lister tous les fichiers ouverts sur le périphérique /dev/hd4, utilisez :

lsof /dev/hd4

Pour trouver le processus qui a /u/abe/foo ouvert sans se soucier s'il n'y en a aucun, utilisez :

lsof -Q /u/abe/foo

Pour agir uniquement si un processus a /u/abe/foo ouvert, utilisez :

lsof /u/abe/foo echo "still in use"

Pour envoyer un SIGHUP aux processus qui ont /u/abe/bar ouvert, utilisez :

kill -HUP `lsof -t /u/abe/bar`

Pour trouver tout fichier ouvert, y compris un fichier de socket de domaine UNIX ouvert, nommé /dev/log, utilisez :

lsof /dev/log

Pour trouver des processus ayant des fichiers ouverts sur le système de fichiers NFS nommé /nfs/mount/point dont le serveur est inaccessible, et en supposant que votre table de montage fournisse le numéro de périphérique pour /nfs/mount/point, utilisez :

lsof -b /nfs/mount/point

Pour effectuer la recherche précédente avec les messages d'avertissement supprimés, utilisez :

lsof -bw /nfs/mount/point

Pour ignorer le fichier de cache des périphériques, utilisez :

lsof -Di

Pour obtenir la sortie des champs PID et nom de commande pour chaque processus, descripteur de fichier, numéro de périphérique de fichier et numéro d'inode de fichier pour chaque fichier de chaque processus, utilisez :

lsof -FpcfDi

Pour lister les fichiers aux descripteurs 1 et 3 de chaque processus exécutant la commande lsof pour l'ID de connexion « abe » toutes les 10 secondes, utilisez :

lsof -c lsof -a -d 1 -d 3 -u abe -r10

Pour lister le répertoire de travail actuel des processus exécutant une commande qui a exactement quatre caractères de long et qui a un 'o' ou 'O' dans le troisième caractère, utilisez cette forme d'expression régulière de l'option -c c :

lsof -c /^..o.$/i -a -d cwd

Pour trouver un fichier de socket IP version 4 par son adresse numérique en point associée, utilisez :

lsof -i@128.210.15.17

Pour trouver un fichier de socket IP version 6 (lorsque le dialecte UNIX prend en charge IPv6) par son adresse numérique en deux-points associée, utilisez :

lsof -i@[0:1:2:3:4:5:6:7]

Pour trouver un fichier de socket IP version 6 (lorsque le dialecte UNIX prend en charge IPv6) par une adresse numérique en deux-points associée qui a une suite de zéros - par exemple, l'adresse de bouclage - utilisez :

lsof -i@[::1]

Pour obtenir une ligne de marqueur de mode répétition qui contient l'heure actuelle, utilisez :

lsof -rm====%T====

Pour ajouter des espaces à la ligne de marqueur précédente, utilisez :

lsof -r "m==== %T ===="

BUGS

Comme lsof lit la mémoire du noyau dans sa recherche de fichiers ouverts, des changements rapides dans la mémoire du noyau peuvent produire des résultats imprévisibles.

Lorsqu'un fichier a plusieurs verrous d'enregistrement, le caractère d'état du verrou (suivant le descripteur de fichier) est dérivé d'un test de la première structure de verrou, et non d'une combinaison quelconque des verrous d'enregistrement individuels qui pourraient être décrits par plusieurs structures de verrou.

Lsof ne peut pas rechercher des fichiers avec des permissions d'accès restrictives par nom à moins qu'il ne soit installé avec la permission root set-UID. Sinon, il est limité à la recherche de fichiers auxquels son utilisateur ou son groupe set-GID (le cas échéant) a des permissions d'accès.

L'affichage de l'adresse de destination d'une socket brute (par exemple, pour ping) dépend du système d'exploitation UNIX. Certains dialectes stockent l'adresse de destination dans le bloc de contrôle de protocole de la socket brute, d'autres non.

Lsof ne peut pas toujours représenter les numéros de périphériques Solaris de la même manière que ls(1). Par exemple, les numéros de périphérique majeurs et mineurs que les fonctions lstat(2) et stat(2) rapportent pour le répertoire sur lequel les fichiers CD-ROM sont montés (typiquement /cdrom) ne sont pas les mêmes que ceux qu'il rapporte pour le périphérique sur lequel les fichiers CD-ROM sont montés (typiquement /dev/sr0). (Lsof rapporte les numéros de répertoire.)

La prise en charge des systèmes de fichiers /proc n'est disponible que pour les dialectes BSD et Tru64 UNIX, Linux et les dialectes dérivés de SYSV R4 - par exemple, FreeBSD, NetBSD, OpenBSD, Solaris, UnixWare.

Certains éléments de /proc - numéro de périphérique, numéro d'inode et taille de fichier - ne sont pas disponibles dans certains dialectes. La recherche de fichiers dans un système de fichiers /proc peut nécessiter que le nom de chemin complet soit spécifié.

Aucun descripteur de fichier de texte (txt) n'est affiché pour les processus Linux. Toutes les entrées pour les fichiers autres que le répertoire de travail actuel, le répertoire racine et les descripteurs de fichiers numériques sont étiquetées comme descripteurs mem.

Lsof ne peut pas rechercher les tuyaux nommés Tru64 UNIX par nom, car leur implémentation noyau de lstat(2) renvoie un numéro de périphérique incorrect pour un tuyau nommé.

Lsof ne peut pas rapporter complètement ou correctement les verrous HP-UX 9.01, 10.20 et 11.00 en raison d'un accès insuffisant aux données du noyau ou d'erreurs dans les données du noyau. Voir la FAQ de lsof (la section FAQ donne son emplacement) pour plus de détails.

Le type de fichier SMT d'AIX est une fabrication. Il est créé pour les structures de fichiers dont le type (15) n'est pas défini dans le fichier d'en-tête AIX /usr/include/sys/file.h. Une façon de créer de telles structures de fichiers est d'exécuter des clients X avec la variable DISPLAY définie sur « :0.0 ».

L'option +|-f[cfn] n'est pas prise en charge sous lsof Linux basé sur /proc, car il ne lit pas les structures du noyau à partir de la mémoire du noyau.

définit le chemin d'accès à un fichier cache de périphériques. Voir la section DEVICE CACHE PATH FROM AN ENVIRONMENT VARIABLE pour plus d'informations.
LSOFPERSDCPATH
définit le composant du milieu d'un chemin de cache de périphériques personnel modifié. Voir la section MODIFIED PERSONAL DEVICE CACHE PATH pour plus d'informations.
