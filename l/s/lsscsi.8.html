NOM

lsscsi - lister les périphériques SCSI (ou hôtes), lister les périphériques NVMe

SYNTAXE

lsscsi [--brief] [--classic] [--controllers] [--device] [--generic] [--help] [--hosts] [--kname] [--list] [--long] [--long-unit] [--lunhex] [--no-nvme] [--pdt] [--protection] [--protmode] [--scsi_id] [--size] [--sysfsroot=PATH] [--sz-lbs] [--transport] [--unit] [--verbose] [--version] [--wwn] [H:C:T:L]

DESCRIPTION

Utilise les informations de sysfs (noyau Linux séries 2.6 et plus récentes) pour lister les périphériques SCSI (ou hôtes) actuellement connectés au système. De nombreux périphériques de stockage non-SCSI (mais pas tous) utilisaient le sous-système SCSI sous Linux. Dans la version 0.30 de lsscsi, le support pour lister les périphériques NVMe a été ajouté.

En mode une ligne par périphérique (LU ou espace de noms NVMe), le mode par défaut, chaque ligne commence par un tuple à 4 éléments entouré de crochets. Pour les périphériques SCSI, le premier élément 'H' est le numéro de l'hôte, le deuxième élément 'C' est le numéro du contrôleur, le troisième élément 'T' est le numéro de la cible et le dernier élément est le numéro de l'unité logique (LUN). Tous les quatre sont des entiers. Pour les espaces de noms NVMe, voir les deux paragraphes suivants. Lorsque l'option --hosts est donnée pour les périphériques SCSI, le tuple est réduit à un seul élément : le numéro de l'hôte.

Si un tuple H:C:T:L est donné comme argument sur la ligne de commande, il agit comme un filtre et seuls les périphériques qui correspondent sont listés. Les deux points ne sont pas obligatoires, et '-', '*', '?' ou les composants manquants à la fin sont interprétés comme des jokers. Par défaut, '*:*:*:*' signifie correspondre aux périphériques (c'est-à-dire aux unités logiques). Toute chaîne de filtre utilisant '*' ou '?' doit être entourée de guillemets simples ou doubles pour empêcher les expansions du shell. Si '-' est utilisé comme joker, le tuple de filtre entier doit être préfixé par '-- ' pour indiquer à cet utilitaire qu'il n'y a plus d'options sur la ligne de commande à interpréter. Un '[' initial et un ']' final sont autorisés (par exemple, '[1:0:0]' correspond à toutes les LUNs sur 1:0:0). Peut également être utilisé pour filtrer --hosts, auquel cas seul le H est actif et peut être soit un nombre, soit sous la forme "host<n>" où <n> est un numéro d'hôte.

Pour les périphériques et contrôleurs NVMe, presque tout le paragraphe précédent s'applique. La principale différence est que "N" apparaît dans la position 'H' (la première). La position 'C' pour NVMe est le numéro mineur de périphérique caractère généré par Linux du contrôleur, qui est le premier nombre qui apparaît dans un nom typique de contrôleur NVMe, par exemple : "/dev/nvme2". La position 'T' pour NVMe est la valeur "CNTLID". La dernière position 'L' est l'identifiant de l'espace de noms NVMe, qui est généralement une valeur séquentielle commençant à 1. Le "N" explicite initial pour les périphériques NVMe est converti en interne en une grande valeur (32 767) qui ne devrait pas interférer avec aucun numéro d'hôte SCSI généré par Linux ; cela signifie également que le tri numérique utilisé pour afficher les hôtes (contrôleurs) et les périphériques (LUs ou unités logiques) placera toujours les périphériques et contrôleurs NVMe après ceux qui utilisent le sous-système SCSI. Pour filtrer en utilisant un argument H:C:T:L pour les contrôleurs NVMe, "hostN", "hostN:<num>", "N" ou "N:<num>" peuvent être utilisés ; lorsqu'aucun "<num>" n'est donné, seuls les contrôleurs NVMe seront listés (c'est-à-dire qu'il n'y aura pas d'hôtes SCSI (HBA) listés).

Par défaut dans cet utilitaire, les noms de nœuds de périphériques (par exemple, "/dev/sda" ou "/dev/root_disk") sont obtenus en notant les numéros majeurs et mineurs du périphérique listé obtenus à partir de sysfs (par exemple, le contenu de "/sys/block/sda/dev") puis en recherchant une correspondance dans le répertoire "/dev". Cette "correspondance par majeur et mineur" permettra aux périphériques qui ont reçu un nom différent par udev (par exemple) d'être correctement rapportés par cet utilitaire.

Dans certaines situations, il peut être utile de voir le nom du nœud de périphérique que Linux produirait par défaut, c'est pourquoi l'option --kname est fournie. Un exemple où cela peut être utile est les journaux d'erreurs du noyau qui ont tendance à rapporter les messages d'erreur de disque en utilisant le nom par défaut du noyau du disque.

OPTIONS

Les arguments des options longues sont obligatoires pour les options courtes également. Les options sont arrangées par ordre alphabétique basé sur le nom de l'option longue. Les options longues avec trait d'union peuvent aussi prendre un underscore, et vice versa (par exemple, --scsi_id ou --scsi-id sont acceptables).

-b, --brief
réduit la sortie d'une ligne par périphérique au tuple et au nom du périphérique primaire. Cela peut simplifier les scripts qui traitent la sortie de cet utilitaire. Avec l'option --generic, il affichera sur chaque ligne le tuple (à partir duquel le nom du périphérique de passage bsg peut être déduit), le nom du périphérique primaire (que le sous-système de bloc utilise) et le nom du périphérique sg (également un passage).
Lorsque l'option --pdt est utilisée conjointement avec cette option, le type de périphérique (PDT) SCSI est affiché en hexadécimal (avec un préfixe "0x") entre le tuple et le nom du périphérique primaire. Pour les espaces de noms NVMe, "0x0" est affiché (pour un disque ou un périphérique d'accès direct).
-c, --classic
La sortie est similaire à celle obtenue de 'cat /proc/scsi/scsi'
-C, --controllers
Liste les contrôleurs NVMe et les hôtes SCSI. C'est un synonyme de l'option --hosts.
-d, --device
Après avoir affiché le nom (probable) du périphérique SCSI, les numéros majeur et mineur du nœud de périphérique sont affichés entre crochets (par exemple "/dev/sda[8:0]").
-g, --generic
Affiche le nom du fichier périphérique générique SCSI. Notez que si le pilote sg est un module, il peut devoir être chargé, sinon '-' peut apparaître.
NVMe n'a pas de périphériques génériques (char) dans le même sens que SCSI. Au lieu de cela, les commandes NVMe Admin, NVM (c'est-à-dire les commandes de type bloc comme Read et Write) et MI (Management Interface (par exemple, vers un boîtier)) sont toutes envoyées au contrôleur contenant, dont le nom du périphérique est affiché lorsque l'option --hosts est utilisée.
Pour désencombrer le mode une ligne par périphérique, l'option --brief combinée avec cette option devrait aider.
-h, --help
Affiche le message d'utilisation et quitte.
-H, --hosts
Liste les hôtes SCSI et les contrôleurs NVMe actuellement connectés au système. Si cette option n'est pas donnée (et que l'option --controllers n'est pas donnée), alors les périphériques SCSI (unités logiques (LUs)) suivis des périphériques NVMe (espaces de noms) sont listés.
-k, --kname
Utilise l'algorithme par défaut de Linux pour nommer les périphériques (par exemple, majeur de bloc 8, mineur 0 est "/dev/sda") plutôt que la "correspondance par majeur et mineur" dans le répertoire "/dev" comme discuté ci-dessus.
-L, --list
Affiche des informations supplémentaires sous forme de paires <nom_attribut>=<valeur>, une paire par ligne précédée de deux espaces. Cette option a le même effet que '-lll'.
-l, --long
Affiche des informations supplémentaires pour chaque périphérique (hôte) SCSI. Peut être utilisé plusieurs fois pour plus d'informations, auquel cas la forme courte de l'option est plus pratique (par exemple, '-lll'). Lorsqu'elle est utilisée trois fois (c'est-à-dire '-lll'), elle affiche les attributs du périphérique (hôte) SCSI un par ligne ; précédé de deux espaces ; sous la forme "<nom_attribut>=<valeur>".
-U, --long-unit
Affiche le nom de l'unité logique en entier, si disponible. Il remplace les chaînes habituelles fournisseur, produit et révision données dans le mode d'une ligne par unité logique. Si aucun nom d'unité logique n'est trouvé, "none" est affiché. Si le nom de l'unité logique est long (par exemple, un UUID), les champs suivants sont repoussés plus loin vers la droite selon les besoins. Cette option est fonctionnellement équivalente à l'option '-uuu'.
Si l'option est utilisée deux fois (par exemple, '-UU'), alors les formats EUI, NAA, UUID et identifiant vendeur T10 sont préfixés par "eui.", "naa.", "uuid." et "t10." respectivement. Notez que le format de nom SCSI utilisé par iSCSI devrait déjà être préfixé par 'iqn.'. Utiliser l'option '--unit' 4 fois ou plus (par exemple '-uuuu') aura la même action que '-UU'.
--long_unit est également une forme acceptable lorsqu'elle est dans
vocant cette option.
-x, --lunhex
lorsque cette option est utilisée une fois, le LUN dans le tuple (au début de chaque ligne de périphérique) est affiché au format « T10 », c'est-à-dire jusqu'à 16 chiffres hexadécimaux. Il est préfixé par « 0x » pour distinguer le LUN de la valeur décimale affichée en l'absence de cette option. Les LUNs hiérarchiques sont également affichés avec un caractère « _ » séparant les niveaux. Par exemple, le LUN à deux niveaux : 0x0355006600000000 apparaîtra sous la forme 0x0355_0066. Si cette option est donnée deux fois (par exemple, en utilisant la forme courte : « -xx »), alors les 16 chiffres hexadécimaux complets sont affichés pour chaque LUN, précédés de « 0x ».
Pour NVMe, l'identifiant d'espace de noms (nsid) est affiché dans la position « L ». Le nsid est une quantité non signée de 32 bits avec 0x0 et 0xffffffff réservés. Sans cette option, le nsid est affiché en décimal. Lorsque cette option est utilisée une fois, le nsid est affiché en hexadécimal avec un préfixe 0x et jusqu'à 3 zéros non significatifs. Lorsque cette option est utilisée deux fois, le nsid est affiché en hexadécimal avec jusqu'à 7 zéros non significatifs.
-N, --no-nvme
cette option exclut les périphériques et contrôleurs NVMe de la sortie. Cette option peut être nécessaire pour empêcher la sortie NVMe d'interférer avec une sortie de format spécifique, comme celle produite lorsque l'option --classic est utilisée.
Pour afficher uniquement les périphériques NVMe, utilisez « lsscsi N », pour afficher uniquement les contrôleurs NVMe, utilisez « lsscsi -H N ».
-D, --pdt
cette option affiche le type de périphérique périphérique SCSI (PDT) en hexadécimal, précédé de « 0x ». Pour les espaces de noms NVME, « 0x0 » est affiché, ce qui correspond à un disque (« Périphérique d'accès direct » ou SSD). En sortie sur une seule ligne, ce PDT hexadécimal remplace l'abréviation du type de périphérique (par exemple, « 0x0 » remplace « disk ») et apparaît après le tuple.
-p, --protection
Affiche les types de protection cible (DIF) et initiateur (DIX).
-P, --protmode
Affiche le mode d'information de protection effectif pour chaque périphérique de disque.
-i, --scsi_id
affiche l'identifiant correspondant dérivé d'udev trouvé dans /dev/disk/by-id/scsi* . Ceci concerne uniquement les périphériques de disque (et similaires). Si aucune correspondance n'est trouvée, « dm-uuid-mpath* » et « usb* » sont recherchés dans le même répertoire. S'il n'y a toujours pas de correspondance, le répertoire /sys/class/block/<disk>/holders est recherché. L'identifiant correspondant est imprimé après le nom du périphérique (par exemple, /dev/sdc) et s'il n'y a pas de correspondance, « - » est affiché. Notez que seuls les périphériques de disque (similaires) correspondent à cette option ; ainsi, par exemple, un boîtier SCSI aura un identifiant de '-'.
Avant la révision 164, la première correspondance dans /dev/disk/by-id/scsi* était imprimée. Une modification a été ajoutée à ce moment-là pour vérifier les identifiants dans un ordre spécifique, car certains sont considérés comme « plus forts » que d'autres. Voir la section ORDRE DES IDENTIFIANTS SCSI ci-dessous.
-s, --size
Affiche la capacité du disque sous forme lisible par l'homme. Lorsqu'elle est donnée une fois, les unités SI normales en base 10 sont utilisées comme préfixe pour « B », qui représente les octets (également appelés bytes). Par exemple, Mo, Go et To représentent respectivement 10^6, 10^9 et 10^12 octets. Lorsqu'elle est donnée deux fois, les préfixes IEC 80000-3 pour « B » sont utilisés ; par exemple, Mio, Gio et Tio représentent respectivement 2^20, 2^30 et 2^40 octets. La sortie est arrondie à 3 chiffres significatifs ou moins afin de tenir sur une seule ligne. Elle affiche également la taille des périphériques RBC, des supports CD/DVD et des disques ZBC gérés par l'hôte. Les disques ZBC gérés par l'hôte ont leur « type de périphérique périphérique » défini à 0 (comme les disques normaux), leur taille est donc affichée.
Si elle est donnée trois fois (la forme courte est plus pratique : « -sss »), la capacité du disque est donnée sous forme de nombre de blocs logiques. Il s'agit d'un chiffre exact en décimal signalé par le périphérique de stockage lors de sa découverte. La découverte se fait généralement juste après le démarrage, ou lorsqu'il a été connecté pour la dernière fois si le périphérique de stockage est amovible.
Pour désencombrer le mode d'une ligne par périphérique, l'option --brief combinée à cette option devrait aider.
-y, --sysfsroot=CHEMIN
suppose que sysfs est monté à CHEMIN au lieu de '/sys' par défaut. Si cette option est donnée, CHEMIN doit être un chemin absolu (c'est-à-dire commencer par '/').
-S, --sz-lbs
Affiche la capacité du disque sous forme de nombre de blocs logiques (ce qui est identique à « -sss »). Lorsqu'elle est utilisée deux fois, une virgule est ajoutée, suivie du nombre de blocs logiques en octets. Il doit s'agir d'un nombre comme 512 ou 4096.
Si la taille du bloc logique ne peut pas être trouvée (par exemple, parce que la version de Linux est antérieure au répertoire /sys/block/<dev_name>/queue), alors le nombre de blocs de 512 octets, suivi d'une virgule puis de '512', est affiché, indépendamment de la taille réelle du bloc logique du périphérique. Cette action de cas spécial se produit que cette option soit donnée une ou plusieurs fois.
Pour désencombrer le mode d'une ligne par périphérique, l'option --brief combinée à cette option devrait aider.
-t, --transport
Affiche les informations de transport. Il s'agira d'informations relatives à la cible ou, si --hosts est donné, d'informations relatives à l'initiateur. Lorsqu'elle est utilisée sans --list, un nom ou un identifiant (ou les deux) sont affichés sur une seule ligne, généralement préfixés par le type de transport. Pour les périphériques, ces informations remplacent les chaînes normales du fournisseur, du produit et de la révision. Lorsque l'option --list est également donnée, des lignes multiples de paires attribute_name=value sont en outre affichées, chacune étant indentée de deux espaces. Voir la section sur les transports ci-dessous.
-u, --unit
Affiche le nom de l'unité logique, si disponible. Si cette option est donnée une ou deux fois, le champ de 30 caractères où les chaînes du fournisseur, du produit et de la révision sont habituellement placées est étendu à 32 caractères et remplacé par le nom de l'unité logique. Si aucun nom d'unité logique n'est trouvé, « none » est imprimé. La première chaîne NAA, EUI-64 ou SCSI trouvée est affichée, sauf si une chaîne de nom SCSI est trouvée et que le port cible associé indique le protocole iSCSI, auquel cas la chaîne de nom SCSI est préférée. Enfin, s'il n'y a pas de correspondance avec ce qui précède et qu'un descripteur d'ID de fournisseur T10 est trouvé, alors il est utilisé.
Si le nom ne peut pas tenir dans le champ de 32 caractères, il est tronqué à droite et un caractère « _ » final est utilisé pour alerter le lecteur de la troncature. La largeur de 32 caractères est choisie car elle est suffisamment grande pour contenir des identifiants NAA ou EUI-64 de 16 octets. Cependant, les chaînes de noms SCSI telles qu'utilisées par iSCSI peuvent être plus grandes.
Si cette option est utilisée deux fois, ce champ est également large de 32 caractères. Si le nom de l'unité logique ne peut pas tenir, il sera tronqué à gauche et un caractère « _ » initial sera utilisé pour alerter le lecteur de la troncature.
Si cette option est utilisée trois fois, le nom complet de l'unité logique est affiché, suivi de plusieurs espaces.
Pour que cette option fonctionne, elle nécessite un noyau Linux à partir de 3.15 inclus. Elle accède au fichier sysfs vpd_pg83 pour le périphérique en question. Les anciens équipements SCSI et ATA (SATA) peuvent ne pas fournir ces informations. Si elles sont fournies par ATA (SATA), ce sera le WWN.
-v, --verbose
affiche les noms des répertoires où les informations sont trouvées. Utilisez plusieurs fois pour plus de sortie.
-V, --version
affiche les informations de version puis quitte. Si utilisé une fois, affiche sur stderr ; si utilisé deux fois, affiche sur stdout et raccourcit la date au format numérique yyyymmdd. Le premier nombre dans la chaîne de version est le numéro de publication.
-w, --wwn
affiche le WWN pour les disques au lieu du fabricant, du modèle et de la révision (ou au lieu des informations de transport). Le World Wide Name (WWN) a généralement 64 bits de long (16 chiffres hexadécimaux) mais peut avoir jusqu'à 128 bits de long. Pour indiquer que le WWN est hexadécimal, il est préfixé par « 0x ». Le WWN ATA/SATA est appelé nom LU dans le jargon SCSI ; par conséquent, cette option est plus ou moins remplacée par les options --unit et --long-unit.

TRANSPORTS

Cet utilitaire répertorie les périphériques SCSI connus sous le nom d'unités logiques (LU) dans le modèle d'architecture SCSI (réf : SAM-5 sur https://www.t10.org) ou les hôtes lorsque l'option --hosts est donnée. Un hôte est appelé un initiateur dans SAM-5. Une commande SCSI voyage via un initiateur, à travers un transport vers une cible, puis vers une unité logique. Un périphérique cible peut contenir plusieurs unités logiques. Un périphérique cible possède un ou plusieurs ports qui peuvent être considérés comme des points d'extrémité de transport. Chaque disque FC et SAS est une cible unique qui possède deux ports et contient une unité logique. Si les deux ports de cible d'un disque FC ou SAS sont connectés et visibles par une machine, alors lsscsi affichera deux entrées. Les initiateurs (c'est-à-dire les hôtes) possèdent également un ou plusieurs ports et certains HBA sous Linux ont une entrée hôte par port initiateur, tandis que d'autres ont une entrée hôte par périphérique initiateur.

Lorsque l'option --transport est donnée pour les périphériques (c'est-à-dire que --hosts n'est pas donné), la plupart des informations produites par lsscsi sont associées à la cible, ou plus précisément : au port cible, à travers lequel les commandes SCSI accédant à une unité logique transitent.

En général, cet utilitaire fournit une ligne de sortie par « périphérique » ou hôte. Des informations nettement plus détaillées peuvent être obtenues en ajoutant l'option --list. Lorsqu'elle est utilisée conjointement avec l'option --transport, après la ligne récapitulative, plusieurs lignes d'informations spécifiques au transport sous la forme « <nom_attribut>=<valeur> » sont affichées, chacune indentée de deux espaces. L'utilisation d'un argument de filtre réduira le volume de sortie s'il y a beaucoup de périphériques ou d'hôtes présents.

Les transports actuellement reconnus sont : IEEE 1394, ATA, FC, iSCSI, SAS, SATA, SPI, SRP et USB.

Pour IEEE 1394 (également appelé Firewire et « SBP » lorsqu'il s'agit de stockage), le nom du port cible basé sur EUI-64 est affiché lorsque --transport est donné, en l'absence de l'option --hosts. Lorsque l'option --hosts est donnée, le nom du port initiateur EUI-64 est affiché. La sortie sur la ligne récapitulative spécifique au transport IEEE 1394 est préfixée par « sbp: ».

Pour détecter les périphériques ATA et SATA, une vérification sommaire est effectuée sur le nom du pilote (après que les vérifications pour les autres transports soient épuisées). En fonction du nom du pilote, le type de transport ATA ou SATA est choisi. La sortie sur la ligne récapitulative est soit « ata: », soit « sata: ». A

TRANSPORTS

Pour les périphériques ATA, une recherche est effectuée pour un fichier vpd_pg83 associé dans sysfs. S'il est trouvé, il peut contenir le WWN du périphérique, qui est affiché s'il est présent. Le WWN n'apparaîtra pas dans les noyaux Linux antérieurs à 3.15 et avec les anciens périphériques PATA et SATA. La plupart des périphériques et hôtes marqués comme "ata:" utiliseront le transport parallèle ATA (PATA). Pour les périphériques SATA connectés via un répartiteur SAS, voir le paragraphe SAS ci-dessous.

Pour Fibre Channel (FC), le nom du port et l'identifiant du port sont affichés lorsque l'option --transport est fournie. En l'absence de l'option --hosts, ces identifiants concerneront le port cible associé au périphérique (unité logique) listé. Lorsque l'option --hosts est fournie, les identifiants concerneront le port initiateur utilisé par l'hôte. Les informations sur la ligne de résumé spécifiques au transport FC sont précédées de "fc:". Si FCoE (sur Ethernet) est détecté, le préfixe est modifié en "fcoe:".

Pour iSCSI, le nom du port cible est affiché lorsque l'option --transport est fournie, en l'absence de l'option --hosts. Il est composé du nom iSCSI et de l'étiquette du groupe de portales cibles. Comme le nom iSCSI commence par "iqn", aucun préfixe supplémentaire n'est utilisé. Lorsque l'option --hosts est fournie, seul "iscsi:" est affiché sur la ligne de résumé.

Pour Serial Attached SCSI (SAS), l'adresse SAS du port cible (ou du port initiateur si l'option --hosts est également fournie) est affichée. Il s'agira d'une adresse naa-5. Pour les HBA SAS et les cibles SAS (telles que les disques et lecteurs de bandes SAS), l'adresse SAS sera mondialement unique. Pour les disques SATA connectés à un répartiteur SAS, le répartiteur fournit l'adresse SAS en ajoutant une valeur non nulle à son adresse SAS (c'est-à-dire celle du répartiteur) (par exemple, adresse_sas_répartiteur + id_phy + 1). Les disques SATA directement connectés aux HBA SAS semblent avoir une adresse SAS indéterminée. Les informations sur la ligne de résumé spécifiques au transport SAS sont précédées de "sas:".

Pour les périphériques SATA, voir le paragraphe ci-dessus sur les périphériques ATA. Comme noté dans le paragraphe précédent, les périphériques SATA connectés à des répartiteurs SAS afficheront une adresse de transport SAS fabriquée (par le répartiteur) plutôt que le WWN du périphérique SATA.

Pour l'interface parallèle SCSI (SPI), l'identifiant du port cible (généralement un nombre compris entre 0 et 15 inclus) est affiché lorsque l'option --transport est fournie, en l'absence de l'option --hosts. Lorsque l'option --hosts est fournie, seul "spi:" est affiché sur la ligne de résumé.

Pour le transport PCIe (PCI Express), il existe deux types de stockage possibles : NVMe et SOP/PQI (SCSI sur PCIe). Il existe très peu d'exemples de ce dernier actuellement, donc cet utilitaire se concentre sur NVMe. NVMe utilise son propre jeu de commandes et non SCSI, mais partage de nombreuses choses. Plutôt que de réinventer tout ce qui est actuellement utilisé par SCSI depuis près de 40 ans, NVMe commence à utiliser certaines parties de SCSI. Un exemple récent est la norme SES-3 pour la gestion des boîtiers, qui a été adoptée par NVMe. Dans SCSI, un périphérique SES est une unité logique avec un type de périphérique (PDT) de 0xd (pour le boîtier), il apparaîtra donc lorsque l'utilitaire lsscsi est invoqué sans aucune option. Dans NVMe, il semble qu'un boîtier apparaisse comme connecté à l'interface de gestion (MI) d'un contrôleur NVMe. Cela signifie qu'il devrait apparaître lors de l'invocation de "lsscsi --hosts". On ne sait pas si un tel contrôleur NVMe peut avoir des espaces de noms de stockage associés. L'utilitaire sg_ses (du package sg3_utils) peut alors recevoir le nom du périphérique de ce contrôleur NVMe (par exemple, /dev/nmve1).
Lorsque l'option --transport est fournie, après "pcie", l'identifiant du fournisseur de sous-système et l'identifiant du périphérique du contrôleur NVMe sont affichés, séparés par un deux-points (par exemple, "pcie 0x8086:0x390a").

Pour le protocole SCSI RDMA (SRP), le GUID du port IB (InfiniBand) est donné. Par exemple, il a une forme comme suit : 0002:c903:00fa:abcd.

Lorsqu'un transport USB est détecté, la ligne de résumé contiendra "usb:" suivi d'un nom de périphérique USB. Le nom du périphérique USB a la forme "<b>-<p1>[.<p2>[.<p3>]]:<c>.<i>" où <b> est le numéro du bus USB, <p1> est le port sur l'hôte. <p2> est un port sur un hub connecté à l'hôte, s'il est présent. Si nécessaire, <p3> est un port de hub USB plus proche du périphérique de stockage USB. <c> fait référence au numéro de configuration tandis que <i> est le numéro d'interface. Il existe un hôte SCSI distinct pour chaque cible SCSI USB. Une cible SCSI USB peut contenir plusieurs unités logiques. Ainsi, la même chaîne "usb: <nom_périphérique>" apparaît pour un hôte SCSI USB et toutes les unités logiques appartenant à la cible SCSI USB associée à cet hôte SCSI USB.

LUNS

Pour des raisons historiques et comme utilisé par plusieurs autres systèmes d'exploitation basés sur Unix, Linux utilise un tuple d'entiers pour décrire (un chemin vers) un périphérique SCSI (également connu sous le nom d'unité logique (LU)). Le dernier élément de ce tuple est le soi-disant numéro d'unité logique (LUN). Et à l'origine en SCSI, un LUN était un entier, d'abord de 3 bits, puis de 8, puis de 16 bits. Les LUN SCSI aujourd'hui (SAM-5 section 4.7) font 64 bits, mais les normes SCSI considèrent maintenant un LUN comme un tableau de 8 octets.

Jusqu'en 2013, Linux mappait les LUN SCSI à un entier de 32 bits en prenant les 4 premiers octets du LUN SCSI et en ignorant les 4 derniers octets. Linux traitait les deux premiers octets du LUN SCSI comme une unité (un mot) et cela devenait les 16 bits les moins significatifs de l'entier du LUN Linux. Les deux octets suivants du LUN SCSI devenaient les 16 bits supérieurs de l'entier du LUN Linux. La raison de cela était de garder les LUN couramment utilisés comme de petits entiers de LUN Linux. Le LUN le plus courant (de loin) en notation hexadécimale de LUN SCSI est 00 00 00 00 00 00 00 00 et cela devient l'entier du LUN Linux 0. Le LUN le plus courant ensuite est 00 01 00 00 00 00 00 00 et cela devient l'entier du LUN Linux 1.

En 2013, il a été proposé d'augmenter les LUN Linux à un entier de 64 bits en étendant le mappage décrit ci-dessus. Dans ce cas, toutes les informations qui peuvent être représentées dans un LUN SCSI sont mappées à un entier LUN Linux (64 bits). Et le mappage peut être inversé sans perte d'information.

Cette version de l'utilitaire prend en charge les entiers LUN Linux de 32 et 64 bits. Par défaut, le LUN affiché à la fin du tuple commençant chaque ligne est un LUN Linux sous forme d'entier décimal. Lorsque l'option --lunhex est fournie, le LUN est au format LUN SCSI avec les 8 octets concaténés, la sortie étant en hexadécimal et précédée de '0x'. Le LUN est décodé selon la description de SAM-5 et les zéros de fin (c'est-à-dire les chiffres à droite) ne sont pas affichés. Ainsi, le LUN 0 (c'est-à-dire 00 00 00 00 00 00 00 00) est affiché comme 0x0000 et le LUN 65 (c'est-à-dire 00 41 00 00 00 00 00 00) est affiché comme 0x0041. Si l'option --lunhex est fournie deux fois, les 64 bits complets (c'est-à-dire 16 chiffres hexadécimaux) sont affichés.

Si l'option --lunhex n'est pas donnée sur la ligne de commande, la variable d'environnement LSSCSI_LUNHEX_OPT est vérifiée. Si LSSCSI_LUNHEX_OPT est présente, sa valeur associée devient le nombre de fois où --lunhex est défini en interne. Ainsi, par exemple, 'LSSCSI_LUNHEX_OPT=2 lsscsi' et 'lsscsi -xx' sont équivalents.

ORDRE DES IDENTIFIANTS SCSI

Cette section ne s'applique qu'à l'option --scsi_id et uniquement aux périphériques de type disque (par exemple, pas aux lecteurs de bandes ni aux boîtiers). Il existe potentiellement plusieurs identifiants SCSI et, à partir de la révision 164, ils sont vérifiés dans l'ordre suivant et seul le premier trouvé est affiché.

L'ordre de préférence des identifiants SCSI est le suivant :
3 : Basé sur NAA (Network Address Authority)
2 : Basé sur EUI-64
8 : Chaîne de nom SCSI (par exemple, iSCSI : iqn.1998-01.com.zzware.iscsi:name1)
S : numéro de série de la page VPD SCSI 0x80
1 : Identifiant du fournisseur T10
0 : Spécifique au fournisseur
Les nombres qui précèdent chaque entrée sont les 'Types de descripteurs' SCSI trouvés dans la définition de la page d'identification des périphériques (0x83) dans SPC/-3, SPC/-4 et SPC/-5. Le 'S' n'est bien sûr pas un nombre et fait référence à une page VPD différente : la page du numéro de série VPD (0x80).

Il existe une option plus générale --wwn qui devrait s'appliquer à presque tous les périphériques. Le terme "WWN" (world-wide name) provient des normes ATA et NVMe et correspond au "Logical Unit (LU) name" en SCSI. Le nom LU en SCSI a tendance à changer en fonction du transport. Pour SAS, le nom LU est l'identifiant NAA de l'unité logique.

En outre, il existe les options --unit et --long-unit qui peuvent être utiles pour identifier de manière unique les périphériques de stockage.

NOTES

Les informations pour cette commande sont dérivées du système de fichiers sysfs, qui est supposé être monté sur /sys, sauf indication contraire de l'utilisateur. Les périphériques (pseudo) SCSI qui ont été détectés par le niveau intermédiaire SCSI seront listés même si les pilotes de niveau supérieur requis (c'est-à-dire sd, sr, st, osst ou ch) n'ont pas été chargés. Si le pilote de niveau supérieur approprié n'a pas été chargé, le nom du fichier du périphérique apparaîtra comme '-' plutôt que quelque chose comme '/dev/st0'. Notez que certains périphériques (par exemple, les scanners et les changeurs de supports) n'ont pas de pilote de niveau supérieur principal et ne peuvent être accédés que via un nom de périphérique SCSI générique (sg).

Les périphériques SCSI génériques peuvent également être accédés via le pilote bsg sous Linux. Par défaut, les noms des nœuds de périphérique du pilote bsg sont de la forme '/dev/bsg/H:C:T:L'. Ainsi, par exemple, le périphérique SCSI affiché par cet utilitaire sur une ligne commençant par le tuple '6:0:1:2' pourrait être accédé via le pilote bsg avec le nom de nœud de périphérique '/dev/bsg/6:0:1:2'.

lsscsi version 0.21 ou ultérieure est requis pour afficher correctement les périphériques SCSI dans les noyaux Linux 2.6.26 (et potentiellement ultérieurs) lorsque l'option du noyau CONFIG_SYSFS_DEPRECATED_V2 n'est pas définie.
