LS(1P) Manuel du programmeur POSIX LS(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ls — lister le contenu d'un répertoire

SYNTAXE

ls [-ikqrs] [-glno] [-A|-a] [-C|-m|-x|-1] \
    [-F|-p] [-H|-L] [-R|-d] [-S|-f|-t] [-c|-u] [fichier...]

DESCRIPTION

Pour chaque opérande nommant un fichier d'un type autre qu'un répertoire ou un lien symbolique vers un répertoire, ls écrira le nom du fichier ainsi que toute information associée demandée. Pour chaque opérande nommant un fichier de type répertoire, ls écrira les noms des fichiers contenus dans le répertoire ainsi que toute information associée demandée. Les noms de fichiers commençant par un <point> ('.') et toute information associée ne seront pas écrits, sauf s'ils sont explicitement référencés, que l'option -A ou -a n'est pas fournie, ou qu'une condition définie par l'implémentation provoque leur écriture. Si une ou plusieurs des options -d, -F, ou -l sont spécifiées, et que ni les options -H ni -L ne sont spécifiées, pour chaque opérande nommant un fichier de type lien symbolique vers un répertoire, ls écrira le nom du fichier ainsi que toute information associée demandée. Si aucune des options -d, -F, ou -l n'est spécifiée, ou si les options -H ou -L sont spécifiées, pour chaque opérande nommant un fichier de type lien symbolique vers un répertoire, ls écrira les noms des fichiers contenus dans le répertoire ainsi que toute information associée demandée. Dans chaque cas où les noms des fichiers contenus dans un répertoire sont écrits, si le répertoire contient des liens symboliques, ls évaluera les informations de fichier et le type de fichier comme étant ceux du lien symbolique lui-même, à moins que l'option -L ne soit spécifiée.

Si aucun opérande n'est spécifié, ls se comportera comme si un seul opérande point ('.') avait été spécifié. Si plus d'un opérande est spécifié, ls écrira d'abord les opérandes non-répertoires ; il triera les opérandes répertoires et non-répertoires séparément selon la séquence de tri de la locale courante.

Chaque fois que ls trie des noms de fichiers ou des chemins selon la séquence de tri de la locale courante, si cette séquence de tri n'a pas d'ordre total de tous les caractères (voir le volume Définitions de base de POSIX.1‐2017, Section 7.3.2, LC_COLLATE), alors tout nom de fichier ou chemin qui se trie de manière égale devra être comparé davantage octet par octet en utilisant la séquence de tri pour la locale POSIX.

L'utilitaire ls détectera les boucles infinies ; c'est-à-dire, entrer dans un répertoire précédemment visité qui est un ancêtre du dernier fichier rencontré. Lorsqu'il détecte une boucle infinie, ls écrira un message de diagnostic sur la sortie d'erreur standard et récupérera sa position dans la hiérarchie ou se terminera.

OPTIONS

L'utilitaire ls doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

Les options suivantes doivent être supportées :

-A
Écrire toutes les entrées de répertoire, y compris celles dont le nom commence par un <point> ('.') mais excluant les entrées point et double-point (si elles existent).
-C
Écrire une sortie en plusieurs colonnes de texte avec les entrées triées le long des colonnes, selon la séquence de tri. Le nombre de colonnes de texte et les caractères séparateurs de colonne sont indéfinis, mais devraient être adaptés à la nature du périphérique de sortie. Cette option désactive la sortie au format long.
-F
Ne pas suivre les liens symboliques nommés comme opérandes à moins que les options -H ou -L ne soient spécifiées. Écrire une barre oblique ('/') immédiatement après chaque nom de chemin qui est un répertoire, un astérisque ('*') après chaque fichier exécutable, une barre verticale ('|') après chaque fichier FIFO, et un arobase ('@') après chaque lien symbolique. Pour d'autres types de fichiers, d'autres symboles peuvent être écrits.
-H
Évaluer les informations de fichier et le type de fichier pour les liens symboliques spécifiés sur la ligne de commande comme étant ceux du fichier référencé par le lien, et non le lien lui-même ; cependant, ls écrira le nom du lien lui-même et non le fichier référencé par le lien.
-L
Évaluer les informations de fichier et le type de fichier pour tous les liens symboliques (qu'ils soient nommés sur la ligne de commande ou rencontrés dans une hiérarchie de fichiers) comme étant ceux du fichier référencé par le lien, et non le lien lui-même ; cependant, ls écrira le nom du lien lui-même et non le fichier référencé par le lien. Lorsque -L est utilisé avec -l, écrire le contenu des liens symboliques au format long (voir la section STDOUT).
-R
Lister récursivement les sous-répertoires rencontrés. Lorsqu'un lien symbolique vers un répertoire est rencontré, le répertoire ne sera pas listé récursivement à moins que l'option -L ne soit spécifiée. L'utilisation de -R avec -d ou -f produit des résultats indéfinis.
-S
Trier avec comme clé principale la taille du fichier (par ordre décroissant) et comme clé secondaire le nom du fichier dans la séquence de tri (par ordre croissant).
-a
Écrire toutes les entrées de répertoire, y compris celles dont le nom commence par un <point> ('.').
-c
Utiliser l'heure de la dernière modification des informations d'état du fichier (voir les Définitions de base du volume POSIX.1‐2017, <sys_stat.h>) au lieu de la dernière modification du fichier lui-même pour le tri (-t) ou l'écriture (-l).
-d
Ne pas suivre les liens symboliques nommés comme opérandes à moins que les options -H ou -L ne soient spécifiées. Ne pas traiter les répertoires différemment des autres types de fichiers. L'utilisation de -d avec -R ou -f produit des résultats indéfinis.
-f
Lister les entrées des opérandes de répertoire dans l'ordre où elles apparaissent dans le répertoire. Le comportement pour les opérandes non-répertoires est indéfini. Cette option active -a. Lorsque -f est spécifié, toute occurrence des options -r, -S et -t sera ignorée et toute occurrence des options -A, -g, -l, -n, -o et -s peut être ignorée. L'utilisation de -f avec -R ou -d produit des résultats indéfinis.
-g
Activer l'option -l (ell), mais désactiver l'écriture du nom ou du numéro du propriétaire du fichier. Désactiver les options -C, -m et -x.
-i
Pour chaque fichier, écrire le numéro de série de fichier (voir stat() dans le volume Interfaces système de POSIX.1‐2017).
-k
Définir la taille de bloc pour l'option -s et le décompte de blocs par répertoire écrit pour les options -l, -n, -s, -g et -o (voir la section STDOUT) à 1024 octets.
-l
(La lettre ell.) Ne pas suivre les liens symboliques nommés comme opérandes à moins que les options -H ou -L ne soient spécifiées. Écrire au format long (voir la section STDOUT). Désactiver les options -C, -m et -x.
-m
Format de sortie en flux ; lister les noms de chemin sur la page, séparés par un caractère <virgule> suivi d'un caractère <espace>. Utiliser un caractère <nouvelle ligne> comme terminateur de liste et après la séquence de séparateur lorsqu'il n'y a pas assez de place sur une ligne pour la prochaine entrée de liste. Cette option désactive la sortie au format long.
-n
Activer l'option -l (ell), mais lors de l'écriture de l'utilisateur ou du groupe propriétaire du fichier, écrire l'UID ou le GID numérique du fichier plutôt que le nom d'utilisateur ou de groupe.

er ou groupe respectivement. Désactive les options -C, -m et -x.
-o
Active l'option -l (elle), mais désactive l'écriture du nom ou du numéro du groupe du fichier. Désactive les options -C, -m et -x.
-p
Écrit une barre oblique ('/') après chaque nom de fichier si ce fichier est un répertoire.
-q
Force chaque instance de caractères de nom de fichier non imprimables et de caractères de tabulation à être écrite comme le caractère point d'interrogation ('?'). Les implémentations peuvent fournir cette option par défaut si la sortie est dirigée vers un périphérique terminal.
-r
Inverse l'ordre du tri pour obtenir une séquence de tri inversée, du plus ancien au plus récent, ou de la plus petite taille de fichier à la plus grande, en fonction des autres options fournies.
-s
Indique le nombre total de blocs de système de fichiers consommés par chaque fichier affiché. Si l'option -k est également spécifiée, la taille du bloc sera de 1024 octets ; sinon, la taille du bloc est définie par l'implémentation.
-t
Trie en utilisant comme clé principale le moment de la modification (du plus récent au plus ancien) et comme clé secondaire le nom de fichier selon la séquence de tri. Pour un lien symbolique, le moment utilisé comme clé de tri est celui du lien symbolique lui-même, à moins que ls n'évalue les informations de son fichier pour qu'elles soient celles du fichier référencé par le lien (voir les options -H et -L).
-u
Utilise le moment du dernier accès (voir le volume Définitions de base de POSIX.1‐2017, <sys_stat.h>) au lieu du dernier modification du fichier pour le tri (-t) ou l'écriture (-l).
-x
Identique à -C, sauf que la sortie en plusieurs colonnes de texte est produite avec les entrées triées horizontalement, plutôt que verticalement, dans les colonnes. Cette option désactive la sortie au format long.
-1
(Le chiffre un.) Force la sortie à une entrée par ligne. Cette option ne désactive pas la sortie au format long. (La sortie au format long est activée par -g, -l (elle), -n et -o ; et désactivée par -C, -m et -x.)

Si une option qui active la sortie au format long (-g, -l (elle), -n et -o) est donnée avec une option qui désactive la sortie au format long (-C, -m et -x), cela ne sera pas considéré comme une erreur. La dernière de ces options spécifiées déterminera si la sortie au format long est écrite.

Si -R, -d ou -f sont spécifiés, les résultats de la spécification de ces options mutuellement exclusives sont décrits dans les descriptions de ces options ci-dessus. Si plus d'une des autres options indiquées dans la section SYNOPSIS dans des ensembles mutuellement exclusifs sont données, cela ne sera pas considéré comme une erreur ; la dernière option spécifiée dans chaque ensemble déterminera la sortie.

Notez que si -t est spécifié, -c et -u ne sont pas seulement mutuellement exclusifs l'un avec l'autre, ils sont aussi mutuellement exclusifs avec -S lors de la détermination de l'ordre de tri. Mais même si -S est spécifié après toutes les occurrences de -c, -t et -u, la dernière utilisation de -c ou -u détermine l'horodatage imprimé lors de la production de la sortie au format long.

OPERANDES

L'opérande suivant sera pris en charge :

fichier
Un chemin d'accès à un fichier à écrire. Si le fichier spécifié n'est pas trouvé, un message de diagnostic sera produit sur la sortie d'erreur standard.

STDIN

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de ls :

COLUMNS
Détermine la largeur préférée de l'utilisateur pour la colonne lors de l'écriture de plusieurs colonnes de texte. Si cette variable contient une chaîne représentant un entier décimal, l'utilitaire ls calculera combien de colonnes de noms de fichiers écrire (voir -C) en fonction de la largeur fournie. Si COLUMNS n'est pas définie ou est invalide, un nombre de positions de colonne défini par l'implémentation sera supposé, basé sur la connaissance de l'implémentation du périphérique de sortie. La largeur de colonne choisie pour écrire les noms de fichiers dans un répertoire donné sera constante. Les noms de fichiers ne seront pas tronqués pour tenir dans la sortie en plusieurs colonnes de texte.
LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour les informations de tri des caractères lors de la détermination de la séquence de tri des chemins.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles comme des caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments) et quels caractères sont définis comme imprimables (classe de caractères print).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LC_TIME
Détermine le format et le contenu des chaînes de date et d'heure écrites par ls.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TZ
Détermine le fuseau horaire pour les chaînes de date et d'heure écrites par ls. Si TZ n'est pas définie ou est nulle, un fuseau horaire par défaut non spécifié sera utilisé.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

Le format par défaut consiste à lister une entrée par ligne sur la sortie standard ; les exceptions sont les terminaux ou lorsque l'une des options -C, -m ou -x est spécifiée. Si la sortie est dirigée vers un terminal, le format est défini par l'implémentation.

Lorsque -m est spécifié, le format utilisé pour le dernier élément de la liste sera :

"%s\n", <nom de fichier>

Le format utilisé pour chaque autre élément de la liste sera :

"%s,%s", <nom de fichier>, <séparateur>

où, s'il n'y a pas assez de place pour le prochain élément de la liste pour tenir dans la longueur de ligne actuelle, <séparateur> est une chaîne contenant un caractère <espace> optionnel et un caractère <saut de ligne> obligatoire ; sinon, c'est un seul caractère <espace>.

Si l'option -i est spécifiée, le numéro de série du fichier (voir le volume Définitions de base de POSIX.1‐2017, <sys_stat.h>) sera écrit dans le format suivant avant toute autre sortie pour l'entrée correspondante :

%u ", <numéro de série du fichier>

Si l'option -l est spécifiée, les informations suivantes seront écrites pour les fichiers autres que les fichiers spéciaux de caractères et de blocs :

"%s %u %s %s %u %s %s\n", <permissions du fichier>, <nombre de liens>,
    <nom d'utilisateur propriétaire>, <nom de groupe>, <taille>, <date et heure>,
    <chemin du fichier>

Si l'option -l est spécifiée, les informations suivantes seront écrites pour les fichiers spéciaux de caractères et de blocs :

"%s %u %s %s %s %s %s\n", <permissions du fichier>, <nombre de liens>,
    <nom d'utilisateur propriétaire>, <nom de groupe>, <informations sur le périphérique>, <date et heure>,
    <chemin du fichier>

Dans les deux cas, si le fichier est un lien symbolique et que l'option -L est également spécifiée, ces informations concerneront le fichier résolu à partir du lien symbolique, sauf que le champ <chemin du fichier> contiendra le chemin d'accès du lien symbolique lui-même. Si le fichier est un lien symbolique et que l'option -L n'est pas spécifiée, ces informations concerneront le lien lui-même et le champ <chemin du fichier> sera de la forme :

"%s -> %s", <chemin du lien>, <contenu du lien>

Les options -n, -g et -o utilisent le même format que -l, mais avec les éléments omis et leurs caractères d'espacement associés. Voir la section OPTIONS.

Dans les deux formes -l précédentes, si <nom d'utilisateur propriétaire> ou <nom de groupe> ne peuvent pas être déterminés, ou si -n est donné, ils seront remplacés par leurs valeurs numériques associées en utilisant le format %u.

Le champ <taille> contiendra la valeur qui serait retournée pour le fichier dans le champ st_size de struct stat (voir le volume Définitions de base de POSIX.1‐2017, <sys_stat.h>). Notez que pour certains types de fichiers, cette valeur n'est pas spécifiée.

Le champ <informations sur le périphérique> contiendra des informations définies par l'implémentation associées au périphérique en question.

SYNOPSIS

ls [ -1|-C|-F|-l|-m|-X ] [ -a|-A ] [ -f|-r ] [ -d|-L ] [ -g|-G ] [ -H|-P ] [ -n|-o ] [ -s|-t ] [ -R ] [ -k ] [ -b|-B|-N|-q|-Q ] [ file ... ]

DESCRIPTION

The ls utility shall list information about the specified files. If no files are specified, it shall list the contents of the current directory. If a specified file is a directory, then the contents of that directory are listed. Otherwise, information about the specified file is listed.

The default action is to list the contents of the current directory. The output of ls shall be directed to standard output. The order in which implementations list the contents of directories is unspecified if the file mode, modification time, or inode number is not used for sorting. Otherwise, the order is specified by the option used for sorting.

The information for each file shall be presented in one of the formats defined by the options below.

The following options shall be supported:

-1
List one file per line.
-a
List all entries except for those starting with the character '.' (dot). When listing the contents of directories, the default entries `.’ (dot) and `..’ (dot-dot) shall not be listed, unless -a is specified.
-A
List all entries except for those starting with the character '.' (dot). When listing the contents of directories, the default entries `.’ (dot) and `..’ (dot-dot) shall not be listed, unless -a is specified.
-b
Print quoted C-style escapes for non-graphic characters. Use the B argument for -N.
-B
Print quoted C-style escapes for nongraphic characters. Use the B argument for -N.
-C
List files in columns. This is the default when standard output is a terminal.
-d
List directories themselves, not their contents. This option affects only what happens when a file operand is a directory.
-f
Do not sort. List files in the order they appear in the directory. This option implies -a.
-F
Append a flag to each file name indicating its type. Possible flags are:
*
Regular file executable by the current user.
/
Directory.
@
Symbolic link.
|
FIFO.
=
Socket.
Implementations may add other flags.
-g
Suppress the owner column. This option implies -l.
-G
Do not print group information. This option implies -l.
-H
If a symbolic link referencing a file of a type other than directory is specified on the command line, ls shall follow the symbolic link, and the type indicated shall be that of the file referenced by the link. Otherwise, if a symbolic link is specified on the command line, ls shall not follow it. This option is used for symbolic links specified on the command line, not for those encountered during the traversal of a directory tree.
-k
Display block counts in 1024-byte units. Otherwise, the block counts are in 512-byte units.
-l
Long listing format. The format is described below.
-L
Follow symbolic links. If a symbolic link is specified on the command line, ls shall follow it, and the type indicated shall be that of the file referenced by the link. If a symbolic link is encountered during the traversal of a directory tree, ls shall follow it, and the type indicated shall be that of the file referenced by the link.
-m
List files in multi-column format, sorted horizontally. Use the -x option for sorted files.
-n
List numeric User IDs and Group IDs. This option implies -l.
-N
Print names without quoting C-style escapes for non-graphic characters. Use the B argument for -N.
-o
Suppress group information. This option implies -l.
-P
Never follow symbolic links. This is the default behavior.
-q
Print a question mark ('?') for nongraphic characters. This is the default for the -N option.
-Q
Quote filenames. This is the default for the -N option.
-r
Reverse the order of the sort.
-R
Recursively list subdirectories encountered.
-s
Display block counts for each file. The counts are measured in the same units as that used for the -k option. In the POSIX locale, the first character of the output line shall be used for sorting if the -t option is specified.
-t
Sort by modification time, newest first.
-X
List files in multi-column format, sorted horizontally. Use the -x option for sorted files.

The options -1, -C, -m, and -X are mutually exclusive.

The options -a and -A are mutually exclusive.

The options -d and -L are mutually exclusive.

The options -g and -G are mutually exclusive.

The options -H and -P are mutually exclusive.

The options -n and -o are mutually exclusive.

The options -s and -t are mutually exclusive.

The options -b, -B, -N, -q, and -Q are mutually exclusive.

If any of the -l, -n, -g, or -o options is specified, the following information shall be written for each file:

"%s%s%s%s%s %lu %-10s %-10s %8", <file mode>,
    <number of hard links>, <user name>, <group name>,
    <file size>, <modification date>, <file name>

The <modification date> shall be the last modification date of the file. In the POSIX locale, the format shall be:

date "+%b %e %H:%M"

if the file has been modified in the last six months, or:

date "+%b %e %Y"

(where two characters are used between %e and %Y) if the file has not been modified in the last six months or if the modification date is in the future, except that, in both cases, the final produced by date shall not be included and the output shall be as if the date command were executed at the time of the last modification date of the file rather than the current time. When the LC_TIME locale category is not set to the POSIX locale, a different format and order of presentation of this field may be used.

If the pathname was specified as a file operand, it shall be written as specified.

The file mode written under the -l, -n, -g, and -o options shall consist of the following format:

"%c%s%s%s%s", <entry type>, <owner permissions>,
    <group permissions>, <other permissions>,
    <optional alternate access method flag>

The <optional alternate access method flag> shall be the empty string if there is no alternate or additional access control method associated with the file; otherwise, it shall be a string containing a single printable character that is not a .

The <entry type> character shall describe the type of file, as follows:

d
Directory.
b
Block special file.
c
Character special file.
l (ell)
Symbolic link.
p
FIFO.
-
Regular file.

Implementations may add other characters to this list to represent other implementation-defined file types.

The next three fields shall be three characters each:

<owner permissions>

Permissions for the file owner class (see the Base Definitions volume of POSIX.1‐2017, Section 4.5, File Access Permissions).
<group permissions>

Permissions for the file group class.
<other permissions>

Permissions for the file other class.

Each field shall have three character positions:

1.
If 'r', the file is readable; if '-', the file is not readable.
2.
If 'w', the file is writable; if '-', the file is not writable.
3.
The first of the following that applies:
S
If in <owner permissions>, the file is not executable and set-user-ID mode is set. If in <group permissions>, the file is not executable and set-group-ID mode is set.
s
If in <owner permissions>, the file is executable and set-user-ID mode is set. If in <group permissions>, the file is executable and set-group-ID mode is set.
T
If in <other permissions> and the file is a directory, search permission is not granted to others, and the restricted deletion flag is set.
t
If in <other permissions> and the file is a directory, search permission is granted to others, and the restricted deletion flag is set.
x
The file is executable or the directory is searchable.
-
None of the attributes of 'S', 's', 'T', 't', or 'x' applies.

Implementations may add other characters to this list for the third character position. Such additions shall, however, be written in lowercase if the file is executable or searchable, and in uppercase if it is not.

If any of the -l, -n, -s, -g, or -o options is specified, each list of files within the directory shall be preceded by a status line indicating the number of file system blocks occupied by files in the directory in 512-byte units if the -k option is not specified, or 1024-byte units if the -k option is specified, rounded up to the next integral number of units, if necessary. In the POSIX locale, the format shall be:

"total %u\n", <number of units in the directory>

If more than one directory, or a combination of non-directory files and directories are written, either as a result of specifying multiple operands, or the -R option, each list of files within a directory shall be preceded by:

"\n%s:\n", <directory name>

If this string is the first thing to be written, the first shall not be written. This output shall precede the number of units in the directory.

If the -s option is given, each file shall be written with the number of blocks used by the file. Along with -C, -1, -m, or -x, the number and a shall precede the filename; with -l, -n, -g, or -o, they shall precede each line describing a file.

STDERR

APPLICATION USAGE

Many implementations use the ('=') to denote sockets bound to the file system for the -F option. Similarly, many historical implementations use the 's' character to denote sockets as the entry type characters for the -l option.

It is difficult for an application to use every part of the file modes field of ls -l in a portable manner. Certain file types and executable bits are not guaranteed to be exactly as shown, as implementations may have extensions. Applications can use this field to pass directly to a user printout or prompt, but actions based on its contents should generally be deferred, instead, to the test utility.

The output of ls (with the -l and related options) contains information that logically could be used by utilities such as chmod and touch to restore files to a known state. However, this information is presented in a format that cannot be used directly by those utilities or be easily translated into a format that can be used. A character has been added to the end of the permissions string so that applications at least have an indication that they may be working in an area they do not understand instead of assuming that they can translate the permissions string into something that can be used. Future versions or related documents may define one or more specific characters to be used based on different standard additional or alternative access control mechanisms.

As with many of the utilities that deal with filenames, the output of ls for multiple files or in one of the long listing formats must be used carefully on systems where filenames can contain embedded white space. Systems and system administrators should institute policies and user training to limit the use of such filenames.

The number of disk blocks occupied by the file that it reports varies depending on underlying file system type, block size units reported, and the method of calculating the number of blocks. On some file system types, the number is the actual number of blocks occupied by the file (counting indirect blocks and ignoring holes in the file); on others it is calculated based on the file size (usually making an allowance for indirect blocks, but ignoring holes).

An example of a small directory tree being fully listed with ls -laRF a in the POSIX locale:

total 11
drwxr-xr-x   3 fox      prog          64 Jul  4 12:07 ./
drwxrwxrwx   4 fox      prog        3264 Jul  4 12:09 ../
drwxr-xr-x   2 fox      prog          48 Jul  4 12:07 b/
-rwxr--r--   1 fox      prog         572 Jul  4 12:07 foo*
a/b:
total 4
drwxr-xr-x   2 fox      prog          48 Jul  4 12:07 ./
drwxr-xr-x   3 fox      prog          64 Jul  4 12:07 ../
-rw-r--r--   1 fox      prog         700 Jul  4 12:07 bar

RATIONALE

Some historical implementations of the ls utility show all entries in a directory except dot and dot-dot when a superuser invokes ls without specifying the -a option. When ``normal'' users invoke ls without specifying -a, they should not see information about any files with names beginning with a unless they were named as file operands.

Implementations are expected to traverse arbitrary depths when processing the -R option. The only limitation on depth should be based on running out of physical storage for keeping track of untraversed directories.

The -1 (one) option was historically found in BSD and BSD-derived implementations only. It is required in this volume of POSIX.1‐2017 so that conforming applications might ensure that output is one entry per line, even if the output is to a terminal.

RATIONALE

L'option -S a été ajoutée dans le problème 7, mais avait été fournie par plusieurs implémentations pendant de nombreuses années. La description donnée dans les documents standard reflète la pratique historique, mais ne correspond pas à une grande partie de la documentation qui décrivait son comportement. La documentation historique la décrivait typiquement comme quelque chose comme:

-S
Trier par taille (taille la plus grande en premier) au lieu de par nom. Les périphériques à caractères spéciaux (listés en dernier) sont triés par nom.

même si le type de fichier n'a jamais été pris en compte lors du tri de la sortie. Les fichiers spéciaux de caractères sont généralement triés vers la fin de la liste car leur taille de fichier sur la plupart des implémentations est nulle. Mais ils sont triés alphabétiquement avec tous les autres fichiers qui ont par hasard la même taille de fichier (zéro), et non triés séparément et ajoutés à la fin.

Ce volume de POSIX.1‐2017 est fréquemment silencieux sur ce qui se passe lorsque des options mutuellement exclusives sont spécifiées. À l'exception de -R, -d et -f, l'utilitaire ls est obligé d'accepter plusieurs options de chaque ensemble d'options mutuellement exclusives sans les considérer comme des erreurs et d'utiliser le comportement spécifié par la dernière option donnée dans chaque ensemble mutuellement exclusif. Puisque ls est l'une des commandes les plus aliassées, il est important que l'implémentation agisse de manière intuitive. Par exemple, si l'alias était:

alias ls="ls -C"

et que l'utilisateur tapait ls -1 (un), une sortie en colonne texte unique devrait en résulter, pas une erreur.

Les options -g, -l (ell), -n et -o ne sont pas des options mutuellement exclusives. Elles activent toutes la sortie au format long. Elles travaillent ensemble pour déterminer si le propriétaire du fichier est écrit (non si -g est présent), le groupe du fichier est écrit (non si -o est présent), et si le groupe ou le propriétaire du fichier est écrit, si c'est le nom (par défaut) ou une représentation textuelle du numéro UID ou GID (si -n est présent) qui est écrit. Les options -C, -m, -x et -1 (un) sont mutuellement exclusives et les trois premières désactivent la sortie au format long. L'option -1 (un) ne modifie pas directement si la sortie au format long est activée ou non, mais en remplaçant -C, -m et -x, elle peut réactiver le format long qui avait été désactivé par l'une de ces options.

Les versions antérieures de cette norme ne décrivaient pas l'option BSD -A (similaire à -a, mais point et double point ne sont pas écrits). Elle a été ajoutée en raison de son implémentation répandue.

Les implémentations peuvent faire de -q la valeur par défaut pour les terminaux afin d'empêcher les attaques par cheval de Troie sur les terminaux avec des séquences d'échappement spéciales. Ceci n'est pas requis car:

*
Certains caractères de contrôle peuvent être utiles sur certains terminaux ; par exemple, un système pourrait les écrire comme "\001" ou "^A".
*
Le comportement spécial pour les terminaux n'est pas pertinent pour la portabilité des applications.

Une proposition initiale spécifiait que le <indicateur de méthode d'accès optionnelle alternative> devait être '+' s'il y avait une méthode d'accès alternative utilisée sur le fichier ou <espace> s'il n'y en avait pas. Ceci a été modifié pour être un <espace> s'il n'y en a pas et un seul caractère imprimable s'il y en a. Cela a été fait pour trois raisons:

1.
Il existe des implémentations historiques utilisant des caractères autres que '+'.
2.
Il existe des implémentations qui varient ce caractère utilisé dans cette position pour distinguer entre diverses méthodes d'accès alternatives en cours d'utilisation.
3.
Les développeurs du standard ne voulaient pas exclure les spécifications futures qui pourraient nécessiter un moyen de spécifier plus d'une méthode d'accès alternative.

Néanmoins, les implémentations fournissant une seule méthode d'accès alternative sont encouragées à utiliser '+'.

Les versions antérieures de cette norme ne disposaient pas de l'option -k, ce qui signifiait que l'option -s ne pouvait pas être utilisée de manière portable car sa taille de bloc était définie par l'implémentation, et les unités utilisées pour spécifier le nombre de blocs occupés par les fichiers dans un répertoire dans une liste ls -l étaient fixées à des unités de 512 octets. L'option -k a été ajoutée pour fournir un moyen d'utiliser l'option -s de manière portable, et par souci de cohérence, elle modifie également les unités susmentionnées de 512 octets à 1024 octets.

Le champ <date et heure> au format -l est spécifié uniquement pour la locale POSIX. Comme noté, le format peut être différent dans d'autres locales. Il n'existe aucun mécanisme pour définir cela dans ce volume de POSIX.1‐2017, car le véhicule approprié est un système de messagerie ; c'est-à-dire que le format doit être spécifié comme un « message ».

FUTURE DIRECTIONS

L'autorisation pour -f d'ignorer les options -A, -g, -l, -n, -o et -s pourrait être supprimée dans une future version.

Une future version de cette norme pourrait exiger que si la séquence de classement pour la locale actuelle n'a pas d'ordre total de tous les caractères, tous les noms de fichiers ou de chemins qui se classent de manière égale seront comparés davantage octet par octet en utilisant la séquence de classement pour la locale POSIX.
