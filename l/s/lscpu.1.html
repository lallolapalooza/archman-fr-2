LSCPU(1) Commandes utilisateur LSCPU(1)

NOM

lscpu - afficher des informations sur l'architecture du CPU

SYNOPIS

lscpu [options]

DESCRIPTION

lscpu collecte des informations sur l'architecture du CPU à partir de sysfs, de /proc/cpuinfo et de toute bibliothèque spécifique à l'architecture applicable (par exemple, librtas sur Powerpc). La sortie de la commande peut être optimisée pour l'analyse ou pour une lecture facile par les humains. Les informations incluent, par exemple, le nombre de CPUs, de threads, de cœurs, de sockets et de nœuds de mémoire non uniforme (NUMA). Il y a également des informations sur les caches du CPU et le partage des caches, la famille, le modèle, les BogoMIPS, l'ordre des octets et le pas.

Le formatage de sortie par défaut sur un terminal est sujet à modification et peut être optimisé pour une meilleure lisibilité. La sortie pour les non-terminaux (par exemple, les pipes) n'est jamais affectée par cette optimisation et est toujours au format "Champ: donnée\n". Utilisez par exemple "lscpu | less" pour voir la sortie par défaut sans optimisations.

Dans les environnements virtualisés, les informations sur l'architecture du CPU affichées reflètent la configuration du système d'exploitation invité, qui est généralement différente du système physique (hôte). Sur les architectures qui prennent en charge la récupération des informations de topologie physique, lscpu affiche également le nombre de sockets physiques, de puces, de cœurs dans le système hôte.

Les options qui aboutissent à un tableau de sortie ont un argument liste. Utilisez cet argument pour personnaliser la sortie de la commande. Spécifiez une liste d'étiquettes de colonnes séparées par des virgules pour limiter le tableau de sortie aux seules colonnes spécifiées, disposées dans l'ordre spécifié. Voir COLUMNS pour une liste d'étiquettes de colonnes valides. Les étiquettes de colonnes ne sont pas sensibles à la casse.

Toutes les colonnes ne sont pas prises en charge sur toutes les architectures. Si une colonne non prise en charge est spécifiée, lscpu imprime la colonne mais ne fournit aucune donnée pour celle-ci.

Les tailles de cache sont rapportées comme un résumé de tous les CPUs. Les versions antérieures à v2.34 rapportaient les tailles par cœur, mais cette sortie était confuse en raison de la topologie complexe des CPUs et de la manière dont les caches sont partagés entre les CPUs. Pour plus de détails sur les caches, voir --cache. Depuis la version v2.37, lscpu suit les identifiants de cache tels que fournis par le noyau Linux et ne commence pas toujours à zéro.

OPTIONS

-a, --all

Inclut les lignes pour les CPUs en ligne et hors ligne dans la sortie (par défaut pour -e). Cette option ne peut être spécifiée qu'avec l'option -e ou -p.

-B, --bytes

Imprime les tailles en octets plutôt que dans un format lisible par l'homme.

Par défaut, l'unité dans laquelle les tailles sont exprimées est l'octet, et les préfixes d'unité sont en puissance de 2^10 (1024). Les abréviations des symboles sont tronquées afin d'atteindre une meilleure lisibilité, en affichant seul le premier caractère de chacun d'eux ; exemples : "1 Kio" et "1 Mio" sont respectivement affichés comme "1 K" et "1 M", omettant ainsi à dessein la mention "iO", qui fait partie de ces abréviations.

-b, --online

Limite la sortie aux CPUs en ligne (par défaut pour -p). Cette option ne peut être spécifiée qu'avec l'option -e ou -p.

-C, --caches[=liste]

Affiche les détails sur les caches CPU. Pour les détails sur les informations disponibles, voir la sortie de --help.

Si l'argument liste est omis, toutes les colonnes pour lesquelles des données sont disponibles sont incluses dans la sortie de la commande.

Lors de la spécification de l'argument liste, la chaîne de caractères de l'option, du signe égal (=) et de la liste ne doit contenir aucun espace ou autre espace blanc. Exemples : -C=NOM,TAILLE-UNE ou --caches=NOM,TAILLE-UNE.

La liste par défaut des colonnes peut être étendue si la liste est spécifiée dans le format +liste (par exemple, lscpu -C=+POLITIQUE-ALLOCATION).

-c, --offline

Limite la sortie aux CPUs hors ligne. Cette option ne peut être spécifiée qu'avec l'option -e ou -p.

--hierarchic[=quand]

Utilise des sous-sections dans la sortie récapitulative. Pour des raisons de compatibilité ascendante, le comportement par défaut est d'utiliser des sous-sections uniquement lors de la sortie sur un terminal et une sortie aplatie sur un non-terminal. L'argument optionnel quand peut être jamais, toujours ou auto. Si l'argument quand est omis, il prend par défaut la valeur "toujours".

-e, --extended[=liste]

Affiche les informations CPU dans un format lisible par l'homme.

Si l'argument liste est omis, les colonnes par défaut sont incluses dans la sortie de la commande. La sortie par défaut est sujette à modification.

Lors de la spécification de l'argument liste, la chaîne de l'option, du signe égal (=) et de la liste ne doit contenir aucun espace ou autre espace blanc. Exemples : '-e=cpu,node' ou '--extended=cpu,node'.

La liste par défaut des colonnes peut être étendue si la liste est spécifiée dans le format +liste (par exemple, lscpu -e=+MHZ).

-J, --json

Utilise le format de sortie JSON pour le résumé par défaut ou la sortie étendue (voir --extended). Pour la compatibilité ascendante, la sortie JSON suit le comportement de résumé par défaut pour les non-terminaux (par exemple, les pipes) où les sous-sections sont manquantes. Voir également --hierarchic.

-p, --parse[=liste]

Optimise la sortie de la commande pour une analyse facile.

Si l'argument liste est omis, la sortie de la commande est compatible avec les versions antérieures de lscpu. Dans ce format compatible, deux virgules sont utilisées pour séparer les colonnes de cache CPU. Si aucun cache CPU n'est identifié, la colonne de cache est omise. Si l'argument liste est utilisé, les colonnes de cache sont séparées par deux-points (:).

Lors de la spécification de l'argument liste, la chaîne de l'option, du signe égal (=) et de la liste ne doit contenir aucun espace ou autre espace blanc. Exemples : '-p=cpu,node' ou '--parse=cpu,node'.

La liste par défaut des colonnes peut être étendue si la liste est spécifiée dans le format +liste (par exemple, lscpu -p=+MHZ).

-r, --raw

Produit la sortie dans son format brut. Cette option n'est applicable qu'aux sorties --extended, --parse et --caches.

-s, --sysroot répertoire

Collecte les données CPU pour une instance Linux autre que celle à partir de laquelle la commande lscpu est émise. Le répertoire spécifié est la racine du système de l'instance Linux à inspecter.

-x, --hex

Utilise des masques hexadécimaux pour les ensembles de CPUs (par exemple "ff"). Par défaut, les ensembles sont affichés sous forme de liste (par exemple 0,1). Notez qu'avant la version 2.30, le masque était affiché avec le préfixe 0x.

-y, --physical

Affiche les identifiants physiques pour toutes les colonnes avec des éléments de topologie (cœur, socket, etc.). Contrairement aux identifiants logiques, qui sont attribués par lscpu, les identifiants physiques sont des valeurs spécifiques à la plateforme fournies par le noyau. Les identifiants physiques ne sont pas nécessairement uniques et ils pourraient ne pas être disposés séquentiellement. Si le noyau ne parvient pas à récupérer un identifiant physique pour un élément, lscpu affiche le caractère tiret (-).

Les numéros logiques des CPUs ne sont pas affectés par cette option.

--output-all

Affiche toutes les colonnes disponibles. Cette option doit être combinée avec soit --extended, --parse, soit --caches.

BOGUES

L'aperçu de base des modèles de CPU est basé sur des heuristiques, prenant en compte les différences telles que les noms des modèles de CPU et les identifiants d'implémentation. Dans certains cas (inhabituels), les CPUs peuvent se différencier par des drapeaux ou des BogoMIPS, mais ces différences sont ignorées dans l'aperçu de lscpu.

Parfois, dans Xen Dom0, le noyau rapporte des données incorrectes.

Sur du matériel virtuel, le nombre de cœurs par socket, etc., peut être incorrect.
