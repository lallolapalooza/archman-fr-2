LSEEK(3P) Manuel du programmeur POSIX LSEEK(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

lseek — déplace le curseur de lecture/écriture de fichier

SYNOPSIS

#include <unistd.h>
off_t lseek(int fildes, off_t offset, int whence);

DESCRIPTION

La fonction lseek() positionne le curseur de fichier pour la description de fichier ouverte associée au descripteur de fichier fildes, comme suit :

*
Si whence est SEEK_SET, le curseur de fichier est positionné à offset octets.
*
Si whence est SEEK_CUR, le curseur de fichier est positionné à son emplacement actuel plus offset.
*
Si whence est SEEK_END, le curseur de fichier est positionné à la taille du fichier plus offset.

Les constantes symboliques SEEK_SET, SEEK_CUR et SEEK_END sont définies dans <unistd.h>.

Le comportement de lseek() sur des périphériques incapables de recherche est défini par l'implémentation. La valeur du curseur de fichier associé à un tel périphérique n'est pas définie.

La fonction lseek() permet de positionner le curseur de fichier au-delà de la fin des données existantes dans le fichier. Si des données sont écrites ultérieurement à cet emplacement, les lectures subséquentes de données dans l'espace vide renverront des octets de valeur 0 jusqu'à ce que des données soient effectivement écrites dans cet espace.

La fonction lseek() ne doit pas, par elle-même, étendre la taille d'un fichier.

Si fildes fait référence à un objet de mémoire partagée, le résultat de la fonction lseek() n'est pas spécifié.

Si fildes fait référence à un objet de mémoire typé, le résultat de la fonction lseek() n'est pas spécifié.

VALEUR DE RETOUR

En cas de succès, le curseur résultant, mesuré en octets depuis le début du fichier, est renvoyé. Sinon, -1 est renvoyé, errno est défini pour indiquer l'erreur, et le curseur de fichier reste inchangé.

ERREURS

La fonction lseek() échouera si :

EBADF
L'argument fildes n'est pas un descripteur de fichier ouvert.
EINVAL
L'argument whence n'a pas une valeur correcte, ou le curseur de fichier résultant serait négatif pour un fichier régulier, un fichier spécial de bloc ou un répertoire.
EOVERFLOW
Le curseur de fichier résultant serait une valeur qui ne peut pas être représentée correctement dans un objet de type off_t.
ESPIPE
L'argument fildes est associé à un tube (pipe), un FIFO ou une socket.

RATIONALE

La norme ISO C inclut les fonctions fgetpos() et fsetpos(), qui fonctionnent sur de très grands fichiers grâce à un type de positionnement spécial.

Bien que lseek() puisse positionner le curseur de fichier au-delà de la fin du fichier, cette fonction n'étend pas par elle-même la taille du fichier. Tandis que seules les fonctions write(), truncate() et ftruncate() peuvent étendre directement la taille d'un fichier dans POSIX.1‐2008, plusieurs fonctions dérivées à l'origine de la norme ISO C, telles que fwrite(), fprintf(), etc., peuvent le faire (en provoquant des appels à write()).

Un curseur de fichier invalide qui provoquerait le retour de [EINVAL] peut être défini par l'implémentation et dépendre du périphérique (par exemple, la mémoire peut avoir peu de valeurs invalides). Un curseur de fichier négatif peut être valide pour certains périphériques dans certaines implémentations.

La norme POSIX.1‐1990 n'interdisait pas spécifiquement à lseek() de renvoyer un curseur négatif. Par conséquent, une application devait effacer errno avant l'appel et vérifier errno au retour pour déterminer si une valeur de retour de (off_t)-1 était un curseur négatif ou une indication d'une condition d'erreur. Les développeurs de la norme ne souhaitaient pas imposer cette action à une application conforme, et ont choisi d'exiger que errno soit défini à [EINVAL] lorsque le curseur de fichier résultant serait négatif pour un fichier régulier, un fichier spécial de bloc ou un répertoire.
