NOM

lspci - lister tous les périphériques PCI

SYNTAXE

lspci [options]

DESCRIPTION

lspci est un utilitaire permettant d'afficher des informations sur les bus PCI du système et les périphériques qui y sont connectés.

Par défaut, il affiche une liste brève des périphériques. Utilisez les options décrites ci-dessous pour demander une sortie plus détaillée ou une sortie destinée à être analysée par d'autres programmes.

Si vous prévoyez de signaler des bogues dans les pilotes de périphériques PCI ou dans lspci lui-même, veuillez inclure la sortie de "lspci -vvx" ou mieux encore "lspci -vvxxx" (cependant, voir ci-dessous pour les mises en garde possibles).

Certaines parties de la sortie, en particulier dans les modes très verbeux, ne sont probablement compréhensibles que par des hackers PCI expérimentés. Pour des définitions exactes des champs, veuillez consulter les spécifications PCI ou les fichiers d'inclusion header.h et /usr/include/linux/pci.h.

L'accès à certaines parties de l'espace de configuration PCI est restreint aux utilisateurs root sur de nombreux systèmes d'exploitation, de sorte que les fonctionnalités de lspci disponibles pour les utilisateurs normaux sont limitées. Cependant, lspci fait de son mieux pour afficher autant d'informations que possible et marque toutes les autres informations avec le texte <accès refusé>.

OPTIONS

Modes d'affichage de base

-m
Affiche les données des périphériques PCI dans un format lisible par machine et rétrocompatible. Voir ci-dessous pour les détails.
-mm
Affiche les données des périphériques PCI dans un format lisible par machine pour une analyse facile par des scripts. Voir ci-dessous pour les détails.
-t
Affiche un diagramme en arbre contenant tous les bus, ponts, périphériques et leurs connexions.

Options d'affichage

-v
Soyez verbeux et affichez des informations détaillées sur tous les périphériques.
-vv
Soyez très verbeux et affichez plus de détails. Ce niveau inclut tout ce qui est jugé utile.
-vvv
Soyez encore plus verbeux et affichez tout ce que nous sommes capables d'analyser, même si cela ne semble pas intéressant du tout (par exemple, des régions mémoire indéfinies).
-k
Affiche les pilotes du noyau gérant chaque périphérique ainsi que les modules du noyau capables de le gérer. Activé par défaut lorsque -v est donné en mode de sortie normal. (Fonctionne actuellement uniquement sous Linux avec le noyau 2.6 ou plus récent.)
-x
Affiche une image hexadécimale de la partie standard de l'espace de configuration (les 64 premiers octets ou 128 octets pour les ponts CardBus).
-xxx
Affiche une image hexadécimale de tout l'espace de configuration PCI. N'est disponible que pour l'utilisateur root, car plusieurs périphériques PCI plantent lorsque vous essayez de lire certaines parties de l'espace de configuration (ce comportement ne viole probablement pas la norme PCI, mais il est au moins très stupide). Cependant, de tels périphériques sont rares, donc vous ne devriez pas trop vous en inquiéter.
-xxxx
Affiche une image hexadécimale de l'espace de configuration PCI étendu (4096 octets) disponible sur les bus PCI-X 2.0 et PCI Express.
-b
Vue centrée sur le bus. Affiche tous les numéros d'IRQ et les adresses tels que vus par les cartes sur le bus PCI, plutôt que tels que vus par le noyau.
-D
Affiche toujours les numéros de domaine PCI. Par défaut, lspci supprime ces numéros sur les machines qui n'ont que le domaine 0.
-P
Identifie les périphériques PCI par leur chemin à travers chaque pont, au lieu de leur numéro de bus.
-PP
Identifie les périphériques PCI par leur chemin à travers chaque pont, affichant le numéro de bus ainsi que le numéro de périphérique.

Options pour contrôler la résolution des ID en noms

-n
Affiche les codes de vendeur et de périphérique PCI sous forme numérique au lieu de les rechercher dans la liste PCI ID.
-nn
Affiche les codes de vendeur et de périphérique PCI sous forme numérique et par leur nom.
-q
Utilise DNS pour interroger la base de données centrale des ID PCI si un périphérique n'est pas trouvé dans le fichier local pci.ids. Si la requête DNS réussit, le résultat est mis en cache dans $XDG_CACHE_HOME/pci-ids et il est reconnu lors des exécutions ultérieures, même si -q n'est plus donné. Veuillez utiliser ce commutateur dans les scripts automatisés avec prudence afin d'éviter de surcharger les serveurs de la base de données.
-qq
Identique à -q, mais le cache local est réinitialisé.
-Q
Interroge la base de données centrale même pour les entrées qui sont reconnues localement. Utilisez cette option si vous suspectez que l'entrée affichée est incorrecte.

Options pour la sélection des périphériques

-s [[[[<domaine>]:]<bus>]:][<périphérique>][.<fonction>]]
Affiche uniquement les périphériques du domaine spécifié (si votre machine a plusieurs ponts hôtes, ils peuvent partager un espace de numéros de bus commun ou chacun d'eux peut adresser son propre domaine PCI ; les domaines sont numérotés de 0 à ffff), bus (0 à ff), périphérique (0 à 1f) et fonction (0 à 7). Chaque composant de l'adresse du périphérique peut être omis ou défini sur "*", les deux signifiant "toute valeur". Tous les nombres sont hexadécimaux. Par exemple, "0:" signifie tous les périphériques sur le bus 0, "0" signifie toutes les fonctions du périphérique 0 sur n'importe quel bus, "0.3" sélectionne la troisième fonction du périphérique 0 sur tous les bus et ".4" affiche seulement la quatrième fonction de chaque périphérique.
-d [<vendeur>]:[<périphérique>][:<classe>[:<prog-if>]]
Affiche uniquement les périphériques avec le vendeur, le périphérique, l'ID de classe et l'interface de programmation spécifiés. Les ID sont donnés en hexadécimal et peuvent être omis ou donnés comme "*", les deux signifiant "toute valeur". L'ID de classe peut contenir des caractères "x" qui représentent "n'importe quel chiffre".

Autres options

-i <fichier>
Utilise <fichier> comme liste d'ID PCI au lieu de /usr/share/hwdata/pci.ids.
-p <fichier>
Utilise <fichier> comme carte des ID PCI gérés par les modules du noyau. Par défaut, lspci utilise /lib/modules/version_du_noyau/modules.pcimap. Ne s'applique qu'aux systèmes Linux disposant d'outils de module suffisamment récents.
-M
Invoque le mode de cartographie des bus qui effectue un balayage approfondi de tous les périphériques PCI, y compris ceux situés derrière des ponts mal configurés, etc. Cette option ne donne des résultats significatifs qu'avec un mode d'accès matériel direct, qui nécessite généralement des privilèges root. Par défaut, le cartographe de bus analyse le domaine. Vous pouvez utiliser l'option -s pour sélectionner un domaine différent.
--version
Affiche la version de lspci. Cette option doit être utilisée seule.

Options d'accès PCI

Les utilitaires PCI utilisent la bibliothèque PCI pour communiquer avec les périphériques PCI (voir pcilib(7) pour les détails). Vous pouvez utiliser les options suivantes

options pour influencer son comportement :

-A <méthode>
La bibliothèque prend en charge diverses méthodes pour accéder au matériel PCI. Par défaut, elle utilise la première méthode d'accès disponible, mais vous pouvez utiliser cette option pour outrepasser cette décision. Voir -A help pour une liste des méthodes disponibles et leurs descriptions.
-O <param>=<valeur>
Le comportement de la bibliothèque est contrôlé par plusieurs paramètres nommés. Cette option permet de définir la valeur de l'un des paramètres. Utilisez -O help pour une liste des paramètres connus et leurs valeurs par défaut.
-H1
Utiliser l'accès matériel direct via le mécanisme de configuration Intel 1. (Ceci est un raccourci pour -A intel-conf1.)
-H2
Utiliser l'accès matériel direct via le mécanisme de configuration Intel 2. (Ceci est un raccourci pour -A intel-conf2.)
-F <fichier>
Au lieu d'accéder au matériel réel, lire la liste des périphériques et les valeurs de leurs registres de configuration à partir du fichier donné produit par une exécution antérieure de lspci -x. Ceci est très utile pour l'analyse des rapports de bogues fournis par l'utilisateur, car vous pouvez afficher la configuration matérielle de la manière que vous souhaitez sans déranger l'utilisateur avec des demandes de dumps supplémentaires.
-G
Augmenter le niveau de débogage de la bibliothèque.

SORTIE LISIBLE PAR MACHINE

Si vous avez l'intention de traiter la sortie de lspci automatiquement, veuillez utiliser l'un des formats de sortie lisibles par machine (-m, -vm, -vmm) décrits dans cette section. Tous les autres formats sont susceptibles de changer entre les versions de lspci.

Tous les nombres sont toujours imprimés en hexadécimal. Si vous souhaitez traiter des identifiants numériques au lieu de noms, veuillez ajouter le commutateur -n.

Format simple (-m)

En mode simple, chaque périphérique est décrit sur une seule ligne, formatée comme des paramètres appropriés pour être passés à un script shell, c'est-à-dire des valeurs séparées par des espaces, mises entre guillemets et échappées si nécessaire. Certains arguments sont positionnels : slot, classe, nom du vendeur, nom du périphérique, nom du sous-système vendeur et nom du sous-système (les deux derniers sont vides si le périphérique n'a pas de sous-système) ; les arguments restants sont de type option :

-rrev
Numéro de révision.
-pprogif
Interface de programmation.

L'ordre relatif des arguments positionnels et des options n'est pas défini. De nouvelles options peuvent être ajoutées dans les versions futures, mais elles auront toujours un seul argument non séparé de l'option par des espaces, de sorte qu'elles puissent être facilement ignorées si elles ne sont pas reconnues.

Format verbeux (-vmm)

La sortie verbeuse est une séquence d'enregistrements séparés par des lignes vides. Chaque enregistrement décrit un périphérique unique par une séquence de lignes, chaque ligne contenant une paire `balise: valeur'. La balise et la valeur sont séparées par un seul caractère tabulation. Ni les enregistrements ni les lignes à l'intérieur d'un enregistrement ne sont dans un ordre particulier. Les balises sont sensibles à la casse.

Les balises suivantes sont définies :

Slot
Le nom de l'emplacement où se trouve le périphérique ([domaine:]bus:périphérique.fonction). Cette balise est toujours la première dans un enregistrement.
Class
Nom de la classe.
Vendor
Nom du vendeur.
Device
Nom du périphérique.
SVendor
Nom du vendeur du sous-système (facultatif).
SDevice
Nom du sous-système (facultatif).
PhySlot
L'emplacement physique où se trouve le périphérique (facultatif, Linux uniquement).
Rev
Numéro de révision (facultatif).
ProgIf
Interface de programmation (facultatif).
Driver
Pilote du noyau gérant actuellement le périphérique (facultatif, Linux uniquement).
Module
Module du noyau déclarant qu'il est capable de gérer le périphérique (facultatif, Linux uniquement). Plusieurs lignes avec cette balise peuvent apparaître.
NUMANode
Nœud NUMA auquel ce périphérique est connecté (facultatif, Linux uniquement).
IOMMUGroup
Groupe IOMMU dont fait partie ce périphérique (facultatif, Linux uniquement).

De nouvelles balises peuvent être ajoutées dans les versions futures, vous devez donc ignorer silencieusement toutes les balises que vous ne reconnaissez pas.

Format verbeux compatible avec les versions précédentes (-vm)

Dans ce mode, lspci essaie d'être parfaitement compatible avec ses anciennes versions. C'est presque la même chose que le format verbeux normal, mais la balise Device est utilisée à la fois pour le slot et le nom du périphérique, elle apparaît donc deux fois dans un seul enregistrement. Veuillez éviter d'utiliser ce format dans tout nouveau code.

FICHIERS

/usr/share/hwdata/pci.ids
Une liste de tous les identifiants PCI connus (vendeurs, périphériques, classes et sous-classes). Maintenue sur https://pci-ids.ucw.cz/, utilisez l'utilitaire update-pciids pour télécharger la version la plus récente.
/usr/share/hwdata/pci.ids.gz
Si lspci est compilé avec le support de la compression, ce fichier est essayé avant pci.ids.
$XDG_CACHE_HOME/pci-ids
Tous les identifiants trouvés en mode requête DNS sont mis en cache dans ce fichier.

BOGUES

Parfois, lspci n'est pas en mesure de décoder complètement les registres de configuration. Cela se produit généralement lorsque la documentation disponible pour les auteurs n'est pas suffisante. Dans de tels cas, il affiche au moins le marqueur <?> pour signaler qu'il y a potentiellement quelque chose de plus à dire. Si vous connaissez les détails, des correctifs seront bien sûr les bienvenus.

L'accès à l'espace de configuration étendu n'est actuellement pris en charge que par le backend linux_sysfs.
