NOM

lstopo, lstopo-no-graphics, hwloc-ls - Afficher la topologie du système

SYNTAXE

lstopo [ options ]... [ nom_fichier ]

lstopo-no-graphics [ options ]... [ nom_fichier ]

hwloc-ls [ options ]... [ nom_fichier ]

Notez que hwloc(7) fournit une explication détaillée du système hwloc ; il doit être lu avant cette page de manuel.

OPTIONS

--of <format>, --output-format <format>
Forcer la sortie dans le format donné. Voir la section FORMATS DE SORTIE ci-dessous.
-i <chemin>, --input <chemin>
Lire la topologie depuis <chemin> au lieu de découvrir la topologie de la machine locale.

Si <chemin> est un fichier, il peut s'agir d'un fichier XML exporté par un programme hwloc précédent. Si <chemin> est "-", l'entrée standard peut être utilisée comme fichier XML.

Sous Linux, <chemin> peut être un répertoire contenant les fichiers de topologie collectés d'une autre topologie de machine avec hwloc-gather-topology.

Sur x86, <chemin> peut être un répertoire contenant un dump cpuid collecté avec hwloc-gather-cpuid.

Lorsque le programme archivemount est disponible, <chemin> peut également être une archive tar contenant de tels fichiers de topologie Linux ou x86.

-i <spécification>, --input <spécification>
Simuler une hiérarchie factice (au lieu de découvrir la topologie sur la machine locale). Si <spécification> est "node:2 pu:3", la topologie contiendra deux nœuds NUMA avec 3 unités de traitement chacun. La chaîne <spécification> doit se terminer par un nombre de PUs.
--if <format>, --input-format <format>
Forcer l'entrée dans le format donné, parmi xml, fsroot, cpuid et synthetic.
--export-xml-flags <flags>
Forcer les drapeaux lors de l'exportation au format XML. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules qui sont passés à hwloc_topology_export_xml(). Ces noms peuvent être des sous-chaînes de noms de drapeaux réels tant qu'un seul correspond. Une valeur de 1 (ou v1) revient au format de hwloc v1.x. La valeur par défaut est 0 (ou none).
--export-synthetic-flags <flags>
Forcer les drapeaux lors de l'exportation au format synthétique. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules qui sont passés à hwloc_topology_export_synthetic(). Ces noms peuvent être des sous-chaînes de noms de drapeaux réels tant qu'un seul correspond. Une valeur de 2 (ou no_attr) revient au format de hwloc v1.9. Une valeur de 3 (ou no_ext,no_attr) revient au format minimaliste original (avant v1.9). La valeur par défaut est 0 (ou none).
-v --verbose
Inclure des détails supplémentaires. L'outil hwloc-info peut être utilisé pour afficher encore plus d'informations sur des objets spécifiques.
-q --quiet -s --silent
Réduire la quantité de détails à afficher.
--distances
Afficher uniquement les matrices de distances.
--distances-transform <links|merge-switch-ports|transitive-closure>
Essayer d'appliquer une transformation aux structures de distances avant de les afficher. Voir hwloc_distances_transform() pour plus de détails. D'autres transformations peuvent être appliquées en utilisant hwloc-annotate(1) (et cela peut sauvegarder leur sortie en XML).
--memattrs
Afficher uniquement les attributs mémoire. Tous sont affichés (tandis que la sortie textuelle par défaut sélectionne les détails des attributs mémoire en fonction du niveau de verbosité).
--cpukinds
Afficher uniquement les types de CPU. Les types de CPU sont affichés dans l'ordre, en commençant par les plus économes en énergie jusqu'aux plus gourmands en performance et en énergie.
--windows-processor-groups
Sous Windows, afficher uniquement les informations sur les groupes de processeurs. Tous sont affichés, tandis que la sortie détaillée par défaut ne les montre que s'il y en a plus d'un.
-f --force
Si le fichier de destination existe déjà, le remplacer.
-l --logical
Afficher les index logiques hwloc de tous les objets, avec le préfixe "L#". Par défaut, les index logiques et physiques/OS sont affichés pour les PUs et les nœuds NUMA, uniquement les index logiques pour les cœurs, les dies et les packages, et aucun index pour les autres types.
-p --physical
Afficher les index OS/physiques de tous les objets, avec le préfixe "P#". Par défaut, les index logiques et physiques/OS sont affichés pour les PUs et les nœuds NUMA, uniquement les index logiques pour les cœurs, les dies et les packages, et aucun index pour les autres types.
--logical-index-prefix <préfixe>
Remplacer " L#" par le préfixe donné pour les index logiques.
--os-index-prefix <préfixe>
Remplacer " P#" par le préfixe donné pour les index physiques/OS.
-c --cpuset
Afficher le jeu d'unités de traitement (cpuset) de chaque objet.
-C --cpuset-only
Afficher uniquement le jeu d'unités de traitement (cpuset) de chaque objet ; n'afficher rien d'autre concernant l'objet.
--cpuset-output-format <hwloc|list|taskset> --cof <hwloc|list|taskset>
Changer le format des chaînes de jeux d'unités de traitement (cpuset) affichées. Par défaut, le format spécifique à hwloc est utilisé. Si list est donné, la sortie est une liste séparée par des virgules de nombres ou de plages, par exemple 2,4-5,8 . Si taskset est donné, les jeux d'unités de traitement (cpuset) de sortie sont compatibles avec le programme taskset (remplace l'ancienne option --taskset).

Cette option doit être combinée avec --cpuset ou --cpuset-only, sinon elle impliquera --cpuset.

--only <type>
Afficher uniquement les objets du type donné dans la sortie textuelle.

<type> peut contenir un filtre pour sélectionner des objets spécifiques parmi le type. Par exemple, --only NUMA[HBM] n'affiche que les nœuds NUMA marqués du sous-type "HBM", tandis que --only "numa[mcdram]" n'affiche que les nœuds NUMA MCDRAM sur KNL.

--filter <type>:<genre>, --filter <type>
Filtrer les objets du type <type>, ou de n'importe quel type si <type> est "all". "io", "cache" et "icache" sont également pris en charge.

<genre> spécifie le comportement du filtrage. Si "none" ou non spécifié, tous les objets du type donné sont supprimés. Si "all", tous les objets sont conservés comme d'habitude. Si "structure", les objets sont conservés lorsqu'ils apportent une structure à la topologie. Si "important" (uniquement applicable aux E/S), seuls les objets importants sont conservés. Voir hwloc_topology_set_type_filter() pour plus de détails.

hwloc prend en charge le filtrage de tous les types sauf les PUs et les nœuds NUMA. lstopo offre également le filtrage des PUs et des nœuds NUMA en les masquant dans les sorties graphique et textuelle, mais tout objet inclus dans ceux-ci (par exemple Misc) sera également masqué. Notez que les PUs et les nœuds NUMA ne peuvent pas être ignorés dans la sortie XML. Notez également que le type d'objet de niveau supérieur ne peut pas être ignoré (généralement Machine ou System).

--ignore <type>
C'est l'ancienne façon de spécifier --filter <type>:none.
--no-smt
Ignorer les PUs. Ceci est identique à --filter PU:none.
--no-caches
Ne pas afficher les caches. Ceci est identique

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

al vers --filter cache:none.
--no-useless-caches
Ceci est identique à --filter cache:structure.
--no-icaches
Ceci est identique à --filter icache:none.
--disallowed
Inclure les objets interdits par les limitations administratives (par ex. les Cgroups sous Linux). Les PUs et les nœuds NUMA hors ligne sont toujours ignorés.
--allow <all|local|0xff|nodeset=0xf0>
Inclure les objets interdits par les limitations administratives (implique --disallowed) et changer également l'ensemble des objets autorisés.

Si local est spécifié, seuls les objets disponibles pour le processus courant sont autorisés (comportement par défaut lors du chargement depuis le backend natif du système d'exploitation). Cela peut être utile si la topologie a été créée par un autre processus (avec des restrictions administratives différentes telles que les Cgroups Linux) et chargée ici depuis XML ou de manière synthétique. Ce cas implique --thissystem.

Si all est spécifié, tous les objets sont autorisés.

Si un bitmap est donné sous forme de chaîne hexadécimale, il est utilisé comme ensemble des PUs autorisées.

Si un bitmap est donné après le préfixe nodeset=, il représente l'ensemble des nœuds NUMA autorisés.

--flags <flags>
Appliquer des drapeaux de topologie. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules, qui sont passés à hwloc_topology_set_flags(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels tant qu'un seul correspond, par exemple disallowed,thissystem_allowed. La valeur par défaut est 8 (ou import).
--merge
Ne pas afficher les niveaux qui n'ont pas d'impact hiérarchique. Ceci définit HWLOC_TYPE_FILTER_KEEP_STRUCTURE pour tous les types d'objets. C'est identique à --filter all:structure.
--no-factorize --no-factorize=<type>
Ne jamais factoriser les objets identiques dans la sortie graphique.

Si un type d'objet est donné, seule la factorisation de ces objets est désactivée. Ceci ne s'applique qu'aux objets normaux côté CPU, il est indépendant de l'effondrement PCI.

--factorize --factorize=[<type>,]<N>[,<F>[,<L>]]
Factoriser les enfants identiques dans la sortie graphique (activé par défaut).

Si <N> est spécifié (4 par défaut), la factorisation ne se produit que lorsqu'il y a strictement plus de N enfants identiques. Si <F> et <L> sont spécifiés, ils définissent les nombres des premiers et derniers enfants à conserver après la factorisation.

Si un type d'objet est donné, seule la factorisation de ces objets est configurée. Ceci ne s'applique qu'aux objets normaux côté CPU, il est indépendant de l'effondrement PCI.

--no-collapse
Ne pas effondrer les périphériques PCI identiques. Par défaut, les périphériques PCI frères identiques (comme de nombreuses fonctions virtuelles au sein d'un même périphérique physique) sont effondrés.
--no-cpukinds
Ne pas afficher les différents types de CPUs dans la sortie graphique. Par défaut, lorsque c'est supporté, différentes épaisseurs de ligne et polices en gras peuvent être utilisées pour afficher des boîtes PU de différents types.
--restrict <cpuset>
Restreindre la topologie au cpuset donné. Ceci supprime certaines PUs et leurs parents désormais sans enfants.

Attention, restreindre les PUs dans une topologie peut modifier les indices logiques de nombreux objets, y compris les nœuds NUMA.

--restrict nodeset=<nodeset>
Restreindre la topologie au nodeset donné. (sauf si --restrict-flags spécifie autre chose). Ceci supprime certains nœuds NUMA et leurs parents désormais sans enfants.

Attention, restreindre les nœuds NUMA dans une topologie peut modifier les indices logiques de nombreux objets, y compris les PUs.

--restrict binding
Restreindre la topologie au binding du processus courant. Cette option nécessite l'utilisation de la topologie réelle de la machine courante (ou de toute autre topologie avec --thissystem ou avec HWLOC_THISSYSTEM réglé à 1 dans l'environnement).

Attention, restreindre la topologie peut modifier les indices logiques de nombreux objets, y compris les PUs et les nœuds NUMA.

--restrict-flags <flags>
Appliquer des drapeaux lors de la restriction de la topologie. Les drapeaux peuvent être donnés sous forme de valeurs numériques ou d'une liste de noms de drapeaux séparés par des virgules, qui sont passés à hwloc_topology_restrict(). Ces noms peuvent être des sous-chaînes des noms de drapeaux réels tant qu'un seul correspond, par exemple bynodeset,memless. La valeur par défaut est 0 (ou none).
--no-io
Ne pas afficher aucun périphérique ou pont I/O. Ceci est identique à --filter io:none. Par défaut, les périphériques courants (GPU, cartes réseau, périphériques de bloc, ...) et les ponts/switchs intéressants sont affichés.
--no-bridges
Ne pas afficher aucun pont I/O sauf les ponts hôtes. Ceci est identique à --filter bridge:none. Par défaut, les périphériques courants (GPU, cartes réseau, périphériques de bloc, ...) et les ponts/switchs intéressants sont affichés.
--whole-io
Afficher tous les périphériques et ponts I/O. Ceci est identique à --filter io:all. Par défaut, seuls les périphériques courants (GPU, cartes réseau, périphériques de bloc, ...) et les ponts/switchs intéressants sont affichés.
--thissystem
Supposer que le backend sélectionné fournit la topologie du système sur lequel nous nous exécutons. Ceci est utile lors du chargement d'une topologie personnalisée telle qu'un fichier XML et de l'utilisation de --restrict binding ou de --allow all.
--pid <pid>
Détecter la topologie telle que vue par le processus <pid>, c'est-à-dire comme si le processus <pid> avait effectué la découverte lui-même. Noter que cela peut par exemple modifier l'ensemble des processeurs autorisés. Afficher également le CPU et la mémoire couramment liés à ce processus en marquant les PUs et les nœuds NUMA correspondants (en vert dans la sortie graphique, voir la section COLORS ci-dessous, ou en ajoutant (binding) à la sortie texte détaillée). Si 0 est donné comme pid, le binding courant pour le processus lstopo sera affiché.
--ps --top
Afficher les processus existants comme objets misc dans la sortie. Pour éviter d'encombrer inutilement la sortie, seuls les processus restreints à une partie de la machine sont affichés. Sous Linux, les threads du noyau ne sont pas affichés. Si de nombreux processus apparaissent, la sortie peut devenir difficile à lire de toute façon, rendant le programme hwloc-ps plus pratique.

Voir --misc-from pour une variante personnalisable utilisant hwloc-ps.

--misc-from <file>
Ajouter des objets Misc tels que décrits dans <file> contenant des entrées telles que :


name=myMisc1
cpuset=0x5


name=myMisc2
cpuset=0x7
subtype=myOptionalSubtype

Ceci est utile pour combiner avec hwloc-ps --lstopo-misc (voir EXEMPLES ci-dessous) car hwloc-ps est beaucoup plus personnalisable que l'option --top de lstopo.

--children-order <order>
Changer l'ordre des différents types d'enfants par rapport à leur parent dans la sortie graphique. <order> peut être une liste de mots-clés séparés par des virgules parmi :

memory:above affiche les enfants mémoire au-dessus des autres enfants (et au-dessus du parent s'il s'agit d'un cache). Les PUs sont donc en dessous de leurs nœuds NUMA locaux, comme le faisait hwloc 1.x.

io:right et misc:right placent les enfants I/O ou Misc à droite des enfants CPU.

io:below et misc:below placent les enfants I/O ou Misc en dessous des enfants CPU.

plain place tout ce qui n'est pas spécifié ensemble avec les enfants CPU normaux.

Si seul plain est spécifié, lstopo affiche la topologie de manière basique qui correspond strictement à l'arbre réel : les enfants Mémoire, I/O et Misc sont listés sous leur parent comme tout autre enfant. Les PUs sont donc à côté de leurs nœuds NUMA locaux, sous un ancêtre commun. Cette sortie peut entraîner des agencements étranges car la taille des enfants Mémoire, CPU et I/O peut être très différente, amenant l'algorithme de placement à mal les organiser en lignes.

L'ordre par défaut est memory:above,io:right,misc:right ce qui signifie que les enfants Mémoire sont au-dessus des enfants CPU tandis que I/O et Misc sont ensemble à droite.

Jusqu'à hwloc 2.5, la valeur par défaut était plutôt memory:above,plain.

De plus, memory:above, io:right, io:below, misc:right et misc:below peuvent être suivis de :horiz, :vert ou :rect pour forcer l'agencement horizontal, vertical ou rectangulaire des enfants à l'intérieur de ces sections.

Voir également les sections SORTIE GRAPHIQUE et MISE EN PAGE ci-dessous.

--fontsize <size>
Définir la taille de la police de texte dans la sortie graphique.

La valeur par défaut est 10.

Les boîtes sont mises à l'échelle en fonction de la taille du texte. La variable d'environnement LSTOPO_TEXT_XSCALE peut être utilisée pour mettre davantage à l'échelle la largeur des boîtes (sa valeur par défaut est 1.0).

L'option --fontsize est ignorée dans le backend ASCII.

--gridsize <size>
Définir la marge entre les éléments dans la sortie graphique.

La valeur par défaut est 7. Elle était de 10 avant hwloc 2.1.

Cette option est ignorée dans le backend ASCII.

--linespacing <size>
Définir l'espacement entre les lignes de texte dans la sortie graphique.

La valeur par défaut est 4.

L'option était incluse dans --gridsize avant hwloc 2.1 (et sa valeur par défaut était 10).

Cette option est ignorée dans le backend ASCII.

end.

--thickness <taille>
Définit l'épaisseur des lignes et des boîtes dans la sortie graphique.

La valeur par défaut est 1.

Cette option est ignorée dans le backend ASCII.

--horiz, --horiz=<type1,...>
Force une disposition graphique horizontale au lieu d'un ratio proche de 4/3 dans la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, la disposition ne s'applique qu'aux objets de type conteneur correspondants. Ignoré pour les ponts car leurs enfants sont toujours alignés verticalement.
--vert, --vert=<type1,...>
Force une disposition graphique verticale au lieu d'un ratio proche de 4/3 dans la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, la disposition ne s'applique qu'aux objets de type conteneur correspondants.
--rect, --rect=<type1,...>
Force une disposition graphique rectangulaire avec un ratio proche de 4/3 dans la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, la disposition ne s'applique qu'aux objets de type conteneur correspondants. Ignoré pour les ponts car leurs enfants sont toujours alignés verticalement.
--no-text, --no-text=<type1,...>
N'affiche aucun texte dans les boîtes de la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, le texte est désactivé pour les objets correspondants. Ceci est surtout utile pour supprimer le texte des objets de type Group.
--text, --text=<type1,...>
Affiche du texte dans les boîtes de la sortie graphique (par défaut). Si une liste d'objets séparés par des virgules est fournie, le texte est réactivé pour les objets correspondants (s'il était précédemment désactivé avec --no-text).
--no-index, --no-index=<type1,...>
N'affiche pas les index d'objets dans la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, les index sont désactivés pour les objets correspondants.
--index, --index=<type1,...>
Affiche les index d'objets dans la sortie graphique (par défaut). Si une liste d'objets séparés par des virgules est fournie, les index sont réactivés pour les objets correspondants (s'ils étaient précédemment désactivés avec --no-index).
--no-attrs, --no-attrs=<type1,...>
N'affiche pas les attributs d'objets (tels que la taille mémoire, la taille du cache, l'ID du bus PCI, la vitesse du lien PCI, etc.) dans la sortie graphique. Si une liste d'objets séparés par des virgules est fournie, les attributs sont désactivés pour les objets correspondants.
--attrs, --attrs=<type1,...>
Affiche les attributs d'objets (tels que la taille mémoire, la taille du cache, l'ID du bus PCI, la vitesse du lien PCI, etc.) dans la sortie graphique (par défaut). Si une liste d'objets séparés par des virgules est fournie, les attributs sont réactivés pour les objets correspondants (s'ils étaient précédemment désactivés avec --no-attrs).
--no-legend
Supprime toutes les lignes de texte de légende en bas de la sortie graphique.
--no-default-legend
Supprime les lignes de texte de légende par défaut en bas de la sortie graphique. Les lignes de légende ajoutées par l'utilisateur avec --append-legend ou l'information "lstopoLegend" sont toujours affichées s'il y en a.
--append-legend <ligne>
Ajoute la ligne de texte au bas de la légende dans la sortie graphique. Si plusieurs lignes sont ajoutées, chaque ligne doit être fournie séparément en passant cette option plusieurs fois. Des lignes de légende supplémentaires peuvent également être spécifiées dans la topologie en utilisant les attributs d'information "lstopoLegend" sur l'objet racine de la topologie.
--grey, --greyscale
Utilise des niveaux de gris au lieu des couleurs dans la sortie graphique.
--palette <gris|niveauxdegres|defaut|couleurs|blanc|aucun>
Change la palette de couleurs. Passer gris ou niveauxdegres est identique à passer --grey ou --greyscale. Passer blanc ou aucun utilise du blanc au lieu de couleurs pour tous les fonds de boîtes. Passer defaut ou couleurs revient à la palette de couleurs par défaut.
--palette type=#rrggbb
Remplace la couleur du type de boîte donné par la combinaison hexadécimale RGB 3x8 bits fournie (par exemple, #ff0000 est le rouge). Les types existants sont machine, group, package, group_in_package, die, core, pu, numanode, memories (boîte contenant plusieurs enfants mémoire), cache, pcidev, osdev, bridge, et misc.

Voir aussi COULEUR PERSONNALISÉE ci-dessous pour la personnalisation des objets individuels.

--binding-color <aucun|#rrggbb>
Ne colore pas les PUs et les nœuds NUMA en fonction du binding dans la sortie graphique. Ou change la couleur pour la combinaison hexadécimale RGB 3x8 bits fournie (par exemple, #ff0000 est le rouge).
--disallowed-color <aucun|#rrggbb>
Ne colore pas les PUs et les nœuds NUMA non autorisés dans la sortie graphique. Ou change la couleur pour la combinaison hexadécimale RGB 3x8 bits fournie (par exemple, #00ff00 est le vert).
--top-color <aucun|#rrggbb>
Ne colore pas les objets de tâche dans la sortie graphique lorsque --top est donné. Ou change la couleur pour la combinaison hexadécimale RGB 3x8 bits fournie (par exemple, #0000ff est le bleu). Ceci est réellement appliqué aux objets Misc de sous-type Process ou Thread.
--version
Rapporte la version et quitte.
-h --help
Affiche le message d'aide et quitte.

DESCRIPTION

lstopo et lstopo-no-graphics sont capables d'afficher une carte topologique du système dans une variété de formats de sortie différents. La seule différence entre lstopo et lstopo-no-graphics est que les sorties graphiques ne sont prises en charge que par lstopo, afin de réduire les dépendances aux bibliothèques externes. hwloc-ls est identique à lstopo-no-graphics.

Le nom de fichier spécifié implique directement le format de sortie qui sera utilisé ; voir la section FORMATS DE SORTIE, ci-dessous. Les formats de sortie qui prennent en charge les couleurs indiqueront des caractéristiques spécifiques sur les CPU individuels par leur couleur ; voir la section COULEURS, ci-dessous.

FORMATS DE SORTIE

Par défaut, si aucun nom de fichier de sortie n'est spécifié, la sortie est envoyée vers une fenêtre graphique si possible dans l'environnement actuel (variable d'environnement DISPLAY définie sur Unix, etc.). Sinon, un résumé textuel est affiché dans la console. La console est également utilisée lorsque le programme s'exécute à partir d'un terminal et que la sortie est redirigée vers un pipe ou un fichier. Ces comportements par défaut peuvent être modifiés en passant --of console pour forcer le mode console ou --of window pour la fenêtre graphique.

Le nom de fichier sur la ligne de commande détermine généralement le format de la sortie. Il existe quelques noms de fichiers qui indiquent des formats et des périphériques de sortie spécifiques (par exemple, un nom de fichier de "-" produira un résumé textuel sur stdout), mais la plupart des noms de fichiers indiquent le format de sortie souhaité par leur suffixe (par exemple, "topo.png" produira un fichier au format PNG).

Le format de la sortie peut également être modifié avec "--of". Par exemple, "--of pdf" générera un fichier au format PDF sur la sortie standard, tandis que "--of fig toto" produira un fichier au format Xfig nommé "toto".

La liste des formats actuellement pris en charge est donnée ci-dessous. N'importe lequel d'entre eux peut être utilisé avec "--of" ou comme suffixe de nom de fichier.

default
Envoie la sortie vers une fenêtre ou vers la console en fonction de l'environnement.
window
Envoie la sortie vers une fenêtre graphique.
console
Envoie un résumé textuel sur stdout. Les processeurs liés ou non autorisés ne sont annotés dans ce mode que s'ils sont verbeux ; voir la section COULEURS, ci-dessous.
ascii
Produit une représentation en art ASCII de la carte (anciennement appelée txt). Si la sortie est redirigée vers stdout et si les couleurs sont prises en charge sur le terminal, la sortie sera colorisée.
tikz ou tex
Produit une représentation tikzpicture LaTeX de la carte qui peut être compilée avec un compilateur LaTeX.
fig
Produit une représentation de la carte qui peut être chargée dans Xfig.
svg
Produit une représentation SVG de la carte, en utilisant Cairo (par défaut, si pris en charge) ou un backend SVG natif (solution de repli, toujours pris en charge). Voir cairosvg et nativesvg ci-dessous.
cairosvg ou svg(cairo)
Si lstopo a été compilé avec le support approprié, produit une représentation SVG de la carte en utilisant Cairo.
nativesvg ou svg(native)
Produit une représentation SVG de la carte en utilisant le backend SVG natif. Il peut être moins joli que la sortie Cairo, mais il est toujours pris en charge, et les objets SVG ont des attributs pour les identifier et les manipuler. Voir dynamic_SVG_example.html pour un exemple.
pdf
Si lstopo a été compilé avec le support approprié, lstopo produit une représentation PDF de la carte.
ps
Si lstopo a été compilé avec le support approprié, lstopo produit une représentation Postscript de la carte.
png
Si lstopo a été compilé avec le support approprié, lstopo produit une représentation PNG de la carte.
synthétique
Si la topologie est symétrique (ce qui nécessite que l'objet racine ait son champ symmetric_subtree défini), lstopo génère une chaîne de description synthétique. Cette sortie peut être réutilisée ultérieurement comme description de topologie synthétique d'entrée. Voir aussi la section Topologies synthétiques de la documentation. Notez que les périphériques divers et d'E/S sont ignorés lors de cette exportation.
xml
lstopo génère une représentation XML de la carte. Elle peut être réutilisée ultérieurement, même sur une autre machine, avec lstopo --input, la variable d'environnement HWLOC_XMLFILE, ou la fonction hwloc_topology_set_xml().

Les noms spéciaux suivants peuvent être utilisés :

-
Envoyer un résumé texte sur stdout.
/dev/stdout
Envoyer un résumé texte sur stdout. C'est effectivement la même chose que de spécifier "-".
-.<format>
Si le nom de fichier entier est "-.<format>", lstopo se comporte comme si "--of <format> -" avait été donné, ce qui signifie qu'un fichier du format donné est envoyé à la sortie standard.

Consultez la sortie de "lstopo --help" pour une liste spécifique des formats de sortie graphique pris en charge par votre installation hwloc.

SORTIE GRAPHIQUE

La sortie graphique est composée de boîtes imbriquées représentant l'inclusion des objets dans la hiérarchie des ressources. Habituellement, une boîte Machine contient une ou plusieurs boîtes Package, qui contiennent plusieurs boîtes Core, avec une ou plusieurs PU chacune.

Caches

Les caches sont affichés d'une manière légèrement différente car ils n'incluent pas réellement de ressources de calcul telles que les cœurs. Par exemple, un cache L2 partagé par une paire de cœurs est dessiné comme une boîte Cache au-dessus de deux boîtes Core (au lieu d'avoir des boîtes Core à l'intérieur de la boîte Cache).

Nœuds NUMA et Caches côté mémoire

Par défaut, les boîtes de nœuds NUMA sont dessinées au-dessus de leurs ressources de calcul locales. Par exemple, un Package processeur contenant un nœud NUMA et quatre Cœurs est affiché comme une boîte Package contenant la boîte de nœud NUMA au-dessus de quatre boîtes Core. Si un nœud NUMA est local au cache L3, le nœud NUMA est affiché au-dessus de cette boîte de cache. Toute cette stratégie de dessin spécifique pour les objets mémoire peut être désactivée en passant l'option de ligne de commande --children-order plain.

Si plusieurs nœuds NUMA sont attachés au même objet parent, ils sont affichés à l'intérieur d'une boîte mémoire supplémentaire sans nom.

Si certains caches côté mémoire existent devant certains nœuds NUMA, ils sont dessinés comme des boîtes immédiatement au-dessus d'eux.

Ponts PCI, périphériques PCI et périphériques OS

La hiérarchie PCI n'est pas dessinée comme un ensemble de boîtes incluses, mais plutôt comme un arbre de ponts (qui peuvent en fait être des commutateurs) avec des liens entre eux. L'arbre commence par un petit carré à gauche pour le pont hôte ou le complexe racine. Il se termine par des boîtes de périphériques PCI à droite. Des ponts/commutateurs PCI intermédiaires peuvent apparaître comme des petits carrés supplémentaires au milieu.

Les périphériques PCI à droite de l'arbre sont des boîtes contenant leur ID de bus PCI (par exemple, 00:02.3). Ils peuvent également contenir des sous-boîtes pour les objets périphériques OS tels qu'une interface réseau eth0 ou une GPU CUDA cuda0.

Lorsqu'il y a un seul lien (ligne horizontale) à droite d'un pont PCI, cela signifie qu'un seul périphérique ou pont est connecté sur le bus PCI secondaire derrière ce pont. Lorsqu'il y a une ligne verticale, cela signifie que plusieurs périphériques et/ou ponts sont connectés au même bus PCI secondaire.

Le débit d'un lien PCI peut être écrit (en Go/s) juste en dessous de sa ligne dessinée (si le système d'exploitation et/ou les bibliothèques sont capables de rapporter cette information). Ce débit est la vitesse actuellement configurée de l'ensemble du lien PCI (somme de la bande passante de toutes les voies PCI de ce lien). Il peut changer pendant l'exécution car certains périphériques sont capables de ralentir leurs liens PCI lorsqu'ils sont inactifs.

MISE EN PAGE

Dans sa sortie graphique, lstopo utilise des heuristiques rectangulaires simples pour essayer d'obtenir un rapport largeur/hauteur de 4/3. Bien que la hiérarchie des ressources soit correctement reflétée, l'organisation physique exacte (distances NUMA, anneaux, graphes complets, etc.) est actuellement ignorée.

La mise en page d'un niveau peut être modifiée avec --vert, --horiz, et --rect pour forcer un objet parent à organiser ses enfants de manière verticale, horizontale ou rectangulaire respectivement.

La position des enfants Mémoire, E/S et Divers par rapport aux autres objets enfants peut être modifiée à l'aide de --children-order. Cela divise effectivement les enfants en plusieurs sections. La mise en page des enfants est d'abord calculée à l'intérieur de chaque section, avant que les sections ne soient placées à l'intérieur (ou en dessous) de la boîte parente.

La mise en page verticale/horizontale/rectangulaire de ces sections supplémentaires peut également être configurée via --children-order.

COULEURS

Les boîtes dans les formats de sortie graphique sont colorisées selon le type d'objet hwloc, par exemple les packages CPU sont verts ou les nœuds NUMA sont roses. Ceci peut être configuré avec --palette, voir aussi COULEURS PERSONNALISÉES ci-dessous. En plus de ces couleurs par défaut, les CPU individuels et les nœuds NUMA peuvent être colorisés pour indiquer différentes caractéristiques :

Vert
La topologie est rapportée telle que vue par un processus spécifique (voir --pid), et le CPU ou le nœud NUMA donné est dans le masque de liaison CPU ou Mémoire de ce processus. Cette couleur peut être modifiée avec --binding-color.
Blanc
Le CPU ou le nœud NUMA fait partie de l'ensemble autorisé (voir ci-dessous). Si la topologie est rapportée telle que vue par un processus spécifique (voir --pid), l'objet ne fait pas non plus partie du masque de liaison de ce processus.
Rouge
Le CPU ou le nœud NUMA ne fait pas partie de l'ensemble autorisé (voir ci-dessous). Cette couleur peut être modifiée avec --disallowed-color.

L'"ensemble autorisé" est l'ensemble des CPU ou des nœuds NUMA auxquels le processus actuel est autorisé à se lier. L'ensemble autorisé est généralement hérité du processus parent ou défini par les politiques administratives du système. Les cgroups (cpusets) Linux sont un exemple de limitation de l'ensemble autorisé pour un processus et ses enfants afin qu'il soit inférieur à l'ensemble complet de CPU ou de nœuds NUMA du système.

Différents processus peuvent donc avoir des CPU ou des nœuds NUMA différents dans l'ensemble autorisé. Par conséquent, invoquer lstopo dans différents contextes et/ou en tant qu'utilisateurs différents peut afficher des couleurs différentes pour les mêmes CPU individuels (par exemple, exécuter lstopo dans un contexte peut montrer un CPU spécifique comme rouge, mais exécuter lstopo dans un contexte différent peut montrer le même CPU comme blanc).

Certains modes de sortie de lstopo, par exemple le mode console (sortie non graphique par défaut), ne prennent pas du tout en charge les couleurs. Le mode console affiche les caractéristiques ci-dessus en ajoutant du texte à chaque ligne de PU si les messages détaillés sont activés.

COULEURS PERSONNALISÉES

Les couleurs des différents types de boîtes peuvent être configurées avec --palette.

La couleur de chaque objet dans la sortie graphique peut également être forcée en spécifiant un attribut d'information "lstopoStyle" pour cet objet. Sa valeur doit être une liste séparée par des points-virgules de "<attribut>=#rrggbb" où rr, gg et bb sont les composantes RVB d'une couleur, chacune comprise entre 0 et 255, en hexadécimal (00 à ff). <attribut> peut être

Arrière-plan
Définit la couleur de fond de la boîte de l'objet principal.
Texte
Définit la couleur du texte affichant le nom, le type, l'index, etc. de l'objet.
Texte2
Définit la couleur du texte supplémentaire près de l'objet, par exemple la vitesse du lien derrière un pont PCI.

L'information "lstopoStyle" peut être ajoutée à des topologies XML enregistrées temporairement avec hwloc-annotate, ou avec hwloc_obj_add_info(). Par exemple, pour afficher tous les objets de cœur en bleu (avec des noms blancs) :


lstopo save.xml
hwloc-annotate save.xml save.xml core:all info lstopoStyle "Background=#0000ff;Text=#ffffff"
lstopo -i save.xml

EXEMPLES

Pour afficher la topologie de la machine en mode texte :


$ lstopo-no-graphics

Pour afficher la topologie de la machine en mode art ASCII :


$ lstopo-no-graphics -.ascii

Pour afficher en mode graphique (en supposant que la variable d'environnement DISPLAY est définie de manière appropriée) :


$ lstopo

Pour exporter la topologie vers un fichier PNG :


$ lstopo file.png

Exemples d'échange et de modification XML

Pour exporter un fichier XML sur une machine et afficher plus tard la sortie graphique correspondante sur une autre machine :


$ machine1$ lstopo file.xml
<transférer file.xml de machine1 à machine2>
$ machine2$ lstopo --input file.xml

Pour sauvegarder la topologie de la machine actuelle en XML et la recharger plus tard plus rapidement tout en la considérant toujours comme la machine actuelle :


$ lstopo file.xml
<...>
$ lstopo --input file.xml --thissystem

Pour restreindre une topologie XML aux seuls processeurs physiques 0, 1, 4 et 5 :


$ lstopo --input file.xml --restrict 0x33 newfile.xml

Pour restreindre une topologie XML au seul nœud numa dont l'index logique est 1 :


$ lstopo --input file.xml --restrict $(hwloc-calc --input file.xml node:1) newfile.xml

Exemples avec filtrage de sortie texte

Pour afficher un résumé de la topologie :


$ lstopo -s

EXAMPLES

To get more details about the topology:


$ lstopo -v

To only show cores:


$ lstopo --only core

To show cpusets:


$ lstopo --cpuset

To only show the cpusets of package:


$ lstopo --only package --cpuset-only

Plus d'exemples

Simulate a fake hierarchy; this example shows with 2 NUMA nodes of 2 processor units:


$ lstopo --input "node:2 2"

To append the kernel release and version to the graphical legend:


$ lstopo --append-legend "Kernel release: $(uname -r)" --append-legend "Kernel version: $(uname -v)"

To show where a process and its children are bound by combining with hwloc-ps:


$ hwloc-ps --pid-children 23 --lstopo-misc - | lstopo --misc-from -
