LSFD(1) Commandes utilisateur LSFD(1)

NOM

lsfd - lister les descripteurs de fichiers

SYNTAXE

lsfd [option]

DESCRIPTION

lsfd est conçu pour être un remplacement moderne de lsof(8) sur les systèmes Linux. Contrairement à lsof, lsfd est spécialisé pour le noyau Linux ; il supporte les fonctionnalités spécifiques à Linux comme les espaces de noms (namespaces) avec un code plus simple. lsfd n'est pas un remplacement direct de lsof ; ils diffèrent par l'interface en ligne de commande et les formats de sortie.

La sortie par défaut est sujette à modification. Par conséquent, lorsque cela est possible, vous devriez éviter d'utiliser les sorties par défaut dans vos scripts. Définissez toujours explicitement les colonnes attendues en utilisant --output liste-colonnes dans les environnements où une sortie stable est requise.

lsfd utilise Libsmartcols pour le formatage de la sortie et le filtrage. Voir la description de l'option --output pour personnaliser le format de sortie, et l'option --filter pour le filtrage. Utilisez lsfd --list-columns pour obtenir une liste de toutes les colonnes disponibles.

OPTIONS

-l, --threads

Lister au niveau des threads.

-J, --json

Utiliser le format de sortie JSON.

-n, --noheadings

Ne pas imprimer d'en-têtes.

-o, --output liste

Spécifier quelles colonnes de sortie imprimer. Voir la section COLONNES DE SORTIE pour les détails sur les colonnes disponibles.

La liste par défaut des colonnes peut être étendue si liste est spécifié dans le format +liste (par exemple, lsfd -o +DELETED).

-r, --raw

Utiliser le format de sortie brut.

--notruncate

Ne pas tronquer le texte dans les colonnes.

-p, --pid pids

Collecter les informations uniquement pour les processus spécifiés. pids est une liste de PIDs. Une virgule ou des espaces peuvent être utilisés comme séparateurs. Vous pouvez utiliser cette option avec pidof(1). Voir EXEMPLES DE FILTRAGE.

L'option -Q avec une expression incluant un PID, par exemple -Q (PID == 1), et l'option -p, par exemple -p 1, peuvent produire la même sortie, mais l'utilisation de l'option -p est beaucoup plus efficace car l'option -p fonctionne à un stade beaucoup plus précoce du traitement que l'option -Q.

-i[4|6], --inet[=4|=6]

Lister uniquement les sockets IPv4 et/ou IPv6.

-Q, --filter expr

Imprimer uniquement les fichiers correspondant à la condition représentée par expr. Voir aussi scols-filter(5) et EXEMPLES DE FILTRAGE.

-C, --counter label:filter_expr

Définir un compteur personnalisé utilisé dans la sortie --summary. lsfd crée un compteur nommé label. Pendant la collecte des informations, lsfd compte les fichiers correspondant à filter_expr et stocke le nombre compté dans le compteur nommé label. lsfd applique les filtres définis avec les options --filter avant de compter ; les fichiers exclus par les filtres ne sont pas comptés.

Voir scols-filter(5) pour filter_expr. label ne doit pas contenir de { ni de :. Vous pouvez définir plusieurs compteurs en spécifiant cette option plusieurs fois.

Voir aussi EXEMPLES DE COMPTEURS.

--summary[=when]

Cette option contrôle la sortie des lignes de résumé. L'argument optionnel when peut être only, append ou never. Si l'argument when est omis, il prend par défaut la valeur only.

Le résumé rapporte les compteurs. Un compteur se compose d'une étiquette et d'une valeur entière. --counter est l'option pour définir un compteur. Si l'utilisateur ne définit aucun compteur, lsfd utilise les définitions des compteurs intégrés prédéfinis (compteurs par défaut) pour créer la sortie du résumé.

ATTENTION : L'utilisation de --summary et --json peut rendre la sortie incorrecte. Seule la combinaison de --summary=only et --json est valide.

--debug-filter

Exporter la structure de données interne du filtre et quitter. Ceci est utile uniquement pour les développeurs de lsfd.

--dump-counters

Exporter la définition des compteurs utilisés dans la sortie --summary.

--hyperlink[=mode]

Afficher les chemins comme des hyperliens de terminal. Le mode peut être défini sur "always", "never", ou "auto". L'argument optionnel when peut être défini sur "auto", "never", ou "always". Si l'argument when est omis, il prendra par défaut la valeur "auto". Le réglage "auto" signifie que les hyperliens ne seront utilisés que si la sortie est dirigée vers un terminal.

-H, --list-columns

Lister les colonnes disponibles que vous pouvez spécifier à l'option --output.

-h, --help

Afficher le texte d'aide et quitter.

-V, --version

Afficher la version et quitter.

DESCRIPTION

The lsfd command lists information about file descriptors opened by processes. It can display details about various types of file descriptors, including network sockets, FIFOs, regular files, and more.

The output format is configurable using the -o (or --output) option. The following fields may be displayed:

AINODECLASS <string>
The class of the inode if the file descriptor points to an anonymous inode. This is used for specific cases such as pipefs, eventfd, etc.
APP <string>
The application name associated with the file descriptor, if available.
ASSOC <string>
Association type of the file descriptor. Possible values include "exe" (executable file), "lib" (shared library), "mmap" (memory mapping), "pipe" (pipe), "eventfd" (eventfd), "timerfd" (timerfd), "signalfd" (signalfd), "inotify" (inotify instance), "fanotify" (fanotify instance), "epoll" (epoll instance), "timerfd" (timerfd instance), "fsnotify" (fsnotify instance), "socket" (socket), etc.
AUTONAME <string>
An automatically generated name for the file descriptor, often derived from its type and associated information.
BLOCK <number>
The block number where the file is located.
CHR <string>
The device name for character special files.
COMMAND <string>
The command name of the process owning the file descriptor.
DEVTYPE <string>
The type of the device associated with the file descriptor: blk (block device), chr (character device).
DELETED <string>
Indicates if the file associated with the file descriptor has been deleted from the file system. Prints "deleted" if deleted.
DIR <string>
The directory path for directory file descriptors.
ENDPOINTS <string>
For connected sockets, this shows the local and remote addresses and ports.
EVENTFD.VALUE <number>
The current value of an eventfd.
FD <number>
The file descriptor number.
FILE <string>
The name of the file associated with the file descriptor.
FMODE <string>
The file descriptor mode flags (e.g., O_RDONLY, O_WRONLY, O_RDWR).
GROUP <string>
The group name of the file's owner.
INET.LADDR <string>
Local IP address (IPv4 or IPv6) and local port for TCP/UDP sockets.
INET.LPORT <number>
Local port number for TCP/UDP sockets.
INET.RADDR <string>
Remote IP address (IPv4 or IPv6) and remote port for TCP/UDP sockets.
INET.RPORT <number>
Remote port number for TCP/UDP sockets.
INET6.LADDR <string>
Local IPv6 address and local port for TCP/UDP sockets.
INET6.LPORT <number>
Local port number for TCP/UDP sockets.
INET6.RADDR <string>
Remote IPv6 address and remote port for TCP/UDP sockets.
INET6.RPORT <number>
Remote port number for TCP/UDP sockets.
INODE <number>
The inode number of the file.
IPCS.KEY <string>
The key used for System V IPC objects.
IPCS.TYPE <string>
The type of System V IPC object (msg, sem, shm).
LKEY <string>
The key for locking operations.
LINK <string>
The target path for symbolic links.
LOCK.TYPE <string>
Type of the file lock (e.g., FLOCK, F_RDLCK, F_WRLCK).
MEM.ADDR <string>
The start address of a memory mapping.
MEM.OFF <number>
The offset within the mapped file.
MEM.PROT <string>
The memory protection flags (rwx).
MEM.SIZE <number>
The size of the memory mapping.
MODE <string>
File type and permissions (similar to ls -l).
MOUNT <string>
The mount point of the file system.
NAME <string>
The name of the file or socket.
NETLINK.GROUPS <number>
Multicast groups subscribed to by a netlink socket.
NETLINK.PID <number>
The PID of the netlink socket's peer.
NETLINK.PROTOCOL <string>
The protocol used by the netlink socket (e.g., generic, route, netfilter).
NFS.FATTRS <string>
NFS file attributes.
NFS.FH <string>
NFS file handle.
PID <number>
Process ID of the process owning the file descriptor.
PIPE.TYPE <string>
Type of pipe (e.g., PIPE, FIFO).
PORT <number>
The port number for network sockets.
PROTO <string>
The protocol of the socket (e.g., TCP, UDP, UNIX).
REMOTE.ADDR <string>
The remote address for connected sockets.
REMOTE.PORT <number>
The remote port for connected sockets.
RETRIES <number>
Number of retries for operations on the file descriptor.
RWCOUNT <number>
Number of read/write operations performed on the file descriptor.
SEMAPHORE.VALUE <number>
The current value of a semaphore.
SEQUENTIAL <string>
Indicates if the file descriptor is opened for sequential access.
SHM.KEY <string>
The key for shared memory segments.
SOCK.FAMILY <string>
The address family of the socket (e.g., AF_INET, AF_INET6, AF_UNIX).
SOCK.MAXMSG <number>
Maximum message size for the socket.
SOCK.PEER-PID <number>
PID of the peer process for Unix domain sockets.
SOCK.PEER-UID <number>
UID of the peer process for Unix domain sockets.
SOCK.PROTO <string>
Protocol name for the socket (e.g., TCP, UDP, RAW).
SOCK.STATE <string>

SOCK.TYPE <string>

SOURCE <string>

User ID number.

Filesystem pathname for UNIX domain socket.
USER <string>
User of the process.
VSOCK.LADDR <string>, VSOCK.RADDR <string>
Local VSOCK address. The format of the element is VSOCK.LCID:VSOCK.LPORT.

Well-known CIDs will be decoded: “*”, “hypervisor”, “local”, or “host”. Well-known ports will be decoded: “*”.

VSOCK.LCID <number>, VSOCK.RCID <number>
Local and remote VSOCK context identifiers.
VSOCK.LPORT <number>, VSOCK.RPORT <number>
Local and remote VSOCK ports.
XMODE <string>
Extended version of MODE. This column may grow; new letters may be appended to XMODE when lsfd supports a new state of file descriptors and/or memory mappings.

[-r]

opened of mapped for reading. This is also in MODE.

[-w]

opened of mapped for writing. This is also in MODE.

[-x]

mapped for executing the code. This is also in MODE.

[-D]

deleted from the file system. See also DELETED.

[-Ll]

locked or leased. l represents a read, a shared lock or a read lease. L represents a write or an exclusive lock or a write lease. If both read/shared and write/exclusive locks or leases are taken by a file descriptor, L is used as the flag.

[-m]

Multiplexed. If the file descriptor is targeted by a eventpoll file or classical system calls for multiplexing (select, pselect, poll, and ppoll), this bit flag is set. Note that if an invocation of the classical system calls is interrupted, lsfd may fail to mark m on the file descriptors monitored by the invocation. See restart_syscall(2).

FILTER EXAMPLES

lsfd has few options for filtering. In most of cases, what you should know is -Q (or --filter) option. Combined with -o (or --output) option, you can customize the output as you want.

List files associated with PID 1 and PID 2 processes:

# lsfd -Q '(PID == 1) or (PID == 2)'

Do the same in an alternative way:

# lsfd -Q '(PID == 1) || (PID == 2)'

Do the same in a more efficient way:

# lsfd --pid 1,2

Whitespaces can be used instead of a comma:

# lsfd --pid '1 2'

Utilize pidof(1) for list the files associated with "firefox":

# lsfd --pid "$(pidof firefox)"

List the 1st file descriptor opened by PID 1 process:

# lsfd -Q '(PID == 1) and (FD == 1)'

Do the same in an alternative way:

# lsfd -Q '(PID == 1) && (FD == 1)'

List all running executables:

# lsfd -Q 'ASSOC == "exe"'

Do the same in an alternative way:

# lsfd -Q 'ASSOC eq "exe"'

Do the same but print only file names:

# lsfd -o NAME -Q 'ASSOC eq "exe"' | sort -u

List deleted files associated to processes:

# lsfd -Q 'DELETED'

List non-regular files:

# lsfd -Q 'TYPE != "REG"'

List block devices:

# lsfd -Q 'DEVTYPE == "blk"'

Do the same with TYPE column:

# lsfd -Q 'TYPE == "BLK"'

List files including "dconf" directory in their names:

# lsfd -Q 'NAME =~ ".\*/dconf/.*"'

List files opened in a QEMU virtual machine:

# lsfd -Q '(COMMAND =~ ".\*qemu.*") and (FD >= 0)'

List timerfd files expired within 0.5 seconds:

# lsfd -Q '(TIMERFD.remaining < 0.5) and (TIMERFD.remaining > 0.0)'

List processes communicating via unix stream sockets:

# lsfd  -Q 'TYPE == "UNIX-STREAM" && UNIX.PATH =~ ".+"' -oUNIX.PATH,PID,COMMAND,FD,SOCK.STATE,ENDPOINTS

List processes communicating via a specified unix stream socket:

# lsfd  -Q 'TYPE == "UNIX-STREAM" && UNIX.PATH == "@/tmp/.X11-unix/X0"' -oUNIX.PATH,PID,COMMAND,FD,SOCK.STATE,ENDPOINTS

COUNTER EXAMPLES

Report the numbers of netlink socket descriptors and unix socket descriptors:

# lsfd --summary=only \
        -C 'netlink sockets':'(NAME =~ "NETLINK:.*")' \
        -C 'unix sockets':'(NAME =~ "UNIX:.*")'
VALUE COUNTER
   57 netlink sockets
 1552 unix sockets

Do the same but print in JSON format:

# lsfd --summary=only --json \
        -C 'netlink sockets':'(NAME =~ "NETLINK:.*")' \
        -C 'unix sockets':'(NAME =~ "UNIX:.*")'
{
   "lsfd-summary": [
      {
         "value": 15,
         "counter": "netlink sockets"
      },{
         "value": 798,
         "counter": "unix sockets"
      }
   ]
}
