lockf(3) Manuel des fonctions de bibliothèque lockf(3)

NOM

lockf - appliquer, tester ou supprimer un verrou POSIX sur un fichier ouvert

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int lockf(int fd, int op, off_t size);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

lockf():

    _XOPEN_SOURCE >= 500
        || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Applique, teste ou supprime un verrou POSIX sur une section d'un fichier ouvert. Le fichier est spécifié par fd, un descripteur de fichier ouvert en écriture, l'action par op, et la section consiste en les positions d'octets pos..pos+size-1 si size est positif, et pos-size..pos-1 si size est négatif, où pos est la position actuelle dans le fichier, et si size est zéro, la section s'étend de la position actuelle dans le fichier jusqu'à l'infini, englobant les positions actuelles et futures de fin de fichier. Dans tous les cas, la section peut s'étendre au-delà de la fin actuelle du fichier.

Sous Linux, lockf() est juste une interface au-dessus des verrous fcntl(2). De nombreux autres systèmes implémentent lockf() de cette manière, mais notez que POSIX.1 laisse la relation entre lockf() et les verrous fcntl(2) non spécifiée. Une application portable devrait probablement éviter de mélanger les appels à ces interfaces.

Les opérations valides sont données ci-dessous :

F_LOCK
Définit un verrou exclusif sur la section spécifiée du fichier. Si (une partie de) cette section est déjà verrouillée, l'appel bloque jusqu'à ce que le verrou précédent soit libéré. Si cette section chevauche une section précédemment verrouillée, les deux sont fusionnées. Les verrous de fichier sont libérés dès que le processus détenant les verrous ferme un descripteur de fichier pour le fichier. Un processus enfant n'hérite pas de ces verrous.
F_TLOCK
Identique à F_LOCK, mais l'appel ne bloque jamais et renvoie une erreur au lieu de cela si le fichier est déjà verrouillé.
F_ULOCK
Déverrouille la section indiquée du fichier. Cela peut entraîner la division d'une section verrouillée en deux sections verrouillées.
F_TEST
Teste le verrou : renvoie 0 si la section spécifiée est déverrouillée ou verrouillée par ce processus ; renvoie -1, définit errno sur EAGAIN (EACCES sur certains autres systèmes), si un autre processus détient un verrou.

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES ou EAGAIN
Le fichier est verrouillé et F_TLOCK ou F_TEST a été spécifié, ou l'opération est interdite car le fichier a été mappé en mémoire par un autre processus.
EBADF
fd n'est pas un descripteur de fichier ouvert ; ou op est F_LOCK ou F_TLOCK et fd n'est pas un descripteur de fichier accessible en écriture.
EDEADLK
op était F_LOCK et cette opération de verrouillage entraînerait une interdiction.
EINTR
Pendant l'attente pour acquérir un verrou, l'appel a été interrompu par la livraison d'un signal intercepté par un gestionnaire ; voir signal(7).
EINVAL
Une opération invalide a été spécifiée dans op.
ENOLCK
Trop de verrous de segment ouverts, table des verrous pleine.
