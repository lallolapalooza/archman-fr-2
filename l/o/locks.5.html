NOM

locks - fichier de verrouillage de libzypp

DESCRIPTION

Le fichier /etc/zypp/locks est lu par libzypp au démarrage si zypp.conf le permet. Les entrées sont utilisées pour le verrouillage initial des paquets. Verrouiller un paquet signifie interdire son installation ou désinstallation.

Les entrées valides sont de la forme :

attribut: valeur

Où les attributs et leurs valeurs sont décrits ci-dessous.

Les verrous sont séparés par des lignes vides.

ATTRIBUTS

Tous les attributs sont en minuscules.

repo

spécifie la restriction du dépôt. Seul l'alias est accepté.
Par défaut, tous les dépôts correspondent.

type

restriction du type résolvable. Les valeurs peuvent être package, patch, pattern, product et srcpackage.
Par défaut, tous les types correspondent.

case_sensitive

si les chaînes de caractères sont comparées de manière sensible à la casse. Les valeurs sont true, false, on, off.
Par défaut, la comparaison n'est pas sensible à la casse.

install_status

statut de l'objet. Les états possibles sont installed, not-installed et all. Si plusieurs statuts d'installation sont spécifiés, le dernier est utilisé. Les valeurs sont installed pour tous les paquets installés, non-installed pour les paquets qui peuvent être installés ou réinstallés et all pour les deux.
Par défaut, la valeur est all.

match_type

type de correspondance de chaîne dans les valeurs. N'affecte pas type et repo qui doivent être spécifiés exactement. Les valeurs sont exact, substring, regex pour les expressions régulières, glob pour la correspondance comme en ligne de commande, et word.
Par défaut, la valeur est substring.

query_string

Chaîne à faire correspondre dans plusieurs attributs. Doit être restreinte par un autre attribut avec une valeur vide (c'est recommandé, car sans restriction, attendez-vous à des problèmes de performances).

version

Restreint le verrou à certaines versions uniquement. Contient deux parties : un opérateur optionnel et la version.
L'opérateur est ==, !=, <, >, ⇐, >=. Si l'opérateur n'est pas spécifié, == est utilisé.
La version a le format [epoch:]version[-release].
Exemple : version: < 0:0.11.4-2

solvable_name

nom de l'objet (par exemple, zypper)

solvable_summary

résumé de l'objet

solvable_arch

architecture de l'objet (par exemple, x86_64, i586)

solvable_description

description de l'objet

solvable_eula

texte de licence des objets qui demandent l'acceptation de la licence par l'utilisateur

solvable_license

licence du paquet (uniquement pour les paquets) (par exemple, GPL2)

solvable_keywords

mots-clés qui spécifient le paquet (uniquement pour les paquets)

solvable_authors

auteurs du paquet (uniquement pour les paquets)

solvable_group

groupe de paquets (uniquement pour les paquets) (par exemple, Development/Tools/Version Control)

update_reference_type

référence pour la mise à jour (par exemple, bugzilla, cve) (uniquement pour les correctifs)

EXEMPLES

Paquet Exact

C'est ainsi que l'interface graphique YaST le fait. Verrouille k3b (par exemple, vous ne voulez pas le mettre à jour).
-----locks-----
type: package
solvable_name: k3b
match_type: exact
case_sensitive: on

Caractère générique de Paquet

C'est ainsi que "zypper addlock cross-*-gcc-icecream-backend" le fait.
-----locks-----
type: package
solvable_name: cross-*-gcc-icecream-backend
match_type: glob
case_sensitive: on

Verrouillage de Version

Ne pas installer de nouveau GCC. Ce format est utilisé lors de la conversion du format de verrouillage openSUSE-10.3.
-----locks-----
solvable_name: gcc
match_type: glob
version: > 4.2

Tout ce qui s'appelle KDE

Verrouille tout ce qui contient « kde » dans le nom.
-----locks-----
solvable_name: kde

Tout ce qui mentionne KDE

Verrouille tout ce qui contient « kde » dans le nom, le résumé ou la description.
-----locks-----
query_string: kde
solvable_name:
solvable_summary:
solvable_description:
