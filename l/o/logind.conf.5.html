LOGIND.CONF(5) logind.conf LOGIND.CONF(5)

NOM

logind.conf, logind.conf.d — Fichiers de configuration du gestionnaire de connexion

SYNTAXE

/etc/systemd/logind.conf
/run/systemd/logind.conf
/usr/local/lib/systemd/logind.conf
/usr/lib/systemd/logind.conf
/etc/systemd/logind.conf.d/*.conf
/run/systemd/logind.conf.d/*.conf
/usr/local/lib/systemd/logind.conf.d/*.conf
/usr/lib/systemd/logind.conf.d/*.conf

DESCRIPTION

Ces fichiers configurent divers paramètres du gestionnaire de connexion de systemd, systemd-logind.service(8). Voir systemd.syntax(7) pour une description générale de la syntaxe.

DIRECTORIES DE CONFIGURATION ET PRÉÉDENCE

La configuration par défaut est définie lors de la compilation, ainsi une configuration n'est nécessaire que lorsqu'il est nécessaire de déroger à ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers de remplacement (drop-ins), comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant l'utilisation de fichiers de remplacement pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration de remplacement sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces remplacements ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées telles qu'elles apparaissent dans les fichiers triés.

Lorsque les paquets ont besoin de personnaliser la configuration, ils peuvent installer des remplacements sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les remplacements doivent être utilisés pour remplacer les remplacements de paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un trait d'union, pour simplifier l'ordre. Cela définit également un concept de priorités de remplacement pour permettre aux fournisseurs de systèmes d'exploitation de fournir des remplacements dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les remplacements de paquets remplacent accidentellement les remplacements définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les remplacements dans /usr/ et la plage 60-90 pour les remplacements dans /etc/ et /run/, pour s'assurer que les remplacements locaux et transitoires ont la priorité sur les remplacements fournis par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Toutes les options sont configurées dans la section [Login] :

NAutoVTs=

Prend un entier positif. Configure combien de terminaux virtuels (VT) doivent être alloués par défaut, qui, lorsqu'ils sont basculés et inutilisés auparavant, font que des services "autovt" sont automatiquement lancés. Ces services sont instanciés à partir de l'unité modèle autovt@.service pour le nom TTY VT respectif, par exemple, autovt@tty4.service. Par défaut, autovt@.service est lié à getty@.service. En d'autres termes, des invites de connexion sont démarrées dynamiquement lorsque l'utilisateur bascule vers des terminaux virtuels inutilisés. Ainsi, ce paramètre contrôle combien de "gettys" de connexion sont disponibles sur les VT. Si un VT est déjà utilisé par un autre sous-système (par exemple, une connexion graphique), ce type d'activation ne sera pas tenté. Notez que le VT configuré dans ReserveVT= est toujours soumis à ce type d'activation, même s'il ne fait pas partie des VT configurés avec la directive NAutoVTs=. Par défaut, il vaut 6. Lorsqu'il est défini sur 0, le lancement automatique des services "autovt" est désactivé.

ReserveVT=

Prend un entier positif. Identifie un terminal virtuel qui sera inconditionnellement réservé pour l'activation de autovt@.service (voir ci-dessus). Le VT sélectionné avec cette option sera marqué comme occupé inconditionnellement, de sorte qu'aucun autre sous-système ne l'allouera. Cette fonctionnalité est utile pour garantir que, quel que soit le nombre de VT alloués par d'autres sous-systèmes, un "getty" de connexion est toujours disponible. Par défaut, il vaut 6 (en d'autres termes, il y aura toujours un "getty" disponible sur Alt-F6.). Lorsqu'il est défini sur 0, la réservation de VT est désactivée.

Ajouté dans la version 190.

KillUserProcesses=

Prend un argument booléen. Configure si les processus d'un utilisateur doivent être tués lorsque l'utilisateur se déconnecte. S'il est vrai, l'unité de portée (scope unit) correspondant à la session et tous les processus à l'intérieur de cette portée seront terminés. S'il est faux, la portée est "abandonnée", voir systemd.scope(5), et les processus ne sont pas tués. Par défaut, la valeur est "no", mais voir les options KillOnlyUsers= et KillExcludeUsers= ci-dessous.

En plus des processus de session, des processus utilisateur peuvent s'exécuter sous l'unité de gestionnaire d'utilisateur user@.service. Selon les paramètres de persistance (linger), cela peut permettre aux utilisateurs d'exécuter des processus indépendamment de leurs sessions de connexion. Voir la description de enable-linger dans loginctl(1).

Notez que le réglage de KillUserProcesses=yes cassera des outils tels que screen(1) et tmux(1), à moins qu'ils ne soient déplacés hors de la portée de la session. Voir l'exemple dans systemd-run(1).

KillOnlyUsers=, KillExcludeUsers=

Ces paramètres prennent des listes d'usernames séparées par des espaces qui remplacent le paramètre KillUserProcesses=. Un nom d'utilisateur peut être ajouté à KillExcludeUsers= pour exclure les processus dans les portées de session de cet utilisateur d'être tués même si KillUserProcesses=yes est défini. Si KillExcludeUsers= n'est pas défini, l'utilisateur "root" est exclu par défaut. KillExcludeUsers= peut être défini sur une valeur vide pour remplacer cette valeur par défaut. Si un utilisateur n'est pas exclu, KillOnlyUsers= est vérifié ensuite. Si ce paramètre est spécifié, seuls les processus dans les portées de session de ces utilisateurs seront tués. Sinon, les utilisateurs sont soumis au paramètre KillUserProcesses=yes.

IdleAction=

Configure l'action à entreprendre lorsque le système est inactif. Prend l'une des valeurs suivantes : "ignore", "poweroff", "reboot", "halt", "kexec", "suspend", "hibernate", "hybrid-sleep", "suspend-then-hibernate", "sleep" et "lock". Par défaut, la valeur est "ignore".

Notez que cela nécessite que les sessions utilisateur signalent correctement leur état d'inactivité au système. Le système exécutera l'action après que toutes les sessions auront signalé qu'elles sont inactives, qu'aucun verrou d'inhibiteur d'inactivité n'est actif, et que, par la suite, le temps configuré avec IdleActionSec= (voir ci-dessous) a expiré.

Ajouté dans la version 198.

IdleActionSec=

Configure le délai après lequel l'action configurée dans IdleAction= (voir ci-dessus) est effectuée après que le système soit devenu inactif.

Ajouté dans la version 198.

InhibitDelayMaxSec=

Spécifie le temps maximum pendant lequel une demande d'arrêt ou de mise en veille du système est retardée en raison d'un verrou d'inhibiteur de type "delay" actif, avant que l'inhibiteur ne soit ignoré et que l'opération ne s'exécute quand même. Par défaut, il vaut 5.

UserStopDelaySec=

Spécifie combien de temps l'enregistrement utilisateur et l'unité de service par utilisateur user@.service sont conservés pour un utilisateur après sa déconnexion complète. S'il est réglé sur zéro, le service par utilisateur est
immédiatement lorsque la dernière session de l'utilisateur a pris fin. Si cette option est configurée sur une valeur non nulle, les cycles de déconnexion/connexion rapides sont accélérés, car le gestionnaire de service de l'utilisateur n'est pas constamment redémarré. Si réglé sur "infinity", le service par utilisateur pour un utilisateur n'est jamais terminé après la première connexion et continue de s'exécuter jusqu'à l'arrêt du système. Valeur par défaut : 10s.

Ajouté dans la version 240.

SleepOperation=

Prend une liste d'opérations de veille. Les valeurs possibles sont "suspend", "hibernate", "hybrid-sleep" et "suspend-then-hibernate". Contrôle les opérations de veille candidates pour l'action "sleep". Lorsque l'action "sleep" est effectuée, les opérations de veille spécifiées sont vérifiées dans un ordre fixe ("suspend-then-hibernate" → "hybrid-sleep" → "suspend" → "hibernate"), et la première prise en charge par la machine est utilisée pour mettre le système en veille. Valeur par défaut : "suspend-then-hibernate suspend hibernate".

Ajouté dans la version 256.

HandlePowerKey=, HandlePowerKeyLongPress=, HandleRebootKey=, HandleRebootKeyLongPress=, HandleSuspendKey=, HandleSuspendKeyLongPress=, HandleHibernateKey=, HandleHibernateKeyLongPress=, HandleLidSwitch=, HandleLidSwitchExternalPower=, HandleLidSwitchDocked=, HandleSecureAttentionKey=

Contrôle la manière dont logind doit gérer les touches d'alimentation, de redémarrage et de veille du système, ainsi que le contact du capot, pour déclencher des actions telles que l'arrêt du système, le redémarrage ou la mise en veille. Peut être l'une des valeurs suivantes : "ignore", "poweroff", "reboot", "halt", "kexec", "suspend", "hibernate", "hybrid-sleep", "suspend-then-hibernate", "sleep", "lock", "factory-reset" et "secure-attention-key". Si "ignore", systemd-logind ne gérera jamais ces touches. Si "lock", toutes les sessions en cours seront verrouillées ; sinon, l'action spécifiée sera effectuée lors de l'événement respectif. Seuls les périphériques d'entrée avec la balise udev "power-switch" seront surveillés pour les événements de touche/capot.

HandlePowerKey= vaut par défaut "poweroff", HandleRebootKey= vaut par défaut "reboot", HandleSuspendKey= vaut par défaut "suspend", HandleHibernateKey= vaut par défaut "hibernate", HandlePowerKeyLongPress= vaut par défaut "ignore", HandleRebootKeyLongPress= vaut par défaut "poweroff", HandleSuspendKeyLongPress= vaut par défaut "hibernate", HandleHibernateKeyLongPress= vaut par défaut "ignore". HandleLidSwitch= vaut par défaut "suspend". HandleLidSwitchExternalPower= est complètement ignoré par défaut (pour la compatibilité ascendante) — une valeur explicite doit être définie avant qu'il ne soit utilisé pour déterminer le comportement. HandleLidSwitchDocked= vaut par défaut "ignore". Si le système est inséré dans une station d'accueil, ou si plus d'un écran est connecté, l'action spécifiée par HandleLidSwitchDocked= se produit ; si le système est alimenté par le secteur, l'action (le cas échéant) spécifiée par HandleLidSwitchExternalPower= se produit ; sinon, l'action HandleLidSwitch= se produit. HandleSecureAttentionKey= vaut par défaut "secure-attention-key"

Une application différente peut désactiver la gestion par logind des touches d'alimentation et de veille du système, ainsi que du contact du capot, en acquérant un verrou d'inhibiteur de bas niveau ("handle-power-key", "handle-suspend-key", "handle-hibernate-key", "handle-lid-switch", "handle-reboot-key"). Ceci est le plus souvent utilisé par les environnements de bureau graphiques pour prendre en charge la gestion de la mise en veille et de la mise en hibernation, et pour utiliser leurs propres mécanismes de configuration. Si un verrou d'inhibiteur de bas niveau est acquis, logind n'effectuera aucune action lorsque cette touche ou ce commutateur est déclenché et que les paramètres Handle*= sont sans importance, à l'exception de HandleSecureAttentionKey=, qui est toujours géré depuis son ajout dans la v257.

Ajouté dans la version 184.

PowerKeyIgnoreInhibited=, SuspendKeyIgnoreInhibited=, HibernateKeyIgnoreInhibited=, LidSwitchIgnoreInhibited=, RebootKeyIgnoreInhibited=

Contrôle si les actions que systemd-logind effectue lorsque les touches d'alimentation, de redémarrage et de veille, ainsi que le contact du capot, sont déclenchées sont soumises à des verrous d'inhibiteur de haut niveau ("shutdown", "reboot", "sleep", "idle"). Les verrous d'inhibiteur de bas niveau ("handle-power-key", "handle-suspend-key", "handle-hibernate-key", "handle-lid-switch", "handle-reboot-key"), sont toujours respectés, quelle que soit cette configuration.

Ces paramètres prennent des arguments booléens. Si "no", les verrous d'inhibiteur acquis par les applications sont respectés. Si "yes", les verrous d'inhibiteur "shutdown", "reboot" "sleep" et "idle" sont ignorés. PowerKeyIgnoreInhibited=, SuspendKeyIgnoreInhibited=, HibernateKeyIgnoreInhibited= et RebootKeyIgnoreInhibited= valent par défaut "no". LidSwitchIgnoreInhibited= vaut par défaut "yes". Cela signifie que lorsque systemd-logind gère les événements par lui-même (aucun verrou d'inhibiteur de bas niveau n'est acquis par une autre application), le contact du capot ne respecte pas les bloqueurs de veille par défaut, mais les touches d'alimentation et de veille le font.

Ajouté dans la version 190.

HoldoffTimeoutSec=

Spécifie une période de temps après le démarrage du système ou la reprise du système pendant laquelle systemd attendra avant de réagir aux événements du capot. Ceci est nécessaire pour que le système puisse détecter correctement tous les périphériques connectés à chaud, afin que systemd puisse ignorer les événements du capot si des moniteurs externes ou des stations d'accueil sont connectés. Si réglé sur 0, systemd réagira toujours immédiatement, potentiellement avant que le noyau n'ait complètement interrogé tous les périphériques connectés à chaud. Ceci est sûr, tant que vous ne vous souciez pas que systemd prenne en compte les périphériques qui ont été branchés ou débranchés pendant que le système était éteint. Valeur par défaut : 30s.

Ajouté dans la version 220.

RuntimeDirectorySize=

Définit la limite de taille du répertoire d'exécution $XDG_RUNTIME_DIR pour chaque utilisateur qui se connecte. Prend une taille en octets, éventuellement suffixée des suffixes habituels K, G, M et T, à la base 1024 (CEI). Alternativement, un pourcentage numérique suffixé par "%" peut être spécifié, ce qui définit la limite de taille par rapport à la quantité de RAM physique. Valeur par défaut : 10%. Notez qu'il s'agit uniquement d'une limite de sécurité. Comme chaque répertoire d'exécution est un système de fichiers tmpfs, il ne consommera que la mémoire nécessaire.

Ajouté dans la version 211.

RuntimeDirectoryInodesMax=

Définit la limite du nombre d'inodes pour le répertoire d'exécution $XDG_RUNTIME_DIR pour chaque utilisateur qui se connecte. Prend un nombre, éventuellement suffixé des suffixes habituels K, G, M et T, à la base 1024 (CEI). Valeur par défaut : RuntimeDirectorySize= divisé par 4096. Notez qu'il s'agit uniquement d'une limite de sécurité. Comme chaque répertoire d'exécution est un système de fichiers tmpfs, il ne consommera que la mémoire nécessaire.

Ajouté dans la version 246.

InhibitorsMax=

Contrôle le nombre maximum d'inhibiteurs simultanés autorisés. Valeur par défaut : 8192 (8K).

Ajouté dans la version 230.

SessionsMax=

Contrôle le nombre maximum de sessions utilisateur simultanées à gérer. Valeur par défaut : 8192 (8K). Selon la manière dont le module pam_systemd.so est inclus dans la configuration de la pile PAM, les sessions de connexion supplémentaires seront soit refusées, soit autorisées mais non suivies par systemd-logind.

Ajouté dans la version 230.

RemoveIPC=

Contrôle si les objets IPC System V et POSIX appartenant à l'utilisateur doivent être supprimés lorsque l'utilisateur se déconnecte complètement. Prend un argument booléen. Si activé, l'utilisateur ne pourra pas consommer de ressources IPC après la fin de la dernière session de l'utilisateur. Cela couvre les sémaphores, la mémoire partagée et les files d'attente de messages de System V, ainsi que la mémoire partagée et les files d'attente de messages POSIX. Notez que les objets IPC de l'utilisateur root et des autres utilisateurs système sont exclus de l'effet de cette configuration. Valeur par défaut : "yes".

Ajouté dans la version 212.

StopIdleSessionSec=

Spécifie un délai d'attente en secondes, ou une période de temps après laquelle systemd-logind vérifie l'état d'inactivité de toutes les sessions. Chaque session inactive pendant plus longtemps que le délai sera arrêtée. Notez que cette option ne s'applique pas aux sessions "greeter" ou "lock-screen". Valeur par défaut : "infinity" (systemd-logind ne vérifie pas l'état d'inactivité des sessions). Pour plus de détails sur la syntaxe des périodes de temps, voir systemd.time(7).

Ajouté dans la version 252.

DesignatedMaintenanceTime=

Spécifie un événement de calendrier par défaut pour les arrêts programmés. Ainsi, lorsque vous utilisez par exemple la commande shutdown -r pour redémarrer le système sans spécifier de délai, logind utiliserait l'événement de calendrier configuré à la place. Pour plus de détails sur la syntaxe des événements de calendrier, voir systemd.time(7).

Ajouté dans la version 257.

WallMessages=

Contrôle si les messages wall(1) doivent être envoyés aux terminaux de tous les utilisateurs actuellement connectés lors d'un arrêt ou d'un redémarrage. Valeur par défaut : "yes", et peut être modifiée à l'exécution via les propriétés DBus "EnableWallMessages" et "WallMessagePrefix".

Ajouté dans la version 258.

logind.conf — Fichier de configuration du gestionnaire de connexion

NOM

logind.conf — Fichier de configuration du gestionnaire de connexion

SYNOPSIS

Le fichier de configuration /etc/systemd/logind.conf et les fichiers dans /etc/systemd/logind.conf.d/ sont utilisés pour configurer le processus systemd-logind.

DESCRIPTION

Le programme systemd-logind est un démon qui gère les identifiants d'utilisateur, les sessions de connexion, les périphériques TTY, et les cessions d'utilisateurs d'une manière plus propre. Il gère la politique d'accès aux périphériques et maintient des informations sur les utilisateurs connectés. Il est principalement configuré via le fichier logind.conf.

Le fichier de configuration principal est /etc/systemd/logind.conf. Les fichiers de configuration supplémentaires sont recherchés dans le répertoire /etc/systemd/logind.conf.d/. Ils sont lus dans l'ordre alphabétique. Les configurations définies dans les fichiers ultérieurs écrasent celles définies dans les fichiers précédents. Les configurations définies dans /etc/systemd/logind.conf sont appliquées en dernier.

Les fichiers de configuration doivent être marqués comme lisibles par tous et modifiables uniquement par root. S'ils ne sont pas correctement protégés, systemd-logind ne les lira pas.

DIRECTORIES DE CONFIGURATION ET PRÉCÉDENCE

Les fichiers de configuration sont définis par les directives suivantes :

/etc/systemd/logind.conf
Configuration par défaut du système.
/etc/systemd/logind.conf.d/*.conf
Configuration spécifique au système, dans un format de type ini. Les fichiers sont triés par nom et leur contenu est appliqué dans l'ordre. Le contenu des fichiers ultérieurs écrasera le contenu des fichiers précédents.

OPTIONS

Le fichier de configuration contient des sections et des paramètres au format clé=valeur. Les sections valides sont [Login]. Les lignes vides ou commençant par # ou ; sont ignorées.

[Login]

NAutoVTs=
Nombre maximal de consoles virtuelles à activer automatiquement. Par défaut, 63.
ReserveVT=
Nombre de consoles virtuelles à réserver pour l'utilisation par le système (par exemple, pour les démons). Par défaut, 1.
KillUserProcesses=
Indique si les processus des utilisateurs doivent être tués lorsqu'ils se déconnectent. Peut être yes, no, runlevel ou other. Par défaut, no.
KillOnlyInHome=
Indique si seuls les processus s'exécutant dans le répertoire personnel de l'utilisateur doivent être tués. Peut être yes ou no. Par défaut, no.
HandlePowerKey=
Action à effectuer lorsque la touche d'alimentation est pressée. Peut être ignore, poweroff, reboot, halt, kexec, suspend, hibernate, hybrid-sleep, suspend-then-hibernate. Par défaut, poweroff.
HandleSuspendKey=
Action à effectuer lorsque la touche de mise en veille est pressée. Peut être ignore, poweroff, reboot, halt, kexec, suspend, hibernate, hybrid-sleep, suspend-then-hibernate. Par défaut, suspend.
HandleHibernateKey=
Action à effectuer lorsque la touche d'hibernation est pressée. Peut être ignore, poweroff, reboot, halt, kexec, suspend, hibernate, hybrid-sleep, suspend-then-hibernate. Par défaut, hibernate.
HandleLidSwitch=
Action à effectuer lorsque le couvercle de l'ordinateur portable est fermé. Peut être ignore, poweroff, reboot, halt, kexec, suspend, hibernate, hybrid-sleep, suspend-then-hibernate. Par défaut, suspend.
HandleLidSwitchExternalPower=
Action à effectuer lorsque le couvercle de l'ordinateur portable est fermé et qu'une alimentation externe est connectée. Les mêmes valeurs que HandleLidSwitch=. Par défaut, suspend.
HandleLidSwitchDocked=
Action à effectuer lorsque le couvercle de l'ordinateur portable est fermé et qu'il est amarré. Les mêmes valeurs que HandleLidSwitch=. Par défaut, ignore.
LoginUnixSocket=
Chemin du socket UNIX de systemd-logind. Par défaut, /run/systemd/login/stdout.
LoginBinary=
Chemin de l'exécutable login. Par défaut, /usr/bin/login.
KillUserGroups=
Indique si les groupes d'utilisateurs doivent être tués lorsqu'ils se déconnectent. Peut être yes ou no. Par défaut, no.
PowerKeyIgnoreInhibited=
Indique si la touche d'alimentation doit être ignorée lorsque l'inhibition est active. Peut être yes ou no. Par défaut, no.
SuspendKeyIgnoreInhibited=
Indique si la touche de mise en veille doit être ignorée lorsque l'inhibition est active. Peut être yes ou no. Par défaut, no.
HibernateKeyIgnoreInhibited=
Indique si la touche d'hibernation doit être ignorée lorsque l'inhibition est active. Peut être yes ou no. Par défaut, no.
LidSwitchIgnoreInhibited=
Indique si la fermeture du couvercle doit être ignorée lorsque l'inhibition est active. Peut être yes ou no. Par défaut, no.

VOIR AUSSI

systemd-logind(8), systemd(1), systemctl(1)

NOTES

Le fichier de configuration est analysé au démarrage de systemd-logind. Pour que les modifications prennent effet, le service systemd-logind doit être redémarré.

Les changements apportés à la configuration logind.conf n'affectent pas les sessions actives. Seules les nouvelles sessions seront affectées.
