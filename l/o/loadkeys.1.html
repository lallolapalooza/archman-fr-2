LOADKEYS(1) Manuel des commandes générales LOADKEYS(1)

NOM

loadkeys - charger les tables de traduction du clavier

SYNTAXE

loadkeys [OPTION]... NOMFICHIER...
loadkeys --default
loadkeys --mktable
loadkeys --bkeymap
loadkeys --tkeymap[=forme]
loadkeys --parse

DESCRIPTION

Le programme loadkeys lit le ou les fichiers spécifiés par NOMFICHIER.... Son but principal est de charger la disposition du clavier du noyau pour la console. Vous pouvez spécifier le périphérique de console avec l'option -C (ou --console ).

RÉINITIALISATION PAR DÉFAUT

Si l'option -d (ou --default ) est donnée, loadkeys charge une disposition de clavier par défaut, probablement le fichier defkeymap.map soit dans /usr/share/kbd/keymaps soit dans /usr/src/linux/drivers/tty/vt. (Probablement le premier était défini par l'utilisateur, tandis que le second est une disposition de clavier qwerty pour PC - peut-être pas ce qui était souhaité.) Parfois, avec une disposition de clavier étrange chargée (avec le signe moins sur une combinaison de modificateurs obscure inconnue), il est plus facile de taper `loadkeys defkeymap.map'.

CHARGER LA DISPOSITION DU CLAVIER DU NOYAU

La fonction principale de loadkeys est de charger ou de modifier les tables de traduction du pilote de clavier. Lors de la spécification des noms de fichiers, l'entrée standard peut être représentée par un tiret (-). Si aucun fichier n'est spécifié, les données sont lues depuis l'entrée standard.

Pour de nombreux pays et types de claviers, des dispositions de clavier appropriées sont déjà disponibles, et une commande comme `loadkeys uk' pourrait faire ce que vous voulez. D'un autre côté, il est facile de construire sa propre disposition de clavier. L'utilisateur doit dire quels symboles appartiennent à chaque touche. Elle peut trouver le code de touche pour une touche en utilisant showkey(1), tandis que le format des dispositions de clavier est donné dans keymaps(5) et peut également être vu à partir de la sortie de dumpkeys(1).

CHARGER LA TABLE DES ACCENTS DU NOYAU

Si le fichier d'entrée ne contient aucune définition de touche de composition, la table des accents du noyau reste inchangée, sauf si l'option -c (ou --clearcompose ) est donnée, auquel cas la table des accents du noyau est vidée. Si le fichier d'entrée contient des définitions de touches de composition, alors toutes les anciennes définitions sont supprimées et remplacées par les nouvelles entrées spécifiées. La table des accents du noyau est une séquence de (par défaut 68) entrées décrivant comment les signes diacritiques morts et les touches de composition se comportent. Par exemple, une ligne

compose ',' 'c' to ccedilla

signifie que <ToucheCompose><,><c> doit être combiné pour <ccedilla>. Le contenu actuel de cette table peut être vu en utilisant `dumpkeys --compose-only'.

CHARGER LA TABLE DES CHAÎNES DU NOYAU

L'option -s (ou --clearstrings ) efface la table des chaînes du noyau. Si cette option n'est pas donnée, loadkeys ajoutera ou remplacera uniquement les chaînes, sans les supprimer. (Ainsi, l'option -s est requise pour atteindre un état bien défini.) La table des chaînes du noyau est une séquence de chaînes portant des noms comme F31. On peut faire en sorte que la touche de fonction F5 (sur un clavier PC ordinaire) produise le texte `Bonjour !', et Shift+F5 `Au revoir !' en utilisant des lignes

keycode 63 = F70 F71
string F70 = "Bonjour !"
string F71 = "Au revoir !"

dans la disposition du clavier. Les liaisons par défaut pour les touches de fonction sont des séquences d'échappement pour la plupart inspirées du terminal VT100.

CRÉER LA TABLE SOURCE DU NOYAU

Si l'option -m (ou --mktable ) est donnée, loadkeys imprime sur la sortie standard un fichier qui peut être utilisé comme /usr/src/linux/drivers/tty/vt/defkeymap.c, spécifiant les liaisons de touches par défaut pour un noyau (et ne modifie pas la disposition actuelle du clavier).

CRÉER UNE DISPOSITION BINAIRE DU CLAVIER

Si l'option -b (ou --bkeymap ) est donnée, loadkeys imprime sur la sortie standard un fichier qui peut être utilisé comme une disposition de clavier binaire attendue par la commande loadkmap de Busybox (et ne modifie pas la disposition actuelle du clavier).

CRÉER UNE DISPOSITION TEXTE DU CLAVIER

Si l'option -t (ou --tkeymap ) est donnée, loadkeys imprime sur la sortie standard un fichier qui peut être utilisé comme une disposition de clavier texte attendue par la commande loadkeys (et ne modifie pas la disposition actuelle du clavier). Un argument optionnel peut être utilisé pour sélectionner la forme du format de sortie : -tforme (ou --tkeymap=forme ).

Formes disponibles :

2 sortie par défaut.
4 une ligne pour chaque code de touche.
8 une ligne pour chaque paire (modificateur, code de touche).
16 une ligne pour chaque code de touche jusqu'au premier trou.

MODE UNICODE

loadkeys détecte automatiquement si la console est en mode Unicode ou ASCII (XLATE). Lorsqu'une disposition de clavier est chargée, les symboles de touches littéraux (comme section) sont résolus en conséquence ; les symboles de touches numériques sont convertis pour s'adapter au mode de console actuel, quelle que soit la manière dont ils sont spécifiés (décimal, octal, hexadécimal ou Unicode).

Le commutateur -u (ou --unicode) force loadkeys à convertir toutes les dispositions de clavier en Unicode. Si le clavier est dans un mode non Unicode, comme XLATE, loadkeys le changera en Unicode pendant son exécution. Un message d'avertissement sera imprimé dans ce cas.

Il est recommandé d'exécuter kbd_mode(1) avant loadkeys au lieu d'utiliser l'option -u.

AUTRES OPTIONS

-a --ascii
Forcer la conversion en ASCII.
-h --help
loadkeys imprime son numéro de version et un court message d'utilisation sur la sortie d'erreur standard des programmes et se termine.
-p --parse
loadkeys recherche et analyse la disposition du clavier sans action.
-q --quiet
loadkeys supprime toute sortie normale.
-V --version
loadkeys imprime le numéro de version et se termine.

AVERTISSEMENT

Notez que toute personne ayant un accès en lecture à /dev/console peut exécuter loadkeys et ainsi modifier la disposition du clavier, la rendant potentiellement inutilisable. Notez que la table de traduction du clavier est commune à toutes les consoles virtuelles, donc tout changement apporté aux liaisons du clavier affecte toutes les consoles virtuelles simultanément.

Notez que parce que les changements affectent toutes les consoles virtuelles, ils survivent aussi à votre session. Cela signifie que même à l'invite de connexion, les liaisons de touches peuvent ne pas être celles attendues par l'utilisateur.

FICHIERS

/usr/share/kbd/keymaps
répertoire par défaut pour les dispositions de clavier.
/usr/src/linux/drivers/tty/vt/defkeymap.map
disposition de clavier par défaut du noyau.

loadkeys(8)

NOM

loadkeys - charge les tables de clavier du noyau

SYNTAXE

loadkeys [options] [keymap]

DESCRIPTION

La commande loadkeys charge une nouvelle table de clavier dans le noyau Linux. Les tables de clavier déterminent la signification des touches pressées. Si aucun argument keymap n'est donné, loadkeys essaie de charger la table de clavier système par défaut, qui est généralement spécifiée dans le fichier de configuration du système d'amorçage (par exemple, /etc/vconsole.conf).

Le noyau Linux utilise des tables de clavier pour interpréter les événements du clavier. Chaque touche du clavier est mappée sur un ou plusieurs codes. Ces codes peuvent être des caractères simples, des séquences de caractères, ou des actions spéciales comme le changement de combinaison de touches.

RÉINITIALISER AUX VALEURS PAR DÉFAUT

Pour réinitialiser la table de clavier aux valeurs par défaut du système, vous pouvez exécuter : 

loadkeys $(localectl status | grep 'X11 Layout' | awk '{print $2}')

Ou, si vous savez quelle table de clavier utiliser : 

loadkeys fr

(remplacez fr par le nom de votre table de clavier préférée).

CHARGER UNE TABLE DE CLAVIER DU NOYAU

Pour charger une table de clavier spécifique, utilisez l'option -k ou --keymap suivie du nom du fichier de la table de clavier. Par exemple : 

loadkeys --keymap /usr/share/kbd/keymaps/i386/qwerty/fr-latin9.map.gz

Les tables de clavier sont généralement situées dans le répertoire /usr/share/kbd/keymaps/. Vous pouvez voir une liste complète des tables de clavier disponibles dans ce répertoire.

CHARGER UNE TABLE D'ACCENTS DU NOYAU

L'option -a ou --ascii-table charge une table d'accents du noyau. Celles-ci sont utilisées pour gérer les caractères accentués et spéciaux.

CHARGER UNE TABLE DE CHAÎNES DU NOYAU

L'option -s ou --string-table charge une table de chaînes du noyau. Celles-ci sont utilisées pour définir des chaînes de caractères associées à des touches spécifiques.

CRÉER UNE TABLE SOURCE DU NOYAU

L'option -c ou --compile crée une table source du noyau à partir d'un fichier spécifié. Le résultat est écrit sur la sortie standard.

CRÉER UNE TABLE DE CLAVIER BINAIRE

L'option -B ou --clear-all efface toutes les tables du noyau et charge la nouvelle. Utilisez cette option avec prudence car elle réinitialise toutes les tables chargées.

CRÉER UNE TABLE DE CLAVIER TEXTE

L'option -t ou --text-table crée une table de clavier au format texte à partir d'un fichier spécifié. Le résultat est écrit sur la sortie standard.

MODE UNICODE

Lorsque vous utilisez des tables de clavier qui prennent en charge Unicode, loadkeys peut charger ces tables pour permettre l'utilisation de caractères Unicode via le clavier. Les tables Unicode sont généralement nommées avec l'extension .map.gz et contiennent des informations sur le mappage des touches aux points de code Unicode.

AUTRES OPTIONS

D'autres options peuvent être disponibles pour loadkeys, telles que la gestion des jeux de caractères, la définition de combinaisons de touches spécifiques, et le débogage. Consultez la page de manuel complète pour une liste exhaustive.

ATTENTION

Une mauvaise configuration de la table de clavier peut rendre votre système inutilisable. Soyez prudent lorsque vous modifiez les tables de clavier et assurez-vous de savoir comment restaurer la configuration par défaut si nécessaire.

FICHIERS

  • /usr/share/kbd/keymaps/ : Répertoire contenant les tables de clavier.
  • /etc/vconsole.conf : Fichier de configuration pour la console virtuelle, où la table de clavier par défaut peut être spécifiée.
