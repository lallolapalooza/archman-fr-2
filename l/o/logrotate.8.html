LOGROTATE(8) Manuel de l'administrateur système LOGROTATE(8)

NOM

logrotate ‐ fait pivoter, compresse et envoie par courrier les journaux système

SYNOPIS

logrotate [--force] [--debug] [--state fichier] [--skip-state-lock] [--wait-for-state-lock] [--verbose] [--log fichier] [--mail commande] fichier_config [fichier_config2 ...]

DESCRIPTION

logrotate est conçu pour faciliter l'administration des systèmes qui génèrent un grand nombre de fichiers journaux. Il permet la rotation automatique, la compression, la suppression et l'envoi par courrier des fichiers journaux. Chaque fichier journal peut être traité quotidiennement, hebdomadairement, mensuellement, ou lorsqu'il atteint une taille trop importante.

Normalement, logrotate est exécuté comme une tâche cron quotidienne. Il ne modifiera pas un journal plus d'une fois par jour, sauf si le critère pour ce journal est basé sur la taille du journal et que logrotate est exécuté plus d'une fois par jour, ou si l'option -f ou --force est utilisée.

Un nombre quelconque de fichiers de configuration peut être fourni en ligne de commande. Les fichiers de configuration ultérieurs peuvent remplacer les options fournies dans les fichiers précédents, de sorte que l'ordre dans lequel les fichiers de configuration logrotate sont listés est important. Normalement, un seul fichier de configuration qui inclut les autres fichiers de configuration nécessaires doit être utilisé. Voir ci-dessous pour plus d'informations sur la façon d'utiliser la directive include pour y parvenir. Si un répertoire est donné en ligne de commande, chaque fichier de ce répertoire est utilisé comme fichier de configuration.

Si aucun argument de ligne de commande n'est donné, logrotate affichera des informations sur la version et les droits d'auteur, ainsi qu'un bref résumé d'utilisation. Si des erreurs surviennent lors de la rotation des journaux, logrotate se terminera avec un statut non nul, bien que le fichier d'état soit mis à jour.

OPTIONS

-f, --force
Indique à logrotate de forcer la rotation, même s'il ne pense pas que cela soit nécessaire. C'est parfois utile après avoir ajouté de nouvelles entrées à un fichier de configuration logrotate, ou si d'anciens fichiers journaux ont été supprimés manuellement, car les nouveaux fichiers seront créés et la journalisation continuera correctement.
-d, --debug
Active le mode de débogage, ce qui signifie qu'aucune modification n'est apportée aux journaux et que le fichier d'état de logrotate n'est pas mis à jour. Seuls les messages de débogage sont affichés.
-s, --state fichier_etat
Indique à logrotate d'utiliser un fichier d'état alternatif. Ceci est utile si logrotate est exécuté en tant qu'utilisateur différent pour divers ensembles de fichiers journaux. Pour éviter l'exécution parallèle, logrotate acquiert par défaut un verrou sur le fichier d'état ; s'il ne peut être acquis, logrotate se terminera avec la valeur 3. Le fichier d'état par défaut est /var/lib/logrotate.status. Si /dev/null est donné comme fichier d'état, alors logrotate n'essaiera pas de verrouiller ou d'écrire dans le fichier d'état.
--skip-state-lock
Ne pas verrouiller le fichier d'état, par exemple si le verrouillage n'est pas pris en charge ou est interdit.
--wait-for-state-lock
Attendre que le verrou sur le fichier d'état soit libéré par un autre processus logrotate. Cette option peut entraîner une attente indéfinie de logrotate. À utiliser avec prudence.
-v, --verbose
Active le mode verbeux, par exemple pour afficher des messages pendant la rotation.
-l, --log fichier
Indique à logrotate de journaliser la sortie verbeuse dans le fichier_journal. La sortie verbeuse journalisée dans ce fichier est la même que celle obtenue en exécutant logrotate avec le commutateur -v. Le fichier journal est écrasé à chaque exécution de logrotate.
-m, --mail commande
Indique à logrotate quelle commande utiliser lors de l'envoi des journaux par courrier. Cette commande doit accepter les arguments suivants :
1) l'objet du message donné avec '-s subject'
2) le destinataire.
La commande doit ensuite lire un message sur l'entrée standard et l'envoyer par courrier au destinataire. La commande de courrier par défaut est /usr/bin/mail.
--usage
Affiche un bref résumé d'utilisation.
-?, --help
Affiche le message d'aide.
--version
Affiche les informations de version.

FICHIER DE CONFIGURATION

logrotate lit tout sur les fichiers journaux qu'il doit traiter à partir de la série de fichiers de configuration spécifiés en ligne de commande. Chaque fichier de configuration peut définir des options globales (les définitions locales remplacent les définitions globales, et les définitions ultérieures remplacent les précédentes) et spécifier les fichiers journaux à faire pivoter. Les options globales n'affectent pas les directives include précédentes. Un fichier de configuration simple ressemble à ceci :

# exemple de fichier de configuration logrotate
compress
/var/log/messages {
    rotate 5
    weekly
    postrotate
        /usr/bin/killall -HUP syslogd
    endscript
}
"/var/log/httpd/access.log" /var/log/httpd/error.log {
    rotate 5
    mail recipient@example.org
    size 100k
    sharedscripts
    postrotate
        /usr/bin/killall -HUP httpd
    endscript
}
/var/log/news/* {
    monthly
    rotate 2
    olddir /var/log/news/old
    missingok
    sharedscripts
    postrotate
        kill -HUP $(cat /var/run/inn.pid)
    endscript
    nocompress
}
~/log/*.log {}

Les premières lignes définissent les options globales ; dans l'exemple, les journaux sont compressés après leur rotation. Notez que les commentaires peuvent apparaître n'importe où dans le fichier de configuration tant que le premier caractère non blanc de la ligne est un #.

Les valeurs sont séparées des directives par des espaces blancs et/ou un signe = facultatif. Les nombres doivent être spécifiés dans un format compris par strtoul(3).

La section suivante du fichier de configuration définit comment gérer le fichier journal /var/log/messages. Le journal passera par cinq rotations hebdomadaires avant d'être supprimé. Après la rotation du fichier journal (mais avant que l'ancienne version du journal ne soit compressée), la commande /usr/bin/killall -HUP syslogd sera exécutée.

La section suivante définit les paramètres pour les deux fichiers /var/log/httpd/access.log et /var/log/httpd/error.log. Chacun est fait pivoter chaque fois qu'il dépasse 100 Ko, et les anciens fichiers journaux sont envoyés par courrier (non compressés) à recipient@example.org après 5 rotations, au lieu d'être supprimés. sharedscripts signifie que le script postrotate ne sera exécuté qu'une seule fois pour cette section, et non une fois pour chaque journal qui est mis en rotation. Notez que les noms de fichiers journaux peuvent être entourés de guillemets (et que les guillemets sont requis si le nom contient des espaces). Les règles de citation normales du shell s'appliquent, avec les caractères ', " et \ pris en charge.

La section suivante définit les paramètres pour tous les fichiers dans /var/log/news. Chaque fichier est mis en rotation mensuellement.

La dernière section utilise l'expansion de tilde pour faire pivoter les fichiers journaux dans le répertoire personnel de l'utilisateur actuel. Ceci n'est disponible que si votre bibliothèque glob prend en charge l'expansion de tilde. GNU glob le prend en charge.

Veuillez utiliser les caractères génériques avec précaution. Si vous spécifiez *, logrotate fera pivoter tous les fichiers, y compris les fichiers déjà mis en rotation. Pour éviter cela, utilisez la directive olddir ou un caractère générique plus précis (tel que *.log).

Veuillez noter que, par défaut, lors de l'utilisation de systemd(1), l'option ProtectSystem=full est définie dans le fichier logrotate.service. Cela empêche logrotate de modifier les journaux dans /etc et /usr.

Voici plus d'informations sur les directives qui peuvent être incluses dans un fichier de configuration logrotate :

DIRECTIVES DU FICHIER DE CONFIGURATION

Ces directives peuvent être incluses dans un fichier de configuration logrotate :

Rotation

rotate nombre
Les fichiers journaux sont tournés nombre fois avant d'être supprimés ou envoyés par courrier à l'adresse spécifiée dans une directive mail. Si nombre est 0, les anciennes versions sont supprimées plutôt que tournées. Si nombre est -1, les anciens journaux ne sont pas supprimés du tout, sauf qu'ils sont affectés par maxage (à utiliser avec prudence, risque de gaspiller performances et espace disque). La valeur par défaut est 0.
olddir répertoire
Les journaux sont déplacés dans répertoire pour la rotation. Le répertoire doit se trouver sur le même périphérique physique que le fichier journal en cours de rotation, à moins que l'option copy, copytruncate ou renamecopy ne soit utilisée. Le répertoire est supposé être relatif au répertoire contenant le fichier journal, sauf si un chemin absolu est spécifié. Lorsque cette option est utilisée, toutes les anciennes versions du journal se retrouvent dans répertoire. Cette option peut être remplacée par l'option noolddir.
noolddir
Les journaux sont tournés dans le répertoire où ils résident normalement (cela remplace l'option olddir).
su utilisateur groupe
Faites tourner les fichiers journaux définis sous cet utilisateur et ce groupe au lieu d'utiliser l'utilisateur/groupe par défaut (généralement root). utilisateur spécifie l'utilisateur utilisé pour la rotation et groupe spécifie le groupe utilisé pour la rotation (voir la section UTILISATEUR ET GROUPE pour plus de détails). Si l'utilisateur/groupe que vous spécifiez ici n'a pas les privilèges suffisants pour créer des fichiers avec la propriété que vous avez spécifiée dans une directive create, cela provoquera une erreur. Si logrotate s'exécute avec les privilèges root, il est recommandé d'utiliser la directive su pour faire tourner les fichiers dans des répertoires qui sont directement ou indirectement sous le contrôle d'utilisateurs non privilégiés.

Fréquence

hourly
Les fichiers journaux sont tournés toutes les heures. Notez que généralement logrotate est configuré pour être exécuté par cron quotidiennement (ou par logrotate.timer lorsqu'on utilise systemd(1)). Vous devrez modifier cette configuration et exécuter logrotate toutes les heures pour pouvoir réellement faire tourner les journaux toutes les heures.
daily
Les fichiers journaux sont tournés tous les jours.
weekly [jour_de_la_semaine]
Les fichiers journaux sont tournés une fois par jour_de_la_semaine, ou si la date a avancé d'au moins 7 jours depuis la dernière rotation (en ignorant l'heure exacte). L'interprétation de jour_de_la_semaine est la suivante : 0 signifie dimanche, 1 signifie lundi, ..., 6 signifie samedi ; la valeur spéciale 7 signifie tous les 7 jours, indépendamment du jour de la semaine. La valeur par défaut est 0 si l'argument jour_de_la_semaine est omis.
monthly
Les fichiers journaux sont tournés la première fois que logrotate est exécuté dans un mois (ce qui se produit normalement le premier jour du mois).
yearly
Les fichiers journaux sont tournés si l'année en cours n'est pas la même que lors de la dernière rotation.
size taille
Les fichiers journaux ne sont tournés que s'ils dépassent taille octets. Si taille est suivi de k, la taille est supposée en kilo-octets. Si M est utilisé, la taille est en méga-octets, et si G est utilisé, la taille est en giga-octets. Ainsi, size 100, size 100k, size 100M et size 100G sont tous valides. Cette option est mutuellement exclusive avec les options d'intervalle de temps, et elle fait tourner les fichiers journaux sans tenir compte de la dernière rotation, si elle est spécifiée après les critères de temps (la dernière option spécifiée a la priorité).

Sélection de fichiers

missingok
Si le fichier journal est manquant, passer au suivant sans émettre de message d'erreur. Voir aussi nomissingok.
nomissingok
Si un fichier journal n'existe pas, émettre une erreur. C'est le comportement par défaut.
ignoreduplicates
Ignorer toute correspondance ultérieure d'un fichier journal.
ifempty
Faire tourner le fichier journal même s'il est vide, ignorant ainsi l'option notifempty (ifempty est le comportement par défaut).
notifempty
Ne pas faire tourner le journal s'il est vide (cela remplace l'option ifempty).
minage nombre
Ne pas faire tourner les journaux qui ont moins de <nombre> jours.
maxage nombre
Supprimer les journaux tournés plus anciens que <nombre> jours. L'âge n'est vérifié que si le fichier journal doit être tourné. rotate -1 n'empêche pas la suppression. Les fichiers sont envoyés par courrier à l'adresse configurée si maillast et mail sont configurés.
minsize taille
Les fichiers journaux sont tournés lorsqu'ils dépassent taille octets, mais pas avant l'intervalle de temps supplémentaire spécifié (daily, weekly, monthly, ou yearly). L'option size associée est similaire sauf qu'elle est mutuellement exclusive avec les options d'intervalle de temps, et qu'elle fait tourner les fichiers journaux sans tenir compte de la dernière rotation, si elle est spécifiée après les critères de temps (la dernière option spécifiée a la priorité). Lorsque minsize est utilisé, la taille et l'horodatage d'un fichier journal sont pris en compte.
maxsize taille
Les fichiers journaux sont tournés lorsqu'ils dépassent taille octets, même avant l'intervalle de temps supplémentaire spécifié (daily, weekly, monthly, ou yearly). L'option size associée est similaire sauf qu'elle est mutuellement exclusive avec les options d'intervalle de temps, et qu'elle fait tourner les fichiers journaux sans tenir compte de la dernière rotation, si elle est spécifiée après les critères de temps (la dernière option spécifiée a la priorité). Lorsque maxsize est utilisé, la taille et l'horodatage d'un fichier journal sont pris en compte.
tabooext [+] liste
La liste actuelle des extensions interdites est modifiée (voir la directive include pour des informations sur les extensions interdites). Si un + précède la liste des extensions, la liste actuelle des extensions interdites est augmentée, sinon elle est remplacée. Au démarrage, la liste des extensions interdites est ,v, .bak, .cfsaved, .disabled, .dpkg-bak, .dpkg-del, .dpkg-dist, .dpkg-new, .dpkg-old, .dpkg-tmp, .new, .old, .orig, .rhn-cfg-tmp-*, .rpmnew, .rpmorig, .rpmsave, .swp, .ucf-dist, .ucf-new, .ucf-old, ~
taboopat [+] liste
La liste actuelle des motifs globaux interdits est modifiée (voir la directive include pour des informations sur les extensions et motifs interdits). Si un + précède la liste des motifs, la liste actuelle des motifs interdits est augmentée, sinon elle est remplacée. Au démarrage, la liste des motifs interdits est vide.

Fichiers et Dossiers

create mode propriétaire groupe, create propriétaire groupe
Immédiatement après la rotation (avant l'exécution du script postrotate), le fichier journal est créé (avec le même nom que le fichier journal qui vient d'être tourné). mode spécifie le mode du fichier journal en octal (identique à chmod(2)), propriétaire spécifie l'utilisateur qui possédera le fichier journal, et groupe spécifie le groupe auquel le fichier journal appartiendra (voir la section UTILISATEUR ET GROUPE pour plus de détails). N'importe lequel des attributs du fichier journal peut être omis, dans ce cas, les attributs pour le nouveau fichier utiliseront les mêmes valeurs que le fichier journal d'origine pour les attributs omis. Cette option peut être désactivée en utilisant l'option nocreate.
nocreate
Les nouveaux fichiers journaux ne sont pas créés (cela remplace l'option create).
createolddir mode [propriétaire [groupe]], createolddir [propriétaire [groupe]]
Si le répertoire spécifié par la directive olddir n'existe pas, il est créé. mode spécifie le mode du répertoire olddir en octal (identique à chmod(2)), propriétaire spécifie l'utilisateur qui possédera le répertoire olddir, et groupe spécifie le groupe auquel le répertoire olddir appartiendra (voir la section UTILISATEUR ET GROUPE pour plus de détails). Si mode n'est pas spécifié, 0755 est supposé. Cette option peut être désactivée en utilisant l'option nocreateolddir.
nocreateolddir
Le répertoire olddir n'est pas créé par logrotate lorsqu'il n'existe pas.
copy
Faites une copie du fichier journal, mais ne modifiez pas l'original du tout. Cette option peut être utilisée, par exemple, pour faire un instantané du fichier journal actuel, ou lorsque d'autres utilitaires doivent tronquer ou analyser le fichier. Lorsque cette option est utilisée, l'option create n'aura aucun effet, car l'ancien fichier journal reste en place. L'option copy permet de stocker les fichiers journaux tournés sur des périphériques différents en utilisant la directive olddir.
nocopy
Ne pas copier le fichier journal d'origine et le laisser en place. (cela remplace l'option copy).
copytruncate
Tronquez le fichier journal d'origine à zéro taille en place après la création
ing a copie, au lieu de déplacer l'ancien fichier journal et de créer éventuellement un nouveau. Il peut être utilisé lorsqu'un programme ne peut pas être invité à fermer son fichier journal et peut donc continuer à écrire (ajouter) dans l'ancien fichier journal indéfiniment. Notez qu'il existe une très courte tranche de temps entre la copie du fichier et son troncage, de sorte que certaines données de journalisation pourraient être perdues. Lorsque cette option est utilisée, l'option create n'aura aucun effet, car l'ancien fichier journal reste en place. L'option copytruncate permet de stocker les fichiers journaux rotatifs sur différents périphériques à l'aide de la directive olddir. L'option copytruncate implique norenamecopy.
nocopytruncate
Ne pas tronquer le fichier journal d'origine sur place après avoir créé une copie (cela remplace l'option copytruncate).
renamecopy
Le fichier journal est renommé en un nom de fichier temporaire dans le même répertoire en lui ajoutant l'extension « .tmp ». Après cela, le script postrotate est exécuté et le fichier journal est copié du nom de fichier temporaire au nom de fichier final. À la fin, le nom de fichier temporaire est supprimé. L'option renamecopy permet de stocker les fichiers journaux rotatifs sur différents périphériques à l'aide de la directive olddir. L'option renamecopy implique nocopytruncate.
norenamecopy
Ne pas renommer et copier le fichier journal d'origine (cela remplace l'option renamecopy).
shred
Supprime les fichiers journaux en utilisant shred -u au lieu d'unlink(). Cela devrait garantir que les journaux ne soient pas lisibles après leur suppression programmée ; ceci est désactivé par défaut. Voir aussi noshred.
noshred
Ne pas utiliser shred lors de la suppression des anciens fichiers journaux. Voir aussi shred.
shredcycles compte
Demande à GNU shred(1) de réécrire les fichiers journaux compte fois avant de les supprimer. Sans cette option, la valeur par défaut de shred sera utilisée.
allowhardlink
Fait pivoter les fichiers avec plusieurs liens physiques ; ceci est désactivé par défaut. Le fichier cible peut être vidé, par exemple avec shred ou copytruncate. À utiliser avec prudence, surtout lorsque les fichiers journaux sont rotatifs en tant que root.
noallowhardlink
Ne pas faire pivoter les fichiers avec plusieurs liens physiques. Voir aussi allowhardlink.

Compression

compress
Les anciennes versions des fichiers journaux sont compressées avec gzip(1) par défaut. Voir aussi nocompress.
nocompress
Les anciennes versions des fichiers journaux ne sont pas compressées. Voir aussi compress.
compresscmd
Spécifie quelle commande utiliser pour compresser les fichiers journaux. La valeur par défaut est gzip(1). Voir aussi compress.
uncompresscmd
Spécifie quelle commande utiliser pour décompresser les fichiers journaux. La valeur par défaut est gunzip(1).
compressext
Spécifie quelle extension utiliser pour les fichiers journaux compressés, si la compression est activée. La valeur par défaut suit celle de la commande de compression configurée.
compressoptions
Des options de ligne de commande peuvent être passées au programme de compression, s'il y en a un en cours d'utilisation. La valeur par défaut, pour gzip(1), est « -6 » (privilégiant une forte compression au détriment de la vitesse). Si vous utilisez une commande de compression différente, vous devrez peut-être modifier compressoptions pour qu'elle corresponde.
delaycompress
Reporter la compression du fichier journal précédent au cycle de rotation suivant. Cela n'a d'effet que lorsqu'il est utilisé en combinaison avec compress. Il peut être utilisé lorsqu'un programme ne peut pas être invité à fermer son fichier journal et peut donc continuer à écrire dans l'ancien fichier journal pendant un certain temps.
nodelaycompress
Ne pas reporter la compression du fichier journal précédent au cycle de rotation suivant (cela remplace l'option delaycompress).

Noms de fichiers

extension ext
Les fichiers journaux avec l'extension ext peuvent la conserver après la rotation. Si la compression est utilisée, l'extension de compression (normalement .gz) apparaît après ext. Par exemple, si vous avez un fichier journal nommé mylog.foo et que vous souhaitez le faire pivoter en mylog.1.foo.gz au lieu de mylog.foo.1.gz.
addextension ext
Les fichiers journaux reçoivent l'extension finale ext après rotation. Si le fichier d'origine se termine déjà par ext, l'extension n'est pas dupliquée, mais simplement déplacée à la fin, c'est-à-dire que filename et filenameext seront tous deux rotatifs en filename.1ext. Si la compression est utilisée, l'extension de compression (normalement .gz) apparaît après ext.
start compte
C'est le nombre à utiliser comme base pour la rotation. Par exemple, si vous spécifiez 0, les journaux seront créés avec une extension .0 lorsqu'ils seront rotatifs à partir des fichiers journaux d'origine. Si vous spécifiez 9, les fichiers journaux seront créés avec un .9, en sautant 0-8. Les fichiers seront toujours rotatifs le nombre de fois spécifié avec la directive rotate.
dateext
Archive les anciennes versions des fichiers journaux en ajoutant une extension de date comme YYYYMMDD au lieu d'ajouter simplement un nombre. L'extension peut être configurée en utilisant les options dateformat et dateyesterday.
nodateext
Ne pas archiver les anciennes versions des fichiers journaux avec une extension de date (cela remplace l'option dateext).
dateformat chaîne_format
Spécifiez l'extension pour dateext en utilisant une notation similaire à la fonction strftime(3). Seuls les spécificateurs %Y %m %d %H %M %S %V %s et %z sont autorisés. La valeur par défaut est -%Y%m%d sauf pour les rotations horaires, qui utilisent -%Y%m%d%H comme valeur par défaut. Notez que le caractère séparant le nom du journal de l'extension fait partie de la chaîne de format de date. L'horloge système doit être réglée après le 9 septembre 2001 pour que %s fonctionne correctement. Notez que les horodatages générés par ce format doivent être triables lexicalement (c'est-à-dire d'abord l'année, puis le mois, puis le jour. Par exemple, 2001/12/01 est correct, mais 01/12/2001 ne l'est pas, car 01/11/2002 serait trié plus bas alors qu'il est plus tard). En effet, lors de l'utilisation de l'option rotate, logrotate trie tous les noms de fichiers rotatifs pour déterminer quels fichiers journaux sont plus anciens et doivent être supprimés.
dateyesterday
Utiliser la date d'hier au lieu de la date d'aujourd'hui pour créer l'extension dateext, de sorte que le fichier journal rotatif ait une date dans son nom qui soit la même que les horodatages qu'il contient.
datehourago
Utiliser l'heure d'il y a une heure au lieu de la date actuelle pour créer l'extension dateext, de sorte que le fichier journal rotatif ait une heure dans son nom qui soit la même que les horodatages qu'il contient. Utile avec la rotation hourly.

Courrier

mail adresse
Lorsqu'un journal est rotatif et supprimé, il est envoyé par courrier à adresse. Si aucun courrier ne doit être généré pour un journal particulier, la directive nomail peut être utilisée.
nomail
Ne pas envoyer par courrier les anciens fichiers journaux à une adresse.
mailfirst
Lors de l'utilisation de la commande mail, envoyer le fichier juste-rotatif, au lieu du fichier sur le point d'expirer.
maillast
Lors de l'utilisation de la commande mail, envoyer le fichier sur le point d'expirer, au lieu du fichier juste-rotatif (c'est la valeur par défaut).

Fichiers de configuration supplémentaires

include fichier_ou_répertoire
Lit le fichier donné en argument comme s'il était inclus en ligne à l'endroit où la directive include apparaît. Si un répertoire est donné, la plupart des fichiers de ce répertoire sont lus par ordre alphabétique avant que le traitement du fichier incluant ne continue. Les seuls fichiers qui sont ignorés sont les fichiers qui ne sont pas des fichiers réguliers (tels que les répertoires et les tubes nommés) et les fichiers dont les noms se terminent par l'une des extensions ou des motifs interdits, tels que spécifiés par les directives tabooext ou taboopat, respectivement. Le chemin donné peut commencer par ~/ pour le rendre relatif au répertoire personnel de l'utilisateur exécutant. Pour des raisons de sécurité, les fichiers de configuration ne doivent pas être inscriptibles par le groupe ni inscriptibles par tous.

Scripts

sharedscripts
Normalement, les scripts prerotate et postrotate sont exécutés pour chaque journal qui est rotatif et le chemin absolu vers le fichier journal est passé comme premier argument au script. Cela signifie qu'un seul script peut être exécuté plusieurs fois pour des entrées de fichiers journaux qui correspondent à plusieurs fichiers (comme dans l'exemple /var/log/news/*). Si sharedscripts est spécifié, les scripts ne sont exécutés qu'une seule fois, quel que soit le nombre de journaux correspondant au motif générique,

SHAREDSCRIPTS

Run prerotate, postrotate, preremove, and first/lastaction scripts only once for each group of logs matching a pattern, instead of for each log file. This is the default behaviour. The whole pattern is passed to them. However, if none of the logs in the pattern require rotating, the scripts will not be run at all. If the scripts exit with error (or any log fails to rotate), the remaining actions will not be executed for any logs. This option overrides the nosharedscripts option.

NOSHAREDSCRIPTS

Run prerotate and postrotate scripts for every log file which is rotated (this is the default, and overrides the sharedscripts option). The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for the affected log only.

FIRSTACTION

    script

ENDSCRIPT

The script is executed once before all log files that match the wildcarded pattern are rotated, before the prerotate script is run and only if at least one log will actually be rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, no further processing is done. See also lastaction and the SCRIPTS section.

LASTACTION

    script

ENDSCRIPT

The script is executed once after all log files that match the wildcarded pattern are rotated, after the postrotate script is run and only if at least one log is rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, just an error message is shown (as this is the last action). See also firstaction and the SCRIPTS section.

PREROTATE

    script

ENDSCRIPT

The script is executed before the log file and its old logs are rotated and only if the log will actually be rotated. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script. If sharedscripts is specified, the whole pattern is passed to the script. See also postrotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.

POSTROTATE

    script

ENDSCRIPT

The script is executed after the log file is rotated and before the log file is being compressed. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script and the absolute path to the final rotated log file is passed as the second argument to the script. If sharedscripts is specified, the whole pattern is passed as the first argument to the script, and the second argument is omitted. See also prerotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.

PREREMOVE

    script

ENDSCRIPT

The script is executed once just before removal of a log file. logrotate will pass the name of file which is soon to be removed as the first argument to the script. See also firstaction and the SCRIPTS section.

SCRIPTS

Les lignes situées entre le mot-clé de début (par ex. prerotate) et endscript (tous deux doivent apparaître sur des lignes séparées) sont exécutées (en utilisant /bin/sh). Le script hérite de certains traits du processus logrotate, notamment stderr, stdout, le répertoire courant, l'environnement et l'umask. Les scripts sont exécutés en tant qu'utilisateur et groupe appelant, indépendamment de toute directive su. Si le drapeau --log était spécifié, le descripteur de fichier 3 est le fichier journal. Le répertoire de travail courant n'est pas spécifié.

USER AND GROUP

Les identificateurs d'utilisateur et de groupe sont résolus d'abord en essayant la représentation textuelle et, si cela échoue, ensuite par la valeur numérique.
