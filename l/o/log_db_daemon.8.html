NOM

log_db_daemon - Démon de journalisation de base de données pour Squid

Version 0.5.

SYNOPIS

log_db_daemon DSN [options]

DESCRIPTION

Ce programme écrit les entrées du fichier access.log de Squid dans une base de données. Actuellement, seul le format de journal natif squid est accepté.

Le script a été développé et testé dans l'environnement suivant :

squid-2.7 Squid-3.2
mysql 5.0.26 et 5.1
perl 5.8.8
OpenSUSE 10.2

OPTIONS

DSN
DSN de la base de données codé sous forme de chemin. Ceci est envoyé comme chemin du fichier d'accès `access_log`.

Exemple de configuration :
access_log daemon:/host/database/table/username/password squid

pour laisser un paramètre non spécifié, utilisez une double barre oblique :
access_log daemon://database/table/username/password squid

Par défaut, "DBI:mysql:database=squid"

--debug
Écrit les informations de débogage sur la sortie d'erreur standard.

CONFIGURATION

Configuration de Squid

Directive `access_log`

Le chemin du fichier journal d'accès est utilisé pour fournir les paramètres de connexion à la base de données.

access_log daemon:/mysql_host:port/database/table/username/password squid

Le préfixe 'daemon' est obligatoire et indique à squid que le programme auxiliaire logfile_daemon doit être utilisé à la place de la journalisation normale par fichier.

Le dernier paramètre indique à squid quel format de journal utiliser lors de l'écriture des lignes dans le démon de journalisation. Actuellement, le format squid est pris en charge.

mysql_host:port
Hôte sur lequel le serveur mysql est en cours d'exécution. S'il est laissé vide, 'localhost' est supposé.
database
Nom de la base de données à laquelle se connecter. S'il est laissé vide, 'squid_log' est supposé.
table
Nom de la table de base de données où les lignes de journal sont stockées. S'il est laissé vide, 'access_log' est supposé.
username
Nom d'utilisateur à utiliser lors de la connexion à la base de données. S'il est laissé vide, 'squid' est supposé.
password
Mot de passe à utiliser lors de la connexion à la base de données. S'il est laissé vide, aucun mot de passe n'est utilisé.

Pour laisser tous les champs à leurs valeurs par défaut, vous pouvez utiliser une seule barre oblique :

access_log daemon:/ squid

Pour spécifier uniquement le mot de passe de la base de données, qui est vide par défaut, vous devez laisser tous les autres paramètres non spécifiés en utilisant des chaînes nulles :

access_log daemon://///password squid

Directive `logfile_daemon`

C'est la manière actuelle d'indiquer à squid où se trouve le démon de journalisation.

logfile_daemon /path/to/squid/libexec/logfile-daemon_mysql.pl

Le script doit être copié à l'emplacement spécifié dans la directive.

Configuration de la base de données

Appelons la base de données 'squid_log' et la table de journal 'access_log'. Les nom d'utilisateur et mot de passe pour la connexion à la base de données seront tous deux 'squid'.

Base de données

Créez la base de données :

CREATE DATABASE squid_log;

Utilisateur

Créez l'utilisateur :

GRANT INSERT,SELECT,CREATE ON squid_log.* TO 'squid'@'localhost' IDENTIFIED BY 'squid';
FLUSH PRIVILEGES;

Notez que seuls les privilèges CREATE, INSERT et SELECT sont accordés à l'utilisateur 'squid'. Cela garantit que le script du démon de journalisation ne peut pas modifier ou altérer les entrées du journal.

Table

Le Démon tentera d'initialiser cette table si aucune n'existe à son démarrage.

La table créée devrait ressembler à ceci :

CREATE TABLE access_log (
  id                   INTEGER NOT NULL AUTO_INCREMENT PRIMARY KEY,
  time_since_epoch     DECIMAL(15,3),
  time_response        INTEGER,
  ip_client            CHAR(15),
  ip_server            CHAR(15),
  http_status_code     VARCHAR(10),
  http_reply_size      INTEGER,
  http_method          VARCHAR(20),
  http_url             TEXT,
  http_username        VARCHAR(20),
  http_mime_type       VARCHAR(50),
  squid_hier_status    VARCHAR(20),
  squid_request_status VARCHAR(20)
);

EXTRACTION DES DONNÉES

Requêtes d'exemple.

Clients accédant au cache
SELECT DISTINCT ip_client FROM access_log;
Nombre de requêtes par jour
SELECT
  DATE(FROM_UNIXTIME(time_since_epoch)) AS date_day,
  COUNT(*) AS num_of_requests
FROM access_log
GROUP BY 1
ORDER BY 1;
Nombre du statut de requête
Pour obtenir le nombre brut de chaque statut de requête : 
SELECT squid_request_status, COUNT(*) AS n
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

Pour calculer le pourcentage de chaque statut de requête :

SELECT
  squid_request_status,
  (COUNT(*)/(SELECT COUNT(*) FROM access_log)*100) AS percentage
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

Pour distinguer uniquement entre HIT et MISS :

SELECT
  'hits',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%HIT%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage
UNION
SELECT
  'misses',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%MISS%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage;
Plages de temps de réponse
SELECT
  '0..500',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 0 AND time_response < 500
UNION
SELECT
  '500..1000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 500 AND time_response < 1000
UNION
SELECT
  '1000..2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 1000 AND time_response < 2000
UNION
SELECT
  '>= 2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 2000;
Trafic par type mime
SELECT
  http_mime_type,
  SUM(http_reply_size) as total_bytes
FROM access_log
GROUP BY http_mime_type
ORDER BY 2 DESC;
Trafic par client
SELECT
  ip_client,
  SUM(http_reply_size) AS total_bytes
FROM access_log
GROUP BY 1
ORDER BY 2 DESC;

PROBLÈMES CONNUS

Problèmes de vitesse

Le moteur de stockage MyISAM est connu pour être plus rapide que InnoDB, donc même s'il ne prend pas en charge les transactions et l'intégrité référentielle, il pourrait être plus approprié dans ce scénario. Vous pourriez vouloir ajouter "ENGINE=MYISAM" à la fin du code de création de table dans le script SQL ci-dessus.

Les index devraient être créés en fonction des requêtes les plus fréquemment exécutées. Le script DDL ne crée qu'un index implicite pour la colonne de clé primaire.

log_db_daemon(8) — Arch Linux

NOM

log_db_daemon - Gestionnaire de base de données pour les logs de Squid.

SYNOPIS

log_db_daemon [-d] [-f configfile] [-i ident] [-l logfile] [-t tmpdir]

DESCRIPTION

Le programme log_db_daemon est un démon qui gère une base de données d'enregistrements de logs de Squid. Il peut être utilisé pour stocker et interroger des informations de logs sur une longue période, ce qui n'est généralement pas possible avec les fichiers de log bruts de Squid.

Le démon lit les fichiers de log de Squid (généralement via des pipes nommés ou en surveillant les fichiers de log), extrait les informations pertinentes, les agrège et les stocke dans une base de données (par exemple, MySQL, PostgreSQL, SQLite).

Il peut également exposer une interface pour interroger la base de données, permettant aux utilisateurs d'obtenir des statistiques et des informations sur le trafic Web.

OPTIONS

-d
Active le mode de débogage. Le démon restera au premier plan et affichera des messages de débogage détaillés sur la sortie standard.
-f configfile
Spécifie le fichier de configuration à utiliser. Si cette option n'est pas fournie, le démon recherchera un fichier de configuration par défaut (par exemple, /etc/log_db_daemon.conf).
-i ident
Spécifie un identifiant unique pour cette instance du démon. Ceci est utile si vous exécutez plusieurs instances de log_db_daemon sur le même système.
-l logfile
Spécifie le fichier journal dans lequel le démon doit écrire ses messages. Par défaut, les messages sont envoyés à syslog.
-t tmpdir
Spécifie le répertoire temporaire à utiliser pour les opérations de la base de données. Ceci est utile si le répertoire temporaire par défaut n'a pas assez d'espace ou d'autorisations.

CONFIGURATION

Le fichier de configuration (spécifié avec l'option -f) contient des directives pour configurer le comportement de log_db_daemon. Les directives courantes incluent:

LogFile
Spécifie le chemin d'accès au fichier de log de Squid à analyser.
Database
Définit les paramètres de connexion à la base de données (type, hôte, nom d'utilisateur, mot de passe, nom de la base de données).
Storage
Configure la manière dont les données sont stockées dans la base de données (par exemple, taille des partitions, règles de rétention).
Listen
Définit l'adresse IP et le port sur lesquels le démon écoutera les requêtes d'interrogation.
Debug
Active ou désactive le mode de débogage.

Voir la documentation de log_db_daemon pour la liste complète des directives de configuration et leur syntaxe.

EXTRACTION DES DONNÉES

Le démon analyse les fichiers de log de Squid et extrait des informations telles que l'adresse IP source, l'URL demandée, la méthode HTTP, le code de statut, la taille de la réponse, le temps de réponse, etc.

Il peut agréger ces données pour générer des statistiques sur des périodes données (par jour, semaine, mois). Par exemple, il peut calculer le nombre de requêtes par adresse IP, les URL les plus demandées, les codes de statut les plus fréquents, etc.

Une approche courante consiste à utiliser des scripts externes pour traiter les fichiers de log de Squid et à injecter les données traitées dans la base de données gérée par log_db_daemon. Une autre approche consiste à utiliser les fonctionnalités de rotation des logs de Squid pour extraire les données calculées, puis à les stocker dans une "table de résumé", supprimant ensuite les lignes utilisées pour le calcul.

Du code de nettoyage similaire pourrait être implémenté dans un script externe et exécuté périodiquement indépendamment des commandes de logs de Squid.

PROBLÈMES CONNUS

Ce script n'a été testé que dans des scénarios à faible volume (client unique, moins de 10 requêtes/s). Des tests dans des environnements à haut volume pourraient révéler des goulots d'étranglement de performance et des bugs.
