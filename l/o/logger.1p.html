LOGGER(1P) Manuel du programmeur POSIX LOGGER(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

logger — enregistrer des messages

SYNTAXE

logger chaîne...

DESCRIPTION

L'utilitaire logger sauvegarde un message, d'une manière et d'un format non spécifiés, contenant les opérandes chaîne fournis par l'utilisateur. Les messages sont destinés à être évalués ultérieurement par du personnel effectuant des tâches d'administration système.

Il est défini par l'implémentation de savoir si les messages écrits dans des locales autres que la locale POSIX sont efficaces.

OPTIONS

Aucune.

OPÉRANDES

Le opérande suivant sera supporté :

chaîne
L'un des arguments de chaîne dont le contenu est concaténé, dans l'ordre spécifié, séparé par des caractères <espace> uniques.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de logger :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume des Définitions de Base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur. (Cela signifie les diagnostics de logger à l'utilisateur ou à l'application, pas les messages de diagnostic que l'utilisateur envoie à l'administrateur système.)
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Non utilisé.

SORTIE STANDARD D'ERREUR

La sortie standard d'erreur ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Non spécifié.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Cet utilitaire permet d'enregistrer des informations pour une utilisation ultérieure par un administrateur système ou un programmeur afin de déterminer pourquoi des utilitaires non interactifs ont échoué. Les emplacements des messages enregistrés, leur format et leur période de conservation ne sont pas spécifiés. Il n'existe aucune méthode permettant à une application conforme de lire les messages, une fois écrits.

EXEMPLES

Une application par lots, exécutée de manière non interactive, essaie de lire un fichier de configuration et échoue ; elle peut tenter d'en informer l'administrateur système avec :

logger monnom: impossible de lire le fichier foo. [horodatage]

JUSTIFICATION

Les développeurs du standard pensaient fermement qu'une méthode d'alerte des administrateurs en cas d'erreurs était nécessaire. L'exemple évident est un utilitaire par lots, exécuté de manière non interactive, qui ne peut pas lire ses fichiers de configuration ou qui ne peut pas créer ou écrire son fichier de résultats. Cependant, les développeurs du standard ne souhaitaient pas définir le format ou les mécanismes de livraison car ils étaient historiquement (et continueront probablement à l'être) très spécifiques au système, et impliquaient des fonctionnalités clairement en dehors du champ d'application de ce volume de POSIX.1‐2017.

Le texte concernant LC_MESSAGES sur les messages de diagnostic signifie les diagnostics de logger à l'utilisateur ou à l'application, pas les messages de diagnostic que l'utilisateur envoie à l'administrateur système.

Plusieurs arguments chaîne sont autorisés, similaires à echo, pour faciliter l'utilisation.

Comme les utilitaires mailx et lp, logger est certes difficile à tester. Cela n'a pas été jugé une justification suffisante pour exclure ces utilitaires de ce volume de POSIX.1‐2017. On peut aussi arguer qu'ils sont, en fait, testables, mais que les tests eux-mêmes ne sont pas portables.

ORIENTATIONS FUTURES

Aucune.
