LOWDOWN(1) Manuel des commandes générales LOWDOWN(1)

NOM

lowdown — traducteur simple de markdown

SYNTAXE

lowdown [options_entrée] [options_sortie] [-Ls] [-M métadonnées] [-m métadonnées] [-o fichier] [-t mode] [-X mot-clé] [fichier]

DESCRIPTION

Traduit depuis lowdown(5) vers divers formats de sortie. Les résultats sont écrits sur la sortie standard.

Les arguments courts sont les suivants :

-L
Liste les clés de métadonnées, une clé par ligne. Le mode -t est ignoré. Les métadonnées sont automatiquement activées. Désactive -X.
-s
Produit un document autonome (par exemple, un document HTML valide incluant le type de document, l'en-tête, etc.) autour du contenu formaté. Voir Documents autonomes pour les détails.
-M métadonnées
Fournit une seule paire clé-valeur de métadonnées. Cela peut être dans la syntaxe normale ou sous forme de paires séparées par un signe égal, selon le caractère (un deux-points ou un signe égal) qui apparaît en premier. Se termine avec une erreur si rien n'est donné. Cela remplace -m et ce qui est analysé à partir du document. Voir Métadonnées.
-m métadonnées
Comme -M, mais remplacé par ce qui est analysé dans le document, puis par -M.
-o fichier
Envoie la sortie au fichier sauf s'il s'agit de “-”, auquel cas on revient au défaut de la sortie standard.
-t mode, -T mode
Le mode de sortie. Il peut s'agir de html pour une sortie HTML5, latex pour LaTeX, gemini pour le format « gemtext » de Gemini, ms pour une sortie roff utilisant le paquet classique (c'est-à-dire sans extension) -ms et nécessitant la prise en charge des tableaux, term pour une sortie terminale compatible ANSI UTF-8, man pour une sortie roff utilisant le paquet classique -man, tree, pour afficher l'arbre d'analyse du document d'entrée, et null pour analyser le document sans aucune rendu. Voir Médias de sortie. La forme -T mode est conservée pour des raisons de compatibilité ascendante.
-X mot-clé
Affiche la valeur de métadonnées du mot-clé ou une chaîne vide si non trouvée. Le mode -t est ignoré. Les métadonnées sont automatiquement activées. Désactive -L.
fichier
Document Markdown en entrée. S'il n'est pas donné ou si fichier est “-”, il est lu depuis l'entrée standard.

Les options suivantes sont des options longues pour l'analyse de l'entrée. Elles affectent l'arbre d'analyse passé à toutes les sorties.

--parse-hilite
Active le support des balises de mise en surbrillance. Celles-ci sont désactivées par défaut car elles peuvent être interprétées erronément comme des titres de section.
--parse-math
Reconnaît les équations mathématiques.
--parse-maxdepth=depth
La profondeur maximale des éléments imbriqués. La valeur par défaut est 128, ce qui est probablement suffisant pour tout document réel. Si la profondeur maximale est atteinte, le système se termine comme si la mémoire était épuisée. Réglez à zéro pour aucune limite.
--parse-no-autolink
N'analyse pas les liens http, https, ftp, mailto, ni les liens relatifs ou fragments de liens.
--parse-no-cmark
N'analyse pas avec les contraintes CommonMark. Cela désactive également l'utilisation de la première valeur de liste ordonnée au lieu de commencer toutes les listes à un.
--parse-no-codeindent
N'analyse pas le contenu indenté comme des blocs de code.
--parse-no-callouts
N'analyse pas les appels (admonitions) GFM/MDN.
--parse-no-deflists
N'analyse pas les listes de définition PHP supplémentaires.
--parse-no-ext-attrs
N'analyse pas les attributs étendus PHP supplémentaires.
--parse-no-fenced
N'analyse pas les blocs de code GFM délimités (spécifiques au langage).
--parse-no-footnotes
N'analyse pas les notes de bas de page MMD.
--parse-no-img-ext
Obsolète. Voir --parse-no-ext-attrs.
--parse-no-intraemph
N'analyse pas l'emphase à l'intérieur des mots et des liens.
--parse-no-mantitle
N'analyse pas le titre, la section, la source et le volume des pages de manuel à partir des métadonnées Pandoc. Les titres de pages de manuel sont indiqués par un titre suivi d'une parenthèse ouverte, d'un chiffre suivi de caractères optionnels, puis d'une parenthèse fermée.
--parse-no-metadata
N'analyse pas les métadonnées. Cela n'affecte pas les métadonnées fournies via -m ou -M.
--parse-no-strike
N'analyse pas les barrés.
--parse-no-super
N'analyse pas du tout les super-scripts ou les sous-scripts.
--parse-no-tables
N'analyse pas les tableaux GFM.
--parse-no-tasklists
N'analyse pas les listes de tâches GFM.
--parse-super-short
Si l'analyse des super-scripts est activée, utilise la syntaxe « courte » traditionnelle non-GFM.

Il existe de nombreuses options de sortie longues. Les suivantes sont partagées par tous les médias de sortie :

--out-standalone
Alias pour -s.
--out-no-smarty
N'utilise pas le filtre de typographie intelligente. Par défaut, certaines séquences de caractères sont traduites en glyphes spécifiques à la sortie.
--template template
Lors de la production d'une sortie autonome -s, utilise un fichier template. Voir Templates. Actuellement uniquement pour -tgemini, -thtml, -tlatex, -tman, -tms, et -ttree.

Ce qui suit concerne les options longues par sortie. Pour HTML avec -thtml, elles sont les suivantes :

--html-callout-mdn, --html-callout-gfm
Produit soit la syntaxe d'appel MDN, soit GFM, soit les deux.
--html-hardwrap
Forcer le retour à la ligne du contenu des paragraphes en produisant des sauts de ligne là où c'est applicable.
--html-no-escapehtml
Si --html-no-skiphtml a été spécifié, cela permet au HTML intégré de ne pas être échappé, et d'être plutôt affiché tel quel. Ceci n'a aucun effet si --html-no-skiphtml n'a pas été spécifié.
--html-no-head-ids
Ne pas produire d'attributs id pour les en-têtes.
--html-no-num-ent
Ne pas normaliser les entités HTML (quand c'est possible) en entités numériques, et utiliser plutôt les entités telles qu'elles sont fournies en entrée.
--html-no-owasp
Ne pas suivre les recommandations OWASP pour l'échappement de texte, et effectuer seulement l'échappement minimal pour s'assurer que le contenu régulier ne soit pas interprété comme du HTML.
--html-no-skiphtml
Produire le HTML intégré. Par défaut, le HTML intégré n'est pas produit du tout. Voir --html-no-escapehtml.
--html-titleblock
S'il y en a eu, formater les informations de titre (titre, auteur, date) dans un élément d'en-tête apparaissant en premier dans le document.

Pour les deux formats roff -tman et -tms (sauf indication contraire), ce qui suit s'applique :

--roff-code-font=fonts
Remplacer les polices par défaut à largeur fixe par un tuple de variantes normales, gras, italique et gras-italique dans cet ordre. Par exemple, B,B,BI,BI utilise le gras (“B”) au lieu d'une largeur fixe. Ne pas spécifier de police utilisera la valeur par défaut, tout comme spécifier un nom de police de longueur nulle. Les alias none, bold, et code n'utilisent aucune police spéciale, le gras, et la largeur fixe par défaut.
--roff-endnotes
Retarder l'impression des notes de bas de page jusqu'à la fin du document. S'applique uniquement à -tms, car -tman ne prend en charge que les notes de fin.
--roff-no-numbered
Ne pas produire de titres numérotés (.NH NN). S'applique uniquement à -tms.
--roff-no-skiphtml
Produire le HTML intégré. Cela n'a généralement pas de sens car le HTML ne sera pas interprété par le lecteur de sortie. Par défaut, le HTML est omis.
--roff-no-links
Ne pas afficher les URL pour les images et les liens (les liens automatiques sont toujours affichés). (Le contenu des liens est toujours affiché.) Annule --roff-short-links pour les images et les liens. S'applique uniquement lorsque --roff-traditional est spécifié.
--roff-short-links
Raccourcir les URL pour les images, les liens et les liens automatiques pour n'inclure que le nom de domaine et le chemin final. S'applique uniquement lorsque --roff-traditional est spécifié.
--roff-traditional
Ne pas utiliser les macros d'hyperlien (.pdfhref, .UR, .MT), les tables multipages (.TS H, .TH), la syntaxe de séquence Unicode (\[uNNNN]), les macros de bloc d'exemple (.EX), les titres de section modernes (.NH NN, .SH NN, .pdfhref O NN), ou les liens intra-documentaires (.pdfhref L). La sortie est compatible avec le troff(1) traditionnel.

Le préfixe d'argument --nroff, comme dans --nroff-traditional, est déprécié au profit de --roff.

La sortie -tterm a les options suivantes :

--term-all-metadata
Si -s est spécifié, produit toutes les métadonnées au lieu de seulement le titre, l'auteur et la date.
--term-columns=columns
Le nombre de colonnes dans le terminal. Utile lors de l'utilisation en pipe. Par défaut, utilise ce que le terminal rapporte ou 72 si ce n'est pas dans un terminal.
--term-hmargin=margin
Le nombre de caractères de marge gauche. Par défaut, zéro. Peut aussi être auto pour définir la marge gauche à la moitié de la valeur restante de --term-columns après soustraction de --term-width.
--term-hpadding=padding
Le nombre de caractères de remplissage à gauche. Par défaut, quatre. Le remplissage empiète sur --term-width.
--term-no-ansi
Ne pas afficher du tout les styles ANSI. Ceci implique --term-no-colour.
--term-no-colour
Ne pas afficher les couleurs ANSI. Cela décorera toujours le texte avec des soulignements, des gras et des italiques, mais n'émettra aucun code couleur.
--term-no-links
Ne pas afficher les URL pour les images et les liens (les liens automatiques sont toujours affichés). (Le contenu des liens est toujours affiché.) Annule --term-short-links et --term-no-rellinks.
--term-no-rellinks
Ne pas afficher les URL pour les liens relatifs. (Le contenu des liens est toujours affiché.) Annule --term-short-links.
--term-short-links
Raccourcir les URL pour les images, les liens et les liens automatiques pour n'inclure que le nom de domaine et le chemin final.
--term-vmargin=margin
Le nombre de nouvelles lignes de marge supérieure et inférieure. Par défaut, zéro.
--term-width=width
Limite logicielle du nombre de caractères par ligne, incluant (--term-hpadding). Ceci peut être dépassé par du texte littéral. Si zéro ou non défini, utilise par défaut la valeur de --term-columns ou 80 au maximum. Tronque à la valeur de --term-columns.

La sortie -tgemini a plusieurs indicateurs qui contrôlent le placement des liens. Par défaut, les liens (images, liens automatiques et liens) sont mis en file d'attente lorsqu'ils sont spécifiés en ligne, puis émis dans une séquence de blocs après l'élément de bloc le plus proche.

--gemini-link-end
Émettre la file d'attente des liens à la fin du document au lieu de les placer après l'élément de bloc le plus proche.
--gemini-link-inline
Rendre tous les liens dans le flux de texte. Cela causera des problèmes lors de liens imbriqués, tels que des images dans des liens, des liens dans des blocs de citation, etc. Il ne doit pas être utilisé sauf dans des documents soigneusement conçus.
--gemini-link-noref
Ne pas formater les étiquettes de liens. Prend la priorité sur --gemini-link-roman.
--gemini-link-roman
Lors du formatage des étiquettes de liens, utiliser des chiffres romains minuscules au lieu de l'hexavigésimal minuscule par défaut (c'est-à-dire, “a”, “b”, ..., “aa”, “ab”, ...).
--gemini-metadata
Imprimer les métadonnées comme clé canonisée suivie d'un deux-points puis de la valeur, chacune sur une ligne (les sauts de ligne sont remplacés par des espaces). Le bloc de métadonnées est terminé par un double saut de ligne. S'il n'y a pas de métadonnées, cela ne fait rien.

La sortie -tlatex a les options suivantes :

--latex-no-numbered
Ne pas numéroter les sections (et sous-sections, etc.).
--latex-no-skiphtml
Produire le HTML intégré. Cela n'a généralement pas de sens car le HTML ne sera pas interprété par le lecteur de sortie. Par défaut, le HTML est omis.

La sortie -tfodt a les options suivantes :

--odt-no-skiphtml
Produire le HTML intégré. Cela n'a généralement pas de sens car le HTML ne sera pas interprété par le lecteur de sortie. Par défaut, le HTML est omis.
phtml
Affiche le HTML incorporé. Cela n'a généralement pas de sens car le HTML ne sera pas interprété par le lecteur de sortie. Par défaut, le HTML est omis.
--odt-style=fichier
Spécifie un fichier de style OpenDocument, qui doit contenir au moins les éléments XML <office:font-face-decls>, <office:scripts> et <office:styles> à la racine du document. Ceci n'est vérifié syntaxiquement d'aucune manière.

Supports de sortie

Le support de sortie est spécifié par -t, qui par défaut est -thtml.

-tfodt
Sortie OpenDocument « plate » (Flat). Les styles automatiques (ceux qui dépendent de l'état du document) sont générés avec la sortie. Les classes spécifiées par des attributs étendus PHP ne sont pas vérifiées quant à leur existence.
-tgemini
Format « gemtext » de Gemini.
-thtml
Sortie HTML5 avec encodage UTF-8.
-tlatex
Sortie LaTeX simple. Les paquets suivants sont requis : amsmath et amssymb pour les mathématiques, graphicx pour les images, inputenc (utf8) pour l'entrée UTF-8, frontend (T1) et textcomp pour les glyphes de sortie, lmodern pour la police Latin Modern, xcolor pour la sortie du moteur de différence, et hyperref pour les liens.
-tman
Le paquet de macros man adapté à la lecture par groff(1), mandoc(1), Heirloom troff, ou traditionnel troff(1). Ne supporte pas les équations et les images. Le support des tableaux est fourni par tbl(1). Comme UTF-8 peut être passé en tant que valeurs d'entrée, preconv(1) peut être nécessaire.
-tms
Le paquet de macros ms adapté à la lecture par groff(1) ou traditionnel troff(1). Ne supporte pas les équations et support limité pour les images PostScript encapsulées (suffixes PS et EPS). Les images sont toujours formatées en bloc. Les dimensions des images et les attributs étendus sont ignorés, bien que les images soient réduites si elles sont plus grandes que la largeur de texte actuelle. Le support des tableaux est fourni par tbl(1). Comme UTF-8 peut être passé en tant que valeurs d'entrée, preconv(1) peut être nécessaire.
-tterm
Sortie UTF-8 échappée ANSI adaptée à la lecture sur le terminal. Images et équations non supportées.
-ttree
Sortie de débogage. Pas pour une utilisation programmatique, car le format peut changer entre les versions.

Documents autonomes

Lorsque -s est spécifié, le contenu formaté est sérialisé dans un modèle de document autonome tel que défini par le type de sortie.

Si non explicitement défini avec --template, un modèle par défaut est produit comme suit :

-tfodt
Enveloppe <office:document> et prologue <office:automatic-styles>, <office:master-styles>, et <office:body>.
-thtml
Déclaration doctype HTML5 suivie de l'enveloppe <html> avec langue optionnelle, puis <head>. Dans l'ordre, le <head> se compose des éléments <meta> de jeu de caractères et de viewport ; éléments <meta> optionnels d'affiliation des métadonnées (créateur), auteur, copyright et date ; sources CSS optionnelles à partir des métadonnées ; sources JavaScript optionnelles à partir des métadonnées ; le <title> éventuellement vide ; puis contenu arbitraire optionnel provenant de l'en-tête HTML des métadonnées.
-tlatex
Déclarations documentclass et usepackage de prologue, contenu arbitraire optionnel de l'en-tête LaTeX des métadonnées, puis instructions begin{document} environnantes.
-tman, -tms
Macros de prologue.
-tterm
Lignes de prologue.
-ttree
Métadonnées et modèle analysé.

Voir Métadonnées pour les valeurs de métadonnées utilisées par le modèle par défaut.

Métadonnées

Les clés de métadonnées sont canonicalisées et désambiguïsées dans l'ordre suivant : -m (remplacé par le contenu du document et -M), le prologue du document lui-même, puis -M (remplaçant le contenu du document et -m).

Après désambiguïsation, les métadonnées sont soit accessibles directement en utilisant -X ou -L, soit sérialisées dans des variables de document et/ou une sortie autonome -s.

Lorsque --template n'est pas utilisé, les clés de métadonnées suivantes sont utilisées dans le modèle par défaut -s :

affiliation
Affiliation de l'auteur (organisation ou institution). Plusieurs affiliations peuvent être séparées par deux espaces ou plus (y compris des sauts de ligne). Utilisé dans -thtml, -tlatex, et -tms.
author
Auteur du document. Plusieurs auteurs peuvent être séparés par deux espaces ou plus (y compris des sauts de ligne). Remplacé par rcsauthor. Utilisé dans -tfodt, -thtml, -tlatex, -tms, et -tterm.
baseheaderlevel
Ajouté à chaque niveau d'en-tête. Obsolète au profit de shiftheadinglevelby.
copyright
Un copyright de document (sans le mot « Copyright »), par exemple, « 2017, Kristaps Dzonsons ». Utilisé dans -tms et -thtml.
css
Un fichier CSS affiché dans l'en-tête du document HTML comme une instruction <link rel="stylesheet" href="..." />. Plusieurs fichiers CSS (dans l'ordre) peuvent être séparés par deux espaces ou plus (y compris des sauts de ligne) et sont affichés dans l'ordre donné. Uniquement utilisé dans -thtml.
date
Date du document au format ISO-8601 YYYY-MM-DD. Remplacé par rcsdate. Utilisé dans -tfodt, -thtml, -tlatex, -tman, -tms, et -tterm.
htmlheader
Contenu HTML arbitraire affiché dans l'en-tête du document HTML immédiatement avant la fermeture de l'élément head. Uniquement utilisé dans -thtml et avec -s. Ces métadonnées ne sont pas traitées : elles sont insérées inchangées dans la sortie.
javascript
Un fichier JavaScript affiché dans l'en-tête du document HTML comme une instruction <script src="..."></script>. Plusieurs fichiers de script (dans l'ordre) peuvent être séparés par deux espaces ou plus (y compris des sauts de ligne) et sont affichés dans l'ordre donné. Uniquement utilisé dans -thtml.
lang
Langue du document au format RFC 5646. Uniquement utilisé dans -thtml.
latexheader
Contenu LaTeX arbitraire affiché dans le prologue du document immédiatement avant begin{document}. Uniquement utilisé dans -tlatex et avec -s. Ces métadonnées ne sont pas traitées : elles sont insérées inchangées dans la sortie.
manheader
Contenu roff arbitraire affiché immédiatement avant la macro .TH. Uniquement
y utilisé dans -tman et avec -s. Ces métadonnées ne sont pas traitées : elles sont transmises inchangées dans la sortie.
msheader
Contenu roff arbitraire affiché immédiatement avant la macro .TL. Uniquement utilisé dans -tms et avec -s. Ces métadonnées ne sont pas traitées : elles sont transmises inchangées dans la sortie.
rcsauthor
Similaire à author, mais au format auteur RCS. Remplace author.
rcsdate
Similaire à date, mais au format date RCS. Remplace date.
section
Section de la page de manuel, par défaut “7”. Uniquement utilisé dans -tman.
shiftheadinglevelby
Déplace tous les en-têtes du nombre donné. Par exemple, une valeur de 1 fait que les en-têtes initialement au niveau 1 (“<h1>”) deviennent de niveau 2 (“<h2>”), tandis qu'une valeur de -1 déplace le niveau 2 au niveau 1. Les niveaux ne passeront pas en dessous de 1. Prend la priorité sur baseheaderlevel. Si non défini ou pas un nombre valide, par défaut à zéro. Utilisé dans -tfodt, -thtml, -tlatex, -tman, et -tms.
source
Source de la page de manuel (organisation fournissant le manuel). Uniquement utilisé dans -tman.
volume
Volume de la page de manuel (décrit la section de la page de manuel). Uniquement utilisé dans -tman.
title
Titre du document. Utilisé dans -tfodt, -thtml, -tlatex, -tman, -tms, et -tterm.

Les valeurs par défaut, telles que “7” pour la section, ne sont pas définies comme valeurs de métadonnées, et n'apparaîtront pas si la clé de métadonnée est utilisée comme variable.

Templates

Certains médias de sortie acceptent un template (--template) pour personnaliser la sortie autonome (-s). Le contenu d'entrée analysé est rempli dans les templates via des instructions de contrôle qui prennent en charge les conditions, les boucles et les séquences de transformation de variables.

Les instructions de contrôle sont délimitées comme $statement$ ou ${statement}. Des espaces blancs arbitraires peuvent entourer l'instruction insensible à la casse entre les délimiteurs correspondants. Les instructions sans délimiteur de fermeture sont considérées comme du texte opaque.

Les instructions suivantes sont disponibles :

$$, ${}
Affiche un $ littéral. Ceci peut contenir des espaces blancs arbitraires.
$ifdef(expression)$
Instruction conditionnelle. Il ne doit pas y avoir d'espaces blancs entre le ifdef et la parenthèse ouvrante. Commence un bloc qui se termine par un else, endif, ou la fin du fichier. Son contenu est affiché seulement si expression est évaluée à une chaîne non vide.
$else$
Commence un bloc qui se termine par un endif ou la fin du fichier. Son contenu est affiché seulement si la condition d'un ifdef précédent est évaluée à une chaîne vide. Un else sans ifdef précédent n'est pas affiché.
$endif$
Ferme un bloc commencé avec ifdef ou else. S'il n'est pas précédé par l'une de ces instructions, il est silencieusement ignoré.
$for(expression)$
Instruction de boucle. Il ne doit pas y avoir d'espaces blancs entre le for et la parenthèse ouvrante. Commence un bloc qui se termine par un endfor ou la fin du fichier. Le contenu du bloc est affiché de manière répétée pour chaque élément de liste évalué à partir de expression. Le mot-clé anaphorique this peut être utilisé pour accéder à l'expression de boucle actuelle dans le bloc.
$expression$
Remplacé par le résultat de l'évaluation d'une expression de template.

Si une instruction de contrôle se termine par deux tirets consécutifs avant le délimiteur de fermeture, l'entrée est consommée jusqu'au prochain saut de ligne, y compris celui-ci, ou jusqu'à la fin du fichier. Cela permet aux médias de sortie sensibles aux lignes d'utiliser des instructions de contrôle sans lignes blanches superflues.

Les expressions sont composées de

initial[([arg]*)]?[.transform[([arg]*)]?]*
,

ou d'une valeur initiale acceptant des arguments optionnels suivis d'une série optionnelle de transformations acceptant des arguments optionnels. Si une liste d'arguments est vide ou n'est pas fournie, elle est évaluée comme une liste vide.

La valeur initial est l'une des suivantes :

and(expression[,expression]*)
Une liste non vide contenant la valeur true si toutes les expressions sont évaluées comme des listes non vides, sinon une liste vide. Une expression vide est évaluée comme une liste vide.
"literal string"
Est évalué comme une liste singleton contenant la chaîne. Une chaîne vide est évaluée comme une liste vide. Le caractère guillemet double peut être échappé, comme dans "foo\"bar".
body
Le corps du document d'entrée analysé.
clé de métadonnée canonique
La valeur pour la clé de métadonnée donnée, si trouvée, sinon une liste vide.
body
Le corps du document d'entrée analysé.
meta(key)
Produit la valeur de métadonnée pour la métadonnée canonique key. Permet des clés qui sont aussi des mots-clés comme body ou endif.
not(expression)
Une liste non vide contenant la valeur true si l'expression est évaluée comme une liste vide, sinon une liste vide.
or(expression[,expression]*)
Une liste non vide contenant la valeur true si une expression est évaluée comme des listes non vides, sinon une liste vide. Une expression vide est évaluée comme une liste vide.
this
La valeur du contexte de boucle actuel ou une liste vide.

Si une clé de métadonnée n'est pas spécifiée dans l'entrée, ou si l'anaphorique this n'a pas été initialisé par un contexte de boucle, la valeur initiale est évaluée comme une liste vide. Sinon, la valeur est une liste singleton.

Si les transformations sont invalides, elles se transformeront en une liste vide.

Les transformations suivantes sont disponibles :

escapegemini, escapegeminiline
Échappe les éléments de liste pour gemini (-tgemini), soit pour plusieurs lignes, soit compressé sur une seule ligne.
escapehtml, escapehtmlattr, escapehtmlurl
Échappe les éléments de liste pour le contenu du corps HTML (-thtml), les attributs, et les attributs d'URL, respectivement.
escapelatex
Échappe les éléments de liste pour le contenu du corps LaTeX (-tlatex).
escaperoff, escaperoffline
Échappe les éléments de liste pour roff (-tms, -tman), soit pour plusieurs lignes, soit compressé sur une seule ligne. escaperoff échappe également les délimiteurs roff initiaux et ceux après les sauts de ligne.
join
Joint une liste en une liste singleton en utilisant deux espaces comme délimiteur de jointure.
lowercase
Met en minuscules tous les éléments de liste.
split
Sépare les éléments de liste sur des séquences de deux espaces blancs ou plus (espace, saut de ligne, tabulation). Ceci est généralement invoqué sur un singleton, mais peut être invoqué de manière répétée sur une liste pré-séparée. Invoque trim avant la première séparation. La liste résultante n'a pas d'éléments qui ne sont que des espaces blancs.
trim
Supprime les espaces blancs du début et de la fin de tous les éléments de liste. Si un élément ne contient aucun caractère non blanc, il est supprimé.

lowdown(1) — page de manuel

NOM

lowdown - une implémentation du format Markdown

SYNTAXE

lowdown [options...] [fichier...]

DESCRIPTION

Le programme lowdown est un processeur de Markdown qui convertit des documents écrits en Markdown en divers formats de sortie. Il est basé sur la spécification CommonMark avec des extensions.

Il peut sortir en plusieurs formats, y compris le texte brut pour le terminal, HTML5, LaTeX, et le format groff ms.

L'objectif principal de lowdown est la rapidité et la fiabilité, tout en offrant une bonne compatibilité avec les spécifications de Markdown.

-tformat
Spécifie le format de sortie. Les formats disponibles sont :
  • commonmark : sortie conforme à la spécification CommonMark.
  • html : sortie HTML5.
  • html5 : sortie HTML5 (identique à html).
  • latex : sortie LaTeX.
  • man : sortie au format nroff man.
  • ms : sortie au format groff ms.
  • term : sortie formatée pour un terminal ANSI.
  • fodt : sortie au format Flat OpenDocument Text.
Le format par défaut est term.
-c
Sortie de texte brut (utilisé principalement pour la sortie term).
-C
Émet du code couleur pour la sortie du terminal.
-e
Échappe les caractères HTML dans la sortie.
-H
Émet la sortie avec un en-tête pour les documents HTML.
-i
Ignore la sortie de métadonnées.
-L
Liste toutes les clés de métadonnées trouvées dans le document.
-o
L'option -ochemin spécifie un fichier de sortie.
-s
Émet un document HTML autonome (incluant le doctype et les balises <html>).
-S
Émet la sortie avec le minimum de balises pour une intégration dans une page HTML existante.
-T
Désactive l'auto-complétion des balises HTML (utile pour certains types d'analyse).
-X
Extrait une valeur de métadonnées spécifique.
-a
Génère des identifiants de liens automatiques (par exemple, pour les en-têtes).
-m
Supprime la sortie des métadonnées.
-r
Convertit les fins de ligne en balises <br> (style GitHub Flavored Markdown).
-u
Convertit toutes les listes en majuscules.

ENVIRONNEMENT

NO_COLOR
Ne pas émettre de couleurs en mode -tterm. Synonyme de NO_COLOUR. Équivalent à --term-nocolour.

FICHIERS

share/html/default.html
Le modèle par défaut utilisé si --template n'est pas fourni à -thtml.
share/latex/default.latex
Le modèle par défaut utilisé si --template n'est pas fourni à -tlatex.
share/man/default.man
Le modèle par défaut utilisé si --template n'est pas fourni à -tman.
share/man/default.ms
Le modèle par défaut utilisé si --template n'est pas fourni à -tms.
share/odt/styles.xml
Styles par défaut utilisés lors de la génération de documents -tfodt autonomes. Modèle pour les styles --odt-style.

ETAT DE SORTIE

L'utilitaire lowdown se termine avec le code 0 en cas de succès, et >0 en cas d'erreur.

Si le drapeau -X est utilisé, lowdown se termine avec une erreur si la clé spécifiée n'est pas trouvée.

EXEMPLES

Pour afficher un fichier Markdown sur un terminal compatible ANSI et UTF-8 :

lowdown -tterm foo.md | less -R

Le terminal peut également être utilisé avec le rendu de groff(1) ou mandoc(1) :

lowdown -stms foo.md | groff -itk -mspdf -Tutf8 | less -R
lowdown -stman foo.md | groff -itk -man -Tutf8 | less -R
lowdown -stman foo.md | mandoc | less

Pour émettre un document HTML5 autonome :

lowdown -s foo.md > foo.html

Pour utiliser groff(1) ou mandoc(1) pour formater en fichier PS :

lowdown -stms foo.md | groff -itk -mspdf > foo.ps
lowdown -stman foo.md | mandoc -Tps > foo.ps

Ou avec LaTeX :

lowdown -stlatex foo.md > foo.latex
pslatex foo.latex

La génération de PDF suit une logique similaire :

lowdown -stms foo.md | pdfroff -itk -mspdf > foo.pdf
lowdown -stman foo.md | mandoc -Tpdf > foo.pdf
lowdown -stlatex foo.md > foo.latex
pdflatex foo.latex

Le support UTF-8 pour la sortie PDF ou PS de groff(1) nécessite les polices appropriées, telles que la police Unicode Times. Celle-ci et d'autres polices Unicode ne sont pas toujours installées par défaut. Elles peuvent être trouvées, pour la sortie PDF, dans le jeu de polices devpdf du répertoire des polices de groff(1) et sont préfixées par ‘U’.

lowdown -stms foo.md | pdfroff -itk -mspdf -FU-T > foo.pdf

Pour lister toutes les clés de métadonnées, puis pour extraire la valeur de métadonnées « title » de foo.md :

lowdown -L foo.md
lowdown -X title foo.md
