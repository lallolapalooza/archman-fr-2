NOM

logrotate ‐ fait tourner, compresse et envoie par e-mail les journaux système

SYNOPIS

logrotate [--force] [--debug] [--state fichier] [--skip-state-lock] [--wait-for-state-lock] [--verbose] [--log fichier] [--mail commande] fichier_de_config [fichier_de_config2 ...]

DESCRIPTION

logrotate est conçu pour faciliter l'administration des systèmes qui génèrent un grand nombre de fichiers journaux. Il permet de faire tourner, compresser, supprimer et envoyer par e-mail automatiquement les fichiers journaux. Chaque fichier journal peut être géré quotidiennement, hebdomadairement, mensuellement, ou lorsqu'il devient trop volumineux.

Normalement, logrotate est exécuté comme une tâche cron quotidienne. Il ne modifiera pas un journal plus d'une fois par jour, sauf si le critère pour ce journal est basé sur la taille du journal et que logrotate est exécuté plus d'une fois par jour, ou si l'option -f ou --force est utilisée.

N'importe quel nombre de fichiers de configuration peut être fourni en ligne de commande. Les fichiers de configuration ultérieurs peuvent remplacer les options données dans les fichiers précédents, de sorte que l'ordre dans lequel les fichiers de configuration de logrotate sont listés est important. Normalement, un seul fichier de configuration qui inclut les autres fichiers de configuration nécessaires devrait être utilisé. Voir ci-dessous pour plus d'informations sur la façon d'utiliser la directive include pour y parvenir. Si un répertoire est donné en ligne de commande, chaque fichier de ce répertoire est utilisé comme fichier de configuration.

Si aucun argument de ligne de commande n'est donné, logrotate affichera des informations sur la version et le copyright, ainsi qu'un résumé d'utilisation. Si des erreurs surviennent lors de la rotation des journaux, logrotate se terminera avec un statut non nul, bien que le fichier d'état soit mis à jour.

OPTIONS

-f, --force
Indique à logrotate de forcer la rotation, même s'il ne pense pas que ce soit nécessaire. Ceci est parfois utile après avoir ajouté de nouvelles entrées à un fichier de configuration de logrotate, ou si d'anciens fichiers journaux ont été supprimés manuellement, car les nouveaux fichiers seront créés et la journalisation continuera correctement.
-d, --debug
Active le mode de débogage, ce qui signifie qu'aucun changement n'est apporté aux journaux et que le fichier d'état de logrotate n'est pas mis à jour. Seuls les messages de débogage sont affichés.
-s, --state fichier_etat
Indique à logrotate d'utiliser un fichier d'état alternatif. Ceci est utile si logrotate est exécuté en tant qu'utilisateur différent pour différents ensembles de fichiers journaux. Pour éviter l'exécution parallèle, logrotate acquiert par défaut un verrou sur le fichier d'état ; s'il ne peut pas être acquis, logrotate se terminera avec la valeur 3. Le fichier d'état par défaut est /var/lib/logrotate.status. Si /dev/null est donné comme fichier d'état, alors logrotate n'essaiera pas de verrouiller ou d'écrire dans le fichier d'état.
--skip-state-lock
Ne pas verrouiller le fichier d'état, par exemple si le verrouillage n'est pas pris en charge ou est interdit.
--wait-for-state-lock
Attendre que le verrou sur le fichier d'état soit libéré par un autre processus logrotate. Cette option peut entraîner une attente indéfinie de logrotate. À utiliser avec prudence.
-v, --verbose
Active le mode verbeux, par exemple pour afficher des messages pendant la rotation.
-l, --log fichier
Indique à logrotate d'enregistrer la sortie verbeuse dans le fichier_journal. La sortie verbeuse enregistrée dans ce fichier est la même que lors de l'exécution de logrotate avec le commutateur -v. Le fichier journal est écrasé à chaque exécution de logrotate.
-m, --mail commande
Indique à logrotate quelle commande utiliser lors de l'envoi des journaux par e-mail. Cette commande doit accepter les arguments suivants :
1) l'objet du message donné avec '-s sujet'
2) le destinataire.
La commande doit ensuite lire un message sur l'entrée standard et l'envoyer au destinataire. La commande de messagerie par défaut est /usr/bin/mail.
--usage
Affiche un bref message d'utilisation.
-?, --help
Affiche le message d'aide.
--version
Affiche les informations de version.

FICHIER DE CONFIGURATION

logrotate lit toutes les informations sur les fichiers journaux qu'il doit traiter à partir de la série de fichiers de configuration spécifiés en ligne de commande. Chaque fichier de configuration peut définir des options globales (les définitions locales outrepassent les globales, et les définitions ultérieures outrepassent les précédentes) et spécifier les fichiers journaux à faire tourner. Les options globales n'affectent pas les directives d'inclusion précédentes. Un fichier de configuration simple ressemble à ceci :

# exemple de fichier de configuration logrotate
compress
/var/log/messages {
    rotate 5
    weekly
    postrotate
        /usr/bin/killall -HUP syslogd
    endscript
}
"/var/log/httpd/access.log" /var/log/httpd/error.log {
    rotate 5
    mail recipient@example.org
    size 100k
    sharedscripts
    postrotate
        /usr/bin/killall -HUP httpd
    endscript
}
/var/log/news/* {
    monthly
    rotate 2
    olddir /var/log/news/old
    missingok
    sharedscripts
    postrotate
        kill -HUP $(cat /var/run/inn.pid)
    endscript
    nocompress
}
~/log/*.log {}

Les premières lignes définissent les options globales ; dans l'exemple, les journaux sont compressés après leur rotation. Notez que des commentaires peuvent apparaître n'importe où dans le fichier de configuration tant que le premier caractère non blanc de la ligne est un #.

Les valeurs sont séparées des directives par des espaces et/ou un signe = optionnel. Les nombres doivent être spécifiés dans un format compris par strtoul(3).

La section suivante du fichier de configuration définit comment gérer le fichier journal /var/log/messages. Le journal subira cinq rotations hebdomadaires avant d'être supprimé. Après la rotation du fichier journal (mais avant que l'ancienne version du journal ne soit compressée), la commande /usr/bin/killall -HUP syslogd sera exécutée.

La section suivante définit les paramètres pour les deux fichiers /var/log/httpd/access.log et /var/log/httpd/error.log. Chacun est fait tourner chaque fois qu'il dépasse 100 kilooctets de taille, et les anciens fichiers journaux sont envoyés par e-mail (non compressés) à recipient@example.org après 5 rotations, au lieu d'être supprimés. Le sharedscripts signifie que le script postrotate ne sera exécuté qu'une seule fois pour cette section, et non une fois pour chaque journal qui est fait tourner. Notez que les noms de fichiers journaux peuvent être entourés de guillemets (et que les guillemets sont nécessaires si le nom contient des espaces). Les règles normales de mise entre guillemets du shell s'appliquent, avec les caractères ', " et \ pris en charge.

La section suivante définit les paramètres pour tous les fichiers dans /var/log/news. Chaque fichier est fait tourner sur une base mensuelle.

La dernière section utilise l'expansion tilde pour faire tourner les fichiers journaux dans le répertoire personnel de l'utilisateur courant. Ceci n'est disponible que si votre bibliothèque glob prend en charge l'expansion tilde. Le glob GNU prend en charge cela.

Veuillez utiliser les jokers avec prudence. Si vous spécifiez *, logrotate fera tourner tous les fichiers, y compris ceux déjà tournés. Une solution consiste à utiliser la directive olddir ou un joker plus précis (tel que *.log).

Veuillez noter que, par défaut, lors de l'utilisation de systemd(1), l'option ProtectSystem=full est définie dans le fichier logrotate.service. Cela empêche logrotate de modifier les journaux dans /etc et /usr.

Voici plus d'informations sur les directives qui peuvent être incluses dans un fichier de configuration de logrotate :

DIRECTIVES DU FICHIER DE CONFIGURATION

Ces directives peuvent être incluses dans un fichier de configuration de logrotate :

Rotation

rotate compte
Les fichiers journaux sont mis en rotation

compte fois avant d'être supprimées ou envoyées par courrier à l'adresse spécifiée dans une directive mail. Si compte est 0, les anciennes versions sont supprimées plutôt que d'être archivées. Si compte est -1, les anciens journaux ne sont pas du tout supprimés, sauf qu'ils sont affectés par maxage (à utiliser avec prudence, peut gaspiller des performances et de l'espace disque). Par défaut, c'est 0.
olddir répertoire
Les journaux sont déplacés dans répertoire pour l'archivage. Le répertoire doit se trouver sur le même périphérique physique que le fichier journal en cours d'archivage, sauf si l'option copy, copytruncate ou renamecopy est utilisée. Le répertoire est supposé être relatif au répertoire contenant le fichier journal, sauf si un nom de chemin absolu est spécifié. Lorsque cette option est utilisée, toutes les anciennes versions du journal se retrouvent dans répertoire. Cette option peut être remplacée par l'option noolddir.
noolddir
Les journaux sont archivés dans le répertoire où ils résident normalement (cela remplace l'option olddir).
su utilisateur groupe
Archive les fichiers journaux définis sous cet utilisateur et ce groupe au lieu d'utiliser l'utilisateur/groupe par défaut (généralement root). utilisateur spécifie l'utilisateur utilisé pour l'archivage et groupe spécifie le groupe utilisé pour l'archivage (voir la section UTILISATEUR ET GROUPE pour les détails). Si l'utilisateur/groupe que vous spécifiez ici n'a pas les privilèges suffisants pour créer des fichiers avec la propriété que vous avez spécifiée dans une directive create, cela provoquera une erreur. Si logrotate s'exécute avec des privilèges root, il est recommandé d'utiliser la directive su pour archiver les fichiers dans des répertoires qui sont directement ou indirectement sous le contrôle d'utilisateurs non privilégiés.

Fréquence

hourly
Les fichiers journaux sont archivés toutes les heures. Notez que généralement logrotate est configuré pour être exécuté par cron quotidiennement (ou par logrotate.timer lors de l'utilisation de systemd(1)). Vous devez modifier cette configuration et exécuter logrotate toutes les heures pour pouvoir réellement archiver les journaux toutes les heures.
daily
Les fichiers journaux sont archivés tous les jours.
weekly [jour_semaine]
Les fichiers journaux sont archivés une fois chaque jour_semaine, ou si la date est avancée d'au moins 7 jours depuis la dernière archivage (en ignorant l'heure exacte). L'interprétation de jour_semaine est la suivante : 0 signifie dimanche, 1 signifie lundi, ..., 6 signifie samedi ; la valeur spéciale 7 signifie tous les 7 jours, indépendamment du jour de la semaine. Par défaut, c'est 0 si l'argument jour_semaine est omis.
monthly
Les fichiers journaux sont archivés la première fois que logrotate est exécuté dans un mois (ce qui correspond normalement au premier jour du mois).
yearly
Les fichiers journaux sont archivés si l'année en cours n'est pas la même que celle de la dernière archivage.
size taille
Les fichiers journaux ne sont archivés que s'ils dépassent taille octets. Si taille est suivi de k, la taille est supposée être en kilooctets. Si M est utilisé, la taille est en mégaoctets, et si G est utilisé, la taille est en gigaoctets. Donc size 100, size 100k, size 100M et size 100G sont tous valides. Cette option est mutuellement exclusive avec les options d'intervalle de temps, et elle provoque l'archivage des fichiers journaux sans tenir compte de la dernière heure d'archivage, si spécifiée après les critères de temps (la dernière option spécifiée a la priorité).

Sélection des fichiers

missingok
Si le fichier journal est manquant, continuez avec le suivant sans émettre de message d'erreur. Voir aussi nomissingok.
nomissingok
Si un fichier journal n'existe pas, émettez une erreur. C'est le comportement par défaut.
ignoreduplicates
Ignore toute correspondance ultérieure d'un fichier journal.
ifempty
Archive le fichier journal même s'il est vide, remplaçant l'option notifempty (ifempty est le comportement par défaut).
notifempty
N'archive pas le journal s'il est vide (cela remplace l'option ifempty).
minage compte
N'archive pas les journaux qui ont moins de <compte> jours.
maxage compte
Supprime les journaux archivés de plus de <compte> jours. L'âge n'est vérifié que si le fichier journal doit être archivé. rotate -1 n'empêche pas la suppression. Les fichiers sont envoyés par courrier à l'adresse configurée si maillast et mail sont configurés.
minsize taille
Les fichiers journaux sont archivés lorsqu'ils dépassent taille octets, mais pas avant l'intervalle de temps spécifié supplémentaire (daily, weekly, monthly ou yearly). L'option size associée est similaire sauf qu'elle est mutuellement exclusive avec les options d'intervalle de temps, et elle provoque l'archivage des fichiers journaux sans tenir compte de la dernière heure d'archivage, si spécifiée après les critères de temps (la dernière option spécifiée a la priorité). Lorsque minsize est utilisé, la taille et l'horodatage d'un fichier journal sont pris en compte.
maxsize taille
Les fichiers journaux sont archivés lorsqu'ils dépassent taille octets même avant l'intervalle de temps spécifié supplémentaire (daily, weekly, monthly ou yearly). L'option size associée est similaire sauf qu'elle est mutuellement exclusive avec les options d'intervalle de temps, et elle provoque l'archivage des fichiers journaux sans tenir compte de la dernière heure d'archivage, si spécifiée après les critères de temps (la dernière option spécifiée a la priorité). Lorsque maxsize est utilisé, la taille et l'horodatage d'un fichier journal sont pris en compte.
tabooext [+] liste
La liste actuelle des extensions interdites est modifiée (voir la directive include pour des informations sur les extensions interdites). Si un + précède la liste des extensions, la liste actuelle des extensions interdites est augmentée, sinon elle est remplacée. Au démarrage, la liste des extensions interdites est ,v, .bak, .cfsaved, .disabled, .dpkg-bak, .dpkg-del, .dpkg-dist, .dpkg-new, .dpkg-old, .dpkg-tmp, .new, .old, .orig, .rhn-cfg-tmp-*, .rpmnew, .rpmorig, .rpmsave, .swp, .ucf-dist, .ucf-new, .ucf-old, ~
taboopat [+] liste
La liste actuelle des modèles globaux interdits est modifiée (voir la directive include pour des informations sur les extensions et les modèles interdits). Si un + précède la liste des modèles, la liste actuelle des modèles interdits est augmentée, sinon elle est remplacée. Au démarrage, la liste des modèles interdits est vide.

Fichiers et Dossiers

create mode propriétaire groupe, create propriétaire groupe
Immédiatement après l'archivage (avant que le script postrotate ne soit exécuté), le fichier journal est créé (avec le même nom que le fichier journal qui vient d'être archivé). mode spécifie le mode du fichier journal en octal (identique à chmod(2)), propriétaire spécifie l'utilisateur qui possédera le fichier journal, et groupe spécifie le groupe auquel le fichier journal appartiendra (voir la section UTILISATEUR ET GROUPE pour les détails). N'importe lequel des attributs du fichier journal peut être omis, auquel cas ces attributs pour le nouveau fichier utiliseront les mêmes valeurs que le fichier journal d'origine pour les attributs omis. Cette option peut être désactivée à l'aide de l'option nocreate.
nocreate
Les nouveaux fichiers journaux ne sont pas créés (cela remplace l'option create).
createolddir mode [propriétaire [groupe]], createolddir [propriétaire [groupe]]
Si le répertoire spécifié par la directive olddir n'existe pas, il est créé. mode spécifie le mode du répertoire olddir en octal (identique à chmod(2)), propriétaire spécifie l'utilisateur qui possédera le répertoire olddir, et groupe spécifie le groupe auquel le répertoire olddir appartiendra (voir la section UTILISATEUR ET GROUPE pour les détails). Si mode n'est pas spécifié, 0755 est supposé. Cette option peut être désactivée à l'aide de l'option nocreateolddir.
nocreateolddir
Le répertoire olddir n'est pas créé par logrotate lorsqu'il n'existe pas.
copy
Crée une copie du fichier journal, mais ne modifie pas l'original du tout. Cette option peut être utilisée, par exemple, pour créer un instantané du fichier journal actuel, ou lorsque d'autres utilitaires doivent tronquer ou analyser le fichier. Lorsque cette option est utilisée, l'option create n'aura aucun effet, car l'ancien fichier journal reste en place. L'option copy permet de stocker les fichiers journaux archivés sur des périphériques différents en utilisant la directive olddir.
nocopy
Ne copie pas le fichier journal d'origine et le laisse en place. (cela remplace l'option copy).
copytruncate
Tronque le fichier journal d'origine à une taille nulle sur place après la création d'une copie, au lieu de déplacer l'ancien fichier journal et d'en créer éventuellement un nouveau. Elle peut être utilisée lorsqu'un programme ne peut pas être informé de la fermeture de son fichier journal et pourrait donc continuer à écrire (ajouter) dans le fichier précédent.fichier journal toujours. Notez qu'il y a une très petite tranche de temps entre la copie du fichier et sa troncature, donc certaines données de journalisation pourraient être perdues. Lorsque cette option est utilisée, l'option create n'aura aucun effet, car l'ancien fichier journal reste en place. L'option copytruncate permet de stocker les fichiers journaux archivés sur différents périphériques en utilisant la directive olddir. L'option copytruncate implique norenamecopy.
nocopytruncate
Ne pas tronquer le fichier journal d'origine sur place après avoir créé une copie (ceci annule l'option copytruncate).
renamecopy
Le fichier journal est renommé en nom de fichier temporaire dans le même répertoire en ajoutant l'extension ".tmp". Après cela, le script postrotate est exécuté et le fichier journal est copié du nom de fichier temporaire vers le nom de fichier final. À la fin, le nom de fichier temporaire est supprimé. L'option renamecopy permet de stocker les fichiers journaux archivés sur différents périphériques en utilisant la directive olddir. L'option renamecopy implique nocopytruncate.
norenamecopy
Ne pas renommer et copier le fichier journal d'origine (ceci annule l'option renamecopy).
shred
Supprimer les fichiers journaux en utilisant shred -u au lieu de unlink(). Ceci devrait garantir que les journaux ne sont pas lisibles après leur suppression programmée ; ceci est désactivé par défaut. Voir aussi noshred.
noshred
Ne pas utiliser shred lors de la suppression des anciens fichiers journaux. Voir aussi shred.
shredcycles count
Demande à shred(1) de GNU d'écraser les fichiers journaux count fois avant la suppression. Sans cette option, le défaut de shred sera utilisé.
allowhardlink
Archiver les fichiers avec plusieurs liens matériels ; ceci est désactivé par défaut. Le fichier cible pourrait être vidé, par exemple avec shred ou copytruncate. Utiliser avec prudence, surtout lorsque les fichiers journaux sont archivés en tant que root.
noallowhardlink
Ne pas archiver les fichiers avec plusieurs liens matériels. Voir aussi allowhardlink.

Compression

compress
Les anciennes versions des fichiers journaux sont compressées avec gzip(1) par défaut. Voir aussi nocompress.
nocompress
Les anciennes versions des fichiers journaux ne sont pas compressées. Voir aussi compress.
compresscmd
Spécifie quelle commande utiliser pour compresser les fichiers journaux. La commande par défaut est gzip(1). Voir aussi compress.
uncompresscmd
Spécifie quelle commande utiliser pour décompresser les fichiers journaux. La commande par défaut est gunzip(1).
compressext
Spécifie quelle extension utiliser pour les fichiers journaux compressés, si la compression est activée. La valeur par défaut suit celle de la commande de compression configurée.
compressoptions
Les options de la ligne de commande peuvent être passées au programme de compression, s'il y en a un en cours d'utilisation. La valeur par défaut, pour gzip(1), est "-6" (privilégiant une compression élevée au détriment de la vitesse). Si vous utilisez une autre commande de compression, vous devrez peut-être modifier compressoptions pour qu'elle corresponde.
delaycompress
Retarder la compression du fichier journal précédent au prochain cycle d'archivage. Ceci n'a d'effet que lorsqu'il est utilisé en combinaison avec compress. Il peut être utilisé lorsqu'un programme ne peut pas être informé de fermer son fichier journal et donc pourrait continuer à écrire dans le fichier journal précédent pendant un certain temps.
nodelaycompress
Ne pas retarder la compression du fichier journal précédent au prochain cycle d'archivage (ceci annule l'option delaycompress).

Noms de fichiers

extension ext
Les fichiers journaux avec l'extension ext peuvent la conserver après l'archivage. Si la compression est utilisée, l'extension de compression (normalement .gz) apparaît après ext. Par exemple, si vous avez un fichier journal nommé mylog.foo et que vous souhaitez l'archiver en mylog.1.foo.gz au lieu de mylog.foo.1.gz.
addextension ext
Les fichiers journaux reçoivent l'extension finale ext après l'archivage. Si le fichier d'origine se termine déjà par ext, l'extension n'est pas dupliquée, mais simplement déplacée à la fin, c'est-à-dire que filename et filenameext seraient tous deux archivés en filename.1ext. Si la compression est utilisée, l'extension de compression (normalement .gz) apparaît après ext.
start count
C'est le nombre à utiliser comme base pour l'archivage. Par exemple, si vous spécifiez 0, les journaux seront créés avec une extension .0 lors de leur archivage à partir des fichiers journaux d'origine. Si vous spécifiez 9, les fichiers journaux seront créés avec une extension .9, en sautant 0 à 8. Les fichiers seront toujours archivés le nombre de fois spécifié avec la directive rotate.
dateext
Archiver les anciennes versions des fichiers journaux en ajoutant une extension de date comme YYYYMMDD au lieu d'ajouter simplement un numéro. L'extension peut être configurée en utilisant les options dateformat et dateyesterday.
nodateext
Ne pas archiver les anciennes versions des fichiers journaux avec une extension de date (ceci annule l'option dateext).
dateformat format_string
Spécifie l'extension pour dateext en utilisant une notation similaire à la fonction strftime(3). Seuls les spécificateurs %Y %m %d %H %M %S %V %s et %z sont autorisés. La valeur par défaut est -%Y%m%d, sauf pour l'hourly qui utilise -%Y%m%d%H comme valeur par défaut. Notez que le caractère séparant le nom du journal de l'extension fait partie de la chaîne dateformat. L'horloge système doit être réglée après le 9 septembre 2001 pour que %s fonctionne correctement. Notez que les horodatages générés par ce format doivent être triables lexicalement (c'est-à-dire d'abord l'année, puis le mois, puis le jour. Par exemple, 2001/12/01 est correct, mais 01/12/2001 ne l'est pas, car 01/11/2002 serait trié plus bas alors qu'il est plus tard). Ceci est dû au fait que lors de l'utilisation de l'option rotate, logrotate trie tous les noms de fichiers archivés pour trouver quels fichiers journaux sont plus anciens et doivent être supprimés.
dateyesterday
Utiliser la date d'hier au lieu d'aujourd'hui pour créer l'extension dateext , afin que le fichier journal archivé ait une date dans son nom qui soit la même que les horodatages qu'il contient.
datehourago
Utiliser l'heure précédente au lieu de la date actuelle pour créer l'extension dateext , afin que le fichier journal archivé ait une heure dans son nom qui soit la même que les horodatages qu'il contient. Utile avec rotate hourly.

Courrier

mail address
Lorsqu'un journal est archivé et supprimé, il est envoyé par courrier à address. Si aucun courrier ne doit être généré par un journal particulier, la directive nomail peut être utilisée.
nomail
Ne pas envoyer d'anciens fichiers journaux par courrier à une adresse quelconque.
mailfirst
Lors de l'utilisation de la commande mail, envoyer le fichier fraîchement archivé, au lieu de celui qui est sur le point d'expirer.
maillast
Lors de l'utilisation de la commande mail, envoyer le fichier sur le point d'expirer, au lieu de celui qui vient d'être archivé (c'est le comportement par défaut).

Fichiers de configuration supplémentaires

include file_or_directory
Lit le fichier donné en argument comme s'il était inclus en ligne là où la directive include apparaît. Si un répertoire est donné, la plupart des fichiers de ce répertoire sont lus par ordre alphabétique avant que le traitement du fichier incluant ne continue. Les seuls fichiers ignorés sont ceux qui ne sont pas des fichiers réguliers (tels que les répertoires et les pipes nommés) et les fichiers dont les noms se terminent par l'une des extensions ou des modèles tabous, tels que spécifiés par les directives tabooext ou taboopat, respectivement. Le chemin donné peut commencer par ~/ pour le rendre relatif au répertoire personnel de l'utilisateur exécutant. NAME

logrotate.conf — configuration file for logrotate

SYNOPSIS

/etc/logrotate.conf

DESCRIPTION

The file /etc/logrotate.conf contains global options that are used by the logrotate utility. The configuration file is divided into a global section for options that apply to all logs, and a section for each log file. In addition to the main configuration file, logrotate will include any files in /etc/logrotate.d, in alphabetical order.

Comments start with the hash mark character (#) and continue to the end of the line. The hash mark character must be the first character on the line.

The configuration directives are not case-sensitive.

OPTIONS

compress
On rotation, the compressed log file will be run old file through `gzip(1)' by default.
nocompress
On rotation, the compressed log file will be run old file through `bzip2(1)' by default.
compresscmd command
Command used to compress log files. Default is `gzip(1)'.
compressext extension
Extension to use for compressed files, i.e. `.z' or `.bz2'. Default is `.gz'.
compressoptions options
Command line options to pass to the compression command. Default is empty.
delaycompress
On rotation, delay compressing the most recent log file until the next rotation occurs. This also affects the `prerotate' and `postrotate' scripts.
nodateext
Don't append any date/time extension to the log file when rotating it. This can be used when log file names are specified explicitly.
extension extension
Use the given extension instead of the date/time stamp.
allpaths
Apply the rotation to all matching files, including those that are already compressed or have been rotated previously. This is the default.
rotate count
Log files are rotated count times. When count is 0, an old log file is deleted when it is replaced by a new log file. When count is 1, the today’s log file is removed at the end of today. If count is 7, then the logs are rotated seven times. Old log files are removed when they are rotated out.
maxage count
Log files are kept for at most count days. If count is `0`, there is no maximum age.
minsize size
Log files are rotated only if they grow bigger than size bytes. If you specify size with a K, M or G suffix, the unit will be B, KB, MB, or GB respectively. If no size is specified, log files are rotated every time logrotate runs. If you specify `0`, log files are rotated every time logrotate runs.
daily
Rotate logs daily.
weekly
Rotate logs weekly.
monthly
Rotate logs monthly.
yearly
Rotate logs yearly.
create [mode owner group]
Create a new empty log file after rotating the old one. The new log file will have the specified mode, owner, and group. If not specified, the new log file will be created with the same permissions as the original log file. The owner and group may be specified numerically or by name. If create is specified, the log file is always created when logrotate runs, even if the log file is empty.
dateext
Append the date/time to the rotated log file. The format of the date/time is taken from the `strftime(3)' man page.
dateformat format
Use the given format for the date string when rotating files. This requires the `dateext' directive to be enabled.
tabooext [+]extension ...
Specify a list of extensions that should not be rotated. If the first character is `+', the list of extensions is appended to the current list of taboo extensions. Otherwise, the list of extensions replaces the current list. By default, the list is `.bak', `.old', `.final', and `.rotate'.
rotatealso
Rotate the files specified in the `rotate' directive also when the current log file is rotated. This option is useful when the log files are split into several files in the same directory.
ifempty
Do not rotate the log file if the log file is empty. This option overrides the minsize option.
notifempty
Rotate the log file even if the log file is empty. This is the default.
olddir directory
Rotated logs (including old logs that have not yet been removed) are moved into directory. The directory must be on the same filesystem as the original log files. This directive must appear before the log file name.
errors address
Mail error messages to address. Logrotate will send mail after trying to rotate all the logs. If this address is the same as the address specified for the `prerotate' or `postrotate' scripts, only one mail message will be sent.
mail address
Mail the contents of the log file to address when it is rotated. The log file is mailed to address only if it has been rotated.
mailfirst
Mail the old log file to the address specified by mail directive before the log file is processed.
maillast
Mail the old log file to the address specified by mail directive after the log file has been processed, i.e. after prerotate and postrotate scripts have been run.
sharedscripts
Run prerotate and postrotate scripts only once for each set of log files which match the pattern, not for each log file. The scripts are run in alphabetical order of the patterns at the end of processing, or beginning of processing, respectively. The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for any logs. This option overrides the nosharedscripts option.
nosharedscripts
Run prerotate and postrotate scripts for every log file which is rotated (this is the default, and overrides the sharedscripts option). The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for the affected log only.
firstaction

    script

endscript
The script is executed once before all log files that match the wildcarded pattern are rotated, before the prerotate script is run and only if at least one log will actually be rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, no further processing is done. See also lastaction and the SCRIPTS section.
lastaction

    script

endscript
The script is executed once after all log files that match the wildcarded pattern are rotated, after the postrotate script is run and only if at least one log is rotated. These directives may only appear inside a log file definition. The whole pattern is passed to the script as its first argument. If the script exits with an error, just an error message is shown (as this is the last action). See also firstaction and the SCRIPTS section.
prerotate

    script

endscript
The script is executed before the log file and its old logs are rotated and only if the log will actually be rotated. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script. If sharedscripts is specified, the whole pattern is passed to the script. See also postrotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.
postrotate

    script

endscript
The script is executed after the log file is rotated and before the log file is being compressed. These directives may only appear inside a log file definition. Normally, the absolute path to the log file is passed as the first argument to the script and the absolute path to the final rotated log file is passed as the second argument to the script. If sharedscripts is specified, the whole pattern is passed as the first argument to the script, and the second argument is omitted. See also prerotate and the SCRIPTS section. See sharedscripts and nosharedscripts for error handling.
preremove

    script

endscript
The script is executed once just before removal of a log file. logrotate will pass the name of file which is soon to be removed as the first argument to the script. See also firstaction and the SCRIPTS section.

CONFIGURATION FILE

The configuration file is divided into a global section for options that apply to all logs, and a section for each log file. In addition to the main configuration file, logrotate will include any files in /etc/logrotate.d, in alphabetical order.

CONFIGURATION FILE DIRECTIVES

The directives used in the configuration file are described in the OPTIONS section.

A log file definition starts with the name of the log file (or a pattern) followed by an opening curly brace `{'. The definition ends with a closing curly brace `}'.

The following is an example of a log file definition:

/var/log/nginx/*log {
    daily
    rotate 4
    maxlen 365
    compress
    delaycompress
    missingok
    notifempty
    create 0640 www-data adm
    sharedscripts
    prerotate
        if [ -d /etc/logrotate.d/httpd-prerotate ]; then \
            run-parts /etc/logrotate.d/httpd-prerotate; \
        fi \
    endscript
    postrotate
        invoke-rc.d nginx rotate > /dev/null 2>&1
    endscript
}

SCRIPTS

The lines between the starting keyword (e.g. prerotate) and endscript (both of which must appear on lines by themselves) are executed (using /bin/sh). The script inherits some traits from the logrotate process, including stderr, stdout, the current directory, the environment, and the umask. Scripts are run as the invoking user and group, irrespective of any su directive. If the --log flag was specified, file descriptor 3 is the log file. The current working directory is unspecified.

USER AND GROUP

User and group identifiers are resolved first by trying the textual representation and, in case it fails, afterwards by the numeric value.
