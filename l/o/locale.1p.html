LOCALE(1P) Manuel du programmeur POSIX LOCALE(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

locale — obtenir des informations spécifiques à la locale

SYNTAXE

locale [-a|-m]
locale [-ck] nom...

DESCRIPTION

L'utilitaire locale écrira des informations sur l'environnement de locale courant, ou sur toutes les locales publiques, sur la sortie standard. Aux fins de cette section, une locale publique est une locale fournie par l'implémentation qui est accessible à l'application.

Lorsque locale est appelé sans aucun argument, il résumera l'environnement de locale courant pour chaque catégorie de locale tel que déterminé par les paramètres des variables d'environnement définies dans le volume Base Definitions de POSIX.1‐2017, Chapitre 7, Locale.

Lorsqu'il est appelé avec des opérandes, il écrira les valeurs qui ont été assignées aux mots-clés dans les catégories de locale, comme suit :

*
Spécifier un nom de mot-clé sélectionnera le mot-clé nommé et la catégorie contenant ce mot-clé.
*
Spécifier un nom de catégorie sélectionnera la catégorie nommée et tous les mots-clés de cette catégorie.

OPTIONS

L'utilitaire locale doit être conforme au volume Base Definitions de POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire.

Les options suivantes doivent être prises en charge :

-a
Écrit des informations sur toutes les locales publiques disponibles. Les locales disponibles doivent inclure POSIX, représentant la locale POSIX. La manière dont l'implémentation détermine quelles autres locales sont disponibles est définie par l'implémentation.
-c
Écrit les noms des catégories de locale sélectionnées ; voir la section SORTIE STANDARD. L'option -c améliore la lisibilité lorsque plus d'une catégorie est sélectionnée (par exemple, via plus d'un nom de mot-clé ou via un nom de catégorie). Elle est valide avec et sans l'option -k.
-k
Écrit les noms et les valeurs des mots-clés sélectionnés. L'implémentation peut omettre les valeurs pour certains mots-clés ; voir la section OPÉRANDES.
-m
Écrit les noms des charmaps disponibles ; voir le volume Base Definitions de POSIX.1‐2017, Section 6.1, Jeu de caractères portable.

OPÉRANDES

L'opérande suivant doit être pris en charge :

nom
Le nom d'une catégorie de locale tel que défini dans le volume Base Definitions de POSIX.1‐2017, Chapitre 7, Locale, le nom d'un mot-clé dans une catégorie de locale, ou le nom réservé charmap. La catégorie ou le mot-clé nommé sera sélectionné pour la sortie. Si un seul nom représente à la fois un nom de catégorie de locale et un nom de mot-clé dans la locale actuelle, les résultats ne sont pas spécifiés. Sinon, les noms de catégorie et de mot-clé peuvent être spécifiés comme opérandes nom, dans n'importe quel ordre. Il est défini par l'implémentation si des valeurs de mots-clés sont écrites pour les catégories LC_CTYPE et LC_COLLATE.

ENTRÉE STANDARD

Non utilisé.

FICHIERS ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de locale :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie avec une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

L'application doit s'assurer que les variables d'environnement LANG, LC_* et NLSPATH spécifient l'environnement de locale courant à écrire ; elles seront utilisées si l'option -a n'est pas spécifiée.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La variable LANG sera écrite en premier en utilisant le format :

"LANG=%s\n", <valeur>

Si LANG n'est pas définie ou est une chaîne vide, la valeur est la chaîne vide.

Si locale est appelée sans aucune option ni opérande, les noms et les valeurs des variables d'environnement LC_* décrites dans ce volume de POSIX.1‐2017 seront écrits sur la sortie standard, une variable par ligne, et chaque ligne utilisera le format suivant. Seules les variables définies dans l'environnement et non remplacées par LC_ALL seront écrites en utilisant ce format :

"%s=%s\n", <nom_variable>, <valeur>

Les noms des variables LC_* associées aux catégories de locale définies dans ce volume de POSIX.1‐2017 qui ne sont pas définies dans l'environnement ou qui sont remplacées par LC_ALL seront écrits dans le format suivant :

"%s=\"%s\"\n", <nom_variable>, <valeur_implicite>

La <valeur_implicite> sera le nom de la locale qui a été sélectionnée pour cette catégorie par l'implémentation, basée sur les valeurs de LANG et LC_ALL, comme décrit dans le volume Base Definitions de POSIX.1‐2017, Chapitre 8, Variables d'environnement.

La <valeur> et la <valeur_implicite> indiquées ci-dessus seront correctement mises entre guillemets pour une éventuelle réintroduction dans le shell. La <valeur> ne sera pas mise entre guillemets doubles (afin qu'elle puisse être distinguée par l'utilisateur du cas de la <valeur_implicite>, qui nécessite toujours des guillemets doubles).

La variable LC_ALL sera écrite en dernier, en utilisant le premier format indiqué ci-dessus. Si elle n'est pas définie, elle sera écrite comme suit :

"LC_ALL=\n"

Si des arguments sont spécifiés :

1.
Si l'option -a est spécifiée, les noms de toutes les locales publiques seront écrits, chacun dans le format suivant :
"%s\n", <nom_locale>
2.
Si l'option -c est spécifiée, les noms de toutes les catégories sélectionnées seront écrits, chacun dans le format suivant :
"%s\n", <nom_catégorie>

Si des mots-clés sont également sélectionnés pour l'écriture (voir les points suivants), la sortie du nom de catégorie précédera la sortie du mot-clé pour cette catégorie.

NAME

locale - query language and cultural region format information

SYNOPSIS

locale [-a] [-c] [-k] [-m] [-v] [name...

DESCRIPTION

The locale utility shall output information about the current locale settings. It can be used to query the set of available locales, or to query specific keywords within the current locale.

The locale utility shall determine the current locale settings from the environment variables described in Section 8.2, Locale Environment Variables. The order of precedence shall be the same as described there.

The following options shall be supported:

-a
Write a list of all available locales on the system. The format of the output is implementation-defined, but each locale shall be on a separate line.
-c
Write the names of the categories associated with the selected keywords. This option is useful when querying multiple keywords, where the order of presentation of the categories is not specified by this volume of POSIX.1‐2017.
-k
Write the names and values of selected keywords. This option selects the output of keyword-value pairs rather than just the keyword values.
-m
Write a list of all available charmaps on the system. Each charmap shall be on a separate line.
-v
Write a description of the locale on the standard error. This is intended for debugging. The exact format is implementation-defined.

If the name arguments are specified, they shall represent keywords or categories for which information is to be retrieved from the current locale.

Keywords and categories are defined in the Base Definitions volume of POSIX.1‐2017, Chapter 7, Locale. The locale utility shall support all keywords defined there.

The format of the output depends on whether the -k option is specified.

1.
If the name arguments are categories (for example, LC_ALL, LC_COLLATE, etc.), and the -k option is not specified, the names and values of all keywords within those categories shall be written. The order of presentation of the categories is not specified. If the -c option is specified, the name of the category shall be written before the keywords in that category.
"%s=%s\n", <keyword name>, <keyword value>

If a value is a compound keyword value (a list of strings), it shall be written as a single string, with the list elements enclosed in double-quotation marks and separated by semicolon characters. For example: "a":"b":"c". The <semicolon>, <backslash>, and double-quote characters within the strings shall be preceded by the escape character.

2.
If the name arguments are keywords, and the -k option is not specified, the values of the selected keywords shall be written, each followed by a <newline>. If the -c option is specified, the names of the categories shall not be written; only the keywords, as selected by the <name> operand, shall be written.
"%s\n", <keyword value>
3.
If the -k option is specified, the names and values of selected keywords shall be written. If a value is non-numeric and is not a compound keyword value, it shall be written in the following format:
"%s=\"%s\"\n", <keyword name>, <keyword value>

If a value is a non-numeric compound keyword value, it shall either be written in the format:

"%s=\"%s\"\n", <keyword name>, <keyword value>

where the <keyword value> is a single string of values separated by <semicolon> characters, or it shall be written in the format:

"%s=%s\n", <keyword name>, <keyword value>

where the <keyword value> is encoded as a set of strings, each enclosed in double-quotation-marks, separated by <semicolon> characters.

If the keyword was charmap, the name of the charmap (if any) that was specified via the localedef -f option when the locale was created shall be written, with the word charmap as <keyword name>.

If a value is numeric, it shall be written in one of the following formats:

"%s=%d\n", <keyword name>, <keyword value>
"%s=%c%o\n", <keyword name>, <escape character>, <keyword value>
"%s=%cx%x\n", <keyword name>, <escape character>, <keyword value>

where the <escape character> is that identified by the escape_char keyword in the current locale; see the Base Definitions volume of POSIX.1‐2017, Section 7.3, Locale Definition.

Compound keyword values (list entries) shall be separated in the output by <semicolon> characters. When included in keyword values, the <semicolon>, <backslash>, double-quote, and any control character shall be preceded (escaped) with the escape character.

4.
If the -k option is not specified, selected keyword values shall be written, each in the following format:
"%s\n", <keyword value>

If the keyword was charmap, the name of the charmap (if any) that was specified via the localedef -f option when the locale was created shall be written.

5.
If the -m option is specified, then a list of all available charmaps shall be written, each in the format:
"%s\n", <charmap>

where <charmap> is in a format suitable for use as the option-argument to the localedef -f option.

STDERR

The standard error shall be used only for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

0
All the requested information was found and output successfully.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Default.

The following sections are informative.

APPLICATION USAGE

If the LANG environment variable is not set or set to an empty value, or one of the LC_* environment variables is set to an unrecognized value, the actual locales assumed (if any) are implementation-defined as described in the Base Definitions volume of POSIX.1‐2017, Chapter 8, Environment Variables.

Implementations are not required to write out the actual values for keywords in the categories LC_CTYPE and LC_COLLATE; however, they must write out the categories (allowing an application to determine, for example, which character classes are available).

EXAMPLES

In the following examples, the assumption is that locale environment variables are set as follows:

LANG=locale_x
LC_COLLATE=locale_y

The command locale would result in the following output:

LANG=locale_x
LC_CTYPE="locale_x"
LC_COLLATE=locale_y
LC_TIME="locale_x"
LC_NUMERIC="locale_x"
LC_MONETARY="locale_x"
LC_MESSAGES="locale_x"
LC_ALL=

The order of presentation of the categories is not specified by this volume of POSIX.1‐2017.

The command:

LC_ALL=POSIX locale -ck decimal_point

would produce:

LC_NUMERIC
decimal_point="."

The following command shows an application of locale to determine whether a user-supplied response is affirmative:

printf 'Prompt for response: '
read response
if printf "%s\n$response" | grep -- -Eq "$(locale yesexpr)"
then
    affirmative processing goes here
else
    non-affirmative processing goes here
fi

RATIONALE

The output for categories LC_CTYPE and LC_COLLATE has been made implementation-defined because there is a questionable value in having a shell script receive an entire array of characters. It is also difficult to return a logical collation description, short of returning a complete localedef source.

The -m option was included to allow applications to query for the existence of charmaps. The output is a list of the charmaps (implementation-supplied and user-supplied, if any) on the system.

The -c option was included for readability when more than one category is selected (for example, via more than one keyword name or via a category name). It is valid both with and without the -k option.

The charmap keyword, which returns the name of the charmap (if any) that was used when the current locale was created, was included to allow applications needing the information to retrieve it.

According to the Base Definitions volume of POSIX.1‐2017, Section 6.1, Portable Character Set, the standard requires that all supported locales must have the same encoding for <period> and <slash>, because these two characters are used within the locale-independent pathname resolution sequence. Therefore, it would be an error if locale -a listed both ASCII and EBCDIC-based locales, since those two encodings do not share the same representation for either <period> or <slash>. Any system that supports both environments would be expected to provide two POSIX locales, one in either codeset, where only the locales appropriate to the current environment can be visible at a time. In an XSI-compliant implementation, the dd utility is the only portable means for performing conversions between the two character sets.
