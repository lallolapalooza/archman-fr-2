NOM

localsearch-3 - Indexeur de système de fichiers.

SYNTAXE

localsearch-3 [OPTION...]

DESCRIPTION

localsearch-3 n'est pas censé être exécuté par l'utilisateur car il est démarré par systemd lorsque l'utilisateur se connecte. Bien sûr, il peut également être démarré manuellement à des fins de débogage. Vous ne pouvez pas exécuter plus d'une instance de celui-ci en même temps.

localsearch-3 extrait des informations uniquement sur les applications et les fichiers.

OPTIONS

-?, --help

Affiche un résumé des options.

-V, --version

Retourne la version de ce binaire.

-n, --no-daemon

Indique à l'indexeur de quitter une fois que tout l'indexage est terminé et que la base de données est à jour. Ce n'est pas le mode de fonctionnement par défaut de l'indexeur, il reste généralement en place agissant comme un démon pour surveiller les mises à jour de fichiers qui peuvent survenir avec le temps. Cette option rend l'option --initial-sleep caduque.

-e, --eligible=FICHIER

Vérifie si FICHIER est éligible pour être extrait en fonction des règles de configuration actuelles. En plus de cela, il vérifiera si FICHIER sera surveillé pour les changements. Cela fonctionne aussi bien avec des arguments FICHIER inexistants qu'avec des arguments FICHIER existants.

INTÉGRATION AU BUREAU

Les environnements de bureau qui utilisent localsearch-3 devraient démarrer l'unité utilisateur localsearch-3.service au démarrage. Par exemple, les sessions gérées par gnome-session peuvent ajouter ce service comme une dépendance Wants= dans leur fichier de configuration gnome-session@name.target.d/session.conf.

Cela permet aux sessions de désactiver l'indexage de fond du système de fichiers (en ne démarrant tout simplement pas localsearch-3.service) dans les situations où il n'est pas nécessaire (par exemple, des sessions de kiosque spéciales)
