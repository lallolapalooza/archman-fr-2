FBB::Log(3bobcat) Messages de journal FBB::Log(3bobcat)

NOM

FBB::Log - gère les messages de journal via std::ostream

SYNOPSIS

#include <bobcat/log>
Option de liaison : -lbobcat

DESCRIPTION

La classe FBB::Log définit un std::ostream utilisant un std::streambuf de type FBB::LogBuf. Elle est utilisée pour envoyer des messages de journal au flux (r)syslog ou à un fichier (configurable). Reportez-vous à la page de manuel logbuf(3bobcat) pour plus de détails sur LogBuf.

Quels (parties de) messages sont effectivement journalisés peut être configuré en utilisant FBB::level en combinaison avec le membre setLevel de Log ou en utilisant l'opérateur fonctionnel en combinaison avec le membre str (voir les membres operator() et str). Par défaut, toutes les informations insérées dans un objet Log sont journalisées.

Les objets de la classe level (cf. level(3bobcat)) peuvent être insérés pour spécifier des « forces » d'insertion pour les informations qui sont ensuite insérées dans les objets Log. Ce n'est que si ces « forces » dépassent les « résistances » d'insertion de l'objet Log (voir le membre setLevel) que les informations sont journalisées.

Une seule instruction d'insertion de journal peut contenir plusieurs appels à level. Si c'est le cas, chaque appel à level met à jour la « force » des insertions suivant l'appel à level.

Les informations insérées dans les objets Log sans insérer d'objets level (ou avant le premier objet level) sont toujours journalisées (voir aussi la section Exemples).

Alternativement, les informations peuvent être journalisées en utilisant des caractères sélecteurs de catégorie. Le membre str(std::string const &active) définit les caractères qui peuvent être utilisés pour définir un processus de journalisation non hiérarchique. Par exemple, str("abc") définit les caractères identifiant le journal 'a', 'b', et 'c' qui peuvent ensuite être utilisés pour définir des instructions de journalisation pour chacune de ces catégories. Ces caractères identifiant le journal peuvent être redéfinis, n'activant que les instructions de journalisation dont les caractères identificateurs ont été spécifiés dans le dernier appel au membre str.

Bien que la journalisation hiérarchique et non hiérarchique puissent toutes deux être utilisées dans un seul programme, elles fonctionnent de manière mutuellement exclusive : une fois la journalisation hiérarchique définie, les catégories non hiérarchiques sont effacées, et une fois les catégories non hiérarchiques définies, le niveau de résistance hiérarchique est réglé à sa valeur maximale, supprimant ainsi efficacement la journalisation hiérarchique.

Par défaut, les messages journalisés sont précédés d'horodatages. Après les horodatages, un délimiteur (par défaut, un seul espace) est inséré. Les délimiteurs sont immédiatement ajoutés aux horodatages et les messages insérés sont immédiatement ajoutés aux délimiteurs. Lors de la spécification de texte comme délimiteurs, envisagez de commencer et de terminer le texte du délimiteur par des espaces pour séparer visuellement le délimiteur de l'horodatage et des informations insérées par la suite.

ESPACE DE NOM

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de nom FBB.

HÉRITE DE

std::ostream

ÉNUMÉRATIONS

L'énumération TimeStamps est définie dans l'espace de nom FBB, principalement pour initialiser les objets FBB::LogBuf. Elle est également utilisée avec les membres Log. Elle a les valeurs suivantes :

o
NOTIMESTAMPS :
Les messages de journal ne seront pas précédés d'horodatages.
o
TIMESTAMPS :
Les messages de journal seront précédés d'horodatages.
o
UTCTIMESTAMPS :
Les messages de journal seront précédés d'horodatages indiquant l'heure UTC.

L'énumération LogManipulator est utilisée pour gérer des situations spéciales ou exceptionnelles via des manipulateurs. Elle est définie dans l'espace de nom FBB et a les deux valeurs suivantes :

o
FATAL :
Lors de l'insertion de FATAL dans un objet Log, une exception FBB::Exception est levée (voir operator<< ci-dessous) ;
o
nl :
Lors de l'insertion de nl dans un objet Log, un caractère \n est inséré dans la ligne actuelle. Si des horodatages sont demandés, la ligne suivante ne commencera pas par un horodatage. Elle est utilisée pour permettre à un seul message de journal d'occuper plusieurs lignes textuelles. La ligne de journal suivante n'est pas décalée sur la largeur de l'horodatage omis. Si cela est préféré : l'horodatage occupe 15 positions de caractères (sans compter la largeur du délimiteur, voir la section CONSTRUCTEURS ci-dessous). Si une spécification de level est active, elle reste active pour les insertions suivant nl.
o
fnl :
Lors de l'insertion de fnl (saut de ligne forcé) dans un objet Log, la ligne actuelle se termine même si la « force » d'insertion actuellement active (définie par level) est inférieure au niveau de « résistance » de l'objet Log. Si une spécification de level est active, elle reste active pour les insertions suivant fnl.
o
endl ou \n :
Lors de l'insertion de endl ou \n, la ligne actuelle se termine et la ligne de journal suivante commence par un horodatage (sauf si les horodatages sont supprimés). Le manipulateur endl est le manipulateur standard de ostream : lorsqu'il est inséré dans un objet Log, son tampon est vidé. La portée d'une spécification level se termine à \n ou endl. Par exemple, 
log.setLevel(2);
log << level(1) << "première ligne\n"
       "deuxième ligne\n";
résulte en la journalisation de deuxième ligne (précédée d'un horodatage).

CONSTRUCTEURS

o
Log() :
Le constructeur par défaut crée un objet Log qui n'est pas encore associé à un flux pour journaliser les messages. Le membre open (voir ci-dessous) peut être utilisé pour définir un tel flux. Par défaut, tous les messages sont précédés d'un horodatage (voir la description du membre setTimestamp ci-dessous), et un seul espace est inséré comme délimiteur juste après l'horodatage. Le membre open peut être utilisé pour modifier le délimiteur par défaut.
o
Log(std::ostream &out, char const *delim = " ") :
Ce constructeur crée un objet Log qui journalise ses messages dans l'objet std::ostream fourni. Par défaut, tous les messages sont précédés d'un horodatage (voir la description du membre setTimestamp ci-dessous). Le paramètre delim est inséré juste après l'horodatage. Si aucun délimiteur ne doit être utilisé, une chaîne vide ou un pointeur nul peuvent être spécifiés.
o
FBB::Log(std::string const &filename, std::ios::openmode mode = std::ios::out | std::ios::app, char const *delim = " ") :
Ce constructeur crée un objet Log qui journalise ses messages dans le fichier nommé. Si filename == "&1", les messages de journal sont écrits dans le flux de sortie standard. Si filename == "&2", les messages de journal sont écrits dans le flux d'erreur standard. Par défaut, le fichier est créé s'il n'existe pas, et tous les messages sont ajoutés au flux. Également par défaut, tous les messages sont précédés d'horodatages (voir la description du membre setTimestamp ci-dessous). Le paramètre delim est inséré juste après l'horodatage. Si aucun délimiteur ne doit être utilisé, une chaîne vide ou un pointeur nul peuvent être spécifiés.

Les constructeurs par copie et par déplacement (ainsi que les opérateurs d'affectation) ne sont pas disponibles.

FONCTIONS MEMBRES

Tous les membres de

std::ostream sont disponibles, car Log hérite de cette classe.

o
size_t level() const:
Ce membre retourne le niveau de journalisation actuellement défini (c'est-à-dire la valeur définie lors du dernier appel à setLevel()). Par défaut, le niveau est défini à zéro, ce qui signifie que toutes les informations sont insérées dans le flux de journalisation ;
o
std::ostream &level(size_t useLevel):
Ce membre définit le niveau de journalisation des messages qui vont être insérés. Les messages sont insérés lorsque useLevel est au moins égal au niveau spécifié par setLevel. Le niveau maximum est std::numeric_limits<size_t>::max(). Si même de tels messages ne doivent pas être insérés dans le ostream, alors le flux doit être désactivé, en utilisant off() (voir ci-dessous). Le niveau spécifié par ce membre reste actif jusqu'à ce qu'un autre appel à level le modifie. Alternativement, le niveau des messages insérés peut être spécifié en insérant un manipulateur FBB::level dans un objet Log (voir level(3bobcat)) ;
o
void off():
Empêche la génération de messages de journalisation. Ceci est annulé en appelant on (voir ci-dessous) ;
o
void on(size_t logLevel = 0):
Réactive la journalisation (par exemple, après que off ait été appelé précédemment) en définissant le niveau que les informations insérées doivent au moins avoir (jusqu'à logLevel). Après on et sauf indication contraire (par exemple, en utilisant level) toutes les informations insérées sont acceptées par l'objet Log ;
o
void open(std::string const &filename, std::ios::openmode mode = std::ios::out | std::ios::app, char const *delim = " "):
Ce membre (ré)associe un objet Log au fichier nommé. Si filename == "&1" les messages de journalisation seront écrits sur le flux de sortie standard. Si filename == "&2" les messages de journalisation seront écrits sur le flux d'erreur standard. Par défaut, le fichier est créé s'il n'existe pas, et tous les messages sont ajoutés au flux. Également par défaut, tous les messages sont précédés d'horodatages (voir la description du membre setTimestamp ci-dessous). Le paramètre delim est inséré immédiatement après l'horodatage. Si un délimiteur ne doit pas être utilisé, une chaîne vide ou un pointeur 0 peuvent être spécifiés ;
o
void setLevel(size_t resistance):
Définit la 'résistance' lors de l'insertion d'informations dans un objet Log. Les informations sont insérées si le niveau défini par le membre level est au moins égal à resistance. Après setLevel et sauf indication contraire (par exemple, en utilisant level), toutes les informations insérées sont acceptées par l'objet Log. setLevel ne réactive pas la journalisation après l'appel à off. Pour réactiver la journalisation après avoir appelé off, on doit être appelé ;
o
void setTimestamp(FBB::TimeStamps stamp, char const *delim = " "):
La fonction membre active (désactive) le préfixe d'horodatage. Utilisez la valeur FBB::TIMESTAMPS pour préfixer les horodatages, FBB::NOTIMESTAMPS supprime les horodatages. Un horodatage consiste en 15 caractères indiquant le nom abrégé du mois, deux chiffres spécifiant le jour du mois, et l'heure (locale ou UTC) du message courant, tels qu'ils apparaissent généralement dans les messages des fichiers de /var/log. Par exemple, Aug 05 13:52:23. Le paramètre delim est inséré immédiatement après l'horodatage. Si un délimiteur est inapproprié, une chaîne vide ou un pointeur 0 peuvent être spécifiés. Lors de la spécification de stamps comme FBB::NOTIMESTAMPS, delim est également ignoré.
o
std::string const &str() const:
L'ensemble actuel de caractères pouvant être spécifiés par l'opérateur d'appel de fonction de Log pour insérer une entrée de journal est retourné. Par défaut, aucun caractère n'est spécifié ;
o
void str(std::string const &chars):
L'argument de ce membre est une std::string définissant les caractères qui peuvent être spécifiés par l'opérateur d'appel de fonction de Log pour insérer une entrée de journal. Si l'opérateur d'appel de fonction spécifie un caractère qui n'est pas spécifié dans chars, alors ce message de journal est ignoré. Par défaut, aucun caractère n'est spécifié.

MEMBRES STATIQUES

o
FBB::Log &initialize(std::string const &filename, std::ios::openmode mode = std::ios::out | std::ios::app, char const *delim = " "):
Retourne une référence à un objet Log statique. Il ne peut être appelé qu'une seule fois, sinon une exception FBB::Exception est levée. Il associe un objet Log statique au fichier nommé.
Si filename == "&1" les messages de journalisation sont écrits sur le flux de sortie standard. Si filename == "&2" les messages de journalisation sont écrits sur le flux d'erreur standard. Par défaut, le fichier est créé s'il n'existe pas, et tous les messages sont ajoutés au flux. Également par défaut, tous les messages sont précédés d'horodatages (voir la description du membre setTimestamp ci-dessous). Le paramètre delim est inséré immédiatement après l'horodatage. Si un délimiteur ne doit pas être utilisé, une chaîne vide ou un pointeur 0 peuvent être spécifiés ;
o
FBB::Log &instance():
Retourne une référence à un objet Log statique, disponible après l'appel à Log::initialize. Si appelé avant Log::initialize(), une exception FBB::Exception est levée.

OPÉRATEURS SURCHARGÉS

o
Log &operator()(char ch):
Si l'argument de la fonction se trouve parmi les caractères spécifiés dans le membre str, les insertions ultérieures jusqu'à (et incluant) l'insertion de std::endl ou des manipulateurs fnl ou FATAL LogManipulator sont journalisées. Si l'argument de la fonction ne se trouve pas parmi les caractères spécifiés dans le membre str, les insertions ultérieures sont ignorées. En appelant ce membre, les insertions hiérarchiques sont supprimées jusqu'à ce que le membre setLevel soit appelé ;
o
Log &operator<<(Log &, LogManipulator):
Cet opérateur insère un LogManipulator dans un objet Log. Lors de l'insertion de FBB::FATAL, une FBB::Exception est levée ; lors de l'insertion de FBB::nl, la ligne est terminée et la prochaine insertion ne commencera pas par un horodatage ; lors de l'insertion de FBB::fnl, la ligne est terminée et la prochaine insertion commencera par un horodatage (si applicable). Après avoir appelé cet opérateur d'insertion avec le manipulateur FATAL ou fnl LogManipulator, les insertions basées sur la catégorie de valeurs sont supprimées jusqu'à ce que l'opérateur d'appel de fonction soit appelé ;
o
Log &operator<<(Log &log, Type const &type):
Cet opérateur est défini comme un modèle, où Type représente tout type pouvant être inséré dans un std::ostream. La valeur type est insérée dans l'objet Log ;
o
Log &operator<<(Log &log, Type &(*fun)(Type &type)):
Dans cet opérateur, fun représente les manipulateurs standard ostream et ios_base, permettant l'insertion de manipulateurs tels que std::endl et std::setw dans des objets Log ;
o
std::ostream &::operator<<(std::ostream &str, FBB::LogManipulator):
Cet opérateur est défini en dehors de l'espace de noms FBB. Il est conservé pour assurer la compatibilité ascendante avec les versions précédentes de bobcat et appelle operator<<(Log, LogManipulatr) lorsque &str peut être converti dynamiquement en Log *. Sinon, l'opérateur n'effectue aucune action.

EXEMPLE

#include <iostream>
#include <iomanip>
//#include <bobcat/log>
#include "../log"
#include <bobcat/level>
using namespace std;
using namespace FBB;
int main()
{
//    Log &log = Log::initialize("&1"); // utilise l'objet Log statique
    Log log;                        // définition explicite d'un objet Log
//    log.open("/tmp/out");           // ou en une fois : Log log{ "/tmp/out" }
    log << "Ce message est écrit sur cout" << nl <<
           setw(16) << ’ ’ << "s'étendant sur plusieurs lignes\n";
    log.off();
    log << "Ce message n'est pas affiché\n";
    log << "Ce message n'est pas affiché\n";
    log << fnl;
    log << "Ce message n'est pas affiché\n";
    log.on(2);
    log << "Ce message est affiché\n";
    log << level(0) << "non affiché" << level(2) << "affiché au niveau 2\n";
    log << level(3) << "au niveau(3)" << level(1) << "non affiché" << fnl;
    log << "nouvelle ligne séparée\n";
    log << level(2) << "de retour en affaires\n";
    log << "dernière ligne\n";
    log.str("ab");
    log(’a’) << "bonjour a!" << endl;
    log(’b’) << "bonjour b!" << nl <<
                setw(16) << ’ ’ << "jusqu'ici, tout va bien" << endl;
    log << "non affiché" << endl;
    log(’c’) << "non affiché\n";
    log << "non affiché\n";
    log.setLevel(2);
    log << level(2) << "de retour en affaires\n";
}

BOGUES

Les manipulateurs nl et fnl sont reçus par les LogBufs des objets Log comme caractères 0 et 1 respectivement. Étant donné que les fichiers journaux ne reçoivent en pratique que des caractères imprimables, cela ne devrait poser aucun problème.
