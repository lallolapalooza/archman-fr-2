NOM

lowdown-diff — visualiser les différences entre fichiers markdown

SYNTAXE

lowdown-diff [options_entrée] [options_sortie] [-s] [-M métadonnées] [-m métadonnées] [-o fichier] [-t mode] fichier_ancien [fichier_nouveau]

DESCRIPTION

Affiche les différences entre documents lowdown(5) sous forme de sortie formatée. Les résultats sont écrits sur la sortie standard.

Les options courtes sont les suivantes :

-s
Produit un document autonome (par exemple, un document HTML valide incluant le type de document, l'en-tête, etc.) autour du contenu formaté. Voir Documents autonomes pour les détails.
-M métadonnées
Fournit une seule paire clé-valeur de métadonnées. Celle-ci peut être dans la syntaxe normale ou sous forme de paires séparées par un signe égal, selon le caractère (un deux-points ou un signe égal) qui vient en premier. Se termine avec une erreur si aucune n'est donnée. Ceci remplace -m et ce qui est analysé à partir du document. Voir Métadonnées.
-m métadonnées
Similaire à -M, mais remplacé par ce qui est analysé à partir du document, puis par -M.
-o fichier
Envoie la sortie vers fichier sauf si c'est “-”, auquel cas on revient à la sortie standard par défaut.
-t mode, -T mode
Le mode de sortie. Il peut s'agir de html pour une sortie HTML5, latex pour du LaTeX, gemini pour le format "gemtext" de Gemini, ms pour une sortie roff utilisant le paquet classique (c'est-à-dire sans extension) -ms et nécessitant un support de tableaux, term pour une sortie terminale compatible ANSI et UTF-8, man pour une sortie roff utilisant le paquet classique -man, tree, pour afficher l'arbre d'analyse du document d'entrée, et null pour analyser le document mais sans le rendre. Voir Médias de sortie. La forme -T mode est conservée pour des raisons de compatibilité ascendante.
fichier_ancien, fichier_nouveau
Documents Markdown utilisés pour la comparaison. Si fichier_nouveau n'est pas donné ou est “-”, il est lu depuis l'entrée standard.

Documents autonomes

Lorsqu'on produit un document autonome, le modèle par défaut est utilisé pour le conteneur.

Pour le rendu HTML, le modèle par défaut est le suivant :

<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>TITLE</title>
</head>
<body>
BODY
</body>
</html>

Pour le rendu LaTeX, le modèle par défaut est le suivant :

\documentclass{article}
\usepackage[utf8]{inputenc}
\usepackage[T1]{fontenc}
\usepackage{amsmath}
\usepackage{amssymb}
\usepackage{longtable}
\usepackage{url}

\title{TITLE}
\date{}

\begin{document}
\maketitle

BODY

\end{document}

Pour le rendu Gemini, le modèle par défaut est le suivant :

BODY

Pour le rendu roff, les modèles par défaut sont les suivants :

.TH "TITLE" "SECTION" "DATE" "SOURCE" "VOLUME"
BODY

Pour le rendu terminal, le modèle par défaut est le suivant :

BODY

Pour l'arbre d'analyse, le modèle par défaut est le suivant :

BODY

Métadonnées

Les métadonnées sont des paires clé-valeur qui peuvent être utilisées pour fournir des informations sur le document. Elles peuvent être fournies via les options -m et -M, ou être analysées à partir du document lui-même.

La syntaxe d'analyse des métadonnées est la suivante :

Key: Value
Another Key: Another Value

Si une clé est spécifiée plusieurs fois, seule la dernière valeur est utilisée. Les métadonnées fournies via -M ont la priorité sur celles fournies via -m, qui ont elles-mêmes la priorité sur celles analysées à partir du document.

Les clés de métadonnées suivantes sont reconnues par défaut :

title
Le titre du document.
date
La date du document.
section
La section du document (pour les pages de manuel).
source
La source du document (pour les pages de manuel).
volume
Le volume du document (pour les pages de manuel).

Médias de sortie

Le mode de sortie détermine le format dans lequel le document est rendu. Les modes disponibles sont :

html
HTML5.
latex
LaTeX.
gemini
Gemini ("gemtext").
ms
roff avec le paquet -ms.
term
Sortie terminale compatible ANSI UTF-8.
man
roff avec le paquet -man.
tree
Arbre d'analyse.
null
Analyse seulement, pas de rendu.

Modèles

METADATA

Metadata are key-value pairs that may be supplied on the command line with -p, or in a metadata file using -m. They are used to customize the output.

Some metadata keys are automatically generated from the input document structure; others must be provided explicitly.

Keys are case-insensitive and are converted to lowercase for internal processing. The canonical form is the lowercase version of the key as it appears in the input, or as provided on the command line or metadata file.

author
The author of the document. Used in -thtml, -tlatex, -tman, and -tms.
baseheaderlevel
The base level for headers. For example, a value of 1 causes the original level 1 headers (“<h1>” in HTML, # in Markdown) to be output as level 1, and level 2 headers to be output as level 2, etc. A value of 2 causes original level 1 headers to be output as level 2, level 2 as level 3, etc. Headers will not move to levels less than 1. Used in -tfodt, -thtml, -tlatex, -tman, and -tms.
date
The date of the document. Used in -thtml, -tlatex, -tman, and -tms.
description
A short description of the document. Used in -thtml and -tman.
extensions
A list of extensions that are enabled for the current document. Used in -thtml.
javascript
A JavaScript file output in the HTML document head as a <script src="..."></script> statement. Multiple script files (in order) may be separated by two or more spaces (including newlines) and are output in the given order. Only used in -thtml.
lang
Document language in RFC 5646 format. Only used in -thtml.
latexheader
Arbitrary LaTeX content output in the document prologue immediately prior to the begin{document}. Only used in -tlatex and with -s. This metadata is not processed: it's passed unchanged into the output.
manheader
Arbitrary roff content output immediately prior to the .TH macro. Only used in -tman and with -s. This metadata is not processed: it's passed unchanged into the output.
msheader
Arbitrary roff content output immediately prior to the .TL macro. Only used in -tms and with -s. This metadata is not processed: it's passed unchanged into the output.
rcsauthor
Like author, but in RCS author format. Overrides author.
rcsdate
Like date, but in RCS date format. Overrides date.
section
Man page section, defaulting to “7”. Only used in -tman.
shiftheadinglevelby
Shift all headers by the given number. For example, a value of 1 causes headers originally at level 1 (“<h1>”) to be level 2 (“<h2>”), while a value of -1 moves level 2 to 1. Levels will not move to less than 1. Takes precedence over baseheaderlevel. If unset or not a valid number, defaults to zero. Used in -tfodt, -thtml, -tlatex, -tman, and -tms.
source
Man page source (organisation providing the manual). Only used in -tman.
volume
Man page volume (describes the manual page section). Only used in -tman.
title
Document title. Used in -tfodt, -thtml, -tlatex, -tman, -tms, and -tterm.

Default values, such “7” for the section, are not set as metadata values, and will not appear if the metadata key is used as a variable.

Templates

Some output media accept a template (--template) to customise standalone (-s) output. Parsed input content is filled into templates through control statements that support conditionals, loops, and variable transformation sequences.

Control statements are delimited as $statement$ or ${statement}. Arbitrary white-space may surround the case-insensitive statement between matching delimiters. Statements without a closing delimiter are considered opaque text.

The following statements are available:

$$, ${}
Output a literal $. This may contain arbitrary white-space.
$ifdef(expression)$
Conditional statement. There may not be any white-space between the ifdef and the opening parenthesis. Begins a block that is ended by a else, endif, or the end of file. Its contents are output only if expression evaluates to a non-empty string.
$else$
Begins a block that is ended by a endif or end of file. Its contents are output only if the condition of a preceding ifdef evaluates to an empty string. An else without a preceding ifdef is not output.
$endif$
Closes a block begin with ifdef or else. If not preceded by one of those statements, is silently ignored.
$for(expression)$
Looping statement. There may not be any white-space between the for and the opening parenthesis. Begins a block that is ended by an endfor or the end of file. Block contents contents are repeatedly output for each list item evaluated from expression. The anaphoric keyword this may be used to access the current loop expression within the block.
$expression$
Replaced by the result of evaluating a template expression.

If a control statement ends with two consecutive hyphens before the closing delimiter, input is consumed up to and including the next newline or until end of file. This allows for line-sensitive output media to use control statements without superfluous blank lines.

Expressions consist of

initial[([arg]*)]?[.transform[([arg]*)]?]*
,

or an initial value accepting optional arguments followed by an optional series of transforms accepting optional arguments. If an argument list is empty or not provided, it evaluates to an empty list.

The initial value is one of the following:

and(expression[,expression]*)
A non-empty list containing the value true if all expressions evaluate to non-empty lists, otherwise an empty list. An empty expression evaluates to an empty list.
"literal string"
Evaluates to a singleton list containing the string. An empty string evaluates to an empty list. The double quote character may be escaped, such as "foo\"bar".
body
The parsed input document body.
canonicalised metadata key
The value for the given metadata key, if found, otherwise an empty list.
body
The parsed input document body.
meta(key)
Produce the metadata value for the canonicalised metadata key. Allows for keys that are also keywords like body or endif.
not(expression)
A non-empty list containing the value true if the expression evaluates as an empty list, otherwise an empty list.
or(expression[,expression]*)
A non-empty list containing the value true if one expression evaluates to non-empty lists, otherwise an empty list. An empty expression evaluates to an empty list.
this
The value of a current loop context or an empty list.

If a metadata key is not specified in the input, or if the anaphoric this has not initialised by a looping context, the initial value evaluates to an empty list. Otherwise, the value is a singleton list.

If transforms are invalid, they will transform into an empty list.

The following transformations are available:

escapegemini, escapegeminiline
Escape list items for gemini (-tgemini), either for multiple lines or compressed to a single line.
escapehtml, escapehtmlattr, escapehtmlurl
Escape list items for HTML (-thtml) body content, attributes, and URL attributes, respectively.
escapelatex
Escape list items for LaTeX (-tlatex) body content.
escaperoff, escaperoffline
Escape list items for roff (-tm
s, -tman), soit pour plusieurs lignes, soit compressé en une seule ligne. escaperoff échappe également les délimiteurs roff initiaux et ceux après les sauts de ligne.
join
Joindre une liste en une liste singleton en utilisant deux espaces comme délimiteur de jointure.
lowercase
Mettre en minuscules tous les éléments de la liste.
split
Diviser les éléments de la liste sur des séquences de deux espaces blancs ou plus (espace, saut de ligne, tabulation). Ceci est généralement invoqué sur un singleton, mais peut être invoqué de manière répétée sur une liste déjà divisée. Invoque trim avant la première division. La liste résultante n'a pas d'éléments qui ne sont que des espaces blancs.
trim
Supprimer les espaces blancs du début et de la fin de tous les éléments de la liste. Si un élément n'a pas de caractères non blancs, il est supprimé.
uppercase
Mettre en majuscules tous les éléments de la liste.

ÉTAT DE SORTIE

L'utilitaire lowdown-diff se termine avec le statut 0 en cas de succès, et avec un statut supérieur à 0 si une erreur se produit.

EXEMPLES

Pour visualiser les différences Markdown sur un terminal compatible ANSI et UTF-8 :

lowdown-diff -tterm ancien.md nouveau.md | less -R

Le terminal peut également être utilisé avec le rendu de groff(1) :

lowdown-diff -stms ancien.md nouveau.md | \
  groff -itk -mspdf -Tutf8 | less -R
lowdown-diff -stman ancien.md nouveau.md | \
  groff -itk -man -Tutf8 | less -R

Pour générer un document HTML5 autonome :

lowdown-diff -s ancien.md nouveau.md > foo.html

Pour utiliser groff(1) pour formater en fichier PS :

lowdown-diff -stms ancien.md nouveau.md | \
  groff -itk -mspdf > foo.ps

Ou avec LaTeX :

lowdown-diff -stlatex ancien.md nouveau.md > foo.latex
pslatex foo.latex

La génération PDF suit une logique similaire :

lowdown-diff -stms ancien.md nouveau.md | \
  pdfroff -itk -mspdf > foo.pdf
lowdown-diff -stlatex ancien.md nouveau.md > foo.latex
pdflatex foo.latex

Le support UTF-8 pour la sortie PDF ou PS de groff(1) nécessite des polices appropriées, telles que la police Times Unicode. Celle-ci et d'autres polices Unicode ne sont pas toujours installées par défaut. Elles peuvent être trouvées, pour la sortie PDF, dans l'ensemble devpdf du répertoire des polices de groff(1) et sont préfixées par ‘U’.

lowdown-diff -stms ancien.md nouveau.md | \
  pdfroff -itk -mspdf -FU-T > foo.pdf
