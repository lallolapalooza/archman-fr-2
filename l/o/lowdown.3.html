NOM

lowdown — bibliothèque simple de traduction markdown

BIBLIOTHÈQUE

bibliothèque «liblowdown»

SYNTAXE

#include <sys/queue.h>
#include <stdio.h>
#include <lowdown.h>

struct lowdown_meta
struct lowdown_node
struct lowdown_opts

DESCRIPTION

Cette bibliothèque analyse lowdown(5) dans divers formats de sortie.

La bibliothèque se compose d'abord d'une interface de haut niveau constituée de lowdown_buf(3), lowdown_buf_diff(3), lowdown_file(3), et lowdown_file_diff(3).

Les fonctions de haut niveau interagissent avec des fonctions de bas niveau qui effectuent l'analyse et la mise en forme. Celles-ci comprennent lowdown_doc_new(3), lowdown_doc_parse(3), et lowdown_doc_free(3) pour analyser les documents lowdown(5) en un arbre syntaxique abstrait.

Les fonctions frontales pour la libération, l'allocation et le rendu sont les suivantes.

  • HTML5 :
    • lowdown_html_free(3)
    • lowdown_html_new(3)
    • lowdown_html_rndr(3)
  • gemini :
    • lowdown_gemini_free(3)
    • lowdown_gemini_new(3)
    • lowdown_gemini_rndr(3)
  • LaTeX :
    • lowdown_latex_free(3)
    • lowdown_latex_new(3)
    • lowdown_latex_rndr(3)
  • OpenDocument :
    • lowdown_odt_free(3)
    • lowdown_odt_new(3)
    • lowdown_odt_rndr(3)
  • roff :
    • lowdown_nroff_free(3)
    • lowdown_nroff_new(3)
    • lowdown_nroff_rndr(3)
  • Terminal UTF-8 :
    • lowdown_term_free(3)
    • lowdown_term_new(3)
    • lowdown_term_rndr(3)
  • débogage :
    • lowdown_tree_rndr(3)

Pour compiler et lier, utilisez pkg-config(1) :

% cc `pkg-config --cflags lowdown` -c -o sample.o sample.c
% cc -o sample sample.o `pkg-config --libs lowdown`

Promesses de Pledge

La bibliothèque lowdown est conçue pour fonctionner dans des environnements sensibles à la sécurité, tels que ceux utilisant pledge(2) sur OpenBSD. La seule promesse requise est stdio pour lowdown_file_diff(3) et lowdown_file(3) : les deux nécessitent l'accès au flux pour lire l'entrée.

TYPES

Toutes les fonctions lowdown utilisent une ou plusieurs des structures suivantes.

La structure principale pour la configuration de l'analyse et de la sortie est struct lowdown_opts. Elle a les champs suivants :

enum lowdown_type type
Le support de sortie :
LOWDOWN_HTML
HTML5
LOWDOWN_LATEX
LaTeX
LOWDOWN_MAN
Macros roff -man
LOWDOWN_FODT
OpenDocument “plat”
LOWDOWN_TERM
Sortie terminale compatible ANSI UTF-8
LOWDOWN_GEMINI
Format Gemini “gemtext”
LOWDOWN_NROFF
Macros roff -ms
LOWDOWN_TREE
Arbre syntaxique (débogage)
unsigned int feat
Fonctionnalités d'analyse. Ce champ de bits peut avoir les bits suivants OR'dés :
LOWDOWN_ATTRS
Analyser les attributs supplémentaires de lien, d'en-tête et d'image PHP.
LOWDOWN_AUTOLINK
Analyser les liens http, https, ftp, mailto, et les liens relatifs ou fragments de liens.
LOWDOWN_CALLOUTS
Analyser les appels (“admonitions”) MDN/GFM.
LOWDOWN_COMMONMARK
Resserrer l'analyse de l'entrée selon la spécification CommonMark. Ceci utilise également la première valeur de liste ordonnée au lieu de commencer toutes les listes à un. Cette fonctionnalité est expérimentale et incomplète.
LOWDOWN_DEFLIST
Analyser les listes de définition supplémentaires PHP. Ceci est actuellement limité aux listes à clé unique.
LOWDOWN_FENCED
Analyser les blocs de code GFM clôturés (spécifiques au langage).
LOWDOWN_FOOTNOTES
Analyser les notes de bas de page style MMD. Ceci ne supporte que le style de note de bas de page référencé, pas le style “en ligne”.
LOWDOWN_HILITE
Analyser les séquences mises en évidence. Celles-ci sont désactivées par défaut car elles peuvent être interprétées à tort comme des en-têtes de section.
LOWDOWN_IMG_EXT
Obsolète. Utiliser LOWDOWN_ATTRS à la place.
LOWDOWN_MANTITLE
Reconnaître ma
n de titres de pages dans les lignes de métadonnées de Pandoc. Applicable uniquement si LOWDOWN_METADATA est également fourni. Les titres des pages de manuel doivent commencer par un titre non vide suivi d'une parenthèse ouvrante, d'un chiffre ou de « n », de lettres optionnelles ensuite, puis d'une parenthèse fermante. Ceci peut être facultativement suivi d'une source et, si une barre verticale est détectée, du contenu après comme volume. Ceux-ci sont transmis aux rendeurs comme les paires clé-valeur de métadonnées title, volume, et facultativement source et volume. Le titre original n'est pas récupérable.
LOWDOWN_MATH
Analyser les équations mathématiques.
LOWDOWN_METADATA
Analyser les métadonnées dans le document.
LOWDOWN_NOCODEIND
Ne pas analyser le contenu indenté comme des blocs de code.
LOWDOWN_NOINTEM
Ne pas analyser l'emphase au sein des mots.
LOWDOWN_STRIKE
Analyser les séquences de barré.
LOWDOWN_SUPER
Analyser les super-scripts. Ceci accepte les super-scripts GFM foo^bar^.
LOWDOWN_SUPER_SHORT
Si LOWDOWN_SUPER est activé, au lieu du style GFM, accepter la forme « courte » de super-script. Ceci accepte foo^bar, qui met les parties suivant le caret jusqu'à un espace en super-scripts ; ou foo^(bar), qui met uniquement les parties entre parenthèses.
LOWDOWN_TABLES
Analyser les tableaux GFM.
LOWDOWN_TASKLIST
Analyser les éléments de liste de tâches GFM.
unsigned int oflags
Fonctionnalités au moment de la sortie. Les valeurs binaires sont spécifiques au type et ne sont pas garanties d'être globalement uniques.

Pour tous les types :

LOWDOWN_SMARTY
Ne pas utiliser la typographie intelligente.
LOWDOWN_STANDALONE
Émettre un document complet au lieu d'un fragment de document. Cet enveloppe est largement remplie à partir des métadonnées si LOWDOWN_METADATA a été fourni comme option ou comme donné dans meta ou metaovr.

Pour LOWDOWN_HTML :

LOWDOWN_HTML_CALLOUT_MDN, LOWDOWN_HTML_CALLOUT_GFM
Émettre la syntaxe de notification de style MDN et/ou GFM.
LOWDOWN_HTML_ESCAPE
Si LOWDOWN_HTML_SKIP_HTML n'a pas été défini, échapper le HTML dans le document afin qu'il soit rendu comme du texte opaque.
LOWDOWN_HTML_HARD_WRAP
Conserver les sauts de ligne dans les paragraphes.
LOWDOWN_HTML_HEAD_IDS
Avoir un identifiant écrit avec chaque élément d'en-tête composé d'une version échappée en HTML du contenu de l'en-tête.
LOWDOWN_HTML_NUM_ENT
Convertir, lorsque possible, les entités HTML en leur forme numérique. Si non défini, les entités sont utilisées telles quelles dans l'entrée.
LOWDOWN_HTML_OWASP
Lors de l'échappement de texte, être extra prudent en suivant les suggestions OWASP pour les caractères à échapper.
LOWDOWN_HTML_SKIP_HTML
Ne pas rendre du tout le HTML dans le document.
LOWDOWN_HTML_TITLEBLOCK
Émettre un bloc de titre de style Pandoc. Il s'agit d'un élément <header id="title-block-header"> juste après le <body> ouvrant contenant des éléments pour le titre, l'auteur(s) et la date spécifiés. Ce sont des éléments <h1> et <p>, respectivement, avec des classes définies selon ce qui est émis (titre, etc.). Au moins l'un d'entre eux doit être spécifié pour que le bloc de titre soit émis.

Pour LOWDOWN_GEMINI, il existe plusieurs options pour contrôler le placement des liens. Par défaut, les liens (images, autolinks et liens) sont mis en file d'attente lorsqu'ils sont spécifiés en ligne, puis émis dans une séquence de blocs après le nœud de bloc le plus proche. (Voir ARBRE SYNTAXIQUE ABSTRAIT.)

LOWDOWN_GEMINI_LINK_END
Émettre la file d'attente des liens à la fin du document au lieu de après le nœud de bloc le plus proche.
LOWDOWN_GEMINI_LINK_IN
Rendre tous les liens dans le flux de texte. Cela entraînera des erreurs lorsque les liens sont imbriqués, comme des images dans des liens, des liens dans des blocs de citation, etc. Il ne doit pas être utilisé sauf dans des documents soigneusement élaborés.
LOWDOWN_GEMINI_LINK_NOREF
Ne pas formater les libellés de liens. Prend la priorité sur LOWDOWN_GEMINI_LINK_ROMAN.
LOWDOWN_GEMINI_LINK_ROMAN
Lors du formatage des libellés de liens, utiliser des chiffres romains en minuscules au lieu de l'hexavigésimal en minuscules par défaut (c'est-à-dire « a », « b », ..., « aa », « ab », ...).
LOWDOWN_GEMINI_METADATA
Afficher les métadonnées sous forme de clé canonique suivie de deux points puis de la valeur, chacune sur une ligne (les sauts de ligne sont remplacés par des espaces). Le bloc de métadonnées est terminé par un double saut de ligne. S'il n'y a pas de métadonnées, cela ne fait rien.

Il ne peut y avoir qu'une seule option parmi LOWDOWN_GEMINI_LINK_END ou LOWDOWN_GEMINI_LINK_IN. Si les deux sont spécifiées, la dernière est désactivée.

Pour LOWDOWN_FODT :

LOWDOWN_ODT_SKIP_HTML
Ne pas rendre du tout le HTML dans le document. Le texte à l'intérieur des éléments HTML reste.

Pour LOWDOWN_LATEX :

LOWDOWN_LATEX_NUMBERED
Utiliser le schéma de numérotation par défaut pour les sections, sous-sections, etc. Si non spécifié, celles-ci sont inhibées.
LOWDOWN_LATEX_SKIP_HTML
Ne pas rendre du tout le HTML dans le document. Le texte à l'intérieur des éléments HTML reste.

Pour LOWDOWN_MAN et LOWDOWN_NROFF :

LOWDOWN_NROFF_GROFF
Utiliser les extensions GNU (c'est-à-dire pour groff(1)) lors du rendu de la sortie. Les arguments groff doivent inclure -mpdfmark pour formater les liens avec LOWDOWN_MAN ou -mspdf au lieu de -ms pour LOWDOWN_NROFF. S'applique aux types de sortie LOWDOWN_MAN et LOWDOWN_NROFF.
LOWDOWN_NROFF_NOLINK
Ne pas afficher du tout les liens s'ils ont du texte intégré. S'applique aux images et aux liens réguliers. Uniquement dans LOWDOWN_MAN ou lorsque LOWDOWN_NROFF_GROFF n'est pas spécifié.
LOWDOWN_NROFF_NUMBERED
Utiliser des sections numérotées si LOWDOWON_NROFF_GROFF n'est pas spécifié. S'applique uniquement au type de sortie LOWDOWN_NROFF.
LOWDOWN_NROFF_SHORTLINK
Rendre les URL de liens sous forme courte. S'applique aux images, aux autolinks et aux liens réguliers. Uniquement dans LOWDOWN_MAN ou lorsque LOWDOWN_NROFF_GROFF n'est pas spécifié.
LOWDOWN_NROFF_SKIP_HTML
Ne pas rendre du tout le HTML dans le document. Le texte à l'intérieur des éléments HTML reste.

Pour LOWDOWN_TERM :

LOWDOWN_TERM_ALL_META
Si LOWDOWN_STANDALONE ode> est spécifié, afficher toutes les métadonnées au lieu de seulement le titre, l'auteur et la date.
LOWDOWN_TERM_NOANSI
Ne pas appliquer du tout les codes de style ANSI. Ceci implique LOWDOWN_TERM_NOCOLOUR.
LOWDOWN_TERM_NOCOLOUR
Ne pas appliquer les codes de couleur ANSI. Cela affichera toujours le soulignement, le gras, etc. Ceci ne doit pas être utilisé en mode différence, car la sortie n'aura aucun sens.
LOWDOWN_TERM_NOLINK
Ne pas afficher les liens du tout. S'applique aux images et aux liens réguliers : les auto-liens sont toujours affichés. Ceci peut être combiné avec LOWDOWN_TERM_SHORTLINK pour également raccourcir les auto-liens.
LOWDOWN_TERM_NORELLINK
Similaire à LOWDOWN_TERM_NOLINK, mais uniquement pour les liens relatifs.
LOWDOWN_TERM_SHORTLINK
Afficher les URL des liens sous forme courte. S'applique aux images, aux auto-liens et aux liens réguliers. Ceci peut être combiné avec LOWDOWN_TERM_NOLINK pour n'afficher que les auto-liens raccourcis.
size_t maxdepth
La profondeur de parsing maximale avant que le parser ne s'arrête. La plupart des documents auront une profondeur de parsing à un chiffre.
struct lowdown_opts_nroff nroff
Si type est LOWDOWN_MAN ou LOWDOWN_NROFF, ceci contient les variantes de police à chasse fixe : const char *cr pour la chasse fixe romaine, const char *cb pour le gras, const char *ci pour l'italique, et const char *cbi pour le gras-italique. Si l'un de ceux-ci est NULL, ils utilisent par défaut leurs variantes à chasse fixe.
struct lowdown_opts_odt odt
Si type est LOWDOWN_FODT, ceci contient const char *sty, qui est soit NULL, soit les styles OpenDocument utilisés lors de la création de documents autonomes. Si NULL, les styles par défaut sont utilisés.
struct lowdown_opts_term term
Si type est LOWDOWN_TERM, ceci contient size_t cols, le nombre non nul de colonnes dans le terminal ; size_t width, la largeur de contenu demandée ou zéro pour automatique ; size_t hmargin, la largeur de la marge gauche ; size_t hpadding, la largeur du padding gauche empiétant sur width ; size_t vmargin, la marge verticale en lignes ; et int centre si le contenu doit être centré (hmargin est ignoré).
char **meta
Un tableau de paires clé-valeur de métadonnées ou NULL. Chaque paire doit apparaître comme si elle était fournie sur une ligne (ou plusieurs lignes) de l'entrée, y compris le caractère de nouvelle ligne de terminaison. Si elle ne consiste pas en une paire valide (par exemple, pas de nouvelle ligne, pas de deux-points), alors elle est ignorée. Lors du traitement, ces valeurs sont remplacées par celles du document (si LOWDOWN_METADATA est spécifié) ou par celles de metaovr.
size_t metasz
Nombre de paires dans metaovr.
char **metaovr
Voir meta. La différence est que metaovr est appliqué après meta et les métadonnées dans le document, il donc remplace les valeurs précédentes.
size_t metaovrsz
Nombre de paires dans metaovr.
const char *templ
Si LOWDOWN_STANDALONE est spécifié, ceci est défini sur le fichier de modèle externe ou NULL pour utiliser le templating interne. Ceci n'est valide que pour les médias de sortie supportant les modèles externes ; sinon, cela peut être ignoré.

Les métadonnées parsées sont stockées dans des paires struct lowdown_meta clé-valeur, ou collectivement sous forme de struct lowdown_metaq, si LOWDOWN_METADATA est défini dans feat. La première structure se compose des champs suivants :

char *key
La clé de métadonnée dans sa forme canonique : alphanumériques en minuscules, tiret et underscore. Les espaces sont supprimés et les autres caractères remplacés par un point d'interrogation.
char *value
La valeur de la métadonnée. Ceci peut être une chaîne vide.

Le type de nœud, en utilisant la sortie HTML5 comme illustration :
LOWDOWN_BLOCKCODE
Un extrait de code de niveau bloc décrit par <pre><code>.
LOWDOWN_BLOCKHTML
Un extrait HTML de niveau bloc. Ceci est simplement du contenu HTML opaque.
LOWDOWN_BLOCKQUOTE
Une citation de niveau bloc décrite par <blockquote>.
LOWDOWN_CODESPAN
Un extrait de code de niveau inline décrit par <code>.
LOWDOWN_DEFINITION
Une liste de définitions décrite par <dl>.
LOWDOWN_DEFINITION_DATA
Données de définition décrites par <dd>.
LOWDOWN_DEFINITION_TITLE
Titre de définition décrit par <dt>.
LOWDOWN_DOC_HEADER
Conteneur pour les métadonnées décrites par <head>.
LOWDOWN_DOUBLE_EMPHASIS
Contenu en gras (ou autrement notable) décrit par <strong>.
LOWDOWN_EMPHASIS
Contenu en italique (ou autrement notable) décrit par <em>.
LOWDOWN_ENTITY
Entité HTML nommée ou numérique.
LOWDOWN_FOOTNOTE
Contenu de note de bas de page.
LOWDOWN_HEADER
Un en-tête de niveau bloc décrit par l'un de <h1> à <h6>.
LOWDOWN_HIGHLIGHT
Texte marqué décrit par <mark>.
LOWDOWN_HRULE
Une ligne horizontale décrite par <hr>.
LOWDOWN_IMAGE
Une image décrite par <img>.
LOWDOWN_LINEBREAK
Un saut de ligne forcé dans un contexte de bloc décrit par <br>.
LOWDOWN_LINK
Un lien vers des médias externes décrit par <a>. Les liens peuvent contenir une balise enfant limitée, mais pas de liens imbriqués.
LOWDOWN_LINK_AUTO
Similaire à LOWDOWN_LINK, sauf qu'il est inféré du contenu textuel.
LOWDOWN_LIST
Une clôture de liste décrite par <ul> ou <ol>.
LOWDOWN_LISTITEM
Un élément de liste décrit par <li>.
LOWDOWN_MATH_BLOCK
Un extrait de texte mathématique au format LaTeX décrit dans \[xx\] ou \(xx\). Ceci est généralement (en HTML) géré extérieurement par un moteur de rendu JavaScript.
LOWDOWN_META
Clés et valeurs de métadonnées. Celles-ci sont décrites par des éléments dans <head>.
LOWDOWN_NORMAL_TEXT
Contenu textuel normal.
LOWDOWN_PARAGRAPH
Un paragraphe de niveau bloc décrit par <p>.
LOWDOWN_RAW_HTML
Un élément inline de HTML brut. (Uniquement si configuré lors du parsing.)

LOWDOWN_NODE_TYPE

LOWDOWN_ROOT
La racine du document. C'est toujours le nœud le plus haut, et le seul nœud où le champ parent est NULL.
LOWDOWN_STRIKETHROUGH
Contenu barré. Décrit par <del>.
LOWDOWN_SUBSCRIPT, LOWDOWN_SUPERSCRIPT
Un indice ou un exposant décrit par <sub> ou <sup>, respectivement.
LOWDOWN_TABLE_BLOCK
Un bloc de tableau décrit par <table>.
LOWDOWN_TABLE_BODY
Une section de corps de tableau décrite par <tbody>.
LOWDOWN_TABLE_CELL
Une cellule de tableau décrite par <td>, ou <th> si elle se trouve dans l'en-tête.
LOWDOWN_TABLE_HEADER
Une section d'en-tête de tableau décrite par <thead>.
LOWDOWN_TABLE_ROW
Une ligne de tableau décrite par <tr>.
LOWDOWN_TRIPLE_EMPHASIS
Combinaison de LOWDOWN_EMPHASIS et LOWDOWN_DOUBLE_EMPHASIS.
size_t id
Un identifiant unique dans le document. Peut être utilisé comme indice de tableau car le nombre est attribué à partir d'un point d'incrémentation monotone pendant l'analyse.
struct lowdown_node *parent
Le parent du nœud, ou NULL à la racine.
enum lowdown_chng chng
Suivi des modifications : si ce nœud a été inséré (LOWDOWN_CHNG_INSERT), supprimé (LOWDOWN_CHNG_DELETE), ou aucun (LOWDOWN_CHNG_NONE).
struct lowdown_nodeq children
Une liste potentiellement vide de nœuds enfants.
<anon union>
Une union anonyme de structures spécifiques au type.
rndr_autolink
Pour LOWDOWN_LINK_AUTO, l'adresse du lien sous forme de link et le type de lien type, qui peut être l'une des valeurs HALINK_EMAIL pour les liens d'e-mail et HALINK_NORMAL sinon. Tout tampon peut avoir une taille nulle.
rndr_blockcode
Pour LOWDOWN_BLOCKCODE, le texte opaque text du bloc et le langage optionnel lang du code.
rndr_blockhtml
Pour LOWDOWN_BLOCKHTML, le texte HTML opaque text.
rndr_codespan
Le texte opaque text du contenu.
rndr_definition
Pour LOWDOWN_DEFINITION, contenant des flags qui peuvent être HLIST_FL_BLOCK si la liste de définitions doit être interprétée comme contenant des nœuds de bloc.
rndr_entity
Pour LOWDOWN_ENTITY, le texte de l'entité text.
rndr_header
Pour LOWDOWN_HEADER, le niveau level de l'en-tête commençant à zéro (cette valeur est relative au niveau d'en-tête de base des métadonnées, par défaut à un), une liste de classes optionnelle séparée par des espaces attr_cls, et un identifiant unique optionnel attr_id.
rndr_image
Pour LOWDOWN_IMAGE, l'adresse de l'image link, le titre de l'image title, les dimensions NxN (largeur par hauteur) dans dims, et le texte alternatif alt. Le style CSS en ligne pour la largeur et la hauteur peut être donné dans attr_width et/ou attr_height, et une liste de classes séparées par des espaces peut être dans attr_cls et un identifiant unique peut être dans attr_id.
rndr_link
Similaire à rndr_autolink, mais sans type et définissant en outre un titre de lien optionnel title, une liste de classes optionnelle séparée par des espaces attr_cls, et un identifiant unique optionnel attr_id.
rndr_list
Pour LOWDOWN_LIST, consiste en un champ de bits flags qui peut être défini à HLIST_FL_ORDERED pour une liste ordonnée et HLIST_FL_UNORDERED pour une liste non ordonnée. Si HLIST_FL_BLOCK est défini, la liste doit être sortie comme si les éléments étaient des blocs séparés. La valeur start pour HLIST_FL_ORDERED est la position de départ de l'élément de liste, qui est un par défaut et jamais zéro. Le nombre items est le nombre d'éléments de liste.
rndr_listitem
Pour LOWDOWN_LISTITEM, consiste en un champ de bits flags qui peut être défini à HLIST_FL_ORDERED pour une liste ordonnée, HLIST_FL_UNORDERED pour une liste non ordonnée, HLIST_FL_DEF pour les données de liste de définition, HLIST_FL_CHECKED ou HLIST_FL_UNCHECKED pour une liste non ordonnée de « tâches », et/ou HLIST_FL_BLOCK pour la sortie d'élément de liste comme s'il contenait des nœuds de bloc. HLIST_FL_BLOCK ne doit pas être utilisé : utilisez les drapeaux de la liste parente (ou de la liste de définition) pour cela. Le num est l'index dans une liste HLIST_FL_ORDERED. Il est strictement croissant avec chaque élément de la liste, en commençant à la variable start donnée dans la struct rndr_list.
rndr_math
Pour LOWDOWN_MATH, le mode d'affichage dans blockmode : si 1, math en ligne ; si 2, multi-lignes. L'équation opaque, supposée être au format LaTeX, se trouve dans text opaque.
rndr_meta
Chaque paire clé-valeur LOWDOWN_META est représentée. Les clés sont en minuscules, sans espaces ni caractères non ASCII. Si elles sont fournies, les nœuds englobés peuvent uniquement consister en LOWDOWN_NORMAL_TEXT et LOWDOWN_ENTITY.
rndr_normal_text
Le texte de base text pour LOWDOWN_NORMAL_TEXT. Si flags est défini à HTEXT_ESCAPED, le texte peut être échappé pour la sortie, mais ne peut pas être modifié par une typographie intelligente ou similaire (il doit être passé tel quel).
rndr_paragraph
Pour LOWDOWN_PARAGRAPH, indique combien de lines le paragraphe a dans le fichier d'entrée et beoln, mis à non nul si le paragraphe se termine par une ligne vide au lieu d'un nœud de bloc de rupture.
rndr_raw_html
Pour LOWDOWN_RAW_HTML, le texte HTML opaque text.
rndr_table
Pour LOWDOWN_TABLE_BLOCK, le nombre de columns dans chaque ligne ou ligne d'en-tête. Le nombre de colonnes dans rndr_table, rndr_table_header, et rndr_table_cell sont les mêmes.
rndr_table_cell
Pour LOWDOWN_TABLE_CELL, le numéro de colonne col actuel sur le total de columns. Voir rndr_table_header pour une description des bits dans flags. Le nombre de colonnes dans rndr_table, rndr_table_header, et rndr_table_cell sont les mêmes.
rndr_table_header
Pour LOWDOWN_TABLE_HEADER, le nombre de columns dans chaque ligne et les flags par colonne, qui peuvent être testés pour égalité avec HTBL_FL_ALIGN_LEFT, HTBL_FL_ALIGN_RIGHT, ou HTBL_FL_ALIGN_CENTER après avoir été masqués avec HTBL_FL_ALIGNMASK ; ou HTBL_FL_HEADER. Si aucun alignement n'est spécifié après le masque, l'alignement par défaut est à gauche. Le nombre de colonnes dans rndr_table, rndr_table_header, et rndr_table_cell sont les mêmes.

La structure générale de l'AST est la suivante. Les nœuds n'ont pas d'ordre imposé, sauf indication contraire :

  • LOWDOWN_ROOT (ordonné)
    • LOWDOWN_DOC_HEADER
      • LOWDOWN_META
        • LOWDOWN_ENTITY
        • LOWDOWN_NORMAL_TEXT
    • (zéro ou plusieurs nœuds de bloc)

Les nœuds spéciaux ont un placement spécifique au sein de leurs parents comme suit :

  • LOWDOWN_DEFINITION (une ou plusieurs paires ordonnées de...)
    • LOWDOWN_DEFINITION_TITLE
      • (nœuds inline)
    • LOWDOWN_DEFINITION_DATA
      • (nœuds de bloc)
  • LOWDOWN_HEADER
    • (nœuds inline)
  • LOWDOWN_LIST
    • LOWDOWN_LISTITEM
      • (nœuds inline ou de bloc, selon le cas)
  • LOWDOWN_TABLE_BLOCK (ordonné)
    • LOWDOWN_TABLE_HEADER (zéro ou plus...)
      • LOWDOWN_TABLE_ROW (un ou plusieurs...)
        • LOWDOWN_TABLE_CELL
          • (nœuds inline)
    • LOWDOWN_TABLE_BODY (zéro ou plus...)
      • LOWDOWN_TABLE_ROW (un ou plusieurs...)
        • LOWDOWN_TABLE_CELL
          • (nœuds inline)

Enfin, LOWDOWN_FOOTNOTE peut apparaître n'importe où dans le document et contient des nœuds de bloc.
