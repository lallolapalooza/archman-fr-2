NOM

loggen --- Génère des messages syslog à un rythme spécifié

SYNOPSIS

loggen [options]

cible [port]

DESCRIPTION

NOTE : L'application loggen est distribuée avec l'application de journalisation système syslog-ng OSE, et fait généralement partie du paquet syslog-ng OSE. La dernière version de l'application syslog-ng OSE est disponible sur la page syslog-ng OSE.

Cette page de manuel n'est qu'un résumé.

L'application loggen est un outil pour tester et soumettre à rude épreuve votre serveur syslog et la connexion au serveur. Elle peut envoyer des messages syslog au serveur à un rythme spécifié en utilisant un certain nombre de types de connexion et de protocoles, y compris TCP, UDP et les sockets de domaine Unix. Les messages peuvent être générés automatiquement (en répétant la chaîne PADD encore et encore), ou lus à partir d'un fichier ou de l'entrée standard.

Lorsque loggen a fini d'envoyer les messages, il affiche les statistiques suivantes :

  • taux moyen : Le taux moyen des messages envoyés en messages/seconde.
  • nombre : Le nombre total de messages envoyés.
  • temps : Le temps nécessaire pour envoyer les messages en secondes.
  • taille moyenne des messages : La taille moyenne des messages envoyés en octets.
  • bande passante : La bande passante moyenne utilisée pour envoyer les messages en kilo-octets/seconde.

OPTIONS

•
--active-connections <nombre-de-connexions>

Nombre de connexions que loggen utilisera pour envoyer des messages à la destination. Cette option n'est utilisable qu'en utilisant des connexions TCP ou TLS vers la destination. Valeur par défaut : 1

L'utilitaire loggen attend que toutes les connexions soient établies avant de commencer à envoyer des messages. Voir aussi l'option --idle-connections.

•
--csv ou -C

Envoyer les statistiques des messages envoyés à la sortie standard au format CSV. Ceci peut être utilisé pour tracer le taux de messages.

•
--dgram ou -D

Utiliser un socket datagramme (UDP ou unix-dgram) pour envoyer les messages à la cible. Nécessite également l'option --inet.

•
dont-parse ou -d

Ne pas analyser les lignes lues à partir des fichiers d'entrée, les envoyer telles que reçues.

•
--help ou -h

Afficher un bref message d'aide.

•
--idle-connection <nombre-de-connexions>

Nombre de connexions inactives que loggen établira vers la destination. Notez que loggen n'enverra aucun message sur les connexions inactives, mais la connexion est maintenue ouverte à l'aide de messages keep-alive. Cette option n'est utilisable qu'en utilisant des connexions TCP ou TLS vers la destination. Voir aussi l'option --active-connections. Valeur par défaut : 0

•
--inet ou -i

Utiliser le protocole TCP (par défaut) ou UDP (lorsqu'il est utilisé avec l'option --dgram) pour envoyer les messages à la cible.

•
--interval <secondes> ou -I <secondes>

Le nombre de secondes pendant lesquelles loggen s'exécutera. Valeur par défaut : 10

NOTE : Lorsque --interval et --number sont utilisés ensemble, loggen enverra des messages jusqu'à ce que la période définie dans --interval expire ou que le nombre de messages défini dans --number soit atteint, selon la première éventualité.

•
--ipv6 ou -6

Spécifier la destination en utilisant son adresse IPv6. Notez que la destination doit avoir une adresse IPv6 réelle.

•
--loop-reading ou -l

Lire le fichier spécifié dans l'option --read-file en boucle : loggen recommencera la lecture depuis le début du fichier lorsqu'il atteindra la fin du fichier.

•
--number <nombre-de-messages> ou -n <nombre-de-messages>

Nombre de messages à générer.

NOTE : Lorsque --interval et --number sont utilisés ensemble, loggen enverra des messages jusqu'à ce que la période définie dans --interval expire ou que le nombre de messages défini dans --number soit atteint, selon la première éventualité.

•
--no-framing ou -F

Ne pas utiliser l'encapsulation du style de protocole IETF-syslog, même si l'option --syslog-proto est définie.

•
--quiet ou -Q

Afficher les statistiques uniquement lorsque loggen a terminé. Si non défini, les statistiques sont affichées toutes les secondes.

•
--permanent ou -T

Continuer à envoyer des journaux indéfiniment, sans limite de temps.

•
--rate <message/seconde> ou -r <message/seconde>

Le nombre de messages générés par seconde pour chaque connexion active. Valeur par défaut : 1000

Si vous souhaitez modifier le taux de messages pendant que loggen s'exécute, envoyez SIGUSR1 pour doubler le taux de messages, ou SIGUSR2 pour le diviser par deux :

kill -USR1 <pid-loggen>kill -USR2 <pid-loggen>

•
--read-file <nom-de-fichier> ou -R <nom-de-fichier>

Lire les messages à partir d'un fichier et les envoyer à la cible. Voir aussi l'option --skip-tokens.

Spécifiez - comme fichier d'entrée pour lire les messages depuis l'entrée standard (stdio). Notez que lors de la lecture de messages depuis l'entrée standard, loggen ne peut utiliser qu'un seul thread. Les paramètres -R - doivent être placés à la fin de la commande, comme ceci : loggen 127.0.0.1 1061 --read-file -

•
--sdata <données-à-envoyer> ou -p <données-à-envoyer>

Envoyer l'argument de l'option --sdata comme partie SDATA des messages IETF-syslog (format RFC-5424). Utilisez-le conjointement avec l'option --syslog-proto. Par exemple : --sdata \"[test name=\\\"value\\\"]

•
--size <taille-message> ou -s <taille-message>

La taille d'un message syslog en octets. Valeur par défaut : 256. Valeur minimale : 127 octets, valeur maximale : 8192 octets.

•
--skip-tokens <nombre>

Ignorer le nombre spécifié de jetons (mots) séparés par des espaces au début de chaque ligne. Par exemple, si les messages dans le fichier ressemblent à foo bar message, --skip-tokens 2 ignore la partie foo bar de la ligne et n'envoie que la partie message. Ne fonctionne que lorsqu'il est utilisé conjointement avec le paramètre --read-file. Valeur par défaut : 0

•
--stream ou -S

Utiliser un socket de flux (TCP ou unix-stream) pour envoyer les messages à la cible.

•
--syslog-proto ou -P

Utiliser le nouveau format de message IETF-syslog. Par défaut, loggen utilise le format de message syslog BSD hérité. Voir aussi l'option --no-framing.

•
--unix </chemin/vers/socket> ou -x </chemin/vers/socket>

Utiliser un socket de domaine UNIX pour envoyer les messages à la cible.

•
--use-ssl ou -U

Utiliser un canal crypté SSL pour envoyer les messages à la cible. Notez qu'il n'est pas possible de vérifier le certificat de la cible, ni d'effectuer une authentification mutuelle.

•
--version ou -V

Afficher le numéro de version de syslog-ng.

EXEMPLES

La commande suivante génère 100 messages par seconde pendant dix minutes et les envoie au port 2010 de localhost via TCP. Chaque message a une taille de 300 octets.

loggen --size 300 --rate 100 --interval 600 127.0.0.1 2010

La commande suivante est similaire à la précédente, mais utilise le protocole UDP.

loggen --inet --dgram --size 300 --rate 100 --interval 600 127.0.0.1 2010

Envoyer un seul message sur TCP6 à l'adresse IPv6 ::1, port 1061 :

loggen --ipv6 --number 1 ::1 1061

Envoyer un seul message sur UDP6 à l'adresse IPv6 ::1, port 1061 :

loggen --ipv6 --dgram --number 1 ::1 1061

Envoyer un seul message en utilisant un socket de domaine Unix :

loggen --unix --stream --number 1 </chemin/vers/socket>

Lire les messages depuis l'entrée standard (stdio) et les envoyer à localhost

:

loggen 127.0.0.1 1061 --read-file -

Fichiers

/usr/bin/loggen
