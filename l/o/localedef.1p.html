LOCALEDEF(1P) Manuel du programmeur POSIX LOCALEDEF(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

localedef — définir l'environnement de locale

SYNTAXE

localedef [-c] [-f charmap] [-i sourcefile] [-u code_set_name] nom

DESCRIPTION

L'utilitaire localedef convertit les définitions sources pour les catégories de locale dans un format utilisable par les fonctions et utilitaires dont le comportement opérationnel est déterminé par le réglage des variables d'environnement de locale définies dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 7, Locale. Il est défini par l'implémentation si les utilisateurs ont la capacité de créer de nouvelles locales, en plus de celles fournies par l'implémentation. Si la constante symbolique POSIX2_LOCALEDEF est définie, le système prend en charge la création de nouvelles locales. Sur les systèmes conformes XSI, la constante symbolique POSIX2_LOCALEDEF doit être définie.

L'utilitaire lit les définitions sources pour une ou plusieurs catégories de locale appartenant à la même locale depuis le fichier nommé dans l'option -i (si spécifié) ou depuis l'entrée standard.

L'opérande nom identifie la locale cible. L'utilitaire prend en charge la création de locales publiques, ou accessibles généralement, ainsi que de locales privées, ou à accès restreint. Les implémentations peuvent restreindre la capacité de créer ou modifier des locales publiques aux utilisateurs disposant des privilèges appropriés.

Chaque définition source de catégorie est identifiée par le nom de la variable d'environnement correspondante et terminée par une instruction END nom-de-catégorie. Les catégories suivantes sont prises en charge. De plus, l'entrée peut contenir des sources pour des catégories définies par l'implémentation.

LC_CTYPE
Définit la classification des caractères et la conversion des casse.
LC_COLLATE

Définit les règles de collation.
LC_MONETARY

Définit le format et les symboles utilisés dans le formatage des informations monétaires.
LC_NUMERIC

Définit le délimiteur décimal, le groupement et le symbole de groupement pour l'édition numérique non monétaire.
LC_TIME
Définit le format et le contenu des informations de date et d'heure.
LC_MESSAGES

Définit le format et les valeurs des réponses affirmatives et négatives.

OPTIONS

L'utilitaire localedef est conforme au volume des Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes sont prises en charge :

-c
Crée une sortie permanente même si des messages d'avertissement ont été émis.
-f charmap
Spécifie le chemin d'un fichier contenant un mappage de symboles de caractères et de symboles d'éléments de collation vers des encodages de caractères réels. Le format du charmap est décrit dans le volume des Définitions de base de POSIX.1‐2017, Section 6.4, Fichier de description de jeu de caractères. L'application doit s'assurer que cette option est spécifiée si des noms symboliques (autres que les symboles de collation définis dans un mot-clé collating-symbol) sont utilisés. Si l'option -f est absente, un mappage de caractères défini par l'implémentation est utilisé.
-i inputfile
Le chemin d'un fichier contenant les définitions sources. Si cette option est absente, les définitions sources sont lues depuis l'entrée standard. Le format du inputfile est décrit dans le volume des Définitions de base de POSIX.1‐2017, Section 7.3, Définition de Locale.
-u code_set_name

Spécifie le nom d'un jeu de codes utilisé comme mappage cible des symboles de caractères et des symboles d'éléments de collation dont les valeurs d'encodage sont définies en termes de valeurs constantes de position de la norme ISO/IEC 10646‐1:2000.

OPERANDES

L'opérande suivant est pris en charge :

nom
Identifie la locale ; voir le volume des Définitions de base de POSIX.1‐2017, Chapitre 7, Locale pour une description de l'utilisation de ce nom. Si le nom contient un ou plusieurs caractères <slash>, nom est interprété comme un chemin où les définitions de locale créées doivent être stockées. Si nom ne contient aucun caractère <slash>, l'interprétation du nom est définie par l'implémentation et la locale est publique. La capacité de créer des locales publiques de cette manière peut être restreinte aux utilisateurs disposant des privilèges appropriés. (En conséquence de la spécification d'un seul nom, bien que plusieurs catégories puissent être traitées en une seule exécution, seules les catégories appartenant à la même locale peuvent être traitées.)

STDIN

Sauf si l'option -i est spécifiée, l'entrée standard est un fichier texte contenant une ou plusieurs définitions sources de catégories de locale, comme décrit dans le volume des Définitions de base de POSIX.1‐2017, Section 7.3, Définition de Locale. Lorsque les lignes sont continuées en utilisant le mécanisme de caractère d'échappement, il n'y a pas de limite à la longueur de la ligne continuée accumulée.

FICHIERS ENTRÉE

Le fichier de mappage de jeu de caractères spécifié comme argument d'option charmap est décrit dans le volume des Définitions de base de POSIX.1‐2017, Section 6.4, Fichier de description de jeu de caractères. Si une définition source de catégorie de locale contient une instruction copy, telle que définie dans le volume des Définitions de base de POSIX.1‐2017, Chapitre 7, Locale, et que l'instruction copy nomme une locale valide et existante, alors localedef se comportera comme si la définition source contenait une définition source de catégorie valide pour la locale nommée.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de localedef :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

(Cette variable n'a aucun effet sur localedef ; la locale POSIX est utilisée pour cette catégorie.)
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en tant que caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée). Cette variable n'a aucun effet sur le traitement des données d'entrée de localedef ; la locale POSIX est utilisée à cette fin, quelle que soit la valeur de cette variable.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des mes

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

L'utilitaire doit signaler toutes les catégories traitées avec succès, dans un format non spécifié.

ERREUR STANDARD

L'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Le format du fichier de sortie créé n'est pas spécifié. Si l'opérande nom ne contient pas de <barre oblique>, l'existence d'un fichier de sortie pour la locale n'est pas spécifiée.

DESCRIPTION ÉTENDUE

Lorsque l'option -u est utilisée, l'argument d'option nom_jeu_de_codes doit être interprété comme un nom, défini par l'implémentation, d'un jeu de codes vers lequel les valeurs des constantes de position de la norme ISO/IEC 10646‐1:2000 seront converties via une méthode définie par l'implémentation. Les valeurs des constantes de position de la norme ISO/IEC 10646‐1:2000 ainsi que d'autres formats (décimal, hexadécimal ou octal) doivent être valides en tant que valeurs d'encodage dans le fichier charmap. Le jeu de codes représenté par le nom défini par l'implémentation peut être n'importe quel jeu de codes pris en charge par l'implémentation.

Lorsque des conflits surviennent entre la spécification charmap de <nom_jeu_de_codes>, <mb_cur_max> ou <mb_cur_min> et l'interprétation définie par l'implémentation de ces éléments respectifs pour le jeu de codes représenté par l'argument d'option nom_jeu_de_codes -u, le résultat n'est pas spécifié.

Lorsque des conflits surviennent entre les valeurs d'encodage charmap spécifiées pour les noms symboliques des caractères de l'ensemble de caractères portable et l'attribution définie par l'implémentation des valeurs d'encodage de caractères, le résultat n'est pas spécifié.

Si un caractère non imprimable dans le charmap a une largeur spécifiée qui n'est pas -1, le résultat sera indéfini.

STATUT DE FIN

Les valeurs de sortie suivantes doivent être retournées :

 0
Aucune erreur ne s'est produite et les locales ont été créées avec succès.
 1
Des avertissements se sont produits et les locales ont été créées avec succès.
 2
La spécification de la locale a dépassé les limites de l'implémentation ou le jeu (ou les jeux) de caractères codés n'était pas pris en charge par l'implémentation, et aucune locale n'a été créée.
 3
La capacité de créer de nouvelles locales n'est pas prise en charge par l'implémentation.
>3
Des avertissements ou des erreurs se sont produits et aucune sortie n'a été créée.

CONSÉQUENCES DES ERREURS

Si une erreur est détectée, aucune sortie permanente ne doit être créée.

Si des avertissements se produisent, une sortie permanente doit être créée si l'option -c a été spécifiée. Les conditions suivantes doivent entraîner l'émission de messages d'avertissement :

*
Si un nom symbolique introuvable dans le fichier charmap est utilisé pour les descriptions des catégories LC_CTYPE ou LC_COLLATE (pour les autres catégories, ce sera une condition d'erreur).
*
Si le nombre d'opérandes du mot-clé order dépasse la limite {COLL_WEIGHTS_MAX}.
*
Si des mots-clés optionnels non pris en charge par l'implémentation sont présents dans la source.

D'autres conditions définies par l'implémentation peuvent également provoquer des avertissements.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

La définition du charmap est facultative et se trouve en dehors de la définition de la locale. Cela permet à la fois des fichiers source entièrement auto-définis et des sources génériques (applicables à plus d'un jeu de codes). Pour faciliter la portabilité, toutes les définitions de charmap doivent utiliser les mêmes noms symboliques pour l'ensemble de caractères portable. Comme expliqué dans le volume Définitions de base de POSIX.1‐2017, Section 6.4, Fichier de description des jeux de caractères, il est défini par l'implémentation si les utilisateurs ou les applications peuvent fournir des fichiers de description de jeux de caractères supplémentaires. Par conséquent, l'option -f peut fonctionner uniquement lorsqu'un charmap défini par l'implémentation est nommé.

EXEMPLES

Aucun.

RATIONALE

La sortie produite par l'utilitaire localedef est définie par l'implémentation. L'opérande nom est utilisé pour identifier la locale spécifique. (Par conséquent, bien que plusieurs catégories puissent être traitées en une seule exécution, seules les catégories appartenant à la même locale peuvent être traitées.)
