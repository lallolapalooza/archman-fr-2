locale(7) Manuel d'informations diverses locale(7)

NOM

locale - description du support multilingue

SYNTAXE

#include <locale.h>

DESCRIPTION

Un « locale » est un ensemble de règles linguistiques et culturelles. Celles-ci couvrent des aspects tels que la langue des messages, différents jeux de caractères, les conventions lexicographiques, etc. Un programme doit pouvoir déterminer son locale et agir en conséquence pour être portable vers différentes cultures.

L'en-tête <locale.h> déclare les types de données, fonctions et macros utiles à cette tâche.

Les fonctions qu'il déclare sont setlocale(3) pour définir le locale courant et localeconv(3) pour obtenir des informations sur le formatage des nombres.

Il existe différentes catégories d'informations de locale dont un programme pourrait avoir besoin ; elles sont déclarées comme des macros. En les utilisant comme premier argument de setlocale(3), il est possible de définir l'une d'elles au locale désiré :

LC_ADDRESS (extension GNU, depuis glibc 2.2)
Modifie les paramètres qui décrivent les formats (par exemple, les adresses postales) utilisés pour décrire des emplacements et des éléments liés à la géographie. Les applications ayant besoin de ces informations peuvent utiliser nl_langinfo(3) pour récupérer des éléments non standards, tels que _NL_ADDRESS_COUNTRY_NAME (nom du pays, dans la langue du locale) et _NL_ADDRESS_LANG_NAME (nom de la langue, dans la langue du locale), qui retournent des chaînes telles que « Deutschland » et « Deutsch » (pour les locales en langue allemande). (D'autres noms d'éléments sont listés dans <langinfo.h>.)
LC_COLLATE
Cette catégorie régit les règles de tri utilisées pour le classement et les expressions régulières, y compris les classes d'équivalence de caractères et les éléments de tri multi-caractères. Cette catégorie de locale change le comportement des fonctions strcoll(3) et strxfrm(3), qui sont utilisées pour comparer des chaînes dans l'alphabet local. Par exemple, le « s » allemand (ß) est trié comme « ss ».
LC_CTYPE
Cette catégorie détermine l'interprétation des séquences d'octets comme caractères (par exemple, caractères mono- ou multi-octets), les classifications de caractères (par exemple, alphabétique ou chiffre) et le comportement des classes de caractères. Sur les systèmes glibc, cette catégorie détermine également les règles de translittération des caractères pour iconv(1) et iconv(3). Elle modifie le comportement des fonctions de manipulation et de classification de caractères, telles que isupper(3) et toupper(3), ainsi que les fonctions de caractères multi-octets telles que mblen(3) ou wctomb(3).
LC_IDENTIFICATION (extension GNU, depuis glibc 2.2)
Modifie les paramètres relatifs aux métadonnées du locale. Les applications ayant besoin de ces informations peuvent utiliser nl_langinfo(3) pour récupérer des éléments non standards, tels que _NL_IDENTIFICATION_TITLE (titre du document de locale) et _NL_IDENTIFICATION_TERRITORY (territoire géographique auquel ce document de locale s'applique), qui pourraient retourner des chaînes telles que « English locale for the USA » et « USA ». (D'autres noms d'éléments sont listés dans <langinfo.h>.)
LC_MONETARY
Cette catégorie détermine le formatage utilisé pour les valeurs numériques monétaires. Elle modifie les informations renvoyées par localeconv(3), qui décrivent la manière dont les nombres sont généralement imprimés, avec des détails tels que le séparateur décimal (virgule ou point). Ces informations sont utilisées en interne par la fonction strfmon(3).
LC_MESSAGES
Cette catégorie affecte la langue dans laquelle les messages sont affichés et l'apparence d'une réponse affirmative ou négative. La bibliothèque C de GNU contient les fonctions gettext(3), ngettext(3) et rpmatch(3) pour faciliter l'utilisation de ces informations. La famille de fonctions GNU gettext respecte également la variable d'environnement LANGUAGE (contenant une liste de locales séparée par des deux-points) si la catégorie est définie sur un locale valide autre que « C ». Cette catégorie affecte également le comportement de catopen(3).
LC_MEASUREMENT (extension GNU, depuis glibc 2.2)
Modifie les paramètres relatifs au système de mesure dans le locale (c'est-à-dire les unités métriques ou les unités coutumières américaines). Les applications peuvent utiliser nl_langinfo(3) pour récupérer l'élément non standard _NL_MEASUREMENT_MEASUREMENT, qui renvoie un pointeur vers un caractère ayant la valeur 1 (métrique) ou 2 (unités coutumières américaines).
LC_NAME (extension GNU, depuis glibc 2.2)
Modifie les paramètres qui décrivent les formats utilisés pour s'adresser aux personnes. Les applications ayant besoin de ces informations peuvent utiliser nl_langinfo(3) pour récupérer des éléments non standards, tels que les éléments _NL_NAME_NAME_MR (salutation générale pour les hommes) et _NL_NAME_NAME_MS (salutation générale pour les femmes), qui retournent des chaînes telles que « Herr » et « Frau » (pour les locales en langue allemande). (D'autres noms d'éléments sont listés dans <langinfo.h>.)
LC_NUMERIC
Cette catégorie détermine les règles de formatage utilisées pour les valeurs numériques non monétaires — par exemple, le séparateur de milliers et le caractère radix (un point dans la plupart des pays anglophones, mais une virgule dans de nombreuses autres régions). Elle affecte les fonctions telles que printf(3), scanf(3) et strtod(3). Ces informations peuvent également être lues avec la fonction localeconv(3).
LC_PAPER (extension GNU, depuis glibc 2.2)
Modifie les paramètres relatifs aux dimensions du format de papier standard (par exemple, format lettre américain ou A4). Les applications ayant besoin des dimensions peuvent les obtenir en utilisant nl_langinfo(3) pour récupérer les éléments non standards _NL_PAPER_WIDTH et _NL_PAPER_HEIGHT, qui renvoient des valeurs int spécifiant les dimensions en millimètres.
LC_TELEPHONE (extension GNU, depuis glibc 2.2)
Modifie les paramètres qui décrivent les formats à utiliser avec les services téléphoniques. Les applications ayant besoin de ces informations peuvent utiliser nl_langinfo(3) pour récupérer des éléments non standards, tels que _NL_TELEPHONE_INT_PREFIX (préfixe international utilisé pour appeler des numéros dans ce locale), qui renvoie une chaîne telle que « 49 » (pour l'Allemagne). (D'autres noms d'éléments sont listés dans <langinfo.h>.)
LC_TIME
Cette catégorie régit le formatage utilisé pour les dates et heures. Par exemple, la plupart des pays européens utilisent une horloge sur 24 heures, contrairement à l'horloge sur 12 heures utilisée aux États-Unis. La définition de cette catégorie affecte le comportement des fonctions telles que strftime(3) et strptime(3).
LC_ALL
Toutes les catégories ci-dessus.

Les valeurs concernant le formatage numérique local sont mises à disposition dans une structure lconv renvoyée par la fonction localeconv(3), qui a la déclaration suivante :


struct lconv {
    /* Informations numériques (non monétaires) */
    char *decimal_point;     /* Caractère du séparateur décimal */
    char *thousands_sep;     /* Séparateur des groupes de chiffres à gauche
                                du séparateur décimal */
    char *grouping;     /* Chaque élément est le nombre de chiffres dans
                           un groupe ; les éléments avec des indices plus élevés
                           sont plus à gauche. Un élément avec la valeur
                           CHAR_MAX signifie qu'aucun regroupement supplémentaire
                           n'est effectué. Un élément avec la valeur 0 signifie
                           que l'élément précédent est utilisé pour tous les groupes plus à gauche.  */
    /* Les champs restants sont pour les informations monétaires */
    char *int_curr_symbol;   /* Les trois premiers caractères sont un symbole monétaire
                                de l'ISO 4217. Le quatrième caractère est le séparateur. Le cinquième caractère
                                est '\0'.  */
    char *currency_symbol;   /* Symbole de la monnaie locale */
    char *mon_decimal_point; /* Caractère du séparateur décimal */
    char *mon_thousands_sep; /* Similaire à thousands_sep ci-dessus */
    char *mon_grouping;      /* Similaire à grouping ci-dessus */
    char *positive_sign;     /* Signe pour les valeurs positives */
    char *negative_sign;     /* Signe pour les valeurs négatives */
    char  int_frac_digits;   /* Chiffres fractionnaires internationaux */
    char  frac_digits;       /* Chiffres fractionnaires locaux */
    char  p_cs_precedes;     /* 1 si currency_symbol précède
                                une valeur positive, 0 s'il la suit */
    char  p_sep_by_space;    /* 1 si un espace sépare
                                currency_symbol d'une valeur positive */
    char  n_cs_precedes;     /* 1 si currency_symbol précède
                                une valeur négative, 0 s'il la suit */
    char  n_sep_by_space;    /* 1 si un espace sépare
                                currency_symbol d'une valeur négative */
    /* Positions des signes positifs et négatifs :
       0 Des parenthèses entourent la quantité et currency_symbol.
       1 La chaîne de signe précède la quantité et currency_symbol.
       2 La chaîne de signe suit la quantité et currency_symbol.
       3 La chaîne de signe précède immédiatement currency_symbol.
       4 La chaîne de signe suit immédiatement currency_symbol.  */
    char  p_sign_posn;
    char  n_sign_posn;
};

Extensions POSIX.1-2008 à l'API locale

POSIX.1-2008 a standardisé un certain nombre d'extensions à l'API locale, basées sur des implémentations qui sont apparues pour la première fois dans glibc 2.3. Ces extensions sont conçues pour résoudre le problème que les API locales traditionnelles ne se mélangent pas bien avec les applications multithreadées et avec les applications qui doivent traiter plusieurs locales.

Les extensions prennent la forme de nouvelles fonctions pour créer et manipuler des objets de locale (newlocale(3), freelocale(3), duplocale(3), et uselocale(3)) et diverses nouvelles fonctions de bibliothèque avec le suffixe « _l » (par exemple, toupper_l(3)) qui étendent les API traditionnelles dépendantes de la locale (par exemple, toupper(3)) pour permettre la spécification d'un objet de locale qui devrait s'appliquer lors de l'exécution de la fonction.

ENVIRONNEMENT

La variable d'environnement suivante est utilisée par newlocale(3) et setlocale(3), et affecte donc tous les programmes localisés non privilégiés :

LOCPATH
Une liste de noms de chemins, séparés par des deux-points (« : »), qui doivent être utilisés pour trouver les données de locale. Si cette variable est définie, seuls les fichiers de données de locale compilés individuellement de LOCPATH et le chemin des données de locale par défaut du système sont utilisés ; aucune archive de locale disponible n'est utilisée (voir localedef(1)). Les fichiers de données de locale compilés individuellement sont recherchés sous des sous-répertoires qui dépendent de la locale actuellement utilisée. Par exemple, lorsque en_GB.UTF-8 est utilisé pour une catégorie, les sous-répertoires suivants sont recherchés, dans cet ordre : en_GB.UTF-8, en_GB.utf8, en_GB, en.UTF-8, en.utf8, et en.

FICHIERS

/usr/lib/locale/locale-archive
Emplacement habituel de l'archive de locale par défaut.
/usr/lib/locale
Chemin habituel par défaut pour les fichiers de locale individuels compilés.

NORMES

POSIX.1-2001.
