NOM

loginctl - Contrôler le gestionnaire de connexion systemd

SYNTAXE

loginctl [OPTIONS...] {COMMANDE} [NOM...]

DESCRIPTION

loginctl peut être utilisé pour introspecter et contrôler l'état du gestionnaire de connexion systemd(1) systemd-logind.service(8).

COMMANDES

Les commandes suivantes sont comprises :

Commandes de session

list-sessions

Liste les sessions actives. La sortie au format JSON peut être activée/désactivée à l'aide de l'option --json= ou -j.

session-status [ID...]

Affiche des informations succinctes sur l'état d'exécution d'une ou plusieurs sessions, suivies des données de journal les plus récentes. Prend en paramètre un ou plusieurs identifiants de session. Si aucun identifiant de session n'est passé, l'état de la session de l'appelant est affiché. Cette fonction est conçue pour générer une sortie lisible par l'homme. Si vous recherchez une sortie analysable par machine, utilisez plutôt show-session.

Ajouté en version 233.

show-session [ID...]

Affiche les propriétés d'une ou plusieurs sessions ou du gestionnaire lui-même. Si aucun argument n'est spécifié, les propriétés du gestionnaire sont affichées. Si un identifiant de session est spécifié, les propriétés de la session sont affichées. Spécifiquement, si l'ID donné est "self", la session à laquelle le processus loginctl appartient est utilisée. Si "auto", la session en cours est utilisée comme avec "self" si elle existe, sinon elle utilise la session graphique de l'utilisateur actuel. Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=. Cette commande est destinée à être utilisée chaque fois qu'une sortie analysable par machine est requise. Utilisez session-status si vous recherchez une sortie formatée lisible par l'homme.

Ajouté en version 233.

activate [ID]

Active une session. Cela amène une session au premier plan si une autre session est actuellement au premier plan sur le siège respectif. Prend un identifiant de session comme argument. Si aucun argument n'est spécifié, la session de l'appelant est mise au premier plan.

Ajouté en version 219.

lock-session [ID...], unlock-session [ID...]

Active/désactive le verrouillage de l'écran sur une ou plusieurs sessions, si la session le supporte. Prend un ou plusieurs identifiants de session comme arguments. Si aucun argument n'est spécifié, la session de l'appelant est verrouillée/déverrouillée.

Ajouté en version 233.

lock-sessions, unlock-sessions

Active/désactive le verrouillage de l'écran sur toutes les sessions actives qui le supportent.

Ajouté en version 188.

terminate-session ID...

Termine une session. Cela tue tous les processus de la session et désalloue toutes les ressources associées à la session. Si l'argument est une chaîne vide, la session qui invoque la commande est terminée.

Ajouté en version 233.

kill-session ID...

Envoie un signal à un ou plusieurs processus de la session. Utilisez --kill-whom= pour sélectionner quel processus tuer. Utilisez --signal= pour sélectionner le signal à envoyer. Si l'argument est une chaîne vide, le signal est envoyé aux processus de la session qui invoque la commande.

Ajouté en version 233.

Commandes utilisateur

list-users

Liste les utilisateurs actuellement connectés. La sortie au format JSON peut être activée/désactivée à l'aide de l'option --json= ou -j.

user-status [USER...]

Affiche des informations succinctes sur l'état d'exécution d'un ou plusieurs utilisateurs connectés, suivies des données de journal les plus récentes. Prend en paramètre un ou plusieurs noms d'utilisateur ou identifiants numériques d'utilisateur. Si aucun paramètre n'est passé, l'état est affiché pour l'utilisateur de la session de l'appelant. Cette fonction est conçue pour générer une sortie lisible par l'homme. Si vous recherchez une sortie analysable par machine, utilisez plutôt show-user.

Ajouté en version 233.

show-user [USER...]

Affiche les propriétés d'un ou plusieurs utilisateurs ou du gestionnaire lui-même. Si aucun argument n'est spécifié, les propriétés du gestionnaire sont affichées. Si un utilisateur est spécifié, les propriétés de l'utilisateur sont affichées. Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=. Cette commande est destinée à être utilisée chaque fois qu'une sortie analysable par machine est requise. Utilisez user-status si vous recherchez une sortie formatée lisible par l'homme.

Ajouté en version 233.

enable-linger [USER...], disable-linger [USER...]

Active/désactive la persistance (lingering) pour un ou plusieurs utilisateurs. Si elle est activée pour un utilisateur spécifique, un gestionnaire d'utilisateur est lancé pour l'utilisateur au démarrage et maintenu après les déconnexions. Cela permet aux utilisateurs qui ne sont pas connectés d'exécuter des services de longue durée. Prend un ou plusieurs noms d'utilisateur ou UID numériques comme argument. Si aucun argument n'est spécifié, la persistance est activée/désactivée pour l'utilisateur de la session de l'appelant.

Voir également le paramètre KillUserProcesses= dans logind.conf(5).

Ajouté en version 233.

terminate-user USER...

Termine toutes les sessions d'un utilisateur. Cela tue tous les processus de toutes les sessions de l'utilisateur et désalloue toutes les ressources d'exécution associées à l'utilisateur. Si l'argument est une chaîne vide, les sessions de l'utilisateur qui invoque la commande sont terminées.

Ajouté en version 233.

kill-user USER...

Envoie un signal à tous les processus d'un utilisateur. Utilisez --signal= pour sélectionner le signal à envoyer. Si l'argument est une chaîne vide, le signal est envoyé aux sessions de l'utilisateur qui invoque la commande.

Ajouté en version 233.

Commandes de siège

list-seats

Liste les sièges actuellement disponibles sur le système local. La sortie au format JSON peut être activée/désactivée à l'aide de l'option --json= ou -j.

seat-status [NAME...]

Affiche des informations succinctes sur l'état d'exécution d'un ou plusieurs sièges. Prend en paramètre un ou plusieurs noms de siège. Si aucun nom de siège n'est passé, l'état du siège de la session de l'appelant est affiché. Cette fonction est conçue pour générer une sortie lisible par l'homme. Si vous recherchez une sortie analysable par machine, utilisez plutôt show-seat.

Ajouté en version 233.

show-seat [NAME...]

Affiche les propriétés d'un ou plusieurs sièges ou du gestionnaire lui-même. Si aucun argument n'est spécifié, les propriétés du gestionnaire sont affichées. Si un siège est spécifié, les propriétés du siège sont affichées. Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=. Cette commande est destinée à être utilisée chaque fois qu'une sortie analysable par machine est requise. Utilisez seat-status si vous recherchez une sortie formatée lisible par l'homme.

Ajouté en version 233.

attach NAME DEVICE...

Attache de manière persistante un ou plusieurs périphériques à un siège. Les périphériques doivent être spécifiés via des chemins de périphériques dans le système de fichiers /sys/. Pour créer un nouveau siège, attachez au moins une carte graphique à un nom de siège précédemment inutilisé. Les noms de siège ne peuvent contenir que des lettres de a à z, A à Z, des chiffres de 0 à 9, des traits d'union "-" et des tirets bas "_" et doivent être précédés de "seat". Pour supprimer l'affectation d'un périphérique à un siège spécifique, réaffectez-le simplement à un siège différent, ou utilisez flush-devices.

Ajouté en version 233.

flush-devices

Supprime toutes les affectations de périphériques précédemment créées avec attach. Après cet appel, seuls les sièges générés automatiquement resteront, et tout le matériel des sièges leur sera affecté.

terminate-seat NAME...

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Termine toutes les sessions sur un siège. Cela tue tous les processus de toutes les sessions sur le siège et désalloue toutes les ressources d'exécution qui y sont attachées.

Ajouté dans la version 233.

OPTIONS

Les options suivantes sont comprises :

-p, --property=

Lors de l'affichage des propriétés de session/utilisateur/siège, limite l'affichage à certaines propriétés spécifiées comme argument. Si non spécifié, toutes les propriétés définies sont affichées. L'argument doit être un nom de propriété, tel que "Sessions". Si spécifié plus d'une fois, toutes les propriétés avec les noms spécifiés sont affichées.

--value

Lors de l'affichage des propriétés de session/utilisateur/siège, n'imprime que la valeur, et omet le nom de la propriété et "=".

Ajouté dans la version 230.

-a, --all

Lors de l'affichage des propriétés de session/utilisateur/siège, affiche toutes les propriétés, qu'elles soient définies ou non.

-l, --full

Ne tronque pas les entrées de l'arbre des processus.

Ajouté dans la version 198.

--kill-whom=

Lorsqu'il est utilisé avec kill-session, choisit quels processus tuer. Prend "leader" ou "all" pour sélectionner s'il faut tuer uniquement le processus leader de la session ou tous les processus de la session. Si omis, la valeur par défaut est all.

Ajouté dans la version 252.

-s, --signal=

Lorsqu'il est utilisé avec kill-session ou kill-user, choisit quel signal envoyer aux processus sélectionnés. Doit être l'un des spécificateurs de signal bien connus, tels que SIGTERM, SIGINT ou SIGSTOP. Si omis, la valeur par défaut est SIGTERM.

La valeur spéciale "help" listera les valeurs connues et le programme se terminera immédiatement, et la valeur spéciale "list" listera les valeurs connues ainsi que les numéros de signal numériques et le programme se terminera immédiatement.

-n, --lines=

Lorsqu'il est utilisé avec user-status et session-status, contrôle le nombre de lignes du journal à afficher, en comptant à partir des plus récentes. Prend un entier positif comme argument. La valeur par défaut est 10.

Ajouté dans la version 219.

-o, --output=

Lorsqu'il est utilisé avec user-status et session-status, contrôle le formatage des entrées du journal affichées. Pour les choix disponibles, voir journalctl(1). La valeur par défaut est "short".

Ajouté dans la version 219.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par "@", pour vous connecter. Le nom d'hôte peut éventuellement être suffixé par un port sur lequel ssh écoute, séparé par ":", puis un nom de conteneur, séparé par "/", ce qui se connecte directement à un conteneur spécifique sur l'hôte spécifié. Cela utilisera SSH pour communiquer avec l'instance du gestionnaire de machine distante. Les noms de conteneurs peuvent être énumérés avec machinectl -H HOST. Mettez les adresses IPv6 entre crochets.

-M, --machine=

Exécute l'opération sur un conteneur local. Spécifiez un nom de conteneur pour vous connecter, éventuellement préfixé par un nom d'utilisateur pour se connecter et un caractère séparateur "@". Si la chaîne spéciale ".host" est utilisée à la place du nom du conteneur, une connexion au système local est établie (ce qui est utile pour se connecter au bus utilisateur d'un utilisateur spécifique : "--user --machine=lennart@.host"). Si la syntaxe "@" n'est pas utilisée, la connexion est établie en tant qu'utilisateur root. Si la syntaxe "@" est utilisée, la partie gauche ou la partie droite peut être omise (mais pas les deux) auquel cas le nom d'utilisateur local et ".host" sont implicites.

--no-ask-password

Ne demande pas à l'utilisateur d'authentification pour les opérations privilégiées.

--no-pager

Ne redirige pas la sortie vers un paginator.

--no-legend

N'imprime pas la légende, c'est-à-dire les en-têtes de colonnes et le pied de page avec des indications.

--json=MODE

Affiche la sortie formatée en JSON. Attend l'une des valeurs suivantes : "short" (pour la sortie la plus courte possible sans espaces superflus ni sauts de ligne), "pretty" (pour une version formatée de la même chose, avec indentation et sauts de ligne) ou "off" (pour désactiver la sortie JSON, par défaut).

-j

Équivalent à --json=pretty si exécuté sur un terminal, et --json=short sinon.

-h, --help

Imprime un court texte d'aide et quitte.

--version

Imprime une courte chaîne de version et quitte.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

EXEMPLES

Exemple 1. Interrogation du statut de l'utilisateur

$ loginctl user-status
fatima (1005)
           Since: Sat 2016-04-09 14:23:31 EDT; 54min ago
           State: active
        Sessions: 5 *3
            Unit: user-1005.slice
                  ├─user@1005.service
                    ...
                  ├─session-3.scope
                    ...
                  └─session-5.scope
                    ├─3473 login -- fatima
                    └─3515 -zsh
Apr 09 14:40:30 laptop login[2325]: pam_unix(login:session):
                       session opened for user fatima by LOGIN(uid=0)
Apr 09 14:40:30 laptop login[2325]: LOGIN ON tty3 BY fatima

Il y a deux sessions, 3 et 5. La session 3 est une session graphique, marquée d'une étoile. L'arbre des processus, y compris les deux unités de portée correspondantes et l'unité de gestion des utilisateurs, est affiché.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages d'un niveau de journalisation plus élevé, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, ou un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'une des valeurs suivantes : console, syslog, kmsg ou journal suivi d'un deux-points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lors de la journalisation vers la console qui devrait être au niveau info). Notez que le niveau de journalisation maximal global a la priorité sur tout niveau de journalisation maximal par cible.

$SYSTEMD_LOG_COLOR

Un booléen. Si vrai, les messages écrits sur le tty seront colorés en fonction de leur priorité.

Ce paramètre n'est utile que lorsque les messages sont écrits directement sur le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. Si vrai, les messages de journalisation de la console seront préfixés par un horodatage.

Ce paramètre n'est utile que lorsque les messages sont écrits directement sur le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux attacheront des horodatages basés sur les métadonnées de l'entrée par eux-mêmes.

$SYSTEMD_LOG_LOCATION

Un booléen. Si vrai, les messages seront préfixés par un nom de fichier et un numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent déjà attaché comme métadonnées aux entrées du journal. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TID

Un booléen. Si vrai, les messages seront préfixés par l'identifiant de thread (TID) numérique actuel.

Notez que ces informations sont déjà attachées comme métadonnées aux entrées du journal. Les inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des valeurs suivantes : console (journaliser vers le tty attaché), console-prefixed (journaliser vers le tty attaché mais avec des préfixes encodant le niveau de journalisation et la "facility", voir syslog(3), kmsg (journaliser vers le tampon de journal circulaire du noyau), journal (journaliser vers le journal), journal-or-kmsg (journaliser vers le journal si disponible, et vers kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie de journal).

$SYSTEMD_LOG_RATELIMIT_KMSG

Si limiter le débit de kmsg ou non. Prend une valeur booléenne. La valeur par défaut est "true". Si désactivé, systemd ne limitera pas le débit des messages écrits dans kmsg.

$SYSTEMD_PAGER, $PAGER

Paginator à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, une série d'implémentations de paginators bien connues est essayée tour à tour, y compris less(1) et more(1), jusqu'à ce qu'un soit trouvé. Si aucune implémentation de paginator n'est découverte, aucun paginator n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur "cat" équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le paginator (avec "cat" ou ""), et sont par ailleurs ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs peuvent vouloir modifier deux options en particulier :

K

Cette option demande au paginator de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même pour revenir à l'invite de commande du paginator, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas "K", et que le paginator invoqué est less, Ctrl+C sera ignoré par l'exécutable, et devra être géré par le paginator.

X

Cette option demande au paginator de ne pas envoyer les chaînes d'initialisation et de désinitialisation de termcap au terminal. Elle est définie par
default pour permettre à la sortie des commandes de rester visible dans le terminal même après la sortie du pager. Néanmoins, cela empêche certaines fonctionnalités du pager de fonctionner, notamment la sortie paginée ne peut pas être parcourue avec la souris.

Notez que la définition de la variable d'environnement $LESS n'a aucun effet pour les invocations de less par les outils systemd.

Voir less(1) pour plus de détails.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut "utf-8", si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET n'a aucun effet pour les invocations de less par les outils systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pager courantes comme less(1), en plus de la "pagination", c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture dans d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque des commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pager devient une limite de sécurité. Il faut veiller à ce que seuls des programmes à fonctionnalité strictement limitée soient utilisés comme pagers, et que les fonctionnalités interactives involontaires comme l'ouverture ou la création de nouveaux fichiers ou le démarrage de sous-processus ne soient pas autorisées. Le "mode sécurisé" pour le pager peut être activé comme décrit ci-dessous, si le pager le prend en charge (la plupart des pagers ne sont pas conçus de manière à en tenir compte). Il est recommandé d'activer explicitement le "mode sécurisé" ou de désactiver complètement le pager en utilisant --no-pager ou PAGER=cat lorsque vous autorisez des utilisateurs non fiables à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur true, le "mode sécurisé" du pager est activé. En "mode sécurisé", LESSSECURE=1 sera défini lors de l'invocation du pager, ce qui indique au pager de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou démarrent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le "mode sécurisé".

Lorsqu'elle est définie sur false, aucune limitation n'est imposée au pager. La définition de SYSTEMD_PAGERSECURE=0 ou sa non-suppression de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas définie, les outils systemd tentent de déterminer automatiquement si le "mode sécurisé" doit être activé et si le pager le prend en charge. Le "mode sécurisé" est activé si l'UID effectif est différent de celui du propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous sudo(8) ou des outils similaires ($SUDO_UID est défini [1]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagers qui ne sont pas connus pour implémenter le "mode sécurisé" ne seront pas utilisés du tout. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à la commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pager.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être respectées, autre que pour désactiver le pager, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Prend un argument booléen. Lorsqu'il est vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : "16", "256" pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256, respectivement. Cela peut être spécifié pour remplacer la décision automatique basée sur $TERM et ce à quoi la console est connectée.

$SYSTEMD_URLIFY

La valeur doit être un booléen. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminal qui le prennent en charge. Cela peut être spécifié pour remplacer la décision prise par systemd en fonction de $TERM et d'autres conditions.
