LOCKF(3P) Manuel du programmeur POSIX LOCKF(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

lockf — verrouillage d'enregistrements sur des fichiers

SYNOPIS

#include <unistd.h>
int lockf(int fildes, int function, off_t size);

DESCRIPTION

La fonction lockf() verrouille des sections d'un fichier avec des verrous en mode consultatif. Les appels à lockf() depuis des threads d'autres processus qui tentent de verrouiller la section de fichier verrouillée retourneront soit une valeur d'erreur, soit bloqueront jusqu'à ce que la section soit déverrouillée. Tous les verrous d'un processus sont supprimés lorsque le processus se termine. Le verrouillage d'enregistrements avec lockf() doit être pris en charge pour les fichiers réguliers et peut être pris en charge pour d'autres fichiers.

L'argument fildes est un descripteur de fichier ouvert. Pour établir un verrou avec cette fonction, le descripteur de fichier doit être ouvert en mode écriture seule (O_WRONLY) ou en mode lecture/écriture (O_RDWR).

L'argument function est une valeur de contrôle qui spécifie l'action à effectuer. Les valeurs autorisées pour function sont définies dans <unistd.h> comme suit :

Fonction Description
F_ULOCK Déverrouille les sections verrouillées.
F_LOCK Verrouille une section pour usage exclusif.
F_TLOCK Teste et verrouille une section pour usage exclusif.
F_TEST Teste une section pour détecter des verrous par d'autres processus.

F_TEST détecte si un verrou par un autre processus est présent sur la section spécifiée.

F_LOCK et F_TLOCK verrouillent tous deux une section d'un fichier si la section est disponible.

F_ULOCK supprime les verrous d'une section de fichier.

L'argument size est le nombre d'octets contigus à verrouiller ou déverrouiller. La section à verrouiller ou déverrouiller commence au décalage courant dans le fichier et s'étend vers l'avant pour une taille positive ou vers l'arrière pour une taille négative (les octets précédents jusqu'au décalage courant mais sans l'inclure). Si size est 0, la section allant du décalage courant jusqu'au plus grand décalage de fichier possible est verrouillée (c'est-à-dire du décalage courant jusqu'à la fin du fichier présente ou future). Une zone n'a pas besoin d'être allouée au fichier pour être verrouillée car les verrous peuvent exister au-delà de la fin du fichier.

Les sections verrouillées avec F_LOCK ou F_TLOCK peuvent, en tout ou en partie, contenir ou être contenues par une section précédemment verrouillée pour le même processus. Lorsque cela se produit, ou si des sections verrouillées adjacentes se produiraient, les sections seront combinées en une seule section verrouillée. Si la demande entraînait le dépassement du nombre de verrous d'une limite imposée par le système, la demande échouerait.

Les requêtes F_LOCK et F_TLOCK diffèrent uniquement par l'action entreprise si la section n'est pas disponible. F_LOCK bloquera le thread appelant jusqu'à ce que la section soit disponible. F_TLOCK entraînera l'échec de la fonction si la section est déjà verrouillée par un autre processus.

Les verrous de fichiers seront libérés lors de la première fermeture par le processus qui verrouille de tout descripteur de fichier pour le fichier.

Les requêtes F_ULOCK peuvent libérer (entièrement ou partiellement) une ou plusieurs sections verrouillées contrôlées par le processus. Les sections verrouillées seront déverrouillées en commençant au décalage de fichier courant sur size octets ou jusqu'à la fin du fichier si size est (off_t)0. Lorsque toute une section verrouillée n'est pas libérée (c'est-à-dire lorsque le début ou la fin de la zone à déverrouiller tombe dans une section verrouillée), les parties restantes de cette section resteront verrouillées par le processus. La libération de la partie centrale d'une section verrouillée entraînera la division en deux sections verrouillées séparées des portions restantes verrouillées au début et à la fin. Si la requête entraînait le dépassement du nombre de verrous dans le système d'une limite imposée par le système, la requête échouerait.

Un risque de blocage mutuel survient si les threads d'un processus contrôlant une section verrouillée sont bloqués par l'accès à une section verrouillée d'un autre processus. Si le système détecte qu'un blocage mutuel se produirait, lockf() échouera avec une erreur [EDEADLK].

L'interaction entre les verrous fcntl() et lockf() n'est pas spécifiée.

Le blocage sur une section sera interrompu par n'importe quel signal.

Une requête F_ULOCK dans laquelle size est non nulle et le décalage du dernier octet de la section demandée est la valeur maximale pour un objet de type off_t, lorsque le processus a un verrou existant dans lequel size est 0 et qui inclut le dernier octet de la section demandée, sera traitée comme une demande de déverrouillage à partir du début de la section demandée avec une taille égale à 0. Sinon, une requête F_ULOCK tentera de déverrouiller uniquement la section demandée.

Tenter de verrouiller une section d'un fichier associé à un flux tamponné produit des résultats non spécifiés.

VALEUR DE RETOUR

En cas de succès, lockf() retourne 0. Sinon, elle retourne -1, définit errno pour indiquer une erreur, et les verrous existants ne sont pas modifiés.

ERREURS

La fonction lockf() échoue si :

EBADF
L'argument fildes n'est pas un descripteur de fichier ouvert valide ; ou function est F_LOCK ou F_TLOCK et fildes n'est pas un descripteur de fichier valide ouvert en écriture.
EACCES ou EAGAIN

L'argument function est F_TLOCK ou F_TEST et la section est déjà verrouillée par un autre processus.
EDEADLK
L'argument function est F_LOCK et un blocage mutuel est détecté.
EINTR
Un signal a été intercepté pendant l'exécution de la fonction.
EINVAL
L'argument function n'est pas F_LOCK, F_TLOCK, F_TEST ou F_ULOCK ; ou size plus le décalage de fichier courant est inférieur à 0.
EOVERFLOW
Le décalage du premier octet, ou si size n'est pas 0 alors le dernier octet, dans la section demandée ne peut pas être représenté correctement dans un objet de type off_t.

La fonction lockf() peut échouer si :

EAGAIN
L'argument function est F_LOCK ou F_TLOCK et le fichier est mappé avec mmap().
EDEADLK ou ENOLCK

L'argument function est F_LOCK, F_TLOCK ou F_ULOCK, et la demande entraînerait le dépassement du nombre de verrous d'une limite imposée par le système.
EOPNOTSUPP ou EINVAL

L'implémentation ne prend pas en charge le verrouillage de fichiers du type indiqué par l'argument fildes.

EXEMPLES

Verrouillage d'une Partie d'un Fichier

Dans l'exemple suivant, un fichier nommé /home/cnd/mod1 est en cours de modification. Les autres processus qui utilisent le verrouillage sont empêchés de le modifier pendant cette opération. Seuls les 10000 premiers octets sont verrouillés, et l'appel de verrouillage échoue si un autre processus a déjà une partie de cette zone verrouillée.

#include <fcntl.h>
#include <unistd.h>
int fildes;
int status;
...
fildes = open("/home/cnd/mod1", O_RDWR);
status = lockf(fildes, F_TLOCK, (off_t)10000);

E'>APPLICATION USAGE

Le verrouillage d'enregistrement ne doit pas être utilisé en combinaison avec les fonctions fopen(), fread(), fwrite() et autres fonctions stdio. Au lieu de cela, les fonctions primitives et non mises en tampon (telles que open()) devraient être utilisées. Des résultats inattendus peuvent survenir dans les processus qui effectuent la mise en tampon dans l'espace d'adressage utilisateur. Le processus peut lire/écrire ultérieurement des données qui sont/étaient verrouillées. Les fonctions stdio sont la source la plus courante de mise en tampon inattendue.

La fonction alarm() peut être utilisée pour fournir une installation de temporisation dans les applications qui en ont besoin.
