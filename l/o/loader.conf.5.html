LOADER.CONF(5) loader.conf LOADER.CONF(5)

NOM

loader.conf - Fichier de configuration pour systemd-boot

SYNTAXE

ESP/loader/loader.conf

DESCRIPTION

systemd-boot(7) lit ESP/loader/loader.conf. Ce fichier configure si le menu est affiché et pendant combien de temps, la police, le bip sonore, les types d'entrées de menu à afficher, le choix par défaut, et certains aspects de l'enregistrement Secure Boot et de la gestion du firmware. Voir la liste des options disponibles ci-dessous.

Le fichier utilise l'encodage UTF-8 et se compose d'une série de lignes séparées par un caractère "line feed" (c'est-à-dire le code ASCII 10). Les lignes vides ou celles commençant par le signe de commentaire ("#") sont ignorées. Les autres lignes se composent d'un nom d'option, suivi d'espaces blancs, et de la valeur de l'option.

Les arguments booléens peuvent être écrits comme "yes"/"y"/"true"/"t"/"on"/"1" ou "no"/"n"/"false"/"f"/"off"/"0".

Note : systemd-boot lira également les fichiers d'entrée du chargeur de démarrage, type #1 (ESP/loader/entries/*.conf et XBOOTLDR/loader/entries/*.conf) et type #2 (ESP/EFI/Linux/*.uki et XBOOTLDR/EFI/Linux/*.uki). Ces fichiers sont décrits par la Boot Loader Specification[1].

Note : le comportement de systemd-boot est également influencé par les variables EFI. Certains des paramètres spécifiés dans ce fichier peuvent être remplacés par ceux-ci, par exemple l'entrée de menu de démarrage par défaut ou les délais d'attente du menu. Voir systemd-boot(7) pour plus de détails.

OPTIONS

Les configurations suivantes sont prises en charge dans loader.conf :

default

Un modèle glob pour sélectionner l'entrée par défaut par ID, qui est le nom du fichier incluant le suffixe littéral ".conf". L'entrée par défaut peut être modifiée dans le menu de démarrage lui-même, auquel cas le nom de l'entrée sélectionnée sera stocké comme une variable EFI, remplaçant cette option.

Si défini sur "@saved", l'entrée choisie sera enregistrée comme une variable EFI à chaque démarrage et sera automatiquement sélectionnée la prochaine fois que le chargeur de démarrage démarrera.

Tableau 1. Les entrées détectées automatiquement utiliseront les noms suivants :

Nom Description
auto-efi-default Chargeur EFI par défaut
auto-efi-shell Shell EFI
auto-osx macOS
auto-poweroff Éteindre le système
auto-reboot Redémarrer le système
auto-reboot-to-firmware-setup Redémarrer vers l'interface du firmware
auto-windows Gestionnaire de démarrage Windows

Les modèles glob pris en charge sont
"?", "*", et "[...]" (y compris les plages). Notez que ces modèles utilisent la même syntaxe que glob(7), mais ne prennent pas en charge toutes les fonctionnalités. En particulier, la négation d'ensemble et les classes de caractères nommées ne sont pas prises en charge. La correspondance est effectuée sans tenir compte de la casse sur l'ID de l'entrée (tel qu'affiché par bootctl list).

Ajouté dans la version 239.

timeout

Durée pendant laquelle le menu de démarrage doit être affiché avant que l'entrée par défaut ne soit démarrée, en secondes. Ceci peut être modifié dans le menu de démarrage lui-même et sera stocké comme une variable EFI dans ce cas, remplaçant cette option.

Si défini sur "menu-disabled" ou "menu-hidden" ou "0" (par défaut), aucun menu n'est affiché et l'entrée par défaut sera démarrée immédiatement. Sauf si "menu-disabled" est utilisé, le menu peut être affiché en appuyant et en maintenant une touche avant que systemd-boot ne soit lancé. Définir ceci sur "menu-force" désactive le délai d'attente tout en affichant toujours le menu.

Ajouté dans la version 239.

console-mode

Cette option configure la résolution de la console. Ceci peut être modifié dans le menu de démarrage lui-même et sera stocké comme une variable EFI dans ce cas, remplaçant cette option.

Prend un nombre ou l'une des valeurs spéciales listées ci-dessous. Les valeurs suivantes peuvent être utilisées :

0

Mode UEFI standard 80x25

Ajouté dans la version 239.

1

Mode 80x50, non pris en charge par tous les appareils

Ajouté dans la version 239.

2

le premier mode non standard fourni par le firmware de l'appareil, le cas échéant

Ajouté dans la version 239.

auto

Sélectionne automatiquement un mode approprié à l'aide d'heuristiques

Ajouté dans la version 239.

max

Sélectionne le mode disponible avec le numéro le plus élevé

Ajouté dans la version 239.

keep

Conserve le mode sélectionné par le firmware (par défaut)

Ajouté dans la version 239.

Ajouté dans la version 239.

editor

Prend un argument booléen. Active (par défaut) ou désactive l'éditeur. L'éditeur doit être désactivé si la machine peut être accédée par des personnes non autorisées.

Ajouté dans la version 239.

auto-entries

Prend un argument booléen. Active (par défaut) ou désactive les entrées pour d'autres entrées de démarrage trouvées sur la partition de démarrage. En particulier, cela peut être utile lorsque des entrées de chargeur sont créées pour afficher des descriptions de remplacement pour ces entrées.

Ajouté dans la version 239.

auto-firmware

Un booléen contrôlant la présence de l'entrée "Redémarrer vers l'interface du firmware" (activée par défaut). Si elle est désactivée, l'interface du firmware peut toujours être atteinte en utilisant la touche f.

Ajouté dans la version 239.

auto-reboot

Un booléen contrôlant la présence de l'entrée "Redémarrer le système" (désactivée par défaut). Même si elle est désactivée, le système peut toujours être redémarré en appuyant sur Shift+b.

Ajouté dans la version 255.

auto-poweroff

Un booléen contrôlant la présence de l'entrée "Éteindre le système" (désactivée par défaut). Même si elle est désactivée, le système peut toujours être éteint en appuyant sur Shift+o.

Ajouté dans la version 255.

beep

Prend un argument booléen. Si le délai d'attente est activé, émet un bip toutes les secondes, sinon émet n bips lorsque la n-ième entrée du menu de démarrage est sélectionnée (désactivé par défaut). Actuellement, seul x86 est pris en charge, où il utilise le haut-parleur du PC.

Ajouté dans la version 251.

secure-boot-enroll

Danger : cette fonctionnalité pourrait endommager légèrement votre appareil si elle est utilisée de manière inappropriée.

Contrôle l'enregistrement des clés Secure Boot trouvées sur l'ESP si le système est en mode de configuration :

off

Aucune action n'est effectuée.

Ajouté dans la version 253.

manual

Des entrées de démarrage pour les clés Secure Boot trouvées sont créées, permettant un enregistrement manuel.

Ajouté dans la version 253.

if-safe

Même comportement que manual, mais tentera d'enregistrer automatiquement la clé "auto" si elle est considérée comme sûre. Actuellement, ce n'est le cas que si le système s'exécute dans une machine virtuelle.

Ajouté dans la version 253.

force

Enregistre toujours la clé "auto" si elle est trouvée. Notez qu'un message d'avertissement avec un délai d'attente sera toujours affiché si cette opération n'est pas connue comme étant sûre.

Ajouté dans la version 253.

Les différents ensembles de variables peuvent être configurés sous /loader/keys/NAME où NAME est le nom qui sera utilisé comme nom de l'entrée. Cela permet d'expédier plusieurs ensembles de variables Secure Boot et de choisir lequel enregistrer à l'exécution.

Les variables Secure Boot prises en charge sont une base de données pour les images autorisées, une pour la clé d'échange de clés (KEK) et une pour la clé de plateforme (PK). Pour plus d'informations, référez-vous à la spécification UEFI[2], dans la section Secure Boot and Driver Signing. Une autre ressource décrivant l'interaction des différentes variables est la documentation EDK2[3].

Un ensemble complet de variables UEFI comprend db.auth, KEK.auth et PK.auth. Notez que ces fichiers doivent être des variables UEFI authentifiées. Voir ci-dessous pour un exemple de la façon de les générer à partir de X.509 réguliers

loader.conf(5) — systemd manual pages

NAME

loader.conf — configuration file for systemd-boot

SYNOPSIS

/etc/systemd/loader.conf, /usr/lib/systemd/loader.conf, /etc/systemd/loader.conf.d/*.conf, /usr/lib/systemd/loader.conf.d/*.conf

DESCRIPTION

The main configuration file for systemd-boot(7) is loaded from the files in the order specified in boot.5.

The file may contain boolean, numeric, or string options, and applies to all entries unless overridden by loader.conf(5) options.

The configuration options are described below. See also bootctl(1).

OPTIONS

timeout
Configures the menu timeout in seconds. If set to 0, the menu is not shown, and the default entry is booted immediately. A negative value means infinite timeout. Default is 3.
console-mode
Configures the console mode. Possible values are:
auto
Use the UEFI firmware's preferred console output. This is the default.
max
Use the maximum console resolution supported by the UEFI firmware.
WIDTHxHEIGHT
Use a specific console resolution.
default-title
Configures the title of the default entry. This is a string that is matched against the title= option in the entries. If multiple entries match, the first one is selected. If no entry matches, the first entry is selected.
editor
Configures whether the boot menu editor is enabled. The editor allows modifying the kernel command line.
yes
Enable the editor. Default.
no
Disable the editor.
auto-firmware-sync
Configures whether to synchronize firmware variables automatically. This option is only relevant if automatic enrollment of secure boot keys is enabled.
yes
Synchronize firmware variables. Default.
no
Do not synchronize firmware variables.
secure-boot-enroll
Configures whether to automatically enroll secure boot keys. If enabled, bootctl(1) will automatically generate and enroll platform keys (PK), key exchange keys (KEK), and the database of permitted signatures (db) upon first boot. This is highly recommended for systems with Secure Boot enabled.
yes
Enable automatic enrollment.
no
Disable automatic enrollment. Default.
secure-boot-enroll-action
Specifies the action to take after the automatic enrollment of secure boot keys is completed.
reboot
Reboot the system after enrollment. This is the default.
shutdown
Shut down the system after enrollment.
reboot-for-bitlocker
Caveat: This feature is experimental, and is likely to be changed (or removed in its current form) in a future version of systemd.

Work around BitLocker requiring a recovery key when the boot loader was updated (disabled by default).

Try to detect BitLocker encrypted drives along with an active TPM. If both are found and Windows Boot Manager is selected in the boot menu, set the "BootNext" EFI variable and restart the system. The firmware will then start Windows Boot Manager directly, leaving the TPM PCRs in expected states so that Windows can unseal the encryption key. This allows systemd-boot(7) to be updated without having to provide the recovery key for BitLocker drive unlocking.

Note that the PCRs that Windows uses can be configured with the "Configure TPM platform validation profile for native UEFI firmware configurations" group policy under "Computer Configuration\Administrative Templates\Windows Components\BitLocker Drive Encryption". When Secure Boot is enabled, changing this to PCRs "0,2,7,11" should be safe. The TPM key protector needs to be removed and then added back for the PCRs on an already encrypted drive to change. If PCR 4 is not measured, this setting can be disabled to speed up booting into Windows.

Added in version 251.

reboot-on-error
Controls auto reboot in case the selected entry fails to start.
yes
Reboot the system if the selected boot entry failed to start.
no
Don't reboot - pass control back to EFI firmware.
auto
Perform the reboot if and only if boot counting is enabled for this entry and the tries left counter wasn't already at 0.

This is the default, as it is typically a safe option, that ensures a clean measurement log on each boot attempt, but also does not risk an unbounded reboot loop.

This feature is considered dangerous because even if all the required files are signed with the keys being loaded, some files necessary for the system to function properly still won't be. This is especially the case with Option ROMs (e.g. for storage controllers or graphics cards). See Secure Boot and Option ROMs[5] for more details.

Added in version 252.

EXAMPLE

# /boot/efi/loader/loader.conf
timeout 0
default 01234567890abcdef1234567890abdf0-*
editor no

The menu will not be shown by default (the menu can still be shown by pressing and holding a key during boot). One of the entries with files with a name starting with "01234567890abcdef1234567890abdf0-" will be selected by default. If more than one entry matches, the one with the highest priority will be selected (generally the one with the highest version number). The editor will be disabled, so it is not possible to alter the kernel command line.

SECURE BOOT KEY GENERATION AND ENROLLMENT

uuid=$(systemd-id128 new --uuid)
for key in PK KEK db; do
  openssl req -new -x509 -subj "/CN=${key}/" -keyout "${key}.key" -out "${key}.pem"
  openssl x509 -outform DER -in "${key}.pem" -out "${key}.der"
  sbsiglist --owner "${uuid}" --type x509 --output "${key}.esl" "${key}.der"
done
# See also: Windows Secure Boot Key Creation and Management Guidance[4]
curl --location \
     "https://go.microsoft.com/fwlink/p/?linkid=321192" -o ms-db-2011.der \
     "https://go.microsoft.com/fwlink/p/?linkid=321185" -o ms-kek-2011.der \
     "https://go.microsoft.com/fwlink/p/?linkid=321194" -o ms-uefi-db-2011.der \
     "https://go.microsoft.com/fwlink/p/?linkid=2239776" -o ms-db-2023.der \
     "https://go.microsoft.com/fwlink/p/?linkid=2239775" -o ms-kek-2023.der \
     "https://go.microsoft.com/fwlink/p/?linkid=2239872" -o ms-uefi-db-2023.der
sha1sum -c <<END
580a6f4cc4e4b669b9ebdc1b2b3e087b80d0678d  ms-db-2011.der
31590bfd89c9d74ed087dfac66334b3931254b30  ms-kek-2011.der
46def63b5ce61cf8ba0de2e6639c1019d0ed14f3  ms-uefi-db-2011.der
45a0fa32604773c82433c3b7d59e7466b3ac0c67  ms-db-2023.der
459ab6fb5e284d272d5e3e6abc8ed663829d632b  ms-kek-2023.der
b5eeb4a6706048073f0ed296e7f580a790b59eaa  ms-uefi-db-2023.der
END
for key in ms-*.der; do
  sbsiglist --owner 77fa9abd-0359-4d32-bd60-28f4e78f784b --type x509 --output "${key%der}esl" "${key}"
done
# Optionally add Microsoft Windows certificates (needed to boot into Windows).
cat ms-db-*.esl >>db.esl
# Optionally add Microsoft UEFI certificates for firmware drivers / option ROMs and third-party
# boot loaders (including shim). This is highly recommended on real hardware as not including this
# may soft-brick your device (see next paragraph).
cat ms-uefi-*.esl >>db.esl
# Optionally add Microsoft KEK certificates. Recommended if either of the Microsoft keys is used as
# the official UEFI revocation database is signed with this key. The revocation database can be
# updated with fwupdmgr(1).
cat ms-kek-*.esl >>KEK.esl
attr=NON_VOLATILE,RUNTIME_ACCESS,BOOTSERVICE_ACCESS,TIME_BASED_AUTHENTICATED_WRITE_ACCESS
sbvarsign --attr "${attr}" --key PK.key --cert PK.pem --output PK.auth PK PK.esl
sbvarsign --attr "${attr}" --key PK.key --cert PK.pem --output KEK.auth KEK KEK.esl
sbvarsign --attr "${attr}" --key KEK.key --cert KEK.pem --output db.auth db db.esl

This is especially the case with Option ROMs (e.g. for storage controllers or graphics cards). See Secure Boot and Option ROMs[5] for more details.
