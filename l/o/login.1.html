LOGIN(1) Commandes utilisateur LOGIN(1)

NOM

login - démarrer une session sur le système

SYNTAXE

login [-p] [-h hôte] [-H] [-f nomutilisateur|nomutilisateur]

DESCRIPTION

login est utilisé lors de la connexion à un système. Si aucun argument n'est donné, login demande le nom d'utilisateur.

L'utilisateur est ensuite invité à saisir un mot de passe, le cas échéant. L'affichage est désactivé pour éviter de révéler le mot de passe. Seul un nombre limité d'échecs de mot de passe sont autorisés avant que login ne se termine et que le lien de communication ne soit rompu. Voir LOGIN_RETRIES dans la section ÉLÉMENTS DE FICHIER DE CONFIGURATION.

Si la gestion de l'expiration des mots de passe a été activée pour le compte, l'utilisateur peut être invité à saisir un nouveau mot de passe avant de continuer. Dans ce cas, l'ancien mot de passe doit être fourni et le nouveau mot de passe saisi avant de continuer. Veuillez vous référer à passwd(1) pour plus d'informations.

L'ID utilisateur et groupe seront définis selon leurs valeurs dans le fichier /etc/passwd. Il y a une exception si l'ID utilisateur est zéro. Dans ce cas, seul l'ID de groupe principal du compte est défini. Cela devrait permettre à l'administrateur système de se connecter même en cas de problèmes réseau. Les valeurs des variables d'environnement $HOME, $USER, $SHELL, $PATH, $LOGNAME et $MAIL sont définies selon les champs appropriés dans l'entrée du mot de passe. $PATH est par défaut /usr/local/bin:/bin:/usr/bin pour les utilisateurs normaux, et /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin pour root, si non configuré autrement.

La variable d'environnement $TERM sera préservée, si elle existe, sinon elle sera initialisée au type de terminal sur votre tty. D'autres variables d'environnement sont préservées si l'option -p est donnée.

Les variables d'environnement définies par PAM sont toujours préservées.

Ensuite, le shell de l'utilisateur est lancé. Si aucun shell n'est spécifié pour l'utilisateur dans /etc/passwd, alors /bin/sh est utilisé. Si le shell spécifié contient un espace, il est traité comme un script shell. S'il n'y a pas de répertoire personnel spécifié dans /etc/passwd, alors / est utilisé, suivi de la vérification .hushlogin comme décrit ci-dessous.

Si le fichier .hushlogin existe, alors une connexion "silencieuse" est effectuée. Cela désactive la vérification du courrier et l'affichage de la dernière heure de connexion et du message du jour. Sinon, si /var/log/lastlog existe, la dernière heure de connexion est affichée et la connexion actuelle est enregistrée.

OPTIONS

-p

Utilisé par getty(8) pour indiquer à login de préserver l'environnement. Voir aussi l'élément de fichier de configuration LOGIN_ENV_SAFELIST.

-f

Utilisé pour sauter une authentification de connexion. Cette option est généralement utilisée par la fonctionnalité de connexion automatique de getty(8).

-h

Utilisé par d'autres serveurs (comme telnetd(8)) pour passer le nom de l'hôte distant à login afin qu'il puisse être placé dans utmp et wtmp. Seul le superutilisateur est autorisé à utiliser cette option.

Notez que l'option -h a un impact sur le nom du service PAM. Le nom de service standard est login, mais avec l'option -h, le nom est remote. Il est nécessaire de créer des fichiers de configuration PAM appropriés (par exemple, /etc/pam.d/login et /etc/pam.d/remote).

-H

Utilisé par d'autres serveurs (par exemple, telnetd(8)) pour indiquer à login de supprimer l'affichage du nom d'hôte dans l'invite de connexion. Voir aussi LOGIN_PLAIN_PROMPT ci-dessous.

-h, --help

Afficher le texte d'aide et quitter.

-V, --version

Afficher la version et quitter.

ÉLÉMENTS DE FICHIER DE CONFIGURATION

login lit le fichier de configuration /etc/login.defs (voir login.defs(5)). Notez que le fichier de configuration peut être distribué avec un autre paquet (généralement shadow-utils). Les éléments de configuration suivants sont pertinents pour login :

MOTD_FILE (string)

Spécifie une liste de fichiers et de répertoires de "message du jour" séparée par des ":" à afficher lors de la connexion. Si le chemin spécifié est un répertoire, alors tous les fichiers avec l'extension .motd sont affichés dans l'ordre de version du répertoire.

La valeur par défaut est /usr/share/misc/motd:/run/motd:/etc/motd. Si l'élément MOTD_FILE est vide ou si une connexion silencieuse est activée, alors le message du jour n'est pas affiché. Notez que la même fonctionnalité est également fournie par le module PAM pam_motd(8).

Les répertoires dans MOTD_FILE sont pris en charge depuis la version 2.36.

Notez que login n'implémente aucun comportement de remplacement de nom de fichier comme pam_motd (voir aussi MOTD_FIRSTONLY), mais tout le contenu de tous les fichiers est affiché. Il est recommandé de conserver la logique supplémentaire dans les générateurs de contenu et d'utiliser /run/motd.d plutôt que de compter sur le comportement de remplacement codé en dur dans les outils système.

MOTD_FIRSTONLY (boolean)

Force login à arrêter l'affichage du contenu spécifié par MOTD_FILE après le premier élément accessible dans la liste. Notez qu'un répertoire est un élément dans ce cas. Cette option permet de configurer la sémantique de login pour être plus compatible avec pam_motd. La valeur par défaut est no.

LOGIN_ENV_SAFELIST (string)

Force login à protéger les variables d'environnement spécifiées si -p n'est pas utilisé. La valeur chaîne est une liste de noms de variables séparée par des virgules. Par exemple : "LANG,LC_MESSAGES,LC_COLLATE". La liste de sécurité est ignorée pour les variables d'environnement HOME, SHELL et USER.

LOGIN_PLAIN_PROMPT (boolean)

Indique à login de supprimer l'affichage du nom d'hôte dans l'invite login:. C'est une alternative à l'option de ligne de commande -H. La valeur par défaut est no.

LOGIN_TIMEOUT (nombre)

Temps maximum en secondes pour la connexion. La valeur par défaut est 60.

LOGIN_RETRIES (nombre)

Nombre maximum de tentatives de connexion en cas de mot de passe incorrect. La valeur par défaut est 3.

LOGIN_KEEP_USERNAME (boolean)

Indique à login de ne redemander le mot de passe que si l'authentification a échoué, mais que le nom d'utilisateur est valide. La valeur par défaut est no.

FAIL_DELAY (nombre)

Délai en secondes avant d'être autorisé à tenter à nouveau trois fois après un échec de connexion. La valeur par défaut est 5.

TTYPERM (string)

Les permissions du terminal. La valeur par défaut est 0600 ou 0620 si le groupe tty est utilisé. Voir aussi mesg(1).

TTYGROUP (string)

Le tty de connexion sera détenu par le TTYGROUP. La valeur par défaut est tty. Si le TTYGROUP n'existe pas, alors la propriété du terminal est définie sur le groupe primaire de l'utilisateur.

Le TTYGROUP peut être soit le nom d'un groupe soit un identifiant de groupe numérique. Voir aussi mesg(1).

HUSHLOGIN_FILE (string)

Si défini, ce fichier peut inhiber toute la conversation habituelle pendant la séquence de connexion. Si un chemin d'accès complet (par exemple, /etc/hushlogins) est spécifié, alors le mode silencieux sera activé si le nom ou le shell de l'utilisateur se trouve dans le fichier. Si ce fichier de connexion silencieuse global est vide, alors le mode silencieux sera activé pour tous les utilisateurs.

Si un chemin d'accès complet n'est pas spécifié, alors le mode silencieux sera activé si le fichier existe dans le répertoire personnel de l'utilisateur.

Par défaut, vérifie /etc/hushlogins et s'il n'existe pas, alors ~/.hushlogin.

Si l'élément HUSHLOGIN_FILE est vide, alors toutes les vérifications sont désactivées.

NOM

login - se connecter au système

SYNOPIS

login [-d device] [-h hostname] [-p] [-f user]

DESCRIPTION

La commande login initie la session de l'utilisateur. Elle demande le nom d'utilisateur et le mot de passe, puis démarre un shell de connexion. Elle est généralement appelée par getty(8) après qu'un utilisateur a accédé au système via un terminal. Elle peut également être appelée directement par un utilisateur pour démarrer une nouvelle session de connexion.

OPTIONS

-d device
Spécifie le périphérique du terminal. Utile si le terminal n'est pas correctement détecté par le système.
-h hostname
Spécifie le nom d'hôte distant. Cela est souvent utilisé pour enregistrer des informations de connexion pour des sessions distantes.
-p
Conserve toutes les variables d'environnement existantes. Ceci est généralement utilisé par les programmes qui appellent login, comme getty(8).
-f user
Force la connexion de l'utilisateur spécifié sans demander de mot de passe. Cette option doit être utilisée avec précaution car elle peut présenter un risque de sécurité.

CONFIG FILE ITEMS

Ces éléments de configuration se trouvent généralement dans le fichier /etc/login.defs.

ALWAYS_வுகள் (boolean)

Si défini sur yes, le répertoire personnel de l'utilisateur sera toujours créé s'il n'existe pas lors de la première connexion. La valeur par défaut est no.

CONSOLE (string)

Spécifie le périphérique de la console. Par défaut, il s'agit de /dev/tty0.

DEFAULT_HOME (boolean)

Indique si la connexion est autorisée si nous ne pouvons pas changer de répertoire vers le répertoire personnel. Si défini sur yes, l'utilisateur se connectera dans le répertoire racine (/) s'il n'est pas possible de changer de répertoire vers le sien. La valeur par défaut est yes.

LASTLOG_UID_MAX (nombre non signé)

Le numéro d'ID utilisateur le plus élevé pour lequel les entrées lastlog doivent être mises à jour. Comme les ID utilisateur plus élevés sont généralement suivis par des services d'authentification et d'identité utilisateur à distance, il n'est pas nécessaire de créer un fichier lastlog volumineux et épars pour eux. L'absence de l'option LASTLOG_UID_MAX dans la configuration signifie qu'il n'y a pas de limite d'ID utilisateur pour l'écriture des entrées lastlog. La valeur par défaut est ULONG_MAX.

LOG_UNKFAIL_ENAB (booléen)

Active l'affichage des noms d'utilisateur inconnus lorsque des échecs de connexion sont enregistrés. La valeur par défaut est no.

Notez que l'enregistrement des noms d'utilisateur inconnus peut poser un problème de sécurité si un utilisateur entre son mot de passe à la place de son nom d'utilisateur.

ENV_PATH (chaîne)

Si défini, il sera utilisé pour définir la variable d'environnement PATH lorsqu'un utilisateur régulier se connecte. La valeur par défaut est /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (chaîne), ENV_SUPATH (chaîne)

Si définis, ils seront utilisés pour définir la variable d'environnement PATH lorsque le superutilisateur se connecte. ENV_ROOTPATH a la priorité. La valeur par défaut est /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

FICHIERS

/var/run/utmp, /var/log/wtmp, /var/log/lastlog, /var/spool/mail/*, /etc/motd, /etc/passwd, /etc/nologin, /etc/pam.d/login, /etc/pam.d/remote, /etc/hushlogins, $HOME/.hushlogin

CREDENCIALS

login prend en charge la configuration via les identifiants systemd (voir https://systemd.io/CREDENTIALS/). login lit les identifiants systemd suivants :

login.noauth (booléen)

Si défini, configure login pour ignorer l'authentification de connexion, de manière similaire à l'option -f.

BOGUES

L'option BSD non documentée -r n'est pas prise en charge. Ceci peut être requis par certains programmes rlogind(8).

Une connexion récursive, qui était possible à l'époque, ne fonctionne plus ; pour la plupart des usages su(1) est un substitut satisfaisant. En effet, pour des raisons de sécurité, login effectue un appel système vhangup(2) pour supprimer tout processus potentiellement à l'écoute sur le tty. Ceci afin d'éviter le reniflement de mot de passe. Si l'on utilise la commande login, le shell environnant est tué par vhangup(2) car il n'est plus le véritable propriétaire du tty. Ceci peut être évité en utilisant exec login dans un shell de premier niveau ou un xterm.
