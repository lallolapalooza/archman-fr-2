LOSETUP(8) Administration système LOSETUP(8)

NOM

losetup - configurer et contrôler les périphériques de boucle

SYNTAXE

Obtenir des informations :

losetup [périphérique-de-boucle]

losetup -l [-a]

losetup -j fichier [-o décalage]

Détacher un périphérique de boucle :

losetup -d périphérique-de-boucle ...

Détacher tous les périphériques de boucle associés :

losetup -D

Configurer un périphérique de boucle :

losetup [-o décalage] [--sizelimit taille] [--sector-size taille] [--loop-ref nom] [-Pr] [--show] -f|périphérique-de-boucle fichier

Redimensionner un périphérique de boucle :

losetup -c périphérique-de-boucle

DESCRIPTION

losetup est utilisé pour associer des périphériques de boucle à des fichiers réguliers ou des périphériques de bloc, pour détacher des périphériques de boucle et pour interroger l'état d'un périphérique de boucle. Si seul l'argument périphérique-de-boucle est donné, l'état du périphérique de boucle correspondant est affiché. Si aucune option n'est donnée, tous les périphériques de boucle sont affichés.

Notez que l'ancien format de sortie (c'est-à-dire, losetup -a) avec des chaînes délimitées par des virgules est obsolète en faveur du format de sortie --list.

Il est possible de créer plusieurs périphériques de boucle indépendants pour le même fichier de support. Cette configuration peut être dangereuse, causer une perte de données, une corruption et des écrasements. Utilisez --nooverlap avec --find lors de la configuration pour éviter ce problème.

La configuration du périphérique de boucle n'est pas une opération atomique lorsqu'elle est utilisée avec --find, et losetup ne protège pas cette opération par un verrou. Le nombre de tentatives est intérieurement limité à un maximum de 16. Il est recommandé d'utiliser par exemple flock(1) pour éviter une collision dans des cas d'utilisation fortement parallèles.

OPTIONS

Les arguments taille et décalage peuvent être suivis des suffixes multiplicatifs KiB (=1024), MiB (=1024*1024), et ainsi de suite pour GiB, TiB, PiB, EiB, ZiB et YiB (le suffixe "iB" est facultatif, par exemple, "K" a la même signification que "KiB") ou les suffixes KB (=1000), MB (=1000*1000), et ainsi de suite pour GB, TB, PB, EB, ZB et YB.

-a, --all

Afficher l'état de tous les périphériques de boucle. Notez que toutes les informations ne sont pas accessibles aux utilisateurs non root. Voir aussi --list. L'ancien format de sortie (tel qu'affiché sans --list) est obsolète.

-d, --detach périphérique-de-boucle...

Détacher le fichier ou le périphérique associé au(x) périphérique(s) de boucle spécifié(s). Notez que depuis le noyau Linux v3.7, l'utilisation de la « destruction paresseuse de périphérique » est activée. L'opération de détachement ne renvoie plus une erreur EBUSY si le périphérique est activement utilisé par le système, mais il est marqué avec l'indicateur autoclear et détruit plus tard. Même si le périphérique n'est pas utilisé, le périphérique de boucle peut être détruit plus tard. Si vous devez attendre la suppression complète du périphérique de boucle, appelez udevadm settle après losetup.

-D, --detach-all

Détacher tous les périphériques de boucle associés.

-f, --find [fichier]

Trouver le premier périphérique de boucle inutilisé. Si un argument fichier est présent, utiliser le périphérique trouvé comme périphérique de boucle. Sinon, afficher simplement son nom.

--show

Afficher le nom du périphérique de boucle attribué si l'option -f et un argument fichier sont présents.

-L, --nooverlap

Vérifier les conflits entre les périphériques de boucle pour éviter une situation où le même fichier de support est partagé entre plusieurs périphériques de boucle. Si le fichier est déjà utilisé par un autre périphérique, réutiliser le périphérique plutôt qu'un nouveau. L'option n'a de sens qu'avec --find.

-j, --associated fichier [-o décalage]

Afficher l'état de tous les périphériques de boucle associés au fichier donné.

-o, --offset décalage

Le début des données est déplacé de décalage octets dans le fichier ou le périphérique spécifié. Le décalage peut être suivi des suffixes multiplicatifs ; voir ci-dessus.

--loop-ref chaîne

Définir une chaîne de référence. Par défaut, compatible avec l'arrière, le nom du fichier de support est utilisé comme référence dans l'ioctl de configuration de boucle (également appelé lo_file_name). Cette option peut écraser ce comportement par défaut et définir la référence à la chaîne. La référence peut être utilisée par udevd dans /dev/loop/by-ref. Le noyau Linux n'utilise pas la référence du tout, mais elle pourrait être utilisée par certains anciens utilitaires qui ne peuvent pas lire le fichier de support à partir de sysfs. La référence n'est lisible que par l'utilisateur root (voir --output +REF) et est limitée à 64 octets.

--sizelimit taille

La fin des données est définie à ne pas dépasser taille octets après le début des données. La taille peut être suivie des suffixes multiplicatifs ; voir ci-dessus.

-b, --sector-size taille

Définir la taille logique du secteur du périphérique de boucle en octets (depuis Linux 4.14). L'option peut être utilisée lors de la création d'un nouveau périphérique de boucle ainsi que comme commande autonome pour modifier la taille du secteur d'un périphérique de boucle déjà existant.

-c, --set-capacity périphérique-de-boucle

Forcer le pilote de boucle à relire la taille du fichier associé au périphérique de boucle spécifié.

-P, --partscan

Forcer le noyau à analyser la table de partition sur un périphérique de boucle nouvellement créé. Notez que l'analyse de la table de partition dépend des tailles de secteur. La taille de secteur par défaut est de 512 octets, sinon vous devez utiliser l'option --sector-size avec --partscan.

-r, --read-only

Configurer un périphérique de boucle en lecture seule.

--direct-io[=on|off]

Activer ou désactiver les E/S directes pour le fichier de support. La valeur par défaut est off. La spécification de --direct-io ou --direct-io=on l'activera. Cependant, --direct-io=off peut être fournie pour le désactiver explicitement.

-v, --verbose

Mode verbeux.

-l, --list

Si un périphérique de boucle ou l'option -a est spécifié, afficher les colonnes par défaut pour le périphérique de boucle spécifié ou pour tous les périphériques de boucle ; la valeur par défaut est d'afficher les informations sur tous les périphériques. Voir aussi --output, --noheadings, --raw, et --json.

-O, --output colonne[,colonne]...

Spécifier les colonnes qui doivent être affichées pour la sortie --list. Utilisez --help pour obtenir la liste de toutes les colonnes prises en charge.

--output-all

Afficher toutes les colonnes disponibles.

-n, --noheadings

Ne pas afficher d'en-têtes pour le format de sortie --list.

--raw

Utiliser le format de sortie --list brut.

-J, --json

Utiliser le format JSON pour la sortie --list.

CHIFFREMENT

Cryptoloop n'est plus supporté au profit de dm-crypt. Pour plus de détails, voir cryptsetup(8).

STATUT DE SORTIE

losetup renvoie 0 en cas de succès, une valeur non nulle en cas d'échec. Lorsque losetup affiche l'état d'un périphérique de boucle, il renvoie 1 si le périphérique n'est pas configuré et 2 en cas d'erreur qui a empêché la détermination de l'état du périphérique.

NOTES

Depuis la version 2.37, losetup utilise l'ioctl LOOP_CONFIGURE pour configurer un nouveau périphérique de boucle en un seul appel ioctl. Les anciennes versions utilisent les ioctls LOOP_SET_FD et LOOP_SET_STATUS64 pour faire de même.

EXAMPLE

Les commandes suivantes peuvent être utilisées comme exemple d'utilisation du périphérique loop.

# dd if=/dev/zero of=~/file.img bs=1024k count=10
# losetup --find --show ~/file.img
/dev/loop0
# mkfs -t ext2 /dev/loop0
# mount /dev/loop0 /mnt
...
# umount /dev/loop0
# losetup --detach /dev/loop0
