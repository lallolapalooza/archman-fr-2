LOGGER(1) Commandes utilisateur LOGGER(1)

NOM

logger - enregistre des messages dans le journal système

SYNTAXE

logger [options] message

DESCRIPTION

logger crée des entrées dans le journal système.

Lorsque l'argument optionnel message est présent, il est écrit dans le journal. S'il n'est pas présent, et si l'option -f n'est pas non plus spécifiée, l'entrée standard est enregistrée.

OPTIONS

-d, --udp

Utilise uniquement les datagrammes (UDP). Par défaut, la connexion est tentée vers le port syslog défini dans /etc/services, qui est souvent 514.

Voir aussi --server et --socket pour spécifier où se connecter.

-e, --skip-empty

Ignore les lignes vides lors du traitement des fichiers. Une ligne vide est définie comme une ligne sans aucun caractère. Ainsi, une ligne ne contenant que des espaces blancs N'EST PAS considérée comme vide. Notez que lorsque l'option --prio-prefix est spécifiée, la priorité ne fait pas partie de la ligne. Ainsi, une ligne vide dans ce mode est une ligne qui ne contient aucun caractère après le préfixe de priorité (par exemple, <13>).

-f, --file fichier

Enregistre le contenu du fichier spécifié. Cette option ne peut pas être combinée avec un message en ligne de commande.

-i

Enregistre le PID du processus logger avec chaque ligne.

--id[=id]

Enregistre le PID du processus logger avec chaque ligne. Lorsque l'argument optionnel id est spécifié, il est utilisé à la place du PID de la commande logger. L'utilisation de --id=$$ (PPID) est recommandée dans les scripts qui envoient plusieurs messages.

Notez que l'infrastructure de journalisation système (par exemple systemd lorsqu'il écoute sur /dev/log) peut suivre les identifiants de socket locaux pour écraser le PID spécifié dans le message. logger(1) est capable de définir ces identifiants de socket sur l'id donné, mais seulement si vous avez les permissions root et qu'un processus avec le PID spécifié existe, sinon les identifiants de socket ne sont pas modifiés et le problème est ignoré silencieusement.

--journald[=fichier]

Écrit une entrée dans le journal systemd. L'entrée est lue depuis le fichier donné, s'il est spécifié, sinon depuis l'entrée standard. Chaque ligne doit commencer par un champ accepté par journald ; voir systemd.journal-fields(7) pour les détails. L'utilisation d'un champ MESSAGE_ID est généralement une bonne idée, car elle facilite la recherche d'entrées. Exemples : 
logger --journald <<fin
MESSAGE_ID=67feb6ffbaf24c5cbec13c008dd72309
MESSAGE=Les chiens aboient, mais la caravane passe.
CHIENS=aboient
CARAVANE=passe
fin
logger --journald=entree.txt

Notez que --journald ignorera les valeurs des autres options, telles que la priorité. Si la priorité est nécessaire, elle doit être dans l'entrée et utiliser le champ PRIORITY. L'exécution simple de journalctl(1) affichera le champ MESSAGE. Utilisez journalctl --output json-pretty pour voir le reste des champs.

Pour inclure des sauts de ligne dans MESSAGE, spécifiez MESSAGE plusieurs fois. Ceci est géré comme un cas spécial, les autres champs seront stockés sous forme de tableau dans le journal s'ils apparaissent plusieurs fois.

--msgid msgid

Définit le champ MSGID de la norme RFC 5424 https://tools.ietf.org/html/rfc5424. Notez que l'espace n'est pas permis dans msgid. Cette option n'est utilisée que si --rfc5424 est également spécifié ; sinon, elle est ignorée silencieusement.

-n, --server serveur

Écrit sur le serveur syslog distant spécifié au lieu du socket du journal système. Sauf si --udp ou --tcp est spécifié, logger essaiera d'abord d'utiliser UDP, mais si cela échoue, une connexion TCP sera tentée.

--no-act

Fait tout sauf écrire le message de journal dans le journal système, et supprime la connexion au journal. Cette option peut être utilisée conjointement avec --stderr à des fins de test.

--octet-count

Utilise la méthode de cadrage par comptage d'octets RFC 6587 https://tools.ietf.org/html/rfc6587 pour envoyer des messages. Lorsque cette option n'est pas utilisée, la valeur par défaut est aucun cadrage sur UDP, et le cadrage non transparent RFC6587 (également connu sous le nom de bourrage d'octets) sur TCP.

-P, --port port

Utilise le port spécifié. Lorsque cette option n'est pas spécifiée, le port est par défaut syslog pour les connexions udp et syslog-conn pour les connexions tcp.

-p, --priority priorité

Enregistre le message dans le journal avec la priorité spécifiée. La priorité peut être spécifiée numériquement ou sous forme d'une paire facility.level. Par exemple, -p local3.info enregistre le message comme informationnel dans la facility local3. Par défaut, c'est user.notice.

--prio-prefix

Recherche un préfixe syslog sur chaque ligne lue depuis l'entrée standard. Ce préfixe est un nombre décimal entre crochets qui encode à la fois la facility et le niveau. Le nombre est construit en multipliant la facility par 8 puis en ajoutant le niveau. Par exemple, local0.info, signifiant facility=16 et level=6, devient <134>.

Si le préfixe ne contient pas de facility, la facility prend par défaut celle spécifiée par l'option -p. De même, si aucun préfixe n'est fourni, la ligne est enregistrée en utilisant la priorité donnée avec -p.

Cette option n'affecte pas un message en ligne de commande.

--rfc3164

Utilise le protocole syslog RFC 3164 https://tools.ietf.org/html/rfc3164 pour soumettre des messages à un serveur distant.

--rfc5424[=sans]

Utilise le protocole syslog RFC 5424 https://tools.ietf.org/html/rfc5424 pour soumettre des messages à un serveur distant. L'argument optionnel sans peut être une liste séparée par des virgules des valeurs suivantes : notq, notime, nohost.

La valeur notq supprime les données structurées timeQuality du message soumis. Les informations timeQuality indiquent si l'horloge locale était synchronisée plus le nombre maximum de microsecondes dont l'horodatage pouvait être décalé. La qualité temporelle est également supprimée automatiquement lorsque --sd-id timeQuality est spécifié.

La valeur notime (qui implique notq) supprime complètement l'horodatage de l'expéditeur au format ISO-8601, y compris les microsecondes et le fuseau horaire.

La valeur nohost supprime les informations de gethostname(2) de l'en-tête du message.

Le protocole RFC 5424 est le protocole par défaut pour logger depuis la version 2.26.

-s, --stderr

Affiche également le message sur la sortie d'erreur standard en plus du journal système.

--sd-id nom[@chiffres]

Spécifie un identifiant d'élément de données structurées pour un en-tête de message RFC 5424. L'option doit être utilisée avant --sd-param pour introduire un nouvel élément. Le nombre d'éléments de données structurées est illimité. L'identifiant (nom plus éventuellement @chiffres) est sensible à la casse et identifie de manière unique le type et le but de l'élément. Le même identifiant ne doit pas exister plus d'une fois dans un message. La partie @chiffres est requise pour les identifiants non standardisés définis par l'utilisateur.

logger génère actuellement uniquement l'élément standardisé timeQuality. RFC 5424 décrit également les éléments origin (avec les paramètres ip, enterpriseId, software et swVersion) et meta (avec les paramètres sequenceId, sysUpTime et language). Ces identifiants d'éléments peuvent être spécifiés sans le suffixe @chiffres.

--sd-param nom=valeur

Spécifie un paramètre structuré

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

structured data element parameter, un nom et une paire valeur. L'option doit être utilisée après --sd-id et peut être spécifiée plusieurs fois pour le même élément. Notez que les guillemets autour de value sont requis et doivent être échappés sur la ligne de commande. 
    logger --rfc5424 --sd-id zoo@123             \
                     --sd-param tiger="hungry"   \
                     --sd-param zebra="running"  \
                     --sd-id manager@123         \
                     --sd-param onMeeting="yes"  \
                     "this is message"

produit :

<13>1 2015-10-01T14:07:59.168662+02:00 ws kzak - - [timeQuality tzKnown="1" isSynced="1" syncAccuracy="218616"][zoo@123 tiger="hungry" zebra="running"][manager@123 onMeeting="yes"] this is message

-S, --size taille

Définit la taille maximale autorisée du message à taille. La valeur par défaut est de 1 Kio, ce qui est la limite traditionnellement utilisée et spécifiée dans la RFC 3164. Avec la RFC 5424, cette limite est devenue flexible. Une bonne hypothèse est que les récepteurs RFC 5424 peuvent traiter au moins des messages de 4 Kio.

La plupart des récepteurs acceptent des messages plus grands que 1 Kio sur tout type de protocole syslog. Ainsi, l'option --size affecte logger dans tous les cas (pas seulement lorsque --rfc5424 a été utilisé).

Note : la limite de taille de message limite la taille globale du message, y compris l'en-tête syslog. La taille des en-têtes varie en fonction des options sélectionnées et de la longueur du nom d'hôte. En règle générale, les en-têtes ne dépassent pas 50 à 80 caractères. Lors de la sélection d'une taille de message maximale, il est important de s'assurer que le récepteur prend également en charge la taille maximale, sinon les messages peuvent être tronqués. Encore une fois, en règle générale, une taille de message de deux à quatre Kio devrait être acceptable, tandis que tout ce qui est plus grand doit être vérifié pour s'assurer qu'il fonctionne.

--socket-errors mode

Affiche les erreurs concernant les connexions de sockets Unix. Le mode peut être on, off, ou auto. Lorsque le mode est auto (la valeur par défaut), logger détecte si le processus d'initialisation est systemd(1), et si c'est le cas, on suppose que /dev/log peut être utilisé tôt au démarrage. L'absence de /dev/log sur d'autres systèmes d'initialisation ne provoquera pas d'erreurs, tout comme lors de l'utilisation de l'appel système openlog(3). Le logger(1) avant la version 2.26 utilisait openlog(3), et était donc incapable de détecter la perte de messages envoyés à des sockets Unix.

Lorsque les erreurs ne sont pas activées, les messages perdus ne sont pas communiqués et entraîneront une sortie réussie de logger(1).

-T, --tcp

Utilise uniquement le flux (TCP). Par défaut, la connexion est tentée vers le port syslog-conn défini dans /etc/services, qui est souvent 601.

Voir aussi --server et --socket pour spécifier où se connecter.

-t, --tag tag

Marque chaque ligne à enregistrer avec le tag spécifié. Le tag par défaut est le nom de l'utilisateur connecté au terminal (ou un nom d'utilisateur basé sur l'ID utilisateur effectif).

-u, --socket socket

Écrit dans le socket spécifié au lieu du socket système du journal.

--

Termine la liste des arguments. Cela permet au message de commencer par un tiret (-).

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

STATUT DE SORTIE

L'utilitaire logger se termine avec le code 0 en cas de succès, et >0 si une erreur se produit.

auth
authpriv pour les informations de sécurité sensibles
cron

daemon
ftp

emerg
alert
crit
err
warning
notice
info
debug

error synonyme déprécié pour err
warn synonyme déprécié pour warning

Pour l'ordre de priorité et les objectifs de ces facilities et niveaux, voir syslog(3).

CONFORMITÉ

La commande logger est censée être compatible avec la norme IEEE Std 1003.2 ("POSIX.2").

EXEMPLES

logger System rebooted

logger -p local0.notice -t HOSTIDM -f /dev/idmc

logger -n loghost.example.com System rebooted
