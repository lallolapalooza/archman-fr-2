Définition à la ligne 166 du fichier lo_types.h.

typedef int(* lo_bundle_start_handler) (lo_timetag time, void *user_data)

Une fonction de rappel pour recevoir la notification qu'un paquet est en cours de dispatch par le serveur ou le thread de serveur. Cette fonction de rappel permet aux applications d'être informées des paquets entrants et de préserver l'ordre et l'atomicité des messages dans les paquets.

Si elle est installée avec lo_server_add_bundle_handlers, cette fonction de rappel sera appelée avec time défini sur l'horodatage du paquet, et user_data défini sur le paramètre user_data passé à lo_server_add_bundle_handlers.

Notez que les paquets peuvent être imbriqués, dans ce cas les appels aux fonctions de rappel de début et de fin de paquet seront également imbriqués. L'application peut suivre les paquets imbriqués de manière similaire à une pile en traitant la fonction de rappel de début comme un "push" et la fonction de rappel de fin comme un "pop". Par exemple, un paquet contenant deux paquets déclenchera 6 appels de fonction de rappel : début, début, fin, début, fin, fin.

Définition à la ligne 77 du fichier lo_types.h.

typedef int(* lo_method_handler) (const char *path, const char *types, lo_arg **argv, int argc, lo_message msg, void *user_data)

Une fonction de rappel

Fonction pour recevoir la notification d'un message correspondant arrivant dans le serveur ou le thread du serveur. La valeur de retour indique au méthode dispatcher si ce gestionnaire a traité le message correctement : une valeur de retour de 0 indique qu'il a été géré, et il ne devrait pas tenter de le transmettre à d'autres gestionnaires, une valeur non nulle signifie qu'il n'a pas été géré et que le dispatcher tentera de trouver d'autres gestionnaires correspondant au chemin et aux types du message entrant.

Lors du rappel, les paramètres seront définis aux valeurs suivantes :

Paramètres

path Le chemin sur lequel le message entrant a été envoyé
types Si vous avez spécifié des types dans votre appel de création de méthode, cela correspondra à ceux-ci et les types entrants auront été coercés pour correspondre, sinon ce seront les types des arguments du message entrant.
argv Un tableau de types lo_arg contenant les valeurs, par exemple, si le premier argument du message entrant est de type 'f', la valeur sera trouvée dans argv[0]->f.
argc Le nombre d'arguments reçus.
msg Une structure contenant le message brut original tel qu'il a été reçu. Aucune coercition de type ne se sera produite et les données seront dans l'ordre des octets OSC (bigendian).
user_data Ceci contient la valeur user_data passée dans l'appel à lo_server_thread_add_method.

typedef void(* lo_server_thread_cleanup_callback) (lo_server_thread s, void *user_data)

Une fonction de rappel pour effectuer le nettoyage lorsque le thread du serveur est démarré. Si elle est installée avec lo_server_thread_set_callbacks, cette fonction de rappel sera appelée dans le thread du serveur, après que le serveur ait arrêté d'écouter et de traiter les événements, avant de se terminer. user_data est défini sur le paramètre user_data passé à lo_server_thread_add_functions.

Définition à la ligne 192 du fichier lo_types.h.

typedef int(* lo_server_thread_init_callback) (lo_server_thread s, void *user_data)

Une fonction de rappel pour effectuer l'initialisation lorsque le thread du serveur est démarré. Si elle est installée avec lo_server_thread_set_callbacks, cette fonction de rappel sera appelée dans le thread du serveur, juste avant que le serveur ne commence à écouter les événements. user_data est défini sur le paramètre user_data passé à lo_server_thread_add_functions.

Si la valeur de retour est non nulle, le démarrage du thread sera interrompu.
