LOCAL(8) Manuel de l'administrateur système LOCAL(8)

NOM

local - consegna di posta locale di Postfix

SYNTAXE

local [opzioni generiche del demone Postfix]

DESCRIZIONE


Il demone local(8) processa le richieste di consegna dal gestore della coda di Postfix per consegnare la posta ai destinatari locali. Ogni richiesta di consegna specifica un file di coda, un indirizzo del mittente, un dominio o un host a cui consegnare, e uno o più destinatari. Questo programma si aspetta di essere eseguito dal gestore del demone master(8).

Il demone local(8) aggiorna i file di coda e segna i destinatari come completati, oppure informa il gestore della coda che la consegna dovrebbe essere riprovata in un secondo momento. I rapporti sullo stato della consegna vengono inviati ai demoni bounce(8), defer(8) o trace(8), a seconda dei casi.

FOLDING DELLA CASELLA

Tutte le decisioni di consegna vengono prese utilizzando il nome del destinatario nudo (cioè la parte locale dell'indirizzo), convertito in minuscolo. Vedere anche sotto ESTENSIONE DELL'INDIRIZZO per alcune eccezioni.

ALIAS A LIVELLO DI SISTEMA E UTENTE

L'amministratore di sistema può configurare uno o più database di alias in stile sendmail a livello di sistema. Gli utenti possono avere file ~.forward in stile sendmail. La posta per nome viene consegnata all'alias nome, alle destinazioni in ~nome/.forward, alla casella di posta posseduta dall'utente nome, oppure viene restituita come non recapitabile.

L'amministratore di sistema può specificare un elenco di file simili a ~/.forward separati da virgole/spazi tramite il parametro di configurazione forward_path. Alla consegna, l'agente di consegna locale prova ogni percorso nell'elenco finché non trova un file.

La consegna tramite file ~/.forward viene eseguita con i privilegi del destinatario. Pertanto, i file simili a ~/.forward devono essere leggibili dal destinatario, e la loro directory padre deve avere il permesso di "esecuzione" per il destinatario.

Il parametro forward_path è soggetto all'interpolazione di $user (nome utente del destinatario), $home (directory home del destinatario), $shell (shell del destinatario), $recipient (indirizzo completo del destinatario), $extension (estensione dell'indirizzo del destinatario), $domain (dominio del destinatario), $local (parte locale dell'indirizzo completo del destinatario) e $recipient_delimiter. Le forme ${name?value} e ${name?{value}} (Postfix 3.0 e successivi) si espandono condizionalmente a value quando $name è definito, e le forme ${name:value} ${name:{value}} (Postfix 3.0 e successivi) si espandono condizionalmente a value quando $name non è definito. La forma ${name?{value1}:{value2}} (Postfix 3.0 e successivi) si espande condizionalmente a value1 quando $name è definito, o value2 altrimenti. I caratteri che possono avere un significato speciale per la shell o il file system vengono sostituiti con underscore. L'elenco dei caratteri accettabili è specificato dal parametro di configurazione forward_expansion_filter.

Un alias o un file ~/.forward può elencare qualsiasi combinazione di comandi esterni, nomi di file di destinazione, direttive :include: o indirizzi email. Vedere aliases(5) per una descrizione precisa. Ogni riga nel file .forward di un utente ha la stessa sintassi della parte destra di un alias.

Quando un indirizzo viene trovato nella sua espansione di alias, la consegna viene effettuata all'utente invece che all'alias. Quando un utente è elencato nel file ~/.forward dell'utente stesso, la consegna viene effettuata alla casella di posta dell'utente invece che all'alias. Un file ~/.forward vuoto significa non inoltrare la posta.

Per evitare che il sistema di posta consumi una quantità irragionevole di memoria, i record di input letti da :include: o dai file ~/.forward vengono suddivisi in blocchi di lunghezza line_length_limit.

Durante l'espansione degli alias, dei file ~/.forward e così via, il programma tenta di evitare consegne duplicate. Il parametro di configurazione duplicate_filter_limit limita il numero di destinatari memorizzati.

INOLTRO POSTA

Per motivi di affidabilità, la posta inoltrata viene reinserita come nuovo messaggio, in modo che ogni destinatario abbia un record di stato di consegna separato.

Per interrompere in anticipo i cicli di inoltro della posta, il software aggiunge un'intestazione opzionale Delivered-To: con l'indirizzo del destinatario finale della busta. Se arriva posta per un destinatario già elencato in un'intestazione Delivered-To:, il messaggio viene respinto.

CONSEGNA CASELLA POSTALE

La casella di posta predefinita per utente è un file nella directory dello spool della posta UNIX (/var/mail/utente o /var/spool/mail/utente); la posizione può essere specificata tramite il parametro di configurazione mail_spool_directory. Specificare un nome che termina con / per la consegna in stile maildir compatibile con qmail.

In alternativa, la casella di posta per utente può essere un file nella directory home dell'utente con un nome specificato tramite il parametro di configurazione home_mailbox. Specificare un nome di percorso relativo. Specificare un nome che termina con / per la consegna in stile maildir compatibile con qmail.

La consegna della casella di posta può essere delegata a un comando esterno specificato tramite i parametri di configurazione mailbox_command_maps e mailbox_command. Il comando viene eseguito con i privilegi dell'utente destinatario (eccezioni: i gruppi secondari non sono abilitati; in caso di consegna come root, il comando viene eseguito con i privilegi di default_privs).

La consegna della casella di posta può essere delegata a trasporti di messaggi alternativi specificati nel file master.cf. I parametri di configurazione mailbox_transport_maps e mailbox_transport specificano un trasporto di messaggi opzionale da utilizzare per tutti i destinatari locali, indipendentemente dal fatto che siano trovati nel database passwd di UNIX. I parametri fallback_transport_maps e fallback_transport specificano un trasporto di messaggi opzionale per i destinatari non trovati nel database degli alias (5) o nel database passwd di UNIX.

Nel caso di consegna di casella postale in stile UNIX, il demone local(8) premette un'intestazione di busta "From mittente timestamp" a ciascun messaggio, premette un'intestazione X-Original-To: con l'indirizzo del destinatario come fornito a Postfix, premette un'intestazione Delivered-To: opzionale con l'indirizzo del destinatario finale della busta, premette un'intestazione Return-Path: con l'indirizzo del mittente della busta, premette un carattere > alle righe che iniziano con "From ", e aggiunge una riga vuota. La casella di posta viene bloccata per accesso esclusivo durante la consegna. In caso di problemi, viene fatto un tentativo di troncare la casella di posta alla sua lunghezza originale.

Nel caso di consegna in stile maildir, il demone locale premette un'intestazione Delivered-To: opzionale con l'indirizzo del destinatario finale della busta, premette un'intestazione X-Original-To: con l'indirizzo del destinatario come fornito a Postfix, e premette un'intestazione Return-Path: con l'indirizzo del mittente della busta.

CONSEGNA COMANDI ESTERNI

Il parametro di configurazione allow_mail_to_commands limita la consegna a comandi esterni. L'impostazione predefinita (alias, forward) vieta le destinazioni di comandi nei file :include:.

Opzionalmente, la directory di lavoro del processo viene cambiata nel percorso specificato con command_execution_directory (Postfix 2.2 e successivi). Il fallimento del cambio di directory causa il rinvio della posta.

Il valore del parametro command_execution_directory è soggetto all'interpolazione di $user (nome utente del destinatario), $home (directory home del destinatario), $shell (shell del destinatario), $recipient (indirizzo completo del destinatario), $extension (estensione dell'indirizzo del destinatario), $domain (dominio del destinatario), $local (parte locale dell'indirizzo completo del destinatario) e $recipient_delimiter. Le forme ${name?value} e ${name?{value}} (Postfix 3.0 e successivi) si espandono condizionalmente a value quando $name è definito, e le forme ${name:value} e ${name:{value}} (Postfix 3.0 e successivi) si espandono condizionalmente a value quando $name non è definito.

La forme ${name?{valeur1}:{valeur2}} (Postfix 3.0 et versions ultérieures) s'étend conditionnellement à valeur1 lorsque $name est défini, ou à valeur2 sinon. Les caractères susceptibles d'avoir une signification spéciale pour le shell ou le système de fichiers sont remplacés par des traits de soulignement. La liste des caractères acceptables est spécifiée avec le paramètre de configuration execution_directory_expansion_filter.

La commande est exécutée directement lorsque c'est possible. L'assistance du shell (/bin/sh sur les systèmes UNIX) n'est utilisée que lorsque la commande contient des caractères magiques de shell, ou lorsque la commande invoque une commande intégrée au shell.

Une quantité limitée de sortie de commande (sortie standard et erreur standard) est capturée pour être incluse dans les rapports d'état de non-livraison. Une commande est terminée de force si elle ne se termine pas dans le délai de command_time_limit secondes. Les codes d'état de sortie des commandes sont censés suivre les conventions définies dans <sysexits.h>. Le code de sortie 0 signifie une achèvement normal et réussi.

Postfix version 2.3 et versions ultérieures prennent en charge les codes d'état améliorés de style RFC 3463. Si une commande se termine avec un état de sortie non nul, et que la sortie de la commande commence par un code d'état amélioré, ce code d'état a la priorité sur l'état de sortie non nul.

Une quantité limitée de contexte de message est exportée via des variables d'environnement. Les caractères susceptibles d'avoir une signification spéciale pour le shell sont remplacés par des traits de soulignement. La liste des caractères acceptables est spécifiée avec le paramètre de configuration command_expansion_filter.

Le répertoire de travail courant est le répertoire de la file d'attente de messagerie.

Le démon local(8) ajoute un en-tête d'enveloppe "From expéditeur horodatage" à chaque message, ajoute un en-tête X-Original-To: avec l'adresse du destinataire telle que donnée à Postfix, ajoute un en-tête facultatif Delivered-To: avec l'adresse finale du destinataire de l'enveloppe, ajoute un en-tête Return-Path: avec l'adresse de l'expéditeur de l'enveloppe, et n'ajoute pas de ligne vide.

LIVRAISON VERS DES FICHIERS EXTERNES

Le format de livraison dépend de la syntaxe du nom du fichier de destination. Le format par défaut est le format de boîte aux lettres de style UNIX. Spécifiez un nom se terminant par / pour une livraison de style maildir compatible qmail.

Le paramètre de configuration allow_mail_to_files restreint la livraison aux fichiers externes. Le réglage par défaut (alias, forward) interdit les destinations de fichiers dans les fichiers :include:.

Dans le cas de la livraison au format de boîte aux lettres de style UNIX, le démon local(8) ajoute un en-tête d'enveloppe "From expéditeur horodatage" à chaque message, ajoute un en-tête X-Original-To: avec l'adresse du destinataire telle que donnée à Postfix, ajoute un en-tête facultatif Delivered-To: avec l'adresse finale du destinataire de l'enveloppe, ajoute un caractère > aux lignes commençant par "From ", et ajoute une ligne vide. L'adresse de l'expéditeur de l'enveloppe est disponible dans l'en-tête Return-Path:. Lorsque la destination est un fichier régulier, il est verrouillé pour un accès exclusif pendant la livraison. En cas de problèmes, une tentative est faite pour tronquer un fichier régulier à sa longueur d'origine.

Dans le cas de la livraison maildir, le démon local ajoute un en-tête facultatif Delivered-To: avec l'adresse finale du destinataire de l'enveloppe, et ajoute un en-tête X-Original-To: avec l'adresse du destinataire telle que donnée à Postfix. L'adresse de l'expéditeur de l'enveloppe est disponible dans l'en-tête Return-Path:.

EXTENSION D'ADRESSE

Le paramètre de configuration facultatif recipient_delimiter spécifie comment séparer les extensions d'adresse des noms de destinataires locaux.

Par exemple, avec "recipient_delimiter = +", les courriels destinés à nom+foo sont livrés à l'alias nom+foo ou à l'alias nom, aux destinations listées dans ~nom/.forward+foo ou dans ~nom/.forward, à la boîte aux lettres appartenant à l'utilisateur nom, ou ils sont renvoyés comme non livrables.

DROITS DE LIVRAISON

Les livraisons à des fichiers externes et à des commandes externes sont effectuées avec les droits de l'utilisateur destinataire pour lequel la livraison est effectuée. En l'absence de contexte utilisateur, le démon local(8) utilise les droits du propriétaire du fichier :include: ou de la base de données d'alias. Lorsque ces fichiers appartiennent au superutilisateur, la livraison est effectuée avec les droits spécifiés par le paramètre de configuration default_privs.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8). Les fichiers de messages corrompus sont marqués afin que le gestionnaire de file d'attente puisse les déplacer ultérieurement dans la file d'attente corrupt.

Selon le réglage du paramètre notify_classes, le postmaster est informé des rejets et d'autres problèmes.

SÉCURITÉ

L'agent de livraison local(8) nécessite une double personnalité : 1) pour accéder à la file d'attente privée de Postfix et aux mécanismes IPC, 2) pour usurper l'identité du destinataire et livrer à des fichiers ou commandes spécifiés par le destinataire. Il est donc sensible à la sécurité.

L'agent de livraison local(8) désapprouve la substitution d'expression régulière de $1 etc. dans alias_maps, car cela ouvrirait une faille de sécurité.

L'agent de livraison local(8) ignorera silencieusement les demandes d'utilisation du serveur proxymap(8) dans alias_maps. Il ouvrira plutôt la table directement. Avant la version 2.2 de Postfix, l'agent de livraison local(8) se terminera par une erreur fatale.

BOGUES


Pour des raisons de sécurité, l'état de livraison des messages des commandes externes ou des fichiers externes n'est jamais validé dans un fichier. Par conséquent, le programme peut occasionnellement livrer plus d'une fois à une commande ou à un fichier externe. Mieux vaut être prudent que désolé.

Les alias mutuellement récursifs ou les fichiers ~/.forward ne sont pas détectés précocement. La boucle de redirection de courrier résultante est interrompue par l'utilisation de l'en-tête de message Delivered-To:.

PARAMÈTRES DE CONFIGURATION

Les modifications apportées à main.cf sont automatiquement prises en compte, car les processus local(8) s'exécutent pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer un changement.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

Le temps qu'un processus démon Postfix peut prendre pour traiter une requête avant d'être terminé par un timer de surveillance intégré.
delay_logging_resolution_limit (2)
Le nombre maximal de chiffres après la virgule lors de la journalisation des valeurs de délai.
export_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix exportera vers des processus non-Postfix.
ipc_timeout (3600s)
La limite de temps pour envoyer ou recevoir des informations sur un canal de communication interne.
local_command_shell (vide)
Programme shell optionnel pour la livraison par local(8) à des commandes non-Postfix.
max_idle (100s)
La durée maximale pendant laquelle un processus démon Postfix inactif attend une connexion entrante avant de se terminer volontairement.
max_use (100)
Le nombre maximal de connexions entrantes qu'un processus démon Postfix servira avant de se terminer volontairement.
prepend_delivered_header (command, file, forward)
Les contextes de livraison de messages où l'agent de livraison local(8) de Postfix ajoute un en-tête de message Delivered-To: avec l'adresse à laquelle le courrier a été livré.
process_id (en lecture seule)
L'identifiant de processus d'une commande ou d'un processus démon Postfix.
process_name (en lecture seule)
Le nom du processus d'une commande ou d'un processus démon Postfix.
propagate_unmatched_extensions (canonical, virtual)
Quelles tables de recherche d'adresses copient une extension d'adresse de la clé de recherche vers le résultat de la recherche.
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente principal de Postfix.
recipient_delimiter (vide)
L'ensemble des caractères qui peuvent séparer la partie locale d'une adresse e-mail, un nom d'utilisateur ou un nom de fichier .forward de son extension.
require_home_directory (no)
Exiger que le répertoire personnel d'un destinataire local(8) existe avant de tenter la livraison du courrier.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix version 3.3 et ultérieures:

enable_original_recipient (yes)
Activer le support de l'adresse du destinataire d'origine après qu'une adresse a été réécrite vers une adresse différente (par exemple avec un alias ou un mappage canonique).
service_name (en lecture seule)
Le nom du service master.cf d'un processus démon Postfix.

Disponible dans Postfix 3.5 et ultérieures:

info_log_address_format (external)
La forme de l'adresse e-mail qui sera utilisée dans la journalisation non-débogage (info, warning, etc.).
