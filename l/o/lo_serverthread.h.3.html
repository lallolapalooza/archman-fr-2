Documentation des fonctions

lo_method lo_server_thread_add_method (lo_server_thread st, const char * path, const char * typespec, lo_method_handler h, const void * user_data)

Ajoute une méthode OSC au thread serveur spécifié.

Paramètres

st Le thread serveur auquel la méthode doit être ajoutée.
path Le chemin OSC auquel enregistrer la méthode. Si NULL est passé, la méthode correspondra à tous les chemins.
typespec Le typespec que la méthode accepte. Les messages entrants avec des typespecs similaires (par exemple, ceux avec des types numériques à la même position) seront coercés vers le typespec donné ici.
h La fonction de rappel du gestionnaire de méthode qui sera appelée si un message correspondant est reçu.
user_data Une valeur qui sera passée à la fonction de rappel, h, lorsqu'elle sera invoquée en correspondance avec cette méthode.

int lo_server_thread_del_lo_method (lo_server_thread st, lo_method m)

Supprime une méthode OSC du thread serveur spécifié.

Paramètres

st Le thread serveur dont la méthode doit être supprimée.
m L'identifiant lo_method retourné par lo_server_add_method pour la méthode à supprimer du serveur.

Retours

Non nul si elle n'a pas été trouvée dans la liste des méthodes pour le serveur.

void lo_server_thread_del_method (lo_server_thread st, const char * path, const char * typespec)

Supprime une méthode OSC du thread serveur spécifié.

Paramètres

st Le thread serveur dont la méthode doit être supprimée.
path Le chemin OSC de la méthode à supprimer. Si NULL est passé, la méthode correspondra au gestionnaire générique.
typespec Le typespec que la méthode accepte.

int lo_server_thread_events_pending (lo_server_thread st)

Retourne vrai s'il y a des événements programmés (par exemple, à partir de paquets) en attente d'être traités par le thread.

void lo_server_thread_free (lo_server_thread st)

Libère la mémoire utilisée par un thread serveur. Libère la mémoire et, si le thread est actuellement en cours d'exécution, arrête le thread associé.

int lo_server_thread_get_port (lo_server_thread st)

Retourne le numéro de port auquel le thread serveur s'est lié.

lo_server lo_server_thread_get_server (lo_server_thread st)

Retourne le lo_server d'un lo_server_thread. Cette fonction est utile pour passer le lo_server d'un thread à lo_send_from().

char * lo_server_thread_get_url (lo_server_thread st)

Retourne une URL décrivant l'adresse du thread serveur. La valeur de retour doit être libérée avec free() pour récupérer la mémoire.

lo_server_thread lo_server_thread_new (const char * port, lo_err_handler err_h)

Crée un nouveau thread serveur pour gérer les messages OSC entrants. Les threads serveurs prennent en charge la réception et la distribution des messages en créant de manière transparente un thread système pour gérer les messages entrants. Utilisez ceci si vous ne souhaitez pas gérer le threading vous-même.

Paramètres

port Si NULL est passé, un port inutilisé sera choisi par le système, son numéro peut être récupéré avec lo_server_thread_get_port() afin qu'il puisse être passé aux clients. Sinon, un numéro de port décimal, un nom de service ou un chemin de socket de domaine UNIX peut être passé.
err_h Une fonction qui sera appelée en cas d'erreur. Le prototype de la fonction est défini dans lo_types.h

lo_server_thread lo_server_thread_new_multicast (const char * group, const char * port, lo_err_handler err_h)

Crée un nouveau thread serveur pour gérer les messages OSC entrants, et rejoint un groupe multicast UDP. Les threads serveur s'occupent de la réception et de la distribution des messages en créant de manière transparente un thread système pour gérer les messages entrants. Utilisez ceci si vous ne souhaitez pas gérer le multithreading vous-même.

Paramètres

group Le groupe multicast à rejoindre. Voir la documentation sur le multicast IP pour la plage d'adresses acceptable ; par exemple, http://tldp.org/HOWTO/Multicast-HOWTO-2.html
port Si NULL est passé, un port inutilisé sera choisi par le système, son numéro pourra être récupéré avec lo_server_thread_get_port() afin qu'il puisse être passé aux clients. Sinon, un numéro de port décimal, un nom de service ou un chemin de socket de domaine UNIX peut être passé.
err_h Une fonction qui sera appelée en cas d'erreur. Le prototype de la fonction est défini dans lo_types.h

lo_server_thread lo_server_thread_new_multicast_iface (const char * group, const char * port, const char * iface, const char * ip, lo_err_handler err_h)

Crée une nouvelle instance de thread serveur et rejoint un groupe multicast UDP, en spécifiant éventuellement quelle interface réseau utiliser. Notez que généralement seul l'un des deux, iface ou ip, est spécifié.

Paramètres

group Le groupe multicast à rejoindre. Voir la documentation sur le multicast IP pour la plage d'adresses acceptable ; par exemple, http://tldp.org/HOWTO/Multicast-HOWTO-2.html
port Si UDP est utilisé, NULL peut être passé pour trouver un port inutilisé. Sinon, un numéro de port décimal ou un nom de service peut être passé. Si des sockets de domaine UNIX sont utilisés, un chemin de socket doit être passé ici.
iface Une chaîne spécifiant le nom d'une interface réseau à utiliser, ou zéro si non spécifié.
ip Une chaîne spécifiant l'adresse IP d'une interface réseau à utiliser, ou zéro si non spécifié.
err_h Une fonction de rappel d'erreur qui sera appelée en cas d'erreur lors de la réception des messages ou de la création du serveur. Passez NULL si vous ne souhaitez pas de gestion des erreurs.

lo_server_thread lo_server_thread_new_with_proto (const char * port, int proto, lo_err_handler err_h)

Crée un nouveau thread serveur pour gérer les messages OSC entrants, en spécifiant le protocole. Les threads serveur s'occupent de la réception et de la distribution des messages en créant de manière transparente un thread système pour gérer les messages entrants. Utilisez ceci si vous ne souhaitez pas gérer le multithreading vous-même.

Paramètres

port Si NULL est passé, un port inutilisé sera choisi par le système, son numéro pourra être récupéré avec lo_server_thread_get_port() afin qu'il puisse être passé aux clients. Sinon, un numéro de port décimal, un nom de service ou un chemin de socket de domaine UNIX peut être passé.
proto Le protocole à utiliser, doit être l'un de LO_UDP, LO_TCP ou LO_UNIX.
err_h Une fonction qui sera appelée en cas d'erreur. Le prototype de la fonction est défini dans lo_types.h

void lo_server_thread_set_callbacks (lo_server_thread st, lo_server_thread_init_callback init, lo_server_thread_cleanup_callback cleanup, void * user_data)

Définit une fonction d'initialisation et/ou de nettoyage pour le thread serveur spécifié. Pour avoir un effet, cela doit être appelé avant que le thread serveur ne soit démarré.

Paramètres

st Le thread serveur auquel la méthode doit être ajoutée.
init La fonction d'initialisation qui sera appelée juste après le démarrage du thread. Peut être NULL.
cleanup La fonction de nettoyage qui sera appelée juste avant la sortie du thread. Peut être NULL.
user_data Une valeur qui sera passée aux fonctions de rappel.
