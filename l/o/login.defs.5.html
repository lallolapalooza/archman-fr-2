NOM

login.defs - configuration de la suite de mots de passe shadow

DESCRIPTION

Le fichier /etc/login.defs définit la configuration spécifique au site pour la suite de mots de passe shadow. Ce fichier est requis. L'absence de ce fichier n'empêchera pas le fonctionnement du système, mais entraînera probablement un comportement indésirable.

Ce fichier est un fichier texte lisible, chaque ligne du fichier décrivant un paramètre de configuration. Les lignes consistent en un nom de configuration et une valeur, séparés par des espaces. Les lignes vides et les lignes de commentaire sont ignorées. Les commentaires sont introduits par un symbole dièse (« # ») et le symbole dièse doit être le premier caractère non blanc de la ligne.

Les valeurs des paramètres peuvent être de quatre types : chaînes de caractères, booléens, nombres et grands nombres. Une chaîne est composée de caractères imprimables. Un booléen doit être soit la valeur oui soit non. Un paramètre booléen indéfini ou avec une valeur autre que celles-ci recevra la valeur non. Les nombres (réguliers et grands) peuvent être des valeurs décimales, octales (précéder la valeur de 0) ou hexadécimales (précéder la valeur de 0x). La valeur maximale des paramètres numériques réguliers et grands dépend de la machine.

Les éléments de configuration suivants sont fournis :

CHFN_RESTRICT (chaîne)

Ce paramètre spécifie quelles valeurs dans le champ gecos du fichier /etc/passwd peuvent être modifiées par les utilisateurs ordinaires à l'aide du programme chfn. Il peut s'agir de toute combinaison des lettres f, r, w, h, pour le nom complet (Full name), le numéro de bureau (Room number), le téléphone au travail (Work phone) et le téléphone personnel (Home phone), respectivement. Pour des raisons de compatibilité descendante, oui est équivalent à rwh et non est équivalent à frwh. Si non spécifié, seul le superutilisateur peut apporter des modifications. Le réglage le plus restrictif est mieux atteint en n'installant pas chfn en mode SUID.

CREATE_HOME (booléen)

Indique si un répertoire personnel doit être créé par défaut pour les nouveaux utilisateurs.

Ce réglage ne s'applique pas aux utilisateurs système et peut être remplacé en ligne de commande.

DEFAULT_HOME (booléen)

Indique si la connexion est autorisée si nous ne pouvons pas nous déplacer vers le répertoire personnel. Par défaut, c'est non.

Si défini sur oui, l'utilisateur se connectera dans le répertoire racine (/) s'il n'est pas possible de se déplacer vers son répertoire personnel.

ENCRYPT_METHOD (chaîne)

Ceci définit l'algorithme de chiffrement par défaut du système pour le chiffrement des mots de passe (si aucun algorithme n'est spécifié en ligne de commande).

Il peut prendre l'une des valeurs suivantes : DES (par défaut), MD5, SHA256, SHA512, YESCRYPT. MD5 et DES ne doivent pas être utilisés pour les nouveaux hachages, consultez crypt(5) pour des recommandations.

Note : ce paramètre remplace la variable MD5_CRYPT_ENAB.

Note : ceci n'affecte que la génération des mots de passe de groupe. La génération des mots de passe d'utilisateur est effectuée par PAM et est soumise à la configuration PAM. Il est recommandé de définir cette variable de manière cohérente avec la configuration PAM.

ENV_PATH (chaîne)

Si défini, il sera utilisé pour définir la variable d'environnement PATH lors de la connexion d'un utilisateur ordinaire. La valeur est une liste de chemins séparés par des deux-points (par exemple /bin:/usr/bin) et peut être précédée de PATH=. La valeur par défaut est PATH=/bin:/usr/bin.

ENV_SUPATH (chaîne)

Si défini, il sera utilisé pour définir la variable d'environnement PATH lors de la connexion du superutilisateur. La valeur est une liste de chemins séparés par des deux-points (par exemple /sbin:/bin:/usr/sbin:/usr/bin) et peut être précédée de PATH=. La valeur par défaut est PATH=/sbin:/bin:/usr/sbin:/usr/bin.

FAIL_DELAY (nombre)

Délai en secondes avant d'autoriser une nouvelle tentative après un échec de connexion.

GID_MAX (nombre), GID_MIN (nombre)

Plage d'identifiants de groupe utilisés pour la création de groupes ordinaires par useradd, groupadd ou newusers.

La valeur par défaut pour GID_MIN (resp. GID_MAX) est 1000 (resp. 60000).

HOME_MODE (nombre)

Le mode pour les nouveaux répertoires personnels. Si non spécifié, l'UMASK est utilisé pour créer le mode.

useradd et newusers utilisent ceci pour définir le mode du répertoire personnel qu'ils créent.

HUSHLOGIN_FILE (chaîne)

Si défini, ce fichier peut inhiber toutes les bavardages habituels pendant la séquence de connexion. Si un chemin absolu est spécifié, alors le mode silencieux sera activé si le nom ou le shell de l'utilisateur est trouvé dans le fichier. S'il ne s'agit pas d'un chemin absolu, le mode silencieux sera activé si le fichier existe dans le répertoire personnel de l'utilisateur.

LASTLOG_UID_MAX (nombre)

Identifiant d'utilisateur le plus élevé pour lequel les entrées lastlog doivent être mises à jour. Comme les identifiants d'utilisateur plus élevés sont généralement suivis par des services d'identité et d'authentification d'utilisateurs distants, il n'est pas nécessaire de créer un énorme fichier lastlog éparse pour eux.

L'absence de l'option LASTLOG_UID_MAX dans la configuration signifie qu'il n'y a pas de limite d'identifiant d'utilisateur pour l'écriture des entrées lastlog.

LOG_UNKFAIL_ENAB (booléen)

Active l'affichage des noms d'utilisateurs inconnus lorsque des échecs de connexion sont enregistrés.

Note : enregistrer des noms d'utilisateurs inconnus peut poser un problème de sécurité si un utilisateur entre son mot de passe au lieu de son nom d'utilisateur.

LOGIN_RETRIES (nombre)

Nombre maximum de tentatives de connexion en cas de mauvais mot de passe.

Ceci sera très probablement remplacé par PAM, car le module pam_unix par défaut possède son propre nombre de 3 tentatives. Cependant, il s'agit d'une solution de secours sûre au cas où vous utiliseriez un module d'authentification qui n'applique pas PAM_MAXTRIES.

LOGIN_TIMEOUT (nombre)

Temps maximum en secondes pour la connexion.

MAIL_DIR (chaîne)

Le répertoire de spooling du courrier. Ceci est nécessaire pour manipuler la boîte aux lettres lorsque son compte utilisateur correspondant est modifié ou supprimé. Si non spécifié, une valeur par défaut définie à la compilation est utilisée. Le paramètre CREATE_MAIL_SPOOL dans /etc/default/useradd détermine si le spool de courrier doit être créé.

MAIL_FILE (chaîne)

Définit l'emplacement des fichiers de spooling du courrier des utilisateurs par rapport à leur répertoire personnel.

Les variables MAIL_DIR et MAIL_FILE sont utilisées par useradd, usermod et userdel pour créer, déplacer ou supprimer le spool de courrier de l'utilisateur.

MAX_MEMBERS_PER_GROUP (nombre)

Nombre maximum de membres par entrée de groupe. Lorsque le maximum est atteint, une nouvelle entrée de groupe (ligne) est commencée dans /etc/group (avec le même nom, le même mot de passe et le même GID).

La valeur par défaut est 0, ce qui signifie qu'il n'y a pas de limite au nombre de membres dans un groupe.

Cette fonctionnalité (groupe divisé) permet de limiter la longueur des lignes dans le fichier de groupe. Ceci est utile pour s'assurer que les lignes pour les groupes NIS ne dépassent pas 1024 caractères.

Si vous avez besoin d'imposer une telle limite, vous pouvez utiliser 25.

Note : les groupes divisés peuvent ne pas être pris en charge par tous les outils (même dans la suite d'outils Shadow). Vous ne devriez pas utiliser cette variable à moins d'en avoir vraiment besoin.

NONEXISTENT (chaîne)

Si un compte système n'a intentionnellement pas de répertoire personnel qui existe, cette chaîne peut être fournie dans l'entrée /etc/passwd pour le compte afin de l'indiquer. Le résultat est que pwck ne générera pas d'avertissement superflu pour ce compte.

PASS_MAX_DAYS (nombre)

Nombre maximum de jours pendant lesquels un mot de passe peut être utilisé. Si le mot de passe est plus ancien que cela, un changement de mot de passe sera forcé. Si non spécifié, -1 sera supposé (ce qui désactive la restriction).

PASS_MIN_DAYS (nombre)

Nombre minimum de jours autorisés entre les changements de mot de passe. Tout changement de mot de passe tenté moins de temps après sera rejeté. Si non spécifié, 0 sera supposé (ce qui désactive la restriction).

PASS_WARN_AGE (nombre)

Aucun avertissement

SHA_CRYPT_MIN_ROUNDS (nombre), SHA_CRYPT_MAX_ROUNDS (nombre)

Lorsque ENCRYPT_METHOD est défini sur SHA256 ou SHA512, ceci définit le nombre de tours SHA utilisés par l'algorithme de chiffrement par défaut (lorsque le nombre de tours n'est pas spécifié sur la ligne de commande).

Avec beaucoup de tours, il est plus difficile de casser le mot de passe par force brute. Mais notez également que plus de ressources CPU seront nécessaires pour authentifier les utilisateurs.

Si non spécifié, la libc choisira le nombre de tours par défaut (5000), ce qui est beaucoup trop bas pour le matériel moderne.

Les valeurs doivent être comprises dans la plage 1000-999 999 999.

Si seule l'une des valeurs SHA_CRYPT_MIN_ROUNDS ou SHA_CRYPT_MAX_ROUNDS est définie, alors cette valeur sera utilisée.

Si SHA_CRYPT_MIN_ROUNDS > SHA_CRYPT_MAX_ROUNDS, la valeur la plus élevée sera utilisée.

Note: Ceci n'affecte que la génération des mots de passe de groupe. La génération des mots de passe utilisateur est effectuée par PAM et soumise à la configuration PAM. Il est recommandé de définir cette variable de manière cohérente avec la configuration PAM.

SUB_GID_MIN (nombre), SUB_GID_MAX (nombre), SUB_GID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur possède déjà des identifiants de groupe subordonnés) allouent SUB_GID_COUNT identifiants de groupe inutilisés dans la plage de SUB_GID_MIN à SUB_GID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT sont respectivement 100000, 600100000 et 65536.

SUB_UID_MIN (nombre), SUB_UID_MAX (nombre), SUB_UID_COUNT (nombre)

Si /etc/subuid existe, les commandes useradd et newusers (sauf si l'utilisateur possède déjà des identifiants utilisateur subordonnés) allouent SUB_UID_COUNT identifiants utilisateur inutilisés dans la plage de SUB_UID_MIN à SUB_UID_MAX pour chaque nouvel utilisateur.

Les valeurs par défaut pour SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT sont respectivement 100000, 600100000 et 65536.

SYS_GID_MAX (nombre), SYS_GID_MIN (nombre)

Plage des identifiants de groupe utilisés pour la création de groupes système par useradd, groupadd, ou newusers.

La valeur par défaut pour SYS_GID_MIN (resp. SYS_GID_MAX) est 101 (resp. GID_MIN-1).

SYS_UID_MAX (nombre), SYS_UID_MIN (nombre)

Plage des identifiants utilisateur utilisés pour la création d'utilisateurs système par useradd ou newusers.

La valeur par défaut pour SYS_UID_MIN (resp. SYS_UID_MAX) est 101 (resp. UID_MIN-1).

SYSLOG_SG_ENAB (booléen)

Active la journalisation "syslog" de l'activité de sg.

TTYGROUP (chaîne), TTYPERM (nombre)

Les permissions du terminal : le tty de connexion sera appartenant au groupe TTYGROUP, et les permissions seront définies à TTYPERM.

TTYGROUP peut être soit le nom d'un groupe, soit un identifiant de groupe numérique.

Si TTYGROUP n'est pas défini, alors la propriété du groupe du terminal est définie sur le groupe principal de l'utilisateur. Si TTYPERM n'est pas défini, alors les permissions sont définies à 0600.

Si vous avez un programme write qui est "setgid" vers un groupe spécial qui possède les terminaux, définissez TTYGROUP au numéro de groupe et TTYPERM à 0620. Sinon, laissez TTYGROUP commenté et assignez TTYPERM à 622 ou 600.

UID_MAX (nombre), UID_MIN (nombre)

Plage des identifiants utilisateur utilisés pour la création d'utilisateurs réguliers par useradd ou newusers.

La valeur par défaut pour UID_MIN (resp. UID_MAX) est 1000 (resp. 60000).

UMASK (nombre)

Le masque de création de mode de fichier est initialisé à cette valeur. Si non spécifié, le masque sera initialisé à 022.

useradd et newusers utilisent ce masque pour définir le mode du répertoire personnel qu'ils créent si HOME_MODE n'est pas défini.

Il est également utilisé par pam_umask comme valeur umask par défaut.

USERDEL_CMD (chaîne)

Si défini, cette commande est exécutée lors de la suppression d'un utilisateur. Elle doit supprimer toute tâche at/cron/print, etc. appartenant à l'utilisateur à supprimer (passé comme premier argument).

Le code de retour du script n'est pas pris en compte.

Voici un exemple de script qui supprime les tâches cron, at et print de l'utilisateur :

#! /bin/sh
# Vérifie l'argument requis.
if [ $# != 1 ]; then
	echo "Usage: $0 nom_utilisateur"
	exit 1
fi
# Supprime les tâches cron.
crontab -r -u $1
# Supprime les tâches at.
# Notez que cela supprimera toutes les tâches appartenant au même UID,
# même si elles étaient partagées par un nom d'utilisateur différent.
AT_SPOOL_DIR=/var/spool/cron/atjobs
find $AT_SPOOL_DIR -name "[^.]*" -type f -user $1 -delete \;
# Supprime les tâches d'impression.
lprm $1
# Terminé.
exit 0

USERGROUPS_ENAB (booléen)

Si défini sur yes, userdel supprimera le groupe de l'utilisateur s'il ne contient plus de membres, et useradd créera par défaut un groupe portant le nom de l'utilisateur.

YESCRYPT_COST_FACTOR (nombre)

Lorsque ENCRYPT_METHOD est défini sur YESCRYPT, ceci définit le facteur de coût utilisé par l'algorithme de chiffrement par défaut (lorsque le facteur de coût n'est pas spécifié sur la ligne de commande).

Avec un facteur de coût élevé, il est plus difficile de casser le mot de passe par force brute. Mais notez également que plus de ressources CPU seront nécessaires pour authentifier les utilisateurs.

La valeur doit être comprise dans la plage 1-11.

Note: Ceci n'affecte que la génération des mots de passe de groupe. La génération des mots de passe utilisateur est effectuée par PAM et soumise à la configuration PAM. Il est recommandé de définir cette variable de manière cohérente avec la configuration PAM.

BOGUES

Une grande partie des fonctionnalités qui étaient autrefois fournies par la suite de mots de passe shadow est maintenant gérée par PAM. Ainsi, /etc/login.defs n'est plus utilisé par passwd(1), ou moins utilisé par login(1), et su(1). Veuillez vous référer aux fichiers de configuration PAM correspondants à la place.
