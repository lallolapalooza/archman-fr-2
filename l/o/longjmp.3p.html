LONGJMP(3P) Manuel du programmeur POSIX LONGJMP(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

longjmp — saut non local

SYNOPSIS

#include <setjmp.h>
void longjmp(jmp_buf env, int val);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

La fonction longjmp() restaure l'environnement sauvegardé par l'invocation la plus récente de setjmp() dans le même processus, avec l'argument jmp_buf correspondant. Si l'invocation la plus récente de setjmp() avec le jmp_buf correspondant s'est produite dans un autre thread, ou s'il n'y a pas d'invocation de ce type, ou si la fonction contenant l'invocation de setjmp() a terminé son exécution entre-temps, ou si l'invocation de setjmp() était dans la portée d'un identificateur de type modifié de manière variable et que l'exécution a quitté cette portée entre-temps, le comportement est indéfini. Il n'est pas spécifié si longjmp() restaure le masque de signaux, laisse le masque de signaux inchangé, ou le restaure à sa valeur au moment où setjmp() a été appelé.

Tous les objets accessibles ont des valeurs, et tous les autres composants de la machine abstraite ont un état (par exemple, les drapeaux d'état de virgule flottante et les fichiers ouverts), tels qu'au moment où longjmp() a été appelé, sauf que les valeurs des objets de durée de stockage automatique ne sont pas spécifiées s'ils remplissent toutes les conditions suivantes :

*
Ils sont locaux à la fonction contenant l'invocation correspondante de setjmp().
*
Ils n'ont pas de type qualifié volatile.
*
Ils sont modifiés entre l'invocation de setjmp() et l'appel à longjmp().

Bien que longjmp() soit une fonction sûre en cas de signal asynchrone, si elle est invoquée à partir d'un gestionnaire de signaux qui a interrompu une fonction non sûre en cas de signal asynchrone ou équivalent (telle que le traitement équivalent à exit() effectué après un retour de l'appel initial à main()), le comportement de tout appel ultérieur à une fonction non sûre en cas de signal asynchrone ou équivalent est indéfini.

L'effet d'un appel à longjmp() où l'initialisation de la structure jmp_buf n'a pas été effectuée dans le thread appelant est indéfini.

VALEUR DE RETOUR

Après l'achèvement de longjmp(), l'exécution du programme continue comme si l'invocation correspondante de setjmp() venait de retourner la valeur spécifiée par val. La fonction longjmp() ne doit pas provoquer le retour de setjmp() avec 0 ; si val est 0, setjmp() retournera 1.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATIF

Les applications dont le comportement dépend de la valeur du masque de signaux ne doivent pas utiliser longjmp() et setjmp(), car leur effet sur le masque de signaux n'est pas spécifié, mais doivent plutôt utiliser les fonctions siglongjmp() et sigsetjmp() (qui peuvent sauvegarder et restaurer le masque de signaux sous le contrôle de l'application).

Il est recommandé aux applications de ne pas appeler longjmp() ou siglongjmp() depuis des gestionnaires de signaux. Pour éviter un comportement indéfini lors de l'appel de ces fonctions à partir d'un gestionnaire de signaux, l'application doit s'assurer de l'une des deux choses suivantes :

1.
Après l'appel à longjmp() ou siglongjmp(), le processus n'appelle que des fonctions sûres en cas de signal asynchrone et ne retourne pas de l'appel initial à main().
2.
Tout signal dont le gestionnaire appelle longjmp() ou siglongjmp() est bloqué pendant chaque appel à une fonction non sûre en cas de signal asynchrone, et aucun appel de ce type n'est effectué après le retour de l'appel initial à main().

longjmp(3p)

longjmp - recharger un contexte précédemment enregistré par setjmp.

Syntaxe

#include <setjmp.h>

void longjmp(jmp_buf env, int val);

Description

La fonction longjmp restaure un contexte de pile précédemment enregistré dans env par un appel à setjmp. L'exécution reprend alors à l'endroit de l'appel setjmp. La valeur de retour de cet appel setjmp sera alors val.

Si val est zéro, setjmp retournera 1. Sinon, setjmp retournera val.

Il est garanti que longjmp ne retourne jamais.

Si longjmp est appelée après que le cadre de pile de l'appel à setjmp a été détruit (par exemple, si le contrôle est retourné de la fonction qui contient l'appel setjmp), le comportement est indéfini.

Valeur de retour

Aucune (longjmp ne retourne jamais).

Exemple

#include <stdio.h>
#include <setjmp.h>

jmp_buf jump_buffer;

void function_that_might_jump(int value) {
    if (value == 0) {
        printf("Saut depuis function_that_might_jump...\n");
        longjmp(jump_buffer, 1); // Saut avec une valeur de 1
    } else {
        printf("function_that_might_jump continue normalement.\n");
    }
}

int main() {
    int return_value;

    printf("Enregistrement du contexte...\n");
    return_value = setjmp(jump_buffer);

    if (return_value == 0) {
        printf("setjmp a retourné 0. Appel de function_that_might_jump...\n");
        function_that_might_jump(0); // Appel qui causera le saut
        printf("Cette ligne ne devrait pas être atteinte.\n");
    } else {
        printf("Retour à main après un longjmp. Valeur de retour de setjmp : %d\n", return_value);
    }

    printf("Fin du programme.\n");
    return 0;
}
