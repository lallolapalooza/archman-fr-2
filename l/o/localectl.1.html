NOM

localectl - Contrôler les paramètres de localisation et de disposition du clavier du système

SYNTAXE

localectl [OPTIONS...] {COMMANDE}

DESCRIPTION

localectl peut être utilisé pour interroger et modifier les paramètres de localisation et de disposition du clavier du système. Il communique avec systemd-localed(8) pour modifier des fichiers tels que /etc/locale.conf et /etc/vconsole.conf.

La localisation du système contrôle les paramètres de langue des services système et de l'interface utilisateur avant la connexion de l'utilisateur, tels que le gestionnaire d'affichage, ainsi que la valeur par défaut pour les utilisateurs après la connexion.

Les paramètres du clavier contrôlent la disposition du clavier utilisée sur la console texte et dans l'interface utilisateur graphique avant la connexion de l'utilisateur, tels que le gestionnaire d'affichage, ainsi que la valeur par défaut pour les utilisateurs après la connexion.

Notez que les modifications effectuées avec cet outil peuvent nécessiter la reconstruction de l'initrd pour prendre effet au début du démarrage du système. L'initrd n'est pas reconstruite automatiquement par localectl, cette tâche doit être effectuée manuellement, généralement en réinstallant le paquet du noyau de la distribution.

Notez que systemd-firstboot(1) peut être utilisé pour initialiser la localisation du système pour les images système montées (mais non démarrées).

COMMANDES

Les commandes suivantes sont comprises :

status

Affiche les paramètres actuels de la localisation système et du mappage du clavier. Si aucune commande n'est spécifiée, c'est la valeur par défaut implicite.

Ajouté dans la version 195.

set-locale LOCALE, set-locale VARIABLE=LOCALE...

Définit la localisation du système. Cela prend une locale telle que "fr_FR.UTF-8", ou une ou plusieurs affectations de locale telles que "LANG=de_DE.utf8", "LC_MESSAGES=en_GB.utf8", et ainsi de suite. Si une locale sans nom de variable est fournie, alors la variable de locale "LANG=" sera définie. Voir locale(7) pour les détails sur les paramètres disponibles et leur signification. Utilisez list-locales pour une liste des locales disponibles (voir ci-dessous).

Ajouté dans la version 195.

list-locales

Liste les locales disponibles utiles pour la configuration avec set-locale.

Ajouté dans la version 195.

set-keymap MAP [TOGGLEMAP]

Définit le mappage du clavier système pour la console et X11. Cela prend un nom de mappage (tel que "fr" ou "us"), et éventuellement un second pour définir un mappage de clavier à bascule. Sauf si --no-convert est passé, le paramètre sélectionné est également appliqué comme mappage de clavier système par défaut de X11, après l'avoir converti en mappage de clavier X11 correspondant le plus étroitement. Utilisez list-keymaps pour une liste des mappages de clavier disponibles (voir ci-dessous).

Ajouté dans la version 195.

list-keymaps

Liste les mappages de clavier disponibles pour la console, utiles pour la configuration avec set-keymap.

Ajouté dans la version 195.

set-x11-keymap LAYOUT [MODEL [VARIANT [OPTIONS]]]

Définit le mappage de clavier système par défaut pour X11 et la console virtuelle. Cela prend un nom de mappage de clavier (tel que "fr" ou "us"), et éventuellement un modèle, une variante et des options, voir kbd(4) pour les détails. Sauf si --no-convert est passé, le paramètre sélectionné est également appliqué comme mappage de clavier système de la console, après l'avoir converti en mappage de clavier de console correspondant le plus étroitement.

Ajouté dans la version 195.

list-x11-keymap-models, list-x11-keymap-layouts, list-x11-keymap-variants [LAYOUT], list-x11-keymap-options

Liste les modèles, dispositions, variantes et options de mappage de touches X11 disponibles, utiles pour la configuration avec set-keymap. La commande list-x11-keymap-variants prend éventuellement un paramètre de disposition pour limiter la sortie aux variantes adaptées à la disposition spécifique.

Ajouté dans la version 201.

OPTIONS

Les options suivantes sont comprises :

-l, --full

Ne pas tronquer la sortie.

Ajouté dans la version 257.

--no-convert

Si set-keymap ou set-x11-keymap est appelé et que cette option est passée, alors le mappage de touches ne sera pas converti de la console vers X11, ou de X11 vers la console, respectivement.

Ajouté dans la version 195.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par "@", pour vous connecter. Le nom d'hôte peut éventuellement être suivi d'un port sur lequel ssh écoute, séparé par ":", puis d'un nom de conteneur, séparé par "/", ce qui se connecte directement à un conteneur spécifique sur la machine distante. Cela utilisera SSH pour communiquer avec l'instance du gestionnaire de machine distante. Les noms de conteneurs peuvent être énumérés avec machinectl -H HOTE. Mettez les adresses IPv6 entre crochets.

-M, --machine=

Exécute l'opération sur un conteneur local. Spécifiez un nom de conteneur auquel se connecter, éventuellement préfixé par un nom d'utilisateur pour se connecter et un caractère "@" séparateur. Si la chaîne spéciale ".host" est utilisée à la place du nom du conteneur, une connexion au système local est établie (ce qui est utile pour se connecter au bus utilisateur d'un utilisateur spécifique : "--user --machine=lennart@.host"). Si la syntaxe "@" n'est pas utilisée, la connexion est effectuée en tant qu'utilisateur root. Si la syntaxe "@" est utilisée, le côté gauche ou le côté droit peut être omis (mais pas les deux), auquel cas le nom d'utilisateur local et ".host" sont implicites.

--no-ask-password

Ne demande pas à l'utilisateur de s'authentifier pour les opérations privilégiées.

-h, --help

Affiche un court message d'aide et quitte.

--version

Affiche une courte chaîne de version et quitte.

--no-pager

Ne pas utiliser de pagineur pour la sortie.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages d'un niveau supérieur, c'est-à-dire moins importants, seront supprimés). Prend une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier dans la plage 0...7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être préfixée par l'une des valeurs suivantes : console, syslog, kmsg ou journal suivie d'un deux-points pour définir le niveau de journalisation maximal pour cette cible de journal spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf lors de la journalisation vers la console qui doit être au niveau info). Notez que le niveau de journalisation maximal global a la priorité sur tous les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Un booléen. S'il est vrai, les messages écrits dans le tty seront colorés selon la priorité.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement dans le terminal, car journalctl(1) et d'autres outils qui affichent les journaux coloreront les messages en fonction du niveau de journalisation de leurs propres métadonnées.

$SYSTEMD_LOG_TIME

Un booléen. S'il est vrai, les messages du journal de la console seront préfixés par un horodatage.

Ce paramètre est uniquement utile lorsque les messages sont écrits directement dans le terminal ou dans un fichier, car journalctl(1) et d'autres outils qui affichent les journaux ajouteront des horodatages basés sur les métadonnées de l'entrée.

$SYSTEMD_LOG_LOCATION

Un booléen.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour modifier le comportement de localectl. Les variables préfixées par SYSTEMD_ sont privilégiées par rapport aux variables standard correspondantes.

$SYSTEMD_LOG_LINENO

Un booléen. S'il est vrai, les messages seront préfixés par le nom du fichier et le numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent attaché comme métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TID

Un booléen. S'il est vrai, les messages seront préfixés par l'ID numérique du thread (TID) actuel.

Notez que ces informations sont attachées comme métadonnées aux entrées du journal de toute façon. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des options suivantes : console (journalisation sur le tty attaché), console-prefixed (journalisation sur le tty attaché mais avec des préfixes codant le niveau de journalisation et la "facility", voir syslog(3), kmsg (journalisation dans le tampon circulaire du journal du noyau), journal (journalisation dans le journal), journal-or-kmsg (journalisation dans le journal si disponible, et dans kmsg sinon), auto (détermination automatique de la cible de journalisation appropriée, par défaut), null (désactivation de la sortie de journalisation).

$SYSTEMD_LOG_RATELIMIT_KMSG

Indique s'il faut limiter le débit de kmsg ou non. Prend une valeur booléenne. La valeur par défaut est "true". Si désactivé, systemd ne limitera pas le débit des messages écrits dans kmsg.

$SYSTEMD_PAGER, $PAGER

Le pagineur à utiliser lorsque --no-pager n'est pas donné. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, une série d'implémentations de pagineurs bien connues sont essayées successivement, y compris less(1) et more(1), jusqu'à ce que l'une soit trouvée. Si aucune implémentation de pagineur n'est découverte, aucun pagineur n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou sur la valeur "cat" équivaut à passer --no-pager.

Remarque : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le pagineur (avec "cat" ou ""), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs pourraient vouloir changer deux options en particulier :

K

Cette option demande au pagineur de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer Ctrl+C lui-même afin de revenir à l'invite de commande du pagineur, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas "K", et que le pagineur invoqué est less, Ctrl+C sera ignoré par l'exécutable et devra être géré par le pagineur.

X

Cette option demande au pagineur de ne pas envoyer de chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du pagineur. Néanmoins, cela empêche certaines fonctionnalités du pagineur de fonctionner, en particulier la sortie paginée ne peut pas être déroulée avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet pour les invocations de less par les outils de systemd.

Voir less(1) pour plus de discussion.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut "utf-8", si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet pour les invocations de less par les outils de systemd.

$SYSTEMD_PAGERSECURE

Les commandes de pagineur courantes comme less(1), en plus de la "pagination", c'est-à-dire du défilement de la sortie, prennent en charge l'ouverture ou l'écriture d'autres fichiers et l'exécution de commandes shell arbitraires. Lorsque les commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le pagineur devient une limite de sécurité. Il faut veiller à ce que seuls des programmes aux fonctionnalités strictement limitées soient utilisés comme pagineurs, et que les fonctionnalités interactives involontaires telles que l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus ne soient pas autorisées. Le "mode sécurisé" pour le pagineur peut être activé comme décrit ci-dessous, si le pagineur le prend en charge (la plupart des pagineurs ne sont pas écrits d'une manière qui en tient compte). Il est recommandé soit d'activer explicitement le "mode sécurisé", soit de désactiver complètement le pagineur en utilisant --no-pager ou PAGER=cat lorsque des utilisateurs non fiables sont autorisés à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'elle est définie sur vrai, le "mode sécurisé" du pagineur est activé. En "mode sécurisé", LESSSECURE=1 sera défini lors de l'invocation du pagineur, ce qui demande au pagineur de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou démarrent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le "mode sécurisé".

Lorsqu'elle est définie sur faux, aucune limitation n'est placée sur le pagineur. Définir SYSTEMD_PAGERSECURE=0 ou ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le "mode sécurisé" doit être activé et si le pagineur le prend en charge. Le "mode sécurisé" est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous sudo(8) ou des outils similaires ($SUDO_UID est défini [1]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les pagineurs qui ne sont pas connus pour implémenter le "mode sécurisé" ne seront pas utilisés du tout. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à être une commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le pagineur.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être prises en compte, autre que pour désactiver le pagineur, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Prend un argument booléen. Lorsqu'il est vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : "16", "256" pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256, respectivement. Ceci peut être spécifié pour remplacer la décision automatique basée sur $TERM et ce à quoi la console est connectée.

$SYSTEMD_URLIFY

La valeur doit être booléenne. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminaux qui le prennent en charge. Ceci peut être spécifié pour remplacer la décision prise par systemd en fonction de $TERM et d'autres conditions.
