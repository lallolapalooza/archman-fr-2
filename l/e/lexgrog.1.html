LEXGROG(1) Outils de pagination manuel LEXGROG(1)

NOM

lexgrog - analyse les informations d'en-tête dans les pages de manuel

SYNTAXE

lexgrog [-m|-c] [-dfw?V] [-E encodage] fichier ...

DESCRIPTION

lexgrog est une implémentation de l'utilitaire traditionnel “groff guess” en lex. Il lit la liste des fichiers spécifiés sur sa ligne de commande, qu'ils soient des fichiers source de pages de manuel ou des pages “cat” préformatées, et affiche leur nom et description tels qu'utilisés par apropos et whatis, ainsi que la liste des filtres de pré-traitement requis par la page de manuel avant qu'elle ne soit passée à nroff ou troff, ou les deux.

Si son entrée est mal formatée, lexgrog affichera “échec d'analyse” ; cela peut être utile pour les programmes externes qui ont besoin de vérifier la correction des pages de manuel. Si l'un des fichiers d'entrée de lexgrog est “-”, il lira depuis l'entrée standard ; si un fichier d'entrée est compressé, une version décompressée sera lue automatiquement.

OPTIONS

-d, --debug
Affiche des informations de débogage.
-m, --man
Analyse l'entrée comme des fichiers source de pages de manuel. C'est le mode par défaut si ni --man ni --cat n'est spécifié.
-c, --cat
Analyse l'entrée comme des pages de manuel préformatées (pages “cat”). --man et --cat ne peuvent pas être spécifiés simultanément.
-w, --whatis
Affiche le nom et la description de l'en-tête de la page de manuel, tels qu'utilisés par apropos et whatis. C'est le mode par défaut si ni --whatis ni --filters n'est spécifié.
-f, --filters
Affiche la liste des filtres nécessaires pour prétraiter la page de manuel avant de la formater avec nroff ou troff.
-E encodage, --encoding encodage
Remplace l'encodage de caractères deviné pour la page par encodage.
-?, --help
Affiche un message d'aide et quitte.
--usage
Affiche un bref message d'utilisation et quitte.
-V, --version
Affiche les informations de version.

STATUT DE RETOUR

0
Exécution réussie du programme.
1
Erreur d'utilisation.
2
lexgrog n'a pas réussi à analyser un ou plusieurs de ses fichiers d'entrée.

EXEMPLES

  $ lexgrog man.1
  man.1: "man - an interface to the system reference manuals"
  $ lexgrog -fw man.1
  man.1 (t): "man - an interface to the system reference manuals"
  $ lexgrog -c whatis.cat1
  whatis.cat1: "whatis - display manual page descriptions"
  $ lexgrog broken.1
  broken.1: échec d'analyse

ANALYSE WHATIS

mandb (qui utilise le même code que lexgrog) analyse la section NAME en haut de chaque page de manuel à la recherche des noms et descriptions des fonctionnalités documentées. Bien que l'analyseur soit assez tolérant, car il doit faire face à un certain nombre de formes qui ont été historiquement utilisées, il peut parfois échouer à extraire les informations requises.

Lorsque vous utilisez le jeu de macros traditionnel man, une section NAME correcte ressemble à ceci :

.SH NAME
foo \- programme pour faire quelque chose

Certains afficheurs de pages de manuel exigent que le ‘\-’ soit exactement comme indiqué ; mandb est plus tolérant, mais pour la compatibilité avec d'autres systèmes, il est néanmoins conseillé de conserver la barre oblique inversée.

Sur le côté gauche, il peut y avoir plusieurs noms, séparés par des virgules. Les noms contenant des espaces seront ignorés pour éviter un comportement pathologique sur certaines sections NAME mal formées. Le texte sur le côté droit est libre et peut être réparti sur plusieurs lignes. Si plusieurs fonctionnalités avec des descriptions différentes sont documentées dans la même page de manuel, la forme suivante est donc utilisée :

.SH NAME
foo, bar \- programmes pour faire quelque chose
.br
baz \- programme pour ne rien faire

(Une macro qui commence un nouveau paragraphe, comme .PP, peut être utilisée à la place de la macro de saut .br.)

Lorsque vous utilisez le jeu de macros mdoc dérivé de BSD, une section NAME correcte ressemble à ceci :

.Sh NAME
.Nm foo
.Nd programme pour faire quelque chose

Il existe plusieurs raisons courantes pour lesquelles l'analyse whatis échoue. Parfois, les auteurs de pages de manuel remplacent ‘.SH NAME’ par ‘.SH MYPROGRAM’, et dans ce cas mandb ne trouve pas la section à partir de laquelle extraire les informations dont il a besoin. Parfois, les auteurs incluent une section NAME, mais y placent du texte libre plutôt que ‘nom \- description’. Cependant, toute syntaxe ressemblant à ce qui précède devrait être acceptée.

VOIR AUSSI

apropos(1), man(1), whatis(1), mandb(8)

NOTES

lexgrog tente d'analyser les fichiers contenant des requêtes .so, mais ne pourra le faire correctement que si les fichiers sont correctement installés dans une hiérarchie de pages de manuel.
