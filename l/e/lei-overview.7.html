LEI-OVERVIEW(7) Manuel utilisateur public-inbox LEI-OVERVIEW(7)

NOM

lei - aperçu de lei

DESCRIPTION

lei(1) est une interface d'email locale pour public-inbox et les emails personnels. Ce document fournit quelques exemples de base.

LEI STORE

lei dispose d'un stockage local inscriptible basé sur le format public-inbox-v2-format(5). Les commandes initialiseront automatiquement le stockage en arrière-plan si nécessaire, mais vous pouvez appeler lei-init(1) directement si vous souhaitez utiliser un emplacement de stockage autre que par défaut "$XDG_DATA_HOME/lei/store".

La commande lei-import(1) fournit l'interface principale pour importer des messages dans le stockage local. De plus, d'autres commandes, telles que lei-q(1) et lei-blob(1), utilisent le stockage local pour mettre en cache les messages des dépôts distants.

EXEMPLES

$ lei import mboxrd:t.mbox.gz
Importe les messages d'un fichier mboxrd gzippé dans le stockage local.
$ lei blob 59ec517f9
Affiche le message avec l'OID de blob git 59ec517f9. Si un message avec cet OID n'est pas trouvé, vérifie si le dépôt git actuel contient le blob, en essayant de le reconstruire à partir d'un message si nécessaire.
$ lei blob 59ec517f9 | lei tag -F eml +kw:flagged +L:next
Définit le mot-clé « flagged » et le libellé « next » sur le message avec l'OID de blob 59ec517f9.

EXTERNALS

En plus du stockage ci-dessus, lei peut effectuer des requêtes en lecture seule sur des « externals » : des boîtes aux lettres et des index externes. Un external peut être enregistré en passant une URL ou un chemin local à lei-add-external(1). Pour les chemins locaux existants, l'external doit être indexé avec public-inbox-index(1) (dans le cas d'une boîte aux lettres ordinaire) ou public-inbox-extindex(1) (dans le cas d'un index externe).

SYNCHRONIZATION

lei a actuellement des capacités primitives de synchronisation d'emails ; voir lei-mail-sync-overview(7) pour plus de détails.

EXEMPLES

$ lei add-external https://public-inbox.org/meta/
Ajoute un external distant pour la boîte aux lettres de public-inbox.
$ lei add-external --mirror https://public-inbox.org/meta/ chemin
Clone https://public-inbox.org/meta/ vers "chemin", l'indexe avec public-inbox-index(1), et l'ajoute comme external local.

RECHERCHE

La commande lei-q(1) recherche dans le stockage local et les externals. Les préfixes de recherche correspondent à ceux disponibles via public-inbox-httpd(1).

EXEMPLES

$ lei q s:lei s:skeleton
Recherche les messages dont l'objet inclut « lei » et « skeleton ».
$ lei q -t s:lei s:skeleton
Fait de même, mais rapporte également les messages non correspondants qui se trouvent dans le même fil de discussion qu'un message correspondant.
$ lei q -t -o /tmp/mdir --mua=mutt s:lei s:skeleton
Écrit les résultats dans un Maildir à « mdir ». Mutt sera invoqué pour ouvrir le mfolder ("mutt -f %f") pendant la récupération et l'écriture des résultats.
$ lei q kw:flagged L:next
Recherche tous les messages marqués comme « flagged » qui ont également un libellé « next ».
$ lei p2q HEAD | lei q -tt -o /tmp/mdir
Recherche les messages dont les OID de blob git post-image correspondent à ceux du dépôt actuel du commit HEAD, les écrit dans le répertoire Maildir « mdir » et marque comme lus les messages qui correspondaient exactement.
$ git show -s HEAD | lei lcat
Affiche un message local pour le lien public-inbox contenu dans un message de commit.
$ lei q -f text m:MESSAGE-ID | lei rediff -U5
Alimente un message contenant un diff à lei-rediff(1) pour régénérer son diff avec cinq lignes de contexte. Sauf si "--git-dir" est spécifié, cela nécessite que le répertoire de travail actuel soit dans le dépôt de code associé.

NOTES DE PERFORMANCE

Inline::C est requis sur les BSD et peut accélérer les choses sur Linux.

lei s'exécute en tant que démon en arrière-plan pour réduire les coûts de démarrage et peut fournir une surveillance Maildir en temps réel via kqueue(2)/inotify(7). IO::KQueue (p5-IO-KQueue sur FreeBSD) et Linux::Inotify2 (liblinux-inotify2-perl et perl-Linux-Inotify2 dans les distributions basées sur .deb et .rpm, respectivement) sont recommandés.

Socket::MsgHdr est facultatif (libsocket-msghdr-perl sous Debian), et améliore encore les performances de démarrage. Son effet est surtout ressenti lors de l'utilisation de la complétion shell.

COMPLÉTION BASH

La complétion Bash préliminaire pour lei est fournie dans "contrib/completion/". Les contributions ajoutant la prise en charge d'autres shells, ainsi que des améliorations à la complétion Bash existante, sont les bienvenues.

MISE À NIVEAU

Comme lei s'exécute en tant que démon, lei-daemon-kill(1) est requis pour arrêter le démon afin qu'il puisse charger le nouveau code. Il sera redémarré lors de la prochaine invocation de toute commande lei.

MISES EN GARDE

Les performances des clients IMAP et NNTP sont médiocres sur les connexions à latence élevée. Cela sera, espérons-le, corrigé en 2022.
