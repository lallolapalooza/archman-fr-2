LEDGER(1) Manuel des commandes générales LEDGER(1)

NOM

ledger — Outil de reporting comptable en partie double en ligne de commande

SYNOPIS

ledger [options] [commande] [arguments]

DESCRIPTION

ledger est un outil comptable en ligne de commande basé sur la puissance et la complétude de la comptabilité en partie double. Ce n'est qu'un outil de reporting, ce qui signifie qu'il ne modifie jamais vos fichiers de données, mais il offre une large sélection de rapports et différentes manières de les personnaliser selon vos besoins.

COMMANDES

ledger accepte plusieurs commandes de haut niveau, chacune générant un type de rapport de base différent. La plupart d'entre elles acceptent un argument requête-de-rapport, afin de déterminer ce qui doit être rapporté. Pour comprendre la syntaxe d'une requête-de-rapport, consultez la section REQUÊTES. Dans sa forme la plus basique, la simple spécification d'une ou plusieurs chaînes de caractères produit un rapport pour tous les comptes contenant ces chaînes.

Si aucune commande n'est donnée, ledger entre dans un REPL (mode interactif), permettant d'exécuter plusieurs commandes sur le même jeu de données sans re-parsing.

Voici une liste complète des commandes de reporting acceptées :

comptes [requête-de-rapport]
Liste tous les comptes pour les écritures qui correspondent à la requête-de-rapport.
balance [requête-de-rapport]
Affiche un rapport de solde montrant les totaux pour les écritures correspondant à la requête-de-rapport, et les totaux agrégés pour les parents de ces comptes. Les options les plus couramment utilisées avec cette commande sont :
--basis (-B)
Rapport basé sur le coût d'acquisition, pas sur le montant ou la valeur. C'est la seule forme de rapport garantie de toujours s'équilibrer à zéro, lorsqu'aucune requête-de-rapport n'est spécifiée. N'affiche que les totaux pour les comptes les plus importants.
--empty (-E)
Affiche les comptes dont le total est zéro.
--flat
Plutôt que d'afficher un arbre hiérarchique, aplatit le rapport pour montrer uniquement les sous-totaux des comptes correspondant à la requête-de-rapport.
--no-total
Supprime le total récapitulatif affiché en bas du rapport.

Les synonymes bal et b sont également acceptés.

budget [requête-de-rapport]
Un rapport de solde spécial qui inclut trois colonnes supplémentaires : le montant budgétisé pendant la période de reporting, la différence entre les dépenses et le budget, et le pourcentage du budget dépensé (dépasse 100 % si vous dépassez le budget). Notez que la budgétisation nécessite la définition d'une ou plusieurs « transactions périodiques » dans vos fichiers de données. Voir le manuel pour plus d'informations.
cleared [requête-de-rapport]
Un rapport de solde spécial qui ajoute deux colonnes supplémentaires : le solde imputé pour chaque compte, et la date de la dernière écriture imputée dans ce compte. Pour que cette comptabilité soit significative, le drapeau d'imputation doit être défini sur au moins une écriture. Voir le manuel pour plus d'informations.
commodities [requête-de-rapport]
Liste toutes les commodités pour les écritures correspondant à la requête-de-rapport.
convert
Lit des données à partir d'un fichier CSV (valeurs séparées par des virgules) et génère des transactions ledger.
csv [requête-de-rapport]
Rapport des écritures correspondant à la requête-de-rapport au format CSV (valeurs séparées par des virgules). Utile pour exporter des données vers une feuille de calcul pour une analyse plus approfondie ou des graphiques.
entry [modèle-d'entrée]
Génère et affiche une nouvelle transaction ledger correctement formatée en comparant le modèle-d'entrée aux transactions de vos fichiers de données. Pour plus d'informations sur les modèles brouillons et l'utilisation de cette commande pour créer rapidement de nouvelles transactions, voir la section ENTRÉES.

Le synonyme xact est également accepté.

emacs [requête]
Produit des données d'écritures et de transactions dans un format facilement utilisable par l'éditeur Emacs, sous forme de formes Lisp. Ceci est utilisé par le mode ledger d'Emacs pour traiter les données de reporting de ledger.
equity [requête-de-rapport]
Affiche une transaction avec une série d'écritures qui équilibrent les totaux actuels des comptes correspondant à la requête-de-rapport dans un compte spécial nommé Équité:Soldes d'ouverture. Le but de ce rapport est de clôturer les livres pour une année précédente, tout en utilisant ces écritures d'équité pour reporter ces soldes.
payees [requête-de-rapport]
Liste tous les payeurs pour les écritures correspondant à la requête-de-rapport.
pricemap
Produit un fichier qui peut être utilisé pour générer un graphique avec graphviz montrant la relation des commodités dans le fichier ledger.
prices [requête-de-rapport]
Rapporte les prix de toutes les commodités dans les écritures correspondant à la requête-de-rapport. Les prix sont rapportés avec la granularité d'une seule journée.
pricedb [requête-de-rapport]
Rapporte les prix de toutes les commodités dans les écritures correspondant à la requête-de-rapport. Les prix sont rapportés jusqu'à la seconde, en utilisant le même format que le fichier ~/.pricedb.
print [requête-de-rapport]
Imprime les transactions complètes de toute écriture correspondante en utilisant le même format qu'elles apparaîtraient dans un fichier de données. Ceci peut être utilisé pour extraire des sous-ensembles d'un fichier ledger pour les transférer vers d'autres fichiers.
push [options]
Dans le REPL, empile un ensemble d'options de ligne de commande, de sorte qu'elles s'appliquent à tous les rapports ultérieurs.
pop
Dans le REPL, dépile toutes les configurations d'options qui ont été pushées.
register [requête-de-rapport]
Liste toutes les écritures correspondant à la requête-de-rapport. C'est l'une des commandes les plus courantes, et elle peut être utilisée pour fournir une variété de rapports utiles. Les options les plus couramment utilisées avec cette commande sont :
--average (-A)
Affiche la moyenne courante, plutôt qu'un total courant.
--current (-c)
Donne la dernière position de solde.

OPTIONS

La commande ledger accepte de nombreuses options, qui sont utilisées pour modifier la façon dont les rapports sont générés. Voici une sélection des options les plus couramment utilisées.

Les options peuvent être groupées. Par exemple, -cdef est équivalent à -c -d -e -f.

--affect compte
Utilisé dans les commandes balance et register, ceci sélectionne un compte spécifique, et n'inclut que les comptes qui sont des descendants directs ou des ancêtres du compte spécifié dans le rapport.
--annually (-a)
Affiche les totaux annuels. Ceci est une option de formatage et affecte la manière dont le rapport est affiché, pas les données qui sont incluses.
--monthly (-m)
Affiche les totaux mensuels. Ceci est une option de formatage et affecte la manière dont le rapport est affiché, pas les données qui sont incluses.
--quarterly (-q)
Affiche les totaux trimestriels. Ceci est une option de formatage et affecte la manière dont le rapport est affiché, pas les données qui sont incluses.
--arrival-date
Dans le rapport register, utilise la date d'arrivée (plutôt que la date de transaction) pour le tri.
--amount montant
Utilisé avec les commandes balance, register, et equity, ceci sélectionne le montant à utiliser pour le report. Pour les transactions avec plusieurs commodités, ceci s'assure que le montant est en montant spécifié.
--attached
N'affiche que les transactions attachées.
--cost (-C)
Utilisé avec les commandes balance et register, ceci fait afficher le coût de base de la transaction, tel que défini par le champ cost dans la base de prix.
--cleared-date date
Dans le rapport register, ne montre que les écritures qui ont été imputées à la date spécifiée.
--color où
Si le reporting de couleur est activé, cette option permet de spécifier où les couleurs doivent être appliquées. Les valeurs autorisées pour où sont : all, pager, none.
--account compte
Ceci est un synonyme pour la requête de rapport accounts. Il est utilisé ici pour que les options puissent être appliquées à la requête.
--commodity devise
Ceci est un synonyme pour la requête de rapport commodities. Il est utilisé ici pour que les options puissent être appliquées à la requête.
--decimal-point point
Spécifie le caractère à utiliser comme point décimal.
--date date
Utilisé avec toutes les commandes de reporting, ceci spécifie la date d'effet des transactions à inclure dans le rapport. Les dates peuvent être spécifiées en tant que chaînes de caractères, qui sont ensuite analysées par parse_date(1).
--date-format format
Ce symbole peut être utilisé pour spécifier le format d'une date.
--begin date
Ceci est un synonyme de --date. Il est utilisé pour spécifier le début d'une plage de dates.
--end date
Ceci est un synonyme de --date. Il est utilisé pour spécifier la fin d'une plage de dates.
--display-currency-symbol
Affiche le symbole de la devise à côté des chiffres de montant.
--double-entry
Force les rapports à être imprimés en double entrée. Ceci est le comportement par défaut pour balance, mais l'option peut être utilisée pour forcer le même comportement dans d'autres rapports.
--decimal-digits nombre
Cette option définit le nombre de décimales qui seront imprimées pour chaque montant.
--diff
Utilisé avec balance, ceci fait afficher l'écart entre deux périodes, en fonction des options --begin et --end.
--dir dossier
Ceci est utilisé pour spécifier un dossier dans lequel rechercher des fichiers de données.
--display-total-with-currency
Affiche le symbole de la devise à côté des chiffres de total.
--effective-date date
Dans le rapport register, utilise la date d'effet (plutôt que la date de transaction) pour le tri.
--exclude modèle
Ceci est un synonyme de --match, avec le sens inverse.
--exclude-memo
Ceci est un synonyme de --match-regex-memo, avec le sens inverse.
--family nom
Ceci est un synonyme de --match.
--file fichier
Ceci est un synonyme pour -f.
--format format
Ceci est utilisé pour spécifier le format d'une date, d'une transaction, ou d'une écriture.
--format-date format
Ceci est un synonyme pour --date-format.
--format-journal format
Ceci est utilisé pour spécifier le format d'une transaction.
--format-transaction format
Ceci est un synonyme pour --format-journal.
--format-entry format
Ceci est utilisé pour spécifier le format d'une écriture.
--history fichier
Permet de spécifier un fichier contenant les transactions de l'historique. Ceci est utilisé par la commande register.
--include modèle
Ceci est un synonyme de --match.
--include-memo
Ceci est un synonyme de --match-regex-memo.
--inventory (-i)
Utilisé avec la commande register, ceci fait que ledger affiche le bilan de l'inventaire de chaque compte.
--journal fichier
Ceci est un synonyme de -f.

FICHIERS

~/.ledgerrc: fichier de configuration pour ledger.

EXEMPLES

Afficher le solde de tous les comptes :

$ ledger balance

Afficher le solde des comptes de dépenses uniquement :

$ ledger balance expenses

Afficher le registre des transactions pour le mois dernier :

$ ledger register month ago

Afficher les transactions du compte « Checking » qui ont été effectuées après le 1er janvier 2005 :

$ ledger register Checking --begin 2005-01-01

Afficher le rapport de budget pour la période de reporting actuelle, en excluant les transactions des comptes de frais de déplacement :

$ ledger budget --current --exclude travel-expenses

REQUÊTES

La plupart des commandes de reporting de ledger acceptent une requête-de-rapport comme argument. Ceci est une chaîne de caractères qui est interprétée comme une requête de rapport, déterminant quels éléments seront inclus dans le rapport.

La syntaxe de la requête-de-rapport est la suivante :

requête-de-rapport ::= terme | terme requête-de-rapport

terme ::= [ '!' ] compte | [ '!' ] payee | [ '!' ] commodité | [ '!' ] date | [ '!' ] { métadonnées } | expr

métadonnées ::= 'compte' | 'payee' | 'commodity' | 'date' | 'code' | 'memo' | 'cleared' | 'status' | 'action' | 'tag' | 'xact'

expr ::= ...

Les mots clés peuvent être utilisés pour spécifier les champs à interroger. Par exemple, pour spécifier un compte, vous pouvez utiliser compte:. Les métadonnées les plus courantes sont : compte, payee, commodité, date, code, memo, cleared, status, action, tag, xact.

L'opérateur ! est utilisé pour inverser la signification d'une requête (c'est-à-dire exclure les éléments qui correspondent).

Il est possible de combiner plusieurs requêtes à l'aide des opérateurs logiques and, or, et not.

Les dates peuvent être spécifiées en utilisant la syntaxe de parse_date(1).

Des expressions arithmétiques peuvent être utilisées pour définir des plages de dates ou des montants.

ENTREES

La commande entry est utilisée pour générer une nouvelle transaction basée sur un modèle. Le modèle peut être une chaîne de caractères ou un fichier.

Lorsqu'un modèle est fourni, ledger compare le modèle aux transactions existantes dans le fichier de données et génère une nouvelle transaction qui est mise en forme de manière appropriée.

La syntaxe des modèles d'entrée est la même que celle des transactions dans un fichier de données ledger.

Par exemple, pour générer une transaction de paiement de loyer, vous pourriez utiliser le modèle suivant :

2023-10-01 Renta
    Expenses:Rent       $1200
    Assets:Checking

Ceci générerait une transaction avec la date du 1er octobre 2023, enregistrant un paiement de 1200 $ de votre compte de chèques vers le compte de dépenses de loyer.

--exchange "COMMODITY [, COMMODITY, ...]" (-X)
Rendre toutes les valeurs dans la commodity donnée, si un taux de conversion de prix peut être déterminé. Si plusieurs commodities sont données, les valeurs dans une commodity listée resteront telles quelles, et les autres seront affichées dans la première commodity listée vers laquelle elles peuvent être converties. Les taux sont toujours affichés par rapport à la date du posting pour lequel ils sont calculés. Cela signifie qu'un rapport register est un rapport de valeur historique. Pour les valeurs actuelles, il peut être préférable d'utiliser le rapport balance.
--gain (-G)
Afficher les gains (ou pertes) dans les valeurs des commodities au fil du temps.
--head number
Afficher uniquement les number premiers postings.
--historical (-H)
Évaluer les commodities à la date de leur acquisition.
--invert
Inverser la valeur des montants affichés.
--market (-V)
Afficher les valeurs de marché actuelles pour tous les montants. Ceci est déterminé d'une manière quelque peu magique. Il est probablement plus simple d'utiliser l'option --exchange.
--period time-period (-p)
Afficher les postings uniquement pour la time-period donnée.
--related (-r)
Afficher les postings qui sont liés à ceux qui auraient été affichés. Cela a pour effet d'afficher l'"autre côté" des postings.
--sort value-expression (-S)
Trier les postings en évaluant l' value-expression donnée. Notez qu'une liste d'expressions séparées par des virgules est autorisée, auquel cas chaque terme de tri est utilisé pour déterminer l'ordre final. Par exemple, pour trier par date puis par montant, on utiliserait :
ledger reg --sort 'date, amount'
L'ordre de tri peut être contrôlé par le signe '-'. Par exemple, pour trier en ordre chronologique inversé :
ledger reg --sort '-date'
--tail number
Afficher uniquement les number derniers postings.
--uncleared (-U)
Afficher uniquement les postings non compensés (c'est-à-dire récents).

select [sql-query]
Lister tous les postings correspondant à la sql-query. Cette commande permet de générer des requêtes de type SQL, par exemple :
ledger select date,amount from posts where account=~/Income/
source
Analyser un fichier journal et vérifier les erreurs. ledger retournera succès si aucune erreur n'est trouvée.
stats [report-query]
Fournir des informations sommaires sur tous les postings correspondant à report-query. Il fournit des informations telles que :
  • Plage de dates de tous les postings correspondants
  • Bénéficiaires uniques
  • Comptes uniques
  • Total des postings
  • Postings non compensés
  • Jours depuis le dernier posting
  • Postings des 7 derniers jours
  • Postings des 30 derniers jours
  • Postings de ce mois
xml [report-query]
Afficher les données relatives au rapport actuel au format XML. Il inclut tous les comptes et commodities impliqués dans le rapport, ainsi que les postings et les transactions qu'ils contiennent. Voir le manuel pour plus d'informations.

OPTIONS

--abbrev-len INT
Définir la longueur minimale à laquelle un compte peut être abrégé s'il ne rentre pas dans la account-width. Si INT est zéro, alors le nom du compte sera tronqué à droite. Si INT est supérieur à la account-width alors le compte sera tronqué à gauche, sans raccourcir les noms de compte pour tenir dans la largeur désirée.
--account EXPR
Ajouter EXPR à tous les comptes rapportés. C'est-à-dire, l'option --account "'Personal'" ajouterait Personal: et --account "tag('VAT')" ajouterait la valeur de l'étiquette VAT au début de chaque compte rapporté dans un rapport balance ou register.
--account-width INT
Définir la largeur de la colonne de compte dans le rapport register à INT caractères.
--actual (-L)
Rapporter uniquement les transactions réelles, sans transactions automatisées ou virtuelles utilisées.
--add-budget
Afficher uniquement les postings non budgétisés.
--align-intervals
Utiliser le début de la période de reporting comme début des intervalles, plutôt que le début de la semaine, du mois, du trimestre ou de l'année.
--amount EXPR (-t)
Appliquer l'expression de valeur donnée au montant du posting. En utilisant --amount EXPR, vous pouvez appliquer une transformation arbitraire aux postings.
--amount-data (-j)
Sur un rapport de registre, n'afficher que les dates et le montant des postings. Utile pour les applications de graphiques et de tableurs.
--amount-width INT
Définir la largeur en caractères de la colonne de montant dans le rapport register.
--anon
Anonymiser la sortie du registre, principalement pour l'envoi de rapports de bug.
--ansi
Utiliser la couleur si le terminal le supporte. Alias pour --color
--args-only
Ignorer les fichiers init et les variables d'environnement pour l'exécution de ledger.
--auto-match
Lors de la génération d'une transaction ledger à partir d'un fichier CSV à l'aide de la commande convert, faire correspondre automatiquement un compte du journal Ledger.
--aux-date
Afficher les dates auxiliaires pour tous les calculs. Alias pour --effective
--average (-A)
Afficher les valeurs moyennes sur le nombre de transactions au lieu des totaux courants.
--average-lot-prices
Rapporter le prix moyen auquel chaque marchandise a été achetée dans un rapport de solde.
--balance-format FMT
Spécifier le format à utiliser pour le rapport balance.
--base
Réduire les marchandises convertibles en bas de la conversion, par ex. afficher le temps en secondes.
--basis (-B)
Rapporter la base de coût sur toutes les écritures. Alias pour --cost
--begin DATE (-b)
Spécifier la DATE de début de tous les calculs. Les transactions antérieures à cette date seront ignorées.
--bold-if EXPR

QUERIES

The syntax for reporting queries can get somewhat complex. It is a series of query terms with an implicit OR operator between them. The following terms are accepted:

regex
A bare string is taken as a regular expression (PCRE) matching the full account name. Thus, to report the current balance for all assets and liabilities, you would use:
ledger bal asset liab
payee regex (@regex)
Query on the payee, rather than the account.
tag regex (%regex)
Query on tags.
note regex (=regex)
Query on anything found in an item's note.
code regex (#regex)
Query on the xact's optional code (which can be any string the user wishes).
term and term
Query terms are joined by an implicit OR operator. You can change this to AND by using the and keyword. For example, to show food expenditures occurring at Shakee's Pizza, you could say:
ledger reg food and @Shakee
term or term
When you wish to be more explicit, use the OR operator.
show
 
not term
Reverse the logical meaning of the following term. This can be used with parentheses to great effect:
ledger reg food and @Shakee and not dining
( term )
If you wish to mix OR and AND operators, it is often helpful to surround logical units with parentheses. NOTE: Because of the way some shells interpret parentheses, you should always escape them:
ledger bal \( assets or liab \) and not food

COMMANDES DE DÉBOGAGE

En plus des commandes de rapport régulières, ledger accepte plusieurs commandes de débogage :

args [requête-de-rapport]
Affiche une analyse complète de la façon dont ledger a interprété la requête-de-rapport donnée. Utile si vous voulez comprendre comment les requêtes de rapport sont traduites en expressions de valeur.
eval [expression-de-valeur]
Évalue l'expression-de-valeur donnée et imprime le résultat. Pour en savoir plus sur les expressions de valeur, consultez la section EXPRESSIONS.
format [chaîne-de-format]
Affiche une analyse de la façon dont la chaîne-de-format a été analysée, et de ce à quoi elle ressemblerait appliquée à une transaction d’exemple. Pour en savoir plus sur les chaînes de format, consultez la section FORMATS.
generate
Génère 50 transactions ledger composées aléatoirement mais valides.
parse [expression-de-valeur]
Analyse l'expression-de-valeur donnée et affiche une analyse de l’arbre d’expression et de sa valeur évaluée. Pour en savoir plus sur les expressions de valeur, consultez la section EXPRESSIONS.
python [fichier]
Lance un interpréteur Python pour lire le fichier donné. Ce qui est spécial à ce sujet, c’est que le module ledger est intégré, et non lu depuis le disque, de sorte qu’il ne nécessite pas que ledger soit installé quelque part, ni que les variantes de bibliothèque partagée soient construites.
reload
Recharge immédiatement tous les fichiers de données pour la session en cours. Ne peut être utilisé que dans le REPL.
template [modèle-brouillon]
Affiche des informations sur la façon dont le modèle-brouillon a été analysé. Voir la section sur les BROUILLONS.

ENVIRONNEMENT

Toute option de ledger peut être définie à l’aide d’une variable d’environnement si l’option a un nom long. Par exemple, définir la variable d’environnement LEDGER_DATE_FORMAT="%d.%m.%Y" aura le même effet que de spécifier --date-format '%d.%m.%Y' sur la ligne de commande. Cependant, les options sur la ligne de commande ont toujours priorité sur les paramètres des variables d’environnement.
