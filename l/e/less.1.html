LESS(1) Manuel des commandes générales LESS(1)

NOM

less - affiche le contenu d'un fichier dans un terminal

SYNTAXE

less -?
less --help
less -V
less --version
less [-[+]aABcCdeEfFgGiIJKLmMnNqQrRsSuUVwWX~]
[-b espace] [-h lignes] [-j ligne] [-k fichier_clé]
[-{oO} fichier_journal] [-p motif] [-P invite] [-t étiquette]
[-T fichier_étiquettes] [-x tab,...] [-y lignes] [-[z] lignes]
[-# décalage] [+[+]cmd] [--] [fichier]...
(Voir la section OPTIONS pour la syntaxe alternative des options avec des noms longs.)

DESCRIPTION

Less est un programme similaire à more(1), mais il possède beaucoup plus de fonctionnalités. Less n'a pas besoin de lire l'intégralité du fichier d'entrée avant de commencer, donc avec de gros fichiers d'entrée, il démarre plus rapidement que les éditeurs de texte comme vi(1). Less utilise termcap (ou terminfo sur certains systèmes), il peut donc s'exécuter sur une variété de terminaux. Il existe même un support limité pour les terminaux à copie carbone. (Sur un terminal à copie carbone, les lignes qui doivent être imprimées en haut de l'écran sont précédées d'un caret.)

COMMANDES

Les commandes sont basées à la fois sur more et vi. Les commandes peuvent être précédées d'un nombre décimal, appelé N dans les descriptions ci-dessous. Le nombre est utilisé par certaines commandes, comme indiqué.

Dans les descriptions suivantes, ^X signifie contrôle-X. ESC représente la touche ESCAPE ; par exemple, ESC-v signifie la séquence de deux caractères "ESCAPE", puis "v".

d ou ^D

ESC-j

ESC-k

Fait défiler horizontalement vers la droite pour afficher la fin de la ligne affichée la plus longue.
ESC-{ ou ^FLÈCHE GAUCHE
Fait défiler horizontalement vers la gauche pour revenir à la première colonne.
r ou ^R ou ^L
Repeint l'écran.
R
Repeint l'écran, en ignorant toute entrée mise en mémoire tampon. C'est-à-dire, recharge le fichier courant. Utile si le fichier change pendant qu'il est consulté.
F
Fait défiler vers l'avant, et continue d'essayer de lire à la fin du fichier. Normalement, cette commande serait utilisée lorsqu'on est déjà à la fin du fichier. C'est un moyen de surveiller la fin d'un fichier qui grandit pendant qu'il est consulté. (Le comportement est similaire à la commande "tail -f".) Pour arrêter d'attendre plus de données, entrez le caractère d'interruption (généralement ^C). Sur les systèmes qui prennent en charge poll(2), vous pouvez également utiliser ^X ou le caractère spécifié par l'option --intr. Si l'entrée est un pipe et que l'option --exit-follow-on-close est activée, less arrête automatiquement d'attendre des données lorsque le côté entrée du pipe est fermé.
ESC-F
Identique à F, mais dès qu'une ligne correspondant au dernier motif de recherche est trouvée, la cloche du terminal retentit et le défilement vers l'avant s'arrête.
g ou < ou ESC-<
Va à la ligne N dans le fichier, par défaut 1 (début du fichier). (Attention : cela peut être lent si N est grand.)
G ou > ou ESC->
Va à la ligne N dans le fichier, par défaut la fin du fichier. (Attention : cela peut être lent si N est grand, ou si N n'est pas spécifié et que l'entrée standard, plutôt qu'un fichier, est lue.)
ESC-G
Identique à G, sauf si aucun nombre N n'est spécifié et que l'entrée est l'entrée standard, va à la dernière ligne actuellement mise en mémoire tampon.
p ou %
Va à une position N pour cent dans le fichier. N doit être compris entre 0 et 100, et peut contenir un point décimal.
P
Va à la ligne contenant l'octet N dans le fichier.
{

L'accolade fermante correspondante est positionnée sur la dernière ligne de l'écran. S'il y a plus d'une accolade ouvrante sur la première ligne, un nombre N peut être utilisé pour spécifier la N-ième accolade sur la ligne.
}
Si une accolade fermante apparaît dans la dernière ligne affichée à l'écran, la commande } ira à l'accolade ouvrante correspondante. L'accolade ouvrante correspondante est positionnée sur la première ligne de l'écran. S'il y a plus d'une accolade fermante sur la dernière ligne, un nombre N peut être utilisé pour spécifier la N-ième accolade sur la ligne.
(
Identique à {, mais s'applique aux parenthèses plutôt qu'aux accolades.
)
Identique à }, mais s'applique aux parenthèses plutôt qu'aux accolades.
[
Identique à {, mais s'applique aux crochets plutôt qu'aux accolades.
]
Identique à }, mais s'applique aux crochets plutôt qu'aux accolades.

ESC-m
Suivi d'une lettre minuscule ou majuscule, efface la marque identifiée par cette lettre.
/motif
Recherche vers l'avant dans le fichier la N-ième ligne contenant le motif. N vaut 1 par défaut. Le motif est une expression régulière, telle qu'elle est reconnue par la bibliothèque d'expressions régulières fournie par votre système. Par défaut, la recherche est sensible à la casse (majuscules et minuscules sont considérées comme différentes) ; l'option -i peut être utilisée pour changer cela. La recherche commence à la première ligne affichée (mais voir les options -a et -j, qui modifient ce comportement).

Certains caractères sont spéciaux s'ils sont entrés au début du motif ; ils modifient le type de recherche plutôt que de faire partie du motif :

^N ou !
Recherche les lignes qui NE correspondent PAS au motif.
^E ou *
Recherche dans plusieurs fichiers. C'est-à-dire, si la recherche atteint la FIN du fichier courant sans trouver de correspondance, la recherche continue dans le fichier suivant dans la liste des arguments de la ligne de commande.
^F ou @
Commence la recherche à la première ligne du PREMIER fichier dans la liste des arguments de la ligne de commande, indépendamment de ce qui est actuellement affiché à l'écran ou des paramètres des options -a ou -j.
^K
Met en surbrillance tout texte correspondant au motif sur l'écran actuel, mais ne se déplace pas vers la première correspondance (CONSERVE la position actuelle).
^R
N'interprète pas les métacaractères d'expressions régulières ; c'est-à-dire, effectue une comparaison textuelle simple.
^S
Suivi d'un chiffre N entre 1 et 5. Seul le texte ayant une correspondance non vide pour le N-ième SOUS-MOTIF parentésé sera considéré comme correspondant au motif. Par exemple, rechercher "(abc)|(def)" modifié avec ^S1 chercherait les instances de "abc", mais mettrait en surbrillance les instances de "abc" et "def". (Pris en charge uniquement si less est compilé avec l'une des bibliothèques d'expressions régulières posix, pcre, ou pcre2.) Plusieurs modificateurs ^S peuvent être spécifiés, pour faire correspondre plus d'un sous-motif.
^W
RETOURNE dans le fichier courant. C'est-à-dire, si la recherche atteint la fin du fichier courant sans trouver de correspondance, la recherche continue depuis la première ligne du fichier courant jusqu'à la ligne où elle a commencé. Si le modificateur ^W est activé, le modificateur ^E est ignoré.
^L
Le caractère suivant est pris littéralement ; c'est-à-dire, il devient partie du motif même s'il s'agit de l'un des caractères modificateurs de recherche ci-dessus.
?motif
Recherche vers l'arrière dans le fichier la N-ième ligne contenant le motif. La recherche commence à la dernière ligne affichée (mais voir les options -a et -j, qui modifient ce comportement).

^N ou !

^E ou *
Recherche dans plusieurs fichiers. C'est-à-dire, si la recherche atteint le début du fichier courant sans trouver de correspondance, la recherche continue dans le fichier précédent dans la liste des arguments de la ligne de commande.
^F ou @
Commence la recherche à la dernière ligne du dernier fichier dans la liste des arguments de la ligne de commande, indépendamment de ce qui est actuellement affiché à l'écran ou des paramètres des options -a ou -j.
^K
Comme dans les recherches avant.
^R
Comme dans les recherches avant.
^S
Comme dans les recherches avant.
^W
RETOURNE dans le fichier courant. C'est-à-dire, si la recherche atteint le début du fichier courant sans trouver de correspondance, la recherche continue depuis la dernière ligne du fichier courant jusqu'à la ligne où elle a commencé.
^L
Comme dans les recherches avant.
ESC-/motif
Identique à "/*".
ESC-?motif
Identique à "?*".
n
Répète la recherche précédente, pour la N-ième ligne contenant le dernier motif. Si la recherche précédente a été modifiée par ^N, la recherche est effectuée pour la N-ième ligne NE contenant PAS le motif. Si la recherche précédente a été modifiée par ^E, la recherche continue dans le fichier suivant (ou précédent) si elle n'est pas satisfaite dans le fichier courant. Si la recherche précédente a été modifiée par ^R, la recherche est effectuée sans utiliser d'expressions régulières. Si la recherche précédente a été modifiée par ^W, la recherche fait un retour au début (ou à la fin) du fichier. Cela n'a aucun effet si la recherche précédente a été modifiée par ^F ou ^K.

Répète la recherche précédente, mais dans la direction inverse.
ESC-n

ESC-N
Répète la recherche précédente, mais dans la direction inverse et en traversant les frontières des fichiers.
ESC-u
Annule la mise en surbrillance de la recherche. Désactive la mise en surbrillance des chaînes correspondant au motif de recherche actuel. Si la mise en surbrillance est déjà désactivée à cause d'une commande ESC-u précédente, la met en surbrillance à nouveau. Toute commande de recherche désactivera également la mise en surbrillance. (La mise en surbrillance peut également être désactivée en basculant l'option -G ; dans ce cas, les commandes de recherche ne réactivent pas la mise en surbrillance.)
ESC-U
Comme ESC-u mais efface également le motif de recherche enregistré. Si la colonne de statut est activée via l'option -J, cela efface toutes les correspondances de recherche marquées dans la colonne de statut.
&motif
Affiche uniquement les lignes qui correspondent au motif ; les lignes qui ne correspondent pas au motif ne sont pas affichées. Si le motif est vide (si vous tapez & immédiatement suivi de ENTRÉE), tout filtrage est désactivé, et toutes les lignes sont affichées. Pendant que le filtrage est en vigueur, une esperluette est affichée au début de l'invite, comme rappel que certaines lignes du fichier peuvent être masquées. Plusieurs commandes & peuvent être saisies, dans ce cas seules les lignes qui correspondent à tous les motifs seront affichées.

^N ou !
Affiche uniquement les lignes qui NE correspondent PAS au motif.
^R
N'interprète pas les métacaractères d'expressions régulières ; c'est-à-dire, effectue une comparaison textuelle simple.
:e [nom_fichier]
Examine un nouveau fichier. Si le nom_fichier est manquant, le fichier "courant" (voir les commandes :n et :p ci-dessous) de la liste des fichiers dans la ligne de commande est réexaminé. Un signe de pourcentage (%) dans le nom_fichier est remplacé par le nom du fichier courant. Un signe dièse (#) est remplacé par le nom du fichier précédemment examiné. Cependant, deux signes de pourcentage consécutifs sont simplement remplacés par un seul signe de pourcentage. Cela vous permet d'entrer un nom de fichier qui contient un signe de pourcentage. De même, deux signes dièse consécutifs sont remplacés par un seul signe dièse. Le nom_fichier est inséré dans la liste des fichiers de la ligne de commande afin qu'il puisse être vu par les commandes :n et :p ultérieures. Si le nom_fichier se compose de plusieurs fichiers, ils sont tous insérés dans la liste des fichiers et le premier est examiné. Si le nom_fichier contient un ou plusieurs espaces, le nom_fichier entier doit être entouré de guillemets doubles (voir également l'option -").
^X^V ou E
Identique à :e. Attention : certains systèmes utilisent ^V comme caractère de littéralisation spécial. Sur ces systèmes, vous ne pourrez peut-être pas utiliser ^V.
:n
Examine le fichier suivant (de la liste des fichiers donnés dans la ligne de commande). Si un nombre N est spécifié, le N-ième fichier suivant est examiné.
:p
Examine le fichier précédent dans la liste de la ligne de commande. Si un nombre N est spécifié, le N-ième fichier précédent est examiné.
:x
Examine le premier fichier dans la liste de la ligne de commande. Si un nombre N est spécifié, le N-ième fichier de la liste est examiné.
:d
Supprime le fichier courant de la liste des fichiers.
t
Va à la balise suivante, s'il y a eu plus d'une correspondance pour la balise actuelle. Voir l'option -t pour plus de détails sur les balises.
T
Va à la balise précédente, s'il y a eu plus d'une correspondance pour la balise actuelle.
^O^N ou ^On
Recherche vers l'avant dans le fichier le N-ième prochain hyperlien OSC 8.
^O^P ou ^Op
Recherche vers l'arrière dans le fichier le N-ième précédent hyperlien OSC 8.
^O^L ou ^Ol
Saute à l'hyperlien OSC 8 actuellement sélectionné.
= ou ^G ou :f
Affiche des informations sur le fichier en cours de visualisation, y compris son nom et le numéro de ligne et le décalage d'octet de la dernière ligne affichée. Si possible, il affiche également la longueur du fichier, le nombre de lignes dans le fichier et le pourcentage du fichier avant la dernière ligne affichée.
-
Suivi de l'une des lettres d'option de la ligne de commande (voir OPTIONS ci-dessous), cela changera le paramètre de cette option et affichera un message décrivant le nouveau paramètre. Si un ^P (CONTROL-P) est entré immédiatement après le tiret, le paramètre de l'option est changé mais aucun message n'est affiché. Si l'option a une valeur numérique (telle que -b ou -h), ou une valeur de chaîne (telle que -P ou -t), une nouvelle valeur peut être entrée après la lettre de l'option. Si aucune nouvelle valeur n'est entrée, un message décrivant le paramètre actuel est affiché et rien n'est changé.
--
Comme la commande -, mais prend un long o

Vous pouvez entrer seulement le début d'un nom d'option, puis appuyer sur TAB pour trouver tous les noms d'options qui commencent par cette chaîne. Un ^P immédiatement après les deux tirets supprime l'impression d'un message décrivant le nouveau paramètre, comme dans la commande -.

Suivi d'une des lettres d'option de la ligne de commande, cela réinitialisera l' option à son réglage par défaut et imprimera un message décrivant le nouveau paramètre. (La commande "-+X" fait la même chose que "-+X" sur la ligne de commande.) Cela ne fonctionne pas pour les options à valeur chaîne.
--+
Similaire à la commande -+, mais prend un nom d'option long plutôt qu'une seule lettre d'option.
-!
Suivi d'une des lettres d'option de la ligne de commande, cela réinitialisera l' option à l'"opposé" de son réglage par défaut et imprimera un message décrivant le nouveau paramètre. Cela ne fonctionne pas pour les options numériques ou à valeur chaîne.
--!
Similaire à la commande -!, mais prend un nom d'option long plutôt qu'une seule lettre d'option.
_
(Tiret bas.) Suivi d'une des lettres d'option de la ligne de commande, cela imprimera un message décrivant le réglage actuel de cette option. Le réglage de l'option n'est pas modifié.
__
(Double tiret bas.) Similaire à la commande _ (tiret bas), mais prend un nom d'option long plutôt qu'une seule lettre d'option. Vous devez appuyer sur ENTRÉE ou RETOUR après avoir tapé le nom de l'option.

Provoque l'exécution de la commande cmd spécifiée à chaque fois qu'un nouveau fichier est examiné. Par exemple, +G fait en sorte que less affiche initialement chaque fichier en commençant par la fin plutôt que par le début.

Les sept commandes suivantes peuvent être valides ou non, en fonction de votre installation particulière.

v
Appelle un éditeur pour éditer le fichier actuellement visualisé. L'éditeur est tiré de la variable d'environnement VISUAL s'il est défini, ou EDITOR si VISUAL n'est pas défini, ou par défaut "vi" si ni VISUAL ni EDITOR n'est défini. Voir également la discussion de LESSEDIT sous la section PROMPTS ci-dessous.
! commande_shell
Appelle un shell pour exécuter la commande_shell donnée. Un signe pourcentage (%) dans la commande est remplacé par le nom du fichier courant. Un signe dièse (#) est remplacé par le nom du fichier précédemment examiné. "!!" répète la dernière commande shell. "!" sans commande shell appelle un shell interactif. Si un ^P (CONTROL-P) est saisi immédiatement après le !, aucun message "terminé" n'est imprimé après l'exécution de la commande shell. Sur les systèmes Unix, le shell est tiré de la variable d'environnement SHELL, ou par défaut "sh". Sur les systèmes MS-DOS, Windows et OS/2, le shell est le processeur de commandes normal.
# commande_shell
Similaire à la commande "!", sauf que la commande est étendue de la même manière que les chaînes d'invite. Par exemple, le nom du fichier courant serait donné sous la forme "%f".
| <m> commande_shell
<m> représente n'importe quelle lettre de marque. Envoie une section du fichier d'entrée à la commande shell donnée. La section du fichier à envoyer est comprise entre la position marquée par la lettre et l'écran actuel. L'écran entier actuel est inclus, que la position marquée soit avant ou après l'écran actuel. <m> peut également être ^ ou $ pour indiquer le début ou la fin du fichier respectivement. Si <m> est . ou un saut de ligne, l'écran actuel est envoyé. Si un ^P (CONTROL-P) est saisi immédiatement après la lettre de marque, aucun message "terminé" n'est imprimé après l'exécution de la commande shell.
s nom_fichier
Enregistre l'entrée dans un fichier. Cela ne fonctionne que si l'entrée est un tuyau, pas un fichier ordinaire.
^O^O
Exécute une commande shell pour ouvrir l'URI dans l'hyperlien OSC 8 actuel, sélectionné par une commande précédente ^O^N ou ^O^P. Pour trouver la commande shell, la variable d'environnement nommée "LESS_OSC8_xxx" est lue, où "xxx" est le schéma de l'URI (la partie avant le premier deux-points), ou est vide s'il n'y a pas de deux-points dans l'URI. La valeur de la variable d'environnement est ensuite étendue de la même manière que les chaînes d'invite (en particulier, toute instance de "%o" est remplacée par l'URI) pour produire une commande shell "gestionnaire" OSC 8. La sortie standard du gestionnaire est une commande shell "ouvreur" qui est ensuite exécutée pour ouvrir l'URI.

Il existe deux cas particuliers :

1.
Si l'URI commence par "#", le reste de l'URI est considéré comme la valeur du paramètre id dans un autre lien OSC 8 dans le même fichier, et ^O^O sautera simplement à ce lien.
2.
Si l'ouvreur commence par les caractères ":e" suivis d'un espace blanc et d'un nom de fichier, alors au lieu d'exécuter l'ouvreur comme une commande shell, le nom de fichier spécifié est ouvert dans l'instance actuelle de less.

Dans un cas simple où l'ouvreur accepte l'URI complète comme paramètre de ligne de commande, le gestionnaire peut être aussi simple que

echo monnavigateur '%o'
Dans d'autres cas, l'URI peut devoir être modifiée, le gestionnaire peut donc avoir à effectuer une manipulation de la valeur %o.

Si la variable LESS_OSC8_xxx n'est pas définie, la variable LESS_OSC8_ANY est essayée. Si ni LESS_OSC8_xxx ni LESS_OSC8_ANY n'est définie, les liens utilisant le schéma "xxx" ne peuvent pas être ouverts. Cependant, il existe des gestionnaires par défaut pour les schémas "man" (utilisé lorsque LESS_OSC8_man n'est pas défini) et "file" (utilisé lorsque LESS_OSC8_file n'est pas défini), qui devraient fonctionner sur les systèmes qui fournissent la commande sed(1) et un shell avec une syntaxe compatible avec le shell Bourne sh(1). Si vous utilisez LESS_OSC8_ANY pour remplacer LESS_OSC8_file, vous devez définir LESS_OSC8_file sur "-" pour indiquer que la valeur par défaut ne doit pas être utilisée, et de même pour LESS_OSC8_man.

L'URI passée à un gestionnaire OSC8 via %o est garantie de ne pas contenir de guillemets simples ou doubles, mais elle peut contenir d'autres métacaractères shell tels que des points-virgules, des signes dollar, des esperluettes, etc. Le gestionnaire doit prendre soin de mettre correctement entre guillemets les paramètres de la commande ouvreur, pour éviter l'exécution de commandes shell non intentionnelles dans le cas de l'ouverture d'une URI contenant des métacaractères shell. De plus, comme la commande gestionnaire est étendue comme une invite de commande, tous les métacaractères interprétés par l'expansion d'invite (tels que pourcentage, point, deux-points, antislash, etc.) doivent être échappés avec un antislash (voir la section PROMPTS pour plus de détails).

^X
Lorsque le message "Attente de données" est affiché, par exemple lors de la commande F, appuyer sur ^X arrêtera less d'attendre et retournera à une invite. Cela peut amener less à penser que le fichier se termine à la position actuelle, il peut donc être nécessaire d'utiliser la commande R ou F pour voir plus de données. L'option --intr peut être utilisée pour spécifier un caractère différent à utiliser à la place de ^X. Cette commande ne fonctionne que sur les systèmes qui prennent en charge la fonction poll(2). Sur les systèmes sans poll(2), le caractère d'interruption (généralement ^C) peut être utilisé à la place.

OPTIONS

Les options de la ligne de commande sont décrites ci-dessous. La plupart des options peuvent être modifiées pendant que less est en cours d'exécution, via la commande "-".

Certaines options peuvent être données sous l'une des deux formes : soit un tiret suivi d'une seule lettre, soit deux tirets suivis d'un nom d'option long. Un nom d'option long peut être abrégé tant que l'abréviation est sans ambiguïté. Par exemple, --mouse peut être abrégé en --mou, mais pas en --mo, car --mouse et --modelines commencent tous deux par --mo. Certains noms d'options longues sont en majuscules, comme --QUIT-AT-EOF, par opposition à --quit-at-eof. Ces noms d'options n'ont besoin que de leur première lettre en majuscule ; le reste du nom peut être en majuscule ou en minuscule. Par exemple, --Quit-at-eof est équivalent à --QUIT-AT-EOF.

Les options sont également tirées de la variable d'environnement "LESS". Par exemple, pour éviter de taper "less -options ..." chaque fois que less est invoqué, vous pourriez dire à csh :

setenv LESS "-options"

ou si vous utilisez sh :

LESS="-options"; export LESS

Sur MS-DOS et Windows, vous n'avez pas besoin des guillemets, mais vous devez faire attention à ce que les signes pourcentage dans la chaîne d'options ne soient pas interprétés comme une expansion de variable d'environnement.

La variable d'environnement est analysée avant la ligne de commande, donc les options de la ligne de commande remplacent la variable d'environnement LESS. Si une option apparaît dans la variable LESS, elle peut être réinitialisée à sa valeur par défaut sur la ligne de commande en commençant l'option de la ligne de commande par "-+".

Certaines options comme -k ou -D nécessitent une chaîne pour suivre la lettre d'option. La chaîne pour cette option est considérée comme se terminant lorsqu'un signe dollar ($) est trouvé. Par exemple, vous pouvez définir deux options -D comme suit :

LESS="Dnwb$Dsbw"

Si l'option --use-backslash apparaît plus tôt dans les options, alors un signe dollar ou un antislash peut être inclus littéralement dans une chaîne d'option en le faisant précéder d'un antislash. Si l'option --use-backslash n'est pas activée, alors les antislash ne sont pas traités spécialement, et il n'y a aucun moyen d'inclure un signe dollar dans la chaîne d'option.

-? ou --help
Cette option affiche un résumé des commandes acceptées par less (identique à la commande h). (Selon la façon dont votre shell interprète le point d'interrogation, il peut être nécessaire de mettre le point d'interrogation entre guillemets, ainsi : "-\?".)
-a ou --search-skip-screen
Par défaut, les recherches avant commencent en haut de l'écran affiché et les recherches arrière commencent en bas de l'écran affiché (sauf pour les recherches répétées invoquées par les commandes n ou N, qui commencent après ou avant la ligne "cible" respectivement ; voir l'option -j pour plus d'informations sur la ligne cible). L'option -a fait en sorte que les recherches avant commencent plutôt en bas de l'écran et les recherches arrière en haut de l'écran, sautant ainsi toutes les lignes affichées à l'écran.
-A ou --SEARCH-SKIP-SCREEN
Fait en sorte que toutes les recherches avant (pas seulement les recherches non répétées) commencent juste après la ligne cible, et toutes les recherches arrière commencent juste avant la ligne cible. Ainsi, les recherches avant sauteront une partie de l'écran affiché (de la première ligne jusqu'à la ligne cible incluse). De même, les recherches arrière.
--skip-screen=n
Les recherches par mot-clé sauteront l'écran affiché de la dernière ligne jusqu'à la ligne cible incluse. C'était le comportement par défaut dans les versions de less antérieures à la 441.
-bn ou --buffers=n
Spécifie la quantité d'espace tampon que less utilisera pour chaque fichier, en unités de kilo-octets (1024 octets). Par défaut, 64 Ko d'espace tampon sont utilisés pour chaque fichier (sauf si le fichier est un tube ; voir l'option -B). L'option -b spécifie au lieu de cela que n kilo-octets d'espace tampon doivent être utilisés pour chaque fichier. Si n est -1, l'espace tampon est illimité ; c'est-à-dire que le fichier entier peut être lu en mémoire.
-B ou --auto-buffers
Par défaut, lorsque des données sont lues à partir d'un tube, des tampons sont alloués automatiquement au besoin. Si une grande quantité de données est lue à partir du tube, cela peut entraîner l'allocation d'une grande quantité de mémoire. L'option -B désactive cette allocation automatique de tampons pour les tubes, de sorte que seulement 64 Ko (ou la quantité d'espace spécifiée par l'option -b) sont utilisés pour le tube. Attention : l'utilisation de -B peut entraîner un affichage erroné, car seule la partie la plus récemment visualisée des données du tube est conservée en mémoire ; toutes les données antérieures sont perdues. Les caractères perdus sont affichés sous forme de points d'interrogation.
-c ou --clear-screen
Provoque le redessin complet de l'écran depuis la ligne supérieure vers le bas. Par défaut, les redessins complets de l'écran sont effectués en faisant défiler depuis le bas de l'écran.
-C ou --CLEAR-SCREEN
Identique à -c, pour la compatibilité avec les anciennes versions de less.
-d ou --dumb
L'option -d supprime le message d'erreur normalement affiché si le terminal est basique ; c'est-à-dire qu'il manque certaines capacités importantes, comme la capacité d'effacer l'écran ou de faire défiler en arrière. L'option -d ne modifie pas autrement le comportement de less sur un terminal basique.
-Dxcouleur ou --color=xcouleur
Change la couleur de différentes parties du texte affiché. x est un caractère unique qui sélectionne le type de texte dont la couleur est définie :
B
Caractères binaires.
C
Caractères de contrôle.
E
Erreurs et messages d'information.
H
Lignes et colonnes d'en-tête, définies via l'option --header.
M
Lettres de marquage dans la colonne d'état.
N
Numéros de ligne activés via l'option -N.
P
Invites.
R
Le caractère de défilement r.
S
Résultats de recherche.
W
La mise en surbrillance activée via l'option -w.
1-5
Le texte d'un résultat de recherche qui correspond au premier à la cinquième sous-expression entre parenthèses. La coloration des sous-expressions ne fonctionne que si less est compilé avec l'une des bibliothèques d'expressions régulières posix, pcre ou pcre2.
d
Texte en gras.
k
Texte clignotant.
s
Texte en surimpression (vidéo inversée).
u
Texte souligné.
Les lettres majuscules et les chiffres ne peuvent être utilisés que lorsque l'option --use-color est activée. Lorsque la couleur du texte est spécifiée à la fois par une lettre majuscule et une lettre minuscule, la lettre majuscule a la priorité. Par exemple, les messages d'erreur sont normalement affichés en texte surimprimé. Donc, si "s" et "E" se voient attribuer une couleur, la couleur "E" s'applique aux messages d'erreur, et la couleur "s" s'applique aux autres textes surimprimés. Les lettres minuscules font référence au texte en gras et souligné formé par surimpression avec des retours arrière (voir l'option -U) et au texte non contenu (tel que les numéros de ligne et les invites), mais pas au texte formaté à l'aide de séquences d'échappement ANSI avec l'option -R (mais voir la note ci-dessous pour un comportement différent sur Windows et MS-DOS).

Une lettre minuscule peut être suivie d'un + pour indiquer que le changement de format normal et la couleur spécifiée doivent tous deux être utilisés. Par exemple, -Dug affiche le texte souligné en vert sans soulignement ; la couleur verte a remplacé le formatage de soulignement habituel. Mais -Du+g affiche le texte souligné à la fois en vert et en format souligné.

couleur est soit une chaîne de couleur 4 bits, soit une chaîne de couleur 8 bits :

Une chaîne de couleur 4 bits est composée d'un ou deux caractères, où le premier caractère spécifie la couleur du premier plan et le second la couleur de l'arrière-plan comme suit :

b
Bleu
c
Cyan
g

k

m

r

La lettre majuscule correspondante désigne une nuance plus vive de la couleur. Par exemple, -DNGk affiche les numéros de ligne en texte vert vif sur fond noir, et -DEbR affiche les messages d'erreur en texte bleu sur fond rouge vif. Si l'un des caractères est un "-" ou est omis, la couleur correspondante est définie sur celle du texte normal.

Une chaîne de couleur 8 bits est constituée d'un ou deux entiers décimaux séparés par un point, où le premier entier spécifie la couleur du premier plan et le second la couleur de l'arrière-plan. Chaque entier est une valeur comprise entre 0 et 255 inclusivement, qui sélectionne une valeur de couleur "CSI 38;5" (voir https://en.wikipedia.org/wiki/ANSI_escape_code#SGR). Si l'un des entiers est un "-" ou est omis, la couleur correspondante est définie sur celle du texte normal.

Une chaîne de couleur 4 bits ou 8 bits peut être suivie d'un ou plusieurs des caractères suivants pour définir des attributs de texte en plus de la couleur.

s ou ~

Souligné

Clignotant

Sur MS-DOS et Windows, l'option --color se comporte différemment de ce qui est décrit ci-dessus de la manière suivante :

  • Les attributs de texte gras (d et *) et clignotant (l et &) à la fin d'une chaîne de couleur ne sont pas pris en charge.
  • Les lettres de sélection de couleur minuscules font référence au texte formaté par des séquences d'échappement ANSI avec -R, en plus du texte surimprimé et non contenu (mais voir -Da).
  • Pour des raisons historiques, lorsqu'une lettre de sélection de couleur minuscule est suivie d'une valeur de couleur numérique, le nombre n'est pas interprété comme une valeur de couleur "CSI 38;5" comme décrit ci-dessus, mais plutôt comme une valeur d'attributs 4 bits de CHAR_INFO, comprise entre 0 et 15 (voir https://learn.microsoft.com/en-us/windows/console/char-info-str).

    Pour éviter toute confusion, il est recommandé d'utiliser les lettres équivalentes plutôt que les chiffres après un sélecteur de couleur minuscule sur MS-DOS/Windows.

  • Les valeurs de couleur numériques ("CSI 38;5" couleur) suivant une lettre de sélection de couleur majuscule ne sont pas prises en charge sur les systèmes antérieurs à Windows 10.
  • Seul un ensemble limité de séquences d'échappement ANSI pour définir la couleur dans le contenu fonctionne correctement. Les séquences de couleur 4 bits fonctionnent, mais les séquences de couleur "CSI 38;5" ne fonctionnent pas.
  • L'option -Da rend le comportement de --color plus similaire à son comportement sur les systèmes non-MS-DOS/Windows en (1) faisant en sorte que les lettres de sélecteur de couleur minuscules n'affectent pas le texte formaté avec des séquences d'échappement ANSI, et (2) permettant aux séquences de couleur "CSI 38;5" dans le contenu de fonctionner en les transmettant au terminal (uniquement sur Windows 10 et versions ultérieures ; sur les systèmes Windows antérieurs, de telles séquences ne fonctionnent pas, quel que soit le réglage de -Da).
-e ou --quit-at-eof
Fait en sorte que less quitte automatiquement la deuxième fois qu'il atteint la fin du fichier. Par défaut, la seule façon de quitter less est via la commande "q".
-E ou --QUIT-AT-EOF
Fait en sorte que less quitte automatiquement la première fois qu'il atteint la fin du fichier.
-f ou --force
Force l'ouverture des fichiers non réguliers. (Un fichier non régulier est un répertoire ou un fichier spécial de périphérique.) Supprime également le message d'avertissement lors de l'ouverture d'un fichier binaire. Par défaut, less refuse d'ouvrir les fichiers non réguliers. Notez que certains systèmes d'exploitation n'autorisent pas la lecture des répertoires, même si -f est activé.
-F ou --quit-if-one-screen
Fait en sorte que less quitte automatiquement si le fichier entier peut être affiché sur le premier écran. Voir également la description de la variable d'environnement LESS_SHELL_LINES ci-dessous.
-g ou --hilite-search
Normalement, less mettra en surbrillance TOUTES les chaînes qui correspondent à la dernière commande de recherche. L'option -g modifie ce comportement pour ne mettre en surbrillance que la chaîne particulière qui a été trouvée par la dernière commande de recherche. Cela peut faire que less s'exécute un peu plus rapidement que par défaut.
-G ou --HILITE-SEARCH
L'option -G supprime toute mise en surbrillance des chaînes trouvées par les commandes de recherche.
-hn ou --max-back-scroll=n
Spécifie un nombre maximum de lignes à faire défiler en arrière. S'il est nécessaire de faire défiler en arrière plus de n lignes, l'écran est redessiné dans un sens avant. (Si le terminal n'a pas la capacité de faire défiler en arrière, -h0 est implicite.)
-i ou --ignore-case
Fait en sorte que les recherches ignorent la casse ; c'est-à-dire que les majuscules et les minuscules sont considérées comme identiques. Cette option est ignorée si des lettres majuscules apparaissent dans le modèle de recherche ; autrement dit, si un modèle contient des lettres majuscules, cette recherche n'ignore pas la casse.
-I ou --IGNORE-CASE
Comme -i, mais les recherches ignorent la casse même si le modèle contient des lettres majuscules.
-jn ou --jump-target=n
Spécifie une ligne à l'écran où la ligne "cible" doit être positionnée. La ligne cible est la ligne spécifiée par toute commande visant à rechercher un motif, à sauter à un numéro de ligne, à sauter à un pourcentage du fichier
age ou sauter vers une balise a. La ligne de l'écran peut être spécifiée par un numéro : la ligne supérieure de l'écran est 1, la suivante est 2, et ainsi de suite. Le numéro peut être négatif pour spécifier une ligne par rapport au bas de l'écran : la ligne inférieure de l'écran est -1, l'avant-dernière est -2, et ainsi de suite. Alternativement, la ligne de l'écran peut être spécifiée comme une fraction de la hauteur de l'écran, en commençant par un point décimal : .5 est au milieu de l'écran, .3 est à trois dixièmes de la première ligne, et ainsi de suite. Si la ligne est spécifiée comme une fraction, le numéro de ligne réel est recalculé si la fenêtre du terminal est redimensionnée. Si l'option --header est utilisée et que la ligne cible spécifiée par -j serait masquée par l'en-tête, la ligne cible est déplacée vers la première ligne après l'en-tête.

Si une forme de l'option -j est utilisée, les recherches avant répétées (invoquées avec « n » ou « N ») commencent à la ligne immédiatement après la ligne cible, et les recherches arrière répétées commencent à la ligne cible, sauf indication contraire de -a ou -A. Par exemple, si « -j4 » est utilisé, la ligne cible est la quatrième ligne de l'écran, donc les recherches avant commencent à la cinquième ligne de l'écran. Cependant, les recherches non répétées (invoquées avec « / » ou « ? ») commencent toujours respectivement au début ou à la fin de l'écran courant.

-J ou --status-column
Affiche une colonne d'état sur le bord gauche de l'écran. Le caractère affiché dans la colonne d'état peut être l'un des suivants :
>
La ligne est coupée avec l'option -S, et le texte coupé au-delà du bord droit de l'écran contient une correspondance pour la recherche actuelle.
<
La ligne est décalée horizontalement, et le texte décalé au-delà du bord gauche de l'écran contient une correspondance pour la recherche actuelle.
=
La ligne est à la fois coupée et décalée, et il y a des correspondances au-delà des deux bords de l'écran.
*
Il y a des correspondances dans la partie visible de la ligne, mais aucune à droite ou à gauche de celle-ci.
a-z, A-Z
La ligne a été marquée avec la lettre correspondante via la commande m ou M.
-knomdefichier ou --lesskey-file=nomdefichier
Induit less à ouvrir et interpréter le fichier nommé comme un fichier binaire lesskey(1). Plusieurs options -k peuvent être spécifiées. Si la variable d'environnement LESSKEY ou LESSKEY_SYSTEM est définie, ou si un fichier lesskey est trouvé à un endroit standard (voir LIAISONS DE CLÉS), il est également utilisé comme fichier lesskey. Notez l'avertissement ci-dessous sous « --lesskey-content ».
--lesskey-src=nomdefichier
Induit less à ouvrir et interpréter le fichier nommé comme un fichier source lesskey(1). Si la variable d'environnement LESSKEYIN ou LESSKEYIN_SYSTEM est définie, ou si un fichier source lesskey est trouvé à un endroit standard (voir LIAISONS DE CLÉS), il est également utilisé comme fichier source lesskey. Avant la version 582, le programme lesskey devait être exécuté pour convertir un fichier source lesskey en un fichier binaire lesskey pour que less puisse l'utiliser. Les versions plus récentes de less lisent directement le fichier source lesskey et ignorent le fichier binaire si le fichier source existe. Notez l'avertissement ci-dessous sous « --lesskey-content ».
--lesskey-content=texte
Induit less à interpréter le texte spécifié comme le contenu d'un fichier source lesskey(1). Dans le texte, les lignes lesskey peuvent être séparées par des nouvelles lignes comme d'habitude, ou par des points-virgules. Un point-virgule littéral peut être représenté par une barre oblique inverse suivie d'un point-virgule.

Avertissement : certaines variables d'environnement comme LESS, LESSSECURE, LESSCHARSET et d'autres, qui sont utilisées tôt au démarrage, ne peuvent pas être définies dans un fichier spécifié par une option de ligne de commande (--lesskey, --lesskey-src ou --lesskey-content). Lors de l'utilisation d'un fichier lesskey pour définir des variables d'environnement, il est plus sûr d'utiliser le fichier lesskey par défaut, ou de spécifier le fichier en utilisant les variables d'environnement LESSKEYIN ou LESSKEY_CONTENT plutôt que d'utiliser une option de ligne de commande.

-K ou --quit-on-intr
Induit less à quitter immédiatement (avec le statut 2) lorsqu'un caractère d'interruption (généralement ^C) est tapé. Normalement, un caractère d'interruption amène less à arrêter ce qu'il fait et à revenir à son invite de commande. Notez que l'utilisation de cette option rend impossible le retour à l'invite de commande depuis la commande « F ».
-L ou --no-lessopen
Ignore la variable d'environnement LESSOPEN (voir la section PRÉPROCESSEUR D'ENTRÉE ci-dessous). Cette option peut être définie à l'intérieur de less, mais elle ne s'appliquera qu'aux fichiers ouverts ultérieurement, pas au fichier actuellement ouvert.
-m ou --long-prompt
Induit less à afficher une invite verbeuse (comme more(1)), avec le pourcentage du fichier. Par défaut, less affiche une invite avec un deux-points.
-M ou --LONG-PROMPT
Induit less à afficher une invite encore plus verbeuse que more(1).
-n ou --line-numbers
Supprime les numéros de ligne. Le défaut (utiliser les numéros de ligne) peut rendre less plus lent dans certains cas, notamment avec un très grand fichier d'entrée. L'utilisation des numéros de ligne signifie : le numéro de ligne sera affiché dans l'invite verbeuse et dans la commande =, et la commande v passera le numéro de ligne actuel à l'éditeur (voir aussi la discussion de LESSEDIT dans INVITES ci-dessous).
-N ou --LINE-NUMBERS
Affiche un numéro de ligne au début de chaque ligne affichée.
-onomdefichier ou --log-file=nomdefichier
Induit less à copier son entrée dans le fichier nommé pendant qu'il est visualisé. Cela ne s'applique que lorsque le fichier d'entrée est un tube, pas un fichier ordinaire. Si le fichier existe déjà, less demandera confirmation avant de l'écraser.
-Onomdefichier ou --LOG-FILE=nomdefichier
L'option -O est similaire à -o, mais elle écrasera un fichier existant sans demander de confirmation.

Si aucun fichier journal n'a été spécifié, les options -o et -O peuvent être utilisées depuis l'intérieur de less pour spécifier un fichier journal. Sans nom de fichier, elles indiqueront simplement le nom du fichier journal. La commande « s » est équivalente à la spécification de -o depuis l'intérieur de less.

-pmotif ou --pattern=motif
L'option -p sur la ligne de commande est équivalente à spécifier +/motif ; c'est-à-dire qu'elle indique à less de commencer à la première occurrence de motif dans le fichier.
-Pinvite ou --prompt=invite
Permet de personnaliser les trois styles d'invite à votre convenance. Cette option serait normalement placée dans la variable d'environnement LESS, plutôt que d'être tapée à chaque commande less. Une telle option doit soit être la dernière option dans la variable LESS, soit être terminée par un signe dollar.
-Ps suivi d'une chaîne modifie l'invite par défaut (courte) pour qu'elle devienne cette chaîne.
-Pm modifie l'invite moyenne (-m).
-PM modifie l'invite longue (-M).
-Ph modifie l'invite pour l'écran d'aide.
-P= modifie le message affiché par la commande =.
-Pw modifie le message affiché pendant l'attente de données (dans la commande « F »).

Toutes les chaînes d'invite consistent en une séquence de caractères et de séquences d'échappement spéciales. Voir la section sur les INVITES pour plus de détails.

-q ou --quiet ou --silent
Entraîne un fonctionnement modérément « silencieux » : le carillon du terminal ne retentit pas si une tentative est faite pour défiler au-delà de la fin du fichier ou avant le début du fichier. Si le terminal a un « carillon visuel », celui-ci est utilisé à la place. Le carillon retentira pour certaines autres erreurs, telles que la saisie d'un caractère invalide. Par défaut, le carillon du terminal retentit dans tous ces cas.
-Q ou --QUIET ou --SILENT
Entraîne un fonctionnement totalement « silencieux » : le carillon du terminal ne retentit jamais. Si le terminal a un « carillon visuel », celui-ci est utilisé dans tous les cas où le carillon du terminal aurait retenti.
-r ou --raw-control-chars
Affiche les caractères de contrôle « bruts ». Par défaut, les caractères de contrôle sont affichés en utilisant la notation caret ; par exemple, un contrôle-A (octal 001) est affiché comme « ^A » (avec quelques exceptions comme décrit sous l'option -U). Avertissement : lorsque l'option -r est utilisée, less ne peut pas suivre l'apparence réelle de l'écran (car cela dépend de la manière dont l'écran répond à chaque type de caractère de contrôle). Ainsi, divers problèmes d'affichage peuvent survenir, tels que des lignes longues coupées au mauvais endroit.

L'UTILISATION DE L'OPTION -r EST DANGEREUSE ET NON RECOMMANDÉE.
L'option -r peut être définie sur la ligne de commande ou via la commande -, mais pour éviter une utilisation involontaire, elle ne peut pas être définie dans une variable d'environnement LESS. Si -r apparaît dans une variable d'environnement LESS, elle est traitée comme si c'était -R.

-R ou --RAW-CONTROL-CHARS
Comme -r, mais seul un ensemble limité de séquences d'échappement est émis sous forme « brute ». Contrairement à -r, l'apparence de l'écran est correctement maintenue. Les séquences émises brutes sont :

1. Séquences SGR ANSI (« couleur »)

2. Hyperliens OSC 8

3. Autres séquences OSC, si le numéro de type OSC est listé dans la variable d'environnement LESSANSIOSCALLOW

4. Séquences OSC commençant par un caractère introductif non standard (c'est-à-dire autre chose que « ] »), si le caractère est listé dans la variable d'environnement LESSANSIOSCCHARS suivi d'un astérisque

Les séquences d'échappement de couleur ANSI sont des séquences de la forme :

ESC [ ... m

où « ... » est composé de zéro ou plusieurs caractères de spécification de couleur. Les séquences d'échappement de couleur ne sont supportées que lorsque la couleur est modifiée à l'intérieur d'une seule ligne, pas entre les lignes. En d'autres termes, le début de chaque ligne est supposé être normal (non coloré), indépendamment des séquences d'échappement dans les lignes précédentes.

Vous pouvez faire en sorte que less pense que des caractères autres que « m » puissent terminer les séquences d'échappement de couleur ANSI en définissant la variable d'environnement LESSANSIENDCHARS sur la liste des caractères qui peuvent terminer une séquence d'échappement de couleur. Et vous pouvez faire en sorte que less pense que des caractères autres que les caractères standard peuvent apparaître entre l'ESC

et le m en définissant la variable d'environnement LESSANSIMIDCHARS sur la liste des caractères qui peuvent apparaître.

Les séquences OSC sont de la forme :

ESC ] N ; ... \7

où le numéro de type OSC N est un entier décimal. La séquence de terminaison peut être soit un caractère BEL (\7) comme ci-dessus, soit la séquence à deux caractères « ESC   ».

-s ou --squeeze-blank-lines
Fait en sorte que les lignes vides consécutives soient réduites à une seule ligne vide. Ceci est utile lors de la visualisation de la sortie de nroff(1).
-S ou --chop-long-lines
Fait en sorte que les lignes plus longues que la largeur de l'écran soient coupées (tronquées) plutôt que renvoyées à la ligne. C'est-à-dire que la partie d'une ligne longue qui ne tient pas dans la largeur de l'écran n'est pas affichée tant que vous n'appuyez pas sur DROITE-FLÈCHE. Le comportement par défaut est de renvoyer les lignes longues à la ligne ; c'est-à-dire d'afficher le reste sur la ligne suivante. Voir aussi l'option --wordwrap. Tant que l'option --header est active, l'option -S est ignorée et les lignes plus longues que la largeur de l'écran sont tronquées.
-ttag ou --tag=tag
L'option -t, suivie immédiatement d'une balise TAG, modifiera le fichier contenant cette balise. Pour que cela fonctionne, des informations de balise doivent être disponibles ; par exemple, il peut y avoir un fichier dans le répertoire courant appelé « tags », qui a été précédemment construit par ctags(1) ou une commande équivalente. Si la variable d'environnement LESSGLOBALTAGS est définie, elle est considérée comme le nom d'une commande compatible avec global(1), et cette commande est exécutée pour trouver la balise. (Voir http://www.gnu.org/software/global/global.html). L'option -t peut également être spécifiée depuis less (en utilisant la commande -) comme moyen d'examiner un nouveau fichier. La commande « :t » équivaut à spécifier -t depuis less.
-Ttagsfile ou --tag-file=tagsfile
Spécifie un fichier de balises à utiliser à la place de « tags ».
-u ou --underline-special
Fait en sorte que les retours arrière et les retours chariot soient traités comme des caractères imprimables ; c'est-à-dire qu'ils sont envoyés au terminal lorsqu'ils apparaissent dans l'entrée.
-U ou --UNDERLINE-SPECIAL
Fait en sorte que les retours arrière, les tabulations, les retours chariot et les « caractères de formatage » (tels que définis par Unicode) soient traités comme des caractères de contrôle ; c'est-à-dire qu'ils sont gérés comme spécifié par l'option -r.

Par défaut, si ni -u ni -U n'est donné, les retours arrière qui apparaissent adjacents à un caractère de soulignement sont traités spécialement : le texte souligné est affiché en utilisant la capacité de soulignement matériel du terminal. De plus, les retours arrière qui apparaissent entre deux caractères identiques sont traités spécialement : le texte surligné est imprimé en utilisant la capacité de gras matériel du terminal. Les autres retours arrière sont supprimés, ainsi que le caractère précédent. Les retours chariot immédiatement suivis d'un saut de ligne sont supprimés. Les autres retours chariot sont gérés comme spécifié par l'option -r. Les caractères de formatage Unicode, tels que le Byte Order Mark, sont envoyés au terminal. Le texte qui est surligné ou souligné peut être recherché si ni -u ni -U n'est actif.

Voir aussi les options --proc-backspace, --proc-tab et --proc-return.

-V ou --version
Affiche le numéro de version de less.
-w ou --hilite-unread
Met temporairement en surbrillance la première ligne « nouvelle » après un déplacement avant d'une page complète. La première ligne « nouvelle » est la ligne immédiatement après la ligne précédemment en bas de l'écran. Met également en surbrillance la ligne cible après une commande g ou p. La surbrillance est supprimée lors de la prochaine commande qui provoque un déplacement. Si l'option --status-line est active, toute la ligne (sur la largeur de l'écran) est mise en surbrillance. Sinon, seul le texte de la ligne est mis en surbrillance, sauf si l'option -J est active, auquel cas seule la colonne d'état est mise en surbrillance.
-W ou --HILITE-UNREAD
Similaire à -w, mais met temporairement en surbrillance la première nouvelle ligne après tout déplacement avant supérieur à une ligne.
-xn,... ou --tabs=n,...
Définit les taquets de tabulation. Si un seul n est spécifié, les taquets de tabulation sont définis aux multiples de n. Si plusieurs valeurs séparées par des virgules sont spécifiées, les taquets de tabulation sont définis à ces positions, puis continuent avec le même espacement que les deux dernières. Par exemple, « -x9,17 » définira des tabulations aux positions 9, 17, 25, 33, etc. La valeur par défaut de n est 8.
-X ou --no-init
Désactive l'envoi des chaînes d'initialisation et de désinitialisation termcap au terminal. Ceci est parfois souhaitable si la chaîne de désinitialisation fait quelque chose d'inutile, comme effacer l'écran.
-yn ou --max-forw-scroll=n
Spécifie un nombre maximum de lignes à faire défiler vers l'avant. S'il est nécessaire de faire défiler plus de n lignes vers l'avant, l'écran est repeint à la place. L'option -c ou -C peut être utilisée pour repeindre depuis le haut de l'écran si désiré. Par défaut, tout déplacement avant provoque un défilement.
-zn ou --window=n ou -n
Change la taille de la fenêtre de défilement par défaut à n lignes. La valeur par défaut est un écran complet. Les commandes z et w peuvent également être utilisées pour changer la taille de la fenêtre. Le « z » peut être omis pour la compatibilité avec certaines versions de more(1). Si le nombre n est négatif, il indique n lignes de moins que la taille d'écran actuelle. Par exemple, si l'écran fait 24 lignes, -z-4 définit la fenêtre de défilement à 20 lignes. Si l'écran est redimensionné à 40 lignes, la fenêtre de défilement change automatiquement pour 36 lignes.
-"cc ou --quotes=cc
Change le caractère de guillemet de nom de fichier. Ceci peut être nécessaire si vous essayez de nommer un fichier qui contient à la fois des espaces et des caractères de guillemets. Suivi d'un seul caractère, cela change le caractère de guillemet en ce caractère. Les noms de fichiers contenant un espace devraient alors être entourés de ce caractère plutôt que de guillemets doubles. Suivi de deux caractères, change le guillemet ouvrant en premier caractère, et le guillemet fermant en second caractère. Les noms de fichiers contenant un espace devraient alors être précédés du caractère de guillemet ouvrant et suivis du caractère de guillemet fermant. Notez qu'même après que les caractères de guillemets ont été modifiés, cette option reste -« » (un trait suivi d'un guillemet double).
-~ ou --tilde
Normalement, les lignes après la fin du fichier sont affichées comme un simple tilde (~). Cette option fait en sorte que les lignes après la fin du fichier soient affichées comme des lignes vierges.
-# ou --shift
Spécifie le nombre par défaut de positions à décaler horizontalement dans les commandes DROITE-FLÈCHE et GAUCHE-FLÈCHE. Si le nombre spécifié est zéro, il définit le nombre par défaut de positions à la moitié de la largeur de l'écran. Alternativement, le nombre peut être spécifié comme une fraction de la largeur de l'écran, en commençant par un point décimal : .5 est la moitié de la largeur de l'écran, .3 en est trois dixièmes, et ainsi de suite. Si le nombre est spécifié comme une fraction, le nombre réel de positions de défilement est recalculé si la fenêtre du terminal est redimensionnée.
--cmd=commandes
La chaîne spécifiée est considérée comme une commande initiale pour less. Ceci est similaire à spécifier « +commandes », sauf que les commandes spécifiées par --cmd ne sont pas exécutées si less se termine immédiatement en raison de l'utilisation de l'option -E ou -F, tandis que les commandes spécifiées par l'option + sont exécutées même si less se termine immédiatement.
--exit-follow-on-close
Lors de l'utilisation de la commande « F » sur un pipe, less cessera automatiquement d'attendre davantage de données lorsque le côté d'entrée du pipe sera fermé.
--file-size
Si --file-size est spécifié, less déterminera la taille du fichier immédiatement après avoir ouvert le fichier. Ensuite, la commande « = » affichera le nombre de lignes dans le fichier. Normalement, cela n'est pas fait, car cela peut être lent si le fichier d'entrée n'est pas consultable (tel qu'un pipe) et qu'il est volumineux.
--follow-name
Normalement, si le fichier d'entrée est renommé pendant l'exécution d'une commande F, less continuera à afficher le contenu du fichier d'origine malgré le changement de nom. Si --follow-name est spécifié, lors d'une commande F, less tentera périodiquement de rouvrir le fichier par son nom. Si la réouverture réussit et que le fichier est différent du fichier d'origine (ce qui signifie qu'un nouveau fichier a été créé avec le même nom que le fichier d'origine (maintenant renommé)), less affichera le contenu de ce nouveau fichier.
--form-feed
Lors du défilement avant ou arrière dans le fichier, arrêtez-vous si une ligne commençant par un caractère de saut de page (^L) est atteinte. Ceci peut être utile lors de la visualisation d'un fichier qui utilise des sauts de page entre les pages.
--header=L,C,N
Définit le nombre de lignes et de colonnes d'en-tête affichées à l'écran. Le nombre de lignes d'en-tête est défini à L. Si L est 0, les lignes d'en-tête sont désactivées. Si L est vide ou manquant, le nombre de lignes d'en-tête reste inchangé. Le nombre de colonnes d'en-tête est défini à C. Si C est 0, les colonnes d'en-tête sont désactivées. Si C est vide ou manquant, le nombre de colonnes d'en-tête reste inchangé. La première ligne d'en-tête est définie au numéro de ligne N dans le fichier. Si N est vide ou manquant, il est considéré comme le numéro de la ligne actuellement affichée sur la première ligne de l'écran (si la commande --header a été émise depuis less), ou 1 (si l'option --header a été donnée sur la ligne de commande). La forme spéciale « --header=- » désactive les lignes d'en-tête et les colonnes d'en-tête, et équivaut à « --header=0,0 ».

Lorsque L est non nul, les L premières lignes en haut de l'écran sont remplacées par les L lignes du fichier commençant à la ligne N, quel que soit la partie du fichier visualisée. Lorsque les lignes d'en-tête sont affichées, tout contenu de fichier avant la ligne d'en-tête ne peut pas être visualisé. Lorsque C est non nul, les C premiers caractères affichés au début de chaque ligne sont remplacés par les C premiers caractères de la ligne, même si le reste de la ligne est défilé horizontalement.

Tant que l'option --header est active, les lignes plus longues que la largeur de l'écran sont tronquées, et l'option -S est ignorée.

--incsearch
Les commandes de recherche ultérieures seront « incrémentales »; c'est-à-dire que
b>less passera à la ligne suivante contenant le motif de recherche au fur et à mesure que chaque caractère du motif est tapé.
--intr=c
Utilise le caractère c au lieu de ^X pour interrompre une lecture lorsque le message « Attente de données » s'affiche. c doit être un caractère ASCII ; c'est-à-dire un caractère dont la valeur est comprise entre 1 et 127 inclus. Un accent circonflexe suivi d'un seul caractère peut être utilisé pour spécifier un caractère de contrôle.
--line-num-width=n
Définit la largeur minimale du champ de numéro de ligne lorsque l'option -N est activée à n caractères. La valeur par défaut est 7.
--match-shift=n
Lorsque l'option -S est activée, si une correspondance de recherche n'est pas visible parce qu'elle est décalée vers la gauche ou vers la droite de l'écran actuellement visible, le texte sera décalé horizontalement pour garantir que la correspondance de recherche soit visible. Cette option sélectionne la colonne dans laquelle le premier caractère de la correspondance de recherche sera placé après le décalage. Autrement dit, il y aura n caractères visibles à gauche de la correspondance de recherche.

Alternativement, le nombre peut être spécifié comme une fraction de la largeur de l'écran, en commençant par un point décimal : .5 représente la moitié de la largeur de l'écran, .3 représente les trois dixièmes de la largeur de l'écran, et ainsi de suite. Si le nombre est spécifié comme une fraction, le nombre réel de positions de défilement est recalculé si la fenêtre du terminal est redimensionnée.

--modelines=n
Avant d'afficher un fichier, less lira les n premières lignes pour essayer de trouver un modeline compatible vim. Si n est zéro, less n'essaiera pas de trouver de modelines. En utilisant un modeline, le fichier lui-même peut spécifier les tabulations qui doivent être utilisées lors de sa visualisation.

Un modeline contient, n'importe où sur la ligne, un nom de programme ("vi", "vim", "ex", ou "less"), suivi d'un deux-points, éventuellement suivi du mot "set", et enfin suivi de zéro ou plusieurs paramètres d'options. Si le mot "set" est utilisé, les paramètres d'options sont séparés par des espaces et se terminent au premier deux-points. Si le mot "set" n'est pas utilisé, les paramètres d'options peuvent être séparés par des espaces ou des deux-points. Le mot "set" est obligatoire si le nom du programme est "less", mais facultatif si l'un des trois autres noms est utilisé. Si un paramètre d'option est de la forme "tabstop=n" ou "ts=n", alors les tabulations sont automatiquement définies comme si --tabs=n avait été spécifié. Voir la description de --tabs pour les valeurs acceptables de n.

--mouse
Active la saisie de la souris : faire défiler la molette de la souris vers le bas permet d'avancer dans le fichier, faire défiler la molette de la souris vers le haut permet de reculer dans le fichier, un clic gauche définit la marque « # » sur la ligne où la souris est cliquée, et un clic droit (ou tout autre clic) ramène à la position de la marque « # ». Maintenir le bouton gauche enfoncé et faire glisser permet également de se déplacer dans le fichier. Si un clic gauche est effectué avec le curseur de la souris sur un hyperlien OSC 8, l'hyperlien est sélectionné comme s'il avait été activé par la commande ^O^N. Si un clic gauche est effectué avec le curseur de la souris sur un hyperlien OSC 8 déjà sélectionné, l'hyperlien est ouvert comme s'il avait été activé par la commande ^O^O. Le nombre de lignes à faire défiler lorsque la molette est déplacée peut être défini par l'option --wheel-lines. La saisie de la souris ne fonctionne que sur les terminaux qui prennent en charge le rapport de souris X11, et sur la version Windows de less.
--MOUSE
Similaire à --mouse, sauf que la direction du défilement lors du mouvement de la molette de la souris est inversée.
--no-edit-warn
N'affiche pas de message d'avertissement lors de l'utilisation de la commande v sur un fichier qui a été ouvert à l'aide d'un préprocesseur LESSOPEN (voir la section PRÉPROCESSEUR D'ENTRÉE ci-dessous).
--no-keypad
Désactive l'envoi des chaînes d'initialisation et de désinitialisation du pavé numérique au terminal. Ceci est parfois utile si les chaînes du pavé numérique font que le pavé numérique se comporte de manière indésirable.
--no-histdups
Cette option modifie le comportement de telle sorte que si une chaîne de recherche ou un nom de fichier est tapé, et que la même chaîne est déjà dans la liste d'historique, la copie existante est supprimée de la liste d'historique avant que la nouvelle ne soit ajoutée. Ainsi, une chaîne donnée n'apparaîtra qu'une seule fois dans la liste d'historique. Normalement, une chaîne peut apparaître plusieurs fois.
--no-number-headers
Les lignes d'en-tête (définies via l'option --header) ne se voient pas attribuer de numéros de ligne. Le numéro de ligne 1 est attribué à la première ligne après les lignes d'en-tête.
--no-paste
Si le terminal prend en charge le « collage entre crochets » compatible xterm, tout texte collé dans less est ignoré, à l'exception du fait qu'une seule ligne de texte peut être collée dans la ligne de commande en bas de l'écran (chaînes de recherche, noms de fichiers, etc.). C'est-à-dire que la première nouvelle ligne du texte collé dans la ligne de commande et tout le texte qui la suit est ignoré.
--no-search-header-lines
Les recherches n'incluent pas les lignes d'en-tête, mais incluent toujours les colonnes d'en-tête.
--no-search-header-columns
Les recherches n'incluent pas les colonnes d'en-tête, mais incluent toujours les lignes d'en-tête.
--no-search-headers
Les recherches n'incluent ni les lignes d'en-tête ni les colonnes d'en-tête.
--no-vbell
Désactive la sonnerie visuelle du terminal.
--proc-backspace
Si définie, les retours arrière sont traités comme si ni l'option -u ni l'option -U n'étaient définies. C'est-à-dire qu'un retour arrière adjacent à un trait de soulignement provoque l'affichage du texte en mode souligné, et un retour arrière entre caractères identiques provoque l'affichage du texte en mode gras. Cette option remplace les options -u et -U, de sorte que l'affichage des retours arrière peut être contrôlé indépendamment des tabulations et des retours chariot. Si elle n'est pas définie, l'affichage des retours arrière est contrôlé par les options -u et -U.
--PROC-BACKSPACE
Si définie, les retours arrière sont traités comme si l'option -U était définie ; c'est-à-dire que les retours arrière sont traités comme des caractères de contrôle.
--proc-return
Si définie, les retours chariot sont traités comme si ni l'option -u ni l'option -U n'étaient définies. C'est-à-dire qu'un retour chariot immédiatement avant un nouvel ligne est supprimé. Cette option remplace les options -u et -U, de sorte que l'affichage des retours chariot peut être contrôlé indépendamment de celui des retours arrière et des tabulations. Si elle n'est pas définie, l'affichage des retours chariot est contrôlé par les options -u et -U.
--PROC-RETURN
Si définie, les retours chariot sont traités comme si l'option -U était définie ; c'est-à-dire que les retours chariot sont traités comme des caractères de contrôle.
--proc-tab
Si définie, les tabulations sont traitées comme si l'option -U n'était pas définie. C'est-à-dire que les tabulations sont développées en espaces. Cette option remplace l'option -U, de sorte que l'affichage des tabulations peut être contrôlé indépendamment de celui des retours arrière et des retours chariot. Si elle n'est pas définie, l'affichage des tabulations est contrôlé par l'option -U. option.
--PROC-TAB
Si définie, les tabulations sont traitées comme si l'option -U était définie ; c'est-à-dire que les tabulations sont traitées comme des caractères de contrôle.
--redraw-on-quit
Lors de la sortie, après l'envoi de la chaîne de désinitialisation du terminal, redessine l'intégralité du dernier écran. Sur les terminaux dont la chaîne de désinitialisation du terminal fait passer le terminal d'un écran alternatif, cela permet au dernier écran du fichier actuel de rester visible après la sortie de less.
--rscroll=c
Cette option modifie le caractère utilisé pour marquer les lignes tronquées. Elle peut commencer par un indicateur d'attribut à deux caractères comme le fait LESSBINFMT. S'il n'y a pas d'indicateur d'attribut, la mise en surbrillance est utilisée. Si elle est définie à « - », les lignes tronquées ne sont pas marquées.
--save-marks
Enregistre les marques dans le fichier d'historique, de sorte que les marques sont conservées entre différentes invocations de less.
--search-options=...
Définit les modificateurs de recherche par défaut. La valeur est une chaîne d'un ou plusieurs des caractères E, F, K, N, R ou W. La définition de l'un d'entre eux a le même effet que la saisie de ce caractère de contrôle au début de chaque motif de recherche. Par exemple, définir --search-options=W équivaut à taper ^W au début de chaque motif. La valeur peut également contenir un chiffre entre 1 et 5, ce qui a le même effet que de taper ^S suivi de ce chiffre au début de chaque motif de recherche. La valeur « - » désactive tous les modificateurs de recherche par défaut.
--show-preproc-errors
Si un préprocesseur produit des données, puis se termine avec un code de sortie non nul, less affichera un avertissement.
--status-col-width=n
Définit la largeur de la colonne d'état lorsque l'option -J est activée. La valeur par défaut est 2 caractères.
--status-line
Si une ligne est marquée, la ligne entière (plutôt que seulement la colonne d'état) est mise en surbrillance. Les lignes mises en surbrillance en raison de l'option -w auront également la ligne entière mise en surbrillance. Si --use-color est défini, la ligne est colorée plutôt que mise en surbrillance.
--use-backslash
Cette option modifie l'interprétation des options qui la suivent. Après l'option --use-backslash, tout antislash dans une chaîne d'options est supprimé et le caractère suivant est pris littéralement. Cela permet d'inclure un signe dollar dans les chaînes d'options.
--use-color
Active la couleur du texte dans divers endroits. L'option -D peut être utilisée pour changer les couleurs. Le texte coloré ne fonctionne que si le terminal prend en charge les séquences d'échappement couleur ANSI (telles que définies dans https://www.ecma-international.org/publications-and-standards/standards/ecma-48).
--wheel-lines=n
Définit le nombre de lignes à faire défiler lorsque la molette de la souris est utilisée et que l'option --mouse ou --MOUSE est activée. La valeur par défaut est de 1 ligne.
--wordwrap
Lorsque l'option -S n'est pas utilisée, coupe chaque ligne à un espace ou à une tabulation si possible, de sorte qu'un mot ne soit pas coupé entre deux lignes. La valeur par défaut est de couper à n'importe quel caractère.
--
Un argument de ligne de commande "--" marque la fin des arguments d'option. Tous les arguments qui suivent sont interprétés comme des noms de fichiers. Ceci peut être utile lorsque l'on visualise un fichier dont le nom commence par un "-" ou un "+". Sinon, les arguments d'option et les arguments de nom de fichier peuvent être mélangés ; c'est-à-dire que les arguments d'option n'ont pas besoin d'apparaître avant les arguments de nom de fichier, sauf si la variable d'environnement POSIXLY_CORRECT est définie.
+
Si une option de ligne de commande commence par +, le reste de cette option est considéré comme une commande initiale pour less. Par exemple, +G dit à less de commencer à la fin du fichier plutôt qu'au début, et +/xyz lui dit de commencer à la première occurrence de "xyz" dans le fichier. À titre de cas spécial, +<nombre> agit comme +<nombre>g ; c'est-à-dire qu'il démarre l'affichage au numéro de ligne spécifié (cependant, voir la mise en garde sous la commande "g" ci-dessus). Si l'option commence par ++, la commande initiale s'applique à tous les fichiers visualisés, pas seulement au premier. La commande + décrite précédemment peut également être utilisée pour définir (ou modifier) une commande initiale pour tous les fichiers. Voir également l'option --cmd.

ÉDITION DE LIGNE

Lors de la saisie d'une ligne de commande en bas de l'écran (par exemple, un nom de fichier pour la commande :e, ou le motif pour une commande de recherche), certaines touches peuvent être utilisées pour manipuler la ligne de commande. La plupart des commandes ont une forme alternative entre crochets [ ] qui peut être utilisée si une touche n'existe pas sur un clavier particulier. (Notez que les formes commençant par ESC ne fonctionnent pas sur certains systèmes MS-DOS et Windows car ESC est le caractère d'effacement de ligne.) Chacune de ces touches spéciales peut être entrée littéralement en la faisant précéder du caractère "littéral", soit ^V, soit ^A. Une barre oblique inverse elle-même peut également être entrée littéralement en entrant deux barres obliques inverses.

LEFTARROW [ ESC-h ]
Déplace le curseur d'un espace vers la gauche.
RIGHTARROW [ ESC-l ]
Déplace le curseur d'un espace vers la droite.
^LEFTARROW [ ESC-b ou ESC-LEFTARROW ]
(C'est-à-dire, CONTROL et LEFTARROW simultanément.) Déplace le curseur d'un mot vers la gauche.
^RIGHTARROW [ ESC-w ou ESC-RIGHTARROW ]
(C'est-à-dire, CONTROL et RIGHTARROW simultanément.) Déplace le curseur d'un mot vers la droite.
HOME [ ESC-0 ]
Déplace le curseur au début de la ligne.
END [ ESC-$ ]
Déplace le curseur à la fin de la ligne.
BACKSPACE
Supprime le caractère à gauche du curseur, ou annule la commande si la ligne de commande est vide.
DELETE ou [ ESC-x ]
Supprime le caractère sous le curseur.
^BACKSPACE [ ESC-BACKSPACE ]
(C'est-à-dire, CONTROL et BACKSPACE simultanément.) Supprime le mot à gauche du curseur.
^DELETE [ ESC-X ou ESC-DELETE ]
(C'est-à-dire, CONTROL et DELETE simultanément.) Supprime le mot sous le curseur.
UPARROW [ ESC-k ]
Récupère la ligne de commande précédente. Si vous tapez d'abord du texte, puis appuyez sur UPARROW, cela récupérera la commande précédente qui commence par ce texte.
DOWNARROW [ ESC-j ]
Récupère la ligne de commande suivante. Si vous tapez d'abord du texte, puis appuyez sur DOWNARROW, cela récupérera la commande suivante qui commence par ce texte.
TAB
Complète le nom de fichier partiel à gauche du curseur. S'il correspond à plusieurs noms de fichiers, la première correspondance est entrée dans la ligne de commande. (Sur les systèmes MS-DOS et Windows, un "\" est ajouté.) La variable d'environnement LESSSEPARATOR peut être utilisée pour spécifier un caractère différent à ajouter au nom d'un répertoire.
BACKTAB [ ESC-TAB ]
Comme TAB, mais parcourt les noms de fichiers correspondants dans l'ordre inverse.
^L
Complète le nom de fichier partiel à gauche du curseur. S'il correspond à plusieurs noms de fichiers, toutes les correspondances sont entrées dans la ligne de commande (si elles rentrent).

^G
Supprime toute la ligne de commande et retourne à l'invite principale.

LIAISONS DE TOUCHES

Vous pouvez définir vos propres commandes less en créant un fichier source lesskey. Ce fichier spécifie un ensemble de touches de commande et une action associée à chaque touche. Vous pouvez également modifier les touches d'édition de ligne (voir ÉDITION DE LIGNE) et définir des variables d'environnement utilisées par less. Voir la page de manuel de lesskey(1) pour plus de détails sur le format du fichier.

Si la variable d'environnement LESSKEYIN est définie, less l'utilise comme nom du fichier source lesskey. Sinon, less recherche dans un emplacement standard le fichier source lesskey : Sur les systèmes Unix, less recherche un fichier lesskey nommé "$XDG_CONFIG_HOME/lesskey" ou "$HOME/.config/lesskey" ou "$HOME/.lesskey". Sur les systèmes MS-DOS et Windows, less recherche un fichier lesskey nommé "$HOME/_lesskey", et s'il n'est pas trouvé là, il recherche alors un fichier lesskey nommé "_lesskey" dans n'importe quel répertoire spécifié dans la variable d'environnement PATH. Sur les systèmes OS/2, less recherche un fichier lesskey nommé "$HOME/lesskey.ini", et s'il n'est pas trouvé, il recherche alors un fichier lesskey nommé "lesskey.ini" dans n'importe quel répertoire spécifié dans la variable d'environnement INIT, et s'il n'est pas trouvé là, il recherche alors un fichier lesskey nommé "lesskey.ini" dans n'importe quel répertoire spécifié dans la variable d'environnement PATH.

Un fichier source lesskey au niveau du système peut également être configuré pour fournir des liaisons de touches. Si une touche est définie à la fois dans un fichier lesskey local et dans le fichier système, les liaisons de touches dans le fichier local ont la priorité sur celles du fichier système. Si la variable d'environnement LESSKEYIN_SYSTEM est définie, less l'utilise comme nom du fichier lesskey système. Sinon, less recherche dans un emplacement standard le fichier lesskey système : Sur les systèmes Unix, le fichier lesskey système est /usr/local/etc/syslesskey. (Cependant, si less a été compilé avec un répertoire sysconf différent de /usr/local/etc, ce répertoire est celui où le fichier sysless est trouvé.) Sur les systèmes MS-DOS et Windows, le fichier lesskey système est c:\_syslesskey. Sur les systèmes OS/2, le fichier lesskey système est c:\syslesskey.ini.

Les anciennes versions de less (avant la v582) utilisaient des fichiers lesskey au format binaire, produits par le programme lesskey. Il n'est plus nécessaire d'utiliser le programme lesskey.

PRÉPROCESSEUR D'ENTRÉE

Vous pouvez définir un "préprocesseur d'entrée" pour less. Avant que less n'ouvre un fichier, il donne d'abord au préprocesseur d'entrée une chance de modifier la façon dont le contenu du fichier est affiché. Un préprocesseur d'entrée est simplement un programme exécutable (ou un script shell), qui écrit le contenu du fichier dans un autre fichier, appelé fichier de remplacement. Le contenu du fichier de remplacement est ensuite affiché à la place du contenu du fichier d'origine. Cependant, il apparaîtra à l'utilisateur comme si le fichier d'origine était ouvert ; c'est-à-dire que less affichera le nom du fichier d'origine comme nom du fichier courant.

Un préprocesseur d'entrée reçoit un argument de ligne de commande, le nom du fichier d'origine, tel qu'entré par l'utilisateur. Il doit créer le fichier de remplacement et, une fois terminé, imprimer le nom du fichier de remplacement sur sa sortie standard. Si le préprocesseur d'entrée ne sort pas un nom de fichier de remplacement, less utilise le fichier d'origine, comme d'habitude. Le préprocesseur d'entrée n'est pas appelé lorsque l'on visualise l'entrée standard. Pour configurer un préprocesseur d'entrée, définissez la variable d'environnement LESSOPEN à une ligne de commande qui appellera votre préprocesseur d'entrée. Cette ligne de commande doit inclure une occurrence de la chaîne "%s", qui sera remplacée par le nom du fichier lorsque la commande du préprocesseur d'entrée sera appelée.

Lorsque less ferme un fichier ouvert de cette manière, il appelle un autre programme, appelé postprocesseur d'entrée, qui peut effectuer toute action de nettoyage souhaitée (comme supprimer le fichier de remplacement créé par LESSOPEN). Ce programme reçoit deux arguments de ligne de commande, le nom du fichier d'origine tel qu'entré par l'utilisateur, et le nom du fichier de remplacement. Pour configurer un postprocesseur d'entrée, définissez la variable d'environnement LESSCLOSE à une ligne de commande qui appellera votre postprocesseur d'entrée. Elle peut inclure deux occurrences de la chaîne "%s" ; la première est remplacée par le nom d'origine du fichier et la seconde par le nom du fichier de remplacement, qui a été généré par LESSOPEN.

Par exemple, sur de nombreux systèmes Unix, ces deux scripts vous permettront de conserver des fichiers au format compressé, tout en laissant less les visualiser directement :

lessopen.sh:
#! /bin/sh
case "$1" in
*.Z) TEMPFILE=$(mktemp)
uncompress -c $1 >$TEMPFILE 2>/dev/null
if [ -s $TEMPFILE ]; then
echo $TEMPFILE
else
rm -f $TEMPFILE
fi
;;
esac

lessclose.sh:
#! /bin/sh
rm $2

Pour utiliser ces scripts, placez-les tous deux là où ils peuvent être exécutés et définissez LESSOPEN="lessopen.sh %s", et LESSCLOSE="lessclose.sh %s %s". Des scripts LESSOPEN et LESSCLOSE plus complexes peuvent être écrits pour accepter d'autres types de fichiers compressés, etc.

INPUT PREPROCESSORS

An input preprocessor is a command that less can run to preprocess the input file before viewing it. This is typically used to decompress files that less cannot handle directly, such as compressed files.

The command to run as the input preprocessor is specified by the LESSOPEN environment variable. If this variable is set, less will run the specified command, passing the name of the input file as an argument to the command. The standard output of the command is then treated as the contents of the file to be displayed. The standard error of the command is ignored.

The command string in LESSOPEN must contain one occurrence of %s, which is replaced with the filename of the input file. For example, LESSOPEN="/usr/local/bin/myfilter %s".

If the standard output of the preprocessor is empty, less assumes there is no replacement file and displays the original file, as normal. This is the default behavior if the preprocessor produces no output.

To set up an input preprocessor to pipe the file data directly to less, rather than putting the data into a replacement file. This avoids the need to decompress the entire file before starting to view it. An input preprocessor that works this way is called an input pipe. An input pipe, instead of writing the name of a replacement file on its standard output, writes the entire contents of the replacement file on its standard output. If the input pipe does not write any characters on its standard output, then there is no replacement file and less uses the original file, as normal. To use an input pipe, make the first character in the LESSOPEN environment variable a vertical bar (|) to signify that the input preprocessor is an input pipe. As with non-pipe input preprocessors, the command string must contain one occurrence of %s, which is replaced with the filename of the input file.

For example, on many Unix systems, this script will work like the previous example scripts:

lesspipe.sh:
#! /bin/sh
case "$1" in
*.Z) uncompress -c $1 2>/dev/null
;;
*) exit 1
;;
esac
exit $?

To use this script, put it where it can be executed and set LESSOPEN="|lesspipe.sh %s".

Note that a preprocessor cannot output an empty file, since that is interpreted as meaning there is no replacement, and the original file is used. To avoid this, if LESSOPEN starts with two vertical bars, the exit status of the script determines the behavior when the output is empty. If the output is empty and the exit status is zero, the empty output is considered to be replacement text. If the output is empty and the exit status is nonzero, the original file is used. For compatibility with previous versions of less, if LESSOPEN starts with only one vertical bar, the exit status of the preprocessor is ignored.

When an input pipe is used, a LESSCLOSE postprocessor can be used, but it is usually not necessary since there is no replacement file to clean up. In this case, the replacement file name passed to the LESSCLOSE postprocessor is "-".

For compatibility with previous versions of less, the input preprocessor or pipe is not used if less is viewing standard input. However, if the first character of LESSOPEN is a dash (-), the input preprocessor is used on standard input as well as other files. In this case, the dash is not considered to be part of the preprocessor command. If standard input is being viewed, the input preprocessor is passed a file name consisting of a single dash. Similarly, if the first two characters of LESSOPEN are vertical bar and dash (|-) or two vertical bars and a dash (||-), the input pipe is used on standard input as well as other files. Again, in this case the dash is not considered to be part of the input pipe command.

SETS DE CARACTÈRES NATIONAUX

Il existe cinq types de caractères dans le fichier d'entrée :

caractères normaux
peuvent être affichés directement à l'écran.
caractères de contrôle
ne devraient pas être affichés directement, mais sont attendus dans les fichiers texte ordinaires (comme le retour arrière et la tabulation).
caractères binaires
ne devraient pas être affichés directement et ne sont pas attendus dans les fichiers texte.
caractères de composition
ne sont pas affichés séparément, mais modifient l'affichage du caractère précédent. (Uniquement lorsque LESSCHARSET est "utf8".)
caractères supprimés
sont simplement supprimés de l'entrée et non affichés. (Uniquement lorsque LESSCHARSET est "utf8".)

Un "jeu de caractères" est simplement une description de quels caractères sont considérés comme normaux, de contrôle ou binaires. La variable d'environnement LESSCHARSET peut être utilisée pour sélectionner un jeu de caractères. Les valeurs possibles pour LESSCHARSET sont :

ascii
BS, TAB, NL, CR et saut de page sont des caractères de contrôle, tous les caractères dont les valeurs sont comprises entre 32 et 126 sont normaux, et tous les autres sont binaires.
iso8859
Sélectionne un jeu de caractères ISO 8859. C'est la même chose que ASCII, sauf que les caractères entre 160 et 255 sont traités comme des caractères normaux.
latin1
Identique à iso8859.
latin9
Identique à iso8859.
dos
Sélectionne un jeu de caractères approprié pour MS-DOS.
ebcdic
Sélectionne un jeu de caractères EBCDIC.
IBM-1047
Sélectionne un jeu de caractères EBCDIC utilisé par OS/390 Unix Services. C'est l'analogue EBCDIC de latin1. Vous obtenez des résultats similaires en définissant soit LESSCHARSET=IBM-1047, soit LC_CTYPE=en_US dans votre environnement.
koi8-r
Sélectionne un jeu de caractères russe.
next
Sélectionne un jeu de caractères approprié pour les ordinateurs NeXT.
utf-8
Sélectionne l'encodage UTF-8 du jeu de caractères ISO 10646. UTF-8 est spécial car il prend en charge les caractères multi-octets dans le fichier d'entrée. C'est le seul jeu de caractères qui prend en charge les caractères multi-octets.
windows
Sélectionne un jeu de caractères approprié pour Microsoft Windows (cp 1252).

Dans de rares cas, il peut être souhaitable d'adapter less pour utiliser un jeu de caractères autre que ceux définissables par LESSCHARSET. Dans ce cas, la variable d'environnement LESSCHARDEF peut être utilisée pour définir un jeu de caractères. Elle doit être définie à une chaîne où chaque caractère de la chaîne représente un caractère du jeu de caractères. Le caractère "." est utilisé pour un caractère normal, "c" pour un contrôle, et "b" pour un binaire. Un nombre décimal peut être utilisé pour la répétition. Par exemple, "bccc4b." signifierait que le caractère 0 est binaire, 1, 2 et 3 sont de contrôle, 4, 5, 6 et 7 sont binaires, et 8 est normal. Tous les caractères après le dernier sont considérés comme identiques au dernier, donc les caractères 9 à 255 seraient normaux. (Ceci est un exemple et ne représente pas nécessairement un jeu de caractères réel.)

IBM-1047 4cbcbc3b9cbccbccbb4c6bcc5b3cbbc4bc4bccbc

Si ni LESSCHARSET ni LESSCHARDEF ne sont définis, mais que l'une des chaînes "UTF-8", "UTF8", "utf-8" ou "utf8" est trouvée dans les variables d'environnement LC_ALL, LC_CTYPE ou LANG, alors le jeu de caractères par défaut est utf-8.

Si cette chaîne n'est pas trouvée, mais que votre système prend en charge l'interface setlocale, less utilisera setlocale pour déterminer le jeu de caractères. setlocale est contrôlé par la définition des variables d'environnement LANG ou LC_CTYPE.

Enfin, si l'interface setlocale n'est pas non plus disponible, le jeu de caractères par défaut est utf-8.

Les caractères de contrôle et binaires sont affichés en surbrillance (vidéo inversée). Chaque caractère de ce type est affiché en notation avec accent circonflexe si possible (par exemple, ^A pour contrôle-A). La notation avec accent circonflexe n'est utilisée que si l'inversion du bit 0100 donne un caractère imprimable normal. Sinon, le caractère est affiché sous forme de nombre hexadécimal entre crochets angulaires. Ce format peut être modifié en définissant la variable d'environnement LESSBINFMT. LESSBINFMT peut commencer par un "*" et un caractère pour sélectionner l'attribut d'affichage : "*k" clignotant, "*d" gras, "*u" souligné, "*s" en surbrillance, et "*n" normal. Si LESSBINFMT ne commence pas par un "*", l'attribut normal est supposé. Le reste de LESSBINFMT est une chaîne qui peut inclure une seule séquence d'échappement de style printf (un % suivi de x, X, o, d, etc.). Par exemple, si LESSBINFMT est "*u[%x]", les caractères binaires sont affichés en hexadécimal souligné entouré de crochets. La valeur par défaut si aucun LESSBINFMT n'est spécifié est "*s<%02X>". Attention : le résultat de l'expansion du caractère via LESSBINFMT doit être inférieur à 31 caractères.

Lorsque le jeu de caractères est utf-8, la variable d'environnement LESSUTFBINFMT fonctionne de manière similaire à LESSBINFMT mais s'applique aux points de code Unicode qui ont été décodés avec succès mais qui ne sont pas adaptés à l'affichage (par exemple, les points de code non assignés). Sa valeur par défaut est "<U+%04lX>". Notez que LESSUTFBINFMT et LESSBINFMT partagent leur réglage d'attribut d'affichage ("*x"), donc la spécification de l'un affectera les deux ; LESSUTFBINFMT est lu après LESSBINFMT, donc son réglage, le cas échéant, aura la priorité. Les octets problématiques dans un fichier UTF-8 (octets d'une séquence tronquée, octets d'une séquence complète mais non de la plus courte forme, octets invalides et octets de fin errants) sont affichés individuellement à l'aide de LESSBINFMT afin de faciliter le diagnostic de la manière dont le fichier UTF-8 est mal formé.

Lorsque le jeu de caractères est utf-8, dans de rares cas, il peut être souhaitable de remplacer la définition Unicode du type de certains caractères. Par exemple, les caractères d'une zone d'utilisation privée sont normalement traités comme des caractères binaires, mais si vous utilisez une police personnalisée avec des caractères imprimables dans cette plage, il peut être souhaitable d'indiquer à less de traiter ces caractères comme imprimables. Cela peut être fait en définissant la variable d'environnement LESSUTFCHARDEF à une liste de définitions de type de caractère séparées par des virgules. Chaque définition de type de caractère consiste soit en un point de code hexadécimal unique, soit en une paire de points de code séparés par un trait d'union, suivie d'un deux-points et d'un caractère de type. Chaque point de code hexadécimal peut éventuellement être précédé de "U" ou "U+". Si une paire de points de code est donnée, le type est défini pour tous les caractères inclus entre les deux valeurs. S'il y a plusieurs valeurs de points de code séparées par des virgules, elles doivent être dans un ordre numérique ascendant.

LESSUTFCHARDEF

Ce paramètre d'environnement vous permet de spécifier comment LESS doit traiter les caractères Unicode. Il est utilisé pour définir les propriétés des caractères dans une plage Unicode spécifiée. Le format est une liste de plages Unicode séparées par des virgules, chacune suivie d'un deux-points et d'un caractère de type.

Les plages Unicode peuvent être spécifiées comme une seule valeur hexadécimale ou comme une plage de deux valeurs hexadécimales séparées par un trait d'union. Les valeurs hexadécimales ne sont pas sensibles à la casse.

Le caractère de type peut être l'un des suivants :

p
Un caractère normal imprimable.
w
Un caractère imprimable large (2 espaces).
b
Un caractère binaire (non imprimable).
c
Un caractère de composition (largeur zéro).
d
Un caractère supprimé (supprimé de l'entrée et non affiché).

Par exemple, définir LESSUTFCHARDEF sur

E000-F8FF:p,F0000-FFFFD:p,100000-10FFFD:p

ferait que tous les caractères de la zone d'utilisation privée soient traités comme imprimables.

Par défaut, les modificateurs d'emoji, les composants et les sélecteurs de variation sont supprimés car de nombreux terminaux ne les affichent pas correctement. Si vous utilisez un terminal qui affiche correctement certains ou tous ces éléments, vous pouvez faire en sorte qu'ils soient affichés en définissant LESSUTFCHARDEF pour les traiter comme des caractères de composition. Par exemple, ceci les définit tous comme des caractères de composition :

FE00-FE0F:c,1F3FB-1F3FF:c,1F9B0-1F9B3:c,E0100-E01EF:c

INVITATIONS

L'option -P vous permet de personnaliser l'invite à votre préférence. La chaîne donnée à l'option -P remplace la chaîne d'invite spécifiée. Certains caractères de la chaîne sont interprétés spécialement. Le mécanisme d'invite est plutôt compliqué pour offrir de la flexibilité, mais l'utilisateur ordinaire n'a pas besoin de comprendre les détails de la construction de chaînes d'invite personnalisées.

Un signe de pourcentage suivi d'un seul caractère est développé en fonction du caractère suivant. (Les références à la taille du fichier d'entrée ci-dessous font référence à la taille prétraitée, si un prétraitement de fichier est utilisé.)

%bX
Remplacé par le décalage en octets dans le fichier d'entrée actuel. Le b est suivi d'un seul caractère (représenté par X ci-dessus) qui spécifie la ligne dont le décalage en octets doit être utilisé. Si le caractère est un "t", le décalage en octets de la ligne supérieure de l'affichage est utilisé, un "m" signifie utiliser la ligne du milieu, un "b" signifie utiliser la ligne inférieure, un "B" signifie utiliser la ligne juste après la ligne inférieure, et un "j" signifie utiliser la ligne "cible", comme spécifié par l'option -j.
%B
Remplacé par la taille du fichier d'entrée actuel.
%c
Remplacé par le numéro de colonne du texte apparaissant dans la première colonne de l'écran.
%dX
Remplacé par le numéro de page d'une ligne dans le fichier d'entrée. La ligne à utiliser est déterminée par le X, comme avec l'option %b.
%D
Remplacé par le nombre de pages dans le fichier d'entrée, ou de manière équivalente, le numéro de page de la dernière ligne dans le fichier d'entrée.
%E
Remplacé par le nom de l'éditeur (de la variable d'environnement VISUAL, ou de la variable d'environnement EDITOR si VISUAL n'est pas définie). Voir la discussion sur la fonctionnalité LESSEDIT ci-dessous.
%f
Remplacé par le nom du fichier d'entrée actuel.
%F
Remplacé par le dernier composant du nom du fichier d'entrée actuel.
%g
Remplacé par le nom du fichier d'entrée actuel échappé par le shell. Ceci est utile lorsque la chaîne développée sera utilisée dans une commande de shell, comme dans LESSEDIT.
%i
Remplacé par l'index du fichier actuel dans la liste des fichiers d'entrée.
%lX
Remplacé par le numéro de ligne d'une ligne dans le fichier d'entrée. La ligne à utiliser est déterminée par le X, comme avec l'option %b.
%L
Remplacé par le numéro de ligne de la dernière ligne dans le fichier d'entrée.
%m
Remplacé par le nombre total de fichiers d'entrée.
%o
Remplacé par l'URI du lien hypertexte OSC 8 actuellement sélectionné, ou un point d'interrogation si aucun lien hypertexte n'est sélectionné. Ceci est utilisé par les gestionnaires OSC 8 comme expliqué dans la description de la commande ^O^O.

Remplacé par le pourcentage dans le fichier d'entrée actuel, basé sur les décalages en octets. La ligne utilisée est déterminée par le X comme avec l'option %b.
%PX
Remplacé par le pourcentage dans le fichier d'entrée actuel, basé sur les numéros de ligne. La ligne utilisée est déterminée par le X comme avec l'option %b.
%s
Identique à %B.
%t
Supprime les espaces de fin. Généralement utilisé à la fin de la chaîne, mais peut apparaître n'importe où.
%T
Normalement développé en mot "file". Cependant, si vous visualisez des fichiers via une liste de balises en utilisant l'option -t, il est développé en mot "tag".
%x
Remplacé par le nom du fichier d'entrée suivant dans la liste.

Si un élément est inconnu (par exemple, la taille du fichier si l'entrée est un tube), un point d'interrogation est imprimé à la place.

Le format de la chaîne d'invite peut être modifié en fonction de certaines conditions. Un point d'interrogation suivi d'un seul caractère agit comme un "SI" : selon le caractère suivant, une condition est évaluée. Si la condition est vraie, tous les caractères suivant le point d'interrogation et le caractère de condition, jusqu'à un point, sont inclus dans l'invite. Si la condition est fausse, ces caractères ne sont pas inclus. Un deux-points apparaissant entre le point d'interrogation et le point peut être utilisé pour établir un "SINON" : tous les caractères entre le deux-points et le point seront inclus dans la chaîne si et seulement si la condition SI est fausse. Les caractères de condition (qui suivent un point d'interrogation) peuvent être :

?a
Vrai si des caractères ont été inclus dans l'invite jusqu'à présent.
?bX
Vrai si le décalage en octets de la ligne spécifiée est connu.
?B
Vrai si la taille du fichier d'entrée actuel est connue.
?c
Vrai si le texte est décalé horizontalement (%c n'est pas zéro).
?dX
Vrai si le numéro de page de la ligne spécifiée est connu.
?e
Vrai si à la fin du fichier.
?f
Vrai s'il y a un nom de fichier d'entrée (c'est-à-dire si l'entrée n'est pas un tube).
?lX
Vrai si le numéro de ligne de la ligne spécifiée est connu.
?L
Vrai si le numéro de ligne de la dernière ligne du fichier est connu.
?m
Vrai s'il y a plus d'un fichier d'entrée.
?n
Vrai s'il s'agit de la première invite dans un nouveau fichier d'entrée.
?pX
Vrai si le pourcentage dans le fichier d'entrée actuel, basé sur les décalages en octets, de la ligne spécifiée est connu.
?PX
Vrai si le pourcentage dans le fichier d'entrée actuel, basé sur les numéros de ligne, de la ligne spécifiée est connu.
?s
Identique à "?B".
?x
Vrai s'il y a un fichier d'entrée suivant (c'est-à-dire si le fichier d'entrée actuel n'est pas le dernier).

Tous les caractères autres que les caractères spéciaux (point d'interrogation, deux-points, point, pourcentage et barre oblique inverse) deviennent littéralement partie de l'invite. N'importe lequel des caractères spéciaux peut être inclus dans l'invite littéralement en le faisant précéder d'une barre oblique inverse.

Quelques exemples :

?f%f:Standard input.

Cette invite imprime le nom du fichier, s'il est connu ; sinon la chaîne "Standard input".

?f%f .?ltLine %lt:?pt%pt\%:?btByte %bt:-...

Cette invite imprimerait le nom du fichier, s'il est connu. Le nom du fichier est suivi du numéro de ligne, s'il est connu, sinon du pourcentage s'il est connu, sinon du décalage en octets s'il est connu. Sinon, un tiret est imprimé. Remarquez comment chaque point d'interrogation a un point correspondant, et comment le % après %pt est inclus littéralement en l'échappant avec une barre oblique inverse.

?n?f%f .?m(%T %i of %m) ..?e(END) ?x- Next\: %x..%t

Ceci imprime le nom du fichier s'il s'agit de la première invite dans un fichier, suivi du message "file N of N" s'il y a plus d'un fichier d'entrée. Ensuite, si nous sommes à la fin du fichier, la chaîne "(END)" est imprimée suivie du nom du fichier suivant, s'il y en a un. Enfin, les espaces de fin sont tronqués. C'est l'invite par défaut. À titre de référence, voici les valeurs par défaut pour les deux autres invites (-m et -M respectivement). Chacune est divisée en deux lignes ici pour des raisons de lisibilité uniquement.

?n?f%f .?m(%T %i of %m) ..?e(END) ?x- Next\: %x.:
	?pB%pB\%:byte %bB?s/%s...%t

?f%f .?n?m(%T %i of %m) ..?ltlines %lt-%lb?L/%L. :
	byte %bB?s/%s. .?e(END) ?x- Next\: %x.:?pB%pB\%..%t
Et voici le message par défaut produit par la commande = : 
?f%f .?m(%T %i of %m) .?ltlines %lt-%lb?L/%L. .
	byte %bB?s/%s. ?e(END) :?pB%pB\%..%t

Les fonctionnalités d'expansion d'invite sont également utilisées à une autre fin : si une variable d'environnement LESSEDIT est définie, elle est utilisée comme commande à exécuter lorsque la commande v est invoquée. La chaîne LESSEDIT est développée de la même manière que les chaînes d'invite. La valeur par défaut pour LESSEDIT est :

%E ?lm+%lm. %g
Notez que cela se développe en nom de l'éditeur, suivi de + et du numéro de ligne, suivi du nom de fichier échappé par le shell. Si votre éditeur n'accepte pas la syntaxe "+linenumber", ou a d'autres différences de syntaxe d'invocation, la variable LESSEDIT peut être modifiée pour changer cette valeur par défaut.

L'option -e fonctionne différemment. Si l'option -e n'est pas définie, less se comporte comme si l'option -e était définie. Si l'option -e est définie, less se comporte comme si l'option -E était définie.

L'option -m fonctionne différemment. Si l'option -m n'est pas définie, l'invite moyenne est utilisée, et elle est préfixée par la chaîne "--More--". Si l'option -m est définie, l'invite courte est utilisée.

NAME

opposite of more - view a file a screenful at a time

SYNOPSIS

DESCRIPTION

less is a program similar to more (section 1), but has enhancements which allow random access to the file, more editing-like features, and better performance on large files or files that are not randomly accessible. less uses memory efficiently; it does not need to read the entire input file into memory, so it can handle much larger files than ed(1) or vi(1).

less normally operates on files named on the command line. If no filenames are given, less reads from standard input. less will normally exit when the end of the file is reached. Use the -E or --quit-if-one-screen option to make less exit automatically if the entire file can be displayed on one screen.

When viewing a file, less accepts various commands, most of which are similar to the commands used by the vi(1) editor. If the input is coming from standard input, less may not be able to determine the size of the file beforehand. In this case, some commands that rely on knowing the file size (like moving to the end of the file) may not work correctly.

This manual page describes the options and commands for less. For more detailed information, see the main less documentation.

Move the cursor forward one character.
^B
Move the cursor backward one character.
^P
Recall the previous command entered.
^N
Recall the next command entered.
^V
Insert the literal character into the line.
ESC
Cancel the current input line.
RET
Accept the current input line.

KEY BINDINGS

Key bindings can be customized using the lesskey utility. See the lesskey(1) manual page for details.

INPUT PREPROCESSOR

less can be configured to use an input preprocessor. This allows you to view files that are compressed or otherwise transformed. See the LESSOPEN environment variable for details.

NATIONAL CHARACTER SETS

less supports international character sets. The behavior may depend on your terminal's settings and the locale environment variables.

PROMPTS

When less prompts for input (e.g., when executing a shell command), the prompt string can be customized using the LESSPROMPT environment variable. If LESSPROMPT is not set, the default prompt is used.

SECURITY

less is generally safe to use. However, if you are viewing files from untrusted sources, be aware that certain commands (like ! and v) can execute arbitrary code. It is recommended to set the SECUREPATH environment variable to restrict access to potentially dangerous commands.

COMPATIBILITY WITH MORE

less can be run in a mode compatible with more. In this mode, some of the enhanced features of less are disabled to provide behavior closer to more. The MORE environment variable can be used to set options that are passed to less when running in this mode.

ENVIRONMENT VARIABLES

LESS_OSC8_ANY
Sets an OSC 8 handler for opening OSC 8 links for which there is no specific LESS_OSC8_xxx handler set for the "xxx" scheme.
LESS_SHELL_LINES
When the -F option is set, less exits automatically if the number of screen lines used to display the file is less than or equal to the screen height minus the value of the LESS_SHELL_LINES variable. Thus, if you use a shell prompt which occupies more than one screen line, this variable can be set to the number of lines used by your prompt, to ensure that the entire file can be seen when -F is used. If not set, LESS_SHELL_LINES is assumed to be 1.
LESS_SIGUSR1
If set to a string of one or more less command characters, those commands will be executed when less receives a SIGUSR1 signal.
LESS_TERMCAP_xx
Where "xx" is any two characters, overrides the definition of the termcap "xx" capability for the terminal.
LESS_TERMCAP_BRACKETED_PASTE_START
Overrides the standard ANSI escape sequence to enable bracketed paste. This is used when the --no-paste option is in effect.
LESS_TERMCAP_BRACKETED_PASTE_END
Overrides the standard ANSI escape sequence to disable bracketed paste.
LESS_TERMCAP_MOUSE_START
Overrides the standard ANSI escape sequence to enable mouse reporting. This is used when the --mouse option is in effect.
LESS_TERMCAP_MOUSE_END
Overrides the standard ANSI escape sequence to disable mouse reporting.
LESS_TERMCAP_SUSPEND
Defines an escape sequence to temporarily suspend screen updates. This is sent to the terminal before clearing the screen. This can be used to avoid screen tearing when the screen is redrawn on certain terminals.
LESS_TERMCAP_RESUME
Defines an escape sequence to resume screen updates. This is sent to the terminal after displaying the prompt.
LESS_UNSUPPORT
A space-separated list of command line options. These options will be ignored (with no error message) if they appear on the command line or in the LESS environment variable. Options listed in LESS_UNSUPPORT can still be changed by the - and -- commands. Each option in LESS_UNSUPPORT is a dash followed by a single character option letter, or two dashes followed by a long option name.
LINES
Sets the number of lines on the screen. Takes precedence over the number of lines specified by the TERM variable. (But if you have a windowing system which supports TIOCGWINSZ or WIOCGETD, the window system's idea of the screen size takes precedence over the LINES and COLUMNS environment variables.)
MORE
Options which are passed to less automatically when running in more-compatible mode.
PATH
User's search path (used to find a lesskey file on MS-DOS, Windows, and OS/2 systems).
POSIXLY_CORRECT
If set to any value, all option arguments on the command line are expected to appear before any filename arguments. This must be set as an actual environment variable, not in a lesskey file.
SHELL
The shell used to execute the ! command, as well as to expand filenames.
TERM
The type of terminal on which less is being run.
VISUAL
The name of the editor (used for the v command).
XDG_CONFIG_HOME
Possible location of the lesskey file; see the KEY BINDINGS section.
XDG_DATA_HOME
Possible location of the history file; see the description of the LESSHISTFILE environment variable.
XDG_STATE_HOME
Possible location of the history file; see the description of the LESSHISTFILE environment variable.
