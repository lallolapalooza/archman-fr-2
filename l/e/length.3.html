Description détaillée

Une interface d'entrée/sortie abstraite.

Attention

C'est du matériel avancé et hardcore. Vous n'en avez pas besoin à moins de savoir vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un accès au système de fichiers physique et aux archives dans ce système de fichiers. Cependant, parfois, vous avez besoin de plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue en RAM, ou vous devez relier une autre API d'entrée/sortie de fichiers à PhysicsFS, ou vous devez traduire les bits (peut-être avez-vous un fichier .zip standard crypté, et vous devez le décrypter à la volée pour l'archiveur zip inconscient).

Un PHYSFS_Io est l'interface que les archiveurs utilisent pour obtenir des données d'archive. Historiquement, cela correspondait aux opérations d'entrée/sortie de fichiers sur le système de fichiers physique, mais depuis PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations d'E/S à l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour les E/S. Il y a quelques exigences notables :

  • Elles ne font que des E/S bloquantes (du moins, pour l'instant).
  • Elles doivent pouvoir être dupliquées. Si vous avez une poignée de fichier de `fopen()`, vous devez être capable d'en créer un clone unique (donc nous avons deux poignées vers le même fichier qui peuvent toutes deux rechercher/lire/etc sans se gêner mutuellement).
  • Elles doivent connaître la taille de l'ensemble de leurs données.
  • Elles doivent être capables de rechercher et de rembobiner à la demande.

... en bref, vous n'allez probablement pas écrire une implémentation HTTP.

Sécurité des threads : les implémentations PHYSFS_Io ne sont pas garanties d'être sûres pour les threads en elles-mêmes. Sous le capot, là où PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement à partir de threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io à partir de deux threads en même temps.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance d'E/S. Libérer les ressources associées, y compris (opaque) si applicable.

Cette fonction doit toujours réussir : à ce titre, elle ne retourne rien. Le système peut appeler votre méthode flush() avant cela. Vous pouvez signaler un échec là-bas si nécessaire. Cette méthode peut toujours être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et autres conditions d'échec et nettoyer.

Une fois que cette méthode est appelée pour une instance donnée, le système supposera qu'il est dangereux de toucher à nouveau cette instance et écartera toute référence à celle-ci.

Paramètres

s L'instance d'E/S à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance d'E/S. Cela doit aboutir à une copie complète de ce PHYSFS_Io, qui peut vivre complètement indépendamment. La copie doit être capable d'effectuer toutes ses opérations sans altérer l'original, y compris le fait que chaque objet puisse être détruit séparément (donc, par exemple : ils ne peuvent pas partager une poignée de fichier ; chacun a besoin de la sienne).

Si vous ne pouvez pas dupliquer une poignée, il est légal de retourner NULL, mais vous avez presque certainement besoin de cette fonctionnalité si vous voulez utiliser ce PHYSFS_Io pour soutenir une archive.

Paramètres

io L'instance d'E/S à dupliquer.

Retours

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources sur le support, ou ailleurs. C'est l'occasion de signaler un échec pour des écritures qui avaient prétendu réussir plus tôt, mais qui avaient encore une chance d'échouer réellement. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut être appelée à d'autres moments également.

Paramètres

io L'instance d'E/S à vider.

Retours

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance d'E/S. Retourner le nombre d'octets disponibles dans le fichier, ou -1 si vous ne pouvez pas le déterminer. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'E/S à interroger.

Retours

Taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qui peut être utilisé pour stocker tout ce qu'elle souhaite. Ce pointeur est par instance du flux, donc il changera probablement lors de l'appel à duplicate(). Il peut être désalloué pendant la méthode destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets depuis l'interface, à la position actuelle d'E/S, et les stocker dans (buffer). La position actuelle d'E/S doit avancer du nombre d'octets lus avec succès.

Vous n'avez pas à implémenter cela ; réglez-le sur NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture. S'il est réglé sur NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance d'E/S à lire.
buf Le tampon pour stocker les données. Il doit être au moins de taille (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire depuis l'interface.

Retours

nombre d'octets lus depuis le fichier, 0 à la fin du fichier (EOF), -1 en cas d'échec complet.

Signaler la position actuelle d'E/S. Retourner le nombre d'octets depuis le début du fichier jusqu'à la position actuelle. Retourner -1 si la position ne peut pas être déterminée.

PHYSFS_uint32 PHYSFS_Io::version

Informations sur la compatibilité binaire. Ceci est utilisé pour s'assurer que le code qui alloue et utilise cette structure est compatible. La bibliothèque initialisera ceci à une valeur qui devrait être compatible avec votre code. Si vous utilisez une version différente (par exemple, si vous allouez la structure dans votre propre code et que vous la passez à la bibliothèque), vous devrez définir ceci avant de pouvoir l'utiliser. À l'heure actuelle, il n'y a qu'une seule version, donc c'est toujours 1.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrire (len) octets depuis (buffer) dans l'interface, à la position actuelle d'E/S. La position actuelle d'E/S doit avancer du nombre d'octets qui ont été effectivement écrits.

Vous n'avez pas à implémenter cela ; définissez-le sur NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. S'il est défini sur NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

buffer Le tampon contenant les données à écrire. Il ne peut pas être NULL.
len Le nombre d'octets à écrire.

Retours

Nombre d'octets écrits, ou -1 en cas d'échec.

Informations de compatibilité binaire. Ceci doit être mis à zéro pour le moment. Nous continuerons probablement à prendre en charge les versions plus anciennes à mesure que nous proposerons de nouvelles fonctionnalités, cependant.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrit (len) octets depuis (buffer) vers l'interface à la position i/o actuelle. La position i/o actuelle doit avancer du nombre d'octets effectivement écrits.

Vous n'avez pas à implémenter cela ; mettez-le à NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. S'il est mis à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Vous êtes autorisé à mettre en tampon ; une écriture peut réussir ici et échouer plus tard lors de la vidange. Notez que PHYSFS_setBuffer() peut fonctionner à un niveau supérieur à votre i/o, vous ne devriez donc généralement pas implémenter vos propres routines de mise en tampon.

Paramètres

io L'instance i/o vers laquelle écrire.
buffer Le tampon à partir duquel lire les données. Il doit avoir au moins (len) octets de long et ne peut pas être NULL.
len Le nombre d'octets à lire depuis (buffer).

Retourne

nombre d'octets écrits dans le fichier, -1 en cas d'échec complet.
