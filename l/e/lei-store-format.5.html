NOM

lei/store - description du format lei/store

DESCRIPTION

"lei/store" est un stockage hybride basé sur public-inbox-extindex-format(5) ("extindex") combiné avec public-inbox-v2-format(5) ("v2") pour le stockage des blobs. Alors que v2 est idéal pour archiver une seule liste de diffusion publique ; il n'a jamais été conçu pour les courriels personnels ni pour le stockage de plusieurs blobs du "même" message.

Comme avec extindex, il peut indexer des en-têtes "List-Id" disparates appartenant au "même" message avec différents OID de blob git. Contrairement à v2 et extindex, les en-têtes "Message-ID" NE SONT PAS requis ; permettant le stockage et l'indexation des brouillons de messages non envoyés.

STRUCTURE DU RÉPERTOIRE

Le stockage des blobs existe sous forme d'époques de style v2. Ces époques se trouvent sous le répertoire "local/" (au lieu de "git/") pour éviter qu'elles ne soient accidentellement traitées comme une boîte de réception v2.

APERÇU DE LINDEXATION ET DÉFINITIONS

$EPOCH - Entier commençant à 0 basé sur le temps
$SCHEMA_VERSION - Version du schéma de la base de données (pour Xapian)
$SHARD - Entier commençant à 0 basé sur le parallélisme
~/.local/share/lei/store
- local/$EPOCH.git                # dépôts git nus normaux
- mail_sync.sqlite3               # état de synchronisation IMAP, Maildir, NNTP

De plus, les éléments suivants partagent les mêmes rôles que dans extindex :

- ei.lock                         # fichier de verrouillage pour protéger l'état global
- ALL.git                         # vide, alternance pour local/*.git
- ei$SCHEMA_VERSION/$SHARD        # base de données Xapian par fragment
- ei$SCHEMA_VERSION/over.sqlite3  # base de données de survol pour WWW, IMAP
- ei$SCHEMA_VERSION/misc          # base de données Xapian diverse

DÉDUPLICATION XREF3

La déduplication de l'index suit extindex, voir "DÉDUPLICATION XREF3" dans public-inbox-extindex-format(5) pour plus d'informations.

DÉDUPLICATION DES BLOBS

Le contenu des dépôts "local/*.git" est dédupliqué par les identifiants d'objet blob git (actuellement SHA-1). Cela permet de stocker plusieurs copies de messages postés sur plusieurs listes et de messages personnellement mis en copie avec différents en-têtes "Received:", "X-Spam-Status:" et similaires, afin de permettre le dépannage.

MÉTAMÉES VOLATILES

Les mots-clés et les informations d'étiquette (tels que décrits dans la RFC 8621 pour JMAP) sont stockés dans les fragments Xapian existants ("ei$SCHEMA_VERSION/$SHARD"). Il est possible de rechercher des messages correspondant à des étiquettes et des mots-clés en utilisant "L:" et "kw:", respectivement. Comme pour toutes les données stockées dans les index Xapian, les métadonnées volatiles sont associées au document Xapian, elles sont donc partagées entre différents blobs du "même" message.

mail_sync.sqlite3

Cette base de données SQLite est maintenue pour la correspondance bidirectionnelle des blobs git avec les UIDs IMAP, les noms de fichiers Maildir et les numéros d'articles NNTP.

Elle est également utilisée pour récupérer des messages des Maildirs indexés par lei-index(1).

IPC

lei-daemon(8) communique avec le processus "lei/store" en utilisant des sockets unix(7) "SOCK_SEQPACKET".

MISES EN GARDE

La réindexation et la synchronisation ne sont pas encore prises en charge.
