NOM

lei q - rechercher des messages correspondant à des termes

SYNTAXE

lei q [OPTIONS] TERME [TERME...]

lei q [OPTIONS] (--stdin|-)

DESCRIPTION

Recherche des messages dans le magasin lei/ et les externals.

OPTIONS

--stdin
Lire les termes de recherche depuis stdin.
--no-save
Ne pas sauvegarder la recherche pour lei-up(1).
--output=MFOLDER
-o MFOLDER
--mfolder=MFOLDER
Attention : cela écrase et remplace la destination de sortie à moins que "--augment" ne soit spécifié.

Destination des résultats (par exemple, "/tmp/results-Maildir", "imaps://utilisateur@mail.example.com/INBOX.test", ou "mboxcl2:/tmp/results-mboxcl2"). Le préfixe peut être un protocole supporté : "imap://" ou "imaps://". Les URL nécessitant une authentification utilisent git-credential(1) pour fournir le nom d'utilisateur et le mot de passe.

Un préfixe peut spécifier le format de la sortie : "maildir", "mboxrd", "mboxcl2", "mboxcl", "mboxo". Pour une description des formats de mail, voir lei-mail-formats(5).

"v2:/chemin/vers/boite-aux-lettres" peut être utilisé pour créer une nouvelle boite aux lettres au format public-inbox-v2-format(5). La nouvelle boite aux lettres ne sera pas configurée dans le fichier public-inbox-config(5).

"maildir" est le défaut pour un répertoire existant ou un chemin non existant.

Défaut : "-" (stdout)

--format=FORMAT
-f FORMAT
Format des résultats vers stdout. Cette option existe pour spécifier commodément le format pour la destination stdout par défaut. "reply", "text", "json", "jsonl", ou "concatjson" sont supportés, ainsi que les différentes variantes mbox décrites dans "--output".

Lorsqu'un format n'est pas spécifié, il est choisi en fonction de la destination ou du préfixe "--output". "json" est utilisé pour la destination par défaut (stdout).

L'utilisation d'un préfixe "format:" avec la destination "--output" est préférée lorsque l'on n'écrit pas sur stdout.

--no-color
Désactiver la couleur (pour "-f reply" et "-f text").
--pretty
Afficher en mode joli "json" ou "concatjson". Si stdout est ouvert sur un tty et utilisé comme destination "--output", "--pretty" est activé par défaut.
--mua=COMMAND
Une commande à exécuter sur "--output" Maildir ou mbox (par exemple, "mutt -f %f"). Pour un sous-ensemble de MUA connus pour accepter une boite aux lettres via "-f", COMMAND peut être abrégé par le nom du programme : "mutt", "mailx", "mail", ou "neomutt".
--alert=COMMAND[,COMMAND...]
Exécuter "COMMAND" après écriture en sortie. ":WINCH" indique d'envoyer "SIGWINCH" au processus "--mua". ":bell" indique d'imprimer un code de sonnerie. Toute autre valeur est interprétée comme une commande à exécuter telle quelle.

Cette option peut être donnée plusieurs fois.

Défaut : ":WINCH,:bell" quand "--mua" est spécifié et "--output" ne pointe pas vers stdout, rien sinon.

--augment
-a
Augmenter la destination de sortie au lieu de l'écraser.
--no-import-before
Ne pas importer les messages avant d'écrire dans une destination de sortie existante. Assurez-vous de ne pas avoir besoin des données existantes dans votre sortie avant d'utiliser cette option, elle efface définitivement les données à moins que "--augment" ne soit utilisé.
--threads
-t
Retourner tous les messages du même fil de discussion que la ou les correspondances réelles.

L'utilisation de cette option deux fois ("-tt") définit le drapeau "flagged" (également appelé "important") sur les messages qui étaient des correspondances réelles. Ceci est utile pour distinguer les messages qui étaient des correspondances directes des messages qui faisaient simplement partie du même fil de discussion.

TODO : Attention : ce drapeau peut devenir persistant et être sauvegardé dans lei/store à moins qu'un MUA ne le désactive ! (Comportement indécis)

Attention : "-tt" ne fonctionne qu'avec les messages indexés localement pour le moment, et pas avec les points d'extrémité distants (HTTP/HTTPS).

--thread-id=MSGID
-T MSGID
Rechercher uniquement les messages dans le même fil de discussion que le Message-ID donné.

Pour les externals HTTP(S), cela ne fonctionne qu'avec les instances exécutant public-inbox 2.0+ (NON PUBLIÉ).

--jobs=QUERY_WORKERS[,WRITE_WORKERS]
--jobs=,WRITE_WORKERS
-j QUERY_WORKERS[,WRITE_WORKERS]
-j ,WRITE_WORKERS
Définir le nombre de processus de requête et d'écriture pour le parallélisme.

"QUERY_WORKERS" est par défaut le nombre de CPU disponibles, mais 4 par hôte distant (HTTP/HTTPS).

"WRITE_WORKERS" est par défaut 75% du nombre de CPU disponibles pour les destinations Maildir et mbox*, mais 4 par hôte IMAP/IMAPS.

Omettre "QUERY_WORKERS" mais laisser la virgule (",") permet de ne définir que "WRITE_WORKERS"

--dedupe=STRATEGY
-d STRATEGY
Stratégie pour la déduplication des messages : "content", "oid", "mid", ou "none".

Défaut : "content"

--[no-]remote
Indique s'il faut inclure les résultats nécessitant un accès réseau. Lorsque des externals locaux sont configurés, "--remote" doit être explicitement passé pour activer le rapport des résultats des externals distants.
--no-local
Limiter les opérations à celles qui nécessitent

NOM

lei q - rechercher des messages dans le répertoire de messages de public-inbox

SYNOPSIS

lei q [-|-- OPTIONS]... [TERMES_DE_RECHERCHE]...

DESCRIPTION

L'outil lei q recherche des messages dans le répertoire de messages locaux de lei. Il supporte les mêmes préfixes de recherche que les instances public-inbox HTTP(S).

Les messages sont récupérés en utilisant les valeurs par défaut de public-inbox, c'est-à-dire en utilisant git ls-remote pour trouver les références externes, puis en effectuant une recherche dans le stockage local.

OPTIONS

--no-network
Désactiver la recherche sur le réseau. Les correspondances ne seront recherchées que dans le répertoire local.
--external=LOCATION
Utiliser l'emplacement externe donné pour la recherche. Cette option peut être donnée plusieurs fois. La recherche sera effectuée dans la combinaison de tous les emplacements externes spécifiés.
--no-external
Ne pas inclure les résultats des externes.
--include=LOCATION
-I LOCATION
Inclure l'externe spécifié dans la recherche. Cette option peut être donnée plusieurs fois.
--exclude=LOCATION
Exclure l'externe spécifié de la recherche. Cette option peut être donnée plusieurs fois.
--only=LOCATION
-O LOCATION
Utiliser uniquement l'externe spécifié pour la recherche. Cette option peut être donnée plusieurs fois, auquel cas la recherche utilisera uniquement l'ensemble spécifié.
--globoff
-g
Ne pas faire correspondre les emplacements en utilisant les jokers "*?" et les plages "[]". Cette option s'applique à "--include", "--exclude" et "--only".
--no-import-remote
Désactiver le comportement par défaut de mémoïsation des messages distants dans le stockage local.
--lock=METHOD
mbox(5) méthodes de verrouillage à utiliser : "dotlock", "fcntl", "flock" ou "none".

Par défaut : fcntl,dotlock

--limit=NUMBER
-NUMBER
-n NUMBER
Limiter de manière floue le nombre de correspondances par externe local et par lei/stockage. Les messages ajoutés par le commutateur "--threads" ne comptent pas dans cette limite, et il n'y a pas de limite pour les externes distants.

Par défaut : 10000

--offset=NUMBER
Décaler le début des résultats de la recherche.

Par défaut : 0

--reverse
-r
Inverser les résultats. Notez que cela s'applique avant "--limit".
--sort=KEY
-s KEY
Trier les résultats par CLÉ. Les clés valides sont "received", "relevance" et "docid".

Par défaut : "received"

--verbose
-v
Fournir plus d'informations sur stderr.
--quiet
-q
Supprimer les messages d'information.
--torsocks=auto|no|yes
--no-torsocks
Faut-il encapsuler les commandes git(1) et curl(1) avec torsocks(1).

Par défaut : "auto"

--proxy=PROTOCOL://HOST[:PORT]

TERMES DE RECHERCHE

"lei q" prend en charge les mêmes préfixes de recherche utilisés par les instances public-inbox HTTP(S) :

s:        correspondance dans le sujet  par ex. s:"un rapide renard brun"
d:        correspondance dans une plage de date et heure, les formats
          "approxidate" de git sont supportés
          Les plages ouvertes telles que `d:derniere.semaine.." et
          `d:..il.y.a.2.jours' sont supportées
b:        correspondance dans le corps du message, y compris les pièces jointes texte
nq:       correspondance dans le texte non cité du corps du message
q:        correspondance dans le texte cité du corps du message
n:        correspondance dans le nom de fichier de la/des pièce(s) jointe(s)
t:        correspondance dans l'en-tête To
c:        correspondance dans l'en-tête Cc
f:        correspondance dans l'en-tête From
a:        correspondance dans les en-têtes To, Cc et From
tc:       correspondance dans les en-têtes To et Cc
l:        correspondance dans le contenu de l'en-tête List-Id
bs:       correspondance dans le sujet et le corps
dfn:      correspondance du nom de fichier diff
dfa:      correspondance des lignes supprimées (-) du diff
dfb:      correspondance des lignes ajoutées (+) du diff
dfhh:     correspondance du contexte du bloc d'en-tête du diff (généralement un nom de fonction)
dfctx:    correspondance des lignes de contexte du diff
dfpre:    correspondance de l'ID de blob git de l'image précédente
dfpost:   correspondance de l'ID de blob git de l'image suivante
dfblob:   correspondance de l'ID de blob git de l'image précédente ou suivante
patchid:  correspondance de la sortie de `git patch-id --stable'
rt:       correspondance de l'heure de réception, comme `d:' si l'horloge de l'expéditeur était correcte

Préfixes de recherche supplémentaires qui n'affectent que le lei/stockage local :

L:       correspondance du label donné
kw:      correspondance des mots-clés donnés

Voir lei-tag(1) pour plus d'informations sur les labels et les mots-clés.

La plupart des préfixes sont probabilistes, ce qui signifie qu'ils prennent en charge la racinisation et les jokers ("*"). Les plages (comme "d:") et les préfixes booléens ne prennent pas en charge la racinisation ou les jokers. La documentation du parseur de requêtes Xapian explique entièrement la syntaxe des requêtes : https://xapian.org/docs/queryparser.html

ASTUCES

"-f reply" est destiné à aider à transformer une lettre d'accompagnement en réponse (car utiliser "git format-patch --in-reply-to=..." est fastidieux). Les résultats (y compris les lignes "From ") doivent être édités et coupés dans votre $EDITOR préféré avant d'être envoyés.
