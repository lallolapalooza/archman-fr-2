LESSPIPE.SH(1) Commandes utilisateur LESSPIPE.SH(1)

NOM

lesspipe.sh - un filtre pour less

SYNTAXE

lesspipe.sh [FICHIER[s]]...

DESCRIPTION

L'objectif de lesspipe.sh est d'améliorer la sortie de less. Le choix des règles à appliquer pour modifier la sortie est basé sur le contenu du fichier. L'extension du fichier n'est respectée qu'en dernier recours. Habituellement, lesspipe.sh est appelé comme filtre d'entrée pour less.

Avec l'aide de ce filtre, less affichera le contenu décompressé des fichiers compressés (gzip, bzip2, compress, zstd, lz4, lzip, xz, lzma ou brotli). Pour les fichiers contenant des archives et des répertoires, une table des matières sera affichée (formats tar, ar, zip, 7-zip, rar, jar, cpio, rpm, deb, ms-cabinet, iso, appimage et snap). De nombreux autres fichiers seront reformatés pour l'affichage. Cela inclut les formats pdf, dvi, markdown, suites Office (MS et Openoffice), les formats NetCDF, matlab, device tree blob, html, xml et media (image, audio et vidéo). Cela nécessite l'installation de programmes d'assistance.

Le filtre peut également être appliqué de manière récursive pour extraire et afficher des fichiers dans des archives à la volée. Cela fonctionne jusqu'à une profondeur de 6, où l'application d'un algorithme de décompression compte comme un niveau distinct.

Si l'utilitaire file signale du texte avec un encodage différent de celui utilisé dans le terminal, le texte sera transformé à l'aide d'iconv dans l'encodage par défaut. Cela suppose que la commande file détecte correctement l'encodage du fichier, ce qui peut être erroné dans certaines situations. Un deux-points ajouté au nom du fichier supprime la conversion.

Lors de l'utilisation des programmes git, vim ou mutt, ils peuvent être activés pour lire des fichiers non texte en utilisant lesspipe.sh. Ceci est décrit dans le Wiki à l'adresse https://github.com/wofr06/lesspipe/wiki.

ACTIVATION DU FILTRE

Le filtre est appelé depuis less à condition que la variable d'environnement LESSOPEN soit correctement définie. Pour les shells similaires à ksh (bash, zsh), la commande

LESSOPEN="|lesspipe.sh %s"; export LESSOPEN
active le filtre pour less. Utilisez le chemin complet si lesspipe.sh n'est pas dans le chemin de recherche. La commande pour définir LESSOPEN peut également être affichée en appelant lesspipe.sh sans arguments. Cela peut même être utilisé pour définir LESSOPEN directement :
eval `lesspipe.sh` (bash) ou
lesspipe.sh|source /dev/stdin (zsh)
Les commandes ci-dessus ne fonctionnent que de la manière décrite si le nom du fichier est lesspipe.sh. S'il est installé sous un autre nom, l'appeler sans argument fonctionnera comme un filtre avec LESSQUIET défini et attendant une entrée depuis STDIN.

Après avoir défini la variable d'environnement comme décrit ci-dessus, less affichera des informations textuelles pour une large gamme de formats de fichiers.

Le filtre n'est normalement pas appelé si une entrée est envoyée à less via un pipe, comme dans

cat somefile | less
Comme décrit dans la page de manuel de less, le filtrage dans un pipe peut cependant être forcé en commençant LESSOPEN par les caractères |-.

LESSOPEN commençant par les deux caractères || pour gérer les fichiers vides et les erreurs de commande n'est que partiellement implémenté. Habituellement, en cas d'échec des commandes dans lesspipe.sh, les messages d'erreur sont affichés.

Pour supprimer les messages informels dans la première ligne de la sortie du filtre, la variable d'environnement LESSQUIET peut être définie à une valeur non vide.

Pour désengager temporairement le filtre, un deux-points peut être ajouté au nom du fichier. Si le nom du fichier contient un deux-points, un signe égal doit être utilisé à la place.

FICHIERS HTML, XML et POD Perl

Les fichiers au format html, xml et pod Perl sont toujours rendus. Parfois, cependant, le contenu original du fichier devrait être consulté. Comme mentionné précédemment, cela peut être réalisé en ajoutant un deux-points au nom du fichier. Si le type de fichier correct (html, xml, pod) suit, la sortie peut être colorisée (voir également la section ci-dessous).

Exemple : less index.html:html

Si le binaire xmq est installé, alors xml est rendu différemment, de sorte que la structure xml soit mieux reconnue. Un affichage similaire pour le contenu html à l'aide de xmq est obtenu en ajoutant un deux-points au nom du fichier. Pour obtenir le contenu du fichier html original, deux deux-points sont requis dans ce cas.

COLORISATION DE LA SORTIE

Le filtre est capable de faire de la mise en évidence syntaxique pour une grande variété de types de fichiers. Si installé, nvimpager est utilisé pour coloriser la sortie. Sinon, bat/batcat, pygmentize, source-highlight, vimcolor et code2color sont essayés tour à tour. Pour bat/batcat, le thème est défini sur ansi et le style sur plain, ce qui se rapproche de la sortie non filtrée de less. Ces paramètres peuvent être modifiés dans ~/.config/bat/config ou via les variables d'environnement BAT_STYLE et BAT_THEME.

Parmi les coloriseurs, un préféré peut être forcé pour la colorisation en définissant la variable d'environnement LESSCOLORIZER au nom du coloriseur. Pour pygmentize et bat/batcat, des paramètres d'options restreints sont autorisés comme suit :

LESSCOLORIZER='pygmentize -O style=foo' (-P autorisé également)
LESSCOLORIZER='bat --style=foo --theme=bar' (par défaut, thème ansi, style plain)
La mise en évidence syntaxique est activée si la variable d'environnement LESS existe et contient l'option -R, ou si less est appelé avec cette option. Ceci garantit que les séquences d'échappement sont converties en couleurs et ne corrompent pas l'affichage. L'utilisation de l'option -r n'est pas recommandée, car la disposition de l'écran peut être incorrecte si des lignes longues sont présentes dans la sortie.

La mise en évidence syntaxique peut être désactivée en ajoutant un deux-points après le nom du fichier, si la sortie était colorisée. Si la mauvaise langue a été choisie pour la mise en évidence syntaxique, une autre peut être forcée en ajoutant un deux-points et une extension au nom du fichier.

Dans un pipe, cette méthode ne peut pas être utilisée. Pour contourner ce problème, un dernier argument peut être ajouté, qui sera inspecté par lesspipe.sh. Un seul deux-points (désengager le filtre) ou :extension (forcer la langue) est possible, comme par exemple avec

commande qui génère du code c | less - :c
Lorsque les conditions de mise en évidence syntaxique sont remplies, les listages de répertoires et les listages de contenu de fichiers tar sont également colorisés.

Comme less est utilisé comme navigateur par défaut dans d'autres programmes (par exemple man, git et perldoc)), lesspipe.sh peut être engagé et modifier la sortie de ces programmes.

SURVEILLANCE DES FICHIERS EN CROISSANCE

Dès que lesspipe.sh appelle un programme pour convertir l'entrée, la capacité de surveiller les fichiers en croissance (en utilisant la commande F dans less) est perdue. Ceci est généralement souhaité pour les fichiers journaux comme syslog. Pour désengager temporairement lesspipe.sh, un deux-points comme dernier argument pour less doit être ajouté, comme par exemple dans

less /var/log/syslog :
ou less peut être appelé avec l'argument +F, ce qui est équivalent à F dans le pager :
less +F /var/log/syslog
L'ajout d'un deux-points au nom du fichier ne fonctionne pas, car le filtre devrait alors être engagé pour au moins supprimer ce deux-points et utiliser cat pour le fichier original. En revanche, les fichiers journaux non croissants peuvent être colorisés à l'aide de ccze. Sa reconnaissance en tant que fichier journal est difficile s'il ne se termine pas par .log, mais peut être forcée en ajoutant :.log au nom du fichier, comme par exemple dans
less /var/log/syslog:.log

USAGE AVANCÉ

Cette version de lesspipe.sh vous permet de visualiser des fichiers individuels contenus dans une archive de fichiers, qui peut elle-même contenir une autre archive.

La notation pour visualiser des fichiers dans des archives multifichiers est

less archive

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

e_fichier:fichier_contenu ou même
less super_archive:fichier_archive:fichier_contenu
Pour afficher le dernier fichier de la chaîne au format brut, un deux-points (:) doit être ajouté au nom du fichier. S'il contient un deux-points, alors le caractère séparateur alternatif, le signe égal (=), doit être utilisé.

Encore une fois, cette méthode d'extraction et d'affichage de fichiers ne fonctionne pas si less est appelé dans un pipe de sortie et que LESSOPEN commence par les caractères |-. Comme déjà pour la coloration syntaxique, la solution consiste à utiliser un deuxième argument commençant par un deux-points. La commande ci-dessus serait alors écrite comme suit :

cat super_archive | less - :archive:fichier_contenu

MECANISME DE COMPLETION POUR LE CONTENU DES ARCHIVES

Avec les fichiers lesscomplete (pour zsh et bash), _less (pour zsh) et less_completion (pour bash) fournis, une complétion par tabulation pour les fichiers dans les archives peut être réalisée. Entrer un deux-points (:) ou un signe égal (=) après le nom d'un fichier archive, puis appuyer sur la touche tabulation déclenche le mécanisme de complétion. Cela fonctionne également dans les archives chaînées. Les fichiers lesscomplete et less_completion doivent se trouver dans l'un des répertoires listés dans $PATH et la fonction _less pour zsh dans un répertoire listé par $fpath. Le script less_completion doit être sourcé dans un script d'initialisation bash, par exemple dans ~/.bashrc. De nouveaux répertoires tels que ~/scripts et ~/.fpath peuvent être ajoutés en utilisant les commandes

PATH=~/scripts:$PATH et fpath=(~/.fpath $fpath)

FILTRAGE DEFINI PAR L'UTILISATEUR

Le filtrage lesspipe.sh peut être remplacé ou amélioré par un programme défini par l'utilisateur. Un tel programme doit être appelé soit .lessfilter (et être placé dans le répertoire personnel de l'utilisateur), soit lessfilter (et être accessible depuis un répertoire mentionné dans $PATH). Il doit être exécutable et se terminer par un code de sortie 0 si le filtrage a été effectué dans ce script. Sinon, un code de sortie non nul signifie que le filtrage est laissé à lesspipe.sh.

Ce mécanisme peut être utilisé pour ajouter le filtrage de nouveaux formats ou, par exemple, pour interdire le filtrage de certains types de fichiers.
