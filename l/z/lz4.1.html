LZ4(1) Commandes utilisateur LZ4(1)

NOM

lz4 - lz4, unlz4, lz4cat - Compresser ou décompresser des fichiers .lz4

SYNTAXE

lz4 [OPTIONS] [-|FICHIER-D'ENTRÉE] FICHIER-DE-SORTIE

unlz4 équivaut à lz4 -d

lz4cat équivaut à lz4 -dcfm

Lorsque vous écrivez des scripts qui ont besoin de décompresser des fichiers, il est recommandé d'utiliser toujours le nom lz4 avec les arguments appropriés (lz4 -d ou lz4 -dc) au lieu des noms unlz4 et lz4cat.

DESCRIPTION

lz4 est une interface en ligne de commande basée sur liblz4, une implémentation extrêmement rapide d'un algorithme de compression sans perte. Elle offre une vitesse de compression par défaut typiquement supérieure à 500 Mo/s par cœur. La vitesse peut être échangée contre un taux de compression plus élevé, en augmentant le paramètre de niveau de compression. Bien que la décompression soit mono-thread, elle atteint plusieurs Go/s, généralement assez rapidement pour être limitée par les E/S. Le format de fichier natif de lz4 est le format .lz4.

Différence entre lz4 et gzip

lz4 supporte une syntaxe de ligne de commande similaire mais pas identique à gzip(1). Les différences sont :

  • lz4 compresse un seul fichier par défaut (voir -m pour plusieurs fichiers)
  • lz4 fichier1 fichier2 signifie : compresse fichier1 dans fichier2
  • lz4 fichier.lz4 par défaut décompressera (utilisez -z pour forcer la compression)
  • lz4 conserve les fichiers originaux (voir --rm pour effacer le fichier source à la fin)
  • lz4 affiche des statistiques de notification en temps réel pendant la compression ou la décompression d'un seul fichier (utilisez -q pour les supprimer)
  • Lorsqu'aucune destination n'est spécifiée, le résultat est envoyé sur une sortie implicite, qui dépend du statut de stdout. Lorsque stdout n'est pas la console, il devient la sortie implicite. Sinon, si stdout est la console, la sortie implicite est nomfichier.lz4.
  • Il est considéré comme une mauvaise pratique de s'appuyer sur la sortie implicite dans les scripts, car l'environnement du script peut changer. Utilisez toujours une sortie explicite dans les scripts. -c garantit que la sortie sera stdout. Inversement, fournir un nom de destination, ou utiliser -m garantit que la sortie sera soit le nom spécifié, soit nomfichier.lz4 respectivement.

Les comportements par défaut peuvent être modifiés par des commandes optionnelles, détaillées ci-dessous.

  • lz4 -m permet de fournir plusieurs noms de fichiers d'entrée, qui seront compressés dans des fichiers utilisant le suffixe .lz4. Les notifications de progression sont désactivées par défaut (utilisez -v pour les activer). Ce mode a un comportement qui imite plus étroitement la ligne de commande de gzip, la principale différence restante étant que les fichiers sources sont conservés par défaut.
  • De même, lz4 -m -d peut décompresser plusieurs fichiers *.lz4.
  • Il est possible de choisir d'effacer les fichiers sources lors de la compression ou de la décompression réussie, en utilisant la commande --rm.
  • Par conséquent, lz4 -m --rm présente un comportement plus proche de celui de gzip.

Concaténation de fichiers .lz4

Il est possible de concaténer des fichiers .lz4 tels quels. lz4 décompressera ces fichiers comme s'il s'agissait d'un seul fichier .lz4. Par exemple :

lz4 fichier1  > foo.lz4
lz4 fichier2 >> foo.lz4

Ensuite, lz4cat foo.lz4 équivaut à cat fichier1 fichier2.

OPTIONS

Concaténation de commandes courtes

Dans certains cas, certaines options peuvent être exprimées en utilisant une commande courte -x ou une commande longue --mot-long. Les commandes courtes peuvent être concaténées ensemble. Par exemple, -d -c équivaut à -dc. Les commandes longues ne peuvent pas être concaténées. Elles doivent être clairement séparées par un espace.

Commandes multiples

Lorsque plusieurs commandes contradictoires sont émises sur la même ligne de commande, seule la dernière sera appliquée.

Mode de fonctionnement

-z --compress
Compresser. C'est le mode de fonctionnement par défaut lorsqu'aucune option de mode de fonctionnement n'est spécifiée, aucun autre mode de fonctionnement n'est implicite par le nom de la commande (par exemple, unlz4 implique --decompress), ni par le nom du fichier d'entrée (par exemple, une extension de fichier .lz4 implique --decompress par défaut). -z peut également être utilisé pour forcer la compression d'un fichier déjà compressé .lz4.
-d --decompress --uncompress
Décompresser. --decompress est également le comportement par défaut lorsque le nom du fichier d'entrée a une extension .lz4.
-t --test
Tester l'intégrité des fichiers .lz4 compressés. Les données décompressées sont ignorées. Aucun fichier n'est créé ni supprimé.
-b#
Mode benchmark, utilisant le niveau de compression #.
--list
Lister les informations sur les fichiers .lz4. Pour des informations détaillées sur les fichiers avec plusieurs trames, utilisez -v. --list déclenche automatiquement le modificateur -m.

Modificateurs de fonctionnement

-#
Niveau de compression, où # est une valeur de 1 à 12. Des valeurs plus élevées échangent la vitesse de compression contre le taux de compression. Les valeurs supérieures à 12 sont considérées comme identiques à 12. Les valeurs recommandées sont 1 pour une compression rapide (par défaut), et 9 pour une compression élevée. Le compromis vitesse/compression variera en fonction des données à compresser. La vitesse de décompression reste rapide à tous les niveaux.
--fast[=#]
Passer aux niveaux de compression ultra-rapides. Plus la valeur est élevée, plus la vitesse de compression est rapide, au détriment d'une certaine compression. Si =# n'est pas présent, il est par défaut à 1. Ce réglage remplace le niveau de compression s'il a été défini précédemment. De même, si un niveau de compression est défini après --fast, il le remplace.
--best
Définir le niveau de compression le plus élevé. Identique à -12.
-T#, --threads=#
Utiliser # threads pour la compression. Lorsque 0, ou aucun fourni : déterminé automatiquement à partir du nombre de cœurs détectés.
--favor-decSpeed
Générer des données compressées optimisées pour la vitesse de décompression. Les données compressées seront plus volumineuses en conséquence (typiquement d'environ 0,5 %), tandis que la vitesse de décompression sera améliorée de 5 à 20 %, en fonction des cas d'utilisation. Cette option ne fonctionne qu'en combinaison avec des niveaux de compression très élevés (>=10).
-D nomDictionnaire
Compresser, décompresser ou effectuer un benchmark en utilisant le dictionnaire nomDictionnaire. La compression et la décompression doivent utiliser le même dictionnaire pour être compatibles. L'utilisation d'un dictionnaire différent lors de la décompression entraînera soit l'échec en raison d'une erreur de décompression, soit une erreur de somme de contrôle.
-f --[no-]force
Cette option a plusieurs effets :
Si le fichier cible existe déjà, il sera écrasé sans demander confirmation.
Lorsqu'elle est utilisée avec --decompress et que lz4 ne parvient pas à reconnaître le type de fichier source, le fichier source est copié tel quel sur la sortie standard. Cela permet à lz4cat --force d'être utilisé comme cat (1) pour les fichiers qui n'ont pas été compressés avec lz4.
-c --stdout --to-stdout
Forcer l'écriture sur la sortie standard, e

lz4(1) - Page de manuel

NOM

lz4

compression rapide par algorithme de compression sans perte LZ4

SYNTAXE

lz4 [OPTIONS] [FILE...]

lz4c [OPTIONS] [FILE...]

lz4d [OPTIONS] [FILE...]

DESCRIPTION

lz4 est un utilitaire en ligne de commande qui permet de compresser et décompresser des fichiers rapidement.

Il existe sous 3 noms :

  • lz4 : le nom principal, utilisé pour la compression et la décompression.
  • lz4c : un alias pour lz4 en mode compression.
  • lz4d : un alias pour lz4 en mode décompression.

Le comportement de lz4 peut être modifié par de nombreuses options qui sont décrites ci-dessous.

OPTIONS

Options de compression

-c
Écrit la sortie sur la sortie standard et lit l'entrée standard. Ceci est le comportement par défaut pour la décompression, mais pas pour la compression, même si elle est la console.
-m --multiple
Fichiers d'entrée multiples. Les noms de fichiers compressés seront suffixés par .lz4. Ce mode réduit également le niveau de notification. Peut également être utilisé pour lister plusieurs fichiers. lz4 -m a un comportement équivalent à gzip -k (il préserve les fichiers source par défaut).
-r
Fonctionne récursivement sur les répertoires. Ce mode active également -m (fichiers d'entrée multiples).
-B#
Taille de bloc [4-7](par défaut : 7)
-B4= 64 Ko ; -B5= 256 Ko ; -B6= 1 Mo ; -B7= 4 Mo
-BI
Produit des blocs indépendants (par défaut)
-BD
Les blocs dépendent des prédécesseurs (améliore le taux de compression, plus notable sur les petits blocs)
-BX
Génère des sommes de contrôle de blocs (par défaut : désactivé)
--[no-]frame-crc
Sélectionne la somme de contrôle de trame (par défaut : activé)
--no-crc
Désactive les sommes de contrôle de trame et de bloc
--[no-]content-size
L'en-tête inclut la taille d'origine (par défaut : non présent)
Note : cette option ne peut être activée que lorsque la taille d'origine peut être déterminée, donc pour un fichier. Elle ne fonctionnera pas avec une taille source inconnue, telle que stdin ou un pipe.
--[no-]sparse
Prise en charge du mode sparse (par défaut : activé sur fichier, désactivé sur stdout)
-l
Utilise le format Legacy (typiquement pour la compression du noyau Linux)
Note : -l n'est pas compatible avec -m (--multiple) ni -r

Autres options

-v --verbose
Mode verbeux
-q --quiet
Supprime les avertissements et les statistiques en temps réel ; spécifiez deux fois pour supprimer également les erreurs
-h -H --help
Affiche l'aide/aide longue et quitte
-V --version
Affiche le numéro de version et quitte
-k --keep
Préserve les fichiers source (comportement par défaut)
--rm
Supprime les fichiers source après une compression ou une décompression réussie
--
Traite tous les arguments suivants comme des fichiers

Mode Benchmark

-b#
Benchmark des fichiers, en utilisant le niveau de compression #
-e#
Benchmark plusieurs niveaux de compression, de b# à e# (inclus)
-i#
Temps d'évaluation minimum en secondes [1-9] (par défaut : 3)

Variables d'environnement

Il est possible de passer certains paramètres à lz4 via des variables d'environnement. Cela peut être utile dans des situations où lz4 est connu pour être invoqué (par un script par exemple) mais où il n'y a aucun moyen de passer des paramètres à lz4 pour influencer la session de compression. La variable d'environnement a une priorité plus élevée que la valeur par défaut de l'exécutable, mais une priorité plus faible que la commande runtime correspondante. Lorsqu'elles sont définies comme variables d'environnement globales, elles peuvent servir à imposer des paramètres par défaut personnalisés différents de ceux définis dans l'exécutable.

LZ4_CLEVEL
spécifie un niveau de compression par défaut que lz4 utilise pour la compression lorsqu'aucun autre niveau de compression n'est spécifié sur la ligne de commande. La valeur par défaut de l'exécutable est généralement 1.
LZ4_NBWORKERS
spécifie un nombre de threads par défaut que lz4 utilisera pour la compression. La valeur par défaut de l'exécutable est généralement 0, ce qui signifie déterminé automatiquement en fonction du processeur local. Cette fonctionnalité n'est pertinente que lorsque lz4 est compilé avec le support du multithreading. Le nombre maximum de threads est limité à LZ4_NBWORKERS_MAX (200 par défaut).
