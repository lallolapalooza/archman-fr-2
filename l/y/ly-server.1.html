NOM

ly-server - Manipuler les fichiers source LilyPond via HTTP

Utilisation :

ly-server [options]

Un serveur HTTP pour manipuler le code d'entrée LilyPond

OPTIONS SERVEUR

-v, --version
afficher le numéro de version et quitter
-h, --help
afficher ce texte d'aide et quitter
-p,--port PORT
port sur lequel le serveur écoute (défaut 5432)
-t,--timeout TEMPS
Si défini, le serveur s'arrête automatiquement après -t secondes d'inactivité NON IMPLÉMENTÉ POUR L'INSTANT !

OPTIONS COMMANDE

-e,--encoding ENC
encodage (entrée) (défaut UTF-8)
--output-encoding ENC
encodage de sortie (défaut à l'encodage d'entrée)
-l,--language NOM
langue par défaut pour les noms de notes (défaut "nederlands")
-d <variable=valeur>
définir une variable (voir ci-dessous)

Les options de commande définissent les valeurs par défaut pour l'exécution des commandes déclenchées par les requêtes HTTP. Ces options peuvent être remplacées par la requête HTTP individuelle.

REQUETES HTTP

Requêtes GET

Certaines requêtes GET seront implémentées ultérieurement pour récupérer des valeurs ou modifier certains paramètres du serveur en fonction du chemin de l'URL.

Requêtes POST

Le serveur accepte les requêtes POST sans (actuellement) utiliser le chemin de l'URL. Comme corps de la requête, il attend une seule chaîne JSON avec les éléments suivants :

commands (obligatoire)
Un tableau contenant une ou plusieurs commandes à exécuter successivement. Chaque entrée contient :
command (obligatoire) :
Un nom pour la commande. Il doit être l'un des noms de la liste des commandes disponibles ci-dessous.
args (optionnel) :
Si une commande nécessite des arguments (par exemple, la commande transpose) ceux-ci sont donnés sous forme d'une seule chaîne de caractères.
variables (optionnel) :
Un dictionnaire d'affectations de variables. Les clés doivent appartenir à la liste ci-dessous, et les types de valeurs appropriés sont vérifiés. Si une ou plusieurs variables sont données elles seront définies *avant* l'exécution de la commande. Une variable peut être modifiée à nouveau avant l'exécution de la commande suivante, mais elle n'est pas réinitialisée automatiquement. Donner une variable avec une valeur de '' supprime la variable.
options (optionnel)
Un dictionnaire d'affectations d'options. Les clés doivent appartenir à la liste ci-dessus des Options de Commande, en prenant le nom long sans les tirets de début, par exemple { "encoding": "UTF-16" }. Si une option est donnée ici elle remplace l'option par défaut donnée sur la ligne de commande, mais uniquement pour la commande actuelle.
data (obligatoire)
Une seule chaîne contenant le document d'entrée LilyPond.

Le serveur essaiera de construire une série de commandes à partir de la requête, et si quelque chose ne va pas, il renverra un message "Bad Request" avec le code de réponse HTTP 400.

Objet Réponse

Si les commandes s'exécutent avec succès, le corps de la réponse contiendra un objet JSON sérialisé avec les éléments suivants :

info
Un tableau d'entrées avec le résultat des commandes "info" (voir ci-dessous). Chaque entrée a un champ command et un champ info.
doc
Un objet avec deux champs :
content
Une chaîne avec le contenu du document après application consécutive de toutes les commandes "edit". (Si aucune commande edit n'a été spécifiée, celle-ci contient l'entrée originale).
commands
Un tableau avec les noms des commandes qui ont été appliquées.
exports
Un tableau d'entrées pour chaque commande "export" appliquée. Chaque entrée a les champs suivants :
doc
Une chaîne avec le contenu du document converti/exporté
command
Le nom de la commande appliquée

Commandes

Il existe trois types de commandes dont les résultats sont gérés indépendamment :

  • Les commandes "info" récupèrent des métadonnées du document d'entrée
  • Les commandes "edit" modifient le document, les commandes d'édition ultérieures enchaînent les modifications
  • Les commandes "export" qui convertissent l'entrée dans un autre format. Les commandes ultérieures ne sont pas affectées par le résultat des commandes d'exportation.

Commandes informatives qui retournent des informations et ne modifient pas le fichier :

mode
affiche le mode (deviné s'il n'est pas donné) du document
version
affiche la version de LilyPond, si elle est définie dans le document
language
affiche la langue des noms de notes, si elle est définie dans le document

Commandes qui modifient l'entrée :

indent
ré-indente le fichier
reformat
re-formate le fichier
translate <langue>
traduit les noms de notes dans la langue spécifiée
transpose <depuis> <vers>
transposer le fichier comme le ferait LilyPond, les notes sont données dans la langue 'nederlands'
abs2rel
convertir la musique absolue en relative
rel2abs
convertir la musique relative en absolue

Commandes qui convertissent l'entrée dans un autre format :

musicxml
convertir en MusicXML (en développement, loin d'être complet)
highlight
exporter le document en HTML colorisé syntaxiquement

Variables

Les variables suivantes peuvent être définies pour influencer le comportement des commandes. S'il existe une valeur par défaut, elle est écrite entre crochets :

mode
mode de l'entrée à lire (automatique par défaut) peut être l'un des suivants : lilypond, scheme, latex, html, docbook, texinfo.
encoding [UTF-8]
encodage à lire (également défini par l'argument -e)
default-language [nederlands]
la langue des noms de hauteur à utiliser par défaut, lorsqu'elle n'est pas spécifiée autrement dans le document
output-encoding
encodage à écrire (par défaut encoding, également défini par l'argument --output-encoding)
indent-tabs [false]
si les tabulations doivent être utilisées pour l'indentation
indent-width [2]
nombre d'espaces par niveau d'indentation (si les tabulations ne sont pas utilisées)
full-html [True]
s'il est défini sur True, un document complet avec HTML colorisé syntaxiquement sera exporté, sinon seul le contenu nu sera enveloppé dans un élément configuré par les variables wrapper-.
stylesheet
nom de fichier à référencer comme feuille de style externe pour le HTML colorisé syntaxiquement. Ce nom de fichier est littéralement utilisé dans la balise <link rel="stylesheet">.
inline-style [false]
si les attributs de style en ligne doivent être utilisés pour le HTML colorisé syntaxiquement. Par défaut, une feuille de style CSS est intégrée.
number-lines [false]
si les numéros de ligne doivent être ajoutés lors de la création de HTML colorisé syntaxiquement.
wrapper-tag [pre]
dans quelle balise le HTML colorisé syntaxiquement sera enveloppé. Valeurs possibles : div, pre, id et code
wrapper-attribute [class]
attribut utilisé pour la balise d'enveloppement. Valeurs possibles : id et class.
document-id [lilypond]
nom appliqué à l'attribut d'enveloppement. Si les trois dernières options utilisent leurs paramètres par défaut, les éléments HTML colorisés seront enveloppés dans un élément <pre class="lilypond"></pre>
linenumbers-id [linenumbers]
si les numéros de ligne sont exportés, c'est le nom utilisé pour les éléments <td>

EXEMPLES

Voici l'invocation de base, écoutant sur le port 5432 :

ly-server

Spécification du port et d'un délai d'attente :

ly-server -p 4000 -t 5000

Exemples de Requêtes

La requête la plus simple, appliquant une seule commande d'édition. Dans ce cas, le résultat sera dans result['doc']['content'] :

{
    'commands': [
        {
            'command': 'indent'
        }
    ],
    'data' : "\relative c' { c ( d e f ) }"
}

Une autre requête simple, appliquant cette fois une commande "info". Le résultat sera dans result['info'], contenant lilypond dans le champ info et mode dans le champ command :

{
    'commands': [
        {
            'command': 'mode'
        }
    ],
    'data' : "\relative c' { c ( d e f ) }"
}

Et un exemple plus complexe. Cela transposera d'abord le document, puis convertira la version transposée indépendamment en HTML colorisé et en MusicXML. De plus, il récupérera le mode. Cette fois, le résultat sera dans les trois endroits : le document transposé dans doc.content, le mode dans info.info, et le HTML et le MusicXML dans exports[0].doc et exports[1].doc. :

{
    'commands': [
        {
            'command': 'transpose',
            'args': 'c d'
        },
        {
            'command': 'highlight',
            'variables': { 'full-html': 'false' }
        },
        { 'command': 'musicxml' },
        { 'command': 'mode' },
    ],
    'options': {
        'language': "deutsch"
    },
    'data': "\relative c' { c4 ( d e ) }"
}
