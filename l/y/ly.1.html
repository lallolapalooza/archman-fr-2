NOM

ly - Manipuler les fichiers sources LilyPond

Utilisation :

ly [options] commandes fichier, ...

Un outil pour manipuler les fichiers sources LilyPond

OPTIONS

-v, --version
afficher le numéro de version et quitter
-h, --help
afficher ce texte d'aide et quitter
-i, --in-place
écraser les fichiers d'entrée
-o,--output NOM
nom du fichier de sortie
-e,--encoding ENC
encodage (entrée) (par défaut UTF-8)
--output-encoding ENC
encodage de sortie (par défaut celui de l'entrée)
-l,--language NOM
langue par défaut des noms de notes (par défaut "nederlands")
-d <variable=valeur>
définir une variable

L'option spéciale -- considère les arguments restants comme des noms de fichiers.

ARGUMENTS

La commande est un argument unique avec des commandes séparées par des points-virgules. Dans la plupart des cas, vous citerez la commande pour qu'elle soit considérée comme un seul argument.

Vous pouvez spécifier plus d'un fichier LilyPond. Si vous souhaitez traiter de nombreux fichiers et écrire les résultats des opérations sur chaque fichier dans un fichier de sortie distinct, vous pouvez utiliser deux caractères spéciaux dans le nom du fichier de sortie : un '*' sera remplacé par le chemin complet du fichier d'entrée actuel (sans extension), et un '?' sera remplacé par le nom du fichier d'entrée (sans chemin ni extension). Si vous ne souhaitez pas que '*' ou '?' soient remplacés dans le nom du fichier de sortie, vous pouvez définir -d replace-pattern=false.

Si vous ne spécifiez pas de noms de fichiers d'entrée ou de sortie, l'entrée standard est lue et la sortie standard est écrite.

COMMANDES

Commandes informatives qui écrivent des informations sur la sortie standard et ne modifient pas le fichier :

mode
affiche le mode (deviné s'il n'est pas donné) du document
version
affiche la version de LilyPond, si définie dans le document
language
affiche la langue des noms de notes, si définie dans le document

Commandes qui modifient le fichier :

indent
réindente le fichier
reformat
re-formate le fichier
translate <langue>
traduit les noms de notes dans la langue spécifiée
transpose <de> <à>
transpose le fichier comme le ferait LilyPond, les notes sont données dans la langue 'nederlands'
abs2rel
convertit la musique absolue en relative
rel2abs
convertit la musique relative en absolue
simplify-accidentals
remplace les notes avec des altérations autant que possible par leurs voisins naturels
write [nom_fichier]
écrit le fichier dans le nom de fichier donné ou la variable de sortie. Si la dernière commande était une commande d'édition, write est appelé automatiquement.

Commandes qui exportent le fichier vers un autre format :

musicxml [nom_fichier]
exporte en MusicXML (en développement, loin d'être complet)
highlight [nom_fichier]
exporte le document en HTML avec coloration syntaxique
hl [nom_fichier]
alias pour highlight

Entre les commandes, vous pouvez définir ou annuler la définition d'une variable en utilisant :

variable=valeur
définit une variable à la valeur spécifiée. Les valeurs spéciales sont true, false, qui sont interprétées comme des valeurs booléennes, ou des chiffres, qui seront interprétés comme des valeurs entières.
variable=
annule la définition d'une variable

VARIABLES

Les variables suivantes peuvent être définies pour influencer le comportement des commandes. Si une valeur par défaut existe, elle est écrite entre crochets :

mode
mode du fichier à lire (par défaut automatique) peut être l'un des suivants : lilypond, scheme, latex, html, docbook, texinfo.
output [-]
le nom du fichier de sortie (également défini par l'argument -o)
encoding [UTF-8]
encodage de lecture (également défini par l'argument -e)
default-language [nederlands]
la langue des noms de notes à utiliser par défaut, lorsqu'elle n'est pas spécifiée autrement dans le document
output-encoding
encodage d'écriture (par défaut encoding, également défini par l'argument --output-encoding)
in-place [false]
indique s'il faut écraser les fichiers d'entrée (identique à -i)
backup-suffix [~]
suffixe à utiliser lors de l'édition des fichiers sur place, si défini, une sauvegarde du fichier original est créée avant de l'écraser
replace-pattern [true]
indique s'il faut remplacer '*' et '?' dans le nom du fichier de sortie.
rel-startpitch [true]
indique s'il faut écrire la musique relative avec une note de départ
rel-absolute
indique s'il faut supposer que la première note dans une expression relative sans note de départ spécifiée est absolue. Si false, elle est supposée relative à c'. Si true, elle est supposée absolue (en fait relative à f. Si non défini, cette variable vaut par défaut true seulement lorsque la version de LilyPond dans le document est >= 2.18.
indent-tabs [false]
indique s'il faut utiliser des tabulations pour l'indentation
indent-width [2]
combien d'espaces pour chaque niveau d'indentation (si les tabulations ne sont pas utilisées)
full-html [True]
si défini sur True, un document complet avec HTML coloré syntaxiquement sera exporté, sinon seul le contenu brut encapsulé dans un élément configuré par les variables wrapper- sera exporté.
stylesheet
nom de fichier à référencer comme feuille de style externe pour le HTML coloré syntaxiquement. Ce nom de fichier est littéralement utilisé dans la balise <link rel="stylesheet">.
inline-style [false

utiliser des attributs de style en ligne pour le HTML avec coloration syntaxique. Par défaut, une feuille de style CSS est intégrée.
number-lines [false]

wrapper-tag [pre]

linenumbers-id [linenumbers]
si les numéros de ligne sont exportés, c'est le nom utilisé pour les éléments <td>

Ces variables influencent la sortie des commandes d'information :

with-filename
imprime le nom du fichier à côté des informations comme la version, etc. Ceci est vrai par défaut s'il y a plus d'un fichier spécifié.

EXEMPLES

Voici un exemple pour réindenter et transposer un fichier LilyPond :

ly "indent; transpose c d" -o output.ly file.ly

Exemples utilisant le '*' dans le nom du fichier de sortie :

ly "transpose c d" *.ly -o '*-transposed.ly'
ly highlight *.ly -o 'html/?.html'
