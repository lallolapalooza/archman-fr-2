SMTP(8) Manuel du gestionnaire système SMTP(8)

NOM

smtp, lmtp — Client SMTP+LMTP de Postfix

SYNTAXE

smtp [options génériques du démon Postfix] [flags=DORX]
lmtp [options génériques du démon Postfix] [flags=DORX]

DESCRIPTION


Le client SMTP+LMTP de Postfix implémente les protocoles de livraison de courrier SMTP et LMTP. Il traite les requêtes de livraison de messages du gestionnaire de files d'attente. Chaque requête spécifie un fichier de file d'attente, une adresse d'expéditeur, un domaine ou un hôte de destination, et des informations sur les destinataires. Ce programme est censé être lancé par le gestionnaire de processus master(8). Le nom du processus, smtp ou lmtp, contrôle le protocole et les noms des paramètres de configuration qui seront utilisés.

Le client SMTP+LMTP met à jour le fichier de file d'attente et marque les destinataires comme terminés, ou il informe le gestionnaire de files d'attente que la livraison doit être réessayée plus tard. Les rapports d'état de livraison sont envoyés au démon bounce(8), defer(8) ou trace(8) selon le cas.

La stratégie de recherche de serveur est différente pour SMTP et LMTP, comme décrit dans les sections « RECHERCHE DE SERVEUR SMTP » et « RECHERCHE DE SERVEUR LMTP ».

Après une transaction de courrier réussie, une connexion peut être sauvegardée dans le serveur de cache de connexions scache(8), afin qu'elle puisse être utilisée par n'importe quel client SMTP+LMTP pour une transaction ultérieure.

Par défaut, la mise en cache des connexions est activée temporairement pour les destinations qui ont un volume élevé de courrier dans la file d'attente active. La mise en cache des connexions peut être activée en permanence pour des destinations spécifiques.

RECHERCHE DE SERVEUR SMTP

Le client SMTP de Postfix prend en charge plusieurs destinations séparées par une virgule ou un espace (Postfix 3.5 et ultérieur). Chaque destination est essayée dans l'ordre spécifié.

Les destinations SMTP ont la forme suivante :

nomdedomaine
nomdedomaine:service
Recherche les échangeurs de courrier pour le domaine spécifié, et se connecte au service spécifié (par défaut : smtp). Optionnellement, les échangeurs de courrier peuvent être recherchés avec des requêtes SRV au lieu de MX ; cela nécessite que le service soit donné sous forme symbolique.
[nomd_hote]
[nomd_hote]:service
Recherche l'adresse(s) pour l'hôte spécifié, et se connecte au service spécifié (par défaut : smtp).
[adresse]
[adresse]:service
Se connecte à l'hôte à l'adresse spécifiée, et se connecte au service spécifié (par défaut : smtp). Une adresse IPv6 doit être formatée comme [ipv6:adresse].

RECHERCHE DE SERVEUR LMTP

Le client LMTP de Postfix prend en charge plusieurs destinations séparées par une virgule ou un espace (Postfix 3.5 et ultérieur). Chaque destination est essayée dans l'ordre spécifié.

Les destinations LMTP ont la forme suivante :

unix:chemin_acces
Se connecte au serveur local du domaine UNIX lié au chemin_acces spécifié. Si le processus s'exécute en chroot, un chemin d'accès absolu est interprété par rapport au répertoire de file d'attente de Postfix.
inet:nomdedomaine
inet:nomdedomaine:service
Recherche les serveurs LMTP pour le domaine et le service spécifiés (par défaut : lmtp). Cette forme est prise en charge lorsque les recherches SRV sont activées, et nécessite que le service soit sous forme symbolique.
inet:nomd_hote
inet:nomd_hote:service
Recherche l'adresse(s) pour l'hôte spécifié, et se connecte au service spécifié (par défaut : lmtp). Lorsque les recherches SRV sont activées, utilisez la forme [nomd_hote] pour forcer les recherches d'adresses.
inet:[adresse]
inet:[adresse]:service
Se connecte à l'hôte local ou distant et au service spécifiés (par défaut : lmtp). Une adresse IPv6 doit être formatée comme [ipv6:adresse].

LIVRAISON POUR UN SEUL DESTINATAIRE

Par défaut, le client SMTP+LMTP de Postfix livre le courrier à plusieurs destinataires par requête de livraison. Ceci est indésirable lorsque l'on ajoute un en-tête de message Delivered-to: ou X-Original-To:. Pour empêcher Postfix d'envoyer plusieurs destinataires par requête de livraison, spécifiez

    transport_destination_recipient_limit = 1

dans le fichier main.cf de Postfix, où transport est le nom dans la première colonne de l'entrée master.cf de Postfix pour ce service de livraison de courrier.

SYNTAXE DES ATTRIBUTS DE COMMANDE

flags=DORX (optionnel)
Indicateurs optionnels de traitement des messages.
D
Ajoute un en-tête de message « Delivered-To: destinataire » avec l'adresse du destinataire de l'enveloppe. Remarque : pour que cela fonctionne, le paramètre transport_destination_recipient_limit doit être égal à 1 (voir LIVRAISON POUR UN SEUL DESTINATAIRE ci-dessus pour plus de détails).

L'indicateur D applique également la détection de boucles : si un message contient déjà un en-tête Delivered-To: avec la même adresse de destinataire, le message est rejeté comme non livrable. La comparaison des adresses ne respecte pas la casse.

Cette fonctionnalité est disponible depuis Postfix 3.5.

O
Ajoute un en-tête de message « X-Original-To: destinataire » avec l'adresse du destinataire telle qu'elle a été donnée à Postfix. Remarque : pour que cela fonctionne, le paramètre transport_destination_recipient_limit doit être égal à 1 (voir LIVRAISON POUR UN SEUL DESTINATAIRE ci-dessus pour plus de détails).

Cette fonctionnalité est disponible depuis Postfix 3.5.

R
Ajoute un en-tête de message « Return-Path: <expéditeur> » avec l'adresse de l'expéditeur de l'enveloppe.

Cette fonctionnalité est disponible depuis Postfix 3.5.

X
Indique que la livraison est finale. Cet indicateur affecte le statut rapporté dans les messages DSN (delivery status notification) de « succès », et le change de « relayé » à « livré ».

Cette fonctionnalité est disponible depuis Postfix 3.5.

SÉCURITÉ

Le client SMTP+LMTP est modérément sensible à la sécurité. Il communique avec les serveurs SMTP ou LMTP et les serveurs DNS sur le réseau. Le client SMTP+LMTP peut être exécuté en chroot avec des privilèges faibles fixes.

BOGUES


La réutilisation des connexions SMTP et LMTP pour TLS (sans fermer la connexion SMTP ou LMTP) n'est pas prise en charge avant Postfix 3.4.

La réutilisation des connexions SMTP et LMTP suppose que les identifiants SASL sont valides pour toutes les destinations qui correspondent à la même adresse IP et au même port TCP.

PARAMÈTRES DE CONFIGURATION

Les versions de Postfix 2.3 et ultérieures implémentent le client SMTP et LMTP avec le même programme, et choisissent le protocole et les paramètres de configuration en fonction du nom du processus, smtp ou lmtp.

La plupart des paramètres de configuration smtp_xxx ont un paramètre "miroir" lmtp_xxx pour la fonctionnalité LMTP équivalente. Ce document ne décrit que les paramètres liés à LMTP qui ne sont pas simplement des paramètres de "miroir".

Les modifications apportées à main.cf sont prises en compte automatiquement, car les processus smtp(8) s'exécutent pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer une modification.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

NAME

lmtp — LMTP server (undocumented)

SYNOPSIS

lmtp [options]

DESCRIPTION

The LMTP server is not documented in detail here. The LMTP protocol is a variation of SMTP, which is used for mail delivery from one Mail Transfer Agent (MTA) to another Mail Delivery Agent (MDA). LMTP is designed for multi-user hosts, where the delivery destination might be a user's mailbox or a file.

For a full description of the LMTP protocol and its implementation in Postfix, see the documentation for the lmtp_proto(5) man page.

SMTP SERVER LOOKUP

The LMTP server uses the following mechanisms to look up the next-hop destination:

  • The transport(5) table, for static routing information.
  • The relocations(5) table, for user name changes.
  • The virtual(5) table, for mail delivered to a specific domain or user.
  • DNS MX records, for MX lookup.

LMTP SERVER LOOKUP

The LMTP server uses the following mechanisms to look up the next-hop destination:

  • The transport(5) table, for static routing information.
  • The relocations(5) table, for user name changes.
  • The virtual(5) table, for mail delivered to a specific domain or user.
  • DNS MX records, for MX lookup.

SINGLE-RECIPIENT DELIVERY

LMTP is designed for single-recipient delivery. When the LMTP server receives a message, it splits it into multiple copies, one for each recipient. This allows for more efficient handling of mail delivery, especially when dealing with mailing lists or large recipient lists.

COMMAND ATTRIBUTE SYNTAX

The LMTP server supports a flexible attribute syntax for commands. This allows for detailed control over the delivery process, including specifying delivery methods, recipient attributes, and other delivery-related information.

SECURITY

The LMTP server supports various security mechanisms, including SASL authentication and TLS encryption. These features help to ensure the confidentiality and integrity of the mail data during transit.

STANDARDS

The LMTP server conforms to the following standards:

  • RFC 1869: SMTP Service Extensions
  • RFC 1870: SMTP Service Extension for 8bit-transfer
  • RFC 2033: Local Mail Transfer Protocol (LMTP)
  • RFC 2821: Simple Mail Transfer Protocol (SMTP)
  • RFC 2854: The Transmission Control Protocol (TCP) encoding of the MIME media type application/www-form-urlencoded
  • RFC 2920: SMTP Service Extension for Command Pipelining
  • RFC 3207: SMTP Service Extension for Secure SMTP over TLS
  • RFC 3461: Simple Mail Transfer Protocol (SMTP) Extended HELLO (EHLO) usage for IPv6
  • RFC 3463: Enhanced Mail System Status Codes
  • RFC 3464: An Extensible Mechanism for Encoding MIME Headers in Network Mail Messages
  • RFC 3798: Message Content Type for Delivery Status Notifications (DSN)
  • RFC 4409: Post Office Protocol: Version 3
  • RFC 5321: Simple Mail Transfer Protocol (SMTP)
  • RFC 5322: Internet Message Format

DIAGNOSTICS

The LMTP server logs diagnostic information to the mail log facility. The log messages indicate the status of mail delivery, including any errors or warnings encountered.

BUGS

This server is undocumented. Bugs may be found by testing.
