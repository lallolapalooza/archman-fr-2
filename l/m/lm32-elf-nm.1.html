NOM

nm - lister les symboles des fichiers objets

SYNTAXE

nm [-A|-o|--print-file-name]
[-a|--debug-syms]
[-B|--format=bsd]
[-C|--demangle[=style]]
[-D|--dynamic]
[-fformat|--format=format]
[-g|--extern-only]
[-h|--help]
[--ifunc-chars=CHARS]
[-j|--format=just-symbols]
[-l|--line-numbers] [--inlines]
[-n|-v|--numeric-sort]
[-P|--portability]
[-p|--no-sort]
[-r|--reverse-sort]
[-S|--print-size]
[-s|--print-armap]
[-t radix|--radix=radix]
[-u|--undefined-only]
[-U|--defined-only]
[-V|--version]
[-W|--no-weak]
[-X 32_64]
[--no-demangle]
[--no-recurse-limit|--recurse-limit]]
[--plugin name]
[--size-sort]
[--special-syms]
[--synthetic]
[--target=bfdname]
[--unicode=method]
[--with-symbol-versions]
[--without-symbol-versions]
[fichier_objet...]

DESCRIPTION

GNU nm liste les symboles des fichiers objets fichier_objet.... Si aucun fichier objet n'est spécifié en argument, nm suppose qu'il s'agit du fichier a.out.

Pour chaque symbole, nm affiche :

  • La valeur du symbole, dans la base choisie par les options (voir ci-dessous), ou hexadécimale par défaut.
  • Le type du symbole. Au moins les types suivants sont utilisés ; d'autres le sont également, en fonction du format du fichier objet. Si la casse est minuscule, le symbole est généralement local ; si la casse est majuscule, le symbole est global (externe). Il existe cependant quelques symboles en minuscule qui sont affichés pour des symboles globaux spéciaux ("u", "v" et "w").
"A"
La valeur du symbole est absolue et ne sera pas modifiée par une liaison ultérieure.
"B"
"b"
Le symbole se trouve dans la section de données BSS. Cette section contient typiquement des données initialisées à zéro ou non initialisées, bien que le comportement exact dépende du système.
"C"
"c"
Le symbole est commun. Les symboles communs sont des données non initialisées. Lors de la liaison, plusieurs symboles communs peuvent apparaître avec le même nom. Si le symbole est défini quelque part, les symboles communs sont traités comme des références indéfinies. La casse minuscule c est utilisée lorsque le symbole se trouve dans une section spéciale pour les petits symboles communs.
"D"
"d"
Le symbole se trouve dans la section de données initialisées.
"G"
"g"
Le symbole se trouve dans une section de données initialisées pour les petits objets. Certains formats de fichiers objets permettent un accès plus efficace aux petits objets de données, comme une variable entière globale par opposition à un grand tableau global.
"i"
Pour les fichiers au format PE, cela indique que le symbole se trouve dans une section spécifique à l'implémentation des DLL.

Pour les fichiers au format ELF, cela indique que le symbole est une fonction indirecte. Il s'agit d'une extension GNU à l'ensemble standard des types de symboles ELF. Elle indique un symbole qui, s'il est référencé par une relocalisation, n'évalue pas à son adresse, mais doit plutôt être appelé à l'exécution. L'exécution à l'exécution renverra la valeur à utiliser dans la relocalisation.

Note - l'affichage réel des symboles pour les symboles indirects GNU est contrôlé par l'option de ligne de commande --ifunc-chars. Si cette option a été fournie, le premier caractère de la chaîne sera utilisé pour les symboles de fonction indirecte globaux. Si la chaîne contient un second caractère, celui-ci sera utilisé pour les symboles de fonction indirecte locaux.

"I"
Le symbole est une référence indirecte à un autre symbole.
"N"
Le symbole est un symbole de débogage.
"n"
Le symbole se trouve dans une section en lecture seule qui n'est ni de données, ni de code, ni de débogage.
"p"
Le symbole se trouve dans une section de déroulement de pile.
"R"
"r"
Le symbole se trouve dans une section de données en lecture seule.
"S"
"s"
Le symbole se trouve dans une section de données non initialisées ou initialisées à zéro pour les petits objets.
"T"
"t"
Le symbole se trouve dans la section de texte (code).
"U"
Le symbole est indéfini.
"u"
Le symbole est un symbole global unique. Il s'agit d'une extension GNU à l'ensemble standard des liaisons de symboles ELF. Pour un tel symbole, l'éditeur de liens dynamique s'assurera qu'un seul symbole de ce nom et de ce type est utilisé dans l'ensemble du processus.
"V"
"v"
Le symbole est un objet faible. Lorsqu'un symbole défini faible est lié à un symbole défini normal, le symbole défini normal est utilisé sans erreur. Lorsqu'un symbole indéfini faible est lié et que le symbole n'est pas défini, la valeur du symbole faible devient zéro sans erreur. Sur certains systèmes, la casse majuscule indique qu'une valeur par défaut a été spécifiée.
"W"
"w"
Le symbole est un symbole faible qui n'a pas été spécifiquement marqué comme symbole objet faible. Lorsqu'un symbole défini faible est lié à un symbole défini normal, le symbole défini normal est utilisé sans erreur. Lorsqu'un symbole indéfini faible est lié et que le symbole n'est pas défini, la valeur du symbole est déterminée d'une manière spécifique au système sans erreur. Sur certains systèmes, la casse majuscule indique qu'une valeur par défaut a été spécifiée.
"-"
Le symbole est un symbole stabs dans un fichier objet a.out. Dans ce cas, les valeurs suivantes affichées sont le champ autres stabs, le champ desc stabs, et le type stab. Les symboles Stabs sont utilisés pour contenir des informations de débogage.
"?"
Le type du symbole est inconnu, ou spécifique au format du fichier objet.
•
Le nom du symbole. Si un symbole a des informations de version associées, alors les informations de version sont affichées. Si le symbole versionné est indéfini ou caché de l'éditeur de liens, la chaîne de version est affichée en suffixe du nom du symbole, précédée d'un caractère @. Par exemple foo@VER_1. Si la version est la version par défaut à utiliser lors de la résolution des références non versionnées du symbole, elle est alors affichée en suffixe précédé de deux caractères @. Par exemple foo@@VER_2.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes.

-A
-o
--print-file-name
Précède chaque symbole du nom du fichier d'entrée (ou membre d'archive) dans lequel il a été trouvé, plutôt que d'identifier le fichier d'entrée une seule fois, avant tous ses symboles.
-a
--debug-syms
Affiche tous les symboles, même ceux réservés au débogueur ; normalement, ils ne sont pas listés.
-B
Identique à --format=bsd (pour la compatibilité avec le nm de MIPS).
-C
--demangle[=style]
Décoder (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer les traits de soulignement initiaux ajoutés par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel de style de décodage peut être utilisé pour choisir un style de décodage approprié pour votre compilateur.
--no-demangle
Ne pas décoder les noms de symboles de bas niveau. C'est le comportement par défaut.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors de la démanglement des chaînes. Comme les formats de manglement de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms vraiment compliqués. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bogue concernant un tel événement sera rejeté.

-D
--dynamic
Affiche les symboles dynamiques plutôt que les symboles normaux. Ceci n'est significatif que pour les objets dynamiques, tels que certains types de bibliothèques partagées.
-f format
--format=format
Utilise le format de sortie format, qui peut être "bsd", "sysv", "posix" ou "just-symbols". La valeur par défaut est "bsd". Seul le premier caractère de format est significatif ; il peut être en majuscule ou en minuscule.
-g
--extern-only
Affiche uniquement les symboles externes.
-h
--help
Affiche un résumé des options de nm et quitte.
--ifunc-chars=CHARS
Lors de l'affichage des symboles de fonction indirecte GNU, nm utilise par défaut le caractère "i" pour les fonctions indirectes locales et globales. L'option --ifunc-chars permet à l'utilisateur de spécifier une chaîne contenant un ou deux caractères. Le premier caractère sera utilisé pour les symboles de fonction indirecte globaux et le second caractère, s'il est présent, sera utilisé pour les symboles de fonction indirecte locaux.
j
Identique à --format=just-symbols.
-l
--line-numbers
Pour chaque symbole, utilise les informations de débogage pour essayer de trouver un nom de fichier et un numéro de ligne. Pour un symbole défini, recherche le numéro de ligne de l'adresse du symbole. Pour un symbole indéfini, recherche le numéro de ligne d'une entrée de relocalisation qui fait référence au symbole. Si des informations de numéro de ligne peuvent être trouvées, elles sont imprimées après les autres informations du symbole.
--inlines
Lorsque l'option -l est active, si l'adresse appartient à une fonction qui a été intégrée (inlined), cette option provoque l'impression des informations source pour toutes les portées englobantes jusqu'à la première fonction non intégrée. Par exemple, si "main" intègre "callee1" qui intègre "callee2", et que l'adresse provient de "callee2", les informations source pour "callee1" et "main" seront également imprimées.
-n
-v
--numeric-sort
Trie les symboles numériquement par leurs adresses, plutôt qu'alphabétiquement par leurs noms.
-p
--no-sort
Ne prend pas la peine de trier les symboles dans un ordre quelconque ; les imprime dans l'ordre où ils sont rencontrés.
-P
--portability
Utilise le format de sortie standard POSIX.2 au lieu du format par défaut. Équivalent à -f posix.
-r
--reverse-sort
Inverse l'ordre du tri (numérique ou alphabétique) ; que le dernier vienne le premier.
-S
--print-size
Imprime la valeur et la taille des symboles définis pour le style de sortie "bsd". Cette option n'a aucun effet pour les formats d'objets qui n'enregistrent pas les tailles de symboles, sauf si --size-sort est également utilisé, auquel cas une taille calculée est affichée.
-s
--print-armap
Lors de la liste des symboles des membres d'archives, inclut l'index : un mappage (stocké dans l'archive par ar ou ranlib) des modules qui contiennent des définitions pour quels noms.
-t radix
--radix=radix
Utilise radix comme base pour imprimer les valeurs des symboles. Il doit être d pour décimal, o pour octal, ou x pour hexadécimal.
-u
--undefined-only
Affiche uniquement les symboles indéfinis (ceux qui sont externes à chaque fichier objet). Par défaut, les symboles définis et indéfinis sont affichés.
-U
--defined-only
Affiche uniquement les symboles définis pour chaque fichier objet. Par défaut, les symboles définis et indéfinis sont affichés.
-V
--version
Affiche le numéro de version de nm et quitte.
-X
Cette option est ignorée pour des raisons de compatibilité avec la version AIX de nm. Elle prend un paramètre qui doit être la chaîne 32_64. Le mode par défaut de nm AIX correspond à -X 32, qui n'est pas pris en charge par GNU nm.
--plugin nom
Charge le plugin nommé nom pour ajouter la prise en charge de types de cibles supplémentaires. Cette option n'est disponible que si la chaîne d'outils a été compilée avec la prise en charge des plugins activée.

Si --plugin n'est pas fourni, mais que la prise en charge des plugins a été activée, alors nm itère sur les fichiers dans ${libdir}/bfd-plugins par ordre alphabétique et le premier plugin qui revendique l'objet en question est utilisé.

Veuillez noter que ce répertoire de recherche de plugins n'est *pas* celui utilisé par l'option -plugin de ld. Pour que nm utilise le plugin de l'éditeur de liens, il doit être copié dans le répertoire ${libdir}/bfd-plugins. Pour les compilations basées sur GCC, le plugin de l'éditeur de liens s'appelle liblto_plugin.so.0.0.0. Pour les compilations basées sur Clang, il s'appelle LLVMgold.so. Le plugin GCC est toujours rétrocompatible avec les versions antérieures, il suffit donc de copier le plus récent.

--size-sort
Trie les symboles par taille. Pour les objets ELF, les tailles de symboles sont lues à partir de l'ELF, pour les autres types d'objets, les tailles de symboles sont calculées comme la différence entre la valeur du symbole et la valeur du symbole avec la valeur supérieure suivante. Si le format de sortie "bsd" est utilisé, la taille du symbole est imprimée, plutôt que la valeur, et -S doit être utilisé pour que la taille et la valeur soient imprimées.

Notez que cette option ne fonctionne pas si --undefined-only a été activé, car les symboles indéfinis n'ont pas de taille.

--special-syms
Affiche les symboles qui ont une signification spéciale spécifique à la cible. Ces symboles sont généralement utilisés par la cible pour un traitement spécial et ne sont normalement pas utiles lorsqu'ils sont inclus dans les listes de symboles normales. Par exemple, pour les cibles ARM, cette option ignorerait les symboles de mappage utilisés pour marquer les transitions entre le code ARM, le code THUMB et les données.
--synthetic
Inclut les symboles synthétiques dans la sortie. Ce sont des symboles spéciaux créés par l'éditeur de liens à diverses fins. Ils ne sont pas affichés par défaut car ils ne font pas partie du code source d'origine du binaire.
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multibytes encodés en UTF-8 dans les chaînes. La valeur par défaut (--unicode=default) est de ne leur appliquer aucun traitement spécial. L'option --unicode=locale affiche la séquence dans la locale actuelle, qui peut ou non les prendre en charge. Les options --unicode=hex et --unicode=invalid les affichent sous forme de séquences d'octets hexadécimaux entourées d'accolades ou de crochets.

L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement mises en surbrillance en rouge (si le périphérique de sortie le prend en charge). La coloration est destinée à attirer l'attention sur la présence de séquences unicode là où elles pourraient ne pas être attendues.

--no-weak
Ne pas afficher les symboles faibles.
--with-symbol-versions
--without-symbol-versions

OPTIONS

--format=bfdname
Specify an object code format other than your system's default format.
--help
Show summary of options.
--internals=
List symbols that are internal to the object file. These are symbols that are not meant to be referenced by other object files. This option is not supported by all object file formats.
--no-sort-own
Do not sort symbols that are defined in the file being examined. By default symbols are sorted.
--print-file-name
Precede each symbol an its file name. If the file name can not be determined, then the symbol is prefixed with ''. (an empty string).
--size-sort
Sort the symbols according to there size. Symbols are sorted by default by there name.
--special-syms
List special symbols in addition to the normal symbols.
--synthetic
List synthetic symbols in addition to the normal symbols.
--target-file=filename
Specify that object code format of filename should be used. This option is used to examine files of a different object code format than the system's default format.
--undefined-only
Only list undefined symbols.
--version
Display the version of the program to be run and exit.
--warn-common
Warn when a common symbol is encountered. By default common symbols are ignored.
--with-symbol-versions
Display symbol version information. This option is enabled by default. For example, foo@VER_1. If the version is the default version to be used when resolving unversioned references to the symbol then it is displayed as a suffix preceded by two @ characters. For example foo@@VER_2. By default, symbol version information is displayed.
--target=bfdname
Specify an object code format other than your system's default format.
@file
Read command-line options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
