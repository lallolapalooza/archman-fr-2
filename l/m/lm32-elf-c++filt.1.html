C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - désérialise les symboles C++ et Java

SYNTAXE

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbole...]

DESCRIPTION

Les langages C++ et Java offrent la surcharge de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction prenne des paramètres de types différents. Afin de pouvoir distinguer ces fonctions aux noms similaires, C++ et Java les encodent en un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de mangling (encodage). Le programme c++filt [1] effectue le mappage inverse : il décode (désérialise) les noms de bas niveau en noms de niveau utilisateur afin qu'ils puissent être lus.

Chaque mot alphanumérique (composé de lettres, de chiffres, de soulignements, de dollars ou de points) rencontré dans l'entrée est un nom encodé potentiel. Si le nom est décodé en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot d'origine est renvoyé. De cette manière, vous pouvez passer un fichier source assembleur entier, contenant des noms encodés, à travers c++filt et voir le même fichier source contenant des noms désérialisés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles depuis l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés être uniquement des noms encodés et aucun contrôle n'est effectué pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et désérialisera le nom en "f()", tandis que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom encodé qui le rend invalide). Cette commande cependant fonctionnera :

echo _Z1fv, | c++filt -n

et affichera "f(),", c'est-à-dire le nom désérialisé suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils fassent partie d'un fichier source assembleur où il peut y avoir des caractères supplémentaires, extrinsèques, après un nom encodé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, les compilateurs C et C++ placent un soulignement devant chaque nom. Par exemple, le nom C "foo" obtient le nom de bas niveau "_foo". Cette option supprime le soulignement initial. Le fait que c++filt supprime le soulignement par défaut dépend de la cible.
-n
--no-strip-underscore
Ne pas supprimer le soulignement initial.
-p
--no-params
Lors de la désérialisation du nom d'une fonction, n'afficher pas les types des paramètres de la fonction.
-t
--types
Tenter de désérialiser les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types encodés ne sont normalement utilisés qu'à l'intérieur du compilateur, et ils peuvent être confondus avec des noms non encodés. Par exemple, une fonction appelée "a" traitée comme un nom de type encodé serait désérialisée en "signed char".
-i
--no-verbose
Ne pas inclure les détails d'implémentation (le cas échéant) dans la sortie désérialisée.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors de la désérialisation des chaînes. Étant donné que les formats d'encodage de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour désérialiser des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, une exhaustion de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

-s format
--format=format
c++filt peut décoder diverses méthodes d'encodage, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode utilisée :
"auto"
Sélection automatique basée sur l'exécutable (la méthode par défaut)
"gnu"
celui utilisé par le compilateur C++ GNU (g++)
"lucid"
celui utilisé par le compilateur Lucid (lcc)
"arm"
celui spécifié par le C++ Annotated Reference Manual
"hp"
celui utilisé par le compilateur HP (aCC)
"edg"
celui utilisé par le compilateur EDG
"gnu-v3"
celui utilisé par le compilateur C++ GNU (g++) avec l'ABI V3.
"java"
celui utilisé par le compilateur Java GNU (gcj)
"gnat"
celui utilisé par le compilateur Ada GNU (GNAT).
--help
Imprimer un résumé des options de c++filt et quitter.
--version
Imprimer le numéro de version de c++filt et quitter.
@fichier
Lire les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en faisant précéder le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.

NAME

c++filt - Démêler les noms C++

SYNOPSIS

c++filt [OPTION]… [input]

DESCRIPTION

Le programme c++filt démêle les noms symboliques qui ont été en manglés par le compilateur C++.

Le démêlage des noms est le processus consistant à convertir des noms symboliques manglés (qui incluent des informations sur les types et l’espace de noms) en noms plus lisibles par l’homme qui reflètent leur déclaration d’origine en C++.

Si une entrée est spécifiée, c++filt lira à partir de celle-ci. Sinon, il lira à partir de l’entrée standard.

Par défaut, c++filt suppose que les noms ont été manglés par le compilateur GNU C++.

OPTIONS

-<compilateur>
Spécifie quel compilateur a été utilisé pour manger les noms. Les compilateurs supportés sont : gnu, hp, ll, mips, tianyuang, thumb, wap, xg++. Par défaut, gnu est utilisé.

-format
Spécifie le format des entrées et des sorties. Les formats supportés sont : demangle et print. Par défaut, demangle est utilisé.

-n, --no-demangle
Ne démêle pas les noms. Ceci est utile pour tester le programme.

-h, --help
Affiche un message d’aide et quitte.

-v, --version
Affiche les informations de version et quitte.

NOTES

Ce programme est une implémentation du programme c++filt de GNU. Il a été écrit par David Carl Smith et amélioré par de nombreuses personnes.
