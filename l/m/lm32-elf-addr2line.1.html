ADDR2LINE(1) Outils de développement GNU ADDR2LINE(1)

NOM

addr2line - convertir des adresses ou un symbole+décalage en noms de fichiers et numéros de ligne

SYNTAXE

addr2line [-a|--addresses]
[-b nom_bfd|--target=nom_bfd]
[-C|--demangle[=style]]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-e nom_fichier|--exe=nom_fichier]
[-f|--functions] [-s|--basename]
[-i|--inlines]
[-p|--pretty-print]
[-j|--section=nom]
[-H|--help] [-V|--version]
[adresse adresse ...]

DESCRIPTION

addr2line traduit des adresses ou un symbole+décalage en noms de fichiers et numéros de ligne. Étant donné une adresse ou un symbole+décalage dans un exécutable ou un décalage dans une section d'un objet relogeable, il utilise les informations de débogage pour déterminer quel nom de fichier et quel numéro de ligne y sont associés.

L'exécutable ou l'objet relogeable à utiliser est spécifié avec l'option -e. Par défaut, c'est le fichier a.out. La section dans l'objet relogeable à utiliser est spécifiée avec l'option -j.

addr2line a deux modes de fonctionnement.

Dans le premier mode, les adresses hexadécimales ou un symbole+décalage sont spécifiés sur la ligne de commande, et addr2line affiche le nom du fichier et le numéro de ligne pour chaque adresse.

Dans le second mode, addr2line lit les adresses hexadécimales ou un symbole+décalage depuis l'entrée standard, et imprime le nom du fichier et le numéro de ligne pour chaque adresse sur la sortie standard. Dans ce mode, addr2line peut être utilisé dans un pipe pour convertir des adresses choisies dynamiquement.

Le format de la sortie est NOM_FICHIER:NUMERO_LIGNE. Par défaut, chaque adresse d'entrée génère une ligne de sortie.

Deux options peuvent générer des lignes supplémentaires avant chaque ligne NOM_FICHIER:NUMERO_LIGNE (dans cet ordre).

Si l'option -a est utilisée, alors une ligne avec l'adresse d'entrée est affichée.

Si l'option -f est utilisée, alors une ligne avec le NOM_FONCTION est affichée. C'est le nom de la fonction contenant l'adresse.

Une option peut générer des lignes supplémentaires après la ligne NOM_FICHIER:NUMERO_LIGNE.

Si l'option -i est utilisée et que le code à l'adresse donnée est présent là en raison d'une inlining par le compilateur, alors des lignes supplémentaires sont affichées ensuite. Une ou deux lignes supplémentaires (si l'option -f est utilisée) sont affichées pour chaque fonction inlinée.

Alternativement, si l'option -p est utilisée, alors chaque adresse d'entrée génère une seule longue ligne de sortie contenant l'adresse, le nom de la fonction, le nom du fichier et le numéro de ligne. Si l'option -i a également été utilisée, alors les fonctions inlinées seront affichées de la même manière, mais sur des lignes séparées, et préfixées par le texte (inlined by).

Si le nom du fichier ou le nom de la fonction ne peuvent pas être déterminés, addr2line affichera deux points d'interrogation à leur place. Si le numéro de ligne ne peut pas être déterminé, addr2line affichera 0.

Lorsque l'on utilise un symbole+décalage, +décalage est optionnel, sauf lorsque le symbole est ambigu avec un nombre hexadécimal. Les symboles résolus peuvent être "mangled" ou "unmangled", sauf que les symboles "unmangled" avec + ne sont pas autorisés.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes.

-a
--addresses
Affiche l'adresse avant le nom de la fonction, le nom du fichier et les informations de numéro de ligne. L'adresse est imprimée avec un préfixe 0x pour l'identifier facilement.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objets est nom_bfd.
-C
--demangle[=style]
Décode (démangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de "mangling". L'argument optionnel de style de démangling peut être utilisé pour choisir un style de démangling approprié pour votre compilateur.
-e nom_fichier
--exe=nom_fichier
Spécifie le nom de l'exécutable pour lequel les adresses doivent être traduites. Le fichier par défaut est a.out.
-f
--functions
Affiche les noms de fonctions ainsi que le nom du fichier et les informations de numéro de ligne.
-s
--basenames
Affiche uniquement la base de chaque nom de fichier.
-i
--inlines
Si l'adresse appartient à une fonction qui a été inlinée, les informations source pour tous les scopes englobants jusqu'à la première fonction non inlinée seront également imprimées. Par exemple, si "main" inlines "callee1" qui inlines "callee2", et que l'adresse provient de "callee2", les informations source pour "callee1" et "main" seront également imprimées.
-j
--section
Lit les décalages relatifs à la section spécifiée au lieu des adresses absolues.
-p
--pretty-print
Rend la sortie plus conviviale : chaque emplacement est imprimé sur une ligne. Si l'option -i est spécifiée, les lignes pour tous les scopes englobants sont préfixées par (inlined by).
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du démangling des chaînes. Étant donné que les formats de "mangling" de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuiserait l'espace de pile disponible sur la machine hôte, déclenchant une erreur de mémoire. La limite essaie d'éviter que cela ne se produise en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour démangler des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-limit.

Notez que cette option n'est efficace que si l'option -C ou --demangle a été activée.

@fichier
Lit les options de la ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière soit avec des apostrophes simples, soit avec des guillemets doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure avec une barre oblique inverse. Le fichier peut lui-même contenir d'autres options @fichier ; toutes ces options seront traitées

lm32-elf-addr2line(1) - Arch Linux

NOM

lm32-elf-addr2line - convertir des adresses en noms de fichiers, adresses et décalages ligne par ligne.

SYNTAXE

lm32-elf-addr2line [options...] [addresse...]

DESCRIPTION

Le programme lm32-elf-addr2line convertit les adresses en emplacements de ligne dans le code source. Il lit une liste d'adresses à partir de l'entrée standard ou des arguments de la ligne de commande, puis pour chaque adresse, il écrit le nom du fichier source et le numéro de ligne correspondant à l'emplacement de ce code dans le programme. Il peut également afficher le nom de la fonction contenant l'adresse.

Ce programme est particulièrement utile pour déboguer des programmes, car il permet de savoir où une adresse correspond dans le code source.

OPTIONS

-a
Affiche l'adresse de décalage de début de chaque fonction en plus de l'information habituelle. Ceci est utile quand vous voulez voir la liste de toutes les adresses comprises dans une fonction.
-b bibliothque
Utilise la bibliothque spécifiée au lieu de celle par défaut. Ceci est utile si votre programme est lié à plusieurs bibliothèques dynamiques.
-C
Désérialise les noms de fonctions C++. Ceci est utile pour obtenir des noms plus lisibles pour les fonctions C++ qui ont été surchargées ou utilisées dans des templates.
-e fichier exécutable
Récupère les informations de débogage à partir du fichier exécutable spécifié. S'il n'est pas spécifié, addr2line utilisera la bibliothèque par défaut.
-f
Affiche le nom de la fonction en plus du nom du fichier et du numéro de ligne.
-i
Traite les adresses comme des adresses d'instructions de niveau inférieur (par exemple, adresses d'instructions de processeur, par opposition aux adresses de ligne de source). Ceci est utile lorsque l'on travaille avec du code assembleur.
-p
Utilise la chaîne de caractères `traduction' pour les noms de fonctions. Ceci est utile pour obtenir des noms de fonctions plus lisibles lorsqu'on travaille avec du code C++. Par exemple, si une fonction est nommée `_ZNSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEE4_M_+}$', `addr2line -p' la traduira en quelque chose de plus compréhensible comme `std::__cxx11::basic_string, std::allocator >::_M_init_copy()'.
-R mapfile
Charge les informations de remappage à partir du fichier spécifié mapfile. Ceci est utile lorsque vous travaillez avec des systèmes qui utilisent des fichiers de remappage pour mapper des adresses virtuelles à des adresses physiques.
-s
Affiche l'adresse de décalage de début de chaque objet en plus de l'information habituelle. Ceci est utile lorsque vous voulez voir la liste de toutes les adresses comprises dans un objet.
-S
Affiche uniquement les noms de fichiers et les numéros de ligne, en omettant les noms de fonctions. Ceci est utile lorsque vous souhaitez réduire la sortie et vous concentrer uniquement sur les emplacements de code.
-v
Affiche la version de `lm32-elf-addr2line' et quitte.
--demangle[=mode]
Désérialise les noms de fonctions. Le mode peut être `auto', `gnu' ou `hp'. Par défaut, le mode `auto' est utilisé, ce qui tente de détecter automatiquement le mode de désérialisation.
--exe=fichier exécutable
Récupère les informations de débogage à partir du fichier exécutable spécifié. S'il n'est pas spécifié, `addr2line' utilisera la bibliothèque par défaut.
--functions
Affiche le nom de la fonction en plus du nom du fichier et du numéro de ligne.
--inlines
Affiche les informations sur les fonctions en ligne autant que possible. Ceci est utile lorsque vous travaillez avec du code optimisé qui utilise des fonctions en ligne, car cela permet de mieux comprendre où le code est exécuté.
--obj=fichier exécutable
Identique à l'option -e.
--pretty-print
Utilise la chaîne de caractères `traduction' pour les noms de fonctions. Ceci est utile pour obtenir des noms de fonctions plus lisibles lorsqu'on travaille avec du code C++. Par exemple, si une fonction est nommée `_ZNSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEE4_M_+}$', `addr2line -p' la traduira en quelque chose de plus compréhensible comme `std::__cxx11::basic_string, std::allocator >::_M_init_copy()'.
--read-file=mapfile
Charge les informations de remappage à partir du fichier spécifié mapfile. Ceci est utile lorsque vous travaillez avec des systèmes qui utilisent des fichiers de remappage pour mapper des adresses virtuelles à des adresses physiques.
--source
Affiche uniquement les noms de fichiers et les numéros de ligne, en omettant les noms de fonctions. Ceci est utile lorsque vous souhaitez réduire la sortie et vous concentrer uniquement sur les emplacements de code.
--version
Affiche la version de `lm32-elf-addr2line' et quitte.

addresse...
Les adresses à convertir. Si aucune adresse n'est spécifiée, `addr2line' essaiera de lire les adresses à partir de l'entrée standard.

--help
Affiche un message d'aide et quitte.
