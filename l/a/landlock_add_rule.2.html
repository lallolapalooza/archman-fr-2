landlock_add_rule(2) Manuel des appels système landlock_add_rule(2)

NOM

landlock_add_rule - ajouter une nouvelle règle Landlock à un jeu de règles

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <linux/landlock.h>  /* Définition des constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Définition des constantes SYS_* */
int syscall(SYS_landlock_add_rule, int ruleset_fd,
            enum landlock_rule_type rule_type,
            const void *rule_attr, uint32_t flags);

DESCRIPTION

Une règle Landlock décrit une action sur un objet que le processus a l'intention d'effectuer. Un ensemble de règles est agrégé dans un jeu de règles, qui peut ensuite restreindre le thread qui l'applique, ainsi que ses futurs enfants.

L'appel système landlock_add_rule() ajoute une nouvelle règle Landlock à un jeu de règles existant. Voir landlock(7) pour un aperçu global.

ruleset_fd est un descripteur de fichier de jeu de règles Landlock obtenu avec landlock_create_ruleset(2).

rule_type identifie le type de structure pointé par rule_attr. Actuellement, Linux prend en charge les valeurs de rule_type suivantes :

LANDLOCK_RULE_PATH_BENEATH
Pour ces règles, l'objet est une hiérarchie de fichiers, et les actions du système de fichiers associées sont définies avec des droits d'accès au système de fichiers.
Dans ce cas, rule_attr pointe vers la structure suivante :

struct landlock_path_beneath_attr {
    __u64 allowed_access;
    __s32 parent_fd;
} __attribute__((packed));

allowed_access contient un masque de bits des actions du système de fichiers autorisées, qui peuvent être appliquées sur le parent_fd donné (voir Actions du système de fichiers dans landlock(7)).
parent_fd est un descripteur de fichier ouvert, de préférence avec le drapeau O_PATH, qui identifie le répertoire parent de la hiérarchie de fichiers ou simplement un fichier.
LANDLOCK_RULE_NET_PORT
Pour ces règles, l'objet est un port TCP, et les actions associées sont définies avec des droits d'accès réseau.
Dans ce cas, rule_attr pointe vers la structure suivante :

struct landlock_net_port_attr {
    __u64 allowed_access;
    __u64 port;
};

allowed_access contient un masque de bits des actions réseau autorisées, qui peuvent être appliquées sur le port donné.
port est le port réseau en endianness hôte.
Il convient de noter que le port 0 passé à bind(2) liera à un port disponible de la plage de ports éphémères. Cela peut être configuré dans le sysctl /proc/sys/net/ipv4/ip_local_port_range (également utilisé pour l'IPv6).
Une règle Landlock avec le port 0 et le droit LANDLOCK_ACCESS_NET_BIND_TCP signifie que demander à lier sur le port 0 est autorisé et que cela se traduira automatiquement par une liaison sur la plage de ports associée.

flags doit être 0.

VALEUR DE RETOUR

En cas de succès, landlock_add_rule() retourne 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

landlock_add_rule() peut échouer pour les raisons suivantes :

EAFNOSUPPORT
rule_type est LANDLOCK_RULE_NET_PORT, mais le TCP n'est pas pris en charge par le noyau en cours d'exécution.
EOPNOTSUPP
Landlock est pris en charge par le noyau mais désactivé au démarrage.
EINVAL
flags n'est pas 0.
EINVAL
Les accès de règle sont incohérents (c'est-à-dire que rule_attr->allowed_access n'est pas un sous-ensemble des accès gérés par le jeu de règles).
EINVAL
Dans struct landlock_path_beneath_attr, les accès de règle ne sont pas applicables au fichier (c'est-à-dire que certains droits d'accès dans rule_attr->allowed_access ne sont applicables qu'aux répertoires, mais rule_attr->parent_fd ne fait pas référence à un répertoire).
EINVAL
Dans struct landlock_net_port_attr, le numéro de port est supérieur à 65535.
ENOMSG
Accès vides (c'est-à-dire que rule_attr->allowed_access est 0).
EBADF
ruleset_fd n'est pas un descripteur de fichier pour le thread courant, ou un membre de rule_attr n'est pas un descripteur de fichier comme attendu.
EBADFD
ruleset_fd n'est pas un descripteur de fichier de jeu de règles, ou un membre de rule_attr n'est pas du type de descripteur de fichier attendu.
EPERM
ruleset_fd n'a pas de droit d'écriture sur le jeu de règles sous-jacent.
EFAULT
rule_attr n'était pas une adresse valide.

NORMES

Linux.

HISTORIQUE

Linux 5.13.

EXEMPLES

Voir landlock(7).

VOIR AUSSI

landlock_create_ruleset(2), landlock_restrict_self(2), landlock(7)
