sous-routine dlarrd (character range, character order, integer n, double precision vl, double precision vu, integer il, integer iu, double precision, dimension( * ) gers, double precision reltol, double precision, dimension( * ) d, double precision, dimension( * ) e, double precision, dimension( * ) e2, double precision pivmin, integer nsplit, integer, dimension( * ) isplit, integer m, double precision, dimension( * ) w, double precision, dimension( * ) werr, double precision wl, double precision wu, integer, dimension( * ) iblock, integer, dimension( * ) indexw, double precision, dimension( * ) work, integer, dimension( * ) iwork, integer info)

DLARRD calcule les valeurs propres d'une matrice tridiagonale symétrique avec une précision appropriée.

Objectif :

!>
!> DLARRD calcule les valeurs propres d'une matrice tridiagonale
!> symétrique T avec une précision appropriée. C'est un code auxiliaire
!> destiné à être appelé depuis DSTEMR.
!> L'utilisateur peut demander toutes les valeurs propres, toutes les valeurs
!> propres dans l'intervalle semi-ouvert (VL, VU], ou les IL-èmes à IU-èmes
!> valeurs propres.
!>
!> Pour éviter le dépassement de capacité, la matrice doit être mise à l'échelle
!> de telle sorte que son plus grand élément n'excède pas en valeur absolue
!> overflow**(1/2) * underflow**(1/4), et pour une précision maximale,
!> elle ne devrait pas être beaucoup plus petite que cela.
!>
!> Voir W. Kahan, Rapport CS41, Département d'informatique, Université de Stanford,
!> 21 juillet 1966.
!>

Paramètres

RANGE 
!>          RANGE est CHARACTER*1
!>          = 'A' : ()   toutes les valeurs propres seront trouvées.
!>          = 'V' : () toutes les valeurs propres dans l'intervalle
!>                           semi-ouvert (VL, VU] seront trouvées.
!>          = 'I' : () les IL-èmes à IU-èmes valeurs propres (de la
!>                           matrice entière) seront trouvées.
!>

ORDER

!>          ORDER est CHARACTER*1
!>          = 'B' : () les valeurs propres seront groupées par
!>                              blocs séparés (voir IBLOCK, ISPLIT) et
!>                              ordonnées de la plus petite à la plus grande
!>                              dans le bloc.
!>          = 'E' : ()
!>                              les valeurs propres pour la matrice entière
!>                              seront ordonnées de la plus petite à la
!>                              plus grande.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice tridiagonale T. N >= 0.
!>

VL

!>          VL est DOUBLE PRECISION
!>          Si RANGE='V', la borne inférieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures
!>          ou égales à VL, ou supérieures à VU, ne seront pas retournées.
!>          VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est DOUBLE PRECISION
!>          Si RANGE='V', la borne supérieure de l'intervalle à
!>          rechercher pour les valeurs propres. Les valeurs propres inférieures
!>          ou égales à VL, ou supérieures à VU, ne seront pas retournées.
!>          VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

GERS

!>          GERS est tableau DOUBLE PRECISION, dimension (2*N)
!>          Les N intervalles de Gerschgorin (le i-ème intervalle de
!>          Gerschgorin est (GERS(2*i-1), GERS(2*i)).
!>

RELTOL

!>          RELTOL est DOUBLE PRECISION
!>          La largeur relative minimale d'un intervalle. Quand un intervalle
!>          est plus étroit que RELTOL fois le plus grand (en magnitude)
!>          des points d'extrémité, il est considéré comme
!>          suffisamment petit, c'est-à-dire convergent. Note : cela devrait
!>          toujours être au moins radix*epsilon machine.
!>

D

!>          D est tableau DOUBLE PRECISION, dimension (N)
!>          Les N éléments diagonaux de la matrice tridiagonale T.
!>

E

!>          E est tableau DOUBLE PRECISION, dimension (N-1)
!>          Les N-1 éléments hors-diagonaux de la matrice tridiagonale T.
!>

E2

!>          E2 est tableau DOUBLE PRECISION, dimension (N-1)
!>          Les N-1 éléments hors-diagonaux au carré de la matrice tridiagonale T.
!>

PIVMIN

!>          PIVMIN est DOUBLE PRECISION
!>          Le pivot minimum autorisé dans la séquence de Sturm pour T.
!>

NSPLIT

!>          NSPLIT est INTEGER
!>          Le nombre de blocs diagonaux dans la matrice T.
!>          1 <= NSPLIT <= N.
!>

ISPLIT

!>          ISPLIT est tableau INTEGER, dimension (N)
!>          Les points de séparation, où T se décompose en sous-matrices.
!>          La première sous-matrice comprend les lignes/colonnes 1 à ISPLIT(1),
!>          la seconde les lignes/colonnes ISPLIT(1)+1 à ISPLIT(2),
!>          etc., et la NSPLIT-ème comprend les lignes/colonnes
!>          ISPLIT(NSPLIT-1)+1 à ISPLIT(NSPLIT)=N.
!>          (Seuls les NSPLIT premiers éléments seront effectivement utilisés,
!>          mais comme l'utilisateur ne peut pas savoir a priori quelle valeur
!>          NSPLIT aura, N mots doivent être réservés pour ISPLIT.)
!>

M

!>          M est INTEGER
!>          Le nombre réel de valeurs propres trouvées. 0 <= M <= N.
!>          (Voir aussi la description de INFO=2,3.)
!>

W

!>          W est tableau DOUBLE PRECISION, dimension (N)
!>          En sortie, les M premiers éléments de W contiendront les
!>          approximations des valeurs propres. DLARRD calcule un intervalle
!>          I_j = (a_j, b_j] qui inclut la valeur propre j. L'approximation de la
!>          valeur propre est donnée par le point milieu de l'intervalle
!>          W(j)= ( a_j + b_j)/2. L'erreur correspondante est bornée par
!>          WERR(j) = abs( a_j - b_j)/2
!>

WERR

!>          WERR est tableau DOUBLE PRECISION, dimension (N)
!>          La borne d'erreur sur l'approximation de la valeur propre
!>          correspondante dans W.
!>

WL

!>          WL est DOUBLE PRECISION
!>

WU

!>          WU

DOUBLE PRÉCISION !> L'intervalle (WL, WU] contient toutes les valeurs propres désirées. !> Si RANGE='V', alors WL=VL et WU=VU. !> Si RANGE='A', alors WL et WU sont les bornes globales de Gerschgorin !> sur le spectre. !> Si RANGE='I', alors WL et WU sont calculés par DLAEBZ à partir de !> la plage d'indices spécifiée. !>

IBLOCK

!>          IBLOCK est un tableau INTEGER, dimension (N)
!>          À chaque ligne/colonne j où E(j) est nulle ou petite, la
!>          matrice T est considérée comme se décomposant en une matrice
!>          triangulaire par blocs. À la sortie, si INFO = 0, IBLOCK(i) spécifie
!>          à quel bloc (de 1 au nombre de blocs) appartient la valeur propre W(i).
!>          (DLARRD peut utiliser les N-M éléments restants comme espace de travail.)
!>

INDEXW

!>          INDEXW est un tableau INTEGER, dimension (N)
!>          Les indices des valeurs propres dans chaque bloc (sous-matrice) ;
!>          par exemple, INDEXW(i)= j et IBLOCK(i)=k impliquent que la
!>          i-ème valeur propre W(i) est la j-ème valeur propre du bloc k.
!>

WORK

!>          WORK est un tableau DOUBLE PRÉCISION, dimension (4*N)
!>

IWORK

!>          IWORK est un tableau INTEGER, dimension (3*N)
!>

INFO

!>          INFO est un INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0 : certaines ou toutes les valeurs propres n'ont pas convergé ou
!>                n'ont pas été calculées :
!>                =1 ou 3 : La dichotomie a échoué pour certaines
!>                        valeurs propres ; ces valeurs propres sont marquées par un
!>                        numéro de bloc négatif. L'effet est que les
!>                        valeurs propres peuvent ne pas être aussi précises que les
!>                        tolérances absolue et relative. Ceci est généralement causé par
!>                        une arithmétique inattendument imprécise.
!>                =2 ou 3 : RANGE='I' seulement : Toutes les valeurs propres
!>                        IL:IU n'ont pas été trouvées.
!>                        Effet : M < IU+1-IL
!>                        Cause : arithmétique non-monotone, causant la
!>                                non-monotonicité de la séquence de Sturm.
!>                        Remède : recalculer, en utilisant RANGE='A', et extraire
!>                                les valeurs propres IL:IU. Dans certains cas, augmenter
!>                                le PARAMETER peut faire fonctionner.
!>                = 4 : RANGE='I', et l'intervalle de Gerschgorin
!>                        initialement utilisé était trop petit. Aucune valeur propre
!>                        n'a été calculée.
!>                        Cause probable : votre machine a une arithmétique
!>                                        à virgule flottante imprécise.
!>                        Remède : Augmenter le PARAMETER,
!>                              recompiler et réessayer.
!>

Paramètres internes :

!>  FUDGE   DOUBLE PRÉCISION, par défaut = 2
!>          Un facteur pour élargir les intervalles de Gerschgorin. Idéalement,
!>          une valeur de 1 devrait fonctionner, mais sur les machines avec une arithmétique
!>          imprécise, cela doit être plus grand. La valeur par défaut pour
!>          les versions publiées publiquement devrait être suffisamment grande pour
!>          gérer la pire machine existante. Notez que cela n'a aucun effet
!>          sur la précision de la solution.
!>
