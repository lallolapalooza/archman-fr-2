landlock_restrict_self(2) Manuel des appels système landlock_restrict_self(2)

NOM

landlock_restrict_self - appliquer un ensemble de règles Landlock

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/landlock.h>  /* Définition des constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Définition des constantes SYS_* */
int syscall(SYS_landlock_restrict_self, int ruleset_fd,
            uint32_t flags);

DESCRIPTION

Une fois qu'un ensemble de règles Landlock est rempli avec les règles désirées, l'appel système landlock_restrict_self() applique cet ensemble de règles au thread appelant. Voir landlock(7) pour une vue d'ensemble.

Un thread peut être restreint avec plusieurs ensembles de règles qui sont ensuite composés pour former le domaine Landlock du thread. Ceci peut être vu comme une pile d'ensembles de règles, mais c'est implémenté d'une manière plus efficace. Un domaine ne peut être mis à jour que d'une manière où les contraintes de chaque ensemble de règles composé, passé et futur, restreindront le thread et ses futurs enfants pendant toute leur durée de vie. Il est donc possible d'appliquer progressivement des politiques de contrôle d'accès personnalisées avec plusieurs ensembles de règles indépendants provenant de différentes sources (par exemple, configuration du système d'initialisation, politique de session utilisateur, politique d'application intégrée). Cependant, la plupart des applications n'auront besoin que d'un seul appel à landlock_restrict_self() et devraient éviter des nombres arbitraires de tels appels en raison de la limite des ensembles de règles composés. Au lieu de cela, les développeurs sont encouragés à construire un seul ensemble de règles personnalisé avec plusieurs appels à landlock_add_rule(2).

Pour appliquer un ensemble de règles, l'appelant doit avoir la capacité CAP_SYS_ADMIN dans son espace utilisateur, ou le bit no_new_privs doit déjà être défini pour le thread. Comme pour seccomp(2), cela évite les scénarios où des processus non privilégiés peuvent affecter le comportement d'enfants privilégiés (par exemple, à cause de binaires set-user-ID). Si ce bit n'était pas déjà défini par un ancêtre de ce thread, le thread doit effectuer l'appel suivant :

prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);

ruleset_fd est un descripteur de fichier d'ensemble de règles Landlock obtenu avec landlock_create_ruleset(2) et entièrement rempli avec un ensemble d'appels à landlock_add_rule(2).

flags doit être 0.

VALEUR DE RETOUR

En cas de succès, landlock_restrict_self() retourne 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

landlock_restrict_self() peut échouer pour les raisons suivantes :

EOPNOTSUPP
Landlock est supporté par le noyau mais désactivé au démarrage.
EINVAL
flags n'est pas 0.
EBADF
ruleset_fd n'est pas un descripteur de fichier pour le thread actuel.
EBADFD
ruleset_fd n'est pas un descripteur de fichier d'ensemble de règles.
EPERM
ruleset_fd n'a pas d'accès en lecture à l'ensemble de règles sous-jacent, ou le thread appelant n'est pas exécuté avec no_new_privs, ou il n'a pas la capacité CAP_SYS_ADMIN dans son espace utilisateur.
E2BIG
Le nombre maximum d'ensembles de règles composés est atteint pour le thread appelant. Cette limite est actuellement de 64.

NORMES

Linux.

HISTORIQUE

Linux 5.13.

EXEMPLES

Voir landlock(7).

VOIR AUSSI

landlock_create_ruleset(2), landlock_add_rule(2), landlock(7)
