DOCUMENTATION DE FONCTION

sous-routine dlagts (integer job, integer n, double precision, dimension( * ) a, double precision, dimension( * ) b, double precision, dimension( * ) c, double precision, dimension( * ) d, integer, dimension( * ) in, double precision, dimension( * ) y, double precision tol, integer info)

DLAGTS résout le système d'équations (T-λI)x = y ou (T-λI)^Tx = y, où T est une matrice tridiagonale générale et λ un scalaire, en utilisant la factorisation LU calculée par slagtf.

Objectif :

!>
!> DLAGTS peut être utilisé pour résoudre l'un des systèmes d'équations
!>
!>    (T - lambda*I)*x = y   ou   (T - lambda*I)**T*x = y,
!>
!> où T est une matrice tridiagonale n x n, pour x, suite à la
!> factorisation de (T - lambda*I) en
!>
!>    (T - lambda*I) = P*L*U ,
!>
!> par la routine DLAGTF. Le choix de l'équation à résoudre est
!> contrôlé par l'argument JOB, et dans chaque cas, il y a une option
!> pour perturber les éléments diagonaux de U nuls ou très petits, cette option
!> étant destinée à être utilisée dans des applications telles que l'itération inverse.
!>

Paramètres

JOB 
!>          JOB est un entier (INTEGER)
!>          Spécifie le travail à effectuer par DLAGTS comme suit :
!>          =  1 : Les équations  (T - lambda*I)x = y  doivent être résolues,
!>                mais les éléments diagonaux de U ne doivent pas être perturbés.
!>          = -1 : Les équations  (T - lambda*I)x = y  doivent être résolues
!>                et, si un dépassement de capacité devait se produire, les éléments
!>                diagonaux de U doivent être perturbés. Voir l'argument TOL ci-dessous.
!>          =  2 : Les équations  (T - lambda*I)**Tx = y  doivent être résolues,
!>                mais les éléments diagonaux de U ne doivent pas être perturbés.
!>          = -2 : Les équations  (T - lambda*I)**Tx = y  doivent être résolues
!>                et, si un dépassement de capacité devait se produire, les éléments
!>                diagonaux de U doivent être perturbés. Voir l'argument TOL ci-dessous.
!>

N

!>          N est un entier (INTEGER)
!>          L'ordre de la matrice T.
!>

A

!>          A est un tableau de double précision (DOUBLE PRECISION), dimension (N)
!>          À l'entrée, A doit contenir les éléments diagonaux de U tels que
!>          renvoyés par DLAGTF.
!>

B

!>          B est un tableau de double précision (DOUBLE PRECISION), dimension (N-1)
!>          À l'entrée, B doit contenir les premiers éléments supradiagonaux de
!>          U tels que renvoyés par DLAGTF.
!>

C

!>          C est un tableau de double précision (DOUBLE PRECISION), dimension (N-1)
!>          À l'entrée, C doit contenir les éléments sous-diagonaux de L tels que
!>          renvoyés par DLAGTF.
!>

D

!>          D est un tableau de double précision (DOUBLE PRECISION), dimension (N-2)
!>          À l'entrée, D doit contenir les seconds éléments supradiagonaux
!>          de U tels que renvoyés par DLAGTF.
!>

IN

!>          IN est un tableau d'entiers (INTEGER), dimension (N)
!>          À l'entrée, IN doit contenir les détails de la matrice P tels que
!>          renvoyés par DLAGTF.
!>

Y

!>          Y est un tableau de double précision (DOUBLE PRECISION), dimension (N)
!>          À l'entrée, le vecteur du second membre y.
!>          À la sortie, Y est écrasé par le vecteur solution x.
!>

TOL

!>          TOL est une double précision (DOUBLE PRECISION)
!>          À l'entrée, avec JOB < 0, TOL doit être la perturbation minimale
!>          à apporter aux éléments diagonaux de U très petits.
!>          TOL doit normalement être choisi environ eps*norm(U), où eps
!>          est la précision relative de la machine, mais si TOL est fourni comme
!>          non positif, alors il est réinitialisé à eps*max( abs( u(i,j) ) ).
!>          Si JOB > 0 alors TOL n'est pas référencé.
!>
!>          À la sortie, TOL est modifié comme décrit ci-dessus, uniquement si TOL
!>          est non positif à l'entrée. Sinon, TOL n'est pas modifié.
!>

INFO

!>          INFO est un entier (INTEGER)
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>          > 0 : un dépassement de capacité surviendrait lors du calcul du INFO-ième
!>                élément du vecteur solution x. Cela ne peut survenir
!>                que lorsque JOB est fourni comme positif et signifie soit
!>                qu'un élément diagonal de U est très petit, soit
!>                que les éléments du vecteur second membre y sont très
!>                grands.
!>

!>          IN is INTEGER array, dimension (N)
!>          On entry, IN must contain details of the matrix P as returned
!>          from SLAGTF.
!>

Y

!>          Y is REAL array, dimension (N)
!>          On entry, the right hand side vector y.
!>          On exit, Y is overwritten by the solution vector x.
!>

TOL

!>          TOL is REAL
!>          On entry, with  JOB < 0, TOL should be the minimum
!>          perturbation to be made to very small diagonal elements of U.
!>          TOL should normally be chosen as about eps*norm(U), where eps
!>          is the relative machine precision, but if TOL is supplied as
!>          non-positive, then it is reset to eps*max( abs( u(i,j) ) ).
!>          If  JOB > 0  then TOL is not referenced.
!>
!>          On exit, TOL is changed as described above, only if TOL is
!>          non-positive on entry. Otherwise TOL is unchanged.
!>

INFO

!>          INFO is INTEGER
!>          = 0: successful exit
!>          < 0: if INFO = -i, the i-th argument had an illegal value
!>          > 0: overflow would occur when computing the INFO(th)
!>               element of the solution vector x. This can only occur
!>               when JOB is supplied as positive and either means
!>               that a diagonal element of U is very small, or that
!!>               the elements of the right-hand side vector y are very
!>               large.
!>
