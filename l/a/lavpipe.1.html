NOM

lavpipe - crée des flux YUV bruts à partir de scripts de listes de canaux

SYNTAXE

lavpipe [-o nombre] [-n nombre] liste-de-canaux

DESCRIPTION

lavpipe lit un fichier script appelé 'liste de canaux' qui est d'une structure similaire aux listes d'édition qui peuvent être fournies à lav2yuv. Pour plus d'informations sur le format de la liste de canaux, voir ci-dessous.

La liste de canaux définit plusieurs sources vidéo et filtres qui sont combinés par lavpipe pour produire un seul flux YUV de sortie sur la sortie standard (qui peut, par exemple, être compressé et stocké sur disque via mpeg2enc(1) ou yuv2lav(1)).

OPTIONS

Les options de ligne de commande sont utilisées pour sortir une partie spécifique du flux vidéo résultant. Cela signifie que vous pouvez indiquer à lavpipe combien d'images ignorer et combien d'images livrer à partir de ce point.

-o nombre
Ceci est le décalage d'images de la vidéo de sortie. Les nombre premières images de la vidéo résultante ne sont ni calculées ni écrites sur la sortie standard. Cette valeur est de 0 par défaut.
-n nombre
Ceci est le nombre d'images. Si les fichiers d'entrée ou les flux définis dans le script de liste de canaux sont suffisamment longs, la sortie sera d'une longueur exacte de nombre images. Une valeur de 0 signifie que toutes les images jusqu'à la dernière, telles que définies dans la liste de canaux, seront écrites, tant qu'il y a une entrée (0 est la valeur par défaut).
liste-de-canaux
Ceci est le nom du fichier de liste de canaux que lavpipe 'exécutera'. Pour des informations sur le format de ce fichier, voir ci-dessous.
-?
Affiche un synopsis de la syntaxe de la commande.

EXEMPLES

lavpipe -o 100 -n 25 film.pli
calculerait et sortirait sur la sortie standard les images 100 à 124 telles que définies dans film.pli (en PAL, ce serait la 5ème seconde du film).
lavpipe input.pli | yuv2lav -q80 output.avi
enregistrerait le film assemblé par lavpipe sous forme de fichier AVI unique.

UTILISATION

Dans cette section, le format des fichiers d'entrée de lavpipe, les scripts de liste de canaux, est expliqué. Si vous avez besoin d'exemples ou d'un tutoriel plus détaillé, veuillez lire la section sur la CRÉATION DE TRANSITIONS DE FILMS de la page de manuel mjpegtools(1). et le fichier README.lavpipe qui devrait être inclus dans la distribution. N'hésitez pas non plus à nous contacter via la liste de diffusion (voir ci-dessous).

Une liste de canaux se compose de deux parties : la liste de sources YUV et, après cela, autant de descriptions de séquences que souhaité. Elle commence toujours par les deux lignes suivantes :

LAV Pipe List
Ceci est la première ligne de chaque script de liste de canaux. Elle est utilisée comme un simple test pour savoir si lavpipe a bien reçu un script de liste de canaux et non votre thèse de doctorat en entrée.
NTSC|PAL
Ceci est la deuxième ligne de chaque liste de canaux et peut être PAL ou NTSC, en fonction du standard vidéo que vous utilisez. Je ne me souviens pas si cela est utilisé actuellement.

Suit maintenant la liste de sources :

nombre
Ceci est le nombre de commandes d'entrée. lavpipe lira les nombre lignes suivantes et les interprétera comme des commandes de flux d'entrée.
commande (nombre fois)
Ceci est une ligne de commande valide avec deux variables $o et $n qui seront remplacées par lavpipe avec le décalage et le nombre d'images que le programme doit produire. Exemple :
lav2yuv -o $o -f $n input.avi

Ainsi, une liste de sources exemple pourrait ressembler à ceci :
2
lav2yuv -o $o -f $n scene1.avi
lav2yuv -o $o -f $n scene2.avi

Après cela, vous pouvez ajouter autant de descriptions de séquences que nécessaire. Chacune d'elles est construite comme suit :

nombre
Le nombre d'images que cette séquence durera.
nombre
Le nombre d'entrées qui seront utilisées dans cette séquence. Ce nombre doit bien sûr être inférieur ou égal au nombre d'entrées définies ci-dessus.
idx [ofs] (nombre fois)
Ce sont les indices des sources définies au début du fichier (la première source est 0) avec un décalage d'images optionnel (c'est-à-dire que la séquence commence avec l'image numéro ofs de cette entrée.) - cette valeur est de 0 par défaut. Exemple :
0 150
commande
Ceci est une ligne de commande valide pour un outil de filtrage YUV qui lit nombre flux d'entrée et écrit un flux de sortie, combinant ses entrées. Optionnellement, l'outil de filtrage peut recevoir les deux variables $o et $n qui seront remplacées par lavpipe comme dans les commandes sources (voir ci-dessus). Pour plus d'informations, lisez README.lavpipe ou la documentation des programmes de filtrage (si disponible). Un filtre exemple pourrait ressembler à ceci :
transist.flt -o 0 -O 255 -s $o -n $n -d 50
Et si la séquence n'a qu'une seule entrée qui doit simplement être copiée en sortie, vous pouvez utiliser un tiret à la place d'une ligne de commande :
-

Et voici un exemple de liste de canaux complète qui implémente une transition de scene1.avi à scene2.avi

BOGUES

Je suis sûr qu'il y en a assez. lavpipe accepte souvent des listes de canaux mal formées et produit ensuite une vidéo qui était tout sauf prévue - sans avertissement.

La mention de $n ci-dessus est fausse. À un moment donné, il y avait deux paramètres, mais maintenant un programme est autorisé à produire autant d'images qu'il le souhaite. L'auteur du programme a codé en dur, pour des raisons inconnues, $n à 0.

NOTES

Il y a aussi quelques limitations sérieuses dans le système, comme le traitement image par image. Mais comme l'objectif en écrivant lavpipe était la simplicité du pipeline, d'autres outils devront être écrits pour accomplir des tâches plus intéressantes.
Mais je tiens à noter qu'il est tout à fait possible d'écrire une liste de canaux qui combine plusieurs fichiers, puis d'utiliser cette liste de canaux comme entrée pour une autre liste de canaux en utilisant simplement la commande lavpipe dans la liste de sources (voir ci-dessus) - cela peut déjà être utilisé pour faire de belles choses, si vous avez de bons filtres.

Les commentaires NE SONT PAS autorisés dans les fichiers de liste de canaux. Les commentaires (texte après #) ci-dessus sont uniquement à des fins d'illustration.
