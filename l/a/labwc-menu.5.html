labwc-menu(5) Manuel des formats de fichiers labwc-menu(5)

NOM

labwc - fichier de menu

DESCRIPTION

Les menus statiques sont construits sur la base du fichier menu.xml situé dans "~/.config/labwc" et les répertoires de base XDG équivalents.

SYNTAXE

Le fichier de menu doit être entièrement englobé dans les balises <openbox_menu> et </openbox_menu>. À l'intérieur de ces balises, les menus sont spécifiés comme suit :

<!-- Un menu de niveau supérieur -->
<menu id="external_menu_settings" label="Paramètres Externes" icon="preferences-other">
  <item label="Paramètres d'affichage">
    <action name="Execute" command="wdisplays" />
  </item>
</menu>
<!-- Un autre menu de niveau supérieur -->
<menu id="">
  <!-- Une entrée de menu avec une action, par exemple pour exécuter une application -->
  <item label="" icon="">
    <action></action>
  </item>
  <!-- Un sous-menu défini ailleurs, utilise les attributs label et icon externes -->
  <menu id="external_menu_settings" />
  <!-- Ligne horizontale -->
  <separator />
  <!-- Un sous-menu en ligne -->
  <menu id="" label="" icon="">
    ...quelques éléments...
  </menu>
  <!-- Titre -->
  <separator label="" />
  <!-- Pipemenu -->
  <menu id="" label="" icon="" execute="COMMANDE" />
</menu>

menu.id (au niveau supérieur)

Définit une arborescence de menus. Chaque menu doit avoir un id, qui est un identifiant unique du menu. Cet id est utilisé pour référencer le menu dans une action ShowMenu. Les identifiants par défaut sont :
  • "root-menu" pour le menu contextuel de la fenêtre racine
  • "client-menu" pour le menu contextuel de la barre de titre d'une fenêtre
  • "client-list-combined-menu" pour une liste de toutes les fenêtres sur tous les espaces de travail. Changera le focus vers l'application sélectionnée ou ira à l'espace de travail sans activer d'application si "Aller là-bas" est sélectionné.
  • "client-send-to-menu" affiche tous les espaces de travail et envoie la fenêtre actuelle vers cet espace de travail lorsqu'il est sélectionné.

menu.id (lorsqu'il est imbriqué sous un autre élément <menu>)

Lien vers un sous-menu défini ailleurs (par un <menu id=""> de niveau supérieur).

menu.label

Le titre du menu, affiché dans son parent. Un label doit être fourni lors de la définition d'un menu, sauf s'il s'agit de l'élément de menu le plus haut.

Notez qu'Openbox requiert également un label="" défini pour les éléments de niveau supérieur, mais par souci de simplicité, labwc les gère avec ou sans l'attribut label.

menu.icon

Une icône à rendre, affichée dans son parent. Cet argument est optionnel. Voir menu.item.icon pour plus de détails.

menu.item.label

Le nom visible de l'élément de menu.

menu.item.icon

Le nom d'une icône à afficher devant l'entrée de menu. Cet attribut est optionnel. Le nom suit les conventions de nommage des entrées "Icon=" dans les fichiers .desktop. Si utilisé, il est recommandé d'utiliser uniquement le nom de l'icône plutôt qu'un chemin complet. Cela garantit que l'icône sera recherchée dans l'échelle de sortie où le menu est rendu. Par exemple, l'utilisation de icon="vlc" est suggérée plutôt que d'utiliser icon="/usr/share/icons/hicolor/16x16/apps/vlc.png".

menu.item.action

Voir labwc-actions(5). Note : Le CDATA XML est pris en charge pour ce nœud afin de maintenir la compatibilité avec obmenu-generator.

menu.separator

Ligne horizontale.

menu.separator.label

Dans un élément "separator", l'attribut label transforme le séparateur d'une ligne horizontale en un titre de menu (en-tête) contenant le texte spécifié par label.

menu.execute

Commande à exécuter pour un menu pipe. Voir les détails ci-dessous.

MENUS PIPE

Les menus pipe sont des menus générés dynamiquement sur la base de la sortie de scripts ou de binaires. On les appelle ainsi parce que la sortie de l'exécutable est transmise au menu labwc.

Pour toute entrée <menu id="" label="" execute="COMMANDE"/> dans menu.xml, la COMMANDE sera exécutée la première fois que l'élément est sélectionné (par exemple, par curseur ou par saisie clavier). La sortie XML de la commande sera analysée et affichée comme un sous-menu. Le contenu des menus pipe est mis en cache jusqu'à ce que l'ensemble du menu (pas seulement le menu pipe) soit fermé.

Le contenu de la sortie doit être entièrement englobé dans les balises <openbox_pipe_menu>. À l'intérieur, les menus sont spécifiés de la même manière que les menus statiques (normaux), par exemple :

<openbox_pipe_menu>
  <item label="Terminal">
    <action name="Execute" command="xterm"/>
  </item>
</openbox_pipe_menu>

Les sous-menus en ligne et les menus pipe imbriqués sont pris en charge.

Notez qu'il incombe à l'exécutable du menu pipe de s'assurer que les attributs ID sont uniques. Les doublons sont ignorés.

Lors de la rédaction de scripts de menu pipe, assurez-vous d'échapper les caractères spéciaux XML tels que "&" ("&amp;"), "<" ("&lt;"), et ">" ("&gt;").

Un menu pipe peut également être utilisé pour définir l'élément de niveau supérieur <menu>. Dans ce cas, l'ensemble du fichier menu.xml serait réduit à quelque chose comme ceci (en remplaçant obmenu-generator par le générateur de menu de votre choix) :

<?xml version="1.0"?>
<openbox_menu>
  <menu id="root-menu" label="" execute="obmenu-generator"/>
</openbox_menu>

LOCALISATION

La localisation disponible pour le "client-menu" par défaut n'est affichée que si aucun "client-menu" n'est présent dans menu.xml. Toute définition de menu dans menu.xml est interprétée comme un remplacement par l'utilisateur.
