landlock_create_ruleset(2) Manuel des appels système landlock_create_ruleset(2)

NOM

landlock_create_ruleset - créer un nouvel ensemble de règles Landlock

BIBLIOTHQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/landlock.h>  /* Définition des constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_landlock_create_ruleset,
            const struct landlock_ruleset_attr *attr,
            size_t size , uint32_t flags);

DESCRIPTION

Un ensemble de règles Landlock identifie un ensemble de règles (c'est-à-dire des actions sur des objets). Cet appel système landlock_create_ruleset() crée un nouveau descripteur de fichier qui identifie un ensemble de règles. Ce descripteur de fichier peut ensuite être utilisé par landlock_add_rule(2) et landlock_restrict_self(2). Voir landlock(7) pour un aperçu général.

attr spécifie les propriétés du nouvel ensemble de règles. Il pointe vers la structure suivante :


struct landlock_ruleset_attr {
    __u64 handled_access_fs;
    __u64 handled_access_net;
};

handled_access_fs est un masque de bits des actions de système de fichiers gérées (voir Actions sur le système de fichiers dans landlock(7)).
handled_access_net est un masque de bits des actions réseau gérées (voir Actions réseau dans landlock(7)).
Cette structure définit un ensemble de droits d'accès gérés, un ensemble d'actions sur différents types d'objets, qui doivent être refusés par défaut lorsque l'ensemble de règles est appliqué. Inversement, les droits d'accès qui ne sont pas spécifiquement listés ici ne seront pas refusés par cet ensemble de règles lorsqu'il sera appliqué.
Pour des raisons historiques, le droit LANDLOCK_ACCESS_FS_REFER est toujours refusé par défaut, même lorsque son bit n'est pas défini dans handled_access_fs. Afin d'ajouter de nouvelles règles avec ce droit d'accès, le bit doit toujours être défini explicitement (voir Actions sur le système de fichiers dans landlock(7)).
La liste explicite des droits d'accès gérés est requise pour des raisons de rétrocompatibilité. Dans la plupart des cas d'utilisation, les processus utilisant Landlock géreront une large gamme, voire la totalité, des droits d'accès qu'ils connaissent au moment de la compilation (et qu'ils ont testés avec un noyau qui les prenait tous en charge).
Cette structure peut évoluer dans les futures versions de Landlock.

size doit être spécifié comme sizeof(struct landlock_ruleset_attr) pour des raisons de compatibilité.

flags doit être 0 si attr est utilisé. Sinon, flags peut être défini à :

LANDLOCK_CREATE_RULESET_VERSION
Si attr est NULL et size est 0, alors la valeur retournée est la version la plus élevée de l'ABI Landlock supportée (à partir de 1). Cette version peut être utilisée pour une approche de sécurité par meilleure approximation, ce qui est encouragé lorsque l'espace utilisateur n'est pas figé à une version spécifique du noyau. Toutes les fonctionnalités documentées dans ces pages man sont disponibles avec la version 1.

VALEUR RETOURNEE

En cas de succès, landlock_create_ruleset() retourne un nouveau descripteur de fichier d'ensemble de règles Landlock, ou une version de l'ABI Landlock, selon flags. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

landlock_create_ruleset() peut échouer pour les raisons suivantes :

EOPNOTSUPP
Landlock est supporté par le noyau mais désactivé au démarrage.
EINVAL
flags inconnu, ou accès inconnu, ou size trop petit.
E2BIG
size est trop grand.
EFAULT
attr n'était pas une adresse valide.
ENOMSG
Accès vides (c'est-à-dire que attr n'a spécifié aucun droit d'accès à restreindre).

NORMES

Linux.

HISTORIQUE

Linux 5.13.

EXEMPLES

Voir landlock(7).

VOIR AUSSI

landlock_add_rule(2), landlock_restrict_self(2), landlock(7)
