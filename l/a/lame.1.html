lame(1) Compresseur audio LAME lame(1)

NOM

lame - créer des fichiers audio mp3

SYNTAXE

lame [options] <fichier_entrée> <fichier_sortie>

DESCRIPTION

LAME est un programme qui peut être utilisé pour créer des fichiers audio compressés. (Lame n'est pas un encodeur MP3). Ces fichiers audio peuvent être lus par des lecteurs MP3 populaires tels que mpg123 ou madplay. Pour lire depuis stdin, utilisez « - » pour <fichier_entrée>. Pour écrire vers stdout, utilisez « - » pour <fichier_sortie>.

OPTIONS

Options d'entrée :

-r
Suppose que le fichier d'entrée est du PCM brut. Le taux d'échantillonnage et mono/stéréo/jstereo doivent être spécifiés sur la ligne de commande. Pour chaque échantillon stéréo, LAME attend que les données d'entrée soient ordonnées, canal gauche d'abord, puis canal droit. Par défaut, LAME s'attend à ce qu'ils soient des entiers signés avec une largeur de bit de 16 et stockés en little-endian. Sans -r, LAME effectuera plusieurs fseek() sur le fichier d'entrée à la recherche d'en-têtes WAV et AIFF.
Peut ne pas être disponible sur votre version.
-x
Inverse les octets dans le fichier d'entrée (ou fichier de sortie lors de l'utilisation de --decode).
Pour résoudre les problèmes d'endianness little/big. Si vos encodages sonnent comme du statique, essayez d'abord cela.
Sans utiliser -x, LAME traitera le fichier d'entrée comme étant en endian natif.
-s sfreq
sfreq = 8/11.025/12/16/22.05/24/32/44.1/48

Requis uniquement pour les fichiers d'entrée PCM bruts. Sinon, il sera déterminé à partir de l'en-tête du fichier d'entrée.

LAME rééchantillonnera automatiquement le fichier d'entrée vers l'un des taux d'échantillonnage MP3 pris en charge si nécessaire.

--bitwidth n
Largeur de bit d'entrée par échantillon.
n = 8, 16, 24, 32 (par défaut 16)

Requis uniquement pour les fichiers d'entrée PCM bruts. Sinon, il sera déterminé à partir de l'en-tête du fichier d'entrée.

--signed
Indique à LAME que les échantillons de l'entrée sont signés (par défaut pour les données pcm brutes 16, 24 et 32 bits).

Requis uniquement pour les fichiers d'entrée PCM bruts.

--unsigned
Indique à LAME que les échantillons de l'entrée sont non signés (par défaut pour les données pcm brutes 8 bits, où 0x80 est zéro).

Requis uniquement pour les fichiers d'entrée PCM bruts et disponible uniquement à la largeur de bit 8.

--little-endian
Indique à LAME que les échantillons de l'entrée sont au format little-endian.

Requis uniquement pour les fichiers d'entrée PCM bruts.

--big-endian
Indique à LAME que les échantillons de l'entrée sont au format big-endian.

Requis uniquement pour les fichiers d'entrée PCM bruts.

--mp1input
Suppose que le fichier d'entrée est un fichier MPEG Layer I (c'est-à-dire MP1).
Si le nom de fichier se termine par « .mp1 », LAME supposera qu'il s'agit d'un fichier MPEG Layer I. Pour stdin ou les fichiers Layer I qui ne se terminent pas par .mp1, vous devez utiliser ce commutateur.
--mp2input
Suppose que le fichier d'entrée est un fichier MPEG Layer II (c'est-à-dire MP2).
Si le nom de fichier se termine par « .mp2 », LAME supposera qu'il s'agit d'un fichier MPEG Layer II. Pour stdin ou les fichiers Layer II qui ne se terminent pas par .mp2, vous devez utiliser ce commutateur.
--mp3input
Suppose que le fichier d'entrée est un fichier MP3.
Utile pour le sous-échantillonnage d'un mp3 à un autre. Par exemple, il peut être utile pour le streaming via un serveur IceCast.
Si le nom de fichier se termine par « .mp3 », LAME supposera qu'il s'agit d'un MP3. Pour stdin ou les fichiers MP3 qui ne se terminent pas par .mp3, vous devez utiliser ce commutateur.
--nogap fichier1 fichier2 ...
Encodage sans interruption pour un ensemble de fichiers contigus
--nogapout dir
Répertoire de sortie pour l'encodage sans interruption (doit précéder --nogap)
--out-dir dir
Si aucun fichier de sortie explicite n'est spécifié, un fichier sera écrit au chemin donné. Ignoré lors de l'utilisation d'une entrée en pipeline/streamée

Options opérationnelles :

-m mode
mode = s, j, f, d, m, l, r

Le stéréo joint est le mode par défaut pour les fichiers stéréo.

Stéréo (s)imple (LR forcé)
Dans ce mode, l'encodeur n'utilise pas les corrélations potentiellement existantes entre les deux canaux d'entrée. Il peut, cependant, négocier la demande de bits entre les deux canaux, c'est-à-dire donner plus de bits à un canal si l'autre contient du silence ou nécessite moins de bits en raison d'une complexité plus faible.

Stéréo (j)oint
Dans ce mode, l'encodeur peut utiliser (sur une base frame par frame) soit le stéréo L/R, soit le stéréo mid/side. En mid/side stereo, les canaux mid (L+R) et side (L-R) sont encodés, et plus de bits sont alloués au canal mid qu'au canal side. Lorsqu'il n'y a pas trop de séparation stéréo, cela augmente effectivement la bande passante, offrant ainsi une meilleure qualité avec la même quantité de bits.

Utiliser le stéréo mid/side de manière inappropriée peut entraîner des artefacts de compression audibles. Trop de changements entre mid/side et stéréo régulier peuvent également mal sonner. Pour déterminer quand passer au stéréo mid/side, LAME utilise un algorithme beaucoup plus sophistiqué que celui décrit dans la documentation ISO.

Stéréo MS (f)orcé
Force toutes les frames à être encodées avec le stéréo mid/side. Il ne doit être utilisé que si vous êtes sûr que chaque frame du fichier d'entrée a une séparation stéréo très faible.

Canal (d)ual
Dans ce mode, les 2 canaux seront encodés de manière totalement indépendante. Chaque canal aura exactement la moitié du débit binaire. Ce mode est conçu pour des applications telles que l'encodage de doubles langues (par exemple : anglais dans un canal et français dans l'autre). L'utilisation de ce mode d'encodage pour des fichiers stéréo réguliers entraînera un encodage de moindre qualité.

(m)ono
L'entrée sera encodée en tant que signal mono. S'il s'agissait d'un signal stéréo, il sera sous-échantillonné en mono. Le mixage est calculé comme la somme des canaux gauche et droit, atténuée de 6 dB. Notez également que si vous utilisez un flux PCM stéréo RAW, vous devez utiliser le paramètre -a.

Canal (l)eft uniquement
L'entrée sera encodée en tant que signal mono. S'il s'agissait d'un signal stéréo, seul le canal gauche sera encodé.

Canal (r)ight uniquement
L'entrée sera encodée en tant que signal mono. S'il s'agissait d'un signal stéréo, seul le canal droit sera encodé.

-a
Mixe le fichier d'entrée stéréo en mono et encode en mono.
Le mixage est calculé comme la somme des canaux gauche et droit, atténuée de 6 dB.

Cette option n'est nécessaire que dans le cas d'une entrée PCM stéréo RAW (car LAME ne peut pas déterminer le nombre de canaux dans le fichier d'entrée). Pour encoder un fichier d'entrée PCM stéréo RAW en mono, utilisez lame -a -m m

Pour les fichiers d'entrée WAV et AIFF, l'utilisation de -m m produira toujours un fichier .mp3 mono à partir d'entrées mono et stéréo.

--freeformat
Produit un flux binaire de format libre. Avec cette option, vous pouvez utiliser -b avec n'importe quel débit binaire supérieur à 8 kbps.

Cependant, même si un décodeur mp3 est requis pour prendre en charge les débits libres au moins jusqu'à 320 kbps, de nombreux lecteurs ne peuvent pas le gérer.

Les tests ont montré que les décodeurs suivants prennent en charge le format libre :
in_mpg123 jusqu'à 560 kbps
l3dec jusqu'à 310 kbps
LAME jusqu'à 640 kbps
MAD jusqu'à 640 kbps

--decode
Utilise LAME pour décoder vers un fichier wav. Le fichier d'entrée peut être de n'importe quel type d'entrée pris en charge par l'encodage, y compris les fichiers de couche II. LAME utilise un fork de

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

mpg123 connu sous le nom de HIP pour le décodage.

Si -t est utilisé (désactiver l'en-tête wav), LAME produira du pcm brut dans le format natif de boutisme. Vous pouvez utiliser -x pour inverser l'ordre des octets.

Cette option n'est pas utilisable si le décodeur MP3 a été explicitement désactivé lors de la compilation de LAME.

-t
Désactiver l'écriture de la balise INFO lors de l'encodage.
Cette balise est intégrée dans la trame 0 du fichier MP3. Elle contient des informations sur les options d'encodage du fichier, et en mode VBR, elle permet aux lecteurs compatibles VBR de rechercher et de calculer correctement la durée de lecture des fichiers VBR.

Lorsque --decode est spécifié (décode en WAV), ce drapeau désactivera l'écriture de l'en-tête WAV. La sortie sera du pcm brut, au format natif de boutisme. Utilisez -x pour inverser les octets.

--comp arg
Au lieu de choisir le débit binaire, en utilisant cette option, l'utilisateur peut choisir le ratio de compression à atteindre.
--scale n
--scale-l n
--scale-r n
Mets à l'échelle l'entrée (tous les canaux, seulement le canal gauche ou seulement le canal droit) par n. Cela multiplie simplement les données PCM (après leur conversion en virgule flottante) par n.

n > 1 : augmenter le volume
n = 1 : pas d'effet
n < 1 : réduire le volume

Utiliser avec précaution, car la plupart des décodeurs MP3 tronqueront les données qui se décodent en valeurs supérieures à 32768.

--replaygain-fast
Calculer ReplayGain rapidement mais de manière légèrement imprécise.

Cela calcule le ReplayGain "Radio" sur le flux de données d'entrée après le volume spécifié par l'utilisateur et/ou le rééchantillonnage.

L'analyse ReplayGain n'affecte pas le contenu d'un flux de données compressé en soi, c'est une valeur stockée dans l'en-tête d'un fichier son. Des informations sur le but de ReplayGain et les algorithmes utilisés sont disponibles sur http://www.replaygain.org/.

Seule la valeur ReplayGain "RadioGain" est calculée, elle est stockée dans la balise LAME. L'analyse est effectuée avec le volume de référence égal à 89dB. Note : le volume de référence a été changé de 83dB lors du passage de la version 3.95 à 3.95.1.

Ce commutateur est activé par défaut.

Voir aussi : --replaygain-accurate, --noreplaygain

--replaygain-accurate
Calculer ReplayGain plus précisément et trouver l'échantillon de crête.

Cela calcule le ReplayGain "Radio" sur le flux de données décodé, trouve l'échantillon de crête en décodant à la volée le flux de données encodé et le stocke dans le fichier.

L'analyse ReplayGain n'affecte pas le contenu d'un flux de données compressé en soi, c'est une valeur stockée dans l'en-tête d'un fichier son. Des informations sur le but de ReplayGain et les algorithmes utilisés sont disponibles sur http://www.replaygain.org/.

Par défaut, LAME effectue une analyse ReplayGain sur les données d'entrée (après la mise à l'échelle du volume spécifiée par l'utilisateur). Ce comportement peut donner des résultats légèrement imprécis car les données à la sortie d'une séquence de compression/décompression avec perte diffèrent des données d'entrée initiales. Lorsque --replaygain-accurate est spécifié, le flux mp3 est décodé à la volée et l'analyse est effectuée sur le flux de données décodé. Bien que théoriquement cette méthode donne des résultats plus précis, elle présente plusieurs inconvénients :

  • des tests ont montré que la différence entre les valeurs ReplayGain calculées sur les données d'entrée et les données décodées n'est généralement pas supérieure à 0,5 dB, bien que la différence de volume minimale perceptible par l'oreille humaine soit d'environ 1,0 dB
  • le décodage à la volée ralentit considérablement le processus d'encodage

L'avantage apparent est que :

*
avec --replaygain-accurate, l'échantillon de crête réel est déterminé et stocké dans le fichier. La connaissance de l'échantillon de crête peut être utile aux décodeurs (lecteurs) pour éviter un effet négatif appelé 'clipping' qui introduit une distorsion dans le son.

Seule la valeur ReplayGain "RadioGain" est calculée, elle est stockée dans la balise LAME. L'analyse est effectuée avec le volume de référence égal à 89dB. Note : le volume de référence a été changé de 83dB lors du passage de la version 3.95 à 3.95.1.

Cette option n'est pas utilisable si le décodeur MP3 a été explicitement désactivé lors de la compilation de LAME. (Note : si LAME est compilé sans le décodeur MP3, l'analyse ReplayGain est effectuée sur les données d'entrée après la mise à l'échelle du volume spécifiée par l'utilisateur).

Voir aussi : --replaygain-fast, --noreplaygain --clipdetect

--noreplaygain
Désactiver l'analyse ReplayGain.

Par défaut, l'analyse ReplayGain est activée. Ce commutateur la désactive.

Voir aussi : --replaygain-fast, --replaygain-accurate

--clipdetect
Détection de clipping.

Active --replaygain-accurate et affiche un message indiquant si un clipping se produit et de combien de dB la forme d'onde est loin de l'échelle complète.

Cette option n'est pas utilisable si le décodeur MP3 a été explicitement désactivé lors de la compilation de LAME.

Voir aussi : --replaygain-accurate

--preset type | [cbr] kbps
Utiliser l'un des préréglages intégrés.

Consultez la section PRESETS ci-dessous.

--preset help donne plus d'informations sur les options utilisées dans ces préréglages.

--noasm type
Désactiver des optimisations spécifiques en assembleur ( mmx / 3dnow / sse ). La qualité n'augmentera pas, seule la vitesse sera réduite. Si vous avez des problèmes pour exécuter Lame sur un processeur Cyrix/Via, désactiver les optimisations mmx pourrait résoudre votre problème.

Algorithmes de mise en forme du bruit et psycho-acoustiques :

-q qual
0 <= qual <= 9

Le débit binaire est bien sûr le principal facteur influençant la qualité. Plus le débit binaire est élevé, plus la qualité est élevée. Mais pour un débit binaire donné, nous avons le choix entre plusieurs algorithmes pour déterminer les meilleurs facteurs d'échelle et le codage Huffman (mise en forme du bruit).

Pour CBR et ABR, le tableau suivant s'applique :

-q 0 :
Utiliser les meilleurs algorithmes (meilleure recherche de codage Huffman, boucle externe complète, et la plus haute précision de plusieurs paramètres).

-q 1 à q 4 :
Similaire à -q 0 sans la boucle externe complète et précision décroissante des paramètres à mesure que l'on s'éloigne de q0. -q 3 est la valeur par défaut.

-q 5 et -q 6 :
Identique à -q 7, mais active la mise en forme du bruit et augmente le gain des sous-blocs

-q 7 à -q 9 :
Identique à -f. Très rapide, qualité acceptable. La psycho-acoustique est utilisée pour le pré-écho et la stéréo milieu/côté, mais aucune mise en forme du bruit n'est effectuée.

Pour le mode VBR par défaut depuis LAME 3.98, le tableau suivant s'applique :

-q 0 à -q 4 :
incluent toutes les fonctionnalités des autres modes et utilisent en plus la meilleure recherche lors de l'application du codage Huffman.

-q 5 et -q 6 :
incluent toutes les fonctionnalités de -q7, calculent et prennent en compte le bruit de quantification réel, et activent en plus le gain des sous-blocs.

-q 7 à -q 9
Ce niveau utilise un modèle psychologique mais ne calcule pas le bruit de quantification lors de l'encodage : il fait une estimation rapide.

-h
Alias de -q 2
-f
Alias de -q 7

Options CBR (débit binaire constant, par défaut) :

-b n
Pour MPEG-1 (fréquences d'échantillonnage de 32, 44,1 et 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Pour MPEG-2 (fréquences d'échantillonnage de 16, 22,05 et 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Pour MPEG-2.5 (fréquences d'échantillonnage de 8, 11,025 et 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

Par défaut, 128 pour MPEG1 et 64 pour MPEG2 et 32 pour MPEG2.5
(64, 32 et 16 respectivement en cas de mono).

--cbr
forcer l'utilisation du débit binaire constant. Utilisé pour désactiver l'encodage VBR ou ABR même si leurs paramètres sont activés.

Options ABR (débit binaire moyen) :

--abr n
Active l'encodage avec un débit binaire moyen cible de n kbits, permettant d'utiliser des trames de différentes tailles. La plage autorisée pour n est de 8 à 310, vous pouvez utiliser n'importe quelle valeur entière dans cette plage.

Il peut être combiné avec les commutateurs -b et -B comme : lame --abr 123 -b 64 -B 192 a.wav a.mp3 ce qui limiterait les tailles de trames autorisées entre 64 et 192 kbits.

L'utilisation de -B N'EST PAS RECOMMANDÉ. Un flux binaire CBR de 128 kbps, en raison du réservoir de bits, peut en fait avoir des trames qui utilisent autant de bits qu'une trame de 320 kbps. Les modes VBR minimisent l'utilisation du réservoir de bits et doivent donc autoriser les trames de 320 kbps pour obtenir la même flexibilité que les flux CBR.

Options VBR (débit binaire variable) :

-v
utiliser le débit binaire variable (--vbr-new)
--vbr-old
Invoque l'algorithme VBR le plus ancien et le plus testé. Il produit des fichiers de très bonne qualité, bien qu'il ne soit pas très rapide. Jusqu'à la version v3.89, il était considéré comme l'algorithme VBR de « cheval de bataille ».
--vbr-new
Invoque le nouvel algorithme VBR. Lors du développement de la version 3.90, une optimisation considérable a été apportée à cet algorithme, et il est maintenant considéré comme égal à l'original --vbr-old. Il présente l'avantage supplémentaire d'être très rapide (plus de deux fois plus rapide que --vbr-old). C'est le défaut depuis la version 3.98.
-V n
0 <= n <= 9.999
Active le VBR (débit binaire variable) et spécifie la valeur de qualité VBR (défaut = 4). Des valeurs décimales peuvent être spécifiées, comme 4.51.
0 = qualité la plus élevée.

Options ABR et VBR :

-b débit
Pour MPEG-1 (fréquences d'échantillonnage de 32, 44,1 et 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Pour MPEG-2 (fréquences d'échantillonnage de 16, 22,05 et 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Pour MPEG-2.5 (fréquences d'échantillonnage de 8, 11,025 et 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

Spécifie le débit binaire minimum à utiliser. Cependant, afin d'éviter le gaspillage d'espace, la plus petite taille de trame disponible sera utilisée pendant les silences.

-B débit
Pour MPEG-1 (fréquences d'échantillonnage de 32, 44,1 et 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Pour MPEG-2 (fréquences d'échantillonnage de 16, 22,05 et 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Pour MPEG-2.5 (fréquences d'échantillonnage de 8, 11,025 et 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

Spécifie le débit binaire maximum autorisé.

Note : Si vous possédez un lecteur MP3 matériel basé sur une puce MAS 3503, vous devez régler le débit binaire maximum à pas plus de 224 kbps.

-F
Applique strictement l'option -b.
Ceci est principalement destiné aux lecteurs matériels qui ne prennent pas en charge les MP3 à faible débit binaire.

Sans cette option, le débit binaire minimum sera ignoré pour les passages de silence analogique, c'est-à-dire lorsque le niveau musical est en dessous du seuil absolu de l'audition humaine (ATH).

Options expérimentales :

-X n
0 <= n <= 7

Lorsque LAME recherche une « bonne » quantification, il doit comparer la quantification actuelle à la meilleure trouvée jusqu'à présent. La comparaison indique laquelle est la meilleure, celle trouvée jusqu'à présent ou celle actuelle. Le paramètre -X sélectionne entre différentes approches pour prendre cette décision, -X0 étant le mode par défaut :

-X0
Les critères sont (par ordre d'importance) :
* bandes de facteurs d'échelle moins distordues
* la somme du bruit au-dessus des seuils est plus faible
* le bruit total est plus faible

-X1
L'actuel est meilleur si le bruit maximum sur toutes les bandes de facteurs d'échelle est inférieur à celui de la meilleure trouvée jusqu'à présent.

-X2
L'actuel est meilleur si la somme totale du bruit est inférieure à celle de la meilleure trouvée jusqu'à présent.

-X3
L'actuel est meilleur si la somme totale du bruit est inférieure à celle de la meilleure trouvée jusqu'à présent et si le bruit maximum sur toutes les bandes de facteurs d'échelle est inférieur à celui de la meilleure trouvée jusqu'à présent plus 2 dB.

-X4
Pas encore documenté.

-X5
Les critères sont (par ordre d'importance) :
* la somme du bruit au-dessus des seuils est plus faible
* la somme totale du bruit est plus faible

-X6
Les critères sont (par ordre d'importance) :
* la somme du bruit au-dessus des seuils est plus faible
* le bruit maximum sur toutes les bandes de facteurs d'échelle est plus faible
* la somme totale du bruit est plus faible

-X7
Les critères sont :
* bandes de facteurs d'échelle moins distordues
ou
* la somme du bruit au-dessus des seuils est plus faible

-Y
permet à LAME d'ignorer le bruit dans sfb21, comme en CBR

Options d'en-tête/flux MP3 :

-e emp
emp = n, 5, c

n = (aucun, par défaut)
5 = 0/15 microsecondes
c = citt j.17

Tout ce que cela fait est de définir un indicateur dans le flux binaire. Si vous avez un fichier d'entrée PCM auquel l'un des types d'emphase (obsolètes) ci-dessus a été appliqué, vous pouvez définir cet indicateur dans LAME. Ensuite, le décodeur MP3 devrait dés-emphatiser la sortie lors de la lecture, bien que la plupart des décodeurs ignorent cet indicateur.

Une meilleure solution serait d'appliquer la dés-emphase à l'aide d'un utilitaire autonome avant l'encodage, puis d'encoder sans -e.

-c
Marquer le fichier encodé comme étant sous copyright.
-o
Marquer le fichier encodé comme étant une copie.
-p
Activer la protection contre les erreurs CRC.
Il ajoutera un code de contrôle de redondance cyclique (CRC) dans chaque trame, permettant de détecter les erreurs de transmission qui pourraient survenir sur le flux MP3. Cependant, cela utilise 16 bits par trame qui seraient autrement utilisés pour l'encodage, et réduira alors légèrement la qualité sonore.
--nores
Désactive le réservoir de bits. Chaque trame deviendra alors indépendante des précédentes, mais la qualité sera moindre.
--strictly-enforce-ISO
Avec cette option, LAME appliquera la limitation de 7680 bits à la taille totale de la trame.
Cela entraîne un gaspillage de nombreux bits pour les encodages à haut débit binaire, mais garantira une compatibilité ISO stricte. Cette compatibilité pourrait être importante pour les lecteurs matériels.

Options de filtre :

--lowpass freq
Définit une fréquence de filtrage passe-bas en kHz. Les fréquences au-dessus de celle spécifiée seront coupées.
--lowpass-width freq
Définit la largeur du filtre passe-bas. La valeur par défaut est de 15 % de la fréquence passe-bas.
--highpass freq
Définit une fréquence de filtrage passe-haut en kHz. Les fréquences inférieures à celle spécifiée seront coupées.
--highpass-width freq
Définit la largeur du filtre passe-haut en kHz. La valeur par défaut est de 15 % de la fréquence passe-haut.
--resample sfreq

Sélectionne la fréquence d'échantillonnage de sortie (uniquement prise en charge pour l'encodage).
Si non spécifié, LAME rééchantillonnera automatiquement l'entrée lors de l'utilisation de rapports de compression élevés.

BALISES ID3

LAME est capable d'intégrer des balises ID3 v1, v1.1 ou v2 dans le fichier MP3 encodé. Cela permet d'inclure des informations utiles sur la piste musicale dans le fichier. Ces données peuvent être lues par la plupart des lecteurs MP3.

Lame choisira intelligemment les balises à utiliser. Il ajoutera des balises ID3 v2 uniquement si les commentaires d'entrée ne tiennent pas dans les balises v1 ou v1.1, c'est-à-dire s'ils dépassent 30 caractères. Dans ce cas, les balises v1 et v2 seront ajoutées, afin de garantir la lecture des balises par les lecteurs MP3 qui ne peuvent pas lire les balises ID3 v2.

MODES D'ENCODAGE

LAME est capable d'encoder votre musique en utilisant l'un de ses 3 modes d'encodage : débit constant (CBR), débit moyen (ABR) et débit variable (VBR).

Débit Constant (CBR)
C'est le mode d'encodage par défaut, et aussi le plus basique. Dans ce mode, le débit sera le même pour l'ensemble du fichier. Cela signifie que chaque partie de votre fichier mp3 utilisera le même nombre de bits. Que le passage musical soit difficile ou facile à encoder, l'encodeur utilisera le même débit, donc la qualité de votre mp3 est variable. Les parties complexes seront de qualité inférieure à celles des plus faciles. Le principal avantage est que la taille finale du fichier ne changera pas et peut être prédite avec précision.
Débit Moyen (ABR)
Dans ce mode, vous choisissez que l'encodeur maintiendra un débit moyen tout en utilisant des débits plus élevés pour les parties de votre musique qui nécessitent plus de bits. Le résultat sera de meilleure qualité que l'encodage CBR, mais la taille moyenne du fichier restera prévisible, ce mode est donc fortement recommandé par rapport au CBR. Ce mode d'encodage est similaire à ce qui est appelé vbr dans AAC ou Liquid Audio (2 autres technologies de compression).
Débit Variable (VBR)
Dans ce mode, vous choisissez la qualité souhaitée sur une échelle de 9 (qualité la plus basse / distorsion la plus élevée) à 0 (qualité la plus haute / distorsion la plus basse). L'encodeur essaie ensuite de maintenir la qualité donnée dans l'ensemble du fichier en choisissant le nombre optimal de bits à dépenser pour chaque partie de votre musique. L'avantage principal est que vous pouvez spécifier le niveau de qualité que vous souhaitez atteindre, mais l'inconvénient est que la taille finale du fichier est totalement imprévisible.

PRÉRÉGLAGES

Les commutateurs --preset sont des alias pour les paramètres de LAME.

Pour activer ces préréglages :

Pour les modes VBR (généralement la meilleure qualité) :

--preset medium
Ce préréglage devrait fournir une transparence quasi totale à la plupart des gens sur la plupart des musiques.
--preset standard
Ce préréglage devrait généralement être transparent pour la plupart des gens sur la plupart des musiques et est déjà d'une qualité assez élevée.
--preset extreme
Si vous avez une ouïe extrêmement fine et un équipement similaire, ce préréglage fournira généralement une qualité légèrement supérieure au mode standard.

Pour CBR 320 kbps (la meilleure qualité possible avec les commutateurs --preset) :

--preset insane
Ce préréglage sera généralement excessif pour la plupart des gens et la plupart des situations, mais si vous voulez la qualité la plus élevée possible sans vous soucier de la taille du fichier, c'est la voie à suivre.

Pour les modes ABR (haute qualité par débit donné, mais pas aussi élevée que VBR) :

--preset kbps
L'utilisation de ce préréglage vous donnera généralement une bonne qualité à un débit spécifié. En fonction du débit saisi, ce préréglage déterminera les paramètres optimaux pour cette situation particulière. Bien que cette approche fonctionne, elle n'est pas aussi flexible que le VBR et n'atteint généralement pas le même niveau de qualité que le VBR à des débits plus élevés.
cbr
Si vous utilisez le mode ABR (voir ci-dessus) avec un débit significatif tel que 80, 96, 112, 128, 160, 192, 224, 256, 320, vous pouvez utiliser l'option --preset cbr kbps pour forcer l'encodage en mode CBR au lieu du mode ABR standard. L'ABR offre une meilleure qualité, mais le CBR peut être utile dans des situations où la diffusion en continu d'un MP3 sur Internet peut être importante.

EXEMPLES

Encodage stéréo conjoint à débit fixe de 128 kbs :

lame -b 128 sample.wav sample.mp3

Encodage stéréo conjoint à débit fixe de 128 kbps, qualité maximale :

lame -q 0 -b 128 sample.wav sample.mp3

Pour désactiver l'encodage stéréo conjoint (légèrement plus rapide, mais moins de qualité aux débits ≤ 128 kbps) :

lame -m s sample.wav sample.mp3

Débit variable (utiliser -V n pour ajuster la qualité/taille du fichier) :

lame -V 2 sample.wav sample.mp3

Diffusion en continu de PCM brut mono 22,05 kHz, sortie 24 kbps :

cat inputfile | lame -r -m m -b 24 -s 22.05 - - > output

Diffusion en continu de PCM brut mono 44,1 kHz, avec rééchantillonnage à 22,05 kHz :

cat inputfile | lame -r -m m -b 24 --resample 22.05 - - > output

Encoder avec le préréglage standard :

lame --preset standard sample.wav sample.mp3
