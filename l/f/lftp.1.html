lftp(1) Manuel des commandes générales lftp(1)

NOM

lftp - Programme sophistiqué de transfert de fichiers

SYNTAXE

lftp [-d] [-e commande] [-p port] [-u utilisateur[,motdepasse]] [site]
lftp -f fichier_script
lftp -c commandes
lftp --version
lftp --help

VERSION

Cette page de manuel documente la version 4.8.1 de lftp.

DESCRIPTION

lftp est un programme de transfert de fichiers qui permet des connexions sophistiquées via FTP, HTTP et autres vers d'autres hôtes. Si site est spécifié, lftp se connectera à ce site, sinon une connexion doit être établie avec la commande open.

lftp peut gérer plusieurs méthodes d'accès aux fichiers : FTP, FTPS, HTTP, HTTPS, HFTP, FISH, SFTP et fichier (HTTPS et FTPS ne sont disponibles que lorsque lftp est compilé avec la bibliothèque GNU TLS ou OpenSSL). Vous pouvez spécifier la méthode à utiliser dans la commande `open URL', par exemple `open http://www.us.kernel.org/pub/linux'. HFTP est le protocole ftp-over-http-proxy. Il peut être utilisé automatiquement à la place de FTP si ftp:proxy est défini sur `http://proxy[:port]'. Fish est un protocole fonctionnant sur une connexion ssh vers un compte unix. SFtp est un protocole implémenté dans SSH2 en tant que sous-système SFTP.

Outre les protocoles de type FTP, lftp prend en charge le protocole BitTorrent via la commande `torrent'. L'ensemencement (seeding) est également pris en charge.

Chaque opération dans lftp est fiable, c'est-à-dire que toute erreur non fatale est correctement gérée et l'opération est répétée. Ainsi, si un téléchargement est interrompu, il reprendra automatiquement à partir du point où il s'est arrêté. Même si le serveur FTP ne prend pas en charge la commande REST, lftp essaiera de récupérer le fichier depuis le début jusqu'à ce que le fichier soit complètement transféré.

lftp possède une syntaxe de commande de type shell vous permettant de lancer plusieurs commandes en parallèle en arrière-plan (&). Il est également possible de grouper des commandes entre () et de les exécuter en arrière-plan. Tous les travaux en arrière-plan sont exécutés dans le même processus unique. Vous pouvez mettre un travail au premier plan en arrière-plan avec ^Z (c-z) et le ramener avec la commande `wait' (ou `fg' qui est un alias pour `wait'). Pour lister les travaux en cours, utilisez la commande `jobs'. Certaines commandes permettent de rediriger leur sortie (cat, ls, ...) vers un fichier ou via un pipe vers une commande externe. Les commandes peuvent être exécutées conditionnellement en fonction de l'état de terminaison de la commande précédente (&&, ||).

Si vous quittez lftp avant que tous les travaux ne soient terminés, lftp se déplacera en mode nohup en arrière-plan. La même chose se produit avec une vraie déconnexion modem ou lorsque vous fermez un xterm.

lftp dispose d'une fonction miroir intégrée qui peut télécharger ou mettre à jour un arbre de répertoires complet. Il existe également un miroir inverse (mirror -R) qui télécharge ou met à jour un arbre de répertoires sur le serveur. Miroir peut également synchroniser des répertoires entre deux serveurs distants, en utilisant FXP si disponible.

Il existe la commande `at' pour lancer un travail à une heure spécifiée dans le contexte actuel, la commande `queue' pour mettre en file d'attente des commandes pour exécution séquentielle pour le serveur actuel, et bien plus encore.

Au démarrage, lftp exécute /etc/lftp.conf puis ~/.lftprc et ~/.lftp/rc (ou ~/.config/lftp/rc si ~/.lftp n'existe pas). Vous pouvez y placer des alias et des commandes `set'. Certaines personnes préfèrent voir le débogage complet du protocole, utilisez `debug' pour activer le débogage. Utilisez `debug 3' pour voir uniquement les messages d'accueil et les messages d'erreur.

lftp a un certain nombre de variables configurables. Vous pouvez utiliser `set -a' pour voir toutes les variables et leurs valeurs ou `set -d' pour voir la liste des valeurs par défaut. Les noms de variables peuvent être abrogés et le préfixe peut être omis tant que le reste ne devient pas ambigu.

Si lftp a été compilé avec OpenSSL (configure --with-openssl), il inclut des logiciels développés par le projet OpenSSL pour une utilisation dans la boîte à outils OpenSSL. (http://www.openssl.org/)

Ferme les connexions inactives. Par défaut uniquement avec le serveur actuel, utilisez -a pour fermer toutes les connexions inactives.

`cls' essaie de récupérer des informations sur les fichiers ou répertoires spécifiés et affiche les informations selon les options de format. La différence entre `ls' et `cls' est que `ls' demande au serveur de formater la liste des fichiers, et `cls' la formate lui-même, après avoir récupéré toutes les informations nécessaires.

exit [bg] [top] [parent] [kill] [code]

exit quittera lftp ou le déplacera en arrière-plan s'il y a des tâches actives. S'il n'y a pas de tâche active, code sera passé au système d'exploitation comme statut de terminaison de lftp. Si code est omis, le code de sortie de la dernière commande sera utilisé.

`exit bg' force le déplacement en arrière-plan lorsque cmd:move-background est faux. `exit top' fait se terminer le "shell" de plus haut niveau (l'exécuteur de commandes internes de lftp). `exit parent' termine le shell parent lors de l'exécution d'un script imbriqué. `exit kill' tue toutes les tâches numérotées avant de se terminer. Les options peuvent être combinées, par exemple `at 08:00 -- exit top kill &' tue toutes les tâches et fait quitter lftp à l'heure spécifiée.

get [-E] [-a] [-c] [-e] [-P N] [-O base] rfile [-o lfile] ...

Récupère le fichier distant rfile et le stocke sous le nom de fichier local lfile. Si -o est omis, le fichier est stocké sous le nom de fichier local correspondant au nom de base de rfile. -E supprimer les fichiers sources après un transfert réussi

-a utiliser le mode ascii (binaire est le mode par défaut)

mirror [OPTS] [source [cible]]

Miroir du répertoire source spécifié vers le répertoire cible.

Par défaut, la source est distante et la cible est un répertoire local. Lors de l'utilisation de -R, le répertoire source est local et la cible est distante. Si le répertoire cible est omis, le nom de base du répertoire source est utilisé. Si les deux répertoires sont omis, les répertoires locaux et distants courants sont utilisés.

La source et/ou la cible peuvent être des URL pointant vers des répertoires.

Si le répertoire cible se termine par un slash (sauf pour le répertoire racine), le nom de base du répertoire source est ajouté.

RX est une expression régulière étendue, comme dans egrep(1).

GP est un modèle glob, par exemple `*.zip'.

Les options d'inclusion et d'exclusion peuvent être spécifiées plusieurs fois. Cela signifie qu'un fichier ou un répertoire sera mis en miroir s'il correspond à une inclusion et ne correspond pas aux exclusions après l'inclusion, ou s'il ne correspond à rien et que la première vérification est une exclusion. Les répertoires sont identifiés par un slash ajouté.

Notez que les liens symboliques ne sont pas créés lors du téléchargement vers un serveur distant, car le protocole FTP ne le permet pas. Pour télécharger les fichiers auxquels les liens font référence, utilisez la commande `mirror -RL' (traiter les liens symboliques comme des fichiers).

Pour les options --newer-than et --older-than, vous pouvez soit spécifier un fichier local, soit une spécification de temps telle qu'utilisée par la commande at(1), par exemple `now-7days' ou `week ago'. Si vous spécifiez un fichier, la date de modification de ce fichier sera utilisée.

Le niveau de verbosité peut être sélectionné à l'aide de l'option --verbose=level ou par plusieurs options -v, par exemple -vvv. Les niveaux sont :

0 - pas de sortie (par défaut)
1 - afficher les actions
2 - +afficher les noms de fichiers non supprimés (lorsque -e n'est pas spécifié)
3 - +afficher les noms de répertoires qui sont mis en miroir

--only-newer désactive la comparaison de taille de fichier et télécharge/télécharge uniquement les fichiers plus récents, même si la taille est différente. Par défaut, les anciens fichiers sont transférés et remplacent les plus récents.

--upload-older permet de remplacer les fichiers distants plus récents par des plus anciens (lorsque le côté cible est distant). Certains back-ends distants ne peuvent pas conserver les horodatages, donc par défaut, les fichiers les plus récents sont conservés.

Le mode de récursion peut être `always', `never', `missing', `newer'. Avec l'option `newer', mirror compare les horodatages des répertoires et n'entre dans un répertoire que s'il est plus ancien ou manquant sur le côté cible. Sachez que lorsqu'un fichier change, l'horodatage du répertoire peut rester le même, donc mirror ne traitera pas ce répertoire.

Les options --file et --directory peuvent être utilisées plusieurs fois et même mélangées, à condition que les répertoires de base des chemins soient les mêmes.

Vous pouvez mettre en miroir entre deux serveurs si vous spécifiez des URL au lieu de répertoires. FXP est automatiquement utilisé pour les transferts entre serveurs FTP, si possible.

Certains serveurs FTP masquent les fichiers pointés par défaut (par exemple .htaccess) et ne les montrent que lorsque la commande LIST est utilisée avec l'option -a. Dans ce cas, essayez d'utiliser `set ftp:list-options -a'.

Les modes de récursion `newer' et `missing' entrent en conflit avec --scan-all-first, --depth-first, --no-empty-dirs et le réglage de mirror:no-empty-dirs=true.

mkdir [-p] [-f] dir(s)

queue [-n num ] cmd

Ajoute la commande donnée à la file d'attente pour une exécution séquentielle. Chaque site a sa propre file d'attente. `-n' ajoute la commande avant l'élément spécifié dans la file d'attente. N'essayez pas de mettre en file d'attente les commandes `cd' ou `lcd', cela pourrait confondre lftp. Faites plutôt le cd/lcd avant la commande `queue', et elle se souviendra de l'endroit où la commande doit être exécutée. Il est possible de mettre en file d'attente un travail déjà en cours en utilisant `queue wait <jobno>', mais le travail continuera son exécution même s'il n'est pas le premier dans la file d'attente.

`queue stop' arrêtera la file d'attente, elle n'exécutera aucune nouvelle commande, mais les travaux déjà en cours continueront de s'exécuter. Vous pouvez utiliser `queue stop' pour créer une file d'attente vide et arrêtée. `queue start' reprendra l'exécution de la file d'attente. Lorsque vous quitterez lftp, il démarrera automatiquement toutes les files d'attente arrêtées.

`queue' sans arguments créera une file d'attente arrêtée ou affichera l'état de la file d'attente.

queue --delete|-d [index ou expression wildcard]

Supprime un ou plusieurs éléments de la file d'attente. Si aucun argument n'est donné, le dernier élément de la file d'attente est supprimé.

queue --move|-m <index ou expression wildcard> [index]

Déplace les éléments donnés avant l'index de file d'attente donné, ou à la fin si aucune destination n'est donnée.

-q Être silencieux.
-v Être verbeux.
-Q Sortie dans un format qui peut être utilisé pour remettre en file d'attente. Utile avec --delete.

Exemples :

> get file &
[1] get file
> queue wait 1
> queue get another_file
> cd a_directory
> queue get yet_another_file
queue -d 3 Supprime le troisième élément de la file d'attente.
queue -m 6 4 Déplace le sixième élément de la file d'attente avant le quatrième.
queue -m "get*zip" 1 Déplace toutes les commandes correspondant à "get*zip" au début de la file d'attente. (L'ordre des éléments est préservé.)
queue -d "get*zip" Supprime toutes les commandes correspondant à "get*zip".

quote cmd

Pour FTP - envoie la commande sans interprétation. À utiliser avec précaution - cela peut conduire à un état distant inconnu et donc provoquer une reconnexion. Vous ne pouvez pas être sûr qu'un changement d'état distant dû à une commande citée soit solide - il peut être réinitialisé par une reconnexion à tout moment.

Pour HTTP - spécifique à l'action HTTP. Syntaxe : ``quote <commande> [<arguments>]''. La commande peut être ``set-cookie'' ou ``post''.

open http://www.site.net
quote set-cookie "variable=valeur; autre_variable=autre_valeur"
set http:post-content-type application/x-www-form-urlencoded
quote post /cgi-bin/script.cgi "var=valeur&othervar=othervalue" > fichier_local

Pour FISH - envoie la commande sans interprétation. Ceci peut être utilisé pour exécuter des commandes arbitraires sur le serveur. La commande ne doit pas prendre d'entrée ni imprimer ### au début d'une nouvelle ligne. Sinon, le protocole perdra sa synchronisation.

Le nom d'une variable peut être abrégé tant qu'il ne devient pas ambigu. Le préfixe avant `:' peut également être omis. Vous pouvez définir une variable plusieurs fois pour différentes fermetures, et ainsi obtenir des réglages particuliers pour un état particulier. La fermeture doit être spécifiée après le nom de la variable séparé par un slash /.

La fermeture pour les variables de domaine `dns:', `net:', `ftp:', `http:', `hftp:' est actuellement juste le nom d'hôte tel que spécifié dans la commande `open' (avec quelques exceptions où la fermeture n'a pas de sens, par exemple dns:cache-size). Pour certaines variables du domaine `cmd:', la fermeture est l'URL actuelle sans le chemin. Pour les variables du domaine `log:', la fermeture est soit `debug' soit `xfer'. Pour les autres variables, elle n'est pas actuellement utilisée. Voir les exemples dans le fichier lftp.conf.

Certaines commandes et réglages acceptent un paramètre d'intervalle de temps. Il a le format Nx[Nx...], où N est la quantité de temps (point flottant) et x est l'unité de temps : d - jours, h - heures, m - minutes, s - secondes. L'unité par défaut est la seconde. Par exemple, 5h30m ou 5.5h. L'intervalle peut aussi être `infinity', `inf', `never', `forever' - cela signifie un intervalle infini. Par exemple, `sleep forever' ou `set dns:cache-expire never'.

Les réglages booléens peuvent être l'un des (vrai, on, yes, 1, +) pour une valeur Vraie ou l'un des (faux, off, no, 0, -) pour une valeur Fausse.

Les réglages tri-booléens ont soit une valeur booléenne, soit `auto'.

Les réglages entiers peuvent avoir un suffixe : k - kibi, m - mebi, g - gigi, etc. Ils peuvent aussi avoir un préfixe : 0 - octal, 0x - hexadécimal.

Mode asynchrone FTP (pipelining)

Lftp peut accélérer les opérations FTP en envoyant plusieurs commandes à la fois, puis en vérifiant toutes les réponses. Voir la variable ftp:sync-mode. Parfois, cela ne fonctionne pas, donc le mode synchrone est la valeur par défaut. Vous pouvez essayer de désactiver le mode synchrone et de voir si cela fonctionne pour vous. Il est connu que certains logiciels réseau traitant la traduction d'adresses fonctionnent incorrectement dans le cas de plusieurs commandes FTP dans un seul paquet réseau.

RFC959 dit : ``L'utilisateur-processus envoyant une autre commande avant la réponse d'achèvement serait en violation du protocole ; mais les processus serveur-FTP devraient mettre en file d'attente toute commande qui arrive pendant qu'une commande précédente est en cours''. De plus, RFC1123 dit : ``Les implémenteurs NE DOIVENT PAS supposer de correspondance entre les limites de lecture sur la connexion de contrôle et les séquences EOL de Telnet (CR LF).'' et ``une seule lecture depuis la connexion de contrôle peut inclure plus d'une commande FTP''.

Il doit donc être sûr d'envoyer plusieurs commandes à la fois, ce qui accélère considérablement l'opération et semble fonctionner avec tous les serveurs ftp basés sur Unix et VMS. Malheureusement, les serveurs basés sur Windows ne peuvent souvent pas gérer plusieurs commandes dans un seul paquet, tout comme certains routeurs défectueux.

OPTIONS

-d
Activer le mode de débogage.
-e commandes
Exécuter les commandes données et ne pas quitter.
-p port
Utiliser le port donné pour se connecter.
-u utilisateur[,motdepasse]
Utiliser le nom d'utilisateur et le mot de passe donnés pour se connecter. N'oubliez pas de citer correctement le mot de passe dans le shell. Notez également qu'il n'est pas sécurisé de spécifier le mot de passe sur la ligne de commande, utilisez le fichier ~/.netrc ou la variable d'environnement LFTP_PASSWORD avec l'option --env-password. Alternativement, vous pouvez utiliser des protocoles basés sur SSH avec des clés autorisées, de sorte que vous n'avez pas à entrer de mot de passe.
--norc
Ne pas exécuter les fichiers rc du répertoire personnel.
--rcfile fichier
Exécuter les commandes du fichier. Peut être spécifié plusieurs fois.
-f fichier_script
Exécuter les commandes du fichier et quitter. Cette option doit être utilisée seule sans autres arguments (sauf --norc).
-c commandes
Exécuter les commandes données et quitter. Les commandes peuvent être séparées par un point-virgule, `&&' ou `||'. N'oubliez pas de citer correctement l'argument des commandes dans le shell. Cette option doit être utilisée seule sans autres arguments (sauf --norc).
D'autres options open peuvent également être données sur la ligne de commande lftp.
