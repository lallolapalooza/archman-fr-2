NOM

lf - gestionnaire de fichiers terminal

SYNTAXE

lf [-command commande] [-config chemin] [-cpuprofile chemin] [-doc] [-help] [-last-dir-path chemin] [-log chemin] [-memprofile chemin] [-print-last-dir] [-print-selection] [-remote commande] [-selection-path chemin] [-server] [-single] [-version] [chemin-cd-ou-selection]

DESCRIPTION

lf est un gestionnaire de fichiers terminal.

Le code source peut être trouvé dans le dépôt à https://github.com/gokcehan/lf

Cette documentation peut être lue depuis le terminal en utilisant lf -doc ou en ligne à https://github.com/gokcehan/lf/blob/master/doc.md Vous pouvez également utiliser la commande help (par défaut <f-1>) dans lf pour consulter la documentation dans un paginateur. Une page man avec le même contenu est également disponible dans le dépôt à https://github.com/gokcehan/lf/blob/master/lf.1

OPTIONS

ARGUMENTS POSITIONNELS

chemin-cd-ou-selection
Définit l'emplacement de départ. Si chemin est un répertoire, démarre là. S'il s'agit d'un fichier, démarre dans le répertoire parent du fichier et sélectionne le fichier. Lorsqu'aucun chemin n'est fourni, lf utilise le répertoire courant. N'accepte qu'un seul argument.

OPTIONS MÉTA

-doc
Affiche la documentation de lf (même contenu que ce fichier) et quitte.
-help
Affiche l'aide de la ligne de commande et quitte.
-version
Affiche les informations de version et quitte.

DÉMARRAGE & CONFIGURATION

-command commande
Exécute commande lors de l'initialisation du client (c'est-à-dire après la lecture de la configuration, avant on-init). Pour exécuter plus d'une commande, vous pouvez soit utiliser le drapeau -command plusieurs fois, soit passer plusieurs commandes en même temps en les chaînant avec ";".
-config chemin
Utilise le fichier de configuration à chemin au lieu des emplacements de recherche normaux. Cela n'affecte que le lfrc qui est lu au démarrage.

INTÉGRATION SHELL

-print-last-dir
Affiche le dernier répertoire sur la sortie standard lorsque lf se termine. Cela peut être utilisé pour laisser lf changer le répertoire de travail de votre shell. Voir CHANGEMENT DE RÉPERTOIRE pour plus de détails.
-last-dir-path chemin
Identique à -print-last-dir, mais écrit le répertoire dans chemin au lieu de la sortie standard.
-print-selection
Affiche les fichiers sélectionnés sur la sortie standard lors de l'ouverture d'un fichier dans lf. Cela peut être utilisé pour utiliser lf comme une boîte de dialogue "ouvrir un fichier". D'abord, sélectionnez les fichiers que vous voulez passer à un autre programme. Ensuite, confirmez la sélection en ouvrant un fichier. Cela provoque la sortie de lf et l'affichage de la sélection. Quitter lf prématurément abandonne la sélection.
-selection-path chemin
Identique à -print-selection, mais écrit la liste séparée par des nouvelles lignes dans chemin au lieu de la sortie standard.

SERVEUR

-remote commande
Envoie commande au serveur en cours d'exécution (par exemple send, query ou quit). Voir COMMANDES À DISTANCE pour plus de détails.
-server
Démarre le processus serveur (sans interface graphique) explicitement. S'exécute en avant-plan et écrit les logs du serveur sur stderr (ou le fichier défini avec -log). Les clients démarrent automatiquement un serveur si aucun n'est en cours d'exécution, sauf si -single est utilisé.
-single
Démarre un client autonome sans serveur. Désactive le contrôle à distance.

DIAGNOSTICS

-log chemin
Ajoute les messages de log d'exécution à chemin.
-cpuprofile chemin
Écrit un profil CPU dans chemin. Le profil peut être utilisé par go tool pprof.
-memprofile chemin
Écrit un profil mémoire dans chemin. Le profil peut être utilisé par go tool pprof.

EXEMPLES

Utiliser lf pour sélectionner des fichiers (en masquant certains types de fichiers) :

lf -command 'set nohidden' -command 'set hiddenfiles "*mp4:*pdf:*txt"' -print-selection

Une autre boîte de dialogue sophistiquée pour "ouvrir un fichier" axée sur le design :

lf -command 'set nopreview; set ratios 1; set drawbox; set promptfmt "Select files [%w] %S q: cancel, l: confirm"' -print-selection

Ouvrir Téléchargements et définir sortby et info sur la date de création :

lf -command 'set sortby btime; set info btime' ~/Downloads

Empêcher temporairement lf de modifier l'historique des commandes :

lf -command 'set nohistory'

Utiliser les paramètres par défaut et enregistrer la session actuelle : 

lf -config /dev/null -log /tmp/lf.log

Forcer la fermeture du serveur :

lf -remote 'quit!'

Hériter du répertoire de travail de lf dans votre shell :

cd "$(lf -print-last-dir)"

COMMANDES

Cette section montre des informations sur les commandes intégrées. Les commandes modales ne prennent aucun argument, mais changent plutôt le mode de fonctionnement pour lire leur entrée de manière pratique, et elles sont donc destinées à être attribuées à des raccourcis clavier.

quitter (par défaut q)

Quitte lf et retourne au shell.

haut (par défaut k et <haut>), moitié-haut (par défaut <c-u>), page-haut (par défaut <c-b> et <pgup>), défilement-haut (par défaut <c-y>), bas (par défaut j et <bas>), moitié-bas (par défaut <c-d>), page-bas (par défaut <c-f> et <pgdn>), défilement-bas (par défaut <c-e>)

Déplace/fait défiler la sélection de fichier actuelle vers le haut/bas d'une page entière/moitié de page/une ligne.

répertoire-parent (par défaut h et <gauche>)

Change le répertoire de travail actuel pour le répertoire parent.

ouvrir (par défaut l et <droite>)

Si le fichier actuel est un répertoire, alors change le répertoire actuel pour celui-ci, sinon, exécute la commande ouvrir. Une commande ouvrir par défaut est fournie pour appeler l'ouvreur système par défaut de manière asynchrone avec le fichier actuel comme argument. Une commande ouvrir personnalisée peut être définie pour remplacer cette valeur par défaut.

saut-suivant (par défaut ]), saut-précédent (par défaut [)

Change le répertoire de travail actuel vers l'élément suivant/précédent de la liste de sauts.

haut (par défaut gg et <début>), bas (par défaut G et <fin>)

Déplace la sélection de fichier actuelle vers le haut/bas du répertoire. Un nombre peut être spécifié pour se déplacer vers une ligne spécifique, par exemple, utilisez 3G pour vous déplacer vers la troisième ligne.

haut (par défaut H), milieu (par défaut M), bas (par défaut L)

Déplace la sélection de fichier actuelle vers le haut/milieu/bas de l'écran.

basculer

Bascule la sélection du fichier actuel ou des fichiers donnés en arguments.

inverser (par défaut v)

Inverse la sélection de tous les fichiers dans le répertoire actuel (c'est-à-dire bascule tous les fichiers). Les sélections dans d'autres répertoires ne sont pas affectées par cette commande. Vous pouvez définir une nouvelle commande pour sélectionner tous les fichiers du répertoire en combinant inverser avec désélectionner (c'est-à-dire cmd tout-sélectionner :désélectionner ; inverser), bien que cela supprime également les sélections dans d'autres répertoires.

désélectionner (par défaut u)

Supprime la sélection de tous les fichiers dans tous les répertoires.

sélectionner-glob, désélectionner-glob

Sélectionne/désélectionne les fichiers qui correspondent au glob donné.

copier (par défaut y)

Enregistre les chemins des fichiers sélectionnés dans le presse-papiers comme fichiers à copier. S'il n'y a pas de fichiers sélectionnés, le chemin du fichier actuel est utilisé à la place.

couper (par défaut d)

Enregistre les chemins des fichiers sélectionnés dans le presse-papiers comme fichiers à déplacer. S'il n'y a pas de fichiers sélectionnés, le chemin du fichier actuel est utilisé à la place.

coller (par défaut p)

Copie/déplace les fichiers du presse-papiers dans le répertoire de travail actuel. Une commande coller personnalisée peut être définie pour remplacer cette valeur par défaut.

effacer (par défaut c)

Efface les chemins de fichiers dans le presse-papiers.

synchroniser

Synchronise les fichiers copiés/coupés avec le serveur. Cette commande est automatiquement appelée lorsque nécessaire.

dessiner

Dessine l'écran. Cette commande est automatiquement appelée lorsque nécessaire.

redessiner (par défaut <c-l>)

Synchronise le terminal et redessine l'écran.

charger

Charge les fichiers et répertoires modifiés. Cette commande est automatiquement appelée lorsque nécessaire.

s="Ss" id='reload_(default_<span_class="Li">&lt;c-r&gt;</span>)'>recharger (défaut <c-r>)

Vider le cache et recharger tous les fichiers et répertoires.

supprimer (modal)

Supprimer le fichier courant ou les fichiers sélectionnés. Une commande supprimer personnalisée peut être définie pour remplacer ce défaut.

renommer (modal) (défaut r)

Renommer le fichier courant en utilisant la méthode intégrée. Une commande renommer personnalisée peut être définie pour remplacer ce défaut.

lire (modal) (défaut :)

Lire une commande à évaluer.

shell (modal) (défaut $)

Lire une commande shell à exécuter.

shell-pipe (modal) (défaut %)

Lire une commande shell à exécuter en redirigeant son entrée/sortie standard vers la barre de statut inférieure.

shell-wait (modal) (défaut !)

Lire une commande shell à exécuter et attendre une pression de touche à la fin.

shell-async (modal) (défaut &)

Lire une commande shell à exécuter de manière asynchrone sans entrée/sortie standard.

trouver (modal) (défaut f), trouver-arrière (modal) (défaut F), trouver-suivant (défaut ;), trouver-précédent (défaut ,)

Lire des touches pour trouver la correspondance de nom de fichier appropriée dans la direction avant/arrière et sauter à la correspondance suivante/précédente.

rechercher (défaut /), rechercher-arrière (défaut ?), rechercher-suivant (défaut n), rechercher-précédent (défaut N)

Lire un modèle pour rechercher une correspondance de nom de fichier dans la direction avant/arrière et sauter à la correspondance suivante/précédente.

filtrer (modal), définirfiltre

La commande filtrer lit un modèle pour filtrer et n'afficher que les fichiers correspondant au modèle. La commande définirfiltre fait de même mais utilise un argument pour définir le filtre immédiatement. Vous pouvez fournir un argument à filtrer pour l'utiliser comme invite de départ.

enregistrer-marque (modal) (défaut m)

Le caractère de troncature affiché à la fin lorsque le nom de fichier ne rentre pas dans le panneau.

truncatepct (int) (par défaut 100)

Lorsqu'un nom de fichier est trop long pour être affiché complètement, l'espace disponible sera divisé en deux parties. truncatepct est un pourcentage entre 0 et 100 qui détermine la taille de la première partie, qui sera affichée au début du nom de fichier. La deuxième partie utilise le reste de l'espace disponible et sera affichée à la fin du nom de fichier. Les deux parties sont séparées par le caractère de troncature (truncatechar). La troncature n'est pas appliquée à l'extension du fichier.

Par exemple, avec le nom de fichier très_long_nom_de_fichier.txt :

  • set truncatepct 100 -> très_long_nom_de~.txt (par défaut)
  • set truncatepct 50 -> très_lon~de_fichier.txt
  • set truncatepct 0 -> ~à_long_nom_de_fichier.txt

visualfmt (chaîne) (par défaut \033[7;36m)

Chaîne de format de l'indicateur pour les fichiers qui sont visuellement sélectionnés.

Chaîne affichée après les commandes de type shell-wait.

PRÉFIXES

Les préfixes de commande suivants sont utilisés par lf :

$  shell           commande shell
%  shell-pipe      commande shell exécutée avec l'interface utilisateur
!  shell-wait      commande shell attendant une pression de touche

Le même évaluateur est utilisé pour la ligne de commande et le fichier de configuration pour lire les commandes shell. La différence est que les préfixes ne sont pas nécessaires sur la ligne de commande. Au lieu de cela, différents modes sont fournis pour lire les commandes correspondantes. Ces modes sont mappés aux touches de préfixe ci-dessus par défaut. Les mappages en mode visuel sont définis de la même manière que les mappages en mode Normal.

SYNTAXE

Les caractères de # à la fin de ligne sont des commentaires et sont ignorés :

# les commentaires commencent par `#`

Les commandes suivantes (set, setlocal, map, nmap, vmap, cmap et cmd) sont utilisées pour la configuration.

Virgule

nd set est utilisé pour définir une option qui peut être un booléen, un entier ou une chaîne de caractères :

set hidden         # booléen activé
set hidden true    # booléen activé
set nohidden       # booléen désactivé
set hidden false   # booléen désactivé
set hidden!        # booléen basculer
set scrolloff 10   # valeur entière
set sortby time    # valeur chaîne sans guillemets
set sortby 'time'  # valeur chaîne avec des guillemets simples (espaces)
set sortby "time"  # valeur chaîne avec des guillemets doubles (échappements antislash)

La commande setlocal est utilisée pour définir une option locale pour un répertoire qui peut être un booléen ou une chaîne de caractères. Les options locales actuellement prises en charge sont dircounts, dirfirst, dironly, hidden, info, reverse et sortby. L'ajout d'un séparateur de chemin d'accès à la fin (par exemple, / pour Unix et \ pour Windows) définit l'option pour le répertoire donné ainsi que ses sous-répertoires :

setlocal /foo/bar hidden         # booléen activé
setlocal /foo/bar hidden true    # booléen activé
setlocal /foo/bar nohidden       # booléen désactivé
setlocal /foo/bar hidden false   # booléen désactivé
setlocal /foo/bar hidden!        # booléen basculer
setlocal /foo/bar sortby time    # valeur chaîne sans guillemets
setlocal /foo/bar sortby 'time'  # valeur chaîne avec des guillemets simples (espaces)
setlocal /foo/bar sortby "time"  # valeur chaîne avec des guillemets doubles (échappements antislash)
setlocal /foo/bar  hidden        # pour le répertoire '/foo/bar' uniquement
setlocal /foo/bar/ hidden        # pour '/foo/bar' et ses sous-répertoires (par exemple, '/foo/bar/baz')

La commande map est utilisée pour lier une touche en mode Normal et Visuel à une commande qui peut être une commande intégrée, une commande personnalisée ou une commande shell :

map gh cd ~        # commande intégrée
map D trash        # commande personnalisée
map i $less $f     # commande shell
map U !du -csh *   # commande shell en attente

La commande nmap fait la même chose mais uniquement en mode Normal.

La commande vmap fait la même chose mais uniquement en mode Visuel.

Aperçu des commandes de mappage qui fonctionnent dans chaque mode :

map                Normal, Visuel
nmap               Normal
vmap               Visuel
cmap               Ligne de commande

La commande cmap est utilisée pour lier une touche sur la ligne de commande à une commande de ligne de commande ou à toute autre commande :

cmap <c-g> cmd-escape
cmap <a-i> set incsearch!

Vous pouvez supprimer une liaison existante en laissant l'expression vide :

map gh             # supprime le mappage 'gh' en mode Normal et Visuel
nmap v             # supprime le mappage 'v' en mode Normal
vmap o             # supprime le mappage 'o' en mode Visuel
cmap <c-g>         # supprime le mappage '<c-g>'

La commande cmd est utilisée pour définir une commande personnalisée :

cmd usage $du -h -d1 | less

Vous pouvez supprimer une commande existante en laissant l'expression vide :

cmd trash          # supprime la commande 'trash'

S'il n'y a pas de préfixe, : est supposé :

map zt set info time

Un : explicite peut être fourni pour regrouper des instructions jusqu'à un retour à la ligne, ce qui est particulièrement utile pour les commandes map et cmd :

map st :set sortby time; set info time

Si vous avez besoin de plusieurs lignes, vous pouvez encapsuler les instructions dans {{ et }} après le préfixe approprié.

map st :{{
    set sortby time
    set info time
}}

MAPPAGES DE TOUCHE

Les touches normales sont assignées à une commande avec la syntaxe habituelle :

map a down

Les touches combinées avec la touche Majuscule utilisent simplement la lettre majuscule :

map A down

Les touches spéciales sont écrites entre les caractères < et > et utilisent toujours des lettres minuscules :

map <enter> down

Les crochets peuvent être assignés avec leurs noms spéciaux :

map <lt> down
map <gt> down

Les touches de fonction sont préfixées par le caractère f :

map <f-1> down

Les touches combinées avec la touche Ctrl sont préfixées par le caractère c :

map <c-a> down

Les touches combinées avec la touche Alt sont assignées de deux manières différentes selon le comportement de votre terminal. Les anciens terminaux (par exemple, xterm) peuvent régler le 8ème bit d'un caractère lorsque la touche Alt est enfoncée. Sur ces terminaux, vous pouvez utiliser l'octet correspondant pour le mappage :

map á down

Les nouveaux terminaux (par exemple, gnome-terminal) peuvent préfixer la touche par un caractère d'échappement lorsque la touche Alt est enfoncée. lf utilise le mécanisme de temporisation de l'échappement pour reconnaître les touches Alt sur ces terminaux (le délai est de 100 ms). Sur ces terminaux, les touches combinées avec la touche Alt sont préfixées par le caractère a :

map <a-a> down

Il est possible de combiner des touches spéciales avec des modificateurs :

map <a-enter> down

AVERTISSEMENT : Certaines combinaisons de touches seront probablement interceptées par votre système d'exploitation, votre gestionnaire de fenêtres ou votre terminal. D'autres combinaisons de touches ne peuvent pas être reconnues par lf en raison du fonctionnement des terminaux (par exemple, la combinaison Ctrl+h envoie une touche retour arrière à la place). Le moyen le plus simple de connaître le nom d'une combinaison de touches et si elle fonctionnera sur votre système est d'appuyer sur la touche pendant que lf est en cours d'exécution et de lire le nom dans l'erreur mapping inconnu.

Les boutons de la souris sont préfixés par le caractère m :

map <m-1> down  # primaire
map <m-2> down  # secondaire
map <m-3> down  # milieu
map <m-4> down
map <m-5> down
map <m-6> down
map <m-7> down
map <m-8> down

Les événements de la molette de la souris sont également préfixés par le caractère m :

map <m-up>    down
map <m-down>  down
map <m-left>  down
map <m-right> down

MAPPAGES PUSH

La manière habituelle de mapper une séquence de touches est de l'assigner à une commande nommée ou non nommée. Bien que cela offre un moyen propre de remapper les touches intégrées ainsi que d'autres commandes, cela peut parfois être limitant. Pour cette raison, la commande push est fournie par lf. Cette commande est utilisée pour simuler des appuis de touches donnés comme arguments. Vous pouvez mapper une touche à une commande push avec un argument pour créer diverses liaisons de touches.

Ceci est principalement utile à deux fins. Premièrement, il peut être utilisé pour mapper une commande avec un compte de commande :

map <c-j> push 10j

Deuxièmement, il peut être utilisé pour éviter de taper le nom lorsqu'une commande prend des arguments :

map r push :rename<space>

Il faut faire attention au fait que puisque la commande push fonctionne avec des touches au lieu de commandes, il est possible de créer accidentellement des liaisons récursives :

map j push 2j

Ces types de liaisons créent un interblocage lorsqu'elles sont exécutées.

COMMANDES SHELL

Les commandes shell régulières sont le type de commande le plus basique qui est utile à de nombreuses fins. Par exemple, nous pouvons écrire une commande shell pour déplacer le(s) fichier(s) sélectionné(s) vers la corbeille. Une première tentative d'écriture d'une telle commande pourrait ressembler à ceci :

cmd trash ${{
    mkdir -p ~/.trash
    if [ -z "$fs" ]; then
        mv "$f" ~/.trash
    else
        IFS="$(printf '\n\t')"; mv $fs ~/.trash
    fi
}}

Nous vérifions $fs pour voir s'il y a des fichiers sélectionnés. Sinon, nous supprimons simplement le fichier courant. Comme il s'agit d'un schéma très courant, une variable distincte $fx est fournie. Nous pouvons utiliser cette variable pour supprimer la condition :

cmd trash ${{
    mkdir -p ~/.trash
    IFS="$(printf '\n\t')"; mv $fx ~/.trash
}}

Le répertoire de la corbeille est vérifié à chaque exécution de la commande. Nous pouvons le déplacer en dehors de la commande afin qu'il ne s'exécute qu'une seule fois au démarrage :

${{ mkdir -p ~/.trash }}
cmd trash ${{ IFS="$(printf '\n\t')"; mv $fx ~/.trash }}

Comme il s'agit de lignes uniques, nous pouvons supprimer {{ et }} :

$mkdir -p ~/.trash
cmd trash $IFS="$(printf '\n\t')"; mv $fx ~/.trash

Enfin, notez que nous définissons manuellement la variable IFS dans ces commandes. Au lieu de cela, nous pourrions utiliser l'option ifs pour la définir pour toutes les commandes shell (c'est-à-dire set ifs "\n"). Cela peut être particulièrement utile pour une utilisation interactive (par exemple, $rm $f ou $rm $fs fonctionneraient simplement). Cette option n'est pas définie par défaut car elle peut avoir un comportement inattendu pour les nouveaux utilisateurs. Cependant, l'utilisation de cette option est fortement recommandée et elle est supposée dans le reste de la documentation.

PIPAGE DES COMMANDES SHELL

COMMANDES SHELL PIPÉES

Les commandes shell normales présentent certaines limitations dans certains cas. Lorsqu'une sortie ou un message d'erreur est donné et que la commande se termine ensuite, l'interface utilisateur reprend immédiatement et il n'y a aucun moyen de voir le message sans revenir à la console. De plus, même lorsqu'il n'y a pas de sortie ou d'erreur, l'interface utilisateur doit toujours être mise en pause pendant l'exécution de la commande. Cela peut provoquer des scintillements à l'écran pour les commandes courtes et des distractions similaires pour les commandes plus longues.

Au lieu de mettre l'interface utilisateur en pause, les commandes shell pipées connectent stdin, stdout et stderr de la commande à la barre d'état en bas de l'interface utilisateur. Cela peut être utile pour les programmes qui suivent la philosophie Unix de ne produire aucune sortie en cas de succès, et des messages d'erreur ou des invites brèves dans d'autres cas.

Par exemple, la commande de renommage suivante invite à l'écrasement dans la barre d'état s'il existe un fichier du nom donné :

cmd rename %mv -i $f $1

Vous pouvez également produire des messages d'erreur dans la commande et ils s'afficheront dans la barre d'état. Par exemple, une commande de renommage alternative peut ressembler à ceci :

cmd rename %[ -e $1 ] && printf "file exists" || mv $f $1

Notez que l'entrée est mise en mémoire tampon ligne par ligne, tandis que la sortie et les erreurs sont mises en mémoire tampon octet par octet.

COMMANDES SHELL EN ATTENTE

Les commandes shell en attente sont similaires aux commandes shell normales, à l'exception du fait qu'elles attendent une pression de touche une fois la commande terminée. Celles-ci peuvent être utiles pour voir la sortie d'un programme avant la reprise de l'interface utilisateur. Les commandes shell en attente sont plus appropriées que les commandes shell pipées lorsque la commande est verbeuse et que la sortie est mieux affichée sur plusieurs lignes.

COMMANDES SHELL ASYNCHRONES

Les commandes shell asynchrones sont utilisées pour démarrer une commande en arrière-plan, puis reprendre l'opération sans attendre que la commande se termine. Stdin, stdout et stderr de la commande ne sont ni connectés au terminal ni à l'interface utilisateur.

COMMANDES DISTANTES

L'une des fonctionnalités les plus avancées de lf sont les commandes distantes. Tous les clients se connectent à un serveur au démarrage. Il est possible d'envoyer des commandes à tous les clients connectés ou à certains d'entre eux via le serveur commun. Ceci est utilisé en interne pour notifier les changements de sélection de fichiers aux autres clients.

Pour utiliser cette fonctionnalité, vous devez utiliser un client prenant en charge la communication avec un socket de domaine Unix. L'implémentation OpenBSD de netcat (nc) en est un exemple. Vous pouvez l'utiliser pour envoyer une commande au fichier socket :

echo 'send echo hello world' | nc -U ${XDG_RUNTIME_DIR:-/tmp}/lf.${USER}.sock

Étant donné qu'un tel client peut ne pas être disponible partout, lf est fourni avec un indicateur de ligne de commande à utiliser comme tel. Lorsque vous utilisez lf, vous n'avez pas besoin de spécifier l'adresse du fichier socket. C'est la méthode recommandée pour utiliser les commandes distantes car elle est plus courte et insensible aux changements d'adresse du fichier socket :

lf -remote 'send echo hello world'

Dans cette commande, send est utilisé pour envoyer le reste de la chaîne sous forme de commande à tous les clients connectés. Vous pouvez éventuellement lui donner un numéro d'ID pour envoyer une commande à un seul client :

lf -remote 'send 1234 echo hello world'

Tous les clients ont un numéro d'ID unique, mais vous n'êtes peut-être pas au courant du numéro d'ID lorsque vous écrivez une commande. À cette fin, une variable $id est exportée dans l'environnement pour les commandes shell. La valeur de cette variable est définie sur l'ID de processus du client. Vous pouvez l'utiliser pour envoyer une commande distante d'un client au serveur, qui renvoie ensuite une commande à lui-même. Vous pouvez donc maintenant afficher un message dans le client actuel en appelant ceci dans une commande shell :

lf -remote "send $id echo hello world"

Étant donné que lf n'a pas de syntaxe de contrôle de flux, les commandes distantes sont utilisées pour de tels besoins. Par exemple, vous pouvez configurer le nombre de colonnes dans l'interface utilisateur en fonction de la largeur du terminal comme suit :

cmd recol %{{
    if [ $lf_width -le 80 ]; then
        lf -remote "send $id set ratios 1:2"
    elif [ $lf_width -le 160 ]; then
        lf -remote "send $id set ratios 1:2:3"
    else
        lf -remote "send $id set ratios 1:2:3:5"
    fi
}}

De plus, la commande query peut être utilisée pour obtenir des informations sur une instance lf spécifique en fournissant son ID :

lf -remote "query $id maps"

Les types d'informations suivants sont pris en charge :

maps     liste des mappages créés par la commande 'map', 'nmap' et 'vmap'
nmaps    liste des mappages créés par la commande 'nmap' et 'map'
vmaps    liste des mappages créés par la commande 'vmap' et 'map'
cmaps    liste des mappages créés par la commande 'cmap'
cmds     liste des commandes créées par la commande 'cmd'
jumps    contenu de la liste des sauts, montrant les emplacements visités précédemment
history  liste des commandes précédemment exécutées sur la ligne de commande
files    liste des fichiers dans le répertoire actuellement ouvert tel qu'affiché par lf, vide si le répertoire est encore en cours de chargement

Lors de la liste des mappages, les caractères dans la première colonne sont :

n  Normal
v  Visuel
c  Ligne de commande

Ceci est utile pour scriptiser des actions basées sur l'état interne de lf. Par exemple, pour sélectionner une commande précédente à l'aide de fzf et l'exécuter :

map <a-h> ${{
    clear
    cmd=$(
        lf -remote "query $id history" |
        awk -F'\t' 'NR > 1 { print $NF}' |
        sort -u |
        fzf --reverse --prompt='Execute command: '
    )
    lf -remote "send $id $cmd"
}}

Il existe également une commande quit pour quitter le serveur lorsqu'il n'y a plus de clients connectés, et une commande quit! pour forcer la fermeture du serveur en fermant d'abord les connexions client :

lf -remote 'quit'
lf -remote 'quit!'

Enfin, les commandes conn et drop connectent ou déconnectent l'ID du/vers le serveur :

lf -remote 'conn $id'
lf -remote 'drop $id'

Ceux-ci sont internes et généralement inutiles pour les utilisateurs.

OPÉRATIONS SUR LES FICHIERS

lf utilise ses propres opérations de copie et de déplacement intégrées par défaut. Celles-ci sont implémentées comme des opérations asynchrones et la progression est affichée dans la règle du bas. Ces commandes n'écrasent pas les fichiers ou répertoires existants du même nom. Au lieu de cela, un suffixe compatible avec l'option --backup=numbered de GNU cp est ajouté aux nouveaux fichiers ou répertoires. Seuls les modes de fichier et (certains) horodatages peuvent être préservés (voir l'option preserve), tous les autres attributs sont ignorés, y compris la propriété, le contexte et xattr. Les fichiers spéciaux tels que les périphériques de caractères et de bloc, les tubes nommés et les sockets sont ignorés, et les liens ne sont pas suivis. Le déplacement est effectué à l'aide de l'opération de renommage du système d'exploitation sous-jacent. Pour les déplacements inter-périphériques, lf se rabat sur la copie, puis supprime les fichiers d'origine s'il n'y a pas d'erreurs. Les erreurs d'opération sont affichées dans la ligne de message ainsi que dans le fichier journal et ne terminent pas prématurément l'opération de fichier correspondante.

Les opérations sur les fichiers peuvent être effectuées sur le fichier actuellement sélectionné ou sur plusieurs fichiers en les sélectionnant d'abord. Lorsque vous copiez un fichier, lf ne copie pas réellement le fichier sur le disque, mais enregistre seulement son nom dans un fichier. La copie réelle du fichier a lieu lorsque vous collez. De même, coller après une opération de couper déplace le fichier.

Vous pouvez personnaliser les opérations de copie et de déplacement en définissant une commande paste. Il s'agit d'une commande spéciale qui est appelée lorsqu'elle est définie, au lieu de l'implémentation intégrée. Vous pouvez utiliser l'exemple suivant comme point de départ :

cmd paste %{{
    load=$(cat ~/.local/share/lf/files)
    mode=$(echo "$load" | sed -n '1p')
    list=$(echo "$load" | sed '1d')
    if [ $mode = 'copy' ]; then
        cp -R $list .
    elif [ $mode = 'move' ]; then
        mv $list .
        rm ~/.local/share/lf/files
        lf -remote 'send clear'
    fi
}}

Certaines choses utiles à considérer sont l'utilisation des options de sauvegarde (--backup) et/ou de préservation des attributs (-a) avec les commandes cp et mv si elles les supportent (c'est-à-dire l'implémentation GNU), le changement du type de commande en asynchrone, ou l'utilisation de la commande rsync avec l'option de barre de progression pour la copie et l'alimentation périodique de la progression vers le client avec des appels echo distants.

Par défaut, lf n'attribue pas la commande delete à une touche pour protéger les nouveaux utilisateurs. Vous pouvez personnaliser la suppression de fichiers en définissant une commande delete. Vous pouvez également attribuer une touche à cette commande si vous le souhaitez. Un exemple de commande pour déplacer les fichiers sélectionnés vers un dossier de corbeille et supprimer complètement les fichiers après une invite est fourni dans le fichier de configuration d'exemple.

RECHERCHE DE FICHIERS

Il existe deux mécanismes implémentés dans lf pour rechercher un fichier dans le répertoire courant. La recherche est la méthode traditionnelle pour déplacer la sélection vers un fichier correspondant à un modèle donné. La trouvaille est une manière alternative de rechercher un modèle en utilisant potentiellement moins de frappes.

Le mécanisme de recherche est implémenté avec les commandes search (par défaut /), search-back (par défaut ?), search-next (par défaut n), et search-prev (par défaut N). Vous pouvez définir searchmethod sur glob pour faire correspondre à l'aide d'un modèle glob. Le globbing prend en charge le

"Li">* pour faire correspondre n'importe quelle séquence, ? pour faire correspondre n'importe quel caractère, et [...] ou [^...] pour faire correspondre des ensembles ou des plages de caractères. Vous pouvez définir searchmethod sur regex pour faire correspondre à l'aide d'un modèle regex. Pour un aperçu complet de la syntaxe RE2 de Go, voir https://pkg.go.dev/regexp/syntax. Vous pouvez activer l'option incsearch pour sauter vers la correspondance actuelle à chaque frappe pendant la saisie. Dans ce mode, vous pouvez soit utiliser cmd-enter pour accepter la recherche, soit utiliser cmd-escape pour annuler la recherche. Vous pouvez également mapper certaines autres commandes avec cmap pour accepter la recherche et exécuter la commande immédiatement après. Par exemple, vous pouvez utiliser la touche flèche droite pour terminer la recherche et ouvrir le fichier sélectionné avec le mapping suivant :

cmap <right> :cmd-enter; open

Le mécanisme de recherche est implémenté avec les commandes find (par défaut f), find-back (par défaut F), find-next (par défaut ;), find-prev (par défaut ,). Vous pouvez désactiver l'option anchorfind pour faire correspondre un modèle à une position arbitraire du nom de fichier au lieu du début. Vous pouvez définir le nombre de clés à faire correspondre en utilisant l'option findlen. Si vous définissez cette valeur à zéro, les clés sont lues jusqu'à ce qu'il n'y ait qu'une seule correspondance. Les valeurs par défaut de ces deux options sont définies pour sauter vers le premier fichier avec l'initiale donnée.

Certaines options affectent à la fois la recherche et la découverte. Vous pouvez désactiver l'option wrapscan pour empêcher les recherches de boucler à la fin de la liste de fichiers. Vous pouvez désactiver l'option ignorecase pour faire correspondre les majuscules dans le modèle et le nom de fichier. Cette option est déjà automatiquement remplacée si le modèle contient des caractères majuscules. Vous pouvez désactiver l'option smartcase pour désactiver ce comportement. Deux options similaires, ignoredia et smartdia, sont fournies pour contrôler la correspondance des diacritiques dans les lettres latines.

OUVERTURE DES FICHIERS

Vous pouvez définir une commande open (par défaut l et <right>) pour configurer l'ouverture des fichiers. Cette commande n'est appelée que lorsque le fichier actuel n'est pas un répertoire, sinon le répertoire est saisi à la place. Vous pouvez la définir comme vous définiriez n'importe quelle autre commande :

cmd open $vi $fx

Il est possible d'utiliser différents types de commandes :

cmd open &xdg-open $f

Vous pourriez vouloir utiliser soit les extensions de fichier, soit les types MIME de la commande file :

cmd open ${{
    case $(file --mime-type -Lb $f) in
        text/*) vi $fx;;
        *) for f in $fx; do xdg-open $f > /dev/null 2> /dev/null & done;;
    esac
}}

Vous pourriez vouloir utiliser setsid avant votre commande d'ouverture pour avoir des processus persistants qui continuent de s'exécuter après la fermeture de lf.

Les commandes shell régulières (c'est-à-dire $) reviennent au terminal, ce qui entraîne un scintillement pour les commandes qui se terminent immédiatement (par exemple, xdg-open dans l'exemple ci-dessus). Si vous souhaitez utiliser des commandes shell asynchrones (c'est-à-dire &) mais également utiliser le terminal si nécessaire (par exemple, vi dans l'exemple ci-dessus), vous pouvez utiliser une commande distante :

cmd open &{{
    case $(file --mime-type -Lb $f) in
        text/*) lf -remote "send $id \$vi \$fx";;
        *) for f in $fx; do xdg-open $f > /dev/null 2> /dev/null & done;;
    esac
}}

Notez que les commandes shell asynchrones s'exécutent dans leur propre groupe de processus par défaut, elles ne nécessitent donc pas l'utilisation manuelle de setsid.

La commande suivante est fournie par défaut :

cmd open &$OPENER $f

Vous pouvez également utiliser d'autres ouvreurs de fichiers existants à votre convenance. Les options possibles sont libfile-mimeinfo-perl (nom exécutable mimeopen), rifle (l'ouvreur de fichiers par défaut de ranger), ou mimeo pour n'en nommer que quelques-uns.

PRÉVISUALISATION DES FICHIERS

lf prévisualise les fichiers dans le panneau de prévisualisation en imprimant le fichier jusqu'à la fin ou jusqu'à ce que le panneau de prévisualisation soit rempli. Cette sortie peut être améliorée en fournissant un script de prévisualisation personnalisé pour le filtrage. Cela peut être utilisé pour mettre en surbrillance le code source, lister le contenu des fichiers d'archive ou afficher des fichiers PDF ou image, pour n'en nommer que quelques-uns. Pour la coloration, lf reconnaît les codes d'échappement ANSI.

Pour utiliser cette fonctionnalité, vous devez définir la valeur de l'option previewer sur le chemin d'un fichier exécutable. Les arguments suivants sont passés au fichier : (1) nom du fichier actuel, (2) largeur, (3) hauteur, (4) position horizontale, (5) position verticale, et (6) mode ("preview" ou "preload"). La sortie de l'exécution est imprimée dans le panneau de prévisualisation.

Différents types de fichiers peuvent être gérés en faisant correspondre l'extension (ou le type MIME de la commande file) :

#!/bin/sh
case "$1" in
    *.tar*) tar tf "$1";;
    *.zip) unzip -l "$1";;
    *.rar) unrar l "$1";;
    *.7z) 7z l "$1";;
    *.pdf) pdftotext "$1" -;;
    *) highlight -O ansi "$1";;
esac

Comme les fichiers peuvent être volumineux, lf ferme automatiquement le flux de sortie du script de prévisualisation avec un SIGPIPE lorsque suffisamment de lignes sont lues. Notez que certains programmes peuvent ne pas bien réagir à SIGPIPE et se terminer avec un code de retour non nul, ce qui évite la mise en cache. Vous pouvez ajouter un || true final pour éviter de telles erreurs :

highlight -O ansi "$1" || true

Vous pourriez également vouloir utiliser le même script dans votre mappage de pager :

set previewer ~/.config/lf/pv.sh
map i $~/.config/lf/pv.sh $f | less -R

Pour le pager less, vous pouvez plutôt utiliser le mécanisme LESSOPEN afin que des informations utiles sur le fichier, telles que le chemin complet du fichier, puissent toujours être affichées dans la barre d'état en dessous :

set previewer ~/.config/lf/pv.sh
map i $LESSOPEN='| ~/.config/lf/pv.sh %s' less -R $f

Étant donné que le script de prévisualisation est appelé pour chaque changement de sélection de fichier, il peut ne pas générer les prévisualisations assez rapidement si l'utilisateur fait défiler les fichiers rapidement. Pour résoudre ce problème, l'option preload peut être définie pour activer le préchargement des prévisualisations de fichiers à l'avance. Si activé, le script de prévisualisation sera exécuté à l'avance sur les fichiers pendant que l'utilisateur navigue parmi eux. Dans ce cas, si le code de sortie du script de prévisualisation est zéro, la sortie sera mise en cache en mémoire et affichée par lf (utile pour les prévisualisations de texte ou de sixels). Sinon, il reviendra à l'appel du script de prévisualisation à nouveau lorsque le fichier est effectivement sélectionné (utile pour les prévisualisations gérées par un programme externe).

CHANGEMENT DE RÉPERTOIRE

lf change le répertoire de travail du processus pour le répertoire actuel afin que les commandes shell fonctionnent toujours dans le répertoire affiché. Après avoir quitté, il revient au répertoire d'origine où il a été lancé pour la première fois, comme tous les programmes shell. Si vous souhaitez rester dans le répertoire actuel après avoir quitté, vous pouvez utiliser l'un des scripts wrapper lfcd fournis dans le dépôt à l'adresse https://github.com/gokcehan/lf/tree/master/etc

Il existe une commande spéciale on-cd qui exécute une commande shell lorsqu'elle est définie et que le répertoire est changé. Vous pouvez la définir comme vous définiriez n'importe quelle autre commande :

cmd on-cd &{{
    bash -c '
    # display git repository status in your prompt
    source /usr/share/git/completion/git-prompt.sh
    GIT_PS1_SHOWDIRTYSTATE=auto
    GIT_PS1_SHOWSTASHSTATE=auto
    GIT_PS1_SHOWUNTRACKEDFILES=auto
    GIT_PS1_SHOWUPSTREAM=auto
    git=$(__git_ps1 " (%s)")
    fmt="\033[32;1m%u@%h\033[0m:\033[34;1m%d\033[0m\033[1m%f$git\033[0m"
    lf -remote "send $id set promptfmt \"$fmt\""
    '
}}

Si vous souhaitez envoyer des séquences d'échappement au terminal, vous pouvez utiliser la commande tty-write pour ce faire. La séquence d'échappement suivante spécifique à xterm définit le titre du terminal sur le répertoire de travail :

cmd on-cd &{{
    lf -remote "send $id tty-write \"\033]0;$PWD\007\""
}}

Cette commande s'exécute chaque fois que vous changez de répertoire, mais pas au démarrage. Vous pouvez ajouter un appel supplémentaire pour qu'elle s'exécute également au démarrage :

cmd on-cd &{{ ... }}
on-cd

Notez que toutes les commandes shell sont possibles, mais % et & sont généralement plus appropriées, car $ et ! provoquent respectivement des scintillements et des pauses.

Il existe également une commande pre-cd, qui fonctionne comme on-cd, mais qui s'exécute avant que le répertoire ne soit réellement changé. Une autre commande connexe est on-load, qui est exécutée lors du chargement d'un répertoire.

CHARGEMENT DU RÉPERTOIRE

Semblable à on-cd, il existe également on-load qui, lorsqu'il est défini, exécute une commande shell après avoir chargé un répertoire. Il fonctionne bien lorsqu'il est combiné avec addcustominfo.

L'exemple suivant peut être utilisé pour afficher des indicateurs git dans la colonne d'informations :

cmd on-load &{{
    cd "$(dirname "$1")" || exit 1
    [ "$(git rev-parse --is-inside-git-dir 2>/dev/null)" = false ] || exit 0
    cmds=""
    pour file in "$@"; faire
        case "$file" in
            */.git|*/.git/*) continuer;;
        esac
        status=$(git status --porcelain --ignored -- "$file" | cut -c1-2 | head -n1)
        si [ -n "$status" ]; alors
            cmds="${cmds}addcustominfo \"${file}\" \"$status\"; "
        sinon
            cmds="${cmds}addcustominfo \"${file}\" ''; "
        fi
    done
    si [ -n "$cmds" ]; alors
        lf -remote "send $id :$cmds"
    fi
}}

Un autre cas d'utilisation pourrait être l'affichage des dimensions des images et des vidéos :

cmd on-load &{{
    cmds=""
    pour file in "$@"; faire
        mime=$(file --mime-type -Lb -- "$file")
        case "$mime" in
            # les images vectorielles posent des problèmes
            image/svg+xml)
                ;;
            image/*|video/*)
                dimensions=$(exiftool -s3 -imagesize -- "$file")
                cmds="${cmds}addcustominfo \"${file}\" \"$dimensions\"; "
                ;;
        esac
    done
    si [ -n "$cmds" ]; alors
        lf -remote "send $id :$cmds"
    fi
}}

COULEURS

lf essaie de s'adapter automatiquement aux couleurs de l'environnement. Il commence avec une palette de couleurs par défaut et met à jour les couleurs en utilisant les valeurs des variables d'environnement existantes, en écrasant potentiellement ses valeurs précédentes. Les couleurs sont définies dans l'ordre suivant :

1.
par défaut
2.
LSCOLORS (ls macOS/BSD)
3.
LS_COLORS (ls GNU)
4.
LF_COLORS (spécifique à lf)
5.
fichier de couleurs (spécifique à lf)

Veuillez vous référer aux pages de manuel correspondantes pour plus d'informations sur LSCOLORS et LS_COLORS. LF_COLORS est fourni avec la même syntaxe que LS_COLORS au cas où vous souhaiteriez configurer les couleurs uniquement pour lf mais pas pour ls. Cela peut être utile car il existe quelques différences entre ls et lf, bien que l'on puisse s'attendre au même comportement pour les cas courants. Le fichier de couleurs (voir la section CONFIGURATION) est fourni pour faciliter la configuration sans variables d'environnement. Ce fichier doit être composé de paires séparées par des espaces blancs avec un caractère # pour démarrer les commentaires jusqu'à la fin de la ligne.

Vous pouvez configurer les couleurs de lf de deux manières. Premièrement, vous pouvez configurer uniquement les 8 couleurs de base utilisées par votre terminal et lf devrait récupérer ces couleurs automatiquement. Selon votre terminal, vous devriez pouvoir sélectionner vos couleurs parmi une palette de 24 bits. C'est l'approche recommandée car les couleurs utilisées par d'autres programmes correspondront également.

Deuxièmement, vous pouvez définir les valeurs des variables d'environnement ou du fichier de couleurs mentionné ci-dessus pour une personnalisation plus fine. Notez que LS_COLORS/LF_COLORS sont plus puissants que LSCOLORS et peuvent être utilisés même lorsque des programmes GNU ne sont pas installés sur le système. Vous pouvez combiner cette deuxième méthode avec la première pour de meilleurs résultats.

Enfin, vous pourriez également souhaiter configurer les couleurs de la ligne d'invite pour qu'elles correspondent aux autres couleurs. Les couleurs de la ligne d'invite peuvent être configurées à l'aide de l'option promptfmt qui peut inclure des couleurs codées en dur sous forme d'échappements ANSI. Voir la valeur par défaut de cette option pour avoir une idée de la façon de colorer cette ligne.

Il convient de noter que lf utilise autant de couleurs annoncées par l'entrée de votre terminal dans les bases de données terminfo ou infocmp de votre système. Si une entrée n'est pas présente, il utilise une base de données interne. Si votre terminal prend en charge les couleurs 24 bits mais n'a pas d'entrée de base de données ou n'annonce pas toutes les capacités, vous pouvez activer la prise en charge en définissant la variable $COLORTERM sur truecolor ou en vous assurant que $TERM est définie sur une valeur se terminant par -truecolor.

Les couleurs par défaut de lf sont principalement tirées des valeurs par défaut de dircolors GNU. Ces valeurs par défaut utilisent 8 couleurs de base et l'attribut gras. Les entrées dircolors par défaut avec des couleurs de fond sont simplifiées pour éviter la confusion avec la sélection de fichier actuelle dans lf. De même, il n'y a que des correspondances de types de fichiers et les correspondances d'extensions sont omises par souci de simplicité. Les valeurs par défaut sont les suivantes, dans l'ordre de leur correspondance dans lf :

or  31;01
