ltrace.conf(5) Fichier de configuration de ltrace ltrace.conf(5)

NOM

ltrace.conf - Fichier de configuration pour ltrace(1).

DESCRIPTION

Cette page de manuel décrit ltrace.conf, un fichier qui décrit les prototypes de fonctions dans les binaires pour que ltrace(1) les utilise. Ltrace a besoin de ces informations pour afficher les arguments des appels de fonctions.

Chaque ligne d'un fichier de configuration décrit au plus un élément. Les lignes composées uniquement d'espaces blancs sont ignorées, tout comme les lignes commençant par le caractère point-virgule (lignes de commentaire). Les éléments décrits peuvent être soit des prototypes de fonctions, soit des définitions d'alias de types.

PROTOTYPES

Un prototype décrit le type de retour et les types des paramètres d'une seule fonction. La syntaxe est la suivante :

LENS NOM ([LENS{,LENS}]);

NOM est le nom (obfusqué) d'un symbole. Dans le cas élémentaire, LENS est simplement un type. Les lentilles (lenses) et les types sont décrits ci-dessous. Par exemple, un prototype de fonction simple pourrait ressembler à ceci :

int kill(int,int);

Malgré la similitude apparente avec le C, ltrace.conf est réellement son propre langage, seulement quelque peu inspiré par le C.

TYPES

Ltrace comprend une gamme de types primitifs. Ceux-ci sont interprétés selon la convention C native sur une architecture donnée. Par exemple, ulong est interprété comme un entier non signé de 4 octets sur une machine GNU/Linux 32 bits, mais comme un entier non signé de 8 octets sur une machine GNU/Linux 64 bits.

void
Indique qu'une fonction ne retourne rien. Peut également être utilisé pour construire un pointeur générique, c'est-à-dire un nombre de la taille d'un pointeur formaté en hexadécimal.
char
Quantité de 8 bits rendue sous forme de caractère.
ushort,short
Indique un entier court non signé ou signé.
uint,int
Indique un entier non signé ou signé.
ulong,long
Indique un entier long non signé ou signé.
float
Indique un nombre à virgule flottante de précision simple.
double
Indique un nombre à virgule flottante de précision double.

En plus des types primitifs, les types composés suivants sont possibles :

struct([LENS{,LENS}])
Décrit une structure avec les types donnés comme champs, par exemple struct(int,int,float).

L'alignement est calculé comme d'habitude sur l'architecture. L'alignement personnalisé (par exemple, les structures compactées) et les champs de bits ne sont pas pris en charge. Il n'est pas non plus possible de différencier les structures et les classes C++ non-POD, pour les architectures où cela fait une différence.

array(LENS,EXPR)
Décrit un tableau de longueur EXPR, composé de types décrits par LENS, par exemple array(int, 6).

Notez qu'en C, les tableaux utilisés comme arguments de fonction se réduisent à des pointeurs. Ltrace gère actuellement cela automatiquement, mais pour une correction formelle complète, de tels arguments devraient être décrits comme des pointeurs vers des tableaux.

LENS*
Décrit un pointeur vers un type donné, par exemple char* ou int***. Notez que le premier exemple décrit réellement un pointeur vers un caractère, pas une chaîne de caractères. Voir ci-dessous pour la lentille string, qui s'applique dans ces cas.

LENSES

Les lentilles modifient la manière dont les types sont décrits. Dans le cas le plus simple, une lentille est directement un type. Sinon, un type est décoré par la lentille. Ltrace comprend les lentilles suivantes :

oct(TYPE)
L'argument, qui devrait être un type entier, est formaté en base 8.
hex(TYPE)
L'argument, qui devrait être un type entier ou à virgule flottante, est formaté en base 16. Les arguments à virgule flottante sont convertis en double puis affichés en utilisant le modificateur %a de fprintf.
hide(TYPE)
L'argument n'est pas affiché dans la liste des arguments.
bool(TYPE)
Les arguments avec une valeur zéro sont affichés comme "false", les autres comme "true".
bitvec(TYPE)
L'argument sous-jacent est interprété comme un vecteur de bits et un résumé des bits définis dans le vecteur est affiché. Par exemple, si les bits 3, 4, 5 et 7 du vecteur de bits sont définis, ltrace affiche <3-5,7>. Un vecteur de bits vide s'affiche comme <>. S'il y a plus de bits définis que non définis, l'inverse est affiché à la place : par exemple ~<0> lorsqu'un nombre 0xfffffffe est affiché. L'ensemble complet est donc affiché ~<>.

Si le type sous-jacent est intégral, les bits sont affichés dans leur ordre naturel big-endian, le LSB étant le bit 0. Par exemple, bitvec(ushort) avec la valeur 0x0102 s'affichera comme <1,8>, indépendamment de l'ordre des octets sous-jacent.

Pour d'autres types de données (notamment les structures et les tableaux), les données sous-jacentes sont interprétées octet par octet. Le bit 0 du premier octet a le numéro 0, le bit 0 du deuxième octet le numéro 8, et ainsi de suite. Ainsi, bitvec(struct(int)) est sensible à l'endianness, et affichera les octets composant l'entier dans leur ordre mémoire. Les pointeurs sont d'abord déréférencés, donc bitvec(array(char, 32)*) est en réalité un pointeur vers un vecteur de bits de 256 bits.

string(TYPE)
string[EXPR]
string

La première forme de l'argument est canonique, les deux dernières sont du sucre syntaxique. Dans la forme canonique, l'argument de la fonction est formaté comme une chaîne de caractères. Le TYPE doit être soit un char*, soit un array(char,EXPR), soit un array(char,EXPR)*. Si un tableau est donné, la longueur sera typiquement une expression zero (mais pas nécessairement). Utiliser un argument qui est un tableau simple (c'est-à-dire pas un pointeur vers un tableau) a du sens par exemple dans les structures C, dans des cas comme struct(string(array(char, 6))), qui décrit le type C struct {char s[6];}.

Étant donné que les chaînes de caractères de type C simple sont assez courantes, il existe deux formes abrégées. La première forme abrégée (avec des crochets) signifie la même chose que string(array(char, EXPR)*). L'utilisation de string seul, sans argument, est alors interprétée comme string[zero].

Notez que char* seul décrit un pointeur vers un caractère. Ltrace déréférencera le pointeur, lira et affichera le seul caractère vers lequel il pointe.

enum(NAME[=VALUE]{,NAME[=VALUE]})
enum[TYPE](NAME[=VALUE]{,NAME[=VALUE]})

Ceci décrit une lentille d'énumération. Si un argument a l'une des valeurs données, il est affiché comme le NAME correspondant. Si une VALUE est omise, la valeur consécutive suivante après la VALUE précédente est prise. Si la première VALUE est omise, elle est 0 par défaut.

TYPE, s'il est donné, est le type sous-jacent. Il est donc possible de créer des énumérations sur des shorts ou des longs — des arguments qui sont eux-mêmes des types simples, non-énumérés en C, mais dont les valeurs peuvent être significativement décrites comme des énumérations. S'il est omis, TYPE est considéré comme int.

ALIASES DE TYPES

Une ligne dans le fichier de configuration peut, au lieu de décrire un prototype, créer un alias de type. Au lieu d'écrire la même énumération ou structure à plusieurs endroits (et potentiellement de la mettre à jour lorsqu'elle change), on peut introduire un nom pour un tel type, et plus tard utiliser simplement ce nom :

typedef NOM = LENS;

STRUCTURES RÉCURSIVES

Ltrace vous permet d'exprimer des structures récursives. Ces structures sont développées jusqu'à la profondeur décrite par le paramètre -A. Pour déclarer un type récursif, vous devez d'abord introduire le type à ltrace en utilisant une déclaration anticipée. Ensuite, vous pouvez utiliser le type dans d'autres définitions de type de la manière habituelle :

typedef NOM = struct;
typedef NOM = struct(NOM peut être utilisé ici)

Par exemple, considérez la structure de liste singulièrement chaînée suivante et une fonction qui prend une telle liste comme argument :

typedef int_list = struct;
typedef int_list = struct(int, int_list*);
void ll(int_list*);

De telles déclarations peuvent conduire à un résultat tel que le suivant :

ll({ 9, { 8, { 7, { 6, ... } } } }) = <void>

Ltrace détecte la récursion et ne développera pas les structures déjà développées. Ainsi, une liste doublement chaînée ressemblerait à ceci :

typedef int_list = struct;
typedef int_list = struct(int, int_list*, int_list*);

Avec une sortie par exemple comme celle-ci :

ll({ 9, { 8, { 7, { 6, ..., ... }, recurse^ }, recurse^ }, nil })

Les jetons "recurse^" signifient que le pointeur donné pointe vers une structure qui a été développée dans la couche précédente. "recurse" simple signifierait qu'il pointe vers cet objet. Par exemple, "recurse^^^" signifie qu'il pointe vers une structure trois couches plus haut. Pour une liste doublement chaînée, le pointeur vers l'élément précédent est bien sûr celui qui vient d'être développé au tour précédent, et donc tous sont soit recurse^, soit nil. Si les pointeurs suivant et précédent sont échangés, la sortie s'ajuste en conséquence :

ll({ 9, nil, { 8, recurse^, { 7, recurse^, { 6, ..., ... } } } })

EXPRESSIONS

Ltrace prend en charge quelques expressions élémentaires. Chaque expression peut être l'une des suivantes :

NOMBRE
Un nombre entier.
argNOMBRE
Valeur du NOMBRE-ième argument. L'expression a la même valeur que l'argument correspondant. arg1 fait référence au premier argument, arg0 à la valeur de retour de la fonction donnée.
retval
Valeur de retour de la fonction, identique à arg0.
eltNOMBRE
Valeur du NOMBRE-ième élément du type de structure environnant. Par exemple, struct(ulong,array(int,elt1)) décrit une structure dont le premier élément est une longueur et le second élément un tableau d'entiers de cette longueur.

zero
zero(EXPR)

Décrit un tableau qui s'étend jusqu'au premier élément, dont chaque octet est 0. Si une expression est donnée, c'est la longueur maximale du tableau. Si un terminateur NUL n'est pas trouvé plus tôt, c'est là que le tableau se termine.

PAQUETS DE PARAMETRES

Parfois, le prototype de fonction réel varie légèrement en fonction des paramètres exacts donnés. Par exemple, le nombre et les types des paramètres de printf ne sont pas connus à l'avance, mais ltrace peut être capable de les déterminer à l'exécution. Cette fonctionnalité a une applicabilité plus large, mais actuellement, le seul paquet de paramètres que ltrace prend en charge est la chaîne de format de style printf elle-même :

format
Lorsque format est vu dans la liste des paramètres, la chaîne sous-jacente est analysée et les spécificateurs de format de style GNU sont utilisés pour déterminer quels sont les arguments réels suivants. Par exemple, si la chaîne de format est "%s %d\n", c'est comme si format était remplacé par string, string, int.

ARGUMENTS DE RETOUR

Les fonctions C utilisent souvent un ou plusieurs arguments pour retourner des valeurs à l'appelant. L'appelant fournit un pointeur vers le stockage, que la fonction appelée initialise. Ltrace prend en charge cet idiome.

Lorsqu'un binaire tracé atteint un appel de fonction, ltrace récupère d'abord tous les arguments. Il affiche ensuite la portion *de gauche* de la liste des arguments. Ce n'est que lorsque la fonction retourne que ltrace affiche également la portion *de droite*. Typiquement, la portion de gauche prend tous les arguments, et la portion de droite ne contient que la valeur de retour. Mais ltrace vous permet de configurer exactement où placer la ligne de séparation au moyen d'un opérateur + placé devant un argument :

int asprintf(+string*, format);

Ici, le premier argument d'asprintf est désigné comme argument de retour, ce qui signifie que l'affichage de toute la liste d'arguments est retardé jusqu'à ce que la fonction retourne :

a.out->asprintf( <unfinished ...>
libc.so.6->malloc(100) = 0x245b010
[... plus d'appels ici ...]
<... asprintf resumed> "X=1", "X=%d", 1) = 5

Il n'est actuellement pas possible d'avoir un argument "inout" qui passe des informations dans les deux sens.

EXEMPLES

Dans ce qui suit, le premier est le prototype C, et après cela se trouve la ligne de configuration de ltrace.

void func_charp_string(char str[]);
void func_charp_string(string);

enum e_foo {RED, GREEN, BLUE};
void func_enum(enum e_foo bar);

void func_enum(enum(RED,GREEN,BLUE));
- ou -
typedef e_foo = enum(RED,GREEN,BLUE);
void func_enum(e_foo);
void func_arrayi(int arr[], int len);
void func_arrayi(array(int,arg2)*,int);

struct S1 {float f; char a; char b;};
struct S2 {char str[6]; float f;};
struct S1 func_struct(int a, struct S2, double d);

struct(float,char,char) func_struct_2(int, struct(string(array(char, 6)),float), double);
