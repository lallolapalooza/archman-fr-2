Description détaillée

libltc - encodage/décodage de timecode linéaire

Le Timecode Linéaire (ou Longitudinal) (LTC) est un encodage de données de timecode sous forme de signal audio à modulation de phase bi-phase de Manchester. Le signal audio est couramment enregistré sur une piste de magnétoscope ou d'autres supports de stockage.

libltc facilite le décodage et l'encodage du LTC à partir/vers le timecode, y compris la prise en charge des dates SMPTE.

Documentation_des structures de données

struct LTCFrame

Trame LTC brute de 80 bits

Le flux de données pour chaque image vidéo du Timecode Longitudinal se compose de quatre-vingts périodes de bits.

À une fréquence d'images de 30 ips, le débit binaire correspond à 30 [ips] * 80 [bits/i] = 2400 bits par seconde. La fréquence pour un flux de zéros serait de 1,2 kHz et pour un flux de uns de 2,4 kHz. Avec toutes les fréquences d'images vidéo et les taux d'échantillonnage audio couramment utilisés, le timecode LTC peut être facilement enregistré dans une piste audio.

Dans chaque trame, 26 des quatre-vingts bits transportent le SMPTE time en format BCD (Binary Coded Decimal).

Ces bits sont UNITS-DE-TRAME, DIZAINES-DE-TRAME, UNITS-DE-SECONDES, DIZAINES-DE-SECONDES, UNITS-DE-MINUTES, DIZAINES-DE-MINUTES, UNITS-D'HEURES et DIZAINES-D'HEURES. Les chiffres BCD sont chargés 'bit de poids faible en premier' (libltc prend en charge l'alignement spécifique à l'architecture).

32 bits sont assignés comme huit groupes de quatre USER-BITS (également parfois appelés 'Binary Groups'). Cette capacité est généralement utilisée pour transporter des informations supplémentaires telles que le numéro de bobine et/ou la date. Les User Bits peuvent être alloués comme on le souhaite tant que les deux bits de drapeau de groupe binaire sont effacés.

La fonction ltc_frame_to_time peut interpréter les user-bits comme Date/Fuseau horaire SMPTE selon SMPTE 309M-1999. De même ltc_time_to_frame fera l'inverse.

Les 16 derniers bits constituent le SYNC WORD. Ces bits indiquent la limite de la trame, la direction de la bande et le débit binaire du ton de synchronisation. Les valeurs de ces bits sont fixées à 0011 1111 1111 1101

Le bit de correction de phase de marque bi-phase (bit 27 ou 59) peut être défini ou effacé de sorte que chaque mot de 80 bits contienne un nombre pair de zéros. Cela signifie que la phase du train d'impulsions dans chaque mot de synchronisation sera la même.

Le bit 10 indique le timecode drop-frame. Le drapeau de trame couleur col.frm est le bit 11 ; si le timecode est intentionnellement synchronisé à une séquence de champ TV couleur, ce bit est défini.

Le bit 58 n'est pas requis pour le compte BCD de HEURES-DIZAINES (qui a une valeur maximale de deux) et n'a reçu aucune autre fonction spéciale, il reste donc non attribué. Ce bit est RESERVÉ pour une attribution future.

Les bits de drapeau de groupe binaire (bits 43 et 59) sont deux bits qui indiquent le format des données des bits utilisateur. SMPTE 12M-1999 définit le bit 58 précédemment réservé pour signaler que l'heure est verrouillée à l'horloge murale dans une tolérance de ± 0,5 secondes.

SMPTE 12M-1999 modifie également le schéma de numérotation du BGF. (BGF1 a été renommé BGF2 et le bit 58 devient BGFB1)

Pour compliquer encore les choses, l'attribution du BGFB ainsi que le bit de correction de phase bi-phase (alias parité) dépendent du format de timecode utilisé.

         25 fps   24, 30 fps
 BGF0      27        43
 BGF1      58        58
 BGF2      43        59
 Parité    59        27

La dénomination des variables choisie pour la structure LTCFrame est basée sur la norme 24,30 ips.

Les bits de drapeau de groupe binaire ne doivent être utilisés que comme indiqué dans le tableau de vérité ci-dessous. Les entrées non attribuées dans le tableau ne doivent pas être utilisées, car elles pourraient se voir attribuer des significations spécifiques à l'avenir.

                                                BGF0      BGF1    BGF2
      user-bits                     timecode    Bit 43   Bit 58  Bit 59 (30fps, 24 fps)
                                   |        |   Bit 27   Bit 58  Bit 43 (25fps)
 Pas de format de bits utilisateur spécifié     |   ?    |     0       0        0
 Jeu de caractères de huit bits (1)       |   ?    |     1       0        0
 Jeu de date et de fuseau horaire            |   ?    |     0       0        1
 Multiplex page/ligne (2)                |   ?    |     1       0        1
 Jeu de caractères non spécifié           |  clk   |     0       1        0
 Réservé                                 |   ?    |     1       1        0
 Jeu de date et de fuseau horaire            |  clk   |     0       1        1
 Multiplex page/ligne (2)                |  clk   |     1       1        1

(1) Jeu de caractères ISO/IEC 646 ou ISO/IEC 2022. Si les codes ISO à sept bits sont utilisés, ils doivent être convertis en codes à huit bits en mettant le huitième bit à zéro. 4 codes ISO peuvent être encodés, user7 et user8 doivent être utilisés pour le premier code avec LSB 7 et MSB en 8. Les codes ISO restants sont à distribuer de la même manière vers user5/6, user3/4 et user1/2 en conséquence.

(2) Page/Ligne indique que ANSI/SMPTE-262M est utilisé pour les bits utilisateur. Il s'agit d'un système de multiplexage qui peut être utilisé pour encoder de grandes quantités de données dans les groupes binaires grâce à l'utilisation du multiplexage temporel.

libltc n'utilise aucun des BGF - à l'exception du bit de parité qui peut être calculé et défini avec ltc_frame_set_parity. La définition et l'interprétation du BGF sont laissées à l'application utilisant libltc. Cependant, libltc fournit des fonctionnalités pour analyser ou définir la date et le fuseau horaire conformément à SMPTE 309M-1999.

Informations supplémentaires : http://www.philrees.co.uk/articles/timecode.htm et http://www.barney-wol.net/time/timecode.html

struct LTCFrameExt

Trame LTC étendue - inclut les décalages de position d'échantillon audio, le volume, etc.

Remarque : Pour les systèmes TV, l'échantillon dans le flux de données audio LTC où la trame LTC commence n'est pas nécessairement au même moment que la trame vidéo décrite par la trame LTC.

off_start indique le moment de la première transition du bit 0 dans la trame LTC.

Pour les systèmes de télévision 525/60, la première transition doit se produire au début de la ligne 5 de la trame à laquelle elle est associée. La tolérance est de ± 1,5 lignes.

Pour les systèmes 625/50, la première transition doit se produire au début de la ligne 2 ± 1,5 lignes de la trame à laquelle elle est associée.

Seulement pour les systèmes 1125/60, la première transition se produit exactement au moment de la référence de synchronisation verticale de la trame. ± 1 ligne.

Exemples
ltcdecode.c.

Champs de données :

float biphase_tics[LTC_FRAME_BIT_COUNT] informations de synchronisation détaillées : phase du signal LTC ; le temps entre chaque bit dans la trame LTC en trames audio. La somme des 80 valeurs du tableau donnera trames audio/trame LTC = (off_end - off_start + 1).

LTCFrame ltc la trame LTC réelle. voir LTCFrame

ltc_off_t off_end l'échantillon dans le flux correspondant à la fin de la trame LTC.

ltc_off_t off_start l'échantillon approximatif dans le flux correspondant au début de la trame LTC.

int reverse si différent de zéro, une trame LTC jouée en sens inverse a été détectée. Puisque la trame était inversée, elle a commencé à off_end et se termine à off_start (off_end > off_start). (Remarque : en lecture inversée, le mot de synchronisation (inversé) de la trame suivante/précédente est détecté, ce décalage est corrigé).

ltcsnd_sample_t sample_max l'échantillon d'entrée maximal du signal pour cette trame (0..255)

ltcsnd_sample_t sample_min l'échantillon d'entrée minimal du signal pour cette trame (0..255)

double volume le volume du signal d'entrée en dbFS

int ltc_encoder_encode_byte (LTCEncoder * e, int byte, double speed)

Generate LTC audio for given byte of the LTC-frame and place it into the internal buffer.

see ltc_encoder_copy_buffer and ltc_encoder_get_bufferptr

LTC has 10 bytes per frame: 0 <= bytecnt < 10 use SMPTESetTime(..) to set the current frame before Encoding. see tests/encoder.c for an example.

The default output signal is @ -3dBFS (38..218 at 8 bit unsigned). see also ltc_encoder_set_volume

Parameters

byte byte of the LTC-frame to encode 0..9
speed vari-speed, < 1.0 faster, > 1.0 slower ; must be != 0

Returns

0 on success, -1 if byte is invalid or buffer overflow (speed > 10.0)

int ltc_encoder_end_encode (LTCEncoder * e)

Terminate encoding and add final transition

Refer to the image at LTCFrame. In this example, the encoded data starts and ends with a rising edge. The transition at the start of tne next frame marks the end of the previous frame. This transition is encoded at the beginning of a frame. However if there is no additional frame to be encoded, a final terminating transition has to be added.

Since LTC is usually sent as continuous stream, this is of no concern. However for a fixed, finite duration to be encoded, this method adds a terminating transition to the buffer.

int ltc_encoder_reinit (LTCEncoder * e, double sample_rate, double fps, enum LTC_TV_STANDARD standard, int flags)

Cet appel échouera si le tampon interne est trop petit pour contenir une trame LTC complète. Utilisez ltc_encoder_set_buffersize pour préparer un tampon interne suffisamment grand pour accueillir toutes les combinaisons de sample_rate, fps auxquelles vous souhaitez réinitialiser.

void ltc_frame_set_parity (LTCFrame * frame, enum LTC_TV_STANDARD standard)

Définit la parité de l'image LTC.

Le bit de correction de phase de la marque bi-phase (bit 27 - ou 59) peut être défini ou effacé de manière à ce que chaque mot de 80 bits contienne un nombre pair de zéros. Cela signifie que la phase dans chaque mot de synchronisation sera la même.

Ceci est purement cosmétique ; la motivation pour maintenir la polarité de la forme d'onde constante est de faciliter la recherche du mot de synchronisation visuellement (sur un oscilloscope).

Il n'est généralement pas nécessaire d'appeler cette fonction directement. Les fonctions utilitaires d'encodage ltc_time_to_frame, ltc_frame_increment et ltc_frame_decrement incluent un appel à celle-ci.

Paramètres

frame le LTC à analyser et à définir ou effacer le bit de correction de phase de la marque bi-phase.
standard Si 1 (également appelé LTC_TV_625_50), le mode 25 ips (bit 59 - également appelé indicateur de groupe binaire bit2) est utilisé, sinon le mode 30 ips, 24 ips (bit 27 - correction de phase de la marque bi-phase) est défini ou effacé.
