LTTNG_UST_TRACEF(3) Manuel LTTng LTTNG_UST_TRACEF(3)

NOM

lttng_ust_tracef, lttng_ust_vtracef - Interface de type printf(3) de LTTng-UST

SYNOPSIS

#include <lttng/tracef.h>
#define lttng_ust_tracef(fmt, ...)
#define lttng_ust_vtracef(fmt, ap)

Lier avec :

•-llttng-ust
•Si vous définissez _LGPL_SOURCE avant d'inclure <lttng/tracef.h> (directement ou indirectement) : -llttng-ust-common

DESCRIPTION

L'API lttng_ust_tracef() et lttng_ust_vtracef() de LTTng-UST vous permet de tracer votre application à l'aide de macros simples de type printf(3) et vprintf(3).

L'argument fmt est passé directement comme paramètre fmt de vasprintf(3), ainsi que :

Pour lttng_ust_tracef()

Les paramètres optionnels suivant fmt.

Pour lttng_ust_vtracef()

Le paramètre ap comme paramètre ap de vasprintf(3) (type va_list).

Pour utiliser lttng_ust_tracef() ou lttng_ust_vtracef(), incluez <lttng/tracef.h> là où vous en avez besoin, et liez votre application avec liblttng-ust et liblttng-ust-common. Voir la section EXEMPLE ci-dessous pour un exemple d'utilisation complet.

Une fois votre application instrumentée avec des appels lttng_ust_tracef() et/ou lttng_ust_vtracef() et prête à être exécutée, utilisez lttng-enable-event(1) pour activer l'événement lttng_ust_tracef:*.

Les événements lttng_ust_tracef() et lttng_ust_vtracef() contiennent un seul champ, nommé msg, qui est la chaîne de caractères formatée.

Si vous avez besoin d'attacher un niveau de journalisation spécifique à un appel lttng_ust_tracef()/lttng_ust_vtracef(), utilisez plutôt lttng_ust_tracelog(3) et lttng_ust_vtracelog(3).

Voir la section LIMITATIONS ci-dessous pour des limitations importantes à considérer lors de l'utilisation de lttng_ust_tracef() ou lttng_ust_vtracef().

EXEMPLE

Voici un exemple d'utilisation de lttng_ust_tracef() :

#include <stdlib.h>
#include <lttng/tracef.h>
int main(void)
{
    int i;
    for (i = 0; i < 25; i++) {
        lttng_ust_tracef("mon message : %s, cet entier : %d",
                         "un message", i);
    }
    return EXIT_SUCCESS;
}

Ce fichier source C, sauvegardé sous le nom app.c, peut être compilé en un programme comme ceci :

$ cc -o app app.c -llttng-ust -llttng-ust-common

Vous pouvez créer une session de traçage LTTng, activer les événements lttng_ust_tracef(), et démarrer la session de traçage créée comme ceci :

$ lttng create ma-session
$ lttng enable-event --userspace 'lttng_ust_tracef:*'
$ lttng start

Ensuite, démarrez le programme à tracer :

$ ./app

Enfin, arrêtez la session de traçage, et inspectez les événements enregistrés :

$ lttng stop
$ lttng view

LIMITATIONS

Les macros utilitaires lttng_ust_tracef() et lttng_ust_vtracef() ont été développées pour simplifier au maximum le traçage en espace utilisateur, malgré des inconvénients notables par rapport aux fournisseurs de points de trace personnalisés et complets :

•Tous les événements générés ont les mêmes noms de fournisseur/événement.
•Il n'y a pas de vérification statique de type.
•Le seul champ d'événement avec des données utilisateur que vous obtenez réellement, nommé msg, est une chaîne de caractères pouvant contenir les valeurs que vous avez passées à la macro en utilisant votre propre format. Cela signifie également que vous ne pouvez pas utiliser de filtrage avec une expression personnalisée au moment de l'exécution car il n'y a pas de champs isolés.
•Étant donné que lttng_ust_tracef() et lttng_ust_vtracef() utilisent la fonction vasprintf(3) de la bibliothèque standard C en arrière-plan pour formater les chaînes au moment de l'exécution, leurs performances attendues sont inférieures à celles de l'utilisation de fournisseurs de points de trace personnalisés avec des champs typés, qui ne nécessitent pas de conversion en chaîne de caractères.
•En général, une chaîne de caractères contenant la représentation textuelle des champs de données utilisateur n'est pas aussi compacte que des champs binaires dans le tracé résultant.

Par conséquent, lttng_ust_tracef()/lttng_ust_vtracef() sont utiles pour le prototypage rapide et le débogage, mais ne devraient pas être considérés pour l'instrumentation d'applications permanentes/sérieuses.

lttng_ust_vtracef() n'a pas d'appel STAP_PROBEV(), car STAP_PROBEV() ne prend pas en charge va_list. Si vous en avez besoin, vous devriez émettre cet appel vous-même.

Voir lttng-ust(3) pour en savoir plus sur les fournisseurs de points de trace personnalisés.
