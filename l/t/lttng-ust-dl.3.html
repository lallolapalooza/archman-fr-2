NOM

lttng-ust-dl - Traçage du chargeur dynamique (aide LTTng-UST)

SYNTAXE

Lancez votre application en préchargeant liblttng-ust-dl.so :

$ LD_PRELOAD=liblttng-ust-dl.so mon-app

DESCRIPTION

Lorsque la bibliothèque liblttng-ust-dl.so est préchargée avant le démarrage d'une application donnée, elle provoque le traçage de tous les appels à dlopen(3) et dlclose(3) dans ladite application avec LTTng-UST (voir lttng-ust(3)).

Voir lttng(1) pour en savoir plus sur la façon de contrôler les sessions de traçage LTTng.


Important

Cette aide LTTng-UST peut également émettre des événements de chargement/déchargement de bibliothèque partagée (voir Suivi du chargement/déchargement de bibliothèques partagées dans lttng-ust(3)). Vous ne devriez PAS utiliser les enregistrements d'événements générés par cette aide LTTng-UST (préfixés par lttng_ust_dl:) pour suivre le chargement et le déchargement de bibliothèques partagées, en particulier dans les situations où une bibliothèque chargée dynamiquement charge ses propres dépendances. Au lieu de cela, préchargez liblttng-ust-dl.so, mais utilisez les enregistrements d'événements de chargement/déchargement de bibliothèques partagées, qui sont plus fiables, pour votre analyse de suivi.

Les événements LTTng-UST suivants sont disponibles lors de l'utilisation de cette bibliothèque.

lttng_ust_dl:dlopen

Émis lorsque dlopen(3) est appelé.

Champs :

Nom du champ Description
baddr Adresse de base de la bibliothèque chargée.
memsz Taille de la bibliothèque chargée en mémoire.
flags Indicateurs passés à dlopen(3).
path Chemin d'accès au fichier de la bibliothèque chargée.
has_build_id Indique si la bibliothèque chargée possède un ID de build. Si ce champ vaut 1, vous pouvez vous attendre à ce qu'un enregistrement d'événement lttng_ust_dl:build_id suive celui-ci (pas nécessairement immédiatement après).
has_debug_link Indique si la bibliothèque chargée possède des informations de lien de débogage. Si ce champ vaut 1, vous pouvez vous attendre à ce qu'un enregistrement d'événement lttng_ust_dl:debug_link suive celui-ci (pas nécessairement immédiatement après).

flags Indicateurs passés à dlmopen(3).

has_build_id Indique si la bibliothèque chargée possède un ID de build. Si ce champ vaut 1, vous pouvez vous attendre à ce qu'un enregistrement d'événement lttng_ust_dl:build_id suive celui-ci (pas nécessairement immédiatement après).
has_debug_link Indique si la bibliothèque chargée possède des informations de lien de débogage. Si ce champ vaut 1, vous pouvez vous attendre à ce qu'un enregistrement d'événement lttng_ust_dl:debug_link suive celui-ci (pas nécessairement immédiatement après).

lttng_ust_dl:dlclose

Émis lorsque dlclose(3) est appelé.

Champs :

Nom du champ Description

lttng_ust_dl:debug_link

Émis lorsque des informations de lien de débogage sont trouvées lors du chargement d'une bibliothèque avec dlopen(3). Voir Débogage d'informations dans des fichiers séparés https://sourceware.org/gdb/onlinedocs/gdb/Separate-Debug-Files.html pour plus d'informations sur les liens de débogage.

Champs :

Nom du champ Description
baddr Adresse de base de la bibliothèque chargée.
filename Nom du fichier de lien de débogage.
crc CRC du fichier de lien de débogage.

lttng_ust_dl:build_id

Émis lorsqu'un ID de build est trouvé lors du chargement d'une bibliothèque avec dlopen(3). Voir Débogage d'informations dans des fichiers séparés https://sourceware.org/gdb/onlinedocs/gdb/Separate-Debug-Files.html pour plus d'informations sur les ID de build.

Champs :

Nom du champ Description
baddr Adresse de base de la bibliothèque chargée.
build_id ID de build.

NAME

lttng-ust-dl - LTTng UST dynamic loading of instrumentation hooks

SYNOPSIS

#include <lttng/tracef.h>

    lttng_ust_dl_attach(3), lttng_ust_dl_detach(3)

DESCRIPTION

This man page documents the functions available for dynamic loading of LTTng UST instrumentation hooks.

These functions are useful when you want to add or remove instrumentation to a running application without restarting it.

lttng_ust_dl_attach

Attaches the LTTng UST instrumentation library to a target process.

This function can be called from a dynamically loaded shared library (plugin) that is loaded into the target process using dlopen(3).

The instrumentation hooks defined in the calling shared library are then registered with LTTng UST.

lttng_ust_dl_detach

Detaches the LTTng UST instrumentation library from a target process.

This function should be called before the dynamically loaded shared library is unloaded from the target process (e.g., using dlclose(3)).

All instrumentation hooks registered by this library are unregistered from LTTng UST.

BUGS

This functionality relies on the dynamic loading features of the C library and the operating system. Issues related to dynamic loading might affect the correct operation of these functions.
