LTTNG_UST_TRACELOG(3) Manuel LTTng LTTNG_UST_TRACELOG(3)

NOM

lttng_ust_tracelog, lttng_ust_vtracelog - Interface LTTng-UST de type printf(3) avec un niveau de journalisation

SYNTAXE

#include <lttng/tracelog.h>
#define lttng_ust_tracelog(level, fmt, ...)
#define lttng_ust_vtracelog(level, fmt, ap)

Lier avec :

•-llttng-ust
•Si vous définissez _LGPL_SOURCE avant d'inclure <lttng/tracelog.h> (directement ou indirectement) : -llttng-ust-common

DESCRIPTION

L'API LTTng-UST lttng_ust_tracelog() et lttng_ust_vtracelog() vous permet de tracer votre application à l'aide de macros simples de type printf(3) et vprintf(3), avec un paramètre supplémentaire pour le niveau de journalisation désiré.

L'argument fmt est passé directement comme paramètre fmt de vasprintf(3), ainsi que :

Pour lttng_ust_tracelog()

Les paramètres optionnels suivant fmt.

Pour lttng_ust_vtracelog()

Le paramètre ap comme paramètre ap de vasprintf(3) (type va_list).

Le but de lttng_ust_tracelog() et lttng_ust_vtracelog() est de faciliter la migration de la journalisation au traçage.

Les valeurs disponibles pour le paramètre level sont :

LTTNG_UST_TRACEPOINT_LOGLEVEL_EMERG

Le système est inutilisable.

LTTNG_UST_TRACEPOINT_LOGLEVEL_ALERT

Une action doit être prise immédiatement.

LTTNG_UST_TRACEPOINT_LOGLEVEL_CRIT

Conditions critiques.

LTTNG_UST_TRACEPOINT_LOGLEVEL_ERR

Conditions d'erreur.

LTTNG_UST_TRACEPOINT_LOGLEVEL_WARNING

Conditions d'avertissement.

LTTNG_UST_TRACEPOINT_LOGLEVEL_NOTICE

Condition normale, mais significative.

LTTNG_UST_TRACEPOINT_LOGLEVEL_INFO

Message informatif.

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_SYSTEM

Informations de débogage avec une portée système (ensemble de programmes).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_PROGRAM

Informations de débogage avec une portée de programme (ensemble de processus).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_PROCESS

Informations de débogage avec une portée de processus (ensemble de modules).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_MODULE

Informations de débogage avec une portée de module (exécutable/bibliothèque) (ensemble d'unités).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_UNIT

Informations de débogage avec une portée d'unité de compilation (ensemble de fonctions).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_FUNCTION

Informations de débogage avec une portée de fonction.

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_LINE

Informations de débogage avec une portée de ligne (niveau de journalisation par défaut).

LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG

Message de niveau débogage.

Pour utiliser lttng_ust_tracelog() ou lttng_ust_vtracelog(), incluez <lttng/tracelog.h> où vous en avez besoin, et liez votre application avec liblttng-ust et liblttng-ust-common. Voir la section EXEMPLE ci-dessous pour un exemple d'utilisation complet.

Une fois votre application instrumentée avec des appels lttng_ust_tracelog() et/ou lttng_ust_vtracelog() et prête à être exécutée, utilisez lttng-enable-event(1) pour activer l'événement lttng_ust_tracelog:*. Vous pouvez isoler des niveaux de journalisation spécifiques avec les options --loglevel et --loglevel-only de cette commande.

Les événements lttng_ust_tracelog() et lttng_ust_vtracelog() contiennent les champs suivants :

Nom du champ Description
line Ligne dans le fichier source où lttng_ust_tracelog() a été appelé.
file Fichier source depuis lequel lttng_ust_tracelog() a été appelé.
func Nom de la fonction depuis laquelle lttng_ust_tracelog() a été appelé.
msg Sortie de chaîne formatée.

Si vous n'avez pas besoin d'associer un niveau de journalisation spécifique à un appel lttng_ust_tracelog()/lttng_ust_vtracelog(), utilisez plutôt lttng_ust_tracef(3).

Voir aussi la section LIMITATIONS ci-dessous pour les limitations importantes à prendre en compte lors de l'utilisation de lttng_ust_tracelog() ou lttng_ust_vtracelog().

EXEMPLE

Voici un exemple d'utilisation de lttng_ust_tracelog() :

#include <stdlib.h>
#include <lttng/tracelog.h>
int main(int argc, char *argv[])
{
    int i;
    if (argc < 2) {
        lttng_ust_tracelog(LTTNG_UST_TRACEPOINT_LOGLEVEL_CRIT,
                           "Pas assez d'arguments : %d", argc);
        return EXIT_FAILURE;
    }
    lttng_ust_tracelog(LTTNG_UST_TRACEPOINT_LOGLEVEL_INFO,
                       "Démarrage de l'application avec %d arguments", argc);
    for (i = 0; i < argc; i++) {
        lttng_ust_tracelog(LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG,
                           "Argument %d : %s", i, argv[i]);
    }
    lttng_ust_tracelog(LTTNG_UST_TRACEPOINT_LOGLEVEL_INFO,
                       "Fermeture de l'application");
    return EXIT_SUCCESS;
}

Ce fichier source C, enregistré sous le nom app.c, peut être compilé en un programme comme suit :

$ cc -o app app.c -llttng-ust -llttng-ust-common

Vous pouvez créer une session de traçage LTTng, activer tous les événements lttng_ust_tracelog(), et démarrer la session de traçage créée comme suit :

$ lttng create my-session
$ lttng enable-event --userspace 'lttng_ust_tracelog:*'
$ lttng start

Ou vous pouvez activer les événements lttng_ust_tracelog() correspondant à un niveau de journalisation au moins aussi sévère qu'un niveau donné :

$ lttng enable-event --userspace 'lttng_ust_tracelog:*' \
                     --loglevel=INFO

Ensuite, démarrez le programme à tracer :

$ ./app a few arguments passed to this application

Enfin, arrêtez la session de traçage et inspectez les événements enregistrés :

$ lttng stop
$ lttng view

LIMITATIONS

Les macros utilitaires lttng_ust_tracelog() et lttng_ust_vtracelog() ont été développées pour rendre le traçage en espace utilisateur extrêmement simple, bien qu'avec des inconvénients notables par rapport aux fournisseurs de points de trace personnalisés et complets :

•Tous les événements générés ont les mêmes noms de fournisseur/événement.
•Il n'y a pas de vérification statique des types.
•Le seul champ d'événement avec des données utilisateur que vous obtenez réellement, nommé msg, est une chaîne contenant potentiellement les valeurs que vous avez passées à la macro en utilisant votre propre format. Cela signifie également que vous ne pouvez pas utiliser le filtrage avec une expression personnalisée à l'exécution car il n'y a pas de champs isolés.
•Étant donné que lttng_ust_tracelog() et lttng_ust_vtracelog() utilisent en arrière-plan la fonction vasprintf(3) de la bibliothèque standard C pour formater les chaînes à l'exécution, leurs performances attendues sont inférieures à celles des fournisseurs de points de trace personnalisés avec des champs typés, qui ne nécessitent pas de conversion en chaîne.
•En général, une chaîne contenant la représentation textuelle des champs de données utilisateur n'est pas aussi compacte que des champs binaires dans la trace résultante.

Par conséquent, lttng_ust_tracelog()/lttng_ust_vtracelog() sont utiles pour le prototypage et le débogage rapides, mais ne devraient pas être considérés pour une instrumentation d'application permanente/sérieuse.

n.

lttng_ust_vtracelog() n'a pas d'appel STAP_PROBEV(), car STAP_PROBEV() ne prend pas en charge va_list. Si vous en avez besoin, vous devez émettre cet appel vous-même.

Voir lttng-ust(3) pour en savoir plus sur les fournisseurs de points de trace personnalisés.
