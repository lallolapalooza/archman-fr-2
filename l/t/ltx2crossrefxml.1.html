NOM

ltx2crossrefxml.pl - créer des fichiers XML pour soumission à crossref.org

SYNOPIS

ltx2crossrefxml [-c fichier_config] [-o fichier_sortie] [-input-is-xml]
fichier_latex1 fichier_latex2 ...

OPTIONS

-c fichier_config
Fichier de configuration. Si ce fichier est absent, les valeurs par défaut sont utilisées. Voir ci-dessous pour son format.
-o fichier_sortie
Fichier de sortie. Si cette option n'est pas utilisée, le XML est envoyé vers la sortie standard.
-input-is-xml
Ne pas transformer les chaînes d'auteur et de titre, suppose qu'elles sont un XML valide.

Les options habituelles "--help" et "--version" sont également prises en charge. Les options peuvent commencer par "-" ou "--", et être ordonnées arbitrairement.

DESCRIPTION

Pour chaque fichier_latex donné, ce script lit les fichiers ".rpi" et (s'ils existent) ".bbl" et génère le XML correspondant qui peut être téléchargé sur Crossref (https://crossref.org). Toute extension de fichier_latex est ignorée, et le fichier_latex lui-même n'est pas lu (et n'a même pas besoin d'exister).

Chaque fichier ".rpi" spécifie les métadonnées d'un seul article à soumettre à Crossref (un élément "journal_article" dans leur schéma) ; un exemple est ci-dessous. Ces fichiers sont générés par le package "resphilosophica" (https://ctan.org/pkg/resphilosophica) et par la procédure de publication de TUGboat (https://tug.org/TUGboat/repository.html), mais (comme toujours) peuvent également être créés à la main ou par toute autre méthode que vous implémentez.

Tous les fichiers ".bbl" présents sont utilisés pour les informations de citation dans le XML de sortie. Voir la section CITATIONS ci-dessous.

Sauf si "--input-is-xml" est spécifié, pour tout texte (auteurs, titre, citations), les séquences de contrôle standard TeX sont remplacées par du texte brut ou de l'UTF-8, ou éliminées, selon le cas. La routine "LaTeX::ToUnicode::convert" est utilisée pour cela (https://ctan.org/pkg/bibtexperllibs). Les séquences de contrôle TeX complexes ne seront presque certainement pas traitées correctement.

Si "--input-is-xml" est donné, les chaînes d'auteur et de titre des fichiers rpi sont générées telles quelles, en supposant qu'elles sont un XML valide ; aucune vérification n'est effectuée.

Le texte de citation des fichiers ".bbl" est toujours converti de LaTeX en texte brut.

Ce script écrit simplement un fichier XML. Il vous appartient de effectuer le téléchargement vers Crossref ; par exemple, vous pouvez utiliser leur outil Java "crossref-upload-tool.jar" (https://www.crossref.org/education/member-setup/direct-deposit-xml/https-post).

Pour la définition du schéma Crossref actuellement généré par ce script, voir https://data.crossref.org/reports/help/schema_doc/5.3.1/index.html avec des liens et informations supplémentaires à https://www.crossref.org/documentation/schema-library/metadata-deposit-schema-5-3-1/.

FORMAT DU FICHIER DE CONFIGURATION

Le fichier de configuration est lu comme du code Perl. Ainsi, les lignes de commentaires commençant par "#" et les lignes vides sont ignorées. Les autres lignes sont typiquement des assignations de la forme (les espaces sont optionnels) :

$variable = valeur ;

Généralement, la valeur est une "chaîne" entourée de guillemets doubles ou simples ASCII, selon la syntaxe Perl. L'idée est de spécifier les valeurs spécifiques à l'utilisateur et au journal nécessaires pour le téléchargement Crossref. Les variables utilisées sont les suivantes :

$depositorName = "Nom du déposant";
$depositorEmail = 'depositor@example.org';
$registrant = 'Organisme';  # nom de l'organisation
$fullTitle = "TITRE COMPLET";   # nom du journal
$issn = "1234-5678";         # requis
$abbrevTitle = "TITRE ABRÉGÉ"; # optionnel
$coden = "CODEN";            # optionnel

Pour une exécution donnée, toutes les données ".rpi" lues sont supposées appartenir au journal spécifié dans le fichier de configuration. Plus précisément, les données de configuration sont écrites comme un élément "journal_metadata", avec le "full_title", "issn", etc., donnés, puis chaque ".rpi" est écrit comme "journal_issue" plus des éléments "journal_article".

Le fichier de configuration peut également définir une fonction Perl : "LaTeX_ToUnicode_convert_hook". Si elle est définie, elle est appelée au début de la procédure qui convertit le texte LaTeX en Unicode, effectuée avec le module LaTeX::ToUnicode, du package "bibtexperllibs" (https://ctan.org/pkg/bibtexperllibs). La fonction doit accepter une chaîne (le texte LaTeX) et retourner une chaîne (vraisemblablement la chaîne transformée). Les conversions standard sont ensuite appliquées à la chaîne retournée, de sorte que la fonction configurée n'ait besoin de gérer que des cas spéciaux, tels que des séquences de contrôle propres au journal concerné.

FORMAT DU FICHIER RPI

Voici (la partie pertinente du) fichier ".rpi" correspondant à l'exemple "rpsample.tex" du package "resphilosophica" (https://ctan.org/pkg/resphilosophica):

%authors=Boris Veytsman\and A. U. Th{\o }r\and C. O. R\"espondent
%title=A Sample Paper:\\ \emph  {A Template}
%year=2012
%volume=90
%issue=1--2
%startpage=1
%endpage=1
%doi=10.11612/resphil.A31245
%paperUrl=http://borisv.lk.net/paper12
%publicationType=full_text

Les autres lignes, certaines ne commençant pas par %, sont ignorées (et non montrées). Pour plus de détails sur le traitement, voir le code.

La valeur de %paperUrl est ce qui sera associé au %doi donné (généré comme élément "resource"). Crossref recommande fortement que l'URL soit celle d'une page de destination (landing page), et non directement celle d'un pdf (https://www.crossref.org/education/member-setup/creating-a-landing-page/). Cas spécial : si l'URL n'est pas spécifiée, et que le journal est Res Philosophica, une URL de recherche à usage spécifique utilisant pdcnet.org est retournée. Tout autre journal doit toujours spécifier ceci.

Le champ %authors est divisé à "\and" (en ignorant les espaces avant et après), et généré comme élément "contributors", en utilisant "sequence="first"" pour le premier listé, "sequence="additional"" pour le reste. Les auteurs sont analysés en utilisant "BibTeX::Parser::Author" (https://ctan.org/pkg/bibtexperllibs).

Si %publicationType n'est pas spécifié, il prend par défaut la valeur "full_text", car cela a été le cas historiquement ; "full_text" peut également être donné explicitement. Les autres valeurs autorisées par le schéma Crossref sont "abstract_only" et "bibliographic_record". Finalement, si la valeur est "omit", l'élément "publication_type"

Chaque ".rpi" doit contenir des informations pour un seul article, mais plusieurs fichiers peuvent être lus en une seule exécution. Il ne serait pas difficile de prendre en charge plusieurs articles dans un seul fichier ".rpi", mais cela rend le débogage et la correction des erreurs plus faciles en conservant l'entrée à un article par fichier.

PLUS D'INFORMATIONS SUR LES NOMS D'AUTEURS

Les trois formats de noms reconnus sont (ce n'est pas un hasard) les mêmes que ceux de BibTeX :

Prénom von Nom
von Nom, Prénom
von Nom, Jr., Prénom

Les formes peuvent être librement mélangées sur une seule ligne %authors, séparées par "\and" (y compris la barre oblique inverse). Les virgules comme séparateurs de noms ne sont pas prises en charge, contrairement à BibTeX.

En bref, vous pouvez presque toujours utiliser la première forme ; vous ne devriez pas le faire si une partie Jr. est présente, ou si la partie Nom est composée de plusieurs jetons mais qu'il n'y a pas de partie von. Voir le document "btxdoc" (``BibTeXing'' par Oren Patashnik) pour plus de détails. Les auteurs sont analysés en utilisant "BibTeX::Parser::Author" (https://ctan.org/pkg/bibtexperllibs).

Dans la ligne %authors d'un fichier ".rpi", certaines directives secondaires sont reconnues, indiquées par des caractères "|". Plus facile à expliquer avec un exemple :

%authors=|organization|\LaTeX\ Project Team \and Alex Brown|orcid=123

Ainsi : 1) si "|organization|" est spécifié, le nom de l'auteur sera affiché comme un contributeur "organization", au lieu du "person_name" habituel, comme l'exige le schéma Crossref.

2) Si "|orcid=valeur|" est spécifié, la valeur est affichée comme un élément "ORCID" pour ce "person_name".

Ces deux directives, "|organization"| et "| orcid|" sont mutuellement exclusives, car c'est ainsi que le schéma Crossref les définit. Le signe "=" après " orcid" est obligatoire, tandis que tous les espaces après le mot-clé " orcid" sont ignorés. Sinon, la valeur ORCID est affichée littéralement. (Par exemple, la valeur ORCID de 123 ci-dessus est clairement invalide, mais elle serait affichée quand même, sans avertissement.)

Des caractères "|" supplémentaires, au début ou à la fin de toute la chaîne %authors, ou doublés au milieu, sont acceptés et ignorés. Les espaces blancs sont ignorés autour de tous les caractères "|".

CITATIONS

Chaque fichier ".bbl" correspondant à un fichier ".rpi" d'entrée est lu et utilisé pour générer un élément "citation_list" pour cet "journal_article" dans le XML de sortie. Si aucun fichier ".bbl" n'existe pour un ".rpi" donné, aucune "citation_list" n'est générée pour cet article.

Le traitement de ".bbl" est rudimentaire : seules des références dites "unstructured_citation" sont produites pour Crossref, c'est-à-dire que le contenu de la citation (chaque paragraphe du ".bbl") est déversé sous forme d'une seule chaîne plate sans balisage.

Le texte de la bibliographie est inconditionnellement converti de TeX en XML, via la méthode décrite ci-dessus. Il n'est pas rare que la conversion soit incomplète ou incorrecte. Il vous appartient de vérifier cela ; par exemple, si des barres obliques inverses subsistent dans la sortie, il s'agit très probablement d'une erreur.

De plus, il est supposé que le fichier ".bbl" contient une séquence de références, chacune commençant par "\bibitem{CLÉ}" (qui doit elle-même être au début d'une ligne, précédée uniquement d'espaces blancs), et que toute la bibliographie se termine par "\end{thebibliography}" (de manière similaire au début d'une ligne). Une bibliographie ne respectant pas ce format ne produira pas de résultats utiles. Les bibliographies peuvent être créées à la main, avec BibTeX, ou par toute autre méthode.

L'attribut "key" de l'élément "citation" est pris comme argument CLÉ de la commande "\bibitem". Le numéro séquentiel de la citation (1, 2, ...) est ajouté. L'argument de "\bibitem" peut être vide ("\bibitem{}", et le numéro de séquence sera utilisé seul. Bien que TeX ne traite pas les clés "\bibitem" vides, cela peut être pratique lors de la création d'un ".bbl" uniquement pour Crossref.

Le fichier ".rpi" est également vérifié pour les informations bibliographiques, dans ce même format.

Demande de fonctionnalité : si quelqu'un est intéressé par la façon de générer des citations structurées (https://data.crossref.org/reports/help/schema_doc/5.3.1/common5_3_1_xsd.html#citation), ce serait formidable. Le schéma ne prend pas en charge de nombreux champs utiles, nous voulons donc également conserver la sortie de texte non structurée.

Le programme beastie de Norman Gray (https://heptapod.host/nxg/beastie) le prend en charge, via "beastie extract-bib.scm -O crossref $(doc).aux", comme appelé dans le fichier TUGboat "Common.mak". Travail en cours.

Soit dit en passant, si pour une raison quelconque nous devons cesser d'utiliser beastie, l'approche la plus viable serait probablement de modifier "tugboat.bst" pour générer des commandes TeX sans effet comme \tubibauthor, \tubibtitle, etc. (à la manière de biblatex), et d'utiliser ces commandes pour discerner les différentes valeurs de champs crossref. Nous ne pouvons pas commencer à partir du .bib car nous devrions alors réimplémenter Bib(La)TeX.

EXEMPLES

ltx2crossrefxml.pl ../paper1/paper1.tex ../paper2/paper2.tex \
                    -o result.xml
ltx2crossrefxml.pl -c myconfig.cfg paper.tex -o paper.xml
