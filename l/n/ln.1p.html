LN(1P) Manuel du programmeur POSIX LN(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ln — lier des fichiers

SYNOPIS

ln [-fs] [-L|-P] fichier_source cible_fichier
ln [-fs] [-L|-P] fichier_source... répertoire_cible

DESCRIPTION

Dans la première forme de synopsis, l'utilitaire ln crée une nouvelle entrée de répertoire (lien) à l'emplacement de destination spécifié par l'opérande cible_fichier. Si l'option -s est spécifiée, un lien symbolique est créé pour le fichier spécifié par l'opérande fichier_source. Cette première forme de synopsis est supposée lorsque le dernier opérande ne nomme pas un répertoire existant ; si plus de deux opérandes sont spécifiés et que le dernier n'est pas un répertoire existant, une erreur se produit.

Dans la seconde forme de synopsis, l'utilitaire ln crée une nouvelle entrée de répertoire (lien), ou si l'option -s est spécifiée un lien symbolique, pour chaque fichier spécifié par un opérande fichier_source, à une destination dans le répertoire existant nommé par répertoire_cible.

Si le dernier opérande spécifie un fichier existant d'un type non spécifié par le volume Interfaces Système de POSIX.1‐2017, le comportement est défini par l'implémentation.

Le chemin de destination correspondant pour chaque fichier_source est la concaténation du chemin du répertoire cible, d'un caractère <slash> si le chemin du répertoire cible ne se terminait pas par un <slash>, et du dernier composant de chemin du fichier_source. La seconde forme de synopsis est supposée lorsque le dernier opérande nomme un répertoire existant.

Pour chaque fichier_source :

1.
Si la destination existe et a été créée par une étape précédente, il est indéterminé si ln écrira un message de diagnostic sur la sortie d'erreur standard, ne fera rien de plus avec le fichier_source courant, et passera aux fichier_source suivants ; ou continuera le traitement du fichier_source courant. Si la destination existe :
a.
Si l'option -f n'est pas spécifiée, ln écrira un message de diagnostic sur la sortie d'erreur standard, ne fera rien de plus avec le fichier_source courant, et passera aux fichier_source suivants.
b.
Si la destination nomme la même entrée de répertoire que le fichier_source courant, ln écrira un message de diagnostic sur la sortie d'erreur standard, ne fera rien de plus avec le fichier_source courant, et passera aux fichier_source suivants.
c.
Des actions équivalentes à la fonction unlink() définie dans le volume Interfaces Système de POSIX.1‐2017 seront effectuées, en utilisant le chemin de destination comme argument path. Si cela échoue pour une raison quelconque, ln écrira un message de diagnostic sur la sortie d'erreur standard, ne fera rien de plus avec le fichier_source courant, et passera aux fichier_source suivants.
2.
Si l'option -s est spécifiée, des actions équivalentes à la fonction symlink() avec fichier_source comme argument path1 et le chemin de destination comme argument path2 seront effectuées. L'utilitaire ln ne fera rien de plus avec fichier_source et passera aux fichiers suivants.
3.
Si fichier_source est un lien symbolique :
a.
Si l'option -P est en vigueur, des actions équivalentes à la fonction linkat() avec fichier_source comme argument path1, le chemin de destination comme argument path2, AT_FDCWD comme arguments fd1 et fd2, et zéro comme argument flag seront effectuées.
b.
Si l'option -L est en vigueur, des actions équivalentes à la fonction linkat() avec fichier_source comme argument path1, le chemin de destination comme argument path2, AT_FDCWD comme arguments fd1 et fd2, et AT_SYMLINK_FOLLOW comme argument flag seront effectuées.

L'utilitaire ln ne fera rien de plus avec fichier_source et passera aux fichiers suivants.

4.
Des actions équivalentes à la fonction link() définie dans le volume Interfaces Système de POSIX.1‐2017 seront effectuées en utilisant fichier_source comme argument path1, et le chemin de destination comme argument path2.

OPTIONS

L'utilitaire ln se conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire.

Les options suivantes seront prises en charge :

-f
Forcer la suppression des noms de chemin de destination existants pour permettre la liaison.
-L
Pour chaque opérande fichier_source qui nomme un fichier de type lien symbolique, créer un lien (physique) vers le fichier référencé par le lien symbolique.
-P
Pour chaque opérande fichier_source qui nomme un fichier de type lien symbolique, créer un lien (physique) vers le lien symbolique lui-même.
-s
Créer des liens symboliques au lieu de liens physiques. Si l'option -s est spécifiée, les options -L et -P seront ignorées silencieusement.

La spécification de plus d'une des options mutuellement exclusives -L et -P ne sera pas considérée comme une erreur. La dernière option spécifiée déterminera le comportement de l'utilitaire (sauf si l'option -s fait qu'elle est ignorée).

Si l'option -s n'est pas spécifiée et qu'aucune option -L ni -P n'est spécifiée, il est défini par l'implémentation laquelle des options -L et -P sera utilisée par défaut.

OPERANDES

Les opérandes suivants seront pris en charge :

fichier_source
Un nom de chemin d'un fichier à lier. Si l'option -s est spécifiée, aucune restriction sur le type de fichier ou sur son existence ne sera faite. Si l'option -s n'est pas spécifiée, le fait qu'un répertoire puisse être lié est défini par l'implémentation.
cible_fichier
Le nom de chemin de la nouvelle entrée de répertoire à créer.
répertoire_cible
Un nom de chemin d'un répertoire existant dans lequel les nouvelles entrées de répertoire sont créées.

STDIN

Non utilisé.

FICHIERS ENTRÉE

Aucun.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de ln :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de localisation.)
LC_ALL
Si elle est définie sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la localisation pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments).

PROLOG

This section is informative.

NAME

ln - link files

SYNOPSIS

ln [-f] [-i] [-L|-P] source_file target_file

ln [-f] [-i] [-L|-P] source_file ... target_directory

ln [-s] [-f] [-i] [-L|-P] source_file target_file

ln [-s] [-f] [-i] [-L|-P] source_file ... target_directory

DESCRIPTION

The ln utility shall create a new reference (link) to a file. This utility is compatible with the shell command language. For each target_file that does not exist, a link is created in the target_directory. Otherwise, if target_file exists and is a regular file, a link named target_file is created.

By default, ln creates a hard link. If the -s option is specified, ln creates a symbolic link.

When creating a hard link, the link count of the referenced file shall be incremented. The link count is a count of the number of references to the file. When the link count reaches zero, the file is discarded.

The source_file is the existing file that is to be linked. The target_file is the name of the new link file. The target_directory is the directory in which to create the new link files.

See the Rationale section for details on the differences between this volume of POSIX.1‐2017 and historical versions of ln.

OPTIONS

The ln utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines.

-f
Attempt to remove each existing destination file that is specified by target_file. If the link cannot be made because the destination file exists and is not a regular file or a symbolic link, and the mode of the destination file does not permit writing, ln shall not attempt to prompt for confirmation. If the destination file exists and is not a regular file or a symbolic link and the mode of the destination file permits writing, then ln shall attempt to remove the destination file and create the new link.
-i
Prompt before overwriting an existing destination file. If the user responds with a file name character (e.g., 'y' or 'Y'), the existing destination file is removed, and the link is made. Otherwise, the link is not made.
-L
If a source_file is a symbolic link, follow the symbolic link. This is the default behavior.
-P
If a source_file is a symbolic link, do not follow the symbolic link. A symbolic link to the source_file shall be created.
-s
Create a symbolic link instead of a hard link.

OPERANDS

The following operands are supported:

source_file
A pathname of an existing file that is to be linked.
target_file
A pathname of the new link file to be created.
target_directory
A pathname of a directory in which to create the new link files.

STDIN

Not used.

INPUT FILES

None.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of ln:

LC_COLLATE
Determine the collation order to be used for determining the sorting order of filenames when multiple filenames are specified for processing.
LC_MESSAGES

Determine the locale that should be used to affect the format and contents of diagnostic messages written to standard error.
NLSPATH
Determine the location of message catalogs for the processing of LC_MESSAGES.

ASYNCHRONOUS EVENTS

Default.

STDOUT

Not used.

STDERR

The standard error shall be used only for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

 0
All the specified files were linked successfully.
>0
An error occurred.

RATIONALE

The CONSEQUENCES OF ERRORS section does not require ln -f a b to remove b if a subsequent link operation would fail.

Some historic versions of ln (including the one specified by the SVID) unlink the destination file, if it exists, by default. If the mode does not permit writing, these versions prompt for confirmation before attempting the unlink. In these versions the -f option causes ln not to attempt to prompt for confirmation.

This allows ln to succeed in creating links when the target file already exists, even if the file itself is not writable (although the directory must be). Early proposals specified this functionality.

This volume of POSIX.1‐2017 does not allow the ln utility to unlink existing destination paths by default for the following reasons:

*
The ln utility has historically been used to provide locking for shell applications, a usage that is incompatible with ln unlinking the destination path by default. There was no corresponding technical advantage to adding this functionality.
*
This functionality gave ln the ability to destroy the link structure of files, which changes the historical behavior of ln.
*
This functionality is easily replicated with a combination of rm and ln.
*
It is not historical practice in many systems; BSD and BSD-derived systems do not support this behavior. Unfortunately, whichever behavior is selected can cause scripts written expecting the other behavior to fail.
*
It is preferable that ln perform in the same manner as the link() function, which does not permit the target to exist already.

This volume of POSIX.1‐2017 retains the -f option to provide support for shell scripts depending on the SVID semantics. It seems likely that shell scripts would not be written to handle prompting by ln and would therefore have specified the -f option.

The -f option is an undocumented feature of many historical versions of the ln utility, allowing linking to directories. These versions require modification.

Early proposals of this volume of POSIX.1‐2017 also required a -i option, which behaved like the -i options in cp and mv, prompting for confirmation before unlinking existing files. This was not historical practice for the ln utility and has been omitted.

The -L and -P options allow for implementing both common behaviors of the ln utility. Earlier versions of this standard did not specify these options and required the behavior now described for the -L option. Many systems by default or as an alternative provided a non-conforming ln utility with the behavior now described for the -P option. Since applications could not rely on ln following links in practice, the -L and -P options were added to specify the desired behavior for the application.

The -L and -P options are ignored when -s is specified in order to allow an alias to be created to alter the default behavior when creating hard links (for example, alias ln='ln -L'). They serve no purpose when -s is specified, since source_file is then just a string to be used as the contents of the created symbolic link and need not exist as a file.

The specification ensures that ln a a with or without the -f option will not unlink the file a. Earlier versions of this standard were unclear in this case.
