LNDIR(1) Manuel des commandes générales LNDIR(1)

NOM

lndir - créer un répertoire miroir de liens symboliques vers un autre arbre de répertoires

SYNTAXE

lndir [ -silent ] [ -ignorelinks ] [ -withrevinfo ] fromdir [ todir ]

DESCRIPTION

Le programme lndir crée une copie miroir todir d'un arbre de répertoires fromdir, sauf que le miroir n'est pas peuplé de fichiers réels mais plutôt de liens symboliques pointant vers les fichiers réels dans l'arbre de répertoires fromdir. Ceci est généralement utile pour maintenir le code source pour différentes architectures de machine. Vous créez un répertoire miroir contenant des liens vers la source réelle, que vous aurez probablement montée depuis une machine distante. Vous pouvez compiler dans l'arbre miroir, et les fichiers objets seront dans le répertoire miroir, tandis que les fichiers sources dans le répertoire miroir ne sont que des liens symboliques vers les fichiers réels.

Ce schéma a l'avantage que si vous mettez à jour la source, vous n'avez pas besoin de propager manuellement le changement aux autres architectures, car toutes les sources dans tous les répertoires miroirs sont des liens symboliques vers la chose réelle : il suffit de se déplacer vers le répertoire miroir et de recompiler.

L'argument todir est optionnel et prend par défaut le répertoire courant. L'argument fromdir peut être relatif (par exemple, ../src) et est relatif à todir (pas au répertoire courant).

Notez que les répertoires BitKeeper, CVS, CVS.adm, .git, .hg, RCS, SCCS et .svn ne sont mis en miroir que si l'option -withrevinfo est spécifiée. Les fichiers dont le nom se termine par ~ ne sont jamais mis en miroir.

Si vous ajoutez des fichiers, exécutez simplement lndir à nouveau. Les nouveaux fichiers seront ajoutés silencieusement. Les anciens fichiers seront vérifiés pour s'assurer qu'ils ont le bon lien.

La suppression de fichiers est un problème plus délicat ; les liens symboliques pointeront simplement vers un "pays de nulle part".

Si un fichier dans fromdir est un lien symbolique, lndir créera le même lien dans todir au lieu de créer un lien vers l'entrée (lien symbolique) dans fromdir. L'option -ignorelinks modifie ce comportement.

OPTIONS

-silent
Normalement, lndir affiche le nom de chaque sous-répertoire lorsqu'il y descend. L'option -silent supprime ces messages de statut.
-ignorelinks
Induit le programme à ne pas traiter les liens symboliques dans fromdir spécialement. Le lien créé dans todir pointera vers le fichier correspondant (lien symbolique) dans fromdir. Si le lien pointe vers un répertoire, c'est presque certainement indésirable.
Cette option existe principalement pour émuler le comportement de la version C de lndir dans X11R6. Son utilisation n'est pas recommandée.
-withrevinfo
Induit tout sous-répertoire de gestion de source (nommé BitKeeper, CVS, CVS.adm, .git, .hg, RCS, SCCS ou .svn) à être traité comme tout autre répertoire, plutôt qu'à être ignoré.

DIAGNOSTICS

Le programme affiche le nom de chaque sous-répertoire qu'il entre, suivi d'un deux-points. L'option -silent supprime ces messages.

Un message d'avertissement s'affiche si le lien symbolique ne peut pas être créé. Le problème habituel est qu'un fichier régulier du même nom existe déjà.

Si le lien existe déjà mais ne pointe pas vers le bon fichier, le programme affiche le nom du lien et l'emplacement où il pointe.
