NOM

lxc-copy - copie un conteneur existant.

SYNTAXE

lxc-copy

lxc-copy
{-n, --name nom} [-P, --lxcpath chemin] [-N, --newname nouveau_nom] [-p, --newpath nouveau_chemin] {-R, --rename}

DESCRIPTION

lxc-copy crée et démarre éventuellement (éphémère ou non) des copies de conteneurs existants.

lxc-copy crée des copies de conteneurs existants. Les copies peuvent être des clones complets du conteneur d'origine. Dans ce cas, tout le système de fichiers racine du conteneur est simplement copié vers le nouveau conteneur. Ou elles peuvent être des snapshots, c'est-à-dire de petites copies en copie-sur-écriture (copy-on-write) du conteneur d'origine. Dans ce cas, le stockage sous-jacent spécifié pour la copie doit supporter les snapshots. Cela inclut actuellement btrfs, lvm (les périphériques lvm ne supportent pas les snapshots de snapshots.), overlay et zfs.

Le stockage sous-jacent de la copie sera du même type que celui du conteneur d'origine. Les snapshots overlay de conteneurs basés sur des répertoires sont exemptés de cette règle.

Lorsque le drapeau -e est spécifié, un snapshot éphémère du conteneur d'origine est créé et démarré. Les conteneurs éphémères auront lxc.ephemeral = 1 défini dans leur fichier de configuration et seront détruits lors de l'arrêt. Lorsque -e est utilisé en combinaison avec -D, un snapshot non éphémère du conteneur d'origine est créé et démarré. Les conteneurs éphémères peuvent également être placés sur un tmpfs avec le drapeau -t. REMARQUE : Si un conteneur éphémère placé sur un tmpfs est redémarré, toutes les modifications apportées seront perdues !

Lorsque -e est spécifié et qu'aucun nouveau nom n'est donné via -N, un nom aléatoire sera choisi pour le snapshot.

Les conteneurs créés et démarrés avec -e peuvent avoir des montages personnalisés. Ceux-ci sont spécifiés avec le drapeau -m. Actuellement, deux types de montages sont supportés : bind et overlay. Les types de montage sont spécifiés comme sous-options du drapeau -m et peuvent être spécifiés plusieurs fois séparés par des virgules. Les montages overlay sont actuellement spécifiés sous la forme -m overlay=/src:/dest. Lorsque aucune destination dest n'est spécifiée, dest sera identique à src. Les montages bind en lecture seule sont spécifiés -m bind=/src:/dest:ro et les montages bind en lecture-écriture -m bind=/src:/dest:rw. Les montages bind en lecture-écriture sont les valeurs par défaut et rw peut être omis lorsqu'un montage en lecture-écriture est souhaité. Lorsque dest est omis, dest sera identique à src. Un exemple pour plusieurs montages serait -m bind=/src1:/dest1:ro,bind=/src2:ro,overlay=/src3:/dest3.

Les montages, leurs options et les formats supportés via le drapeau -m sont sujets à modification.

OPTIONS

-N,--newname nouveau_nom
Le nom de la copie.
-p,--newpath nouveau_chemin
Le chemin de la copie.
-R,--rename
Renommer le conteneur d'origine.
-s,--snapshot
Créer un snapshot du conteneur d'origine. Le stockage sous-jacent de la copie doit supporter les snapshots. Cela inclut actuellement btrfs, lvm, overlay et zfs.
-a,--allowrunning
Autoriser la création d'un snapshot d'un conteneur déjà en cours d'exécution. Cela peut causer une corruption ou une perte de données selon le système de fichiers et les applications utilisés. À utiliser avec prudence.
-F,--foreground
Exécuter le snapshot en premier plan. La console du snapshot sera attachée au tty courant. (Cette option ne peut être spécifiée qu'en conjonction avec -e.)
-d, --daemon
Exécuter le snapshot en tant que démon (C'est le mode par défaut pour les conteneurs éphémères.). Comme le conteneur n'a plus de tty, si une erreur se produit, rien ne sera affiché, le fichier journal peut être utilisé pour vérifier l'erreur. (Cette option ne peut être spécifiée qu'en conjonction avec -e.)
-m, --mount type_montage
Spécifier un montage pour un snapshot. Les options pour le type de montage peuvent être de type {bind, overlay}. Par exemple -m bind=/src:/dest:ro,overlay=/src:/dest (Cette option ne peut actuellement être spécifiée qu'en conjonction avec -e.).
-t, --tmpfs
Lorsque cette option est spécifiée, le conteneur éphémère sera placé sur un tmpfs. REMARQUE : Redémarrer un conteneur éphémère situé sur un tmpfs entraînera la perte de toutes les modifications apportées. Ce drapeau ne fonctionnera que pour les conteneurs éphémères créés avec le drapeau -e. Le conteneur d'origine, à partir duquel le snapshot éphémère est créé, doit être stocké comme un simple répertoire.
-B, --backingstorage stockage_sous-jacent
Spécifier le type de stockage sous-jacent à utiliser pour la copie où 'stockage_sous-jacent' est de type 'btrfs', 'dir', 'lvm', 'loop', 'overlay', ou 'zfs'.
-L, --fssize taille [unité]
Spécifier la taille pour un système de fichiers 'lvm'.
-K, --keepname
Lorsque cette option est spécifiée, le nom d'hôte du conteneur d'origine sera conservé pour la copie.
-D, --keepdata
Lorsque cette option est spécifiée avec -e, un conteneur non éphémère est créé et démarré.
-M, --keepmac
Lorsque cette option est spécifiée, l'adresse MAC du conteneur d'origine sera conservée pour la copie.

HOOK DE COPIE

Si le conteneur copié possède une ou plusieurs configurations lxc.hook.clone, alors les hooks spécifiés seront appelés pour le nouveau conteneur. Les 3 premiers arguments passés au hook de clone seront le nom du conteneur, une section ('lxc') et le type de hook ('clone'). Les arguments supplémentaires passés à lxc-copy seront passés au programme hook en commençant à l'argument 4. La variable d'environnement LXC_ROOTFS_MOUNT indique le chemin sous lequel le système de fichiers racine du conteneur est monté. Le chemin du fichier de configuration est stocké dans LXC_CONFIG_FILE, le nouveau nom du conteneur dans LXC_NAME, l'ancien nom du conteneur dans LXC_SRC_NAME, et le chemin ou le périphérique sur lequel se trouve le rootfs est dans LXC_ROOTFS_PATH.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes lxc.

-?, -h, --help
Imprimer un message d'utilisation plus long que la normale.
--usage
Donner le message d'utilisation
-q, --quiet
mode silencieux activé
-P, --lxcpath=CHEMIN
Utiliser un chemin alternatif pour les conteneurs. Le chemin par défaut est /var/lib/lxc.
-o, --logfile=FICHIER
Sortie vers un autre FICHIER de journalisation. Par défaut, pas de journal.
-l, --logpriority=NIVEAU
Définit la priorité du journal à NIVEAU. La priorité de journal par défaut est ERROR. Les valeurs possibles sont : FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Notez que cette option définit la priorité des événements enregistrés dans le fichier journal alternatif. Elle n'a aucun effet sur les événements ERROR enregistrés sur stderr.

-n, --name=NOM
Utilise l'identifiant de conteneur NOM. Le format de l'identifiant de conteneur est une chaîne alphanumérique.
--rcfile=FICHIER
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation du conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur créé précédemment (via lxc-create).

--version
Affiche le numéro de version.
