NOM

lxc-destroy - détruit un conteneur.

SYNTAXE


lxc-destroy
{-n nom} [-f] [-s]

DESCRIPTION

lxc-destroy détruit l'objet système précédemment créé par la commande lxc-create.

OPTIONS

-f, --force
Si un conteneur est en cours d'exécution, l'arrête d'abord. Si cette option n'est pas spécifiée et que le conteneur est en cours d'exécution, alors lxc-destroy sera abandonné.
-s, --snapshots
détruit le conteneur spécifié y compris tous ses snapshots.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes lxc.

-?, -h, --help
Affiche un message d'utilisation plus long que la normale.
--usage
Donne le message d'utilisation
-q, --quiet
silencieux activé
-P, --lxcpath=CHEMIN
Utilise un chemin de conteneur alternatif. Le défaut est /var/lib/lxc.
-o, --logfile=FICHIER
Sortie vers un fichier journal alternatif FICHIER. Le défaut est aucun journal.
-l, --logpriority=NIVEAU
Définit la priorité du journal à NIVEAU. La priorité du journal par défaut est ERROR. Les valeurs possibles sont : FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Notez que cette option définit la priorité des événements du journal dans le fichier journal alternatif. Elle n'a aucun effet sur le journal des événements ERROR sur stderr.

-n, --name=NOM
Utilise l'identifiant de conteneur NOM. Le format de l'identifiant de conteneur est une chaîne alphanumérique.
--rcfile=FICHIER
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation pour le conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur précédemment créé (via lxc-create).

--version
Affiche le numéro de version.

DIAGNOSTIC

Le conteneur n'a pas été trouvé
Le conteneur spécifié pour la destruction n'a pas été trouvé. Il est probable qu'il n'existe pas et qu'il ait déjà été détruit. Vous pouvez utiliser la commande lxc-ls pour lister les conteneurs disponibles sur le système.
