NOM

lxc-create - crée un conteneur

SYNTAXE


lxc-create
{-n nom} [-f fichier_config] {-t template} [-B stockage_support] [-- options_template]

DESCRIPTION

lxc-create crée un objet système où sont stockées les informations de configuration et où peuvent être stockées les informations utilisateur. L'identifiant nom est utilisé pour spécifier le conteneur à utiliser avec les différentes commandes lxc.

L'objet est un répertoire créé dans /var/lib/lxc et identifié par son nom.

L'objet est la définition des différentes ressources qu'une application peut utiliser ou voir. Plus le fichier de configuration contient d'informations, plus le conteneur est isolé et plus l'application est confinée.

Si le fichier de configuration fichier_config n'est pas spécifié, le conteneur sera créé avec l'isolation par défaut : processus, ipc sysv et points de montage.

OPTIONS

-f, --config fichier_config
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation du conteneur.
-t, --template template
'template' est le nom court d'un script 'lxc-template' existant qui est appelé par lxc-create, par exemple : busybox, debian, fedora, ubuntu ou sshd. Référez-vous aux exemples dans /usr/share/lxc/templates pour les détails sur la structure attendue du script. Alternativement, le chemin complet vers un script modèle exécutable peut également être passé en paramètre. "none" peut être utilisé pour forcer lxc-create à ignorer la création de la rootfs.
-B, --bdev stockage_support
'stockage_support' est l'une des options : 'dir', 'lvm', 'loop', 'btrfs', 'zfs', 'rbd', ou 'best'. La valeur par défaut est 'dir', ce qui signifie que le système de fichiers racine du conteneur sera un répertoire sous /var/lib/lxc/nom_conteneur/rootfs. Ce type de stockage de support permet de spécifier optionnellement --dir ROOTFS, signifiant que la rootfs du conteneur doit être placée sous le chemin spécifié, plutôt que le chemin par défaut. (Le type de stockage de support 'none' est un alias pour 'dir'.) Si 'btrfs' est spécifié, alors le système de fichiers cible doit être btrfs, et la rootfs du conteneur sera créée en tant que nouveau sous-volume. Cela permet de créer des clones instantanés, mais oblige également rsync --one-filesystem à le traiter comme un système de fichiers séparé. Si stockage_support est 'lvm', alors un périphérique de bloc lvm sera utilisé et les options supplémentaires suivantes sont disponibles : --lvname lvname1 créera un LV nommé lvname1 plutôt que le nom par défaut, qui est le nom du conteneur. --vgname vgname1 créera le LV dans le groupe de volumes vgname1 plutôt que le groupe par défaut, lxc. --thinpool thinpool1 créera le LV en tant que volume provisionné mince dans le pool nommé thinpool1 plutôt que le pool par défaut, lxc. --fstype FSTYPE créera un système de fichiers FSTYPE sur le LV, plutôt que le système par défaut, qui est ext4. --fssize TAILLE créera un LV (et un système de fichiers) de taille TAILLE plutôt que la taille par défaut, qui est 1G.

Si stockage_support est 'loop', vous pouvez utiliser --fstype FSTYPE et --fssize TAILLE comme pour 'lvm'. Les valeurs par défaut pour ces options sont les mêmes que pour 'lvm'.

Si stockage_support est 'rbd', alors vous aurez besoin d'une configuration valide dans ceph.conf et d'un ceph.client.admin.keyring défini. Vous pouvez spécifier les options suivantes : --rbdname RBDNAME créera un périphérique de bloc nommé RBDNAME plutôt que le nom par défaut, qui est le nom du conteneur. --rbdpool POOL créera le périphérique de bloc dans le pool nommé POOL, plutôt que le pool par défaut, qui est 'lxc'.

Si stockage_support est 'best', alors lxc essaiera, dans l'ordre, btrfs, zfs, lvm, et enfin un stockage de type répertoire.

-- options_template
Ceci passera options_template au template en tant qu'arguments. Pour voir la liste des options prises en charge par le template, vous pouvez exécuter lxc-create -t TEMPLATE -h.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes lxc.

-?, -h, --help
Affiche un message d'utilisation plus long que la normale.
--usage
Affiche le message d'utilisation
-q, --quiet
Mute activé
-P, --lxcpath=CHEMIN
Utilise un chemin de conteneur alternatif. Le chemin par défaut est /var/lib/lxc.
-o, --logfile=FICHIER
Sortie vers un fichier journal FICHIER alternatif. Par défaut, pas de journal.
-l, --logpriority=NIVEAU
Définit la priorité du journal à NIVEAU. La priorité de journal par défaut est ERROR. Les valeurs possibles sont : FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Notez que cette option définit la priorité des événements journalisés dans le fichier journal alternatif. Elle n'a aucun effet sur la journalisation des événements ERROR sur stderr.

-n, --name=NOM
Utilise l'identifiant de conteneur NOM. Le format de l'identifiant de conteneur est une chaîne alphanumérique.
--rcfile=FICHIER
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation du conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur précédemment créé (via lxc-create).

--version
Affiche le numéro de version.

DIAGNOSTIC

Le conteneur existe déjà
Comme le message l'indique, vous essayez de créer un conteneur mais il existe déjà un conteneur portant le même nom. Vous pouvez utiliser la commande lxc-ls pour lister les conteneurs disponibles sur le système.

NAME

lxc-create - create a new LXC container.

SYNOPSIS

lxc-create -n <name> -t <template> [options]

DESCRIPTION

lxc-create is a client program to create a new LXC container.

It takes a name for the container and a template used to create the container.

The template is responsible for creating the root filesystem of the container.

For example, to create a container named 'mycontainer' using the 'ubuntu' template:

lxc-create -n mycontainer -t ubuntu

This will download the necessary rootfs from the template provider if it is not found locally.

OPTIONS

-n <name>

The name of the container to create.

-t <template>

The template to use for creating the container's root filesystem.

Common templates include:

  • alpine
  • debian
  • fedora
  • ubuntu

You can also specify a local script as a template.

--

This signifies the end of lxc-create options and the beginning of options to be passed to the template.

COMMON OPTIONS

These options are common to most LXC commands:

-L <path>

Specify the path to the LXC configuration directory. Defaults to /var/lib/lxc.

-f <configfile>

Specify the path to the container configuration file.

-P <path>

Specify the path to the root filesystem of the container.

-o <logfile>

Log to the specified file instead of stderr.

-d

Don't daemonize the process after creation.

-c <dir>

Specify the directory for container configuration files. Defaults to /etc/lxc.

-C <dir>

Specify the directory for container control sockets. Defaults to /run/lxc.

-p <dir>

Specify the directory for container processes. Defaults to /run/lxc.

-s <key=value>

Add a configuration option to the container configuration.

DIAGNOSTIC

lxc-create will print error messages to stderr if something goes wrong.

You can increase verbosity using the -v option (e.g., -vv for more verbose output).

SEE ALSO

lxc(1), lxc-destroy(1), lxc-start(1), lxc-stop(1), lxc-ls(1)

NOM

lxc-create - créer un nouveau conteneur LXC.

SYNOPSIS

lxc-create -n <nom> -t <template> [options]

DESCRIPTION

lxc-create est un programme client pour créer un nouveau conteneur LXC.

Il prend un nom pour le conteneur et un modèle utilisé pour créer le conteneur.

Le modèle est responsable de la création du système de fichiers racine du conteneur.

Par exemple, pour créer un conteneur nommé 'mycontainer' en utilisant le modèle 'ubuntu' :

lxc-create -n mycontainer -t ubuntu

Cela téléchargera le système de fichiers racine nécessaire à partir du fournisseur de modèle s'il n'est pas trouvé localement.

OPTIONS

-n <nom>

Le nom du conteneur à créer.

-t <template>

Le modèle à utiliser pour créer le système de fichiers racine du conteneur.

Les modèles courants incluent :

  • alpine
  • debian
  • fedora
  • ubuntu

Vous pouvez également spécifier un script local comme modèle.

--

Ceci signifie la fin des options lxc-create et le début des options à passer au modèle.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes LXC :

-L <path>

Spécifiez le chemin vers le répertoire de configuration LXC. Par défaut : /var/lib/lxc.

-f <configfile>

Spécifiez le chemin vers le fichier de configuration du conteneur.

-P <path>

Spécifiez le chemin vers le système de fichiers racine du conteneur.

-o <logfile>

Connectez-vous au fichier spécifié au lieu de stderr.

-d

Ne pas démoniser le processus après la création.

-c <dir>

Spécifiez le répertoire pour les fichiers de configuration des conteneurs. Par défaut : /etc/lxc.

-C <dir>

Spécifiez le répertoire pour les sockets de contrôle des conteneurs. Par défaut : /run/lxc.

-p <dir>

Spécifiez le répertoire pour les processus des conteneurs. Par défaut : /run/lxc.

-s <key=value>

Ajouter une option de configuration à la configuration du conteneur.

DIAGNOSTIC

lxc-create affichera des messages d'erreur sur stderr si quelque chose se passe mal.

Vous pouvez augmenter la verbosité en utilisant l'option -v (par exemple, -vv pour une sortie plus détaillée).
