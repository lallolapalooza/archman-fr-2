NOM

lxc-execute - exécute une application à l'intérieur d'un conteneur.

SYNTAXE


lxc-execute
{-n nom} [-d] [-f fichier_config] [-s CLE=VAL] [-u, --uid uid] [-g, --gid gid] [-- commande]

DESCRIPTION

lxc-execute exécute la commande spécifiée à l'intérieur du conteneur spécifié par nom.

Il configurera le conteneur conformément à la configuration préalablement définie avec la commande lxc-create ou avec le paramètre du fichier de configuration. Si aucune configuration n'est définie, l'isolation par défaut est utilisée.

Cette commande est principalement utilisée lorsque vous souhaitez lancer rapidement une application dans un environnement isolé.

La commande lxc-execute exécutera la commande spécifiée dans le conteneur via un processus intermédiaire, lxc-init. Ce lxc-init, après avoir lancé la commande spécifiée, attendra sa fin et celle de tous les autres processus reparentés. (pour supporter les démons dans le conteneur). En d'autres termes, dans le conteneur, lxc-init aura le pid 1 et le premier processus de l'application aura le pid 2.

Le lxc-init ci-dessus est conçu pour transmettre les signaux reçus à la commande démarrée.

OPTIONS

-f, --rcfile fichier_config
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation pour le conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur précédemment créé (via lxc-create).

-s, --define CLE=VAL
Attribue la valeur VAL à la variable de configuration CLE. Cela remplace toute affectation faite dans fichier_config.
-d, --daemon
Exécute le conteneur comme un démon. Comme le conteneur n'a plus de tty, en cas d'erreur, rien ne sera affiché, le fichier journal peut être utilisé pour vérifier l'erreur.
-u, --uid uid
Exécute la commande avec l'identifiant utilisateur (utiliser la valeur numérique) uid à l'intérieur du conteneur.
--g, --gid gid
Exécute la commande avec l'identifiant groupe (utiliser la valeur numérique) gid à l'intérieur du conteneur.
--
Signale la fin des options et désactive le traitement ultérieur des options. Tous les arguments après le -- sont traités comme des arguments de commande.

Cette option est utile lorsque vous souhaitez spécifier des options à commande et que vous ne voulez pas que lxc-execute les interprète.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes lxc.

-?, -h, --help
Affiche un message d'utilisation plus long que la normale.
--usage
Affiche le message d'utilisation
-q, --quiet
mode silencieux activé
-P, --lxcpath=CHEMIN
Utilise un chemin de conteneur alternatif. Le chemin par défaut est /var/lib/lxc.
-o, --logfile=FICHIER
Écrit la sortie dans un FICHIER journal alternatif. Par défaut, il n'y a pas de journal.
-l, --logpriority=NIVEAU
Définit la priorité du journal à NIVEAU. La priorité du journal par défaut est ERROR. Les valeurs possibles sont : FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Notez que cette option définit la priorité des événements enregistrés dans le fichier journal alternatif. Elle n'a aucun effet sur les événements d'erreur enregistrés sur stderr.

-n, --name=NOM
Utilise l'identifiant de conteneur NOM. Le format de l'identifiant de conteneur est une chaîne alphanumérique.
--rcfile=FICHIER
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation pour le conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur précédemment créé (via lxc-create).

--version
Affiche le numéro de version.

DIAGNOSTIC

Le conteneur est occupé
Le conteneur spécifié exécute déjà une application. Vous devez l'arrêter avant de réutiliser ce conteneur ou d'en créer un nouveau.
