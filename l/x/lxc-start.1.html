NOM

lxc-start - exécute une application à l'intérieur d'un conteneur.

SYNTAXE


lxc-start
{-n nom} [-f fichier_config] [-c console_device] [-L log_console] [-d] [-F] [-p fichier_pid] [-s CLÉ=VAL] [-C] [--share-[net|ipc|uts] nom|pid] [commande]

DESCRIPTION

lxc-start exécute la commande spécifiée à l'intérieur du conteneur spécifié par nom.

Il mettra en place le conteneur conformément à la configuration précédemment définie avec la commande lxc-create ou avec le paramètre du fichier de configuration. Si aucune configuration n'est définie, l'isolation par défaut est utilisée.

Si aucune commande n'est spécifiée, lxc-start utilisera la commande définie dans lxc.init.cmd ou, si elle n'est pas définie, la commande par défaut "/sbin/init" pour exécuter un conteneur système.

OPTIONS

-d, --daemon
Exécute le conteneur en tant que démon. Comme le conteneur n'a plus de tty, si une erreur survient rien ne sera affiché, le fichier journal peut être utilisé pour vérifier l'erreur. (C'est le mode par défaut)
-F, --foreground
Exécute le conteneur au premier plan. Dans ce mode, la console du conteneur sera attachée au tty courant et les signaux seront routés directement vers le conteneur.
-p, --pidfile fichier_pid
Crée un fichier avec l'identifiant du processus.
-f, --rcfile fichier_config
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation pour le conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur créé précédemment (via lxc-create).

-c, --console périphérique_console
Spécifie un périphérique à utiliser pour la console du conteneur, par exemple /dev/tty8. Si cette option n'est pas spécifiée, le terminal courant sera utilisé à moins que -d ne soit spécifié.
-L, --console-log log_console
Spécifie un fichier pour enregistrer la sortie de la console du conteneur.
-s, --define CLÉ=VALEUR
Attribue la valeur VALEUR à la variable de configuration CLÉ. Ceci remplace toute affectation faite dans fichier_config.
-C, --close-all-fds
Si des descripteurs de fichiers sont hérités, fermez-les. Si cette option n'est pas spécifiée, lxc-start échouera. Note : --daemon implique --close-all-fds.
--share-net nom|pid
Hérite d'un espace de noms réseau d'un conteneur nom ou d'un pid. L'espace de noms réseau continuera d'être géré par le propriétaire d'origine. La configuration réseau du conteneur de démarrage est ignorée et les scripts de montée/descente ne seront pas exécutés.
--share-ipc nom|pid
Hérite d'un espace de noms IPC d'un conteneur nom ou d'un pid.
--share-uts nom|pid
Hérite d'un espace de noms UTS d'un conteneur nom ou d'un pid. Le LXC de démarrage ne définira pas le nom d'hôte, mais le système d'exploitation du conteneur pourra le faire de toute façon.

OPTIONS COMMUNES

Ces options sont communes à la plupart des commandes lxc.

-?, -h, --help
Affiche un message d'utilisation plus long que la normale.
--usage
Donne le message d'utilisation
-q, --quiet
silencieux
-P, --lxcpath=CHEMIN
Utilise un chemin de conteneur alternatif. Le chemin par défaut est /var/lib/lxc.
-o, --logfile=FICHIER
Sortie vers un FICHIER journal alternatif. Par défaut, il n'y a pas de journal.
-l, --logpriority=NIVEAU
Définit la priorité du journal à NIVEAU. La priorité du journal par défaut est ERROR. Les valeurs possibles sont : FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Notez que cette option définit la priorité des événements enregistrés dans le fichier journal alternatif. Elle n'a aucun effet sur les événements ERROR enregistrés sur stderr.

-n, --name=NOM
Utilise l'identifiant de conteneur NOM. Le format de l'identifiant de conteneur est une chaîne alphanumérique.
--rcfile=FICHIER
Spécifie le fichier de configuration pour configurer les fonctionnalités de virtualisation et d'isolation pour le conteneur.

Ce fichier de configuration, s'il est présent, sera utilisé même s'il existe déjà un fichier de configuration dans le conteneur créé précédemment (via lxc-create).

--version
Affiche le numéro de version.

DIAGNOSTIC

Le conteneur est occupé
Le conteneur spécifié exécute déjà une application. Vous devriez l'arrêter avant de réutiliser ce conteneur ou d'en créer un nouveau.
