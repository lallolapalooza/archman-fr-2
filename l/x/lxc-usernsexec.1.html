NOM

lxc-usernsexec - Exécute une tâche en tant que root dans un nouvel espace de noms utilisateur.

SYNTAXE


lxc-usernsexec
[-m map-uid] {-- commande}

DESCRIPTION

lxc-usernsexec peut être utilisé pour exécuter une tâche en tant que root dans un nouvel espace de noms utilisateur.

OPTIONS

-m map-uid
La map uid à utiliser dans l'espace de noms utilisateur. Chaque map est composée de quatre valeurs séparées par des deux-points. Premièrement, un caractère 'u', 'g' ou 'b' pour spécifier si cette map concerne les ids utilisateur, les ids de groupe, ou les deux ; ensuite, le premier userid dans l'espace de noms utilisateur ; ensuite, le premier userid tel qu'il est vu sur l'hôte ; et enfin, le nombre d'ids à mapper.

Plusieurs maps peuvent être spécifiées. Si aucune map n'est spécifiée, alors par défaut, les plages complètes d'uid et de gid accordées par /etc/subuid et /etc/subgid seront mappées aux uids et gids commençant à 0 dans le conteneur.

Notez que lxc-usernsexec essaie toujours de faire setuid et setgid à 0 dans l'espace de noms. Par conséquent, l'uid 0 dans l'espace de noms doit être mappé.

EXEMPLES

Pour lancer un shell avec les subuids complets alloués mappés dans le conteneur, utilisez

	  lxc-usernsexec

Pour exécuter un shell différent de /bin/sh, utilisez

	  lxc-usernsexec -- /bin/bash

Si votre id utilisateur est 1000, root dans un conteneur est mappé à 190000, et vous souhaitez changer le propriétaire d'un fichier qui vous appartient à root dans le conteneur, vous pouvez utiliser :

	  lxc-usernsexec -m b:0:1000:1 -m b:1:190000:1 -- /bin/chown 1:1 $fichier

Ceci mappe votre userid à root dans l'espace de noms utilisateur, et 190000 à l'uid 1. Puisque root dans l'espace de noms utilisateur est privilégié sur tous les usermids mappés dans l'espace de noms, vous êtes autorisé à changer la propriété du fichier, ce que vous ne pourriez pas faire sur l'hôte en utilisant un simple chown.
