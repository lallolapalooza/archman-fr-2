DESCRIPTION

lvconvert change le type de LV et inclut des utilitaires pour la maintenance des données de LV. Le type de LV contrôle la disposition des données et la redondance. Le type de LV est également appelé type de segment ou segtype.

Pour afficher le type de LV actuel, exécutez la commande :

lvs -o name,segtype LV

Dans certains cas, un LV est une seule couche de mapper de périphérique (dm) au-dessus des périphériques physiques. Dans d'autres cas, des LVs cachés (périphériques dm) sont empilés entre le LV visible et les périphériques physiques. Les LVs dans les couches intermédiaires sont appelés sous-LVs. Une commande exécutée sur un LV visible opère parfois sur un sous-LV plutôt que sur le LV spécifié. Dans d'autres cas, un sous-LV doit être spécifié directement sur la ligne de commande.

Les sous-LVs peuvent être affichés avec la commande :

lvs -a

Le type linear est équivalent au type striped lorsqu'une seule bande existe. Dans ce cas, les types peuvent parfois être utilisés de manière interchangeable.

Dans la plupart des cas, le type mirror est déprécié et le type raid1 devrait être utilisé. Ce sont tous deux des implémentations de mise en miroir.

Les types de RAID mis en bande sont raid0/raid0_meta, raid5 (un alias pour raid5_ls), raid6 (un alias pour raid6_zr) et raid10 (un alias pour raid10_near).

Contrairement à la mise en miroir, raid5 et raid6 mettent en bande les données et calculent des blocs de parité. Les blocs de parité peuvent être utilisés pour la récupération des blocs de données en cas de défaillance des périphériques. Un nombre maximum d'un périphérique dans un LV raid5 peut échouer, et deux en cas de raid6. Les types de RAID mis en bande mettent typiquement en bande les blocs de parité et de données pour des raisons de performance, évitant ainsi la contention sur un seul périphérique. Des dispositions spécifiques de blocs de parité et de données (layouts) peuvent être utilisées pour optimiser les performances d'E/S, ou pour convertir entre les niveaux de RAID. Voir lvmraid(7) pour plus d'informations.

Les dispositions de blocs de parité rotatifs de raid5 peuvent être : left-asymmetric (raid5_la), left-symmetric (raid5_ls avec alias raid5), right-asymmetric (raid5_ra), right-symmetric (raid5_rs) et raid5_n, qui ne fait pas pivoter les blocs de parité. Les dispositions de raid6 sont : zero-restart (raid6_zr avec alias raid6), next-restart (raid6_nr), et next-continue (raid6_nc).

Les dispositions incluant _n permettent la conversion entre les niveaux de RAID (raid5_n vers raid6 ou raid5_n vers striped/raid0/raid0_meta). De plus, des dispositions RAID6 spéciales pour les conversions entre niveaux RAID5 et RAID6 sont : raid6_ls_6, raid6_rs_6, raid6_la_6 et raid6_ra_6. Celles-ci correspondent à leurs homologues raid5 (par exemple, raid5_rs peut être directement converti en raid6_rs_6 et vice-versa).

raid10 (un alias pour raid10_near) est actuellement limité à une copie de données et à un nombre pair de sous-LVs. Il s'agit d'une disposition de groupe de miroirs, donc un seul sous-LV peut échouer par groupe de miroirs sans perte de données.

Les types de RAID mis en bande prennent en charge la conversion de la disposition, de leur taille de bande et de leur nombre de bandes.

Les types de RAID mis en bande combinés avec raid1 permettent la conversion de linear → striped/raid0/raid0_meta et vice-versa par exemple par linear ↔ raid1 ↔ raid5_n (puis ajout de bandes) ↔ striped/raid0/raid0_meta.

OPTIONS

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande doit allouer des Unités Physiques (PE) à partir du VG. Chaque VG et LV a une politique d'allocation qui peut être modifiée avec vgchange/lvchange, ou remplacée sur la ligne de commande. normal applique des règles de bon sens telles que ne pas placer de stripes parallèles sur le même PV. inherit applique la politique du VG à un LV. contiguous exige que les nouveaux PE soient placés adjacents aux PE existants. cling place les nouveaux PE sur le même PV que les PE existants dans le même stripe du LV. S'il existe suffisamment de PE pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par exemple en plaçant deux stripes sur le même PV. Les arguments PV positionnels optionnels sur la ligne de commande peuvent également être utilisés pour limiter les PV que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
-b|--background
Si l'opération nécessite une interrogation, cette option fait que la commande retourne avant que l'opération ne soit terminée, et l'interrogation se fait en arrière-plan.
-H|--cache
Spécifie que la commande gère un LV de cache ou un pool de cache. Voir --type cache et --type cache-pool. Voir lvmcache(7) pour plus d'informations sur la mise en cache LVM.
--cachedevice PV
Le nom d'un périphérique à utiliser pour un cache.
--cachemetadataformat auto|1|2
Spécifie le format des métadonnées du cache utilisé par la cible de cache.
--cachemode writethrough|writeback|passthrough
Spécifie quand les écritures sur un LV de cache doivent être considérées comme terminées. writeback considère une écriture comme terminée dès qu'elle est stockée dans le pool de cache. writethrough considère une écriture comme terminée uniquement lorsqu'elle a été stockée à la fois dans le pool de cache et sur le LV d'origine. Bien que writethrough puisse être plus lent pour les écritures, il est plus résilient si quelque chose arrive à un périphérique associé au LV du pool de cache. Avec passthrough, toutes les lectures sont servies à partir du LV d'origine (toutes les lectures manquent le cache) et toutes les écritures sont transférées vers le LV d'origine ; de plus, les hits d'écriture provoquent l'invalidation des blocs de cache. Voir lvmcache(7) pour plus d'informations.
--cachepolicy Chaîne
Spécifie la politique de cache pour un LV de cache. Voir lvmcache(7) pour plus d'informations.
--cachepool LV
Le nom d'un pool de cache.
--cachesettings Chaîne
Spécifie les options du noyau ajustables pour les LV dm-cache ou dm-writecache. Utilisez le format 'option=valeur' ou 'option1=valeur option2=valeur', ou répétez --cachesettings pour chaque option définie. Ces paramètres outrepassent les comportements par défaut du noyau qui sont généralement adéquats. Pour supprimer les cachesettings et revenir aux comportements par défaut du noyau, utilisez --cachesettings 'default' pour dm-cache ou une chaîne vide --cachesettings '' pour dm-writecache. Voir lvmcache(7) pour plus d'informations.
--cachesize Taille[m|UNITÉ]
La taille du cache à utiliser.
--cachevol LV
Le nom d'un volume de cache.
-c|--chunksize Taille[k|UNITÉ]
La taille des blocs dans un snapshot, un pool de cache ou un pool thin. Pour les snapshots, la valeur doit être une puissance de 2 comprise entre 4 KiB et 512 KiB, et la valeur par défaut est 4. Pour un pool de cache, la valeur doit être comprise entre 32 KiB et 1 GiB, et la valeur par défaut est 64. Pour un pool thin, la valeur doit être comprise entre 64 KiB et 1 GiB, et la valeur par défaut commence à 64 et augmente pour que la taille des métadonnées du pool tienne dans 128 MiB, si la taille des métadonnées du pool n'est pas spécifiée. La valeur doit être un multiple de 64 KiB. Voir lvmthin(7) et lvmcache(7) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--compression o|n
Contrôle si la compression est activée ou désactivée pour le volume VDO. Voir lvmvdo(7) pour plus d'informations sur l'utilisation de VDO.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci outrepassent les paramètres de lvm.conf(5). L'argument chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définir le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le niveau de détail des messages envoyés au fichier journal et/ou à syslog (s'il est configuré).
--deduplication o|n
Contrôle si la déduplication est activée ou désactivée pour le volume VDO. Voir lvmvdo(7) pour plus d'informations sur l'utilisation de VDO.
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepte une liste de périphériques séparés par des virgules. Cela outrepasse le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela outrepasse le paramètre lvm.conf(5) devices/devicesfi
le et les paramètres devices/use_devicesfile.
--discards passdown|nopassdown|ignore
Spécifie comment la couche de pool fin de device-mapper dans le noyau doit gérer les suppressions (discards). ignore fait en sorte que le pool fin ignore les suppressions. nopassdown fait en sorte que le pool fin traite lui-même les suppressions pour permettre la réutilisation des étendues inutilisées dans le pool fin. passdown fait en sorte que le pool fin traite lui-même les suppressions (comme nopassdown) et les transmet au périphérique sous-jacent. Voir lvmthin(7) pour plus d'informations.
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour des tests et le débogage.
--errorwhenfull y|n
Spécifie le comportement du pool fin lorsque l'espace de données est épuisé. Lorsque oui, device-mapper renverra immédiatement une erreur lorsqu'un pool fin est plein et qu'une requête d'E/S nécessite de l'espace. Lorsque non, device-mapper mettra en file d'attente ces requêtes d'E/S pendant une période de temps pour permettre l'extension du pool fin. Des erreurs seront renvoyées si aucun espace n'est disponible après le délai d'attente. (Voir aussi l'option du module noyau "dm_thin_pool" no_space_timeout.) Voir lvmthin(7) pour plus d'informations.
-f|--force ...
Outrepasse diverses vérifications, confirmations et protections. Utiliser avec une extrême prudence.
-h|--help
Affiche l'aide.
--integritysettings String
Spécifie les options du noyau configurables pour dm-integrity. Voir lvmraid(7) pour plus d'informations.
-i|--interval Number
Rapporte la progression à intervalles réguliers.
--journal String
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre lvm.conf log/journal. command: enregistre des informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche l'aide détaillée.
--merge
Un alias pour --mergethin, --mergemirrors, ou --mergesnapshot, en fonction du type de LV.
--mergemirrors
Fusionne les images LV qui ont été séparées d'un LV raid1. Voir --splitmirrors avec --trackchanges.
--mergesnapshot
Fusionne le LV snapshot COW dans son origine. Lors de la fusion d'un snapshot, si les LV d'origine et de snapshot ne sont pas ouverts, la fusion commencera immédiatement. Sinon, la fusion commencera la première fois que le LV d'origine ou de snapshot sera activé et que les deux seront fermés. La fusion d'un snapshot dans une origine qui ne peut pas être fermée, par exemple un système de fichiers racine, est différée jusqu'à la prochaine activation du volume d'origine. Lorsque la fusion commence, le LV résultant portera le nom, le numéro mineur et l'UUID de l'origine. Pendant que la fusion est en cours, les lectures ou écritures sur l'origine apparaissent comme étant dirigées vers le snapshot en cours de fusion. Lorsque la fusion se termine, le snapshot fusionné est supprimé. Plusieurs snapshots peuvent être spécifiés sur la ligne de commande ou une balise @peut être utilisée pour spécifier que plusieurs snapshots doivent être fusionnés vers leurs origines respectives.
--mergethin
Fusionne le LV fin dans son LV d'origine. Le LV fin d'origine prend le contenu du snapshot fin, et le LV snapshot fin est supprimé. Voir lvmthin(7) pour plus d'informations.
--metadataprofile String
Le profil de métadonnées à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--mirrorlog core|disk
Spécifie le type de journal de miroir pour les LV de type "mirror" (ne s'applique pas au type "raid1".) disk est un journal persistant et nécessite une petite quantité d'espace de stockage, généralement sur un périphérique séparé des données mises en miroir. core n'est pas persistant ; le journal est conservé uniquement en mémoire. Dans ce cas, le miroir doit être synchronisé (en copiant les données du LV du premier périphérique vers les autres) à chaque activation du LV, par exemple après un redémarrage. mirrored est un journal persistant qui est lui-même mis en miroir, mais doit être évité. Utilisez plutôt le type raid1 pour la redondance du journal.
-m|--mirrors [+|-]Number
Spécifie le nombre d'images miroir en plus de l'image LV d'origine ; par exemple, --mirrors 1 signifie qu'il y a deux images des données, l'originale et une image miroir. Les arguments PV positionnels optionnels sur la ligne de commande peuvent spécifier les périphériques sur lesquels les images doivent être placées. Il existe deux implémentations de mise en miroir : "raid1" et "mirror". Ce sont les noms des types de LV correspondants, ou "types de segments". Utilisez l'option --type pour spécifier celui à utiliser (raid1 est par défaut, et mirror est hérité). Utilisez lvm.conf(5) global/mirror_segtype_default et global/raid10_segtype_default pour configurer les types par défaut. Le préfixe plus + peut être utilisé, auquel cas le nombre est ajouté au nombre actuel d'images, ou le préfixe moins - peut être utilisé, auquel cas le nombre est soustrait du nombre actuel d'images. Voir lvmraid(7) pour plus d'informations.
-n|--name String
Spécifie le nom d'un nouveau LV. Lorsqu'il n'est pas spécifié, un nom par défaut "lvol#" est généré, où # est un numéro généré par LVM.
--nohints
N'utilise pas le fichier d'indices (hints) pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours la suppression standard du fichier d'indices lorsque cela est approprié.
--nolocking
Désactive le verrouillage. Utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas de notification de udev. Il continuera indépendamment de tout traitement udev possible en arrière-plan. N'utilisez cette option que si udev n'est pas en cours d'exécution ou si ses règles ignorent les périphériques créés par LVM.
--originname LV
Spécifie le nom à utiliser pour le LV d'origine externe lors de la conversion d'un LV en LV fin. Le LV en cours de conversion devient une origine externe en lecture seule portant ce nom.
--pooldatavdo y|n
Utilise le type de volume VDO pour le volume de données du pool.
--poolmetadata LV
Le nom d'un LV à utiliser pour stocker les métadonnées du pool.
--poolmetadatasize Size[m|UNIT]
Spécifie la taille du nouveau LV de métadonnées du pool.
--poolmetadataspare y|n
Active ou désactive la création et la gestion automatiques d'un LV de métadonnées de pool de secours dans le VG. Un LV de métadonnées de secours est un espace réservé qui peut être utilisé lors de la réparation d'un pool.
--profile String
Un alias pour --commandprofile ou --metadataprofile, en fonction de la commande.
-q|--quiet ...
Supprime la sortie et les messages de journal. Remplace --debug et --verbose. Répéter une fois pour supprimer également toutes les invites avec la réponse 'non'.
--raidintegrity y|n
Active ou désactive les sommes de contrôle d'intégrité des données pour les images raid.
--raidintegrityblocksize Number
La taille de bloc à utiliser pour dm-integrity sur les images raid. La taille de bloc d'intégrité doit généralement correspondre à la taille de bloc logique du périphérique, ou à la taille de bloc du système de fichiers. Elle peut être inférieure à la taille de bloc du système de fichiers, mais pas inférieure à la taille de bloc logique du périphérique. Valeurs possibles : 512, 1024, 2048, 4096.
--raidintegritymode String
Utilise un journal (par défaut) ou un bitmap pour maintenir la cohérence des sommes de contrôle d'intégrité en cas de crash. Les zones de bitmap sont recalculées après un crash, de sorte que la corruption dans ces zones ne serait pas détectée. Un journal n'a pas ce problème. Le mode journal double les écritures sur le stockage, mais peut améliorer les performances pour les écritures dispersées regroupées en une seule écriture de journal. Le mode bitmap peut en théorie atteindre le débit d'écriture complet du périphérique, mais ne bénéficierait pas de l'optimisation potentielle des écritures dispersées.
-r|--readahead auto|none|Number
Définit le nombre de secteurs de lecture anticipée d'un LV. auto est la valeur par défaut, qui permet au noyau de choisir automatiquement une valeur appropriée. none est équivalent à zéro.
-R|--regionsize Size[m|UNIT]
Taille de chaque région de synchronisation raid ou miroir. lvm.conf(5) activation/raid_region_size peut être utilisé pour configurer une valeur par défaut.
--repair
Remplace les PV défaillants dans un LV raid ou miroir, ou exécute un utilitaire de réparation sur un pool fin. Voir lvmraid(7) et lvmthin(7) pour plus d'informations.
--replace  ;PV
Remplace un PV spécifique dans un LV raid par un autre PV. Le nouveau PV à utiliser peut être spécifié de manière optionnelle après le LV. Plusieurs PV peuvent être remplacés en répétant cette option. Voir lvmraid(7) pour plus d'informations.
-k|--setactivationskip y|n
Définit (yes) ou efface (no) de manière persistante l'indicateur "activation skip" sur un LV. Un LV avec cet indicateur défini n'est pas activé à moins que l'option --ignoreactivationskip ne soit utilisée par la commande d'activation. Cet indicateur est défini par défaut sur les nouveaux LV de snapshot "thin". L'indicateur n'est pas appliqué à la désactivation. La valeur actuelle de l'indicateur est indiquée dans les bits lv_attr de lvs.
-s|--snapshot
Combine un ancien LV de snapshot COW avec un ancien LV d'origine pour inverser une commande --splitsnapshot précédente.
--splitcache
Sépare un pool de cache d'un LV de cache, et conserve le LV de pool de cache inutilisé. Avant la séparation, le cache est vidé. Voir aussi --uncache.
--splitmirrors Nombre
Sépare le nombre spécifié d'images d'un LV raid1 ou miroir et les utilise pour créer un nouveau LV. Si --trackchanges est également spécifié, les modifications apportées au LV raid1 sont suivies pendant que le LV séparé reste détaché. Si --name est spécifié, alors les images sont séparées de manière permanente du LV d'origine et les modifications ne sont pas suivies.
--splitsnapshot
Sépare un snapshot COW de son LV d'origine. Le LV qui est détaché contient les blocs qui diffèrent du LV d'origine ainsi que des métadonnées les décrivant. Ce LV peut être effacé puis détruit avec lvremove.
--startpoll
Démarre l'interrogation d'un LV pour continuer le traitement d'une conversion.
--stripes Nombre
Spécifie le nombre de bandes dans un LV stripé. C'est le nombre de PV (périphériques) sur lesquels un LV stripé est réparti. Les données qui apparaissent séquentiellement dans le LV sont réparties sur plusieurs périphériques par unités de la taille de bande (voir --stripesize). Ceci ne s'applique pas à l'espace alloué existant, seul l'espace nouvellement alloué peut être stripé.
-I|--stripesize Taille[k|UNIT]
La quantité de données écrite sur un périphérique avant de passer au suivant dans un LV stripé.
--swapmetadata
Extrait le LV de métadonnées d'un pool et le remplace par un autre LV spécifié. Le LV extrait est préservé et prend le nom du LV qui l'a remplacé. À utiliser uniquement pour la réparation. Lorsque le LV de métadonnées est extrait du pool, il peut être activé directement et utilisé avec les outils de provisionnement fin : cache_dump(8), cache_repair(8), cache_restore(8), thin_dump(8), thin_repair(8), thin_restore(8).
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées tout en retournant un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil s'appuie sur la lecture de métadonnées qu'il pense avoir changées mais qui ne l'ont pas été.
-T|--thin
Spécifie que la commande gère un LV fin ou un pool fin. Voir --type thin, --type thin-pool, et --virtualsize. Voir lvmthin(7) pour plus d'informations sur le provisionnement fin LVM.
--thinpool LV
Le nom d'un LV de pool fin.
--trackchanges
Peut être utilisé avec --splitmirrors sur un LV raid1. Cela entraîne le suivi des modifications apportées au LV raid1 d'origine pendant que les images séparées restent détachées. Ceci est un état temporaire qui permet à l'image détachée en lecture seule d'être fusionnée efficacement dans le LV raid1 plus tard. Seules les régions avec des données modifiées sont resynchronisées pendant la fusion. Pendant qu'un LV raid1 suit les modifications, les opérations sur celui-ci sont limitées à la fusion de l'image séparée (voir --mergemirrors) ou à la séparation permanente de l'image (voir --splitmirrors avec --name.
--type linear|striped|snapshot|raid|mirror|thin|thin-pool|vdo|vdo-pool|cache|cache-pool|writecache
Le type de LV, également connu sous le nom de "segment type" ou "segtype". Voir les descriptions d'utilisation pour les façons spécifiques d'utiliser ces types. Pour plus d'informations sur la redondance et les performances (raid<N>, mirror, striped, linear) voir lvmraid(7). Pour le provisionnement fin (thin, thin-pool) voir lvmthin(7). Pour la mise en cache des performances (cache, cache-pool) voir lvmcache(7). Pour les snapshots de copie sur écriture (snapshot) voir les définitions d'utilisation. Pour VDO (vdo) voir lvmvdo(7). Plusieurs commandes omettent une option de type explicite car le type est déduit d'autres options ou raccourcis (par exemple --stripes, --mirrors, --snapshot, --virtualsize, --thin, --cache, --vdo). Utiliser les types déduits avec précaution car cela peut entraîner des résultats inattendus.

Sépare un pool de cache d'un LV de cache, et supprime le LV de pool de cache inutilisé. Avant la séparation, le cache est vidé. Voir aussi --splitcache.
--usepolicies
Effectue une opération selon la politique configurée dans lvm.conf(5) ou un profil.
--vdopool LV
Le nom d'un LV de pool VDO. Voir lvmvdo(7) pour plus d'informations sur l'utilisation de VDO.
--vdosettings String
Spécifie les options VDO ajustables pour les LVs VDO. Utilisez le format 'option=valeur' ou 'option1=valeur option2=valeur', ou répétez --vdosettings pour chaque option à définir. Ces paramètres remplacent les comportements par défaut de VDO. Pour supprimer les vdosettings et revenir aux comportements par défaut de VDO, utilisez --vdosettings 'default'. Définit le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.

-V|--virtualsize Taille[m|UNIT]
La taille virtuelle d'un nouveau LV fin. Voir lvmthin(7) pour plus d'informations sur le provisionnement fin LVM. L'utilisation de la taille virtuelle (-V) et de la taille réelle (-L) ensemble crée un LV épars. lvm.conf(5) global/sparse_segtype_default détermine le type de segment par défaut utilisé pour créer un LV épars. Tout ce qui est écrit dans un LV épars sera retourné lors de la lecture. La lecture depuis d'autres zones du LV retournera des blocs de zéros. Lors de l'utilisation d'un snapshot pour créer un LV épars, un périphérique virtuel caché est créé en utilisant la cible zéro, et le LV aura le suffixe _vorigin. Les snapshots sont moins efficaces que le provisionnement fin lors de la création de grands LVs épars (Gio).
-W|--wipesignatures y|n
Contrôle la détection puis l'effacement des signatures sur les nouveaux LVs. Il y a une invite pour chaque signature détectée afin de confirmer son effacement (sauf si --yes est utilisé pour ignorer les confirmations). Lorsqu'il n'est pas spécifié, les signatures sont effacées chaque fois que le zéro est effectué (voir --zero). Ce comportement peut être configuré avec lvm.conf(5) allocation/wipe_signatures_when_zeroing_new_lvs. Si l'effacement blkid est utilisé (lvm.conf(5) allocation/use_blkid_wiping) et que LVM est compilé avec le support d'effacement blkid, alors la bibliothèque blkid(8) est utilisée pour détecter les signatures (utiliser blkid -k pour lister les signatures reconnues). Sinon, le code LVM natif est utilisé pour détecter les signatures (seules les signatures MD RAID, swap et LUKS sont détectées dans ce cas). Le LV ne sera pas effacé si l'indicateur de lecture seule est défini.
-y|--yes
Ne pas demander de confirmation interactivement mais toujours répondre oui. Utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)
-Z|--zero y|n
Pour les snapshots, cela contrôle la mise à zéro des 4 premiers KiB de données dans le snapshot. Si le LV est en lecture seule, le snapshot ne sera pas mis à zéro. Pour les pools fins, cela contrôle la mise à zéro des blocs provisionnés. Le provisionnement de grands blocs mis à zéro a un impact négatif sur les performances.

VARIABLES

VG
Nom du Groupe de Volumes. Voir lvm(8) pour les noms valides.
LV
Nom du Volume Logique. Voir lvm(8) pour les noms valides. Un argument positionnel LV inclut généralement le nom du VG et le nom du LV, par exemple VG/LV. LV1 indique que le LV doit avoir un type spécifique, où les types de LV acceptés sont listés. (raid représente le type raid<N>).
PV
Nom du Volume Physique, un chemin de périphérique sous /dev. Pour les commandes gérant les extent physiques, un argument positionnel PV accepte généralement un suffixe indiquant une plage (ou plusieurs plages) d'extent physiques (PE). Lorsque le premier PE est omis, il prend par défaut le début du périphérique, et lorsque le dernier PE est omis, il prend par défaut la fin.
Plage de début et de fin (inclusive) : PV[:PE-PE] ...
Plage de début et de longueur (en comptant à partir de 0) : PV[:PE+PE] ...
Tag
Nom de l'étiquette. Voir lvm(8) pour des informations sur les noms d'étiquettes et l'utilisation des étiquettes à la place d'un VG, LV ou PV.
Chaîne
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Taille[UNITÉ]
Taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs binaires, quelle que soit la casse, par exemple 'k' et 'K' font référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B sont des octets, s|S sont des secteurs de 512 octets, k|K sont des KiB, m|M sont des MiB, g|G sont des GiB, t|T sont des TiB, p|P sont des PiB, e|E sont des EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient des multiples de 1000.)

NOTES

La syntaxe de commande précédente effectuait deux opérations différentes :
lvconvert --thinpool LV1 --poolmetadata LV2
Si LV1 n'était pas un pool fin, la commande convertirait LV1 en un pool fin, en utilisant éventuellement un LV spécifié pour les métadonnées. Mais, si LV1 était déjà un pool fin, la commande échangerait le LV de métadonnées actuel avec LV2 (à des fins de réparation).

De la même manière, la syntaxe de commande précédente effectuait deux opérations différentes :
lvconvert --cachepool LV1 --poolmetadata LV2
Si LV1 n'était pas un pool de cache, la commande convertirait LV1 en un pool de cache, en utilisant éventuellement un LV spécifié pour les métadonnées. Mais, si LV1 était déjà un pool de cache, la commande échangerait le LV de métadonnées actuel avec LV2 (à des fins de réparation).

EXEMPLES

Convertir un LV linéaire en un LV miroir bidirectionnel.
lvconvert --type mirror --mirrors 1 vg/lvol1

Convertir un LV linéaire en un LV RAID1 bidirectionnel.
lvconvert --type raid1 --mirrors 1 vg/lvol1

Convertir un LV miroir pour utiliser un log en mémoire.
lvconvert --mirrorlog core vg/lvol1

Convertir un LV miroir pour utiliser un log sur disque.
lvconvert --mirrorlog disk vg/lvol1

Convertir un LV miroir ou raid1 en un LV linéaire.
lvconvert --type linear vg/lvol1

Convertir un LV miroir en un LV raid1 avec le même nombre d'images.
lvconvert --type raid1 vg/lvol1

Convertir un LV linéaire en un LV miroir bidirectionnel, en allouant de nouvelles étendues à partir de plages PV spécifiques.
lvconvert --mirrors 1 vg/lvol1 /dev/sda:0-15 /dev/sdb:0-15

Convertir un LV miroir en un LV linéaire, en libérant des étendues physiques d'un PV spécifique.
lvconvert --type linear vg/lvol1 /dev/sda

Séparer une image d'un LV miroir ou raid1, en en faisant un nouveau LV.
lvconvert --splitmirrors 1 --name lv_split vg/lvol1

Séparer une image d'un LV raid1, et suivre les modifications apportées au LV raid1 pendant que l'image séparée reste détachée.
lvconvert --splitmirrors 1 --trackchanges vg/lvol1

Fusionner une image (qui a été précédemment créée avec --splitmirrors et --trackchanges) dans le LV raid1 d'origine.
lvconvert --mergemirrors vg/lvol1_rimage_1

Remplacer le PV /dev/sdb1 par le PV /dev/sdf1 dans un LV raid1/4/5/6/10.
lvconvert --replace /dev/sdb1 vg/lvol1 /dev/sdf1

DESCRIPTION

Converts an existing logical volume from one type to another. This can be used to change the RAID level of a RAID logical volume, convert a linear or striped logical volume to a RAID logical volume, convert a thick logical volume to a thin logical volume, or convert a logical volume to act as a cache for another logical volume.

The conversion can involve moving data between physical volumes within the volume group. If the conversion requires data to be moved, the source logical volume must not be inactive and must not be in an error state.

If the conversion requires data to be moved, and the new layout requires more space than the current layout, the conversion will fail unless additional physical extents are available in the volume group.

The command can also be used to repair a mirrored or RAID logical volume by replacing a missing or failed physical volume.

USAGE

Full path to the logical volume is required.

To convert an existing logical volume, specify the logical volume path and the new type and any new physical volumes or logical volumes required for the new type.

OPTIONS

--repair LogicalVolumePath
Repair a mirrored or RAID logical volume that has missing or failed physical volumes. The missing or failed PVs are replaced with available PVs in the VG. If no PVs are specified, then the VG is scanned for suitable PVs.
--replace [PhysicalVolumePath | PhysicalVolumePath?PhysicalVolumePath]+ LogicalVolumePath PhysicalVolumePath | PhysicalVolumePath?PhysicalVolumePath
Replace one or more physical volumes in a logical volume with new physical volumes. This is typically used to replace failed or degraded PVs.
--stripes LogicalVolumePath PhysicalVolumePath | PhysicalVolumePath?PhysicalVolumePath
Convert a linear or striped logical volume to a striped logical volume with the specified number of stripes and physical volumes.
--type LogicalType LogicalVolumePath [PhysicalVolumePath | PhysicalVolumePath?PhysicalVolumePath]
Convert the logical volume to the specified type. The following types are supported:
raid: Convert a linear or striped logical volume to a RAID logical volume. This requires the PVs for the new RAID logical volume to be specified. If a RAID level is not specified, then the default RAID level is used.
raid0, raid1, raid4, raid5, raid6, raid10: Convert to a specific RAID level.
raid10: Create a RAID10 logical volume. This requires the number of devices for each mirror in the RAID10. The number of devices must be an even number.
raid1, raid10: Convert to RAID1 or RAID10 using one or more PVs. The number of PVs must be the same as the number of PVs in the LV. The PVs are added as mirrors.
raid1, raid6: Convert to RAID1 or RAID6 using one or more PVs. The number of PVs must be the same as the number of PVs in the LV. The PVs are added as mirrors or parity devices.
raid1, raid4, raid5, raid6, raid10: Convert to a specific RAID level using one or more PVs. The number of PVs must be the same as the number of PVs in the LV. The PVs are added as mirrors or parity devices.
raid1, raid4, raid5, raid6, raid10: Convert to a specific RAID level using one or more PVs. The number of PVs must be the same as the number of PVs in the LV. The PVs are added as mirrors or parity devices.
raid1, raid4, raid5, raid6, raid10: Convert to a specific RAID level using one or more PVs. The number of PVs must be the same as the number of PVs in the LV. The PVs are added as mirrors or parity devices.
mirror: Convert a linear or striped logical volume to a mirrored logical volume. This requires the PVs for the new mirror logical volume to be specified.
thin: Convert a thick logical volume to a thin logical volume. This requires a thin pool to be specified. The existing logical volume will be used as the origin for the new thin logical volume.
thin-pool: Convert a logical volume to a thin pool. This can be used to create a thin pool from an existing logical volume.
cache-pool: Convert a logical volume to a cache pool. This requires a logical volume to be specified for the cache pool metadata.
cache: Convert a logical volume to a cache logical volume. This requires a cache pool and chunk size to be specified.
--thinpool LogicalVolumePath
Specify the thin pool to use for converting a logical volume to a thin logical volume.
--poolmetadatasize Size
Set the size of the metadata for a thin pool. This option is only valid when converting a logical volume to a thin pool or a thin logical volume.
--pooldatavdo y|n
Enable or disable VDO (Volume Deduplication and Compression) for a thin pool. This option is only valid when converting a logical volume to a thin pool.
--originname Name
Set the name of the origin for a thin logical volume. This option is only valid when converting a logical volume to a thin logical volume.
--poolmetadata LogicalVolumePath
Specify the logical volume to use for the cache pool metadata when converting a logical volume to a cache pool.
-c Size
Specify the chunk size for a cache logical volume. This option is only valid when converting a logical volume to a cache logical volume.
--splitcache LogicalVolumePath
Detach the cache pool from a cache logical volume, keeping the cache pool intact.
--uncache LogicalVolumePath
Detach and remove the cache pool from a cache logical volume.
--splitmirrors LogicalVolumePath
Split a mirrored logical volume into two separate logical volumes. Each new logical volume will be a copy of the original mirrored logical volume.
--merge LogicalVolumePath
Merge a mirrored logical volume back into a single logical volume. This will remove one of the mirrors and convert the logical volume to a linear logical volume.
--removemissing LogicalVolumePath
Remove missing physical volumes from a mirrored or RAID logical volume. This is useful if a physical volume is permanently lost and cannot be replaced.

None.

ADVANCED USAGE

The lvconvert command can be used to perform complex conversions, such as converting a RAID1 logical volume to a RAID5 logical volume, or converting a linear logical volume to a thin logical volume with VDO enabled.

For example, to convert a RAID1 logical volume to a RAID5 logical volume, you would use the following command:

lvconvert --type raid5 vg/lvol1 /dev/sd[c-e]

This command converts the RAID1 logical volume vg/lvol1 to a RAID5 logical volume using the physical volumes /dev/sdc1, /dev/sdd1, and /dev/sde1.

NOTES

The conversion process can take a significant amount of time, depending on the size of the logical volume and the speed of the underlying storage.

It is recommended to back up any important data before performing any conversion operations.

EXAMPLES

Convert a linear LV to a RAID1 LV using 2 PVs.

lvconvert --type raid1 vg/lvol1 /dev/sdb1 /dev/sdc1

Replace PVs /dev/sdb1 and /dev/sdc1 with PVs /dev/sdd1 and /dev/sde1 in a RAID1 LV.

lvconvert --replace /dev/sdb1 --replace /dev/sdc1 vg/lvol1 /dev/sdd1 /dev/sde1

Convert a RAID1 LV to a RAID5 LV using 3 PVs.

lvconvert --type raid5 vg/lvol1 /dev/sd[def]1

Replace PVs /dev/sd[b-d]1 with PVs /dev/sd[f-h]1 in a raid1 LV.

lvconvert --replace /dev/sdb1 --replace /dev/sdc1 --replace /dev/sdd1 vg/lvol1 /dev/sdf1 /dev/sdg1 /dev/sdh1

Replace the maximum of 2 PVs /dev/sd[bc]1 with PVs /dev/sd[gh]1 in a raid6 LV.

lvconvert --replace /dev/sdb1 --replace /dev/sdc1 vg/lvol1 /dev/sdg1 /dev/sdh1

Convert a thick LV into a thin-pool data volume and continue using this LV through thinLV and for the conversion set the pool metadata size to 1GiB.

lvconvert --type thin --poolmetadatasize 1G vg/lvol1

Convert an LV into a thin-pool with VDO deduplication and compression for storing its data.

lvconvert --type thin-pool --pooldatavdo y vg/lvol1

Convert an LV into a thin LV in the specified thin pool. The existing LV is used as an external read-only origin for the new thin LV.

lvconvert --type thin --thinpool vg/tpool1 vg/lvol1

Convert an LV into a thin LV in the specified thin pool. The existing LV is used as an external read-only origin for the new thin LV, and is renamed "external".

lvconvert --type thin --thinpool vg/tpool1 --originname external vg/lvol1

Convert an LV to a cache pool LV using another specified LV for cache pool metadata.

lvconvert --type cache-pool --poolmetadata vg/poolmeta1 vg/lvol1

Convert an LV to a cache LV using the specified cache pool and chunk size.

lvconvert --type cache --cachepool vg/cpool1 -c 128 vg/lvol1

Detach and keep the cache pool from a cache LV.

lvconvert --splitcache vg/lvol1

Detach and remove the cache pool from a cache LV.

lvconvert --uncache vg/lvol1
