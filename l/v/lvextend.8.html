DESCRIPTION

lvextend étend la taille d'un LV. Cela nécessite l'allocation d'extensions logiques à partir des extensions physiques libres du VG. Si l'extension ajoute un nouveau segment LV, le nouveau segment utilisera le type de segment existant du LV.

L'extension d'un LV snapshot en copie sur écriture ajoute de l'espace pour les blocs COW.

Utilisez lvconvert(8) pour changer le nombre d'images de données dans un LV RAID ou miroir.

Dans la section d'utilisation ci-dessous, --size Taille peut être remplacé par --extents Nombre. Voir les deux descriptions dans la section des options.

OPTIONS

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande doit allouer des Extensions Physiques (PE) à partir des PE libres du VG. Chaque VG et LV a une politique d'allocation qui peut être changée avec vgchange/lvchange, ou remplacée en ligne de commande. normal applique des règles de bon sens telles que ne pas placer de bandes parallèles sur la même PV. inherit applique la politique du VG à un LV. contiguous exige que les nouvelles PE soient placées adjacentes aux PE existantes. cling place les nouvelles PE sur la même PV que les PE existantes dans la même bande du LV. S'il y a suffisamment de PE pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par exemple en plaçant deux bandes sur la même PV. Les arguments PV positionnels optionnels sur la ligne de commande peuvent également être utilisés pour limiter les PV que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après un changement. L'activation de cette option est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou au s
yslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés sembleront manquants. Cette option peut être répétée, ou accepte une liste de périphériques séparés par des virgules. Ceci remplace le fichier périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded o|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-l|--extents [+]Nombre[POURCENT]
Spécifie la nouvelle taille du LV en extentions logiques. Les options --size et --extents sont des méthodes alternatives pour spécifier la taille. Le nombre total d'extentions physiques utilisées sera plus grand lorsque des données redondantes sont nécessaires pour les niveaux RAID. Une syntaxe alternative permet de déterminer la taille indirectement comme un pourcentage de la taille d'un VG, LV ou ensemble de PVs associé. Le suffixe %VG désigne la taille totale du VG, le suffixe %FREE l'espace libre restant dans le VG, et le suffixe %PVS l'espace libre dans les PVs spécifiés. Pour un snapshot, la taille peut être exprimée en pourcentage de la taille totale du LV d'origine avec le suffixe %ORIGIN (100%ORIGIN fournit de l'espace pour l'origine entière). Lorsqu'elle est exprimée en pourcentage, la taille définit une limite supérieure pour le nombre d'extentions logiques dans le nouveau LV. Le nombre précis d'extentions logiques dans le nouveau LV n'est pas déterminé tant que la commande n'est pas terminée. Lorsque le préfixe plus + ou moins - est utilisé, la valeur n'est pas une taille absolue, mais est relative et ajoutée ou soustraite de la taille actuelle.
-f|--force ...
Outrepasse diverses vérifications, confirmations et protections. À utiliser avec une extrême prudence.
--fs Chaîne
Contrôle le redimensionnement du système de fichiers lors du redimensionnement d'un LV. checksize : Vérifie la taille du système de fichiers et réduit le LV si le système de fichiers n'utilise pas l'espace réduit (réduction du système de fichiers non nécessaire.) Si l'espace réduit est utilisé par le système de fichiers, alors ne redimensionne pas le système de fichiers ou le LV, et retourne une erreur. (checksize s'applique uniquement lors de la réduction, et ne fait rien pour l'extension.) resize : Redimensionne le système de fichiers en appelant la commande de redimensionnement spécifique au système de fichiers. Cela peut également inclure le montage, le démontage ou l'exécution de fsck. Voir --fsmode pour contrôler le comportement de montage, et --nofsck pour désactiver fsck. resize_fsadm : Utilise l'ancienne méthode d'appel de fsadm pour gérer le système de fichiers (obsolète.) Attention : cette option n'empêche pas lvreduce de détruire les systèmes de fichiers qui sont démontés (ou montés si les invites sont ignorées.) ignore : Redimensionne le LV sans vérifier ni gérer un système de fichiers. Attention : utiliser ignore lors de la réduction de la taille du LV peut détruire le système de fichiers.

Note : Si vous redimensionnez un LV sans système de fichiers et que la nouvelle taille du LV correspond à la taille existante, la commande retourne un code d'état non nul (échec). Cependant, si un redimensionnement de système de fichiers est également demandé en même temps que le redimensionnement du LV, et que les tailles correspondent déjà, la commande retourne un code d'état nul (succès). Cela se produit car les commandes externes appelées pour redimensionner le système de fichiers retournent succès même si les nouvelles et anciennes tailles de système de fichiers sont identiques. LVM suit le comportement du code d'état de la commande dans ce scénario.

--fsmode Chaîne
Contrôle le comportement de montage du système de fichiers pour le redimensionnement du système de fichiers. manage : Monte ou démonte le système de fichiers selon les besoins pour redimensionner le système de fichiers, et tente de restaurer l'état de montage d'origine à la fin. nochange : Ne monte ni ne démonte le système de fichiers. Si le montage ou le démontage est nécessaire pour redimensionner le système de fichiers, alors ne redimensionne pas le système de fichiers ou le LV et échoue la commande. offline : Démonte le système de fichiers s'il est monté, et redimensionne le système de fichiers lorsqu'il est démonté. Si le montage est nécessaire pour redimensionner le système de fichiers, alors ne redimensionne pas le système de fichiers ou le LV et échoue la commande.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre des informations dans le journal systemd. Ces informations s'ajoutent à celles activées par le paramètre log/journal de lvm.conf. command : enregistre des informations sur la commande. output : enregistre la sortie par défaut de la commande. debug : enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide complet.
-m|--mirrors Nombre
Non utilisé.
-n|--nofsck
N'exécute pas fsck lors du redimensionnement du système de fichiers avec --resizefs.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PVs. Une commande peut lire plus de périphériques pour trouver des PVs lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices si approprié.
--nolocking
Désactive le verrouillage. À utiliser avec précaution, les commandes concurrentes peuvent produire des résultats incorrects.
--nosync
Fait en sorte que la création de mirror, raid1, raid4, raid5 et raid10 saute la synchronisation initiale. Dans le cas de mirror, raid1 et raid10, toutes les données écrites par la suite seront mises en miroir, mais le contenu original ne sera pas copié. Dans le cas de raid4 et raid5, aucun bloc de parité ne sera écrit, bien que toutes les données écrites par la suite provoquent le stockage de blocs de parité. Ceci est utile pour sauter une synchronisation initiale potentiellement longue et coûteuse en ressources d'un LV mirror/raid1/raid4/raid5 et raid10 vide. Cette option n'est pas valide pour raid6, car raid6 repose sur une parité correcte (syndromes P et Q) créée pendant la synchronisation initiale afin de reconstruire correctement les données utilisateur en cas de défaillance de périphériques. raid0 et raid0_meta ne fournissent aucune copie de données ni support de parité et ne supportent donc pas la synchronisation initiale.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas de notification de udev. Il continuera indépendamment de tout traitement udev possible en arrière-plan. Utilisez cette option uniquement si udev ne fonctionne pas ou a des règles qui ignorent les périphériques créés par LVM.
--poolmetadatasize [+]Taille[m|UNITÉ]
Spécifie la nouvelle taille du LV de métadonnées du pool. Le préfixe plus + peut être utilisé, auquel cas la valeur est ajoutée à la taille actuelle.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages de log. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est précédé du nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-r|--resizefs
Redimensionne le système de fichiers en utilisant la commande de redimensionnement spécifique au système de fichiers. Peut inclure le montage, le démontage ou l'exécution de fsck. Voir --fsmode pour contrôler le comportement de montage, et --nofsck pour désactiver fsck. Voir --fs pour plus d'options (--resizefs est équivalent à --fs resize.)
-L|--size [+]Taille[m|UNITÉ]
Spécifie la nouvelle taille du LV. Les options --size et --extents sont des méthodes alternatives pour spécifier la taille. Le nombre total d'extentions physiques utilisées sera plus grand lorsque des données redondantes sont nécessaires pour les niveaux RAID. Lorsque le préfixe plus + ou moins - est utilisé, la valeur n'est pas une taille absolue, mais est relative et ajoutée ou soustraite de la taille actuelle.
-i|--stripes Nombre
Spécifie le nombre de rayures dans un LV rayé. C'est le nombre de PVs (périphériques) sur lesquels un LV rayé est réparti. Les données qui apparaissent séquentiellement dans le LV sont réparties sur plusieurs périphériques par unités de taille de rayure (voir --stripesize). Ceci ne modifie pas l'espace alloué existant, mais s'applique uniquement à l'espace alloué par la commande. Lors de la création d'un LV RAID 4/5/6, ce nombre n'inclut pas les périphériques supplémentaires requis pour la parité. Le nombre maximum dépend du type de RAID (raid0 : 64, raid10 : 32, raid4/5 : 63, raid6 : 62), et lorsqu'il n'est pas spécifié, la valeur par défaut dépend du type de RAID (raid0 : 2, raid10 : 2, raid4/5 : 3, raid6 : 5.) Pour répartir un nouveau LV RAID sur tous les PVs par défaut, voir lvm.conf(5) allocation/raid_stripe_all_devices.
-I|--stripesize Taille[k|UNITÉ]
La quantité de données écrite sur un périphérique avant de passer au suivant dans un LV rayé.
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées, tout en retournant succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations multi-étapes si un outil dépend de la relecture des métadonnées qu'il croit avoir changées, mais qui ne l'ont pas été.

NAME

lvextend — Extend the size of a logical volume

SYNOPSIS

lvextend [-A|--alloc AllocationPolicy] [-d|--debug] [-f|--force] [-i|--stripes Stripes] [-I|--stripe-size StripeSize] [-l|--logicalextents LogicalExtents[|“%FREE”|“%100FREE”]] [-m|--mirrors Mirrors] [-N|--noformat] [-p|--permission R|RW] [-r|--resizefs] [-t|--test] [-v|--verbose] [-y|--yes] [LogicalVolume[:PE[-PE]]...] [PhysicalVolume[:PE[-PE]]...]

lvextend [-d|--debug] [-f|--force] [-i|--stripes Stripes] [-I|--stripe-size StripeSize] [-l|--logicalextents LogicalExtents[|“%FREE”|“%100FREE”]] [-m|--mirrors Mirrors] [-N|--noformat] [-p|--permission R|RW] [-r|--resizefs] [-t|--test] [-v|--verbose] [-y|--yes] [LogicalVolume] [PhysicalVolume]

lvextend [-d|--debug] [-f|--force] [-l|--logicalextents LogicalExtents[|“%FREE”|“%100FREE”]] [-p|--permission R|RW] [-r|--resizefs] [-t|--test] [-v|--verbose] [-y|--yes] LogicalVolume PhysicalVolume

DESCRIPTION

Extends the size of an existing logical volume.

You can extend a logical volume by specifying the size and/or the physical volumes from which to allocate the extents.

If no physical volumes are specified, the allocation policy configured for the volume group is used.

The logical volume may be extended into a different type than it currently is, e.g. a linear volume may be converted into a RAID1 or RAID0 volume. See lvm.conf(5) for more details.

Use lvdisplay(8) to see the current size of the logical volume and vgdisplay(8) to see the amount of free space in the volume group.

The total size of the logical volume may not exceed the size of the volume group.

USAGE

The logical volume name may be prefixed with the volume group name for unambiguous identification (e.g. vg01/lvol01).

If lvextend is run on an LV with an insufficient number of physical extents for the requested operation (e.g. extending a linear LV to a RAID1 LV), the LV will be converted to the new type.

When extending with a specific size, the size must be positive. Otherwise, the size is reduced. See lvreduce(8) for reducing.

When extending a mirror, you can add more mirrors by using the -m option. This will increase the number of copies of the data.

When extending a snapshot, you can increase its maximum size. Use -L or -l to specify the new maximum size.

When extending a thin-provisioned volume, you can increase its maximum size. Use -L or -l to specify the new maximum size.

When extending a thin-provisioned volume that is also a pool, you can increase its size.

When extending a VDO volume, you can increase its size.

See lvmraid(7) for details on RAID volume types.

See lvmthin(7) for details on thin provisioning.

See lvmcache(7) for details on caching.

See lvmvdo(7) for details on VDO volumes.

OPTIONS

-A |--alloc AllocationPolicy

Determines the allocation policy for logical extents if no physical volume is specified. See lvm.conf(5) for the list of policies.

-d|--debug
Enable debugging.
-f|--force
Force the use of the specified options, and attempt to extend the volume even if there are problems with the metadata.
-i|--stripes Stripes
Number of stripes to use for data in a striped volume. The number of physical volumes must be greater than or equal to this value.
-I|--stripe-size StripeSize
The number of physical extents per stripe. The default is 512.
-l|--logicalextents LogicalExtents[|“%FREE”|“%100FREE”]
The number of logical extents to add.
“%FREE”: The number of logical extents to add is the number of free extents in the volume group.
“%100FREE”: All remaining free extents in the volume group are added.
This option is mutually exclusive with -L.
-m|--mirrors Mirrors
Number of mirrors to use for data in a mirrored volume. If this value is specified, the logical volume type will be changed to mirror. The number of physical volumes must be greater than or equal to this value.
-N|--noformat
Do not format the logical volume.
-p|--permission R|RW
Set the permission mode for the logical volume. R for read-only and RW for read-write.
-r|--resizefs
Resize the filesystem on the logical volume as well. The filesystem must be supported by fsadm(8). Use with extreme caution.
-t|--test
Perform a simulation of the operation without making any changes.
--type LV|raid|raid<N>|mirror|striped|linear|snapshot|thin|thin-pool|vdo|cache|cache-pool|writecache
The LV type, also known as "segment type" or "segtype". See usage descriptions for the specific ways to use these types. For more information about redundancy and performance (raid<N>, mirror, striped, linear) see lvmraid(7). For thin provisioning (thin, thin-pool) see lvmthin(7). For performance caching (cache, cache-pool) see lvmcache(7). For copy-on-write snapshots (snapshot) see usage definitions. For VDO (vdo) see lvmvdo(7). Several commands omit an explicit type option because the type is inferred from other options or shortcuts (e.g. --stripes, --mirrors, --snapshot, --virtualsize, --thin, --cache, --vdo). Use inferred types with care because it can lead to unexpected results.
--usepolicies
Perform an operation according to the policy configured in lvm.conf(5) or a profile.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Extend the size of an LV by 54MiB, using a specific PV.
lvextend -L +54 vg01/lvol10 /dev/sdk3

Extend the size of an LV by the amount of free space on PV /dev/sdk3. This is equivalent to specifying "-l +100%PVS" on the command line.
lvextend vg01/lvol01 /dev/sdk3

Extend an LV by 16MiB using specific physical extents.
lvextend -L+16m vg01/lvol01 /dev/sda:8-9 /dev/sdb:8-9

Extend an LV to use all remaining free space in volume group and all resize its filesystem with fsadm(8).
lvextend -l+100%FREE -r vg01/lvol01
