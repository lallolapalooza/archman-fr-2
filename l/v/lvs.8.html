NOM

lvs — Afficher des informations sur les volumes logiques

SYNTAXE

lvs
[ arguments_options ]
[ arguments_positionnels ]

DESCRIPTION

OPTIONS

--aligned
À utiliser avec --separator pour aligner la sortie des colonnes.
-a|--all
Afficher des informations sur les LV internes. Ce sont des composants de LV normaux, tels que des miroirs, qui ne sont pas accessibles indépendamment, par exemple, non montables.
--binary
Utiliser des valeurs binaires "0" ou "1" au lieu de valeurs littérales descriptives pour les colonnes qui ont exactement deux valeurs valides à rapporter (sans compter la valeur "inconnue" qui indique que la valeur n'a pas pu être déterminée).
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
--configreport log|vg|lv|pv|pvseg|seg
Voir lvmreport(7).
-d|--debug ...
Définir le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
--foreign
Rapporter/afficher les VG étrangers qui seraient autrement ignorés. Voir lvmsystemid(7) pour plus d'informations sur les VG étrangers.
--headings none|abbrev|full|0|1|2
Type d'en-têtes à utiliser dans la sortie du rapport. none ou 0 : Pas d'en-têtes. abbrev ou 1 : Abréviations des noms de colonnes. full ou 2 : Noms complets des colonnes.
-h|--help
Afficher le texte d'aide.
-H|--history
Inclure les LV historiques dans la sortie. (Cela n'a aucun effet sauf si des LV ont été supprimés alors que metadata/record_lvs_history dans lvm.conf(5) était activé.)
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--journal Chaîne
Enregistrer des informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre log/journal de lvm.conf. command : enregistrer des informations sur la commande. output : enregistrer la sortie par défaut de la commande. debug : enregistrer le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--logonly
Supprimer le rapport de commande et n'afficher que le rapport de journal.
--longhelp
Afficher le texte d'aide détaillé.
--nameprefixes
Ajouter un préfixe "LVM2_" suivi du nom du champ à la sortie. Utile avec --noheadings pour produire une liste de paires champ=valeur qui peuvent être utilisées pour définir des variables d'environnement (par exemple, dans les règles udev).
--noheadings
Supprimer la ligne d'en-têtes qui est normalement la première ligne de sortie. Utile lors du filtrage de la sortie.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactiver le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--nosuffix
Supprimer le suffixe des tailles de sortie. À utiliser avec --units (sauf h et H) si vous traitez la sortie.

OPTIONS

-c|--config
Read configuration information from the LVM configuration files. See lvm.conf(5) for more information.
-d|--debug ...
Set debug level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
-d|--devices String
Set the devices file that LVM will use instead of the default (usually /etc/lvm/devices.conf). Use --devices help to see the list of available fields.
--disablemonitoring
Disable monitoring of LVM events. This is useful if LVM events are being processed by another process.
--globalrconflictpolicy String
Set the global conflict policy for all VGs. This policy will be used when multiple hosts access the same VG. Possible values are: Readonly, Writeable, Error.
--lockingargument String
Use the specified string as the argument to the locking method. See lvm.conf(5) for more information.
-h|--longhelp
Display extended usage information.
--metadataprofile String
Use the specified metadata profile to store metadata. See lvm.conf(5) for more information.
--monitor
Enable monitoring of LVM events. This is useful if you want to track changes to LVM logical volumes and volume groups.
--nameprefixes
When used with --separator, output values in the field=value pairs are not quoted.
--nocolons
Remove colons from device names. This is useful when comparing device names with other tools.
--noscan
Do not scan for devices. This is useful when you have a small number of devices and you want to speed up the boot process.
-o|--options String
Specify the fields to be displayed in the output. Use -o help to view the list of all available fields. Use separate lists of fields to add, remove or compact by repeating the -o option: -o+field1,field2 -o-field3,field4 -o#field5. These lists are evaluated from left to right. Use field name lv_all to view all LV fields, vg_all all VG fields, pv_all all PV fields, seg_all all LV segment fields, and pvseg_all all PV segment fields. See the lvm.conf(5) report section for more config options. See lvmreport(7) for more information about reporting.
--profile String
An alias for --commandprofile or --metadataprofile, depending on the command.
-q|--quiet ...
Suppress output and log messages. Overrides --debug and --verbose. Repeat once to also suppress any prompts with answer 'no'.
--readonly
Prevent the command from making changes, including activation and metadata updates. (See --permission r for read only LVs.)
--reportformat basic|json|json_std
Overrides current output format for reports which is defined globally by the report/output_format setting in lvm.conf(5). basic is the original format with columns and rows. If there is more than one report per command, each report is prefixed with the report name for identification. json produces report output in JSON format. json_std produces report output in JSON format which is more compliant with JSON standard. See lvmreport(7) for more information.
--rows
Output columns as rows.
--segments
Use default columns that emphasize segment information.
-S|--select String
Select objects for processing and reporting based on specified criteria. The criteria syntax is described by --select help and lvmreport(7). For reporting commands, one row is displayed for each object matching the criteria. See --options help for selectable object fields. Rows can be displayed with an additional "selected" field (-o selected) showing 1 if the row matches the selection and 0 otherwise. For non-reporting commands which process LVM entities, the selection is used to choose items to process.
--separator String
String to use to separate each column. Useful if grepping the output.
--shared
Report/display shared VGs that would otherwise be skipped when lvmlockd is not being used on the host. See lvmlockd(8) for more information about shared VGs.
-O|--sort String
Comma-separated ordered list of columns to sort by. Replaces the default selection. Precede any column with - for a reverse sort on that column.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
--unbuffered
Produce output immediately without sorting or aligning the columns properly.
--units [Number]r|R|h|H|b|B|s|S|k|K|m|M|g|G|t|T|p|P|e|E
All sizes are output in these units: human-(r)eadable with '<' rounding indicator, (h)uman-readable, (b)ytes, (s)ectors, (k)ilobytes, (m)egabytes, (g)igabytes, (t)erabytes, (p)etabytes, (e)xabytes. Capitalise to use multiples of 1000 (S.I.) instead of 1024. Custom units can be specified, e.g. --units 3M.
--unquoted
When used with --nameprefixes, output values in the field=value pairs are not quoted.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Nom du groupe de volumes. Voir lvm(8) pour les noms valides.
LV
Nom du volume logique. Voir lvm(8) pour les noms valides. Un argument positionnel LV inclut généralement le nom du VG et le nom du LV, par exemple VG/LV.
Tag
Nom de l'étiquette. Voir lvm(8) pour des informations sur les noms d'étiquettes et l'utilisation des étiquettes à la place d'un VG, LV ou PV.
String
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Size[UNIT]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs binaires, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNIT. UNIT représente d'autres unités d'entrée possibles : b|B est octets, s|S est secteurs de 512 octets, k|K est KiB, m|M est MiB, g|G est GiB, t|T est TiB, p|P est PiB, e|E est EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient des multiples de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement être substitué à un paramètre VG requis.

NOTES

Les bits de lv_attr sont :

1
Type de volume : (C)ache, (m)irrored, (M)irrored sans synchronisation initiale, (o)rigin, (O)rigin avec fusion de snapshot, (g) integrity, (r)aid, (R)aid sans synchronisation initiale, (s)napshot, (S)napshot en cours de fusion, (p) vmove, (v)irtual, image miroir ou raid (i)mage, miroir ou raid (I)mage hors synchronisation, journal de miroir (l)og, en cours de (c)onversion, volume fin (V)olume, pool fin (t) pool, données de pool fin (T) pool, pool v(d)o, données de pool v(D)o, métadonnées de raid ou de pool ou de pool, spare de métadonnées.
2
Permissions : (w)ritable, (r)ead-only, activation en (R)ead-only de volume non read-only.
3
Politique d'allocation : (a)nywhere, (c)ontiguous, (i)nherited, c(l)ing, (n)ormal. Ceci est en majuscules si le volume est actuellement verrouillé contre les modifications d'allocation, par exemple lors de pvmove(8).
4
Mineur fixe (m)inor.
5
État : (a)ctive, (h)istorical, (s)uspended, snapshot (I)nvalid, snapshot suspendu (S)invalid, échec de fusion de snapshot (m)erge, échec de fusion de snapshot suspendu (M)erge, périphérique mappé (d)evice présent sans tables, périphérique mappé présent avec table (i)inactive, pool fin (c)heck requis, pool fin suspendu (C)heck requis, (X) inconnu.
6
Périphérique (o)pen, (X) inconnu.
7
Type de cible : (C)ache, (m)irror, (r)aid, (s)napshot, (t)hin, (u)nknown, (v)irtual. Ceci regroupe les volumes logiques liés à la même cible du noyau. Ainsi, par exemple, les images miroir, les journaux miroir ainsi que les miroirs eux-mêmes apparaissent comme (m) s'ils utilisent le pilote noyau miroir device-mapper d'origine ; tandis que les équivalents raid utilisant le pilote noyau md raid apparaissent tous comme (r). Les snapshots utilisant le pilote device-mapper d'origine apparaissent comme (s) ; tandis que les snapshots de volumes fins utilisant le nouveau pilote de provisionnement fin apparaissent comme (t).
8
Les blocs de données nouvellement alloués sont écrasés avec des blocs de (z)éros avant utilisation.
9
Santé du volume, où il existe actuellement trois groupes d'attributs identifiés :
Communs à tous les volumes logiques : (p)artial, (X) unknown.
(p)artial signifie qu'un ou plusieurs des volumes physiques utilisés par ce volume logique sont manquants du système. (X) unknown signifie que l'état est inconnu.
Liés aux volumes logiques RAID : (r)efresh nécessaire, (m)ismatches existent, (w)ritemostly.
(r)efresh signifie qu'un ou plusieurs des volumes physiques utilisés par ce volume logique RAID ont subi une erreur d'écriture. L'erreur d'écriture peut être due à une défaillance temporaire de ce volume physique ou à une indication de défaillance. Le périphérique doit être actualisé ou remplacé. (m)ismatches signifie que le volume logique RAID a des parties du tableau qui ne sont pas cohérentes. Les incohérences sont détectées en initiant un "check" sur un volume logique RAID. (Les opérations de vérification, "check" et "repair", peuvent être effectuées sur un volume logique RAID via la commande 'lvchange'.) (w)ritemostly signifie que les périphériques dans un volume logique RAID 1 ont été marqués comme write-mostly. Re(s)haping signifie qu'un volume logique RAID est en cours d'ajout/suppression de bandes, ou de modification de la taille des bandes ou de l'algorithme RAID. (R)emove after reshape signifie que les images raid en bandes libérées doivent être supprimées.
Liés aux volumes logiques de pools fins : (
F)ailed, hors d'(D)onnées, métadonnées en lecture seule.
(F)ailed est défini si le pool fin rencontre des défaillances graves et qu'ainsi aucune E/S supplémentaire n'est autorisée. Hors d'(D)onnées est défini si le pool fin a épuisé l'espace de données. (M)étadonnées en lecture seule signifie que le pool fin rencontre certains types de défaillances mais qu'il est encore possible de lire au moins, mais aucun changement de métadonnées n'est autorisé.
Lié aux volumes logiques fins : (F)ailed.
(F)ailed est défini lorsque le pool fin associé entre en état Failed et qu'aucune E/S supplémentaire n'est autorisée.
Lié aux volumes logiques de cache d'écriture : (E)rror.
(E)rror est défini lorsque dm-writecache signale une erreur.
10
s(k)ip activation : ce volume est marqué pour être ignoré lors de l'activation.
