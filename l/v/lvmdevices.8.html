DESCRIPTION

Le fichier des périphériques LVM (devices file) est la liste des périphériques que les commandes LVM utiliseront. Il est situé dans /etc/lvm/devices/system.devices. La commande lvmdevices(8) gère ce fichier, et est utilisée pour ajouter, supprimer et lister les périphériques.

Listage des périphériques

Exécutez la commande lvmdevices sans options ni arguments pour afficher les entrées de system.devices :
lvmdevices

Chaque ligne commence par un nom de périphérique actuel du système, suivi de son identifiant de périphérique provenant du fichier des périphériques, suivi d'autres détails de périphérique utilisés par LVM. Une ligne commençant par « Device none » indique qu'aucun périphérique du système ne correspond à l'identifiant du périphérique. (La consultation directe du fichier system.devices n'indique pas si un périphérique est présent sur le système.)

Ajout de périphériques

Pour utiliser un périphérique avec LVM, ajoutez-le au fichier des périphériques avec l'une des commandes suivantes.

Ajouter un périphérique en référençant son chemin d'accès :
lvmdevices --adddev périphérique

Ajouter un périphérique en référençant son PVID :
lvmdevices --addpvid PVID

Ajouter un périphérique en référençant son identifiant de périphérique :
lvmdevices --addid NOMID --deviceidtype TYPEDEID

Ajouter tous les PV d'un VG :
vgimportdevices VG

Ajouter tous les PV de tous les VG visibles :
vgimportdevices -a

pvcreate, vgcreate, et vgextend recherchent également en dehors du fichier des périphériques existant pour trouver le périphérique cible, et l'ajoutent automatiquement au fichier des périphériques.

Suppression de périphériques

Supprimer un périphérique du fichier des périphériques empêchera LVM de voir ou d'utiliser ce périphérique. Supprimez un périphérique avec l'une des commandes suivantes.

Supprimer un périphérique en référençant son chemin d'accès :
lvmdevices --deldev périphérique

Supprimer un périphérique en référençant son PVID :
lvmdevices --delpvid PVID

Supprimer un périphérique en référençant son identifiant de périphérique :
lvmdevices --delid NOMID --deviceidtype TYPEDEID

Identifiants de périphériques

LVM identifie les périphériques dans le fichier des périphériques en utilisant des identifiants spécifiques au matériel, tels que le WWID ou le numéro de série. Les identifiants spécifiques au sous-système sont utilisés pour les types de périphériques virtuels, qui visent également à être uniques et stables. Lorsqu'aucun identifiant matériel ou de sous-système n'est disponible, LVM utilise par défaut le nom du périphérique comme identifiant de périphérique. L'utilisation de noms de périphériques comme identifiants n'est pas optimale car ils ne sont pas stables et changent souvent après le redémarrage. Lorsque des noms de périphériques sont utilisés comme identifiants, LVM doit effectuer une analyse supplémentaire des périphériques pour les localiser si le nom du périphérique change.

Lorsque des identifiants de périphériques stables sont utilisés, LVM n'accédera pas aux périphériques en dehors de ceux listés dans le fichier des périphériques. Lorsque des noms de périphériques sont utilisés comme identifiants, LVM analysera les périphériques en dehors du fichier des périphériques pour localiser les PV sur les périphériques dont le nom a changé. Le paramètre de configuration search_for_devnames peut être utilisé pour contrôler le comportement de LVM dans la localisation des entrées de nom de périphérique renommées.

Un identifiant de périphérique se compose de deux parties : un TYPEID et un NOMID.

Le TYPEID spécifie l'origine de l'identifiant, et le NOMID est l'identifiant réel. Il existe un ensemble prédéfini de TYPEID listé dans la section suivante. Une entrée du fichier des périphériques doit avoir l'un de ces types d'identifiant. Lors de l'ajout d'un périphérique au fichier des périphériques, LVM choisit automatiquement le meilleur TYPEID, qui peut être remplacé avec l'option --deviceidtype (ce n'est généralement pas recommandé.)

Pour afficher tous les identifiants de périphériques possibles pour un périphérique, ou la valeur d'un type spécifique, utilisez les commandes :

lvmdevices --listids périphérique
lvmdevices --listids périphérique --deviceidtype TYPEDEID

Types identifiants périphériques

Les types d'identifiants de périphériques disponibles sont :

•
sys_wwid utilise le wwid rapporté par le fichier sysfs wwid. C'est le premier choix.
•
wwid_naa utilise le wwid naa décodé à partir du fichier sysfs vpd_pg83.
•
wwid_eui utilise le wwid eui décodé à partir du fichier sysfs vpd_pg83.
•
wwid_t10 utilise le wwid t10 décodé à partir du fichier sysfs vpd_pg83.
•
sys_serial utilise le numéro de série rapporté par le fichier sysfs serial ou le fichier vpd_pg80. Un numéro de série est utilisé si aucun wwid n'est disponible.
•
mpath_uuid est utilisé pour les périphériques dm multipath, rapporté par sysfs.
•
crypt_uuid est utilisé pour les périphériques dm crypt, rapporté par sysfs.
•
md_uuid est utilisé pour les périphériques md, rapporté par sysfs.
•
lvmlv_uuid est utilisé si un PV est placé au-dessus d'un LV LVM, rapporté par sysfs.
•
loop_file est utilisé pour les périphériques de boucle, le nom du fichier de base rapporté par sysfs.
•
devname le nom du périphérique est utilisé si aucun autre type ne s'applique.
•
nvme_uuid, nvme_nguid, nvme_eui64 ne sont généralement pas utilisés, mais peuvent apparaître pour les périphériques nvme qui rapportent des valeurs wwid invalides.

Fichiers sysfs

La plupart des types d'identifiants de périphériques lisent la valeur de l'identifiant du périphérique à partir de sysfs. Ces valeurs sysfs peuvent également être lues directement à partir des chemins suivants :

/sys/dev/block/majeur:mineur/device/wwid
/sys/dev/block/majeur:mineur/device/serial
/sys/dev/block/majeur:mineur/wwid
/sys/dev/block/majeur:mineur/device/vpd_pg83 (binaire)
/sys/dev/block/majeur:mineur/device/vpd_pg80 (binaire)
/sys/dev/block/majeur:mineur/dm/uuid (lu par LVM via ioctl)
/sys/dev/block/majeur:mineur/md/uuid
/sys/dev/block/majeur:mineur/loop/backing_file

(Certaines valeurs sysfs sont modifiées avant d'être utilisées comme identifiant de périphérique, par exemple les espaces sont omis ou remplacés par des underscores.)

Contenu fichier devices

LVM écrit des informations supplémentaires dans le fichier des périphériques en plus des identifiants de périphérique. Les commandes LVM mettent automatiquement à jour ces informations si elles changent. Cela inclut le dernier nom de périphérique connu, et l'UUID PV (PVID) de l'en-tête de disque LVM.

DESCRIPTION

The lvmdevices utility is used to manage the devices file, which is a list of devices that LVM can use. This file is typically located at /etc/lvm/devices/system.devices.

The devices file is intended to be managed by LVM commands, not by the user directly. It contains a HASH value that LVM uses to detect if the file has been modified since LVM last wrote it. When LVM updates the devices file, the previous version is moved to /etc/lvm/devices/backup/.

The following fields can be found in the devices file:

VERSION
Incremented for each file update.
PRODUCT_UUID
A unique machine ID used to detect if the system.devices file has been moved to a new machine, and may require updating. When not available, HOSTNAME is used.

Device entry fields:

IDTYPE
Indicates the source of the device ID value in IDNAME.
IDNAME
The unique device ID value.
DEVNAME
The most recent device name associated with the device ID.
PVID
The LVM PV UUID from the LVM disk header.
PART
The partition number if a PV exists on a partition.

The following commands can be used to manage the devices file:

Check devices file entries for outdated information:

lvmdevices --check

Update devices file fields that are outdated:

lvmdevices --update

DEVICE ID REFRESH

When LVM writes system.devices, it includes a local machine ID in the system.devices file (as PRODUCT_UUID or HOSTNAME). When LVM reads system.devices, it compares this saved machine ID to the current machine, which allows LVM to detect when system.devices has been copied or restored onto a different machine. When a machine change is detected, LVM enables a "device ID refresh" mode (configured by lvm.conf(5) device_ids_refresh and device_ids_refresh_checks).

In refresh mode, a device in system.devices that is not found by its device ID will be located using its PVID. LVM will scan all devices on the system to search for the missing PVIDs in system.devices. If a PVID is found on a new device, the system.devices entry is updated with a new device ID matching the new device on which the PVID was found. The refresh mode can be configured to run once, when the machine change is first detected, or can be enabled for a period of time following the first refresh, or can be disabled entirely.

device_ids_refresh = 0
Disables refresh mode.
device_ids_refresh = 1
Enables one attempt to refresh device IDs when a machine change is first detected.
device_ids_refresh = seconds
The refresh mode is enabled for this number of seconds following the initial refresh attempt, or until all PVs in system.devices are found. During this period, a REFRESH_UNTIL line appears in system.devices. Accepted values are 10-600 seconds.

In addition to the automated device ID refresh mode, refresh can be performed manually:

Check if system.devices would be updated with new device IDs:

lvmdevices --check --refresh

Update system.devices with new device IDs if PVs are found on new devices:

lvmdevices --update --refresh

The machine ID used in system.devices will be either the DMI product_uuid from /sys/devices/virtual/dmi/id/product_uuid, or the hostname from uname(2). See lvm.conf(5) device_ids_refresh_checks to configure this.

CUSTOM DEVICES FILES

Multiple devices files can be kept in /etc/lvm/devices, which allows LVM to be used with different sets of devices. For example, a given application may not need to access the system's devices, and the system may not need to access the application's devices. In this case, system.devices could list only the system's devices and <application>.devices file could list only the application's devices. The option --devicesfile <filename> is used to select the devices file to use with the command. Without the option set, the default system.devices file is used.

If the special devices file /etc/lvm/devices/dmeventd.devices exists, then dmeventd uses dmeventd.devices instead of system.devices. Using dmeventd.devices is necessary if VGs from separate devices files require the services of dmeventd. In this case, dmeventd.devices should list devices from all of the VGs that require dmeventd.

DISABLING AND OVERRIDING

There are multiple ways that the devices file feature can be disabled or overridden:

•
no system.devices
If the system.devices file does not exist, then the devices file feature is disabled.
•
use_devicesfile=0
If lvm.conf use_devicesfile is set to 0, then the devices file feature is disabled, even if the system.devices file exists.
•
--devicesfile ""
If an empty devices file name is specified on the command line, then that command will not use a devices file.
•
--devices device
If specific devices are named on the command line with --devices, then the command will not use a devices file, and will only access the named devices.
•
pvs -A
If given the -A or --allpvs option, the pvs(8) command will not use a devices file.

When the devices file is disabled, LVM commands revert to using the lvm.conf filter. When the devices file is used, LVM commands ignore the lvm.conf filter setting, except for vgimportdevices which does apply the regex filter to the set of devices on the system when looking for VGs to import to the devices file.

VG METADATA

LVM commands that write VG metadata will include the device ID of each PV in the VG metadata. The device ID can be displayed with the options:

pvs -o deviceidtype,deviceid

(Note that the lvmdevices command does not update VG metadata, but subsequent LVM commands modifying the metadata will include the device ID.)

CREATING THE DEVICES FILE

If the system.devices file does not yet exist, the pvcreate or vgcreate commands will create it only if they see no existing VGs on the system. lvmdevices --adddev and vgimportdevices will always create a new devices file if it does not yet exist.

OPTIONS

--config String
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument String utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--deldev String
Supprime un périphérique du fichier des périphériques. Utilisé seul, --deldev spécifie un nom de périphérique. Utilisé avec --deviceidtype, --deldev spécifie un identifiant de périphérique.
--delid String
Supprime le périphérique avec l'identifiant de périphérique spécifié du fichier des périphériques.
--delnotfound
Supprime les entrées du fichier des périphériques sans périphérique correspondant.
--delpvid String
Supprime un périphérique avec le PVID du fichier des périphériques.

Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés sembleront être manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier des périphériques.
--devicesfile String
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).

--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.

N'utilise pas le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices lorsque approprié.
--nolocking
Désactive le verrouillage. Utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile String
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages de journalisation. Remplace --debug et --verbose. Répéter une fois pour également supprimer toute invite en répondant 'non'.
--refresh
Recherche les PV manquants sur de nouveaux périphériques et met à jour le fichier des périphériques avec les nouveaux identifiants de périphériques pour les PV s'ils sont trouvés sur de nouveaux périphériques. Ceci est utile si les PV ont été déplacés vers de nouveaux périphériques avec de nouveaux WWID, par exemple. Le type d'identifiant de périphérique et le nom peuvent tous deux changer pour un PV. ATTENTION : si un PV est détaché du système, mais qu'un périphérique contenant un clone ou un snapshot de ce PV est présent, alors refresh remplacerait le bon identifiant de périphérique par l'identifiant de périphérique du clone/snapshot, et lvm commencerait à utiliser le mauvais périphérique pour le PV. Utiliser deldev/adddev pour changer en toute sécurité un identifiant de périphérique PV dans ce scénario.
-t|--test
Exécute en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées mais en renvoyant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil repose sur la relecture de métadonnées qu'il croit avoir changées mais qui ne l'ont pas fait.
--update
Met à jour le contenu du fichier des périphériques.
-v|--verbose ...
Définit le niveau de verbosité. Répéter de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Affiche les informations de version.
-y|--yes
Ne demande pas de confirmation interactivement mais suppose toujours la réponse oui. Utiliser avec extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

String
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Size[UNIT]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font toutes deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNIT. UNIT représente d'autres unités d'entrée possibles : b|B sont les octets, s|S sont les secteurs de 512 octets, k|K sont les KiB, m|M sont les MiB, g|G sont les GiB, t|T sont les TiB, p|P sont les PiB, e|E sont les EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient un multiple de 1000.)
