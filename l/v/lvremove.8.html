NOM

lvremove — Supprime un ou plusieurs volumes logiques du système

SYNOPIS

lvremove args_positionnels
[ args_optionnels ]

DESCRIPTION

lvremove supprime un ou plusieurs LVs. Pour les LVs standards, cela renvoie les extents logiques utilisés par le LV vers le VG pour être utilisés par d'autres LVs.

Une confirmation sera demandée avant de désactiver tout LV actif préalablement à la suppression. Les LVs ne peuvent pas être désactivés ou supprimés tant qu'ils sont ouverts (par exemple, s'ils contiennent un système de fichiers monté). La suppression d'un LV d'origine supprimera également tous les snapshots dépendants.

Lorsqu'une seule option de forçage est utilisée, les LVs sont supprimés sans confirmation, et la commande tentera de désactiver les LVs inutilisés.

Pour supprimer des LVs endommagés, deux options de forçage peuvent être nécessaires (-ff).

LVs historiques

Si le paramètre de configuration metadata/record_lvs_history est activé et que le LV en cours de suppression fait partie de l'historique d'au moins un LV encore présent, alors une représentation simplifiée du LV sera conservée. Cela inclut l'heure de suppression (champ de rapport lv_time_removed), l'heure de création (lv_time), le nom (lv_name), l'UUID du LV (lv_uuid) et le nom du VG (vg_name). Cela permet aux rapports ultérieurs de voir la chaîne d'ascendance des volumes snapshots "thin", même après la suppression de certains LVs intermédiaires. Les noms de ces LVs historiques acquièrent un trait d'union comme préfixe (par exemple, '-lvol1') et ne peuvent pas être réactivés. Utilisez lvremove une seconde fois, avec le trait d'union, pour supprimer complètement l'enregistrement de l'ancien LV.

OPTIONS

-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après un changement. L'activation est fortement recommandée ! Voir vgcfgbackup(8) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'argument utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini à non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-f|--force ...
Ignore diverses vérifications, confirmations et protections. À utiliser avec extrême prudence.
-h|--help
Affiche le texte d'aide.
--journal Chaîne
Enregistre les informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre lvm.conf log/journal. command: enregistre des informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche le texte d'aide détaillé.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques des PV. Une commande peut lire davantage de périphériques pour trouver des PVs lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard des fichiers d'indices si nécessaire.
--nohistory
N'enregistre pas l'historique des LVs en cours de suppression. Ceci n'a aucun effet à moins que le paramètre de configuration metadata/record_lvs_history ne soit activé.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas la notification d'udev. Il continuera, indépendamment de tout traitement possible par udev en arrière-plan. N'utilisez ceci que si udev n'est pas en cours d'exécution ou s'il a des règles qui ignorent les périphériques créés par LVM.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprime la sortie et les messages de journalisation. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON, plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-S|--select Chaîne
Sélectionne des objets pour le traitement et le reporting en fonction de critères spécifiés. La syntaxe des critères est décrite par --select help et lvmreport(7). Pour les commandes de reporting, une ligne est affichée pour chaque objet correspondant aux critères. Voir --options help pour les champs d'objets sélectionnables. Les lignes peuvent être affichées avec un champ supplémentaire "selected" (-o selected) indiquant 1 si la ligne correspond à la sélection et 0 si
herwise. Pour les commandes ne générant pas de rapport qui traitent des entités LVM, la sélection est utilisée pour choisir les éléments à traiter.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées, mais en retournant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil s'appuie sur la lecture des métadonnées qu'il croit avoir changées mais qui n'ont pas été modifiées.
-v|--verbose ...
Définir le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
-y|--yes
Ne pas demander de confirmation interactivement mais répondre toujours oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

VG
Nom du Groupe de Volumes. Voir lvm(8) pour les noms valides.
LV
Nom du Volume Logique. Voir lvm(8) pour les noms valides. Un argument positionnel LV comprend généralement le nom du VG et le nom du LV, par exemple VG/LV.
Tag
Nom de l'étiquette (Tag). Voir lvm(8) pour des informations sur les noms d'étiquettes et leur utilisation à la place d'un VG, LV ou PV.
Select
Select indique qu'un paramètre positionnel requis peut être omis si l'option --select est utilisée. Aucun argument n'apparaît à cette position.
String
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Size[UNIT]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNIT. UNIT représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient un multiple de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement remplacer un paramètre VG requis.

EXEMPLES

Supprimer un LV actif sans demander de confirmation.
lvremove -f vg00/lvol1

Supprimer tous les LV du VG spécifié.
lvremove vg00
