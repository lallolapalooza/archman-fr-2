LV2LINT(1) Manuel des commandes générales LV2LINT(1)

NOM

lv2lint - un linter LV2

SYNTAXE

lv2lint [OPTIONS] {URI_PLUGIN}*

DESCRIPTION

lv2lint vérifie si les plugins LV2 donnés respectent la spécification.

Il ne se contente pas de vérifier les fichiers *.ttl, mais charge effectivement les plugins (et leurs interfaces utilisateur) et vérifie si les fonctionnalités requises et les extensions exposées correspondent bien entre le binaire et le *.ttl.

Il permet ainsi de trouver des erreurs qui ne peuvent pas être facilement trouvées en vérifiant simplement la validité du *.ttl.

Il est recommandé de l'exécuter sur vos plugins dans le cadre de votre intégration continue, après les avoir vérifiés pour leur validité avec sord_validate et avant de les publier.

OPTIONS

-v

Afficher les informations sur la version et la licence

-h

Afficher les informations d'utilisation

-q

Mode silencieux, n'afficher qu'un résumé

-d

Afficher la documentation détaillée des éléments de test

-o

Exécuter les éléments de test en ligne

-m

Créer un courriel à l'auteur du plugin

-g GREETER

Salutation personnalisée pour les courriels

-s SYMBOL_PATTERN

Modèle de symbole (caractère générique shell) à mettre sur liste blanche (peut être utilisé plusieurs fois)

-l LIBRARY_PATTERN

Modèle de bibliothèque (caractère générique shell) à mettre sur liste blanche (peut être utilisé plusieurs fois)

-u URI_PATTERN

Modèle d'URI (caractères génériques shell) à préfixer aux modèles de liste blanche de test, de symbole et de bibliothèque (peut être utilisé plusieurs fois). Le modèle de liste blanche sera alors seulement effectif lorsque le modèle d'URI actuel correspondra également (par exemple, pour le plugin lui-même ou l'une de ses interfaces utilisateur).

-t TEST_PATTERN

Modèle de nom de test (caractère générique shell) à mettre sur liste blanche (peut être utilisé plusieurs fois)

-I INCLUDE_DIR

En plus des chemins d'installation par défaut des plugins LV2, utiliser le répertoire d'inclusion pour rechercher des plugins (peut être utilisé plusieurs fois)

-M (no)pack (Par défaut : pack)

Modes à activer/désactiver, par exemple le mode (pack)ageur saute certains tests fatals pour les responsable de paquets qui ne sont importants que pour les binaires distribués librement.

Si vous êtes un responsable de paquet de distribution, préférez exécuter avec '-M pack' (Par défaut). Si vous voulez construire des binaires pour la distribution, préférez exécuter avec -M nopack.

-S (no)warn|note|pass|all (Par défaut : fail|warn)

En plus des erreurs seules (fail), afficher également les avertissements (warn), les notes (note), les succès (pass) ou tout (all) sur la console. Le préfixe no- inverse la signification.

-E (no)warn|note|all (Par défaut : fail)

En plus des erreurs seules (fail), traiter également les avertissements (warn), les notes (note) ou tout (all) comme des erreurs. Le préfixe no- inverse la signification.
