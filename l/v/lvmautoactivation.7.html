LVMAUTOACTIVATION(7) Manuel d'informations diverses LVMAUTOACTIVATION(7)

NOM

lvmautoactivation — Autoactivation LVM

DESCRIPTION

L'autoactivation est l'activation des LV effectuée automatiquement par le système en réponse à l'attachement de périphériques LVM à la machine. Lorsque tous les PV d'un VG sont attachés, le VG est complet et les LV du VG sont activés.

L'autoactivation des VG, ou de LV spécifiques, peut être empêchée en utilisant vgchange ou lvchange --setautoactivation n. La configuration lvm.conf(5) auto_activation_volume_list est une autre façon de limiter l'autoactivation.

autoactivation par événement

L'autoactivation LVM est "basée sur les événements", où les VG complets sont activés en réponse à des uevents qui se produisent pendant le démarrage du système ou à tout moment après le démarrage du système. Une ancienne forme d'autoactivation était "statique", où les VG complets sont activés à un point fixe pendant le démarrage du système par un service systemd, et non en réponse à des événements.

L'autoactivation basée sur les événements est pilotée par udev, les règles udev et systemd. Lorsqu'un périphérique est attaché à une machine, un uevent est généré par le noyau pour notifier l'espace utilisateur du nouveau périphérique. systemd-udev exécute les règles udev pour traiter le nouveau périphérique. Les règles Udev utilisent blkid pour identifier le périphérique comme un PV LVM et exécutent ensuite la règle udev spécifique à LVM pour le périphérique, ce qui déclenche l'autoactivation.

Il existe deux variantes d'autoactivation basée sur les événements qui peuvent être utilisées sur un système, en fonction de la règle udev LVM installée (trouvée dans /lib/udev/rules.d/). Ce qui suit résume les étapes de chaque règle qui mènent à l'autoactivation :

69-dm-lvm-metad.rules

•
périphérique /dev/name avec majeur:mineur X:Y est attaché à la machine
•
systemd/udev exécute blkid pour identifier /dev/name comme un PV LVM
•
la règle udev 69-dm-lvm-metad.rules est exécutée pour /dev/name
•
la règle udev LVM exécute le service systemd lvm2-pvscan@X:Y.service
•
le service lvm2-pvscan exécute :
pvscan --cache -aay --major X --minor Y
•
pvscan lit le périphérique, enregistre que le PV est en ligne (voir pvs_online), et vérifie si le VG est complet.
•
si le VG est complet, pvscan crée le fichier temporaire vgs_online, et active le VG.
•
la sortie de la commande d'activation peut être vue via systemctl status lvm2-pvscan*

69-dm-lvm.rules

•
périphérique /dev/name avec majeur:mineur X:Y est attaché à la machine
•
systemd/udev exécute blkid pour identifier /dev/name comme un PV LVM
•
la règle udev 69-dm-lvm.rules est exécutée pour /dev/name
•
la règle udev LVM exécute :
pvscan --cache --listvg --checkcomplete --vgonline --autoactivation event --udevoutput --journal=output /dev/name
•
pvscan lit le périphérique, enregistre que le PV est en ligne (voir pvs_online), et vérifie si le VG est complet.
•
si le VG est complet, pvscan crée le fichier temporaire vgs_online, et imprime le nom du VG pour que la règle udev l'importe : LVM_VG_NAME_COMPLETE='vgname'
•
si la règle udev LVM voit LVM_VG_NAME_COMPLETE de pvscan, elle active le VG en utilisant un service systemd transitoire nommé lvm-activate-<vgname>.
•
le service lvm-activate-<vgname> exécute
vgchange -aay --autoactivation event <vgname>
•
la sortie de la commande d'activation peut être vue via journalctl -u lvm-activate-<vgname>

options pvscan

--cache
Lire l'argument <device> (et uniquement cet appareil), et enregistrer que le PV est en ligne en créant le fichier /run/lvm/pvs_online/<pvid> contenant le nom du VG et le périphérique pour le PV.
-aay
Activer le VG depuis la commande pvscan (inclut implicitement --checkcomplete et --vgonline).
--checkcomplete
Vérifier si le VG est complet, c'est-à-dire si tous les PV sont présents sur le système, en vérifiant les fichiers /run/lvm/pvs_online/<pvid>.
--vgonline
Créer /run/lvm/vgs_online/<vgname> si le VG est complet (utilisé pour garantir qu'une seule commande effectue l'activation).
--autoactivation event
Informer la commande qu'elle est utilisée pour l'autoactivation basée sur les événements.
--listvg
Afficher le nom du VG utilisant le périphérique.
--udevoutput
Afficher uniquement la sortie qui peut être importée dans la règle udev, en utilisant le format de clé d'environnement udev, c'est-à-dire NAME='value'.
--journal=output
Envoyer la sortie de commande standard au journal (lorsque la sortie standard est réservée à la sortie udev).

fichiers run

Les commandes d'autoactivation utilisent un certain nombre de fichiers temporaires dans /run/lvm (avec l'attente qu'ils soient effacés entre les redémarrages).

pvs_online
pvscan --cache crée un fichier ici pour chaque PV attaché. Le fichier est nommé avec le PVID et contient le nom du VG et les informations du périphérique. L'existence du fichier est utilisée pour déterminer quand tous les PV d'un VG donné sont présents. Les informations du périphérique dans ces fichiers sont également utilisées pour optimiser la localisation des périphériques d'un VG lorsque le VG est activé.
pvs_lookup
pvscan --cache crée un fichier ici nommé pour un VG (s'il n'en existe pas déjà un). Le fichier contient une liste de PVIDs dans le VG. Ceci est nécessaire lorsqu'un PV est traité sans métadonnées VG, auquel cas la liste des PVIDs du fichier de recherche est utilisée pour vérifier si le VG est complet.
vgs_online
La première commande d'activation (pvscan ou vgchange) à créer un fichier ici, nommé pour le VG, activera le VG. Ceci résout une course lorsque des commandes concurrentes tentent d'activer un VG simultanément.

autoactivation statique

Une méthode d'autoactivation statique n'est plus fournie par lvm. Définir event_activation=0 désactive toujours l'autoactivation basée sur les événements. ATTENTION : désactiver l'activation par événement sans alternative peut empêcher un système de démarrer. Un service systemd personnalisé pourrait être écrit pour exécuter l'autoactivation pendant le démarrage du système, auquel cas désactiver l'autoactivation par événement pourrait être utile.

filtre lvm.conf

Les liens symboliques des périphériques de /dev/disk/ peuvent être utilisés dans le filtre de lvm.conf(5) pour se prémunir contre les changements de noms de périphériques du noyau. Les préfixes /dev/disk/by-path/ ou /dev/disk/by-id/ doivent être inclus dans les noms de filtre ; ces préfixes aident lvm à détecter que des noms de liens symboliques sont utilisés. Les filtres contenant des liens symboliques nécessitent une correspondance spéciale par les commandes exécutées dans la règle udev lvm.

Les liens symboliques courants, par exemple commençant par wwn-, scsi-, pci-, ou lvm-pv-uuid-, sont recommandés. Les liens symboliques peu communs ou personnalisés créés par des règles udev personnalisées peuvent être moins fiables. Si une règle udev personnalisée crée des liens symboliques utilisés dans le filtre lvm, alors la règle udev doit être démarrée avant la règle lvm.

EXEMPLES

Le VG "vg" contient deux PV :

# pvs -o name,vgname,uuid /dev/sdb /dev/sdc
  PV         VG PV UUID
  /dev/sdb   vg 1uKpaT-lFOZ-NLHX-j4jI-OBi1-QpdE-HZ5hZY
  /dev/sdc   vg 5J3tM8-aIPe-2vbd-DBe7-bvRq-TGj0-DaKV2G

utilisation de --cache :

# pvscan --cache /dev/sdb
  pvscan[12922] PV /dev/sdb online.
# pvscan --cache /dev/sdc
  pvscan[12923] PV /dev/sdc online.
# cat /run/lvm/pvs_online/1uKpaTlFOZNLHXj4jIOBi1QpdEHZ5hZY
8:16
vg:vg
dev:/dev/sdb
# cat /run/lvm/pvs_online/5J3tM8aIPe

lvmautoactivation(7) — LVM TOOLS

NAME

lvmautoactivation, pvscan — LVM auto-activation

DESCRIPTION

The LVM auto-activation feature allows the system to automatically activate all logical volumes and volume groups on boot or on plug-in of storage devices.

The auto-activation is controlled by the auto_activation_volume_groups parameter in lvm.conf(5).

The pvscan command can be used to scan for physical volumes and activate volume groups based on certain criteria. The following options are relevant for auto-activation:

  • --cache: Scans for LVM metadata on devices and updates the LVM cache.
  • -aay, --all y: Activates all LVM objects (physical volumes, volume groups, and logical volumes) that are found.
  • --listvg: Lists the volume groups found.
  • --checkcomplete: Checks if a volume group is complete (all physical volumes are available).
  • --vgonline: Brings a volume group online if it is complete.
  • --udevoutput: Outputs information in a format suitable for udev rules.
  • --listlvs: Lists the logical volumes found.

EXAMPLES

# pvscan --cache -aay /dev/sdb
  PV /dev/sdb    VG vg            [1.00 GiB]
  PV /dev/sdc    VG vg            [1.00 GiB]
  Total: 2 [2.00 GiB]

  VG vg is complete.
  1 logical volume(s) in volume group "vg" now active

This command scans for physical volumes, assuming they belong to the volume group "vg". If the volume group is complete (i.e., all its physical volumes are present), it will be activated.

# cat /run/lvm/pvs_online/1uKpaTlFOZNLHXj4jIOBi1QpdEHZ5hZY
8:16
vg:vg
dev:/dev/sdb
# cat /run/lvm/pvs_online/5J3tM8aIPe2vbdDBe7bvRqTGj0DaKV2G
8:32
vg:vg
dev:/dev/sdc

The files in /run/lvm/pvs_online/ track online physical volumes. The filename is a hash of the PV UUID.

# ls /run/lvm/vgs_online/vg
/run/lvm/vgs_online/vg

The presence of a file or directory in /run/lvm/vgs_online/ indicates that the volume group is online.

use of -aay:

# pvscan --cache -aay /dev/sdb
  pvscan[12935] PV /dev/sdb online, VG vg incomplete (need 1).
# pvscan --cache -aay /dev/sdc
  pvscan[12936] PV /dev/sdc online, VG vg is complete.
  pvscan[12936] VG vg run autoactivation.
  1 logical volume(s) in volume group "vg" now active

In this example, scanning /dev/sdb shows that the volume group "vg" is incomplete because one physical volume is missing. Scanning /dev/sdc completes the volume group "vg", and it is then auto-activated.

# cat /run/lvm/pvs_online/1uKpaTlFOZNLHXj4jIOBi1QpdEHZ5hZY
8:16
vg:vg
dev:/dev/sdb
$ cat /run/lvm/pvs_online/5J3tM8aIPe2vbdDBe7bvRqTGj0DaKV2G
8:32
vg:vg
dev:/dev/sdc
# ls /run/lvm/vgs_online/vg
/run/lvm/vgs_online/vg

use of --listvg:

# pvscan --cache --listvg /dev/sdb
  VG vg
# pvscan --cache --listvg /dev/sdc
  VG vg

This command simply lists the volume groups associated with the specified physical volumes.

# cat /run/lvm/pvs_online/1uKpaTlFOZNLHXj4jIOBi1QpdEHZ5hZY
8:16
vg:vg
dev:/dev/sdb
$ cat /run/lvm/pvs_online/5J3tM8aIPe2vbdDBe7bvRqTGj0DaKV2G
8:32
vg:vg
dev:/dev/sdc

use of --checkcomplete:

# pvscan --cache --listvg --checkcomplete --vgonline /dev/sdb
  pvscan[12996] PV /dev/sdb online, VG vg incomplete (need 1).
  VG vg incomplete
# pvscan --cache --listvg --checkcomplete --vgonline /dev/sdc
  pvscan[12997] PV /dev/sdc online, VG vg is complete.
  VG vg complete

This command checks if the volume group is complete and brings it online if it is. The first command shows it's incomplete, while the second shows it becomes complete after scanning /dev/sdc.

use of --udevoutput:

# pvscan --cache --listvg --checkcomplete --vgonline --udevoutput /dev/sdb
LVM_VG_NAME_INCOMPLETE='vg'
# pvscan --cache --listvg --checkcomplete --vgonline --udevoutput /dev/sdc
LVM_VG_NAME_COMPLETE='vg'

This command outputs information in a format suitable for udev rules. It indicates whether the volume group is complete or incomplete.

use of --listlvs:

# lvs -o name,devices vg
  LV    Devices
  lvol0 /dev/sdb(0)
  lvol1 /dev/sdc(0)
  lvol2 /dev/sdb(1),/dev/sdc(1)

This command lists the logical volumes and the physical extents they use within the volume group "vg".

# pvscan --cache --listlvs --checkcomplete /dev/sdb
  pvscan[13288] PV /dev/sdb online, VG vg incomplete (need 1).
  VG vg incomplete
  LV vg/lvol0 complete
  LV vg/lvol2 incomplete
# pvscan --cache --listlvs --checkcomplete /dev/sdc
  pvscan[13289] PV /dev/sdc online, VG vg is complete.
  VG vg complete
  LV vg/lvol1 complete
  LV vg/lvol2 complete

This command scans for physical volumes, checks the completeness of the volume group, and lists the status of logical volumes. It shows which logical volumes are complete based on the available physical volumes.
