NOM

lvscan — Lister tous les volumes logiques dans tous les groupes de volumes

SYNTAXE

lvscan
[ arguments_option ]

DESCRIPTION

lvscan scanne tous les VG ou tous les périphériques bloc LVM supportés dans le système pour les LV. La sortie consiste en une ligne pour chaque LV indiquant s'il est actif, s'il s'agit d'un snapshot ou d'une origine, la taille du périphérique et sa politique d'allocation. Utilisez lvs(8) ou lvdisplay(8) pour obtenir des informations plus complètes sur les LV.

UTILISATION

lvscan

[ -a|--all ]
[ --ignorelockingfailure ]
[ --readonly ]
[ --reportformat basic|json|json_std ]
[ OPTIONS_COMMUNES ]

OPTIONS

-a|--all
Afficher des informations sur les LV internes. Ce sont des composants de LV normaux, tels que les miroirs, qui ne sont pas accessibles indépendamment, par exemple non montables.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). La chaîne d'argument utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définir le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande n'essaiera pas d'utiliser device-mapper. Pour les tests et le débogage.
-h|--help
Afficher le texte d'aide.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--journal Chaîne
Enregistrer les informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre log/journal de lvm.conf. commande : enregistrer des informations sur la commande. sortie : enregistrer la sortie par défaut de la commande. debug : enregistrer le débogage complet de la commande.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Afficher le texte d'aide long.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours l'invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactiver le verrouillage. Utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, en fonction de la commande.
-q|--quiet ...
Supprimer les messages de sortie et de journalisation. Remplace --debug et --verbose. Répétez une fois pour également supprimer toutes les invites avec la réponse 'non'.
--readonly
Empêcher la commande d'apporter des modifications, y compris l'activation et les mises à jour des métadonnées. (Voir --permission r pour les LV en lecture seule.)
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec colonnes et lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées mais en renvoyant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil s'appuie sur la lecture des métadonnées qu'il croit avoir changées mais qui n'ont pas changé.
-v|--verbose ...
Définir le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
-y|--yes
Ne pas demander de confirmation de manière interactive mais répondre toujours oui. À utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

Chaîne
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Taille[UNITÉ]
Taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles: b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient un multiple de 1000.)

NAME

lvm.conf - Configuration file for LVM2

DESCRIPTION

The LVM configuration information is stored in the file /etc/lvm/lvm.conf.

This file allows the system administrator to control the behavior of the LVM commands. Many of the settings in this file can also be specified on the command line using options like -d, -v, -t, -f and --test, or by using the lvm.conf section of vgchange(8) or lvchange(8).

A full list of parameters and their descriptions can be found in the lvm.conf(5) man page. However, some of the most commonly used parameters are described below.

SYNTAX

Parameters are specified in the format parameter = value.

Comments start with a hash symbol (#) and continue to the end of the line.

Parameters can be grouped into sections using square brackets ([]).

Example:

devices {
filter = [ "a|/dev/sda.*|", "r|/dev/cdrom|" ]
}

PARAMETERS

devices
This section controls which devices are scanned for LVM Physical Volumes (PVs).
  • filter: This parameter can be used to include or exclude specific devices. The filter is a list of strings, where each string is a regular expression. Devices matching an include pattern (e.g. "a|/dev/sda.*|") are scanned, and devices matching an exclude pattern (e.g. "r|/dev/cdrom|") are ignored. The default filter includes all devices.
  • md_component_filter: Similar to the devices filter, but only applies to devices that are components of a Linux Software RAID (md device).
  • label_scan: (default: 1) If set to 0, LVM will not scan devices for LVM labels. This can speed up boot time but means that new PVs will not be detected automatically.
  • preferred_names: This parameter specifies a list of device name patterns that LVM should try to use when naming devices.
  • cache_dir: Specifies the directory where LVM metadata caches are stored.
  • cache_file_prefix: Specifies the prefix for the metadata cache files.
global
Global LVM settings.
  • locking_type: Specifies the type of locking LVM should use. Common values are 0 (no locking), 1 (filesystem locking), 2 (read-write locking) and 3 (read-only locking). If not set, LVM will try to detect the best locking type.
  • fsync_locking: (default: 1) If set to 0, LVM will not perform an fsync() after writing metadata. This can speed up operations but may lead to data corruption if the system crashes.
  • log_syslog: (default: 1) If set to 1, LVM messages will be sent to the syslog daemon.
  • log_logfiles: (default: 1) If set to 1, LVM messages will be written to log files in /var/log/lvm/.
  • max_backup_copies: (default: 2) Sets the maximum number of metadata backup copies.
  • proc_path: Path to the proc filesystem.
  • sysfs_path: Path to the sysfs filesystem.
  • activation: Controls LVM device activation. Can be 'local' or 'remote'.
allocation
Controls how LVM allocates space.
  • alloc_policy: Specifies the allocation policy. Common values include 'contiguous', 'cling', 'normal', 'any'. 'normal' is the default.
  • partial_allocation: (default: 1) Allows allocation of partial Physical Extents (PEs).
  • space_limit: Defines the maximum amount of space that LVM can allocate.
backup
Settings related to metadata backups.
  • backup_dir: Directory where metadata backups are stored. (Default: /etc/lvm/backup)
  • archive_dir: Directory where metadata archives are stored. (Default: /etc/lvm/archive)
  • retain_min_days: Minimum number of days to retain metadata backups.
  • retain_max_hours: Maximum number of hours to retain metadata backups.
metadata
Settings related to metadata handling.
  • checksum_type: Specifies the metadata checksum type. Common values are 'crc32_1', 'crc32_2', 'crc32_3', 'crc32_4', 'sha256', 'sha384', 'sha512'.
  • use_lvmetad: (default: 1) If set to 1, LVM will use the lvmetad daemon for faster metadata scanning.
each_vg
This section contains parameters that are applied to each Volume Group (VG) individually.
  • vg_processing_volume_list: A list of Physical Volumes (PVs) to process.

EXAMPLES

To filter out all devices except those starting with /dev/sda and /dev/sdb, you could add the following to lvm.conf:

devices {
filter = [ "a|/dev/sda.*|", "a|/dev/sdb.*|" ]
}

To disable LVM metadata logging to syslog:

global {
log_syslog = 0
}
