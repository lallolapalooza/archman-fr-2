NOM

lvmvdo — Support pour le Virtual Data Optimizer dans LVM

DESCRIPTION

VDO est un logiciel qui fournit des fonctionnalités de déduplication, de compression et de provisionnement fin au niveau des blocs pour le stockage primaire.

La déduplication est une technique permettant de réduire la consommation des ressources de stockage en éliminant les copies multiples de blocs dupliqués. La compression prend les blocs uniques individuels et les réduit. Ces blocs réduits sont ensuite regroupés efficacement dans des blocs physiques. Le provisionnement fin gère le mappage des blocs logiques présentés par VDO vers l'emplacement où les données ont été physiquement stockées, et élimine également tous les blocs nuls.

Avec la déduplication, au lieu d'écrire les mêmes données plus d'une fois, VDO détecte et enregistre chaque bloc dupliqué comme une référence au bloc d'origine. VDO maintient un mappage entre les adresses de blocs logiques (LBA) (utilisées par la couche de stockage au-dessus de VDO) et les adresses de blocs physiques (utilisées par la couche de stockage sous VDO). Après la déduplication, plusieurs adresses de blocs logiques peuvent être mappées à la même adresse de bloc physique ; ce sont des blocs partagés et ils sont comptés par référence par le logiciel.

Avec la compression, VDO compresse plusieurs blocs (ou blocs partagés) avec l'algorithme rapide LZ4, et les regroupe lorsque cela est possible afin que plusieurs blocs compressés tiennent dans un bloc de 4 Ko sur le stockage sous-jacent. Le mappage des LBA se fait vers une adresse de bloc physique et un index à l'intérieur de celle-ci pour les données compressées souhaitées. Tous les blocs compressés sont individuellement comptés par référence pour des raisons de correction.

Le partage de blocs et la compression de blocs sont invisibles pour les applications utilisant le stockage, qui lisent et écrivent les blocs comme si VDO n'était pas présent. Lorsqu'un bloc partagé est écrasé, un nouveau bloc physique est alloué pour stocker les nouvelles données du bloc afin de garantir que les autres adresses de blocs logiques mappées au bloc physique partagé ne sont pas modifiées.

Pour utiliser VDO avec lvm(8), vous devez installer les outils en espace utilisateur standard de VDO vdoformat(8) et le module du noyau « dm_vdo » (Pour les noyaux plus anciens <6.9, le module VDO hors arbre « kvdo » est nécessaire).

Le module du noyau implémente la virtualisation du stockage à grain fin, le provisionnement fin, le partage de blocs, la compression et l'identification efficace en mémoire des doublons. Les outils en espace utilisateur incluent vdostats(8) pour extraire les statistiques des volumes VDO.

TERMES VDO

VDODataLV
Le LV de données VDO est un grand LV caché avec le suffixe _vdata. Il est créé dans un VG utilisé par la cible du noyau VDO pour stocker tous les blocs de données et de métadonnées.
VDOPoolLV
Le LV de pool VDO est un pool pour les VDOLV virtuels, dont la taille correspond à celle de VDODataLV utilisé. Un seul VDOLV est actuellement pris en charge.
VDOLV
Le LV VDO est un LV virtuel créé à partir de VDOPoolLV. Il apparaît vide après sa création.

UTILISATION VDO

Les principales méthodes pour utiliser VDO avec lvm2 :

1. Créer un VDOPoolLV et un VDOLV

Créez un VDOPoolLV qui contiendra les données VDO, et un VDOLV de taille virtuelle que l'utilisateur pourra utiliser. Si vous ne spécifiez pas la taille virtuelle, le VDOLV est créé avec la taille maximale qui peut toujours tenir dans le volume de données, même si aucune déduplication ou compression ne peut se produire (c'est-à-dire qu'il peut contenir le contenu incompressible de /dev/urandom). Si vous ne spécifiez pas le nom de VDOPoolLV, il est pris dans la séquence vpool0, vpool1, ...

Remarque : Les performances des opérations TRIM/Discard sont lentes pour les gros volumes de type VDO. Veuillez essayer d'éviter d'envoyer des requêtes de suppression, sauf si nécessaire, car cela pourrait prendre un temps considérable pour terminer l'opération de suppression.

lvcreate --type vdo -n VDOLV -L TailleDonnées -V GrandeTailleVirtuelle VG/VDOPoolLV
lvcreate --vdo -L TailleDonnées VG

Exemple

# lvcreate --type vdo -n vdo0 -L 10G -V 100G vg/vdopool0
# mkfs.ext4 -E nodiscard /dev/vg/vdo0

2. Convertir un LV existant en VDOPoolLV

Convertit un LV déjà créé ou existant en un VDOPoolLV, qui est un volume pouvant contenir des données et des métadonnées. Il vous sera demandé de confirmer une telle conversion car elle DÉTRUIT IRRÉVERSIBLEMENT le contenu de ce volume et le volume est immédiatement formaté par vdoformat(8) comme volume de données de pool VDO. Vous pouvez spécifier la taille virtuelle du VDOLV associé à ce VDOPoolLV. Si vous ne spécifiez pas la taille virtuelle, elle sera définie à la taille maximale qui peut contenir des données 100 % incompressibles.

lvconvert --type vdo-pool -n VDOLV -V TailleVirtuelle VG/VDOPoolLV
lvconvert --vdopool VG/VDOPoolLV

Exemple

# lvconvert --type vdo-pool -n vdo0 -V10G vg/ExistingLV

3. Modifier la compression et la déduplication d'un VDOPoolLV

Désactive ou active la compression et la déduplication pour VDOPoolLV (le volume qui maintient tous les VDOLV qui lui sont associés).

lvchange --compression o|n --deduplication o|n VG/VDOPoolLV

Exemple

# lvchange --compression n  vg/vdopool0
# lvchange --deduplication y vg/vdopool1

4. Modifier les paramètres par défaut utilisés pour créer un VDOPoolLV

VDO vous permet de définir une grande variété d'options. Beaucoup de ces paramètres peuvent être spécifiés dans lvm.conf ou dans les paramètres de profil. Vous pouvez préparer un certain nombre de profils différents dans le répertoire /etc/lvm/profile et simplement spécifier le nom du fichier de profil. Vérifiez la sortie de lvmconfig --type default --withcomments pour une description détaillée de tous les paramètres VDO individuels.

Exemple

# cat <<EOF > /etc/lvm/profile/vdo_create.profile
allocation {
vdo_use_compression=1
vdo_use_deduplication=1
vdo_minimum_io_size=4096
vdo_block_map_cache_size_mb=128
vdo_block_map_period=16380
vdo_use_sparse_index=0
vdo_index_memory_size_mb=256
vdo_slab_size_mb=2048
vdo_ack_threads=1
vdo_bio_threads=1
vdo_bio_rotation=64
vdo_cpu_threads=2
vdo_hash_zone_threads=1
vdo_logical_threads=1
vdo_physical_threads=1
vdo_max_discard=1
}
EOF
# lvcreate --vdo -L10G --metadataprofile vdo_create vg/vdopool0
# lvcreate --vdo -L10G --config 'allocation/vdo_cpu_threads=4' vg/vdopool1

5. Définir ou modifier les paramètres VDO avec l'option --vdosettings

Utilisez la forme 'option=valeur' ou 'option1=valeur option2=valeur', ou répétez --vdosettings pour chaque option définie. Les options sont listées dans la section Exemple ci-dessus. Pour une description complète, voir lvm.conf(5). Les options peuvent omettre les préfixes 'vdo_' et 'vdo_use_' ainsi que tous leurs traits de soulignement. Ainsi, par exemple, vdo_use_deduplication=1 et deduplication=1 sont équivalents. Pour modifier l'option d'un VDOPoolLV existant, utilisez la commande lvchange(8). Cependant, toutes les options ne peuvent pas être modifiées. Seules les options de compression et de déduplication peuvent également être modifiées pour un LV VDO actif. Les options de priorité la plus basse sont spécifiées dans le fichier de configuration, puis avec --vdosettings, et les plus hautes sont les options explicites --compression et --deduplication.

Exemple

# lvcreate --vdo -L10G --vdosettings 'ack_threads=1 hash_zone_threads=2' vg/vdopool0
# lvchange --vdosettings 'bio_threads=2 deduplication=1' vg/vdopool0

6. Vérifier l'utilisation de VDOPoolLV

Pour vérifier rapidement la quantité de données déjà consommée sur un VDOPoolLV, utilisez lvs(8)

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

. Le champ Data% indique la quantité de données occupée dans le contenu des données virtuelles pour le VDOLV et l'espace déjà consommé avec tous les blocs de données et de métadonnées dans le VDOPoolLV. Pour une description détaillée, utilisez la commande vdostats(8).

Note : vdostats(8) ne comprend actuellement que les noms de périphériques /dev/mapper.

Exemple

# lvcreate --type vdo -L10G -V20G -n vdo0 vg/vdopool0
# mkfs.ext4 -E nodiscard /dev/vg/vdo0
# lvs -a vg
  LV               VG Attr       LSize  Pool     Origin Data%
  vdo0             vg vwi-a-v--- 20.00g vdopool0        0.01
  vdopool0         vg dwi-ao---- 10.00g                 30.16
  [vdopool0_vdata] vg Dwi-ao---- 10.00g
# vdostats --all /dev/mapper/vg-vdopool0-vpool
/dev/mapper/vg-vdopool0 :
  version                             : 30
  release version                     : 133524
  data blocks used                    : 79
  ...

7. Extension de la taille du VDOPoolLV

Vous pouvez ajouter de l'espace pour contenir des données et des métadonnées VDO en étendant le VDODataLV à l'aide des commandes lvresize(8) et lvextend(8). L'extension doit ajouter au moins une nouvelle tranche VDO. Vous pouvez configurer la taille de la tranche avec le paramètre allocation/vdo_slab_size_mb.

Vous pouvez également activer l'extension automatique de la taille d'un VDOPoolLV surveillé avec les paramètres activation/vdo_pool_autoextend_percent et activation/vdo_pool_autoextend_threshold.

Note : Vous ne pouvez pas réduire la taille d'un VDOPoolLV.

lvextend -L+TailleAjoutée VG/VDOPoolLV

Exemple

# lvextend -L+50G vg/vdopool0
# lvresize -L300G vg/vdopool1

8. Extension ou réduction de la taille du VDOLV

Vous pouvez étendre ou réduire un LV VDO virtuel comme un LV standard avec les commandes lvresize(8), lvextend(8) et lvreduce(8).

Note : La réduction nécessite le traitement de TRIM pour la zone de disque réduite afin de dés mapper les blocs de données utilisés du VDOPoolLV, ce qui peut prendre beaucoup de temps.

lvextend -L+TailleAjoutée VG/VDOLV
lvreduce -L-TailleRéduite VG/VDOLV

Exemple

# lvextend -L+50G vg/vdo0
# lvreduce -L-50G vg/vdo1
# lvresize -L200G vg/vdo2

9. Activation des composants d'un VDODataLV

Vous pouvez activer un VDODataLV séparément en tant que composant LV à des fins d'examen. L'activation du VDODataLV active le LV de données en mode lecture seule, et le LV de données ne peut pas être modifié. Si le VDODataLV est actif en tant que composant, tout LV supérieur utilisant ce volume NE PEUT PAS être activé. Vous devez d'abord désactiver le VDODataLV pour continuer à utiliser le VDOPoolLV.

Exemple

# lvchange -ay vg/vpool0_vdata
# lvchange -an vg/vpool0_vdata

SUJETS VDO

1. Empilement VDO

Vous pouvez convertir ou empiler un VDOPooLV avec les types de volumes actuellement pris en charge : linéaire, stripe, raid et cache avec cachepool.

1. Utilisation de plusieurs volumes utilisant le même VDOPoolLV

Vous pouvez convertir un LV VDO existant en un volume fin. Après cette conversion, vous pouvez créer un instantané fin ou ajouter d'autres volumes fins avec un pool fin nommé d'après le nom du LV d'origine LV_tpool0. Voir lvmthin(7) pour plus de détails.

Exemple

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvconvert --type thin vg/vdo1
# lvcreate -V20 vg/vdo1_tpool0

2. VDOPoolLV au-dessus de raid

Utilisation d'un LV de type raid pour un VDODataLV.

Exemple

# lvcreate --type raid1 -L 5G -n vdopool vg
# lvconvert --type vdo-pool -V 10G vg/vdopool

3. Mise en cache d'un VDOPoolLV

La mise en cache de VDOPoolLV (accepte également le nom de volume VDODataLV) fournit un mécanisme pour accélérer les lectures et écritures de blocs déjà compressés et dédupliqués, ainsi que les métadonnées VDO.

Exemple

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvcreate --type cache-pool -L 1G -n cachepool vg
# lvconvert --cache --cachepool vg/cachepool vg/vdopool
# lvconvert --uncache vg/vdopool

4. Mise en cache d'un VDOLV

La mise en cache de LV VDO vous permet de 'mettre en cache' un périphérique pour de meilleures performances avant qu'il n'atteigne la couche de traitement du Pool LV VDO.

Exemple

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvcreate --type cache-pool -L 1G -n cachepool vg
# lvconvert --cache --cachepool vg/cachepool vg/vdo1
# lvconvert --uncache vg/vdo1

5. Utilisation de Discard/TRIM avec un VDOLV

Vous pouvez rejeter des données sur un LV VDO et réduire les blocs utilisés sur un VDOPoolLV. Cependant, les performances actuelles des opérations de rejet ne sont pas encore optimales et prennent une quantité considérable de temps et de CPU. Sauf si vous en avez vraiment besoin, vous devriez éviter d'utiliser discard.

Lorsqu'un périphérique bloc va être réécrit, ses blocs seront automatiquement réutilisés pour de nouvelles données. Discard est utile dans les situations où l'utilisateur sait que la portion donnée d'un LV VDO ne sera pas utilisée et que l'espace rejeté peut être utilisé pour la provision de blocs dans d'autres régions du LV VDO. Pour la même raison, vous devriez éviter d'utiliser mkfs avec discard pour un LV VDO fraîchement créé afin d'économiser beaucoup de temps que cette opération prendrait autrement, car le périphérique est déjà censé être vide.

6. Utilisation de la mémoire

La cible VDO nécessite 38 MiB de RAM et plusieurs quantités variables :

  • 1.15 MiB de RAM pour chaque 1 MiB de taille du cache de mappage de blocs configuré. Le cache de mappage de blocs nécessite un minimum de 150 MiB de RAM.
  • 1.6 MiB de RAM pour chaque 1 TiB d'espace logique.
  • 268 MiB de RAM pour chaque 1 TiB de stockage physique géré par le volume.

UDS nécessite un minimum de 250 MiB de RAM, ce qui est également la quantité par défaut utilisée par la déduplication.

La mémoire requise pour l'index UDS dépend du type d'index et de la taille requise de la fenêtre de déduplication et est contrôlée par le paramètre allocation/vdo_use_sparse_index.

Avec l'indexation clairsemée UDS activée, elle repose sur la localité temporelle des données et tente de ne conserver en mémoire que les entrées d'index les plus pertinentes, et peut maintenir une fenêtre de déduplication dix fois plus grande qu'avec un index dense tout en utilisant la même quantité de mémoire.

Bien que l'index clairsemé offre la plus grande couverture, l'index dense fournit plus de conseils de déduplication. Pour la plupart des charges de travail, avec la même quantité de mémoire, la différence dans les taux de déduplication entre les index denses et clairsemés est négligeable.

Un index dense avec 1 GiB de RAM maintient une fenêtre de déduplication de 1 TiB, tandis qu'un index clairsemé avec 1 GiB de RAM maintient une fenêtre de déduplication de 10 TiB. En général, 1 GiB est suffisant pour 4 TiB d'espace physique avec un index dense et 40 TiB avec un index clairsemé.

7. Exigences en matière d'espace de stockage

Vous pouvez configurer un VDOPoolLV pour utiliser jusqu'à 256 TiB de stockage physique. Seule une partie du stockage physique est utilisable pour stocker des données. Cette section fournit les calculs pour déterminer la taille utilisable d'un volume géré par VDO.

La cible VDO nécessite du stockage pour deux types de métadonnées VDO et pour l'index UDS :

  • Le premier type de métadonnées VDO utilise environ 1 MiB pour chaque 4 GiB de stockage physique, plus 1 MiB supplémentaire par tranche.
  • Le second type de métadonnées VDO consomme environ 1.25 MiB pour chaque 1 GiB de stockage logique, arrondi à la tranche supérieure.
  • La quantité de stockage requise pour l'index UDS dépend du type d'index et de la quantité de RAM allouée à l'index. Pour chaque 1 GiB de RAM, un index UDS dense utilise 17 GiB de stockage et un index UDS clairsemé utilisera 170 GiB de stockage.

NOM

lvmvdo — Optimiseur de données virtuel

DESCRIPTION

Les commandes LVM VDO vous permettent d'utiliser des périphériques de stockage VDO (Virtual Data Optimizer) avec LVM. VDO est une technologie qui offre la déduplication et la compression des données pour réduire la quantité de stockage physique nécessaire pour vos données.

TERMES VDO

Voici quelques termes VDO courants :

  • Bloc : L'unité de données de base utilisée par VDO.
  • Déduplication : Le processus de suppression des copies redondantes des blocs de données.
  • Compression : Le processus de réduction de la taille des blocs de données.
  • Niveau de surcharge : Le pourcentage d'espace physique utilisé pour les métadonnées VDO.

UTILISATION VDO

Pour utiliser VDO avec LVM, vous devez d'abord créer un périphérique VDO. Vous pouvez le faire à l'aide de la commande vdo create. Par exemple, pour créer un périphérique VDO nommé myvdo avec une taille de 10 Go sur un périphérique de bloc nommé /dev/sdb, vous utiliseriez la commande suivante :

vdo create --name=myvdo --device=/dev/sdb --size=10G

Une fois le périphérique VDO créé, vous pouvez l'utiliser comme n'importe quel autre périphérique de bloc avec LVM. Par exemple, pour créer un volume logique nommé mylv sur le périphérique VDO myvdo, vous utiliseriez la commande suivante :

lvcreate -L 10G -n mylv myvdo

Vous pouvez ensuite utiliser le volume logique mylv comme n'importe quel autre volume logique LVM.

SUJETS VDO

Voici quelques commandes LVM VDO courantes :

  • lvmvdo create : Crée un nouveau périphérique VDO.
  • lvmvdo remove : Supprime un périphérique VDO existant.
  • lvmvdo status : Affiche le statut d'un ou plusieurs périphériques VDO.
  • lvmvdo list : Liste tous les périphériques VDO disponibles.
