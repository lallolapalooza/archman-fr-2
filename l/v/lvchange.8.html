OPTIONS

-a|--activate y|n|ay
Change l'état actif des LV. Un LV actif peut être utilisé via un périphérique bloc, permettant l'accès aux données du LV. y rend les LV actifs, ou disponibles. n rend les LV inactifs, ou indisponibles. Le périphérique bloc pour le LV est ajouté ou supprimé du système via device-mapper dans le noyau. Un lien symbolique /dev/VGName/LVName pointant vers le nœud de périphérique est également ajouté/supprimé. Tous les logiciels et scripts devraient accéder au périphérique via le lien symbolique et le considérer comme le nom du périphérique. L'emplacement et le nom du nœud de périphérique sous-jacent peuvent dépendre de la distribution, de la configuration (par ex. udev), ou de la version de release. ay spécifie l'auto-activation, qui est utilisée par les commandes d'activation générées par le système. Par défaut, les LV sont auto-activés. Une propriété d'auto-activation peut être définie sur un VG ou un LV pour désactiver l'auto-activation, voir --setautoactivation y|n dans vgchange, lvchange, vgcreate et lvcreate. Affichez la propriété avec vgs ou lvs "-o autoactivation". La liste auto_activation_volume_list de lvm.conf(5) inclut les noms des VG ou LV qui doivent être auto-activés, et tout ce qui n'est pas listé n'est pas auto-activé. Lorsque auto_activation_volume_list est indéfini (par défaut), il n'a aucun effet. Si auto_activation_volume_list est défini et vide, aucun LV n'est auto-activé. Les éléments inclus par auto_activation_volume_list ne seront pas auto-activés si la propriété d'auto-activation a été désactivée. Voir lvm.conf(5) pour plus d'informations sur les options d'activation ey et sy pour les VG partagés.
--activationmode partial|degraded|complete
Détermine si l'activation des LV est autorisée lorsque des PV sont manquants, par ex. en raison d'une défaillance de périphérique. complete n'autorise l'activation que des LV sans PV manquants, et est le mode le plus restrictif. degraded autorise l'activation des LV RAID avec des PV manquants. (Cela n'inclut pas le type "mirror", voir "raid1" à la place.) partial autorise l'activation de tout LV avec des PV manquants, et ne doit être utilisé que pour la récupération ou la réparation. Pour le comportement par défaut, voir lvm.conf(5) activation_mode. Voir lvmraid(7) pour plus d'informations.
--addtag Tag
Ajoute une étiquette à un PV, VG ou LV. Cette option peut être répétée pour ajouter plusieurs étiquettes à la fois. Voir lvm(8) pour des informations sur les étiquettes.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Détermine la politique d'allocation lorsqu'une commande doit allouer des Extensions Physiques (PE) du VG. Chaque VG et LV a une politique d'allocation qui peut être modifiée avec vgchange/lvchange, ou remplacée sur la ligne de commande. normal applique des règles de bon sens, comme ne pas placer de bandes parallèles sur le même PV. inherit applique la politique du VG à un LV. contiguous exige que les nouveaux PE soient placés adjacents aux PE existants. cling place les nouveaux PE sur le même PV que les PE existants dans la même bande du LV. S'il y a suffisamment de PE pour une allocation, mais que normal ne les utilise pas, anywhere les utilisera même si cela réduit les performances, par ex. en plaçant deux bandes sur le même PV. Les arguments PV positionnels optionnels sur la ligne de commande peuvent également être utilisés pour limiter les PV que la commande utilisera pour l'allocation. Voir lvm(8) pour plus d'informations sur l'allocation.
-A|--autobackup y|n
Spécifie si les métadonnées doivent être sauvegardées automatiquement après un changement. L'activation de cette option est fortement conseillée ! Voir vgcfgbackup(8) pour plus d'informations.
--cachemode writethrough|writeback|passthrough
Spécifie quand les écritures sur un LV de cache doivent être considérées comme terminées. writeback considère une écriture comme terminée dès qu'elle est stockée dans le pool de cache. writethrough ne considère une écriture comme terminée que lorsqu'elle a été stockée à la fois dans le pool de cache et sur le LV d'origine. Bien que writethrough puisse être plus lent pour les écritures, il est plus résilient si quelque chose arrive à un périphérique associé au LV de pool de cache. Avec passthrough, toutes les lectures sont servies à partir du LV d'origine (toutes les lectures manquent le cache) et toutes les écritures sont transmises au LV d'origine ; de plus, les succès d'écriture provoquent l'invalidation des blocs de cache. Voir lvmcache(7) pour plus d'informations.
--cachepolicy Chaîne
Spécifie la politique de cache pour un LV de cache. Voir lvmcache(7) pour plus d'informations.
--cachesettings Chaîne
Spécifie les options de noyau ajustables pour les LV dm-cache ou dm-writecache. Utilisez la forme 'option=valeur' ou 'option1=valeur option2=valeur', ou répétez --cachesettings pour chaque option définie. Ces paramètres remplacent les comportements par défaut du noyau qui sont généralement adéquats. Pour supprimer les cachesettings et revenir aux comportements par défaut du noyau, utilisez --cachesettings 'default' pour dm-cache ou une chaîne vide --cachesettings '' pour dm-writecache. Voir lvmcache(7) pour plus d'informations.
--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--compression y|n
Contrôle si la compression est activée ou désactivée pour le volume VDO. Voir lvmvdo(7) pour plus d'informations sur l'utilisation de VDO.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-C|--contiguous y|n
Définit ou réinitialise la politique d'allocation contiguë pour les LV. Par défaut, il n'y a pas d'allocation contiguë basée sur le principe du prochain emplacement libre. Il n'est possible de passer d'une politique d'allocation non contiguë à une politique contiguë que si toutes les extensions physiques allouées dans le LV sont déjà contiguës.
-d|--debug ...
Définit le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le niveau de détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--deduplication y|n
Contrôle si la déduplication est activée ou désactivée pour le volume VDO. Voir lvmvdo(7) pour plus d'informations sur l'utilisation de VDO.
--deltag Tag
Supprime une étiquette d'un PV, VG ou LV. Cette option peut être répétée pour supprimer plusieurs étiquettes à la fois. Voir lvm(8) pour des informations sur les étiquettes.
--detachprofile
Détache un profil de métadonnées d'un VG ou LV. Voir lvm.conf(5) pour plus d'informations sur les profils.
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier des périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres de lvm.conf(5) devices/devicesfile et devices/use_devicesfile.
--discards passdown|nopassdown|ignore
Spécifie comment la couche de pool mince de device-mapper dans le noyau doit gérer les rejets (discards). ignore fait en sorte que le pool mince ignore les rejets. nopassdown fait en sorte que le pool mince traite lui-même les rejets pour permettre la réutilisation des extensions inutiles dans le pool mince. passdown fait en sorte que le pool mince traite les rejets
rds lui-même (comme nopassdown) et transmet les discards au périphérique sous-jacent. Voir lvmthin(7) pour plus d'informations.
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour des tests et le débogage.
--errorwhenfull y|n
Spécifie le comportement du pool mince lorsque l'espace de données est épuisé. Lorsque oui, device-mapper renverra immédiatement une erreur lorsqu'un pool mince est plein et qu'une requête d'E/S nécessite de l'espace. Lorsque non, device-mapper mettra en file d'attente ces requêtes d'E/S pendant une période de temps pour permettre au pool mince d'être étendu. Des erreurs seront renvoyées si aucun espace n'est disponible après le délai d'attente. (Voir aussi le paramètre du module noyau "dm_thin_pool" no_space_timeout.) Voir lvmthin(7) pour plus d'informations.
-f|--force ...
Ignore diverses vérifications, confirmations et protections. À utiliser avec une extrême prudence.
-h|--help
Affiche l'aide.
-K|--ignoreactivationskip
Ignore le drapeau LV « activation skip » lors de l'activation pour permettre l'activation des LVs avec ce drapeau défini.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--ignoremonitoring
N'interagit pas avec dmeventd à moins que --monitor ne soit spécifié. Ne pas utiliser ceci si dmeventd surveille déjà un périphérique.
--integritysettings String
Spécifie les options de noyau ajustables pour dm-integrity. Voir lvmraid(7) pour plus d'informations.
--journal String
Enregistre les informations dans le journal systemd. Ces informations sont supplémentaires aux informations activées par le réglage log/journal de lvm.conf. command: enregistre les informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Affiche l'aide détaillée.
-j|--major Number
Définit le numéro majeur d'un périphérique bloc LV.
--[raid]maxrecoveryrate Size[k|UNIT]
Définit le taux de récupération maximal pour un LV RAID. La valeur du taux est une quantité de données par seconde pour chaque périphérique du tableau. Définir le taux à 0 signifie qu'il sera illimité. Voir lvmraid(7) pour plus d'informations.
--metadataprofile String
Le profil de métadonnées à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--minor Number
Définit le numéro mineur d'un périphérique bloc LV.
--[raid]minrecoveryrate Size[k|UNIT]
Définit le taux de récupération minimum pour un LV RAID. La valeur du taux est une quantité de données par seconde pour chaque périphérique du tableau. Définir le taux à 0 signifie qu'il sera illimité. Voir lvmraid(7) pour plus d'informations.
--monitor y|n
Démarre (oui) ou arrête (non) la surveillance d'un LV avec dmeventd. dmeventd surveille les événements du noyau pour un LV, et effectue une maintenance automatisée pour le LV en réponse à des événements spécifiques. Voir dmeventd(8) pour plus d'informations.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques des PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices lorsque approprié.
--nolocking
Désactive le verrouillage. À utiliser avec prudence, les commandes concurrentes peuvent produire des résultats incorrects.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas la notification d'udev. Il continuera indépendamment de tout traitement udev possible en arrière-plan. Utilisez ceci uniquement si udev n'est pas en cours d'exécution ou s'il a des règles qui ignorent les périphériques créés par LVM.
-P|--partial
Les commandes feront de leur mieux pour activer les LVs avec des extentions PV manquantes. Les extentions manquantes peuvent être remplacées par des segments d'erreur ou de zéro selon le réglage missing_stripe_filler. Les métadonnées ne peuvent pas être modifiées avec cette option.

-M|--persistent y|n

--poll y|n
Lorsque oui, démarre la transformation en arrière-plan d'un LV. Une transformation incomplète, par exemple pvmove ou lvconvert interrompu par un redémarrage ou un crash, peut être redémarrée depuis le dernier point de contrôle avec --poll y. Lorsque non, la transformation en arrière-plan d'un LV n'aura pas lieu, et la transformation ne sera pas terminée. Il peut ne pas être approprié de sonder immédiatement un LV après l'activation, auquel cas --poll n peut être utilisé pour différer le sondage jusqu'à une commande --poll y ultérieure.

--readonly
Empêche la commande d'effectuer des modifications, y compris les mises à jour d'activation et de métadonnées. (Voir --permission r pour les LVs en lecture seule.)
--rebuild PV
Sélectionne un PV à reconstruire dans un LV raid. Plusieurs PV peuvent être reconstruits en répétant cette option. Utilisez cette option à la place de --resync ou --syncaction repair lorsque les PV avec des données corrompues sont connus, et que leurs données doivent être reconstruites plutôt que de reconstruire les données par défaut (rotatives). Voir lvmraid(7) pour plus d'informations.
--refresh
Si le LV est actif, recharge ses métadonnées. Dans un environnement où udev est utilisé pour gérer le contenu /dev, l'utilisation de cette option est fortement recommandée. En effet, refresh régénère également les événements udev pour un LV en fonction des règles udev existantes appliquées pour définir le contenu et les permissions /dev. De plus, cette opération peut être utile si quelque chose s'est mal passé, ou si une forme de partage manuel de LV est utilisée.

Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le réglage report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. Voir lvmreport(7) pour plus d'informations.
--resync
Démarre la synchronisation des miroirs. La synchronisation se produit généralement automatiquement, mais cette option la force à s'exécuter. Voir également --rebuild pour synchroniser un PV spécifique. Pendant la synchronisation, les données sont lues à partir du périphérique miroir primaire et copiées vers les autres. Cela peut prendre un temps considérable, pendant lequel le LV n'a pas de copie redondante complète des données. Voir lvmraid(7) pour plus d'informations.

NAME

lvchange — Change characteristics of a logical volume

SYNOPSIS

lvchange [OPTIONS] LV

lvchange [OPTIONS] LV Pattern

DESCRIPTION

Modify allocated Logical Volumes and control their attributes and availability.

USAGE

This command can accept a linear, striped, snapshot, or mirror logical volume name. For details, see lvm(8).

When changing attributes of a mirror, the change is applied to the mirror device itself, not the individual mirrors (legs). See lvmraid(7) for details on how to change attributes of individual mirror legs.

OPTIONS

-a|--available y|n
Controls the availability of the logical volume. If set to y (yes), the LV is made available (activated). If set to n (no), the LV is made unavailable (deactivated). For a mirror, this activates or deactivates all legs. For a snapshot, it activates or deactivates the snapshot. For a linear or striped LV, it activates or deactivates the LV. Deactivating an LV may fail if it is in use (e.g. mounted).
-k|--keepactive y|n
Controls whether an LV (e.g. a snapshot) should remain active if its associated mirror is deactivated. This is only relevant for mirrors where a leg is a snapshot. Default is n (no).
-m|--monitor y|n
Controls monitoring of the logical volume. If set to y (yes), monitoring is enabled for the LV. If set to n (no), monitoring is disabled. This option is only relevant for mirrors and snapshots. See lvm.conf(5) for more details.
-p|--permission r|w
Controls the permission of the logical volume. If set to r (read-only), the LV is made read-only. If set to w (read-write), the LV is made read-write. Note that changes may not be immediately visible to all systems if LVM is used on a cluster.
-q|--poll n
Set the polling interval for asynchronous devices (e.g. RAID, snapshot). A value of 0 disables polling. The default value is 60 seconds. This option can be used for individual LVs. If the LV is part of a mirror or raid array, this option will attempt to disable polling for individual LVs but this may not always be possible.
-Q|--poll_queue n
Set the polling queue size for asynchronous devices. A value of 0 disables polling queue. The default value is 1000. This option can be used for individual LVs.
-P|--partial
A mirror with one missing leg can be activated with this option. It is not possible to activate a mirror with more than one missing leg. See lvmraid(7) for more details.
--[raid]syncaction check|repair
Initiate different types of RAID synchronization. This causes the RAID LV to read all data and parity blocks in the array and check for discrepancies (mismatches between mirrors or incorrect parity values). check will count but not correct discrepancies. repair will correct discrepancies. Mind that these synchronization actions are transient and have to be restarted after a system failure/reboot or a configuration change to the RaidLV. See lvs(8) for reporting discrepancies found or repaired.
--sysinit
Indicates that vgchange/lvchange is being invoked from early system initialisation scripts (e.g. rc.sysinit or an initrd), before writable filesystems are available. As such, some functionality needs to be disabled and this option acts as a shortcut which selects an appropriate set of options. Currently, this is equivalent to using --ignorelockingfailure, --ignoremonitoring, --poll n, and setting env var LVM_SUPPRESS_LOCKING_FAILURE_MESSAGES. vgchange/lvchange skip autoactivation, and defer to pvscan autoactivation.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
--vdosettings String
Specifies tunable VDO options for VDO LVs. Use the form 'option=value' or 'option1=value option2=value', or repeat --vdosettings for each option being set. These settings override the default VDO behaviors. To remove vdosettings and revert to the default VDO behaviors, use --vdosettings 'default'. See lvmvdo(7) for more information.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--[raid]writebehind Number
The maximum number of outstanding writes that are allowed to devices in a RAID1 LV that is marked write-mostly. Once this value is exceeded, writes become synchronous (i.e. all writes to the constituent devices must complete before the array signals the write has completed). Setting the value to zero clears the preference and allows the system to choose the value arbitrarily.
--[raid]writemostly PV[:t|n|y]
Mark a device in a RAID1 LV as write-mostly. All reads to these drives will be avoided unless absolutely necessary. This keeps the number of I/Os to the drive to a minimum. The default behavior is to set the write-mostly attribute for the specified PV. It is also possible to remove the write-mostly flag by adding the suffix :n at the end of the PV name, or to toggle the value with the suffix :t. Repeat this option to change the attribute on multiple PVs.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)
-Z|--zero y|n
Set zeroing mode for thin pool. Note: already provisioned blocks from pool in non-zero mode are not cleared in unwritten parts when setting --zero y.

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
Tag
Tag name. See lvm(8) for information about tag names and using tags in place of a VG, LV or PV.
Select
Select indicates that a required positional parameter can be omitted if the --select option is used. No arg appears in this position.
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
