NOM

lvmdump — crée des vidages d'informations lvm2 à des fins de diagnostic

SYNTAXE

lvmdump
[-a] [-c] [-d répertoire] [-h] [-l] [-m] [-p] [-s] [-u]

DESCRIPTION

lvmdump est un outil pour vidanger diverses informations concernant LVM2. Par défaut, il crée une archive tar suitable pour être soumise avec un rapport de problème.

Le contenu de l'archive tar est le suivant :

•
dmsetup info
•
tableau des processus en cours d'exécution
•
entrées récentes de /var/log/messages (contenant les messages système)
•
configuration complète de lvm et cache (contenu de /etc/lvm)
•
liste des nœuds de périphériques présents sous /dev
•
liste des fichiers présents dans /sys/block
•
liste des fichiers présents dans /sys/devices/virtual/block
•
si activé avec -m, un vidage des métadonnées sera également inclus
•
si activé avec -a, la sortie de débogage de vgscan, pvscan et la liste de tous les groupes de volumes, volumes physiques et volumes logiques disponibles seront inclus
•
si activé avec -l, l'état de lvmetad s'il est en cours d'exécution
•
si activé avec -p, l'état de lvmpolld s'il est en cours d'exécution
•
si activé avec -s, informations système et contexte
•
si activé avec -u, informations udev et contexte

OPTIONS

-a
Collecte avancée.
ATTENTION : si lvm est déjà bloqué, ce script peut également se bloquer si -a est utilisé.
-d répertoire
Vidanger dans un répertoire au lieu d'une archive tar. Par défaut, lvmdump produira une seule archive tar compressée contenant toutes les informations. En utilisant cette option, il peut être instruit de produire uniquement l'arborescence de vidage brute, ancrée dans répertoire.
-h
Afficher le message d'aide
-l
Inclure le vidage du démon lvmetad(8) s'il est en cours d'exécution. Le vidage contient les informations mises en cache stockées actuellement dans lvmetad : métadonnées VG, métadonnées PV et divers mappages entre ces métadonnées pour un accès rapide.
-m
Collecter les métadonnées LVM à partir des PV. Cette option génère un vidage 1:1 de la zone de métadonnées de tous les PV visibles par le système, ce qui peut considérablement augmenter la taille du vidage. Cependant, le vidage des métadonnées peut représenter une ressource de diagnostic précieuse.
-p
Inclure le vidage du démon lvmpolld(8) s'il est en cours d'exécution. Le vidage contient toutes les opérations en cours actuellement surveillées par le démon et l'historique partiel de tous les résultats d'opérations de sondage déjà terminées et non collectés, y compris la raison.
-s
Collecter les informations système et le contexte. Actuellement, cela englobe les informations collectées en appelant la commande lsblk et diverses informations et contextes systemd : état général des unités systemd présentes dans le système, statut plus détaillé des unités contrôlant les fonctionnalités LVM et le contenu du journal systemd pour le démarrage en cours.
-u
Collecter les informations udev et le contexte : fichier /etc/udev/udev.conf, version du démon udev (sortie de la commande 'udevadm info --version'), règles udev actuellement utilisées dans le système (contenu des répertoires /lib/udev/rules.d et /etc/udev/rules.d), liste des fichiers dans le répertoire /lib/udev et vidage du contenu actuel de la base de données udev (sortie de la commande 'udevadm info --export-db').

VARIABLES D'ENVIRONNEMENT

LVM_BINARY
Le binaire LVM2 à utiliser. Par défaut : "lvm". Vous pourriez parfois avoir besoin de le définir à "/usr/bin/lvm.static", par exemple.
DMSETUP_BINARY
Le binaire dmsetup à utiliser. Par défaut : "dmsetup".
