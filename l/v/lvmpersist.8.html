NOM

lvmpersist - gérer les réservations persistantes sur un groupe de périphériques de blocage

DESCRIPTION

Les réservations persistantes (RP) fournissent un mécanisme pour contrôler l'accès aux périphériques de stockage partagés, typiquement pour protéger les périphériques contre les modifications par des hôtes qui ne devraient pas écrire sur ces périphériques partagés. Ceci est généralement une préoccupation dans les environnements SAN ou clusterisés, où plusieurs hôtes ont accès aux mêmes périphériques de stockage.

Si un groupe de volumes LVM (VG) contient des périphériques compatibles RP, alors les commandes LVM peuvent être utilisées pour gérer la RP au niveau du VG, appliquant la RP à chaque Volume Physique (PV) du VG. (Tous les PV du VG doivent supporter la RP.)

lvmpersist est un utilitaire de bas niveau utilisé pour effectuer des opérations RP sur des périphériques de blocage individuels. LVM fournit également une interface de gestion RP de plus haut niveau via une interface de commande LVM standard :
vgchange --setpersist, vgchange --persist

lvmpersist est un script qui n'implémente pas les options ou les capacités courantes de la ligne de commande LVM. Le script utilise les commandes sg_persist, mpathpersist et nvme pour effectuer les opérations RP sur les périphériques de blocage. Les commandes LVM de plus haut niveau (par exemple, vgchange) exécutent le script lvmpersist.

Types de périphériques

Les périphériques SCSI ou similaires à SCSI (par exemple, iSCSI, SAS, Fibre Channel), dm-multipath et NVME sont supportés. Les RP ont été introduites avec la norme SCSI Primary Commands Version 3 (SPC-3).

Lorsque des périphériques multipath sont utilisés, multipath.conf doit être configuré avec "reservation_key file". (Exécutez mpathconf --option reservation_key:file, et redémarrez multipathd.)

Types de réservation persistante

LVM utilise le type RP "Write Exclusive" (WE) pour les périphériques dans un VG local, et "Write Exclusive - all registrants" (WEAR) pour les périphériques dans un VG partagé. Une exception concerne les périphériques dm-multipath, pour lesquels WEAR est utilisé dans les VG locaux et partagés (ceci est nécessaire pour que tous les chemins restent utilisables.)

La commande lvmpersist a deux options pour spécifier le type de RP :

--access ex|sh

Définit l'accès à "ex" (exclusif) si les périphériques ne doivent être accédés que par un seul hôte (c'est-à-dire si les périphériques font partie d'un VG local). Définit l'accès à "sh" (partagé) si les périphériques sont destinés à être accédés simultanément par plusieurs hôtes (c'est-à-dire si les périphériques font partie d'un VG partagé). lvmpersist choisira le type RP approprié pour chaque périphérique (généralement WE pour "ex", et WEAR pour "sh".)
--prtype PRTYPE
Lorsqu'une valeur PRTYPE est spécifiée, lvmpersist n'utilisera que ce type pour tous les périphériques.

Types RP et les abréviations utilisées dans les interfaces/messages :

WE Write Exclusive
EA Exclusive Access
WERO Write Exclusive - registrants only
EARO Exclusive Access - registrants only
WEAR Write Exclusive - all registrants
EAAR Exclusive Access - all registrants

(Les types WERO et EARO ne sont pas encore supportés.)

Clés de réservation persistante

Les clés RP peuvent avoir jusqu'à 8 octets de long, et sont représentées par jusqu'à 16 caractères hexadécimaux avec un préfixe "0x". Les zéros initiaux ne sont pas autorisés, par exemple, utilisez 0x1234abcd, pas 0x000000001234abcd. Une valeur décimale de clé (sans préfixe 0x) est acceptée en entrée, mais apparaîtra en hexadécimal en sortie.

Chaque hôte utilisant des périphériques partagés doit utiliser une clé RP unique.

Les clés RP doivent être configurées sur chaque hôte dans /etc/lvm/lvmlocal.conf (voir Paramètres Locaux ci-dessous.)

UTILISATION

L'ensemble de commandes et d'options de base pour gérer la RP :

Utilitaire RP au niveau du périphérique :
lvmpersist start|stop|remove|clear|read [OPTIONS] DEST

Configuration RP du VG :
vgchange --setpersist y|n VG

Opérations RP du VG :
vgchange --persist start|stop|remove|clear|read|check VG

Commandes lvmpersist

lvmpersist start --ourkey KEY DEST

"start" enregistre la clé locale et réserve les périphériques. Si une clé différente du même hôte est toujours enregistrée, elle sera remplacée par la clé spécifiée. Lorsque --access ou --prtype ne sont pas spécifiés, l'accès "ex" est utilisé.

lvmpersist stop --ourkey KEY DEST

"stop" désenregistre la clé locale, ce qui supprime également une réservation locale.

lvmpersist remove --ourkey KEY --removekey REMKEY DEST

"remove" supprime la clé d'un autre hôte enregistré. L'hôte avec la clé supprimée perd la capacité d'écrire sur les périphériques. (Cette commande s'applique aux VG partagés, où plusieurs hôtes sont démarrés en même temps.)

lvmpersist start --ourkey KEY --removekey REMKEY DEST

"start" avec removekey enregistre la clé locale et prend la réservation d'un autre hôte (en utilisant preempt-abort). L'autre hôte perd la capacité d'écrire sur les périphériques. (Cette commande s'applique aux VG locaux, pour lesquels un seul hôte peut être démarré à la fois.)

lvmpersist clear --ourkey KEY DEST

"clear" supprime toutes les clés et réservations des périphériques.

lvmpersist devtest|read|read-keys|read-reservation DEST

Ces commandes sont utilisées pour tester si les périphériques supportent la RP, et pour afficher les clés et réservations RP actuelles.

lvmpersist check-key --key KEY DEST

Vérifie si une clé spécifiée est enregistrée.

OPTIONS :

--ourkey KEY

La clé RP locale, par exemple 0x123abc
--removekey REMKEY

La clé d'un autre hôte.
--key KEY

Toute clé à vérifier.
--access ex|sh

Utilise un type RP pour l'accès exclusif ou partagé aux périphériques.
--prtype PRTYPE

Utilise le type de réservation spécifié (alternative à --access).
--ptpl

Active la persistance à travers la perte de puissance pendant le démarrage (enregistrement).

DEST :

--device CHEMIN ...

Un ou plusieurs périphériques sur lesquels opérer.
--vg NOMVG

Un VG sur lequel opérer (tous les PV du VG.)
--vg NOMVG --device CHEMIN ...

Un ou plusieurs périphériques sur lesquels opérer, et un nom de VG à utiliser comme identifiant pour l'ensemble des périphériques.

lvmpersist nécessite soit les noms de périphériques spécifiques, chacun spécifié comme --device /dev/nom, soit le nom d'un VG, spécifié avec --vg NOMVG. Lorsqu'un VG est spécifié, sans périphériques de blocage individuels, lvmpersist exécute les commandes RP sur chaque PV du VG. Lorsque des périphériques sont spécifiés, et qu'un VG est également fourni avec --vg, alors le nom du VG est simplement utilisé dans les messages de log pour identifier l'ensemble des périphériques dans son ensemble. Lorsque lvmpersist est exécuté par des commandes LVM de plus haut niveau, chaque périphérique est spécifié avec --device, et le nom du VG est spécifié avec --vg.

Commandes métadonnées VG

vgchange --setpersist est utilisé pour configurer l'automatisation et l'application de la RP par rapport à l'utilisation plus large du VG

. La configuration est stockée dans les métadonnées du VG.

vgchange --setpersist y|n VG

Active ou désactive l'automatisation par défaut et l'application des PR pour le VG, en définissant ou en effaçant les deux paramètres PR « autostart » et « require » (et potentiellement d'autres paramètres futurs).

vgchange --setpersist autostart|noautostart|require|norequire VG

Définit ou efface individuellement les paramètres autostart et require.

Lorsque « autostart » est défini, les commandes d'auto-activation et d'auto-lockstart (vgchange -aay, vgchange --lockstart --lockopt auto) démarreront d'abord les PR sur le VG. Si le démarrage des PR échoue, ces commandes s'arrêtent et ne tentent pas l'activation ou le lockstart.

Lorsque « require » est défini, les commandes lvm qui écrivent ou activent un VG nécessitent que les PR soient démarrés avant de tenter d'écrire ou d'activer.

vgs -o persist VG

Affiche les paramètres.

Commandes VG PR

vgchange --persist est utilisé pour effectuer des opérations PR sur les périphériques du VG.

vgchange --persist start VG

Démarre les PR sur les périphériques VG. Enregistre la clé locale et acquiert une réservation.

vgchange --persist stop VG

Arrête les PR sur les périphériques VG. Désenregistre la clé locale, ce qui libère une réservation si elle est détenue par la clé.

vgchange --persist remove --removekey remkey VG

Supprime la clé PR d'un autre hôte des périphériques d'un VG partagé, désactivant immédiatement la capacité de l'autre hôte à écrire sur les périphériques. (Cette commande s'applique aux VGs partagés, pour lesquels plusieurs hôtes sont démarrés simultanément.)

vgchange --persist start --removekey remkey VG

Démarre les PR sur les périphériques VG, tout en supprimant simultanément la clé et la réservation d'un autre hôte des périphériques VG, désactivant la capacité de l'autre hôte à écrire sur les périphériques. (Cette commande s'applique aux VGs locaux, pour lesquels un seul hôte peut être démarré à la fois.)

vgchange --persist check VG

Vérifie si les PR sont démarrés (la clé locale et la réservation existent sur tous les périphériques.) La commande se termine avec succès si les PR sont démarrés sur tous les périphériques du VG.

vgchange --persist read VG

Affiche les enregistrements PR et les réservations sur chacun des périphériques du VG.

vgchange --persist clear VG

Efface toutes les clés PR et réservations sur les périphériques du VG.

vgchange --persist autostart VG

Démarre les PR sur les périphériques VG si autostart est défini. Ceci est destiné à être utilisé par l'automatisation du système, comme l'auto-activation et l'auto-lockstart.

Démarrage supplémentaire des PR

L'option --persist start peut être ajoutée à d'autres commandes afin que ces commandes tentent d'abord de démarrer les PR (indépendamment du paramètre autostart).

vgchange -ay --persist start
vgchange -aay --persist start
vgchange --lockstart --persist start
vgchange --setpersist y|require|autostart --persist start
vgimport --persist start
vgchange --systemid <local_id> --persist start

Utilisation des VGs locaux

Lors de l'utilisation d'un VG local, un seul hôte est démarré à la fois, et une réservation WE (Write Exclusive) est généralement détenue sur les périphériques.

L'utilisation des PR avec les VGs locaux protège les périphériques VG contre l'écriture erronée par un autre hôte ayant accès aux mêmes périphériques. Elle complète l'utilisation de l'ID système du VG pour contrôler le propriétaire prévu d'un VG, mais ajoute une protection renforcée au niveau du périphérique, au cas où un autre hôte n'utiliserait pas la fonctionnalité d'ID système LVM.

Si un hôte souhaite prendre le contrôle de force d'un VG local actuellement utilisé par un autre hôte, il peut utiliser vgchange --persist start --removekey remkey VG, où « remkey » est la clé PR de l'hôte actuellement démarré.

Utilisation des VGs partagés

Lors de l'utilisation d'un VG partagé, tous les hôtes utilisant le VG sont démarrés, et une réservation WEAR (Write Exclusive - all registrants) est détenue sur les périphériques.

Les PR doivent être démarrés avant le verrouillage (vgchange --persist start suivi de vgchange --lockstart, ou un vgchange --persist start --lockstart combiné.)

Si un hôte souhaite empêcher de manière forcée un autre hôte d'écrire sur les périphériques du VG partagé, il peut utiliser vgchange --persist remove --removekey remkey où « remkey » est la clé PR de l'autre hôte.

Paramètres locaux

Chaque hôte utilisant les PR doit avoir une clé PR unique parmi tous les hôtes utilisant le même VG. Il existe deux approches pour définir une valeur de clé, qui sont définies dans /etc/lvm/lvmlocal.conf :

local/pr_key

La valeur définie dans pr_key sera utilisée directement. Il s'agit d'une chaîne hexadécimale jusqu'à 16 caractères de long. pr_key ne sera pas utilisé pour les VGs partagés sanlock.

local/host_id

Pour un VG partagé sanlock, ou si aucun pr_key n'est défini, une clé sera créée en utilisant le host_id. Il s'agit d'un entier décimal compris entre 1 et 2000.

Pour un VG local, ou un VG partagé dlm, une clé utilisant host_id a la forme :

0x100000000000XXXX où XXXX sont les chiffres hexadécimaux de la valeur host_id.

Pour un VG partagé sanlock, la clé est basée sur host_id et un numéro de génération (tiré du bail sanlock), et a la forme :

0x100000YYYYYYXXXX où XXXX sont les chiffres hexadécimaux de la valeur host_id, et YYYYYY sont les chiffres hexadécimaux du numéro de génération.

Le numéro de génération sanlock augmente de valeur chaque fois que l'hôte démarre le VG, de sorte qu'un hôte utilisera une nouvelle clé à chaque démarrage. Dans certains cas, les PR peuvent être démarrés avec une clé incluant le numéro de génération incorrect, auquel cas la commande lockstart mettra à jour la clé avec la valeur correcte (le numéro de génération est officiellement déterminé lors du lockstart.)

vgcreate

Les fonctionnalités PR peuvent être activées lors de la création d'un nouveau VG :

vgcreate --setpersist y VG PVs

Pour les VGs locaux, --persist start peut être inclus pour également démarrer les PR sur le nouveau VG.

La création de nouveaux VGs partagés avec --setpersist fonctionne différemment. Les PR sont toujours démarrés pour un nouveau VG partagé, même sans --persist start. D'abord, un PR exclusif (généralement en mode WE) est acquis pour les périphériques du nouveau VG. Les périphériques sont ensuite initialisés, et les métadonnées du nouveau VG sont écrites. Le PR exclusif est ensuite supprimé, et un PR partagé (généralement en mode WEAR) est acquis pour le partage normal du VG. Enfin, l'espace de verrouillage du VG est démarré.

vgextend

Pour les VGs locaux, vgextend démarre les PR sur les nouveaux périphériques avant de les ajouter au VG (le paramètre require ou autostart doit être activé.) Pour les VGs partagés, l'utilisateur doit utiliser lvmpersist pour démarrer les PR sur les nouveaux périphériques, depuis tous les hôtes, avant d'exécuter vgextend. vgextend vérifie que la réservation et les clés sur les nouveaux périphériques correspondent aux périphériques existants.

vgremove

La commande vgremove arrête les PR sur les périphériques du VG uniquement si les paramètres « require » ou « « autostart » ont été définis à l'aide de vgchange --setpersist. Si les PR ont été démarrés indépendamment de tout paramètre setpersist, alors vgremove n'arrêtera pas automatiquement les PR sur les périphériques.

vgexport/vgimport

vgexport --persist stop arrête les PR après l'exportation du VG, et vgimport --persist start démarre les PR avant l'importation du VG. L'écriture des métadonnées du VG pour l'exportation se produit avant l'arrêt des PR, et l'écriture des métadonnées du VG pour l'importation se produit après le démarrage des PR.

vgchange --systemid

Les PR peuvent être démarrés en même temps que la prise de possession de l'ID système d'un VG, ou les PR peuvent être arrêtés en même temps que l'abandon de la possession de l'ID système d'un VG (voir lvmsystemid(7) pour plus d'informations.)

vgchange --systemid local_system_id --persist start VG

Cette commande est utilisée pour prendre possession d'un VG appartenant à un tiers. Les PR sont démarrés, et si cela réussit, l'ID système du VG sera défini sur l'ID système local. (Note : l'ID système étranger du VG doit être inclus dans extra_system_ids locaux pour accéder à un VG étranger.) Pour supprimer de manière forcée (préemption-abandon) les PR détenus par un autre hôte sur le VG, --removekey remkey peut être inclus, où remkey est la clé PR du détenteur actuel des PR.

vgchange --systemid foreign_system_id --persist stop VG

Cette commande est utilisée pour abandonner la possession d'un VG appartenant localement. L'ID système du VG est mis à jour vers la nouvelle valeur, puis les PR sont arrêtés.

Persistance après perte de tension

Pour activer l'utilisation de la « persistance après perte de tension », où l'état des PR est conservé sur un périphérique s'il est cyclé électriquement, activez le paramètre ptpl :

vgchange --setpersist ptpl VG

Le paramètre PTPL est appliqué lors de l'enregistrement de la clé (partie du démarrage des PR), il prendra donc effet pour chaque hôte lors du prochain démarrage. Il est appliqué à tous les PV du VG, donc chaque périphérique doit supporter le PTPL. Le paramètre PTPL n'est pas activé par « --setpersist y ».

L'une ou l'autre des commandes suivantes effacera le paramètre PTPL :

vgchange --setpersist noptpl VG
vgchange --setpersist n VG
