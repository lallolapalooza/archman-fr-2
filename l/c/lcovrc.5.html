NOM

lcovrc - fichier de configuration lcov

DESCRIPTION

Le fichier lcovrc contient des informations de configuration pour l'outil de couverture de code lcov (voir lcov(1)).

Le fichier de configuration global du système se trouve à l'emplacement $LCOV_HOME/etc/lcovrc. Il s'agit généralement de /etc/lcovrc ou de /usr/local/etc/lcovrc, mais peut se trouver n'importe où où vous avez installé le paquet l。. Pour modifier les paramètres d'un utilisateur individuel, placez une copie personnalisée de ce fichier à l'emplacement ~/.lcovrc. Lorsque disponibles, les options en ligne de commande remplacent les paramètres du fichier de configuration.

Les commandes genhtml, lcov, et geninfo prennent également en charge l'option --config-file, qui peut être utilisée pour spécifier un ou plusieurs fichiers qui doivent être utilisés à la place des fichiers rc par défaut du système ou de l'utilisateur. Plusieurs fichiers d'options peuvent être utiles si vous avez des options communes spécifiques à un projet et à une équipe et que vous souhaitez assurer la cohérence entre plusieurs utilisateurs. Si plusieurs options --config-file sont appliquées dans l'ordre où elles apparaissent. Notez que le nom de l'option "--config-file" doit être spécifié en entier et ne peut pas être abrégé. Une erreur se produira si l'option n'est pas reconnue.

Les lignes d'un fichier de configuration peuvent être :

*
des lignes vides ou des lignes ne contenant que des caractères d'espacement. Ces lignes sont ignorées.
*
des lignes de commentaires qui commencent par un signe dièse ('#'). Celles-ci sont traitées comme des lignes vides et seront ignorées.
*
des instructions de la forme 'clé = valeur'.
*
Les valeurs peuvent être prises à partir de variables d'environnement via la syntaxe

'clé = ...$ENV{NOM_VAR_ENV}...'.

La sous-chaîne '$ENV{NOM_VAR_ENV}' est remplacée par la valeur de la variable d'environnement.

Une ou plusieurs variables d'environnement peuvent être utilisées pour définir la valeur RC.

Une liste des instructions valides et leur description se trouve dans la section 'OPTIONS' ci-dessous.
NOTEZ qu'il n'y a pas de vérification des erreurs pour les clés dans le fichier d'options : les fautes d'orthographe sont simplement vues comme des valeurs qui ne sont utilisées par aucun outil particulier. Si vous n'êtes pas sûr que votre fichier d'options soit lu ou que ses valeurs soient appliquées, vous pouvez utiliser l'option --verbose --verbose pour activer l'affichage des substitutions de valeurs d'options. (L'option apparaît deux fois pour permettre un niveau de verbosité plus élevé.)

Les options de type 'liste' et 'scalaire' (non liste) sont prises en charge dans le fichier lcovrc.

Pour les options scalaires (non liste) :

*
si elles sont spécifiées en ligne de commande et dans le fichier lcovrc, la valeur spécifiée en ligne de commande l'emporte. La valeur du fichier RC est ignorée.
*
Les options scalaires incluent : 'criteria_script = ...' , 'genhtml_annotate_script = ...' , 'version_script = ...' , etc.

Pour les options de liste :

*
l'entrée du fichier RC peut être utilisée plusieurs fois ; chaque utilisation ajoute à la liste.
Par exemple, l'entrée ci-dessous entraînera deux motifs 'omit' qui seront tous deux vérifiés :
# notez les marqueurs de début/fin explicites dans le regexp
omit_lines = ^\s+//\s*MY_EXCLUDE_MARKER\s*$
# Notez que le regexp ci-dessous correspond n'importe où sur la ligne
omit_lines = NR_CM_DBG_PRINT
*
Si des entrées sont spécifiées en ligne de commande, les entrées du fichier RC sont ignorées : la ligne de commande l'emporte. Si des entrées sont spécifiées dans plusieurs fichiers RC (c'est-à-dire si plusieurs arguments --config-file sont fournis), alors les fichiers RC sont appliqués dans l'ordre d'apparition, et les entrées de liste sont ajoutées dans l'ordre. Pour la plupart des options de type liste, l'ordre n'a pas d'importance.
*
les options de liste incluent :
filter = ...
exclude = ...
ignore = ...
substitute = ...
omit_lines = ...
erase_functions = ...
genhtml_annotate_script = ...
etc. Pour un ensemble complet d'options de liste, voir la documentation de chaque option de configuration, ci-dessous.

Ces directives peuvent être utilisées pour modifier le comportement par défaut des outils de la suite lcov.

genhtml_branch_lines = 0|1

Lorsque activé (1), les branches seront affichées comme des lignes supplémentaires.

genhtml_color_run = 0|1

Si activé (1), utilise des couleurs pour indiquer les sections exécutées.

genhtml_dark_mode = 0|1

Si activé (1), utilise une palette de couleurs pour le mode sombre.

genhtml_demangle_cpp = 0|1

Si activé (1), les noms des fonctions C++ seront dé-manglés (simplifiés).

genhtml_diag_width = number

Définit la largeur des diagnostics.

genhtml_display_larges = 0|1

Si activé (1), les grandes fonctions seront affichées.

genhtml_display_zeros = 0|1

Si activé (1), les lignes non exécutées seront affichées.

genhtml_escape_html = 0|1

Si activé (1), les caractères HTML seront échappés.

genhtml_frame_lines = 0|1

Si activé (1), les lignes seront affichées dans des cadres.

genhtml_function_group = 0|1

Si activé (1), les fonctions similaires seront regroupées.

genhtml_html_extension = html

Définit l'extension des fichiers HTML générés.

genhtml_html_gzip = 0|1

Si activé (1), tous les fichiers HTML générés seront compressés avec gzip.

genhtml_html_prolog = filename

Inclut un fichier HTML au début de la sortie.

genhtml_html_epilog = filename

Inclut un fichier HTML à la fin de la sortie.

genhtml_hierarchical = 0|1

Affiche les données de couverture dans une structure de répertoires hiérarchique (plutôt que plate/3 niveaux).

genhtml_keep_descriptions = 0|1

Ne pas supprimer les descriptions de tests inutilisées si différent de zéro.

genhtml_legend = 0|1

Inclure la légende des couleurs dans la sortie HTML si différent de zéro.

genhtml_no_prefix = 0|1

Ne pas supprimer le préfixe des noms de répertoires si différent de zéro.

genhtml_no_source = 0|1

Ne pas créer de vue du code source si différent de zéro.

genhtml_num_spaces = number

Spécifie la taille des tabulations.

genhtml_precision = number

Spécifie la précision des taux de couverture.

genhtml_sort = 0|1

Inclure les pages d'aperçu triées.

genhtml_source_lines = 0|1

Si activé (1), affiche le nombre de lignes de source.

genhtml_title = text

Définit le titre des fichiers HTML générés.

genhtml_desc_html = 0|1

Permet le balisage HTML dans le texte de description des cas de test si différent de zéro.

genhtml_missed = 0|1

Affiche le nombre de lignes manquées au lieu du nombre de lignes exécutées.

merge_function_aliases = 0|1

Regroupe les alias de fonctions dans le rapport - voir la section --merge de man(1) genhtml.

suppress_function_aliases = 0|1

Si activé, supprime la liste des alias dans le tableau des détails des fonctions.

derive_function_end_line = 0|1

Si activé, dérive la ligne de fin de fonction à partir des données de couverture de ligne - par défaut ACTIVÉ.

derive_end_line_all_files = 0|1

Si activé, dérive les lignes de fin de fonction pour tous les types de fichiers. Par défaut, nous dérivons les lignes de fin pour les fichiers C/C++ uniquement.

trivial_function_threshold = number

Taille maximale d'une fonction (nombre de lignes) qui sera vérifiée par '--filter trivial'.

excessive_count_theshold = number

Définit le seuil de comptage d'exécutions que l'outil doit considérer comme indiquant un bug du compilateur (données de couverture corrompues).

Démangle les symboles C++. Appeler plusieurs fois pour spécifier la commande et ses arguments en ligne de commande (comportement de type '-Xlinker').

Spécifie les paramètres supplémentaires à passer à l'outil de démangeaison. Cet argument est obsolète - utilisez plutôt l'argument 'demangle_cpp' de type Xlinker.

Emplacement de l'outil gcov.

Ajuste les noms des tests si différent de zéro.

Utilise le format intermédiaire de gcov ? Les valeurs valides sont 0, 1, auto.

no_exception_branch = 0|1

Spécifie si les branches d'exception doivent être exclues de la couverture des branches.

Répertoire contenant les fichiers gcov du noyau.

Emplacement des répertoires temporaires.

Affiche les chemins complets lors de l'opération de liste si différent de zéro.

Spécifie la largeur maximale pour la sortie de la liste. Cette valeur est ignorée lorsque lcov_list_full_path est différent de zéro.

Spécifie le pourcentage maximum de noms de fichiers qui peuvent être tronqués lors du choix d'un préfixe de répertoire dans la sortie de la liste. Cette valeur est ignorée lorsque lcov_list_full_path est différent de zéro.

function_coverage = 0|1

Spécifie si les données de couverture des fonctions doivent être collectées, traitées et affichées.

branch_coverage = 0|1

Spécifie si les données de couverture des branches doivent être collectées, traitées et affichées.

Spécifie si les données de couverture des conditions/décisions modifiées (MC/DC) doivent être collectées, traitées et affichées.

fail_under_branches = percentage

Demande à lcov/genhtml/geninfo de renvoyer un code de sortie non nul si la couverture des branches est inférieure au pourcentage de seuil spécifié.

Demande à lcov/genhtml/geninfo de renvoyer un code de sortie non nul si la couverture des lignes est inférieure au pourcentage de seuil spécifié.

lcov_json_module = module

Spécifie le module JSON à utiliser, ou choisit le meilleur disponible s'il est défini sur auto.

parallel = number

Spécifie le nombre maximum d'esclaves parallèles (défaut: 1 (pas de parallélisme)).

Spécifie la mémoire maximale à utiliser lors du traitement parallèle, en Mo. Ne pas forker si la consommation mémoire estimée dépasse ce nombre (défaut: 0 (pas de limite)).

Spécifie le nombre d'échecs consécutifs de fork() à autoriser avant d'abandonner (défaut: 5).

Contrôle de limitation : spécifie un pourcentage de la mémoire système à utiliser comme maximum lors du traitement parallèle. Ne pas forker si la consommation mémoire estimée dépasse le maximum. Cette valeur n'est utilisée que si la mémoire maximale n'est pas définie (défaut: non défini).

Utilise une comparaison insensible à la casse pour trouver les fichiers correspondants, pour les directives include/exclude, etc.

lcov_excl_stop = regexp

Remplace l'expression régulière de fin de région d'exclusion.

Remplace l'expression régulière de début de région d'exclusion de branche.

OPTIONS

config_file = filename

Inclut un autre fichier de configuration.

L'inclusion est équivalente à insérer le contenu de filename à cet endroit dans le fichier actuel. Par conséquent, les paramètres du fichier inclus sont traités après les paramètres précédents dans le fichier actuel, mais avant les paramètres ultérieurs du fichier actuel. En conséquence :

Les options scalaires définies précédemment dans le fichier actuel sont remplacées par les paramètres du fichier inclus, et les options scalaires du fichier inclus sont remplacées par les paramètres ultérieurs dans le fichier actuel.

Les options de tableau des parties précédentes du fichier actuel apparaissent avant les paramètres du fichier inclus, et les options de tableau des parties ultérieures du fichier actuel apparaissent après.

L'inclusion de fichiers de configuration est récursive : un fichier de configuration inclus peut inclure un autre fichier, et ainsi de suite. Les boucles d'inclusion ne sont pas prises en charge et entraîneront une erreur d'utilisation.

Le cas d'utilisation le plus courant de l'inclusion de fichiers de configuration est de permettre à un fichier d'options au niveau du site ou du projet d'inclure un fichier d'options spécifique à l'utilisateur ou au module - par exemple, comme ceci :


...
config_file = $ENV{HOME}/.lcovrc_user
...

genhtml_css_file = filename

Spécifie un fichier CSS externe
Fichier de feuille de style. Utilisez cette option pour modifier l'apparence de la sortie HTML générée par genhtml. Lors de la génération de la sortie, une copie de ce fichier sera placée dans le répertoire de sortie.

Cette option correspond à l'option de ligne de commande --css-file de genhtml.

Par défaut, un fichier CSS standard est généré.

genhtml_header = string

Spécifiez le texte de l'en-tête à utiliser en haut de chaque page HTML.

Cette option correspond à l'option de ligne de commande --header-title de genhtml.
La valeur par défaut est "LCOV - (différentiel )? rapport de couverture"

genhtml_footer = string

Spécifiez le texte du pied de page à utiliser en bas de chaque page HTML.

Cette option correspond à l'option de ligne de commande --footer de genhtml.

La valeur par défaut est la chaîne de version de l'outil LCOV.

genhtml_dark_mode = 0|1

Si différent de zéro, affichez en utilisant du texte clair sur fond sombre plutôt que du texte sombre sur fond clair.

Cette option correspond à l'option de ligne de commande --dark-mode de genhtml.

Par défaut, une palette 'claire' est utilisée.

genhtml_hi_limit = hi_limit
genhtml_med_limit = med_limit

Spécifiez les limites de taux de couverture pour la classification des entrées de fichier. Utilisez cette option pour modifier les taux de couverture (en pourcentage) pour la couverture de lignes, de fonctions et de branches à laquelle un résultat est classé comme couverture élevée, moyenne ou faible. Cette classification affecte la couleur des entrées correspondantes sur les pages d'aperçu de la sortie HTML :

Élevée : hi_limit <= taux <= 100 couleur par défaut : vert
Moyenne : med_limit <= taux < hi_limit couleur par défaut : jaune
Faible : 0 <= taux < med_limit couleur par défaut : rouge

Les valeurs par défaut sont 90 et 75 pour cent.

Il existe également des options pour configurer différents seuils pour la couverture de lignes, de branches et de fonctions. Voir ci-dessous.

genhtml_line_hi_limit = line_hi_limit
genhtml_line_med_limit = line_med_limit

Spécifiez un seuil spécifique pour les limites de couverture de lignes utilisées pour décider si un pourcentage donné de couverture de lignes est classé comme couverture élevée, moyenne ou faible. Si les valeurs spécifiques aux lignes ne sont pas spécifiées, alors les valeurs par défaut genhtml_med_limit ou genhtml_hi_limit sont utilisées.

genhtml_branch_hi_limit = branch_hi_limit
genhtml_branch_med_limit = branch_med_limit

Spécifiez un seuil spécifique pour les limites de couverture de branches utilisées pour décider si un pourcentage donné de couverture de branches est classé comme couverture élevée, moyenne ou faible. Si les valeurs spécifiques aux branches ne sont pas spécifiées, alors les valeurs par défaut genhtml_med_limit ou genhtml_hi_limit sont utilisées.

genhtml_function_hi_limit = function_hi_limit
genhtml_function_med_limit = function_med_limit

Spécifiez un seuil spécifique pour les limites de couverture de fonctions utilisées pour décider si un pourcentage donné de couverture de fonctions est classé comme couverture élevée, moyenne ou faible. Si les valeurs spécifiques aux fonctions ne sont pas spécifiées, alors la valeur par défaut genhtml_med_limit ou genhtml_hi_limit est utilisée.

rtl_file_extensions = str[,str]+

Spécifiez une liste d'extensions de fichiers séparées par des virgules qui doivent être considérées comme du code RTL (par exemple, Verilog).

Si non spécifié, l'ensemble par défaut est 'v,vh,sv,vhdl?'. Il n'y a pas d'équivalent dans la ligne de commande.
Cette option est utilisée par genhtml et lcov.

info_file_pattern = str

Spécifiez un motif de correspondance glob associé aux fichiers trace lcov (adapté comme argument pour 'find'). Si non spécifié, la valeur par défaut est '*.info'.

c_file_extensions = str[,str]+

Spécifiez une liste d'extensions de fichiers séparées par des virgules qui doivent être considérées comme du code C/C++.

Si non spécifié, l'ensemble par défaut est 'c,h,i,C,H,I,icc,cpp,cc,cxx,hh,hpp,hxx'. Si vous voulez que tous les fichiers soient traités comme du code C/C++, vous pouvez utiliser : c_file_extensions = .*

Ce paramètre doit être défini dans le fichier lcovrc ou via l'option de ligne de commande --rc name=value ; notez que vous devrez peut-être protéger la valeur de l'expansion du shell dans ce dernier cas.

java_file_extensions = str[,str]+

Spécifiez une liste d'extensions de fichiers séparées par des virgules qui doivent être considérées comme du code Java.

Si non spécifié, l'ensemble par défaut est 'java'. Si vous voulez que tous les fichiers soient traités comme du code Java, vous pouvez utiliser : java_file_extensions = .*

Exemple :

1. Lorsque geninfo signale qu'il ne trouve pas le fichier source


/path/to/src/.libs/file.c

alors que le fichier est réellement situé dans


/path/to/src/file.c

utilisez le paramètre suivant :


geninfo_adjust_src_path = /.libs

Cela supprimera toutes les chaînes "/.libs" du chemin.

/tmp/build/file.c

alors que le fichier est réellement situé dans


/usr/src/file.c

utilisez le paramètre suivant :


geninfo_adjust_src_path = /tmp/build => /usr/src

Notez que cette option n'a aucun effet sans un rappel version-script, défini soit par l'option de ligne de commande --version-script, soit par l'option de fichier de configuration version_script.

La valeur par défaut est 0 : ne pas générer les informations manquantes.

resolve_script = chemin_vers_exécutable|paramètre

Cette option est équivalente à l'option geninfo/lcov/genhtml "--resolve-script".

Cette option peut être utilisée plusieurs fois dans le fichier lcovrc pour spécifier à la fois un script de résolution et des options supplémentaires qui sont passées au script.

Le script de résolution fournit un mécanisme pour trouver un fichier source ou de données qui ne peut pas être trouvé en modifiant simplement les chemins par des modèles de substitution (voir substitute = replace_regexp ci-dessus) et en recherchant le long de la liste de répertoires correspondante :

geninfo : l'entrée de fichier de configuration 'build_directory = dirname' ou l'option de ligne de commande --build=directory, utilisée pour rechercher les fichiers GCNO,
geninfo/genhtml/lcov : l'entrée de fichier de configuration 'source_directory = dirname' ou l'option de ligne de commande --source=directory, utilisée pour rechercher les fichiers source.
Le script de résolution est appelé comme suit :
resolve_script [callback_args] nom_fichier

ou

$resolve_callback = resolve_module ->new([callback_args])

pour initialiser le rappel, puis

$resolve_callback-> resolve (nom_fichier)

pour trouver l'emplacement réel du fichier.

Si nécessaire, le rappel peut vérifier le suffixe du nom de fichier pour déterminer s'il doit rechercher un fichier source ou de données.

Le script doit renvoyer soit une chaîne vide (fichier non trouvé/aucun fichier de ce type), soit le nom du chemin réel. Le chemin renvoyé peut être absolu ou relatif au répertoire de travail courant.

select_script = chemin_vers_exécutable|paramètre

Cette option est équivalente à l'option genhtml "--select-script".

Cette option peut être utilisée plusieurs fois dans le fichier lcovrc pour spécifier à la fois un script de sélection et des options supplémentaires qui sont passées au script.

Le script de sélection fournit un mécanisme pour décider si une ligne source particulière est intéressante, c'est-à-dire si elle doit être incluse dans le rapport de couverture généré, ou non.

Les lignes qui sont

not selected but fall within num_context_lines d'une ligne sélectionnée sont également inclus dans le rapport. Voir ci-dessous.

Notez que la sélection est fondamentalement destinée à montrer des régions de code avec un certain contexte environnant. Elle pourrait ne pas faire ce que vous attendez s'il n'y a pas de code - par exemple, si la région d'intérêt a été compilée hors de portée via des directives de compilation ou d'exclusion. Par exemple : lorsque vous sélectionnez en fonction de l'identifiant SHA ou de la liste de modifications, un commentaire inséré ne sera pas sélectionné sauf s'il se trouve à moins de num_context_lines d'une ligne de code insérée ou modifiée.

Le script select est appelé comme suit :

select_script [callback_args] lineDataJson annotateDataJson fileName lineNumber

ou comme suit :

$selectCallback = select_module ->new([callback_args])

pour initialiser l'objet de rappel, puis comme suit :

$selectCallback select (lineDataRef annotateDataRef fileName lineNumber)

pour déterminer la sélection, où
  • fileName est le nom du fichier source et
  • lineNumber est le numéro de ligne du fichier source, indexé à partir de zéro,
  • lineDataJson est une structure LineData encodée en JSON (voir le code source de lcovutil.pm), et
  • annotateDataJson sont les données encodées en JSON retournées par votre annotate-script (voir le paramètre --annotate-script dans man genhtml(1). ), ou la chaîne vide s'il n'y a pas d'annotations pour ce fichier.

Le rappel de module est similaire, sauf qu'il reçoit des objets plutôt que des encodages JSON des objets.

Le script doit renvoyer "1" ou "0".

Voir l'implémentation d'exemple $LCOV_HOME/share/lcov/support-scripts/select.pm.

Spécifie le caractère (ou l'expression régulière) utilisé pour diviser les paramètres de type liste qui ont été passés sous forme de chaîne unique. Ce paramètre est utile dans le cas où vous avez besoin d'utiliser une chaîne multi-option mais qu'une ou plusieurs des options contiennent un caractère virgule qui serait sinon considéré comme un délimiteur.

Affiche les messages de débogage pour les données dans les noms de fichiers qui correspondent à regexp.

case_insensitive = [0|1]

Spécifie si la comparaison de chaînes est insensible à la casse lors de la recherche de correspondances de noms de fichiers, de la vérification des directives d'inclusion/exclusion, etc.

Notez que les noms de chemins à casse mixte ou en minuscules peuvent être passés à vos rappels --version-script et --annotate-script lorsque la correspondance insensible à la casse est utilisée. Vos rappels doivent gérer les différences potentielles de casse.

La valeur par défaut est '0' : correspondance sensible à la casse.

sort_input = [0|1]

Spécifie s'il faut trier les noms de fichiers avant la capture et/ou l'agrégation. Le tri réduit certains types de différences de sortie dépendantes de l'ordre de traitement - par exemple, en raison d'ambiguïtés dans les données de branche générées par gcc.

La valeur par défaut est '0' : pas de tri - traitement des fichiers dans l'ordre où ils ont été spécifiés sur la ligne de commande et/ou trouvés lors du parcours du système de fichiers.
