NOM

lcov - une interface graphique pour gcov

SYNOPIS

Capture le fichier trace de couverture (à partir des données générées par le compilateur).
Le format du fichier trace lcov (fichier ".info") est décrit dans la page de manuel geninfo(1).

lcov -c|--capture

[-d|--directory répertoire] [-k|--kernel-directory répertoire]
[-o|--output-file fichier_trace] [-t|--test-name nom_test]
[-b|--base-directory répertoire]
[--build-directory répertoire]
[--source-directory répertoire]
[-i|--initial]
[--all]]
[--gcov-tool outil]
[--branch-coverage]
[--mcdc-coverage]
[--demangle-cpp [param]]
[--checksum] [--no-checksum] [--no-recursion] [-f|--follow]
[--sort-input]
[--compat-libtool] [--no-compat-libtool]
[--msg-log [nom_fichier_log]]
[--ignore-errors erreurs]
[--expect-message-count type_message=expression[,type_message=expression..]]
[--preserve] [--to-package paquet] [--from-package paquet] [--no-markers] [--external] [--no-external]
[--compat mode=on|off|auto]
[--context-script fichier_script]
[--criteria-script fichier_script]
[--resolve--script fichier_script]
[--version-script fichier_script]
[--comment chaine_commentaire]
[--large-file regex]

Génère un fichier trace (à partir des données générées par le compilateur) avec toutes les valeurs de compteur mises à zéro :

lcov -z|--zerocounters

[-d|--directory répertoire] [--no-recursion] [-f|--follow]

Affiche les comptes de couverture enregistrés dans un fichier trace généré précédemment :

lcov -l|--list fichier_trace

[--list-full-path] [--no-list-full-path]

Agrège plusieurs fichiers traces de couverture en un seul :

lcov -a|--add-tracefile motif_fichier_trace

[-o|--output-file fichier_trace]
[--prune-tests]
[--forget-test-names]
[--map-functions]
[--branch-coverage]
[--mcdc-coverage]
[--checksum] [--no-checksum]
[--sort-input]

Selon votre modèle d'utilisation, il peut ne pas être nécessaire de créer des fichiers de données de couverture agrégés. Par exemple, si vos tests de régression sont divisés en plusieurs suites, vous voudrez peut-être conserver des données de suite séparées et comparer les résultats par suite et agrégés au fil du temps. genhtml vous permet de spécifier des fichiers traces via un ou plusieurs modèles globaux, ce qui vous permet de générer des rapports agrégés sans générer explicitement de fichiers traces agrégés. Voir la page de manuel de genhtml.

Génère un nouveau fichier trace à partir d'un fichier trace existant, en ne conservant que les données des fichiers correspondant au motif :

lcov -e|--extract fichier_trace motif

[-o|--output-file fichier_trace] [--checksum] [--no-checksum]

Génère un nouveau fichier trace à partir d'un fichier trace existant, en supprimant les données des fichiers correspondant au motif :

lcov -r|--remove fichier_trace motif

[-o|--output-file fichier_trace] [--checksum] [--no-checksum]

Génère un nouveau fichier trace à partir de fichiers traces existants en effectuant des opérations d'ensemble sur les données de couverture :

lcov --intersect motif_glob_droite

[-o|--output-file fichier_trace]
motif_glob_gauche

La sortie reflétera

(union des fichiers correspondant aux motifs globaux de gauche) intersect (union des fichiers correspondant aux motifs globaux de droite)
de telle sorte que les points de couverture trouvés dans les deux ensembles soient fusionnés (sommés) tandis que les points de couverture trouvés dans un seul ensemble sont supprimés. Notez que les blocs de branche sont définis comme étant identiques si et seulement si leur ID de bloc et la liste associée des expressions de branche sont identiques. Les fonctions sont définies comme identiques si leur nom et leur emplacement sont identiques.
lcov --subtract motif_glob_droite

[-o|--output-file fichier_trace]
motif_glob_gauche

La sortie reflétera

(union des fichiers correspondant aux motifs globaux de gauche) subtract (union des fichiers correspondant aux motifs globaux de droite)
de telle sorte que les points de couverture trouvés uniquement dans l'ensemble de gauche seront conservés et tous les autres seront supprimés.

Résume le contenu d'un fichier trace :

lcov --summary fichier_trace

Affiche la version ou un message d'aide et quitte :

lcov [-h|--help] [--version]

Options communes de lcov - prises en charge par tous les cas d'utilisation ci-dessus :

lcov [--keep-going]
[--filter type]
[-q|--quiet]
[-v|--verbose]
[--comment chaine_commentaire]
[--debug]
[--parallel|-j [entier]]
[--memory nombre_entier_en_Mo]
[--tempdir nom_répertoire]
[--branch-coverage]
[--mcdc-coverage]
[--config-file fichier_config] [--rc mot_clé=valeur]
[--profile [fichier_profil]]
[--include motif_glob]
[--exclude motif_glob]
[--erase-functions motif_regex]
[--substitute motif_regex]
[--omit-lines motif_regex]
[--fail-under-branches pourcentage]
[--fail-under-lines pourcentage]

DESCRIPTION

lcov est une interface graphique pour l'outil de test de couverture gcov de GCC. Il collecte les données de couverture de lignes, de fonctions et de branches pour plusieurs fichiers sources et crée des pages HTML contenant le code source annoté avec des informations de couverture. Il ajoute également des pages de synthèse pour faciliter la navigation dans la structure des fichiers.

Utilisez lcov pour collecter les données de couverture et genhtml pour créer les pages HTML. Les données de couverture peuvent être collectées à partir du noyau Linux en cours d'exécution ou d'une application user-space. Pour ce faire, vous devez suivre les étapes de préparation suivantes :

Pour la couverture du noyau Linux :

Suivez les instructions de configuration de l'infrastructure gcov-kernel : https://docs.kernel.org/dev-tools/gcov.html

Pour la couverture des applications user-space :

Compilez l'application avec GCC en utilisant les options "-fprofile-arcs" et "-ftest-coverage" ou "--coverage".

Veuillez noter que cette page de manuel fait référence au format de sortie de lcov comme "fichier .info" ou "fichier trace", et que la sortie de GCOV est appelée "fichier .da".

Notez également que lors de l'affichage des pourcentages, 0% et 100% ne sont affichés que lorsque les valeurs sont exactement 0% et 100% respectivement. Les autres valeurs qui seraient conventionnellement arrondies à 0% ou 100% sont plutôt affichées comme la valeur non limite la plus proche. Ce comportement est conforme à celui de l'outil gcov(1).

Par défaut, lcov et les outils associés génèrent et collectent des données de couverture de lignes et de fonctions. Les données de branche ne sont pas collectées ou affichées par défaut ; tous les outils prennent en charge les options --branch-coverage et --mdcd-coverage pour activer respectivement la couverture de branche et MC/DC - ou vous pouvez activer en permanence la couverture de branche en ajoutant les paramètres appropriés à votre fichier de configuration lcov personnel, de groupe ou de site. Voir la page de manuel lcovrc(5) pour plus de détails.

OPTIONS

En général, (presque) toutes les options de lcov peuvent également être spécifiées dans un fichier de configuration - voir la page de manuel lcovrc(5) pour plus de détails.

-a motif_fichier_trace
--add-tracefile motif_fichier_trace

Ajoute le contenu de tous les fichiers correspondant au motif glob

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

tracefile_pattern.

Spécifiez plusieurs fichiers de trace à l'aide de l'option -a pour combiner les données de couverture contenues dans ces fichiers en additionnant les compteurs d'exécution pour les combinaisons de tests et de noms de fichiers correspondants.

Le résultat de l'opération d'addition sera écrit sur stdout ou sur le fichier de trace spécifié avec -o.

Une seule des options -z, -c, -a, -e, -r, -l ou --summary peut être spécifiée à la fois.

-b répertoire
--base-directory répertoire

Utilisez répertoire comme répertoire de base pour les chemins relatifs.

Utilisez cette option pour spécifier le répertoire de base d'un environnement de compilation lorsque lcov produit des messages d'erreur tels que :

ERREUR : impossible de lire le fichier source /home/user/project/subdir1/subdir2/subdir1/subdir2/file.c

Dans cet exemple, utilisez /home/user/project comme répertoire de base.

Cette option est requise lors de l'utilisation de lcov sur des projets construits avec libtool ou des environnements de construction similaires qui fonctionnent avec un répertoire de base, c'est-à-dire des environnements où le répertoire de travail courant lors de l'invocation du compilateur n'est pas le même répertoire que celui où se trouve le fichier source.

Notez que cette option ne fonctionnera pas dans les environnements où plusieurs répertoires de base sont utilisés. Dans ce cas, utilisez le paramètre du fichier de configuration geninfo_auto_base=1 (voir la page de manuel lcovrc(5) ).

--build-directory répertoire_de_construction

Recherchez les fichiers de données .gcno à partir du répertoire de construction plutôt qu'à côté du fichier .gcda correspondant.

Voir la page de manuel geninfo(1) pour plus de détails.

--source-directory nom_répertoire
Ajoute 'nom_répertoire' à la liste des emplacements où rechercher les fichiers sources.

Pour les chemins de fichiers sources relatifs listés dans, par exemple, les chemins trouvés dans tracefile, ou trouvés dans la sortie gcov lors de --capture - potentiellement après l'application de substitutions - lcov
cherchera d'abord le chemin à partir de 'cwd' (où genhtml a été invoqué), puis à partir de chaque répertoire alternatif dans l'ordre spécifié. Le premier emplacement correspondant est utilisé.

Cette option peut être spécifiée plusieurs fois, pour ajouter d'autres répertoires au chemin de recherche source.

-c
--capture
Capture les données de couverture d'exécution.

Par défaut, capture les compteurs d'exécution du noyau actuel et écrit les données de couverture résultantes sur la sortie standard. Utilisez l'option --directory pour capturer les compteurs d'un programme en espace utilisateur.

Le résultat de l'opération de capture sera écrit sur stdout ou sur le fichier de trace spécifié avec -o.

Lorsqu'elle est combinée avec le drapeau --all, la couverture d'exécution et de compilation sera extraite en une seule étape. Voir la description du drapeau --initial ci-dessous.

Voir la page de manuel geninfo(1) pour plus de détails sur le processus de capture et les options et paramètres disponibles.

Une seule des options -z, -c, -a, -e, -r, -l, --diff ou --summary peut être spécifiée à la fois.

--branch-coverage


Collecte et/ou conserve les données de couverture des branches.

Ceci est équivalent à utiliser l'option "--rc branch_coverage=1" ; l'option a été ajoutée pour mieux correspondre à l'interface genhml.

--mcdc-coverage


Collecte et conserve les données MC/DC.

Ceci est équivalent à utiliser l'option "--rc mcdc_coverage=1". La couverture MC/DC est prise en charge pour les versions GCC 14.2 et supérieures, ou LLVM 18.1 et supérieures.
Voir llvm2lcov --help pour plus de détails sur la capture de données MC/DC dans LLVM.

Voir la section MC/DC de la page de manuel genhtml(1) pour plus de détails.

--checksum
--no-checksum

Spécifiez si des données de somme de contrôle doivent être générées lors de l'écriture des fichiers de trace et/ou si les sommes de contrôle correspondantes doivent être vérifiées lors de la combinaison des fichiers de trace.

Utilisez --checksum pour activer la génération de sommes de contrôle ou --no-checksum pour la désactiver. La génération de sommes de contrôle est désactivée par défaut.

Lorsque la génération de sommes de contrôle est activée, une somme de contrôle sera générée pour chaque ligne de code source et stockée avec les données de couverture. Cette somme de contrôle sera utilisée pour empêcher les tentatives de combiner des données de couverture provenant de différentes versions de code source.

Si vous ne travaillez pas avec différentes versions de code source, désactivez cette option pour accélérer le traitement des données de couverture et réduire la taille des fichiers de trace.

Notez que cette option est quelque peu subsumée par l'option --version-script qui fait quelque chose de similaire, mais au niveau du 'fichier entier'.

--compat mode=valeur[,mode=valeur,...]

Définit le mode de compatibilité.

Utilisez --compat pour spécifier que lcov doit activer un ou plusieurs modes de compatibilité lors de la capture des données de couverture. Vous pouvez fournir une liste de paires mode=valeur séparées par des virgules pour spécifier les valeurs de plusieurs modes.

Les valeurs valides sont :

on

Active le mode de compatibilité.
off
Désactive le mode de compatibilité.
auto
Applique la détection automatique pour déterminer si le mode de compatibilité est requis. Notez que la détection automatique n'est pas disponible pour tous les modes de compatibilité.

Si aucune valeur n'est spécifiée, 'on' est supposé comme valeur par défaut.

Les modes valides sont :

libtool

Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant le mécanisme libtool. Voir aussi --compat-libtool.

La valeur par défaut pour ce paramètre est 'on'.

hammer
Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant une version de GCC 3.3 contenant une modification (patch hammer) de versions ultérieures de GCC. Vous pouvez identifier une version modifiée de GCC 3.3 en vérifiant le répertoire de construction de votre projet pour les fichiers se terminant par l'extension '.bbg'. Les versions non modifiées de GCC 3.3 nomment ces fichiers '.bb'.

La valeur par défaut pour ce paramètre est 'auto'.

split_crc
Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant une version de GCC 4.6 contenant une modification (sommes de contrôle de fonction divisées) de versions ultérieures de GCC. Les messages d'erreur typiques lors de l'exécution de lcov sur des données de couverture produites par de telles versions de GCC sont « manque de mémoire » et « fin de fichier inattendue atteinte ».

La valeur par défaut pour ce paramètre est 'auto'

--compat-libtool
--no-compat-libtool

Spécifiez si le mode de compatibilité libtool doit être activé.

Utilisez --compat-libtool pour activer le mode de compatibilité libtool ou --no-compat-libtool pour le désactiver. Le mode de compatibilité libtool est activé par défaut.

Lorsque le mode de compatibilité libtool est activé, lcov supposera que le code source relatif à un fichier .da situé dans un répertoire nommé ".libs" peut être trouvé dans son répertoire parent.

Si vous avez des répertoires nommés ".libs" dans votre environnement de construction mais n'utilisez pas libtool, désactivez cette option pour éviter les problèmes lors de la capture des données de couverture.

--config-file fichier_configuration

Spécifie un fichier de configuration à utiliser. Voir la page de manuel lcovrc(5) pour les détails du format du fichier et des options. Voir également l'entrée config_file dans la même page de manuel pour savoir comment inclure un fichier de configuration dans un autre.

Lorsque cette option est spécifiée, ni le fichier de configuration système /etc/lcovrc, ni le fichier de configuration par utilisateur ~/.lcovrc ne sont lus.

Cette option peut être utile lorsqu'il est nécessaire d'exécuter plusieurs instances de lcov avec des options de fichier de configuration différentes en parallèle.

Notez que cette option doit être spécifiée en entier - les abréviations ne sont pas prises en charge.

--profile [ fichier_données_profil ]

Indique à l'outil de suivre les performances et d'autres données de configuration. Si le fichier_données_profil optionnel n'est pas spécifié, alors les données de profil sont écrites dans un fichier nommé avec le même nom de base que --output-filename, avec le suffixe .json ajouté.

Une seule des options -z, -c, -a, -e, -r, -l, --diff ou --summary peut être spécifiée à la fois.

-d répertoire
--directory répertoire

Utilise les fichiers .da dans répertoire au lieu du noyau.

Si vous souhaitez travailler sur les données de couverture d'un programme en espace utilisateur, utilisez cette option pour spécifier l'emplacement où le programme a été compilé (c'est là que les fichiers de compteur se terminant par .da seront stockés).

Notez que vous pouvez spécifier cette option plus d'une fois.

--exclude motif

Exclut les fichiers sources correspondant au motif.

Utilisez ce commutateur si vous souhaitez exclure les données de couverture pour un ensemble particulier de fichiers sources correspondant à l'un des motifs donnés. Plusieurs motifs peuvent être spécifiés en utilisant plusieurs commutateurs de ligne de commande --exclude. Les motifs seront interprétés comme des motifs de caractères génériques shell (notez qu'ils devront peut-être être échappés en conséquence pour empêcher le shell de les développer en premier).

Note : Le motif doit être spécifié pour correspondre au chemin absolu de chaque fichier source. Si vous spécifiez un motif qui ne semble pas être correctement appliqué - les fichiers que vous vous attendiez à être exclus apparaissent toujours dans la sortie - vous pouvez rechercher des messages d'avertissement dans le fichier journal. lcov émettra un avertissement pour chaque motif qui n'est appliqué au moins une fois.

Peut être combiné avec le commutateur de ligne de commande --include. Si un fichier donné correspond à la fois au motif d'inclusion et au motif d'exclusion, le motif d'exclusion aura la priorité.

--erase-functions regexp

Exclut les données de couverture des lignes qui se trouvent dans une fonction dont le nom correspond à la regexp fournie. Notez qu'il s'agit d'un nom manglé ou démanglé, selon que l'option --demangle-cpp est utilisée ou non.

Notez que cette option nécessite que vous utilisiez une version de gcc suffisamment récente pour prendre en charge les rapports de début/fin de fonction, ou que vous configuriez l'outil pour dériver les données requises - voir la discussion derive_function_end_line dans la page de manuel lcovrc(5).

--substitute regexp_motif
Applique l'expression régulière Perl regexp_motif aux noms de fichiers sources trouvés pendant le traitement. Ceci est utile, par exemple, lorsque le nom de chemin rapporté par gcov ne correspond pas à la disposition de votre source et que le fichier n'est pas trouvé, ou dans des environnements plus compliqués où la structure du répertoire de construction ne correspond pas à la disposition du code source ou à la disposition dans le système de contrôle de révision du projet.

lcov(1) manual page

NAME

lcov - gcov/emacs-lisp-coverage wrapper

SYNOPSIS

lcov [--capture | --list | --remove | --branch | --diff | --checksum | --concatenate | --compare | --archive | --human-readable | --html | --directory | --output-file | --daemon | --config-file | --quiet | --verbose | --version | --help] ...

DESCRIPTION

lcov is a graphical front-end for gcov, emacs-lisp-coverage(1) and python-coverage.py(1). It collects execution counts generated by gcov, emacs-lisp-coverage or python-coverage.py and transforms them into a format that is suitable for creating HTML pages or for further processing.

In addition to the standard gcov features, lcov may also be used to collect coverage data for C++, Java, Python, Perl, shell scripts and emacs lisp. When used with emacs-lisp-coverage or python-coverage.py, lcov will fetch coverage data for all files of the specified language.

See the man pages for geninfo(1), genhtml(1), genpng(1), lcovrc(5) and gcov(1) for details on specific operations.

OPTIONS

The following options are available for lcov:

-c
--capture

Capture execution counts.

This option instructs lcov to capture execution counts from file. It will search for the data files generated by gcov, emacs-lisp-coverage or python-coverage.py and use the provided source file information to create a trace file.

The trace file may then be used to generate HTML pages using genhtml or for further processing using other lcov commands.

Default is to search for data files in the current directory.

-l
--list

List trace file.

This option instructs lcov to list the contents of a trace file. It will show the file name, line number and execution count for each covered line.

-r tracefile [pattern]...
--remove tracefile [pattern]...

Remove selected file names from trace file.

Use this switch if you want to remove coverage data for a particular set of files from a trace file. Additional command line parameters will be interpreted as shell wildcard patterns (note that they may need to be escaped accordingly to prevent the shell from expanding them first). Every file entry in tracefile which matches at least one of those patterns will be removed.

Note: The pattern must be specified to match the absolute path of each source file.

The result of the remove operation will be written to stdout or the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--branch tracefile [pattern]...

Add branch coverage data to trace file.

Use this switch if you want to add branch coverage data for a particular set of files to a trace file. Additional command line parameters will be interpreted as shell wildcard patterns (note that they may need to be escaped accordingly to prevent the shell from expanding them first). Every file entry in tracefile which matches at least one of those patterns will have branch coverage data added.

Note: The pattern must be specified to match the absolute path of each source file.

The result of the branch operation will be written to stdout or the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--diff tracefile1 tracefile2

Create difference between trace files.

Use this switch if you want to compare two trace files. It will show the differences in execution counts between the two files.

The result of the diff operation will be written to stdout or the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--checksum tracefile

Calculate checksum for trace file.

Use this switch if you want to calculate the checksum of a trace file. It will show the checksum of the file.

The result of the checksum operation will be written to stdout.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

-a tracefile
--concatenate tracefile

Concatenate trace files.

Use this switch if you want to concatenate multiple trace files into one. All trace files specified with --add-tracefile will be concatenated.

The result of the concatenate operation will be written to stdout or the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--compare tracefile1 tracefile2

Compare trace files.

Use this switch if you want to compare two trace files. It will show the differences in execution counts between the two files.

The result of the compare operation will be written to stdout or the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--archive tracefile

Create archive from trace file.

Use this switch if you want to create an archive from a trace file. It will create a compressed archive containing the trace file and all associated source files.

The result of the archive operation will be written to the tracefile specified with -o.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

--human-readable tracefile

Convert trace file to human-readable format.

Use this switch if you want to convert a trace file to a human-readable format. It will show the file name, line number and execution count for each covered line.

The result of the conversion will be written to stdout.

Only one of -z, -c, -a, -e, -r, -l, --diff or --summary may be specified at a time.

-h
--html

Generate HTML pages.

Use this option to generate HTML pages from a trace file. The HTML pages will show the coverage data in a graphical format.

This option requires the trace file to be generated using the --capture option. The HTML pages will be generated in the current directory, or in the directory specified by the --output-directory option.

-d directory
--directory directory

Search directory.

Use this option to specify the directory in which to search for source files and data files. If not specified, the current directory will be used.

-o outfile
--output-file outfile

Write output to file.

Use this option to specify the file to which the output should be written. If not specified, the output will be written to stdout.

--daemon

Run in daemon mode.

Use this option to run lcov in daemon mode. In this mode, lcov will listen for incoming connections on a specified port and accept coverage data from clients.

--config-file conf

Use configuration file.

Use this option to specify a configuration file to be used by lcov. The configuration file may contain any of the lcov options, in addition to custom options specific to the configuration file.

See the man page for lcovrc(5) for details.

-q
--quiet

Quiet mode.

Use this option to suppress all output from lcov, except for errors and warnings.

-v
--verbose

Verbose mode.

Use this option to enable verbose output from lcov. This will print all messages, including debug messages.

--version

Display version information.

Show version number and exit.

--help

Display help information.

Show a summary of options and exit.

--substitute s/pattern/replacement/flags

Substitute pattern in source file names.

This option allows you to correct or remove parts of source file paths. This is useful in situations where geninfo cannot find the correct path to source code files of a project. By providing a regexp_pattern in Perl regular expression format (see man perlre(1) ), you can instruct geninfo to remove or change parts of the incorrect source path. Also see the --resolve-script option.

One or more --substitution patterns and/or a --resolve-script may be specified. When multiple patterns are specified, they are applied in the order specified, substitution patterns first followed by the resolve callback. The file search order is:

1.
Look for file name (unmodified).
If the file exits: return it.
2.
Apply all substitution patterns in order - the result of the first pattern is used as the input of the second pattern, and so forth.
If a file corresponding to the resulting name exists: return it.
3.
Apply the 'resolve' callback to the final result of pattern substitutions.
If a file corresponding to the resulting name exists: return it.
4.
Otherwise: return original (unmodified) file name.
Depending on context, the unresolved file name may or may not result in an error.

Substitutions are used in multiple contexts by lcov/genhtml/geninfo:

  • during --capture, applied to source file names found in gcov-generated coverage data files (see man gcov(1) ).
  • during --capture, applied to alternate --build-dir paths, when looking for the .gcno (compile time) data file corresponding to some .gcda (runtime) data file.
  • applied to file names found in lcov data files (".info" files) - e.g., during lcov data aggregation or HTML and text report generation.
    For example, substituted names are used to find source files for text-based filtering (see the --filter section, below) and are passed to --version-script, --annotate-script, and -criteria-script callbacks.
  • applied to file names found in the --diff-file passed to genhtml.

Example:

1. When geninfo reports that it cannot find source file


/path/to/src/.libs/file.c

while the file is actually located in


/path/to/src/file.c

use the following parameter:


--substitute 's#/.libs##g'

This will remove all "/.libs" strings from the path.

2. When geninfo reports that it cannot find source file


/tmp/build/file.c

while the file is actually located in


/usr/src/file.c

use the following parameter:


--substitute 's#/tmp/build#/usr/src#g'

This will change all "/tmp/build" strings in the path to "/usr/src".

--omit-lines regexp

Exclude coverage data from lines whose content matches regexp.

Use this switch if you want to exclude line and branch coverage data for some particular constructs in your code (e.g., some complicated macro). Multiple patterns can be specified by using multiple --omit-lines command line switches. The regexp will be interpreted as perl regular expressions (note that they may need to be escaped accordingly to prevent the shell from expanding them first). If you want the pattern to explicitly match from the start or end of the line, your regexp should start and/or end with "^" and/or "$".

Note that the lcovrc config file setting lcov_excl_line = regexp is similar to --omit-lines. --omit-lines is useful if there are multiple teams each of which want to exclude certain patterns. --omit-lines is additive and can be specified across multiple config files whereas each call to lcov_excl_line overrides the previous value - and thus teams must coordinate.

--external

Specify whether to capture coverage data for external source files.

External source files are files which are not located in one of the directories specified by --directory or --base-directory. Use --external to include coverpoints in external source files while capturing coverage data or --no-external to exclude them. If your --directory or --base-directory path contains a soft link, then actual target directory is not considered to be "internal" unless the --follow option is used.

The --no-external option is somewhat of a blunt instrument; the --exclude and --include options provide finer grained control over which coverage data is and is not included if your project structure is complex and/or --no-external does not do what you want.

Data for external source files is included by default.

If non-zero, ignore testcase names in .info file - i.e., treat all coverage data as if it came from the same testcase. This may improve performance and reduce memory consumption if user does not need per-testcase coverage summary in coverage reports.

Determine list of unique tracefiles.

Use this option to determine a list of unique tracefiles from the list specified by --add-tracefile. A tracefile is considered to be unique if it is the only tracefile that:

1.
contains data for a specific source file
2.
contains data for a specific test case name
3.
contains non-zero coverage data for a specific line, function or branch

Note that the list of retained files may depend on the order they are processed. For example, if A and B contain identical coverage data, then the first one we see will be retained and the second will be pruned. The file processing order is nondeterministic when the --parallel option is used - implying that the pruned result may differ from one execution to the next in this case.

--prune-testsmustbespecifiedtogetherwith --add-tracefile. When specified, lcov will emit the list of unique files rather than combined tracefile data.

This option must be specified together with --add-tracefile. When specified, lcov will emit the list of functions and associated tracefiles rather than combined tracefile data.

--comment comment_string

--ignore-errors erreurs

Spécifiez une liste d'erreurs après lesquelles continuer le traitement.

Utilisez cette option pour spécifier une liste d'une ou plusieurs classes d'erreurs après lesquelles lcov doit continuer le traitement au lieu d'avorter. Notez que l'outil générera un avertissement (plutôt qu'une erreur fatale) sauf si vous ignorez l'erreur deux fois (ou plus) :

lcov ... --ignore-errors source,source ...

erreurs peut être une liste séparée par des virgules des mots-clés suivants :

branch:
l'ID de branche (2ème champ dans l'entrée 'BRDA' du fichier .info) ne suit pas la séquence entière attendue.
callback:
Erreur de script de version.
child:
le processus fils a retourné un code de sortie non nul lors de l'exécution --parallel. Cela indique généralement que le fils a rencontré une erreur : voir le fichier log immédiatement avant ce message. En contraste : l'erreur parallel indique une exception inattendue/non gérée dans le processus fils - pas une erreur 'typique' de lcov.
corrupt:
fichier corrompu/illisible trouvé.
count:
Un nombre excessif de messages d'une certaine classe ont été signalés - les messages ultérieurs de ce type seront supprimés. La limite peut être contrôlée par la variable 'max_message_count'. Voir la page de manuel lcovrc(5).
deprecated:
Vous utilisez une option obsolète. Cette option sera supprimée dans une future version - vous devriez donc modifier vos scripts dès maintenant.
empty:
le fichier de données .info est vide (par exemple, parce que tout le code a été 'supprimé' ou exclu.
excessive:
vos données de couverture contiennent un nombre de 'coups'（hits）suspectement élevé qui n'est probablement pas correct - indiquant potentiellement un bug dans votre chaîne d'outils. Voir la section excessive_count_threshold dans la page de manuel lcovrc(5) pour plus de détails.
fork:
Impossible de créer un processus fils lors de l'exécution --parallel.
Si le message est ignoré ( --ignore-errors fork ), alors genhtml attendra une courte période puis réessayera l'exécution échouée.
Si vous rencontrez des erreurs continues, désactivez ou réduisez le parallélisme, définissez une limite de mémoire, ou trouvez un serveur plus grand pour exécuter la tâche.
format:
Syntaxe ou valeur inattendue trouvée dans le fichier .info - par exemple, un nombre négatif ou un numéro de ligne zéro rencontré.
gcov:
l'outil gcov est retourné avec un code de retour non nul.
graph:
le fichier graphique n'a pas pu être trouvé ou est corrompu.
inconsistent:
vos données de couverture sont incohérentes en interne : elles font deux ou plusieurs affirmations mutuellement exclusives. Par exemple, une expression est marquée comme étant à la fois une branche d'exception et non une branche d'exception. (Voir la page de manuel genhtml(1) pour plus de détails.
internal:
Problème interne de l'outil détecté. Veuillez signaler ce bug avec un cas de test.
mismatch:
Entrées incohérentes trouvées dans le fichier de trace :
  • l'expression de branche (3ème champ dans l'entrée 'BRDA' du fichier .info) des données de fusion ne correspond pas, ou
  • le nombre d'exécutions de fonction (FNDA:...) mais pas de déclaration de fonction (FN:...).
missing:
Fichier inexistant ou illisible.
negative:
Nombre de 'coups'（hits）négatif trouvé.

Notez que les comptages négatifs peuvent être causés par un bug GCC connu - voir


https://gcc.gnu.org/bugzilla/show_bug.cgi?id=68080

et essayez de compiler avec "-fprofile-update=atomic". Vous devrez recompiler, réexécuter vos tests et recapturer les données de couverture.

package:
un package perl requis n'est pas installé sur votre système. Dans certains cas, il est possible d'ignorer ce message et de continuer - cependant, certaines fonctionnalités seront désactivées dans ce cas.
parallel:
divers types d'erreurs liées au parallélisme - c'est-à-dire, un processus fils est mort en raison d'une erreur. Le message d'erreur correspondant apparaît dans le fichier log juste avant l'erreur parallel.

Si vous rencontrez une erreur liée à l'exécution parallèle qui semble invalide, il peut être judicieux de supprimer le drapeau --parallel et de réessayer. Si la suppression du drapeau conduit à un résultat différent, veuillez signaler le problème (avec un cas de test) afin que l'outil puisse être corrigé.

parent:
le processus parent s'est terminé alors que le fils était actif lors de l'exécution --parallel. Cela se produit lorsque le parent a rencontré une erreur fatale - par exemple une erreur dans un autre fils qui n'a pas été ignorée. Ce fils ne peut pas continuer à fonctionner sans son parent - et va donc se terminer.
range:
Les données de couverture font référence à un numéro de ligne supérieur au nombre de lignes du fichier source. Cela peut être causé par une incompatibilité de version ou par un problème dans les données gcov.
source:
le fichier source pour un ensemble de données n'a pas pu être trouvé.
unsupported:
la fonctionnalité demandée n'est pas prise en charge pour cette configuration d'outil. Par exemple, les exclusions de plages de début/fin de fonction utilisent certaines fonctionnalités GCOV qui ne sont pas disponibles dans les anciennes versions de GCC.
unused:
le modèle include/exclude/erase/omit/substitute n'a correspondu à aucun chemin de fichier.
usage:
utilisation non prise en charge détectée - par exemple, une combinaison d'options non prise en charge.
utility:
un outil appelé pendant le traitement a retourné un code d'erreur (par exemple, 'find' a rencontré un répertoire illisible).
version:
les identifiants de contrôle de révision du fichier que nous essayons de fusionner ne sont pas les mêmes - la numérotation des lignes et d'autres informations peuvent être incorrectes.

Voir également la page de manuel lcovrc(5) pour une discussion sur le paramètre 'max_message_count' qui peut être utilisé pour contrôler le nombre d'avertissements émis avant que tous les messages subséquents ne soient supprimés. Ceci peut être utilisé pour réduire le volume du fichier log.

LCOV(1)

NOM

lcov - outil de collection de données de couverture

SYNOPSIS

lcov [-h|--help] [-v|--version] [-g|--generate-build-id] [-j nb_proc|--parallel nb_proc] [-b build_dir|--build-directory build_dir] [-d trace_dir|--directory trace_dir] [--initial] [--all] [-k subdir|--kernel-directory subdir] [-o tracefile|--output-file tracefile] [-s|--summary] [-c|--capture] [-a tracefile|--add tracefile] [-e tracefile|--extract tracefile] [-r tracefile pattern|--remove tracefile pattern] [-l tracefile|--list tracefile] [-t testname|--test-name testname] [-p dir|--temp-directory dir] [-q|--quiet] [--debug] [--no-markers] [--no-recursion] [--no-list-full-path|--list-full-path] [--to-package package] [--from-package package] [--diff tracefile1 tracefile2] [--compare-version] [--fail-under-lines percentage] [--fail-under-branches percentage] [--rc keyword=value] [--memory integer]

DESCRIPTION

lcov est un utilitaire qui collecte les données de couverture de code collectées par l'outil gcov et les combine pour une utilisation par des outils tels que genhtml et geninfo. Il peut être utilisé pour collecter des données de couverture pour le code en espace utilisateur ou pour le code du noyau.

lcov collecte les données de couverture dans des fichiers texte appelés fichiers de trace, par défaut nommés "*.info".

OPTIONS

Les options suivantes sont disponibles.

-b build_dir
--build-directory build_dir

Utilisé pour spécifier le répertoire dans lequel le programme doit être construit. Ceci est nécessaire lorsque le programme gcov est appelé depuis un répertoire de build différent du répertoire source. Par exemple, lorsque vous utilisez un répertoire de build séparé.

lcov recherche les fichiers de données de compilation (.gcno) dans le répertoire spécifié par --directory et les fichiers de données d'exécution (.gcda) dans le répertoire spécifié par --build-directory.

Si les deux répertoires sont identiques, vous pouvez omettre l'une ou l'autre de ces options.

-c
--capture

Capture les données de couverture de l'exécution du programme. Cette option peut être utilisée avec les options -d et -o.

Si l'option --initial est spécifiée, les données de couverture initiales seront capturées. Ces données incluent les informations sur les lignes de code qui n'ont pas été exécutées. Les données de couverture initiales sont utiles pour obtenir un rapport de couverture de 100% même lorsque certaines parties du code ne sont pas atteintes.

--initial sera ignoré sauf en mode --capture.

--all sera ignoré si --initial est spécifié.

La procédure recommandée lors de la capture de données pour un cas de test est la suivante :

  1. créer le fichier de données de couverture de référence
# lcov -c -i -d appdir -o app_base.info
  1. exécuter le test
# appdir/test
  1. créer le fichier de données de couverture du test
# lcov -c -d appdir -o app_test.info
  1. combiner les données de couverture de référence et de test
# lcov -a app_base.info -a app_test.info -o app_total.info

Les 4 étapes ci-dessus sont équivalentes à :

# lcov --capture --all -o app_total.info -d appdir

La combinaison des données de compilation et d'exécution produira un résultat différent de la capture des données d'exécution seules si votre projet contient des unités de compilation qui ne sont pas utilisées dans aucun de vos exécutables de cas de test ou bibliothèques partagées - c'est-à-dire, il existe des fichiers de données '.gcno' (temps de compilation) qui n'ont pas de fichiers de données '.gcda' (temps d'exécution) correspondants. Dans ce cas, le rapport d'exécution seule ne contiendra aucun point de couverture des fichiers inutilisés, tandis que ces points de couverture apparaîtront (avec tous les comptes de 'hit' à zéro) dans le rapport combiné.

L'indicateur --initial est ignoré sauf en mode --capture. L'indicateur --all est ignoré si l'indicateur --initial est spécifié.

Cette option permet à l'outil d'utiliser un parallélisme maximum - jusqu'à la limite imposée par la restriction de mémoire.

-t testname
--test-name testname

Spécifie le nom du test à stocker dans le fichier de trace.

Ce nom identifie un ensemble de données de couverture lorsque plusieurs ensembles de données sont fusionnés dans un fichier de trace combiné (voir l'option -a).

Les noms de test valides peuvent contenir des lettres, des chiffres décimaux et le caractère de soulignement ("_").

--to-package package

Stocke les fichiers .da pour un traitement ultérieur.

Utilisez cette option si vous avez des machines séparées pour la construction et les tests et que vous souhaitez effectuer la création du fichier .info sur la machine de construction. Pour ce faire, suivez ces étapes :

Sur la machine de test :


- exécutez le test
- exécutez lcov -c [-d directory] --to-package file
- copiez file sur la machine de construction

Sur la machine de construction :


- exécutez lcov -c --from-package file [-o et autres options]

Cela fonctionne pour les données de couverture du noyau et de l'espace utilisateur. Notez que vous devrez peut-être spécifier le chemin vers le répertoire de construction en utilisant -b avec --to-package ou --from-package. Notez également que les données du package doivent être converties en fichier .info avant de recompiler le programme, sinon elles deviendront invalides.

--version

Affiche le numéro de version, puis quitte.

-z
--zerocounters

Réinitialise tous les compteurs d'exécution à zéro.

Par défaut, essaie de réinitialiser les compteurs d'exécution du noyau. Utilisez l'option --directory pour réinitialiser tous les compteurs d'un programme en espace utilisateur.

Un seul parmi -z, -c, -a, -e, -r, -l, --diff ou --summary peut être spécifié à la fois.

--tempdir dirname

Écrit les données temporaires et intermédiaires dans le répertoire indiqué. Par défaut, c'est "/tmp".
