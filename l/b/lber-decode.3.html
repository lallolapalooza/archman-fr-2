LBER_DECODE(3) Manuel des fonctions de bibliothèque LBER_DECODE(3)

NOM

ber_get_next, ber_skip_tag, ber_peek_tag, ber_scanf, ber_get_int, ber_get_enum, ber_get_stringb, ber_get_stringa, ber_get_stringal, ber_get_stringbv, ber_get_null, ber_get_boolean, ber_get_bitstring, ber_first_element, ber_next_element - Routines de décodage de la bibliothèque simplifiée des règles d'encodage de base (LBER) d'OpenLDAP

BIBLIOTHÈQUE

OpenLDAP LBER (liblber, -llber)

SYNTAXE

#include <lber.h>

ber_tag_t ber_get_next(Sockbuf *sb, ber_len_t *len, BerElement *ber);

ber_tag_t ber_skip_tag(BerElement *ber, ber_len_t *len);

ber_tag_t ber_peek_tag(BerElement *ber, ber_len_t *len);

ber_tag_t ber_scanf(BerElement *ber, const char *fmt, ...);

ber_tag_t ber_get_int(BerElement *ber, ber_int_t *num);

ber_tag_t ber_get_enum(BerElement *ber, ber_int_t *num);

ber_tag_t ber_get_stringb(BerElement *ber, char *buf, ber_len_t *len);

ber_tag_t ber_get_stringa(BerElement *ber, char **buf);

ber_tag_t ber_get_stringal(BerElement *ber, struct berval **bv);

ber_tag_t ber_get_stringbv(BerElement *ber, struct berval *bv, int alloc);

ber_tag_t ber_get_null(BerElement *ber);

ber_tag_t ber_get_boolean(BerElement *ber, ber_int_t *bool);

ber_tag_t ber_get_bitstringa(BerElement *ber, char **buf, ber_len_t *blen);

ber_tag_t ber_first_element(BerElement *ber, ber_len_t *len, char **cookie);

ber_tag_t ber_next_element(BerElement *ber, ber_len_t *len, const char *cookie);

DESCRIPTION

Ces routines fournissent une interface de sous-routine à une implémentation simplifiée des règles d'encodage de base (BER) d'ASN.1. La version de BER que ces routines prennent en charge est celle définie pour le protocole LDAP. Les règles d'encodage sont les mêmes que BER, à la différence que seules les longueurs de forme définie sont utilisées, et que les chaînes de bits et les chaînes d'octets sont toujours encodées sous forme primitive. Cette page de manuel décrit les routines de décodage de la bibliothèque lber. Consultez lber-encode(3) pour plus de détails sur les routines d'encodage correspondantes. Consultez lber-types(3) pour des informations sur les types, les allocateurs et les désallocateurs.

Normalement, les seules routines qui doivent être appelées par une application sont ber_get_next() pour obtenir le prochain élément BER et ber_scanf() pour effectuer le décodage réel. Dans certains cas, ber_peek_tag() peut également devoir être appelée dans une utilisation normale. Les autres routines sont fournies pour les applications qui nécessitent plus de contrôle que ce que ber_scanf() fournit. En général, ces routines renvoient la balise de l'élément décodé, ou LBER_ERROR si une erreur s'est produite.

La routine ber_get_next() est utilisée pour lire le prochain élément BER à partir du Sockbuf donné, sb. Elle retire et renvoie la balise principale, retire et renvoie la longueur de l'élément entier dans len, et configure ber pour les appels ultérieurs à ber_scanf() et autres pour décoder l'élément. Consultez lber-sockbuf(3) pour plus de détails sur l'implémentation Sockbuf du paramètre sb.

La routine ber_scanf() est utilisée pour décoder un élément BER de manière très similaire à la façon dont fonctionne scanf(3). Elle lit à partir de ber, un pointeur vers un BerElement tel que renvoyé par ber_get_next(), interprète les octets selon la chaîne de format fmt, et stocke les résultats dans ses arguments supplémentaires. La chaîne de format contient des spécifications de conversion qui sont utilisées pour diriger l'interprétation de l'élément BER. La chaîne de format peut contenir les caractères suivants.

a
Chaîne d'octets. Un char ** doit être fourni. La mémoire est allouée, remplie avec le contenu de la chaîne d'octets, terminée par un caractère nul, et renvoyée dans le paramètre. L'appelant doit libérer la chaîne renvoyée en utilisant ber_memfree().
A
Chaîne d'octets. Une variante de "a". Un char ** doit être fourni. La mémoire est allouée, remplie avec le contenu de la chaîne d'octets, terminée par un caractère nul, et renvoyée dans le paramètre, sauf si une chaîne de longueur nulle en résulterait ; dans ce cas, l'argument est mis à NULL. L'appelant doit libérer la chaîne renvoyée en utilisant ber_memfree().
s
Chaîne d'octets. Un tampon char * doit être fourni, suivi d'un pointeur vers un ber_len_t initialisé à la taille du tampon. Au retour, la chaîne d'octets terminée par un caractère nul est placée dans le tampon, et le ber_len_t est défini sur la taille réelle de la chaîne d'octets.
O
Chaîne d'octets. Un struct ber_val ** doit être fourni, qui au retour pointe vers une structure berval allouée dynamiquement contenant la chaîne d'octets et sa longueur. L'appelant doit libérer la structure renvoyée en utilisant ber_bvfree().
o
Chaîne d'octets. Un struct ber_val * doit être fourni, qui au retour contient la chaîne d'octets allouée dynamiquement et sa longueur. L'appelant doit libérer la chaîne d'octets renvoyée en utilisant ber_memfree().
m
Chaîne d'octets. Un struct ber_val * doit être fourni, qui au retour contient la chaîne d'octets et sa longueur. La chaîne réside dans la mémoire attribuée à BerElement, et ne doit pas être libérée par l'appelant.
b
Booléen. Un pointeur vers un ber_int_t doit être fourni.
e
Énumération. Un pointeur vers un ber_int_t doit être fourni.
i
Entier. Un pointeur vers un ber_int_t doit être fourni.
B
Chaîne de bits. Un char ** doit être fourni qui pointera vers les bits alloués dynamiquement, suivi d'un ber_len_t *, qui pointera vers la longueur (en bits) de la chaîne de bits renvoyée.
n
Null. Aucun paramètre n'est requis. L'élément est simplement ignoré s'il est reconnu.
v
Séquence de chaînes d'octets. Un char *** doit être fourni, qui au retour pointera vers un tableau alloué dynamiquement et terminé par un caractère nul de chaînes de caractères contenant les chaînes d'octets. NULL est renvoyé si la séquence est vide. L'appelant doit libérer le tableau renvoyé et les chaînes d'octets en utilisant ber_memvfree().
V
Séquence de chaînes d'octets avec longueurs. Un struct berval *** doit être fourni, qui au retour pointera vers un tableau alloué dynamiquement et terminé par un caractère nul de pointeurs struct berval contenant les chaînes d'octets et leurs longueurs. NULL est renvoyé si la séquence est vide. L'appelant doit libérer les structures renvoyées en utilisant ber_bvecfree().
W
Séquence de chaînes d'octets avec longueurs. Un BerVarray * doit être fourni, qui au retour pointera vers un tableau alloué dynamiquement de struct berval contenant les chaînes d'octets et leurs longueurs. Le tableau est terminé par une struct berval avec un pointeur de chaîne bv_val NULL.
M
Séquence de chaînes d'octets avec longueurs. C'est une forme généralisée des trois formats précédents. Un void ** (ptr) doit être fourni, suivi d'un ber_len_t * (len) et d'un ber_len_t (off). Au retour, (ptr) pointera vers un tableau alloué dynamiquement dont tous les éléments ont la taille (*len). Une struct berval sera remplie à partir du décalage (off) dans chaque élément. Les chaînes de chaque struct berval résident dans la mémoire attribuée à BerElement et ne doivent pas être libérées par l'appelant. Le tableau est terminé par une struct berval avec un pointeur de chaîne NU

Lorsque la fonction ber_scanf() rencontre une balise dans la chaîne de format qui ne correspond pas à l'élément BER en cours, elle renvoie la balise de l'élément qu'elle a rencontrée et ne modifie aucun des arguments passés. Si une erreur survient pendant le décodage, elle renvoie LBER_ERROR.

La routine ber_skip_tag() saute la balise suivante et sa longueur du BerElement. Elle est généralement utilisée lorsque l'application souhaite ignorer un élément.

La routine ber_peek_tag() examine la balise suivante et sa longueur du BerElement sans les retirer. Elle est utile lorsque l'application a besoin de déterminer le type d'un élément avant de décider de le décoder ou de l'ignorer.

Les routines ber_get_int(), ber_get_enum(), ber_get_stringb(), ber_get_stringa(), ber_get_stringal(), ber_get_stringbv(), ber_get_null(), ber_get_boolean() et ber_get_bitstringa() sont des fonctions de décodage plus spécifiques qui peuvent être appelées directement par l'application.

Les routines ber_first_element() et ber_next_element() sont utilisées pour itérer sur les éléments d'une séquence BER. ber_first_element() renvoie la balise et la longueur du premier élément de la séquence, et initialise un "cookie" pour les appels ultérieurs à ber_next_element(). ber_next_element() renvoie la balise et la longueur de l'élément suivant dans la séquence, en utilisant le "cookie" fourni.

Note : Le décodage d'une chaîne peut renvoyer une mémoire allouée dynamiquement qui doit être libérée par l'appelant en utilisant les fonctions fournies par la bibliothèque lber (par exemple, ber_memfree(), ber_bvfree(), ber_memvfree(), ber_bvecfree(), ber_bvarray_free()).

VOIR AUSSI

lber-encode(3), lber-sockbuf(3), lber-types(3), scanf(3)

AUTEUR

Les auteurs originaux sont Kurt D. Zeilenga et Marcus Watts. La maintenance a été assurée par l'équipe OpenLDAP.

LL bv_val pointeur de chaîne. NULL est retourné si la séquence est vide. Le nombre d'éléments dans le tableau est également stocké dans (*len) au retour. L'appelant doit libérer le tableau retourné à l'aide de ber_memfree().
l
Longueur de l'élément suivant. Un pointeur vers un ber_len_t doit être fourni.
t
Tag de l'élément suivant. Un pointeur vers un ber_tag_t doit être fourni.
T
Ignorer l'élément et retourner son tag. Un pointeur vers un ber_tag_t doit être fourni.
x
Ignorer l'élément. L'élément suivant est ignoré.
{
Début de séquence. Aucun paramètre requis. Le tag et la longueur de la séquence initiale sont ignorés.
}
Fin de séquence. Aucun paramètre requis et aucune action n'est effectuée.
[
Début d'ensemble. Aucun paramètre requis. Le tag et la longueur de l'ensemble initial sont ignorés.
]
Fin d'ensemble. Aucun paramètre requis et aucune action n'est effectuée.

La routine ber_get_int() tente d'interpréter l'élément suivant comme un entier, retournant le résultat dans num. Le tag de ce qu'elle trouve est retourné en cas de succès, LBER_ERROR (-1) en cas d'échec.

La routine ber_get_stringb() est utilisée pour lire une chaîne d'octets dans un tampon préalloué. Le paramètre len doit être initialisé à la taille du tampon, et contiendra la longueur de la chaîne d'octets lue au retour. Le tampon doit être suffisamment grand pour contenir la valeur de la chaîne d'octets plus un octet NULL de terminaison.

La routine ber_get_stringa() est utilisée pour allouer dynamiquement de l'espace dans lequel une chaîne d'octets est lue. L'appelant doit libérer la chaîne retournée à l'aide de ber_memfree().

La routine ber_get_stringal() est utilisée pour allouer dynamiquement de l'espace dans lequel une chaîne d'octets et sa longueur sont lues. Elle prend un struct berval **, et retourne le résultat dans ce paramètre. L'appelant doit libérer la structure retournée à l'aide de ber_bvfree().

La routine ber_get_stringbv() est utilisée pour lire une chaîne d'octets et sa longueur dans la structure struct berval * fournie. Si le paramètre alloc est zéro, la chaîne résidera dans la mémoire attribuée à l'élément Ber, et ne doit pas être libérée par l'appelant. Si le paramètre alloc est non nul, la chaîne sera copiée dans un espace alloué dynamiquement qui doit être retourné à l'aide de ber_memfree().

La routine ber_get_null() est utilisée pour lire un élément NULL. Elle retourne le tag de l'élément qu'elle ignore.

La routine ber_get_boolean() est utilisée pour lire une valeur booléenne. Elle est appelée de la même manière que ber_get_int().

La routine ber_get_enum() est utilisée pour lire une valeur d'énumération. Elle est appelée de la même manière que ber_get_int().

La routine ber_get_bitstringa() est utilisée pour lire une valeur de chaîne de bits. Elle prend un char ** qui contiendra les bits alloués dynamiquement, suivi d'un ber_len_t *, qui pointera vers la longueur (en bits) de la chaîne de bits retournée. L'appelant doit libérer la chaîne retournée à l'aide de ber_memfree().

La routine ber_first_element() est utilisée pour retourner le tag et la longueur du premier élément d'un ensemble ou d'une séquence. Elle retourne également dans cookie un cookie magique qui doit être passé aux appels ultérieurs à ber_next_element(), qui retourne des informations similaires.

EXEMPLES

Supposons que la variable ber contienne un encodage BER léger de l'objet ASN.1 suivant :

      AlmostASearchRequest := SEQUENCE {
          baseObject      DistinguishedName,
          scope           ENUMERATED {
              baseObject    (0),
              singleLevel   (1),
              wholeSubtree  (2)
          },
          derefAliases    ENUMERATED {
              neverDerefaliases   (0),
              derefInSearching    (1),
              derefFindingBaseObj (2),
              alwaysDerefAliases  (3)
          },
          sizelimit       INTEGER (0 .. 65535),
          timelimit       INTEGER (0 .. 65535),
          attrsOnly       BOOLEAN,
          attributes      SEQUENCE OF AttributeType
      }

L'élément peut être décodé à l'aide de ber_scanf() comme suit.

      ber_int_t    scope, deref, size, time, attrsonly;
      char   *dn, **attrs;
      ber_tag_t tag;
      tag = ber_scanf( ber, "{aeeiib{v}}",
          &dn, &scope, &deref,
          &size, &time, &attrsonly, &attrs );
      if( tag == LBER_ERROR ) {
              /* erreur */
      } else {
              /* succès */
      }
      ber_memfree( dn );
      ber_memvfree( attrs );

ERREURS

Si une erreur survient pendant le décodage, ces routines retournent généralement LBER_ERROR ((ber_tag_t)-1).

NOTES

Les valeurs de retour de toutes ces fonctions sont déclarées dans le fichier d'en-tête <lber.h>. Certaines routines peuvent allouer dynamiquement de la mémoire qui doit être libérée par l'appelant à l'aide des routines de désallocation fournies.
