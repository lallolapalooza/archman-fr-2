LBER_SOCKBUF(3) Manuel des fonctions de bibliothèque LBER_SOCKBUF(3)

NOM

ber_sockbuf_alloc, ber_sockbuf_free, ber_sockbuf_ctrl, ber_sockbuf_add_io, ber_sockbuf_remove_io, Sockbuf_IO - Infrastructure I/O LBER d'OpenLDAP

BIBLIOTHÈQUE

LBER d'OpenLDAP (liblber, -llber)

SYNTAXE

#include <lber.h>

Sockbuf *ber_sockbuf_alloc( void );

void ber_sockbuf_free(Sockbuf *sb);

int ber_sockbuf_ctrl(Sockbuf *sb, int opt, void *arg);

int ber_sockbuf_add_io(Sockbuf *sb, Sockbuf_IO *sbio, int layer, void *arg);

int ber_sockbuf_remove_io(Sockbuf *sb, Sockbuf_IO *sbio, int layer);

typedef struct sockbuf_io_desc {
int sbiod_level;
Sockbuf *sbiod_sb;
Sockbuf_IO *sbiod_io;
void *sbiod_pvt;
struct sockbuf_io_desc *sbiod_next;
} Sockbuf_IO_Desc;
typedef struct sockbuf_io {
int (*sbi_setup)(Sockbuf_IO_Desc *sbiod, void *arg);
int (*sbi_remove)(Sockbuf_IO_Desc *sbiod);
int (*sbi_ctrl)(Sockbuf_IO_Desc *sbiod, int opt, void *arg);
ber_slen_t (*sbi_read)(Sockbuf_IO_Desc *sbiod, void *buf, ber_len_t len);
ber_slen_t (*sbi_write)(Sockbuf_IO_Desc *sbiod, void *buf, ber_len_t len);
int (*sbi_close)(Sockbuf_IO_Desc *sbiod);
} Sockbuf_IO;

DESCRIPTION

Ces routines sont utilisées pour gérer les opérations d'E/S de bas niveau effectuées par la bibliothèque Lightweight BER. Elles sont appelées implicitement par les autres bibliothèques et n'ont généralement pas besoin d'être appelées directement depuis les applications. Le framework d'E/S est modulaire et de nouvelles couches de transport peuvent être prises en charge en définissant de manière appropriée une structure Sockbuf_IO et en l'installant sur un Sockbuf existant. Les structures Sockbuf sont allouées et libérées par ber_sockbuf_alloc() et ber_sockbuf_free(), respectivement. La fonction ber_sockbuf_ctrl() est utilisée pour obtenir et définir des options relatives à un Sockbuf ou à une couche d'E/S spécifique du Sockbuf. Les fonctions ber_sockbuf_add_io() et ber_sockbuf_remove_io() sont utilisées pour ajouter et supprimer des couches d'E/S spécifiques sur un Sockbuf.

Les options pour ber_sockbuf_ctrl() incluent :

LBER_SB_OPT_HAS_IO
Prend un argument Sockbuf_IO * et renvoie 1 si le gestionnaire donné est installé sur le Sockbuf, sinon renvoie 0.
LBER_SB_OPT_GET_FD
Récupère le descripteur de fichier associé au Sockbuf ; arg doit être un ber_socket_t *. La valeur de retour sera 1 s'il y avait un descripteur valide, -1 sinon.
LBER_SB_OPT_SET_FD
Définit le descripteur de fichier du Sockbuf au descripteur pointé par arg ; arg doit être un ber_socket_t *. La valeur de retour sera toujours 1.
LBER_SB_OPT_SET_NONBLOCK
Active/désactive l'état non bloquant du descripteur de fichier associé au Sockbuf. arg doit être NULL pour désactiver et non-NULL pour activer l'état non bloquant. La valeur de retour sera 1 pour succès, -1 sinon.
LBER_SB_OPT_DRAIN
Vide (lit et ignore) toutes les entrées disponibles sur le Sockbuf. La valeur de retour sera 1.
LBER_SB_OPT_NEEDS_READ
Renvoie une valeur non nulle si des entrées attendent d'être lues.
LBER_SB_OPT_NEEDS_WRITE
Renvoie une valeur non nulle si le Sockbuf est prêt à être écrit.
LBER_SB_OPT_GET_MAX_INCOMING
Renvoie la taille maximale autorisée d'un message entrant ; arg doit être un ber_len_t *. La valeur de retour sera 1.
LBER_SB_OPT_SET_MAX_INCOMING
Définit la taille maximale autorisée d'un message entrant ; arg doit être un ber_len_t *. La valeur de retour sera 1.

Les options non présentes dans cette liste seront transmises à chaque gestionnaire Sockbuf_IO à tour de rôle jusqu'à ce que l'un d'eux les traite. Si l'option n'est pas gérée, ber_sockbuf_ctrl() renverra 0.

Plusieurs gestionnaires Sockbuf_IO peuvent être empilés en plusieurs couches pour fournir diverses fonctionnalités. Les couches actuellement définies incluent

LBER_SBIOD_LEVEL_PROVIDER
la couche la plus basse, parlant directement à un réseau
LBER_SBIOD_LEVEL_TRANSPORT
une couche intermédiaire
LBER_SBIOD_LEVEL_APPLICATION
une couche supérieure

Les gestionnaires Sockbuf_IO actuellement définis dans liblber incluent

ber_sockbuf_io_tcp
Le fournisseur par défaut orienté flux
ber_sockbuf_io_fd
Un fournisseur orienté flux pour les sockets IPC locaux
ber_sockbuf_io_dgram
Un fournisseur orienté datagramme. Ce gestionnaire n'est présent que si la bibliothèque liblber a été construite avec LDAP_CONNECTIONLESS défini.
ber_sockbuf_io_readahead
Une couche de mise en mémoire tampon, généralement utilisée avec un fournisseur de datagrammes pour masquer les sémantiques de datagramme des couches supérieures.
ber_sockbuf_io_debug
Un gestionnaire générique qui affiche des dumps hexadécimaux de tout le trafic. Ce gestionnaire peut être inséré plusieurs fois à des couches arbitraires pour montrer le flux de données entre d'autres gestionnaires.

Des gestionnaires supplémentaires peuvent être présents dans libldap si leur prise en charge a été activée :

ldap_pvt_sockbuf_io_sasl
Un gestionnaire de couche application pour l'encodage/décodage SASL.
sb_tls_sbio
Un gestionnaire de couche transport pour l'encodage/décodage SSL/TLS. Notez que ce gestionnaire est privé à la bibliothèque et n'est pas exposé dans l'API.

Les gestionnaires fournis sont tous instanciés implicitement par libldap, et les applications n'auront généralement pas besoin de les manipuler directement.
