GZIP(1) Manuel des commandes générales GZIP(1)

NOM

gzip, gunzip, zcat - compresser ou décompresser des fichiers

SYNTAXE

gzip [ -acdfhklLnNrtvV19 ] [-S suffixe] [ nom ... ]
gunzip [ -acfhklLnNrtvV ] [-S suffixe] [ nom ... ]
zcat [ -fhLV ] [ nom ... ]

DESCRIPTION

La commande gzip réduit la taille des fichiers nommés en utilisant le codage Lempel-Ziv (LZ77). Chaque fois que possible, chaque fichier est remplacé par un fichier portant l'extension .gz, tout en conservant les mêmes droits de propriété, ainsi que les dates et heures d'accès et de modification. (L'extension par défaut est z pour MSDOS, FAT OS/2, FAT Windows NT et Atari.) Si aucun fichier n'est spécifié, ou si un nom de fichier est "-", l'entrée standard est compressée vers la sortie standard. La commande gzip ne tente de compresser que les fichiers réguliers. En particulier, elle ignore les liens symboliques.

Si le nom du fichier compressé est trop long pour son système de fichiers, gzip le tronque. La commande gzip tente de tronquer uniquement les parties du nom de fichier plus longues que 3 caractères (une partie est délimitée par des points). Si le nom ne contient que de petites parties, les parties les plus longues sont tronquées. Par exemple, si les noms de fichiers sont limités à 14 caractères, gzip.msdos.exe est compressé en gzi.msd.exe.gz. Les noms ne sont pas tronqués sur les systèmes qui n'ont pas de limite de longueur de nom de fichier.

Par défaut, gzip conserve le nom de fichier original et l'horodatage dans le fichier compressé. Ceux-ci sont utilisés lors de la décompression du fichier avec l'option -N. Ceci est utile lorsque le nom du fichier compressé a été tronqué ou lorsque l'horodatage n'a pas été préservé après un transfert de fichier.

Les fichiers compressés peuvent être restaurés dans leur forme originale en utilisant gzip -d, gunzip ou zcat. Si le nom original sauvegardé dans le fichier compressé n'est pas approprié pour son système de fichiers, un nouveau nom est construit à partir du nom original pour le rendre valide.

gunzip prend une liste de fichiers dans sa ligne de commande et remplace chaque fichier dont le nom se termine par .gz, -gz, .z, -z, ou _z (insensible à la casse) et qui commence par le bon nombre magique, par un fichier décompressé sans l'extension originale. gunzip reconnaît également les extensions spéciales .tgz et .taz comme raccourcis pour .tar.gz et .tar.Z respectivement. Lors de la compression, gzip utilise l'extension .tgz si nécessaire au lieu de tronquer un fichier avec une extension .tar.

gunzip peut actuellement décompresser les fichiers créés par gzip, zip, compress, compress -H ou pack. La détection du format d'entrée est automatique. Lors de l'utilisation des deux premiers formats, gunzip vérifie une somme de contrôle CRC de 32 bits. Pour pack et gunzip vérifie la longueur décompressée. Le format standard compress n'a pas été conçu pour permettre des vérifications de cohérence. Cependant gunzip est parfois capable de détecter un fichier .Z corrompu. Si vous obtenez une erreur lors de la décompression d'un fichier .Z, ne supposez pas que le fichier .Z est correct simplement parce que l'utilitaire uncompress standard ne se plaint pas. Cela signifie généralement que l'utilitaire uncompress standard ne vérifie pas son entrée et génère volontiers des sorties incorrectes. Le format SCO compress -H (méthode de compression lzh) n'inclut pas de CRC mais permet également quelques vérifications de cohérence.

Les fichiers créés par zip ne peuvent être décompressés par gzip que s'ils contiennent un seul membre compressé avec la méthode « deflate ». Cette fonctionnalité est uniquement destinée à faciliter la conversion de fichiers tar.zip au format tar.gz. Pour extraire un fichier zip avec un seul membre, utilisez une commande comme 'gunzip <foo.zip' ou 'gunzip -S .zip foo.zip'. Pour extraire des fichiers zip avec plusieurs membres, utilisez unzip au lieu de gunzip.

La commande zcat est identique à gunzip -c. (Sur certains systèmes, zcat peut être installé sous le nom de gzcat pour préserver le lien original vers compress.) zcat décompresse soit une liste de fichiers dans la ligne de commande, soit son entrée standard et écrit les données décompressées sur la sortie standard. zcat décompressera les fichiers qui ont le bon nombre magique, qu'ils aient ou non un suffixe .gz.

La commande gzip utilise l'algorithme Lempel-Ziv utilisé dans zip et PKZIP. Le degré de compression obtenu dépend de la taille de l'entrée et de la distribution des sous-chaînes communes. Typiquement, le texte tel que le code source ou l'anglais est réduit de 60 à 70%. La compression est généralement bien meilleure que celle obtenue par LZW (utilisé dans compress), le codage de Huffman (utilisé dans pack), ou le codage de Huffman adaptatif (compact).

La compression est toujours effectuée, même si le fichier compressé est légèrement plus grand que l'original. L'expansion dans le pire des cas est de quelques octets pour l'en-tête du fichier gzip, plus 5 octets par bloc de 32 KiB, soit un taux d'expansion de 0,015% pour les fichiers volumineux. Le nombre réel de blocs de disque utilisés n'augmente presque jamais.

gzip préserve normalement le mode et l'horodatage de modification d'un fichier lors de la compression ou de la décompression. Si vous avez les privilèges appropriés, il préserve également le propriétaire et le groupe du fichier.

OPTIONS

-a --ascii
Mode texte ASCII : convertir les fins de ligne selon les conventions locales. Cette option n'est prise en charge que sur certains systèmes non-Unix. Pour MSDOS, CR LF est converti en LF lors de la compression, et LF est converti en CR LF lors de la décompression.
-c --stdout --to-stdout
Écrire la sortie sur la sortie standard ; laisser les fichiers originaux inchangés. S'il y a plusieurs fichiers d'entrée, la sortie consiste en une séquence de membres compressés indépendamment. Pour obtenir une meilleure compression, concaténez tous les fichiers d'entrée avant de les compresser.
-d --decompress --uncompress
Décompresser.
-f --force
Forcer la compression ou la décompression même si le fichier a plusieurs liens ou si le fichier correspondant existe déjà, ou si les données compressées sont lues depuis ou écrites vers un terminal. Si les données d'entrée ne sont pas dans un format reconnu par gzip, et si l'option --stdout est également donnée, copier les données d'entrée sans modification vers la sortie standard : faire en sorte que zcat se comporte comme cat. Si -f n'est pas donné, et lorsque l'on n'exécute pas en arrière-plan, gzip demande une confirmation pour écraser un fichier existant.
-h --help
Afficher un écran d'aide et quitter.
-k --keep
Conserver (ne pas supprimer) les fichiers d'entrée pendant la compression ou la décompression.
-l --list
Pour chaque fichier compressé, lister les champs suivants :


taille compressée : taille du fichier compressé
taille décompressée : taille du fichier décompressé
ratio : taux de compression (0,0% si inconnu)
nom_décompressé : nom du fichier décompressé

La taille décompressée est donnée comme -1 pour les fichiers qui ne sont pas au format gzip, comme les fichiers .Z compressés. Pour obtenir la taille décompressée d'un tel fichier, vous pouvez utiliser :


zcat fichier.Z | wc -c

En combinaison avec l'option --verbose, les champs suivants sont également affichés :


méthode : méthode de compression
crc : la somme de contrôle CRC 32 bits des données décompressées
date et heure : horodatage pour le fichier décompressé

Les méthodes de compression actuellement prises en charge sont deflate, compress, lzh (SCO compress -H) et pack. Le crc est donné comme ffffffff pour un fichier qui n'est pas au format gzip.

Avec --name, le nom décompressé, la date et l'heure sont ceux stockés dans le fichier compressé s'ils sont présents.

Avec --verbose, les totaux de taille et le taux de compression pour tous les fichiers sont également affichés, sauf si certaines tailles sont inconnues. Avec --quiet, les lignes de titre et de totaux ne sont pas affichées.

"L">-L --license
Affiche la licence gzip et quitte.
-n --no-name
Lors de la compression, ne sauvegarde pas par défaut le nom du fichier d'origine et l'horodatage. (Le nom d'origine est toujours sauvegardé si le nom a dû être tronqué.) Lors de la décompression, ne restaure pas le nom du fichier d'origine s'il est présent (supprime uniquement le gzip suffixe du nom du fichier compressé) et ne restaure pas l'horodatage d'origine s'il est présent (le copie depuis le fichier compressé). Cette option est la valeur par défaut lors de la décompression.
-N --name
Lors de la compression, sauvegarde toujours le nom du fichier d'origine, et sauvegarde la partie secondes de l'horodatage de modification d'origine si l'original est un fichier régulier et que son horodatage est au moins 1 (1970-01-01 00:00:01 UTC) et inférieur à 2**32 (2106-02-07 06:28:16 UTC, en supposant que les secondes intercalaires ne sont pas comptées) ; c'est la valeur par défaut. Lors de la décompression, restaure le nom de fichier et l'horodatage sauvegardés s'ils sont présents. Cette option est utile sur les systèmes qui ont une limite de longueur de nom de fichier ou lorsque l'horodatage a été perdu après un transfert de fichier.
-q --quiet
Supprime tous les avertissements.
-r --recursive
Parcourt la structure de répertoires récursivement. Si l'un des noms de fichier spécifiés sur la ligne de commande est un répertoire, gzip descendra dans le répertoire et compressera tous les fichiers qu'il y trouve (ou les décompressera dans le cas de gunzip ).
-S .suf --suffix .suf
Lors de la compression, utilise le suffixe .suf au lieu de .gz. Bien que tout suffixe non vide puisse être donné à condition qu'il ne contienne pas "/", les suffixes autres que .z et .gz devraient être évités pour ne pas causer de confusion lorsque les fichiers sont transférés vers d'autres systèmes.

Lors de la décompression, ajoute .suf au début de la liste des suffixes à essayer, lors de la dérivation d'un nom de fichier de sortie à partir d'un nom de fichier d'entrée.

--synchronous
Utilise une sortie synchrone. Avec cette option, gzip est moins susceptible de perdre des données lors d'un crash système, mais peut être considérablement plus lent.
-t --test
Teste. Vérifie l'intégrité du fichier compressé puis quitte.
-v --verbose
Verbeux. Affiche le nom et le pourcentage de réduction pour chaque fichier compressé ou décompressé.
-V --version
Version. Affiche le numéro de version et les options de compilation puis quitte.
-# --fast --best
Régule la vitesse de compression en utilisant le chiffre spécifié #, où -1 ou --fast indique la méthode de compression la plus rapide (moins de compression) et -9 ou --best indique la méthode de compression la plus lente (meilleure compression). Le niveau de compression par défaut est -6 (c'est-à-dire, biaisé vers une forte compression au détriment de la vitesse).
--rsyncable
Lorsque vous synchronisez un fichier compressé entre deux ordinateurs, cette option permet à rsync de transférer uniquement les fichiers qui ont été modifiés dans l'archive au lieu de l'archive entière. Normalement, après qu'une modification a été apportée à n'importe quel fichier de l'archive, l'algorithme de compression peut générer une nouvelle version de l'archive qui ne correspond pas à la version précédente de l'archive. Dans ce cas, rsync transfère la nouvelle version entière de l'archive vers l'ordinateur distant. Avec cette option, rsync peut transférer uniquement les fichiers modifiés ainsi qu'une petite quantité de métadonnées qui est requise pour mettre à jour la structure de l'archive dans la zone qui a été modifiée.

UTILISATION AVANCÉE

Plusieurs fichiers compressés peuvent être concaténés. Dans ce cas, gunzip extraira tous les membres à la fois. Par exemple :


gzip -c file1 > foo.gz
gzip -c file2 >> foo.gz

Puis


gunzip -c foo

est équivalent à


cat file1 file2

En cas de dommage à l'un des membres d'un fichier .gz, les autres membres peuvent toujours être récupérés (si le membre endommagé est supprimé). Cependant, vous pouvez obtenir une meilleure compression en compressant tous les membres à la fois :


cat file1 file2 | gzip > foo.gz

compresse mieux que


gzip -c file1 file2 > foo.gz

Si vous voulez recompresser des fichiers concaténés pour obtenir une meilleure compression, faites :


gzip -cd old.gz | gzip > new.gz

Si un fichier compressé se compose de plusieurs membres, la taille décompressée et le CRC rapportés par l'option --list ne s'appliquent qu'au dernier membre. Si vous avez besoin de la taille décompressée pour tous les membres, vous pouvez utiliser :


gzip -cd file.gz | wc -c

Si vous souhaitez créer un fichier d'archive unique avec plusieurs membres afin que les membres puissent ensuite être extraits indépendamment, utilisez un archiver tel que tar ou zip. GNU tar prend en charge l'option -z pour invoquer gzip de manière transparente. gzip est conçu comme un complément à tar, pas comme un remplacement.

ENVIRONNEMENT

La variable d'environnement GZIP peut contenir un ensemble d'options par défaut pour gzip. Ces options sont interprétées en premier et peuvent être remplacées par des paramètres explicites de la ligne de commande. Comme cela peut causer des problèmes lors de l'utilisation de scripts, cette fonctionnalité n'est prise en charge que pour --rsyncable, --synchronous, et des options comme -9 qui définissent le niveau de compression ; toute autre option ou opérande dans GZIP est silencieusement ignorée.

Vous pouvez utiliser un alias ou un script à la place. Par exemple, au lieu de définir GZIP="-9" dans l'environnement, si gzip est dans le répertoire /usr/bin vous pouvez préfixer $HOME/bin à votre PATH et créer un script exécutable $HOME/bin/gzip contenant ce qui suit :


#! /bin/sh
export PATH=/usr/bin
exec gzip -9 "$@"

DIAGNOSTICS

Le code de sortie est normalement 0 ; si une erreur se produit, le code de sortie est 1. Si un avertissement se produit, le code de sortie est 2.

Usage: gzip [-cdfhklLnNrtvV19] [-S suffix] [file ...]
Des options invalides ont été spécifiées sur la ligne de commande.
file: not in gzip format
Le fichier spécifié à gunzip n'a pas été compressé.
file: Corrupt input.
Utilisez zcat pour récupérer certaines données. Le fichier compressé a été endommagé. Les données jusqu'au point de défaillance peuvent être récupérées en utilisant


zcat file > recover

file: compressed with xx bits, can only handle yy bits
Le fichier a été compressé (avec LZW) par un programme qui pouvait gérer plus de bits que le code de décompression sur cette machine. Recomprimez le fichier avec gzip, qui compresse mieux et utilise moins de mémoire.
file: already has .gz suffix -- unchanged
Le fichier est supposé être déjà compressé. Renommez le fichier et réessayez.
file already exists; do you wish to overwrite (y or n)?
Répondez "y" si vous voulez que le fichier de sortie soit remplacé ; "n" sinon.
gunzip: corrupt input
Une violation SIGSEGV a été détectée, ce qui signifie généralement que le fichier d'entrée a été corrompu.
xx.x% Pourcentage de l'entrée économisé par la compression.
(Pertinent uniquement pour -v et -l.)
-- not a regular file or directory: ignored
Lorsque le fichier d'entrée n'est pas un fichier régulier ou un répertoire (par exemple, un lien symbolique, un socket, un FIFO, un fichier de périphérique), il est laissé inchangé.
-- has xx other links: unchanged
Le fichier d'entrée a des liens ; il est laissé inchangé. Voir ln(1) pour plus d'informations. Utilisez l'indicateur -f pour forcer la compression des fichiers à liens multiples.

AVERTISSEMENTS

Lors de l'écriture de données compressées sur une bande, il est généralement nécessaire de compléter la sortie avec des zéros jusqu'à une limite de bloc. Lorsque les données sont lues et que le bloc entier est passé à gunzip pour la décompression, gunzip détecte qu'il y a des données résiduelles après les données compressées et émet un avertissement par défaut. Vous pouvez utiliser l'option --quiet pour supprimer l'avertissement.

BUGS

Dans quelques rares cas, l'option --best donne une compression moins bonne que le niveau de compression par défaut (-6). Sur certains fichiers très redondants, compress compresse mieux que gzip.
