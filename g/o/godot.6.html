NOM

godot - moteur de jeu 2D et 3D multiplateforme avec un éditeur riche en fonctionnalités

SYNOPSIS

godot [options] [chemin vers la scène ou le fichier 'project.godot']

DESCRIPTION

Godot Engine est un moteur de jeu 2D et 3D multiplateforme avancé et riche en fonctionnalités.
Il fournit un ensemble énorme d'outils courants, afin que vous puissiez vous concentrer sur la création de votre jeu sans réinventer la roue.

Options générales :

-h, --help
Afficher ce message d'aide.
--version
Afficher la chaîne de version.
-v, --verbose
Utiliser le mode verbeux de la sortie standard.
--quiet
Mode silencieux, supprime les messages de la sortie standard. Les erreurs sont toujours affichées.

Options d'exécution :

-e, --editor
Démarrer l'éditeur au lieu d'exécuter la scène.
-p, --project-manager
Démarrer le gestionnaire de projet, même si un projet est détecté automatiquement.
-q, --quit
Quitter après la première itération.
-l, --language <locale>
Utiliser une locale spécifique (<locale> étant un code de deux lettres).
--path <directory>
Chemin vers un projet (<directory> doit contenir un fichier 'project.godot').
-u, --upwards
Scanner les dossiers vers le haut à la recherche du fichier project.godot.
--main-pack <file>
Chemin vers un fichier pack (.pck) à charger.
--render-thread <mode>
Mode du thread de rendu ('unsafe', 'safe', 'separate').
--remote-fs <address>
Système de fichiers distant (adresse <host/IP>[:<port>]).
--remote-fs-password <password>
Mot de passe pour le système de fichiers distant.
--audio-driver <driver>
Pilote audio ('PulseAudio', 'ALSA', 'Dummy').
--audio-output-latency <ms>
Remplacer la latence de sortie audio en millisecondes (par défaut 15 ms). Des valeurs plus basses rendent la lecture du son plus réactive mais augmentent l'utilisation du CPU, et peuvent entraîner des craquements audio si le CPU ne suit pas.
--video-driver <driver>
Pilote vidéo ('Vulkan', 'GLES2').

Options d'affichage :

-f, --fullscreen
Demander le mode plein écran.
-m, --maximized
Demander une fenêtre maximisée.
-w, --windowed
Demander le mode fenêtré.
-t, --always-on-top
Demander une fenêtre toujours au premier plan.
--resolution <W>x<H>
Demander la résolution de la fenêtre.
--position <X>,<Y>
Demander la position de la fenêtre.
--low-dpi
Forcer le mode faible DPI (macOS et Windows uniquement).
--no-window
Désactiver la création de fenêtre (Windows uniquement). Utile en conjonction avec --script.

Options de débogage :

-d, --debug
Déboguer (débogueur local de la sortie standard).
-b, --breakpoints
Liste de points d'arrêt sous forme de paires source::ligne séparées par des virgules, sans espaces (utilisez %20 à la place).
--profiling
Activer le profilage dans le débogueur de script.
--remote-debug <address>
Débogage distant (adresse <host/IP>:<port>).
--debug-collisions
Afficher les formes de collision lors de l'exécution de la scène.
--debug-navigation
Afficher les polygones de navigation lors de l'exécution de la scène.
--max-fps <fps>
Définir un nombre maximal de frames par seconde rendues (peut être utilisé pour limiter la consommation d'énergie). Une valeur de 0 donne une fréquence d'images illimitée.
--frame-delay <ms>
Simuler une charge CPU élevée (délayer chaque frame de <ms> millisecondes). Ne pas utiliser comme limiteur de FPS ; utilisez plutôt --max-fps.
--time-scale <scale>
Forcer l'échelle de temps (des valeurs plus élevées sont plus rapides, 1.0 est la vitesse normale).
--disable-render-loop
Désactiver la boucle de rendu afin que le rendu n'ait lieu que lorsqu'il est explicitement appelé depuis un script.
--disable-crash-handler
Désactiver le gestionnaire de plantage lorsque le code de la plateforme le prend en charge.
--fixed-fps <fps>
Forcer un nombre fixe de frames par seconde. Ce paramètre désactive la synchronisation en temps réel.
--print-fps
Afficher les frames par seconde sur la sortie standard.

Outils autonomes :

-s, --script <script>
Exécuter un script.
--check-only
Analyser uniquement les erreurs et quitter (à utiliser avec --script).
--export-release <preset> <path>
Exporter le projet en mode release en utilisant le préréglage et le chemin de sortie donnés. Le nom du préréglage doit correspondre à celui défini dans export_presets.cfg.
<path> doit être absolu ou relatif au répertoire du projet, et inclure le nom de fichier du binaire (par ex. 'builds/game.exe').
Le répertoire cible doit exister.
--export-debug <preset> <path>
Exporter le projet en mode debug en utilisant le préréglage et le chemin de sortie donnés. Le nom du préréglage doit correspondre à celui défini dans export_presets.cfg.
<path> doit être absolu ou relatif au répertoire du projet, et inclure le nom de fichier du binaire (par ex. 'builds/game.exe').
Le répertoire cible doit exister.
--export-pack <preset> <path>
Exporter uniquement les données du projet en utilisant le préréglage et le chemin de sortie donnés. L'extension de <path> détermine s'il sera au format PCK ou ZIP.
--doctool <path>
Exporter la référence de l'API du moteur au format XML vers le <path> donné, en fusionnant si des fichiers existants sont trouvés.
--no-docbase
Interdire l'exportation des types de base (utilisé avec --doctool).
--build-solutions
Construire les solutions de script (par ex. pour les projets C#). Implique --editor et nécessite un projet valide à éditer.
--dump-gdextension-interface
Générer le fichier d'en-tête GDExtension 'gdextension_interface.h' dans le dossier courant. Ce fichier est le fichier de base requis pour implémenter une
GDExtension.
--dump-extension-
api
Génère un dump JSON de l'API Godot pour les bindings GDExtension nommé 'extension_api.json' dans le dossier
courant.
--test <t
est>

'physics', 'physics_2d', 'render', '
