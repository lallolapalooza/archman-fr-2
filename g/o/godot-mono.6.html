NOM

godot - moteur de jeu 2D et 3D multiplateforme avec un éditeur riche en fonctionnalités

SYNOPSIS

godot [options] [chemin vers la scène ou le fichier 'project.godot']

DESCRIPTION

Godot Engine est un moteur de jeu 2D et 3D multiplateforme avancé et riche en fonctionnalités.
Il fournit un vaste ensemble d'outils courants, afin que vous puissiez vous concentrer sur la création de votre jeu sans réinventer la roue.

Options générales :

-h, --help
Afficher ce message d'aide.
--version
Afficher la chaîne de version.
-v, --verbose
Utiliser le mode stdout verbeux.
--quiet
Mode silencieux, supprime les messages stdout. Les erreurs sont toujours affichées.

Options d'exécution :

-e, --editor
Démarrer l'éditeur au lieu d'exécuter la scène.
-p, --project-manager
Démarrer le gestionnaire de projet, même si un projet est détecté automatiquement.
-q, --quit
Quitter après la première itération.
-l, --language <locale>
Utiliser une locale spécifique (<locale> étant un code de deux lettres).
--path <directory>
Chemin vers un projet (<directory> doit contenir un fichier 'project.godot').
-u, --upwards
Scanner les dossiers vers le haut à la recherche du fichier project.godot.
--main-pack <file>
Chemin vers un fichier pack (.pck) à charger.
--render-thread <mode>
Mode du thread de rendu ('unsafe', 'safe', 'separate').
--remote-fs <address>
Système de fichiers distant (adresse <host/IP>[:<port>]).
--remote-fs-password <password>
Mot de passe pour le système de fichiers distant.
--audio-driver <driver>
Pilote audio ('PulseAudio', 'ALSA', 'Dummy').
--audio-output-latency <ms>
Remplacer la latence de sortie audio en millisecondes (par défaut 15 ms). Des valeurs plus basses rendent la lecture sonore plus réactive mais augmentent l'utilisation du CPU, et peuvent entraîner des craquements audio si le CPU ne suit pas.
--video-driver <driver>
Pilote vidéo ('Vulkan', 'GLES2').

Options d'affichage :

-f, --fullscreen
Demander le mode plein écran.
-m, --maximized
Demander une fenêtre maximisée.
-w, --windowed
Demander le mode fenêtré.
-t, --always-on-top
Demander une fenêtre toujours au premier plan.
--resolution <W>x<H>
Demander une résolution de fenêtre.
--position <X>,<Y>
Demander une position de fenêtre.
--low-dpi
Forcer le mode bas DPI (macOS et Windows uniquement).
--no-window
Désactiver la création de fenêtre (Windows uniquement). Utile en conjonction avec --script.

Options de débogage :

-d, --debug
Déboguer (débogueur stdout local).
-b, --breakpoints
Liste de points d'arrêt sous forme de paires source::ligne séparées par des virgules, sans espaces (utilisez %20 à la place).
--profiling
Activer le profilage dans le débogueur de script.
--remote-debug <address>
Débogage distant (adresse <host/IP>:<port>).
--debug-collisions
Afficher les formes de collision lors de l'exécution de la scène.
--debug-navigation
Afficher les polygones de navigation lors de l'exécution de la scène.
--max-fps <fps>
Définir un nombre maximal de frames par seconde rendues (peut être utilisé pour limiter la consommation d'énergie). Une valeur de 0 donne une fréquence d'images illimitée.
--frame-delay <ms>
Simuler une charge CPU élevée (délayer chaque frame de <ms> millisecondes). Ne pas utiliser comme limiteur de FPS ; utilisez plutôt --max-fps.
--time-scale <scale>
Forcer l'échelle de temps (les valeurs plus élevées sont plus rapides, 1.0 est la vitesse normale).
--disable-render-loop
Désactiver la boucle de rendu afin que le rendu n'ait lieu que lorsqu'il est explicitement appelé depuis un script.
--disable-crash-handler
Désactiver le gestionnaire de plantage lorsque le code de la plateforme le prend en charge.
--fixed-fps <fps>
Forcer un nombre fixe de frames par seconde. Ce paramètre désactive la synchronisation en temps réel.
--print-fps
Afficher les frames par seconde sur stdout.

Outils autonomes :

-s, --script <script>
Exécuter un script.
--check-only
Analyser uniquement les erreurs et quitter (à utiliser avec --script).
--export-release <preset> <path>
Exporter le projet en mode release en utilisant le préréglage et le chemin de sortie donnés. Le nom du préréglage doit correspondre à celui défini dans export_presets.cfg.
<path> doit être absolu ou relatif au répertoire du projet, et inclure le nom de fichier du binaire (par ex. 'builds/game.exe').
Le répertoire cible doit exister.
--export-debug <preset> <path>
Exporter le projet en mode debug en utilisant le préréglage et le chemin de sortie donnés. Le nom du préréglage doit correspondre à celui défini dans export_presets.cfg.
<path> doit être absolu ou relatif au répertoire du projet, et inclure le nom de fichier du binaire (par ex. 'builds/game.exe').
Le répertoire cible doit exister.
--export-pack <preset> <path>
Exporter uniquement les données du projet en utilisant le préréglage et le chemin de sortie donnés. L'extension de <path> détermine s'il sera au format PCK ou ZIP.
--doctool <path>
Exporter la référence de l'API du moteur au format XML vers le <path> donné, en fusionnant si des fichiers existants sont trouvés.
--no-docbase
Interdire l'exportation des types de base (utilisé avec --doctool).
--build-solutions
Construire les solutions de script (par ex. pour les projets C#). Implique --editor et nécessite un projet valide à éditer.
--dump-gdextension-interface

NAME

godot-mono — 3D and 2D game engine

SYNOPSIS

godot --headless --path path
godot --editor
godot --project-dir dir
godot --script script [args...]
godot --check-only --script script
godot --build-templates
godot --dump-extension-api
godot --test test

DESCRIPTION

Godot is a cross-platform, free and open-source 2D and 3D game engine. It boasts a wide range of features, with a focus on letting you create whatever you want. Godot's scenes, nodes, and rich API make creating and iterating on your game feel smooth and efficient.

The godot-mono command provides a command-line interface to the Godot engine, allowing for various operations such as running projects in headless mode, executing scripts, and performing development-related tasks.

--headless
Run the engine in headless mode (without a graphical interface). This is useful for dedicated servers or automated tasks.
--path path
Set the project path. If not specified, the current directory is used.
--editor
Run the Godot editor.
--project-dir dir
Set the project directory. This is an alternative to using --path. If both are specified, --project-dir takes precedence.
--script script [args...]
Execute the specified script. Any additional arguments are passed to the script.
--check-only --script script
Check the specified script for errors without executing it.
--build-templates
Build export templates. This is typically used for distributing your game.
--dump-extension-api
Generate JSON dump of the Godot API for GDExtension bindings named 'extension_api.json' in the current folder. This file is the base file required to implement a GDExtension.
--dump-extension-api
Generate JSON dump of the Godot API for GDExtension bindings named 'extension_api.json' in the current folder.
--test test
Run a unit test ('string', 'math', 'physics', 'physics_2d', 'render', 'oa_hash_map', 'gui', 'shaderlang', 'gd_tokenizer', 'gd_parser', 'gd_compiler', 'gd_bytecode', 'ordered_hash_map', 'astar').

FILES

XDG_DATA_CONFIG/godot/ or ~/.config/godot/

User-specific configuration folder, contains persistent editor settings, script and text editor templates and projects metadata.
XDG_DATA_HOME/godot/ or ~/.local/share/godot/
Contains the default configuration and user data folders for Godot-made games (user:// path), as well as export templates.
XDG_DATA_CACHE/godot/ or ~/.cache/godot/
Cache folder for generated thumbnails and scene previews, as well as temporary location for downloads.
/usr/share/doc/godot/
Additional documentation files.
/usr/share/licenses/godot/
Detailed licensing information.
