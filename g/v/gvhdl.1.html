DESCRIPTIO

N

FreeHDL est une suite compilateur/simulateur pour le langage de description matérielle VHDL. Les standards VHDL'93 ainsi que VHDL'87 sont pris en

charge.

FreeHDL traduit les fichiers sources VHDL originaux en C++. Ensuite, le code source C++ peut être compilé et lié au noyau pour construire le programme de simulation. Le démarrage de l'exécutable généré simulera le modèle VHDL correspondant. Le processus de construction réel pour générer le simulateur à partir de la source VHDL est un processus complexe qui est géré par le script gv

hdl.

FICHIERS_VHDL est une liste de noms de fichiers sources VHDL qui doivent se terminer par .vhdl ou .vhd. Le premier nom de fichier VHDL détermine également le nom de l'exécutable du simulateur. C'est-à-dire que l'exécutable final sera nommé d'après le premier fichier VHDL sans l'extension .vhdl ou .vhd. Notez que les fichiers objets ainsi que le simulateur seront créés dans le répertoire

courant.

FICHIERS_OBJET spécifie une liste de fichiers objets qui sont liés à l'exécutable du simulateur. gvhdl considère tous les fichiers qui se terminent par .o comme des fichiers objets. Typiquement, ces fichiers objets sont

générés précédemment (à l'aide de l'option -c) à partir d
u code source VHDL lors d'une étape de compilation séparée.

OPTION

S
-L VHDL
LIB
Chemin vers le répertoire racine de la bibliothèque VHDL. Dans ce répertoire, le compilateur recherche un fichier nommé v2cc.libs. Le fichier de correspondance v2cc.libs traduit les noms d'unités de bibliothèque en répertoires. Notez que plus d'un VHDLLIB peut être
fourni.
-
g
Ajoute des informations de débogage à l'exécutable. Plus précisément, cette option associe le code machine généré aux lignes correspondantes dans les fichiers sources
VHDL.
-
G
Ajoute des informations de débogage à l'exécutable mais n'associe pas le code machine aux lignes de source VHDL. Cette option est en fait utilisée pour déboguer le code C++
généré.
-
c
Ne pas générer d'exécutable simulateur. En utilisant cette option, le compilateur traduit le code source VHDL en exécutables et les compile en code objet mais ne génère pas d'exécutable simulateur final. Cette option est particulièrement utile pour compiler des paquets
VHDL.

AME
Associe le code source VHDL à la bibliothèque VHDL LIBNAME. Par défaut, le nom de bibliothèque WORK est utilisé. Cette option est particulièrement importante si des composants VHDL provenant de plusieurs bibliothèques VHDL doivent être intégrés dans le simulateur. Notez que pour utiliser avec succès un composant VHDL provenant d'une autre bibliothèque que la bibliothèque de travail courante, les fichiers VHDL correspondants doivent être trouvés par le compilateur en utilisant les mécanismes décrits dans v2cc.libs. De plus, les composants doivent être compilés avec l'option appropriée -l

VARIABLES

D'ENVIRONNEMENT
V2CC_LIBRARY_P
ATH
La variable V2CC_LIBRARY_PATH se compose de noms de fichiers séparés par ":". En plus de la variabl
e d'environnement, vous pouvez utiliser l'option de ligne de commande "-L libdir" avec v2cc. Les ré
pertoires spécifiés avec "-L" sont ajoutés devant ceux spécifiés par V2CC_LIBRARY_PATH. Dans
le chemin de bibliothèque final, ils apparaissent dans le même ordre que sur la ligne de commande.

SOUS-ENSEMBLE VHDL PRIS EN

CHARGE

Actuellement, FreeHDL ne prend pas en charge l'ensemble du standard VHDL'93. La liste incomplète suivante donne un aperçu de ce qui n'est actuellement pas pris en charge

:

- L'association individuelle des formels de type composite n'est pas prise en

charge.

- Les variables partagées ne sont pas prises en

charge.

- Les attributs transaction, quiet, stable et delayed ne sont pas pris en

charge.

- Les attributs définis par l'utilisateur ne sont pas pris en

charge.

- Les groupes ne sont pas pris en

charge.

- Les affectations de signaux gardées ne sont pas prises en

charge.

- Les configurations ne sont pas prises en

charge.

- Actuellement, les

drivers ne peuvent
pas être désactivés.

EXEMPLE

S

Utilis

ez


gvhdl -c adder.

vhdl

pour construire un fichier objet pour adder.vhdl. Notez que adder.vhdl peut contenir plusieurs modèles

VHDL.


gvhdl adder.

vhdl

générera un simulateur pour le dernier modèle VHDL trouvé dans adder.vhdl. Cependant, dans ce cas, tous les composants VHDL nécessaires pour construire le simulateur doivent être inclus dans le fichier source

VHDL.


gvhdl top.vhdl adder.o

--libieee

génère un simulateur pour le dernier modèle VHDL trouvé dans top.vhdl en compilant tous les modèles dans top.vhdl et en liant (le fichier objet adder.o généré précédemment) et les bibliothèques standard IEEE à

l'exécutable.


gvhdl -c -l mylib adder.

vhdl

construira un fichier objet incluant tous les composants fournis dans adder.vhdl. Cependant, dans ce cas, les composants

seront associés à la bibliothèque mylib au lieu du nom de bibliothèque par défaut work. Notez que l'option -l n'affect
e que le code source C++ généré mais ne modifie pas l'emplacement où les fichiers objets ou les exécutables sont stockés.

COMMANDES DE

SIMULATION

Après le démarrage du simulateur, un bref résumé des commandes disponibles est affiché à l'écran

:


c <number> : execute cycles = exécute <number> cycles de simulation
n : next = exécute le cycle de simulation suivant
q : quit = quitte la simulation
r <time> : run = exécute la simulation pendant <time>
d : dump = sauvegarde les signaux
doff : dump off = arrête la sauvegarde des signaux
don : dump on = continue la sauvegarde des signaux
s : show = affiche les valeurs des signaux
dv : dump var = sauvegarde un signal de la liste des signaux
ds : dump show = affiche la liste des signaux sauvegardés
nds : number show = affiche le nombre de signaux sauvegardés
dc [-f <filename>] [-t <timescale> <time unit>] [-cfg <translation file>] [-q]
: configure le processus de

sauvegarde

Notez que les signaux sont sauvegardés dans un fichier (le nom de fichier par défaut est "wave.dmp") au format VCD. Ce format

de fichier devrait être accepté par chaque visualiseur de formes d'onde VCD. Le nom du fichier est défini sur "wave.dmp" mais
peut être changé en utilisant "dc -f <new_file_name>". Cependant, assurez-vous d'exécuter "dc -f ..." avant d'exécuter "d".

OPTIONS DE LIGNE DE COMMANDE DU

SIMULATEUR

La simulation peut être contrôlée via le paramètre de ligne de commande '-cmd "cmd1; cmd2; ..."' où 'cmd1', 'cmd2', ... sont des commandes de simulation comme décrit dans la section précédente. Notez que chaque commande doit être séparée par ';'. Par exemple,

exécuter


./top -cmd "d;run 1000 ns;q;

"

démarrera le programme de simulation 'top', sauvegardera tous les signaux et exécutera la simulati

on pendant 1000 ns. Enfin, la simulation est terminée. En fait, la dernière commande 'q;' est fac
ultative car le simulateur se termine automatiquement dès que la dernière commande a été exécutée.
