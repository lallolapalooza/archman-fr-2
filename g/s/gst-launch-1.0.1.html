NOM

gst-launch-1.0 - construit et exécute un pipeline GStreamer

SYNOPSIS

gst-launch-1.0 [OPTION...] DESCRIPTION-PIPELINE

DESCRIPTION

gst-launch-1.0 est un outil qui construit et exécute des pipelines GStreamer de base.

Sous sa forme simple, une DESCRIPTION-PIPELINE est une liste d'éléments séparés par des points d'exclamation (!). Des propriétés peuvent être ajoutées aux éléments, sous la forme propriété=valeur. Un « preset » peut également être défini en utilisant la @preset=<nom du preset> syntaxe.

Pour une description complète des DESCRIPTIONS-PIPELINE possibles, voir la section description du pipeline ci-dessous ou consulter la documentation de GStreamer.

Veuillez noter que gst-launch-1.0 est principalement un outil de débogage pour les développeurs et les utilisateurs. Vous ne devriez pas construire des applications par-dessus. Pour les applications, écrivez un petit script Python ou une application Rust (ou utilisez le langage de programmation de votre choix) et utilisez la fonction gst_parse_launch() de l'API GStreamer comme moyen facile de construire des pipelines à partir de descriptions de pipeline.

OPTIONS

gst-launch-1.0 accepte les options suivantes :

--help
Affiche l'aide, le synopsis et les DRAPEAUX disponibles
-v, --verbose
Affiche les informations d'état et les notifications de propriétés
-q, --quiet
N'affiche aucune information de progression
-m, --messages
Affiche les messages postés sur le bus du pipeline
-t, --tags
Affiche les tags (également connus sous le nom de métadonnées)
-e, --eos-on-shutdown
Force un événement EOS sur les sources avant d'arrêter le pipeline. C'est utile pour s'assurer que les multiplexeurs créent des fichiers lisibles lorsqu'un pipeline de multiplexage est arrêté de force via Ctrl-C (surtout dans le cas de `mp4mux` et `qtmux` où le fichier créé sera illisible si le fichier n'a pas été finalisé correctement).
-f, --no-fault
N'installe pas de gestionnaire de segmentation fault
--no-position
N'affiche pas la position actuelle du pipeline. Si cette option n'est pas spécifiée, la position sera affichée lorsque stdout est un TTY. Pour activer l'affichage de la position lorsque stdout n'est pas un TTY, utilisez l'option "--force-position".
--force-position
Permet d'afficher la position actuelle du pipeline même si stdout n'est pas un TTY. Cette option n'a aucun effet si l'option "--no-position" est spécifiée.

OPTIONS GSTREAMER

gst-launch-1.0 accepte également les options suivantes qui sont communes à toutes les applications GStreamer :

--gst-version
Affiche la chaîne de version de la bibliothèque principale de GStreamer.
--gst-fatal-warnings
Fait que GStreamer s'arrête si un message d'avertissement survient. Cela équivaut à définir la variable d'environnement G_DEBUG à 'fatal_warnings' (voir la section variables d'environnement ci-dessous pour plus d'informations).
--gst-debug=CHAÎNE
Une liste de paires nom_de_catégorie:niveau séparées par des virgules pour spécifier les niveaux de débogage pour chaque catégorie. Le niveau est compris entre 0 et 9, où 0 n'affichera aucun message et 9 affichera tous les messages. Le caractère générique * peut être utilisé pour correspondre aux noms de catégories. Notez que l'ordre des catégories et des niveaux est important ; les caractères génériques à la fin peuvent remplacer les niveaux définis précédemment. Les niveaux de journalisation sont : 1=ERROR, 2=WARNING, 3=FIXME, 4=INFO, 5=DEBUG, 6=LOG, 7=TRACE, 9=MEMDUMP. Depuis GStreamer 1.2, on peut également utiliser les noms de niveaux de débogage, par exemple --gst-debug=*sink:LOG. Une description complète des différents niveaux de débogage se trouve dans la documentation de l'API de la bibliothèque principale de GStreamer, dans la section « Running GStreamer Applications ».

Utilisez --gst-debug-help pour afficher les noms des catégories

Exemple : GST_CAT:5,GST_ELEMENT_*:3,oggdemux:5

--gst-debug-level=NIVEAU
Définit le seuil d'affichage des messages de débogage. Un niveau plus élevé affichera plus de messages. La plage utile est 0-9, avec 0 par défaut. Le niveau 6 (niveau LOG) affichera toutes les informations généralement nécessaires à des fins de débogage. Les niveaux supérieurs ne sont utiles que dans des cas très spécifiques. Voir ci-dessus pour la liste complète des niveaux.
--gst-debug-no-color
GStreamer affiche normalement les messages de débogage de manière à ce que les messages soient codés par couleur lorsqu'ils sont imprimés sur un terminal qui gère les séquences d'échappement ANSI. L'utilisation de cette option fait que GStreamer affiche les messages sans couleur. Définir la variable d'environnement GST_DEBUG_NO_COLOR produira le même effet.
--gst-debug-color-mode
GStreamer affiche normalement les messages de débogage de manière à ce que les messages soient codés par couleur lorsqu'ils sont imprimés sur un terminal qui gère les séquences d'échappement ANSI (sur *nix), ou utilise l'API console W32 pour colorer les messages imprimés dans une console (sur W32). L'utilisation de cette option fait que GStreamer affiche les messages sans couleur ('off' ou 'disable'), affiche les messages avec les couleurs par défaut ('on' ou 'auto'), ou affiche les messages en utilisant les séquences d'échappement ANSI pour la coloration ('unix'). Définir la variable d'environnement GST_DEBUG_COLOR_MODE produira le même effet.
--gst-debug-disable
Désactive le débogage.
--gst-debug-help
Affiche une liste des catégories de débogage disponibles et de leur niveau de débogage par défaut.
--gst-plugin-path=CHEMIN
Ajoute des répertoires séparés par ':' au chemin de recherche des plugins
--gst-plugin-load=PLUGINS
Précharge les plugins spécifiés dans une liste séparée par des virgules. Une autre manière de spécifier les plugins à précharger est d'utiliser la variable d'environnement GST_PLUGIN_PATH

DESCRIPTION DU PIPELINE

Un pipeline se compose d'éléments et de liens. Les éléments peuvent être placés dans des bacs de différents types. Les éléments, les liens et les bacs peuvent être spécifiés dans une description de pipeline dans n'importe quel ordre.

Éléments

TYPEÉLÉMENT [PROPRIÉTÉ1 ...]

Crée un élément de type TYPEÉLÉMENT et définit les PROPRIÉTÉS.

Propriétés

PROPRIÉTÉ=VALEUR ...

Définit la propriété à la valeur spécifiée. Vous pouvez utiliser gst-inspect-1.0(1) pour connaître les propriétés et les valeurs autorisées de différents éléments.
Les propriétés d'énumération peuvent être définies par nom, surnom ou valeur.

Presets

@preset=<nom du preset> ...

Définit le preset sur l'élément. Vous pouvez utiliser gst-inspect-1.0(1) pour savoir quels presets sont disponibles pour un élément donné.

Bacs

[TYPEBAC.] ( [PROPRIÉTÉ1 ...] DESCRIPTION-PIPELINE )

Spécifie qu'un bac de type TYPEBAC est créé et que les propriétés données sont définies. Chaque élément entre les accolades est placé dans le bac. Veuillez noter le point qui doit être utilisé après le TYPEBAC. Vous n'aurez presque jamais besoin de cette fonctionnalité ; elle n'est vraiment utile que pour les applications utilisant l'API gst_launch_parse() avec 'bin' comme type de bac. De cette manière, il est possible de construire des pipelines partiels au lieu d'un pipeline de premier niveau complet.

Liens

[[ÉLÉMENTSOURCE].[PAD1,...]] ! [[ÉLÉMENTSINK].[PAD1,...]] [[ÉLÉMENTSOURCE].[PAD1,...]] ! CAPS ! [[ÉLÉMENTSINK].[PAD1,...]] [[ÉLÉMENTSOURCE].[PAD1,...]] : [[ÉLÉMENTSINK].[PAD1,...]] [[ÉLÉMENTSOURCE].[PAD1,...]] : CAPS : [[ÉLÉMENTSINK].[PAD1,...]]

Lie l'élément nommé ÉLÉMENTSOURCE à l'élément nommé ÉLÉMENTSINK, en utilisant les caps spécifiées dans CAPS comme filtre. Les noms peuvent être définis sur les éléments avec la propriété name. Si le nom est omis, l'élément qui a été spécifié juste avant ou après le lien est utilisé. Cela fonctionne entre les bins. Si un nom de pad est donné, le lien est établi avec ces pads. Si aucun nom de pad n'est donné, toutes les possibilités sont essayées et un pad correspondant est utilisé. Si plusieurs noms de pads sont donnés, les deux côtés doivent avoir le même nombre de pads spécifiés et plusieurs liens sont établis dans l'ordre donné.
Ainsi, le lien le plus simple est un simple point d'exclamation, qui relie l'élément à sa gauche à l'élément à sa droite.
L'utilisation de l'opérateur : tente de relier tous les pads possibles entre les éléments

Caps

MEDIATYPE [, PROPERTY[, PROPERTY ...]]] [; CAPS[; CAPS ...]]

Crée une capacité avec le type de média donné et éventuellement avec les propriétés données. Le type de média peut être échappé en utilisant " ou '. Si vous voulez chaîner des caps, vous pouvez ajouter d'autres caps dans le même format par la suite.

Propriétés

NAME=[(TYPE)]VALUE
dans les listes et les plages : [(TYPE)]VALUE

Définit la propriété demandée dans les capacités. Le nom est une valeur alphanumérique et le type peut avoir les valeurs suivantes, insensibles à la casse :
- i ou int pour les valeurs ou plages d'entiers
- f ou float pour les valeurs ou plages de nombres à virgule flottante
- b, bool ou boolean pour les valeurs booléennes
- s, str ou string pour les chaînes de caractères
- fraction pour les fractions (framerate, pixel-aspect-ratio)
- l ou list pour les listes
Si aucun type n'a été donné, l'ordre suivant est essayé : entier, flottant, booléen, chaîne de caractères.
Les valeurs entières doivent être analysables par strtol(), les flottants par strtod(). Les valeurs FOURCC peuvent être des entiers ou des chaînes de caractères. Les valeurs booléennes sont (insensibles à la casse) yes, no, true ou false et peuvent, comme les chaînes de caractères, être échappées avec " ou '.
Les plages ont ce format : [ VALUE, VALUE ]
Les listes utilisent ce format : { VALUE [, VALUE ...] }

EXEMPLES DE PIPELINES

Les exemples ci-dessous supposent que vous disposez des plug-ins corrects. En général, "pulsesink" peut être remplacé par un autre plug-in de sortie audio tel que "alsasink", "osxaudiosink" ou "wasapisink".
De même, "xvimagesink" peut être remplacé par "d3dvideosink", "ximagesink", "glimagesink", ou "osxvideosink".
Gardez toutefois à l'esprit que différents sinks peuvent accepter différents formats et même le même sink peut accepter différents formats sur différentes machines, vous pourriez donc avoir besoin d'ajouter des éléments de conversion tels que audioconvert et audioresample (pour l'audio) ou videoconvertscale (pour la vidéo) avant le sink pour que les choses fonctionnent.

Lecture audio

Remarque : Pour la lecture audio/vidéo, il est préférable d'utiliser les éléments playbin3 ou uridecodebin3, ce ne sont que des exemples de pipelines.
Lecture du fichier musical mp3 "music.mp3" à l'aide d'un plug-in basé sur libmpg123 et sortie vers un périphérique Pulseaudio

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Lecture d'un fichier au format Ogg Vorbis

gst-launch-1.0 filesrc location=music.ogg ! oggdemux ! vorbisdec ! audioconvert ! audioresample ! pulsesink

Lecture d'un fichier mp3 ou d'un flux http utilisant GIO

gst-launch-1.0 giosrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! pulsesink

gst-launch-1.0 giosrc location=http://domain.com/music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Utilisation de GIO pour lire un fichier mp3 situé sur un serveur SMB

gst-launch-1.0 giosrc location=smb://computer/music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Conversion de format

Conversion d'un fichier musical mp3 en fichier Ogg Vorbis

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! vorbisenc ! oggmux ! filesink location=music.ogg

Conversion au format FLAC

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! flacenc ! filesink location=test.flac

Autres

Lecture d'un fichier .WAV contenant des données audio brutes (PCM).

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! audioresample ! pulsesink

Conversion d'un fichier .WAV contenant des données audio brutes en fichier Ogg Vorbis ou mp3

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! vorbisenc ! oggmux ! filesink location=music.ogg

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! lamemp3enc ! xingmux ! id3v2mux ! filesink location=music.mp3

Extraction de toutes les pistes d'un disque compact et conversion en un seul fichier mp3

gst-launch-1.0 cdparanoiasrc mode=continuous ! audioconvert ! lamemp3enc ! mpegaudioparse ! xingmux ! id3v2mux ! filesink location=cd.mp3

Extraction de la piste 5 du CD et conversion en un seul fichier mp3

gst-launch-1.0 cdparanoiasrc track=5 ! audioconvert ! lamemp3enc ! mpegaudioparse ! xingmux ! id3v2mux ! filesink location=track5.mp3

En utilisant gst-inspect-1.0(1), il est possible de découvrir des paramètres comme ceux ci-dessus pour cdparanoiasrc qui lui indiqueront d'extraire le CD entier ou seulement des pistes. Alternativement, vous pouvez utiliser une URI et gst-launch-1.0 trouvera un élément (tel que cdparanoia) qui prend en charge ce protocole pour vous, par exemple :
gst-launch-1.0 cdda://5 ! lamemp3enc vbr=new vbr-quality=6 ! filesink location=track5.mp3

Enregistrement du son depuis votre entrée audio et encodage dans un fichier ogg

gst-launch-1.0 pulsesrc ! audioconvert ! vorbisenc ! oggmux ! filesink location=input.ogg

Vidéo

Remarque : Pour la lecture audio/vidéo, il est préférable d'utiliser les éléments playbin3 ou uridecodebin3, ce ne sont que des exemples de pipelines.
Affichage uniquement de la partie vidéo d'un fichier vidéo MPEG-2 PS, sortie vers une fenêtre d'affichage X

gst-launch-1.0 filesrc location=JB_FF9_TheGravityOfLove.mpg ! mpegdemux ! mpegvideoparse ! mpeg2dec ! videoconvert ! xvimagesink

Affichage de la partie vidéo d'un fichier .vob (utilisé sur les DVD), sortie vers une fenêtre SDL

gst-launch-1.0 filesrc location=/flflfj.vob ! dvddemux ! mpegvideoparse ! mpeg2dec ! videoconvert ! sdlvideosink

Lecture des parties vidéo et audio d'un film MPEG

gst-launch-1.0 filesrc location=movie.mpg ! dvddemux name=demuxer demuxer. ! queue ! mpegvideoparse ! mpeg2dec ! videoconvert ! sdlvideosink demuxer. ! queue ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Lecture d'un film AVI avec un flux de sous-titres texte externe
Cet exemple montre également comment faire référence à des pads spécifiques par leur nom si un élément (ici : textoverlay) possède plusieurs pads d'entrée ou de sortie.

gst-launch-1.0 textoverlay name=overlay ! videoconvert ! videoscale ! autovideosink filesrc location=movie.avi ! decodebin3 ! videoconvert ! overlay.video_sink filesrc location=movie.srt ! subparse ! overlay.text_sink

Lecture d'un film AVI avec un flux de sous-titres texte externe en utilisant playbin3

gst-launch-1.0 playbin3 uri=file:///path/to/movie.avi suburi=file:///path/to/movie.srt

Streaming réseau

Diffusion vidéo en utilisant RTP et des éléments réseau.

Cette commande serait exécutée sur l'émetteur

gst-launch-1.0 v4l2src ! queue ! videoconvert ! x264enc tune=zerolatency key-int-max=15 ! video/x-h264,profile=main !rtph264pay pt=96 config-interval=-1 ! udpsink host=192.168.1.1 port=5000

Utilisez cette commande sur le récepteur

gst-launch-1.0 udpsrc port=5000 ! application/x-rtp, clock-rate=90000,payload=96 ! rtpjitterbuffer ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! xvimagesink

Diagnostic

Génère un flux nul et l'ignore (et affiche des détails).

gst-launch-1.0 -v fakesrc num-buffers=16 ! fakesink silent=false

Génère une tonalité sinusoïdale pure pour tester la sortie audio

gst-launch-1.0 audiotestsrc ! audioconvert ! audioresample ! pulsesink

Génère un motif de test familier pour tester la sortie vidéo

gst-launch-1.0 videotestsrc ! xvimagesink

gst-launch-1.0 videotestsrc ! ximagesink

Liaison automatique

Vous pouvez utiliser l'élément decodebin pour sélectionner automatiquement les bons éléments afin d'obtenir une pipeline fonctionnelle.

Lecture de tout format audio pris en charge

gst-launch-1.0 filesrc location=musicfile ! decodebin3 ! audioconvert ! audioresample ! pulsesink

Lecture de tout format vidéo pris en charge avec sortie vidéo et audio. Les threads sont utilisés automatiquement. Pour simplifier encore, vous pouvez utiliser l'élément playbin :

gst-launch-1.0 filesrc location=videofile ! decodebin3 name=decoder decoder. ! queue ! audioconvert ! audioresample ! pulsesink decoder. ! videoconvert ! xvimagesink

gst-launch-1.0 playbin3 uri=file:///home/joe/foo.avi

gst-launch-1.0 playbin3 uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm

Connexions filtrées

Ces exemples vous montrent comment utiliser des caps filtrés.

Affichage d'une image de test et utilisation du format vidéo YUY2 ou YV12 pour cela.

gst-launch-1.0 videotestsrc ! 'video/x-raw,format=YUY2;video/x-raw,format=YV12' ! xvimagesink

gst-launch-1.0 v4l2src ! image/jpeg ! queue ! decodebin3 ! videoconvert ! autovideosink

Enregistrement de l'audio et écriture dans un fichier .wav. Forçage de l'utilisation d'échantillons signés de 16 à 32 bits et d'une fréquence d'échantillonnage comprise entre 32 kHz et 64 kHz.

gst-launch-1.0 pulsesrc ! 'audio/x-raw,rate=[32000,64000],format={S16LE,S24LE,S32LE}' ! wavenc ! filesink location=recording.wav

VARIABLES D'ENVIRONNEMENT

GST_DEBUG
Liste séparée par des virgules des catégories de débogage et des niveaux (par exemple, GST_DEBUG=totem:4,typefind:5). '*' est autorisé comme joker dans la cat
s part of debug category names (e.g. GST_DEBUG=*sink:6,*audio*:6). Since 1.2.0 it is also possible to specify the log level by name (1=ERROR, 2=WARN, 3=FIXME, 4=INFO, 5=DEBUG, 6=LOG, 7=TRACE, 9=MEMDUMP) (e.g. GST_DEBUG=*audio*:LOG)
GST_DEBUG_NO_COLOR
When this environment variable is set, coloured debug output is disabled.
GST_DEBUG_DUMP_DOT_DIR
When set to a filesystem path, store 'dot' files of pipeline graphs there. These can then later be converted into an image using the 'dot' utility from the graphviz set of tools, like this: dot foo.dot -Tsvg -o foo.svg (png or jpg are also possible as output format). There is also a utility called 'xdot' which allows you to view the .dot file directly without converting it first.
When the pipeline changes state through NULL to PLAYING and back to NULL, a dot file is generated on each state change. To write a snapshot of the pipeline state, send a SIGHUP to the process or use the pipeline_snapshot tracer from the GStreamer Rust plugins.
GST_REGISTRY
Path of the plugin registry file. Default is ~/.cache/gstreamer-1.0/registry-CPU.bin where CPU is the machine/cpu type GStreamer was compiled for, e.g. 'x86_64', etc. (check the output of "uname -i" and "uname -m" for details).
GST_REGISTRY_UPDATE
Set to "no" to force GStreamer to assume that no plugins have changed, been added or been removed. This will make GStreamer skip the initial check whether a rebuild of the registry cache is required or not. This may be useful in embedded environments where the installed plugins never change. Do not use this option in any other setup.
GST_PLUGIN_PATH
Specifies a list of directories to scan for additional plugins. These take precedence over the system plugins.
GST_PLUGIN_SYSTEM_PATH
Specifies a list of plugins that are always loaded by default. If not set, this defaults to the system-installed path, and the plugins installed in the user's home directory
GST_DEBUG_FILE
Set this variable to a file path to redirect all GStreamer debug messages to this file. If left unset, debug messages will be output to the standard error output.
ORC_CODE
Useful Orc environment variable. Set ORC_CODE=debug to enable debuggers such as gdb to create useful backtraces from Orc-generated code. Set ORC_CODE=backup or ORC_CODE=emulate if you suspect Orc's SIMD code generator is producing incorrect code. (Quite a few important GStreamer plugins like videotestsrc, audioconvert or audioresample use Orc).
G_DEBUG
Useful GLib environment variable. Set G_DEBUG=fatal_warnings to make GStreamer programs abort when a critical warning such as an assertion failure occurs. This is useful if you want to find out which part of the code caused that warning to be triggered and under what circumstances. Simply set G_DEBUG as mentioned above and run the program in gdb (or let it core dump). Then get a stack trace in the usual way.

FILES

~/.cache/gstreamer-1.0/registry-*.bin
The plugin cache; can be deleted at any time, will be re-created automatically when it does not exist yet or plugins change. Based on XDG_CACHE_DIR, so may be in a different location than the one suggested.
