NOM

gssproxy.conf - Fichier de configuration du démon GssProxy

DESCRIPTION

Directives de configuration optionnelles pour le démon gssproxy.

Les fichiers de configuration GSS-Proxy sont des fichiers de configuration classiques de style ini. Chaque option consiste en une paire clé = valeur. Tous les caractères situés après '#' seront traités comme des commentaires et ignorés. Les paramètres booléens acceptent "1", "true", "yes" et "on" comme valeurs positives. Toutes les autres valeurs seront considérées comme des valeurs négatives.

Les fichiers de configuration GSS-Proxy doivent soit être nommés "gssproxy.conf", soit être de la forme "##-foo.conf" (c'est-à-dire, commencer par deux chiffres suivis d'un trait d'union, et se terminer par ".conf"). Les fichiers ne respectant pas ce format seront ignorés à moins d'être spécifiquement demandés par le biais des paramètres de la ligne de commande. Au sein d'un même fichier, les valeurs ou sections dupliquées seront fusionnées. Entre plusieurs fichiers, les doublons généreront un avertissement, et la première valeur rencontrée aura la priorité (c'est-à-dire, il n'y a pas de fusion).

SECTIONS

Une section dans un fichier de configuration GSS-Proxy est identifiée par le nom de section entre crochets ([nom_section]).

Il existe une section spéciale pour les paramètres globaux de gssproxy, appelée [gssproxy].

Les services tels que nfs, apache, ssh, etc. sont représentés par des sections comme [service/nfs], [service/apache], etc. et sont identifiés par le paramètre "euid" (voir ci-dessous).

SUBSTITUTIONS DE VARIABLES

Les paramètres de type chaîne de caractères peuvent contenir des motifs de substitution. Cela permet à gssproxy de gérer plus facilement les motifs pour l'emplacement de stockage des keytabs ou des caches de crédentials.

Les motifs pris en charge sont :

%U

se substitue à l'uid numérique de l'utilisateur (par exemple, 123)

%u

se substitue au nom d'utilisateur (par exemple, jean).

OPTIONS

gssproxy prend en charge les options suivantes :

allow_any_uid (booléen)

Autorise tout processus de n'importe quel utilisateur à utiliser ce service.

Notez que sans une option de socket personnalisée, cette option peut amener une définition de service à masquer l'accès aux services suivants. Pour éviter les problèmes, modifiez l'ordre des services dans votre fichier de configuration de sorte que les services avec allow_any_uid activé soient listés en dernier, ou définissez un socket personnalisé pour les autres services.

Par défaut : false

allow_protocol_transition (booléen)

Autorise les clients à demander un ticket pour eux-mêmes pour un utilisateur arbitraire.

Cette option contrôle si les requêtes s4u2self sont autorisées pour le client demandeur. Le keytab configuré est utilisé comme identité du service pour lequel un ticket est demandé. Le KDC doit toujours autoriser l'opération pour qu'elle réussisse.

Par défaut : false

allow_constrained_delegation (booléen)

Autorise les clients à demander un ticket pour un autre service en utilisant un ticket de preuve.

Cette option contrôle si les requêtes s4u2proxy sont autorisées pour le client demandeur. Le KDC doit toujours autoriser l'opération pour qu'elle réussisse.

Par défaut : false

allow_client_ccache_sync (booléen)

Autorise les clients à demander que les crédentials soient renvoyés pour une meilleure mise en cache.

Cette option permet au proxy, dans certaines circonstances, de renvoyer une option supplémentaire dans la structure de réponse de certains appels lorsqu'il détermine qu'un nouveau ticket a pu être ajouté au ccache interne. Les clients peuvent alors remplacer leur copie (chiffrée) par le ccache mis à jour.

Par défaut : false

cred_store (chaîne de caractères)

Ce paramètre permet de contrôler la manière dont gssproxy doit utiliser l'interface cred_store fournie par GSSAPI. Le paramètre peut être défini plusieurs fois par service.

La syntaxe du paramètre cred_store est la suivante : cred_store = <option_cred_store>:<valeur_cred_store>

Actuellement, cette interface prend en charge les options suivantes :

keytab

Définit le keytab que le service doit utiliser. Exemple : cred_store = keytab:/chemin/vers/keytab

client_keytab

Définit un keytab client que le service doit utiliser. Exemple : cred_store = client_keytab:/chemin/vers/client_keytab.

ccache

Définit un cache de crédentials que le service doit utiliser. Exemple : cred_store = ccache:/chemin/vers/ccache.

Notamment, les paramètres client_keytab et ccache sont généralement utilisés avec des espaces réservés de substitution de variables (voir ci-dessus). Par exemple :

    cred_store = keytab:/etc/krb5.keytab
    cred_store = ccache:FILE:/var/lib/gssproxy/krb5cc_%U
    cred_store = client_keytab:/var/lib/gssproxy/%U.keytab

Par défaut : cred_store =

cred_usage (chaîne de caractères)

Permet de restreindre le type d'opérations autorisées pour ce service.

Les options autorisées sont : initiate, accept, both

Par défaut : cred_usage = both

debug (booléen)

Active le débogage vers syslog. Le réglage sur true est identique au réglage du niveau de débogage sur 1.

Par défaut : debug = false

debug_level (entier)

Niveau de détail auquel les messages de débogage doivent être enregistrés. 0 correspond à aucune journalisation, tandis que 1 active la journalisation de débogage de base. Le niveau 2 augmente la verbosité, incluant une vérification plus détaillée des crédentials.

Aux niveaux 3 et supérieurs, la sortie KRB5_TRACE est enregistrée. Si KRB5_TRACE était déjà défini dans l'environnement d'exécution, la sortie de trace est envoyée à sa valeur à la place. Référez-vous à docs/KRB5_TRACE.md pour plus d'informations.

Par défaut : 1 si debug est vrai, sinon 0

enforce_flags (chaîne de caractères)

Une liste de drapeaux de requête GSS qui sont ajoutés inconditionnellement à chaque appel d'initialisation de contexte. Les drapeaux peuvent seulement être ajoutés à la liste ou retirés de la liste en préfixant un signe +/- au nom ou à la valeur du drapeau.

Noms des drapeaux reconnus : DELEGATE, MUTUAL_AUTH, REPLAY_DETECT, SEQUENCE, CONFIDENTIALITY, INTEGRITY, ANONYMOUS

Exemples :

    enforce_flags = +REPLAY_DETECT
    enforce_flags = -0x0001

Par défaut : enforce_flags =

euid (entier ou chaîne de caractères)

Soit l'uid numérique (par exemple, 48) soit symbolique (par exemple, apache) d'un processus en cours d'exécution, requis pour identifier un service.

Le paramètre "euid" est impératif, toute section sans celui-ci sera rejetée.

Par défaut : euid =

filter_flags (chaîne de caractères)

Une liste de drapeaux de requête GSS qui sont filtrés inconditionnellement de chaque appel d'initialisation de contexte. Les drapeaux ne peuvent être ajoutés à la liste ou retirés de la liste en préfixant un signe +/- au nom ou à la valeur du drapeau.

NOTE : Comme gssproxy est souvent utilisé pour refuser l'accès aux crédentials, le drapeau Delegate est filtré par défaut. Pour autoriser un service à déléguer des crédentials, utilisez le premier exemple ci-dessous.

Noms des drapeaux reconnus : DELEGATE, MUTUAL_AUTH, REPLAY_DETECT, SEQUENCE, CONFIDENTIALITY, INTEGRITY, ANONYMOUS

Exemples :

    filter_flags = -DELEGATE
    filter_flags = -0x0001 +ANONYMOUS

Par défaut : filter_flags = +DELEGATE

impersonate (booléen)

Utilise l'usurpation d'identité (s4u2self + s4u2proxy) pour obtenir des crédentials

Par défaut : impersonate = false

kernel_nfsd (booléen)

Drapeau booléen qui permet au noyau Linux de vérifier si gssproxy est en cours d'exécution (via /proc/net/rpc/use-gss-proxy).

Par défaut : kernel_nfsd = false

krb5_principal (chaîne de caractères)

Le principal krb5 à utiliser de préférence pour ce service, si aucun n'est demandé par l'application. Notez que cela n'impose pas l'utilisation de ce nom spécifique ; cela définit seulement une valeur par défaut.

Par défaut : krb5_principal =

mechs (chaîne de caractères)

Actuellement, seul krb5 est pris en charge.

Le paramètre "mechs" est impératif, toute section sans celui-ci sera rejetée.

Par défaut : mechs =

min_lifetime (entier)

Durée de vie minimale d'un credential mis en cache, en secondes.

Par défaut : min_lifetime = 15

program (string)

Si spécifié, ce service ne correspondra que lorsque le programme exécuté est la chaîne spécifiée.

Les programmes sont supposés être spécifiés sous forme de chemins canoniques (c'est-à-dire, pas de chemins relatifs, pas de liens symboliques). De plus, le caractère '|' est réservé pour une utilisation future et est donc interdit.

run_as_user (string)

Le nom de l'utilisateur auquel gssproxy réduira les privilèges.

Cette option n'est disponible que dans la section globale.

Par défaut : run_as_user =

selinux_context (string)

Cette option est obsolète. Utilisez plutôt un socket personnalisé ou euid à la place.

socket (string)

Ce paramètre permet de créer un fichier socket par service sur lequel les composants client et serveur de gssproxy communiquent.

Lorsque ce paramètre n'est pas défini, gssproxy utilisera une valeur par défaut intégrée.

syslog_status (boolean)

Active la sortie de débogage par appel vers syslog. Cela peut être utile pour enquêter sur les problèmes dans les applications utilisant gssproxy.

Par défaut : syslog_status = false

trusted (boolean)

Définit si ce service est considéré comme fiable. À utiliser avec prudence, cela permet l'usurpation d'identité.

Par défaut : trusted = false

worker threads (integer)

Définit le nombre de threads de travail que gssproxy créera au démarrage.

Par défaut : worker threads =
