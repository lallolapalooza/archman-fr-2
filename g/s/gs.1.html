GS(1) Ghostscript GS(1)

NOM

gs - Ghostscript (Interpréteur et visualiseuse des langages PostScript et PDF)

SYNTAXE

gs [ options ] [ fichiers ] ... (Unix, VMS)
gswin32c [ options ] [ fichiers ] ... (MS Windows)
gswin32 [ options ] [ fichiers ] ... (MS Windows 3.1)
gsos2 [ options ] [ fichiers ] ... (OS/2)

DESCRIPTION

La commande gs (gswin32c, gswin32, gsos2) invoque Ghostscript, un interpréteur des langages PostScript™ et Portable Document Format (PDF) d'Adobe Systems. gs lit les "fichiers" en séquence et les exécute comme des programmes Ghostscript. Après cela, il lit d'autres entrées depuis le flux d'entrée standard (normalement le clavier), interprétant chaque ligne séparément et l'envoyant vers un périphérique de sortie (qui peut être un fichier ou une fenêtre de prévisualisation X11, voir ci-dessous). L'interpréteur se termine proprement lorsqu'il rencontre la commande "quit" (soit dans un fichier, soit depuis le clavier), en fin de fichier, ou lors d'un signal d'interruption (comme Control-C au clavier).

L'interpréteur reconnaît de nombreuses options, dont certaines sont décrites ci-dessous. Veuillez consulter la documentation d'utilisation pour des informations complètes. Les options peuvent apparaître n'importe où dans la ligne de commande et s'appliquent à tous les fichiers qui les suivent. L'invocation de Ghostscript avec l'option -h ou -? produit un message qui montre plusieurs options utiles, tous les périphériques connus de cet exécutable, et le chemin de recherche des polices ; sur Unix, il montre également l'emplacement de la documentation détaillée.

Ghostscript peut être compilé pour utiliser de nombreux périphériques de sortie différents. Pour voir quels périphériques votre exécutable inclut, exécutez "gs -h".

À moins que vous ne spécifiiez un périphérique particulier, Ghostscript ouvre normalement le premier d'entre eux et y dirige la sortie.

S'il est compilé avec le support X11, le périphérique par défaut est souvent une fenêtre X11 (prévisualisation), sinon ghostscript utilisera généralement le périphérique bbox et affichera sur stdout les dimensions du fichier postscript.

Donc, si le premier périphérique de la liste est celui que vous souhaitez utiliser, il suffit de taper la commande

gs fichier.ps

Vous pouvez également vérifier l'ensemble des périphériques disponibles depuis Ghostscript : invoquez Ghostscript et tapez

noms-périphériques ==

mais le premier périphérique de la liste résultante n'est pas nécessairement le périphérique par défaut que vous déterminez avec "gs -h". Pour spécifier "AbcXyz" comme périphérique de sortie initial, incluez l'option

-sPERIPHERIQUE=AbcXyz

Par exemple, pour une sortie vers une imprimante Epson, vous pourriez utiliser la commande

gs -sPERIPHERIQUE=epson fichier.ps

L'option "-sPERIPHERIQUE=" doit précéder la première mention d'un fichier à imprimer, et seule la première utilisation de l'option a un effet.

Enfin, vous pouvez spécifier un périphérique par défaut dans la variable d'environnement GS_PERIPHERIQUE. L'ordre de priorité pour ces alternatives, du plus élevé au plus bas (Ghostscript utilise le périphérique défini le plus haut dans la liste), est :

   setpagedevice
   (ligne de commande)
   GS_PERIPHERIQUE
   (premier périphérique dans la liste de compilation)

Certains périphériques peuvent supporter différentes résolutions (densités). Pour spécifier la résolution sur un tel périphérique, utilisez l'option "-r" :

gs -sPERIPHERIQUE=<périphérique> -r<xres>x<yres>

Par exemple, sur une imprimante compatible Epson 9 aiguilles, vous obtenez le mode de densité la plus faible (le plus rapide) avec

gs -sPERIPHERIQUE=epson -r60x72

et le mode de densité la plus élevée (meilleure qualité de sortie) avec

gs -sPERIPHERIQUE=epson -r240x72.

Si vous sélectionnez une imprimante comme périphérique de sortie, Ghostscript vous permet également de choisir où Ghostscript envoie la sortie – sur les systèmes Unix, généralement vers un fichier temporaire. Pour envoyer la sortie vers un fichier "foo.xyz", utilisez l'option

-sOutputFile=foo.xyz

Vous pourriez vouloir imprimer chaque page séparément. Pour ce faire, envoyez la sortie vers une série de fichiers "foo1.xyz, foo2.xyz, ..." en utilisant l'option "-sOutputFile=" avec "%d" dans un modèle de nom de fichier :

-sOutputFile=foo%d.xyz

Chaque fichier résultant reçoit une page de sortie, et les fichiers sont numérotés en séquence. "%d" est une spécification de format printf ; vous pouvez aussi utiliser une variante comme "%02d".

Sur les systèmes Unix et MS Windows, vous pouvez également envoyer la sortie vers un pipe. Par exemple, pour envoyer la sortie vers la commande "lpr" (qui, sur de nombreux systèmes Unix, la dirige vers une imprimante), utilisez l'option

-sOutputFile=%pipe%lpr

Notez que les caractères '%' doivent être doublés sur MS Windows pour éviter d'être déformés par l'interpréteur de commandes.

Vous pouvez également envoyer la sortie vers la sortie standard :

-sOutputFile=-
ou 
-sOutputFile=%stdout%

Dans ce cas, vous devez également utiliser l'option -q, pour éviter que Ghostscript n'écrive de messages sur la sortie standard.

Pour sélectionner une taille de papier spécifique, utilisez l'option de ligne de commande

-sPAPERSIZE=<taille_papier>

par exemple

-sPAPERSIZE=a4
ou 
-sPAPERSIZE=legal

La plupart des tailles de papier ISO et US sont reconnues. Voir la documentation d'utilisation pour une liste complète, ou les définitions dans le fichier d'initialisation "gs_statd.ps".

Ghostscript peut faire beaucoup plus que d'imprimer ou de visualiser des fichiers PostScript et PDF. Par exemple, si vous voulez connaître la boîte englobante d'un fichier PostScript (ou EPS), Ghostscript fournit un "périphérique" spécial qui imprime simplement ces informations.

Par exemple, en utilisant l'un des fichiers d'exemple distribués avec Ghostscript,

gs -sPERIPHERIQUE=bbox golfer.ps

affiche

%%BoundingBox: 0 25 583 732
%%HiResBoundingBox: 0.808497 25.009496 582.994503 731.809445

OPTIONS

-- nomfichier arg1 ...
Prend l'argument suivant comme nom de fichier, comme d'habitude, mais prend tous les arguments restants (même s'ils ont la forme syntaxique d'options) et définit le nom "ARGUMENTS" dans "userdict" (pas dans "systemdict") comme un tableau de ces chaînes, avant d'exécuter le fichier. Lorsque Ghostscript a fini d'exécuter le fichier, il retourne à la console.
-Dnom=jeton

-dnom=jeton
Définit un nom dans "systemdict" avec la définition donnée. Le jeton doit être exactement un jeton (tel que défini par l'opérateur "jeton") et ne peut contenir d'espaces.
-Dnom

-dnom
Définit un nom dans "systemdict" avec la valeur=null.
-Snom=chaîne

-snom=chaîne
Définit un nom dans "systemdict" avec une chaîne donnée comme valeur. Ceci est différent de -d. Par exemple, -dnom=35 est équivalent au fragment de programme
/nom 35 def
tandis que -snom=35 est équivalent à
/nom (35) def
-P
Demande à Ghostscript de rechercher d'abord les fichiers de bibliothèque dans le répertoire courant. Par défaut, Ghostscript ne recherche plus dans le répertoire courant, sauf si, bien sûr, le premier répertoire explicitement fourni est "." dans -I. Voir également la section FICHIERS D'INITIALISATION ci-dessous, et le fichier groupé Use.htm pour une discussion détaillée sur les chemins de recherche et comment Ghostscript trouve les fichiers.
-q
Démarrage silencieux : supprime les messages de démarrage normaux, et fait également l'équivalent de -dQUIET.
-gnombre1xnombre2
Équivalent à -dDEVICEWIDTH=nombre1 et -dDEVICEHEIGHT=nombre2. Ceci est pour les périphériques (tels que les fenêtres X11) qui nécessitent (ou autorisent) la spécification de la largeur et de la hauteur.
-rnombre

-rn

nombre1xnombre2
Équivalent à -dDEVICEXRESOLUTION=nombre1 et -dDEVICEYRESOLUTION=nombre2. Ceci est destiné aux appareils tels que les imprimantes qui prennent en charge plusieurs résolutions X et Y. Si un seul nombre est donné, il est utilisé pour les résolutions X et
Y.
-Irépertoir
es
Ajoute la liste désignée de répertoires au début du chemin de recherche pour les fichiers de
bibliothèque.
-
Ceci n'est pas vraiment un interrupteur, mais indique à Ghostscript que l'entrée standard provient d'un fichier ou d'un pipe et non de manière interactive dep
uis la ligne de commande. Ghostscript lit depuis l'entrée standard jusqu'à ce qu'il atteigne la fin de fichier, l'exécute comme tout autre fichier, puis continue le traitement de la ligne de commande. Lorsque la ligne de commande a été entièrement traitée, Ghostscript se termine au lieu de passer en mode interactif.

Notez que le fichier d'initialisation normal "gs_init.ps" rend "systemdict" en lecture seule, de sorte que les valeurs des noms définis avec -D, -d, -S ou -s ne peuvent pas être modifiées (bien que, bien sûr, elles puissent être

remplacées par des définitions dans "userdict" ou d'autres dictionnaires.)

MODE

SAFER

L'option -dSAFER restreint les accès au système de fichiers à ceux des fichiers et répertoires autorisés par les variables d'environnement pertinentes (telles que GS_LIB) ou par les paramètres de la ligne de commande (voir https://ghostscript.com/doc/current/Use.htm pour plus de détails)

.

Le mode SAFER est maintenant le mode d'operation par défaut. Ainsi, lors de l'exécution de programmes qui ont besoin d'ouvrir des fichiers ou de définir des paramètres restreints, vous devriez passer l'option de ligne de commande -dNOSAFER ou son synonyme -dDELAYSAFER

.

L'exécution avec NOSAFER/DELAYSAFER (comme le suggère le nom) assouplit la séc

urité et n'est donc recommandée QUE pour le débogage ou dans des flux de travail
TRÈS contrôlés, et fortement NON recommandée dans toutes les autres circonstances.

N

Lors de la recherche des fichiers d'initialisation "gs_*.ps", des fichiers liés aux polices, ou du fichier pour l'opérateur "run", Ghostscript essaie d'abord d'ouvrir le fichier avec le nom tel que donné, en utilisant le répertoire de travail courant si aucun répertoire n'est spécifié. Si cela échoue, et que le nom de fichier ne spécifie pas un répertoire ou un lecteur explicite (par exemple, ne contient pas "/" sur les systèmes Unix ou "\" sur les systèmes MS Windows ), Ghostscript essaie les répertoires dans cet ordre
