NOM

gdnsd-plugin-geoip - méta-plugin gdnsd pour GSLB + basculement via les bases de données GeoIP2 de MaxMind

SYNTAXE

Exemple minimal de fichier de configuration gdnsd utilisant ce plugin :

plugins => { geoip => {
  maps => {
    my_prod_map => {
      geoip2_db => GeoIP2-City.mmdb,
      datacenters => [dc-03, dc-02, dc-01, dc-fail],
      map => {
          EU => {
              DE => [dc-03, dc-01, dc-fail],
              CH => [dc-01, dc-03, dc-fail]
          },
          NA => { MX => [dc-02, dc-fail] }
      }
    },
    my_auto_map => {
      geoip2_db => GeoIP2-Country.mmdb,
      datacenters => [dc1, dc2],
      auto_dc_coords => {
         dc1 => [ 38.9, -77 ],
         dc2 => [ 50.1, 8.7 ],
      }
    }
  },
  resources => {
    prod_www => {
      map => my_prod_map
      service_types => up
      dcmap => {
        dc-01 => 192.0.2.1,
        dc-02 => { lb01 => 192.0.2.2, lb02 => 192.0.2.3 },
        dc-03 => [ 192.0.2.4, 192.0.2.5, 192.0.2.6 ],
        dc-fail => last.resort.cname.example.net.
      }
    }
    corp_www => {
      map => my_auto_map
      dcmap => {
        dc1 => 192.0.2.100,
        dc2 => 192.0.2.101
      }
    }
  }
}}

DESCRIPTION

gdnsd-plugin-geoip utilise les bases de données binaires GeoIP2 de MaxMind pour mapper les adresses et les résultats CNAME en fonction de la géographie et de la disponibilité des services surveillés. Il prend en charge pleinement IPv6 et la norme émergente edns-client-subnet. Si une requête contient l'option edns-client-subnet avec un masque réseau source supérieur à zéro, les informations edns-client-subnet seront utilisées à la place de l'adresse IP source de la requête (l'adresse IP du cache qui interroge).

Il prend en charge les bases de données au format GeoIP2, qui se terminent généralement par .mmdb. Il ne prend pas en charge les bases de données au format GeoIP1 (qui se terminent généralement par .dat).

Il peut également être utilisé sans aucune base de données GeoIP, auquel cas la seule entrée de mappage réseau provient des données de configuration "nets" ou d'un fichier "nets" externe, qui mappe explicitement les sous-réseaux à des listes de centres de données.

Ce plugin peut fonctionner dans un mode automatique basé sur la distance (utilisant les informations de coordonnées d'une base de données de niveau Ville). Il peut également fonctionner sans coordonnées et s'appuyer sur l'utilisateur pour configurer une carte hiérarchique de mappages défaut en cascade de localisation utilisateur vers centre de données, en commençant au niveau du continent.

Les deux modes peuvent également être efficacement mélangés aux limites géographiques.

Pour chaque "map" que vous définissez (qui mappe des codes de localisation géographique à des listes ordonnées de vos emplacements de centres de données), ce plugin fusionne tous les sous-réseaux GeoIP bruts dans les super-réseaux les plus grands possibles qui contiennent des réponses identiques dans votre configuration. Ceux-ci sont ensuite utilisés pour définir des masques de portée edns-client-subnet plus grands que ceux que vous obtiendriez en renvoyant simplement des résultats GeoIP bruts.

METAFO DU PLUGIN

La documentation de gdnsd-plugin-metafo(8) est une lecture obligatoire pour comprendre la documentation du plugin geoip ici. Le plugin geoip est un sur-ensemble exact du plugin metafo, et réutilise presque tout le code source du plugin metafo. Metafo effectue le basculement le long d'une seule liste globale ordonnée de centres de données. Ce que le plugin_geoip ajoute aux fonctionnalités de metafo est la capacité pour la liste de basculement des centres de données de devenir dynamique par requête en fonction d'indices géographiques dérivés de l'adresse réseau du client.

EMPLACEMENTS DES FICHIERS

La configuration de ce plugin peut référencer plusieurs fichiers externes de configuration et/ou de données. Par défaut, tous les fichiers référencés dans la configuration de ce plugin sont chargés à partir du sous-répertoire geoip du répertoire de configuration du démon (par défaut /etc/gdnsd). Vous pouvez charger à partir d'autres emplacements en spécifiant des chemins de fichiers absolus.

CONFIGURATION - NIVEAU SUPÉRIEUR

Le niveau supérieur de la configuration du plugin geoip (c'est-à-dire "plugins => { geoip => { ... } }") ne prend en charge que trois clés explicites. L'une est le paramètre facultatif "undefined_datacenters_ok".

Les deux autres sont obligatoires et développées en détail dans les deux sections suivantes : "maps" et "resources". La section "maps" définit un ou plusieurs mappages nommés d'informations géographiques à partir de bases de données binaires GeoIP vers des sous-ensembles ordonnés de noms de centres de données. La section "resources" définit une ou plusieurs ressources nommées, chacune faisant référence à l'une des cartes nommées et résolvant les noms de centres de données en ensembles spécifiques d'adresses ou de CNAME.

Toutes les autres clés présentes à ce niveau seront héritées à l'intérieur de chaque hachage par ressource dans la section "resources", agissant comme valeurs par défaut par ressource pour tout ce qui n'est pas explicitement défini là.

"undefined_datacenters_ok = false"

Booléen, par défaut false. S'il est défini sur true, les ressources geoip sont autorisées à laisser certains des centres de données spécifiés dans leur "map" non définis dans leur "dcmap" au niveau de la ressource. Par exemple, une carte M pourrait définir 3 centres de données nommés A, B et C, mais une ressource utilisant la carte M pourrait seulement définir des adresses de résultat pour les centres de données B et C dans son "dcmap". Ce serait autrement une erreur de configuration majeure.

!!! DANGER !!! - Définir cette valeur sur true est une bonne façon de se tirer une balle dans le pied si vous ne faites pas très attention à la façon dont vos cartes et vos ressources sont configurées les unes par rapport aux autres, en particulier en "Mode Auto Ville". Les cartes sont calculées sans aucune connaissance des ressources qui les utilisent. Si un réseau ou un emplacement spécifique correspond à une liste de centres de données qui ne contient aucun des centres de données définis pour une ressource donnée, les résultats des requêtes d'exécution pour cette ressource à partir de cet emplacement ou réseau seront l'ensemble vide (aucun enregistrement de réponse du tout). Cela se produira presque à coup sûr en "Mode Auto Ville" si le nombre de centres de données non définis dans une ressource est supérieur ou égal à la "auto_dc_limit" de la carte.

CONFIGURATION - CARTES

Toutes les clés de configuration au niveau "maps" sont les noms des cartes que vous choisissez de définir. Une carte, conceptuellement, est un mappage entre la géographie et/ou la topologie réseau vers divers sous-ensembles ordonnés de centres de données. La valeur de chaque carte nommée doit être une table de hachage, et les clés de configuration suivantes s'appliquent à l'intérieur :

"geoip2_db = GeoIP2-City.mmdb"

Chaîne de caractères, nom de fichier, facultatif. C'est le nom de fichier d'une base de données au format MaxMind GeoIP2. Elle doit contenir le modèle de données Ville ou Pays. Aucune distinction n'est faite ici pour la version IP, et il est normal que ces bases de données contiennent à la fois des données IPv4 et IPv6 ensemble. Si l'une ou l'autre est manquante, les clients utilisant cette famille d'adresses seront par défaut.

"datacenters = [ un, deux, trois, ... ]"

Tableau de chaînes de caractères, requis. C'est l'ensemble total de noms de centres de données utilisés par cette carte. Vous devez définir au moins un nom de centre de données (bien que 2 ou plus seraient infiniment plus utiles). À l'heure actuelle, il y a une limite maximale de 254 noms de centres de données par carte, bien que cela puisse être augmenté si quelqu'un en a besoin. L'ordre spécifié ici est l'ordre de résultat par défaut de repli dans divers cas par défaut (par exemple, si aucune liste de défauts de carte explicite de niveau supérieur n'est donnée).

faux par défaut.
