DESCRIPTIO

N

gdomap Le démon gdomap est utilisé par les programmes GNUstep pour rechercher des objets distribués de processus s'exécutant à travers le réseau (et entre différents comptes utilisateurs sur une seule machine). Le démon n'est PAS utilisé pour la recherche lorsque deux processus appartenant au même utilisateur utilisent une connexion locale à la machine. Cette page manuelle explique l'utilisation de gdomap. Pour des informations sur la conception et l'implémentation (et des notes spéciales pour les empaqueteurs), veuillez consulter la documentation HTML installée dans $GNUSTEP_SYSTEM_DOC, sous Command-line

Tools.

Habituellement, le démon gdomap est démarré au démarrage du système et se lie au port 538. Voir le Guide de construction GNUstep pour un script de démarrage

d'exemple.

Par défaut, gdomap interroge chaque machine du réseau local pour voir s'il y a une copie de gdomap en cours d'exécution. Cela est fait pour les réseaux de classe C et les sous-réseaux de réseaux de classe C. Si votre hôte est sur un réseau de classe B ou de classe A, le comportement par défaut est de le traiter comme un réseau de classe C et d'interroger uniquement les hôtes qui seraient attendus sur un réseau de classe C du même

nombre.

Si vous fonctionnez sur un réseau de classe A ou de classe B, ou si votre réseau a un grand nombre d'hôtes qui n'auront pas gdomap - vous pouvez fournir un fichier de configuration listant les hôtes à interroger explicitement, plutôt que de laisser gdomap interroger tous les hôtes du réseau

local.

Vous pouvez également vouloir fournir le fichier de configuration afin que les hôtes qui ne sont pas réellement sur votre réseau local puissent toujours être trouvés lorsque votre code essaie de se connecter à un hôte en utilisant @"*" comme nom d'hôte. NB. cette fonctionnalité n'existe pas dans

OpenStep.

Un fichier de configuration consiste en une liste d'adresses IP à interroger. Les adresses IP doivent être en notation standard « point », une par ligne. Les lignes vides sont autorisées dans le fichier de configuration. Tout ce qui se trouve sur une ligne après un dièse ('#') est ignoré. Vous informez gdomap du fichier de configuration avec l'option de ligne de commande

'-c'.

gdomap utilise l'ioctl SIOCGIFCONF pour construire une liste d'adresses IP et de masques de sous-réseau pour les cartes d'interface réseau de votre machine. Sur certains systèmes d'exploitation, cette fonctionnalité n'est pas disponible (ou est cassée), donc vous devez indiquer à gdomap les adresses et les masques des interf

aces en utilisant l'option '-a' de la ligne de commande. Le fichier nommé avec '-a' doit contenir une série de lignes avec des paires d'adresses et de masques séparées par des espaces en notation « point ». Vous ne devez PAS inclure les interfaces de bouclage dans cette liste. Si vous voulez prendre en charge la diffusio
n d'informations d'interrogation sur un réseau, vous pouvez fournir l'adresse de diffusion comme troisième élément sur la ligne. Si votre système d'exploitation a une autre méthode pour vous donner une liste d'interfaces réseau et de masques, veuillez m'envoyer un exemple de code afin que je puisse l'implémenter dans gdomap.
