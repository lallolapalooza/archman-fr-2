OPTIONS EN LIGNE DE

COMMANDE

c
Définit le répertoire de configuration, par défaut /etc/gdnsd. Le répertoire des zones est le sous-répertoire zones/ du répertoire de
configuration.
-
D
Active la sortie de journalisation de niveau débogage supplémentaire selon les

-

Envoie la sortie du journal à syslog plutôt qu'à stderr par défaut. C'est activé implicitement par l'action "daemonize" et est également recommandé lors de l'exécution en tant que service systemd, afin de capturer les informations de

Force l'option de configuration "zones_strict_data" à true pour cette invocation, quel que soit le paramètre dans le fichier de configuration. C'est principalement utile pour la validation lors de l'option "checkconf

-
R
Mode de remplacement pour "start" et "daemonize" :

Normalement, si une autre instance du serveur a le socket de contrôle du serveur verrouillé, une tentative "start" ou "daemonize" échouera. Avec ce drapeau défini, le nouveau serveur se connectera à l'ancien via son socket de contrôle et tentera une reprise de fonctionnement gracieuse sans interruption. Cela permet à la fois des changements de code et de configuration de se produire sans perdre de requêtes dans la plupart des cas et est en général assez transparent. Voir la documentation de gdnsdctl(8) pour "replace" pour plus d'inform

ations, car c'est l'interface préfér

-
i
Mode idempotent pour "start" et "daemonize" :

Normalement, si une autre instance du serveur a le socket de contrôle du serveur verrouillé, une tentative "start" ou "daemonize" échouera. Avec ce drapeau défini, si une autre

instance est déjà en cours d'exéc
ution, cette instance sig
nalera un succès et quittera immé
diatement avec un statut de zéro.

PRIVILÈGE

S

Ce service ne prête aucune attention à, ni ne tente de vérifier ou de modifier, quoi que ce soit concernant l'environnement de sécurité d'exécution ou l'ensemble de privilèges, ou s'il se trouve ou non en train de s'exécuter en tant que "root", ou ne tente aucune action qui nécessiterait couramment des privilèges "root", comme modifier ses propres rlimits memlock ou augmenter sa propre priorité de processus. La seule exception est que le code suppose aveuglément que la liaison de ses ports d'écoute DNS, qui sont par défaut dans la plage privilégiée, fonctionnera

simplement.

Il s'attend à ce que toutes ces choses soient gérées par des mécanismes externes : soit un système d'init de type systemd q

ui peut tout faire de manière déclarative, soit une combinaison d'outils dans un script d'init pour un système d'init

COMPATIBILITÉ AVEC

SYSTEMD

Lorsqu'il est exécuté en tant que service systemd, "start" devrait être utilisé plutôt que "daemonize", le drapeau "-l" devrait être utilisé, et le type devrait être défini à "Type=notify" avec "NotifyAccess=all". Ces derniers éléments feront que systemd définira $NOTIFY_SOCKET pour le démon, et le démon l'utilisera à son tour pour envoyer une notification de disponibilité lorsque il a terminé les tâches de démarrage initial et est prêt à servir les requêtes. "gdnsdctl -l stop" devrait être utilisé pour la commande "ExecStop="

.

L'arborescence des sources contient un exemple de

fichier unit systemd avec des valeurs par défa
ut raisonnables pour un déploiement en production.

FICHIERS DE ZONE -

RFC1035

Le répertoire pour les fichiers de zone RFC1035 standard (le backend de données de zone par défaut) est le sous-répertoire nommé zones/ dans le répertoire de configuration, donc le défaut serait /etc/gdnsd/zones/

.

Les fichiers de zone RFC1035 sont le format de fichier de zone traditionnel que l'on utilise typiquement avec par ex. BIND. Pour plus d'informations sur le format interne et le traitement de ces fichiers, voir gdnsd.zonefile(5). Cette section traite de la manière dont le répertoire lui-même est

géré.

Tous les fichiers du répertoire des zones sont considérés comme des fichiers de zone. En général, il devrait y avoir exactement un fichier par zone, et le nom de fichier devrait correspondre au nom de zone. Les noms de fichier commençant par "." sont ignorés. Tous les fichiers de zone doivent être des fichiers réguliers (par opposition aux répertoires, liens symboliques, sockets, etc)

.

Afin de mieux prendre en charge le cas spécial des zones de délégation in-addr.arpa sans classe de style RFC 2137 (qui contiennent des barres obliques), tout symbole "@" dans le nom de fichier sera traduit en une barre oblique ("/") lors de la transformation d'un nom de fichier en son nom de zone

correspondant.

Pour des raisons similaires, si votre serveur est destiné à servir la racine du DNS, le nom de fichier pour la zone racine devrait être le nom de fichier spécial ROOT_ZONE, plutôt que le nom de fichier littéral impossible .. Car les serveurs faisant autorité ne peuvent pas servir deuxo domains qui ont une relation parent<->child correctement, un serveur racine ne peut servir aucune autre zone, donc ce serait le seul fichier de zone.

Les

séquences d'échappement standard des fichiers de zone DNS sont reconnues dans les noms de fichiers (par ex. "\." pour un point dans un libellé, ou "\NNN" où NNN est un entier décimal dans la plage 0 - 255), si pour une raison quelconque vous avez besoin d'un caractère étrange

dans

votre nom de zone. Les points finaux sur les noms de fichiers de zone sont ignorés ; par ex. example.com et example.

com.

sont fonctionnellement équivalents. Les zones en double (par ex. avoir à la fois les deux représentations ci-dessus de "example.com" présentes dans le répertoire des zones, et/ou ajouter un mappement de cas

différent

tel que EXample.Com) sont illégales. Les sous-zones (par ex. avoir des fichiers de zone pour à la fo

is "examp
le.com" et

"subz.example.com")

sont

également illégales. FICHIERS DE ZONE - RECHARGEMENT "gdnsdctl reload-zones" déclenche le rechargement de toutes les données de zone. L'opération de rechargement est effectuée dans un thread
