DESCRIPTIO

N

gdal raster reproject peut être utilisé pour reprojeter un jeu de données raster. Le programme peut reprojeter vers n'importe quelle projection prise en

charge.

D'abord, gdal raster reproject doit déterminer l'étendue et la résolution de la sortie, si celles-ci n'ont pas été spécifiées à l'aide de --bbox et --resolution. Celles-ci sont déterminées en transformant un échantillon de points du SRS source vers le SRS de destination. Les détails de la procédure peuvent être trouvés dans la documentation de GDALSuggestedWarpOutput(). Si plusieurs entrées sont fournies à gdal raster reproject, l'étendue de sortie sera calculée pour couvrir toutes celles-ci, à une résolution cohérente avec l'entrée de plus haute

résolution.

Une fois les dimensions de l'image de sortie déterminées, gdal raster reproject divise l'image de sortie en morceaux qui peuvent être traités indépendamment. gdal raster reproject itère ensuite sur les lignes de balayage de ces morceaux, et pour chaque pixel de sortie détermine une région rectangulaire de pixels source qui contribuent à la valeur du pixel de sortie. Les dimensions de cette région rectangulaire sont généralement déterminées en estimant les échelles relatives des rasters source et destination, mais peuvent être spécifiées manuellement (voir la documentation du paramètre XSCALE dans GDALWarpOptions::papszWarpOptions). Comme la région source est un simple rectangle, il n'est pas possible pour un pixel de sortie d'être associé à des pixels source des deux côtés de l'antiméridien ou du pôle (lors de la transformation depuis des coordonnées géographiques)

.

La région rectangulaire de pixels source est ensuite fournie à une fonction qui effectue l'algorithme de rééchantillonnage sélectionné avec --resampling. Selon l'algorithme de rééchantillonnage et les échelles relatives des rasters source et destination, les pixels source peuvent être pondérés soit selon la fraction approximative du pixel source qui est couverte par le pixel de destination (par ex. rééchantillonnage "mean" et "sum"), soit par les distances cartésiennes horizontales et verticales entre le centre du pixel source et le centre du pixel cible (par ex. rééchantillonnage bilinéaire ou spline cubique). Dans ce dernier cas, la pondération relative d'un pixel source individuel est déterminée par le produit des pondérations déterminées pour sa ligne et sa colonne ; la distance cartésienne diagonale n'est pas

calculée.

Cette sous-commande est également disponible en tant qu'étape potentielle de gdal raster

pipeline

Les valeurs invalides dans les pixels source, qu'elles soient identifiées via une valeur nodata définie dans les métadonnées de la bande source, une bande masque, une bande alpha (pour une bande alpha, une valeur de 0 signifie invalide. Les détails de la manière dont elles sont prises en compte dépendent du noyau de rééchantillonnage

:
  • pour le rééchantillonnage au voisin le plus proche, pour chaque pixel cible, la coordonnée de son centre est projetée vers les coordonnées source et le pixel source contenant cette coordonnée est identifié. Si ce pixel source est invalide, le pixel cible est considéré comme
    • nodata.
  • pour bilinear, cubic, cubicspline et lanczos, pour chaque pixel cible, la coordonnée de son centre est projetée vers les coordonnées source et un pixel source correspondant est identifié. Si ce pixel source est invalide, le pixel cible est considéré comme nodata (dans ce cas, les pixels valides à l'intérieur du rayon du noyau ne seraient pas considérés). Étant donné que ces noyaux de rééchantillonnage ont un rayon de noyau non nul, ce pixel source n'est qu'un parmi plusieurs pixels sources, et il est possible qu'il y ait des valeurs invalides dans ces autres pixels sources contributeurs. TRANSFORMATION

APPROXIMATIVE

Par défaut gdal raster reproject utilise un approximateur linéaire pour les transformations avec une erreur autorisée de 0,125 pixel dans le jeu de données source. L'approximateur transforme précisément trois points par ligne de balayage de sortie (le début, le milieu et la fin) d'une ligne et d'une colonne dans le jeu de données de sortie vers une ligne et une colonne dans le jeu de données source. Il compare ensuite une approximation linéaire des coordonnées du point central à la valeur transformée précisément. Si la somme des erreurs horizontale et verticale est inférieure au seuil d'erreur, les points source restants sont approximés par interpolation linéaire entre le point de début et le point central, et entre le point central et le point de fin. Si l'erreur dépasse le seuil, la ligne de balayage est divisée en deux sections et l'approximateur est appliqué récursivement à chaque section jusqu'à ce que l'erreur soit inférieure au seuil ou que tous les points aient été calculés

exactement.

Le seuil d'erreur (en pixels du jeu de données source) peut être contrôlé avec l'option --error-threshold. Si vous souhaitez comparer une reprojection véritablement pixel par pixel, utilisez --error-threshold=0 ce qui désacti

ve complètement c
et approximateur.
