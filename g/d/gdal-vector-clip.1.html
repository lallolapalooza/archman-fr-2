NOM

gdal-vector-clip - Découper un jeu de données vectorielles

Ajouté dans la version 3.11.

SYNOPIS

Usage : gdal vector clip [OPTIONS] <INPUT> <OUTPUT>
Découpe un jeu de données vectorielles.
Arguments positionnels :
  -i, --input <INPUT>                                  Jeux de données vectorielles d'entrée [requis]
  -o, --output <OUTPUT>                                Jeu de données vectorielles de sortie [requis]
Options communes :
  -h, --help                                           Affiche le message d'aide et quitte
  --json-usage                                         Affiche l'utilisation sous forme de document JSON et quitte
  --config <KEY>=<VALUE>                               Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <INPUT-LAYER>             Nom(s) de couche(s) d'entrée [peut être répété]
  -f, --of, --format, --output-format <OUTPUT-FORMAT>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <KEY>=<VALUE>                Option de création [peut être répétée]
  --lco, --layer-creation-option <KEY>=<VALUE>         Option de création de couche [peut être répétée]
  --overwrite                                          Indique si l'écrasement des sorties existantes est autorisé
  --update                                             Indique si l'ouverture d'un jeu de données existant en mode mise à jour est autorisée
  --overwrite-layer                                    Indique si l'écrasement des sorties existantes est autorisé
  --append                                             Indique si l'ajout à une couche existante est autorisé
                                                       Mutuellement exclusif avec --upsert
  --output-layer <OUTPUT-LAYER>                        Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <ACTIVE-LAYER>                        Définir la couche active (sinon toutes)
  --bbox <BBOX>                                        Boîte englobante de découpage sous la forme xmin,ymin,xmax,ymax
                                                       Mutuellement exclusif avec --geometry, --like
  --bbox-crs <BBOX-CRS>                                CRS de la boîte englobante de découpage
  --geometry <GEOMETRY>                                Géométrie de découpage (WKT ou GeoJSON)
                                                       Mutuellement exclusif avec --bbox, --like
  --geometry-crs <GEOMETRY-CRS>                        CRS de la géométrie de découpage
  --like <DATASET>                                     Jeu de données à utiliser comme modèle pour les limites
                                                       Mutuellement exclusif avec --bbox, --geometry
  --like-sql <SELECT-STATEMENT>                        Instruction SELECT à exécuter sur le jeu de données 'like'
                                                       Mutuellement exclusif avec --like-where
  --like-layer <LAYER-NAME>                            Nom de la couche du jeu de données 'like'
  --like-where <WHERE-EXPRESSION>                      Clause WHERE SQL à exécuter sur le jeu de données 'like'
                                                       Mutuellement exclusif avec --like-sql
Options avancées :
  --if, --input-format <INPUT-FORMAT>                  Formats d'entrée [peut être répété]
  --oo, --open-option <KEY>=<VALUE>                    Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <KEY>=<VALUE>      Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector clip peut être utilisé pour découper un jeu de données vectorielles à l'aide de coordonnées géo-référencées.

Soit --bbox, --geometry ou --like doit être spécifié.

clip peut également être utilisé comme une étape du pipeline gdal vector.

Le découpage aboutit parfois à des géométries dont le type n'est pas compatible avec le type attendu. Ce programme divise les multi-géométries ou les collections de géométries en leurs parties pour les couches qui sont d'un type de géométrie unique (comme point, linestring, polygone) et ne conserve que les parties de ce type. Il promeut également les types de géométrie uniques (par exemple, polygones) vers les types de géométrie multiples (par exemple, multipolygones). Si l'utilisateur a besoin de conserver tout type d'intersection, la couche doit utiliser le type wkbUnknown (géométrie quelconque).

Options standard

-f, --of, --format, --output-format <OUTPUT-FORMAT>
Quel format de vecteur de sortie utiliser. Les valeurs autorisées peuvent être obtenues avec gdal --formats | grep vector | grep rw | sort
--co <NAME>=<VALUE>
De nombreux formats ont une ou plusieurs options de création de jeu de données optionnelles qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoPackage prend en charge des options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique du format des pilotes vectoriels pour les options de création légales pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal génère une erreur si le fichier ou le jeu de données cible existe déjà.
--active-layer <ACTIVE-LAYER>
Définit la couche active. Lorsqu'elle est spécifiée, seule la couche nommée sera traitée. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront traitées.
--bbox <xmin>,<ymin>,<xmax>,<ymax>
Limites pour découper le jeu de données. Elles sont supposées être dans le CRS du jeu de données d'entrée, sauf si --bbox-crs est spécifié. Les axes X et Y sont ceux "conviviaux pour le SIG", c'est-à-dire que X est la longitude ou l'est, et Y est la latitude ou le nord. Mutuellement exclusif avec --like et --geometry.
--bbox-crs <CRS>
CRS dans lequel les valeurs <xmin>,<ymin>,<xmax>,<ymax> de --bbox sont exprimées. Si non spécifié, il est supposé être le CRS du jeu de données d'entrée. Notez que la spécification de --bbox-crs n'implique pas de reprojection vectorielle. Au lieu de cela, les limites sont reprojetées du bbox-crs vers le CRS du jeu de données d'entrée.
--geometry <WKT_or_GeoJSON>
Géométrie sous forme de chaîne WKT ou GeoJSON pour découper le jeu de données. Si la géométrie d'entrée est GeoJSON, son CRS est supposé être WGS84, sauf s'il existe un CRS défini dans la géométrie GeoJSON ou si --geometry-crs est spécifié. Si la géométrie d'entrée est WKT, son CRS est supposé être celui du jeu de données d'entrée, sauf si --geometry-crs est spécifié. Les axes X et Y sont ceux "conviviaux pour le SIG", c'est-à-dire que X est la longitude ou l'est, et Y est la latitude ou le nord. Mutuellement exclusif avec --bbox et --like.
--geometry-crs <CRS>
CRS dans lequel les valeurs de coordonnées de --geometry sont exprimées. Si non spécifié, il est supposé être le CRS du jeu de données d'entrée. Notez que la spécification de --geometry-crs n'implique pas de reprojection vectorielle. Au lieu de cela, les limites sont reprojetées du geometry-crs vers le CRS du jeu de données d'entrée.
--like <DATASET>
Jeu de données vectoriel ou raster à utiliser comme modèle pour les limites. Si le jeu de données spécifié est un raster, ses limites rectangulaires sont utilisées comme géométrie de découpage. Si
le jeu de données spécifié est un jeu de données vectoriel, ses géométries polygonales sont fusionnées ensemble pour former la géométrie de découpage (attention, l'union résultante peut ne pas être parfaite s'il y a des espaces entre les entités polygonales individuelles). Si plusieurs couches sont présentes, --like-sql ou --like-layer doit être spécifié. Mutuellement exclusif avec --bbox et --geometr
