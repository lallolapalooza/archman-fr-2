NOM

gdal-vector-filter - Filtrer un jeu de données vectorielles

Ajouté dans la version 3.11.

SYNTAXE

Usage: gdal vector filter [OPTIONS] <ENTREE> <SORTIE>
Filtrer un jeu de données vectorielles.
Arguments positionnels :
  -i, --input <ENTREE>                                 Jeux de données vectorielles d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données vectorielles de sortie [requis]
Options courantes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>                               Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <ENTREE-COUCHE>             Nom(s) de la couche d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>                Option de création [peut être répétée]
  --lco, --layer-creation-option <CLE>=<VALEUR>         Option de création de couche [peut être répétée]
  --overwrite                                          Autoriser l'écrasement du fichier de sortie existant
  --update                                             Ouvrir le jeu de données existant en mode mise à jour
  --overwrite-layer                                    Autoriser l'écrasement de la couche de sortie existante
  --append                                             Autoriser l'ajout à la couche existante
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <COUCHE-ACTIVE>                       Définir la couche active (si non spécifiée, toutes)
  --bbox <BOITE-ENGlobANTE>                            Boîte englobante sous forme xmin,ymin,xmax,ymax
  --where <WHERE>|@<nom-fichier>                      Requête d'attribut sous une forme restreinte des requêtes utilisées dans la clause WHERE de SQL
Options avancées :
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLE>=<VALEUR>     Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector filter peut être utilisé pour filtrer un jeu de données vectorielles à partir de leur étendue spatiale ou d'une clause WHERE SQL.

filter peut également être utilisé comme une étape du pipeline gdal vector.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être obtenues avec gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données facultatives qui peuvent être utilisées pour contrôler des détails sur le fichier créé. Par exemple, le pilote GeoPackage prend en charge les options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote du format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats, mais la documentation du format est la source faisant autorité pour les options de création de pilote. Voir la documentation spécifique au format des pilotes vectoriels pour les options de création valides pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.
--active-layer <COUCHE-ACTIVE>
Définit la couche active. Lorsqu'elle est spécifiée, seule la couche nommée sera traitée. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront traitées.
--bbox <xmin>,<ymin>,<xmax>,<ymax>
Limites de filtrage du jeu de données. Elles sont supposées être dans le CSR du jeu de données d'entrée. Les axes X et Y sont ceux "conviviaux SIG", c'est-à-dire que X est la longitude ou l'est, et Y est la latitude ou le nord. Notez que le filtrage ne coupe pas les géométries à la boîte englobante.
--where <WHERE>|@<nom-fichier>
Requête d'attribut (comme WHERE en SQL).

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour éviter la détection automatique du pilote, lorsque celle-ci échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichier.

Peut être répété.

SORTIE GDALG (ICI/DONNÉES EN FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON à l'aide du format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectorielles à l'aide du pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière à la volée / en flux.

EXEMPLES

Exemple 1 : Sélectionner les entités d'un fichier GeoPackage qui intersectent la boîte englobante de la longitude 2, latitude 49, à la longitude 3, latitude 50 en WGS 84

$ gdal vector filter --bbox=2,49,3,50 in.gpkg out.gpkg --overwrite
