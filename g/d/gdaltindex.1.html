NAME

gdaltindex - Builds a shapefile as a raster tileindex.

SYNOPSIS

--help
Show this help message and exit
--help-general
Gives a brief usage message for the generic GDAL commandline options and exit.
-overwrite
Added in version 3.9.

Overwrite the tile index if it already exists.

-recursive
Added in version 3.9.

Whether directories specified in <file_or_dir> should be explored recursively.

-filename_filter <val>
Added in version 3.9.

Pattern that the filenames contained in directories pointed by <file_or_dir> should follow. '*' is a wildcard character that matches any number of any characters including none. '?' is a wildcard character that matches a single character. Comparisons are done in a case insensitive way. Several filters may be specified.

For example :-filename_filter "*.tif" -filename_filter "*.tiff"

-min_pixel_size <val>
Added in version 3.9.

Minimum pixel size in term of geospatial extent per pixel (resolution) that a raster should have to be selected. The pixel size is evaluated after reprojection of its extent to the target SRS defined by -t_srs.

-max_pixel_size <val>
Added in version 3.9.

Maximum pixel size in term of geospatial extent per pixel (resolution) that a raster should have to be selected. The pixel size is evaluated after reprojection of its extent to the target SRS defined by -t_srs.

-of <output_format>
The OGR format of the output tile index file. If not specified, the format is guessed from the extension.
-tileindex <field_name>
The output field name to hold the file path/location to the indexed rasters. The default tile index field name is location.
-write_absolute_path
The absolute path to the raster files is stored in the tile index file. By default the raster filenames will be put in the file exactly as they are specified on the command line.
-skip_different_projection
Only files with same projection as files already inserted in the tileindex will be inserted (unless -t_srs is specified). Default does not check projection and accepts all inputs.
-t_srs <target_srs>
Geometries of input files will be transformed to the desired target coordinate reference system. Default creates simple rectangular polygons in the same coordinate reference system as the input rasters.
-src_srs_name <field_name>
The name of the field to store the SRS of each tile. This field name can be used as the value of the TILESRS keyword in MapServer
-src_srs_format {AUTO|WKT|EPSG|PROJ}
The format in which the SRS of each tile must be written. Types can be AUTO, WKT, EPSG, PROJ. This option should be used together with -src_srs_format.
-lyr_name <name>
Layer name to create/append to in the output tile index file.
-lco <NAME>=<VALUE>
Added in version 3.9.

Layer creation option (format specific)

<index_file>
The name of the output file to create/append to. The default dataset will be created if it doesn't already exist, otherwise it will append to the existing dataset.
<file_or_dir>
The input GDAL raster files, can be multiple files separated by spaces. Wildcards may also be used. Stores the file locations in the same style as specified here, unless -write_absolute_path option is also used.

Starting with GDAL 3.9, this can also be a directory name. -recursive can also be used to recurse down to sub-directories.

It is also possible to use the generic option --optfile filelist.txt to specify a list of source files.

OPTIONS SPECIFIC TO USE BY THE GDAL GTI DRIVER

gdaltindex can be used to generate a tile index suitable for use by the GTI driver. There are two possibilities:

  • either use directly a vector tile index generated by gdaltindex as the input of the GTI driver
  • or generate a small XML .gti wrapper file, for easier use with non-file-based formats such as databases, or for vector formats that do not support setting layer metadata items.

Formats that support layer metadata are for example GeoPackage (-of GPKG), FlatGeoBuf (-of FlatGeoBuf) or PostGIS (-of PG)

Setting -tr and -ot is recommended to avoid the GTI driver to have to deduce them by opening the first tile in the index. If the tiles have nodata or mask band, -nodata and -mask should also be set.

In a GTI context, the extent of all tiles referenced in the tile index must be expressed in a single SRS. Consequently, if input tiles may have different SRS, either -t_srs or -skip_different_projection should be specified.

gdaltindex(1) — Arch Linux

NAME

gdaltindex

Builds a simple spatial index of the input datasets.

SYNOPSIS

gdaltindex [options] output_tile_index input_datasets...

DESCRIPTION

The gdaltindex utility builds a spatial index of the input raster files. The output is a vector file that contains one feature per input file. The geometry of the feature is the bounding box of the input file. The attribute information of the features consists of the name of the input file.

The output file can be in various formats (Shapefile, GeoPackage, etc.). If the output format is not specified using the -of option, it is deduced from the output filename extension.

The following output formats are some of the most common:

Shapefile
The extension is .shp. It is the default format if no other format is specified.
GeoPackage
The extension is .gpkg. Use the option -of GPKG.

The utility can also generate an XML file that can be used as an input for the GDAL GTI / Virtual Raster Tile Index driver.

OPTIONS SPECIFIC TO USE BY THE GDAL GTI DRIVER

-gti_filename <name>
Ajouté dans la version 3.9.

Nom du fichier XML Virtual Tile Index à générer, qui peut être utilisé comme entrée pour le pilote GDAL GTI / Virtual Raster Tile Index. Ceci peut être utile lors de l'écriture de l'index de tuiles dans un format vectoriel qui ne prend pas en charge l'écriture d'éléments de métadonnées de couche.

-tr <xres> <yres>
Ajouté dans la version 3.9.

Résolution cible en unités SRS par pixel.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme éléments de métadonnées de couche RESX et RESY pour les formats qui prennent en charge les métadonnées de couche.

-te <xmin> <ymin> <xmax> <ymax>
Ajouté dans la version 3.9.

Extension cible en unités SRS.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme éléments de métadonnées de couche MINX, MINY, MAXX et MAXY pour les formats qui prennent en charge les métadonnées de couche.

-ot <datatype>
Ajouté dans la version 3.9.

Type de données des tuiles de l'index de tuiles : Byte, Int8, UInt16, Int16, UInt32, Int32, UInt64, Int64, Float32, Float64, CInt16, CInt32, CFloat32 ou CFloat64

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme élément de métadonnées de couche DATA_TYPE pour les formats qui prennent en charge les métadonnées de couche.

-bandcount <val>
Ajouté dans la version 3.9.

Nombre de bandes des tuiles de l'index de tuiles.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme élément de métadonnées de couche BAND_COUNT pour les formats qui prennent en charge les métadonnées de couche.

Un mélange de tuiles avec N et N+1 bandes est autorisé, à condition que l'interprétation des couleurs de la (N+1)ème bande soit alpha. La valeur N+1 doit être écrite comme le nombre de bandes dans cette situation.

Si -nodata ou -colorinterp sont spécifiés et ont plusieurs valeurs, le nombre de bandes est également déduit de ce nombre.

-nodata <val>[,<val>...]
Ajouté dans la version 3.9.

Valeur nodata des tuiles de l'index de tuiles.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme élément de métadonnées de couche NODATA pour les formats qui prennent en charge les métadonnées de couche.

-colorinterp <val>[,<val>...]
Ajouté dans la version 3.9.

Interprétation des couleurs des tuiles de l'index de tuiles : red, green, blue, alpha, gray, undefined.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme élément de métadonnées de couche COLOR_INTERPRETATION pour les formats qui prennent en charge les métadonnées de couche.

-mask
Ajouté dans la version 3.9.

Indique si les tuiles de l'index de tuiles ont une bande de masque.

Écrit dans le XML Virtual Tile Index si -gti_filename est spécifié, ou comme élément de métadonnées de couche MASK_BAND pour les formats qui prennent en charge les métadonnées de couche.

-mo <KEY>=<VALUE>
Ajouté dans la version 3.9.

Écrit un élément de métadonnées de couche arbitraire, pour les formats qui prennent en charge les métadonnées de couche. Cette option peut être répétée.

NOTE :

Cette option ne peut pas être utilisée avec -gti_filename
-fetch_md <gdal_md_name> <fld_name> <fld_type>
Ajouté dans la version 3.9.

Récupère un élément de métadonnées de la tuile raster et l'écrit comme un champ dans l'index de tuiles.

<gdal_md_name> doit être le nom de l'élément de métadonnées raster. {PIXEL_SIZE} peut être utilisé comme nom spécial pour indiquer la taille du pixel.

<fld_name> doit être le nom du champ à créer dans l'index de tuiles.

<fld_type> doit être le nom du type à créer. L'un des choix parmi String, Integer, Integer64, Real, Date, DateTime

Cette option peut être répétée.

Par exemple : -fetch_md TIFFTAG_DATETIME creation_date DateTime

EXAMPLES

Exemple 1

Produire un shapefile (doq_index.shp) avec un enregistrement pour chaque image trouvée par l'utilitaire dans le dossier doq. Chaque enregistrement contient des informations pointant vers l'emplacement de l'image et également une forme de rectangle englobant montrant les limites de l'image :

gdaltindex doq_index.shp doq/*.tif

Exemple 2

Exécuter la même commande qu'auparavant, mais en créant cette fois un GeoPackage au lieu d'un Shapefile.

gdaltindex -of GPKG doq_index.gpkg doq/*.tif

Exemple 3

L'option -t_srs peut également être utilisée pour transformer tous les rasters d'entrée dans la même projection de sortie :

gdaltindex -t_srs EPSG:4326 -src_srs_name src_srs tile_index_mixed_srs.shp *.tif

Exemple 4

Créer un index de tuiles à partir de fichiers listés dans un fichier texte, avec des métadonnées adaptées à l'utilisation par le pilote GDAL GTI / Virtual Raster Tile Index.

gdaltindex tile_index.gti.gpkg -ot Byte -tr 60 60 -colorinterp Red,Green,Blue --optfile my_list.txt

C API

Cet utilitaire est également accessible depuis C avec GDALTileIndex().

VOIR AUSSI

Options communes aux programmes raster pour d'autres options de ligne de commande, et en particulier le commutateur --optfile qui peut être utilisé pour spécifier une liste de jeux de données d'entrée.
