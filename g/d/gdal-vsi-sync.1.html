NOM

gdal-vsi-sync - Synchroniser un fichier/répertoire source et cible situé sur l'interface système de fichiers virtuelle GDAL (VSI)

Ajouté dans la version 3.11.

SYNTAXE

Usage: gdal vsi sync [OPTIONS] <SOURCE> <DESTINATION>
Synchroniser un fichier ou répertoire source et cible situé sur l'interface système de fichiers virtuelle GDAL (VSI).
Arguments positionnels :
  --source <SOURCE>                Nom du fichier ou répertoire source [requis]
  --destination <DESTINATION>      Nom du fichier ou répertoire de destination [requis]
Options communes :
  -h, --help                       Afficher le message d'aide et quitter
  --json-usage                     Afficher l'usage sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>           Option de configuration [peut être répétée]
  -q, --quiet                      Mode silencieux (pas de barre de progression)
Options :
  -r, --recursive                  Synchroniser récursivement
  --strategy <STRATÉGIE>           Stratégie de synchronisation. STRATÉGIE=timestamp|ETag|overwrite (défaut : timestamp)
  -j, --num-threads <NB-THREADS>   Nombre de tâches (ou ALL_CPUS)

DESCRIPTION

gdal vsi sync synchronise les fichiers et répertoires situés sur les systèmes de fichiers virtuels GDAL (compressés, hébergés sur le réseau, etc. : /vsimem, /vsizip, /vsitar, /vsicurl, ...).

C'est un analogue de la commande UNIX rsync. Dans l'implémentation actuelle, rsync serait plus efficace pour la copie de fichiers locaux, mais l'intérêt principal de gdal vsi sync est lorsque la source ou la destination est un système de fichiers distant comme /vsis3/ ou /vsigs/, auquel cas il peut prendre en compte les horodatages des fichiers (ou optionnellement l'ETag/MD5Sum) pour éviter des opérations de copie inutiles.

Ceci est implémenté efficacement pour :

  • système de fichiers local <--> système de fichiers distant.
  • système de fichiers distant <--> système de fichiers distant, où les systèmes de fichiers distants source et cible sont les mêmes et l'un d'entre eux est /vsis3/, /vsigs/ ou /vsiaz/. Ou lorsque la destination est /vsiaz/ et la source est /vsis3/, /vsigs/, /vsiadls/ ou /vsicurl/

De manière similaire au comportement de rsync, si le nom du fichier source se termine par une barre oblique, cela signifie que le contenu du répertoire doit être copié, mais pas le nom du répertoire lui-même. Par exemple, en supposant que /home/even/foo contienne un fichier bar, gdal vsi sync -r /home/even/foo/ /mnt/media créera un fichier /mnt/media/bar. Alors que gdal vsi sync -r /home/even/foo /mnt/media créera un répertoire /mnt/media/foo qui contient un fichier bar.

Ceci est implémenté par VSISync().

Options

-r, --recursive
Synchroniser récursivement.
--strategy timestamp|ETag|overwrite
Détermine quel critère est utilisé pour déterminer si un fichier de destination doit être remplacé lorsqu'il existe déjà et a la même taille que la source. Ne s'applique que lorsque la source ou la destination est un système de fichiers réseau.

La valeur par défaut est timestamp (similaire au fonctionnement de aws s3 sync). Pour une opération de téléversement, un fichier distant est remplacé s'il a une taille différente ou s'il est plus ancien que la source. Pour une opération de téléchargement, un fichier local est remplacé s'il a une taille différente ou s'il est plus récent que le fichier distant.

La stratégie ETag suppose que la métadonnée ETag du fichier distant est le MD5Sum du contenu du fichier, ce qui n'est vrai que dans le cas de /vsis3/ pour les fichiers n'utilisant pas le chiffrement côté serveur KMS et téléversés en une seule opération PUT (donc inférieurs à 50 Mo compte tenu de la valeur par défaut utilisée par GDAL). À n'utiliser que pour /vsis3/, /vsigs/ ou d'autres systèmes de fichiers utilisant un MD5Sum comme ETAG.

La stratégie overwrite remplacera toujours le fichier de destination par celui de la source.

-j, --num-threads <valeur>
Nombre de tâches à exécuter simultanément

EXEMPLES

Exemple 1: Synchroniser un répertoire local sur un bucket S3

$ gdal vsi sync -r mon_repertoire/ /vsis3/bucket/mon_repertoire
