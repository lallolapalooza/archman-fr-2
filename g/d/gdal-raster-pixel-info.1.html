NOM

gdal-raster-pixel-info - Renvoie les informations sur un pixel d'un jeu de données raster

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal raster pixel-info [OPTIONS] <ENTRÉE> [<colonne,ligne> ou <X,Y>]
Renvoie les informations sur un pixel d'un jeu de données raster.
Arguments positionnels :
  -i, --dataset, --input <ENTRÉE>                       Jeu de données raster d'entrée [requis]
  -p, --pos, --position <colonne,ligne> ou <X,Y>       Position du pixel [peut être répété]
Options courantes :
  -h, --help                                           Affiche le message d'aide et quitte
  --json-usage                                         Affiche l'utilisation sous forme de document JSON et quitte
  --config <CLÉ>=<VALEUR>                              Option de configuration [peut être répétée]
Options :
  -f, --of, --format, --output-format <FORMAT-SORTIE>   Format de sortie. FORMAT-SORTIE=geojson|csv (par défaut : geojson)
  -b, --band <BANDE>                                   Bande(s) d'entrée (index à partir de 1) [peut être répété]
  --overview <NIVEAU-VUE-ENSEMBLE>                     Quel niveau de vue d'ensemble du fichier source doit être utilisé
  --position-crs <CRS-POSITION>                        CRS de la position (par défaut : pixel)
  -r, --resampling <RÉÉCHANTILLONNAGE>                 Algorithme de rééchantillonnage pour l'interpolation. RÉÉCHANTILLONNAGE=nearest|bilinear|cubic|cubicspline (par défaut : nearest)
Options avancées :
  --oo, --open-option <CLÉ>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --if, --input-format <FORMAT-ENTRÉE>                 Formats d'entrée [peut être répété]

DESCRIPTION

gdal raster pixel-info fournit un mécanisme pour interroger des informations sur un pixel étant donné sa localisation dans l'un des nombreux systèmes de coordonnées pris en charge.

Il prend en charge la sortie soit en GeoJSON soit en CSV.

Les éléments suivants seront signalés (lorsqu'ils sont connus) :

  • Coordonnées d'entrée
  • Coordonnées d'entrée converties en colonne, ligne
  • Valeur du pixel pour chaque bande sélectionnée, avec la valeur non mise à l'échelle
  • Pour les fichiers VRT, quels fichiers contribuent à la valeur du pixel.

Les options suivantes sont disponibles :

Options standard

-f, --of, --format, --output-format geojson|csv
Quel format de sortie utiliser. Par défaut, GeoJSON.
--oo <NOM>=<VALEUR>
Option d'ouverture du jeu de données (spécifique au format).

Peut être répétée.

--if <format>
Nom du format/pilote à tenter d'utiliser pour ouvrir le ou les fichiers d'entrée. Il est généralement inutile de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsque celle-ci échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichiers.

Peut être répétée.

-b <bande>
Sélectionne une bande à interroger. Plusieurs bandes peuvent être listées. Par défaut, toutes les bandes sont interrogées.
-p, --pos, --position <colonne,ligne> ou <X,Y>
Requis. Cela peut être spécifié soit comme une option, soit comme une valeur positionnelle après le nom du jeu de données, soit lorsque l'on appelle depuis gdal, sous forme de valeurs (séparées par des espaces) fournies sur l'entrée standard.

Par défaut, lorsque --position-crs n'est pas spécifié, ou est défini à pixel, il s'agit d'un couple colonne, ligne (éventuellement avec une partie fractionnaire). Si --position-crs est défini à dataset, il s'agit d'une coordonnée géoréférencée exprimée dans le CRS du jeu de données. Si --position-crs est spécifié avec une définition de CRS, il s'agit d'une coordonnée géoréférencée exprimée dans ce CRS.

X signifie toujours longitude ou est, Y signifie toujours latitude ou nord.

Plusieurs couples x,y peuvent être spécifiés.

--position-crs pixel|dataset|<définition-crs>
CRS de la position, ou l'une des deux valeurs spéciales suivantes :
  • pixel signifie que la position est définie comme colonne, ligne (par défaut)
  • dataset signifie que la position est une coordonnée géoréférencée exprimée dans le CRS du jeu de données.
-r, --resampling nearest|bilinear|cubic|cubicspline
Sélectionne un algorithme d'échantillonnage. Par défaut, nearest.

Les méthodes disponibles sont :

  • nearest applique un plus proche voisin.
  • bilinear applique un noyau de convolution bilinéaire.
  • cubic applique un noyau de convolution cubique.
  • cubicspline applique un noyau de convolution B-Spline.
--ovr, --overview <index>
Interroge la (niveau_vue_ensemble)ème vue d'ensemble (niveau_vue_ensemble=0 est la 1ère vue d'ensemble), au lieu de la bande de base. Notez que la localisation x,y (si le système de coordonnées est pixel/ligne) doit toujours être donnée par rapport à la bande de base.

EXEMPLES

Exemple 1 : Rapport sur le pixel colonne=5, ligne=10 du fichier byte.tif

$ gdal raster pixel-info byte.tif 5 10
{
  "type":"FeatureCollection",
  "crs":{
    "type":"name",
    "properties":{
      "name":"urn:ogc:def:crs:EPSG::26711"
    }
  },
  "features":[
    {
      "type":"Feature",
      "properties":{
        "input_coordinate":[
          5.0,
          10.0
        ],
        "column":5.0,
        "line":10.0,
        "bands":[
          {
            "band_number":1,
            "raw_value":132,
            "unscaled_value":132.0
          }
        ]
      },
      "geometry":{
        "type":"Point",
        "coordinates":[
          441020.0,
          3750720.0
        ]
      }
    }
  ]
}

Exemple 2 : Rapport sur le point aux coordonnées UTM 11N est=441320 et nord=3750720 sur le fichier byte.tif

$ gdal raster pixel-info --position-crs=dataset byte.tif 441320 3750720
{
  "type":"FeatureCollection",
  "crs":{
    "type":"name",
    "properties":{
      "name":"urn:ogc:def:crs:EPSG::26711"
    }
  },
  "features":[
    {
      "type":"Feature",
      "properties":{
        "input_coordinate":[
          441320.0,
          3750720.0
        ],
        "column":10.0,
        "line":10.0,
        "bands":[
          {
            "band_number":1,
            "raw_value":115,
            "unscaled_value":115.0
          }
        ]
      },
      "geometry":{
        "type":"Point",
        "coordinates":[
          441320.0,
          3750720.0
        ]
      }
    }
  ]
}

Exemple 4 : Rapport sur un point aux coordonnées WGS84 fournies sur l'entrée standard, dans l'ordre longitude, latitude.

$ echo -117.6355 33.8970 | gdal raster pixel-info --of=csv --position-crs=WGS84 byte.tif
-117.6355 33.8970 | gdal raster pixel-info --of=csv --position-crs=WGS84 byte.tif
