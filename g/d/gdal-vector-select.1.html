NOM

gdal-vector-select - Sélectionner un sous-ensemble de champs d'un jeu de données vectorielles

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal vector select [OPTIONS] <ENTREE> <SORTIE> <CHAMPS>
Sélectionner un sous-ensemble de champs d'un jeu de données vectorielles.
Arguments positionnels :
  -i, --input <ENTREE>                                 Jeux de données vectorielles d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données vectorielles de sortie [requis]
  --fields <CHAMPS>                                    Champs à sélectionner (ou exclure si --exclude) [peut être répété] [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <COUCHE-ENTREE>             Nom(s) de la couche d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>                Option de création [peut être répétée]
  --lco, --layer-creation-option <CLE>=<VALEUR>      Option de création de couche [peut être répétée]
  --overwrite                                          Autoriser la réécriture d'un fichier de sortie existant
  --update                                             Autoriser l'ouverture d'un jeu de données existant en mode mise à jour
  --overwrite-layer                                    Autoriser la réécriture d'une couche de sortie existante
  --append                                             Autoriser l'ajout à une couche existante
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <COUCHE-ACTIVE>                       Définir la couche active (si non spécifié, toutes)
  --exclude                                            Exclure les champs spécifiés
                                                       Mutuellement exclusif avec --ignore-missing-fields
  --ignore-missing-fields                              Ignorer les champs manquants
                                                       Mutuellement exclusif avec --exclude
Options avancées :
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLE>=<VALEUR>     Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector select peut être utilisé pour sélectionner un sous-ensemble de champs.

select peut également être utilisé comme une étape du gdal vector pipeline.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être obtenues avec gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données optionnelles qui peuvent être utilisées pour contrôler des détails sur le fichier créé. Par exemple, le pilote GeoPackage prend en charge les options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être listée avec l'option de ligne de commande --formats, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique du format Pilotes vectoriels pour les options de création légales pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser un fichier ou un jeu de données cible existant. Sinon, par défaut, gdal génère une erreur si le fichier ou le jeu de données cible existe déjà.
--active-layer <COUCHE-ACTIVE>
Définir la couche active. Lorsqu'elle est spécifiée, seule la couche nommée sera soumise au traitement. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront soumises au traitement.
--fields <CHAMPS>
Liste de champs séparés par des virgules à copier de la couche d'entrée vers la nouvelle couche (ou à exclure si --exclude est spécifié)

Les noms de champs contenant des espaces, des virgules ou des guillemets doubles doivent être entourés d'un guillemet double de début et de fin, et les guillemets doubles dans un nom de champ doivent être échappés avec une barre oblique inverse.

Selon le shell utilisé, cela peut nécessiter un guillemet supplémentaire. Par exemple, pour sélectionner champ_normal, un_champ_avec_espace, et virgule et un champ avec " guillemet double avec un shell Unix :

--fields "champ_normal,\"un_champ_avec_espace, et virgule\",\"un champ avec \\\" guillemet double\""

Un champ n'est sélectionné qu'une seule fois, même s'il est mentionné plusieurs fois dans la liste.

Les champs de géométrie peuvent également être spécifiés dans la liste. Si la couche source n'a pas de nom explicite pour le champ de géométrie, _ogr_geometry_ doit être utilisé pour sélectionner le champ de géométrie unique.

Spécifier un nom de champ source inexistant entraîne une erreur.

--ignore-missing-fields
Par défaut, si un champ spécifié par --fields n'existe pas dans les couches d'entrée, une erreur est émise et le traitement est arrêté. En spécifiant --ignore-missing-fields, seul un avertissement est émis et les champs inexistants sont simplement ignorés.
--exclude
Modifie le comportement de l'algorithme de telle sorte que tous les champs sont sélectionnés, à l'exception de ceux mentionnés par --fields.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichiers.

Peut être répété.

SORTIE GDALG (ENSEMBLE DE DONNÉES À LA VOLÉE / FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON à l'aide du format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel à l'aide du pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière à la volée / en flux.

EXEMPLES

>

Exemple 1 : Sélectionner le champ EAS_ID et le champ géométrie depuis un

Shapefile 
$ gdal vector
select in.shp o
ut.gpkg "EAS_I
D,_ogr_geometry
_" --overwrite

Exemple 2 : Supprimer des champs sensibles d'une

couche 
$ gdal vector
select in.shp
out.gpkg --e
xclude "name,s
urname,address" --overwrite
