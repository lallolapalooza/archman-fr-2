NOM

gdal-raster-footprint - Calculer l'empreinte d'un jeu de données raster

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal raster footprint [OPTIONS] <ENTRÉE>... <SORTIE>
Calculer l'empreinte d'un jeu de données raster.
Arguments positionnels :
  -i, --input <ENTRÉE>                                  Jeux de données raster d'entrée [peut être répété] [requis]
  -o, --output <SORTIE>                                 Jeu de données vectoriel de sortie [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation en document JSON et quitter
  --config <CLÉ>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -f, --of, --format, --output-format <FORMAT-SORTIE>   Format de sortie
  --co, --creation-option <CLÉ>=<VALEUR>               Option de création [peut être répétée]
  --lco, --layer-creation-option <CLÉ>=<VALEUR>        Option de création de couche [peut être répétée]
  --append                                             Autoriser l'ajout à une couche existante
  --overwrite                                          Autoriser l'écrasement de la sortie existante
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie (par défaut : footprint)
  -b, --band <BANDE>                                   Bande(s) d'entrée (index à partir de 1) [peut être répété]
  --combine-bands <COMBINE-BANDS>                      Définit comment les bandes de masque des bandes sélectionnées sont combinées pour générer une seule bande de masque, avant d'être vectorisées. COMBINE-BANDS=union|intersection (par défaut : union)
  --overview <OVERVIEW>                                Niveau d'aperçu du fichier source à utiliser
                                                       Exclusif mutuellement avec --src-nodata
  --src-nodata <SRC-NODATA>                            Définir les valeurs nodata pour les bandes d'entrée. [1.. valeurs]
                                                       Exclusif mutuellement avec --overview
  --coordinate-system <COORDINATE-SYSTEM>              Système de coordonnées cible. COORDINATE-SYSTEM=georeferenced|pixel
  --dst-crs <DST-CRS>                                 SCR de destination
  --split-multipolygons                                Diviser les multipolygones en plusieurs entités, chacune avec un seul polygone
  --convex-hull                                        Calculer l'enveloppe convexe de l'empreinte
  --densify-distance <DENSIFY-DISTANCE>                Distance maximale entre 2 points consécutifs de la géométrie de sortie.
  --simplify-tolerance <SIMPLIFY-TOLERANCE>            Tolérance utilisée pour fusionner les points consécutifs de la géométrie de sortie.
  --min-ring-area <MIN-RING-AREA>                      Valeur minimale pour l'aire d'un anneau
  --max-points <MAX-POINTS>                            Nombre maximal de points de chaque géométrie de sortie (par défaut : 100)
  --location-field <LOCATION-FIELD>                    Nom du champ où le chemin du jeu de données d'entrée sera stocké. (par défaut : location)
                                                       Exclusif mutuellement avec --no-location-field
  --no-location-field                                  Désactiver la création d'un champ avec le chemin du jeu de données d'entrée
                                                       Exclusif mutuellement avec --location-field
  --absolute-path                                      Stocker le chemin du jeu de données d'entrée comme chemin absolu
Options avancées :
  --oo, --open-option <CLÉ>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --if, --input-format <FORMAT-ENTRÉE>                 Formats d'entrée [peut être répété]

DESCRIPTION

gdal raster footprint calcule l'empreinte d'un fichier raster, en prenant en compte les valeurs nodata (ou plus généralement la bande de masque attachée aux bandes raster), et en générant des polygones/multipolygones correspondant aux zones où les pixels sont valides, puis écrit dans un fichier vectoriel de sortie.

Depuis GDAL 3.12, cet algorithme peut faire partie d'un pipeline gdal.

L'utilitaire gdal raster clean-collar peut être exécuté comme étape de prétraitement pour générer des bandes de masque appropriées.

Les options suivantes sont disponibles :

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être obtenues par gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoTIFF prend en charge des options de création pour contrôler la compression et si le fichier doit être tuilé.

Peut être répétée.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats mais la documentation du format est la source définitive d'informations sur les options de création du pilote. Voir Pilotes raster documentation spécifique au format pour les options de création légales de chaque format.

--layer-creation-option <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de couche facultatives qui peuvent être utilisées pour contrôler les particularités de la couche créée. Par exemple, le pilote GeoPackage prend en charge des options de création de couche pour contrôler l'identifiant d'entité ou le nom de la colonne géométrique, définir l'identifiant ou la description, etc.

Peut être répétée.

Les options de création de couche disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création de couche. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats mais la documentation du format est la source définitive d'informations sur les options de création du pilote. Voir Pilotes vectoriels documentation spécifique au format pour les options de création légales de chaque format.

Notez que les options de création de couche sont différentes des options de création de jeu de données.

--output-layer <COUCHE-SORTIE>
Nom de la couche de sortie. Par défaut : footprint.
--overwrite
Autoriser le programme à écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal génère une erreur si le fichier ou le jeu de données cible existe déjà.
--append
Autoriser l'ajout d'entités aux couches existantes
-b <bande>
Sélectionner une <bande> d'entrée à traiter. Les bandes sont numérotées à partir de 1. Plusieurs -b peuvent être utilisés pour sélectionner un ensemble de bandes d'entrée. Si non spécifié, toutes les bandes sont prises en compte. La façon dont les bandes multiples sont combinées est contrôlée par --combine-bands
--combine-bands union|intersection
Définit comment les bandes de masque des bandes sélectionnées sont combinées pour générer une seule bande de masque, avant d'être vectorisées. La valeur par défaut est union: c'est-à-dire qu'un pixel est valide s'il est valide au moins pour l'une des bandes sélectionnées. intersection signifie qu'un pixel n'est valide que s'il est valide pour toutes les bandes sélectionnées.
--ovr <index>
Pour spécifier quel niveau d'aperçu du fichier source doit être utilisé, lorsque des aperçus sont disponibles sur le raster source. Par défaut, le niveau de pleine résolution est utilisé. L'index commence à 0, c'est-à-dire que 0 signifie le premier niveau d'aperçu. Cette option est exclusivement mutuelle avec --src-nodata.
--src-nodata <valeur>
Définir les valeurs valeurs pour les bandes d'entrée (des valeurs différentes peuvent être fournies pour chaque bande). Si une seule valeur est spécifiée, elle s'applique à toutes les bandes sélectionnées. Si plus d'une valeur est fournie, il doit y avoir autant de valeurs que de bandes sélectionnées, et toutes les valeurs doivent être entre guillemets pour rester groupées en un seul argument du système d'exploitation. Si l'option n'est pas spécifiée, la bande de masque intrinsèque de chaque bande sélectionnée sera utilisée.
--coordinate-system pixel|georeferenced
Système de coordonnées cible. Par défaut, si le jeu de données d'entrée est géoréférencé, georeferenced est implicite, c'est-à-dire que la géométrie de l'empreinte sera exprimée en coordonnées dans le SCR du raster (ou celui spécifié avec --dst-crs). Si l'on spécifie pixel, les coordonnées de la géométrie de l'empreinte sont des indices de colonne et de ligne.
--dst-crs <CRS_DEF>
SCR cible du fichier de sortie. Le <CRS_DEF> peut être n'importe lequel des formats habituels de GDAL/OGR, WKT complet, PROJ.4, EPSG:n ou un fichier contenant le WKT. Spécifier cette option implique --coordinate-system=georeferenced. L'empreinte est reprojetée depuis le SCR du raster source vers le SCR spécifié.
--split-multipolygons
Lorsqu'il est spécifié, les multipolygones sont divisés en plusieurs entités, chacune avec un seul polygone.
--convex-hull
Lorsqu'il est spécifié, l'enveloppe convexe des (multi)polygones est calculée.
--densify-distance <value>
La valeur spécifiée de cette option est la distance maximale entre 2 points consécutifs de la géométrie de sortie. L'unité de la distance est en pixels si --coordinate-system est égal à pixel, ou sinon en unités géoréférencées du raster source. Cette option est appliquée avant la reprojection impliquée par --dst-crs.
--simplify-tolerance <value>
La valeur spécifiée de cette option est la tolérance utilisée pour fusionner les points consécutifs de la géométrie de sortie à l'aide de la méthode OGRGeometry::Simplify() . L'unité de la distance est en pixels si --coordinate-system est égal à pixel, ou sinon en unités géoréférencées du jeu de données vectoriel cible. Cette option est appliquée après la reprojection impliquée par --dst-crs.
--min-ring-area <value>
Valeur minimale pour l'aire d'un anneau. L'unité de l'aire est en pixels carrés si --coordinate-system est égal à pixel, ou sinon en unités géoréférencées du jeu de données vectoriel cible. Cette option est appliquée après la reprojection impliquée par --dst-crs
--max-points <value>|unlimited
Nombre maximal de points de chaque géométrie de sortie (ne comptant pas le point de fermeture de chaque anneau, qui est toujours identique au premier point). La valeur par défaut est 100. unlimited peut être utilisé pour supprimer cette limitation.
--location-field <field_name>
Spécifie le nom du champ dans le jeu de données vectoriel résultant où le chemin du jeu de données d'entrée sera stocké. Le nom du champ par défaut est « location ». Pour éviter d'écrire le chemin du jeu de données d'entrée, utilisez --no-location-field
--no-location-field
Désactive l'écriture du chemin du jeu de données d'entrée en tant que champ dans le jeu de données vectoriel de sortie.
--absolute-path
Permet d'écrire le chemin absolu du jeu de données d'entrée. Par défaut, le nom de fichier est écrit dans le champ de localisation exactement tel que spécifié sur la ligne de commande.

Les opérations géométriques post-vectorisation sont appliquées dans l'ordre suivant :

  • division facultative (--split-multipolygons)
  • densification facultative (--densify-distance)
  • reprojection facultative (--dst-crs)
  • filtrage facultatif par aire minimale d'anneau (--min-ring-area)
  • application facultative de l'enveloppe convexe (--convex-hull)
  • simplification facultative (--simplify-tolerance)
  • limitation du nombre de points (--max-points)

Ajouté dans la version 3.12.

SORTIE GDALG (JEU DE DONNÉES EN FLUX / À LA VOLÉE)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG . Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel à l'aide du pilote GDALG : GDAL Streamed Algorithm , et appliquer le pipeline spécifié de manière en flux / à la volée.

NOTE :

Cependant, cet algorithme n'est pas nativement compatible avec le streaming. Par conséquent, un jeu de données temporaire en mémoire sera généré, ce qui peut entraîner un temps de traitement important à l'ouverture.

EXEMPLES

Exemple 1 : Écrire l'empreinte d'un fichier GeoTIFF dans un fichier GeoJSON.

gdal raster footprint my_raster.tif footprint.geojson
