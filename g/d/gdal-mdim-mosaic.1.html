NOM

gdal-mdim-mosaic - Construire une mosaïque, virtuelle (VRT) ou matérialisée, à partir de jeux de données multidimensionnels

Ajouté dans la version 3.12.

SYNTAXE

Usage: gdal mdim mosaic [OPTIONS] <ENTRÉE>... <SORTIE>
Construire une mosaïque, virtuelle (VRT) ou matérialisée, à partir de jeux de données multidimensionnels.
Arguments positionnels :
  -i, --input <ENTRÉE>                                  Jeux de données raster multidimensionnels d'entrée [1.. valeurs] [requis]
  -o, --output <SORTIE>                                Jeu de données raster multidimensionnel de sortie (créé par l'algorithme) [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>                                Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie
  --co, --creation-option <CLÉ>=<VALEUR>                Option de création [peut être répétée]
  --overwrite                                          Autoriser l'écrasement de la sortie existante
  --array <TABLEAU>                                      Nom du ou des tableaux à mosaiquer. [peut être répété]
Options avancées :
  --oo, --open-option <CLÉ>=<VALEUR>                    Options d'ouverture [peut être répétée]
  --if, --input-format <FORMAT-ENTRÉE>                 Formats d'entrée [peut être répété]

DESCRIPTION

gdal mdim mosaic construit une mosaïque de tableaux multidimensionnels à partir d'une liste de jeux de données GDAL multidimensionnels d'entrée. Cette mosaïque peut être une mosaïque virtuelle au format Multidimensional VRT (Virtual Dataset), ou dans un format multidimensionnel plus conventionnel comme NetCDF: Network Common Data Form ou Zarr.

Les caractères génériques '*', '?' ou '['] de VSIGlob() peuvent être utilisés pour les noms des jeux de données d'entrée, même pour des fichiers situés sur des systèmes de fichiers réseau tels que /vsis3/, /vsigs/, /vsiaz/, etc. Alternativement, si un nom de jeu de données d'entrée est précédé du caractère @, il sera supposé contenir la liste des noms de jeux de données réels (un par ligne) à utiliser comme jeux de données d'entrée.

Pour créer une mosaïque à partir d'un tableau, certaines contraintes structurelles s'appliquent à tous les tableaux contributeurs des jeux de données d'entrée :

  • Tous les tableaux contributeurs doivent avoir le même nom et chemin de tableau (par exemple, "/measurements/pressure").
  • Ils doivent avoir le même type de données et la même valeur nodata.
  • Ils doivent partager le même nombre de dimensions, dans le même ordre, et avec les mêmes noms.
  • chaque dimension du tableau doit avoir une variable d'indexation numérique unidimensionnelle associée.

Un cas d'utilisation typique est lorsqu'un tableau multidimensionnel est découpé en plusieurs fichiers, et que l'on souhaite reconstruire le tableau complet.

Le programme peut prendre en charge la mosaique le long de plusieurs axes.

Il peut y avoir des « trous » parmi les jeux de données sources le long des dimensions mosaiquées, et éventuellement des chevauchements (mais seulement lors d'un espacement régulier le long d'une dimension mosaiquée). Les trous sont remplis avec la valeur nodata, si elle est définie dans les tableaux sources, ou initialisés à zéro sinon. En cas de chevauchement, l'ordre de la liste d'entrée est utilisé pour déterminer la priorité. Les fichiers listés à la fin sont ceux à partir desquels le contenu sera récupéré.

Différents cas d'utilisation typiques qui peuvent être traités par ce programme sont :

  • un tableau 3D est découpé le long d'une seule dimension (par exemple, temporelle) en plusieurs fichiers, chaque tranche ayant un échantillon le long de cette dimension. Dans ce cas d'utilisation, les horodatages des tranches n'ont pas besoin d'être régulièrement espacés.
  • un tableau 2D est découpé/tuilé le long des dimensions X et Y, avec un espacement régulier le long de ces dimensions X et Y, et où les valeurs de coordonnées sont alignées sur la même grille parmi les tuiles.

Par défaut, un tableau cible est créé pour chaque tableau à deux dimensions ou plus. Ce comportement peut être restreint à des tableaux spécifiques à l'aide de l'option --array.

Les options suivantes sont disponibles :

Options standard

-i, --input <ENTRÉE>
Noms des jeux de données multidimensionnels d'entrée. Requis.

Les caractères génériques '*', '?' ou '['] de VSIGlob() peuvent être utilisés pour les noms des jeux de données d'entrée, même pour des fichiers situés sur des systèmes de fichiers réseau tels que /vsis3/, /vsigs/, /vsiaz/, etc. Alternativement, si un nom de jeu de données d'entrée est précédé du caractère @, il sera supposé contenir la liste des noms de jeux de données réels (un par ligne) à utiliser comme jeux de données d'entrée.

-o, --output <SORTIE>
Nom du jeu de données multidimensionnel de sortie. Requis.
-f, --of, --format, --output-format <FORMAT-SORTIE>
Sélectionne le format de sortie. Il peut s'agir d'un format qui prend en charge la sortie multidimensionnelle (tel que NetCDF: Network Common Data Form, Multidimensional VRT). Lorsque cette option n'est pas spécifiée, le format est deviné lorsque cela est possible à partir de l'extension du nom de fichier de destination.
--co, --creation-option <CLÉ>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être affichée avec l'option de ligne de commande --format, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique du format Pilotes raster pour connaître les options de création légales pour chaque format.

Les options de création au niveau du tableau peuvent être passées en les préfixant par ARRAY:. Voir GDALGroup::CopyFrom() pour plus de détails concernant ces options.

--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal signale une erreur si le fichier ou le jeu de données cible existe déjà.
--array <TABLEAUX>
Nom ou chemin complet d'un ou plusieurs tableaux à mosaiquer. Si non spécifié, un tableau cible est créé pour chaque tableau ayant deux dimensions ou plus.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture du jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à essayer pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichiers.

Peut être répété.

EXEMPLES

Exemple 1 : Mosaiquer plusieurs fichiers netCDF commençant par slice qui sont des tranches d'un tableau 3D

gdal mdim mosaic slice*.nc out.vrt
