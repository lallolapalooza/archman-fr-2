NOM

gdal-raster-polygonize - Créer un jeu de données d'entités polygonales à partir d'une bande raster

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal raster polygonize [OPTIONS] <ENTRÉE> <SORTIE>
Créer un jeu de données d'entités polygonales à partir d'une bande raster.
Arguments positionnels :
  -i, --input <ENTRÉE>                                  Jeux de données raster d'entrée [requis]
  -o, --output <SORTIE>                                 Jeu de données vectoriel de sortie [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -f, --of, --format, --output-format <FORMAT-DE-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLÉ>=<VALEUR>               Option de création [peut être répétée]
  --lco, --layer-creation-option <CLÉ>=<VALEUR>        Option de création de couche [peut être répétée]
  --overwrite                                          Autoriser l'écrasement de la sortie existante
  --update                                              Ouvrir le jeu de données existant en mode mise à jour
  --overwrite-layer                                    Autoriser l'écrasement de la couche de sortie existante
  --append                                             Autoriser l'ajout à une couche existante
  --output-layer <COUCHE-DE-SORTIE>                    Nom de la couche de sortie
  -b, --band <BANDE>                                   Bande d'entrée (index basé sur 1) (par défaut : 1)
  --attribute-name <NOM-D'ATTRIBUT>                    Nom du champ avec la valeur de pixel (par défaut : DN)
  -c, --connect-diagonal-pixels                        Considérer les pixels diagonaux comme connectés
Options avancées :
  --if, --input-format <FORMAT-D'ENTRÉE>               Formats d'entrée [peut être répétée]
  --oo, --open-option <CLÉ>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLÉ>=<VALEUR>     Options d'ouverture de sortie [peut être répétée]

DESCRIPTION

gdal raster polygonize crée des polygones vectoriels pour toutes les régions connectées de pixels dans le raster partageant une valeur de pixel commune. Chaque polygone est créé avec un attribut indiquant la valeur de pixel de ce polygone. Les pixels définis sur la valeur NoData, ou masqués à l'aide d'une bande de masque externe, ne sont pas inclus dans le traitement.

L'utilitaire peut créer le jeu de données vectoriel de sortie s'il n'existe pas déjà, sinon il peut y ajouter des éléments.

L'utilitaire est basé sur la :GDALPolygonize() fonction qui contient des détails supplémentaires sur l'algorithme.

Depuis GDAL 3.12, cet algorithme peut faire partie d'un pipeline gdal.

Options standard

-f, --of, --format, --output-format <FORMAT-DE-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être données par gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoTIFF prend en charge des options de création pour contrôler la compression et si le fichier doit être tuilé.

Peut être répétée.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont pas d'options de création du tout. Une liste des options prises en charge pour un format peut être listée avec l'option de ligne de commande --formats mais la documentation du format est la source définitive d'informations sur les options de création du pilote. Voir Pilotes raster documentation spécifique au format pour les options de création légales de chaque format.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Autoriser le programme à écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal échoue si le fichier ou le jeu de données cible existe déjà.
--update
Si le jeu de données de sortie doit être ouvert en mode mise à jour. Implique qu'il existe déjà.
--overwrite-layer
Si l'écrasement de la couche vectorielle de sortie existante est autorisé.
--append
Si l'ajout d'entités à la couche vectorielle de sortie existante est autorisé
-b, --band <BANDE>
Sélectionne une bande particulière à polygoniser. Par défaut, la bande 1.
--nln, --output-layer <COUCHE-DE-SORTIE>
Fournit un nom pour la couche vectorielle de sortie. Par défaut, "polygonize".
--attribute-name <NOM-D'ÉLÉVATION>
Le nom du champ à créer (par défaut "DN").
-c, --connect-diagonal-pixels
Considérer les pixels diagonaux (pixels aux coins) comme connectés. Le comportement par défaut est de ne considérer comme connectés que les pixels qui se touchent par les bords, ce qui équivaut à une 4-connectivité. Lorsque cette option est sélectionnée, l'algorithme considérera également les pixels aux coins comme connectés, ce qui équivaut à une 8-connectivité.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répétée.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsque celle-ci échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichiers.

Peut être répétée.

Ajouté dans la version 3.12.

SORTIE GDALG (JEU DE DONNÉES À LA VOLÉE / EN FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande en tant que fichier JSON à l'aide du format de sortie GDALG . Le fichier résultant peut ensuite être ouvert en tant que jeu de données vectoriel à l'aide du pilote GDALG : GDAL Streamed Algorithm et appliquer le pipeline spécifié de manière à la volée / en flux.

NOTE :

Cependant, cet algorithme n'est pas nativement compatible avec le streaming. Par conséquent, un jeu de données temporaire en mémoire sera généré, ce qui peut entraîner un temps de traitement important à l'ouverture.

EXEMPLES

Exemple 1 : Créer un shapefile avec des polygones pour les régions connectées de la bande 1 du GeoTIFF d'entrée.

gdal raster polygonize input.tif polygonize.shp
