NOM

gdal-vector-check-coverage - Vérifier la couverture de polygones pour la validité

Ajouté en version 3.12.

SYNOPSIS

Usage: gdal vector check-coverage [OPTIONS] <ENTREE> <SORTIE>
Vérifier la validité d'une couverture de polygones
Arguments positionnels :
  -i, --input <ENTREE>                                 Datasets vectoriels d'entrée [requis]
  -o, --output <SORTIE>                                Dataset vectoriel de sortie [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <COUCHE-ENTREE>           Nom(s) de la couche d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>               Option de création [peut être répétée]
  --lco, --layer-creation-option <CLE>=<VALEUR>        Option de création de couche [peut être répétée]
  --overwrite                                          Autoriser l'écrasement de la sortie existante
  --update                                             Ouvrir le dataset existant en mode mise à jour
  --overwrite-layer                                    Autoriser l'écrasement de la couche existante
  --append                                             Ajouter à la couche existante
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --include-valid                                      Inclure les entrées valides dans la sortie, avec géométrie vide
  --geometry-field <CHAMP-GEOMETRIE>                   Nom du champ de géométrie à vérifier
  --maximum-gap-width <LARGEUR-MAX-ECART>              Largeur maximale d'un écart à signaler
Options avancées :
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLE>=<VALEUR>     Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Upsert des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector check-coverage vérifie si un jeu de données de polygones forme une couverture valide, c'est-à-dire :

  • aucun polygone ne se chevauche
  • tous les bords partagés ont des nœuds aux mêmes emplacements
  • les écarts entre les polygones sont plus grands qu'une largeur spécifiée

Pour chaque polygone ne satisfaisant pas ces critères, une entité linéaire est produite avec la géométrie du bord invalide. Si la couverture est valide, le jeu de données de sortie sera vide à moins que --include-valid ne soit utilisé.

Il est supposé que les polygones individuels sont eux-mêmes valides conformément au standard OGC Simple Features. Ceci peut être vérifié par gdal vector check-geometry.

NOTE :

Cette commande nécessite une compilation GDAL contre la bibliothèque GEOS (version 3.12 ou supérieure).

Options standard

--geometry-field
Spécifie le nom du champ de géométrie à tester, pour les couches ayant plusieurs champs de géométrie. Par défaut, le premier champ de géométrie sera utilisé.
--include-valid
Inclut les entités pour les géométries valides dans la sortie, en maintenant une correspondance 1:1 entre les entités d'entrée et de sortie.
--maximum-gap-width <LARGEUR-MAX-ECART>
Définit la plus grande zone qui doit être considérée comme un écart.
-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être données par gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données optionnelles qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoPackage prend en charge des options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être listée avec l'option de commande --formats, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique au format Pilotes vectoriels pour les options de création légales pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique des pilotes, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichier.

Peut être répété.

SORTIE GDALG (DU DATASET EN TEMPS RÉEL / PAR FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel en utilisant le pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière à la volée / par flux.

NOTE :

Cependant, cet algorithme n'est pas compatible nativement avec le streaming. Par conséquent, un jeu de données temporaire en mémoire sera généré, ce qui peut entraîner un temps de traitement important à l'ouverture.
