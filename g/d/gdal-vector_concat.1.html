DESCRIPTIO

N

gdal vector concat concatène plusieurs jeux de données

sources.

Il possède 3 modes principaux

:
  • --mode = merge-per-layer-name (le défaut). Le jeu de données de sortie généré par la commande contiendra autant de couches qu'il y a de noms de couches différents dans les jeux de données sources. Par exemple, s'il y a 2 jeux de données, l'un avec les couches a et b, et l'autre avec les couches b et c, 3 couches de sortie seront créées : a, b (fusionnant les 2 couches sources) et c
    • .
  • --mode = stack. Le jeu de données de sortie généré par la commande contiendra autant de couches qu'il y a de couches dans les jeux de données sources. Par exemple, s'il y a 2 jeux de données ds1 (avec les couches a et b) et ds2 (avec les couches b et c), 4 couches de sortie seront créées : ds1_a, ds1_b, ds2_b et ds2_
    • c.
  • --mode = single. Le jeu de données de sortie généré par la commande
    • contiendra une seule couche,
fusionnant toutes les couches d
es jeux de données sources.

Lorsqu'une couche de sortie fusionne plusieurs couches sources, par défaut le schéma résultant contiendra l'union de tous les champs sources. Il est possible de ne sélectionner que l'intersection avec --field-strategy défini à intersection. Concernant le système de coordonnées résultant, par défaut le système de coordonnées de la couche source sera utilisé comme système de coordonnées cible, et les entités des autres couches sources qui ne correspondent pas à ce système de coordonnées seront reprojetées vers celui-ci. --dst-crs peut être utilisé pour sélectionner un système de coordonnées de destination

donné.

Cette commande peut également être utilisée comme première étape d'un gdal vector p

ipeline.
