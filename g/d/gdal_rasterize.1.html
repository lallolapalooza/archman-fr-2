NOM

gdal_rasterize - Graver des géométries vectorielles dans une image raster.

SYNTAXE

Utilisation : gdal_rasterize [--help] [--long-usage] [--help-general]
                      [-b <band>]... [-i] [-at]
                      [[-burn <valeur>]...|[-a <nom_attribut>]|[-3d]]
                      [-add]
                      [[-l <nom_couche>]...|[-sql <instruction_sql>]]
                      [-where <expression>] [-dialect <dialecte_sql>]
                      [-a_nodata <valeur>] [-init <valeur>]... [-a_srs <def_srs>]
                      [-to <NOM>=<VALEUR>]... [-te <xmin> <ymin> <xmax> <ymax>]
                      [[-tr <res_x> <res_y>]|[-ts <largeur> <hauteur>]]
                      [-tap] [-optim AUTO|VECTOR|RASTER] [-co <NOM>=<VALEUR>]...
                      [-ot Byte|Int8|[U]Int{16|32|64}|CInt{16|32}|[C]Float{32|64}]
                      [-of <format_sortie>] [--quiet] [-oo <NOM>=<VALEUR>]...
                      <source_donnees> <fichier_destination>

DESCRIPTION

Ce programme grave des géométries vectorielles (points, lignes et polygones) dans la ou les bandes raster d'une image raster. Les vecteurs sont lus à partir de formats vectoriels supportés par OGR. Si le raster de sortie existe déjà, les pixels affectés sont mis à jour sur place.

La reprojection à la volée des données vectorielles dans le système de coordonnées des données raster est supportée.

--help
Affiche ce message d'aide et quitte.
--help-general
Donne un bref message d'utilisation pour les options génériques de ligne de commande GDAL et quitte.
-b <bande>
La ou les bandes dans lesquelles graver les valeurs. Plusieurs options -b peuvent être utilisées pour graver dans une liste de bandes. Par défaut, la gravure se fait dans la bande 1. Non utilisé lors de la création d'un nouveau raster.
-i
Inverse la rasterisation. Grave la valeur de gravure fixe, ou la valeur de gravure associée à la première entité dans toutes les parties de l'image *pas* à l'intérieur du polygone fourni.

NOTE :

Lorsque les entités vectorielles contiennent un polygone imbriqué dans un autre polygone (comme une île dans un lac), GDAL doit être compilé contre GEOS pour obtenir des résultats corrects.
-at
Active l'option de rasterisation ALL_TOUCHED de sorte que tous les pixels touchés par des lignes ou des polygones soient mis à jour, pas seulement ceux sur le chemin de rendu de la ligne, ou dont le point central est dans le polygone (le comportement n'est pas spécifié lorsque le polygone touche seulement le centre du pixel). Désactivé par défaut pour les règles de rendu normales.

NOTE :

Lorsque cette option est activée, l'ordre des entités d'entrée (lignes ou polygones) peut affecter les résultats. Lorsque deux entités se touchent, la dernière (c'est-à-dire la plus haute) déterminera la valeur du pixel gravé au bord. Vous pourriez souhaiter utiliser l'option -sql pour réordonner les entités (ORDER BY) afin d'obtenir un résultat plus prévisible.
-burn <valeur>
Une valeur fixe à graver dans une bande pour tous les objets. Une liste d'options -burn peut être fournie, une par bande à écrire.
-a <nom_attribut>
Identifie un champ d'attribut sur les entités à utiliser comme valeur de gravure. La valeur sera gravée dans toutes les bandes de sortie.
-3d
Indique qu'une valeur de gravure doit être extraite des valeurs "Z" de l'entité. Fonctionne avec les points et les lignes (interpolation linéaire le long de chaque segment). Pour les polygones, fonctionne correctement uniquement s'ils sont plats (même valeur Z pour tous les sommets).
-add
Au lieu de graver une nouvelle valeur, ceci ajoute la nouvelle valeur au raster existant. Approprié pour les cartes de chaleur par exemple.
-l <nom_couche>
Indique la ou les couches de la source de données qui seront utilisées pour les entités d'entrée. Peut être spécifié plusieurs fois, mais au moins un nom de couche ou une option -sql doit être spécifié (pas les deux).
-where <expression>
Une expression de requête optionnelle de style WHERE SQL à appliquer pour sélectionner les entités à graver à partir de la ou des couches d'entrée.
-sql <instruction_select>
Une instruction SQL à évaluer sur la source de données pour produire une couche virtuelle d'entités à graver. À partir de GDAL 3.7, la syntaxe @nom_fichier peut être utilisée pour indiquer que le contenu se trouve dans le fichier indiqué.

NOTE :

Cette option sera ignorée si l'option -l a été définie également.
-dialect <dialecte>
Dialecte SQL. Dans certains cas, peut être utilisé pour utiliser SQL OGR (non optimisé) au lieu du SQL natif d'un SGBDR en passant OGRSQL. Le dialecte "SQLITE" peut également être utilisé avec n'importe quelle source de données.
-of <format>
Sélectionne le format de sortie. S'il n'est pas spécifié, le format est deviné à partir de l'extension. Utiliser le nom court du format.
-a_nodata <valeur>
Attribue une valeur nulle spécifiée aux bandes de sortie.
-init <valeur>
Pré-initialise les bandes de l'image de sortie avec ces valeurs. Cependant, elles ne sont pas marquées comme valeur nulle dans le fichier de sortie. Si une seule valeur est donnée, la même valeur est utilisée dans toutes les bandes.
-a_srs <def_srs>
Remplace la projection pour le fichier de sortie. Si non spécifié, la projection du fichier vectoriel d'entrée sera utilisée si disponible. Lors de l'utilisation de cette option, aucune reprojection des entités du SRS vectoriel source vers le SRS spécifié de la sortie raster, utilisez donc cette option uniquement pour corriger un SRS source invalide. La <def_srs> peut être l'une des formes GDAL/OGR habituelles, WKT complet, PROJ.4, EPSG:n ou un fichier contenant le WKT.
-to <NOM>=<VALEUR>
Définit une option de transformation appropriée à passer à GDALCreateGenImgProjTransformer2(). Ceci est utilisé lors de la conversion des coordonnées des géométries dans l'espace pixel raster cible. Par exemple, ceci peut être utilisé pour spécifier des options de transformation liées aux RPC.
-co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création optionnelles qui peuvent être utilisées pour contrôler des détails du fichier créé. Par exemple, le pilote GeoTIFF supporte des options de création pour contrôler la compression, et si le fichier doit être tuilé.

Les options de création disponibles varient selon le pilote du format, et certains formats simples n'ont aucune option de création. Une liste des options supportées pour un format peut être listée avec l'option de ligne de commande --format, mais la documentation du format est la source définitive d'information sur les options de création du pilote. Voir la documentation spécifique au format des Pilotes raster pour les options de création légales pour chaque format.

-te <xmin> <ymin> <xmax> <ymax>
Définit l'étendue de la zone d'intérêt (Extent) pour la sortie raster. Par défaut, l'étendue est déterminée par l'étendue des entités vectorielles d'entrée, mais cela peut être modifié par cette option. Les unités sont celles du système de coordonnées cible.
-tr <res_x> <res_y>
Définit la résolution du pixel de sortie en unités du système de coordonnées cible. Par défaut, la résolution est déterminée par la source de données vectorielle (si elle est géoréférencée) ou par le rapport de l'étendue et des dimensions du raster de sortie (si -ts est utilisé). La valeur de -tr peut être négative.

NOTE :

Si les deux options -tr et -ts sont spécifiées, la dernière l'emporte.
-ts <largeur> <hauteur>
Définit la taille du raster de sortie en nombre de pixels. La résolution est déterminée par le rapport de l'étendue et de la taille spécifiée.

NOTE :

Si les deux options -tr et -ts sont spécifiées, la dernière l'emporte.
-tap
Active l'option align_to_max_extent. Aligne l'étendue de sortie sur le maximum des deux étendue d'entrée et de sortie. Pour les rasters de sortie, l'étendue est celle définie par les options -te, -tr ou -ts. Pour les sources de données vectorielles, il s'agit de l'étendue des entités d'entrée. Utile quand on rasterise des données vectorielles dans un raster existant.
-optim <AUTO|VECTOR|RASTER>
Choisit l'algorithme d'optimisation à utiliser pour la rasterisation. "AUTO" sélectionne automatiquement l'algorithme le plus performant. "VECTOR" utilise un algorithme optimisé pour les sources de données vectorielles. "RASTER" utilise un algorithme optimisé pour les sources de données raster. La valeur par défaut est "AUTO".
-ot <type>
Type de données de sortie pour les bandes raster. Les options sont Byte, Int8, UInt16, Int16, UInt32, Int32, Float32, Float64, etc. Par défaut, le type de données du raster de sortie est celui des données source, si spécifié, sinon il est déterminé par les valeurs de gravure.
--quiet
Supprime l'affichage de la barre de progression et des messages.
-oo <NOM>=<VALEUR>
Options d'ouverture de jeu de données pour la source de données (par exemple, pour le format VRT).
<source_donnees>
La source de données vectorielles. Peut être un fichier, un nom de couche dans un fichier, ou une URL.
<fichier_destination>
Le fichier raster de destination. S'il existe, il sera mis à jour. Sinon, il sera créé.

EXEMPLES

Graver un polygone d'un fichier Shapefile nommé 'polygons.shp' dans un fichier GeoTIFF nommé 'output.tif' avec une valeur de 1:

$ gdal_rasterize -b 1 -burn 1 polygons.shp output.tif

Graver les entités d'une couche PostgreSQL nommée 'roads' (avec un code de déplacement de 255) dans un raster GDAL existant 'existing.tif':

$ gdal_rasterize -b 1 -a_nodata 0 -burn 255 PG:"host=localhost dbname=mydb
    user=myuser password=mypass" -l roads existing.tif

Graver les entités d'un fichier GeoJSON 'buildings.geojson' dans un nouveau fichier GeoTIFF 'buildings.tif' avec une valeur extraite du champ 'height':

$ gdal_rasterize -a height buildings.geojson buildings.tif

Graver les entités d'un fichier GeoJSON 'roads.geojson' dans un nouveau fichier GeoTIFF 'roads.tif' avec une résolution de 5 mètres par 5 mètres:

$ gdal_rasterize -tr 5.0 5.0 roads.geojson roads.tif

Graver les entités d'un fichier GeoJSON 'land.geojson' dans un nouveau fichier GeoTIFF 'land.tif' en utilisant l'option ALL_TOUCHED:

$ gdal_rasterize -at land.geojson land.tif

Graver les entités d'un fichier GeoJSON 'rivers.geojson' dans un nouveau fichier GeoTIFF 'rivers.tif' en utilisant l'option ALL_TOUCHED et en spécifiant l'étendue du fichier:

$ gdal_rasterize -at -te -10 20 30 50 rivers.geojson rivers.tif

Graver des entités d'un fichier GeoJSON 'points.geojson' dans un nouveau fichier GeoTIFF 'points.tif' en utilisant l'option ALL_TOUCHED et en spécifiant une résolution et une étendue:

$ gdal_rasterize -at -tr 100 100 -te -10 20 30 50 points.geojson points.tif

Graver les entités d'un fichier GeoJSON 'features.geojson' dans un nouveau fichier GeoTIFF 'features.tif' en utilisant l'option ALL_TOUCHED et en spécifiant une taille et une étendue:

$ gdal_rasterize -at -ts 1000 1000 -te -10 20 30 50 features.geojson features.tif

Utiliser une instruction SQL pour graver des entités à partir d'une base de données SQLite 'source.sqlite' dans un fichier GeoTIFF 'destination.tif':

$ gdal_rasterize -sql "SELECT * FROM my_table WHERE type='road'" source.sqlite destination.tif

Utiliser une instruction SQL pour graver des entités à partir d'une base de données PostgreSQL 'source.pg' dans un fichier GeoTIFF 'destination.tif' en spécifiant un dialecte et en inversant la gravure:

$ gdal_rasterize -sql "SELECT * FROM my_table ORDER BY id DESC" -dialect PostgreSQL -i source.pg destination.tif
