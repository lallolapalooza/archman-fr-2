NOM

gdal-raster-compare - Compare deux jeux de données raster

Ajouté dans la version 3.12.

SYNOPSIS

Utilisation : gdal raster compare [OPTIONS] <REFERENCE> <INPUT>
Compare deux jeux de données raster.
Arguments positionnels :
  --reference <REFERENCE>              Jeu de données de référence [requis]
  -i, --input <INPUT>                  Jeu de données raster d'entrée [requis]
Options communes :
  -h, --help                           Afficher le message d'aide et quitter
  --json-usage                         Afficher l'utilisation sous forme de document JSON et quitter
  -q, --quiet                          Mode silencieux (pas de barre de progression)
Options :
  --skip-all-optional                  Ignorer toutes les comparaisons facultatives
  --skip-binary                        Ignorer la comparaison du fichier binaire
  --skip-crs                           Ignorer la comparaison du SCR
  --skip-geotransform                  Ignorer la comparaison de la géotransformation
  --skip-overview                      Ignorer la comparaison des vues d'ensemble
  --skip-metadata                      Ignorer la comparaison des métadonnées
  --skip-rpc                           Ignorer la comparaison des métadonnées RPC
  --skip-geolocation                   Ignorer la comparaison des métadonnées de géolocalisation
  --skip-subdataset                    Ignorer la comparaison des sous-jeux de données
Options avancées :
  --if, --input-format <INPUT-FORMAT>  Formats d'entrée [peut être répété]
  --oo, --open-option <KEY>=<VALUE>    Options d'ouverture [peut être répété]

DESCRIPTION

gdal raster compare compare deux jeux de données pris en charge par GDAL et signale les différences. En plus de signaler les différences sur la sortie standard, le programme renverra également le nombre de différences dans sa valeur de sortie.

Par convention, le premier jeu de données spécifié comme argument positionnel, ou via --reference, est supposé être le jeu de données de référence/exact/golden. Le second jeu de données spécifié comme argument positionnel, ou via --input, est le jeu de données comparé au jeu de données de référence.

Les pixels de l'image et diverses métadonnées sont vérifiés. Une comparaison octet par octet est également effectuée, comptée comme une différence. Ainsi, s'il est seulement important que les données visibles par GDAL soient identiques, un nombre de différences de 1 (la différence binaire) devrait être considéré comme acceptable, ou vous pouvez spécifier --skip-binary pour omettre la comparaison octet par octet.

Ce programme peut également être utilisé comme dernière étape d'un pipeline raster.

Les options suivantes sont disponibles :

Options

--reference <reference-dataset>
Le jeu de données considéré comme correct, appelé jeu de données de référence.
--input <input-dataset>
Le jeu de données comparé au jeu de données de référence, appelé jeu de données d'entrée.
--skip-all-optional
Indique s'il faut ignorer tous les tests facultatifs. C'est un alias pour définir toutes les autres --skip-XXXX options.

Les tests non facultatifs restants sont :

  • vérification de la largeur, de la hauteur et du nombre de bandes du jeu de données
  • vérification de la description de la bande, du type de données, de l'interprétation des couleurs et de la valeur nodata
  • vérification du contenu des pixels
--skip-binary
Indique s'il faut ignorer la comparaison exacte du contenu binaire.
--skip-overview
Indique s'il faut ignorer la comparaison des vues d'ensemble.
--skip-geolocation
Indique s'il faut ignorer la comparaison du domaine de métadonnées GEOLOCATION.
--skip-geotransform
Indique s'il faut ignorer la comparaison de la matrice de géotransformation.
--skip-metadata
Indique s'il faut ignorer la comparaison des métadonnées
--skip-rpc
Indique s'il faut ignorer la comparaison du domaine de métadonnées des coefficients polynomiaux rationnels (RPC).
--skip-crs
Indique s'il faut ignorer la comparaison des systèmes de coordonnées de référence (SCR).
--skip-sds
Indique s'il faut ignorer la comparaison de tous les sous-jeux de données faisant partie du jeu de données.

EXEMPLES

Exemple 1 : Comparaison de deux jeux de données qui diffèrent par leurs types de données

$ gdal raster compare autotest/gcore/data/byte.tif autotest/gcore/data/uint16.tif
Le fichier de référence a une taille de 736 octets, alors que le fichier d'entrée a une taille de 1136 octets.
La bande 1 du fichier de référence a le type de données Byte, mais la bande d'entrée a le type de données UInt16
$ echo $?
2

Exemple 2 : Comparaison de deux jeux de données dont les valeurs ont des unités différentes

$ gdal raster pipeline read test_in_foot.tif ! calc --calc "X * 0.3048" ! compare --reference=reference_in_meter.tif
