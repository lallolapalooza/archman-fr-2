NOM

gdal-vector-segmentize - Segmenter les géométries d'un jeu de données vectoriel

Ajouté dans la version 3.12.

SYNTAXE

Utilisation : gdal vector segmentize [OPTIONS] <ENTRÉE> <SORTIE> <LONGUEUR-MAX>
Segmenter les géométries d'un jeu de données vectoriel.
Arguments positionnels :
  -i, --input <ENTRÉE>                                 Jeux de données vectoriels d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données vectoriel de sortie [requis]
  --max-length <LONGUEUR-MAX>                          Longueur maximale d'un segment [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <COUCHE-ENTRÉE>             Nom(s) de la couche d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLÉ>=<VALEUR>                Option de création [peut être répétée]
  --lco, --layer-creation-option <CLÉ>=<VALEUR>         Option de création de couche [peut être répétée]
  --overwrite                                          Indique si l'écrasement d'une sortie existante est autorisé
  --update                                             Indique si l'ouverture d'un jeu de données existant en mode mise à jour est autorisée
  --overwrite-layer                                    Indique si l'écrasement d'une couche de sortie existante est autorisé
  --append                                             Indique si l'ajout à une couche existante est autorisé
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <COUCHE-ACTIVE>                       Définir la couche active (si non spécifié, toutes)
  --active-geometry <GÉOMÉTRIE-ACTIVE>                 Nom du champ de géométrie sur lequel restreindre le traitement (si non spécifié, toutes)
Options avancées :
  --if, --input-format <FORMAT-ENTRÉE>                  Formats d'entrée [peut être répété]
  --oo, --open-option <CLÉ>=<VALEUR>                    Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLÉ>=<VALEUR>      Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector segmentize garantit que les segments des LineStrings ou les anneaux des Polygons ne dépassent pas la longueur maximale spécifiée, en insérant des points intermédiaires.

Il exécute l'opération OGRGeometry::segmentize().

Il peut également être utilisé comme étape d'un gdal vector pipeline.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être obtenues avec gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoPackage prend en charge des options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être affichée avec l'option de ligne de commande --formats, mais la documentation du format est la source faisant autorité pour les options de création du pilote. Consultez la documentation spécifique au format des Pilotes vectoriels pour connaître les options de création légales pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.
--active-layer <COUCHE-ACTIVE>
Définit la couche active. Lorsqu'elle est spécifiée, seule la couche spécifiée par son nom sera traitée. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront traitées.
--active-geometry <GÉOMÉTRIE-ACTIVE>
Définit le champ de géométrie actif par son nom. Lorsqu'il est spécifié, seul le champ de géométrie spécifié sera traité. Les autres champs de géométrie ne seront pas modifiés. Si cette option n'est pas spécifiée, tous les champs de géométrie seront traités. Cette option peut être combinée avec --active-layer.
--max-length <LONGUEUR-MAX>
La valeur spécifiée pour cette option est la distance maximale entre deux points consécutifs de la géométrie de sortie avant que des points intermédiaires ne soient ajoutés. L'unité de la distance est les unités géoréférencées de la couche source.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour éviter la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichiers.

Peut être répété.

SORTIE GDALG (DU COURS / JEU DE DONNÉES EN FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel en utilisant le pilote GDALG : GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière continue / en flux.

EXEMPLES

Exemple 1: S'assurer que les segments des géométries ne dépassent pas un kilomètre (en supposant que le SCR est en mètres)

$ gdal vector segmentize --max-length=1000 in.gpkg out.gpkg --overwrite

gdal-vector-segmentize(1)

NOM

gdal-vector-segmentize — Segmente les géométries vectorielles en segments de longueur spécifiée.

SYNTAXE

gdal-vector-segmentize  [-help]  [-so]  [-min_segment_length <length>]  [-approx_max_length <length>]  <input_dataset>  <output_dataset>

DESCRIPTION

La commande gdal-vector-segmentize est un utilitaire de ligne de commande pour segmenter les géométries linéaires d'un jeu de données vectorielles d'entrée en plusieurs segments d'une longueur maximale spécifiée. Cela est particulièrement utile pour simplifier ou discrétiser des géométries complexes, par exemple pour des applications de modélisation ou de rendu.

Le script segmente les lignes complexes (par exemple, des courbes) en segments plus petits. L'option -min_segment_length définit la longueur maximale de chaque segment résultant. L'option -approx_max_length peut être utilisée pour spécifier une longueur maximale approximative pour les segments résultants, ce qui peut être utile pour obtenir un certain niveau de détail sans subdiviser excessivement les géométries.

Le jeu de données de sortie contiendra les géométries segmentées. Les attributs des géométries d'origine sont préservés.

GDALG OUTPUT (À LA VOLÉE / FLUX DE DONNÉES)

La commande gdal-vector-segmentize prend en charge la sortie vers des jeux de données de type flux (par exemple, GeoJSON, Shapefile) et la création de jeux de données de type "à la volée" (On-The-Fly - OTF).

Lors de la spécification d'un jeu de données de sortie, vous pouvez utiliser des chemins de fichiers standard ou des URL pour les formats qui les prennent en charge.

EXEMPLES

Pour segmenter un fichier Shapefile d'entrée nommé input.shp en segments d'une longueur maximale de 100 unités et enregistrer le résultat dans output.shp :

gdal-vector-segmentize -min_segment_length 100 input.shp output.shp

Pour segmenter un fichier GeoJSON input.geojson en segments d'une longueur maximale approximative de 50 unités, sans spécifier de longueur minimale stricte :

gdal-vector-segmentize -approx_max_length 50 input.geojson output.geojson
