DESCRIPTIO

N

gdal vector pipeline peut être utilisé pour traiter un jeu de données vectoriel et effectuer diverses étapes de traitement qui acceptent des vecteurs et génèrent des

vecteurs.

Pour les pipelines mélangeant raster et vectoriel, consultez gdal pipe

line.

La plupart des étapes procèdent par évaluation à la demande des entités, sauf indication contraire dans leur documentation, sans « matérialiser » le jeu de données résultant de l'opération de chaque étape. Il peut être souhaitable parfois, pour des raisons de performance, de procéder à la matérialisation d'un jeu de données intermédiaire sur le disque en utilisant gdal vector

materi
alize.

SYNOPSI

S 
Utilisation : gdal vector pipeline [OPTIONS] <PIPELINE>
Traiter un jeu de données vectoriel en appliquant plusieurs étapes.
Arguments positionnels :
Options communes :
-h, --help Afficher le message d'aide et quitter --json-usage Afficher l'utilisation sous forme de document JSON et quitter --config <KE
Y>=<VALUE> Option de configuration [peut être répétée] -q, --quiet Mode silencieux (pas de barre de progression) Options : --skip-errors Ig
norer les erreurs lors de l'écriture des entités <PIPELINE> est de la forme : read|concat [READ-OPTIONS] ( ! <STEP-NAME> [STEP-OPTIONS] )* ! write|info [WRITE-OPTIONS]

Un pipeline enchaîne plusieurs étapes, séparées par le caractère ! (point d'exclamation). La première étape doit être read ou concat, et la dernière info, partition ou write. Chaque étape a ses propres arguments positionnels ou non positionnels. À part read, concat, info, partition et write, toutes les autres étapes peuvent potentiellement être utilisées plusieurs fois dans un

pipeline.

GDALG OUTPUT (JEU DE DONNÉES EN TEMPS RÉEL / EN

FLUX)

Un pipeline peut être sérialisé dans un fichier JSON à l'aide du format GDALG de sortie. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel en utilisant le GDALG : pilote GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière en temps réel / en

flux.

Le membre command_line du fichier JSON devrait nominativement être la ligne de commande complète sans l'étape finale write, et est ce qui est généré par gdal vector pipeline ! .... ! write

out.gdalg.json. 
{
    "type": "gdal_streamed_alg
", "command_line": "gdal vec
tor pipeline ! read in.gpkg ! r
eproject --dst-crs=EPSG:32632" }

L'étape finale write peut être ajoutée, mais si c'est le cas, elle doit spécifier explicitement le format de sortie en flux et un nom de jeu de données de sortie non

significatif. 
{
    "type": "gdal_streamed_alg",
"command_line": "gdal vector pip
eline ! read in.gpkg ! reproject --
dst-crs=EPSG:32632 ! write --output-
format=streamed streamed_dataset" }

SUBSTITUTION

S

Ajouté dans la version 3.

12.

Il est possible d'utiliser gdal pipeline pour utiliser un pipeline déjà sérialisé dans un fichier .gdal.json, et personnaliser ses étapes existantes, typiquement en changeant un nom de fichier d'entrée, en spécifiant un nom de fichier de sortie, ou en ajoutant/modifiant des arguments

d'étapes.

PIPELINE

IMBRIQUÉ

Ajouté dans la version 3.

12.

Il est possible de créer des « pipelines imbriqués », c'est-à-dire des pipelines à l'intérieur de

pipelines.

Un pipeline imbriqué est délimité par des crochets ([ et ) entourés d'un

espace.

Il y a 2 types de pipelines imbriqués

:
  • pipelines imbriqués d'entrée : où le jeu de données résultant du pipeline imbriqué est utilisé comme jeu de données d'entrée pour un argument du pipeline
    • principal.
  • pipelines imbriqués de sortie : où la sortie d'une étape du pipeline principal est utilisée comme entrée du pipeline imbriqué dans une étape suivante. Les pipelines imbriqués de sortie ne peuvent être utilisés qu'avec l'étape te
e
.

Voir Pipeline

imbri
qué.
