NOM

gdal-raster-aspect - Générer une carte d'aspect

Ajouté dans la version 3.11.

SYNTAXE

Usage: gdal raster aspect [OPTIONS] <ENTREE> <SORTIE>
Générer une carte d'aspect
Arguments positionnels:
  -i, --input <ENTREE>                                 Jeux de données raster d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données raster de sortie [requis]
Options courantes:
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>                               Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options:
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>             Option de création [peut être répétée]
  --overwrite                                          Autoriser l'écrasement de la sortie existante
                                                       Mutuellement exclusif avec --append
  --append                                             Ajouter en tant que sous-jeu de données à la sortie existante
                                                       Mutuellement exclusif avec --overwrite
  -b, --band <BANDE>                                   Bande d'entrée (index basé sur 1) (défaut : 1)
  --convention <CONVENTION>                            Convention pour les angles de sortie. CONVENTION=azimuth|trigonometric-angle (défaut : azimuth)
  --gradient-alg <GRADIENT-ALG>                        Algorithme utilisé pour calculer le gradient de terrain. GRADIENT-ALG=Horn|ZevenbergenThorne (défaut : Horn)
  --zero-for-flat                                      Sortir zéro pour les zones plates
  --no-edges                                           Ne pas essayer d'interpoler les valeurs aux bords du jeu de données ou près des valeurs nodata
Options avancées:
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]

DESCRIPTION

gdal raster aspect génère une carte d'aspect, à partir de tout raster d'élévation supporté par GDAL.

Cette sous-commande est également disponible comme étape potentielle de gdal raster pipeline

Elle produit un raster flottant 32 bits avec des valeurs comprises entre 0° et 360° représentant l'azimut vers lequel font face les pentes. La définition de l'azimut est telle que : - 0° signifie que la pente fait face au Nord, - 90° à l'Est, - 180° au Sud - et 270° à l'Ouest (à condition que le haut de votre raster d'entrée soit orienté au nord).

La valeur d'aspect -9999 est utilisée comme valeur nodata pour indiquer un aspect indéfini dans les zones plates avec une pente de 0.

Une valeur nodata dans le jeu de données cible sera également émise si au moins un pixel défini avec la valeur nodata est trouvé dans la fenêtre 3x3 centrée autour de chaque pixel source. Par défaut, l'algorithme calculera les valeurs aux bords de l'image ou si une valeur nodata est trouvée dans la fenêtre 3x3, en interpolant les valeurs manquantes, sauf si --no-edges est spécifié, auquel cas une bordure d'un pixel autour de l'image sera définie avec la valeur nodata.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format de raster de sortie utiliser. Les valeurs autorisées peuvent être obtenues par gdal --formats | grep raster | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création optionnelles qui peuvent être utilisées pour contrôler les détails du fichier créé. Par exemple, le pilote GeoTIFF prend en charge des options de création pour contrôler la compression et si le fichier doit être tuilé.

Peut être répété.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats, mais la documentation du format est la source définitive d'information sur les options de création du pilote. Voir la documentation spécifique au format Pilotes raster pour les options de création légales pour chaque format.

--overwrite
Autoriser le programme à écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal génère une erreur si le fichier ou le jeu de données cible existe déjà.
-b, --band <BANDE>
Index (commençant à 1) de la bande pour laquelle l'aspect doit être calculé.
--convention azimuth|trigonometric-angle
Convention pour les angles de sortie.

Par défaut : azimuth, c'est-à-dire : - 0° signifie que la pente fait face au Nord, - 90° à l'Est, - 180° au Sud - et 270° à l'Ouest (à condition que le haut de votre raster d'entrée soit orienté au nord).

Si défini sur trigonometric-angle, - 0° signifie que la pente fait face à l'Est, - 90° au Nord, - 180° à l'Ouest - et 270° au Sud.

--gradient-alg Horn|ZevenbergenThorne
Algorithme utilisé pour calculer le gradient de terrain. La valeur par défaut est Horn. La littérature suggère que Zevenbergen & Thorne est plus adapté aux paysages lisses, tandis que la formule de Horn est plus performante sur un terrain plus accidenté.
--zero-for-flat
Indique s'il faut sortir zéro pour les zones plates. Par défaut, les zones plates où la pente est nulle recevront une valeur nodata (-9999). En activant cette option, elles sont définies à 0.
--no-edges
Ne pas essayer d'interpoler les valeurs aux bords du jeu de données ou près des valeurs nodata.

SORTIE GDALG (DONNÉES EN TEMPS RÉEL / FLUIDES)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données raster en utilisant le pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière "en temps réel" / fluide.

EXEMPLES

Exemple 1: Génère une carte d'aspect à partir d'un fichier DTED0.

$ gdal raster aspect n43.dt0 out.tif --overwrite
