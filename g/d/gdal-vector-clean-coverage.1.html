NOM

gdal-vector-clean-coverage - Supprimer les trous et les superpositions d'un jeu de données de polygones

Ajouté dans la version 3.12.

SYNTAXE

Utilisation : gdal vector clean-coverage [OPTIONS] <ENTREE> <SORTIE>
Modifier les frontières des polygones pour rendre les arêtes communes identiques, en supprimant les trous et les superpositions.
Arguments positionnels :
  -i, --input <ENTREE>                                  Jeux de données vectoriels d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données vectoriel de sortie [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <COUCH-ENTREE>            Nom(s) de la couche d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>                Option de création [peut être répétée]
  --lco, --layer-creation-option <CLE>=<VALEUR>         Option de création de couche [peut être répétée]
  --overwrite                                          Permettre l'écrasement d'une sortie existante
  --update                                             Permettre l'ouverture d'un jeu de données existant en mode mise à jour
  --overwrite-layer                                    Permettre l'écrasement d'une couche existante
  --append                                             Permettre l'ajout à une couche existante
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COCHE-SORTIE>                        Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <COUCHE-ACTIVE>                       Définir la couche active (si non spécifiée, toutes)
  --snapping-distance <DISTANCE-COLLAGE>               Distance de tolérance pour le collage des nœuds
  --merge-strategy <STRATEGIE-FUSION>                  Algorithme pour attribuer les superpositions aux polygones voisins. STRATEGIE-FUSION=longest-border|max-area|min-area|min-index
  --maximum-gap-width <LARGEUR-MAX-TROU>               Largeur maximale d'un trou à refermer
Options avancées :
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLE>=<VALEUR>      Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer les entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector clean-coverage modifie les frontières d'un jeu de données polygonal, de sorte que les trous et les superpositions entre les entités soient supprimés et que les arêtes partagées soient définies à l'aide des mêmes sommets. Le jeu de données résultant formera une couverture polygonale qui pourra être utilisée avec gdal vector simplify-coverage.

Cette commande peut également être utilisée comme une étape du gdal vector pipeline, bien qu'elle nécessite de charger l'intégralité du jeu de données en mémoire à la fois.

NOTE :

Cette commande nécessite une compilation de GDAL liée à la bibliothèque GEOS (version 3.14 ou supérieure).

Options standard

--maximum-gap-width <LARGEUR-MAX-TROU>
Définit la plus grande zone qui doit être considérée comme un "trou" et fusionnée dans un polygone adjacent. Les trous seront fusionnés à moins qu'un cercle dont le rayon est supérieur à la tolérance spécifiée ne puisse être inscrit dans le trou. La largeur maximale par défaut des trous est zéro, ce qui signifie que les trous ne sont pas fermés.
--merge-strategy <STRATEGIE-FUSION>
Méthode par laquelle les superpositions ou les trous doivent être ajoutés aux polygones adjacents. Les options incluent : - longest-border (par défaut) : ajouter les zones au polygone avec lequel l'arête la plus longue est partagée - max-area : ajouter les zones au plus grand polygone adjacent - min-area : ajouter les zones au plus petit polygone adjacent - min-index : ajouter les zones au polygone adjacent qui a été lu en premier
--snapping-distance <DISTANCE-COLLAGE>
Contrôle l'étape de collage des nœuds, lorsque des sommets proches sont collés ensemble. Par défaut, une distance de collage automatique est déterminée sur la base d'une analyse de l'entrée. Réglez sur zéro pour désactiver tout collage.
--active-layer <COUCHE-ACTIVE>
Définit la couche active. Lorsqu'elle est spécifiée, seule la couche spécifiée par son nom sera soumise au traitement. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront soumises au traitement.
-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être données par gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données optionnelles qui peuvent être utilisées pour contrôler des détails sur le fichier créé. Par exemple, le pilote GeoPackage prend en charge des options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être obtenue avec l'option de ligne de commande --formats, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique au format des pilotes vectoriels pour connaître les options de création légales pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture de jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour éviter la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichier.

Peut être répété.

SORTIE GDAL-G (JEU DE DONNÉES À LA VOLÉE / EN FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel en utilisant le pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière à la volée / en flux.

NOTE :

Cependant, cet algorithme n'est pas nativement compatible avec le streaming. Par conséquent, un jeu de données temporaire en mémoire sera généré, ce qui peut entraîner un temps de traitement important à l'ouverture.

EXEMPLE

S

Exemple 1 : Créer puis simplifier une couverture

polygonale 
$ gdal vector pipeline read ne_10m_admin
_0_countries.shp ! \
make-valid ! \
clean-coverage ! \
simplify-coverage --tolerance 1 ! \ write countries.shp
