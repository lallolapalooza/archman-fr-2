NOM

gdal-raster-clip - Découper un jeu de données raster

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal raster clip [OPTIONS] <ENTRÉE> <SORTIE>
Découper un jeu de données raster.
Arguments positionnels :
  -i, --input <ENTRÉE>                                  Jeux de données raster en entrée [requis]
  -o, --output <SORTIE>                                 Jeu de données raster en sortie [requis]
Options communes :
  -h, --help                                           Afficher le message d'aide et quitter
  --json-usage                                         Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>                              Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -f, --of, --format, --output-format <FORMAT-SORTIE>   Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLÉ>=<VALEUR>               Option de création [peut être répétée]
  --overwrite                                          Autoriser l'écrasement de la sortie existante
                                                       Exclusif avec --append
  --append                                             Ajouter en tant que sous-jeu de données à la sortie existante
                                                       Exclusif avec --overwrite
  --bbox <BBOX>                                        Boîte englobante de découpe sous la forme xmin,ymin,xmax,ymax
                                                       Exclusif avec --window, --geometry, --like
  --bbox-crs <BBOX-CRS>                                SCR de la boîte englobante de découpe
  --window <WINDOW>                                    Fenêtre raster sous la forme colonne,ligne,largeur,hauteur en pixels
                                                       Exclusif avec --bbox, --geometry, --like
  --geometry <GEOMETRY>                                Géométrie de découpe (WKT ou GeoJSON)
                                                       Exclusif avec --bbox, --window, --like
  --geometry-crs <GEOMETRY-CRS>                        SCR de la géométrie de découpe
  --like <DATASET>                                     Jeu de données à utiliser comme modèle pour les limites
                                                       Exclusif avec --bbox, --window, --geometry
  --like-sql <SELECT-STATEMENT>                        Instruction SELECT à exécuter sur le jeu de données 'like'
                                                       Exclusif avec --like-where
  --like-layer <LAYER-NAME>                            Nom de la couche du jeu de données 'like'
  --like-where <WHERE-EXPRESSION>                      Clause WHERE SQL à exécuter sur le jeu de données 'like'
                                                       Exclusif avec --like-sql
  --only-bbox                                          Pour 'geometry' et 'like', ne considérer que leur boîte englobante
  --allow-bbox-outside-source                          Autoriser la boîte de découpe à inclure des pixels en dehors du jeu de données d'entrée
  --add-alpha                                          Ajouter une bande de masque alpha à la destination lorsque le raster source n'en a pas.
Options avancées :
  --if, --input-format <FORMAT-ENTRÉE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLÉ>=<VALEUR>                   Options d'ouverture [peut être répétée]

DESCRIPTION

gdal raster clip peut être utilisé pour découper un jeu de données raster en utilisant des coordonnées géoréférencées.

Soit --bbox ou --like doit être spécifié.

Le jeu de données de sortie est dans le même SCR que celui en entrée, et la résolution d'origine est préservée. Les limites sont arrondies pour correspondre aux emplacements de pixels entiers (c'est-à-dire qu'aucune rééchantillonnage n'est effectué)

clip peut aussi être utilisé comme une étape d'un pipeline gdal raster.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format de raster de sortie utiliser. Les valeurs autorisées peuvent être fournies par gdal --formats | grep raster | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoTIFF prend en charge des options de création pour contrôler la compression et si le fichier doit être tuilé.

Peut être répétée.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. La liste des options prises en charge pour un format peut être listée avec l'option de ligne de commande --formats mais la documentation du format est la source définitive d'informations sur les options de création du pilote. Voir Pilotes raster la documentation spécifique au format pour les options de création légales de chaque format.

--overwrite
Autoriser le programme à écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.
--bbox <xmin>,<ymin>,<xmax>,<ymax>
Limites auxquelles découper le jeu de données. On suppose qu'elles sont dans le SCR du jeu de données d'entrée, sauf si --bbox-crs est spécifié. Les axes X et Y sont les "axes conviviaux pour les SIG", c'est-à-dire que X est la longitude ou l'abscisse, et Y est la latitude ou l'ordonnée. Les limites sont étendues si nécessaire pour correspondre aux limites des pixels d'entrée. Par défaut, gdal raster clip produira une erreur si les limites indiquées par --bbox sont supérieures aux étendues du jeu de données d'entrée. Cette vérification peut être contournée en utilisant --allow-bbox-outside-source.
--bbox-crs <SCR>
SCR dans lequel les valeurs <xmin>,<ymin>,<xmax>,<ymax> de --bbox sont exprimées. Si non spécifié, on suppose qu'il s'agit du SCR du jeu de données d'entrée. Notez que spécifier --bbox-crs ne provoque pas la reprojection du raster. À la place, les limites sont reprojectées du bbox-crs vers le SCR du jeu de données d'entrée.
--window <colonne>,<ligne>,<largeur>,<hauteur>
Ajouté dans la version 3.12.

Sélectionne une sous-fenêtre de l'image source à copier en fonction de l'emplacement pixel/ligne. Les décalages pixel/ligne (colonne et ligne) sont mesurés depuis la gauche et le haut de l'image. Si la sous-fenêtre s'étend au-delà des limites du jeu de données source, les pixels de sortie seront écrits avec une valeur de zéro, sauf si une valeur NoData est définie dans le jeu de données source.

--geometry <WKT_ou_GeoJSON>
Géométrie sous forme de chaîne WKT ou GeoJSON d'un polygone (ou multipolygone) au quel découper le jeu de données. Les zones raster à l'intérieur de la boîte englobante de la géométrie mais pas à l'intérieur de la géométrie elle-même seront définies à la valeur nodata du raster, ou à 0 s'il n'y en a pas. Tous les pixels chevauchant la géométrie seront sélectionnés. Si la géométrie d'entrée est GeoJSON, son SCR est supposé être WGS84, sauf s'il y a un SCR défini dans la géométrie GeoJSON ou si --geometry-crs est spécifié. Si la géométrie d'entrée est WKT, son SCR est supposé être celui du jeu de données d'entrée, sauf si --geometry-crs est spécifié. Les axes X et Y sont les "axes conviviaux pour les SIG", c'est-à-dire que X est la longitude ou l'abscisse, et Y est la latitude ou l'ordonnée. Exclusif avec --bbox et --like.
--geometry-crs <SCR>
SCR dans lequel les valeurs des coordonnées de --geometry sont exprimées. Si non spécifié, on suppose qu'il s'agit du SCR du jeu de données d'entrée. Les limites sont reprojectées du geometry-crs vers le SCR du jeu de données d'entrée.
--like <DATASET>
Jeu de données vectoriel ou raster à utiliser comme modèle pour les limites. Si le jeu de données spécifié est un raster, ses limites rectangulaires sont utilisées comme géométrie de découpe. Si le jeu de données spécifié est un jeu de données vectoriel, ses géométries polygonales sont réunies en union ensemble pour former la géométrie de découpage. Si plusieurs couches sont présentes, --like-sql ou --like-layer doit être spécifié. Les zones raster à l'intérieur de la boîte englobante de la géométrie mais pas à l'intérieur de la géométrie elle-même seront définies à la valeur nodata du raster, ou 0 s'il n'y en a pas. Mutuellement exclusif avec --bbox et --geometry.
--like-sql <SELECT-STATEMENT>
Sélectionner les géométries souhaitées à partir du jeu de données vectoriel de découpage à l'aide d'une requête SQL. par exemple SELECT geom FROM my_layer WHERE country = 'France'. Le dialecte SQL utilisé sera celui par défaut du jeu de données like (OGR SQL pour Shapefile, SQLite pour GeoPackage, PostgreSQL pour PostGIS, etc.). Mutuellement exclusif avec --like-layer et --like-where
--like-layer <LAYER-NAME>
Sélectionner la couche nommée à partir du jeu de données vectoriel de découpage. Mutuellement exclusif avec --like-sql
--like-where <WHERE-EXPRESSION>
Restreindre les géométries souhaitées de la couche du jeu de données vectoriel de découpage en fonction d'une requête d'attribut. par exemple country = 'France'.
--only-bbox
Pour --geometry et --like, ne considérer que la boîte englobante de la géométrie.
--allow-bbox-outside-source
Si défini, permet aux bornes indiquées par --bbox de couvrir une étendue supérieure à celle du jeu de données d'entrée. Les pixels de sortie des zones au-delà de l'étendue d'entrée seront définis à zéro ou à la valeur NoData du jeu de données d'entrée.
--addalpha
Ajoute un canal de masque alpha à la destination lorsque le raster source n'en possède pas.

Options avancées

--oo <NAME>=<VALUE>
Option d'ouverture du jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter d'utiliser pour ouvrir le fichier(s) d'entrée. Il est généralement inutile de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichiers.

Peut être répété.

EXEMPLES

Exemple 1 : Découper un fichier GeoTIFF selon la boîte englobante de la longitude 2, latitude 49, à la longitude 3, latitude 50 en WGS 84

$ gdal raster clip --bbox=2,49,3,50 --bbox-crs=EPSG:4326 in.tif out.tif --overwrite

Exemple 2 : Découper un fichier GeoTIFF en utilisant les bornes de reference.tif

$ gdal raster clip --like=reference.tif in.tif out.tif --overwrite

Exemple 3 : Découper un fichier GeoTIFF à partir de la colonne raster 1000 et de la ligne 2000, pour une largeur de 500 pixels et une hauteur de 600 pixels

$ gdal raster clip --window=1000,2000,500,600 in.tif out.tif --overwrite
