NOM

gdal_calc - Calculatrice raster en ligne de commande avec syntaxe numpy.

SYNTAXE

gdal_calc [--help] [--help-general]
             --calc=expression --outfile=<nom_fichier_sortie> [-A <nom_fichier>]
             [--A_band=<n>] [-B...-Z <nom_fichier>] [<autres_options>]

DESCRIPTION

Calculatrice raster en ligne de commande avec syntaxe numpy. Utilisez n'importe quelle arithmétique de base prise en charge par les tableaux numpy telle que +, -, * et / ainsi que les opérateurs logiques tels que >. Notez que tous les fichiers doivent avoir les mêmes dimensions (sauf si l'option --extent est utilisée), mais aucune vérification de projection n'est effectuée (sauf si l'option --projectionCheck est utilisée).

NOTE :

gdal_calc est un utilitaire Python et n'est disponible que si les liaisons Python GDAL sont disponibles.
--help
Afficher ce message d'aide et quitter
--help-general
Donne un bref message d'utilisation pour les options génériques de ligne de commande GDAL et quitte.
--calc=<expression>
Calcul en syntaxe numpy utilisant +, -, /, *, ou toute fonction de tableau numpy (c'est-à-dire log10()). Plusieurs options --calc peuvent être listées pour produire un fichier multibande (GDAL >= 3.2). Voir Exemple 10.
-A <nom_fichier>
Fichier raster GDAL d'entrée, vous pouvez utiliser n'importe quelle lettre (a-z, A-Z). (minuscule pris en charge depuis GDAL 3.3)

Une lettre peut être répétée, ou plusieurs valeurs (séparées par un espace) peuvent être fournies (GDAL >= 3.3). L'effet sera de créer un tableau numpy 3D. Depuis GDAL 3.5, les exceptions de caractères génériques (utilisant ?, *) sont prises en charge pour tous les shells/plateformes. Dans ce cas, la formule de calcul doit utiliser cette entrée comme un tableau 3D et doit renvoyer un tableau 2D (voir Exemple 3). Si le calcul ne renvoie pas un tableau 2D, une erreur sera générée.

--A_band=<n>
Numéro de bande raster pour le fichier A (par défaut 1).
--outfile=<nom_fichier_sortie>
Fichier de sortie à générer ou à remplir.
--NoDataValue=<valeur>
Valeur NoData pour la sortie (valeur par défaut spécifique au type de données). Pour indiquer de ne pas définir de valeur NoData, utilisez --NoDataValue=none (GDAL >= 3.3)

NOTE :

En utilisant l'API Python : la valeur None indiquera la valeur par défaut spécifique au type de données. La valeur 'none' indiquera de ne pas définir de valeur NoData.
--hideNoData
Ajouté dans la version 3.3.

Ignore la valeur NoData des bandes d'entrée. Par défaut, la valeur NoData des bandes d'entrée ne participe pas au calcul. En définissant ce paramètre, aucun traitement spécial ne sera effectué sur la valeur NoData d'entrée, et elle participera au calcul comme toute autre valeur. La sortie n'aura pas de valeur NoData définie, à moins que vous n'ayez explicitement spécifié une valeur en définissant --NoDataValue=<valeur>.

--type=<type_de_données>
Type de données de sortie, doit être l'un des suivants [Byte, Int8, UInt16, Int16, UInt32, Int32, UInt64, Int64, Float64, Float32, CInt16, CInt32, CFloat64, CFloat32].

NOTE :

Malgré le type de données défini à l'aide de --type, lors des opérations arithmétiques intermédiaires utilisant des opérandes du même type, le résultat de l'opération respectera le type de données d'origine. Cela peut conduire à des résultats inattendus dans le résultat final.

NOTE :

UInt64, Int64, CInt16, CInt32, CFloat32, CFloat64 ont été ajoutés dans GDAL 3.5.3 Int8 a été ajouté dans GDAL 3.7
--format=<format_gdal>
Format GDAL pour le fichier de sortie.
--color-table=<nom_fichier>
Permet de spécifier le nom d'un fichier de table de couleurs (ou un objet ColorTable) (avec interprétation d'index de palette) à utiliser pour le raster de sortie. Formats pris en charge : txt (c'est-à-dire comme gdaldem, mais les noms de couleurs ne sont pas pris en charge), qlr, qml (c'est-à-dire exporté depuis QGIS)
--extent=<option>
Ajouté dans la version 3.3.

Cette option détermine comment gérer les rasters avec des étendues différentes. Cette option est mutuellement exclusive avec l'option projwin, qui est utilisée pour fournir une étendue personnalisée.

Pour toutes les options ci-dessous, la taille des pixels (résolution) et le SRS (Système de Référence Spatiale) de tous les rasters d'entrée doivent être identiques.

ignore (par défaut) - seules les dimensions des rasters sont comparées. Si les dimensions ne correspondent pas, l'opération échouera.

fail - les dimensions et l'étendue (bornes) des rasters doivent correspondre, sinon l'opération échouera.

union - l'étendue (bornes) de la sortie sera le rectangle minimal contenant toutes les étendues d'entrée.

intersect - l'étendue (bornes) de la sortie sera le rectangle maximal contenu dans toutes les étendues d'entrée.

--projwin <ulx> <uly> <lrx> <lry>
Ajouté dans la version 3.3.

Cette option fournit une étendue personnalisée pour la sortie, elle est mutuellement exclusive avec l'option extent.

--projectionCheck
Ajouté dans la version 3.3.

Par défaut, aucune vérification de projection ne sera effectuée. En définissant cette option, si la projection n'est pas la même pour toutes les bandes, l'opération échouera.

--creation-option=<option>
Passe une option de création au pilote de format de sortie. Plusieurs options peuvent être listées. Voir la documentation spécifique au format pour les options de création valides pour chaque format.
--co=<option>
Identique à creation-option.
--allBands=[a-z, A-Z]
Applique l'expression à toutes les bandes d'un raster donné. Lorsque --allBands est utilisé, --calc ne peut être spécifié qu'une seule fois. Voir Exemple 11 et Exemple 12.
--overwrite
Écrase le fichier de sortie s'il existe déjà. L'écrasement doit être compris ici comme la suppression et la recréation du fichier à partir de zéro. Notez que si cette option n'est pas spécifiée et que le fichier de sortie existe déjà, il sera mis à jour sur place.
--debug
Afficher les informations de débogage.
--quiet
Supprimer les messages de progression.
