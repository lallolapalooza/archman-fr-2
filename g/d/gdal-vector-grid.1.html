LECTURE DE VALEURS SÉPARÉES PAR DES

VIRGULES

Souvent, vous avez un fichier texte contenant une liste de valeurs XYZ séparées par des virgules (le fameux fichier CSV). Vous pouvez facilement utiliser ce type de source de données dans gdal vector grid. Tout ce que vous avez à faire est de créer un en-tête de jeu de données virtuel (VRT) pour votre fichier CSV et de l'utiliser comme source de données d'entrée pour gdal vector grid. Vous trouverez les détails sur le format VRT sur la page de description VRT -- OGR Virtual

Format.

Voici un petit exemple. Supposons que nous ayons un fichier CSV appelé dem.csv

contenant 
Easting,Northing,Elevation
86943.4,891957,139.13
87124.3,892075,135.01
86962.4,892321,182.04
87077.6,891995,135.01
.
.
.

Pour les données ci-dessus, nous allons créer un en-tête dem.vrt avec le contenu suivant

: 
<OGRVRTDataSource>
    <OGRVRTLayer name="dem">
        <SrcDataSource>dem.csv</SrcDataSource>
        <GeometryType>wkbPoint</GeometryType>
        <GeometryField encoding="PointFromColumns" x="Easting" y="Northing" z="Elevation"/>
    </OGRVRTLayer>
</OGRVRTDataSour
c
e
>

Cette description spécifie une géométrie dite 2.5D avec trois coordonnées X, Y et Z. La valeur Z sera utilisée pour l'interpolation. Maintenant, vous pouvez utiliser dem.vrt avec tous les programmes OGR (commencez par ogrinfo pour tester que tout fonctionne correctement). La source de données contiendra une seule couche appelée "dem" remplie d'entités ponctuelles construites à partir des valeurs du fichier CSV. En utilisant cette technique, vous pouvez gérer des fichiers CSV avec plus de trois colonnes, changer de colonnes, etc. OK, maintenant l'étape finale

: 
gdal vecto
r grid inv
dist dem.vr
t demv.tif

Ou, si nous ne souhaitons pas utiliser un fichier VRT

: 
gdal vector grid invdist -l dem
-oo X_POSSIBLE_NAMES=Easting \ -
oo Y_POSSIBLE_NAMES=Northing --
zfield=Elevation dem.csv dem.tif

Si votre fichier CSV ne contient pas d'en-têtes de colonnes, il peut être géré dans le fichier VRT de la manière suivante

SORTIE GDALG (JEU DE DONNÉES EN TEMPS RÉEL /

DIFFUSÉ)

Ce programme prend en charge la sérialisation de la ligne de commande en tant que fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert en tant que jeu de données raster en utilisant le pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière en temps réel /

diffusée.

NOTE

:
Cependant, cet algorithme n'est pas nativement compa
tible avec le streaming. Par conséquent, un jeu de
données temporaire sera généré, ce qui peut entra
îner un temps de traitement important à l'ouverture.
