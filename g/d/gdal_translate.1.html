NOM

gdal_translate - Convertit des données raster entre différents formats.

SYNTAXE

Usage: gdal_translate [--help] [--long-usage] [--help-general]
                      [-ot Byte|Int8|[U]Int{16|32|64}|CInt{16|32}|[C]Float{32|64}]
                      [-if <format>]... [-of <output_format>] [--quiet]
                      [-b <band>]... [-mask <mask>] [-expand gray|rgb|rgba]
                      [[-strict]|[-not_strict]]
                      [-outsize <xsize[%]|0> <ysize[%]|0>] [-tr <xres> <yes>]
                      [-ovr <level>|AUTO|AUTO-<n>|NONE] [-sds]
                      [-r nearest,bilinear,cubic,cubicspline,lanczos,average,mode]
                      [[-scale [<src_min> <src_max> [<dst_min> <dst_max>]]]...|
                      [-scale_X [<src_min> <src_max> [<dst_min> <dst_max>]]]...|
                      [-unscale]]
                      [[-exponent <value>]|[-exponent_X <value>]...]
                      [-srcwin <xoff> <yoff> <xsize> <ysize>]
                      [-projwin <ulx> <uly> <lrx> <lry>]
                      [-projwin_srs <srs_def>] [-epo] [-eco] [-a_srs <srs_def>]
                      [-a_coord_epoch <epoch>] [-a_ullr <ulx> <uly> <lrx> <lry>]
                      [-a_nodata <value>|none]
                      [-a_gt <gt(0)> <gt(1)> <gt(2)> <gt(3)> <gt(4)> <gt(5)>]
                      [-a_scale <value>] [-a_offset <value>] [-nogcp]
                      [-gcp <pixel> <line> <easting> <northing> [<elevation>]]...
                      [-colorinterp {red|green|blue|alpha|gray|undefined|pan|coastal|rededge|nir|swir|mwir|lwir|...},...]
                      [-colorinterp_X {red|green|blue|alpha|gray|undefined|pan|coastal|rededge|nir|swir|mwir|lwir|...}]...
                      [[-stats]|[-approx_stats]]
                      [-norat] [-noxmp] [-co <NAME>=<VALUE>]...
                      [-mo <NAME>=<VALUE>]... [-dmo <DOMAIN>:<KEY>=<VALUE>]...
                      [-oo <NAME>=<VALUE>]...
                      <input_file> <output_file>

DESCRIPTION

L'utilitaire gdal_translate peut être utilisé pour convertir des données raster entre différents formats, en effectuant potentiellement certaines opérations telles que la sélection de sous-ensembles, le rééchantillonnage et la mise à l'échelle des pixels.

--help
Affiche ce message d'aide et quitte.
--help-general
Donne un bref message d'utilisation pour les options génériques de ligne de commande GDAL et quitte.
-ot <type>
Force les bandes de l'image de sortie à avoir un type de données spécifique supporté par le pilote, qui peut être l'un des suivants : Byte, Int8, UInt16, Int16, UInt32, Int32, UInt64, Int64, Float32, Float64, CInt16, CInt32, CFloat32 ou CFloat64.
-strict
Ne pas être indulgent avec les divergences et les données perdues lors de la conversion vers le format de sortie.
-if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsqu'elle échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences sur les extensions de fichiers.

Ajouté en version 3.2.

-of <format>
Sélectionne le format de sortie. S'il n'est pas spécifié, le format est deviné à partir de l'extension. Utilisez le nom court du format.
-b <band>
Sélectionne une bande d'entrée band pour la sortie. Les bandes sont numérotées à partir de 1. Plusieurs commutateurs -b peuvent être utilisés pour sélectionner un ensemble de bandes d'entrée à écrire dans le fichier de sortie, ou pour réorganiser les bandes. band peut aussi être réglé sur "mask,1" (ou juste "mask") pour signifier la bande masque de la première bande du jeu de données d'entrée.
-mask <band>
Sélectionne une bande d'entrée band pour créer la bande masque du jeu de données de sortie. Les bandes sont numérotées à partir de 1. band peut être réglé sur "none" pour éviter de copier le masque global du jeu de données d'entrée s'il existe. Sinon, il est copié par défaut ("auto"), sauf si le masque est un canal alpha, ou s'il est explicitement utilisé comme bande régulière du jeu de données de sortie ("-b mask"). band peut aussi être réglé sur "mask,1" (ou juste "mask") pour signifier la bande masque de la 1ère bande du jeu de données d'entrée.
-expand gray|rgb|rgba
Pour exposer un jeu de données à 1 bande avec une table de couleurs comme un jeu de données à 3 (RVB) ou 4 (RVBA) bandes. Utile pour les pilotes de sortie comme JPEG, JPEG2000, MrSID, ECW qui ne supportent pas les jeux de données indexés par couleur. La valeur 'gray' permet d'exposer un jeu de données avec une table de couleurs ne contenant que des niveaux de gris en un jeu de données indexé en niveaux de gris.
-outsize <xsize>[%]|0 <ysize>[%]|0
Définit la taille du fichier de sortie. La taille est en pixels et lignes, sauf si '%' est attaché, auquel cas c'est une fraction de la taille de l'image d'entrée. Si l'une des 2 valeurs est réglée sur 0, sa valeur sera déterminée à partir de l'autre tout en maintenant le rapport d'aspect du jeu de données source.
-tr <xres> <yres>
Définit la résolution cible. Les valeurs doivent être exprimées en unités de géoréférencement. Les deux doivent être des valeurs positives. Ceci est mutuellement exclusif avec -outsize, -a_ullr, et -a_gt.
-ovr {<level>|AUTO|AUTO-<n>|NONE}
Ajouté en version 3.6.

Pour spécifier quel niveau d'aperçu du fichier source doit être utilisé. Le choix par défaut, AUTO, sélectionnera le niveau d'aperçu dont la résolution est la plus proche de la résolution cible. Spécifiez une valeur entière (base 0, c'est-à-dire 0=1er niveau d'aperçu) pour sélectionner un niveau particulier. Spécifiez AUTO-n où n est un entier supérieur ou égal à 1, pour sélectionner un niveau d'aperçu inférieur au niveau AUTO. Ou spécifiez NONE pour forcer l'utilisation de la résolution de base (peut être utile si des aperçus ont été générés avec une méthode de rééchantillonnage de faible qualité, et qu'une méthode de rééchantillonnage de meilleure qualité est spécifiée avec -r.)

Lorsque -ovr est spécifié comme une valeur entière, et ni -outsize ni -tr n'est spécifié, la taille de l'aperçu sera utilisée comme taille de sortie.

Lorsque -ovr est spécifié, les valeurs de -srcwin doivent être exprimées comme le décalage de pixels et la taille du jeu de données source à pleine résolution. De même, lors de l'utilisation de -outsize avec des valeurs en pourcentage, elles se réfèrent à la taille du jeu de données source à pleine résolution.

-r {nearest|bilinear|cubic|cubicspline|lanczos|average|rms|mode}
Sélectionne un algorithme de rééchantillonnage.

nearest (par défaut) applique un rééchantillonneur par plus proche voisin (échantillonnage simple).

average calcule la moyenne de tous les pixels contribuants non-NODATA. À partir de GDAL 3.1, il s'agit d'une moyenne pondérée tenant correctement compte du poids des pixels source ne contribuant pas entièrement au pixel cible.

rms calcule la moyenne quadratique / moyenne quadratique de tous les pixels contribuants non-NODATA (GDAL >= 3.3).

bilinear applique un noyau de convolution bilinéaire.

cubic applique un noyau de convolution cubique.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

cubicspline applique un noyau de convolution B-Spline.

lanczos applique un noyau de convolution sinc fenêtré de Lanczos.

mode sélectionne la valeur qui apparaît le plus souvent parmi tous les points échantillonnés.

-scale [<src_min> <src_max> [<dst_min> <dst_max>]]
Ré-échelonne les valeurs des pixels d'entrée de la plage src_min à src_max vers la plage dst_min à dst_max. Si omises, la plage de sortie va de la valeur minimale à la valeur maximale autorisée pour les types de données entiers (par exemple de 0 à 255 pour une sortie Byte) ou de 0 à 1 pour les types de données flottants. Si omis, la plage d'entrée est calculée automatiquement à partir du jeu de données source, dans son intégralité (pas seulement la fenêtre d'intérêt potentiellement spécifiée avec -srcwin ou -projwin). Cela peut être une opération lente sur un grand jeu de données source, et si vous l'utilisez plusieurs fois pour plusieurs invocations de gdal_translate, il peut être bénéfique d'appeler gdalinfo -stats {source_dataset} au préalable pour pré-calculer les statistiques, pour les formats qui supportent la sérialisation des calculs de statistiques (GeoTIFF, VRT...). Notez que les valeurs spécifiées après -scale sont uniquement utilisées pour calculer une échelle et un décalage à appliquer aux valeurs raster d'entrée. En particulier, src_min et src_max ne sont pas utilisés pour rogner les valeurs d'entrée, sauf si -exponent est également spécifié. Au lieu d'être rognées, les valeurs sources qui sont en dehors de la plage de src_min et src_max seront mises à l'échelle vers des valeurs en dehors de la plage de dst_min et dst_max. Si un rognage sans mise à l'échelle exponentielle est souhaité, -exponent 1 peut être utilisé. -scale peut être répété plusieurs fois (s'il est spécifié une seule fois, il s'applique également à toutes les bandes du jeu de données de sortie), afin de spécifier des paramètres par bande. Il est également possible d'utiliser la syntaxe -scale_bn où bn est un numéro de bande (par exemple, -scale_2 pour la 2ème bande du jeu de données de sortie) pour spécifier les paramètres d'une ou plusieurs bandes spécifiques.
-exponent <exp_val>
Applique une mise à l'échelle non linéaire avec une fonction puissance. exp_val est l'exposant de la fonction puissance (doit être positif). Cette option doit être utilisée avec l'option -scale. Si spécifié une seule fois, -exponent s'applique à toutes les bandes de l'image de sortie. Il peut être répété plusieurs fois afin de spécifier des paramètres par bande. Il est également possible d'utiliser la syntaxe -exponent_bn où bn est un numéro de bande (par exemple, -exponent_2 pour la 2ème bande du jeu de données de sortie) pour spécifier les paramètres d'une ou plusieurs bandes spécifiques.

La valeur mise à l'échelle Dst est calculée à partir de la valeur source Src avec la formule suivante :


{Dst} = \left( {Dst}_{max} - {Dst}_{min} \right) \times \operatorname{max} \left( 0, \operatorname{min} \left( 1, \left( \frac{{Src} - {Src}_{min}}{{Src}_{max}-{Src}_{min}} \right)^{exp\_val} \right) \right) + {Dst}_{min}



-unscale
Applique les métadonnées d'échelle/décalage pour les bandes afin de convertir les valeurs linéairement mises à l'échelle en valeurs non mises à l'échelle. Il est également souvent nécessaire de réinitialiser le type de données de sortie avec le commutateur -ot. La valeur non mise à l'échelle est calculée à partir de la valeur brute mise à l'échelle avec la formule suivante :


{unscaled\_value} = {scaled\_value} * {scale} + {offset}



-srcwin <xoff> <yoff> <xsize> <ysize>
Sélectionne une sous-fenêtre de l'image source pour la copie basée sur la position pixel/ligne. Les décalages pixel/ligne (xoff et yoff) sont mesurés à partir du bord gauche et supérieur de l'image. Si la sous-fenêtre dépasse les limites du jeu de données source, les pixels de sortie seront écrits avec une valeur de zéro, à moins qu'une valeur NoData ne soit définie soit dans le jeu de données source, soit par -a_nodata. Alternativement, gdal_translate peut émettre une erreur dans ce cas si cela est dirigé par les options -epo ou -eco.
-projwin <ulx> <uly> <lrx> <lry>
Sélectionne une sous-fenêtre de l'image source pour la copie (comme -srcwin) mais avec les coins donnés en coordonnées géoréférencées (par défaut exprimées dans le SRS du jeu de données. Peut être modifié avec -projwin_srs). Si la sous-fenêtre dépasse les limites du jeu de données source, les pixels de sortie seront écrits avec une valeur de zéro, à moins qu'une valeur NoData ne soit définie soit dans le jeu de données source, soit par -a_nodata. Alternativement, gdal_translate peut émettre une erreur dans ce cas si cela est dirigé par les options -epo ou -eco.

NOTE :

À partir de GDAL 3.11, l'étendue décrite par -projwin sera transformée dans le SRS du jeu de données et utilisée pour sélectionner une sous-fenêtre. Avant GDAL 3.11, seuls les deux points d'angle étaient transformés dans le SRS du jeu de données, et ces deux points transformés étaient utilisés pour définir une étendue dans le SRS du jeu de données. Selon les SRS impliqués, la sous-fenêtre sélectionnée dans GDAL 3.11 peut être substantiellement plus grande que dans les versions précédentes.

NOTE :

Lors de l'utilisation de la rééchantillonnage du plus proche voisin, la fenêtre spécifiée par -projwin est étendue (arrondie, pour GDAL < 3.11) si nécessaire pour correspondre aux limites des pixels d'entrée. Pour les autres algorithmes de rééchantillonnage, la fenêtre n'est pas modifiée.
-projwin_srs <srs_def>
Spécifie le SRS dans lequel interpréter les coordonnées données avec -projwin. <srs_def> peut être l'une des formes habituelles de GDAL/OGR, un WKT complet, PROJ.4, EPSG:n ou un fichier contenant le WKT.

ATTENTION :

Cela ne provoque pas la reprojection du jeu de données dans le SRS spécifié.
-epo
(Erreur en cas de dépassement partiel) Si cette option est activée, les valeurs -srcwin ou -projwin qui dépassent partiellement l'étendue du raster source seront considérées comme une erreur. Le comportement par défaut est d'accepter de telles requêtes.
-eco
(Erreur en cas de dépassement complet) Identique à -epo, sauf que le critère d'erreur est lorsque la requête dépasse complètement l'étendue du raster source.
-a_srs <srs_def>
Remplace la projection pour le fichier de sortie. Peut être utilisé avec -a_ullr ou -a_gt pour spécifier l'étendue dans cette projection.

Les systèmes de coordonnées de référence qui peuvent être passés sont tous ceux pris en charge par l'appel OGRSpatialReference::SetFromUserInput(), ce qui inclut les CRS projetés, géographiques ou composés EPSG (c'est-à-dire EPSG:4296), une définition de CRS en texte bien connu (WKT), des déclarations PROJ.4, ou le nom d'un fichier .prj contenant une définition de CRS WKT.

NOTE :

Aucune reprojection n'est effectuée.
-a_coord_epoch <epoch>
Ajouté dans la version 3.4.

Attribue une époque de coordonnées, liée au SRS de sortie. Utile lorsque le SRS de sortie est un CRS dynamique.

-a_scale <value>
Définit la valeur d'échelle de bande. Aucune modification des valeurs de pixels n'est effectuée. Notez que -unscale ne prend pas en compte -a_scale. Vous pouvez par exemple spécifier -scale 0 1 <offset> <offset+scale> pour appliquer un tuple (décalage, échelle), pour l'équivalent des 2 étapes : gdal_translate input.tif tmp.vrt -a_scale scale -a_offset offset suivi de gdal_translate tmp.vrt output.tif -unscale
-a_offset <value>
Définit la valeur de décalage de bande. Aucune modification des valeurs de pixels n'est effectuée. Notez que -unscale ne prend pas en compte -a_offset. Vous pouvez par exemple spécifier -scale 0 1 <offset> <offset+scale> pour appliquer un tuple (décalage, échelle), pour l'équivalent des 2 étapes : gdal_translate input.tif tmp.vrt -a_scale scale -a_offset offset suivi de gdal_translate tmp.vrt output.tif -unscale
-a_ullr <ulx> <uly> <lrx> <lry>
Attribue/remplace les limites géoréférencées du fichier de sortie. Cela attribue des limites géoréférencées au fichier de sortie, ignorant ce qui aurait été dérivé du fichier source. Cela ne provoque donc pas de reprojection vers le SRS spécifié. Ceci est mutuellement exclusif avec -a_gt
-a_gt <gt(0)> <gt(1)> <gt(2)> <gt(3)> <gt(4)> <gt(5)>
Attribue/remplace le géotransform du fichier de sortie. Cela attribue le géotransform au fichier de sortie, ignorant ce qui aurait été dérivé du fichier source. Cela ne provoque donc pas de reprojection vers le SRS spécifié. Voir Tutoriel sur le géotransform. Ceci est mutuellement exclusif avec -a_ullr

Ajouté dans la version 3.8.

-a_nodata <value>
Attribue une valeur nodata spécifiée aux bandes de sortie. Elle peut être définie sur none pour éviter de définir une valeur nodata pour le fichier de sortie si elle existe pour le fichier source. Notez que si le jeu de données d'entrée a une valeur nodata, cela ne provoque pas le changement des valeurs de pixels égales à cette valeur nodata à la valeur spécifiée avec cette option.

NODATA / GESTION DU MASQUE DE VALIDITÉ SOURCE PENDANT LE RÉÉCHANTILLONNAG

E

Les valeurs masquées, qu'elles soient identifiées par une valeur nodata définie dans les métadonnées de la bande source, une bande masque ou une bande alpha, ne seront pas utilisées lors du rééchantillonnage (lors de l'utilisation de -outsize ou -tr

).
orphe
lin

Les détails de la prise en compte dépendent du noyau de rééchantillonnage

:
  • pour le rééchantillonnage au plus proche, pour chaque pixel cible, l'un des pixels source pouvant contribuer est sélectionné (d'une manière spécifique à l'implémentation). Sa valeur est utilisée telle quelle, qu'elle soit valide ou
    • non.
  • pour bilinéaire, cubique, cubique-spline et lanczos, pour chaque pixel cible, les poids des pixels source contributeurs sont mis à zéro pour les ignorer lorsqu'ils sont masqués. Il y a une spécificité supplémentaire pour cubique : étant donné que certains des poids du noyau sont négatifs, une telle stratégie pourrait conduire à un fort dépassement/sous-dépassement lorsqu'il y a une alternance de pixels valides et invalides. Par conséquent, si dans l'une des directions horizontale ou verticale, le nombre maximal de pixels source valides dans chaque dimension est inférieur au rayon du noyau de rééchantillonnage, le pixel cible est considéré comme
    • nodata.
  • pour les autres méthodes de rééchantillonnage, le
    • s pixels source contribuant au pixel cible
sont ignorés s'ils sont masqués. Seuls les pixels
valides sont pris en compte. S'il n'y en a
aucun, le pixel cible est considéré comme nodata.
