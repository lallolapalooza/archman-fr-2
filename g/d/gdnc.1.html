NOM

gdnc - Centre de notification distribué GNUstep

SYNTAXE

gdnc

DESCRIPTION

Le démon gdnc est utilisé par les programmes GNUstep pour s'envoyer mutuellement des notifications et des messages. Par défaut, il utilise des communications inter-processus privées accessibles uniquement par l'utilisateur courant sur la machine sur laquelle il s'exécute (là où le système d'exploitation les prend en charge).

Chaque utilisateur doit avoir sa propre instance de gdnc en cours d'exécution. Bien que gdnc soit démarré automatiquement dès qu'il est nécessaire, il est recommandé de démarrer gdnc dans un script de connexion personnel comme ~/.bashrc ou ~/.cshrc. Alternativement (si vous n'avez pas d'outils en ligne de commande qui utilisent des notifications distribuées), vous pouvez lancer gdnc au démarrage de votre système de fenêtrage ou de votre gestionnaire de fenêtres. Par exemple, sur les systèmes avec X11, vous pouvez lancer gdnc depuis votre script .xinitrc ou, alternativement, si vous utilisez Window Maker, le placer dans le script de démarrage automatique de Window Maker. Consultez le GNUstep Build Guide pour un exemple de script de démarrage.

OPTIONS

Pour attacher gdnc à une session distante, utilisez l'argument

-NSHost nom_hôte

Pour exécuter une copie du serveur afin de gérer les notifications publiques (disponibles pour tous les utilisateurs sur la machine locale)

-GSPublic YES

Pour exécuter une copie du serveur afin de gérer les notifications réseau-publiques (disponibles pour tous les utilisateurs capables de se connecter à la machine locale sur le réseau)

-GSNetwork YES

DIAGNOSTICS

gdomap -L GDNCServer recherchera les instances de gdnc qui ont été lancées avec les arguments de ligne de commande NSHost, GSPublic ou GSNetwork.

Alternativement, gdomap -N listera tous les noms enregistrés sur l'hôte local.

VOIR AUSSI

gdomap(8), GNUstep(7), gpbs(1)

Script de démarrage d'exemple du GNUstep Build Guide: http://gnustep.made-it.com/BuildGuide/index.html#GNUSTEP.SERVICES
