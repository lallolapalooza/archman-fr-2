NOM

gdal-vector-simplify - Simplifie les géométries d'un jeu de données vectoriel

Ajouté dans la version 3.12.

SYNTAXE

Usage: gdal vector simplify [OPTIONS] <ENTREE> <SORTIE> <TOLERANCE>
Simplifie les géométries d'un jeu de données vectoriel.
Arguments positionnels :
  -i, --input <ENTREE>                                 Jeu(x) de données vectoriel(s) d'entrée [requis]
  -o, --output <SORTIE>                                Jeu de données vectoriel de sortie [requis]
  --tolerance <TOLERANCE>                              Tolérance de distance pour la simplification. [requis]
Options courantes :
  -h, --help                                           Affiche le message d'aide et quitte
  --json-usage                                         Affiche l'utilisation sous forme de document JSON et quitte
  --config <CLE>=<VALEUR>                               Option de configuration [peut être répétée]
  -q, --quiet                                          Mode silencieux (pas de barre de progression)
Options :
  -l, --layer, --input-layer <COUCHE-ENTREE>           Nom(s) de la ou des couches d'entrée [peut être répété]
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLE>=<VALEUR>              Option de création [peut être répétée]
  --lco, --layer-creation-option <CLE>=<VALEUR>        Option de création de couche [peut être répétée]
  --overwrite                                          Autoriser l'écrasement du fichier de sortie existant
  --update                                             Ouvrir le jeu de données existant en mode mise à jour
  --overwrite-layer                                    Autoriser l'écrasement de la couche de sortie existante
  --append                                             Ajouter à la couche existante
                                                       Mutuellement exclusif avec --upsert
  --output-layer <COUCHE-SORTIE>                       Nom de la couche de sortie
  --skip-errors                                        Ignorer les erreurs lors de l'écriture des entités
  --active-layer <COUCHE-ACTIVE>                       Définir la couche active (si non spécifié, toutes)
  --active-geometry <GEOMETRIE-ACTIVE>                 Nom du champ géométrique auquel restreindre le traitement (si non spécifié, toutes)
Options avancées :
  --if, --input-format <FORMAT-ENTREE>                 Formats d'entrée [peut être répété]
  --oo, --open-option <CLE>=<VALEUR>                   Options d'ouverture [peut être répétée]
  --output-oo, --output-open-option <CLE>=<VALEUR>     Options d'ouverture de sortie [peut être répétée]
  --upsert                                             Mettre à jour/insérer des entités (implique 'append')
                                                       Mutuellement exclusif avec --append

DESCRIPTION

gdal vector simplify simplifie les géométries, en s'assurant que le résultat est une géométrie valide ayant la même dimension et le même nombre de composantes que l'entrée.

La simplification utilise un algorithme de différence de distance maximale similaire à celui utilisé dans l'algorithme de Douglas-Peucker.

Ceci est réalisé par la méthode OGRGeometry::SimplifyPreserveTopology() qui préserve la topologie par entité, mais pas pour une couche entière. Ainsi, des trous ou des chevauchements peuvent apparaître entre des géométries qui étaient initialement contiguës. Pour effectuer une simplification qui préserve les frontières partagées entre les géométries, voir gdal vector simplify-coverage.

Cette commande peut également être utilisée comme une étape de gdal vector pipeline.

NOTE :

Cette commande nécessite une compilation de GDAL contre la bibliothèque GEOS.

Options standard

-f, --of, --format, --output-format <FORMAT-SORTIE>
Quel format vectoriel de sortie utiliser. Les valeurs autorisées peuvent être obtenues avec gdal --formats | grep vector | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création de jeu de données facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoPackage prend en charge des options de création pour contrôler la version.

Peut être répété.

Les options de création de jeu de données disponibles varient selon le pilote de format, et certains formats simples n'ont aucune option de création. Une liste des options prises en charge pour un format peut être listée avec l'option de ligne de commande --formats, mais la documentation du format est la source d'information définitive sur les options de création du pilote. Voir la documentation spécifique du format des pilotes vectoriels pour les options de création autorisées pour chaque format.

Notez que les options de création de jeu de données sont différentes des options de création de couche.

-lco <NOM>=<VALEUR>
Option de création de couche (spécifique au format)
--overwrite
Permet au programme d'écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal génère une erreur si le fichier ou le jeu de données cible existe déjà.
--active-layer <COUCHE-ACTIVE>
Définit la couche active. Lorsqu'elle est spécifiée, seule la couche spécifiée par son nom sera traitée. Les autres couches ne seront pas modifiées. Si cette option n'est pas spécifiée, toutes les couches seront traitées.
--active-geometry <GEOMETRIE-ACTIVE>
Définit le champ géométrique actif à partir de son nom. Lorsqu'il est spécifié, seul le champ géométrique spécifié sera traité. Les autres champs géométriques ne seront pas modifiés. Si cette option n'est pas spécifiée, tous les champs géométriques seront traités. Cette option peut être combinée avec --active-layer.
--tolerance <TOLERANCE>
La valeur spécifiée pour cette option est la tolérance utilisée pour fusionner les points consécutifs de la géométrie de sortie en utilisant la méthode OGRGeometry::SimplifyPreserveTopology(). L'unité de la distance est dans les unités géoréférencées de la couche source.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture du jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à tenter pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour éviter la détection automatique du pilote, lorsque celle-ci échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichier.

Peut être répété.

SORTIE GDALG (TEMPS RÉEL / FLUX DE DONNÉES)

Ce programme prend en charge la sérialisation de la ligne de commande sous forme de fichier JSON en utilisant le format de sortie GDALG. Le fichier résultant peut ensuite être ouvert comme un jeu de données vectoriel en utilisant le pilote GDALG: GDAL Streamed Algorithm, et appliquer le pipeline spécifié de manière temps réel / en flux.

EXEMPLES

Exemple 1 : Simplifier les géométries en utilisant une tolérance d'un km (en supposant que la CRS est en mètres)

$ gdal vector simplify --tolerance=1000 in.gpkg out.gpkg --overwrite
