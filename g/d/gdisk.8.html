NOM

gdisk - Manipulateur interactif de table de partitions GUID (GPT)

SYNTAXE

gdisk [ -l ] périphérique

DESCRIPTION

GPT fdisk (alias gdisk) est un programme piloté par menu en mode texte pour la création et la manipulation de tables de partitions. Il convertira automatiquement une ancienne table de partitions Master Boot Record (MBR) ou un disque-label BSD stocké sans partition de transport MBR au nouveau format Globally Unique Identifier (GUID) Partition Table (GPT), ou chargera une table de partitions GUID. Lorsqu'il est utilisé avec l'option de ligne de commande -l, le programme affiche la table de partitions actuelle puis se quitte.

GPT fdisk opère principalement sur les en-têtes et tables de partitions GPT ; cependant, il peut et générera un MBR protecteur frais, si nécessaire. (Tout code de chargeur de démarrage dans le MBR protecteur ne sera pas perturbé.) Si vous avez créé un MBR protecteur inhabituel, tel qu'un MBR hybride créé par gptsync ou la propre fonction de création de MBR hybride de gdisk, cela ne devrait pas être perturbé par la plupart des actions ordinaires. Certaines options de récupération de données avancées nécessitent que vous compreniez les distinctions entre les données principales et de sauvegarde, ainsi qu'entre les en-têtes GPT et les tables de partitions. Pour plus d'informations sur MBR vs GPT, ainsi que sur la terminologie et la structure GPT, consultez la documentation étendue de gdisk sur https://www.rodsbooks.com/gdisk/ ou consultez Wikipedia.

Le programme gdisk utilise une interface utilisateur similaire à celle de fdisk de Linux, mais gdisk modifie les partitions GPT. Il a également la capacité de transformer des partitions MBR ou des disklabels BSD en partitions GPT. Comme le programme fdisk original, gdisk ne modifie pas les structures du disque tant que vous ne les écrivez pas explicitement sur le disque, donc si vous faites une erreur, vous pouvez quitter le programme avec l'option 'q' pour laisser vos partitions inchangées.

Normalement, gdisk opère sur les fichiers de périphérique disque, tels que /dev/sda ou /dev/hda sous Linux, /dev/disk0 sous Mac OS X, ou /dev/ad0 ou /dev/da0 sous FreeBSD. Le programme peut également opérer sur des fichiers d'image disque, qui peuvent être soit des copies de disques entiers (créés avec dd, par exemple) soit des images disque brutes utilisées par des émulateurs tels que QEMU ou VMWare. Notez que seules les images disque *brutes* sont prises en charge ; gdisk ne peut pas fonctionner sur des formats d'image disque compressés ou autres formats avancés.

Le système de partitionnement MBR utilise une combinaison d'adressage cylindre/tête/secteur (CHS) et d'adressage par blocs logiques (LBA). Le premier est rudimentaire et limitatif. GPT abandonne l'adressage CHS et utilise exclusivement le mode LBA 64 bits. Ainsi, les structures de données GPT, et donc gdisk, n'ont pas besoin de traiter les géométries CHS et tous les problèmes qu'elles créent. Les utilisateurs de fdisk noteront que gdisk manque des options et des limitations associées aux géométries CHS.

Pour de meilleurs résultats, vous devriez utiliser un programme de table de partitions spécifique au système d'exploitation chaque fois que possible. Par exemple, vous devriez créer des partitions Mac OS X avec le programme Utilitaire de disque de Mac OS X et des partitions Linux avec le programme gdisk de Linux ou GNU Parted.

Au démarrage, gdisk tente d'identifier le type de partition utilisé sur le disque. S'il trouve des données GPT valides, gdisk les utilisera. Si gdisk trouve un MBR valide ou un disque-label BSD mais aucune donnée GPT, il tentera de convertir le MBR ou le disque-label en format GPT. (Les disklabels BSD auront probablement des partitions première et/ou dernière inutilisables car elles chevauchent les structures de données GPT, cependant.) GPT fdisk peut identifier, mais pas utiliser les données de, les disques Apple Partition Map (APM), qui sont utilisés sur les Macintosh basés sur 680x0 et PowerPC. En quittant avec l'option 'w', gdisk remplace le MBR ou le disque-label par un GPT. Cette action est potentiellement dangereuse ! Votre système peut devenir non amorçable, et les codes de type de partition peuvent être corrompus si le disque utilise des codes de type non reconnus. Des problèmes de démarrage sont particulièrement probables si vous êtes en multi-amorçage avec un système d'exploitation non compatible GPT. Si vous lancez par erreur gdisk sur un disque MBR, vous pouvez quitter le programme en toute sécurité sans faire de changements en utilisant l'option 'q'.

La conversion MBR vers GPT laissera au moins un espace dans la numérotation des partitions si le MBR original utilisait des partitions logiques. Ces espaces sont inoffensifs, mais vous pouvez les éliminer en utilisant l'option 's', si vous le souhaitez. (Faire cela peut nécessiter de mettre à jour votre fichier /etc/fstab.)

Lors de la création d'une nouvelle table de partitions, certaines considérations peuvent être appropriées :

*
Pour les disques de données (non amorçables), et pour les disques amorçables utilisés sur les ordinateurs basés sur BIOS avec GRUB comme chargeur de démarrage, les partitions peuvent être créées dans l'ordre et les tailles souhaitées.
*
Les disques amorçables pour les systèmes basés sur EFI nécessitent une partition système EFI (code interne gdisk 0xEF00) formatée en FAT-32. Je recommande de créer cette partition sur 550 Mio. (Des ESP plus petites sont courantes, mais certains EFI ont des pilotes FAT fragiles qui nécessitent une partition plus grande pour un fonctionnement fiable.) Les fichiers liés au démarrage y sont stockés. (Notez que GNU Parted identifie de telles partitions comme ayant le « drapeau d'amorçage » réglé.)
*
Certains chargeurs de démarrage pour systèmes basés sur BIOS utilisent une partition d'amorçage BIOS (code interne gdisk 0xEF02), dans laquelle le chargeur de démarrage secondaire est stocké, potentiellement sans système de fichiers. (GRUB2 peut utiliser facultativement une telle partition.) Cette partition peut généralement être assez petite (environ 32 à 200 Kio, bien que 1 Mio soit plus courant en pratique), mais vous devriez consulter la documentation de votre chargeur de démarrage pour plus de détails.
*
Si Windows doit démarrer à partir d'un disque GPT, une partition de type Réservé à Microsoft (code interne gdisk 0x0C01) est recommandée. Cette partition devrait faire environ 128 Mio. Elle suit généralement la partition système EFI et précède immédiatement les partitions de données Windows. (Notez que les anciennes versions de GNU Parted créent toutes les partitions FAT avec ce type, ce qui rend en fait la partition inutilisable pour le stockage de fichiers normal sous Windows et Mac OS X.)
*
Certains utilitaires GPT d'OS créent un espace vide (généralement 128 Mio) après chaque partition. L'intention est de permettre aux futurs utilitaires de disque d'utiliser cet espace. Un tel espace libre n'est pas requis pour les disques GPT, mais sa création peut aider à la maintenance future du disque. Vous pouvez utiliser l'option de positionnement relatif des partitions de GPT fdisk (en spécifiant le secteur de départ comme '+128M', par exemple) pour simplifier la création de tels espaces.

OPTIONS

-l
Liste la table de partitions pour le périphérique spécifié et quitte.

La plupart des interactions avec gdisk se font via ses menus interactifs en mode texte. Trois menus existent : le menu principal, le menu de récupération et de transformation, et le menu des experts. Le menu principal fournit les fonctions les plus susceptibles d'être utiles pour les tâches de partitionnement typiques, telles que la création et la suppression de partitions, la modification des codes de type de partition, etc. Les fonctions spécifiques sont :

b
Sauvegarde les données de partition dans un fichier de sauvegarde. Vous pouvez sauvegarder votre table de partitions actuelle en mémoire dans un fichier disque en utilisant cette option. Le fichier résultant est un fichier binaire composé du MBR protecteur, de l'en-tête GPT principal, de l'en-tête GPT de sauvegarde et d'une copie de la table de partitions, dans cet ordre. Notez que la sauvegarde concerne les structures de données actuelles en mémoire, donc si vous lancez le programme, apportez des modifications, puis utilisez cette option, la sauvegarde reflétera vos modifications. Notez également que l'option de restauration se trouve sur le menu de récupération et de transformation ; l'option de sauvegarde se trouve sur le menu principal pour encourager son utilisation.
c
Change le nom GPT d'une partition. Ce nom est encodé sous forme de chaîne UTF-16, mais une entrée et un affichage corrects de tout ce qui dépasse les valeurs ASCII de base nécessitent un environnement local et une prise en charge des polices appropriées. Pour la plupart, Linux ignore le nom de la partition, mais il peut être important dans certains systèmes d'exploitation. GPT fdisk définit un nom par défaut basé sur le code de type de partition. Notez que le nom de partition GPT est différent du nom de système de fichiers, qui est encodé dans les structures de données du système de fichiers.
d
Supprime une partition. Cette action supprime l'entrée de la table de partitions mais ne perturbe pas les données à l'intérieur des secteurs initialement alloués à la partition sur le disque. Si une partition MBR hybride correspondante existe, gdisk la supprime également, et étend

Afficher un résumé des types de partition. GPT utilise un GUID pour identifier les types de partition pour des systèmes d'exploitation et des usages particuliers. Pour faciliter la saisie des données, gdisk les compresse en valeurs de deux octets (quatre chiffres hexadécimaux) qui sont liées à leurs codes MBR équivalents. Plus précisément, le code MBR est multiplié par hexadécimal 0x0100. Par exemple, le code pour l'espace d'échange Linux en MBR est 0x82, et il est 0x8200 dans gdisk. Une correspondance un-à-un est cependant impossible. Le plus notablement, les codes pour toutes les variétés de partitions FAT et NTFS correspondent à un seul code GPT (saisi comme 0x0700 dans gdisk). Certains systèmes d'exploitation utilisent un seul code MBR mais emploient beaucoup plus de codes en GPT. Pour ceux-ci, gdisk ajoute les numéros de code séquentiellement, comme 0xa500 pour un disklabel FreeBSD, 0xa501 pour FreeBSD boot, 0xa502 pour FreeBSD swap, et ainsi de suite. Notez que ces codes de deux octets sont uniques à gdisk. n
Créer une nouvelle partition. Cette commande est modelée d'après l'option fdisk équivalente, bien que quelques différences existent. Vous saisissez un numéro de partition, un secteur de début et un secteur de fin. Les secteurs de début et de fin peuvent tous deux être spécifiés en termes absolus comme numéros de secteurs ou comme positions mesurées en kibioctets (K), mébioctets (M), gibioctets (G), tébioctets (T), ou pébioctets (P) ; par exemple, 40M spécifie une position à 40MiB du début du disque. Vous pouvez spécifier des positions relatives au début ou à la fin de la plage par défaut spécifiée en faisant précéder le nombre par un symbole '+' ou '-', comme dans +2G pour spécifier un point à 2GiB après le secteur de début par défaut, ou -200M pour spécifier un point à 200MiB avant le dernier secteur disponible. Appuyer sur la touche Entrée sans saisie spécifie la valeur par défaut, qui est le début du plus grand bloc disponible pour le secteur de début et la fin du même bloc pour le secteur de fin. Les points de début et de fin par défaut peuvent être ajustés pour optimiser l'alignement des
partitions.
o
Effacer toutes les données de partition. Ceci inclut les données d'en-tête GPT, toutes les définitions de partition, et le MBR protecteur. L'alignement des secteurs est réinitialisé à la valeur par défaut (1 MiB, ou 2048 secteurs sur un disque avec des secteurs de 512 octets)
.
p
Afficher les données de base résumées de la partition. Ceci inclut les numéros de partition, les numéros de secteurs de début et de fin, les tailles de partition, les codes de type de partition de gdisk, et les noms de partition. Pour des informations supplémentaires, utilisez la commande
'i'.
q
Quitter le programme sans sauvegarder vos changements. Utilisez cette option si vous vouliez juste voir des informations ou si vous faites une erreur et voulez annuler tous vos
changements.
r
Entrer dans le menu de récupération & transformation. Ce menu inclut des options de récupération d'urgence (pour réparer des structures de données GPT endommagées) et des options pour transformer vers ou depuis d'autres systèmes de partitionnement, incluant la création de MBR
hybrides.
s
Trier les entrées de partition. Les numéros de partition GPT n'ont pas besoin de correspondre à l'ordre des partitions sur le disque. Si vous voulez qu'ils correspondent, vous pouvez utiliser cette option. Notez que certaines utilitaires de partitionnement trient les partitions chaque fois qu'ils font des changements. De tels changements seront reflétés dans vos noms de fichiers de périphérique, donc vous pourriez avoir besoin d'éditer /etc/fstab si vous utilisez cette
option.
t
Changer le code de type d'une seule partition. Vous saisissez le code de type en utilisant un nombre hexadécimal de deux octets, comme décrit précédemment. Vous pouvez aussi saisir un GUID directement, si vous en avez un et que gdisk ne le connaît
pas.
v
Vérifier le disque. Cette option vérifie une variété de problèmes, tels que des CRC incorrects et des données principales et de sauvegarde non concordantes. Cette option ne corrige pas automatiquement la plupart des problèmes, cependant ; pour cela, vous devez utiliser les options du menu de récupération & transformation. Si aucun problème n'est trouvé, cette commande affiche un résumé de l'espace disque non
alloué.
w
Écrire les données. Utilisez cette commande pour sauvegarder vos
changements.
x
Entrer dans le menu des experts. Utiliser cette option donne accès à des fonctionnalités que vous pouvez utiliser pour vous mettre dans encore plus d'ennuis que le menu principal ne le
permet.
?
Afficher le menu. Tapez cette commande (ou
toute autre commande non reconnue) pour voir un résumé des options disponibles.

Le deuxième menu de gdisk est le menu de récupération & transformation, qui donne accès aux options de récupération de données et aux fonctionnalités liées à la transformation des partitions entre schémas de partitionnement (convertir des disklabels BSD en partitions GPT ou créer des MBR hybrides, par exemple). Quelques options de ce menu dupliquent la fonctionnalité du menu principal, par commodité. Les options de ce menu sont

:
b
Reconstruire l'en-tête GPT à partir de la sauvegarde. Vous pouvez utiliser l'en-tête GPT de sauvegarde pour reconstruire l'en-tête GPT principal avec cette option. Elle est susceptible d'être utile si votre en-tête GPT principal a été endommagé ou détruit (disons, par une utilisation négligente de dd)
.
c
Charger la table de partition de sauvegarde. Ordinairement, gdisk utilise seulement la table de partition principale (bien que l'intégrité de la sauvegarde soit vérifiée quand vous lancez le programme). Si la table de partition principale a été endommagée, vous pouvez utiliser cette option pour charger la sauvegarde depuis le disque et l'utiliser à la place. Notez que cela produira presque certainement aucune entrée de partition ou des entrées étranges si vous venez de convertir un disque MBR au format GPT, puisqu'il n'y aura pas de table de partition de sauvegarde sur le
disque.
d
Utiliser l'en-tête GPT principal et reconstruire la sauvegarde. Cette option est susceptible d'être utile si l'en-tête GPT de sauvegarde a été endommagé ou
détruit.
e
Charger la table de partition principale. Cette option recharge la table de partition principale depuis le disque. Elle n'est susceptible d'être utile que si vous avez essayé d'utiliser la table de partition de sauvegarde (via 'c') mais qu'elle est en pire état que la table de partition
principale.
f
Charger le MBR et construire un GPT frais à partir de celui-ci. Utilisez cette option si votre GPT est corrompu ou entre en conflit avec le MBR et que vous voulez utiliser le MBR comme base pour un nouveau ensemble de partitions
GPT.
g
Convertir GPT en MBR et sortir. Cette option convertit autant de partitions que possible en forme MBR, détruit les structures de données GPT, sauvegarde le nouveau MBR, et sort. Utilisez cette option si vous avez essayé GPT et trouvez que MBR fonctionne mieux pour vous. Notez que cette fonction génère jusqu'à quatre partitions primaires MBR ou trois partitions primaires et autant de partitions logiques que possible. Chaque partition logique nécessite au moins un bloc non alloué immédiatement avant son premier bloc. Par conséquent, il peut être possible de convertir un maximum de quatre partitions sur des disques avec des partitions serrées ; cependant, si de l'espace libre a été inséré entre les partitions quand elles ont été créées, et si le disque fait moins de 2 TiB, il devrait être possible de convertir toutes les partitions en forme MBR. Voir aussi l'option
'h'.
h
Créer un MBR hybride. C'est une solution de contournement laide qui permet aux systèmes d'exploitation non conscients de GPT, ou à ceux qui ne peuvent pas démarrer depuis un disque GPT, d'accéder jusqu'à trois des partitions sur le disque en créant des entrées MBR pour elles. Notez que ces entrées MBR hybrides peuvent facilement se désynchroniser des entrées GPT, particulièrement quand des utilitaires GPT non conscients de l'hybride sont utilisés pour éditer le disque. Ainsi, vous pourriez avoir besoin de recréer le MBR hybride si vous utilisez de tels outils. Contrairement à l'option 'g', cette option ne supporte pas la conversion de partitions en partitions logiques
MBR.
i
Afficher des informations détaillées sur la partition. Cette option est identique à l'option 'i' du menu
principal.
l
Charger les données de partition depuis un fichier de sauvegarde. Cette option est l'inverse de l'option 'b' du menu principal. Notez que la restauration des données de partition depuis autre chose que le disque original n'est pas
recommandée.

Retourner au menu principal. Cette option vous permet de saisir des commandes du menu
principal.
o
Afficher les données du MBR protecteur. Vous pouvez voir un résumé des partitions du MBR protecteur avec cette option. Cela peut vous permettre de repérer des problèmes évidents ou aider à identifier les partitions dans un MBR
hybride.

Afficher la table de partition. Cette option est identique à l'option 'p' du menu
principal.
q
Quitter sans sauvegarder les changements. Cette option est identique à l'option 'q' du menu
principal.

Transformer les partitions BSD en partitions GPT. Cette option fonctionne sur les disklabels BSD contenus dans des partitions GPT (ou MBR converti). Les codes de type des partitions converties nécessiteront probablement un ajustement manuel. gdisk essaiera de convertir les disklabels BSD stockés sur le disque principal au lancement, mais cette conversion est susceptible de produire des premières et/ou dernières partitions inutilisables. Les nombreuses variantes BSD signifient que la probabilité que gdisk soit incapable de convertir un disklabel BSD est élevée par rapport à la probabilité de problèmes avec une conversion

Le troisième menu de gdisk est le menu des experts. Ce menu fournit des options avancées qui ne sont pas étroitement liées à la récupération ou à la transformation entre systèmes de partitionnement. Ses options sont

:
a
Définir les attributs. GPT fournit un champ d'attributs de 64 bits qui peut être utilisé pour définir des fonctionnalités pour chaque partition. gdisk prend en charge quatre attributs : partition système, lecture seule, cachée, et ne pas monter automatiquement. Vous pouvez définir d'autres attributs, mais leurs numéros ne sont pas traduits en quelque chose d'utile. En pratique, la plupart des OS semblent ignorer ces
attributs.
b
Inverse l'ordre des octets pour le nom de la partition spécifiée. Certains outils de partitionnement, y compris GPT fdisk 1.0.7 et antérieurs, peuvent écrire le nom de la partition dans le mauvais ordre d'octets sur les ordinateurs big-endian, tels que les mainframes IBM s390 et les Mac basés sur PowerPC. Cette fonctionnalité corrige ce
problème.
c
Modifier le GUID de la partition. Vous pouvez entrer un GUID unique personnalisé pour une partition en utilisant cette option. (Notez que cela fait référence au GUID qui identifie de manière unique une partition, pas à son code de type, que vous pouvez changer avec l'option 't' du menu principal.) Ordinairement, gdisk attribue ce numéro aléatoirement ; cependant, vous pourriez vouloir ajuster le numéro manuellement si vous vous retrouvez avec le même GUID sur deux partitions à cause d'attributions de GUID buggées (espérons-le pas dans gdisk) ou d'une coïncidence
incroyable.
d
Affiche la valeur d'alignement des secteurs. Voir la description de l'option 'l' pour plus de
détails.
e
Déplace les structures de données GPT de sauvegarde à la fin du disque. Utilisez cette commande si vous avez ajouté des disques à un tableau RAID, créant ainsi un disque virtuel avec un espace qui suit les structures de données GPT de sauvegarde. Cette commande déplace les structures de données GPT de sauvegarde à la fin du disque, où elles
appartiennent.
f
Rend le GUID du disque et tous les GUIDs uniques des partitions aléatoires (mais pas leurs GUIDs de code de type de partition). Cette fonction peut être utilisée après avoir cloné un disque avec une autre utilité afin de rendre tous les GUIDs à nouveau
uniques.
g
Modifier le GUID du disque. Chaque disque a un code GUID unique, que gdisk attribue aléatoirement lors de la création des structures de données GPT. Vous pouvez générer un nouveau GUID aléatoire ou en entrer un manuellement avec cette
option.
h
Recalcule les valeurs CHS dans le MBR protecteur ou hybride. Cette option peut parfois aider si un utilitaire de disque, un OS ou un BIOS n'aime pas les valeurs CHS utilisées par les partitions dans le MBR protecteur ou hybride. En particulier, la spécification GPT exige une valeur CHS de 0xFFFFFF pour les partitions de plus de 8 Gio, mais cette valeur est techniquement illégale selon les normes habituelles. Certains BIOS se bloquent s'ils rencontrent cette valeur. Cette option recalculera une valeur CHS plus normale -- 0xFEFFFF pour les partitions de plus de 8 Gio, permettant à ces BIOS de
démarrer.
i
Affiche les informations détaillées sur la partition. Cette option est identique à l'option 'i' du menu
principal.
j
Ajuste l'emplacement de la table de partition principale. Cette valeur est normalement 2, mais elle peut avoir besoin d'être augmentée dans certains cas, comme lorsqu'un système-sur-puce (SoC) est codé en dur pour lire le code de démarrage depuis le secteur 2. Je recommande de ne pas ajuster cette valeur à moins que ce soit absolument
nécessaire.
k
Ajuste l'emplacement de la table de partition de sauvegarde. Cette table de partition est normalement située juste avant les métadonnées de sauvegarde à la fin du disque, mais elle peut avoir besoin d'être déplacée dans quelques cas très rares. Je recommande de ne pas ajuster cette valeur à moins que ce soit absolument
nécessaire.
l
Modifier la valeur d'alignement des secteurs. Les disques avec plus de secteurs logiques par secteurs physiques (comme les disques Advanced Format modernes), certaines configurations RAID, et de nombreux dispositifs SSD, peuvent souffrir de problèmes de performance si les partitions ne sont pas correctement alignées pour leurs structures de données internes. Sur les nouveaux disques, GPT fdisk tente d'aligner les partitions sur des limites de 1 Mio (2048 secteurs sur les disques avec des secteurs de 512 octets) par défaut, ce qui optimise la performance pour tous ces types de disques. Sur les disques déjà partitionnés, GPT fdisk tente d'identifier la valeur d'alignement utilisée sur ce disque, mais définira un alignement de 8 secteurs sur les disques de plus de 300 Go même si des valeurs d'alignement inférieures sont détectées. Dans les deux cas, cela peut être changé en utilisant cette option. La valeur d'alignement affecte également la valeur de secteur de fin par défaut lors de la création d'une nouvelle partition ; elle sera alignée à un multiple de la valeur d'alignement moins un, si possible. Cela devrait maintenir les partitions en multiple de la valeur d'alignement en taille. Certains outils de chiffrement de disque exigent que les partitions aient une taille correspondant à une certaine valeur, généralement 4096 octets, donc l'alignement par défaut de 1 Mio fonctionne bien pour
eux.
m
Retour au menu principal. Cette option vous permet d'entrer des commandes du menu
principal.
n
Crée un nouveau MBR protecteur. Utilisez cette option si le MBR protecteur actuel est endommagé d'une manière que gdisk ne détecte et ne corrige pas automatiquement, ou si vous voulez convertir un MBR hybride en un GPT « pur » avec un MBR protecteur
conventionnel.
o
Affiche les données du MBR protecteur. Vous pouvez voir un résumé des partitions du MBR protecteur avec cette option. Cela peut vous permettre de repérer des problèmes évidents ou d'aider à identifier les partitions dans un MBR
hybride.
p
Affiche la table de partition. Cette option est identique à l'option 'p' du menu
principal.
q
Quitter sans enregistrer les changements. Cette option est identique à l'option 'q' du menu
principal.
r
Entrez dans le menu de récupération et transformations. Cette option est identique à l'option 'r' du menu
principal.
s
Redimensionner la table de partition. La taille par défaut de la table de partition est de 128 entrées. Officiellement, les tailles inférieures à 16 Kio (128 entrées, étant donné la taille normale d'une entrée) ne sont pas prises en charge par la spécification GPT ; cependant, en pratique, elles semblent fonctionner, et peuvent parfois être utiles lors de la conversion de disques MBR. Les tailles plus grandes fonctionnent également bien. Les OS peuvent imposer leurs propres limites sur le nombre de partitions,
cependant.
t
Échanger les entrées de deux partitions dans la table de partition. Une partition peut être vide. Par exemple, si les partitions 1-4 sont définies, la transposition de 1 et 5 résulte en une table avec des partitions numérotées de 2 à 5. La transposition des partitions de cette manière n'a aucun effet sur leur allocation d'espace disque ; cela altère seulement leur ordre dans la table de
partition.
u
Répliquer la table de partition de l'appareil actuel sur un autre appareil. On vous demandera de taper le nom de fichier du nouvel appareil. Après que l'opération d'écriture soit terminée, vous pouvez continuer à éditer la table de partition de l'appareil original. Notez que la table de partition répliquée est une copie exacte, y compris tous les GUIDs ; si l'appareil doit avoir ses propres GUIDs uniques, vous devriez utiliser l' option f sur le nouveau
disque.
v
Vérifier le disque. Cette option est identique à l'option 'v' du menu
principal.
z
Effacer (détruire) les structures de données GPT et quitter. Utilisez cette option si vous voulez repartitionner un disque GPT en utilisant fdisk ou un autre programme qui ne prend pas en charge GPT. On vous donnera le choix de préserver le MBR existant, au cas où ce serait un MBR hybride avec des partitions récupérables ou si vous avez déjà créé de nouvelles partitions MBR et voulez effacer les restes de vos partitions GPT. Si vous avez déjà créé de nouvelles partitions MBR, il est concevable que cette option endommage la première et/ou la dernière partition MBR ! Un tel événement est peu probable, mais pourrait survenir si vos nouvelles partitions MBR chevauchent les anciennes structures de données
GPT.
?
Affiche le menu. Cette option (ou t
oute entrée non reconnue) affiche u
n résumé des options du menu.

Dans de nombreux cas, vous pouvez appuyer sur la touche Entrée pour sélectionner une option par défaut lors de la saisie de données. Quand une seule option est possible, gdisk contourne générale

ment complètement l'invite.

BOGUE

S

Les bogues et limitations connus incluent

:
*
Le programme ne compile correctement que sous Linux, FreeBSD, Mac OS X et Windows. Les versions Linux pour x86-64 (64 bits), x86 (32 bits) et PowerPC (32 bits) ont été testées, la version x86-64 ayant été la plus testée. Sous FreeBSD, les versions 32 bits (x86) et 64 bits (x86-64) ont été testées. Seules les versions 32 bits pour Mac OS X et Windows ont été testées par l'auteur, bien que j'aie entendu dire que des versions 64 bits ont été compilées avec
succès.
*
La version FreeBSD du programme ne peut pas écrire les changements de la table de partition sur un disque quand les partitions existantes sur ce disque sont montées. (Le même problème existe avec de nombreuses autres utilités FreeBSD, telles que gpt, fdisk, et dd.) Cette limitation peut être surmontée en tapant sysctl kern.geom.debugflags=16 à l'invite d'un
shell.
*
Les champs utilisés pour afficher les numéros de secteur de début et de fin des partitions dans la commande 'p' ont une largeur de 14 caractères. Cela se traduit par une limitation d'environ 45 Pio. Sur les disques plus grands, les colonnes affichées seront
désalignées.
*
Dans la version Windows, seuls les caractères ASCII sont pris en charge dans le champ de nom de partition. Si une partition existante utilise des caractères UTF-16 non ASCII, ils sont susceptibles d'être corrompus dans l'affichage des options de menu 'i' et 'p' ; cependant, ils devraient être préservés lors du chargement et de l'enregistrement des partitions. Les binaires pour Linux, FreeBSD et OS X prennent en charge le UTF-16 completnoms de
partitions.
*
Le programme ne peut charger que jusqu'à 128 partitions (4 partitions primaires et 124 partitions logiques) lors de la conversion depuis le format MBR. Cette limite peut être augmentée en modifiant la ligne #define MAX_MBR_PARTS dans le fichier de code source basicmbr.h et en recompilant ; cependant, une telle modification nécessitera l'utilisation d'une table de partitions plus grande que la normale. (La limite de 128 partitions a été choisie car ce nombre est égal aux 128 partitions prises en charge par la taille de table de partitions la plus courante.
)
*
La conversion depuis le format MBR échoue parfois à cause d'un espace insuffisant au début ou (plus souvent) à la fin du disque. Le redimensionnement de la table de partitions (en utilisant l'option 's' du menu des experts) peut parfois résoudre ce problème ; cependant, dans les cas extrêmes, il peut être nécessaire de redimensionner une partition à l'aide de GNU Parted ou d'un outil similaire avant la conversion avec gdisk
.
*
Les conversions MBR ne fonctionnent que si le disque possède des descripteurs de partition LBA corrects. Ces descripteurs doivent être présents sur tout disque de plus de 8 Gio ou sur des disques plus petits partitionnés avec un logiciel autre que celui des temps très
anciens.
*
La prise en charge du disklabel BSD peut créer des premières et/ou dernières partitions qui se chevauchent avec les structures de données GPT. Cela peut parfois être compensé en ajustant la taille de la table de partitions, mais dans les cas extrêmes, la ou les partitions concernées peuvent nécessiter d'être
supprimées.
*
En raison de la nature hautement variable des structures de disklabel BSD, les conversions depuis cette forme peuvent être peu fiables -- des partitions peuvent être ignorées, converties de manière à créer des chevauchements avec d'autres partitions, ou converties avec des valeurs de début ou de fin incorrectes. Utilisez cette fonctionnalité avec prudence
!
*
Le démarrage après la conversion d'un disque MBR ou disklabel BSD est susceptible d'être perturbé. Parfois, la réinstallation d'un chargeur de dém
arrage corrigera le problème, mais d'autres fois, vous devrez peut-être changer de chargeur de démarrage. En dehors des plateformes basées sur EFI
, Windows jusqu'à au moins Windows 7 ne prend pas en charge le démarrage à partir de disques GPT. La création d'un MBR hybride (en utilisant
l'option 'h' du menu de récupération et de transformation) ou l'abandon du GPT au profit du MBR peuvent être vos seules options dans ce cas.
