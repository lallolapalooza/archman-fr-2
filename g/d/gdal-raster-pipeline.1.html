NOM

gdal-raster-pipeline - Traiter un jeu de données raster en appliquant plusieurs étapes

Ajouté dans la version 3.11.

DESCRIPTION

gdal raster pipeline peut être utilisé pour traiter un jeu de données raster et effectuer diverses étapes de traitement qui acceptent du raster et génèrent du raster.

Pour les pipelines mélangeant raster et vecteur, consultez gdal pipeline.

La plupart des étapes procèdent à une évaluation à la demande des blocs raster, sauf indication contraire dans leur documentation, sans « matérialiser » le jeu de données résultant de l'opération de chaque étape. Il peut être souhaitable parfois, pour des raisons de performance, de matérialiser un jeu de données intermédiaire sur disque en utilisant gdal raster materialize.

SYNTAXE

Usage: gdal raster pipeline [OPTIONS] <PIPELINE>
Traiter un jeu de données raster en appliquant plusieurs étapes.
Arguments positionnels :
Options communes :
  -h, --help              Afficher le message d'aide et quitter
  --json-usage            Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLE>=<VALEUR>  Option de configuration [peut être répétée]
  -q, --quiet             Mode silencieux (pas de barre de progression)
<PIPELINE> est de la forme : read|mosaic|stack [OPTIONS-LECTURE] ( ! <NOM-ÉTAPE> [OPTIONS-ÉTAPE] )* ! info|compare|tile|write [OPTIONS-ÉCRITURE]

Un pipeline enchaîne plusieurs étapes, séparées par le caractère ! (point d'exclamation). La première étape doit être read, calc, mosaic ou stack, et la dernière write, info ou tile. Chaque étape a ses propres arguments positionnels ou non positionnels. À part read, calc, mosaic, stack, compare, info, tile et write, toutes les autres étapes peuvent potentiellement être utilisées plusieurs fois dans un pipeline.

Les étapes potentielles sont :

* calc [OPTIONS] <ENTRÉES>...
----------------------------
Effectuer des calculs sur les rasters
Arguments positionnels :
  -i, --input <ENTRÉES>                                     Jeux de données raster d'entrée [1.. valeurs] [requis]
Options :
  --ot, --datatype, --output-data-type <TYPE-DONNÉES-SORTIE>  Type de données de sortie. TYPE-DONNÉES-SORTIE=Byte|Int8|UInt16|Int16|UInt32|Int32|UInt64|Int64|CInt16|CInt32|Float16|Float32|Float64|CFloat32|CFloat64

  --no-check-extent                                        Ne pas vérifier la cohérence des extensions d'entrée

GDALG OUTPUT (JEU DE DONNÉES À LA VOLÉE / EN

FLUX)

Un pipeline peut être sérialisé dans un fichier JSON en utilisant le GDALG format de sortie. Le fichier résultant peut ensuite être ouvert comme un jeu de données raster en utilisant le GDALG : pilote d'algorithme GDAL en flux, et appliquer le pipeline spécifié de manière à la volée / en

flux.

Le membre command_line du fichier JSON devrait nominativement être la ligne de commande entière sans l'étape finale write, et est ce qui est généré par gdal raster pipeline ! .... ! write

out.gdalg.json. 
{
    "type": "gdal_streamed_alg
", "command_line": "gdal ra
ster pipeline ! read in.tif ! r
eproject --dst-crs=EPSG:32632" }

L'étape finale write c

SOUS-RUBRIQUES

Peut être ajoutée, mais si c'est le cas, elle doit explicitement spécifier le format de sortie stream et un nom de jeu de données de sortie non significatif.

{

    "command_line": "gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write --output-format=streamed streamed_dataset"
}

SUBSTITUTIONS

Ajouté dans la version 3.12.

Il est possible d'utiliser gdal pipeline pour utiliser un pipeline déjà sérialisé dans un fichier .gdal.json, et de personnaliser ses étapes existantes, typiquement en changeant un nom de fichier d'entrée, en spécifiant un nom de fichier de sortie, ou en ajoutant/modifiant des arguments d'étapes.

Voir Substitutions.

PIPELINE IMBRIQUÉ

Ajouté dans la version 3.12.

Il est possible de créer des "pipelines imbriqués", c'est-à-dire des pipelines à l'intérieur de pipelines.

Un pipeline imbriqué est délimité par des crochets ([ et ]) entourés d'un espace.

Il existe 2 types de pipelines imbriqués :

  • pipelines imbriqués d'entrée : où le jeu de données résultat du pipeline imbriqué est utilisé comme jeu de données d'entrée pour un argument du pipeline principal.
  • pipelines imbriqués de sortie : où la sortie d'une étape du pipeline principal est utilisée comme entrée du pipeline imbriqué dans une étape suivante. Les pipelines imbriqués de sortie ne peuvent être utilisés qu'avec l'étape tee.

Voir Pipeline imbriqué.

EXEMPLES

Exemple 1 : Reprojeter un fichier GeoTIFF vers le SCR EPSG:32632 ("WGS 84 / UTM zone 32N") et ajouter un élément métadonnées

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! edit --metadata AUTHOR=EvenR ! write out.tif --overwrite

Exemple 2 : Sérialiser la commande d'une reprojection d'un fichier GeoTIFF dans un fichier GDALG, puis la lire

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write in_epsg_32632.gdalg.json --overwrite
$ gdal raster info in_epsg_32632.gdalg.json

Exemple 3 : Mosaïquer à la volée plusieurs fichiers d'entrée et découper cette mosaïque.

gdal raster pipeline ! mosaic input*.tif ! tile output_folder
