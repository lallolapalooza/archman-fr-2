NOM

gdalbuildvrt - Construit un VRT à partir d'une liste de jeux de données.

SYNTAXE

gdalbuildvrt [--help] [--long-usage] [--help-general]
             [--quiet]
             [[-strict]|[-non_strict]]
             [-tile_index <nom_champ>]
             [-resolution user|average|common|highest|lowest|same]
             [-tr <xres> <yes>] [-input_file_list <nom_fichier>]
             [[-separate]|[-pixel-function <fonction>]]
             [-pixel-function-arg <NOM>=<VALEUR>]...
             [-allow_projection_difference] [-sd <n>] [-tap]
             [-te <xmin> <ymin> <xmax> <ymax>] [-addalpha] [-b <bande>]...
             [-hidenodata] [-overwrite]
             [-srcnodata "<valeur>[ <valeur>]..."]
             [-vrtnodata "<valeur>[ <valeur>]..."] [-a_srs <srs_def>]
             [-r nearest|bilinear|cubic|cubicspline|lanczos|average|mode]
             [-oo <NOM>=<VALEUR>]... [-co <NOM>=<VALEUR>]...
             [-ignore_srcmaskband]
             [-nodata_max_mask_threshold <seuil>]
             <nom_jeu_donnees_vrt> [<nom_jeu_donnees_source>]...

DESCRIPTION

Ce programme construit un VRT (Virtual Dataset) qui est une mosaïque d'une liste de jeux de données GDAL. La liste des jeux de données GDAL peut être spécifiée à la fin de la ligne de commande, placée dans un fichier texte (un nom de fichier par ligne) pour des listes très longues, ou il peut s'agir d'un tileindex MapServer (voir l'utilitaire gdaltindex). Si un tile index est utilisé, toutes les entrées du tile index seront ajoutées au VRT.

NOTE :

À partir de GDAL 3.9, pour les mosaïques virtuelles comportant un très grand nombre de rasters sources (centaines de milliers de rasters sources, ou plus), il est conseillé d'utiliser l'utilitaire gdaltindex pour générer un tile index compatible avec le pilote GTI.

Avec -separate, chaque entrée va dans une bande séparée dans le jeu de données VRT. Sinon, les fichiers sont considérés comme des rasters sources d'une mosaïque plus grande et le fichier VRT a le même nombre de bandes que les fichiers d'entrée.

Si un jeu de données GDAL est composé de plusieurs sous-jeux de données et a 0 bande raster, tous les sous-jeux de données seront ajoutés au VRT plutôt que le jeu de données lui-même.

gdalbuildvrt effectue quelques vérifications pour s'assurer que tous les fichiers qui seront mis dans le VRT résultant ont des caractéristiques similaires : nombre de bandes, projection, interprétation des couleurs, etc. Sinon, les fichiers qui ne correspondent pas aux caractéristiques communes seront ignorés à moins que -strict ne soit utilisé. (Ceci n'est vrai que dans le mode par défaut, et pas lors de l'utilisation de l'option -separate)

Depuis GDAL 3.12, une fonction (par exemple, min, mean, median) peut être spécifiée (-pixel-function) pour calculer les valeurs de pixels à partir d'entrées qui se chevauchent. Si aucune fonction n'est spécifiée, ou dans les versions antérieures, l'ordre de la liste d'entrée est utilisé pour déterminer la priorité. Les fichiers listés à la fin sont ceux dont le contenu sera récupéré. Notez que les valeurs nodata seront prises en compte pour potentiellement récupérer des données de jeux de données de priorité inférieure, mais actuellement, le canal alpha n'est pas pris en compte pour effectuer un compositing alpha (donc une source avec alpha=0 apparaissant au-dessus d'une autre source remplacera son contenu). Cela pourrait être modifié dans les versions futures.

--help
Affiche ce message d'aide et quitte.
--help-general
Donne un bref message d'utilisation pour les options génériques de ligne de commande GDAL et quitte.
-tileindex <nom_champ>
Utilise la valeur spécifiée comme champ d'index de tuile, au lieu de la valeur par défaut qui est 'location'.
-resolution {highest|lowest|average|user|same}
Dans le cas où la résolution de tous les fichiers d'entrée n'est pas la même, l'indicateur -resolution permet à l'utilisateur de contrôler la manière dont la résolution de sortie est calculée.

highest choisira les plus petites valeurs de dimensions de pixel parmi l'ensemble des rasters sources.

lowest choisira les plus grandes valeurs de dimensions de pixel parmi l'ensemble des rasters sources.

average est la valeur par défaut et calculera une moyenne des dimensions de pixel parmi l'ensemble des rasters sources.

user doit être utilisé en combinaison avec l'option -tr pour spécifier la résolution cible.

same (ajouté dans GDAL 3.11) vérifie que tous les rasters sources ont la même résolution et renvoie une erreur lorsque ce n'est pas le cas.

common (ajouté dans GDAL 3.11) détermine le plus grand commun diviseur des dimensions de pixel sources, par exemple 0.2 pour des dimensions de pixel sources de 0.4 et 0.6.

-tr <xres> <yres>
Définit la résolution cible. Les valeurs doivent être exprimées dans les unités géoréférencées. Les deux doivent être des valeurs positives. La spécification de ces valeurs est bien sûr incompatible avec les valeurs highest|lowest|average de l'option -resolution.
-tap
(pixels alignés cibles) aligne les coordonnées de l'étendue du fichier de sortie avec les valeurs de -tr, de telle sorte que l'étendue alignée inclue l'étendue minimale. L'alignement signifie que xmin / resx, ymin / resy, xmax / resx et ymax / resy sont des valeurs entières.
-te <xmin> <ymin> <xmax> <ymax>
Définit les étendues géoréférencées du fichier VRT. Les valeurs doivent être exprimées dans les unités géoréférencées. Si non spécifié, l'étendue du VRT est la boîte englobante minimale de l'ensemble des rasters sources. Les pixels situés dans l'étendue du VRT mais non couverts par un raster source seront lus comme des pixels valides avec une valeur de zéro, sauf si une valeur NODATA est spécifiée en utilisant -vrtnodata ou si une bande alpha est ajoutée avec -addalpha.
-addalpha
Ajoute une bande de masque alpha au VRT lorsque les rasters sources n'en ont pas. Principalement utile pour les sources RVB (ou les sources en niveaux de gris). La bande alpha est remplie à la volée avec la valeur 0 dans les zones sans raster source, et avec la valeur 255 dans les zones avec raster source. L'effet est qu'un visualiseur RGBA rendra les zones sans raster source comme transparentes et les zones avec raster source comme opaques. Cette option n'est pas compatible avec -separate.
-hidenodata
Même si une bande contient une valeur nodata, donner cette option fait que la bande VRT ne rapporte pas la valeur NoData. Utile lorsque vous souhaitez contrôler la couleur d'arrière-plan du jeu de données. En utilisant conjointement avec l'option -addalpha, vous pouvez préparer un jeu de données qui ne rapporte pas de valeur nodata mais qui est transparent dans les zones sans données.
-srcnodata "<valeur>[ <valeur>]..."
Définit les valeurs nodata pour les bandes d'entrée (des valeurs différentes peuvent être fournies pour chaque bande). Si plus d'une valeur est fournie, toutes les valeurs doivent être mises entre guillemets pour les conserver ensemble comme un seul argument du système d'exploitation. Si l'option n'est pas spécifiée, les paramètres nodata intrinsèques des jeux de données sources seront utilisés (s'ils existent). La valeur définie par cette option est écrite dans l'élément NODATA de chaque élément ComplexSource. Utilisez une valeur de None pour ignorer les paramètres nodata intrinsèques des jeux de données sources.
-ignore_srcmaskband
Ajouté dans la version 3.3.

À partir de GDAL 3.3, si une source possède une bande masque (bande masque interne/externe, ou bande alpha), un élément <ComplexSource> est créé par défaut avec un élément enfant <UseMaskBand>true</UseMaskBand>, pour indiquer au pilote VRT d'utiliser la bande masque de la source pour masquer les pixels en cours de compositing. Ceci est une généralisation de l'élément NODATA. W
