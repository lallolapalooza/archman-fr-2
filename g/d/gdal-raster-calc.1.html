NOM

gdal-raster-calc - Effectuer des calculs pixel par pixel sur un raster

Ajouté dans la version 3.11.

SYNOPSIS

Utilisation : gdal raster calc [OPTIONS] <ENTRÉES>... <SORTIE>
Effectuer de l'algèbre raster
Arguments positionnels :
  -i, --input <ENTRÉES>                                     Jeux de données raster d'entrée [1.. valeurs] [requis]
  -o, --output <SORTIE>                                    Jeu de données raster de sortie [requis]
Options courantes :
  -h, --help                                               Afficher le message d'aide et quitter
  --json-usage                                             Afficher l'utilisation sous forme de document JSON et quitter
  --config <CLÉ>=<VALEUR>                                  Option de configuration [peut être répétée]
  -q, --quiet                                              Mode silencieux (pas de barre de progression)
Options :
  -f, --of, --format, --output-format <FORMAT-DE-SORTIE>   Format de sortie ("GDALG" autorisé)
  --co, --creation-option <CLÉ>=<VALEUR>                   Option de création [peut être répétée]
  --overwrite                                              Autoriser l'écrasement de la sortie existante
                                                           Mutuellement exclusif avec --append
  --append                                                 Ajouter comme sous-jeu de données à la sortie existante
                                                           Mutuellement exclusif avec --overwrite
  --ot, --datatype, --output-data-type <TYPE-DE-DONNÉES-DE-SORTIE>  Type de données de sortie. TYPE-DE-DONNÉES-DE-SORTIE=Byte|Int8|UInt16|Int16|UInt32|Int32|UInt64|Int64|CInt16|CInt32|Float16|Float32|Float64|CFloat32|CFloat64
  --no-check-srs                                           Ne pas vérifier la cohérence des systèmes de référence spatiale d'entrée
  --no-check-extent                                        Ne pas vérifier la cohérence des emprises d'entrée
  --propagate-nodata                                       Définir les pixels sur la valeur NoData de sortie si l'un des pixels d'entrée est NoData
  --calc <CALC>                                            Expression(s) à évaluer [1.. valeurs] [requis]
  --dialect <DIALECTE>                                     Dialecte de l'expression. DIALECTE=muparser|builtin (par défaut : muparser)
  --flatten                                                Générer un raster de sortie à une bande par expression, même si les jeux de données d'entrée sont multibandes
  --nodata <NODATA>                                        Assigner une valeur nodata spécifiée aux bandes de sortie ('none', valeur numérique, 'nan', 'inf', '-inf')
Options avancées :
  --if, --input-format <FORMAT-D'ENTRÉE>                   Formats d'entrée [peut être répétée]
  --oo, --open-option <CLÉ>=<VALEUR>                       Options d'ouverture [peut être répétée]

DESCRIPTION

gdal raster calc effectue des calculs pixel par pixel sur un ou plusieurs jeux de données GDAL d'entrée. Les calculs peuvent être effectués de manière immédiate, en écrivant les résultats dans un format raster conventionnel, ou de manière différée, en les écrivant sous forme d'un ensemble de bandes dérivées dans un VRT (Virtual Dataset).

La liste des jeux de données GDAL d'entrée peut être spécifiée à la fin de la ligne de commande ou placée dans un fichier texte (une entrée par ligne) pour les listes très longues. Si plus d'un jeu de données d'entrée est utilisé, il doit être préfixé par un nom par lequel il sera référencé dans le calcul, par exemple A=mes_données.tif. (Si un seul jeu de données est utilisé, il sera référencé avec la variable X dans les formules.)

Depuis GDAL 3.12, il est également possible d'utiliser une fonction pixel C++ VRT (telle que sum, mean, min, max) en spécifiant --dialect à builtin.

Les entrées doivent avoir le même système de référence spatiale et doivent couvrir la même emprise spatiale mais ne sont pas tenues d'avoir la même résolution spatiale. La vérification de l'emprise spatiale peut être désactivée avec --no-check-extent, auquel cas les entrées doivent avoir les mêmes dimensions. La vérification du système de référence spatiale peut être désactivée avec --no-check-srs.

Depuis GDAL 3.12, cet algorithme peut faire partie d'un pipeline gdal ou gdal raster pipeline.

Les options suivantes sont disponibles :

-f, --of, --format, --output-format <FORMAT-DE-SORTIE>
Quel format raster de sortie utiliser. Les valeurs autorisées peuvent être données par gdal --formats | grep raster | grep rw | sort
--co <NOM>=<VALEUR>
De nombreux formats ont une ou plusieurs options de création facultatives qui peuvent être utilisées pour contrôler les particularités du fichier créé. Par exemple, le pilote GeoTIFF prend en charge des options de création pour contrôler la compression et si le fichier doit être tuilé.

Peut être répétée.

Les options de création disponibles varient selon le pilote de format, et certains formats simples n'ont pas d'options de création du tout. Une liste des options prises en charge pour un format peut être listée avec l'option de ligne de commande --formats mais la documentation du format est la source définitive d'informations sur les options de création du pilote. Voir la documentation spécifique des pilotes raster pour les options de création légales de chaque format.

--overwrite
Autoriser le programme à écraser le fichier ou le jeu de données cible existant. Sinon, par défaut, gdal renvoie une erreur si le fichier ou le jeu de données cible existe déjà.
-i [<nom>=]<entrée>
Sélectionner un jeu de données d'entrée à traiter. Si plus d'un jeu de données d'entrée est fourni, chaque jeu de données doit être préfixé par un nom par lequel il sera référencé dans --calc.
--calc
Une expression à évaluer à l'aide de la bibliothèque d'analyse mathématique muparser . L'expression peut faire référence à des bandes individuelles de chaque entrée (par exemple, X[1] + 3) ou elle peut être appliquée à toutes les bandes d'une entrée (X + 3).

Il existe deux méthodes par lesquelles une expression peut être appliquée à plusieurs bandes. Dans la méthode par défaut, l'expression est appliquée à chaque bande individuellement, ce qui résulte en une bande de sortie pour chaque bande d'entrée. Par exemple, avec une entrée à trois bandes X, l'expression --calc "X+3" serait développée en --calc "X[1]+3" --calc "X[2]+3" --calc "X[3]+3". Si l' expression contient une référence à toutes les bandes de plusieurs entrées, ces entrées doivent soit avoir le même nombre de bandes, soit une seule bande. Par exemple, si les entrées A et B ont chacune trois bandes, et l'entrée C a une seule bande, alors l'argument --calc "A + B + C" est équivalent à --calc "A[1] + B[1] + C[1]" --calc "A[2] + B[2] + C[1]" --calc "A[3] + B[3] + C[1]". De même, --calc "sum(A,B,C)" serait développée en --calc "sum(A[1], B[1], C[1]" --calc "sum(A[2], B[2], C[1])" --calc "sum(A[3], B[3], C[1])".

Dans la deuxième méthode, qui est activée avec --flatten, les fonctions d'agrégation (sum, avg, minet max) invoquées sur plusieurs bandes seront appliquées à toutes les bandes en agrégat. Dans ce cas, sum(A) est développée en sum(A[1], A[2], A[3]), et sum(A,C) est développée en sum(A[1], A[2], A[3], C[1]). Si l'expression se compose _uniquement_ de fonctions d'agrégation, cela produira une seule bande de sortie quel que soit le nombre de bandes d'entrée présentes. Cependant, si l'expression contient une référence non agrégée à toutes les bandes d'une entrée, une bande de sortie sera toujours produite pour chaque bande d'entrée. Un exemple simple est l'expression A / sum(A), qui produirait un raster à N bandes où chaque bande de sortie contient la fraction de la bande d'entrée par rapport au total.

Plusieurs calculs peuvent être spécifiés ; des bandes de sortie seront produites pour chaque expression dans l'ordre où elles sont fournies.

Les rasters d'entrée seront convertis en nombres flottants sur 64 bits avant d'effectuer les calculs.

Depuis GDAL 3.12, il est également possible d'utiliser une fonction pixel C++ VRT (telle que sum, mean, min, max) en spécifiant --dialect à builtin. Les arguments des fonctions sont passés entre parenthèses, comme sum(k=1), min(propagateNoData=true) ou interpolate_linear(t0=1,dt=1,t=10).

--dialect muparser|builtin
Ajouté dans la version 3.12.

Spécifie le moteur d'expression utilisé pour interpréter la valeur de --calc. La valeur par défaut est muparser.

--flatten
Ajouté dans la version 3.12.

Génère une seule bande de raster de sortie par expression, même si les jeux de données d'entrée sont multibandes.

Pour le dialecte muparser par défaut, utiliser le nom d'un raster d'entrée (disons A) est équivalent à A[1],A[2],...,A[n]. Cette syntaxe fonctionne avec les fonctions muparser min, max, sum et avg .

Par exemple, considérons 2 rasters A et B avec 3 bandes chacun, alors --flatten --calc "avg(A)-avg(B)" est équivalent à --calc "avg(A[1],A[2],A[3])-avg(B[1],B[2],B[3])"

Et --flatten --dialect=builtin --calc mean calculera une seule bande avec la moyenne des 4 bandes d'entrée.

--no-check-extent
Ne pas vérifier que les rasters d'entrée ont la même étendue spatiale. Les rasters d'entrée devront plutôt avoir les mêmes dimensions. La géotransformation du premier raster d'entrée sera assignée à la sortie.
--no-check-srs
Ne pas vérifier la cohérence des systèmes de référence spatiale des entrées. Toutes les entrées seront supposées avoir le système de référence spatiale du premier raster d'entrée, et ce système de référence spatiale sera utilisé pour la sortie.
--nodata
Ajouté dans la version 3.12.

Définit la valeur NoData pour le jeu de données de sortie. Peut être défini à "none" pour laisser la valeur NoData indéfinie. Si --nodata n'est pas spécifié, gdal raster calc utilisera une valeur NoData provenant du premier jeu de données source qui en a une.

--propagate-nodata
Ajouté dans la version 3.12.

Si défini, une valeur NoData dans n'importe quel jeu de données d'entrée utilisé dans une expression causera que la valeur de sortie soit NoData.

SORTIE GDALG (JEU DE DONNÉES EN TEMPS RÉEL / EN FLUX)

Ce programme prend en charge la sérialisation de la ligne de commande en tant que fichier JSON en utilisant le format de sortie GDALG . Le fichier résultant peut ensuite être ouvert en tant que jeu de données raster à l'aide du pilote GDALG : Algorithme en flux de GDAL , et appliquer le pipeline spécifié de manière en temps réel / en flux.

EXEMPLES

Exemple 1 : Somme bande par bande de trois fichiers

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --calc "A+B+C" -o out.tif

Exemple 2 : Moyenne par jeu de données de toutes les bandes de chaque jeu de données

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --flatten --calc "avg(A)" --calc "avg(B)" --calc "avg(C)" -o out.tif

Exemple 3 : Maximum bande par bande de trois fichiers

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --calc "max(A,B,C)" -o out.tif

Exemple 4 : Définir les valeurs de zéro et inférieures à NaN

gdal raster calc -i "A=input.tif" -o result.tif --calc="A > 0 ? A : NaN"

Exemple 5 : Calculer la moyenne (en tant que bande unique) de toutes les bandes de deux jeux de données d'entrée

gdal raster calc -i A=input1.tif -i B=input2.tif -o result.tif --flatten --calc=mean --dialect=builtin
