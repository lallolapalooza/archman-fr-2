NOM

gdal-vector-info - Obtenir des informations sur un jeu de données vectoriel

Ajouté dans la version 3.11.

SYNTAXE

Utilisation : gdal vector info [OPTIONS] <ENTRÉE>...
Retourne des informations sur un jeu de données vectoriel.
Arguments positionnels :
  -i, --dataset, --input <ENTRÉE>                       Jeux de données vectoriels d'entrée [peut être répété] [requis]
Options courantes :
  -h, --help                                           Affiche le message d'aide et quitte
  --json-usage                                         Affiche l'utilisation sous forme de document JSON et quitte
  --config <CLÉ>=<VALEUR>                               Option de configuration [peut être répétée]
Options :
  -f, --of, --format, --output-format <FORMAT-SORTIE>  Format de sortie. FORMAT-SORTIE=json|text
  -l, --layer, --input-layer <COUCHE-ENTRÉE>             Nom de la couche d'entrée [peut être répété]
                                                       Mutuellement exclusif avec --sql
  --features                                           Liste toutes les entités (attention à la consommation de RAM sur les couches volumineuses)
                                                       Mutuellement exclusif avec --summary
  --summary                                            Liste les noms des couches et le type de géométrie
                                                       Mutuellement exclusif avec --features
  --limit <NOMBRE-ENTITÉS>                              Limite le nombre d'entités par couche (implique --features)
  --sql <instruction>|@<nom-fichier>                    Exécute l'instruction SQL indiquée et retourne le résultat
                                                       Mutuellement exclusif avec --input-layer
  --where <OÙ>|@<nom-fichier>                          Requête d'attribut dans une forme restreinte des requêtes utilisées dans la clause WHERE de SQL
  --dialect <DIALECTE>                                  Dialecte SQL
  --update                                             Ouvre le jeu de données en mode mise à jour
Options avancées :
  --oo, --open-option <CLÉ>=<VALEUR>                    Options d'ouverture [peut être répétée]
  --if, --input-format <FORMAT-ENTRÉE>                  Formats d'entrée [peut être répété]

DESCRIPTION

gdal vector info liste diverses informations sur un jeu de données vectoriel supporté par GDAL.

Depuis GDAL 3.12, gdal vector info peut être utilisé comme dernière étape d'un pipeline.

Les options suivantes sont disponibles :

Options standard

-f, --of, --format, --output-format json|text
Quel format de sortie utiliser. Par défaut, c'est JSON, et depuis GDAL 3.12, c'est du texte lorsqu'il est appelé depuis la ligne de commande.
-l, --layer, --input-layer <COUCHE-ENTRÉE>
Nom d'une ou plusieurs couches à inspecter. Si aucun nom de couche n'est passé et que --sql n'est pas spécifié, alors toutes les couches seront sélectionnées.
--summary
Affiche un résumé avec la liste des couches et le type de géométrie de chaque couche. Cette option est mutuellement exclusive avec l'option --features.
--features
Liste toutes les entités par défaut, sauf si limité avec --limit. Attention à la consommation de RAM sur les couches volumineuses lors de l'utilisation de la sortie JSON. Cette option est mutuellement exclusive avec l'option --summary.
--limit <NOMBRE-ENTITÉS>
Ajouté dans la version 3.12.

Limite le nombre d'entités rapportées par couche. Lorsque défini, cela implique --features.

--sql <instruction>|@<nom-fichier>
Exécute l'instruction SQL indiquée et retourne le résultat. La syntaxe @<nom-fichier> peut être utilisée pour indiquer que le contenu se trouve dans le fichier spécifié (par exemple @mon_select.txt où mon_select.txt est un fichier dans le répertoire courant). Les données peuvent également être modifiées avec SQL INSERT, UPDATE, DELETE, DROP TABLE, ALTER TABLE etc. si le jeu de données est ouvert en mode mise à jour. Les capacités de modification dépendent du dialecte sélectionné avec --dialect.

Cette option est mutuellement exclusive avec l'option --where.

--where <OÙ>|@<nom-fichier>
Une requête d'attribut dans une forme restreinte des requêtes utilisées dans l'instruction WHERE de SQL. Seules les entités correspondant à la requête d'attribut seront rapportées. La syntaxe @<nom-fichier> peut être utilisée pour indiquer que le contenu se trouve dans le fichier spécifié.

Exemple de --where et de guillemets :

--where "\"Corner Point Identifier\" LIKE '%__00_00'"

Cette option est mutuellement exclusive avec l'option --sql.

--dialect <dialecte>
Dialecte SQL. Dans certains cas, peut être utilisé pour utiliser le dialecte OGR SQL (non optimisé) au lieu du SQL natif d'un SGBDR en passant la valeur de dialecte OGRSQL. Le dialecte SQL SQLite peut être sélectionné avec les valeurs de dialecte SQLITE et INDIRECT_SQLITE, et cela peut être utilisé avec n'importe quelle source de données.

Options avancées

--oo <NOM>=<VALEUR>
Option d'ouverture du jeu de données (spécifique au format).

Peut être répété.

--if <format>
Nom du format/pilote à essayer pour ouvrir le(s) fichier(s) d'entrée. Il n'est généralement pas nécessaire de le spécifier, mais il peut être utilisé pour ignorer la détection automatique du pilote, lorsque celle-ci échoue à sélectionner le pilote approprié. Cette option peut être répétée plusieurs fois pour spécifier plusieurs pilotes candidats. Notez qu'elle ne force pas ces pilotes à ouvrir le jeu de données. En particulier, certains pilotes ont des exigences concernant les extensions de fichiers.

Peut être répété.
