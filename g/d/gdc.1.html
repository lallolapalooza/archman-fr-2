GDC(1) GNU GDC(1)

NOM

gdc - Compilateur GCC pour le langage D

SYNTAXE

gdc [-c|-S] [-g] [-pg]
[-Oniveau] [-Wavertissement...]
[-Irep...] [-Lrep...]
[-foption...] [-moption-machine...]
[-o fichier-sortie] [@fichier] fichier-entree...

Seules les options les plus utiles sont listées ici ; voir ci-dessous pour le reste.

DESCRIPTION

La commande gdc est le compilateur GNU pour le langage D et supporte de nombreuses options similaires à gcc. Ce manuel ne documente que les options spécifiques à gdc.

OPTIONS

Fichiers d'entrée et de sortie

Pour tout fichier d'entrée donné, le suffixe du nom de fichier détermine le type de compilation effectué. Les types de noms de fichiers d'entrée suivants sont pris en charge :

fichier.d
Fichiers source D.
fichier.dd
Fichiers source Ddoc.
fichier.di
Fichiers d'interface D.

Vous pouvez spécifier plusieurs fichiers d'entrée sur la ligne de commande gdc, chacun étant compilé séparément dans le processus de compilation. Si vous spécifiez une option "-o fichier", tous les fichiers d'entrée sont compilés ensemble, produisant un fichier de sortie unique, nommé fichier. Ceci est autorisé même en utilisant "-S" ou "-c".

Un fichier d'interface D ne contient que ce dont un import du module a besoin, plutôt que toute l'implémentation de ce module. Ils peuvent être créés par gdc à partir d'un fichier source D en utilisant l'option "-H". Lorsque le compilateur résout une déclaration d'importation, il recherche d'abord les fichiers .di correspondants, puis les .d.

Un fichier source Ddoc contient du code dans le langage du préprocesseur macro D. Il est principalement conçu pour être utilisé dans la production de documentation utilisateur à partir de commentaires intégrés, avec une légère affinité pour la génération HTML. Si un fichier source .d commence par la chaîne "Ddoc", il est traité comme une documentation générale et non comme un fichier source D.

Options d'exécution

Ces options affectent le comportement d'exécution des programmes compilés avec gdc.

-fall-instantiations
Génère du code pour toutes les instanciations de modèles. La stratégie d'émission de modèles par défaut consiste à ne pas générer de code pour les déclarations qui ont été instanciées spéculativement, par exemple à partir de "__traits(compiles, ...)", ou qui proviennent d'un module importé non compilé.
-fno-assert
Désactive la génération de code pour les contrats "assert".
-fno-bounds-check
Désactive la vérification des limites de tableau pour toutes les fonctions, ce qui peut améliorer les performances du code qui utilise intensivement les tableaux. Notez que cela peut entraîner un comportement imprévisible si le code en question viole effectivement les contraintes de limites de tableau. Il est sûr d'utiliser cette option si vous êtes sûr que votre code ne déclenche jamais une "RangeError".
-fbounds-check=valeur
Une alternative à -fbounds-check qui permet un meilleur contrôle sur l'activation ou la désactivation de la vérification des limites. Les valeurs suivantes sont prises en charge :
on
Active la vérification des limites de tableau pour toutes les fonctions.
safeonly
Active la vérification des limites de tableau uniquement pour les fonctions @safe.
off
Désactive complètement la vérification des limites de tableau.
-fno-builtin
Ne reconnaît pas les fonctions intégrées à moins qu'elles ne commencent par le préfixe __builtin_. Par défaut, le compilateur reconnaîtra quand une fonction du package "core.stdc" est une fonction intégrée.
-fcheckaction=valeur
Cette option contrôle le code généré en cas d'échec d'assertion, de vérification de limites ou de commutation finale. Les valeurs suivantes sont prises en charge :
context
Lève une "AssertError" avec des informations de contexte supplémentaires.
halt
Arrête l'exécution du programme.
throw
Lève une "AssertError" (par défaut).
-fdebug
-fdebug=valeur
Active la compilation de code conditionnel "debug" dans le programme. L'option -fdebug elle-même définit le niveau de débogage à 1, tandis que -fdebug= active le code "debug" identifié par l'une des valeurs suivantes :
ident
Active la compilation de tout code "debug" identifié par ident.
-fno-druntime
Implémente https://dlang.org/spec/betterc.html. Supposons que la compilation cible un environnement sans bibliothèque d'exécution D.

Ceci est équivalent à compiler avec les options suivantes :

gdc -nophoboslib -fno-exceptions -fno-moduleinfo -fno-rtti
-fextern-std=standard
Définit le nommage C++ de compatibilité avec la version identifiée par standard. Les valeurs suivantes sont prises en charge :
c++98
c++03
Définit "__traits(getTargetInfo, "cppStd")" sur 199711.
c++11
Définit "__traits(getTargetInfo, "cppStd")" sur 201103.
c++14
Définit "__traits(getTargetInfo, "cppStd")" sur 201402.
c++17
Définit "__traits(getTargetInfo, "cppStd")" sur 201703. C'est la valeur par défaut.
c++20
Définit "__traits(getTargetInfo, "cppStd")" sur 202002.
c++23
Définit "__traits(getTargetInfo, "cppStd")" sur 202302.
-finclude-imports
Inclut les modules importés dans la compilation, comme s'ils étaient fournis sur la ligne de commande. Lorsque cette option est activée, tous les modules importés sont compilés à l'exception de ceux qui font partie de libphobos.
-fno-invariants
Désactive la génération de code pour les contrats "invariant" de classe.
-fno-moduleinfo
Désactive la génération d'informations sur les modules, telles que les versions et les dépendances de modules.
-fno-rtti
Désactive la génération d'informations sur le type d'exécution (RTTI). Cela peut réduire la taille du code et améliorer les performances, mais désactive des fonctionnalités telles que la manipulation des exceptions et la réflexion.
-fno-sanitize=option
Désactive une option de sanitizer spécifique. Les options disponibles sont les mêmes que pour gcc.
-fno-tход
Désactive la génération de code pour les contrats "out".
-fno-unittest
Désactive la compilation du code des tests unitaires.
-fprofile=value
Active la génération de données de profilage pour l'optimisation des performances. La valeur peut être l'un des éléments suivants :
atoms
Utilise les données de profilage pour générer des informations d'ordre des fonctions (call graph).
statements
Utilise les données de profilage pour générer des informations sur la couverture des instructions (statement coverage).
-frelease
Active une série d'options d'optimisation destinées à produire un code de production plus rapide et plus petit. En particulier, les vérifications des limites de tableau et les assertions sont désactivées. Cette option est équivalente à "-O2 -release".
-fswitch=value
Contrôle la génération de code pour les commutateurs `switch` incomplets. Les valeurs suivantes sont prises en charge :
error
Lève une "AssertError" (par défaut).
on
Génère du code pour gérer les cas manquants des commutateurs.
off
Ne génère pas de code pour les cas manquants des commutateurs, ce qui peut entraîner un comportement indéfini si un tel cas est rencontré.
-ftemplate=value
Contrôle la manière dont les modèles sont instanciés et le code généré pour eux. Les valeurs suivantes sont prises en charge :
compileall
Compile toutes les instanciations de modèles, même celles qui pourraient être inutilisées. Cela peut entraîner une augmentation du temps de compilation et de la taille du code, mais garantit que tous les modèles sont disponibles.
guess
Tente de deviner quelles instanciations de modèles sont nécessaires. C'est le comportement par défaut et il est généralement efficace, mais peut parfois conduire à des instanciations manquantes.
-fversion=ident
Définit un identifiant de version, qui peut être utilisé dans le code pour activer ou désactiver sélectivement des blocs de code basés sur des directives de préprocesseur.
-fwarn=spec
Active des avertissements supplémentaires spécifiques. Les spécifications disponibles incluent :
all
Active tous les avertissements.
no
Désactive tous les avertissements.
unused
Avertit sur les variables, fonctions, types, etc. non utilisés.

Options pour la recherche de répertoires

Ces options spécifient les répertoires à rechercher pour les fichiers, les bibliothèques et d'autres parties du compilateur :

-Idir
Spécifie un répertoire à utiliser lors de la recherche de modules importés au moment de la compilation. Plusieurs options -I peuvent être utilisées, et les chemins sont recherchés dans le même ordre.
-Jdir
Spécifie un répertoire à utiliser lors de la recherche de fichiers dans des imports de chaînes de caractères au moment de la compilation. Ce commutateur est requis afin d'utiliser des expressions import(fichier). Plusieurs options -J peuvent être utilisées, et les chemins sont recherchés dans le même ordre.
-Ldir
Lors de l'édition de liens, spécifie un répertoire de recherche de bibliothèques, comme avec gcc.
-Bdir
Cette option spécifie où trouver les exécutables, les bibliothèques, les fichiers sources et les fichiers de données du compilateur lui-même, comme avec gcc.
-fmodule-file=module=spec
Cette option manipule les chemins de fichiers des modules importés, de sorte que si un module importé correspond à tout ou à la partie la plus à gauche de module, le chemin de fichier dans spec est utilisé comme emplacement pour rechercher les sources D. Ceci est utilisé lorsque le chemin et les noms des fichiers sources ne sont pas les mêmes que la hiérarchie des paquets et des modules. Considérer les exemples suivants : 
gdc test.d -fmodule-file=A.B=foo.d -fmodule-file=C=bar

Ceci indiquera au compilateur de rechercher dans tous les chemins d'importation le fichier source foo.d lors de l'importation de A.B, et le répertoire bar/ lors de l'importation de C, comme annoté dans le code D suivant :

module test;
import A.B;     // Correspond à A.B, recherche foo.d
import C.D.E;   // Correspond à C, recherche bar/D/E.d
import A.B.C;   // Pas de correspondance, recherche A/B/C.d
-imultilib dir
Utilise dir comme sous-répertoire du répertoire gcc contenant les sources et interfaces D spécifiques à la cible.
-iprefix préfixe
" >
Spécifie prefix comme préfixe pour le répertoire gcc contenant les sources et interfaces D spécifiques à la cible. Si le prefix représente un répertoire, vous devez inclure le '/' fin
al.
-nostdi
nc
Ne recherche pas dans les répertoires système standard les fichiers source et interface D. Seuls les répertoires spécifiés avec les options -I (et le répertoire du fich
