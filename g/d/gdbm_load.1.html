NOM

gdbm_load - recréer une base de données GDBM à partir d'un fichier de vidage.

SYNTAXE

gdbm_load [-MUnr] [-b NUM] [-c NUM] [-m MODE] [-u NOM|UID[:NOM|GID]] [--block-size=NUM] [--cache-size=NUM] [--mmap=NUM] [--mode=MODE] [--no-meta] [--replace] [--update] [--user=NOM|UID[:NOM|GID]] FICHIER [FICHIER_DB]

gdbm_load [-Vh] [--help] [--usage] [--version]

DESCRIPTION

Crée un fichier de base de données gdbm FICHIER_DB à partir du fichier de vidage FICHIER. Si l'argument FICHIER n'est pas fourni, la base de données créée est envoyée sur la sortie standard d'erreur.

Si le fichier d'entrée est au format de vidage ASCII, le mode et la propriété de la base de données créée sont restaurés à partir des informations du vidage. Ceci peut être outrepassé en utilisant les options de ligne de commande (voir ci-dessous).

OPTIONS

-b, --block-size=NUM
Définit la taille du bloc.
-c, --cache-size=NUM
Définit la taille du cache.
-M, --mmap
Utilise le mappage mémoire.
-m, --mode=MODE
Définit le mode du fichier de base de données (nombre octal).
-n, --no-meta
N'essaie pas de restaurer les métadonnées de la base de données (mode et propriété).
-r, --replace
Remplace les clés existantes. Doit être utilisé conjointement avec l'option -U (--update).
-U, --update
Met à jour une base de données existante. Les paires clé/valeur du fichier de vidage seront ajoutées à cette base de données, sans supprimer les clés existantes. Pour écraser les clés dupliquées dans le fichier de vidage, utilisez l'option --replace.
Si la base de données n'existe pas, elle sera créée.
-u, --user=NOM|UID[:NOM|GID]
Définit la propriété du fichier.
-h, --help
Affiche un bref résumé d'utilisation.
--usage
Affiche une liste des options disponibles.
-V, --version
Affiche la version du programme
