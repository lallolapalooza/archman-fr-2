Mode

surveillance (par défaut) En mode surveillance, le

de surveillance standard du noyau par les mêmes mécanismes que les plugins de surveillance normaux (par exemple http_status). Cela signifie qu'elles seront soumises aux mesures anti-flapping standard via les paramètres de seuil standard ( "up_thresh", "down_thresh","ok_thresh") avant d'affecter l'état final vu par les plugins de résolution. Ce mode convient si les mises à jour traitées sont des

elles. Mode direct En mode direct, le paramètre
standa
rd
"interval" n'est utilisé que comme indice pour le code de surveillance du système de fichiers afin d'essayer de vérifier les mises à jour au moins aussi souvent que l'intervalle fourni. Cependant, dans de nombreux cas (en particulier par exemple sur Linux avec la prise en charge inotify()), les mises à jour du fichier peuvent être détectées beaucoup plus tôt,

peut-être presque instantanément. Il y aura un court délai de stabilisation (~1 seconde) après la détection de toute mise à jour afin de fusionner les mises

à jour

FORMAT DU FICHIER Le fichier est formaté en utilisant le même langage "vscf" que celui utilisé pour le fichier de configuration principal et les bases de données de réseaux geoip. Le format de données attendu est un simple hash clé-valeur au niveau supérieur, où les clés sont les adresses IP surveillées ou les valeurs CNAME issues des plugins de surveillance et les valeurs sont de la forme "state[/ttl]", où state est soit "UP" ou "DOWN" et le ttl optionnel est une valeur ttl entière. Les valeurs TTL ne sont utilisées que pour les service_types en mode "direct" ; le TTL est

ca
