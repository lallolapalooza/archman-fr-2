NOM

gnutls_certificate_verify_peers - Fonction API

SYNTAXE

#include <gnutls/gnutls.h>

int gnutls_certificate_verify_peers(gnutls_session_t session, gnutls_typed_vdata_st * data, unsigned int elements, unsigned int * status);

ARGUMENTS

gnutls_session_t session
est une session gnutls
gnutls_typed_vdata_st * data
un tableau de données typées
unsigned int elements
le nombre d'éléments de données
unsigned int * status
est le résultat de la vérification

DESCRIPTION

Cette fonction vérifiera le certificat du pair et stockera le statut dans la variable status sous forme d'un OU binaire de valeurs gnutls_certificate_status_t ou zéro si le certificat est approuvé. Notez que la valeur dans status n'est définie que lorsque la valeur de retour de cette fonction est succès (c'est-à-dire, l'échec à approuver un certificat n'implique pas une valeur de retour négative). Les drapeaux de vérification par défaut utilisés par cette fonction peuvent être outrepassés en utilisant gnutls_certificate_set_verify_flags(). Voir la documentation de gnutls_certificate_verify_peers2() pour les détails du processus de vérification.

Cette fonction prendra en compte les réponses OCSP concaténées envoyées par le serveur, ainsi que les extensions de certificat X.509 suivantes : Contraintes de Nom, Usage de Clé et Contraintes de Base (pathlen).

Les types de data acceptables sont GNUTLS_DT_DNS_HOSTNAME, GNUTLS_DT_RFC822NAME et GNUTLS_DT_KEY_PURPOSE_OID. Les deux premiers acceptent comme données un nom d'hôte ou une adresse e-mail terminés par un caractère nul, et le dernier un identifiant d'objet terminé par un caractère nul (par exemple, GNUTLS_KP_TLS_WWW_SERVER).

Si un nom d'hôte DNS est fourni, cette fonction comparera le nom d'hôte du certificat à celui fourni. Si les noms ne correspondent pas, le drapeau de statut GNUTLS_CERT_UNEXPECTED_OWNER sera défini. Si un OID d'objectif de clé est fourni et que le certificat final contient l'extension d'usage de clé étendue PKIX, il devra avoir l'objectif de clé fourni ou être marqué pour tout objectif, sinon le statut de vérification aura le drapeau GNUTLS_CERT_SIGNER_CONSTRAINTS_FAILURE défini.

Pour éviter les attaques par déni de service, certaines limites supérieures par défaut concernant la taille de clé du certificat et la taille de la chaîne sont définies. Pour les outrepasser, utilisez gnutls_certificate_set_verify_limits().

Notez que lors de l'utilisation de clés publiques brutes, la vérification ne fonctionnera pas car il n'y a pas de corps de certificat correspondant à la clé brute qui puisse être vérifié. Dans ce cas, cette fonction retournera GNUTLS_E_INVALID_REQUEST.

RETOUR

GNUTLS_E_SUCCESS (0) lorsque la validation est effectuée, ou un code d'erreur négatif sinon. Un code d'erreur réussi signifie que le paramètre status doit être vérifié pour obtenir le statut de validation.
