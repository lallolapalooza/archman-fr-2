NOM

gnutls_ocsp_resp_verify - fonction d'API

SYNOPSIS

#include <gnutls/ocsp.h>

int gnutls_ocsp_resp_verify(gnutls_ocsp_resp_const_t resp, gnutls_x509_trust_list_t trustlist, unsigned int * verify, unsigned int flags);

ARGUMENTS

gnutls_ocsp_resp_const_t resp
devrait contenir un type gnutls_ocsp_resp_t
gnutls_x509_trust_list_t trustlist
ancres de confiance sous forme de type gnutls_x509_trust_list_t
unsigned int * verify
variable de sortie avec l'état de vérification, un gnutls_ocsp_verify_reason_t
unsigned int flags
indicateurs de vérification de gnutls_certificate_verify_flags

DESCRIPTION

Vérifie la signature de la réponse OCSP de base par rapport à la clé publique du certificat d'un signataire de confiance. La trustlist doit être remplie avec les ancres de confiance. La fonction extraira le certificat du signataire de la réponse OCSP de base et le vérifiera par rapport à la trustlist. Un signataire de confiance est un certificat qui se trouve soit dans la trustlist, soit qui est signé directement par un certificat dans la
trustlist et possède le bit d'utilisation de clé étendue id-ad-ocspSigning défini.

La variable de sortie verify contiendra des codes d'état de vérification (par exemple, GNUTLS_OCSP_VERIFY_SIGNER_NOT_FOUND, GNUTLS_OCSP_VERIFY_INSECURE_ALGORITHM) qui ne sont valides que si la fonction a renvoyé GNUTLS_E_SUCCESS.

Notez que la fonction renvoie GNUTLS_E_SUCCESS même lorsque la vérification a échoué. L'appelant doit toujours inspecter la variable verify pour connaître l'état de la vérification.

La variable flags doit être définie à 0 pour le moment.

RETOURNE

En cas de succès, GNUTLS_E_SUCCESS (0) est renvoyé, sinon une valeur d'erreur négative.
