NOM

gnutls_transport_set_pull_timeout_function - Fonction API

SYNTAXE

#include <gnutls/gnutls.h>

void gnutls_transport_set_pull_timeout_function(gnutls_session_t session, gnutls_pull_timeout_func func);

ARGUMENTS

gnutls_session_t session
est un type gnutls_session_t.
gnutls_pull_timeout_func func
une fonction de rappel (callback)

DESCRIPTION

C'est la fonction où vous définissez une fonction pour que gnutls sache si des données sont prêtes à être reçues. Elle doit attendre les données pendant une période donnée en millisecondes. Le rappel doit retourner 0 en cas de délai d'attente dépassé, un nombre positif si des données peuvent être reçues, et -1 en cas d'erreur. Vous devrez remplacer cette fonction si select() n'est pas adapté aux appels de transport fournis.

Comme avec select(), si la valeur du délai d'attente est zéro, le rappel doit retourner zéro si aucune donnée n'est immédiatement disponible. La valeur spéciale GNUTLS_INDEFINITE_TIMEOUT indique que le rappel doit attendre indéfiniment des données.


gnutls_pull_timeout_func est de la forme, int (*gnutls_pull_timeout_func)(gnutls_transport_ptr_t, unsigned int ms);

Ce rappel est nécessaire lorsque gnutls_handshake_set_timeout() ou gnutls_record_set_timeout() sont définis, sous TLS1.3 et pour appliquer les délais d'attente du mode DTLS en mode bloquant.

Pour assurer la compatibilité avec les futures versions de GnuTLS, ce rappel doit être défini lorsqu'une fonction de réception personnalisée est enregistrée. Le rappel ne sera pas utilisé lorsque la session est en mode TLS avec des sockets non bloquants. C'est-à-dire, lorsque GNUTLS_NONBLOCK est spécifié pour une session TLS dans gnutls_init().

La fonction d'aide gnutls_system_recv_timeout() est fournie pour simplifier l'écriture des rappels.
