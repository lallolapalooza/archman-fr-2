DESCRIPTIO

N

Le programme gnome-session démarre l'environnement de bureau GNOME. Cette commande est généralement exécutée par votre gestionnaire de connexion (GDM, SDDM, lightdm ou autre). Il chargera soit votre session enregistrée, soit il fournira une session par défaut pour l'utilisateur telle que définie par l'administrateur système (ou l'installation GNOME par défaut sur votre système)

.

La session par défaut est définie dans gnome.session, un fichier de type .desktop recherché dans $XDG_CONFIG_HOME/gnome-session/sessions, $XDG_CONFIG_DIRS/gnome-session/sessions et $XDG_DATA_DIRS/gnome-session/session

s
.

SYSTEM

D

gnome-session utilise systemd pour la majeure partie de la gestion de ses services. systemd fournit deux cibles spéciales pour l'intégration au bureau : graphical-session.target et graphical-session-pre.target. Celles-ci fonctionnent entre les environnements de bureau et devraient être utilisées si possible. gnome-session fournit les cibles supplémentaires spécifiques à GNOME suivantes

:

gnome-session.

target
Unité générique active pendant toute la session. Similaire à graphical-session.
target.

gnome-session-pre.

target
Utilisée pour les tâches qui doivent être effectuées avant le démarrage de la session. Similaire à graphical-session-pre.
target.

gnome-session-x11@SESSION.target, gnome-session-wayland@SESSION.

target
Unité principale démarrée pour une session basée sur X11/Wayland. SESSION est défini selon la session passée via --session
.

gnome-session-x11.target, gnome-session-wayland.

target
Unités de commodité sans la session intégrée dans la
cible.

gnome-session@SESSION.

target
Unité de commodité avec seulement les informations SESSION
intégrées.

gnome-session-basic-services.

target
Unité spéciale qui liste les services de base nécessaires à toute session GNOME construite autour de gnome-shell. Cela permet une réutilisation pratique par les sessions kiosque comme l'écran de connexion
GDM.

gnome-session-x11-services.

target
Unité spéciale démarrée lorsque les services X11 sont nécessaires. Les programmes devront utiliser la variable d'environnement spéciale GNOME_SETUP_DISPLAY au lieu de DISPLAY
.

Notez qu'il faut faire attention à définir des règles After= appropriées. Il est également fortement recommandé de toujours faire cela en combinaison avec BindsTo= ou PartOf= sur l'une des cibles principales (par ex. graphical-session.target)

.

Les unités doivent définir CollectMode=inactive-or-failed. De plus, il est fortement recommandé de définir TimeoutStopSec=5 afin que la déconnexion ne soit pas retardé

e indéfiniment si le processus n
e s'arrête pas correctement.

DÉFINITION DE

SESSION

Les sessions sont définies dans des fichiers .session, qui utilisent un format de type .desktop, avec les clés suivantes dans le groupe GNOME Session

:

Nam

e
Nom de la session. Peut être
localisé.

Kios

k
Les sessions kiosque sont des sessions spéciales à usage unique construites autour du lancement d'une application spécifique. Par exemple, une session kiosque peut exécuter un navigateur web plein écran verrouillé sur une page spécifique. Dans GNOME, nous utilisons les sessions kiosque pour l'écran de connexion (où l'application est l'interface de l'écran de connexion) et l'expérience de première installation (initial-setup). Lorsqu'il est défini à true, gnome-session ne fera aucune tentative de démarrage automatique de fichiers .desktop, et exigera plutôt que la session configure toute la fonctionnalité requise via
systemd.

Voici un exemple de définition de session

: 
[GNOME Se
ssion] N
ame=GNOME

Les fichiers .session sont chargés depuis $XDG_CONFIG_HOME/gnome-session/sessions, $XDG_CONFIG_DIRS/gnome-session/sessions et $XDG_DATA_DIRS/gnome-session/sessions

.

Les définitions de session ne font rien par elles-mêmes, et elles doivent être accompagnées d'une configuration systemd pour fournir certaines fonctionnalités (c'est-à-dire lancer des services). La manière recommandée de faire cela est de se connecter à l'une des cibles décrites ci-dessus. Par exemple : lors de la définition d'une session nommée foobar

, vous pouvez créer un fichier drop-in systemd dans /etc/systemd/user/gnome-session@foobar.target.d/session.conf et définir l
es dépendances Requires= et Wants= pour indiquer à systemd quels services il doit démarrer lors du lancement de cette session.
