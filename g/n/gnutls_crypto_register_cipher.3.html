NOM

gnutls_crypto_register_cipher - Fonction d'API

SYNTAXE

#include <gnutls/crypto.h>

int gnutls_crypto_register_cipher(gnutls_cipher_algorithm_t algorithm, int priority, gnutls_cipher_init_func init, gnutls_cipher_setkey_func setkey, gnutls_cipher_setiv_func setiv, gnutls_cipher_encrypt_func encrypt, gnutls_cipher_decrypt_func decrypt, gnutls_cipher_deinit_func deinit);

ARGUMENTS

gnutls_cipher_algorithm_t algorithm
est l'identifiant de l'algorithme gnutls
int priority
est la priorité de l'algorithme
gnutls_cipher_init_func init
Une fonction qui initialise le chiffrement
gnutls_cipher_setkey_func setkey
Une fonction qui définit la clé du chiffrement
gnutls_cipher_setiv_func setiv
Une fonction qui définit le nonce/IV du chiffrement (non-AEAD)
gnutls_cipher_encrypt_func encrypt
Une fonction qui effectue le chiffrement (non-AEAD)
gnutls_cipher_decrypt_func decrypt
Une fonction qui effectue le déchiffrement (non-AEAD)
gnutls_cipher_deinit_func deinit
Une fonction qui désinitialise le chiffrement

DESCRIPTION

Cette fonction enregistrera un algorithme de chiffrement à utiliser par gnutls. Tout algorithme enregistré remplacera les algorithmes inclus et par convention, les algorithmes implémentés par le noyau ont une priorité de 90 et ceux assistés par CPU de 80. L'algorithme avec la priorité la plus basse sera utilisé par gnutls.

Dans le cas où les fonctions d'initialisation ou de définition de clé enregistrées retournent GNUTLS_E_NEED_FALLBACK, GnuTLS tentera d'utiliser le chiffrement enregistré suivant en priorité.

Les fonctions marquées comme non-AEAD ne sont pas requises lors de l'enregistrement d'un chiffrement à utiliser avec la nouvelle API AEAD introduite dans GnuTLS 3.4.0. GnuTLS utilise en interne la nouvelle API AEAD.

OBSOLÈTE

depuis 3.7.0, il n'est plus possible de remplacer l'implémentation du chiffrement

RETOUR

GNUTLS_E_SUCCESS en cas de succès, sinon un code d'erreur négatif.
