NOM

gnutls_srp_set_server_credentials_function - Fonction d'API

SYNOPSIS

#include <gnutls/gnutls.h>

void gnutls_srp_set_server_credentials_function(gnutls_srp_server_credentials_t cred, gnutls_srp_server_credentials_function * func);

ARGUMENTS

gnutls_srp_server_credentials_t cred
est un type gnutls_srp_server_credentials_t.
gnutls_srp_server_credentials_function * func
est la fonction de rappel

DESCRIPTION

Cette fonction peut être utilisée pour définir un rappel afin de récupérer les informations d'identification SRP de l'utilisateur. La forme de la fonction de rappel est :

int (*callback)(gnutls_session_t, const char* username, gnutls_datum_t *salt, gnutls_datum_t *verifier, gnutls_datum_t *generator, gnutls_datum_t *prime);


username contient le nom d'utilisateur réel. Le salt , verifier , generator et prime doivent être remplis en utilisant gnutls_malloc(). Par souci de commodité, prime et generator peuvent également être l'un des paramètres statiques définis dans gnutls.h.

Initialement, le champ data est NULL dans chaque structure gnutls_datum_t que le rappel doit remplir. Lorsque le rappel est terminé, GnuTLS désalloue tous ces tampons qui ne sont pas NULL, quel que soit le résultat.

Afin d'empêcher les attaquants de deviner des noms d'utilisateur valides, si un utilisateur n'existe pas, les valeurs g et n doivent être remplies à l'aide des paramètres d'un utilisateur aléatoire. Dans ce cas, le rappel doit retourner la valeur spéciale (1). Voir également gnutls_srp_set_server_fake_salt_seed. Si cela n'est pas requis pour votre application, retournez une valeur négative à partir du rappel pour abandonner la négociation.

La fonction de rappel ne sera appelée qu'une seule fois par négociation. La fonction de rappel doit retourner 0 en cas de succès, tandis que -1 indique une erreur.
