NOM

gnutls_reauth - fonction de l'API

SYNOPSIS

#include <gnutls/gnutls.h>

int gnutls_reauth(gnutls_session_t session, unsigned int flags);

ARGUMENTS

gnutls_session_t session
est de type gnutls_session_t.
unsigned int flags
doit être zéro

DESCRIPTION

Cette fonction effectue l'authentification post-handshake pour TLS 1.3. L'authentification post-handshake est initiée par le serveur en appelant cette fonction. Les clients répondent lorsque GNUTLS_E_REAUTH_REQUEST a été vu lors de la réception des données.

Les erreurs non fatales attendues par cette fonction sont : GNUTLS_E_INTERRUPTED, GNUTLS_E_AGAIN, ainsi que GNUTLS_E_GOT_APPLICATION_DATA lorsqu'elle est appelée côté serveur.

Les deux premières interrompent la procédure d'authentification en raison de l'interruption de la couche de transport, et la dernière parce qu'il y avait des données en attente avant que le pair n'initie la réauthentification. Le serveur doit lire/traiter ces données comme non authentifiées et réessayer d'appeler gnutls_reauth().

Lorsque cette fonction est appelée sous TLS1.2 ou antérieur ou que le pair n'a pas annoncé l'authentification post-handshake, elle échoue toujours avec GNUTLS_E_INVALID_REQUEST. La vérification du certificat du pair reçu est déléguée aux callbacks de vérification de session ou de crédentiels. Un serveur peut vérifier si l'authentification post-handshake est supportée par le client en vérifiant les indicateurs de session avec gnutls_session_get_flags().

Avant d'appeler cette fonction côté serveur, la fonction gnutls_certificate_server_set_request() doit être appelée en définissant les attentes pour le certificat reçu (demande ou exigence). Si aucune n'est définie, cette fonction retournera GNUTLS_E_INVALID_REQUEST.

Notez que l'authentification post-handshake est disponible indépendamment du type de négociation initial (PSK ou certificat). Dans tous les cas, cependant, les crédentiels de certificat doivent être définis dans la session avant d'appeler cette fonction.

RETOUR

GNUTLS_E_SUCCESS en cas d'authentification réussie, sinon un code d'erreur négatif.
