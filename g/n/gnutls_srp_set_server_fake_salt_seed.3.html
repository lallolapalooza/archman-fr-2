gnutls_srp_set_server_fake_salt_seed(3) gnutls gnutls_srp_set_server_fake_salt_seed(3)

NOM

gnutls_srp_set_server_fake_salt_seed - Fonction d'API

SYNTAXE

#include <gnutls/gnutls.h>

void gnutls_srp_set_server_fake_salt_seed(gnutls_srp_server_credentials_t cred, const gnutls_datum_t * seed, unsigned int salt_length);

ARGUMENTS

gnutls_srp_server_credentials_t cred
est un type gnutls_srp_server_credentials_t
const gnutls_datum_t * seed
sont les données de départ, doivent seulement être valides jusqu'au retour de la fonction ; la taille de départ doit être supérieure à zéro
unsigned int salt_length
est la longueur des sels factices générés

DESCRIPTION

Cette fonction définit le départ utilisé pour générer les sels pour les noms d'utilisateur invalides (inexistants).

Afin d'empêcher les attaquants de deviner les noms d'utilisateur valides, lorsqu'un utilisateur n'existe pas, gnutls génère un sel et un vérificateur et poursuit le protocole comme d'habitude. L'authentification échouera finalement, mais le client ne pourra pas dire si le nom d'utilisateur est valide (existe) ou invalide.

Si un attaquant apprend le départ, étant donné un sel (qui fait partie de la négociation) qui a été généré lorsque le départ était en cours d'utilisation, il peut déterminer si l'authentification a échoué à cause d'un nom d'utilisateur inconnu ou non. Ce départ ne peut pas être utilisé pour révéler des données d'application ou des mots de passe.


salt_length devrait représenter la longueur du sel que votre application utilise. La génération de sels factices de plus de 20 octets n'est pas supportée.

Par défaut, le départ est une valeur aléatoire, différente à chaque fois qu'un gnutls_srp_server_credentials_t est alloué et les sels factices ont une longueur de 16 octets.
