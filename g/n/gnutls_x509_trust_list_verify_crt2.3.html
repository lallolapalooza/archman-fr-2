NOM

gnutls_x509_trust_list_verify_crt2 - Fonction API

SYNTAXE

#include <gnutls/x509.h>

int gnutls_x509_trust_list_verify_crt2(gnutls_x509_trust_list_t list, gnutls_x509_crt_t * cert_list, unsigned int cert_list_size, gnutls_typed_vdata_st * data, unsigned int elements, unsigned int flags, unsigned int * voutput, gnutls_verify_output_function func);

ARGUMENTS

gnutls_x509_trust_list_t list
La liste
gnutls_x509_crt_t * cert_list
est la liste de certificats à vérifier
unsigned int cert_list_size
est la taille de la liste de certificats
gnutls_typed_vdata_st * data
un tableau de données typées
unsigned int elements
le nombre d'éléments de données
unsigned int flags
Indicateurs pouvant être utilisés pour modifier l'algorithme de vérification. Utiliser l'opérateur OR des énumérations gnutls_certificate_verify_flags.
unsigned int * voutput
contiendra la sortie de la vérification du certificat.
gnutls_verify_output_function func
Si non nul, sera appelé pour chaque élément de chaîne vérifié avec la sortie.

DESCRIPTION

Cette fonction tentera de vérifier la chaîne de certificats donnée et retournera son statut. Le paramètre voutput contiendra une séquence combinée par OR des drapeaux de gnutls_certificate_status_t.

Lorsqu'une chaîne de certificats de cert_list_size avec plus d'un certificat est fournie, le statut de vérification s'appliquera au premier certificat de la chaîne qui a échoué à la vérification. Le processus de vérification commence à la fin de la chaîne (de l'AC au certificat final). Le premier certificat de la chaîne doit être le certificat final tandis que les autres membres peuvent être triés ou non.

En outre, un profil de vérification de certificat peut être spécifié parmi ceux de gnutls_certificate_verification_profiles_t en appliquant l'opérateur OR au résultat de GNUTLS_PROFILE_TO_VFLAGS() aux drapeaux de vérification.

Des paramètres de vérification supplémentaires sont possibles via les types data ; les types acceptables sont GNUTLS_DT_DNS_HOSTNAME, GNUTLS_DT_IP_ADDRESS et GNUTLS_DT_KEY_PURPOSE_OID. Le premier accepte une chaîne de caractères se terminant par un caractère nul comme nom d'hôte, et le second un identifiant d'objet se terminant par un caractère nul (par exemple, GNUTLS_KP_TLS_WWW_SERVER). Si un nom d'hôte DNS est fourni, cette fonction comparera le nom d'hôte dans le certificat final à celui donné. Si les noms ne correspondent pas, le drapeau de statut GNUTLS_CERT_UNEXPECTED_OWNER sera défini. De plus, elle prendra en compte les certificats fournis avec gnutls_x509_trust_list_add_named_crt().

Si un OID de but de clé est fourni et que le certificat final contient l'extension d'utilisation de clé étendue PKIX, il sera requis de correspondre à l'OID fourni ou d'être marqué pour n'importe quel but, sinon la vérification échouera avec le statut GNUTLS_CERT_PURPOSE_MISMATCH.

RETOURNE

En cas de succès, GNUTLS_E_SUCCESS (0) est retourné, sinon une valeur d'erreur négative. Notez qu'un échec de vérification n'entraînera pas de code d'erreur, seul voutput sera mis à jour.
