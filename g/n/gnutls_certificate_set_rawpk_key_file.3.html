NOM

gnutls_certificate_set_rawpk_key_file - Fonction d'API

SYNOPSIS

#include <gnutls/gnutls.h>

int gnutls_certificate_set_rawpk_key_file(gnutls_certificate_credentials_t cred, const char * rawpkfile, const char * privkeyfile, gnutls_x509_crt_fmt_t format, const char * pass, unsigned int key_usage, const char ** names, unsigned int names_length, unsigned int privkey_flags, unsigned int pkcs11_flags);

ARGUMENTS

gnutls_certificate_credentials_t cred
est un type gnutls_certificate_credentials_t.
const char * rawpkfile
contient une clé publique brute au format PKIX.SubjectPublicKeyInfo.
const char * privkeyfile
contient le chemin d'un fichier de clé privée.
gnutls_x509_crt_fmt_t format
encodage des clés. DER ou PEM.
const char * pass
un mot de passe optionnel pour déverrouiller le fichier de clé privée privkeyfile.
unsigned int key_usage
une séquence OR de drapeaux GNUTLS_KEY_*.
const char ** names
est un tableau de noms DNS appartenant à la clé publique (NULL s'il n'y en a pas).
unsigned int names_length
contient la longueur de la liste des noms.
unsigned int privkey_flags
une séquence OR de gnutls_pkcs_encrypt_flags_t. Ceux-ci s'appliquent à la clé privée pkey.
unsigned int pkcs11_flags
une parmi les gnutls_pkcs11_obj_flags. Ceux-ci s'appliquent aux URLs.

DESCRIPTION

Cette fonction définit une paire clé publique/clé privée lue à partir d'un fichier dans le type gnutls_certificate_credentials_t à utiliser pour l'authentification et/ou le chiffrement. spki et privkey doivent correspondre, sinon les signatures définies ne pourront pas être validées. En cas de non-correspondance, cette fonction retourne GNUTLS_E_CERTIFICATE_KEY_MISMATCH. Cette fonction doit être appelée une fois pour le client car il n'existe actuellement aucun mécanisme pour déterminer quelle clé publique brute sélectionner pour le pair lorsqu'il y en a plusieurs. Plusieurs clés publiques brutes pour le serveur peuvent être distinguées en définissant les names.

Notez ici que spki est une clé publique brute telle que définie dans la RFC7250. Cela signifie qu'il n'y a pas de certificat environnant qui contient la clé publique et donc aucun mécanisme direct pour prouver l'authenticité de cette clé. La paire de clés peut être utilisée pendant une négociation TLS, mais son authenticité doit être établie via un autre mécanisme (par exemple, TOFU ou empreinte connue).

Les formats pris en charge sont les clés non chiffrées de base, PKCS8, PKCS12 et le format openssl, et seront détectés automatiquement.

Si la clé publique brute et la clé privée sont fournies en encodage PEM, alors les chaînes qui contiennent leurs valeurs doivent être terminées par un caractère nul.

L'utilisation de la clé (telle que définie par l'extension X.509 (2.5.29.15)) peut être définie explicitement car il n'y a pas de structure de certificat autour de la clé pour définir cette valeur. Voir pour plus d'informations gnutls_x509_crt_get_key_usage().

Notez que cette fonction, par défaut, retourne zéro en cas de succès et une valeur négative en cas d'erreur. Depuis la version 3.5.6, lorsque le drapeau GNUTLS_CERTIFICATE_API_V2 est défini à l'aide de gnutls_certificate_set_flags(), elle renvoie un index (supérieur ou égal à zéro). Cet index peut être utilisé dans d'autres fonctions pour faire référence à la paire de clés ajoutée.

RETOURNE

En cas de succès, GNUTLS_E_SUCCESS (0) est retourné, dans le cas où la paire de clés ne correspond pas, GNUTLS_E_CERTIFICATE_KEY_MISMATCH est retourné, dans les autres cas d'erreur, un code d'erreur négatif différent est retourné.
