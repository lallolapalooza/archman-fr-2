gnutls_x509_crt_get_authority_info_access(3) gnutls gnutls_x509_crt_get_authority_info_access(3)

NOM

gnutls_x509_crt_get_authority_info_access - Fonction API

SYNTAXE

#include <gnutls/x509.h>

int gnutls_x509_crt_get_authority_info_access(gnutls_x509_crt_t crt, unsigned int seq, int what, gnutls_datum_t * data, unsigned int * critical);

ARGUMENTS

gnutls_x509_crt_t crt
Contient le certificat
unsigned int seq
spécifie le numéro de séquence du descripteur d'accès (0 pour le premier, 1 pour le second, etc.)
int what
quelles données obtenir, un type gnutls_info_access_what_t.
gnutls_datum_t * data
données de sortie à libérer avec gnutls_free().
unsigned int * critical
pointeur vers un entier de sortie qui est défini à une valeur non nulle si l'extension est marquée comme critique (peut être NULL)

DESCRIPTION

Notez qu'une API plus simple pour accéder aux données d'informations de l'autorité est fournie par gnutls_x509_aia_get() et gnutls_x509_ext_import_aia().

Cette fonction extrait l'extension Authority Information Access (AIA), voir la section 4.2.2.1 de la RFC 5280 pour plus d'informations. L'extension AIA contient une séquence de données AccessDescription (AD).

Le paramètre d'entrée seq est utilisé pour indiquer quel membre de la séquence intéresse l'appelant. Le premier membre est 0, le second membre est 1, et ainsi de suite. Lorsque la valeur de seq est hors limites, GNUTLS_E_REQUESTED_DATA_NOT_AVAILABLE est retourné.

Le type de données retourné dans data est spécifié via what qui devrait être des valeurs gnutls_info_access_what_t.

Si what est GNUTLS_IA_ACCESSMETHOD_OID alors data contiendra l'OID de la méthode d'accès (par exemple, "1.3.6.1.5.5.7.48.1").

Si what est GNUTLS_IA_ACCESSLOCATION_GENERALNAME_TYPE, data contiendra le type GeneralName de l'emplacement d'accès (par exemple, "uniformResourceIdentifier").

Si what est GNUTLS_IA_URI, data contiendra les données de l'URI de l'emplacement d'accès. La demande de cette valeur what entraîne une erreur si l'emplacement d'accès n'est pas de type "uniformResourceIdentifier".

Si what est GNUTLS_IA_OCSP_URI, data contiendra l'URI OCSP. La demande de cette valeur what entraîne une erreur si la méthode d'accès n'est pas 1.3.6.1.5.5.7.48.1 alias OCSP, ou si l'emplacement d'accès n'est pas de type "uniformResourceIdentifier". Dans ce cas, GNUTLS_E_UNKNOWN_ALGORITHM sera retourné, et seq devrait être incrémenté et cette fonction appelée à nouveau.

Si what est GNUTLS_IA_CAISSUERS_URI, data contiendra l'URI caIssuers. La demande de cette valeur what entraîne une erreur si la méthode d'accès n'est pas 1.3.6.1.5.5.7.48.2 alias caIssuers, ou si l'emplacement d'accès n'est pas de type "uniformResourceIdentifier". Dans ce cas, traiter comme pour GNUTLS_IA_OCSP_URI.

D'autres valeurs what pourront être allouées à l'avenir selon les besoins.

Si data est NULL, la fonction fait la même chose sans stocker les données de sortie, c'est-à-dire qu'elle définira critical et effectuera la vérification des erreurs comme d'habitude.

La valeur du drapeau critique est retournée dans * critical . Fournissez un critical NULL si vous voulez que la fonction s'assure que l'extension n'est pas critique, comme requis par la RFC 5280.

RETOUR

GNUTLS_E_SUCCESS en cas de succès, GNUTLS_E_INVALID_REQUEST en cas de crt invalide, GNUTLS_E_CONSTRAINT_ERROR si l'extension est incorrectement marquée comme critique (utilisez un critical non NULL pour outrepasser), GNUTLS_E_UNKNOWN_ALGORITHM si l'OID demandé ne correspond pas (par exemple, lors de l'utilisation de GNUTLS_IA_OCSP_URI), sinon un code d'erreur négatif.
