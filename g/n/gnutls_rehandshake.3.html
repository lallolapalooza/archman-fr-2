NOM

gnutls_rehandshake - fonction API

SYNTAXE

#include <gnutls/gnutls.h>

int gnutls_rehandshake(gnutls_session_t session);

ARGUMENTS

gnutls_session_t session
est un type gnutls_session_t.

DESCRIPTION

Cette fonction ne peut être appelée que côté serveur, et demande à un client TLS 1.2 ou antérieur de renégocier les paramètres (effectuer une négociation), en envoyant un message de demande de salutation.

Si cette fonction réussit, l'application appelante doit appeler gnutls_record_recv() jusqu'à ce que GNUTLS_E_REHANDSHAKE soit retourné pour effacer toute donnée en attente. Si le code d'erreur GNUTLS_E_REHANDSHAKE n'est pas vu, alors la demande de négociation n'a pas été suivie par le pair (le protocole TLS ne l'exige pas du client, et une telle conformité doit être gérée par le protocole applicatif).

Une fois que le code d'erreur GNUTLS_E_REHANDSHAKE est vu, l'application appelante doit procéder à l'appel de gnutls_handshake() pour négocier les nouveaux paramètres.

Si le client ne souhaite pas renégocier les paramètres, il peut répondre avec un message d'alerte, et dans ce cas le code de retour vu par les appels ultérieurs à gnutls_record_recv() sera GNUTLS_E_WARNING_ALERT_RECEIVED avec l'alerte spécifique étant GNUTLS_A_NO_RENEGOTIATION. Un client peut également choisir d'ignorer cette demande.

Sous TLS 1.3, cette fonction est équivalente à gnutls_session_key_update() avec l'indicateur GNUTLS_KU_PEER. Dans ce cas, les appels ultérieurs à gnutls_record_recv() ne retourneront pas GNUTLS_E_REHANDSHAKE, et les appels à gnutls_handshake() côté serveur sont une opération nulle.

Cette fonction échoue toujours avec GNUTLS_E_INVALID_REQUEST lorsqu'elle est appelée côté client.

RETOURNE

GNUTLS_E_SUCCESS en cas de succès, sinon un code d'erreur négatif.
