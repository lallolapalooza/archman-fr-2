NOM

gnutls_x509_crt_check_hostname2 - Fonction API

SYNTAXE

#include <gnutls/x509.h>

unsigned gnutls_x509_crt_check_hostname2(gnutls_x509_crt_t cert, const char * hostname, unsigned int flags);

ARGUMENTS

gnutls_x509_crt_t cert
devrait contenir un type gnutls_x509_crt_t
const char * hostname
Une chaîne terminée par null qui contient un nom DNS
unsigned int flags
gnutls_certificate_verify_flags

DESCRIPTION

Cette fonction vérifie si le sujet du certificat donné correspond au nom d'hôte donné. Il s'agit d'une implémentation de base de la correspondance décrite dans la RFC6125, et elle prend en compte les jokers, ainsi que l'extension de nom alternatif de sujet DNSName/IPAddress PKIX.

Les adresses IPv4 sont acceptées par cette fonction au format décimal pointé (par exemple, ddd.ddd.ddd.ddd), et les adresses IPv6 au format hexadécimal x:x:x:x:x:x:x:x. Pour celles-ci, l'extension de nom alternatif de sujet IPAddress est consultée. Les versions précédentes à 3.6.0 de GnuTLS, en cas de non-correspondance, consultaient (dans une extension non standard) les champs DNSname et CN. Ce n'est plus le cas.

Lorsque le drapeau GNUTLS_VERIFY_DO_NOT_ALLOW_WILDCARDS est spécifié, aucun joker n'est pris en compte. Sinon, ils ne sont considérés que si le nom de domaine comporte trois composantes ou plus, et que le joker commence à la position la plus à gauche. Lorsque le drapeau GNUTLS_VERIFY_DO_NOT_ALLOW_IP_MATCHES est spécifié, l'entrée sera traitée comme un nom DNS, et la correspondance d'adresses IP textuelles avec la partie IPAddress du nom alternatif ne sera pas autorisée.

La fonction gnutls_x509_crt_check_ip() est disponible pour la correspondance des adresses IP.

RETOURNE

une valeur non nulle en cas de succès de la correspondance, et zéro en cas d'échec.
