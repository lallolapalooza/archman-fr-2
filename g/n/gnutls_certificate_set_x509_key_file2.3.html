gnutls_certificate_set_x509_key_file2(3) gnutls gnutls_certificate_set_x509_key_file2(3)

NOM

gnutls_certificate_set_x509_key_file2 - Fonction API

SYNTAXE

#include <gnutls/gnutls.h>

int gnutls_certificate_set_x509_key_file2(gnutls_certificate_credentials_t res, const char * certfile, const char * keyfile, gnutls_x509_crt_fmt_t type, const char * pass, unsigned int flags);

ARGUMENTS

gnutls_certificate_credentials_t res
est un type gnutls_certificate_credentials_t.
const char * certfile
est un fichier contenant la liste des certificats (chemin) pour la clé privée spécifiée, au format PKCS7, ou une liste de certificats
const char * keyfile
est un fichier contenant la clé privée
gnutls_x509_crt_fmt_t type
est PEM ou DER
const char * pass
est le mot de passe de la clé
unsigned int flags
une séquence OR de gnutls_pkcs_encrypt_flags_t

DESCRIPTION

Cette fonction définit une paire certificat/clé privée dans le type gnutls_certificate_credentials_t. Cette fonction peut être appelée plus d'une fois, s'il existe plusieurs clés/certificats pour le serveur. Pour les clients qui ont besoin d'envoyer plus que leur propre certificat d'entité finale, par exemple, également un certificat d'autorité de certification intermédiaire, alors le fichier certfile doit contenir la chaîne de certificats ordonnée.

Notez que les noms dans le certificat fourni seront pris en compte lors de la sélection du certificat approprié à utiliser (en cas de plusieurs paires certificat/clé).

Cette fonction peut également accepter des URL dans keyfile et certfile. Dans ce cas, elle utilisera la clé privée et le certificat indiqués par les URL. Notez que les URL prises en charge sont celles indiquées par gnutls_url_is_supported(). Avant GnuTLS 3.4.0, lorsqu'une URL était spécifiée, la partie pass était ignorée et une fonction de rappel PIN devait être enregistrée, ce qui n'est plus le cas dans les versions actuelles.

Si le fichier certfile est fourni sous forme d'URL PKCS 11, alors le certificat et ses émetteurs présents sur le jeton sont importés (c'est-à-dire que la chaîne de confiance requise est formée).

Si cette fonction échoue à charger, la structure res est dans un état indéfini ; elle ne doit pas être réutilisée pour charger d'autres clés ou certificats.

Notez que, par défaut, cette fonction retourne zéro en cas de succès et une valeur négative en cas d'erreur. Depuis la version 3.5.6, lorsque le drapeau GNUTLS_CERTIFICATE_API_V2 est défini en utilisant gnutls_certificate_set_flags(), elle retourne un index (supérieur ou égal à zéro). Cet index peut être utilisé par d'autres fonctions pour faire référence à la paire clé ajoutée.

RETOURNE

En cas de succès, cette fonction retourne zéro, et sinon une valeur négative en cas d'erreur (voir ci-dessus pour modifier ce comportement).
