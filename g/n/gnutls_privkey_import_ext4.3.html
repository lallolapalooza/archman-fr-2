NOM

gnutls_privkey_import_ext4 - Fonction API

SYNTAXE

#include <gnutls/abstract.h>

int gnutls_privkey_import_ext4(gnutls_privkey_t pkey, void * userdata, gnutls_privkey_sign_data_func sign_data_fn, gnutls_privkey_sign_hash_func sign_hash_fn, gnutls_privkey_decrypt_func decrypt_fn, gnutls_privkey_deinit_func deinit_fn, gnutls_privkey_info_func info_fn, unsigned int flags);

ARGUMENTS

gnutls_privkey_t pkey
La clé privée
void * userdata
Données privées à fournir aux rappels
gnutls_privkey_sign_data_func sign_data_fn
Rappel pour les opérations de signature (peut être NULL)
gnutls_privkey_sign_hash_func sign_hash_fn
Rappel pour les opérations de signature (peut être NULL)
gnutls_privkey_decrypt_func decrypt_fn
Rappel pour les opérations de déchiffrement (peut être NULL)
gnutls_privkey_deinit_func deinit_fn
Une fonction de désinitialisation
gnutls_privkey_info_func info_fn
Renvoie des informations sur l'algorithme de clé publique (ne doit pas être NULL)
unsigned int flags
Indicateurs pour l'importation

DESCRIPTION

Cette fonction associera les rappels donnés au type gnutls_privkey_t. Au moins un des rappels doit être non nul. Si une fonction de désinitialisation est fournie, les indicateurs sont supposés contenir GNUTLS_PRIVKEY_IMPORT_AUTO_RELEASE.

Notez que contrairement à la fonction de signature de gnutls_privkey_import_ext3(), les fonctions de signature fournies à cette fonction prennent explicitement l'algorithme de signature comme paramètre et différentes fonctions sont fournies pour signer les données et les hachages.

La fonction sign_hash_fn doit être appelée pour signer des données pré-hachées. L'entrée du rappel est la sortie du hachage (tel que SHA256) correspondant à l'algorithme de signature. Pour les signatures RSA PKCS1, l'algorithme de signature peut être défini sur GNUTLS_SIGN_RSA_RAW, et dans ce cas les données doivent être traitées comme une structure RSA PKCS1 DigestInfo.

La fonction sign_data_fn doit être appelée pour signer des données. Les données d'entrée seront les données à signer (et à hacher), avec l'algorithme de signature fourni. Cette fonction doit être utilisée pour les algorithmes de signature tels qu'Ed25519 qui ne peuvent pas accepter de données pré-hachées en entrée.

Lorsque les deux fonctions sign_data_fn et sign_hash_fn sont fournies, elles doivent être capables de fonctionner sur tous les algorithmes de signature supportés, sauf si cela est interdit par le type de l'algorithme (par exemple, comme avec Ed25519).

La fonction info_fn doit fournir des informations sur les algorithmes de signature supportés par cette clé privée, et doit prendre en charge les indicateurs GNUTLS_PRIVKEY_INFO_PK_ALGO, GNUTLS_PRIVKEY_INFO_HAVE_SIGN_ALGO et GNUTLS_PRIVKEY_INFO_PK_ALGO_BITS. Elle doit retourner -1 pour les indicateurs inconnus.

VALEUR DE RETOUR

En cas de succès, GNUTLS_E_SUCCESS (0) est retourné, sinon une valeur d'erreur négative.
