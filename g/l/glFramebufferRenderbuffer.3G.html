GLFRAMEBUFFERRENDERB(3G) [FIXME: manual] GLFRAMEBUFFERRENDERB(3G)

NOM

glFramebufferRenderbuffer, glNamedFramebufferRenderbuffer - attacher un renderbuffer comme tampon logique d'un objet framebuffer

SPÉCIFICATION C

void glFramebufferRenderbuffer(GLenumtarget, GLenumattachment, GLenumrenderbuffertarget, GLuintrenderbuffer);

void glNamedFramebufferRenderbuffer(GLuintframebuffer, GLenumattachment, GLenumrenderbuffertarget, GLuintrenderbuffer);

PARAMÈTRES

target

Spécifie la cible à laquelle le framebuffer est lié pour glFramebufferRenderbuffer.

framebuffer

Spécifie le nom de l'objet framebuffer pour glNamedFramebufferRenderbuffer.

attachment

Spécifie le point d'attachement du framebuffer.

renderbuffertarget

Spécifie la cible renderbuffer. Doit être GL_RENDERBUFFER.

renderbuffer

Spécifie le nom d'un objet renderbuffer existant de type renderbuffertarget à attacher.

DESCRIPTION

glFramebufferRenderbuffer et glNamedFramebufferRenderbuffer attachent un renderbuffer comme l'un des tampons logiques de l'objet framebuffer spécifié. Les renderbuffers ne peuvent pas être attachés au framebuffer d'affichage et de lecture par défaut ; ils ne sont donc pas des cibles valides pour ces commandes.

Pour glFramebufferRenderbuffer, l'objet framebuffer est celui lié à target, qui doit être GL_DRAW_FRAMEBUFFER, GL_READ_FRAMEBUFFER ou GL_FRAMEBUFFER. GL_FRAMEBUFFER est équivalent à GL_DRAW_FRAMEBUFFER.

Pour glNamedFramebufferRenderbuffer, framebuffer est le nom de l'objet framebuffer.

renderbuffertarget doit être GL_RENDERBUFFER.

renderbuffer doit être zéro ou le nom d'un objet renderbuffer existant de type renderbuffertarget. Si renderbuffer n'est pas zéro, alors le renderbuffer spécifié sera utilisé comme le tampon logique identifié par attachment de l'objet framebuffer spécifié. Si renderbuffer est zéro, alors la valeur de renderbuffertarget est ignorée.

attachment spécifie l'attachement logique du framebuffer et doit être GL_COLOR_ATTACHMENTi, GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT ou GL_DEPTH_STENCIL_ATTACHMENT. i peut varier de zéro à la valeur de GL_MAX_COLOR_ATTACHMENTS moins un. Définir attachment à la valeur GL_DEPTH_STENCIL_ATTACHMENT est un cas spécial qui fait que les attachements de profondeur et de stencil de l'objet framebuffer spécifié sont définis à renderbuffer, qui devrait avoir le format interne de base GL_DEPTH_STENCIL.

La valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE pour le point d'attachement spécifié est définie à GL_RENDERBUFFER et la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME est définie à renderbuffer. Toutes les autres valeurs d'état du point d'attachement spécifié sont définies à leurs valeurs par défaut. Aucun changement n'est apporté à l'état de l'objet renderbuffer et toute attachement précédent au attachment tampon logique de l'objet framebuffer spécifié est rompu.

Si renderbuffer est zéro, ces commandes détacheront l'image, s'il y en a une, identifiée par le point d'attachement spécifié de l'objet framebuffer spécifié. Toutes les valeurs d'état du point d'attachement sont définies à leurs valeurs par défaut.

ERREUR

GL_INVALID_ENUM est généré par glFramebufferRenderbuffer si target n'est pas l'une des cibles de framebuffer acceptées.

GL_INVALID_OPERATION est généré par glFramebufferRenderbuffer si zéro est lié à target.

GL_INVALID_OPERATION est généré par glNamedFramebufferRenderbuffer si framebuffer n'est pas le nom d'un objet framebuffer existant.

GL_INVALID_ENUM est généré si attachment n'est pas l'un des points d'attachement acceptés.

GL_INVALID_ENUM est généré si renderbuffertarget n'est pas GL_RENDERBUFFER.

GL_INVALID_OPERATION est généré si renderbuffertarget n'est pas zéro ou le nom d'un objet renderbuffer existant de type GL_RENDERBUFFER.
