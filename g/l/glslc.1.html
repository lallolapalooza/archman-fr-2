Si un nom est spécifié via -o, le fichier de sortie portera ce nom.

•Si une option de sélection de stage de compilation est donnée (-S ou -c), un fichier de sortie sera généré pour chaque fichier de shader d'entrée. EXEMPLES

The following examples demonstrate the behavior of glslc:

When compiling a GLSL shader file main.vert to SPIR-V:
glslc main.vert
This will produce a SPIR-V binary file named main.vert.spv in the current directory.
To specify an output file name:
glslc main.vert -o my_shader.spv
This will produce a SPIR-V binary file named my_shader.spv.
To compile multiple files into a single SPIR-V module:
glslc main.vert main.frag -o my_module.spv
This will compile both main.vert and main.frag and link them into a single SPIR-V module named my_module.spv.
To compile HLSL shader code:
glslc -x hlsl main.hlsl -o main.spv
This will compile the HLSL source file main.hlsl into SPIR-V.
To generate preprocessed GLSL output:
glslc -E main.vert
This will print the preprocessed GLSL source code to standard output.
To generate GLSL assembly output:
glslc -S main.vert
This will produce a GLSL assembly file named main.vert.spvasm.
To generate dependency information in a format compatible with Make:
glslc -MD main.vert
This will create a dependency file named main.vert.spv.d along with the SPIR-V binary.
To control the output of dependency information:
glslc -c -MD main.vert -MF deps.mk -MT my_target.o
This will create a dependency file named deps.mk with the target my_target.o.

glslc -c -MD main.vert -o obj obj obj.d obj: main.vert
glslc -c -MD main.vert -o obj -MF dep_info -MT target obj dep_info target: main.vert

Options de Liaison de Ressources

-fauto-bind-uniforms

L'option -fauto-bind-uniforms demande au compilateur d'attribuer automatiquement des numéros de liaison aux variables uniformes lorsqu'une liaison explicite n'est pas spécifiée dans le code source du shader.

Un numéro de liaison explicite peut être spécifié dans le code source du shader en utilisant un qualificateur de disposition binding. Par exemple :

layout(binding = 12) uniform texture2D;

-fhlsl-iomap

L'option -fhlsl-iomap demande au compilateur d'utiliser les affectations de registres HLSL comme valeurs de liaison.

-fimage-binding-base

L'option -fimage-binding-base [stage] base définit la liaison minimale attribuée automatiquement pour les images. Si une phase (stage) est spécifiée, elle n'affecte que la phase spécifiée.

Pour HLSL, définit une valeur inférieure de 1 à la base.

-fsampler-binding-base

L'option -fsampler-binding-base [stage] base définit la liaison minimale attribuée automatiquement pour les samplers. Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

Pour HLSL, définit une valeur inférieure de 1 à la base.

-ftexture-binding-base

L'option -ftexture-binding-base [stage] base définit la liaison minimale attribuée automatiquement pour les textures. Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

Pour HLSL, définit une valeur inférieure de 1 à la base.

-fubo-binding-base

L'option -fubo-binding-base [stage] base définit la liaison minimale attribuée automatiquement pour les objets de tampon uniformes (Uniform Buffer Objects - GLSL) ou les Cbuffers (HLSL). Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

Pour HLSL, définit une valeur inférieure de 1 à la base.

-fcbuffer-binding-base

L'option -fcbuffer-binding-base [stage] base est identique à -fubo-binding-base [stage] base.

-fssbo-binding-base

L'option -fssbo-binding-base [stage] base définit la liaison minimale attribuée automatiquement pour les objets de tampon de stockage de shaders (Shader Storage Buffer Objects - GLSL). Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

Ceci n'affecte que la compilation GLSL.

-fuav-binding-base

L'option -fuav-binding-base [stage] base définit une valeur inférieure de 1 à la liaison minimale attribuée automatiquement pour les vues d'accès non ordonnées (Unordered Access Views - UAV). Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

Ceci n'affecte que la compilation HLSL.

-fresource-set-binding

L'option -fresource-set-binding [stage] <reg0> <set0> <binding0> définit l'ensemble de descripteurs et la liaison pour une ressource HLSL, par nom de registre. Pour spécifier les paramètres pour plusieurs registres, ajoutez leurs triplets composés du nom du registre, de l'ensemble de descripteurs et de la liaison.

Exemple :

# Pour une texture dans le registre t1, utiliser l'ensemble 1, liaison 0.
# Pour une texture dans le registre t2, utiliser l'ensemble 1, liaison 3
glslc -x hlsl foo.frag -fresource-set-binding t1 1 0 t2 1 3

Si une phase est spécifiée, elle n'affecte que la phase spécifiée.

# Identique à l'exemple précédent, mais les paramètres s'appliquent
# uniquement aux shaders de fragment (pixel).
glslc -x hlsl foo.frag -fresource-set-binding frag t1 1 0 t2 1 3

DIVERGENCES PAR RAPPORT AUX SPÉCIFICATIONS GLSL ET EXTENSIONS

Directives #line et macro __FILE__ basées sur le nom du fichier source

Cette section décrit comment le compilateur glslc étend la syntaxe pour la directive #line et la macro __FILE__. Par défaut, le compilateur glslc active l'extension GL_GOOGLE_cpp_style_line_directive. Il générera cette syntaxe étendue dans la sortie prétraitée (obtenue via l'option -E).


Attention

Cette section est encore en évolution. Des changements sont à prévoir.

Les spécifications GLSL ont une notion de chaînes source.

La source d'un shader unique est un tableau de chaînes de caractères de l'ensemble de caractères. Un shader unique est constitué de la concaténation de ces chaînes.

— Section 3.2 des versions 3.30 et 4.50

Avec la notion ci-dessus, le deuxième paramètre de la directive #line devrait être une expression entière constante représentant le numéro de la chaîne source. De plus, la macro __FILE__ "substituera une constante entière décimale indiquant quel numéro de chaîne source est actuellement traité."

Le compilateur glslc implémente la syntaxe standard #line et __FILE__. Il fournit également une extension, GL_GOOGLE_cpp_style_line_directive, pour permettre l'utilisation de noms de fichiers source à la place des indices de chaînes source entiers. Plus précisément, la directive #line peut avoir, après substitution de macro, l'une des trois formes suivantes :

#line numéro-de-ligne
#line numéro-de-ligne index-de-chaîne-source-entière
#line numéro-de-ligne "nom-du-fichier-source"

où nom-du-fichier-source peut être toute combinaison de caractères à l'exception des guillemets doubles. (Notez que, conformément à la spécification GLSL, "il n'y a pas de séquences d'échappement ni d'autres utilisations de la barre oblique inverse au-delà de son utilisation comme caractère de continuation de ligne".)

Et si le #line basé sur le nom du fichier source est utilisé, la macro __FILE__ se développe en une chaîne dont le contenu est le nom du fichier, encadré par des guillemets doubles. Le nom du fichier est déterminé comme étant le dernier des éléments suivants :

• Le nom du fichier passé au compilateur glslc,
• Le nom de fichier de l'argument de la directive #line la plus récente, s'il y en a une.

#include

Le compilateur glslc étend GLSL avec la syntaxe d'inclusion en activant l'extension GL_GOOGLE_include_directive. Il prétraitera et substituera correctement les directives #include avec les comportements suivants.


Attention

Cette section est encore en évolution. Des changements sont à prévoir.

Si des directives #include sont utilisées dans un shader, une ligne #extension GL_GOOGLE_include_directive : enable sera générée dans la sortie prétraitée.

L'extension GL_GOOGLE_cpp_style_line_directive est implicitement activée par l'extension GL_GOOGLE_include_directive.

Le nom de fichier argument de #include doit être entouré de guillemets doubles. Il doit s'agir d'un chemin relatif, en utilisant le séparateur de chemin que le système d'exploitation supporte. Cependant, le dernier élément du chemin - le nom du fichier lui-même - ne doit contenir ni '/' ni '\', quel que soit le séparateur de chemin utilisé. Cela ne sera pas signalé comme une erreur, mais déclenchera un comportement indéfini. Par exemple, supposons qu'il existe un fichier nommé f\ilename.vert sur un système Unix. Il n'est pas possible de construire un #include qui inclut ce fichier.

De plus, il n'est pas possible d'échapper des caractères dans une directive #include, donc l'argument du fichier ne peut pas contenir de caractères spéciaux nécessitant un échappement en C.

L'argument du fichier est un

chemin relatif qui est d'abord comparé au répertoire du fichier inclus lui-même, puis à tous les arguments -I dans l'ordre de leur apparition sur la ligne de commande. Si le fichier ne peut être trouvé, glslc interr

ompt l'exécution avec une erreur. -07
