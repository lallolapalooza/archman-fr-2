NOM

glTexSubImage3D, glTextureSubImage3D - spécifier une sous-image de texture tridimensionnelle

SPÉCIFICATION EN C

void glTexSubImage3D(GLenum target, GLint level, GLint xoffset, GLint yoffset, GLint zoffset, GLsizei width, GLsizei height, GLsizei depth, GLenum format, GLenum type, const void * pixels);

void glTextureSubImage3D(GLuint texture, GLint level, GLint xoffset, GLint yoffset, GLint zoffset, GLsizei width, GLsizei height, GLsizei depth, GLenum format, GLenum type, const void *pixels);

PARAMÈTRES

target

Spécifie la cible à laquelle la texture est liée pour glTexSubImage3D. Doit être GL_TEXTURE_3D ou GL_TEXTURE_2D_ARRAY.

texture

Spécifie le nom de l'objet texture pour glTextureSubImage3D. La cible effective de texture doit être l'une des valeurs de target valides ci-dessus.

level

Spécifie le numéro du niveau de détail. Le niveau 0 est l'image de base. Le niveau n est la n-ième image de réduction mipmap.

xoffset

Spécifie un décalage de texel dans la direction x au sein du tableau de texture.

yoffset

Spécifie un décalage de texel dans la direction y au sein du tableau de texture.

zoffset

Spécifie un décalage de texel dans la direction z au sein du tableau de texture.

width

Spécifie la largeur de la sous-image de texture.

height

Spécifie la hauteur de la sous-image de texture.

depth

Spécifie la profondeur de la sous-image de texture.

format

Spécifie le format des données de pixel. Les valeurs symboliques suivantes sont acceptées : GL_RED, GL_RG, GL_RGB, GL_BGR, GL_RGBA, GL_DEPTH_COMPONENT, et GL_STENCIL_INDEX.

type

Spécifie le type de données des pixels. Les valeurs symboliques suivantes sont acceptées : GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, et GL_UNSIGNED_INT_2_10_10_10_REV.

pixels

Pointeur vers les données de l'image en mémoire.

DESCRIPTION

Le texturage applique une partie d'une image de texture spécifiée sur chaque primitive graphique pour laquelle le texturage est activé.

glTexSubImage3D et glTextureSubImage3D redéfinissent une région contiguë d'une texture tridimensionnelle ou d'un tableau de textures bidimensionnelles existant. Les texels référencés par pixels remplacent la partie du tableau de textures existant avec des indices x de xoffset à xoffset + width - 1, inclus, des indices y de yoffset à yoffset + height - 1, inclus, et des indices z de zoffset à zoffset + depth - 1, inclus. Pour les textures tridimensionnelles, l'indice z se réfère à la troisième dimension. Pour les tableaux de textures bidimensionnelles, l'indice z se réfère à l'indice de la tranche. Cette région ne peut pas inclure de texels en dehors de la plage du tableau de textures tel qu'il a été spécifié initialement. Ce n'est pas une erreur de spécifier une sous-texture avec une largeur, une hauteur ou une profondeur nulle, mais une telle spécification n'a aucun effet.

Si un objet buffer nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER (voir glBindBuffer()) pendant la spécification d'une image de texture, pixels est traité comme un décalage d'octets dans le magasin de données de l'objet buffer.

NOTES

Les modes de glPixelStore() affectent les images de texture.

glTexSubImage3D et glTextureSubImage3D spécifient une sous-texture tridimensionnelle ou un tableau de sous-textures bidimensionnelles pour l'unité de texture courante, spécifiée avec glActiveTexture().

GL_STENCIL_INDEX est accepté pour format uniquement si la version GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré si target ou la cible effective de texture n'est pas GL_TEXTURE_3D, GL_TEXTURE_2D_ARRAY ou GL_TEXTURE_CUBE_MAP_ARRAY.

GL_INVALID_OPERATION est généré par glTextureSubImage3D si texture n'est pas le nom d'un objet texture existant.

GL_INVALID_ENUM est généré si format n'est pas une constante de format acceptée.

GL_INVALID_ENUM est généré si type n'est pas une constante de type.

GL_INVALID_VALUE est généré si level est inférieur à 0.

GL_INVALID_VALUE peut être généré si level est supérieur à log 2 max, où max est la valeur retournée par GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE est généré si xoffset < - b, xoffset + width > w - b, yoffset < - b, ou yoffset + height > h - b, ou zoffset < - b, ou zoffset + depth > d - b, où w est la GL_TEXTURE_WIDTH, h est la GL_TEXTURE_HEIGHT, d est la GL_TEXTURE_DEPTH et b est la largeur de la bordure de l'image de texture en cours de modification. Notez que w, h et d incluent deux fois la largeur de la bordure.

GL_INVALID_VALUE est généré si width, height, ou depth est inférieur à 0.

GL_INVALID_OPERATION est généré si le tableau de textures n'a pas été défini par une opération glTexImage3D() ou glTexStorage3D() précédente.

GL_INVALID_OPERATION est généré si type est l'un des GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, ou GL_UNSIGNED_SHORT_5_6_5_REV et que format n'est pas GL_RGB.

GL_INVALID_OPERATION est généré si type est l'un des GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, ou GL_UNSIGNED_INT_2_10_10_10_REV et que format n'est ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION est généré si format est GL_STENCIL_INDEX et que le format interne de base n'est pas GL_STENCIL_INDEX.

GL_INVALID_OPERATION est généré si un objet buffer nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que son magasin de données est actuellement mappé.

GL_INVALID_OPERATION est généré si un objet buffer nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que les données seraient décompressées depuis l'objet buffer de telle sorte que les lectures mémoire requises dépasseraient la taille du magasin de données.

GL_INVALID_OPERATION est généré si un objet buffer nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que pixels n'est pas divisible exactement par le nombre d'octets nécessaires pour stocker en mémoire une donnée indiquée par type.

GETS ASSOCIÉS

glGetTexImage()

glGet() avec l'argument GL_PIXEL_UNPACK_BUFFER_BINDING
