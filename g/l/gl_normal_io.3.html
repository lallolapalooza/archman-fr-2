CÉDER LE

TERMINAL

Une complication unique au mode serveur non bloquant est qu'il nécessite que le terminal soit laissé en mode brut entre les appels à gl_get_line(). Si ce n'était pas le cas, la boucle d'événements externe ne pourrait pas détecter les appuis de touches individuels, et l'édition de ligne de base implémentée par le pilote du terminal entrerait en conflit avec l'édition fournie par gl_get_line(). Cela signifie que chaque fois que le terminal doit être utilisé pour autre chose que la saisie d'une nouvelle ligne d'entrée avec gl_get_line(), il doit être restauré à un état utilisable. En particulier, chaque fois que le processus est suspendu ou terminé, le terminal doit être rendu à un état normal. Si cela n'est pas fait, alors selon les caractéristiques du shell utilisé pour invoquer le programme, l' utilisateur peut se retrouver avec un terminal bloqué. À cette fin, la fonction gl_normal_io() est fournie pour basculer le terminal vers l'état dans lequel il se trouvait lorsque le mode brut a été établi pour la dernière

fois. 
  int gl_normal_io(GetLine *gl)
;

Ce que fait cette fonction est d'abord de vider toute sortie en attente vers le terminal, puis de déplacer le curseur au début de la ligne du terminal qui suit la fin de la ligne d'entrée saisie incomplètement. À ce stade, il est sûr de suspendre ou de terminer le processus, et il est sûr pour l'application de lire et d'écrire sur le terminal. Pour reprendre la saisie de la ligne d'entrée, l'application doit appeler la fonction gl_raw_io()

. 
  int gl_raw_io(GetLine *gl)
;

Cette fonction démarre une nouvelle ligne, réaffiche la ligne d'entrée partiellement terminée (le cas échéant), restaure la position du curseur à l'intérieur de cette ligne à l'endroit où elle était lorsque gl_normal_io() a été appelé, puis bascule vers le mode terminal brut, non bloquant, prêt à continuer la saisie de la ligne d'entrée lorsque gl_get_line() sera appelé à

nouveau.

Notez qu'en mode serveur non bloquant, si gl_get_line() est appelé après un appel à gl_normal_io(), sans appel intermédiaire à gl_raw_io(), gl_get_line() appellera gl_raw_mode() lui-même, et le terminal restera dans ce mode lorsque gl_get_line()

reto
urnera.

GESTION DES

SIGNAUX

Dans la section précédente, il a été souligné qu'en mode serveur non bloquant, le terminal doit être restauré à un état raisonnable chaque fois qu'un signal est reçu qui suspend ou termine le processus. En mode d'E/S normal, cela est fait pour vous par gl_get_line(), mais en mode serveur non bloquant, puisque le terminal est laissé en mode brut entre les appels à gl_get_line(), cette gestion des signaux doit être faite par l'application. Comme il y a de nombreux signaux qui peuvent suspendre ou terminer un processus, ainsi que d'autres signaux qui sont importants pour gl_get_line(), tels que le signal SIGWINCH, qui lui indique quand la taille du terminal a changé, la fonction gl_tty_signals() est fournie pour installer des gestionnaires de signaux pour tous les signaux

pertinents.

PAR

GL_GET_LINE Étant donné que l'on attend de l'application qu'elle gère les signaux en mode serveur non bloquant, gl_get_line() n'essaie pas de dupliquer cela lorsqu'elle est appelée. Si l'un des signaux qu'elle est configurée pour intercepter est envoyé à l'application pendant que gl_get_line() est appelée, gl_get_line() rétablit les gestionnaires de signaux de l'appelant, puis juste avant de renvoyer, renvoie le signal au processus pour laisser le gestionnaire de signal de l'application le traiter. Si le processus n'est pas terminé par ce signal, gl_get_line() renvoie NULL, et un appel suivant à gl_return_status() renvoie l'énumérationd valeur GLR_SIGNAL.

INTERRUPTION DE LA SAISIE DE LIGNE

Souvent, plutôt que de laisser le processus se terminer, les applications répondent au signal utilisateur d'interruption SIGINT en abandonnant la ligne de saisie en cours. La façon de faire cela en mode I/O serveur non bloquant est de ne pas appeler gl_handle_signal() lorsque ce signal est intercepté, mais plutôt d'appeler gl_abandon_line().

  void gl_abandon_line(GetLine *gl);

Cette fonction fait en sorte que lorsque gl_get_line() est appelée ensuite, elle vide d'abord toute sortie en attente vers le terminal, puis écarte la ligne de saisie en cours, affiche une nouvelle invite sur la ligne suivante, et commence enfin à accepter la saisie d'une nouvelle ligne de l'utilisateur.

FONCTIONS SÉCURISÉES POUR LES SIGNAUX

À condition que certaines règles soient suivies, les fonctions suivantes peuvent être écrites pour être appelées en toute sécurité depuis des gestionnaires de signaux. D'autres fonctions de cette bibliothèque ne doivent pas être appelées depuis des gestionnaires de signaux.

  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line()

Pour que cela soit vrai, tous les gestionnaires de signaux qui appellent ces fonctions doivent être enregistrés de telle sorte qu'une seule instance de chacune d'entre elles puisse s'exécuter à la fois. La façon de faire cela est d'utiliser la fonction POSIX sigaction() pour enregistrer tous les gestionnaires de signaux, et lors de ce faire, utiliser le membre sa_mask de la structure sigaction correspondante, pour indiquer que tous les signaux dont les gestionnaires invoquent les fonctions ci-dessus, doivent être bloqués lorsque le signal actuel est géré. Cela empêche deux gestionnaires de signaux d'opérer sur un objet GetLine en même temps.

Pour empêcher les gestionnaires de signaux d'accéder à un objet GetLine pendant que gl_get_line() ou l'une de ses fonctions publiques associées l'utilise, toutes les fonctions publiques associées à gl_get_line(), y compris gl_get_line() elle-même, bloquent temporairement la livraison des signaux lorsqu'elles accèdent aux objets GetLine. Attention, les seuls signaux qu'elles bloquent sont les signaux que gl_get_line() est actuellement configuré pour intercepter, alors assurez-vous que si vous appelez l'une des fonctions ci-dessus depuis des gestionnaires de signaux, que les signaux auxquels ces gestionnaires sont assignés sont configurés pour être interceptés par gl_get_line() (voir gl_trap_signal()).

UTILISATION DES TEMPS D'ATTENTE POUR SONDER

Si au lieu d'utiliser select() ou poll() pour attendre l'I/O, votre application a juste besoin de sortir périodiquement de gl_get_line() pour faire brièvement autre chose avant de retourner accepter la saisie de l'utilisateur, cela peut être fait en mode serveur non bloquant en utilisant la fonction gl_inactivity_timeout() (voir gl_get_line(3)), pour spécifier qu'une fonction de rappel retournant GLTO_CONTINUE doit être appelée chaque fois que gl_get_line() attend l'I/O depuis plus d'un temps spécifié.

Lorsque ce rappel est déclenché, gl_get_line() retournera NULL, et un appel suivant à gl_return_status() retournera GLR_BLOCKED.

Attention, gl_get_line() ne retournera pas tant que l'utilisateur n'aura pas tapé une touche pendant l'intervalle spécifié, donc si l'intervalle est long, et que l'utilisateur continue de taper, gl_get_line() peut ne pas retourner pendant un certain temps. En d'autres termes, il n'y a aucune garantie qu'il retournera dans le temps spécifié.

LE PROGRAMME DE DÉMONSTRATION SERVEUR

Le programme demo3 distribué avec la bibliothèque, fournit un exemple fonctionnel d'utilisation du mode I/O serveur non bloquant dans un programme réel. En ce qui concerne l'utilisateur, ce programme fonctionne de manière identique au programme de démonstration principal (appelé demo), sauf que tandis que le programme de démonstration principal utilise le mode d'I/O bloquant normal, demo3 utilise l'I/O non bloquant et une boucle d'événements externe. Le code source se trouve dans demo3.c, et les commentaires qu'il contient expliquent les différentes étapes.
