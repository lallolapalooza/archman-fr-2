PARAMÈTRES

location

Spécifie l'emplacement de la variable uniforme à modifier.

count

Pour les commandes vectorielles (glUniform*v), spécifie le nombre d'éléments à modifier. Ceci doit être 1 si la variable uniforme ciblée n'est pas un tableau, et 1 ou plus si c'est un tableau.

Pour les commandes matricielles (glUniformMatrix*), spécifie le nombre de matrices à modifier. Ceci doit être 1 si la variable uniforme ciblée n'est pas un tableau de matrices, et 1 ou plus si c'est un tableau de matrices.

transpose

Pour les commandes matricielles, spécifie si la matrice doit être transposée lors du chargement des valeurs dans la variable uniforme.

v0, v1, v2, v3

Pour les commandes scalaires, spécifie les nouvelles valeurs à utiliser pour la variable uniforme spécifiée.

value

Pour les commandes vectorielles et matricielles, spécifie un pointeur vers un tableau de count valeurs qui seront utilisées pour mettre à jour la variable uniforme spécifiée.

DESCRIPTION

glUniform modifie la valeur d'une variable uniforme ou d'un tableau de variables uniformes. L'emplacement de la variable uniforme à modifier est spécifié par location, qui doit être une valeur retournée par glGetUniformLocation(). glUniform opère sur l'objet de programme qui a été rendu partie de l'état courant par un appel à glUseProgram().

Les commandes glUniform{1|2|3|4}{f|i|ui} sont utilisées pour modifier la valeur de la variable uniforme spécifiée par location en utilisant les valeurs passées en arguments. Le nombre spécifié dans la commande doit correspondre au nombre de composantes du type de données de la variable uniforme spécifiée (par exemple, 1 pour float, int, unsigned int, bool ; 2 pour vec2, ivec2, uvec2, bvec2, etc.). Le suffixe f indique que des valeurs en virgule flottante sont passées ; le suffixe i indique que des valeurs entières sont passées ; le suffixe ui indique que des valeurs entières non signées sont passées, et ce type doit également correspondre au type de données de la variable uniforme spécifiée. Les variantes i de cette fonction doivent être utilisées pour fournir des valeurs pour les variables uniformes définies comme int, i

vec2, ivec3, ivec4, ou des tableaux de ceux-ci. Les variantes ui de cette fonction doivent être utilisées pour fournir des valeurs à des variables uniformes définies comme unsigned int, uvec2, uvec3, uvec4, ou des tableaux de ceux-ci. Les variantes f doivent être utilisées pour fournir des valeurs à des variables uniformes de type float, vec2, vec3, vec4, ou des tableaux de ceux-ci. Les variantes i, ui ou f peuvent être utilisées pour fournir des valeurs à des variables uniformes de type bool, bvec2, bvec3, bvec4, ou des tableaux de ceux-ci. La variable uniforme sera définie à false si la valeur d'entrée est 0 ou 0.0f, et elle sera définie à true dans le cas

contraire.

Toutes les variables uniformes actives définies dans un objet programme sont initialisées à 0 lorsque l'objet programme est lié avec succès. Elles conservent les valeurs qui leur ont été assignées par un appel à glUniform jusqu'à ce que la prochaine opération de liaison réussie se produise sur l'objet programme, moment où elles sont à nouveau initialisées à

0.

Les commandes glUniform{1|2|3|4}{f|i|ui}v peuvent être utilisées pour modifier une variable uniforme unique ou un tableau de variables uniformes. Ces commandes transmettent un compteur et un pointeur vers les valeurs à charger dans une variable uniforme ou un tableau de variables uniformes. Un compteur de 1 doit être utilisé si l'on modifie la valeur d'une seule variable uniforme, et un compteur de 1 ou supérieur peut être utilisé pour modifier un tableau entier ou une partie d'un tableau. Lors du chargement de n éléments à partir d'une position arbitraire m dans un tableau de variables uniformes, les éléments m + n - 1 dans le tableau seront remplacés par les nouvelles valeurs. Si m + n - 1 est supérieur à la taille du tableau de variables uniformes, les valeurs pour tous les éléments du tableau au-delà de la fin du tableau seront ignorées. Le nombre spécifié dans le nom de la commande indique le nombre de composantes pour chaque élément dans value, et il doit correspondre au nombre de composantes dans le type de données de la variable uniforme spécifiée (par exemple, 1 pour float, int, bool ; 2 pour vec2, ivec2, bvec2, etc.). Le type de données spécifié dans le nom de la commande doit correspondre au type de données de la variable uniforme spécifiée comme décrit précédemment pour glUniform{1|2|3|4}

{f|i|ui}.

Pour les tableaux de variables uniformes, chaque élément du tableau est considéré comme étant du type indiqué dans le nom de la commande (par exemple, glUniform3f ou glUniform3fv peuvent être utilisés pour charger un tableau de variables uniformes de type vec3). Le nombre d'éléments du tableau de variables uniformes à modifier est spécifié par coun

t

Les commandes glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv sont utilisées pour modifier une matrice ou un tableau de matrices. Les nombres dans le nom de la commande sont interprétés comme la dimensionnalité de la matrice. Le nombre 2 indique une matrice 2 × 2 (c'est-à-dire 4 valeurs), le nombre 3 indique une matrice 3 × 3 (c'est-à-dire 9 valeurs), et le nombre 4 indique une matrice 4 × 4 (c'est-à-dire 16 valeurs). La dimensionnalité des matrices non carrées est explicite, le premier nombre représentant le nombre de colonnes et le second nombre représentant le nombre de lignes. Par exemple, 2x4 indique une matrice 2 × 4 avec 2 colonnes et 4 lignes (c'est-à-dire 8 valeurs). Si transpose est GL_FALSE, chaque matrice est supposée être fournie dans l'ordre colonne majeur. Si transpose est GL_TRUE, chaque matrice est supposée être fournie dans l'ordre ligne majeur. L'argument count indique le nombre de matrices à transmettre. Un compteur de 1 doit être utilisé si l'on modifie la v

aleur d'une seule matrice, et un compteur supérieur à 1 peut être utilisé pour modifier un tableau de matrices.

NOTE

S

glUniform1i et glUniform1iv sont les seules deux fonctions qui peuvent être utilisées pour charger des variables uniformes définies comme des types sampler. Le chargement de samplers avec toute autre fonction entraînera une erreur GL_INVALID_OPERATION

.

Si count est supérieur à 1 et que la variable uniforme indiquée n'est pas un tableau, une erreur GL_INVALID_OPERATION est générée et la variable uniforme spécifiée restera

inchangée.

En dehors des exceptions précédentes, si le type et la taille de la variable uniforme tels que définis dans le shader ne correspondent pas au type et à la taille spécifiés dans le nom de la commande utilisée pour charger sa valeur, une erreur GL_INVALID_OPERATION sera générée et la variable uniforme spécifiée restera

inchangée.

Si location est une valeur autre que -1 et qu'elle ne représente pas un emplacement de variable uniforme valide dans l'objet programme courant, une erreur sera générée, et aucun changement ne sera apporté au stockage des variables uniformes de l'objet programme courant. Si location est égal à -1, les données transmises seront ignorées sil

encieusement et la variable uniforme
spécifiée ne sera pas changée.

ERREUR

S

GL_INVALID_OPERATION est généré s'il n'y a pas d'objet programme

courant.

GL_INVALID_OPERATION est généré si la taille de la variable uniforme déclarée dans le shader ne correspond pas à la taille indiquée par la commande glUn

iform.

GL_INVALID_OPERATION est généré si l'une des variantes entières signées ou non signées de cette fonction est utilisée pour charger une variable uniforme de type float, vec2, vec3, vec4, ou un tableau de ceux-ci, ou si l'une des variantes en virgule flottante de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières signées de cette fonction est utilisée pour charger une variable uniforme de type unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières non signées de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si location est un emplacement de uniforme invalide pour l'objet programme courant et que location n'est pas égal à

-1.

GL_INVALID_VALUE est généré si count est inférieur à

0.

GL_INVALID_OPERATION est généré si count est supérieur à 1 et que la variable uniforme indiquée n'est pas une variable

tableau.

GL_INVALID_OPERATION est généré si un sampler est chargé à l'aide d'une commande autre que glUniform1i et glUniform1i

v
.
