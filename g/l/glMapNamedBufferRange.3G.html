NOM

glMapNamedBufferRange, glMapBufferRange - mapper une plage de mémoires tampons de données

SPÉCIFICATION C

void *glMapNamedBufferRange(GLuint buffer, GLintptr offset, GLsizeiptr length, GLbitfield access);

void *glMapBufferRange(GLenum target, GLintptr offset, GLsizeiptr length, GLbitfield access);

PARAMÈTRES

buffer

Le nom d'un tampon de mémoire à mapper.

target

La cible de liaison du tampon de mémoire. Doit être l'une des cibles de liaison de tampon répertoriées ci-dessous.

offset

Le décalage dans le tampon de mémoire qui sera le début de la plage mappée. Doit être aligné sur l'alignement minimal de mappage du tampon.

length

La longueur de la plage qui sera mappée. Doit être zéro ou plus.

access

Un masque de bits indiquant les droits d'accès pour la plage mappée. Les bits valides sont :
•GL_MAP_READ_BIT
La plage mappée sera accessible en lecture.
•GL_MAP_WRITE_BIT
La plage mappée sera accessible en écriture.
•GL_MAP_PERSISTENT_BIT
La plage mappée sera persistante. Nécessite également GL_MAP_COHERENT_BIT. Si ce bit est défini, alors glBufferStorage doit également avoir été appelé avec GL_MAP_PERSISTENT_BIT défini.
•GL_MAP_COHERENT_BIT
Les écritures dans la plage mappée seront cohérentes. Nécessite également GL_MAP_PERSISTENT_BIT. Si ce bit est défini, alors glBufferStorage doit également avoir été appelé avec GL_MAP_COHERENT_BIT défini.
•GL_MAP_INVALIDATE_RANGE_BIT
Le contenu de la plage mappée doit être ignoré. Toutes les écritures précédentes dans la plage seront ignorées.
•GL_MAP_INVALIDATE_BUFFER_BIT
Le contenu de tout le tampon doit être ignoré. Toutes les écritures précédentes dans le tampon seront ignorées.
•GL_MAP_FLUSH_EXPLICIT_BIT
Les écritures dans la plage mappée ne seront pas automatiquement envoyées au tampon. Les utilisateurs doivent appeler glFlushMappedBufferRange pour envoyer les modifications.
•GL_MAP_UNSYNCHRONIZED_BIT
Les écritures précédentes dans le tampon par le processeur graphique doivent être ignorées. Cela n'est valide que si le tampon a été mappé avec GL_MAP_PERSISTENT_BIT.

DESCRIPTION

glMapNamedBufferRange et glMapBufferRange mappent une plage spécifiée de la mémoire d'un tampon de mémoire de données dans l'espace d'adressage du processeur hôte, et renvoient un pointeur vers cette plage. Le pointeur est un pointeur de type void* vers les données du tampon.

Les données de la plage mappée peuvent être lues et/ou écrites en utilisant le pointeur renvoyé, en fonction des bits définis dans access. Les bits valides pour access sont GL_MAP_READ_BIT, GL_MAP_WRITE_BIT, GL_MAP_PERSISTENT_BIT, GL_MAP_COHERENT_BIT, GL_MAP_INVALIDATE_RANGE_BIT, GL_MAP_INVALIDATE_BUFFER_BIT, GL_MAP_FLUSH_EXPLICIT_BIT, et GL_MAP_UNSYNCHRONIZED_BIT.

Si length est zéro, alors glMapNamedBufferRange renvoie un pointeur non NULL sans mappé de mémoire. Si length n'est pas zéro, le décalage plus la longueur ne doivent pas dépasser la taille du tampon. Le décalage doit être un multiple de l'alignement minimal de mappage du tampon.

Si access contient GL_MAP_INVALIDATE_RANGE_BIT, cela indique que le contenu de la plage qui sera mappée est maintenant sans importance et peut être ignoré. Si access contient GL_MAP_INVALIDATE_BUFFER_BIT, cela indique que le contenu de tout le tampon est maintenant sans importance et peut être ignoré.

Si access contient GL_MAP_FLUSH_EXPLICIT_BIT, cela indique que les modifications apportées à la plage mappée ne seront pas automatiquement envoyées au tampon. Au lieu de cela, l'application doit appeler glFlushMappedBufferRange pour envoyer les modifications.

Si access contient GL_MAP_UNSYNCHRONIZED_BIT, cela indique que toute écriture précédente dans le tampon par le processeur graphique doit être ignorée. Cela n'est valable que si le tampon a été mappé avec GL_MAP_PERSISTENT_BIT.

Si le tampon est déjà dans un état mappé, un GL_INVALID_OPERATION sera généré.

Les modifications apportées à la plage mappée ne deviennent visibles au processeur graphique que lorsque le tampon est désimprimé avec glUnmapBuffer, ou lorsque glFlushMappedBufferRange est appelé (si GL_MAP_FLUSH_EXPLICIT_BIT a été spécifié).

Le pointeur renvoyé par glMapNamedBufferRange pointe vers les données du tampon dont le nom est buffer. Le pointeur renvoyé par glMapBufferRange pointe vers les données du tampon actuellement lié à la cible target.

Les mappages persistants sont plus performants car ils ne nécessitent pas de copie de données entre le noyau et l'espace utilisateur. Cependant, ils sont plus complexes à gérer.

NOTES

Les cibles GL_DISPATCH_INDIRECT_BUFFER et GL_SHADER_STORAGE_BUFFER sont acceptées uniquement si la version GL est 4.3 ou supérieure.

La cible GL_QUERY_BUFFER est disponible uniquement si la version GL est 4.4 ou supérieure.

Les indicateurs GL_MAP_PERSISTENT_BIT et GL_MAP_COHERENT_BIT sont disponibles uniquement si la version GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré par glMapBufferRange si target n'est pas l'une des cibles de liaison de tampon énumérées ci-dessus.

GL_INVALID_OPERATION est généré par glMapBufferRange si zéro est lié à target.

GL_INVALID_OPERATION est généré par glMapNamedBufferRange si buffer n'est pas le nom d'un objet tampon existant.

GL_INVALID_VALUE est généré si offset ou length est négatif, si $offset + length$ est supérieur à la valeur de GL_BUFFER_SIZE pour l'objet tampon, ou si access a des bits définis autres que ceux définis ci-dessus.

GL_INVALID_OPERATION est généré pour l'une des conditions suivantes :

•length est zéro.
•L'objet tampon est déjà dans un état mappé.
•Ni GL_MAP_READ_BIT ni GL_MAP_WRITE_BIT n'est défini.
•GL_MAP_READ_BIT est défini et l'un de GL_MAP_INVALIDATE_RANGE_BIT, GL_MAP_INVALIDATE_BUFFER_BIT ou GL_MAP_UNSYNCHRONIZED_BIT est défini.
•GL_MAP_FLUSH_EXPLICIT_BIT est défini et GL_MAP_WRITE_BIT n'est pas défini.
•L'un de GL_MAP_READ_BIT, GL_MAP_WRITE_BIT, GL_MAP_PERSISTENT_BIT, ou GL_MAP_COHERENT_BIT est défini, mais le même bit n'est pas inclus dans les indicateurs de stockage du tampon.

Aucune erreur n'est générée si la mémoire en dehors de la plage mappée est modifiée ou interrogée, mais le résultat est indéfini et des erreurs système (y compris potentiellement la terminaison du programme) peuvent survenir.

GETS ASSOCIÉS

glGet() avec pname GL_MIN_MAP_BUFFER_ALIGNMENT. La valeur doit être une puissance de deux supérieure ou égale à 64.
