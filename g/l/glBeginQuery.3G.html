NOM

glBeginQuery - délimite les frontières d'un objet requête

SPÉCIFICATION C

void glBeginQuery(GLenum target, GLuint id);

void glEndQuery(GLenum target);

PARAMÈTRES POUR GLBEGINQUERY

target

Spécifie le type de cible de l'objet requête établi entre glBeginQuery et le glEndQuery subséquent. La constante symbolique doit être l'un des GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED_CONSERVATIVE, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, ou GL_TIME_ELAPSED.

id

Spécifie le nom d'un objet requête.

PARAMÈTRES POUR GLENDQUERY

target

Spécifie le type de cible de l'objet requête à conclure. La constante symbolique doit être l'un des GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED_CONSERVATIVE, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, ou GL_TIME_ELAPSED.

DESCRIPTION

glBeginQuery et

glEndQuery délimitent les frontières d'un objet requête. query doit être un nom retourné précédemment par un appel à glGenQueries(). Si un objet requête avec le nom id n'existe pas encore, il est créé avec le type déterminé par target. target doit être l'un des GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, ou GL_TIME_ELAPSED. Le comportement de l'objet requête dépend de son type et est le suivant.

Si target est GL_SAMPLES_PASSED, id doit être un nom inutilisé, ou le nom d'un objet requête d'occlusion existant. Lorsque glBeginQuery est exécuté, le compteur d'échantillons ayant passé de l'objet requête est réinitialisé à 0. Le rendu ultérieur incrémentera le compteur pour chaque fragment qui passe le test de profondeur. Si la valeur de GL_SAMPLE_BUFFERS est 0, alors le compte d'échantillons ayant passé est incrémenté de 1 pour chaque fragment. Si la valeur de GL_SAMPLE_BUFFERS est 1, alors le compte d'échantillons ayant passé est incrémenté par le nombre d'échantillons dont le bit de couverture est défini. Cependant, les implémentations, à leur discrétion, peuvent plutôt augmenter le compte d'échantillons ayant passé par la valeur de GL_SAMPLES si un échantillon dans le fragment est couvert. Lorsque glEndQuery est exécuté, le compteur d'échantillons ayant passé est assigné à la valeur de résultat de l'objet requête. Cette valeur peut être interrogée en appelant glGetQueryObject() avec pname GL_QUERY_RESULT.

Si target est GL_ANY_SAMPLES_PASSED ou GL_ANY_SAMPLES_PASSED_CONSERVATIVE, id doit être un nom inutilisé, ou le nom d'un objet requête booléen d'occlusion existant. Lorsque glBeginQuery est exécuté, le drapeau d'échantillons ayant passé de l'objet requête est réinitialisé à GL_FALSE. Le rendu subséquent fait que le drapeau est mis à GL_TRUE si un échantillon passe le test de profondeur dans le cas de GL_ANY_SAMPLES_PASSED, ou si l'implémentation détermine qu'un échantillon pourrait passer le test de profondeur dans le cas de GL_ANY_SAMPLES_PASSED_CONSERVATIVE. L'implémentation peut être capable de fournir un test plus efficace dans le cas de GL_ANY_SAMPLES_PASSED_CONSERVATIVE si certains faux positifs sont acceptables pour l'application. Lorsque glEndQuery est exécuté, le drapeau d'échantillons ayant passé est assigné à la valeur de résultat de l'objet requête. Cette valeur peut être interrogée en appelant glGetQueryObject() avec pname GL_QUERY_RESULT.

Si target est GL_PRIMITIVES_GENERATED, id doit être un nom inutilisé, ou le nom d'un objet requête primitif existant précédemment associé à la liaison de requête GL_PRIMITIVES_GENERATED. Lorsque glBeginQuery est exécuté, le compteur de primitives générées de l'objet requête est réinitialisé à 0. Le rendu subséquent incrémentera le compteur une fois pour chaque sommet émis par le shader de géométrie, ou par le shader de sommets s'il n'y a pas de shader de géométrie. Lorsque glEndQuery est exécuté, le compteur de primitives générées est assigné à la valeur de résultat de l'objet requête. Cette valeur peut être interrogée en appelant glGetQueryObject() avec pname GL_QUERY_RESULT.

Si target est GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, id doit être un nom inutilisé, ou le nom d'un objet requête primitif existant précédemment associé à la liaison de requête GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN. Lorsque glBeginQuery est exécuté, le compteur de primitives écrites de l'objet requête est réinitialisé à 0. Le rendu subséquent incrémentera le compteur une fois pour chaque sommet écrit dans le(s) tampon(s) de retour de transformation lié(s). Si le mode de retour de transformation n'est pas activé entre l'appel à glBeginQuery et glEndQuery, le compteur ne sera pas incrémenté. Lorsque glEndQuery est exécuté, le compteur de primitives écrites est assigné à la valeur de résultat de l'objet requête. Cette valeur peut être interrogée en appelant glGetQueryObject() avec pname GL_QUERY_RESULT.

Si target est GL_TIME_ELAPSED, id doit être un nom inutilisé, ou le nom d'un objet requête de minuteur existant précédemment associé à la liaison de requête GL_TIME_ELAPSED. Lorsque glBeginQuery est exécuté, le compteur de temps de l'objet requête est réinitialisé à 0. Lorsque glEndQuery est exécuté, le temps serveur écoulé depuis l'appel à glBeginQuery est écrit dans le compteur de temps de l'objet requête. Cette valeur peut être interrogée en appelant glGetQueryObject() avec pname GL_QUERY_RESULT.

Interroger GL_QUERY_RESULT vide implicitement le pipeline GL jusqu'à ce que le rendu délimité par l'objet requête soit terminé et que le résultat soit disponible. GL_QUERY_RESULT_AVAILABLE peut être interrogé pour déterminer si le résultat est immédiatement disponible ou si le rendu n'est pas encore terminé.

NOTES

Si le compteur de la cible de requête dépasse la valeur maximale représentable dans le nombre de bits disponibles, tel que rapporté par glGetQueryiv() avec target défini sur la cible de requête appropriée et pname défini sur GL_QUERY_COUNTER_BITS, le compte devient indéfini.

Une implémentation peut supporter 0 bits dans son compteur, auquel cas les résultats des requêtes sont toujours indéfinis et essentiellement inutiles.

Lorsque GL_SAMPLE_BUFFERS est 0, le compteur d'échantillons ayant passé d'une requête d'occlusion s'incrémentera une fois pour chaque fragment qui passe le test de profondeur. Lorsque GL_SAMPLE_BUFFERS est 1, une implémentation peut soit incrémenter le compteur d'échantillons ayant passé individuellement pour chaque échantillon d'un fragment qui passe le test de profondeur, soit choisir d'incrémenter le compteur pour tous les échantillons d'un fragment si l'un d'eux passe le test de profondeur.

Les cibles de requête GL_ANY_SAMPLES_PASSED et GL_TIME_ELAPSED sont disponibles uniquement si la version de GL est 3.3 ou supérieure.

La cible de requête GL_ANY_SAMPLES_PASSED_CONSERVATIVE est disponible uniquement si la version de GL est 4.3 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré si target n'est pas l'un des tokens acceptés.

GL_INVALID_OPERATION est généré si glBeginQuery est exécuté alors qu'un objet requête du même target est déjà actif.

GL_INVALID_OPERATION est généré si

glEndQuery est exécuté lorsqu'un objet requête du même target n'est pas actif.

GL_INVALID_OPERATION est généré si id est 0.

GL_INVALID_OPERATION est généré si id est le nom d'un objet requête déjà actif.

GL_INVALID_OPERATION est généré si id fait référence à un objet requête existant dont le type ne correspond pas à target.
