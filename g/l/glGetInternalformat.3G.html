NOM

glGetInternalformat - récupérer des informations sur le support, dépendant de l'implémentation, des formats internes

SPÉCIFICATION C

void glGetInternalformativ(GLenumtarget, GLenuminternalformat, GLenumpname, GLsizeibufSize, GLint *params);

void glGetInternalformati64v(GLenumtarget, GLenuminternalformat, GLenumpname, GLsizeibufSize, GLint64 *params);

PARAMÈTRES

target

Indique l'utilisation du format interne. target doit être GL_TEXTURE_1D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_3D, GL_TEXTURE_CUBE_MAP, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_BUFFER, GL_RENDERBUFFER, GL_TEXTURE_2D_MULTISAMPLE ou GL_TEXTURE_2D_MULTISAMPLE_ARRAY.

internalformat

Spécifie le format interne pour lequel récupérer des informations.

pname

Spécifie le type d'information à interroger.

bufSize

Spécifie le nombre maximal d'entiers de la largeur spécifiée qui peuvent être écrits dans params par la fonction.

params

Spécifie l'adresse d'une variable dans laquelle écrire les informations récupérées.

DESCRIPTION

glGetInternalformativ et glGetInternalformati64v récupèrent des informations sur le support, dépendant de l'implémentation, des formats internes. target indique la cible avec laquelle le format interne sera utilisé et doit être l'une des suivantes : GL_RENDERBUFFER, GL_TEXTURE_2D_MULTISAMPLE, ou GL_TEXTURE_2D_MULTISAMPLE_ARRAY, correspondant respectivement à une utilisation comme tampon de rendu, texture multisample bidimensionnelle ou texture multisample de tableau bidimensionnelle.

internalformat spécifie le format interne pour lequel récupérer des informations et doit être un format rendable en couleur, en profondeur ou en stencil.

Les informations récupérées seront écrites en mémoire à l'adresse du pointeur spécifié dans params. Pas plus de bufSize entiers ne seront écrits dans cette mémoire.

Si pname est GL_NUM_SAMPLE_COUNTS, le nombre de décomptes d'échantillons qui seraient renvoyés par l'interrogation de GL_SAMPLES sera renvoyé dans params.

Si pname est GL_SAMPLES, les décomptes d'échantillons pris en charge pour internalformat et target sont écrits dans params par ordre numérique décroissant. Seules des valeurs positives sont renvoyées. Interroger GL_SAMPLES avec bufSize valant un renverra simplement le nombre maximal d'échantillons pris en charge pour ce format. La valeur maximale dans GL_SAMPLES est garantie d'être au moins égale au plus petit des éléments suivants :

•La valeur de GL_MAX_INTEGER_SAMPLES si internalformat est un format entier signé ou non signé.
•La valeur de GL_MAX_DEPTH_TEXTURE_SAMPLES si internalformat est un format rendable en profondeur ou en stencil et que target est GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY.
•La valeur de GL_MAX_COLOR_TEXTURE_SAMPLES si internalformat est un format rendable en couleur et que target est GL_TEXTURE_2D_MULTISAMPLE ou GL_TEXTURE_2D_MULTISAMPLE_ARRAY.
•La valeur de GL_MAX_SAMPLES.

Si pname est GL_INTERNALFORMAT_SUPPORTED, params est défini à GL_TRUE si internalformat est un format interne pris en charge pour target et à GL_FALSE dans le cas contraire.

Si pname est GL_INTERNALFORMAT_PREFERRED, params est défini à GL_TRUE si internalformat est un format pour target qui est préféré par l'implémentation et à GL_FALSE dans le cas contraire.

Si pname est GL_INTERNALFORMAT_RED_SIZE, GL_INTERNALFORMAT_GREEN_SIZE, GL_INTERNALFORMAT_BLUE_SIZE, GL_INTERNALFORMAT_ALPHA_SIZE, GL_INTERNALFORMAT_DEPTH_SIZE, GL_INTERNALFORMAT_STENCIL_SIZE, ou GL_INTERNALFORMAT_SHARED_SIZE alors params est défini aux résolutions réelles qui seraient utilisées pour stocker les composants du tableau d'images de la ressource pour les canaux rouge, vert, bleu, alpha, profondeur, stencil et partagé respectivement. Si internalformat est un format interne compressé, alors params est défini à la résolution de composant d'un format interne non compressé qui produit une image de qualité approximativement équivalente à celle de l'algorithme de compression. Si le format interne n'est pas pris en charge, ou si un composant particulier n'est pas présent dans le format, 0 est écrit dans params.

Si pname est GL_INTERNALFORMAT_RED_TYPE, GL_INTERNALFORMAT_GREEN_TYPE, GL_INTERNALFORMAT_BLUE_TYPE, GL_INTERNALFORMAT_ALPHA_TYPE, GL_INTERNALFORMAT_DEPTH_TYPE, ou GL_INTERNALFORMAT_STENCIL_TYPE alors params est défini à un jeton identifiant le type de données utilisé pour stocker le composant respectif. Si le internalformat représente un format interne compressé, alors les types renvoyés spécifient comment les composants sont interprétés après la décompression.

Si pname est GL_MAX_WIDTH, GL_MAX_HEIGHT, GL_MAX_DEPTH, ou GL_MAX_LAYERS alors pname est rempli avec la largeur, hauteur, profondeur ou le nombre de couches maximal respectivement pour les textures avec le format interne internalformat. Si pname est GL_MAX_COMBINED_DIMENSIONS alors pname est rempli avec les dimensions combinées maximales d'une texture du format interne spécifié.

Si pname est GL_COLOR_COMPONENTS alors params est défini à la valeur GL_TRUE si le format interne contient un composant de couleur (c.-à-d. rouge, vert, bleu ou alpha) et à GL_FALSE dans le cas contraire. Si pname est GL_DEPTH_COMPONENTS ou GL_STENCIL_COMPONENTS alors params est défini à GL_TRUE si le format interne contient respectivement un composant de profondeur ou de stencil, et à GL_FALSE dans le cas contraire.

Si pname est GL_COLOR_RENDERABLE, GL_DEPTH_RENDERABLE ou GL_STENCIL_RENDERABLE alors params est défini à GL_TRUE si le format interne spécifié est respectivement rendable en couleur, en profondeur ou en stencil, et à GL_FALSE dans le cas contraire.

Si pname est GL_FRAMEBUFFER_RENDERABLE ou GL_FRAMEBUFFER_RENDERABLE_LAYERED alors params est défini à l'une des valeurs GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT ou GL_NONE pour indiquer que les attaches de framebuffer (attaches en couches dans le cas de GL_FRAMEBUFFER_RENDERABLE_LAYERED) avec ce format interne sont soit rendables sans aucune restriction, rendables avec certaines restrictions, ou pas du tout rendables.

Si pname est GL_FRAMEBUFFER_BLEND, params est défini à GL_TRUE pour indiquer que le format interne est pris en charge pour les opérations de mélange lorsqu'il est attaché à un framebuffer, et à GL_FALSE dans le cas contraire.

Si pname est GL_READ_PIXELS alors params est défini à GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT ou GL_NONE pour indiquer que soit un support complet, un support limité, ou aucun support n'est fourni pour la lecture des pixels à partir des attaches de framebuffer dans le format interne spécifié.

Si pname est GL_READ_PIXELS_FORMAT ou GL_READ_PIXELS_TYPE alors params est rempli avec le format ou le type respectivement le plus recommandé pour obtenir la meilleure qualité d'image et les meilleures performances. Pour GL_READ_PIXELS_FORMAT, la valeur renvoyée dans params est un jeton accepté pour l'argument format de glReadPixels(). Pour GL_READ_PIXELS_TYPE, la valeur renvoyée dans params est un jeton accepté pour l'argument type de glReadPixels().

Si pname est GL_TEXTURE_IMAGE_FORMAT ou GL_TEXTURE_IMAGE_TYPE alors params est rempli avec le format ou le type recommandé par l'implémentation à utiliser dans les appels à glTexImage2D() et autres fonctions similaires. Pour GL_TEXTURE_IMAGE_FORMAT, params est rempli d'un jeton approprié pour être utilisé comme argument format de glTexImage2D(). Pour GL_TEXTURE_IMAGE_TYPE, params est rempli d'un jeton approprié pour être utilisé comme argument type de glTexImage2D().

<p class="Pp">Si pname est GL_GET_TEXTURE_IMAGE_FORMAT ou GL_GET_TEXTURE_IMAGE_TYPE alors params est rempli avec le format ou le type recommandé par l'implémentation à utiliser dans les appels à glGetTexImage() et autres fonctions similaires. Pour GL_GET_TEXTURE_IMAGE_FORMAT, params est rempli avec un jeton adapté pour être utilisé comme argument format de glGetTexImage(). Pour GL_GET_TEXTURE_IMAGE_TYPE, params est rempli avec un jeton adapté pour être utilisé comme argument type de glGetTexImage().

Si pname est GL_MIPMAP alors pname est défini à GL_TRUE pour indiquer que le format interne spécifié prend en charge les mipmaps, et à GL_FALSE sinon.

Si pname est GL_GENERATE_MIPMAP ou GL_AUTO_GENERATE_MIPMAP alors params indique le niveau de prise en charge de la génération manuelle ou automatique de mipmaps pour le format interne spécifié, respectivement. Les valeurs retournées peuvent être l'une des suivantes GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT et GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge.

Si pname est GL_COLOR_ENCODING alors l'encodage couleur de la ressource est retourné dans params. Les valeurs possibles pour les tampons de couleur sont GL_LINEAR ou GL_SRGB, pour les composantes de couleur linéaires ou encodées sRGB, respectivement. Pour les formats non couleur (tels que la profondeur ou le stencil), ou pour les ressources non prises en charge, la valeur GL_NONE est retournée.

Si pname est GL_SRGB_READ, ou GL_SRGB_WRITE alors params indique le niveau de prise en charge de la lecture et de l'écriture d'images encodées sRGB, respectivement. Pour GL_SRGB_READ, la prise en charge de la conversion depuis l'espace colorimétrique sRGB lors des opérations de lecture est retournée dans params et pour GL_SRGB_WRITE, la prise en charge de la conversion vers l'espace colorimétrique sRGB lors des opérations d'écriture sur la ressource est retournée dans params. params peut être défini à GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge, respectivement.

Si pname est GL_FILTER alors params est défini à soit GL_TRUE ou GL_FALSE pour indiquer la prise en charge ou l'absence de prise en charge des modes de filtrage autres que GL_NEAREST ou GL_NEAREST_MIPMAP pour le format interne spécifié.

Si pname est GL_VERTEX_TEXTURE, GL_TESS_CONTROL_TEXTURE, GL_TESS_EVALUATION_TEXTURE, GL_GEOMETRY_TEXTURE, GL_FRAGMENT_TEXTURE, ou GL_COMPUTE_TEXTURE, alors la valeur écrite dans params indique la prise en charge de l'utilisation de la ressource comme source de texturation dans les étages de shader de vertex, de contrôle de tessellation, d'évaluation de tessellation, de géométrie, de fragment et de calcul, respectivement. params peut être défini à GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge, respectivement.

Si pname est GL_TEXTURE_SHADOW, GL_TEXTURE_GATHER ou GL_TEXTURE_GATHER_SHADOW alors la valeur écrite dans params indique le niveau de prise en charge de l'utilisation de la ressource avec un échantillonneur d'ombres, dans les opérations de collecte ou comme échantillonneur d'ombres dans les opérations de collecte, respectivement. Les valeurs retournées peuvent être GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge, respectivement.

Si pname est GL_SHADER_IMAGE_LOAD, GL_SHADER_IMAGE_STORE ou GL_SHADER_IMAGE_ATOMIC alors la valeur retournée dans params indique le niveau de prise en charge des chargements d'images, des stockages et des opérations atomiques pour les ressources du format interne spécifié. Les valeurs retournées peuvent être GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge du tout, respectivement.

Si pname est GL_IMAGE_TEXEL_SIZE alors la taille d'un texel lorsque la ressource est utilisée comme texture d'image est retournée dans params. Si la ressource n'est pas prise en charge pour les textures d'image, zéro est retourné.

Si pname est GL_IMAGE_COMPATIBILITY_CLASS alors la classe de compatibilité de la ressource lorsqu'elle est utilisée comme texture d'image est retournée dans params. Les valeurs possibles retournées sont GL_IMAGE_CLASS_4_X_32, GL_IMAGE_CLASS_2_X_32, GL_IMAGE_CLASS_1_X_32, GL_IMAGE_CLASS_4_X_16, GL_IMAGE_CLASS_2_X_16, GL_IMAGE_CLASS_1_X_16, GL_IMAGE_CLASS_4_X_8, GL_IMAGE_CLASS_2_X_8, GL_IMAGE_CLASS_1_X_8, GL_IMAGE_CLASS_11_11_10, et GL_IMAGE_CLASS_10_10_10_2, qui correspondent aux formats 4x32, 2x32, 1x32, 4x16, 2x16, 1x16, 4x8, 2x8, 1x8, la classe (a) 11/11/10 format flottant compacté, et la classe (b) 10/10/10/2 formats compactés, respectivement. Si la ressource n'est pas prise en charge pour les textures d'image, GL_NONE est retourné.

Si pname est GL_IMAGE_PIXEL_FORMAT ou GL_IMAGE_PIXEL_TYPE alors le format ou le type de pixel de la ressource lorsqu'elle est utilisée comme texture d'image est retourné dans params, respectivement. Dans les deux cas, si la ressource n'est pas prise en charge pour les textures d'image GL_NONE est retourné.

Si pname est GL_IMAGE_FORMAT_COMPATIBILITY_TYPE, les critères de correspondance utilisés pour la ressource lorsqu'elle est utilisée comme texture d'image sont retournés dans params. Les valeurs possibles retournées dans params sont GL_IMAGE_FORMAT_COMPATIBILITY_BY_SIZE ou GL_IMAGE_FORMAT_COMPATIBILITY_BY_CLASS. Si la ressource n'est pas prise en charge pour les textures d'image, GL_NONE est retourné.

Si pname est GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_TEST ou GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_TEST, la prise en charge de l'utilisation de la ressource à la fois comme source pour l'échantillonnage de texture tout en étant liée comme tampon pour le test de profondeur ou de stencil, respectivement, est écrite dans params. Les valeurs possibles retournées sont GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge. Si la ressource ou l'opération n'est pas prise en charge, GL_NONE est retourné.

Si pname est GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_WRITE ou GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_WRITE, la prise en charge de l'utilisation de la ressource à la fois comme source pour l'échantillonnage de texture tout en effectuant des écritures de profondeur ou de stencil sur les ressources, respectivement, est écrite dans params. Les valeurs possibles retournées sont GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge. Si la ressource ou l'opération n'est pas prise en charge, GL_NONE est retourné.

Si pname est GL_TEXTURE_COMPRESSED alors GL_TRUE est retourné dans params si internalformat est un format interne compressé. GL_FALSE est retourné dans params sinon.

Si pname est GL_TEXTURE_COMPRESSED_BLOCK_WIDTH, GL_TEXTURE_COMPRESSED_BLOCK_HEIGHT ou GL_TEXTURE_COMPRESSED_BLOCK_SIZE alors la largeur, la hauteur ou la taille totale, respectivement, d'un bloc (en unités machine de base) est retournée dans params. Si le format interne n'est pas compressé, ou si la ressource n'est pas prise en charge, 0 est retourné.

Si pname est GL_CLEAR_BUFFER, le niveau de prise en charge de l'utilisation de la ressource avec glClearBufferData() et glClearBufferSubData() est retourné dans params. Les valeurs possibles retournées sont GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge du tout, respectivement. Si la ressource ou l'opération n'est pas prise en charge, GL_NONE est retourné.

Si pname est GL_TEXTURE_VIEW, le niveau de prise en charge de l'utilisation de la ressource avec la commande glTextureView() est retourné dans params. Les valeurs possibles retournées sont GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge, respectivement. Si la ressource ou l'opération n'est pas prise en charge, GL_NONE est retourné.

Si pname est GL_VIEW_COMPATIBILITY_CLASS alors la classe de compatibilité de la ressource lorsqu'elle est utilisée comme vue de texture est retournée dans params. Les valeurs possibles retournées sont GL_VIEW_CLASS_128_BITS, GL_VIEW_CLASS_96_BITS, GL_VIEW_CLASS_64_BITS, GL_VIEW_CLASS_48_BITS, GL_VIEW_CLASS_32_BITS, GL_VIEW_CLASS_24_BITS, GL_VIEW_CLASS_16_BITS, GL_VIEW_CLASS_8_BITS, GL_VIEW_CLASS_S3TC_DXT1_RGB, GL_VIEW_CLASS_S3TC_DXT1_RGBA, GL_VIEW_CLASS_S3TC_DXT3_RGBA, GL_VIEW_CLASS_S3TC_DXT5_RGBA, GL_VIEW_CLASS_RGTC1_RED, GL_VIEW_CLASS_RGTC2_RG, GL_VIEW_CLASS_BPTC_UNORM, et GL_VIEW_CLASS_BPTC_FLOAT.

Si pname est GL_CLEAR_TEXTURE alors la présence de prise en charge de l'utilisation des commandes glClearTexImage() et glClearTexSubImage() avec la ressource est écrite dans params. Les valeurs possibles écrites sont GL_FULL_SUPPORT, GL_CAVEAT_SUPPORT, ou GL_NONE pour indiquer une prise en charge complète, limitée ou aucune prise en charge, respectivement. Si la ressource ou l'opération n'est pas prise en charge, GL_NONE est retourné.

NOTES

NAME

glGetInternalformat - query information about internal texel data formats

C SPECIFICATION

    GLboolean glIsRenderable(GLenum texture);
    void glGetInternalformativ(GLenum target, GLenum internalformat, GLenum pname, GLsizei bufSize, GLint* params);
    void glGetInternalformati64v(GLenum target, GLenum internalformat, GLenum pname, GLsizei bufSize, GLint64* params);

PARAMETERS

target
Specifies the renderable buffer target. It must be GL_RENDERBUFFER, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, or GL_TEXTURE_RECTANGLE.
internalformat
Specifies the internal format of the texture or renderbuffer to query.
pname
Specifies the symbolic name of the query. The symbolic names that query for values of type GLint are GL_INTERNALFORMAT_SUPPORTED, GL_INTERNALFORMAT_RED_SIZE, GL_INTERNALFORMAT_GREEN_SIZE, GL_INTERNALFORMAT_BLUE_SIZE, GL_INTERNALFORMAT_ALPHA_SIZE, GL_INTERNALFORMAT_DEPTH_SIZE, GL_INTERNALFORMAT_STENCIL_SIZE, GL_INTERNALFORMAT_SHARED_SIZE, GL_INTERNALFORMAT_RED_TYPE, GL_INTERNALFORMAT_GREEN_TYPE, GL_INTERNALFORMAT_BLUE_TYPE, GL_INTERNALFORMAT_ALPHA_TYPE, GL_INTERNALFORMAT_ATTENUATION_TYPE, GL_INTERNALFORMAT_DOUBLE_EXT_TYPE, GL_INTERNALFORMAT_COLOR_COMPONENTS, GL_INTERNALFORMAT_COLOR_BITS, GL_INTERNALFORMAT_DEPTH_TYPE, GL_INTERNALFORMAT_STENCIL_TYPE, GL_INTERNALFORMAT_SAMPLE_COUNT, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ETC2, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ETC2_ALPHA, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ASTC, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ASTC_ALPHA, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_BPTC, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_BPTC_ALPHA, GL_IMAGE_COMPATIBILITY_CLASS, GL_GL_IMAGE_PIXEL_FORMAT, GL_GL_IMAGE_PIXEL_TYPE, GL_GL_IMAGE_FORMAT_COMPATIBILITY_TYPE, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_TEST, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_TEST, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_WRITE, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_WRITE, GL_TEXTURE_COMPRESSED, GL_TEXTURE_COMPRESSED_BLOCK_WIDTH, GL_TEXTURE_COMPRESSED_BLOCK_HEIGHT, GL_TEXTURE_COMPRESSED_BLOCK_SIZE, GL_CLEAR_BUFFER, GL_TEXTURE_VIEW, and GL_VIEW_COMPATIBILITY_CLASS. The symbolic names that query for values of type GLint64 are GL_INTERNALFORMAT_RED_SIZE64, GL_INTERNALFORMAT_GREEN_SIZE64, GL_INTERNALFORMAT_BLUE_SIZE64, GL_INTERNALFORMAT_ALPHA_SIZE64, GL_INTERNALFORMAT_DEPTH_SIZE64, GL_INTERNALFORMAT_STENCIL_SIZE64, GL_INTERNALFORMAT_SHARED_SIZE64, GL_INTERNALFORMAT_COLOR_COMPONENTS64, GL_INTERNALFORMAT_COLOR_BITS64.
bufSize
Specifies the size of the array pointed to by params.
params
Returns the requested data.

DESCRIPTION

glGetInternalformativ and glGetInternalformati64v query implementation-dependent values associated with a renderable format. The format can be specified by internalformat, which must be a valid internal format for the specified target.

The target parameter must be one of GL_RENDERBUFFER, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, or GL_TEXTURE_RECTANGLE.

If target is GL_RENDERBUFFER, the query is for renderbuffer objects. If target is a texture target, the query is for texture objects.

The pname parameter specifies the type of information to query.

GL_INTERNALFORMAT_SUPPORTED: Returns a single integer indicating whether the internalformat is supported for the specified target. If supported, a 1 is returned; otherwise, a 0 is returned.

GL_INTERNALFORMAT_RED_SIZE, GL_INTERNALFORMAT_GREEN_SIZE, GL_INTERNALFORMAT_BLUE_SIZE, GL_INTERNALFORMAT_ALPHA_SIZE, GL_INTERNALFORMAT_DEPTH_SIZE, GL_INTERNALFORMAT_STENCIL_SIZE, GL_INTERNALFORMAT_SHARED_SIZE: Return the number of bits used by the red, green, blue, alpha, depth, stencil, or shared components, respectively, of the specified internalformat.

GL_INTERNALFORMAT_RED_TYPE, GL_INTERNALFORMAT_GREEN_TYPE, GL_INTERNALFORMAT_BLUE_TYPE, GL_INTERNALFORMAT_ALPHA_TYPE: Return the data type used for the red, green, blue, or alpha components, respectively. The possible return values are GL_NONE, GL_UNSIGNED_NORMALIZED, GL_SIGNED_NORMALIZED, GL_FLOAT, GL_INT, GL_UINT, GL_HALF_FLOAT, GL_FIXED.

GL_INTERNALFORMAT_DEPTH_TYPE, GL_INTERNALFORMAT_STENCIL_TYPE: Return the data type used for the depth or stencil components, respectively. The possible return values are GL_NONE, GL_FLOAT, GL_INT, GL_UINT, GL_HALF_FLOAT, GL_FIXED.

GL_INTERNALFORMAT_COLOR_COMPONENTS: Returns the number of color-renderable components in the internalformat. This may be less than the number of components in the format if some components are not color-renderable.

GL_INTERNALFORMAT_COLOR_BITS: Returns the total number of bits in the color-renderable components of the internalformat.

GL_INTERNALFORMAT_SAMPLE_COUNT: Returns an array of integers specifying the supported number of samples for multisample textures or renderbuffers with the specified internalformat. The query returns a list of integers, terminated by zero. For example, if multisample textures support 2, 4, and 8 samples, the array returned would be [2, 4, 8, 0].

GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ETC2, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ETC2_ALPHA, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ASTC, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_ASTC_ALPHA, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_BPTC, GL_INTERNALFORMAT_VIEW_CLASS_FORMAT_BPTC_ALPHA: Returns a symbolic constant representing the view class of the specified compressed format. See "Texture Objects" in the OpenGL specification for a list of view classes.

GL_IMAGE_COMPATIBILITY_CLASS, GL_GL_IMAGE_PIXEL_FORMAT, GL_GL_IMAGE_PIXEL_TYPE, GL_GL_IMAGE_FORMAT_COMPATIBILITY_TYPE, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_TEST, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_TEST, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_WRITE, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_WRITE, GL_TEXTURE_COMPRESSED, GL_TEXTURE_COMPRESSED_BLOCK_WIDTH, GL_TEXTURE_COMPRESSED_BLOCK_HEIGHT, GL_TEXTURE_COMPRESSED_BLOCK_SIZE, GL_CLEAR_BUFFER, GL_TEXTURE_VIEW, and GL_VIEW_COMPATIBILITY_CLASS: These tokens query properties related to image load/store operations, texture views, and texture compression. Refer to the OpenGL specification for detailed descriptions of each.

The 64-bit variants (e.g., GL_INTERNALFORMAT_RED_SIZE64) return the same information as their 32-bit counterparts but as 64-bit integers. This is primarily useful for formats that might exceed the range of a 32-bit integer, although this is unlikely for component sizes.

NOTES

The tokens GL_IMAGE_COMPATIBILITY_CLASS, GL_GL_IMAGE_PIXEL_FORMAT, GL_GL_IMAGE_PIXEL_TYPE, GL_GL_IMAGE_FORMAT_COMPATIBILITY_TYPE, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_TEST, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_TEST, GL_SIMULTANEOUS_TEXTURE_AND_DEPTH_WRITE, GL_SIMULTANEOUS_TEXTURE_AND_STENCIL_WRITE, GL_TEXTURE_COMPRESSED, GL_TEXTURE_COMPRESSED_BLOCK_WIDTH, GL_TEXTURE_COMPRESSED_BLOCK_HEIGHT, GL_TEXTURE_COMPRESSED_BLOCK_SIZE, GL_CLEAR_BUFFER, GL_TEXTURE_VIEW, and GL_VIEW_COMPATIBILITY_CLASS are supported only if the GL version is 4.3 or higher.

The GL_CLEAR_TEXTURE token is accepted for pname only if the GL version is 4.4 or higher.

ERRORS

GL_INVALID_VALUE is generated if bufSize is negative.

GL_INVALID_ENUM is generated if pname is not GL_SAMPLES or GL_NUM_SAMPLE_COUNTS.

GL_INVALID_ENUM is generated if internalformat is not color-, depth-, or stencil-renderable.

GL_INVALID_ENUM is generated if target is not one of GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY or GL_RENDERBUFFER.
