glLinkProgram lie l'objet programme spécifié par program. Si des objets shader de type GL_VERTEX_SHADER sont attachés à program, ils seront utilisés pour créer un exécutable qui s'exécutera sur le processeur de sommets programmable. Cette valeur sera définie à GL_TRUE si l'objet programme a été lié sans erreurs et est prêt à être utilisé, et GL_FALSE sinon. indéfinis.

NAME

glLinkProgram — link a program object

C SPECIFICATION

void glLinkProgram(GLuint program );

PARAMETERS

program

Specifies the handle of the program object to be linked.

DESCRIPTION

glLinkProgram links the specified program object. Linking is the process of combining shader objects that have been attached to a program object into a form that can be executed by the OpenGL pipeline.

A program object is a container for shader objects. Shaders are first attached to a program object using glAttachShader. Then, glLinkProgram is called to link the attached shaders. After linking, the program object is ready to be used for rendering. If the program object has already been linked, calling glLinkProgram will cause it to be re-linked. If the program object is currently in use (i.e. it has been made part of the current rendering state using glUseProgram), linking will fail, and an error will be generated.

The linking process requires that the attached shaders are compiled. If any of the attached shaders have not been compiled, linking will fail and an error will be generated.

The linking process itself is asynchronous. When glLinkProgram returns, the linking operation may not have completed. However, the program object is guaranteed to be in a usable state (either successfully linked or failed to link). Querying the link status using glGetProgramiv with the argument GL_LINK_STATUS will block until the linking operation is completed.

After linking, the program object is considered to be in a linked state. The link status can be queried using glGetProgramiv with the argument GL_LINK_STATUS. If the linking was successful, the status will be GL_TRUE. Otherwise, it will be GL_FALSE. If the linking failed, the error log can be retrieved using glGetProgramInfoLog.

If the linking operation fails, the program object will be left in an invalid state. It can be reset to a valid state by calling glDeleteProgram and then recreated.

The program object may contain uniforms. The values of uniforms are not affected by linking. However, if the program object is being used for rendering, any uniforms that have been modified since the last link operation will be reset to their default values.

After a program object has been linked, any previously attached shader objects can be detached using glDetachShader, and then deleted using glDeleteShader.

NOTES

The linking process can be computationally expensive. If a program object is linked frequently, it may be beneficial to cache the program object and reuse it.

The maximum number of simultaneously linked program objects is implementation-dependent and can be queried using glGetIntegerv with the argument GL_MAX_PROGRAM_OBJECTS.

ERRORS

GL_INVALID_HANDLE is generated if the value of program is not a valid program object.

GL_INVALID_OPERATION is generated if the program object specified by program is currently in use by glUseProgram.

GL_INVALID_OPERATION is generated if any of the shader objects attached to program have not been compiled.
