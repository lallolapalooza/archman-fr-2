NOM

glCompressedTexImage2D - spécifie une image de texture bidimensionnelle dans un format compressé

SPÉCIFICATION C

void glCompressedTexImage2D(GLenumtarget, GLintlevel, GLenuminternalformat, GLsizeiwidth, GLsizeiheight, GLintborder, GLsizeiimageSize, const void *data);

PARAMÈTRES

target

Spécifie la texture cible. Doit être GL_TEXTURE_2D, GL_PROXY_TEXTURE_2D, GL_TEXTURE_1D_ARRAY, GL_PROXY_TEXTURE_1D_ARRAY, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, ou GL_PROXY_TEXTURE_CUBE_MAP.

level

Spécifie le numéro de niveau de détail. Le niveau 0 est le niveau de l'image de base. Le niveau n est la nièmeimage de réduction de la mipmap.

internalformat

Spécifie le format des données d'image compressées stockées à l'adresse data.

width

Spécifie la largeur de l'image de texture. Toutes les implémentations prennent en charge les images de texture 2D et les images de texture de cube map d'au moins 16384 texels de large.

height

Spécifie la hauteur de l'image de texture. Toutes les implémentations prennent en charge les images de texture 2D et les images de texture de cube map d'au moins 16384 texels de haut.

border

Cette valeur doit être 0.

imageSize

Spécifie le nombre d'octets non signés de données d'image commençant à l'adresse spécifiée par data.

data

Spécifie un pointeur vers les données d'image compressées en mémoire.

DESCRIPTION

Le texturing permet aux éléments d'un tableau d'images d'être lus par les shaders.

glCompressedTexImage2D charge une image de texture bidimensionnelle compressée définie et récupérée précédemment si target est GL_TEXTURE_2D, ou l'une des faces de la cube map telle que GL_TEXTURE_CUBE_MAP_POSITIVE_X. (voir glTexImage2D()).

Si target est GL_TEXTURE_1D_ARRAY, data est traité comme un tableau de textures 1D compressées.

Si target est GL_PROXY_TEXTURE_2D, GL_PROXY_TEXTURE_1D_ARRAY ou GL_PROXY_TEXTURE_CUBE_MAP, aucune donnée n'est lue depuis data, mais tout l'état de l'image de texture est recalculé, vérifié pour la cohérence, et comparé aux capacités de l'implémentation. Si l'implémentation ne peut pas gérer une texture de la taille demandée, elle définit tout l'état de l'image à 0, mais ne génère pas d'erreur (voir glGetError()). Pour interroger un tableau de mipmap entier, utilisez un niveau de tableau d'image supérieur ou égal à 1.

internalformat doit être un format d'image compressé connu (tel que GL_RGTC) ou un format de texture compressé spécifié par une extension. Lorsqu'une texture est chargée avec glTexImage2D() en utilisant un format de texture compressé générique (par exemple, GL_COMPRESSED_RGB), le GL sélectionne parmi ses extensions prenant en charge les textures compressées. Afin de charger l'image de texture compressée en utilisant glCompressedTexImage2D, interrogez la taille et le format de l'image de texture compressée en utilisant glGetTexLevelParameter().

Si un objet tampon nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER (voir glBindBuffer()) lorsqu'une image de texture est spécifiée, data est traité comme un décalage en octets dans le magasin de données de l'objet tampon.

Si les données compressées sont organisées en blocs de taille fixe de texels, les modes de stockage de pixels peuvent être utilisés pour sélectionner un sous-rectangle à partir d'un rectangle conteneur plus grand. Ces modes de stockage de pixels fonctionnent de la même manière que pour glTexImage2D(). Dans la description suivante, désignons par bs, bw, bh et bd les valeurs des modes de stockage de pixels GL_UNPACK_COMPRESSED_BLOCK_SIZE, GL_UNPACK_COMPRESSED_BLOCK_WIDTH, GL_UNPACK_COMPRESSED_BLOCK_HEIGHT, et GL_UNPACK_COMPRESSED_BLOCK_DEPTH, respectivement. bs est la taille du bloc compressé en octets ; bw, bh et bd sont la largeur, la hauteur et la profondeur du bloc compressé en pixels.

Par défaut, les modes de stockage de pixels GL_UNPACK_ROW_LENGTH, GL_UNPACK_SKIP_ROWS, GL_UNPACK_SKIP_PIXELS, GL_UNPACK_IMAGE_HEIGHT et GL_UNPACK_SKIP_IMAGES sont ignorés pour les images compressées. Pour activer GL_UNPACK_SKIP_PIXELS et GL_UNPACK_ROW_LENGTH, bs et bw doivent tous deux être non nuls. Pour activer également GL_UNPACK_SKIP_ROWS et GL_UNPACK_IMAGE_HEIGHT, bh doit être non nul. Pour activer également GL_UNPACK_SKIP_IMAGES, bd doit être non nul. Tous les paramètres doivent être cohérents avec le format compressé pour produire les résultats souhaités.

Lors de la sélection d'un sous-rectangle à partir d'une image compressée :

•La valeur de GL_UNPACK_SKIP_PIXELS doit être un multiple de bw ;
•la valeur de GL_UNPACK_SKIP_ROWS doit être un multiple de bw.

imageSize doit être égal à :

b s × width b w × height b h

REMARQUES

Les formats internes compressés spécifiques GL_COMPRESSED_RGB8_ETC2, GL_COMPRESSED_SRGB8_ETC2, GL_COMPRESSED_RGB8_PUNCHTHROUGH_ALPHA1_ETC2, GL_COMPRESSED_SRGB8_PUNCHTHROUGH_ALPHA1_ETC2, GL_COMPRESSED_RGBA8_ETC2_EAC, GL_COMPRESSED_SRGB8_ALPHA8_ETC2_EAC, GL_COMPRESSED_R11_EAC, GL_COMPRESSED_SIGNED_R11_EAC, GL_COMPRESSED_RG11_EAC, et GL_COMPRESSED_SIGNED_RG11_EAC ne sont disponibles que si la version du GL est 4.3 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré si internalformat n'est pas l'un des formats internes compressés spécifiques : GL_COMPRESSED_RED_RGTC1, GL_COMPRESSED_SIGNED_RED_RGTC1, GL_COMPRESSED_RG_RGTC2, GL_COMPRESSED_SIGNED_RG_RGTC2. GL_COMPRESSED_RGBA_BPTC_UNORM, GL_COMPRESSED_SRGB_ALPHA_BPTC_UNORM, GL_COMPRESSED_RGB_BPTC_SIGNED_FLOAT, GL_COMPRESSED_RGB_BPTC_UNSIGNED_FLOAT, GL_COMPRESSED_RGB8_ETC2, GL_COMPRESSED_SRGB8_ETC2, GL_COMPRESSED_RGB8_PUNCHTHROUGH_ALPHA1_ETC2, GL_COMPRESSED_SRGB8_PUNCHTHROUGH_ALPHA1_ETC2, GL_COMPRESSED_RGBA8_ETC2_EAC, GL_COMPRESSED_SRGB8_ALPHA8_ETC2_EAC, GL_COMPRESSED_R11_EAC, GL_COMPRESSED_SIGNED_R11_EAC, GL_COMPRESSED_RG11_EAC, ou GL_COMPRESSED_SIGNED_RG11_EAC.

GL_INVALID_VALUE est généré si imageSize n'est pas cohérent avec le format, les dimensions et le contenu des données d'image compressées spécifiées.

GL_INVALID_VALUE est généré si border n'est pas 0.

GL_INVALID_OPERATION est généré si les combinaisons de paramètres ne sont pas prises en charge par le format interne compressé spécifique tel que spécifié dans l'extension de compression de texture spécifique.

GL_INVALID_OPERATION est généré si un nom d'objet tampon non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et si le magasin de données de l'objet tampon est actuellement mappé.

GL_INVALID_OPERATION est généré si un nom d'objet tampon non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et si les données seraient décompactées depuis l'objet tampon de telle sorte que les lectures mémoire requises dépasseraient la taille du magasin de données.

Des résultats indéfinis, y compris une terminaison anormale du programme, sont générés si data n'est pas encodé d'une manière cohérente avec la spécification de l'extension définissant le format de compression interne.
