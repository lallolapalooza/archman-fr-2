NOM

glutPostOverlayRedisplay, glutPostWindowOverlayRedisplay - marque la superposition de la fenêtre actuelle ou spécifiée comme devant être redessinée.

AVERTISSEMENT

Pas encore implémenté dans freeglut.

SYNTAXE

void glutPostOverlayRedisplay(void);
void glutPostWindowOverlayRedisplay(int win);

DESCRIPTION

Marque la superposition de la fenêtre actuelle comme devant être redessinée. Lors de la prochaine itération de glutMainLoop, la fonction de rappel d'affichage de la superposition de la fenêtre (ou simplement la fonction de rappel d'affichage si aucune fonction de rappel d'affichage de la superposition n'est enregistrée) sera appelée pour redessiner le plan de superposition de la fenêtre. Plusieurs appels à glutPostOverlayRedisplay avant la prochaine opportunité de fonction de rappel d'affichage (ou d'affichage de superposition si l'une est enregistrée) génèrent un seul redessinage. glutPostOverlayRedisplay peut être appelé dans une fonction de rappel d'affichage ou d'affichage de superposition pour marquer à nouveau cette fenêtre pour le redessinage.

Logiquement, la notification de dommage de superposition pour une fenêtre est traitée comme un glutPostOverlayRedisplay sur la fenêtre endommagée. Contrairement aux dommages signalés par le système de fenêtrage, glutPostOverlayRedisplay ne mettra pas la propriété de superposition endommagée (renvoyée par glutLayerGet(GLUT_OVERLAY_DAMAGED)) à vrai.

Si la fenêtre sur laquelle vous souhaitez poster un redessinage de superposition n'est pas déjà courante (et vous n'exigez pas qu'elle le devienne immédiatement), utiliser glutPostWindowOverlayRedisplay est plus efficace que d'appeler glutSetWindow vers la fenêtre désirée puis d'appeler glutPostOverlayRedisplay.

EXEMPLE

Si vous effectuez un effet interactif comme le « rubberbanding » dans la superposition, il est conseillé de structurer votre rendu pour minimiser le scintillement (la plupart des superpositions sont en simple buffer). Effacez la superposition uniquement si vous savez que la fenêtre a été endommagée. Sinon, essayez simplement d'effacer ce que vous avez dessiné en dernier et redessinez-le dans une position mise à jour. Voici un exemple de fonction de rappel d'affichage de superposition utilisée pour implémenter le « rubberbanding » de superposition :

  void
  redrawOverlay(void)
  {
    static int prevStretchX, prevStretchY;
    if (glutLayerGet(GLUT_OVERLAY_DAMAGED)) {
      /* Le dommage signifie qu'un effacement complet est nécessaire. */
      glClear(GL_COLOR_BUFFER_BIT);
    } else {
      /* Efface le dernier rubber-band. */
      glIndexi(transparent);
      glBegin(GL_LINE_LOOP);
      glVertex2i(anchorX, anchorY);
      glVertex2i(anchorX, prevStretchY);
      glVertex2i(prevStretchX, prevStretchY);
      glVertex2i(prevStretchX, anchorY);
      glEnd();
    }
    glIndexi(red);
    glBegin(GL_LINE_LOOP);
    glVertex2i(anchorX, anchorY);
    glVertex2i(anchorX, stretchY);
    glVertex2i(stretchX, stretchY);
    glVertex2i(stretchX, anchorY);
    glEnd();
    prevStretchX = stretchX;
    prevStretchY = stretchY;
  }

Remarquez comment glutLayerGet(GLUT_OVERLAY_DAMAGED) est utilisé pour déterminer si un effacement est nécessaire en raison de dommages ; si un effacement est inutile, il est plus rapide de simplement dessiner le dernier « rubberband » en utilisant le pixel transparent.

Lorsque l'application a terminé l'effet « rubberbanding », la meilleure façon de supprimer le « rubberband » est simplement de masquer la superposition en appelant glutHideOverlay.

VOIR AUSSI

glutPostRedisplay, glutEstablishOverlay, glutLayerGet
