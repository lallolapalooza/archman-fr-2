DESCRIPTIO

N

glBufferData et glNamedBufferData créent un nouveau magasin de données pour un objet tampon. Dans le cas de glBufferData, l'objet tampon actuellement lié à target est utilisé. Pour glNamedBufferData, un objet tampon associé à l'ID spécifié par l'appelant dans buffer sera utilisé à la

place.

Lors de la création du nouveau stockage, tout magasin de données préexistant est supprimé. Le nouveau magasin de données est créé avec la taille spécifiée en octets et usage. Si data n'est pas NULL, le magasin de données est initialisé avec les données de ce pointeur. Dans son état initial, le nouveau magasin de données n'est pas mappé, il a un pointeur mappé NULL, et son accès mappé est GL_READ_WRITE

.

usage est un indice donné à l'implémentation GL concernant la manière dont le magasin de données d'un objet tampon sera accédé. Cela permet à l'implémentation GL de prendre des décisions plus intelligentes qui peuvent avoir un impact significatif sur les performances de l'objet tampon. Cela ne contraint toutefois pas l'utilisation réelle du magasin de données. usage peut être décomposé en deux parties : d'abord, la fréquence d'accès (modification et utilisation), et ensuite, la nature de cet accès. La fréquence d'accès peut être l'une des suivantes

:

STREA

M
Le contenu du magasin de données sera modifié une fois et utilisé au plus quelques
fois.

STATI

C
Le contenu du magasin de données sera modifié une fois et utilisé de nombreuses
fois.

DYNAMI

C
Le contenu du magasin de données sera modifié à plusieurs reprises et utilisé de nombreuses
fois.

La nature de l'accès peut être l'une des suivantes

:

DRA

W
Le contenu du magasin de données est modifié par l'application, et utilisé comme source pour les commandes de rendu et de spécification d'image
GL.

REA

D
Le contenu du magasin de données est modifié en lisant des données depuis le GL, et utilisé pour renvoyer ces données lorsqu'elles sont interrogées par
l'application.

COP

Y
Le contenu du magasin de données est modifié en lisant d
es données depuis le GL, et utilisé comme source pour
les commandes de rendu et de spécification d'image GL.

NOTE

S

Si data est NULL, un magasin de données de la taille spécifiée est tout de même créé, mais son contenu reste non initialisé et donc

indéfini.

Les clients doivent aligner les éléments de données de manière cohérente avec les exigences de la plateforme client, avec une exigence de niveau de base supplémentaire selon laquelle un décalage dans un tampon vers une donnée composée de N octets doit être un multiple de

N.

La cible GL_ATOMIC_COUNTER_BUFFER n'est disponible que si la version GL est 4.2 ou

supérieure.

Les cibles GL_DISPATCH_INDIRECT_BUFFER et GL_SHADER_STORAGE_BUFFER ne sont disponibles que si la version GL est 4.3 ou

supérieure.

La cible GL_QUERY_BUFFER n'est disponible que

si la version GL
est 4.4 ou supérieure.

ERREUR

S

GL_INVALID_ENUM est généré par glBufferData si target n'est pas l'une des cibles de tampon

acceptées.

GL_INVALID_ENUM est généré si usage n'est pas GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, ou GL_DYNAMIC_COPY

.

GL_INVALID_VALUE est généré si size est

négatif.

GL_INVALID_OPERATION est généré par glBufferData si le nom réservé d'objet tampon 0 est lié à target

.

GL_INVALID_OPERATION est généré par glNamedBufferData si buffer n'est pas le nom d'un objet tampon

existant.

GL_INVALID_OPERATION est généré si le drapeau GL_BUFFER_IMMUTABLE_STORAGE de l'objet tampon est GL_TRUE

.

GL_OUT_OF_MEMORY est généré si le GL est incapable de créer un magasin de données avec la taille spécifi

ée
.
