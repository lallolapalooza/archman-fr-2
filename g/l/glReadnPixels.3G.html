NAME

glReadnPixels — read pixels from the framebuffer and write them into a buffer of a specified size

C SPECIFICATION

void glReadnPixels(GLint x, GLint y, GLsizei width, GLsizei height,
                   GLenum format, GLenum type, GLsizei bufSize, GLvoid *data);

PARAMETERS

x, y
Specify the window coordinates of the first pixel to be read. The coordinates are relative to the current GL context's window.
width, height
Specify the dimensions of the pixel rectangle to be read. The width and height arguments specify the size of the pixel rectangle in pixels.
format
Specifies the format of the pixel data. See the description of format in the glReadPixels man page.
type
Specifies the data type of the pixel data. See the description of type in the glReadPixels man page.
bufSize
Specifies the size, in bytes, of the buffer pointed to by data. This must be large enough to hold the requested pixel data. See the description of bufSize in the glReadnPixels man page.
data
Returns the specified window-relative pixels. This is a pointer to a buffer where the packed pixel data is written.

DESCRIPTION

glReadnPixels is a version of glReadPixels that takes an additional argument, bufSize, which specifies the size of the buffer pointed to by data.

glReadnPixels reads one or more pixels from the specified location in the framebuffer and returns them to the calling program. The pixels are returned as an array of values in data. x and y specify the window coordinates of the lower-left corner of the pixel rectangle to be read, with x and y corresponding to the center of the pixel, and the coordinates increasing in the positive x and y directions. If the pixel coordinates are outside the window, the result is undefined.

The width and height arguments specify the dimensions of the pixel rectangle to be read. width = 0 or height = 0 results in no pixels being returned.

The format and type arguments specify the format of the returned pixel data. The format argument can be any of the formats listed for glReadPixels. The type argument can be any of the types listed for glReadPixels.

The bufSize argument specifies the size, in bytes, of the buffer pointed to by data. If bufSize is not large enough to hold the requested pixel data, glReadnPixels generates a GL_INVALID_OPERATION error. Otherwise, the data is written into the buffer.

The memory layout of the returned pixel data depends on the current GL_PACK_ALIGNMENT, GL_PACK_LSB_FIRST, and GL_PACK_SWAP_BYTES pixel store parameters. See glPixelStore.

The type argument determines the size and interpretation of each pixel in the returned data. The following table shows the possible values for type and their corresponding memory formats.

GL_BYTE 1 signed byte per component 1, 2, 3, or 4

GL_SHORT 1 signed short per component 1, 2, 3, or 4
GL_UNSIGNED_INT 1 unsigned int per component 1, 2, 3, or 4
GL_INT 1 signed int per component 1, 2, 3, or 4
GL_FLOAT 1 float per component 1, 2, 3, or 4
GL_HALF_FLOAT 1 half-float per component 1, 2, 3, or 4

GL_UNSIGNED_SHORT_5_6_5 packed 1
GL_UNSIGNED_SHORT_5_6_5_REV packed 1
GL_UNSIGNED_SHORT_4_4_4_4 packed 1
GL_UNSIGNED_SHORT_4_4_4_4_REV packed 1
GL_UNSIGNED_SHORT_5_5_5_1 packed 1
GL_UNSIGNED_SHORT_1_5_5_5_REV packed 1
GL_UNSIGNED_INT_8_8_8_8 packed 1

Return values are placed in memory as follows. If format is GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_RED, GL_GREEN, or GL_BLUE, a single value is returned and the data for the ith pixel in the jth row is placed in location j ⁢ width + i. GL_RGB and GL_BGR return three values, GL_RGBA and GL_BGRA return four values for each pixel, with all values corresponding to a single pixel occupying contiguous space in data. Storage parameters set by glPixelStore(), such as GL_PACK_LSB_FIRST and GL_PACK_SWAP_BYTES, affect the way that data is written into memory. See glPixelStore() for a description.

glReadnPixels function will only handle the call if bufSize is at least of the size required to store the requested data. Otherwise, it will generate a GL_INVALID_OPERATION error.

NOTES

Values for pixels that lie outside the window connected to the current GL context are undefined.

If an error is generated, no change is made to the contents of data.

ERRORS

GL_INVALID_ENUM is generated if format or type is not an accepted value.

GL_INVALID_VALUE is generated if either width or height is negative.

GL_INVALID_OPERATION is generated if format is GL_STENCIL_INDEX and there is no stencil buffer.

GL_INVALID_OPERATION is generated if format is GL_DEPTH_COMPONENT and there is no depth buffer.

GL_INVALID_OPERATION is generated if format is GL_DEPTH_STENCIL and there is no depth buffer or if there is no stencil buffer.

GL_INVALID_ENUM is generated if format is GL_DEPTH_STENCIL and type is not GL_UNSIGNED_INT_24_8 or GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, or GL_UNSIGNED_SHORT_5_6_5_REV and format is not GL_RGB.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, or GL_UNSIGNED_INT_2_10_10_10_REV and format is neither GL_RGBA nor GL_BGRA.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the buffer object's data store is currently mapped.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the data would be packed to the buffer object such that the memory writes required would exceed the data store size.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and data is not evenly divisible into the number of bytes needed to store in memory a datum indicated by type.

GL_INVALID_OPERATION is generated if GL_READ_FRAMEBUFFER_BINDING is non-zero, the read framebuffer is complete, and the value of GL_SAMPLE_BUFFERS for the read framebuffer is greater than zero.

GL_INVALID_OPERATION is generated by glReadnPixels if the buffer size required to store the requested data is greater than bufSize.

glGet() with argument GL_PIXEL_PACK_BUFFER_BINDING
