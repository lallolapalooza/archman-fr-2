NOM

glReadPixels, glReadnPixels - lire un bloc de pixels du tampon de trame

SPÉCIFICATION C

void glReadPixels(GLint x, GLint y, GLsizei width, GLsizei height, GLenum format, GLenum type, void * data);

void glReadnPixels(GLint x, GLint y, GLsizei width, GLsizei height, GLenum format, GLenum type, GLsizei bufSize, void *data);

PARAMÈTRES

x, y

Spécifient les coordonnées de la fenêtre du premier pixel lue à partir du tampon de trame. Cet emplacement est le coin inférieur gauche d'un bloc rectangulaire de pixels.

width, height

Spécifient les dimensions du rectangle de pixels. width et height de un correspondent à un seul pixel.

format

Spécifie le format des données de pixels. Les valeurs symboliques suivantes sont acceptées : GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_DEPTH_STENCIL, GL_RED, GL_GREEN, GL_BLUE, GL_RGB, GL_BGR, GL_RGBA, et GL_BGRA.

type

Spécifie le type de données des pixels. Doit être l'une des valeurs : GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_HALF_FLOAT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, GL_UNSIGNED_INT_24_8, GL_UNSIGNED_INT_10F_11F_11F_REV, GL_UNSIGNED_INT_5_9_9_9_REV, ou GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

bufSize

Spécifie la taille du tampon data pour la fonction glReadnPixels.

data

Retourne les données de pixels.

DESCRIPTION

glReadPixels et glReadnPixels retournent les données de pixels du tampon de trame, en commençant par le pixel dont le coin inférieur gauche est à la position (x, y), dans la mémoire client à l'emplacement data. Plusieurs paramètres contrôlent le traitement des données de pixels avant qu'elles ne soient placées dans la mémoire client. Ces paramètres sont définis avec glPixelStore(). Cette page de référence décrit les effets sur glReadPixels et glReadnPixels de la plupart, mais pas de la totalité, des paramètres spécifiés par ces trois commandes.

Si un objet tampon nommé non nul est lié à la cible GL_PIXEL_PACK_BUFFER (voir glBindBuffer()) lors de la demande d'un bloc de pixels, data est traité comme un décalage en octets dans le magasin de données de l'objet tampon plutôt que comme un pointeur vers la mémoire client.

glReadPixels et glReadnPixels retournent les valeurs de chaque pixel dont le coin inférieur gauche est à x + i y + j pour 0 <= i < width et 0 <= j < height. Ce pixel est dit être le i-ème pixel de la j-ème ligne. Les pixels sont retournés par ligne, de la ligne la plus basse à la ligne la plus haute, de gauche à droite dans chaque ligne.

format spécifie le format des valeurs de pixels retournées ; les valeurs acceptées sont :

GL_STENCIL_INDEX

Les valeurs de stencil sont lues à partir du tampon de stencil.

GL_DEPTH_COMPONENT

Les valeurs de profondeur sont lues à partir du tampon de profondeur. Chaque composant est converti en virgule flottante de manière à ce que la valeur de profondeur minimale corresponde à 0 et la valeur maximale corresponde à 1. Chaque composant est limité à la plage 0 à 1.

GL_DEPTH_STENCIL

Les valeurs sont prises à partir des tampons de profondeur et de stencil. Le paramètre type doit être GL_UNSIGNED_INT_24_8 ou GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

GL_RED, GL_GREEN, GL_BLUE, GL_RGB, GL_BGR, GL_RGBA, GL_BGRA

Les valeurs de couleur sont prises à partir du tampon de couleur.

Enfin, les indices ou les composants sont convertis au format approprié, tel que spécifié par type. Si format est GL_STENCIL_INDEX et type n'est pas GL_FLOAT, chaque indice est masqué avec la valeur de masque donnée dans le tableau suivant. Si type est GL_FLOAT, alors chaque indice entier est converti au format virgule flottante simple précision.

Si format est GL_RED, GL_GREEN, GL_BLUE, GL_RGB, GL_BGR, GL_RGBA, ou GL_BGRA et type n'est pas GL_FLOAT, chaque composant est multiplié par le multiplicateur indiqué dans le tableau suivant. Si type est GL_FLOAT, alors chaque composant est transmis tel quel (ou converti au format virgule flottante simple précision du client s'il est différent de celui utilisé par le GL).

Les valeurs de retour sont placées en mémoire comme suit. Si format est GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_RED, GL_GREEN, ou GL_BLUE, une seule valeur est retournée et les données pour le i-ème pixel de la j-ème ligne sont placées à l'emplacement j ⁢ width + i. GL_RGB et GL_BGR retournent trois valeurs, GL_RGBA et GL_BGRA retournent quatre valeurs pour chaque pixel, toutes les valeurs correspondant à un seul pixel occupant un espace contigu dans data. Les paramètres de stockage définis par glPixelStore(), tels que GL_PACK_LSB_FIRST et GL_PACK_SWAP_BYTES, affectent la manière dont les données sont écrites en mémoire. Voir glPixelStore() pour une description.

glReadnPixels ne traitera l'appel que si bufSize est au moins de la taille requise pour stocker les données demandées. Sinon, elle générera une erreur GL_INVALID_OPERATION .

REMARQUES

Les valeurs des pixels situés en dehors de la fenêtre connectée au contexte GL courant sont indéfinies.

Si une erreur est générée, le contenu de datan'est pas modifié.

ERREUR

GL_INVALID_ENUM est généré si format ou type n'est pas une valeur acceptée.

GL_INVALID_VALUE est généré si width ou height est négatif.

GL_INVALID_OPERATION est généré si format est GL_STENCIL_INDEX et qu'il n'y a pas de tampon de stencil.

GL_INVALID_OPERATION est généré si format est GL_DEPTH_COMPONENT et qu'il n'y a pas de tampon de profondeur.

GL_INVALID_OPERATION est généré si format est GL_DEPTH_STENCIL et qu'il n'y a pas de tampon de profondeur ou pas de tampon de stencil.

GL_INVALID_ENUM est généré si format est GL_DEPTH_STENCIL et type n'est pas GL_UNSIGNED_INT_24_8 ou GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

GL_INVALID_OPERATION est généré si type est l'un de GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, ou GL_UNSIGNED_SHORT_5_6_5_REV et format n'est pas GL_RGB.

GL_INVALID_OPERATION est généré si type est l'un de GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, ou GL_UNSIGNED_INT_2_10_10_10_REV et format n'est ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION est généré si un nom d'objet tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que le magasin de données de l'objet tampon est actuellement associé (mapped).

GL_INVALID_OPERATION est généré si un nom d'objet tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que les données seraient empaquetées dans l'objet tampon de telle sorte que les écritures mémoire requises dépasseraient la taille du magasin de données.

GL_INVALID_OPERATION est généré si un nom d'objet tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que data n'est pas un multiple exact du nombre d'octets nécessaires pour stocker en mémoire une donnée indiquée par type.

GL_INVALID_OPERATION est généré si GL_READ_FRAMEBUFFER_BINDING est non nul, le framebuffer de lecture est complet, et la valeur de GL_SAMPLE_BUFFERS pour le framebuffer de lecture est supérieure à zéro.

GL_INVALID_OPERATION est généré par glReadnPixels si la taille de tampon requise pour stocker les données demandées est supérieure à bufSize.

INTERROGATIONS ASSOCIÉES

glGet() avec l'argument GL_PIXEL_PACK_BUFFER_BINDING
