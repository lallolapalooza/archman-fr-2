glab-cluster-agent-bootstrap -

Initialise un agent GitLab pour
Kubernetes dans un projet.

SYNOPSI

S

glab cluster agen

t bootstrap agen
t-name [drapeaux]

DESCRIPTIO

N

Initialise un agent GitLab pour Kubernetes (agentk) dans un

projet.

Le premier argument doit être le nom de

l'agent.

Cela nécessite les commandes kubectl et flux soient accessibles via $PATH

.

Cette commande se compose de plusieurs étapes idempotentes

:
1
.
Enregistrer l'agent auprès du
projet.
2
.
Configurer
l'agent.
3
.
Configurer un environnement avec tableau de bord pour
l'agent.
4
.
Configurer un environnement avec tableau de bord pour FluxCD (si --create-flux-envi
ronment).
5
.
Créer un
jeton pour
l'agent.
  • Si l'agent a atteint le nombre maximal de jetons, celui qui n'a pas été utilisé depuis le plus longtemps est révoqué et un nouveau est
    • créé.
  • Si l'agent n'a pas a
    • tteint le nombre maxi
mal de jetons, un nou
veau est créé.
6
.
Pousser le Secret Kubernetes contenant le jeton vers le
cluster.
7
.
Créer les ressources Flux HelmRepository et
HelmRelease.
8
.
Commiter et pousser les ressources Flux Helm créées vers le chemin du
manifeste.
9
.
Déclencher la réconciliation Flux du HelmRelease de l'agent GitLab (sauf si --no-r
econ
cil
e).

OPTION

S

--commit-author-email="noreply@glab.gitlab.com" Adresse e-mail de l'auteur du commit Git à utiliser. En conflit avec le drapeau --use-api-commit-author

.

--commit-author-name="glab" Nom de l'auteur du commit Git à utiliser. En conflit avec le drapeau --use-api-commit-author

.

--create-environment[=true] Créer un environnement pour l'agent

GitLab.

--create-flux-environment[=true] Créer un environnement pour FluxCD. N'affecte que la création de l'environnement, pas l'utilisation de Flux lui-même. Flux est toujours requis pour le processus d'initialisation

.

--environment-flux-resource-path="helm.toolkit.fluxcd.io/v2beta1/namespaces//helmreleases/" Chemin de la ressource Flux de l'environnement pour l'agent

GitLab.

--environment-name="/" Nom de l'environnement pour l'agent

GitLab.

--environment-namespace="" Namespace Kubernetes de l'environnement pour l'agent

GitLab.

--flux-environment-flux-resource-path="kustomize.toolkit.fluxcd.io/v1/namespaces/flux-system/kustomizations/flux-system" Chemin de la ressource Flux de l'environnement pour

FluxCD.

--flux-environment-name="/" Nom de l'environnement pour

FluxCD.

--flux-environment-namespace="" Namespace Kubernetes de l'environnement pour

FluxCD.

--flux-source-name="flux-system" Nom de la source

Flux.

--flux-source-namespace="flux-system" Namespace de la source

Flux.

--flux-source-type="git" Type de source du flux-system, comme Git, OCI ou

Helm.

--gitlab-agent-token-secret-name="gitlab-agent-token" Nom du Secret où le jeton de l'agent GitLab est stocké. Le helm-release-target-namespace est implicite pour le namespace du

Secret.

--helm-release-filepath="gitlab-agent-helm-release.yaml" Chemin du fichier dans le projet de l'agent GitLab vers lequel commiter le Flux

HelmRelease.

--helm-release-name="gitlab-agent" Nom du manifeste Flux

HelmRelease.

--helm-release-namespace="flux-system" Namespace du manifeste Flux

HelmRelease.

--helm-release-target-namespace="gitlab-agent" Namespace du déploiement de l'agent

GitLab.

--helm-release-values=[] Chemin local vers les fichiers values.yaml. Plusieurs fichiers peuvent être séparés par des virgules ou spécifiés en répétant le

drapeau.

--helm-release-values-from=[] Référence à un objet Kubernetes contenant la clé de données values.yaml au format '/', où 'kind' doit être l'un des suivants : (Secret, ConfigMap). Plusieurs références peuvent être séparées par des virgules ou spécifiées en répétant le

drapeau.

--helm-repository-address="https://charts.gitlab.io" Adresse de la

HelmRepository.

--helm-repository-filepath="gitlab-helm-repository.yaml" Chemin du fichier dans le projet de l'agent GitLab vers lequel commiter la Flux

HelmRepository.

--helm-repository-name="gitlab" Nom du manifeste Flux

HelmRepository.

--helm-repository-namespace="flux-system" Namespace du manifeste Flux

HelmRepository.

-b, --manifest-branch="" Branche vers laquelle commiter les Flux Manifests. (par défaut, la branche par défaut du

projet)

-p, --manifest-path="" Emplacement du répertoire dans le dépôt Git pour stocker les ressources Helm de l'agent GitLab pour

Kubernetes.

--no-reconcile[=false] Ne pas déclencher la réconciliation Flux pour la ressource Flux de l'agent GitLab pour

Kubernetes.

--use-api-commit-author[=false] Lors de la création de commits Git, utiliser l'utilisateur de la requête API authentifiée. En conflit avec les drapeaux --commit-author-name et --commit-author-emai

l
.

EXEMPL

E 
# Initialiser "my-agent" à la racine du projet Git dans le répertoire courant, et déclencher la réconciliation
$ glab cluster agent bootstrap my-agent
# Initialiser "my-agent" vers "manifests/" du projet Git dans le répertoire courant, et déclencher la réconciliation
# Particulièrement utile lorsque "flux bootstrap gitlab --path manifests/" est utilisé.
# Assurez-vous que le "--path" de la commande "flux bootstrap gitlab" correspond
# au "--manifest-path" de la commande "glab cluster agent bootstrap".
$ glab cluster agent bootstrap my-agent --manifest-path manifests/
# Initialiser "my-agent" vers "manifests/" du projet Git dans le répertoire courant, et ne pas déclencher manuellement une réconciliation
$ glab cluster agent bootstrap my-agent --manifest-path manifests/ --no-reconcile
# Initialiser "my-agent" sans configurer d'environnement
$ glab cluster agent bootstrap my-agent --create-environment=false
# Initialiser "my-agent" et configurer un environnement avec un nom et un namespace Kubernetes personnalisés
$ glab cluster agent bootstrap my-agent --environment-name production --environment-namespace default
# Initialiser "my-agent" sans configurer d'environnement FluxCD
$ glab cluster agent bootstrap my-agent --create-flux-environment=false
# Initialiser "my-agent" et configurer un environnement FluxCD avec un nom et un namespace Kubernetes personnalisés
$ glab cluster agent bootstrap my-agent --flux-environment-name production-flux --flux-environment-namespace flux-system
# Initialiser "my-agent" et passer des valeurs supplémentaires du Helm Chart GitLab depuis un fichier local
$ glab cluster agent bootstrap my-agent --helm-release-values values.yaml
# Initialiser "my-agent" et passer des valeurs supplémentaires du Helm Chart GitLab depuis une ConfigMap Kubernetes
$ glab cluster agent bootstrap my-agent --helm-release-values-from ConfigMap/agent-config
# Initialiser "my-agent" et committer avec un utilisateur personnalisé
$ glab cluster agent bootstrap my-agent --commit-author-name="Tanuki" --commit-author-email="tanuki@example.com"
# Initialiser "my-agent" avec l'utilisateur API authentifié
$ glab cluster agent bootstrap my-agent --use-api-commit-auth
