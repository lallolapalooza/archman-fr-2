L'emplacement de la variable uniforme à modifier est spécifié par location, qui doit être une valeur retournée par glGetUniformLocation(). glUniform opère sur l'objet programme qui a été rendu partie de l'état courant en appelant glUseProgram(). Les commandes location en utilisant les valeur

passées en arguments. Le nombre spécifié dans la commande doit correspondre au nombre de composantes dans le type de données de la variable uniforme spécifiée (par ex., glUniform{1|2|3|4}{f|i|ui} sont utilisées pour changer la valeur de la variable uniforme spécifiée par 1 pour float, int, unsigned int, bool ; 2 pour vec2, ivec2, uvec2, bvec2, etc.). Le suffixe f indique que des valeurs en virgule flottante sont passées ; le suffixe i indique que des valeurs entières sont passées ; le suffixe ui indique que des valeurs entières non signées sont passées, et ce type doit également correspondre au type de données de la variable uniforme spécifiée. Les variantes i de cette fonction doivent être utilisées pour fournir des valeurs pour des variables uniformes définies comme int, ivec2, ivec3, ivec4, ou des tableaux de ceux-ci. Les variantes ui de cette fonction doivent être utilisées pour fournir des valeurs aux variables uniformes définies comme unsigned int, uvec2, uvec3, uvec4, ou des tableaux de ceux-ci. Les variantes f doivent être utilisées pour fournir des valeurs aux variables uniformes de type float, vec2, vec3, vec4, ou des tableaux de ceux-ci. Soit les variantes i, ui ou variantes f peuvent être utilisées pour fournir des valeurs aux variables uniformes de type bool, bvec2, bvec3, bvec4, ou des tableaux de ceux-ci. La variable uniforme sera définie à false si la valeur d'entrée est 0 ou 0.0f, et elle sera définie à true

sinon.

Toutes les variables uniformes actives définies dans un objet programme sont initialisées à 0 lorsque l'objet programme est lié avec succès. Elles conservent les valeurs qui leur ont été assignées par un appel à glUniform jusqu'à ce que la prochaine opération de liaison réussie se produise sur l'objet programme, au moment où elles sont à nouveau initialisées à

0.

Les commandes glUniform{1|2|3|4}{f|i|ui}v peuvent être utilisées pour modifier une variable uniforme unique ou un tableau de variables uniformes. Ces commandes passent un compteur et un pointeur vers les valeurs à charger dans une variable uniforme ou un tableau de variables uniformes. Un compteur de 1 doit être utilisé si l'on modifie la valeur d'une seule variable uniforme, et un compteur de 1 ou supérieur peut être utilisé pour modifier un tableau entier ou une partie d'un tableau. Lors du chargement de n éléments à partir d'une position arbitraire m dans un tableau de variables uniformes, les éléments m + n - 1 dans le tableau seront remplacés par les nouvelles valeurs. Si m + n - 1 est supérieur à la taille du tableau de variables uniformes, les valeurs pour tous les éléments du tableau au-delà de la fin du tableau seront ignorées. Le nombre indiqué dans le nom de la commande indique le nombre de composantes pour chaque élément dans value, et il doit correspondre au nombre de composantes dans le type de données de la variable uniforme spécifiée (par ex., 1 pour float, int, bool ; 2 pour vec2, ivec2, bvec2, etc.). Le type de données spécifié dans le nom de la commande doit correspondre au type de données de la variable uniforme spécifiée comme décrit précédemment pour glUniform{1|2|3|4}

{f|i|ui}.

Pour les tableaux de variables uniformes, chaque élément du tableau est considéré comme étant du type indiqué dans le nom de la commande (par ex., glUniform3f ou glUniform3fv peuvent être utilisés pour charger un tableau de variables uniformes de type vec3). Le nombre d'éléments du tableau de variables uniformes à modifier est spécifié par coun

t

Les commandes glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv sont utilisées pour modifier une matrice ou un tableau de matrices. Les nombres dans le nom de la commande sont interprétés comme la dimensionnalité de la matrice. Le nombre 2 indique une matrice 2 × 2 (c.-à-d., 4 valeurs), le nombre 3 indique une matrice 3 × 3 (c.-à-d., 9 valeurs), et le nombre 4 indique une matrice 4 × 4 (c.-à-d., 16 valeurs). La dimensionnalité des matrices non carrées est explicite, le premier nombre représentant le nombre de colonnes et le second nombre représentant le nombre de lignes. Par exemple, 2x4 indique une matrice 2 × 4 avec 2 colonnes et 4 lignes (c.-à-d., 8 valeurs). Si transpose est GL_FALSE, chaque matrice est supposée être fournie en ordre colonne-major. Si transpose est GL_TRUE, chaque matrice est supposée être fournie en ordre ligne-major. L'argument count indique le nombre de matrices à passer. Un compteur de 1 doit être utilisé si l'on modifie la vale

ur d'une seule matrice, et un compteur supérieur à 1
peut être utilisé pour modifier un tableau de matrices.

REMARQUE

S

glUniform1i et glUniform1iv sont les deux seules fonctions qui peuvent être utilisées pour charger des variables uniformes définies comme des types sampler. Le chargement de samplers avec toute autre fonction entraînera une erreur GL_INVALID_OPERATION

.

Si count est supérieur à 1 et que la variable uniforme indiquée n'est pas un tableau, une erreur GL_INVALID_OPERATION est générée et la variable uniforme spécifiée restera

inchangée.

En dehors des exceptions précédentes, si le type et la taille de la variable uniforme tels que définis dans le shader ne correspondent pas au type et à la taille spécifiés dans le nom de la commande utilisée pour charger sa valeur, une erreur GL_INVALID_OPERATION sera générée et la variable uniforme spécifiée restera

inchangée.

Si location est une valeur autre que -1 et qu'elle ne représente pas un emplacement de variable uniforme valide dans l'objet programme courant, une erreur sera générée, et aucun changement ne sera apporté à la mémoire des variables uniformes de l'objet programme courant. Si location est égal à -1, les données passées seront ignorées silen

cieusement et la variable uniforme
spécifiée ne sera pas changée.

S

GL_INVALID_OPERATION est généré s'il n'y a pas d'objet programme

courant.

GL_INVALID_OPERATION est généré si la taille de la variable uniforme déclarée dans le shader ne correspond pas à la taille indiquée par la commande glUn

GL_INVALID_OPERATION est généré si l'une des variantes entières signées ou non signées de cette fonction est utilisée pour charger une variable uniforme de type float, vec2, vec3, vec4, ou un tableau de ceux-ci, ou si l'une des variantes en virgule flottante de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières signées de cette fonction est utilisée pour charger une variable uniforme de type unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières non signées de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si location est un emplacement uniforme invalide pour l'objet programme courant et que location n'est pas égal à

-1.

GL_INVALID_OPERATION est généré si un sampler est chargé à l'aide d'une commande autre que glUniform1i et glUniform1i

NAME

glUniformMatrix2x3fv - specify the value of a uniform variable

C SPECIFICATION

void glUniformMatrix2x3fv(GLint location, GLsizei count, GLboolean transpose, const GLfloat *value);

PARAMETERS

location
Specifies the uniform variable to be modified. Must be the uniform location of an integer-vector or boolean-vector uniform variable.
count
Specifies the number of elements that are to be modified. This must be 1 if the named uniform is a single matrix. Otherwise, it must be greater than or equal to 1.
transpose
Specifies whether to transpose the matrix or matrices. Must be GL_FALSE.
value
Specifies the address of the buffer in which the specified number of matrix elements are stored.

DESCRIPTION

glUniformMatrix2x3fv specifies the value of a uniform variable or variables when the program object currently in use is part of the active program.

location specifies the uniform variable to be modified.

count specifies the number of elements to be modified.

transpose indicates whether the matrix or matrices should be transposed when they are stored in the program object. GL_FALSE indicates that the matrix should not be transposed.

value points to an array of count matrices, each of size 2x3. The matrix elements are followed by the next matrix, with no intervening unspecified values. The matrices are stored in column-major order.

If location is the uniform location of a multi-dimensional array of matrices, then count indicates the number of matrices to be modified. Otherwise, count must be 1.

The matrices specified by value are loaded into the uniform variable indicated by location.

NOTES

If location is not -1 and the uniform variable indicated by location is not able to be modified (e.g., because it is derived in the shader), or if location is not a valid uniform location, an GL_INVALID_OPERATION is generated.

If transpose is not GL_FALSE, an GL_INVALID_VALUE is generated.

If the specified uniform variable is not a matrix of the indicated type, an GL_INVALID_OPERATION is generated.

If count is greater than 1, and the indicated uniform variable is not an array of matrices, an GL_INVALID_OPERATION is generated.

If count is greater than 1, and the indicated uniform variable is an array of matrices, but the array is not large enough to contain count matrices, an GL_INVALID_OPERATION is generated.

ERRORS

GL_INVALID_OPERATION is generated by the following, in addition to any of the conditions described in "NOTES":

  • If location is not -1 and is not the location of a uniform variable within the currently linked program object.

  • If the size of the uniform variable indicated by location is not compatible with the specified count and element type.

GL_INVALID_VALUE is generated if count is less than or equal to 0.

ASSOCIATED GETS

glUniform*() with values.
