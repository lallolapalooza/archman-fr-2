DESCRIPTION

La fonction gl_get_line() fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)). Si l'utilisateur tape au terminal, chaque appel lui demande une ligne d'entrée, puis fournit des fonctionnalités d'édition interactives, similaires à celles du shell tcsh de Unix. En plus de l'édition simple de ligne de commande, elle prend en charge le rappel des lignes de commande précédemment saisies, la complétion par TAB des noms de fichiers, et l'expansion de noms de fichiers par caractères génériques en ligne. La documentation des fonctionnalités d'édition de ligne de commande au niveau utilisateur et de toutes les options de configuration utilisateur se trouve dans la page de manuel tecla(7). Cette page de manuel concerne la documentation destinée aux programmeurs intéressés par l'utilisation de cette bibliothèque dans leur application.

UN EXEMPLE

Ce qui suit montre un exemple complet d'utilisation de la fonction gl_get_line() pour obtenir une entrée de l'utilisateur :

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La ligne que l'utilisateur a tapée */
    GetLine *gl;   /* L'objet ressource de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adopter le choix de l'utilisateur */
                             /* de jeu de caractères. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Vous avez tapé : %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

Dans l'exemple, d'abord les ressources nécessaires à la fonction gl_get_line() sont créées en appelant new_GetLine(). Cela alloue la mémoire utilisée dans les appels ultérieurs à la fonction gl_get_line(), y compris le tampon d'historique pour enregistrer les lignes précédemment saisies. Ensuite, une ou plusieurs lignes sont lues depuis l'utilisateur, jusqu'à ce qu'une erreur survienne, ou que l'utilisateur tape exit. Ensuite, enfin, les ressources qui ont été allouées par new_GetLine() sont retournées au système en appelant del_GetLine(). Notez l'utilisation de la valeur de retour NULL de del_GetLine() pour rendre gl NULL. C'est une précaution de sécurité. Si le programme tente ensuite de passer gl à gl_get_line(), ladite fonction se plaindra et retournera une erreur, au lieu de tenter d'utiliser l'objet ressource supprimé.

LES FONCTIONS UTILISÉES DANS L'EXEMPLE

Les descriptions des fonctions utilisées dans l'exemple sont les suivantes :

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Cette fonction crée les ressources utilisées par la fonction gl_get_line() et retourne un pointeur opaque vers l'objet qui les contient. La longueur maximale d'une ligne d'entrée est spécifiée via l'argument linelen, et le nombre d'octets à allouer pour stocker les lignes d'historique est défini par l'argument histlen. Les lignes d'historique sont stockées côte à côte dans un seul tampon de cette taille. Notez que cela signifie que le nombre de lignes d'historique qui peuvent être stockées à tout moment dépend des longueurs des lignes individuelles. Si vous souhaitez imposer une limite supérieure au nombre de lignes pouvant être stockées, voir la fonction gl_limit_history() décrite plus loin. Si vous ne voulez pas d'historique du tout, spécifiez histlen comme zéro, et aucun tampon d'historique ne sera alloué.

En cas d'erreur, un message est affiché sur stderr et NULL est retourné.

  GetLine *del_GetLine(GetLine *gl)

Cette fonction supprime les ressources qui ont été retournées par un appel précédent à new_GetLine(). Elle retourne toujours NULL (c'est-à-dire un objet supprimé). Elle ne fait rien si l'argument gl est NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La fonction gl_get_line() peut être appelée un nombre quelconque de fois pour lire l'entrée de l'utilisateur. L'argument gl doit avoir été précédemment retourné par un appel à new_GetLine(). L'argument prompt doit être une chaîne de caractères normale terminée par NUL, spécifiant l'invite à présenter à l'utilisateur. Par défaut, les invites sont affichées littéralement, mais si elles sont activées avec la fonction gl_prompt_style() (voir plus loin), les invites peuvent contenir des directives pour faire des soulignements, passer du gras à la police normale et vice versa, ou activer et désactiver la mise en surbrillance.

Si vous souhaitez spécifier le contenu initial de la ligne, pour que l'utilisateur le modifie, passez la chaîne souhaitée via l'argument start_line. Vous pouvez ensuite spécifier à quel caractère de cette ligne le curseur est initialement positionné

SOURCES DE CONFIGURATION

ALTERNATIVES

Comme mentionné ci-dessus, par défaut, les utilisateurs ont la possibilité de configurer le comportement de gl_get_line() via un fichier de configuration appelé .teclarc dans leurs répertoires personnels. Le fait que toutes les applications partagent ce même fichier de configuration est à la fois un avantage et un inconvénient. Dans la plupart des cas, c'est un avantage, car cela encourage l'uniformité et libère l'utilisateur de la nécessité de configurer chaque application séparément. Dans certaines applications, cependant, ce seul moyen de configuration est un problème. C'est particulièrement vrai pour les logiciels embarqués, où il n'y a pas de système de fichiers pour lire un fichier de configuration, et aussi dans les applications où un choix radicalement différent de mappage de touches est nécessaire pour émuler une interface de clavier héritée. Pour prendre en charge de tels cas, la fonction suivante permet à l'application de contrôler d'où les informations de configuration sont

lues. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Elle permet aux commandes de configuration qui seraient normalement lues depuis le fichier ~/.teclarc de l'utilisateur, d'être lues depuis une chaîne, un fichier de configuration spécifique à l'application, et/ou un fichier de configuration spécifique à l'utilisateur, ou aucun de ceux-ci. Si cette fonction est appelée avant le premier appel à gl_get_line(), le comportement par défaut de lecture de ~/.teclarc au premier appel à gl_get_line() est désactivé, de sorte que toute la configuration doit être réalisée à l'aide des sources de configuration spécifiées avec cette

fonction.

Si app_string != NULL, alors il est interprété comme une chaîne contenant une ou plusieurs commandes de configuration, séparées les unes des autres dans la chaîne par des caractères de nouvelle ligne intégrés. Si app_file != NULL alors il est interprété comme le chemin complet d'un fichier de configuration spécifique à l'application. Si user_file != NULL alors il est interprété comme le chemin complet d'un fichier de configuration spécifique à l'utilisateur, tel que ~/.teclarc. Par exemple, dans l'appel

suivant,

                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

Elle tente ensuite de lire les commandes de configuration à l'échelle du système depuis un fichier facultatif appelé /usr/share/myapp/teclarc, puis lit enfin les commandes de configuration spécifiques à l'utilisateur depuis un fichier .teclarc facultatif dans le répertoire personnel de l'utilisateur. Notez que les arguments sont listés par ordre de priorité croissante, le contenu de app_string pouvant être potentiellement remplacé par des commandes dans app_file, et les commandes dans app_file pouvant être potentiellement remplacées par des commandes dans user_file

Ceci est particulièrement important pour les signaux qui termineraient le processus par défaut, car le terminal doit être restauré dans un état utilisable avant que cela ne se produise.             d'interruption du clavier (généralement ^C)
            et la touche d'interruption du clavier.
            errno=EINTR

            contrôle se termine.
            errno=ENOTTY
 SIGPIPE -  Ce signal est généré lorsqu'un programme tente
            d'écrire dans un tuyau dont l'extrémité distante
            n'est lue par aucun processus. Cela peut se
            produire par exemple si vous avez appelé
            gl_change_terminal() pour rediriger la
            sortie vers un tuyau caché sous un pseudo-terminal.
            errno=EPIPE

            errno=EINTR

En d'autres termes, si l'application appelante ne remplace pas le gestionnaire par défaut en fournissant son propre gestionnaire de signaux, la réception du signal correspondant terminera l'application avant que gl_get_line() ne retourne.

GESTION FIABLE DES

SIGNAUX

La gestion des signaux est étonnamment difficile à réaliser de manière fiable sans conditions de course. Dans gl_get_line(), beaucoup de soins ont été pris pour permettre aux applications d'effectuer une gestion fiable des signaux autour de gl_get_line(). Cette section explique comment tirer parti de

cela.

À titre d'exemple des problèmes qui peuvent survenir si l'application n'est pas écrite correctement, imaginez que votre application ait un gestionnaire de signal SIGINT qui définit un drapeau global. Supposons maintenant que l'application teste ce drapeau juste avant d'invoquer gl_get_line(). Si un signal SIGINT se trouve être reçu dans la petite fenêtre de temps entre l'instruction qui teste la valeur de ce drapeau, et l'instruction qui appelle gl_get_line(), alors gl_get_line() ne verra pas le signal, et ne sera pas interrompu. En conséquence, l'application ne pourra pas répondre au signal tant que l'utilisateur n'aura pas terminé la saisie de la ligne et gl_get_line() n'aura pas retourné. Selon l'application, cela peut ou non être un désastre, mais au minimum cela déroutera

l'utilisateur.

La manière d'éviter ces problèmes est de faire ce qui

suit.

1. Si nécessaire, utilisez la fonction gl_trap_signal() pour
configurer gl_get_line() pour interrompre lorsque des signaux
importants sont

capturés.

2. Configurez gl_get_line() de telle sorte que si l'un des
signaux qu'il capture est bloqué lorsque
gl_get_line() est appelé, il sera débloqué
automatiquement pendant les périodes où gl_get_line()
attend des E/S. Cela peut être fait soit
pour chaque signal, en appelant la
fonction gl_trap_signal(), et en spécifiant l'attribut
GLS_UNBLOCK du signal, soit globalement en
appelant la fonction gl_catch_blocked()

. 
     void gl_catch_blocked(GetLine *gl)
;


Cette fonction ajoute simplement l'attribut GLS_UNBLOCK
à tous les signaux qu'elle est actuellement configurée pour
piéger

.

3. Juste avant d'appeler gl_get_line(), bloquez la délivrance
de tous les signaux que gl_get_line() est
configuré pour piéger. Cela peut être fait en utilisant la fonction POSIX
sigprocmask() en conjonction avec la
fonction gl_list_signals()

. 
      int gl_list_signals(GetLine *gl, sigset_t *set)
;


Cette fonction retourne l'ensemble des signaux qu'elle est
actuellement configurée pour capturer dans l'argument set,
qui est sous la forme requise par sigprocma

sk().

4. Dans l'exemple, on testerait maintenant le drapeau global que
le gestionnaire de signal définit, sachant qu'il n'y a maintenant plus de
risque que ce drapeau soit défini à nouveau avant que
gl_get_line() ne débloque ses signaux lors de l'exécution
d'E/S

.

5. Finalement, gl_get_line() retourne, soit parce qu'un
signal a été capturé, une erreur s'est produite, ou l'utilisateur a
terminé la saisie de sa

ligne.

6. On vérifierait alors à nouveau le drapeau de signal global, et si
il est défini, on y répondrait, et on remettrait le drapeau à

zéro.

7. Utilisez sigprocmask() pour débloquer les signaux qui ont été
bloqués à l'étape

3.

La même technique peut être utilisée autour de certaines fonctions POSIX sensibles aux signaux, telles que sigsetjmp() et sigsuspend(), et en particulier, la première de ces deux fonctions peut être utilisée en conjonction avec siglongjmp() pour implémenter une gestion de signal sans conditions de course autour d'autres appels système longs. La manière de faire cela est expliquée ensuite, en montrant comment gl_get_line() parvient à piéger fiablement les signaux autour d'appels à des fonctions comme read() et select() sans conditions de

course.

La première chose que gl_get_line() fait, chaque fois qu'il est appelé, est d'utiliser la fonction POSIX sigprocmask() pour bloquer la délivrance de tous les signaux qu'il est actuellement configuré pour capturer. Cela est redondant si l'application les a déjà bloqués, mais cela ne fait aucun mal. Il annule cette étape juste avant de

retourner.

Chaque fois que gl_get_line() doit appeler read() ou select() pour attendre des entrées de l'utilisateur, il appelle d'abord la fonction POSIX sigsetjmp(), en s'assurant de spécifier une valeur non nulle pour son argument savesigs. La raison de ce dernier argument deviendra claire sous

peu.

Si sigsetjmp() retourne zéro, gl_get_line() fait alors ce qui

suit. 
a. Il utilise la fonction POSIX sigaction() pour enregistrer
   un gestionnaire de signal temporaire pour tous les signaux qu'il
   est configuré pour piéger. Ce gestionnaire de signal fait deux
   choses.
   1. Il enregistre le numéro du signal reçu
      dans une variable de portée fichier.
   2. Il appelle ensuite la fonction POSIX siglongjmp()
      en utilisant le tampon qui a été passé à
      sigsetjmp() comme premier argument, et
      une valeur non nulle comme second argument.
   Lorsque ce gestionnaire de signal est enregistré, le membre sa_mask
   de l'argument struct sigaction act de
   l'appel à sigaction() est configuré pour contenir tous
   les signaux que gl_get_line() capture. Cela
   garantit qu'un seul signal sera capturé à la fois par
   notre gestionnaire de signal, ce qui à son tour garantit que
   les instances multiples de notre gestionnaire de signal ne se
   marchent pas les unes sur les autres.
b. Maintenant que le gestionnaire de signal a été configuré,
   gl_get_line() débloque tous les signaux qu'il
   est configuré pour piéger.
c. Il appelle ensuite les appels système read() ou select() pour attendre les entrées du clavier.
d. Si cet appel système retourne (c.-à-d. qu'aucun signal n'est reçu),
   gl_get_line()] bloque à nouveau la délivrance des signaux
   d'intérêt.
e. Il rétablit ensuite les gestionnaires de signal qui ont été

Utiliser gl_get_line() pour demander à l'utilisateur une réponse d'un seul caractère est peu pratique pour l'utilisateur, car il doit appuyer sur la touche entrée ou retour avant que le caractère qu'il a tapé ne soit renvoyé au programme. Entre les appels à gl_get_line(), la fonction gl_display_text() fournit un moyen pratique d'afficher des paragraphes de texte, justifiés à gauche et répartis sur une ou plusieurs lignes du terminal en fonction des contraintes de la largeur actuelle du terminal. Dans ces exemples, l'utilisation avancée de préfixes, suffixes et lignes de remplissage optionnels pour dessiner un cadre autour du texte est également

L'argument indentation spécifie le nombre de caractères à utiliser pour indenter chaque ligne de sortie. L'argument fill_char spécifie le caractère qui sera utilisé pour effectuer cette

SÉCURITÉ DES

THREADS

Dans un programme multi-thread, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des versions réentrantes des fonctions système, lorsqu'elles sont disponibles. Malheureusement, ni terminfo ni termcap n'ont été conçus pour être réentrants, vous ne
