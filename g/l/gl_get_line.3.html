DESCRIPTION

La fonction gl_get_line() fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)). Si l'utilisateur tape au terminal, chaque appel lui demande une ligne d'entrée, puis offre des fonctionnalités d'édition interactives, similaires à celles du shell tcsh de Unix. En plus de l'édition de ligne de commande simple, elle prend en charge le rappel des lignes de commande précédemment saisies, la complétion par TAB des noms de fichiers, et l'expansion de noms de fichiers en ligne par jokers. La documentation des fonctionnalités d'édition de ligne de commande au niveau utilisateur et de toutes les options de configuration utilisateur se trouve dans la page de manuel tecla(7). Cette page de manuel concerne la documentation pour les programmeurs intéressés par l'utilisation de cette bibliothèque dans leur application.

UN EXEMPLE

Voici un exemple complet d'utilisation de la fonction gl_get_line() pour obtenir une entrée de l'utilisateur :

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La ligne tapée par l'utilisateur */
    GetLine *gl;   /* L'objet de ressources gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adopter le choix de l'utilisateur */
                             /* de jeu de caractères. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Vous avez tapé : %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

Dans l'exemple, d'abord les ressources nécessaires à la fonction gl_get_line() sont créées en appelant new_GetLine(). Ceci alloue la mémoire utilisée dans les appels ultérieurs à la fonction gl_get_line(), y compris le tampon d'historique pour enregistrer les lignes précédemment saisies. Ensuite, une ou plusieurs lignes sont lues de l'utilisateur, jusqu'à ce qu'une erreur se produise, ou que l'utilisateur tape exit. Puis enfin, les ressources qui ont été allouées par new_GetLine() sont retournées au système en appelant del_GetLine(). Notez l'utilisation de la valeur de retour NULL de del_GetLine() pour rendre gl NULL. Ceci est une mesure de sécurité. Si le programme tente ensuite de passer gl à gl_get_line(), ladite fonction se plaindra et retournera une erreur, au lieu de tenter d'utiliser l'objet de ressources supprimé.

LES FONCTIONS UTILISÉES DANS L'EXEMPLE

Les descriptions des fonctions utilisées dans l'exemple sont les suivantes :

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Cette fonction crée les ressources utilisées par la fonction gl_get_line() et retourne un pointeur opaque vers l'objet qui les contient. La longueur maximale d'une ligne d'entrée est spécifiée via l'argument linelen, et le nombre d'octets à allouer pour stocker les lignes d'historique est défini par l'argument histlen. Les lignes d'historique sont stockées côte à côte dans un seul tampon de cette taille. Notez que cela signifie que le nombre de lignes d'historique qui peuvent être stockées à un moment donné dépend des longueurs des lignes individuelles. Si vous souhaitez placer une limite supérieure au nombre de lignes qui peuvent être stockées, consultez la fonction gl_limit_history() décrite plus loin. Si vous ne voulez pas d'historique du tout, spécifiez histlen à zéro, et aucun tampon d'historique ne sera alloué.

En cas d'erreur, un message est affiché sur stderr et NULL est retourné.

  GetLine *del_GetLine(GetLine *gl)

Cette fonction supprime les ressources qui ont été retournées par un appel précédent à new_GetLine(). Elle retourne toujours NULL (c'est-à-dire un objet supprimé). Elle ne fait rien si l'argument gl est NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La fonction gl_get_line() peut être appelée un nombre quelconque de fois pour lire l'entrée de l'utilisateur. L'argument gl doit avoir été retourné précédemment par un appel à new_GetLine(). L'argument prompt doit être une chaîne normale terminée par NUL, spécifiant l'invite à présenter à l'utilisateur. Par défaut, les invites sont affichées littéralement, mais si elles sont activées avec la fonction gl_prompt_style() (voir plus loin), les invites peuvent contenir des directives pour faire du soulignement, passer et revenir des polices en gras, ou activer et désactiver la mise en surbrillance.

Si vous souhaitez spécifier le contenu initial de la ligne, que l'utilisateur doit modifier, passez la chaîne souhaitée via l'argument start_line. Vous pouvez ensuite spécifier sur quel caractère de cette ligne le curseur est initialement positionné.

SOURCES DE CONFIGURATION

ALTERNATIVES

Comme mentionné ci-dessus, par défaut, les utilisateurs ont la possibilité de configurer le comportement de gl_get_line() via un fichier de configuration appelé .teclarc dans leurs répertoires personnels. Le fait que toutes les applications partagent ce même fichier de configuration est à la fois un avantage et un inconvénient. Dans la plupart des cas, c'est un avantage, car cela encourage l'uniformité et libère l'utilisateur de la nécessité de configurer chaque application séparément. Dans certaines applications, cependant, ce moyen unique de configuration pose problème. C'est particulièrement vrai pour les logiciels embarqués, où il n'y a pas de système de fichiers pour lire un fichier de configuration, et aussi dans les applications où un choix radicalement différent de mappage de touches est nécessaire pour émuler une interface clavier héritée. Pour prendre en charge de tels cas, la fonction suivante permet à l'application de contrôler d'où les informations de configuration sont

lues. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Elle permet aux commandes de configuration qui seraient normalement lues depuis le fichier ~/.teclarc d'un utilisateur, d'être lues depuis une ou plusieurs sources parmi : une chaîne, un fichier de configuration spécifique à l'application et/ou un fichier de configuration spécifique à l'utilisateur. Si cette fonction est appelée avant le premier appel à gl_get_line(), le comportement par défaut de lecture de ~/.teclarc au premier appel à gl_get_line() est désactivé ; toute la configuration doit donc être réalisée à l'aide des sources de configuration spécifiées avec cette

fonction.

Si app_string != NULL, alors il est interprété comme une chaîne contenant une ou plusieurs commandes de configuration, séparées les unes des autres dans la chaîne par des caractères de nouvelle ligne intégrés. Si app_file != NULL, alors il est interprété comme le chemin complet d'un fichier de configuration spécifique à l'application. Si user_file != NULL, alors il est interprété comme le chemin complet d'un fichier de configuration spécifique à l'utilisateur, tel que ~/.teclarc. Par exemple, dans l'appel

suivant, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

l'argument app_string fait démarrer l'application appelante en mode d'édition vi, au lieu du mode emacs par défaut, et désactive l'utilisation de la cloche du terminal par la bibliothèque. Elle tente ensuite de lire les commandes de configuration à l'échelle du système depuis un fichier optionnel appelé /usr/share/myapp/teclarc, puis lit enfin les commandes de configuration spécifiques à l'utilisateur depuis un fichier .teclarc optionnel dans le répertoire personnel de l'utilisateur. Notez que les arguments sont listés par ordre de priorité croissante, le contenu de app_string pouvant être potentiellement remplacé par les commandes dans app_file, et les commandes dans app_file pouvant être potentiellement remplacées par les commandes dans user_file

.

Vous pouvez appeler cette fonction autant de fois que nécessaire, les résultats étant cumulatifs, mais notez que des copies de tout nom de fichier spécifié via app_file et user_file sont enregistrés en interne pour une utilisation ultérieure par la fonction de liaison de touche read-init-files. Si vous prévoyez d'appeler cette fonction plusieurs fois, assurez-vous que le dernier appel spécifie les noms de fichiers que vous souhaitez relire lorsque l'utilisateur demande la relecture des fichiers de

configuration.

Des séquences de touches individuelles peuvent également être liées et déliées à l'aide de la fonction gl_bind_keyseq()

suivantes.

Lorsque des liaisons utilisateur et application pour une même séquence de touches ont été spécifiées, la liaison utilisateur a la priorité. La liaison de l'application est rétablie ultérieurement si la liaison de l'utilisateur est déliée plus tard, soit par un autre appel à cette fonction, soit par un appel à gl_configure_ge

L' argument keyseq spécifie la séquence de touches à lier ou à délier, et est exprimée de la même manière que dans un fichier de configuration ~/.teclarc. la séquence

COMPLÉTION DE MOTS

PERSONNALISÉE

Si dans votre application, vous souhaitez que la complétion par TAB complète d'autres éléments en plus des noms de fichiers, ou à la place de ceux-ci, vous pouvez le faire en enregistrant une fonction de rappel de complétion alternative, via un appel à la fonction gl_customize_c

ompletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

L' argument data fournit un moyen pour votre application de passer des informations arbitraires, spécifiques à l'application, à la fonction de rappel. Celles-ci sont transmises à la fonction de rappel à chaque fois qu'elle est appelée. Elles pourraient par exemple pointer vers la table de symboles à partir de laquelle les complétions possibles doivent être recherchées. L' argument match_fn spécifie la fonction de rappel à appeler. Le type de fonction CplMatchFn est défini dans libtecla.h, tout comme une macro CPL_MATCH_FN() que vous pouvez utiliser pour déclarer et prototyper des fonctions de rappel. La déclaration et les responsabilités des fonctions de rappel sont décrites en détail dans la page de manuel cpl_complete_word(3)

.

En bref, la fonction de rappel est responsable de la recherche vers l'arrière dans la ligne d'entrée, à partir du point où l'utilisateur a appuyé sur TAB, pour trouver le début du mot en cours de complétion. Elle doit ensuite rechercher les complétions possibles de ce mot et les enregistrer une par une dans l'objet WordCompletion qui lui est passé en argument, en appelant la fonction cpl_add_completion(). Si la fonction de rappel souhaite fournir la complétion de noms de fichiers en plus de ses propres complétions spécifiques, elle a la possibilité d'appeler elle-même la fonction de rappel de complétion de noms de fichiers intégrée. Ceci est également documenté dans la page de manuel cpl_complete_word(3)

.

Notez que si vous souhaitez que gl_get_line() retourne la ligne d'entrée actuelle lorsqu'une complétion réussie a été effectuée, vous pouvez le faire lorsque vous appelez cpl_add_completion(), en faisant du dernier caractère du suffixe de continuation un caractère de nouvelle ligne. Si vous faites cela, la ligne d'entrée sera mise à jour pour afficher la complétion, avec tout suffixe de continuation jusqu'au caractère de nouvelle ligne, puis gl_get_line() retournera cette ligne

d'entrée.

Si, pour une raison quelconque, votre fonction de rappel doit écrire quelque chose sur le terminal, elle doit appeler gl_normal_io() avant de le faire. Cela commencera une nouvelle ligne après la ligne d'entrée actuellement en cours d'édition, rétablira les E/S normales du terminal, et indiquera à gl_get_line() que la ligne d'entrée devra être red

essinée lorsque la fonctio
n de rappel retournera.

COMPLÉTION

Dans la section précédente, la capacité à personnaliser le comportement de la seule action de complétion par défaut, complete-word, a été décrite. Dans cette section, la capacité à installer des fonctions d'action supplémentaires, afin que différents types de complétion de mots puissent être liés à différentes séquences de touches, est décrite. Ceci est réalisé en utilisant la fonction gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Les arguments data et match_fn sont tels que décrits dans la page de manuel cpl_complete_word, et spécifient la fonction de rappel qui doit être invoquée pour identifier les complétions possibles. L' argument list_only détermine si l'action en cours de définition doit tenter de compléter le mot autant que possible dans la ligne d'entrée avant d'afficher les complétions ambiguës possibles, ou si elle doit simplement afficher la liste des complétions possibles sans toucher à la ligne d'entrée. La première option est sélectionnée en spécifiant une valeur de 0, et la seconde en spécifiant une valeur de 1. L' argument name spécifie le nom par lequel les fichiers de configuration et les futures invocations de cette fonction doivent se référer à l'action. Ceci doit être soit le nom d'une action de complétion existante à modifier, soit un nouveau nom non utilisé pour une nouvelle action. Enfin, l' argument keyseq spécifie la séquence de touches par défaut à lier à l'action. Si ceci est NULL, aucune nouvelle séquence de touches ne sera liée à

l'action.

DÉFINITION D'ACTIONS

PERSONNALISÉES

Bien que les actions de liaison de touches intégrées soient suffisantes pour les besoins de la plupart des applications, une application spécialisée peut parfois avoir besoin de définir une ou plusieurs actions personnalisées, liées à des séquences de touches spécifiques à l'application. Par exemple, une application de vente bénéficierait d'une séquence de touches qui afficherait le nom de la pièce correspondant à un numéro de pièce précédant le curseur. Une telle fonctionnalité dépasse clairement le cadre des fonctions d'action intégrées. Ainsi, pour de tels cas particuliers, la fonction gl_register_action() est

fournie. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Cette fonction permet à l'application d'enregistrer une fonction externe, fn, qui sera ensuite appelée chaque fois que soit la séquence de touches spécifiée, keyseq, est saisie par l'utilisateur, soit que l'utilisateur entre une autre séquence de touches qu'il lie ensuite au nom d'action spécifié, name, dans son fichier de configuration. L' argument data peut être un pointeur vers n'importe quoi que l'application souhaite voir passer à la fonction d'action, fn, chaque fois que cette fonction est

invoquée.

La fonction d'action, fn, devrait être déclarée en utilisant la macro suivante, qui est définie dans libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Les arguments gl et data sont ceux qui ont été précédemment passés à gl_register_action() lorsque la fonction d'action a été enregistrée. L' argument count est un argument numérique que l'utilisateur a la possibilité d'entrer en utilisant l' action digit-argument, avant d'invoquer l'action. Si l'utilisateur n'entre pas de nombre, alors l' argument count est défini à 1. Nominalement, cet argument est interprété comme un nombre de répétitions, ce qui signifie que l'action devrait être répétée ce nombre de fois. En pratique cependant, pour certaines actions, un nombre de répétitions n'a que peu de sens. Dans de tels cas, les actions peuvent soit simplement ignorer l' argument count, soit utiliser sa valeur à une autre

fin.

Une copie de la ligne d'entrée actuelle est passée dans l'argument en lecture seule line. La position actuelle du curseur dans cette chaîne est donnée par l'index contenu dans l' argument curpos. Notez que la manipulation directe de la ligne d'entrée et de la position du curseur n'est pas autorisée. En effet, les règles dictées par divers modes, tels que le mode vi par rapport au mode emacs, le mode sans écho, et le mode insertion par rapport au mode surimpression, etc., rendent trop complexe pour un développeur d'application d'écrire une action d'édition conforme, et contraignent également les changements futurs des internes de gl_get_line(). Une solution potentielle à ce dilemme serait de permettre à la fonction d'action d'éditer la ligne en utilisant les actions d'édition existantes. Cela est actuellement à

l'étude.

Si la fonction d'action souhaite écrire du texte sur le terminal, sans que cela se mélange avec le texte affiché de la ligne d'entrée, ou lire depuis le terminal sans avoir à gérer les E/S brutes du terminal, alors avant de faire l'une ou l'autre de ces opérations, elle doit suspendre temporairement l'édition de ligne en appelant la fonction gl_normal_io(). Cette fonction vide toute sortie en attente vers le terminal, déplace le curseur au début de la ligne suivant la dernière ligne du terminal de la ligne d'entrée, puis restaure le terminal dans un état adapté à l'utilisation avec les fonctions stdio du C. Ce dernier inclut des choses comme la restauration du mappage normal de \n vers \r\n, et, en mode serveur, la restaure de la forme bloquante normale des E/S du terminal. Après avoir appelé cette fonction, la fonction d'action peut lire depuis et écrire vers le terminal sans craindre de créer un désordre. Il n'est pas nécessaire pour la fonction d'action de restaurer l'environnement d'édition original avant de retourner. Cela est fait automatiquement par gl_get_line() après le retour de la fonction d'action. Voici un exemple simple d'une fonction d'action qui écrit la phrase "Hello world" sur une nouvelle ligne du terminal après la ligne en cours d'édition. Lorsque cette fonction retourne, la ligne d'entrée est redessinée sur la ligne suivant la ligne "Hello world", et l'édition de ligne

reprend. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspendre temporairement l'édition */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

Les fonctions d'action doivent retourner l'une des valeurs suivantes, pour indiquer à gl_get_line() comment

procéder. 
  GLA_ABORT     -   Faire en sorte que gl_get_line() retourne NULL.
  GLA_RETURN    -   Faire en sorte que gl_get_line() retourne la
                    ligne d'entrée complétée.
  GLA_CONTINUE  -   Reprendre l'édition de la ligne de
commande.

Notez que le argument name de gl_register_action() spécifie le nom par lequel un utilisateur peut référencer l'action dans son fichier de configuration. Cela lui permet de réassocier l'action à une séquence de touches alternative. Pour que cela fonctionne, il est nécessaire d'appeler gl_register_action() entre l'appel à new_GetLine() et le premier appel à gl_get_

lin
e().

ARCHIVAGE MANUEL DE

L'HISTORIQUE

Par défaut, chaque fois qu'une ligne est saisie par l'utilisateur, elle est automatiquement ajoutée à la liste d'historique, juste avant que gl_get_line() retourne la ligne à l'appelant. C'est pratique pour la majorité des applications, mais il y a aussi des applications qui ont besoin d'un contrôle plus fin sur ce qui est ajouté à la liste d'historique. Dans de tels cas, l'ajout automatique des lignes saisies à la liste d'historique peut être désactivé en appelant la fonction gl_automatic

_history(). 
  int gl_automatic_history(GetLine *gl, int enable)
;

Si cette fonction est appelée avec son argument enable défini à 0, gl_get_line() n'archivera pas automatiquement les lignes saisies ultérieurement. L'archivage automatique peut être réactivé plus tard, en appelant à nouveau cette fonction, avec son argument enable défini à 1. Pendant que l'archivage automatique de l'historique est désactivé, l'application appelante peut utiliser la fonction gl_append_history() pour ajouter des lignes à la liste d'historique selon les

besoins. 
  int gl_append_history(GetLine *gl, const char *line)
;

L' argument line spécifie la ligne à ajouter à la liste d'historique. Cela doit être une chaîne normale terminée par ' '. Si cette chaîne contient des caractères de nouvelle ligne, la ligne qui sera archivée dans la liste d'historique sera terminée par le premier d'entre eux. Sinon, elle sera terminée par le terminateur ' '. Si la ligne est plus longue que la longueur maximale de ligne d'entrée, qui a été spécifiée lorsque new_GetLine() a été appelée, lorsque la ligne sera rappelée, elle sera tronquée à la longueur réelle de la ligne gl_get_li

ne().

Si la réussite, gl_append_history() retourne 0. Sinon, elle retourne une valeur non nulle, et définit errno à l'une des valeurs

suivantes. 
   EINVAL  -  L'un des arguments passés à
              gl_append_history() était NULL.
   ENOMEM  -  La ligne spécifiée était plus longue que la taille allouée
              du tampon d'historique (telle que spécifiée lorsque
              new_GetLine() a été appelée), elle n'a donc pas pu être
archivée.

Une description textuelle de l'erreur peut être obtenue en appelant éventuellement gl_error_message(). Notez qu'après une telle erreur, la liste d'historique reste dans un état valide pour recevoir de nouvelles lignes d'historique, il y a donc peu d'inconvénient à simplement ignorer le statut de retour de gl_append_

CONFIGURATION DIVERSE DE

L'HISTORIQUE

Si vous souhaitez changer la taille du tampon d'historique qui a été initialement spécifiée dans l'appel à new_GetLine(), vous pouvez le faire avec la fonction gl_resize_his

L' argument histlen spécifie la nouvelle taille en octets, et si vous spécifiez cela comme 0, le tampon sera

Par exemple, un tampon de 1000 octets pourrait tout aussi bien stocker 10 lignes de longueur moyenne de 100 octets, ou 2 lignes de longueur moyenne de 50 octets.   void gl_limit_history(GetLine *gl, int max_lines);

Pour rejeter des lignes du tampon d'historique, utilisez la fonction gl_clear_history().

  void gl_toggle_history(GetLine *gl, int enable);

Définir l'argument enable à 0 désactive le mécanisme d'historique, et le définir à 1 le réactive. Lorsque l'historique est désactivé, aucune nouvelle ligne ne sera ajoutée à la liste d'historique, et les raccourcis clavier de recherche d'historique agiront comme s'il n'y avait rien dans le tampon d'historique.

CHANGEMENT DE TERMINAL

La fonction constructeur new_GetLine() suppose que l'entrée doit être lue depuis stdin, et la sortie écrite vers stdout. La fonction suivante vous permet de passer à différents flux d'entrée et de sortie.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

L'argument gl est l'objet qui a été retourné par new_GetLine(). L'argument input_fp spécifie le flux à lire, et output_fp spécifie le flux à écrire. Seulement si les deux font référence à un terminal, l'entrée de terminal interactive sera activée. Sinon, gl_get_line() appellera simplement fgets() pour lire l'entrée de commande. Si les deux flux font référence à un terminal, alors ils doivent faire référence au même terminal, et le type de ce terminal doit être spécifié via l'argument term. La valeur de l'argument term est recherchée dans la base de données d'informations de terminal (terminfo ou termcap), afin de déterminer quelles séquences de contrôle spéciales sont nécessaires pour contrôler divers aspects du terminal. new_GetLine(), par exemple, passe la valeur de retour de getenv("TERM") dans cet argument. Notez que si un ou les deux de input_fp et output_fp ne font pas référence à un terminal, alors il est légal de passer NULL à la place d'un type de terminal.

Notez que si vous souhaitez passer des descripteurs de fichiers à gl_change_terminal(), vous pouvez le faire en créant des enveloppes de flux stdio en utilisant la fonction POSIX fdopen().

GESTION DES ÉVÉNEMENTS EXTERNES

Par défaut, gl_get_line() ne retourne pas avant qu'une ligne d'entrée complète n'ait été entrée par l'utilisateur, ou qu'une erreur ne se produise. Dans les programmes qui doivent surveiller les E/S d'autres sources que le terminal, il y a deux options.

  1. Utilisez les fonctions décrites dans la page de manuel
     gl_io_mode(3) pour passer
     gl_get_line() en mode serveur non bloquant. Dans ce mode,
     gl_get_line() devient une fonction d'édition de ligne incrémentale
     non bloquante qui peut être appelée en toute sécurité depuis une boucle
     d'événements externe. Bien que ce soit une méthode très polyvalente,
     elle implique de prendre en charge certaines responsabilités qui sont
     normalement effectuées en arrière-plan par
     gl_get_line().
  2. Pendant que gl_get_line() attend une entrée clavier de l'utilisateur,
     vous pouvez lui demander de surveiller également l'activité sur des
     descripteurs de fichiers arbitraires, tels que des sockets réseau, des
     pipes, etc., et de faire en sorte qu'elle appelle des fonctions de votre
     choix lorsqu'une activité est détectée. Cela fonctionne sur tout système
     disposant de l'appel système select(), ce qui est la plupart, sinon
     toutes les variantes d'Unix.

L'enregistrement d'un descripteur de fichier à surveiller par gl_get_line() implique d'appeler la fonction gl_watch_fd().

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si cela renvoie non nul, cela signifie soit que vos arguments sont invalides, soit que cette fonctionnalité n'est pas prise en charge sur le système hôte.

L'argument fd est le descripteur de fichier à surveiller. L'argument event spécifie quel type d'activité est d'intérêt, choisi parmi les valeurs énumérées suivantes :

  GLFD_READ   -  Surveiller l'arrivée de données à lire.
  GLFD_WRITE  -  Surveiller la capacité d'écrire sur le descripteur
                 de fichier sans bloquer.
  GLFD_URGENT -  Surveiller l'arrivée de données urgentes hors bande
                 sur le descripteur de fichier.

L'argument callback est la fonction à appeler lorsque l'activité sélectionnée est détectée. Elle doit être définie avec la macro suivante, définie dans libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

L'argument data de la fonction gl_watch_fd() est passé à la fonction de rappel pour son propre usage, et peut pointer vers n'importe quoi, y compris NULL. Le descripteur de fichier et l'argument d'événement sont également passés à la fonction de rappel, ce qui permet potentiellement à la même fonction de rappel d'être enregistrée pour plus d'un type d'événement et/ou plus d'un descripteur de fichier. La valeur de retour de la fonction de rappel doit être l'une des valeurs suivantes.

  GLFD_ABORT    -  Indiquer à gl_get_line() d'avorter. Lorsque cela
                   se produit, gl_get_line() renvoie
                   NULL, et un appel ultérieur à
                   gl_return_status() renverra
                   GLR_FDABORT. Notez que si l'application a
                   besoin que errno ait toujours une valeur
                   significative lorsque gl_get_line() renvoie
                   NULL, la fonction de rappel doit définir
                   errno de manière appropriée.
  GLFD_REFRESH  -  Redessiner la ligne d'entrée puis continuer
                   à attendre l'entrée. Renvoie ceci si votre
                   rappel a écrit sur le terminal.
  GLFD_CONTINUE -  Continuer à attendre l'entrée, sans
                   redessiner la ligne.

Notez qu'avant d'appeler le rappel, gl_get_line() bloque la plupart des signaux, et laisse ses propres gestionnaires de signaux installés, donc si vous avez besoin de capturer un signal particulier, vous devrez à la fois installer temporairement votre propre gestionnaire de signaux et débloquer le signal. La gestion des signaux est étonnamment difficile à réaliser de manière fiable sans conditions de course. Dans gl_get_line(), beaucoup de soin a été apporté pour permettre aux applications d'effectuer une gestion fiable des signaux autour de gl_get_line(). Cette section explique comment tirer parti de

cela.

À titre d'exemple des problèmes qui peuvent survenir si l'application n'est pas écrite correctement, imaginez qu'une application ait un gestionnaire de signal SIGINT qui définit un drapeau global. Selon l'application, cela peut ou ne peut pas être une catastrophe, mais au minimum cela déroutera

l'utilisateur.

suit.

importants sont

interceptés.

La première chose que gl_get_line() fait, chaque fois qu'elle est appelée, est d'utiliser la fonction POSIX sigprocmask() pour bloquer la livraison de tous les signaux pour lesquels elle est actuellement configurée pour intercepter. bientôt.

suit. 
a. Elle utilise la fonction POSIX sigaction() pour enregistrer
   un gestionnaire de signal temporaire pour tous les signaux qu'elle
   est configurée pour intercepter. Ce gestionnaire de signal fait deux
   choses.

      dans une variable de portée fichier.

      sigsetjmp() comme premier argument, et
      une valeur non nulle comme second argument.

   de l'argument struct sigaction act de
   l'appel à sigaction() est configuré pour contenir tous
   les signaux que gl_get_line() intercepte. Cela
   garantit qu'un seul signal sera intercepté à la fois par
   notre gestionnaire de signal, ce qui à son tour garantit que
   plusieurs instances de notre gestionnaire de signal ne se
   marchent pas sur les pieds.

   gl_get_line() débloque tous les signaux qu'elle
   est configurée pour intercepter.

   des entrées au clavier.

   d'intérêt.
e. Elle rétablit ensuite les gestionnaires de signal qui ont été
   déplacés par celui qui vient d'être
installé.

First, note that when a call to siglongjmp() causes sigsetjmp() to return, provided that the savesigs argument of sigsetjmp() was non-zero, as specified above, the signal process mask is restored to how it was when sigsetjmp() was called. 1. If so instructed by the gl_get_line() configuration
attributes of the signal that was caught,
gl_get_line() restores the terminal attributes to
the state that they had when gl_get_line() was
called. This is particularly important for signals that
suspend or terminate the process, since otherwise the
terminal would be left in an unusable state.

2. It then reinstates the application's signal handlers.

3. Then it uses the C standard-library raise()
function to re-send the application the signal that
was caught.

3. Next it unblocks delivery of the signal that we just
sent. This results in the signal that was just sent
via raise(), being caught by the application's
original signal handler, which can now handle it as it
sees fit.

4. If the signal handler returns (ie. it doesn't terminate
the process), gl_get_line() blocks delivery of the
above signal again.

5. It then undoes any actions performed in the first of the
above steps, and redisplays the line, if the signal
configuration calls for this.

6. gl_get_line() then either resumes trying to
read a character, or aborts, depending on the
configuration of the signal that was caught.

What the above steps do in essence is to take asynchronously delivered signals and handle them synchronously, one at a time, at a point in the code where gl_get_line() has complete control over its environment.

LA TAILLE DU TERMINAL

Sur la plupart des systèmes, la combinaison de l'ioctl TIOCGWINSZ et du signal SIGWINCH est utilisée pour maintenir une idée précise de la taille du terminal. La taille du terminal est réinterrogée chaque fois que gl_get_line() est appelé et à chaque réception d'un signal SIGWINCH.

Sur les quelques systèmes où ce mécanisme n'est pas disponible, au démarrage, new_GetLine() recherche d'abord les variables d'environnement LINES et COLUMNS. Si celles-ci ne sont pas trouvées, ou si elles contiennent des valeurs inutilisables, alors si une base de données d'informations terminal comme terminfo ou termcap est disponible, la taille par défaut du terminal est recherchée dans cette base de données. Si cela échoue également à fournir la taille du terminal, une taille par défaut de 80 colonnes par 24 lignes est utilisée.

Même sur les systèmes qui prennent en charge ioctl(TIOCGWINSZ), si le terminal se trouve à l'autre extrémité d'une ligne série, le pilote de terminal n'a généralement aucun moyen de détecter quand un redimensionnement se produit ou de demander quelle est la taille actuelle. Dans de tels cas, aucun SIGWINCH n'est envoyé au processus, et les dimensions renvoyées par ioctl(TIOCGWINSZ) ne sont pas correctes. La seule façon de gérer de tels cas est de fournir un moyen à l'utilisateur d'entrer une commande qui indique au système distant la nouvelle taille. Cette commande appellerait alors la fonction gl_set_term_size() pour informer gl_get_line() du changement de taille.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

Les arguments ncolumn et nline sont utilisés pour spécifier les nouvelles dimensions du terminal et ne doivent pas être inférieurs à 1. Sur les systèmes qui prennent en charge ioctl(TIOCGWINSZ), cette fonction appelle d'abord ioctl(TIOCSWINSZ) pour informer le pilote de terminal du changement de taille. En mode I/O serveur non bloquant, si une ligne est en cours de saisie, la ligne de saisie est alors redessinée pour s'adapter à la taille modifiée. Enfin, les nouvelles valeurs sont enregistrées dans gl pour une utilisation future par gl_get_line().

La fonction gl_terminal_size() vous permet de consulter la taille actuelle du terminal et d'installer une taille de secours alternative pour les cas où la taille n'est pas disponible. Attention, la taille du terminal ne sera pas disponible si vous lisez à partir d'un pipe ou d'un fichier, de sorte que les valeurs par défaut peuvent être importantes même sur les systèmes qui prennent en charge les moyens de connaître la taille du terminal.

  typedef struct {
    int nline;        /* Le terminal a nline lignes */
    int ncolumn;      /* Le terminal a ncolumn colonnes */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

Cette fonction met d'abord à jour les dimensions du terminal de secours de gl_get_line(), puis enregistre ses découvertes dans la valeur de retour.

Les arguments def_ncolumn et def_nline spécifient le nombre par défaut de colonnes et de lignes du terminal à utiliser si la taille du terminal ne peut pas être déterminée via ioctl(TIOCGWINSZ) ou les variables d'environnement.

MASQUER CE QUE VOUS TAPEZ

Lorsque vous entrez des informations sensibles, telles que des mots de passe, il est préférable de ne pas afficher le texte que vous saisissez sur le terminal. De plus, ce texte ne doit pas être enregistré dans la liste d'historique, car quelqu'un qui trouverait votre terminal sans surveillance pourrait le rappeler, ou quelqu'un qui fouillerait dans vos répertoires pourrait le voir dans votre fichier d'historique. Dans cet esprit, la fonction gl_echo_mode() vous permet d'activer et de désactiver l'affichage et l'archivage de tout texte saisi ultérieurement dans les appels à gl_get_line().

  int gl_echo_mode(GetLine *gl, int enable);

L'argument enable spécifie si le texte saisi doit être visible ou non. S'il est égal à 0, les lignes saisies par la suite ne seront pas visibles sur le terminal et ne seront pas enregistrées dans la liste d'historique. S'il est égal à 1, les lignes saisies ultérieures seront affichées au fur et à mesure de leur saisie, et à condition que l'historique n'ait pas été désactivé via un appel à gl_toggle_history(), elles seront également archivées dans la liste d'historique. Enfin, si l'argument enable est égal à -1, le mode d'écho est laissé inchangé, ce qui vous permet de consulter le réglage actuel sans modification via la valeur de retour. Dans tous les cas, la valeur de retour de la fonction est 0 si l'écho a été désactivé avant que la fonction ne soit appelée, et 1 s'il était activé.

Lorsque l'écho est désactivé, notez que bien que la complétion par tabulation complète invisiblement votre préfixe autant que possible, les complétions ambiguës ne seront pas affichées.

REQUÊTES DE CARACTÈRE UNIQUE

Utiliser gl_get_line() pour demander à l'utilisateur une réponse d'un seul caractère est gênant pour l'utilisateur, car il doit appuyer sur la touche Entrée ou Retour avant que le caractère tapé ne soit renvoyé au programme. Ainsi, la fonction gl_query_char() a été fournie pour les requêtes de caractère unique de ce type.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

Cette fonction affiche le prompt spécifié au début d'une nouvelle ligne, et attend que l'utilisateur tape un caractère. Lorsque l'utilisateur tape un caractère, gl_query_char() l'affiche à droite du prompt, démarre une nouvelle ligne, puis renvoie le caractère au programme appelant. La valeur de retour de la fonction est le caractère qui a été tapé. Si la lecture a dû être interrompue pour une raison quelconque, EOF est renvoyé à la place. Dans ce dernier cas, l'application peut appeler la fonction précédemment documentée gl_return_status() pour savoir ce qui s'est mal passé. Il pourrait s'agir, par exemple, de la réception d'un signal, ou du dépassement du délai d'inactivité optionnel.

Si l'utilisateur appuie simplement sur Entrée, la valeur de l'argument defchar est substituée. Cela signifie que lorsque l'utilisateur appuie sur Retour ou Entrée, le caractère spécifié dans defchar est affiché après le prompt, comme si l'utilisateur l'avait tapé, et est également renvoyé à l'application appelante. Si un tel remplacement n'est pas important, passez simplement '0 comme valeur de defchar.

Si le caractère entré est un caractère non imprimable, il est affiché symboliquement. Par exemple, le contrôle-A est affiché sous forme de ^A, et les caractères supérieurs à 127 sont affichés en octal, précédés d'une barre oblique inverse.

Comme avec gl_get_line(), l'écho du caractère entré peut être désactivé à l'aide de la fonction gl_echo_mode().

Si le processus appelant est suspendu en attendant que l'utilisateur tape sa réponse, le curseur est déplacé sur la ligne suivant la ligne du prompt, puis lorsque le processus reprend, le prompt est redessiné, et gl_query_char() reprend l'attente que l'utilisateur tape un caractère.

Notez qu'en mode serveur non bloquant (voir gl_io_mode(3)), si une ligne d'entrée incomplète est en cours de lecture lorsque gl_query_char() est appelé, la ligne d'entrée partielle est supprimée et effacée du terminal, avant que le nouveau prompt ne soit affiché. Le prochain appel à gl_get_line() commencera donc l'édition d'une nouvelle ligne.

LECTURE DE CARACTÈRES BRUTS

Alors que la fonction gl_query_char() affiche visiblement un prompt à l'utilisateur pour un caractère, et affiche ce qu'il a tapé, la fonction gl_read_char() lit un caractère signal de l'utilisateur, sans rien écrire sur le terminal, ni perturber une ligne d'entrée incomplètement saisie. Cela signifie qu'elle peut être appelée non seulement entre les appels à gl_get_line(), mais aussi depuis les fonctions de rappel que l'application a enregistrées pour être appelées par gl_get_line().

  int gl_read_char(GetLine *gl);

En cas de succès, la valeur de retour de gl_read_char() est le caractère lu. En cas d'échec, EOF est renvoyé, et la fonction gl_return_status() peut être appelée pour savoir ce qui s'est mal passé. Les possibilités incluent le dépassement du délai d'inactivité optionnel, la réception d'un signal configuré pour arrêter gl_get_line(), ou un blocage de l'I/O du terminal, en mode I/O serveur non bloquant.

Attention, certaines touches du clavier, comme les touches de fonction et les touches fléchées, génèrent généralement au moins 3 caractères chacune, de sorte qu'un seul appel à gl_read_char() ne sera pas

suffisant pour

identifier de telles frappes.

AFFICHAGE DYNAMIQUE DE

TEXTE

Entre les appels à gl_get_line(), la fonction gl_display_text() fournit un moyen pratique d'afficher des paragraphes de texte, justifiés à gauche et répartis sur une ou plusieurs lignes du terminal selon les contraintes de la largeur courante du terminal. Des exemples d'utilisation de cette fonction se trouvent dans les programmes de démonstration, où elle est utilisée pour afficher des introductions. Dans ces exemples, l'utilisation avancée de préfixes, suffixes et lignes de remplissage optionnels pour dessiner une boîte autour du texte est également

illustrée. 
  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl n'est pas actuellement connecté à un terminal, par exemple si la sortie d'un programme qui utilise gl_get_line() est acheminée via un tube vers un autre programme ou redirigée vers un fichier, alors la valeur du paramètre def_width est utilisée comme largeur du

terminal.

L'argument indentation spécifie le nombre de caractères à utiliser pour indenter chaque ligne de sortie. L'argument fill_char spécifie le caractère qui sera utilisé pour effectuer cette

indentation.

L'argument prefix peut être soit NULL, soit une chaîne à placer au début de chaque nouvelle ligne (après toute indentation). De même, l'argument suffix peut être soit NULL, soit une chaîne à placer à la fin de chaque ligne. Le suffixe est placé aligné sur le bord droit du terminal, et tout espace entre son premier caractère et le dernier mot de cette ligne est rempli par le caractère spécifié via l'argument fill_char. Normalement, le caractère de remplissage est une

espace.

L'argument start indique à gl_display_text() combien de caractères ont déjà été écrits sur la ligne de terminal courante, et indique ainsi l'index de colonne de départ du curseur. Puisque la valeur de retour de gl_display_text() est l'index de colonne de fin du curseur, en passant la valeur de retour d'un appel à l'argument start de l'appel suivant, un paragraphe réparti sur plus d'une chaîne peut être composé en appelant gl_display_text() pour chaque portion successive du paragraphe. Notez que des caractères de nouvelle ligne littéraux sont nécessaires à la fin de chaque paragraphe pour forcer le début d'une nouvelle

ligne.

t() renv
oie -1.

JEUX DE CARACTÈRES

INTERNATIONAUX

Depuis la version 1.4.0 de libtecla, gl_get_line() est propre aux 8 bits. Cela signifie que tous les caractères 8 bits imprimables dans la locale actuelle de l'utilisateur sont désormais affichés tels quels et inclus dans la ligne de saisie retournée. En supposant que le programme appelant contienne correctement un appel comme

celui-ci, 
  setlocale(LC_CTYPE, "")
;

alors la locale actuelle est déterminée par la première des variables d'environnement LC_CTYPE, LC_ALL, et LANG, dont on trouve qu'elle contient un nom de locale valide. Si aucune de ces variables n'est définie, ou si le programme néglige d'appeler setlocale, alors la locale par défaut C est utilisée, qui est l'ASCII 7 bits américain. Sur la plupart des plateformes de type unix, vous pouvez obtenir une liste des locales valides en tapant la commande

:

-a

à l'invite du shell. Une documentation supplémentaire sur la manière dont l'utilisateur peut utiliser cela pour saisir des caractères internationaux se trouve dans la page de manu

THREADS

Dans un programme multi-thread, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des versions réentrantes des fonctions système, lorsque cela est disponible. Malheureusement, ni terminfo ni termcap n'ont été conçus pour être réentrants, vous ne po
