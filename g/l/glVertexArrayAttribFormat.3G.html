NAME

glVertexArrayAttribFormat - define the format and dimensions of an array attribute slot

C SPECIFICATION

void glVertexArrayAttribFormat(
    GLuint vaobj,
    GLuint attribindex,
    GLint size,
    GLenum type,
    GLboolean normalized,
    GLuint relativeoffset
);
void glVertexArrayAttribIFormat(
    GLuint vaobj,
    GLuint attribindex,
    GLint size,
    GLenum type,
    GLuint relativeoffset
);
void glVertexArrayAttribLFormat(
    GLuint vaobj,
    GLuint attribindex,
    GLint size,
    GLenum type,
    GLuint relativeoffset
);

PARAMETERS

vaobj

Specifies the vertex array object to be modified. If vaobj is zero, the commands modify the conventional vertex array objects.

attribindex

Specifies the index of the vertex attribute to be modified.

size

Specifies the number of components per vertex attribute. Must be a value between 1 and 4, inclusive. Otherwise, a {@GL_INVALID_VALUE} error is generated.

type

Specifies the data type of each component in the vertex attribute array. For {@code glVertexArrayAttribFormat}, symbolic constants such as {@GL_FLOAT}, {@GL_HALF_FLOAT}, {@GL_INT}, {@GL_UNSIGNED_INT}, {@GL_SHORT}, {@GL_UNSIGNED_SHORT}, {@GL_BYTE}, {@GL_UNSIGNED_BYTE}, {@GL_DOUBLE}, {@GL_FIXED}, {@GL_INT_2_10_10_10_REV}, {@GL_UNSIGNED_INT_2_10_10_10_REV}, {@GL_UNSIGNED_INT_10_10_10_2} are accepted. For {@code glVertexArrayAttribIFormat}, {@GL_INT}, {@GL_UNSIGNED_INT}, {@GL_SHORT}, {@GL_UNSIGNED_SHORT}, {@GL_BYTE}, {@GL_UNSIGNED_BYTE}, {@GL_INT_2_10_10_10_REV}, {@GL_UNSIGNED_INT_2_10_10_10_REV}, {@GL_UNSIGNED_INT_10_10_10_2} are accepted. For {@code glVertexArrayAttribLFormat}, {@GL_DOUBLE} are accepted. Otherwise, a {@GL_INVALID_ENUM} error is generated.

normalized

For {@code glVertexArrayAttribFormat}, specifies whether fixed-point data should be normalized. If {@GL_TRUE}, fixed-point data will be liearly mapped to the range [-1,1] for signed data types or [0,1] for unsigned data types. If {@GL_FALSE}, the data will be used directly. {@code normalized} is ignored if {@code type} is not a fixed-point type.

relativeoffset

Specifies the offset, in bytes, of the first component of the vertex attribute in each array record. The value must be a multiple of the size of {@code type}.

DESCRIPTION

These commands specify the format of the vertex array attributes for a given vertex array object (VAO) and attribute index. Specifically, {@code glVertexArrayAttribFormat} defines the size, type, and normalized behavior of an attribute, while {@code glVertexArrayAttribIFormat} is similar but for integer attributes, and {@code glVertexArrayAttribLFormat} is for double-precision floating-point attributes.

The {@code attribindex} parameter specifies the attribute index to be modified. The {@code size} parameter indicates the number of components (1 to 4). The {@code type} parameter specifies the data type. {@code normalized} is a boolean flag for {@code glVertexArrayAttribFormat} indicating whether fixed-point data should be normalized. The {@code relativeoffset} parameter defines the byte offset of the attribute within its vertex data structure.

These functions are used in conjunction with {@code glVertexArrayVertexBinding} to associate buffer objects with vertex attributes and define how they are fetched.

Use of {@code glVertexArrayAttribFormat} with integer types ({@GL_INT}, {@GL_UNSIGNED_INT}, etc.) implies that the attribute data will be converted to floating-point format before being passed to the vertex shader. Integer attributes that should be treated as integers in the vertex shader must be configured using {@code glVertexArrayAttribIFormat} or {@code glVertexArrayAttribLFormat}.

The {@code type} parameter for {@code glVertexArrayAttribFormat} accepts additional types such as {@GL_HALF_FLOAT}, which are not available for {@code glVertexArrayAttribIFormat} or {@code glVertexArrayAttribLFormat}. Conversely, {@code glVertexArrayAttribLFormat} specifically accepts {@GL_DOUBLE}.

NOTES

These commands are available only if the GL version is 4.3 or greater.

The effect of these commands is to modify the state associated with the vertex array object {@code vaobj}. When a VAO is bound, these settings are used to interpret the data in the buffer objects attached to the vertex attribute bindings.

The {@code normalized} parameter is only effective when {@code type} is a fixed-point type (e.g., {@GL_BYTE}, {@GL_SHORT}, {@GL_INT}, {@GL_UNSIGNED_BYTE}, {@GL_UNSIGNED_SHORT}, {@GL_UNSIGNED_INT}).

ERRORS

On the}-(\u2714) indicates that the function is available.

GL_INVALID_VALUE is generated if {@code size} is not between 1 and 4.

GL_INVALID_OPERATION is generated if {@code vaobj} is not zero or a name of an existing vertex array object.

GL_INVALID_ENUM is generated if {@code type} is not one of the accepted values.

GL_INVALID_OPERATION is generated if {@code relativeoffset} is not a multiple of the size of {@code type}.

GL_INVALID_OPERATION is generated if {@code glVertexArrayAttribIFormat} is called with a {@code type} that is not an integer type.

GL_INVALID_OPERATION is generated if {@code glVertexArrayAttribLFormat} is called with a {@code type} that is not {@GL_DOUBLE}.
