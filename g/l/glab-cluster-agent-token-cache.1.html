NOM

glab-cluster-agent-token-cache - Gérer les jetons mis en cache du GitLab Agent.

SYNTAXE

glab cluster agent token-cache [flags]

DESCRIPTION

Gère les jetons mis en cache du GitLab Agent créés par 'glab cluster agent get-token'.

Ce groupe de commandes vous permet de lister et de vider les jetons qui sont mis en cache localement dans le trousseau de clés et le cache du système de fichiers.

Stockage du cache

La CLI GitLab met en cache les jetons d'agent dans deux emplacements :

1.
Trousseau de clés - Utilise le trousseau de clés du système (Gestionnaire d'informations d'identification Windows, Trousseau d'accès macOS, Service de sécurité Linux)
2.
Système de fichiers - Stocke les jetons dans le répertoire de cache de l'utilisateur sous forme de fichiers chiffrés.

Le cache améliore les performances en évitant la nécessité de créer de nouveaux jetons pour chaque opération kubectl lors de l'utilisation de 'glab cluster agent update-kubeconfig'.

Format de la clé de cache

Les jetons mis en cache sont stockés à l'aide d'un format de clé qui inclut :

  • URL de l'instance GitLab encodée en Base64
  • ID de l'agent

Cela garantit que les jetons sont correctement isolés par instance GitLab et par agent.

OPTIONS HERITEES DES COMMANDES PARENTES

-h, --help[=false] Afficher l'aide pour cette commande.

-R, --repo="" Sélectionner un autre dépôt. Peut utiliser le format PROPRIETAIRE/REPO ou GROUPE/NAMESPACE/REPO. Accepte également une URL complète ou une URL Git.
