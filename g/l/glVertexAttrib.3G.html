PARAMÈTRES

index

Spécifie l'index de l'attribut de sommet générique à modifier.

v0, v1, v2, v3

Pour les commandes scalaires, spécifie les nouvelles valeurs à utiliser pour l'attribut de sommet spécifié.

v

Pour les commandes vectorielles (glVertexAttrib*v), spécifie un pointeur vers un tableau de valeurs à utiliser pour l'attribut de sommet générique.

type

Pour les commandes empaquetées (glVertexAttribP*), spécifie le type d'empaquetage utilisé sur les données. Ce paramètre doit être GL_INT_2_10_10_10_REV ou GL_UNSIGNED_INT_2_10_10_10_REV, pour spécifier respectivement des données signées ou non signées, ou GL_UNSIGNED_INT_10F_11F_11F_REV pour spécifier des données en virgule flottante.

normalized

Pour les commandes empaquetées, si GL_TRUE, alors les valeurs doivent être converties en valeurs en virgule flottante par normalisation. Sinon, elles sont converties directement en valeurs en virgule flottante. Si type indique un format en virgule flottante, alors la valeur normalized doit être GL_FALSE.

value

Pour les commandes empaquetées, spécifie la nouvelle valeur empaquetée à utiliser pour l'attribut de sommet spécifié.

DESCRIPTION

La famille d'emplacements de fonction glVertexAttrib permet à une application de passer des attributs de sommet génériques dans des emplacements numérotés.

Les attributs génériques sont définis comme des valeurs à quatre composantes organisées en un tableau. La première entrée de ce tableau est numérotée 0, et la taille du tableau est spécifiée par la constante dépendant de l'implémentation GL_MAX_VERTEX_ATTRIBS. Les éléments individuels de ce tableau peuvent être modifiés avec un appel glVertexAttrib qui spécifie l'index de l'élément à modifier et une valeur pour cet élément.

Ces commandes peuvent être utilisées pour spécifier une, deux, trois ou les quatre composantes de l'attribut de sommet générique spécifié par index. Un 1 dans le nom de la commande indique qu'une seule valeur est passée, et elle sera utilisée pour modifier la première composante de l'attribut de sommet générique. La deuxième et la troisième composantes seront mises à 0, et la quatrième composante sera mise à 1. De même, un 2 dans le nom de la commande indique que des valeurs sont fournies pour les deux premières composantes, la troisième composante sera mise à 0, et la quatrième composante sera mise à 1. Un 3 dans le nom de la commande indique que des valeurs sont fournies pour les trois premières composantes et que la quatrième composante sera mise à 1, alors qu'un 4 dans le nom indique que des valeurs sont fournies pour les quatre composantes.

Les lettres s, f, i, d, ub, us, et ui indiquent si les arguments sont de type short, float, int, double, unsigned byte, unsigned short ou unsigned int. Lorsque v est ajouté au nom, les commandes peuvent prendre un pointeur vers un tableau de telles valeurs.

Des lettres supplémentaires en majuscules peuvent indiquer des modifications supplémentaires du comportement par défaut de la fonction glVertexAttrib :

Les commandes contenant N indiquent que les arguments seront passés comme des valeurs en virgule fixe qui sont mises à l'échelle vers une plage normalisée selon les règles de conversion de composante définies par la spécification OpenGL. Les valeurs signées sont censées représenter des valeurs en virgule fixe dans la plage [-1,1], et les valeurs non signées sont censées représenter des valeurs en virgule fixe dans la plage [0,1].

Les commandes contenant I indiquent que les arguments sont étendus à des entiers signés ou non signés complets.

Les commandes contenant P indiquent que les arguments sont stockés comme des composantes empaquetées au sein d'un type naturel plus grand.

Les commandes contenant L indiquent que les arguments sont des quantités complètes de 64 bits et doivent être passés directement aux entrées de shader déclarées comme des types double précision de 64 bits.

Les variables d'attribut du langage de shader OpenGL peuvent être de type mat2, mat3 ou mat4. Les attributs de ces types peuvent être chargés à l'aide des emplacements de fonction glVertexAttrib . Les matrices doivent être chargées dans des emplacements d'attribut générique successifs dans l'ordre des colonnes, avec une colonne de la matrice dans chaque emplacement d'attribut générique.

Une variable d'attribut définie par l'utilisateur déclarée dans un vertex shader peut être liée à un index d'attribut générique en appelant glBindAttribLocation(). Cela permet à une application d'utiliser des noms de variables plus descriptifs dans un vertex shader. Un changement ultérieur de l'attribut de sommet générique spécifié sera immédiatement reflété comme un changement de la variable d'attribut correspondante dans le vertex shader.

La liaison entre un index d'attribut de sommet générique et une variable d'attribut définie par l'utilisateur dans un vertex shader fait partie de l'état d'un objet programme, mais la valeur courante de l'attribut de sommet générique n'en fait pas partie. La valeur de chaque attribut de sommet générique fait partie de l'état courant, tout comme les attributs de sommet standard, et elle est maintenue même si un objet programme différent est utilisé.

Une application peut librement modifier les attributs de sommet génériques qui ne sont pas liés à une variable d'attribut de vertex shader nommée. Ces valeurs sont simplement maintenues comme partie de l'état courant et ne seront pas accédées par le vertex shader. Si un attribut de sommet générique lié à une variable d'attribut dans un vertex shader n'est pas mis à jour pendant l'exécution du vertex shader, le vertex shader utilisera à plusieurs reprises la valeur courante de l'attribut de sommet générique.

REMARQUES

Les attributs de sommet génériques peuvent être mis à jour à tout moment.

Il est possible pour une application de lier plus d'un nom d'attribut au même index d'attribut de sommet générique. Cela est appelé de l'aliasing, et cela n'est autorisé que si une seule des variables d'attribut aliasées est active dans le vertex shader, ou si aucun chemin à travers le vertex shader ne consomme plus d'un des attributs aliasés au même emplacement. Les implémentations OpenGL ne sont pas tenues de faire de la détection d'erreurs pour détecter l'aliasing, elles sont autorisées à supposer que l'aliasing ne se produira pas, et elles sont autorisées à employer des optimisations qui ne fonctionnent qu'en l'absence d'aliasing.

Il n'existe aucune disposition pour lier des attributs de sommet standard ; par conséquent, il n'est pas possible d'aliaser des attributs génériques avec des attributs standard.

Les versions glVertexAttribL ne sont disponibles que si la version GL est 4.1 ou supérieure.

GL_UNSIGNED_INT_10F_11F_11F_REV est accepté pour type par glVertexAttribP* seulement si la version GL est 4.4 ou supérieure.

ERREUR

GL_INVALID_VALUE est généré si index est supérieur ou égal à GL_MAX_VERTEX_ATTRIBS.

GL_INVALID_ENUM est généré si glVertexAttribP* est utilisé avec un type autre que GL_INT_2_10_10_10_REV, GL_UNSIGNED_INT_2_10_10_10_REV, ou GL_UNSIGNED_INT_10F_11F_11F_REV.

GL_INVALID_ENUM est généré si glVertexAttribL est utilisé avec un type autre que GL_DOUBLE.
