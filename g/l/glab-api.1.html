NOM

glab-api - Effectuer une requête authentifiée à l'API GitLab.

SYNTAXE

glab api [options]

DESCRIPTION

Effectue une requête HTTP authentifiée à l'API GitLab et affiche la réponse. L'argument endpoint doit être soit un chemin d'un endpoint de l'API GitLab v4, soit graphql pour accéder à l'API GraphQL de GitLab.

  • Documentation de l'API REST GitLab ⟨https://docs.gitlab.com/api/⟩
  • Documentation GraphQL de GitLab ⟨https://docs.gitlab.com/api/graphql/⟩

Si le répertoire courant est un répertoire Git, utilise l'hôte GitLab authentifié du répertoire courant. Sinon, gitlab.com sera utilisé. Pour annuler le nom d'hôte GitLab, utilisez --hostname.

Ces valeurs de remplacement, lorsqu'elles sont utilisées dans l'argument endpoint, sont remplacées par des valeurs du dépôt du répertoire courant :

  • :branch
  • :fullpath
  • :group
  • :id
  • :namespace
  • :repo
  • :user
  • :username

Méthodes : la méthode de requête HTTP par défaut est GET, si aucun paramètre n'est ajouté, et POST sinon. Annulez la méthode avec --method.

Passez une ou plusieurs valeurs --raw-field au format clé=valeur pour ajouter des paramètres encodés en JSON au corps du POST.

L'indicateur --field se comporte comme --raw-field avec une conversion de type magique basée sur le format de la valeur :

  • Les valeurs littérales true, false, null, et les nombres entiers sont convertis en types JSON appropriés.
  • Les valeurs de remplacement :namespace, :repo, et :branch sont remplies avec des valeurs du dépôt du répertoire courant.
  • Si la valeur commence par @, le reste de la valeur est interprété comme un nom de fichier à partir duquel lire la valeur. Passez - pour lire depuis l'entrée standard.

Pour les requêtes GraphQL, tous les champs autres que query et operationName sont interprétés comme des variables GraphQL.

Le corps de la requête brute peut être passé depuis l'extérieur via un fichier spécifié par --input. Passez - pour lire depuis l'entrée standard. Dans ce mode, les paramètres spécifiés avec les indicateurs --field sont sérialisés en paramètres de requête URL.

En mode --paginate, toutes les pages de résultats sont demandées séquentiellement jusqu'à ce qu'il n'y ait plus de pages de résultats. Pour les requêtes GraphQL :

  • La requête originale doit accepter une variable $endCursor: String.
  • La requête doit récupérer l'ensemble des champs pageInfo{ hasNextPage, endCursor } d'une collection.

OPTIONS

-F, --field=[] Ajoute un paramètre de type inféré. Change la méthode HTTP par défaut en « POST ».

-H, --header=[] Ajoute un en-tête de requête HTTP supplémentaire.

--hostname="" Le nom d'hôte GitLab pour la requête. Par défaut, 'gitlab.com', ou l'hôte authentifié dans le répertoire Git courant.

-i, --include[=false] Inclut les en-têtes de réponse HTTP dans la sortie.

--input="" Le fichier à utiliser comme corps pour la requête HTTP.

-X, --method="GET" La méthode HTTP pour la requête.

--paginate[=false] Effectue des requêtes HTTP supplémentaires pour récupérer toutes les pages de résultats.

-f, --raw-field=[] Ajoute un paramètre de chaîne.

--silent[=false] N'affiche pas le corps de la réponse.

OPTIONS HERITEES DES COMMANDES PARENTES

-h, --help[=false] Affiche l'aide pour cette commande.

EXEMPLE

$ glab api projects/:fullpath/releases
$ glab api projects/gitlab-com%2Fwww-gitlab-com/issues
$ glab api issues --paginate
$ glab api graphql -f query="query { currentUser { username } }"
$ glab api graphql -f query='
  query {
    project(fullPath: "gitlab-org/gitlab-docs") {
      name
      forksCount
      statistics {
        wikiSize
      }
      issuesEnabled
      boards {
        nodes {
          id
          name
        }
      }
    }
  }
'
$ glab api graphql --paginate -f query='
  query($endCursor: String) {
    project(fullPath: "gitlab-org/graphql-sandbox") {
      name
      issues(first: 2, after: $endCursor) {
        edges {
          node {
            title
          }
        }
        pageInfo {
          endCursor
          hasNextPage
        }
      }
    }
  }'
