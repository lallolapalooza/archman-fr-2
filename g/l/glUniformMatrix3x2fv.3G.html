PARAMÈTRES

location

Spécifie l'emplacement de la variable uniforme à modifier.

count

Pour les commandes de vecteur (glUniform*v), spécifie le nombre d'éléments à modifier. Cela doit être 1 si la variable uniforme ciblée n'est pas un tableau, et 1 ou plus si c'est un tableau.

Pour les commandes de matrice (glUniformMatrix*), spécifie le nombre de matrices à modifier. Cela doit être 1 si la variable uniforme ciblée n'est pas un tableau de matrices, et 1 ou plus si c'est un tableau de matrices.

transpose

Pour les commandes de matrice, spécifie s'il faut transposer la matrice lorsque les valeurs sont chargées dans la variable uniforme.

v0, v1, v2, v3

Pour les commandes scalaires, spécifie les nouvelles valeurs à utiliser pour la variable uniforme spécifiée.

value

Pour les commandes de vecteur et de matrice, spécifie un pointeur vers un tableau de count valeurs qui seront utilisées pour mettre à jour la variable uniforme spécifiée.

DESCRIPTION

glUniform modifie la valeur d'une variable uniforme ou d'un tableau de variables uniformes. L'emplacement de la variable uniforme à modifier est spécifié par location, qui doit être une valeur retournée par glGetUniformLocation(). glUniform opère sur l'objet programme qui a été rendu partie de l'état courant en appelant glUseProgram().

Les commandes glUniform{1|2|3|4}{f|i|ui} sont utilisées pour changer la valeur de la variable uniforme spécifiée par location en utilisant les valeurs passées en arguments. Le nombre spécifié dans la commande doit correspondre au nombre de composantes dans le type de données de la variable uniforme spécifiée (par ex., 1 pour float, int, unsigned int, bool ; 2 pour vec2, ivec2, uvec2, bvec2, etc.). Le suffixe f indique que des valeurs en virgule flottante sont passées ; le suffixe i indique que des valeurs entières sont passées ; le suffixe ui indique que des valeurs entières non signées sont passées, et ce type doit également correspondre au type de données de la variable uniforme spécifiée. Les i variantes de cette fonction doivent être utilisées pour fournir des valeurs pour les variables uniformes définies as int, ivec2, ivec3, ivec4, ou des tableaux de ceux-ci. Les variantes ui de cette fonction doivent être utilisées pour fournir des valeurs pour les variables uniformes définies comme unsigned int, uvec2, uvec3, uvec4, ou des tableaux de celles-ci. Les variantes f doivent être utilisées pour fournir des valeurs pour les variables uniformes de type float, vec2, vec3, vec4, ou des tableaux de celles-ci. Les variantes i, ui ou f peuvent être utilisées pour fournir des valeurs pour les variables uniformes de type bool, bvec2, bvec3, bvec4, ou des tableaux de celles-ci. La variable uniforme sera définie sur false si la valeur d'entrée est 0 ou 0.0f, et elle sera définie sur true dans le cas contraire.

Toutes les variables uniformes actives définies dans un objet programme sont initialisées à 0 lorsque l'objet programme est lié avec succès. Elles conservent les valeurs qui leur sont attribuées par un appel à glUniform jusqu'à la prochaine opération de liaison réussie sur l'objet programme, moment auquel elles sont à nouveau initialisées à 0.

Les commandes glUniform{1|2|3|4}{f|i|ui}v peuvent être utilisées pour modifier une seule variable uniforme ou un tableau de variables uniformes. Ces commandes passent un compte et un pointeur vers les valeurs à charger dans une variable uniforme ou un tableau de variables uniformes. Un compte de 1 doit être utilisé si la modification de la valeur d'une seule variable uniforme, et un compte de 1 ou supérieur peut être utilisé pour modifier un tableau entier ou une partie d'un tableau. Lors du chargement de n éléments à partir d'une position arbitraire m dans un tableau de variables uniformes, les éléments m + n - 1 du tableau seront remplacés par les nouvelles valeurs. Si m + n - 1 est supérieur à la taille du tableau de variables uniformes, les valeurs de tous les éléments du tableau au-delà de la fin du tableau seront ignorées. Le nombre spécifié dans le nom de la commande indique le nombre de composantes pour chaque élément de value, et il doit correspondre au nombre de composantes du type de données du type de données de la variable uniforme spécifiée (par exemple, 1 pour float, int, bool ; 2 pour vec2, ivec2, bvec2, etc.). Le type de données spécifié dans le nom de la commande doit correspondre au type de données de la variable uniforme spécifiée comme décrit précédemment pour glUniform{1|2|3|4}{f|i|ui}.

Pour les tableaux de variables uniformes, chaque élément du tableau est considéré comme étant du type indiqué dans le nom de la commande (par exemple, glUniform3f ou glUniform3fv peuvent être utilisés pour charger un tableau de variables uniformes de type vec3). Le nombre d'éléments du tableau de variables uniformes à modifier est spécifié par count

Les commandes glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv sont utilisées pour modifier une matrice ou un tableau de matrices. Les nombres dans le nom de la commande sont interprétés comme la dimensionnalité de la matrice. Le nombre 2 indique une matrice 2 × 2 (c'est-à-dire 4 valeurs), le nombre 3 indique une matrice 3 × 3 (c'est-à-dire 9 valeurs), et le nombre 4 indique une matrice 4 × 4 (c'est-à-dire 16 valeurs). Les matrices non carrées sont explicitées, le premier nombre représentant le nombre de colonnes et le second nombre représentant le nombre de lignes. Par exemple, 2x4 indique une matrice 2 × 4 avec 2 colonnes et 4 lignes (c'est-à-dire 8 valeurs). Si transpose est GL_FALSE, chaque matrice est supposée être fournie en ordre de colonne. Si transpose est GL_TRUE, chaque matrice est supposée être fournie en ordre de ligne. L'argument count indique le nombre de matrices à passer. Un compte de 1 doit être utilisé si la modification de la valeur d'une seule matrice, et un compte supérieur à 1 peut être utilisé pour modifier un tableau de matrices.

NOTES

glUniform1i et glUniform1iv sont les deux seules fonctions qui peuvent être utilisées pour charger des variables uniformes définies comme types échantillonneurs. Charger des échantillonneurs avec toute autre fonction entraînera une erreur GL_INVALID_OPERATION.

Si count est supérieur à 1 et que la variable uniforme indiquée n'est pas un tableau, une erreur GL_INVALID_OPERATION est générée et la variable uniforme spécifiée restera inchangée.

À l'exception des exceptions précédentes, si le type et la taille de la variable uniforme tels que définis dans le shader ne correspondent pas au type et à la taille spécifiés dans le nom de la commande utilisée pour charger sa valeur, une erreur GL_INVALID_OPERATION sera générée et la variable uniforme spécifiée restera inchangée.

Si location est une valeur autre que -1 et qu'elle ne représente pas un emplacement de variable uniforme valide dans l'objet programme actuel, une erreur sera générée et aucune modification ne sera apportée au stockage de la variable uniforme de l'objet programme actuel. Si location est égal à -1, les données passées seront silencieusement ignorées et la variable uniforme spécifiée ne sera pas modifiée.

ERREURS

GL_INVALID_OPERATION est généré s'il n'y a pas d'objet programme courant.

GL_INVALID_OPERATION est généré si la taille de la variable uniforme déclarée dans le shader ne correspond pas à la taille indiquée par la commande glUniform.

GL_INVALID_OPERATION est généré si l'une des variantes entières signées ou non signées de cette fonction est utilisée pour charger une variable uniforme de type float, vec2, vec3, vec4, ou un tableau de ceux-ci, ou si l'une des variantes à virgule flottante de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières signées de cette fonction est utilisée pour charger une variable uniforme de type unsigned int, uvec2, uvec3, uvec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes entières non signées de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est généré si location est un emplacement uniforme invalide pour l'objet programme actuel et que location n'est pas égal à -1.

GL_INVALID_VALUE est généré si count est inférieur à 0.

GL_INVALID_OPERATION est généré si count est supérieur à 1 et que la variable uniforme indiquée n'est pas une variable tableau.

GL_INVALID_OPERATION est généré si un échantillonneur est chargé en utilisant une commande autre que glUniform1i et glUniform1iv.

NAME

glUniformMatrix2x3fv - specify the value of a uniform variable

C SPECIFICATION

void glUniformMatrix2x3fv(GLint location, GLsizei count, GLboolean transpose, const GLfloat *value);

PARAMETERS

location
Specifies the location of the uniform variable to be modified.
count
Specifies the number of matrices that will be downloaded and sent to the uniform variable.
transpose
Specifies whether each individual matrix is transposed before being sent to the GL server. Should be GL_FALSE if each is not transposed, and GL_TRUE if each is transposed.
value
Specifies a pointer to an array of `count` matrix values that will be sent to the uniform variable. Array elements are taken in column-major order.

DESCRIPTION

`glUniformMatrix2x3fv` specifies the value of a uniform variable when the uniform variable is of type `mat2x3` or `mat3x2`.

`location` is the location of the uniform variable to be modified, and is obtained as described in glUniformLocation .

If `location` is that of a vertex shader uniform variable and the program contains multiple active vertex shader variants, the command is applied to all active variants. If `location` is that of a fragment shader uniform variable and the program contains multiple active fragment shader variants, the command is applied to all active variants.

`count` is the number of matrix values to be written. This must be 1 unless the uniform variable is an array of matrices. If `location` corresponds to an array of matrices, then `count` matrices will be written.

`transpose` is used to indicate whether the matrix or matrices are to be transposed. If `transpose` is GL_TRUE, the `value` array contains matrices in row-major order. If `transpose` is GL_FALSE, the `value` array contains matrices in column-major order.

`value` points to an array of `2 * 3 * count` or `3 * 2 * count` floating-point values. The values are loaded into the uniform variable in column-major order unless `transpose` is GL_TRUE, in which case they are loaded in row-major order.

`glUniformMatrix2x3fv` provides a simple, direct way to set the values of uniform variables of type `mat2x3` or `mat3x2`.

NOTES

If the uniform variable declared in the GLSL shader is a sampler, its type must match the type of this command. For example, a uniform variable declared as `sampler2D` requires `glUniform1i` or `glUniform1iv` to set its value.

If `count` is greater than 1, then `location` must refer to the location of the first element of an array uniform variable. Otherwise, a GL error will be generated.

A GL error is generated if `count` is greater than 1 and `location` does not refer to the location of an array uniform variable.

A GL error is generated if `transpose` is not GL_FALSE or GL_TRUE.

ERRORS

`GL_INVALID_OPERATION` is generated if zero is added to the name of an invalid uniform location.

`GL_INVALID_VALUE` is generated if `count` is negative.

`GL_INVALID_OPERATION` is generated if `transpose` is not GL_FALSE or GL_TRUE.

`GL_INVALID_OPERATION` is generated if the named uniform variable is not a matrix type or if the dimensions of the matrix type do not match the dimensions specified in the function name.

`GL_INVALID_OPERATION` is generated if the currently bound program object is not a value allowed as a program object.
