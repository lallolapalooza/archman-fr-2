DESCRIPTIO

N

glGetFramebufferAttachmentParameteriv et glGetNamedFramebufferAttachmentParameteriv renvoient les paramètres des attaches d'un objet framebuffer

spécifié.

Pour glGetFramebufferAttachmentParameteriv, l'objet framebuffer est celui lié à target, qui doit être l'un de GL_DRAW_FRAMEBUFFER, GL_READ_FRAMEBUFFER ou GL_FRAMEBUFFER. GL_FRAMEBUFFER est équivalent à GL_DRAW_FRAMEBUFFER. Les tampons des framebuffers par défaut peuvent également être interrogés s'ils sont liés à target

.

Pour glGetNamedFramebufferAttachmentParameteriv, framebuffer est le nom de l'objet framebuffer. Si framebuffer est zéro, le framebuffer de dessin par défaut est

interrogé.

Si le framebuffer spécifié est un objet framebuffer, attachment doit être l'un de GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT GL_DEPTH_STENCIL_ATTACHMENT, ou GL_COLOR_ATTACHMENTi, où i est compris entre zéro et la valeur de GL_MAX_COLOR_ATTACHMENTS moins

un.

Si le framebuffer spécifié est un framebuffer par défaut, target, attachment doit être l'un de GL_FRONT_LEFT, GL_FRONT_RIGHT, GL_BACK_LEFT, GL_BACK_RIGHT, GL_DEPTH ou GL_STENCIL, identifiant le tampon

correspondant.

Si attachment est GL_DEPTH_STENCIL_ATTACHMENT, le même objet doit être lié à la fois aux points d'attach de profondeur et de pochoir de l'objet framebuffer, et des informations sur cet objet sont

renvoyées.

Au retour réussi, si pname est GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE, alors params contiendra l'un de GL_NONE, GL_FRAMEBUFFER_DEFAULT, GL_TEXTURE, ou GL_RENDERBUFFER, identifiant le type d'objet qui contient l'image attachée. Les autres valeurs acceptées pour pname dépendent du type d'objet, comme décrit

ci-dessous.

Si la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE est GL_NONE, alors soit aucun framebuffer n'est lié à target ; soit un framebuffer par défaut est interrogé, attachment est GL_DEPTH ou GL_STENCIL, et le nombre de bits de profondeur ou de pochoir, respectivement, est zéro. Dans ce cas, interroger pname GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME renverra zéro, et toutes les autres interrogations généreront une

erreur.

Si la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE n'est pas GL_NONE, ces interrogations s'appliquent à tous les autres types de framebuffer

:
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_RED_SIZE, GL_FRAMEBUFFER_ATTACHMENT_GREEN_SIZE, GL_FRAMEBUFFER_ATTACHMENT_BLUE_SIZE, GL_FRAMEBUFFER_ATTACHMENT_ALPHA_SIZE, GL_FRAMEBUFFER_ATTACHMENT_DEPTH_SIZE ou GL_FRAMEBUFFER_ATTACHMENT_STENCIL_SIZE, alors params contiendra le nombre de bits dans le composant rouge, vert, bleu, alpha, profondeur ou pochoir correspondant de l'attach spécifié. Si le composant demandé n'est pas présent dans l'attach, ou si aucun stockage de données ou image de texture n'a été spécifié pour l'attach, alors params contiendra
zéro.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_COMPONENT_TYPE, alors params contiendra le format des composants de l'attach spécifié, l'un de GL_FLOAT, GL_INT, GL_UNSIGNED_INT, GL_SIGNED_NORMALIZED, ou GL_UNSIGNED_NORMALIZED pour les composants flottants, entiers signés, entiers non signés, à virgule fixe normalisée signée, ou à virgule fixe normalisée non signée respectivement. Seuls les tampons de couleur peuvent avoir des composants entiers. Si aucun stockage de données ou image de texture n'a été spécifié pour l'attach, alors params contiendra GL_NONE. Cette interrogation ne peut pas être effectuée pour un attach combiné profondeur+pochoir, car il n'a pas un format
unique.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_COLOR_ENCODING, alors params contiendra l'encodage des composants de l'attach spécifié, l'un de GL_LINEAR ou GL_SRGB pour les composants linéaires ou encodés sRGB, respectivement. Seuls les composants de tampon de couleur peuvent être encodés sRGB ; de tels composants sont traités comme décrit dans la spécification OpenGL. Pour un framebuffer par défaut, l'encodage des couleurs est déterminé par l'implémentation. Pour les objets framebuffer, les composants sont encodés sRGB si le format interne d'un attach de couleur est l'un des formats SRGB rendables en couleur. Si l'attach n'est pas un attach de couleur, ou si aucun stockage de données ou image de texture n'a été spécifié pour l'attach, alors params contiendra GL_LINEAR
.

Si la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE est GL_RENDERBUFFER,

alors
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME, params contiendra le nom de l'objet renderbuffer qui contient l'image
attachée.

Si la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE est GL_TEXTURE,

alors
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME, alors params contiendra le nom de l'objet texture qui contient l'image
attachée.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_TEXTURE_LEVEL, alors params contiendra le niveau mipmap de l'objet texture qui contient l'image
attachée.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_TEXTURE_CUBE_MAP_FACE et la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME est le nom d'un objet texture de cube map, alors params contiendra la face de cube map de l'objet texture cubemap qui contient l'image attachée. Sinon params contiendra
zéro.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_LAYERED, alors params contiendra GL_TRUE si un niveau entier d'une texture tridimensionnelle, d'une texture de cube map, ou d'une texture de tableau unidimensionnelle ou bidimensionnelle est attaché. Sinon, params contiendra GL_FALSE
.
•Si pname est GL_FRAMEBUFFER_ATTACHMENT_TEXTURE_LAYER ; la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME est le nom d'une texture tridimensionnelle, ou d'une texture de tableau unidimensionnelle ou bidimensionnelle ; et la valeur de GL_FRAMEBUFFER_ATTACHMENT_LAYERED est GL_FALSE, alors params contiendra la couche de texture qui contient l'image attachée. ERREUR

S

GL_INVALID_ENUM est généré par glGetFramebufferAttachmentParameteriv si target n'est pas l'une des cibles de framebuffer

acceptées.

GL_INVALID_OPERATION est généré par glGetNamedFramebufferAttachmentParameteriv si framebuffer n'est pas zéro ou le nom d'un objet framebuffer

existant.

GL_INVALID_ENUM est généré si pname n'est pas valide pour la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE, comme décrit

ci-dessus.

GL_INVALID_OPERATION est généré si attachment n'est pas l'un dedes points d'attachement de framebuffer acceptés, comme décrit

ci-dessus.

GL_INVALID_OPERATION est généré si la valeur de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE est GL_NONE et pname n'est pas GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME ou GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE

.

GL_INVALID_OPERATION est généré si attachment est GL_DEPTH_STENCIL_ATTACHMENT et que des objets différents sont liés aux points d'attachement depth et stencil de target

.

GL_INVALID_OPERATION est généré si attachment est GL_DEPTH_STENCIL_ATTACHMENT et pname est GL_FRAMEBUFFER_ATTACHMENT_COMPONENT_TYP

E
