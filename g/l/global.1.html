GLOBAL(1) Manuel des commandes générales GLOBAL(1)

NOM

global - affiche les emplacements des symboles donnés

SYNTAXE

global [-adEFGilMnNqrstTvx][-S dir][-e] motif
global -c[dFiIMoOPqrsTv] préfixe
global -f[adlnqrstvx][-L liste-fichiers][-S dir] fichiers
global -g[aEGilMnoOqtvVx][-L liste-fichiers][-S dir][-e] motif [fichiers]
global -I[ailMnqtvx][-S dir][-e] motif
global -P[aEGilMnoOqtvVx][-S dir][-e] motif
global -p[qrv]
global -u[qv]

DESCRIPTION

Global trouve les emplacements des symboles donnés dans les fichiers source C, Yacc, Java, PHP et assembleur, et affiche le nom du chemin, le numéro de ligne et l'image de la ligne des emplacements. Global peut localiser non seulement les définitions mais aussi les références et d'autres symboles.

Global peut traiter un arbre source, c'est-à-dire un répertoire contenant des sous-répertoires et des fichiers source, comme un projet. Avant d'utiliser cette commande, vous devez exécuter gtags(1) à la racine du projet que vous souhaitez étudier pour créer des fichiers de tags. Ensuite, vous pouvez utiliser la commande global n'importe où dans le projet. Vous n'avez pas besoin de spécifier où se trouve le fichier de tags. Au lieu de cela, global le localise lui-même.

Vous pouvez spécifier une expression régulière pour motif. Global comprend deux versions différentes de la syntaxe des expressions régulières : de base et étendue (par défaut).

COMMANDES

Les commandes suivantes sont disponibles :

<aucune commande> motif
Aucune commande signifie une commande de recherche de tag. Affiche les tags qui correspondent à motif. Par défaut, affiche les tags de définition.
-c, --completion[=limite] [préfixe]
Affiche les symboles qui commencent par préfixe. Si préfixe n'est pas donné, affiche tous les symboles. Si limite est donnée, affiche jusqu'à limite lignes.
-f, --file fichiers
Affiche tous les tags des fichiers. Cette commande implique l'option -x.
-g, --grep motif [fichiers]
Affiche toutes les lignes qui correspondent au motif. Si des fichiers sont donnés, cette commande recherche dans ces fichiers.
--help
Affiche un message d'utilisation.
-I, --idutils motif
Affiche toutes les lignes qui correspondent au motif. Cette fonction utilise idutils(1) comme moteur de recherche. Pour utiliser cette commande, vous devez installer idutils(1) sur votre système et exécuter gtags(1) avec l'option -I.
-P, --path [motif]
Affiche les noms de chemins qui correspondent au motif. Si aucun motif n'est donné, affiche tous les chemins du projet.
-p, --print-dbpath
Affiche l'emplacement de ´GTAGS´.
--print nom
Affiche l'emplacement de nom, qui peut être l'un des éléments suivants : ´root´, ´dbpath´ ou ´conf´. ´root´ signifie le répertoire racine du projet. ´dbpath´ signifie un répertoire où résident les bases de données de tags. ´conf´ signifie le fichier de configuration.
-u, --update
Met à jour les fichiers de tags de manière incrémentielle. Cette commande invoque en interne gtags(1). Vous pouvez exécuter cette commande n'importe où dans le projet, contrairement à gtags(1).
--version
Affiche le numéro de version.

OPTIONS

Les options suivantes sont disponibles :

-a, --absolute
Affiche les noms de chemins absolus. Par défaut, affiche les noms de chemins relatifs.
--color quand
Utilise la couleur pour mettre en surbrillance le motif dans la ligne ; quand peut être l'un des : jamais, toujours ou auto (par défaut). La couleur par défaut est du texte rouge gras sur fond actuel ; la variable d'environnement GREP_COLORS (seuls mt et ms sont effectifs à présent) ou GREP_COLOR la définit. Cette option est effective pour les commandes suivantes : <aucune commande>, -f, -g, -I, -P.
-C, --directory dir
Change le répertoire avant de faire tout le travail, y compris l'analyse des paramètres.
-d, --definition
Affiche les emplacements des définitions.
-e, --regexp motif
Utilise motif comme motif ; utile pour protéger les motifs commençant par ´-´.
-E, --extended-regexp
Interprète motif comme une expression régulière étendue. C'est le défaut.
--encode-path caractères
Convertit les caractères de chemin dans caractères en un symbole ´%´, suivi de la représentation hexadécimale à deux chiffres du caractère. Un espace sera converti en ´%20´.
-F, --first-match
Arrête la recherche sans parcourir tous les fichiers de tags listés dans GTAGSLIBPATH lorsque des tags sont trouvés dans un fichier de tags. C'est le défaut.
--from-here contexte
Détermine le type de tag par contexte. Sa syntaxe devrait être ´numéro_ligne:chemin´. Si le contexte est une définition du motif alors utilise -r, sinon s'il y a au moins une définition du motif alors utilise -d, sinon utilise -s. Si cette option est spécifiée alors -d, -r et -s sur la ligne de commande sont ignorés. Une expression régulière n'est pas autorisée pour motif. Cette option suppose une utilisation dans des environnements conversationnels tels que les éditeurs et les IDE.
-G, --basic-regexp
Interprète motif comme une expression régulière de base. Le défaut est une expression régulière étendue.
--gtagsconf fichier
Définit la variable d'environnement GTAGSCONF sur fichier.
--gtagslabel label
Définit la variable d'environnement GTAGSLABEL sur label.
-i, --ignore-case
Ignore la casse dans le motif.
-L, --file-list fichier
Obtient les fichiers de fichier en plus des arguments. Le fichier fichier peut être défini sur '-' pour accepter une liste de fichiers provenant de l'entrée standard. Les noms de fichiers doivent être séparés par un saut de ligne.
-l, --local
Affiche uniquement les tags qui existent sous le répertoire courant.
--literal
Exécute une recherche littérale au lieu d'une recherche par expression régulière. Cette option fonctionne avec la commande de recherche de tags, la commande -g, la commande -P et la commande -I.
-M, --match-case
La recherche est sensible à la casse. C'est le défaut.
--match-part partie
Spécifie comment la complétion du nom de chemin doit correspondre, où partie est l'un des éléments suivants : ´first´, ´last´ ou ´all´ (par défaut). Cette option n'est valide qu'avec la commande -c en conjonction avec -P.
-n, --nofilter
Supprime le filtre de tri et le filtre de conversion de chemin.
-N, --nearness[=début]
Utilise la méthode de tri par proximité (tri par le plus proche de début) pour la sortie. Par défaut

ult, la méthode de tri alphabétique est utilisée. Cette option est efficace pour la commande de recherche de tags, la commande -P et la commande -g. À titre d'exception, la commande -g ignore cette option lorsque des fichiers sont spécifiés par des arguments. La proximité est définie par le nombre de répertoires parents à remonter pour atteindre la cible. Le résultat du tri par proximité est la concaténation des éléments suivants ([0]-[n]) dans cet ordre. La valeur par défaut de start est le répertoire courant. 
[0] Si le point de départ est un fichier, sortie de la recherche locale dans le fichier.
[1] Sortie de la recherche locale dans le répertoire de départ, à l'exception de [0].
[2] Sortie de la recherche locale dans le répertoire parent, à l'exception de [0]-[1].
[3] Sortie de la recherche locale dans le grand-parent, à l'exception de [0]-[2].
... (répéter jusqu'au répertoire racine du projet)
[n] Sortie de la recherche locale dans le répertoire racine du projet, à l'exception de [0]-[n-1].
Dans chaque répertoire, les éléments sont triés par ordre alphabétique.
-O, --only-other
Traiter uniquement les fichiers texte autres que le code source, comme ´README´. Cette option n'est valide qu'avec la commande -g ou -P. Cette option remplace l'option -o.
-o, --other
Traiter non seulement les fichiers source mais aussi les fichiers texte autres que le code source, comme ´README´. Cette option n'est valide qu'avec la commande -g ou -P.
--path-style format
Afficher les noms de chemins en utilisant le format, qui peut être l'un des suivants : ´relative´, ´absolute´, ´shorter´, ´abslib´ ou ´through´. ´relative´ signifie chemin relatif. ´absolute´ signifie chemin absolu. ´shorter´ signifie le plus court entre le chemin relatif et le chemin absolu. ´abslib´ signifie chemin absolu pour les bibliothèques (GTAGSLIBPATH) et chemin relatif pour le reste. ´through´ signifie le chemin relatif depuis le répertoire racine du projet (format interne de GPATH). La valeur par défaut est ´relative´. L'option --path-style a une priorité plus élevée que l'option -a.
--print0
Afficher chaque enregistrement suivi d'un caractère nul au lieu d'un saut de ligne.
-q, --quiet
Mode silencieux.
-r, --reference, --rootdir
Afficher les tags de référence. La référence désigne la référence à un symbole qui a des définitions. Avec l'option -p, afficher le répertoire racine du projet.
--result format
Afficher en utilisant le format, qui peut être l'un des suivants : ´path´ (par défaut), ´ctags´, ´ctags-x´, ´grep´ ou ´cscope´. Les options --result=ctags et --result=ctags-x sont équivalentes aux options -t et -x respectivement. L'option --result a une priorité plus élevée que les options -t et -x.
--single-update file
Mettre à jour les fichiers de tags avec gtags(1) en utilisant l'option --single-update. Il est considéré que file a été ajouté, mis à jour ou supprimé, et qu'il n'y a aucun changement dans les autres fichiers. Cette option implique l'option -u.
-s, --symbol
Afficher les autres tags de symboles. Autre symbole désigne la référence à un symbole qui n'a pas de définition.
-S, --scope dir
Afficher uniquement les tags qui existent sous le répertoire dir. C'est similaire à l'option -l, mais vous n'avez pas besoin de changer de répertoire.
-T, --through
Parcourir tous les fichiers de tags listés dans GTAGSLIBPATH. Par défaut, arrêter la recherche dès qu'un tag est trouvé. Cette option est ignorée si l'option -s, -r ou -l est spécifiée.
-t, --tags
Utiliser le format standard ctags.
-V, --invert-match
Inverser le sens de la correspondance, pour sélectionner les lignes ne correspondant pas. Cette option n'est valide qu'avec les commandes -g ou -P.
-v, --verbose
Mode verbeux.
-x, --cxref
Utiliser le format standard ctags cxref (avec -x).

EXEMPLES

$ ls -F
Makefile      src/    lib/
$ gtags
$ ls G*
GPATH   GRTAGS  GTAGS
$ global main
src/main.c
$ (cd src; global main)
main.c
$ global -x main
main              10 src/main.c  main (argc, argv) {
$ global -f src/main.c
main              10 src/main.c  main (argc, argv) {
func1             55 src/main.c  func1() {
func2             72 src/main.c  func2() {
func3            120 src/main.c  func3() {
$ global -x '^[sg]et'
set_num           20 lib/util.c  set_num(values) {
get_num           30 lib/util.c  get_num() {
$ global -rx set_num
set_num          113 src/op.c            set_num(32);
set_num          225 src/opop.c               if (set_num(0) > 0) {
$ global strlen
$ (cd /usr/src/sys; gtags)
$ export GTAGSLIBPATH=/usr/src/sys
$ global -a strlen
/usr/src/sys/libkern/strlen.c
$ (cd /usr/src/lib; gtags)
$ GTAGSLIBPATH=/usr/src/lib:/usr/src/sys
$ global -a strlen
/usr/src/lib/libc/string/strlen.c

FICHIERS

´GTAGS´
Fichier de tags pour les définitions.
´GRTAGS´
Fichier de tags pour les références.
´GPATH´
Fichier de tags pour les fichiers source.
´GTAGSROOT´
Si la variable d'environnement GTAGSROOT n'est pas définie et que le fichier ´GTAGSROOT´ existe dans le même répertoire que ´GTAGS´, alors global définit GTAGSROOT avec le contenu du fichier.
´gtags.conf´, ´$HOME/.globalrc´
Données de configuration pour GNU Global. Voir gtags.conf(5).

ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de global :

GREP_COLOR
La couleur à utiliser pour --color ; GREP_COLORS a la priorité.
GREP_COLORS
La couleur (mt ou ms) à utiliser pour --color ; voir grep(1).
GTAGSBLANKENCODE
Si cette variable est définie, l'option --encode-path=" <TAB>" est spécifiée.
GTAGSCACHE
La taille du cache B-tree. La valeur par défaut est 50000000 (octets).
GTAGSCONF
Fichier de configuration.
GTAGSDBPATH
Le répertoire dans lequel se trouvent les fichiers de tags. Cette valeur est ignorée lorsque GTAGSROOT n'est pas définie. L'utilisation de cette variable n'est pas recommandée.
GTAGSFORCECPP
Si cette variable est définie, chaque fichier dont le suffixe est ´.h´ est traité comme un fichier source C++.
GTAGSLABEL
Étiquette de configuration. La valeur par défaut est default.
GTAGSLIBPATH
Si cette variable est définie, elle est utilisée comme chemin pour rechercher les fonctions de bibliothèque. Si le symbole donné n'est pas trouvé dans le projet actuel, global recherche également dans ces chemins. Comme seul ´GTAGS´ est ciblé lors de la récupération, cette variable est ignorée lorsque -r ou -s est spécifié.
GTAGSLOGGING
Si cette variable est définie, ´$GTAGSLOGGING´ est utilisé comme nom de chemin d'un fichier journal. Il n'y a pas de valeur par défaut.
GTAGSROOT
Le répertoire racine du projet. Habituellement, il est reconnu par l'existence de ´GTAGS´. L'utilisation de cette variable n'est pas recommandée.
GTAGSTHROUGH
Si cette variable est définie, l'option -T est spécifiée.
GTAGSOBJDIR, MAKEOBJDIR
Si l'une des deux variables est définie, elle est utilisée comme nom du répertoire d'objets de style BSD. La première a la priorité. La valeur par défaut est ´obj´.
GTAGSOBJDIRPREFIX, MAKEOBJDIRPREFIX
Si l'une des deux variables est définie, elle est utilisée comme préfixe du répertoire d'objets de style BSD. La première a la priorité. La valeur par défaut est ´/usr/obj´.

CONFIGURATION

Les variables de configuration suivantes affectent l'exécution de global :

icase_path (booléen)
Ignorer les distinctions de casse dans le pattern.

DIAGNOSTICS

Global se termine avec une valeur non nulle si une erreur s'est produite, 0 sinon.
