NOM

gl_Layer - contient la couche sélectionnée d'une pièce jointe de framebuffer multi-couches

DÉCLARATION

// Phase de géométrie

out int gl_Layer ;

// Phase de fragment

in int gl_Layer ;

DESCRIPTION

Dans le langage de géométrie, gl_Layer est utilisé pour sélectionner une couche spécifique (ou une face et une couche de carte de cube) dans une pièce jointe de framebuffer multi-couches. La couche réelle utilisée proviendra de l'un des sommets du primitiva en cours de traitement. Le sommet dont provient la couche est indéfini, il est donc recommandé d'écrire la même valeur à gl_Layer pour tous les sommets de la primitiva. Si un shader assigne statiquement une valeur à gl_Layer, le mode de rendu par couches est activé. Si un shader assigne statiquement une valeur à gl_Layer, et qu'il existe un chemin d'exécution à travers le shader qui ne définit pas gl_Layer, alors la valeur de gl_Layer est indéfinie pour les invocations du shader qui empruntent ce chemin.

Lorsqu'elle est utilisée avec un tableau de textures de cartes de cube, la variable de sortie gl_Layer prend une valeur spéciale. Au lieu de faire référence à la couche uniquement, elle est utilisée pour sélectionner une face de carte de cube et une couche. Définir gl_Layer à la valeur couche*6+face permettra de rendre vers la face de la carte de cube définie dans la couche. Les valeurs des faces sont les suivantes :

Valeur de Face Cible résultante
0 GL_TEXTURE_CUBEMAP_POSITIVE_X
1 GL_TEXTURE_CUBEMAP_NEGATIVE_X
2 GL_TEXTURE_CUBEMAP_POSITIVE_Y
3 GL_TEXTURE_CUBEMAP_NEGATIVE_Y
4 GL_TEXTURE_CUBEMAP_POSITIVE_Z
5 GL_TEXTURE_CUBEMAP_NEGATIVE_Z

Par exemple, pour rendre vers la face positive y de la carte de cube située dans la 5ème couche du tableau de cartes de cube, gl_Layer doit être définie à 5*6+2.

La variable d'entrée gl_Layer dans le langage de fragment aura la même valeur qui a été écrite dans la variable de sortie gl_Layer dans le langage de géométrie. Si la phase de géométrie n'assigne pas dynamiquement une valeur à gl_Layer, la valeur de gl_Layer dans la phase de fragment sera indéfinie. Si la phase de géométrie ne fait aucune assignation statique à gl_Layer, l'entrée gl_Layer dans la phase de fragment sera zéro. Sinon, la phase de fragment lira la même valeur écrite par la phase de géométrie, même si cette valeur est hors de portée. Si un shader de fragment contient un accès statique à gl_Layer, il sera comptabilisé dans la limite définie par l'implémentation pour le nombre maximum d'entrées de la phase de fragment.
