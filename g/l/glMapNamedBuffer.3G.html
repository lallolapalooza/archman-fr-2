DESCRIPTIO

N

glMapBuffer et glMapNamedBuffer associent le magasin de données entier d'un objet tampon spécifié à l'espace d'adressage du client. Les données peuvent ensuite être directement lues et/ou écrites par rapport au pointeur retourné, en fonction de la politique acces

s

spécifiée. Un pointeur vers le début de la plage associée est retourné une fois que toutes les opérations en attente sur cet objet tampon sont terminées, et peut être utilisé pour modifier et/ou interroger la plage correspondante du

magasin de données selon la valeur de
access :•
GL_READ_ONLY indique que le pointeur retourné peut être utilisé pour lire les données de l'objet tampon.•
GL_WRITE_ONLY indique que le pointeur retourné peut être utilisé pour modifier les données de l'objet tampon.•

GL_READ_WRITE indique que le pointeur retourné peut être utilisé pour lire et modifier les données de l'objet

tampon.

Si une erreur est générée, un pointeur NULL est retourné. Si aucune erreur ne se produit, le pointeur retourné reflétera une allocation alignée sur la valeur

de

GL_MIN_MAP_BUFFER_ALIGNMENT en unités machine de

base.

Les valeurs des pointeurs retournés ne peuvent pas être passées en tant que valeurs de paramètres aux commandes GL. Par exemple, elles ne peuvent pas être utilisées pour spécifier des pointeurs de tableau, ou pour spécifier ou interroger des données d'image de pixel ou de texture ; de telles actions produisent des résultats indéfinis, bien que les implémentations puissent ne pas vérifier un tel comportement pour des raisons de performance. Aucune erreur GL n'est générée si le pointeur retourné est accédé d'une manière incohérente avec access (par exemple, utilisé pour lire depuis une association faite avec access GL_WRITE_ONLY ou pour écrire vers une association faite avec acces

s

GL_READ_ONLY), mais le résultat est indéfini et des erreurs système (possiblement incluant la terminaison du programme) peuvent survenir. Les associations aux magasins de données des objets tampons peuvent avoir des caractéristiques de performance non standard. Par exemple, de telles associations peuvent être marquées comme des régions de mémoire non mettables en cache, et dans de tels cas, lire depuis celles-ci peut être très lent. Pour assurer des performances optimales, le client devrait utiliser l'association d'une manière cohérente avec les valeurs de GL_BUFFER_USAGE pour

l'objet t
ampon et de

access. Utiliser une association d'une manière incohérente avec ces valeurs est susceptible d'être plusieurs ordres de grandeur plus lent que

d'utiliser la mémoire normale.
