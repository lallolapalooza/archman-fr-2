COMPLÉTION DE MOTS PERSONNALISÉE

Si dans votre application, vous souhaitez que la complétion par TAB complète d'autres choses en plus des noms de fichiers ou à la place de ceux-ci, vous pouvez organiser cela en enregistrant une fonction de rappel de complétion alternative, via un appel à la gl_customize_completion() fonction.

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

L' data argument fournit un moyen pour votre application de passer des informations arbitraires, spécifiques à l'application, à la fonction de rappel. Celles-ci sont passées à la fonction de rappel à chaque fois qu'elle est appelée. Elle pourrait par exemple, pointer vers la table de symboles à partir de laquelle les complétions possibles doivent être recherchées. L' match_fn argument spécifie la fonction de rappel à appeler. Le CplMatchFn type de fonction est défini dans libtecla.h, tout comme une macro CPL_MATCH_FN() que vous pouvez utiliser pour déclarer et prototyper des fonctions de rappel. La déclaration et les responsabilités des fonctions de rappel sont décrites en profondeur dans la page de manuel cpl_complete_word(3).

En bref, la fonction de rappel est responsable de la recherche vers l'arrière dans la ligne d'entrée, en remontant depuis le point où l'utilisateur a appuyé TAB, pour trouver le début du mot en cours de complétion. Elle doit ensuite rechercher les complétions possibles de ce mot, et les enregistrer une par une dans l'objet WordCompletion qui lui est passé en argument, en appelant la fonction cpl_add_completion() . Si la fonction de rappel souhaite fournir une complétion de nom de fichier en plus de ses propres complétions spécifiques, elle a la possibilité d'appeler elle-même la fonction de rappel de complétion de nom de fichier intégrée. Ceci est également documenté dans la cpl_complete_word(3) page de manuel.

Notez que si vous souhaitez que gl_get_line() retourne la ligne d'entrée actuelle lorsqu'une complétion réussie a été effectuée, vous pouvez organiser cela lorsque vous appelez cpl_add_completion(), en faisant que le dernier caractère du suffixe de continuation soit un caractère de nouvelle ligne. Si vous faites cela, la ligne d'entrée sera mise à jour pour afficher la complétion, avec tout suffixe de continuation jusqu'au caractère de nouvelle ligne, puis gl_get_line() retournera cette ligne d'entrée.

Si, pour une raison quelconque, votre fonction de rappel doit écrire quelque chose sur le terminal, elle doit appeler gl_normal_io() avant de le faire. Cela commencera une nouvelle ligne après la ligne d'entrée actuellement en cours d'édition, rétablira l'E/S normale du terminal, et indiquera à gl_get_line() que la ligne d'entrée devra être redessinée lorsque la fonction de rappel retournera.

AJOUT D'ACTIONS DE COMPLÉTION

Dans la section précédente, la capacité de personnaliser le comportement de la seule action de complétion par défaut, complete-word, a été décrite. Dans cette section, la capacité d'installer des fonctions d'action supplémentaires, afin que différents types de complétion de mots puissent être liés à différentes séquences de touches, est décrite. Ceci est réalisé en utilisant la fonction gl_completion_action() .

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Les arguments data et match_fn sont comme décrits dans la page de manuel cpl_complete_word , et spécifient la fonction de rappel qui doit être invoquée pour identifier les complétions possibles. L' list_only argument détermine si l'action en cours de définition doit tenter de compléter le mot autant que possible dans la ligne d'entrée avant d'afficher toute complétion ambiguë possible, ou si elle doit simplement afficher la liste des complétions possibles sans toucher à la ligne d'entrée. La première option est sélectionnée en spécifiant une valeur de 0, et la seconde en spécifiant une valeur de 1. L' name argument spécifie le nom par lequel les fichiers de configuration et les futures invocations de cette fonction doivent faire référence à l'action. Ceci doit être soit le nom d'une action de complétion existante à changer, ou un nouveau nom non utilisé pour une nouvelle action. Enfin, l' keyseq argument spécifie la séquence de touches par défaut à lier à l'action. Si c'est NULL, aucune nouvelle séquence de touches ne sera liée à l'action.

Attention, pour que l'utilisateur puisse changer la séquence de touches liée aux actions installées de cette manière, lorsque vous appelez gl_completion_action() pour installer une action donnée pour la première fois, vous devriez le faire entre l'appel à new_GetLine() et le premier appel à gl_get_line(). Sinon, lorsque le fichier de configuration de l'utilisateur est lu lors du premier appel à gl_get_line(), le nom de votre action supplémentaire ne sera pas connu, et toute référence à elle dans le fichier de configuration générera une erreur.

Comme discuté pour gl_customize_completion(), si votre fonction de rappel, pour une raison quelconque, doit écrire quoi que ce soit sur le terminal, elle doit appeler gl_normal_io() avant de le faire.

DÉFINITION D'ACTIONS PERSONNALISÉES

Bien que les actions de liaison de touches intégrées soient suffisantes pour les besoins de la plupart des applications, une application spécialisée peut parfois avoir besoin de définir une ou plusieurs actions personnalisées, liées à des séquences de touches spécifiques à l'application. Par exemple, une application de vente bénéficierait d'avoir une séquence de touches qui affichait le nom de la pièce correspondant à un numéro de pièce situé avant le curseur. Une telle fonctionnalité dépasse clairement le cadre des fonctions d'action intégrées. Ainsi, pour de tels cas particuliers, la fonction gl_register_action() est fournie.

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Cette fonction permet à l'application d'enregistrer une fonction externe, fn, qui sera ensuite appelée chaque fois que la séquence de touches spécifiée, keyseq, est saisie par l'utilisateur, ou que l'utilisateur saisit une autre séquence de touches qu'il lie ensuite au nom d'action spécifié, name, dans son fichier de configuration. L' data argument peut être un pointeur vers n'importe quoi que l'application souhaite faire passer à la fonction d'action, fn, chaque fois que cette fonction est invoquée.

La fonction d'action, fn, devrait être déclarée en utilisant la macro suivante, qui est définie dans libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Les arguments gl et data sont ceux qui ont été précédemment passés à gl_register_action() lorsque la fonction d'action a été enregistrée. L' count argument est un argument numérique que l'utilisateur a la possibilité de saisir en utilisant l'action digit-argument , avant d'invoquer l'action. Si l'utilisateur n'entre pas de nombre, alors l' count argument est défini à 1. Nominalement, cet argument est interprété comme un nombre de répétitions, ce qui signifie que l'action devrait être répétée ce nombre de fois. En pratique cependant, pour certaines actions, un nombre de répétitions a peu de sens. Dans de tels cas, les actions peuvent soit simplement ignorer l' count argument, ou utiliser sa valeur à une autre fin.

Une copie de la ligne d'entrée actuelle est passée dans l'argument en lecture seule line . La position actuelle du curseur dans cette chaîne est donnée par l'index contenu dans l' curpos argument. Notez que la manipulation directe de la ligne d'entrée et de la position du curseur n'est pas autorisée. C'est parce que les règles dictées par divers modes, comme le mode vi versus le mode emacs, le mode sans écho, et le mode insertion versus le mode surimpression etc, rendent trop complexe pour un développeur d'application d'écrire une action d'édition conforme, ainsi que de contraindre les changements futurs aux internes de gl_get_line(). Une solution potentielle à ce dilemme serait de permettre à la fonction d'action d'éditer la ligne en utilisant les actions d'édition existantes. Ceci est actuellement à l'étude.

Si la fonction d'action souhaite écrire du texte sur le terminal, sans que cela se mélange avec le texte affiché de la ligne d'entrée, ou lire depuis le terminal sans avoir à gérer l'E/S brute du terminal, alors avant de faire l'une ou l'autre de ces opérations, elle doit suspendre temporairement l'édition de ligne en appelant la fonction gl_normal_io() . Cette fonction vide toute sortie en attente vers le terminal, déplace le curseur au début de la ligne qui suit la dernière ligne du terminal de la ligne d'entrée, puis restaure le terminal à un état adapté à l'utilisation avec les fonctionnalités stdio de C. Ce dernier inclut des choses comme la restauration du mappage normal de \n vers \r\n, et, en mode serveur, la restauration de la forme bloquante normale de l'E/S du terminal. Après avoir appelé cette fonction, la fonction d'action peut lire depuis et écrire vers le terminal sans craindre de faire un désordre. Il n'est pas nécessaire pour la fonction d'action de restaurer l'environnement d'édition original avant de retourner. Cela est fait automatiquement par gl_get_line() après le retour de la fonction d'action. Voici un exemple simple d'une fonction d'action qui écrit la phrase "Hello world" sur une nouvelle ligne du terminal après la ligne en cours d'édition. Lorsque cette fonction retourne, la ligne d'entrée est redessinée sur la ligne qui suit la ligne "Hello world", et l'édition de ligne reprend.

  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspendre temporairement l'édition */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
  }

Les fonctions d'action doivent retourner l'une des valeurs suivantes, pour indiquer à gl_get_line() comment procéder.

  GLA_ABORT     -   Faire en sorte que gl_get_line() retourne NULL.
  GLA_RETURN    -   Faire en sorte que gl_get_line() retourne la
                    ligne d'entrée complétée.
  GLA_CONTINUE  -   Reprendre l'édition de la ligne de commande.

Notez que l'argument name de gl_register_action() spécifie le nom par lequel un utilisateur peut référencer l'action dans son fichier de configuration. Cela lui permet de réassocier l'action à une séquence de touches alternative. Pour que cela fonctionne, il est nécessaire d'appeler gl_register_action() entre l'appel à new_GetLine() et le premier appel à gl_get_line().

FICHIERS D'HISTORIQUE

Pour sauvegarder le contenu du tampon d'historique avant de quitter votre application, et les restaurer ultérieurement lorsque vous redémarrez l'application, les fonctions suivantes sont fournies.

 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);

L'argument filename spécifie le nom à donner au fichier d'historique lors de la sauvegarde, ou le nom d'un fichier d'historique existant lors du chargement. Cela peut contenir des expressions de répertoire personnel et de variables d'environnement, telles que "~/.myapp_history" ou "$HOME/.myapp_history".

Avec chaque ligne d'historique, des informations supplémentaires à son sujet, telles que le moment où elle a été saisie par l'utilisateur, et son niveau d'imbrication, sont enregistrées sous forme de commentaire précédant la ligne dans le fichier d'historique. Écrire cela comme un commentaire permet au fichier d'historique de servir également de fichier de commandes, au cas où vous souhaiteriez rejouer une session entière avec lui. Puisque les préfixes de commentaires diffèrent selon les langages, l'argument comment est fourni pour spécifier le préfixe de commentaire. Par exemple, si votre application était un shell unix, tel que le shell bourne, vous spécifieriez "#" ici. Quel que soit le caractère de commentaire que vous choisissez, vous devez spécifier le même préfixe à gl_load_history() que celui que vous avez utilisé lorsque vous avez appelé gl_save_history() pour écrire le fichier d'historique.

L'argument max_lines doit être soit -1 pour spécifier que toutes les lignes de la liste d'historique doivent être sauvegardées, soit un nombre positif spécifiant un plafond sur le nombre de lignes les plus récentes à sauvegarder.

Les deux fonctions retournent une valeur non nulle en cas d'erreur, après avoir écrit un message d'erreur sur stderr. Notez que gl_load_history() ne considère pas la non-existence d'un fichier comme une erreur.

LISTES D'HISTORIQUE MULTIPLES

Si votre application utilise un seul objet GetLine pour saisir de nombreux types différents de lignes d'entrée, vous souhaiterez peut-être que gl_get_line() distingue les différents types de lignes dans la liste d'historique, et ne rappelle que les lignes correspondant au type de ligne actuel. Pour prendre en charge cette exigence, gl_get_line() marque les lignes enregistrées dans la liste d'historique avec un identifiant entier choisi par l'application. Initialement, cet identifiant est défini à 0 par new_GetLine(), mais il peut être changé ultérieurement en appelant gl_group_history().

  int gl_group_history(GetLine *gl, unsigned id);

L'identifiant entier id peut être n'importe quel nombre choisi par l' application, mais notez que gl_save_history() et gl_load_history() préservent l'association entre les identifiants et les lignes d'entrée historiques entre les invocations du programme, vous devriez donc choisir des identifiants fixes pour les différents types de lignes d'entrée utilisés par votre application.

Chaque fois que gl_get_line() ajoute une nouvelle ligne d'entrée à la liste d'historique, l'identifiant d'historique courant est enregistré avec elle, et lorsqu'on lui demande de rappeler une ligne d'entrée historique, elle ne rappelle que les lignes marquées avec l'identifiant courant.

AFFICHAGE DE L'HISTORIQUE

La liste d'historique peut être affichée en appelant gl_show_history().

  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);

Cela affiche le contenu courant de la liste d'historique sur le flux de sortie stdio fp. Si l'argument max_lines est supérieur ou égal à zéro, alors pas plus que ce nombre de lignes les plus récentes ne sera affiché. Si l'argument all_groups est non nul, les lignes de tous les groupes d'historique sont affichées. Sinon, seules celles du groupe d'historique actuellement sélectionné sont affichées. L'argument chaîne de format, fmt, détermine comment la ligne est affichée. Cela peut contenir des caractères arbitraires qui sont écrits tels quels, entrelacés avec l'une des directives de format suivantes :

  %D  -  La date à laquelle la ligne a été initialement
         saisie, formatée comme 2001-11-20.
  %T  -  L'heure à laquelle la ligne a été saisie,
         formatée comme 23:59:59.
  %N  -  Le numéro d'entrée séquentiel de la ligne dans
         le tampon d'historique.
  %G  -  Le numéro du groupe d'historique auquel la
         ligne appartient.
  %%  -  Un caractère % littéral.
  %H  -  La ligne d'historique elle-même.

Ainsi, une chaîne de format comme "%D %T %H0 produirait quelque chose comme :

  2001-11-20 10:23:34  Hello world

Notez l'inclusion d'un caractère de nouvelle ligne explicite dans la chaîne de format.

RECHERCHE DANS L'HISTORIQUE

La fonction gl_lookup_history() permet à l'application appelante de rechercher des lignes dans la liste d'historique.

  typedef struct {
    const char *line;    /* La ligne historique */
                         /*  demandée. */
    unsigned group;      /* Le groupe d'historique auquel */
                         /*  la ligne appartient. */
    time_t timestamp;    /* La date et l'heure auxquelles */
                         /*  la ligne a été initialement */
                         /*  saisie. */
  } GlHistoryLine;
  int gl_lookup_history(GetLine *gl, unsigned long id,
                        GlHistoryLine *hline);

L'argument id indique quelle ligne rechercher, où la première ligne qui a été saisie dans la liste d'historique après l'appel à new_GetLine() est désignée par 0, et les lignes saisies ultérieurement sont désignées avec des numéros successivement plus élevés. Notez que la plage de lignes actuellement préservées dans la liste d'historique peut être interrogée en appelant la fonction gl_range_of_history() , décrite plus tard. Si la ligne demandée est dans la liste d'historique, les détails de la ligne sont enregistrés dans la variable pointée par l'argument hline , et 1 est retourné. Sinon, 0 est retourné, et la variable pointée par hline est laissée inchangée.

Attention, la chaîne retournée dans hline->line fait partie du tampon d'historique, elle ne doit donc pas être modifiée par l'appelant, et sera recyclée lors du prochain appel à toute fonction qui prend gl comme argument. Vous devriez donc faire une copie privée de cette chaîne si vous avez besoin de la conserver.

ARCHIVAGE MANUEL DE L'HISTORIQUE

Par défaut, chaque fois qu'une ligne est saisie par l'utilisateur, elle est automatiquement ajoutée à la liste d'historique, juste avant que gl_get_line() retourne la ligne à l'appelant. C'est pratique pour la majorité des applications, mais il existe aussi des applications qui ont besoin d'un contrôle plus fin sur ce qui est ajouté à la liste d'historique. Dans de tels cas, l' ajout automatique des lignes saisies à la liste d'historique peut être désactivé en appelant la fonction gl_automatic_history() .

  int gl_automatic_history(GetLine *gl, int enable);

Si cette fonction est appelée avec son argument enable défini à 0, gl_get_line() n'archivera pas automatiquement les lignes saisies ultérieurement. L'archivage automatique peut être réactivé plus tard, en appelant à nouveau cette fonction, avec son argument enable défini à 1. Pendant que l'archivage automatique de l'historique est désactivé, l'application appelante peut utiliser gl_append_history() pour ajouter des lignes à la liste d'historique selon les besoins.

  int gl_append_history(GetLine *gl, const char *line);

L'argument line spécifie la ligne à ajouter à la liste d'historique. Cela doit être une chaîne normale terminée par ' ' . Si cette chaîne contient des caractères de nouvelle ligne, la ligne archivée dans la liste d'historique sera terminée par le premier d'entre eux. Sinon, elle sera terminée par le ' ' terminateur. Si la ligne est plus longue que la longueur maximale de ligne d'entrée, qui a été spécifiée lorsque new_GetLine() a été appelé, lorsque la ligne sera rappelée, elle sera tronquée à la longueur réelle de la ligne gl_get_line() .

Si l'opération réussit, gl_append_history() retourne 0. Sinon, elle retourne une valeur non nulle, et définit errno à l'une des valeurs suivantes.

   EINVAL  -  L'un des arguments passés à
              gl_append_history() était NULL.
   ENOMEM  -  La ligne spécifiée était plus longue que la taille
              allouée du tampon d'historique (telle que spécifiée lorsque
              new_GetLine() a été appelé), elle n'a donc pas pu être
              archivée.

Une description textuelle de l'erreur peut être obtenue éventuellement en appelant gl_error_message(). Notez qu'après une telle erreur, la liste d'historique reste dans un état valide pour recevoir de nouvelles lignes d'historique, il n'y a donc que peu d'inconvénient à simplement ignorer le statut de retour de gl_append_history().

CONFIGURATION DIVERSE DE L'HISTORIQUE

Si vous souhaitez changer la taille du tampon d'historique qui a été initialement spécifiée dans l'appel à new_GetLine(), vous pouvez le faire avec la fonction gl_resize_history() .

  int gl_resize_history(GetLine *gl, size_t histlen);

L'argument histlen spécifie la nouvelle taille en octets, et si vous spécifiez cela comme 0, le tampon sera supprimé.

Comme mentionné dans la discussion de new_GetLine(), le nombre de lignes qui peuvent être stockées dans le tampon d'historique dépend des longueurs des lignes individuelles. Par exemple, un tampon de 1000 octets pourrait stocker aussi bien 10 lignes de longueur moyenne de 100 octets, que 2 lignes de longueur moyenne de 50 octets. Bien que le tampon ne soit jamais agrandi lorsque de nouvelles lignes sont ajoutées, une liste de pointeurs vers le tampon est agrandie lorsque c'est nécessaire pour accueillir le nombre de lignes actuellement stockées dans le tampon. Pour placer une limite supérieure sur le nombre de lignes dans le tampon, et ainsi un plafond sur la quantité de mémoire utilisée dans cette liste, vous pouvez appeler la fonction gl_limit_history() function.

  void gl_limit_history(GetLine *gl, int max_lines);

Le max_lines doit être un nombre positif >= 0, spécifiant une limite supérieure sur le nombre de lignes dans le tampon, ou -1 pour annuler toute limite précédemment spécifiée. Lorsqu'une limite est en vigueur, seules les max_lines lignes ajoutées le plus récemment sont conservées dans le tampon. Les anciennes lignes sont supprimées.

Pour supprimer des lignes du tampon d'historique, utilisez la fonction gl_clear_history().

  void gl_clear_history(GetLine *gl, int all_groups);

L'argument all_groups indique à la fonction s'il faut supprimer uniquement les lignes associées au groupe d'historique actuel (voir gl_group_history()) ou toutes les lignes historiques du tampon.

La fonction gl_toggle_history() vous permet d'activer et de désactiver l'historique sans perdre le contenu actuel de la liste d'historique.

  void gl_toggle_history(GetLine *gl, int enable);

Définir l'argument enable à 0 désactive le mécanisme d'historique, et le définir à 1 le réactive. Lorsque l'historique est désactivé, aucune nouvelle ligne ne sera ajoutée à la liste d'historique, et les raccourcis clavier de recherche d'historique agiront comme s'il n'y avait rien dans le tampon d'historique.

INTERROGATION DES INFORMATIONS D'HISTORIQUE

L'état configuré de la liste d'historique peut être interrogé avec la fonction gl_history_state().

  typedef struct {
    int enabled;     /* True si l'historique est activé */
    unsigned group;  /* Le groupe d'historique actuel */
    int max_lines;   /* La limite supérieure actuelle sur le */
                     /*  nombre de lignes dans la liste */
                     /*  d'historique, ou -1 si illimitée. */
  } GlHistoryState;
  void gl_state_of_history(GetLine *gl,
                           GlHistoryState *state);

Au retour, les informations d'état sont enregistrées dans la variable pointée par l'argument state.

La fonction gl_range_of_history() renvoie le nombre et la plage des lignes dans la liste d'historique.

typedef struct {
  unsigned long oldest;  /* Le numéro d'entrée séquentiel */
                         /*  de la ligne la plus ancienne */
                         /*  dans la liste d'historique. */
  unsigned long newest;  /* Le numéro d'entrée séquentiel */
                         /*  de la ligne la plus récente */
                         /*  dans la liste d'historique. */
  int nlines;            /* Le nombre de lignes dans la */
                         /*  liste d'historique. */
} GlHistoryRange;
void gl_range_of_history(GetLine *gl, GlHistoryRange *range);

Les valeurs de retour sont enregistrées dans la variable pointée par l'argument range. Si le membre nlines de cette structure est supérieur à zéro, alors les membres oldest et newest rapportent la plage des lignes dans la liste, et newest=oldest+nlines-1. Sinon, ils sont tous deux à zéro.

La fonction gl_size_of_history() renvoie la taille totale du tampon d'historique et la quantité du tampon actuellement occupée.

  typedef struct {
    size_t size;      /* La taille du tampon d'historique */
                      /*  (octets). */
    size_t used;      /* Le nombre d'octets du tampon */
                      /*  d'historique qui sont */
                      /*  actuellement occupés. */
  } GlHistorySize;
  void gl_size_of_history(GetLine *gl, GlHistorySize *size);

Au retour, les informations de taille sont enregistrées dans la variable pointée par l'argument size.

CHANGEMENT DES TERMINAUX

La fonction constructeur new_GetLine() suppose que l'entrée doit être lue depuis stdin et la sortie écrite sur stdout. La fonction suivante vous permet de passer à différents flux d'entrée et de sortie.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

L'argument gl est l'objet renvoyé par new_GetLine(). L'argument input_fp spécifie le flux à lire et output_fp spécifie le flux à écrire. Ce n'est que si les deux font référence à un terminal que l'entrée interactive du terminal sera activée. Sinon, gl_get_line() appellera simplement fgets() pour lire l'entrée de commande. Si les deux flux font référence à un terminal, ils doivent faire référence au même terminal, et le type de ce terminal doit être spécifié via l'argument term. La valeur de l'argument term est recherchée dans la base de données d'informations de terminal (terminfo ou termcap), afin de déterminer quelles séquences de contrôle spéciales sont nécessaires pour contrôler divers aspects du terminal. new_GetLine() par exemple, passe la valeur de retour de getenv("TERM") dans cet argument. Notez que si un ou les deux de input_fp et output_fp ne font pas référence à un terminal, alors il est légal de passer NULL au lieu d'un type de terminal.

Notez que si vous souhaitez passer des descripteurs de fichiers à gl_change_terminal(), vous pouvez le faire en créant des wrappers de flux stdio à l'aide de la fonction POSIX fdopen().

GESTION DES ÉVÉNEMENTS EXTERNES

Par défaut, gl_get_line() ne retourne pas tant qu'une ligne d'entrée complète n'a pas été saisie par l'utilisateur, ou qu'une erreur ne se produit pas. Dans les programmes qui doivent surveiller les E/S provenant d'autres sources que le terminal, il y a deux options.

  1. Utilisez les fonctions décrites dans la
     page de manuel gl_io_mode(3) pour
     faire passer gl_get_line() en mode serveur non bloquant. Dans ce
     mode, gl_get_line() devient une fonction d'édition de ligne
     incrémentale non bloquante qui peut être appelée en toute sécurité à
     partir d'une boucle d'événements externe. Bien que ce soit une méthode
     très polyvalente, elle implique de prendre en charge certaines
     responsabilités qui sont normalement effectuées en arrière-plan par
     gl_get_line().
  2. Pendant que gl_get_line() attend une entrée clavier de l'utilisateur,
     vous pouvez lui demander de surveiller également l'activité sur des
     descripteurs de fichiers arbitraires, tels que des sockets réseau, des
     pipes, etc., et de faire appel à des fonctions de votre choix lorsque
     l'activité est détectée. Cela fonctionne sur tout système disposant de
     l'appel système select(), ce qui est la plupart, sinon la totalité,
     des saveurs d'Unix.

L'enregistrement d'un descripteur de fichier à surveiller par gl_get_line() implique d'appeler la fonction gl_watch_fd().

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si cela renvoie une valeur non nulle, cela signifie que soit vos arguments sont invalides, soit cette fonctionnalité n'est pas prise en charge sur le système hôte.

L'argument fd est le descripteur de fichier à surveiller. L'argument event spécifie quel type d'activité est d'intérêt, choisi parmi les valeurs énumérées suivantes :

  GLFD_READ   -  Surveiller l'arrivée de données à lire.
  GLFD_WRITE  -  Surveiller la possibilité d'écrire sur le
                 descripteur de fichier sans bloquer.
  GLFD_URGENT -  Surveiller l'arrivée de données urgentes
                 hors bande sur le descripteur de fichier.

L'argument callback est la fonction à appeler lorsque l'activité sélectionnée est détectée. Elle doit être définie avec la macro suivante, définie dans libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

L'argument data de la fonction gl_watch_fd() est transmis à la fonction de rappel pour son propre usage, et peut pointer vers n'importe quoi, y compris NULL. Le descripteur de fichier et l'argument d'événement sont également transmis à la fonction de rappel, ce qui permet potentiellement à la même fonction de rappel d'être enregistrée pour plus d'un type d'événement et/ou plus d'un descripteur de fichier. La valeur de retour de la fonction de rappel doit être l'une des valeurs suivantes.

  GLFD_ABORT    -  Indiquer à gl_get_line() d'avorter. Lorsque cela
                   se produit, gl_get_line() retourne
                   NULL, et un appel ultérieur à
                   gl_return_status() retournera
                   GLR_FDABORT. Notez que si
                   l'application a besoin que errno ait
                   toujours une valeur significative lorsque
                   gl_get_line() retourne NULL,
                   la fonction de rappel doit définir
                   errno de manière appropriée.
  GLFD_REFRESH  -  Redessiner la ligne d'entrée puis continuer
                   à attendre l'entrée. Retournez ceci si
                   votre rappel a écrit sur le terminal.
  GLFD_CONTINUE -  Continuer à attendre l'entrée, sans
                   redessiner la ligne.

Notez qu'avant d'appeler le rappel, gl_get_line() bloque la plupart des signaux et laisse ses propres gestionnaires de signaux installés, donc si vous avez besoin de capturer un signal particulier, vous devrez temporairement installer votre propre gestionnaire de signaux et débloquer le signal. Assurez-vous de rebloquer le signal (s'il était initialement bloqué) et de rétablir le gestionnaire de signaux d'origine, le cas échéant, avant de retourner.

Si la fonction de rappel doit lire ou écrire sur le terminal, elle devrait idéalement d'abord appeler gl_normal_io(gl) pour suspendre temporairement l'édition de ligne. Cela restaurera le terminal en mode canonique, E/S bloquantes, et déplacera le curseur au début d'une nouvelle ligne de terminal. Plus tard, lorsque le rappel retournera, gl_get_line() remarquera que gl_normal_io() a été appelé, réaffichera la ligne d'entrée et reprendra l'édition. Notez que dans ce cas, les valeurs de retour GLFD_REFRESH et GLFD_CONTINUE sont équivalentes.

Pour prendre en charge les cas où la fonction de rappel appelle une fonction tierce qui écrit occasionnellement et de manière imprévisible sur le terminal, la conversion automatique de "0 en "0 est réactivée avant que la fonction de rappel ne soit appelée. Si le rappel sait que la fonction tierce a écrit sur le terminal, il doit alors retourner la valeur de retour GLFD_REFRESH, pour indiquer à gl_get_line() de réafficher la ligne d'entrée.

Pour supprimer une fonction de rappel que vous avez précédemment enregistrée pour un descripteur de fichier et un événement donnés, appelez simplement gl_watch_fd() avec les mêmes arguments de descripteur de fichier et d' event, mais avec un argument callback de 0. L'argument data est ignoré dans ce cas.

RÉGLAGE D'UN TEMPS MORT D'INACTIVITÉ

Sur les systèmes disposant de l'appel système select(), la fonction gl_inactivity_timeout() peut être utilisée pour définir ou annuler un temps mort d'inactivité. L'inactivité dans ce cas fait référence à la fois à l'entrée clavier et aux E/S sur tous les descripteurs de fichiers enregistrés par des appels précédents et ultérieurs à gl_watch_fd(). Sur les systèmes inhabituels qui n'ont pas select(), cet appel n'a aucun effet.

  int gl_
inactivity_timeout(GetLine *gl, GlTimeoutFn *callback, void *data, unsigned long sec, unsigned long nsec);

Le délai d'attente est spécifié sous la forme d'un nombre entier de secondes et d'un nombre entier de nanosecondes, via les sec et nsec arguments respectivement. Par la suite, chaque fois qu'aucune activité n'est observée pendant cette période, la fonction spécifiée via l'argument callback est appelée. L'argument data de gl_inactivity_timeout() est transmis tel quel à cette fonction de rappel chaque fois qu'elle est invoquée, et peut donc être utilisé pour transmettre des informations arbitraires spécifiques à l'application à la fonction de rappel. La macro suivante est fournie dans libtecla.h pour que les applications puissent déclarer et prototyper des fonctions de rappel de délai d'attente.

  #define GL_TIMEOUT_FN(fn) \
               GlAfterTimeout (fn)(GetLine *gl, void *data)

Au retour, la fonction de rappel de l'application doit retourner l'un des énumérateurs suivants pour indiquer à gl_get_line() comment procéder après que le délai d'attente a été traité par la fonction de rappel.

  GLTO_ABORT    -  Indique à gl_get_line() d'interrompre. Quand
                   cela se produit, gl_get_line() va
                   retourner NULL, et un appel suivant
                   à gl_return_status() retournera
                   GLR_TIMEOUT. Notez que si l'application a besoin que
                   la variable errno ait toujours
                   une valeur significative quand
                   gl_get_line() retourne NULL,
                   la fonction de rappel doit définir
                   errno de manière appropriée.
  GLTO_REFRESH  -  Redessine la ligne d'entrée, puis continue
                   à attendre des entrées. Vous devez retourner
                   cette valeur si votre fonction de rappel a écrit sur le
                   terminal sans avoir d'abord appelé
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En mode d'E/S bloquant normal, continue à
                   attendre des entrées, sans redessiner la
                   ligne d'entrée de l'utilisateur.
                   En mode serveur E/S non bloquant (voir
                   gl_io_mode(3)), fait en sorte que gl_get_line()
                   se comporte comme si l'E/S était bloquante. Cela signifie
                   que gl_get_line() va immédiatement
                   retourner NULL, et un appel suivant
                   à gl_return_status() retournera
                   GLR_BLOCKED.

Notez qu'avant d'appeler la fonction de rappel, gl_get_line() bloque la plupart des signaux et laisse ses propres gestionnaires de signaux installés, donc si vous avez besoin de capter un signal particulier, vous devrez à la fois installer temporairement votre propre gestionnaire de signaux et débloquer le signal. Assurez-vous de re-bloquer le signal (s'il était initialement bloqué) et de rétablir le gestionnaire de signaux d'origine, s'il y en a un, avant de retourner.

Si la fonction de rappel a besoin de lire ou d'écrire sur le terminal, elle devrait idéalement d'abord appeler gl_normal_io(gl) pour suspendre temporairement l'édition de ligne. Cela restaurera le terminal en mode canonique, E/S bloquante, et déplacera le curseur au début d'une nouvelle ligne de terminal. Plus tard, quand la fonction de rappel retourne, gl_get_line() remarquera que gl_normal_io() a été appelé, réaffichera la ligne d'entrée et reprendra l'édition. Notez que dans ce cas, les valeurs de retour, GLTO_REFRESH et GLTO_CONTINUE sont équivalentes.

Pour prendre en charge les cas où la fonction de rappel appelle une fonction tierce qui écrit occasionnellement et de manière imprévisible sur le terminal, la conversion automatique de "0 vers "0 est réactivée avant que la fonction de rappel ne soit appelée. Si la fonction de rappel sait que la fonction tierce a écrit sur le terminal, elle devrait alors retourner la valeur de retour GLTO_REFRESH , pour indiquer à gl_get_line() de réafficher la ligne d'entrée.

LA TAILLE DU TERMINAL

Sur la plupart des systèmes, la combinaison de TIOCGWINSZ ioctl et du SIGWINCH signal est utilisée pour maintenir une idée précise de la taille du terminal. La taille du terminal est nouvellement interrogée à chaque fois que gl_get_line() est appelé et chaque fois qu'un SIGWINCH signal est reçu.

Sur les quelques systèmes où ce mécanisme n'est pas disponible, au démarrage new_GetLine() cherche d'abord les LINES et COLUMNS variables d'environnement. Si elles ne sont pas trouvées, ou si elles contiennent des valeurs inutilisables, alors si une base de données d'informations sur le terminal comme terminfo ou termcap est disponible, la taille par défaut du terminal est recherchée dans cette base de données. Si cela ne permet pas non plus d'obtenir la taille du terminal, une taille par défaut de 80 colonnes par 24 lignes est utilisée.

Même sur les systèmes qui prennent en charge ioctl(TIOCGWINSZ), si le terminal se trouve à l'autre extrémité d'une ligne série, le pilote du terminal n'a généralement aucun moyen de détecter quand un redimensionnement se produit ou d'interroger quelle est la taille actuelle. Dans de tels cas, aucun SIGWINCH n'est envoyé au processus, et les dimensions retournées par ioctl(TIOCGWINSZ) ne sont pas correctes. La seule façon de gérer de tels cas est de fournir un moyen à l'utilisateur de saisir une commande qui indique au système distant la nouvelle taille. Cette commande appellerait alors la gl_set_term_size() fonction pour informer gl_get_line() du changement de taille.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

Les ncolumn et nline arguments sont utilisés pour spécifier les nouvelles dimensions du terminal, et ne doivent pas être inférieurs à 1. Sur les systèmes qui prennent en charge ioctl(TIOCGWINSZ), cette fonction appelle d'abord ioctl(TIOCSWINSZ) pour informer le pilote du terminal du changement de taille. En mode d'E/S serveur non bloquant, si une ligne est actuellement en cours de saisie, la ligne d'entrée est alors redessinée pour s'adapter à la taille modifiée. Enfin, les nouvelles valeurs sont enregistrées dans gl pour une utilisation future par gl_get_line().

La gl_terminal_size() fonction vous permet d'interroger la taille actuelle du terminal, et d'installer une taille de secours alternative pour les cas où la taille n'est pas disponible. Attention, la taille du terminal ne sera pas disponible si vous lisez depuis un pipe ou un fichier, donc les valeurs par défaut peuvent être importantes même sur les systèmes qui prennent en charge des moyens de découvrir la taille du terminal.

  typedef struct {
    int nline;        /* Le terminal a nline lignes */
    int ncolumn;      /* Le terminal a ncolumn colonnes */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

Les def_ncolumn et def_nline spécifient le nombre par défaut de colonnes et de lignes du terminal à utiliser si la taille du terminal ne peut pas être déterminée via ioctl(TIOCGWINSZ) ou les variables d'environnement.

En gardant cela à l'esprit, la gl_echo_mode() fonction vous permet d'activer et de désactiver l'affichage et l'archivage de tout texte qui est saisi ultérieurement dans les appels à gl_get_line().

L' enable argument spécifie si le texte saisi doit être visible ou non. Si c'est 0, alors les lignes saisies ultérieurement ne seront pas visibles sur le terminal, et ne seront pas enregistrées dans la liste d'historique. Si c'est 1, alors les lignes d'entrée ultérieures seront affichées au fur et à mesure qu'elles sont saisies, et à condition que l'historique n'ait pas été désactivé via un appel à gl_toggle_history(), elles seront également archivées dans la liste d'historique. Enfin, si l'argument enable est -1, alors le mode d'écho est laissé inchangé, ce qui vous permet d'interroger de manière non destructive le paramètre actuel via la valeur de retour. Dans tous les cas, la valeur de retour de la fonction est 0 si l'écho était désactivé avant que la fonction ne soit appelée, et 1 s'il était activé.

Lorsque l'écho est désactivé, notez que même si la complétion par tabulation complétera de manière invisible votre préfixe aussi loin que possible, les complétions ambiguës ne seront pas affichées.

REQUÊTES À UN SEUL CARACTÈRE

Utiliser gl_get_line() pour demander à l'utilisateur une réponse d'un seul caractère est incommode pour l'utilisateur, car il doit appuyer sur la touche entrée ou retour avant que le caractère qu'il a tapé ne soit renvoyé au programme. C'est pourquoi la gl_query_char() fonction a été fournie pour les requêtes d'un seul caractère comme celle-ci.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

Cette fonction affiche l'invite spécifiée au début d'une nouvelle ligne, et attend que l'utilisateur tape un caractère. Lorsque l'utilisateur tape un caractère, gl_query_char() l'affiche à droite de l'invite, démarre une nouvelle ligne, puis renvoie le caractère au programme appelant. La valeur de retour de la fonction est le caractère qui a été tapé. Si la lecture a dû être interrompue pour une raison quelconque, EOF est retourné à la place. Dans ce dernier cas, l'application peut appeler la fonction gl_return_status()précédemment documentée, pour savoir ce qui s'est mal passé. Cela pourrait être, par exemple, la réception d'un signal, ou le déclenchement du minuteur d'inactivité optionnel.

Si l'utilisateur appuie simplement sur entrée, la valeur de l'argument defchar est substituée. Cela signifie que lorsque l'utilisateur appuie sur newline ou retour, le caractère spécifié dans defcharest affiché après l'invite, comme si l'utilisateur l'avait tapé, ainsi que renvoyé à l'application appelante. Si un tel remplacement n'est pas important, passez simplement '0 comme valeur de defchar.

Si le caractère saisi est un caractère non imprimable, il est affiché symboliquement. Par exemple, control-A est affiché comme ^A, et les caractères au-delà de 127 sont affichés en octal, précédés d'une barre oblique inverse.

Comme avec gl_get_line(), l'écho du caractère saisi peut être désactivé en utilisant la fonction gl_echo_mode() .

Si le processus appelant est suspendu pendant qu'il attend que l'utilisateur tape sa réponse, le curseur est déplacé sur la ligne suivant la ligne d'invite, puis lorsque le processus reprend, l'invite est réaffichée, et gl_query_char() reprend l'attente que l'utilisateur tape un caractère.

Notez qu'en mode serveur non bloquant, (voir gl_io_mode(3)), si une ligne d'entrée incomplète est en cours de lecture lorsque gl_query_char() est appelée, la ligne d'entrée partielle est ignorée, et effacée du terminal, avant que la nouvelle invite ne soit affichée. Le prochain appel à gl_get_line() commencera donc à éditer une nouvelle ligne.

LECTURE DE CARACTÈRES BRUTS

Alors que la gl_query_char() fonction invite visiblement l'utilisateur à taper un caractère, et affiche ce qu'il a tapé, la gl_read_char() fonction lit un caractère brut de l'utilisateur, sans rien écrire sur le terminal, ou sans perturber une ligne d'entrée incomplète. Cela signifie qu'elle peut être appelée non seulement entre les appels à gl_get_line(), mais aussi depuis les fonctions de rappel que l'application a enregistrées pour être appelées par gl_get_line().

  int gl_read_char(GetLine *gl);

En cas de succès, la valeur de retour de gl_read_char() est le caractère qui a été lu. En cas d'échec, EOF est retourné, et la gl_return_status() fonction peut être appelée pour savoir ce qui s'est mal passé. Les possibilités incluent le déclenchement du minuteur d'inactivité optionnel, la réception d'un signal configuré pour interrompre gl_get_line(), ou le blocage de l'E/S du terminal, en mode d'E/S serveur non bloquant.

NAME

gl_erase_terminal, gl_display_text — clear terminal and display text

LIBRARY

libtecla

SYNOPSIS

#include <tecla.h>

int

gl_display_text(GetLine *gl, int indentation,

DESCRIPTION

The gl_erase_terminal() and gl_display_text() functions allow the calling program to perform more advanced screen manipulation than is possible using just the basic gl_get_line() function alone.

AN EXAMPLE

A common use of these functions is to display introductory text from within a callback function, prior to the command-line editing session commencing. The following code snippet shows how you might do this:

        GetLine *gl;
        int       width;

        gl = gl_create_context(NULL, NULL, NULL, NULL);
        if (gl == NULL)
                errx(EXIT_FAILURE, "gl_create_context() failed");

        /* ... */

        width = gl_get_screen_width(gl);
        gl_display_text(gl, 0, NULL, NULL, ' ', width, 0,
                        "Welcome to My Application!\n\n"
                        "This is a multi-line introduction intended to explain\n"
                        "the purpose of this program, and to provide a quick\n"
                        "guide to using it.\n\n"
                        "Please type your first command:\n");
        gl_set_prompt(gl, "myapp> ");
        line = gl_get_line(gl);
        gl_destroy_context(gl);

THE FUNCTIONS USED IN THE EXAMPLE

The example uses the following functions:

gl_create_context(3)
Creates and initialises a GetLine context.
gl_get_screen_width(3)
Returns the current width of the terminal.
gl_display_text(3)
Displays the introductory text.
gl_set_prompt(3)
Sets the command-line prompt.
gl_get_line(3)
Reads a line of text from the user.
gl_destroy_context(3)
Destroys the GetLine context and frees associated resources.

THE RETURN STATUS OF GL_GET_LINE

The return status of gl_get_line() indicates how the user terminated the input line. It is one of the following values:

EOF
An end-of-file was detected on the input stream. This occurs if the user presses Ctrl-D at the start of an empty line, or if the input is redirected from a file.
SIGINT
The user pressed Ctrl-C.
Any other value
Zero or greater indicates that the user pressed the Enter key, and the value is the length of the string returned.

If the user presses Ctrl-C, the calling program should probably abort execution or take other appropriate action. The value returned by gl_get_line() is the character that caused the line termination, unless Ctrl-C was pressed, in which case the return value is SIGINT.

%M
The name of the current host.
%m
The first character of the name of the current host.
%U
The user name of the current user.
%u
The first character of the user name of the current user.
%W
The current working directory.
%w
The trailing component of the current working directory.
%%
A literal percentage character.

If the prompt string is NULL, then the default prompt of "> " is used.

CUSTOMIZED WORD COMPLETION

Libtecla supports custom word completion. If the program is linked with the libtecla_cpl library, then calling gl_get_line() will automatically invoke word completion facilities whenever the user presses the Tab key. The word completion can be customized by providing a word completion callback function.

The callback function should have the following signature:

  const char *my_word_completion(GetLine *gl, const char *word);

The function is called with the GetLine context and the word that the user wants to complete. It should return a string containing the word completion, or NULL if no completion is possible. The returned string is dynamically allocated and must be freed by the caller.

The callback function can be registered using the following function:

  void gl_set_word_completion(GetLine *gl,
                              const char *(*callback)(GetLine *, const char *));

In addition to word completion, libtecla also supports file name completion. This is enabled by default, but can be disabled using the gl_set_file_completion() function.

ADDING COMPLETION ACTIONS

The libtecla library allows you to define custom actions that can be triggered during tab completion. These actions are associated with specific completion strings and are executed when the user selects a completion that matches a defined action.

You can add a completion action using the following function:

  int gl_add_completion_action(GetLine *gl, const char *completion,
                               void (*action)(GetLine *, const char *));

Here:

gl
The GetLine context.
completion
The string that triggers the action.
action
A pointer to the function to be executed when the completion is selected. The action function receives the GetLine context and the selected completion string as arguments.

The action function should return void and can perform any task, such as displaying information, modifying the command line, or triggering other events.

DEFINING CUSTOM ACTIONS

You can define custom actions to be performed when specific completions are selected. These actions are functions that take the GetLine context and the selected completion string as arguments.

Example of a custom action function:

  void my_custom_action(GetLine *gl, const char *completion) {
      printf("Action triggered for completion: %s\n", completion);
      // Perform custom actions here
  }

To associate this action with a completion string, use gl_add_completion_action():

  gl_add_completion_action(gl, "my_command", my_custom_action);

HISTORY FILES

Libtecla can maintain a history of commands entered by the user. This history can be saved to and loaded from a file. The history file is specified when creating the GetLine context:

  gl = gl_create_context(NULL, NULL, "~/.myapp_history", NULL);

If the history file exists, commands entered in previous sessions will be loaded. When the GetLine context is destroyed, commands entered in the current session will be appended to the file.

MULTIPLE HISTORY LISTS

Libtecla supports multiple history lists. This allows you to maintain separate histories for different contexts or command sets within your application.

You can create and manage multiple history lists using the following functions:

  History *hist_create(void);
  void hist_destroy(History *hist);
  int hist_load(History *hist, const char *filename);
  int hist_save(History *hist, const char *filename);
  int hist_add(History *hist, const char *line);
  char *hist_get(History *hist, int index);

To associate a history list with a GetLine context, use:

  void gl_set_history(GetLine *gl, History *hist);

DISPLAYING HISTORY

Libtecla provides functionality to display the command history to the user. This can be useful for commands like `history` or `fc`.

The function gl_display_history() can be used to display the history entries.

  void gl_display_history(GetLine *gl);

This function will print the history entries to the terminal, typically preceded by their history numbers.

LOOKING UP HISTORY

You can search the command history using prefixes. For example, typing `ls` and pressing Up Arrow might bring up the last command starting with `ls`.

Libtecla handles this automatically when history functionality is enabled. You can also manually search history using:

  char *gl_history_search(GetLine *gl, const char *prefix);

This function returns the most recent history entry that starts with the given prefix, or NULL if no such entry is found. The returned string is dynamically allocated and must be freed by the caller.

MANUAL HISTORY ARCHIVAL

While libtecla automatically saves history when the context is destroyed, you can also manually save the history at any point using:

  int gl_save_history(GetLine *gl);

This function saves the current command history to the file specified during context creation. It returns 0 on success and -1 on error.

MISCELLANEOUS HISTORY CONFIGURATION

Several functions allow you to configure the behavior of command history:

gl_set_history_max_len(max_len)
Sets the maximum number of lines to store in the history.
gl_set_history_duplicates(allow_duplicates)
Controls whether duplicate commands are allowed in the history.

QUERYING HISTORY INFORMATION

You can retrieve information about the command history using these functions:

gl_get_history_len(gl)
Returns the current number of lines in the history.
gl_get_history_entry(gl, index)
Returns the history entry at the specified index. The index is 0-based.

CHANGING TERMINALS

If your program needs to switch between different terminal types (e.g., connecting to a serial port and then to a network socket), you can use the gl_set_terminal() function:

  int gl_set_terminal(GetLine *gl, FILE *in, FILE *out);

This function changes the input and output streams associated with the GetLine context. It returns 0 on success and -1 on error.

Note that switching terminals might require re-initialization of certain terminal-specific settings.

EXTERNAL EVENT HANDLING

Libtecla can be integrated with external event loops (e.g., using select(2) or poll(2)). This is particularly useful in non-blocking mode.

The gl_check_notify() function can be used to check if there are any pending events that require attention:

  int gl_check_notify(GetLine *gl);

This function returns a non-zero value if there are events to process, and 0 otherwise. You would typically call this function in your event loop.

You can set an inactivity timeout for gl_get_line(). If no input is received within the specified timeout period, gl_get_line() will return prematurely.

  void gl_set_read_timeout(GetLine *gl, int seconds);

Setting the timeout to 0 disables the timeout.

SIGNAL HANDLING DEFAULTS

By default, libtecla installs handlers for certain signals (e.g., SIGINT, SIGQUIT) to ensure proper cleanup and behavior. These handlers prevent signals from interrupting the editing process abruptly.

CUSTOMIZED SIGNAL HANDLING

If you need to handle signals differently, you can disable libtecla's default signal handlers and install your own.

  void gl_set_signal_handling(GetLine *gl, int enable);

Calling this function with enable = 0 disables libtecla's handlers. Call it with enable = 1 to restore the defaults.

RELIABLE SIGNAL HANDLING

For maximum reliability, especially in signal-intensive applications, consider using libtecla's built-in signal handling mechanism. This ensures that signals are processed correctly even during terminal input operations.

THE TERMINAL SIZE

Libtecla automatically detects the terminal size (width and height) and updates it as needed. You can query the current terminal size using:

  int gl_get_screen_width(GetLine *gl);
  int gl_get_screen_height(GetLine *gl);

These functions return the current width and height of the terminal screen in characters.

HIDING WHAT YOU TYPE

For applications requiring password input or other sensitive data, you can disable the echoing of characters typed by the user.

  void gl_set_echo(GetLine *gl, int echo);

Set echo to 0 to disable echoing, and to 1 to re-enable it. Note that disabling echo affects the entire line editing session.

SINGLE CHARACTER QUERIES

In addition to line-based input, libtecla can be used to read single characters without waiting for a newline. This is useful for interactive prompts that require a simple yes/no answer.

Use the gl_get_char() function for this purpose:

  int gl_get_char(GetLine *gl);

This function reads and returns the next character from the input stream. It returns EOF on end-of-file.

READING RAW CHARACTERS

The gl_read_raw_chars() function allows you to read characters directly from the input stream without any editing or processing.

  int gl_read_raw_chars(GetLine *gl, char *buffer, int count);

This function reads up to count characters from the input and stores them in buffer. It returns the number of characters read, or -1 on error. This function is typically used internally by libtecla but can be exposed for advanced use cases. Be aware that using this function bypasses normal line editing, which might not be enough to identify such keystrokes.

CLEARING THE TERMINAL

The calling program can clear the terminal by calling gl_erase_terminal(). In non-blocking server-I/O mode, this function also arranges for the current input line to be redrawn from scratch when gl_get_line() is next called.

  int gl_erase_terminal(GetLine *gl);

DISPLAYING TEXT DYNAMICALLY

Between calls to gl_get_line(), the gl_display_text() function provides a convenient way to display paragraphs of text, left-justified and split over one or more terminal lines according to the constraints of the current width of the terminal. Examples of the use of this function may be found in the demo programs, where it is used to display introductions. In those examples the advanced use of optional prefixes, suffixes and filled lines to draw a box around the text is also illustrated.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

If gl isn't currently connected to a terminal, for example if the output of a program that uses gl_get_line() is being piped to another program or redirected to a file, then the value of the def_width parameter is used as the terminal width.

The indentation argument specifies the number of characters to use to indent each line of ouput. The fill_char argument specifies the character that will be used to perform this indentation.

The prefix argument can either be NULL, or be a string to place at the beginning of each new line (after any indentation). Similarly, the suffix argument can either be NULL, or be a string to place at the end of each line. The suffix is placed flush against the right edge of the terminal, and any space between its first character and the last word on that line is filled with the character specified via the fill_char argument. Normally the fill-character is a space.

The start argument tells gl_display_text() how many characters have already been written to the current terminal line, and thus tells it the starting column index of the cursor. Since the return value of gl_display_text() is the ending column index of the cursor, by passing the return value of one call to the start argument of the next call, a paragraph that is broken between more than one string can be composed by calling gl_display_text() for each successive portion of the paragraph. Note that literal newline characters are necessary at the end of each paragraph to force a new line to be started.

On error, gl_display_text() returns -1.

CALLBACK FUNCTION FACILITIES

Unless otherwise stated, callback functions, such as tab completion callbacks and event callbacks should not call any functions in this module. The following functions, however, are designed specifically to be used by callback functions.

Calling the gl_replace_prompt() function from a callback tells gl_get_line() to display a different prompt when the callback returns. Except in non-blocking server mode, it has no effect if used between calls to gl_get_line(). In non-blocking server mode (see the gl_io_mode(3) man page, when used between two calls to gl_get_line() that are operating on the same input line, the current input line will be re-drawn with the new prompt on the following call to gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

INTERNATIONAL CHARACTER SETS

Since libtecla version 1.4.0, gl_get_line() has been 8-bit clean. This means that all 8-bit characters that are printable in the user's current locale are now displayed verbatim and included in the returned input line. Assuming that the calling program correctly contains a call like the following,

  setlocale(LC_CTYPE, "");

then the current locale is determined by the first of the environment variables LC_CTYPE, LC_ALL, and LANG, that is found to contain a valid locale name. If none of these variables are defined, or the program neglects to call setlocale, then the default C locale is used, which is US 7-bit ASCII. On most unix-like platforms, you can get a list of valid locales by typing the command:

  locale -a

at the shell prompt. Further documentation on how the user can make use of this to enter international characters can be found in the tecla(7) man page.

THREAD SAFETY

In a multi-threaded program, you should use the libtecla_r.a version of the library. This uses reentrant versions of system functions, where available. Unfortunately neither terminfo nor termcap were designed to be reentrant, so you can't safely use the functions of the getline module in multiple threads (you can use the separate file-expansion and word-completion modules in multiple threads, see the corresponding man pages for details). However due to the use of POSIX reentrant functions for looking up home directories etc, it is safe to use this module from a single thread of a multi-threaded program, provided that your other threads don't use any termcap or terminfo functions.
