NOM

glab-ci-run - Crée ou exécute un nouveau pipeline CI/CD.

SYNTAXE

glab ci run [indicateurs]

DESCRIPTION

L'option --branch est disponible pour tous les types de pipelines.

Les options pour les variables sont incompatibles avec les pipelines de requêtes de fusion. Si elles sont utilisées avec des pipelines de requêtes de fusion, la commande échouera avec un message tel que ERROR: if any flags in the group [output output-format] are set none of the others can be

Spécifiez une ou plusieurs entrées de pipeline en utilisant l'indicateur -i ou --input pour chaque entrée. Chaque indicateur d'entrée utilise le format clé:valeur.

Les valeurs sont typées et seront par défaut de type string sauf si un type est explicitement spécifié. Pour spécifier un type, utilisez la syntaxe type(valeur). Par exemple, clé:string(valeur) passera la chaîne valeur en tant qu'entrée.

Les types valides sont :

  • string : Une valeur de type chaîne de caractères. C'est le type par défaut. Par exemple, clé:string(valeur).
  • int : Une valeur entière. Par exemple, clé:int(42).
  • float : Une valeur à virgule flottante. Par exemple, clé:float(3.14).
  • bool : Une valeur booléenne. Par exemple, clé:bool(true).
  • array : Un tableau de chaînes de caractères. Par exemple, clé:array(foo,bar).

Un tableau de chaînes peut être spécifié avec une virgule finale. Par exemple, clé:array(foo,bar,) passera le tableau [foo, bar]. array() spécifie un tableau vide. Pour passer un tableau contenant une chaîne vide, utilisez array(,).

Les arguments de valeur contenant des parenthèses doivent être échappés du shell avec des guillemets. Par exemple, --input clé:array(foo,bar) devrait être écrit comme --input 'clé:array(foo,bar)'.

OPTIONS

-b, --branch="" Crée un pipeline sur la branche/référence.

-i, --input=[] Passe des entrées au pipeline au format ':'. Ne peut pas être utilisé pour les pipelines de requêtes de fusion. Voir la documentation pour des exemples.

--mr[=false] Exécute un pipeline de requête de fusion au lieu d'un pipeline de branche.

--variables=[] Passe des variables au pipeline au format :. Ne peut pas être utilisé pour les pipelines de MR.

--variables-env=[] Passe des variables au pipeline au format :. Ne peut pas être utilisé pour les pipelines de MR.

--variables-file=[] Passe le contenu d'un fichier comme variable de fichier au pipeline au format :. Ne peut pas être utilisé pour les pipelines de MR.

-f, --variables-from="" Fichier JSON contenant des variables pour l'exécution du pipeline. Attend un tableau de hashs, chacun avec au moins 'key' et 'value'. Ne peut pas être utilisé pour les pipelines de MR.

-w, --web[=false] Ouvre le pipeline dans un navigateur. Utilise le navigateur par défaut, ou le navigateur spécifié dans la variable d'environnement BROWSER.

OPTIONS HÉRITÉES DES COMMANDES PARENT

-h, --help[=false] Affiche l'aide de cette commande.

-R, --repo="" Sélectionne un autre dépôt. Peut utiliser le format PROPRIÉTAIRE/DÉPÔT ou GROUPE/ESPACE NOMINAL/DÉPÔT. Accepte également une URL complète ou une URL Git.

EXEMPLE

$ glab ci run
$ glab ci run --variables "clé1:valeur,avec,virgule"
$ glab ci run -b main
$ glab ci run --web
$ glab ci run --mr
# Spécifier des variables CI
$ glab ci run -b main --variables-env clé1:val1
$ glab ci run -b main --variables-env clé1:val1,clé2:val2
$ glab ci run -b main --variables-env clé1:val1 --variables-env clé2:val2
$ glab ci run -b main --variables-file MONCLÉ:fichier1 --variables CLÉ2:valeur_quelconque
# Spécifier des entrées CI
$ glab ci run -b main --input clé1:val1 --input clé2:val2
$ glab ci run -b main --input "réplicas:int(3)" --input "debug:bool(false)" --input "régions:array(us-est,eu-ouest)"
// Pour un exemple de 'glab ci run -f' avec un fichier de variables, voir
// [Exécuter un pipeline CI/CD avec des variables provenant d'un fichier](https://docs.gitlab.com/editor_extensions/gitlab_cli/#run-a-cicd-pipeline-with-variables-from-a-file)
// dans la documentation GitLab.
