NOM

GlusterFS - Système de fichiers clusterisé.

SYNOPIS

glusterfsd [options] [point de montage]

DESCRIPTION

GlusterFS est un système de fichiers clusterisé capable de s'étendre à plusieurs pétaoctets. Il agrège divers blocs de stockage sur une interconnexion Infiniband RDMA ou TCP/IP pour créer un grand système de fichiers réseau parallèle. Les blocs de stockage peuvent être constitués de n'importe quel matériel courant tel qu'un serveur x86-64 avec RAID SATA-II et une carte HBA Infiniband.

GlusterFS est un système de fichiers entièrement conforme POSIX. Côté client, il dépend du paquet FUSE ; côté serveur, il fonctionne de manière transparente sur différents systèmes d'exploitation (actuellement pris en charge sur GNU/Linux, Solaris).

OPTIONS

Les arguments obligatoires ou optionnels pour les options longues sont également obligatoires ou optionnels pour les options courtes correspondantes.

Options de base

-f, --volfile=FICHIER_VOLUME
Fichier à utiliser comme FICHIER_VOLUME [défaut:/etc/glusterfs/glusterfs.vol]
-l, --log-file=FICHIER_JOURNAL
Fichier à utiliser pour la journalisation [défaut:/var/log/glusterfs/glusterfs.log]
-L, --log-level=NIVEAU_JOURNAL
Sévérité de la journalisation. Les options valides sont TRACE, DEBUG, INFO, WARNING, ERROR et CRITICAL [défaut: WARNING]
-s, --volfile-server=SERVEUR
Serveur à partir duquel obtenir le volume. Cette option remplace --volfile option

Options avancées

--localtime-logging
Activer les horodatages des journaux en heure locale.
--debug
Exécuter en mode débogage. Cette option définit --no-daemon, --log-level à DEBUG et --log-file à la console
-N, --no-daemon
Exécuter au premier plan
--read-only
Rend le système de fichiers en lecture seule
-p, --pid-file=FICHIER_PID
Fichier à utiliser comme fichier PID
-S FICHIER_SOCKET
Fichier socket à utiliser pour la communication inter-processus
--brick-name RÉPERTOIRE
Répertoire à utiliser comme répertoire d'exportation pour GlusterFS
--brick-port PORT
Port de brique à enregistrer auprès du mappeur de ports Gluster
--volfile-id=CLÉ
CLÉ du fichier de volume à récupérer depuis le serveur
--volfile-server-port=PORT
Numéro de port du serveur de fichier de volume
--volfile-server-transport=TRANSPORT
Type de transport pour obtenir le fichier de volume depuis le serveur [défaut: tcp]
--volume-name=NOM_VOLUME
Nom du volume à utiliser pour POINT_DE_MONTAGE [défaut: volume le plus haut dans FICHIER_VOLUME]
--xlator-option=NOM_VOLUME.OPTION=VALEUR
Ajouter/remplacer une option de traducteur pour un volume avec la valeur spécifiée

Options Fuse

--attribute-timeout=SECONDES
Définir le délai d'attente des attributs pour les inodes dans le module noyau fuse [défaut: 1]
--entry-timeout=SECONDES
Définir le délai d'attente des entrées dans le module noyau fuse [défaut: 1]
--direct-io-mode=BOOL
Activer/désactiver le mode direct-io dans le module fuse [défaut: activer]
--resolve-gids
Résoudre tous les groupes auxiliaires dans le traducteur fuse (max 32 sinon)
--auto-invalidation=BOOL
contrôle si le noyau fuse peut invalider automatiquement les attributs, les dentry et le cache de pages. Désactivez ceci uniquement si les mêmes fichiers/répertoires ne sont pas accédés simultanément sur deux montages différents [défaut: activé]

Options diverses

-?, --help
Donner cette liste d'aide
--usage
Donner un court message d'utilisation
-V, --version
Afficher la version du programme

FICHIERS

/etc/glusterfs/*.vol

EXEMPLES

Démarrer un serveur GlusterFS sur localhost avec le nom de volume foo

glusterfsd -s localhost --volfile-id foo.server.media-disk-1 -p /var/lib/glusterd/vols/foo/run/server-media-disk-1.pid -S /tmp/<uniqueid>.socket --brick-name /media/disk-1 -l /var/log/glusterfs/bricks/media-disk-1.log --brick-port 24009 --xlator-option foo-server.listen-port=24009
