NOM

glGet - renvoie la ou les valeurs d'un paramètre sélectionné

SPÉCIFICATION C

void glGetBooleanv(GLenumpname, GLboolean *data);

void glGetDoublev(GLenumpname, GLdouble *data);

void glGetFloatv(GLenumpname, GLfloat *data);

void glGetIntegerv(GLenumpname, GLint *data);

void glGetInteger64v(GLenumpname, GLint64 *data);

void glGetBooleani_v(GLenumtarget, GLuintindex, GLboolean *data);

void glGetIntegeri_v(GLenumtarget, GLuintindex, GLint *data);

void glGetFloati_v(GLenumtarget, GLuintindex, GLfloat *data);

void glGetDoublei_v(GLenumtarget, GLuintindex, GLdouble *data);

void glGetInteger64i_v(GLenumtarget, GLuintindex, GLint64 *data);

PARAMÈTRES

pname

Spécifie la valeur du paramètre à renvoyer pour les versions non indexées de glGet. Les constantes symboliques de la liste ci-dessous sont acceptées.

target

Spécifie la valeur du paramètre à renvoyer pour les versions indexées de glGet. Les constantes symboliques de la liste ci-dessous sont acceptées.

index

Spécifie l'index de l'élément particulier interrogé.

data

Renvoie la ou les valeurs du paramètre spécifié.

DESCRIPTION

Ces commandes renvoient des valeurs pour des variables d'état simples dans GL. pname est une constante symbolique indiquant la variable d'état à renvoyer, et data est un pointeur vers un tableau du type indiqué dans lequel placer les données renvoyées.

Une conversion de type est effectuée si data a un type différent de la valeur de la variable d'état demandée. Si glGetBooleanv est appelée, une valeur en virgule flottante (ou entière) est convertie en GL_FALSE si et seulement si elle vaut 0.0 (ou 0). Sinon, elle est convertie en GL_TRUE. Si glGetIntegerv est appelée, les valeurs booléennes sont renvoyées sous la forme GL_TRUE ou GL_FALSE, et la plupart des valeurs en virgule flottante sont arrondies à l'entier le plus proche. Les couleurs et les normales en virgule flottante sont cependant renvoyées avec une correspondance linéaire qui associe 1.0 à la valeur entière représentable la plus positive et -1.0 à la valeur entière représentable la plus négative. Si glGetFloatv ou glGetDoublev est appelée, les valeurs booléennes sont renvoyées sous la forme GL_TRUE ou GL_FALSE, et les valeurs entières sont converties en valeurs en virgule flottante.

Les constantes symboliques suivantes sont acceptées par pname:

GL_ACTIVE_TEXTURE

data renvoie une seule valeur indiquant l'unité de multitexturation active. La valeur initiale est GL_TEXTURE0. Voir glActiveTexture().

GL_ALIASED_LINE_WIDTH_RANGE

data renvoie une paire de valeurs indiquant la plage de largeurs prises en charge pour les lignes aliasées. Voir glLineWidth().

GL_ARRAY_BUFFER_BINDING

data renvoie une seule valeur, le nom de l'objet tampon actuellement lié à la cible GL_ARRAY_BUFFER. Si aucun objet tampon n'est lié à cette cible, 0 est renvoyé. La valeur initiale est 0. Voir glBindBuffer().

GL_BLEND

data renvoie une seule valeur booléenne indiquant si la fusion est activée. La valeur initiale est GL_FALSE. Voir glBlendFunc().

GL_BLEND_COLOR

data renvoie quatre valeurs, les composantes rouge, verte, bleue et alpha qui sont les composantes de la couleur de fusion. Voir glBlendColor().

GL_BLEND_DST_ALPHA

data renvoie une valeur, la constante symbolique identifiant la fonction de fusion de destination alpha. La valeur initiale est GL_ZERO. Voir glBlendFunc() et glBlendFuncSeparate().

GL_BLEND_DST_RGB

data renvoie une valeur, la constante symbolique identifiant la fonction de fusion de destination RVB. La valeur initiale est GL_ZERO. Voir glBlendFunc() et glBlendFuncSeparate().

GL_BLEND_EQUATION_RGB

data renvoie une valeur, une constante symbolique indiquant si l'équation de fusion RVB est GL_FUNC_ADD, GL_FUNC_SUBTRACT, GL_FUNC_REVERSE_SUBTRACT, GL_MIN ou GL_MAX. Voir glBlendEquationSeparate().

GL_BLEND_EQUATION_ALPHA

data renvoie une valeur, une constante symbolique indiquant si l'équation de fusion Alpha est GL_FUNC_ADD, GL_FUNC_SUBTRACT, GL_FUNC_REVERSE_SUBTRACT, GL_MIN ou GL_MAX. Voir glBlendEquationSeparate().

GL_BLEND_SRC_ALPHA

data renvoie une valeur, la constante symbolique identifiant la fonction de fusion de source alpha. La valeur initiale est GL_ONE. Voir glBlendFunc() et glBlendFuncSeparate().

GL_BLEND_SRC_RGB

data renvoie une valeur, la constante symbolique identifiant la fonction de fusion de source RVB. La valeur initiale est GL_ONE. Voir glBlendFunc() et glBlendFuncSeparate().

GL_COLOR_CLEAR_VALUE

data renvoie quatre valeurs : les composantes rouge, verte, bleue et alpha utilisées pour effacer les tampons de couleur. Les valeurs entières, si demandées, sont mappées linéairement depuis la représentation interne en virgule flottante de sorte que 1.0 renvoie la valeur entière représentable la plus positive, et -1.0 renvoie la valeur entière représentable la plus négative. La valeur initiale est (0, 0, 0, 0). Voir glClearColor().

GL_COLOR_LOGIC_OP

data renvoie une seule valeur booléenne indiquant si les valeurs de couleur RGBA d'un fragment sont fusionnées dans le framebuffer à l'aide d'une opération logique. La valeur initiale est GL_FALSE. Voir glLogicOp().

GL_COLOR_WRITEMASK

data renvoie quatre valeurs booléennes : les autorisations d'écriture rouge, verte, bleue et alpha pour les tampons de couleur. La valeur initiale est (GL_TRUE, GL_TRUE, GL_TRUE, GL_TRUE). Voir glColorMask().

GL_COMPRESSED_TEXTURE_FORMATS

data renvoie une liste de constantes symboliques de longueur GL_NUM_COMPRESSED_TEXTURE_FORMATS indiquant quels formats de texture compressés sont disponibles. Voir glCompressedTexImage2D().

GL_MAX_COMPUTE_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre maximal de blocs de stockage de shader actifs pouvant être accessibles par un shader de calcul.

GL_MAX_COMBINED_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre total maximal de blocs de stockage de shader actifs pouvant être accessibles par tous les shaders actifs.

GL_MAX_COMPUTE_UNIFORM_BLOCKS

data renvoie une valeur, le nombre maximal de blocs uniformes par shader de calcul. La valeur doit être d'au moins 14. Voir glUniformBlockBinding().

GL_MAX_COMPUTE_TEXTURE_IMAGE_UNITS

data renvoie une valeur, le nombre maximal d'unités d'image de texture prises en charge pouvant être utilisées pour accéder aux textures à partir du shader de calcul. La valeur doit être d'au moins 16. Voir glActiveTexture().

GL_MAX_COMPUTE_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre maximal de valeurs individuelles en virgule flottante, entières ou booléennes pouvant être stockées dans la mémoire des variables uniformes pour un shader de calcul. La valeur doit être d'au moins 1024. Voir glUniform().

GL_MAX_COMPUTE_ATOMIC_COUNTERS

data renvoie une seule valeur, le nombre maximal de compteurs atomiques disponibles pour les shaders de calcul.

GL_MAX_COMPUTE_ATOMIC_COUNTER_BUFFERS

data renvoie une seule valeur, le nombre maximal def tampons de compteur atomique pouvant être accessibles par un shader de calcul.

GL_MAX_COMBINED_COMPUTE_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre de mots pour les variables uniformes des shaders de calcul dans tous les blocs uniformes (y compris le défaut). La valeur doit être au moins 1. Voir glUniform().

GL_MAX_COMPUTE_WORK_GROUP_INVOCATIONS

data renvoie une valeur, le nombre d'invocations dans un seul groupe de travail local (c'est-à-dire le produit des trois dimensions) qui peut être envoyé à un shader de calcul.

GL_MAX_COMPUTE_WORK_GROUP_COUNT

Accepté par les versions indexées de glGet. data le nombre maximum de groupes de travail qui peuvent être envoyés à un shader de calcul. Les indices 0, 1 et 2 correspondent respectivement aux dimensions X, Y et Z.

GL_MAX_COMPUTE_WORK_GROUP_SIZE

Accepté par les versions indexées de glGet. data la taille maximale d'un groupe de travail qui peut être utilisée lors de la compilation d'un shader de calcul. Les indices 0, 1 et 2 correspondent respectivement aux dimensions X, Y et Z.

GL_DISPATCH_INDIRECT_BUFFER_BINDING

data renvoie une seule valeur, le nom de l'objet tampon actuellement lié à la cible GL_DISPATCH_INDIRECT_BUFFER. Si aucun objet tampon n'est lié à cette cible, 0 est renvoyé. La valeur initiale est 0. Voir glBindBuffer().

GL_MAX_DEBUG_GROUP_STACK_DEPTH

data renvoie une seule valeur, la profondeur maximale de la pile de groupes de messages de débogage.

GL_DEBUG_GROUP_STACK_DEPTH

data renvoie une seule valeur, la profondeur actuelle de la pile de groupes de messages de débogage.

GL_CONTEXT_FLAGS

data renvoie une valeur, les indicateurs avec lesquels le contexte a été créé (tels que la fonctionnalité de débogage).

GL_CULL_FACE

data renvoie une seule valeur booléenne indiquant si l'écrêtage des polygones est activé. La valeur initiale est GL_FALSE. Voir glCullFace().

GL_CULL_FACE_MODE

data renvoie une seule valeur indiquant le mode d'écrêtage des polygones. La valeur initiale est GL_BACK. Voir glCullFace().

GL_CURRENT_PROGRAM

data renvoie une valeur, le nom de l'objet programme qui est actuellement actif, ou 0 si aucun objet programme n'est actif. Voir glUseProgram().

GL_DEPTH_CLEAR_VALUE

data renvoie une valeur, la valeur utilisée pour effacer le tampon de profondeur. Les valeurs entières, si demandées, sont linéairement mappées à partir de la représentation interne à virgule flottante de telle sorte que 1.0 renvoie la valeur entière représentable la plus positive, et -1.0 renvoie la valeur entière représentable la plus négative. La valeur initiale est 1. Voir glClearDepth().

GL_DEPTH_FUNC

data renvoie une valeur, la constante symbolique qui indique la fonction de comparaison de profondeur. La valeur initiale est GL_LESS. Voir glDepthFunc().

GL_DEPTH_RANGE

data renvoie deux valeurs : les limites de mappage proche et lointain pour le tampon de profondeur. Les valeurs entières, si demandées, sont linéairement mappées à partir de la représentation interne à virgule flottante de telle sorte que 1.0 renvoie la valeur entière représentable la plus positive, et -1.0 renvoie la valeur entière représentable la plus négative. La valeur initiale est (0, 1). Voir glDepthRange().

GL_DEPTH_TEST

data renvoie une seule valeur booléenne indiquant si le test de profondeur des fragments est activé. La valeur initiale est GL_FALSE. Voir glDepthFunc() et glDepthRange().

GL_DEPTH_WRITEMASK

data renvoie une seule valeur booléenne indiquant si le tampon de profondeur est activé pour l'écriture. La valeur initiale est GL_TRUE. Voir glDepthMask().

GL_DITHER

data renvoie une seule valeur booléenne indiquant si la tramage des couleurs et des indices de fragments est activé. La valeur initiale est GL_TRUE.

GL_DOUBLEBUFFER

data renvoie une seule valeur booléenne indiquant si le double buffering est pris en charge.

GL_DRAW_BUFFER

data renvoie une valeur, une constante symbolique indiquant vers quels tampons le dessin est effectué. Voir glDrawBuffer(). La valeur initiale est GL_BACK s'il y a des tampons arrière, sinon c'est GL_FRONT.

GL_DRAW_BUFFERi

data renvoie une valeur, une constante symbolique indiquant vers quels tampons le dessin est effectué pour la sortie couleur correspondante. Voir glDrawBuffers(). La valeur initiale de GL_DRAW_BUFFER0 est GL_BACK s'il y a des tampons arrière, sinon c'est GL_FRONT. Les valeurs initiales des tampons de dessin pour toutes les autres sorties couleur sont GL_NONE.

GL_DRAW_FRAMEBUFFER_BINDING

data renvoie une valeur, le nom de l'objet framebuffer actuellement lié à la cible GL_DRAW_FRAMEBUFFER. Si le framebuffer défaut est lié, cette valeur sera zéro. La valeur initiale est zéro. Voir glBindFramebuffer().

GL_READ_FRAMEBUFFER_BINDING

data renvoie une valeur, le nom de l'objet framebuffer actuellement lié à la cible GL_READ_FRAMEBUFFER. Si le framebuffer défaut est lié, cette valeur sera zéro. La valeur initiale est zéro. Voir glBindFramebuffer().

GL_ELEMENT_ARRAY_BUFFER_BINDING

data renvoie une seule valeur, le nom de l'objet tampon actuellement lié à la cible GL_ELEMENT_ARRAY_BUFFER. Si aucun objet tampon n'est lié à cette cible, 0 est renvoyé. La valeur initiale est 0. Voir glBindBuffer().

GL_FRAGMENT_SHADER_DERIVATIVE_HINT

data renvoie une valeur, une constante symbolique indiquant le mode de l'indice de précision des dérivées pour les shaders de fragments. La valeur initiale est GL_DONT_CARE. Voir glHint().

GL_IMPLEMENTATION_COLOR_READ_FORMAT

data renvoie une seule valeur GLenum indiquant le format des données de pixels préféré par l'implémentation. Voir glReadPixels().

GL_IMPLEMENTATION_COLOR_READ_TYPE

data renvoie une seule valeur GLenum indiquant le type des données de pixels préféré par l'implémentation. Voir glReadPixels().

GL_LINE_SMOOTH

data renvoie une seule valeur booléenne indiquant si l'antialiasing des lignes est activé. La valeur initiale est GL_FALSE. Voir glLineWidth().

GL_LINE_SMOOTH_HINT

data renvoie une valeur, une constante symbolique indiquant le mode de l'indice d'antialiasing des lignes. La valeur initiale est GL_DONT_CARE. Voir glHint().

GL_LINE_WIDTH

data renvoie une valeur, la largeur de ligne spécifiée avec glLineWidth(). La valeur initiale est 1.

GL_LAYER_PROVOKING_VERTEX

data renvoie une valeur, la spécification dépendante de l'implémentation du sommet d'un primitive utilisé pour sélectionner la couche de rendu. Si la valeur renvoyée est équivalente à GL_PROVOKING_VERTEX, alors la sélection du sommet suit la convention spécifiée par glProvokingVertex(). Si la valeur renvoyée est équivalente à GL_FIRST_VERTEX_CONVENTION, alors la sélection est toujours prise du premier sommet de la primitive. Si la valeur renvoyée est équivalente à GL_LAST_VERTEX_CONVENTION, alors la sélection est toujours prise du dernier sommet de la primitive. Si la valeur renvoyée est équivalente à GL_UNDEFINED_VERTEX, alors la sélection n'est pas garantie d'être prise d'un sommet spécifique de la primitive.

GL_LOGIC_OP_MODE

data renvoie une valeur, une constante symbolique indiquant le mode de l'opération logique sélectionné. La valeur initiale est GL_COPY. Voir glLogicOp().

GL_MAJOR_VERSION

data renvoie une valeur, le numéro de version majeure de l'API OpenGL prise en charge par le contexte actuel.

GL_MAX_3D_TEXTURE_SIZE

data renvoie une valeur, une estimation approximative de la plus grande texture 3D que la GL peut gérer. La valeur doit être au moins 64. Utilisez GL_PROXY_TEXTURE_3D pour déterminer si une texture est trop grande. Voir glTexImage3D().

GL_MAX_ARRAY_TEXTURE_LAYERS

data renvoie une valeur. La valeur indique le nombre maximum de couches autorisées dans une texture tableau, et doit être au moins 256. Voir glTexImage2D().

GL_MAX_CLIP_DISTANCES

data renvoie une valeur, le nombre maximum de distances de découpage définies par l'application. La valeur doit être au moins 8.

GL_MAX_COLOR_TEXTURE_SAMPLES

data renvoie une valeur, le nombre maximum d'échantillons dans une texture multisample couleur.

GL_MAX_COMBINED_ATOMIC_COUNTERS

data renvoie une seule valeur, le nombre maximum de compteurs atomiques disponibles pour tous les shaders actifs.

GL_MAX_COMBINED_FRAGMENT_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre de mots pour les variables uniformes des shaders de fragments dans tous les blocs uniformes (y compris le défaut). La valeur doit être au moins 1. Voir glUniform().

GL_MAX_COMBINED_GEOMETRY_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre de mots pour les variables uniformes des shaders géométriques dans tous les blocs uniformes (y compris le défaut). La valeur doit être au moins 1. Voir glUniform().

GL_MAX_COMBINED_TEXTURE_IMAGE_UNITS

data renvoie une valeur, le nombre maximum d'unités d'images de texture prises en charge qui peuvent être utilisées pour accéder aux cartes de texture à partir du shader de sommets et du processeur de fragments combinés. Si le shader de sommets et l'étape de traitement des fragments accèdent à la même unité d'image de texture, cela compte comme l'utilisation de deux unités d'images de texture par rapport à cette limite. La valeur doit être au moins 48. Voir glActiveTexture().

GL_MAX_COMBINED_UNIFORM_BLOCKS

data renvoie une valeur, le nombre maximum de blocs uniformes par programme. La valeur doit être au moins 70. Voir glUniformBlockBinding().

GL_MAX_COMBINED_VERTEX_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre de mots pour les variables uniformes des shaders de sommets dans tous les blocs uniformes (y compris le défaut). La valeur doit être au moins 1. Voir glUniform().

GL_MAX_CUBE_MAP_TEXTURE_SIZE

data renvoie une valeur. La valeur donne une estimation approximative de la plus grande texture cube-map que
t le GL peut gérer. La valeur doit être d'au moins 1024. Utilisez GL_PROXY_TEXTURE_CUBE_MAP pour déterminer si une texture est trop grande. Voir glTexImage2D().

GL_MAX_DEPTH_TEXTURE_SAMPLES

data renvoie une valeur, le nombre maximal d'échantillons dans une texture de profondeur ou profondeur-stencil multisample.

GL_MAX_DRAW_BUFFERS

data renvoie une valeur, le nombre maximal de sorties simultanées qui peuvent être écrites dans un shader de fragment. La valeur doit être d'au moins 8. Voir glDrawBuffers().

GL_MAX_DUAL_SOURCE_DRAW_BUFFERS

data renvoie une valeur, le nombre maximal de tampons de dessin actifs lors de l'utilisation du mélange à double source. La valeur doit être d'au moins 1. Voir glBlendFunc() et glBlendFuncSeparate().

GL_MAX_ELEMENTS_INDICES

data renvoie une valeur, le nombre maximal recommandé d'indices de tableau de sommets. Voir glDrawRangeElements().

GL_MAX_ELEMENTS_VERTICES

data renvoie une valeur, le nombre maximal recommandé de sommets de tableau de sommets. Voir glDrawRangeElements().

GL_MAX_FRAGMENT_ATOMIC_COUNTERS

data renvoie une valeur unique, le nombre maximal de compteurs atomiques disponibles pour les shaders de fragment.

GL_MAX_FRAGMENT_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre maximal de blocs de stockage de shader actifs qui peuvent être accessibles par un shader de fragment.

GL_MAX_FRAGMENT_INPUT_COMPONENTS

data renvoie une valeur, le nombre maximal de composantes des entrées lues par le shader de fragment, qui doit être d'au moins 128.

GL_MAX_FRAGMENT_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre maximal de valeurs individuelles flottantes, entières ou booléennes qui peuvent être stockées dans le stockage de variables uniformes pour un shader de fragment. La valeur doit être d'au moins 1024. Voir glUniform().

GL_MAX_FRAGMENT_UNIFORM_VECTORS

data renvoie une valeur, le nombre maximal de vecteurs 4 individuels de valeurs flottantes, entières ou booléennes qui peuvent être stockés dans le stockage de variables uniformes pour un shader de fragment. La valeur est égale à la valeur de GL_MAX_FRAGMENT_UNIFORM_COMPONENTS divisée par 4 et doit être d'au moins 256. Voir glUniform().

GL_MAX_FRAGMENT_UNIFORM_BLOCKS

data renvoie une valeur, le nombre maximal de blocs uniformes par shader de fragment. La valeur doit être d'au moins 12. Voir glUniformBlockBinding().

GL_MAX_FRAMEBUFFER_WIDTH

data renvoie une valeur, la largeur maximale pour un framebuffer qui n'a pas d'attachements, qui doit être d'au moins 16384. Voir

glFramebufferParameter.

GL_MAX_FRAMEBUFFER_HEIGHT

data renvoie une valeur, la hauteur maximale pour un framebuffer qui n'a pas d'attachements, qui doit être d'au moins 16384. Voir

glFramebufferParameter.

GL_MAX_FRAMEBUFFER_LAYERS

data renvoie une valeur, le nombre maximal de couches pour un framebuffer qui n'a pas d'attachements, qui doit être d'au moins 2048. Voir

glFramebufferParameter.

GL_MAX_FRAMEBUFFER_SAMPLES

data renvoie une valeur, le nombre maximal d'échantillons dans un framebuffer qui n'a pas d'attachements, qui doit être d'au moins 4. Voir

glFramebufferParameter.

GL_MAX_GEOMETRY_ATOMIC_COUNTERS

data renvoie une valeur unique, le nombre maximal de compteurs atomiques disponibles pour les shaders de géométrie.

GL_MAX_GEOMETRY_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre maximal de blocs de stockage de shader actifs qui peuvent être accessibles par un shader de géométrie.

GL_MAX_GEOMETRY_INPUT_COMPONENTS

data renvoie une valeur, le nombre maximal de composantes des entrées lues par un shader de géométrie, qui doit être d'au moins 64.

GL_MAX_GEOMETRY_OUTPUT_COMPONENTS

data renvoie une valeur, le nombre maximal de composantes des sorties écrites par un shader de géométrie, qui doit être d'au moins 128.

GL_MAX_GEOMETRY_TEXTURE_IMAGE_UNITS

data renvoie une valeur, le nombre maximal d'unités d'image de texture prises en charge qui peuvent être utilisées pour accéder aux mappages de texture depuis le shader de géométrie. La valeur doit être d'au moins 16. Voir glActiveTexture().

GL_MAX_GEOMETRY_UNIFORM_BLOCKS

data renvoie une valeur, le nombre maximal de blocs uniformes par shader de géométrie. La valeur doit être d'au moins 12. Voir glUniformBlockBinding().

GL_MAX_GEOMETRY_UNIFORM_COMPONENTS

data renvoie une valeur, le nombre maximal de valeurs individuelles flottantes, entières ou booléennes qui peuvent être stockées dans le stockage de variables uniformes pour un shader de géométrie. La valeur doit être d'au moins 1024. Voir glUniform().

GL_MAX_INTEGER_SAMPLES

data renvoie une valeur, le nombre maximal d'échantillons pris en charge dans les tampons multisamples au format entier.

GL_MIN_MAP_BUFFER_ALIGNMENT

data renvoie une valeur, l'alignement minimal en unités machine de base des pointeurs renvoyés parglMapBuffer() et glMapBufferRange(). Cette valeur doit être une puissance de deux et doit être d'au moins 64.

GL_MAX_LABEL_LENGTH

data renvoie une valeur, la longueur maximale d'un étiquette qui peut être assignée à un objet. Voir glObjectLabel() et glObjectPtrLabel().

GL_MAX_PROGRAM_TEXEL_OFFSET

data renvoie une valeur, le décalage de texel maximal autorisé dans une recherche de texture, qui doit être d'au moins 7.

GL_MIN_PROGRAM_TEXEL_OFFSET

data renvoie une valeur, le décalage de texel minimal autorisé dans une recherche de texture, qui doit être au plus -8.

GL_MAX_RECTANGLE_TEXTURE_SIZE

data renvoie une valeur. La valeur donne une estimation approximative de la plus grande texture rectangulaire que le GL peut gérer. La valeur doit être d'au moins 1024. Utilisez GL_PROXY_TEXTURE_RECTANGLE pour déterminer si une texture est trop grande. Voir glTexImage2D().

GL_MAX_RENDERBUFFER_SIZE

data renvoie une valeur. La valeur indique la taille maximale prise en charge pour les tampons de rendu. Voir glFramebufferRenderbuffer().

GL_MAX_SAMPLE_MASK_WORDS

data renvoie une valeur, le nombre maximal de mots de masque d'échantillonnage.

GL_MAX_SERVER_WAIT_TIMEOUT

data renvoie une valeur, l'intervalle maximal de glWaitSync() d'attente.

GL_MAX_SHADER_STORAGE_BUFFER_BINDINGS

data renvoie une valeur, le nombre maximal de points de liaison de tampon de stockage de shader sur le contexte, qui doit être d'au moins 8.

GL_MAX_TESS_CONTROL_ATOMIC_COUNTERS

data renvoie une valeur unique, le nombre maximal de compteurs atomiques disponibles pour les shaders de contrôle de tessellation.

GL_MAX_TESS_EVALUATION_ATOMIC_COUNTERS

data renvoie une valeur unique, le nombre maximal de compteurs atomiques disponibles pour les shaders d'évaluation de tessellation.

GL_MAX_TESS_CONTROL_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre maximal de blocs de stockage de shader actifs qui peuvent être accessibles par un shader de contrôle de tessellation.

GL_MAX_TESS_EVALUATION_SHADER_STORAGE_BLOCKS

data renvoie une valeur, le nombre maximal de blocs de stockage de shader actifs qui peuvent être accessibles par un shader d'évaluation de tessellation.

GL_MAX_TEXTURE_BUFFER_SIZE

data renvoie une valeur. La valeur donne le nombre maximal de texels autorisés dans le tableau de texels d'un objet tampon de texture. La valeur doit être d'au moins 65536.

GL_MAX_TEXTURE_IMAGE_UNITS

data renvoie une valeur, le nombre maximal d'unités d'image de texture prises en charge qui peuvent être utilisées pour accéder aux mappages de texture depuis le shader de fragment. La valeur doit être d'au moins 16. Voir glActiveTexture().

GL_MAX_TEXTURE_LOD_BIAS

data renvoie une valeur, la valeur absolue maximale du biais de niveau de détail de la texture. La valeur doit être d'au moins 2.0.

GL_MAX_TEXTURE_SIZE

data renvoie une valeur. La valeur donne une estimation approximative de la plus grande texture que le GL peut gérer. La valeur doit être d'au moins 1024. Utilisez une cible de texture proxy telle que GL_PROXY_TEXTURE_1D ou GL_PROXY_TEXTURE_2D pour déterminer si une texture est trop grande. Voir glTexImage1D() et glTexImage2D().

GL_MAX_UNIFORM_BUFFER_BINDINGS

data renvoie une valeur, le nombre maximal de points de liaison de tampon uniforme sur le contexte, qui doit être d'au moins 36.

GL_MAX_UNIFORM_BLOCK_SIZE

GL_UNPACK_SWAP_BYTES

data retourne une seule valeur booléenne indiquant si les octets des indices et des composantes de pixels de deux octets et de quatre octets sont échangés après avoir été lus depuis la mémoire. La valeur initiale est GL_FALSE. Voir glPixelStore().

GL_VERTEX_ARRAY_BINDING

data retourne une seule valeur, le nom de l'objet de tableau de sommets actuellement lié au contexte. Si aucun objet de tableau de sommets n'est lié au contexte, 0 est retourné. La valeur initiale est 0. Voir glBindVertexArray().

GL_VERTEX_BINDING_DIVISOR

Accepté par les formes indexées. data retourne une seule valeur entière représentant le diviseur de pas d'instance du premier élément dans le stockage de données du tampon lié pour l'attribut de sommet lié à l'index index.

GL_VERTEX_BINDING_OFFSET

Accepté par les formes indexées. data retourne une seule valeur entière représentant le décalage en octets du premier élément dans le stockage de données du tampon lié pour l'attribut de sommet lié à l'index index.

GL_VERTEX_BINDING_STRIDE

Accepté par les formes indexées. data retourne une seule valeur entière représentant le décalage en octets entre le début de chaque élément dans le stockage de données du tampon lié pour l'attribut de sommet lié à l'index index.

GL_VERTEX_BINDING_BUFFER

Accepté par les formes indexées. data retourne une seule valeur entière représentant le nom du tampon lié à la liaison de sommet index.

GL_MAX_VERTEX_ATTRIB_RELATIVE_OFFSET

data retourne une seule valeur entière contenant le décalage maximal qui peut être ajouté à un décalage de liaison de sommet.

GL_MAX_VERTEX_ATTRIB_BINDINGS

data retourne une seule valeur entière contenant le nombre maximal de tampons de sommets qui peuvent être liés.

GL_VIEWPORT

Utilisé avec les variantes non indexées de glGet (telles que glGetIntegerv), data retourne quatre valeurs : les coordonnées x et y de la fenêtre de la zone de vue, suivies de sa largeur et de sa hauteur. Initialement, les coordonnées x et y de la fenêtre sont toutes deux mises à 0, et la largeur et la hauteur sont définies sur la largeur et la hauteur de la fenêtre dans laquelle le GL effectuera son rendu. Voir glViewport().

Utilisé avec les variantes indexées de glGet (telles que glGetIntegeri_v), data retourne quatre valeurs : les coordonnées x et y de la fenêtre de la zone de vue indexée, suivies de sa largeur et de sa hauteur. Initialement, les coordonnées x et y de la fenêtre sont toutes deux mises à 0, et la largeur et la hauteur sont définies sur la largeur et la hauteur de la fenêtre dans laquelle le GL effectuera son rendu. Voir

glViewportIndexedf.

GL_VIEWPORT_BOUNDS_RANGE

data retourne deux valeurs, la plage minimale et maximale des limites de la zone de vue. La plage minimale devrait être d'au moins [-32768, 32767].

GL_VIEWPORT_INDEX_PROVOKING_VERTEX

data retourne une valeur, le sommet dépendant de l'implémentation d'un primitiva qui est utilisé pour sélectionner l'indice de la zone de vue. Si la valeur retournée est équivalente à GL_PROVOKING_VERTEX, alors la sélection du sommet suit la convention spécifiée par glProvokingVertex(). Si la valeur retournée est équivalente à GL_FIRST_VERTEX_CONVENTION, alors la sélection est toujours prise du premier sommet de la primitive. Si la valeur retournée est équivalente à GL_LAST_VERTEX_CONVENTION, alors la sélection est toujours prise du dernier sommet de la primitive. Si la valeur retournée est équivalente à GL_UNDEFINED_VERTEX, alors la sélection n'est pas garantie d'être prise d'un sommet spécifique de la primitive.

GL_VIEWPORT_SUBPIXEL_BITS

data retourne une seule valeur, le nombre de bits de précision sub-pixel que le GL utilise pour interpréter les limites de la zone de vue en virgule flottante. La valeur minimale est 0.

GL_MAX_ELEMENT_INDEX

data retourne une seule valeur, l'indice maximal qui peut être spécifié lors du transfert d'attributs de sommet génériques vers le GL.

Beaucoup des paramètres booléens peuvent également être interrogés plus facilement en utilisant glIsEnabled().

NOTES

Les paramètres suivants retournent la valeur associée pour l'unité de texture active : GL_TEXTURE_1D, GL_TEXTURE_BINDING_1D, GL_TEXTURE_2D, GL_TEXTURE_BINDING_2D, GL_TEXTURE_3D et GL_TEXTURE_BINDING_3D.

GL_MAX_VIEWPORTS, GL_VIEWPORT_SUBPIXEL_BITS, GL_VIEWPORT_BOUNDS_RANGE, GL_LAYER_PROVOKING_VERTEX et GL_VIEWPORT_INDEX_PROVOKING_VERTEX sont disponibles uniquement si la version du GL est 4.1 ou supérieure.

GL_MAX_VERTEX_ATOMIC_COUNTERS, GL_MAX_TESS_CONTROL_ATOMIC_COUNTERS, GL_MAX_TESS_EVALUATION_ATOMIC_COUNTERS, GL_MAX_GEOMETRY_ATOMIC_COUNTERS, GL_MAX_FRAGMENT_ATOMIC_COUNTERS et GL_MIN_MAP_BUFFER_ALIGNMENT sont acceptés par pname uniquement si la version du GL est 4.2 ou supérieure.

GL_MAX_ELEMENT_INDEX est accepté par pname uniquement si la version du GL est 4.3 ou supérieure.

GL_MAX_COMPUTE_UNIFORM_BLOCKS, GL_MAX_COMPUTE_TEXTURE_IMAGE_UNITS, GL_MAX_COMPUTE_UNIFORM_COMPONENTS, GL_MAX_COMPUTE_ATOMIC_COUNTERS, GL_MAX_COMPUTE_ATOMIC_COUNTER_BUFFERS, GL_MAX_COMBINED_COMPUTE_UNIFORM_COMPONENTS, GL_MAX_COMPUTE_WORK_GROUP_INVOCATIONS, GL_MAX_COMPUTE_WORK_GROUP_COUNT et GL_MAX_COMPUTE_WORK_GROUP_SIZE et GL_DISPATCH_INDIRECT_BUFFER_BINDING sont disponibles uniquement si la version du GL est 4.3 ou supérieure.

GL_MAX_DEBUG_GROUP_STACK_DEPTH, GL_DEBUG_GROUP_STACK_DEPTH et GL_MAX_LABEL_LENGTH sont acceptés uniquement si la version du GL est 4.3 ou supérieure.

GL_MAX_UNIFORM_LOCATIONS est accepté uniquement si la version du GL est 4.3 ou supérieure.

GL_MAX_FRAMEBUFFER_WIDTH, GL_MAX_FRAMEBUFFER_HEIGHT, GL_MAX_FRAMEBUFFER_LAYERS et GL_MAX_FRAMEBUFFER_SAMPLES sont disponibles uniquement si la version du GL est 4.3 ou supérieure.

GL_MAX_VERTEX_SHADER_STORAGE_BLOCKS, GL_MAX_TESS_CONTROL_SHADER_STORAGE_BLOCKS, GL_MAX_TESS_EVALUATION_SHADER_STORAGE_BLOCKS, GL_MAX_GEOMETRY_SHADER_STORAGE_BLOCKS, GL_MAX_FRAGMENT_SHADER_STORAGE_BLOCKS et GL_MAX_COMPUTE_SHADER_STORAGE_BLOCKS ne sont disponibles que si la version GL est 4.3 ou supérieure.

GL_TEXTURE_BUFFER_OFFSET_ALIGNMENT n'est disponible que si la version GL est 4.3 ou supérieure.

GL_VERTEX_BINDING_DIVISOR, GL_VERTEX_BINDING_OFFSET, GL_VERTEX_BINDING_STRIDE, GL_VERTEX_BINDING_BUFFER, GL_MAX_VERTEX_ATTRIB_RELATIVE_OFFSET et GL_MAX_VERTEX_ATTRIB_BINDINGS ne sont disponibles que si la version GL est 4.3 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré si pname n'est pas une valeur acceptée.

GL_INVALID_VALUE est généré dans l'un des cas suivants pour glGetBooleani_v, glGetIntegeri_v, ou glGetInteger64i_v si index est en dehors de la plage valide pour l'état indexé target.
