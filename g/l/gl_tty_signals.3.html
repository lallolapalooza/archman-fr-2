RENDRE LE TERMINAL Une complication unique au mode serveur non bloquant est qu'il nécessite que le terminal soit laissé en mode brut entre les appels à gl_get_line() . Si ce n'était pas le cas, la boucle d'événements externe ne pourrait pas détecter les pressions de touches individuelles, et l'édition de ligne de base implémentée par le pilote du terminal entrerait en conflit avec l'édition fournie par gl_get_line() . Cela signifie que chaque fois que le terminal doit être utilisé pour autre chose que la saisie d'une nouvelle ligne d'entrée avec gl_get_line() , il doit être restauré à un état utilisable. Nom

gl_tty_signals - Gérer les signaux du terminal pour la saisie de ligne.

Synopsis

#include <tecla.h>

Description

Ce manuel décrit la gestion des signaux du terminal par la bibliothèque tecla.

Mode d'E/S Serveur

En mode d'E/S serveur non bloquant, la bibliothèqueTecla peut gérer les signaux, ce qui permet aux applications de répondre à certains signaux sans avoir à quitter immédiatement. Ceci est réalisé en utilisant la fonction gl_handle_signal().

  int gl_handle_signal(GetLine *gl, int sig);

Cette fonction est conçue pour être appelée par un gestionnaire de signaux. Si le signal `sig` est un signal que gl_get_line() est actuellement configuré pour attraper (voir gl_trap_signal()), gl_handle_signal() retournera 1. Sinon, elle retournera 0.

Les fonctions suivantes peuvent être appelées depuis les gestionnaires de signaux :

  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line()

Pour que cela soit sûr, il faut suivre certaines règles, décrites plus loin dans la section "FONCTIONS SÛRES POUR LES SIGNAUX".

Si gl_handle_signal() retourne 1, le gestionnaire de signaux doit simplement retourner. Si elle retourne 0, le gestionnaire de signaux peut effectuer les actions qu'il juge appropriées pour les signaux non gérés par tecla.

La valeur de retour de gl_handle_signal() est souvent ignorée, car les gestionnaires de signaux peuvent également utiliser la fonction gl_return_status() pour déterminer le statut de retour de l'appel précédent à gl_get_line(). La fonction gl_return_status() retourne une des valeurs suivantes :

GLR_SIGNAL
Un signal configuré pour être intercepté par gl_get_line() a été reçu.
GLR_BLOCKED
L'attente d'E/S a expiré (voir gl_inactivity_timeout()).
GLR_LINE
Une ligne a été entrée par l'utilisateur.
GLR_EOF
Fin de fichier reçue.

Abandonner le Terminal

En mode serveur non bloquant, il est parfois nécessaire que le programme libère temporairement le terminal afin que d'autres processus puissent l'utiliser. Ceci est réalisé en appelant la fonction gl_release_terminal().

  void gl_release_terminal(GetLine *gl);

Cette fonction effectue les opérations suivantes :

  • Elle vide la mémoire tampon de sortie du terminal.
  • Elle restaure les paramètres du terminal à leurs valeurs d'origine.
  • Elle abandonne la ligne d'entrée en cours.
  • Elle imprime une nouvelle invite sur la ligne suivante.
  • Elle commence à accepter la saisie pour une nouvelle ligne.

La fonction gl_get_line() ne peut être appelée qu'une fois par tour de boucle d'événements. Si vous utilisez gl_release_terminal(), vous devez vous assurer que gl_get_line() n'est pas appelée pendant que le terminal est libéré.

Gestion des Signaux

La bibliothèqueTecla fournit des mécanismes pour gérer les signaux lorsqu'elle est utilisée en mode serveur non bloquant.

Signaux de terminaison de processus.

Les signaux tels que SIGINT, SIGTERM et SIGHUP sont généralement utilisés pour terminer un processus. En mode serveur non bloquant, ces signaux peuvent être gérés de manière à ne pas interrompre brutalement l'application.

Si un tel signal est reçu, gl_handle_signal() sera appelée. Si elle retourne 1, le gestionnaire de signaux doit simplement se terminer. La bibliothèqueTecla se chargera de la gestion appropriée du signal, par exemple en annulant la ligne d'entrée en cours et en réaffichant l'invite.

Si gl_handle_signal() retourne 0, cela signifie que le signal reçu n'est pas géré par la bibliothèqueTecla. Le gestionnaire de signaux doit alors effectuer l'action appropriée, comme quitter le programme.

Signaux de suspension de processus.

Les signaux tels que SIGTSTP sont utilisés pour suspendre un processus. En mode serveur non bloquant, ces signaux peuvent être gérés pour permettre au programme de reprendre plus tard.

Si SIGTSTP est reçu, gl_handle_signal() sera appelée. Si elle retourne 1, le gestionnaire de signaux doit simplement se terminer. La bibliothèqueTecla mettra le processus en arrière-plan et restaurera le terminal. Lorsque le processus sera ramené au premier plan, il pourra continuer.

Si gl_handle_signal() retourne 0, le gestionnaire de signaux doit gérer SIGTSTP lui-même, par exemple en envoyant SIGSTOP au processus.

Interruption de la boucle d'événements

Le mode serveur non bloquant est conçu pour être utilisé avec une boucle d'événements. Il est possible d'interrompre cette boucle de manière contrôlée en utilisant les signaux.

Lorsque gl_get_line() est appelée en mode serveur non bloquant, elle peut retourner prématurément si un signal configuré est reçu. Dans ce cas, gl_return_status() retournera GLR_SIGNAL.

Le gestionnaire de signaux doit alors décider s'il faut continuer à attendre une entrée utilisateur, abandonner la ligne en cours, ou quitter l'application. Si le gestionnaire de signaux appelle gl_handle_signal() et que celle-ci retourne 1, la bibliothèqueTecla s'occupera de la gestion du signal.

Si le gestionnaire de signaux souhaite abandonner la ligne en cours au lieu de la laisser se terminer par le signal, il doit appeler gl_abandon_line() au lieu de simplement laisser gl_handle_signal() gérer le signal.

Signaux interceptés par GL_GET_LINE

Par défaut, gl_get_line() est configuré pour intercepter les signaux suivants :

  SIGINT, SIGQUIT, SIGTSTP, SIGTTIN, SIGTTOU, SIGINFO

Vous pouvez modifier cette liste en utilisant la fonction gl_trap_signal().

  void gl_trap_signal(GetLine *gl, int sig, int trap);

Si `trap` est défini sur 1, le signal `sig` sera intercepté par gl_get_line(). Si `trap` est défini sur 0, le signal `sig` ne sera pas intercepté.

Il est important de noter que si vous interceptez un signal qui doit normalement entraîner la terminaison du processus (par exemple, SIGINT), vous devez vous assurer que votre gestionnaire de signaux gère correctement cette éventualité, par exemple en appelant gl_handle_signal() et en vérifiant sa valeur de retour.

Si le gestionnaire de signaux appelle gl_handle_signal() et que celle-ci retourne 1, le gestionnaire doit simplement retourner. La bibliothèque se chargera de la gestion du signal. Si gl_handle_signal() retourne 0, cela signifie que le signal n'est pas intercepté par gl_get_line(), et le gestionnaire doit alors effectuer l'action appropriée, qui peut inclure la terminaison du processus.

L'appel à gl_get_line() peut retourner prématurément lorsqu'un signal intercepté est reçu. Dans ce cas, gl_return_status() retournera GLR_SIGNAL.

Abandonner la Saisie de Ligne

Souvent, plutôt que de laisser un signal terminer le processus, les applications répondent au signal d'interruption utilisateur SIGINT en abandonnant la ligne de saisie en cours. La manière de faire cela en mode E/S serveur non bloquant est de ne pas appeler gl_handle_signal() lorsque ce signal est intercepté, mais d'appeler plutôt gl_abandon_line().

  void gl_abandon_line(GetLine *gl);

Cette fonction fait en sorte que lorsque gl_get_line() est appelée ultérieurement, elle vide d'abord toute sortie en attente vers le terminal, puis écarte la ligne de saisie en cours, affiche une nouvelle invite sur la ligne suivante, et enfin commence à accepter la saisie d'une nouvelle ligne de l'utilisateur.

FONCTIONS SÛRES POUR LES SIGNAUX

À condition que certaines règles soient suivies, les fonctions suivantes peuvent être appelées en toute sécurité depuis des gestionnaires de signaux. D'autres fonctions de cette bibliothèque ne doivent pas être appelées depuis des gestionnaires de signaux.

  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line()

Pour que cela soit vrai, tous les gestionnaires de signaux qui appellent ces fonctions doivent être enregistrés de telle sorte qu'une seule instance de chacun d'eux puisse être en cours d'exécution à la fois. La façon de faire cela est d'utiliser la fonction POSIX sigaction() pour enregistrer tous les gestionnaires de signaux, et lors de cette opération, utiliser le membre sa_mask de la structure sigaction correspondante pour indiquer que tous les signaux dont les gestionnaires invoquent les fonctions ci-dessus doivent être bloqués lorsque le signal courant est traité. Cela empêche deux gestionnaires de signaux d'opérer simultanément sur un objet GetLine.

Pour empêcher les gestionnaires de signaux d'accéder à un objet GetLine pendant que gl_get_line() ou l'une de ses fonctions publiques associées l'exploite, toutes les fonctions publiques associées à gl_get_line(), y compris gl_get_line() elle-même, bloquent temporairement la livraison des signaux lorsqu'elles accèdent aux objets GetLine. Attention, les seuls signaux qu'elles bloquent sont les signaux que gl_get_line() est actuellement configuré pour attraper, alors assurez-vous que si vous appelez l'une des fonctions ci-dessus depuis des gestionnaires de signaux, les signaux auxquels ces gestionnaires sont assignés sont configurés pour être attrapés par gl_get_line() (voir gl_trap_signal()).

Utilisation de Timeouts pour le Sondage

Si, au lieu d'utiliser select() ou poll() pour attendre les E/S, votre application a juste besoin de sortir périodiquement de gl_get_line() pour faire brièvement autre chose avant de revenir pour accepter l'entrée de l'utilisateur, cela peut être fait en mode serveur non bloquant en utilisant la fonction gl_inactivity_timeout() (voir gl_get_line(3)), pour spécifier qu'une fonction de rappel retournant GLTO_CONTINUE doit être appelée chaque fois que gl_get_line() a attendu les E/S pendant plus d'un temps spécifié.

Lorsque cette fonction de rappel est déclenchée, gl_get_line() retournera NULL, et un appel ultérieur à gl_return_status() retournera GLR_BLOCKED.

Attention, gl_get_line() ne retournera pas tant que l'utilisateur n'aura pas tapé une touche pendant l'intervalle spécifié. Ainsi, si l'intervalle est long et que l'utilisateur continue de taper, gl_get_line() peut ne pas retourner pendant un certain temps. Autrement dit, il n'y a aucune garantie qu'elle retournera dans le temps spécifié.

Le Programme de Démonstration Serveur

Le programme demo3 distribué avec la bibliothèque fournit un exemple fonctionnel de la manière d'utiliser le mode E/S serveur non bloquant dans un programme réel. En ce qui concerne l'utilisateur, ce programme fonctionne identiquement au programme de démonstration principal (appelé demo), sauf que si le programme de démonstration principal utilise le mode d'E/S bloquant normal, demo3 utilise les E/S non bloquantes et une boucle d'événements externe. Le code source se trouve dans demo3.c, et les commentaires qu'il contient expliquent les différentes étapes.
