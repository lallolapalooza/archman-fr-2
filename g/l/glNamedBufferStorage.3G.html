DESCRIPTIO

N

glBufferStorage et glNamedBufferStorage créent un nouveau magasin de données immuable. Pour glBufferStorage, l'objet tampon actuellement lié à target sera initialisé. Pour glNamedBufferStorage, buffer est le nom de l'objet tampon qui sera configuré. La taille du magasin de données est spécifiée par size. Si des données initiales sont disponibles, leur adresse peut être fournie dans data. Sinon, pour créer un magasin de données non initialisé, data devrait être NULL

.

Les paramètres flags spécifient l'utilisation prévue du magasin de données du tampon. Ils doivent être une combinaison binaire d'un sous-ensemble des drapeaux suivants

:

GL_DYNAMIC_STORAGE_BI

T
Le contenu du magasin de données peut être mis à jour après la création par des appels à glBufferSubData(). Si ce bit n'est pas défini, le contenu du tampon ne peut pas être directement mis à jour par le client. L'argument data peut être utilisé pour spécifier le contenu initial du magasin de données du tampon, indépendamment de la présence de GL_DYNAMIC_STORAGE_BIT. Indépendamment de la présence de ce bit, les tampons peuvent toujours être mis à jour par des appels côté serveur tels que glCopyBufferSubData() et glClearBufferSu
bData().

GL_MAP_READ_BI

T
Le magasin de données peut être mappé par le client pour un accès en lecture et un pointeur dans l'espace d'adressage du client est obtenu à partir duquel on peut
lire.

GL_MAP_WRITE_BI

T
Le magasin de données peut être mappé par le client pour un accès en écriture et un pointeur dans l'espace d'adressage du client est obtenu à travers lequel on peut
écrire.

GL_MAP_PERSISTENT_BI

T
Le client peut demander au serveur de lire depuis ou d'écrire dans le tampon pendant qu'il est mappé. Le pointeur du client vers le magasin de données reste valide tant que le magasin de données est mappé, même pendant l'exécution de commandes de dessin ou de
dispatch.

GL_MAP_COHERENT_BI

T
L'accès partagé aux tampons qui sont simultanément mappés pour un accès client et utilisés par le serveur sera cohérent, tant que cette mappage est effectué à l'aide de glMapBufferRange(). C'est-à-dire que les données écrites dans le magasin soit par le client soit par le serveur seront immédiatement visibles pour l'autre sans aucune action supplémentaire de l'application. En particulier,
•Si GL_MAP_COHERENT_BIT n'est pas défini et que le client effectue une écriture suivie d'un appel à la commande glMemoryBarrier() avec le GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT défini, alors dans les commandes suivantes le serveur verra les
écritures.
•Si GL_MAP_COHERENT_BIT est défini et que le client effectue une écriture, alors dans les commandes suivantes le serveur verra les
écritures.
•Si GL_MAP_COHERENT_BIT n'est pas défini et que le serveur effectue une écriture, l'application doit appeler glMemoryBarrier() avec le GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT défini, puis appeler glFenceSync() avec GL_SYNC_GPU_COMMANDS_COMPLETE (ou glFinish). Ensuite, le CPU verra les écritures après que la synchronisation soit
terminée.
•Si GL_MAP_COHERENT_BIT est défini et que le serveur effectue une écriture, l'application doit appeler glFenceSync avec GL_SYNC_GPU_COMMANDS_COMPLETE (ou glFinish()). Ensuite, le CPU verra les écritu
res après que la synchr
onisation soit terminée.

GL_CLIENT_STORAGE_BI

T
Lorsque tous les autres critères pour l'allocation du stockage du tampon sont satisfaits, ce bit peut être utilisé par une implémentation pour déterminer s'il faut utiliser un stockage local au serveur ou au client comme magasin de sauvegarde pour le
tampon.

Les combinaisons autorisées de drapeaux sont soumises à certaines restrictions. Elles sont les suivantes

:
•Si flags contient GL_MAP_PERSISTENT_BIT, il doit également contenir au moins l'un de GL_MAP_READ_BIT ou GL_MAP_WRITE_BIT
.
•Si flags contient GL_MAP_COHERENT_BIT, il doit également contenir GL_MAP_PERSISTENT_BI
T
.

NOTE

S

glBufferStorage n'est disponible que si la version de GL est 4.4 ou

supérieure.

glNamedBufferStorage n'est disponible que si la version de GL est 4.5 ou

supérieure.

Si data est NULL, un magasin de données de la taille spécifiée est tout de m

ême créé, mais son contenu reste
non initialisé et donc indéfini.

R

acceptées.

GL_INVALID_OPERATION est généré par glNamedBufferStorage si buffer n'est pas le nom d'un objet tampon

existant.

GL_INVALID_VALUE est généré si size est inférieur ou égal à

zéro.

GL_INVALID_OPERATION est généré par glBufferStorage si le nom d'objet tampon réservé 0 est lié à target

.

GL_OUT_OF_MEMORY est généré si le GL est incapable de créer un magasin de données avec les propriétés demandées dans flags

.

GL_INVALID_VALUE est généré si flags a des bits définis autres que ceux définis

ci-dessus.

L'erreur GL_INVALID_VALUE est générée si flags contient GL_MAP_PERSISTENT_BIT mais ne contient pas au moins l'un de GL_MAP_READ_BIT ou GL_MAP_WRITE_BIT

.

GL_INVALID_VALUE est généré si flags contient GL_MAP_COHERENT_BIT, mais ne contient pas également GL_MAP_PERSISTENT_BIT

.
