DESCRIPTIO

N

glUseProgram installe l'objet programme spécifié par program comme partie de l'état de rendu courant. Un ou plusieurs exécutables sont créés dans un objet programme en attachant avec succès des objets shader à celui-ci avec glAttachShader(), en compilant avec succès les objets shader avec glCompileShader(), et en liant avec succès l'objet programme avec glLinkProgr

am().

Un objet programme contiendra un exécutable qui s'exécutera sur le processeur de sommets s'il contient un ou plusieurs objets shader de type GL_VERTEX_SHADER qui ont été compilés et liés avec succès. Un objet programme contiendra un exécutable qui s'exécutera sur le processeur géométrique s'il contient un ou plusieurs objets shader de type GL_GEOMETRY_SHADER qui ont été compilés et liés avec succès. De même, un objet programme contiendra un exécutable qui s'exécutera sur le processeur de fragments s'il contient un ou plusieurs objets shader de type GL_FRAGMENT_SHADER qui ont été compilés et liés avec

succès.

Tant qu'un objet programme est en cours d'utilisation, les applications sont libres de modifier les objets shader attachés, de compiler les objets shader attachés, d'attacher des objets shader supplémentaires, et de détacher ou supprimer des objets shader. Aucune de ces opérations n'affectera les exécutables qui font partie de l'état courant. Cependant, le re-liage de l'objet programme actuellement en cours d'utilisation installera l'objet programme comme partie de l'état de rendu courant si l'opération de liaison a réussi (voir glLinkProgram() ). Si l'objet programme actuellement en cours d'utilisation est re-lié sans succès, son statut de liaison sera défini à GL_FALSE, mais les exécutables et l'état associé resteront partie de l'état courant jusqu'à un appel ultérieur à glUseProgram qui le retire de l'utilisation. Une fois retiré de l'utilisation, il ne peut pas redevenir partie de l'état courant avant d'avoir été re-lié avec

succès.

Si program vaut zéro, alors l'état de rendu courant fait référence à un objet programme invalide et les résultats de l'exécution du shader sont indéfinis. Cependant, ceci n'est pas une

erreur.

Si program ne contient pas d'objets shader de type GL_FRAGMENT_SHADER, un exécutable sera installé sur le processeur de sommets, et éventuellement sur

le processeur géométrique, mais les résultats de l'ex
écution du shader de fragments seront indéfinis.

REMARQUE

S

Comme les objets tampon et les objets texture, l'espace de noms pour les objets programme peut être partagé entre un ensemble de contextes, tant que les côtés serveur des contextes partagent le même espace d'adressage. Si l'espace de noms est partagé entre contextes, tous les objets attachés et les données associées à ces objets attachés sont également

partagés.

Les applications sont responsables de fournir la synchr

onisation entre les appels d'API lorsque les objets
sont accessibles depuis différents fils d'exécution.
