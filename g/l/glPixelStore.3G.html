NOM

glPixelStore - définir les modes de stockage de pixels

SPÉCIFICATION C

void glPixelStoref(GLenum pname, GLfloat param);

void glPixelStorei(GLenum pname, GLint param);

PARAMÈTRES

pname

Spécifie le nom symbolique du paramètre à définir. Six valeurs affectent l'empaquetage des données de pixels en mémoire : GL_PACK_SWAP_BYTES, GL_PACK_LSB_FIRST, GL_PACK_ROW_LENGTH, GL_PACK_IMAGE_HEIGHT, GL_PACK_SKIP_PIXELS, GL_PACK_SKIP_ROWS, GL_PACK_SKIP_IMAGES, et GL_PACK_ALIGNMENT. Six autres affectent le désempaquetage des données de pixels depuis la mémoire : GL_UNPACK_SWAP_BYTES, GL_UNPACK_LSB_FIRST, GL_UNPACK_ROW_LENGTH, GL_UNPACK_IMAGE_HEIGHT, GL_UNPACK_SKIP_PIXELS, GL_UNPACK_SKIP_ROWS, GL_UNPACK_SKIP_IMAGES, et GL_UNPACK_ALIGNMENT.

param

Spécifie la valeur à laquelle pname est défini.

DESCRIPTION

glPixelStore définit les modes de stockage de pixels qui affectent le fonctionnement de glReadPixels() ultérieur ainsi que le désempaquetage des motifs de texture (voir glTexImage1D(), glTexImage2D(), glTexImage3D(), glTexSubImage1D(), glTexSubImage2D(), glTexSubImage3D()), glCompressedTexImage1D(), glCompressedTexImage2D(), glCompressedTexImage3D(), glCompressedTexSubImage1D(), glCompressedTexSubImage2D() ou glCompressedTexSubImage1D().

pname est une constante symbolique indiquant le paramètre à définir, et param est la nouvelle valeur. Six des douze paramètres de stockage affectent la manière dont les données de pixels sont retournées à la mémoire client. Ce sont les suivants :

GL_PACK_SWAP_BYTES

Si vrai, l'ordre des octets pour les composantes de couleur multioctets, les composantes de profondeur ou les indices de stencil est inversé. C'est-à-dire, si une composante de quatre octets est composée des octets b 0, b 1, b 2, b 3, elle est stockée en mémoire sous la forme b 3, b 2, b 1, b 0 si GL_PACK_SWAP_BYTES est vrai. GL_PACK_SWAP_BYTES n'a aucun effet sur l'ordre des composantes dans la mémoire au sein d'un pixel, seulement sur l'ordre des octets au sein des composantes ou des indices. Par exemple, les trois composantes d'un pixel au format GL_RGB sont toujours stockées avec le rouge en premier, le vert en second, et le bleu en troisième, quelle que soit la valeur de GL_PACK_SWAP_BYTES.

GL_PACK_LSB_FIRST

Si vrai, les bits sont ordonnés dans un octet du moins significatif au plus significatif ; sinon, le premier bit de chaque octet est le plus significatif.

GL_PACK_ROW_LENGTH

Si supérieur à 0, GL_PACK_ROW_LENGTH définit le nombre de pixels dans une ligne. Si le premier pixel d'une ligne est placé à l'emplacement p en mémoire, alors l'emplacement du premier pixel de la ligne suivante est obtenu en sautant

k = n ⁢ l a s ⁢ s ⁢ n ⁢ l a ⁢ s >= a s < a

composantes ou indices, où n est le nombre de composantes ou d'indices dans un pixel, l est le nombre de pixels dans une ligne (GL_PACK_ROW_LENGTH s'il est supérieur à 0, sinon l'argument de largeur de la routine de pixels), a est la valeur de GL_PACK_ALIGNMENT, et s est la taille, en octets, d'une seule composante (si a < s, alors c'est comme si a = s). Dans le cas de valeurs de 1 bit, l'emplacement de la ligne suivante est obtenu en sautant

k = 8 ⁢ a ⁢ n ⁢ l 8 ⁢ a

composantes ou indices.

Le mot composante dans cette description fait référence aux valeurs non-indices rouge, vert, bleu, alpha et profondeur. Le format de stockage GL_RGB, par exemple, a trois composantes par pixel : d'abord le rouge, puis le vert, et enfin le bleu.

GL_PACK_IMAGE_HEIGHT

Si supérieur à 0, GL_PACK_IMAGE_HEIGHT définit le nombre de pixels dans un volume de texture tridimensionnel, où « image » est définie par tous les pixels partageant le même indice de la troisième dimension. Si le premier pixel d'une ligne est placé à l'emplacement p en mémoire, alors l'emplacement du premier pixel de la ligne suivante est obtenu en sautant

k = n ⁢ l ⁢ h a s ⁢ s ⁢ n ⁢ l ⁢ h a ⁢ s >= a s < a

composantes ou indices, où n est le nombre de composantes ou d'indices dans un pixel, l est le nombre de pixels dans une ligne (GL_PACK_ROW_LENGTH s'il est supérieur à 0, sinon l'argument de largeur de la routine glTexImage3D()), h est le nombre de lignes dans une image de pixels (GL_PACK_IMAGE_HEIGHT s'il est supérieur à 0, sinon l'argument de hauteur de la routine glTexImage3D()), a est la valeur de GL_PACK_ALIGNMENT, et s est la taille, en octets, d'une seule composante (si a < s, alors c'est comme si a = s).

Le mot composante dans cette description fait référence aux valeurs non-indices rouge, vert, bleu, alpha et profondeur. Le format de stockage GL_RGB, par exemple, a trois composantes par pixel : d'abord le rouge, puis le vert, et enfin le bleu.

GL_PACK_SKIP_PIXELS, GL_PACK_SKIP_ROWS, et GL_PACK_SKIP_IMAGES

Ces valeurs sont fournies comme une commodité au programmeur ; elles n'offrent aucune fonctionnalité qui ne puisse être dupliquée simplement en incrémentant le pointeur passé à glReadPixels(). Définir GL_PACK_SKIP_PIXELS à i est équivalent à incrémenter le pointeur de i ⁢ n composantes ou indices, où n est le nombre de composantes ou d'indices par pixel. Définir GL_PACK_SKIP_ROWS à j est équivalent à incrémenter le pointeur de j ⁢ m composantes ou indices, où m est le nombre de composantes ou d'indices par ligne, comme calculé dans la section GL_PACK_ROW_LENGTH. Définir GL_PACK_SKIP_IMAGES à k est équivalent à incrémenter le pointeur de k ⁢ p, où p est le nombre de composantes ou d'indices par image, comme calculé dans la section GL_PACK_IMAGE_HEIGHT.

GL_PACK_ALIGNMENT

Spécifie les exigences d'alignement pour le début de chaque ligne de pixels en mémoire. Les valeurs autorisées sont 1 (alignement par octet), 2 (lignes alignées sur des octets pairs), 4 (alignement par mot), et 8 (les lignes commencent sur des frontières de double mot).

Les six autres des douze paramètres de stockage affectent la manière dont les données de pixels sont lues depuis la mémoire client. Ces valeurs sont importantes pour glTexImage1D(), glTexImage2D(), glTexImage3D(), glTexSubImage1D(), glTexSubImage2D(), et glTexSubImage3D().

Ce sont les suivantes :

GL_UNPACK_SWAP_BYTES

Si vrai, l'ordre des octets pour les composantes de couleur multioctets, les composantes de profondeur ou les indices de stencil est inversé. C'est-à-dire, si une composante de quatre octets est composée des octets b 0, b 1, b 2, b 3, elle est prise en mémoire comme b 3, b 2, b 1, b 0 si GL_UNPACK_SWAP_BYTES est vrai. GL_UNPACK_SWAP_BYTES n'a aucun effet sur l'ordre des composantes dans la mémoire au sein d'un pixel, seulement sur l'ordre des octets au sein des composantes ou des indices. Par exemple, les trois composantes d'un pixel au format GL_RGB sont toujours stockées avec le rouge en premier, le vert en second, et le bleu en troisième, quelle que soit la valeur de GL_UNPACK_SWAP_BYTES.

GL_UNPACK_LSB_FIRST

Si vrai, les bits sont ordonnés dans un octet du moins significatif au plus significatif ; sinon, le premier bit de chaque octet est le plus significatif.

GL_UNPACK_ROW_LENGTH

Si supérieur à 0, GL_UNPACK_ROW_LENGTH définit le nombre de pixels dans une ligne. Si le premier pixel d'une ligne est placé à l'emplacement p en mémoire, alors l'emplacement du premier pixel de la ligne suivante est obtenu en sautant

k = n ⁢ l a s ⁢ s ⁢ n ⁢ l a ⁢ s >= a s < a

composantes ou indices, où n est le nombre de composantes ou d'indices dans un pixel, l est le nombre de pixels dans une ligne (GL_UNPACK_ROW_LENGTH s'il est supérieur à 0, sinon l'argument de largeur de la routine de pixels), a est la valeur de GL_UNPACK_ALIGNMENT, et s est la taille, en octets, d'une seule composante (si a < s, alors c'est comme si a = s). Dans le cas de valeurs de 1 bit, l'emplacement de la ligne suivante est obtenu en sautant

k = 8 ⁢ a ⁢ n ⁢ l 8 ⁢ a

composantes ou indices.

Le mot composante dans cette description fait référence aux valeurs non-indices rouge, vert, bleu, alpha et profondeur. Le format de stockage GL_RGB, par exemple, a trois composantes par pixel : d'abord le rouge, puis le vert, et enfin le bleu.

glPixelStoref peut être utilisé pour définir n'importe quel paramètre de stockage de pixels. Si le type du paramètre est booléen, alors si param vaut 0, le paramètre est false ; sinon il est défini à true. Si pname est un paramètre de type entier, param est arrondi à l'entier le plus

proche.

De même, glPixelStorei peut également être utilisé pour définir n'importe lequel des paramètres de stockage de pixels. Les paramètres booléens sont définis à false si param vaut 0

et à true sinon.
