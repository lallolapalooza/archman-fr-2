NOM

glTexSubImage3D, glTextureSubImage3D - spécifier une sous-image de texture tridimensionnelle

SPÉCIFICATION C

void glTexSubImage3D(GLenum target, GLint level, GLint xoffset, GLint yoffset, GLint zoffset, GLsizei width, GLsizei height, GLsizei depth, GLenum format, GLenum type, const void * pixels);

void glTextureSubImage3D(GLuint texture, GLint level, GLint xoffset, GLint yoffset, GLint zoffset, GLsizei width, GLsizei height, GLsizei depth, GLenum format, GLenum type, const void *pixels);

PARAMÈTRES

target

Spécifie la cible à laquelle la texture est liée pour glTexSubImage3D. Doit être GL_TEXTURE_3D ou GL_TEXTURE_2D_ARRAY.

texture

Spécifie le nom de l'objet texture pour glTextureSubImage3D. La cible effective de texture doit être l'une des valeurs de target valides ci-dessus.

level

Spécifie le numéro du niveau de détail. Le niveau 0 est le niveau d'image de base. Le niveau n est l'image de réduction mipmap n.

xoffset

Spécifie un décalage de texel dans la direction x au sein du tableau de textures.

yoffset

Spécifie un décalage de texel dans la direction y au sein du tableau de textures.

zoffset

Spécifie un décalage de texel dans la direction z au sein du tableau de textures.

width

Spécifie la largeur de la sous-image de texture.

height

Spécifie la hauteur de la sous-image de texture.

depth

Spécifie la profondeur de la sous-image de texture.

format

Spécifie le format des données de pixel. Les valeurs symboliques suivantes sont acceptées : GL_RED, GL_RG, GL_RGB, GL_BGR, GL_RGBA, GL_DEPTH_COMPONENT et GL_STENCIL_INDEX.

type

Spécifie le type de données des données de pixel. Les valeurs symboliques suivantes sont acceptées : GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2 et GL_UNSIGNED_INT_2_10_10_10_REV.

pixels

Spécifie un pointeur vers les données de l'image en mémoire.

DESCRIPTION

Le texturage applique une partie d'une image de texture spécifiée sur chaque primitive graphique pour laquelle le texturage est activé.

glTexSubImage3D et glTextureSubImage3D redéfinissent une sous-région contiguë d'une texture tridimensionnelle ou d'un tableau de textures bidimensionnelles existant. Les texels référencés par pixels remplacent la partie du tableau de textures existant avec des indices x xoffset et xoffset + width - 1, inclus, des indices y yoffset et yoffset + height - 1, inclus, et des indices z zoffset et zoffset + depth - 1, inclus. Pour les textures tridimensionnelles, l'indice z fait référence à la troisième dimension. Pour les tableaux de textures bidimensionnels, l'indice z fait référence à l'indice de la tranche. Cette région ne peut pas inclure de texels en dehors de la plage du tableau de textures tel qu'il a été spécifié à l'origine. Il n'y a pas d'erreur si une sous-texture avec une largeur, une hauteur ou une profondeur nulle est spécifiée, mais une telle spécification n'a aucun effet.

Si un objet tampon nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER (voir glBindBuffer()) pendant que l'image de texture est spécifiée, pixels est traité comme un décalage en octets dans le magasin de données de l'objet tampon.

NOTES

Les modes glPixelStore() affectent les images de texture.

glTexSubImage3D et glTextureSubImage3D spécifient une sous-texture tridimensionnelle ou un tableau de sous-textures bidimensionnel pour l'unité de texture actuelle, spécifiée avec glActiveTexture().

GL_STENCIL_INDEX est accepté pour format uniquement si la version GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est générée si target ou la cible effective de texture n'est pas GL_TEXTURE_3D, GL_TEXTURE_2D_ARRAY ou GL_TEXTURE_CUBE_MAP_ARRAY.

GL_INVALID_OPERATION est générée par glTextureSubImage3D si texture n'est pas le nom d'un objet texture existant.

GL_INVALID_ENUM est générée si format n'est pas une constante de format acceptée.

GL_INVALID_ENUM est générée si type n'est pas une constante de type.

GL_INVALID_VALUE est générée si level est inférieur à 0.

GL_INVALID_VALUE peut être générée si level est supérieur à log 2 max, où max est la valeur retournée par GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE est générée si xoffset < - b, xoffset + width > w - b, yoffset < - b, ou yoffset + height > h - b, ou zoffset < - b, ou zoffset + depth > d - b, où w est la GL_TEXTURE_WIDTH, h est la GL_TEXTURE_HEIGHT, d est la GL_TEXTURE_DEPTH et b est la largeur de bordure de l'image de texture en cours de modification. Notez que w, h et d incluent deux fois la largeur de bordure.

GL_INVALID_VALUE est générée si width, height ou depth est inférieur à 0.

GL_INVALID_OPERATION est générée si le tableau de textures n'a pas été défini par une opération précédente glTexImage3D() ou glTexStorage3D().

GL_INVALID_OPERATION est générée si type est l'un de GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, ou GL_UNSIGNED_SHORT_5_6_5_REV et que format n'est pas GL_RGB.

GL_INVALID_OPERATION est générée si type est l'un de GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, ou GL_UNSIGNED_INT_2_10_10_10_REV et que format n'est ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION est générée si format est GL_STENCIL_INDEX et que le format interne de base n'est pas GL_STENCIL_INDEX.

GL_INVALID_OPERATION est générée si un objet tampon nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que le magasin de données de l'objet tampon est actuellement mappé.

GL_INVALID_OPERATION est générée si un objet tampon nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que les données seraient dépaquetées de l'objet tampon de telle sorte que les lectures mémoire requises dépasseraient la taille du magasin de données.

GL_INVALID_OPERATION est générée si un objet tampon nommé non nul est lié à la cible GL_PIXEL_UNPACK_BUFFER et que pixels n'est pas un multiple exact du nombre d'octets nécessaires pour stocker en mémoire une donnée indiquée par type.
