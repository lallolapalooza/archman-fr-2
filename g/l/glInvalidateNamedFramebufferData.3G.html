GLINVALIDATEFRAMEBUF(3G) [FIXME: manuel] GLINVALIDATEFRAMEBUF(3G)

NOM

glInvalidateFramebuffer, glInvalidateNamedFramebufferData - invalider le contenu de certaines ou toutes les pièces jointes d'un framebuffer

SPÉCIFICATION C

void glInvalidateFramebuffer(GLenum cible, GLsizei nombreAttachements, const GLenum * attachements);

void glInvalidateNamedFramebufferData(GLuint framebuffer, GLsizei nombreAttachements, const GLenum *attachements);

PARAMÈTRES

cible

Spécifie la cible à laquelle l'objet framebuffer est attaché pour glInvalidateFramebuffer.

framebuffer

Spécifie le nom de l'objet framebuffer pour glInvalidateNamedFramebufferData.

nombreAttachements

Spécifie le nombre d'entrées dans le tableau attachements.

attachements

Spécifie un pointeur vers un tableau identifiant les pièces jointes à invalider.

DESCRIPTION

glInvalidateFramebuffer et glInvalidateNamedFramebufferData invalident tout le contenu d'un ensemble spécifié de pièces jointes d'un framebuffer.

Pour glInvalidateFramebuffer, l'objet framebuffer est celui lié à cible. cible doit être GL_FRAMEBUFFER, GL_READ_FRAMEBUFFER ou GL_DRAW_FRAMEBUFFER. GL_FRAMEBUFFER est équivalent à GL_DRAW_FRAMEBUFFER. Les framebuffers par défaut peuvent également être invalidés s'ils sont liés à cible.

Pour glInvalidateNamedFramebufferData, framebuffer est le nom de l'objet framebuffer. Si framebuffer est zéro, le framebuffer de dessin par défaut est affecté.

L'ensemble des pièces jointes dont le contenu doit être invalidé est spécifié dans le tableau attachements, qui contient nombreAttachements éléments.

Si l'objet framebuffer spécifié est un objet framebuffer, chaque élément de attachements doit être l'un des éléments suivants : GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT GL_DEPTH_STENCIL_ATTACHMENT, ou GL_COLOR_ATTACHMENTi, où i est compris entre zéro et la valeur de GL_MAX_FRAMEBUFFER_ATTACHMENTS moins un.

Si le framebuffer spécifié est un framebuffer par défaut, chaque élément de attachements doit être l'un des éléments suivants : GL_FRONT_LEFT, GL_FRONT_RIGHT, GL_BACK_LEFT, GL_BACK_RIGHT, GL_AUXi, GL_ACCUM, GL_COLOR, GL_DEPTH, ou GL_STENCIL. GL_COLOR est traité comme GL_BACK_LEFT pour un contexte double tampon et GL_FRONT_LEFT pour un contexte simple tampon. Les autres pièces jointes identifient le tampon spécifique correspondant.

L'intégralité du contenu de chaque pièce jointe spécifiée devient indéfinie après l'exécution de glInvalidateFramebuffer ou glInvalidateNamedFramebufferData.

Si l'objet framebuffer n'est pas complet, glInvalidateFramebuffer et glInvalidateNamedFramebufferData peuvent être ignorés. Ce n'est pas une erreur.

ERREURS

GL_INVALID_ENUM est généré par glInvalidateFramebuffer si cible n'est pas l'une des cibles de framebuffer acceptées.

GL_INVALID_OPERATION est généré par glInvalidateNamedFramebufferData si framebuffer n'est pas zéro ou le nom d'un objet framebuffer existant.

GL_INVALID_VALUE est généré si nombreAttachements est négatif.

GL_INVALID_ENUM est généré si un élément de attachements n'est pas l'un des points de pièce jointe de framebuffer acceptés, comme décrit ci-dessus.

GL_INVALID_OPERATION est généré si un élément de attachements est GL_COLOR_ATTACHMENTm où m est supérieur ou égal à la valeur de GL_MAX_COLOR_ATTACHMENTS.

ASSOCIÉES GETS

glGet() avec l'argument GL_MAX_COLOR_ATTACHMENTS
