NOM

glhack - Explorer les labyrinthes du Péril

SYNOPSIS

glhack [options]

glhack -s [options]

DESCRIPTION

glHack est un port du jeu NetHack, utilisant l'accélération matérielle via OpenGL(R) pour rendre la graphique en tuiles 2D. Il utilise LibSDL comme bibliothèque vidéo et d'entrée. Le rendu logiciel est également bien pris en charge.

NetHack est un jeu orienté affichage de type Donjons & Dragons(tm). L'affichage tty standard et la structure de commandes ressemblent à rogue.

Pour commencer, vous n'avez vraiment besoin de connaître que deux commandes. La commande `?' vous donnera une liste des commandes disponibles (ainsi que d'autres informations) et la commande `/' identifiera les choses que vous voyez à l'écran.

Pour gagner le jeu (par opposition au simple fait de jouer pour battre les meilleurs scores des autres), vous devez localiser l'Amulette de Yendor qui se trouve quelque part sous le 20ème niveau du donjon et la rapporter. Ce n'est pas une tâche facile !

Lorsque le jeu se termine, que ce soit par votre mort, votre abandon ou votre évasion des cavernes, glHack vous donnera (un fragment de) la liste des meilleurs scores. Le score est basé sur de nombreux aspects de votre comportement, mais une estimation approximative est obtenue en additionnant la quantité d'or que vous avez trouvée dans la caverne à quatre fois votre expérience (réelle). Les pierres précieuses peuvent valoir beaucoup d'or lorsqu'elles sont apportées à la sortie. Il y a une pénalité de 10 % si vous vous faites tuer.

OPTIONS NETHACK

Ce sont les options standard que NetHack prend en charge.

-u nomdujoueur
Cette option fournit la réponse à la question « Qui êtes-vous ? ». Elle remplace tout nom provenant des options ou du fichier de configuration, des variables du shell USER ou LOGNAME, ou de getlogin(), qui seront sinon essayées dans cet ordre. Si aucune de ces sources ne fournit un nom utile, le joueur sera invité à en fournir un. Les noms de joueurs (en conjonction avec les uid) sont utilisés pour identifier les fichiers de sauvegarde, vous pouvez donc avoir plusieurs parties sauvegardées sous différents noms. Inversement, vous devez utiliser le nom de joueur approprié pour restaurer une partie sauvegardée.

Un suffixe de nomdujoueur peut être utilisé pour spécifier la profession, la race, l'alignement et/ou le genre du personnage. La syntaxe complète du nomdujoueur incluant un suffixe est "nom-ppp-rrr-aaa-ggg". "ppp" correspond au moins aux trois premières lettres de la profession (cela peut aussi être spécifié à l'aide de l'option -p ). "rrr" correspond au moins aux trois premières lettres de la race du personnage (cela peut aussi être spécifié à l'aide de l'option -r ). "aaa" correspond au moins aux trois premières lettres de l'alignement du personnage, et "ggg" correspond au moins aux trois premières lettres du genre du personnage. N'importe laquelle des parties du suffixe peut être omise.

-p profession
Cela peut être utilisé pour déterminer le rôle du personnage. Vous pouvez spécifier le nom masculin ou féminin pour le rôle du personnage, ou les trois premiers caractères du rôle comme abréviation. `@' et random peuvent aussi être utilisés pour signifier « choisir un rôle aléatoire ».
-r race
De même, cela peut être utilisé pour demander explicitement qu'une race soit choisie.

Remarque : omettre l'une de ces caractéristiques entraînera une invitation à fournir cette information lors du démarrage du jeu.

-@
Choisir aléatoirement toutes les caractéristiques (restantes) du personnage. Cela n'affecte aucune caractéristique qui a déjà été spécifiée par d'autres moyens.
-s
Cette option seule imprimera la liste de vos scores sur la version actuelle. Le -s peut aussi être suivi des arguments -p et -r pour n'imprimer que les scores de rôles et de races particuliers. Il peut aussi être suivi d'un ou plusieurs noms de joueurs pour imprimer les scores des joueurs mentionnés, par 'all' pour imprimer tous les scores, ou par un nombre pour imprimer ce nombre de meilleurs scores.
-dec et -ibm
Ces options de ligne de commande sont équivalentes aux options en jeu decgraphics et ibmgraphics , et sont fournies uniquement par commodité sur les systèmes prenant en charge plusieurs types de terminaux.
-D ou -X
Ces options démarreront le jeu dans un mode de découverte spécial non comptabilisé. Si le joueur est l'administrateur du jeu, -D démarrera en mode débogage (sorcier) à la place.
-n
Cette option supprime l'impression de toute nouvelle de l'administrateur du jeu.
-d
Cette option n'est généralement utile que pour l'administrateur du jeu. Si elle apparaît, elle doit être le premier argument, et fournit un répertoire qui servira de terrain de jeu. Elle remplace la valeur de NETHACKDIR, HACKDIR, ou du répertoire spécifié par l'administrateur du jeu lors de la compilation (généralement /usr/lib/games/glhack). Le terrain de jeu doit contenir plusieurs fichiers auxiliaires tels que les fichiers d'aide, la liste des meilleurs scores, et un sous-répertoire save où les parties sont sauvegardées.

OPTIONS GLHACK

Ce sont les options de ligne de commande spécifiques à glHack.

Elles commencent toutes par un double tiret (`--'). Les valeurs sont normalement séparées de l'option par un espace, comme "--depth 32".

Alternativement, une valeur peut être placée après un signe `=' sans aucun espace, comme "--depth=32". Cela devrait être utilisé si la valeur commence par un signe moins (`-'), sinon le nombre sera confondu avec une nouvelle option.

Les options qui prennent une valeur sont montrées ici avec des valeurs d'exemple.

--mode 640x480
Spécifie le mode vidéo. Normalement, glHack détectera automatiquement le mode, mais l'utilisation de cette option le remplacera. La valeur par défaut (lorsque tout le reste échoue) est 800x600.
--depth 8
Profondeur vidéo (bits par pixel). Les valeurs possibles sont 15, 16, 24 et 32, et 8 lors de l'utilisation du rendu logiciel. La valeur par défaut est détectée automatiquement.
--windowed
Jouer dans une fenêtre plutôt qu'en plein écran.
--gamma=-2
Valeur de correction gamma. La plage est de -5 à +5, où les valeurs positives rendent l'écran plus lumineux, et les valeurs négatives le rendent plus sombre. Zéro est la valeur par défaut (aucun ajustement).
--tileheight 64
Choisir le jeu de tuiles, qui peut être 16, 32 ou 64. La valeur par défaut est 32. Pour obtenir le jeu de tuiles 3D isométrique, utilisez la valeur 64.
--fontsize 22
Choisir la taille de la police, parmi 8, 14, 20 ou 22. La valeur par défaut est 20. La taille donnée sera utilisée pour toutes les fenêtres de texte, remplaçant tout paramètre wincap dans le fichier de configuration.
--help
Afficher une page d'aide.
--version
Afficher la version actuelle. Cela peut aussi être fait dans le jeu à l'aide de la commande #version.

ENVIRONNEMENT

USER ou LOGNAME
Votre nom de connexion (utilisé comme nom de joueur).
HOME
Votre répertoire personnel (utilisé pour trouver le fichier de configuration).
NETHACKOPTIONS
Chaîne prédéfinissant plusieurs options standard de NetHack.
GLHACKOPTIONS
Chaîne prédéfinissant plusieurs options spécifiques à glHack.
NETHACKDIR
Répertoire du terrain de jeu (voir l'option -d ci-dessus).

De plus, SHOPTYPE est utilisé en mode débogage (sorcier).

SÉCURITÉ

glHack s'exécute avec set-gid games. Cela est nécessaire pour créer/modifier les fichiers de jeu persistants. En général, les programmes set-gid sont beaucoup plus sécurisés que lesuid programs. An attacker who successfully compromises a set-gid game executable can only mess around with various game data files (typically those in /var/games and /var/lib/games).

Since glHack is based on NetHack 3.4.0, any security issues with NetHack 3.4.0 (past or future) will almost certainly apply to this release of glHack.

Currently there is only one place in the glHack-specific code that creates or writes to a file: the screenshot code. Taking screenshots is restricted to the game administrator (the "wizard" account).

As far as I know, glHack will never execute another program. The following features of the NetHack 3.4.0 codebase which do execute other programs are disabled in glHack's standard (compile-time) configuration: running a compression utility (COMPRESS), running a shell (SHELL), reading mail (MAIL), and running an external pager (TTY code).

FILES

~/.glhackrc
Configuration file for glHack. See the glhackrc(5) manual page for more information.
/usr/lib/games/glhack
The static playground. Read-only files are stored here. Files found here will be marked "(STATIC)" in the entries below.
/var/lib/games/glhack
The variable playground. Persistent (read/write) data files are stored here. These files are marked "(VAR)" below.
nhdat (STATIC)
Archive containing all the stuff that NetHack requires to play (level files, text files, help files, etc). The format is DLB (Data LiBrarian) and is NetHack-specific.
license (STATIC)
Rules governing redistribution.
glhack_recover (STATIC)
This program can be used to recover a game after glHack has crashed (assuming the files were not corrupted). It can only be run as the superuser (root).
gl*.png (STATIC)
Images (fonts, tilesets, etc) used by glHack.
gl*.lst (STATIC)
Miscellaneous data files (e.g. tile facing info) used by glHack.
record (VAR)
The list of top scorers.
logfile (VAR)
An extended list of games played.
perm (VAR)
Empty file used for locking purposes.
bonDD.nn (VAR)
Bone files: descriptions of the ghost and belongings of a deceased adventurer.
NNNNname.dd (VAR)
Temporary files for a user who is currently playing glHack, or after glHack has crashed. The `NNNN' part is the numeric userid, followed by the player's name.
save/ (VAR)
A subdirectory containing the saved games.
