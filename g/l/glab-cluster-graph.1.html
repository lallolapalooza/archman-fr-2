NOM

glab-cluster-graph - Interroge le graphe d'objets Kubernetes, en utilisant l'Agent GitLab pour Kubernetes. (EXPÉRIMENTAL)

SYNTAXE

glab cluster graph [flags]

DESCRIPTION

Cette commande démarre un serveur web qui affiche une vue en temps réel du graphe d'objets Kubernetes dans un navigateur. Elle utilise l'Agent GitLab pour Kubernetes en cours d'exécution dans le cluster. Elle nécessite :

  • La version 18.1 ou ultérieure de GitLab et de l'Agent GitLab.
  • Au minimum le rôle Développeur dans le projet de l'agent.
  • Cette commande nécessite un jeton d'accès personnel ou un jeton d'accès de projet pour l'authentification. Le jeton doit avoir les scopes read_api et k8s_proxy.

Laissez vos commentaires dans l'issue 7900 ⟨https://gitlab.com/gitlab-org/cli/-/issues/7900⟩.

Filtrage des ressources

Pour filtrer les ressources, les espaces de noms et sélectionner les objets racines, utilisez le Common Expression Language (CEL) ⟨https://cel.dev/⟩.

object_selector_expression : Filtre les objets. L'expression doit retourner un booléen. Ces variables sont disponibles :

  • obj : L'objet Kubernetes évalué.
  • group : Le groupe de l'objet.
  • version : La version de l'objet.
  • resource : Le nom de la ressource de l'objet, comme pods pour le type Pod.
  • namespace : L'espace de noms de l'objet.
  • name : Le nom de l'objet.
  • labels : Les étiquettes de l'objet.
  • annotations : Les annotations de l'objet.

resource_selector_expression : Filtre les informations de découverte Kubernetes pour inclure ou exclure des ressources de la requête de surveillance. L'expression doit retourner un booléen. Ces variables sont disponibles :

  • group : Le groupe de l'objet.
  • version : La version de l'objet.
  • resource : Le nom de la ressource de l'objet, comme pods pour le type Pod.
  • namespaced : La portée du groupe, de la version et de la ressource. Peut être bool, true, ou false.

Pour sélectionner les objets racines, utilisez le drapeau --root-expression. Lorsqu'il est défini, seuls les objets qui sont directement ou transitivement accessibles depuis les objets racines sont affichés. Ce drapeau utilise les mêmes variables que object_selector_expression et doit retourner un booléen. Plusieurs valeurs sont jointes par des instructions OR. Si l'une correspond, l'objet est utilisé comme racine.

Pour plus d'informations sur l'utilisation des sélecteurs d'étiquettes ⟨https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/#label-selectors⟩ et des sélecteurs de champs ⟨https://kubernetes.io/docs/concepts/overview/working-with-objects/field-selectors/⟩ pour sélectionner des espaces de noms, consultez la documentation de Kubernetes.

Usage avancé

Outre les moyens de haut niveau pour construire la requête, cette commande vous permet de construire et d'envoyer la requête en utilisant toutes les fonctionnalités de l'API sous-jacente. Pour comprendre ce qui est possible et comment le faire, consultez le document de conception technique ⟨https://gitlab.com/gitlab-org/cluster-integration/gitlab-agent/-/blob/master/doc/graph_api.md⟩

L'utilisateur doit avoir la permission d'accéder au projet de l'agent. Pour plus d'informations, voir Accorder aux utilisateurs l'accès à Kubernetes ⟨https://docs.gitlab.com/user/clusters/agent/user_access/⟩.

Cette fonctionnalité est expérimentale. Elle peut être défectueuse ou supprimée sans préavis. Pour en savoir plus sur la signification des fonctionnalités expérimentales, consultez https://docs.gitlab.com/policy/development_stages_support/

Utilisez les fonctionnalités expérimentales à vos propres risques.

OPTIONS

-a, --agent=0 L'ID numérique de l'Agent auquel se connecter.

--apps[=false] Surveille les déploiements, les ensembles de réplication, les ensembles de démons et les ensembles d'état dans le groupe apps/v1.

--batch[=false] Surveille les travaux et les travaux cron dans le groupe batch/v1.

--cluster-rbac[=false] Surveille les rôles de cluster et les liaisons de rôles de cluster dans le groupe rbac.authorization.k8s.io/v1.

--core[=false] Surveille les pods, les secrets, les configmaps et les comptes de service dans le groupe core/v1

--crd[=false] Surveille les définitions de ressources personnalisées dans le groupe apiextensions.k8s.io/v1.

--ignore-arc-direction[=false] Ignore la direction de l'arc lors de l'évaluation de la connectivité des racines. GitLab et l'agent 18.3+ requis.

--listen-addr="localhost:0" Adresse sur laquelle écouter.

--listen-net="tcp" Réseau sur lequel écouter les connexions.

--log-watch-request[=false] Journalise la requête de surveillance sur stdout. Utile pour le débogage.

-n, --namespace=[] Espaces de noms à surveiller. Si non spécifié, tous les espaces de noms sont surveillés avec filtrage par étiquettes et sélecteurs de champs.

--ns-expression="" Expression CEL pour sélectionner les espaces de noms. Évaluée avant la surveillance d'un espace de noms et lors de toute mise à jour de l'objet espace de noms.

--ns-field-selector="" Sélecteur de champs pour sélectionner les espaces de noms.

--ns-label-selector="" Sélecteur d'étiquettes pour sélectionner les espaces de noms.

--rbac[=false] Surveille les rôles et les liaisons de rôles dans le groupe rbac.authorization.k8s.io/v1.

-r, --resource=[] Une liste de ressources à surveiller. Vous pouvez voir la liste des ressources prises en charge par votre cluster en exécutant 'kubectl api-resources'.

--root-expression=[] Expression CEL pour sélectionner les objets racines. GitLab et l'agent 18.3+ requis.

--stdin[=false] Lire la requête de surveillance depuis l'entrée standard.

OPTIONS HERITEEES DES COMMANDES PARENTES

-h, --help[=false] Afficher l'aide pour cette commande.

-R, --repo="" Sélectionner un autre dépôt. Peut utiliser le format PROPRIETAIRE/REPO ou GROUPE/ESPACENOM/REPO. Accepte également l'URL complète ou l'URL Git.

EXEMPLE

# Exécute la requête par défaut pour l'agent 123
$ glab cluster graph -R utilisateur/projet -a 123
# Affiche les ressources courantes des groupes core et RBAC
$ glab cluster graph -R utilisateur/projet -a 123 --core --rbac
# Affiche certaines ressources
$ glab cluster graph -R utilisateur/projet -a 123 --resource=pods --resource=configmaps
# Identique à ci-dessus, mais plus compact
$ glab cluster graph -R utilisateur/projet -a 123 -r={pods,configmaps}
# Sélectionne un certain espace de noms
$ glab cluster graph -R utilisateur/projet -a 123 -n={mon-ns,mon-truc}
# Sélectionne tous les espaces de noms qui ont une certaine annotation
$ glab cluster graph -R utilisateur/projet -a 123 --ns-expression='"mon-annotation" dans annotations'
# Usage avancé - passe la requête complète directement via stdin.
# La requête ci-dessous surveille les comptes de service dans tous les espaces de noms sauf kube-system.
$ Q='{"queries":[{"include":{"resource_selector_expression":"resource == \"serviceaccounts\""}}],"namespaces":{"object_selector_expression":"name != \"kube-system\""}}'
$ echo -n "$Q" | glab cluster graph -R utilisateur/projet -a 123 --stdin
# Filtrage des racines
$ glab cluster graph -R utilisateur/projet -a 123 --root-expression 'group == "" && resource == "pods"'
