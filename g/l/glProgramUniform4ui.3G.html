PARAMETRES

program

Spécifie le handle du programme contenant la variable uniform à modifier.

location

Spécifie l'emplacement de la variable uniform à modifier.

count

Pour les commandes de vecteur (glProgramUniform*v), spécifie le nombre d'éléments à modifier. Ce nombre doit être 1 si la variable uniform ciblée n'est pas un tableau, et 1 ou plus si c'est un tableau.

Pour les commandes de matrice (glProgramUniformMatrix*), spécifie le nombre de matrices à modifier. Ce nombre doit être 1 si la variable uniform ciblée n'est pas un tableau de matrices, et 1 ou plus si c'est un tableau.

transpose

Pour les commandes de matrice, spécifie si la matrice doit être transposée. Si transpose est GL_TRUE, la matrice fournie dans value est transposée. Sinon, elle est utilisée telle quelle.

value

Pointeur vers le tableau contenant les nouvelles valeurs du/des variable(s) uniform.

v0, v1, v2, v3

Les valeurs à définir pour la variable uniform.

DESCRIPTION

Ces fonctions sont utilisées pour définir la valeur d'une variable uniform à l'intérieur d'un objet programme. Elles sont similaires aux fonctions glUniform*, mais elles ne nécessitent pas que le programme soit actif lors de leur appel.

Le paramètre program doit contenir le handle d'un programme valide, et location doit être l'emplacement d'une variable uniform dans ce programme. Ces fonctions écrasent les valeurs existantes de la variable uniform spécifiée.

Les fonctions terminées par f attendent des valeurs en virgule flottante, celles terminées par i attendent des valeurs entières signées, et celles terminées par ui attendent des valeurs entières non signées.

Les fonctions terminées par v (par exemple, glProgramUniform1fv) acceptent un pointeur vers un tableau de valeurs. Le paramètre count spécifie le nombre d'éléments (ou de matrices) à écrire.

Les fonctions glProgramUniformMatrix* sont utilisées pour définir des variables uniforms de type matrice. Le paramètre transpose indique si la matrice doit être transposée avant d'être définie. Les matrices sont stockées en mémoire sous forme de colonnes.

ERREURS

GL_INVALID_VALUE

Si program n'est pas le handle d'un programme valide, ou si location n'est pas un emplacement valide pour une variable uniform dans program.

Si count est négatif.

Si une commande de matrice est appelée avec un count tel que le nombre total de matrices dépasse la limite maximale du système.

GL_INVALID_OPERATION

Si program est le programme par défaut (ID 0).

Si program n'a pas été compilé et lié avec succès.

GL_INVALID_FRAMEBUFFER_OPERATION

Si le programme est exécuté lors d'une requête de lecture sur une framebuffer incomplète.

DESCRIPTIO

N

glProgramUniform modifie la valeur d'une variable uniforme ou d'un tableau de variables uniformes. L'emplacement de la variable uniforme à modifier est spécifié par location, qui doit être une valeur renvoyée par glGetUniformLocation(). glProgramUniform opère sur l'objet programme spécifié par program

.

Les commandes glProgramUniform{1|2|3|4}{f|i|ui} sont utilisées pour changer la valeur de la variable uniforme spécifiée par location en utilisant les valeurs passées en arguments. Le nombre spécifié dans la commande doit correspondre au nombre de composantes du type de données de la variable uniforme spécifiée (par ex., 1 pour float, int, unsigned int, bool ; 2 pour vec2, ivec2, uvec2, bvec2, etc.). Le suffixe f indique que des valeurs en virgule flottante sont passées ; le suffixe i indique que des valeurs entières sont passées ; le suffixe ui indique que des valeurs entières non signées sont passées, et ce type doit également correspondre au type de données de la variable uniforme spécifiée. Les variantes i de cette fonction doivent être utilisées pour fournir des valeurs à des variables uniformes définies en tant que int, ivec2, ivec3, ivec4, ou des tableaux de ceux-ci. Les variantes ui de cette fonction doivent être utilisées pour fournir des valeurs à des variables uniformes définies en tant que unsigned int, uvec2, uvec3, uvec4, ou des tableaux de ceux-ci. Les variantes f doivent être utilisées pour fournir des valeurs à des variables uniformes de type float, vec2, vec3, vec4, ou des tableaux de ceux-ci. Les variantes i, ui ou f peuvent être utilisées pour fournir des valeurs à des variables uniformes de type bool, bvec2, bvec3, bvec4, ou des tableaux de ceux-ci. La variable uniforme sera définie à false si la valeur d'entrée est 0 ou 0.0f, et elle sera définie à true dans le cas

contraire.

Toutes les variables uniformes actives définies dans un objet programme sont initialisées à 0 lorsque l'objet programme est lié avec succès. Elles conservent les valeurs qui leur ont été assignées par un appel à glProgramUniform jusqu'à ce que la prochaine opération de liaison réussie ait lieu sur l'objet programme, auquel moment elles sont à nouveau initialisées à

0.

Les commandes glProgramUniform{1|2|3|4}{f|i|ui}v peuvent être utilisées pour modifier une seule variable uniforme ou un tableau de variables uniformes. Ces commandes passent un compte et un pointeur vers les valeurs à charger dans une variable uniforme ou un tableau de variables uniformes. Un compte de 1 doit être utilisé si l'on modifie la valeur d'une seule variable uniforme, et un compte de 1 ou supérieur peut être utilisé pour modifier tout un tableau ou une partie d'un tableau. Lors du chargement n éléments à partir d'une position arbitraire m dans un tableau de variables uniformes, les éléments m + n - 1 dans le tableau seront remplacés par les nouvelles valeurs. Si m + n - 1 est supérieur à la taille du tableau de variables uniformes, les valeurs pour tous les éléments du tableau au-delà de la fin du tableau seront ignorées. Le nombre spécifié dans le nom de la commande indique le nombre de composantes pour chaque élément dans value, et il doit correspondre au nombre de composantes dans le type de données de la variable uniforme spécifiée (par ex., 1 pour float, int, bool ; 2 pour vec2, ivec2, bvec2, etc.). Le type de données spécifié dans le nom de la commande doit correspondre au type de données de la variable uniforme spécifiée comme décrit précédemment pour glProgramUniform{1|2|3|

4}{f|i|ui}.

Pour les tableaux de variables uniformes, chaque élément du tableau est considéré comme étant du type indiqué dans le nom de la commande (par ex., glProgramUniform3f ou glProgramUniform3fv peuvent être utilisées pour charger un tableau de variables uniformes de type vec3). Le nombre d'éléments du tableau de variables uniformes à modifier est spécifié par coun

t

Les commandes glProgramUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv sont utilisées pour modifier une matrice ou un tableau de matrices. Les nombres dans le nom de la commande sont interprétés comme la dimensionnalité de la matrice. Le nombre 2 indique une matrice 2 × 2 (c.-à-d., 4 valeurs), le nombre 3 indique une matrice 3 × 3 (c.-à-d., 9 valeurs), et le nombre 4 indique une matrice 4 × 4 (c.-à-d., 16 valeurs). La dimensionnalité des matrices non carrées est explicite, le premier nombre représentant le nombre de colonnes et le second nombre représentant le nombre de lignes. Par exemple, 2x4 indique une matrice 2 × 4 avec 2 colonnes et 4 lignes (c.-à-d., 8 valeurs). Si transpose est GL_FALSE, chaque matrice est supposée être fournie dans l'ordre colonne par colonne. Si transpose est GL_TRUE, chaque matrice est supposée être fournie dans l'ordre ligne par ligne. L'argument count indique le nombre de matrices à passer. Un compte de 1 doit être utilisé si l'on modifie la vale

ur d'une seule matrice, et un compte supérieur à 1
peut être utilisé pour modifier un tableau de matrices.

NOTE

S

glProgramUniform1i et glProgramUniform1iv sont les seules deux fonctions qui peuvent être utilisées pour charger des variables uniformes définies comme des types sampler. Le chargement de samplers avec toute autre fonction entraînera une erreur GL_INVALID_OPERATION

.

Si count est supérieur à 1 et que la variable uniforme indiquée n'est pas un tableau, une erreur GL_INVALID_OPERATION est générée et la variable uniforme spécifiée restera

inchangée.

En dehors des exceptions précédentes, si le type et la taille de la variable uniforme tels que définis dans le shader ne correspondent pas au type et à la taille spécifiés dans le nom de la commande utilisée pour charger sa valeur, une erreur GL_INVALID_OPERATION sera générée et la variable uniforme spécifiée restera

inchangée.

Si location est une valeur autre que -1 et qu'elle ne représente pas un emplacement de variable uniforme valide dans program, une erreur sera générée, et aucun changement ne sera apporté au stockage des variables uniformes de program. Si location est égal à -1, les données passées seront ignorées silenc

ieusement et la variable uniforme
spécifiée ne sera pas modifiée.

ERREUR

S

GL_INVALID_OPERATION est généré si program ne fait pas référence à un objet programme appartenant au

GL.

GL_INVALID_OPERATION est généré si la taille de la variable uniforme déclarée dans le shader ne correspond pas à la taille indiquée par la commande glProgramUniform

.

GL_INVALID_OPERATION est généré si l'une des variantes d'entier signé ou non signé de cette fonction est utilisée pour charger une variable uniforme de type float, vec2, vec3, vec4, ou un tableau de ceux-ci, ou si l'une des variantes en virgule flottante de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes d'entier signé de cette fonction est utilisée pour charger une variable uniforme de type unsigned int, uvec2, uvec3, uvec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si l'une des variantes d'entier non signé de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, ou un tableau de

ceux-ci.

GL_INVALID_OPERATION est généré si location est un emplacement uniforme invalide pour program et location n'est pas égal à

-1.

GL_INVALID_VALUE est généré si count est inférieur à

0.

GL_INVALID_OPERATION est généré si count est supérieur à 1 et que la variable uniforme indiquée n'est pas une variable

tableau.

GL_INVALID_OPERATION est généré si un sampler est chargé à l'aide d'une commande autre que glProgramUniform1i et glProgramUniform1i

v
.
