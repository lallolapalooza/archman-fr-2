NOM

glBufferData, glNamedBufferData - crée et initialise le stockage de données d'un objet tampon

SPÉCIFICATION C

void glBufferData(GLenum cible, GLsizeiptr taille, const void * données, GLenum utilisation);

void glNamedBufferData(GLuint tampon, GLsizeiptr taille, const void *données, GLenum utilisation);

PARAMÈTRES

cible

Spécifie la cible à laquelle l'objet tampon est lié pour glBufferData, qui doit être l'une des cibles de liaison de tampon dans le tableau suivant :
Cible de liaison de tampon But
GL_ARRAY_BUFFER Attributs de sommet
GL_ATOMIC_COUNTER_BUFFER Stockage de compteur atomique
GL_COPY_READ_BUFFER Source de copie de tampon
GL_COPY_WRITE_BUFFER Destination de copie de tampon
GL_DISPATCH_INDIRECT_BUFFER Commandes de dispatch de calcul indirectes
GL_DRAW_INDIRECT_BUFFER Arguments de commande indirects
GL_ELEMENT_ARRAY_BUFFER Indices de tableau de sommets
GL_PIXEL_PACK_BUFFER Cible de lecture de pixel
GL_PIXEL_UNPACK_BUFFER Source de données de texture
GL_QUERY_BUFFER Tampon de résultat de requête
GL_SHADER_STORAGE_BUFFER Stockage en lecture-écriture pour les shaders
GL_TEXTURE_BUFFER Tampon de données de texture
GL_TRANSFORM_FEEDBACK_BUFFER Tampon de feedback de transformation
GL_UNIFORM_BUFFER Stockage de bloc uniforme

tampon

Spécifie le nom de l'objet tampon pour la fonction glNamedBufferData.

taille

Spécifie la taille en octets du nouveau stockage de données de l'objet tampon.

données

Spécifie un pointeur vers les données qui seront copiées dans le stockage de données pour initialisation, ou NULL si aucune donnée ne doit être copiée.

utilisation

Spécifie le modèle d'utilisation attendu du stockage de données. La constante symbolique doit être GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, ou GL_DYNAMIC_COPY.

DESCRIPTION

glBufferData et glNamedBufferData créent un nouveau stockage de données pour un objet tampon. Dans le cas de glBufferData, l'objet tampon actuellement lié à cible est utilisé. Pour glNamedBufferData, un objet tampon associé à l'identifiant spécifié par l'appelant dans tampon sera utilisé à la place.

Lors de la création du nouveau stockage, tout stockage de données existant est supprimé. Le nouveau stockage de données est créé avec la taille et l'utilisation spécifiées. Si données n'est pas NULL, le stockage de données est initialisé avec les données de ce pointeur. Dans son état initial, le nouveau stockage de données n'est pas mappé, il a un pointeur mappé NULL et son accès mappé est GL_READ_WRITE.

utilisation est un indice pour l'implémentation GL concernant la manière dont le stockage de données d'un objet tampon sera accédé. Cela permet à l'implémentation GL de prendre des décisions plus intelligentes qui peuvent impacter significativement les performances de l'objet tampon. Cependant, cela ne contraint pas l'utilisation réelle du stockage de données. utilisation peut être décomposée en deux parties : d'abord, la fréquence d'accès (modification et utilisation), et ensuite, la nature de cet accès. La fréquence d'accès peut être l'une des suivantes :

STREAM

Le contenu du stockage de données sera modifié une fois et utilisé au plus quelques fois.

STATIC

Le contenu du stockage de données sera modifié une fois et utilisé de nombreuses fois.

DYNAMIC

Le contenu du stockage de données sera modifié à plusieurs reprises et utilisé de nombreuses fois.

La nature de l'accès peut être l'une des suivantes :

DRAW

Le contenu du stockage de données est modifié par l'application et utilisé comme source pour les commandes de dessin et de spécification d'image GL.

READ

Le contenu du stockage de données est modifié en lisant les données depuis le GL et utilisé pour retourner ces données lorsqu'elles sont interrogées par l'application.

COPY

Le contenu du stockage de données est modifié en lisant les données depuis le GL et utilisé comme source pour les commandes de dessin et de spécification d'image GL.

NOTES

Si données est NULL, un stockage de données de la taille spécifiée est toujours créé, mais son contenu reste non initialisé et donc indéfini.

Les clients doivent aligner les éléments de données de manière cohérente avec les exigences de la plateforme cliente, avec une exigence supplémentaire de niveau de base selon laquelle un décalage dans un tampon vers une donnée comprenant N octets doit être un multiple de N.

La cible GL_ATOMIC_COUNTER_BUFFER n'est disponible que si la version GL est 4.2 ou supérieure.

Les cibles GL_DISPATCH_INDIRECT_BUFFER et GL_SHADER_STORAGE_BUFFER ne sont disponibles que si la version GL est 4.3 ou supérieure.

La cible GL_QUERY_BUFFER n'est disponible que si la version GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est générée par glBufferData si cible n'est pas l'une des cibles de tampon acceptées.

GL_INVALID_ENUM est générée si utilisation n'est pas GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, ou GL_DYNAMIC_COPY.

GL_INVALID_VALUE est générée si taille est négative.

GL_INVALID_OPERATION est générée par glBufferData si le nom réservé d'objet tampon 0 est lié à cible.

GL_INVALID_OPERATION est générée par glNamedBufferData si tampon n'est pas le nom d'un objet tampon existant.

GL_INVALID_OPERATION est générée si le drapeau GL_BUFFER_IMMUTABLE_STORAGE de l'objet tampon est GL_TRUE.

GL_OUT_OF_MEMORY est générée si le GL est incapable de créer un stockage de données avec la taille spécifiée.

NAME

glNamedBufferData – creates and initializes a new buffer object's data store

C SPECIFICATION

void glNamedBufferData(GLuint buffer, GLsizeiptr size, const void *data, GLenum usage);

PARAMETERS

buffer
The name of the buffer object.
size
The size of the buffer object's data store in basic memory units.
data
A pointer to the data that will be used to initialize the buffer object's data store. If this pointer is NULL, then the initial contents of the buffer object are undefined.
usage
The intended usage pattern of the buffer object. The symbolic constant must be one of the GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, or GL_DYNAMIC_COPY.

DESCRIPTION

glNamedBufferData creates a new buffer object or replaces the data store of an existing buffer object. When you create a buffer object by calling glGenBuffers, it is initially empty. You must initialize its data store by calling glBufferData or glNamedBufferData. If buffer is the name of an existing buffer object, the existing data store is deleted and the buffer object is assigned a new data store of size size, initialized with the data pointed to by data.

If data is not NULL, then size must be at least as large as the number of basic memory units specified by size. The values copied from data are the first size basic memory units of the new data store.

If data is NULL, then the initial contents of the buffer object's data store are undefined. The buffer object is still created with the specified size.

The usage parameter is a hint to the GL implementation about how the buffer will be accessed. This information may be used to optimize buffer transfer operations. It is a symbolic constant:

  • GL_STREAM_DRAW: The data store will be modified once and used to draw many times.
  • GL_STREAM_READ: The data store will be modified once and used to read many times.
  • GL_STREAM_COPY: The data store will be modified once and used for reads and draws many times.
  • GL_STATIC_DRAW: The data store will be modified infrequently and used to draw many times.
  • GL_STATIC_READ: The data store will be modified infrequently and used to read many times.
  • GL_STATIC_COPY: The data store will be modified infrequently and used for reads and draws many times.
  • GL_DYNAMIC_DRAW: The data store will be modified many times and used to draw many times.
  • GL_DYNAMIC_READ: The data store will be modified many times and used to read many times.
  • GL_DYNAMIC_COPY: The data store will be modified many times and used for reads and draws many times.

Usage values of type GL_STATIC_* indicate that the data store will not be modified after it is initialized. Usage values of type GL_DYNAMIC_* indicate that the data store will be modified more than once after it is initialized. Usage values of type GL_STREAM_* indicate that the data store will be modified once after it is initialized.

The terms DRAW, READ, and COPY describe how the data store will be used with subsequent calls to glDrawArrays, glDrawElements, glDrawArraysIndirect, glDrawElementsIndirect, and how the buffer object will be used as the source or destination of glCopyBufferSubData, and the sources and destinations of calls to glCopyBufferSubData.

If data is NULL, then glNamedBufferData is equivalent to calling glBufferData with data=NULL. However, glNamedBufferData does not require the buffer to be first bound using glBindBuffer.

NOTES

Buffer objects are created by glGenBuffers, bound by glBindBuffer, and deleted by glDeleteBuffers.

glNamedBufferData is available for buffer objects created with glGenBuffers.

glNamedBufferData is available for buffer objects created with glCreateBuffers.

If size is 0, then the buffer object is created with an empty data store.

ERRORS

GL_INVALID_VALUE is generated if size is negative.

GL_INVALID_OPERATION is generated if buffer was not generated by glGenBuffers.

GL_INVALID_OPERATION is generated if the specified usage is not one of the valid usage parameters.
