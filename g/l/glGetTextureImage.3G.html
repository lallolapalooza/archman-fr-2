NOM

glGetTexImage, glGetnTexImage, glGetTextureImage - renvoient une image de texture

SPÉCIFICATION C

void glGetTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, void *pixels);

void glGetnTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

void glGetTextureImage(GLuinttexture, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

PARAMÈTRES

target

Spécifie la cible à laquelle la texture est liée pour glGetTexImage et glGetnTexImage . GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Zet GL_TEXTURE_CUBE_MAP_ARRAY sont acceptables.

texture

Spécifie le nom de l'objet texture.

level

Spécifie le numéro de niveau de détail de l'image souhaitée. Le niveau 0 est le niveau de l'image de base. Le niveau n est la nième image de réduction de mipmap.

format

Spécifie un format de pixel pour les données renvoyées. Les formats pris en charge sont GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_DEPTH_STENCIL, GL_RED, GL_GREEN, GL_BLUE, GL_RG, GL_RGB, GL_RGBA, GL_BGR, GL_BGRA, GL_RED_INTEGER, GL_GREEN_INTEGER, GL_BLUE_INTEGER, GL_RG_INTEGER, GL_RGB_INTEGER, GL_RGBA_INTEGER, GL_BGR_INTEGER, GL_BGRA_INTEGER.

type

Spécifie un type de pixel pour les données renvoyées. Les types pris en charge sont GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_HALF_FLOAT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, GL_UNSIGNED_INT_24_8, GL_UNSIGNED_INT_10F_11F_11F_REV, GL_UNSIGNED_INT_5_9_9_9_REVet GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

bufSize

Spécifie la taille du tampon pixels pour glGetnTexImage et glGetTextureImage .

pixels

Renvoie l'image de texture. Doit être un pointeur vers un tableau du type spécifié par type.

DESCRIPTION

glGetTexImage, glGetnTexImage et glGetTextureImage renvoient une image de texture dans pixels. Pour glGetTexImage et glGetnTexImage, target indique si l'image de texture souhaitée est celle spécifiée par glTexImage1D() (GL_TEXTURE_1D), glTexImage2D() (GL_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_2D ou l'une des GL_TEXTURE_CUBE_MAP_*), ou glTexImage3D() (GL_TEXTURE_2D_ARRAY, GL_TEXTURE_3D, GL_TEXTURE_CUBE_MAP_ARRAY). Pour glGetTextureImage, texture spécifie le nom de l'objet texture. En plus des types de textures acceptés par glGetTexImage et glGetnTexImage, la fonction accepte également les objets texture de cube map (avec la cible effective GL_TEXTURE_CUBE_MAP). level spécifie le numéro de niveau de détail de l'image souhaitée. format et type spécifient le format et le type du tableau d'images souhaité. Voir la page de référence de glTexImage1D() pour une description des valeurs acceptables pour les paramètres format et type respectivement. Pour les fonctions glGetnTexImage et glGetTextureImage, bufSize indique la taille du tampon destiné à recevoir les données de pixels récupérées. glGetnTexImage et glGetTextureImage n'écrivent pas plus de bufSize octets dans pixels.

Si un objet tampon non nommé (de valeur non nulle) est lié à la cible GL_PIXEL_PACK_BUFFER (voir glBindBuffer()) lorsqu'une image de texture est demandée, pixels est traité comme un décalage en octets dans le magasin de données de l'objet tampon.

Pour comprendre le fonctionnement de glGetTexImage, considérez l'image de texture interne à quatre composantes sélectionnée comme un tampon de couleur RGBA de la taille de l'image. La sémantique de glGetTexImage est alors identique à celle de glReadPixels(), à l'exception qu'aucune opération de transfert de pixel n'est effectuée, lorsqu'elle est appelée avec le même format et le même type, avec x et y définis à 0, width défini à la largeur de l'image de texture et height défini à 1 pour les images 1D, ou à la hauteur de l'image de texture pour les images 2D.

Si l'image de texture sélectionnée ne contient pas quatre composantes, les correspondances suivantes sont appliquées. Les textures à une seule composante sont traitées comme des tampons RGBA avec le rouge défini à la valeur de la composante unique, le vert défini à 0, le bleu défini à 0 et l'alpha défini à 1. Les textures à deux composantes sont traitées comme des tampons RGBA avec le rouge défini à la valeur de la composante zéro, l'alpha défini à la valeur de la composante un, et le vert et le bleu définis à 0. Enfin, les textures à trois composantes sont traitées comme des tampons RGBA avec le rouge défini à la composante zéro, le vert défini à la composante un, le bleu défini à la composante deux et l'alpha défini à 1.

Pour déterminer la taille requise de pixels, utilisez glGetTexLevelParameter() pour déterminer les dimensions de l'image de texture interne, puis mettez à l'échelle le nombre de pixels requis par le stockage requis pour chaque pixel, en fonction de format et type. Assurez-vous de prendre en compte les paramètres de stockage de pixel, en particulier GL_PACK_ALIGNMENT.

Si glGetTextureImage est utilisé sur un objet texture de cube map, la texture est traitée comme une image tridimensionnelle d'une profondeur de 6, où les faces de la cube map sont ordonnées comme des couches d'image, dans l'ordre présenté dans le tableau ci-dessous :

Numéro de couche Face de cube map
0 GL_TEXTURE_CUBE_MAP_POSITIVE_X
1 GL_TEXTURE_CUBE_MAP_NEGATIVE_X
2 GL_TEXTURE_CUBE_MAP_POSITIVE_Y
3 GL_TEXTURE_CUBE_MAP_NEGATIVE_Y
4 GL_TEXTURE_CUBE_MAP_POSITIVE_Z
5 GL_TEXTURE_CUBE_MAP_NEGATIVE_Z

REMARQUES

Si une erreur est générée, le contenu de pixelsn'est pas modifié.

glGetTexImage et glGetnTexImage renvoient l'image de texture pour l'unité de texture active.

GL_STENCIL_INDEX est accepté pour format uniquement si la version GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est généré par glGetTexImage et glGetnTexImage si target n'est pas une valeur acceptée. Celles-ci incluent :

•GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLEet GL_TEXTURE_CU

NAME

glGetTextureImage, glGetCompressedTextureImage, glGetnCompressedTexImage, glGetnTexImage - retrieve a texture image or compressed texture image

C SPECIFICATION

void glGetTexImage(GLenum target, GLint level, GLenum format, GLenum type, void *pixels);
void glGetTextureImage(GLuint texture, GLint level, GLenum format, GLenum type, GLsizei bufSize, void *pixels);
void glGetCompressedTextureImage(GLuint texture, GLint level, GLsizei bufSize, void *pixels);
void glGetnCompressedTexImage(GLenum target, GLint level, GLsizei bufSize, void *pixels);
void glGetnTexImage(GLenum target, GLint level, GLenum format, GLenum type, GLsizei bufSize, void *pixels);

PARAMETERS

texture
Specifies the texture object name.
texture
Specifies the texture object name.
level
Specifies the level-of-detail number. 0 represents the base image.
format
Specifies the format of the pixel data. See the explanation under glTexImage2D.
type
Specifies the data type of the pixel data. The possible symbolic constants are GL_BYTE, GL_UNSIGNED_BYTE, GL_SHORT, GL_UNSIGNED_SHORT, GL_INT, GL_UNSIGNED_INT, GL_FLOAT, GL_HALF_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_5_5_5_1_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_10_10_10_2_REV, GL_UNSIGNED_INT_16_8_8_8_8, GL_UNSIGNED_INT_16_8_8_8_8_REV, GL_UNSIGNED_INT_24_8, GL_UNSIGNED_INT_24_8_REV, GL_UNSIGNED_INT_10F_11F_11F_REV, GL_UNSIGNED_INT_5_9_9_9_REV, and GL_FLOAT_32_UNSIGNED_INT_24_8_REV.
bufSize
The size of the buffer pointed to by pixels in bytes.
pixels
Returns the texture image, compressed or raw pixels. The format of the returned data depends on the internal format of the texture and the specified format and type.
target
Specifies the texture target. Must be one of GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_2D_MULTISAMPLE, or GL_TEXTURE_2D_MULTISAMPLE_ARRAY.

DESCRIPTION

glGetTexImage copies a specified texture image from the currently bound texture object into an array of pixel data. The texture object is determined by the target argument. The texture can be one-, two-, or three-dimensional, or a cubemap texture, or a texture array. The level of detail is specified by level.

glGetTextureImage retrieves the specified texture image from the texture object identified by texture. The image is copied into the buffer starting at the memory address specified by pixels.

glGetCompressedTextureImage retrieves a compressed texture image from the texture object identified by texture. The image is copied into the buffer starting at the memory address specified by pixels.

glGetnTexImage and glGetnCompressedTexImage are version of glGetTexImage and glGetCompressedTextureImage that take an additional argument bufSize. This argument specifies the maximum number of bytes that may be written into pixels. These functions are intended to be used in security-sensitive contexts, such as when receiving data from untrusted clients.

The format of the returned data is controlled by format and type. See glTexImage2D for a description of these parameters.

glGetCompressedTextureImage and glGetnCompressedTexImage are used to retrieve the compressed representation of a texture image. The format and type parameters are ignored for these functions.

The data is returned in the same order that it would be stored if the texture image were written using glCompressedTexImage2D. The pixel coordinates x=0, y=0, z=0 correspond to the first element of the array.

The values are placed into the buffer as if glPixelStore was called with the following parameters:

GL_PACK_ROW_LENGTH
0
GL_PACK_IMAGE_HEIGHT
0
GL_PACK_SKIP_PIXELS
0
GL_PACK_SKIP_ROWS
0
GL_PACK_SKIP_VOLUMES
0
GL_PACK_ALIGNMENT
1

NOTES

The behavior of glGetTexImage depends on the pixel storage modes set by glPixelStore. See glPixelStore (3G) for a complete description of these parameters.

glGetTextureImage, glGetCompressedTextureImage, glGetnCompressedTexImage, and glGetnTexImage require the texture object to have been created with glTextureData or glTextureStorage.

If a buffer object is bound to the GL_PIXEL_PACK_BUFFER target, then pixels is treated as an offset into that buffer object, and the texture image is read from the buffer object into the buffer object. The value of GL_PIXEL_PACK_BUFFER_BINDING is the value of the buffer object binding.

If the texture is a cubemap texture, glGetTexImage and glGetTextureImage will retrieve the image corresponding to the face specified by target.

If the texture is a texture array, glGetTexImage and glGetTextureImage will retrieve the image corresponding to the layer specified by target.

The bufSize parameter for glGetnTexImage and glGetnCompressedTexImage is the size of the buffer in bytes.

ERRORS

GL_INVALID_ENUM is generated if target, format, or type is not a valid enum value.

GL_INVALID_VALUE is generated if level is less than 0.

GL_INVALID_VALUE may be generated if level is greater than log 2 max, where max is the returned value of GL_MAX_TEXTURE_SIZE.

GL_INVALID_OPERATION is generated if the texture object is not defined.

GL_INVALID_OPERATION is generated if the specified texture is not a texture object.

GL_INVALID_OPERATION is generated if the texture object has not been defined by means of glTexImage1D, glTexImage2D, glTexImage3D, glCompressedTexImage1D, glCompressedTexImage2D, glCompressedTexImage3D, glCopyTexImage1D, glCopyTexImage2D, glCopyTexImage3D, glCopyCompressedTexImage1D, glCopyCompressedTexImage2D, or glCopyCompressedTexImage3D.

GL_INVALID_OPERATION is generated if level is non-zero and the effective target is GL_TEXTURE_RECTANGLE.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, or GL_UNSIGNED_INT_10F_11F_11F_REV and format is not GL_RGB.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, or GL_UNSIGNED_INT_5_9_9_9_REV and format is neither GL_RGBA or GL_BGRA.

GL_INVALID_OPERATION is generated if format is GL_STENCIL_INDEX and the base internal format is not GL_STENCIL_INDEX or GL_DEPTH_STENCIL.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the buffer object's data store is currently mapped.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the data would be packed to the buffer object such that the memory writes required would exceed the data store size.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and pixels is not evenly divisible into the number of bytes needed to store in memory a datum indicated by type.

GL_INVALID_OPERATION is generated by glGetTextureImage and glGetnTexImage if the buffer size required to store the requested data is greater than bufSize.
