GLMAPBUFFER(3G) [FIXME: manuel] GLMAPBUFFER(3G)

NOM

glMapBuffer, glMapNamedBuffer - mapper tout le stockage de données d'un objet tampon dans l'espace d'adressage du client

SPÉCIFICATION C

void *glMapBuffer(GLenum target, GLenum access);

void *glMapNamedBuffer(GLuint buffer, GLenum access);

PARAMÈTRES

target

Spécifie la cible à laquelle l'objet tampon est lié pour glMapBuffer, qui doit être l'une des cibles de liaison de tampon du tableau suivant :
Cible de liaison de tampon Objectif
GL_ARRAY_BUFFER Attributs de sommet
GL_ATOMIC_COUNTER_BUFFER Stockage de compteurs atomiques
GL_COPY_READ_BUFFER Source de copie de tampon
GL_COPY_WRITE_BUFFER Destination de copie de tampon
GL_DISPATCH_INDIRECT_BUFFER Commandes de calcul indirectes
GL_DRAW_INDIRECT_BUFFER Arguments de commande indirects
GL_ELEMENT_ARRAY_BUFFER Indices de tableau de sommets
GL_PIXEL_PACK_BUFFER Cible de lecture de pixels
GL_PIXEL_UNPACK_BUFFER Source de données de texture
GL_QUERY_BUFFER Tampon de résultat de requête
GL_SHADER_STORAGE_BUFFER Stockage en lecture/écriture pour les shaders
GL_TEXTURE_BUFFER Tampon de données de texture
GL_TRANSFORM_FEEDBACK_BUFFER Tampon de retour de transformation
GL_UNIFORM_BUFFER Stockage de blocs uniformes

buffer

Spécifie le nom de l'objet tampon pour glMapNamedBuffer.

access

Spécifie la politique d'accès pour glMapBuffer et glMapNamedBuffer, indiquant s'il sera possible de lire, écrire, ou à la fois lire et écrire dans le stockage de données mappé de l'objet tampon. La constante symbolique doit être GL_READ_ONLY, GL_WRITE_ONLY, ou GL_READ_WRITE.

DESCRIPTION

glMapBuffer et glMapNamedBuffer mappent l'intégralité du stockage de données d'un objet tampon spécifié dans l'espace d'adressage du client. Les données peuvent alors être directement lues et/ou écrites par rapport au pointeur retourné, en fonction de la politique d'accès spécifiée.

Un pointeur vers le début de la plage mappée est retourné une fois que toutes les opérations en attente sur cet objet tampon sont terminées, et peut être utilisé pour modifier et/ou interroger la plage correspondante du stockage de données selon la valeur d'access :

•GL_READ_ONLY indique que le pointeur retourné peut être utilisé pour lire les données de l'objet tampon.
•GL_WRITE_ONLY indique que le pointeur retourné peut être utilisé pour modifier les données de l'objet tampon.
•GL_READ_WRITE indique que le pointeur retourné peut être utilisé pour lire et modifier les données de l'objet tampon.

Si une erreur est générée, un pointeur NULL est retourné.

Si aucune erreur ne se produit, le pointeur retourné reflétera une allocation alignée sur la valeur de GL_MIN_MAP_BUFFER_ALIGNMENT unités de base de la machine.

Les valeurs de pointeur retournées ne peuvent pas être passées comme paramètres à des commandes GL. Par exemple, elles ne peuvent pas être utilisées pour spécifier des pointeurs de tableau, ou pour spécifier ou interroger des données d'image de pixels ou de textures ; de telles actions produisent des résultats indéfinis, bien que les implémentations puissent ne pas vérifier un tel comportement pour des raisons de performance.

Aucune erreur GL n'est générée si le pointeur retourné est accédé d'une manière incohérente avec access (par exemple, utilisé pour lire à partir d'un mappage effectué avec access GL_WRITE_ONLY ou écrire dans un mappage effectué avec access GL_READ_ONLY), mais le résultat est indéfini et des erreurs système (y compris potentiellement la terminaison du programme) peuvent survenir.

Les mappages vers les stockages de données des objets tampons peuvent avoir des caractéristiques de performance non standard. Par exemple, de tels mappages peuvent être marqués comme des régions de mémoire non cachables, et dans ce cas, la lecture à partir d'eux peut être très lente. Pour garantir des performances optimales, le client doit utiliser le mappage d'une manière cohérente avec les valeurs de GL_BUFFER_USAGE pour l'objet tampon et de access. L'utilisation d'un mappage d'une manière incohérente avec ces valeurs risque d'être plusieurs ordres de grandeur plus lente que l'utilisation de la mémoire normale.

NOTES

L'alignement du pointeur retourné n'est garanti que si la version de GL est 4.2 ou supérieure. De plus, la cible GL_ATOMIC_COUNTER_BUFFER n'est acceptée que si la version de GL est 4.2 ou supérieure.

Les cibles GL_DISPATCH_INDIRECT_BUFFER et GL_SHADER_STORAGE_BUFFER ne sont disponibles que si la version de GL est 4.3 ou supérieure.

La cible GL_QUERY_BUFFER n'est disponible que si la version de GL est 4.4 ou supérieure.

ERREURS

GL_INVALID_ENUM est générée par glMapBuffer si target n'est pas l'une des cibles de liaison de tampon listées ci-dessus.

GL_INVALID_OPERATION est générée par glMapBuffer si zéro est lié à target.

GL_INVALID_OPERATION est générée par glMapNamedBuffer si buffer n'est pas le nom d'un objet tampon existant.

GL_INVALID_ENUM est générée si access n'est pas GL_READ_ONLY, GL_WRITE_ONLY, ou GL_READ_WRITE.

GL_OUT_OF_MEMORY est générée si le GL ne parvient pas à mapper le stockage de données de l'objet tampon. Cela peut se produire pour diverses raisons spécifiques au système, telles que l'absence de mémoire virtuelle restante suffisante.

GL_INVALID_OPERATION est générée si l'objet tampon est dans un état mappé.

GETS ASSOCIÉS

glGetBufferPointerv() avec l'argument GL_BUFFER_MAP_POINTER

glGetBufferParameter() avec les arguments GL_BUFFER_MAPPED, GL_BUFFER_ACCESS, ou GL_BUFFER_USAGE

glGet() avec le paramètre pname GL_MIN_MAP_BUFFER_ALIGNMENT. La valeur doit être une puissance de deux d'au moins 64.
