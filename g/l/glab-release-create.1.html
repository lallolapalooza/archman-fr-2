NOM

glab-release-create - Crée une nouvelle release GitLab ou met à jour une release existante.

SYNOPIS

glab release create [...] [flags]

DESCRIPTION

Crée une nouvelle release GitLab pour un dépôt, ou met à jour une release existante. Nécessite au moins le rôle Développeur.

Une release existante est mise à jour avec les nouvelles informations que vous fournissez.

Pour créer une release à partir d'un tag Git annoté :

1.
Créez le tag localement avec Git, et poussez le tag vers GitLab.
2.
Exécutez cette commande.
3.
Si le tag Git que vous spécifiez n'existe pas, la commande crée une release à partir de l'état le plus récent de la branche par défaut, et l'étiquette avec le nom de tag que vous spécifiez.

Pour remplacer ce comportement, utilisez --ref. Le ref
peut être un SHA de commit, un autre nom de tag, ou un nom de branche. 4. Optionnel. Pour récupérer le nouveau tag localement après la release, exécutez
git fetch --tags origin.

OPTIONS

-a, --assets-links="" Représentation de chaîne JSON des liens d'assets. Voir la documentation pour un exemple.

-m, --milestone=[] Le titre de chaque jalon auquel la release est associée. Plusieurs jalons peuvent être séparés par des virgules ou spécifiés en répétant le flag.

-n, --name="" Le nom ou titre de la release.

--no-close-milestone[=false] Empêche la fermeture des jalons après la création de la release.

--no-update[=false] Empêche la mise à jour de la release existante.

-N, --notes="" Les notes de release ou la description. Accepte Markdown.

-F, --notes-file="" Lit le 'fichier' de notes de release. Pour lire depuis stdin, utilisez '-'.

--package-name="release-assets" Le nom du paquet, lors du téléchargement d'assets vers la release de paquet générique avec --use-package-registry.

--publish-to-catalog=false ⟨EXPÉRIMENTAL⟩ Publie la release dans le catalogue CI/CD de GitLab.

-r, --ref="" Si le tag spécifié n'existe pas, crée une release à partir du ref et l'étiquette avec le nom de tag spécifié. Accepte un SHA de commit, un nom de tag, ou un nom de branche.

-D, --released-at="" Date et heure au format ISO 8601 où la release était prête. Par défaut, la date et l'heure actuelles.

-T, --tag-message="" Message à utiliser si un nouveau tag annoté est créé.

--use-package-registry[=false] Télécharge les assets de la release vers le registre de paquets générique du projet. Remplace la variable d'environnement GITLAB_RELEASE_ASSETS_USE_PACKAGE_REGISTRY.

OPTIONS HÉRITÉES DES COMMANDES PARENT

-h, --help[=false] Affiche l'aide de cette commande.

-R, --repo="" Sélectionne un autre dépôt. Peut utiliser le format PROPRIÉTAIRE/DÉPÔT ou GROUPE/ESPACE DE NOMS/DÉPÔT. Accepte également l'URL complète ou l'URL Git.

EXEMPLE

# Crée une release interactivement
$ glab release create v1.0.1
# Crée une release non-interactivement en spécifiant une note
$ glab release create v1.0.1 --notes "release de correction de bugs"
# Utilise les notes de release d'un fichier
$ glab release create v1.0.1 -F changelog.md
# Télécharge un asset de release avec un nom d'affichage (le type sera 'other' par défaut)
$ glab release create v1.0.1 '/chemin/vers/asset.zip#Mon libellé d'affichage'
# Télécharge un asset de release avec un nom d'affichage et un type
$ glab release release v1.0.1 '/chemin/vers/asset.png#Mon libellé d\'affichage#image'
# Télécharge tous les assets d'un dossier spécifié (les types sont 'other' par défaut)
$ glab release create v1.0.1 ./dist/*
# Télécharge toutes les archives tar d'un dossier spécifié (les types sont 'other' par défaut)
$ glab release create v1.0.1 ./dist/*.tar.gz
# Crée une release avec des assets spécifiés sous forme d'objet JSON
$ glab release create v1.0.1 --assets-links='
  [
    {
      "name": "Asset1",
      "url":"https://<domaine>/quelque/part/1",
      "link_type": "other",
      "direct_asset_path": "chemin/vers/fichier"
    }
  ]'
# (EXPÉRIMENTAL) Crée une release et la publie dans le catalogue CI/CD de GitLab
# Nécessite que le flag `ci_release_cli_catalog_publish_option` soit activé
# pour ce projet dans votre instance GitLab. NE PAS exécuter manuellement. L'utiliser comme partie
# d'un pipeline CI/CD avec le mot-clé "release" :
#
# - Il récupère les composants du dépôt actuel en recherchant
#   des fichiers `yml` dans le répertoire "templates" et ses sous-répertoires.
# - Il échoue si le flag `ci_release_cli_catalog_publish_option`
#   n'est pas activé pour ce projet dans votre instance GitLab.
# Les composants peuvent être définis :
# - Dans des fichiers uniques se terminant par `.yml` pour chaque composant, comme `templates/secret-detection.yml`.
# - Dans des sous-répertoires contenant des fichiers `template.yml` comme points d'entrée,
#   pour les composants qui regroupent plusieurs fichiers liés. Par exemple,
#   `templates/secret-detection/template.yml`.
$ glab release create v1.0.1 --publish-to-catalog
