DESCRIPTIO

N

glGetTexImage, glGetnTexImage et glGetTextureImage renvoient une image de texture dans pixels. Pour glGetTexImage et glGetnTexImage, target indique si l'image de texture souhaitée est celle spécifiée par glTexImage1D() (GL_TEXTURE_1D), glTexImage2D() (GL_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_2D ou l'un des GL_TEXTURE_CUBE_MAP_*), ou glTexImage3D() (GL_TEXTURE_2D_ARRAY, GL_TEXTURE_3D, GL_TEXTURE_CUBE_MAP_ARRAY). Pour glGetTextureImage, texture spécifie le nom de l'objet texture. En plus des types de textures acceptés par glGetTexImage et glGetnTexImage, la fonction accepte également les objets texture de cube map (avec la cible effective GL_TEXTURE_CUBE_MAP). level spécifie le numéro de niveau de détail de l'image souhaitée. format et type spécifient le format et le type du tableau d'image souhaité. Voir la page de référence de glTexImage1D() pour une description des valeurs acceptables pour les paramètres format et type, respectivement. Pour les fonctions glGetnTexImage et glGetTextureImage, bufSize indique la taille du tampon destiné à recevoir les données de pixels récupérées. glGetnTexImage et glGetTextureImage n'écrivent pas plus de bufSize octets dans pixels

.

Si un objet tampon nommé non nul est lié à la cible GL_PIXEL_PACK_BUFFER (voir glBindBuffer()) lorsqu'une image de texture est demandée, pixels est traité comme un décalage en octets dans le magasin de données de l'objet

tampon.

Pour comprendre le fonctionnement de glGetTexImage, considérez l'image de texture interne à quatre composantes sélectionnée comme un tampon de couleur RGBA de la taille de l'image. La sémantique de glGetTexImage est alors identique à celle de glReadPixels(), à l'exception qu'aucune opération de transfert de pixel n'est effectuée, lorsqu'elle est appelée avec le même format et type, avec x et y définis à 0, width défini à la largeur de l'image de texture et height défini à 1 pour les images 1D, ou à la hauteur de l'image de texture pour les images

2D.

Si l'image de texture sélectionnée ne contient pas quatre composantes, les correspondances suivantes sont appliquées. Les textures à une seule composante sont traitées comme des tampons RGBA avec le rouge défini à la valeur de la composante unique, le vert défini à 0, le bleu défini à 0 et l'alpha défini à 1. Les textures à deux composantes sont traitées comme des tampons RGBA avec le rouge défini à la valeur de la composante zéro, l'alpha défini à la valeur de la composante un, et le vert et le bleu définis à 0. Enfin, les textures à trois composantes sont traitées comme des tampons RGBA avec le rouge défini à la composante zéro, le vert défini à la composante un, le bleu défini à la composante deux et l'alpha défini à

1.

Pour déterminer la taille requise de pixels, utilisez glGetTexLevelParameter() pour déterminer les dimensions de l'image de texture interne, puis mettez à l'échelle le nombre de pixels requis par le stockage requis pour chaque pixel, en fonction de format et type. Veillez à prendre en compte les paramètres de stockage de pixels, en particulier GL_PACK_ALIGNMENT

.

Si glGetTextureImage est utilisé sur un objet texture de cube map, la texture est traitée comme une image tridimensionnelle d'une profondeur de 6, où les faces de la cube map sont ordonnées comme des couches d'image, dans un ordre présenté dans le tableau ci-dessous

NOM

glGetTextureImage, glGetnTexImage - renvoyer une image de texture

SPÉCIFICATION C

void glGetTextureImage( GLuint texture, GLint level, GLenum format, GLenum type, GLsizei bufSize, void *pixels );

void glGetnTexImage( GLenum target, GLint level, GLenum format, GLenum type, GLsizei bufSize, void *pixels );

PARAMÈTRES

texture
Spécifie l'objet texture cible à partir duquel renvoyer les données d'image. Le comportement de glGetTextureImage est identique à celui de glGetTexImage avec target défini sur la cible effective de la texture spécifiée par texture.
level
Spécifie le niveau de détail de l'image de texture à renvoyer. 0 représente l'image de base, 1 représente la première image mise à l'échelle, et ainsi de suite.
format
Spécifie le format des données de pixels à renvoyer. Il doit s'agir d'un format de format de pixels valide.
type
Spécifie le type des données de pixels à renvoyer. Il doit s'agir d'un type de données de pixels valide.
bufSize
Spécifie la taille en octets du tampon vers lequel les données d'image de texture seront copiées.
pixels
Spécifie le pointeur vers le tampon dans lequel les données d'image de texture seront renvoyées.
target
Pour glGetnTexImage, spécifie la cible de texture dont les données d'image sont renvoyées. Il peut s'agir de GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, ou GL_TEXTURE_CUBE_MAP_ARRAY.

DESCRIPTION

Les fonctions glGetTextureImage et glGetnTexImage renvoient une image de niveau de détail spécifié d'une texture dans un tampon de mémoire spécifié par pixels.

La fonction glGetTextureImage est une interface plus moderne introduite dans le profil OpenGL 4.5 et les extensions ARB_get_texture_sub_image et EXT_direct_state_access. Elle permet d'interroger directement un objet texture sans avoir besoin de lier d'abord la texture à une cible de texture.

La fonction glGetnTexImage est similaire à glGetTexImage mais remplace les valeurs de tailles d'image par une taille de tampon bufSize pour empêcher les dépassements de tampon.

Le paramètre format spécifie le format des données de pixels à renvoyer. Le paramètre type spécifie le type des données de pixels.

Les données de pixels sont renvoyées dans le tampon pixels, en commençant par le pixel le plus bas dans la coordonnée y, puis le pixel le plus à gauche dans la coordonnée x. Les lignes sont alignées selon l'alignement du remplissage du paquet spécifié par GL_PACK_ALIGNMENT.

La taille du tampon requise pour stocker les données demandées peut être calculée comme suit :

    largeur * hauteur * profondeur * octets_par_composant * nombre_de_composants

Où :

  • largeur, hauteur et profondeur sont les dimensions de l'image de texture au niveau spécifié.
  • octets_par_composant est déterminé par le paramètre type.
  • nombre_de_composants est déterminé par le paramètre format.

L'alignement du remplissage du paquet peut affecter la quantité réelle de mémoire requise. Si le tampon spécifié par pixels est trop petit pour contenir les données d'image demandées, un dépassement de tampon peut se produire. glGetnTexImage garantit que ce ne sera pas le cas, en renvoyant un sous-ensemble des données si nécessaire ou en générant une erreur si les données ne peuvent pas tenir dans le tampon.

NOTES

L'énumération des éléments de texture pour les textures cubiques peut être effectuée en utilisant les constantes :

    GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X,
    GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y,
    GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z

Pour les textures 3D, vous pouvez utiliser le paramètre target de glGetTexImage avec la valeur GL_TEXTURE_3D.

Pour les textures 2D, vous pouvez utiliser le paramètre target de glGetTexImage avec la valeur GL_TEXTURE_2D.

Pour les textures 1D, vous pouvez utiliser le paramètre target de glGetTexImage avec la valeur GL_TEXTURE_1D.

Si une mémoire tampon de pixels est liée à la cible GL_PIXEL_PACK_BUFFER, le comportement est le même que celui de glGetTexImage, sauf que les données d'image sont copiées dans l'objet mémoire tampon de pixels lié. Dans ce cas, la taille en octets du tampon est déterminée par la taille de l'objet mémoire tampon de pixels.

ERREURS

GL_INVALID_OPERATION est générée par glGetTextureImage si texture n'est pas le nom d'un objet texture existant.

GL_INVALID_ENUM est générée si format ou type n'est pas une valeur acceptée.

GL_INVALID_VALUE est générée si level est inférieur à 0.

GL_INVALID_VALUE peut être générée si level est supérieur à log 2 ⁡ max, où max est la valeur renvoyée par GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE est générée si level est différent de zéro et que la cible effective est GL_TEXTURE_RECTANGLE.

GL_INVALID_OPERATION est générée si type est l'un des GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, ou GL_UNSIGNED_INT_10F_11F_11F_REV et que format n'est pas GL_RGB.

GL_INVALID_OPERATION est générée si type est l'un des GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, ou GL_UNSIGNED_INT_5_9_9_9_REV et que format n'est ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION est générée si format est GL_STENCIL_INDEX et que le format interne de base n'est ni GL_STENCIL_INDEX ni GL_DEPTH_STENCIL.

GL_INVALID_OPERATION est générée si un nom d'objet mémoire tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que son magasin de données est actuellement mappé.

GL_INVALID_OPERATION est générée si un nom d'objet mémoire tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que les données seraient empaquetées dans l'objet mémoire tampon de telle sorte que les écritures mémoire requises dépasseraient la taille du magasin de données.

GL_INVALID_OPERATION est générée si un nom d'objet mémoire tampon non nul est lié à la cible GL_PIXEL_PACK_BUFFER et que pixels n'est pas un multiple exact du nombre d'octets nécessaires pour stocker en mémoire une donnée indiquée par type.

GL_INVALID_OPERATION est générée par glGetTextureImage et glGetnTexImage si la taille du tampon requise pour stocker les données demandées est supérieure à bufSize.
