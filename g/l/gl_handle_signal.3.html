N

MODE D'E/S

SERVEUR

En mode d'E/S serveur non bloquant, l'application doit disposer d'une boucle d'événements qui appelle gl_get_line() chaque fois que le descripteur de fichier du terminal peut effectuer le type d'E/S que gl_get_line() attend. Pour déterminer quel type d'E/S gl_get_line() attend, l' application appelle la fonction gl_pending_io()

. 
  GlPendingIO gl_pending_io(GetLine *gl)
;

La valeur de retour de cette fonction est l'une des deux valeurs énumérées

suivantes. 
  GLP_READ    -  gl_get_line() attend d'écrire un
                 caractère sur le terminal.
  GLP_WRITE   -  gl_get_line() attend de lire un
                 caractère depuis le
clavier.

Si l'application utilise soit l'appel système select() soit poll() pour surveiller les E/S sur un groupe de descripteurs de fichiers, elle devrait appeler la fonction gl_pending_io() avant chaque appel à ces fonctions pour voir dans quelle direction d'E/S elle devrait leur dire de surveiller, et configurer leurs arguments en conséquence. Dans le cas de l'appel système select(), cela signifie utiliser la macro FD_SET() pour ajouter le descripteur de fichier du terminal soit à l'ensemble des descripteurs de fichiers à surveiller pour la lisibilité, soit à l'ensemble à surveiller pour

l'écriture.

Comme en mode d'E/S normal, la valeur de retour de gl_get_line() est soit un pointeur vers une ligne d'entrée terminée, soit NULL. Cependant, alors qu'en mode d'E/S normal, une valeur de retour NULL signifie toujours qu'une erreur s'est produite, en mode serveur non bloquant, NULL est également retourné lorsque gl_get_line() ne peut ni lire ni écrire sur le terminal sans se bloquer. Ainsi, en mode serveur non bloquant, afin de déterminer si une valeur de retour NULL signifie qu'une erreur s'est produite ou non, il est nécessaire d'appeler la fonction gl_return_status(). Si cette fonction retourne la valeur énumérée GLR_BLOCKED, comme documenté dans la page man gl_get_line(3), cela signifie que gl_get_line() est en attente d'E/S, et qu'aucune erreur ne s'est

produite.

Lorsque gl_get_line() retourne NULL et que gl_return_status() indique que cela est dû à des E/S de terminal bloquées, l'application devrait appeler gl_get_line() à nouveau lorsque le type d'E/S signalé par gl_pending_io() devient possible. Les arguments prompt, start_line et start_pos de gl_get_line() seront ignorés lors de ces appels. Si vous devez changer l'invite de la ligne en cours d'édition, vous pouvez appeler la fonction gl_replace_prompt() (documentée dans la page man gl_get_line(3)) entre les appels à gl_get_line(). gl_get_line().

RENDRE LE

TERMINAL

Une complication unique au mode serveur non bloquant est qu'il nécessite que le terminal soit laissé en mode brut entre les appels à gl_get_line(). Si ce n'était pas le cas, la boucle d'événements externe ne pourrait pas détecter les appuis de touches individuels, et l'édition de ligne de base implémentée par le pilote du terminal entrerait en conflit avec l'édition fournie par gl_get_line(). Cela signifie que chaque fois que le terminal doit être utilisé pour autre chose que la saisie d'une nouvelle ligne d'entrée avec gl_get_line(), il doit être restauré à un état utilisable. En particulier, chaque fois que le processus est suspendu ou terminé, le terminal doit être rendu à un état normal. Si cela n'est pas fait, alors selon les caractéristiques du shell utilisé pour invoquer le programme, l'utilisateur peut se retrouver avec un terminal bloqué. À cette fin, la fonction gl_normal_io() est fournie pour basculer le terminal vers l'état dans lequel il se trouvait lorsque le mode brut a été établi pour la dernière

fois. 
  int gl_normal_io(GetLine *gl)
;

Ce que fait cette fonction, c'est d'abord vider toute sortie en attente vers le terminal, puis de déplacer le curseur au début de la ligne du terminal qui suit la fin de la ligne d'entrée saisie incomplètement. À ce stade, il est sûr de suspendre ou de terminer le processus, et il est sûr pour l'application de lire et d'écrire sur le terminal. Pour reprendre la saisie de la ligne d'entrée, l'application devrait appeler la fonction gl_raw_io()

. 
  int gl_raw_io(GetLine *gl)
;

Cette fonction démarre une nouvelle ligne, réaffiche la ligne d'entrée partiellement terminée (le cas échéant), restaure la position du curseur dans cette ligne à l'endroit où elle était lorsque gl_normal_io() a été appelée, puis bascule à nouveau vers le mode terminal brut non bloquant, prêt à continuer la saisie de la ligne d'entrée lorsque gl_get_line() sera appelée à

nouveau.

Notez qu'en mode serveur non bloquant, si gl_get_line() est appelée après un appel à gl_normal_io(), sans appel intermédiaire à gl_raw_io(), gl_get_line() appellera gl_raw_mode() elle-même, et le terminal restera dans ce mode lorsque gl_get_line()

reto
urnera.

SIGNAUX

Dans la section précédente, il a été souligné que, en mode serveur non bloquant, le terminal doit être restauré à un état raisonnable chaque fois qu'un signal est reçu qui suspend ou termine le processus. En mode d'E/S normal, cela est fait pour vous par gl_get_line(), mais en mode serveur non bloquant, puisque le terminal est laissé en mode brut entre les appels à gl_get_line(), cette gestion des signaux doit être faite par l'application. Comme il existe de nombreux signaux qui peuvent suspendre ou terminer un processus, ainsi que d'autres signaux importants pour gl_get_line(), tels que le signal SIGWINCH, qui lui indique quand la taille du terminal a changé, la fonction gl_tty_signals() est fournie pour installer des gestionnaires de signaux pour tous les signaux

pertinents.
