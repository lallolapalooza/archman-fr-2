DESCRIPTION glUniform modifie la valeur d'une variable uniforme ou d'un tableau de variables uniformes. L'emplacement de la variable uniforme à modifier est spécifié par location, qu

i doit

être une valeur retournée par glGetUniformLocation(). glUniform opère sur l'objet programme qui a été rendu partie de l'état courant en appelant glUseProgram(). Les commandes glUniform{1|2|3|4}{f|i|ui} sont utilisées pour changer la valeur de la variable uniforme spécifiée par 1 pour float, int, unsigned int, bool ; 2 pour vec2, ivec2, uvec2, bvec2, etc.). Le suffixe f indique que des valeurs en virgule flottante sont passées ; le suffixe i indique que des valeurs entières sont passées ; le suffixe ui indique que des valeurs entières non signées sont passées, et ce type doit également correspondre au type de données de la variable uniforme spécifiée. Les variantes i de cette fonction doivent être utilisées pour fournir des valeurs pour des variables uniformes définies as int, ivec2, ivec3, ivec4, ou des tableaux de ceux-ci. Les variantes ui de cette fonction doivent être utilisées pour fournir des valeurs pour les variables uniformes définies comme unsigned int, uvec2, uvec3, uvec4, ou des tableaux de celles-ci. Les variantes f doivent être utilisées pour fournir des valeurs pour les variables uniformes de type float, vec2, vec3, vec4, ou des tableaux de celles-ci. Les variantes i, ui ou f peuvent être utilisées pour fournir des valeurs pour les variables uniformes de type bool, bvec2, bvec3, bvec4, ou des tableaux de celles-ci. La variable uniforme sera mise à false si la valeur d'entrée est 0 ou 0.0f, et elle sera mise à true sinon.

Toutes les variables uniformes actives définies dans un objet de programme sont initialisées à 0 lors de la liaison réussie de l'objet de programme. Elles conservent les valeurs qui leur sont assignées par un appel à glUniform jusqu'à la prochaine opération de liaison réussie sur l'objet de programme, moment auquel elles sont à nouveau initialisées à 0.

Les commandes glUniform{1|2|3|4}{f|i|ui}v peuvent être utilisées pour modifier une seule variable uniforme ou un tableau de variables uniformes. Ces commandes passent un nombre et un pointeur vers les valeurs à charger dans une variable uniforme ou un tableau de variables uniformes. Un nombre de 1 doit être utilisé si la valeur d'une seule variable uniforme est modifiée, et un nombre de 1 ou plus peut être utilisé pour modifier un tableau entier ou une partie d'un tableau. Lors du chargement de n éléments à partir d'une position arbitraire m dans un tableau de variables uniformes, les éléments m + n - 1 du tableau seront remplacés par les nouvelles valeurs. Si m + n - 1 est supérieur à la taille du tableau de variables uniformes, les valeurs pour tous les éléments du tableau au-delà de la fin du tableau seront ignorées. Le nombre spécifié dans le nom de la commande indique le nombre de composantes pour chaque élément dans value, et il doit correspondre au nombre de composantes du type de données de la variable uniforme spécifiée (par exemple, 1 pour float, int, bool ; 2 pour vec2, ivec2, bvec2, etc.). Le type de données spécifié dans le nom de la commande doit correspondre au type de données de la variable uniforme spécifiée, comme décrit précédemment pour glUniform{1|2|3|4}{f|i|ui}.

Pour les tableaux de variables uniformes, chaque élément du tableau est considéré comme étant du type indiqué dans le nom de la commande (par exemple, glUniform3f ou glUniform3fv peut être utilisé pour charger un tableau de variables uniformes de type vec3). Le nombre d'éléments du tableau de variables uniformes à modifier est spécifié par count

Les commandes glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv sont utilisées pour modifier une matrice ou un tableau de matrices. Les nombres dans le nom de la commande sont interprétés comme la dimensionnalité de la matrice. Le nombre 2 indique une matrice 2 × 2 (soit 4 valeurs), le nombre 3 indique une matrice 3 × 3 (soit 9 valeurs) et le nombre 4 indique une matrice 4 × 4 (soit 16 valeurs). La dimensionnalité non carrée de la matrice est explicite, le premier nombre représentant le nombre de colonnes et le second le nombre de lignes. Par exemple, 2x4 indique une matrice 2 × 4 avec 2 colonnes et 4 lignes (soit 8 valeurs). Si transpose est GL_FALSE, chaque matrice est supposée être fournie en ordre par colonne (column major). Si transpose est GL_TRUE, chaque matrice est supposée être fournie en ordre par ligne (row major). L'argument count indique le nombre de matrices à passer. Un nombre de 1 doit être utilisé si la valeur d'une seule matrice est modifiée, et un nombre supérieur à 1 peut être utilisé pour modifier un tableau de matrices.

NOTES

glUniform1i et glUniform1iv sont les deux seules fonctions qui peuvent être utilisées pour charger des variables uniformes définies comme des types sampler. Charger des samplers avec toute autre fonction entraînera une erreur GL_INVALID_OPERATION.

Si count est supérieur à 1 et que la variable uniforme indiquée n'est pas un tableau, une erreur GL_INVALID_OPERATION est générée et la variable uniforme spécifiée restera inchangée.

À l'exception des exceptions précédentes, si le type et la taille de la variable uniforme tels que définis dans le shader ne correspondent pas au type et à la taille spécifiés dans le nom de la commande utilisée pour charger sa valeur, une erreur GL_INVALID_OPERATION sera générée et la variable uniforme spécifiée restera inchangée.

Si location est une valeur autre que -1 et qu'elle ne représente pas un emplacement de variable uniforme valide dans l'objet de programme actuel, une erreur sera générée et aucune modification ne sera apportée au stockage de la variable uniforme de l'objet de programme actuel. Si location est égal à -1, les données fournies seront silencieusement ignorées et la variable uniforme spécifiée ne sera pas modifiée.

ERREURS

GL_INVALID_OPERATION est générée s'il n'y a pas d'objet de programme courant.

GL_INVALID_OPERATION est générée si la taille de la variable uniforme déclarée dans le shader ne correspond pas à la taille indiquée par la commande glUniform.

GL_INVALID_OPERATION est générée si l'une des variantes entier signé ou non signé de cette fonction est utilisée pour charger une variable uniforme de type float, vec2, vec3, vec4, ou un tableau de ceux-ci, ou si l'une des variantes à virgule flottante de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est générée si l'une des variantes entier signé de cette fonction est utilisée pour charger une variable uniforme de type unsigned int, uvec2, uvec3, uvec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est générée si l'une des variantes entier non signé de cette fonction est utilisée pour charger une variable uniforme de type int, ivec2, ivec3, ivec4, ou un tableau de ceux-ci.

GL_INVALID_OPERATION est générée si location est un emplacement uniforme invalide pour l'objet de programme actuel et que location n'est pas égal à -1.

GL_INVALID_VALUE est générée si count est inférieur à 0.

GL_INVALID_OPERATION est générée si count est supérieur à 1 et que la variable uniforme indiquée n'est pas une variable de tableau.

GL_INVALID_OPERATION est générée si un sampler est chargé en utilisant une commande autre que glUniform1i et glUniform1iv.
