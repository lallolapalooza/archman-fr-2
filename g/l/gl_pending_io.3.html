MODE D'E/S

SERVEUR

En mode d'E/S serveur non bloquant, l'application doit disposer d'une boucle d'événements qui appelle gl_get_line() chaque fois que le descripteur de fichier du terminal peut effectuer le type d'E/S pour lequel gl_get_line() attend. Pour déterminer le type d'E/S pour lequel gl_get_line() attend, l'application appelle la fonction gl_pending_io()

. 
  GlPendingIO gl_pending_io(GetLine *gl)
;

La valeur de retour de cette fonction est l'une des deux valeurs énumérées

suivantes. 
  GLP_READ    -  gl_get_line() attend d'écrire un
                 caractère sur le terminal.
  GLP_WRITE   -  gl_get_line() attend de lire un
                 caractère depuis le
clavier.

Si l'application utilise soit l'appel système select() ou poll() pour surveiller les E/S sur un groupe de descripteurs de fichier, elle doit appeler la fonction gl_pending_io() avant chaque appel à ces fonctions pour voir dans quelle direction d'E/S elle doit leur demander de surveiller, et configurer leurs arguments en conséquence. Dans le cas de l'appel système select(), cela signifie utiliser la macro FD_SET() pour ajouter le descripteur de fichier du terminal soit à l'ensemble des descripteurs de fichier à surveiller pour la lisibilité, soit à l'ensemble à surveiller pour

l'écritabilité.

Comme en mode d'E/S normal, la valeur de retour de gl_get_line() est soit un pointeur vers une ligne d'entrée terminée, soit NULL. Cependant, alors qu'en mode d'E/S normal, une valeur de retour NULL signifie toujours qu'une erreur s'est produite, en mode serveur non bloquant, NULL est également retourné lorsque gl_get_line() ne peut ni lire ni écrire sur le terminal sans se bloquer. Ainsi, en mode serveur non bloquant, afin de déterminer si une valeur de retour NULL signifie qu'une erreur s'est produite ou non, il est nécessaire d'appeler la fonction gl_return_status(). Si cette fonction retourne la valeur énumérée GLR_BLOCKED, comme documenté dans la page man gl_get_line(3), cela signifie que gl_get_line() attend des E/S et qu'aucune erreur ne s'est

produite.

Lorsque gl_get_line() retourne NULL et que gl_return_status() indique que cela est dû à des E/S de terminal bloquées, l'application doit appeler gl_get_line() à nouveau lorsque le type d'E/S rapporté par gl_pending_io() devient possible. Les arguments prompt, start_line et start_pos de gl_get_line() seront ignorés lors de ces appels. Si vous devez changer l'invite de la ligne en cours d'édition, vous pouvez appeler la fonction gl_replace_prompt() (documentée dans la page man gl_get_line(3)) entre les appels à gl_get_

lin
e().

RENDRE LE

TERMINAL

Une complication propre au mode serveur non bloquant est qu'il nécessite que le terminal reste en mode brut entre les appels à gl_get_line(). Si ce n'était pas le cas, la boucle d'événements externe ne pourrait pas détecter les appuis de touches individuels, et l'édition de ligne de base implémentée par le pilote de terminal entrerait en conflit avec l'édition fournie par gl_get_line(). Cela signifie que chaque fois que le terminal doit être utilisé pour autre chose que la saisie d'une nouvelle ligne d'entrée avec gl_get_line(), il doit être restauré à un état utilisable. En particulier, chaque fois que le processus est suspendu ou terminé, le terminal doit être rendu à un état normal. Si cela n'est pas fait, alors selon les caractéristiques du shell utilisé pour invoquer le programme, l'utilisateur peut se retrouver avec un terminal bloqué. À cette fin, la fonction gl_normal_io() est fournie pour ramener le terminal à l'état dans lequel il se trouvait lorsque le mode brut a été établi pour la dernière

fois. 
  int gl_normal_io(GetLine *gl)
;

Ce que fait cette fonction, c'est d'abord vider toute sortie en attente vers le terminal, puis déplacer le curseur au début de la ligne du terminal qui suit la fin de la ligne d'entrée incomplètement saisie. À ce stade, il est sûr de suspendre ou de terminer le processus, et il est sûr pour l'application de lire et d'écrire sur le terminal. Pour reprendre la saisie de la ligne d'entrée, l'application doit appeler la fonction gl_raw_io()

. 
  int gl_raw_io(GetLine *gl)
;

Cette fonction démarre une nouvelle ligne, réaffiche la ligne d'entrée partiellement terminée (le cas échéant), restaure la position du curseur dans cette ligne à l'endroit où elle se trouvait lorsque gl_normal_io() a été appelée, puis repasse en mode terminal brut non bloquant prêt à continuer la saisie de la ligne d'entrée lorsque gl_get_line() sera appelée à

nouveau.

Notez qu'en mode serveur non bloquant, si gl_get_line() est appelée après un appel à gl_normal_io(), sans appel intermédiaire à gl_raw_io(), gl_get_line() appellera gl_raw_mode() elle-même, et le terminal restera dans ce mode lorsque gl_get_line()

reto
urnera.

GESTION DES

SIGNAUX

Dans la section précédente, il a été souligné qu'en mode serveur non bloquant, le terminal doit être restauré à un état raisonnable chaque fois qu'un signal est reçu qui suspend ou termine le processus. En mode d'E/S normal, cela est fait pour vous par gl_get_line(), mais en mode serveur non bloquant, puisque le terminal est laissé en mode brut entre les appels à gl_get_line(), cette gestion des signaux doit être faite par l'application. Puisqu'il y a de nombreux signaux qui peuvent suspendre ou terminer un processus, ainsi que d'autres signaux importants pour gl_get_line(), tels que le signal SIGWINCH, qui lui indique quand la taille du terminal a changé, la fonction gl_tty_signals() est fournie pour installer des gestionnaires de signaux pour tous les signaux

pertinents. 
  int gl_tty_signals(void (*term_handler)(int),
                     void (*susp_handler)(int),
                     void (*cont_handler)(int),
                     void (*size_handler)(int))
;

suivants. 
  term_handler  -  C'est le gestionnaire de signal à utiliser
                   pour intercepter les signaux qui par défaut
                   terminent tout processus qui les reçoit
                   (ex. SIGINT ou SIGTERM).
  susp_handler  -  C'est le gestionnaire de signal à utiliser

                   suspendent tout processus qui les reçoit

                   par l'utilisateur (ex. SIGWINCH).

PAR GL_GET_LINE Puisqu'on attend de l'application qu'elle traite les signaux en mode serveur non bloquant, gl_get_line() n'essaie pas de dupliquer cela lorsqu'il est appelé. ABORTER L'ENTRÉE DE

LIGNE

Souvent, plutôt que de laisser le processus se terminer, les applications répondent au signal d'interruption utilisateur SIGINT en interrompant la ligne d'entrée en cours. La manière de faire cela en mode d'E/S serveur non bloquant est de ne pas appeler gl_handle_signal() lorsque ce signal est intercepté, mais d'appeler plutôt gl_abandon_l

ine(). 
  void gl_abandon_line(GetLine *gl)
;

Cette fonction fait en sorte que lorsque gl_get_line() est appelé à nouveau, il vide d'abord toute sortie en attente vers le terminal, puis abandonne la ligne d'entrée en c

ours, affiche un nouveau invite sur la ligne suivante, et enfin c
ommence à accepter l'entrée d'une nouvelle ligne de l'utilisateur.

FONCTIONS SÛRES POUR LES

SIGNAUX

À condition que certaines règles soient respectées, les fonctions suivantes ont été écrites pour pouvoir être appelées en toute sécurité depuis des gestionnaires de signaux. Les autres fonctions de cette bibliothèque ne doivent pas être appelées depuis des gestionnaires de

signaux. 
  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line(
)

Pour que cela soit vrai, tous les gestionnaires de signaux qui appellent ces fonctions doivent être enregistrés de telle manière qu'une seule instance de l'un d'entre eux puisse s'exécuter à la fois. La manière de faire cela est d'utiliser la fonction POSIX sigaction() pour enregistrer tous les gestionnaires de signaux, et lors de cela, d'utiliser le membre sa_mask de la structure sigaction correspondante, pour indiquer que tous les signaux dont les gestionnaires invoquent les fonctions ci-dessus doivent être bloqués lorsque le signal en cours est traité. Cela empêche deux gestionnaires de signaux d'opérer sur un objet GetLine en même

temps.

Pour empêcher les gestionnaires de signaux d'accéder à un objet GetLine pendant que gl_get_line() ou l'une de ses fonctions publiques associées y opèrent, toutes les fonctions publiques associées à gl_get_line(), y compris gl_get_line() lui-même, bloquent temporairement la délivrance des signaux lorsqu'ils accèdent aux objets GetLine. Attention, les seuls signaux qu'ils bloquent sont les signaux que gl_get_line() est actuellement configuré pour intercepter, alors assurez-vous que si vous appelez l'une des fonctions ci-dessus depuis des gestionnaires de signaux, les signaux auxquels ces gestionnaires sont assignés sont configurés pour être interceptés par gl_get_line() (voir gl_trap_s

ignal
()).

UTILISER DES DÉLAIS D'EXPIRATION POUR

L'INTERROGATION

Si au lieu d'utiliser select() ou poll() pour attendre l'E/S, votre application a simplement besoin de sortir de gl_get_line() périodiquement pour faire autre chose brièvement avant de retourner accepter l'entrée de l'utilisateur, cela peut être fait en mode serveur non bloquant en utilisant la fonction gl_inactivity_timeout() (voir gl_get_line(3)), pour spécifier qu'une fonction de rappel qui retourne GLTO_CONTINUE doit être appelée chaque fois que gl_get_line() attend l'E/S depuis plus d'un temps

spécifié.

Lorsque ce rappel est déclenché, gl_get_line() retournera NULL, et un appel suivant à gl_return_status() retournera GLR_BLOCKED

.

Attention, gl_get_line() ne retournera pas tant que l'utilisateur n'a pas appuyé sur une touche pendant l'intervalle spécifié, donc si l'intervalle est long, et que l'utilisateur continue de taper, gl_get_line() pourrait ne pas retourner pendant un moment. En d'autres t

ermes, il n'y a aucune garantie qu'il
retournera dans le temps spécifié.
