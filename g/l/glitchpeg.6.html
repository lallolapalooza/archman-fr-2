NOM

glitchpeg - économiseur d'écran d'image "glitchée".

SYNTAXE

glitchpeg [--display hôte:écran.dallescreen] [--visual visuel] [--window] [--root] [--window-id numéro] [--delay numéro] [--duration numéro] [--count numéro]

DESCRIPTION

Charge une image, la corrompt, puis affiche la version corrompue, plusieurs fois par seconde. Après un certain temps, trouve une nouvelle image à corrompre.

Il "glitche" l'image en modifiant des octets aléatoires dans le fichier image compressé avant de le décompresser. Cela crée des effets visuels intéressants sur les fichiers JPEG, mais ne fonctionne pas bien sur les fichiers PNG, car les PNG contiennent des sommes de contrôle qui détectent la corruption simple.

OPTIONS

--visual visuel
Spécifie quel visuel utiliser. Les valeurs légales sont le nom d'une classe de visuel, ou le numéro d'identification (décimal ou hexadécimal) d'un visuel spécifique.
--window
Dessine dans une fenêtre nouvellement créée. C'est le comportement par défaut.
--root
Dessine sur la fenêtre racine.
--window-id numéro
Dessine sur la fenêtre spécifiée.
--delay numéro
Délai par image, en microsecondes. Par défaut : 30000 (0.03 seconde).
--duration numéro
Nombre de secondes avant de charger une nouvelle image. Par défaut : 120.
--count numéro
Nombre de "glitches" à introduire par itération. Par défaut : 400.

ENVIRONNEMENT

DISPLAY
pour obtenir le nom d'hôte et le numéro d'écran par défaut.
XENVIRONMENT
pour obtenir le nom d'un fichier de ressources qui remplace les ressources globales stockées dans la propriété RESOURCE_MANAGER.
XSCREENSAVER_WINDOW
L'identifiant de la fenêtre à utiliser avec --root.

SÉCURITÉ

Étant donné que ce programme injecte intentionnellement des données invalides dans les bibliothèques de décodage d'images de votre système d'exploitation, il est possible qu'il plante suite à ces données corrompues.

Cela ne devrait pas être possible, mais ça pourrait l'être.

Veuillez noter que si cela se produit, cela indique un grave bug de sécurité dans les bibliothèques d'images de votre système ! Cela signifie probablement que vos bibliothèques sont vulnérables aux attaques de dépassement de tampon ou similaires, qui peuvent conduire à une exécution de code à distance. Vous devriez signaler ce bug aux mainteneurs de ces bibliothèques d'images.

Dans le contexte de xscreensaver, lorsqu'il est configuré pour charger uniquement des fichiers image locaux, cela ne devrait pas constituer une préoccupation de sécurité directe : le plantage de cet économiseur d'écran n'affectera pas le démon xscreensaver et ne déverrouillera pas votre écran.
