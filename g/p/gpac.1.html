SYNOPSI

S

gpac [options]FILTRE[LIAISON]FILTRE[...]
gpac est l'outil en ligne de commande de GPAC pour configurer et exécuter des chaînes de

filtres.

FILTRE : une déclaration de filtre unique (par ex. -i file, -o dump, inspect, ...), voir gpac -h doc.
[LIAISON] : une instruction de liaison (par ex. @, @2, @2#StreamType=Visual, ...), voir gpac -h doc.
[options] : une ou plusieurs chaînes d'options, chacune commençant par le caractère -.
- une option utilisant un seul - indique une option de gpac (voir gpac -hx) ou de libgpac (voir gpac -hx core)
- une option utilisant -- indique une option globale de filtre ou de méta-filtre (par ex. FFMPEG) option, par ex. --block_size=1000 ou --profile=Baseline (voir gpac -h

doc)

L'ordre de déclaration des filtres peut influencer le résolveur de liaisons qui essaiera de lier dans l'ordre de déclaration. La plupart du temps, pour des graphes simples, cela n'a aucun impact. Cependant, pour des graphes complexes sans déclarations de liaison, cela peut conduire à des résultats différents.
Les options ne nécessitent aucun ordre particulier et peuvent être présentes n'importe où, y compris entre les instructions de liaison ou les déclarations de filtres.
Les valeurs booléennes n'ont pas besoin de valeur spécifiée. Les autres types doivent être formatés en opt=val, sauf pour les options .I -i, -src, .I -o, -dst et .I

-h.

La session peut être interrompue à tout moment avec ctrl+c, qui peut aussi être utilisé pour basculer le rapport

global.

Utilisation des Alias

La ligne de commande gpac peut devenir assez complexe lorsque de nombreuses sources ou filtres sont utilisés. Afin de simplifier cela, un système d'alias est fourni.

Pour attribuer un alias, utilisez la syntaxe gpac -alias="NOM VALEUR".
* `NOM` : doit être une chaîne unique, sans espace.
* `VALEUR` : la liste des arguments que cet alias remplace. S'il n'est pas défini, l'alias est détruit.

Lors de l'analyse des arguments, l'alias sera remplacé par sa valeur.
Exemple
gpac -alias="sortie aout vout"

Ceci permet plus tard la lecture audio et vidéo en utilisant gpac -i src.mp4 sortie

Les alias peuvent utiliser les arguments de la ligne de commande. Les syntaxes autorisées sont :
* `@{a}` : remplacé par la valeur de l'argument d'index a après l'alias.
* `@{a,b}` : remplacé par la valeur des arguments d'index a et b.
* `@{a:b}` : remplacé par la valeur des arguments entre l'index a et b.
* `@{-a,b}` : remplacé par la valeur des arguments d'index a et b, en insérant un séparateur de liste (virgule par défaut) entre eux.
* `@{-a:b}` : remplacé par la valeur des arguments entre l'index a et b, en insérant un séparateur de liste (virgule par défaut) entre eux.
* `@{+a,b}` : clone le mot parent dans l'alias pour a et b, en remplaçant ce motif dans chaque clone par l'argument correspondant.
* `@{+a:b}` : clone le mot parent dans l'alias pour chaque argument entre l'index a et b, en remplaçant ce motif dans chaque clone par l'argument correspondant.

L'index spécifié peut être :
* index avant : un entier strictement positif, 1 étant le premier argument après l'alias.
* index arrière : la valeur 'n' (ou 'N') pour indiquer le dernier argument sur la ligne de commande. Ceci peut être suivi de -x pour remonter les arguments (par exemple, @{n-1} est l'avant-dernier argument).

Avant de résoudre les alias, tous les arguments des options sont déplacés au début de la ligne de commande. Cela implique que les arguments des alias ne peuvent pas être des options.
Les arguments non utilisés par des alias sont conservés sur la ligne de commande, les autres sont supprimés.

Exemple
-alias="foo src=@{N} dst=test.mp4"

La commande gpac foo f1 f2 se développe en gpac src=f2 dst=test.mp4 f1
Exemple
-alias="liste: inspect src=@{+:N}"

La commande gpac liste f1 f2 f3 se développe en gpac inspect src=f1 src=f2 src=f3
Exemple
-alias="liste inspect src=@{+2:N}"

La commande gpac liste f1 f2 f3 se développe en gpac inspect src=f2 src=f3 f1
Exemple
-alias="plist aout vout flist:srcs=@{-,N}"

La commande gpac plist f1 f2 f3 se développe en gpac aout vout flist:srcs="f1,f2,f3"

La documentation des alias peut être définie en utilisant gpac -aliasdoc="NOM VALEUR", où NOM est le nom de l'alias et VALEUR la documentation.
La documentation des alias apparaîtra alors dans l'aide de gpac.

Identifiants Utilisateur

Certains serveurs dans GPAC peuvent utiliser l'authentification basée sur l'utilisateur et le groupe.
Les informations sont stockées par défaut dans le fichier users.cfg situé dans le répertoire de profil GPAC.
Le fichier peut être écrasé en utilisant l'option .I -users.

Par défaut, ce fichier n'existe pas tant qu'au moins un utilisateur n'a pas été configuré.

L'option .I creds permet d'inspecter ou de modifier les informations des utilisateurs et des groupes. La syntaxe pour la valeur de l'option est :
* `show` ou aucune valeur : affiche le fichier users.cfg.
* `reset` : supprime le fichier users.cfg (c'est-à-dire supprime tous les utilisateurs et groupes).
* `NOM` : affiche les informations de l'utilisateur NOM.
* `+NOM` : ajoute l'utilisateur NOM.
* `+NOM:I1=V1[,I2=V2]` : définit l'information I1 avec la valeur V1 pour l'utilisateur NOM. Le nom d'information password réinitialise le mot de passe sans invite.
* `-NOM` : supprime l'utilisateur NOM.
* `_NOM` : force le changement de mot de passe de l'utilisateur NOM.
* `@NOM` : affiche les informations du groupe NOM.
* `@+NOM[:u1[,u2]]` : ajoute le groupe NOM s'il n'existe pas et ajoute les spécifications

fied users to group
* `@-NAME:u1[,u2]`: supprime les utilisateurs spécifiés du groupe NAME
* `@-NAME`: supprime le groupe

NAME

Par défaut, tous les utilisateurs ajoutés sont membres du groupe users.
Les mots de passe ne sont pas stockés, seul un hachage SHA256 est

stocké.

Les serveurs utilisant des règles d'authentification peuvent utiliser un fichier de configuration au lieu d'un nom de répertoire.
Ce fichier de configuration est organisé en sections, le nom de chaque section décrivant un répertoire.
Exemple
[somedir]
ru=foo
rg=ba

r

Les clés suivantes sont définies par répertoire, mais peuvent être ignorées par le serveur selon son mode de fonctionnement :
* ru : liste séparée par des virgules des noms d'utilisateurs ayant un accès en lecture au répertoire
* rg : liste séparée par des virgules des noms de groupes ayant un accès en lecture au répertoire
* wu : liste séparée par des virgules des noms d'utilisateurs ayant un accès en écriture au répertoire
* wg : liste séparée par des virgules des noms de groupes ayant un accès en écriture au répertoire
* mcast : liste séparée par des virgules des noms d'utilisateurs ayant le droit de créer des flux multicast (serveur RTSP uniquement)
* filters : liste séparée par des virgules des noms de filtres pour lesquels le répertoire est valide. Si non trouvé ou all, s'applique à tous les

filtres

Les droits peuvent être configurés sur des sous-répertoires en ajoutant des sections pour les répertoires souhaités.
Exemple
[d1]
rg=bar
[d1/d2]
ru=fo

o

Avec cette configuration :
- le répertoire d1 sera lisible par tous les membres du groupe bar
- le répertoire d1/d2 ne sera lisible que par l'utilisateur

foo

harge que le schéma d'authentification HTTP Basic
et devraient être exécutés de préférence via TLS.

Fichier de

configuration

GPAC utilise un fichier de configuration pour modifier les options par défaut de libgpac et des filtres. Ce fichier est appelé GPAC.cfg et est situé :
- sur les plateformes Windows, dans C:UsersODatar dans C:Program FilesGPAC.
- sur les plateformes iOS, dans un dossier .gpac du répertoire de stockage de l'application.
- sur les plateformes Android, dans /sdcard/GPAC/ si ce répertoire existe, sinon dans /data/data/io.gpac.gpac/GPAC.
- sur les autres plateformes, dans un $HOME/.

gpac/.

Les applications dans GPAC peuvent également spécifier un fichier de configuration différent via l'option .I -p profile. EX gpac -p=foo []
Cela chargera la configuration depuis $HOME/.gpac/foo/GPAC.cfg, en le créant si nécessaire.
Le nom réservé 0 est utilisé pour désactiver l'écriture du fichier de

configuration.

Le fichier de configuration est structuré en sections, chacune composée d'une ou plusieurs clés :
- la section foo est déclarée comme [foo]
- la clé bar avec la valeur N est déclarée comme bar=N0 La valeur de la clé N n'est pas interprétée et est toujours traitée comme du texte

ASCII.

Par défaut, le fichier de configuration ne contient que quelques options et répertoires spécifiques au système. Il est possible de sérialiser l'ensemble des options dans le fichier de configuration, en utilisant .I -wc .I -wf.
Cela devrait être évité car la taille du fichier de configuration résultant sera assez grande, entraînant donc une utilisation de la mémoire plus importante pour les applications.
Les options spécifiées dans le fichier de configuration peuvent être remplacées par les valeurs du fichier restrict.cfg situé dans le répertoire système de partage de GPAC (par ex. /usr/share/gpac ou C:Program FilesGPAC), si présent ; cela permet d'imposer des valeurs de configuration à l'échelle du système.
Remarque : les méthodes décrites dans cette section s'app

liquent à toute application dans GPAC transférant ses
arguments à libgpac. C'est le cas de gpac et MP4Box.

Options globales des

filtres

Il est possible de spécifier des options globales à plusieurs filtres en utilisant --OPTNAME=VAL. Les options globales ne remplacent pas les options des filtres mais prennent priorité sur les options chargées depuis le fichier de configuration.
Cela définira l'option OPTNAME, lorsqu'elle est présente, à VAL dans tout filtre chargé.
Exemple
--buffer=100 -i file vout

aout

Cela est équivalent à spécifier vout:buffer=100 aout:buffer=100.
Exemple
--buffer=100 -i file vout aout:

buffer=10

Cela est équivalent à spécifier vout:buffer=100 aout:buffer=10.
Attention : cette syntaxe ne s'applique qu'aux options de filtres régulières. Elle ne peut pas être utilisée avec les raccourcis intégrés (gfreg, enc, ...).
Les options de méta-filtres peuvent être définies de la même manière en utilisant la syntaxe --OPT_NAME=VAL.
Exemple
--profile=Baseline -i file.cmp -o dump.

264

Cela est équivalent à spécifier -o dump.264:profile=Baseline

.

Pour les deux syntaxes, il est possible de spécifier le nom du registre de filtre de l'option, en utilisant --FNAME:OPTNAME=VAL ou --FNAME@OPTNAME=VAL.
Dans ce cas, l'option ne sera définie que pour les filtres qui sont des instances du registre FNAME. Cela est utilisé lorsque plusieurs registres utilisent les mêmes noms d'options.
Exemple
--flist@timescale=100 -i plist1 -i plist2 -o live.

mpd

Cela définira l'option timescale su

r les filtres de listes de lecture
mais pas sur le filtre dasher.

Aperçu

Les filtres sont des unités de traitement configurables qui consomment et produisent des paquets de données. Ces paquets sont transportés entre les filtres via un canal de données appelé PID. Un PID est chargé d'allouer/suivre les paquets de données et de les transmettre au(x) filtre(s) de destination. Un PID de sortie de filtre peut être connecté à zéro ou plusieurs filtres. Cette diffusion en éventail est gérée en interne par GPAC (il n'existe pas de filtre tee dans GPAC).
Note : Lorsqu'un PID ne peut être connecté à aucun filtre, un avertissement est généré et tous les paquets distribués sur ce PID seront détruits. La session peut cependant toujours s'exécuter, sauf si .I -full-link est défini.

Chaque PID de sortie transporte un ensemble de propriétés décrivant les données qu'il livre (par exemple, largeur, hauteur, codec, ...). Les propriétés peuvent être intégrées (voir gpac -h props) ou définies par l'utilisateur. Chaque PID suit les modifications de ses propriétés et déclenche la reconfiguration des filtres lors du traitement des paquets. Cela permet à la chaîne de filtres d'être reconfigurée à l'exécution, en rechargeant potentiellement une partie de la chaîne (par exemple, décharger un décodeur vidéo lors du passage de sources compressées à des sources non compressées).

Chaque filtre expose un ensemble d'arguments pour se configurer, en utilisant des types de propriétés et des valeurs décrits sous forme de chaînes formatées avec des séparateurs. Cette aide est fournie avec les ensembles de séparateurs par défaut :=#,@ pour spécifier les filtres, les propriétés et les options. Utilisez .I -seps pour les modifier.

Format des propriétés et des options de filtre

* booléen : formaté comme yes,true,1 ou no,false,0
* énumération (pour les arguments de filtre uniquement) : doit utiliser la syntaxe donnée dans la description de l'argument, sinon la valeur 0

(premier dans l'énumération) est supposé.
* 1-dimension (nombres, flottants, entiers...) : formaté comme valeur[unité], où l'unité peut être k,K (x 1000) ou m,M (x 1000000) ou g,G (x 1000000000) ou sec (x 1000) ou min (x 60000). +I signifie la valeur max float/int/uint, -I la valeur min float/int/uint.
* fraction : formatée comme num/den ou num-den ou num, auquel cas le dénominateur est 1 si num est un entier, ou 1000000 si num est une valeur flottante.
* entier non signé 32 bits : formaté comme nombre ou en hexadécimal utilisant le format 0xAABBCCDD.
* N-dimension (vecteurs) : formatés comme valeurs DIM1xDIM2[xDIM3[xDIM4]], sans multiplicateur d'unité.
* Pour les vecteurs d'entiers 2D, les noms de résolution suivants peuvent être utilisés : 360, 480, 576, 720, 1080, hd, 2k, 2160, 4k, 4320, 8k
* chaîne : formatée comme :
* `value` : copie value dans la chaîne.
* `file@FILE` : charge la chaîne depuis le fichier local FILE (ouvert en mode binaire).
* `bxml@FILE` : binarise le XML depuis le fichier local FILE et définit le type de propriété à data - voir https://wiki.gpac.io/NHML-Format.
* data : formaté comme :
* `size@address` : bloc de données constant, non copié interne ; size donne la taille du bloc, address le pointeur de données.
* `0xBYTESTRING` : bloc de données spécifié en hexadécimal, copié interne.
* `file@FILE` : charge les données depuis le fichier local FILE (ouvert en mode binaire).
* `bxml@FILE` : binarise le XML depuis le fichier local FILE - voir https://wiki.gpac.io/NHML-Format.
* `b64@DATA` : charge les données depuis DATA encodé en base-64.
* pointeur : adresse du pointeur telle que formatée par %p en C.
* listes de chaînes : formatées comme val1,val2[,...]. Chaque valeur peut aussi utiliser la syntaxe file@FILE.
* listes d'entiers : formatées comme val1,val2[,...

]

Note : Les caractères spéciaux dans les formats de propriétés (0x,/,-,+I,-I,x) ne peuvent pas être

configurés.

Les nombres et fractions peuvent être expri

més comme THH:MM:SS.ms, TMM:SS.ms, THH:
MM:SS ou TMM:SS, traduits en millisecondes.

[FILTER]

Déclaration

générique

Chaque filtre est déclaré par son nom, avec des arguments de filtre optionnels ajoutés sous forme de liste de paires nom=valeur séparées par des deux-points. Une syntaxe supplémentaire est fournie pour :
* booléen : la valeur peut être omise, par défaut true (ex : :allt). L'utilisation de ! avant le nom négate le résultat (ex : :!moof_first)
* énumérations : le nom peut être omis, ex : :disp=pbo est équivalent à :

pbo.

Lorsque des paramètres de chaîne sont utilisés (ex : URLs), il est recommandé d'échapper la chaîne en utilisant le mot-clé gpac.
Exemple
filter:ARG=http://foo/bar?yes:gpac:

opt=VAL

Cela extraira correctement l'URL.
Exemple
filter:ARG=http://foo/bar?yes:

opt=VAL

Cela échouera à extraire l'URL et gardera :opt=VAL comme partie de l'URL.
Le mécanisme d'échappement n'est pas nécessaire pour les sources locales, pour lesquelles l'existence du fichier est vérifiée lors de l'analyse des arguments. Il n'est pas non plus nécessaire pour les gestionnaires de protocoles intégrés (avin://, video://, audio://, pipe://)
Pour les protocoles tcp:// et udp://, l'échappement n'est pas nécessaire si un / final est ajouté après le numéro de port.
Exemple
-i tcp://127.0.0.1:1234:

OPT

Cela échouera à extraire l'URL et les options.
Exemple
-i tcp://127.0.0.1:1234/:

OPT

Cela extraira l'URL et les options.
Note : un astuce pour éviter la séquence d'échappement est de déclarer l'option urls à la fin, ex : f1:opt1=foo:url=http://bar, à condition que vous n'ayez qu'un seul paramètre d'URL à spécifier sur le

filtre.

Il est possible de désactiver l'analyse des options (pour les options de chaîne) en dupliquant le séparateur.
Exemple
filter::opt1=UDP://IP:PORT/:someopt=VAL::

opt2=VAL2

Cela passera UDP://IP:PORT/:

someopt=VAL à opt1 sans
l'inspecter, et VAL2 à opt2.

Sink

Les filtres source et sink n'ont pas besoin d'être adressés par le nom du filtre, spécifier src= ou dst= à la place suffit. Vous pouvez aussi utiliser la syntaxe -src URL ou -i URL pour les sources et -dst URL ou -o URL pour les destinations, cela permet la complétion de ligne de commande dans les shells.
Exemple
"src=file.mp4" ou "-src file.mp4" ou "-i file.

mp4"

Cela trouvera un filtre (par exemple fin) capable de charger file.mp4. Le même résultat peut être obtenu en utilisant fin:src=file.mp4.

"dst=dump.yuv" ou "-dst dump.yuv" ou "-o dump.

yuv"

Cela déversera le contenu vidéo dans dump.yuv. Le même résultat peut être obtenu en utilisant fout:dst=dump.

yuv.

Des filtres source ou sink spécifiques peuvent aussi être spécifiés en utilisant filterName:src=URL ou filterName:

dst=URL.

Les syntaxes src= et dst= peuvent aussi être

utilisées dans les alias pour le clonage
dynamique d'arguments (voir gpac -hx alias).

Cela utilisera ffdmx pour lire file.mp4 et ffdec pour le décoder.

ltre spécifique lorsque des chaînes de
filtres alternatives sont possibles.

Spécification des encodeurs et

décodeurs

Par défaut, la chaîne de filtres sera résolue sans aucun décodage/encodage si la destination accepte le format souhaité. Sinon, des décodeurs/encodeurs seront chargés dynamiquement pour effectuer la conversion, sauf si la résolution dynamique est désactivée. Il existe un nom de filtre raccourci spécial pour les encodeurs enc permettant de faire correspondre un filtre fournissant l'encodage souhaité. Les paramètres pour enc sont :
* c=NAME : identifie le codec souhaité. NAME peut être le nom de codec GPAC ou l' instance d'encodeur pour ffmpeg/autres
* b=UINT, rate=UINT, bitrate=UINT : indique le débit en bits par seconde
* g=UINT, gop=UINT : indique la taille du GOP en images
* pfmt=NAME : indique le nom du format de pixels cible (voir les propriétés (-h props) ) de la source, si supporté par le codec
* all_intra=BOOL : indique que toutes les images doivent être des images intra, si supporté par le

codec

Les autres options seront passées au filtre s'il accepte l'analyse générique d'arguments (comme c'est le cas pour ffmpeg).
La syntaxe raccourcie c=TYPE (ex : c=aac:opts) est aussi

supportée.

Exemple
gpac -i dump.yuv:size=320x240:fps=25 enc:c=avc:b=150000:g=50:cgop=true:fast=true -o raw.

264

Cela crée un AVC à 25 fps à 175kbps avec une durée de gop de 2 secondes, en utilisant les paramètres gop fermé et encodage rapide pour

ffmpeg.

L'opération inverse (forcer un décodage) est possible en utilisant le filtre reframer.
Exemple
gpac -i file.mp4 reframer:raw=av -o

null

Cela forcera le décodage des médias depuis file.

mp4 et jettera (enverra à null) le résultat
(faisant par exemple un benchmark du décodeur).

Échappement des séparateurs

d'options

Lorsqu'un filtre utilise une option définie comme chaîne utilisant le même caractère séparateur que gpac, vous pouvez soit modifier l'ensemble des séparateurs, soit échapper le séparateur en le dupliquant. Les options entourées par un séparateur dupliqué ne sont pas analysées. Cela est principalement utilisé pour les méta-filtres, comme ffmpeg, pour passer des options aux sous-filtres tels que libx264 (cf paramètre x264opts ).
Exemple
f:a=foo:

b=bar

Cela définira l'option a à foo et l'option b à bar sur le filtre.
Exemple
f::a=foo:

b=bar

Cela définira l'option a à foo:b=bar sur le filtre.
Exemple
f:a=foo::b=bar:c::

d=fun

Cela définira l'opti

on a à foo, b à bar:
c et l'option d à fu
n sur le filtre.

Liaison de filtre

[LINK]

Chaque filtre expose un ou plusieurs ensembles de capacités, appelés paquets de capacités, qui sont des types et valeurs de propriétés qui doivent être appariés ou exclus lors de la connexion des PID.
Pour vérifier les sources et destinations possibles pour un filtre FNAME, utilisez gpac -h links

FNAME

Le résolveur de graphe de filtres utilise cette information avec les propriétés du PID pour lier les différents

filtres.

Les directives de liaison, lorsqu'elles sont fournies, spécifient depuis quelle source un filtre peut accepter des connexions.
Elles ne spécifient pas vers quelle destination un filtre peut se

connecter.

Liaison de filtre par

défaut

Lorsqu'aucune instruction de liaison n'est donnée (voir ci-dessous), la stratégie de liaison par défaut utilisée est soit le mode implicite (par défaut dans gpac) soit le mode complet (si .I -cl est défini).
Chaque PID est vérifié pour une connexion possible à tous les filtres définis, dans leur ordre de déclaration.
Pour chaque filtre DST acceptant une connexion du PID, directement ou avec des filtres intermédiaires :
- si le filtre DST a des directives de liaison, les utiliser pour autoriser ou rejeter la connexion du PID.
- sinon, si le mode complet est activé, autoriser la connexion..
- sinon (mode implicite) :
- si DST n'est pas un sink et est le premier filtre correspondant sans directive de liaison, autoriser la connexion.
- sinon, si DST n'est pas un sink et n'est pas le premier filtre correspondant sans directive de liaison, rejeter la connexion.
- sinon (DST est un sink) et aucune connexion précédente à un filtre non-sink, autoriser la

connexion.

Dans tous les modes de liaison, un filtre peut empêcher d'être lié à un filtre sans directives de liaison en définissant l'option RSID sur le filtre.
Cela est généralement nécessaire lors de l'insertion/suppression dynamique de filtres dans une session existante où certains filtres n'ont pas d'ID défini et ne sont pas souhaités pour la chaîne

insérée.

Exemple
gpac -i file.mp4 c=avc -o

output

Avec cette configuration en mode implicite :
- si le fichier a un PID vidéo, il se connectera à enc mais pas à output. Le PID de sortie de enc se connectera à output.
- si le fichier a d'autres PID que la vidéo, ils se connecteront à output, car ce filtre enc n'accepte que la

vidéo.

Exemple
gpac -cl -i file.mp4 c=avc -o

output

Avec cette configuration en mode complet :
- si le fichier a un PID vidéo, il se connectera à la fois à enc et à output, et le PID de sortie de enc sera se connecte à la sortie.
- si le fichier a d'autres PID que la vidéo, ils se connecteront à la sortie.

De plus, en mode implicite, les connexions de filtres sont limitées aux filtres définis entre la dernière source et le(s) puits.
Exemple
gpac -i video1 reframer:saps=1 -i video2 ffsws:osize=128x72 -o output

Cela connectera :
- video1 à reframer puis reframer à output, mais empêchera la connexion de reframer à ffsws.
- video2 à ffsws puis ffsws à output, mais empêchera la connexion de video2 à reframer.

Exemple
gpac -i video1 -i video2 reframer:saps=1 ffsws:osize=128x72 -o output

Cela connectera video1 ET video2 à reframer->ffsws->output

Le mode implicite permet de spécifier des chaînes de traitement linéaires (sans éventail de PID, sauf pour la/les sortie(s) finale(s)) sans directives de liaison, simplifiant les lignes de commande pour les cas courants.
Attention : l'ordre des arguments est vraiment important en mode implicite !

Exemple
gpac -i file.mp4 c=avc c=aac -o output

Si le fichier a un PID vidéo, il se connectera à c=avc mais pas à output. Le PID de sortie de c=avc se connectera à output.
Si le fichier a un PID audio, il se connectera à c=aac mais pas à output. Le PID de sortie de c=aac se connectera à output.
Si le fichier a d'autres PID que l'audio ou la vidéo, ils se connecteront à output.

Exemple
gpac -i file.mp4 ffswf=osize:128x72 c=avc resample=osr=48k c=aac -o output

Cela forcera :
- SRC(video)->ffsws->enc(video)->output et empêchera les connexions SRC(video)->output, SRC(video)->enc(video) et ffsws->output qui auraient lieu en mode complet.
- SRC(audio)->resample->enc(audio)->output et empêchera les connexions SRC(audio)->output, SRC(audio)->enc(audio) et resample->output qui auraient lieu en mode complet.

Liaisons rapides

Les liaisons entre filtres peuvent être spécifiées manuellement. La syntaxe est un caractère @ éventuellement suivi d'un entier (0 si omis).
Cela indique que le filtre suivant spécifié au prompt ne doit être lié qu'à un filtre listé précédemment.
L'entier optionnel est un index basé sur 0 des déclarations de filtres précédentes, 0 indiquant la déclaration de filtre précédente, 1 celle d'avant la déclaration précédente, ...).
Si @@ est utilisé au lieu de @, l'entier optionnel donne l'index du filtre à partir du premier filtre (index 0) spécifié dans la ligne de commande.
Plusieurs directives de liaison peuvent être données pour un filtre.
Exemple
fA fB @1 fC

Cela indique que fC n'accepte les entrées que de fA.
Exemple
fA fB fC @1 @0 fD

Cela indique que fD n'accepte les entrées que de fB et fC.
Exemple
fA fB fC ... @@1 fZ

Cela indique que fZ n'accepte les entrées que de fB.

Liaisons complexes

La directive de liaison @ est simplement un raccourci rapide pour définir les arguments de filtre suivants :
* FID=name : attribue un identifiant au filtre
* SID=name1[,name2...] : définit une liste d'identifiants de filtres, ou sourceIDs, restreignant la liste des entrées possibles pour un filtre.

Exemple
fA fB @1 fC

Cela est équivalent à fA:FID=1 fB fC:SID=1.
Exemple
fA:FID=1 fB fC:SID=1

Cela indique que fC n'accepte l'entrée que de fA, mais que fB pourrait accepter des entrées de fA.
Exemple
fA:FID=1 fB:FID=2 fC:SID=1 fD:SID=1,2

Cela indique que fD n'accepte l'entrée que de fA et fB, et que fC n'accepte l'entrée que de fA
Remarque : Un filtre avec sourceID défini ne peut pas recevoir d'entrée de filtres sans ID.

Un nom de sourceID peut être étendu davantage à l'aide d'un identifiant de fragment (# par défaut) :
* name#PIDNAME : n'accepte que le(s) PID avec le nom PIDNAME
* name#TYPE : n'accepte que les PID du type de média correspondant. TYPE peut être audio, video, scene, text, font, meta
* name#TYPEN : n'accepte que le PID N (index basé sur 1) du type correspondant de la source (par exemple video2 pour n'accepter que le deuxième PID vidéo)
* name#TAG=VAL : accepte le PID si son filtre parent n'a pas de tag ou un tag correspondant à VAL
* name#ITAG=VAL : accepte le PID si son filtre parent n'a pas de tag hérité ou un tag hérité correspondant à VAL
* name#P4CC=VAL : n'accepte que les PID avec la propriété intégrée de type P4CC et la valeur VAL.
* name#PName=VAL : identique à ci-dessus, en utilisant le nom intégré correspondant à la propriété.
* name#AnyName=VAL : identique à ci-dessus, en utilisant le nom d'une propriété non intégrée.
* name#Name=OtherPropName : compare la valeur avec la valeur d'une autre propriété du PID. La correspondance échouera si la valeur à comparer n'est pas présente ou diffère de la valeur à vérifier. La propriété à comparer doit être une propriété intégrée.
Si la propriété n'est pas définie sur le PID, la propriété correspond. Sinon, sa valeur est vérifiée par rapport à la valeur donnée.

Les modificateurs suivants pour les comparaisons sont autorisés (pour tout format de fragment utilisant =) :
* name#P4CC=!VAL : n'accepte que les PID avec la propriété NE correspondant PAS à VAL.
* name#P4CC-VAL : n'accepte que les PID avec la propriété strictement inférieure à VAL (uniquement pour les propriétés numériques à 1 dimension).
* name#P4CC+VAL : n'accepte que les PID avec la propriété strictement supérieure à VAL (uniquement pour les propriétés numériques à 1 dimension).

Un nom de sourceID peut également utiliser un joker ou être vide pour correspondre à une propriété quel que soit le filtre source.
Exemple
fA fB:SID=*#ServiceID=2
fA fB:SID=#ServiceID=2

Cela indique de faire correspondre la connexion entre fA et fB uniquement pour les PID avec une propriété ServiceID de 2.
Ces extensions fonctionnent également avec le raccourci LINK @.
Exemple
fA fB @1#video fC

Cela indique que fC n'accepte les entrées que de fA, et de type vidéo.
Exemple
gpac -i img.heif @#ItemID=200 vout

Cela indique de connecter à vout uniquement les PID avec la propriété ItemID égale à 200.
Exemple
gpac -i vid.mp4 @#PID=1 vout

Cela indique de connecter à vout uniquement les PID avec la propriété ID égale à 1.
Exemple
gpac -i vid.mp4 @#Width=640 vout

Cela indique de connecter à vout uniquement les PID avec la propriété Width égale à 640.
Exemple
gpac -i vid.mp4 @#Width-640 vout

Cela indique de connecter à vout uniquement les PID avec la propriété Width inférieure à 640
Exemple
gpac -i vid.mp4 @#ID=ItemID#ItemNumber=1 vout

Cela ne connectera à vout que le PID avec une propriété ID égale à la propriété ItemID (conserver les éléments, écarter les pistes) et un numéro d'élément de 1 (premier élément).

Plusieurs fragments peuvent être spécifiés pour vérifier plusieurs propriétés de PID.
Exemple
gpac -i vid.mp4 @#Width=640#Height+380 vout

Cela indique de connecter à vout uniquement les PID avec la propriété Width égale à 640 et la propriété Height supérieure à 380.

Attention : Si un PID se connecte directement à un ou plusieurs filtres chargés explicitement, aucune autre résolution dynamique de liaison ne sera effectuée pour le connecter à d'autres filtres sans sourceID défini. Les directives de liaison doivent être soigneusement configurées.
Exemple
fA @ reframer fB

Si fB accepte les entrées fournies par fA mais que reframer ne les accepte pas, cela liera le PID de fA au filtre fB car fB n'a pas de sourceID.
Puisque le PID est connecté, le moteur de filtres n'essaiera pas de résoudre une liaison entre fA et reframer.

Une exception est faite pour les fichiers locaux : par défaut, une destination de fichier local forcera un remultiplexage des PID d'entrée d'un fichier local.
Exemple
gpac -i file.mp4 -o dump.mp4

Cela empêchera la connexion directe du PID de type fichier à la destination file.mp4, en remultiplexant le fichier.

L'option spéciale nomux est utilisée pour autoriser les connexions directes (ignorée pour les filtres non-puits).
Exemple
gpac -i file.mp4 -o dump.mp4:nomux

Cela résultera en une copie directe du fichier.

Cela ne s'applique qu'aux destinations de fichiers locaux. Pour les pipes, les sockets ou d'autres sorties de fichiers (HTTP, ROUTE) :
- la copie directe est activée par défaut
- nomux=0 peut être utilisé pour forcer le remultiplexage

Étiquetage des sous-sessions

Les filtres peuvent être assignés à une sous-session à l'aide de :FS=N, avec N un entier positif.
Les filtres appartenant à des sous-sessions différentes ne peuvent se lier entre eux que :
- si explicitement autorisé par les directives sourceID (@ ou SID)
- ou s'ils ont le même identifiant de sous-session

Cela est principalement utilisé pour le mode implicite dans gpac : chaque premier filtre source spécifié après un filtre puits déclenchera une nouvelle sous-session.
Exemple
gpac -i in1.mp4 -i in2.mp4 -o out1.mp4 -o out2.mp4

Cela résultera en une multiplexage des deux entrées dans les deux sorties.
Exemple
gpac -i in1.mp4 -o out1.mp4 -i in2.mp4 -o out2.mp4

Cela résultera en in1 mixé vers out1 et in2 mixé vers out2, ces deux derniers filtres appartenant à une sous-session différente.

Héritage des arguments

Sauf si explicitement désactivé (voir .I -max-chain), le moteur de filtres résoudra les connexions implicites ou explicites (LINK) entre les filtres et allouera toute chaîne de filtres nécessaire pour connecter les filtres. Ce faisant, il charge de nouveaux filtres avec des arguments hérités à la fois de la source et de la destination.
Exemple
gpac -i file.mp4:OPT -o file.aac -o file.264

Cela passera le :OPT à tous les filtres chargés entre la source et les deux destinations.
Exemple
gpac -i file.mp4 -o file.aac:OPT -o file.264

Cela passera le :OPT à tous les filtres chargés entre la source et la destination file.aac.
Remarque : les arguments de destination hérités sont les arguments placés APRÈS l'option dst=.
Exemple
gpac -i file.mp4 fout:OPTFOO:dst=file.aac:OPTBAR

Cela passera le :OPTBAR à tous les filtres chargés entre la source file.mp4 et la destination file.aac, mais pas OPTFOO.
L'héritage des arguments peut être arrêté en utilisant le mot-clé gfloc : les arguments après le mot-clé ne seront pas hérités.
Exemple
gpac -i file.mp4 -o file.aac:OPTFOO:gfloc:OPTBAR -o file.264

Cela passera le :OPTFOO à tous les filtres chargés entre la source file.mp4 et la destination file.aac, mais pas OPTBAR
Les arguments sont suivis par défaut pour vérifier s'ils ont été utilisés par la chaîne de filtres, et un avertissement est émis si ce n'est pas le cas.
Il peut être utile de spécifier des arguments qui peuvent ne pas être consommés en fonction de la résolution du graphe ; le mot-clé spécifique gfopt indique que les arguments après le mot-clé ne seront pas suivis.
Exemple
gpac -i file.mp4 -o file.aac:OPTFOO:gfopt:OPTBAR -o file.264

Cela avertira si OPTFOO n'est pas consommé, mais ne suivra pas OPTBAR.

Un filtre peut se voir attribuer un nom (à des fins d'inspection, non hérité) à l'aide de l'option :N=name. Ce nom n'est pas utilisé dans la résolution des liens et peut être modifié à l'exécution par l'instance du filtre.

Un filtre peut se voir attribuer une étiquette (n'importe quelle chaîne) à l'aide de l'option :TAG=name. Cette étiquette n'a pas besoin d'être unique et peut être utilisée pour exclure un filtre lors de la résolution des liens. Les étiquettes ne sont pas héritées, par conséquent les filtres chargés dynamiquement n'ont jamais d'étiquette.

Un filtre peut également se voir attribuer une étiquette héritée (n'importe quelle chaîne) à l'aide de l'option :ITAG=name. Ces étiquettes sont héritées et sont généralement utilisées pour suivre les filtres chargés dynamiquement.

Modélisation d'URL

Les URL de destination peuvent être construites dynamiquement à l'aide de modèles. Le motif $KEYWORD$ est remplacé dans le modèle par la valeur résolue et $KEYWORD%%0Nd$ est remplacé dans le modèle par l'entier résolu, complété par jusqu'à N zéros si nécessaire.
KEYWORD est sensible à la casse et peut apparaître plusieurs fois dans la chaîne. KEYWORD pris en charge :
* num : remplacé par le numéro de fichier s'il est défini, 0 sinon
* PID : ID du PID source
* URL : URL du fichier source
* File : chemin sur le disque du fichier source ; s'il n'est pas trouvé, utilise l'URL si définie, sinon le nom du PID
* Type : nom du type de flux du PID (video, audio ...)
* OType : identique à Type mais utilise le type original lorsque le flux est chiffré (par ex. passage de crypt à video)
* p4cc=ABCD : utilise la propriété du PID avec la valeur 4CC ABCD
* pname=VAL : utilise la propriété du PID avec le nom VAL
* cts, dts, dur, sap : utilise les propriétés du premier paquet du PID au moment de la résolution du modèle
* OTHER : localise la propriété 4CC pour le nom donné, ou le nom de la propriété si aucune 4CC ne correspond.

$$ est un caractère d'échappement pour $

La modélisation peut être utile lors de l'encodage de plusieurs qualités en une seule passe.
Exemple
gpac -i dump.yuv:size=640x360 vcrop:wnd=0x0x320x180 c=avc:b=1M @2 c=avc:b=750k -o dump_$CropOrigin$x$Width$x$Height$.264

Cela créera une version recadrée de la source, encodée en AVC à 1M, et une version complète du contenu en AVC à 750k. Les sorties seront dump_0x0x320x180.264 pour la version recadrée et dump_0x0x640x360.264 pour la version non recadrée.

Clonage de filtres

Lorsqu'un filtre accepte une seule connexion et a une entrée connectée, il n'est plus disponible pour la résolution dynamique. Il peut y avoir des cas où ce comportement est indésirable. Prenez un fichier HEIF avec N éléments et faites :
Exemple
gpac -i img.heif -o dump_$ItemID$.jpg

Dans ce cas, un seul élément (probablement le premier déclaré dans le fichier) sera connecté à la destination.
Les autres éléments ne seront pas connectés car la destination n'accepte qu'un seul PID d'entrée.
Exemple
gpac -i img.heif -o dump_$ItemID$.jpg

Dans ce cas, la destination sera clonée pour chaque élément, et tous seront exportés vers différents JPEG grâce à la modélisation d'URL.
Exemple
gpac -i vid.mpd c=avc:FID=1 -o transcode.mpd:SID=1

Dans ce cas, l'encodeur sera cloné pour chaque PID vidéo de la source, et la destination n'utilisera que les PID provenant des encodeurs.

Lorsque le lien implicite est activé, tous les filtres sont par défaut clonables. Cela permet de dupliquer le traitement pour chaque PID de même type.
Exemple
gpac -i dual_audio resample:osr=48k c=aac -o dst

Le filtre rééchantillonneur sera cloné pour chaque PID audio, et l'encodeur sera cloné pour chaque sortie du rééchantillonneur.
Vous pouvez désactiver explicitement les instructions de clonage :
Exemple
gpac -i dual_audio resample:osr=48k:clone=0 c=aac -o dst

Le premier audio se connectera au filtre resample, le second au filtre enc, et la sortie de resample se connectera à un clone du filtre enc.

Modélisation de chaînes de filtres

Il peut y avoir des cas où le nombre de sorties désirées dépend du contenu source, par exemple l'export d'un multiplex de N services vers N fichiers. Lorsque la destination implique le multiplexage des PID d'entrée, l'option :clone ne suffit pas car le multiplexeur acceptera toujours les PID d'entrée.
Pour gérer cela, il est possible d'utiliser un nom de propriété PID dans le sourceID d'un filtre avec la valeur * ou une valeur vide. Dans ce cas, chaque fois qu'un nouveau PID avec une nouvelle valeur pour la propriété est trouvé, le filtre avec un tel sourceID sera cloné dynamiquement.
Avertissement : Cette fonctionnalité ne doit être appelée qu'avec une seule propriété définie à * (ou vide) par source ID, les résultats sont indéfinis sinon.
Exemple
gpac -i source.ts -o file_$ServiceID$.mp4:SID=*#ServiceID=*
gpac -i source.ts -o file_$ServiceID$.mp4:SID=#ServiceID=

Dans ce cas, chaque nouvelle valeur ServiceID trouvée lors de la connexion des PID à la destination créera un nouveau fichier de destination.

Le clonage en mode de lien implicite s'applique également à la sortie :
Exemple
gpac -i dual_audio -o dst_$PID$.aac

Chaque piste audio sera exportée en aac (potentiellement réencodée si nécessaire).

Attribution de propriétés PID

Il est possible de définir des propriétés sur les PID de sortie qui seront déclarés par un filtre. Cela permet d'étiqueter des parties du graphe avec des propriétés différentes des autres parties (par exemple ServiceID). La syntaxe est la même que celle des options de filtre et utilise le séparateur de fragment pour identifier les propriétés, par ex. #Name=Value.
Cela définit la propriété du PID de sortie (4cc, nom intégré ou n'importe quel nom) à la valeur donnée. La valeur peut être omise pour un booléen (par défaut true, par ex. :#Alpha).
Les propriétés non intégrées sont analysées comme suit :
- file@FOO sera déclaré comme chaîne avec une valeur définie au contenu de FOO.
- bxml@FOO sera déclaré comme donnée avec une valeur définie au contenu binarisé de FOO.
- FOO sera déclaré comme chaîne avec une valeur définie à FOO.
- TYPE@FOO sera analysé selon TYPE. Si le type n'est pas reconnu, la valeur entière est copiée en tant que chaîne. Voir gpac -h props pour les types définis.

Les propriétés PID assignées par l'utilisateur sur le filtre fA seront héritées par tous les filtres chargés dynamiquement pour résoudre la connexion fA -> fB.
Si fB a également des propriétés PID assignées par l'utilisateur, celles-ci ne s'appliquent qu'à partir de fB dans la chaîne et ne sont pas héritées par les filtres entre fA et fB.

Avertissement : Les propriétés ne sont pas filtrées et remplacent les propriétés des PID de sortie du filtre, soyez prudent pour ne pas casser la session en remplaçant des propriétés fondamentales telles que width/height/samplerate/... !
Exemple
gpac -i v1.mp4:#ServiceID=4 -i v2.mp4:#ServiceID=2 -o dump.ts

Cela multiplexera les flux dans dump.ts, en utilisant ServiceID 4 pour les PID de v1.mp4 et ServiceID 2 pour les PID de v2.mp4.

Les propriétés PID peuvent être assignées conditionnellement en vérifiant d'autres propriétés PID. La syntaxe utilise des parenthèses (non configurables) après le signe d'assignation de propriété :
#Prop=(CP=CV)VAL
Cela assignera la propriété PID Prop à VAL pour les PID avec la propriété CP égale à CV.
#Prop=(CP=CV)VAL,(CP2=CV2)VAL2
Cela assignera la propriété PID Prop à VAL pour les PID avec la propriété CP égale à CV, et à VAL2 pour les PID avec la propriété CP2 égale à CV2.
#Prop=(CP=CV)(CP2=CV2)VAL
Cela assignera la propriété PID Prop à VAL pour les PID avec la propriété CP égale à CV et la propriété CP2 égale à CV2.
#Prop=(CP=CV)VAL,()DEFAULT
Cela assignera la propriété PID Prop à VAL pour les PID avec la propriété CP égale à CV, ou à DEFAULT pour les autres PID.
La syntaxe de condition est la même que celle du fragment d'ID source.
Remarque : Lorsqu'elle est définie, la valeur par défaut (condition vide) correspond toujours au PID, elle doit donc être placée en dernier dans la liste des conditions.
Exemple
gpac -i source.mp4:#MyProp=(audio)"Super Audio",(video)"Super Video"

Cela assignera la propriété MyProp à Super Audio pour les PID audio et à Super Video pour les PID vidéo.
Exemple
gpac -i source.mp4:#MyProp=(audio1)"Super Audio"

Cela assignera la propriété MyProp à Super Audio pour le premier PID audio déclaré.
Exemple
gpac -i source.mp4:#MyProp=(Width+1280)HD

Cela assignera la propriété MyProp à HD pour les PID avec la propriété Width supérieure à 1280.

La valeur de la propriété peut utiliser des modèles avec les mots-clés suivants :
* $GINC(init[,inc]) ou @GINC(...) : remplacé par un entier pour chaque nouveau PID de sortie du filtre (voir les options spécifiques du filtre pour les détails de la syntaxe)
* PROP (encadré par `$` ou `@`) : remplacé par la valeur sérialisée de la propriété PROP (nom ou 4CC) du PID ou par une chaîne vide si une telle propriété n'existe pas
Exemple
gpac -i source.ts:#ASID=$PID$

Cela assignera l'ID DASH AdaptationSet à la valeur ID du PID.
Exemple
gpac -i source.ts:#RepresentationID=$ServiceID$

Cela assignera l'ID DASH Representation à la valeur ServiceID du PID.

Utilisation de fichiers d'options

Il est possible d'utiliser un fichier pour définir les options d'un filtre, en spécifiant le nom du fichier cible comme option sans valeur, c'est-à-dire :myopts.txt.
Avertissement : Seuls les fichiers locaux sont autorisés.
Un fichier d'options est un fichier texte simple contenant une ou plusieurs options ou propriétés PID sur une ou plusieurs lignes.
- Une ligne commençant par "//" est un commentaire et est ignorée (non configurable).
- Une ligne commençant par ":" indique une option échappée (la ligne entière est analysée comme une seule option).
Les options dans un fichier d'options peuvent pointer vers d'autres fichiers d'options, avec un niveau de redirection maximum de 5.
Une déclaration de fichier d'options (filter:myopts.txt) suit les mêmes règles d'héritage que les options régulières.
Exemple
gpac -i source.mp4:myopts.txt:foo=bar -o dst

Tout filtre chargé entre source.mp4 et dst héritera des options myopts.txt et foo et résoudra les options et propriétés PID données dans myopts.txt.

Ignorer des filtres à l'exécution

L'option spéciale ccp peut être utilisée pour remplacer des filtres par un filtre d'identité à l'exécution en fonction de l'ID du codec d'entrée.
L'option est une liste d'IDs de codec à vérifier. Pour les filtres d'encodeur, une liste vide réutilise le type de codec de l'encodeur.
Lorsque l'ID du codec du PID correspond à l'un des codecs spécifiés, le filtre est remplacé par un filtre reframer avec une entrée PID unique et le même nom et ID. > Exemple
-i src c=avc:b=1m:ccp -o mux

Ceci remplacera le filtre d'encodeur par un reframer si le PID d'entrée est au format AVC|H264, ou utilisera l'encodeur pour d'autres PID visuels.
Exemple
-i src c=avc:b=1m:ccp=avc,hevc -o mux

Ceci remplacera le filtre d'encodeur par un reframer si le PID d'entrée est au format AVC|H264 ou HEVC, ou utilisera l'encodeur pour d'autres PID visuels.
Exemple
-i src cecrypt:cfile=drm.xml:ccp=aac -o mux

Ceci remplacera le filtre d'encryptage par un reframer si le PID d'entrée est au format AAC, ou utilisera l'encryptage pour d'autres PID.

Options spécifiques de filtre

Certains mots-clés spécifiques sont remplacés lors du traitement des options de filtre.
Attention : Ces mots-clés ne s'appliquent pas aux propriétés des PID. Plusieurs mots-clés ne peuvent pas être définis pour une seule option.
Mots-clés définis :
* $GSHARE : remplacé par le chemin système du répertoire partagé GPAC (par exemple, /usr/share/gpac)
* $GJS : remplacé par le premier chemin du répertoire partagé global et les chemins définis via .I -js-dirs qui contiennent le nom du fichier suivant le macro, par exemple, $GJS/source.js
* $GDOCS : remplacé par le chemin système :
- répertoire de documents de l'application pour iOS
- variable d'environnement EXTERNAL_STORAGE si présente ou /sdcard sinon pour Android
- répertoire personnel de l'utilisateur pour les autres plateformes
* $GLANG : remplacé par l'option de configuration globale .I -lang
* $GUA : remplacé par l'option de configuration globale de l'agent utilisateur .I -user-agent
* $GINC(init_val[,inc]) : remplacé par init_val et incrémente init_val de inc (nombre positif ou négatif, 1 s'il n'est pas spécifié) chaque fois qu'un nouveau filtre utilisant cette chaîne est créé.

La construction $GINC peut être utilisée pour attribuer dynamiquement des numéros dans les chaînes de filtres :
Exemple
gpac -i source.ts tssplit @#ServiceID= -o dump_$GINC(10,2).ts

Ceci exportera le premier service dans dump_10.ts, le second dans dump_12.ts, etc...

Comme vu précédemment, les options suivantes peuvent être définies sur n'importe quel filtre, mais ne sont pas visibles dans l'aide de chaque filtre :
* FID : identifiant du filtre
* SID : source(s) du filtre (valeur chaîne)
* N=NAME : nom du filtre (valeur chaîne)
* FS : identifiant de sous-session (valeur entière non signée)
* RSID : requiert que sourceID soit présent sur les filtres cibles (pas de valeur)
* TAG : étiquette du filtre (valeur chaîne)
* ITAG : étiquette héritée du filtre (valeur chaîne)
* FBT : temps de tampon en microsecondes (valeur entière non signée)
* FBU : unités de tampon (valeur entière non signée)
* FBD : temps de tampon de décodage en microsecondes (valeur entière non signée)
* clone : active/désactive explicitement le drapeau de clonage de filtre (pas de valeur)
* nomux : active/désactive la copie directe de fichier (pas de valeur)
* gfreg : noms préférés du registre de filtres pour la résolution de liens (valeur chaîne)
* gfloc : les options suivantes sont locales à la déclaration du filtre, non héritées (pas de valeur)
* gfopt : les options suivantes ne sont pas suivies (pas de valeur)
* gpac : séparateur d'arguments pour les URL (pas de valeur)
* ccp : contrôle de remplacement de filtre (valeur liste de chaînes)
* NCID : ID de la configuration netcap à utiliser (chaîne)
* LT : définit des outils de journalisation et des niveaux supplémentaires pour le filtre en utilisant la même syntaxe que -logs, par exemple : LT=filter@debug (valeur chaîne)
* DBG : débogage des propriétés de PID d'entrée manquantes (=pid), des propriétés de paquet d'entrée manquantes (=pck) ou des deux (=all)

Les options de contrôle du tampon sont utilisées pour modifier la mise en tampon par défaut des PID d'un filtre :
- FBT contrôle le temps maximum de tampon des PID de sortie d'un filtre
- FBU contrôle le nombre maximum de paquets dans le tampon des PID de sortie d'un filtre lorsque le timing n'est pas disponible
- FBD contrôle le temps maximum de tampon des PID d'entrée d'un filtre de décodage, ignoré pour les autres filtres

Si un autre filtre envoie des messages de demande de tampon, la valeur maximale de FBT (resp. FBD) et le temps de tampon demandé par l'utilisateur seront utilisés pour le temps de tampon de sortie (resp. le temps de tampon de décodage).

Les options FBT, FBU, FBD et DBG peuvent être définies :
* par instance de filtre : fA reframer:FBU=2
* par classe de filtre pour l'exécution : --reframer@FBU=2
* dans le fichier de configuration GPAC dans une section par filtre : [filter@reframer]FBU=2

Les valeurs par défaut sont définies par les paramètres par défaut de la session -buffer-gen, buffer-units et -buffer-dec.

Filtres externes

GPAC est livré avec un ensemble de filtres intégrés dans libgpac. Il peut également charger des filtres externes dans des bibliothèques dynamiques, situés dans le dossier de modules par défaut ou dans les dossiers listés dans l'option .I -mod-dirs. Les fichiers doivent être nommés gf_* et doivent exporter une seule fonction RegisterFilter renvoyant un registre de filtre - voir la documentation de libgpac pour plus de détails.
