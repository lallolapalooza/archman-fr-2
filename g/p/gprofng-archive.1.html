DESCRIPTIO

N

Archive les binaires d'application et les fichiers sources associés dans une expérience gprofng afin de la rendre autonome et

portable.

Par défaut, les binaires sont archivés dans le cadre de la collecte des données, mais les fichiers sources de l'application ne le sont pas. Utilisez cet outil pour modifier ce comportement et archiver ensuite des composants supplémentaires

.

Cet outil doit être exécuté sur le

même système où les données
de profilage ont été enregistrées.

NOTE

S
-
Archivage des binaires d'application - Par défaut, les binaires sont archivés
automatiquement lorsqu'une expérience est créée. Cependant, l'archivag
e ne se produit pas dans une ou plusieurs des circonstances suivantes :
  • Si l'application profilée est terminée avant de se terminer
    • normalement.
  • Si un processus en cours d'exécution est
    • profilé.
  • Si l'archivage est explicitement désactivé lors du profilage. Par exemple en utilisant l'option -a off sur gprofng
    • coll
ect
app.

Dans ces cas, gprofng archive doit être exécuté manuellement et sur la même machine où les données de profilage ont été

enregistrées.

L'archivage des données d'expérience pendant le processus de collecte des données peut être assez coûteux. Surtout si l'expérience a de nombreux processus descendants. Dans de tels cas, une stratégie plus efficace consiste à utiliser l'option -a off lors de la collecte des données. Une fois la collecte terminée, les données peuvent être archivées à l'aide de l'option -s all. Cela enregistre tous les exécutables et fichiers sources dans

l'expérience.

Si pendant l'archivage, un message d'erreur indique qu'un exécutable ou un fichier source ne peut pas être trouvé, la commande addpath pour ajouter le chemin du ou des fichiers manquants peut être incluse dans le fichier .er.rc. Après avoir ajouté cette commande, archivez à nouveau l'expérience. L'archivage peut être répété autant de fois que nécessaire pour archiver tous les

fichiers.

L'archivage doit être effectué sur le même système que celui utilisé pour collecter l'expérience. Si certains fichiers ne peuvent pas être accessibles depuis ce système (par ex. des sources ou des fichiers objet), un archivage supplémentaire peut être effectué en utilisant un autre système qui y a accès. Par exemple, le système où l'application a été

compilée.

Certaines applications Java stockent des objets partagés dans des fichiers jar. Par défaut, de tels objets partagés ne sont pas archivés automatiquement. Pour archiver les objets partagés contenus dans des fichiers jar, assurez-vous d'inclure la commande addpath dans un fichier .er.rc. La commande addpath doit indiquer le chemin du fichier jar, y compris le fichier jar lui-même. Le fichier .er.rc doit être enregistré dans le répertoire personnel de

l'utilisateur, ou le répertoi
re parent de l'expérience.
  • Archivage des sources de l'application - Par défaut, les fichiers sources de l'application ne sont pas archivés dans l'expérience. Exécutez la commande gprofng archive avec l'option -s all, ou -s used sur chaque expérience pour enregistrer les fichiers sources dans
    • l'expérience.
  • Archivage automatique des sources de l'application - La variable d'environnement GPROFNG_ARCHIVE peut être définie pour archiver automatiquement les sources lorsque l'expérience est terminée. Cette variable d'environnement peut contenir les arguments -s et -m, sous forme de paires d'arguments et d'options, séparées par un ou plusieurs espaces.

    Si plus d'un argument -s apparaît sur la ligne de commande, le dernier prévaut. Si -s est à la fois passé sur la ligne de commande et défini par la variable d'environnement, l'option de la variable d'environnement

    prévaut.

    Notez que si l'archivage automatique des sources pendant la collecte des données a été activé à l'aide de la variable GPROFNG_ARCHIVE, ou des options -a src, ou -a usedsrc, il est recommandé de confirmer que les fichiers sources ont été correctement résolus en exécutant la commande gprofng archive -s all, ou gprofng archive

    -s
    • used.
  • Les options -d et -r sont mutuellement
    • exclusives.
  • Lors de l'utilisation de l'option -d ou -r, la variable d'environnement GPROFNG_ARCHIVE_COMMON_DIR peut être utilisée pour spécifier l'emplacement de l'archive commune. Cela peut être très pratique lors de l'utilisation d'un script pour profiler des
    • applications.
  • Si plus d'une option -s est donnée sur la ligne de commande, ou spécifiée dans la variable d'environnement, l'option spécifiée pour toutes doit être la même. Sinon, gprofng archive se termine avec une
    • erreur.
  • Cet outil ne fonctionne pas sur les expériences enregistrées avec des versions antérieures des outils. S'il est invoqué sur de telles expériences, un avertissement est affiché. Utilisez la version de gprofng archive de la même version avec
    • laquelle l'expérienc
e a été enregistrée. n>
