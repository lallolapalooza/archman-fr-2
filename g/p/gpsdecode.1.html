NOM

gpsdecode - décoder les flux GPS, RTCM ou AIS dans un format lisible

SYNTAXE

gpsdecode [OPTIONS]

gpsdecode -h

gpsdecode -V

DESCRIPTION

L'outil gpsdecode est un décodeur en mode batch pour NMEA et divers formats de paquets binaires associés au GPS, à l'AIS et aux services de correction différentielle. Il produit une sortie JSON sur la sortie standard à partir de données binaires sur l'entrée standard. Le JSON est le même format que celui documenté par gpsd ; cet outil utilise la même logique de décodage que gpsd, mais avec une interface plus simple destinée au traitement par lots de fichiers de données.

Tous les formats d'entrée de capteurs connus du projet GPSD peuvent être décodés par cet outil. Ceux-ci incluent : NMEA, AIVDM (le format de phrase dérivé de NMEA utilisé par l'AIS, le système d'identification automatique marine), RTCM2, et tous les formats binaires GPS pris en charge (notamment SiRF). Voir gpsd(8) pour les normes applicables et les limitations connues de la logique de décodage.

Vous pouvez utiliser cet outil avec nc(1) pour examiner les flux AIS provenant de services de regroupement AIS, les flux RTCM provenant de récepteurs RTCM ou de diffuseurs NTRIP.

OPTIONS

-?, -h, --help

Affiche un message d'utilisation, puis quitte.

-c, --json

Définit le format de sortie AIS pour séparer les champs par un symbole pipe ASCII. Les champs sont affichés dans l'ordre où ils apparaissent dans le paquet AIS. Les nombres ne sont pas mis à l'échelle (-u est forcé). Les chaînes de caractères sont décompressées de six bits en ASCII complet.

-d, --decode

Décode les paquets présentés sur l'entrée standard vers la sortie standard. C'est le comportement par défaut.

-D LVL, --debug LVL

Définit le niveau de verbosité du débogage à LVL. Ceci est principalement utile pour le dépannage.

-e, --encode

Encode le JSON sur l'entrée standard en JSON sur la sortie standard. Cette option est uniquement utile pour les tests de régression du code d'affichage et d'analyse JSON.

-j, --json

Définit le format de sortie sur JSON (comportement par défaut).

-m, --minlength

Affiche les longueurs minimales pour chaque type de paquet dans l'entrée (en ignorant les paquets de commentaires). Ceci intéresse probablement uniquement les développeurs de GSD.

-n, --nmea

Affiche le pseudo-NME0183 généré.

-s, --split24

Rapporte les moitiés de phrases AIS de type 24 séparément au lieu d'essayer de les agréger.

-t TYPES, --types TYPES

Une liste de types numériques séparés par des virgules. Les paquets avec un type numérique AIS, RTCM2 ou RTCM3 sont transmis et affichés uniquement s'ils correspondent à un type de la liste. Les paquets d'autres natures (en particulier les paquets GPS) sont transmis sans condition.

-u, --unsscaled

Supprime la mise à l'échelle des données AIS en quantités flottantes et l'expansion textuelle des codes numériques. Une sortie avec cette option est sans perte.

-v, --verbose

Affiche les paquets textuels sur la sortie au fur et à mesure de leur réception à l'entrée, précédant immédiatement la sortie correspondante.

-V, --version

Affiche le numéro de version, puis quitte.

FORMAT AIS DSV

Avec l'option -c ou --ais, les lignes de sortie sont les valeurs des champs de charge utile AIS, séparées par des pipes, dans l'ordre où elles apparaissent dans la charge utile. Les plages de champs exprimant une date sont émises sous forme d'horodatage ISO8601 (recherchez les deux-points et le Z final indiquant l'heure Zulu/UTC), et le groupe de 19 bits des champs d'état TDMA trouvés à la fin des messages de types 1 à 4 sont émis sous forme d'un seul entier non signé (en hexadécimal précédé de « 0x »). Les champs d'autorité régionale inutilisés sont également affichés (en hexadécimal précédé de « 0x »). Les champs binaires de longueur variable sont émis sous forme d'une longueur de bits entière, suivie d'un deux-points, suivie d'un vidage hexadécimal.

VALEURS DE RETOUR

0

En cas de succès.

1

si l'action était inconnue ou si l'écriture dans le socket de contrôle a échoué,
