DESCRIPTIO

N

Le programme gpg-card est utilisé pour administrer les cartes à puce et les jetons USB. Il fournit un sur-ensemble des fonctionnalités de gpg --card-edit et peut être considéré comme une interface pour scdaemon, qui est un démon démarré par gpg-agent pour gérer les cartes à

puce.

Si gpg-card est invoqué sans commandes, un mode interactif est

utilisé.

Si gpg-card est invoqué avec une ou plusieurs commandes, les mêmes commandes que celles disponibles en mode interactif sont exécutées depuis la ligne de commande. Ces commandes doivent être délimitées par un double tiret. Si un double tiret ou un caractère spécifique au shell est requis dans une commande, la commande entière doit être mise entre guillemets. Si l'une de ces commandes retourne une erreur, les commandes restantes ne sont plus exécutées à moins que la commande ne soit préfixée d'un tiret

simple.

Une liste de commandes est disponible en utilisant la commande help et une brève description de chaque commande est affichée en utilisant help CMD. Voir la section COMMANDES pour une description

complète.

Voir les sections NOTES pour des instr

uctions concernant des cartes ou
des applications de carte spécifiques.

NOTES (OPENPGP)

La prise en charge des cartes OpenPGP dans gpg-card n'est pas encore complète. Pour les fonctionnalités manquantes, veuillez continuer à utiliser gpg --card-edit.

NOTES (PIV)

GnuPG prend en charge les cartes PIV (``Personal Identity Verification'' tel que spécifié par la publication spéciale 800-73-4 du NIST). Cette section décrit comment initialiser (personnaliser) un nouveau token Yubikey doté de l'application PIV (nécessite Yubikey-5). Nous supposons que les identifiants n'ont pas encore été modifiés et sont donc :

Clé d'authentification
Il s'agit d'une clé de 24 octets décrite par la chaîne hexadécimale
010203040506070801020304050607080102030405060708.
Code PIN de l'application PIV
Il s'agit de la chaîne 123456.
Clé de déblocage du code PIN
Il s'agit de la chaîne 12345678.

Voir la section des exemples pour savoir comment modifier ces paramètres par défaut. Pour une utilisation en production, il est important d'utiliser des valeurs sécurisées. Notez que la clé d'authentification n'est pas interrogée via le dialogue Pinentry habituel mais doit être saisie manuellement ou lue à partir d'un fichier. L'utilisation d'une machine dédiée pour personnaliser les tokens est fortement suggérée.

Pour voir ce qu'il y a sur la carte, la commande list peut être utilisée. Nous utiliserons le mode interactif dans ce qui suit (la chaîne gpg/card> est l'invite). Un exemple de sortie pour une carte vierge est :

gpg/card> list
Reader ...........: 1050:0407:X:0
Card type ........: yubikey
Card firmware ....: 5.1.2
Serial number ....: D2760001240102010006090746250000
Application type .: OpenPGP
Version ..........: 2.1
[...]

On peut constater à la ligne ``Application type'' que GnuPG a sélectionné l'application OpenPGP du Yubikey. Ceci est dû au fait que GnuPG attribue la priorité la plus élevée à l'application OpenPGP. Pour utiliser l'application PIV du Yubikey, plusieurs méthodes peuvent être utilisées :

Avec un Yubikey 5 ou plus récent, l'application OpenPGP du Yubikey peut être désactivée :

gpg/card> yubikey disable all opgp
gpg/card> yubikey list
Application  USB    NFC
-----------------------
OTP          yes    yes
U2F          yes    yes
OPGP         no     no
PIV          yes    no
OATH         yes    yes
FIDO2        yes    yes
gpg/card> reset

Le reset est nécessaire pour que le système GnuPG relise la carte. Notez que les applications désactivées conservent toutes leurs données et peuvent être réactivées à tout moment (utilisez ‘help yubikey’).

Une autre option, qui fonctionne pour toutes les versions de Yubikey, est de désactiver la prise en charge des cartes OpenPGP dans scdaemon. Ceci est fait en ajoutant la ligne

disable-application openpgp

à ‘~/.gnupg/scdaemon.conf’ et en redémarrant scdaemon, soit en tuant le processus, soit en utilisant ‘gpgconf --kill scdaemon’. Enfin, l'ordre par défaut dans lequel scdaemon essaie les applications de carte peut être modifié. Par exemple, pour préférer PIV à OpenPGP, il suffit d'ajouter

application-priority piv

à ‘~/.gnupg/scdaemon.conf’ et de redémarrer scdaemon. Ceci n'a d'effet que sur les tokens qui prennent en charge à la fois PIV et OpenPGP, mais n'entrave pas l'utilisation des tokens OpenPGP uniquement.

Avec l'une de ces méthodes, la commande list de gpg-card affiche ceci :

gpg/card> list
Reader ...........: 1050:0407:X:0
Card type ........: yubikey
Card firmware ....: 5.1.2
Serial number ....: FF020001008A77C1
Application type .: PIV
Version ..........: 1.0
Displayed s/n ....: yk-9074625
PIN usage policy .: app-pin
PIN retry counter : - 3 -
PIV authentication: [none]
      keyref .....: PIV.9A
Card authenticat. : [none]
      keyref .....: PIV.9E
Digital signature : [none]
      keyref .....: PIV.9C
Key management ...: [none]
      keyref .....: PIV.9D

Dans le cas où plusieurs tokens sont connectés à l'ordinateur, gpg-card n'en affichera qu'un seul. Pour afficher un autre token, le numéro du token (0, 1, 2, ...) peut être donné en argument à la commande list. La commande ‘list --cards’ affiche une liste de tous les tokens insérés.

Notez que le ``Displayed s/n'' est imprimé sur le token et affiché également dans les invites Pinentry demandant le code PIN. Les quatre slots de clés standard sont toujours affichés, si d'autres slots de clés sont initialisés, ils sont également affichés. La clé d'authentification PIV (référence interne PIV.9A) est utilisée pour authentifier la carte et le détenteur de la carte. L'utilisation de la clé privée associée est protégée par le code PIN de l'application, qui doit être fourni une fois et la clé peut alors être utilisée jusqu'à ce que la carte soit réinitialisée ou retirée du lecteur ou du port USB. GnuPG utilise cette clé avec son support Secure Shell. La clé d'authentification de carte (PIV.9E) est également connue sous le nom de CAK et est utilisée pour prendre en charge les applications d'accès physique. La clé privée n'est pas protégée par un code PIN et peut donc être utilisée immédiatement. La clé de signature numérique (PIV.9C) est utilisée pour signer numériquement des documents. L'utilisation de la clé privée associée est protégée par le code PIN de l'application, qui doit être fourni pour chaque opération de signature. La clé de gestion des clés (PIV.9D) est utilisée pour le chiffrement. L'utilisation de la clé privée associée est protégée par le code PIN de l'application, qui doit être fourni une seule fois afin que les opérations de déchiffrement puissent être effectuées jusqu'à ce que la carte soit réinitialisée ou retirée du lecteur ou du port USB.

Nous allons maintenant générer trois des quatre clés. Notez que GnuPG n'utilise actuellement pas la clé d'authentification de carte ; cependant, cette clé est obligatoire selon la norme PIV et nous la créons donc également. La génération de clés nécessite que nous nous authentifiions auprès de la carte. Cela peut se faire soit sur la ligne de commande (ce qui révélerait la clé) :

gpg/card> auth 010203040506070801020304050607080102030405060708

soit en lisant la clé à partir d'un fichier. Ce fichier doit consister en une seule ligne terminée par LF avec la clé encodée en hexadécimal (comme ci-dessus) :

gpg/card> auth < myauth.key

Comme d'habitude, ‘help auth’ donne de l'aide pour cette commande. Un message d'erreur est affiché si une clé non correspondante est utilisée. L'authentification est valide jusqu'à une réinitialisation de la carte ou jusqu'à ce que la carte soit retirée du lecteur ou du port USB. Notez qu'en mode non interactif, le ‘<’ doit être mis entre guillemets pour que le shell ne l'interprète pas comme son propre symbole de redirection.

Voici les commandes réelles pour générer les clés :

gpg/card> generate --algo=nistp384 PIV.9A
PIV card no. yk-9074625 detected
gpg/card> generate --algo=nistp256 PIV.9E
PIV card no. yk-9074625 detected
gpg/card> generate --algo=rsa2048 PIV.9C
PIV card no. yk-9074625 detected

Si une clé a déjà été créée pour l'un des slots, une erreur sera affichée ; pour créer une nouvelle clé de toute façon, l'option ‘--force’

peut être utilisé. Notez que seules les clés privée et publique ont été créées mais aucun certificat n'est stocké dans les emplacements de clé. En fait, GnuPG utilise sa propre méthode non standard pour stocker uniquement la clé publique à la place du certificat. Les autres applications ne pourront pas utiliser ces clés tant que gpgsm ou un autre outil n'a pas été utilisé pour créer et stocker les certificats respectifs. Voyons ce que la commande list affiche maintenant

gpg/card> list

L'information principale pour chaque clé est le keygrip, une chaîne hexadécimale de 40 octets identifiant la clé. Ce keygrip est un identifiant unique pour les paramètres spécifiques d'une clé. Il est utilisé par gpg-agent et d'autres parties de GnuPG pour associer une clé privée à son format de certificat spécifique au protocole (X.509, OpenPGP ou SecureShell). Sous le keygrip, la référence de la clé est affichée avec les capacités d'utilisation de la clé. Enfin, l'algorithme est imprimé dans le format utilisé par {gpg}. À ce stade, aucune autre information n'est affichée car pour ces nouvelles clés, gpg ne pourra pas trouver de certificats

correspondants.

Notez la dernière étape qui a importé le certificat créé. Si vous aviez plutôt créé une demande de signature de certificat (CSR) au lieu d'un certificat auto-signé et l'aviez envoyée à une autorité de certification (CA), vous feriez la même étape d'importation avec le certificat reçu de la CA. Notez le keygrip (préfixé par une esperluette) tel qu'affiché lors de la création du certificat ou listez-le à nouveau en utilisant ‘gpgsm --with-keygrip -k otto@example.net’. Pour déplacer maintenant la clé et le certificat sur la carte, lancez gpg-card à nouveau et entrez

: 
gpg/card> writekey PIV.9D 34798AAFE
0A7565088101CC4AE31C5C8C74461CB gp
g/card> writecert PIV.9D < encr.crt

Si vous avez entré une phrase secrète pour protéger la clé privée, on vous la demandera via l'invite de Pinentry. En cas de succès, la clé et le certificat ont été écrits sur la carte et une commande list affiche

[...]

Si la même clé (identifiée par le keygrip) a été utilisée pour plusieurs certificats, vous verrez plusieurs parties « used for ». Avec cela, la clé de chiffrement est maintenant entièrement fonctionnelle et peut être utilisée pour déchiffrer des messages chiffrés avec ce certificat. Attention : la clé d'origine est toujours stockée sur le disque et devrait être déplacée vers un support de sauvegarde. Cela peut simplement se faire en copiant le fichier ‘34798AAFE0A7565088101CC4AE31C5C8C74461CB.key’ du répertoire ‘~/.gnupg/private-keys-v1.d/’ vers le support de sauvegarde et en supprimant le fichier à son emplacement

d'origine.
