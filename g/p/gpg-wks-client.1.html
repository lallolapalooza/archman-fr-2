DESCRIPTIO

N

Le gpg-wks-client est utilisé pour envoyer des requêtes à un fournisseur de Web Key Service. Cela se fait généralement pour téléverser une clé dans un Web Key

Directory.

Avec la commande --supported, l'appelant peut tester si un site prend en charge le Web Key Service. L'argument est une adresse arbitraire dans le domaine à tester. Par exemple «foo@example.net ». La commande renvoie le succès si le Web Key Service est pris en charge. L'opération est silencieuse ; pour obtenir une sortie de diagnostic, utilisez l'option --verbose. Voir l'option --with-colons pour une variante de cette

commande.

Avec la commande --check, l'appelant peut tester si une clé existe pour une adresse mail fournie. La commande renvoie le succès si une clé est

disponible.

La commande --create est utilisée pour envoyer une requête de publication dans le Web Key Directory. Les arguments sont l'empreinte de la clé et l'identifiant utilisateur à publier. La sortie de la commande est un courriel correctement formaté avec tous les en-têtes standard. Ce courriel peut être transmis à sendmail(8) ou à tout autre outil pour envoyer réellement ce courriel. Si sendmail(8) est installé, l'option --send peut être utilisée pour envoyer directement la requête créée. Si le fournisseur demande un identifiant utilisateur « mailbox-only » et qu'un tel identifiant n'est pas trouvé, gpg-wks-client essaiera un identifiant utilisateur

supplémentaire.

Les commandes --receive et --read sont utilisées pour traiter les courriels de confirmation envoyés par le fournisseur de service. La première attend un message MIME chiffré, la seconde un message MIME déjà déchiffré. Le résultat de ces commandes est un autre courriel qui peut être envoyé de la même manière que le courriel créé avec --create

.

La commande --install-key installe manuellement une clé dans un répertoire local (voir l'option -C) reflétant la structure d'un WKD. Les arguments sont un fichier contenant le bloc de clé et l'identifiant utilisateur à installer. Si le premier argument ressemble à une empreinte, la clé est prise du trousseau courant ; pour forcer l'utilisation d'un fichier, préfixez le premier argument avec « ./ ». Si aucun argument n'est donné, les paramètres sont lus depuis stdin ; le format attendu est des lignes contenant l'empreinte et la boîte aux lettres séparées par un espace. La commande --remove-key supprime une clé de ce répertoire, son seul argument est un identifiant

utilisateur.

La commande --mirror est similaire à --install-key mais prend les clés du serveur LDAP configuré pour Dirmngr. Si aucun argument n'est donné, toutes les clés et identifiants utilisateurs sont installés. Si des arguments sont donnés, ils sont considérés comme des noms de domaine pour limiter les clés à installer. L'option --blacklist peut être utilisée pour limiter davantage les clés à

installer.

La commande --print-wkd-hash affiche les identifiants utilisateur WKD et les boîtes aux lettres correspondantes à partir des identifiants utilisateurs donnés sur la ligne de commande ou via stdin (un identifiant utilisateur par ligne)

.

La commande --print-wkd-url affiche les URL utilisées pour récupérer la clé pour les identifiants utilisateurs donnés depuis le WKD. Le format désormais préféré avec des sous-domaines est utilisé

ici.

EXEMPLE

S

Pour utiliser les services avec des clients ne disposant pas d'une prise en charge intégrée, le mécanisme mailcap peut être utilisé. Mettez simplement

: 
application/vnd.gnupg.wks; \
  /usr/bin/gpg
-wks-client -v --read --send; \ needstermi
nal; \ description=WKS message dans le «/etc/mailcap ». Cela suppose qu'un /usr/lib/sendmail est installé. Avec cette configuration, tous les programmes de courriel réels exécuteront gpg-wks-client pour les messages reçus d'un Web Key
Service.
