gpm-root - un gestionnaire par défa

ut pour gpm, utilisé pour dessiner
des menus sur la fenêtre racine

SYNOPSI

S

gpm-root [ opti

ons
]

DESCRIPTIO

N

Le programme gpm-root est conçu pour gérer les événements Ctrl-Souris afin de dessiner des menus sur l'arrière-plan du tty courant. Les menus réels sont décrits par un fichier de configuration dans le répertoire personnel de

l'utilisateur.

Veuillez noter que gpm-root nécessite Linux 1.1.73 ou plus récent, car les noyaux précédents manquent de certaines capacités de gestion de l'écran nécessaires au

programme.

Le programme utilise les fichiers /dev/vcs* pour dessiner sur l'écran de la console. Ceux-ci ne sont disponibles qu'à partir du noyau 1.1.81. Si vous n'avez pas ces nœuds de périphérique, vous devriez les créer en utilisant create_vcs dans le répertoire de la distribution. L'outil ne fonctionnera pas avec des noyaux antérieurs à 1.1.81, car ils manquaient d'une capacité complète de capture/restauration de

l'écran.

Les options de ligne de commande disponibles sont les suivantes

:
-m nomb
re
Choisir le modificateur à utiliser (par défaut : control). Le modificateur peut être fourni soit sous forme de nombre, soit sous forme de chaîne symbolique. Les chaînes autorisées sont shift, anyAlt, leftAlt, rightAlt,
control.
-
u
Refuser l'utilisation des fichiers de configuration spécifiques à l'utilisateur. Avec cette option activée, seul /etc/gpm-root.conf sera utilisé comme source d'informations de configuration. Cette option est destinée aux administrateurs système qui craignent que la sécurité puisse être compromise par ce démon. Les choses devraient être suffisamment sécurisées, mais si vous trouvez une faille, merci de me le
signaler.
-
D
Ne pas entrer automatiquement en mode arrière-plan au démarrage, et consigner les messages dans le flux d'erreur standard, et non via le mécanisme syslog. Cela est utile pour le débogage ; dans les versions précédentes, cela se faisait avec une option de
compilation.
-V incrément de
verbosité
Augmenter le niveau maximal des messages qui seront consignés. Ainsi, un argument positif a pour effet de rendre le programme plus verbeux. On peut aussi donner un argument négatif pour rendre le programme silencieux ; cependant, notez qu'en raison des règles de getopt(3), un argument négatif doit suivre l'option sans espace entre les deux (c'est-à-dire -
V-1 mais pas -V -1). Program Arguments,,,libc. L'
argument est facultatif et sa valeur par défaut est 1.

Chaque fois qu'un menu est dessiné, le fichier de configuration est reanalysé s'il a changé. Cela permet de modifier la configuration personnelle sans réinvoquer le

démon.

Le fichier de configuration réel est mieux présenté en regardant votre /etc/gpm-root.conf.

La syntaxe du fichier ne sera pas décrite ici, étant assez apparente à partir de l'exemple ci-dessus. Les espaces et les retours à la ligne ne sont pas utilisés lors de l'analyse du fichier, et la disposition du fichier est libre. Les commentaires sont autorisés dans le fichier : tout caractère dièse (#) trouvé au début de la ligne ou après une espace blanche fait que l'analyseur ignore tout jusqu'à la ligne suivante. Pour insérer des guillemets (") dans des chaînes, précez-les d'une barre oblique

inverse.

Notez que les menus récursifs sont autorisés, à n'importe quel niveau de

récursion.

Les mots-clés appartiennent à trois groupes : le mot-clé button, les mots-clés cfg et les mots-clés d'action. Ils sont tous décrits dans le tableau ci-dessous

:
button nombre me
nu
Le mot-clé button est utilisé pour introduire un menu. Il est suivi du numéro du bouton concerné (1=gauche, 2=millieu, 3=droit), d'une accolade ouvrante,
d'un menu et d'une accolade fermante. Un menu est composé d'instructions cfg, suivies d'instructions d'action. Les instructions cfg peuvent apparaître dans n
'importe quel ordre, tandis que l'ordre des instructions d'action indique l'ordre réel dans lequel les actions apparaîtront sur l'écran, de haut en bas.

Les instructions suivantes appartiennent à l'ensemble

cfg.
name chaî
ne
Si le mot-clé name est présent, la chaîne spécifiée sera utilisée comme nom pour le menu
courant.
background coul
eur
Cette instruction est utilisée pour spécifier la couleur d'arrière-plan à utiliser dans le menu courant. La couleur peut être spécifiée avec l'une des huit chaînes canoniques black, red, cyan etc. L'arrière-plan est par défaut
black.
foreground coul
eur
Cette instruction est utilisée pour spécifier la couleur de premier plan des éléments du menu. Sa valeur par défaut est white. Un mot-clé bright facultatif peut apparaître avant la couleur
réelle.
border coul
eur
border est utilisé pour spécifier la couleur de la bordure du menu. Sa valeur par défaut est white. Un mot-clé bright facultatif peut apparaître avant la couleur
réelle.
head coul
eur
head est utilisé pour spécifier la couleur de premier plan du t
itre du menu. Sa valeur par défaut est white. Un mot-clé b
right facultatif peut apparaître avant la couleur réelle.

Les instructions suivantes appartiennent à l'ensemble

action.
chaîne f.fgcmd cmdstri
ng
Lorsque le bouton de la souris est relâché au-dessus de l'élément de menu correspondant, la cmdstring est collée dans la file d'attente clavier de la console courante. Ceci n'est pas encore
implémenté.
chaîne f.bgcmd cmdstri
ng
Lorsque le bouton de la souris est relâché au-dessus de l'élément de menu correspondant, un shell (/bin/sh) est forké pour exécuter la commande spécifiée, avec stdin connecté à /dev/null, et stdout, stderr connectés à la console
active.
chaîne f.jptty ttynumb
er
Lorsque le bouton de la souris est relâché au-dessus de l'élément de menu correspondant, la console est commutée à celle spécifiée. Le ttynumber doit être spécifié sous forme de chaîne. N'importe quel tty peut être atteint de cette manière, même ceux qui ne sont pas accessibles via le
clavier.
chaîne f.mktty ttynumb
er
Lorsque le bouton de la souris est relâché au-dessus de l'élément de menu correspondant, une console inutilisée est sélectionnée, et /sbin/mingetty est exécuté dedans. La console courante est commutée vers la console nouvellement ouverte. J'utilise cette commande pour économiser la mémoire du noyau en n'ouvrant qu'une seule console via /etc/inittab et en ne demandant les autres que lorsque j'ai besoin de me
connecter.
chaîne Menu
entier
Un menu peut suivre directement l'étiquette string. Lorsque le pointeur de la souris quitte le cadre du menu au niveau de string, un second menu est affiché sur
l'écran.
chaîne f.
lock
Lorsque le bouton de la souris est relâché au-dessus de l'élément de menu correspondant, le clavier et l'écran sont verrouillés, et seul l'utilisateur ayant verrouillé ou le superutilisateur peut les déverrouiller. Ceci n'est pas encore
implémenté.
chaîne f.
load
La charge moyenne (loadavg) courante lorsque le menu est affiché est concaténée à string pour construire le message réel affiché sur l'écran. Rien ne se passe lors du relâchement du
bouton.
chaîne f.
free
La mémoire libre et la mémoire swap lorsque le menu est affiché sont concaténées à string pour construire le message réel affiché sur l'écran. Rien ne se passe lors du relâchement du
bouton.
chaîne f.
time
L'heure courante est formatée avec strftime(3), selon string. La chaîne résultante est le message réel affiché sur l'écran. Rien ne se passe lors du relâchement du
bouton.
chaîne f.pipe cmdli
ne
Lorsque le pointeur de la souris quitte le cadre du menu au niveau de string, une boîte de message est affichée sur l'écran montrant les dix dernières lignes de la sortie de cmdline. cmdline est exécuté par /bin/sh. Ceci n'est pas encore
implémenté.
chaîne f.
nop
Cela ne fait rien, cela affiche simplement string sur
le
menu.

Les variables d'environnement HOME, LOGNAME et USER sont définies au

x valeurs de l'utilisateur appelant avant de lancer un processus
externe (f.bgcmd, f.pipe). Le répertoire courant est toujours /.
