NOM

gpg-connect-agent - Communiquer avec un agent en cours d'exécution

SYNOPSIS

gpg-connect-agent [options][commandes]

DESCRIPTION

Le programme gpg-connect-agent est un utilitaire pour communiquer avec un agent gpg-agenten cours d'exécution. Il est utile pour examiner les commandes fournies par gpg-agent via l'interface Assuan. Il peut aussi être utile pour scripter de simples applications. L'entrée est attendue sur stdin et la sortie est imprimée sur stdout.

C'est très similaire à l'exécution de gpg-agent en mode serveur ; mais ici nous nous connectons à une instance en cours d'exécution.

Les options suivantes peuvent être utilisées :

--dirmngr
Se connecter à un gestionnaire de répertoire (client de serveur de clés) en cours d'exécution au lieu du gpg-agent. Si un dirmngr n'est pas en cours d'exécution, le démarrer.
--keyboxd
Se connecter à un démon keybox en cours d'exécution au lieu du gpg-agent. Si un keyboxd n'est pas en cours d'exécution, le démarrer.
-S
--raw-socket nom
Se connecter au socket nom en supposant qu'il s'agit d'un serveur de style Assuan. Ne pas exécuter d'initialisations spéciales ni de vérifications d'environnement. Cela peut être utilisé pour se connecter directement à n'importe quel serveur socket de style Assuan.
-E
--exec
Prendre le reste de la ligne de commande comme un programme et ses arguments et l'exécuter comme un serveur Assuan. Voici comment vous exécuteriez gpgsm:
 gpg-connect-agent --exec gpgsm --server
Notez que vous ne pouvez pas utiliser d'options sur la ligne de commande dans ce cas.
-v
--verbose
Afficher des informations supplémentaires pendant l'exécution.
-q
--quiet
Essayer d'être aussi silencieux que possible.
--homedir rép
Définir le nom du répertoire personnel à rép. Si cette option n'est pas utilisée, le répertoire personnel par défaut est «~/.gnupg». Elle n'est reconnue que lorsqu'elle est donnée sur la ligne de commande. Elle remplace également tout répertoire personnel défini par la variable d'environnementGNUPGHOMEou (sur les systèmes Windows) par l'entrée de Registre HKCU\Software\GNU\GnuPG:HomeDir.

Sur les systèmes Windows, il est possible d'installer GnuPG comme une application portable. Dans ce cas, seule cette option de ligne de commande est prise en compte, toutes les autres façons de définir un répertoire personnel sont ignorées.

--chuid uid
Changer l'utilisateur courant en uid qui peut être soit un numéro soit un nom. Cela peut être utilisé depuis le compte root pour exécuter gpg-connect-agent pour un autre utilisateur. Si uid n'est pas l'UID courant, un PATH standard est défini et la variable d'environnement GNUPGHOME est effacée. Pour ignorer ce dernier point, l'option --homedir peut être utilisée. Cette option n'a d'effet que lorsqu'elle est utilisée sur la ligne de commande. Cette option n'a actuellement aucun effet sur Windows.
--no-ext-connect
Lors de l'utilisation de -S ou --exec, gpg-connect-agent se connecte au serveur Assuan en mode étendu pour permettre le passage de descripteurs. Cette option le fait utiliser l'ancien mode.
--no-autostart
Ne pas démarrer le gpg-agent ou le dirmngr s'il n'a pas encore été démarré.
--no-history
En mode interactif, l'historique de la ligne de commande est généralement sauvegardé et restauré depuis et vers un fichier sous le répertoire personnel GnuPG. Cette option inhibe l'utilisation de ce fichier.
--agent-program fichier
Spécifier le programme agent à démarrer si aucun n'est en cours d'exécution. La valeur par défaut est déterminée en exécutant gpgconf avec l'option --list-dirs. Notez que le symbole pipe (|) est utilisé pour un hack de la suite de tests de régression et ne peut donc pas être utilisé dans le nom de fichier.
--dirmngr-program fichier
Spécifier le programme gestionnaire de répertoire (client de serveur de clés) à démarrer si aucun n'est en cours d'exécution. Cela n'a d'effet que s'il est utilisé avec l'option --dirmngr.
--keyboxd-program fichier
Spécifier le programme démon keybox à démarrer si aucun n'est en cours d'exécution. Cela n'a d'effet que s'il est utilisé avec l'option --keyboxd.
-r fichier
--run fichier
Exécuter les commandes du fichier au démarrage puis continuer avec la méthode d'entrée régulière. Notez que les commandes données sur la ligne de commande sont exécutées après ce fichier.
-s
--subst
Exécuter la commande /subst au démarrage.
--hex
Imprimer les lignes de données en format hexadécimal et la représentation ASCII des caractères non contrôle.
--decode
Décoder les lignes de données. C'est-à-dire supprimer les échappements par pourcentage mais s'assurer qu'une nouvelle ligne commence toujours par un D et un espace.
-u
--unbuffered
Mettre stdin et stdout en mode d'E/S non tamponné. C'est parfois utile pour le script.

COMMANDES DE CONTRÔLE

Lors de la lecture des commandes Assuan, gpg-agent permet également quelques commandes spéciales pour contrôler son fonctionnement. Ces commandes de contrôle commencent toutes par une barre oblique (/).

/echo args
Simplement imprimer args.
/let nom valeur
Définir la variable nom à valeur. Les variables ne sont substituées sur l'entrée que si /subst a été utilisé. Les variables sont référencées en préfixant le nom d'un signe dollar et éventuellement en incluant le nom entre accolades. Les règles pour un nom valide sont identiques à celles du shell standard bourne. Ceci n'est pas encore appliqué mais pourrait l'être à l'avenir. Lorsqu'il est utilisé avec des accolades, aucun espace blanc initial ou final n'est autorisé.

Si une variable n'est pas trouvée, elle est recherchée dans l'environnement et si elle est trouvée, copiée dans la table des variables.

Des fonctions de variables sont disponibles : Le nom de la fonction doit être suivi d'au moins un espace et d'au moins un argument. Les fonctions suivantes sont disponibles :

get
Retourner une valeur décrite par l'argument. Les arguments disponibles sont :
cwd
Le répertoire de travail courant.
homedir
Le répertoire personnel gnupg.
sysconfdir
Le répertoire de configuration système de GnuPG.
bindir
Le répertoire binaire de GnuPG.
libdir
Le répertoire de bibliothèques de GnuPG.
libexecdir
Le répertoire de bibliothèques de GnuPG pour les fichiers exécutables.
datadir
Le répertoire de données de GnuPG.
serverpid
Le PID du serveur courant. La commande /serverpid doit avoir été donnée pour retourner une valeur utile.
unescape args
Supprimer les échappements de style C de args. Notez que \0 et \x00 terminent implicitement la chaîne retournéecitly. La chaîne à convertir est constituée de l'ensemble des arguments situés après l'espace délimitant le nom de la fonction.
unpercent args
unpercent+ args
Supprime l'échappement de style pourcentage de args. Notez que %00 termine implicitement la chaîne. La chaîne à convertir est constituée de l'ensemble des arguments situés après l'espace délimitant le nom de la fonction. unpercent+ mappe également les signes plus vers des espaces.
percent args
percent+ args
Échappe args en utilisant l'échappement de style pourcentage. Les tabulations, les sauts de page, les sauts de ligne, les retours à la ligne et les deux-points sont échappés. percent+ mappe également les espaces vers des signes plus.
errcode arg
errsource arg
errstring arg
Suppose que arg est un entier et l'évalue en utilisant strtol. Retourne le code d'erreur gpg-error, la source de l'erreur ou une chaîne formatée avec le code d'erreur et la source de l'erreur.
+
-
*
/
%
Évalue tous les arguments comme des entiers longs en utilisant strtol et applique cet opérateur. Une division par zéro produit une chaîne vide.
!
|
&
Évalue tous les arguments comme des entiers longs en utilisant strtol et applique les opérateurs logiques NOT, OR ou AND. L'opérateur NOT ne fonctionne que sur le dernier argument.
/definq name var
Utilise le contenu de la variable var pour les requêtes avec name. name peut être un astérisque (*) pour correspondre à n'importe quelle requête.
/definqfile name file
Utilise le contenu de file pour les requêtes avec name. name peut être un astérisque (*) pour correspondre à n'importe quelle requête.
/definqprog name prog
Exécute prog pour les requêtes correspondant à name et lui transmet la ligne entière en tant qu'arguments de ligne de commande.
/datafile name
Écrit toutes les lignes de données du serveur dans le fichier name. Le fichier est ouvert en écriture et créé s'il n'existe pas. Un fichier existant est d'abord tronqué à 0. Les données écrites dans le fichier sont entièrement décodées. L'utilisation d'un tiret unique pour name écrit sur stdout. Le fichier reste ouvert jusqu'à ce qu'un nouveau fichier soit défini avec cette commande ou que cette commande soit utilisée sans argument.
/showdef
Affiche toutes les définitions
/cleardef
Supprime toutes les définitions
/sendfd file mode
Ouvre file en mode (qui doit être une chaîne de mode fopen valide) et envoie le descripteur de fichier au serveur. Ceci est généralement suivi par une commande comme INPUT FD pour définir la source d'entrée pour d'autres commandes.
/recvfd
Pas encore implémenté.
/open var file [mode]
Ouvre file et assigne le descripteur de fichier à var. Attention : Cette commande est expérimentale et pourrait changer dans des versions futures.
/close fd
Ferme le descripteur de fichier fd. Attention : Cette commande est expérimentale et pourrait changer dans des versions futures.
/showopen
Affiche une liste des fichiers ouverts.
/serverpid
Envoie la commande Assuan GETINFO pid au serveur et stocke le PID retourné à des fins internes.
/sleep
Dors pendant une seconde.
/hex
/nohex
Identique à l'option de ligne de commande --hex.
/decode
/nodecode
Identique à l'option de ligne de commande --decode.
/subst
/nosubst
Active et désactive la substitution de variables. Elle est désactivée par défaut, sauf si l'option de ligne de commande --subst a été utilisée. Si /subst a été activé une fois, les espaces de début de ligne sont supprimés des lignes d'entrée, ce qui facilite la lecture des scripts.
/while condition
/end
Ces commandes fournissent un moyen d'exécuter des boucles. Toutes les lignes entre while et le end correspondant sont exécutées tant que l'évaluation de condition produit une valeur non nulle ou est la chaîne true ou yes. L'évaluation est faite en passant condition à la fonction strtol . Exemple : 
  /subst
  /let i 3
  /while $i
    /echo loop counter is $i
    /let i ${- $i 1}
  /end
/if condition
/end
Ces commandes fournissent un moyen d'exécution conditionnelle. Toutes les lignes entre le if et le end correspondant ne sont exécutées que si l'évaluation de condition produit une valeur non nulle ou est la chaîne true ou yes. L'évaluation est faite en passant condition à la fonction strtol .
/run file
Exécute les commandes de file.
/history --clear
Efface l'historique des commandes.
/bye
Termine la connexion et le programme.
/help
Affiche une liste des commandes de contrôle disponibles.
