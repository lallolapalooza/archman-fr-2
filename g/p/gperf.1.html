DESCRIPTIO

N

GNU « gperf » génère des fonctions de hachage

parfaites.

Si une option longue indique un argument comme obligatoire, alors il est obligatoire pour l'option courte équivalente

également.

Emplacement du fichier de sortie

:

--output-file=FICHIER Écrit la sortie dans le fichier

spécifié.

Les résultats sont écrits sur la sort

ie standard si aucun fichier de sort
ie n'est spécifié ou s'il vaut -.

:
-e, --delimiters=LISTE-DE-SÉPARAT
EURS
Permet à l'utilisateur de fournir une chaîne contenant les séparateurs utilisés pour séparer les mots-clés de leurs attributs. La valeur par défaut est «
, ».
-t, --struct-ty
pe
Permet à l'utilisateur d'inclure une déclaration de type structuré pour le code généré. Tout texte avant %% est considéré comme faisant partie de la déclaration de type. Des mots- clés et des champs supplémentaires peuvent suivre, un groupe de champs par
ligne.
--ignore-ca
se
Considère les caractères ASCII en majusc
ules et en minuscules comme équivalents.
Notez que les correspondances de c
as dépendant de la locale sont ignorées.

Détails du code de sortie

:
-K, --slot-name=NO
M
Sélectionne le nom du composant du mot-clé dans la structure de
mot-clé.
-F, --initializer-suffix=INITIALISATE
URS
Initialiseurs pour les composants supplémentaires dans la structure de
mot-clé.
-H, --hash-function-name=NO
M
Spécifie le nom de la fonction de hachage générée. La valeur par défaut est « hash
».
-N, --lookup-function-name=NO
M
Spécifie le nom de la fonction de recherche générée. Le nom par défaut est « in_word_set
».
-Z, --class-name=NO
M
Spécifie le nom de la classe C++ générée. Le nom par défaut est « Perfect_Hash

-7, --seven-b

Suppose des caracteurs sur 7

-l, --compare-leng
ths
Compare les longueurs des clés avant d'essayer une comparaison de chaînes. C'est nécessaire si les mots-clés contiennent des octets NUL. Cela aide également à réduire le nombre de comparaisons de chaînes effectuées lors de la
recherche.
-c, --compare-strn
cmp
Génère du code de comparaison utilisant strncmp plutôt que
strcmp.
-C, --readonly-tab
les
Rend le contenu des tables de recherche générées constant, c'est-à-dire en lecture
seule.
-E, --en
um
Définit des valeurs constantes à l'aide d'un enum local à la fonction de recherche plutôt qu'avec des

-I, --includ

Inclut le fichier d'en-tête système nécessaire <string.h> au début du
code.
-G, --global-tab
le
Génère la table statique de mots-clés en tant que variable globale statique, plutôt que de la cacher à l'intérieur de la fonction de recherche (ce qui est le comportement par défaut)
.
-P, --p
ic
Optimise la table générée pour son inclusion dans des bibliothèques partagées. Cela réduit le temps de démarrage des programmes utilisant une bibliothèque partagée contenant le code
généré.
-Q, --string-pool-name=NO
M
Spécifie le nom du pool de chaînes généré par l'option --pic. Le nom par défaut est « stringpool
».
--null-strin
gs
Utilise des chaînes NULL au lieu de chaînes vides pour les entrées de table de mots-clés
vides.
--constants-prefix=PRÉFI
XE
Spécifie le préfixe pour les constantes comme
TOTAL_KEYWORDS.
-W, --word-array-name=NO
M
Spécifie le nom du tableau de liste de mots. Le nom par défaut est « wordlist
».
--length-table-name=NO
M
Spécifie le nom du tableau de longueurs. Le nom par défaut est « lengthtable
».
-S, --switch=NOMB
RE
Fait en sorte que le code C généré utilise un schéma d'instruction switch plutôt qu'une table de recherche par tableau. Cela peut entraîner une réduction des besoins en temps et en espace pour certains fichiers de clés. L'argument NOMBRE détermine combien d'instructions switch sont générées. Une valeur de 1 génère 1 switch contenant tous les éléments, une valeur de 2 génère 2 tables avec 1/2 des éléments dans chaque table, etc. Si NOMBRE est très grand, disons 1000000, le code C généré effectue une recherche
binaire.
-T, --omit-struct-t
ype
Empêche le transfert de la déclara

tie. Utilisez cette option si

Algorithme utilisé par gperf

:
-k, --key-positions=CL
ÉS
Sélectionne les positions de clés utilisées dans la fonction de hachage. Les choix possibles vont de 1 à 255 inclus. Les positions sont séparées par des virgules, des plages peuvent être utilisées et les positions de clés peuvent apparaître dans n'importe quel ordre. De plus, le méta-caractère « * » fait en sorte que la fonction de hachage générée considère TOUTES les positions de clés, et $ indique le « dernier caractère » d'une clé, par ex. $,1,2,4,
6-10.
-D, --duplicat
es
Gère les mots-clés qui produisent des valeurs de hachage en double. C'est utile pour certains ensembles de mots-clés hautement
redondants.
-m, --multiple-iterations=ITÉRATIO
NS
Effectue plusieurs choix de valeurs -i et -j, et choisit les meilleurs résultats. Cela augmente le temps d'exécution d'un facteur ITÉRATIONS mais fait un bon travail pour minimiser la taille de la table
générée.
-i, --initial-asso=
N
Fournit une valeur initiale pour le tableau des valeurs associées. La valeur par défaut est 0. Régler cette valeur plus haute aide à gonfler la taille de la table
finale.
-j, --jump=VALEUR-DE-S
AUT
Affecte la « valeur de saut », c'est-à-dire de combien avancer la valeur de caractère associée en cas de collision. Doit être un nombre impair, la valeur par défaut
est 5.
-n, --no-strl
en
N'inclut pas la longueur du mot-clé lors du calcul de la fonction de
hachage.
-r, --rand
om
Utilise l'aléatoire pour initialiser le tableau des valeurs
associées.
-s, --size-multiple=
N
Affecte la taille de la table de hachage générée. L'argument numérique N indique « combien de fois plus grand ou plus petit » la plage de valeurs associées devr
ait être, par rapport au nombre de clés, par ex. une valeur de 3 signifie « permettre à la valeur associée maximale d'être environ 3 fois plus grande que le nomb
re de clés d'entrée ». Inversement, une valeur de 1/3 signifie « rendre la valeur associée maximale environ 3 fois plus petite que le nombre de clés d'entrée ».
Une table plus grande devrait diminuer le temps requis pour une recherche infructueuse, au prix d'un espace de table supplémentaire. La valeur par défaut est 1. ss="Ss">
