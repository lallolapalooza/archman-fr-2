DESCRIPTIO

N

gpsctl peut basculer un récepteur GNSS double mode entre les modes NMEA et binaire du fabricant. Il peut également être utilisé pour définir le débit en bauds de l'appareil. Remarque : tous les appareils ne disposent pas de ces fonctionnalités

.

Si vous n'avez qu'un seul récepteur GNSS connecté à votre machine, et que gpsd est en cours d'exécution, il n'est pas nécessaire de spécifier l'appareil ; gpsctl effectue son travail via gpsd, qui le localisera pour

vous.

Lorsque gpsd est en cours d'exécution, gpsctl peut être exécuté par n'importe quel utilisateur, ou en tant que

root.

Lorsque gpsd n'est pas en cours d'exécution, la spécification de l'appareil est requise, et vous devrez exécuter le programme en tant que root ou être membre du groupe propriétaire de l'appareil afin d'avoir un accès en écriture à l'appareil. Sur de nombreuses variantes Unix, le groupe propriétaire sera nommé

'dialout'.

L'exécution sous sudo entraînera une perte de

fonctionnalités
.

OPTION

S

Le programme accepte les options suivantes

:

-?, -h, --hel

p
Affiche l'utilisation du programme et se
termine.

-b, --binar

y
Passe le récepteur GNSS en mode natif (binaire)
.

-c DÉBIT, --rate

DÉBIT
Change le temps de cycle du récepteur. Les unités sont en secondes. Remarque, la plupart des récepteurs ont un temps de cycle fixe de 1
seconde.

-D NIV, --debug

NIV
Définit le niveau des messages de
débogage.

-e, --ech

o
Génère le paquet à partir de tous les autres arguments spécifiés et l'envoie sur la sortie standard au lieu de l'appareil. Ce commutateur peut être utilisé avec l'option -t sans spécifier d'appareil. Remarque : les données du paquet pour un prototype binaire seront brutes, non converties en ASCII d'aucune
manière.

-f, --forc

e
Force l'accès bas niveau, direct (non via le démon)
.

-l, --lis

t
Liste un tableau montrant quels commutateurs d'options peuvent être appliqués à quels types d'appareils, puis se
termine.

-n, --nme

a
Passe le récepteur GNSS en mode
NMEA.

-r, --rese

t
Réinitialise le récepteur GNSS. Le port et le type de l'appareil doivent être
spécifiés.

-R, --rmsh

m
Supprime le segment de mémoire partagée GPSD utilisé pour l'exportation SHM. Cette option ne sera généralement d'intérêt que pour les développeurs de
GPSD.

-s VITESSE, --speed

VITESSE
Définit le débit en bauds auquel le récepteur émet les
paquets.

Utilisez l'option -s avec prudence. Sur les GPS USB et Bluetooth, il est également possible que la configuration du mode série échoue, soit parce que la puce d'adaptateur série ne prend pas en charge les modes autres que 8N1, soit parce que le micrologiciel de l'appareil ne synchronise pas correctement la puce d'adaptateur série avec l'UART de la puce GPS lorsque la vitesse change. Ces échecs peuvent bloquer votre appareil, nécessitant éventuellement un cycle d'alimentation du GPS ou (dans les cas extrêmes) la déconnexion physique de la batterie de secours

NVRAM.

-t TYPE, --type

TYPE
Force le type
d'appareil.

-T DÉLAI, --timeout

DÉLAI
Change le délai d'attente de l'échantillonnage. La valeur par défaut est de 8 secondes, ce qui devrait toujours être suffisant pour obtenir un paquet d'identification d'un appareil émettant au débit normal de 1 par
seconde.

-V, --versio

n
Affiche la version du programme et se
termine.

-x CHAÎNE, --ship

CHAÎNE
Envoie la chaîne de contrôle spécifiée au récepteur GNSS. Les échappements de barre oblique de style C dans la chaîne sont décodés. Utilisez \xNN pour l'hexadécimal, \e sera remplacé par ESC. 
En mode normal, via _gpsd_, la chaîne décodée est transmise
inch
angée à _gpsd_, qui l'envoie à son tour au récepteur. Les en-têt
es, les sommes de contrôle et les suffixes doivent être fournis. 
En mode bas niveau (direct), *gpsctl* fournira les en-têtes de paquets et
les
traînées ainsi que la somme de contrôle selon le type de paquet binaire, et
toute somme de contrôle et traînée requises pour les types de paquets texte. 
Vous devez incluir
e le $ initial pour
les paquets NMEA. 
Lors de l'envoi à un appareil UBX, Allystar ou CASIC, les d
eux premiers octets de la chaîne fournie deviendront la clas
se et le type de message, et le reste sera la charge utile. 
Lors de l'envoi à un appareil Navcom NCT ou Trimble
TSIP, le premier octet est interprété comme l'iden
tifiant de commande et le reste comme charge utile. 
Lors de l'envoi à un appareil Zodiac, les deux premiers octets sont utilisés com
me un identifiant de message de type court little-endian, et le reste comme char
ge utile en paires d'octets interprétées comme des entiers courts little-endian. 
Pour tous les autres GPS binaires pris en charge (notamm
ent SiRF), la chaîne est considérée comme la charge util
e complète du message et est enveloppée avec les octets d
'en-tête, de traînée et de somme de contrôle appropriés.

L'argument de l'option de forçage, -t, doit être une chaîne qui est contenue dans exactement un des noms de pilotes connus ; pour une liste, exécutez gpsctl

-l.

Le forçage du type d'appareil se comporte quelque peu différemment selon que cet outil passe par le démon ou non. En mode haut niveau, si l'appareil que le démon sélectionne pour vous ne correspond pas au pilote que vous avez spécifié, gpsctl se termine avec un avertissement. (Cela peut être utile dans des scripts.

)

En mode bas niveau, si l'appareil s'identifie comme un Generic NMEA, utilisez le pilote sélectionné à la place. Cela sera utile si vous avez un appareil GPS de type connu qui est en mode NMEA et ne répond pas aux sondes. (Cette option a été initialement mise en œuvre pour communiquer avec les puces SiRFStar I, qui ne répondent pas à la sonde d'identification SiRF normale.

)

Si aucune option n'est donnée, le programme affichera un message identifiant le type GPS de l'appareil sélectionné puis se

terminera.

Les opérations de réinitialisation (-r) doivent être exécutées seules ; les autres peuvent être combinées. gpsctl exécutera plusieurs options dans cet ordre : changement de mod

e (-b ou -n) en premier, changements de vitesse (-s) en second, tau
x de cycle (-c) en troisième et chaînes de contrôle (-x) en dernier.

VARIABLES

D'ENVIRONNEMENT

En définissant la variable d'environnement GPSD_SHM_KEY, vous pouvez contrôler la valeur de clé utilisée pour désigner le segment de mémoire partagée supprimé avec l'option -R. Cela sera principalement utile lors de l'isolation des instances de test de gpsd par rapport aux i

nstances de
production.

EXEMPLE

S

gpsctl

/dev/ttyUSB0
Tente d'identifier l'appareil sur le périphérique série USB 0. Expire après le nombre de secondes par défaut. L'ajout de -f forcera l'accès bas niveau et supprimera la plainte normale lorsque cet outil ne peut pas trouver un GPSD avec lequel
travailler.

gpsctl -f -n -s 9600

/dev/ttyUSB0
Utilise des opérations bas niveau (sans passer par une instance gpsd) pour basculer un GPS en mode NMEA à 9600bps. L'outil identifiera le type de GPS
lui-même.

gpsctl -x '\xb5\x62\x0a\x04\x00\x00\x0e\x34

'
Envoie une requête pour UBX-MON-VER à un récepteur GNSS c
onnecté à
gpsd.

BOGUE

S

Les GPS SiRF ne peuvent être identifiés que par la réussite d'une tentative de les faire basculer en mode binaire SiRF. Ainsi, le processus de sondage de l'un d'eux fonctionnant en NMEA changera son

comportement.

Les changements de débit en bauds et de mode fonction

nent en mode direct mais ne sont pas fiables en mo
de client. Cela sera corrigé dans une future version.
