NOM

gpart - deviner les partitions de disques durs de type PC

SYNOPSIS

gpart [options] périphérique

Options : [-b <MBR de sauvegarde>][-C c,h,s][-c][-d][-E][-e][-f] [-g][-h][-i][-K <dernier secteur>][-k <nombre de secteurs>] [-L] [-l <fichier journal>][-n <incrément>] [-q][-s <taille de secteur>] [-t <nom de module>][-V][-v] [-W <périphérique>][-w <nom de module, poids>]

DESCRIPTION

gpart essaie de deviner quelles partitions se trouvent sur un disque dur. Si la table de partitions primaire a été perdue, écrasée ou détruite, les partitions existent toujours sur le disque mais le système d'exploitation ne peut pas y accéder.

gpart ignore la table de partitions primaire et scanne le disque (ou l'image de disque, le fichier) secteur après secteur à la recherche de plusieurs types de systèmes de fichiers/partitions. Il le fait en « demandant » aux modules de reconnaissance de systèmes de fichiers s'ils pensent qu'une séquence donnée de secteurs ressemble au début d'un système de fichiers ou d'un type de partition. Actuellement, les types de systèmes de fichiers suivants sont connus de gpart (listés par noms de modules) :

beos
Type de système de fichiers BeOS.
bsddl
Schéma de sous-partitionnement disklabel FreeBSD/NetBSD/386BSD utilisé sur les plateformes Intel.
ext2
Système de fichiers étendu de deuxième génération de Linux.
fat
« Systèmes de fichiers » MS-DOS FAT12/16/32.
hpfs
Système de fichiers haute performance IBM OS/2.
hmlvm
Volumes physiques LVM de Linux (LVM par Heinz Mauelshagen).
lswap
Partition d'échange Linux (versions 0 et 1).
minix
Type de système de fichiers du système d'exploitation Minix.
ntfs
Système de fichiers MS Windows NT/2000.
qnx4
Système de fichiers QNX 4.x.
reiserfs
Le système de fichiers Reiser (version 3.5.X, X > 11, 3.6.X).
s86dl
Sun Solaris sur les plateformes Intel utilise un schéma de sous-partitionnement sur les disques durs PC similaire aux disklabels BSD.
xfs
Le système de fichiers journalisé de Silicon Graphics pour Linux.

D'autres modules de devinette de systèmes de fichiers peuvent être ajoutés à l'exécution (voir l' -t option). Veuillez consulter le fichier gpart README pour des explications détaillées sur la façon de créer des modules de devinette. Tous les modules sont accompagnés d'un facteur de poids de devinette qui indique à quel point leurs devinettes sont « éclairées » par rapport aux autres modules. Ce poids peut être modifié si un certain module continue d'identifier à tort une partition.

Naturellement, seules les partitions qui ont été formatées d'une certaine manière peuvent être reconnues. Si le type d'une entrée de partition dans la table de partitions primaire est changé de x en y alors que le système de fichiers est toujours de type x, gpart devinera toujours un type x.

Aucune vérification n'est effectuée pour savoir si un système de fichiers trouvé est propre ou même cohérent/montable, il est donc tout à fait possible que gpart puisse identifier des partitions qui existaient avant le schéma de partitionnement actuel du disque. Surtout sur les grands disques, les anciens en-têtes de système de fichiers/superblocs peuvent rester présents longtemps avant d'être finalement écrasés par les données de l'utilisateur.

Il faut souligner que gpart fait un travail très heuristique, ne croyez jamais sa sortie sans aucun contrôle de plausibilité. Il peut facilement avoir raison dans ses devinettes, mais il peut aussi avoir terriblement tort. Vous avez été averti.

Après avoir trouvé une liste de types de partitions possibles, la liste est vérifiée pour sa cohérence. Par exemple, une partition qui se chevauche avec la précédente sera écartée. Toutes les partitions restantes sont étiquetées avec l'une des attributs suivants : « primaire », « logique », « orpheline » ou « invalide ».

Une partition étiquetée « orpheline » est une partition logique qui semble correcte mais qui est manquée dans la chaîne de partitions logiques. Cela peut se produire si une partition logique est supprimée de la table de partitions étendue sans écraser l'espace disque réel.

Une partition « invalide » est une partition qui ne peut pas être acceptée pour diverses raisons. Si une table de partitions primaire cohérente a été créée dans ce processus, elle est imprimée et peut être écrite dans un fichier ou un périphérique.

PARTITIONS ÉTENDUES

Si le disque/fichier à examiner ne consiste qu'en des partitions primaires, gpart a de bonnes chances de les identifier. Les partitions étendues, en revanche, peuvent entraîner beaucoup de problèmes.

Les partitions étendues sont réalisées comme une liste chaînée de tables de partitions étendues, chacune incluant une entrée pointant vers une partition logique. La taille d'une partition étendue dépend de l'endroit où se termine la dernière partition logique. Cela signifie que les partitions étendues peuvent inclure des « trous », de l'espace disque non alloué qui ne devrait être attribué qu'aux partitions logiques, et non aux primaires.

gpart essaie de faire de son mieux pour vérifier une chaîne de partitions logiques trouvée, mais il y a très nombreux points de défaillance possibles. Si de « bons » programmes fdisk sont utilisés pour créer des partitions étendues, les tables résultantes consistent en un enregistrement d'amorçage mis à zéro et les quatre entrées de partition dont au moins deux devraient être marquées comme inutilisées. Malheureusement, par exemple, le programme fdisk fourni avec Windows NT ne semble pas mettre à zéro la zone de l'enregistrement d'amorçage, donc gpart doit être excessivement tolérant pour reconnaître les tables de partitions étendues. Cette tolérance peut entraîner des devinettes assez stupides.

TRANSFERTS DE DISQUE

Si vous voulez examiner des disques durs provenant d'autres systèmes, vous devriez noter la géométrie (nombre de cylindres, têtes par cylindre et secteurs par tête) utilisée pour ce disque, et indiquer à gpart cette géométrie.

L'examen de disques provenant de machines ayant une finianité différente de celle de l'analyse n'a pas du tout été testé, et n'est actuellement pas recommandé.

GRANDS DISQUES

gpart s'appuie sur le fait que le système d'exploitation signale la géométrie correcte du disque. Malheureusement, parfois le système d'exploitation peut signaler une géométrie plus petite que la réelle (par exemple, des disques avec plus de 1024 ou 16384 cylindres).

gpart vérifie si les partitions devinées s'étendent au-delà de la taille du disque et les marque « invalides », mais peut se tromper si la taille du disque est calculée à partir d'une géométrie incorrecte. Par exemple, si un disque avec la géométrie 1028/255/63 doit être analysé, et que le système d'exploitation signale 1024/255/63 gpart devrait être appelé comme

gpart -C 1028,255,63 <autres options> <périphérique>

PRÉCAUTIONS

gpart peut être d'une certaine aide lorsque la table de partitions primaire a été perdue ou détruite, mais il ne peut en aucune circonstance remplacer des sauvegardes appropriées du disque/de la table de partitions. Pour sauvegarder le secteur d'amorçage principal (MBR) y compris la table de partitions primaire dans un fichier, tapez

dd if=/dev/hda of=mbr bs=512 count=1

en remplaçant /dev/hda par le nom du périphérique de bloc du disque en question. Cela devrait être fait pour tous les disques du système. Pour restaurer la table de partitions primaire sans écraser le MBR, tapez

dd if=mbr of=/dev/hda bs=1 count=64 skip=446 seek=446

Avertissement : assurez-vous que tous les paramètres sont tapés comme indiqué et que le périphérique du disque est correct. Le fait de ne pas le faire peut entraîner une corruption grave du système de fichiers. Le fichier sauvegardé devrait être stocké dans un endroit sûr comme une disquette.
