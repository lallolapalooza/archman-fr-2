GPM-TYPES(7) Manuel d'informations diverses GPM-TYPES(7)

NOM

gpm-types - types de pointeurs (souris, tablettes, etc.) gérés par gpm.
Les informations ci-dessous sont extraites du fichier texinfo, qui est la source d'informations préférée.

DESCRIPTION

Cette page man décrit les différents types de pointeurs actuellement disponibles dans gpm. Si vous consultez le code source, vous verrez que le code spécifique aux pointeurs est confiné dans mice.c (alors qu'il ne comprenait auparavant que des décodeurs de souris, gpm prend désormais en charge les tablettes et les écrans tactiles).

Le type de souris est spécifié en ligne de commande avec l'option -t. L'option prend un argument, qui représente le nom d'un type de souris. Chaque type peut être associé à différents noms. Pour les anciens types de souris, un nom est l'ancien nom compatible avec la sélection, et un autre est le nom XFree. Après la version 1.18.1 de gpm, le nombre de synonymes est devenu arbitraire et le nom réellement utilisé est rendu disponible à la fonction responsable de l'initialisation de la souris. Il est donc possible pour un décodeur de souris de se comporter légèrement différemment selon le nom utilisé pour le périphérique (si cette fonctionnalité avait déjà été présente, nous n'aurions par exemple pas ms+ et ms+lr comme types de souris différents).

La procédure d'initialisation de chaque type de souris peut également recevoir des options supplémentaires, au moyen de l'option -o en ligne de commande. Puisque l'interprétation de la chaîne d'options est spécifique au décodeur, les options autorisées sont décrites en association avec chaque type de souris. Quand aucune description de chaîne d'options n'est fournie, cela signifie que la chaîne d'options n'est pas utilisée pour ce type de souris et que la spécification d'une chaîne génère une erreur. Quand le document fait référence aux « options série standard », cela signifie que l'une des options -o dtr, -o rts, -o both peut être spécifiée pour basculer les lignes de contrôle du port série.

Les types de souris suivants sont actuellement reconnus :

bare Microsoft
Le protocole Microsoft, sans aucune extension. Il ne rapporte que deux boutons. Si votre périphérique en a trois, vous devriez essayer de lancer le décodeur mman ou msc. Dans ce dernier cas, vous devez dire à la souris de parler le protocole msc en basculant les lignes DTR et RTS (avec l'une des options -o drt, -o rts ou -o both) ou en invoquant gpm -t msc tout en maintenant le bouton du milieu enfoncé. Très ennuyeux, en effet. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
ms
C'est le protocole Microsoft original, avec une extension pour le bouton du milieu. Certains anciens périphériques à deux boutons envoient des paquets parasites qui peuvent être mal interprétés comme des événements du bouton du milieu. Si c'est votre cas, utilisez le type de souris bare. Certains nouveaux périphériques à deux boutons sont « plug and play », et ils ne jouent pas du tout le jeu ; dans ce cas, essayez -t pnp. Beaucoup (la plupart) des périphériques à trois boutons qui utilisent le protocole microsoft échouent à rapporter certains événements du bouton du milieu pendant le mouvement de la souris. Puisque le protocole ne distingue pas le relâchement du bouton du milieu de son appui, il serait possible de se désynchroniser, aussi ce décodeur déclare le bouton du milieu comme relâché à chaque fois que la souris bouge. Cela empêche de faire un glisser-déposer avec le bouton du milieu, aussi vous devriez probablement utiliser -t ms+lr à la place de ce décodeur, surtout si vous voulez utiliser X. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
ms+
C'est la même chose que -t ms sauf que le bouton du milieu n'est pas réinitialisé pendant le mouvement de la souris. Vous pouvez donc faire un glisser-déposer avec le bouton du milieu. Cependant, si votre souris présente le comportement buggé habituel, le décodeur est susceptible de se désynchroniser de la réalité, pensant que le bouton du milieu est relâché quand il est enfoncé et vice versa. Vous devriez probablement utiliser -t ms+lr à la place de ce décodeur. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
ms+lr
C'est la même chose que -t ms+ sauf qu'il y a une fonctionnalité supplémentaire pour réinitialiser l'état du bouton du milieu en appuyant simultanément sur les deux autres boutons. Faites cela quand le décodeur entre dans un état confus où il pense que le bouton du milieu est relâché quand il est enfoncé et vice versa. (Si vous en avez assez de devoir faire cela, ne blâmez pas gpm ; blâmez votre souris buggée ! Notez que la plupart des souris à trois boutons qui parlent le protocole microsoft peuvent être faites pour utiliser le protocole MouseSystems à la place. Le « 3 Button Serial Mouse mini-HOWTO » contient des informations à ce sujet.) Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
msc MouseSystems
C'est le protocole standard pour les périphériques série à trois boutons. Certains de ces périphériques n'entrent en mode MouseSystem que si les lignes RTS, DTR ou les deux sont mises à l'état bas. Ainsi, vous pouvez essayer -t msc associé avec -o rts, -o dtr ou -o both.
mman Mouseman
Le protocole utilisé par les nouveaux périphériques Logitech à trois boutons. Il est rétrocompatible avec le protocole Microsoft, donc si votre souris a trois boutons et fonctionne avec -t ms ou des décodeurs similaires, vous pouvez essayer -t mman à la place pour utiliser le bouton du milieu. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
sun
Le protocole utilisé sur les ordinateurs Sparc et quelques autres. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
mm MMSeries
Le titre dit tout. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
logi Logitech
C'est le protocole utilisé par les anciennes souris Logitech série.
bm BusMouse
Certains périphériques bus utilisent ce protocole, y compris ceux produits par Logitech.
ps2 PS/2
Le protocole utilisé par la plupart des souris bus.
ncr
Ce « type » est capable de décoder le stylet de pointage trouvé sur certains ordinateurs portables (le stylet NCR 3125)
wacom
Le protocole utilisé par la tablette Wacom. Depuis la version 1.18.1, nous avons un nouveau décodeur Wacom, car l'ancien ne fonctionnait pas avec les nouvelles tablettes. Ce décodeur a été testé avec les tablettes Ultrapad, PenPartner et Graphire. Options : -o relative (par défaut) pour le mode relatif, -o absolute pour le mode absolu.
genitizer
Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
logim
Utilisé pour transformer les souris Logitech en souris compatibles Mouse-Systems. Évidemment, cela ne fonctionne qu'avec certaines des souris Logitech.
pnp
Ce décodeur fonctionne avec les nouvelles souris produites par notre ami Bill, et peut-être aussi avec les anciennes. Le protocole Pnp est câblé en dur à 1200 bauds et est perturbé par l'initialisation normale, aussi c'est un décodeur -t bare sans aucune initialisation. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
ms3
Un décodeur pour les nouveaux périphériques IntelliMouse série, ceux avec trois boutons et un protocole incompatible avec les anciens. La molette est actuellement inutilisée.
imps2
« IntelliMouse » sur le port ps/2. Ce type peut aussi être utilisé pour une souris ps/2 générique à deux boutons, puisqu'il détectera automatiquement le type.
netmouse
Décode le type de périphériques « Genius NetMouse » sur le port ps/2. Pour les périphériques série « Netmouse », utilisez le décodeur « ms3 ».
cal
Un décodeur du « périphérique Calcomp UltraSlate ».
calr
Même chose que ci-dessus, mais en mode relatif.
twid
Prise en charge du clavier Twiddler. Depuis gpm-1.14, ce décodeur inclut un générateur de caractères pour la console texte, mais ne prend pas encore en charge les keycodes X. S'il est utilisé avec -R, gpm répétera quand même les événements de souris au serveur X. Plus d'informations sur la prise en charge du twiddler peuvent être trouvées dans README.twiddler, dans la distribution gpm.
syn synaptics
Un décodeur pour le Synaptics TouchPad connecté au port série. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
synps2 synaptics_ps2
Identique à ci-dessus, mais pour les appareils connectés au port ps2.
brw
Un décodeur pour le Fellowes Browser, un appareil avec 4 boutons et une molette. Ce décodeur de souris accepte les options série standard, bien qu'elles ne devraient pas être nécessaires.
js Joystick
Ce type de souris utilise le périphérique joystick pour générer des événements souris. Il n'est disponible que si l'en-tête linux/joystick.h est trouvé lors de la compilation. L'en-tête (et le périphérique également) n'a été introduit que pendant le développement de la version 2.1, et n'est pas présent dans la version 2.0 du noyau.
summa
Ceci est un décodeur pour la tablette Symmagraphics de Genius, exécutée en mode absolu. Un répéteur est associé à ce décodeur, donc gpm -R summa peut être utilisé pour générer des événements X même pour d'autres appareils de pointage absolus, comme les écrans tactiles. Pour utiliser les données répétées depuis X, vous avez besoin d'un module xf86Summa.o modifié.
mtouch
Un décodeur pour l'écran tactile MicroTouch. Veuillez vous référer au fichier README.microtouch dans l'arborescence source de gpm pour plus d'informations. Dans un avenir proche, cependant, je prévois de réintégrer le contenu de ce fichier dans cette documentation.
gunze
Un décodeur pour l'écran tactile gunze. Veuillez vous référer au fichier README.gunze dans l'arborescence source de gpm pour plus d'informations. Dans un avenir proche, cependant, je prévois de réintégrer le contenu de ce fichier dans cette documentation. Le décodeur accepte les options suivantes : smooth=, debounce=. Une plus grande fluidité entraîne également un mouvement plus lent ; une fluidité plus faible donne un mouvement plus rapide mais, évidemment, moins fluide. La fluidité par défaut est 9. Le temps de débounce est exprimé en millisecondes et est la durée minimale d'un événement montée-descente pour être considéré comme un tap. Les rebonds plus courts sont ignorés.
acecad
La tablette Acecad en mode absolu.
wp wizardpad
Tablette Genius WizardPad
