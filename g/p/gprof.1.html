"gprof"produit un profil d'exécution de programmes C, Pascal ou Fortran77. L'effet des routines appelées est intégré dans le profil de chaque appelant. Les données de profil sont prises dans le fichier de profil du graphe d'appel (
gmon.out par défaut) qui est créé par les programmes compilés avec l'option-pg
de "cc" , "pc" et "f77" . L'option-pg
lie également les versions des routines de bibliothèque compilées pour le profilage.
"Gprof"lit le fichier objet donné (par défaut "a.out"
) et établit la relation entre sa table de symboles et le profil du graphe d'appel à partir de
gmon.out. Si plus d'un fichier de profil est spécifié, la sortie
"gprof"affiche la somme des informations de profil des fichiers de profil donnés.
"Gprof"calcule le temps passé dans chaque routine. Ensuite, ces temps sont propagés le long des arêtes du graphe d'appel. Les cycles sont découverts, et les appels vers un cycle sont amenés à partager le temps du cycle.
Plusieurs formes de sortie sont disponibles à partir de l'analyse.
Le profil plat montre combien de temps votre programme a passé dans chaque fonction, et combien de fois cette fonction a été appelée. Si vous voulez simplement savoir quelles fonctions consomment le plus de cycles, c'est indiqué ici de manière concise. Le graph

e d'a
ppel

montre, pour chaque fonction, quelles fonctions l'ont appelée, quelles autres fonctions elle a appelées, et combien de fois. Il y a également une estimation du temps passé dans les sous-routines de chaque fonction. Cela peut suggérer des endroits où vous pourriez essayer d'éliminer des appels de fonctions qui

consomment beaucoup de temps.

Lesource annoté est une copie du code source du programme, étiquetée avec le nombre de fois que chaque ligne du programme a été exécutée. "-r"
"--function-ordering"
L'option --function-ordering fait que "gprof" imprime un ordre de fonctions suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de tlb et de cache pour le programme sur les systèmes qui supportent un ordre arbitraire des fonctions dans un exécutable.

Les détails exacts pour forcer l'éditeur de liens à placer les fonctions dans un ordre particulier dépendent du système et sont hors du cadre de ce manuel.

"-R map_file"
"--file-ordering map_file"
L'option --file-ordering fait que "gprof" imprime un ordre de ligne de liaison .o suggéré pour le programme basé sur les données de profilage. Cette option suggère un ordre qui peut améliorer le comportement de pagination, de tlb et de cache pour le programme sur les systèmes qui ne supportent pas un ordre arbitraire de fonctions dans un exécutable.

L'utilisation de l'argument -a est fortement recommandée avec cette option.

L'argument map_file est un chemin vers un fichier qui fournit des correspondances entre noms de fonctions et fichiers objets. Le format du fichier est similaire à la sortie du programme "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Pour créer un map_file avec GNU "nm", tapez une commande comme "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
L'option -T fait que "gprof" imprime sa sortie au style BSD "traditionnel".
"-w width"
"--width=width"
Définit la largeur des lignes de sortie à width. Actuellement, utilisé uniquement lors de l'impression de l'index des fonctions en bas du graphe d'appels.
"-x"
"--all-lines"
Cette option n'affecte que la sortie du code source annoté. Par défaut, seules les lignes au début d'un bloc de base sont annotées. Si cette option est spécifiée, chaque ligne dans un bloc de base est annotée en répétant l'annotation de la première ligne. Ce comportement est similaire à "tcov"avec -a.
"--demangle[=style]"
"--no-demangle"
Ces options contrôlent si les noms de symboles C++ doivent être démanglés lors de l'impression de la sortie. Par défaut, les symboles sont démanglés. L'option "--no-demangle" peut être utilisée pour désactiver le démanglement. Les compilateurs différents ont des styles de mangling différents. L'argument optionnel de style de démanglement peut être utilisé pour choisir un style de démanglement approprié pour votre compilateur.

Options d'analyse

"-a"
"--no-static"
L'option -a fait que "gprof" supprime l'impression des fonctions déclarées statiquement (privées). (Ce sont les fonctions dont les noms ne sont pas listés comme globaux et qui ne sont pas visibles en dehors du fichier/fonction/bloc où elles ont été définies.) Le temps passé dans ces fonctions, les appels vers/depuis elles, etc., seront tous attribués à la fonction qui a été chargée directement avant elle dans le fichier exécutable. Cette option affecte à la fois le profil plat et le graphe d'appels.
"-c"
"--static-call-graph"
L'option -c fait que le graphe d'appels du programme soit augmenté par une heuristique qui examine l'espace texte du fichier objet et identifie les appels de fonctions dans le code machine binaire. Comme les enregistrements normaux de graphe d'appels ne sont générés que lorsque des fonctions sont entrées, cette option identifie les enfants qui auraient pu être appelés, mais ne l'ont jamais été. Les appels vers des fonctions qui n'ont pas été compilées avec le profilage activé sont également identifiés, mais seulement si des entrées de table de symboles sont présentes pour elles. Les appels vers des routines de bibliothèque dynamique ne sont généralement pas trouvés par cette option. Les parents ou enfants identifiés via cette heuristique sont indiqués dans le graphe d'appels avec des comptes d'appel de 0.
"-D"
"--ignore-non-functions"
L'option -D fait que "gprof" ignore les symboles qui ne sont pas connus pour être des fonctions. Cette option donnera des données de profil plus précises sur les systèmes où elle est supportée (Solaris et HPUX par exemple).
"-k from/to"
L'option -k vous permet de supprimer du graphe d'appels tout arc depuis des symboles correspondant à symspec from vers ceux correspondant à symspec to.
"-l"
"--line"
L'option -l active le profilage ligne par ligne, ce qui fait que les coups d'histogramme sont attribués à des lignes de code source individuelles, au lieu de fonctions. Cette fonctionnalité ne fonctionne qu'avec des programmes compilés par de vieilles versions du compilateur "gcc" . Les nouvelles versions de "gcc" sont conçues pour fonctionner avec l'outil "gcov" à la place.

Si le programme a été compilé avec le comptage de blocs de base activé, cette option identifiera aussi combien de fois chaque ligne de code a été exécutée. Bien que le profilage ligne par ligne puisse aider à isoler où dans une grande fonction un programme passe son temps, il augmente aussi significativement le temps d'exécution de "gprof", et amplifie les imprécisions statistiques.

"--inline-file-names"
Cette option fait que "gprof" imprime le fichier source après chaque symbole à la fois dans le profil plat et le graphe d'appels. Le chemin complet vers le fichier est imprimé si utilisé avec l'option -L .
"-m num"
"--min-count=num"
Cette option n'affecte que la sortie du compte d'exécution. Les symboles qui sont exécutés moins de num fois sont supprimés.
"-nsymspec"
"--time=symspec"
L'option -n fait que "gprof", dans son analyse de graphe d'appels, propage seulement les temps pour les symboles correspondant à symspec.
"-Nsymspec"
"--no-time=symspec"
L'option -n fait que "gprof", dans son analyse de graphe d'appels, ne propage pas les temps pour les symboles correspondant à symspec.
"-Sfilename"
"--external-symbol-table=filename"
L'option -S fait que "gprof" lise un fichier de table de symboles externe, comme /proc/kallsyms, plutôt que de lire la table de symboles depuis le fichier objet donné (par défaut c'est "a.out"). C'est utile pour profiler des modules du noyau.
"-z"
"--display-unused-functions"
Si vous donnez l'option -z , "gprof" mentionnera toutes les fonctions dans le profil plat, même celles qui n'ont jamais été appelées et pour lesquelles aucun temps n'a été passé. C'est utile en conjonction avec l'option -c pour découvrir quelles routines n'ont jamais été appelées.

Options diverses

"-d[num]"
"--debug[=num]"
L'option -d num spécifie les options de débogage. Si num n'est pas spécifié, active tout le débogage.
"-h"
"--help"
L'option -h imprime l'utilisation de la ligne de commande.
"-Oname"
"--file-format=name"
Sélectionne le format des fichiers de données de profil. Les formats reconnus sont auto (par défaut), bsd, 4.4bsd, magic, et prof (pas encore supporté).
"-s"
"--sum"
L'option -s fait que "gprof" résume les informations dans les fichiers de données de profil qu'il a lus, et écrit un fichier de données de profil appelé gmon.sum, qui contient toutes les informations des fichiers de données de profil que "gprof" a lus. Le fichier gmon.sum peut être l'un des fichiers d'entrée spécifiés ; l'effet de ceci est de fusionner les données des autres fichiers d'entrée dans gmon.sum.

Finalement, vous pouvez exécuter "gprof" à nouveau sans -s pour analyser les données cumulatives dans le fichier gmon.sum.

"-v"
"--version"
L'option -v fait que "gprof" imprime le numéro de version actuel, puis se termine.

Options dépréciées

Ces options ont été remplacées par des versions plus récentes qui utilisent des symspecs.

"-e function_name"
L'option -e function indique à "gprof" de ne pas imprimer d'informations sur la fonction function_name (et ses enfants...) dans le graphe d'appels. La fonction sera toujours listée comme enfant de toutes les fonctions qui l'appellent, mais son numéro d'index sera affiché comme [not printed]. Plus d'une option -e peut être donnée ; seulement un function_name peut être indiqué avec chaque -e option.
"-E function_name"
L'option "-E function" fonctionne comme l'option "-e" , mais le temps passé dans la fonction (et les enfants qui n'ont été appelés nulle part ailleurs) ne sera pas utilisé pour calculer les pourcentages-de-temps pour le graphe d'appels. Plus d'une option -E peut être donnée ; seulement un function_name peut être indiqué avec chaque -E option.
"-f function_name"
Le -f fonction option fait "gprof" limiter le graphe d'appels à la fonction function_name et ses enfants (et leurs enfants...). Plusieurs options -f peuvent être données ; une seule function_name peut être indiquée avec chaque option -f
"-F function_name"
L' -F fonction option fonctionne comme l' "-f" option, mais seul le temps passé dans la fonction et ses enfants (et leurs enfants...) sera utilisé pour déterminer le temps total et les pourcentages de temps pour le graphe d'appels. Plusieurs options -F peuvent être données ; une seule function_name peut être indiquée avec chaque option -F L'option -F remplace l' -E

ANOMALIES

La granularité de l'échantillonnage est affichée, mais reste statistique au mieux. Nous supposons que le temps pour chaque exécution d'une fonction peut être exprimé par le temps total pour la fonction divisé par le nombre de fois la fonction est appelée. Ainsi le temps propagé le long des arcs du graphe d'appels vers les parents de la fonction est directement proportionnel au nombre de fois cet arc est parcouru.

Les parents qui ne sont pas eux-mêmes profilés verront le temps de leurs enfants profilés leur être propagé, mais ils apparaîtront comme étant invoqués spontanément dans la liste du graphe d'appels, et leur temps ne sera pas propagé plus loin. De même, les capteurs de signaux, même s'ils sont profilés, apparaîtront comme spontanés (bien que pour des raisons plus obscures). Tous les enfants profilés des capteurs de signaux devraient voir leurs temps correctement propagés, sauf si le capteur de signal a été invoqué pendant l'exécution de la routine de profilage, auquel cas tout est perdu.

Le programme profilé doit appeler "exit"(2) ou retourner normalement pour que les informations de profilage soient enregistrées dans le fichier gmon.out
