DESCRIPTIO

N

Le gpg-wks-server est une implémentation côté serveur du Web Key Service. Il reçoit les demandes de publication, envoie les demandes de confirmation, reçoit les confirmations et publie la clé. Il dispose également de fonctionnalités pour faciliter la configuration et la maintenance d'un Web Key

Directory.

Lorsqu'il est utilisé avec la commande --receive, un seul courriel de Web Key Service est traité. Habituellement, cette commande est utilisée avec l'option --send pour envoyer directement les courriels créés. Voir ci-dessous pour un exemple

d'installation.

La commande --cron est utilisée pour les tâches de nettoyage régulières. Par exemple, les demandes non confirmées doivent être supprimées après leur date d'expiration. Il est préférable d'exécuter cette commande une fois par jour depuis un

cronjob.

La commande --list-domains affiche tous les domaines configurés. De plus, elle crée les répertoires manquants pour la configuration et affiche des avertissements concernant les problèmes de

configuration.

La commande --check-key (ou simplement --check) vérifie si une clé avec l'user-id donné est installée. Le processus retourne le succès dans ce cas ; pour afficher également un diagnostic, utilisez l'option -v. Si la clé n'est pas installée, un diagnostic est affiché et le processus retourne l'échec ; pour supprimer le diagnostic, utilisez l'option -q. Plus d'un user-id peut être donné ; voir aussi l'option with-file

.

La commande --install-key installe manuellement une clé dans le WKD. Les arguments sont un fichier contenant le bloc de clé et l'user-id à installer. Si le premier argument ressemble à une empreinte, la clé est prise depuis le trousseau actuel ; pour forcer l'utilisation d'un fichier, préfixez le premier argument avec "./". Si aucun argument n'est donné, les paramètres sont lus depuis stdin ; le format attendu est des lignes contenant l'empreinte et la boîte mail séparées par un

espace.

La commande --remove-key désinstalle une clé du WKD. Le processus retourne le succès dans ce cas ; pour afficher également un diagnostic, utilisez l'option -v. Si la clé n'est pas installée, un diagnostic est affiché et le processus retourne l'échec ; pour supprimer le diagnostic, utilisez l'option -q

.

La commande --revoke-key n'est pas

encore fon
ctionnelle.

EXEMPLE

S

Le Web Key Service nécessite un répertoire de travail pour stocker les clés en attente de publication. En tant que root, créez un répertoire de travail

: 
  # mkdir /var/lib/gnupg/wks
  # chown webkey:webkey /var/lib/gnupg/wks
  # chmod 2750 /var/lib/gnupg/w
k
s

Ensuite, sous votre compte webkey, créez des répertoires pour tous vos domaines. Ici, nous le faisons pour « example.net »

: 
  $ mkdir /var/
lib/gnupg/wk
s/example.net

Enfin,

exécutez 
  $ gpg-wks-
server --li
st-domains

pour créer les sous-répertoires requis avec les permissions correctement définies. Pour chaque domaine, une adresse de soumission doit être configurée. Tous les courriels de service sont dirigés vers cette adresse. Elle peut être la même adresse pour tous les domaines configurés, par exemple

: 
  $ cd /var/lib/gnupg/wks/example.net
  $ echo key-submission@example.net >submission-addre
s
s

Le protocole exige que la clé à publier soit envoyée avec un courriel chiffré au service. Vous devez donc créer une clé pour l'adresse de soumission

: 
  $ gpg --batch --passphrase '' --quick
-gen-key key-submission@example.net
$ gpg -K key-submission@example.net

La sortie de la dernière commande ressemble à ceci

: 
  sec   rsa3072 2016-08-30 [SC]
        C0FCF8642D830C53246211400346653590B37
95B uid [ultimate] key-submission@example.net
bxzcxpxk8h87z1k7bzk86xn5aj47intu@example.net ssb rsa3072 2016-08-30 [E]

Prenez l'empreinte de cette sortie et publiez manuellement la clé

: 
  $ gpg-wks-server --install-key C0FCF8642
D830C53246211400346653590B3795B \ >
key-submission@example.net

Enfin, cette adresse de soumission doit être redirigée vers un script exécutant gpg-wks-server. La commande procmail peut être utilisée pour cela : Redirigez l'adresse de soumission vers l'utilisateur « webkey » et placez ceci dans le fichier «.procmailrc » de webkey

:

e.net \ --from webkey@example.net --send
