DESCRIPTIO

N

Le gpgconf est un utilitaire pour interroger et modifier de manière automatique et raisonnablement sûre les fichiers de configuration dans le répertoire personnel ‘.gnupg’. Il est conçu pour ne pas être invoqué manuellement par l'utilisateur, mais automatiquement par des interfaces graphiques (GUI). ([Veuillez noter qu'actuellement aucun verrouillage n'est effectué, l'accès concurrent doit donc être évité. Certaines précautions existent pour éviter la corruption lors d'une utilisation concurrente, mais les résultats peuvent être incohérents et certaines modifications peuvent être perdues. La conception sans état rend difficile la fourniture de garanties plus fortes.]

)

gpgconf fournit un accès à la configuration d'un ou plusieurs composants du système GnuPG. Ces composants correspondent plus ou moins aux programmes qui existent dans le cadre de GnuPG, comme GPG, GPGSM, DirMngr, etc. Mais il ne s'agit pas d'une relation stricte un à un. Toutes les options de configuration ne sont pas disponibles via gpgconf. gpgconf fournit une méthode générique et abstraite pour accéder aux options de configuration les plus importantes qui peuvent être contrôlées de manière réaliste via un tel

mécanisme.

gpgconf peut être utilisé pour recueillir et modifier les options disponibles dans chaque composant, et peut également fournir leurs valeurs par défaut. gpgconf fournira des informations de type détaillées qui peuvent être utilisées pour restreindre la saisie de l'utilisateur sans tenter de valider les

modifications.

gpgconf fournit le backend d'un éditeur de configuration. L' éditeur de configuration est généralement un programme d'interface graphique qui affiche les options actuelles, leurs valeurs par défaut, et permet à l'utilisateur d'apporter des modifications aux options. Ces modifications peuvent ensuite être rendues actives avec gpgconf à nouveau. Un tel programme qui utilise gpgconf de cette manière sera appe

lé GUI tout au lon
g de cette section.

UTILISATI

ON

La commande --list-components listera tous les composants qui peuvent être configurés avec gpgconf. Habituellement, un composant correspondra à un programme lié à GnuPG et contiendra les options du fichier de configuration de ce programme qui peuvent être modifiées en utilisant gpgconf. Cependant, ce n'est pas nécessairement le cas. Un composant peut aussi être un groupe d'options sélectionnées de plusieurs programmes, ou contenir entièrement des options virtuelles qui ont un effet spécial plutôt que de changer exactement une option dans un fichier de

configuration.

Un composant est un ensemble d'options de configuration qui appartiennent sémantiquement ensemble. De plus, plusieurs changements à un composant peuvent être faits de manière atomique avec une seule opération. L'interface graphique pourrait par exemple fournir un menu avec une entrée pour chaque composant, ou une fenêtre avec une feuille d'onglets par

composant.

La commande --list-components liste tous les composants disponibles, un par ligne. Le format de chaque ligne est

:

name:description:pgmname:

échappé.
descripti

La chaîne dans ce champ contient une description lisible par l'homme du composant. Elle peut être affichée à l'utilisateur de l'interface graphique à des fins informatives. Elle est échappée en pourcentage et localisé

Listage des

options

 

Chaque composant contient une ou plusieurs options. Les options peuvent être regroupées en groupes d'options pour permettre à l'interface graphique de donner des indications visuelles à l'utilisateur sur les options qui sont

liées.

La commande liste toutes les options (et les groupes auxquels elles appartiennent) dans le composant component, une par ligne. component doit être la chaîne dans le champ name dans la sortie de la commande --list-components

.

Il y a une ligne pour chaque option et chaque groupe. D'abord viennent toutes les options qui ne sont dans aucun groupe. Ensuite vient une ligne décrivant un groupe. Puis viennent toutes les options qui appartiennent à chaque groupe. Puis vient le groupe suivant et ainsi de suite. Il n'y a pas besoin d'avoir de groupe (et dans ce cas la sortie s'arrêtera après la dernière option non groupée)

.

Sous Unix, ‘gpgconf.ctl’ peut être utilisé pour changer certaines des répertoires
compilés où les composants GnuPG sont attendus. Ce

répertoires d'installation physiques sont évalués et non les liens symboliques.
Les lignes vides et les lignes commençant par le signe dièse sont ignorées dans le
fichier. Les mots-clés doivent être suivis d'une espace facultative, d'un signe
égal, d'une espace facultative, et de la valeur. Les variables d'environnement sont
substituées à la manière standard du shell, la valeur finale doit commencer par
une barre oblique, les barres obliques finales sont supprimées. Les mots-clés valides sont
rootdir, sysconfdir, socketdir, et
.enable. Aucune erreur n'est imprimée pour les mots-clés inconnus. Le
mot-clé .enable est spécial : si le mot-clé est utilisé et que sa
valeur s'évalue à vrai, le fichier entier est ignoré.
