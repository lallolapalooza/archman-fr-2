gpgwrap(1) Manuel des commandes générales gpgwrap(1)

NOM

gpgwrap - un petit enveloppeur pour gpg

SYNOPSIS

gpgwrap -V

gpgwrap -P [-v] [-i] [-a] [-p <fichier>]

gpgwrap -F [-v] [-i] [-a] [-c] [-p <fichier>] [-o <nom>] [--] <fichier> [<fichier> ... ]

gpgwrap [-v] [-i] [-a] [-p <fichier>] [-o <nom>] [--] gpg [options gpg]

DESCRIPTION

GNU Privacy Guard (gpg) fournit l'option --passphrase-fd. Celle-ci indique à gpg de lire la phrase secrète depuis le descripteur de fichier donné. Habituellement, ce descripteur de fichier est ouvert avant gpg est exécuté via execvp(3). C'est exactement ce que gpgwrap fait. La phrase secrète peut être transmise à gpgwrap de 4 manières :

  • en tant que chemin de fichier, où la phrase secrète est stockée en texte clair dans le fichier
  • elle est acheminée depuis un autre programme vers l'entrée standard de gpgwrap
  • via la GPGWRAP_PASSPHRASE variable d'environnement
  • gpgwrap la demande à l'utilisateur

Sans précautions, le premier point compromet l'infrastructure sécurisée fournie par gpg . Mais dans des environnements purement par lots, c'est peut-être ce que vous voulez. Sinon, si vous êtes prêt à saisir les phrases secrètes une seule fois et ne voulez pas qu'elles soient stockées en texte clair dans un fichier gpg-agent est ce que vous cherchez. Une autre objection de sécurité pourrait être l'utilisation de la variable d'environnement GPGWRAP_PASSPHRASE qui contient la phrase secrète et peut être lue par d'autres processus du même utilisateur.

OPTIONS

-V, --version
Affiche la version et se termine.
-P, --print
Récupère la phrase secrète et l'affiche encodée sur la sortie standard.
-F, --file
Lit les commandes gpg à partir des fichiers donnés. Si <fichier> est - elle est lue depuis l'entrée standard. Exactement une commande par ligne est attendue. La ligne donnée est traitée de la manière suivante :
  • En premier lieu, la phrase secrète est encodée. Cela signifie que les caractères inhabituels sont remplacés par leurs nombres octaux échappés par une barre oblique.
  • Deuxièmement, la phrase secrète encodée est stockée dans la variable d'environnement GPGWRAP_PASSPHRASE.
  • "exec gpgwrap -- " est ajouté au début de chaque ligne, avant que le résultat ne soit passé comme argument à "sh -c".
-h, --help
Affiche les informations d'utilisation.
-v, --verbose
Augmente le niveau de verbosité.
-i, --interactive
Demande toujours la phrase secrète (ignore -p et la variable d'environnement).
-a, --ask-twice
Demande deux fois si une phrase secrète est demandée.
-c, --check-exit-code
Lors de la lecture des commandes gpg à partir d'un fichier, gpgwrap ignore par défaut le code de sortie de ses processus enfants. Cette option active la vérification du code de sortie. Si un enfant se termine de manière anormale ou avec un code de sortie différent de 0 gpgwrap s'arrête immédiatement et retourne avec ce code de sortie. Voir aussi la section BUGS.
-p <fichier>, --passphrase-file <fichier>
Lit la phrase secrète depuis <fichier>. Si <fichier> est - elle est lue depuis l'entrée standard. La phrase secrète doit être en texte clair. Si cette option n'est pas donnée, la phrase secrète sera prise soit depuis la variable d'environnement GPGWRAP_PASSPHRASE soit elle sera demandée sur le tty de contrôle si la variable d'environnement n'est pas définie.
-o <nom>, --option-name <nom>
Spécifie le nom de l'option "--passphrase-fd" comprise par le programme à exécuter. C'est utile si vous voulez utiliser gpgwrap en combinaison avec d'autres programmes que gpg.

LIMITATIONS

La phrase secrète donnée est soumise à plusieurs limitations selon la manière dont elle a été transmise à gpgwrap:

  • Il y a une limitation de taille : la phrase secrète ne devrait pas dépasser quelques kilo-octets (examinez le code source pour la limite exacte).
  • gpgwrap vous permet d'utiliser tous les caractères dans une phrase secrète, même \000, mais cela ne signifie pas que gpg l'acceptera. gpg peut rejeter votre phrase secrète ou n'en lire qu'une partie si elle contient des caractères comme \012 (en C aussi connu comme \n).
  • Si vous définissez la variable d'environnement GPGWRAP_PASSPHRASE vous devriez faire particulièrement attention au caractère barre oblique, car gpgwrap utilise la barre oblique pour échapper les nombres octaux (voir l'option -F). Écrivez donc la barre oblique elle-même comme nombre octal : \134.

EXEMPLES

1.
gpgwrap -p /chemin/vers/un/fichier/secret  \
gpg -c -z 0 --batch --no-tty  \
    --cipher-algo blowfish < infile > outfile
Lit la phrase secrète depuis /chemin/vers/un/fichier/secret et exécute gpg pour faire un chiffrement symétrique de infile et l'écrire dans outfile.
2.
gpgwrap -i -a  \
gpg -c -z 0 --batch --no-tty  \
    --cipher-algo blowfish < infile > outfile
Idem que ci-dessus sauf que gpgwrap demande la phrase secrète deux fois.
3.
gpgwrap -F -i - <<EOL
gpg --decrypt --batch --no-tty < "$HOME/infile1" > "$HOME/outfile1"
gpg --decrypt --batch --no-tty < "$HOME/infile2" > "$HOME/outfile2"
gpg --decrypt --batch --no-tty < "$HOME/infile3" > "$HOME/outfile3"
gpg --decrypt --batch --no-tty < "$HOME/infile4" > "$HOME/outfile4"
EOL
gpgwrap demande la phrase secrète et exécute quatre instances de gpg pour déchiffrer les fichiers donnés.
4.
GPGWRAP_PASSPHRASE="maphrasesecrete"
export GPGWRAP_PASSPHRASE
gpgwrap -F -c -v /tmp/cmdfile1 - /tmp/cmdfile2 <<EOL
gpg --decrypt --batch --no-tty < "$HOME/infile1" > "$HOME/outfile1"
gpg --decrypt --batch --no-tty < "$HOME/infile2" > "$HOME/outfile2"
gpg --decrypt --batch --no-tty < "$HOME/infile3" > "$HOME/outfile3"
gpg --decrypt --batch --no-tty < "$HOME/infile4" > "$HOME/outfile4"
EOL
Idem que ci-dessus sauf que gpgwrap obtient la phrase secrète via la variable d'environnement, lit les commandes supplémentaires à partir d'autres fichiers et vérifie le code de sortie de chaque gpg instance. Cela signifie que si une gpg commande a un code de sortie non nul, aucune autre commande n'est exécutée. De plus gpgwrap produit une sortie verbeuse.
5.
GPGWRAP_PASSPHRASE="$(gpgwrap -P -i -a)"
export GPGWRAP_PASSPHRASE
find . -maxdepth 1 -type f |
while read FILE; do
    FILE2="$FILE.bz2.gpg"
    bzip2 -c "$FILE" |
    gpgwrap gpg -c -z 0 --batch --no-tty  \
        --cipher-algo blowfish > "$FILE2" &&
    touch -r "$FILE" "$FILE2" &&
    rm -f "$FILE"
done
Lit la phrase secrète, compresse tous les fichiers du répertoire courant, les chiffre et conserve la date du fichier original.
6.
find . -maxdepth 1 -type f -name '*.bz2.gpg' |
awk '{
    printf("gpg --decrypt --batch --no-tty --quiet ");
    printf("--no-secmem-warning < %s\n", $0);
    }' |
gpgwrap -F -i -c - |
bzip2 -d -c - |
grep -i 'data'
Déchiffre tous les fichiers *.bz2.gpg du répertoire courant, les décompresse et affiche toutes les occurrences de data. Si vous acheminez le résultat vers less vous rencontrez des problèmes car gpgwrap et less essaient de lire depuis le TTY en même temps. Dans un tel cas, il est préférable d'utiliser la variable d'environnement pour fournir la phrase secrète (l'exemple ci-dessus montre comment faire).
7.
GPGWRAP_PASSPHRASE="$(gpgwrap -P -i -a)"
export GPGWRAP_PASSPHRASE
gpgwrap -P |
ssh -C -x -P -l user host "
    GPGWRAP_PASSPHRASE=\"\$(cat)\"
    ...
    "
Demander une phrase secrète deux fois et l'écrire dans la variable GPGWRAP_PASSPHRASE d'environnement.
8.
echo -n "Passphrase: "
stty -echo
read GPGWRAP_PASSPHRASE
echo
stty echo
export GPGWRAP_PASSPHRASE
Une autre façon de demander manuellement la phrase secrète. Cela était nécessaire en combinaison avec les anciennes versions de gpgwrap, car elles ne prenaient pas en charge -P. Notez qu'avec cette méthode, aucune conversion automatique vers les nombres octaux échappés par antislash n'a lieu.
9.
echo "mysecretpassphrase" |
gpg --batch --no-tty --passphrase-fd 0  \
    --output outfile --decrypt infile
Méthode peu coûteuse pour donner la phrase secrète à gpg sans gpgwrap. Notez que vous ne pouvez pas utiliser stdin pour passer un fichier à gpg, car stdin est déjà utilisé pour la phrase secrète.
10.
gpg --batch --no-tty  \
    --passphrase-fd 3 3< /path/to/a/secret/file  \
    < infile > outfile
Ceci est une méthode plus avancée pour donner la phrase secrète, elle est équivalente à l'option -p de gpgwrap. Cet exemple devrait au moins fonctionner avec le bash.
11.
gpg --batch --no-tty --passphrase-fd 3  \
    3< <(echo "mysecretpassphrase")  \
    < infile > outfile
Comme ci-dessus, mais la phrase secrète est donnée directement. Cet exemple devrait au moins fonctionner avec le bash.

BOGUES

Dans la version 0.02 de gpgwrap , le code de sortie de gpg n'était renvoyé que si gpgwrap lisait la phrase secrète depuis un fichier. Depuis la version 0.03, seul -F omet la vérification du code de sortie par défaut, mais elle peut être activée avec -c.
