DESCRIPTION

La commande gfortran prend en charge toutes les options prises en charge par la commande gcc. Seules les options spécifiques à GNU Fortran sont documentées ici.

Toutes les options GCC et GNU Fortran sont acceptées à la fois par gfortran et par gcc (ainsi que par tout autre pilote construit au même moment, tel que g++), car l'ajout de GNU Fortran à la distribution GCC permet l'acceptation des options GNU Fortran par tous les pilotes pertinents.

Dans certains cas, les options ont des formes positive et négative ; la forme négative de -ffoo serait -fno-foo. Ce manuel ne documente que l'une de ces deux formes, celle qui n'est pas celle par défaut.

Options contrôlant le dialecte Fortran

Les options suivantes contrôlent les détails du dialecte Fortran accepté par le compilateur :

-ffree-form
-ffixed-form
Spécifie la disposition utilisée par le fichier source. La disposition libre a été introduite dans Fortran 90. La disposition fixe était traditionnellement utilisée dans les anciens programmes Fortran. Lorsque aucune des deux options n'est spécifiée, la forme de la source est déterminée par l'extension du fichier.
-fall-intrinsics
Cette option provoque l'acceptation de toutes les procédures intrinsèques (y compris les extensions spécifiques à GNU). Cela peut être utile avec -std= pour forcer la conformité aux normes tout en ayant accès à l'ensemble complet des intrinsèques disponibles avec gfortran. En conséquence, -Wintrinsics-std est ignoré et aucune procédure définie par l'utilisateur portant le même nom qu'un intrinsèque n'est appelée, sauf si elle est explicitement déclarée "EXTERNAL".
-fallow-argument-mismatch
Certains codes contiennent des appels à des procédures externes avec des incompatibilités entre les appels et la définition de la procédure, ou avec des incompatibilités entre différents appels. Un tel code n'est pas conforme et est généralement signalé par une erreur. Cette option dégrade l'erreur en un avertissement qui ne peut être désactivé qu'en désactivant tous les avertissements via -w. Une seule occurrence par argument est signalée par cet avertissement. -fallow-argument-mismatch est implicite dans -std=legacy.

L'utilisation de cette option est *fortement* déconseillée. Il est possible de fournir un code conforme aux normes qui autorise différents types d'arguments en utilisant une interface explicite et TYPE(*).

-fallow-invalid-boz
Une constante littérale BOZ peut apparaître dans un nombre limité de contextes dans le Fortran conforme aux normes. Cette option dégrade une condition d'erreur en un avertissement, et permet à une constante littérale BOZ d'apparaître là où la norme Fortran l'interdirait autrement.
-fd-lines-as-code
-fd-lines-as-comments
Active un traitement spécial pour les lignes commençant par "d" ou "D" dans les sources en forme fixe. Si l'option -fd-lines-as-code est donnée, elles sont traitées comme si la première colonne contenait un espace. Si l'option -fd-lines-as-comments est donnée, elles sont traitées comme des lignes de commentaire.

Activer et personnaliser le

prétraitement

De nombreux compilateurs Fortran, y compris GNU Fortran, permettent de faire passer le code source par un préprocesseur C (CPP ; parfois aussi appelé préprocesseur Fortran, FPP) pour permettre la compilation conditionnelle. Dans le cas de GNU Fortran, il s'agit du préprocesseur C GNU en mode traditionnel. Sur les systèmes avec des noms de fichiers préservant la casse, le préprocesseur est automatiquement invoqué si l'extension du nom de fichier est .F, .FOR, .FTN, .fpp, .FPP, .F90, .F95, .F03 ou .F08. Pour invoquer manuellement le préprocesseur sur n'importe quel fichier, utilisez -cpp ; pour désactiver le prétraitement sur les fichiers où le préprocesseur est exécuté automatiquement, utilisez -nocpp

.

Si un fichier prétraité inclut un autre fichier avec l'instruction Fortran « INCLUDE », le fichier inclus n'est pas prétraité. Pour prétraiter les fichiers inclus, utilisez l'instruction préprocesseur équivalente « #include »

.

Si GNU Fortran invoque le préprocesseur, « __GFORTRAN__ » est défini. Les macros « __GNUC__ », « __GNUC_MINOR__ » et « __GNUC_PATCHLEVEL__ » peuvent être utilisées pour déterminer la version du compilateur. Voir Top,,Overview,cpp,The C Preprocessor pour plus de

détails.

GNU Fortran prend en charge un certain nombre de « INTEGER » et « REAL » en plus des types de kind requis par la norme Fortran. La disponibilité d'un type de kind donné dépend de l'architecture. Les macros préprocesseur prédéfinies suivantes peuvent être utilisées pour inclure conditionnellement du code pour ces types de kind supplémentaires : « __GFC_INT_1__ », « __GFC_INT_2__ », « __GFC_INT_8__ », « __GFC_INT_16__ », « __GFC_REAL_10__ » et « __GFC_REAL_16__ »

Options pour demander ou supprimer les erreurs et les avertissements

Les erreurs sont des messages de diagnostic qui signalent que le compilateur GNU Fortran ne peut pas compiler le morceau de code source concerné. Le compilateur continue à traiter le programme dans le but de signaler d'autres erreurs pour aider au débogage, mais ne produit aucune sortie compilée.

Les avertissements sont des messages de diagnostic qui signalent des constructions qui ne sont pas intrinsèquement erronées mais qui sont risquées ou suggèrent qu'il y a probablement un bug dans le programme. Sauf si -Werror est spécifié, ils n'empêchent pas la compilation du programme.

déclarations. Chacune de ces options d'avertissement spécifiques possède également une forme négative commençant par -Wno- pour désactiver les avertissements ; par exemple, -Wno-implicit. Ce manuel ne liste qu'une des deux formes, celle qui n'est pas la valeur par

défaut.

-fno-underscoring
Make external function and variable names be generated without an appended underscore. This is usually required to interface with C code compiled with an older version of GCC.

It is also required to interface with C code that does not use a preprocessor. In this case, the linker name will be used directly as the external name. Note that this can lead to name clashes with C functions or global variables, and the linker will not warn about these conflicts. This option is not recommended because it makes GNU Fortran name mangling behave in a way that is inconsistent with other compilers and the Fortran standard.

Some C compilers (like older versions of GCC) append an underscore to external function names and global variables. GNU Fortran does this by default. Using this option tells GNU Fortran not to append the underscore. This is for compatibility with C code that does not add this underscore itself.
