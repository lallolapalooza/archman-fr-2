NOM

geotifcp - Copie un TIFF avec les métadonnées GeoTIFF mises à jour

SYNOPSIS

geotifcp [options] [-e fichier_mondial_esri] [-g métadonnées] entrée sortie

DESCRIPTION

geotifcp est identique en fonction au programme LIBTIFF tiffcp, avec la fonctionnalité supplémentaire que si l'option "-g" est utilisée, les informations GeoTIFF du fichier seront installées dans le fichier de sortie. L'option "-e fichier_mondial" remplacera les informations de point d'ancrage et d'échelle du fichier de métadonnées en fonction du contenu du fichier mondial ESRI.

Si l'option "-g" n'est pas utilisée, les informations geotiff du fichier source sont préservées dans le nouveau fichier de sortie.

"geotifcp" hérite de toutes les autres capacités de transformation de fichiers du programme tiffcp; pour de l'aide sur les paramètres supplémentaires, tapez la commande:

% geotifcp -h

Le format des métadonnées est le même que celui décrit dans le programme listgeo(1). Normalement, les fichiers de métadonnées à utiliser avec geotifcp sont générés à partir d'un fichier similaire avec listgeo, puis modifiés manuellement selon les besoins.

OPTIONS

-g fichier
installe les métadonnées GeoTIFF à partir du fichier
-4 chaîne_proj4
installe les métadonnées GeoTIFF à partir d'une chaîne proj4
-e fichier
installe les informations de positionnement à partir du fichier mondial ESRI fichier
-a
ajoute à la sortie au lieu d'écraser
-8
écrit en BigTIFF au lieu du ClassicTIFF par défaut
-o décalage
définit le décalage initial du répertoire
-p contig
regroupe les échantillons de manière contiguë (par exemple, RGBRGB...)
-p separate
stocke les échantillons séparément (par exemple, RRR...GGG...BBB...)
-s
écrit la sortie en bandes
-t
écrit la sortie en tuiles
-i
ignore les erreurs de lecture
-d
tronque 8 bits par échantillon à 4 bits par échantillon
-r #
fait en sorte que chaque bande n'ait pas plus de # lignes
-w #
définit la largeur de la tuile de sortie (pixels)
-l #
définit la longueur de la tuile de sortie (pixels)
-f lsb2msb
force l'ordre des bits FillOrder (LSB vers MSB) pour la sortie
-f msb2lsb
force l'ordre des bits FillOrder (MSB vers LSB) pour la sortie
-c lzw[:opts]
compresse la sortie avec l'encodage Lempel-Ziv & Welch
-c zip[:opts]
compresse la sortie avec l'encodage deflate
-c jpeg[:opts]
compresse la sortie avec l'encodage JPEG
-c packbits
compresse la sortie avec l'encodage packbits
-c g3[:opts]
compresse la sortie avec l'encodage CCITT Group 3
-c g4
compresse la sortie avec l'encodage CCITT Group 4
-c none
n'utilise aucun algorithme de compression en sortie

Options du groupe 3 :

1d
utilise l'encodage 1D par défaut du CCITT Group 3
2d
utilise l'encodage 2D optionnel du CCITT Group 3
fill
aligne les codes EOL (End Of Line) sur des octets

Par exemple, -c g3:2d:fill pour obtenir des données encodées en G3-2D avec des EOL alignés sur des octets

Options JPEG :

#
définit le niveau de qualité de compression (0-100, défaut 75)
r
sortie d'image couleur en RGB plutôt qu'en YCbCr

Par exemple, -c jpeg:r:50 pour obtenir des données RVB encodées en JPEG avec une qualité de compression de 50%

Options LZW et deflate :

#
définit la valeur du prédicteur

Par exemple, -c lzw:2 pour obtenir des données encodées en LZW avec différenciation horizontale
