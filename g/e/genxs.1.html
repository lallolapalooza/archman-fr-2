genxs(1) Manuel des commandes générales genxs(1)

NOM

genxs - Générateur de sérialiseur XML de Mono

SYNTAXE

genxs fichierConfiguration [dossierDestination]

DESCRIPTION

genxs est un outil pour générer des lecteurs et des écrivains de sérialisation XML personnalisés pour des classes.

fichierConfiguration est un fichier de configuration qui spécifie plusieurs informations, telles que la classe pour laquelle générer le lecteur et l'écrivain, le nom et l'espace de noms des classes à générer, et une collection de hooks (points d'accroche) à appliquer. En utilisant des hooks, il est possible de personnaliser le comportement du sérialiseur sans avoir à modifier le fichier généré, vous pouvez donc le régénérer en toute sécurité si la classe source est modifiée.

dossierDestination spécifie le dossier où les fichiers seront générés.

NOTE : Cet outil ne s'exécute que dans l'environnement d'exécution Mono, car il utilise certaines classes internes non disponibles dans d'autres environnements d'exécution.

FORMAT DU FICHIER DE CONFIGURATION

Le fichier de configuration est un document XML basé sur la grammaire suivante (« ? » signifie optionnel, « * » 0 ou plus) :

<configuration>
	<serializer class="nom" assembly="nom"> *
		<reader>nom</reader> ?
		<writer>nom</writer> ?
		<namespace>nom</namespace> ?
		<outFileName>nom</outFileName> ?
		<readerHooks> ?
			<hook ...> *
		</readerHooks>
		<writerHooks> ?
			<hook ...> *
		</writerHooks>
	</serializer>
</configuration>

Un fichier de configuration peut contenir plusieurs éléments « serializer », chacun spécifiant la classe pour laquelle générer un sérialiseur ainsi que plusieurs options de génération. La classe source est spécifiée dans les attributs suivants :

*
class : nom de la classe (y compris l'espace de noms).
*
assembly : nom de l'assembly. Il peut inclure le chemin complet.

Les options de génération sont spécifiées dans les éléments enfants :

*
reader : nom de la classe de lecteur.
*
noReader : si « true », ne génère pas la classe de lecteur.
*
writer : nom de la classe d'écrivain.
*
baseSerializer : nom de la classe de sérialiseur XML de base. Cet élément est uniquement pour la version 2.0.
*
implementation : nom de la classe d'implémentation du sérialiseur. Cet élément est uniquement pour la version 2.0.
*
noWriter : si « true », ne génère pas la classe d'écrivain.
*
namespace : espace de noms des classes de lecteur et d'écrivain.
*
generateAsInternal : si « true », génère les classes comme internes.
*
outFileName : nom du fichier généré.
*
readerHooks : une liste de hooks à appliquer au lecteur.
*
writerHooks : une liste de hooks à appliquer à l'écrivain.

SPÉCIFICATION DES HOOKS

En utilisant les hooks, vous pouvez personnaliser le comportement des lecteurs et des écrivains. Une spécification de hook suit cette grammaire :

<hook type="nom">
	<select> ?
		<typeName>nom</typeName> ?
		<typeAttribute>nom</typeAttribute> *
		<typeMember>nom</typeMember> ?
	</select>
	<replace>code source</replace> ?
	<insertBefore>code source</insertBefore> ?
	<insertAfter>code source</insertAfter> ?
</hook>

L'attribut « type » spécifie le contexte dans lequel le hook est appliqué. Il peut être l'un des suivants :

*
attributes : le hook est appliqué là où les attributs sont sérialisés/désérialisés.
*
elements : le hook est appliqué là où les éléments sont sérialisés/désérialisés.
*
unknownAttribute : le hook est appliqué là où les attributs inconnus sont traités.
*
unknownElement : le hook est appliqué là où les éléments inconnus sont traités.
*
member : le hook est appliqué là où un membre est sérialisé/désérialisé.
*
type : le hook est appliqué pour le type entier.

L'élément « select » spécifie les classes et les membres auxquels le hook doit être ajouté. Il peut contenir les éléments suivants :

*
typeName : la classe portant ce nom sera sélectionnée (doit inclure l'espace de noms)
*
typeAttribute : toutes les classes portant cet attribut seront sélectionnées (spécifier le nom complet de la classe de l'attribut, y compris l'espace de noms). Plusieurs noms d'attributs peuvent être spécifiés.
*
typeMember : nom du membre de classe pour lequel le hook doit être ajouté.

Le code source du hook peut être spécifié en utilisant l'un des éléments suivants :

*
replace : le code source fourni remplacera toutes les opérations de sérialisation/désérialisation dans le contexte du hook.
*
insertBefore : le code source sera ajouté avant le contexte du hook.
*
insertAfter : le code source sera ajouté après le contexte du hook.

Lors de l'écriture du code pour un hook, vous pouvez utiliser certaines variables spéciales qui sont définies pendant le processus de génération de code. Les variables sont les suivantes :

*
$TYPE : nom de la classe en cours de génération, sans l'espace de noms.
*
$FULLTYPE : nom complet de la classe en cours de génération, y compris l'espace de noms.
*
$OBJECT : l'objet en cours de sérialisation ou de désérialisation. Lors de l'utilisation d'un hook de lecteur de remplacement de type « type », le code du hook doit attribuer l'objet désérialisé à cette variable.
*
-I $ELEMENT : nom de l'élément de l'objet en cours de sérialisation/désérialisation.
*
$NAMESPACE : espace de noms de l'élément de l'objet en cours de sérialisation/désérialisation.
*
$MEMBER : nom du membre en cours de sérialisation/désérialisation. Valide uniquement dans le contexte « member ».

EXEMPLES DE HOOKS

L'exemple suivant ajoute un appel à une méthode Validate après la désérialisation de n'importe quel objet :

<hook type="type">
	<insertAfter>
		System.Xml.Schema.XmlSchema.Validate$TYPE ($OBJECT);
	</insertAfter>
</hook>

Cet exemple spécifie le code à utiliser pour désérialiser la classe XmlSchema :

<hook type="type">
	<select>
		<typeName>System.Xml.Schema.XmlSchema</typeName>
	</select>
	<replace>
		$OBJECT = System.Xml.Schema.XmlSchema.Read (Reader, null);
	</replace>
</hook>

Celui-ci spécifie le code à utiliser pour lire les instances de XmlSchema :

<hook type="type">
	<select>
		<typeName>System.Xml.Schema.XmlSchema</typeName>
	</select>
	<replace>$OBJECT.Write (Writer);</replace>
</hook>

Avec ces deux hooks, le sérialiseur affichera des informations lors de la sérialisation de la classe "MyClass" :

<hook type="type">
	<select>
		<typeName>MyNamespace.MyClass</typeName>
	</select>
	<insertBefore>Console.WriteLine ("Serializing MyClass");</replace>
	<insertAfter>Console.WriteLine ("MyClass serialized");</insertAfter>
</hook>
<hook type="member">
	<select>
		<typeName>MyNamespace.MyClass</typeName>
	</select>
	<insertAfter>
		Console.WriteLine ("Serialized member $MEMBER");
	</insertAfter>
</hook>

Ce hook écrit un élément supplémentaire pour tous les types qui ont l'attribut personnalisé "MyAttribute" :

<hook type="elements">
	<select>
		<typeAttribute>MyNamespace.MyAttribute</typeAttribute>
	</select>
	<insertAfter>
		Writer.WriteStartElement ("privateData");
		Writer.WriteString ($OBJECT.PrivateData);
		Writer.WriteEndElement ();
	</insertAfter>
</hook>

NAME

genxs - serializer/deserializer generator for WSDL/XSD.

SYNOPSIS

genxs [-o output] [-h] [input...]]

DESCRIPTION

genxs is a tool that generates C# serializer/deserializer code for XML Web Services based on WSDL or XSD files. It uses an intermediate XML configuration file to control the generation process.

The main goal of genxs is to provide a flexible mechanism for generating code that can be easily customized to fit specific needs. This is achieved through a system of hooks, which allow the user to intercept and modify the serialization and deserialization processes.

CONFIGURATION FILE FORMAT

The configuration file is an XML file that describes how the serialization and deserialization should be performed. It has the following structure:

<configuration>
  <serializer type="[Namespace.ClassName], [AssemblyName]">
    <reader>[ReaderClassName]</reader>
    <writer>[WriterClassName]</writer>
    <namespace>[Namespace]</namespace>
    <outFileName>[FileName]</outFileName>
    <readerHooks>
      <!-- Reader hooks go here -->
    </readerHooks>
    <writerHooks>
      <!-- Writer hooks go here -->
    </writerHooks>
  </serializer>
  <!-- More serializers can be defined here -->
</configuration>
  • serializer: Defines a serializer for a specific type.
    • type: The fully qualified name of the type to serialize/deserialize, including the assembly name.
  • reader: The base class for the reader.
  • writer: The base class for the writer.
  • namespace: The namespace for the generated code.
  • outFileName: The name of the output file.
  • readerHooks: Contains a list of hooks for the reader.
  • writerHooks: Contains a list of hooks for the writer.

SPECIFYING HOOKS

Hooks are used to customize the serialization and deserialization process. They can be used to handle specific elements, types, or attributes.

<hook type="[hook type]">
  <select>
    <!-- Selection criteria -->
  </select>
  <replace>[Code to execute]</replace>
  <insertBefore>[Code to execute]</insertBefore>
  <insertAfter>[Code to execute]</insertAfter>
</hook>
  • type: The type of hook. Common types include:
    • unknownElement: Handles unknown elements.
    • type: Handles specific types.
    • elements: Handles elements in general.
  • select: Specifies the criteria for selecting the hook. This can include element names, type names, or attribute values.
  • replace: Replaces the default behavior with the specified code.
  • insertBefore: Inserts code before the default behavior.
  • insertAfter: Inserts code after the default behavior.

$OBJECT is a placeholder for the current object being processed.

Reader is a placeholder for the reader object.

Writer is a placeholder for the writer object.

HOOK EXAMPLES

The following examples demonstrate how to use hooks:

  • Handling unknown elements by calling ServiceDescription.ReadExtension: 
    <hook type="unknownElement">
  <select>
    <typeAttribute>System.Web.Services.Configuration.XmlFormatExtensionPointAttribute</typeAttribute>
  </select>
  <replace>ServiceDescription.ReadExtension (Reader, $OBJECT);</replace>
</hook>
  • Reading an XmlSchema object: 
    <hook type="type">
  <select>
    <typeName>System.Xml.Schema.XmlSchema</typeName>
  </select>
  <replace>$OBJECT = System.Xml.Schema.XmlSchema.Read (Reader, null);</replace>
</hook>
  • Writing extensions: 
    <hook type="elements">
  <select>
    <typeAttribute>System.Web.Services.Configuration.XmlFormatExtensionPointAttribute</typeAttribute>
  </select>
  <insertBefore>ServiceDescription.WriteExtensions (Writer, $OBJECT);</insertBefore>
</hook>
  • Writing an XmlSchema object: 
    <hook type="type">
  <select>
    <typeName>System.Xml.Schema.XmlSchema</typeName>
  </select>
  <replace>$OBJECT.Write (Writer);</replace>
</hook>

CONFIGURATION FILE EXAMPLE

This is an example configuration file for generating code for System.Web.Services.Description.ServiceDescription:

<configuration>
	<serializer type="System.Web.Services.Description.ServiceDescription, System.Web.Services">
		<reader>ServiceDescriptionReaderBase</reader>
		<writer>ServiceDescriptionWriterBase</writer>
		<namespace>System.Web.Services.Description</namespace>
		<outFileName>ServiceDescriptionSerializerBase.cs</outFileName>
		<readerHooks>
			<hook type="unknownElement">
				<select>
					<typeAttribute>System.Web.Services.Configuration.XmlFormatExtensionPointAttribute</typeAttribute>
				</select>
				<replace>ServiceDescription.ReadExtension (Reader, $OBJECT);</replace>
			</hook>
			<hook type="type">
				<select>
					<typeName>System.Xml.Schema.XmlSchema</typeName>
				</select>
				<replace>$OBJECT = System.Xml.Schema.XmlSchema.Read (Reader, null);</replace>
			</hook>
		</readerHooks>
		<writerHooks>
			<hook type="elements">
				<select>
					<typeAttribute>System.Web.Services.Configuration.XmlFormatExtensionPointAttribute</typeAttribute>
				</select>
				<insertBefore>ServiceDescription.WriteExtensions (Writer, $OBJECT);</insertBefore>
			</hook>
			<hook type="type">
				<select>
					<typeName>System.Xml.Schema.XmlSchema</typeName>
				</select>
				<replace>$OBJECT.Write (Writer);</replace>
			</hook>
		</writerHooks>
	</serializer>
</configuration>
