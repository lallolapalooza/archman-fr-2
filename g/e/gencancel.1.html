DESCRIPTIO

N

gencancel fournit à l'administrateur de news un outil utile pour générer des messages de contrôle d'annulation, en les écrivant sur la sortie standard. L'article d'annulation généré peut ensuite être injecté par inews (voir les exemples ci-dessous)

.

gencancel attend le Message-ID de l'article à annuler ; cet argument message-id doit être correctement échappé pour le shell et entouré de chevrons. gencancel essaiera alors de lire l'article original dans la file d'attente de news pour déterminer les groupes de discussion originaux dans lesquels il a été publié, et réutilisera cette information pour le message de contrôle d'annulation. Si vous souhaitez la modifier, ou si l'information n'a pas été trouvée, vous devrez la définir avec l'option -n

.

Si INN a été compilé avec la prise en charge de Cancel-Lock, gencancel générera le bon champ d'en-tête admin Cancel-Key à utiliser pour authentifier les annulations. Si, pour une raison quelconque, vous devez annuler un article publié depuis votre serveur de news avec un champ d'en-tête Cancel-Lock, les hachages admin Cancel-Key correspondants sont nécessaires pour authentifier la demande de retrait. Cette information est calculée avec le paramètre canlockadmin défini dans inn-secrets

.conf.

Si vous avez seulement besoin des hachages admin Cancel-Key, vous pouvez utiliser l'option -k. Seul le corps du champ d'en-tête Cancel-Key sera alors écrit sur la sortie standard. Vous pouv

ez ensuite le réutiliser, par exemple dans une d
emande de remplacement ou depuis un autre script.

OPTION

S
-
a
gencancel produit par défaut un champ d'en-tête Approved, utilisant la même valeur que le corps du champ d'en-tête From. Si -a est utilisé, aucun champ d'en-tête Approved n'est produit.

Ce champ d'en-tête est utile pour annuler des articles initialement publiés dans des groupes de discussion modérés. Si un article de contrôle d'annulation liste un groupe de discussion modéré dans son champ d'en-tête Newsgroups, et qu'aucun champ d'en-tête Approved n'est présent, l'annulation sera d'abord envoyée au modérateur pour approbation. Les messages de contrôle d'annulation ne sont pas tenus de contenir un champ d'en-tête Approved en dehors des groupes de discussion modérés, mais peuvent le faire, vous ne devriez donc généralement pas utiliser -a à moins de vouloir vraiment que vos annulations soient approuvées par un modérateur, ou d

'être certain que le champ d'en-tête Newsgrou
ps ne liste aucun groupe de discussion modéré.
-b bo
dy
gencancel écrit par défaut "Admin cancel." dans le corps des messages de contrôle d'annulation. L'utilisation de cet argument permet d'écrire une valeur différente, qui peut être vide ou
multi-lignes.
-c chars
et
Par défaut, "ISO-8859-1" est spécifié comme jeu de caractères utilisé dans le champ d'en-tête Content-Type. Si vous modifiez le corps par défaut avec -b, vous voudrez peut-être aussi changer le charset en
conséquence.
-
d
gencancel génère un champ d'en-tête Date dans l'heure locale de votre serveur de news. L'utilisation de -d utilisera une date en
UTC.
-f fr
om
gencancel utilise par défaut la valeur de complaints dans inn.conf pour le champ d'en-tête From. L'utilisation de cet argument permet de définir la valeur souhaitée. La même valeur sera utilisée pour le champ d'en-tête Approved (s'il est généré, lorsque -a n'est pas donné)
.
-
k
Au lieu de produire un message de contrôle d'annulation complet, gencancel produira seulement le corps du champ d'en-tête Cancel-Key avec les hachages admin.

Cette option n'est disponible q

ue si INN a été compilé avec la
prise en charge de Cancel-Lock.
-
L
gencancel produit par défaut un champ d'en-tête Cancel-Key pour authentifier le message de contrôle d'annulation. Si -L est utilisé, aucun champ d'en-tête Cancel-Key n'est produit.

Cette option n'est disponible q

ue si INN a été compilé avec la
prise en charge de Cancel-Lock.
-
m
gencancel génère par défaut un Message-ID aléatoire et l'utilise comme identifiant unique du message de contrôle d'annulation. Si -m est utilisé, aucun champ d'en-tête Message-ID n'est
produit.
-n newsgrou
ps
gencancel génère par défaut le même champ d'en-tête Newsgroups que celui présent dans l'article original à annuler. Cela est fait pour s'assurer au mieux que le message de contrôle d'annulation sera relayé vers les mêmes serveurs de news que le message original.

Si votre serveur de news ne transporte pas (ou ne transporte plus) localement l'article original, vo

us devrez donner un groupe de discussion explicite ou une liste de groupes de discussion séparés par
des virgules avec cette option, qui sera utilisée comme champ d'en-tête Newsgroups de l'annulation.
-s subje
ct
gencancel utilise par défaut "cmsg cancel <message-id>" comme sujet des messages de contrôle d'annulation. L'utilisa
tion de cet argument permet de définir une valeur
différente pour le champ d'en-tête Subject. Assur
ez-vous qu'elle est correctement encodée en MIME.

EXEMPLE

S

Pour récupérer seulement les hachages admin Cancel-Key associés au Message-ID donné

: 
gencancel -k '<mid@news>
'

Si vous utilisez des caractères non-ASCII dans les en-têtes, assurez-vous de les encoder correctement en MIME. Par exemple, utilisez le module Perl "Encode

" : 
FROM=$(perl -e 'use Encode;
                print encode("MIME-Q",
                             decode("UTF-8", "Julien ELIE"));')
gencancel -f "$FROM <admin@news.server.com>" '<mid@news>
'

Vous verrez alors dans la sortie un champ d'en-tête correctement encodé en MIME

: 
From: =?UTF-8?Q?Julien_=C3=89LIE?= <admin@news.server.
com>

Un exemple d'appel avec un corps multi-lignes personnalisé

: 
gencancel -b "$(echo -e "Multi\nLine\nBody.")" '<mid@news>
'

(Utilisez -c pour changer le jeu de caractères Content-Type par défaut pour le corps.

)

Vous pouvez ensuite envoyer le résultat dans "inews -h -P -D" (signifiant que inews attend un article avec en-têtes, n'ajoute pas de champ d'en-tête Sender, et écrit le résultat sur la sortie standard au lieu de l'injecter réellement)

: 
gencancel '<mid@news>' | inews -h -P
-D

Si tout semble correct, injectez-le dans le système de news (sans donner "-D" à inews)

: 
gencancel '<mid@news>' | inews -h
-P

Notez que inews envoie le message au serveur spécifié dans le paramètre server dans inn.

con
f.
