get_kernel_syms(2) Manuel des appels système get_kernel_syms(2)

NOM

get_kernel_syms - récupérer les symboles exportés du noyau et des modules

SYNTAXE

#include <linux/module.h>
[[deprecated]] int get_kernel_syms(struct kernel_sym *table);

DESCRIPTION

Note : Cet appel système n'est présent qu'avant Linux 2.6.

Si table est NULL, get_kernel_syms() renvoie le nombre de symboles disponibles pour la requête. Sinon, il remplit une table de structures :


struct kernel_sym {
    unsigned long value;
    char          name[60];
};

Les symboles sont entrelacés avec des symboles magiques de la forme #nom-du-module, le noyau ayant un nom vide. La valeur associée à un symbole de cette forme est l'adresse à laquelle le module est chargé.

Les symboles exportés par chaque module suivent leur marqueur de module magique et les modules sont retournés dans l'ordre inverse de celui de leur chargement.

VALEUR RENVOYÉE

En cas de succès, renvoie le nombre de symboles copiés dans table. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

Il n'y a qu'un seul retour d'erreur possible :

ENOSYS
get_kernel_syms() n'est pas pris en charge dans cette version du noyau.

STANDARDS

Linux.

HISTORIQUE

Supprimé dans Linux 2.6.

Cet appel système obsolète n'est pas pris en charge par glibc. Aucune déclaration n'est fournie dans les en-têtes glibc, mais, par un hasard historique, les versions de glibc antérieures à glibc 2.23 exportaient une ABI pour cet appel système. Par conséquent, pour utiliser cet appel système, il suffisait de déclarer manuellement l'interface dans votre code ; alternativement, vous pouviez invoquer l'appel système en utilisant syscall(2).

BOGUES

Il n'y a aucun moyen d'indiquer la taille du tampon alloué pour table. Si des symboles ont été ajoutés au noyau depuis que le programme a interrogé la taille de la table des symboles, la mémoire sera corrompue.

La longueur des noms de symboles exportés est limitée à 59 caractères.

En raison de ces limitations, cet appel système est déprécié au profit de query_module(2) (qui est lui-même aujourd'hui déprécié au profit d'autres interfaces décrites sur sa page de manuel).

VOIR AUSSI

create_module(2), delete_module(2), init_module(2), query_module(2)
