gethostname(2) Manuel des appels système gethostname(2)

NOM

gethostname, sethostname - obtenir/définir le nom d'hôte

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int gethostname(char *name, size_t size);
int sethostname(const char *name, size_t size);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

gethostname():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc 2.19 et antérieur */ _BSD_SOURCE

sethostname():

    Depuis glibc 2.21:
        _DEFAULT_SOURCE
    Dans glibc 2.19 et 2.20:
        _DEFAULT_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)
    Jusqu'à et y compris glibc 2.19:
        _BSD_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)

DESCRIPTION

Ces appels système sont utilisés pour accéder ou modifier le nom d'hôte du système. Plus précisément, ils opèrent sur le nom d'hôte associé à l'espace de noms UTS du processus appelant.

sethostname() définit le nom d'hôte à la valeur fournie dans le tableau de caractères name. L'argument size spécifie le nombre d'octets dans name. (Ainsi, name n'a pas besoin d'un octet nul de fin.)

gethostname() renvoie le nom d'hôte terminé par un octet nul dans le tableau de caractères name, dont la taille est de size octets. Si le nom d'hôte terminé par un octet nul est trop grand pour tenir, le nom est tronqué et aucune erreur n'est renvoyée (mais voir VERSIONS ci-dessous). POSIX.1 indique que si une telle troncature se produit, il n'est pas spécifié si le tampon renvoyé inclut un octet nul de fin.

VALEUR DE RETOUR

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
name est une adresse invalide.
EINVAL
size est négatif ou, pour sethostname(), size est supérieur à la taille maximale autorisée.
ENAMETOOLONG
(glibc gethostname()) size est plus petit que la taille réelle. (Avant glibc 2.1, glibc utilise EINVAL pour ce cas.)
EPERM
Pour sethostname(), l'appelant ne possédait pas la capacité CAP_SYS_ADMIN dans l'espace de noms utilisateur associé à son espace de noms UTS (voir namespaces(7)).

VERSIONS

SUSv2 garantit que "Les noms d'hôte sont limités à 255 octets". POSIX.1 garantit que "Les noms d'hôte (sans l'octet nul de fin) sont limités à HOST_NAME_MAX octets". Sous Linux, HOST_NAME_MAX est défini avec la valeur 64, ce qui est la limite depuis Linux 1.0 (les noyaux précédents imposaient une limite de 8 octets).

Différences bibliothèque C/noyau

La bibliothèque GNU C n'utilise pas l'appel système gethostname(); elle implémente plutôt gethostname() comme une fonction de bibliothèque qui appelle uname(2) et copie jusqu'à size octets du champ nodename renvoyé dans name. Après avoir effectué la copie, la fonction vérifie si la longueur de nodename est supérieure ou égale à size. Si c'est le cas, la fonction renvoie -1 avec errno défini à ENAMETOOLONG ; dans ce cas, un octet nul de fin n'est pas inclus dans name.

NORMES

gethostname()
POSIX.1-2024.
sethostname()
Aucune.

HISTORIQUE

SVr4, 4.4BSD (ces interfaces sont apparues pour la première fois dans 4.2BSD). POSIX.1 spécifie gethostname() mais pas sethostname().

Les versions de glibc antérieures à glibc 2.2 géraient différemment le cas où la longueur de nodename était supérieure ou égale à size : rien n'était copié dans name et la fonction renvoyait -1 avec errno défini à ENAMETOOLONG.

VOIR AUSSI
