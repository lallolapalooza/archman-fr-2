sous-routine cgedmd (character, intent(in) jobs, character, intent(in) jobz, character, intent(in) jobr, character, intent(in) jobf, integer, intent(in) whtsvd, integer, intent(in) m, integer, intent(in) n, complex(kind=wp), dimension(ldx,*), intent(inout) x, integer, intent(in) ldx, complex(kind=wp), dimension(ldy,*), intent(inout) y, integer, intent(in) ldy, integer, intent(in) nrnk, real(kind=wp), intent(in) tol, integer, intent(out) k, complex(kind=wp), dimension(*), intent(out) eigs, complex(kind=wp), dimension(ldz,*), intent(out) z, integer, intent(in) ldz, real(kind=wp), dimension(*), intent(out) res, complex(kind=wp), dimension(ldb,*), intent(out) b, integer, intent(in) ldb, complex(kind=wp), dimension(ldw,*), intent(out) w, integer, intent(in) ldw, complex(kind=wp), dimension(lds,*), intent(out) s, integer, intent(in) lds, complex(kind=wp), dimension(*), intent(out) zwork, integer, intent(in) lzwork, real(kind=wp), dimension(*), intent(out) rwork, integer, intent(in) lrwork, integer, dimension(*), intent(out) iwork, integer, intent(in) liwork, integer, intent(out) info)

CGEDMD calcule la Décomposition Dynamique de Mode (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    CGEDMD calcule la Décomposition Dynamique de Mode (DMD) pour
!>    une paire de matrices d'instantanés de données. Pour les matrices d'entrée
!>    X et Y telles que Y = A*X avec une matrice A inaccessible,
!>    CGEDMD calcule un certain nombre de paires de Ritz de A en utilisant
!>    l'extraction de Rayleigh-Ritz standard d'un sous-espace
!>    de range(X) déterminé à l'aide des vecteurs singuliers gauches principaux
!>    de X. Optionnellement, CGEDMD retourne les résidus
!>    des paires de Ritz calculées, les informations nécessaires pour
!>    un raffinement des vecteurs de Ritz, ou les vecteurs propres
!>    de la DMD exacte.
!>    Pour plus de détails, voir les références ci-dessous. Pour plus de détails sur l'implémentation, voir [3].
!>

Références :

!>    [1] P. Schmid : Dynamic mode decomposition of numerical
!>        and experimental data,
!>        Journal of Fluid Mechanics 656, 5-28, 2010.
!>    [2] Z. Drmac, I. Mezic, R. Mohr : Data driven modal
!>        decompositions: analysis and enhancements,
!>        SIAM J. on Sci. Comp. 40 (4), A2253-A2285, 2018.
!>    [3] Z. Drmac : A LAPACK implementation of the Dynamic
!>        Mode Decomposition I. Rapport technique. AIMDyn Inc.
!>        et LAPACK Working Note 298.
!>    [4] J. Tu, C. W. Rowley, D. M. Luchtenburg, S. L.
!>        Brunton, N. Kutz : On Dynamic Mode Decomposition:
!>        Theory and Applications, Journal of Computational
!>        Dynamics 1(2), 391 -421, 2014.
!>

Paramètres

JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D telle que X*D ait des colonnes non nulles unitaires
!>           (en norme euclidienne 2)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il s'avère qu'une i-ème colonne de X est un vecteur
!>
non-nul, alors la i-ème colonne de Y est mise à !> zéro et un drapeau d'avertissement est levé. !> 'Y' :: Les matrices de données instantanées X et Y sont multipliées !> par une matrice diagonale D de sorte que Y*D ait des colonnes !> non nulles unitaires (dans la norme euclidienne 2). !> 'N' :: Pas de mise à l'échelle des données. !>

JOBZ

!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et retournés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront retournés
!>           sous forme factorisée comme le produit X(:,1:K)*W, où X
!>           contient une base POD (vecteurs singuliers gauches principaux
!>           de la matrice de données X) et W contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de K, X, W, Z.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!>

JOBR

!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus pour les paires propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit valide, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!>

JOBF

!>    JOBF (entrée) CHARACTER*1
!>    Spécifie s'il faut stocker les informations nécessaires au post-
!>    traitement (par exemple le calcul de vecteurs Ritz affinés)
!>    'R' :: La matrice nécessaire au raffinement des vecteurs Ritz
!>           est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non mis à l'échelle du DMD Exact
!>           sont calculés et retournés dans le tableau B. Voir la
!>           description de B.
!>    'N' :: Aucune donnée de raffinement de vecteurs propres n'est calculée.
!>

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet la sélection de l'algorithme SVD à partir de la
!>    bibliothèque LAPACK.
!>    1 :: CGESVD (l'algorithme SVD par QR)
!>    2 :: CGESDD (l'algorithme Diviser pour Régner ; si suffisamment
!>         d'espace de travail est disponible, c'est l'option la plus rapide)
!>    3 :: CGESVDQ (le SVD par QR préconditionné ; ceci et 4
!>         sont les options les plus précises)
!>    4 :: CGEJSV (le SVD par Jacobi préconditionné ; ceci et 3
!>         sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative dans
!>    la précision des petites valeurs singulières est possible si
!>    les instantanés varient en norme de sorte que X soit sévèrement
!>    mal conditionnée. Si les petites valeurs singulières (plus petites que EPS*||X||)
!>    sont d'intérêt et que JOBS=='N', alors
!>    les options (3, 4) donnent les résultats les plus précis, où
!>    l'option 4 est légèrement meilleure et avec un fondement théorique
!>    plus solide.
!>    Si JOBS=='S', c'est-à-dire si les colonnes de X seront normalisées,
!>    alors toutes les méthodes donnent des résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M>= 0
!>    La dimension de l'espace d'état (la dimension des lignes de X, Y).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de paires d'instantanés de données
!>    (le nombre de colonnes de X et Y).
!>

X

!>    X (entrée/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée, X contient la matrice d'instantanés de données X. On
!>    suppose que les normes des colonnes de X sont dans l'intervalle des
!>    nombres flottants normalisés.
!>    < À la sortie, les K premières colonnes de X contiennent une base POD,
!>    c'est-à-dire les K premiers vecteurs singuliers gauches de la matrice
!>    de données d'entrée X, U(:,1:K). Les N colonnes de X contiennent tous
!>    les vecteurs singuliers gauches de la matrice d'entrée X.
!>    Voir les descriptions de K, Z et W.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= M
!>    La dimension principale du tableau X.
!>

Y

!>    Y (entrée/espace de travail/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée, Y contient la matrice d'instantanés de données Y
!>    < À la sortie,
!>    Si JOBR == 'R', les K premières colonnes de Y contiennent
!>    les vecteurs résidus pour les paires de Ritz calculées.
!>    Voir la description de RES.
!>    Si JOBR == 'N', Y contient les données d'entrée originales,
!>                    mises à l'échelle selon la valeur de JOBS.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= M
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique,
!>    c'est-à-dire comment tronquer les petites valeurs singulières de la matrice
!>    d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite un SVD hautement précis, ce qui
!>                 peut ne pas être faisable.
!>    Le rang numérique peut être forcé en utilisant une valeur
!>    positive de NRNK comme suit :
!>    0 < NRNK <= N :: au plus NRNK des plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles
!>    calculées est inférieur à NRNK, alors seules ces valeurs
!>    non nulles seront utilisées et la dimension réellement utilisée
!>    est inférieure à NRNK. Le nombre réel de
!>    valeurs singulières non nulles est retourné dans la variable
!>    K. Voir les descriptions de TOL et K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour la troncature des petites valeurs singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER,  0 <= K <= N
!>    La dimension de la base POD pour la matrice d'instantanés
!>    de données X et le nombre de paires de Ritz calculées.
!>    La valeur de K est déterminée selon la règle établie
!>    par les paramètres NRNK et TOL.
!>    Voir les descriptions de NRNK et TOL.
!>

EIGS

!>    EIGS (sortie) COMPLEX(KIND=WP) tableau N-par-1
!>    Les K premières entrées (K<=N) de EIGS contiennent
!>    les valeurs propres calculées (valeurs de Ritz).
!>    Voir les descriptions de K et Z.
!>

Z

!>    Z (espace de travail/sortie) COMPLEX(KIND=WP)  tableau M-par-N
!>    Si JOBZ =='V' alors Z contient les vecteurs de Ritz.  Z(:,i)
!>    est un vecteur propre de la i-ème valeur de Ritz ; ||Z(:,i)||_2=1.
!>    Si JOBZ == 'F', alors les Z(:,i) sont donnés implicitement comme
!>    les colonnes de X(:,1:K)*W(1:K,1:K), c'est-à-dire que X(:,1:K)*W(:,i)
!>    est un vecteur propre correspondant à EIGS(i). Les colonnes
!>    de W(1:k,1:K) sont les vecteurs propres calculés du
!>    quotient de Rayleigh K-par-K.
!>    Voir les descriptions de EIGS, X et W.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau N-par-1
!>    RES(1:K) contient les résidus pour les K paires
!>    de Ritz calculées,
!>    RES(i) = || A * Z(:,i) - EIGS(i)*Z(:,i))||_2.
!>    Voir la description de EIGS et Z.
!>

B

!>    B (sortie) COMPLEX(KIND=WP)  tableau M-par-N.
!>    SI JOBF =='R', B(1:M,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs affinés ; voir plus de
!>    détails dans les références fournies.
!>    Si JOBF == 'E', B(1:M,1:K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du
!>    DMD Exact, à une mise à l'échelle par les valeurs propres inverses près.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>    Voir les descriptions de X, W, K.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= M
!>    La dimension principale du tableau B.
!>

W

!>    W (espace de travail/sortie) COMPLEX(KIND=WP) tableau N-par-N
!>    À la sortie, W(1:K,1:K) contient les K vecteurs propres
!>    calculés du quotient de Rayleigh matriciel.
!>    Les vecteurs de Ritz (retournés dans Z) sont le
!>    produit de X (contenant une base POD pour la matrice
!>    d'entrée X) et W. Voir les descriptions de K, S, X et Z.
!>    W est également utilisé comme espace de travail pour stocker temporairement les
!>    vecteurs singuliers droits de X.
!>

LDW

!>    LDW (entrée) INTEGER, LDW >= N
!>    La dimension principale du tableau W.
!>

S

!>    S (espace de travail/sortie) COMPLEX(KIND=WP) tableau N-par-N
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de Rayleigh
!>    matriciel. Ce contenu est écrasé pendant
!>    la décomposition en valeurs propres par CGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) INTEGER, LDS >= N
!>    La dimension principale du tableau S.
!>

ZWORK

!>    ZWORK (espace de travail/sortie) COMPLEX(KIND=WP) tableau LZWORK-par-1
!>    ZWORK est utilisé comme espace de travail complexe dans le SVD complexe, tel
!>    que spécifié par WHTSVD (1,2, 3 ou 4) et pour CGEEV pour calculer
!>    les valeurs propres d'un quotient de Rayleigh.
!>    Si l'appel à CGEDMD n'est qu'une interrogation d'espace de travail, alors
!>    ZWORK(1) contient la longueur minimale de l'espace de travail complexe et
!>    ZWORK(2) est la longueur optimale de l'espace de travail complexe.
!>    Ainsi, la longueur du travail est d'au moins 2.
!>    Voir la description de LZWORK.
!>

LZWORK

!>    LZWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail ZWORK.
!>    LZWORK est calculé comme MAX(LZWORK_SVD, LZWORK_CGEEV),
!>    où LZWORK_CGEEV = MAX( 1, 2*N )  et le minimal
!>    LZWORK_SVD est calculé comme suit
!>    Si WHTSVD == 1 :: CGESVD ::
!>       LZWORK_SVD = MAX(1,2*MIN(M,N)+MAX(M,N))
!>    Si WHTSVD == 2 :: CGESDD ::
!>       LZWORK_SVD = 2*MIN(M,N)*MIN(M,N)+2*MIN(M,N)+MAX(M,N)
!>    Si WHTSVD == 3 :: CGESVDQ ::
!>       LZWORK_SVD = obtenable par une interrogation
!>    Si WHTSVD == 4 :: CGEJSV ::
!>       LZWORK_SVD = obtenable par une interrogation
!>    Si à l'entrée LZWORK = -1, alors une interrogation d'espace de travail est
!>    supposée et la procédure ne calcule que les longueurs minimale
!>    et optimale de l'espace de travail et les retourne dans
!>    LZWORK(1) et LZWORK(2), respectivement.
!>

RWORK

!>    RWORK (espace de travail/sortie) REAL(KIND=WP) tableau LRWORK-par-1
!>    À la sortie, RWORK(1:N) contient les valeurs singulières de
!>    X (pour JOBS=='N') ou de X mis à l'échelle par colonnes (JOBS=='S', 'C').
!>    Si WHTSVD==4, alors RWORK(N+1) et RWORK(N+2) contiennent
!>    le facteur de mise à l'échelle RWORK(N+2)/RWORK(N+1) utilisé pour mettre à l'échelle X
!>    et Y afin d'éviter un débordement dans le SVD de X.
!>    Cela peut être d'intérêt si l'option de mise à l'échelle est désactivée
!>    et que l'on souhaite autant de valeurs propres petites que possible
!>    avec la plus haute précision faisable.
!>    Si l'appel à CGEDMD n'est qu'une interrogation d'espace de travail, alors
!>    RWORK(1) contient la longueur minimale de l'espace de travail.
!>    Voir la description de LRWORK.
!>

LRWORK

!>    LRWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail RWORK.
!>    LRWORK est calculé comme suit :
!>    LRWORK = MAX(1, N+LRWORK_SVD,N+LRWORK_CGEEV), où
!>    LRWORK_CGEEV = MAX(1,2*N) et RWORK_SVD est l'espace de travail réel
!>    pour la sous-routine SVD déterminé par le paramètre d'entrée
!>    WHTSVD.
!>    Si WHTSVD == 1 :: CGESVD ::
!>       LRWORK_SVD = 5*MIN(M,N)
!>    Si WHTSVD == 2 :: CGESDD ::
!>       LRWORK_SVD =  MAX(5*MIN(M,N)*MIN(M,N)+7*MIN(M,N),
!>       2*MAX(M,N)*MIN(M,N)+2*MIN(M,N)*MIN(M,N)+MIN(M,N) ) )
!>    Si WHTSVD == 3 :: CGESVDQ ::
!>       LRWORK_SVD = obtenable par une requête
!>    Si WHTSVD == 4 :: CGEJSV ::
!>       LRWORK_SVD = obtenable par une requête
!>    Si à l'entrée LRWORK = -1, une requête d'espace de travail est
!>    supposée et la procédure ne calcule que la longueur minimale
!>    de l'espace de travail réel et la retourne dans RWORK(1).
!
>

IWOR

K 
!>    IWORK (espace de travail/sortie) tableau INTEGER LIWORK-par-1
!>    Espace de travail requis uniquement si WHTSVD vaut
!>    2, 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, la
!>    longueur minimale de IWORK est calculée et retournée dans
!>    IWORK(1). Voir la description de LIWORK.
!
>

LIWOR

K 
!>    LIWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail IWORK.
!>    Si WHTSVD == 1, alors seul IWORK(1) est utilisé ; LIWORK >=1
!>    Si WHTSVD == 2, alors LIWORK >= MAX(1,8*MIN(M,N))
!>    Si WHTSVD == 3, alors LIWORK >= MAX(1,M+N-1)
!>    Si WHTSVD == 4, alors LIWORK >= MAX(3,M+3*N)
!>    Si à l'entrée LIWORK = -1, une requête d'espace de travail est
!>    supposée et la procédure ne calcule que les longueurs minimale
!>    et optimale des espaces de travail pour ZWORK, RWORK et
!>    IWORK. Voir les descriptions de ZWORK, RWORK et IWORK.
!
>

INF

O 
!>    INFO (sortie) INTEGER
!>    -i < 0 :: À l'entrée, le i-ème argument avait une
!>              valeur illégale
!>       = 0 :: Retour réussi.
!>       = 1 :: Entrée vide. Sortie rapide (M=0 ou N=0).

DGEDMD calcule la décomposition dynamique de mode (DMD) pour une paire de matrices d'instantanés de données.

Objectif :

!>    DGEDMD calcule la décomposition dynamique de mode (DMD) pour
!>    une paire de matrices d'instantanés de données. Pour les matrices d'entrée
!>    X et Y telles que Y = A*X avec une matrice inaccessible
!>    A, DGEDMD calcule un certain nombre de paires de Ritz de A en utilisant
!>    l'extraction standard de Rayleigh-Ritz à partir d'un sous-espace
!>    de range(X) qui est déterminé en utilisant les vecteurs singuliers gauches principaux
!>    de X. Optionnellement, DGEDMD retourne les résidus
!>    des paires de Ritz calculées, les informations nécessaires pour
!>    un raffinement des vecteurs de Ritz, ou les vecteurs propres
!>    de la DMD exacte.
!>    Pour plus de détails, voir les références listées
!>    ci-dessous. Pour plus de détails sur l'implémentation, voir [3].
!>

!>    RES (sortie) tableau N-par-1 REAL(KIND=WP)

!>    calculées.

!>       RES(i) = || A * Z(:,i) - LAMBDA(i)*Z(:,i))||_2.

!>    où B = [ real(LAMBDA(i)) imag(LAMBDA(i)) ]
!>          [-imag(LAMBDA(i)) real(LAMBDA(i)) ].
!>    Il est vrai que
!>    RES(i)   = || A*ZC(:,i)   - LAMBDA(i)  *ZC(:,i)   ||_2
!>    RES(i+1) = || A*ZC(:,i+1) - LAMBDA(i+1)*ZC(:,i+1) ||_2
!>    où ZC(:,i)   =  Z(:,i) + sqrt(-1)*Z(:,i+1)
!>          ZC(:,i+1) =  Z(:,i) - sqrt(-1)*Z(:,i+1)
!>    Voir la description de REIG, IMEIG et Z.

Detailed Description


This subroutine computes the singular value decomposition (SVD) of
    a general matrix X, where


    X = U * S * V**H



Here, S is a R-by-R diagonal matrix with non-negative real numbers
    (singular values) on the diagonal. U and V are R-by-R unitary matrices.


The subroutine uses the QR algorithm to compute the SVD.

The minimal workspace lengths are given by:


WORK(1) contains the minimal workspace length and WORK(2) is the
    optimal workspace length. hence, the length of work is at least 2.
    See the description of LWORK.


LWORK


LWORK (input) INTEGER
    The minimal length of the workspace vector WORK.
    LWORK is the same as in ZGEDMD, because in ZGEDMDQ only ZGEDMD requires
    real workspace for snapshots of dimensions MIN(M,N)-by-(N-1).
    If on entry LWORK = -1, then a workspace query is assumed and the
    procedure only computes the minimal and the optimal workspace length for
    WORK.


IWORK


IWORK (workspace/output) INTEGER LIWORK-by-1 array
    Workspace that is required only if WHTSVD equals 2 , 3 or 4 . (See the
    description of WHTSVD).
    If on entry LWORK =-1 or LIWORK=-1, then the minimal length of IWORK is
    computed and returned in IWORK(1). See the description of LIWORK.


LIWORK


LIWORK (input) INTEGER
    The minimal length of the workspace vector IWORK.
    If WHTSVD == 1, then only IWORK(1) is used; LIWORK >=1
    Let M1=MIN(M,N), N1=N-1. Then
    If WHTSVD == 2, then LIWORK >= MAX(1,8*MIN(M1,N1))
    If WHTSVD == 3, then LIWORK >= MAX(1,M1+N1-1)
    If WHTSVD == 4, then LIWORK >= MAX(3,M1+3*N1)
    If on entry LIWORK = -1, then a workspace query is assumed and the
    procedure only computes the minimal and the optimal workspace lengths
    for both WORK and IWORK. See the descriptions of WORK and IWORK.


INFO


INFO (output) INTEGER
    -i < 0 :: On entry, the i-th argument had an illegal value
       = 0 :: Successful return.
       = 1 :: Void input. Quick exit (M=0 or N=0).
       = 2 :: The SVD computation of X did not converge.

       = 3 :: The computation of the eigenvalues did not converge.
