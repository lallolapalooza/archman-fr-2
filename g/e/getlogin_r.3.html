getlogin(3) Manuel des fonctions de bibliothèque getlogin(3)

NOM

getlogin, getlogin_r, cuserid - obtenir le nom d'utilisateur

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <unistd.h>
char *getlogin(void);
int getlogin_r(size_t bufsize;
               char buf[bufsize], size_t bufsize);
#include <stdio.h>
char *cuserid(char *string);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

getlogin_r():

    _POSIX_C_SOURCE >= 199506L

cuserid():

    Depuis glibc 2.24 :
        (_XOPEN_SOURCE && ! (_POSIX_C_SOURCE >= 200112L)
            || _GNU_SOURCE
    Jusqu'à et y compris glibc 2.23 :
        _XOPEN_SOURCE

DESCRIPTION

getlogin() renvoie un pointeur vers une chaîne contenant le nom de l'utilisateur connecté sur le terminal de contrôle du processus, ou un pointeur nul si cette information ne peut pas être déterminée. La chaîne est allouée statiquement et peut être écrasée lors des appels ultérieurs à cette fonction ou à cuserid().

getlogin_r() renvoie ce même nom d'utilisateur dans le tableau buf de taille bufsize.

cuserid() renvoie un pointeur vers une chaîne contenant un nom d'utilisateur associé à l'identifiant effectif du processus. Si string n'est pas un pointeur nul, il doit s'agir d'un tableau pouvant contenir au moins L_cuserid caractères ; la chaîne est renvoyée dans ce tableau. Sinon, un pointeur vers une chaîne dans une zone statique est renvoyé. Cette chaîne est allouée statiquement et peut être écrasée lors des appels ultérieurs à cette fonction ou à getlogin().

La macro L_cuserid est une constante entière indiquant la longueur du tableau dont vous pourriez avoir besoin pour stocker un nom d'utilisateur. L_cuserid est déclarée dans <stdio.h>.

Ces fonctions permettent à votre programme d'identifier positivement l'utilisateur qui s'exécute (cuserid()) ou l'utilisateur qui s'est connecté à cette session (getlogin()). (Ces deux informations peuvent différer lorsque des programmes avec identifiant d'utilisateur effectif sont impliqués.)

Pour la plupart des usages, il est plus utile d'utiliser la variable d'environnement LOGNAME pour déterminer qui est l'utilisateur. C'est plus flexible précisément parce que l'utilisateur peut définir LOGNAME arbitrairement.

VALEUR RENVOYÉE

getlogin() renvoie un pointeur vers le nom d'utilisateur en cas de succès, et NULL en cas d'échec, avec errno défini pour indiquer l'erreur. getlogin_r() renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec.

ERREURS

POSIX spécifie :

EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite du système sur le nombre total de fichiers ouverts a été atteinte.
ENXIO
Le processus appelant n'a pas de terminal de contrôle.
ERANGE
(getlogin_r) La longueur du nom d'utilisateur, y compris l'octet nul de terminaison ('\0'), est supérieure à bufsize.

Linux/glibc a aussi :

ENOENT
Il n'y avait pas d'entrée correspondante dans le fichier utmp.
ENOMEM
Mémoire insuffisante pour allouer la structure passwd.
ENOTTY
L'entrée standard ne référençait pas un terminal. (Voir ANOMALIES.)

FICHIERS

/etc/passwd
fichier de base de données des mots de passe
/var/run/utmp
(traditionnellement /etc/utmp; certaines versions de libc utilisaient /var/adm/utmp)

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
getlogin () Sécurité des threads MT-Unsafe race:getlogin race:utent sig:ALRM timer locale
getlogin_r () Sécurité des threads MT-Unsafe race:utent sig:ALRM timer locale
cuserid () Sécurité des threads MT-Unsafe race:cuserid/!string locale

Dans le tableau ci-dessus, utent dans race:utent signifie que si l'une des fonctions setutent(3), getutent(3), ou endutent(3) est utilisée en parallèle dans différents threads d'un programme, des conditions de course sur les données peuvent survenir. getlogin() et getlogin_r() appellent ces fonctions, nous utilisons donc race:utent pour rappeler cela aux utilisateurs.

VERSIONS

OpenBSD possède getlogin() et setlogin(), et un nom d'utilisateur associé à une session, même si elle n'a pas de terminal de contrôle.

NORMES

getlogin_r()

cuserid()

NORMES

ANOMALIES

Malheureusement, il est souvent plutôt facile de tromper getlogin(). Parfois, cela ne fonctionne pas du tout, car certains programmes ont corrompu le fichier utmp. Souvent, cela ne donne que les 8 premiers caractères du nom de connexion. L'utilisateur actuellement connecté sur le terminal de contrôle de notre programme n'est pas nécessairement celui qui l'a démarré. Évitez getlogin() pour des usages liés à la sécurité.

Notez que glibc ne suit pas la spécification POSIX et utilise stdin au lieu de /dev/tty. Une anomalie. (D'autres systèmes récents, comme SunOS 5.8, HP-UX 11.11 et FreeBSD 4.8 renvoient aussi le nom de connexion lorsque stdin est redirigé.)

Personne ne sait précisément ce que cuserid() fait ; évitez-le dans les programmes portables. Ou évitez-le tout simplement : utilisez getpwuid(geteuid()) à la place, si c'est ce que vous vouliez. N'utilisez pas cuserid().

VOIR AUSSI
