DESCRIPTIO

N

Les fonctions getdns_general(3) et getdns_general_sync fournissent des points d'entrée publics dans la bibliothèque d'API getdns pour récupérer toutes les réponses valides à une requête auprès du DNS (notez que les autres espaces de noms dans le contexte ne sont pas utilisés). La plupart des cas d'utilisation typiques des applications sont probablement satisfaits par des appels à getdns_address(3) qui remplacerait getaddrinfo(3)

.

context Un pointeur vers le contexte DNS précédemment créé qui doit être utilisé avec cette requête DNS. Voir getdns_context

(3)

name Le nom de domaine basé sur ASCII recherché sous forme de chaîne. Il peut également s'agir d'une adresse IPv4 ou IPv6 pour les types de requête qui prennent des adresses au lieu de noms de domaine, comme PTR. Les valeurs ici suivent les règles de la section 2.1 de la RFC 4343 pour autoriser les octets non ASCII et les caractères spéciaux dans les

libellés.

request_type Spécifie le RRtype pour la requête ; les numéros de RRtype sont listés dans le registre IANA. Par exemple, pour obtenir les enregistrements NS, request_type serait 2. L'API a également défini des macros pour la plupart des RRtypes par nom ; les noms de définition commencent tous par "GETDNS_RRTYPE_". Par exemple, pour obtenir les enregistrements NS, vous pouvez également définir request_type sur GETDNS_RRTYPE_NS

.

extensions extensions pour cette requête, NULL si aucune extension, voir libgetnds (3) pour une description détaillée des

extensions

userarg renvoyé à la fonction de rappel intact, peut être

NULL

transaction_id rempli par l'API et utilisé pour identifier le rappel (par exemple pour getdns_cancel_callback), peut être NULL, défini à 0 si la fonction

échoue

callbackfn pointeur non-NULL vers une fonction de rappel définie par l'application, généralement utilisée pour traiter la réponse. Seule la signature asynchrone accepte une fonction de rappel, la signature synchrone n'inclut pas de rappel. Voir libgetdns (3) pour une discussion plus détaillée des fonctions de

rappel.

response Un type getdns_dict est renvoyé dans response et contient toujours au moins trois noms : replies_full (une liste contenant la réponse DNS sous forme de données binaires), repl

ies_tree (une liste contenant les données de réponse DNS analysées) et status (un int). Le
stockage associé à cela doit être libéré par un appel à getdns_free_sync_request_memory (3).

VALEURS DE

RETOUR

Lors d'une exécution réussie, les fonctions renvoient GETDNS_RETURN_GOOD , sinon les valeurs d'erreur suivantes sont renvoyées

:

GETDNS_RETURN_BAD_CONTEXT si le pointeur de contexte est invalide ou si le contexte a des défauts

internes

GETDNS_RETURN_BAD_DOMAIN_NAME si le nom de domaine passé à la fonction est

invalide

GETDNS_RETURN_EXTENSION_MISFORMAT si le type de données spécifié dans une ou plusieurs des extensions ne correspond pas aux

spécifications

GETDNS_RETURN_GENERIC_ERROR si un problème a été rencontré dans la fonction qui n'est pas traité par l'un des codes de retour plus

spécifiques

GETDNS_RETURN_INVALID PARAMETER si un ou plusieurs paramètres ont une valeur

invalide

GETDNS_RETURN_MEMORY_ERROR si impossible d'allouer la mémoire

requise

GETDNS_RETURN_NO_SUCH_EXTENSION si une ou plusieurs des chaînes spécifiées dans les extensions ne sont pas

valides

Les valeurs de status incluses dans le paramètre response sont

:

GETDNS_RESPSTATUS_GOOD si au moins une réponse a été

renvoyée

GETDNS_RESPSTATUS_NO_NAME si les requêtes pour le nom ont produit uniquement des réponses

négatives

GETDNS_RESPSTATUS_ALL_TIMEOUT si toutes les requêtes pour le nom ont

expiré

GETDNS_RESPSTATUS_NO_SECURE_ANSWERS si seules des réponses sécurisées ont été acceptées (selon le contexte) et si au moins une réponse a été reçue mais aucune réponse DNS n'était sécurisée via

DNSSEC

Pour une explication plus détaillée de l'objet de réponse, voir libget
