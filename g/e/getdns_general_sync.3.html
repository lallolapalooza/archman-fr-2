getdns_general(3) getdns getdns_general(3)

NOM

getdns_general, getdns_general_sync -- effectuer une requête DNS getdns

BIBLIOTHÈQUE

Bibliothèque de résolution DNS (libgetdns, -lgetdns)

SYNTAXE

#include <getdns.h>

getdns_return_t
getdns_general (getdns_context *context,

const char *name,
uint16_t request_type
getdns_dict *extensions,
void *userarg,
getdns_transaction_t *transaction_id,
getdns_callback_t callbackfn)

getdns_return_t
getdns_general_sync (getdns_context *context,

const char *name,
uint16_t request_type
getdns_dict *extensions,
getdns_dict **response)

DESCRIPTION

Les fonctions getdns_general(3) et getdns_general_sync fournissent des points d'entrée publics à la bibliothèque d'API getdns pour récupérer toute réponse valide à une requête du DNS (notez que les autres espaces de noms dans le contexte ne sont pas utilisés). La plupart des cas d'utilisation typiques pour les applications sont probablement satisfaits par des appels à getdns_address(3) qui remplaceraient getaddrinfo(3).

context Un pointeur vers le contexte DNS précédemment créé qui doit être utilisé avec cette requête DNS. Voir getdns_context (3)

name Le nom de domaine basé sur ASCII recherché sous forme de chaîne. Il peut également s'agir d'une adresse IPv4 ou IPv6 pour les types de requêtes qui acceptent des adresses au lieu de noms de domaine, tels que PTR. Les valeurs ici suivent les règles de la section 2.1 de la RFC 4343 pour autoriser les octets non-ASCII et les caractères spéciaux dans les étiquettes.

request_type Spécifie le type d'enregistrement (RRtype) pour la requête ; les numéros de RRtype sont listés dans le registre de l'IANA. Par exemple, pour obtenir les enregistrements NS, request_type serait 2. L'API dispose également de macros définies pour la plupart des RRtypes par leur nom ; les noms de définition commencent tous par "GETDNS_RRTYPE_". Par exemple, pour obtenir les enregistrements NS, vous pouvez également définir request_type sur GETDNS_RRTYPE_NS.

extensions Extensions pour cette requête, NULL s'il n'y a pas d'extensions, voir libgetnds (3) pour une description détaillée des extensions

userarg Retourné à la fonction de rappel intact, peut être NULL

transaction_id Rempli par l'API et utilisé pour identifier le rappel (par exemple, pour getdns_cancel_callback), peut être NULL, défini à 0 si la fonction échoue

callbackfn Pointeur non-NULL vers une fonction de rappel définie par l'application, généralement utilisée pour traiter la réponse. Seule la signature asynchrone accepte une fonction de rappel, la signature synchrone n'inclut pas de rappel. Voir libgetdns (3) pour une discussion plus détaillée des fonctions de rappel.

response Un type getdns_dict est retourné en réponse et contient toujours au moins trois noms : replies_full (une liste contenant la réponse DNS sous forme de données binaires), replies_tree (une liste contenant les données analysées de la réponse DNS) et status (un entier). Le stockage associé à cela doit être libéré par un appel à getdns_free_sync_request_memory (3).

VALEURS DE RETOUR

En cas de succès, les fonctions retournent GETDNS_RETURN_GOOD , sinon les valeurs d'erreur suivantes sont retournées :

GETDNS_RETURN_BAD_CONTEXT si le pointeur de contexte est invalide ou si le contexte présente des déficiences internes

GETDNS_RETURN_BAD_DOMAIN_NAME si le nom de domaine passé à la fonction est invalide

GETDNS_RETURN_EXTENSION_MISFORMAT si le type de données spécifié dans une ou plusieurs extensions ne correspond pas aux spécifications

GETDNS_RETURN_GENERIC_ERROR si un problème a été rencontré dans la fonction et qu'il n'est pas couvert par l'un des codes de retour plus spécifiques

GETDNS_RETURN_INVALID PARAMETER si un ou plusieurs paramètres ont une valeur invalide

GETDNS_RETURN_MEMORY_ERROR si la mémoire requise n'a pas pu être allouée

GETDNS_RETURN_NO_SUCH_EXTENSION si une ou plusieurs des chaînes spécifiées dans les extensions ne sont pas valides

Les valeurs de status incluses dans le paramètre response sont :

GETDNS_RESPSTATUS_GOOD si au moins une réponse a été retournée

GETDNS_RESPSTATUS_NO_NAME si les requêtes pour le nom ont produit des réponses négatives

GETDNS_RESPSTATUS_ALL_TIMEOUT si toutes les requêtes pour le nom ont expiré

GETDNS_RESPSTATUS_NO_SECURE_ANSWERS si seules les réponses sécurisées ont été acceptées (par contexte) et qu'au moins une réponse a été reçue, mais aucune réponse DNS n'était sécurisée via DNSSEC

Pour une explication plus détaillée de l'objet réponse, voir libgetdns (3)
