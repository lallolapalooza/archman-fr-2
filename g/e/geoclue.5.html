DESCRIPTIO

N

Le fichier de configuration principal de GeoClue « geoclue.conf » spécifie les paramètres qui contrôlent le fonctionnement de geoclue. Les paramètres peuvent être réécrits en plaçant des fichiers de configuration dans le répertoire conf.d et sont appliqués dans l'ordre alphabétique. Ainsi, un fichier de configuration « 90-config.conf » réécrira les paramètres spécifiés dans un autre fichier de configuration « 50-config.conf » dans le répertoire conf.

d.

Tous les paramètres de configuration ci-dessous sont obligatoires et les valeurs par défaut sont celles que vous voyez avant de les modifier dans geoclue.conf. Si vous souhaitez conserver les valeurs par défaut, copiez et commentez la ou les lignes appropriées avant de les

modifier.

L'absence de la clé « enable » pour une source particulière dans le fichier de configurat

ion principal entraîne l'activation de cette source par défaut. L'ajout d'une clé « enable
» dans tout fichier de configuration supplémentaire peut réécrire cette valeur par défaut.

OPTIONS DE CONFIGURATION DES SOURCES DE

LOCALISATION
[i
p]

Options de configuration de la source
IP
enable=true
Activer la source GeoIP
method=ichnaea
Méthode (backend) à utiliser pour la localisation par IP. Les méthodes actuellement implémentées sont :
« ichnaea » : Utiliser l'API Ichnaea avec l'URL de la source wifi.
« gmaps » : Utiliser la localisation déterminée par Google Maps. « reallyfreegeoip » : reallyfreegeoip.org. Cette API ne renvoie pas la précision, nous utilisons donc une valeur constante. Voir l'option accuracy ci-dessous.
Les options suivantes n'ont pas besoin d'être définies, mais peuvent être fournies si vous souhaitez remplacer les valeurs par défaut de la méthode :
url=https://example.com/v1/geolocate
URL alternative du service GeoIP implémenté par la méthode sélectionnée.
accuracy=30000.0
Remplacer la précision reçue du serveur GeoIP (ou codée en dur dans la méthode) par cette valeur.
[network-nme
a]

Options de configuration de la source NMEA
réseau
enable=true
Récupérer la localisation à partir des sources NMEA sur le réseau local ?
(Les sources sont automatiquement découvertes à l'aide d'avahi, domaine « _nmea-0183._tcp ».)
nmea-socket=/var/run/gps-share.sock
Utiliser un socket unix nmea comme source de données. S'il n'est pas défini, le socket unix ne sera pas utilisé.
[3
g]

Options de configuration de la source
3G
enable=true
Activer la source 3G. La source 3G utilise l'URL du service de géolocalisation sans fil définie dans la section « wifi ».
[cdm
a]

Options de configuration de la source
CDMA
enable=true
Activer la source CDMA
[modem-gp
s]

Options de configuration de la source GPS
modem
enable=true
Activer la source Modem-GPS
[wif
i]

Options de configuration de la source
WiFi
enable=true
Activer la source
WiFi
url=https://example.com/v1/geolocate?key=YOUR_KEY
URL du service de géolocalisation sans fil compatible avec l'API Ichnaea (https://ichnaea.readthedocs.io/en/latest/api/geolocate.html). Si elle n'est pas définie, la valeur par défaut est une URL définie dans la configuration de compilation. Si aucune URL n'est définie ici ou dans la configuration de compilation, les sources wifi et 3g seront désactivées. Une clé d'API peut être définie avec le paramètre d'URL «
key ».
submit-data=false
Soumettre les données à un service de géolocalisation sans fil.
Si défini à true, geoclue soumettra automatiquement les données réseau à un service de géolocalisation sans fil à chaque fois qu'il obtient un verrouillage GPS. Actuellement, seules les sources Modem-GPS ou NMEA réseau sont prises en charge en tant que fournisseurs d'une localisation à soumettre (une à la fois). Si la source Modem-GPS est activée ci-dessus, elle sera le fournisseur exclusif (que le système soit effectivement équipé de ce modem ou non), sinon la source NMEA réseau sera prise en
compte.
submission-url=https://example.com/v2/geosubmit?key=YOUR_KEY
URL pour soumettre des données à un service de géolocalisation sans fil avec une API compatible Ichnaea (https://ichnaea.readthedocs.io/en/latest/api/geosubmit2.html)
.
submission-nick=geoclue
Un pseudonyme avec lequel soumettre les données réseau. Définit un en-tête HTTP « X-Nickname » pour la requête de soumission. Si défini à une chaîne vide, il est omis de la soumission. Sinon, il doit comporter de 2 à 32 caractères. La valeur par défaut est « geoclue ».

s]

Options de configuration de la
boussole
enable=true
Activer la boussole
[static-sour
ce]

Options de configuration de la source statique.
Cette source lit la localisation à partir du fichier « geolocation » dans /etc. Voir « FICHIER DE LOCALISATION STATIQUE » ci-dessous pour le format de ce fichier. Bien que ce fichier soit constamment surveillé pour les changements pendant le fonctionnement de geoclue, et que la localisation statique signalée soit mise à jour en conséquence, cette source n'est pas destinée à fournir à geoclue une localisation changeant dynamiquement (veuillez utiliser la source NMEA réseau pour
cela).
enable=true
Activer la source statique.
Si vous utilisez cette source, vous devriez probablement désactiver les autres sources de localisation dans geoclue.conf afin qu'elles ne remplacent pas la localisation statique configurée.

OPTIONS DE CONFIGURATION DES

APPLICATIONS

Avoir une entrée ici pour une application avec allowed=true signifie que geoclue ne demandera pas à l'agent d'autoriser l'application. Cela permet de s'assurer que les applications dotées d'un mécanisme d'autorisation intégré (par ex. les navigateurs web) n'ont pas besoin d'être liées à des

agents.

Si votre application se voit refuser l'accès aux informations de localisation et que votre système d'exploitation ne fournit aucun mécanisme pour changer cela, il s'agit probablement d'un bogue dans votre système d'exploitation (ou dans geoclue). La solution est de signaler le problème avec tous les détails, plutôt que d'ajouter votre application à cette

liste.
Format
:
[random-app]
Identifiant de bureau de l'application sans la partie .desktop

allowed=true|false
Accès autorisé aux informations de localisation

?

system=true|false
L'application est-elle un composant système

?

users=
Liste des UID de tous les utilisateurs pour lesquels cette application

est autorisée à accéder aux informations de localisation, séparés
par « ; ». Laissez-le vide pour l'autoriser pour tous les utilisateurs.
Exemples
:
[gnome-datetime-panel]
allowed=true
system=true
users=

[gnome-color-panel]
allowed=true
system=true
users

=

[org.gnome.Shell]
allowed=true
system=true
users

=

[io.elementary.desktop.agent-geoclue2]
allowed=true
system=true
users=/p>

[epiphany]
allowed=true
system=false
users

=

[firefox]
allowed=true
system=false
users=

FICHIER DE LOCALISATION

STATIQUE

Format de base

:

Le fichier de localisation statique dans /etc (utilisé par la source statique) est un fichier texte composé de ce qui suit

:
1
Latitude (nombre à virgule flottante ; les valeurs positives signifient nord, les négatives
sud)
2
Longitude (nombre à virgule flottante ; les valeurs positives signifient est, les négatives
ouest)
3
Altitude (nombre à virgule flottante ; en
mètres)
4
Rayon de précision (
nombre à virgule fl
ottante ; en mètres)

Ces valeurs doivent être

séparées par des carac
tères de nouvelle ligne.

Informations de format supplémentaires

:
•
Le caractère '#' commence un commentaire, qui se poursuit jusqu'à la fin de la ligne en
cours.
•
Les espaces en début et fin de chaque ligne sont
ignorés.
•
Les lignes vides (ou co
ntenant uniquement des
espaces ou un commenta
ire) sont ignorées.

Exemple

: 
# Fichier de localisation statique exemple pour une machine à l'intérieur de la torche d
e la Statue de la Liberté 40.6893129 # latitude -74.0445531 # longitude 96
# altitude 1.83 # rayon de précision (le diamètre de la torche est de 12 pieds)

Notes

:

Pour plus de sécurité, le fichier de localisation statique peut être rendu lisible uniquement par l'utilisateur geoclue

: 
# chown geoclue
/etc/geolocati
on # chmod 600 /
etc/geolocation
