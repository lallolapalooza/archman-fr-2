DESCRIPTION

Les appels aux fonctions getdns nécessitent un contexte DNS, qui est un groupe de paramètres de l'API qui affectent la manière dont les appels DNS sont effectués. Pour la plupart des applications, un contexte par défaut est suffisant.

Pour créer un nouveau contexte DNS, utilisez la fonction :


getdns_return_t getdns_context_create (getdns_context_t *context, bool set_from_os)

L'appel à getdns_context_create renvoie immédiatement un contexte qui peut être utilisé avec d'autres appels d'API ; ce contexte contient les valeurs par défaut de l'API. La plupart des applications voudront que set_from_os soit défini sur vrai.

Pour nettoyer le contexte, y compris le nettoyage de toutes les transactions en cours qui ont été appelées en utilisant ce contexte, utilisez la fonction :


void getdns_context_destroy (getdns_context_t context)

Lorsque getdns_context_destroy() renvoie, l'application sait que toutes les transactions en cours associées à ce contexte auront été appelées ; les rappels qui n'avaient pas été appelés avant que getdns_context_destroy() ne soit appelé seront appelés avec un type de rappel GETDNS_CALLBACK_CANCEL. getdns_context_destroy() renvoie après que tout le nettoyage nécessaire soit terminé et que les rappels soient effectués.

Si vous utilisez getdns dans un environnement multithread, vous utilisez donc bien sûr la bibliothèque OpenSSL sous-jacente en mode multithread et la version de cette bibliothèque en cours d'utilisation pourrait avoir des exigences à ce sujet. Vous pourriez avoir besoin de fournir une ou deux fonctions pour lui permettre de fonctionner correctement. Par exemple, avant d'appeler getdns_context_create(), vous pourriez avoir besoin d'utiliser les fonctions OpenSSL CRYPTO_set_id_callback et CRYPTO_set_locking_callback pour configurer le fonctionnement asynchrone (l'application appelle ces fonctions une fois pour l'initialisation). OpenSSL 1.0.0 ou une version ultérieure utilise la fonction CRYPTO_THREADID_set_callback.

context Utilisé pour renvoyer le pointeur vers une structure opaque. L'appelant transmet l'adresse d'un pointeur (décl: getdns_context *context ; passé comme &context) qui sera rempli suite au retour de la fonction. Le résultat est un contexte nouvellement alloué et initialisé (en l'absence d'erreurs). Dans la fonction getdns_destroy_context, il s'agit du contexte dont la mémoire associée sera libérée.

set_from_os Si set_from_os est 0, l'appelant doit fournir des serveurs de noms de transfert s'il fonctionne en mode stub. Si set_from_os est 1, les fichiers système sont utilisés pour initialiser le contexte. /etc/resolv.conf est utilisé pour remplir les forwarders lors de l'exécution en tant que résolveur stub (seules les lignes "nameserver" sont reconnues). Si set_from_os est 1, les entrées /etc/hosts sont privilégiées avant de recourir à une requête DNS. Les erreurs dans les fichiers système n'empêcheront pas la construction du contexte.

userarg Dans le cas d'utilisation étendue, cet argument est transmis tel quel à chacune des fonctions de gestion de la mémoire à chaque fois qu'elles sont appelées.

malloc La fonction qui sera utilisée pour créer les dictionnaires de réponse (et les membres au sein des dictionnaires de réponse). Par défaut, le malloc système est utilisé.

realloc La fonction qui sera utilisée pour créer les dictionnaires de réponse (et les membres au sein des dictionnaires de réponse). Par défaut, le realloc système est utilisé.

free La fonction qui sera utilisée pour libérer le stockage des dictionnaires de réponse (et les membres au sein des dictionnaires de réponse). Par défaut, le free système est utilisé.

DESCRIPTION (LONGUE)

De nombreux appels dans l'API DNS nécessitent un contexte DNS. Un contexte DNS contient les informations dont l'API a besoin pour traiter les appels DNS, tels que les emplacements des serveurs DNS en amont, les ancres de confiance DNSSEC, et ainsi de suite. La structure interne du contexte DNS est opaque et peut être différente selon les systèmes d'exploitation. Lorsqu'un contexte est passé à une fonction, il doit s'agir d'un contexte alloué ; le contexte ne doit pas être NULL.

Une application typique utilisant cette API n'a pas besoin de savoir quoi que ce soit sur les contextes. Fondamentalement, l'application crée un contexte par défaut, l'utilise dans les fonctions qui nécessitent un contexte, puis la désalloue une fois terminée. La manipulation de contexte est disponible pour les programmes plus conscients du DNS, mais ne devrait pas intéresser les applications qui veulent simplement les résultats des recherches d'enregistrements A, AAAA, SRV et PTR.

Il est prévu que les contextes dans les implémentations de l'API ne soient pas nécessairement thread-safe, mais ils ne seront pas thread-hostile. Un contexte ne doit pas être utilisé par plusieurs threads : créez un nouveau contexte à utiliser sur un thread différent. Il est tout à fait normal qu'une application ait de nombreux contextes, et certaines applications lourdes en DNS voudront certainement en avoir plusieurs, même si l'application utilise un seul thread.

Lorsque le contexte est utilisé pour la première fois dans l'API et que set_from_os est 1, l'API commence à remplacer certaines valeurs par des valeurs provenant du système d'exploitation, telles que celles que l'on trouverait dans res_query(3), /etc/resolv.conf, etc., puis poursuit avec la nouvelle fonction. Certains utilisateurs avancés ne voudront pas que l'API modifie les valeurs par défaut du système d'exploitation ; si set_from_os est 0, l'API n'effectuera aucune mise à jour des valeurs initiales basée sur les changements du système d'exploitation. Par exemple, cela pourrait être utile si l'API agit comme un résolveur stub utilisant un résolveur récursif DNS spécifique choisi par l'application, et non celui qui pourrait provenir de DHCP.

VALEURS DE RETOUR

En cas de succès, chacune de ces fonctions renvoie GETDNS_RETURN_GOOD, sinon les valeurs d'erreur suivantes sont renvoyées :

GETDNS_RETURN_GENERIC_ERROR échec d'allocation de mémoire ou quelque chose d'autre d'imprévu s'est produit lors de l'initialisation du contexte

GETDNS_RETURN_BAD_CONTEXT si le pointeur de contexte est invalide (getdns_context_destroy)

Le dictionnaire getdns renvoyé par getdns_context_get_api_information doit être détruit par l'appelant et inclut les paires nom/valeur suivantes :

version_string
une valeur binaire contenant une chaîne imprimable de la version de l'API DNS implémentée par cette bibliothèque
implementation_string
une valeur binaire contenant une chaîne imprimable définie par l'implémentation
resolution_type
un entier égal à GETDNS_RESOLUTION_RECURSING ou GETDNS_RESOLUTION_STUB
all_context
un dictionnaire getdns avec les noms de tous les types de contexte, alimentez-le avec getdns_pretty_print_dict (3) pour obtenir quelque chose de facilement lisible
