GETGROUPS(3P) Manuel du programmeur POSIX GETGROUPS(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

getgroups — obtenir les identifiants de groupe supplémentaires

SYNTAXE

#include <unistd.h>
int getgroups(int gidsetsize, gid_t grouplist[]);

DESCRIPTION

La fonction getgroups() remplit le tableau grouplist avec les identifiants de groupe supplémentaires actuels du processus appelant. Il est défini par l'implémentation si getgroups() retourne également l'identifiant de groupe effectif dans le tableau grouplist.

L'argument gidsetsize spécifie le nombre d'éléments dans le tableau grouplist. Le nombre réel d'identifiants de groupe stockés dans le tableau sera retourné. Les valeurs des entrées du tableau dont les indices sont supérieurs ou égaux à la valeur retournée sont indéfinies.

Si gidsetsize est 0, getgroups() retournera le nombre d'identifiants de groupe qu'il retournerait autrement sans modifier le tableau pointé par grouplist.

Si l'identifiant de groupe effectif du processus est retourné avec les identifiants de groupe supplémentaires, la valeur retournée sera toujours supérieure ou égale à un et inférieure ou égale à la valeur de {NGROUPS_MAX}+1.

VALEUR DE RETOUR

En cas de succès, le nombre d'identifiants de groupe supplémentaires sera retourné. Une valeur de retour de -1 indique un échec et errno sera défini pour indiquer l'erreur.

ERREURS

La fonction getgroups() échouera si :

EINVAL
L'argument gidsetsize est non nul et inférieur au nombre d'identifiants de groupe qui auraient été retournés.

Les sections suivantes sont informatives.

EXEMPLES

Obtenir les identifiants de groupe supplémentaires du processus appelant

L'exemple suivant place les identifiants de groupe supplémentaires actuels du processus appelant dans le tableau group.

#include <sys/types.h>
#include <unistd.h>
...
gid_t *group;
int nogroups;
long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX) + 1;
group = (gid_t *)malloc(ngroups_max *sizeof(gid_t));
ngroups = getgroups(ngroups_max, group);

UTILISATION PAR L’APPLICATION

Aucun.

RATIONNEL

La fonction associée setgroups() est une opération privilégiée et n'est donc pas couverte par ce volume de POSIX.1‐2017.

Comme le suggère la définition des groupes supplémentaires, l'identifiant de groupe effectif peut apparaître dans le tableau retourné par getgroups() ou il peut être retourné uniquement par getegid(). Il peut y avoir des doublons, mais l'application doit appeler getegid() pour être sûre d'obtenir toutes les informations. Diverses variations d'implémentation et séquences administratives font que l'ensemble des groupes apparaissant dans le résultat de getgroups() varie en ordre et quant à l'inclusion de l'identifiant de groupe effectif, même lorsque l'ensemble des groupes est le même (au sens mathématique de « ensemble »). (L'historique d'un processus et de ses parents pourrait affecter les détails du résultat.)

Les développeurs d'applications doivent noter que {NGROUPS_MAX} n'est pas nécessairement une constante sur toutes les implémentations.
