gettimeofday(2) Manuel des appels système gettimeofday(2)

NOM

gettimeofday, settimeofday - obtenir/définir l'heure

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/time.h>
[[obsolète]]
int gettimeofday(struct timeval *restrict tv,
                 struct timezone *_Nullable restrict tz);
[[obsolète]]
int settimeofday(const struct timeval *tv,
                 const struct timezone *_Nullable tz);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

settimeofday() :

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et antérieures :
        _BSD_SOURCE

DESCRIPTION

Les fonctions gettimeofday() et settimeofday() peuvent obtenir et définir l'heure ainsi qu'un fuseau horaire.

L'argument tv est un struct timeval (tel que spécifié dans <sys/time.h>) :


struct timeval {
    time_t      tv_sec;     /* seconds */
    suseconds_t tv_usec;    /* microseconds */
};

et donne le nombre de secondes et de microsecondes depuis l'Epoch (voir time(2)).

L'argument tz est un struct timezone:


struct timezone {
    int tz_minuteswest;     /* minutes west of Greenwich */
    int tz_dsttime;         /* type of DST correction */
};

Si tv ou tz vaut NULL, la structure correspondante n'est ni définie ni retournée. (Cependant, cela entraînera des avertissements de compilation si tv vaut NULL.)

L'utilisation de la structure timezone est obsolète ; l'argument tz devrait normalement être spécifié comme NULL. Voir VERSIONS.

Sous Linux, il existe certaines sémantiques étranges de « warp clock » associées à l'appel système settimeofday() si, au tout premier appel (après le démarrage) ayant un argument tz non NULL, l'argument tv vaut NULL et le champ tz_minuteswest est non nul. (Le champ tz_dsttime devrait valoir zéro dans ce cas.) Dans un tel cas, on suppose que l'horloge CMOS est réglée sur l'heure locale et qu'elle doit être incrémentée de ce montant pour obtenir l'heure UTC du système. C'est sans doute une mauvaise idée d'utiliser cette fonctionnalité.

VALEUR RENVOYÉE

gettimeofday() et settimeofday() renvoient 0 en cas de succès. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
L'un des arguments tv ou tz pointait en dehors de l'espace d'adressage accessible.
EINVAL
(settimeofday()) : timezone est invalide.
EINVAL
(settimeofday()) : tv.tv_sec est négatif ou tv.tv_usec est en dehors de l'intervalle [0, 999999].
EINVAL (depuis Linux 4.3)
(settimeofday()) : Une tentative a été faite pour définir l'heure sur une valeur inférieure à la valeur actuelle de l'horloge CLOCK_MONOTONIC (voir clock_gettime(2)).
EPERM
Le processus appelant n'a pas les privilèges suffisants pour appeler settimeofday() ; sous Linux, la capacité CAP_SYS_TIME est requise.

VERSIONS

Différences bibliothèque C/noyau

Sur certaines architectures, une implémentation de gettimeofday() est fournie dans la vdso(7).

Le noyau accepte NULL pour tv et tz. L'argument timezone est ignoré par glibc et musl, et n'est pas transmis au/depuis le noyau. bionic d'Android transmet l'argument timezone au/depuis le noyau, mais Android ne met pas à jour le fuseau horaire du noyau en fonction du fuseau horaire de l'appareil dans Paramètres, de sorte que le fuseau horaire du noyau est généralement UTC.

NORMES

Aucune.

HISTORIQUE

SVr4, 4.3BSD. POSIX.1-2001 décrivait gettimeofday() mais pas settimeofday(). POSIX.1-2008 a marqué gettimeofday() comme obsolète, recommandant l'utilisation de clock_gettime(2) à la place. De même, clock_settime(2) devrait être utilisé à la place de settimeofday(). POSIX.1-2024 a supprimé gettimeofday().

Traditionnellement, les champs de struct timeval étaient de type long.

Le champ tz_dsttime

Sur un noyau non Linux, avec glibc, le champ tz_dsttime de struct timezone sera défini à une valeur non nulle par gettimeofday() si le fuseau horaire actuel a eu ou aura une règle d'heure d'été appliquée. En ce sens, il reflète exactement la signification de daylight(3) pour le fuseau actuel. Sur Linux, avec glibc, la définition du champ tz_dsttime de struct timezone n'a jamais été utilisée par settimeofday() ou gettimeofday(). Ainsi, ce qui suit est purement d'intérêt historique.

Sur les anciens systèmes, le champ tz_dsttime contient une constante symbolique (les valeurs sont données ci-dessous) qui indique dans quelle partie de l'année l'heure d'été est en vigueur. (Remarque : cette valeur est constante tout au long de l'année : elle n'indique pas que l'heure d'été est en vigueur, elle sélectionne simplement un algorithme.) Les algorithmes d'heure d'été définis sont les suivants :


DST_NONE     /* not on DST */
DST_USA      /* USA style DST */
DST_AUST     /* Australian style DST */
DST_WET      /* Western European DST */
DST_MET      /* Middle European DST */
DST_EET      /* Eastern European DST */
DST_CAN      /* Canada */
DST_GB       /* Great Britain and Eire */
DST_RUM      /* Romania */
DST_TUR      /* Turkey */
DST_AUSTALT  /* Australian style with shift in 1986 */

Il s'est avéré, bien sûr, que la période pendant laquelle l'heure d'été est en vigueur ne peut être donnée par un simple algorithme, un par pays ; en effet, cette période est déterminée par des décisions politiques imprévisibles. Cette méthode de représentation des fuseaux horaires a donc été abandonnée.

NOTES

L'heure renvoyée par gettimeofday() est affectée par des sauts discontinus de l'heure du système (par ex., si l'administrateur système modifie manuellement l'heure du système). Si vous avez besoin d'une horloge à incrément monotone, voir clock_gettime(2).

Les macros pour manipuler les structures timeval sont décrites dans timeradd(3).

VOIR AUSSI
