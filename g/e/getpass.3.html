getpass(3) Manuel des fonctions de bibliothèque getpass(3)

NOM

getpass - obtenir un mot de passe

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <unistd.h>
[[deprecated]] char *getpass(const char *prompt);
Exigences pour les macros de test de fonctionnalités sur glibc (voir feature_test_macros(7)) :

getpass() :

    Depuis glibc 2.2.2 :
        _XOPEN_SOURCE && ! (_POSIX_C_SOURCE >= 200112L)
            || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
            || /* glibc <= 2.19 : */ _BSD_SOURCE
    Avant glibc 2.2.2 :
        aucun

DESCRIPTION

Cette fonction est obsolète. Ne l'utilisez pas. Voir NOTES. Si vous souhaitez lire une entrée sans écho du terminal activé, voir la description du drapeau ECHO dans termios(3).

La fonction getpass() ouvre /dev/tty (le terminal de contrôle du processus), affiche la chaîne prompt, désactive l'écho, lit une ligne (le « mot de passe »), restaure l'état du terminal et ferme à nouveau /dev/tty.

VALEUR DE RETOUR

La fonction getpass() renvoie un pointeur vers un tampon statique contenant (les PASS_MAX premiers octets) le mot de passe sans le retour à la ligne final, terminé par un octet nul ('\0'). Ce tampon peut être écrasé par un appel ultérieur. En cas d'erreur, l'état du terminal est restauré, errno est défini pour indiquer l'erreur, et NULL est renvoyé.

ERREURS

ENXIO
Le processus n'a pas de terminal de contrôle.

FICHIERS

/dev/tty

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
getpass () Sécurité des threads MT-Unsafe term

NORMES

Aucune.

HISTORIQUE

Version 7 AT&T UNIX. Présent dans SUSv2, mais marqué LEGACY. Supprimé dans POSIX.1-2001.

NOTES

Vous devriez utiliser à la place readpassphrase(3bsd), fourni par libbsd.

Dans l'implémentation de la bibliothèque C GNU, si /dev/tty ne peut pas être ouvert, l'invite est écrite sur stderr et le mot de passe est lu depuis stdin. Il n'y a pas de limite à la longueur du mot de passe. L'édition de ligne n'est pas désactivée.

Selon SUSv2, la valeur de PASS_MAX doit être définie dans <limits.h> au cas où elle serait inférieure à 8, et peut dans tous les cas être obtenue en utilisant sysconf(_SC_PASS_MAX). Cependant, POSIX.2 retire les constantes PASS_MAX et _SC_PASS_MAX, ainsi que la fonction getpass(). La version glibc accepte _SC_PASS_MAX et renvoie BUFSIZ (par exemple, 8192).

BOGUES

Le processus appelant doit zéroter le mot de passe dès que possible pour éviter de laisser le mot de passe en clair visible dans l'espace d'adressage du processus.
