DESCRIPTIO

N

getgroups() renvoie les identifiants de groupes supplémentaires du processus appelant dans list. L'argument size doit être défini au nombre maximal d'éléments pouvant être stockés dans le tampon pointé par list. Si le processus appelant est membre de plus de size groupes supplémentaires, une erreur se

produit.

Il n'est pas spécifié si l'identifiant de groupe effectif du processus appelant est inclus dans la liste renvoyée. (Ainsi, une application doit également appeler getegid(2) et ajouter ou supprimer la valeur résultante.

)

Si size vaut zéro, list n'est pas modifié, mais le nombre total d'identifiants de groupes supplémentaires du processus est renvoyé. Cela permet à l'appelant de déterminer la taille d'une list allouée dynamiquement à utiliser dans un appel ultérieur à getgroup

s().

setgroups() définit les identifiants de groupes supplémentaires pour le processus appelant. Des privilèges appropriés sont requis (voir la description de l'erreur EPERM, ci-dessous). L'argument size spécifie le nombre d'identifiants de groupes supplémentaires dans le tampon pointé par list. Un processus peut abandonner tous ses groupes supplémentaires avec l'appel

: 


setgroups(0, (gid_t [0]){}
)
;

Différences bibliothèque

C/noyau

Au niveau du noyau, les identifiants d'utilisateur et de groupe sont un attribut par thread. Cependant, POSIX exige que tous les threads d'un processus partagent les mêmes identifiants. L'implémentation des threads NPTL prend en charge les exigences POSIX en fournissant des fonctions d'encapsulation pour les différents appels système qui modifient les UID et GID du processus. Ces fonctions d'encapsulation (y compris celle pour setgroups()) emploient une technique basée sur les signaux pour garantir que lorsqu'un thread modifie ses identifiants, tous les autres threads du processus modifient également leurs identifiants. Pour plus de détails, voir npt

l(
7

L'appel système getgroups() original de Linux ne prenait en charge que des identifiants de groupe sur 16 bits. Par la suite, Linux 2.4 a ajouté getgroups32(), prenant en charge les identifiants sur 32 bits. La fonction d'encapsulation getgroups() de glibc gère de manière transpa

NOTE

S

Un processus peut avoir jusqu'à NGROUPS_MAX identifiants de groupes supplémentaires en plus de l'identifiant de groupe effectif. La constante NGROUPS_MAX est définie dans <limits.h>. L'ensemble des identifiants de groupes supplémentaires est hérité du processus parent et préservé à travers un execve(

2).

Le nombre maximal d'identifiants de groupes supplémentaires peut être trouvé à l'exécution en utilisant sysconf(3)

: 


long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX)
;

La valeur de retour maximale de getgroups() ne peut pas être supérieure à une unité plus que cette valeur. Depuis Linux 2.6.4, le nombre maximal d'identifiants de groupes supplémentaires est également exposé via le fichier en lecture seule spécifique à Linux, /proc/sys/kernel/ngroups_ma

x
.

#include <err.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
#define MALLOC(n, T)  ((T *) reallocarray(NULL, n, sizeof(T)))
static gid_t *agetgroups(size_t *ngids);
int
main(void)
{
    gid_t   *gids;
    size_t  n;
    gids = agetgroups(&n);
    if (gids == NULL)
        err(EXIT_FAILURE, "agetgroups");
    if (n != 0) {
        printf("%jd", (intmax_t) gids[0]);
        for (size_t i = 1; i < n; i++)
            printf(" %jd", (intmax_t) gids[i]);
    }
    puts("");
    free(gids);
    exit(EXIT_SUCCESS);
}
static gid_t *
agetgroups(size_t *ngids)
{
    int    n;
    gid_t  *gids;
    n = getgroups(0, NULL);
    if (n == -1)
        return NULL;
    gids = MALLOC(n, gid_t);
    if (gids == NULL)
        return NULL;
    n = getgroups(n, gids);
    if (n == -1) {
        free(gids);
        return NULL;
    }
    *ngids = n;
    return gids;
}
