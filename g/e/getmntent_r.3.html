getmntent(3) Manuel des fonctions de bibliothèque getmntent(3)

NOM

getmntent, setmntent, addmntent, endmntent, hasmntopt, getmntent_r - lire une entrée du fichier descripteur de systèmes de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <stdio.h>
#include <mntent.h>
FILE *setmntent(const char *path, const char *type);
struct mntent *getmntent(FILE *stream);
int addmntent(FILE *restrict stream,
              const struct mntent *restrict mnt);
int endmntent(FILE *streamp);
char *hasmntopt(const struct mntent *mnt, const char *opt);
/* Extension GNU */
#include <mntent.h>
struct mntent *getmntent_r(int size;
              FILE *restrict streamp,
              struct mntent *restrict mntbuf,
              char buf[restrict size], int size);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getmntent_r() :

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et antérieures :
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Ces routines sont utilisées pour accéder au fichier de description des systèmes de fichiers /etc/fstab et au fichier de description des systèmes de fichiers montés /etc/mtab.

La setmntent() fonction ouvre le fichier de description des systèmes de fichiers path et renvoie un pointeur de fichier qui peut être utilisé par getmntent(). L'argument type est le type d'accès requis et peut prendre les mêmes valeurs que l'argument mode de fopen(3). Le flux renvoyé doit être fermé en utilisant endmntent() plutôt que fclose(3).

La getmntent() fonction lit la ligne suivante du fichier de description des systèmes de fichiers à partir de stream et renvoie un pointeur vers une structure contenant les champs extraits d'une ligne du fichier. Le pointeur pointe vers une zone statique de mémoire qui est écrasée par les appels suivants à getmntent().

La addmntent() fonction ajoute la mntent structure mnt à la fin du streamouvert.

La endmntent() fonction ferme le stream associé au fichier de description des systèmes de fichiers.

La hasmntopt() fonction parcourt le champ mnt_opts (voir ci-dessous) de la mntent structure mnt à la recherche d'une sous-chaîne correspondant à opt. Voir <mntent.h> et mount(8) pour les options de montage valides.

La fonction réentrant getmntent_r() est similaire à getmntent(), mais stocke la mntent structure dans le *mntbuffourni, et stocke les chaînes pointées par les entrées de cette structure dans le tableau fourni buf de taille size.

La mntent structure est définie dans <mntent.h> comme suit :


struct mntent {
    char *mnt_fsname;   /* nom du système de fichiers monté */
    char *mnt_dir;      /* préfixe de chemin du système de fichiers */
    char *mnt_type;     /* type de montage (voir mntent.h) */
    char *mnt_opts;     /* options de montage (voir mntent.h) */
    int   mnt_freq;     /* fréquence de sauvegarde en jours */
    int   mnt_passno;   /* numéro de passage sur fsck parallèle */
};

Puisque les champs des fichiers mtab et fstab sont séparés par des espaces, des échappements octaux sont utilisés pour représenter les caractères espace (\040), tabulation (\011), nouvelle ligne (\012) et antislash (\\) dans ces fichiers lorsqu'ils apparaissent dans l'une des quatre chaînes d'une mntent structure. Les routines addmntent() et getmntent() convertiront de la représentation en chaîne vers la représentation échappée et inversement. Lors de la conversion depuis la représentation échappée, la séquence \134 est également convertie en un antislash.

VALEUR RENVOYÉE

Les getmntent() et getmntent_r() fonctions renvoient un pointeur vers la mntent structure ou NULL en cas d'échec.

La addmntent() fonction renvoie 0 en cas de succès et 1 en cas d'échec.

La endmntent() fonction renvoie toujours 1.

La hasmntopt() fonction renvoie l'adresse de la sous-chaîne si une correspondance est trouvée et NULL sinon.

FICHIERS

/etc/fstab
fichier de description des systèmes de fichiers
/etc/mtab
fichier de description des systèmes de fichiers montés

ATTRIBUTS

NORMES

Aucune.

HISTORIQUE

Les fonctions non réentrantes proviennent de SunOS 4.1.3. Une routine getmntent_r() a été introduite dans HP-UX 10, mais elle renvoie un int. Le prototype montré ci-dessus est exclusif à glibc.

System V a également une getmntent() fonction mais la séquence d'appel diffère, et la structure renvoyée est différente. Sous System V /etc/mnttab est utilisé. 4.4BSD et Digital UNIX ont une routine getmntinfo(), un enveloppement autour de l'appel système getfsstat().
