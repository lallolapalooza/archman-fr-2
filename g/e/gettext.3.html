GETTEXT(3) Manuel des fonctions de bibliothèque GETTEXT(3)

NOM

gettext, dgettext, dcgettext — traduire un message

SYNTAXE

#include <libintl.h>

char * gettext (const char * msgid);
char * dgettext (const char * domainname, const char * msgid);
char * dcgettext (const char * domainname, const char * msgid,
                  int category);

DESCRIPTION

Les fonctions gettext, dgettext et dcgettext tentent de traduire une chaîne de caractères dans la langue maternelle de l'utilisateur, en recherchant la traduction dans un catalogue de messages.

L'argument msgid identifie le message à traduire. Par convention, il s'agit de la version anglaise du message, avec les caractères non-ASCII remplacés par des approximations ASCII. Ce choix permet aux traducteurs de travailler avec des catalogues de messages, appelés fichiers PO, qui contiennent à la fois les versions anglaise et traduite de chaque message, et peuvent être installés à l'aide de l'utilitaire msgfmt.

Un domaine de messages est un ensemble de messages msgid traduisibles. Généralement, chaque paquet logiciel a son propre domaine de messages. Le nom du domaine est utilisé pour déterminer le catalogue de messages dans lequel la traduction est recherchée ; il doit s'agir d'une chaîne non vide. Pour la fonction gettext, il est spécifié par un appel précédent à textdomain. Pour les fonctions dgettext et dcgettext, il est passé comme argument domainname ; si cet argument est NULL, le nom de domaine spécifié par un appel précédent à textdomain est utilisé à la place.

La recherche de traduction s'opère dans le contexte de la locale actuelle. Pour les fonctions gettext et dgettext, la facette de locale LC_MESSAGES est utilisée. Elle est déterminée par un appel précédent à la fonction setlocale. setlocale (LC_ALL, "") initialise la locale LC_MESSAGES en fonction de la première valeur non vide des trois variables d'environnement LC_ALL, LC_MESSAGES, LANG ; voir setlocale(3). Pour la fonction dcgettext, la facette de locale est déterminée par l'argument category, qui doit être l'une des constantes LC_xxx définies dans l'en-tête <locale.h>, à l'exclusion de LC_ALL. Dans les deux cas, les fonctions utilisent également la facette de locale LC_CTYPE afin de convertir le message traduit du jeu de codes du traducteur vers le jeu de codes de la locale actuelle, sauf si cela est remplacé par un appel antérieur à la fonction bind_textdomain_codeset.

Le catalogue de messages utilisé par les fonctions se trouve au chemin d'accès dirname/locale/category/domainname.mo. Ici dirname est le répertoire spécifié via bindtextdomain. Sa valeur par défaut dépend du système et de la configuration ; typiquement, c'est prefix/share/locale, où prefix est le préfixe d'installation du paquet. locale est le nom de la facette de locale actuelle ; l'implémentation GNU essaie également des généralisations, comme le nom de la langue sans le nom du territoire. category est LC_MESSAGES pour les fonctions gettext et dgettext, ou l'argument passé à la fonction dcgettext.

Si la variable d'environnement LANGUAGE est définie sur une valeur non vide, et que la locale n'est pas la locale « C », la valeur de LANGUAGE est supposée contenir une liste de noms de locales séparés par des deux-points. Les fonctions tenteront de rechercher une traduction de msgid dans chaque locale successivement. Il s'agit d'une extension GNU.

Dans la locale « C », ou si aucun des catalogues utilisés ne contient de traduction pour msgid, les fonctions gettext, dgettext et dcgettext retournent msgid.

VALEUR DE RETOUR

Si une traduction a été trouvée dans l'un des catalogues spécifiés, elle est convertie dans le jeu de codes de la locale et retournée. La chaîne résultante est allouée statiquement et ne doit pas être modifiée ni libérée. Sinon, msgid est retourné.

ERREURS

errno n'est pas modifié.

BOGUES

Le type de retour devrait être const char *, mais est char * pour éviter les avertissements dans le code C antérieur à ANSI C.

Lorsqu'une chaîne vide est utilisée pour msgid, les fonctions peuvent retourner une chaîne non vide.
