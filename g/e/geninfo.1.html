--build-directory répertoire_de_build

Rechercher les fichiers de données . gcno dans répertoire_de_build plutôt que de les trouver uniquement à côté du fichier .o et/ou .gcda

correspondant. Par défaut, geninfo s'attend à trouver les fichiers .gcno et .gcda (compile- et temps d'exécution, respectivement) dans le même répertoire.

Lorsque cette option est utilisée :

geninfo chemin1 --build-directory chemin2 ...

alors geninfo recherchera le fichier .gcno

chemin2/chemin/relatif/vers/da_base.gcno

lorsqu'il trouve le fichier .gcda

chemin1/chemin/relatif/vers/da_base.gcda.

Utilisez cette option lorsque vous avez utilisé la variable d'environnement GCOV_PREFIX pour indiquer à l'environnement d'exécution gcc ou llvm d'écrire les fichiers de données de couverture ailleurs que dans le répertoire où le code a été initialement compilé. Voir gcc(1) et/ou rechercher GCOV_PREFIX et GCOV_PREFIX_STRIP.

Cette option peut être utilisée plusieurs fois pour spécifier plusieurs répertoires alternatifs où rechercher les fichiers .gcno. Cela peut être utile si votre application utilise du code compilé dans de nombreux emplacements distincts - par exemple, des bibliothèques communes partagées entre les équipes.

--source-directory dirname
Ajoute 'dirname' à la liste des emplacements où rechercher les fichiers source.

Pour les chemins de fichiers source relatifs trouvés dans les données gcov - éventuellement après application de substitutions, geninfo recherchera d'abord le chemin à partir de 'cwd' (où genhtml a été invoqué), puis à partir de chaque nom de répertoire alternatif dans l'ordre spécifié. Le premier emplacement correspondant est utilisé.

Cette option peut être spécifiée plusieurs fois, pour ajouter d'autres répertoires au chemin de recherche des sources.

--branch-coverage

Collecte et conserve les données de couverture des branches.

Ceci est équivalent à utiliser l'option "--rc branch_coverage=1" ; l'option a été ajoutée pour mieux correspondre à l'interface genhml.

--mcdc-coverage

Collecte et conserve les données MC/DC.

Ceci est équivalent à utiliser l'option "--rc mcdc_coverage=1". La capture de la couverture MC/DC est prise en charge pour les versions de GCC 14.2 et supérieures, ou les versions de LLVM 18.1 et supérieures.
Voir llvm2lcov --help pour plus de détails sur la capture de données MC/DC dans LLVM.

Voir la section MC/DC du manuel genhtml(1) pour plus de détails.

--checksum
--no-checksum

Spécifie s'il faut générer des données de somme de contrôle lors de l'écriture des fichiers trace.

Utilisez --checksum pour activer la génération de somme de contrôle ou --no-checksum pour la désactiver. La génération de somme de contrôle est désactivée par défaut.

Lorsque la génération de somme de contrôle est activée, une somme de contrôle sera générée pour chaque ligne de code source et stockée avec les données de couverture. Cette somme de contrôle sera utilisée pour empêcher les tentatives de combinaison de données de couverture provenant de différentes versions de code source.

Si vous ne travaillez pas avec différentes versions de code source, désactivez cette option pour accélérer le traitement des données de couverture et réduire la taille des fichiers trace.

Notez que cette option est quelque peu remplacée par l'option --version-script qui fait quelque chose de similaire, mais au niveau du 'fichier entier'.

--compat mode=valeur[,mode=valeur,...]

Définit le mode de compatibilité.

Utilisez --compat pour spécifier que geninfo doit activer un ou plusieurs modes de compatibilité lors de la capture des données de couverture. Vous pouvez fournir une liste de paires mode=valeur séparées par des virgules pour spécifier les valeurs de plusieurs modes.

Les valeurs valides sont :

on

Active le mode de compatibilité.
off
Désactive le mode de compatibilité.
auto
Applique la détection automatique pour déterminer si le mode de compatibilité est requis. Notez que la détection automatique n'est pas disponible pour tous les modes de compatibilité.

Si aucune valeur n'est spécifiée, 'on' est supposé comme valeur par défaut.

Les modes valides sont :

libtool

Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant le mécanisme libtool. Voir également --compat-libtool.

La valeur par défaut pour ce paramètre est 'on'.

hammer
Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant une version de GCC 3.3 contenant une modification (patch hammer) des versions ultérieures de GCC. Vous pouvez identifier une version modifiée de GCC 3.3 en vérifiant le répertoire de compilation de votre projet pour des fichiers se terminant par l'extension .bbg. Les versions non modifiées de GCC 3.3 nomment ces fichiers .bb.

La valeur par défaut pour ce paramètre est 'auto'.

split_crc
Activez ce mode si vous capturez des données de couverture pour un projet qui a été construit en utilisant une version de GCC 4.6 contenant une modification (sommes de contrôle de fonction divisées) des versions ultérieures de GCC. Les messages d'erreur typiques lors de l'exécution de geninfo sur des données de couverture produites par de telles versions de GCC sont « manque de mémoire » et « fin de fichier inattendue atteinte ».

La valeur par défaut pour ce paramètre est 'auto'.

--compat-libtool
--no-compat-libtool

Spécifie s'il faut activer le mode de compatibilité libtool.

Utilisez --compat-libtool pour activer le mode de compatibilité libtool ou --no-compat-libtool pour le désactiver. Le mode de compatibilité libtool est activé par défaut.

Lorsque le mode de compatibilité libtool est activé, geninfo supposera que le code source relatif à un fichier .gcda situé dans un répertoire nommé ".libs" peut être trouvé dans son répertoire parent.

Si vous avez des répertoires nommés ".libs" dans votre environnement de compilation mais que vous n'utilisez pas libtool, désactivez cette option pour éviter des problèmes lors de la capture des données de couverture.

--config-file fichier-config

Spécifie un fichier de configuration à utiliser. Voir le manuel lcovrc(5) pour les détails du format du fichier et des options. Voir également l'entrée config_file dans le même manuel pour les détails sur la manière d'inclure un fichier de configuration dans un autre.

Lorsque cette option est spécifiée, ni le fichier de configuration système /etc/lcovrc, ni le fichier de configuration utilisateur ~/.lcovrc ne sont lus.

Cette option peut être utile lorsqu'il est nécessaire d'exécuter plusieurs instances de geninfo avec différentes options de fichier de configuration en parallèle.

Notez que cette option doit être spécifiée en entier - les abréviations ne sont pas prises en charge.

--profile [ fichier-données-profil ]

Indique à l'outil de suivre les performances et d'autres données de configuration. Si le fichier-données-profil optionnel n'est pas spécifié, alors les données de profil sont écrites dans un fichier nommé avec le même nom de base que le --output-filename, avec le suffixe .json ajouté.

--derive-func-data

Calcule les données de couverture de fonction à partir des données de couverture de ligne.

Utilisez cette option pour collecter des données de couverture de fonction, même si la version de l'outil gcov installée sur le système de test ne fournit pas ces données. lcov en dérivera plutôt des données de couverture de fonction à partir des données de couverture de ligne et des informations sur les lignes appartenant à une fonction.

--external
--no-external

Spécifie s'il faut capturer les données de couverture pour les fichiers source externes.

Les fichiers source externes sont des fichiers qui ne sont pas situés dans l'un des répertoires spécifiés par --directory ou --base-directory. Utilisez --external pour inclure les points de couverture dans les fichiers source externes lors de la capture des données de couverture ou --no-external pour les exclure. Si votre chemin --directory ou --base-directory contient un lien symbolique, alors le répertoire cible réel n'est pas considéré comme « interne » à moins que l'option --follow ne soit utilisée.

L'option --no-external est un peu un instrument brut ; les options --exclude et --include offrent un contrôle plus précis sur les données de couverture qui sont incluses ou non si la structure de votre projet est complexe et/ou si --no-external ne fait pas ce que vous voulez.

Les données pour les fichiers source externes sont incluses par défaut.

-f
--follow

Suivre les liens lors de la recherche des fichiers .gcda, ainsi que pour déterminer si un répertoire source (lié symboliquement) est « interne » au projet ou non - voir l'option --no-external, ci-dessus, pour plus d'informations. L'option de ligne de commande --follow est équivalente à l'option de fichier de configuration geninfo_follow_symlinks. Voir le manuel lcovrc(5) pour plus d'informations.

--sort-input

Spécifie s'il faut trier les noms de fichiers avant la capture et/ou l'agrégation. Le tri réduit certains types de différences de sortie dépendantes de l'ordre de traitement. Voir la section sort_input du manuel lcovrc(5).

--gcov-tool outil

Spécifie l'emplacement de l'outil gcov.

Si l'option --gcov-tool est utilisée plusieurs fois, alors les arguments sont concaténés lors de l'exécution du rappel - similaire au fonctionnement du paramètre -Xlinker de gcc. Cela offre une manière potentiellement plus facile de passer des arguments à votre outil, sans nécessiter de script wrapper. Dans ce cas, votre rappel sera exécuté comme : outil-0 'outil-1; ... 'nom_fichier'. Notez que le deuxième argument et les suivants sont mis entre guillemets lors du passage au shell, afin de gérer les paramètres qui contiennent des espaces.

L'argument --gcov-tool peut être une chaîne séparée par split_char - voir man(4) lcovrc.

Une utilisation courante de cette option est d'activer LLVM :

geninfo --gcov-tool llvm-cov --gcov-tool gcov ...
geninfo --gcov-tool llvm-cov,gcov ...

Note : 'llvm-cov gcov nom_fichier_da' générera une sortie au format compatible gcov comme requis par lcov.

Si non spécifié, 'gcov' est utilisé par défaut.

-h
--help

Affiche un court message d'aide, puis quitte.

--include modèle

Inclut les fichiers source correspondant au modèle.

Utilisez ce commutateur si vous souhaitez inclure les données de couverture uniquement pour un ensemble particulier de fichiers source correspondant à l'un des modèles donnés. Plusieurs modèles peuvent être spécifiés en utilisant plusieurs commutateurs de ligne de commande --include. Les modèles seront interprétés comme des modèles de caractères génériques de shell (notez qu'ils pourraient devoir être échappés en conséquence pour empêcher le shell de les développer d'abord).

Voir la page de manuel lcov pour les détails.

--exclude modèle

Exclut les fichiers source correspondant au modèle.

Utilisez ce commutateur si vous souhaitez exclure les données de couverture d'un ensemble particulier de fichiers source correspondant à l'un des modèles donnés. Plusieurs modèles peuvent être

spécifié à l'aide de plusieurs options de ligne de commande --exclude. Les modèles seront interprétés comme des modèles de caractères génériques de shell (notez qu'ils peuvent nécessiter une échappement appropriée pour empêcher le shell de les développer en premier). Remarque : Le modèle doit être spécifié pour correspondre au chemin d'accès absolu de chaque fichier source.

Peut être combiné avec l'option de ligne de commande --include. Si un fichier donné correspond à la fois au modèle d'inclusion et au modèle d'exclusion, le modèle d'exclusion a la priorité.

Voir la page de manuel lcov pour plus de détails.

--erase-functions regexp

Exclure les données de couverture des lignes qui tombent dans une fonction dont le nom correspond à l'expression régulière fournie. Notez qu'il s'agit d'un nom mélangé ou non mélangé, selon que l'option --demangle-cpp est utilisée ou non.

Notez que cette option nécessite que vous utilisiez une version de gcc suffisamment récente pour prendre en charge les rapports de début/fin de fonction ou que vous configuriez l'outil pour dériver les données requises - voir la discussion sur derive_function_end_line dans la page de manuel lcovrc.

--substitute regexp_pattern

Appliquer l'expression régulière Perl regexp_pattern aux noms de fichiers source trouvés pendant le traitement. Ceci est utile lorsque le nom de chemin signalé par gcov ne correspond pas à la disposition de votre source et que le fichier n'est pas trouvé. Voir la page de manuel lcov pour plus de détails.

--omit-lines regexp

Exclure les données de couverture des lignes dont le contenu correspond à regexp.

Utilisez ce commutateur si vous souhaitez exclure les données de couverture de ligne, de branche et MC/DC pour certaines constructions particulières de votre code (par exemple, une macro compliquée). Voir la page de manuel lcov pour plus de détails.

--forget-test-names

Si différent de zéro, ignorez les noms de cas de test dans le fichier trace - c'est-à-dire traitez toutes les données de couverture comme si elles provenaient du même cas de test. Cela peut améliorer les performances et réduire la consommation de mémoire si l'utilisateur n'a pas besoin d'un résumé de couverture par cas de test dans les rapports de couverture.

Cette option peut également être configurée de manière permanente à l'aide de l'option de fichier de configuration forget_testcase_names.

--msg-log [ nom_fichier_log ]

Spécifiez l'emplacement pour stocker les messages d'erreur et d'avertissement (en plus de l'écriture sur STDERR). Si nom_fichier_log n'est pas spécifié, l'emplacement par défaut est utilisé.

--ignore-errors erreurs

Spécifiez une liste d'erreurs après lesquelles continuer le traitement.

Utilisez cette option pour spécifier une liste d'une ou plusieurs classes d'erreurs après lesquelles geninfo doit continuer le traitement au lieu d'avorter. Notez que l'outil générera un avertissement (plutôt qu'une erreur fatale) sauf si vous ignorez l'erreur deux fois (ou plus) :

geninfo ... --ignore-errors unused,unused

erreurs peut être une liste séparée par des virgules des mots-clés suivants :

branch:
l'ID de branche (2ème champ dans l'entrée 'BRDA' du fichier .info) ne suit pas la séquence entière attendue.
callback:
Erreur de script de version.
child:
le processus enfant a renvoyé un code de sortie non nul lors de l'exécution --parallel. Cela indique généralement que l'enfant a rencontré une erreur : voir le fichier journal immédiatement avant ce message. En revanche : l'erreur parallel indique une exception inattendue/non gérée dans le processus enfant - pas une erreur 'typique' de lcov.
corrupt:
fichier corrompu/illisible trouvé.
count:
Un nombre excessif de messages d'une certaine classe ont été signalés - les messages ultérieurs de ce type seront supprimés. La limite peut être contrôlée par la variable 'max_message_count'. Voir la page de manuel lcovrc.
deprecated:
Vous utilisez une option obsolète. Cette option sera supprimée dans une future version - vous devriez donc modifier vos scripts dès maintenant.
empty:
le fichier de données .info est vide (par exemple, parce que tout le code a été 'supprimé' ou exclu.
excessive:
vos données de couverture contiennent un nombre de 'hits' suspecté d'être trop élevé, ce qui est peu probable d'être correct - indiquant éventuellement un bug dans votre chaîne d'outils.

Voir la section excessive_count_threshold dans la page de manuel lcovrc(5) pour plus de détails.

fork:
Impossible de créer un processus enfant lors de l'exécution --parallel.
Si le message est ignoré ( --ignore-errors fork ), alors genhtml attendra une courte période puis réessayera l'exécution échouée.
Si vous rencontrez des erreurs continues, désactivez ou réduisez le parallélisme, définissez une limite de mémoire, ou trouvez un serveur plus grand pour exécuter la tâche.
format:
Syntaxe ou valeur inattendue trouvée dans le fichier .info - par exemple, un nombre négatif ou un numéro de ligne zéro rencontré.
gcov:
l'outil gcov est revenu avec un code de retour non nul.
graph:
le fichier graphique n'a pas pu être trouvé ou est corrompu.
inconsistent:
vos données de couverture sont incohérentes en interne : elles font deux ou plusieurs affirmations mutuellement exclusives. Par exemple, une expression est marquée comme étant à la fois une branche d'exception et non une branche d'exception. (Voir la page de manuel genhtml(1) pour plus de détails.
internal:
problème interne de l'outil détecté. Veuillez signaler ce bug ainsi qu'un cas de test.
mismatch:
Informations incorrectes trouvées dans les données de couverture et/ou le code source - par exemple, le code source contient des directives d'exclusion chevauchantes.
missing:
Le fichier n'existe pas ou n'est pas lisible.
negative:
nombre de 'hits' négatif trouvé.

Notez que les comptes négatifs peuvent être causés par un bug connu de GCC - voir


https://gcc.gnu.org/bugzilla/show_bug.cgi?id=68080

et essayez de compiler avec "-fprofile-update=atomic". Vous devrez recompiler, réexécuter vos tests et recapturer les données de couverture.

package:
un package Perl requis n'est pas installé sur votre système. Dans certains cas, il est possible d'ignorer ce message et de continuer - cependant, certaines fonctionnalités seront désactivées dans ce cas.
parallel:
divers types d'erreurs liées au parallélisme - c'est-à-dire qu'un processus enfant est mort en raison d'une erreur. Le message d'erreur correspondant apparaît dans le fichier journal juste avant l'erreur parallel.

Si vous rencontrez une erreur liée à l'exécution parallèle qui semble invalide, il peut être judicieux de supprimer l'indicateur --parallel et de réessayer. Si la suppression de l'indicateur conduit à un résultat différent, veuillez signaler le problème (avec un cas de test) afin que l'outil puisse être corrigé.

parent:
le processus parent s'est terminé alors que l'enfant était actif pendant l'exécution --parallel. Cela se produit lorsque le parent a rencontré une erreur fatale - par exemple, une erreur dans un autre enfant qui n'a pas été ignorée. Cet enfant ne peut pas continuer à travailler sans son parent - et va donc se terminer.
path:
certains chemins de fichiers n'ont pas pu être résolus - par exemple, le fichier .gcno correspondant à certains .gcda n'a pas été trouvé, voir l'option --build-directory pour plus d'informations.
range:
Les données de couverture font référence à un numéro de ligne supérieur au nombre de lignes dans le fichier source. Cela peut être causé par une incompatibilité de version ou par un problème dans les données gcov.
source:
le fichier source d'un jeu de données n'a pas pu être trouvé.

la fonctionnalité demandée n'est pas prise en charge pour cette configuration d'outil. Par exemple, les exclusions de plage de lignes de début/fin de fonction utilisent certaines fonctionnalités GCOV qui ne sont pas disponibles dans les anciennes versions de GCC.
unused:
le modèle d'inclusion/exclusion/effacement/omission/substitution n'a correspond à aucun nom de chemin de fichier.
usage:
utilisation non prise en charge détectée - par exemple, une combinaison d'options non prise en charge.
utility:
un outil appelé pendant le traitement a renvoyé un code d'erreur (par exemple, 'find' a rencontré un répertoire illisible).
