DESCRIPTIO

N

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications devraient utiliser getaddrinfo(3), getnameinfo(3) et gai_strerror(3) à la

place.

La fonction sethostent() spécifie que, si stayopen est vrai (1), un socket TCP connecté devrait être utilisé pour les requêtes vers le serveur de noms et que la connexion devrait rester ouverte pendant les requêtes successives. Sinon, les requêtes vers le serveur de noms utiliseront des datagrammes

UDP.

La fonction endhostent() met fin à l'utilisation d'une connexion TCP pour les requêtes vers le serveur de

noms.

La fonction gethostbyname() retourne une structure de type hostent pour l'hôte donné name. Ici, name est soit un nom d'hôte soit une adresse IPv4 en notation pointée standard (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent struct in_addr dans le champ h_addr_list[0] de la structure hostent retournée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias auquel pointe HOSTALIASES sera d'abord recherché pour name (voir hostname(7) pour le format du fichier). Le domaine courant et ses parents sont recherchés à moins que name ne se termine par un

point.

La fonction gethostbyaddr() retourne une structure de type hostent pour l'adresse d'hôte donnée addr de taille size et de type d'adresse type. Les types d'adresse valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument d'adresse d'hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple un struct in_addr * (probablement obtenu via un appel à inet_addr(3)) pour le type d'adresse AF_INET

.

La fonction (obsolète) herror() affiche le message d'erreur associé à la valeur courante de h_errno sur stderr

.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et retourne la chaîne de message

correspondante.

Les requêtes de nom de domaine effectuées par gethostbyname() et gethostbyaddr() reposent sur les sources configurées par le Name Service Switch (nsswitch.conf(5)) ou un serveur de noms local (named(8)). L'action par défaut est d'interroger les sources configurées par le Name Service Switch (nsswitch.conf(5)), et à défaut, un serveur de noms local (named(8))

.

VALEUR

RENVOYÉE

Les fonctions gethostbyname() et gethostbyaddr() retournent la structure hostent ou un pointeur nul si une erreur se produit. En cas d'erreur, la variable h_errno contient un numéro d'erreur. Lorsqu'elle n'est pas NULL, la valeur de retour

ERREURS

La variable h_errno peut prendre les valeurs suivantes :

HOST_NOT_FOUND
L'hôte spécifié est inconnu.
NO_DATA
Le nom demandé est valide mais n'a pas d'adresse IP. Un autre type de requête au serveur de noms pour ce domaine peut renvoyer une réponse. La constante NO_ADDRESS est un synonyme de NO_DATA.
NO_RECOVERY
Une erreur non récupérable du serveur de noms s'est produite.
TRY_AGAIN
Une erreur temporaire s'est produite sur un serveur de noms faisant autorité. Réessayez plus tard.

NOTES

Les fonctions gethostbyname() et gethostbyaddr() peuvent renvoyer des pointeurs vers des données statiques, qui peuvent être écrasées par des appels ultérieurs. La copie de la struct hostent ne suffit pas, car elle contient des pointeurs ; une copie profonde est requise.

Dans l'implémentation BSD d'origine, l'argument size de gethostbyname() était un int. La norme SUSv2 est boguée et déclare l'argument size de gethostbyaddr() comme étant de type size_t. (C'est faux, car il doit être de type int, et size_t ne l'est pas. POSIX.1-2001 en fait un socklen_t, ce qui est correct.) Voir aussi accept(2).

Le prototype BSD pour gethostbyaddr() utilise const char * pour le premier argument.

Extension System V/POSIX

POSIX exige l'appel gethostent(), qui doit renvoyer l'entrée suivante dans la base de données des hôtes. Lors de l'utilisation de DNS/BIND, cela n'a pas beaucoup de sens, mais cela peut être raisonnable si la base de données des hôtes est un fichier qui peut être lu ligne par ligne. Sur de nombreux systèmes, une routine de ce nom lit le fichier /etc/hosts. Elle peut n'être disponible que si la bibliothèque a été compilée sans prise en charge DNS. La version glibc ignorera les entrées ipv6. Cette fonction n'est pas réentrante, et glibc ajoute une version réentrante, gethostent_r().

Extensions GNU

glibc2 possède également gethostbyname2() qui fonctionne comme gethostbyname(), mais permet de spécifier la famille d'adresses à laquelle l'adresse doit appartenir.

glibc2 possède également des versions réentrantes : gethostent_r(), gethostbyaddr_r(), gethostbyname_r() et gethostbyname2_r(). L'appelant fournit une structure hostent ret qui sera remplie en cas de succès, et un tampon de travail temporaire buf de taille bufsize. Après l'appel, result pointera vers le résultat en cas de succès. En cas d'erreur ou si aucune entrée n'est trouvée, result sera NULL. Les fonctions renvoient 0 en cas de succès et un numéro d'erreur non nul en cas d'échec. En plus des erreurs renvoyées par les versions non réentrantes de ces fonctions, si buf est trop petit, les fonctions renverront ERANGE, et l'appel devrait être réessayé avec un tampon plus grand. La variable globale h_errno n'est pas modifiée, mais l'adresse d'une variable dans laquelle stocker les numéros d'erreur est passée dans h_errnop.

BOGUES

gethostbyname() ne reconnaît pas les composants d'une chaîne d'adresse IPv4 pointée qui sont exprimés en hexadécimal.
