getpeername(2) Manuel des appels système getpeername(2)

NOM

getpeername - obtenir le nom du socket distant connecté

BIBLIOTHEQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/socket.h>
int getpeername(int sockfd, struct sockaddr *restrict addr,
                socklen_t *restrict addrlen);

DESCRIPTION

getpeername() retourne l'adresse du pair connecté au socket sockfd, dans le tampon pointé par addr. L'argument addrlen doit être initialisé pour indiquer la quantité d'espace pointé par addr. Au retour, il contient la taille réelle du nom retourné (en octets). Le nom est tronqué si le tampon fourni est trop petit.

L'adresse retournée est tronquée si le tampon fourni est trop petit ; dans ce cas, addrlen contiendra une valeur supérieure à celle fournie à l'appel.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
L'argument sockfd n'est pas un descripteur de fichier valide.
EFAULT
L'argument addr pointe vers une zone mémoire qui n'appartient pas à l'espace d'adressage valide du processus.
EINVAL
addrlen est invalide (par exemple, est négatif).
ENOBUFS
Des ressources système insuffisantes étaient disponibles pour effectuer l'opération.
ENOTCONN
Le socket n'est pas connecté.
ENOTSOCK
Le descripteur de fichier sockfd ne fait pas référence à un socket.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD (est apparu pour la première fois dans 4.2BSD).

NOTES

Pour les sockets de flux, une fois qu'un connect(2) a été effectué, chaque socket peut appeler getpeername() pour obtenir l'adresse du socket distant. D'autre part, les sockets de datagramme sont sans connexion. Appeler connect(2) sur un socket de datagramme définit simplement l'adresse distante pour les datagrammes sortants envoyés avec write(2) ou recv(2). L'appelant de connect(2) peut utiliser getpeername() pour obtenir l'adresse distante qu'il a précédemment définie pour le socket. Cependant, le socket distant ignore cette information, et appeler getpeername() sur le socket distant ne retournera aucune information utile (à moins qu'un appel connect(2) n'ait également été exécuté sur le pair). Notez également que le destinataire d'un datagramme peut obtenir l'adresse de l'expéditeur lors de l'utilisation de recvfrom(2).

VOIR AUSSI

accept(2), bind(2), getsockname(2), ip(7), socket(7), unix(7)
