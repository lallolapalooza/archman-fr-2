DESCRIPTION

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications devraient utiliser getaddrinfo(3), getnameinfo(3) et gai_strerror(3) à la place.

La fonction sethostent() spécifie, si stayopen est vrai (1), qu'un socket TCP connecté doit être utilisé pour les requêtes du serveur de noms et que la connexion doit rester ouverte lors des requêtes successives. Sinon, les requêtes du serveur de noms utiliseront des datagrammes UDP.

La fonction endhostent() termine l'utilisation d'une connexion TCP pour les requêtes du serveur de noms.

La fonction gethostbyname() renvoie une structure de type hostent pour le nom d'hôte name donné. Ici, name est soit un nom d'hôte, soit une adresse IPv4 en notation pointée standard (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent en struct in_addr dans le champ h_addr_list[0] de la structure hostent renvoyée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias pointé par HOSTALIASES sera d'abord recherché pour name (voir hostname(7) pour le format du fichier). Le domaine actuel et ses parents sont recherchés à moins que name ne se termine par un point.

La fonction gethostbyaddr() renvoie une structure de type hostent pour l'adresse hôte donnée addr de taille size et de type d'adresse type. Les types d'adresse valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument adresse hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple un struct in_addr * (probablement obtenu via un appel à inet_addr(3)) pour le type d'adresse AF_INET.

La fonction (obsolète) herror() affiche le message d'erreur associé à la valeur actuelle de h_errno sur stderr.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et renvoie la chaîne de message correspondante.

Les requêtes de nom de domaine effectuées par gethostbyname() et gethostbyaddr() s'appuient sur les sources configurées du Name Service Switch (nsswitch.conf(5)) ou sur un serveur de noms local (named(8)). L'action par défaut est de requêter les sources configurées du Name Service Switch (nsswitch.conf(5)), à défaut, un serveur de noms local (named(8)).

Historique

Le fichier nsswitch.conf(5) est la manière moderne de contrôler l'ordre des recherches d'hôtes.

Dans glibc 2.4 et versions antérieures, le mot-clé order était utilisé pour contrôler l'ordre des recherches d'hôtes tel que défini dans /etc/host.conf (host.conf(5)).

La structure hostent est définie dans <netdb.h> comme suit :


struct hostent {
    char  *h_name;            /* nom officiel de l'hôte */
    char **h_aliases;         /* liste des alias */
    int    h_addrtype;        /* type d'adresse hôte */
    int    h_length;          /* taille de l'adresse */
    char **h_addr_list;       /* liste des adresses */
}
#define h_addr h_addr_list[0] /* pour la compatibilité ascendante */

Les membres de la structure hostent sont :

h_name
Le nom officiel de l'hôte.
h_aliases
Un tableau de noms alternatifs pour l'hôte, terminé par un pointeur nul.
h_addrtype
Le type d'adresse ; actuellement toujours AF_INET ou AF_INET6.
h_length
La taille de l'adresse en octets.
h_addr_list
Un tableau de pointeurs vers les adresses réseau de l'hôte (en ordre d'octets réseau), terminé par un pointeur nul.
h_addr
La première adresse dans h_addr_list pour la compatibilité ascendante.

VALEUR DE RETOUR

La fonction gethostbyname() renvoie un pointeur vers la structure hostent pour l'hôte demandé, ou un pointeur nul si une erreur se produit. Une description de l'erreur peut être trouvée dans la variable globale h_errno.

La fonction gethostbyaddr() renvoie un pointeur vers la structure hostent pour l'adresse hôte demandée, ou un pointeur nul si une erreur se produit. Une description de l'erreur peut être trouvée dans la variable globale h_errno.

La fonction gethostent() renvoie un pointeur vers la structure hostent pour l'entrée hôte suivante, ou un pointeur nul si la fin du fichier est atteinte ou si une erreur se produit. Les erreurs ne sont pas distinguables de la fin du fichier sans vérifier h_errno.

Les fonctions gethostbyname2_r(), gethostbyname_r(), gethostbyaddr_r() et gethostent_r() renvoient 0 en cas de succès, ou un numéro d'erreur différent de zéro si une erreur se produit. Les résultats sont placés dans la structure pointée par ret. Si result n'est pas NULL, il est mis à jour pour pointer vers la structure renvoyée dans ret, ou il est mis à NULL si aucune entrée n'a été trouvée. L'erreur correspondante est placée dans la variable pointée par h_errnop.

ERREURS

La variable globale h_errno peut contenir l'une des valeurs suivantes :

HOST_NOT_FOUND
Le nom d'hôte n'a pas pu être trouvé. Cela peut être dû à une faute de frappe ou à l'absence du nom d'hôte dans la base de données.
TRY_AGAIN
Serveur DNS temporairement non disponible ou une autre condition réseau temporaire. La requête peut réussir si elle est répétée.
NO_RECOVERY
Une erreur irrécupérable s'est produite. Cela peut être dû à une mauvaise configuration du serveur DNS ou du fichier host.
NO_DATA
Le nom d'hôte existe, mais il n'y a pas de type d'adresse demandé disponible. Par exemple, un nom d'hôte peut avoir une adresse IPv4 mais pas d'adresse IPv6. Le type d'adresse demandé est spécifié par le champ h_addrtype de la structure hostent renvoyée.

Les fonctions _r (réentrantes) renvoient un code d'erreur non nul correspondant à l'une des valeurs ci-dessus (ou à d'autres codes d'erreur spécifiques à l'implémentation).

CONFORMITÉ

Les fonctions gethostbyname(), gethostbyaddr(), sethostent(), gethostent() et endhostent() sont conformes à POSIX.1-2001, mais sont obsolètes. La norme POSIX recommande l'utilisation de getaddrinfo(3) et getnameinfo(3) à la place.

La fonction gethostbyname2() est une extension GNU.

La fonction herror() est obsolète et non conforme aux normes. Il est recommandé d'utiliser gai_strerror(3) à la place.

La fonction hstrerror() est obsolète et non conforme aux normes. Il est recommandé d'utiliser gai_strerror(3) à la place.

Les fonctions *_r (réentrantes) sont des extensions POSIX.1-2001.
