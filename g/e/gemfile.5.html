GEMSPE

C

Le fichier .gemspec https://guides.rubygems.org/specification-reference/ est l'endroit où vous fournissez les métadonnées de votre gem à Rubygems. Certaines attributs Gemspec requis incluent le nom, la description et la page d'accueil de votre gem. C'est aussi là que vous spécifiez les dépendances dont votre gem a besoin pour

fonctionner.

Si vous souhaitez utiliser Bundler pour aider à installer les dépendances d'un gem pendant son développement, utilisez la méthode gemspec pour récupérer les dépendances listées dans le fichier .gemsp

ec.

La méthode gemspec ajoute toutes les dépendances d'exécution comme exigences de gem dans le groupe par défaut. Elle ajoute aussi les dépendances de développement comme exigences de gem dans le groupe development. Enfin, elle ajoute une exigence de gem sur votre projet (path: '.'). En conjonction avec Bundler.setup, cela vous permet de requérir des fichiers du projet dans votre code de test comme si le projet était installé comme un gem ; vous n'avez pas besoin de manipuler manuellement le chemin de chargement ou de requérir des fichiers du projet via des chemins

relatifs.

La méthode gemspec supporte les options facultatives :path, :glob, :name, et :development_group, qui contrôlent où bundler cherche le .gemspec, le glob qu'il utilise pour chercher le gemspec (par défaut : {,*,*/*}.gemspec), quel .gemspec nommé il utilise (si plus d'un est présent), et dans quel groupe les dépendances de développement sont

incluses.

Quand une dépendance gemspec rencontre des conflits de version lors de la résolution, la version locale en développement sera toujours sélectionnée -- même s'il existe des versions distantes qui correspondent mieux aux autres exigences pour le gem gems

pe
