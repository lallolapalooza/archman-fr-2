DESCRIPTIO

N

Ces appels fournissent une prise en charge spécifique à l'architecture pour une implémentation du stockage local au thread. Pour l'instant, set_thread_area() est disponible sur m68k, MIPS, C-SKY et x86 (les variantes 32 bits et 64 bits) ; get_thread_area() est disponible sur m68k et

x86.

Sur m68k, MIPS et C-SKY, set_thread_area() permet de stocker un pointeur arbitraire (fourni dans l'argument tp sur m68k et dans l'argument addr sur MIPS et C-SKY) dans la structure de données du noyau associée au thread appelant ; ce pointeur peut ensuite être récupéré à l'aide de get_thread_area() (voir aussi NOTES pour des informations concernant l'obtention du pointeur de thread sur MIPS)

.

Sur x86, Linux consacre trois entrées de la table de descripteurs globale (GDT) au stockage local au thread. Pour plus d'informations sur la GDT, consultez le manuel du développeur de logiciels Intel ou le manuel de programmation de l'architecture

AMD.

Ces deux appels système prennent un argument qui est un pointeur vers une structure du type suivant

: 


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;

    unsigned int  lm:1;

get_thread_area() lit l'entrée de la GDT indiquée par u_info->entry_number et remplit le reste des champs dans u_info

.

set_thread_area() définit une entrée TLS dans la

GDT.

L'entrée du tableau TLS définie par set_thread_area() correspond à la valeur de u_info->entry_number passée par l'utilisateur. Si cette valeur est dans les limites, set_thread_area() écrit le descripteur TLS pointé par u_info dans le tableau TLS du

thread.

Lorsque set_thread_area() reçoit un entry_number de -1, il recherche une entrée TLS libre. Si set_thread_area() trouve une entrée TLS libre, la valeur de u_info->entry_number est définie au retour pour indiquer quelle entrée a été

modifiée.

Un user_desc est considéré comme « vide » si read_exec_only et seg_not_present sont définis à 1 et si tous les autres champs sont à 0. Si un descripteur « vide » est passé à set_thread_area(), l'entrée TLS correspondante sera effacée. Voir BUGS pour plus de

détails.

Depuis Linux 3.19, set_thread_area() ne peut pas être utilisé pour écrire des segments non présents, des segments d

e 16 bits ou des segments de code, bien que l'e
ffacement d'un segment soit toujours acceptable.

    Linux Programmer's Manual

    get_thread_area(2)

    SYNOPSIS

    int get_thread_area(struct user_desc *u_info);

    DESCRIPTION

    get_thread_area récupère les informations sur la zone de thread spécifiée par u_info->entry_number.

    La structure user_desc est définie dans <asm/ldt.h> comme suit :

    struct user_desc {
    unsigned int entry_number;
    unsigned int base_addr;
    unsigned int limit;
    unsigned int seg_32bit; /* Bit 0 is 1 for 32-bit segment, 0 for 16-bit */
    unsigned int contents;  /* Bit 4 is 1 for executable, 0 for data */
                          /* Bit 3 is 1 for expand-down, 0 for expand-up */
                          /* Bits 1 and 2 define ring */
    unsigned int read_exec_atomicity; /* Bit 0 is 1 for read/write, 0 for read-only */
    unsigned int権限_bit_flags;      /* Bits 1 and 2 are 1 for ring 1/2 */
    unsigned int limit_in_pages; /* Bit 0 is 1 for limit in pages, 0 for limit in bytes */
    unsigned int available_user_bits; /* Bits 1-7 are available for user-defined flags */
};

    Sur les systèmes x86, le noyau utilise une table de descripteurs de segment locaux (LDT) pour chaque thread. Chaque thread a une LDT qui contient des descripteurs qui définissent les caractéristiques des segments de mémoire. La fonction get_thread_area permet à un programme utilisateur d'accéder à ces descripteurs.

    Le champ entry_number de la structure user_desc spécifie l'index du descripteur de segment que vous souhaitez récupérer. Le noyau remplira le reste de la structure user_desc avec les informations du descripteur de segment correspondant.

    RETURN VALUE

    En cas de succès, get_thread_area renvoie 0. En cas d'erreur, elle renvoie -1 et errno est définie de manière appropriée.

    ERRORS

    EINVAL
    entry_number est invalide ou hors limites.

    STANDARDS

    Cette fonction est spécifique à Linux.

    HISTORY

    La fonction get_thread_area a été introduite dans le noyau Linux.

    NOTES

    L'utilisation de la LDT par les programmes utilisateurs est généralement déconseillée. Les mécanismes modernes de gestion de la mémoire, tels que le pagination, fournissent une gestion de la mémoire plus flexible et plus sûre. L'accès direct à la LDT peut entraîner des problèmes de sécurité et de compatibilité.

    Pour la plupart des applications, il n'est pas nécessaire d'utiliser cette fonction. Elle est principalement destinée aux programmes système ou aux débogueurs qui ont besoin d'inspecter ou de manipuler l'état interne des threads.

    BUGS

    Aucun bug connu.
