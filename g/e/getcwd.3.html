getcwd(3) Manuel des fonctions de bibliothèque getcwd(3)

NOM

getcwd, getwd, get_current_dir_name - obtenir le répertoire de travail courant

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <unistd.h>
char *getcwd(char *buf, size_t size);
char *get_current_dir_name(void);
[[deprecated]] char *getwd(char buf[PATH_MAX]);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

get_current_dir_name() :

    _GNU_SOURCE

getwd() :

    Depuis glibc 2.12 :
        (_XOPEN_SOURCE >= 500) && ! (_POSIX_C_SOURCE >= 200809L)
            || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
            || /* glibc <= 2.19 : */ _BSD_SOURCE
    Avant glibc 2.12 :
        _BSD_SOURCE || _XOPEN_SOURCE >= 500

DESCRIPTION

Ces fonctions renvoient une chaîne terminée par un octet nul contenant un chemin absolu qui est le répertoire de travail courant du processus appelant. Le chemin est renvoyé comme résultat de la fonction et via l'argument buf, s'il est présent.

La fonction getcwd() copie un chemin absolu du répertoire de travail courant dans le tableau pointé par buf, dont la longueur est size.

Si la longueur du chemin absolu du répertoire de travail courant, y compris l'octet nul de terminaison, dépasse size octets, NULL est renvoyé et errno est défini sur ERANGE ; une application devrait vérifier cette erreur et allouer un buffer plus grand si nécessaire.

En tant qu'extension à la norme POSIX.1-2001, getcwd() de glibc alloue le buffer dynamiquement en utilisant malloc(3) si buf est NULL. Dans ce cas, le buffer alloué a la longueur size sauf si size est zéro, auquel cas buf est alloué aussi grand que nécessaire. L'appelant doit libérer le buffer renvoyé avec free(3).

get_current_dir_name() utilisera malloc(3) pour allouer un tableau suffisamment grand pour contenir le chemin absolu du répertoire de travail courant. Si la variable d'environnement PWD est définie et que sa valeur est correcte, alors cette valeur sera renvoyée. L'appelant doit libérer le buffer renvoyé avec free(3).

getwd() n'alloue aucune mémoire avec malloc(3). L'argument buf doit être un pointeur vers un tableau d'au moins PATH_MAX octets. Si la longueur du chemin absolu du répertoire de travail courant, y compris l'octet nul de terminaison, dépasse PATH_MAX octets, NULL est renvoyé et errno est défini sur ENAMETOOLONG. (Notez que sur certains systèmes, PATH_MAX peut ne pas être une constante de compilation ; de plus, sa valeur peut dépendre du système de fichiers, voir pathconf(3).) Pour des raisons de portabilité et de sécurité, l'utilisation de getwd() est déconseillée.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient un pointeur vers une chaîne contenant le chemin du répertoire de travail courant. Dans le cas de getcwd() et getwd(), il s'agit de la même valeur que buf.

En cas d'échec, ces fonctions renvoient NULL et errno est défini pour indiquer l'erreur. Le contenu du tableau pointé par buf est indéfini en cas d'erreur.

ERREURS

EACCES
La permission de lire ou de rechercher un composant du nom de fichier a été refusée.
EFAULT
buf pointe vers une adresse invalide.
EINVAL
L'argument size est zéro et buf n'est pas un pointeur nul.
EINVAL
getwd() : buf est NULL.
ENAMETOOLONG
getwd() : La taille de la chaîne de chemin absolu terminée par un octet nul dépasse PATH_MAX octets.
ENOENT
Le répertoire de travail courant a été supprimé.
ENOMEM
Pas assez de mémoire.
ERANGE
L'argument size est inférieur à la longueur du chemin absolu du répertoire de travail, y compris l'octet nul de terminaison. Vous devez allouer un tableau plus grand et réessayer.

VERSIONS

POSIX.1-2001 laisse le comportement de getcwd() indéfini si buf est NULL.

POSIX.1-2001 ne définit aucune erreur pour getwd().

DIFFÉRENCES BIBLIOTHÈQUE C/NOYAU

Sous Linux, le noyau fournit un appel système getcwd() que les fonctions décrites dans cette page utiliseront si possible. L'appel système prend les mêmes arguments que la fonction de bibliothèque du même nom, mais est limité à renvoyer au maximum PATH_MAX octets. (Avant Linux 3.12, la limite de la taille du chemin renvoyé était la taille de page du système. Sur de nombreuses architectures, PATH_MAX et la taille de page du système sont toutes deux de 4096 octets, mais quelques architectures ont une taille de page plus grande.) Si la longueur du chemin du répertoire de travail courant dépasse cette limite, l'appel système échoue avec l'erreur ENAMETOOLONG. Dans ce cas, les fonctions de bibliothèque se rabattent sur une implémentation alternative (plus lente) qui renvoie le chemin complet.

Suite à un changement dans Linux 2.6.36, le chemin renvoyé par l'appel système getcwd() sera précédé de la chaîne "(unreachable)" si le répertoire courant ne se trouve pas sous la racine du répertoire du processus courant (par exemple, parce que le processus a défini une nouvelle racine de système de fichiers avec chroot(2) sans changer son répertoire courant dans la nouvelle racine). Un tel comportement peut également être causé par un utilisateur non privilégié en changeant le répertoire courant dans un autre espace de noms de montage. Lors du traitement de chemins provenant de sources non fiables, les appelants des fonctions décrites dans cette page (avant glibc 2.27) ou l'appel système brut getcwd() devraient envisager de vérifier si le chemin renvoyé commence par '/' ou '(' pour éviter d'interpréter un chemin inaccessible comme un chemin relatif.
