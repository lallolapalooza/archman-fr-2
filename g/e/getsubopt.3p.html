GETSUBOPT(3P) Manuel du programmeur POSIX GETSUBOPT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

getsubopt — analyse les arguments de sous-option d'une chaîne

SYNTAXE

#include <stdlib.h>
int getsubopt(char **optionp, char * const *keylistp, char **valuep);

DESCRIPTION

La fonction getsubopt() analyse les arguments de sous-option dans un argument de drapeau. De telles options résultent souvent de l'utilisation de getopt().

L'argument optionp de getsubopt() est un pointeur vers un pointeur vers la chaîne d'argument de l'option. Les arguments de sous-option sont séparés par des caractères <virgule> et chacun peut consister soit en un seul jeton, soit en une paire jeton-valeur séparée par un <signe égal>.

L'argument keylistp est un pointeur vers un vecteur de chaînes. La fin du vecteur est identifiée par un pointeur NULL. Chaque entrée du vecteur est l'un des jetons possibles qui pourraient être trouvés dans *optionp. Comme les caractères <virgule> délimitent les arguments de sous-option dans optionp, ils ne devraient pas apparaître dans l'une des chaînes pointées par keylistp. De même, comme un <signe égal> sépare un jeton de sa valeur, l'application ne doit pas inclure de <signe égal> dans l'une des chaînes pointées par keylistp. La fonction getsubopt() ne modifiera pas le vecteur keylistp.

L'argument valuep est l'adresse d'un pointeur de chaîne de valeur.

Si un <virgule> apparaît dans optionp, il sera interprété comme un séparateur de sous-option. Après le traitement des caractères <virgule>, s'il y a un ou plusieurs caractères <signe égal> dans une chaîne de sous-option, le premier <signe égal> dans toute chaîne de sous-option sera interprété comme un séparateur entre un jeton et une valeur. Les caractères <signe égal> suivants dans une chaîne de sous-option seront interprétés comme faisant partie de la valeur.

Si la chaîne à *optionp ne contient qu'un seul argument de sous-option (équivalent, pas de caractères <virgule>), getsubopt() mettra à jour *optionp pour pointer vers le caractère nul à la fin de la chaîne. Sinon, elle isolera l'argument de sous-option en remplaçant le séparateur <virgule> par un caractère nul, et mettra à jour *optionp pour pointer vers le début de l'argument de sous-option suivant. Si l'argument de sous-option a une valeur associée (équivalent, contient un <signe égal>), getsubopt() mettra à jour *valuep pour pointer vers le premier caractère de la valeur. Sinon, elle mettra *valuep à un pointeur NULL. L'application appelante peut utiliser cette information pour déterminer si la présence ou l'absence d'une valeur pour la sous-option constitue une erreur.

De plus, lorsque getsubopt() ne parvient pas à faire correspondre l'argument de sous-option avec un jeton dans le tableau keylistp, l'application appelante devrait décider s'il s'agit d'une erreur, ou si l'option non reconnue doit être traitée d'une autre manière.

VALEUR RENVOYÉE

La fonction getsubopt() renvoie l'index de la chaîne de jeton correspondante, ou -1 si aucune chaîne de jeton n'a été trouvée.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Analyse des sous-options

L'exemple suivant utilise la fonction getsubopt() pour analyser un argument de valeur dans la variable externe optarg renvoyée par un appel à getopt().

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int do_all;
const char *type;
int read_size;
int write_size;
int read_only;
enum
{
    RO_OPTION = 0,
    RW_OPTION,
    READ_SIZE_OPTION,
    WRITE_SIZE_OPTION
};
const char *mount_opts[] =
{
    [RO_OPTION] = "ro",
    [RW_OPTION] = "rw",
    [READ_SIZE_OPTION] = "rsize",
    [WRITE_SIZE_OPTION] = "wsize",
    NULL
};
int
main(int argc, char *argv[])
{
    char *subopts, *value;
    int opt;
    while ((opt = getopt(argc, argv, "at:o:")) != -1)
        switch(opt)
            {
            case 'a':
                do_all = 1;
                break;
            case 't':
                type = optarg;
                break;
            case 'o':
                subopts = optarg;
                while (*subopts != ' ')
                {
                    char *saved = subopts;
                    switch(getsubopt(&subopts, (char **)mount_opts,
                        &value))
                    {
                    case RO_OPTION:
                        read_only = 1;
                        break;
                    case RW_OPTION:
                        read_only = 0;
                        break;
                    case READ_SIZE_OPTION:
                        if (value == NULL)
                            abort();
                        read_size = atoi(value);
                        break;
                    case WRITE_SIZE_OPTION:
                        if (value == NULL)
                            abort();
                        write_size = atoi(value);
                        break;
                    default:
                        /* Unknown suboption. */
                        printf("Unknown suboption `%s'\n", saved);
                        abort();
                    }
                }
                break;
            default:
                abort();
            }
    /* Do the real work. */
    return 0;
}

Si l'exemple ci-dessus est invoqué avec :

programme -o ro,rsize=512

alors après l'analyse des options, la variable do_all sera 0, type sera un pointeur NULL, read_size sera 512, write_size sera 0, et read_only sera 1. S'il est invoqué avec :

programme -o oops

il affichera :

"Unknown suboption `oops'"

avant d'avorter.

USAGE PAR L'APPLICATION

La valeur de *valuep lorsque getsubopt() renvoie -1 n'est pas spécifiée. Les implémentations historiques fournissent diverses extensions incompatibles pour permettre à une application d'accéder au texte de sous-option qui n'a pas été trouvé dans le tableau keylistp.

RATIONALE

L'argument keylistp de getsubopt() est typé comme char * const * pour correspondre à la pratique historique. Cependant, le standard est clair sur le fait que les implémentations ne modifieront ni le tableau ni les chaînes contenues dans le tableau, comme si l'argument avait été typé const char * const *.
