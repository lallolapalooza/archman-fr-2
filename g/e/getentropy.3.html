getentropy(3) Manuel des fonctions de bibliothèque getentropy(3)

NOM

getentropy - remplir un tampon avec des octets aléatoires

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int getentropy(void buffer[], size_t length);
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

getentropy() :

    _DEFAULT_SOURCE

DESCRIPTION

La fonction getentropy() écrit length octets de données aléatoires de haute qualité dans le tampon commençant à l'emplacement pointé par buffer. La valeur maximale autorisée pour l'argument length est de 256.

Un appel réussi à getentropy() fournit toujours le nombre d'octets d'entropie demandé.

VALEUR DE RETOUR

En cas de succès, cette fonction renvoie zéro. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Une partie ou la totalité du tampon spécifié par buffer et length n'est pas dans une mémoire adressable valide.
EINVAL
length est supérieur à 256.
EIO
Une erreur non spécifiée s'est produite lors de la tentative de surcharge de buffer avec des données aléatoires.
ENOSYS
Cette version du noyau n'implémente pas l'appel système getrandom(2) requis pour implémenter cette fonction.

NORMES

Aucune.

HISTORIQUE

glibc 2.25. OpenBSD.

NOTES

La fonction getentropy() est implémentée à l'aide de getrandom(2).

Alors que l'enveloppe glibc fait de getrandom(2) un point d'annulation, getentropy() n'est pas un point d'annulation.

getentropy() est également déclarée dans <sys/random.h>. (Aucune macro de test de fonctionnalité ne doit être définie pour obtenir la déclaration à partir de ce fichier d'en-tête.)

Un appel à getentropy() peut bloquer si le système vient d'être démarré et que le noyau n'a pas encore collecté suffisamment d'aléas pour initialiser le pool d'entropie. Dans ce cas, getentropy() continuera à bloquer même si un signal est géré, et ne renverra qu'une fois le pool d'entropie initialisé.

VOIR AUSSI

getrandom(2), urandom(4), random(7)
