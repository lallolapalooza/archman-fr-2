subroutine cgelsy (integer m, integer n, integer nrhs, complex, dimension( lda, * ) a, integer lda, complex, dimension( ldb, * ) b, integer ldb, integer, dimension( * ) jpvt, real rcond, integer rank, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, integer info)

CGELSY résout des systèmes surdéterminés ou sousdéterminés pour les matrices GE

But :

!>
!> CGELSY calcule la solution de norme minimale d'un problème de moindres
!> carrés linéaire complexe :
!>     minimiser || A * X - B ||
!> en utilisant une factorisation orthogonale complète de A. A est une
!> matrice M par N qui peut être de rang déficient.
!>
!> Plusieurs vecteurs de second membre b et vecteurs de solution x peuvent
!> être traités dans un seul appel ; ils sont stockés en tant que colonnes
!> de la matrice de second membre B de taille M par NRHS et de la matrice
!> de solution X de taille N par NRHS.
!>
!> La routine calcule d'abord une factorisation QR avec pivotement sur les
!> colonnes :
!>     A * P = Q * [ R11 R12 ]
!>                 [  0  R22 ]
!> où R11 est définie comme la plus grande sous-matrice principale dont le
!> nombre de condition estimé est inférieur à 1/RCOND. L'ordre de R11,
!> RANK, est le rang effectif de A.
!>
!> Ensuite, R22 est considérée comme négligeable, et R12 est annihilée
!> par des transformations unitaires à droite, aboutissant à la
!> factorisation orthogonale complète :
!>    A * P = Q * [ T11 0 ] * Z
!>                [  0  0 ]
!> La solution de norme minimale est alors
!>    X = P * Z**H [ inv(T11)*Q1**H*B ]
!>                 [        0         ]
!> où Q1 est constituée des premières RANK colonnes de Q.
!>
!> Cette routine est essentiellement identique à la version originale xGELSX
!> à trois différences près :
!>   o La permutation de la matrice B (le second membre) est plus rapide et
!>     plus simple.
!>   o L'appel à la subroutine xGEQPF a été remplacé par
!>     l'appel à la subroutine xGEQP3. Cette subroutine est une version
!>     Blas-3 de la factorisation QR avec pivotement sur les colonnes.
!>   o La matrice B (le second membre) est mise à jour avec Blas-3.
!>

Paramètres

M 
!>          M est INTEGER
!>          Le nombre de lignes de la matrice A. M >= 0.
!>

N

!>          N est INTEGER
!>          Le nombre de colonnes de la matrice A. N >= 0.
!>

NRHS

!>          NRHS est INTEGER
!>          Le nombre de seconds membres, c'est-à-dire le nombre de
!>          colonnes des matrices B et X. NRHS >= 0.
!>

A

!>          A est un tableau COMPLEX, dimension (LDA,N)
!>          À l'entrée, la matrice A de taille M par N.
!>          À la sortie, A a été écrasée par les détails de sa
!>          factorisation orthogonale complète.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,M).
!>

B

!>          B est un tableau COMPLEX, dimension (LDB,NRHS)
!>          À l'entrée, la matrice de second membre B de taille M par NRHS.
!>          À la sortie, la matrice de solution X de taille N par NRHS.
!>          Si M = 0 ou N = 0, B n'est pas référencée.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale du tableau B. LDB >= max(1,M,N).
!>

JPVT

!>          JPVT est un tableau INTEGER, dimension (N)
!>          À l'entrée, si JPVT(i) .ne. 0, la i-ème colonne de A est permutée
!>          au début de AP, sinon la colonne i est une colonne libre.
!>          À la sortie, si JPVT(i) = k, alors la i-ème colonne de A*P
!>          était la k-ème colonne de A.
!>

RCOND

!>          RCOND est REAL
!>          RCOND est utilisé pour déterminer le rang effectif de A, qui
!>          est défini comme l'ordre de la plus grande sous-matrice
!>          triangulaire principale R11 dans la factorisation QR avec
!>          pivotement de A, dont le nombre de condition estimé est < 1/RCOND.
!>

RANK

!>          RANK est INTEGER
!>          Le rang effectif de A, c'est-à-dire l'ordre de la sous-matrice
!>          R11. C'est le même que l'ordre de la sous-matrice T11
!>          dans la factorisation orthogonale complète de A.
!>          Si NRHS = 0, RANK = 0 en sortie.
!>

WORK

!>          WORK est un tableau COMPLEX, dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) retourne le LWORK optimal.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK.
!>          La stratégie non par blocs exige que :
!>            LWORK >= MN + MAX( 2*MN, N+1, MN+NRHS )
!>          où MN = min(M,N).
!>          L'algorithme par blocs exige que :
!>            LWORK >= MN + MAX( 2*MN, NB*(N+1), MN+MN*NB, MN+NB*NRHS )
!>          où NB est une borne supérieure sur la taille de bloc retournée
!>          par ILAENV pour les routines CGEQP3, CTZRZF, CTZRQF, CUNMQR,
!>          et CUNMRZ.
!>
!>          Si LWORK = -1, une interrogation d'espace de travail est supposée ; la routine
!>          calcule uniquement la taille optimale du tableau WORK, retourne
!>          cette valeur comme première entrée du tableau WORK, et aucun message
!>          d'erreur lié à LWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau REAL, dimension (2*N)
!>

INFO

!>          INFO est INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale
!>

!>          RANK est INTEGER
!>          Le rang effectif de A, c'est-à-dire l'ordre de la sous-matrice
!>          R11. C'est le même que l'ordre de la sous-matrice T11
!>          dans la factorisation orthogonale complète de A.

!>          WORK est un tableau COMPLEX*16, dimension (MAX(1,LWORK))

!>          LWORK est INTEGER
!>          La dimension du tableau WORK.
!>          La stratégie non par blocs exige que :
!>            LWORK >= MN + MAX( 2*MN, N+1, MN+NRHS )
!>          où MN = min(M,N).
!>          L'algorithme par blocs exige que :
!>            LWORK >= MN + MAX( 2*MN, NB*(N+1), MN+MN*NB, MN+NB*NRHS )
!>          où NB est une borne supérieure sur la taille de bloc retournée

!>

!>          supposée ; la routine calcule uniquement la taille optimale

!>          n'est émis par XERBLA.
