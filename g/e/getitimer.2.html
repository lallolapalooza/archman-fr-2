DESCRIPTIO

N

Ces appels système donnent accès aux minuteurs d'intervalle, c'est-à-dire des minuteurs qui expirent initialement à un moment donné dans le futur, et (facultativement) à intervalles réguliers par la suite. Lorsqu'un minuteur expire, un signal est généré pour le processus appelant, et le minuteur est réinitialisé à l'intervalle spécifié (si l'intervalle est non nul)

.

Trois types de minuteurs — spécifiés via l' argument which — sont fournis, chacun comptant sur une horloge différente et générant un signal différent à l'expiration du minuteur

:
ITIMER_RE
AL
Ce minuteur décompte en temps réel (c'est-à-dire temps écoulé). À chaque expiration, un signal SIGALRM est
généré.
ITIMER_VIRTU
AL
Ce minuteur décompte sur le temps CPU en mode utilisateur consommé par le processus. (La mesure inclut le temps CPU consommé par tous les fils dans le processus.) À chaque expiration, un signal SIGVTALRM est
généré.
ITIMER_PR
OF
Ce minuteur décompte sur le temps CPU total (c'est-à-dire à la fois utilisateur et système) consommé par le processus. (La mesure inclut le temps CPU consommé par tous les fils du processus.) À chaque expiration, un signal SIGPROF
est
généré.
En conjonction avec ITIMER_VIRTUAL, ce minuteur peut être utilisé pour profile
r le temps CPU utilisateur et sy
stème consommé par le processus.

Un processus n'a qu'un seul minuteur de chacun des trois

types.

Les valeurs des minuteurs sont définies par les structures suivantes

: 


struct itimerval {
    struct timeval it_interval; /* Intervalle pour le minuteur périodique */
    struct timeval it_value;    /* Temps jusqu'à la prochaine expiration */
};
struct timeval {
    time_t      tv_sec;         /* secondes */
    suseconds_t tv_usec;        /* microsecondes */
}
;

getitimer(

)

La fonction getitimer() place la valeur actuelle du minuteur spécifié par which dans le tampon pointé par curr_value

.

La sous-structure it_value est remplie avec le temps restant jusqu'à la prochaine expiration du minuteur spécifié. Cette valeur change à mesure que le minuteur décompte, et sera réinitialisée à it_interval lorsque le minuteur expire. Si les deux champs de it_value sont à zéro, alors ce minuteur est actuellement désarmé (inactif)

.

La sous-structure it_interval est remplie avec l'intervalle du minuteur. Si les deux champs de it_interval sont à zéro, alors il s'agit d'un minuteur à d

éclenchement unique (c'est-à-di
re qu'il n'expire qu'une fois).

setitimer(

)

La fonction setitimer() arme ou désarme le minuteur spécifié par which, en définissant le minuteur à la valeur spécifiée par new_value. Si old_value n'est pas NULL, le tampon qu'il pointe est utilisé pour renvoyer la valeur précédente du minuteur (c'est-à-dire les mêmes informations que celles renvoyées par getitimer())

.

Si l'un des champs dans new_value.it_value est non nul, alors le minuteur est armé pour expirer initialement à l'heure spécifiée. Si les deux champs dans new_value.it_value sont à zéro, alors le minuteur est

désarmé.

Le champ new_value.it_interval spécifie le nouvel intervalle po

ur le minuteur ; si ses deux so
us-champs sont à zéro, le minute
ur est à déclenchement unique.

VERSION

S

Les normes sont muettes sur la signification de l'appel

: 


setitimer(which, NULL, &old_value)
;

De nombreux systèmes (Solaris, les BSD, et peut-être d'autres) traitent cela comme équivalent à

: 


getitimer(which, &old_value)
;

Dans Linux, cela est traité comme équivalent à un appel dans lequel les champs new_value sont à zéro ; c'est-à-dire que le minuteur est désactivé. N'utilisez pas cette mauvaise fonctionnalité d

e Linux : elle n'est pas
portable et inutile.

NOTE

S

Les minuteurs n'expireront jamais avant l'heure demandée, mais peuvent expirer quelque temps (court) après, ce qui dépend de la résolution du minuteur système et de la charge du système ; voir time(7). (Mais voir BUGS ci-dessous.) Si le minuteur expire alors que le processus est actif (toujours vrai pour ITIMER_VIRTUAL), le signal sera délivré immédiatement lorsqu'il est

généré.

Un enfant créé via fork(2) n'hérite pas des minuteurs d'intervalle de son parent. Les minuteurs d'intervalle sont préservés à travers un execve(

2).

POSIX.1 laisse l'interaction entre setitimer() et les trois interfaces alarm(2), sleep(3) et usleep(3)

non spé
cifiée.

BUG

S

La génération et la délivrance d'un signal sont distinctes, et une seule instance de chacun des signaux listés ci-dessus peut être en attente pour un processus. Sous une charge très élevée, un minuteur ITIMER_REAL peut expirer avant que le signal d'une expiration précédente ait été délivré. Le second signal dans un tel événement sera

perdu.

Avant Linux 2.6.16, les valeurs des minuteurs sont représentées en jiffies. Si une requête est faite pour définir un minuteur avec une valeur dont la représentation en jiffies dépasse MAX_SEC_IN_JIFFIES (défini dans include/linux/jiffies.h), alors le minuteur est silencieusement tronqué à cette valeur plafond. Sur Linux/i386 (où, depuis Linux 2.6.13, le jiffy par défaut est de 0,004 seconde), cela signifie que la valeur plafond pour un minuteur est d'environ 99,42 jours. Depuis Linux 2.6.16, le noyau utilise une représentation interne différente pour les temps, et ce plafond est

supprimé.

Sur certains systèmes (y compris i386), les noyaux Linux antérieurs à Linux 2.6.12 ont un bogue qui produira des expirations prématurées de minuteur allant jusqu'à un jiffy dans certaines circonstances. Ce bogue est corrigé dans Linux 2.6.

12.

POSIX.1-2001 dit que setitimer() devrait échouer si un tv_useune valeur c est spécifiée en dehors de l'intervalle [0, 999999]. Cependant, jusqu'à et y compris Linux 2.6.21, Linux ne renvoie pas d'erreur, mais ajuste à la place silencieusement la valeur des secondes correspondante pour le minuteur. À partir de Linux 2.6.22, cette non-conformité a été corrigée : une valeur tv_usec incorrecte entraîne une erreur EINV
