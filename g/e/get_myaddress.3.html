void clnt_pcreateerror(const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi un handle RPC client n'a pas pu être créé. Le message est précédé de la chaîne s et d'un deux-points. Utilisé lorsqu'un appel à clnt_create(), clntraw_create(), clnttcp_create(), ou clntudp_create() échoue.
void clnt_perrno(enum clnt_stat stat);
Affiche un message sur la sortie d'erreur standard correspondant à la condition indiquée par stat. Utilisé après callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué ; clnt est le handle utilisé pour effectuer l'appel. Le message est précédé de la chaîne s et d'un deux-points. Utilisé après clnt_call().
char *clnt_spcreateerror(const char *s);
Identique à clnt_pcreateerror(), sauf qu'il renvoie une chaîne au lieu d'afficher sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
char *clnt_sperrno(enum clnt_stat stat);
Prend les mêmes arguments que clnt_perrno(), mais au lieu d'envoyer un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué, renvoie un pointeur vers une chaîne contenant le message. La chaîne se termine par un saut de ligne. (NEWLINE).
clnt_sperrno() est utilisé à la place de clnt_perrno() si le programme n'a pas de sortie d'erreur standard (ce qui est assez probable pour un programme fonctionnant en tant que serveur), ou si le programmeur ne souhaite pas que le message soit affiché avec printf(3), ou si un format de message différent de celui pris en charge par clnt_perrno() doit être utilisé. Note : contrairement à clnt_sperror() et clnt_spcreateerror(), clnt_sperrno() renvoie un pointeur vers des données statiques, mais le résultat ne sera pas écrasé à chaque appel.
char *clnt_sperror(CLIENT *rpch, const char *s);
Identique à clnt_perror(), sauf que (comme clnt_sperrno()) il renvoie une chaîne au lieu d'afficher sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Cette routine crée un client RPC factice pour le programme distant prognum, version versnum. Le transport utilisé pour passer des messages au service est en fait un tampon dans l'espace d'adressage du processus, de sorte que le serveur RPC correspondant doit résider dans le même espace d'adressage ; voir svcraw_create(). Cela permet de simuler le RPC et d'acquérir des surcoûts RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau. Cette routine renvoie NULL si elle échoue.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Comme le RPC basé sur TCP utilise une E/S mise en tampon, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; les valeurs zéro choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL si elle échoue.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou jusqu'à ce que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call().
Avertissement : comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Ko de données encodées, ce transport ne peut pas être utilisé pour les procédures qui prennent de grands arguments ou retournent d'énormes résultats.

            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Cette routine crée un client RPC pour le programme distant prognum, sur versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour obtenir cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou jusqu'à ce que l'appel expire. void get_myaddress(struct sockaddr_in *addr);
Insère l'adresse IP de la machine dans *addr, sans consulter les routines de bibliothèque qui traitent /etc/hosts. Le numéro de port est toujours défini sur htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Une interface utilisateur pour le service portmap, qui renvoie une liste des mappages actuels programme RPC vers port sur l'hôte situé à l'adresse IP *addr. Cette routine peut renvoyer NULL. La commande rpcinfo -p utilise cette routine.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Une interface utilisateur pour le service portmap, qui renvoie le numéro de port sur lequel attend un service qui prend en charge le numéro de programme prognum, version versnum, et parle le protocole de transport associé à protocol. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Une valeur de retour de zéro signifie que le mappage n'existe pas ou que le système RPC n'a pas réussi à contacter le service portmap distant. Dans ce dernier cas, la variable globale rpc_createerr contient le statut RPC.

Une interface utilisateur pour le service portmap, qui demande au portmap sur l'hôte à l'adresse IP *addr d'effectuer un appel RPC en votre nom vers une procédure sur cet hôte.
