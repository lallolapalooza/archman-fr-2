GENSIO_EVENT_REA

D

Appelé lorsque des données sont lues depuis le périphérique

E/S.

Si err est nul, buf pointe vers un tampon de données et buflen est le nombre d'octets

disponibles.

Si err est défini, buf et buflen sont indéfinis et vous ne devez pas les utiliser ni les modifier. err est un errno gensio

standard.

Si err est non nul, vous devez définir le nombre d'octets consommés dans buflen. Notez que vous devez désactiver la lecture si vous ne consommez pas tous les octets ou dans d'autres situations où vous ne voulez pas que le gestionnaire de lecture soit appelé. auxdata, s'il n'est pas NULL, peut contenir des informations sur le message, comme s'il s'agit de données hors bande (oob). Voir les informations sur le gensio spécifique pour plus de

détails.

Notez qu'un seul rappel de lecture est autorisé à s'exécuter à la fois sur un

gensio.

Si une erreur est signalée dans err, le gensio sera fermé. Cela est utilisé pour signaler que l'autre extrémité a fermé la connexion (GE_REMCLOSE), ou que d'autres erreurs internes se sont

produites.

Vous devriez toujours retourner zéro,

cela n'avait pas d'importance auparav
ant, mais c'est le cas maintenant.

GENSIO_EVENT_WRITE_READ

Y

Appelé lorsque des données peuvent être écrites sur le périphérique

E/S.

Notez qu'un seul rappel d'écriture est autorisé à s'exécuter à la fois sur un

gensio.

Contrairement aux systèmes de type Unix, un gestionnaire d'écriture sera appelé (si activé) si la couche inférieure a une exception. C'est nécessaire parce que nous n'avons pas de gestionnaire d'exception séparé provenant de la couche inférieure. Mais cela permet à l'opération d'écriture de retourner un échec si quelque chose s'est mal

passé.

Vous devriez toujours retourner zéro,

cela n'avait pas d'importance auparav
ant, mais c'est le cas maintenant.

GENSIO_EVENT_NEW_CHANNE

L

Un nouveau canal a été créé par l'extrémité distante de la connexion. Le nouveau gensio de canal est dans buf et doit être casté. Des informations sur le canal seront passées dans auxdata, voir la documentation sur le gensio particulier pour plus de détails. Si cela retourne une erreur (non nulle), le canal est fermé, bien que dans le futur des retours d'erreurs spécifiques puissent avoir un comportem

ent différent. Vous devez retourner GE_NOTSUP (comme vous devriez le faire pour tous les événements non gérés) si
vous ne supportez pas cet événement. Tous les autres retours d'erreurs autres que zéro et GE_NOTSUP sont réservés.

SÉRIE

Ce sont des contrôles pour les paramètres de port série. Ceux-ci sont reçus sur le côté serveur uniquement. Il devrait répondre en définissant la valeur (si possible et la valeur n'est pas zéro) et répondre avec la valeur actuelle avec sergensio_xxx()

.

Si le serveur reçoit une valeur zéro pour l'un de ceux-ci, il devrait simplement rapporter la valeur et ne rien

changer.

FONCTIONS

D'ÉTAT

GENSIO_EVENT_SER_MODEMSTATE_MASK
GENSIO_EVENT_SER_LINESTATE_MASK
Ceux-ci sont reçus sur le côté serveur pour demander la mise à jour du masque des valeurs rapportées. Le serveur doit répondre en retournant le masque actuel avec le sergensio_modemstate ou sergensio_linestate. Le serveur n'a pas besoin de gérer tous les bits demandés par

l'utilisateur.

GENSIO_EVENT_SER_MODEMSTATE
GENSIO_EVENT_SER_LINESTAT

E

Sur le côté client, ceux-ci rapportent les changements actuels de modemstate

et linestate sous forme d'entier non signé. Voir sergensio_modemstate(3)
et sergensio_linestate(3) pour la signification des bits dans l'entier.
