DESCRIPTION

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications doivent utiliser getaddrinfo(3), getnameinfo(3) et gai_strerror(3) à la place.

La fonction sethostent() spécifie, si stayopen est vrai (1), qu'un socket TCP connecté doit être utilisé pour les requêtes du serveur de noms et que la connexion doit rester ouverte pendant les requêtes successives. Sinon, les requêtes du serveur de noms utiliseront des datagrammes UDP.

La fonction endhostent() met fin à l'utilisation d'une connexion TCP pour les requêtes du serveur de noms.

La fonction gethostbyname() renvoie une structure de type hostent pour le nom d'hôte name donné. Ici name est soit un nom d'hôte, soit une adresse IPv4 en notation décimale pointée standard (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent struct in_addr dans le champ h_addr_list[0] de la structure hostent retournée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias pointé par HOSTALIASES sera d'abord recherché pour name (voir hostname(7) pour le format du fichier). Le domaine actuel et ses parents sont recherchés à moins que name ne se termine par un point.

La fonction gethostbyaddr() renvoie une structure de type hostent pour l'adresse d'hôte addr donnée de taille size et de type d'adresse type. Les types d'adresse valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument d'adresse d'hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple un struct in_addr * (probablement obtenu via un appel à inet_addr(3)) pour le type d'adresse AF_INET.

La fonction (obsolète) herror() imprime le message d'erreur associé à la valeur actuelle de h_errno sur stderr.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et renvoie la chaîne de message correspondante.

Les requêtes de noms de domaine effectuées par gethostbyname() et gethostbyaddr() s'appuient sur les sources configurées du Name Service Switch (nsswitch.conf(5)) ou sur un serveur de noms local (named(8)). L'action par défaut est d'interroger les sources configurées du Name Service Switch (nsswitch.conf(5)), et en cas d'échec, un serveur de noms local (named(8)).

Historique

Le fichier nsswitch.conf(5) est la manière moderne de contrôler l'ordre des recherches d'hôtes.

Dans glibc 2.4 et versions antérieures, le mot-clé order était utilisé pour contrôler l'ordre des recherches d'hôtes tel que défini dans /etc/host.conf (host.conf(5)).

La structure hostent est définie dans <netdb.h> comme suit :


struct hostent {
    char  *h_name;            /* nom officiel de l'hôte */
    char **h_aliases;         /* liste des alias */
    int    h_addrtype;        /* type d'adresse de l'hôte */
    int    h_length;          /* taille de l'adresse */
    char **h_addr_list;       /* liste des adresses */
}
#define h_addr h_addr_list[0] /* pour la compatibilité ascendante */

Les membres de la structure hostent sont :

h_name
Le nom officiel de l'hôte.
h_aliases
Un tableau de noms alternatifs pour l'hôte, terminé par un pointeur nul.
h_addrtype
Le type d'adresse ; actuellement toujours AF_INET ou AF_INET6.
h_length
La taille de l'adresse en octets.
h_addr_list
Un tableau de pointeurs vers les adresses réseau de l'hôte (en ordre d'octets réseau), terminé par un pointeur nul.
h_addr
La première adresse dans h_addr_list pour la compatibilité ascendante.

ERREURS

La variable h_errno peut avoir les valeurs suivantes :

HOST_NOT_FOUND
L'hôte spécifié est inconnu.
NO_DATA
Le nom demandé est valide mais n'a pas d'adresse IP. Un autre type de requête au serveur de noms pour ce domaine peut retourner une réponse. La constante NO_ADDRESS est synonyme de NO_DATA.
NO_RECOVERY
Une erreur irrécupérable du serveur de noms s'est produite.
TRY_AGAIN
Une erreur temporaire s'est produite sur un serveur de noms faisant autorité. Réessayez plus tard.

NOTES

Les fonctions gethostbyname() et gethostbyaddr() peuvent retourner des pointeurs vers des données statiques, qui peuvent être écrasées par des appels ultérieurs. La copie de la struct hostent ne suffit pas, car elle contient des pointeurs ; une copie profonde est requise.

Dans l'implémentation BSD d'origine, l'argument size de gethostbyname() était un int. La norme SUSv2 est boguée et déclare l'argument size de gethostbyaddr() comme étant de type size_t. (C'est faux, car il doit être de type int, et size_t ne l'est pas. POSIX.1-2001 en fait un socklen_t, ce qui est correct.) Voir aussi accept(2).

Le prototype BSD pour gethostbyaddr() utilise const char * pour le premier argument.

Extension System V/POSIX

POSIX exige l'appel gethostent(), qui doit retourner l'entrée suivante dans la base de données des hôtes. Lors de l'utilisation de DNS/BIND, cela n'a pas beaucoup de sens, mais cela peut être raisonnable si la base de données des hôtes est un fichier qui peut être lu ligne par ligne. Sur de nombreux systèmes, une routine de ce nom lit dans le fichier /etc/hosts. Elle peut n'être disponible que lorsque la bibliothèque a été compilée sans prise en charge DNS. La version glibc ignorera les entrées ipv6. Cette fonction n'est pas réentrante, et glibc ajoute une version réentrante gethostent_r().

Extensions GNU

glibc2 a également gethostbyname2() qui fonctionne comme gethostbyname(), mais permet de spécifier la famille d'adresses à laquelle l'adresse doit appartenir.

glibc2 a également des versions réentrantes gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), et gethostbyname2_r(). L'appelant fournit une structure hostent ret qui sera remplie en cas de succès, et un tampon de travail temporaire buf de taille bufsize. Après l'appel, result pointera vers le résultat en cas de succès. En cas d'erreur ou si aucune entrée n'est trouvée, result sera NULL. Les fonctions retournent 0 en cas de succès et un numéro d'erreur non nul en cas d'échec. En plus des erreurs retournées par les versions non réentrantes de ces fonctions, si buf est trop petit, les fonctions retourneront ERANGE, et l'appel devrait être réessayé avec un tampon plus grand. La variable globale h_errno n'est pas modifiée, mais l'adresse d'une variable dans laquelle stocker les numéros d'erreur est passée dans h_errnop.

BOGUES

gethostbyname() ne reconnaît pas les composants d'une chaîne d'adresse IPv4 pointée qui sont exprimés en hexadécimal.
