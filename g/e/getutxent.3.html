DESCRIPTIO

N

Les nouvelles applications devraient utiliser les versions « utmpx » de ces fonctions spécifiées par POSIX.1 ; voir

NORMES.

utmpname() définit le chemin d'accès du fichier au format utmp que les autres fonctions utmp doivent utiliser. Si utmpname() n'est pas utilisé pour définir le chemin d'accès avant l'utilisation des autres fonctions, celles-ci supposent _PATH_UTMP, tel que défini dans <paths.h>

.

setutent() rembobine le pointeur de fichier au début du fichier utmp. Il est généralement bon de l'appeler avant toutes les autres

fonctions.

endutent() ferme le fichier utmp. Il devrait être appelé lorsque le code utilisateur a terminé l'accès au fichier avec les autres

fonctions.

getutent() lit une ligne à la position courante du fichier dans le fichier utmp. Elle renvoie un pointeur vers une structure contenant les champs de la ligne. La définition de cette structure est montrée dans utmp(

5).

getutid() recherche vers l'avant à partir de la position courante du fichier dans le fichier utmp en se basant sur ut. Si ut->ut_type est l'un de RUN_LVL, BOOT_TIME, NEW_TIME, ou OLD_TIME, getutid() trouvera la première entrée dont le champ ut_type correspond à ut->ut_type. Si ut->ut_type est l'un de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, ou DEAD_PROCESS, getutid() trouvera la première entrée dont le champ ut_id correspond à ut->ut_

id.

getutline() recherche vers l'avant à partir de la position courante du fichier dans le fichier utmp. Elle parcourt les entrées dont le ut_type est USER_PROCESS ou LOGIN_PROCESS et renvoie la première dont le champ ut_line correspond à ut->ut_l

ine.

pututline() écrit la structure utmp ut dans le fichier utmp. Elle utilise getutid() pour chercher l'emplacement approprié dans le fichier pour insérer la nouvelle entrée. Si elle ne trouve pas un emplacement approprié pour ut, pututline() ajoutera la nouvelle

entrée à la fin
du fichier.

VALEUR

RENVOYÉE

getutent(), getutid(), et getutline() renvoient un pointeur vers une struct utmp en cas de succès, et NULL en cas d'échec (ce qui inclut le cas « enregistrement non trouvé »). Cette struct utmp est allouée dans un stockage statique, et peut être écrasée par des appels

ultérieurs.

En cas de succès pututline() renvoie ut ; en cas d'échec, elle renvoie

NULL.

utmpname() renvoie 0 si le nouveau nom a été stocké avec succès, ou -1 en cas

d'échec.

En cas d'échec, ces fonctions errno défini pour in

diquer
l'erreur.

HISTORIQU

E

XPG2,

SVr4.

Dans XPG2 et SVID 2, la fonction pututline() est documentée comme renvoyant void, et c'est ce qu'elle fait sur de nombreux systèmes (AIX, HP-UX). HP-UX introduit une nouvelle fonction _pututline() avec le prototype donné ci-dessus pour pututlin

e().

Toutes ces fonctions sont maintenant obsolètes sur les systèmes non Linux. POSIX.1-2001 et POSIX.1-2008, à la suite de SUSv1, n'ont aucune de ces fonctions, mais utilisent

plutôt 
#include <utmpx.
h> 
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void en
dutxent
(void);

Ces fonctions sont fournies par glibc et effectuent la même tâche que leurs équivalentes sans le « x », mais utilisent struct utmpx, définie sur Linux comme étant identique à struct utmp. Pour plus de complétude, glibc fournit aussi utmpxname(), bien que cette fonction ne soit pas spécifiée par POSIX.

1.

Sur certains autres systèmes, la structure utmpx est un sur-ensemble de la structure utmp, avec des champs supplémentaires, et des versions plus larges des champs existants, et des fichiers parallèles sont maintenus, souvent /var/*/utmpx et /var/*/wtmpx

.

Linux glibc, en revanche, n'utilise pas un fichier utmpx parallèle car sa structure utmp est déjà suffisamment grande. Les fonctions « x » listées ci-dessus sont simplement des alias pour leurs homologues sans le « x » (par ex., getutxent() est un alias pour getute

nt(
)).

    _GNU_SOURCE
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE

Ces fonctions sont des extensions GNU, analogues des fonctions de même nom sans le suffixe _r. L'argument ubuf donne à ces fonctions un endroit pour stocker leur résultat. En cas de succès, elles renvoient 0, et un pointeur vers le résultat est écrit dans *ubufp. En cas d'erreur, ces fonctions renvoient -1. Il n'exist

e pas d'équivalents utmpx des fonc

spécifie pas de telles fonctions.)

EXEMPLE

S

TL'exemple suivant ajoute et supprime un enregistrement utmp, en supposant qu'il est exécuté depuis un terminal pseudo. Pour une utilisation dans une application réelle, vous devriez vérifier les valeurs de retour de getpwuid(3) et ttyname

(3). 
#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo avant l'ajout de l'entrée:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* seulement correct pour les ptys nommées /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo après l'ajout de l'entrée:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo après la suppression de l'entrée:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
