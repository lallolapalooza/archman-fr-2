getunwind(2) Manuel des appels système getunwind(2)

NOM

getunwind - copie les données de déroulement dans le tampon de l'appelant

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/unwind.h>
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
[[deprecated]] long syscall(size_t buf_size;
                            SYS_getunwind, void buf[buf_size],
                            size_t buf_size);

DESCRIPTION

Note : cet appel système est obsolète.

L'appel système getunwind() spécifique à IA-64 copie les données de déroulement de la pile d'appels du noyau dans le tampon pointé par buf et retourne la taille des données de déroulement ; ces données décrivent la page de porte (code du noyau qui est mappé dans l'espace utilisateur).

La taille du tampon buf est spécifiée par buf_size. Les données sont copiées uniquement si buf_size est supérieur ou égal à la taille des données de déroulement et si buf n'est pas NULL ; sinon, aucune donnée n'est copiée et l'appel réussit, retournant la taille qui serait nécessaire pour stocker les données de déroulement.

La première partie des données de déroulement contient une table de déroulement. Le reste contient les informations de déroulement associées, dans aucun ordre particulier. La table de déroulement contient des entrées de la forme suivante :


u64 start;      (adresse 64 bits du début de la fonction)
u64 end;        (adresse 64 bits de la fin de la fonction)
u64 info;       (décalage relatif à BUF vers les informations de déroulement)

Une entrée dont la valeur start est zéro indique la fin de la table. Pour plus d'informations sur le format, voir le manuel IA-64 Software Conventions and Runtime Architecture.

VALEUR DE RETOUR

En cas de succès, getunwind() retourne la taille des données de déroulement. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

getunwind() échoue avec l'erreur EFAULT si les informations de déroulement ne peuvent pas être stockées dans l'espace spécifié par buf.

NORMES

Linux sur IA-64.

HISTORIQUE

Linux 2.4.

Cet appel système a été déprécié. La méthode moderne pour obtenir les données de déroulement du noyau est via le vdso(7).
