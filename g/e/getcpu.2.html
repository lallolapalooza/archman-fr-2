getcpu(2) Manuel des appels système getcpu(2)

NOM

getcpu - déterminer le processeur et le nœud NUMA sur lesquels le fil d'exécution appelant s'exécute

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <sched.h>
int getcpu(unsigned int *_Nullable cpu, unsigned int *_Nullable node);

DESCRIPTION

L'appel système getcpu() identifie le processeur et le nœud sur lesquels le fil d'exécution ou le processus appelant s'exécute actuellement et les écrit dans les entiers pointés par les arguments cpu et node. Le processeur est un petit entier unique identifiant un CPU. Le nœud est un identifiant unique petit identifiant un nœud NUMA. Lorsque cpu ou node est NULL, rien n'est écrit dans le pointeur respectif.

Les informations placées dans cpu ne sont garanties d'être actuelles qu'au moment de l'appel : à moins que l'affinité du CPU n'ait été fixée à l'aide de sched_setaffinity(2), le noyau peut changer le CPU à tout moment. (Normalement, cela n'arrive pas car le planificateur essaie de minimiser les mouvements entre les CPUs pour garder les caches chauds, mais c'est possible.) L'appelant doit tenir compte de la possibilité que les informations retournées dans cpu et node ne soient plus actuelles au moment du retour de l'appel.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Les arguments pointent en dehors de l'espace d'adressage du processus appelant.

NORMES

Linux.

HISTORIQUE

Linux 2.6.19 (x86-64 et i386), glibc 2.29.

DIFFÉRENCES BIBLIOTHÈQUE C/NOYAU

L'appel système du noyau a un troisième argument :


int getcpu(unsigned int *cpu, unsigned int *node,
           struct getcpu_cache *tcache);

L'argument tcache est inutilisé depuis Linux 2.6.24, et (lors de l'appel direct du système) doit être spécifié comme NULL, sauf si la portabilité vers Linux 2.6.23 ou antérieur est requise.

Dans Linux 2.6.23 et antérieur, si l'argument tcache n'était pas NULL, il spécifiait un pointeur vers un tampon alloué par l'appelant dans le stockage local du fil d'exécution, qui était utilisé pour fournir un mécanisme de mise en cache pour getcpu(). L'utilisation du cache pouvait accélérer les appels getcpu(), au prix d'une très faible chance que les informations retournées soient obsolètes. Le mécanisme de mise en cache était considéré comme problématique lors de la migration des fils d'exécution entre CPUs, et l'argument est donc maintenant ignoré.

NOTES

Linux fait de son mieux pour rendre cet appel aussi rapide que possible. (Sur certaines architectures, cela est fait via une implémentation dans le vdso(7).) L'intention de getcpu() est de permettre aux programmes de faire des optimisations avec des données par CPU ou pour l'optimisation NUMA.

VOIR AUSSI

mbind(2), sched_setaffinity(2), set_mempolicy(2), sched_getcpu(3), cpuset(7), vdso(7)
