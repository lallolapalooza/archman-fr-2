getaddrinfo(3) Manuel des fonctions de bibliothèque getaddrinfo(3)

NOM

getaddrinfo, freeaddrinfo, gai_strerror - traduction d'adresses et de services réseau

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netdb.h>
int getaddrinfo(const char *restrict node,
                const char *restrict service,
                const struct addrinfo *restrict hints,
                struct addrinfo **restrict res);
void freeaddrinfo(struct addrinfo *res);
const char *gai_strerror(int errcode);

DESCRIPTION

Étant donné node et service, qui identifient un hôte Internet et un service, getaddrinfo() renvoie une ou plusieurs structures addrinfo , chacune contenant une adresse Internet pouvant être spécifiée dans un appel à bind(2) ou connect(2). La fonction getaddrinfo() combine les fonctionnalités fournies par les fonctions gethostbyname(3) et getservbyname(3) en une seule interface, mais contrairement à ces dernières, la fonction getaddrinfo() est réentrante et permet aux programmes d'éliminer les dépendances IPv4-contre-IPv6.

La structure addrinfo utilisée par getaddrinfo() contient les champs suivants :


struct addrinfo {
    int              ai_flags;
    int              ai_family;
    int              ai_socktype;
    int              ai_protocol;
    socklen_t        ai_addrlen;
    struct sockaddr *ai_addr;
    char            *ai_canonname;
    struct addrinfo *ai_next;
};

L'argument hints pointe vers une structure addrinfo qui spécifie les critères de sélection des structures d'adresse de socket renvoyées dans la liste pointée par res. Si hints n'est pas NULL, il pointe vers une structure addrinfo dont les champs ai_family, ai_socktypeet ai_protocol spécifient des critères qui limitent l'ensemble des adresses de socket renvoyées par getaddrinfo(), comme suit :

ai_family
Ce champ spécifie la famille d'adresses souhaitée pour les adresses renvoyées. Les valeurs valides pour ce champ incluent AF_INET et AF_INET6. La valeur AF_UNSPEC indique que getaddrinfo() doit renvoyer des adresses de socket pour n'importe quelle famille d'adresses (IPv4 ou IPv6 par exemple) pouvant être utilisée avec node et service.
ai_socktype
Ce champ spécifie le type de socket préféré, par exemple SOCK_STREAM ou SOCK_DGRAM. Spécifier 0 dans ce champ indique que des adresses de socket de n'importe quel type peuvent être renvoyées par getaddrinfo().
ai_protocol
Ce champ spécifie le protocole pour les adresses de socket renvoyées. Spécifier 0 dans ce champ indique que des adresses de socket avec n'importe quel protocole peuvent être renvoyées par getaddrinfo().
ai_flags
Ce champ spécifie des options supplémentaires, décrites ci-dessous. Plusieurs drapeaux sont spécifiés en les combinant par un OU bit à bit.

Tous les autres champs de la structure pointée par hints doivent contenir soit 0, soit un pointeur nul, selon le cas.

Spécifier hints comme NULL est équivalent à définir ai_socktype et ai_protocol à 0 ; ai_family à AF_UNSPEC; et ai_flags à (AI_V4MAPPED | AI_ADDRCONFIG). (POSIX spécifie des valeurs par défaut différentes pour ai_flags; voir REMARQUES.) node spécifie soit une adresse réseau numérique (pour IPv4, la notation chiffres-et-points telle que prise en charge par inet_aton(3); pour IPv6, le format de chaîne hexadécimal tel que pris en charge par inet_pton(3]), soit un nom d'hôte réseau, dont les adresses réseau sont recherchées et résolues. Si hints.ai_flags contient le drapeau AI_NUMERICHOST , alors node doit être une adresse réseau numérique. Le drapeau AI_NUMERICHOST supprime toute recherche potentiellement longue d'adresse d'hôte réseau.

Si le drapeau AI_PASSIVE est spécifié dans hints.ai_flagset que node est NULL, alors les adresses de socket renvoyées seront adaptées pour le bind(2)d'un socket qui acceptera accept(2) des connexions. L'adresse de socket renvoyée contiendra l'« adresse générique » (INADDR_ANY pour les adresses IPv4, IN6ADDR_ANY_INIT pour les adresses IPv6). L'adresse générique est utilisée par les applications (typiquement des serveurs) qui ont l'intention d'accepter des connexions sur n'importe laquelle des adresses réseau de l'hôte. Si node n'est pas NULL, alors le drapeau AI_PASSIVE est ignoré.

Si le drapeau AI_PASSIVE n'est pas défini dans hints.ai_flags, alors les adresses de socket renvoyées seront adaptées pour une utilisation avec connect(2), sendto(2)ou sendmsg(2). Si node est NULL, alors l'adresse réseau sera définie sur l'adresse de l'interface de bouclage (INADDR_LOOPBACK pour les adresses IPv4, IN6ADDR_LOOPBACK_INIT pour les adresses IPv6) ; cela est utilisé par les applications qui ont l'intention de communiquer avec des pairs s'exécutant sur le même hôte.

service définit le port dans chaque structure d'adresse renvoyée. Si cet argument est un nom de service (voir services(5)), il est traduit en numéro de port correspondant. Cet argument peut également être spécifié sous forme de nombre décimal, qui est simplement converti en binaire. Si service est NULL, alors le numéro de port des adresses de socket renvoyées restera non initialisé. Si AI_NUMERICSERV est spécifié dans hints.ai_flags et que service n'est pas NULL, alors service doit pointer vers une chaîne contenant un numéro de port numérique. Ce drapeau est utilisé pour inhiber l'invocation d'un service de résolution de noms dans les cas où il est connu comme non requis.

Soit node soit service, mais pas les deux, peut être NULL.

La fonction getaddrinfo() alloue et initialise une liste chaînée de structures addrinfo , une pour chaque adresse réseau correspondant à node et service, sous réserve des restrictions imposées par hints, et renvoie un pointeur vers le début de la liste dans res. Les éléments de la liste chaînée sont liés par le champ ai_next .

Il existe plusieurs raisons pour lesquelles la liste chaînée peut avoir plus d'une structure addrinfo , notamment : l'hôte réseau est multi-hébergé, accessible via plusieurs protocoles (par exemple, à la fois AF_INET et AF_INET6) ; ou le même service est disponible via plusieurs types de socket (une adresse SOCK_STREAM et une autre adresse SOCK_DGRAM , par exemple). Normalement, l'application devrait essayer d'utiliser les adresses dans l'ordre dans lequel elles sont renvoyées. La fonction de tri utilisée dans getaddrinfo() est définie dans la RFC 3484 ; l'ordre peut être ajusté pour un système particulier en édifiant /etc/gai.conf (disponible depuis glibc 2.5).

Si hints.ai_flags inclut le drapeau AI_CANONNAME , alors le champ ai_canonname de la première des structures addrinfo de la liste renvoyée est défini pour pointer vers le nom officiel de l'hôte.

Les champs restants de chaque structure addrinfo renvoyée sont initialisés comme suit :

•
Les champs ai_family, ai_socktypeet ai_protocol renvoient les paramètres de création de socket (c'est-à-dire que ces champs ont la même signification que les arguments correspondants de socket(2)). Par exemple, ai_family pourrait renvoyer AF_INET ou AF_INET6; ai_socktype pourrait renvoyer SOCK_DGRAM ou SOCK_STREAM; et ai_protocol renvoie le protocole pour le socket.
Ȃ2 ;
Un pointeur vers l'adresse du socket est placé dans le champ ai_addr , et la taille de l'adresse du socket, en octets, est placée dans le champ ai_addrlen .

Si hints.ai_flags inclut l'indicateur AI_ADDRCONFIG , alors les adresses IPv4 ne sont renvoyées dans la liste pointée par res que si le système local a au moins une adresse IPv4 configurée, et les adresses IPv6 ne sont renvoyées que si le système local a au moins une adresse IPv6 configurée. L'adresse de bouclage n'est pas considérée dans ce cas comme une adresse configurée valide. Cet indicateur est utile sur, par exemple, des systèmes uniquement IPv4, pour s'assurer que getaddrinfo() ne renvoie pas d'adresses de socket IPv6 qui échoueraient toujours dans connect(2) ou bind(2).

Si hints.ai_flags spécifie l'indicateur AI_V4MAPPED , et que hints.ai_family a été spécifié comme AF_INET6, et qu'aucune adresse IPv6 correspondante n'a pu être trouvée, alors renvoyer des adresses IPv6 mappées IPv4 dans la liste pointée par res. Si à la fois AI_V4MAPPED et AI_ALL sont spécifiés dans hints.ai_flags, alors renvoyer à la fois des adresses IPv6 et des adresses IPv6 mappées IPv4 dans la liste pointée par res. AI_ALL est ignoré si AI_V4MAPPED n'est pas également spécifié.

La freeaddrinfo() libère la mémoire qui a été allouée pour la liste chaînée allouée dynamiquement res.

Extensions à getaddrinfo() pour les noms de domaine internationalisés

À partir de glibc 2.3.4, getaddrinfo() a été étendu pour autoriser sélectivement la conversion transparente des noms d'hôte entrants et sortants vers et depuis le format de nom de domaine internationalisé (IDN) (voir RFC 3490, Internationalizing Domain Names in Applications (IDNA)). Quatre nouveaux indicateurs sont définis :

AI_IDN
Si cet indicateur est spécifié, alors le nom de nœud donné dans node est converti au format IDN si nécessaire. L'encodage source est celui de la locale courante.
Si le nom d'entrée contient des caractères non ASCII, alors l'encodage IDN est utilisé. Les parties du nom de nœud (délimitées par des points) qui contiennent des caractères non ASCII sont encodées à l'aide de l'encodage compatible ASCII (ACE) avant d'être passées aux fonctions de résolution de noms.
AI_CANONIDN
Après une recherche de nom réussie, et si l'indicateur AI_CANONNAME a été spécifié, getaddrinfo() renverra le nom canonique du nœud correspondant à la valeur de la structure addrinfo renvoyée. La valeur de retour est une copie exacte de la valeur renvoyée par la fonction de résolution de noms.
Si le nom est encodé à l'aide de ACE, alors il contiendra le préfixe xn-- pour un ou plusieurs composants du nom. Pour convertir ces composants en une forme lisible, l'indicateur AI_CANONIDN peut être passé en plus de AI_CANONNAME. La chaîne résultante est encodée à l'aide de l'encodage de la locale courante.
AI_IDN_ALLOW_UNASSIGNED
AI_IDN_USE_STD3_ASCII_RULES
Définir ces indicateurs activera respectivement les indicateurs IDNA_ALLOW_UNASSIGNED (autoriser les points de code Unicode non assignés) et IDNA_USE_STD3_ASCII_RULES (vérifier la sortie pour s'assurer qu'il s'agit d'un nom d'hôte conforme à STD3) à utiliser dans le traitement IDNA.

VALEUR RENVOYÉE

getaddrinfo() renvoie 0 en cas de succès, ou l'un des codes d'erreur non nuls suivants :

EAI_ADDRFAMILY
L'hôte réseau spécifié n'a aucune adresse réseau dans la famille d'adresses demandée.
EAI_AGAIN
Le serveur de noms a renvoyé une indication d'échec temporaire. Réessayez plus tard.
EAI_BADFLAGS
hints.ai_flags contient des indicateurs invalides ; ou hints.ai_flags incluait AI_CANONNAME et node était NULL.
EAI_FAIL
Le serveur de noms a renvoyé une indication d'échec permanent.
EAI_FAMILY
La famille d'adresses demandée n'est pas prise en charge.
EAI_MEMORY
Mémoire insuffisante.
EAI_NODATA
L'hôte réseau spécifié existe, mais n'a aucune adresse réseau définie.
EAI_NONAME
Le node ou service est inconnu ; ou à la fois node et service sont NULL ; ou AI_NUMERICSERV a été spécifié dans hints.ai_flags et service n'était pas une chaîne représentant un numéro de port numérique.
EAI_SERVICE
Le service demandé n'est pas disponible pour le type de socket demandé. Il peut être disponible via un autre type de socket. Par exemple, cette erreur pourrait survenir si service était « shell » (un service disponible uniquement sur les sockets de flux), et que soit hints.ai_protocol était IPPROTO_UDP, soit hints.ai_socktype était SOCK_DGRAM; ou l'erreur pourrait survenir si service n'était pas NULL, et hints.ai_socktype était SOCK_RAW (un type de socket qui ne prend pas en charge le concept de services).
EAI_SOCKTYPE
Le type de socket demandé n'est pas pris en charge. Cela pourrait survenir, par exemple, si hints.ai_socktype et hints.ai_protocol sont incohérents (p. ex., SOCK_DGRAM et IPPROTO_TCP, respectivement).
EAI_SYSTEM
Autre erreur système ; errno est défini pour indiquer l'erreur.

La gai_strerror() fonction traduit ces codes d'erreur en une chaîne lisible par l'humain, adaptée à la notification d'erreurs.

EXEMPLES

Les programmes suivants démontrent l'utilisation de getaddrinfo(), gai_strerror(), freeaddrinfo(), et getnameinfo(3). Les programmes sont un serveur et un client écho pour les datagrammes UDP.

Programme serveur

#include <netdb.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
#define BUF_SIZE 500
int
main(int argc, char *argv[])
{
    int                      sfd, s;
    char                     buf[BUF_SIZE];
    ssize_t                  nread;
    socklen_t                peer_addrlen;
    struct addrinfo          hints;
    struct addrinfo          *result, *rp;
    struct sockaddr_storage  peer_addr;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s port\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;    /* Autoriser IPv4 ou IPv6 */
    hints.ai_socktype = SOCK_DGRAM; /* Socket de datagramme */
    hints.ai_flags = AI_PASSIVE;    /* Pour l'adresse IP générique */
    hints.ai_protocol = 0;          /* N'importe quel protocole */
    hints.ai_canonname = NULL;
    hints.ai_addr = NULL;
    hints.ai_next = NULL;
    s = getaddrinfo(NULL, argv[1], &hints, &result);
    if (s != 0) {
        fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(s));
        exit(EXIT_FAILURE);
    }
    /* getaddrinfo() renvoie une liste de structures d'adresse.
       Essayez chaque adresse jusqu'à ce que bind(2) réussisse.
       Si socket(2) (ou bind(2)) échoue, nous (fermons le socket
       et) essayons l'adresse suivante.  */
    for (rp = result; rp != NULL; rp = rp->ai_next) {
        sfd = socket(rp->ai_family, rp->ai_socktype,
                     rp->ai_protocol);
        if (sfd == -1)
            continue;
        if (bind(sfd, rp->ai_addr, rp->ai_addrlen) == 0)
            break;                  /* Succès */
        close(sfd);
    }
    freeaddrinfo(result);           /* Plus nécessaire */
    if (rp == NULL) {               /* Aucune adresse n'a réussi */
        fprintf(stderr, "Could not bind\n");
        exit(EXIT_FAILURE);
    }
    /* Lire les datagrammes et les renvoyer à l'émetteur.  */
    for (;;) {
        char host[NI_MAXHOST], service[NI_MAXSERV];
        peer_addrlen = sizeof(peer_addr);
        nread = recvfrom(sfd, buf, BUF_SIZE, 0,
                         (struct sockaddr *) &peer_addr, &peer_addrlen);
        if (nread == -1)
            continue;               /* Ignorer la requête échouée */
        s = getnameinfo((struct sockaddr *) &peer_addr,
                        peer_addrlen, host, NI_MAXHOST,
                        service, NI_MAXSERV, NI_NUMERICSERV);
        if (s == 0)
            printf("Received %zd bytes from %s:%s\n",
                   nread, host, service);
        else
            fprintf(stderr, "getnameinfo: %s\n", gai_strerror(s));
        if (sendto(sfd, buf, nread, 0, (struct sockaddr *) &peer_addr,
                   peer_addrlen) != nread)
        {
            fprintf(stderr, "Error sending response\n");
        }
    }
}

Programme client

#include <netdb.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
#define BUF_SIZE 500
int
main(int argc, char *argv[])
{
    int              sfd, s;
    char             buf[BUF_SIZE];
    size_t           size;
    ssize_t          nread;
    struct addrinfo  hints;
    struct addrinfo  *result, *rp;
    if (argc < 3) {
        fprintf(stderr, "Usage: %s host port msg...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Obtenir les adresses correspondant à l'hôte/port.  */
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;    /* Autoriser IPv4 ou IPv6 */
    hints.ai_socktype = SOCK_DGRAM; /* Socket de datagramme */
    hints.ai_flags = 0;
    hints.ai_protocol = 0;          /* N'importe quel protocole */
    s = getaddrinfo(argv[1], argv[2], &hints, &result);
    if (s != 0) {
        fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(s));
        exit(EXIT_FAILURE);
    }
    /* getaddrinfo() renvoie une liste de structures d'adresse.
       Essayer chaque adresse jusqu'à ce que connect(2) réussisse.
       Si socket(2) (ou connect(2)) échoue, nous (fermons le socket
       et) essayons l'adresse suivante.  */
    for (rp = result; rp != NULL; rp = rp->ai_next) {
        sfd = socket(rp->ai_family, rp->ai_socktype,
                     rp->ai_protocol);
        if (sfd == -1)
            continue;
        if (connect(sfd, rp->ai_addr, rp->ai_addrlen) != -1)
            break;                  /* Succès */
        close(sfd);
    }
    freeaddrinfo(result);           /* Plus nécessaire */
    if (rp == NULL) {               /* Aucune adresse n'a réussi */
        fprintf(stderr, "Could not connect\n");
        exit(EXIT_FAILURE);
    }
    /* Envoyer les arguments restants de la ligne de commande sous forme
       de datagrammes séparés, et lire les réponses du serveur.  */
    for (size_t j = 3; j < argc; j++) {
        size = strlen(argv[j]) + 1;
                /* +1 pour l'octet nul de terminaison */
        if (size > BUF_SIZE) {
            fprintf(stderr,
                    "Ignoring long message in argument %zu\n", j);
            continue;
        }
        if (write(sfd, argv[j], size) != size) {
            fprintf(stderr, "partial/failed write\n");
            exit(EXIT_FAILURE);
        }
        nread = read(sfd, buf, BUF_SIZE);
        if (nread == -1) {
            perror("read");
            exit(EXIT_FAILURE);
        }
        printf("Received %zd bytes: %s\n", nread, buf);
    }
    exit(EXIT_SUCCESS);
}
