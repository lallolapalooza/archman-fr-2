NOM

getc_putc - programme pour tester les performances du disque dur.

SYNTAXE

getc_putc [-d répertoire] [-s taille(KiB)] [-m nom-machine] [-u uid-à-utiliser:gid-à-utiliser] [-g gid-à-utiliser]

DESCRIPTION

Cette page de manuel documente brièvement le programme getc_putc.

C'est un simple complément au benchmark bonnie++. Il est utilisé pour tester diverses façons de faire des E/S un octet à la fois. Généralement, vous n'avez pas besoin d'en faire suffisamment pour que cela ait un impact significatif sur les performances, quelle que soit la méthode. Mais parfois, c'est nécessaire (par exemple, lors de l'analyse des E/S d'un terminal, puis du lancement d'un autre processus qui prendra en charge toutes les E/S, comme un simple shell).

Les réels avantages de ceci sont d'aider à régler certaines disputes sur les performances de telles choses, et d'éduquer les novices sur à quel point les E/S par octet sont mauvaises.

OPTIONS

Pour getc_putc, chaque option est de la forme d'un trait d'union suivi d'une lettre, puis le paramètre suivant contient la valeur.

-d
le répertoire à utiliser pour les tests.
-s
la taille du fichier pour les performances des E/S par octet, mesurée en kilooctets. NB : Vous pouvez spécifier la taille en mégaoctets en ajoutant 'm' à la fin du nombre.

La valeur par défaut pour ce test est de tester avec un fichier de 512 MiB. Sur ce fichier, seule 1/64ème sera utilisée pour les appels système de write() et read() (tout le reste prend trop de temps).

-m
nom de la machine - à des fins d'affichage uniquement.
-u
ID utilisateur à utiliser. Lorsque vous exécutez en tant que root, spécifiez l'UID à utiliser pour les tests. Il n'est pas recommandé d'utiliser root, donc si vous voulez vraiment exécuter en tant que root, utilisez -u root. De plus, si vous voulez spécifier le groupe à utiliser, utilisez le format utilisateur:groupe. Si vous spécifiez un utilisateur par nom mais aucun groupe, le groupe principal de cet utilisateur sera choisi. Si vous spécifiez un utilisateur par numéro et aucun groupe, le groupe sera nogroup.
-g
ID de groupe à utiliser. Identique à l'utilisation de :groupe pour le paramètre -u, juste une manière différente de le spécifier pour la compatibilité avec d'autres programmes.
-q
mode silencieux. Si spécifié, certains messages d'information supplémentaires seront supprimés. De plus, les données CSV seront la seule sortie sur la sortie standard et les données texte seront sur la sortie d'erreur standard. Cela signifie que vous pouvez exécuter getc_putc -q >> fichier.csv pour enregistrer vos données CSV.

SORTIE

La sortie principale est en texte brut sur 80 colonnes, conçue pour bien s'insérer lorsqu'elle est collée dans un e-mail et qui fonctionnera bien avec les afficheurs Braille.

Le deuxième type de sortie est CSV (Comma Separated Values - Valeurs séparées par des virgules). Cela peut être facilement importé dans n'importe quel logiciel de tableur ou de base de données.

Pour chaque test, le résultat est une vitesse en KiB/s. Je n'affiche pas le temps CPU car il représente vraisemblablement 99% de la puissance d'un seul CPU (ou quelque chose de très proche).

SIGNaux

Gère SIGINT et effectue un nettoyage (ce qui peut prendre un certain temps). Un second SIGINT ou un SIGQUIT le fera mourir immédiatement.

SIGXCPU et SIGXFSZ agissent comme SIGINT.

Ignore SIGHUP.
