DESCRIPTIO

N

La fonction getopt() analyse les arguments de la ligne de commande. Ses arguments argc et argv sont le nombre d'arguments et le tableau tels que transmis à la fonction main() lors de l'invocation du programme. Un élément de argv qui commence par « - » (et qui n'est pas exactement « - » ou « -- ») est un élément d'option. Les caractères de cet élément (à part le « - » initial) sont des caractères d'option. Si getopt() est appelé à plusieurs reprises, il renvoie successivement chacun des caractères d'option de chacun des éléments

d'option.

La variable optind est l'index de l'élément suivant à traiter dans argv. Le système initialise cette valeur à 1. L'appelant peut la réinitialiser à 1 pour relancer l'analyse du même argv, ou lors de l'analyse d'un nouveau vecteur

d'arguments.

Si getopt() trouve un autre caractère d'option, il renvoie ce caractère, en mettant à jour la variable externe optind et une variable statique nextchar afin que le prochain appel à getopt() puisse reprendre l'analyse avec le caractère d'option suivant ou l'élément argv

suivant.

S'il n'y a plus de caractères d'option, getopt() renvoie -1. Alors optind est l'index dans argv du premier élément argv qui n'est pas une

option.

optstring est une chaîne contenant les caractères d'option autorisés. Un caractère d'option autorisé est tout caractère ascii(7) visible sur un octet (pour lequel isgraph(3) renverrait une valeur non nulle) qui n'est ni « - », ni « : », ni « ; ». Si un tel caractère est suivi d'un deux-points, l'option requiert un argument, donc getopt() place un pointeur vers le texte suivant dans le même élément argv, ou le texte du élément argv suivant, dans optarg. Deux deux-points signifient qu'une option prend un argument optionnel ; s'il y a du texte dans l'élément argv courant (c'est-à-dire dans le même mot que le nom de l'option lui-même, par exemple « -oarg »), alors il est renvoyé dans optarg, sinon optarg est défini à zéro. Il s'agit d'une extension GNU. Si optstring contient W suivi d'un point-virgule, alors -W foo est traité comme l'option longue --foo. (L'option -W est réservée par POSIX.2 pour les extensions d'implémentation.) Ce comportement est une extension GNU, non disponible avec les bibliothèques antérieures à glibc

2.

Par défaut, getopt() permute le contenu de argv au fur et à mesure de son analyse, de sorte qu'à la fin tous les non-options soient à la fin. Deux autres modes d'analyse sont également implémentés. Si le premier caractère de optstring est « + » ou si la variable d'environnement POSIXLY_CORRECT est définie, alors le traitement des options s'arrête dès qu'un argument non-option est rencontré. Si « + » n'est pas le premier caractère de optstring, il est traité comme une option normale. Si le comportement POSIXLY_CORRECT est requis dans ce cas, optstring contiendra deux symboles « + ». Si le premier caractère de optstring est « - », alors chaque élément argv non-option est traité comme s'il s'agissait de l'argument d'une option avec le code de caractère 1. (Ceci est utilisé par des programmes écrits pour s'attendre à des options et d'autres éléments argv dans n'importe quel ordre et qui se soucient de l'ordre des deux.) L'argument spécial « -- » force la fin de l'analyse des options quel que soit le mode

d'analyse.

Lors du traitement de la liste d'options, getopt() peut détecter deux types d'erreurs : (1) un caractère d'option qui n'était pas spécifié dans optstring et (2) un argument d'option manquant (c'est-à-dire une option à la fin de la ligne de commande sans l'argument attendu). Ces erreurs sont gérées et signalées comme suit

:
•
Par défaut, getopt() affiche un message d'erreur sur la sortie d'erreur standard, place le caractère d'option erroné dans optopt, et renvoie « ? » comme résultat de la
fonction.
•
Si l'appelant a défini la variable globale opterr à zéro, alors getopt() n'affiche pas de message d'erreur. L'appelant peut déterminer qu'une erreur s'est produite en testant si la valeur de retour de la fonction est « ? ». (Par défaut, opterr a une valeur non nulle.
)
•
Si le premier caractère (après un éventuel « + » ou « - » optionnel décrit ci-dessus) de optstring est un deux-points (« : »), alors getopt() n'affiche pas non plus de message d'erreur. De plus, il renvoie « : » au lieu de « ? » pour indi
quer un argument d'option manquant. Cela permet à l'appelan
t de distinguer les deux types d'erreurs différents.

DESCRIPTION

The getopt() function is used to parse the command-line options.

argc and argv are the argument count and argument vector respectively, as provided by the caller (typically from `main`).

optstring is a string which specifies the option characters the function should recognize. If a character is followed by a colon (':'), then that option requires an argument, which should be placed immediately after the option character or in the next argument. This argument is stored in the external variable optarg.

The order in which options are scanned is determined by the environment variable POSIXLY_CORRECT (see ENVIRONMENT). If POSIXLY_CORRECT is set, or if the first character of optstring is a '+', then option processing stops as soon as the first nonoption argument is encountered. If the first character of optstring is a '-', then option processing stops as soon as a nonoption argument is encountered, but any remaining arguments are still processed by future calls with the same optstring.

If the first character of optstring is not a '-', and nonoption arguments are being processed, getopt() permutes argv by moving all nonoption arguments to the end of the array. It returns the first nonoption argument when it is encountered.

Subsequent calls to getopt() return the next option character or diagnostic, and the external variable optind is updated to the index of the next argument to be processed.

When getopt() encounters an option character that is valid, it returns the option character. If the option character requires an argument, the next argument in argv is stored in optarg. If the option character does not require an argument, optarg is NULL.

When getopt() encounters an option that is not recognized, or when an option that requires an argument is missing an argument, it returns '?'.

If optstring begins with a colon (':'), then the error processing is disabled. In this mode, when an unrecognized option is encountered, getopt() returns ':' instead of '?'. When an option requiring an argument is missing an argument, getopt() returns ':' instead of '?'.

When all options have been processed, getopt() returns -1, and optind is set to the index of the first nonoption argument, or to `argc` if there have been no nonoption arguments.

The getopt_long() and getopt_long_only() functions are extensions that permit the parsing of options specified in the GNU style (long options, like `--output`).

The longopts argument to getopt_long() and getopt_long_only() is the address of the first element of an array of `struct option`. The last element of the array must be a zero-valued element.

struct option {
    const char *name;       // The name of the long option without the leading
                            // two hyphens.
    int         has_arg;    // Indicates whether the option takes an argument.
                            // Must be no_argument, required_argument, or
                            // optional_argument.
    int        *flag;       // If not NULL, the integer pointed to by flag is
                            // set to val when the option is found, and the
                            // option returning a value is 0.
    int         val;        // The return value to return from the function.
                            // If flag is NULL, this is the return value.
                            // If flag is not NULL, this is the value to set
                            // flag to.
};

The has_arg field can be one of the following:

no_argument
The option does not take an argument.
required_argument
The option requires an argument.
optional_argument
The option takes an optional argument.

The getopt_long_only() function is identical to getopt_long() except that it also recognizes long options prefixed with a single hyphen.

The optstring parameter is still parsed for short options. The long options are described by the longopts array. If an option is found in both the short and long forms, the short form is preferred.

If flag is NULL, getopt_long() and getopt_long_only() return the value of val for the option. If flag is not NULL, they return 0, and set the integer pointed to by flag to val.

The behavior of getopt_long() and getopt_long_only() when encountering an unrecognized option or a missing argument is the same as getopt(). However, if the GNU extensions are enabled, they also return '?' for an ambiguous match.

RETURN VALUE

The return value depends on the first character in optstring: if it is ':', then ':' is returned; otherwise '?' is returned.

getopt_long() and getopt_long_only() also return the option character when a short option is recognized. For a long option, they return val if flag is NULL, and 0 otherwise. Error and -1 returns are the same as for getopt(), plus '?' for an ambiguous match or an extraneous parameter.

HISTORY

getopt()
POSIX.1-2001, and POSIX.2.

On some older implementations, getopt() was declared in <stdio.h>. SUSv1 permitted the declaration to appear in either <unistd.h> or <stdio.h>. POSIX.1-1996 marked the use of <stdio.h> for this purpose as LEGACY. POSIX.1-2001 does not require the declaration to appear in <stdio.h>.

Very old versions of glibc were affected by a _PID_GNU_nonoption_argv_flags_ environment variable.

NOTES

A program that scans multiple argument vectors, or rescans the same vector more than once, and wants to make use of GNU extensions such as '+' and '-' at the start of optstring, or changes the value of POSIXLY_CORRECT between scans, must reinitialize getopt() by resetting optind to 0, rather than the traditional value of 1. (Resetting to 0 forces the invocation of an internal initialization routine that rechecks POSIXLY_CORRECT and checks for GNU extensions in optstring.)

Command-line arguments are parsed in strict order meaning that an option requiring an argument will consume the next argument, regardless of whether that argument is the correctly specified option argument or simply the next option (in the scenario the user mis-specifies the command line). For example, if optstring is specified as "1n:" and the user specifies the command line arguments incorrectly as prog -n -1, the -n option will be given the optarg value "-1", and the -1 option will be considered to have not been specified.

EXAMPLES

getopt()

The following trivial example program uses getopt() to handle two program options: -n, with no associated value; and -t val, which expects an associated value.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int flags, opt;
    int nsecs, tfnd;
    nsecs = 0;
    tfnd = 0;
    flags = 0;
    while ((opt = getopt(argc, argv, "nt:")) != -1) {
        switch (opt) {
        case 'n':
            flags = 1;
            break;
        case 't':
            nsecs = atoi(optarg);
            tfnd = 1;
            break;
        default: /* '?' */
            fprintf(stderr, "Usage: %s [-t nsecs] [-n] name\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }
    }
    printf("flags=%d; tfnd=%d; nsecs=%d; optind=%d\n",
           flags, tfnd, nsecs, optind);
    if (optind >= argc) {
        fprintf(stderr, "Expected argument after options\n");
        exit(EXIT_FAILURE);
    }
    printf("name argument = %s\n", argv[optind]);
    /* Other code omitted */
    exit(EXIT_SUCCESS);
}

getopt_long()

The following example program illustrates the use of getopt_long() with most of its features.

#include <getopt.h>
#include <stdio.h>     /* for printf */
#include <stdlib.h>    /* for exit */
int
main(int argc, char *argv[])
{
    int c;
    int digit_optind = 0;
    while (1) {
        int this_option_optind = optind ? optind : 1;
        int option_index = 0;
        static struct option long_options[] = {
            {"add",     required_argument, 0,  0 },
            {"append",  no_argument,       0,  0 },
            {"delete",  required_argument, 0,  0 },
            {"verbose", no_argument,       0,  0 },
            {"create",  required_argument, 0, 'c'},
            {"file",    required_argument, 0,  0 },
            {0,         0,                 0,  0 }
        };
        c = getopt_long(argc, argv, "abc:d:012",
                        long_options, &option_index);
        if (c == -1)
            break;
        switch (c) {
        case 0:
            printf("option %s", long_options[option_index].name);
            if (optarg)
                printf(" with arg %s", optarg);
            printf("\n");
            break;
        case '0':
        case '1':
        case '2':
            if (digit_optind != 0 && digit_optind != this_option_optind)
              printf("digits occur in two different argv-elements.\n");
            digit_optind = this_option_optind;
            printf("option %c\n", c);
            break;
        case 'a':
            printf("option a\n");
            break;
        case 'b':
            printf("option b\n");
            break;
        case 'c':
            printf("option c with value '%s'\n", optarg);
            break;
        case 'd':
            printf("option d with value '%s'\n", optarg);
            break;
        case '?':
            break;
        default:
            printf("?? getopt returned character code 0%o ??\n", c);
        }
    }
    if (optind < argc) {
        printf("non-option ARGV-elements: ");
        while (optind < argc)
            printf("%s ", argv[optind++]);
        printf("\n");
    }
    exit(EXIT_SUCCESS);
}
