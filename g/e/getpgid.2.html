setpgid(2) Manuel des appels système setpgid(2)

NOM

setpgid, getpgid, setpgrp, getpgrp - définir/obtenir le groupe de processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <unistd.h>
int setpgid(pid_t pid, pid_t pgid);
pid_t getpgid(pid_t pid);
pid_t getpgrp(void);                            /* Version POSIX.1 */
[[deprecated]] pid_t getpgrp(pid_t pid);        /* Version BSD */
int setpgrp(void);                              /* Version System V */
[[deprecated]] int setpgrp(pid_t pid, pid_t pgid);  /* Version BSD */
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getpgid() :

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L

setpgrp() (POSIX.1) :

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE

setpgrp() (BSD), getpgrp() (BSD) :

    [Ces fonctions ne sont disponibles que dans les versions antérieures à glibc 2.19]
    _BSD_SOURCE &&
        ! (_POSIX_SOURCE || _POSIX_C_SOURCE || _XOPEN_SOURCE
            || _GNU_SOURCE || _SVID_SOURCE)

DESCRIPTION

Toutes ces interfaces sont disponibles sous Linux et sont utilisées pour obtenir et définir l'identifiant de groupe de processus (PGID) d'un processus. Les méthodes préférées, spécifiées par POSIX.1, pour faire cela sont : getpgrp(void), pour récupérer le PGID du processus appelant ; et setpgid(), pour définir le PGID d'un processus.

setpgid() définit le PGID du processus spécifié par pid à pgid. Si pid est zéro, l'identifiant de processus du processus appelant est utilisé. Si pgid est zéro, le PGID du processus spécifié par pid est rendu identique à son identifiant de processus. Si setpgid() est utilisé pour déplacer un processus d'un groupe de processus à un autre (comme le font certains interpréteurs de commandes lors de la création de pipelines), les deux groupes de processus doivent faire partie de la même session (voir setsid(2) et credentials(7)). Dans ce cas, le pgid spécifie un groupe de processus existant à rejoindre et l'identifiant de session de ce groupe doit correspondre à l'identifiant de session du processus qui le rejoint.

La version POSIX.1 de getpgrp(), qui ne prend aucun argument, renvoie le PGID du processus appelant.

getpgid() renvoie le PGID du processus spécifié par pid. Si pid est zéro, l'identifiant de processus du processus appelant est utilisé. (Récupérer le PGID d'un processus autre que l'appelant est rarement nécessaire, et la fonction POSIX.1 getpgrp() est préférée pour cette tâche.)

La fonction setpgrp() de style System V, qui ne prend aucun argument, est équivalente à setpgid(0, 0).

L'appel setpgrp() spécifique à BSD, qui prend les arguments pid et pgid, est une fonction enveloppe qui appelle


setpgid(pid, pgid)

Depuis glibc 2.19, la fonction setpgrp() spécifique à BSD n'est plus exposée par <unistd.h>; les appels doivent être remplacés par l'appel setpgid() montré ci-dessus.

L'appel getpgrp() spécifique à BSD, qui prend un seul argument pid , est une fonction enveloppe qui appelle


getpgid(pid)

Depuis glibc 2.19, la fonction getpgrp() spécifique à BSD n'est plus exposée par <unistd.h>; les appels doivent être remplacés par des appels à la fonction POSIX.1 getpgrp() qui ne prend aucun argument (si l'intention est d'obtenir le PGID de l'appelant), ou par l'appel getpgid() montré ci-dessus.

VALEUR RENVOYÉE

En cas de succès, setpgid() et setpgrp() renvoient zéro. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

La fonction POSIX.1 getpgrp() renvoie toujours le PGID de l'appelant.

getpgid(), et la fonction getpgrp() spécifique à BSD renvoient un groupe de processus en cas de succès. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EACCES
Une tentative a été faite de changer l'identifiant de groupe de processus de l'un des enfants du processus appelant et l'enfant avait déjà effectué un execve(2) (setpgid(), setpgrp()).
EINVAL
pgid est inférieur à 0 (setpgid(), setpgrp()).
EPERM
Une tentative a été faite de déplacer un processus dans un groupe de processus d'une session différente, ou de changer l'identifiant de groupe de processus de l'un des enfants du processus appelant alors que l'enfant se trouvait dans une session différente, ou de changer l'identifiant de groupe de processus d'un chef de session (setpgid(), setpgrp()).
EPERM
Le groupe de processus cible n'existe pas. (setpgid(), setpgrp()).
ESRCH
Pour getpgid() : pid ne correspond à aucun processus. Pour setpgid() : pid n'est ni le processus appelant ni un enfant du processus appelant.

NOTES

Un enfant créé via fork(2) hérite de l'identifiant de groupe de processus de son parent. Le PGID est préservé à travers un execve(2).

Chaque groupe de processus est membre d'une session et chaque processus est membre de la session dont son groupe de processus est membre. (Voir credentials(7).)

Une session peut avoir un terminal de contrôle. À tout moment, un (et seulement un) des groupes de processus de la session peut être le groupe de processus avant-plan du terminal ; les groupes de processus restants sont en arrière-plan. Si un signal est généré depuis le terminal (par exemple, en appuyant sur la touche d'interruption pour générer SIGINT), ce signal est envoyé au groupe de processus avant-plan. (Voir termios(3) pour une description des caractères qui génèrent des signaux.) Seul le groupe de processus avant-plan peut read(2) depuis le terminal ; si un groupe de processus d'arrière-plan essaie de read(2) depuis le terminal, un signal SIGTTIN lui est envoyé, ce qui le suspend. Les fonctions tcgetpgrp(3) et tcsetpgrp(3) sont utilisées pour obtenir/définir le groupe de processus avant-plan du terminal de contrôle.

Les appels setpgid() et getpgrp() sont utilisés par des programmes tels que bash(1) pour créer des groupes de processus afin de mettre en œuvre le contrôle des tâches de l'interpréteur de commandes.

Si la terminaison d'un processus cause l'orphelinage d'un groupe de processus, et si un membre du groupe de processus nouvellement orphelin est arrêté, puis un signal SIGHUP suivi d'un signal SIGCONT sera envoyé à chaque processus du groupe de processus nouvellement orphelin. Un groupe de processus orphelin est un groupe dont le parent de chaque membre est soit lui-même membre du groupe de processus, soit membre d'un groupe de processus dans une autre session (voir aussi credentials(7)).

VOIR AUSSI

getuid(2), setsid(2), tcgetpgrp(3), tcsetpgrp(3), termios(3), credentials(7)
