DESCRIPTIO

N

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications devraient plutôt utiliser getaddrinfo(3), getnameinfo(3) et gai_strerro

r(3).

La fonction sethostent() spécifie que, si stayopen est vrai (1), un socket TCP connecté devrait être utilisé pour les requêtes vers le serveur de noms et que la connexion devrait rester ouverte pendant les requêtes successives. Sinon, les requêtes vers le serveur de noms utiliseront des datagrammes

UDP.

La fonction endhostent() met fin à l'utilisation d'une connexion TCP pour les requêtes vers le serveur de

noms.

La fonction gethostbyname() retourne une structure de type hostent pour l'hôte donné name. Ici, name est soit un nom d'hôte soit une adresse IPv4 en notation standard à points (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent struct in_addr dans le champ h_addr_list[0] de la structure hostent retournée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias auquel HOSTALIASES pointe sera d'abord recherché pour name (voir hostname(7) pour le format du fichier). Le domaine courant et ses parents sont recherchés sauf si name se termine par un

point.

La fonction gethostbyaddr() retourne une structure de type hostent pour l'adresse d'hôte donnée addr de taille size et de type d'adresse type. Les types d'adresse valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument d'adresse d'hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple une struct in_addr * (probablement obtenue via un appel à inet_addr(3)) pour le type d'adresse AF_INET

.

La fonction (obsolète) herror() affiche le message d'erreur associé à la valeur courante de h_errno sur stderr

.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et retourne la chaîne de message

correspondante.

Les requêtes de nom de domaine effectuées par gethostbyname() et gethostbyaddr() reposent sur les sources configurées par le Name Service Switch (nsswitch.conf(5)) ou un serveur de noms local (named(8)). L'action par défaut est d'interroger les sources configurées par le Name Service Switch (nsswitch.conf(5)), et à défaut, un serveur de noms local (named(8))

.

Historiqu

e

Le fichier nsswitch.conf(5) est la méthode moderne de contrôle de l'ordre des recherches

d'hôtes.

Dans glibc 2.4 et antérieures, le mot-clé order était utilisé pour contrôler l'ordre des recherches d'hôtes tel que défini dans /etc/host.conf (host.conf(5))

.

NOM

gethostbyname, gethostbyname_r, gethostbyname2, gethostbyname2_r — obtention des informations d'un hôte par nom

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <netdb.h>

struct hostent *gethostbyname(const char *name);

int gethostbyname_r(const char *name, struct hostent *ret, char *buf, size_t bufsize, struct hostent **result, int *h_errnop);

struct hostent *gethostbyname2(const char *name, int af);

int gethostbyname2_r(const char *name, int af, struct hostent *ret, char *buf, size_t bufsize, struct hostent **result, int *h_errnop);

DESCRIPTION

Ces fonctions sont utilisées pour obtenir des informations sur un hôte à partir de son nom d'hôte.

Le nom d'hôte est spécifié par l'argument name. La famille d'adresses est spécifiée par l'argument af dans les fonctions gethostbyname2 et gethostbyname2_r. Les valeurs possibles pour af sont AF_INET et AF_INET6.

Les fonctions non suffixées par _r retournent un pointeur vers une structure hostent qui contient les informations sur l'hôte. Cette structure est définie dans le fichier d'en-tête <netdb.h> comme suit :

struct hostent {
    char  *h_name;       /* nom canonique de l'hôte */
    char  **h_aliases;   /* liste des alias, terminée par NULL */
    int   h_addrtype;    /* type de l'adresse de l'hôte (ex. AF_INET) */
    int   h_length;      /* longueur de l'adresse en octets */
    char  **h_addr_list; /* liste des adresses pour l'hôte, terminée par NULL */
};

Les fonctions suffixées par _r sont des versions réentrantes. Elles retournent 0 en cas de succès et un numéro d'erreur non nul en cas d'échec. Elles utilisent un tampon fourni par l'appelant (buf, de taille bufsize) pour stocker les données nécessaires. Le pointeur result sera défini pour pointer vers la structure hostent remplie en cas de succès, ou sera mis à NULL en cas d'erreur ou si aucune entrée n'est trouvée. Le numéro d'erreur est stocké dans la variable pointée par h_errnop.

La fonction gethostbyname2 permet de spécifier la famille d'adresses, tandis que gethostbyname essaie de deviner la famille d'adresses. Dans la pratique, gethostbyname est souvent implémentée en appelant gethostbyname2 avec AF_INET.

Les fonctions gethostbyname et gethostbyname2 peuvent retourner des pointeurs vers des données statiques. Ces données peuvent être écrasées par des appels ultérieurs. La copie de la structure hostent ne suffit pas, car elle contient des pointeurs ; une copie profonde est requise.

La fonction gethostbyname ne reconnaît pas les composants d'une chaîne d'adresse IPv4 en pointillé exprimés en hexadécimal.

Les fonctions gethostbyname et gethostbyaddr sont obsolètes. Il est recommandé d'utiliser getaddrinfo(3) et getnameinfo(3) à la place.

VALEUR DE RETOUR

Les fonctions gethostbyname et gethostbyname2 retournent un pointeur vers une structure hostent en cas de succès, ou un pointeur NULL en cas d'erreur. La variable globale h_errno est définie pour indiquer la raison de l'erreur.

Les fonctions réentrantes gethostbyname_r et gethostbyname2_r retournent 0 en cas de succès, et un numéro d'erreur non nul en cas d'échec. Le pointeur result est mis à NULL en cas d'erreur ou si aucune entrée n'est trouvée. La variable pointée par h_errnop contient le numéro d'erreur.

ERREURS

La variable h_errno peut avoir les valeurs suivantes :

HOST_NOT_FOUND
L'hôte spécifié est inconnu.
NO_DATA
Le nom demandé est valide mais n'a pas d'adresse IP. Un autre type de requête au serveur de noms pour ce domaine peut renvoyer une réponse. La constante NO_ADDRESS est un synonyme de NO_DATA.
NO_RECOVERY
Une erreur non récupérable du serveur de noms s'est produite.
TRY_AGAIN
Une erreur temporaire s'est produite sur un serveur de noms faisant autorité. Réessayez plus tard.

NOTES

Les fonctions gethostbyname() et gethostbyaddr() peuvent retourner des pointeurs vers des données statiques, qui peuvent être écrasées par des appels ultérieurs. La copie de la structure hostent ne suffit pas, car elle contient des pointeurs ; une copie profonde est requise.

Dans l'implémentation BSD d'origine, l'argument size de gethostbyname() était un int. La norme SUSv2 est boguée et déclare l'argument size de gethostbyaddr() comme étant de type size_t. (C'est faux, car il doit être de type int, et size_t ne l'est pas. POSIX.1-2001 en fait un socklen_t, ce qui est correct.) Voir également accept(2).

Le prototype BSD pour gethostbyaddr() utilise const char * pour le premier argument.

Extension System V/POSIX

POSIX exige l'appel gethostent(), qui doit renvoyer l'entrée suivante dans la base de données des hôtes. Lorsque vous utilisez DNS/BIND, cela n'a pas beaucoup de sens, mais cela peut être raisonnable si la base de données des hôtes est un fichier qui peut être lu ligne par ligne. Sur de nombreux systèmes, une routine de ce nom lit le fichier /etc/hosts. Elle peut n'être disponible que lorsque la bibliothèque a été compilée sans prise en charge DNS. La version glibc ignorera les entrées ipv6. Cette fonction n'est pas réentrante, et glibc ajoute une version réentrante gethostent_r().

Extensions GNU

glibc2 dispose également de gethostbyname2() qui fonctionne comme gethostbyname(), mais permet de spécifier la famille d'adresses à laquelle l'adresse doit appartenir.

glibc2 dispose également de versions réentrantes gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), et gethostbyname2_r(). L'appelant fournit une structure hostent ret qui sera remplie en cas de succès, et un tampon de travail temporaire buf de taille bufsize. Après l'appel, result pointera vers le résultat en cas de succès. En cas d'erreur ou si aucune entrée n'est trouvée, result sera NULL. Les fonctions retournent 0 en cas de succès et un numéro d'erreur non nul en cas d'échec. En plus des erreurs retournées par les versions non réentrantes de ces fonctions, si buf est trop petit, les fonctions retourneront ERANGE, et l'appel doit être retenté avec un tampon plus grand. La variable globale h_errno n'est pas modifiée, mais l'adresse d'une variable dans laquelle stocker les numéros d'erreur est passée dans h_errnop.

BOGUES

gethostbyname() ne reconnaît pas les composants d'une chaîne d'adresse IPv4 en pointillé exprimés en hexadécimal.
