getutent(3) Manuel des fonctions de bibliothèque getutent(3)

NOM

getutent, getutid, getutline, pututline, setutent, endutent, utmpname — accéder aux entrées du fichier utmp

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPTION

Les nouvelles applications devraient utiliser les fonctions de la version "utmpx" spécifiée par POSIX.1 ; voir NORMES.

utmpname() définit le chemin du fichier au format utmp auquel les autres fonctions utmp doivent accéder. Si utmpname() n'est pas utilisé pour définir le chemin avant que les autres fonctions ne soient utilisées, elles supposent _PATH_UTMP, tel que défini dans <paths.h>.

setutent() rembobine le pointeur de fichier au début du fichier utmp. C'est généralement une bonne idée de l'appeler avant toute autre fonction.

endutent() ferme le fichier utmp. Il doit être appelé lorsque le code utilisateur a fini d'accéder au fichier avec les autres fonctions.

getutent() lit une ligne depuis la position actuelle du fichier dans le fichier utmp. Il renvoie un pointeur vers une structure contenant les champs de la ligne. La définition de cette structure est montrée dans utmp(5).

getutid() recherche en avant depuis la position actuelle du fichier dans le fichier utmp en fonction de ut. Si ut->ut_type est l'un de RUN_LVL, BOOT_TIME, NEW_TIME ou OLD_TIME, getutid() trouvera la première entrée dont le champ ut_type correspond à ut->ut_type. Si ut->ut_type est l'un de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS ou DEAD_PROCESS, getutid() trouvera la première entrée dont le champ ut_id correspond à ut->ut_id.

getutline() recherche en avant depuis la position actuelle du fichier dans le fichier utmp. Il parcourt les entrées dont ut_type est USER_PROCESS ou LOGIN_PROCESS et renvoie la première dont le champ ut_line correspond à ut->ut_line.

pututline() écrit la structure utmp ut dans le fichier utmp. Il utilise getutid() pour rechercher l'emplacement approprié dans le fichier pour insérer la nouvelle entrée. S'il ne parvient pas à trouver un emplacement approprié pour ut, pututline() ajoutera la nouvelle entrée à la fin du fichier.

VALEUR RENVOYÉE

getutent(), getutid() et getutline() renvoient un pointeur vers une struct utmp en cas de succès, et NULL en cas d'échec (ce qui inclut le cas "enregistrement introuvable"). Cette struct utmp est allouée dans un stockage statique et peut être écrasée par des appels ultérieurs.

En cas de succès, pututline() renvoie ut ; en cas d'échec, il renvoie NULL.

utmpname() renvoie 0 si le nouveau nom a été stocké avec succès, ou -1 en cas d'échec.

En cas d'échec, ces fonctions définissent errno pour indiquer l'erreur.

ERREURS

ENOMEM
Espace insuffisant.
ESRCH
Enregistrement introuvable.

setutent(), pututline() et les fonctions getut*() peuvent également échouer pour les raisons décrites dans open(2).

FICHIERS

/var/run/utmp
base de données des utilisateurs actuellement connectés
/var/log/wtmp
base de données des connexions utilisateur passées

Dans le tableau ci-dessus, utent dans race:utent signifie que si l'une des fonctions setutent(), getutent(), getutid(), getutline(), pututline(), utmpname(), ou endutent() est utilisée en parallèle dans différents threads d'un programme, des courses de données peuvent se produire.

NORMES

Aucune.

HISTORIQUE

XPG2, SVr4.

Dans XPG2 et SVID 2, la fonction pututline() est documentée comme renvoyant void, et c'est ce qu'elle fait sur de nombreux systèmes (AIX, HP-UX). HP-UX introduit une nouvelle fonction _pututline() avec le prototype donné ci-dessus pour pututline().

Toutes ces fonctions sont maintenant obsolètes sur les systèmes non Linux. POSIX.1-2001 et POSIX.1-2008, suivant SUSv1, n'ont aucune de ces fonctions, mais utilisent à la place

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Ces fonctions sont fournies par glibc et remplissent la même tâche que leurs équivalents sans le "x", mais utilisent struct utmpx, définie sous Linux pour être identique à struct utmp. Pour complétude, glibc fournit également utmpxname(), bien que cette fonction ne soit pas spécifiée par POSIX.1.

Sur certains autres systèmes, la structure utmpx est un superset de la structure utmp, avec des champs supplémentaires, et des versions plus grandes des champs existants, et des fichiers parallèles sont maintenus, souvent /var/*/utmpx et /var/*/wtmpx.

Linux glibc, en revanche, n'utilise pas de fichier utmpx parallèle car sa structure utmp est déjà suffisamment grande. Les fonctions "x" listées ci-dessus sont simplement des alias pour leurs homologues sans le "x" (par exemple, getutxent() est un alias pour getutent()).

NOTES

notes glibc

Les fonctions ci-dessus ne sont pas sûres pour les threads. glibc ajoute des versions réentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Exigences de macro de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

getutent_r(), getutid_r(), getutline_r() :

    _GNU_SOURCE
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */    _SVID_SOURCE || _BSD_SOURCE

Ce sont des extensions GNU, analogues aux fonctions du même nom sans le suffixe _r. L'argument ubuf donne à ces fonctions un endroit pour stocker leur résultat. En cas de succès, elles renvoient 0, et un pointeur vers le résultat est écrit dans *ubufp. En cas d'erreur, ces fonctions renvoient -1. Il n'y a pas d'équivalents utmpx des fonctions ci-dessus. (POSIX.1 ne spécifie pas de telles fonctions.)

NAME

getutxid, getutxline, pututxline, setutxent, endutxent, utmpx — access utmpx database

LIBRARY

libutil

SYNOPSIS

#include <utmpx.h>
struct utmpx *getutxid(const struct utmpx *id);
struct utmpx *getutxline(const struct utmpx *line);
void setutxent(void);
void endutxent(void);
struct utmpx *pututxline(const struct utmpx *utxptr);

DESCRIPTION

The getutxent(), getutxid(), getutxline(), pututxline(), setutxent(), and endutxent() functions provide an interface to the user accounting database, typically the file /var/run/utmp, and its historical archive /var/log/wtmp. The database is structured as an array of utmpx structures.

The utmpx structure contains the following members:

  • char ut_user[UT_NAMESIZE]; Username.
  • char ut_id[UT_IDSIZE]; Identifying information. For initialization processes, this is the empty string. For login processes, this identifies the terminal device.
  • char ut_line[UT_LINESIZE]; Terminal device name.
  • pid_t ut_pid; Process ID.
  • short ut_type; Type of entry. Possible values are:

    • EMPTY
    • RUN_LVL
    • BOOT_TIME
    • OLD_TIME
    • NEW_TIME
    • INIT_PROCESS
    • LOGIN_PROCESS
    • USER_PROCESS
    • DEAD_PROCESS
    • CRON_JOB
    • REBOOT_TIME
    • SYSLOG
  • struct timeval ut_tv; Time entry was made.
  • char ut_host[UT_HOSTSIZE]; Hostname for remote connections.
  • char pad[20]; Padding for future use.

The getutxent() function reads the next entry from the database.

The setutxent() function repositions the file pointer to the beginning of the database. Subsequent calls to getutxent() will start from the beginning.

The endutxent() function closes the database file.

The getutxid() function searches the database for an entry whose ut_id field matches the ut_id field of the structure pointed to by id. If id->ut_type is UT_UNKNOWN, then the ut_id field is used for the search. If id->ut_type is not UT_UNKNOWN, then the ut_id field is ignored, and the ut_type field is used for the search. The search starts from the beginning of the database.

The getutxline() function searches the database for an entry whose ut_line field matches the ut_line field of the structure pointed to by line. The search starts from the beginning of the database.

The pututxline() function writes the structure pointed to by utxptr into the database. If an entry with the same ut_line and ut_id already exists, it is overwritten. If no such entry exists, a new one is added. The pututxline() function normally overwrites the existing entry, but if the ut_type is DEAD_PROCESS, it deletes the entry.

After calling pututxline(), the database is effectively locked and should be updated again to release it.

The ut_id field is often derived from the terminal name. For example, for /dev/tty0, the ut_id would be 0. For /dev/pts/1, the ut_id would be 1.

The ut_host field is used to store the hostname for remote logins. It is usually null-terminated.

The ut_user field is the username. For non-login processes, it may be empty.

RETURN VALUE

The getutxent(), getutxid(), and getutxline() functions return a pointer to a utmpx structure on success, or NULL on failure or end of file.

The pututxline() function returns a pointer to the written utmpx structure on success, or NULL on failure.

ERRORS

No specific errors are documented.

FILES

  • /var/run/utmp
  • /var/log/wtmp

STANDARDS

POSIX.1-2001, POSIX.1-2008.

HISTORY

The getutent(), getutid(), getutline(), pututline(), setutent(), and endutent() functions were part of the AT&T UNIX system.

The utmpx structure and the functions prefixed with utx were introduced in POSIX.1-2001.

NOTES

The ut_id field is a 4-byte value, but the typical terminal device names are shorter than 4 characters. The value in ut_id is usually the last few characters of the device name, e.g., 0 for /dev/tty0, 1 for /dev/pts/1.

The functions described here are not thread-safe because they use a static buffer to store the returned utmpx structure. If you need thread-safe access, consider using getutxent_r(3) and its companions.

The ut_host field is intended for remote logins. If the login is local, this field is usually empty or contains the hostname.

The pututxline() function overwrites an existing entry if one with the same ut_line and ut_id is found. If ut_type is DEAD_PROCESS, the entry is removed.

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmpx entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutxent();
    if (pututxline(&entry) == NULL)
        err(EXIT_FAILURE, "pututxline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutxent();
    if (pututxline(&entry) == NULL)
        err(EXIT_FAILURE, "pututxline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutxent();
    exit(EXIT_SUCCESS);
}
