DESCRIPTION

Les fonctions gethostbyname*(), gethostbyaddr*(), herror() et hstrerror() sont obsolètes. Les applications doivent utiliser getaddrinfo(3), getnameinfo(3) et gai_strerror(3) à la place.

La fonction sethostent() spécifie, si stayopen est vrai (1), qu'un socket TCP connecté doit être utilisé pour les requêtes du serveur de noms et que la connexion doit rester ouverte pendant les requêtes successives. Sinon, les requêtes du serveur de noms utiliseront des datagrammes UDP.

La fonction endhostent() met fin à l'utilisation d'une connexion TCP pour les requêtes du serveur de noms.

La fonction gethostbyname() renvoie une structure de type hostent pour l'hôte donné name. Ici, name est soit un nom d'hôte, soit une adresse IPv4 en notation décimale pointée (comme pour inet_addr(3)). Si name est une adresse IPv4, aucune recherche n'est effectuée et gethostbyname() copie simplement name dans le champ h_name et son équivalent struct in_addr dans le champ h_addr_list[0] de la structure hostent retournée. Si name ne se termine pas par un point et que la variable d'environnement HOSTALIASES est définie, le fichier d'alias pointé par HOSTALIASES sera d'abord recherché pour name (voir hostname(7) pour le format de fichier). Le domaine actuel et ses parents sont recherchés sauf si name se termine par un point.

La fonction gethostbyaddr() renvoie une structure de type hostent pour l'adresse hôte donnée addr de taille size et de type d'adresse type. Les types d'adresses valides sont AF_INET et AF_INET6 (définis dans <sys/socket.h>). L'argument adresse hôte est un pointeur vers une structure d'un type dépendant du type d'adresse, par exemple un struct in_addr * (probablement obtenu via un appel à inet_addr(3)) pour le type d'adresse AF_INET.

La fonction (obsolète) herror() imprime le message d'erreur associé à la valeur actuelle de h_errno sur stderr.

La fonction (obsolète) hstrerror() prend un numéro d'erreur (typiquement h_errno) et renvoie la chaîne de message correspondante.

Les requêtes de nom de domaine effectuées par gethostbyname() et gethostbyaddr() s'appuient sur les sources configurées du Name Service Switch (nsswitch.conf(5)) ou sur un serveur de noms local (named(8)). L'action par défaut est de interroger les sources configurées du Name Service Switch (nsswitch.conf(5)), à défaut, un serveur de noms local (named(8)).

Historique

Le fichier nsswitch.conf(5) est la manière moderne de contrôler l'ordre des recherches d'hôtes.

Dans glibc 2.4 et versions antérieures, le mot-clé order était utilisé pour contrôler l'ordre des recherches d'hôtes tel que défini dans /etc/host.conf (host.conf(5)).

La structure hostent est définie dans <netdb.h> comme suit :


struct hostent {
    char  *h_name;            /* nom officiel de l'hôte */
    char **h_aliases;         /* liste des alias */
    int    h_addrtype;        /* type d'adresse de l'hôte */
    int    h_length;          /* taille de l'adresse */
    char **h_addr_list;       /* liste des adresses */
}
#define h_addr h_addr_list[0] /* pour la compatibilité descendante */

Les membres de la structure hostent sont :

h_name
Le nom officiel de l'hôte.
h_aliases
Un tableau de noms alternatifs pour l'hôte, terminé par un pointeur nul.
h_addrtype
Le type d'adresse ; toujours AF_INET ou AF_INET6 actuellement.
h_length
La taille de l'adresse en octets.
h_addr_list
Un tableau de pointeurs vers les adresses réseau de l'hôte (en ordre d'octets réseau), terminé par un pointeur nul.
h_addr
La première adresse dans h_addr_list pour la compatibilité descendante.

NOTE

S

Les fonctions gethostbyname() et gethostbyaddr() peuvent retourner des pointeurs vers des données statiques, qui peuvent être écrasées par des appels ultérieurs. Copier la struct hostent ne suffit pas, car elle contient des pointeurs ; une copie profonde est

nécessaire.

Dans l'implémentation BSD originale, l'argument size de gethostbyname() était un int. La norme SUSv2 est erronée et déclare que l'argument size de gethostbyaddr() est de type size_t. (C'est incorrect, car il doit être int, et size_t ne l'est pas. POSIX.1-2001 le fait socklen_t, ce qui est correct.) Voir aussi accept(

2).

Le prototype BSD pour gethostbyaddr() utilise const char * pour le premier

argument.

Extension System

V/POSIX

POSIX exige l'appel gethostent(), qui doit retourner l'entrée suivante dans la base de données des hôtes. Lors de l'utilisation de DNS/BIND, cela n'a pas beaucoup de sens, mais cela peut être raisonnable si la base de données des hôtes est un fichier qui peut être lu ligne par ligne. Sur de nombreux systèmes, une routine de ce nom lit depuis le fichier /etc/hosts. Elle peut être disponible uniquement lorsque la bibliothèque a été construite sans support DNS. La version glibc ignorera les entrées ipv6. Cette fonction n'est pas réentrante, et glibc ajoute une version réentrante gethoste

nt_
r().

Extensions

GNU

glibc2 possède aussi une gethostbyname2() qui fonctionne comme gethostbyname(), mais permet de spécifier la famille d'adresses à laquelle l'adresse doit

appartenir.

glibc2 possède aussi des versions réentrantes gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), et gethostbyname2_r(). L'appelant fournit une structure hostent ret qui sera remplie en cas de succès, et un tampon de travail temporaire buf de taille bufsize. Après l'appel, result pointera vers le résultat en cas de succès. En cas d'erreur ou si aucune entrée n'est trouvée, result sera NULL. Les fonctions retournent 0 en cas de succès et un numéro d'erreur non nul en cas d'échec. En plus des erreurs retournées par les versions non réentrantes de ces fonctions, si buf est trop petit, les fonctions retourneront ERANGE, et l'appel devrait être réessayé avec un tampon plus grand.
