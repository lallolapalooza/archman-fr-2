subroutine dsgesv (integer n, integer nrhs, double precision, dimension( lda, * ) a, integer lda, integer, dimension( * ) ipiv, double precision, dimension( ldb, * ) b, integer ldb, double precision, dimension( ldx, * ) x, integer ldx, double precision, dimension( n, * ) work, real, dimension( * ) swork, integer iter, integer info)

DSGESV calcule la solution du système d'équations linéaires A * X = B pour les matrices GE (précision mixte avec raffinement itératif)

But :

!>
!> DSGESV calcule la solution d'un système réel d'équations linéaires
!>    A * X = B,
!> où A est une matrice N×N et X et B sont des matrices N×NRHS.
!>
!> DSGESV tente d'abord de factoriser la matrice en PRÉCISION SIMPLE
!> et d'utiliser cette factorisation dans une procédure de raffinement
!> itératif pour produire une solution avec une erreur arrière
!> rétrograde en norme de PRÉCISION DOUBLE (voir ci-dessous). Si
!> l'approche échoue, la méthode passe à une factorisation et une
!> résolution en PRÉCISION DOUBLE.
!>
!> Le raffinement itératif ne sera pas une stratégie gagnante si le
!> rapport des performances en PRÉCISION SIMPLE sur les performances
!> en PRÉCISION DOUBLE est trop faible. Une stratégie raisonnable
!> devrait prendre en compte le nombre de seconds membres et la
!> taille de la matrice. Cela pourrait être fait avec un appel à
!> ILAENV à l'avenir. Pour l'instant, nous essayons toujours le
!> raffinement itératif.
!>
!> Le processus de raffinement itératif s'arrête si
!>     ITER > ITERMAX
!> ou si pour tous les seconds membres nous avons :
!>     RNRM < SQRT(N)*XNRM*ANRM*EPS*BWDMAX
!> où
!>     o ITER est le numéro de l'itération courante dans le processus
!>       de raffinement itératif
!>     o RNRM est la norme infinie du résidu
!>     o XNRM est la norme infinie de la solution
!>     o ANRM est la norme opérateur infinie de la matrice A
!>     o EPS est l'epsilon machine renvoyé par DLAMCH('Epsilon')
!> Les valeurs ITERMAX et BWDMAX sont fixées à 30 et 1.0D+00
!> respectivement.
!>

!>          Le nombre d'équations linéaires, c'est-à-dire l'ordre de

!>          Le nombre de seconds membres, c'est-à-dire le nombre de

!>          double précision a été utilisée (INFO = 0 et ITER < 0,

!>          A = P*L*U ; les éléments diagonaux unitaires de L ne sont

!>          La dimension principale du tableau A.  LDA >= max(1,N).

!>          > 0 :  si INFO = i, U(i,i) calculé en PRÉCISION DOUBLE est

!>                 mais le facteur U est exactement singulier, la
!>                 solution n'a donc pas pu être calculée.

NAME


ZCGSV - General dense matrix solver, with iterative refinement, using a COMPLEX*16 factorization







SYNOPSIS


SUBROUTINE ZCGSV(
   N, NRHS, A, LDA, IPIV, B, LDB, X, LDX, WORK, SWORK, RWORK, ITER, INFO )

CHARACTER * (*)      A, B, X, WORK
INTEGER              INFO, ITER, LDA, LDB, LDX, N, NRHS
INTEGER              IPIV( * )
DOUBLE PRECISION     RWORK( * )
COMPLEX*16           SWORK( * )








Detailed Description


ZCGSV solves the system of linear equations A*X = B, with a general
    dense matrix A. The routine first attempts to factorize the matrix in
    single precision (COMPLEX) and use this factorization within an iterative
    refinement procedure to produce a solution with COMPLEX*16 normwise
    backward error quality (see below). If the approach fails the method switches
    to a COMPLEX*16 factorization and solve.


The iterative refinement is not going to be a winning strategy if
    the ratio COMPLEX performance over COMPLEX*16 performance is too
    small. A reasonable strategy should take the number of right-hand
    sides and the size of the matrix into account. This might be done
    with a call to ILAENV in the future. Up to now, we always try
    iterative refinement.


The iterative refinement process is stopped if


    ITER > ITERMAX



or for all the RHS we have:


    RNRM < SQRT(N)*XNRM*ANRM*EPS*BWDMAX



where


    o ITER is the number of the current iteration in the iterative
      refinement process
    o RNRM is the infinity-norm of the residual
    o XNRM is the infinity-norm of the solution
    o ANRM is the infinity-operator-norm of the matrix A
    o EPS is the machine epsilon returned by DLAMCH('Epsilon')



The value ITERMAX and BWDMAX are fixed to 30 and 1.0D+00
    respectively.
